オープンウェブイ v0.13.1

追加

  • 🦾 モデルとしてのエージェントのコーディング エージェントを提供するオープン ターミナルでは、Claude Code、Codex、Pi などのコーディング エージェントがモデル ピッカーに表示されるようになりました。彼らとチャットしたり、音声で電話をかけたり、推論の労力とサービス レベルを選択したり、チャットでツールのリクエストを承認したりすることができます。各会話では 1 人のエージェントが使用され、エージェント チャットを再生成、継続、編集して再送信することはできません。エージェントの端末が失われると、そのチャットと新しいチャットはデフォルト モデルに戻り、以前の応答はエージェントの名前を保持します。エージェント チャットのオートコンプリートではタスク モデルが使用されるか、タスク モデルがない場合はスキップされます。 #33843、#33860、#33880、#33857
  • 🪢 Tether のご紹介 Tether は、自分のコンピューターを Open WebUI に結び付ける、macOS、Windows、Linux 用の新しいデスクトップ コンパニオン アプリです。一度サインインすると、ターミナル メニューの [デバイス] の下にコンピュータが表示されるため、モデル、コーディング エージェント、オートメーションは実際のファイル、リポジトリ、ツールで動作し、携帯電話を含む任意のブラウザからアクセスできます。 Tether は Open WebUI に接続するため、開くポートはありません。接続が切断された後もターミナル出力が再開され、Open WebUI ページが開いていない場合でもデスクトップに通知が配信されます。デフォルトでは、「SESSION_EXPIRES_IN」で設定され、90 日間使用されないと期限切れになる更新可能なセッションを使用してサインインします。
  • 💸 ツールチャットが大幅に安くなりました。 ツールを使用したチャットのコストが大幅に安くなりました。引用指示、記憶の呼び出し、スキル リスト、および付属の知識は、ツール ラウンドごとにシステム プロンプトまたはメッセージに書き換えられなくなりました。そのため、会話の始まりはリクエスト間で同じままであり、プロバイダーはプロンプト キャッシュから会話を提供できます。結果として、カスタム パイプでは異なるメッセージ レイアウトが表示されます。 「変更されたツールの結果としてのコンテキスト」を参照してください。 #33852
  • 🚦 自動ツール権限 管理者は、フル アクセスと承認を求める (デフォルトではオフ) に次ぐ 3 番目のツール権限モードである自動をオンにできるようになりました。レビュー モデルは各ツール呼び出しをチェックし、確認が必要ないと判断した場合にのみ、すぐに実行します。レビューでは、ツール、その引数、および最後のいくつかのメッセージが構成されたスコアリング API に送信され、エラー、タイムアウト、またはコンテキストが多すぎるためにレビューできない呼び出しは承認を求められます。
  • 📚 小さいファイルの全テキスト。 抽出されたテキストが新しいしきい値 (デフォルトでは 50,000 文字、「RAG_FULL_TEXT_CHAR_THRESHOLD」または管理ドキュメント設定で設定) より短いファイルは、取得ではなく完全に含まれるようになりました。これは、ファイルのプリロードによって会話にコンテンツが追加されるときと、モデルがファイル検索ツールで添付ファイルを読み取るときの両方に適用され、ファイル ビューアにはそれがいつ行われるかが表示されます。
  • ⏱️ 大規模なチャットの高速化。 大規模なチャットが約 2 倍の速度で開くようになり、チャットを既読または未読としてマークしたり、チャットからタグを削除したりするのが 4 ～ 6 倍速くなりました。 #33665、#33666
  • 🏎️ チャット アクセス チェックの高速化。 メッセージの送信、インジケーターの入力、共有リンク、コメント、ファイル アクセスでは、誰がアクセスできるかを確認するためだけに会話全体を読み込む必要がなくなり、大規模なチャットで最も役立ちます。 #33667、#33669
  • 🔧 より寛容なツール呼び出し。 引数をコード フェンスでラップしたり、2 回エンコードしたり、数値やブール値ではなくテキストとして送信したりするツール呼び出しが実行されるようになり、モデルがプレーン テキスト マークアップとして書き出すツール呼び出しが認識されて実行されます。 #33868
  • 🛑 ツール ループが停止します。 同じ引数を使用したツール呼び出しが 2 回続けて失敗すると、ツール ループが終了するようになりました。そのため、モデルは最終応答を書き込み、トークン制限によって切断された応答は未完了のツール呼び出しを実行しなくなりました。
  • 🛠️ モデルのデフォルト ツール。 管理モデル設定のモデルのデフォルト セクションにツール ピッカーが追加されました。独自のツール リストを持たないモデルは、それらのツールを有効にして新しいチャットを開始し、新しいモデル フォームによってそれらが事前に選択されます。 #33749、#33787
  • 🚀 チャネルの高速化 チャネル リスト、チャネル メッセージ、チャネル内の返信メッセージの読み込みが大幅に高速になり、特に多数のチャネルまたは多数の返信がある場合、新しいデータベース インデックスによりチャネル スレッドと反応が高速化されています。 #33690、#33691、#33688
  • 🪶 推論ストリームの軽量化。 OpenRouter などのプロバイダーからの長い推論応答は、ストリーミング中にブラウザーと Redis に送信されるデータが大幅に少なくなりました。 #33698
  • 🗂️ サイドバーのチャット リストの高速化。 サイドバーのチャット リストは、チャンネル リストを待つのではなく、独自のデータが準備できるとすぐに表示されるようになりました。 #33686
  • ⌨️ 大量のペースト後の入力の高速化 16,000 行のテキストを貼り付けた後のチャット入力の入力が、キーストロークあたり 8.6 秒から 74 ミリ秒まで、約 117 倍速くなりました。 #33729、#12087
  • 🧮 Redis フィルター検索の高速化。 Redis を有効にすると、チャット リクエストでモデルのフィルターをより速く検索できるようになりました。 #33668
  • 🪟 タブ ペインの分割。 大きな画面では、タブまたはチャットをワークスペースの端にドラッグするか、新しい画面分割ボタンを押すと、サイズ変更可能なペインに分割され、チャットを含む複数のタブが並べて表示されたままになります。タッチ スクリーン上で長押ししてドラッグすると、タブの順序を変更したり、ペイン間を移動したりすることもできます。 コミット
  • 🧳 チャットごとにタブが記憶される 各チャットの開いているタブ、分割レイアウト、および選択した端末が、ユーザーごとにサーバー上に非公開で保存され、別のデバイスであってもチャットを再度開くと復元されます。サインアウトすると、保存されていないファイルの編集について警告が表示されます。 #33899、#33885
  • 🪣 バッチ化されたツール検索呼び出し。 ツール検索をオンにすると、モデルは単一の call_tool リクエストで見つかった複数の独立したツールを実行できるため、モデルのターン数が節約され、ツールを多用するチャットのコストが削減されます。
  • 🧭 ツール検索エンジン。 管理インターフェイス設定のツール検索では、デフォルトのキーワード検索に加えて、ドキュメント埋め込みモデル (メモリ内に保持され、保存されない) からの埋め込み、またはクエリとツール定義を関連性スコアリング API に送信することによってツールを照合できるようになりました。
  • 🏷️ 読み取り可能なツール呼び出しラベル。 管理者は、[管理者設定] > [インターフェイス] でツール呼び出しラベルをオンにするか、デフォルトでオフになっている「ENABLE_TOOL_CALL_LABELS」を使用して、各ツール呼び出しが何を行っているのか、またその結果についてユーザーの言語で短い説明をモデルに求めることができるようになりました。 コミット

Tether connects out to Open WebUI, so there are no ports to open, its terminal output resumes after a dropped connection, and it delivers notifications to your desktop even when no Open WebUI page is open. A review model checks each tool call and runs it right away only when it judges that no confirmation is needed. Changed

  • ⚠️ Database Migrations: This release includes database schema changes; we strongly recommend backing up your database and all associated data before upgrading in production environments. If you are running a multi-worker, multi-server, or load-balanced deployment, all instances must be updated simultaneously, rolling updates are not supported and will cause application failures due to schema incompatibility.
  • 💥 Preload files off by default. With native function calling, the default, attached files are no longer added to the conversation automatically, and models read them with their file tools instead. Models without tool support or without the Files built-in tool can no longer see attached files until you turn on Preload files in the model's Capabilities. Legacy function calling, and API requests that do not come from a chat in the web UI, keep the old behavior. #33815
  • 🎯 Retrieval defaults. Unless you saved your own values, "RAG_TOP_K" and "RAG_TOP_K_RERANKER" now default to 10 instead of 3, and "CHUNK_SIZE" to 1024 instead of 1000. Each query now retrieves more text, so prompts with knowledge get longer. The new chunk size applies to files processed from now on; existing knowledge keeps its chunks until it is reindexed.
  • 🧷 Context as hidden tool results. With native function calling, memory recall, the skills list and the attached knowledge list now arrive as hidden tool results after your message instead of in the system prompt. This is what keeps tool chats cacheable, and it means custom pipes can see a tool message as the last message.
  • 🗨️ Side chats are saved. Side chats, which were always temporary in 0.13.0, are now saved as regular chats and appear in the chat list. They stay temporary only when you turn on Temporary Chat in the side chat or your admin enforces temporary chats.
  • 🚧 Tool call limit. Reaching the tool call limit now makes the model write a final answer without tools, instead of ending the reply with the "Tool-call limit reached" error.
  • 🔦 Tool Search prompt. With Tool Search on, the model no longer sees a list of the hidden tools and finds them only by searching.
  • ✏️ Always Use Full Text. The Full Context Mode setting in the admin Documents settings is now called Always Use Full Text and includes complete documents regardless of the full text threshold.
  • ↔️ Always full-width tabs. On large screens the tabbed workspace now always fills the chat area, with the chat as one of its tabs, and the full-width toggle added in 0.13.0 is gone.
  • 🔀 Integrations moved into + menu. The Integrations button is now part of the + menu in the message input, and the new Show Input Selections setting, off by default, controls whether selected tools, skills, filters and capabilities are shown beside it.
  • 🔓 Side chat permission. The Allow Side Chat permission no longer requires the Temporary Chat permission.
  • 🕸️ Chrome first in Browser tab. The Browser tab now starts in Chrome mode when the terminal offers it, and switches to Proxy mode with a message if Chrome fails to start.
  • ⛔ Terminal select setting removed. The Show Files on Terminal Select setting has been removed from the Interface settings. #33855, #33840
