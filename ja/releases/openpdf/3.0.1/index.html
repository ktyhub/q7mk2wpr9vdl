OpenPDF 3.0.1

Highlights

  • New capabilities (additive, no migration needed) — Adds a text coordinate extraction API (PR #1466), an API to set a custom first-line baseline Y in ColumnText (PR #1477, issue #1430), and basic PDF/A-2 and PDF/A-3 conformance support (PR #1480); also adds support for Ideographic Variation Sequences (IVS) in TrueType fonts (PR #1482). None of this is breaking — all opt-in.
  • Rendering and data-integrity fixes — Fixes an IndexOutOfBoundsException in FopGlyphProcessor from 1:N Thai glyph expansion (PR #1457), non-breaking space (U+00A0) handling in text justification (PR #1473), the AI(11) length for GS1-128 Production date barcodes (PR #1476), and indexed image detection that was inflating PDF file sizes (PR #1479). Matters most if you render Thai text, GS1-128 barcodes, or care about output size.
  • openpdf-html / openpdf-renderer — CSS @font-face support is substantially improved (PR #1470, completed in PR #1489) alongside htmlunit-neko DOMParser integration and HTML5 feature tests (PR #1490); openpdf-renderer gains a comprehensive unit test suite plus docs/build cleanup (PR #1471, PR #1472). Also fixes a VSCode project loading failure (issue #1446, PR #1475).
  • Dependencies and build tooling — Bouncy Castle is bumped to 1.83 (PR #1460), relevant if you rely on signing/encryption; JUnit jumps 5.13.4 → 6.0.3 (PR #1462) and checkstyle 11.0.0 → 13.2.0 (PR #1495), with many other dependabot bumps to Maven plugins, Kotlin, commons-io, and error_prone_annotations. These are build/test-time only and should not change runtime behavior.
  • Verdict / who should upgrade — A feature-and-fix patch release with no documented breaking changes or migration steps; the "Required Java version clarification" (PR #1453) is README-only. Upgrade if you need PDF/A-2/3, the new extraction/ColumnText APIs, better @font-face, or hit any of the fixed bugs; users stable on 3.0.0 with none of those needs can skip. Note several entries are explicitly marked [WIP] (PR #1467, PR #1469, PR #1478), so treat those particular changes (Android compatibility, Barcode128Test, refactors) as lower-confidence.
