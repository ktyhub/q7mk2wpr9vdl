OCRmyPDF v17.13.0

変更点

  • Ghostscript (「投機的」変換) を使用せずに作成された PDF/A が検証されるようになりました。 veraPDF の代わりに pikepdf の PDF/A サポート (pikepdf.pdfa) を使用し、 最終出力は、メタデータと最適化の手順の後に再度検証されます。 veraPDF は使用されなくなったため、Ghostscript フリーのパスが利用可能になりました veraPDF がインストールされているかどうか (Docker イメージを含む)。ファイル バリデーターは以前のように Ghostscript への移動を承認しません。 -v1で実行 その理由を見てみましょう。
  • 投機的変換で PDF/A-1b がサポートされ、一般的な問題が修正されました 以前は常にファイルを Ghostscript に送信していました。他の出力を置き換えます。 sRGB を使用したインテント、画像補間フラグを削除し、印刷フラグをオンに設定します。 注釈、PDF/A-1 に必要な /CIDSet の追加、および XMP プロパティの削除 PDF/A では許可されていない非表示の注釈。
  • 新しいオプション --pdfa-backend {auto,ghostscript,internal} (API: pdfa_backend=)。デフォルトの auto は、OCRmyPDF 独自の変換を試み、 次にゴーストスクリプト。 internal は Ghostscript を使用しないため、JPEG はパススルーします。 変化なし。結果が承認されない場合、pdfa 出力タイプは失敗し、 終了コード 10 および --output-type auto は通常の PDF を出力します。 ghostscript 常に Ghostscript を使用します。 Ghostscript のみが実装するオプション (--pdfa-image-compression、--ghostscript-jpeg-quality、 --ghostscript-jpeg-maxdpi、--color-conversion-strategy、CMYK、 Gray または UseDeviceIndependentColor)、auto の下の Ghostscript を選択します。 と は internal のエラーです。
  • OCRmyPDF には pikepdf[pdfa] 10.15 以降が必要になりました。 pdfa エクストラ jsonschema、referencing、fonttools を導入し、すべてパッケージ化されています。 Debian と Red Hat。
  • --force-ocr はハイパーリンクを保持し、リンクの注釈を ラスタライズされたページ。 --deskew と --clean-final も同様です。新しいモード --mode force-ocr-no-links は古い動作を維持します。 {issue}605
  • Ghostscript が埋め込まれていないフォントを置き換える場合、常に使用されるようになりました。 独自のフォント (-dNONATIVEFONTMAP) を使用するため、出力はすべてのフォントで同じになります。 プラットフォーム。 macOS では、ネイティブ フォント ルックアップにより数十メガバイトの システムフォント。 OCRmyPDF は、標準の 14 以外のフォントが使用されている場合に警告します。 代替された場合、または代替が太字または斜体のスタイルを失った場合。 {issue}1369
  • タイムゾーンのない作成日は現地時間とみなされ、 出力の日付はそのゾーンを取得し、警告が表示されます。 TZ を設定して別のものを選択します ゾーン。
  • デフォルト モードでは、すでにテキストが含まれているページで OCRmyPDF が停止するようになりました。 前のページを OCR した後ではなく、最初のスキャンの直後 それ。エラーはページに名前を付けます。 {issue}613
  • 出力ファイルのチェックが大幅に高速化されます。各ストリームは 完全にデコードする代わりに圧縮するための最も安価な方法。 プログレスバーが表示されます。 JPEG 2000 および CCITT 画像もチェックされるようになりましたが、 切り詰められずに破損した JPEG は検出されなくなりました。 {issue}1570
  • OCRmyPDF には PyInstaller フックが同梱されるようになり、それを使用するアプリをバンドルできるようになりました 追加のオプションなしで。 Tesseract と Ghostscript は引き続きインストールする必要があります。 {issue}1024
  • 新しい PageInfo.has_visible_text。 OCR層。 has_textは変更ありません。

修正

  • すでにラスタライズされた非表示の OCR レイヤーを持つスキャン上の --force-ocr テキストが表示されているかのように、400 dpi 以上で表示されます。 ファイルサイズを倍増します。 {issue}961
  • プロセス ワーカー (Windows および macOS の use_threads=False) がすべてのサーバーで失敗しました 'OcrOptions' object has no attribute 'tesseract'のページ。 {issue}1757
  • ocrmypdf.ocr() は、次のようなしきい値処理方法名を拒否しました。 tesseract_thresholding='adaptive-otsu'。 {issue}1460
  • --rotate-pages --tesseract-timeout 0 はページの向きを検出しましたが、検出しませんでした ページを回転させます。クックブックでは、この組み合わせをローテーションに推奨しています。 または OCR を使用しないデスキュー。 {issue}778
  • --output-type auto および --force-ocr では、出力には PDF/A というラベルが付けられました。 veraPDF が有効であったときに、検証または PDF/A 宣言が行われていなかった Docker の画像のように、取り付けられていません。 {issue}1751
  • Ghostscript の PDF/A 変換により、ほとんどのハイパーリンク ( フラグを印刷します)。 PDF/A では許可されていない非表示の注釈が追加されました。 Ghostscript が実行される前に削除され、投機的と同じ警告が表示されます。 黙って変換するのではなく、変換します。 {issue}605
  • /ToUnicode を含まないフォントのテキスト。閲覧者はグリフを通じて抽出します。 Ghostscript が PDF/A を作成するときに、名前が文字化けするか失われます。 {issue}1297
  • dc:contributor など、同等のドキュメント情報を持たない XMP メタデータ および dc:subject は、Ghostscript が PDF/A を作成したときに失われました。それは今です 多言語のすべての言語を含む、値全体をコピーします。 財産。 {issue}1220
  • iText および pdftk の PDF 内の画像が Flate なしで再圧縮されました。 予測子により、出力が約 30% 増加します。 {issue}1620
  • 縦書き日本語およびその他の縦書きまたは回転した OCR 行からコピーされたテキスト 偽のスペースや文字の順序が乱れていました。 {issue}1244
  • グリフレスフォールバックフォントで設定されたテキスト。フォントがインストールされていない場合に使用されます。 スクリプト (CJK など)、選択またはコピー時に失われた文字をカバーします。 Chrome およびその他の pdfium ベースのビューア。
  • 異なる解像度のフルページ画像で構成されるページは、次の解像度でラスタライズされました。 最高解像度ではなく加重平均解像度。 {issue}948
  • ドキュメント言語 (/Lang) が Tesseract の言語コードに設定されていませんでした deu、fra、cesなど。 2 文字コードのない言語は、 彼らの 3 文字のコード。 {issue}1749
  • コンテンツ ストリームに不正な数値が含まれる一部の LaTeX PDF。 0.000-50131235、OCRmyPDFを停止しました。現在、視聴者として警告し続けています する。 {issue}1054
  • 実数として格納された /Rotate、または数値以外の cm 演算子 オペランドにより、ページ スキャンがクラッシュしました。
  • --force-ocr --ocr-engine none は画像のないページでクラッシュしました。
  • OCRmyPDF 自身の PDF/A が最終チェックに失敗した場合、Ghostscript フォールバック FileExistsError で失敗する可能性があります。 Windows では常にそうなっていました。
  • デフォルトの--output-type autoで、大きくなったファイルの説明 ここでは PDF/A 変換を指します。 {issue}1369
  • Ghostscript 10.08 の無題ファイルのタイトル 'Untitled' (引用符付き) 再び削除されました。
  • Docker イメージの Web サービスは、Streamlit スクリプトを見つけることができませんでした。の Web サービスの Docker ドキュメントが更新されました。 {issue}1753
  • Docker ウォッチャーは、指定された deskew をオフにしなくなりました。 OCR_DESKEW が設定されていない場合は、OCR_JSON_SETTINGS。

OCRmyPDF v17.13.0

Changes

  • PDF/A made without Ghostscript ("speculative" conversion) is now validated with pikepdf's PDF/A support (pikepdf.pdfa) instead of veraPDF, and the final output is validated again after the metadata and optimization steps. veraPDF is no longer used, so the Ghostscript-free path is available whether or not veraPDF is installed, including in the Docker image. Files the validator does not approve go to Ghostscript as before; run with -v1 to see why.
  • Speculative conversion now supports PDF/A-1b, and repairs common problems that previously always sent a file to Ghostscript: it replaces other output intents with sRGB, removes image interpolation flags, sets the Print flag on annotations, adds the /CIDSet PDF/A-1 requires, and removes XMP properties and hidden annotations that PDF/A does not permit.
  • New option --pdfa-backend {auto,ghostscript,internal} (API: pdfa_backend=). auto, the default, tries OCRmyPDF's own conversion and then Ghostscript. internal never uses Ghostscript, so JPEGs pass through unchanged; if the result is not approved, the pdfa output types fail with exit code 10 and --output-type auto outputs a regular PDF. ghostscript always uses Ghostscript. Options that only Ghostscript implements (--pdfa-image-compression, --ghostscript-jpeg-quality, --ghostscript-jpeg-maxdpi, and --color-conversion-strategy CMYK, Gray or UseDeviceIndependentColor) now select Ghostscript under auto and are an error with internal.
  • OCRmyPDF now requires pikepdf[pdfa] 10.15 or later. The pdfa extra brings in jsonschema, referencing and fonttools, all packaged by Debian and Red Hat.
  • --force-ocr now keeps hyperlinks, moving link annotations onto the rasterized page; so do --deskew and --clean-final. The new mode --mode force-ocr-no-links keeps the old behaviour. {issue}605
  • When Ghostscript substitutes fonts that are not embedded, it now always uses its own fonts (-dNONATIVEFONTMAP), so output is the same on every platform; on macOS, native font lookup could embed tens of megabytes of system fonts. OCRmyPDF warns when fonts other than the standard 14 are substituted, or when a substitute loses bold or italic styling. {issue}1369
  • A creation date without a time zone is now taken to be local time, and the output's dates get that zone, with a warning. Set TZ to choose another zone.
  • In the default mode, a page that already has text now stops OCRmyPDF straight after the initial scan, instead of after OCRing the pages before it. The error names the page. {issue}613
  • The check of the output file is much faster: each stream is checked in the cheapest way for its compression instead of being fully decoded, and a progress bar is shown. JPEG 2000 and CCITT images are now checked too, but JPEGs that are corrupt without being truncated are no longer detected. {issue}1570
  • OCRmyPDF now ships a PyInstaller hook, so apps that use it can be bundled without extra options. Tesseract and Ghostscript must still be installed. {issue}1024
  • New PageInfo.has_visible_text, which excludes invisible text such as an OCR layer. has_text is unchanged.

Fixes

  • --force-ocr on a scan that already had an invisible OCR layer rasterized it at no less than 400 dpi, as if the text were visible, which could multiply the file size. {issue}961
  • Process workers (use_threads=False on Windows and macOS) failed on every page with 'OcrOptions' object has no attribute 'tesseract'. {issue}1757
  • ocrmypdf.ocr() rejected thresholding method names such as tesseract_thresholding='adaptive-otsu'. {issue}1460
  • --rotate-pages --tesseract-timeout 0 detected page orientation but did not rotate the pages. The cookbook now recommends this combination for rotating or deskewing without OCR. {issue}778
  • With --output-type auto and --force-ocr, output was labelled PDF/A without being validated or given the PDF/A declarations when veraPDF was not installed, as in the Docker image. {issue}1751
  • Ghostscript's PDF/A conversion deleted most hyperlinks (those without the Print flag). Hidden annotations, which PDF/A does not permit, are now removed before Ghostscript runs, with the same warning as speculative conversion, instead of silently. {issue}605
  • Text in fonts without /ToUnicode, which viewers extract through glyph names, was garbled or lost when Ghostscript made the PDF/A. {issue}1297
  • XMP metadata with no document-info equivalent, such as dc:contributor and dc:subject, was lost when Ghostscript made the PDF/A. It is now copied with its whole value, including every language of a multilingual property. {issue}1220
  • Images in PDFs from iText and pdftk were recompressed without their Flate predictor, growing the output by about 30%. {issue}1620
  • Copied text from vertical Japanese and other vertical or rotated OCR lines had spurious spaces and characters out of order. {issue}1244
  • Text set in the glyphless fallback font, used when no installed font covers a script (e.g. CJK), lost characters when selected or copied in Chrome and other pdfium-based viewers.
  • A page made of full-page images at different resolutions was rasterized at a weighted average resolution rather than the highest. {issue}948
  • The document language (/Lang) was not set for Tesseract's language codes such as deu, fra and ces. Languages without a two-letter code now get their three-letter code. {issue}1749
  • Some LaTeX PDFs with malformed numbers in a content stream, such as 0.000-50131235, stopped OCRmyPDF. It now warns and continues, as viewers do. {issue}1054
  • A /Rotate stored as a real number, or a cm operator with a non-numeric operand, crashed the page scan.
  • --force-ocr --ocr-engine none crashed on pages with no images.
  • When OCRmyPDF's own PDF/A failed its final check, the Ghostscript fallback could fail with FileExistsError; on Windows it always did.
  • With the default --output-type auto, the explanation for a file that grew now points to PDF/A conversion. {issue}1369
  • Ghostscript 10.08's title 'Untitled' (with quotes) for untitled files is removed again.
  • The Docker image's web service could not find its Streamlit script. The Docker documentation for the web service is updated. {issue}1753
  • The Docker watcher no longer turns off deskew given in OCR_JSON_SETTINGS when OCR_DESKEW is not set.
