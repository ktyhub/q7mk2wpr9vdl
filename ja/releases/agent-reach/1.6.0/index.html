#エージェントリーチ v1.6.0

中国語:

  • 古いバージョンからのアップグレード: 「Agent Reach の更新を手伝ってください」という文を AI に送信するだけです。キーと設定は保持され、古いバージョンのプログラムは自動的に削除されます。
  • プラットフォームを追加するために一言言うだけで、必要なソフトウェアが自動的にインストールされます。管理者パスワードは必要ありません。ログインするかキーを入力するだけで済みます。
  • 小紅書や Twitter などのログインが必要なプラットフォームの場合は、ウィンドウがポップアップしたりブラウザを占有したりしない Agent Reach 独自の専用ブラウザを使用します。複数のAIが同時にチェック可能。
  • RSS フィードと Exa の Web 全体検索が「Web ページ」に統合されました。今後新しいバージョンが出る際には、AIが変更内容をわかりやすい英語で教えてくれて、同意した上で更新されます。

英語:

  • 古いバージョンからのアップグレード: AI に「エージェント リーチの更新」という文を送信するだけです。キーと設定は保持され、古いプログラムは削除されます。
  • プラットフォームの追加は 1 文で完了します。必要なものはすべてインストールされ、管理者パスワードは必要ありません。ログインするかキーを入力するだけです。
  • Xiaohongshu や X などのログインが必要なプラットフォームでは、ユーザーのブラウザではなく、Agent Reach 独自のブラウザがバックグラウンドで使用されるようになり、複数の AI が同時に検索できるようになりました。
  • RSS と Exa 検索は「ウェブ」の一部になりました。新しいバージョンがリリースされると、AI は何が変更されたかをわかりやすい言葉で教えてくれ、ユーザーが「はい」と答えた場合にのみ更新されます。

1.6はリビルド品です。エージェントは 1 つのコマンド agent-reach を呼び出します。 Agent Reach がインストールまたは保存するものはすべて、~/.agent-reach/ の下に存在します。 1.6 は再構築されたバージョンです。エージェントは 1 つのコマンド agent-reach のみを呼び出し、Agent Reach によってインストールおよび保存されたものはすべて ~/.agent-reach/ の下にあります。

中国語 (技術的な詳細):

  • このバージョンのリリース前に、28/40 のアクションがテストされています。次のものは公開マシンでテストされておらず、管理者の承認を得てこのバージョンでリリースされます: Reddit (テスト ネットワークはブロックされています)、Instagram (トラフィックが制限されています)、Bilibili 字幕、LinkedIn、Snowball Hot Posts (ログインしていません)、および Small Universe (キーが割り当てられていません)。
  • 非ログインによるパブリック API のブロック、パブリック クオート トリガー ブラウザ、エラー認証プロンプト、および未登録キャッシュのクリアを修正しました。一時的な音声/字幕は Reach に保存されます。 BOSS サイトの検索では、公式の OpenCLI、JD アップストリーム適応障害リストが優先されます。 PR とリリースの両方で、実際の受け入れステータスと保留ステータスを確認します。
  • CLI まず、宣言された公開検索/読み取り用の Web ツールを再利用し、成功後にブラウザを準備しません。結果にはソースとコンテンツ範囲がマークされ、サイト パスではログインを求める前に明らかに認証が必要です。元のサイトの機能を保持するようにバックエンドを指定できます。
  • ブラウザ チャネルは 1 つのログインを共有します。ログインは 10 分間操作がないと自動的に終了し、次回は自動的に開きます。
  • チャンネル自動準備ツールを追加しました。削除時に Web サイトのログインのみを消去します。デフォルトのプラットフォームを削除することもできます。一度削除すると、アップデートによって再び追加されることはありません。 ・アップデートの際、動作確認済みのツールは動作確認済みのバージョンのまま、その他のツールは互換性の範囲内の最新バージョンを使用します。
  • 最初に公開コンテンツを読み続けてください。ログインは必要ありません。インストール後、短い形式を使用して確認できる内容を説明します。
  • Microcosm の転写を保持します。追加のモデル構成と重複した Web サイト クロール実装を削除します。
  • Bridge は専用ブラウザで管理されます。実際のページ操作に応じてタイミングが調整され、ログが定期的に保存されます。クリーンアップが失敗した場合、チャネルは保持されます。アンインストールでは台帳ファイルのみが削除されます。リリース前に実際に受け入れられるチャネルが必要です。
  • デフォルトではクエリはヘッドレスであり、ローカル サイト ログインの読み取り専用再利用が優先されます。ウィンドウ ログインとヘッドレス クエリは同じ構成を共有します。 Bilibili 字幕と Snowball コミュニティは自動的に同時にログインし、BOSS JD はアップストリームのブラウザ インターフェイスを使用します。インターフェイスの欠落や現在の制限が、再ログインが必要であると誤って報告されなくなりました。
  • 専用ブラウザは、拡張機能によって独自の設定に保存された番号によって識別され、ユーザーが毎日使用する Chrome は専用ブラウザとして認識されなくなります。ログイン ウィンドウが開いているときに、クエリによってログイン ウィンドウが閉じられなくなりました。
  • ブラウザ チャネルは並行してクエリできます。同じプラットフォーム上で最大 2 チャネル、合計 4 チャネルを同時に実行できます。追加のチャネルは、すぐに「ビジー」を報告するのではなく、キューに入れられます。ウィンドウへのログインやログアウトなどの操作は、実行中のクエリが完了した後に実行されます。
  • ログインしていない場合、「アップストリーム ツールが壊れています」ではなく「ログインが必要」というメッセージが表示されます: Snowball Community (エラー コード 400016)、Bilibili 字幕 (Bilibili ログインなし)、LinkedIn (専用ブラウザで LinkedIn ログインなし)。
  • 1.5 からのアップグレードはよりスムーズです。インストールとアップデートは 1 つの install.md に結合され、最初にバージョンを確認してから分割されます (古いバージョンが指す update.md がそこに転送されます)。 agent-reach update は、pip/pipx によってインストールされた古いバージョンに遭遇すると、uv インストールに切り替えます。 setup は、古いバージョンの Agent Reach プログラムを削除します (プログラム自体のみを削除し、他のツールはそのまま残します)。インストール レポートには、何が保持され、何が変更され、追加し直す前に使用されたチャネルが説明されます。インストール アドレスは、常に最新の正式バージョンを指すように変更されます。
  • プラットフォームでエラーが発生した場合、元のエラーメッセージと独自の対処提案がそのまま AI に引き継がれ、AI はプラットフォーム名を使用して、どのプラットフォームに一時的な問題が発生しているかをユーザーに伝えます。 Reach 独自の提案で上書きされることはなくなりました (「ログイン」すると、Reach には独自の専用ブラウザのログイン手順が表示されます)。

英語 (技術):

  • 40 件のアクションのうち 28 件がリリース前に実際に承認されました。これらはメンテナの承認を得て未テストで出荷されます: Reddit (テストネットワークはブロックされています)、Instagram (レート制限)、Bilibili 字幕、LinkedIn、Xueqiu ホットポスト/ストック (ログインなし)、Xiaoyuzhou (キーなし)。
  • ブラウザ チャネルは 1 つのプロファイルを共有し、10 分間アイドル状態になると終了し、必要に応じて再度開きます。
  • チャネルを追加すると、そのツールが準備されます。削除すると、そのサイトのログインのみがクリアされます。デフォルトのプラットフォームは削除できますが、更新しても再び追加されることはありません。
  • 更新すると、テストされたバージョンを持つツールがそのバージョンに維持されます。他のツールは、サポートされている範囲内の最新バージョンを取得します。
  • 公開コンテンツは引き続き公開優先であり、コンパクトな機能レシートを備えています。
  • Xiaoyuzhou の転写を保存します。余分なプランナーと重複したサイト抽出を削除します。
  • 既存のローカル サイト セッションを読み取り専用で再利用します。クエリはデフォルトでヘッドレスになり、人間によるログイン用のウィンドウが表示されます。
  • 専用ブラウザは、その拡張機能が独自のプロファイル内に保存する ID によって識別されるため、ユーザー自身の Chrome がそれと間違われることはありません。クエリによって、開いているログイン ウィンドウが閉じられなくなりました。
  • ブラウザ チャネルはクエリを並行して実行します。プラットフォームごとに最大 2 つ、合計で 4 つまで実行され、残りは一度に BUSY に失敗するのではなくキューに入れられます。ログイン ウィンドウ、ログアウト、ブラウザのセットアップはクエリの実行を待ちます。
  • ログインしていない場合は UPSTREAM_BROKEN ではなく NEED_LOGIN を報告します: Xueqiu コミュニティ (エラー 400016)、Bilibili 字幕 (Bilibili ログインなし)、LinkedIn (専用ブラウザで LinkedIn ログインなし)。
  • 1.5 からのスムーズなアップグレード: インストールとアップデートは 1 つのガイド、install.md を共有し、最初にバージョンをチェックします (1.5 がユーザーに送信する update.md はそれを指します)。 agent-reach update は、pip/pipx インストールを単独で uv に移動します。 setup は古い Agent Reach プログラム (Agent Reach 自体のみ) を削除します。インストール レポートには、何が保持され、何が変更され、どの古いチャネルを再度追加できるかが説明されます。インストール URL は常に最新リリースを指します。
  • アップストリーム エラーは、変更されずにエージェントに届きます (元のメッセージとヘルプ)。エージェントは、どのプラットフォームが一時的に利用不可になっているかをプラットフォーム名でユーザーに通知します。 Reach は、それらを独自のアドバイスに置き換えなくなりました (NEED_LOGIN は引き続き Reach の専用ブラウザーのログイン手順を提供します)。

🔐 上司の直接採用 — ログインステータスの誤った判断 (二重認証情報の保管)

  • 根本原因: Boss には、相互に表現しない 2 つのログイン状態ストレージがあります - ローカル ~/.boss-agent/auth/session.enc 専用の Chrome プロファイル内のブラウザ Cookie。 boss status / status --live 前者のみを確認してください (Bridge/httpx 時代のレガシー資格情報ライブラリ)、厳密な CDP モードでの existing-browser の検索ではブラウザーの Cookie が使用されます。 「ローカルに古い認証情報があり、ブラウザがログインしていない」場合、boss status は logged_in: true を報告し、エージェントを誤解させます。 ログインをスキップして直接検索し、最後に AUTH_EXPIRED を押します。古いランブックは禁止されました _security_check ログインしていないかのように、2 つのルールが重なり合い、エージェントを「アンチクライム スライダー」の間違ったブランチに押し込みます。
  • 修正: check() 純粋な標準ライブラリを使用して、レイヤー 4 読み取り専用検出 _cdp_zhipin_login_cookie() を追加しました。 実装された最小限の WebSocket クライアントは、CDP ブラウザ本体 (Storage.getCookies) に zhipin があるかどうかを直接問い合わせます。 wt2 Cookie は ブラウザに依存し、新しい依存関係を導入せず、ブラウザを起動せず、検索も実行しません。 No wt2 → 「ブラウザはログインしていません。検索では AUTH_EXPIRED が報告されます」と明確に報告し、「ユーザー ログイン +」をポイントします。 login --cdp";検出に失敗しました → 「不明なログイン状態」が報告されます。セキュリティ検証ページのプロンプトには、ブラウザーの Cookie ステータスも含まれます。
  • ランブックの修正: 誤解を招くルール「ログイン ステータスの決定には boss status のみを信頼する」を削除し、医師のルールに変更します。 ブラウザの Cookie は正確に検出されます。専用 Chrome を起動した後、ユーザーがログイン ステータスを視覚的に確認できるようにするために強制的に一時停止されます。 AUTH_EXPIRED がグラウンド トゥルースとして設定されます (ログイン プロセスに直接進み、セキュリティ検証の方向での解釈は禁止されます)。 _security_checkはAUTH_EXPIREDがない場合のみスライダーで扱います。

  • check() 4 層読み取り専用検出 (boss-agent-cli がインストールされているかどうか → 9222 ポートに到達できない → Zhipin タブがあるかどうか) → ブラウザに wt2 ログイン Cookie があるかどうか)。

Agent-Reach v1.6.0

Highlights

  • Single-command rebuild — v1.6 is a ground-up rebuild: agents now drive everything through one entry point (agent-reach <channel> <action>, plus agent-reach read <url> / agent-reach channels) behind a unified JSON envelope, error hints and per-call timeouts, with all installs, keys, cookies and tools under ~/.agent-reach/. For adopters this is the headline capability and a breaking caller-side change: harnesses, wrappers or MCP clients built against the pre-1.6 command surface must be rewritten, and state outside that directory does not migrate automatically.

  • Read-only CDP probe fixes Boss login-state misjudgment — boss status only validated the legacy local credential store while CDP-mode search actually used browser cookies, so agents could be told "logged in" and then hit AUTH_EXPIRED. The fix adds a fourth read-only detection layer, _cdp_zhipin_login_cookie(), which queries the CDP browser via a stdlib WebSocket client and Storage.getCookies for the wt2 cookie — no new dependency, no browser launch, no search. The runbook now treats AUTH_EXPIRED as ground truth, and the boss-agent-cli backend was pinned to upstream commit 4c991b7 (#403–#407).

  • Upgrade from 1.5 is now a single guided flow — install and update share one install.md that version-checks before diverging (update.md from 1.5 now redirects there), agent-reach update self-migrates pip/pipx installs to uv, and setup removes the old Agent Reach program while preserving config.yaml keys. Release notes also now open with plain-language summaries intended for the AI to relay to end users.

  • Browser channels gained parallel queries and precise auth errors — up to 2 concurrent queries per platform and 4 total; excess queries queue instead of failing BUSY, and login windows, logout and browser setup wait for in-flight queries. Missing-login cases now report NEED_LOGIN with the concrete cause (Xueqiu error 400016, Bilibili no-login, LinkedIn absent in the dedicated browser) instead of the misleading UPSTREAM_BROKEN, so agents attribute credential gaps correctly instead of misreading them as upstream breakage.

  • Breaking removals land in the pre-1.6 surface — the MCP server entry, watch, doctor --live, browser start, configure --from-browser, twitter-cookies / xhs-cookies, old install --channels, old skill --install, format, check-update, the RSS channel, and pipx installs are gone; adopters must move to the add / remove / login / logout / doctor / check / skill / update / configure / uninstall surface.

🐛 Bug Fixes / 修复

🔐 Boss直聘 — 登录态误判（双凭据存储）

  • 根因： Boss 有两个互不代表的登录态存储——本地 ~/.boss-agent/auth/session.enc 和专用 Chrome profile 内的浏览器 cookie。boss status / status --live 只校验前者 （Bridge/httpx 时代的遗留凭据库），而 existing-browser 严格 CDP 模式下搜索走的是浏览器 cookie。 「本地有旧凭据 + 浏览器未登录」时 boss status 会报 logged_in: true，误导 Agent 跳过登录直接搜索，最终撞上 AUTH_EXPIRED；旧 runbook 又禁止把 _security_check 当成未登录，两条规则叠加把 Agent 推向「反爬滑块」的错误分支。
  • 修复： check() 新增第 4 层只读探测 _cdp_zhipin_login_cookie()，用纯标准库 实现的最小 WebSocket 客户端直接问 CDP 浏览器本体（Storage.getCookies）有无 zhipin 的 wt2 cookie，以浏览器为准，不引入新依赖、不拉起浏览器、不执行搜索。 无 wt2 → 明确报「浏览器未登录，搜索会报 AUTH_EXPIRED」并指向「用户登录 + login --cdp」；探测失败 → 报「登录态未知」；安全校验页提示也附带浏览器 cookie 状态。
  • Runbook 修正： 删除误导规则「判断登录态只信 boss status」，改为以 doctor 的 浏览器 cookie 探测为准；拉起专用 Chrome 后强制暂停让用户肉眼确认登录状态； AUTH_EXPIRED 定为 ground truth（直接走登录流程，禁止往安全校验方向解释）， _security_check 仅在无 AUTH_EXPIRED 时按滑块处理。

✨ Features / 新增

🎯 Boss直聘 channel

  • 新增 boss channel：经 boss-agent-cli + CDP 真 Chrome 搜岗位、取 JD 全文。
  • check() 四层只读探测（boss-agent-cli 装没装 → 9222 端口通不通 → 有无 zhipin 页签 → 浏览器内有无 wt2 登录 cookie）。
  • 抓取走公开 API（search_jobs + job_card_browser + browser_source="existing-browser"）。

  • Skill 与安装指南支持“帮我配 Boss直聘”：Agent 启动仅监听回环地址的专用 Chrome， 用户只负责手动登录，最后由 Agent 验证登录态与 CDP 链路。

  • code 37 按原始文案分类：环境异常为 ENVIRONMENT_RISK 并立即停止；只有明确 token/stoken 过期才允许一次刷新。专用 Chrome profile 应长期复用并降低频率。
