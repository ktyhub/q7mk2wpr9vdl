nacos 3.2.4

#ナコス3.2.4

Nacos 3.2.4 は、主に 3.2 シリーズのバグ修正、セキュリティ強化、エクスペリエンス向上を目的としたリリースです。

このリリースは以下に重点を置いています。

  • JRaft、HTTP/gRPC 認証、組み込みデータベース、ログイン、アクティブ ヘルス チェック、および MCP インポート セキュリティを強化します。
  • スタンドアロン コンソール、プロンプトの表示、構成履歴、リスナーの状態、MCP ツールの認証の問題を修正しました。
  • 構成の詳細、編集、履歴ページの使いやすさが向上しました。

クラスターおよび API オペレーターの場合、このリリースでは次のことも行われます。

  • ローリング アップグレード対応の強制により、サーバー ID 認証をネイティブ JRaft gRPC トラフィックに追加します。
  • 選択された非推奨の v3 AI API をデフォルトで無効にし、一時的な互換性スイッチを提供します。
  • プライベートまたはローカル ターゲットからの MCP ツールのインポート用のホワイトリスト ポリシーを追加します。

このリリースでの詳細な変更点は次のとおりです。

機能

  • #15687 ローリング アップグレード対応の強制を使用して、ネイティブ JRaft gRPC トラフィックにサーバー ID 認証を追加します。

拡張/リファクタリング

  • #14817 非推奨のパイプラインおよびMCPインポートAPIに対して、デフォルトで無効になっている共有互換性ゲートを追加しました。
  • #15661 サポートされているスカラー型と登録された行マッパーに対する分散埋め込みデータベースの結果解決を強化します。
  • #15688 一貫したルート照合のためにコントローラーのコンテキストパス URI 解析をリファクタリングします。
  • #15695 コンパクトなメタデータと全画面コンテンツビューにより、構成の詳細、編集、履歴のレイアウトが改善されました。
  • #15712 ターゲットアドレスを検証し、安全でないMySQL JDBCオプションを無効にすることで、アクティブなヘルスチェックを強化します。
  • #15749 MCP ツールのインポートに構成可能な送信アクセス制御を追加し、パブリック ターゲットと許可リストに登録されたプライベートまたはローカル ターゲットを許可します。

バグ修正

  • #15475 サーバーが発信者固有のRBACを強制するように、スタンドアロンコンソールからの発信者ID転送を修正しました。
  • #15476 リスト、詳細、バージョン、ダウンロード、およびClient読み取りパスに対するプロンプト表示の強制を修正しました。
  • #15560 コンソールから公開した後にMCPツールのパススルー認証が失われる問題を修正しました。
  • #15634 #15563 Admin、HTTP/gRPC、Prometheus、および AgentSpec API にわたる認証メタデータとリソース解析を修正しました。
  • #15660 Configクローン権限チェッカーBeanの欠落が原因で発生するスタンドアロンコンソールの起動エラーを修正しました。
  • #15682 ログイン失敗の応答を正規化することで、ユーザー名の列挙を防止しました。
  • #15701 Derby での構成履歴の次のレコードのクエリを修正し、グレー名フィルタリングを正しく適用しました。
  • #15724 クラスターメンバー間でIPリスナーごとの状態を集約するときに、名前空間フィルターを保持します。

重大な変更通知

Nacos 3.2.4 は、非推奨の AI API とプライベート MCP ツールのインポートのデフォルトの動作を変更し、不可逆的な JRaft 認証強制移行を導入します。

影響を受けるユーザー:

  • 非推奨のパイプライン リスト/詳細または従来の MCP インポート API を呼び出すユーザー。これらの API はデフォルトで HTTP 410 Gone を返すようになりました。
  • コンソール オペレーターがプライベート アドレスまたはローカル アドレスから MCP ツールをインポートする。これらのターゲットには、管理者が管理する許可リストが必要になりました。
  • すべてのメンバーが JRaft 認証の強制を有効にした後、クラスターが混合バージョンのローリング ダウングレードを試行します。

推奨されるアップグレード パス:

  • 正規パイプラインおよび /v3/console/ai/import/* API に移行します。追加の移行時間が必要な場合は、一時的に nacos.core.api.compatibility.enabled=true を設定します。
  • すべてのコンソール インスタンスで nacos.console.ai.mcp.import.allowed-private-addresses を構成し、プライベート ターゲットが必要な場合はコンソールを再起動します。
  • アップグレードする前に、nacos.core.auth.server.identity.key と nacos.core.auth.server.identity.value がすべてのクラスター メンバーで同一に構成されていることを確認してください。 Nacos はこれらの値を使用して JRaft gRPC リクエストを認証しますが、クラスター全体でそれらの値を同期しません。
  • JRaft 認証が強制モードに入った後は、混合バージョンのローリング ダウングレードに依存しないでください。

正規 AI API、パブリック MCP エンドポイント、一貫したサーバー ID をすでに使用しているユーザーは、これらの互換性変更の影響を受けません。

nacos 3.2.4

Nacos 3.2.4 is mainly a bugfix, security-hardening, and experience-improvement release for the 3.2 series.

This release focuses on:

  • Strengthening JRaft, HTTP/gRPC authorization, embedded database, login, active health check, and MCP import security.
  • Fixing standalone Console, Prompt visibility, Config history, listener state, and MCP tool authentication issues.
  • Improving Config detail, edit, and history page usability.

For cluster and API operators, this release also:

  • Adds server-identity authentication to native JRaft gRPC traffic with rolling-upgrade-aware enforcement.
  • Disables selected deprecated v3 AI APIs by default and provides a temporary compatibility switch.
  • Adds an allowlist policy for MCP tool imports from private or local targets.

Detailed changes in this release:

Feature

  • #15687 Add server-identity authentication to native JRaft gRPC traffic with rolling-upgrade-aware enforcement.

Enhancement/Refactor

  • #14817 Add a shared, disabled-by-default compatibility gate for deprecated Pipeline and MCP import APIs.
  • #15661 Harden distributed embedded database result resolution to supported scalar types and registered row mappers.
  • #15688 Refactor controller context-path URI parsing for consistent route matching.
  • #15695 Improve Config detail, edit, and history layouts with compact metadata and a full-screen content view.
  • #15712 Harden active health checks by validating target addresses and disabling unsafe MySQL JDBC options.
  • #15749 Add configurable outbound access control for MCP tool imports, allowing public targets and allowlisted private or local targets.

BugFix

  • #15475 Fix caller identity forwarding from a standalone Console so the Server enforces caller-specific RBAC.
  • #15476 Fix Prompt visibility enforcement for list, detail, version, download, and Client read paths.
  • #15560 Fix MCP tool passthrough authentication being lost after publishing from the Console.
  • #15634 #15563 Fix authorization metadata and resource parsing across Admin, HTTP/gRPC, Prometheus, and AgentSpec APIs.
  • #15660 Fix standalone Console startup failure caused by a missing Config clone permission checker bean.
  • #15682 Prevent username enumeration by normalizing login failure responses.
  • #15701 Fix Config history next-record queries on Derby and apply gray-name filtering correctly.
  • #15724 Preserve the namespace filter when aggregating listener-by-IP state across cluster members.

Breaking Change Notice

Nacos 3.2.4 changes the default behavior of deprecated AI APIs and private MCP tool imports, and introduces an irreversible JRaft authentication enforcement transition.

Affected users:

  • Users calling the deprecated Pipeline list/detail or legacy MCP import APIs. These APIs now return HTTP 410 Gone by default.
  • Console operators importing MCP tools from private or local addresses. These targets now require an administrator-managed allowlist.
  • Clusters attempting a mixed-version rolling downgrade after all members have enabled JRaft authentication enforcement.

Recommended upgrade path:

  • Migrate to the canonical Pipeline and /v3/console/ai/import/* APIs. If additional migration time is required, temporarily set nacos.core.api.compatibility.enabled=true.
  • Configure nacos.console.ai.mcp.import.allowed-private-addresses on every Console instance and restart the Console when private targets are required.
  • Before upgrading, verify that nacos.core.auth.server.identity.key and nacos.core.auth.server.identity.value are configured identically on every cluster member. Nacos uses these values to authenticate JRaft gRPC requests but does not synchronize them across the cluster.
  • Do not rely on a mixed-version rolling downgrade after JRaft authentication has entered enforced mode.

Users already using the canonical AI APIs, public MCP endpoints, and consistent server identities are not affected by these compatibility changes.

Java Version Requirements

| Module | Java Required | |--------|--------------| | Nacos-Server / Nacos-Console | Java 17 | | Nacos-Client | Java 8 | | Nacos-Maintainer-Client | Java 8 |
