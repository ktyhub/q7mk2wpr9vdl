nacos 2.4.0

#ナコス2.4.0

最初に 2.4.0.1 を使用してください このバージョンは、多くの新機能をサポートする重要なバージョンです。 最も主な機能は、Nacos サポート メンテナーが、デフォルトのパスワードを使用する代わりに管理者ユーザー nacos パスワードを初期化し、nacos クラスターをデプロイするためのデフォルトのセキュリティを向上させることです。 もう 1 つは、スタンドアロン モードで展開するときに認証が有効になっていないユーザーに対する対応するリスクに関する誤ったアラームを防ぐために、デフォルトで無効になっている derby ops API です。保守者がこの API を使用して derby のデータを保守および照会したい場合、保守者は nacos.config.derby.ops.enabled=true を使用してこの API を開くことができます。 その他の主な機能は、Nacos のセキュリティを向上させるためのオプション機能として Nacos クラスター ノード間の TLS Grpc 通信をサポートすることです。つまり、nacos は client とサーバー間の TLS 通信をサポートするだけではありません。さらに、Nacos は、ヘルスおよびクラスターごとにサービスのインスタンスを選択できるだけでなく、ネーミングモジュールのコールバック Subscriber の前にユーザー拡張 Selector をサポートし始めました。また、Nacos client は、Subscriber キャッシュと比較ロジックを削減するために、新しいイベントによるコールバック サービスの差分をサポートします。 3 番目の主な機能は、Nacos コンソールでの一部の構成の使用をサポートし、prometheus sd プロトコルへのすべてのメタデータの追加のサポートや、aliyun ram v4 署名のサポートなど、プラグインの拡張使用をサポートすることです。 このバージョンでは、大幅な機能更新に加えて、以前のバージョンのいくつかのバグも修正され、セキュリティの脆弱性のある特定の依存関係がアップグレードされています。 詳細は以下を参照してください。

機能

[#10374] カスタムセレクターの命名をサポートし、サービスの差分イベントをサポートします。 [#11456] Nacosクラスタノード間のTLS Grpc通信をサポートします。 [#11847] Nacos コンソールは、cas による設定の公開をサポートしています。 [#11943] インポート構成のユーザーを記録します。 [#11957] ユーザーnacosのデフォルトのパスワードを削除します。 [#12130] prometheus http sdにメタデータをラベルとして追加します。 [#12162] aliyun ram v4 署名方式をサポートしました。

強化とリファクタリング

[#11956] nacos client ログモジュールをリファクタリングし、SPI 負荷電流ロガーアダプタを使用します。 [#12013] CUSTOM_NACOS_MEMORY環境によるstartup.shの高速構成Nacosメモリ設定を強化しました。 [#12072] totalCountLimit が 0 未満の場合、サポートは制限を課しません。 [#12166] nacos client init プロパティロガーを強化しました。 [#12177] コンソールヘッダーのリンクを新しい nacos.io に更新します。 [#12178] ページネーションに総レコード数表示を追加しました。 [#12185] CacheDirUtil で nacos プロパティを使用します。 [#12221] URL から accessToken を削除します。 [#12235] ResponseExceptionHandlerのログ形式を強化しました。 [#12246] 設定リストとサービスリストの合計数の表示を国際化しました。 [#12321] NetworkInterface.ifUp からの予期しない例外のログを強化しました。 [#12355] ConfigDumpのコストをPrometheusに記録します。 [#12372] derby ops apiのデフォルトを無効にします。 [#12382] RAM情報スイッチをサポートしました。

バグ修正

依存関係

nacos 2.4.0

Please use 2.4.0.1 first

This version is an important version which support many new features.

The most mainly feature is Nacos support maintainer to initialize the admin user nacos password instead of using default password to improve the default security for deploy nacos clusters.

One more thing is default disabled derby ops API to prevent false alarms regarding corresponding risks for users without authentication enabled when deploying in standalone mode. If maintainers want use this API to maintain and query data in derby, maintainers can use nacos.config.derby.ops.enabled=true to open this API.

And other mainly features are support TLS Grpc communication between Nacos cluster nodes as an optional feature to improve Nacos security, which means nacos not only support TLS communication between client and server; What's more, Nacos start to support user extend Selector before callback Subscriber for naming module, not only can select instance of services by healthy and clusters. And Nacos client support callback service diffs by new event to reduce Subscriber cache and compare logics.

Third mainly features are support some configs usages in Nacos console and support more enhancement usage for plugins, such as support add all metadata to prometheus sd protocol and support aliyun ram v4 signature.

In addition to substantial feature updates, this version also fixes some bugs from previous versions and upgrades certain dependencies with security vulnerabilities.

[#12235] Enhance logging format in the ResponseExceptionHandler. [#12246] Internationalize the display of total counts in the configuration list and service list. [#12321] Enhance log for unexpected exception from NetworkInterface.ifUp. [#12355] Record the cost of ConfigDump in Prometheus. [#12372] Disable derby ops api default. [#12382] Support ram info switch.

[#11951] Fix the problem that the serviceName and groupName are not resolved correctly when deleting an empty service instance. [#12022] Fix nacos datasource plugin ClassCastException problem. [#12046] Fix cipher-aes config encrypt plugin not effect when publish config again. [#12060] Fix too large ttl when auth disabled. [#12168] Fix the labels of the query conditions on the Permission Control - Role Management page are still displayed in Chinese after switching the system language to English.
