accelerate v1.10.0

マイナー 公開日2025年8月7日 出典huggingface/accelerate English original

v1.10.0 を加速します

N-D 並列処理

複数の GPU にわたる大規模なモデルのトレーニングは、特に さまざまな並列処理戦略 (TP、CP、DP など) を組み合わせる場合、複雑になる可能性があります。このプロセスを簡素化するために、Axolotl と協力して、並列化戦略の任意の組み合わせをトレーニング スクリプトに直接適用できる使いやすい統合を導入しました。各並列処理タイプのサイズを指定する ParallelismConfig を渡すだけです。とても簡単です。 その仕組みについて詳しくは、最新の ブログ投稿 をご覧ください。

parallelism_config = ParallelismConfig(
    dp_shard_size=2,
    dp_replicate_size=2,
    cp_size=2,
    tp_size=2,
)
accelerator = Accelerator(
    parallelism_config=parallelism_config,
   ...
)
model = AutoModelForCausalLM.from_pretrained("your-model-name", device_mesh=accelerator.torch_device_mesh)
model = accelerator.prepare(model)
  • 並列処理構成 + TP + HSDP + BYODM (Bring Your Own Device Mesh) (https://github.com/huggingface/accelerate/pull/3682 の @SalmanMohammadi による)
  • 機能: https://github.com/huggingface/accelerate/pull/3700 の @S1ro1 によるコンテキスト パラレル v2.0
  • https://github.com/huggingface/accelerate/pull/3687 の @winglian によるローカル変数の未設定エラーを防ぐために、デフォルトの submesh_tp_size を設定します
  • https://github.com/huggingface/accelerate/pull/3703 の @WoosungMyung により、Parallelism getter プロパティを Accelerator クラスに追加
  • 修正: https://github.com/huggingface/accelerate/pull/3707 の @S1ro1 によって tp 以外が指定されていない場合でも (まれに) prepare が機能します。
  • https://github.com/huggingface/accelerate/pull/3713 の @winglian による State の Trainer リセットにより、コンストラクターにParallelism_config を設定します
  • 修正: https://github.com/huggingface/accelerate/pull/3716 の @S1ro1 によって tp サイズが env から読み取られない
  • https://github.com/huggingface/accelerate/pull/3720 の @SunMarc により PartialState から ParallelismConfig を削除

FSDP の改善

無視されたモジュール属性を修正しました。これにより、q_proj および v_proj パラメーターを制約する層を萌える PEFT モデルをトレーニングできるようになりました。これは、gpt-oss モデルを微調整する場合に特に重要です。

  • ENH: https://github.com/huggingface/accelerate/pull/3698 の @BenjaminBossan による FSDP 無視モジュールを正規表現にできるようにする
  • TST https://github.com/huggingface/accelerate/pull/3719 の @BenjaminBossan による FSDPignored_modules のテストを str として追加

マイナーな改善

  • 機能: CpuOffload pre_forward は、既にデバイス上にある場合は移動を試みません (https://github.com/huggingface/accelerate/pull/3695 の @JoeGaffney による)
  • 修正: https://github.com/huggingface/accelerate/pull/3712 の @jp1924 による高速化で環境変数の値が大文字と小文字を区別しないようにしました
  • https://github.com/huggingface/accelerate/pull/3721 の @SunMarc により use_ipex を削除

accelerate v1.10.0

Highlights

  • Composable N-D parallelism — ParallelismConfig combines DP sharding/replication, TP, and CP in one topology. Pass it to Accelerator, provide accelerator.torch_device_mesh to Transformers through device_mesh=, then call accelerator.prepare(); custom device meshes are also supported (#3682), reducing manual mesh and process-group wiring.
  • Integrated context parallelism — CP v2 joins the same configuration and preparation flow (#3700), enabling sequence-dimension sharding for long-context training. Validate attention handling: Accelerate’s automatic CP path assumes causal attention and removes attention masks, so custom or non-causal masking needs explicit integration.
  • FSDP regex ignores for MoE PEFT — ignored_modules now accepts regex patterns (#3698, #3719), enabling FSDP with PEFT on MoE layers containing q_proj and v_proj, notably for gpt-oss. Avoid overly broad patterns, which can exclude additional parameters from sharding and increase memory usage.
  • More robust parallelism lifecycle — parallelism_config is exposed on Accelerator (#3703), preserved across Trainer state resets (#3713), and removed from PartialState (#3720); integrations should read it from the accelerator. TP-only prepare() and TP environment-variable parsing are also fixed (#3707, #3716).
  • Lower offload overhead and predictable configuration — CPU offload now skips transfers when a tensor is already on the target device (#3695), while case-insensitive environment-variable values (#3712) reduce configuration surprises.
  • Removed IPEX launch flag — the deprecated accelerate launch --ipex option is gone (#3721). Remove it from scripts and wrappers; PyTorch 2.7+ provides the Intel CPU/XPU optimizations that previously motivated it.

N-D Parallelism

Training large models across multiple GPUs can be complex, especially when combining different parallelism strategies (e.g TP, CP, DP). To simplify this process, we've collaborated with Axolotl to introduce an easy-to-use integration that allows you to apply any combination of parallelism strategies directly in your training script. Just pass a ParallelismConfig specifying the size of each parallelism type—it's that simple. Learn more about how it works in our latest blogpost.

parallelism_config = ParallelismConfig(
    dp_shard_size=2,
    dp_replicate_size=2,
    cp_size=2,
    tp_size=2,
)
accelerator = Accelerator(
    parallelism_config=parallelism_config,
   ...
)
model = AutoModelForCausalLM.from_pretrained("your-model-name", device_mesh=accelerator.torch_device_mesh)
model = accelerator.prepare(model)

FSDP improvements

We've fixed ignored modules attribute. With this, it is now possible to train PEFT model that moe layers that contrains q_proj and v_proj parameters. This is especially important for fine-tuning gpt-oss model.

  • ENH: Allow FSDP ignored modules to be regex by @BenjaminBossan in https://github.com/huggingface/accelerate/pull/3698
  • TST Add test for FSDP ignored_modules as str by @BenjaminBossan in https://github.com/huggingface/accelerate/pull/3719
