accelerate v1.14.0

マイナー 公開日2026年6月11日 出典huggingface/accelerate English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

v1.14.0 を加速します

FSDP2 の改善

このリリースでは、FSDP2 の修正と生活の質の向上の大規模なバッチが提供されます。ロード時の正しい dtype 処理、エンベディング/ノルムのシャーディング、QLoRA クラッシュ防止、およびより堅牢な自動ラップ ポリシーです。

  • #4015 の @SunMarc による Fsdp2 fully_shard の埋め込みとノルム
  • #4021 の @SunMarc による fsdp2 ロードの完全な状態の dict dtype の不一致を修正
  • #4022 の @SunMarc によるリージョン コンパイル fsdpv2 を修正
  • [FSDP2] #3985 の @roycho96 による混合 dtype AssertionError を修正するために、full_shard の前にモデルを統一 dtype にキャストします。
  • [FSDP2] #3987 の @roycho96 による QLoRA クラッシュを防ぐために、非浮動凍結 Params4bit を fully_shard から自動除外します
  • 修正(FSDP2): #3999 の @JohnGiorgi による _no_split_modules フォールバックを無視する自動ラップ ポリシー
  • 修正: #3982 の @roycho96 による fsdp2_load_full_state_dict でキーベースのマッチングを使用する
  • 修正: #3981 で @roycho96 による fsdp2_load_full_state_dict 呼び出しに欠落していた model_has_params4bit ガードを追加
  • fsdp2 を修正: #4065 の @lollinng によってリークするのではなく、削除済み / NOT_YET_IMPLEMENTED FSDP1 キーを削除します。
  • #3977 の @joshuaswanson による prepare_model() でのモデルの二重ラッピングを防止

AMD ROCm のサポート

Accelerate が AMD ROCm デバイス上でエンドツーエンドで動作するようになりました。ありがとう@Abdennacer-Badaoui!

  • #4025 の @Abdennacer-Badaoui により、AMD ROCm でエンドツーエンドの作業を高速化します。

ニューロン

再コンパイルを削減し、デバイスの欠落ケースをカバーするための Neuron のさらなる改善。

  • #4000 で @czkkkkkk による再コンパイルを減らすために、Neuron デバイス用のパディングされたオールギャザーとブロードキャストを追加しました。
  • 修正: @michaelbenayoun による欠落しているニューロン デバイスのケースを #4042 に追加

量子化とオフロード

量子化モデル (Torchoo、int8、タイ重み処理など) のオフロード サポートを改善しました。

  • #3973 の @SunMarc による Torchao オフロード
  • #4044 の @jiqing-feng による int8 オフロード フック切断統計復元を修正
  • #4043 の @jiqing-feng による、load_and_quantize_model の結合された重みに対して keep_in_fp32_modules が機能しない問題を修正
  • #4063 の @lollinng による FP8 fnuz / e8m0fnu dtype の dtype_byte_size を修正

データのロード

  • 機能: #3969 の @yuxinyuan による Even_batches を使用した BatchSamplerShard での動的バッチ サイズのサポート
  • #3958 の @SunMarc による n_shards == num_processes の場合の反復可能なデータセットのシャーディング条件を修正
  • #4052 の @3manifold により、apply_padding=False および num_samples < num_processes の場合の split_between_processes の暗黙的なパディングを修正しました。

accelerate v1.14.0

Highlights

  • FSDP2 training correctness — FSDP2 now casts models to a uniform dtype before sharding, fully shards embeddings and normalization layers, and excludes frozen non-floating Params4bit from wrapping (#3985, #4015, #3987). Mixed-precision training and QLoRA should avoid these known sharding assertions and crashes without manual workarounds.
  • FSDP2 loading and conversion — Full-state loading now uses key-based matching with corrected dtype and Params4bit handling (#3982, #4021, #3981). Auto-wrap respects _no_split_modules, and prepare_model() prevents double-wrapping (#3999, #3977). The to-fsdp2 conversion drops unsupported FSDP1-only keys instead of leaking them into FSDP2 (#4065), so those options are no longer forwarded.
  • Expanded hardware support — Accelerate now supports end-to-end AMD ROCm workflows (#4025), while Neuron pads all-gather and broadcast operations to reduce recompilation (#4000). For XPU, pytorch-triton-xpu is renamed to triton-xpu (#4007); update any explicit dependency references.
  • Quantized offloading — TorchAO offloading is now supported (#3973), int8 offload-hook statistics are restored correctly (#4044), and keep_in_fp32_modules works with tied weights in load_and_quantize_model (#4043). This reduces precision surprises when offloading quantized models with shared parameters.
  • Distributed data edge cases — BatchSamplerShard supports dynamic batch sizes with even_batches (#3969). Fixes also remove unintended padding when processes outnumber samples (#4052) and correct iterable-dataset sharding when shard and process counts match (#3958). Pipelines using workarounds should recheck sample counts and padding assumptions.
  • Breaking changes — None declared upstream.

FSDP2 Improvements

This release brings a large batch of FSDP2 fixes and quality-of-life improvements: correct dtype handling on load, sharding of embeddings/norms, QLoRA crash prevention, and a more robust auto-wrap policy.

  • Fsdp2 fully_shard embedding and norm by @SunMarc in #4015
  • Fix fsdp2 load full state dict dtype mismatch by @SunMarc in #4021
  • Fix region compilation fsdpv2 by @SunMarc in #4022
  • [FSDP2] Cast model to uniform dtype before fully_shard to fix mixed-dtype AssertionError by @roycho96 in #3985
  • [FSDP2] Auto-exclude non-floating frozen Params4bit from fully_shard to prevent QLoRA crash by @roycho96 in #3987
  • fix(FSDP2): auto-wrap policy ignoring _no_split_modules fallback by @JohnGiorgi in #3999
  • fix: use key-based matching in fsdp2_load_full_state_dict by @roycho96 in #3982
  • fix: add missing model_has_params4bit guard to fsdp2_load_full_state_dict call by @roycho96 in #3981
  • Fix to-fsdp2: drop REMOVED / NOT_YET_IMPLEMENTED FSDP1 keys instead of leaking them by @lollinng in #4065
  • Prevent double-wrapping models in prepare_model() by @joshuaswanson in #3977

AMD ROCm support

Accelerate now works end-to-end on AMD ROCm devices. Thanks @Abdennacer-Badaoui!

  • Make accelerate work end-to-end on AMD ROCm by @Abdennacer-Badaoui in #4025

Neuron

Further Neuron improvements to reduce recompilation and cover missing device cases.

  • Add padded allgather and broadcast for Neuron devices to reduce recompilation by @czkkkkkk in #4000
  • fix: add missing neuron device case by @michaelbenayoun in #4042

Quantization & Offloading

We improved offloading support for quantized models, including Torchao, int8, and tied-weight handling.

  • Torchao offload by @SunMarc in #3973
  • Fix int8 offload hook detachment statistics restoration by @jiqing-feng in #4044
  • Fix keep_in_fp32_modules not working for tied weights in load_and_quantize_model by @jiqing-feng in #4043
  • Fix dtype_byte_size for FP8 fnuz / e8m0fnu dtypes by @lollinng in #4063

Data Loading

  • Feat: Support dynamic batch size in BatchSamplerShard with even_batches by @yuxinyuan in #3969
  • Fix iterable dataset sharding condition when n_shards == num_processes by @SunMarc in #3958
  • Fix implicit padding in split_between_processes when apply_padding=False and num_samples < num_processes by @3manifold in #4052
