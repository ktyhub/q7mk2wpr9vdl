accelerate v1.8.0

マイナー 公開日2025年6月19日 出典huggingface/accelerate English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

v1.8.0 を加速します

FSDPv2 リファクタリング + FP8 サポート

他の機能 (FP8、torch.compile、アクティベーション チェックポイントなど) を使用して FSDP2 を構成する方法が多すぎるため、FSDPv2 モデルの準備方法を簡略化しました。セットアップの制限が厳しくなりましたが、エラーが減り、ユーザー エクスペリエンスのパフォーマンスが向上しました。 FP8 のサポートも追加しました。結果についてはこちらをご覧ください。 @S1ro1 さんの貢献に感謝します!

  • [FSDP2] リファクタリング + FP8 by @S1ro1 (https://github.com/huggingface/accelerate/pull/3585)

Intel CPU での分散トレーニングの高速化

Intel CPU ユーザー向けに、CCL_WORKER_COUNT 変数を更新し、KMP パラメーターを追加しました。これにより、分散トレーニングのパフォーマンス (Tensor Parallelism など) が大幅に向上し、トランスフォーマー TP モデルのトレーニング時に Intel 第 4 世代 Xeon で最大 40% 高速化されます。

  • https://github.com/huggingface/accelerate/pull/3575 の @jiqing-feng による単純な起動で ccl と KMP パラメータを設定します

DeepSpeed の地域コンパイル

DeepSpeed エンジンによる地域コンパイルのサポートを追加しました。 DeepSpeed の .compile() は、場外の torch.compile(...) ではなく torch.nn.Module.compile(...) を使用してインプレースでモデルを変更するため、それを考慮する必要がありました。この機能を提供してくれた @IlyasMoutawwakel に感謝します!

  • https://github.com/huggingface/accelerate/pull/3609 の @IlyasMoutawwakel によるディープスピード地域コンパイルを修正

ipex.optimize の廃止

ipex.optimize は非推奨になります。ほとんどの最適化は PyTorch にアップストリームされており、将来の改善はそこに直接反映されます。 PyTorch 2.8 を持たないユーザーの場合は、当面は IPEX に依存し続けます。

  • https://github.com/huggingface/accelerate/pull/3608 の @yao-matrix による加速の ipex.optimize を削除

XPU サポートの向上

Intel XPU のサポートを大幅に拡張し、安定させました。

  • https://github.com/huggingface/accelerate/pull/3590 の @yao-matrix により XPU で fsdp2 ベンチマークを有効にします
  • https://github.com/huggingface/accelerate/pull/3595 の @yao-matrix により xpu で big_model_inference を有効にします
  • @yao-matrix により XPU で test_load_checkpoint_and_dispatch_with_broadcast ケースを有効にします
  • https://github.com/huggingface/accelerate/pull/3578 の @yao-matrix により、XPU で test_cli および test_example ケースを有効にします
  • https://github.com/huggingface/accelerate/pull/3599 の @yao-matrix により、XPU で torchao および pippy テスト ケースを有効にします
  • https://github.com/huggingface/accelerate/pull/3592 の @yao-matrix により xpu で Regional_compilation ベンチマークを有効にします
  • https://github.com/huggingface/accelerate/pull/3623 での @jiqing-feng による xpu 8 ビット値のロードを修正
  • デバイスに依存しない GradScaler を @yao-matrix により https://github.com/huggingface/accelerate/pull/3588 に追加
  • https://github.com/huggingface/accelerate/pull/3627 の @yao-matrix により、TorchTensorParallelPlugin に xpu サポートを追加

トラッカー

実験追跡バックエンドとして SwanLab のサポートを追加しました。この貢献に対して @ShaohonChen に多大な感謝を！また、分散環境の時期尚早なセットアップを防ぐために、すべてのトラッカーの初期化を延期しました。

  • https://github.com/huggingface/accelerate/pull/3605 の @ShaohonChen による Accelerate のオフライン/オンライン実験追跡のために SwanLab を統合
  • 修正: https://github.com/huggingface/accelerate/pull/3581 の @yuanjua による時期尚早の分散セットアップを防ぐためにトラッカーの初期化を延期する

accelerate v1.8.0

Highlights

  • Simpler, stricter FSDPv2 setup with FP8 — FSDPv2 preparation now uses a more restrictive configuration path, reducing invalid combinations with FP8, torch.compile, and activation checkpointing while targeting better performance. Existing FSDPv2 recipes should be checked against examples/fsdp2 before upgrading, especially custom feature-composition logic (PR #3585).

  • IPEX optimization deprecation — Accelerate no longer applies ipex.optimize() directly because most optimizations have moved upstream to PyTorch. On PyTorch 2.8+, migrate to native PyTorch equivalents; PyTorch versions below 2.8 still rely on IPEX (PR #3608).

  • Intel CPU distributed-training tuning — accelerate launch now configures CCL_WORKER_COUNT and KMP parameters for Intel CPUs, improving oneCCL and threading coordination. The release reports up to a 40% speedup for transformer tensor-parallel training on 4th Gen Xeon; check for conflicts if you already override these environment variables (PR #3575).

  • DeepSpeed compilation and gradient accumulation — Regional compilation now handles DeepSpeedEngine.compile() mutating models in place, unlike out-of-place torch.compile() (PR #3609). Gradient-accumulation steps can also be derived and synchronized from the DeepSpeed plugin, reducing duplicate configuration and fixing accumulation-related issues (PRs #3630, #3632, #3638).

  • Broader, better-tested Intel XPU support — This release enables big_model_inference, adds XPU support to TorchTensorParallelPlugin, and introduces a device-agnostic GradScaler (PRs #3595, #3627, #3588). It also fixes XPU 8-bit value loading and expands test coverage for FSDPv2 benchmarks, regional compilation, TorchAO, and PiPPy, making XPU workflows more viable for validation.

  • More flexible experiment tracking and startup — SwanLab is now supported for offline and online tracking (PR #3605). Tracker initialization is deferred to prevent premature distributed-environment setup, so custom tracker integrations should not assume they are initialized during object construction (PR #3581).

FSDPv2 refactor + FP8 support

We've simplified how to prepare FSDPv2 models, as there were too many ways to compose FSDP2 with other features (e.g., FP8, torch.compile, activation checkpointing, etc.). Although the setup is now more restrictive, it leads to fewer errors and a more performant user experience. We’ve also added support for FP8. You can read about the results here. Thanks to @S1ro1 for this contribution!

  • [FSDP2] Refactor + FP8 by @S1ro1 in https://github.com/huggingface/accelerate/pull/3585

Faster Distributed Training on Intel CPUs

We updated the CCL_WORKER_COUNT variable and added KMP parameters for Intel CPU users. This significantly improves distributed training performance (e.g., Tensor Parallelism), with up to a 40% speed-up on Intel 4th Gen Xeon when training transformer TP models.

  • Set ccl and KMP param in simple launch by @jiqing-feng in https://github.com/huggingface/accelerate/pull/3575

Regional Compilation for DeepSpeed

We added support for regional compilation with the DeepSpeed engine. DeepSpeed’s .compile() modifies models in-place using torch.nn.Module.compile(...), rather than the out-of-place torch.compile(...), so we had to account for that. Thanks @IlyasMoutawwakil for this feature!

  • Fix deepspeed regional compilation by @IlyasMoutawwakil in https://github.com/huggingface/accelerate/pull/3609

ipex.optimize deprecation

ipex.optimize is being deprecated. Most optimizations have been upstreamed to PyTorch, and future improvements will land there directly. For users without PyTorch 2.8, we’ll continue to rely on IPEX for now.

  • remove ipex.optimize in accelerate by @yao-matrix in https://github.com/huggingface/accelerate/pull/3608

Better XPU Support

We've greatly expanded and stabilized support for Intel XPUs:

  • enable fsdp2 benchmark on XPU by @yao-matrix in https://github.com/huggingface/accelerate/pull/3590
  • enable big_model_inference on xpu by @yao-matrix in https://github.com/huggingface/accelerate/pull/3595
  • enable test_load_checkpoint_and_dispatch_with_broadcast cases on XPU by @yao-matrix in
  • enable test_cli & test_example cases on XPU by @yao-matrix in https://github.com/huggingface/accelerate/pull/3578
  • enable torchao and pippy test cases on XPU by @yao-matrix in https://github.com/huggingface/accelerate/pull/3599
  • enable regional_compilation benchmark on xpu by @yao-matrix in https://github.com/huggingface/accelerate/pull/3592
  • fix xpu 8bit value loading by @jiqing-feng in https://github.com/huggingface/accelerate/pull/3623
  • add device-agnostic GradScaler by @yao-matrix in https://github.com/huggingface/accelerate/pull/3588
  • add xpu support in TorchTensorParallelPlugin by @yao-matrix in https://github.com/huggingface/accelerate/pull/3627

Trackers

We've added support for SwanLab as an experiment tracking backend. Huge thanks to @ShaohonChen for this contribution ! We also deferred all tracker initializations to prevent premature setup of distributed environments.

  • Integrate SwanLab for offline/online experiment tracking for Accelerate by @ShaohonChen in https://github.com/huggingface/accelerate/pull/3605
  • Fix: Defer Tracker Initialization to Prevent Premature Distributed Setup by @yuanjua in https://github.com/huggingface/accelerate/pull/3581
