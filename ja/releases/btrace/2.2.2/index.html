btrace v2.2.2

Highlights

  • Accurate port discovery — btrace.port now contains the actual local port bound by BTrace (#461). Launch scripts and automation using dynamic ports should read this property instead of assuming the requested port was selected.
  • Consistent command-line configuration — Shared settings are now initialized from command-line arguments (#505), reducing divergence between CLI options and runtime configuration. Smoke-test custom launchers that override settings or depend on option precedence.
  • Less reliance on JDK compiler internals — Removing javac-internal usage (#524) reduces exposure to compiler API and module-system changes, improving resilience when building or running BTrace across JDK upgrades.
  • JDK 17 added to CI — The test matrix now includes JDK 17 (#519), providing compatibility coverage for newer runtimes. This is test coverage rather than an explicit support-policy change, so verify your deployment JDK before upgrading.
  • Modernized build and verification tooling — Gradle advances to 7.3.3 (#506), Shadow to 7.1.2 (#520), OSPackage to 9.1.0 (#521), JMH to 1.34 (#515, #516), and JUnit 5 to 5.8.2 (#501). Wrapper-based builds pick these up automatically; custom Gradle plugins, packaging scripts, and benchmarks should be revalidated.
  • Breaking changes — None identified.
