btrace v2.2.1

Highlights

  • JDK compatibility and JFR — Fixes broken instance classes on JDK 11 (#482), adds JFR event support for JDK 8 (#511), and corrects JFR event category definitions (#510). Upgrade if you instrument JDK 11 or use JFR events on JDK 8.
  • Probe matching correctness — Fixes explicit method descriptor matching for overloaded methods (#509) and makes the type check respect return types (#517). Review probes relying on these behaviors, since previously missed matches may now fire.
  • Installation and startup — Resolves a failed git clone workflow (#478) and an incorrect Windows launcher script (#491), removing blockers for clone-based setup and Windows startup.
  • Output and performance — Ensures probe output is redirected on the first connection (#498) and addresses input-dependent performance problems in CallGraph.java (#489). This matters for automation and call-graph analysis.
  • Upgrade recommendation — Worth upgrading for users affected by the JDK, JFR, probe-matching, Windows, or performance fixes; others can skip. This is a bug-fix release, not a no-op, and the changelog documents no breaking changes or required migration steps.

Changelog

v2.2.0 (2021-12-26)

Full Changelog

Fixed issues:

  • Instance classes don't work in JDK11 #482
  • git clone not successful #478
  • Cant start btrace because of wrong windows script #491\
  • BTrace probe's output is not being redirected for the first connection #498
  • [Performance Bug Report] Specific input cause time differences in CallGraph.java #489
  • Explicit method descriptor matching does not work properly for overloaded methods #509
  • JFR event definition category is not working #510
  • Add JFR event support to JDK 8 #511\
  • Return type is ignored in the 'type' check #517
