LlamaFactory v0.9.5

Highlights

  • First-class Qwen3.5 / Qwen3.6 / Gemma 4 support — The headline capability: Qwen3.5 is adapted in #10213, rolled out across the full series in #10237, and Qwen3.6 arrives in #10415, with Gemma 4 added in #10346. This is deeper than config registration — it touches the visual tower (#10227), projector paths (#10242, #10382), multimodal token-ID padding (#10359), packing (#10436) and FlashAttention-2 (#10448). If you've been waiting to fine-tune these architectures, this release makes them trainable end-to-end; given the long tail of follow-up fixes, pin a specific commit rather than a moving tag.

  • Transformers v5 compatibility — A coordinated dependency push (#10147) updates peft and deepspeed alongside Transformers v5, backed by targeted fixes: removing the deprecated safe_serialization argument (#10208), handling NotImplementedError in export_model (#10438, fixes #10410), and meta-device init (#10414), with the version upper bound raised in #10446. Treat this as a required migration, not an optional upgrade — exercise your export and serialization paths, since v5 changes init and save behavior, and note that CI/HF-hub 429 workarounds are already folded in (#10155).

  • V1 training stack matures — The v1 rewrite gains real training weight: FSDP2 (#9773) with Ulysses sequence parallelism (#10262) and rank-0 init (#10264), LoRA/Freeze plus a merge workflow (#10157), DeepSpeed (#10181), quantization (#10161), checkpoint resume (#10280), reward training (#10431), a Triton fused-MoE kernel (#10481) and Liger kernel support (#10493), alongside FlashAttention selection with normal / padding-free / dynamic batching. This is the most consequential change for adopters — v1 is clearly the future path, but it's moving fast, so evaluate it for new projects and watch the ongoing device-mesh and gradient-clipping fixes (#10366, #10429).

  • Distributed training and MoE reliability — You can now launch distributed runs via ray.remote (#10109), with KTransformers AMX MoE SFT through Accelerate (#10430) and HyperParallel FSDP2 SFT (#10289). Multiple MoE/kernel patches land (#9867, #10334, #10481) and a multi-GPU LoggerHandler race condition is fixed (#10156). For multi-node or MoE workloads this matters more than new model checkboxes — the emphasis here is correctness and stability under scale.

  • Training data and loss options — New method choices arrive via EAFT (#9720) and ASFT (#10174); multi-turn training can now discard history CoT (#10435); datasets.interleave_datasets gains all_exhausted_without_replacement (#10112); and packing gets fixes for neat-packing/MRoPE (#10283) and empty system-message content (#10291). These are the levers that actually shift training quality and reproducibility — worth testing if your pipeline depends on packing or interleaved datasets.

  • Platforms, tooling, and migration watch-outs — FP8 gains a Transformer Engine backend (#9705) with follow-up fixes (#9742); the ROCm base image moves to 7.2 and drops the PyTorch reinstall step (#10223); NPUs get Qwen3.5 Partial-RoPE / hybrid-attention support (#10421); and Trackio is integrated for experiment tracking (#10165). Two upgrade notes: the docs now require Python >=3.11 (#10259), and the lfm template was renamed to lfm2 (#9731), so existing configs referencing the old name must be updated.

No breaking changes were explicitly flagged in this release.

Added primary support for Qwen3.5/Qwen3.6/Gemma4 models and compatibility with Transformers v5.
