LlamaFactory v0.8.0

Highlights

  • Distributed training in LlamaBoard — The Web UI now supports single-node distributed training, resuming from saved checkpoints/configurations—including full- and freeze-tuning checkpoints—and throughput monitoring (#4053, #4066). Developers can manage and diagnose multi-GPU jobs without switching to the CLI.

  • More alignment objectives — KTO (#3785) supports optimization from binary desirable/undesirable feedback without paired preference examples, while SimPO adds a reference-free preference objective. Teams can evaluate both as alternatives to DPO/PPO within the existing training pipeline.

  • Multimodal inference — API mode now accepts image inputs, making newly supported vision-language models such as PaliGemma usable in serving. CLI inference also gains system-message control (#3812), while fixes to multimodal RLHF and LoRA targeting (#3835) reduce fine-tuning failures.

  • Dataset interoperability and packing — Preference datasets now accept ShareGPT format (#3799), dataset_info.json supports num_samples (#3829), and SFT offers greedy-knapsack packing (#4009). Use num_samples for controlled subset runs and validate packed sequence lengths and loss masking before enabling packing. Large files were also removed from the repository, so check workflows that referenced bundled copies.

  • Serving and initialization controls — Pass max_lora_rank through to vLLM (#3794) so higher-rank adapters are not constrained by backend defaults. The new train_from_scratch argument enables random initialization instead of loading pretrained weights; reserve it for pretraining-style runs because it fundamentally changes training’s starting point.

  • Breaking changes — None announced.
