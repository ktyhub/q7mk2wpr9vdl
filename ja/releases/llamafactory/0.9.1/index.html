LlamaFactory v0.9.1

Highlights

  • Model coverage — Adds training/inference support for Qwen2.5 and Qwen2.5-Coder families, Llama-3.2, OpenCoder, Index, EXAONE-3.0-Instruct, and Pixtral 12B. Upgrade if you need these models without maintaining custom integrations.
  • Multimodal capabilities — Adds Llama-3.2-Vision, LLaVA-NeXT, LLaVA-NeXT-Video, Video-LLaVA, Pixtral, and multi-image inference, plus Qwen2-VL Liger-Kernel support and fixes for Qwen2-VL saving/inference on vLLM. Especially relevant for image/video and vLLM users; less compelling for text-only workloads.
  • Training correctness and observability — Fixes abnormal loss values with transformers 4.46, DPO metrics, Qwen2-VL processor saving, function-call dataset processing, and chat-engine behavior. New effective-token calculation for SFT and DPO improves dataset sizing and training-budget estimates.
  • Dependencies and migration — No explicit breaking changes or required migration steps are listed. To enable the upstream gradient accumulation fix, use transformers>=4.46.0,<=4.46.1; dependency and container updates also touch datasets, tyro, ROCm Docker, and vLLM 0.6.3, so validate pinned environments before upgrading.
  • Security and upgrade verdict — Includes a fix for CVE-2024-52803 (aa6a174d6822340022433c5ba38182b4932adecb), a strong reason to patch even without using new models. Upgrade promptly if affected or using the newly supported/fixed workflows; otherwise this can wait, provided the security advisory does not apply to your deployment.
