レア試薬-6.10.1

6.10.1 (2026-11-20)

これは、npm に公開される最初の 6.10 リリースです。これには、以下の 6.10.0 からの変更、移行メモ、および貢献者のクレジットに加えて、パッチ修正が含まれています。

バグ修正

  • kuna: シリアル ジョブ数に 1 つの定数を使用します (#12735) (3e3faf2)

6.10.0 (2026-11-20)

ハイライト

  • 3 つのオフライン CLI および MCP ツールを使用して、UEFI ファームウェア ボリューム、ファイル、AMI NVRAM を検査および抽出します。 #12342。ありがとう@bartman081523。
  • Android ブート イメージと OTA ペイロード、NES 2.0 コンテナー、Maven、Gradle、および NuGet パッケージのメタデータを検査します。 a88c0a5 #9487 #11378 #10674 05be423 #10353 43b9fa8 #10351 #8144。 @Davmunrey、@gensokyo-dev、@jayykernel、@mvanhorn に感謝します。
  • 証拠リビジョン 2 では、ファイル、プロセス、デバッガー、およびブラウザーの観察結果に明示的な主体の身元が示されています。以下の移行の詳細を参照してください。
  • 検証済みの Ghidra 12.2 レーンは、認識された DOS COM ファイルを開き、より多くの RISC-V、MIPS32、および PowerPC64 ELF ターゲットをサポートします。 #4811 #4487 #2362 #2338 #12517 #12085。 @abhay-2108、@AurelioB、@Davmunrey、@kaoru0822-北宇治、@Rinkia に感謝します。

変更点

  • JavaScript セマンティック インデックス作成では、ネストされた評価コンテキストに固定オブジェクト形状を使用して、割り当てのオーバーヘッドを削減します。 #9007。ありがとう@mshzy。
  • ELF の動的依存関係と必要なシンボル バージョンを検査し、個別のデバッグ ファイル リンケージを解決し、DWARF コンパイル ユニットをオフラインで検査し、FDO パッケージ化と dlopen ノートをデコードします。 e9c72db #7868 54e3918 #9560 637e4cb #8523 #7237 #7235。 @AniketR10、@gensokyo-dev、@mvanhorn に感謝します。
  • WebAssembly からカーゴ監査可能な依存関係を読み取り、Go および Rust 依存関係の証拠を CycloneDX としてエクスポートします。 #5069 237b1ea #8445。 @gensokyo-dev、@kaoru0822-北宇治、@mvanhorn、@yu0809 に感謝します。
  • CPython 3.14 および 3.15 バイトコードをデコードし、Kuna 1.1000 を使用します。 1d08253 #10518 #12107。 @abhisheksharma001、@gensokyo-dev、@N0zoM1z0 に感謝します。
  • 管理対象メンバーの検査では、unresolved_definitions が保持され、未解決の定義座標が要約されます。ネイティブ検査は、プロトタイプ命令の競合を明らかにし、RISC-V イニシャライザ ポインタを解決し、シグネチャがカバーする Mach-O スライスを特定します。 #12462 #8161 #1244 #12109 #11620。 @akshad-exe、@N0zoM1z0、@ShuaixinHuang に感謝します。
  • GDB と Rizin は、停止したセッションがコマンドを拒否する理由と、デバッガーの停止または終了が完了できなかった理由を説明します。 #11652 #11517 #11185。
  • セットアップは、fx、Junie、Goose、および Kilo の登録を管理し、明示的な MCP カタログ プロファイルの選択をサポートし、共有 enable: false に手動競合としてフラグを立てます。コンパクト MCP 入力スキーマは、ポータブルなアドバタイズド方言を使用します。 #10709 #9354 #11019 #10632。 @kaoru0822-北宇治さん、ありがとうございます。
  • リーダーエラー名は、整合性チェックの失敗と制限の強制です。ブリッジ拒否により、要求が送信されたかどうかが識別され、回復により、関連する制御またはサイズ超過の MCP 結果の次の操作が指定されます。 #11052 #11056 #11021 #11119 #11125 #11129 #11505 #11634 #11623 #11133 #11172 #11015 #11777。

  • Android マッピング インスペクションは、マッピング メンバーなしで残留署名を報告します。ブート リーダーと OTA リーダーは、容量チェックの前にブート ヘッダー、ベンダー RAM ディスク テーブル、OTA マニフェストと署名のエクステントを検証します。 MIPS 検査により、サポートされていない Android 再配置宣言が特定されます。調和検査は、正確なアーカイブ ルート パスでマニフェストと一致します。 Deno ロックファイル検査は、デコード不可能な行と一緒に有効な指定子を保持します。 #12494 #12396 #12395 #12431 #12397 #12700 #12667。

  • GPU 検査は、不正なコンテナを invalid_format として報告し、検出中にスタンドアロン PTX エンコーディングを検証します。 Core-note の読み取りは記録されたソース範囲を尊重し、PyInstaller と Swift リーダーは容量の上限を適用する前にエントリのフレーミングと vtable の境界をチェックします。 #10644 #12707 #12634 #12622 #12627。

⚠ 重大な変更

  • 証拠記録と手作りのバンドルには evidence_format: 2 が必要です。 6.10 を使用して、古い観察、バンドル、スナップショットを再作成します。古い観測値を再エクスポートしても、その識別情報は更新されません。 subject.digest、subject.format、および subject.architecture の代わりに subject.identity を読み取ります (ファイル ID は sha256 を使用します)。すべてのレコードには件名があり、必要に応じて明示的な未知の ID を使用します。アーティファクトの選択を含むアイデンティティは、証拠 ID に参加します。 compare_artifacts を使用する前に、6.7-era アーティファクト サマリーを再作成します。 #11416 #10861。
  • スナップショットは target: {kind, identity} およびヌル以外の execution.subject: {identity, name, local_path} を使用します。バインディング エラーでは、同じターゲット シェイプが使用されます。 Universal Mach-O Evidence ID には、選択したスライスが含まれます。ライブ ページ ツールとそのビューは、資格情報が削除された {kind: "url", url, origin} ID、不透明な URL の null 起点、null のサブジェクト名とローカル パスを使用します。非公開または読み取り不可能な URL は不明な ID を保持します。影響を受けた証拠とスナップショットを再作成します。 #11551 PR 11559。
  • プロセス キャプチャには manifest.root_process が必要です。サブジェクト ID は、観察された場合は {kind: "process", pid, start_time, executable_sha256}、開始 ID を読み取れなかった場合は {kind: "unknown", reason: "not-observed"}、PID 正規化が有効な場合は {kind: "unknown", reason: "withheld-by-caller"} です。静止決済で cleanup_outcome: "cleaned" を受け入れます。保存されたプロセス証拠を再作成します。既存の省略セマンティクスは引き続き適用されます。raw_data が data と等しい場合は省略され、residual_unknowns が存在しない場合は省略されます。 #11568 #10481 #8032 #10956。 @gensokyo-dev、@N0zoM1z0、@Rinkia、@wunianze666-netizen に感謝します。 ・RizinコマンドEvidenceとGDB起動およびコンソールEvidenceは{kind: "session", session_kind, id, target}を使用します。 REA が観察できる場合、セッション ターゲットは初期起動ファイルを識別します。 GDB はオプションの実行可能ファイルを受け入れます。これがない場合、またはファイル ID が確認できない場合、ターゲットは not-observed という理由で不明です。バインディングは起動ファイルのみを記述します。現在の劣等者のアイデンティティについては、別の観察が必要です。 ID が変更されるため、デバッガーの証拠を再作成します。 PR 11570 PR 11572 230db70 #11710 #11581。 @gensokyo-dev、@N0zoM1z0 に感謝します。
  • Ghidra および Hopper プロファイルは、ハンドバンプ マーカーを rea_version および sources_sha256 を含む analysis_profile.parameters.producer に置き換えます。 Ghidra は、選択値に bridge_sources_sha256 とバージョン サフィックスを削除します。ホッパーはfunction_dossier_coverageをドロップします。プロファイルと証拠 ID が変更されます。ターゲットを開いて、新しいスナップショットを保存します。 #11320。
  • Ghidra には、12.2 以降でサポートされる 12.x ビルドと、そのビルドの宣言された範囲内の JDK (検証済みの 12.2 ビルドの場合は 25 以降) が必要です。 ComLoader によって受け入れられる DOS COM ファイルの場合は、報告された load_address (現在はリニア 0x100) を読み取ります。 BinaryLoader フォールバックでは引き続き 1000:0100 が使用されます。 #12081 #12086。
  • IDA に接続された登録では、明示的に "protocol": "native" を設定し、オープン GUI データベースのネイティブ プラグイン エンドポイントを使用する必要があります。従来の 1.4 プロキシ登録をそのモード、またはヘッドレス モードの ida-pro-mcp 2.x スーパーバイザに移行します。 procedure_callers は IDA プロファイルから削除され、IDA アセンブリ/指示ツールは may_show_ui 注釈を削除します。 #10846 #11546 #10516。
  • rea <command> --mcp の代わりに rea mcp または rea --mcp を使用します。 rea completions <shell> を使用してシェル フックを再生成し、新しいレンダリング用の Markdown 引数診断スナップショットを更新します。フラグ型の不明な MCP サブコマンドは、選択された出力形式を尊重します。 7d502dd #11724 62014b5 #11742 #10583 #11654。 @gensokyo-dev、@N0zoM1z0 に感謝します。
  • MCP は、full 入力および出力スキーマ プロファイルを拒否します。これらの設定を削除するか、compact を選択してください。設定されていない REA_MCP_OUTPUT_SCHEMA_PROFILE は off を意味します。 tools/list[].outputSchemaを受信するには、compactに設定します。 MCP 制限エラーでは details.limit.cli_flag が省略されます。 CLI は、該当する場合には独自のフラグを提供します。 #10693 #11413。
  • inspect_pcap_capture、start_rizin_debug_session、start_gdb_session (inferior_tty を含む)、load_frida_script、および instrument_with_frida への MCP 呼び出しでは絶対ローカル パスを使用します。 CLI --script-file は引き続き相対パスを受け入れ、解決された絶対 source_path を記録します。 #11508 #11079 #11580 #11506。
  • ネイティブ rea analyze は、フラグに名前を付ける invalid_request を使用した --integrity-policy などの JavaScript のみのオプションを拒否します。これらのオプションは、JavaScript ターゲットにのみ渡します。 inspect-managed-members --detail summary の場合、--evidence-bundle <path> の名前を --evidence_output <path> に変更し、標準出力の .summary および .evidence_bundle を読み取ります。パブリケーションの失敗には共有エラー形状が使用されます。 compare-managed-members からの障害などの複合 CLI 障害は、完成した入力を {argument, observation} を持つ details.argument_observations[] エントリーとして運ぶことができます。 PR 10808 PR 10845 PR 10961。
  • ターゲットが選択された plist が欠落しているか、読み取り不能であるか、正規ではない場合は、入力の問題がある invalid_request の代わりに target_unavailable を details.path および reason でデコードします。現在のアプリバンドルまたはリソースルートの外側にある plist を別のターゲットとして開きます。 #9754 #10798。ありがとう@Anandumv。
