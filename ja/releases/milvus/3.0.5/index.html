#ミルバスv3.0.5

v3.0.5

発売日：2026年10月30日

|ミルバスのバージョン | Python SDK バージョン | Node.js SDK バージョン | Java SDK バージョン | Go SDK バージョン | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 3.0.5 | 3.0.2 | 3.0.6 | 3.0.12 | 3.0.0 |

Milvus v3.0.5 のリリースを発表できることを嬉しく思います。このリリースでは、QueryCoord にリソース グループ対応の負荷ステータスが追加され、いくつかのパスでのメモリ使用量が削減されます。また、コーディネーターの再起動、ローリング アップグレード、一時的な etcd エラーに関する安定性の問題も修正されます。

改善点

  • QueryCoord にリソース グループごとの負荷率とシャード リーダーの準備状況を追加し、各シャード リーダーにそのレプリカのリソース グループをタグ付けしたため、クエリを単一のリソース グループ内でルーティングできるようになりました (#52500、#52711)
  • デコードされた投稿ブロックを直接借用することで、スコアのない Tantivy 用語クエリでのコピーを削減しました (#54469)
  • Knowhere を v3.0.17 にアップグレードし、NULL 許容ベクトル オフセット マッピングを Knowhere API の背後に移動しました (#54473)
  • リクエストごとのエンコード バッファを再利用することで、バッチ化された RESTful クエリと検索応答をエンコードする際のメモリ割り当てが削減されました (#54540)
  • アナライザー フィルターでコンパイルされた正規表現とフィルターごとの検索キャッシュを再利用することにより、テキスト アナライザーのパフォーマンスが向上しました (#54570)
  • コンパクション書き込み増幅を削減するために、オプトインの 2 層ミックス コンパクション プランナー (dataCoord.compaction.twoTierCompaction、デフォルト オフ) を追加しました (#54589)
  • 小さなシールされたセグメントをロードする際のタイムスタンプ インデックスのメモリ使用量を削減 (#54659)
  • 失敗した get 操作の internal_storage_op_count メトリックに、欠落していた status="fail" ラベルを追加しました。ラベルのない古いシリーズは停止し、新しいシリーズはゼロから始まります (#54637)
  • パーティションの命名規則に一致する、最初の文字の後のリソース グループ名のハイフンを許可します (#54679)
  • レコード全体で出力列を再利用することにより、圧縮マージ ソートでのメモリ割り当てを削減しました (#54718)

バグ修正

  • 構造体配列フィールドを含むコレクションが、最初の検索時またはキャッシュの削除後に生の埋め込みリスト ベクトルを強制的にロードし、メモリ使用量とクエリ レイテンシが増加する問題を修正しました (#54167)
  • CMEK 対応コレクションでの更新/挿入により、削除部分 (主キーとタイムスタンプ) が暗号化なしで WAL に書き込まれる問題を修正しました (#54478)
  • ST_DWITHIN フィルターが、RTREE インデックスのあるセグメントでは、インデックスのないセグメントよりも少ない行を返す問題を修正しました。空のジオメトリは ST_DWITHIN と一致しなくなり、PostGIS (#54611) と一致しました
  • 次のフラッシュでコミットされたマニフェストと競合する列レイアウトが使用されたため、コーディネーターの再起動後にストレージ V3 セグメントへの書き込みが停止する可能性がある問題を修正しました (#54652)
  • 他のコレクションと物理チャネルを共有するドロップされたデータベースから暗号化された WAL メッセージを再生中に QueryNode がパニックになる可能性がある問題を修正しました (#54640)
  • フィールドが省略され、バッチに新しい主キーが含まれている場合に、null 許容の構造体配列フィールドを持つコレクションで部分的な更新/挿入が失敗する問題を修正しました (#54619)
  • インデックス状態のクエリ中にパーティションが削除されたときに、インデックス状態が誤って失敗として報告される問題を修正しました (#54670)
  • タスクの実行と同時に同期タスクの統計をシリアル化するときのデータ競合を修正しました (#54610)
  • フィールドに非整数の max_length を指定すると、フィールドの名前が無効なパラメータ エラーではなく、生の解析エラーが返される問題を修正しました (#54694)
  • ローリング アップグレード中に MixCoord を停止するとコア ダンプが発生し、古いポッドが数分間終了状態のままになるパニックを修正しました (#54732)
  • Milvus Backup が FlushAll によって返されたフラッシュ ポジションを複製できない問題を修正しました (#54745)
  • リーダーの変更などの一時的な etcd エラーで MixCoord およびその他のコンポーネントがクラッシュし、スケールダウンが停止する可能性がある問題を修正しました。 etcd が回復するまで再試行し、再監視するようになりました (#54754)
  • クラスターのすべてのクエリ ノードを同時に停止すると、正常な停止タイムアウト (デフォルトでは 30 分) までハングする可能性がある問題を修正しました。 queryNode.standaloneMigrateDataTimeout の名前が queryNode.migrateDataTimeout に変更されましたが、古いキーは引き続き機能します (#54813)
  • メッセージ キューを切り替えた後 (たとえば、Pulsar から Woodpecker に)、クエリ ノードが互換性のない位置から再接続を続け、データの消費を停止する可能性がある問題を修正しました (#54811)
  • iso や interval などのコンテキスト キーワードにちなんで名付けられたフィールドが作成できてもフィルター式では使用できない問題を修正しました。 LIKE、AND、OR、NOT、IN は、コレクションの作成時またはフィールドの追加時に、大文字小文字を問わずフィールド名として拒否されるようになりました (#54770)
  • etcd 書き込みの再試行中に SuspendNode リクエスト中に client が切断されるとコーディネーターがクラッシュする可能性がある問題を修正しました (#54802)

milvus v3.0.5

v3.0.5

Release date: October 30, 2026

| Milvus Version | Python SDK Version | Node.js SDK Version | Java SDK Version | Go SDK Version | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 3.0.5 | 3.0.2 | 3.0.6 | 3.0.12 | 3.0.0 |

We are excited to announce the release of Milvus v3.0.5! This release adds resource-group-aware load status in QueryCoord, reduces memory use in several paths. It also fixes stability issues around coordinator restarts, rolling upgrades and transient etcd errors.

Improvements

  • Added per-resource-group load percentage and shard-leader readiness in QueryCoord, and tagged each shard leader with its replica's resource group, so queries can be routed within a single resource group (#52500, #52711)
  • Reduced copying in unscored Tantivy term queries by borrowing decoded postings blocks directly (#54469)
  • Upgraded Knowhere to v3.0.17 and moved nullable vector offset mapping behind Knowhere APIs (#54473)
  • Reduced memory allocations when encoding batched RESTful query and search responses by reusing per-request encoding buffers (#54540)
  • Improved text analyzer performance by reusing compiled regexes and per-filter search caches in analyzer filters (#54570)
  • Added an opt-in two-tier mix compaction planner (dataCoord.compaction.twoTierCompaction, default off) to reduce compaction write amplification (#54589)
  • Reduced timestamp index memory usage when loading small sealed segments (#54659)
  • Added the missing status="fail" label to the internal_storage_op_count metric for failed get operations; the old unlabeled series stops and the new series starts from zero (#54637)
  • Allowed hyphens in resource group names after the first character, matching the naming rules for partitions (#54679)
  • Reduced memory allocations in compaction merge sort by reusing output columns across records (#54718)

Bug fixes

  • Fixed an issue where collections with struct array fields could force-load raw embedding-list vectors on first search or after cache eviction, increasing memory usage and query latency (#54167)
  • Fixed an issue where upserts on CMEK-enabled collections wrote the delete part (primary keys and timestamps) to the WAL without encryption (#54478)
  • Fixed an issue where ST_DWITHIN filters returned fewer rows on segments with an RTREE index than on unindexed segments; empty geometries no longer match ST_DWITHIN, consistent with PostGIS (#54611)
  • Fixed an issue where writes to Storage V3 segments could stall after a coordinator restart because the next flush used a column layout that conflicted with the committed manifest (#54652)
  • Fixed an issue where QueryNode could panic while replaying encrypted WAL messages from a dropped database that shared a physical channel with other collections (#54640)
  • Fixed an issue where partial upserts failed on collections with nullable struct array fields when the field was omitted and the batch contained new primary keys (#54619)
  • Fixed an issue where index state was incorrectly reported as Failed when a partition was dropped while the index state was being queried (#54670)
  • Fixed a data race when serializing sync task statistics concurrently with task execution (#54610)
  • Fixed an issue where specifying a non-integer max_length for a field returned a raw parsing error instead of an invalid-parameter error naming the field (#54694)
  • Fixed a panic when stopping MixCoord during rolling upgrades that caused a core dump and left the old pod stuck in Terminating for several minutes (#54732)
  • Fixed an issue where Milvus Backup could not replicate the flush positions returned by FlushAll (#54745)
  • Fixed an issue where MixCoord and other components crashed on transient etcd errors such as leader changes, which could stall scale-down; they now retry and re-watch until etcd recovers (#54754)
  • Fixed an issue where stopping all query nodes of a cluster at the same time could hang for up to the graceful stop timeout (30 minutes by default); renamed queryNode.standaloneMigrateDataTimeout to queryNode.migrateDataTimeout, and the old key still works (#54813)
  • Fixed an issue where, after switching the message queue (for example from Pulsar to Woodpecker), query nodes could keep reconnecting from an incompatible position and stop consuming data (#54811)
  • Fixed an issue where fields named after contextual keywords such as iso or interval could be created but not used in filter expressions; LIKE, AND, OR, NOT and IN are now rejected as field names in any casing when creating a collection or adding a field (#54770)
  • Fixed an issue where the coordinator could crash when a client disconnected during a SuspendNode request while an etcd write was being retried (#54802)
