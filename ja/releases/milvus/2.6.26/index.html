#ミルバスv2.6.26

v2.6.26

発売日：2026年10月26日

|ミルバスのバージョン | Python SDK バージョン | Node.js SDK バージョン | Java SDK バージョン | Go SDK バージョン | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

Milvus v2.6.26 のリリースを発表できることを嬉しく思います。このリリースでは、RPC メッセージのデコードが高速化され、大規模な検索およびクエリ リクエストに対するプロキシ メモリの使用量が削減され、null 許容フィルタリングおよび NGRAM フィルタリングでの QueryNode のクラッシュ、コレクションの読み込みおよびインポート ジョブ中のハング、コーディネーターの起動後に遡る可能性のあるタイムスタンプが修正されています。

改善点

  • より高速な protobuf デコーダーにより、検索、クエリ、挿入、および更新/挿入の RPC メッセージのデコードが高速化されました。デフォルトで有効になり、common.enableFastPB (#53994、#54002) 経由で切り替え可能です。
  • Tantivy のアップグレードによってステミング結果が変更されたり、既存のテキスト インデックスと BM25 データの一致が失われることがないよう、Tantivy とは独立してテキスト アナライザー ステマーを固定しました (#54029、#54098)
  • 非同期セグコア操作の完了と高負荷時に呼び出し元が結果を受け取るまでの遅延が短縮されたため、完了した結果がメモリを保持しながらキューに入れられた作業の後ろで待機することがなくなりました (#54128)
  • シャードごとにリクエスト ペイロードをディープ コピーするのではなく、シャード間でリクエスト ペイロードを共有することで、大規模な検索およびクエリ リクエストに対するプロキシ メモリの使用量を削減します。 50 の同時検索 nq=10000 のテストで、ライブ ヒープが 8.7 GB から 5.85 GB に減少しました (#54224)
  • プランのコンパイル中に、OR/AND チェーン内の同じ列の array_contains 条件を array_contains_any/array_contains_all にマージし、数千の条件を持つフィルターのコンパイル オーバーヘッドを削減しました (#54435)
  • クエリごとにインデックスを再スキャンするのではなく、有効性ビットマップをキャッシュすることで、シールされたセグメント内の JSON パス インデックスの null チェック フィルタリングが改善されました (#54422)
  • 増大するインデックスのないシールされたセグメントでのスパース IP および BM25 検索用の暫定インデックス アルゴリズム (TAAT_NAIVE、DAAT_WAND、または DAAT_MAXSCORE) を選択するための queryNode.segcore.interimIndex.sparseIPIndexAlgo および sparseBM25IndexAlgo 設定を追加しました (#54443)
  • StorageV2 セグメントを複数のバッチでロードする際に繰り返される Parquet フッターの読み取りと解析を削減し、Azure ソブリン クラウド上のエンドポイント URL 形式に対する milvus-storage 修正を適用しました (#54488)

バグ修正

  • 厳密なグループ サイズを使用したグループ化検索では、一致するエンティティが十分に存在する場合でも、group_size 未満の結果を持つグループが返される可能性がある問題を修正しました。この動作を調整するために queryNode.groupBy.strictGroupStrategy と関連設定を追加しました (#53451)
  • 挿入または更新/挿入の実行中に null 許容フィールドでフィルタリングすると、QueryNode がクラッシュしたり、成長するセグメントで null 値が誤って読み取られる可能性がある問題を修正しました (#53870)
  • NULL 許容整数フィールドで AND/OR と範囲外の整数比較を組み合わせるフィルターが QueryNode をクラッシュさせたり、誤った結果を返したりする可能性がある問題を修正しました (#53897)
  • パターンに NUL 文字が含まれている場合、NGRAM インデックスを持つフィールドに対する LIKE クエリが QueryNode をクラッシュさせるか、一致しない行を返す可能性がある問題を修正しました (#53710)
  • コーディネーターの起動中に永続化された TSO ウィンドウの読み取りに失敗すると、新しく割り当てられたタイムスタンプと ID が逆になる可能性がある問題を修正しました (#51795)
  • キャンセルまたはタイムアウトした検索およびクエリのリクエストがプロキシ キューに残ったまま実行され、負荷がかかると他のリクエストが遅延する問題を修正しました (#52938)
  • 大きなパーティション上のデータノードを OOM で強制終了する可能性がある、クラスタリング圧縮のピーク メモリの削減 (#54078)
  • 単一のリクエストで DataNode のインポート メモリ制限を超えるメモリが必要な場合、インポート ジョブが無期限にハングする可能性があり、ドロップされたインポート ジョブが終了せずにメモリを待機し続ける問題を修正しました (#54112)
  • JSON 統計がロードされたときに、整数と浮動小数点リテラルが混在する JSON フィールドのフィルター (例: p == 1 OR p == 2.0) が不完全な結果を返す問題を修正しました (#54157)
  • QueryNode のロードまたは監視 RPC がハングすると、コレクションのロードとバランシングが無期限に停止する可能性がある問題を修正しました。 QueryCoord タスクのタイムアウトが強制されるようになり、チャネル タスクのデフォルトは 2 分、セグメントおよびリーダー タスクのデフォルトは 5 分に引き上げられました (#54218)
  • 同時待機者がロード完了またはキャンセル通知を見逃したため、QueryNode でのセグメントのロードが無期限にハングする可能性がある問題を修正しました (#54455)
  • バランシングやインデックスの更新によってトリガーされるセグメントロードなど、優先度の低いセグメントロードが生のフィールドデータを高い優先度でロードし、リソースの緊急ロードと競合する問題を修正しました (#54336)
  • 出力にベクトル配列または StructArray ベクトル フィールドが含まれている場合、Go SDK で空のページを返すページ分割されたクエリが「FieldData type not match」で失敗する問題を修正しました (#54360)
  • インポート ジョブを削除しても、DataNode で既に実行されているインポート タスクが停止しなかった問題を修正しました (#54433)
  • LoadCollection 後に作成されたパーティションが CDC スタンバイ クラスターにアンロードされたままになるため、コレクションが解放されて再ロードされるまでデータをクエリできなくなる問題を修正しました (#54567)
  • milvus_proxy_report_value メトリクスが成功した更新/挿入を 2 回カウントし、報告された値を誇張する問題を修正しました (#54606)

milvus v2.6.26

v2.6.26

Release date: October 26, 2026

| Milvus Version | Python SDK Version | Node.js SDK Version | Java SDK Version | Go SDK Version | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

We are excited to announce the release of Milvus v2.6.26! This release speeds up RPC message decoding, cuts Proxy memory usage for large search and query requests, and fixes QueryNode crashes in nullable and NGRAM filtering, hangs during collection loading and import jobs, and timestamps that could go backward after coordinator startup.

Improvements

  • Sped up decoding of search, query, insert, and upsert RPC messages with a faster protobuf decoder, enabled by default and switchable via common.enableFastPB (#53994, #54002)
  • Pinned the text analyzer stemmer independently of Tantivy so that Tantivy upgrades do not change stemming results or cause missed matches on existing text indexes and BM25 data (#54029, #54098)
  • Reduced the delay between an async segcore operation completing and its caller receiving the result under heavy load, so completed results no longer wait behind queued work while holding memory (#54128)
  • Reduced Proxy memory usage for large search and query requests by sharing request payloads across shards instead of deep-copying them per shard; live heap dropped from 8.7 GB to 5.85 GB in a test with 50 concurrent nq=10000 searches (#54224)
  • Merged same-column array_contains conditions in OR/AND chains into array_contains_any/array_contains_all during plan compilation, reducing compilation overhead for filters with thousands of conditions (#54435)
  • Improved null-check filtering on JSON path indexes in sealed segments by caching the validity bitmap instead of rescanning the index for every query (#54422)
  • Added the queryNode.segcore.interimIndex.sparseIPIndexAlgo and sparseBM25IndexAlgo settings to choose the interim index algorithm (TAAT_NAIVE, DAAT_WAND, or DAAT_MAXSCORE) for sparse IP and BM25 search on growing and unindexed sealed segments (#54443)
  • Reduced repeated Parquet footer reads and parsing when loading StorageV2 segments in multiple batches, and picked up a milvus-storage fix for the endpoint URL format on Azure sovereign clouds (#54488)

Bug fixes

  • Fixed an issue where grouping search with strict group size could return groups with fewer than group_size results even when enough matching entities existed; added queryNode.groupBy.strictGroupStrategy and related settings to tune this behavior (#53451)
  • Fixed an issue where filtering on a nullable field while inserts or upserts were running could crash the QueryNode or misread null values in growing segments (#53870)
  • Fixed an issue where filters that combine AND/OR with out-of-range integer comparisons on nullable integer fields could crash the QueryNode or return incorrect results (#53897)
  • Fixed an issue where LIKE queries on fields with an NGRAM index could crash the QueryNode or return non-matching rows when the pattern contained NUL characters (#53710)
  • Fixed an issue where a failed read of the persisted TSO window during coordinator startup could cause newly allocated timestamps and IDs to go backward (#51795)
  • Fixed an issue where canceled or timed-out search and query requests stayed in the Proxy queue and were still executed, delaying other requests under load (#52938)
  • Reduced peak memory of clustering compaction, which could OOM-kill DataNodes on large partitions (#54078)
  • Fixed an issue where import jobs could hang indefinitely when a single request needed more memory than the DataNode import memory limit, and where dropped import jobs kept waiting for memory instead of exiting (#54112)
  • Fixed an issue where filters on JSON fields that mix integer and floating-point literals (e.g. p == 1 OR p == 2.0) returned incomplete results when JSON stats were loaded (#54157)
  • Fixed an issue where collection loading and balancing could stall indefinitely when a QueryNode load or watch RPC hung; QueryCoord task timeouts are now enforced, with defaults raised to 2 minutes for channel tasks and 5 minutes for segment and leader tasks (#54218)
  • Fixed an issue where segment loading on QueryNode could hang indefinitely because concurrent waiters missed load-completion or cancellation notifications (#54455)
  • Fixed an issue where low-priority segment loads, such as those triggered by balancing or index updates, loaded raw field data at high priority and competed with urgent loads for resources (#54336)
  • Fixed an issue where paginated queries returning an empty page failed with "FieldData type not matched" in the Go SDK when the output included vector array or StructArray vector fields (#54360)
  • Fixed an issue where dropping an import job did not stop its import tasks already running on DataNodes (#54433)
  • Fixed an issue where partitions created after LoadCollection stayed unloaded on CDC standby clusters, so their data could not be queried until the collection was released and reloaded (#54567)
  • Fixed an issue where the milvus_proxy_report_value metric counted successful upserts twice, overstating the reported value (#54606)
