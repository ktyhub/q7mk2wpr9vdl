milvus v3.0.4

#ミルバスv3.0.4

v3.0.4

発売日：2026年10月26日

|ミルバスのバージョン | Python SDK バージョン | Node.js SDK バージョン | Java SDK バージョン | Go SDK バージョン | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 3.0.4 | 3.0.2 | 3.0.6 | 3.0.10 | 3.0.0 |

Milvus v3.0.4 のリリースを発表できることを嬉しく思います。このリリースでは、一括インポート、圧縮、フィルターおよびグループ化された検索が高速化され、Storage V3 の列グループの遅延読み込みが追加され、インポート、コレクションの読み込み、および部分更新書き込みでのハングが修正され、アクセス制御の問題や CVE もいくつか発生します。

改善点

  • 入力チャンクを並列で読み取り、バイト範囲を熱心にプリフェッチすることにより、ソート圧縮の読み取りスループットが向上しました (#53437)
  • Parquet、Lance、および Vortex ファイルによってサポートされる外部コレクションに事前計算されたスパース ベクトルのサポートを追加しました (#53894)
  • プロキシ DML タスクを専用パッケージにリファクタリングして、タスクの責任を分離しました (#54064)
  • シールされたセグメントの検索のすべての出力フィールドが、検索自体と同じセグメント スナップショットから入力されるようにしました (#54074)
  • 最初のアクセスまで Storage V3 列グループのロードを延期する queryNode.segcore.tieredStorage.lazyColumnGroupEnabled オプション (デフォルトで無効) を追加し、セグメントのロード時間とメモリ使用量を削減しました (#54169)
  • IP メトリクスと BM25 メトリクスに個別にスパース AutoIndex ビルド パラメータを設定するための autoIndex.params.sparse.ip.build と autoIndex.params.sparse.bm25.build を追加し、autoIndex.params.sparse.build (#54212) にフォールバックしました。
  • CheckHealth 中に DataCoord セルフメトリクスを収集しなくなったことにより、大きなセグメントメタデータを持つクラスターでのヘルスチェックのレイテンシーが減少しました (#54214)
  • ジョブ ID でインポート タスクのインデックスを作成することにより、多くのインポート ジョブを含むクラスターの DataCoord インポート スケジューリングのパフォーマンスが向上しました (#54202)
  • 廃止された JSON 統計プレフィックスをセグメントごとに 1 回ではなく GC サイクルごとに 1 回スキャンすることで、ガベージ コレクション中のオブジェクト ストレージ リストのリクエストを削減しました (#54207)
  • 既存の配列チャンク オフセットから長さを読み取ることで、シールされたセグメントでの ARRAY_LENGTH フィルターのパフォーマンスが向上し、顧客のフィルター ワークロードで QPS が 102 から 270 に上昇しました (#54321)
  • grpc-go を v1.84.0 にアップグレードしました。これにより、プロキシはデコード直後に生のリクエスト バッファを解放し、実行中の大規模検索ごとにヒープをリクエスト サイズ全体 (nq=10000, 1536-dim 検索の場合は 61.5 MB) まで節約します (#54271)
  • StreamingNode での部分的な更新に対する比較およびスワップ チェックをオフにする非表示の streaming.partialUpdate.enableCAS オプションを追加しました (デフォルトで有効)。これにより、同時の古い更新に対する保護と引き換えに書き込みオーバーヘッドが低くなります (#54249)
  • プロキシが成功するすべてのクエリにログを記録するという偽の「ステータスが nil」という警告を削除しました (#54247)
  • RESTful V2 挿入および更新/挿入リクエストをデコードする際のメモリ割り当てを削減し、変換失敗時の完全なリクエスト ペイロードのログ記録を停止しました (#54403)
  • 事前インポート後に正確なファイルごとの ID 範囲を割り当てるように一括インポートを再調整しました。これにより、事前にファイルのサイズを設定することなくインポート リクエストがすぐに返され、インポート書き込みの再試行中のログ ID の枯渇が修正されました (#54416)
  • IP および BM25 スパース ベクトル フィールドの暫定インデックス アルゴリズムをオーバーライドする起動設定オプションを追加しました (#54441)
  • CVE-2026-78667、CVE-2026-97031、および CVE-2026-78669 (#54451) に対処するために、Go to 1.26.9 および golang.org/x/net を v0.60.0 にアップグレードしました。
  • 生の JSON を解析する代わりに、JSON シュレッディング統計から VARCHAR、BOOL、および整数グループ キーを読み取ることで、シールされたセグメント内の型付き JSON パスでのグループバイ検索が改善されました (#54456)
  • OpenTelemetry を 1.45.0 に、cilium/ebpf を 0.22.0 にアップグレードし、CVE-2026-81870 および CVE-2026-10722 (#54461) に対処するためにランタイム イメージのcurl、tar、zlib、およびglibcを更新しました。
  • キャッシュミス時にのみ用語を変換することで、インデックス付き ARRAY_CONTAINS フィルターの冗長なクエリ用語変換を削減しました (#54459、#54465)
  • 各バッチが完了するのを待つのではなく、継続的にインポートタスクをスケジュールすることで、インポートのスループットが向上しました (#54471)
  • CDC レプリケーション設定のプライマリ クラスターとセカンダリ クラスターの両方でクラスター ローカルの Flush および FlushAll のサポートを追加しました (#54502)
  • 検索のファンアウト作業 (PK 充填、距離調整、出力フィールドの実体化) を専用のスレッド プールに分離し、検索がフィールドとインデックスの読み込みの後にキューに入れられないようになりました (#54524)

バグ修正

  • 起動中の一時的な etcd 読み取りエラーにより、タイムスタンプ アロケータが以前に割り当てられたタイムスタンプよりも古いタイムスタンプを発行する可能性がある問題を修正しました (#51762)
  • インポート ジョブが永久にハングし、pchannel のチェックポイントをブロックする可能性がある問題を修正しました。以前は手動による etcd 修復と StreamingNode の再起動が必要でした (#54111)
  • Timestamptz または Geometry フィールドを含むコレクションに行を挿入するときの Go SDK パニックを修正しました (#54131)
  • 部分更新の実行時にシャードでの高い書き込みレイテンシーと書き込みバックログが修正され、各部分更新コミットが同じ vchannel 上の他のすべての書き込みをブロックしました。部分的な更新では、同じ主キーにアクセスする書き込みのみがブロックされるようになりました (#54215)
  • セグメントのロードまたはチャネル監視リクエストがスタックしたときに、コレクションのロードが無期限にハングする可能性がある問題を修正しました。 QueryCoord は、タスクステップごとに queryCoord.channelTaskTimeout (デフォルト 2 分) および queryCoord.segmentTaskTimeout (デフォルト 5 分) を適用するようになりました。そのため、個々のセグメントのロードに時間がかかる場合は、セグメントのタイムアウトを増やします (#54217)
  • Storage V3 での L0 圧縮マニフェストのコミットが遅いと、DataCoord でのフラッシュおよびセグメント情報リクエストが停止する可能性がある問題を修正しました (#54186)
  • AWS ランタイムの個別のコピーをバンドルするネイティブ ライブラリによって引き起こされる、AWS S3 ストレージへのアクセス時の潜在的なクラッシュを修正しました (#54192)
  • 優先度の低いセグメントのロード (スケールダウンまたはバランシング中など) が生のフィールド データを高い優先度でロードし、他のロードと競合して検索レイテンシが増加する問題を修正しました (#54335)
  • StorageV3 のパックされたスカラー インデックス (STL_SORT、MARISA) のロードで予算よりも多くのメモリが使用される可能性があり、ロードの失敗によって処理中のダウンロードがすぐに停止されない問題を修正しました (#54359)
  • ORDER BY および LIMIT を使用した GROUP BY 集計クエリが、結果がセグメントおよびノード間でマージされた場合に不完全または不正な集計値を返す可能性がある問題を修正しました (#54393)
  • 認証が有効になっていると、非 root ユーザーが client テレメトリ管理 API にアクセスできる問題を修正しました。これらの API には root ユーザーが必要になりました (#54408)
  • ユーザーが別のデータベースまたは履歴コレクション名を指定することによって、インポート権限のないコレクションのインポート ジョブの詳細を表示できる問題を修正しました (#54449)
  • QueryNode セグメントのロードを待機しているリクエストが無期限にハングし、ロードの完了とキャンセルの両方が失われる可能性がある問題を修正しました (#54452)
  • バケットが切り捨てられた場合、検索集約 top_hits が L2 およびハミング メトリクスに対して最も類似した結果ではなく最も類似性の低い結果を返す可能性がある問題を修正しました (#54458)
  • 出力フィールドが複数のシャードから返された場合、group-by を使用したハイブリッド検索が失敗する可能性がある問題を修正しました (#54457)
  • 新しい主キーが存在する場合、null 許容またはデフォルト値の TIMESTAMPTZ フィールドを省略した部分的な更新/挿入が失敗するか、有効なリクエストを拒否する可能性がある問題を修正しました (#54460、#54464)
  • ワードレベルの MinHash 署名を計算する際のメモリ リークを修正しました (#54463)
  • RESTful v2 検索が、正でない groupSize や strictGroupSize などの明示的なグループバイ パラメーターをサイレントに無視する問題を修正しました。無効な値はデフォルトに戻るのではなく拒否されるようになりました (#54466)
  • 前の書き込みがすでに適用されている後でも、強力な整合性クエリが次の定期的なタイムティックを待機する可能性がある問題を修正しました (#54501)
  • セグメントが成長したままである間に挿入されたデータが永続化された後、TEXT フィールドを含むアイドル コレクションのチャネル チェックポイントの進行が停止する問題を修正しました (#54538)
  • ある Milvus バージョンで書き込まれたスナップショット マニフェストが別のバージョンでデコードできない可能性がある問題を修正しました。スナップショット マニフェストは自己記述型 Avro ファイルになりました (#54549)
  • レプリケーションが設定されていないクラスター上のレプリケート設定のクエリがリクエストがタイムアウトするまでブロックされ、セカンダリがすべてのメッセージを拒否するとレプリケート ストリームがバックオフされる問題を修正しました (#54555)
  • CDC セカンダリ クラスター上の LoadCollection 後に作成されたパーティションがロードされず、セカンダリ上のクエリでデータが失われる問題を修正しました (#54561)
  • アップサートが成功すると、プロキシ メトリクスで報告された値が 2 回カウントされ、報告された量が誇張される問題を修正しました (#54605)

milvus v3.0.4

v3.0.4

Release date: October 26, 2026

| Milvus Version | Python SDK Version | Node.js SDK Version | Java SDK Version | Go SDK Version | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 3.0.4 | 3.0.2 | 3.0.6 | 3.0.10 | 3.0.0 |

We are excited to announce the release of Milvus v3.0.4! This release speeds up bulk import, compaction, and filtered and grouped search, adds lazy column-group loading for Storage V3, and fixes hangs in import, collection loading, and partial-update writes, along with several access control issues and CVEs.

Improvements

  • Improved sort compaction read throughput by reading input chunks in parallel and prefetching byte ranges eagerly (#53437)
  • Added support for precomputed sparse vectors in external collections backed by Parquet, Lance, and Vortex files (#53894)
  • Refactored Proxy DML tasks into a dedicated package to separate task responsibilities (#54064)
  • Ensured all output fields of a search on sealed segments are filled from the same segment snapshot as the search itself (#54074)
  • Added the queryNode.segcore.tieredStorage.lazyColumnGroupEnabled option (disabled by default) to defer loading Storage V3 column groups until first access, reducing segment load time and memory usage (#54169)
  • Added autoIndex.params.sparse.ip.build and autoIndex.params.sparse.bm25.build to configure sparse AutoIndex build parameters separately for IP and BM25 metrics, falling back to autoIndex.params.sparse.build (#54212)
  • Reduced health check latency on clusters with large segment metadata by no longer collecting DataCoord self metrics during CheckHealth (#54214)
  • Improved DataCoord import scheduling performance for clusters with many import jobs by indexing import tasks by job ID (#54202)
  • Reduced object storage list requests during garbage collection by scanning obsolete JSON stats prefixes once per GC cycle instead of once per segment (#54207)
  • Improved ARRAY_LENGTH filter performance on sealed segments by reading lengths from existing array chunk offsets, raising QPS from 102 to 270 on a customer filter workload (#54321)
  • Upgraded grpc-go to v1.84.0 so Proxy releases raw request buffers right after decoding, saving up to the full request size (61.5 MB for an nq=10000, 1536-dim search) of heap per in-flight large search (#54271)
  • Added a hidden streaming.partialUpdate.enableCAS option (enabled by default) to turn off compare-and-swap checks for partial updates on StreamingNode, trading protection against concurrent stale updates for lower write overhead (#54249)
  • Removed a spurious "status is nil" warning that Proxy logged on every successful query (#54247)
  • Reduced memory allocations when decoding RESTful V2 insert and upsert requests, and stopped logging full request payloads on conversion failures (#54403)
  • Reworked bulk import to assign exact per-file ID ranges after preimport, so import requests return immediately without sizing files up front, and fixed log ID exhaustion during import write retries (#54416)
  • Added startup configuration options to override the interim index algorithm for IP and BM25 sparse vector fields (#54441)
  • Upgraded Go to 1.26.9 and golang.org/x/net to v0.60.0 to address CVE-2026-78667, CVE-2026-97031, and CVE-2026-78669 (#54451)
  • Improved search group-by on typed JSON paths in sealed segments by reading VARCHAR, BOOL, and integer group keys from JSON shredding stats instead of parsing raw JSON (#54456)
  • Upgraded OpenTelemetry to 1.45.0 and cilium/ebpf to 0.22.0, and updated curl, tar, zlib, and glibc in runtime images to address CVE-2026-81870 and CVE-2026-10722 (#54461)
  • Reduced redundant query-term conversion for indexed ARRAY_CONTAINS filters by converting terms only on cache miss (#54459, #54465)
  • Improved import throughput by scheduling import tasks continuously instead of waiting for each batch to finish (#54471)
  • Added support for cluster-local Flush and FlushAll on both primary and secondary clusters in CDC replication setups (#54502)
  • Isolated search fan-out work (PK filling, distance refinement, and output field materialization) into a dedicated thread pool so that searches no longer queue behind field and index loading (#54524)

Bug fixes

  • Fixed an issue where a transient etcd read failure during startup could make the timestamp allocator issue timestamps older than previously allocated ones (#51762)
  • Fixed an issue where import jobs could hang forever and block a pchannel's checkpoint, which previously required manual etcd repair and a StreamingNode restart (#54111)
  • Fixed a Go SDK panic when inserting rows into collections with Timestamptz or Geometry fields (#54131)
  • Fixed high write latency and write backlogs on a shard when partial updates were running, where each partial-update commit blocked all other writes on the same vchannel; partial updates now only block writes that touch the same primary keys (#54215)
  • Fixed an issue where collection loading could hang indefinitely when a segment load or channel watch request got stuck; QueryCoord now enforces queryCoord.channelTaskTimeout (default 2 min) and queryCoord.segmentTaskTimeout (default 5 min) per task step, so increase the segment timeout if individual segment loads take longer (#54217)
  • Fixed an issue where slow L0 compaction manifest commits on Storage V3 could stall flush and segment info requests in DataCoord (#54186)
  • Fixed a potential crash when accessing AWS S3 storage, caused by native libraries bundling separate copies of the AWS runtime (#54192)
  • Fixed an issue where low-priority segment loads (for example, during scale-down or balancing) loaded raw field data at high priority, competing with other loads and increasing search latency (#54335)
  • Fixed an issue where loading StorageV3 packed scalar indexes (STL_SORT, MARISA) could use more memory than budgeted, and where load failures did not stop in-flight downloads promptly (#54359)
  • Fixed an issue where GROUP BY aggregation queries with ORDER BY and LIMIT could return incomplete or incorrect aggregate values when results were merged across segments and nodes (#54393)
  • Fixed an issue where, with authorization enabled, non-root users could access client telemetry administration APIs; these APIs now require the root user (#54408)
  • Fixed an issue where users could view import job details for collections they lacked Import permission on by specifying a different database or a historical collection name (#54449)
  • Fixed an issue where requests waiting on a QueryNode segment load could hang indefinitely, missing both load completion and cancellation (#54452)
  • Fixed an issue where search aggregation top_hits could return the least similar results instead of the most similar ones for L2 and Hamming metrics when buckets were truncated (#54458)
  • Fixed an issue where hybrid search with group-by could fail when output fields were returned from multiple shards (#54457)
  • Fixed an issue where partial upserts that omitted a nullable or default-valued TIMESTAMPTZ field could fail or reject valid requests when new primary keys were present (#54460, #54464)
  • Fixed a memory leak when computing word-level MinHash signatures (#54463)
  • Fixed an issue where RESTful v2 search silently ignored explicit group-by parameters such as a non-positive groupSize or strictGroupSize; invalid values are now rejected instead of falling back to defaults (#54466)
  • Fixed an issue where Strong-consistency queries could wait for the next periodic time tick even after preceding writes had already been applied (#54501)
  • Fixed an issue where the channel checkpoint stopped advancing for idle collections with TEXT fields after inserted data had been persisted while the segment remained Growing (#54538)
  • Fixed an issue where snapshot manifests written by one Milvus version could fail to decode in another version; snapshot manifests are now self-describing Avro files (#54549)
  • Fixed an issue where querying the replicate configuration on a cluster without replication configured blocked until the request timed out, and made replicate streams back off when the secondary rejects every message (#54555)
  • Fixed an issue where partitions created after LoadCollection on a CDC secondary cluster were not loaded, causing queries on the secondary to miss their data (#54561)
  • Fixed an issue where successful upserts counted the reported value twice in proxy metrics, overstating the reported amount (#54605)
