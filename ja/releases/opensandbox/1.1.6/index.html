OpenSandbox docker/出口/v1.1.6

新機能

✨ 特徴

  • DNS 解決および nftables 更新の障害カウンター 新しい egress.dns.query.failed_total{reason} (no_upstreams / upstream_error / empty_response / rcode) および egress.nftables.updates.failed_total{operation} カウンターにより、以前はログにのみ存在していた障害が観察可能になります。これには、失敗した動的許可セット更新によりポリシーが許可するトラフィックがドロップされるサイレント フェールクローズのケースも含まれます。 (#1410)
  • mitmdump 出力が出力ログ シンクに到達するようになりました。 ctx.log 経由で出力された mitmproxy および資格情報プロキシ ログは出力ザップ ロガーに 1 行ずつパイプされるため、OPENSANDBOX_LOG_OUTPUT が設定されている場合はログ ファイルとローテーションに到達します。環境変数を設定しないと、動作は以前と同様に標準出力に残ります。 (#1468)

🐛 バグ修正

  • mitmproxy 11.0.2 は HTTP/2 スループットを復元します。 アップストリームの HTTP/2 フロー制御修正 (mitmproxy/mitmproxy#7317) により、大規模な HTTP/2 応答の深刻なスロットリングが削除されます。216 MiB の応答は、mitmproxy 10.4.2 の 0.61 MiB/s から 24.43 MiB/s まで、ダイレクト パスのスループットに近づきました。 (#1396)
  • DNS 由来の NFT エントリは、長時間接続でも期限切れになりません。 dns+nft モードでは、許可された DNS 応答から学習した IP は、アクティブな TCP 接続が保持している間に更新され、アクティビティ終了後に最後の更新が行われます。以前にドロップされた標準の 6 分間のリースは、永続的な gRPC チャネル シナリオでは約 370 秒後に再接続されます。このシナリオは正常に再接続されるようになりました。 TCP のみ — UDP/QUIC は引き続き DNS 主導の更新に依存します。 (#1399)
  • DNS 遅延ヒストグラム バケットが秒単位と一致するようになりました。 egress.dns.query.duration は SDK のデフォルトのミリ秒ラダーを使用していたため、現実的な遅延はすべて単一のバケットに収まり、分位数は無意味な補間でした。明示的な秒ベースの境界により、使用可能な分布が復元され、回帰テストによって境界が保護されます。 (#1405)
  • ストリーミングされたリクエストボディに対する Credential Vault ヘッダーの挿入が修正されました。 stream_large_bodies では、request フックが起動される前に 1 MiB を超えるボディが転送されるため、認証ヘッダーの到着が遅すぎて、アップロードが 403 invalid api-key で失敗しました。インジェクションは requestheaders フック (アップストリーム接続の前に起動) に移動され、これにより、応答がリクエスト フックよりも前に到着した場合 (例: 413 アップロード中) に失敗した応答のリダクションも修正されます。 (#1466)
  • No-SNI TLS 接続は、切断されるのではなく、透過的な MITM を通過するようになりました。 ClientHello にホスト名がないため、mitmproxy のホスト名検証は宛先 IP にフォールバックし、接続を切断します (hostname mismatch) - 安全でないフラグが設定されている (Credential Vault が拒否する) 場合を除き、IP で接続する ossfs2 などの client の OSS への HTTPS 出力が切断されます。 No-SNI フローはそのまま通過するようになりました。ホスト名ベースの ignore_hosts マッチングと TCP 拒否/許可の強制は引き続き適用されます。 (#1469)

📦 その他

  • mitmproxy SSE 切り捨て再現ツール。 mitmproxy/mitmproxy#8364 の自己完結型複製スクリプトとドキュメント。TLS HTTP/1.1 上の大きな SSE 本文は、本体の直後にアップストリームが閉じるときに切り詰められます。TLS モードが複製され、プレーン/遅延クローズ コントロールが通過します。 (#1462)

OpenSandbox docker/egress/v1.1.6

Highlights

  • HTTP/2 throughput restored — Upgrading to mitmproxy 11.0.2 fixes severe large-response throttling (#1396). A 216 MiB download improved from 0.61 MiB/s to 24.43 MiB/s, effectively restoring near-direct-path performance.
  • Credential Vault works with streamed uploads — Authentication injection now runs at requestheaders, before the upstream connection, fixing 403 invalid api-key failures for bodies over 1 MiB with stream_large_bodies; response redaction is also applied when responses arrive before the request hook, such as mid-upload 413 responses (#1466).
  • Persistent dns+nft connections keep learned IPs alive — Active TCP connections now renew DNS-derived allow-list entries, with one final renewal after disconnect (#1399). This eliminates reconnects after roughly 370 seconds in persistent gRPC workloads; UDP and QUIC still depend on DNS-driven refresh.
  • Transparent MITM supports clients without SNI — No-SNI TLS traffic, notably IP-addressed HTTPS traffic from clients such as ossfs2, now passes through without hostname mismatch failures or requiring the insecure flag rejected by Credential Vault (#1469). Hostname-based ignore_hosts and TCP allow/deny enforcement remain in effect.
  • More actionable failure and latency telemetry — New DNS-reason and nftables-operation failure counters expose failures previously visible only in logs, including fail-closed allow-set updates that silently drop permitted traffic (#1410). DNS duration histogram buckets now match seconds, producing usable quantiles instead of all realistic latencies landing in one bucket (#1405).
  • Unified egress logging and remaining SSE caveat — When OPENSANDBOX_LOG_OUTPUT is set, mitmproxy and credential-proxy ctx.log output now reaches the egress log file and rotation; without it, output remains on stdout (#1468). Note that large SSE responses over TLS HTTP/1.1 can still truncate when upstream closes immediately; reproduction tooling is included (#1462), but no fix ships in this release.

No breaking changes identified in this release.

What's New

✨ Features

  • Failure counters for DNS resolution and nftables updates. New egress.dns.query.failed_total{reason} (no_upstreams / upstream_error / empty_response / rcode) and egress.nftables.updates.failed_total{operation} counters make failures that previously existed only in logs observable — including the silent fail-closed case where a failed dynamic allow-set update drops traffic the policy permits. (#1410)

  • mitmdump output now lands in the egress log sink. mitmproxy and credential-proxy logs printed via ctx.log are piped line-by-line into the egress zap logger, so they reach the log file and rotation when OPENSANDBOX_LOG_OUTPUT is set; with the env var unset, behavior stays on stdout as before. (#1468)

🐛 Bug Fixes

  • mitmproxy 11.0.2 restores HTTP/2 throughput. The upstream HTTP/2 flow-control fix (mitmproxy/mitmproxy#7317) removes severe throttling of large HTTP/2 responses: a 216 MiB response went from 0.61 MiB/s on mitmproxy 10.4.2 to 24.43 MiB/s — near the direct-path throughput. (#1396)

  • DNS-derived nft entries no longer expire under long-lived connections. In dns+nft mode, IPs learned from allowed DNS responses are renewed while an active TCP connection holds them, with one final renewal after activity ends. The stock six-minute lease previously dropped reconnects after ~370s in a persistent gRPC-channel scenario; that scenario now reconnects cleanly. TCP only — UDP/QUIC still rely on DNS-driven refresh. (#1399)

  • DNS latency histogram buckets now match its seconds unit. egress.dns.query.duration was using the SDK-default millisecond ladder, so every realistic latency landed in a single bucket and quantiles were meaningless interpolations. Explicit second-based boundaries restore a usable distribution, with a regression test guarding them. (#1405)

  • Credential Vault header injection fixed for streamed request bodies. With stream_large_bodies, bodies over 1 MiB are forwarded before the request hook fired, so auth headers arrived too late and uploads failed with 403 invalid api-key. Injection moved to the requestheaders hook (fires before the upstream connection), and this also fixes missed response redaction when the response arrives before the request hook (e.g. a 413 mid-upload). (#1466)

  • No-SNI TLS connections now pass through transparent MITM instead of breaking. With no hostname in the ClientHello, mitmproxy's hostname verification fell back to the destination IP and tore down the connection (hostname mismatch) — breaking HTTPS egress to OSS for clients like ossfs2 that connect by IP, unless the insecure flag was set (which Credential Vault rejects). No-SNI flows now pass through untouched; hostname-based ignore_hosts matching and TCP deny/allow enforcement still apply. (#1469)

📦 Misc

  • mitmproxy SSE truncation repro tooling. Self-contained reproduction scripts and docs for mitmproxy/mitmproxy#8364, where large SSE bodies over TLS HTTP/1.1 are truncated when the upstream closes right after the body: TLS mode reproduces, plain/delayed-close controls pass. (#1462)
