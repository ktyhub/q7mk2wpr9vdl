OpenSandbox リリース - 1.2.1

1.2.0 からアップグレードするユーザー向けの安定したパッチ リリース (1.2.1 リリース候補とその後の修正の両方を含む)。サーバー、CLI、SDK、チャート、およびプラットフォーム イメージは、1.2.1 で一緒に出荷されます。

ハイライト

  • 動的資格情報: Credential Vault Exchange は、解決されたシークレットのボールト永続化を行わずに、サーバー、出力、および 5 つの SDK すべてにわたって要求ごとに資格情報を解決します (#2457 #2535 #2534 #2560)。
  • マルチバージョン高速サンドボックス VMM: マネージド Firecracker 1.16.1/1.17.0 バンドルにより、新しいテンプレート ビルドではインストールされている最も高いバージョンが選択され、既存のアーティファクトは正確に記録された VMM バージョンで復元され、利用できない場合は明示的に失敗します (#2795 #2812 fast-sandbox#189)。
  • より安全なデータと容量の管理: 段階的なアップロードにより、アトミック置換が利用可能な場合は上書きデータ損失が削減され、コントローラーの再起動によりライブ サンドボックス ポッドが保持され、Docker により要求された書き込み可能レイヤーのディスク クォータが強制されます (#2433 #2478 #2398 #2716)。

サーバー

  • ResourceAware プールでの作成およびスナップショット復元を通じて、テンプレートの CPU/メモリ シェイプを保持します。レガシー プールは、既存の動作を保持します (#2602 #2619 #2623 #2628 #2633)。
  • 書き込み可能なコンテナー層で Docker resourceLimits.disk を強制し、サポートされていないドライバーまたは無効な制限に対して、黙って無視するのではなく 400 を返します (#2716)。
  • 一時停止したサンドボックスから直接 Docker スナップショットを許可します (#1941)。
  • サーバープロキシデータパスをメンテナンスモードに移行します。既存のトラフィックは引き続きサポートされますが、展開はイングレス ゲートウェイ (#2548) に移行する必要があります。
  • スペルミスのあるオプションを黙って受け入れるのではなく、クローズされたリクエストオブジェクト内の不明なフィールドを拒否します (#2576)。
  • オブジェクトごとのインフォーマーの無効化とサーバー側のメタデータ セレクター (#2599 #2559) により、Kubernetes API トラフィックとリストのコストを削減します。
  • OCI テンプレート アーティファクトが予期されるリポジトリに SHA-256 固定される必要があります (#2491)。
  • 同時に削除されたコンテナーを除き、Docker の有効期限の強制を復元できない場合、起動に失敗します (#2533)。
  • その他の修正により、作成タイムアウト診断とアイドル一時停止プローブ境界が改善されました (#2434 #2596)。 Docker マウント、ホストパス、およびリソースの検証 (#2421 #2505 #2474 #2701 #2751);プロキシ GET ボディと枯渇エラー (#2518 #2519);空のメタデータ フィルター、名前検証、および API エラー コード (#2461 #2499 #2702 #2703)。

SDKs

  • 5 つの SDK はすべて、交換資格情報ソースと資格情報のみのバインディング認証をサポートします。 Kotlin/C# コンシューマーは、拡張された資格情報の種類 (#2534 #2560) を再コンパイルして確認する必要があります。
  • オプションの詳細ダウンロード API は、既存のアダプターを変更することなく、ステータス、ヘッダー、範囲、および部分応答検出を公開します。 Python/JavaScript/C# は、エンコードされた長さがデコードされた出力を説明できない場合、不明な合計を報告します (#1597 #2592)。
  • ドキュメントでは、ライフサイクル/ネットワーク オプション、交換認証情報、テンプレート ワークフロー、および S3 の例 (#2590 #2597 #2620 #2506) が拡張されています。

Python

  • MCP は、バックグラウンド コマンド ポーリングとインクリメンタル出力用に command_get_status および command_get_logs を追加します (#2648)。
  • サイレント コマンド SSE ストリームがタイムアウトになるようになりました。ダウンロードが放棄されると接続が解放され、ストリーミングの失敗では一貫して SDK 例外 (#2527 #2487 #2531 #2570 #2515 #2525) が使用されます。
  • プールを正常にシャットダウンすると、サンドボックスを放棄するのではなく、クリーンアップ キルを排出します。小規模な修正では、エンドポイントの無効化、アダプターのリダイレクト/フック、および対処可能な MCP エラー (#2507 #2409 #2553 #2524) がカバーされています。

JavaScript

  • 正のミリ秒未満のコマンド タイムアウトが無制限になるのを防ぎます。無制限のリダイレクト期限、構造化された分離セッション エラー、反復中のダウンロードの終了を修正しました (#2440 #2488 #2466 #2514)。

コトリン

  • コマンド/セッション タイムアウトの小数部分をミリ秒単位で切り上げ、ミリ秒未満の値が無制限になるのを防ぎます (#2537)。

C#

  • インラインおよび交換バリアントには共通の CredentialSource モデルを使用します。再コンパイル時にインラインのみの前提を更新します (#2560)。

行きます

  • 改行を挿入せずにコードインタープリターの出力フラグメントを Execution.Text() に保持します (#2447)。
  • 確立されたストリームを切り捨てたり、未完了の Readiness プローブを受け入れたりすることなく、ウェイク、Running-state、および Interpreter-readiness バジェットを強制します (#2572 #2611 #2528 #2668 #2480 #2504)。
  • キャンセルされたプール操作中にクリーンアップの所有権を保持し、再試行のために不完全な破棄をフェンスします。キャンセルされた取得では、健全なアイドル容量が消費されなくなりました (#2542 #2617 #2580 #2616)。
  • ライフサイクルの変更後に、他の呼び出し元が引き続き必要とするフェッチをキャンセルせずに、古いエンドポイント ルックアップをフェンスします (#2503 #2564 #2579)。
  • その他、バウンド再試行オーバーフローとサーバー提供の遅延を修正しました (#2452 #2508 #2509)。 SSE 解析、マルチパート境界、およびヘッダーのマージを改善しました (#2439 #2618 #2468 #2529)。正しいプールのメンテナンス、テレメトリの期限、およびタイムアウト テスト (#2453 #2565 #2540 #2479)。

コントローラー

  • 名前空間スコープのキャッシュ、構成可能なリーダー選出タイミング、およびデプロイメント調整用の controller.extraArgs を追加します (#2571 #2651 #2566)。
  • エビクション前にプール割り当てを回復し、コントローラーの再起動後にライブサンドボックス Pod を保護します (#2398)。
  • 必要なダイジェストが欠落している rootfs スナップショットを拒否し、唯一の再開可能なランタイム (#2482) を削除する代わりに、その Pod を保持します。
  • その他の修正により、ライフサイクル関連のメモリ増加が防止され、poolMax の削減後に余分なアイドル状態の Pod が削除され、リカバリ ConfigMap が正しい名前空間 (#2646 #2470 #2694) に配置されます。

実行

  • JUPYTER_TOKEN が設定されていない場合に Jupyter ランタイム トークンを検出します (#2448)。
  • 既存のコンテンツを保護するために、名前を変更する前にアップロードと分離ファイルの置換を段階的に行います。アトミック性には、以下で説明するインプレース権限フォールバックを備えた、書き込み可能な格納ディレクトリが必要です (#2433 #2478)。
  • コピーアップ/名前変更中に分離ワークスペースのコンテンツとモードを保持し、オーバーレイの削除を優先し、ホスト ターゲットに従うのではなくシンボリックリンク chmod を拒否します (#2638 #2469)。
  • Kubernetes 出口サイドカー CA ローテーションの後に MITM trust を更新し、永続的な TLS 障害を回避します (#2582)。
  • 分離された実行はシェル制御入力を消費しなくなりました。 Bash セッションを削除すると、すべてのアクティブな実行が終了し、PTY クローズによって通常のバックグラウンド ジョブがハングアップされますが、HUP 無視ジョブの端末のような動作は維持されます (#2517 #2731 #2733)。
  • Jupyter 起動の再試行とセッションのクリーンアップを復元し、サポートされていない言語を即座に失敗させ、完了を報告する前に出力/エラーを配信します (#2486 #2689 #2606)。
  • 一時的なセットアップの失敗後に、クエリを自動的に再実行せずに SQL 実行を回復します (#2757)。
  • セキュリティ強化: ダウンロード ヘッダーの制御バイトをパーセント エンコードし、RFC 8187 ファイル名エンコードを修正しました (#2741 #2516)。
  • その他の修正は、コマンド ログの相関と検証をカバーしています (#2598 #2686)。 PTY 出力とエクスポートされたエスケープ (#2644 #2772);ダウンロード/検索の検証およびファイルのタイムスタンプ (#2451 #2687 #2604); cgroup-v1 メトリックと SQL バイト レンダリング (#2641 #2685);古い Kotlin/JVM デプロイメントに対するオプトインのレガシー SSE 回避策 (#2472)。

ネットワーキング

出口

  • Credential Vault Exchange: 出力派生のサンドボックス ID とリクエスト ターゲットを使用して、UDS/HTTPS 経由で新しいヘッダーを解決します。解決はクローズに失敗し、解決されたシークレットはボールトによって永続化もキャッシュもされません (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563)。
  • MITM (#2662) による元の宛先チェックを含む、サブジェクトごとの高速サンドボックス TCP ポートおよび IP/CIDR プラス ポート ポリシーを強制します。
  • 出力を再起動せずに、高速サンドボックス オペレータの拒否/許可ルールと到達可能なポートの上限をホットリロードします。変更はアクティブなサブジェクト全体にアトミックに適用され、失敗時の以前のポリシーが保持され、失効後に古い DNS 応答が拒否されます。ネットワーク セキュリティ ガイドでは、古いガイド URL (#2727 #2814) を保持しながら、展開、優先順位、適用の境界について文書化しています。
  • dns+nft サイドカー ポリシー PATCH/DELETE で、確立されたトラフィックを dropEstablished=true でブロックすることを選択できるようにします。高速サンドボックスはサポートされていません (#2346)。
  • [実験的] 耐久性のあるフェンス、認証された子セッション、確認済みのポリシー/Vault スナップショットを使用して、厳格な Actions v2 の所有権/永続性とサブジェクトの準備を強化します。デフォルトは変更されません (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708)。
  • [実験] — 本番環境用ではありません: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound は予算付きの TLS ハンドシェイク実験を選択しますが、資格情報の挿入やリクエスト転送は機能しません。復号化されたすべての HTTP/1.1 および HTTP/2 発信元トラフィックは引き続き拒否されます。 all はデフォルトのままです。 OSEP-0023 ロールアウトには、未完了の作業 (#2737 #2797 #2777) が記載されています。
  • セキュリティ修正: ポリシー PATCH は変更されていない拒否ルールを保持し、無効な defaultAction 値は、矛盾した潜在的なフェールオープン強制を生成するのではなく拒否されます (#2664 #2662 #2693)。
  • カーネル内の高速サンドボックス DNS リースを更新し、削除中に他のサブジェクトのリースを保持します (#2652 #2653)。
  • その他の強化には、実験的な傍受ポートの検証、冪等の Readiness フック、および NFT スモーク/リードバック チェック (#2587 #2510 #2543 #2735) が含まれます。

イングレス

  • 1 つのキューと待機ウェイク バジェットを使用し、フライトの存続期間に対してそれを検証します。通常/高速サンドボックスの混合ウェイク ルーティングで起動時にパニックが発生しなくなりました (#2511 #2513 #2600)。
  • その他の修正により、レガシー ホスト名ポートが検証され、最終ステータス/client-IP テレメトリが修正され、ウェイク テスト レースが削除されました (#2578 #2484 #2688 #2512)。

高速サンドボックス

  • ランタイムおよびテンプレート ビルド用にマネージド Firecracker 1.16.1/1.17.0 バイナリをバンドルし、最新のインストールされた VMM (#2795 #2812 fast-sandbox#189) をサイレントに使用するのではなく、復元用に正確なアーティファクトが記録されたバージョンを選択します。
  • ResourceAware 直接 Firecracker VMM を境界付き cgroup サブツリーに分離し、クリーンアップのために失敗したランタイム ID を保持しながらプールローカル OOM から Fastlet を保護します (#2626 fast-sandbox#162)。
  • 新しいオブジェクト ストア テンプレートでフリー ページ レポートを有効にし、静的リソースのコミットメントを変更せずにゲストが解放したメモリをホストに返します。 OCI テンプレートはまだサポートされていません (#2546 fast-sandbox#114)。
  • 再利用可能なウォーム ublk デバイスとベストエフォート型チェックポイント/rootfs レイヤー圧縮 (#2594 fast-sandbox#163 #2546 fast-sandbox#158) により、OCI ストレージを改善します。
  • ローカルに公開された OCI チェックポイント BLOB を再利用して、境界付きストレージ、ライブデバイス参照の保護、およびレジストリ フォールバックを使用して、同一ノードの再開を高速化します (#2812 fast-sandbox#178)。
  • [実験的] RootfsOnly OCI スナップショットは、機能チェック、生成モード検証、およびジャーナル リカバリを備えて、ランタイム キャプチャから Fast Sandbox の FastPath および SandboxSnapshot CRD まで拡張されるようになりました。メモリを保持せずにコールドブートを復元します。 OpenSandbox REST/SDK モードの選択と RootfsOnly の一時停止/再開は引き続きサポートされていません (#2706 fast-sandbox#173 #2812 fast-sandbox#177)。
  • OverlayBD テンプレート ビルドはゲスト コントロールを挿入し、デフォルトでフリーズ/解凍を検証するようになりました。 RootfsOnly キャプチャ機能 (#2812 fast-sandbox#183) を取得するには、既存のテンプレートを再構築する必要があります。
  • オプションの標準エラー出力ミラーリングを使用して、ファーストパーティ Kubernetes コンポーネントの共有 YAML 構成ファイルのログ記録とローテーションを追加します。ログ コレクターとカスタム起動フラグは移行が必要です (#2812 fast-sandbox#197)。
  • タイムスタンプ付きのテンプレート構築フェーズ、経過時間、イメージのプル、rootfs の準備、ゲストの準備、スナップショット、パブリケーションにわたる失敗を公開します (#2815 fast-sandbox#201)。
  • [実験的] フェンスにより、永続的な所有者 ID と確認された引退を伴う厳密な Action v2 操作が遅延しました。 v1 はデフォルトのままです (#2546 fast-sandbox#152)。
  • 名前空間/API-client チューニング、チャート スケジューリング フック、オプションのダイレクト オリジン配信、およびテンプレート ベイク実行初期化モードを追加 (#2581 fast-sandbox#161 #2566 #2494 #2497)。
  • 即時の作成/一時停止/再開の遷移は、解決遅延なしで収束するようになり、アクティブ プールは、容量としてカウントされるのではなく、ターミナル Fastlet ポッドを置き換えます (#2626 fast-sandbox#166 #2706 fast-sandbox#172)。
  • ublkd デバイスの損失後に、手動でキャッシュをワイプせずに、アイドル状態の共有スナップファイルの添付ファイルを回復します。他のサンドボックス リースの添付ファイルは、ライブ コンシューマ (#2812 fast-sandbox#193) の下で再構築されるのではなく、保護されたままになります。
  • その他の修正は、BusyBox ベースのテンプレートの準備状況、タイムスタンプの精度、および既存のシークレット レンダリング (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695) をカバーします。 Firecracker イメージ/テンプレート参照のキャッシュ アフィニティ マッチングを復元します (#2812 fast-sandbox#119)。
  • ResourceAware のロールアウト範囲を拡大し、飽和容量を変更せずにフィクスチャの CPU バジェットを修正します (#2622 #2637 #2647 #2669 #2812)。 ublk リカバリ、交換/コンソール統合テスト、KVM 選択、およびスナップショット ステージングのドキュメント (#2454 #2561 #2676 #2665 #2714) を改善しました。ゲート PR KVM は、無関係なラベルがアクティブな実行をキャンセルすることなく、メンテナが追加した ok-to-test 上で実行されます (#2813)。

その他

  • コンソール: BFF が保持する認証情報と自動セッション クリーンアップを備えたブラウザ PTY シェルを追加し、切断フィードバックを改善し、インターフェイスを英語に翻訳します (#2233 #2639 #2657)。
  • ノード エージェント: クラスター全体のサンドボックス監視ではなく、ノードローカル VM メタデータと再起動セーフ オフセットを使用して、オプトイン vm-console ソースを通じてゲスト カーネル/初期化コンソール出力を収集します (#2234 #2677 #2546 高速サンドボックス#154)。
  • CLI 修正により、リテラル出力と文字列構成が保持されます (#2520 #2522)。構成エラー、引数エラー、タイムアウトエラー、および上書き拒否エラー (#2521 #2551 #2692 #2742 #2748 #2743) を改善しました。そして、osb template get の欠落している manifest_ref (#2523 #2691 #2747 #2745) を含む、PTY クリーンアップ、メトリック監視、およびテーブル出力を修復します。
  • 例では、ACK PeerPods/TDX ウォークスルーを追加し、Google ADK 2.13.0 のネイティブ環境/ツールセットを採用し、Python ネットワーク分離の例 (#2545 #2734 #2711) を修正します。
  • ガバナンス/文書は、AAIF 憲章と DCO/CC-BY-4.0 拠出規則を公開し、投票と所有権を明確にし、提案ステータスを調整し、文書の署名と出所のギャップを調整します (#2490 #2678 #2679 #2680 #2624 #2670 #2671 #2672 #2673 #2674 #2467)。
  • メンテナンスには、孤立したノードとエージェントのストリーム、デッドコード/テストのクリーンアップ、単一プラットフォームの種類インポート、および Linux/eBPF テスト セットアップ (#2471 #2496 #2640 #2736 #2573 が含まれます。 #2473)。
  • リリースの準備には、候補バージョン バンプ、メモ、および生成された BOM (#2583 #2584 #2585 #2588 #2720 #2723 が含まれます。 #2724 #2725 #2726)。

アップグレードと互換性

  • マネージド Firecracker: 一致するチャート、ランタイム、ビルダー イメージをデプロイします。 runtimeEnvironments → firecracker.firecracker.vmmDir がサポートされるようになり、絶対マネージド バイナリ ディレクトリを参照する必要があります。新しい管理対象ビルドでは、インストールされている最も高いバージョン (現在 1.17.0) が選択されます。 Full/RootfsOnly リストアにはマニフェストに記録されたバージョンが必要で、それが使用できない場合は最新にフォールバックせずに失敗します。既存のアーティファクトの 1.16.1 バイナリを再ラベル付けせずに保持します。古いバイナリを保持しても、永続化された高速サンドボックス状態 (#2795 #2812 fast-sandbox#189) のダウングレード互換性は保証されません。
  • リクエストの検証: 閉じられたリクエスト オブジェクトから不明なキーを削除し、エイリアスのスペルを 1 つだけ使用します。これらは 422 を返すようになりました。 ImageAuth.token/Docker-config エクストラをサポートされている username/password に置き換え、名前/アドレスから末尾の改行を削除し、ポリシー defaultAction (#2576 #2499 には allow/deny のみを使用します。 #2693)。
  • SDK 認証情報モデル: Kotlin/C# は 1.2.0 と ABI 互換性がありません。拡張されたソースと null 許容/型なしの認証の前提を再コンパイルしてレビューします。 Exchange 認証には credential のみが含まれます。 Python インライン ソースは余分なキーを拒否するため、生成されたモデルのユーザーは手書きのモデルを好む必要があります。変更されたソース/メタデータ モデルおよび Execution には、キー付き Go リテラルを使用します。 JSON ラウンドトリップにより、Execution.Text() のプライベート フォーマット モード (#2560 #2534 #2447) が失われます。
  • プロキシ/イングレス: メンテナンス専用のサーバー プロキシ オプションをイングレスに移行します。レガシー ホスト名ポートは 1–65535 の正規 10 進数である必要があり、--wake-park-budget は --wake-max-flight-lifetime (#2548 #2578 #2511) より下である必要があります。
  • Docker クォータ: 指定された disk/storage/ephemeral-storage 制限は正の値であり、ストレージ ドライバーによってサポートされている必要があります。そうでない場合、作成は 400 を返します。書き込み可能なレイヤーのみがカバーされ、マウント、ボリューム、またはイメージ レイヤーのバインドはカバーされません。 Windows は、既存のディスク サイズの動作 (#2716) を保持します。
  • Docker プリフライト/スタートアップ: 重複、ルート、コロンを含む、または予約されたマウント先と署名付き int64 を超える数量を修正します。明示的な / ホストパス許可リストは、すべての POSIX 子孫を許可します。コンテナーが同時に削除されない限り、期限切れ復元の失敗により起動が妨げられるようになりました。永続的なデーモン エラー (#2421 #2505 #2751 #2474 #2533) を調査します。
  • ダウンロード: 詳細な API はカスタム アダプターのオプションのままです。追加する前に 206/isPartial と範囲を確認し、応答本文を閉じます。不明な合計には -1 が使用されます。エンコードされた HTTP の長さ/範囲は、デコードされた進行状況または再開オフセットではありません。 Python 呼び出し元は、生の httpx エラー (#1597 #2592 #2515 #2525) ではなく、SDK 例外をキャッチする必要があります。
  • タイムアウトとポーリング: Python コマンド ストリームは、バイトなしで max(request_timeout, 30s) の後にタイムアウトになります。正当な沈黙を得るには、request_timeout を上げます。 MCP ポーラーは完了後にログをもう一度読み取り、不透明なカーソルを保持する必要があります。空の出力は完了していません。カスタム Go プール ストアはキャンセルを尊重する必要があり、不完全な破棄は再試行のために隔離されたままになります (#2527 #2648 #2580)。
  • アップロードのアトミック性: 段階的なアップロード/分離された置換には、書き込み可能なディレクトリを含むディレクトリを使用します。既存の書き込み可能なファイルは、ステージング権限エラーが発生した場合、非アトミックな切り捨てにフォールバックします。通常の/files/replaceはそのままです。段階的な置換では、xattrs/ACLs/capabilities/SELinux ラベルではなくモードが保持されます。所有権は通常の書き込みの場合はベスト エフォートであり、分離された書き込みの場合はセッション UID/GID (#2433 #2478) です。
  • アップロード ストレージ: ハードリンク/オープン リーダーは古い i ノードを保持し、マルチパートの上書きにはファイル サイズの約 3 倍が必要になる場合があり、中断されたライターはステージング ファイルを残す可能性があります。予約済みの .osb-upload-/.osb-staging- 名、特に接頭辞と 16 桁の 16 進数は避けてください。既存の衝突の名前を直接変更します。特殊ファイルのターゲットは拒否されますが、バインドマウント/オープンされたファイルは名前の変更を妨げる可能性があります。ディレクトリ同期はベストエフォートです (#2433 #2478)。
  • セッションのライフサイクル: 分離されたフォアグラウンド stdin は /dev/null になりました。ファイルまたはヒアドキュメントを使用してください。 Bash セッションを削除すると、重複する実行がすべて終了します。 PTY クローズでは、グループが強制終了されるまでに SIGHUP と最大 500 ミリ秒が追加されますが、nohup/HUP 無視ジョブは存続できます (#2517 #2731 #2733)。
  • Jupyter/JVM: カスタム イメージには、明示的なトークンまたは検出可能なランタイム トークン ファイルと、要求されたカーネルが必要です。 EXECD_SSE_LEGACY_COMPAT よりもシェーディングされた sandbox-api 1.0.18+ を優先します。これはデフォルトでオフになっており、構造化された exit_code 値 (#2448 #2689 #2472) を削除します。
  • コントローラー構成: キャッシュ スコープには、すべての管理対象名前空間に加えて、高速サンドボックス テンプレート/ランタイム環境名前空間が含まれる必要があります。 RBAC を変更したり、テナントを分離したりすることはありません。現在発効している controller.podRecovery.* を確認し、プレーン マニフェスト アップグレードによって残された古い ConfigMap を削除します。カスタム選択のタイミングには、リース > 更新 > 1.2×再試行 (#2571 #2581 fast-sandbox#161 #2694 #2651) が必要です。
  • Exchange 展開: サーバー/SDK/出力バージョンを調整します。サイドカー ライブ リビジョン ランタイムは交換をサポートしていません。リゾルバー呼び出し元認証は実装されていません。Ed25519/JWKS は設計のみのままです。 trusted CA では、保護された UDS または trusted-egress-only HTTPS を使用します。サンドボックス許可ルールはリゾルバーを公開してはならず、MITM UID の除外だけでは分離ではありません (#2501 #2549 #2631 #2547)。
  • [実験的] Strict Actions v2: は、永続的な状態、分離された管理ポート、およびマネージャーの承認を備えたクリーンベースの直接 Firecracker デプロイメントでのみ、OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/ファストレット actionsApiVersion 値の sandbox.fast.io/actions/v2 の一致を有効にします。一時停止/再開、スナップショット/復元、ライブ バインディングの削除、所有者の移行、および同じ UID の再利用は引き続きサポートされていません。端末削除/新しい UID を使用し、フェンスを保持し、フェンシングを認証として扱わない、または既存の状態を v1 にダウングレードしない (#2441 #2460 #2493 #2546 fast-sandbox#152)。
  • [実験的] 資格情報にバインドされたインターセプト: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound は依然として復号化されたアプリケーションの転送を拒否するため、運用環境では有効にしないでください。スイッチが設定されていない場合、有効になっている両方のレガシー ゲートは非推奨のエイリアスのままになります。リビジョンランタイムのみはインストールのみです。明示的なモード/ゲートの競合、空/不明な値、およびサイドカーでのこのスイッチの設定は起動に失敗します (#2737 #2797)。
  • 実験的な起動要件: 資格情報バインド モードでは、透過 MITM、dns+nft、およびデフォルトのインターセプト ポート 80,443 のみが必要です。安全でない TLS 検証、チェーンされたプロキシ、および効果的な ignore_hosts/allow_hosts を削除します。ランタイムユーザー config.yaml の次に config.yml がチェックされます。読み取り/解析エラーはフェールクローズされます。 all に戻るには、両方のレガシー ゲートの設定を解除します。サイドカー ライブ リビジョンは、追加の傍受ポート (#2587 #2797) も拒否します。
  • ポート ポリシー: 高速サンドボックスは TCP のみをサポートし、ルールごとに最大 256 ポートをサポートし、ドメインとポートの組み合わせはサポートしません。通常の更新では、確立されたフローが保持されます。 dropEstablished は dns+nft サイドカー PATCH/DELETE でのみサポートされ、POST では無視され、高速サンドボックス、DNS のみ、ライブ リビジョン、またはチェーン プロキシ プラス トランスペアレント MITM モードではサポートされません。 TCP リセットではなく、パケット ドロップがインストールされます。ポートのみの許可を削除するだけでは、確立されたフローのブロックはトリガーされません (#2662 #2346)。
  • オペレーター ルールのリロード: 高速サンドボックスは、ランタイムで変更可能なルール ファイルを 1 分ごとにリロードします。 ConfigMap を subPath ではなくディレクトリとしてマウントし、kubelet プロジェクション遅延を考慮します。イメージでベイクされたルールには、引き続き新しいイメージと再作成が必要です。リロードが成功すると、DNS が学習したリースがクリアされるため、許可されたドメインは別の検索が必要になります。失敗したリロードでは以前のオーバーレイが保持され、確立された接続は強制的に終了されません (#2727 #2814)。
  • ネットワーク セキュリティ境界: ドメインは、既知の IP への直接接続ではなく、フィルター DNS を拒否します。これらのパスには明示的な IP/CIDR 拒否またはデフォルト拒否ポリシーを使用します。オペレーターはオペレーターが許可するオーバーライドを拒否するため、許可された内部サービスには拒否範囲のカーブアウトが必要です。従来の Docker/Kubernetes の作成では、networkPolicy が指定された場合にのみ出力が挿入されます。 poolRef と networkPolicy はサポートされていないため、テンプレートでプールされたコントロールを構成します (#2814)。
  • ResourceAware ロールアウト: 直接 Firecracker resource-admission.json が v2 から v3 に移行します。古い/新しい Fastlet は他の構成バージョンを拒否するため、プールごとにコントローラー/Fastlet のアップグレードを調整します。ハートビートは v2 のままです。ホストには、書き込み可能な cgroup v2、clone3(CLONE_INTO_CGROUP)、およびゼロ実効プール スワップが必要です。共有メモリの上限は、VM ごとの保護ではなく、コンテナー交換後の存続保証でもありません (#2626 fast-sandbox#162)。
  • 復元のサイズ設定: ResourceAware プールはテンプレートの CPU/メモリ形状を使用します。新しいスナップショットの再生ソース制限は、復元時の呼び出し側制限と一致する必要があります。制限が記録されていないレガシー プールとスナップショットは、以前の動作 (#2623 #2628 #2633) を保持します。
  • [実験的] RootfsOnly: Full はデフォルトのままです。明示的な RootfsOnly モードは、一時停止/再開や OpenSandbox REST/SDK モードの選択ではなく、再利用可能な OCI スナップショットの高速サンドボックス FastPath/CRD を通じて使用できます。新しいキャプチャには、適格なパッチ適用済み Firecracker 1.17.0 テンプレート、ライブ ゲスト ヘルパー、適格なカーネル/OverlayBD バックエンド、排他的 ext4 所有権、および一致するダイジェスト/ストレージ証明書を持つ絶対 FAST_SANDBOX_ROOTFS_QUALIFICATION プロファイルが必要です。カスタム バイナリ ダイジェストはバージョン ゲートをバイパスしません。ランタイム、Fastlet/プロキシ、ビルダー、およびツールを一緒にアップグレードし、適格なテンプレートを再構築し、ジャーナル/フェンスを保存します。コールドブートを復元し、エントリポイントを再実行します。アプリケーション メモリの保存や、検証済みの CPU/アーキテクチャ間の移植性は保証されません (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189)。
  • OverlayBD テンプレート ビルド: ゲスト コントロール インジェクションとフリーズ/解凍検証が OCI ビルダーに必須になりました。 FSB_GUEST_CONTROL_ENABLED はオプトアウトではなくなりました。ヘルパーが欠落しているか、互換性がない場合、またはプローブが失敗すると、ビルドが停止します。ネイティブ テンプレートは変更されません。既存の OCI テンプレートは、キャプチャ機能を得るためにメタデータの編集ではなく再構築する必要があります (#2812 fast-sandbox#183)。
  • 高速サンドボックス ログ: 対象の Kubernetes コンポーネントは、デフォルトで /var/log/fast-sandbox の下にローテーション ファイルを書き込むようになりました (ファイルあたり 100 MiB、10 個のバックアップ、7 日間のバックアップ保持、gzip)。 alsoStderr: true が構成されていない限り、アプリケーション ログは kubectl logs に表示されなくなりました。従来の klog 出力フラグを共有ログ YAML に置き換え、チャート管理の静的ワークロードの ConfigMap/ログ ボリューム マウントを接続し、各テナントの名前空間を個別に構成します。構成は起動時のみです。ライブ Pod の削除ではなく、Fastlet に対して制御されたプールのドレイン/置換を使用し、一時的なログが失われる前に収集を調整します。明示的な欠落/無効な構成、または書き込み不可能な出力により起動が妨げられます。ローテーション制限はハード ディスク クォータではなく、ゲスト/VM ログ (#2812 fast-sandbox#197) をカバーしません。
  • OCI チェックポイント キャッシュ: OverlayBD のブロック キャッシュとは別に、追加の BLOB キャッシュ用のスペースを予約します (デフォルト: 16 GiB、4096 ファイル、1 GiB の空きスペース予約)。ハードリンクの再利用のために、ステージング/キャッシュ/デバイスの状態を 1 つのファイルシステムに保持します。ファイルシステム間の配置や競合はレジストリにフォールバックします。 FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 を設定して、BLOB キャッシュの挿入/検索を無効にします。アクティブデバイスのピンは、予算が縮小した場合も含めて保護されたままになります (#2812 fast-sandbox#178)。
  • ublkd リカバリ: 共有スナップファイルの自動再構築は、他のサンドボックス リースに添付が必要ない場合にのみ適用されます。これは、実行中の VM の透過的なリカバリではありません。共有キャッシュを手動で消去するのではなく (#2812 fast-sandbox#193)、他のリースが残っているときに再試行する前に、通常のライフサイクルを通じて影響を受けるサンドボックスを削除します。
  • テンプレートの再構築: オプトイン runtime.execd_run_as_init には再構築されたテンプレートが必要です。 execd は、ゲスト PID 1 の下のサブリーパーのままです。フリー ページ レポートには、再構築されたオブジェクト ストア テンプレートと互換性のある VMM/カーネル サポートも必要です。復元されたデバイス状態を切り替えることはできません。また、OCI レポートを有効にしたり、より高いオーバーコミットを正当化したりすることはできません。ロールバックでは、古いテンプレート (#2494 #2497 #2546 fast-sandbox#114) が使用されます。
  • OCI チャートのデフォルト: アイドル状態の ublk デバイスが予約されるようになりました。 runtime.oci.poolLow=0 をオンデマンド割り当てに設定し、poolSizeGB を切り上げられた rootfs 容量に一致させます。 P2P はデフォルトで有効のままです。カスタム runtime.config は、直接配信用に別途調整が必要です (#2594 fast-sandbox#163 #2566)。
  • スナップショットの整合性: ポッドを保持している間、欠落しているコミット ダイジェストは一時停止に失敗するようになりました。古いスナップショットは修復されません。 OCI テンプレート参照は、予期されるリポジトリに完全な SHA-256 ダイジェストを保持する必要があります。無効な参照を再構築します (#2482 #2491)。
  • CLI スクリプト: 非正のリクエスト タイムアウトと空のルール ターゲットは使用法エラーです。 osb config init 上書き拒否は、ファイルを変更せずに 1 を終了するようになりました (#2742 #2692 #2743)。
  • VM コンソール コレクション: vm-console をオプトインし、hostPaths.vmConsole をランタイム状態のルートに合わせ、すべてのランタイム ノードをカバーし、ファイルシンクの保持を管理します (#2234 #2677)。
  • アーティファクト検証: アンブレラ ワークフローでは、署名/出所を包括的にカバーすることはできません。 BOM ダイジェストの照合は発信元の証明ではないため、署名要件をバイパスしてはなりません (#2467)。
  • イメージ: opensandbox/<component>:release-1.2.1 (3 つのレジストリすべて、高速サンドボックス用の fsb イメージ)
  • パッケージ: サーバー / CLI / SDK はすべて 1.2.1

OpenSandbox release-1.2.1

Stable patch release for users upgrading from 1.2.0, including both 1.2.1 release candidates and subsequent fixes. Server, CLI, SDKs, charts, and platform images ship together at 1.2.1.

Highlights

  • Dynamic credentials: Credential Vault Exchange resolves credentials per request across the server, egress, and all five SDKs, without vault persistence of resolved secrets (#2457 #2535 #2534 #2560).
  • Multi-version Fast Sandbox VMMs: managed Firecracker 1.16.1/1.17.0 bundles let new template builds select the highest installed version while existing artifacts restore with their exact recorded VMM version, failing explicitly if it is unavailable (#2795 #2812 fast-sandbox#189).
  • Safer data and capacity management: staged uploads reduce overwrite data loss where atomic replacement is available, controller restarts preserve live-sandbox Pods, and Docker enforces requested writable-layer disk quotas (#2433 #2478 #2398 #2716).

Server

  • Carry template CPU/memory shapes through creation and snapshot restore on ResourceAware pools; legacy pools retain their existing behavior (#2602 #2619 #2623 #2628 #2633).
  • Enforce Docker resourceLimits.disk on the writable container layer, returning 400 for unsupported drivers or invalid limits instead of silently ignoring them (#2716).
  • Allow Docker snapshots directly from paused sandboxes (#1941).
  • Move the server-proxied data path into maintenance mode; existing traffic remains supported, but deployments should migrate to the ingress gateway (#2548).
  • Reject unknown fields in closed request objects rather than silently accepting misspelled options (#2576).
  • Reduce Kubernetes API traffic and list costs through per-object informer invalidation and server-side metadata selectors (#2599 #2559).
  • Require OCI template artifacts to be SHA-256-pinned in the expected repository (#2491).
  • Fail startup when Docker expiration enforcement cannot be restored, except for concurrently removed containers (#2533).
  • Other fixes improve create-timeout diagnostics and idle-pause probe bounds (#2434 #2596); Docker mount, host-path, and resource validation (#2421 #2505 #2474 #2701 #2751); proxy GET bodies and exhaustion errors (#2518 #2519); and empty metadata filters, name validation, and API error codes (#2461 #2499 #2702 #2703).

SDKs

  • All five SDKs support exchange credential sources and credential-only binding auth; Kotlin/C# consumers must recompile and review widened credential types (#2534 #2560).
  • Optional detailed download APIs expose status, headers, ranges, and partial-response detection without requiring changes to existing adapters; Python/JavaScript/C# report unknown totals when encoded lengths cannot describe decoded output (#1597 #2592).
  • Documentation expands lifecycle/network options, exchange credentials, template workflows, and S3 examples (#2590 #2597 #2620 #2506).

Python

  • MCP adds command_get_status and command_get_logs for background-command polling and incremental output (#2648).
  • Silent command SSE streams now time out; abandoned downloads release connections, and streaming failures consistently use SDK exceptions (#2527 #2487 #2531 #2570 #2515 #2525).
  • Graceful pool shutdown drains cleanup kills rather than abandoning sandboxes; smaller fixes cover endpoint invalidation, adapter redirects/hooks, and actionable MCP errors (#2507 #2409 #2553 #2524).

JavaScript

  • Prevent positive sub-millisecond command timeouts from becoming unbounded; fix unlimited redirect deadlines, structured isolated-session errors, and closing downloads during iteration (#2440 #2488 #2466 #2514).

Kotlin

  • Round fractional command/session timeout milliseconds upward, preventing sub-millisecond values from becoming unbounded (#2537).

C#

  • Use the common CredentialSource model for inline and exchange variants; update inline-only assumptions when recompiling (#2560).

Go

  • Preserve code-interpreter output fragments in Execution.Text() without inserting newlines (#2447).
  • Enforce wake, Running-state, and interpreter-readiness budgets without truncating established streams or accepting unfinished readiness probes (#2572 #2611 #2528 #2668 #2480 #2504).
  • Preserve cleanup ownership during cancelled pool operations and fence incomplete destruction for retry; cancelled acquires no longer consume healthy idle capacity (#2542 #2617 #2580 #2616).
  • Fence stale endpoint lookups after lifecycle changes without cancelling fetches still needed by other callers (#2503 #2564 #2579).
  • Other fixes bound retry overflow and server-supplied delays (#2452 #2508 #2509); improve SSE parsing, multipart boundaries, and header merging (#2439 #2618 #2468 #2529); and correct pool maintenance, telemetry deadlines, and timeout tests (#2453 #2565 #2540 #2479).

Controller

  • Add namespace-scoped caches, configurable leader-election timings, and controller.extraArgs for deployment tuning (#2571 #2651 #2566).
  • Recover pool allocations before eviction, protecting live-sandbox Pods after controller restarts (#2398).
  • Reject rootfs snapshots missing required digests and retain their Pods instead of deleting the only resumable runtime (#2482).
  • Other fixes prevent lifecycle-related memory growth, remove excess idle Pods after poolMax reductions, and place the recovery ConfigMap in the correct namespace (#2646 #2470 #2694).

Execd

  • Discover Jupyter runtime tokens when JUPYTER_TOKEN is unset (#2448).
  • Stage uploads and isolated-file replacements before rename to protect existing content; atomicity requires a writable containing directory, with an in-place permission fallback described below (#2433 #2478).
  • Preserve isolated-workspace contents and modes during copy-up/rename, honor overlay deletions, and reject symlink chmod rather than following host targets (#2638 #2469).
  • Refresh MITM trust after Kubernetes egress-sidecar CA rotation, avoiding persistent TLS failures (#2582).
  • Isolated runs no longer consume shell control input; deleting Bash sessions terminates all active runs, and PTY close hangs up ordinary background jobs while retaining terminal-like behavior for HUP-ignoring jobs (#2517 #2731 #2733).
  • Restore Jupyter startup retries and session cleanup, fail unsupported languages promptly, and deliver output/errors before reporting completion (#2486 #2689 #2606).
  • Recover SQL execution after temporary setup failures without automatically replaying queries (#2757).
  • Security hardening: percent-encode control bytes in download headers and correct RFC 8187 filename encoding (#2741 #2516).
  • Other fixes cover command-log correlation and validation (#2598 #2686); PTY output and exported escapes (#2644 #2772); download/search validation and file timestamps (#2451 #2687 #2604); cgroup-v1 metrics and SQL byte rendering (#2641 #2685); and an opt-in legacy SSE workaround for older Kotlin/JVM deployments (#2472).

Networking

egress

  • Credential Vault Exchange: resolve fresh headers through UDS/HTTPS using egress-derived sandbox identity and request targets; resolution fails closed, and resolved secrets are neither persisted nor cached by the vault (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563).
  • Enforce Fast Sandbox per-subject TCP port and IP/CIDR-plus-port policies, including original-destination checks through MITM (#2662).
  • Hot-reload Fast Sandbox operator deny/allow rules and reachable-port caps without restarting egress; changes apply atomically across active subjects, retaining the previous policy on failure and rejecting stale DNS answers after revocation. The network-security guide documents deployment, precedence, and enforcement boundaries while preserving old guide URLs (#2727 #2814).
  • Allow dns+nft sidecar policy PATCH/DELETE to opt into blocking established traffic with dropEstablished=true; Fast Sandbox is not supported (#2346).
  • [EXPERIMENTAL] Harden strict Actions v2 ownership/persistence and subject readiness with durable fences, authenticated child sessions, and acknowledged policy/Vault snapshots; defaults remain unchanged (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708).
  • [EXPERIMENTAL] — not for production: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound selects a budgeted TLS handshake experiment, not working credential injection or request forwarding: all decrypted HTTP/1.1 and HTTP/2 origin traffic is still denied. all remains the default; the OSEP-0023 rollout describes unfinished work (#2737 #2797 #2777).
  • Security fixes: policy PATCH preserves untouched deny rules, and invalid defaultAction values are rejected rather than producing inconsistent, potentially fail-open enforcement (#2664 #2662 #2693).
  • Renew Fast Sandbox DNS leases in the kernel and preserve other subjects' leases during deletion (#2652 #2653).
  • Other hardening covers experimental interception-port validation, idempotent readiness hooks, and nft smoke/read-back checks (#2587 #2510 #2543 #2735).

ingress

  • Use one queue-plus-wait wake budget and validate it against flight lifetime; mixed regular/Fast Sandbox wake routing no longer panics at startup (#2511 #2513 #2600).
  • Other fixes validate legacy hostname ports, correct final-status/client-IP telemetry, and remove a wake-test race (#2578 #2484 #2688 #2512).

Fast Sandbox

  • Bundle managed Firecracker 1.16.1/1.17.0 binaries for runtime and template builds, selecting the exact artifact-recorded version for restore rather than silently using the latest installed VMM (#2795 #2812 fast-sandbox#189).
  • Isolate ResourceAware direct-Firecracker VMMs in a bounded cgroup subtree, protecting Fastlet from pool-local OOM while retaining failed-runtime identities for cleanup (#2626 fast-sandbox#162).
  • Enable free-page reporting in new object-store templates, returning guest-freed memory to the host without changing static resource commitments; OCI templates are not yet supported (#2546 fast-sandbox#114).
  • Improve OCI storage with reusable warm ublk devices and best-effort checkpoint/rootfs layer compaction (#2594 fast-sandbox#163 #2546 fast-sandbox#158).
  • Reuse locally published OCI checkpoint blobs for faster same-node resume, with bounded storage, protection for live-device references, and registry fallback (#2812 fast-sandbox#178).
  • [EXPERIMENTAL] RootfsOnly OCI snapshots now extend from runtime capture to Fast Sandbox's FastPath and SandboxSnapshot CRD, with capability checks, produced-mode validation, and journaled recovery. Restores cold-boot without preserving memory; OpenSandbox REST/SDK mode selection and RootfsOnly pause/resume remain unsupported (#2706 fast-sandbox#173 #2812 fast-sandbox#177).
  • OverlayBD template builds now inject guest-control and validate freeze/thaw by default; existing templates need rebuilding to gain RootfsOnly capture capability (#2812 fast-sandbox#183).
  • Add shared YAML-configured file logging and rotation for first-party Kubernetes components, with optional stderr mirroring; log collectors and custom launch flags need migration (#2812 fast-sandbox#197).
  • Expose timestamped template-build phases, elapsed times, and failures across image pull, rootfs preparation, guest readiness, snapshotting, and publication (#2815 fast-sandbox#201).
  • [EXPERIMENTAL] Fence delayed strict Actions v2 operations with durable owner identity and confirmed retirement; v1 remains the default (#2546 fast-sandbox#152).
  • Add namespace/API-client tuning, chart scheduling hooks, optional direct-origin delivery, and template-baked execd init mode (#2581 fast-sandbox#161 #2566 #2494 #2497).
  • Immediate create/pause/resume transitions now converge without settle delays, and active pools replace terminal Fastlet Pods instead of counting them as capacity (#2626 fast-sandbox#166 #2706 fast-sandbox#172).
  • Recover idle shared snapfiles attachments after ublkd device loss without manual cache wipes; attachments with other Sandbox leases remain protected rather than being rebuilt under live consumers (#2812 fast-sandbox#193).
  • Other fixes cover BusyBox-based template readiness, timestamp precision, and existing-secret rendering (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695); restore cache-affinity matching for Firecracker image/template references (#2812 fast-sandbox#119).
  • Expand ResourceAware rollout coverage and correct fixture CPU budgets without changing saturation capacity (#2622 #2637 #2647 #2669 #2812); improve ublk recovery, exchange/console integration tests, KVM selection, and snapshot-staging documentation (#2454 #2561 #2676 #2665 #2714); gate PR KVM runs on maintainer-added ok-to-test, without unrelated labels cancelling an active run (#2813).

  • Governance/docs publish the AAIF charter and DCO/CC-BY-4.0 contribution rules, clarify voting and ownership, reconcile proposal statuses, and document signing/provenance gaps (#2490 #2678 #2679 #2680 #2624 #2670 #2671 #2672 #2673 #2674 #2467).
  • Maintenance covers orphan node-agent streams, dead-code/test cleanup, single-platform Kind imports, and Linux/eBPF test setup (#2471 #2496 #2640 #2736 #2573 #2473).
  • Release preparation includes candidate version bumps, notes, and generated BOMs (#2583 #2584 #2585 #2588 #2720 #2723 #2724 #2725 #2726).

Upgrade & Compatibility

  • Managed Firecracker: deploy matching charts, runtime, and builder images; runtimeEnvironments → firecracker.firecracker.vmmDir is now supported and must reference an absolute managed-binary directory. New managed builds choose the highest installed version (currently 1.17.0); Full/RootfsOnly restores require the manifest-recorded version and fail if it is unavailable, rather than falling back to latest. Keep 1.16.1 binaries for existing artifacts without relabeling them; retaining old binaries does not guarantee downgrade compatibility for persisted Fast Sandbox state (#2795 #2812 fast-sandbox#189).
  • Request validation: remove unknown keys from closed request objects and use only one alias spelling; these now return 422. Replace ImageAuth.token/Docker-config extras with supported username/password, remove trailing newlines from names/addresses, and use only allow/deny for policy defaultAction (#2576 #2499 #2693).
  • SDK credential models: Kotlin/C# are not ABI-compatible with 1.2.0; recompile and review widened sources and nullable/typeless auth assumptions. Exchange auth contains only credential; Python inline sources reject extra keys, and generated-model users should prefer handwritten models. Use keyed Go literals for changed source/metadata models and Execution; JSON round-tripping loses Execution.Text()'s private formatting mode (#2560 #2534 #2447).
  • Proxy/ingress: migrate maintenance-only server-proxy options to ingress; legacy hostname ports must be canonical decimals in 1–65535, and --wake-park-budget must be below --wake-max-flight-lifetime (#2548 #2578 #2511).
  • Docker quotas: supplied disk/storage/ephemeral-storage limits must be positive and supported by the storage driver or creation returns 400. Only the writable layer is covered, not bind mounts, volumes, or image layers; Windows retains its existing disk-size behavior (#2716).
  • Docker preflight/startup: correct duplicate, root, colon-containing, or reserved mount destinations and quantities above signed int64; an explicit / host-path allowlist authorizes all POSIX descendants. Expiration-restore failures now prevent startup unless the container was concurrently removed; investigate persistent daemon errors (#2421 #2505 #2751 #2474 #2533).
  • Downloads: detailed APIs remain optional for custom adapters; check 206/isPartial and ranges before appending, and close response bodies. Unknown totals use -1; encoded HTTP lengths/ranges are not decoded progress or resume offsets. Python callers should catch SDK exceptions rather than raw httpx errors (#1597 #2592 #2515 #2525).
  • Timeouts and polling: Python command streams time out after max(request_timeout, 30s) without bytes; raise request_timeout for legitimate silence. MCP pollers must read logs once more after completion and retain opaque cursors; empty output is not completion. Custom Go pool stores must honor cancellation, and incomplete destruction stays fenced for retry (#2527 #2648 #2580).
  • Upload atomicity: use writable containing directories for staged uploads/isolated replacements; existing writable files fall back to non-atomic truncation on staging permission errors. Ordinary /files/replace remains in-place. Staged replacement preserves modes, not xattrs/ACLs/capabilities/SELinux labels; ownership is best effort for ordinary writes and session UID/GID for isolated writes (#2433 #2478).
  • Upload storage: hardlinks/open readers retain the old inode, multipart overwrites may need roughly three times the file size, and interrupted writers can leave staging files. Avoid reserved .osb-upload-/.osb-staging- names, especially a prefix plus 16 hex digits; rename existing collisions directly. Special-file targets are rejected, while bind-mounted/open files can prevent rename; directory sync is best effort (#2433 #2478).
  • Session lifecycle: isolated foreground stdin is now /dev/null; use files or here-documents. Bash-session deletion terminates all overlapping runs; PTY close adds SIGHUP and up to 500 ms before group kill, while nohup/HUP-ignoring jobs can survive (#2517 #2731 #2733).
  • Jupyter/JVM: custom images need an explicit token or discoverable runtime token files and the requested kernel. Prefer shaded sandbox-api 1.0.18+ over EXECD_SSE_LEGACY_COMPAT, which is off by default and removes structured exit_code values (#2448 #2689 #2472).
  • Controller configuration: cache scope must include all managed namespaces, plus Fast Sandbox template/runtime-environment namespaces; it does not change RBAC or provide tenant isolation. Review controller.podRecovery.*, which now takes effect, and remove obsolete ConfigMaps left by plain-manifest upgrades. Custom election timings require lease > renew > 1.2×retry (#2571 #2581 fast-sandbox#161 #2694 #2651).
  • Exchange deployment: align server/SDK/egress versions; the sidecar live revision runtime does not support exchange. Resolver caller authentication is not implemented—Ed25519/JWKS remains design-only. Use a protected UDS or trusted-egress-only HTTPS with trusted CAs; sandbox allow rules must not expose resolvers, and MITM UID exclusion alone is not isolation (#2501 #2549 #2631 #2547).
  • [EXPERIMENTAL] Strict Actions v2: enable matching OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion values of sandbox.fast.io/actions/v2 only on clean-base direct-Firecracker deployments with durable state, isolated management ports, and manager authorization. Pause/resume, snapshots/restore, live binding removal, owner migration, and same-UID reuse remain unsupported; use terminal deletion/new UIDs, preserve fences, and never treat fencing as authentication or downgrade existing state to v1 (#2441 #2460 #2493 #2546 fast-sandbox#152).
  • [EXPERIMENTAL] Credential-bound interception: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound still denies decrypted application forwarding and must not be enabled in production. With the switch unset, both legacy gates enabled remain a deprecated alias; revision-runtime alone is installation-only. Explicit mode/gate conflicts, empty/unknown values, and setting this switch on sidecar fail startup (#2737 #2797).
  • Experimental startup requirements: credential-bound mode requires transparent MITM, dns+nft, and only default interception ports 80,443; remove insecure TLS verification, chained proxies, and effective ignore_hosts/allow_hosts. Runtime-user config.yaml then config.yml are checked; read/parse errors fail closed. To return to all, unset both legacy gates; sidecar live revision also rejects extra interception ports (#2587 #2797).
  • Port policies: Fast Sandbox supports TCP only, at most 256 ports per rule, and no domain-plus-port combinations; normal updates preserve established flows. dropEstablished is supported only on dns+nft sidecar PATCH/DELETE, ignored by POST, and unsupported in Fast Sandbox, dns-only, live-revision, or chained-proxy-plus-transparent-MITM modes; it installs packet drops, not TCP resets. Removing a port-only allow alone does not trigger established-flow blocking (#2662 #2346).
  • Operator-rule reload: Fast Sandbox reloads runtime-mutable rule files on a one-minute tick; mount ConfigMaps as directories, not subPath, and allow for kubelet projection delay. Image-baked rules still require a new image and recreation. Successful reloads clear DNS-learned leases, so allowed domains need another lookup; failed reloads retain the previous overlay, and established connections are not forcibly terminated (#2727 #2814).
  • Network-security boundaries: domain denies filter DNS, not direct connections to known IPs; use explicit IP/CIDR denies or default-deny policies for those paths. Operator denies override operator allows, so permitted internal services require a deny-range carve-out. Classic Docker/Kubernetes creation injects egress only when networkPolicy is supplied; poolRef plus networkPolicy is unsupported, so configure pooled controls in the template (#2814).
  • ResourceAware rollout: direct-Firecracker resource-admission.json moves from v2 to v3; old/new Fastlets reject the other configuration version, so coordinate controller/Fastlet upgrades per pool. Heartbeats remain v2. Hosts require writable cgroup v2, clone3(CLONE_INTO_CGROUP), and zero effective pool swap; the shared memory ceiling is not per-VM protection or a guarantee of survival across container replacement (#2626 fast-sandbox#162).
  • Restore sizing: ResourceAware pools use template CPU/memory shapes; new snapshots replay source limits, which restore-time caller limits must match. Legacy pools and snapshots without recorded limits retain their prior behavior (#2623 #2628 #2633).
  • [EXPERIMENTAL] RootfsOnly: Full remains the default; explicit RootfsOnly mode is available through Fast Sandbox FastPath/CRDs for reusable OCI snapshots, not pause/resume or OpenSandbox REST/SDK mode selection. New capture requires qualified patched Firecracker 1.17.0 templates, a live guest helper, qualified kernel/OverlayBD backend, exclusive ext4 ownership, and an absolute FAST_SANDBOX_ROOTFS_QUALIFICATION profile with matching digests/storage attestation; custom binary digests do not bypass the version gate. Upgrade runtime, Fastlet/Proxy, builder, and tools together, rebuild qualified templates, and preserve journals/fences. Restore cold-boots and reruns the entrypoint; no application-memory preservation or validated cross-CPU/architecture portability is promised (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189).
  • OverlayBD template builds: guest-control injection and freeze/thaw validation are now mandatory for the OCI builder; FSB_GUEST_CONTROL_ENABLED is no longer an opt-out. Missing/incompatible helpers or failed probes stop the build. Native templates are unchanged; existing OCI templates need rebuilding rather than metadata edits to gain capture capability (#2812 fast-sandbox#183).
  • Fast Sandbox logs: covered Kubernetes components now write rotating files under /var/log/fast-sandbox by default (100 MiB per file, 10 backups, 7-day backup retention, gzip); application logs no longer appear in kubectl logs unless alsoStderr: true is configured. Replace legacy klog output flags with the shared logging YAML, wire ConfigMap/log-volume mounts for chart-managed static workloads, and configure each tenant namespace separately. Configuration is startup-only: use controlled Pool draining/replacement for Fastlets, not deletion of live Pods, and arrange collection before ephemeral logs are lost. Explicit missing/invalid configuration or unwritable output prevents startup; rotation limits are not a hard disk quota and do not cover guest/VM logs (#2812 fast-sandbox#197).
  • OCI checkpoint cache: reserve space for the additional blob cache (defaults: 16 GiB, 4096 files, 1 GiB free-space reserve), separately from OverlayBD's block cache. Keep staging/cache/device state on one filesystem for hard-link reuse; cross-filesystem placement or contention falls back to the registry. Set FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 to disable blob-cache insertion/lookups; active-device pins remain protected, including when budgets shrink (#2812 fast-sandbox#178).
  • ublkd recovery: automatic shared-snapfiles rebuilding applies only when no other Sandbox lease needs the attachment; it is not transparent recovery of running VMs. Remove affected Sandboxes through their normal lifecycle before retrying when other leases remain, rather than manually wiping shared caches (#2812 fast-sandbox#193).
  • Template rebuilds: opt-in runtime.execd_run_as_init needs rebuilt templates; execd remains a subreaper beneath guest PID 1. Free-page reporting also needs rebuilt object-store templates and compatible VMM/kernel support, cannot toggle restored device state, and does not enable OCI reporting or justify higher overcommit; rollback uses an older template (#2494 #2497 #2546 fast-sandbox#114).
  • OCI chart defaults: idle ublk devices are now reserved; set runtime.oci.poolLow=0 for on-demand allocation and match poolSizeGB to rounded-up rootfs capacity. P2P remains enabled by default; custom runtime.config needs separate adjustment for direct-origin delivery (#2594 fast-sandbox#163 #2566).
  • Snapshot integrity: missing commit digests now fail pause while retaining Pods; old snapshots are not repaired. OCI template references must carry a full SHA-256 digest in the expected repository; rebuild invalid references (#2482 #2491).
  • CLI scripts: non-positive request timeouts and empty rule targets are usage errors; osb config init overwrite refusal now exits 1 without changing the file (#2742 #2692 #2743).
  • VM console collection: opt in to vm-console, align hostPaths.vmConsole with the runtime state root, cover every runtime node, and manage file-sink retention (#2234 #2677).
  • Artifact verification: umbrella workflows do not provide blanket signing/provenance coverage; BOM digest matching is not proof of origin, and signature requirements must not be bypassed (#2467).
