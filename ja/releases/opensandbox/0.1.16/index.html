オープンサンドボックス python/サンドボックス/v0.1.16

新機能

✨ 特徴

  • 回復力のある HTTP トランスポート - 非同期および同期 client は、バックオフ、ジッター、Retry-After 処理、試行ごとのタイムアウト、全体の期限、および再試行コールバックを備えた構成可能な再試行トランスポートを共有するようになりました。再試行は、HTTP 429、502、および 503 の冪等リクエストに対してデフォルトで有効になっています。以前の高速フェイル動作を必要とする呼び出し元は、RetryPolicy.disabled() を使用できます。ユーザー指定のトランスポートは変更されず、ストリーミング SSE リクエストは再生をバイパスします。 #1372
  • サンドボックス ライフサイクル フック - Sandbox.create および SandboxSync.create は、安定した Python モデルとサーバー調整された検証を備えた、オプションの preStart および定期的なライフサイクル フックを受け入れるようになりました。フックのタイムアウト範囲はサーバー権限のままです。 #1588 #1605
  • 分離セッションでのバックグラウンド実行 — 分離セッションは、分離された作業を開始し、そのステータスと増分結合出力をポーリングできます。アクティブなバックグラウンド実行はアイドル状態の収集を一時停止します。読み取り専用ワークスペースは、実行ログを保持できないため、バックグラウンド実行を拒否します。 #1456
  • ランタイム割り当てと強化の可視性 — サンドボックス応答では、確認されたプール割り当ての概要を公開できますが、分離された機能には、execd init モードと強化層の状態が含まれます。これらのフィールドは追加的なものであり、サーバーが対応する状態を確認できない場合は存在しないままになります。 #1481 #1474
  • プール容量のバックプレッシャー - 互換性のあるライフサイクル サーバーは、最終的に一般的な準備タイムアウトを報告するのではなく、枯渇した Kubernetes プール容量を KUBERNETES::POOL_CAPACITY_EXHAUSTED および Retry-After の HTTP 429 として表示できるようになりました。サンドボックスの作成は非冪等のままであり、このステータスでは自動的に再生されません。 #1581

⚡ パフォーマンス

  • サンドボックスの起動の高速化 - 非同期サンドボックスの作成、接続、再開により、execd エンドポイントと出力エンドポイントが同時に解決され、2 つの管理 API ルックアップが 1 つの並列待機に減ります。障害の伝播とクリーンアップ作成のセマンティクスは変更されません。 #1531
  • 制限された並列プールのクリーンアップ - アイドル サンドボックスのリリースでは、ベストエフォートのクリーンアップと従来のパブリック動作を維持しながら、制限された同時実行性を使用します。 PR で測定された 100 サンドボックスのクリーンアップは、約 8.3 秒から 0.8 秒に減少しました。 #1475

🐛 バグ修正

  • 標準準拠の SSE 解析 - コマンドおよび分離された実行ストリームは、SSE 固有のフレーミングを使用するようになり、JSON 文字列内の Unicode 区切り文字を保持しながら、従来のベア JSON フレームとの互換性を維持します。 #1444
  • 信頼性の高いバックグラウンド コマンド完了 — バックグラウンド コマンド ストリームは execution_complete の後に停止し、最後の HTTP ターミネータの前にピアが閉じた場合の誤った RemoteProtocolError エラーを防ぎます。フォアグラウンド ストリーミングの動作は変わりません。 #1532
  • エンドポイント キャッシュ競合の修正 — 古いエンドポイント フェッチを完了しても、非同期または同期 clients での新しい代替の飛行中フェッチが削除されなくなりました。 #1567
  • さらに便利な API エラー — 非構造化 4xx および 5xx 応答本文は例外メッセージに含まれており、生の response_body バイトとして引き続き利用できます。 HTTP 429 応答は SandboxRateLimitException を使用し、解析された retry_after が存在する場合は公開します。 #1496 #1372
  • よりクリーンな準備状況診断 - 準備状況タイムアウト メッセージは、適用されない可能性がある展開固有のネットワーク修正を示唆することなく、タイミング、接続コンテキスト、および最後のヘルスチェック エラーを保持します。 #1493

📦 その他

  • ライフサイクル モデルを再生成し、パッケージのフォールバック バージョンを 0.1.16 に変更し、非同期および同期のデフォルト ユーザー エージェント文字列をリリースと調整しました。 #1622 #1623

OpenSandbox python/sandbox/v0.1.16

Highlights

  • Default retries change failure behavior — The headline change is a shared retry transport for async and sync clients: idempotent requests now automatically retry on HTTP 429/502/503 with backoff, jitter, Retry-After, per-attempt timeouts and an overall deadline (#1372). This is the one behavior change to plan around: callers that depended on fast-fail must opt out via RetryPolicy.disabled(); user-supplied transports are left alone and streaming SSE bypasses replay. Note also that HTTP 429 now raises SandboxRateLimitException with parsed retry_after instead of a generic error (#1496), so code catching the old exception type needs updating.

  • New lifecycle and background-run capabilities are additive — Sandbox.create / SandboxSync.create gain optional preStart and periodic lifecycle hooks with server-authoritative timeout ranges (#1588, #1605); isolated sessions can launch detached background work with status and incremental output polling (#1456); and sandbox responses expose additive Pool allocation, execd init mode and hardening-layer fields (#1481, #1474). These are opt-in / best-effort — absent fields simply mean the server couldn't confirm state — so no migration is required to adopt them.

  • Real performance and reliability wins for heavy users — Async create/connect/resume now resolve execd and egress endpoints in parallel, cutting two management lookups to one wait (#1531), and idle Pool cleanup is bounded-concurrency (the PR measured 100-sandbox cleanup dropping from ~8.3s to ~0.8s, #1475). Pool exhaustion also surfaces cleanly as HTTP 429 with KUBERNETES::POOL_CAPACITY_EXHAUSTED plus Retry-After rather than a generic readiness timeout (#1581); sandbox creation stays non-idempotent and is deliberately not replayed on that status.

  • Protocol and diagnostics fixes remove several sharp edges #1444 makes SSE framing standards-compliant (preserving Unicode separators in JSON strings while accepting legacy bare-JSON frames), #1532 stops background streams at execution_complete to avoid false RemoteProtocolError failures, #1567 fixes an endpoint-cache race where a stale fetch evicted a newer one, and error messages now retain unstructured response bodies as raw response_body and cleaner readiness diagnostics (#1496, #1493). Worth noting for log/test assertions: exception messages now include previously omitted response bodies.

  • Verdict: upgrade for most users; not a no-op or re-tag — This is a substantive release with new features, perf gains and fixes, plus the fallback version bump to 0.1.16 and regenerated lifecycle models/User-Agents (#1622, #1623). Upgrade if you want resilience to transient 429/502/503, faster startup/cleanup, background runs or hooks, or if you're hitting the SSE/cache bugs. You can reasonably skip if you require strict fast-fail semantics and catch the old generic 429 exception type and cannot yet adopt RetryPolicy.disabled() / the new SandboxRateLimitException.

What's New

✨ Features

  • Resilient HTTP transport — Async and sync clients now share a configurable retry transport with backoff, jitter, Retry-After handling, per-attempt timeouts, an overall deadline, and retry callbacks. Retries are enabled by default for idempotent requests on HTTP 429, 502, and 503; callers that require the previous fast-fail behavior can use RetryPolicy.disabled(). User-supplied transports remain untouched, and streaming SSE requests bypass replay. #1372
  • Sandbox lifecycle hooks — Sandbox.create and SandboxSync.create now accept optional preStart and periodic lifecycle hooks, with stable Python models and server-aligned validation. Hook timeout ranges remain server-authoritative. #1588 #1605
  • Background runs in isolated sessions — Isolated sessions can start detached work and poll its status and incremental combined output. Active background runs suspend idle collection; read-only workspaces reject background execution because they cannot persist run logs. #1456
  • Runtime allocation and hardening visibility — Sandbox responses can expose confirmed Pool allocation summaries, while isolated capabilities include execd init mode and hardening-layer state. These fields are additive and remain absent when the server cannot confirm the corresponding state. #1481 #1474
  • Pool capacity back-pressure — Compatible lifecycle servers can now surface exhausted Kubernetes Pool capacity as HTTP 429 with KUBERNETES::POOL_CAPACITY_EXHAUSTED and Retry-After, instead of eventually reporting a generic readiness timeout. Sandbox creation remains non-idempotent and is not automatically replayed on this status. #1581

⚡ Performance

  • Faster sandbox startup — Async sandbox creation, connection, and resume resolve execd and egress endpoints concurrently, reducing the two management API lookups to one parallel wait. Failure propagation and create cleanup semantics remain unchanged. #1531
  • Bounded parallel Pool cleanup — Idle sandbox release uses bounded concurrency while preserving best-effort cleanup and legacy public behavior. The measured 100-sandbox cleanup in the PR dropped from about 8.3 seconds to 0.8 seconds. #1475

🐛 Bug Fixes

  • Standards-compliant SSE parsing — Command and isolated execution streams now use SSE-specific framing, preserving Unicode separators inside JSON strings while remaining compatible with legacy bare-JSON frames. #1444
  • Reliable background command completion — Background command streams stop after execution_complete, preventing false RemoteProtocolError failures when the peer closes before the final HTTP terminator. Foreground streaming behavior is unchanged. #1532
  • Endpoint cache race fix — Completing an older endpoint fetch no longer removes a newer replacement inflight fetch in async or sync clients. #1567
  • More useful API errors — Unstructured 4xx and 5xx response bodies are included in exception messages and remain available as raw response_body bytes. HTTP 429 responses use SandboxRateLimitException and expose parsed retry_after when present. #1496 #1372
  • Cleaner readiness diagnostics — Readiness timeout messages retain timing, connection context, and the last health-check error without suggesting deployment-specific network fixes that may not apply. #1493

📦 Misc

  • Regenerated lifecycle models, bumped the package fallback version to 0.1.16, and aligned async and sync default User-Agent strings with the release. #1622 #1623
