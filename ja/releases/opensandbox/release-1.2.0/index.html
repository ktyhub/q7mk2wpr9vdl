OpenSandbox リリース - 1.2.0

1.2.0 ラインの安定したカット。release-1.1.1 以降、2 つのリリース候補と RC 硬化後のデルタを介してマージされたすべてが含まれています。イメージは RCS に同梱されています。 SDK/CLI/サーバー パッケージは 1.2.0 で公開されます。 1.1.x の全員がアップグレードする必要があります。以下の各セクションのベースライン: release-1.1.1。

ハイライト

  • 高速サンドボックスの自動一時停止とアクセス時のウェイクアップ (OSEP-0024) はエンドツーエンドで実現します。イングレスはアクティビティを記録し、復元が完了するまで一時停止したサンドボックスへのリクエストをパークします。サーバーはオプトイン lifecycle.idlePolicy 作成フィールドの背後でアイドル スイーパーを実行し、5 台すべての SDK がウェイク リトライ コントラクトを取得します。デフォルトではオフ、追加のみ (#2156) #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) は高速サンドボックス用にエンドツーエンドで着陸します。出力側サイドカーは、耐久性のあるサブジェクトごとの永続性と密閉された一時停止/再開転送を備えたボールトを保持します。サーバーは、公開読み取りには決して表示されない資格情報値を持つユーザーが到達可能なボールト API を公開します。MITM CA はプールごとに固定されているため、出力の再起動によって trust アンカーがライブで回転することはなくなります。サンドボックス - クラシック プロファイルのエンドツーエンドのポート スコープの出力ルール (#2249 #2252 #2255 #2263 #2251 #2212)
  • 高速サンドボックス スナップショットとテンプレート ビルドは、OCI レジストリ (OverlayBD OCI ライフサイクル) に公開して起動できます。また、信頼性キャンペーンにより、5 つの言語すべてで SDK ファイル転送から呼び出し全体のタイムアウトが削除され、execd がサンドボックス スコープの CPU/メモリと OOM キルをレポートし、Docker バックエンドの正確性と PTY/セッション出力の問題の長いリストが修正されます。 (#2338 #2165 #2200 #2191)

サーバー

  • 高速サンドボックス用に OSEP-0024 自動一時停止のサーバー側を実装します。lifecycle.idlePolicy 作成フィールド (idleTimeoutSeconds 30–86400、onIdle: pause、wakeOnAccess、オプションの activeProbe) は、予約されたサンドボックス CR アノテーションとして保持されます。アイドル スイーパーは、オプトインされた FSB サンドボックスを列挙し、Redis でアクティビティをチェックし、サンドボックスごとの一時停止ロックを取得し、べき等 FastPath PauseSandbox を発行します。宣言された activeProbe はイングレス ゲートウェイを介して実行され、OpenSandbox-Skip-Activity センチネルは 1 つの観測を抑制し、ゲートウェイ ホップとプロキシ ホップの両方で削除されます。構成は [automation.idle_pause] の下に移動し、スイーパーが有効になっている場合、ロード時に redis.dsn が検証されます (#2192 #2181 #2215)
  • Credential Vault API (OSEP-0022、高速サンドボックス プロファイル) の実装: POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault は、完全な Vault リビジョンを FastPath ハンドラー リレー経由でプッシュし、リレー応答を同期出力検証済み ACK として扱います。CRD は Vault マテリアルを伝送することはなく、すべてのパブリック読み取りはサーバー側でサニタイズされます。 PATCH はクロスレプリカ バックストップとして expectedRevision を使用してメモリ内に構成され、非 fsb バックエンドがサイドカーの /credential-vault サーフェスをプロキシし、fsb credentialProxy 作成時の拒否が解除されます (#2263)
  • 固定された MITM CA をサーバー作成の SandboxTemplate にベイクします (OSEP-0022): 新しい [kubernetes] template_mitm_ca_secret 構成 (デフォルトはオフ) は、すべてのテンプレートで spec.egressMitmCertificate (証明書エントリのみで、秘密キーは生成されません) を発行します。 Secret は各テンプレート名前空間 (ops-runbook 配布) に存在する必要があり、コピーが欠落していると明らかにビルドに失敗します (#2288)
  • lifecycle.renewalPolicy (OSEP-0009) の追加: アクセス時更新オプトインは、不透明な extensions["access.renew.extend.seconds"] キーから構造化された renewalPolicy.extendSeconds (300–86400) に移動します。従来のキーは非推奨になり (1.x 全体でサポートされ、2.0 で削除されました)、高速サンドボックスは no-op を黙って受け入れるのではなく、400 で拒否します (#2296)
  • 診断コンテキスト エンドポイントを実装します (#2236 の仕様): GET /v1/sandboxes/{sandboxId}/diagnostics/context は、execd に接続せずに、Docker、Kubernetes、および高速サンドボックスのサンドボックス ID、ライフサイクル状態、バックエンド タイプ、およびバックエンド定義の識別子を返します — Kubernetes コンテキストは、ポッドが割り当てられる前に使用可能なままです。これを実装していない拡張機能バックエンドは 501 を返します (#2292)
  • エンコードされたままのパスをサンドボックス プロキシ経由で転送します。スターレットは、パーセント デコードされたパスから {full_path:path} ルートをバインドしたため、デコードされた ? がクエリを開始し、%2F がセパレータになり、%2E%2E セグメントが解決されました。つまり、Docker ホスト マップ エンドポイントのプレフィックス エスケープが閉じられました。プロキシは、client のまだエンコードされた末尾を生のパスから取得し (ルーティングされたパスにデコードされることを検証)、生のクエリ文字列からクエリを読み取るようになりました。そのため、バックエンドは、イングレス ゲートウェイと一致するリクエスト ターゲットをバイト単位で受信します (#2228)。
  • イベント ループからの Docker 呼び出しをブロックし続ける: プロキシ エンドポイント ルックアップ、ネットワーク存在検証、および PVC ボリュームごとの検査/作成が非同期ハンドラー内で同期的に実行されるため、低速な Docker デーモン (大規模なプル中など) がプロキシ トラフィックを含む他のすべてのリクエストをフリーズしました。これらはテナント コンテキストが保持されたワーカー スレッドで実行されるようになり、ボリューム検証の失敗によっても自動作成されたボリュームがクリーンアップされます (#2268 #2366)
  • Docker のサンドボックス状態としてイメージ継承ラベルのレポートを停止: メタデータの読み取りは、イメージからマージされたラベルを含むすべての予約されていないコンテナー ラベルにフォールバックされ、復元されたコンテナーは expires-at、ホスト ポート、出力トークンなどの予約済みラベルを継承します。最悪の場合、復元された TTL サンドボックスは、サーバーの再起動後にすでに期限切れとして削除されていました。 Create はリクエストのメタデータ キーを予約ラベルに記録し、それらのキーのみを読み取るようになりました。イメージ上に存在するがサンドボックスによって設定されていない予約ラベルは、コンテナーの開始前に空白になります (#2363 #2269)
  • 書き込みをサイレントにドロップする gVisor スナップショットを拒否します。gVisor のデフォルト --overlay2=root:self の docker commit は、サンドボックスの書き込みをまったく復元せずに READY を報告する可能性があります。有効な引数に --overlay2=none が含まれていない限り、スナップショットのプリフライトは gVisor を拒否するようになり、ファイルシステムの差分がファイルストアのみの場合は作成が失敗して閉じられます (#2241)
  • 作成応答が失われた fsb スナップショットを保持します。リクエストが永続的に受け入れられた後の FastPath からの UNAVAILABLE/DEADLINE_EXCEEDED は、行を書き込まずに 500 を返し、SandboxSnapshot とその公開されたアーティファクトをレコードなしで取り残しました。今すぐ作成は失敗する前にスナップショットをプローブし、FastPath が永続化したときにスナップショットを送信済みとして報告します (#2361)
  • 残りの Docker バックエンドの粗いエッジを修正: BatchSandbox の有効期限レポートでは、spec.expireTime を過ぎた Running ではなく Terminated/SANDBOX_EXPIRED が報告されます (#2238)。同時ライフサイクルの競合は 500 ではなく 404/409 にマップされます (#2387)。同時メタデータ パッチが 500 秒に達したり、キーが削除されたりすることはなくなりました (#2267 #2281)。 createdAt は読み取り全体にわたって安定しており、一時停止/再開の遷移が記録されます (#2405)。ネットワーク ポリシー アクションが検証され、不明なフィールドは 422 (#2383 #2385) を返します。サンドボックス イメージはコンテナー構成から読み取られるため、docker rmi -f で指定されたイメージは 500 番台の GET /sandboxes (#2353) ではなくなります。テンプレートは、ゲート作成チェックごとに CR を同期する代わりに、データベース プロジェクション trust を読み取ります (#2326)。 Redis コンシューマーが有効になっている場合、更新クールダウンはすべての更新ソースに適用されます (#2276 #2279)。 BatchSandbox ポッドのデフォルトは restartPolicy: Never なので、kubelet の再起動で Succeed (#2128) を報告している間は書き込み可能レイヤーをワイプできなくなります。 podman の pasta/slirp4netns/none ネットワーク モードはパススルーします (接続するブリッジがないため、networkPolicy は拒否されます) (#2203)。異常な小数秒を含む Docker タイムスタンプは、現在時刻を通知せずに報告しなくなりました (#2220)。また、execd キャッシュ コンテナーは [docker] セキュリティ プロファイルと secure_runtime (#2254) を尊重します。

SDKs

以下のコード変更は 1.2.0 パッケージを利用します。

  • OSEP-0024 SDK コントラクトを 5 つの言語すべてに追加します: client 側フェイルファスト検証を含む型付き lifecycle.idlePolicy 作成フィールド、およびウェイク リトライ コントラクト - ゲートウェイ所有の OpenSandbox-Wake: expired マーカー (その存在は、リクエストがパークされ転送されなかったことを証明し、どのメソッドでも再試行が安全になります) を運ぶ 503 上で、SDK制限された予算 (デフォルトは 5 回の試行/60 秒、client ノブごと) の下で Retry-After の後に再送信し、使い果たすと型付きウェイク タイムアウト例外が発生します。裸の 503 の処理は変更されていません (#2198 #2218)。この契約は当初、ストリーミング トランスポートをバイパスしていました。ストリームを開始するリクエストは、JavaScript、Python、Go でウェイク再試行されるようになりました。確立されたストリームは決して再試行されません。一方、C#/Kotlin ストリームの開始は現在フェイルファストです (#2357 #2426)
  • Credential Vault client コントラクトを 5 台すべての SDK (OSEP-0022) に追加します。テンプレートに基づくサンドボックスは、ネットワーク ポリシーと同じテンプレート発信元の信号でサーバー経由で Vault 呼び出しをルーティングしますが、サイドカー ダイレクト アダプターは影響を受けません (#2263)。
  • 5 台すべての SDK で、リクエスト タイムアウト (デフォルトは 30 秒) でファイルのアップロードとダウンロードの上限を停止します。呼び出し全体のタイムアウトには本文の送信と応答の読み取りが含まれていたため、大規模または低速の転送は、正常であっても飛行中に失敗しました。転送は専用の client で実行されるようになり、応答ヘッダーの待機を制限する呼び出し全体の期限は設定されないため、停止した転送はハングせずに引き続き失敗します (#2165 #2186 #2196 #2206)
  • SDK サーフェス全体に診断を実装します (#2292 を使用): context はマネージャーとサンドボックス ファサードの両方を通じて 5 つの言語すべてで公開され、JavaScript、Go、および C# は既存の Python/JVM サーフェスと一致するパブリック ログ/イベント API を取得します。 (#2292)
  • lifecycle.renewalPolicy を 5 つすべての SDK (OSEP-0009) に追加します: client 側のフェイルファスト検証 (extendSeconds 300–86400) を備えた型指定された作成フィールドで、不透明な拡張キー (#2296) を置き換えます。
  • 5 つの SDK すべてでポート スコープの出力ルールをサポート: NetworkRule.ports (TCP 1 ～ 65535、ルールごとに最大 256、target はオプションになりました)、サーバーをミラーリングする client 側検証 (範囲、重複、上限、ドメイン + ポートが拒否)。 JavaScript は、ターゲットまたはポートの不変式を共用体型としてエンコードします (#2212)
  • Go および Kotlin で権威のある execution_complete.exit_code を表示し、古いサーバーとの互換性を維持しながら、以前の evalue/inferred-0 フォールバックよりも優先します (#2330)。 JavaScript、C#、Kotlin のヘッダー名の大文字と小文字に関係なく、構成されたキーに対して明示的に指定された OPEN-SANDBOX-API-KEY ヘッダーを尊重します (#2348 #2372 #2375)。 Go、Python、および JavaScript で作成される client-pool ウォームアップの sandbox.create メトリクスを抑制します (#2199)
  • JavaScript、C#、および Go のクロスオリジン リダイレクトで保護された資格情報を削除します。サンドボックス プレフィックス付きヘッダー、エンドポイント トークン (X-EXECD-ACCESS-TOKEN、X-API-Key)、および構成された認証ヘッダーは、リダイレクトによってスキーム/ホスト/ポートが変更されるたびに削除されますが、同一オリジン ホップと関連のないヘッダーは保持されます。ファイルのアップロードは JavaScript のリダイレクトに従うことはなく、ブラウザーでは、不透明なリダイレクトは資格情報を再実行する危険を冒さずに失敗して閉じられます (#2178 #2173 #2183)
  • 共有ポリシーを介して JavaScript および C# コード インタープリター データ プレーン ヘッダーをルーティングします。ダイレクト モード /code リクエストは、execd にテナント OPEN-SANDBOX-API-KEY を送信しなくなり、明示的に構成された接続キーは、大文字と小文字が異なるエントリが重複することなく、構成された apiKey よりも優先され、エンドポイント スコープの資格情報が依然として優先されます (#2149)

Python

  • ストリームの開始時にゲートウェイのウェイク タイムアウトを再試行します。SSE clients は再試行ラッパーを完全に削除したため、commands.run、セッションが実行され、自動一時停止されたサンドボックスに対する codes.run は、復元がゲートウェイのパーク バジェットを超えるたびにマークされた 503 で失敗しました。ストリーミング トランスポートではウェイクのみの再試行が行われるようになり (一般的な再試行や期限の追加はありません)、ドキュメントではストリームが再試行をバイパスすると主張しなくなりました (#2357)
  • 接続ドメインを正規化します。domain / OPEN_SANDBOX_DOMAIN の末尾のスラッシュまたは /v1 により、サーバーが 404 した //v1/... URL が生成されました。同じ変数が他のすべての SDK で機能しました。 Python は両方を削除するようになりました (#2347)
  • 所有するトランスポート全体で SSL コンテキストを再利用: CA 証明書は呼び出しごとに再ロードされ、非同期同時実行下でのイベント ループをブロックしました - 測定された作成 P50 は同時実行下で最大 18 ～ 28% 向上しました (#2360)
  • UTF-8 BOM の後の最初の SSE イベントを保存します (ネットワーク チャンクにわたる 1 つの分割を含む) (#2226)。キャンセル時にウェイクタイムアウト応答ボディを閉じる (#2371);中断された非同期ファイル ダウンロード応答を閉じて、キャンセルまたは失敗した読み取りが接続を占有しないようにします (#2369)。エラー応答に JSON 以外の本文が含まれる場合、ステータス コードを保持します。プロキシの HTML/空の 404/500 は、以前はステータスのない InvalidArgumentException として表示されていました (#2402)。 retry_after を失った手動例外 (#2364) の代わりに、コード インタプリタ codes.run の失敗から共有構造化エラーを発生させます。余分な改行を挿入する代わりに、コードインタープリターの出力フラグメントを Execution.text にまとめて保持します (#2408)。ミリ秒未満のコマンド タイムアウトを、0 (タイムアウトを無効にする) を送信する代わりに、最大 1 ミリ秒に丸めます (#2419);キャンセルされたエンドポイントフェッチの同時待機者への伝播を停止します (#2277)。サンドボックス プールを介して credential_proxy を転送します。これは、以前にサイレントにドロップされました (#2283)。失敗したファイル置換を成功として報告するのをやめます (#2222)。 STARTING (#2209) でスタックする代わりに、非同期プールの起動をクリーンアップしてキャンセルしました。ライフサイクル client を再生成して、古いハードコードされたデフォルトを削除します (ワイヤの動作は変更されません) (#2280); MCP: 1 つのツール呼び出しをキャンセルしても、他の待機中の呼び出しがすべて失敗した同じサンドボックスの合体共有接続がキャンセルされなくなりました (#2355)

JavaScript

  • CR 行末を持つ実行イベントを保持: SSE パーサーは LF でのみ分割するため、有効な CR で区切られたストリームは実行 ID、出力、および完了イベントをサイレントにドロップしました (#2374)
  • 実行中のエンドポイント キャッシュの無効化の範囲を各サンドボックスに設定したため、サンドボックス B を無効にしても、サンドボックス A の保留中のフェッチ結果が破棄されなくなりました (#2349)
  • ファイルアップロードで再利用されたバイトチャンクを保持: Uint8Array/Buffer ビューを再利用する非同期プロデューサーは、両方のスナップショットではなく、変更されたコンテンツを 2 回アップロードしました (#2428)。応答ヘッダーが到着した後も呼び出し元のキャンセルをアクティブにしておく — SSE ストリーム中またはダウンロード中に中止すると、以前は本体が実行されたままになっていました (#2350)
  • クロスオリジン リダイレクトで保護されたヘッダーを削除します (上記のクロス SDK エントリを参照) (#2173)

コトリン

  • どのような場合でも、設定されたキーの前に明示的な API キー ヘッダーを保持し、未設定の場合は空のキー ヘッダーの添付を停止します (#2375)
  • 逆シリアル化の失敗時に生の応答本文を保持し、シリアライザー/ランタイムの不一致から LinkageError をキャッチします。以前は、AbstractMethodError がすべてのハンドラーをエスケープし、サーバーの実際の応答が回復不能な状態で SSE ストリームをサイレントに強制終了していました (#2416)

C#

  • 大文字と小文字に関係なく、明示的な API キー ヘッダーを尊重します。大文字と小文字を区別するチェックにより、競合する 2 番目のデフォルト エントリが追加され、メトリック レポーターが呼び出し元の資格情報を置き換えました (#2372)
  • クロスオリジン リダイレクトで保護された資格情報を削除し、共有データ プレーン ヘッダー ポリシーを通じてコード インタプリタ リクエストをルーティングします (上記のクロス SDK エントリを参照) (#2183 #2149)

行きます

  • デフォルトで非冪等書き込みの再試行を停止します。再試行が有効になっていると、27 の POST/PATCH 呼び出しサイト (サンドボックス/セッション/コマンド/ファイル/スナップショット/ボールトの変更) が 2 回実行されても成功を返す可能性があります。POST/PATCH はデフォルトでステータス コードを再試行しなくなり、送信前であることが証明されたトランスポートの失敗のみを再試行し (リクエスト バイトの前にダイヤル/CONNECT/TLS を実行)、SSE ブートストラップは一般的な再試行をバイパスします。ループ。重複実行のリスクを受け入れる発信者は、RetryConfig.RetryableStatusCodesNonIdempotent (#2342) 経由でオプトインできます。
  • SSE ストリームの開始時にゲートウェイのウェイク タイムアウトを再試行します。以前は、6 つのストリーミング呼び出しサイト (コマンド/コード/セッションの実行、メトリクスの監視) が、マーク 503 ですぐに失敗しました。ブートストラップは同じ Retry-After バジェット内にパークし、枯渇すると型指定されたウェイク タイムアウト エラーを返します。確立されたストリームは決して再生されず、書き込みステータス オプトインがあっても裸の 503 は再試行されません。また、リダイレクト チェーンを通じて到達した 503 はウェイクの出所を失うため、すでに実行されたリクエストは再送信されません。フェールファストに依存する呼び出し元は WakeRetryDisabled() (#2426) を渡すことができます
  • Execution.Text() に行終端文字を保持します: execd にはすでにイベント テキストに \n/\r が含まれており、標準出力を再構築するために連結が必要ですが、ヘルパーは終了したイベントの間に余分な改行を挿入しました ("a\n" + "b\n" は "a\n\nb\n" になりました)。前のイベントがまだターミネータで終わっていない場合にのみセパレータが追加されるようになりました (#2381)
  • ダイレクト モード データ プレーン リクエストからテナント API キーを削除します。ConnectionConfig.Headers を通じて提供されたテナント キーが、untrusted サンドボックス内の execd および出力サイドカーに配信されました。これにより、5 つの SDK すべてにわたる認証情報公開の修正が完了しました (#2337)。
  • テナント キーをサンドボックスに密輸するのではなく、API キー ヘッダーを使用してプロキシされたデータ プレーン リクエストを認証し、マルチテナント プロキシ モードでの 401 を修正します (#2274)。表面 execution_complete.exit_code (#2330)

実行

  • サンドボックスを対象とした CPU/メモリ メトリクスと OOM キルのレポート: GET /metrics はコンテナ内のホストの /proc を読み取るため、ダッシュボードにはホスト全体の数値が表示されます。制限が設定されている場合 (ホスト ビューは無制限のゲストに対して保持されます)、使用量はサンドボックス独自の cgroup から取得されるようになり、cgroupfs ポーラーはカーネル OOM Kill カウンタを 5 秒ごとに比較して、構造化された警告ログを含む execd.system.oom.kills をエクスポートします。機能は必要ありません (#2200 #2191)
  • ファイル API を通じてセッション プライベート /tmp を提供します。厳密な分離プロファイルの /tmp はホスト側パスのない匿名 tmpfs であったため、/tmp の下のファイル API パスが失敗し、呼び出し元は Base64 シェル コマンドを介してアーティファクトをシャトルする必要がありました。 /tmp は、名前空間にバインドマウントされたホストベースのセッションごとのディレクトリになりました。同じプライベート セマンティクスですが、既存のファイル エンドポイントを介して読み取りと書き込みが可能です (#2424)
  • ブラウザ PTY WebSocket 認証のサポート: ブラウザはネイティブ WebSocket ハンドシェイクで X-EXECD-ACCESS-TOKEN を設定できないため、端末接続には BFF リレーが必要でした。 PTY アップグレードは、opensandbox-pty サブプロトコルの資格情報エントリ (Kubernetes スタイル) を介して既存の exec トークンを受け入れるようになりました。新しいトークン発行者とヘッダーの優先順位は SDK/CLI clients に対して保持されません (#2334)
  • フォアグラウンド実行がキャンセルまたは切断されたときに、分離されたセッションを維持します。実行のコンテキストは HTTP リクエストから派生するため、切断または timeout_seconds の有効期限が永続セッション シェルを含むプロセス グループ全体に SIGINT されます。セッションは終了し、その後の実行はすべて 404 になります。セッションが存続している間、実行中のコマンドのみが中断されるようになり (制限付き SIGKILL エスカレーションを使用)、サイレント フォアグラウンド実行は定期的な SSE ping を発行するため、ゲートウェイのアイドル タイムアウトによってストリームが閉じられなくなりました (#2351)
  • bash セッションの出力行末を保持: run_in_session stdout イベントにより \n/\r バイトが削除されるため、空白行は回復できず、イベントを連結しても出力が再構築されません。イベント テキストには元の行末が付けられるようになりました。コンシューマーは実行ごとにイベント テキストを連結する必要があります (#2318)
  • カーネルが停止するか接続が切断されると、Jupyter の実行を終了します。どちらの場合も、以前はコード インタプリタ リクエストを無期限に開いたままにし、SSE ping でリクエストを存続させていました。実行 (KernelDied / KernelConnectionLost) が 1 回だけ失敗するようになりました (#2401)
  • 16 MiB を超える行を超えてセッション出力を読み取り続けます。読み取りループは上限で停止しました。bash セッションは 24 時間のデフォルトのタイムアウトまでハングし、分離されたセッションは出力を次の実行に漏洩しました。長すぎる行は分割して渡されるようになりました (UTF-8 を分割することはありません) (#2275)
  • 大きなバックグラウンド コードを分離セッションで実行します。ラッパーは単一の bash -c 引数としてコードを渡し、Linux は 1 つの exec 引数を 128 KiB に制限します。これを超えるバックグラウンド コードは Argument list too long のみで失敗します。フォアグラウンド パス (#2400) と同様に、標準入力を介して配信されるようになりました。プライベート ネットワーク機能をプローブするため、制限されたランタイムは不透明な EOF ではなく share_net=false セッションの構造化エラーを取得します (#2333)
  • 小さな修正: コマンドの完了とエラーに関して exit_code を明示的にレポートする (#2303 #2316)。ストリーム開始後に、Python SDK がドロップした裸の JSON 本体ではなく、フレーム化された SSE error イベントとして実行エラーを送信します (#2354)。シェルの終了時に空になるまで PTY 出力をバッファーに保持するため、出力の最後の画面が失われることがなくなりました (#2362)。書き込み中であっても、PTY テイクオーバー時に常に WSCloseTakenOver (4001) クローズ フレームを送信します (#2376 #2378)。出力を読み取りながら分離された実行のスクリプトを作成することで、おしゃべりな実行によって stdin/stdout パイプでデッドロックが発生しなくなります (#2399)。間違ったファイルを黙って操作するのではなく、セッション ファイル ビューでスコープ外の絶対パスを拒否します (#2322)。分離セッション ファイル API (#2299) を通じて binds マウント ポイントを提供します。リンクを解除する前にコマンド出力ファイルを切り捨てることで、fd を保持するデーモンが目に見えないディスクの増大を引き起こすことがなくなります (#2295)。無効な上限使用量メトリックを省略し、スキャン エラーでクローズされたクォータ受付を失敗します (#2257)。共有 trust ストア全体にわたる JDK MITM CA インポートの重複排除 (4 つの JDK の ~6.2 s → ~0.6 s) (#2310);設定されていない場合、デフォルトの PTY セッションは TERM=xterm-256color になります (#2313); Content-Disposition ファイル名の引用符とバックスラッシュをパーセント エンコードします (#2161)。ダウンロード ヘッダーを設定する前に Range ヘッダーを解析して、不正な範囲がクリーンな JSON 416 (#2216) を返すようにします。

出口

OSEP-0022 ボールト アイテムは、fast-sandbox プロファイルの資格情報ボールト サーフェスに関係します。 OSEP-0023 項目は、デフォルトでオフになっている実験的リビジョン ランタイムにスコープされたままです。

  • 高速サンドボックス用の出力保持ボールト (OSEP-0022) を追加し、段階的にランディングします: 作成専用 POST (重複で 409、サーバー レプリカ全体でアトミック) を使用した内部 /vault/{sandboxUid} リレー サーフェス、expectedRevision と expectedIncarnation 前提条件を使用したフルリビジョン PUT により、古いライターがリセットの後続プログラム、値を含む GET、およびポリシーを維持する DELETE にランディングすることはありません。 (#2249);永続的なサブジェクトごとの永続性 - ポッド スコープのボリューム (オプションの tmpfs) の下にサブジェクトごとに 1 つのファイル、ポリシー ファイルと同じコミット プロトコル、acked は永続的で適用されることを意味、インカネーション フェンスされたリロード、バインド解除時のパージ (#2252);置き換えられた fastlet-proxy vault ルートが削除されました (#2247)
  • 一時停止/再開をまたいでボールトを実行する (OSEP-0022「ボールトのライフサイクル」): VAULT_EXPORT は、実行時ティアダウンの前に厳密にボールト ファイルをスナップショット バンドルにコピーし、サブジェクトをシールします (一時停止中、すべてのボールト操作は 409 と応答します。強制は継続します)。VAULT_IMPORT が唯一の承認されたインカネーション転送です。本物のエクスポートの失敗は一時停止チェックポイントに失敗するため、バンドルなしではティアダウンは実行されません。機能シグナルにより、ボールト永続性のない出力は失敗する代わりに転送をスキップします (#2255 #2290)
  • 高速サンドボックス MITM CA の固定 (OSEP-0022): プールに固定され、バージョン管理された CA は、読み取り専用シークレット マウントから mitmdump confdir にシードされ、generate-on-start に置き換えられます。出力再起動によって CA がローテーションされなくなり、すべてのライブ サンドボックスの TLS trust がサイレントに無効化されます。欠落または不一致の CA は、/healthz (#2251) で浮上した mitmCaFingerprint / mitmCaDown を含む MITM アドオンのみを拒否します。
  • スロット再利用時の古いサブジェクトのテイクオーバーを定義します。高速サンドボックスのディスパッチ キーはスロット IP であり、スロットは再利用されるため、SET_BINDING は、デッドだが登録されているサブジェクトがまだ保持しているキーを要求できます。出力はそれを権限のあるものとして扱い、後続の拒否優先サブジェクトを登録する前に、古いサブジェクトの NFT ルール、DNS refcount、MITM リダイレクト、およびボールト スライスを破棄します。 (#2250)
  • 高速サンドボックス ネットワーク ポリシーをボールト パターンに合わせます。記録されたポリシーは出力保留状態になります。リビジョン前提条件を備えた /policy/{sandboxUid} リレー サーフェス、耐久性のあるサブジェクトごとのファイル、POLICY_EXPORT/POLICY_IMPORT スナップショット転送、および出力再起動後、コミットされたファイルが再生された作成時バインディング入力を置き換えます (#2309)。
  • ポート スコープの出力ルールをエンドツーエンドでサポート (クラシック プロファイル): NetworkRule.ports (TCP 1 ～ 65535、ルールあたり ≤256) により、target がオプションになります — ポートのみのルール、または IP/CIDR と組み合わせられたポート。ドメイン ルールは DNS プロキシ層で評価されるため、domain+ports は拒否されます。オペレーターが提供する reachable.ports.cap ホワイトリストは、すべてのユーザー ルールに先立って常に拒否として強制されるため、defaultAction: allow でさえホワイトリストに登録されていないポートを開くことができず、高速サンドボックス ルートは、fastlet NFT パスがそれらを強制できるまで 400 で ports を拒否します (フェールクローズ、文書化) (#2212)
  • MITM リダイレクト ターゲットをポート スコープ ルールから除外します。オペレータ ポート フロアとトランスペアレント MITM の両方がアクティブな場合、インターセプトされたすべてのフローは静かにブラックホール化されました。フィルタ チェーンが実行される前に、iptables REDIRECT が dport 80/443 をローカル リスナーに書き換えたため、フロア補数のドロップによって書き換えられたポートが判断されました。リスナー タプルは、すべてのポート スコープのルールより先に受け入れられるようになり、新しい到達可能性は追加されません。また、ホワイトリストに登録されていないインターセプト ポートは、サイレントに渡すのではなく、プロキシで目に見えて失敗するようになりました (#2435)
  • OSEP-0023 実験基盤 [実験] を境界線全体で継続します: リクエストごとのローテーションによるライブ資格情報限定 Vault アドミッション (#2176)、公開前の確認済みポリシー リビジョン (#2182)、制限付きドレインによる HTTP/2 アドミッション (#2201)、ランタイム フォールト予期しない MITM 出口の封じ込め (#2172)、アトミック リビジョン ポリシー ファイルの永続性 (#2162)、nft 適用効果分類 (#2167)、競合するネイティブ リストに対する起動拒否を備えた静的 TLS パススルー セレクター (#2229)、TLS アドミッション カウンタ(#2265)、インストール専用のサブジェクト リビジョン IPC 基盤 (#2284)、および v2 ライフサイクル コンシューマに先立って統合された高速サンドボックス サブジェクトの移行 (#2294)

イングレス

  • OSEP-0024 アクティビティ追跡とウェイクオンアクセスを実装します。--activity-enabled を使用すると、ルーティングされたすべてのリクエストが単調なアクティビティ タイムスタンプを Redis に記録します。ファイア アンド フォーゲットであり、ホット パス上には存在しません。 --wake-enabled では、一時停止された高速サンドボックスにルーティングされたリクエストは、503 で応答される代わりに保留されます。チェックポイントで囲まれたシングルフライト、境界付き駐車場、および再現可能な本体を持つ冪等メソッドに制限された古いルート再生の下で、サンドボックスごとにレプリカごとに 1 つの ResumeSandbox が使用されます。 wake-timeout 応答には、OSEP 定義のマーカー (503 + Retry-After: 1 + OpenSandbox-Wake: expired) が含まれており、サンドボックスが来歴を偽造できないように、すべての上流応答から削除されます。両方のフラグが設定されていない場合、動作は以前とバイト同一です (#2156 #2180)

高速サンドボックス

  • スナップショットとテンプレート ビルドを OCI レジストリに公開: 各 OverlayBD ビルドは OCI レジストリ (rootfs および snapfiles イメージ、名前インデックスなし - サンドボックスは status.manifestRef から起動) をターゲットにできます。Fastlet はデフォルトで明示的なオプトアウトで OCI を有効にし、OverlayBD テンプレートには OCI ストレージが必要です。コントローラーはスナップショット アーティファクトのクリーンアップを統合し、ランタイム削除後に Fastlet の容量を更新します。マニフェスト キャッシュは Fastlet の置き換えでも存続します。 SandboxSnapshot CRD は oci:// マニフェスト参照を取得し、OCI スナップショットの spec.templateName をオプションにします (#2338)
  • 固定スロットではなくリソースごとにプール サンドボックスを配置します。spec.sandboxResources は、別の CPU/メモリ overcommitRatio (ResourceAware モードで必要) を使用して mode (LegacySlot | ResourceAware) を取得します。 cpu/memory 制限は、ResourceAware プールがリクエストごとに上書きできる実行時制限/デフォルトになり、サンドボックス ステータスは呼び出し元所有の不変 resources.limits (ResourceAware プールのみ) を取得し、プール ステータスはリソース コミットメントとファストレット/サンドボックス カウンターをレポートします (#2442)
  • サンドボックスの削除を信頼できるものにします。削除では、ランタイム不在チェックの前にフェンスで囲まれた Fastlet 削除が送信されるようになりました。そのため、トランスポートの失敗や空の検査応答は、サンドボックスがなくなった証拠として扱われなくなりました (CR が失われている間に microVM が孤立する可能性があります)。 Fastlet は ID ごとのトゥームストーンを記録するため、作成を遅らせても削除されたサンドボックスを復活させることはできません。プレースメントの作成もより速く回復します: FastPath は、拒否が証明された後、制限された予算内で候補者リストを更新します (#2214)
  • そして、より小さな項目: 読み取り専用スナップファイルは各 Fastlet 内で共有され (fsb-vm はデフォルトで共有します)、共有スナップファイルの回復と孤立キャッシュのクリーンアップ (#2438) を伴います。ゲスト NAT 更新を 1 つの iptables-restore --noflush にバッチ処理するため、ゲスト アドレスを再適用してもルールが蓄積されなくなりました (#2214)。ネットワーク接続に IP がない間は SET_BINDING を延期し、サンドボックスプールのステータス更新ループを停止し、ランタイム削除時にゲート ルートを削除し、Docker ハブ資格情報ホストを正規化します (#2338)。そして、Fastlet から作成ごとのフェーズのタイミングを発行し、作成レイテンシーの証拠パイプラインにフィードします (作成後 16 ～ 17 ミリ秒で測定された定常状態のウォーム配信) (#2327)

アップグレードと互換性

  • 中断 (SDK へ): POST/PATCH リクエストはデフォルトで再試行されなくなりました。書き込みのステータス コードの再試行には、RetryConfig.RetryableStatusCodesNonIdempotent を介した明示的なオプトインが必要です。また、あいまいなトランスポートの失敗 (読み取り/書き込みのタイムアウト、予期しない EOF) による書き込みの再試行は行われなくなりました。書き込みの再試行に依存する呼び出し元は、返されたエラーを処理するか、オプトインする必要があります (#2342)
  • 動作の変更 (Python および Go SDKs): ストリームを開始するリクエスト (commands.run、codes.run、セッション/分離実行、メトリクス監視) は、すぐに失敗するのではなく、ウェイク バジェット内でゲートウェイのマークされたウェイク タイムアウト 503 を再試行するようになりました。確立されたストリームは決して再生されません。 WakeRetryDisabled() (Go) または無効なウェイク再試行 (Python) (#2357 #2426) で古いフェイルファストを維持します。
  • 動作の変更: SDK 表示ヘルパーは、すでに終了した標準出力イベントの間に余分な改行を挿入しなくなり (Go Execution.Text()、Python コードインタープリター Execution.text)、Go ヘルパーは、後続の CR をレガシーの 1.2 以前の bash セッション イベントのターミネータとして扱います (#2381) #2408)
  • 動作の変更: bash セッションの標準出力イベント テキストに元の行末が含まれるようになり、空白行がイベントとして表示されるようになりました。コンシューマは各イベントを改行のない行として扱うのではなく、実行ごとにイベント テキストを連結して正確な出力を復元する必要があります (#2318)

  • 動作変更: --overlay2=none のない gVisor コンテナの Docker でバックアップされたスナップショットは、不完全なイメージをサイレントに公開するのではなく、SNAPSHOT::UNSUPPORTED_RUNTIME (409) で拒否されます (#2241)
  • 動作の変更: サンドボックス cgroup に制限が設定されている場合 (以前はホスト全体)、execd CPU/メモリ メトリクスはサンドボックス スコープの値を報告します。メトリクス名とワイヤ形式は変更されませんが、ダッシュボードは変更されます (#2200)

OpenSandbox release-1.2.0

Stable cut of the 1.2.0 line, carrying everything merged since release-1.1.1 through two release candidates plus a post-rc hardening delta. Images shipped with the rcs; SDK/CLI/server packages publish at 1.2.0. Everyone on 1.1.x should upgrade. Baseline for every section below: release-1.1.1.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: the ingress records activity and parks requests to paused sandboxes until the restore completes, the server runs an idle sweeper behind an opt-in lifecycle.idlePolicy create field, and all five SDKs get the wake-retry contract — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject persistence and sealed pause/resume transfer, the server exposes the user-reachable vault API with credential values never appearing on any public read, and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes — plus port-scoped egress rules end to end in the classic profile (#2249 #2252 #2255 #2263 #2251 #2212)
  • Fast Sandbox snapshots and template builds can publish to and boot from OCI registries (OverlayBD OCI lifecycle), and a reliability campaign removes whole-call timeouts from SDK file transfers in all five languages, makes execd report sandbox-scoped CPU/memory and OOM kills, and fixes a long list of Docker-backend correctness and PTY/session output issues (#2338 #2165 #2200 #2191)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle.idlePolicy create field (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) persists as a reserved Sandbox CR annotation; an idle sweeper enumerates opted-in fsb sandboxes, checks activity in Redis, takes a per-sandbox pause lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe runs through the ingress gateway, and an OpenSandbox-Skip-Activity sentinel suppresses one observation and is stripped on both gateway and proxy hops. Config moves under [automation.idle_pause], and redis.dsn is validated at load when the sweeper is enabled (#2192 #2181 #2215)
  • Implement the Credential Vault API (OSEP-0022, fast-sandbox profile): POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault pushes complete vault revisions over the FastPath handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material and every public read is sanitized server-side; PATCH composes in memory with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] key to a structured renewalPolicy.extendSeconds (300–86400); the legacy key is deprecated (supported throughout 1.x, removed in 2.0), and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)
  • Implement the diagnostics context endpoint (spec in #2236): GET /v1/sandboxes/{sandboxId}/diagnostics/context returns the sandbox ID, lifecycle state, backend type, and backend-defined identifiers for Docker, Kubernetes, and Fast Sandbox without connecting to execd — Kubernetes context stays available before a Pod is allocated; extension backends that don't implement it return 501 (#2292)
  • Forward the still-encoded path through the sandbox proxy: Starlette bound the {full_path:path} route from the percent-decoded path, so a decoded ? started a query, %2F became a separator, and %2E%2E segments were resolved — closing a prefix-escape on Docker host-mapped endpoints; the proxy now takes the client's still-encoded tail from the raw path (validating it decodes to the routed path) and reads the query from the raw query string, so backends receive request targets byte-for-byte, matching the ingress gateway (#2228)
  • Keep blocking Docker calls off the event loop: proxy endpoint lookups, network-existence validation, and per-PVC volume inspect/create ran synchronously inside async handlers, so a slow Docker daemon (e.g. during a large pull) froze every other request including proxy traffic; they now run on worker threads with tenant context preserved, and volume-validation failures still clean up auto-created volumes (#2268 #2366)
  • Stop reporting image-inherited labels as sandbox state on Docker: metadata reads fell back to every non-reserved container label — including labels merged in from the image — and restored containers inherited reserved labels such as expires-at, host ports, and the egress token; in the worst case a restored TTL sandbox was deleted as already expired after a server restart. Creates now record the request's metadata keys in a reserved label and read back only those keys, and reserved labels present on the image but not set by the sandbox are blanked before container start (#2363 #2269)
  • Reject gVisor snapshots that would silently drop writes: docker commit under gVisor's default --overlay2=root:self can report READY while restoring none of the sandbox's writes; snapshot preflight now refuses gVisor unless the effective args include --overlay2=none, and create fails closed when the filesystem diff is filestore-only (#2241)
  • Keep an fsb snapshot whose create reply was lost: a UNAVAILABLE/DEADLINE_EXCEEDED from FastPath after the request was durably accepted returned 500 without writing a row, stranding the SandboxSnapshot and its published artifacts with no record; the create now probes for the snapshot before failing and reports it as submitted when FastPath persisted it (#2361)
  • Fix the remaining Docker-backend rough edges: BatchSandbox expiry reports Terminated/SANDBOX_EXPIRED instead of Running past spec.expireTime (#2238); concurrent lifecycle conflicts map to 404/409 instead of 500 (#2387); concurrent metadata patches no longer race into 500s or dropped keys (#2267 #2281); createdAt stays stable across reads and pause/resume transitions are recorded (#2405); network policy actions are validated and unknown fields return 422 (#2383 #2385); the sandbox image is read from the container config so a docker rmi -f'd image no longer 500s GET /sandboxes (#2353); template reads trust the database projection instead of syncing the CR on every create-gate check (#2326); the renew cooldown applies to every renew source when the Redis consumer is enabled (#2276 #2279); BatchSandbox pods default to restartPolicy: Never so a kubelet restart can no longer wipe the writable layer while reporting Succeed (#2128); podman's pasta/slirp4netns/none network modes pass through (with networkPolicy rejected, since there is no bridge to attach to) (#2203); Docker timestamps with unusual fractional seconds no longer silently report the current time (#2220); and the execd cache container honors [docker] security profiles and secure_runtime (#2254)

Code changes below ride the 1.2.0 packages.

  • Add the OSEP-0024 SDK contract to all five languages: a typed lifecycle.idlePolicy create field with client-side fail-fast validation, plus the wake-retry contract — on a 503 carrying the gateway-owned OpenSandbox-Wake: expired marker (its presence proves the request was parked and never forwarded, making any-method retry safe), the SDK resends after Retry-After under a bounded budget (default 5 attempts / 60 s, per-client knobs) and exhaustion raises a typed wake-timeout exception; bare 503 handling is unchanged (#2198 #2218). The contract initially bypassed streaming transports; the request that starts a stream now wake-retries in JavaScript, Python, and Go — established streams are never replayed — while C#/Kotlin stream starts currently fail fast (#2357 #2426)
  • Add the Credential Vault client contract to all five SDKs (OSEP-0022): template-backed sandboxes route vault calls through the server on the same template-origin signal as network policy, while sidecar-direct adapters stay untouched (#2263)
  • Stop capping file uploads and downloads at the request timeout (30 s default) in all five SDKs — the whole-call timeout covered sending the body and reading the response, so any large or slow transfer failed mid-flight even while healthy; transfers now run on a dedicated client with no whole-call deadline that still bounds the wait for response headers, so a stalled transfer still fails instead of hanging (#2165 #2186 #2196 #2206)
  • Implement diagnostics across the SDK surface (with #2292): context is exposed through both the manager and sandbox facades in all five languages, and JavaScript, Go, and C# gain public logs/events APIs matching the existing Python/JVM surface (#2292)
  • Add lifecycle.renewalPolicy to all five SDKs (OSEP-0009): a typed create field with client-side fail-fast validation (extendSeconds 300–86400), replacing the opaque extensions key (#2296)
  • Support port-scoped egress rules in all five SDKs: NetworkRule.ports (TCP 1–65535, at most 256 per rule, target now optional) with client-side validation mirroring the server (range, duplicates, cap, domain+ports rejected); JavaScript encodes the target-or-ports invariant as a union type (#2212)
  • Surface the authoritative execution_complete.exit_code in Go and Kotlin, preferring it over the previous evalue/inferred-0 fallbacks while staying compatible with older servers (#2330); honor an explicitly supplied OPEN-SANDBOX-API-KEY header over the configured key regardless of header-name casing in JavaScript, C#, and Kotlin (#2348 #2372 #2375); suppress sandbox.create metrics for client-pool warmup creates in Go, Python, and JavaScript (#2199)
  • Strip protected credentials on cross-origin redirects in JavaScript, C#, and Go: sandbox-prefixed headers, endpoint tokens (X-EXECD-ACCESS-TOKEN, X-API-Key), and configured authentication headers are removed whenever a redirect changes scheme/host/port, while same-origin hops and unrelated headers are preserved; file uploads never follow redirects in JavaScript, and in browsers an opaque redirect fails closed rather than risk replaying credentials (#2178 #2173 #2183)
  • Route the JavaScript and C# code-interpreter data-plane headers through the shared policy: direct-mode /code requests no longer carry the tenant OPEN-SANDBOX-API-KEY to execd, an explicitly configured connection key keeps precedence over the configured apiKey without duplicate case-variant entries, and endpoint-scoped credentials still win (#2149)

Python

  • Retry the gateway's wake timeout when starting a stream: the SSE clients stripped the retry wrapper entirely, so commands.run, session runs, and codes.run against an auto-paused sandbox failed with the marked 503 whenever the restore outlasted the gateway's park budget; streaming transports now carry a wake-only retry (no general retries, no added deadlines), and the docs no longer claim streams bypass retries (#2357)
  • Normalize the connection domain: a trailing slash or /v1 in domain / OPEN_SANDBOX_DOMAIN produced //v1/... URLs that the server 404'd — the same variable worked in every other SDK; Python now strips both (#2347)
  • Reuse SSL contexts across owned transports: CA certificates were reloaded on every call, blocking the event loop under asyncio concurrency — measured create P50 improves ~18–28% under concurrency (#2360)
  • Preserve the first SSE event after a UTF-8 BOM (including one split across network chunks) (#2226); close wake-timeout response bodies on cancellation (#2371); close interrupted async file-download responses so a cancelled or failed read no longer occupies the connection (#2369); keep the status code when an error response carries a non-JSON body — a proxy's HTML/empty 404/500 previously surfaced as InvalidArgumentException with no status (#2402); raise the shared structured error from Code Interpreter codes.run failures instead of a hand-built exception that lost retry_after (#2364); keep code-interpreter output fragments together in Execution.text instead of inserting extra newlines (#2408); round sub-millisecond command timeouts up to 1 ms instead of sending 0 (which disabled the timeout) (#2419); stop propagating a cancelled endpoint fetch to concurrent waiters (#2277); forward credential_proxy through sandbox pools, which silently dropped it before (#2283); stop reporting failed file replacements as successful (#2222); clean up cancelled async pool startup instead of getting stuck in STARTING (#2209); regenerate the lifecycle client to drop stale hardcoded defaults (wire behavior unchanged) (#2280); MCP: cancelling one tool call no longer cancels a coalesced shared connect for the same sandbox, which failed every other waiting call (#2355)

JavaScript

  • Preserve execution events with CR line endings: the SSE parsers only split on LF, so a valid CR-delimited stream silently dropped the execution ID, output, and completion event (#2374)
  • Scope in-flight endpoint-cache invalidation to each sandbox, so invalidating sandbox B no longer discards a pending fetch's result for sandbox A (#2349)
  • Preserve reused byte chunks in file uploads: an async producer that reuses a Uint8Array/Buffer view uploaded the mutated content twice instead of both snapshots (#2428); keep caller cancellation active after response headers arrive — aborting mid-SSE-stream or mid-download previously left the body running (#2350)
  • Strip protected headers on cross-origin redirects (see the cross-SDK entry above) (#2173)

Kotlin

  • Keep an explicit API key header ahead of the configured key in any casing, and stop attaching an empty key header when unconfigured (#2375)
  • Preserve the raw response body on deserialize failures and catch LinkageError from a serializer/runtime mismatch — previously an AbstractMethodError escaped every handler, killing SSE streams silently with the server's actual response unrecoverable (#2416)

C#

  • Honor an explicit API key header regardless of casing: the case-sensitive check added a second, conflicting default entry, and the metrics reporter replaced the caller's credential (#2372)
  • Strip protected credentials on cross-origin redirects and route code-interpreter requests through the shared data-plane header policy (see the cross-SDK entries above) (#2183 #2149)

Go

  • Stop retrying non-idempotent writes by default: with retry enabled, 27 POST/PATCH call sites (sandbox/session/command/file/snapshot/vault mutations) could execute twice and still return success — POST/PATCH no longer retry status codes by default, retry only transport failures proven to be pre-send (dial/CONNECT/TLS before request bytes), and SSE bootstraps bypass the generic retry loop; callers who accept duplicate-execution risk can opt in via RetryConfig.RetryableStatusCodesNonIdempotent (#2342)
  • Retry the gateway's wake timeout when starting an SSE stream: the six streaming call sites (command/code/session runs, metrics watch) previously failed immediately with the marked 503; the bootstrap now parks within the same Retry-After budget and returns the typed wake-timeout error on exhaustion — established streams are never replayed, a bare 503 is still not retried even with write-status opt-in, and a 503 reached through a redirect chain loses wake provenance so an already-executed request is never resent; callers relying on fail-fast can pass WakeRetryDisabled() (#2426)
  • Keep line terminators in Execution.Text(): execd already includes \n/\r in event text and requires concatenation to reconstruct stdout, but the helper inserted an extra newline between terminated events ("a\n" + "b\n" became "a\n\nb\n"); a separator is now added only when the preceding event does not already end in a terminator (#2381)
  • Strip the tenant API key from direct-mode data-plane requests: a tenant key supplied through ConnectionConfig.Headers was delivered to execd and the egress sidecar inside the untrusted sandbox — completing the credential-exposure fixes across all five SDKs (#2337)
  • Authenticate proxied data-plane requests with the API key header instead of smuggling the tenant key into the sandbox, fixing 401s in multi-tenant proxy mode (#2274); surface execution_complete.exit_code (#2330)

Controller

  • Retain a BatchSandbox until cleanup completes: a deleted sandbox could disappear from the lifecycle API (GET 404) while its owned pod still ran, letting a replacement sandbox write the same persistent directory before the old writer exited; deletion now uses foreground cascading deletion alongside the existing finalizers — queries report Stopping during managed cleanup, and 404 arrives only after the runtime is gone (#2154)
  • Fix task-executor treating an empty exit file as exit code 0, which reported a failed or interrupted task as Succeeded when the shim was killed mid-write (#2270)

Execd

  • Report sandbox-scoped CPU/memory metrics and OOM kills: GET /metrics read the host's /proc inside the container, so dashboards showed host-wide numbers; usage now comes from the sandbox's own cgroup when limits are configured (host view kept for unlimited guests), and a cgroupfs poller diffs the kernel OOM kill counter every 5 s to export execd.system.oom.kills with structured warn logs — no capabilities required (#2200 #2191)
  • Serve the session-private /tmp through the files API: the strict isolation profile's /tmp was an anonymous tmpfs with no host-side path, so files-API paths under /tmp failed and callers had to shuttle artifacts through base64 shell commands; /tmp is now a host-backed per-session directory bind-mounted into the namespace — same private semantics, but readable and writable through the existing files endpoints (#2424)
  • Support browser PTY WebSocket authentication: browsers cannot set X-EXECD-ACCESS-TOKEN on a native WebSocket handshake, so terminal connections needed a BFF relay; the PTY upgrade now accepts the existing execd token via the opensandbox-pty subprotocol's credential entry (Kubernetes-style) with no new token issuer and header precedence preserved for SDK/CLI clients (#2334)
  • Keep isolated sessions alive when a foreground run is cancelled or disconnected: the run's context derived from the HTTP request, so a disconnect or timeout_seconds expiry SIGINT'd the whole process group including the persistent session shell — the session died and every later run 404'd; runs now interrupt only the running command (with a bounded SIGKILL escalation) while the session survives, and silent foreground runs emit periodic SSE pings so gateway idle timeouts no longer close the stream (#2351)
  • Preserve bash session output line endings: run_in_session stdout events dropped \n/\r bytes, so blank lines were unrecoverable and concatenating events did not reconstruct the output; event text now carries its original line ending — consumers should concatenate event text per run (#2318)
  • End a Jupyter execution when its kernel dies or the connection drops: both cases previously left the code-interpreter request open indefinitely with SSE pings keeping it alive; they now fail the execution (KernelDied / KernelConnectionLost) exactly once (#2401)
  • Keep reading session output past a line longer than 16 MiB: the read loop stopped at the cap — bash sessions hung until the 24 h default timeout, and isolated sessions leaked output into the next run; over-long lines are now passed on in pieces (never splitting UTF-8) (#2275)
  • Run large background code in isolated sessions: the wrapper passed code as a single bash -c argument, and Linux caps one exec argument at 128 KiB — background code above that failed with only Argument list too long; it is now delivered through stdin like the foreground path (#2400); probe private-network capability so restricted runtimes get a structured error for share_net=false sessions instead of an opaque EOF (#2333)
  • And the smaller fixes: report exit_code explicitly on command completion and errors (#2303 #2316); send run errors after the stream started as framed SSE error events instead of a bare JSON body the Python SDK dropped (#2354); keep PTY output buffered until drained when the shell exits, so the last screen of output is no longer lost (#2362); always send the WSCloseTakenOver (4001) close frame on PTY takeover, even mid-write (#2376 #2378); write an isolated run's script while reading its output so a chatty run can no longer deadlock on the stdin/stdout pipes (#2399); reject out-of-scope absolute paths in the session files view instead of silently touching the wrong file (#2322); serve binds mount points through the isolated session files API (#2299); truncate command output files before unlink so daemons holding the fd can't cause invisible disk growth (#2295); omit invalid upper-usage metrics and fail quota admission closed on scan errors (#2257); deduplicate JDK MITM CA imports across shared trust stores (~6.2 s → ~0.6 s for four JDKs) (#2310); default PTY sessions to TERM=xterm-256color when unset (#2313); percent-encode quotes and backslashes in Content-Disposition filenames (#2161); and parse the Range header before setting download headers so a malformed range returns a clean JSON 416 (#2216)

Networking

egress

The OSEP-0022 vault items concern the fast-sandbox profile's credential-vault surface; the OSEP-0023 items remain scoped to the default-off experimental revision runtime.

  • Add the egress-held vault for fast sandboxes (OSEP-0022), landing in stages: the internal /vault/{sandboxUid} relay surface with create-only POST (409 on duplicate, atomic across server replicas), full-revision PUT with expectedRevision and an expectedIncarnation precondition so a stale writer can never land on a reset's successor, value-including GET, and DELETE that keeps the policy (#2249); durable per-subject persistence — one file per subject under a Pod-scoped volume (optional tmpfs), the same commit protocol as policy files so acked means durable and applied, incarnation-fenced reload, and purge on unbind (#2252); and the superseded fastlet-proxy vault route removed (#2247)
  • Carry the vault across pause/resume (OSEP-0022 "Vault Lifecycle"): VAULT_EXPORT copies the vault file into the snapshot bundle strictly before runtime teardown and seals the subject (all vault ops answer 409 while paused; enforcement continues), and VAULT_IMPORT is the only authorized incarnation transfer — a genuine export failure fails the pause checkpoint so teardown never runs without a bundle, and a vaultTransfer capability signal lets an egress without vault persistence skip the transfer instead of failing (#2255 #2290)
  • Pin the fast-sandbox MITM CA (OSEP-0022): the pool-pinned, versioned CA is seeded from a read-only secret mount into the mitmdump confdir, replacing generate-on-start — an egress restart no longer rotates the CA and silently invalidates every live sandbox's TLS trust; a missing or mismatched CA refuses only the MITM addon with mitmCaFingerprint / mitmCaDown surfaced on /healthz (#2251)
  • Define stale-subject takeover on slot reuse: the fast-sandbox dispatch key is the slot IP and slots are reused, so a SET_BINDING can claim a key still held by a dead-but-registered subject — egress now treats that as authoritative, tearing down the stale subject's nft rules, DNS refcount, MITM redirect, and vault slice before registering the successor deny-first (#2250)
  • Align the fast-sandbox network policy with the vault pattern: the recorded policy becomes egress-held state — a /policy/{sandboxUid} relay surface with revision preconditions, durable per-subject files, POLICY_EXPORT/POLICY_IMPORT snapshot transfer, and, after an egress restart, the committed file superseding the replayed create-time binding input (#2309)
  • Support port-scoped egress rules end to end (classic profile): NetworkRule.ports (TCP 1–65535, ≤256 per rule) makes target optional — port-only rules, or ports combined with an IP/CIDR; domain+ports is rejected since domain rules evaluate at the DNS proxy layer; an operator-shipped reachable.ports.cap whitelist is enforced as an always-deny ahead of every user rule so even defaultAction: allow cannot open a non-whitelisted port, and the fast-sandbox route rejects ports with 400 until the fastlet nft path can enforce them (fail-closed, documented) (#2212)
  • Exempt the MITM redirect target from port-scoped rules: with the operator port floor and transparent MITM both active, every intercepted flow was silently blackholed — the iptables REDIRECT rewrote dport 80/443 to the local listener before the filter chain ran, so the floor-complement drop judged the rewritten port; the listener tuple is now accepted ahead of every port-scoped rule, adding no new reachability, and a non-whitelisted intercepted port now fails visibly at the proxy instead of passing silently (#2435)
  • Continue the OSEP-0023 experimental foundation [EXPERIMENTAL] across the line: live credential-bound Vault admission with per-request rotation (#2176), acknowledged Policy revisions before publication (#2182), HTTP/2 admission with bounded drain (#2201), runtime-fault containment on an unexpected MITM exit (#2172), atomic revision policy-file persistence (#2162), nft apply-effect classification (#2167), static TLS passthrough selectors with startup rejection for conflicting native lists (#2229), TLS admission counters (#2265), the installation-only subject revision IPC foundation (#2284), and converged Fast Sandbox subject transitions ahead of the v2 lifecycle consumers (#2294)
  • And the smaller items: ship egress-trace, a read-only admission viewer inside the egress image (live policy state, nft sets, DNS leases, per-connection verdicts, and a probe subcommand; decrypted contents are never shown) (#2230); forward DNS queries over TCP when the client used TCP, so large truncated answers (SPF/DKIM TXT, many-record responses) finally arrive (#2358); preserve shared gateway DNS rules when the last subject on one fast-sandbox gateway releases, which previously removed the entire shared nft table (#2427); trim fsyncs from the create-time policy bootstrap and add per-stage create-latency instrumentation — real warm delivery measured sub-100 ms end to end with policy enforced (#2327)

ingress

  • Implement OSEP-0024 activity tracking and wake-on-access: with --activity-enabled, every routed request records a monotonic activity timestamp to Redis — fire-and-forget, never on the hot path; with --wake-enabled, a request routed to a paused fast sandbox is parked instead of answered 503: one ResumeSandbox per replica per sandbox under a checkpoint-fenced singleflight, a bounded parking lot, and stale-route replay restricted to idempotent methods with reproducible bodies; the wake-timeout answer carries the OSEP-defined marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired), stripped from every upstream response so a sandbox cannot forge provenance; with both flags unset, behavior is byte-identical to before (#2156 #2180)

Upgrade & Compatibility

  • Breaking (Go SDK): POST/PATCH requests are no longer retried by default — status-code retries for writes require explicit opt-in via RetryConfig.RetryableStatusCodesNonIdempotent, and ambiguous transport failures (read/write timeouts, unexpected EOF) are no longer retried for writes; callers that relied on write retries must handle the returned error or opt in (#2342)
  • Behavior change (Python and Go SDKs): the request that starts a stream (commands.run, codes.run, session/isolated runs, metrics watch) now retries the gateway's marked wake-timeout 503 within the wake budget instead of failing fast — established streams are never replayed; keep the old fail-fast with WakeRetryDisabled() (Go) or disabled wake retry (Python) (#2357 #2426)
  • Behavior change: SDK display helpers no longer insert extra newlines between already-terminated stdout events (Go Execution.Text(), Python code-interpreter Execution.text), and the Go helper treats a trailing CR as a terminator for legacy pre-1.2 bash-session events (#2381 #2408)
  • Behavior change: bash-session stdout event text now includes its original line endings, and blank lines appear as events — consumers must concatenate event text per run to recover exact output instead of treating each event as a newline-free line (#2318)
  • Behavior change: a BatchSandbox past its spec.expireTime now reports Terminated / SANDBOX_EXPIRED instead of Running, even while the pod is still Ready — callers that treat Running as alive should check expiry (#2238)
  • Behavior change: BatchSandbox pods now default to restartPolicy: Never — deployments that relied on the implicit Always and want restarts must set it explicitly in their batchsandbox_template_file (#2128)

  • Behavior change: Docker-backed snapshots of gVisor containers without --overlay2=none are rejected with SNAPSHOT::UNSUPPORTED_RUNTIME (409) instead of publishing a silently incomplete image (#2241)
  • Behavior change: execd CPU/memory metrics report sandbox-scoped values when the sandbox cgroup has limits configured (previously host-wide); metric names and wire format are unchanged, but dashboards will shift (#2200)
  • Behavior change: on Docker, labels inherited from the image no longer appear as sandbox metadata, restored sandboxes no longer inherit the source's reserved labels, and image.uri reports the reference the sandbox was created with (#2363 #2269 #2353)

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.0
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.0            # Python
npm install @alibaba-group/opensandbox@1.2.0   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.0")
dotnet add package Alibaba.OpenSandbox --version 1.2.0
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.0

uvx opensandbox-server==1.2.0
