claude-code v2.1.328

パッチ 公開日2026年11月19日 出典anthropics/claude-code English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.328

何が変わったのか

  • Amazon Bedrock、Google Cloud のエージェント プラットフォーム、Microsoft Foundry、および Claude アプリ ゲートウェイに Claude Opus 4.6 および Sonnet 4.6 の自動モードを追加しました。許可モードのない対話型セッションが開始されます
  • コマンドおよび HTTP フックと同様に、mcp_tool フックに "onFailure": "block" を追加しました。呼び出しが失敗したフックはアクションをブロックします。
  • 許可プロンプトをスキップするセッションからのメッセージがクラウド セッションによって保持されドロップされる可能性がある場合の警告を追加しました
  • /status および claude doctor に、OpenTelemetry エクスポータにエンドポイントがなく、そのデータが失われる可能性がある場合の通知を追加しました。
  • CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME を追加しました。これにより、ホストは claude -p --resume と --continue がフックによって遅延されたツール呼び出しを実行するのを停止できます。
  • ポリシー プラグインの allowManagedModsOnly オプションをオンにするためのクロード コードを埋め込むアプリのサポートを追加しました。管理者が管理する設定が引き続き優先されます
  • ポリシーの maxEffortLevel が有効なエフォート レベルではない場合に、Claude アプリ ゲートウェイに起動警告を追加しました
  • セルフホスト ランナー: ベース フォルダーの下のパスの代わりに、セッションが --capacity 1 でリポジトリに使用するフォルダーに名前を付けるために --repository-folder を追加しました。これはシンボリック リンクにすることはできません。
  • 自己ホスト型ランナー: ホストの設定時に起動警告を追加しました。json は、セッションが無視するデフォルトの許可モードを設定します。
  • 自己ホスト型ランナー: --hook-label を claude self-hosted-runner orchestrator に追加し、選択したセッション ラベルを spawn-runner フックに手動で追加しました。
  • 自己ホスト型ランナー: spawn-runner フックのセッションにラベルを付けるために、--metadata key=value を claude --environment に追加しました。
  • 自己ホスト型ランナー: オーケストレーターの /metrics に claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds を追加したため、再度開かれたセッションの待機時間を新しいセッションの待機時間から判断できるようになりました。
  • 自己ホスト型ランナー: Anthropic がセッション中のランナーの開始を放棄した頻度を原因別にカウントするオーケストレーター メトリクス claude_code_self_hosted_orchestrator_sessions_given_up_total を追加しました。
  • echo ==== や [ a == b ] など、= で始まる単語で「見つからない」エラーで停止する zsh の Bash コマンドを修正しました。 =cmd はコマンドのパスに展開されなくなりました
  • /compact のように再構築するのではなく、セッションの以前のシステム プロンプトを再利用する自動圧縮を修正しました。
  • 非常に長い入力または不正な入力でマークダウン レンダリングがフリーズする問題を修正しました。
  • 稀に発生する画面フリーズを修正
  • Esc の直後に入力すると、許可プロンプトまたは質問で失われることがよくある問題を修正しました。 Alt を Esc およびキーとして送信する端末では、未使用の Alt キーまたは Option キーがそこで削除されるようになりました。
  • 遅い接続によりプロンプトが 2 つに切断された場合に、プロンプトに入力されるペーストまたは端末の応答を修正しました
  • サードパーティプロバイダー上、またはテレメトリや機能フラグがオフになっている場合、スケジュールされたタスクファイルを読み取れない場合、スケジュールされたタスクを保存すると、プロジェクトの他の保存されたタスクが消去される問題を修正しました
  • プロジェクトのスケジュールされたタスク ファイルにタイプミスがあるスケジュールされたタスクが、次回そのファイルが保存されたときに削除される問題を修正しました。
  • メッセージが遅れて保存された場合、再開されたクラウド セッションで圧縮の概要や最近のメッセージが失われる可能性がある問題を修正しました。
  • スピナーのトークンカウントと、再試行された返信を 2 回カウントするサブエージェントのトークンカウント、ストリーミングされなかった返信の欠落、クロードが考えている間に静止する問題を修正しました。
  • 応答中に使用クレジットがなくなったときに表示されるレート制限というエラーを修正しました
  • Bedrock、Agent Platform、Foundry、または Claude アプリ ゲートウェイ上でベータを拒否するゲートウェイの背後に CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS が設定されていると、Claude Desktop の外で自動モードが毎ターン失敗する問題を修正
  • CLAUDE_STREAM_IDLE_TIMEOUT_MS がゲートウェイ、カスタム ベース URL、クラウド プロバイダーの 5 分間の接続制限を延長しない問題を修正
  • スケジュールされたタスク以外の、サードパーティプロバイダー上の一部のクロードデスクトップセッションが、大規模なツールの結果後に「プロンプトが長すぎます」で永久に終了してしまう問題を修正しました。最大のものは現在除外されています

  • Bedrock、Google Cloud のエージェント プラットフォーム、または Foundry が進捗状況の概要の工数設定を拒否した場合、セッションのサブエージェントのモデルの工数がオフになる問題を修正しました (2.1.327 のリグレッション)
  • 自動またはバイパス モード以外の許可プロンプト、計画の承認、または質問が 10 分間開いたままになっている場合、コード モードがスクリプトを停止する問題を修正しました。
  • 自動およびバイパス許可モードのコード モード スクリプトが、前のスクリプトの実行中に接続していた MCP サーバーの呼び出しに失敗する問題を修正しました。
  • claude --resume ピッカーで選択されたセッションで、自動またはバイパス許可モードでバックグラウンドでコード モード スクリプトが実行されない問題を修正しました。
  • 1 つの返信で複数のスクリプトを実行したセッションを再開すると、ロードされたスキル、フック コンテキスト、または権限承認で入力されたメモが失われるコード モードを修正しました
  • セッションがピッカーから再開されたとき、または許可を求めるモードで再開されたときに、コード モード スクリプトが切断されたことがクロードに通知されない問題を修正しました。

  • コード モード編集の改善: 何も変更しない編集でもスクリプトは停止しなくなり、失敗した編集がどこに一致するか、または最も近いかがクロードに通知されます。
  • 改善されたコード モード: スクリプトが失敗したときにどのツール呼び出しがまだ実行されていたかをクロードに通知するようになりました。
  • クロードがコード モードの自動モードおよびバイパス モードで開発サーバーを起動する方法を改善しました。クロードは、/tasks に表示されるバックグラウンド タスクとして開発サーバーを実行するように指示されます。
  • Windows: スクリプトのシェル コマンドが Git Bash で実行されること、および同じ名前の関数の代わりに PowerShell エイリアスが実行されることをクロードに指示することにより、コード モードを改善しました。
  • 複数の進行中のチームメイトの同時開始を改善しました。「ロック ファイルはすでに保持されています」というエラーで失敗することが大幅に減りました。
  • コンピューター使用承認ダイアログを改善しました。各アプリのアクセス レベルとよりわかりやすい警告が表示されるようになりました。
  • クロスセッション メッセージングの改善: クロードは、クラウド セッションまたは別のコンピューターがリストにない場合にリモート コントロールがオフであることを説明するようになりました。
  • 別のセッションからのメッセージが保持またはドロップされたときに標準エラー出力に表示される claude -p テキスト出力と、それを許可する方法を改善しました。
  • 公開されたアーティファクトを誰が開くことができるかに関するクロードの回答を改善しました。クロードは、前回の公開の回答を繰り返す代わりに、アーティファクトを再度確認するように指示されるようになりました。
  • 再開された自己ホスト型ランナー セッションの改善: クロードは、以前の作業がまだ存在するかどうかを確認し、何が不足しているかを通知するようになりました。
  • サードパーティプロバイダーの Opus 4.6 および Sonnet 4.6 のプラン モードと Bash プロンプトが、新しいモデルと同様に自動モードを使用および提供するように変更されました。 disableAutoMode は両方をオフにします
  • コード モードを変更し、スクリプトの出力で UserPromptSubmit フック (マネージド フックを含む) を実行しなくなりました。その出力を編集するには、updatedToolOutput で PostToolUse フックを使用します。
  • ほとんどのモデルで /code-review を変更し、バグと CLAUDE.md 違反のみを報告するようにしました。再利用、簡素化、効率的なクリーンアップのために /simplify を実行します。
  • /code-review を変更して、ほとんどのモデルで各検出結果を重要、既存、または問題にマークし、各概要を修正案で終了するようにしました。クリーンなレビューのリストには「コードレビューで問題は見つかりませんでした」と表示されるようになりました。
  • claude.ai <name> 形式の deniedMcpServers エントリを、クラウドおよびセルフホスト ランナー セッションでもそのコネクタに適用するように変更しました。
  • マネージド PostToolUse フックが変更され、実行前に拒否された呼び出しに対しては起動しなくなりました。ログ エントリ、書き換え、ブロック、またはそこで停止することはありません。 PostToolBatch が最も多く取得されますが、拒否済みとしてマークされません
  • 送信前に Yes または No を尋ねるように /bug を変更したため、Enter を繰り返してもレポートが送信されたり、GitHub が開かれなくなりました。
  • claude -p、エージェント SDK、デスクトップ、および VS Code のサブエージェントが、CLAUDE_CODE_FORK_SUBAGENT=0 が設定されている場合にデフォルトで独自のサブエージェントを待機するように変更されました。
  • バックグラウンド サブエージェントとそれが待機するサブエージェントを 1 回の 10 分間の待機に対してカウントするように、claude -p を CLAUDE_CODE_FORK_SUBAGENT=0 に変更しました。長いチェーンの場合は CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS を上げる
  • PermissionRequestフックで書き換えられたシェルコマンドをサンドボックス外で実行するサンドボックス除外コマンドに変更しました。
  • Chrome のようこそ画面と /chrome のクロードを変更して、許可モードまたは /permissions のルールが応答しない限り、クロードがサイトで操作する前にクロード コードが質問するようにしました。
  • サードパーティプロバイダー上、またはテレメトリまたは機能フラグがオフになっているクロードデスクトップとエージェントSDKセッションを変更して、質問を開いた状態で閉じられたときに、回答なしで続行するのではなくターンを終了するようにしました。
  • サードパーティプロバイダー上、またはテレメトリまたは機能フラグがオフになっている場合に、貼り付けられたテキストがクロード用に貼り付け済みとしてマークされるように変更しました。
  • Anthropic API のターミナル セッションでのサブエージェントの進行状況の概要を、テレメトリをオフにして、はるかに少ないトークンを使用して、短いノートからデフォルトの小型高速モデルによって書き込まれるように変更しました。
  • sandbox.failIfUnavailable が設定されていない限り、開始できないサンドボックスの報告方法を変更しました。次のサンドボックス化された Bash コマンドは拒否され、セッションではサンドボックスがオフであると表示されます。
  • /list-agents のリストをあなただけに表示するように変更しました。クロードは必要に応じてセッション自体をリストします
  • セルフホスト ランナー: 設定により Claude の GitHub ツールが名前で保護されるように、組み込みの gh api がデフォルトでオフになるように変更されました。 --use-anthropic-gh true がオンになります
  • 自己ホスト型ランナー: セッション自体の claude が起動する前、または終了後にラッパー スクリプトが実行する claude を、Anthropic 管理の git を持たないように変更しました。
  • 自己ホスト型ランナー: CLAUDE_RUNNER_SESSION_UUID と CLAUDE_CODE_REMOTE_SESSION_UUID の両方をセッションとその checkout、post-session、spawn-runner フックに設定するように変更しました。
  • --capacity 1 でセルフホスト ランナーを変更し、プッシュ先のリポジトリのパスがシンボリック リンクである場合にセッションを早期に拒否するようにしました。
  • [VSCode] 別のセッションからのメッセージが保留されている場合の通知と、それを許可できる設定ファイルへのリンクを追加しました。
  • [VSCode] パネルが低い場合、またはコマンド、URL、または説明が長い場合に、[いいえ] ボタン、返信フィールド、またはタイトルが切り取られる許可プロンプトを修正しました。
  • [VSCode] 失敗またはブロックされたツール呼び出しに理由がないか、理由が途中で中断され、Glob および Grep が結果としてエラーをカウントする問題を修正しました。

claude-code v2.1.328

What's changed

  • Added auto mode for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude apps gateway; interactive sessions with no permission mode start in it
  • Added "onFailure": "block" for mcp_tool hooks, as for command and HTTP hooks: a hook whose call fails blocks the action
  • Added a warning when a message from a session that skips permission prompts may be held and dropped by a cloud session
  • Added a notice in /status and claude doctor when an OpenTelemetry exporter has no endpoint and its data would likely be lost
  • Added CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME, which lets a host stop claude -p --resume and --continue from running a tool call that a hook deferred
  • Added support for apps that embed Claude Code to switch on the policy plugin's allowManagedModsOnly option; an admin's managed settings still win
  • Added a startup warning to the Claude apps gateway when a policy's maxEffortLevel is not a valid effort level
  • Self-hosted runner: Added --repository-folder to name the folder that sessions use for a repository at --capacity 1, in place of its path under the base folder, which can't be a symbolic link
  • Self-hosted runner: Added a start-up warning when the host's settings.json sets a default permission mode that sessions ignore
  • Self-hosted runner: Added --hook-label to claude self-hosted-runner orchestrator, to hand chosen session labels to the spawn-runner hook
  • Self-hosted runner: Added --metadata key=value to claude --environment, to label a session for the spawn-runner hook
