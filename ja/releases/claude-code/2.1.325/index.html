claude-code v2.1.325

クロードコード v2.1.325

何が変わったのか

  • zstd 圧縮された応答のデコード方法におけるセキュリティ問題を修正しました
  • VS Code および同様の統合ターミナルにノートブック セルの再実行に関するスピナー ヒントを追加しました。クロードが Jupyter ノートブックを読み取りまたは編集したときに表示されます。
  • 組織のポリシーがリクエストをブロックしたときに表示されるエラーの下に、続行方法を示す行を追加しました: /rewind を実行してメッセージを変更するか、/clear を実行します
  • サンドボックス化された git checkout、git stash、または自動スタッシュ プルが .claude のような保護されたファイルを更新できない場合のクロードへのメモを追加しました。
  • ベア リポジトリ、--separate-git-dir チェックアウト、Android repo チェックアウトのワークツリーでエラーが発生して停止する /security-review とスキルのインライン git コマンドを修正しました
  • モデル設定が opusplan または haiku の場合に、独自のモデルを持つサブエージェントがプラン モード モデルに移動される問題を修正しました。
  • メイン セッションのモデルでファイルの読み取りと MCP の結果をサイジングする別のモデルのサブエージェントを修正しました
  • 多くのサードパーティ製ゲートウェイと Foundry 上のセッションが、圧縮ではなく毎ターンコンテキスト長エラーで停止する問題を修正しました。
  • クロードコードがきれいに終了せずに停止した後、再開されたセッションから最近のターンが失われることがある問題を修正
  • 作業ディレクトリが削除された後に起動ディレクトリで実行されるシェル コマンドを修正しました。コマンドはメッセージとともに失敗し、再発行できるようになりました。
  • plansDirectory フォルダーに保存できない場合に承認された計画の編集が失われる問題を修正しました。計画はデフォルトの計画フォルダーに保存され、場所と理由を示す警告が表示されます。
  • 保存された sonnet[1m] モデル設定が、新規インストール時に API が拒否するモデル ID に書き換えられる問題を修正
  • スケジュールされたタスクが後に応答した場合に、プロンプトへの応答が非表示になるフォーカス ビューを修正しました
  • フルスクリーンがオフのときにバックグラウンド サブエージェントのビューにプロンプトが表示されないことがある問題を修正しました
  • リスト内の長いオプションと許可プロンプトが折り返されるときに部分的に上書きされ、狭い端末で最初に実行される画面で行が失われる問題を修正しました。
  • 権限ルールに関する起動警告と、スクロールして表示されなくなったときに記録される「N MCP サーバーには認証が必要です」通知を修正しました
  • エージェント名または作業フォルダーに制御文字または改行が含まれている場合に、制御文字が表示されたり、複数行に分割されたりするウェルカム ヘッダーを修正しました。
  • クロードが自分だけが実行できるコマンドを試行したときに表示される赤色のエラーを修正しました。プロンプトで入力した場合にのみ実行されると薄暗い線が表示されるようになりました。
  • /stats が表示するアクティブ日数の合計が 1 日高すぎる問題を修正しました
  • 分析に適したセッションがない場合にレポートの準備ができたと表示し、escaping を指定せずに 2 つの値を HTML レポートに書き込む /insights を修正しました。
  • 管理設定、--settings、またはプロジェクトの .claude/settings.json または .claude/settings.local.json がそのまま維持されているときに音声モードが変更されたと言う /voice を修正しました。それは今、何がそれを保持しているかを示しています
  • Windows および Linux でクイック起動に Cmd+Esc を表示する IDE のようこそダイアログを修正しました
  • 組織のポリシーがクラウド セッションを拒否する場合に表示される Slack アプリのヒントを修正しました
  • キーを読み取る端末がない場合に claude purge がサイレントにハングし、標準入力がパイプされているときにそのプロジェクト ピッカーと -i プロンプトがキーボードを無視する問題を修正しました。
  • claude plugin eval --output-dir '' が現在のフォルダーにレポートを書き込む問題を修正しました。エラーで終了するようになりました
  • テキスト スタイル以外の制御シーケンスを渡す端末上の claude -p テキスト出力を修正しました。パイプとファイルは変更されません
  • config ディレクトリに溜まる残りの .oauth_refresh.lock.owner.tmp.* ファイルを修正しました
  • クロード コードがサーバーに要求しなかった、キーレス コンソール サインインで「組織によって高速モードが無効になっています」という /fast を修正しました。
  • クロード コードがネットワークなしなどでモデルをチェックできなかった場合に、組織がモデルを制限しているという /model を修正しました。
  • /login でブラウザのステップの直後に Esc キーを押したときに既存のログインを置き換える「コンソール アカウントでサインイン」を修正しました
  • サインインが失敗したりキャンセルされた場合に、ブラウザーにサインイン成功ページが表示される問題を修正しました。
  • claude auth status およびその他の短いコマンドがコンソール プロファイルにロックを残し、次のセッションが約 1 分間ハングする問題を修正しました。
  • バックグラウンド サービスを開始したシェルからの API キーまたはトークンを使用 (および課金) する claude.ai ログインで開始されるバックグラウンド セッションを修正しました
  • セッションがバックグラウンドで別のサインインに移動する多くのケースを修正しました。これらの動きは現在拒否され、何が機能するかを示すメッセージが表示されます
  • バックグラウンドへの移動が拒否された後、終了ダイアログで 2 回目の Enter キーを押すとバックグラウンドでの作業が停止する問題を修正しました。
  • allowedProviders 管理設定で許可されていない場合に、Bedrock に会話を送信する Amazon Bedrock でのトークンカウントを修正しました
  • HOME 環境変数なしで Claude Code を起動すると、AWS credential_process ヘルパーと Google Cloud のデフォルト認証情報が失敗する問題を修正
  • サブエージェントのプランが承認された後、セッションが以前の許可モードに戻ることがある問題を修正しました
  • 以前の呼び出しからのすべての設定をサイレントに破棄するエージェント SDK applyFlagSettings() 呼び出しの 1 つの無効な値を修正しました。これを行う呼び出しはエラーで拒否されるようになりました
  • 完了したプルリクエストに独自のレビューまたはマージのみが必要な場合に、入力待ちとして表示されるセッションを修正しました
  • 警告なしで無視される認識されない teammateMode 設定値を修正しました: claude -p、起動警告、および claude doctor はスキップされたエントリとしてリストされるようになりました (まだ適用されていません)
  • 新しいホーム ディレクトリでの最初の実行時に、CLAUDE_CODE_PLUGIN_SEED_DIR のプラグインから WorktreeCreate フックをスキップする --worktree を修正しました。
  • ディスパッチなどのブリーフモードセッションで、ターンがすでに応答した後に再度応答を送信する問題を修正しました
  • プラグインが別の URL にリストしたときに、動作中の Atlassian、Asana、または Sentry コネクタがクラウド セッションで失敗したとクロードが発言する問題を修正
  • フォルダーの移動または事前ウォームスタート後に、フォルダー自身の MCP サーバー (.mcp.json、ローカル) がホスト追加またはまったく追加されていないものとしてリストされ、WebSocket サーバーに接続されない Claude Desktop および SDK セッションを修正しました。
  • 接続中にプラグインのリロードによってプラグインの MCP サーバーが削除された後も、/mcp がプラグインの MCP サーバーをリストしたままになる問題を修正しました。
  • トークンの更新が一瞬だけ拒否された後、MCP サーバーが「認証が必要」のままになり、その mcp_tool フックがスキップされる問題を修正しました。
  • ツール呼び出し中にサーバーの接続が置き換えられた後、ヘッドレス モードで質問せずに MCP 引き出しリクエストがキャンセルされる問題を修正
  • ツール呼び出しが MCP サーバーに再接続した後、SDK ホストからの MCP ツール呼び出しが「未接続」と応答する問題を修正
  • 質問が Esc キーで閉じられるか、再度質問された後にスタックする MCP タスクを修正しました。フッターには入力が必要であることが表示され、/tasks で Enter を押すと質問が再度表示されます。
  • 同じサーバーへの別の呼び出しが接続を失った後、後の呼び出しが再接続したときに更新を停止するバックグラウンド MCP タスクを修正しました
  • 入力中のメッセージの上にバックグラウンド MCP タスクの質問が開く問題を修正しました。ドラフトを送信またはクリアするまで待機し、スピナーとターン タイマーが動作し続けるようになりました。
  • 2.34 などの古い git バージョンでリポジトリのルート ファイルが除外される worktree.sparsePaths とスパース プラグインおよびマーケットプレイスのクローンを修正しました
  • セッション中に追加されたリポジトリを使用できない複数のリポジトリを含むセルフホスト ランナー セッションを修正しました
  • クロードが自分のアーティファクトまたはそのデータを読み取る前に許可を求める問題を修正
  • 一部のクラウド セッションで適用されないアーティファクト ツールの許可ルールとフックの拒否と確認を修正しました
  • EnterWorktree で入力されたワークツリーを無視し、~ パスをプロジェクトに書き込み、サインインの有効期限が切れた後、/mcp に MCP サーバーが接続されていると表示されたままになるコード モード スクリプトを修正しました。
  • 権限ダイアログまたは計画の承認で「はい」を入力して入力した単語がコードモードのクロードに届かない問題を修正
  • コードモードスクリプト中に終了したセッションを再開すると、クロードが自動的に作業を開始する問題を修正しました。次のプロンプトを待ちます
  • ツール呼び出しの実行中に送信されるメッセージの欠落している OpenTelemetry user_prompt イベントを修正しました。イベントには delivery.mode: "mid_turn" と実行ターンの prompt.id があります
  • VS Code でキューに入れられたメッセージが 1 つのターンにマージされたとき、または 1 つのメッセージに画像が含まれていたときに、以前のメッセージのテキストが省略される OpenTelemetry user_prompt イベントを修正しました。
  • スラッシュコマンドのallowed-tools付与がターン中またはターン後に目覚めたバックグラウンドエージェントに適用される問題を修正
  • サインインしたアカウントまたは組織によって記録された場合にのみ他のセッションをアップロードするように /feedback および /bug を修正しました
  • cd 以降のプロジェクトをカバーしない相対的な拒否および要求許可ルール (Read(./.env) など) を修正しました。追加されたディレクトリにも適用されるようになりました
  • mcp__plugin_*_ で始まる許可ルールの拒否と確認を修正しました。プラグインの MCP サーバーまたは別の大文字で綴られたツールが欠落していました。
  • 自己ホスト型ランナーおよび claude remote-control セッションで、クロード コードの再起動後に到着するアクセス許可の承認に拒否ルールが適用されない問題を修正しました
  • クロード コードがリポジトリの特定のサブフォルダーで開始されたときに、コミットされた .claude/settings.local.json がユーザーのものとして扱われる場合がある問題を修正しました。
  • 特定の Bash コマンドに適用されない拒否ルールと確認ルールを修正しました
  • 一部の複合コマンドが質問せずに実行できる Bash 権限チェックのギャップを修正しました。これらは現在許可を求めています
  • Bash 許可ルールが、指定したプログラムとは異なるプログラムを実行する可能性があるケースを修正しました。
  • プラグインの読み込み中にクラウド セッションでコネクタ ツールの承認プロンプトが自動的に応答される問題を修正しました
  • 一部のサブエージェントが、許可ルールが設定されているか、アップロードが以前に承認されているかを最初に確認せずに、組織外のユーザーが表示できるアーティファクトを変更したり、ファイルをアップロードしたりする問題を修正しました。
  • アーティファクトに対して「次回から質問しない」が選択されている場合に、組織外のユーザーが閲覧できるページの確認をスキップする一部のアーティファクトの公開を修正しました。
  • 組織外の人々が見ることができるアーティファクトへの最初の変更のみを判断する自動モードを修正しました。はい、その変更だけをカバーするようになりました
  • エージェントおよびスキルに対する管理対象の strictPluginOnlyCustomization ロックが、すでに実行されているセッションでは有効にならない問題を修正しました
  • 場合によっては、サンドボックス コマンドがネイティブ アップデーターのダウンロード フォルダーに書き込むことができる問題を修正しました。
  • Bash サンドボックスがワークツリーの設定とフックを完全に保護しなかったケースを修正しました
  • Bash サンドボックスがリンクされたワークツリーの共有 git フォルダーを完全に保護しなかったケースを修正しました
  • いくつかの異常な git 状態における /teleport のスタッシュ選択を修正しました。停止して何をすべきかを指示するようになりました。
  • Windows: アカウントで開けないフォルダーに PATH エントリがある場合に約 1 秒続く可能性がある起動停止を修正しました。
  • Windows 上の /resume が、異なるドライブ文字の大文字またはスラッシュで記録されたフォルダーのセッションを拒否または非表示にする問題を修正しました。
  • セッションが異なるドライブ文字の大文字と小文字で記録された場合に、Windows でセッション中の /resume がプロジェクトの保存済み trust を削除する問題を修正しました。
  • Linux: 作業ディレクトリが denyRead 内の allowRead フォルダーの下 (シンボリックリンクされたホーム ディレクトリの下など) にある場合に、サンドボックス化された Bash コマンドが bwrap: Can't create file で失敗する問題を修正しました。
  • トークン更新が完了するまで (このバージョンが含まれると) Claude Desktop のサードパーティ展開が「停止中」のままになる問題を修正
  • 改善されたサブエージェントは、出力トークンの制限で切断されます。回答の最後だけを返すのではなく、回答全体をもう一度、より短く尋ねられるようになりました。
  • キーレス コンソール サインインまたは他の Anthropic プロファイル ログインによる起動の改善: 資格情報のロックを待たずに、まだ有効なトークンが読み取られます。
  • アカウントの電子メール チェックを改善しました。コマンドの実行、ファイルの書き込み、Web フェッチ、および MCP 呼び出しのスクリプトで、client の ID として電子メールを拒否するようになりました。
  • プライベート プラグイン マーケットプレイスの HTTPS authentication failed メッセージを改善しました。git のターミナル プロンプトと askpass プログラムが無効になっていると表示され、新しい git バージョンでも表示されるようになりました。
  • マーケットプレイスの追加の確認、プラグインの推奨プロンプト、およびプラグインがファイルとシェルにアクセスしてコンピューター上でコードを実行できることを示すプラグインのインストール警告を改善しました。
  • クロード アカウントのサインインの動作を停止する API キー、プロバイダー、または設定を指定するように claude --desktop サインイン エラーを改善しました。
  • macOS および Windows 上の /voice 「音声が検出されませんでした」メッセージを改善しました。マイクを選択する場所が表示されるようになりました。
  • MCP タスクの改善: タスクが回答を待っているときにクロードに通知され、/tasks を指し示すことができるようになりました。
  • claude remote-control の改善: 自動的に停止する場合はステータス 4 で終了し (単一セッションの実行は引き続き終了 0)、登録できない場合はステータス 69 で終了するため、サービス マネージャーが再度開始できるようになります。
  • バックグラウンド セッションがそのセッションの API キーまたはトークンを使用できないときに表示されるメッセージを改善しました。キーを設定に追加することは推奨されなくなりました。
  • バンドルされた dataviz スキルの、静止画像および年齢層などの自然な順序を持つ部分に対する部分から全体へのアドバイスを改善しました。
  • デフォルトで通常の権限フローに従うようにサンドボックス化された Bash コマンドを変更しました。プロンプトなしで実行し続けるように sandbox.autoAllowBashIfSandboxed: true を設定します。
  • サンドボックスを有効にする管理設定を変更しました。プロンプトなしでコマンドを実行し続けるには、最上位の管理ソースで sandbox.autoAllowBashIfSandboxed: true を設定します。
  • 読み取り専用 git コマンドが、プロジェクトのリポジトリまたは自分が rust したリポジトリではないリポジトリで最初に問い合わせるように変更されました。プロンプトなしで実行するには、additionalDirectories 設定ではなく --add-dir という名前を付けます。
  • allowed-tools またはフックを宣言するスキルを実行する前に質問するように、スケジュールされたタスクと /loop を変更しました。無人で実行するには、Skill(name) を permissions.allow に追加します。
  • デスクトップ、IDE、および SDK ホストの「常に許可」を変更しました。ルールのみを保存する場合にのみ提供され、そのコマンドが再び許可されるため、そのルールに依存するスケジュールされたタスクが待機できるようになりました。
  • 起動フォルダーと同様に、追加されたディレクトリ内の .claude 設定、スキル、エージェント、コマンド、フックへのサンドボックス書き込みを拒否するようにサンドボックスを変更しました。
  • 変更されたワークツリー分離: 分離されたワークツリー セッションまたはエージェントは、git bisect run、git maintenance register|start、および scalar のセットアップ コマンドを拒否され、引き続き機能するコマンドが通知されるようになりました。
  • プラグイン MCP バンドル (.mcpb、.dxt) を、プラグイン フォルダー内の .mcpb-cache ではなく、プラグイン ディレクトリの下に解凍するように変更しました。そのため、読み取り専用のプラグイン フォルダーが読み込まれます。 URLで取得したものを再度ダウンロード
  • 管理設定が組織のものとしてカウントするように prependPlugins または appendPlugins で宣言、有効化、およびリストされるリモート マーケットプレイスのプラグインを変更しました。 pluginDigests は非推奨であり、無視されます
  • プラグインのフォルダー内のいくつかの安全でないパスとリンクをスキップするようにプラグインの読み込みを変更し、claude plugin validate を報告するように変更しました。
  • ネストされたスキルの読み込みを変更しました。--plugin-dir プラグインの .claude/skills フォルダーは、その上で開始されたセッションから読み込まれなくなりました。代わりにプラグインフォルダーで Claude Code を起動してください
  • プロジェクト内のシンボリックリンクを経由する WorktreeCreate フック パスを拒否するように EnterWorktree を変更しました。フックに実際のパスを出力させる
  • tmux と iTerm2 のチームメイト、および ← で開かれたエージェント ビューからの新しいセッションが、シェルが最後に実行された場所 (cd) ではなく、セッションのフォルダーで開始されるように変更されました。
  • バックグラウンドタスクまたはスケジュールされたタスクによって連続して開始された 8 ターン後に更新頻度が低くなるようにターミナルのプロンプト提案を変更し、キーを押すかターミナルに戻るまで使用量を節約します
  • バックグラウンド MCP タスクの質問の Esc キーを「後で回答する」に変更しました。サーバーには何も送信されず、質問は /tasks に残ります。
  • ゲートウェイの claude-sonnet-latest など、claude- で始まる認識できないモデル ID のコンテキスト ウィンドウも設定するように CLAUDE_CODE_MAX_CONTEXT_TOKENS を変更しました。
  • プライバシー設定を変更する許可を求めるように /login を変更しました
  • MOD の $.model.complete および $.model.classify 呼び出しをカウントするための /cost、$.session.usage()、--max-budget-usd、およびコストとトークンのメトリクスを変更しました
  • クロード コードのサンドボックスが独自の使用のために開始するプログラム (ネットワーク ブリッジなど) を、環境内でクロード コードのサインイン トークンと API キーなしで実行するように変更しました。
  • ripgrep、ローカル git コマンド、およびサンドボックス ランタイム独自のヘルパー プログラムが、環境内で mTLS client キーのパスフレーズなしで実行されるように変更されました。
  • リモート コントロール: 接続されたセッションに共有リンクがある場合、または共有リンクが確認できない場合に最初に切断するように /resume および /teleport を変更しました。 /remote-control を実行して再度接続します
  • sandbox.failIfUnavailable にもかかわらず、ウェブ上のクロード コード、クラウドのスケジュールされたタスク、および Cowork クラウド セッションが開始されるように変更しました: ホストされたコンテナーにはコマンド サンドボックスがありません
  • クラウドまたは自己ホスト型セッションの接続を介した設定、許可ルール、フックまたはステータスのリクエストが返される量が少なくなるか、拒否されるように変更されました。セッションに適用される内容は変更されません
  • キャッシュされたアカウント データのない claude -p が、最初のリクエストの前にそのデータを待機するように変更され、クリーンな環境での最初の実行が数秒後に開始できるようになりました。
  • クロードの指示を変更し、必要なファイルを一時的なスクラッチパッド フォルダーに保管しないよう変更しました。このフォルダーはクリアできます。
  • ブランチまたはタグ上のコミットの完全な ID を受け入れるようにマーケットプレイス ref を変更しました。このバージョンより前の clients はそのようなピンを複製できないため、この方法で固定されたマーケットプレイスはそこで読み込みを停止します
  • ALL_PROXY が唯一のプロキシ セットである場合に CONNECT トンネルを使用するようにプラグイン マーケットプレイスとプラグインのダウンロードを変更しました。 CONNECT を拒否したプロキシは失敗するようになりました
  • -p および SDK は、フォルダーが trust された場合にのみ .claude/settings.local.json 許可ルールを適用するように、コンテナーにマウントされたワークツリーまたはサブモジュールで実行されるように変更されました。
  • checkout フックのチェックアウト以外のセッション フォルダーまたはリポジトリ パスがシンボリック リンクであるセッションを拒否するようにセルフホスト ランナーを変更しました。
  • クラウド セッションおよびリモート コントロールでの使用制限および共有予算エラーから「管理者に引き上げるよう依頼する」を削除しました。
  • [VSCode] ターミナルに表示されるプロンプトの提案を追加しました。タブは提案された次のプロンプトを受け入れます。クロード コードの設定の promptSuggestionEnabled: false。json でオフになります。
  • [VSCode] API キーを作成しないコンソール サインインを追加しました
  • [VSCode] SSH、WSL、およびコンテナウィンドウのパネルからMCPサーバーにサインインするときにリダイレクトURLを貼り付けるフィールドを追加しました
  • [VSCode] Claude Codeを別のモデルで再起動するか、リモートコントロールでモデルを切り替えた後、モデルピッカーのチェックマークが古いモデルのままになる問題を修正しました。
  • [VSCode] 組織によって設定された努力上限または maxEffortLevel 設定を超えるレベルを提供する努力セレクターを修正しました
  • [VSCode] マネージド allowedProviders 設定が拒否するサインイン画面を修正しました
  • [VSCode] MCP ツールの許可プロンプトで、安全性チェックで疑問が生じたときにクロード コードが尋ねる理由が表示されない問題を修正しました。
  • [VSCode] 組織設定を読み込めなかった場合に、コマンドを再度実行するようにというメッセージが修正されました。タブの「再試行」リンクと一致して、再試行するように指示されます。
  • [VSCode] untrusted フォルダーに表示されるメモを改善しました。拡張機能がオフになっている理由とオンにする方法が表示されるようになりました。
  • [VSCode] システムがクロード コードの実行を拒否したときに表示されるエラーを改善しました。IT チームはブロックされたプログラムを許可できると表示されるようになりました。
  • [VSCode] ブラウザーにローカルホストの接続エラーが表示された場合の対処方法を示すサインイン カードを改善しました。
  • [VSCode] インストールリンクのマーケットプレイス確認ボタンを「Trust マーケットプレイスで続行」に変更しました
  • [Web 上の Claude Code] 新しいクラウド セッションで、ツール検索を通じて読み込まれた MCP ツールの説明が 4,096 文字でカットされていた問題を修正しました。他のクロード コード セッションと同様に、制限は 16,384 になりました。
  • [Claude Tag] 組織が管理していないワークスペースで投稿者のクロードのサインインが期限切れになった場合、Slack に貼り付けられたアーティファクト リンクにカードが表示されない問題を修正しました。普通のカードが表示されるようになりました

claude-code v2.1.325

What's changed

  • Fixed a security issue in how zstd-compressed responses are decoded
  • Added a spinner tip in VS Code and similar integrated terminals about re-running a notebook cell, shown once Claude has read or edited a Jupyter notebook
  • Added a line under the error shown when your organization's policy blocks a request, saying how to continue: run /rewind and change the message, or run /clear
  • Added a note for Claude when a sandboxed git checkout, git stash or autostash pull cannot update protected files such as those in .claude
  • Fixed /security-review and skills' inline git commands stopping with an error in worktrees of bare repositories, --separate-git-dir checkouts and Android repo checkouts
  • Fixed subagents with their own model being moved to the plan-mode model when the model setting is opusplan or haiku
  • Fixed subagents on a different model sizing file reads and MCP results with the main session's model
  • Fixed sessions on many third-party gateways and Foundry stopping with a context length error on every turn instead of compacting
  • Fixed recent turns sometimes going missing from a resumed session after Claude Code stopped without a clean exit
  • Fixed shell commands running in the launch directory after the working directory was deleted; the command now fails with a message and can be re-issued
  • Fixed an approved plan edit being lost when the plansDirectory folder can't take it: the plan is now saved in the default plans folder, and a warning says where and why

  • Fixed sessions showing as waiting for input when a finished pull request only needed your own review or merge

  • Fixed --worktree skipping a WorktreeCreate hook from a plugin in CLAUDE_CODE_PLUGIN_SEED_DIR on the first run in a new home directory

  • Fixed Claude starting work by itself when you resumed a session that ended during a Code Mode script; it now waits for your next prompt

  • Fixed sandboxed commands being able to write to the native updater's download folder in some cases

  • Fixed a case where the Bash sandbox did not fully protect a linked worktree's shared git folder

  • Fixed /resume on Windows refusing or hiding sessions whose folder was recorded with a different drive-letter case or slashes
  • Fixed an in-session /resume on Windows dropping a project's saved trust when the session was recorded with a different drive-letter case
  • Linux: Fixed sandboxed Bash commands failing with bwrap: Can't create file when the working directory was below an allowRead folder inside a denyRead, such as under a symlinked home directory
  • Fixed Claude Desktop's third-party deployments staying on "Stopping" until a token renewal finished (once it includes this version)
  • Improved subagents cut off at the output token limit: they are now asked for the whole answer again, more briefly, instead of returning only its end
  • Improved startup with a keyless Console sign-in or other Anthropic profile login: a token that is still valid is read without waiting for the credentials lock
  • Improved the account email check: it now also refuses your email as a client's identity in scripts a command runs, file writes, web fetches and MCP calls
  • Improved the HTTPS authentication failed message for private plugin marketplaces: it now says git's terminal prompts and askpass programs are disabled, and it also appears with newer git versions
  • Improved the add-marketplace confirmations, plugin recommendation prompts and plugin install warning to say that plugins can run code on your computer, with access to your files and shell

  • Improved the /voice "No audio detected" message on macOS and Windows: it now says where to pick your microphone
