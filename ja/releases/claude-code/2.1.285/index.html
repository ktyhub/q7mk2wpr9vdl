claude-code v2.1.285

パッチ 公開日2026年9月29日 出典anthropics/claude-code English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

クロードコード v2.1.285

何が変わったのか

  • WebFetch ツールをオフにするための CLAUDE_CODE_DISABLE_WEB_FETCH 環境変数を追加しました
  • 現在のディレクトリ、または --continue / --resume <id> とのセッションでクロード デスクトップ アプリを開くための claude --desktop を追加しました。
  • プラグインのオプションと未設定のオプションを表示するため、または --values-stdin を使用して標準入力から読み取った新しい値を保存するための claude plugin configure <plugin> を追加しました。
  • <server>.<key>=<value> を claude plugin install --config に追加したため、バンドルされた .mcpb MCP サーバー独自の設定をインストール時に設定でき、/plugin → Configure にアクセスすることなく起動できます。
  • マシンが使用できる API プロバイダー (Anthropic API、カスタム エンドポイント、Bedrock、Mantle、Vertex AI、Foundry、AWS 上の Claude Platform、またはクラウド ゲートウェイ) を制限するための allowedProviders 管理設定を追加しました。
  • タイムアウトした非ストリーミング フォールバック リクエストの再送信を制限するための CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES 環境変数を追加しました
  • claude -p と CLAUDE_CODE_FORK_SUBAGENT=1 を修正しました。サブエージェント自身のエージェント呼び出しがフォアグラウンドで実行されるようになったため、サブエージェントは子の結果を取得します。
  • GIT_SSH または git config の core.sshCommand に設定された ssh プログラムを無視して SSH 経由でプラグインとマーケットプレイスのインストールと更新を行う問題を修正しました。
  • OS が管理設定ファイルの読み取りを拒否した場合にクロード コードの起動が拒否される問題を修正しました。警告が表示され、そのファイルのポリシーなしで開始されるようになりました。その他の読み取りエラーや解析不可能なファイルはすべてのセッションを停止します
  • 会話が圧縮された後に再起動されたクラウド セッションが、セッションがすでに読み取ったか公開したアーティファクトへの次の更新を拒否する問題を修正しました。
  • 完全な name@marketplace ID を持つ claude plugin disable および enable が、インストールされているプラグイン独自の設定エントリではなく、別の大文字で設定エントリを変更する問題を修正しました。
  • リモート コントロール経由で送信されたメッセージに添付されたファイルが、ダウンロードが 1 回失敗した後に残される問題を修正しました。ネットワーク エラー、タイムアウト、またはサーバー エラーが発生した場合、最大 2 回まで再試行されるようになりました。
  • set_model リクエスト (エージェント SDK の setModel など) によるセッション中のモデルの切り替えを修正し、再起動するまで新しいモデルが組み込みの出力トークン制限と自動圧縮ウィンドウのままになるようにしました。
  • @ を含む URL パスワードの一部、または URL が @ を %40 として書き込む場合のそのすべてを示す編集されたログとトランスクリプトを修正しました。
  • ワークツリーからの SSH パスフレーズと新しいホスト プロンプト、およびターミナルを引き継ぐ /teleport フェッチを修正しました。これらのフェッチは、要求する代わりに高速に失敗するようになりました。
  • SDK および -p セッションでセッション中に追加された MCP サーバーのスイッチがオフになり、ツールが利用可能な状態になる問題を修正
  • claude -p --permission-prompt-tool を修正: バックグラウンド サブエージェントの権限リクエストは、自動的に拒否されるのではなく、プロンプト ツールに送られるようになりました。
  • claude mcp list と claude mcp get、および MCP サーバー名と値から改行と端末エスケープ シーケンスを出力する claude mcp remove、login、logout の見つからないエラーを修正しました。
  • = が含まれているという理由だけで、多くのインライン スクリプト (python3 -c、node -e) を実行するたびに承認を求めるサンドボックスの自動許可を修正しました。
  • フォーク サブエージェントがセッションのプラン モードまたは dontAsk モードを維持しない問題を修正しました。フォークは親の権限モードで実行され、プラン モードを終了できなくなりました。
  • --[no-]chrome がマシンの /chrome 設定のデフォルトであると言う claude remote-control --help を修正しました。生成されたセッションでは、--chrome が渡されない限り、Chrome のクロードがオフのままになります
  • 各レポートの後に 2 番目の冗長な応答を求める自動モードのバックグラウンド サブエージェントを修正しました
  • クラウド セッションの作成と /remote-env がアカウントの環境の最新 20 件のみを読み取る問題を修正しました
  • クロードがメッセージを開始したときではなく、到着するとすぐにメッセージを既読としてマークするリモート コントロールと、端末が終了するとキューに残っているメッセージが失われる問題を修正しました (メッセージは次の再開時に到着するようになりました)
  • claude plugin install または /plugin を使用してプラグインをインストールすると、ID が .、-、@ または (macOS、Windows) capitals でのみ異なる場合に、インストールされているプラグインのキャッシュまたはデータ フォルダーに配置される問題を修正しました。インストールは拒否されました
  • プランが同じ応答に書き込まれたときに、ExitPlanMode で欠落しているプランまたは古いプランが表示されるフックと SDK 権限コールバックを修正しました。
  • クラウド セッションでの最初の応答が数十ミリ秒遅れて到着する問題、2.1.283 の回帰を修正しました
  • Anthropic API に対して ANTHROPIC_AUTH_TOKEN で認証するセッションが組織のポリシーをロードしない問題を修正しました
  • ワークフロー スクリプトが後で待機する、またはまったく待機しない失敗した agent()、parallel()、または pipeline() 呼び出しが、未処理の Promise 拒否として扱われ、バックグラウンド セッションが終了する可能性がある問題を修正しました。
  • フックが開始したバックグラウンド プロセス (some-daemon & など) が出力を開いたままにしている間、同期フックがクロード コードをハングさせていた問題を修正しました。フックは、自身のプロセスが終了した直後に終了するようになりました。
  • レート制限されたドメインの安全性チェックをネットワークまたはエンタープライズ ポリシー ブロックとして報告する WebFetch を修正しました
  • フルスクリーンの Ctrl+O トランスクリプトを数百回のファイル読み取りまたは検索で開くと一時的にフリーズする問題を修正しました。トランスクリプトを開いたときにツール呼び出しがまだ実行中であるため、終了時に結果が表示されるようになりました。
  • エラーメッセージの代わりに生の JSON 本文が表示される Amazon Bedrock のミッドストリーム modelTimeoutException および serviceUnavailableException エラーを修正しました
  • クロード GitHub アプリがインストール ステータスがまだチェックされていないリポジトリにインストールされていないと言う /autofix-pr と /schedule を修正しました
  • /artifacts の行 (x) を閉じるとアーティファクトからファイルのリンクが解除される問題を修正しました。そのため、同じファイルを再度公開すると、更新ではなく新しいアーティファクトが作成されました。
  • 会話の巻き戻し (Esc Esc) 後にアーティファクト ツールが公開され、クロードが巻き戻しターンでのみ読み取ったファイルの新しいコンテンツが上書きされる問題を修正しました。クロードがファイルを再度読み取るまで、公開は拒否されます。
  • Artifact ツールが確認せずに作業ディレクトリの外にファイルを公開できるようにする Artifact 許可ルール (「再度確認しない」) を修正しました。ルールがそれをカバーするように、--add-dir を含むファイルのフォルダーを追加します。
  • サーバーが client が予期していたものとは異なるフォールバック モデルで拒否に応答したときに、間違ったモデルでターンを報告する /cost および SDK modelUsage を修正しました。
  • アーティファクト ツールを修正し、クロードの以前の読み取りが途中で中断された場合、またはファイルが変更されてからページが公開された場合に、クロードが再読み取りせずにソース ファイルを上書きできないようにしました。
  • 別の権限モードでアーティファクトを以前に承認していた場合に、アーティファクト ツール アセットのアップロードと他の人のアーティファクトの読み取りの分類子をスキップする自動モードを修正しました
  • プロジェクトフォルダーを一時的に読み取れなかった場合の、/ultrareview からの誤解を招く「core.worktree が設定されています」エラーを修正しました
  • ワークツリーごとの設定が core.longpaths に設定されている git ワークツリーから作業ツリーをアップロードできない、macOS および Linux 上の /ultrareview を修正しました。
  • 一時的なサーバーエラーの再試行後、最初の試行が実際には成功した場合に、アーティファクトツールがパブリッシュを別のセッションとの競合として報告することがある問題を修正しました
  • server:8443.key など、名前の拡張子の前にコロンが付いている認証情報ファイルに対するコミットされていない変更を含む /ultrareview アップロードを修正しました。
  • クラッシュしたプロセスによって残されたログイン更新ロックを 2 つのセッションが同時に回復するときに発生する稀な認証エラーを修正しました
  • コマンド パーサーの起動に失敗した場合 (たとえば、マシンのメモリが不足している場合)、PowerShell ツールの権限チェックが拒否ルールと確認ルールをスキップし、後のチェックのためにその失敗をキャッシュする問題を修正しました。
  • macOS および Linux での /ultrareview アップロードが一部の異常なファイル名で実行が遅くなる問題と、資格情報ファイル チェックで多くのバックアップ マークまたはエディタ マークが付いたファイル名またはフォルダ名が欠落している問題を修正しました。
  • セットアップ中にキャンセルが到着したときに、キャンセルされたシェル コマンドまたはフックがまだ開始され、最後まで実行される問題を修正しました。
  • vim モードの修正: 外部エディター (Ctrl+G) で編集した後、NORMAL モードの x または r は、プロンプトの最後に貼り付けられたテキストのプレースホルダーを破壊しなくなりました。
  • API の出力コンテンツ フィルターによってブロックされた応答が、フィルターのエラーをすぐに表示せずに、場合によっては数分間再送信および再試行される問題を修正しました。
  • まだ設定が必要なバンドルされた .mcpb MCP サーバーをサイレントにスキップするプラグインを修正しました: /plugin、インストール メッセージと claude plugin install がそのように表示し、設定をポイントするようになりました。
  • セッションの圧縮または再開が失敗する、履歴なしで開く、または保存されたトランスクリプトに圧縮マーカーまたはフィールドが欠落しているか不正な形式のループ ウェイクアップ エントリが保持されている場合にクラッシュする問題を修正しました。
  • WSL: 変更されたファイル名にコロンが含まれているか、ドットまたはスペースで終わっている場合、/ultrareview が Linux ボリュームへのチェックアウトのアップロードを拒否する問題を修正しました。
  • --max-turnsで終了したターンをCLAUDE_CODE_RESUME_INTERRUPTED_TURNが再実行する問題を修正
  • ブラウザーが成功を示した後、永遠に待機する可能性があるサインインを修正しました
  • Windows: 場合によっては、ホーム フォルダーをルートとするリポジトリのリンクされたワークツリーをアップロードする /ultrareview を修正しました。
  • ファイルがアップロードされる前に、アップロード フォルダーが見つからないと報告するクラウド セッションを修正しました
  • 保留中のコマンドを承認する許可プロンプトを待機しているバックグラウンド セッションに claude agents から送信される応答を修正しました
  • シェルエイリアスなどからオプションが前にある場合に、コマンド名をプロンプトとして使用して新しいセッションを開始する claude attach、logs、stop、respawn および rm を修正しました。
  • WebSocket (ws) MCP サーバーを除外する claude mcp list を修正しました。それぞれが URL とヘルスステータスとともにリストされるようになりました。
  • 設定エントリで type フィールドが省略されている stdio サーバーのタイプ、コマンド、引数、環境が表示されない claude mcp get を修正しました。
  • git の Trace2 出力が設定されている場合、.claude/settings.local.json 許可ルールが Git リポジトリの外で保留される問題を修正しました
  • /claude-api 評価ランナー スキャフォールドと、出力ファイルに植えられたシンボリックリンクまたはハード リンクを介したレポート ビルダーの書き込みを修正しました。
  • スコア平均において、/claude-api 評価ランナー スキャフォールドのカウント応答が max_tokens で切れていた問題を修正しました。切り捨てられたマークが付けられ、個別にカウントされるようになりました。
  • 返信でテキスト (マークダウン テーブルの行ラベルなど) をインデントするために &nbsp; が使用される場合、ターミナルでリテラル テキストとして表示される &nbsp; を修正しました。
  • フルスクリーン モード以外での長いセッションの途中で発生した短時間のフリーズ (最大 1 秒) を修正しました。これは、/clear または /compact の後に再発しました。
  • ターゲットがデバイス (/dev/null にシンボリックリンクされているファイルなど) であり、承認が IDE の差分ビューから取得されたか編集が変更された場合、承認された編集が決して完了しない問題を修正しました。
  • ストリーミングが失敗し続けると、失敗した API リクエストが最大 21 回再試行される問題を修正しました。非ストリーミング フォールバックは、新しい再試行セットを取得するのではなく、リクエストの再試行バジェットを共有するようになりました。
  • Chrome のクロードの改善: ネイティブ ホストがコンピューター名を報告するようになり、接続されているブラウザーを「ブラウザ 1」/「ブラウザ 2」ではなくコンピューターごとにラベル付けできるようになりました。
  • 管理者がデフォルト モデルへのアクセスを削除した場合に、失敗するのではなく、同じ層の古い利用可能なモデルに切り替えるように Bedrock および Vertex AI セッションを改善しました。セッションのタイトルと概要はそれにフォールバックするようになりました
  • エンタープライズ ポリシーを引用する代わりに、git アドレスが拒否される理由を示すプラグイン マーケットプレイスのエラーを改善しました
  • プラグイン、マーケットプレイス、現在のリポジトリのリモートの git URL の検証が改善されました。
  • アーティファクト ツールの結果の改善: ページの作成または編集と同じ手順で公開することを提案するようになり、ラウンドトリップを節約できます。
  • リモート コントロールの改善: Claude Desktop などのアプリによってホストされているセッションについて尋ねられた /btw のサイド質問では、最後に終了したターンだけでなく、進行中のターンも表示されるようになりました。
  • クロードが BMP、HEIC、HEIF、AVIF、または TIFF ファイルとして送信する画像の改善: クロード アプリには、クロード コードが変換できるプレビューが表示されるようになりました。
  • 自動モードでのサブエージェントの改善: サブエージェントの実行は、誰にも到達しない余分なターンを行うのではなく、呼び出し元にレポートを返すとすぐに終了するようになりました。
  • Bedrock および Vertex の起動モデル チェックの改善: アカウントで使用できないモデルは、起動のたびに再チェックされるのではなく、最大 1 日まで記憶されるようになりました。
  • アーティファクト ツールのパブリッシュ結果が改善され、使用するトークンが減りました。アーティファクトの更新に関するメモが短くなり、パブリッシュのたびにアーティファクトを見つける場所が繰り返されなくなりました。
  • 非ストリーミング フォールバック リクエスト中の SDK のライブネスの向上: 部分メッセージをオンにすると、ping ストリーム イベントが Anthropic API、AWS 上のクロード プラットフォーム、およびゲートウェイで 30 秒ごとに送信されるようになりました。
  • バックグラウンドで実行されているセッションの /resume および claude --resume を改善しました。拒否する代わりにそのセッションを開き、claude --resume <id> "prompt" で与えられたプロンプトが次のターンとしてセッションに送信されるようになりました。
  • 多くの権限拒否ルールと MCP ツールが設定されている場合のターンごとのパフォーマンスの向上
  • フルスクリーン レンダリングがオフになっているときに、長時間セッションで Ctrl+O トランスクリプト ビューを終了するときの応答性が向上しました。
  • 通常のリクエストと同じ User-Agent、x-app、およびセッション ID ヘッダーを送信するために、Bedrock、Vertex、および Mantle の起動モデル チェックを改善しました。
  • MCP ツールを変更し、--mcp-config、エージェント SDK、またはプラグイン サーバーが alwaysLoad に設定されている場合、独自の _meta['anthropic/alwaysLoad'] を false に設定するツールが延期されたままになるようにしました。
  • バックグラウンドの Bash および PowerShell コマンドが制限時間後に停止するように変更されました (timeout と run_in_background、デフォルトは 30 分、最大 2 時間)。誰かが停止するとクロードに通知されます
  • コード レビューのプル リクエスト レビューと /ultrareview が、レビューを実行しているマシンが独自の管理者 (MDM または管理設定ファイル) によって設定されていない限り、disableWorkflows がオンのときに実行されるように変更されました。
  • カスタム ANTHROPIC_BASE_URL の背後にあるセッションを変更し、1M コンテキスト ウィンドウを持つモデル (Opus 4.7+、Sonnet 5+、Fable) を使用するようにしました。ゲートウェイが 200K で停止した場合は、/autocompact 200k を実行します
  • チーム セッションとエンタープライズ セッション、およびサインイン プラン クロード コードが決定できないセッションで、起動時に組織ポリシーを読み込めなかった場合に、組織ポリシーが読み込まれるまで WebFetch を保留するように変更しました。
  • /memory を変更し、バックグラウンド セッションまたはクロード コード独自のツールのいずれかが開始されたセッションから自動メモリをオンにできなくなりました。オフにしてもまだ動作します
  • ユーザー設定がデフォルトで別のモードになっている場合に、サードパーティのプロバイダーやテレメトリがオフの場合にも表示されるように、自動モードをデフォルトの許可モードにするようにワンタイム オファーを変更しました。
