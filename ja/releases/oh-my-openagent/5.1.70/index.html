オーマイオープンエージェント v5.1.70

単純な omo login は、OmO アカウントが閉じられている間にターミナルからコンピューターにサインインします。 OmO デスクトップ アプリを持たないコンピューター (SSH 経由のサーバー、新しい Linux ボックス) は omo login を実行し、別のデバイスで承認するためのデバイス コードを取得し、OS 資格情報ストアに資格情報を保存します。 Attach-before-mint 拒否 (#13096) は、サービスに何かが要求される前に、既にデバイスを備えているコンピューターに応答します。成功行では、サインインしたアカウント (Signed in to OmO as <email>.) に名前を付け、omo whoami もそのアカウントに名前を付けます。失敗したアカウントの読み取りには、それを確認する方法が記載されています。 omo logout と omo whoami は閉じている間も実行されるため、コマンドを拒否するメッセージはありません。 login --help はルートを記述し (コマンドは omo --help から隠蔽されたままになります)、他のすべての閉じられた login フォームはルートに名前を付けるメッセージで拒否され、閉じられたヒントは両方のルートに名前を付けます。コンパイルされたエントリは、コマンドが使用するのと同じ共有解析 (login -- を含む) でワンショット起動として裸の login、logout、および whoami を分類します。破損したアイテムのメッセージでは、デスクトップ アプリのみの行き止まりではなく、ターミナル ルートも指定されます。テストは、npm ランチャー (このソースからランチャー ツリーの一時コピーに構築されたサービス認証バンドルに対して)、コンパイルされたエントリ、およびツールキット CLI を介してフローを実行します。このとき、分離された HOME とランタイム ディレクトリ、継承されたセッション バスなし、挿入されたストア、およびすべてのゼロミント ケースでの拒否テキスト アサーションが使用されます。 (#13281) (#13328)

コンピューター使用の適合性プリフライト テストは Windows で合格します。 ドライバーが見つからないメッセージは、すべての OS でスラッシュを含むリポジトリ相対パスを出力するようになりました。そのため、実行はすべてのホストで同じものを読み取り、stdio-probe テストは、POSIX シェル スクリプトではなく、ホストの実際の実行可能ファイルとして代用エンジンを構築します。 QA ツールのみ。実行時の動作は変わりません。 (#13295、#13221の一部)

コンピュータの使用は、QA の宣言された結果適合カタログを取得します。 script/qa/computer/conformance/ は、各 OS 上のすべてのアクション、ツールキット、およびモード セルが正確なエンジン コードで配信または拒否することを宣言する型付きカタログ、欠落、重複、スキップ、またはミスコーディングされたセル、またはユーザーのセッションを妨害したセルを失敗したレポート、ENVIRONMENT_ERROR として壊れたホストの実行を終了する環境プリフライト、および 12 を追加します。モデルフリーの参照タスク。 QA ツールのみ。実行時の動作は変わりません。 (#13241、#13221の一部)

デスクトップ セッションのアクション可能性待機テストは、ビジーなホストで失敗しなくなりました。 バッテリーの待機は、注入可能なクロックで実行されるようになりました。つまり、以前と同様に、セッション内のホストの単調時間と、テスト内の偽のバックエンド自体のクロックです。したがって、the_battery_waits_for_an_element_that_appears_enabled_after_500_ms は、ホスト負荷が破る可能性がある実時間の境界ではなく、偽の時間で 500 ミリ秒の待機をチェックします。実行時の動作は変わりません。 (#13180、#13178 を修正) ファジー ハンドオフは、終了したセッションが多数あるアカウントで失敗しなくなり、正確な名前とは異なるセッションに移行することはなくなりました。 ファジー ハンドオフは、他のデバイスで終了したものも含め、すべてのセッションでスレッドの正確な ID、エイリアス、または名前を最初に試行するため、1 つのセッションに正確に一致する名前が常にそのセッションに到達します。それ以外の場合は、ローカル、ライブ、および終了したセッションが比較され、どこに存在しても明らかに最良の一致が勝ちます。同等に優れた 2 つの一致がある場合は、どちらを選択するかを選択してください。一致できない終了したセッションは、500 候補のファジー キャップにカウントされなくなりました。そのため、大きな履歴によって一意の一致がブロックされることはなくなりました。 (#13141、#13066 に続きます)

エイリアス要求が作成後にサインインを要求するスレッドは、引き続きエイリアスによって名前が付けられます。 thread_create がエイリアスを確認してからその要求を行うまでの間にアカウント トークンの有効期限が切れると、すでに作成されているスレッドにはデバイス上のエイリアスによって名前が付けられ、呼び出しは ok に対してエラーではなく alias_scope: "local" で応答します。 thread_rename は、請求によりアカウントがなくなった場合にも同じことを行います。ローカル名として使用されるエイリアスがすべてのパスで削除されるようになりました。 (#13179、#13112 に続きます) (#13141)

omo login は、既にデバイスを持っているコンピューターに 2 番目のデバイスを登録しなくなりました。 コード、ブラウザー タブ、または新しいキーの前に、保存されているサインインと、コンピューターの OmO デバイス サービスが保持するデバイス (パークを含む) がチェックされます。保留、不確実、ロック、または読み取り不能の状態では、デスクトップの横に「omo CLI on <host>」行を追加する代わりに、新しいデバイスが拒否され、既存のデバイスが保持されます。サービスがマシン ID をアドバタイズすると、両方のサインイン フローがハッシュ化されたハードウェア ID (SHA256("omo-machine-v1" + id)、生の ID がコンピューターから離れることはありません) を送信し、machine_exists の拒否により、デバイスの削除や引き継ぎを行わずにサインインが終了します。 (#13096) (#13141)

アカウントがサインインしていない場合、スレッド エイリアスがスレッドの作成をブロックしなくなりました。 thread_create と alias は、エイリアス レジストリがアカウント トークンを取得できない場合にスレッドを作成するようになりました。デスクトップ起動は常にその状態になります。 name が指定されない限り、エイリアスはスレッドのローカル名になり、結果はエイリアスがローカルのみ (alias_scope: "local") であることを示します。エイリアスを持つ thread_rename も同様です。他のすべてのエイリアス エラーは変更されません。 (#13112、#13104 を修正)

修正: ファイルはバンドルされたブンシン SDK を介して再びリレー動作を読み取ります (readText、readBytes、および read は「切り捨てられたバイト結果のブール値である必要があります」で拒否されなくなりました)。ミントされた機能トークンで送信された操作は不正な形式として拒否されなくなり、サポートされていない clientName は、サポートされているロールに名前を付ける invalid_client_name で一度に失敗するようになりました。 (#13108)

プログラミング スキルは、コードの所有権から始まります。 その最初の段落では、モデルがコードを所有していることを伝えます。新しい動作を既存の構造に適合させ、重複したコードや無効なコードを残さず、変更されているコードの欠陥を、既存のものまたは他の人のものとして言い訳するのではなく、根本原因で修正します。これは、「怠惰な上級エンジニア」というペルソナ ラインを置き換えるものです。 (#13091)

モニターは、前のバッチの送信中に到着したバッチを失わなくなりました。 flushMonitor は、ディスパッチを待機した後にモニターの保留中のエントリを削除したため、待機中にキューに入れられたバッチはドロップされたものとしてカウントされずに消えました。フラッシュは、エントリがまだ排出されたものである場合にのみエントリを削除するようになりました。 (#13089)

フォアグラウンド タスクは、一度に失敗するのではなく、その子を待ちます。 run_in_background: false を伴うすべての task は、約 1 秒以内に Session error で終了し、子を中止しました。これは、opencode が実行中のアシスタント ターンを error: null で報告し、ポーラーがキー自体を失敗として扱ったためです。現在は、設定されたエラーのみが子を終了します。 (#13076)

oh-my-openagent v5.1.70

Plain omo login signs a computer in from the terminal while OmO accounts are closed. A computer with no OmO desktop app — a server over SSH, a fresh Linux box — runs omo login, gets a device code to approve on another device, and stores the credential in the OS credential store; the attach-before-mint refusal (#13096) answers a computer that already has its device before anything is asked of the service. The success line names the signed-in account (Signed in to OmO as <email>.), and omo whoami names it too; a failed account read still says how to see it. omo logout and omo whoami run while closed, so no message names a command that refuses. login --help describes the route (the command stays hidden from omo --help), every other closed login form refuses with a message that names the route, the closed hints name both routes, and the compiled entry classifies bare login, logout and whoami as one-shot launches with the same shared parse the command uses (login -- included). The damaged-item message names the terminal route too instead of a desktop-app-only dead end. Tests run the flow through the npm launcher (against a service-auth bundle built from this source into a temp copy of the launcher tree), the compiled entry and the toolkit CLI, with an isolated HOME and runtime dir, no inherited session bus, an injected store, and a refusal-text assertion on every zero-mint case. (#13281) (#13328)

The computer-use conformance preflight tests pass on Windows. The missing-driver message now prints its repo-relative path with forward slashes on every OS, so a run reads the same on every host, and the stdio-probe test builds its stand-in engine as a real executable for the host instead of a POSIX shell script. QA tooling only; no runtime behaviour changes. (#13295, part of #13221)

Computer use gets a declared-outcome conformance catalog for its QA. script/qa/computer/conformance/ adds a typed catalog in which every action, toolkit and mode cell on each OS declares that it delivers or refuses with an exact engine code, a report that fails a missing, duplicate, skipped or mis-coded cell or one that disturbed the person's session, an environment preflight that ends a broken host's run as ENVIRONMENT_ERROR, and twelve model-free reference tasks. QA tooling only; no runtime behaviour changes. (#13241, part of #13221)

The desktop session's actionability wait test no longer fails on a busy host. The battery's wait now runs on an injectable clock: the host's monotonic time in a session, as before, and the fake backend's own clock in the test. So the_battery_waits_for_an_element_that_appears_enabled_after_500_ms checks the 500 ms wait in fake time instead of wall-clock bounds that host load could break. Runtime behaviour does not change. (#13180, fixes #13178)

A fuzzy handoff no longer fails on an account with many ended sessions, and never goes to a different session than an exact name would. A fuzzy handoff first tries the thread's exact id, alias or name across every session, ended ones on other devices included, so a name that exactly matches one session always reaches that session. Otherwise local, live and ended sessions are compared together and the clearly best match wins wherever it lives; two equally good matches ask you to pick. Ended sessions that cannot match no longer count against the 500-candidate fuzzy cap, so a large history no longer blocks a unique match. (#13141, follows #13066)

A thread whose alias claim asks for a sign-in after it was created is still named by the alias. When the account token expires between thread_create checking an alias and claiming it, the thread it already created is now named by the alias on its device and the call answers ok with alias_scope: "local", instead of an error. thread_rename does the same when the account is gone by the claim. An alias used as a local name is now trimmed on every path. (#13179, follows #13112) (#13141)

omo login no longer registers a second device for a computer that already has one. Before any code, browser tab or new key, it checks the stored sign-in and the device the computer's OmO device service holds (parked included). A held, uncertain, locked or unreadable state refuses a new device and keeps the existing one, instead of adding an "omo CLI on <host>" row beside the desktop's. When the service advertises machine identity, both sign-in flows send a hashed hardware id (SHA256("omo-machine-v1" + id); the raw id never leaves the computer), and a machine_exists refusal ends the sign-in without removing or taking over any device. (#13096) (#13141)

A thread alias no longer blocks thread creation when no account is signed in. thread_create with an alias now creates the thread when the alias registry cannot get an account token. A desktop launch is always in that state. The alias becomes the thread's local name unless a name is given, and the result says the alias is local only (alias_scope: "local"). thread_rename with an alias does the same. Every other alias error is unchanged. (#13112, fixes #13104)

One computer is one OmO device: omo login binds to the machine's device service instead of registering its own. A sign-in now advertises machine binding. When the service asks for the machine hash, omo asks this machine's device service (device.machine_binding) for it, and computes the same hash itself when no device service runs. The sign-in presents the device keys this machine already holds, so the service keeps the machine's existing device instead of adding a row. If the device service holds a device whose keys omo does not have (the desktop app's sign-in), omo refuses and points to the desktop app instead of minting a second device.
