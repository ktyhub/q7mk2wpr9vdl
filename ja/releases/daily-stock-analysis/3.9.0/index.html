daily_stock_analysis v3.9.0

マイナー 公開日2026年3月20日 出典ZhuLinsen/daily_stock_analysis English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

デイリーストック分析 v3.9.0

リリースのハイライト

  • 🤖 モデル リンクとレポート言語がより柔軟になりました - エージェントは AGENT_LITELLM_MODEL を通じてモデル リンクを個別に選択できるようになり、通常の分析とエージェント レポートも REPORT_LANGUAGE=zh|en を通じて統一言語で出力できるため、「英語コンテンツ + 中国語シェル」などの混合問題が軽減され、チームがメイン分析とエージェントそれぞれのコスト、速度、機能を比較検討できるようになります。
  • 🔎 ホームページ分析エクスペリエンスは閉ループ最適化のラウンドを完了しました - A-share オートコンプリートがホームページに追加され、コード、中国語名、ピンイン、およびエイリアスの検索をサポートしました。同時に、ダッシュボードのステータスが統合ストアに統合され、履歴、レポート、ニュース、Markdown ドロワー間の相互作用がより安定し、「Ask AI」の質問でも現在のレポートのコンテキストが優先されます。
  • 💬 通知と取得機能は拡大し続けています - Slack のファーストクラス通知チャネルを追加しました。 SearXNG は、パブリック インスタンスを自動的に検出し、自己構築インスタンスが構成されていない場合、制御されたポーリングに従ってそれらをダウングレードできます。 Tavily の時間に敏感なニュース リンクが修復された後は、厳密に時間に敏感なフィルタリングによってエラーが発生して有効な結果が失われることはなくなります。
  • 💼 ポジションと市場レビューの間のリンクがより安定しています — A 株市場レビューは、オプションで TickFlow にアクセスして、インデックスと騰落統計を強化できます。同時売られすぎウィンドウを減らすために、ポジションブックの書き込みがシリアル化に変更されます。為替レート更新の入り口と無効ステータスのプロンプトもより明確になり、ユーザーの誤った判断が減少します。

新機能

  • 🔎 ウェブ株オートコンプリート MVP - ホームページ分析入力ボックスは、ローカルインデックス主導のオートコンプリートを追加し、株式コード、中国語名、ピンイン、およびエイリアスのマッチングをサポートします。候補を選択した後、正規コードが送信され、stock_name、original_query、selection_source が分析リクエスト、タスク ステータス、および SSE イベントに透過的に送信されます。インデックスのロードが失敗すると、元の送信プロセスをブロックすることなく、自動的に古い入力モードに戻ります。同期には、静的インデックス ローダー、インデックス生成スクリプト、フロントエンドとバックエンドのコントラクト テストが追加されます。開発は段階的に行われ、第 1 段階では A 株のみがサポートされます。
  • 💬 Slack のファーストクラス通知チャネル - Slack ネイティブ通知のサポートを追加し、ボット トークンと受信 Webhook アクセス メソッドの両方をサポートしました。同時に構成する場合は、ボット API の使用を優先して、テキストと画像が同じチャネルに送信されるようにします。ボット トークン モードは、画像のアップロード (マルチパートを使用しない生の本文 POST) をサポートします。 SLACK_BOT_TOKEN、SLACK_CHANNEL_ID、SLACK_WEBHOOK_URL 構成項目、GitHub アクション ワークフローが同期し、対応するシークレット配信を完了するように追加されました。
  • 🌍 レポート出力言語は構成可能です (問題 #758) - REPORT_LANGUAGE=zh|en、デフォルトの zh を追加しました。言語設定は、通常の分析とエージェント プロンプトを同時に挿入し、Markdown/Jinja テンプレート、通知フォールバック、履歴/API report_language メタデータ、および Web レポート ページの固定コピーをカバーして、「英語コンテンツ + 中国語シェル」の混合出力を回避します。
  • 🚀 エージェントは通常の分析モデルから切り離されています (問題 #692) - AGENT_LITELLM_MODEL を追加しました (LITELLM_MODEL を継承するには空白のままにしておきます。openai/<model> に従って正規化されるプレフィックスはありません)。エージェント実行リンクの is_primary/is_fallback マークと /api/v1/agent/models は、エージェントの実際のモデル リンクに基づくように変更されます。システム構成と起動期間の検証が完了しました。 AGENT_LITELLM_MODEL unknown_model/missing_runtime_source によってチェックされます。 Web 設定ページには、エージェントのメイン モデルの選択が追加され、チャネル モードのランタイム構成と同期されます。
  • 🔎 SearXNG パブリック インスタンスの自動検出と制御されたポーリング (#752) - SEARXNG_PUBLIC_INSTANCES_ENABLED を追加しました。 SEARXNG_BASE_URLS が構成されていない場合、デフォルトで searx.space からパブリック インスタンス リストを取得し、制御されたポーリング順序でインスタンスを選択します。同じリクエスト内でタイムアウト、接続エラー、HTTP 非 200、または無効な JSON が発生した場合、自動的に次のインスタンスに切り替わります。自己構築インスタンスを構成したユーザーは、元の優先順位とセマンティクスを変更せずに維持します。 daily_analysis GitHub アクション ワークフローは、このスイッチの明示的な透過的な送信もサポートしており、起動ログに現在のステータスを表示します。
  • 📈 TickFlow マーケットレビューの強化 (#632) — オプションの TICKFLOW_API_KEY を追加しました。設定後、TickFlow は A 株市場レビューにおける主要な指数トレンドに対して優先的に与えられます。現在の TickFlow パッケージがターゲット プール クエリをサポートしている場合、市場の騰落統計も TickFlow を優先します。障害が発生した場合や権限が不十分な場合は、ただちに既存の AkShare / Tushare / efinance リンクにフォールバックします。セクター価格リストのフォールバック順序は変更されません。アクセス層は、実際の SDK コントラクトにも適合しています。メインのインデックス クエリは、単一リクエストの上限に従ってバッチを取得し、TickFlow によって返された比例 change_pct / amplitude をプロジェクトの内部パーセンテージ基準に均一に変換します。

改善点

  • ダッシュボード状態スライスとワークスペースの閉鎖 — ホーム/ダッシュボード状態を stockPoolStore に移動し、履歴選択、レポートの読み込み、タスクの同期、ポーリング更新、およびマークダウン ドロワーの処理を単一の状態スライスに統合しました。
  • ダッシュボード パネルの標準化 — 現在のダッシュボード レイアウト コントラクトを安定させながら、共有トークン、標準化された状態、および履歴リストの限定されたパネル内スクロールを使用して履歴、レポート、ニュース、およびマークダウン プレゼンテーションを統合しました。
  • ダッシュボードからチャットへのフォローアップ ブリッジ - ページ間の状態を直接結合するのではなく、レポート コンテキストのハイドレーションを通じて「Ask AI」フォローアップをルーティングしながら、強化された履歴コンテキストがまだ読み込まれているときにチャット送信を使用できるようにしました。
  • 💼 ポジション台帳の同時書き込みシリアル化 (#742) - ポジション ソース イベントの書き込み/削除は、最初に SQLite でシリアル化された書き込みロックを取得し、オーバーブッキングされたトランザクションを台帳に書き込むための同時販売のウィンドウを短縮します。直接位置書き込みインターフェイスはロック競合中に 409 portfolio_busy を返し、CSV インポートは送信を 1 つずつ維持し、ビジー状態を failed_count としてカウントします。
  • 💱 ポジション ページの為替レートの手動更新エントリを入力します (#748) - Web /portfolio ページの [為替レート ステータス] カードに [為替レートを更新] ボタンが表示され、既存の POST /api/v1/portfolio/fx/refresh インターフェイスが直接呼び出されます。更新後は、スナップショットとリスク データのみが再ロードされ、「更新済み / まだ古い / 更新失敗」の結果がインライン サマリーでフィードバックされるため、fxStale 長期滞在の誤解に対するユーザーの不安が軽減されます。

修正

  • 🔎 Web オートコンプリート「コミット セマンティック修正を入力」 — ストックのオートコンプリートでは、ヒット候補を検索するときにデフォルトで最初の項目が強調表示されなくなりました。候補リストが展開されているが、ユーザーが矢印キーまたはマウスで明示的に選択していない場合、Enter キーを押すと元の入力が送信され続け、手動入力が最初の候補によってサイレントに上書きされるのを防ぎます。
  • 🌍 REPORT_LANGUAGE 起動解析と履歴表示の間のローカライゼーション境界を完了します - Config は、起動時に「実際の環境変数が最初、.env が最後」という既存のセマンティクスに従い続け、2 つが競合する場合には明示的な警告を出力し、REPORT_LANGUAGE の不明瞭なソースによって引き起こされる誤った判断を減らします。同時に、/api/v1/history/{id} 英語の詳細応答は、ローカライズされた sentiment_label、履歴マークダウンと同期されます。 また、英語 bias_status のリスク レベル絵文字も正確に識別され、乐观 や 🚨Safe などの中国語と英語の混合/誤検知表示を回避します。
  • 📰 Tavily の時間に敏感なニュース検索のリリース時間マッピングの修復 (#782) - Tavily は株式ニュースおよび厳密に時間に敏感なインテリジェンスのディメンションで topic="news" を明示的に使用するようになり、published_date / publishedDate の 2 つのリリース時間フィールドと互換性があります。 Tavily が明確に結果を返すが、後続のハード フィルタリング段階ですべて drop_unknown として記録される問題を修正しました。質問は破棄されましたが、機関分析、パフォーマンスの期待、業界分析などの分析次元はブロードソース検索に復元され、ニュース モードに一律に圧縮されなくなりました。
  • 💱 ポジション ページで為替レートの更新を無効にするためのセマンティック修正 (#772) - PORTFOLIO_FX_UPDATE_ENABLED=false、POST /api/v1/portfolio/fx/refresh が明示的な refresh_enabled=false および disabled_reason を返すようになり、Web /portfolio ページでは「為替レートのオンライン更新が無効になっています」というメッセージが明確に表示され、「現在の範囲で更新できる為替レートのペアはありません」と誤って報告されなくなりました。
  • 🤖 エージェントのタイムアウトと構成の強化 — AGENT_ORCHESTRATOR_TIMEOUT_S は従来の単一エージェント ReAct ループも保護するようになり、残りの予算が使い果たされると並列ツール バッチは待機を停止し、無効な数値 .env 値は起動をクラッシュさせるのではなく、警告とともに安全なデフォルトにフォールバックします。
  • 🌐 CORS ワイルドカード + 資格情報の互換性 — CORS_ALLOW_ALL=true は、allow_origins=["*"] と資格情報付きリクエストを組み合わせなくなり、デモ/開発セットアップにおけるブラウザー側のクロスオリジン障害を回避します。
  • 🧭 Web UI から非表示になった利用できないエージェント設定 — Deep Research / Event Monitor コントロールは、現在のブランチで互換性のみのメタデータとして扱われ、機能しないトグルが公開されるのを避けるために [設定] ページから削除されます。

ドキュメント

  • Ollama ローカル モデル構成手順を追加し、README.md と docs/README_EN.md を同時に更新しました (修正 #690)
  • Ollama 設定手順の改善: 環境変数テーブル docs/full-guide.md / docs/full-guide_EN.md と、英語ユーザーが Ollama を独立した設定エントリとして使用できないという誤解を避けるために OLLAMA_API_BASE を追加しました。重複する OLLAMA_API_BASE エントリを 1 つのエントリにマージします
  • ドキュメント同期ガバナンスの境界を明確にする: README.md、トピックドキュメント、バイリンガルドキュメント、配信指示の間のデフォルトの同期ルールを補足して、後続のドキュメントのずれを軽減します。

daily_stock_analysis v3.9.0

发布亮点

  • 🤖 模型链路与报告语言更灵活 — Agent 现在可以通过 AGENT_LITELLM_MODEL 独立选择模型链路，普通分析与 Agent 报告也可通过 REPORT_LANGUAGE=zh|en 输出统一语言，减少“英文内容 + 中文壳子”这类混排问题，并允许团队分别权衡主分析与 Agent 的成本、速度和能力。
  • 🔎 首页分析体验完成一轮闭环优化 — 首页新增 A 股自动补全，支持代码、中文名、拼音和别名检索；同时 Dashboard 状态收口到统一 store，历史、报告、新闻与 Markdown 抽屉的交互更稳定，“Ask AI” 追问也会优先携带当前报告上下文。
  • 💬 通知与检索能力继续外扩 — 新增 Slack 一等通知渠道；SearXNG 在未配置自建实例时可以自动发现公共实例并按受控轮询降级；Tavily 时效新闻链路修复后，严格时效过滤不再错误丢光有效结果。
  • 💼 持仓与市场复盘链路更稳 — A 股 market review 可选接入 TickFlow 强化指数与涨跌统计；持仓账本写入改为串行化以缩小并发超卖窗口；汇率刷新入口和禁用态提示也更加清晰，减少用户误判。

新功能

  • 🔎 Web 股票自动补全 MVP — 首页分析输入框新增本地索引驱动的自动补全，支持股票代码、中文名、拼音和别名匹配；选中候选后会提交 canonical code，并透传 stock_name、original_query、selection_source 到分析请求、任务状态和 SSE 事件；索引加载失败时自动退回旧输入模式，不阻断原有提交流程。同步补充了静态索引加载器、索引生成脚本和前后端契约测试。分阶段进行开发，第一阶段仅支持 A 股。
  • 💬 Slack 一等通知渠道 — 新增 Slack 原生通知支持，同时支持 Bot Token 和 Incoming Webhook 两种接入方式；同时配置时优先使用 Bot API，确保文本与图片发送到同一频道；Bot Token 模式支持图片上传（raw body POST，不使用 multipart）；新增 SLACK_BOT_TOKEN、SLACK_CHANNEL_ID、SLACK_WEBHOOK_URL 配置项，GitHub Actions 工作流同步补齐对应 Secrets 传递。
  • 🌍 报告输出语言可配置（Issue #758）— 新增 REPORT_LANGUAGE=zh|en，默认 zh；语言设置会同步注入普通分析与 Agent Prompt，并覆盖 Markdown/Jinja 模板、通知 fallback、历史/API report_language 元数据及 Web 报告页固定文案，避免“英文内容 + 中文壳子”的混合输出。
  • 🚀 Agent 与普通分析模型解耦（Issue #692）— 新增 AGENT_LITELLM_MODEL（留空继承 LITELLM_MODEL，无前缀按 openai/<model> 归一）；Agent 执行链路与 /api/v1/agent/models 的 is_primary/is_fallback 标记改为基于 Agent 实际模型链路；系统配置与启动期校验补齐 AGENT_LITELLM_MODEL 的 unknown_model/missing_runtime_source 检查；Web 设置页新增 Agent 主模型选择并与渠道模式运行时配置同步。
  • 🔎 SearXNG 公共实例自动发现与受控轮询（#752）— 新增 SEARXNG_PUBLIC_INSTANCES_ENABLED，在未配置 SEARXNG_BASE_URLS 时默认从 searx.space 拉取公共实例列表，并按受控轮询顺序选择实例；同次请求内遇到超时、连接错误、HTTP 非 200 或无效 JSON 会自动切换到下一个实例。已配置自建实例的用户保持原有优先级与语义不变；daily_analysis GitHub Actions 工作流也已支持显式透传该开关并在启动日志中展示当前状态。
  • 📈 TickFlow market review enhancement (#632) — 新增可选 TICKFLOW_API_KEY；配置后，A 股大盘复盘的主要指数行情优先尝试 TickFlow；若当前 TickFlow 套餐支持标的池查询，市场涨跌统计也会优先尝试 TickFlow。失败或权限不足时立即回退到现有 AkShare / Tushare / efinance 链路；板块涨跌榜回退顺序保持不变。接入层同时适配了真实 SDK 契约：主指数查询按单次请求上限分批拉取，并将 TickFlow 返回的比例型 change_pct / amplitude 统一转换为项目内部的百分比口径。

改进

  • Dashboard state slice and workspace closure — moved Home / Dashboard state into stockPoolStore, consolidated history selection, report loading, task syncing, polling refresh, and markdown drawer handling under a single state slice.
  • Dashboard panel standardization — kept the current dashboard layout contract stable while unifying history, report, news, and markdown presentation with shared tokens, standardized states, and bounded in-panel scrolling for the history list.
  • Dashboard-to-chat follow-up bridge — routed “Ask AI” follow-ups through report-context hydration instead of direct cross-page state coupling, while keeping chat sends usable when enriched history context is still loading.
  • 💼 持仓账本并发写入串行化（#742）— 持仓源事件写入/删除现在会在 SQLite 下先获取串行化写锁，减少并发卖出把超售流水写入账本的窗口；直接持仓写接口在锁竞争时返回 409 portfolio_busy，CSV 导入保持逐条提交并把 busy 计入 failed_count。
  • 💱 持仓页汇率手动刷新入口补齐（#748）— Web /portfolio 页面现在会在“汇率状态”卡片中展示“刷新汇率”按钮，直接调用现有 POST /api/v1/portfolio/fx/refresh 接口；刷新后会仅重载快照与风险数据，并以内联摘要反馈“已更新 / 仍 stale / 刷新失败”的结果，减少用户对 fxStale 长时间停留的误解。

修复

  • 🔎 Web 自动补全 Enter 提交语义修正 — 股票自动补全在搜索命中候选时不再默认高亮第一项；候选列表展开但用户尚未用方向键或鼠标明确选中时，按 Enter 会继续提交原始输入，避免手动输入被第一条候选静默覆盖。
  • 🌍 补齐 REPORT_LANGUAGE 启动解析与历史展示本地化边界 — Config 在启动时继续遵循“真实环境变量优先、.env 兜底”的既有语义，并在两者冲突时输出显式告警，减少 REPORT_LANGUAGE 来源不清带来的误判；同时 /api/v1/history/{id} 英文详情响应会同步本地化 sentiment_label，历史 Markdown 也会正确识别英文 bias_status 的风险等级 emoji，避免出现 乐观 或 🚨Safe 这类中英混排/误报展示。
  • 📰 Tavily 时效新闻检索发布时间映射修复（#782）— Tavily 在股票新闻和严格时效的情报维度中现在会显式使用 topic="news"，并兼容 published_date / publishedDate 两种发布时间字段；修复了 Tavily 明明返回结果却在后续硬过滤阶段被全部记为 drop_unknown 丢弃的问题，同时将机构分析、业绩预期、行业分析等分析型维度恢复为宽源搜索，不再被统一压缩成新闻模式。
  • 💱 持仓页汇率刷新禁用语义修正（#772）— 当 PORTFOLIO_FX_UPDATE_ENABLED=false 时，POST /api/v1/portfolio/fx/refresh 现在会返回显式 refresh_enabled=false 与 disabled_reason，Web /portfolio 页面会明确提示“汇率在线刷新已被禁用”，不再误报“当前范围无可刷新的汇率对”。
  • 🤖 Agent timeout and config hardening — AGENT_ORCHESTRATOR_TIMEOUT_S now also protects the legacy single-agent ReAct loop, parallel tool batches stop waiting once the remaining budget is exhausted, and invalid numeric .env values fall back to safe defaults with warnings instead of crashing startup.
  • 🌐 CORS wildcard + credentials compatibility — CORS_ALLOW_ALL=true no longer combines allow_origins=["*"] with credentialed requests, avoiding browser-side cross-origin failures in demo/development setups.
  • 🧭 Unavailable Agent settings hidden from Web UI — Deep Research / Event Monitor controls are now treated as compatibility-only metadata in the current branch and are removed from the Settings page to avoid exposing non-functional toggles.
