OpenHands v1.10.0

Highlights

  • Automation becomes a first-class, data-driven surface — PR #16303 adds manifest-driven sub-pages to the automation interface and PR #16266 ships a featured-automations landing dashboard, moving automation UI away from hardcoded pages toward manifest-defined ones. PR #16233 derives the automation timeout cap from the deployment instead of a fixed value, and bundled components jump to agent-server 1.40.1 / automation 1.6.0 (#16334) and @openhands/extensions 0.16.0 (#16321). Teams building or configuring automations get the most value here.

  • Canvas default model flips to GLM 5.2 — PR #16146 changes the Canvas default model to GLM 5.2; new sessions will use it unless you explicitly override the model. Not a hard breaking change, but a behavioral change worth verifying if you relied on the previous default. PR #16144 also fixes MCP credentials being dropped during Canvas mutations — relevant if you connect authenticated MCP servers to Canvas.

  • Security and multi-backend reliability fixes — PR #16264 resolves npm audit vulnerabilities; PR #16290 switches local proxy targets to IPv4 loopback (fixes proxy failures in IPv6-first/local setups); PR #16243 pins backend identity on sidebar conversation links (fixes links resolving against the wrong backend in multi-backend deployments). PR #16234 adds activity log export, useful for auditing and incident review.

  • No breaking changes or migration steps — Nothing here requires data migration or config rewrites; changes are additive features and fixes plus routine dependency bumps (react, tanstack, tailwind, monaco-editor 0.56.0, i18next, testing/typing groups). CI now requires frontend screenshot/video and a checked human-tested box (#16325), which is a contributor-process change only, not a runtime concern.

  • Upgrade guidance — Worth upgrading if you use the automation interface, Canvas (especially with MCP servers), local proxy targets, multi-backend deployments, or want the npm audit fixes. Safe to skip for now if you're on v1.9.0 and none of those apply — this is a feature-and-hardening release, not an emergency patch.
