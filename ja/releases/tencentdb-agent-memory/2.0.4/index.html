TencentDB-エージェント-メモリ v2.0.4

[2.0.4] - 2026-11-18

v2.0.4を発売。 v2.0.3 と比較すると、スキル圧縮パッケージのバッチ インポートとカスタム メモリ プロンプト ワード置換モードが追加され、メモリ構成、長時間のアップストリーム リクエスト、オンライン セッション レコードとトラブルシューティング ログが強化され、安定性と権限に関する多くの問題が修正されています。

製品のポジショニング: エージェントのエクスペリエンス、ドキュメント、コードを次のエージェントにとって再利用可能な資産にします ファイルを直接読み取ります。詳細については、README_CN.md を参照してください。

📦 スキル圧縮パッケージのインポート

  • パネルにスキルをインポートする場合、複数の圧縮パッケージを一度に選択またはドラッグでき、各圧縮パッケージがスキルに対応します。
  • 各パッケージには SKILL.md のコピーが必要です。成功、スキップ、失敗は個別にリストされます。1 つの失敗は残りのパッケージには影響しません。
  • 元のカタログのインポートと会話からのインポートは変更されません。

✍️ カスタマイズされたメモリ プロンプトは組み込みの段落を置き換えることができます (デフォルトは依然として追加です)

  • カスタマイズされた L1 / L2 / L3 プロンプトワードは、単に最後に追加するのではなく、システムプロンプト内の対応する段落を置き換えることができます
  • このモードが指定されていない場合、既存のプロンプト単語と抽出結果は現在と同じです。保存されたプロンプトワードを移行する必要はありません
  • 交換後も、出力形式、長さ制限、ツール範囲はシステムによって維持されます。長すぎるコンテンツやこれらの制約を上書きしようとするコンテンツは保存時に拒否され、一度選択したモードは変更できません。

🧠 記憶の構成がより安定します

  • シーンのバックログはバッチで整理され、中断後に最後の位置から再開されます。
  • デフォルトでは、単一のシーン ファイルは 256KB を超えません。超過したファイルは小さくすることしかできません。
  • 会話が行われた時間で並べ替えると、それ以降の事実や以前の事実が新しい結論をカバーしなくなります。
  • マルチインスタンスのデプロイメントでは、1 つのインスタンスの処理が遅いことによって、他のインスタンスがメモリを抽出することがブロックされなくなりました。
  • 古い構成を変更する必要はありません

⏱️ 上流に長期間データがない場合、事前に切断されなくなります。

  • 上流側が継続的にデータを送信しない場合でも、5 分以内に接続が切断されなくなりました。データ受信間のデフォルトの間隔は 30 分、応答ヘッダーのデフォルトの待機時間は 10 分です。
  • 転送全体は依然として既存の 1 時間の上限によってカバーされます。上記のデフォルト値は、これら 2 つの項目が個別に設定されていない場合に使用されます。

📼 オンラインセッション記録 (セッショントレース)

  • オンライン セッションの記録が、ラウンドごとに 1 レコードからモデル コールごとに 1 レコードに変更されました。リクエストとリプライはそのまま保存され、ツール呼び出しの途中ステップも記録されます。
  • レコード フィールドは、それに応じて調整されます。messages は request (上流に送信された要求の完了) に変更され、output は response (上流から返された応答) に変更されます。 agent、protocol、status およびその他のフィールドが追加され、user_query はアップロードされなくなりました
  • 古いバージョンのプロキシとの互換性: /v3/session/add は、古いバージョンのプロキシによってラウンドでアップロードされたレコードを引き続き受け入れます。検証ルールや保存形式は従来と同じです。古いバージョンのプロキシは変更せずにアップロードを続けることができます。
  • 新しいバージョンのプロキシにアップグレードすると、セッション レコードは新しいロジックと形式に従って保存されます。アップグレード前と後のレコードは同じディレクトリ内にあり、request フィールドが含まれているかどうかによって区別できます。

🔎 トラブルシューティング ログ

・L0からL3までの記憶処理ログに、開始、完了、時間の経過、失敗の各段階が補足され、会話録音、記憶抽出、シーン整理、人格生成などで処理が滞っているかどうかの判断が容易になります。

  • 認証失敗ログは、無効なユーザー キーとプロキシ→コアの内部認証失敗を区別し、401/403 を見つけやすくします。ログには重要な内容が記録されない

🐛修正

  • モデルが書き込みツールを呼び出さず、パーソナリティ テキストのみを出力する場合でも、完全な構造を持つテキストがパーソナリティ ファイルに書き込まれます。構造が一致しない場合、または長すぎる場合は書き込まれません。
  • クライアントがセッション ID を提供しない場合、同じユーザー キーに基づくリクエストは同じセッション内に残り、初期化されるたびに新しいものに置き換えられることはなくなります。
  • CodeBuddy は、エージェントがいないチームを選択すると初期化を直ちにスキップし、認識できない選択項目が継続的にポップアップ表示されなくなります。
  • エージェントとタスクのビューとリストは、発信者、チームメンバーのステータス、可視範囲によってフィルタリングされます。アクセス権限のないプライベートエージェントは表示されなくなります。
  • コード マップの構築が失敗すると、エラー プロンプトで停止し、クエリが続行されなくなりました。手動で再同期すると回復しました。
  • Wiki インポート後の無制限の進行状況クエリはなくなりました。インポートが繰り返されるか、すぐに終了する場合は、完了と失敗が表示されます。約 10 分または連続読み取りに失敗すると自動チェックが一時停止され、手動で再度チェックできます。
  • ユーザー メッセージに閉じられていない区切り文字や複数行の Key-Value テキストが表示されても、エージェントがスタックすることがなくなりました。
  • ブラウザが言語設定の保存に失敗した場合でもパネルは機能します
  • キーが見つからないか無効な場合でも、「Unauthorized」が返されます。認証サービスまたはメモリ サービスがタイムアウトするか中断されると、無効なキーの代わりにサーバー側のエラーが返されます。
  • Python SDK はタイムアウトを非有限値に設定することを拒否します フル Changelog: https://github.com/TencentCloud/TencentDB-Agent-Memory/compare/v2.0.3...v2.0.4

TencentDB-Agent-Memory v2.0.4

Highlights

  • Session trace schema change (behavioral) — Recording granularity shifts from one record per conversation turn to one per model invocation, capturing the full raw request/response plus tool-call intermediates. Fields are renamed (messages → request, output → response), new agent/protocol/status are added, and user_query is dropped. If you consume session records downstream, you must handle both shapes in the same directory — tell them apart by the presence of request. Old Proxy uploads at /v3/session/add still work unchanged; the new format is written only after upgrading Proxy.

  • Opt-in prompt replacement mode — L1/L2/L3 custom prompts can now replace the built-in segments instead of just appending. Default stays append, so existing prompts, extraction results, and saved configs need no migration. Once you pick replace mode it is locked (cannot be switched back), and saves are rejected if the content tries to alter output format, length caps, or tool scope — so treat it as a one-way, constrained customization rather than a quick toggle.

  • Skill archive batch import — You can select or drag in multiple zip archives at once, one skill per archive, each requiring a SKILL.md. Successes, skips, and failures are reported separately and a bad archive does not block the rest — useful for bulk-onboarding a skill library. Directory-based and conversation-based imports are untouched.

  • More resilient memory consolidation — Backlog consolidation is now batched and resumes from the last position after interruption; per-scene files are capped at 256 KB by default and already-oversized files may only shrink; consolidation sorts by conversation time so late-arriving older facts no longer overwrite newer conclusions; and a slow instance no longer blocks others' extraction in multi-instance deployments. No config changes required — mainly a win for large memory stores and concurrent setups.

  • Relaxed upstream timeouts — The hard 5-minute idle cutoff is gone: the default inter-data gap is now 30 minutes and time-to-response-headers 10 minutes, with the existing 1-hour overall cap still backing it. Long-running upstream inference will no longer be killed prematurely; these defaults apply automatically when unset, so override only if you need tighter or looser thresholds.

  • Fixes that change observable behavior — Agent/Task view and list endpoints now filter by caller, team membership, and visibility (private agents no longer leak); auth logs distinguish invalid user keys from Proxy→Core internal auth failures (never logging key contents); auth/memory service timeouts and interruptions now surface as server errors instead of masquerading as invalid keys; the Python SDK rejects non-finite timeout values; and a missing client session ID no longer causes a fresh session on every init. Watch for changed error codes and tighter access in clients.

No breaking changes — existing configs, saved prompts, and old Proxy uploads remain compatible.

[2.0.4] - 2026-11-18

v2.0.4 发布，相比 v2.0.3 新增技能压缩包批量导入与自定义记忆提示词替换模式，增强记忆整理、长耗时上游请求、在线会话记录和排障日志，并修复多项稳定性与权限问题。

产品定位：让 Agent 的经验、文档、代码沉淀成可复用资产，让下一位 Agent 直接读档。详见 README_CN.md。

📦 技能压缩包导入

  • 面板导入技能时可以一次选择或拖入多个压缩包，每个压缩包对应一个技能
  • 每个包内需要有一份 SKILL.md；成功、跳过和失败会分开列出，一个失败不影响其余包
  • 原有的目录导入和从对话导入保持不变

✍️ 自定义记忆提示词可替换内置段落（默认仍为追加）

  • 自定义 L1 / L2 / L3 提示词可以选择替换系统提示里的对应段落，而不只是追加在后面
  • 不指定该模式时，已有提示词和抽取结果与现在一致；已保存的提示词无需迁移
  • 替换后，输出格式、长度上限和工具范围仍由系统保持。过长、或试图改写这些约束的内容会在保存时被拒绝，且模式一旦选定不能再改

🧠 记忆整理更稳

  • 积压的场景整理改为分批完成，中断后从上次位置继续
  • 单个场景文件默认不超过 256KB；已经超过的文件只允许变小
  • 整理按对话发生的时间排序，后到的更早事实不再覆盖较新的结论
  • 多实例部署中，一个实例整理缓慢不再挡住其他实例抽取记忆
  • 旧配置无需修改

⏱️ 上游长时间无数据不再被提前掐断

  • 上游连续不发数据时，不再在 5 分钟被连接掐断。两次收到数据的间隔默认 30 分钟，等待响应头默认 10 分钟
  • 整次转发仍由已有的 1 小时上限兜底；未单独配置这两项时使用上述默认值

📼 在线会话记录（session trace）

  • 在线会话由每轮记录一条，改为每次模型调用记录一条，原样保存该次请求和回复，工具调用的中间步骤也会被记录
  • 记录字段随之调整：messages 改为 request（发往上游的完整请求），output 改为 response（上游返回的回复）；新增 agent、protocol、status 等字段，不再上传 user_query
  • 兼容旧版 Proxy：/v3/session/add 仍接受旧版 Proxy 按轮上传的记录，校验规则和存储格式都与之前一致，旧版 Proxy 无需改动即可继续上传
  • 升级到新版 Proxy 后，会话记录改按新的逻辑和格式存储。升级前后的记录在同一目录下，可以根据是否含有 request 字段来区分

🔎 排障日志

  • 记忆从 L0 到 L3 的处理日志补充开始、完成、耗时和失败阶段，便于判断处理卡在对话记录、记忆抽取、场景整理还是人格生成
  • 鉴权失败日志区分用户密钥无效与 Proxy→Core 内部鉴权失败，便于定位 401/403；日志不记录密钥内容

🐛 修复

  • 模型未调用写入工具、只输出人格正文时，结构完整的文本仍会写入人格文件；结构不符或过长时保持不写入
  • 客户端未提供会话标识时，同一用户密钥下的请求保持同一次会话，不再每次初始化都换成新的
  • CodeBuddy 选中一个自己没有 Agent 的团队时立即跳过初始化，不再连续弹出无法识别的选择
  • Agent 与 Task 的查看和列表按调用者、团队成员身份和可见范围过滤，无权访问的私有 Agent 不再出现
  • 代码图谱构建失败后停在错误提示上，不再持续查询；手动重新同步后恢复
  • Wiki 导入后不再无限查询进度。重复导入或很快结束时，完成和失败会显示出来；自动检查大约 10 分钟或连续读取失败后暂停，可以手动再查
  • 用户消息中出现未闭合的分隔线和多行键值文本时，不再把代理卡住
  • 浏览器无法保存语言偏好时，面板仍可使用
  • 密钥缺失或无效时仍返回未授权。鉴权服务或记忆服务超时、中断时改为返回服务端错误，不再表现为密钥无效
  • Python SDK 拒绝把超时设为非有限数值
