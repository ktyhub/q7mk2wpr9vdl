TencentDB-Agent-Memory v0.3.6

TencentDB-エージェント-メモリ v0.3.6

[0.3.6] - 2026-05-28

🚀 新機能

  • コンテキスト バジェット制御の呼び出し (#71 / #70): 長いセッションがメモリ拡張によりコンテキストを混雑させることを防ぐために、長すぎるエントリを分数順序でプルーニングし、オーバーフロー部分を破棄するための recall.maxCharsPerMemory および recall.maxTotalRecallChars 構成を追加しました。
  • L1 / L2 / L3 プロンプト ワードはユーザー入力言語に応じて適応されます (#38): 4 つのプロンプト l1-extraction、l1-dedup、scene-extraction、および persona-generation の自由テキスト フィールドは、locale を構成しなくても、ユーザー メッセージ言語で記述されるようになりました。
  • sendDimensions の埋め込み (オプションでクローズ): embedding.sendDimensions 構成項目を追加しました。 false に設定すると、リクエスト本文の dimensions フィールドが省略され、BGE-M3 などの固定次元モデルに接続できます。
  • ゲートウェイのオプションのベアラー認証 + CORS ホワイトリスト: server.apiKey / TDAI_GATEWAY_API_KEY および server.corsOrigins / TDAI_CORS_ORIGINS を追加しました。有効にした後、非 /health ルートはベアラー トークンを伝送し、タイミング攻撃を防ぐために定数時間の比較を行う必要があります。 hermes Python クライアント同期は MEMORY_TENCENTDB_GATEWAY_API_KEY をサポートします。
  • オフロード collect モード: L3 圧縮をトリガーせずにデータ収集のみを実行する offload.mode: "collect" を追加しました。純粋なデータの蓄積またはデバッグのシナリオに適しています。

🐛修正

  • L2 LLM 障害により scene_blocks/ がワイプされる (#88): LLM がエラーをスローした場合、最新のバックアップから scene_blocks/ を自動的に復元する、フェイルソフト設計。
  • シーン ファイル名にスペースが含まれているため、ペルソナ シーン ナビゲーション参照が無効になります: filename-normalizer.ts を追加し、SceneExtractor.extract でファイル名を自動的に正規化しました。
  • api.runtime.state により、undefined の登録クラッシュが発生します (#78 / #85 / #79): オプションのチェーン + フォールバックを追加し、runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw の 3 レベルのダウングレードをサポートします。
  • contextEngine スロット ID がプラグイン名と一致しません: openclaw doctor --fix によるスロットのリセットを避けるために、これを memory-tencentdb に変更します。
  • L1.5 セトリングが戻らず、L2 がフリーズする: 60 秒のタイムアウトを追加し、コンテキスト エンジン スロットが設定されていない場合は自動的に強制セトリングします。
  • スタンドアロン テキスト タスクは引き続きツールを公開します (#58 / #59): ツール リストは enableTools=false ではまったく送信されません。
  • L2 コールド スタート スキップ偽更新 l2LastRunTime: 実際の実行時にのみタイムスタンプを更新します。
  • sanitizeText は、絵文字 / CJK / Math Bold などの非 BMP 文字を誤って削除します (#30 / #31): 孤立したサロゲートのみに一致するように、通常のパターンに u フラグを追加します。
  • MIN_KEEP 拒否による緊急切り捨てデッドロック: _emergencyTruncateOversized、強制削除、ペアリング クリーンアップを追加しました。
  • 積極的な圧縮の複数ラウンドの累積消費時間: 6 ラウンドの全量の tiktoken から、単一の正確なカットオフ ポイント、615 メッセージ、84 秒 → 14 秒に変更されました。
  • FP-HEAD-DELETE により新しいメッセージが誤って削除される: 代わりに FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP を使用し、シーンを 38 秒→ 122 ミリ秒で再生します。
  • 最初のアセンブルが遅い: 短絡前の高速トークン推定を追加 (29 秒→ 1.4 秒)。
  • トークン計算精度: details が INTERNAL_KEYS に追加されます。デフォルトでは、l3TiktokenEncoding は cl100k_base に変更されます。
  • Dockerfile.hermes で生成された config.yaml に api_key がありません (#77 / #81): model.api_key を同期的に書き込みます。
  • インストール スクリプトに関する複数の問題 (#18 / #19 / #20 / #54 / #55): HERMES_AGENT_DIR の上書きをサポートし、root は su を再帰しなくなり、systemd 環境は絶対パス ノードを使用します。
  • よりクリーンなセキュリティ強化: 無効なカットオフを拒否し、expired/total > 80% で削除を防止し、保持ガードレールを最小限に抑えます。

✨ 改善点

  • デフォルトでは、l3TiktokenEncoding が cl100k_base に変更され、主流の国内/オープンソース モデルのワード セグメンタに一致します。
  • オフロードログのダウングレード: AGGRESSIVE / EMERGENCY などはデバッグ用にダウングレードされ、わずか 10 秒後に WARN が出力されます。
  • Docker ドキュメントは、cd docker/opensource の事前手順を補足します。質問/相談問題のテンプレートを追加します。

⚠️設定項目の変更（下位互換性）

|キー |デフォルト値 |説明 | |---|---|---| | recall.maxCharsPerMemory | 0 | 0/未設定 = トリミングなし | | recall.maxTotalRecallChars | 0 | 0/未設定 = トリミングなし | | embedding.sendDimensions | true | falseにはBGE-M3などに適したdimensionsはありません。 | l3TiktokenEncoding | cl100k_base (旧 o200k_base) |手動オーバーライドは、明示的に o200k_base に依存する場合にのみ必要です。

TencentDB-Agent-Memory v0.3.6

Highlights

  • Recall budgets and token accounting — New recall.maxCharsPerMemory / recall.maxTotalRecallChars score-rank and truncate oversized memories so long sessions stop inflating recall and crowding the context window; both default to 0 (off), so set explicit caps to opt in and expect lower-ranked tail entries to be silently dropped (PR #71, issue #70). Separately, l3TiktokenEncoding flips from o200k_base to cl100k_base and details now include INTERNAL_KEYS, so token counts feeding budgets and compression thresholds will shift — pin the old encoding explicitly if you depended on its numbers.
  • Gateway auth and CORS (behavioral change) — With server.apiKey / TDAI_GATEWAY_API_KEY and CORS origins configured, every route except /health now demands a Bearer token compared in constant time against timing attacks; clients must send it (Hermes reads MEMORY_TENCENTDB_GATEWAY_API_KEY). Roll credentials out before enabling, and note that a non-empty allowlist keeps cross-origin callers blocked until you add their origins.
  • Language-adaptive prompts and BGE-M3 embeddings — The l1-extraction, l1-dedup, scene-extraction and persona-generation prompts now write free-text fields in the user's message language, letting you drop locale tuning (issue #38). embedding.sendDimensions: false omits the dimensions field for fixed-dimension backends like BGE-M3 — the fix if your provider rejects or ignores that parameter.
  • Fail-soft reliability and state handling — L2 LLM errors now restore scene_blocks/ from the latest backup instead of wiping it (#88), and api.runtime.state gained optional chaining plus a resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw fallback (#78/#85/#79). Watch two things: the contextEngine slot ID is now memory-tencentdb (old configs may be reset by openclaw doctor --fix), and sanitizeText uses the u flag so emoji/CJK/Math Bold survive instead of being stripped (#30/#31).
  • Compression, cleanup and cost wins — Aggressive compression is a single-pass cut-point (615 messages, 84s → 14s), boundary-delete replay drops 38s → 122ms, and a fast token-estimate short-circuit cuts first assemble from 29s → 1.4s. Cleaner safety guards (reject invalid cutoffs, block deletion above expired/total > 80%, min-keep floor) plus new offload.mode: "collect" (data-only, no L3 compression) make bulk runs safer for large histories.
  • No breaking changes — all configuration changes are backward compatible.

[0.3.6] - 2026-05-28

🚀 新功能

  • Recall 上下文预算控制 (#71 / #70)：新增 recall.maxCharsPerMemory 与 recall.maxTotalRecallChars 配置，按分数顺序裁剪超长条目并丢弃溢出部分，避免长会话因记忆膨胀挤占上下文。
  • L1 / L2 / L3 提示词按用户输入语言自适应 (#38)：l1-extraction、l1-dedup、scene-extraction、persona-generation 四个 prompt 的自由文本字段现在跟随用户消息语言书写，无需配置 locale。
  • Embedding sendDimensions 可选关闭：新增 embedding.sendDimensions 配置项，设为 false 时省略请求体中的 dimensions 字段，可对接 BGE-M3 等固定维度模型。
  • Gateway 可选 Bearer 鉴权 + CORS 白名单：新增 server.apiKey / TDAI_GATEWAY_API_KEY 与 server.corsOrigins / TDAI_CORS_ORIGINS，启用后非 /health 路由需携带 Bearer token，constant-time 比较防时序攻击。Hermes Python 客户端同步支持 MEMORY_TENCENTDB_GATEWAY_API_KEY。
  • Offload collect 模式：新增 offload.mode: "collect"，仅执行数据采集而不触发 L3 压缩，适用于纯数据积累或调试场景。

🐛 修复

  • L2 LLM 失败导致 scene_blocks/ 被清空 (#88)：LLM 抛错时自动从最新备份恢复 scene_blocks/，fail-soft 设计。
  • 场景文件名含空格导致 Persona Scene Navigation 引用失效：新增 filename-normalizer.ts，在 SceneExtractor.extract 中自动归一化文件名。
  • api.runtime.state 为 undefined 导致注册崩溃 (#78 / #85 / #79)：加可选链 + fallback，支持 runtimeState.resolveStateDir() → OPENCLAW_STATE_DIR → ~/.openclaw 三级降级。
  • contextEngine slot ID 与插件名不一致：改为 memory-tencentdb，避免 openclaw doctor --fix 重置 slot。
  • L1.5 settle 永不返回导致 L2 卡死：增加 60s 超时，未配置 Context Engine slot 时自动 force-settle。
  • Standalone 文本任务仍暴露工具 (#58 / #59)：enableTools=false 时彻底不传工具列表。
  • L2 cold-start skip 误更新 l2LastRunTime：仅在确实运行过时更新时间戳。
  • sanitizeText 误删 emoji / CJK / Math Bold 等非 BMP 字符 (#30 / #31)：正则加 u flag，只匹配孤立 surrogate。
  • Emergency 截断在 MIN_KEEP 拒绝下死锁：新增 _emergencyTruncateOversized，兜底强制删除并配对清理。
  • 多轮 aggressive compression 累计耗时：由 6 轮全量 tiktoken 改为单趟精确切点，615 条消息 84s→14s。
  • FP-HEAD-DELETE 误删新消息：改用 FP-BOUNDARY-DELETE + BOUNDARY-INCR-SKIP，重放场景 38s→122ms。
  • 首次 assemble 慢：增加 fast-token-estimate 前置短路，29s→1.4s。
  • Token 计算精度：details 加入 INTERNAL_KEYS；l3TiktokenEncoding 默认改为 cl100k_base。
  • Dockerfile.hermes 生成的 config.yaml 缺 api_key (#77 / #81)：同步写入 model.api_key。
  • 安装脚本多处问题 (#18 / #19 / #20 / #54 / #55)：支持 HERMES_AGENT_DIR 覆盖、root 不再递归 su、systemd 环境用绝对路径 node。
  • Cleaner 安全加固：拒绝无效 cutoff、expired/total > 80% 阻止删除、最小保留护栏。

✨ 改进

  • l3TiktokenEncoding 默认改为 cl100k_base，匹配主流国产/开源模型分词器。
  • Offload 日志降级：AGGRESSIVE / EMERGENCY 等降到 debug，仅超 10s 输出 WARN。
  • Docker 文档补充 cd docker/opensource 前置步骤；新增 question/consultation issue 模板。

⚠️ 配置项变化（向后兼容）

| Key | 默认值 | 说明 | |---|---|---| | recall.maxCharsPerMemory | 0 | 0/未设置 = 不裁剪 | | recall.maxTotalRecallChars | 0 | 0/未设置 = 不裁剪 | | embedding.sendDimensions | true | false 时不携带 dimensions，适配 BGE-M3 等 | | l3TiktokenEncoding | cl100k_base（原 o200k_base） | 仅在显式依赖 o200k_base 时需手动覆盖 |
