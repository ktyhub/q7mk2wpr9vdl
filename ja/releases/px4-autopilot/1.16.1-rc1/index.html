PX4-Autopilot v1.16.1-rc1

Highlights

  • Accelerometer calibration persisted in the correct frame — Backport of #25626 (#25639): accel offsets and scales are now rotated from the body frame back into the sensor frame before being saved. On airframes with non-identity sensor orientation this changes the stored calibration numbers, so vehicles calibrated on earlier 1.16 builds should be re-calibrated after flashing — otherwise the old, wrongly-framed offsets keep getting applied on reboot.
  • End-of-mission behavior and landing fixes — #25727 makes the vehicle loiter at the final waypoint when a mission completes, replacing the previous post-mission behavior; integrations that assumed auto-RTL or a hold elsewhere need to revisit their mission logic. Closely related, #25726 fixes an off-track landing bug in FlightTaskAuto. Note also that the docs now carry an explicit RTL-mode issue warning (#25623): review return-to-launch paths before flight.
  • MAVLink message spacing for low-bandwidth links — #25662 adds spacing to AVAILABLE_MODES messages to cut telemetry congestion on narrow links. Ground stations or companion computers parsing mode availability will see a lower update rate — fine for readability of the link, but latency-sensitive mode-switching logic should be validated.
  • UAVCAN ESC telemetry no longer publishes garbage at startup — #25656 initializes the ESC message before publishing instead of emitting uninitialized memory. Anyone decoding CAN ESC status or feeding it into control/health monitoring gets deterministic values during boot, removing a class of spurious startup faults.
  • SITL: UXRCE DDS agent IP is now a parameter — Backport of #25231 (#25299) moves the DDS agent IP from a hardcoded/build-time value to a runtime parameter in SITL. This removes rebuild friction for micro-ROS/DDS setups and makes parallel simulation instances against different agents practical.
  • Board and sensor coverage expanded — VOXL2 patches (#25377), VTOL attitude control for ark_fpv (#25655), CUAV 7-Nano migrating to new sensors (#25098 via #25546), and new V6X-RT sensor sets V6XRT001/002 (#25732). The CUAV 7-Nano sensor swap is the one to watch: existing sensor and calibration configuration may not carry over cleanly to the new hardware revision.

No breaking API changes in this release.
