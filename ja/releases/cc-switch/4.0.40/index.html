CCスイッチ v4.0.40

このバージョンでは、Grok Build の公式カードを認証センターの xAI アカウントにバインドできるようになり、Claude や Codex 公式カードなどの複数の Grok アカウント間で切り替えることができます。 プラグイン ページ は反重力 CLI をサポートしています。 使用統計 では、サプライヤーとモデルのリストにキャッシュ ヒット率が追加されました。 Xiaomi MiMo には残高とトークン プランの制限クエリが組み込まれています。認証センターのアカウント カードは、サイドバー アプリケーションの順序と非表示設定に従います。 このバージョンでは、ディープ リンク インポート MCP、使用スクリプト、SQL インポート、非ネイティブ リスニング アドレスのセキュリティ チェックも強化され、データベース、ローカル ルーティング、使用状況の同期、セッション検索、およびアプリケーション ページの速度が向上しています。また、 Kim Code Desktop のメインエージェントの使用はカウントされません。反重力の出力速度が 4.0.38 から誤って高くなります。 T3 コードの反重力セッションと単独で実行されている ACP は表示されません。ミストラル API の公式応答は、考え始めた後は空です。 Parallel View ツールが呼び出された後、Kimi ネイティブの応答は常に 400 を報告します。 WorkBuddy エンタープライズ アカウント ポイントは使用済みとして表示されます。トレイに表示されません xAI クォータと公式アカウントは Web サイトのドメイン名として表示されます。重複したスキルがスキルページの「ディスカバリー」に表示されます。 「アプリケーション」ページには、バージョンを確認するまでインストール状況は表示されません。 English → | 日本語版 →

追加

Grok 公式カードは xAI アカウントにバインドされています

Grok Build の Grok 公式フォームに「ログイン メソッド」 (#9321、close #8599) が追加されました。認証センターで xAI アカウントを選択し、xAI アカウントを追加または管理するか、「Grok CLI でログイン」することができます。使い方はクロード、コーデックスオフィシャルカードと同様です。

  • 各バインドされたアカウントは個別のカードです。名前に口座番号を含めると、好きなだけカードを追加できます。アカウントに関連付けられていないユーザーは、同じ固定カードを引き続き使用します。
  • アカウントがバインドされているカードに切り替えると、CC Switch はまずこのアカウントのログインを更新し、次にそのアカウントを Grok CLI の ~/.grok/auth.json に書き込みます。ファイル内の他の内容は変更されません。このアカウントがすでにログインしている場合、Grok CLI は書き込まれません。ネットワークに一時的に障害が発生すると、後で再試行するように求められます。アカウントが実際に無効な場合は、認証センターにアクセスして再度ログインするように求められます。
  • 番号を変更する前に、Grok CLI によって現在ログインしている番号が認証センターに収集されます。 「Login with Grok CLI」カードに切り替えると、最初の番号変更前の番号に戻ります。
  • 認証センターでアカウントを削除するときに、Grok CLI が CC スイッチを使用してこのアカウントにログインしている場合、元のログインが復元されます。元のアカウントがなくなっている場合は、ログアウトします。
  • アカウント番号にバインドされているカードの場合、カード、使用量、およびパレットの制限はすべてこの番号に従ってチェックされます。アカウントのないカードの Grok CLI ログインの有効期限が切れた場合は、認証センターで同じユーザーのアカウントを使用して制限を確認してください。 ###反重力 CLI プラグイン 「プラグイン」ページは、Antigravity CLI (#9882、#9885) をサポートしています。他のアプリケーションと同様に、agy 独自のコマンド ラインを呼び出すことができます。 「Discover」で公式およびパートナーマーケットのプラグインを参照して、インストール、有効化、無効化、アンインストール、更新を行うことができます。
  • アップデートする前に、市販のバージョン番号を比較してください。最新バージョンの場合は再インストールしないでください。
  • プラグインが実行中の Antigravity セッションまたはバックグラウンド サービスによって占有されている場合、まずプラグインを閉じて再試行するように求められます。
  • 古い Antigravity アプリケーションによってインストールされたプラグインは、数値で名前が付けられたディレクトリに配置されます。 CC Switch ではアップデートできません。 「検出」でそれらをアンインストールして再インストールするように求められます。

使用状況統計: プロバイダーおよびモデルごとにキャッシュ ヒット率を表示します

使用状況統計の「サプライヤー」および「モデル」リストでは、トークンの後に「ヒット率」列が追加されるため、どのサプライヤーとどのモデルがキャッシュを使用していないかがわかります。アルゴリズムはリクエスト ログのヒット率と同じです (キャッシュ ヒット数 ÷ キャッシュ可能な入力数)。各行のキャッシュ ヒットとキャッシュ可能な入力を合計すると、一番上の合計になります。キャッシュ可能な入力がない行には「—」が表示されます。

Xiaomi MiMo 残高とトークン プランの制限

Xiaomi MiMo のプロバイダーには 2 つの公式クエリ (クローズ済み #9404) が組み込まれているため、コンソールの Cookie 使用スクリプトに依存する必要はなくなりました。

  • トークン プラン (tp- で始まるキー): 使用済みクォータと合計クォータ、およびこの期間の終了時刻が表示されます。
  • 残高 (sk- で始まるキー): 利用可能な残高 (凍結部分を差し引いたもの) を表示します。残高が 0 の場合は、無効な Key とはみなされません。

認証センター カードはサイドバー アプリケーションに続きます

認証センターのアカウントカードは、「アプリケーション」ページにドラッグしたアプリケーションの順に並んでいます。このアカウントを使用するすべてのアプリケーションが非表示になっている場合にのみ、カードが非表示になります (Copilot、ChatGPT、xAI アカウントは、Claude Code などのアプリケーションのサプライヤーによっても使用されます)。サプライヤーフォームからスキップされたカードは常に表示されます。

新しいプリセットを追加

StringAIを追加しました。

変更

  • データベースとローカル ルーティングが高速化 (#9820、#9821): メイン データベースが WAL モードに切り替えられ、各ルーティング リクエストで読み取られる構成、ルーティング、価格設定、およびフェイルオーバー キューがキャッシュから読み取られるように変更され、ルーティング データベース操作が別のスレッドに移動され、リクエストを処理するスレッドが占有されなくなります。リクエストを転送するときに会話のコンテンツがコピーされる回数が 1 回減り、書き換えられていないリクエストに対してプライバシー フィルタリングが繰り返されなくなります。
  • 使用状況の同期が高速化 (#9817、#9818): 各アプリケーションのセッション ログが並行してスキャンされます。使用スクリプトは別のスレッドで実行されるため、他のリクエストの速度が低下することはなくなりました。
  • 会話コンテンツの検索が高速化 (#9827、#9896): 1 つまたは 2 つの単語の検索ではテキスト全体がスキャンされなくなりました。入力を続けると、最後に完了していない検索がキャンセルされます。検索インデックスの形式が変更され、アップグレード後の最初の検索でインデックスが再構築されます。
  • 「アプリケーション」ページがより速く開きます (#9418、#9886、閉じる#9884): まず、各ツールのバージョンチェックを待たずに、マシンのインストールパスに従って「インストール済み/未インストール」グループを表示します。各ツールのバージョンも同時にチェックされ、チェック後に各ツールが表示されます。

セキュリティ

  • ディープ リンク インポート MCP (#9831): 確認ボックスには MCP サーバーのすべてのフィールド (作業ディレクトリ、リクエスト ヘッダーなどを含む) が表示され、リスクの高いフィールドは赤色でマークされます。ローカル環境変数を読み取り、補助コマンドを実行し、作業ディレクトリをネットワーク共有パスにポイントするか、構成アドレスが http / https ではない場合は、インポートを直接拒否します。
  • スクリプトの使用方法 (#9829): スクリプトによって送信されたリクエストはリダイレクトに従わなくなり、CC スイッチ自体のルーティング ポートに送信できなくなりました。応答は最大 2 MiB を読み取ることができます。スクリプトに入力されたキー、アドレス、その他の変数は正しくエスケープされます。ディープリンク内の使用状況クエリアドレスもチェックされます。イントラネットまたはローカル アドレスの場合は、確認ボックスが表示されます。
  • SQL インポート (#9832): SQL バックアップまたは WebDAV / S3 同期スナップショットをインポートする場合、トリガーとビューの作成は許可されず、最大ファイル サイズは 512 MiB で、実行は 30 秒を超えると中止されます。
  • 非ローカル リスニング アドレスのホスト チェック (#9833): ルーティング サービスが 0.0.0.0 / :: をリッスンする場合、DNS の再バインドを防ぐために、ローカル マシンからのリクエストもホスト チェックに合格する必要があります。

修正

  • ** Kim Code Desktop のメイン エージェントの使用量はカウントされません** (#9505、#9498 を参照): Kim Code Desktop 1.3.5 はセッション ログ形式を変更し、メイン エージェントの使用量はスキップされ、サブエージェント モデルは unknown として表示されます。両方の形式を二重計算せずに読み取ることができるようになりました。アップグレード後、以前に見逃された使用法とモデルを補うために、古いログが再スキャンされます。
  • 反重力の出力速度が誤って高い (#9858): 4.0.38 以降、長期間検討されてきたリクエストでは数万 tok/s が表示されることがあります。 Antigravity の出力トークンには隠された思考が含まれており、最初の単語の時間にも思考時間が含まれます。現在は完了時間に基づいて計算されます。
  • T3 コードおよびスタンドアロン ACP の反重力セッションは表示されません (#9857、#9838 を参照): これらのセッションはセッション リストと使用統計に表示されるようになります。これらに対して使用できる回復コマンドはなく、CC スイッチで削除することもできません。質問の外側に T3 コードによって追加された説明は削除され、タイトルには元の質問が表示されます。
  • 思考を有効にすると、ミストラル公式 API の返信が空になります (#9902 を参照): ミストラル公式 API (提供するサードパーティ モデルを含む) は、返信を思考とテキストの断片に分割して返します。ローカルルートが読めず、返信が空か、思考プロセスがありません。両方のフラグメントを順番に読み取ることができるようになりました。アップストリームへのリクエストは変更されません。
  • Kimi のネイティブ応答は、画像を並列で表示した後も 400 を報告し続けます (#8825、#7504 を参照): Codex Desktop は、並列ツール呼び出しの結果の間にプロンプ​​トを挿入します。 Kimi のアップストリームのような厳密なネイティブ応答は、呼び出しに従わない結果を破棄し、このセッション後のすべてのラウンドで 400 が報告されます。次に、すべての結果をまとめて、挿入プロンプトを配置しましょう。
  • WorkBuddy エンタープライズ アカウント ポイントが使用済みとして表示されます (#9694 を参照): エンタープライズ アカウントは、企業の使用状況を確認するために変更され、合計金額、使用済み、有効期限が表示されます。無制限の場合は「無制限、N 使用済み」と表示されます。金額が見つからない場合、クエリは失敗し、「使用済み (合計 0)」は表示されなくなります。
  • xAI クォータがトレイに表示されない (#9899 を参照): Codex および Claude Code の xAI OAuth プロバイダー (Codex アグリゲーションのメンバーを含む) も、バインドされた xAI アカウントに応じてトレイにクォータを表示します。バインドされていない場合は、メイン インターフェイス カードと一致する認証センターのデフォルト アカウントが使用されます。
  • トレイ内の公式アカウントは Web サイトのドメイン名として表示されます (#9863): 管理対象アカウントが含まれる公式 Codex カード、Codex OAuth、GitHub Copilot、および xAI OAuth カードもバインドされています。トレイのサブタイトルにはログインしているアカウントが表示されます（手動メモが優先されます）。メイン インターフェイスの xAI OAuth カードにはアカウント番号も表示されます。トレイは、認証センターへのログイン、デフォルトのアカウントの切り替え、削除またはログアウト後に更新されます。
  • スキル ページの「検出」に重複したスキルが表示される: 同じウェアハウスの最後のディレクトリにある同じ名前の 2 つのスキルが、同じディレクトリにロードされます。 「Discover」は当初 2 行表示されていましたが、ウェアハウスのルート ディレクトリに最も近い 1 行のみが表示されるようになりました。
  • OpenCode Desktop に付属する CLI は、npm を使用してアップグレードするように求められます (#9099): この CLI のインストール ソースは OpenCode Desktop として表示され、デスクトップ アプリケーションで更新され、「すべてのアップグレード」にはカウントされなくなったと説明されています。別途インストールした OpenCode は通常通りアップグレードされます。
  • 64 MiB 上限に近いストリーミング イベントが誤ってスキップされる (#9867): 4.0.39 によって追加されるバッファー上限が、単一のイベントに基づいて判断されるように変更されます。上限に近い通常イベントが、同じブロック内の次のイベントと一緒に破棄されなくなりました。

アップグレード手順

  • ルーティング サービスが 0.0.0.0 / :: を監視し、カスタム ホスト名 (.local、.internal、.localhost で終わらない) を使用してこのマシン上のルートにアクセスする場合、アップグレード後に 403 を受け取ります。このホスト名を「ローカルルート」の「接続アドレス」に入力する必要があります（このアドレスは各クライアントの設定にも書き込まれます）。 LAN、WSL、Docker 内の他のデバイスは影響を受けません。
  • セッション コンテンツ検索のインデックスは、アップグレード後の最初の検索時に再構築されます。セッションが多い場合、最初の検索は遅くなります。

cc-switch v4.0.40

Highlights

  • Grok Official now supports xAI account switching — #9321 adds account-bound Grok cards that refresh credentials and write only the selected identity to ~/.grok/auth.json, preserving its other contents. Quotas follow the bound account, while deleting an account or returning to “Follow Grok CLI login” restores the previous CLI identity.

  • Antigravity CLI joins the plugin manager — #9882 and #9885 support discovering and managing official and partner-market plugins through agy. Updates skip current versions and require stopping active sessions; plugins installed by older Antigravity versions into numbered directories must be uninstalled and reinstalled because CC Switch cannot update them.

  • Quota diagnostics are more actionable — Supplier and model tables now expose cache-hit rate, making cache-unfriendly workloads visible. Xiaomi MiMo also gains built-in queries for tp- Token Plan usage and sk- balance, including frozen-fund adjustments, removing the need for cookie-scraping usage scripts.

  • Import and routing surfaces are hardened — #9831, #9829, and #9832 reject risky deep-link MCP configurations, restrict usage-script redirects and response size, and block SQL triggers/views with new size and execution-time limits. Migration: if routing listens on 0.0.0.0 or :: and local requests use a custom hostname, expect HTTP 403 until that hostname is added under Local Routing → Connection Address (#9833).

  • Routing, usage collection, and search are faster — WAL, cached request-path configuration, and dedicated database threads reduce routing contention (#9820, #9821); session logs are scanned in parallel, and usage scripts run off the request path. Migration: the search-index format changed, so the first search after upgrading rebuilds the index and may take longer for large histories (#9827).

  • Provider compatibility fixes prevent empty or stuck sessions — Mistral responses now preserve reasoning/body fragment order, and Kimi native Responses groups parallel image-tool results before intervening prompts to prevent subsequent turns from repeatedly returning HTTP 400 (#8825). Antigravity throughput is recalculated against full elapsed time so hidden thinking no longer inflates tok/s, while the 64 MiB streaming fix avoids dropping valid near-limit events (#9867).

CC Switch v4.0.40

本版本让 Grok Build 的官方卡可以绑定授权中心里的 xAI 账号，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。插件页支持 Antigravity CLI；用量统计的供应商和模型列表加了缓存命中率；小米 MiMo 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

新增

Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（#9321，关闭 #8599），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

  • 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
  • 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 ~/.grok/auth.json，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
  • 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
  • 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
  • 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

Antigravity CLI 插件

「插件」页支持 Antigravity CLI（#9882、#9885），和其他应用一样调用 agy 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

  • 更新前先比对市场上的版本号，已是最新就不重装。
  • 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
  • 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 #9404），不用再靠抓控制台 Cookie 的用量脚本：

  • Token Plan（tp- 开头的 Key）：显示已用和总额度，以及本期结束时间。
  • 余额（sk- 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

新增预设

新增 StringAI。

变更

  • 数据库与本地路由更快（#9820、#9821）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
  • 用量同步更快（#9817、#9818）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
  • 会话内容搜索更快（#9827、#9896）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
  • 「应用」页打开更快（#9418、#9886，关闭 #9884）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

安全

  • 深链接导入 MCP（#9831）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
  • 用量脚本（#9829）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
  • SQL 导入（#9832）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
  • 非本机监听地址的 Host 检查（#9833）：路由服务监听 0.0.0.0 / :: 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

修复

  • Kimi Code Desktop 主 agent 的用量没统计（#9505，见 #9498）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 unknown。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
  • Antigravity 输出速度虚高（#9858）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
  • T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到（#9857，见 #9838）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
  • Mistral 官方 API 开思考后回复为空（见 #9902）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
  • Kimi 原生 Responses 在并行看图后一直报 400（#8825，见 #7504）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
  • WorkBuddy 企业账号积分显示为已用完（见 #9694）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
  • 托盘里看不到 xAI 额度（见 #9899）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
  • 托盘里官方账号显示成网站域名（#9863）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
  • Skills 页的「发现」里出现重复的技能：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
  • OpenCode Desktop 自带的 CLI 被提示用 npm 升级（#9099）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
  • 快到 64 MiB 上限的流式事件被误跳过（#9867）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

升级说明

  • 路由服务监听 0.0.0.0 / ::、又在本机用自定义主机名（不以 .local、.internal、.localhost 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
  • 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
