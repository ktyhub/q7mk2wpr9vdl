cc-switch v4.0.26

#cc-スイッチ v4.0.26 #CCスイッチv4.0.26 このバージョンでは、認証センターと公式サプライヤー カードに各アカウントのサブスクリプション プランを表示できるようになります。 GitHub Copilot アカウントには、上限のあるすべてのクォータがリストされます。ワンクリックのインポート リンクで、Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi のサプライヤーもインポートできるようになりました。 Codex カードは、GPT モデルの公式 Fast ファイルを保持することを選択できます。 CC Switch は、システム エージェントが Codex および Grok Build からローカル ルーティングへのリクエストを引き継ぐときに通知します。 DeepSeek Harness は、WSL にインストールされたときに構成ディレクトリを設定し、管理することもできます。このバージョンでは、パフォーマンスの最適化も行われています。サプライヤー リスト、メイン ウィンドウの読み込み、起動、セッションの読み取り、ルート転送がすべて高速になり、セッションの同期がデータベースを占有するときにインターフェイスが停止することがなくなりました。さらに、IPv6 が利用できない場合、ルーティング リクエストが 2 分以上停止し、ログインする必要がある MCP サーバーが接続に失敗したことを示し、Claude Desktop ルーティング カードがモデルを変更して有効になりません。Codex がルーティング経由でチャットに転送されるとキャッシュ ヒット率が低下します。GitHub Copilot の Grok リクエストが 422 を報告し、応答が繰り返し表示され、ポップアップ ウィンドウがぼやけます。 Retina 以外のディスプレイ。 4.0 の完全なアップデート内容については、v4.0 リリース ノート を参照してください。 English → | 日本語版 →

追加

アカウント サブスクリプション プラン

以前は、認証センターの Claude アカウントのみがサブスクリプション プランを書き込み、他のアカウントはログイン日のみを表示していました。同じサービスの Max アカウントと Free アカウントはまったく同じに見えます。 GitHub Copilot、ChatGPT、Kimi、Antigravity、および xAI アカウントの 2 行目の先頭にもサブスクリプション プランが記述されるようになりました。 Codex、Kimi、Antigravity、Gemini CLI の公式カード、Copilot および xAI アカウント カードにも、サブタイトルの後に「・プロジェクト名」が追加されます。

  • カード上のプラン名はクォータ クエリの結果に直接基づいており、複数のリクエストは送信されません (Kimi、Antigravity、および xAI は、クォータを確認するときにプラン名を取得するためにもう 1 つの並行リクエストを持ちます)。プラン名はクォータがロードされた後にのみ表示され、クォータをチェックしないカードは表示されません。
  • プラン名が見つからない場合は、プラン名が表示されないだけで、金額は通常どおり表示されます。更新が失敗した場合、最後に見つかったプランが保持されます。
  • Grok CLI でログインした Grok Build カードと、アカウントのない Antigravity カードにはまだプラン名がなく、残高を確認する方法ではこの情報を取得できません。

GitHub 副操縦士 すべての残高を表示

以前は、Copilot アカウントには高度なリクエストの割合のみが表示されていました。上限のある各アイテムに独自の行が追加されました。カーソルを合わせると「残り/合計」が表示され、無料アカウントのコード補完とチャット数も表示されます。

  • 高度なリクエストの名前は Credits に変更されます。これは Codex 内の名前と一致しており、トレイでも同じです。
  • 無料アカウントにはクレジットがありません。以前は「残量100%」と表示されていましたが、現在は「現在のプランには含まれておりません」と表記され、サプライヤーカードにもこの項目は表示されなくなりました。

ワンクリックインポートでより多くのアプリケーションをサポート

以前は、Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness、および Oh My Pi のベンダー リンクは完全に拒否されていました。これらのアプリへのリンクもインポートできるようになりました。

  • Claude Desktop: リンクが Anthropic 形式で、モデル名が claude- で始まる (またはモデルが書かれていない) 場合、直接接続カードにインポートされます。それ以外の場合は、モデル マッピング カードにインポートされ、リンク内のモデルに従って 4 つのスロットが埋められます。
  • MiniMax コード、Kimi コード、DeepSeek ハーネス、Oh My Pi: Pi などの単一モデルとしてインポートされ、モデルがリンクに含まれている必要があります。
  • Oh My Pi は、環境変数名またはコマンドとして特定の方法で書き込まれた Key を読み取ります。インポート後、リンク内のアドレスにローカルキーが送信される場合があります。したがって、このタイプのキー (! で始まり、小文字は含まれないなど) はインポートを拒否されます。

Codex カードは公式の Fast ファイルを保持します

Codex サードパーティ カード モデル リストの GPT モデルでは、公式の Fast 速度ファイルが削除されており、Fast を選択できませんでした (#5234)。公式 ChatGPT アカウント (CPA など) を転送する転送は、実際には Fast をサポートしています。 Codex サプライヤー フォームの [詳細オプション] の [アップストリーム形式] に [公式高速ファイルを保持する] があります。これはデフォルトではオフになっており、アップストリーム形式が応答の場合にのみ表示されます。 Codex を開いて Fast を選択すると、リクエストには service_tier=priority が含まれます。

  • 公式 ChatGPT アカウントを転送する転送のみが認識されるため、クォータの消費が早くなります。他のアップストリームはエラーを報告するか、より高い料金を請求される可能性があります。
  • 以前に公式カードで「Fast」を選択したことがある場合、カードを開いた直後にここで有効になります。集約モードでは効果がありません。変更後はCodexを再起動する必要があります。

システムエージェントがローカルルートを引き継いだときにアラートを送信する

Clash などのプロキシ ツールが有効になっている場合、Codex および Grok Build によってローカル ルート (http://127.0.0.1:<port>) に送信されたリクエストは、システム プロキシによって取得され、空の 502 を返す前にリモート ノードに転送されることがあります (#9221)。 Codex には「502 Bad Gateway」のみが表示され、CC Switch はリクエストを受信できません。ログが残っていないので確認が困難です。 Codex または Grok Build がルーティング モードに入ると、CC Switch はクライアントと同じプロキシ ルールに従ってバックグラウンドでローカル ルートにリクエストを送信します。リクエストを返せない場合、警告がログに記録されます。手動でルーティング モードに入ると、プロキシ ツールでローカル アドレスを直接接続する方法 (たとえば、クラッシュ ルールの先頭に IP-CIDR,127.0.0.0/8,DIRECT,no-resolve を追加する) を説明するプロンプトがインターフェイスにポップアップ表示されます。

DeepSeek ハーネス設定ディレクトリ

以前は、DeepSeek Harness は DSH_HOME または ~/.dsh のみを認識し、WSL にインストールされた DSH は Windows 版 CC Switch (#9239) では管理できませんでした。 「設定 → アプリケーション構成」に DeepSeek Harness 列があり、ここで構成ディレクトリを設定できます。サプライヤー、スキル、ディレクティブ ファイル、セッション、および使用状況のインポートはすべてこのディレクトリに従います。 WSL にパスを入力すると、その WSL ディストリビューションでバージョンの検出、インストール、アップグレードも実行されます。

変更

  • パフォーマンスの最適化:
    • サプライヤー リストの読み取りが速くなり、サプライヤーの数が増えるほど、より明確になります。変更されていないサプライヤーがデータベースに繰り返し書き込まれることはなくなり、クラウド同期もトリガーされなくなります (#9180)。
    • セカンダリページとサプライヤーエディターを使用時にロードするように変更し、メインウィンドウの起動時にロードされるスクリプトを半分に削減しました (#9181)。
    • 起動時のログのクリーニングはバックグラウンドに移動します。スケジュールされた更新は、ウィンドウが非表示または最小化されている場合には一時停止され、ウィンドウが表示されていても前面にない場合には通常どおり更新されます (#9182)。
    • セッションレコードを読み取るときに、データのコピーを 1 回減らすと、軽量モードに移行した後にセッションキャッシュが解放されます (#9183)。
    • ルーティングは、特に応答が長い場合に、大量のメモリ コピーを行わずにストリーミング応答を転送します。フェイルオーバーによるデータベースの読み取り頻度は低くなります (#9161)。
  • セッション同期中にインターフェイスがスタックしなくなりました (#9178): 大きなセッション ファイルは、同期中に数十秒間データベースを占有します。この期間中、スキル ページを開く、Pi または Oh My Pi に切り替える、ネットワークまたはデータ設定を開く、アイコンの選択、統合サプライヤー パネル、速度テスト、およびその他の操作を行うと、同期が完了するまでウィンドウ全体とトレイ全体がスタックします。現在、これらの操作はバックグラウンドで待機しており、インターフェイスは通常どおりに応答します。
  • セッション読み取りページのツールバーの再レイアウト (#9109): 最初の行にはパスと読み取りツールが含まれ、2 行目には時間、セッション統計、モデル、および使用状況が含まれます。線の最初と最後に落ちやすい分離点を削除します。モデル名が長すぎる場合は改行して表示されます。カーソルを置くと完全な名前が表示されます。
  • デフォルト: Grok Build のデフォルト モデルは grok-4.7 に変更され、Kimi プリセット (Codex を除く) のデフォルト モデルは kimi-k3.1-pro に変更され、Hermes の Qianwen コーディング プランのデフォルト モデルは qwen3.7-plus (#9193) に変更されます。 TeamoRouter は、teamorouter.com ドメイン名に変更されます。 Claude Desktop オフィシャルカードのダウンロードリンクが claude.com/download に変更されました。すでに追加されているサプライヤーは影響を受けません。

修正

  • IPv6 が利用できない場合、ルーティング リクエストは送信されるまでに 2 分以上遅延します (#9212)。 Zhipu GLM や Alibaba Cloud Bailian などのサービスのドメイン名は、最初に IPv6 アドレスを解決します。 IPv6 がブロックされているネットワークでは、ローカル ルーティングは、IPv4 に切り替える前に、システムが各 IPv6 アドレスをタイムアウトするまで待機する必要があります。これには、macOS では約 150 秒、Windows では約 43 秒かかります。これで、IPv6 アドレスが 300 ミリ秒以内に接続できなかった場合、同時に IPv4 も試行され、リクエストの内容は変更されません。
  • ログインが必要な MCP サーバー、接続チェックで「接続に失敗しました」と表示される (#9190)。 Notion や Sentry などのサーバーには OAuth ログインが必要です。クライアントにログインした後は、通常どおり使用できます。ただし、クライアントのログイン情報を使用せずに CC Switch がチェックを行うと、失敗と判断されます。この状況では黄色の点が表示され、ホバーするとサーバーに接続できるがログインのみが必要であることが示されます。 CC Switch は依然として、クライアントの保存されたログイン資格情報を読み取りません。
  • Claude Desktop ルーティング カードのモデルを変更した後、古いモデルが Claude Desktop に残っているため、削除して再構築します (#9203)。保存する際、「メニュー表示名」を空欄にすると、機種名が自動的に入力されます。後から機種変更しただけの場合、表示名は古いままになります。これで、表示名が旧モデル名と同じ場合は、新モデルに合わせて表示名も変更され、自分で付けた名前はそのまま残ります。
  • Codex をルーティング経由でチャットに転送する場合、会話中に設定を変更するとキャッシュ ヒット率が低下します。たとえば、途中で sandbox_mode に切り替えた後、Codex はこのラウンドの先頭に説明を挿入します。以前は、会話の先頭にマージされ、履歴全体が書き換えられ、上流のすべてのキャッシュが無効になります。このメモは現在もそのまま残されており、以前の履歴は変更されません。
  • Codex がチャット経由でルーティングされる場合、別のセッションの思考内容が現在のセッションに混在する可能性があります。アップストリームによって提供されるツール呼び出し ID は簡単に繰り返すことができます (exec_command:0 など)。ローカル ルートが再起動されるか、キャッシュが使い果たされた後、他のセッションで同じ名前の呼び出しが見つかる可能性があります。 Codex セッションによって区別されるようになり、同じセッション内のみを検索します。
  • ルーティング リクエストが失敗した場合、クライアントのモデル名がリクエスト ログに記録されます。たとえば、Claude Desktop のバックグラウンド タスクは claude-haiku-4-5-20251001 を使用します。このカードのモデルにマッピングした後、アップストリームは 429 を報告しますが、ログには Haiku が表示されます。設定していないモデルが呼び出されているようです。失敗したリクエストも、成功したリクエストと同様に「claude-haiku-4-5-20251001 → 実際のモデル」と書き込まれるようになりました。
  • ローカル ログインに続くクロードの公式カードには、ログインの有効期限が切れると常に「トークンを更新する」と表示され、回復するにはクロード コードを再度実行する必要があります。ログインの有効期限が切れると、CC スイッチはクロード コードにログイン自体を更新し、クォータを再度読み取るように要求します。 Claude 設定ディレクトリが設定されている場合はスキップします。
  • Claude Code および Claude Desktop の自動モードのセキュリティ分類子が利用できない場合、クライアントは再試行を繰り返し、クォータを消費し続けます (#9201、#9199)。現在、ツールの結果の 3 回連続のラウンドで分類子が使用できないことが報告されると、ローカル ルートは直接エラーを返し、アップストリームに送信しなくなりました。続行するには新しいメッセージを送信してください。
  • Grok モデル時間 422 を使用した GitHub Copilot 経由のコーデックス (#7989、#7988)。 Copilot の Grok リクエストは、直接 xAI と同じ方法で処理されるようになりました。
  • Codex が GitHub Copilot を通過すると、同じ応答が 2 回表示されます (#8025、#7977)。
  • アプリケーションのインストールまたはアップグレード時に、同じ名前の既存のファイルが見つかり、プロンプトには npm が推奨する --force (#9196、#9173) のみが含まれます。このファイルはおそらく別のインストール方法からのものであり、--force はそれを直接上書きします。これで、プロンプトに競合するファイル パスが書き出されます。バックアップの名前を変更して再試行することをお勧めします。
  • スキルにファイル ソフト リンクがある場合、WebDAV 自動同期が失敗します (#9197)。たとえば、CLAUDE.md と GEMINI.md の両方が AGENTS.md にリンクされている場合、同じ名前のファイルがパッケージに表示されます。各ファイルは独自の名前を保持するようになりました。
  • Codex サブエージェントの同時実行上限に関する 2 つの問題 (#9148): config.toml のテーブル ヘッダーの後ろにコメントがある場合、上限を変更すると [features.multi_agent_v2] が上書きされる可能性があります。 [agents] を引用符付きのキー名として記述すると、Codex によって認識されない余分な重複フィールドが書き込まれます。説明には、変更は新しいセッションに対してのみ有効であることも追加されています。
  • ヘッドレス プロファイルを使用している場合、DeepSeek ハーネスは CC スイッチによって保存されたキーを見つけることができません。MISSING_CREDENTIAL が報告されます。ヘッドレス プロファイルに書き込むときに、DSH ドキュメントに従って資格情報の読み取りが有効になるようになりました。この項目を変更したプロファイルは変更されません。
  • 1x モニターでは、「モデルの選択」などのポップアップがぼやけて表示されます (#9238)。ポップアップ ウィンドウが中央にある場合、ウィンドウが 0.5 ピクセルに収まる可能性があり、非 Retina ディスプレイではテキストと境界線がぼやけて表示されます。
  • macOS では、MCP フォーム、プロンプト ワード エディター、スキル ウェアハウス、セッション検索などの入力ボックスに入力すると、最初の文字が自動的に大文字に変更されます。その結果、環境変数名、リクエスト ヘッダー、コマンド、およびアドレスが誤って保存される場合があります。
  • Linux AppImage は、古いバージョンの libwayland-client (#9229、#8723) をパッケージ化しています。これは、Intel Core Graphics および Wayland を備えた環境では開けない可能性があります。

cc-switch v4.0.26

Highlights

  • Subscription visibility — Authorization and official-provider cards now show plan names and every metered GitHub Copilot quota, including Free-tier chat and completions. Free accounts report “not included” instead of a misleading 100% for Credits; plan names appear only after quota loading and silently disappear on lookup failure.

  • Broader one-click imports — Links now work for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness, and Oh My Pi. Claude Desktop links become direct connections only when using Anthropic-format claude-* models or no model; otherwise they become model-mapping cards. The other four require an explicit model, and dangerous Oh My Pi key syntax—such as !-prefixed values—is rejected to prevent accidental credential exposure.

  • Codex Fast tier and new behavior — Responses-format Codex providers can opt into Preserve official Fast tier, adding service_tier=priority when Fast is selected. This works only with gateways that forward official ChatGPT accounts, may consume quotas faster or fail elsewhere, does not apply in aggregate mode, and requires restarting Codex. Prior Fast selections activate once enabled.

  • Proxy and WSL diagnostics — Codex and Grok Build now probe local routes under the client’s proxy rules, warning when requests may escape to a proxy node and return an empty 502; add 127.0.0.0/8 to your proxy’s direct rules. DeepSeek Harness gains a configurable directory covering providers, Skills, instructions, sessions, and usage, with WSL paths also used for detection, installation, and upgrades.

  • Faster, more responsive routing — Lazy loading, reduced database writes and copies, background startup maintenance, and streamlined streaming reduce startup, session, and forwarding overhead (#9180, #9181, #9183, #9161). Session synchronization now queues UI actions instead of freezing the window and tray (#9178), while IPv6 connection failures fall back to IPv4 after 300 ms rather than waiting roughly 150 seconds on macOS (#9212).

  • Routing correctness fixes — Failed requests now log both the client-requested and actual upstream models, making mapping-related 429s diagnosable. Codex-to-Chat preserves history when settings change, preventing cache invalidation, and isolates tool-call lookup by session to stop cross-session reasoning leakage (#9203 covers a related Claude Desktop model-rename fix). Also notable: unavailable safety classifiers now stop after three rounds instead of retrying indefinitely (#9201); manually customized Claude configuration directories skip automatic login refresh.

CC Switch v4.0.26

本版本让授权中心和官方供应商卡片显示每个账号的订阅计划，GitHub Copilot 账号会列出所有有上限的额度；一键导入链接现在也能导入 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商。Codex 卡片可以选择保留 GPT 模型的官方 Fast 档；系统代理把 Codex、Grok Build 发往本地路由的请求接走时，CC Switch 会提醒你。DeepSeek Harness 可以设置配置目录，装在 WSL 里也能管理。这一版还做了一轮性能优化：供应商列表、主窗口加载、启动、会话读取和路由转发都更快，会话同步占着数据库时界面也不再卡住。另外修复了 IPv6 不通时经路由请求先卡两分多钟、需要登录的 MCP 服务器显示连接失败、Claude Desktop 路由卡片改了模型不生效、Codex 经路由转 Chat 时缓存命中率下降、GitHub Copilot 的 Grok 请求报 422 和回复重复显示、非 Retina 显示器上弹窗模糊等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

账号订阅计划

以前授权中心里只有 Claude 账号会写订阅计划，其他账号只显示登录日期，同一个服务的 Max 账号和 Free 账号看起来一模一样。

现在 GitHub Copilot、ChatGPT、Kimi、Antigravity、xAI 账号的第二行开头也会写订阅计划。Codex、Kimi、Antigravity、Gemini CLI 的官方卡片，以及 Copilot、xAI 账号卡片，副标题后面也会加上「· 计划名」。

  • 卡片上的计划名直接用额度查询的结果，不会多发请求（Kimi、Antigravity、xAI 查额度时会多一个并行请求取计划名）；额度加载出来后计划名才出现，不查额度的卡片不显示。
  • 计划名查不到时只是不显示，额度照常显示；刷新失败时保留上次查到的计划。
  • 跟随 Grok CLI 登录的 Grok Build 卡片、没绑账号的 Antigravity 卡片暂时还没有计划名，它们查额度的方式拿不到这项信息。

GitHub Copilot 显示全部额度

Copilot 账号以前只显示高级请求的百分比。现在每一项有上限的额度各占一行，悬停可以看到「剩余 / 共」，Free 账号的代码补全和聊天次数也能看到了。

  • 高级请求改叫 Credits，和 Codex 的叫法一致，托盘里也一样。
  • Free 账号没有 Credits，以前会显示成「还剩 100%」，现在写「当前计划不含」，供应商卡片上不再显示这一项。

一键导入支持更多应用

以前 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商链接会直接被拒绝。现在这些应用的链接也能导入了。

  • Claude Desktop：链接是 Anthropic 格式、模型名都以 claude- 开头（或没写模型）时，导入成直连卡片；其他情况导入成模型映射卡片，四个档位按链接里的模型填好。
  • MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi：和 Pi 一样导入成单个模型，链接里必须带模型。
  • Oh My Pi 会把某些写法的 Key 当成环境变量名或命令来读，导入后可能把你本机的密钥发到链接里的地址。所以这类 Key（以 ! 开头、没有小写字母等）会被拒绝导入。

Codex 卡片保留官方 Fast 档

Codex 第三方卡片模型列表里的 GPT 模型以前一律去掉了官方的 Fast 速度档，选不了 Fast（#5234）。转发官方 ChatGPT 账号的中转（如 CPA）其实支持 Fast。

现在 Codex 供应商表单「高级选项」里，「上游格式」下面多了「保留官方 Fast 档」，默认关闭，只在上游格式为 Responses 时显示。打开后 Codex 选了 Fast 时请求会带 service_tier=priority。

  • 只有转发官方 ChatGPT 账号的中转才认，会更快消耗额度；其他上游可能报错或按更高价格计费。
  • 以前在官方卡片下选过 Fast 的，打开后会马上在这家生效。聚合模式下不生效，改完需要重启 Codex。

系统代理接走本地路由时提醒

开着 Clash 这类代理工具时，Codex 和 Grok Build 发往本地路由（http://127.0.0.1:<port>）的请求可能被系统代理接走，转到远程节点后返回一个空的 502（#9221）。Codex 只显示「502 Bad Gateway」，CC Switch 这边也收不到请求，没有任何日志，很难查。

现在 Codex 或 Grok Build 进入路由模式后，CC Switch 会在后台按客户端同样的代理规则给本地路由发一次请求。请求回不来时，日志里会记一条警告；如果是你手动进入路由模式，界面上也会弹出提示，说明怎么在代理工具里让本机地址直连（例如在 Clash 规则最前面加 IP-CIDR,127.0.0.0/8,DIRECT,no-resolve）。

DeepSeek Harness 配置目录

以前 DeepSeek Harness 只认 DSH_HOME 或 ~/.dsh，装在 WSL 里的 DSH 在 Windows 版 CC Switch 里管不了（#9239）。

现在「设置 → 应用配置」里多了 DeepSeek Harness 一栏，可以设置配置目录。供应商、Skills、指令文件、会话和用量导入都会跟着这个目录走。填 WSL 里的路径时，版本检测、安装和升级也会在那个 WSL 发行版里进行。

变更

  • 性能优化：
    • 供应商列表读取更快，供应商越多越明显；没改动的供应商不再重复写入数据库，也就不会因此触发云同步（#9180）。
    • 次要页面和供应商编辑器改为用到时才加载，主窗口启动要加载的脚本少了一半（#9181）。
    • 启动时的日志清理挪到后台进行；窗口隐藏或最小化时暂停定时刷新，窗口可见但不在前台时照常刷新（#9182）。
    • 读取会话记录时少复制一遍数据，进入轻量模式后会释放会话缓存（#9183）。
    • 路由转发流式响应时少了大量内存复制，响应很长时尤其明显；故障转移读数据库的次数也更少（#9161）。
  • 会话同步时界面不再卡住（#9178）：大会话文件同步时会占着数据库几十秒，这期间打开 Skills 页、切到 Pi 或 Oh My Pi、打开网络或数据设置、图标选择、统一供应商面板、测速等操作会让整个窗口和托盘卡住，直到同步结束。现在这些操作都在后台等待，界面照常响应。
  • 会话阅读页的工具栏重新排版（#9109）：第一行放路径和阅读工具，第二行放时间、会话统计、模型和用量；去掉了容易落在行首行尾的分隔点，模型名太长时换行显示，悬停可看完整名称。
  • 预设： Grok Build 默认模型改为 grok-4.7，Kimi 预设（Codex 的除外）默认模型改为 kimi-k3.1-pro，Hermes 的千问 Coding Plan 默认模型改为 qwen3.7-plus（#9193）；TeamoRouter 改用 teamorouter.com 域名；Claude Desktop 官方卡片的下载链接改为 claude.com/download。已添加的供应商不受影响。

修复

  • IPv6 不通时，经路由的请求要先卡两分多钟才发出（#9212）。智谱 GLM、阿里云百炼等服务的域名会先解析出 IPv6 地址，在 IPv6 不通的网络里，本地路由要等系统把每个 IPv6 地址都超时一遍才改用 IPv4，macOS 上约 150 秒、Windows 上约 43 秒。现在 IPv6 地址 300 毫秒内连不上就同时尝试 IPv4，发出的请求内容不变。
  • 需要登录的 MCP 服务器，连通性检查显示「连接失败」（#9190）。Notion、Sentry 这类服务器需要 OAuth 登录，客户端里登录后能正常用，但 CC Switch 检查时不带客户端的登录凭据，就被判成了失败。现在这种情况显示黄色圆点，悬停会说明服务器能连上、只是要求登录。CC Switch 仍然不读取客户端保存的登录凭据。
  • Claude Desktop 路由卡片改了模型后，Claude Desktop 里还是旧模型，删掉重建才行（#9203）。保存时「菜单显示名」留空会自动填成模型名，之后只改模型时显示名还是旧的。现在显示名和旧模型名一样时会跟着新模型一起改，你自己起的名字保持不变。
  • Codex 经路由转 Chat 时，对话中途改了设置后缓存命中率下降。比如中途切换 sandbox_mode 后，Codex 会在这一轮开头插入一条说明，以前它被合并到对话最开头，改写了整段历史，上游缓存就全部失效了。现在这条说明留在原位，之前的历史保持不变。
  • Codex 经路由转 Chat 时，可能把另一个会话的思考内容混进当前会话。上游给的工具调用 ID 容易重复（如 exec_command:0），本地路由重启或缓存被挤掉后，可能找到别的会话里同名的调用。现在按 Codex 会话区分，只在同一个会话里找。
  • 路由请求失败时，请求日志里记的是客户端的模型名。比如 Claude Desktop 的后台任务用的是 claude-haiku-4-5-20251001，映射到这张卡片的模型后上游报 429，日志里却显示 Haiku，看起来像调用了一个你没配过的模型。现在失败的请求和成功的一样，会写成「claude-haiku-4-5-20251001 → 实际模型」。
  • 跟随本机登录的 Claude 官方卡片，登录过期后一直显示「令牌待刷新」，要再跑一次 Claude Code 才恢复。现在登录过期时 CC Switch 会让 Claude Code 自己刷新登录，再读取额度。设置了 Claude 配置目录时跳过。
  • Claude Code 和 Claude Desktop 自动模式的安全分类器不可用时，客户端会一直重试、持续消耗额度（#9201、#9199）。现在连续 3 轮工具结果都报告分类器不可用时，本地路由直接返回错误，不再发给上游；发一条新消息即可继续。
  • Codex 通过 GitHub Copilot 用 Grok 模型时报 422（#7989、#7988）。现在 Copilot 的 Grok 请求和直连 xAI 一样做兼容处理。
  • Codex 通过 GitHub Copilot 时，同一条回复显示两遍（#8025、#7977）。
  • 安装或升级应用时撞上已有的同名文件，提示里只有 npm 建议的 --force（#9196、#9173）。这个文件多半来自另一种安装方式，用 --force 会直接覆盖它。现在提示会写出冲突的文件路径，建议先改名备份再重试。
  • Skills 里有文件软链接时，WebDAV 自动同步失败（#9197）。比如 CLAUDE.md 和 GEMINI.md 都链接到 AGENTS.md 时，打包会出现重名文件。现在每个文件保留自己的名字。
  • Codex 子代理并发上限的两个问题（#9148）：config.toml 里表头后面带注释时，改上限可能覆盖掉 [features.multi_agent_v2]；[agents] 写成带引号的键名时，会多写一个 Codex 不认的重复字段。说明文字也补充了改动只对新会话生效。
  • DeepSeek Harness 用 headless profile 时找不到 CC Switch 保存的 Key，报 MISSING_CREDENTIAL。现在写入 headless profile 时会按 DSH 文档开启凭据读取；你自己改过这一项的 profile 保持不变。
  • 在 1x 显示器上，「选择模型」等弹窗显示模糊（#9238）。弹窗居中时可能落在半个像素上，非 Retina 显示器上文字和边框会发虚。
  • macOS 上，在 MCP 表单、提示词编辑、Skills 仓库、会话搜索等输入框里打字时首字母被自动改成大写，环境变量名、请求头、命令、地址可能因此被存错。
  • Linux AppImage 打包了旧版 libwayland-client（#9229、#8723），在 Intel 核显加 Wayland 的环境下可能打不开。
