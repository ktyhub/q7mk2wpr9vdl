#cc-スイッチ v4.0.31

CCスイッチ v4.0.31

このバージョンでは、新しいマネージド アプリケーション Tencent WorkBuddy が追加されています。カスタム モデルは WorkBuddy 独自のモデル構成に書き込まれており、WorkBuddy で直接選択できます。複数の WorkBuddy アカウント間で切り替えることもできます。切り替える前に、各アカウントのパッケージ、残りポイント、有効期限を確認できます。インターフェースは ドイツ語 で新たに追加され、README も 8 つのインターフェース言語すべてで利用可能です。 さらに、Claude Code がルーティング経由で OpenAI Responses 形式のリレーに接続されている場合、同じリレーが別の Azure リソースに割り当てられた後、セッションは各ラウンドで 400 として報告され、続行できなくなります。ルーティング経由で Gemini ネイティブ フォーマットのアップストリームに接続すると、並列ツール呼び出しは 400 として報告され、キャッシュ ヒット率は非常に低くなります。 macOS トレイのホバー プロンプトが常に画面上でハングします。 Codex によって継続された古い会話の使用法は決してインポートされません。 English → | 日本語版 →

＃＃ 追加

ワークバディ

Tencent WorkBuddy は新しいマネージド アプリケーションになります (#8757、要件については #4802、#5802、#7419、#7076 を参照してください)。 OpenCode と同様に、複数のベンダーが同時に有効です。

  • カスタム モデル: [追加] をクリックすると、サプライヤーのモデルが WorkBuddy 自身の models.json に書き込まれ、WorkBuddy のモデル選択に「名前: モデル ID」として表示されます。空白の場合は「メーカーレーベル」となります。 WorkBuddy に追加したモデルはそのまま保持されます。 WorkBuddy のカスタム モデルは、OpenAI Chat Completions 形式のみをサポートします。
    • プリセット内のモデルについては、WorkBuddy のモデル選択で思考強度を選択できます (Kimi K3.1 Pro の場合は低 / 高 / 最大など)。
    • WorkBuddy は現在、同じモデル ID の 2 回の出現をサポートしていません。プリセットを選択すると、他のカードで使用されているモデルとそのカードはスキップされます。手動で入力された重複したモデル ID にはマークが付けられ、保存できません。
  • 公式アカウント: WorkBuddy にログインしたアカウントは、ニックネーム、パッケージ、残りのポイント、ポイントの有効期限 (3 日以内に有効期限) が表示される「認証センター」に自動的に含まれます。アカウントを切り替えるには 2 つの入り口があります。このアカウントにバインドされた「WorkBuddy 公式ログイン」カードを追加するか、認証センターのこのアカウントのメニューで「WorkBuddy をこのアカウントに切り替える」をクリックします。
    • 切り替える前に必ず WorkBuddy を完全に終了してください (メニュー バー/トレイを含む)。そうしないと、現在のログインが書き戻されます。
    • 「別のアカウントにログイン」は、ローカルのログイン ページで WorkBuddy を停止するだけで、サーバー上の現在のアカウントはログアウトしません。含まれているアカウントは引き続き元に戻すことができます。
    • パッケージとポイントは、WorkBuddy が実行されており、アカウントがログインしている場合にのみ確認できます。一度確認すると、キャッシュされて表示されます。
  • MCP、スキル、プロンプト ワード: WorkBuddy の mcp.json、スキル カタログ、およびグローバル プロンプト ワード CODEBUDDY.md に同期されます。 WorkBuddy コネクタによって管理される MCP エントリは変更されません。
  • セッション管理と使用状況の統計: WorkBuddy セッションをリストし、セッション ログから使用状況をインポートします。端末ではセッションを再開できません。

ドイツ語インターフェース、8 か国語の README

  • ドイツ語: システム言語は初回起動時に自動的に選択され、トレイ メニューとショートカット パネルも翻訳されています。プライバシー フィルターのプレースホルダーは、韓国語やロシア語と同様に、ドイツ語のインターフェイスでは一時的に英語で表示されます。
  • READMEを繁体字中国語、韓国語、トルコ語、ロシア語版に追加し、インターフェースの8言語に対応しました。

その他

  • 「スキル」ページの右上隅にある「⋯」メニューに直接「今すぐ再同期」があります (#9417): 「ストレージと同期」に移動して見つける必要はありません。
  • 会話管理で「プロジェクトごと」にグループ化すると、Codex デスクトップ バージョンのどのプロジェクトにも属さない会話が 1 つのグループ「Codex チャット」にグループ化されます (#9415): 各会話は 1 つのグループに属しなくなりました。
  • リクエスト ログのステータス コード フィルタリングを追加しました: 403、404、502、503、504、520、529 (#9425)。

変更

  • プライバシー フィルターは、リクエストが送信される前の最後のステップに変更されます (#9460): 以前は、リクエストは最初にルートに入ったときにフィルターされていました。フェイルオーバーのリトライやCCスイッチ自身が生成した圧縮ダイジェストなど、後からリクエストに追加された内容は処理されません。今後は、アップストリームに送信されるたびにフィルタリングされ、より完全なカバレッジが提供されます。ツールの説明テキストは処理されません。テストも高速化され、結果は以前と一致しています。
  • Codex 使用状況のインポートが高速化 (#9400): Codex セッション ログを読み取る際の解析とメモリ割り当ての繰り返しが少なくなります。

修正

  • Claude Code / Claude Desktop は、ルーター経由で OpenAI Response 形式を転送する際に、「要求されたアイテムは別の Azure OpenAI リソースで作成されました」という 400 を時々報告し、同じセッション内で毎回エラーを報告します (#9424)。転送により、同じセッションが異なる Azure OpenAI リソースに分散され、セッション履歴には別のリソースによって生成された思考レコードが含まれます。セッション中にサプライヤーが変更された場合、同様の invalid_encrypted_content が報告されます。上流側がこの方法で拒否した場合、これらの思考記録は削除され、自動的に再試行され、セッションは続行できるようになります。通常のリクエストは影響を受けません。
  • クロード コードがルーティング経由で上流の Gemini ネイティブ フォーマットに接続されている場合、並列ツール呼び出しは 400 個の「関数応答部分の数」を報告します (#9453): 複数のメッセージに散在するツールの結果は、送信される前にマージされるようになりました。
  • クロード コードがルーティング経由で上流の Gemini ネイティブ フォーマットに接続する場合、ロング セッション キャッシュのヒット率はわずか約 20% です (#9450): クロード コードは各ラウンドに残りのトークン プロンプトを追加します。以前は履歴全体の先頭に移動されていたため、各ラウンドの始まりが異なっていました。現在は元の位置に留まり、以前の履歴はラウンドごとに変更されずに残り、キャッシュにヒットする可能性があります。
  • クロード コードがルーティング経由で上流の Gemini ネイティブ フォーマットに接続する場合、ストリーミング リクエスト レコードの使用率は低く、キャッシュ読み取りは多くの場合 0 (#9464) として記録されます。
  • macOS のトレイ アイコンの「CC スイッチ」ホバー プロンプトが常に画面上でハングアップし、アプリケーションを終了することしかできません (#9445、#9329、#9446): このプロンプトは macOS では表示されなくなりましたが、問題が発生した場合はアイコンとショートカット パネル上のドットが引き続き通知します。
  • macOS 上の他のアプリケーションが全画面表示になっている場合、メニュー バー アイコンをクリックしてもショートカット パネルが表示されません (#9331)。
  • クロード コード ルーティング モードでは、サプライヤーに設定されている CLAUDE_CODE_SUBAGENT_MODEL_FORCE を settings.json (#9451、#9455) に書き込むことはできません。現在では、他のサプライヤー固有の設定と同様にサプライヤーを使用して書き込まれるため、切り替えによって独自のグローバル設定がクリアされることはありません。
  • コーデックス 終了した古い会話を継続した後、新しく生成された使用法がインポートされていません (#9420)。
  • Codex がサードパーティ サプライヤーに直接接続されている場合、「非テイクオーバー スイッチング中に公式ログインを維持する」をオフにしても、すぐには有効になりません。公式カードに切り替えてから元に戻す必要があります (#9367): 設定を変更すると、現在のサプライヤーの構成が上書きされます。
  • Codex サードパーティ サプライヤーの公式モデルと同じ名前の GPT モデルの場合、モデル選択で表示される表示名は、設定した表示名ではありません (#9380)。
  • macOS で Claude Desktop をアンインストールした後も、「アプリケーション」ページにはインストール済みとして表示されます (#9383): Claude.app のみが認識されるようになり、残りのデータ ディレクトリはカウントされなくなりました。
  • Linux KDE Wayland ではコピー ボタンのプロンプトが正常に表示されますが、クリップボードが空であるか、古い内容がまだ残っています (#9384)。
  • 公式 Copilot CLI カードのアカウント ドロップダウン リストでは、アカウントをバインドしないオプションに「デフォルト アカウントを使用する」と表示されますが、実際には Copilot CLI 自身の GitHub ログインが使用されます (#9408): 現在は、「Copilot CLI 自身のログインに従ってください」と表示されています。
  • DeepSeek ハーネスを手動で追加したモデルは互換性オプションを設定できません (#9330): 互換性エディターも表示されるようになり、developer 文字を受け入れない Bailian 互換モードなどのインターフェイスではこの文字をオフにすることができます。
  • スキルを有効にすると、シンボリック リンクの作成に失敗したというメッセージが表示され、具体的な理由が表示されません (#9439): エラー レポートには、システムによって与えられたエラー コード (Windows の os error 5 など) が含まれるようになり、権限の問題なのか他の理由なのかを判断しやすくなりました。
  • サイドバーの下部にある「アプリケーション」と「設定」では、ドイツ語、トルコ語、ロシア語のインターフェースでテキストが切り取られます。

アップグレード手順

データベース バージョンが 25 から 26 にアップグレードされ、MCP とスキル用の WorkBuddy スイッチが追加されました。データベースはアップグレード前に自動的にバックアップされます。アップグレード後に古いバージョンにロールバックすると、古いバージョンではデータベースのバージョンが新しすぎるため開けないというメッセージが表示されます。

cc-switch v4.0.31

Highlights

  • WorkBuddy integration — Tencent WorkBuddy is now a managed app with multiple simultaneously active providers (#8757). Custom models are written to its models.json, while MCP, Skills, prompts, sessions, and usage data can be synchronized. Only OpenAI Chat Completions is supported for custom models, and duplicate model IDs are rejected.
  • WorkBuddy account switching — The authorization center displays account plans, remaining credits, and expiration dates. Fully quit WorkBuddy—including its tray—before switching, or it may overwrite the new login; quota data is refreshed only while WorkBuddy is running and signed in.
  • Recovery for broken Azure-backed sessions — When an OpenAI Responses relay routes conversation history to a different Azure resource, CC Switch now removes incompatible reasoning records and retries once (#9424). This can recover sessions stuck on repeated 400s, including after a mid-conversation provider change.
  • Better Gemini Native routing and caching — Tool results split across messages are now combined, avoiding parallel-tool-call 400 errors (#9453). Per-turn token notices stay in place instead of being moved to the start of history, preserving cache prefixes and improving long-conversation cache hits (#9450).
  • Privacy filtering covers late-added content — Filtering now runs immediately before every upstream request, including failover retries and CC Switch-generated summaries (#9460). Tool descriptions remain unfiltered, so sensitive information embedded there is not covered.
  • Database upgrade prevents downgrade — The schema moves from version 25 to 26 for WorkBuddy MCP/Skills toggles. Backups are automatic, but older versions cannot open the upgraded database; keep the backup if rollback may be needed.

CC Switch v4.0.31

本版本新增受管应用腾讯 WorkBuddy：自定义模型写进 WorkBuddy 自己的模型配置，在 WorkBuddy 里直接就能选；还能在多个 WorkBuddy 账号之间切换，切换前先看到每个号的套餐、剩余积分和到期时间。界面新增德语，README 也有了全部八种界面语言的版本。

另外修复了 Claude Code 经路由连 OpenAI Responses 格式的中转时，会话被同一个中转分到不同 Azure 资源后每一轮都报 400、再也继续不了；经路由连 Gemini Native 格式上游时，并行工具调用报 400、缓存命中率很低；macOS 托盘悬停提示一直挂在屏幕上；Codex 续接的旧对话用量从不导入等问题。

新增

WorkBuddy

腾讯 WorkBuddy 成为新的受管应用（#8757，需求见 #4802、#5802、#7419、#7076）。和 OpenCode 一样是多个供应商同时生效：

  • 自定义模型：点「添加」后，供应商的模型写进 WorkBuddy 自己的 models.json，在 WorkBuddy 的模型选择里显示为「名称:模型 ID」，名称留空时用「厂商标签」。WorkBuddy 里自己添加的模型原样保留。WorkBuddy 的自定义模型只支持 OpenAI Chat Completions 格式。
    • 预设里的模型在 WorkBuddy 的模型选择里可以选思考强度（例如 Kimi K3.1 Pro 的 low / high / max）。
    • WorkBuddy 暂时不支持同一个模型 ID 出现两次。选预设时会跳过已被别的卡片用掉的模型并说明是哪张卡；手动填了重复的模型 ID 会标出来，不能保存。
  • 官方账号：在 WorkBuddy 里登录过的账号会自动收录到「授权中心」，显示昵称、套餐、剩余积分和积分到期时间（三天内到期标橙）。切换账号有两个入口：添加绑定了这个账号的「WorkBuddy 官方登录」卡片，或者在授权中心这个账号的菜单里点「切换 WorkBuddy 到这个账号」。
    • 切换前要先完全退出 WorkBuddy（包括菜单栏 / 托盘），否则它会把当前登录写回去。
    • 「登录另一个账号」只在本机让 WorkBuddy 停在登录页，不会在服务端登出当前账号，已收录的账号仍然可以切回去。
    • 套餐和积分要在 WorkBuddy 正在运行、并且登录着这个账号时才能查到，查到后会缓存显示。
  • MCP、Skills、提示词：同步到 WorkBuddy 的 mcp.json、Skills 目录和全局提示词 CODEBUDDY.md。WorkBuddy 连接器管理的 MCP 条目不会被改动。
  • 会话管理和用量统计：列出 WorkBuddy 会话，从会话日志导入用量。会话不能在终端里恢复。

德语界面，README 八种语言

  • 德语：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。隐私过滤器的占位符在德语界面下和韩语、俄语一样暂用英文。
  • README 新增繁体中文、韩语、土耳其语和俄语版本，和界面的八种语言一一对应。

其他

  • Skills 页面右上角的「⋯」菜单里直接有「立即重新同步」（#9417）：不用再进「存储与同步」里找。
  • 会话管理「按项目」分组时，Codex 桌面版不属于任何项目的对话归到一组「Codex 聊天」（#9415）：不再每个对话各占一组。
  • 请求日志的状态码筛选新增 403、404、502、503、504、520、529（#9425）。

变更

  • 隐私过滤器改在请求发出前的最后一步过滤（#9460）：以前在请求刚进入路由时过滤，故障转移重试、CC Switch 自己生成的压缩摘要等后来加进请求的内容不会被处理。现在每一次发往上游前都会过滤，覆盖更全；工具的说明文字不处理。检测也更快，结果和以前一致。
  • Codex 用量导入更快（#9400）：读取 Codex 会话日志时少做重复的解析和内存分配。

修复

  • Claude Code / Claude Desktop 经路由连 OpenAI Responses 格式的中转时，偶尔报 400「The requested item was created under a different Azure OpenAI resource」，之后同一会话每一轮都报错（#9424）。中转把同一个会话分到了不同的 Azure OpenAI 资源，会话历史里带着另一个资源生成的思考记录；会话中途换供应商也会报类似的 invalid_encrypted_content。现在上游这样拒绝时，会去掉这些思考记录后自动重试一次，会话可以继续。正常的请求不受影响。
  • Claude Code 经路由连 Gemini Native 格式上游时，并行工具调用后报 400「number of function response parts」（#9453）：分散在几条消息里的工具结果现在会合并到一起再发出。
  • Claude Code 经路由连 Gemini Native 格式上游时，长会话缓存命中率只有两成左右（#9450）：Claude Code 每一轮都会追加一条剩余 Token 提示，以前被挪到整段历史的最前面，导致每一轮的开头都不一样。现在留在原来的位置，前面的历史每一轮保持不变，可以命中缓存。
  • Claude Code 经路由连 Gemini Native 格式上游时，流式请求记录的用量偏少，缓存读取常常记成 0（#9464）。
  • macOS 上托盘图标的「CC Switch」悬停提示一直挂在屏幕上，只能退出应用（#9445、#9329、#9446）：macOS 上不再显示这个提示，出问题时图标上的圆点和快捷面板照常提醒。
  • macOS 上其他应用全屏时，点菜单栏图标弹不出快捷面板（#9331）。
  • Claude Code 路由模式下，供应商里设置的 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 写不进 settings.json（#9451、#9455）：现在和供应商的其他专属设置一样随供应商写入，你自己在全局设置的值也不会被切换清掉。
  • Codex 续接已结束的旧对话后，新产生的用量一直没有导入（#9420）。
  • Codex 直连第三方供应商时，关掉「非接管切换时保留官方登录」不会立即生效，要切回官方卡再切回来（#9367）：现在改完设置就会重写当前供应商的配置。
  • Codex 第三方供应商里与官方同名的 GPT 模型，模型选择里显示的不是你设置的显示名（#9380）。
  • macOS 上卸载 Claude Desktop 后，「应用」页仍把它列为已安装（#9383）：现在只认 Claude.app，残留的数据目录不再算。
  • Linux KDE Wayland 上复制按钮提示成功，但剪贴板是空的或还是旧内容（#9384）。
  • Copilot CLI 官方卡的账号下拉里，不绑定账号的选项写着「使用默认账号」，实际用的是 Copilot CLI 自己的 GitHub 登录（#9408）：现在写成「跟随 Copilot CLI 自己的登录」。
  • DeepSeek Harness 手动添加的模型没法设置兼容选项（#9330）：现在也显示兼容性编辑器，可以为百炼兼容模式这类不接受 developer 角色的接口关掉这个角色。
  • 启用 Skill 时提示符号链接创建失败，看不出具体原因（#9439）：报错里现在带上系统给出的错误码（例如 Windows 的 os error 5），方便判断是权限问题还是别的原因。
  • 侧栏底部的「应用」和「设置」，德语、土耳其语、俄语界面下文字被截断。

升级说明

数据库版本从 25 升到 26，为 MCP 和 Skills 增加 WorkBuddy 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
