cc-switch v4.0.35

パッチ 公開日2026年11月18日 出典farion1231/cc-switch English original

#cc-スイッチ v4.0.35 #CCスイッチv4.0.35 このバージョンでは、Claude Code / Claude Desktop で ChatGPT アカウントを使用する Codex カードで GPT-6.2 を使用できるようになります。 Codex /goal の 完全なターゲット はセッション管理で確認でき、リクエスト詳細内のリクエスト ID は ワンクリックでコピーできます。 さらに、クロード コードの自動モードは、思考をオフにできないモデルでは完全にブロックされます。 Codex 集約モードと「Open Terminal」は、Responses-Lite に reasoning.context が必要であることを報告します。 Codex がコンテキストを圧縮した後の最初のリクエストは拒否されます。カスタム日付が非常に早い年に選択されている場合、使用状況ページがスタックします。また、スキルのマネージド コピーが存在しない場合はアンインストールできません。 English → | 日本語版 →

追加

セッション管理で Codex /goal の完全なターゲットを表示します

ターゲットが 700 バイトを超えると、Codex によって挿入されたコンテキストにターゲットのコンテンツが書き込まれず、ターゲットはセッション管理で表示されなくなります (#9647 を参照)。ここで、完全な目標がセッション記録から読み取られ、ワンステップの「目標・ステータス」として表示されます。これは展開されて完全な内容が表示されます。目標とステータスが変更されていない重複レコードは表示されなくなりました。

リクエストの詳細で完全なリクエスト ID をコピーできます。

リクエスト詳細内の値が長すぎる場合は、省略記号で切り捨てられます。 Codex の resp_... などの長いリクエスト ID は、ログ照合のために完全にコピーできません (#9681 を参照)。リクエスト ID の後にコピー ボタンが表示されます。

GPT-6.2 Sol / Astra の価格を追加しました

価格は公式標準ファイル (272K 以内) に従って計算されます。長いコンテキスト ファイル、Batch / Fast およびその他のファイルは GPT-6 として区別されません。

修正

  • Claude Code / Claude Desktop で ChatGPT アカウントを使用する Codex カードは GPT-6.2 を取得できず、手動で入力した後でも「ChatGPT アカウントで Codex を使用する場合はサポートされていません」と報告されます (#9678、#9670 を参照): OpenAI は Codex クライアントのバージョン、CC スイッチに応じてどのモデルを提供するかを決定します。報告されたバージョンは古すぎます。次に、Codex 0.169.0 に従ってリクエストします。モデル ID はハードコードされていません。
  • Claude Code の自動モードは、思考をオフにすることができないモデル上の Bash、MCP、およびその他のツール呼び出しではすべて拒否されます (#8887、#9671 を参照): 自動モードでの判断リクエストには思考をオフにする必要があります。 MiniMax-M3.1-Flash などのモデルは 400 を直接報告し、Claude Code は判定サービスが利用できないとみなします。これで、ルーティング (Claude Code と Claude Desktop) を通過するときに、Anthropic 形式の上流側はこのようなエラーを報告し、思考を閉じるフィールドを削除して、同じ会社で再試行します。元々上流で受け付けたリクエストはキャッシュに影響を与えずにそのまま送信されます。
  • Codex は、アグリゲーション モードで「Responses-Lite は reasoning.context が all_turns である必要がある」と報告しており、同じ会社の直接接続とルーティングは正常です (#9665 を参照): カードがモデル ディレクトリに書き込まない場合、アグリゲーション モードは直接接続と同じ GPT-6 公式設定を使用します。カードから「ターミナルを開く」ときに発生する同じエラーも修正されました。
  • Codex がルーティングを通じてチャット形式に変換される場合、コンテキスト圧縮後の最初のリクエストは、「メッセージの内容を空にすることはできない」として厳しい要件によりゲートウェイによって拒否されます (#9660 を参照): 画像のみを含むユーザー メッセージは、圧縮中に空のメッセージになります。チャット形式に変換すると、内容が空のユーザー メッセージが削除され、他のメッセージは変更されません。
  • 使用状況ページのカスタム日付の開始点が 1905 年などの非常に早い年に選択されると、クライアントがフリーズします (#9691 を参照): 最初の使用記録から今日までの日付のみを選択できるようになりました。範囲外の日付は選択できません。手動で入力した日付は範囲内に戻されます。
  • スキルのマネージド コピーが利用できなくなった場合はアンインストールできません (#9669、#9668 を参照)。

cc-switch v4.0.35

Highlights

  • GPT-6.2 on ChatGPT-backed Codex cards — Claude Code and Claude Desktop now report Codex client version 0.169.0 instead of pinning model IDs, fixing the “not supported” rejection and letting OpenAI’s negotiation determine availability (#9678). Pricing covers only the standard ≤272K tier; long-context, Batch, and Fast tiers are not yet differentiated.
  • Auto mode tolerates mandatory reasoning — When an Anthropic-format upstream rejects the request to disable thinking—such as MiniMax-M3.1-Flash—the router removes that field and retries once with the same provider. Accepted requests remain untouched, preserving cache behavior, while Bash/MCP tool calls no longer fail across the session.
  • Codex routing handles aggregation and compaction — Cards without a model catalog now use the official GPT-6 settings employed by direct connections, satisfying Responses-Lite’s reasoning.context = all_turns requirement in aggregation and “Open Terminal” flows (#9665). Chat-format conversion also removes empty user messages produced by image-only compaction, preventing the first post-compaction request from being rejected (#9660).
  • Session and request diagnostics are no longer truncated — Full /goal text is recovered from session records even when Codex omits goals over 700 bytes from injected context; unchanged goal/status duplicates are collapsed. Long request IDs such as resp_... now have a copy button for reliable log correlation (#9647, #9681).
  • Guardrails for stale state — Missing managed Skill copies no longer block uninstall (#9669), while custom usage dates are limited to the range from the first recorded usage through today. Out-of-range manual input is clamped, eliminating the freeze caused by extremely early years (#9691).
  • Breaking changes — None.

CC Switch v4.0.35

本版本让 Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片能用上 GPT-6.2，会话管理里可以看到 Codex /goal 的完整目标，请求详情里的请求 ID 可以一键复制。

另外修复了 Claude Code 的 auto 模式在关不掉思考的模型上被整体拦下；Codex 聚合模式和「打开终端」报 Responses-Lite 需要 reasoning.context；Codex 压缩上下文后第一条请求被拒；用量页自定义日期选到很早的年份时卡死；Skill 的托管副本不在了就卸载不掉等问题。

新增

会话管理里显示 Codex /goal 的完整目标

目标超过 700 字节时，Codex 注入的上下文里不写目标内容，会话管理里也就看不到目标（见 #9647）。现在从会话记录里读出完整目标，显示成一步「目标 · 状态」，展开即是完整内容；目标和状态都没变的重复记录不再显示。

请求详情里可以复制完整的请求 ID

请求详情里过长的值会被省略号截断，像 Codex 的 resp_... 这类长请求 ID 没法完整复制去对日志（见 #9681）。现在请求 ID 后面多了一个复制按钮。

新增 GPT-6.2 Sol / Astra 的价格

按官方标准档（272K 以内）的价格计费；长上下文档、Batch / Fast 等档位和 GPT-6 一样暂不区分。

修复

  • Claude Code / Claude Desktop 里用 ChatGPT 账号的 Codex 卡片获取不到 GPT-6.2，手动填了也报「not supported when using Codex with a ChatGPT account」（#9678，见 #9670）：OpenAI 按 Codex 客户端版本决定给哪些模型，CC Switch 报的版本太旧。现在按 Codex 0.169.0 请求，没有写死任何模型 ID。
  • Claude Code 的 auto 模式在关不掉思考的模型上，Bash、MCP 等工具调用全部被拒（见 #8887、#9671）：auto 模式的判断请求要求关闭思考，MiniMax-M3.1-Flash 这类模型直接报 400，Claude Code 就认为判断服务不可用。现在经路由时（Claude Code 和 Claude Desktop），Anthropic 格式的上游这样报错会去掉关闭思考的字段，在同一家重试一次。上游本来接受的请求原样发送，不影响缓存。
  • Codex 聚合模式下报「Responses-Lite requires reasoning.context to be all_turns」，同一家直连和路由都正常（见 #9665）：卡片没写模型目录时，聚合模式改用和直连一样的 GPT-6 官方设置。从卡片「打开终端」时出现的同一个报错也一并修好。
  • Codex 经路由转成 Chat 格式时，压缩上下文后第一条请求被要求严格的网关以「message content cannot be empty」拒绝（见 #9660）：压缩时只含图片的用户消息会变成空消息，现在转成 Chat 格式时去掉内容为空的用户消息，其他消息不变。
  • 用量页自定义日期的起点选到 1905 年这类很早的年份时，客户端卡死（见 #9691）：现在只能选从第一条用量记录到今天之间的日期，范围外的日期不可选，手动输入的也会被拉回范围内。
  • Skill 的托管副本已经不在时卸载不掉（#9669，见 #9668）。

致谢

感谢 @imfuxiao（Codex 卡片支持 GPT-6.2）、@Maharramoff（卸载托管副本已不在的 Skill）、@SaladDay（拆分本地路由的转发代码、数据库访问改用应用类型）的贡献。

特别感谢以下贡献者：你们的 PR 发现并修复了真实的问题，只是同样的问题后来在主线上另行修好，PR 因此关闭。@xunapro（#4262，同类 PR 里最早提出 S3 服务商选择没被记住、阿里云 OSS / 腾讯云 COS 因路径式地址报 403）、@mercutiojohn（#8547，找准了 Gemini CLI 供应商获取模型列表失败的三个原因）。

感谢 @chencyan364、@DemosHume、@LAN-SHH、@mouse8867、@leafsnow、@zhuqiang1248、@ramonmi、@zx2121651、@VICCC-0x90 提出需求、报告问题和提供复现信息。
