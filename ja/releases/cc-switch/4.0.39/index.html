cc-スイッチ v4.0.39

#CCスイッチv4.0.39 このバージョンは主に修理用です。 API キー入力ボックスにコピー ボタンが追加されました。 バックアップには合計サイズの上限を設定でき、それを超えると古いものから削除されます。 Claude Code が Codex OAuth 経由で GPT-6.2 Sol / Astra を使用すると、システムによって要求されるキャッシュ ヒット率が大幅に向上します。 さらに、Claude Code と Claude Desktop のネイティブ プロバイダーが修正され、フェールオーバーまでに最大 600 秒待機する必要がありました。ストリーミング応答が長いと、使用量とログ収集によって占有されるメモリが増加し続けます。ワンクリックでインポートリンクマージ設定が失敗した後も、確認ボックスがポップアップ表示されます。 Codex デスクトップ バージョンのみがインストールされている場合、プラグイン ページには「Codex がインストールされていません」と表示されます。プラグイン ページは、アンインストールされたアプリケーション用に空の構成フォルダーを作成します。 OpenCode Go の DeepSeek V4.1 Flash が見つからない max ギアについて考える。ポップアップ レイヤーやドロップダウン メニューを素早くクリックするとちらつくなどの問題。 English → | 日本語版 →

追加

API キー入力ボックスをワンクリックでコピーできます

サプライヤー フォームの API キー入力ボックスの横にコピー ボタン (#9232) があります。コピーされるのは、先頭と末尾のスペースが削除されたキーです。成功か失敗かを尋ねるメッセージが表示されます。入力ボックスが空の場合、または編集できない場合は表示されません。

最大合計バックアップ サイズ

新しい「最大合計バックアップ サイズ」がバックアップ設定に追加されました (#9011、#6706 に関連)。デフォルトは「制限なし」で、アップグレード後にバックアップは削除されません。 ・ 上限値を設定後、バックアップフォルダーがこのサイズを超えると、古いバックアップから順に削除されます。 ・ 最新のバックアップとリカバリに使用したバックアップは常に保持されるため、単一のバックアップが上限を超えた場合でもフォルダが上限を超える可能性があります。

  • 上限は、次回のバックアップまたは毎日のメンテナンス時に有効になります。毎日のメンテナンスでは、バックアップのクラッシュによって残された 24 時間以上経過した一時ファイルもクリーンアップされます。

変更

  • Codex OAuth 経由で GPT-6.2 Sol / Astra を使用すると、クロード コードのキャッシュ ヒット率が高くなります (#9848、#9847 を参照): システム プロンプトが最初の開発者メッセージに配置されるように変更され、ChatGPT バックエンドはそれを会話と一緒にキャッシュします。 2ラウンド以降の実大当り率は約98％。他のモデルと API キーのルーティングは変更されません。
  • プライバシー フィルターの高速化 (#9826): フィルター結果は変更されません。

修正

  • Claude Code と Claude Desktop のネイティブ プロバイダーがスタックして単語を印刷できない場合、フェイルオーバーに最大 600 秒かかります (#9754): このタイプのストリーミング リクエストは非ストリーミング リクエストのタイムアウトを使用し、他のストリーミング リクエストと同様に最初のワード タイムアウト (デフォルトは 60 秒) を使用するようになりました。
  • 長いまたは終わりのないストリーミング応答により、ログ収集の使用量とメモリ使用量が増加し続けます (#9846、#9843 を参照): バッファーは最大 64 MiB になり、非常に大きなイベントが発生した後でも後続のコンテンツを解析し続けることができます。
  • ワンクリック インポート リンクのマージ構成が失敗した後も、確認ボックスがポップアップ表示されます (#9844、#9841 を参照): エラーのみが表示され、確認ボックスは表示されなくなりました。
  • デスクトップ バージョンの Codex のみがインストールされている場合、プラグイン ページに「Codex がインストールされていません」と表示されます (#9850 を参照): たとえば、Windows にはデスクトップ バージョンの Codex (MSIX) のみがインストールされます。個別にインストールされた codex が見つからない場合、プラグイン ページや Codex コマンド ラインを使用するその他の場所では、代わりにデスクトップ バージョンに付属するものが使用されるようになりました。 「アプリケーション」ページのインストール、アップグレード、アンインストールは、引き続き個別にインストールされた Codex CLI にのみ適用されます。
  • プラグイン ページは、アンインストールされたアプリケーション用に空の構成フォルダーを作成します (#9852 を参照): プラグイン ページを開くと、Codex、Grok Build、OpenClaw、Pi、MiniMax Code などのインストールされていないアプリケーション用に ~/.codex や ~/.grok などの空のフォルダーも作成されます。次に、コマンド ライン ツールを見つけてビルドします。インストールされていない場合は、「インストールされていません」と表示されます。
  • OpenCode Go の DeepSeek V4.1 Flash には max 思考装置がありません (#9853 を参照): デフォルトでは、OpenCode Go のモデル リストには low、high、および max と記載されています。 OpenCode はユニバーサル low / medium / high には戻りません。
  • 素早くクリックすると、ポップアップ レイヤとドロップダウン メニューが点滅します (#9176、#9175 を参照): アニメーションの開閉中にもう一度クリックしても、連続して 2 回切り替わることはありません。

cc-switch v4.0.39

Highlights

  • Claude Code 流式可靠性 — 原生供应商卡住时的故障转移从最长 600 秒降至默认 60 秒的首字超时；长流式响应的用量/日志缓冲限制为 64 MiB，降低内存持续增长的风险。依赖长请求或故障转移的用户值得升级。
  • Codex OAuth 缓存优化 — 仅针对 Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 的路径，系统提示改放入首条 developer 消息，官方实测第二轮起缓存命中率约 98%；其他模型和 API Key 路由不受影响。使用该组合的用户优先升级。
  • 备份大小上限 — 新增可选的「备份总大小上限」，超限时从最旧备份开始删除，但最新备份和正在用于恢复的备份始终保留。默认「不限制」，升级不会自动删除备份；需要控制磁盘占用的用户可配置此选项，但单份备份超过上限时仍可能超限。
  • 插件与模型预设修复 — 仅安装 Codex 桌面版（MSIX）时会回退使用其内置 CLI，打开插件页也不再为未安装应用创建空配置目录；OpenCode Go 的 DeepSeek V4.1 Flash 补齐 low / high / max 思考档位。相关用户值得升级。
  • 小修复与升级建议 — API Key 复制按钮会去除首尾空格并提示复制结果；导入失败不再误弹确认框，快速点击不再导致弹层和菜单闪烁；隐私过滤器提速但结果不变。未发现破坏性变更或必需迁移步骤；未使用相关功能的用户可跳过本次升级。

CC Switch v4.0.39

本版本以修复为主。API Key 输入框加了复制按钮；备份可以设置总大小上限，超过时从最旧的开始删；Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时，系统提示的缓存命中率大幅提高。

另外修复了 Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，要等最长 600 秒才故障转移；很长的流式响应让用量和日志收集占用的内存一直增长；一键导入链接合并配置失败后仍弹出确认框；只装了 Codex 桌面版时，插件页显示「未安装 Codex」；插件页给没装的应用建了空配置文件夹；OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位；快速点击时弹出层和下拉菜单闪烁等问题。

新增

API Key 输入框可以一键复制

供应商表单的 API Key 输入框旁边多了复制按钮（#9232），复制的是去掉首尾空格后的 Key，成功或失败都会提示。输入框为空或不可编辑时不显示。

备份总大小上限

备份设置里新增「备份总大小上限」（#9011，相关 #6706），默认「不限制」，升级后不会删任何备份。

  • 设置上限后，备份文件夹超过这个大小时，会从最旧的备份开始删除。
  • 最新的一份备份和恢复正在使用的备份始终保留，所以单份备份比上限还大时，文件夹仍可能超过上限。
  • 上限在下次备份或每日维护时生效。每日维护还会清理备份中途崩溃留下、超过 24 小时的临时文件。

变更

  • Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时缓存命中率更高（#9848，见 #9847）：系统提示改放在第一条 developer 消息里，ChatGPT 后端会把它和对话一起缓存。实测从第二轮起命中率约 98%。其他模型和用 API Key 的路由不变。
  • 隐私过滤器更快（#9826）：过滤结果不变。

修复

  • Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，最长要等 600 秒才故障转移（#9754）：这类流式请求用的是非流式请求的超时，现在和其他流式请求一样用首字超时（默认 60 秒）。
  • 很长或一直不结束的流式响应，让用量和日志收集占用的内存一直增长（#9846，见 #9843）：缓冲现在最多 64 MiB，遇到超大的事件后也能继续解析后面的内容。
  • 一键导入链接合并配置失败后，仍弹出确认框（#9844，见 #9841）：现在只提示错误，不再弹确认框。
  • 只装了 Codex 桌面版时，插件页显示「未安装 Codex」（见 #9850）：比如 Windows 上只装了 Codex 桌面版（MSIX）。现在找不到单独安装的 codex 时，插件页等用到 Codex 命令行的地方会改用桌面版自带的那份。「应用」页的安装、升级和卸载仍只管单独安装的 Codex CLI。
  • 插件页给没装的应用建了空配置文件夹（见 #9852）：打开插件页时，没装 Codex、Grok Build、OpenClaw、Pi 或 MiniMax Code 也会建出 ~/.codex、~/.grok 等空文件夹。现在找到命令行工具后才建，没装的照常显示「未安装」。
  • OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位（见 #9853）：预设现在按 OpenCode Go 的模型列表写明 low、high、max 三档，OpenCode 不再退回通用的 low / medium / high。
  • 快速点击时，弹出层和下拉菜单闪烁（#9176，见 #9175）：在打开或关闭的动画过程中再点一下，不会再连着切换两次。
