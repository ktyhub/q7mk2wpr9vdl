CC スイッチ v4.0.22

このバージョンでは、CC Switch によって管理される 14 番目のアプリケーションである DeepSeek Harness のサポートが追加されています。サプライヤーは Web とデスクトップの構成を一緒に記述し、MCP、スキル、およびプロンプト ワードがそれに同期され、セッションを参照でき、「アプリケーション」ページのインストール、アップグレード、およびアンインストールが可能です。認証センターで DeepSeek アカウントにログインし、残高や使用状況の統計を確認することもできます。 Oh My Pi の使用量もカウントされるようになりました。 「ターミナルを開く」にチェックを入れると、権限の確認をスキップし、起動パラメータを追加できます。また、Codex カードでターミナルを開くこともできます。 WebDAV 構成はクリアできます。スキルは、ディレクトリを開いて検出ページのドキュメントを表示できます。 GitHub Copilot のクロード モデルはネイティブ インターフェイスに変更されており、キャッシュ ヒット率が大幅に向上していることがわかります。さらに、OAuth リモート MCP が macOS に接続されているときにクロード アカウントの切り替えが失敗する問題、グローバル プロキシが有効になっているときにクロード アカウントを追加するときに 403 が報告される問題、新しいクロード デスクトップ セッションにデフォルトで Fable が使用される問題、MiniMax の週次割り当てが使い果たされた後表示されない問題、未使用のサプライヤー残高が自動的に更新されない問題、リクエストがルート自体にリダイレクトされてメモリが急増する問題、Gemini ツールの呼び出しが 400 と報告される問題、xAI が Codex を拒否する問題が修正されました。 0.163 エラー レポートのページ全体をリクエスト ログに保存したり、データベースを拡張したりするなどの問題があります。 4.0 の完全なアップデート内容については、v4.0 リリース ノート を参照してください。 English → | 日本語版 →

＃＃ 追加

ディープシーク ハーネス

DeepSeek ハーネス (コマンド dsh) は、独自のプロバイダー、MCP、スキル、プロンプト、セッション (#8795、#8986) を備えたスタンドアロン アプリケーションになりました。 ~/.dshで設定します。 DSH_HOME が設定されている場合は、それが優先されます。

  • **Web とデスクトップは一緒に管理されます。 ** DeepSeek Harness の Web バージョンとデスクトップ バージョンには、それぞれ 1 つの構成 (プロファイル) があります。 CC スイッチは、サプライヤーと MCP を 2 つのプロファイルに同時に書き込みます。不足しているプロファイルは自動的に構築されます。初期化された headless と acp も一緒に書き込まれます。サイドバーには DeepSeek ハーネスが 1 つだけあり、「追加」タイトルの横に、Web とデスクトップがこのリストを共有していることが示されています。あるコピーが別のコピーとは異なるように手動で変更されると、エディターは拒否されてプロンプトが表示され、変更は上書きされません。
  • **サプライヤーは同時に追加できます。 ** OpenCodeと同様に「追加」「削除」により、複数のサプライヤーが同時に書き込み、DeepSeek Harnessでモデルを選択することができます。 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages の 3 つのインターフェイスをサポートしており、Pi ディレクトリからプリセットされています。 API キーは DeepSeek Harness 独自の認証情報ファイル .credentials.yaml に書き込まれ、参照のみが構成に配置されます。構成内の他のプラグイン設定はそのまま保持され、書き込みに失敗した場合はロールバックされます。
  • **モデル編集。 ** 思考と画像の入力スイッチ、コンテキストの長さ、最大出力は、Pi と Kim Code のモデル行と同様に、個別に入力されます。 DeepSeek Harnessは、モデルごとにオプションのシンキングギアやインターフェイス互換性オプションを設定することもできます。 OpenCodeとMiniMax Codeのモデル編集もこんな感じに変更されました。
  • **DeepSeek アカウントのログイン。 ** ブラウザを使用して、認証センターの DeepSeek Harness グループの DeepSeek アカウントにログインすると、残高とボーナスが表示されます。 Web とデスクトップはこのログインを共有し、どちらかの場所でのログインまたはログアウトは両方の側で有効になります。サプライヤーを追加する場合、「DeepSeek 公式ログイン」を選択すると認証センターにジャンプします。ログイン後、公式カードが追加されたアカウントが一番前に表示されます。アカウントのモデルは、DeepSeek Harness 自体によって提供されます。このカードは編集できず、ログアウトすると自動的に消えます。
  • **MCP、スキル、プロンプトワード。 ** 標準入出力とストリーミング可能な HTTP MCP をサポートします。
  • **セッションと使用法。 ** DeepSeek Harness セッション (思考プロセスやツール呼び出しを含む) を閲覧できます。 DeepSeek Harness でセッションを復元および削除してください。使用状況はセッション レコードからインポートされ、DeepSeek アカウントを使用したリクエストは使用状況ページに「DeepSeek アカウント (OAuth)」として個別に表示されます。
  • **「アプリケーション」ページでは、DeepSeek Harness を管理します。 ** @deepseek-ai/dsh のインストール、アップグレード、アンインストールには npm を使用します。アンインストールしてもデータは削除されません。
  • DeepSeek ハーネスはローカル ルーティングを経由しません。

Oh My Pi の使用統計

使用状況ページでは Oh My Pi の使用量がカウントされ、独自のアプリケーション カテゴリ (#9046、#8939) が追加されました。サブエージェントの使用状況、会話以外のモデル呼び出しもカウントされ、最初のインポートには以前のサブエージェント セッションが含まれます。 Oh My Pi と Pi が同じセッション ディレクトリを使用する場合、それぞれは独自のセッションのみをインポートします。 Pi によって既にインポートされたデータを再インポートする必要はありません。

「ターミナルを開く」では、権限の確認をスキップし、起動パラメータを追加できます。

[ターミナルを開く] ダイアログ ボックスにはさらに 2 つの項目があります (#9008)。

  • **許可の確認をスキップします。 ** 確認後、クロードコードと反重力は--dangerously-skip-permissionsで起動し、コーデックスは--dangerously-bypass-approvals-and-sandboxで起動します。デフォルトではチェックされていません。
  • **追加パラメータ (オプション)。 ** --debug や --append-system-prompt "Be concise" などのパラメータを入力し、その後に起動コマンドを入力します。スペースで区切って、スペースを含む値を引用符で囲みます (最大 16 個の値)。パラメータはパラメータとしてプログラムにのみ渡され、コマンドとして実行されることはありません。 どちらの項目も今回開いた端末にのみ使用され、設定は書き込まれません。ターミナルが正常に開かれると、CC Switch は適用することで選択を記憶します。

Codex カードは「ターミナルを開く」こともできます

以前は、このボタンは Codex カードでは使用できませんでした。現在、サードパーティのカードによって開かれた端末はこのカードのみを使用します。codex -c ... で始まり、config.toml は変更しないでください。キーは環境変数を通じて渡され、コマンド ラインには表示されません。 config.tomlで現在のサプライヤーが残した設定を、可能な限り本カードに影響を与えない値に変更します。変更できないもの (リクエスト ヘッダーや指定されたプロファイルなど) は、現在のサプライヤーのキーが他の場所に送信されないように、最初にこのカードに切り替えてからカードを開くように求められます。現在使用しているカードは codex を直接起動します。

WebDAV 構成をクリアする

以前に WebDAV 同期を構成した後は、自動同期をオフにすることしかできず、アドレス、アカウント、パスワードは常にローカル マシンに残されました (#8977)。 WebDAV 同期設定に [設定をクリア] ボタンが追加されました。確認後、情報はローカル マシンから削除され、自動同期は停止します。クラウドにアップロードされたデータは削除されません。

スキル: ディレクトリを開く、名前をコピーする、ドキュメントを表示する

  • インストールされているスキル (#8993): ⋯ メニューで「ディレクトリを開く」を選択し、ファイル マネージャーでこのスキルのフォルダを開くことができます。スキル名をクリックして名前をコピーします。元の「コピー ディレクトリ名」は削除されました。
  • ディスカバリー ページ (#9039): 各行には「ドキュメントを開く」ボタンがあります。インストール前に説明を読むことができます。書類がない場合は、倉庫のホームページを開いてください。

改善点

GitHub 副操縦士のクロード モデルは、キャッシュ ヒット率の大幅な向上を示唆しています (#8908)。以前は、Copilot の Claude モデルはすべて Chat Completions 形式に変換されて送信されていたため、キャッシュ タグが失われていました。会話の途中でクロード コードによって挿入されたシステム メッセージもキャッシュに割り込みます。 Copilot は、ネイティブ インターフェイスを直接使用するネイティブ Anthropic インターフェイス モデルをサポートするようになりました。 Copilot Enterprise Edition の長いセッションのキャッシュ ヒット率は、約 35% ～約 95% と測定されています。 スキル リポジトリを追加、有効化、非アクティブ化、または削除する場合、このリポジトリのみが再読み取りされます (#8907、#1426)。すべてのリポジトリは再ダウンロードされなくなります。 [更新] ボタンをクリックしても、すべてが再度読み取られます。 **トレイと使用設定のアカウントに関連付けられているクロード公式カードの限度額も確認できます。 ** 以前は、トレイではなくカード上にのみ表示され、使用設定ポップアップ ウィンドウは有効になっていない状態で表示されたままでした。 Claude Desktop のルーティング サービスは、x-api-key トークン (#5123) も受け入れ、トークンの検証は時間のかかる固定比較 (#7488、#7482) に変更されます。 クロード構成ディレクトリが WSL にある場合、認証センターはクロード アカウントが現在サポートされていないことを直接示します。また、「アカウントの追加」と「再ログイン」は使用できません。以前は、代わりに「ターミナルを開く」を使用するように求められましたが、現在は Windows でクロード コードが開くため、これも使用できません。 MCP リストとスキル リストのチェック ボックスにカーソルを合わせたときに、2 つのプロンプトが同時にポップアップ表示されなくなりました。;疑問符のヘルプ カードが右側に表示され、マウスがブロックされなくなり、長いコンテンツがカード内で折り返されてスクロールされます (#8593)。 他の場所から認証センターの特定のグループにジャンプすると、ページの他の部分はそれに応じて移動しなくなります (#8964)。 OpenCode、OpenClaw、Hermesの設定ファイルが読み込めない場合、サプライヤーページにエラーが表示されます (#9044)。以前は、ページは何も構成されていなかったかのように空でした。サプライヤーの追加に失敗し、冗長なレコードが残った後にのみエラーが表示されました。 **管理対象の ChatGPT および xAI アカウントのログイン期限が切れると、プロンプトが「認証センターでこのアカウントに再度ログインしてください。」に変わります。 ** 以前は、存在しないコマンドを実行するように求められました。 デフォルト: OspreyAI および iFlytek Astron コーディング プランにクロード コードのデフォルト (#9036) を追加しました。 TokenFlux は、新しいドメイン名 tokenflux.com および tokenflux.dev をバックアップ アドレスとして使用します。

修正

  • macOS で OAuth ログインを必要とするリモート MCP に接続する場合、クロード アカウントを切り替えると、「クロード コードのログイン情報が大きすぎるため、キーチェーンに書き込むことができません。また、切り替えがありません」というメッセージが表示されます (#9002)。 MCP のログイン情報とアカウントが同じキーチェーン エントリ内に存在するため、1 回の書き込みの最大長を超えています。これで、超長いコードがクロード コードと同じ方法で記述されました。
  • グローバル プロキシがオンになっている場合、認証センターにクロード アカウントを追加すると、ログインに成功した後、ブラウザは 403 (#9038) を報告します。トークン交換は Claude Code 自体によって行われ、以前はグローバル プロキシを使用していませんでした。これで、CC スイッチがログインして残高を確認するためにクロード コードを実行すると、グローバル プロキシが渡されます (SOCKS プロキシ クロード コードはサポートしていないため、渡されません)。
  • Claude Desktop の新しいセッションはデフォルトで Fable を使用し、構成が有効になるたびにモデルの順序が変更されます (#7491、#7457、#8973)。 Claude Desktop は、リスト内の最初のモデルを、事前にアルファベット順に記述されたデフォルト モデルとして扱います。次に、インターフェース上に Sonnet、Opus、Fable、Haiku の順に書き込みます。新しいセッションはデフォルトで Sonnet ファイルを使用します。
  • MiniMax の週次割り当てを使い切ると、週次割り当てはカードとトレイに表示されなくなります。 5 時間の割り当てが最初にリセットされるときは、割り当てがいっぱいであるように見えます (#8124、#8123)。赤色の「使用済み」と週ごとのクォータのリセットへのカウントダウンが表示されるようになりました。
  • 使用されていないサプライヤーは自動クエリ間隔を設定しているため、残高は更新されません (#8342、#8335)。
  • アップストリーム アドレスにルート自体のアドレスが入力されると、リクエストは無限にルートにリダイレクトされ、メモリが増大し続けます (#8598)。ここで、構成エラーを直接報告します。
  • Claude Code がルーター経由で Gemini に接続すると、ツールの呼び出し後に 400 メッセージが報告されます。署名が間違って配置され、「Unknown name thoughtSignature」(#6690) が報告されます。 CC スイッチは再起動後または以前のラウンドで署名を失い、Gemini 3 以降はリクエストを拒否します (#6833)。 Vertex のツール結果の後には、「モデル ターンで終わるリクエストはサポートされていません」というテキストが続きます (#8988)。
  • Claude コードがルーティング経由で OpenAI Responses に転送されると、ブロックされたドメイン名を持つ WebSearch は 400 (#8979) を直接報告します。これで、API キーで接続された応答がそのまま上流に渡されます。 ChatGPT 公式ログインのルートはドメイン名のブロックをサポートしていないため、エラーが明確に報告されます。
  • Codex 0.163 の上記ルートは xAI Times 400 (#8997、#8996) に接続されています。
  • Codex の config.toml に [[skills.config]] のような配列テーブルがある場合、サードパーティ サプライヤーのアドレスがこのテーブルに書き込まれます (#9029、#9023)。
  • OpenCode 新しい形式 (V2) ベンダーの「接続性のチェック」では、options.baseURL が欠落していると報告しています (#8969)。
  • アップストリーム エラーが報告されると、リクエスト ログには HTML エラーのページ全体が保存され、データベースとバックアップはますます大きくなります (#9010、#6706)。各レコードの最初の 4096 文字のみが保存されるようになりました。保存されている古いレコードは今回は消去されません。
  • Windows で MyDockFinder などのサードパーティのタスクバーを使用している場合、トレイ アイコンをクリックしても応答がありません (#8729、#8565)。
  • 以前のバージョンの Kimi Code 0.43.0 は、「アプリケーション」ページでアップグレードしても変更されません (#9032)。古いバージョンにはアップグレードを自動的に確認するオプションがなく、代わりにそれをインストールしたパッケージ マネージャーを使用するか、公式のインストール スクリプトを再実行する必要があります。
  • **「アプリケーション」ページでは、プログラムファイルはあるものの実行できないアプリケーションは、「インストール済み」グループに「未インストール」として表示されます。 ** 「実行できません」とその理由が表示されるようになりました。
  • Antigravity の CLI と IDE の両方がインストールされている場合、IDE で継続されている古いセッションの使用状況が更新されず、セッションを開くことができません (#8941)。

アップグレード手順

データベース バージョンが 23 から 24 にアップグレードされ、MCP とスキル用の DeepSeek ハーネス スイッチが追加されました。データベースはアップグレード前に自動的にバックアップされます。アップグレード後に古いバージョンにロールバックすると、古いバージョンではデータベースのバージョンが新しすぎるため開けないというメッセージが表示されます。

  • DeepSeek ハーネスはデフォルトでサイドバーに表示されます。使用しない場合は、「アプリケーション」ページで「サイドバーにDeepSeekハーネスを表示」をオフにすることができます。

cc-switch v4.0.22

Highlights

  • DeepSeek Harness becomes the 14th managed app — CC Switch now manages its providers, MCP, Skills, prompts, sessions, and npm lifecycle (#8795, #8986). Web and Desktop profiles are synchronized, conflicting manual edits are rejected instead of overwritten, and API keys stay in .credentials.yaml. Harness traffic bypasses CC Switch’s local router, so route-based policies will not apply.

  • Copilot’s Claude models now use native Anthropic requests — eliminating the Chat Completions conversion that discarded cache markers and was disrupted by mid-conversation system messages (#8908). Reported enterprise cache-hit rates rose from roughly 35% to 95%, potentially reducing latency and token costs substantially.

  • Codex provider cards can launch isolated terminals — these use codex -c ..., pass keys through environment variables, and leave config.toml untouched. However, existing headers or profile settings can still override the card; CC Switch warns when this happens. The new permission-bypass options for Claude Code, Antigravity, and Codex disable important safety boundaries and apply only to that terminal session (#9008).

  • Several cross-provider routing failures are resolved — self-referencing upstream URLs now fail fast instead of causing an infinite forwarding loop and memory growth (#8598); Gemini tool signatures survive restarts and later turns (#6690, #6833); and Codex array tables no longer receive provider URLs by mistake (#9029).

  • Logs and sync credentials are easier to control — upstream error bodies are capped at 4,096 characters to prevent database and backup bloat, but existing oversized records are not cleaned up (#9010). WebDAV settings can now be fully purged locally without deleting cloud data, while Oh My Pi gains usage accounting, including subagents and non-conversation model calls (#9046).

  • The database migration is one-way — schema version 23 upgrades to 24 for DeepSeek Harness MCP and Skills switches. CC Switch creates a backup automatically, but after upgrading, older releases reject the database as too new; do not downgrade without restoring that backup.

CC Switch v4.0.22

本版本新增对 DeepSeek Harness 的支持，它是 CC Switch 管理的第 14 个应用：供应商一起写进它的 Web 和 Desktop 配置，MCP、Skills、提示词同步给它，会话可以浏览，「应用」页可以安装、升级、卸载；还可以在授权中心登录 DeepSeek 账号、查看余额，用量也会统计。Oh My Pi 的用量现在也会统计。「打开终端」可以勾选跳过权限确认、追加启动参数，Codex 卡片也能打开终端；WebDAV 配置可以清除；Skills 可以打开目录、在发现页查看文档；GitHub Copilot 的 Claude 模型改走原生接口，提示缓存命中率大幅提高。另外修复了 macOS 上连了 OAuth 远程 MCP 时切换 Claude 账号失败、开了全局代理时添加 Claude 账号报 403、Claude Desktop 新会话默认用 Fable、MiniMax 周额度用完后不显示、没在用的供应商余额不自动刷新、请求被转回路由自己导致内存暴涨、Gemini 工具调用报 400、xAI 拒绝 Codex 0.163 的请求、请求日志里存下整页报错把数据库撑大等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

DeepSeek Harness

DeepSeek Harness（命令是 dsh）现在是一个独立的应用，有自己的供应商、MCP、Skills、提示词和会话（#8795、#8986）。配置在 ~/.dsh，设了 DSH_HOME 时以它为准。

  • Web 和 Desktop 一起管理。 DeepSeek Harness 的网页版和桌面版各有一份配置（profile），CC Switch 把供应商和 MCP 同时写进两份，缺的那份会自动建好；已经初始化的 headless、acp 也一起写。侧栏只有一个 DeepSeek Harness，「已添加」标题旁注明 Web 和 Desktop 共用这份列表。某一份被手动改得和另一份不一样时，编辑会被拒绝并提示，不会覆盖你的改动。
  • 供应商可以同时添加。 和 OpenCode 一样是「添加」「移除」，多个供应商同时写进去，在 DeepSeek Harness 里选模型。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种接口，预设来自 Pi 的目录。API Key 写进 DeepSeek Harness 自己的凭据文件 .credentials.yaml，配置里只放引用；配置里的其他插件设置原样保留，写入失败会回滚。
  • 模型编辑。 思考、图片输入用开关，上下文长度和最大输出单独填，和 Pi、Kimi Code 的模型行一样；DeepSeek Harness 还可以设置可选的思考档位和每个模型的接口兼容选项。OpenCode、MiniMax Code 的模型编辑也改成了这个样子。
  • DeepSeek 账号登录。 在授权中心的 DeepSeek Harness 组用浏览器登录 DeepSeek 账号，显示余额和赠金；Web 和 Desktop 共用这份登录，在任一处登录或退出，两边同时生效。添加供应商时选「DeepSeek 官方登录」会跳到授权中心。登录后，账号以一张官方卡显示在「已添加」最前面，账号下的模型由 DeepSeek Harness 自己提供，这张卡不能编辑，退出登录后自动消失。
  • MCP、Skills、提示词。 支持 stdio 和 Streamable HTTP 两种 MCP。
  • 会话和用量。 可以浏览 DeepSeek Harness 的会话（含思考过程和工具调用）；恢复和删除会话请在 DeepSeek Harness 里操作。用量从会话记录导入，走 DeepSeek 账号的请求在用量页单独显示为「DeepSeek 账号（OAuth）」。
  • 「应用」页管理 DeepSeek Harness。 用 npm 安装、升级、卸载 @deepseek-ai/dsh，卸载不删你的数据。
  • DeepSeek Harness 不经过本地路由。

Oh My Pi 的用量统计

用量页现在会统计 Oh My Pi 的用量，有自己的应用分类（#9046、#8939）。子代理的用量、对话之外的模型调用也会算进去，首次导入会包括以前的子代理会话。Oh My Pi 和 Pi 用同一个会话目录时，各自只导入自己的会话。Pi 已导入的数据不用重新导入。

「打开终端」可以跳过权限确认、追加启动参数

「打开终端」对话框多了两项（#9008）：

  • 跳过权限确认。 勾选后 Claude Code 和 Antigravity 以 --dangerously-skip-permissions 启动，Codex 以 --dangerously-bypass-approvals-and-sandbox 启动。默认不勾。
  • 附加参数（可选）。 填 --debug、--append-system-prompt "Be concise" 这类参数，接在启动命令后面。用空格分隔，含空格的值用引号括起来，最多 16 个。参数只作为参数传给程序，不会被当成命令执行。

两项都只用于这次打开的终端，不写进任何配置；终端打开成功后，CC Switch 会按应用记住你的选择。

Codex 卡片也能「打开终端」

以前 Codex 卡片上没有这个按钮。现在第三方卡片打开的终端只用这张卡：以 codex -c ... 启动，不改 config.toml，Key 通过环境变量传入，不出现在命令行里。当前供应商在 config.toml 里留下的设置会尽量改成不影响这张卡的值，改不了的（比如请求头、指定的 profile）会提示先切到这张卡再打开，避免当前供应商的 Key 被发到别处。当前使用中的卡直接启动 codex。

清除 WebDAV 配置

以前配好 WebDAV 同步后，只能关掉自动同步，地址、账号、密码一直留在本机（#8977）。现在 WebDAV 同步设置里有「清除配置」按钮，确认后从本机删除这些信息并停止自动同步；云端已上传的数据不会删除。

Skills：打开目录、复制名称、查看文档

  • 已安装的 Skill（#8993）：⋯ 菜单里可以「打开目录」，在文件管理器里打开这个 Skill 的文件夹；点击 Skill 名称就能复制名称。原来的「复制目录名」去掉了。
  • 发现页（#9039）：每一行多了「打开文档」按钮，安装前可以先看说明，没有文档时打开仓库主页。

改进

GitHub Copilot 的 Claude 模型提示缓存命中率大幅提高（#8908）。以前 Copilot 的 Claude 模型一律转成 Chat Completions 格式发送，会丢掉缓存标记，Claude Code 在对话中途插入的系统消息还会打断缓存。现在 Copilot 支持原生 Anthropic 接口的模型直接走原生接口，Copilot 企业版长会话的缓存命中率实测从约 35% 提高到约 95%。

添加、启用、停用、删除 Skill 仓库时，只重新读取这一个仓库（#8907、#1426），不再把所有仓库重新下载一遍。点刷新按钮仍会全部重新读取。

托盘和用量设置里也能看到绑了账号的 Claude 官方卡额度。 以前只有卡片上显示，托盘里没有，用量设置弹窗还显示成未启用。

Claude Desktop 的路由服务也接受 x-api-key 传令牌（#5123），令牌校验改成固定耗时的比较（#7488、#7482）。

Claude 配置目录在 WSL 里时，授权中心直接说明暂不支持 Claude 账号，「添加账号」「重新登录」不可用。以前会让你改用「打开终端」，但这时打开的是 Windows 里的 Claude Code，同样用不了。

MCP、Skills 列表悬停勾选框时不再同时弹出两个提示；问号帮助卡片改为显示在右边，不再挡住鼠标，长内容会换行、在卡片里滚动（#8593）。

从别处跳到授权中心的某一组时，页面其他部分不再跟着移动（#8964）。

OpenCode、OpenClaw、Hermes 的配置文件读不了时，供应商页会显示错误（#9044）。以前页面像从没配置过一样空着，添加供应商失败后才看到报错，还会留下一条多余的记录。

托管的 ChatGPT、xAI 账号登录过期时，提示改为「请在授权中心重新登录这个账号」。 以前提示运行一条并不存在的命令。

预设： 新增 OspreyAI、讯飞星火 Astron Coding Plan 的 Claude Code 预设（#9036）；TokenFlux 改用新域名 tokenflux.com，tokenflux.dev 作为备用地址。

修复

  • macOS 上连了需要 OAuth 登录的远程 MCP 时，切换 Claude 账号报「Claude Code 的登录信息太大，无法写入钥匙串，没有切换」（#9002）。MCP 的登录信息和账号存在同一个钥匙串条目里，超过了一次写入的长度上限。现在超长时改用和 Claude Code 一样的写法。
  • 开了全局代理时，在授权中心添加 Claude 账号，浏览器登录成功后报 403（#9038）。换取令牌是 Claude Code 自己完成的，以前它没有用到全局代理。现在 CC Switch 运行 Claude Code 登录、查额度时会把全局代理传给它（SOCKS 代理 Claude Code 不支持，不传）。
  • Claude Desktop 新会话默认用 Fable，而且模型顺序每次启用配置都会变（#7491、#7457、#8973）。Claude Desktop 把模型列表里的第一个当默认模型，以前按字母顺序写。现在按界面上 Sonnet、Opus、Fable、Haiku 的顺序写，新会话默认用 Sonnet 档。
  • MiniMax 周额度用完后，卡片和托盘里不再显示周额度，5 小时额度刚重置时看起来像额度全满（#8124、#8123）。现在显示为红色的「已用完」和周额度重置倒计时。
  • 没在用的供应商设了自动查询间隔，余额也不刷新（#8342、#8335）。
  • 上游地址填成了路由自己的地址时，请求被无限转回路由，内存不断增长（#8598）。现在直接报配置错误。
  • Claude Code 经路由连 Gemini 时，工具调用后报 400：签名放错位置报「Unknown name thoughtSignature」（#6690）；CC Switch 重启后或较早的轮次丢了签名，Gemini 3 以上拒绝请求（#6833）；Vertex 上工具结果后面跟着文字时报「Requests ending with a model turn are not supported」（#8988）。
  • Claude Code 经路由转 OpenAI Responses 时，WebSearch 带屏蔽域名就直接报 400（#8979）。现在 API Key 接入的 Responses 上游会原样传过去；ChatGPT 官方登录的路由不支持屏蔽域名，仍会明确报错。
  • Codex 0.163 以上经路由连 xAI 时报 400（#8997、#8996）。
  • Codex 的 config.toml 里有 [[skills.config]] 这类数组表时，第三方供应商的地址被写进了这张表里（#9029、#9023）。
  • OpenCode 新格式（V2）的供应商「检测连通」报缺少 options.baseURL（#8969）。
  • 上游报错时，请求日志存下整页 HTML 报错，数据库和备份越来越大（#9010、#6706）。现在每条只存前 4096 个字符；已经存下的旧记录这次不清理。
  • Windows 上用 MyDockFinder 这类第三方任务栏时，点托盘图标没反应（#8729、#8565）。
  • Kimi Code 0.43.0 以前的版本在「应用」页升级后版本不变（#9032）。旧版本没有自动确认升级的选项，现在改用安装它的包管理器，或重新运行官方安装脚本。
  • 「应用」页里，程序文件在但运行不起来的应用，分在「已安装」组里却显示「未安装」。 现在显示为「无法运行」，并给出原因。
  • Antigravity 的 CLI 和 IDE 都装了时，在 IDE 里继续的旧会话用量不更新、会话打不开（#8941）。

升级说明

数据库版本从 23 升到 24，为 MCP 和 Skills 增加 DeepSeek Harness 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。

  • DeepSeek Harness 默认显示在侧栏，不用的话可以在「应用」页关掉「在侧栏显示 DeepSeek Harness」。
