#cc-スイッチ v4.0.27

CC スイッチ v4.0.27

このバージョンでは、セッション管理によるメッセージ本文の検索、インターフェイス密度とインターフェイス スケーリング設定の追加、モデル価格表の検索が可能になり、Grok Build で使用されているサプライヤーもターミナルを開くことができます。スキルのインストール済みページが再デザインされ、サプライヤーのアイコンがダークとライトのテーマに従います。さらに、構成ファイルが通常のファイルに置き換えられたり、ソフト リンクのときに書き込みに失敗したり、サプライヤーはリクエストをキャンセルした後に再起動するまでサーキット ブレーカーの回復でスタックしたり、Codex がカスタム権限を設定した後にプラン モードがエラーを報告したり、実行スキルが更新があると誤って報告されたり、スキル ウェアハウスにスキルが 0 表示されたり、Python の pi.exe が Windows 上で Pi として認識されたり、モデル価格の同期がタイムアウトしたり、ウィンドウが表示されなかったりしました。ダイアログボックスを開くときにドラッグしたり、右クリックでブラウザメニューがポップアップしたり、ショートカットパネルが異常に表示されるなどの Linux の問題。 4.0 の完全なアップデート内容については、v4.0 リリース ノート を参照してください。 English → | 日本語版 →

追加

会話のメッセージ本文を検索する

以前は、セッション管理ページでの検索では、タイトル、ディレクトリ、セッション ID しか見つかりませんでした。話した内容は覚えているが、どのセッションだったか思い出せないときは見つかりませんでした (#7896、#7420)。 これで、「メッセージ テキストの検索」を開くことができます。ページの右上隅にある「⋯」メニューから開くか、検索結果がない場合はプロンプト内のボタンを直接クリックします。開くと、検索結果に、ヒットした本文のフラグメントとヒットしたメッセージの数がリストされます。

  • デフォルトではオフです。開いた後、CC Switch はメッセージ本文をローカルにインデックス付けし、作成中に進行状況が表示されます。現時点では、本体の結果が完全ではない可能性があります。
  • インデックスは別個のローカル ファイル session-index.db であり、クラウド同期やバックアップには参加しません。このスイッチをオフにすると削除されます。

インターフェイス密度とインターフェイスのスケーリング

「設定 → 一般 → 外観」に 2 つの新しい項目が追加されました (#9209):

  • インターフェース密度: 「コンパクト」は元のサイズであり、デフォルト値です。 「快適」は文字サイズが大きく、ボタンや入力ボックスの高さが高くなります。
  • インターフェイス ズーム: 90%、100%、110%、125% の 4 段階。Ctrl (macOS では ⌘) と +、- を押して調整することもできます。Ctrl/⌘ と 0 を押して復元することもできます。 どちらの設定も、テーマと同様にローカルにのみ保存されます。トレイ アクセス パネルはコンパクトなサイズのままです。

モデル価格表を検索できます

モデル ID または名前でフィルター処理するための検索ボックスがモデル価格表の上に追加されました (#9205)。 Enter を押すと最初の結果が編集されます。一致するモデルがない場合は、Enter キーを押すと、入力したモデルに新しい価格が追加されます。

Grok Build ターミナルを開く

Grok Build のサプライヤー カードには、[ターミナルを開く] ボタン (#9234) もあります。 Grok CLI では、1 つの端末だけでサプライヤーを変更することはできないため、このボタンは使用されているサプライヤーにのみ表示されます。開かれた端末は、CC スイッチによって管理される Grok 構成を直接使用します。許可確認を省略する場合は--always-approveが追加されます。

変更

  • スキルがインストールされたページの再フォーマット (#9210):
    • 名前列は左側に固定され、ウィンドウが狭い場合、各アプリケーションの列はその下に水平にスクロールします。
    • ステータスとソースのフィルタリングは「検出」ページと同じツールバーに移動され、スキルは選択後にブロックされません。バッチ操作では、アプリケーションごとに更新、アンインストール、「有効化」/「無効化」を保持します。
    • ヘッダーの「N Updatable」リンクは削除され、ツールバーの「Update All」にはすでに番号が書き込まれています。このスキルを更新するには、各行の「更新可能」マークをクリックします。
    • 各行の「...」メニューには、開いているドキュメント、開いているディレクトリ、およびアンインストールが保持されます。書き込みに失敗した場合は、記載の位置にエラーメッセージが表示されます。
  • サプライヤー アイコンはテーマに従います (#8438): カード アイコンの背後にある固定の白い背景を削除しました。単色のダークアイコンはテキストの色に応じて変化し、ダークモードではっきりと見えます。暗いストロークを持つ複数色のアイコン、画像アイコン、およびアップロードしたアイコンは、ダーク モードでも背景が明るいままです。
  • 右クリックしてもブラウザ メニューがポップアップしなくなりました (#8919、#8921): 以前は、メイン ウィンドウとトレイ パネルを右クリックすると、ブラウザ独自のメニューがポップアップ表示されていました (Windows では、「戻る」、「再読み込み」、「名前を付けて保存」、「印刷」など)。もはや;入力ボックス、コード エディター、および選択したテキストは、引き続き右クリックしてコピーして貼り付けることができます。
  • サーキット ブレーカーのログには、サプライヤーが示されています (#9292): サーキット ブレーカーのログ (CB-001 から CB-006) にはすべて「アプリケーション: サプライヤー ID」が含まれています。サーキットブレーカーがサプライヤーを拒否すると、サプライヤーの名前を示す FWD-004 の行も記録され、それを静かにスキップしなくなりました。ログのみが変更されていますが、ルーティングとサーキット ブレーカーの動作は変更されていません。
  • プリセット: Mistral AI プリセットのデフォルト モデルは mistral-large-4 に変更され (Mistral Medium 3.5 は Mistral によって廃止されることが発表されました)、Claude Code、Codex、および Claude Desktop の Mistral AI プリセットは非表示になりません。 Mistral Vibe パッケージと API は同じ割り当てを共有します。 「Get API Key」は Vibe CLI のキー ページを開くように変更され、無料、サブスクリプション、従量課金制で利用可能です。サプライヤーを追加するときに「Vibe」を検索して見つけることもできます。 Genesis (#9269) と TokenPlus (#9296) を追加しました。すでに追加されているサプライヤーは影響を受けません。

修正

  • 設定ファイルがソフト リンクの場合、プロバイダーを切り替えると通常のファイルに置き換えられ、Windows 上でエラーが直接報告されます (#6764、#9283)。 dotfiles ツールまたは同期フォルダーを使用して ~/.claude/settings.json、~/.codex/config.toml、opencode.json などのファイルを管理する場合、これらのファイルは通常はソフト リンクになります。以前は、書き込み時にリンク自体が置き換えられていました。 macOS と Linux では、リンクは通常のファイルに変わり、元のファイルから切り離されました。 Windows では、「アトミック置換に失敗しました」というエラー (OS エラー 1464) が報告されました。これで、リンクが指す実際のファイルが書き込まれ、リンクは変更されません。
  • リクエストが途中でキャンセルされた後、プロバイダーは再起動されるまでサーキット ブレーカーの回復状態になる可能性があります (#7206、#9292)。サーキット ブレーカーの回復期間中、サーキット ブレーカーは 1 つの検出リクエストのみを渡します。リクエストが完了する前にクライアントが切断された場合、クォータは返されず、このサプライヤーに対する後続のリクエストはすべて拒否されます。これで、リクエストがどのように終了してもスポットは返されます。
  • Codex でカスタム権限を設定した後、プラン モードを使用してエラーを報告します (#7349、#7294)。新しい Codex では、カスタム権限を読み取るときに model_catalog_json を絶対パスにする必要があります。以前は、CC Switch がファイル名を書き込み、コーデックスは AbsolutePathBuf deserialized without a base path を報告していました。ここで絶対パスを書きます。構成ディレクトリが WSL 内にある場合でも、ファイル名を書き込みます。
  • 一度実行されたスキルは「更新可能」として表示され、更新をクリックするとディレクトリ全体がカバーされます (#7780、#7772)。 Python の実行時に生成される __pycache__ および .pyc ファイルは、スキル コンテンツに含まれます。これらのファイルは、更新をチェックするときに無視されるようになりました。以前のバージョンから取得された古いレコードは自動的に変換され、誤検知は発生しません。
  • スキル ウェアハウスに「認識されたスキルは 0 件」と表示されます (#9273)。インポート中に追加された倉庫ブランチは HEAD として記録されます。または、倉庫のデフォルト ブランチがマスターであるがメインに割り当てられている場合、数量は常に 0 になります。現在、カウントは実際に読み取られたブランチに基づいています。読み取りに失敗したウェアハウスには、「読み取り失敗」とその理由が表示されます。スキルをインポートして新しい倉庫を追加すると、次回開いたときに再度読み取られます。
  • Windows は、Python パッケージ内の pi.exe を Pi (#9267) として扱います。 PyPI には Scripts\pi.exe をインストールする無関係な pi パッケージがあり、アプリケーション ページには「実行できません」と表示されます。 Pi は npm 経由でのみリリースされ、Python Scripts ディレクトリ内の pi.exe は Pi として認識されなくなりました。
  • モデル価格の同期が失敗し、error decoding response body (#9262) のみが表示されました。遅いネットワークまたはプロキシでは、models.dev から価格表をダウンロードすると途中でタイムアウトになります。タイムアウトが 15 秒から 60 秒に緩和され、失敗した場合には同期ステータスに本当の理由が書き込まれるようになりました。
  • DeepSeek ハーネス サプライヤーを追加すると、Invalid DeepSeek Harness profile YAML のみが表示されます。どのファイルであるかわかりません (#9297)。エラー レポートにエラー構成ファイルのパスと YAML の特定のエラーが書き込まれるようになり、修復するファイルを見つけやすくなります。
  • 接続テストにより、リダイレクション ステーションに到達できないことが判明しました (#9253、#5747)。一部のゲートウェイは、/v1 と /v1/ の間で相互にリダイレクトします。現在、リダイレクトを受信した場合でも接続できることをテストしています。
  • ダイアログ ボックスを開くときにウィンドウをドラッグできません (#9140)。ダイアログ ボックスが開いているときにウィンドウをドラッグできるようになりました。 Windows および Linux でアプリ内ウィンドウ ボタンを使用する場合、最小化、最大化、および閉じるボタンは引き続き使用できます。
  • Linux ショートカット パネル表示例外: ライトウェイト モードで再度開かれたパネルとウィンドウは正しくレンダリングされず (#9233、#9216)、表示ズームが設定されているときにパネルの一部が切り取られます (#9287、#8556)。 Linux 上のパネルは不透明な背景に変更されました。
  • サプライヤー名が絵文字などの文字で始まるか、スペースで始まる場合、アイコンのないカードに表示される最初の文字が文字化けまたは空白になります (#8139)。
  • ワンクリックインポートリンクのリスク警告では、IPv4 アドレスが埋め込まれた IPv6 アドレスが欠落します (#8127)。このタイプのアドレスは、ローカル マシンであるかイントラネットであるかにかかわらず、実際に指す IPv4 アドレスに基づいて判断されるようになりました。

cc-switch v4.0.27

Highlights

  • Full-text session search is opt-in — Search can now match message bodies, not just titles, directories, and IDs (#7896). CC Switch builds a separate local session-index.db; it is excluded from cloud sync and backups, deleted when the feature is disabled, and results may be incomplete during initial indexing—important if you rely on cross-device session history.
  • Configuration writes preserve symlinks — Provider switches now write through to the target of linked files such as ~/.claude/settings.json, ~/.codex/config.toml, and opencode.json instead of replacing the link (#9283). This keeps dotfiles and synced configurations connected and fixes Windows atomic-replacement error 1464; existing links need no migration.
  • Two reliability blockers are fixed — Codex custom-permission configurations now use an absolute model_catalog_json path, resolving plan-mode deserialization failures (#7349); WSL configuration directories intentionally still use a filename. Canceled requests now return circuit-breaker probe slots, preventing providers from remaining stuck in recovery until restart (#9292).
  • Skill updates no longer chase runtime artifacts — Update checks ignore __pycache__ and .pyc, preventing used Python Skills from being falsely marked stale and then overwritten during updates (#7780); old records are converted automatically. Repository discovery now counts the branch actually read and reports failures with reasons instead of showing “0 skills” (#9273).
  • Provider setup gains safer defaults and Grok terminal access — New Mistral AI presets default to mistral-large-4 because Medium 3.5 is deprecated; existing providers are unchanged. Grok Build’s terminal action appears only on the active provider because Grok CLI cannot switch providers per terminal; it uses CC Switch’s managed configuration and adds --always-approve when permission confirmation is skipped (#9234).
  • Breaking changes — None.

CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 pi.exe 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（#7896、#7420）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

  • 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
  • 索引是单独的本地文件 session-index.db，不参与云同步，也不进备份；关闭这个开关会删除它。

界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（#9209）：

  • 界面密度：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
  • 界面缩放：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 +、- 调整，按 Ctrl/⌘ 加 0 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（#9205）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（#9234）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 --always-approve。

变更

  • Skills 已安装页重新排版（#9210）：
    • 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
    • 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
    • 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
    • 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
  • 供应商图标跟随主题（#8438）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
  • 右键不再弹出浏览器菜单（#8919、#8921）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
  • 熔断日志写明是哪家供应商（#9292）：熔断器的日志（CB-001 到 CB-006）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 FWD-004，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
  • 预设： Mistral AI 预设的默认模型改为 mistral-large-4（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（#9269）、TokenPlus（#9296）。已添加的供应商不受影响。

修复

  • 配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错（#6764、#9283）。用 dotfiles 工具或同步文件夹管理 ~/.claude/settings.json、~/.codex/config.toml、opencode.json 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
  • 请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启（#7206、#9292）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
  • Codex 设置了自定义权限后，用 plan 模式报错（#7349、#7294）。较新的 Codex 读取自定义权限时要求 model_catalog_json 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 AbsolutePathBuf deserialized without a base path。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
  • 运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录（#7780、#7772）。Python 运行时生成的 __pycache__ 和 .pyc 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
  • Skills 仓库显示「识别到 0 个技能」（#9273）。导入时添加的仓库分支记为 HEAD，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
  • Windows 上把 Python 包里的 pi.exe 当成 Pi（#9267）。PyPI 上有一个无关的 pi 包会装出 Scripts\pi.exe，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python Scripts 目录里的 pi.exe 不再被识别为 Pi。
  • 模型价格同步失败，只提示 error decoding response body（#9262）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
  • 添加 DeepSeek Harness 供应商时只提示 Invalid DeepSeek Harness profile YAML，不知道是哪个文件（#9297）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
  • 连通性测试把会重定向的中转站判为不通（#9253、#5747）。有的网关在 /v1 和 /v1/ 之间互相重定向，现在测试收到重定向就算连得上。
  • 打开对话框时窗口拖不动（#9140）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
  • Linux 快捷面板显示异常：轻量模式下重新打开的面板和窗口渲染出错（#9233、#9216），设置了显示缩放时面板被裁掉一部分（#9287、#8556）。Linux 上的面板改为不透明背景。
  • 供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白（#8139）。
  • 一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址（#8127）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
