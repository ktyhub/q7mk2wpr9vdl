cc-switch v4.0.33

パッチ 公開日2026年11月16日 出典farion1231/cc-switch English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#cc-スイッチ v4.0.33 #CCスイッチv4.0.33 このバージョンでは、サードパーティのプロバイダーから Claude official に切り替えた後、すでに開いている Claude Code セッションが依然として前のプロバイダーにリクエストを送信し、回復するにはセッションを再起動する必要があるという問題が修正されています。 Ollama Cloud がパッケージ クォータ クエリに追加されました。認証センターの Antigravity アカウント切り替え も Windows をサポートするようになりました。 さらに、Claude Code/Claude Desktop のサプライヤーは、Gemini ネイティブ形式を選択したときにモデル リストを取得するときに「API キーが無効であるか、権限がありません」というレポートを修正しました。一部のサービスプロバイダーは、モデルリストの取得がCloudflareによってブロックされています。 Antigravity Orchestrator の一部のリクエストにはまだ価格が付けられていません。一部の NAS では WebDAV 同期が完全に利用できません。 WebDAV/S3 のアップロードに失敗すると、「リクエストの構築に失敗しました」と表示されるだけです。クォータの適用時にネットワークのジッターが発生すると、再度ログインを求められるなどのクエリ xAI の問題。スキルの更新を途中で失敗して元のスキルを削除してしまうなど。 English → | 日本語版 →

追加

Ollama Cloud パッケージのクォータ

アドレス ollama.com のサプライヤーは、トークン プラン クォータをクエリできるようになりました (要件については、#9382 を参照)。現在のパッケージには、クォータの残りの割合と現在のパッケージ内のリセット時間が表示され、パッケージの古いバージョンには、残りの割合 5 時間と 1 週間あたり 2 つのウィンドウが表示されます。個別に購入した割り当ては表示されません。従量課金制アカウントにはパッケージ割り当てがありません。その理由については後で説明します。ネイティブで実行される Ollama (localhost:11434) にはプランがないため、認識されません。

  • 新しく追加された Ollama Cloud サプライヤーまたはワンクリック インポートの場合、クォータ クエリはデフォルトで有効になります。既存のサプライヤーの場合は、カード上の [使用量クエリの構成] をクリックすると、トークン プラン テンプレートが自動的に選択されます。 「使用状況クエリを有効にする」を開いて保存します。

Windows で Antigravity アカウントを切り替える

認証センターでの Antigravity アカウントの切り替えは、以前は macOS のみをサポートしていましたが、現在は Windows でも使用できるようになりました。切り替え後、agy は新しいアカウントを読み取ります。 Antigravity 公式カードはアカウントをバインドし、バインドされたアカウントの限度額を確認できます。また、ターミナルを開く前に、どのアカウントに切り替えるかプロンプトが表示されます。 Linux はまだサポートされていません。

修正

  • サードパーティプロバイダーからクロード公式に切り替えた後も、開いているクロードコードセッションは前のプロバイダーにリクエストを送信するため、再開するには再起動する必要があります (#9247、#7808、#3057を参照): 実行中のクロードコードは、セッション内で追加および変更された環境変数、および削除された環境変数のみを読み取ります。セッションに残ります。さて、切り替える場合は、まず削除するアドレス、認証情報、モデルマッピングをnull値として書き込みます。開いているセッションの次のリクエストでは前のリクエストは使用されなくなり、約 10 秒後にファイルから削除されます。セッションの開始時に設定されたメイン モデル (ANTHROPIC_MODEL) は変更されません。以前のモデルで設定されていた場合は、切り替え後にモデル メニューで [デフォルト] を選択するか、新しいセッションを開きます。
  • クロード コード/クロード デスクトップのサプライヤーが Gemini ネイティブ形式を選択すると、「モデル リストの取得」で常に「API キーが無効か、権限がありません」と報告されます: ここで、Google が要求する方法でキーを渡します。ルーティングされる実際のリクエストはすでに正常であり、モデル リストの取得のみが影響を受けます。また、Pi、Oh My Pi、Kimi Codeについては、Googleインターフェースのサプライヤーを選択すると、これまでは最大50モデルまでしか掲載されていなかったモデルリストを取得できましたが、全モデルを掲載できるようになりました。
  • モデルリストを取得する際、Cloudflareの背後にある一部のサービスプロバイダーがモデルリストを直接拒否し、「APIキーが無効か権限がありません」と誤って報告されました (#7429、#7427を参照): リクエストにはデフォルトでユーザーエージェントが含まれるようになりました。 User-Agent がサプライヤーまたはリクエストヘッダーに設定されている場合、その設定が優先されます。
  • Antigravity が Orchestrator を選択すると、一部のリクエストはまだ価格が付けられていないと表示されます (#9542、#9493 を参照): 「Gemini 4 Hydrogen (Orchestrator)」として表示されるステップは、Gemini 4 Hydrogen の価格に応じて価格が設定され、過去 30 日間の履歴も料金を補います。カスタム価格は依然として優先されます。
  • 一部の NAS では WebDAV 同期が完全に利用できず、テスト接続、アップロード、ダウンロードがすべて失敗します (#5623、#5621 を参照): これらの NAS は、共有フォルダーが既に存在する場合でも「ディレクトリの作成」に 400 を返します。以前は直接中止されていましたが、現在はディレクトリが存在するかどうかを再度チェックするようになりました。
  • WebDAV / S3 アップロードがサーバーによって切断されると、「リクエストの構築に失敗しました」のみが表示されます (#9559 を参照): リクエストが構築されなかったのか、送信時に失敗したのかが明確になり、ネットワーク、TLS、またはサーバーの問題であるかどうかの判断を容易にするために、具体的な理由が添付されます。アドレス内のパスワードと署名パラメータはエラー レポートには表示されません。
  • S3 自動同期はオフになった後も再度アップロードされる可能性があります (#9528): 別の同期の進行中にキューに入れられた自動アップロードは、開始前に設定が再読みされるようになり、期間中に自動同期または S3 同期がオフになった場合はアップロードされなくなります。 WebDAV はまさにそれです。
  • xAI アカウントの残高をクエリするときに、ネットワーク ジッターまたは xAI サービス エラーが発生した場合は、再度ログインするように求められます (#9526、#9522 を参照): このプロンプトは、ログインが実際に無効な場合にのみ表示されます。一時的なエラーは通常どおり報告され、最後に見つかった残高は保持されます。次回もう一度試してください。
  • デフォルト以外の xAI アカウントの有効期限が切れた後、認証センターで選択されたデフォルト アカウントは別のアカウントに置き換えられました (#9548、#9543 を参照)。
  • スキルの更新時にコピーが途中で失敗した場合、元のスキルは削除されますが、リストにはインストール済みとして表示されます (#9521 を参照): 新しいバージョンは完全にコピーされた後にのみ置き換えられ、失敗した場合は元のバージョンが保持されるようになりました。
  • コーデックスがルーティング経由でチャット形式に変換される場合、ツール定義の required: null は厳密なアップストリームによって拒否されます (#7023、#7019 を参照)。
  • macOS/Linux 上のシェル設定ファイルへのパスにコロンが含まれている場合、「システム環境変数の競合が検出されました」というメッセージが表示され、変数の削除または復元が失敗します (#7170、#7169 を参照)。
  • PIPELLM、AICodeWith、および E-FlowCode の Pi デフォルトは、モデル選択で古いモデル名として表示されます (#9514): たとえば、Claude Opus 5.5 は claude-opus-5 として表示され、実際のリクエストは新しいモデルです。これらのプリセットを使用して生成された DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、および Kim Code プリセットは、一緒に変更されます。すでに追加されているサプライヤーは、元の保存名を保持します。
  • api.commandcode.ai/providers の形式のアドレスを持つサプライヤーは、コマンド コード パッケージ クエリ クォータとして使用されます (#9518)。

cc-switch v4.0.33

Highlights

  • Claude Code 切换供应商 — 修复从第三方供应商切回 Claude 官方后，已打开的会话仍请求上一家的问题（#9247）。切换时先将被删除的地址、凭据和模型映射写成空值，约 10 秒后再从文件中删除，使会话的下一条请求立即生效。但 ANTHROPIC_MODEL 在会话启动时已固定，不会自动改变；若上一家配置过它，切回后需在模型菜单选择一次 Default 或新开会话。经常切换供应商的用户应优先升级。

  • 模型列表与协议兼容性 — Claude Code / Claude Desktop 使用 Gemini Native 格式时，模型列表不再误报「API Key 无效或无权限」；实际路由请求此前正常，本次只修列表获取。Pi、Oh My Pi、Kimi Code 的 Google 接口列表不再限制为 50 个模型；Cloudflare 后的服务商默认携带 User-Agent，自定义值仍优先。同时修复 Codex 转 Chat 格式时工具定义中的 required: null 被严格上游拒绝的问题。

  • 同步与 Skill 更新可靠性 — WebDAV 现在能兼容部分在目录已存在时仍返回 400 的 NAS；WebDAV / S3 上传失败会区分请求构造错误与发送错误，给出具体原因，并避免暴露密码和签名参数。关闭自动同步后，已排队的 S3 上传不会再执行。Skill 更新改为完整复制成功后才替换，失败会保留原版本，避免更新失败导致 Skill 丢失。使用 NAS、S3 或频繁更新 Skill 的用户值得升级。

  • 额度、账号与计价 — 新增 Ollama Cloud Token Plan 额度查询；新添加或导入的供应商默认启用，已有供应商需在卡片「配置用量查询」中选择 Token Plan 模板并保存。Windows 现已支持 Antigravity 账号切换、绑定和额度查看，Linux 仍不支持。xAI 查询遇到临时网络或服务错误时不再要求重新登录，并保留上次额度；非默认账号过期也不会再顶替默认账号。Antigravity Orchestrator 的 Hydrogen 步骤按 Gemini 4 Hydrogen 计价，近 30 天历史费用会补算，自定义价格仍优先。

  • 升级判断 — 未声明破坏性变更，也没有强制迁移步骤；可选功能除外，现有配置无需调整。另外修复了 macOS / Linux 冒号路径下的环境变量冲突处理、部分 Pi 预设的旧模型名，以及 api.commandcode.ai/providers 被误判为 Command Code 套餐的问题。命中上述问题的用户建议升级；完全未使用相关功能、且当前没有这些故障的用户可以跳过。

CC Switch v4.0.33

本版本修复了从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家、要重开会话才恢复的问题。套餐额度查询新增 Ollama Cloud；授权中心的 Antigravity 账号切换现在也支持 Windows。

另外修复了 Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时获取模型列表总报「API Key 无效或无权限」；部分服务商获取模型列表被 Cloudflare 拦下；Antigravity Orchestrator 仍有部分请求显示未定价；WebDAV 同步在一些 NAS 上完全用不了；WebDAV / S3 上传失败只显示「请求构造失败」；查询 xAI 额度时遇到网络抖动就被要求重新登录；更新 Skill 中途失败把原来的 Skill 删掉等问题。

新增

Ollama Cloud 套餐额度

地址是 ollama.com 的供应商现在可以查询 Token Plan 额度（需求见 #9382）：现行套餐显示本期套餐内额度的剩余比例和重置时间，旧版套餐显示 5 小时和每周两个窗口的剩余比例。单独购买的额度不显示；按量付费的账号没有套餐额度，会说明原因。本机运行的 Ollama（localhost:11434）没有套餐，不会被识别。

  • 新添加或一键导入的 Ollama Cloud 供应商默认开启额度查询；已有的供应商在卡片上点「配置用量查询」，Token Plan 模板会自动选好，打开「启用用量查询」后保存即可。

Windows 上切换 Antigravity 账号

授权中心的 Antigravity 账号切换以前只支持 macOS，现在 Windows 也能用：切换后 agy 读到的是新账号，Antigravity 官方卡可以绑定账号、查看所绑账号的额度，打开终端前也会提示将切换到哪个账号。Linux 暂不支持。

修复

  • 从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家，要重开会话才恢复（#9247，见 #7808、#3057）：运行中的 Claude Code 只会读入 settings.json 里新增和改动的环境变量，被删掉的仍留在会话里。现在切换时先把要删的地址、凭据和模型映射写成空值，开着的会话下一条请求就不再用上一家，约 10 秒后再从文件里删掉。会话启动时就定下的主模型（ANTHROPIC_MODEL）不会跟着变：如果上一家设了它，切回后在模型菜单里选一次 Default，或者新开会话。
  • Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时，「获取模型列表」总是报「API Key 无效或无权限」：现在按 Google 要求的方式传 Key。经路由的实际请求本来就正常，只有获取模型列表受影响。另外，Pi、Oh My Pi、Kimi Code 选 Google 接口的供应商，获取模型列表以前最多只列出 50 个，现在能列全。
  • 获取模型列表时，部分放在 Cloudflare 后面的服务商直接拒绝，被误报为「API Key 无效或无权限」（#7429，见 #7427）：请求现在默认带上 User-Agent；供应商或请求头里设了 User-Agent 的，仍以设置的为准。
  • Antigravity 选 Orchestrator 时，仍有部分请求显示未定价（#9542，见 #9493）：显示为「Gemini 4 Hydrogen (Orchestrator)」的步骤按 Gemini 4 Hydrogen 的价格计价，近 30 天内的历史也会补上费用。自定义价格仍然优先。
  • WebDAV 同步在部分 NAS 上完全用不了，测试连接、上传、下载都失败（#5623，见 #5621）：这些 NAS 在共享文件夹已存在时仍对「建目录」回 400，以前会直接中止，现在会再查一次目录是否存在。
  • WebDAV / S3 上传被服务器中途断开时，只显示「请求构造失败」（见 #9559）：现在分清是请求没构造出来还是发送时失败，并附上具体原因，方便判断是网络、TLS 还是服务器的问题。地址里的密码和签名参数不会出现在报错里。
  • S3 自动同步在关掉之后仍可能再上传一次（#9528）：另一次同步进行中时排队的自动上传，现在开始前会重新读取设置，期间关掉了自动同步或 S3 同步就不再上传。WebDAV 本来就是这样。
  • 查询 xAI 账号额度时，遇到网络抖动或 xAI 服务出错就提示需要重新登录（#9526，见 #9522）：只有登录真的失效才这样提示，临时错误照常报错并保留上次查到的额度，下次查询再试。
  • 一个非默认的 xAI 账号过期后，授权中心里选好的默认账号被换成了别的账号（#9548，见 #9543）。
  • 更新 Skill 时如果复制到一半失败，原来的 Skill 被删掉，列表里却仍显示已安装（见 #9521）：现在新版本完整复制好之后才替换，失败时保留原来的版本。
  • Codex 经路由转成 Chat 格式时，工具定义里的 required: null 被要求严格的上游拒绝（#7023，见 #7019）。
  • macOS / Linux 上 shell 配置文件的路径里带冒号时，「检测到系统环境变量冲突」删除或恢复变量会失败（#7170，见 #7169）。
  • PIPELLM、AICodeWith、E-FlowCode 的 Pi 预设在模型选择里显示成旧模型名（#9514）：比如 Claude Opus 5.5 显示成 claude-opus-5，实际请求的是新模型。用这几个预设生成的 DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code 预设一起修正；已经添加的供应商保留原来保存的名字。
  • 地址形如 api.commandcode.ai/providers 的供应商被当成 Command Code 套餐查询额度（#9518）。
