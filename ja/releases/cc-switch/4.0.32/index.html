#cc-スイッチ v4.0.32

CCスイッチ v4.0.32

このバージョンでは、バックグラウンドでアップデートを自動的にダウンロード: 「設定 → バージョン情報」で「アップデートを自動的にダウンロード」をオンにすると、新しいバージョンがバックグラウンドでダウンロードされ、検証されます。右下隅に、インストールするかどうかを尋ねるプロンプトが表示されます。確認しないと再起動されません。 「設定 → ネットワーク」に IP 検出 が追加されました。これにより、CC Switch がグローバル プロキシ、一時プロキシ、または現在のネットワーク経由でアクセスされたときに、出口 IP と地域を表示できるようになります。 さらに、Codex がルーティング プロバイダーとスイッチング プロバイダーを介して古いセッションを継続する場合、アップストリームが最初に 200 を返し、その後「復号化できません」と報告し、ラウンド全体が破棄されるなどの問題も修正しました。 Codex は、ルーティングまたはアグリゲーションを通じて Mistral AI に接続するときにレポート 422 を要求します。 CC スイッチ内の操作がクラッシュすると、トレイが空になり、再起動するまでプロバイダーを切り替えることができなくなります。 mise でインストールされたツールは、「アプリケーション」ページに 2 つのインストール レコードを表示します。 English → | 日本語版 →

追加

バックグラウンドでアップデートを自動的にダウンロードする

「設定→バージョン情報」に「アップデートを自動的にダウンロードする」スイッチが追加されます。このスイッチはデフォルトではオフになっており、デバイスごとに個別に設定できます。

  • CC Switchは電源を入れてから1分後にチェックし、その後は6時間ごとにチェックします。新しいバージョンがある場合は、バックグラウンドでダウンロードされて検証されます。
  • ダウンロード後、メインインターフェイスの右下隅にインストールするかどうかを尋ねられます。インストールにより CC Switch が再起動され、ローカル ルーティングを通過するリクエストが中断されるため、続行するには [インストールと再起動] をクリックする必要があります。これは、ルーティングがオンのときにプロンプ​​トに表示されます。
  • 「後で」をクリックしても、このバージョンの入力を求めるプロンプトは表示されなくなります。設定の赤い点、「バージョン情報」ページのボタン、トレイ メニューとショートカット パネルの新しい「再起動して vX に更新」は引き続きインストールできます。 ・ポータブル版およびLinuxのdeb/rpmインストールパッケージは自動インストールできません。スイッチがグレーアウトされ、その理由が説明されます。

IP 検出

「設定 → ネットワーク」により、グローバル プロキシの下に IP 検出が追加されます (#9449、要件については #9448 を参照): 保存されたグローバル プロキシを選択するか、一時プロキシを入力します (この検出にのみ使用され、保存されません)。 「IP 検出」をクリックすると、出口 IP、2 つの検出サービスの結果が一致するかどうか、国または地域、都市、オペレーターなどの情報が表示されます。グローバル プロキシがない場合は、システム プロキシまたは直接接続が検出に使用されます。プロキシを指定した場合、プロキシが接続できない場合は直接接続は使用されません。

  • クリックした後にのみ実行され、icanhazip.com、ipify.org にアクセスし、測定された IP を ipwho.is に送信して場所を照会します。
  • 測定されるのは、この回線を介した CC スイッチ自体の出口であり、Claude Code や Codex などのクライアントの出口と必ずしも同じではありません。

その他

  • GitHub Copilot リバース サプライヤー カードには、バインドされた GitHub アカウントが表示されます (#9228、要件については #9480 を参照): 以前は、GitHub Copilot の公式 Web サイト アドレスのみが表示され、複数のアカウントを区別するのが困難でした。バインドされていない場合は、認証センターのデフォルトのアカウントが表示されます。備考が記入されている場合は備考が優先されます。

修正

  • Codex がスイッチング プロバイダーを通じて古いセッションを継続すると、アップストリームは最初に 200 を返し、次に「暗号化された関数の出力コンテンツを復号化またはデコードできませんでした」と報告します。 Codex が 5 回再接続すると、このラウンドは破棄されます (#9476): リクエストに思考レコードまたは前のプロバイダーによって生成された暗号化されたコンテンツが含まれている場合、CC スイッチはアップストリームが出力を開始するのを待ってから引き渡します。 Codex では、この時点で拒否された場合は、これらのコンテンツを削除し、同じ会社で自動的に再試行し、セッションを続行できます。そのようなコンテンツのないリクエストは通常​​どおりストリーミングされます。
  • Codex がルーティングまたはアグリゲーション経由で Mistral AI に接続されている場合、リクエストは 422 extra_forbidden (#9507) を報告します。Codex によって保持される応答特殊フィールド、Mistral 上の DeepSeek / GLM モデルに自動的に追加される思考パラメーター、およびツール使用後の各ラウンドで保持される reasoning_content は、api.mistral.ai に送信されるときに削除されます。他のアップストリームは影響を受けません。
  • CC スイッチの内部動作が一度クラッシュすると、トレイ メニューが空になり、サプライヤーを切り替えることができなくなり、終了時に直接接続を復元できなくなります。再起動のみ可能です (#9472、#9483、#8058 を参照): データベース、設定、構成ファイルの書き込み、MCP、プロンプト ワード、価格、バックアップ、その他の操作をクラッシュ後に復元できるようになり、クラッシュ時の未完了の変更はロールバックされます。
  • GitHub Copilot 経由で Claude Code / Claude Desktop を使用する場合、Copilot の Responses インターフェイスのみをサポートする Grok などのモデルは、「/chat/completions エンドポイント経由ではアクセスできない」と報告されました (#6954、#9473): このタイプのモデルは現在、Responses インターフェイスを使用しており、両方のインターフェイスでサポートされているモデルは変更されていません。
  • Antigravity が Orchestrator を選択すると、すべての使用状況が仮想モデルの名前で記録され、コストは 0 になります (#9493、#9494): 価格は各ステップで使用される実際のモデルに基づき、Gemini 4 Hydrogen の価格が追加されるようになりました。インポートされた反重力履歴は再解析され、コストは補償されます。
  • 「統合コーデックス セッション履歴」をオンにするか、履歴を移行すると、数か月前のセッションが codex resume で 1 位にランクされる (#3866、#9471): 通常の .jsonl セッション ファイルを書き換える場合、元の変更時刻が保持され、圧縮ファイルも保持されます。変更された変更時刻は復元されません。
  • Hermes で削除されたサプライヤーの場合、CC スイッチの削除ボタンは常にグレーになります (#4816、#9470):Hermes に存在しなくなったサプライヤーを編集および削除できるようになりました。 Hermes 設定を読み取れない場合でも、ロックされたままになります。
  • プリセットから OpenClaw サプライヤーを追加すると、/model はフォームに最後に保存されたモデルではなく、プリセットに付属するモデルをリストします (#9474、#6729 を参照): フォーム内の削除されたモデルは再表示されず、新しく追加されたモデルも選択できます。プリセットを変更せずに直接保存すると、すべてのプリセットモデルが登録されます。既存のサプライヤーの編集はまだ同期されず、#6729 は引き続き追跡されます。
  • mise でインストールされたツール、「アプリケーション」ページには 2 つのインストール レコードが表示されます (mise が Homebrew でインストールされている場合、そのうちの 1 つは homebrew としてマークされます) (#9515): misse の shim は、実際に指すインストールとしてカウントされるようになりました。
  • ウィンドウが短い場合、[ターミナルを開く]ダイアログ ボックスの確認ボタンが画面からはみ出してクリックできません (#9478): ダイアログ ボックスの内容は独立してスクロールでき、ボタンは下部に固定されます。 「追加パラメータ (オプション)」入力ボックスで Enter キーを押してターミナルを直接開くこともできます。
  • 利用状況ページの為替レートのステータスにピリオドがありませんが、次の説明に接続されています (#9436)。

cc-switch v4.0.32

Highlights

  • Automatic update downloads, manual installation — Enable the opt-in setting to check one minute after launch, then every six hours; updates are downloaded and verified in the background. Installation still requires confirmation and restarts CC Switch, interrupting requests through its local router. Portable and Linux deb/rpm builds cannot auto-install. “Later” suppresses the prompt for that version without removing the other update entry points.
  • Proxy-aware IP diagnostics (#9449) — Check the exit IP and geolocation for a saved global proxy or an unsaved temporary proxy. Results show agreement between two IP services, and a failed selected proxy does not fall back to direct access. Note that this measures CC Switch’s own route, not necessarily Claude Code’s or Codex’s traffic.
  • Reliable Codex provider routing (#9476, #9507) — If a new provider rejects encrypted content from a previous provider after starting a 200 response, CC Switch strips that content and retries once with the same provider. Requests to Mistral AI also omit Responses-only fields, model-specific thinking parameters, and stale reasoning_content, eliminating 422 extra_forbidden errors.
  • Copilot model compatibility and account visibility (#9473, #9228) — Models such as Grok that Copilot exposes only through Responses are routed to that endpoint instead of failing on /chat/completions. Provider cards now distinguish accounts using the bound GitHub identity or a custom note.
  • Crash recovery and accurate accounting (9472, #9483, #9494) — Database, settings, configuration, MCP, prompt, pricing, and backup operations can recover after an internal crash and roll back incomplete writes, preventing a broken tray and direct-connect state. Antigravity Orchestrator usage is now charged to the model used at each step, and imported history is reparsed to backfill costs.
  • Provider management fixes — Hermes providers deleted externally become editable and removable (#9470); new OpenClaw providers now register the models actually saved in the form (#9474), though editing existing providers still does not sync them. Codex history ordering is also corrected by preserving original .jsonl modification times (#9471).

No breaking changes.

CC Switch v4.0.32

本版本新增后台自动下载更新：在「设置 → 关于」打开「自动下载更新」后，新版本会在后台下载并校验好，右下角弹出提示问你是否安装，不会未经确认就重启。「设置 → 网络」新增 IP 检测，可以查看 CC Switch 经全局代理、临时代理或当前网络访问时的出口 IP 和所在地区。

另外修复了 Codex 经路由换供应商续接旧会话后，上游先回 200 再报「无法解密」导致整轮报废；Codex 经路由或聚合接 Mistral AI 时请求报 422；CC Switch 内部某个操作崩溃一次后，托盘变空、切不了供应商，直到重启；用 mise 装的工具在「应用」页显示两条安装记录等问题。

新增

后台自动下载更新

「设置 → 关于」新增「自动下载更新」开关，默认关闭，每台设备单独设置。

  • 打开后，CC Switch 启动一分钟后检查一次，之后每六小时检查一次，有新版本就在后台下载并校验。
  • 下载好后，主界面右下角会问你是否安装。安装会重启 CC Switch，正在经本地路由的请求会中断，所以一定要你点「安装并重启」才会进行；路由开着时提示里会写明这一点。
  • 点「稍后」只是不再为这个版本弹提示，设置里的红点、「关于」页的按钮，以及托盘菜单和快捷面板里新增的「重启并更新到 vX」仍然可以安装。
  • 便携版和 Linux 的 deb / rpm 安装包不能自动安装，开关会置灰并说明原因。

IP 检测

「设置 → 网络」在全局代理下方新增 IP 检测（#9449，需求见 #9448）：选已保存的全局代理或填一个临时代理（只用于这次检测，不保存），点「检测 IP」后会显示出口 IP、两个检测服务的结果是否一致，以及国家或地区、城市、运营商等信息。没设全局代理时，按系统代理或直连检测；指定了代理时，代理连不上不会改用直连。

  • 只在点击后运行，会访问 icanhazip.com、ipify.org，并把测得的 IP 发给 ipwho.is 查询位置。
  • 测的是 CC Switch 自己经这条线路的出口，不一定等于 Claude Code、Codex 等客户端的出口。

其他

  • GitHub Copilot 反代供应商卡片显示绑定的 GitHub 账号（#9228，需求见 #9480）：以前只显示 GitHub Copilot 的官网地址，多个账号时分不清。没绑定时显示授权中心的默认账号，填了备注时备注优先。

修复

  • Codex 经路由换供应商续接旧会话时，上游先回 200、再报「Encrypted function output content could not be decrypted or decoded」，Codex 重连五次后这一轮报废（#9476）：请求里带着上一家生成的思考记录或加密内容时，CC Switch 会先等上游开始输出再交给 Codex，这时被拒就去掉这些内容后在同一家自动重试一次，会话可以继续。不带这类内容的请求照常直接流式返回。
  • Codex 经路由或聚合接 Mistral AI 时，请求报 422 extra_forbidden（#9507）：Codex 带的 Responses 专用字段、为 Mistral 上的 DeepSeek / GLM 模型自动加的思考参数，以及用过工具之后每轮都带的 reasoning_content，发往 api.mistral.ai 时都会去掉。其他上游不受影响。
  • CC Switch 内部某个操作崩溃一次后，托盘菜单变空、切不了供应商，退出时也恢复不了直连，只能重启（#9472、#9483，见 #8058）：数据库、设置、配置文件写入、MCP、提示词、价格、备份等操作现在都能在崩溃后恢复，崩溃时没写完的改动会回滚。
  • 经 GitHub Copilot 用 Claude Code / Claude Desktop 时，Grok 这类在 Copilot 里只支持 Responses 接口的模型报「not accessible via the /chat/completions endpoint」（#6954、#9473）：这类模型现在改走 Responses 接口，两种接口都支持的模型不变。
  • Antigravity 选 Orchestrator 时，用量全部记在一个虚拟模型名下、费用为 0（#9493、#9494）：现在按每一步实际使用的模型计价，并新增 Gemini 4 Hydrogen 的价格。已导入的 Antigravity 历史会重新解析一次，补上费用。
  • 开启「统一 Codex 会话历史」或迁移历史后，几个月前的会话在 codex resume 里排到了最前面（#3866、#9471）：改写普通 .jsonl 会话文件时会保留原来的修改时间，压缩过的文件本来就会保留。已经被改乱的修改时间不会恢复。
  • 在 Hermes 里删掉的供应商，CC Switch 里删除按钮一直是灰的（#4816、#9470）：Hermes 里已经没有的供应商现在可以编辑和删除；读不到 Hermes 配置时仍然锁定。
  • 从预设新增 OpenClaw 供应商时，/model 里列的是预设自带的模型，不是表单里最后保存的（#9474，见 #6729）：在表单里删掉的模型不会再出现，新加的模型也能选；不改动预设直接保存时，会登记预设的全部模型。编辑已有供应商时还不会同步，#6729 仍在跟进。
  • 用 mise 安装的工具，「应用」页显示两条安装记录（mise 用 Homebrew 安装时其中一条标成 homebrew）（#9515）：mise 的 shim 现在算作它实际指向的那个安装。
  • 窗口较矮时，「打开终端」对话框的确认按钮被挤出屏幕，点不到（#9478）：对话框内容可以单独滚动，按钮固定在底部；在「附加参数（可选）」输入框里按回车也可以直接打开终端。
  • 用量页的汇率状态缺句号，和后面的说明连在一起（#9436）。
