MinerU 4.2.2-released

#MinerU マイネル-4.2.2-released

4.2.2

  • ローカル VLM エンジンの障害の伝播とライフサイクル管理を改善します。 LMDeploy、vLLM、llama.cpp、MLX の公衆衛生および無効化契約を統合します。エンジン障害を確認した後、キャッシュ インスタンスの再利用を停止し、グローバル障害が通常の識別障害とみなされることによるサイレント劣化を回避するように関連ホストに通知します。通常のシングルチップ認識が失敗した場合でも、既存のフォールバックが引き続き保持されます。
  • 解析サービスのヘルス チェックとタスク クリーニングを強化。ヘルスチェックをサポートするロードされたランタイムを定期的に検出します。一時的に利用できない場合は新しい推論を拒否し、正常な場合は再開します。エンジンの停止が確認されると、健全性と機能のインターフェイスは明確なエラーを返し、実行中のタスクとキューに入れられたタスクは既存の境界に従ってクリーンアップされ、回復はホストによって管理されます。シャットダウン時の転送中の検出、キャンセル、リソース解放の順序を改善します。
  • バッチ解析の入力およびエラー処理を修正。コンテンツの署名とコンテナーの識別を使用してファイルを検証し、Office ロック ファイルによって後続のドキュメントがブロックされるのを防ぎ、~$ で始まる名前の正当なドキュメントを保持します。明示的な破損、暗号化、リソース制限、入力不足、権限エラーは単一の失敗として記録され、続行されます。エンジン、サービス、または出力に障害が発生すると、後続の処理が停止します。概要では成功、スキップ、失敗、未処理の数がそれぞれ報告され、一部の失敗ではゼロ以外の終了コードが返されます。
  • バッチ出力パス判定を修正。ディレクトリおよび複数ファイルの入力では常にディレクトリ出力が使用され、ドキュメントが 1 つしかない場合でも同じセマンティクスが維持されます。既存または新規作成された results.v1、results.md、およびその他のドット付きディレクトリをサポートし、既存の通常のファイルへのバッチ結果の書き込みを拒否します。明示的な単一ファイル出力は、ターゲット ファイルの上書きを引き続きサポートします。
  • 読み取りとエクスポートに対する明確な責任。 mineru read の Markdown 出力は、プログレッシブ読み取り、標準出力、JSON および継続プロンプトの保持に使用されます。 --output PATHは写真のみに使用されます。リダイレクトまたは SDK を使用して現在のテキスト フラグメントを保存し、mineru parse ... -o ... を使用して指定されたページ範囲を完全にエクスポートして、完全な製品の読み取り予算によって制限されているフラグメントを間違えることを避けることができます。
  • サービスの起動と終了のエクスペリエンスを向上させます。サービスが正常に監視されると、直接アクセス可能な API ドキュメント アドレスが出力されます。通常の Ctrl+C 終了では、割り込みスタックが表示されなくなります。未実装の Webhook 機能宣言と対応するドキュメントを削除します。
  • ランタイムの依存関係を更新します。この公開ライフサイクル契約に従って、最小バージョンは mineru-llama-cpp 0.2.1 および mineru-vl-utils 2.0.9 に調整されています。

互換性に関するヒント。保存するには、元の mineru read <locator> -o part.md を stdout リダイレクトまたは SDK に変更する必要があります。完成品が必要な場合はmineru parse <path> --pages <range> -o result.mdをご使用ください。一括呼び出し元は、新しい結果の概要と終了コードに基づいて、完全な成功、部分的な失敗、全体的な中止を区別する必要があります。

4.2.2

  • ローカル VLM 障害の伝播とライフサイクル管理を改善します。 LMDeploy、vLLM、llama.cpp、および MLX の共有ヘルスおよび障害コントラクトを使用します。エンジン障害が確認されると、キャッシュされたインスタンスが無効になり、そのホストに通知され、グローバルな停止がサイレントにローカル認識フォールバックになるのを防ぎます。通常の作物ごとの失敗では、既存のフォールバック動作が維持されます。
  • 解析サーバーのヘルスチェックとタスクのクリーンアップを強化。ヘルスチェックをサポートする初期化されたランタイムを定期的に調査します。一時的に利用できなくなると、健全性が回復するまで新しい推論が拒否されます。エンジンの停止が確認されると、明示的な健全性と機能のエラーが発生し、既存のライフサイクル境界を通じて実行中のタスクとキューに入れられたタスクがクリーンアップされます。回復は依然としてホストの責任です。シャットダウン時のアクティブなプローブ、キャンセル、リソースの解放の順序を改善します。
  • バッチ入力検証とエラー処理を修正。 ~$ で始まる有効なドキュメントは引き続きサポートされながら、Office ロック ファイルによって後続のドキュメントが停止されないように、ファイル コンテンツの署名とコンテナーを検証します。既知の破損、暗号化、リソース制限、欠落、またはアクセス不能の入力を個別の失敗として報告し、続行します。エンジン、サービス、出力に障害が発生すると、バッチが停止します。概要は、成功した入力、スキップされた入力、失敗した入力、および未処理の入力を区別します。部分的に失敗すると、ゼロ以外の終了コードが返されます。
  • バッチ出力パスの処理を修正。ディレクトリおよび複数ファイルの入力では、ドキュメントが 1 つだけ残っている場合でも、常にディレクトリ出力が生成されます。 results.v1 や results.md などの既存および新規のドット付きディレクトリ名を受け入れ、既存の通常のファイルをバッチ宛先として拒否します。明示的な単一ファイル出力は、出力先の上書きを引き続きサポートします。
  • 読み取りとエクスポートを明確にします。 mineru read からのマークダウンは、継続ヒントを含むプログレッシブ stdout または JSON 読み取りのままです。 --output PATH は画像用に予約されています。リダイレクトまたは SDK を使用して現在のテキスト フラグメントを保存し、mineru parse ... -o ... を使用して、読み取り予算なしで完全なページ範囲をエクスポートします。
  • サービスの起動とシャットダウンを改善します。バインドが成功した後に直接アクセス可能な API ドキュメント URL を出力し、通常の Ctrl+C シャットダウン時の中断トレースバックを回避し、未実装の Webhook 機能宣言とドキュメントを削除します。
  • ランタイムの依存関係を更新します。共有ライフサイクル コントラクトには、mineru-llama-cpp 0.2.1 および mineru-vl-utils 2.0.9 以降の互換性のあるバージョンが必要です。

互換性に関する注意事項。 mineru read <locator> -o part.md を標準出力リダイレクトまたは SDK 保存に置き換えます。完全なエクスポートには、mineru parse <path> --pages <range> -o result.md を使用します。バッチ呼び出し元は、結果の概要と終了コードを解釈して、完全な成功、部分的な失敗、中止されたバッチを区別する必要があります。

MinerU mineru-4.2.2-released

Highlights

  • Failure containment for local VLM engines — Confirmed failures in LMDeploy, vLLM, llama.cpp, or MLX now invalidate cached engine instances and notify their hosts instead of being silently downgraded to recognition fallbacks. Ordinary per-crop failures still fall back, so batch behavior changes only for confirmed engine-level outages.

  • Health-aware parse serving — The server periodically probes supported runtimes, rejects new inference while temporarily unhealthy, and reports explicit health and capability errors after confirmed engine death. Running and queued tasks follow the existing cleanup boundaries; operators should treat host-managed recovery—not automatic engine resurrection—as part of restart handling.

  • More resilient batch input handling — Content-signature and container validation prevent Office lock files from blocking a batch while preserving valid documents whose names start with ~$. Corrupt, encrypted, inaccessible, missing, or resource-limited files become individual failures; engine, service, and output failures abort remaining work. Callers must inspect succeeded/skipped/failed/unprocessed counts, and a partial failure now exits nonzero.

  • Predictable batch output paths — Directory and multi-file inputs always request directory output, even when only one document remains. Dotted directory names such as results.v1 and results.md are accepted, but existing regular files are rejected as batch destinations; explicit single-file output still overwrites its target.

  • Breaking read/parse export contract — mineru read <locator> -o part.md no longer saves Markdown: --output is image-only. Use stdout redirection or the SDK to save the current budget-limited fragment, and use mineru parse <path> --pages <range> -o result.md for a complete export.

  • Runtime floors and capability cleanup — Upgrade pins must satisfy mineru-llama-cpp >= 0.2.1 and mineru-vl-utils >= 2.0.9 for the shared lifecycle contracts. Unimplemented webhook declarations and documentation were removed, so integrations should not rely on webhook support.

4.2.2

  • 完善本地 VLM 引擎的故障传播与生命周期管理。统一消费 LMDeploy、vLLM、llama.cpp 和 MLX 的公共健康与失效契约；确认引擎失效后停止复用缓存实例，并通知关联宿主，避免把全局故障当作普通识别失败而静默降级。普通单片识别失败仍保留既有回退。
  • 增强解析服务的健康检查与任务清理。周期探测已加载且支持健康检查的运行时；暂时不可用时拒绝新推理，恢复健康后重新开放。确认引擎死亡时，健康与能力接口返回明确错误，运行及排队任务按既有边界清理，恢复由宿主管理。完善关闭期间的在途探测、取消和资源释放顺序。
  • 修复批量解析的输入与错误处理。使用内容签名和容器识别验证文件，避免 Office 锁文件阻断后续文档，同时保留名称以 ~$ 开头的合法文档。明确的损坏、加密、资源限制、输入缺失及权限错误记录为单项失败并继续；引擎、服务或输出故障停止后续处理。摘要分别报告成功、跳过、失败和未处理数量，部分失败返回非零退出码。
  • 修复批量输出路径判断。目录和多文件输入始终采用目录输出，只有一个文档时也保持相同语义。支持已有或新建的 results.v1、results.md 等带点目录，拒绝将批量结果写入已有普通文件；显式单文件输出继续支持覆盖目标文件。
  • 明确阅读与导出的职责。mineru read 的 Markdown 输出用于渐进阅读，保留 stdout、JSON 和续读提示；--output PATH 仅用于图片。保存当前文本片段可使用重定向或 SDK，完整导出指定页范围使用 mineru parse ... -o ...，避免把受阅读预算限制的片段误当成完整产物。
  • 改善服务启动与退出体验。服务成功监听后打印可直接访问的 API 文档地址；正常 Ctrl+C 退出不再显示中断堆栈。移除未实现的 webhook 能力声明及对应文档。
  • 更新运行时依赖。最低版本调整为 mineru-llama-cpp 0.2.1 和 mineru-vl-utils 2.0.9，与本次公共生命周期契约保持一致。

兼容性提示。原有 mineru read <locator> -o part.md 需要改为 stdout 重定向或 SDK 保存；需要完整产物时使用 mineru parse <path> --pages <range> -o result.md。批量调用方应根据新的结果摘要和退出码区分完整成功、部分失败和全局中止。

4.2.2

  • Improve local VLM failure propagation and lifecycle management. Consume shared health and failure contracts for LMDeploy, vLLM, llama.cpp, and MLX. Confirmed engine failure invalidates cached instances and notifies their hosts, preventing a global outage from silently becoming a local recognition fallback. Ordinary per-crop failures retain the existing fallback behavior.
  • Strengthen parse-server health checks and task cleanup. Periodically probe initialized runtimes that support health checks. Temporary unavailability rejects new inference until health recovers. Confirmed engine death produces explicit health and capability errors and cleans up running and queued tasks through the existing lifecycle boundaries; recovery remains the host's responsibility. Improve the ordering of active probes, cancellation, and resource release during shutdown.
  • Correct batch input validation and error handling. Validate file content signatures and containers so Office lock files do not stop subsequent documents, while valid documents beginning with ~$ remain supported. Report known corrupt, encrypted, resource-limited, missing, or inaccessible inputs as individual failures and continue. Engine, service, and output failures stop the batch. Summaries distinguish succeeded, skipped, failed, and unprocessed inputs; partial failure returns a nonzero exit code.
  • Correct batch output-path handling. Directory and multiple-file inputs always produce directory output, even when only one document remains. Accept existing and new dotted directory names such as results.v1 and results.md, and reject existing regular files as batch destinations. Explicit single-file output continues to support overwriting its destination.
  • Clarify reading and exporting. Markdown from mineru read remains a progressive stdout or JSON read with continuation hints; --output PATH is reserved for images. Save the current text fragment through redirection or the SDK, and use mineru parse ... -o ... to export a complete page range without the reading budget.
  • Improve service startup and shutdown. Print directly accessible API documentation URLs after successful binding, avoid interrupt tracebacks on normal Ctrl+C shutdown, and remove unimplemented webhook capability declarations and documentation.
  • Update runtime dependencies. Require mineru-llama-cpp 0.2.1 and mineru-vl-utils 2.0.9 or newer compatible versions for the shared lifecycle contracts.

Compatibility note. Replace mineru read <locator> -o part.md with stdout redirection or SDK saving. For complete exports, use mineru parse <path> --pages <range> -o result.md. Batch callers should interpret the result summary and exit code to distinguish full success, partial failure, and an aborted batch.
