MinerU 4.2.1-released

#MinerU マイネル-4.2.1-released

4.2.1

  • Doclib の切り捨てと継続読み取りで欠落していたコンテンツを修正。 Markdown ドキュメントまたは単一ページが context=0 で読み取られると、長さ制限に達した後、next_request.locator および next_request.after まで現在のページの残りのコンテンツを読み取り続け、読み取り後に次のページを提案します。 CLI 継続マークと SDK ドキュメントが同時に更新されます。
  • ホスト型解決サービスの障害回復を改善します。連続起動または再起動失敗が上限に達した場合は自動再試行を停止し、残っているプロセスをクリーンアップします。ホスティング モードまたはギアをリセットし、ドキュメント ライブラリ サービスを再起動した後、回復を再度試みることができます。モード、ギアを切り替え、サービスを終了する際の古いプロセスと制御チャネルのリサイクルを改善します。
  • Windows ホスティング サービス ポート プローブを修正。サービスの実際のバインド動作に従ってポートを確認し、非厳密ポート モードでシステムによって占有または予約されているポートをスキップして、正常に検出された後に開始できない問題を軽減します。
  • ドキュメント ライブラリ サービスの正常な終了を改善。ライフサイクル クリーンアップはホスト シャットダウン コールバックを通じて実行され、Windows シャットダウン プロセスがバックグラウンド タスク、管理された解析プロセス、データベース リソースもリサイクルできるようになります。
  • 欠落していた Windows GPU メモリ情報を修正。 DXGI とハードウェア インベントリ間の PCI アドレスの一致を改善し、同じモデルのデバイス エントリに曖昧さがある場合でも一貫したビデオ メモリとデバイス属性を保持し、ハードウェア診断情報の整合性を向上します。
  • ネイティブ PDF で欠落しているテキストを修正。浮動小数点エラーにより 360 度に近い通常のテキスト方向を受け入れ、ネイティブ テキストがバックフィルされたときに横書きテキストが誤ってフィルタリングされるのを防ぎます。

統合のヒント。組み込み Doclib ホストは、インターフェースのクローズをサポートするために shutdown コールバックを設定する必要があり、コールバックが見つからない場合は service_unavailable を返します。標準の mineru server エントリには、このコールバックが構成されています。

4.2.1

  • 切り捨て後の完全な Doclib の継続。 context=0 を使用したマークダウン ドキュメントと単一ページの読み取りでは、next_request.locator と next_request.after の両方を使用して、出力制限に達した後に未完成のページを再開し、次のページを提案します。 CLI 継続マーカーと SDK ドキュメントは同じ契約に従います。
  • バインドされた管理対象解析サーバーの回復。起動または再起動の失敗が繰り返された場合は自動再試行を停止し、残りのプロセスをクリーンアップします。管理モードまたは管理層を再度設定するか、ドキュメント ライブラリ サーバーを再起動すると、回復を再開できます。モード変更、階層変更、シャットダウン時のプロセスと制御チャネルのクリーンアップを改善します。
  • Windows 管理対象ポートのプローブを修正。サーバーの実際のバインド動作と一致し、厳密ポート モードが無効になっている場合は占有ポートまたはシステム予約ポートをスキップし、ポート プローブが成功した後の起動エラーを減らします。
  • ドキュメント ライブラリの正常なシャットダウン。ホスト シャットダウン コールバックを使用して、Windows 上のバックグラウンド タスク、管理された解析プロセス、データベース リソースなどのライフサイクル クリーンアップを実行します。
  • Windows GPU メモリ情報を復元。 DXGI とハードウェア インベントリの間の PCI アドレスの一致を改善し、同じモデルのエントリがあいまいな ID を持つ場合でも一貫したメモリとデバイスのプロパティを保持します。
  • ネイティブの PDF 本文テキストを保持。浮動小数点エラーにより 360 度に近い通常のテキスト方向を受け入れ、ネイティブ テキストの復元中に横書きテキストがフィルタリングされるのを防ぎます。

統合に関するメモ。組み込み Doclib ホストは、シャットダウン エンドポイントをサポートするために shutdown コールバックを提供する必要があります。コールバックが見つからない場合は、service_unavailable が返されます。標準の mineru server エントリ ポイントはすでにコールバックを提供しています。

MinerU mineru-4.2.1-released

Highlights

  • Complete truncated reads — With context=0, markdown and single-page reads that hit the output limit now resume the remainder of the page using both next_request.locator and next_request.after, then suggest the next page, so clients stop losing tail content. CLI continuation markers and SDK docs now follow this contract — align any custom pagination logic accordingly.
  • Bounded parse-server recovery — Managed parsing servers now stop retrying after repeated start/restart failures and clean up leftover processes instead of looping indefinitely; recovery only resumes after re-setting the managed mode or tier, or restarting the document library server. Expect fewer leaked workers and a clear, operator-driven recovery path after a bad deploy.
  • Windows port probing and graceful shutdown — Port detection now mirrors the server's actual bind behavior and skips occupied or system-reserved ports unless strict-port mode is enabled, reducing "probe succeeded but start failed" cases. Shutdown also runs through a host callback so background tasks, managed parse processes, and database resources are released cleanly on Windows.
  • Shutdown callback required for embedded hosts — If you embed Doclib instead of using the standard mineru server entry point, you must supply a shutdown callback or the shutdown endpoint returns service_unavailable; the standard entry point already provides it, so this mainly affects custom hosts.
  • Windows GPU memory diagnostics restored — PCI-address matching between DXGI and the hardware inventory is tightened, and consistent memory/device properties are retained when same-model entries are ambiguous — relevant if you depend on hardware reporting for GPU selection or diagnostics.
  • Native PDF body text preserved — Text directions within floating-point tolerance of 360° are accepted as horizontal, so native text backfill no longer filters out legitimate body text that previously failed the direction check.

No breaking changes.

4.2.1

  • 修复 Doclib 截断续读遗漏内容。Markdown 文档或单页读取在 context=0 时，达到长度限制后通过 next_request.locator 与 next_request.after 继续读取当前页的剩余内容，读完后再建议下一页。CLI 续读标记和 SDK 文档同步更新。
  • 完善托管解析服务的故障恢复。连续启动或重启失败达到上限后停止自动重试，并清理残留进程。重新设置托管模式或档位、重启文档库服务后可再次尝试恢复。切换模式、档位及关闭服务时，完善旧进程和控制通道的回收。
  • 修复 Windows 托管服务端口探测。按照服务实际绑定行为检查端口，在非严格端口模式下跳过已占用或被系统保留的端口，减少探测成功后仍无法启动的问题。
  • 改善文档库服务的优雅退出。通过宿主停机回调执行生命周期清理，使 Windows 关闭流程也能回收后台任务、托管解析进程和数据库资源。
  • 修复 Windows GPU 显存信息缺失。完善 DXGI 与硬件库存的 PCI 地址匹配，在同型号设备条目存在歧义时保留一致的显存和设备属性，提高硬件诊断信息的完整性。
  • 修复原生 PDF 正文缺失。接受因浮点误差接近 360° 的正常文本方向，避免水平文字在原生文本回填时被错误过滤。

集成提示。嵌入式 Doclib 宿主需要设置 shutdown 回调以支持关闭接口，缺少回调时返回 service_unavailable。标准 mineru server 入口已配置该回调。

4.2.1

  • Complete Doclib continuation after truncation. Markdown document and single-page reads with context=0 use both next_request.locator and next_request.after to resume the unfinished page after reaching the output limit, then suggest the next page. CLI continuation markers and SDK documentation follow the same contract.
  • Bound managed parse-server recovery. Stop automatic retries after repeated startup or restart failures and clean up remaining processes. Setting the managed mode or tier again, or restarting the document library server, allows recovery to resume. Improve process and control-channel cleanup during mode changes, tier changes, and shutdown.
  • Correct Windows managed-port probing. Match the server's actual binding behavior and skip occupied or system-reserved ports when strict-port mode is disabled, reducing startup failures after a successful port probe.
  • Graceful document library shutdown. Use a host shutdown callback to run lifecycle cleanup, including background tasks, managed parsing processes, and database resources on Windows.
  • Restore Windows GPU memory information. Improve PCI-address matching between DXGI and the hardware inventory, and retain consistent memory and device properties when same-model entries have ambiguous identities.
  • Preserve native PDF body text. Accept normal text directions close to 360° due to floating-point error, preventing horizontal text from being filtered during native text restoration.

Integration note. Embedded Doclib hosts must provide a shutdown callback to support the shutdown endpoint. A missing callback returns service_unavailable. The standard mineru server entry point already provides the callback.
