重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

Java

Druid は Java 25 をサポートするようになりました。Java 21 は引き続きサポートされていますが、Java 25 にアップグレードすることをお勧めします。

Java 17 のサポートは終了しました。

#19304 #19336

歴史的な層のエイリアス

historicalTierAliases コーディネーターの動的構成を使用して、仮想層名を多数の実履歴層にマップできます。これにより、履歴層のグループに単一の識別子が作成されます。ロード/ドロップ ルールがエイリアスを参照すると、コーディネーターはエイリアスを実際の層に置き換えます。たとえば、履歴層 hot_1 および hot_2 をエイリアス hot にマップする場合、ルール {"hot": 2} はそれぞれの 2 つのレプリカを hot_1 および hot_2 にロードします。

#19204 #19667

リアルタイム セグメント モードのクエリ コンテキスト

realtimeSegmentsOnly クエリ コンテキスト パラメーターは非推奨になり、realtimeSegmentsMode に置き換えられました。

realtimeSegmentsMode を次のいずれかに設定できます。

  • include (デフォルト): リアルタイム セグメントを含むすべてのセグメントをクエリします。
  • exclude: クエリのリアルタイム セグメントをスキップします。
  • exclusive: リアルタイム セグメントのみをクエリします

これは、ブルー/グリーン デプロイメントなどを実行し、新しい履歴レプリカ自動スケーリング グループのみをクエリし、「ライブ」ノード (リアルタイムでも履歴でもない) には触れたくない場合に便利です。

#19486

セグメント メタデータ検索の高速化

druid.segment.timeline.fastIntervalSearch を true に設定すると、Druid が間隔ツリーに基づくインデックスを使用してメタデータをメモリに保存し、より迅速な識別と取得が可能になります。

この機能はデフォルトではオフになっています。

#19138 #19850

バックグラウンドでのファイルの取得

MSQ タスク エンジンは、ワーカーによるクラウド ストレージからの入力ファイルの非同期フェッチをサポートするようになりました。これにより、ダウンロードと処理が重複するため、一般に、多数のファイルを読み取る際のスループットが向上します。それ以外の場合、ワーカーは各ファイルを処理中にクラウド ストレージから直接ストリーミングします。

この機能はデフォルトでオンになっており、backgroundFetchExternalFiles 設定によって制御されます。

#19539

Dart のセグメントのプリフェッチ

Dart は、Dart がプリフェッチするセグメントの数を制御するランタイム プロパティ druid.msq.dart.worker.segmentLoadAheadCount をサポートするようになりました。ワーカーに対して 0 より大きい値を設定すると、この設定がワーカーのデフォルトの segmentLoadAheadCount 値になります。クエリに segmentLoadAheadCount クエリ コンテキスト パラメータが含まれている場合、クエリ コンテキストが優先されます。

#19559

Web コンソールでの SQL への変換の改善

Web コンソールは、ストリーミング スーパーバイザから SQL ベースの取り込みクエリへの変換をサポートするようになりました。これにより、ストリーミング タスクを 1 回限りのバッチ取り込みとして実行することが容易になります。

「クエリ」ビューの「...」メニューから「スーパーバイザを SQL に変換」オプションを選択します。既存のスーパーバイザから選択することも、新しいスーパーバイザに JSON を指定することもできます。

#19547

従来の ZSTD フレームを非推奨にする

Druid 38 は、レガシー v0.4-v0.7 ZSTD フレームからの読み取りをサポートする最後のメジャー Druid リリースになります。これらのフレームのサポートは、バッチ取り込みとストリーミング取り込みの両方について、将来のリリースで削除される予定です。

この非推奨の主な理由は、基礎となるライブラリ zstd-jni が、バージョン 1.5.7-13 以降のレガシー フレームのデコードを削除することです。

ストリーミング取り込み

スケーリングのクールダウン

ストリーミング タスク オートスケーラーのスケールアップおよびスケールダウンに対して、さまざまなクールダウン期間を構成できるようになりました。

#19286

スーパーバイザの再起動の改善

スーパーバイザは、すべての変更に対して再起動されなくなりました。変更の種類に応じて、次のいずれかが発生する可能性があります。

  • Druid は、再起動しなくても、更新された仕様を永続化します。
  • Druid はスーパーバイザを再起動しますが、実行中のタスクは影響を受けません。
  • Druid が再起動すると、スーパーバイザが再起動され、そのタスクが終了します。これは、この変更前のデフォルトの動作でした。

たとえば、スーパーバイザ仕様への表面的な変更によって再起動がトリガーされなくなりました。

#19700 #19720

さらに、仕様の変更を判断するアルゴリズムが改善されました。たとえば、自動スケーリングが有効になっている場合、ioConfig.taskCount を変更してもスーパーバイザの再起動はトリガーされません。

#19541

最新のオフセットと埋め戻し

Kafka および RabbitMQ の場合、スーパーバイザを最新のオフセットにリセットし、新しい境界付きバックフィル スーパーバイザを開始して、スキップされた範囲からデータを取り込むことができるようになりました。これは、アラート シナリオなど、最新のデータが最も重要な Druid クラスターを操作する場合に便利な機能です。

次の要件に注意してください。

  • スーパーバイザの useEarliestSequenceNumber プロパティは false である必要があります。
  • バックフィル スーパーバイザのタスクがメイン スーパーバイザのタスクと同時に書き込むことができるように、スーパーバイザ コンテキストでは useConcurrentLocks を true に設定する必要があります。
  • スーパーバイザは RUNNING 状態である必要があります。

このアクションを実行するには、POST /druid/indexer/v1/supervisor/{supervisorId}/resetToLatestAndBackfill または Web コンソールを使用します。

#19477

ストリーミング公開セグメントのプルーナブルシャード仕様

Kafka の取り込みでは、圧縮を待たずにクエリ時にブローカーがプルーニングしたセグメントをパブリッシュできるようになりました。 tuningConfig.streamingPartitionsSpec.partitionDimensions を低から中程度のカーディナリティ ディメンションのリストに設定します。各タスクの記録 ディメンションごとに観察される個別の値が、新しい dim_value_set シャード仕様にスタンプされます。宣言されたディメンションでフィルタリングするクエリは、値が一致しないセグメントをスキップします。

この機能はオプトインで Kafka のみであり、によって無効になります。 デフォルト。設定されていない場合、動作は変わりません。

dim_value_set はフォールバックのない新しいコア シャード仕様タイプであるため、前方互換性はありません。 streamingPartitionsSpec を有効にする前に、すべてのサービスをアップグレードしてください。 dim_value_set セグメントが公開されると、ダウングレードはサポートされなくなります 圧縮されるか、streamingPartitionsSpec が取り外されるまで。

streamingPartitionsSpecにmaxValuesPerDimension(オプション)を追加しました。

クエリを実行する

新しいクエリ レーン戦略

weighted クエリ レーンニング戦略は、しきい値 (セグメント数、間隔期間、データ経過時間、セグメント範囲) に違反した回数によってクエリにスコアを付け、異なる容量制限を持つ構成可能な段階的レーンにクエリを割り当てます。これにより、既存のバイナリ高/低戦略よりも微妙なレーン割り当てが可能になります。 重み付けされたクエリ レーニング戦略は、オプションのしきい値ごとのコストの重みをサポートします。

  • periodWeight
  • durationWeight
  • segmentCountWeight -segmentRangeWeight

これらのしきい値の重みのデフォルトは 1 です。

クラスター管理

diskNormalized バランサー戦略の改善

diskNormalized 戦略はより調整可能になりました。 utilizationThreshold 構成はより直観的に機能します。しきい値を増やすと戦略の「許容度」が高まり、しきい値を下げるとノードのディスク使用率が近くなります。

#19663

MiddleManager と Indexer が再起動される

MiddleManager と Indexer は、再起動後も有効または無効の状態を保持するようになりました。再起動後にサーバーが再び有効になるという以前の動作を希望する場合は、druid.worker.startAlwaysEnabled = true を設定します。

#19373

Kafka アイドル信号

Kafka のコストベースのオートスケーラーが改善されました。 poll-idle ratio は、処理能力に余裕があるかどうか、ポーリングに費やされた時間のみを反映しました。代わりに使用率を使用するようにオートスケーラーを構成できるようになりました。

1 - (avgProcessingRate / maxObservedRate)

自動スケーリングにこの新しい比率を使用するには、useUtilizationRatio を true に設定します。

Important features, changes, and deprecations

This section contains important information about new and existing features.

Java

Druid now supports Java 25. While Java 21 is still supported, we recommend you upgrade to Java 25.

Support for Java 17 has been dropped.

#19304 #19336

Historical tier aliases

You can map a virtual tier name to a number of real Historical tiers with the historicalTierAliases Coordinator dynamic configuration. This creates a single identifier for a group of Historical tiers. When a load/drop rule references the alias, the Coordinator replaces it with the actual tiers. For example, if you map the Historical tiers hot_1 and hot_2 to the alias hot, the rule {"hot": 2} loads 2 replicas of each onto hot_1 and hot_2.

#19204 #19667

Realtime segments mode query context

The realtimeSegmentsOnly query context parameter has been deprecated and replaced with realtimeSegmentsMode.

You can set realtimeSegmentsMode to one of the following:

  • include (default): query all segments, including realtime segments
  • exclude: skip realtime segments for the query
  • exclusive: query only realtime segments

This is useful when performing things like blue/green deployments and you only want to query new Historical replica autoscaling groups and not touch any "live" nodes (neither realtime nor historical).

#19486

Faster segment metadata search

You can set druid.segment.timeline.fastIntervalSearch to true so that Druid uses an index based on interval trees to store that metadata in memory for faster identification and retrieval.

This feature is off by default.

#19138 #19850

Fetching files in the background

The MSQ task engine now supports workers fetching input files from cloud storage asynchronously. This overlaps downloading with processing, which generally improves throughput when reading larger numbers of files. Otherwise, workers stream each file directly from cloud storage while processing it.

This feature is on by default and is controlled by the backgroundFetchExternalFiles setting.

#19539

Segment prefetching for Dart

Dart now supports the runtime property druid.msq.dart.worker.segmentLoadAheadCount, which controls the number of segments that Dart prefetches. If set greater than 0 for a worker, this setting becomes the default segmentLoadAheadCount value for the worker. If a query includes the segmentLoadAheadCount query context parameter, the query context takes precedence.

#19559

Improved Convert to SQL in web console

The web console now supports converting streaming supervisors to SQL-based ingestion queries. This makes it easier for you to run a streaming task as a one-time batch ingestion.

Select the Convert supervisor to SQL option from the ... menu in the Query view. You can select from existing supervisors or provide JSON for a new one.

#19547

Deprecate legacy ZSTD frames

Druid 38 will be the last major Druid release that supports reading from legacy v0.4-v0.7 ZSTD frames. Support will be removed for these frames in future releases for both batch and streaming ingestion.

The primary reason for this deprecation is that the underlying library zstd-jni removes decoding for legacy frames in version 1.5.7-13 onward.

#19286

Improved supervisor restarts

Supervisors no longer restart for all changes. Based on the type of change, one of the following can occur:

  • Druid persists the updated spec without a restart.
  • Druid restarts the supervisor, but running tasks aren't impacted.
  • Druid restarts the supervisor is restarted and its tasks are terminated, which was the default behavior before this change.

For example, cosmetic changes to a supervisor spec no longer trigger a restart.

#19700 #19720

Additionally, the algorithm for determining a change in the spec has been improved. For example, changes to ioConfig.taskCount don't trigger a supervisor restart if auto-scaling is enabled.

#19541

Latest offset and backfill

For Kafka and RabbitMQ, you can now reset a supervisor to the latest offset and start a new bounded backfill supervisor to ingest data from the skipped range. This is a useful feature for operating Druid clusters where the most recent data is the most important, like alerting scenarios.

Note the following requirements:

  • The supervisor's useEarliestSequenceNumber property must be false.
  • The supervisor context must have useConcurrentLocks set to true to allow the backfill supervisor's tasks to write concurrently with the main supervisor's tasks.
  • The supervisor must be in a RUNNING state.

Use POST /druid/indexer/v1/supervisor/{supervisorId}/resetToLatestAndBackfill or the web console to perform this action.

#19477

Prunable shard specs for streaming published segments

Kafka ingestion can now publish segments that the Broker prunes at query time without waiting for compaction. Set tuningConfig.streamingPartitionsSpec.partitionDimensions to a list of low-to-medium cardinality dimensions; each task records the distinct values it observes per dimension and stamps them onto a new dim_value_set shard spec. Queries that filter on a declared dimension then skip segments whose values can't match.

The feature is opt-in, Kafka-only, and disabled by default; when unset, behavior is unchanged.

dim_value_set is a new core shard spec type with no fallback, so it is not forward-compatible. Upgrade all services before enabling streamingPartitionsSpec. Once dim_value_set segments are published, downgrade is unsupported until they are compacted away or streamingPartitionsSpec is removed.

Added maxValuesPerDimension (optional) to streamingPartitionsSpec.

Querying

New query laning strategy

The weighted query laning strategy scores queries by how many thresholds they breach (segment count, interval duration, data age, segment range) and assigns them to configurable graduated lanes with different capacity limits, providing more nuanced lane assignment than the existing binary high/low strategy.

The weighted query laning strategy supports optional per-threshold cost weights:

  • periodWeight
  • durationWeight
  • segmentCountWeight
  • segmentRangeWeight

These threshold weights default to 1.

ZooKeeper-based task runner

The ZooKeeper-based RemoteTaskRunner (druid.indexer.runner.type=remote) has been removed. ZooKeeper-based segment announcement and discovery removed

If your configuration sets druid.serverview.type to anything other than http, startup now fails with a clear error message. Remove the property (or set it to http, which is the default) to proceed.

The following configuration properties are no longer recognized and should be removed from common.runtime.properties:

  • druid.announcer.segmentsPerNode
  • druid.announcer.maxBytesPerNode
  • druid.announcer.skipLoadSpec
  • druid.announcer.skipDimensionsAndMetrics
  • druid.announcer.skipSegmentAnnouncementOnZk
  • druid.zk.paths.announcementsPath
  • druid.zk.paths.liveSegmentsPath
  • druid.zk.paths.propertiesPath
  • druid.zk.paths.connectorPath

ZooKeeper is still used for leader election, service (node) announcement and discovery, and Overlord-to-MiddleManager task management.

#19377

Jackson update

If external code has both @JacksonInject and @JsonProperty on the same parameter and relies on the JSON value winning when supplied, add the explicit useInput = OptBoolean.TRUE to the annotation (or stay on Jackson 2.20.x). All such sites in Druid itself have been updated.
