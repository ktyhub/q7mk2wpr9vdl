druid 0.20.0

マイナー 公開日2020年10月17日 出典apache/druid English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ドルイドドルイド-0.20.0 Apache Druid 0.20.0 には、約 160 の新機能、バグ修正、パフォーマンス強化、ドキュメントの改善、および 36 人の寄稿者による追加のテスト カバレッジが含まれています。詳細については、変更の完全なリスト および マイルストーンにタグ付けされたすべて を参照してください。

<a name="20-new-features" href="#20-new-features">#</a> 新機能

<a name="20-ingestion" href="#20-ingestion">#</a> 取り込み

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> InputSource の結合

新しい結合InputSourceが追加され、ユーザーは取り込み中に複数の入力ソースを結合できるようになりました。詳細については、https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source を参照してください。 https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> 並列取り込みハッシュ パーティショニング用の numShards を自動的に決定します

ハッシュ パーティショニングが並列バッチ インジェストで使用される場合、パーティション仕様で numShards を指定する必要はなくなりました。 Druid は、パーティショニング キーのカーディナリティを決定する新しい取り込みフェーズでデータをスキャンすることにより、シャードの数を自動的に決定できるようになりました。 https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> 並列バッチ取り込みのサブタスク ファイル数制限

サイズベースの splitHintSpec は、並列バッチ取り込みで個々のサブタスクに割り当てられるファイルの数を制限する新しい maxNumFiles パラメーターをサポートするようになりました。 既存の Druid セグメントからデータを再取り込むために使用されるセグメントベースの splitHintSpec にも、同様に機能する新しい maxNumSegments パラメーターがあります。 詳細はhttps://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-specをご覧ください。 https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> タスク スロットの使用状況メトリック

新しいタスク スロットの使用状況メトリックが追加されました。詳細については、https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service で taskSlot メトリクスのエントリを参照してください。 https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> 圧縮

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> 自動圧縮のためのすべてのパーティション化スキームのサポート

自動圧縮用のパーティション仕様を定義できるようになり、ユーザーは圧縮時にデータを再パーティション化できるようになりました。詳細については、圧縮 tuningConfig の新しい partitionsSpec プロパティのドキュメントを参照してください。 https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> 自動圧縮ステータス API

データソースの自動圧縮のステータスを示す新しいコーディネーター API が追加されました。新しい API は、データソースに対して自動圧縮が有効になっているかどうか、および圧縮がどの程度進行したかの概要を示します。 Web コンソールも更新され、次の情報が表示されます。 https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png 新しい API の詳細については https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status を、関連する新しい圧縮メトリクスについては https://druid.apache.org/docs/latest/operations/metrics.html#coordination を参照してください。 https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> クエリ

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> ハッシュ パーティショニングを使用したクエリ セグメント プルーニング

Druid は、ハッシュ パーティション化されたセグメントのクエリ時セグメント プルーニング (クエリの読み取り候補として特定のセグメントを除外する) をサポートするようになりました。この最適化は、取り込み時にハッシュ パーティション仕様で指定されたすべての partitionDimensions がクエリのフィルター セットに存在し、クエリ内のフィルターが partitionDimensions の個別の値 (セレクター フィルターなど) に適用される場合に適用されます。ハッシュ パーティショニングを使用したセグメント プルーニングは、バインド フィルターなどの非離散フィルターではサポートされません。 既存のセグメントを持つ既存ユーザーの場合、この新機能を利用するにはそれらのセグメントを再取り込む必要があります。これは、セグメントのプルーニングでは、partitionFunction をセグメントと一緒に保存する必要がありますが、古いバージョンの Druid で作成されたセグメントには存在しません。デフォルトは Druid の以前のバージョンで使用されていたのと同じパーティション関数であるため、partitionFunction を明示的に指定する必要はありません。 デフォルトの partitionDimensions 値 (すべてのディメンション + 時間列によるパーティション) を使用して作成されたセグメントはこの方法ではプルーニングできないことに注意してください。セグメントは明示的な partitionDimensions を使用して作成する必要があります。 https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> ベクトル化

ベクトル化機能を有効にするには、druid.query.default.context.vectorizeVirtualColumns プロパティを true に設定するか、クエリ コンテキストで vectorize プロパティを設定してください。詳細については、https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters を参照してください。

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> 式仮想列のベクトル化サポート

式の仮想列にベクトル化がサポートされるようになりました (使用されている式に応じて)。これにより、場合によっては 3 ～ 5 倍のパフォーマンスが向上します。 ベクトル化をサポートする特定の式の詳細については、https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support を参照してください。 https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> アグリゲーターのベクトル化サポートの追加

ベクトル化サポートが、数値最小/最大アグリゲーター、分散アグリゲーター、ANY アグリゲーター、druid-histogram 拡張機能のアグリゲーターなど、いくつかの集計タイプに追加されました。 https://github.com/apache/druid/pull/10260 - 最小値/最大値の数値 https://github.com/apache/druid/pull/10304 - ヒストグラム https://github.com/apache/druid/pull/10338 - 任意 https://github.com/apache/druid/pull/10390 - 差異 min、max、および ANY アグリゲーターでベクトル化を有効にすると、場合によっては約 1.3 倍から 1.8 倍のパフォーマンスの向上が確認され、ヒストグラム アグリゲーターでは約 1.04 倍から 1.07 倍のパフォーマンスの向上が確認されました。

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> GroupBy クエリおよび Scan クエリの offset パラメータ

GroupBy クエリと Scan クエリに offset パラメータを設定できるようになりました。これにより、結果を返すときに多くの行をスキップするように Druid に指示します。詳細はhttps://druid.apache.org/docs/0.20.0/querying/limitspec.html、https://druid.apache.org/docs/0.20.0/querying/scan-query.htmlをご覧ください。 https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> SQL クエリの OFFSET 句

Druid SQL クエリで OFFSET 句がサポートされるようになりました。詳細はhttps://druid.apache.org/docs/0.20.0/querying/sql.html#offsetをご覧ください。 https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> 部分文字列検索演算子

Druid は、式言語と SQL クエリに新しい部分文字列検索演算子を追加しました。 Druid SQL の CONTAINS_STRING および ICONTAINS_STRING 文字列関数のドキュメント (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions)、および Druid 式言語の contains_string および icontains_string のドキュメント (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions) を参照してください。 STRPOS の代わりにこれらの関数を使用することにより、場合によっては約 2.5 倍のパフォーマンスの向上が確認されました。 https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> SQL クエリの UNION ALL 演算子

Druid SQL クエリは、複数のクエリの結果を結合する UNION ALL 演算子をサポートするようになりました。この演算子でサポートされるクエリ形状の詳細については、https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all を参照してください。 https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> クラスター全体のデフォルトのクエリ コンテキスト設定

druid.query.override.default.context.* (* をプロパティ名で置き換えた) 形式の構成を追加することで、クラスター全体のデフォルトのクエリ コンテキスト プロパティを設定できるようになりました。 https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> その他の機能

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> 改善された保持ルール UI

Web コンソールの保持ルール UI が改善されました。期間ドロップダウンで提案と基本的な検証が提供され、クラスターのデフォルト ルールが表示され、デフォルト ルールの編集がよりアクセスしやすくなりました。 https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Redis キャッシュ拡張機能の強化

Redis キャッシュ拡張機能は、Redis クラスター、使用するデータベースの選択、パスワードで保護されたサーバーへの接続、および expiration および timeout プロパティのピリオド形式の構成をサポートするようになりました。 https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> 応答ヘッダーの送信サーバー バージョンを無効にする

Druid の応答ヘッダーでサーバーのバージョン情報の送信を無効にできるようになりました。 これは、新しいプロパティ druid.server.http.sendServerVersion によって制御されます。デフォルトは true です。 https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> バイトベースの構成プロパティを単位で指定する

Druid は、バイトベースの構成プロパティを指定するための単位をサポートするようになりました。例:

druid.server.maxSize=300g

と同等

druid.server.maxSize=300000000000

詳細はhttps://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.htmlをご覧ください。 https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> バグ修正

<a name="20-query-correctness" href="#20-query-correctness">#</a> 履歴にセグメント タイムラインがない場合のクエリの正確性の問題を修正

Druid 0.20.0 は、ブローカーがヒストリカルにデータソースの特定のセグメントがあることを期待してクエリを発行するが、クエリ時のヒストリカルには実際にはそのデータソースのセグメントがありません (たとえば、ヒストリカルがクエリを処理する前にセグメントがすべてアンロードされている) 場合のクエリの正確性の問題を修正します。 0.20.0 より前では、クエリは正常に返されますが、前述の方法で欠落しているセグメントからの結果は返されませんでした。 0.20.0 では、このような状況ではクエリが失敗するようになりました。 https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> 結果レベルのキャッシュにデータが入力されない問題を修正

Druid 0.20.0 は、0.19.0 (https://github.com/apache/druid/issues/10337) で導入された、結果レベルのキャッシュが有効になっているときにクエリ キャッシュが生成されなくなる可能性がある問題を修正します。 https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> 分散アグリゲーターの順序付けを修正しました

以前、分散アグリゲーターは、分散の代わりにアグリゲーターの内部 count 変数を使用して比較する誤ったコンパレーターを使用していました。 https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> 制限仕様を使用した groupBy クエリの誤ったキャッシュを修正しました

Druid 0.20.0 は、クエリの limitSpec がキャッシュ キーで考慮されず、limitSpec を除いて同一のクエリが発行された場合に不正確な結果が生じる可能性がある、groupBy クエリとキャッシュの問題を修正します。 https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> ロールアップが有効な場合の stringFirst および stringLast の修正

https://github.com/apache/druid/issues/7243 が解決され、stringFirst および stringLast アグリゲーターは、ロールアップが有効な状態で取り込み中に使用された場合に例外を引き起こさなくなりました。 https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Druid 0.20.0 へのアップグレード

0.19.0 から 0.20.0 にアップグレードする場合は、次の考慮事項に注意してください。 0.19.0 よりも前のバージョンから更新する場合は、関連する中間バージョンの release note を参照してください。

<a name="20-default-max-size" href="#20-default-max-size">#</a> デフォルト maxSize

druid.server.maxSize のデフォルトは、druid.segmentCache.locations 内で定義された maxSize 値の合計になります。ユーザーは引き続き、デフォルト値よりも優先される druid.server.maxSize のカスタム値を指定できます。 https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> 圧縮および強制終了タスク ID の変更

コーディネーターによって発行された圧縮および強制終了タスクには、タスク ID の先頭に coordinator-issued が付けられるようになり、ユーザー発行の強制終了タスクには先頭に api-issued が付きます。 https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> 並列取り込みの分割ヒント仕様の新しいサイズ制限

並列バッチ取り込み用のサイズベースおよびセグメントベースの splitHintSpec では、サブタスクあたり 1000 というデフォルトのファイル/セグメント制限が適用され、それぞれ maxNumFiles および maxNumSegments によって制御されます。 https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> 新しい PostAggregator および AggregatorFactory メソッド

これら 2 つのインターフェイスには 0.20.0 で定義された新しいメソッドがあるため、カスタム PostAggregator または AggregatorFactory 実装を使用して拡張機能を開発したユーザーは、拡張機能を更新する必要があります。 PostAggregator には新しいメソッドが追加されました。

  ValueType getType();

PostAggregator の型情報をサポートするために、AggregatorFactory には 2 つの新しいメソッドもあります。

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

インターフェイスの変更の詳細については、https://github.com/apache/druid/pull/9638 を参照してください。

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> 新しい Expr 関連のメソッド

Expr および関連インターフェイスが 0.20.0 で変更されたため、カスタム Expr 実装を使用して拡張機能を開発したユーザーは、拡張機能を更新する必要があります。詳細は以下のPRをご覧ください。 https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> より正確な query/cpu/time メトリクス

0.20.0 では、query/cpu/time メトリックの精度が向上しました。以前は、クエリ処理中の作業の特定の部分が考慮されていませんでした。詳細については、次の PR で説明します。 https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> 新しい監査ログ サービスのメトリック列

監査ログを使用している場合は、監査ログ サービス メトリック (comment、remote_address、および created_date) に新しい列が追加されていることに注意してください。オプションの payload 列も追加されました。これは、druid.audit.manager.includePayloadAsDimensionInMetric から true に設定することで有効にできます。 https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> リクエスト ログ内の sqlQueryContext

クエリ リクエスト ログを使用している場合、リクエスト ログ イベントには SQL クエリの sqlQueryContext が含まれるようになります。 https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> メタデータ ストア内の追加のセグメントごとの状態

Druid 0.20.0 によって作成されたハッシュ パーティション化されたセグメントには、メタデータ ストアに追加の partitionFunction データが含まれるようになります。 さらに、圧縮タスクは、圧縮履歴の追跡に使用される追加のセグメントごとの情報をメタデータ ストアに保存するようになりました。 https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> 既知の問題

<a name="20-location-strat" href="#20-location-strat">#</a> druid.segmentCache.locationSelectorStrategy 注入の失敗

druid.segmentCache.locationSelectorStrategy の値を指定すると、注入エラーによるサービスの開始が防止されます。詳細はhttps://github.com/apache/druid/issues/10348をご覧ください。

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Web コンソール データ サンプラーでのリソース リーク

Web コンソールでデータをサンプリング中にタイムアウトが発生すると、入力ソースから読み取るために作成された内部リソースが適切に閉じられません。詳細については、https://github.com/apache/druid/pull/10467 を参照してください。

druid druid-0.20.0

Apache Druid 0.20.0 contains around 160 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 36 contributors. Refer to the complete list of changes and everything tagged to the milestone for further details.

<a name="20-new-features" href="#20-new-features">#</a> New Features

<a name="20-ingestion" href="#20-ingestion">#</a> Ingestion

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> Combining InputSource

A new combining InputSource has been added, allowing the user to combine multiple input sources during ingestion. Please see https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source for more details.

https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Automatically determine numShards for parallel ingestion hash partitioning

When hash partitioning is used in parallel batch ingestion, it is no longer necessary to specify numShards in the partition spec. Druid can now automatically determine a number of shards by scanning the data in a new ingestion phase that determines the cardinalities of the partitioning key.

https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Subtask file count limits for parallel batch ingestion

The size-based splitHintSpec now supports a new maxNumFiles parameter, which limits how many files can be assigned to individual subtasks in parallel batch ingestion.

The segment-based splitHintSpec used for reingesting data from existing Druid segments also has a new maxNumSegments parameter which functions similarly.

Please see https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec for more details.

https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Task slot usage metrics

New task slot usage metrics have been added. Please see the entries for the taskSlot metrics at https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service for more details.

https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Compaction

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Support for all partitioning schemes for auto-compaction

A partitioning spec can now be defined for auto-compaction, allowing users to repartition their data at compaction time. Please see the documentation for the new partitionsSpec property in the compaction tuningConfig for more details:

https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig

https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> Auto-compaction status API

A new coordinator API which shows the status of auto-compaction for a datasource has been added. The new API shows whether auto-compaction is enabled for a datasource, and a summary of how far compaction has progressed.

The web console has also been updated to show this information:

https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png

Please see https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status for details on the new API, and https://druid.apache.org/docs/latest/operations/metrics.html#coordination for information on new related compaction metrics.

https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Querying

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Query segment pruning with hash partitioning

Druid now supports query-time segment pruning (excluding certain segments as read candidates for a query) for hash partitioned segments. This optimization applies when all of the partitionDimensions specified in the hash partition spec during ingestion time are present in the filter set of a query, and the filters in the query filter on discrete values of the partitionDimensions (e.g., selector filters). Segment pruning with hash partitioning is not supported with non-discrete filters such as bound filters.

For existing users with existing segments, you will need to reingest those segments to take advantage of this new feature, as the segment pruning requires a partitionFunction to be stored together with the segments, which does not exist in segments created by older versions of Druid. It is not necessary to specify the partitionFunction explicitly, as the default is the same partition function that was used in prior versions of Druid.

Note that segments created with a default partitionDimensions value (partition by all dimensions + the time column) cannot be pruned in this manner, the segments need to be created with an explicit partitionDimensions.

https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vectorization

To enable vectorization features, please set the druid.query.default.context.vectorizeVirtualColumns property to true or set the vectorize property in the query context. Please see https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters for more information.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Vectorization support for expression virtual columns

Expression virtual columns now have vectorization support (depending on the expressions being used), which an results in a 3-5x performance improvement in some cases.

Please see https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support for details on the specific expressions that support vectorization.

https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> More vectorization support for aggregators

Vectorization support has been added for several aggregation types: numeric min/max aggregators, variance aggregators, ANY aggregators, and aggregators from the druid-histogram extension.

https://github.com/apache/druid/pull/10260 - numeric min/max https://github.com/apache/druid/pull/10304 - histogram https://github.com/apache/druid/pull/10338 - ANY https://github.com/apache/druid/pull/10390 - variance

We've observed about a 1.3x to 1.8x performance improvement in some cases with vectorization enabled for the min, max, and ANY aggregator, and about 1.04x to 1.07x wuth the histogram aggregator.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> offset parameter for GroupBy and Scan queries

It is now possible set an offset parameter for GroupBy and Scan queries, which tells Druid to skip a number of rows when returning results. Please see https://druid.apache.org/docs/0.20.0/querying/limitspec.html and https://druid.apache.org/docs/0.20.0/querying/scan-query.html for details.

https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> OFFSET clause for SQL queries

Druid SQL queries now support an OFFSET clause. Please see https://druid.apache.org/docs/0.20.0/querying/sql.html#offset for details.

https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Substring search operators

Druid has added new substring search operators in its expression language and for SQL queries.

Please see documentation for CONTAINS_STRING and ICONTAINS_STRING string functions for Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) and documentation for contains_string and icontains_string for the Druid expression language (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions).

We've observed about a 2.5x performance improvement in some cases by using these functions instead of STRPOS.

https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> UNION ALL operator for SQL queries

Druid SQL queries now support the UNION ALL operator, which fuses the results of multiple queries together. Please see https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all for details on what query shapes are supported by this operator.

https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Cluster-wide default query context settings

It is now possible to set cluster-wide default query context properties by adding a configuration of the form druid.query.override.default.context.*, with * replaced by the property name.

https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Other features

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> Improved retention rules UI

The retention rules UI in the web console has been improved. It now provides suggestions and basic validation in the period dropdown, shows the cluster default rules, and makes editing the default rules more accessible.

https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Redis cache extension enhancements

The Redis cache extension now supports Redis Cluster, selecting which database is used, connecting to password-protected servers, and period-style configurations for the expiration and timeout properties.

https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Disable sending server version in response headers

It is now possible to disable sending of server version information in Druid's response headers.

This is controlled by a new property druid.server.http.sendServerVersion, which defaults to true.

https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Specify byte-based configuration properties with units

Druid now supports units for specifying byte-based configuration properties, e.g.:

druid.server.maxSize=300g

equivalent to

druid.server.maxSize=300000000000

Please see https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html for more details.

https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Bug fixes

<a name="20-query-correctness" href="#20-query-correctness">#</a> Fix query correctness issue when historical has no segment timeline

Druid 0.20.0 fixes a query correctness issue when a broker issues a query expecting a historical to have certain segments for a datasource, but the historical when queried does not actually have any segments for that datasource (e.g., they were all unloaded before the historical processed the query). Prior to 0.20.0, the query would return successfully but without the results from the segments that were missing in the manner described previously. In 0.20.0, queries will now fail in such situations.

https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Fix issue preventing result-level cache from being populated

Druid 0.20.0 fixes an issue introduced in 0.19.0 (https://github.com/apache/druid/issues/10337) which can prevent query caches from being populated when result-level caching is enabled.

https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Fix for variance aggregator ordering

The variance aggregator previously used an incorrect comparator that compared using an aggregator's internal count variable instead of the variance.

https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Fix incorrect caching for groupBy queries with limit specs

Druid 0.20.0 fixes an issues with groupBy queries and caching, where the limitSpec of the query was not considered in the cache key, leading to potentially incorrect results if queries that are identical except for the limitSpec are issued.

https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Fix for stringFirst and stringLast with rollup enabled

https://github.com/apache/druid/issues/7243 has been resolved, the stringFirst and stringLast aggregators no longer cause an exception when used during ingestion with rollup enabled.

https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Upgrading to Druid 0.20.0

Please be aware of the following considerations when upgrading from 0.19.0 to 0.20.0. If you're updating from an earlier version than 0.19.0, please see the release notes of the relevant intermediate versions.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Default maxSize

druid.server.maxSize will now default to the sum of maxSize values defined within the druid.segmentCache.locations. The user can still provide a custom value for druid.server.maxSize which will take precedence over the default value.

https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Compaction and kill task ID changes

Compaction and kill tasks issued by the coordinator will now have their task IDs prefixed by coordinator-issued, while user-issued kill tasks will be prefixed by api-issued.

https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> New size limits for parallel ingestion split hint specs

The size-based and segment-based splitHintSpec for parallel batch ingestion now apply a default file/segment limit of 1000 per subtask, controlled by the maxNumFiles and maxNumSegments respectively.

https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> New PostAggregator and AggregatorFactory methods

Users who have developed an extension with custom PostAggregator or AggregatorFactory implementions will need to update their extensions, as these two interfaces have new methods defined in 0.20.0.

PostAggregator now has a new method:

  ValueType getType();

To support type information on PostAggregator, AggregatorFactory also has 2 new methods:

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Please see https://github.com/apache/druid/pull/9638 for more details on the interface changes.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> New Expr-related methods

Users who have developed an extension with custom Expr implementions will need to update their extensions, as Expr and related interfaces hae changed in 0.20.0. Please see the PR below for details:

https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> More accurate query/cpu/time metric

In 0.20.0, the accuracy of the query/cpu/time metric has been improved. Previously, it did not account for certain portions of work during query processing, described in more detail in the following PR:

https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> New audit log service metric columns

If you are using audit logging, please be aware that new columns have been added to the audit log service metric (comment, remote_address, and created_date). An optional payload column has also been added, which can be enabled by setting druid.audit.manager.includePayloadAsDimensionInMetric to true.

https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext in request logs

If you are using query request logging, the request log events will now include the sqlQueryContext for SQL queries.

https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> Additional per-segment state in metadata store

Hash-partitioned segments created by Druid 0.20.0 will now have additional partitionFunction data in the metadata store.

Additionally, compaction tasks will now store additional per-segment information in the metadata store, used for tracking compaction history.

https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Known issues

<a name="20-location-strat" href="#20-location-strat">#</a> druid.segmentCache.locationSelectorStrategy injection failure

Specifying a value for druid.segmentCache.locationSelectorStrategy prevents services from starting due to an injection error. Please see https://github.com/apache/druid/issues/10348 for more details.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Resource leak in web console data sampler

When a timeout occurs while sampling data in the web console, internal resources created to read from the input source are not properly closed. Please see https://github.com/apache/druid/pull/10467 for more information.
