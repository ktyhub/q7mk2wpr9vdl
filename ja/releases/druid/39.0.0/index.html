重要な機能、変更、非推奨

このセクションには、新機能と既存の機能に関する重要な情報が含まれています。

Java

Java 21 のサポートは終了しました。 Java 25 にアップグレードする必要があります。

カタログの DDL ステートメント (実験的)

Druid は、カタログ内のメタデータを管理するための CREATE ステートメントと ALTER ステートメントをサポートするようになりました。これらを各取り込み仕様で設定するのではなく、テーブルの列、時間分割、クラスタリング、集計投影、および物理レイアウトを宣言するために使用します。 この機能はデフォルトではオフになっています。有効にするには、druid.sql.planner.enableCatalogDdl を true に設定します。 詳細は【カタログ】(https://druid.apache.org/docs/39.0.0/development/extensions-core/catalog)をご覧ください。 #19830 #20377 #20452 #19770 #19711

Kafka ヘッダーベースのフィルタリング

Kafka スーパーバイザーはヘッダーでレコードをフィルターできるようになりました。これにより、トピックのレコードの一部のみが必要な場合に、取り込みの CPU とメモリの使用量が削減されます。 フィルタを使用するには、スーパーバイザの ioConfig に headerBasedFilterConfig を追加します。 in フィルターを使用します。ここで、dimension はヘッダー名、values は取り込むヘッダー値のリストです。ヘッダー値がリストにないレコードは削除されますが、オフセットは引き続き進みます。 フィルタリングは寛容です。ヘッダーがない場合、ヘッダー値が null、空、デコードできない場合、または評価が失敗した場合、レコードは取り込まれます。 新しい ingest/events/filtered メトリックは、ヘッダー フィルターによってドロップされたレコードの数を報告します。 #18525

型指定されたクエリ コンテキスト パラメータ

クエリ コンテキスト リファレンス および スキャン クエリ にリストされている共通のクエリ コンテキスト パラメーターは、型指定された QueryContextParameter 記述子になりました。次の変更は、クエリ コンテキストの処理に適用されます。

  • 整数パラメータと長整数パラメータは、切り捨てたりラップしたりする代わりに、正確な整数ではない値を拒否します。たとえば、1.5、および範囲外の値です。 5.0 や "5.0" のような整数値は引き続き受け入れられます。無効な値は失敗し、「クエリ コンテキスト パラメータ [x] は ... である必要があります。」というエラー メッセージが表示されるようになりました。
  • クエリ コンテキスト内の null または SET x = NULL は、druid.query.default.context またはブローカーの動的構成で構成されたデフォルトをクリアしなくなりました。デフォルトは、キーが設定されていない場合と同様に適用されます。以前は、組み込みのデフォルトを使用するリーダーに null が到達していました。構成されたデフォルトをオーバーライドするには、明示的な値を設定します。
  • maxSubqueryBytes は、サブクエリ ガードレールと同様に、自動、無効、または負でないバイト数を受け入れる型付き文字列パラメータです。 SET maxSubqueryBytes = TRUE などの無効な値は検証中に失敗し、1e9 などの数値が受け入れられるようになりました。 #20555

Druid JDBC ドライバー

Druid は、/druid/v2/sql/ エンドポイントを使用する独自の JDBC ドライバーを提供するようになりました。 Avatica ドライバーからこのドライバーに切り替えることをお勧めします。新しいドライバーには、スティッキーな負荷分散を必要としないドライバー側の接続管理、結果のストリーミング、SET ステートメントのサポート、および非ネイティブ SQL エンジンのサポートという利点があります。 #19951

Netty 4.2

Druid は現在、HTTP client に Netty 4.2 を使用しています。以前、Druid は Netty 3 を使用していました。これはメモリ特性の大幅な変更です。

  • ダイレクト メモリ: HTTP client は、ダイレクト メモリを消費するようになりました。 -XX:MaxDirectMemorySize の予算に近い事業者は、予算を増やす必要があるかもしれません。
  • プールされたバッファ: バッファがプールされるようになったため、アイドル状態であっても常駐メモリが Netty 3 よりも多く表示される場合があります。これは、プールされたアロケータでは正常です。 HTTP client の動作を制御する新しい構成 (druid.global.http.connectTimeout、druid.global.http.allocator、druid.broker.http.connectTimeout、および druid.broker.http.allocator) があります。一部の Netty 構成を直接設定することもできます。 #19567

コーディネーターのサービス品質フィルタリング

コーディネーターの QoS フィルタリングを有効にして、低速 API 要求のバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぐことができるようになりました。 この機能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))) を構成するには、druid.coordinator.server.maxConcurrentRequests を使用します。オフにするには、このプロパティを 0 に設定します。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサー/モニターは影響を受けません。 #19271

機能領域と関連する変更

このセクションには、領域ごとに分かれた release note の詳細が含まれています。

摂取

  • regex 入力形式の RE2/J 正規表現のサポートを追加しました #19514
  • AWS 推奨の標準再試行ポリシーを使用するように S3 client を変更しました。 druid.s3.retryMode および druid.s3.maxAttempts #19892 を使用して再試行戦略をカスタマイズできます。
  • Protobuf の取り込みでは、オプションとしてマークされていない proto3 フィールドのデフォルト値が保持されるようになりました。以前は、0 を保持する int32 フィールド (または "" を保持する文字列、false を保持する bool、最初の値を保持する enum) は null として取り込まれていました。このようなフィールドは実際の値として取り込まれるようになりました。 #20485

SQL ベースの取り込み

  • ワーカーは、ワーカー コンテキスト全体ではなく、必要なワーカー コンテキストのみをタスク コンテキストに渡すようになりました。 #20650

ストリーミング取り込み

選択したパーティションからの取り込み

Kafka スーパーバイザーは ioConfig.partitionIds を受け入れるようになりました。これにより、トピックの選択されたパーティションのみを取り込むことができます。たとえば、これを独立した診断の取り込みに使用できます。 #20474

コストベースのオートスケーラーの改善
  • Kafka のコストベースのオートスケーラーをシミュレートして、さまざまな量のラグに対する最適なタスク数を決定できるようになりました。 #19687
  • コストベースのオートスケーラーのクリティカルラグしきい値を設定できるようになりました。ラグがしきい値の 75% に達すると、オートスケーラーはスケールアップ境界をバイパスします。ラグが 100% に達すると、オートスケーラーは最大タスク数までスケールアップします。 #19655
  • スーパーバイザのコストベースのオートスケーラーのクールダウンを次の 2 つの方法のいずれかで設定できるようになりました。
    • 高感度: minScaleUpDelay / minScaleDownDelay < taskDuration を設定します。たとえば、minScaleUpDelay = taskDuration / 2 の場合、2 つのタスク ロールオーバー間には最大 1 つのスケーリング イベントが発生します。
    • 低感度 : minScaleUpDelay / minScaleDownDelay > taskDuration を設定します。この場合、クールダウンは事実上無視され、スケーリングはタスクのロールオーバー時にのみ発生します。 #20706
  • コストベースのオートスケーラーは、コストベースのオートスケーラーの決定を行うために、タスク メトリックの瞬間値ではなく移動平均を使用するようになりました。これにより、よりスムーズなスケーリングが可能になりますが、タスクのライフサイクルの終わりに向かって発生するメトリクスの傾向の変化に対する応答がわずかに遅れるという代償が生じる場合があります。トレンドの変化に対する感度を高めるには、minScaleUpDelay および minScaleDownDelay を taskDuration よりも小さく設定します。
その他のストリーミング取り込みの改善
  • Kafka インデックス作成タスクが、サンプルが実際に利用可能になる前に 1.0 (つまり、完全なアイドル状態) のポーリング アイドル率を報告するバグを修正しました。これにより、タスク全体にわたるスーパーバイザー オートスケーラーの平均アイドル率が歪む可能性がありました。 #20783

クエリを実行する

クエリの計画時間

新しい druid.sql.planner.maxPlanningTimeMs ランタイム プロパティを使用して、ブローカーが SQL クエリの計画に費やす時間を制限できるようになりました。 maxPlanningTimeMs クエリ コンテキスト パラメーターを使用してクエリごとに設定することもできます。計画が構成された予算を超えると、ブローカー スレッドが拘束されるのではなく、クエリは HTTP 504 クエリ タイムアウト エラーで失敗します。デフォルト値は 0 で、タイムアウトが無効になります。 #20314

クエリ応答トレーラーによって引き起こされる JDK HTTP client エラーを修正しました

ブローカーとヒストリカルは、リクエストに TE: trailers ヘッダーが含まれている場合にのみ、X-Druid-Response-Complete および X-Error-Message HTTP トレーラーを送信するようになりました。 Cliこれらのトレーラーを読み取るエントは、そのヘッダーを送信する必要があります。これにより、JDK 17.0.21、21.0.13、および 25.0.5 上の Druid JDBC ドライバーを含む java.net.http.HttpClient-based client のクエリ エラー (java.net.ProtocolException: CR expected) が修正されます。 #20717

その他のクエリの改善

  • Dart を使用して、sys スキーマ #19952 などのメタデータ テーブルをクエリできるようになりました。
  • CAST(x AS LONG) が Druid SQL で CAST(x AS BIGINT) のエイリアスとして受け入れられるようになりました #20402
  • datasource フィルター プッシュダウンを sys.segments テーブルに追加 #19718
  • FIRST_VALUE および LAST_VALUE ウィンドウ関数にフレーミング サポートを追加しました #19301
  • 降順で実行される timeseries、timeBoundary、スキャン クエリのパフォーマンスが向上しました #19947
  • COALESCE #18400のパフォーマンスを改善しました
  • 耐久ストレージと MSQ エクスポートを使用した MSQ タスクの S3 API の使用効率が向上 #19893
  • カタログタイプの検証とネイティブタイプ文字列の解析が改善されました #19769
  • Calcite 1.42.0 #19976 #19370 にアップグレード

クラスター管理

Kubernetes ノード ラベル

druid-kubernetes-extensions 拡張機能は、Druid プロセスが実行される Kubernetes ノードのラベルから構成値を解決する k8sNodeLabel 動的構成プロバイダーをサポートするようになりました。 #20404

Peon ポッド テンプレート

新しい GET /druid/indexer/v1/k8s/taskrunner/podTemplates エンドポイントを使用して、Overlord で現在構成されている Peon ポッド テンプレート名を取得できるようになりました。構成された各テンプレートの名前を返します。エンドポイントには CONFIG 読み取り権限が必要で、オーバーロードがカスタム テンプレート ポッド アダプターを使用していない場合は 404 を返します。 #19712

環境変数

environment 動的構成プロバイダーは、NullPointerException を持つ Kafka スーパーバイザーなどのコンシューマーを失敗させる null 値を生成するのではなく、環境内に設定されていない変数を省略するようになりました。スキップされた変数は情報レベルで記録されます。 #20381

接続プール

druid.global.http.poolImplementation を使用して、Druid 接続プールが接続要求を追跡する方法を構成できるようになりました。 デフォルトはretainingです。 retaining を使用すると、プールは開いたすべての接続を保持し、古い接続や壊れた接続を新しい接続に置き換えるので、プールは最高水準点に留まります。 #20542 #20273

HTTP 応答ヘッダー

Druid はオプションで HTTP 応答で X-Druid-Server、X-Druid-Service、X-Druid-Version を返すことができるようになり、オペレーターは直接リクエストまたはルータープロキシリクエストを処理したプロセスとバージョンを識別できるようになります。これらのヘッダーはクラスターのトポロジとバージョン情報を公開するため、すべての client が受信を許可されている場合にのみ有効にします。それらを有効にするには、druid.server.http.enableResponseIdentityHeaders を true に設定します。 #20268

LDAP サポートの改善

memberOf 属性を返さないサーバー (OpenLDAP など) での LDAP グループベースの承認のサポートが追加されました。 LDAP 資格情報バリデーターで groupBaseDn および groupSearch を構成して、グループ メンバーシップを自動的に解決するグループ逆引き参照を有効にします。 #19432

テーブルの可視性

現在、読み取り権限を持たないテーブルにクエリを実行すると、「禁止」エラーではなく「見つからない」エラーが表示されます。 以前の動作を復元するには、druid.sql.planner.authorizeTableVisibility を false に設定します。 さらに、true に設定すると、INSERT と REPLACE にはターゲット テーブルへの READ アクセスと WRITE アクセスの両方が必要になります。このプロパティが false に設定されている場合、必要なのは書き込み権限のみです。このプロパティの値に関係なく、ユーザーがテーブルへの読み取りアクセス権を持っている場合、テーブルは INFORMATION_SCHEMA にのみ表示されます。 これは、必要な権限に影響を与える重大な変更です。詳細については、「SQL ベースの取り込みのアクセス許可の変更」(#permissions-changes-for-sql-based-ingestion) を参照してください。 #20075

Java ホーム変数

中間管理者は、作業ディレクトリに存在する必要がある bin/java スクリプトを使用するときに、JAVA_HOME を優先するようになりました。 ドルイドは次のロジックを使用します

  • コマンドを指定した場合 (config.getJavaCommand が null でない場合など)、それを使用します。
  • bin/run-java が存在する場合は、それを使用します
  • Javaを使用する #19709

コーディネーター エンドポイントの QoS フィルタリングを追加する

設定可能な QoS フィルタリングをコーディネータに追加して、低速 API リクエストのバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぎます。 新しい構成を追加しました: druid.coordinator.server.maxConcurrentRequests (デフォルト: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))、<= 0 を無効に設定)。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサーとモニターは影響を受けません。 #19271

その他のクラスター管理の改善点

  • UnusedSegmentsKiller がアクティブな取り込みで間隔をスキップしないように、組み込みの Kill タスクで使用できる KILL タスク ロック タイプを追加しました #19921
  • PostgreSQL のサポートを export-metadata ツールに追加しました #19698
  • クエリを処理しないタスク (バッチ、圧縮、MSQ タスクなど) を実行しているタスクは、druid.server.http.unannouncePropagationDelay を無視し、待機せずにシャットダウンするようになりました。リアルタイム ストリーミング タスクは引き続き遅延を考慮します #20444
  • ポートバインディングの改善。 Druid ノードは、Jetty を実際のサービス ポートにバインドしながら、ピア検出用に別のプレーンテキスト ポートをアドバタイズできるようになりました #19598
  • ロードされたセグメントのヒープ フットプリントを削減しました #20467
  • Druid 32.0.0 以来 404 エラーを返していた shutdownAllTasks Overlord API (POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks) を修正しました。 #20824

データ管理

圧縮中の間隔をスキップする

自動圧縮では、データソース圧縮構成の skipIntervals 設定がサポートされるようになり、既存の skipOffsetFromLatest の動作に加えて、特定の間隔を圧縮から除外できるようになりました。これは、たとえば、バックフィル ジョブがアクティブに書き込みを行っている間隔や、常に圧縮に失敗する間隔を除外する場合に便利です。 #19792

大規模なセグメント ファイルの可視性の向上

Druid は、範囲またはハッシュ パーティショニング設定により、タイム チャンク内に大きすぎるセグメント ファイル (ホット パーティション) が生成された場合にレポートするようになりました。ハッシュまたは範囲パーティション化を使用したネイティブ バッチ インジェストでは、警告がログに記録され、ingest/segments/oversized メトリクスが生成されるようになりました。このメトリクスは、範囲パーティション化の場合、2 倍を超える maxRowsPerSegment 行、または 3 倍を超える targetRowsPerSegment 行を含むパブリッシュされたセグメントをカウントします。タスク完了レポートには、この数も oversizedSegments として含まれます。 #20173

セグメント検索の高速化

高速間隔検索を有効にすることで、メモリ内タイムラインでのセグメント検索を高速化できるようになりました。この機能は、間隔ツリー インデックスを使用してメモリ内のタイムラインを編成し、セグメントの読み込みと検索を高速化します。 この機能を使用するには、druid.segment.timeline.fastIntervalSearch を true に設定します。 #19138 #19861

部分的なセグメントのロード

Druid は、仮想ストレージの部分セグメント読み込みをサポートするようになりました (デフォルトでオン)。オフにするには、次のいずれかを false に設定します。

  • ランタイムプロパティ druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • クエリコンテキストパラメータ virtualStoragePartialDownloadsEnabled #19739

その他のデータ管理の改善点

  • S3 互換ストレージの MD5 リクエスト チェックサムのサポートを追加しました。この機能を有効にするには、druid.s3.enableLegacyMd5 を true #20055 に設定します。

task/run/time メトリック

statsd および prometheus エミッターは、task/run/time で taskStatus の寸法を放射するようになりました。これは重大な変更です。詳細については、「task/run/time のアラート」(#alerts-on-taskruntime) を参照してください。 #20122

コントリビューターの拡張機能

氷山

Apache Iceberg の取り込みは、iceberg-arrow によってサポートされるオプトインのベクトル化リーダーをサポートするようになりました。 "useArrowReader": true で有効にします。 arrowBatchSize でバッチ処理を調整します (デフォルトは 1024)。 Arrow パスは、Parquet データ ファイル、辞書でエンコードされた値、スキーマ進化、タイムトラベル スナップショット、列射影、述語プッシュダウンをサポートします。位置削除ファイルまたは等価削除ファイルを含むスナップショットはサポートされておらず、Druid はそれらをエラーで拒否します。これらのスナップショットには標準の削除対応リーダーを使用してください。 Arrow パスは分割できないため、並列バッチ スループットが必要な場合は無効にしてください。デフォルトのリーダーは変更されず、両方のパスが同じ Iceberg 入力ソース タイプの下に共存します。 #19510

アップグレードに関する注意事項と互換性のない変更

アップグレードに関する注意事項

Netty 4.2

Druid は現在、HTTP client に Netty 4.2 を使用しています。以前は、Druid は Netty 3 を使用していました。これはメモリ特性の大幅な変更です。

  • ダイレクト メモリ: HTTP client は、ダイレクト メモリを消費するようになりました。 -XX:MaxDirectMemorySize の予算に近い運用を行っている事業者は、予算を増やす必要があるかもしれません。
  • プールされたバッファ: バッファはプールされるようになったため、アイドル状態であっても常駐メモリが Netty 3 よりも多く表示される場合があります。これは、プールされたアロケータでは正常です。 HTTP client の動作を制御する新しい構成 (druid.global.http.connectTimeout、druid.global.http.allocator、druid.broker.http.connectTimeout、および druid.broker.http.allocator) があります。一部の Netty 構成を直接設定することもできます。 #19567

ダーツワーカー

ヒストリカルのダーツ ワーカーは、新しい DartWorkerService メカニズムを使用してブローカーによって発表され、発見されるようになりました。 Dart を有効にしている場合は、標準のローリング アップグレードの順序に従ってください。アップグレード中は、Broker の前に Historicals を再起動します。ダウングレード中は、履歴の前にブローカーを再起動してください。 #20508

Protobuf の取り込み

  • Protobuf の取り込みでは、オプションとしてマークされていない proto3 フィールドのデフォルト値が保持されるようになりました。以前は、0 を保持する int32 フィールド (または "" を保持する文字列、false を保持する bool、最初の値を保持する enum) は null として取り込まれていました。このようなフィールドは実際の値として取り込まれるようになりました。 #20485

クエリ応答トレーラーによって引き起こされる JDK HTTP client エラーを修正しました

ブローカーとヒストリカルは、リクエストに TE: trailers ヘッダーが含まれている場合にのみ、X-Druid-Response-Complete および X-Error-Message HTTP トレーラーを送信するようになりました。 Cliこれらのトレーラーを読み取るエントは、そのヘッダーを送信する必要があります。これにより、JDK 17.0.21、21.0.13、および 25.0.5 上の Druid JDBC ドライバーを含む java.net.http.HttpClient-based client のクエリ エラー (java.net.ProtocolException: CR expected) が修正されます。 #20717

型指定されたクエリ コンテキスト パラメータ

クエリ コンテキスト リファレンス および スキャン クエリ にリストされている共通のクエリ コンテキスト パラメーターは、型指定された QueryContextParameter 記述子になりました。次の変更は、クエリ コンテキストの処理に適用されます。

  • 整数パラメータと長整数パラメータは、切り捨てたりラップしたりする代わりに、正確な整数ではない値を拒否します。たとえば、1.5、および範囲外の値です。 5.0 や "5.0" のような整数値は引き続き受け入れられます。無効な値は失敗し、「クエリ コンテキスト パラメータ [x] は ... である必要があります。」というエラー メッセージが表示されるようになりました。
  • クエリ コンテキスト内の null または SET x = NULL は、druid.query.default.context またはブローカーの動的構成で構成されたデフォルトをクリアしなくなりました。デフォルトは、キーが設定されていない場合と同様に適用されます。以前は、組み込みのデフォルトを使用するリーダーに null が到達していました。構成されたデフォルトをオーバーライドするには、明示的な値を設定します。
  • maxSubqueryBytes は、サブクエリ ガードレールと同様に、自動、無効、または負でないバイト数を受け入れる型付き文字列パラメータです。 SET maxSubqueryBytes = TRUE などの無効な値は検証中に失敗し、1e9 などの数値が受け入れられるようになりました。 [#20555][https://github.com/apache/druid/pull/20555/]

Java ホーム変数

中間管理者は、作業ディレクトリに存在する必要がある bin/java スクリプトを使用するときに、JAVA_HOME を尊重するようになりました。 ドルイドは次のロジックを使用します

  • コマンドを指定した場合 (config.getJavaCommand が null でない場合など)、それを使用します。
  • bin/run-java が存在する場合は、それを使用します
  • Javaを使用する #19709

コーディネーターのサービス品質フィルタリング

コーディネーターの QoS フィルタリングを有効にして、低速 API 要求のバーストによってスレッド プールが使い果たされ、ヘルス チェックがブロックされるのを防ぐことができるようになりました。 この機能 (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))) を構成するには、druid.coordinator.server.maxConcurrentRequests を使用します。オフにするには、このプロパティを 0 に設定します。 リーダー ステータスのエンドポイントは上限から除外されるため、ロード バランサー/モニターは影響を受けません。 #19271

互換性のない変更

SQL ベースの取り込みに対する権限の変更

テーブルの可視性 の変更は、SQL ベースの取り込みに必要な権限に影響します。 INSERT と REPLACE には、ターゲット テーブルに対する (WRITE に加えて) READ アクセスが必要になりました。 以前の動作を復元するには、druid.sql.planner.authorizeTableVisibility を false に設定します。 #20075

task/run/time に関するアラート

statsd および prometheus エミッターは、task/run/time で taskStatus の寸法を放射するようになりました。これは、task/run/time のダッシュボードとアラートの重大な変更です。

  • statsd (非 DogStatsD モード): ディメンション値はドット付きメトリック名に結合されるため、druid.overlord.task.run.time.DATASOURCE.TASKTYPE は druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE になります。古い名前に対するクエリはデータの受信を停止します。
  • statsd (DogStatsD モード): taskStatus タグが追加されます。既存のクエリは引き続き機能し、それを集計します。
  • prometheus: taskStatus ラベルが追加されます。正確なラベル セットを選択するクエリと、古いラベル セットを前提とする記録ルールを更新します。 以前の動作を維持するには、古いディメンション リストを druid.emitter.statsd.dimensionMapPath または druid.emitter.prometheus.dimensionMapPath で固定します。 #20122

SysMonitor が削除されました

SysMonitor は Druid 27 で非推奨となったため削除されました。代わりに OshiSysMonitor を使用してください。 #20200

MariaDB Connector/J 3.x による接続 URI の動作の変更

MariaDB JDBC コネクタが 2.7.3 から 3.5.10 にアップグレードされ、次のような影響があります。

  • druid.metadata.storage.connector.connectURI と org.mariadb.jdbc.Driver の場合は、jdbc:mariadb: を使用します。従来の jdbc:mysql: URI は、permitMysqlScheme が含まれている場合にのみ引き続き使用できます。たとえば、jdbc:mysql://<host>/druid?permitMysqlScheme は、メタデータ ストレージが URI をドライバーに直接渡すためです。
  • MariaDB ベースの SQL 入力ソースとデフォルトの druid.access.jdbc.enforceAllowedProperties=true による JDBC ルックアップの場合は、jdbc:mariadb: を使用します。 Druid の JDBC プロパティ検証では、jdbc:mysql: が Connector/J 3.x パーサーにルーティングされず、permitMysqlScheme はデフォルトの druid.access.jdbc.allowedProperties に含まれていません。オプションを追加するだけでは十分ではありません。
  • Connector/J 2.x を提供し続けるユーザーは、既存の jdbc:mysql: または jdbc:mariadb: URI を変更する必要はありません。 MySQL Connector/J ユーザーは影響を受けません。
  • distribution/docker/Dockerfile.mariadb から再構築されたイメージは Connector/J 3.5.10 をインストールするようになり、上記の 3.x ガイダンスに従う必要があります。 #20036

Important features, changes, and deprecations

This section contains important information about new and existing features.

Java

Support for Java 21 has been dropped. You must upgrade to Java 25.

DDL statements for the catalog (experimental)

Druid now supports CREATE and ALTER statements to manage metadata in the catalog. Use them to declare a table's columns, time partitioning, clustering, aggregate projections, and physical layout, instead of setting these in each ingestion spec.

This feature is off by default. To enable it, set druid.sql.planner.enableCatalogDdl to true.

For more information, see Catalog.

#19830 #20377 #20452 #19770 #19711

Kafka header-based filtering

Kafka supervisors can now filter records by their headers. This reduces ingestion CPU and memory use when you only need some of a topic's records.

To use the filter, add headerBasedFilterConfig to the supervisor's ioConfig. Use an in filter where dimension is the header name and values lists the header values to ingest. Records whose header value isn't in the list are dropped, and offsets still advance.

Filtering is permissive: records are ingested if they don't have the header, if the header value is null, empty, or can't be decoded, or if evaluation fails.

The new ingest/events/filtered metric reports how many records header filtering dropped.

#18525

Typed query context parameters

Common query context parameters listed in Query context reference and Scan queries are now typed QueryContextParameter descriptors. The following changes apply to the query context handling:

  • Integer and long parameters reject values that aren't exact integers instead of truncating or wrapping them. For example 1.5, and values out of range. Integral values like 5.0 or "5.0" are still accepted. Invalid values now fail with an error message: "Query context parameter [x] should be ...."
  • A null in the query context, or SET x = NULL, no longer clears a default configured with druid.query.default.context or the Broker dynamic configuration. The default applies as if the key were not set. Previously the null reached readers, which used the built-in default. To override a configured default, set an explicit value.
  • maxSubqueryBytes is a typed string parameter that accepts auto, disabled or a non-negative number of bytes, as the subquery guardrail does. Invalid values such as SET maxSubqueryBytes = TRUE now fail during validation, and numbers such as 1e9 are now accepted.

#20555

Druid JDBC driver

Druid now provides its own JDBC driver that uses the /druid/v2/sql/ endpoint. We recommend that you switch from the Avatica driver to this driver. The new driver provides the following benefits: driver-side connection management that doesn't require sticky load balancing, streaming results, support for SET statements, and support for non-native SQL engines.

#19951

Netty 4.2

Druid now uses Netty 4.2 for its HTTP client. Previously, Druid used Netty 3. This is a substantive change in memory characteristics:

  • Direct memory: The HTTP client now consumes some direct memory. Operators running close to their -XX:MaxDirectMemorySize budget may need to increase it.
  • Pooled buffers: Buffers are now pooled, so resident memory may appear higher than under Netty 3, even when idle. This is normal for a pooled allocator.

There are new configs that control the behavior of the HTTP client: druid.global.http.connectTimeout, druid.global.http.allocator, druid.broker.http.connectTimeout, and druid.broker.http.allocator. You can also set some Netty configs directly.

#19567

Quality of service filtering for Coordinator

You can now enable QoS filtering for the Coordinator to prevent a burst of slow API requests from exhausting the thread pool and blocking health checks.

Use druid.coordinator.server.maxConcurrentRequests to configure this feature (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Set this property to 0 to turn it off.

Leader-status endpoints are excluded from the cap so load balancers/monitors stay unaffected.

#19271

Functional area and related changes

This section contains detailed release notes separated by areas.

Ingestion

  • Added support for RE2/J regex for the regex input format #19514
  • Changed the S3 client to use the AWS-recommended standard retry policy. You can customize the retry strategy using druid.s3.retryMode and druid.s3.maxAttempts #19892
  • Protobuf ingestion now keeps the default value of proto3 fields that are not marked optional. Previously an int32 field holding 0 (or a string holding "", a bool holding false, an enum holding its first value) was ingested as null. Such fields now ingest as their actual value. #20485

SQL-based ingestion

  • Workers now only pass the necessary worker context instead of the entire worker context to the task context. #20650

Streaming ingestion

Ingesting from selected partitions

Kafka supervisors now accept ioConfig.partitionIds, which lets you ingest only selected partitions of a topic. For example, you can use this for independent diagnostic ingestion.

#20474

Cost-based autoscaler improvements
  • You can now simulate the cost-based autoscaler for Kafka to help determine the optimal task count for different amounts of lag. #19687
  • You can now set a critical lag threshold for the cost-based autoscaler. When lag reaches 75% of the threshold, the autoscaler bypasses the scale-up boundary. When lag reaches 100%, the autoscaler scales up to the maximum task count. #19655
  • You can now choose to configure cooldown for the cost-based autoscaler for a supervisor in one of 2 ways:
    • High sensitivity: Set minScaleUpDelay / minScaleDownDelay < taskDuration. For example if minScaleUpDelay = taskDuration / 2, there would be at most 1 scaling event between 2 task rollovers
    • Low sensitivity : Set minScaleUpDelay / minScaleDownDelay > taskDuration. In this case, cooldown is effectively ignored and the scaling happens on task rollover only. #20706
  • The cost-based autoscaler now uses running averages instead of instantaneous values of task metrics to make decisions for the cost based auto-scaler. This leads to smoother scaling but may sometimes come at the cost of slightly delayed responses to change in metric trends that occur towards the end of the task lifecycle. For higher sensitivity to changing trends, set minScaleUpDelay and minScaleDownDelay to be smaller than taskDuration.
Other streaming ingestion improvements
  • Fixed a bug where a Kafka indexing task would report a poll-idle-ratio of 1.0 (i.e. fully idle) before any sample was actually available, which could skew the supervisor autoscaler's averaged idle ratio across tasks. #20783

Querying

Query planning time

You can now limit how long the Broker spends planning a SQL query with the new druid.sql.planner.maxPlanningTimeMs runtime property. You can also set it per query using the maxPlanningTimeMs query context parameter. When planning exceeds the configured budget, the query fails with an HTTP 504 Query timeout error instead of tying up a Broker thread. The default value is 0, which disables the timeout.

#20314

Fixed JDK HTTP client failures caused by query response trailers

Brokers and Historicals now send the X-Druid-Response-Complete and X-Error-Message HTTP trailers only when the request includes the TE: trailers header. Clients that read these trailers must send that header. This fixes query failures (java.net.ProtocolException: CR expected) in java.net.http.HttpClient-based clients, including the Druid JDBC driver, on JDK 17.0.21, 21.0.13 and 25.0.5.

#20717

  • You can now use Dart to query metadata tables such as those in the sys schema #19952
  • CAST(x AS LONG) is now accepted as an alias for CAST(x AS BIGINT) in Druid SQL #20402
  • Added datasource filter pushdown to sys.segments table #19718
  • Added framing support to the FIRST_VALUE and LAST_VALUE window functions #19301
  • Improved the performance of timeseries, timeBoundary, and scan queries that run in descending order #19947
  • Improved the performance of COALESCE #18400
  • Improved S3 API usage efficiency for MSQ tasks using durable storage and MSQ export #19893

Cluster management

Kubernetes node labels

The druid-kubernetes-extensions extension now supports a k8sNodeLabel dynamic config provider, which resolves configuration values from the labels of the Kubernetes node a Druid process runs on.

#20404

Peon pod template

You can now retrieve the Peon pod template names currently configured on the Overlord using the new GET /druid/indexer/v1/k8s/taskrunner/podTemplates endpoint. It returns the name for each configured template. The endpoint requires CONFIG read permission and returns 404 when the Overlord is not using the custom template pod adapter.

#19712

Environment variables

The environment dynamic config provider now omits variables that are not set in the environment instead of producing a null value that fails consumers such as the Kafka supervisor with a NullPointerException. A skipped variable is logged at info level.

#20381

Connection pools

You can now configure how the Druid connection pool tracks connection demand using druid.global.http.poolImplementation.

The default is retaining. With retaining, the pool keeps every connection it opens and replaces each stale or broken connection with a new one, so the pool stays at its high-water mark.

#20542 #20273

HTTP response headers

Druid can now optionally return X-Druid-Server, X-Druid-Service, and X-Druid-Version on HTTP responses, allowing operators to identify the process and version that served a direct or Router-proxied request. These headers expose cluster topology and version information, so only enable them if all clients are permitted to receive it. To enable them, set druid.server.http.enableResponseIdentityHeaders to true.

#20268

Improved LDAP support

Added support for LDAP group-based authorization on servers that do not return the memberOf attribute (such as OpenLDAP). Configure groupBaseDn and groupSearch on the LDAP credentials validator to enable a reverse group lookup that resolves group memberships automatically.

#19432

Table visibility

Users who query tables they don't have READ permission for now see a "not found" error instead of a "forbidden" error.

To restore the previous behavior, set druid.sql.planner.authorizeTableVisibility to false.

Additionally, when set to true, INSERT and REPLACE require both READ and WRITE access to the target table. If this property is set to false, they only require WRITE permission. Regardless of the value of this property, tables only appear in INFORMATION_SCHEMA if the user has READ access to them.

This is a breaking change that affects the permissions you need. For more information, see permissions changes for SQL-based ingestion.

#20075

Java home variable

Middle Managers now honor JAVA_HOME when using the bin/java script, which should be present in the working directory.

Druid uses the following logic

  • If you specified a command (such as if config.getJavaCommand is not null), use that.
  • If bin/run-java exists, use that
  • Use java

Added configurable QoS filtering to the Coordinator to prevent a burst of slow API requests from exhausting the thread pool and blocking health checks . Added a new configuration: druid.coordinator.server.maxConcurrentRequests (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8)), set <= 0 to disable). Leader-status endpoints are excluded from the cap so load balancers and monitors remain unaffected.

  • Added a KILL task lock type that can be used by embedded kill tasks so that the UnusedSegmentsKiller does not skip intervals with active ingestions #19921
  • Added support for PostgreSQL to the export-metadata tool #19698
  • Peons running tasks that do not serve queries (for example, batch, compaction, and MSQ tasks) now ignore druid.server.http.unannouncePropagationDelay and shut down without waiting. Real-time streaming tasks still honor the delay #20444
  • Improved port binding. Druid nodes can now advertise a different plaintext port for peer discovery while binding Jetty to the actual service port #19598
  • Reduced the heap footprint of loaded segments #20467
  • Fixed the shutdownAllTasks Overlord API (POST /druid/indexer/v1/datasources/{datasource}/shutdownAllTasks), which returned a 404 error since Druid 32.0.0. #20824

Data management

Skip intervals during compaction

Auto-compaction now supports a skipIntervals setting in the datasource compaction config, allowing specific intervals to be excluded from compaction in addition to the existing skipOffsetFromLatest behavior. This is useful, for example, to exclude an interval that a backfill job is actively writing to, or one that consistently fails compaction.

#19792

Better visibility for large segment files

Druid now reports when your range or hash partitioning settings produce overly large segment files (hot partitions) in a time chunk. Native batch ingestion with hash or range partitioning now logs a warning and emits the ingest/segments/oversized metric. The metric counts published segments with more than double maxRowsPerSegment rows, or more than triple targetRowsPerSegment for range partitioning. The task completion report also includes this count as oversizedSegments.

#20173

Faster segment searches

You can now speed up segment searches in the in-memory timeline by enabling fast interval search. This feature uses an interval tree index to organize the timeline in memory for faster loading and searching of segments.

To use this feature, set druid.segment.timeline.fastIntervalSearch to true.

#19138 #19861

Partial segment loading

Druid now supports partial segment loading for virtual storage (on by default). To turn it off, set either of the following to false:

  • the runtime property druid.indexer.task.virtualStoragePartialDownloadsEnabled
  • the query context parameter virtualStoragePartialDownloadsEnabled

#19739

Other data management improvements

  • Added support for MD5 request checksums for S3-compatible storage. To enable this feature, set druid.s3.enableLegacyMd5 to true #20055
  • Added support for pushing, pulling, and killing segments in Azure and Google Cloud deep storage without zip compression #20454 #20327 #20382 #20380
  • Improved the loading algorithm to better disperse requests across Historical tiers when using virtual storage #20155
  • Improved the efficiency of embedded kill tasks #19772

Metrics and monitoring

Tier storage metrics

The tier storage metrics now provide better observability for Historicals, with or without virtual storage. Two metrics, tier/required/capacity and tier/total/capacity, are deprecated and will be removed in a future release. Use tier/storage/required and tier/storage/capacity instead.

#20199

task/run/time metric

The statsd and prometheus emitters now emit the taskStatus dimension on task/run/time. This is a breaking change. For more information, see alerts on task/run/time.

#20122

Other metrics and monitoring improvements

  • Peon task metrics for clusters that use the Kubernetes Overlord extension now include a podTemplate dimension. This makes it easier to monitor clusters that map different tasks to different pod templates #20001
  • Added mergeBuffer/maxSpillProximity which measures how close any single groupBy query came to spilling during the emission period, as a fraction in [0.0, 1.0] #19627
  • Added taskType to the various task count metrics, so you can filter them by task type #20123

Contributor extensions

Iceberg

Apache Iceberg ingestion now supports an opt-in vectorized reader backed by iceberg-arrow. Enable it with "useArrowReader": true; tune batching with arrowBatchSize (default 1024). The Arrow path supports Parquet data files, dictionary-encoded values, schema evolution, time-travel snapshots, column projection, and predicate pushdown. Snapshots containing positional or equality delete files aren't supported, and Druid rejects them with an error; use the standard delete-aware reader for those snapshots. The Arrow path is not splittable, so keep it disabled where parallel batch throughput is required. The default reader remains unchanged, and both paths coexist under the same Iceberg input-source type.

#19510

Open Policy Agent

Added the druid-opa-authorizer contributor extension, which enables authorization through Open Policy Agent (OPA). You can write Rego policies to control access to Druid resources based on user identity, action, and resource type. The extension supports both basic authentication and LDAP authentication workflows.

#19670

Upgrade notes and incompatible changes

Upgrade notes

Netty 4.2

Druid now uses Netty 4.2 for its HTTP client. Previously, Druid used Netty 3. This is a substantive change in memory characteristics:

  • Direct memory: The HTTP client now consumes some direct memory. Operators running close to their -XX:MaxDirectMemorySize budget may need to increase it.
  • Pooled buffers: Buffers are now pooled, so resident memory may appear higher than under Netty 3, even when idle. This is normal for a pooled allocator.

There are new configs that control the behavior of the HTTP client: druid.global.http.connectTimeout, druid.global.http.allocator, druid.broker.http.connectTimeout, and druid.broker.http.allocator. You can also set some Netty configs directly.

#19567

Dart workers

Dart workers on Historicals are now announced and discovered by the Broker with a new DartWorkerService mechanism. If you've enabled Dart, follow the standard rolling upgrade order: during an upgrade, restart Historicals before the Broker; during a downgrade, restart the Broker before Historicals.

#20508

Protobuf ingestion

  • Protobuf ingestion now keeps the default value of proto3 fields that are not marked optional. Previously an int32 field holding 0 (or a string holding "", a bool holding false, an enum holding its first value) was ingested as null. Such fields now ingest as their actual value.

#20485

Fixed JDK HTTP client failures caused by query response trailers

Brokers and Historicals now send the X-Druid-Response-Complete and X-Error-Message HTTP trailers only when the request includes the TE: trailers header. Clients that read these trailers must send that header. This fixes query failures (java.net.ProtocolException: CR expected) in java.net.http.HttpClient-based clients, including the Druid JDBC driver, on JDK 17.0.21, 21.0.13 and 25.0.5.

#20717

Typed query context parameters

Common query context parameters listed in Query context reference and Scan queries are now typed QueryContextParameter descriptors. The following changes apply to the query context handling:

  • Integer and long parameters reject values that aren't exact integers instead of truncating or wrapping them. For example 1.5, and values out of range. Integral values like 5.0 or "5.0" are still accepted. Invalid values now fail with an error message: "Query context parameter [x] should be ...."
  • A null in the query context, or SET x = NULL, no longer clears a default configured with druid.query.default.context or the Broker dynamic configuration. The default applies as if the key were not set. Previously the null reached readers, which used the built-in default. To override a configured default, set an explicit value.
  • maxSubqueryBytes is a typed string parameter that accepts auto, disabled or a non-negative number of bytes, as the subquery guardrail does. Invalid values such as SET maxSubqueryBytes = TRUE now fail during validation, and numbers such as 1e9 are now accepted.

[#20555][https://github.com/apache/druid/pull/20555/]

Java home variable

Middle Managers now honor JAVA_HOME when using the bin/java script, which should be present in the working directory.

Druid uses the following logic

  • If you specified a command (such as if config.getJavaCommand is not null), use that.
  • If bin/run-java exists, use that
  • Use java

#19709

Quality of service filtering for Coordinator

You can now enable QoS filtering for the Coordinator to prevent a burst of slow API requests from exhausting the thread pool and blocking health checks.

Use druid.coordinator.server.maxConcurrentRequests to configure this feature (default: max(1, max(serverHttpNumThreads - 4, serverHttpNumThreads * 0.8))). Set this property to 0 to turn it off.

Leader-status endpoints are excluded from the cap so load balancers/monitors stay unaffected.

#19271

Incompatible changes

Permissions changes for SQL-based ingestion

The table visibility changes affect the permissions required for SQL-based ingestion. INSERT and REPLACE now require READ access (in addition to WRITE) on the target table.

To restore the previous behavior, set druid.sql.planner.authorizeTableVisibility to false.

#20075

Alerts on task/run/time

The statsd and prometheus emitters now emit the taskStatus dimension on task/run/time. This is a breaking change for dashboards and alerts on task/run/time:

  • statsd (non-DogStatsD mode): Dimension values are joined into the dotted metric name, so druid.overlord.task.run.time.DATASOURCE.TASKTYPE becomes druid.overlord.task.run.time.DATASOURCE.TASKSTATUS.TASKTYPE. Queries against the old name stop receiving data.
  • statsd (DogStatsD mode): A taskStatus tag is added. Existing queries keep working and aggregate over it.
  • prometheus: A taskStatus label is added. Update any queries that select on an exact label set and any recording rules that assume the old label set.

To keep the previous behavior, pin the old dimension list with druid.emitter.statsd.dimensionMapPath or druid.emitter.prometheus.dimensionMapPath.

#20122

SysMonitor removed

SysMonitor has been removed after being deprecated in Druid 27. Use OshiSysMonitor instead.

#20200

MariaDB Connector/J 3.x changes connection URI behavior

The MariaDB JDBC connector has been upgraded from from 2.7.3 to 3.5.10, which has the following impact:

  • For druid.metadata.storage.connector.connectURI with org.mariadb.jdbc.Driver, use jdbc:mariadb:. A legacy jdbc:mysql: URI remains usable only if it includes permitMysqlScheme. For example, jdbc:mysql://<host>/druid?permitMysqlScheme, because metadata storage passes the URI directly to the driver.
  • For MariaDB-backed SQL input sources and JDBC lookups with the default druid.access.jdbc.enforceAllowedProperties=true, use jdbc:mariadb:. Druid's JDBC property validation does not route jdbc:mysql: to the Connector/J 3.x parser, and permitMysqlScheme is not in the default druid.access.jdbc.allowedProperties, Adding the option alone is not sufficient.
  • Users who continue supplying Connector/J 2.x do not need to change existing jdbc:mysql: or jdbc:mariadb: URIs. MySQL Connector/J users are unaffected.
  • Images rebuilt from distribution/docker/Dockerfile.mariadb now install Connector/J 3.5.10 and must follow the 3.x guidance above.

#20036

Developer notes

Web console code editor

The web console's code editors moved from Ace (ace-builds and react-ace) to Code Mirror 6. All editors now share a single CodeEditor component, including the workbench, the explore view's SQL inputs, JSON inputs, spec and value dialogs, history, and explain. Two Lezer grammars, one for DruidSQL and one for Hjson, drive the highlighting and the completions.

#20507

Dependency updates

Druid 39.0.0 includes a variety of updates to dependencies such as Calcite. For a full list, see the Area - Dependencies label in the milestone.
