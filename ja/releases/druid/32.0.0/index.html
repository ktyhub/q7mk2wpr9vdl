<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> 新しいオーバーロード API

セグメントを使用済みまたは未使用としてマークするための API は、コーディネーターからオーバーロード サービスに移動されました。

  • データソースのすべてのセグメントを未使用としてマークします。 POST /druid/indexer/v1/datasources/{dataSourceName}

  • データソースのすべての (影になっていない) セグメントを使用済みとしてマークします。 DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • 複数のセグメントを使用済みとしてマークします POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • 複数の (影になっていない) セグメントを未使用としてマークします POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • 単一セグメントを使用済みとしてマークします。 POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • 単一セグメントを未使用としてマークします。 DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

この変更の一環として、対応するコーディネーター API は非推奨となり、将来のリリースでは削除される予定です。

  • POST /druid/coordinator/v1/datasources/{dataSourceName}
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}

コーディネーターはこれらのリクエストに応えるためにオーバーロードを呼び出します。

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> 複数値文字列のリアルタイム クエリ処理

リアルタイム クエリ処理では、式の処理中にすべての文字列が複数値の文字列として考慮されなくなり、多くのバグと予期しないエラーが修正されました。これにより、文字列列に対する式のリアルタイム クエリのパフォーマンスも向上します。

この変更は、JSON オブジェクトに欠落しているプロパティなど、データ行が暗黙的に null であるリアルタイム セグメントの topN クエリに影響します。

この変更が行われる前は、これらは null ではなく [] として処理され、リアルタイム セグメントの処理と公開セグメントの間で不一致が発生していました。セグメントを処理するときに、値は [] として扱われ、topN はこれを無視しました。公開後、値は null になりましたが、topN はこれを無視しません。同じクエリでも、永続化の前後で結果が異なる可能性があります。

この変更後、topN エンジンはリアルタイム セグメントを処理するときに [] を null として扱うようになり、これは公開されたセグメントと一貫性があります。

この変更は、リアルタイムであるかどうかに関係なく、実際の複数値文字列列には影響しません。

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> MSQ タスク エンジン クエリの結合ヒント

Druid は、MSQ タスク エンジンを使用する SQL JOIN クエリのヒントをサポートするようになりました。これにより、クエリで結合レベルごとに使用する必要がある JOIN タイプのヒントを提供できるようになります。結合ヒントはサブクエリに再帰的に影響します。

#17541

<a name="32.0.0-changes-and-deprecations" href="#32.0.0-changes-and-deprecations">#</a> 変更と非推奨

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> ANSI-SQL の互換性とクエリ結果

ANSI-SQL に準拠していない古い動作を維持できる構成のサポートは削除されました。

  • druid.generic.useDefaultValueForNull=true
  • druid.expressions.useStrictBooleans=false
  • druid.generic.useThreeValueLogicForNativeFilters=false

クエリ結果には影響しなくなりました。現在は、SQL 準拠の非レガシー動作のみがサポートされています。

構成が従来の動作に設定されている場合、Druid サービスは開始できません。

これらの設定を行わずに引き続き同じ結果を得たい場合は、クエリを更新する必要があります。そうしないと、アップグレード後に結果が不正確になります。

クエリを更新する方法の詳細については、移行ガイド を参照してください。

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> MSQ タスク エンジン クエリの結合ヒント

Druid は、MSQ タスク エンジンを使用する SQL JOIN クエリのヒントをサポートするようになりました。これにより、クエリで結合レベルごとに使用する必要がある JOIN タイプのヒントを提供できるようになります。結合ヒントはサブクエリに再帰的に影響します。

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

<a name="32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing" href="#32.0.0-functional-area-and-related-changes-ingestion-streaming-ingestion-control-how-many-segments-get-merged-for-publishing">#</a> 公開するために結合するセグメントの数を制御します

スーパーバイザ仕様の maxColumnsToMerge プロパティを使用して、パブリッシュのためにセグメントをマージするときに、単一フェーズでマージするセグメントの数を指定できるようになりました。この制限は、マージするセグメントのセットに存在する列の合計数に影響します。制限を超えると、セグメントのマージが複数のフェーズで発生します。 Druid は、この設定に関係なく、各フェーズで少なくとも 2 つのセグメントをマージします。

<a name="32.0.0-functional-area-and-related-changes-cluster-management-reduce-metadata-io" href="#32.0.0-functional-area-and-related-changes-cluster-management-reduce-metadata-io">#</a> メタデータ IO を削減する

Overlord ランタイム プロパティ druid.indexer.tasklock.batchAllocationReduceMetadataIO は、バッチ セグメント割り当て中の IO を削減するのに役立ちます。このフラグを true (デフォルト値) に設定すると、オーバーロードはセグメント割り当て中に必要なセグメント ペイロードのみをフェッチできるようになります。

<a name="32.0.0-functional-area-and-related-changes-data-management" href="#32.0.0-functional-area-and-related-changes-data-management">#</a> データ管理

<a name="32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29" href="#32.0.0-functional-area-and-related-changes-data-management-sorting-columns-for-compaction-with-the-msq-task-engine-%28experimental%29">#</a> MSQ タスク エンジンを使用した圧縮のための列の並べ替え (実験的)

MSQ タスク エンジンを使用する圧縮では、時間以外の列を含むセグメントの並べ替えがサポートされるようになりました。 forceSegmentSortByTime が圧縮構成または推論されたスキーマに設定されている場合、次のことが起こります。

  • __time はすでにスキーマの一部として含まれているため、ディメンション スキーマの最初の列として明示的に追加するのをスキップします。
  • 列マッピングがスキーマで指定された順序で __time を伝播するようにする
  • MSQ クエリ コンテキストで forceSegmentSortByTime を設定します。

<a name="32.0.0-functional-area-and-related-changes-data-management-other-data-management-improvements" href="#32.0.0-functional-area-and-related-changes-data-management-other-data-management-improvements">#</a> その他のデータ管理の改善点

  • 同じ列順序の異なる順列が異なるスキーマにならないように集中データソース スキーマを改善しました #17044
  • 列スキーマが明示的に指定されていない場合、常に複数値ディメンションを配列として処理するように圧縮タスクを変更しました #17110

<a name="32.0.0-important-features" href="#32.0.0-important-features">#</a> Important features

This section contains important information about new and existing features.

<a name="32.0.0-important-features-new-overlord-apis" href="#32.0.0-important-features-new-overlord-apis">#</a> New Overlord APIs

APIs for marking segments as used or unused have been moved from the Coordinator to the Overlord service:

  • Mark all segments of a datasource as unused: POST /druid/indexer/v1/datasources/{dataSourceName}

  • Mark all (non-overshadowed) segments of a datasource as used: DELETE /druid/indexer/v1/datasources/{dataSourceName}

  • Mark multiple segments as used POST /druid/indexer/v1/datasources/{dataSourceName}/markUsed

  • Mark multiple (non-overshadowed) segments as unused POST /druid/indexer/v1/datasources/{dataSourceName}/markUnused

  • Mark a single segment as used: POST /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

  • Mark a single segment as unused: DELETE /druid/indexer/v1/datasources/{dataSourceName}/segments/{segmentId}

As part of this change, the corresponding Coordinator APIs have been deprecated and will be removed in a future release:

  • POST /druid/coordinator/v1/datasources/{dataSourceName}
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUsed
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/markUnused
  • POST /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}/segments/{segmentId}
  • DELETE /druid/coordinator/v1/datasources/{dataSourceName}

The Coordinator now calls the Overlord to serve these requests.

#17545

<a name="32.0.0-important-features-realtime-query-processing-for-multi-value-strings-" href="#32.0.0-important-features-realtime-query-processing-for-multi-value-strings-">#</a> Realtime query processing for multi-value strings

Realtime query processing no longer considers all strings as multi-value strings during expression processing, fixing a number of bugs and unexpected failures. This should also improve realtime query performance of expressions on string columns.

This change impacts topN queries for realtime segments where rows of data are implicitly null, such as from a property missing from a JSON object.

Before this change, these were handled as [] instead of null, leading to inconsistency between processing realtime segments and published segments. When processing segments, the value was treated as [], which topN ignores. After publishing, the value became null, which topN does not ignore. The same query could have different results before and after being persisted

After this change, the topN engine now treats [] as null when processing realtime segments, which is consistent with published segments.

This change doesn't impact actual multi-value string columns, regardless of if they're realtime.

#17386

<a name="32.0.0-important-features-join-hints-in-msq-task-engine-queries" href="#32.0.0-important-features-join-hints-in-msq-task-engine-queries">#</a> Join hints in MSQ task engine queries

Druid now supports hints for SQL JOIN queries that use the MSQ task engine. This allows queries to provide hints for the JOIN type that should be used at a per join level. Join hints recursively affect sub queries.

<a name="32.0.0-changes-and-deprecations" href="#32.0.0-changes-and-deprecations">#</a> Changes and deprecations

<a name="32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results" href="#32.0.0-changes-and-deprecations-ansi-sql-compatibility-and-query-results">#</a> ANSI-SQL compatibility and query results

Support for the configs that let you maintain older behavior that wasn't ANSI-SQL compliant have been removed:

  • druid.generic.useDefaultValueForNull=true
  • druid.expressions.useStrictBooleans=false
  • druid.generic.useThreeValueLogicForNativeFilters=false

They no longer affect your query results. Only SQL-compliant non-legacy behavior is supported now.

If the configs are set to the legacy behavior, Druid services will fail to start.

If you want to continue to get the same results without these settings, you must update your queries or your results will be incorrect after you upgrade.

For more information about how to update your queries, see the migration guide.

<a name="32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries" href="#32.0.0-changes-and-deprecations-join-hints-in-msq-task-engine-queries">#</a> Join hints in MSQ task engine queries

Druid now supports hints for SQL JOIN queries that use the MSQ task engine. This allows queries to provide hints for the JOIN type that should be used at a per join level. Join hints recursively affect sub queries.

select /*+ sort_merge */ w1.cityName, w2.countryName
from
(
  select /*+ broadcast */ w3.cityName AS cityName, w4.countryName AS countryName from wikipedia w3 LEFT JOIN wikipedia-set2 w4 ON w3.regionName = w4.regionName
) w1
JOIN wikipedia-set1 w2 ON w1.cityName = w2.cityName
where w1.cityName='New York';

  • Changed real-time segment metrics so that they are for each Sink instead of for each FireHydrant. This is a return to emission behavior prior to improvements to real-time query performance made in 30.0.0 #17170
  • Changed query stats to be first before intervals in getNativeQueryLine logging so that the stats are retained if the query object gets truncated #17326

<a name="32.0.0-functional-area-and-related-changes-extensions" href="#32.0.0-functional-area-and-related-changes-extensions">#</a> Extensions

<a name="32.0.0-functional-area-and-related-changes-extensions-delta-lake" href="#32.0.0-functional-area-and-related-changes-extensions-delta-lake">#</a> Delta Lake

  • The Delta Lake input source now supports decimal data types and is handled as a double. If the value cannot fit within a double, ingest it as a string #17376
  • You can now filter by snap shot version even if if the version is 0 #17367

<a name="32.0.0-functional-area-and-related-changes-extensions-grpc-queries" href="#32.0.0-functional-area-and-related-changes-extensions-grpc-queries">#</a> gRPC queries

A new contributor extension enabled a gRPC API for SQL and native queries, which means that gRPC-based clients can use the extension to issue SQL queries. Use this extension for simple queries.

For more information, see gRPC query extension for Druid.

#15982

<a name="32.0.0-functional-area-and-related-changes-extensions-kubernetes" href="#32.0.0-functional-area-and-related-changes-extensions-kubernetes">#</a> Kubernetes

  • Middle Manger-less ingestion using Kubernetes is now more resilient to Overlord restarts #17446
  • You can now pass empty arrays to type and dataSource keys in selector based pod template selection strategy #17400
  • Improved the TaskRunner to expose the getMaximumCapacity field #17107

<a name="32.0.0-functional-area-and-related-changes-extensions-iceberg" href="#32.0.0-functional-area-and-related-changes-extensions-iceberg">#</a> Iceberg

The Iceberg extension now supports the AWS Glue Iceberg catalog.

#17392

<a name="32.0.0-functional-area-and-related-changes-documentation-improvements" href="#32.0.0-functional-area-and-related-changes-documentation-improvements">#</a> Documentation improvements

The docs now include examples for all supported Apache Druid SQL functions. You can easily learn how to use each function by following along with the examples. These examples leverage datasets included with Druid, making it simple to get started quickly.

Check out the examples at All Druid SQL functions.

<a name="32.0.0-upgrade-notes-and-incompatible-changes" href="#32.0.0-upgrade-notes-and-incompatible-changes">#</a> Upgrade notes and incompatible changes

<a name="32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes" href="#32.0.0-upgrade-notes-and-incompatible-changes-incompatible-changes">#</a> Incompatible changes

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes">#</a> Developer notes

  • Improved dependency support between extensions. When an extension has a dependency on another extension, it now tries to use the dependency's class loader to find classes required classes #16973
  • Coordinator APIs for marking segments as used or unused are now deprecated and will be removed in a future release. Use the corresponding Overlord APIs instead. For a full list, see New Overlord APIs or #17545

<a name="32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates" href="#32.0.0-upgrade-notes-and-incompatible-changes-developer-notes-dependency-updates">#</a> Dependency updates

The following dependencies have had their versions bumped:

  • javax.xml.bind is no longer used. Druid now uses jakarta.xml.bind #17370
  • Several dependencies for the web console have had their dependencies updated. For a full list, see #17381, #17365, #17363
  • Removed file-loader dependency for the web console #17346
  • Guice from 4.2.2 to 5.1.0
  • git-commit-id-maven-plugin from 4.9.10 to 9.0.1 #17571
  • Netty from version 4.1.108.Final to 4.1.116.Final
