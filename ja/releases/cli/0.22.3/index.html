#cli v0.22.3

Release Note

パッチの変更

  • 674d53a: uvx を実行する前に、astral-sh/setup-uv 経由で uv をインストールすることで、Lint Skills CI ジョブを修正しました。
  • c7c42f6: 修正: スクリプト サービスの登録とテスト パス検証エラーの解決
  • 80bd150: feat(auth): macOS および Windows で厳密な OS キーチェーン統合を使用します。 #623を閉じます。 CLI は、資格情報を安全に保存するときに、macOS および Windows 上でフォールバック .encryption_key テキスト ファイルを書き込まなくなりました。代わりに、ネイティブ OS キーチェーン (macOS ではキーチェーン アクセス、Windows では資格情報マネージャー) を厳密に使用します。キーチェーンへのログインに成功したときに古い .encryption_key ファイルが見つかった場合、セキュリティのためにそのファイルは自動的に削除されます。 Linux デプロイメントでは、ヘッドレス継続的インテグレーション (CI) ランナー、Docker コンテナー、およびデスクトップ DBUS サービスのない SSH 環境との最大限の互換性を確保するために、デフォルトでシームレスなファイルベースのフォールバックが引き続き使用されます。
  • ec7f56b: 生成されたスキルを最新の Google Discovery API 仕様と同期します

cli v0.22.3

Release Notes

Patch Changes

  • 674d53a: Fix Lint Skills CI job by installing uv via astral-sh/setup-uv before running uvx

  • c7c42f6: fix: register script service and resolve test path validation errors

  • 80bd150: feat(auth): use strict OS keychain integration on macOS and Windows

    Closes #623. The CLI no longer writes a fallback .encryption_key text file on macOS and Windows when securely storing credentials. Instead, it strictly uses the native OS keychain (Keychain Access on macOS, Credential Manager on Windows). If an old .encryption_key file is found during a successful keychain login, it will be automatically deleted for security. Linux deployments continue to use a seamless file-based fallback by default to ensure maximum compatibility with headless continuous integration (CI) runners, Docker containers, and SSH environments without desktop DBUS services.

  • ec7f56b: Sync generated skills with latest Google Discovery API specs

Verifying GitHub Artifact Attestations

The artifacts in this release have attestations generated with GitHub Artifact Attestations. These can be verified by using the GitHub CLI:

gh attestation verify <file-path of downloaded artifact> --repo googleworkspace/cli

You can also download the attestation from GitHub and verify against that directly:

gh attestation verify <file-path of downloaded artifact> --bundle <file-path of downloaded attestation>
