airflow 2.7.3

Highlights

  • Python 3.12 and dependency ceilings — This patch explicitly caps Airflow at < 3.12 (#35123) and adds hard upper bounds on pendulum<3.0 (#35336), connexion<3.0 (#35218), sentry_sdk==1.33.0 (#35298), and WTForms<3.1.0 (#34943). If you're planning a Python 3.12 rollout, it's blocked here; these pins also mean a future upgrade will likely require coordinated dependency movement rather than a drop-in bump.
  • Scheduler and triggerer reliability — Two crash paths are closed: the scheduler no longer crash-loops when DAG run creation fails (#35135), and the triggerer thread no longer crashes in daemon mode (#34931). Both are production-stability fixes worth prioritizing — the first in particular hit deployments under DB contention or concurrent DAG run creation.
  • Dynamic task mapping correctness — Fixes premature evaluation of tasks inside a mapped task group (#34337). If you rely on expand()/expand_kwargs() with groups whose mapped values come from upstream XComs, this removes a class of "ran before its inputs were ready" bugs — verify any workarounds you added now that they're no longer needed.
  • REST API semantics — Several endpoint refinements land together: trigger_rule values are now surfaced in the REST API (#35194), dag_run and task_instance endpoints get consistency fixes (#34942), read-only fields now reject writes (#33413), and ~ as a dag_id returns only task instances of readable DAGs (#34939). API consumers should re-check any code that wrote to read-only fields or depended on the old ~ wildcard behavior.
  • Trigger-rule and timezone behavior changes — Tasks with the all_skipped trigger rule are now marked skipped when any upstream task is upstream_failed (#34392), and TimeSensorAsync now honors the DAG's timezone instead of UTC (#33406). The latter can shift deferrable sensor fire times for non-UTC DAGs — audit any timezone-sensitive schedules before upgrading.
  • Frontend dependency security bumps — @babel/traverse is raised to 7.23.2 (#34988) and undici to 5.26.3 (#34971) under airflow/www. These are transitive/security-driven updates, so expect no functional change but a cleaner dependency audit.

No breaking changes in this release.
