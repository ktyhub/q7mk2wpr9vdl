エアフロー airflow-ctl/0.1.5

:パッケージ: PyPI: https://pypi.org/project/apache-airflow-ctl/0.1.5 :書籍: ドキュメント: https://airflow.apache.org/docs/apache-airflow-ctl/0.1.5 :ハンマーとレンチ: Release Notes: https://airflow.apache.org/docs/apache-airflow-ctl/0.1.5/release_notes.html

重大な変更

  • DAGSの次回実行コマンドを追加(#66172、#66188)
  • 一括削除 Dag Run を追加 (#67095)
  • クリア/再実行動作用に rerun_with_latest_version 構成階層を追加 (#63884)
  • API でタスク グループ インスタンスのパッチ適用を実装 (#62812)
  • 認証なしでリモートバージョンチェックを許可 (#65099)
  • get_dag_runs エンドポイントにカーソルベースのページネーションを追加 (#65604)
  • 新しいタスクのキューイングを有効にする (#63484)
  • get_task_instances エンドポイントにカーソルベースのページネーションを追加 (#64845)
  • DAG API 応答に is_backfillable プロパティを追加 (#64644)
  • 自動生成コマンドの必要なプリミティブ パラメーターを、--flag オプションの代わりに位置引数として公開します。オプションのパラメーターは --flag 形式を維持します。 airflowctl パラメータ スタイルに関する dev-list 遅延コンセンサスに従います (https://lists.apache.org/thread/m1qvcvow3l17ytv40vhslh40wn3rntrm を参照) (#66768)

バグ修正

  • 接続インポートスキーマ処理を修正 (#67063)
  • ドキュメント内の壊れたダウンロード URL と変数名を修正 (#67046)
  • 欠落していた pyyaml ランタイム依存関係を修正 (#65489)
  • --state が省略された場合の dagrun list クラッシュを修正 (#65608)
  • バックフィルパラメータが既存の DAG 実行設定をオーバーライドしない問題を修正 (#64939)
  • client-py の Ruff の問題を修正 (#64868)

改善点

  • AIP-103: タスク状態とアセット状態のコア API エンドポイントを追加 (#67041)
  • airflowctl PR の RELEASE_NOTES.rst への手動編集を避けるためのコメントを追加 (#67128)
  • airflowctl の Dag capitalization を「DAG」から「Dag」に揃える (#66112)
  • バックフィル作成およびドライランペイロードを JSON として送信 (#65158)
  • airflowctl utils の既存の safe_load 関数を使用してヘルプ テキストをロードする (#65841)
  • 1.0 未満の airflowctl httpx 依存関係をキャップする (#65607)
  • 未使用の airflow-ctl/newsfragments ディレクトリを削除 (#65507)
  • 誤ったフォールバック ロジックを修正 (#64586)
  • 非プロバイダーの mypy チェックを、個別の CI ジョブではなく、通常のコミット前の静的チェックとして実行します (#64780)
  • クリア、成功/失敗のマーク付け、および複数のタスク インスタンスの削除をサポート (#64141)

airflow airflow-ctl/0.1.5

Highlights

  • Required parameters now positional, not --flag (#66768) — The biggest migration risk in this release: auto-generated airflowctl commands now take required primitive parameters as positional arguments, while optional ones keep the --flag form (per the dev-list lazy consensus). Any automation that pins flags for required values will break on upgrade — re-check each command's help output instead of assuming the old signature.
  • Cursor-based pagination on two hot endpoints (#65604, #64845) — get_dag_runs and get_task_instances gain cursor-based paging, which matters once you walk large run/task histories where offset paging gets brittle as rows shift. Clients parsing the old response shape should verify their logic; new integrations get a more stable way to traverse big result sets.
  • Faster operational workflows: new commands and bulk actions (#66172, #66188, #67095, #64141) — dags next execution surfaces upcoming runs, bulk Dag Run deletion plus multi-instance clear/mark-success/mark-failure/delete replace repetitive one-at-a-time calls. Tooling built on loops of single-item requests has a quicker path worth switching to.
  • Clear/rerun now follows a config hierarchy (#63884) — The new rerun_with_latest_version setting changes which code version clear and rerun operations target, and precedence now matters. Teams relying on rerunning tasks against a specific version should audit how their config layers resolve before trusting the default.
  • Core API and backfill reliability expand (#67041, #64644, #65158, #64939) — AIP-103 adds Core API endpoints for task state and asset state, DAG responses gain an is_backfillable flag, backfill create/dry-run payloads are sent as JSON, and backfill params now correctly override an existing DAG run's conf. Watch the payload/content-type shift if you hand-craft backfill requests.
  • Quiet install and CLI unblocks (#65489, #65607, #65608, #67063) — A missing pyyaml runtime dependency is fixed, httpx is capped below 1.0 to avoid incompatible releases, dagrun list no longer crashes when --state is omitted, and connections import schema handling is corrected. Minor on paper, but these remove the failures that blocked fresh installs and everyday CLI calls.

Significant Changes

  • Add dags next execution command (#66172, #66188)
  • Add bulk delete Dag Runs (#67095)
  • Add rerun_with_latest_version config hierarchy for clear/rerun behavior (#63884)
  • Implement patching of task group instances in API (#62812)
  • Allow remote version check without authentication (#65099)
  • Add cursor-based pagination for get_dag_runs endpoint (#65604)
  • Enable queueing new tasks (#63484)
  • Add cursor-based pagination for get_task_instances endpoint (#64845)
  • Add is_backfillable property to DAG API responses (#64644)
  • Expose required primitive parameters of auto-generated commands as positional arguments instead of --flag options. Optional parameters keep the --flag form. Follows the dev-list lazy consensus on airflowctl parameter style (see https://lists.apache.org/thread/m1qvcvow3l17ytv40vhslh40wn3rntrm) (#66768)

Bug Fixes

  • Fix connections import schema handling (#67063)
  • Fix broken download URLs and variable names in docs (#67046)
  • Fix missing pyyaml runtime dependency (#65489)
  • Fix dagrun list crash when --state is omitted (#65608)
  • Fix backfill params not overriding existing DAG run conf (#64939)
  • Fix Ruff issues in client-py (#64868)

Improvements

  • AIP-103: Add Core API endpoints for task state and asset state (#67041)
  • Add comment to avoid manual edits to RELEASE_NOTES.rst in airflowctl PRs (#67128)
  • Align Dag capitalization from "DAG" to "Dag" for airflowctl (#66112)
  • Send backfill create and dry-run payloads as JSON (#65158)
  • Use existing safe_load function in airflowctl utils to load help texts (#65841)
  • Cap airflowctl httpx dependency below 1.0 (#65607)
  • Remove unused airflow-ctl/newsfragments directory (#65507)
  • Fix incorrect fallback logic (#64586)
  • Run non-provider mypy checks as regular pre-commit static checks instead of separate CI jobs (#64780)
  • Support clearing, marking success/failure, and deleting multiple task instances (#64141)
