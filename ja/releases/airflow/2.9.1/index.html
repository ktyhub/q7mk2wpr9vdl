エアフロー 2.9.1

重大な変更

Stackdriver ロギングのバグ修正には Google プロバイダー 10.17.0 以降が必要です (#38071)

Stackdriver Logging を使用する場合は、Google プロバイダのバージョン「10.17.0`` or later. Airflow ``2.9.1`` now passes ``gcp_log_name`` to the ``StackdriverTaskHandler`` instead of ``name」を使用する必要があり、これは以前のプロバイダのバージョンでは失敗します。 これにより、Airflow がログを設定したときに「[logging] remove_base_log_folder」で設定されたログ名が上書きされ、タスク ログが間違った宛先に送信されるというバグが修正されます。

airflow 2.9.1

Highlights

  • Stackdriver logging requires Google provider ≥10.17.0 — The one genuine upgrade hazard in this release (#38071): Airflow now passes gcp_log_name to StackdriverTaskHandler instead of name, which raises on older provider versions, so bump the provider in lockstep with 2.9.1 or task logging breaks. The upside is that the log name configured via [logging] remove_base_log_folder is no longer overwritten during logging setup, fixing logs landing in the wrong destination.

  • Trigger-kwarg encryption migration repaired — The decryption failures that could stall a 2.9.x upgrade are addressed across #39246, #39361, and #39374. This matters most for deferred operators/triggerers with encrypted trigger_kwargs: it clears the upgrade blocker and makes the triggerer path safe to roll out.

  • TriggerDagRunOperator: execution_date → logical_date — Deprecated in favor of logical_date (#39285). This aligns with Airflow 2.x "logical date" terminology; update any DAGs still passing execution_date, and expect a warning now and removal in a future release.

  • BaseXCom.get_one un-deprecated (for now) — The removal plan is paused (#38991), so code calling get_one gets a reprieve—don't spend migration cycles on it yet, but treat it as temporary since it can be re-deprecated later.

  • Log and mapped-task observability changes — Task log message lines now include run_id (#39280), so any log parsers or grep filters keyed to the old format need adjusting. map_index_template now renders for failed tasks as long as it was defined before the failure point (#38902), and task-instance log_url switches to grid view (#39183), both easing debugging of mapped tasks.

  • Python 3.12 signaled; auth and CLI polish — Python 3.12 is added to Trove classifiers (#39004), a practical signal to begin runtime upgrade planning. Also relevant if you run custom auth managers or public-role setups: AUTH_ROLE_PUBLIC is now checked in check_authentication (#39012) and is_authorized_custom_view handles custom actions (#39167). Separately, airflow dags backfill only emits its deprecation warning when -I/--ignore-first-depends-on-past is supplied (#38676), cutting warning noise.

Significant Changes

Stackdriver logging bugfix requires Google provider 10.17.0 or later (#38071)

If you use Stackdriver logging, you must use Google provider version 10.17.0 or later. Airflow 2.9.1 now passes gcp_log_name to the StackdriverTaskHandler instead of name, and this will fail on earlier provider versions.

This fixes a bug where the log name configured in [logging] remove_base_log_folder was overridden when Airflow configured logging, resulting in task logs going to the wrong destination.
