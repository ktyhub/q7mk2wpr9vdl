バグ修正

  • 内部通信プロトコルを改善することで、大きなデータによるタスクの実行エラーを修正しました (#51924、#53194)
  • 長時間にわたる複数回の再キュー試行後に失敗する再スケジュールセンサーを修正 (#52706)
  • マッピングされたタスクのさまざまなシナリオをカバーするために xcom_pull を改善 (#51568)
  • スキーマフィールドが使用されている場合のトリガーでの接続取得エラーを修正 (#52691)
  • タスク実行のためのユーザー偽装 (run_as_user) サポートを追加 (#51780)
  • DAG 構造を変更せずにバンドル名を変更すると DAG バージョンが更新されない問題を修正 (#51939)
  • exception をタスク コールバックのコンテキストに追加し直す (#52066)
  • 再試行のタスクログ取得で間違ったログが表示される問題を修正 (#51592)
  • シリアル化中の AIP-39 より前に作成された DAG のデータ間隔処理を修正しました (#51913)
  • EOF が欠落した場合に残るタスク スーパーバイザーを修正 (#51180) (#51970)
  • シリアル化中に EventsTimetable の説明を保持する (#51926)
  • DAG バンドルが非アクティブになった場合の削除インポート エラー (#51921)
  • DB 移行中のインポート エラーのクリーンアップ (#51919)
  • Dag プロセッサのサブプロセスの EOF 検出を修正 (#51895)
  • ログの終わりマークが欠落している場合、タスク ログのストリーミングを停止する (#51482)
  • ログストリーミングを停止する前に空のループをさらに許可する (#52624)
  • dag.test による Jinja2 テンプレートのディープ コピー エラーを修正 (#51673)
  • 監視機能でログファイル記述子を明示的に閉じる (#51654)
  • 構造化されたログ形式とレイアウトを改善 (#51567) (#51626)
  • 接続 ID の代わりにドロップダウンに接続フック名を使用する (#51613)

airflow 3.0.3

Highlights

  • Release type & upgrade call — 3.0.3 is a bug-fix-only patch over 3.0.2 (plus misc/doc changes), with no breaking changes and no migration steps; it's a low-risk drop-in. Anyone running Airflow 3.0.x should upgrade, especially if hit by the execution, mapping, or UI issues below. Teams still on 2.x can skip unless they're doing the 2.7.0 → 3.0.0 SQLite migration, which is fixed here (#51431). Not a no-op or re-tag.

  • Restored 3.0 regressions — This release explicitly "adds back" three things 3.0 dropped: user impersonation via run_as_user for task execution (#51780), exception in the task callback context (#52066), and the config setting controlling stacktrace exposure (#51617). If you omitted 3.0.0 precisely because these broke your tasks or debugging workflow, this is the main reason to move now.

  • Task execution reliability & large payloads — The internal communication protocol was reworked to stop task failures with large data (#51924, #53194), alongside fixes for lingering task supervisors and missed EOF detection (#51180, #51970, #51895, #51654), reschedule sensors failing after repeated re-queues over long periods (#52706), and triggerer connection retrieval when a schema field is used (#52691). These target silent/hard-to-diagnose runtime failures, so long-running or high-throughput deployments benefit most.

  • Mapped tasks & dynamic mapping — Several mapping/trigger edge cases are corrected: xcom_pull across mapped-task scenarios (#51568), start_from_trigger with MappedOperator (#52681), trigger expansion logic gating on start_from_trigger (#52873), a bad cadwyn migration for upstream map indexes (#52797), and XCom.get_all() deserialization (#53102). Also notable: DAG versions now update when a bundle name changes without structural changes (#51939), and pre-AIP-39 DAGs serialize their data intervals correctly (#51913) — relevant if you use DAG bundles or migrated older DAGs.

  • UI, API & observability polish — Grid view gets meaningful perf/responsiveness and refresh fixes (#52718, #52822, #52919, #53086), backfill creation now honors run-backwards and DAG-run config from the form (#52168, #51584), and connection dropdowns use Connection Hook Names instead of IDs (#51613). Logging is cleaner too: structured log format/layout improvements (#51567, #51626), correct retry-attempt and skipped-task logs (#51592, #53028, #53101), and reduced noise when fetching connections/variables (#51826) — worthwhile for anyone living in the UI or debugging logs daily.
