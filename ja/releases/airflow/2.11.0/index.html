airflow 2.11.0

エアフロー 2.11.0

重大な変更

トリガーベースのスケジューリング用の DeltaTriggerTimetable (#47074)

この変更により、既存の一連のタイムテーブルを補完する新しい組み込みタイムテーブルである DeltaTriggerTimetable が導入されます。 データ間隔に依存せず、デルタベースのトリガー スケジュールをサポートすることによるエアフロー タイムテーブル。 Airflow には現在、主に 2 種類のタイムテーブルがあります。

  • データ間隔ベース (例: CronDataIntervalTimetable, DeltaDataIntervalTimetable)
  • トリガーベース (例: CronTriggerTimetable) ただし、「timedelta(days=1)」のようなデルタ間隔に対する同等のトリガーベースのオプションはありませんでした。 その結果、「schedule=timedelta(days=1)」のような単純なスケジュールでも、データ間隔を通じて解釈されてしまいました。 レンズ - 上流/下流のデータ依存関係を気にしないユーザーにとっては不必要な複雑さが加わります。 この機能は、ユーザーが Airflow 3.0 にアップグレードする前に移行を開始できるように、Airflow 2.11.0 にバックポートされています。
  • エアフロー 2.11 では、schedule=timedelta(...) still defaults to DeltaDataIntervalTimetable。
  • 新しい設定オプション [scheduler] create_delta_data_intervals (default: True) allows opting in to DeltaTriggerTimetable。
  • Airflow 3.0 では、この設定のデフォルトである False, meaning DeltaTriggerTimetable が、timedelta スケジュールのデフォルトになります。 2.11 でこの構成を反転することで、ユーザーは新しいスケジュール動作を事前にプレビューして採用することができ、アップグレード中の予期せぬ事態を最小限に抑えることができます。

すべてのバックエンドにわたる一貫したタイミング メトリクス (#39908、#43966)

以前は、Airflow は「StatsD」についてはミリ秒単位でタイミング メトリクスを報告していましたが、他のバックエンドについては秒単位で報告していました。 「OpenTelemetry`` and ``Datadog」など。この矛盾により、解釈や比較が困難になりました システム全体のタイミングメトリクス。 Airflow 2.11 には、新しい構成オプションが導入されています。

  • [metrics] timer_unit_consistency (default: False in 2.11, True およびエアフロー 3.0) にドロップされました。 有効にすると、バックエンドに関係なく、すべてのタイミング メトリックが一貫してミリ秒単位でレポートされます。 この設定は必須となり、Airflow 3.0 では常に True になります (設定は削除されます)。 2.11 でこれを有効にすると、ユーザーは早期に移行でき、アップグレード中の予期せぬ事態を回避できます。

Airflow 3 への移行を容易にする

このリリースでは、ユーザーが Airflow 3 へのアップグレードの準備をするのに役立ついくつかの変更が導入されています。

  • execution_date now also include a logical_date field. Airflow 3 drops execution_date entirely in favor of logical_date (#44283) を使用するすべてのモデル
  • Airflow 3.0 の構成の監査と移行を支援するために、2.11 に「airflow config lint`` and ``airflow config update」コマンドを追加しました。 (#45736、#50353、#46757)

Python 3.8 のサポートが削除されました

Python 3.8 はサポートが終了したため、サポートが削除されました。 エアフロー 2.11 には、Python 3.9、3.10、3.11、または 3.12 が必要です。

新機能

  • DeltaTriggerTimetable (#47074) を紹介します。
  • Airflow 3 への移行を容易にするためのバックポート「airflow config update`` and ``airflow config lint」の変更 (#45736、#50353)
  • DAG 依存関係ビューで DAG 内のタスクを表示するリンクを追加 (#47721)
  • すべてのメトリクス ロガーにわたってタイマーとタイミング メトリクス (ミリ秒) を調整します (#39908、#43966)

バグ修正

  • ti.log_url timestamp format from "%Y-%m-%dT%H:%M:%S%z" to "%Y-%m-%dT%H:%M:%S.%f%z" を修正 (#50306)

  • UI: /xcom/list got exception when applying filter on the value 列 (#46053)
  • 実験的な内部 api (#47769) を介してノートフィールドを設定できるようにします

その他

  • logical_date to models using execution_date を追加 (#44283)
  • Python 3.8 のサポートを終了 (#49980、#50015)
  • 非推奨の BaseOperatorLink.get_link シグネチャに対する警告を出力する (#46448)

  • エグゼキュータ airflow.cfg 変数の引用符を外します (#48084)
  • XCom docs to show examples of pushing multiple XComs を更新 (#46284、#47068)

airflow 2.11.0

Highlights

  • Python 3.8 support removed — Airflow 2.11 requires Python 3.9–3.12. Upgrade the runtime before upgrading Airflow; environments still on Python 3.8 will not be supported (#49980, #50015).
  • Preview Airflow 3 delta scheduling — schedule=timedelta(...) still uses DeltaDataIntervalTimetable by default in 2.11. Set [scheduler] create_delta_data_intervals=False to opt into the new DeltaTriggerTimetable, which schedules without data intervals; Airflow 3 makes this behavior the default (#47074).
  • Normalize timing metrics before upgrading — Enable [metrics] timer_unit_consistency=True to report all timing metrics in milliseconds. This resolves the previous split where StatsD used milliseconds while OpenTelemetry and Datadog used seconds; check dashboard thresholds and alerts for unit assumptions (#39908, #43966).
  • Migrate from execution_date to logical_date — Models that expose execution_date now also include logical_date. Update plugins, templates, and custom code to use logical_date before Airflow 3 removes execution_date entirely (#44283).
  • Audit configuration with the new CLI commands — Use airflow config lint to identify configuration requiring attention and airflow config update to assist migration. Review configuration changes before applying them to avoid unexpected production behavior (#45736, #50353, #46757).

Significant Changes

DeltaTriggerTimetable for trigger-based scheduling (#47074)

This change introduces DeltaTriggerTimetable, a new built-in timetable that complements the existing suite of Airflow timetables by supporting delta-based trigger schedules without relying on data intervals.

Airflow currently has two major types of timetables:

  • Data interval-based (e.g., CronDataIntervalTimetable, DeltaDataIntervalTimetable)
  • Trigger-based (e.g., CronTriggerTimetable)

However, there was no equivalent trigger-based option for delta intervals like timedelta(days=1). As a result, even simple schedules like schedule=timedelta(days=1) were interpreted through a data interval lens—adding unnecessary complexity for users who don't care about upstream/downstream data dependencies.

This feature is backported to Airflow 2.11.0 to help users begin transitioning before upgrading to Airflow 3.0.

  • In Airflow 2.11, schedule=timedelta(...) still defaults to DeltaDataIntervalTimetable.
  • A new config option [scheduler] create_delta_data_intervals (default: True) allows opting in to DeltaTriggerTimetable.
  • In Airflow 3.0, this config defaults to False, meaning DeltaTriggerTimetable becomes the default for timedelta schedules.

By flipping this config in 2.11, users can preview and adopt the new scheduling behavior in advance — minimizing surprises during upgrade.

Consistent timing metrics across all backends (#39908, #43966)

Previously, Airflow reported timing metrics in milliseconds for StatsD but in seconds for other backends such as OpenTelemetry and Datadog. This inconsistency made it difficult to interpret or compare timing metrics across systems.

Airflow 2.11 introduces a new config option:

  • [metrics] timer_unit_consistency (default: False in 2.11, True and dropped in Airflow 3.0).

When enabled, all timing metrics are consistently reported in milliseconds, regardless of the backend.

This setting has become mandatory and always True in Airflow 3.0 (the config will be removed), so enabling it in 2.11 allows users to migrate early and avoid surprises during upgrade.

Ease migration to Airflow 3

This release introduces several changes to help users prepare for upgrading to Airflow 3:

  • All models using execution_date now also include a logical_date field. Airflow 3 drops execution_date entirely in favor of logical_date (#44283)
  • Added airflow config lint and airflow config update commands in 2.11 to help audit and migrate configs for Airflow 3.0. (#45736, #50353, #46757)

Python 3.8 support removed

Support for Python 3.8 has been removed, as it has reached end-of-life. Airflow 2.11 requires Python 3.9, 3.10, 3.11, or 3.12.

New Features

  • Introduce DeltaTriggerTimetable (#47074)
  • Backport airflow config update and airflow config lint changes to ease migration to Airflow 3 (#45736, #50353)
  • Add link to show task in a DAG in DAG Dependencies view (#47721)
  • Align timers and timing metrics (ms) across all metrics loggers (#39908, #43966)

Bug Fixes

  • Don't resolve path for DAGs folder (#46877)
  • Fix ti.log_url timestamp format from "%Y-%m-%dT%H:%M:%S%z" to "%Y-%m-%dT%H:%M:%S.%f%z" (#50306)
  • Ensure that the generated airflow.cfg contains a random fernet_key and secret_key (#47755)
  • Fixed setting rendered_map_index via internal api (#49057)
  • Store rendered_map_index from TaskInstancePydantic into TaskInstance (#48571)
  • Allow using log_url property on TaskInstancePydantic (Internal API) (#50560)
  • Fix Trigger Form with Empty Object Default (#46872)
  • Fix TypeError when deserializing task with execution_timeout set to None (#46822)
  • Always populate mapped tasks (#46790)
  • Ensure check_query_exists returns a bool (#46707)
  • UI: /xcom/list got exception when applying filter on the value column (#46053)
  • Allow to set note field via the experimental internal api (#47769)

Miscellaneous

  • Add logical_date to models using execution_date (#44283)
  • Drop support for Python 3.8 (#49980, #50015)
  • Emit warning for deprecated BaseOperatorLink.get_link signature (#46448)

Doc Only Changes

  • Unquote executor airflow.cfg variable (#48084)
  • Update XCom docs to show examples of pushing multiple XComs (#46284, #47068)
