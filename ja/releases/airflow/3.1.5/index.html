airflow 3.1.5

Highlights

  • Security and secret handling — Fix invalid JWT handling in JWTRefreshMiddleware (#56904) and close secret-exposure paths through deprecated import paths (#58726), illegal-argument kwargs (#58283), and rendered UI templates (#58772). Prioritize upgrading if you expose Airflow’s UI/API or render sensitive task data.
  • Scheduler and task reliability — Fix the max_active_runs backfill race with concurrent schedulers (#58935), deadline pruning for duplicate run_ids (#58910), retries across all exit codes (#58478), and TriggerDagRunOperator remaining deferred with reset_dag_run=True (#58333). Also repairs pre-AIP-39 run handling (#58773) and supervisor reconnects for dag.test() and task subprocesses (#58266, #58263).
  • DAG and asset correctness — Stabilize DAG hashes containing unordered dict template fields (#59091, #59175), prevent orphaned DAG versions through atomic SerializedDagModel.write_dag (#58281), preserve Asset.extra via AssetAlias (#58712), and stop inlet-only assets being orphaned (#58986). Additional fixes cover falsy default_args (#58396), connections without conn_type (#58664), and Pydantic string-to-datetime conversion (#58916).
  • Resource use and UI — gc.freeze reduces LocalExecutor memory spikes (#58934). UI fixes add a grid-query count guard (#57977, #58632), repair a task-instance tab memory leak (#58557), and correct HITL rendering, timezone handling, backfill timing, and failed-task extra links. This matters most for LocalExecutor deployments and large or heavily used grids.
  • Upgrade assessment — This is a substantive bug-fix release, not a re-tag or metadata-only update, despite “No significant changes.” No breaking changes or required migration steps are listed; the Airflow 2 database-access migration guide (#57479) is documentation-only. Affected deployments should upgrade, while stable installations unaffected by these fixes can follow their normal patch cadence.
