エアフロー 3.2.2

📦 PyPI: https://pypi.org/project/apache-airflow/3.2.2/ 📚 ドキュメント: https://airflow.apache.org/docs/apache-airflow/3.2.2/ 🛠 Release Note: https://airflow.apache.org/docs/apache-airflow/3.2.2/release_notes.html 🐳 Docker 画像: 「docker プル アパッチ/エアフロー:3.2.2」 🚏 制約: https://github.com/apache/airflow/tree/constraints-3.2.2

重大な変更

  • airflow.utils.email.send_email now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the starttls() 呼び出しによって実行された SMTP STARTTLS アップグレードは SSL コンテキストなしで行われたため、あらゆる証明書が受け入れられました。 自己署名証明書または非検証証明書を使用して SMTP サーバーを意図的に Airflow に向け、以前の動作を保持する必要がある展開では、email.ssl_context = "none" in airflow.cfg. The "default" value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the SMTP_SSL パスを設定する必要があります。これは STARTTLS パスにも適用されるようになりました。 (#65346)

  • #64963 では、完全一致の *_pattern REST API query parameters to the new index-friendly *_prefix_pattern parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (LIKE 'term%' via a range scan) instead of substring-based (ILIKE '%term%'), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing *_pattern パラメーターから切り替えられた Airflow UI は依然として以前とまったく同じように動作します。 #66015 では、検索バーごとの「どこでも一致」トグルが追加され、以前の部分文字列の動作に依存していたユーザーが UI からその動作を選択できるようになりました。各検索入力と各テキスト フィルターの錠剤には、値の横に小さな正規表現アイコンの切り替えが表示されます。 「*_prefix_pattern`` to ``*_pattern」から入力するスイッチをオンにします。 (#66015)

  • 遅延タスクが無期限に停止する原因となったトリガーの競合状態とデッドロックを修正

    同期 SDK メソッド (例: によって使用される get_task_states) を呼び出すトリガー いくつかの Google プロバイダー オペレーターの「safe_to_cancel」) は、トリガーのクラッシュを引き起こす可能性があります。 内部サブプロセス。 その後、トリガーは通常どおりハートビートを継続します。 スケジューラーには正常に見えますが、トリガーは何も発生せずに処理されているため、 すべての遅延タスクがタイムアウトになります。 これは問題 #64620 で最初に報告されました。ある 部分的な修正は Airflow 3.2.1 (#64882) で同梱されましたが、新たなデッドロックが発生しました 負荷がかかると同じ目に見える症状が発生します。

    どちらの問題も、ロックベースのシリアル化を応答に置き換えることによって修正されます。 多重化: 各リクエストには一意の ID が付けられ、レスポンスは再度ルーティングされます。 正しい呼び出し元であるため、トリガー スレッドからの同時リクエストが競合しなくなるか、 実行中のトリガーの数や呼び出される SDK メソッドに関係なく、デッドロックが発生します。

    新機能: トリガー サブプロセス ウォッチドッグ

    レースが修正されていても、イベント ループをブロックするトリガー (例: time.sleep() or performing blocking I/O directly in async def run()) 以前はトリガーを無期限に正常に見せたままにしておきました。

    新しい「[triggerer] runner_health_check_threshold」設定オプション (デフォルト: 30 秒) ウォッチドッグを追加します。トリガーのサブプロセスがしきい値よりも長く沈黙した場合、 親プロセスはハートビートの更新を停止するため、スケジューラはハングを検出し、 トリガーが個別にタイムアウトするのを待つのではなく、トリガーを再割り当てします。 オプションを設定する 0 に設定してウォッチドッグを無効にします。 (#66412)

  • [core] allowed_deserialization_classes_regexp を厳密にして、完全な文字列一致を要求します

    [core] allowed_deserialization_classes_regexp のパターンが一致するようになりました re.fullmatch() instead of re.match() を使用してクラス名全体に対して。 以前は「airflow\.models\.Variable」のようなパターンが認められていましたが、 対象のクラスだけでなく、それで始まる名前も (例: airflow.models.Variable_Malicious), because re.match のみアンカー 文字列の先頭に。

    このオプションのデフォルト値は空であるため、すぐに使用できるデプロイメントは 影響を受けません。依存するパターンを使用してこのオプションを構成したデプロイメント 接頭辞一致セマンティクス - たとえば、「任意のクラス」を意味する「airflow\.models\.」 airflow.models" — must add .*の下をパターンに (airflow\.models\..*) 以前の動作を保持します。 (#66499)

  • カスタム期限参照クラスは、逆シリアル化時に新しい deadline_references attribute on AirflowPlugin, matching the existing pattern for custom timetables and custom partition mappers. To use a custom DeadlineReference subclass, register it in a plugin's deadline_references list. Custom references that are not registered will raise DeadlineReferenceNotRegistered を介して登録する必要があります。 (#66737)

airflow 3.2.2

Highlights

  • Triggerer deadlock fix and subprocess watchdog — Deferred tasks could hang forever when a triggerer subprocess crashed while the parent kept heartbeating as healthy; first reported in #64620, a partial 3.2.1 fix (#64882) traded the race for a load-dependent deadlock with the same symptom. #66412 replaces lock-based serialization with response multiplexing (unique request IDs routed back to the correct caller), and adds [triggerer] runner_health_check_threshold (default 30s): if the subprocess goes silent, heartbeats stop so the scheduler reassigns triggers instead of waiting for every deferred task to time out. Set it to 0 to disable, but tune it if you legitimately run long blocking calls — a slow trigger can now be flagged unhealthy.

  • SMTP STARTTLS now verifies certificates — #65346 makes email.ssl_context apply to the STARTTLS path, validating against the system CA bundle by default via ssl.create_default_context; previously starttls() ran with no SSL context and accepted any cert. Self-signed or internal SMTP relays will begin failing TLS handshakes after upgrade. If you must preserve the permissive behavior, explicitly set email.ssl_context = "none" in airflow.cfg. Note the option now governs both STARTTLS and SMTP_SSL, so this is a genuine security fix with a real behavioral cost for private mail servers.

  • UI search is prefix-based now — #64963 switched list-endpoint UI filters from substring matching (*_pattern, ILIKE '%term%') to index-friendly prefix matching (*_prefix_pattern, LIKE 'term%' range scans), letting B-tree indexes keep search fast on large metadata databases. The REST API keeps both parameter forms with unchanged semantics, and #66015 adds a per-search-bar / per-filter-pill "Match anywhere" toggle (regex icon) to opt a given input back into substring matching. Expect user reports that searching in the middle of a DAG ID no longer finds matches — the toggle is the answer, not a rollback.

  • Deserialization allowlist regexes require full matches — #66499 changes [core] allowed_deserialization_classes_regexp from re.match() to re.fullmatch(), closing an escape where airflow\.models\.Variable also admitted names like airflow.models.Variable_Malicious. The default is empty, so out-of-the-box installs are unaffected, but anyone using prefix-style patterns such as airflow\.models\. to mean "any class under this namespace" must append .* (airflow\.models\..*) or legitimate classes will start being rejected at deserialization.

  • Custom deadline references must be registered — #66737 aligns DeadlineReference with the existing timetable and partition-mapper patterns: custom subclasses now have to be listed in the new deadline_references attribute of an AirflowPlugin, and unregistered ones raise DeadlineReferenceNotRegistered at deserialization. If you ship custom deadline logic, this is a required migration — audit your plugins before upgrading, or DAG parsing will fail on those references.

  • Tighter auth defaults across API and UI — A cluster of hardening fixes shifts the security posture: default-deny at the API and UI router level (#67171), JWT revoked on /auth/logout regardless of the auth-manager logout URL (#67362), and refusing secrets-backend fallback on Execution-API authorization denials (#67173), plus starlette>=1.0.1 required for the Host-header parsing fix (#67460). If you depend on permissive fallbacks or custom auth managers, exercise those flows after upgrading — previously silent denials will now be enforced.

Significant Changes

  • The SMTP STARTTLS upgrade performed by airflow.utils.email.send_email now validates the SMTP server's certificate against the system's trusted CA bundle by default. Previously the starttls() call was made without an SSL context, so any certificate was accepted. Deployments that intentionally point Airflow at an SMTP server with a self-signed or otherwise non-validating certificate and need to preserve the previous behaviour must set email.ssl_context = "none" in airflow.cfg. The "default" value (now also the default when the option is unset) uses :func:ssl.create_default_context. Previously this option applied only to the SMTP_SSL path; it now applies to the STARTTLS path as well. (#65346)

  • In #64963, the Airflow UI switched from full-match *_pattern REST API query parameters to the new index-friendly *_prefix_pattern parameters on list endpoints. This is a behavioral change for search-as-you-type filters in the UI: matches are prefix-based (LIKE 'term%' via a range scan) instead of substring-based (ILIKE '%term%'), which means the database can use B-tree indexes and search stays fast on large deployments. The REST API itself keeps both forms: existing *_pattern parameters still behave exactly as before. In #66015, a per-search-bar "Match anywhere" toggle was added so users who relied on the previous substring behavior can opt back into it from the UI. Each search input and each text filter pill now has a small regex-icon toggle next to the value; flipping it on switches that input from *_prefix_pattern to *_pattern. (#66015)

  • Fix triggerer race condition and deadlock that caused deferred tasks to stall indefinitely

    Triggers that call synchronous SDK methods (e.g. get_task_states used by safe_to_cancel in several Google provider operators) could crash the triggerer's internal subprocess. The triggerer would then continue to heartbeat normally — appearing healthy to the scheduler — while silently processing zero triggers, causing every deferred task to time out. This was first reported in issue #64620; a partial fix shipped in Airflow 3.2.1 (#64882) but introduced a new deadlock with the same visible symptom under load.

    Both issues are fixed by replacing the lock-based serialization with response multiplexing: each request now carries a unique ID and the response is routed back to the correct caller, so concurrent requests from trigger threads no longer contend or deadlock regardless of how many triggers are running or what SDK methods they call.

    New: triggerer subprocess watchdog

    Even with the race fixed, a trigger that blocks the event loop (e.g. by calling time.sleep() or performing blocking I/O directly in async def run()) would previously leave the triggerer appearing healthy indefinitely.

    A new [triggerer] runner_health_check_threshold config option (default: 30 seconds) adds a watchdog: if the triggerer subprocess goes silent for longer than the threshold, the parent process stops updating the heartbeat so the scheduler can detect the hang and reassign triggers rather than waiting for them to individually time out. Set the option to 0 to disable the watchdog. (#66412)

  • Tighten [core] allowed_deserialization_classes_regexp to require full-string matches

    Patterns in [core] allowed_deserialization_classes_regexp are now matched against the entire classname using re.fullmatch() instead of re.match(). Previously a pattern such as airflow\.models\.Variable admitted not only the intended class but also names that started with it (e.g. airflow.models.Variable_Malicious), because re.match only anchors at the start of the string.

    The default value of this option is empty, so out-of-the-box deployments are unaffected. Deployments that configured this option with patterns relying on prefix-match semantics — for example airflow\.models\. to mean "any class under airflow.models" — must add .* to the pattern (airflow\.models\..*) to retain the previous behaviour. (#66499)

  • Custom deadline reference classes must now be registered via the new deadline_references attribute on AirflowPlugin, matching the existing pattern for custom timetables and custom partition mappers. To use a custom DeadlineReference subclass, register it in a plugin's deadline_references list. Custom references that are not registered will raise DeadlineReferenceNotRegistered at deserialization. (#66737)
