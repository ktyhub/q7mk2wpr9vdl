エアフローヘルムチャート/1.20.0

重大な変更

Apache Airflow の古いバージョン <2.11 のサポートは終了しました (#61018)

Apache Airflow のサポートされる最小バージョンは 2.11.0 になりました。をデプロイしたい場合は、 Apache Airflow の古いバージョンの場合は、最後にリリースされたバージョンのチャート 1.19.0 を使用してください。

workers specific sections have been moved to workers.celery / workers.kubernetes セクション

それに応じて構成を更新してください。

  • workers.command command is now deprecated in favor of workers.celery.command/workers.kubernetes.command (#60067)。
  • workers.securityContexts command is now deprecated in favor of workers.celery.securityContexts/workers.kubernetes.securityContexts (#60396)。
  • workers.containerLifecycleHooks command is now deprecated in favor of workers.celery.containerLifecycleHooks/workers.kubernetes.containerLifecycleHooks (#61369)。
  • workers.kerberosSidecar section is now deprecated in favor of workers.celery.kerberosSidecar/workers.kubernetes.kerberosSidecar (#61881)。
  • workers.kerberosInitContainer section is now deprecated in favor of workers.celery.kerberosInitContainer/workers.kubernetes.kerberosInitContainer (#60751)。
  • workers.terminationGracePeriodSeconds command is now deprecated in favor of workers.celery.terminationGracePeriodSeconds/workers.kubernetes.terminationGracePeriodSeconds (#61892)。
  • workers.nodeSelector command is now deprecated in favor of workers.celery.nodeSelector/workers.kubernetes.nodeSelector (#61957)。 *「workers.podDisruptionBudget`` section is now deprecated in favor of ``workers.celery.podDisruptionBudget」。それに応じて構成を更新してください。 (#61414) *「workers.keda`` section is now deprecated in favor of ``workers.celery.keda」。それに応じて構成を更新してください。 (#61820) *「workers.resources`` section is now deprecated in favor of ``workers.celery.resources`` and ``workers.kubernetes.resources」。それに応じて構成を更新してください。 (#61890)

以前の構成オプションは引き続き機能しますが、非推奨となり、将来のバージョンでは削除される予定です。

Git-Sync はサービスタイプのオブジェクトではないため、readiness Probe は削除されます。 (#62334)

機能の動作を有効にするには、「dags.gitSync.recommendedProbeSetting`` to ``true」を設定します。アップグレード中にセットアップが中断されないように、セクション自体は将来のリリースで削除される予定です。

Git-Sync には専用の liveness サービスがあるため、liveness プローブの動作が変更されます。機能の動作を有効にするには、dags.gitSync.recommendedProbeSetting to true を設定します。

それに応じて構成を更新してください。

自動環境変数が container_extra_envs and custom_airflow_environment から削除されました (#60750)

Kubernetes Executor 環境変数とシークレットの自動プレフィックス追加は、両方の container_extra_envs and custom_airflow_environment ヘルパー関数から削除されました。

変更点:

以前は、コンポーネント固有の設定に環境変数を追加した場合 (例: .Values.scheduler.env), the chart automatically created an additional environment variable (to specified in the env section) with the AIRFLOW__KUBERNETES_ENVIRONMENT_VARIABLES__ prefix for Kubernetes Executor worker pods. After this change, only the variable specified in env セクションが作成されていました)。 さらに、.Values.secret section, the AIRFLOW__KUBERNETES_SECRETS__ prefix is no longer automatically added. Secrets are now passed as-is via secretKeyRef で指定された値の場合は、ワーカー ポッドのプレフィックス付きコピーは付けられません。

この変更の理由:

  • 「client_secret`` information. Previously, due to prefix, it was recognized as internal Airflow configuration leading to unintended exposure in Airflow UI (under Admin -> Configuration), even when ``AIRFLOW__API__EXPOSE_CONFIG`` is set to ``non-sensitive-only」のような機密データの意図しない公開を防ぎます。
  • ワーカーへの意図しない環境伝播を回避します。コンポーネント固有の環境設定は、厳密に特定のコンポーネントを対象としています。以前の動作では、これらの変数がワーカー ポッドに渡されるため、構成の競合や予期しない副作用が発生する可能性がありました。

移行が必要です:

環境変数を特に Kubernetes Executor ワーカー ポッドに渡す必要がある場合は、次のいずれかの方法を使用します。

オプション 1: .Values.env を使用します

.. コードブロック:: yaml

環境:
  - 名前: my_var
    値: "my_value"

.Values.env で指定された環境変数は、自動プレフィックスなしでそのまま渡されるようになりました (コンポーネント固有の env と同じ動作)。

オプション 2: .Values.config.kubernetes_environment_variables を使用します

.. コードブロック:: yaml

構成:
  kubernetes_環境変数:
    my_var: "my_value"

デフォルトのエアフロー画像が 3.1.8 に更新されました (#63392)

チャートで使用されるデフォルトのエアフロー画像は「3.1.8``, previously it was ``3.1.7」になりました。

機能

  • podAnnotations and airflowPodAnnotations 値で Helm テンプレート式をサポート (#63019)
  • ログクリーンスクリプトに分レベルのログ保持を追加 (#61855)
  • LOG_MAX_SIZE 環境変数をログ グルーマーに追加 (#61559)

改善点

  • チャートヘルパーから自動 KUBERNETES_ENVIRONMENT_VARIABLES and KUBERNETES_SECRETS プレフィックスを削除 (#60750)
  • JWT シークレットをトリガー、ワーカー、DAG プロセッサーから削除 (#63204)
  • workers.celery.nodeSelector & workers.kubernetes.nodeSelector を追加 (#61957)
  • workers.celery.terminationGracePeriodSeconds & workers.kubernetes.terminationGracePeriodSeconds を追加 (#61892)
  • workers.celery.resources & workers.kubernetes.resources を追加 (#61890)
  • workers.celery.keda セクションを追加 (#61820)
  • workers.celery.podDisruptionBudget を追加 (#61414)
  • workers.celery.containerLifecycleHooks & workers.kubernetes.containerLifecycleHooks を追加 (#61369)
  • Git-Sync livenessProbe & deprecate readinessProbe & add startupProbe をリファクタリングする (#62334)
  • 非推奨のコンポーネントごとの securityContext 値について警告する (#62729)
  • apiServer, statsd, and pgbouncer に対するイングレス非推奨警告を追加 (#62490)
  • 不足しているサポートを追加: securityContexts and containerLifecycleHook (#60677)

バグ修正

  • より制限的なチャートレンダリングロジック (#63464)
  • HPA が有効な場合、api-server spec.replicas を省略します (#63187)
  • workers.celery.kerberosSidecar & workers.kubernetes.kerberosSidecar セクションを追加 (#61881)
  • 秘密キーなしでのみ非推奨の警告を表示するチャートNOTES.txtを修正しました (#62722)
  • Ingress テンプレートの TLS ホストの tpl レンダリングを修正 #62358 (#62548)
  • webserver.defaultUser.enabled=false が無視される問題を修正 (#62143)

ドキュメントのみが変更されます

  • Helm Chart ドキュメントのクリーンアップ (#62544)
  • ワーカーセクションに欠落している非推奨警告を追加 (#63659)

その他

  • Helm Chart で 2.11 以下のすべての Airflow バージョンのサポートを削除 (#61018)
  • デフォルトのエアフロー バージョンは 3.1.8 (#63392)
  • すべてのディストリビューションの .gitignore に *.iml を追加 (#63636)
  • 重要な CI 環境をアップグレードする (#62792、#62610)
  • 選択したファイルに短い SPDX ライセンス識別子の使用を許可 (#62073)
  • 推移的な依存関係を含むすべてのビルドシステム/要件を修正 (#62570)

airflow helm-chart/1.20.0

Highlights

  • Worker settings are now executor-specific — Move shared workers.* settings into workers.celery.* or workers.kubernetes.*, including resources, node selectors, security contexts, lifecycle hooks, Kerberos, and termination grace periods; PDB and KEDA settings move under workers.celery (for example, #61890, #61957, #61820). Legacy keys still work but are deprecated, so update values overlays before the next chart removes them.

  • Worker environment and secret propagation changed — container_extra_envs and custom_airflow_environment no longer add AIRFLOW__KUBERNETES_ENVIRONMENT_VARIABLES__ or AIRFLOW__KUBERNETES_SECRETS__ copies (#60750). Component-specific variables stay on that component, reducing accidental exposure and configuration conflicts. To inject values into Kubernetes Executor pods, define them under .Values.env or .Values.config.kubernetes_environment_variables instead of relying on the old automatic behavior.

  • Git-Sync probe defaults require attention — Readiness probing is deprecated, liveness behavior changes, and a startup probe is added (#62334). Set dags.gitSync.recommendedProbeSetting: true to select the recommended probe configuration; otherwise explicitly review DAG startup detection during the upgrade.

  • Airflow 2.11 is the new minimum — Deployments on older Airflow versions must stay on chart 1.19.0 (#61018). The default image moves to Airflow 3.1.8 (#63392), so pin and validate your application image separately if you are not ready to adopt that runtime.

  • Helm templating reaches pod annotations — podAnnotations and airflowPodAnnotations now support Helm template expressions (#63019), enabling dynamic metadata without extra manifests. Tighter rendering logic (#63464) and a fix for TLS host templating in ingress (#62548) also make complex overlays more reliable, but warrant regression-testing rendered manifests.

  • Existing installation pitfalls are fixed — webserver.defaultUser.enabled=false is now honored (#62143), HPA-enabled API servers omit an explicit replica count (#63187), and sensitive JWT secrets are removed from triggerer, worker, and dag-processor containers (#63204), reducing unnecessary secret distribution.

  • No breaking API changes, but the support-floor and environment-propagation changes require migration.

Significant Changes

Support for old versions of Apache Airflow <2.11 has been dropped (#61018)

Minimum supported version of Apache Airflow is now 2.11.0. If you want to deploy an old version of Apache Airflow, please use the last released version of the chart 1.19.0.

workers specific sections have been moved to workers.celery / workers.kubernetes sections

Please update your configuration accordingly:

  • workers.command command is now deprecated in favor of workers.celery.command/workers.kubernetes.command (#60067).
  • workers.securityContexts command is now deprecated in favor of workers.celery.securityContexts/workers.kubernetes.securityContexts (#60396).
  • workers.containerLifecycleHooks command is now deprecated in favor of workers.celery.containerLifecycleHooks/workers.kubernetes.containerLifecycleHooks (#61369).
  • workers.kerberosSidecar section is now deprecated in favor of workers.celery.kerberosSidecar/workers.kubernetes.kerberosSidecar (#61881).
  • workers.kerberosInitContainer section is now deprecated in favor of workers.celery.kerberosInitContainer/workers.kubernetes.kerberosInitContainer (#60751).
  • workers.terminationGracePeriodSeconds command is now deprecated in favor of workers.celery.terminationGracePeriodSeconds/workers.kubernetes.terminationGracePeriodSeconds (#61892).
  • workers.nodeSelector command is now deprecated in favor of workers.celery.nodeSelector/workers.kubernetes.nodeSelector (#61957).
  • workers.podDisruptionBudget section is now deprecated in favor of workers.celery.podDisruptionBudget. Please update your configuration accordingly. (#61414)
  • workers.keda section is now deprecated in favor of workers.celery.keda. Please update your configuration accordingly. (#61820)
  • workers.resources section is now deprecated in favor of workers.celery.resources and workers.kubernetes.resources. Please update your configuration accordingly. (#61890)

The previous configuration options are still working, but are deprecated and will be removed in a future version.

As Git-Sync is not service-type object, the readiness probe will be removed. (#62334)

To enable feature behaviour set dags.gitSync.recommendedProbeSetting to true. Section itself will be removed in future release as to not break setups during upgrades.

As Git-Sync has dedicated liveness service, the liveness probe behaviour will be changed. To enable feature behaviour set dags.gitSync.recommendedProbeSetting to true.

Please update your configuration accordingly.

Automatic env variables removed from container_extra_envs and custom_airflow_environment (#60750)

The automatic prefix addition for Kubernetes Executor environment variables and secrets has been removed from both the container_extra_envs and custom_airflow_environment helper functions.

What changed:

Previously, when you added environment variables to component-specific configurations (e.g., .Values.scheduler.env), the chart automatically created an additional environment variable (to specified in the env section) with the AIRFLOW__KUBERNETES_ENVIRONMENT_VARIABLES__ prefix for Kubernetes Executor worker pods. After this change, only the variable specified in env section will be created. Furthermore, for values specified under .Values.secret section, the AIRFLOW__KUBERNETES_SECRETS__ prefix is no longer automatically added. Secrets are now passed as-is via secretKeyRef without the prefixed copy for worker pods.

Why this change:

  • Prevent unintended exposure of sensitive data like client_secret information. Previously, due to prefix, it was recognized as internal Airflow configuration leading to unintended exposure in Airflow UI (under Admin -> Configuration), even when AIRFLOW__API__EXPOSE_CONFIG is set to non-sensitive-only.
  • Avoid unintended environment propagation to workers: component-specific env configurations are intended strictly for specific components. Previous behaviour caused these variables to be passed to worker pods, which could result in configuration conflicts and unexpected side effects.

Migration Required:

If you need to pass environment variables specifically to Kubernetes Executor worker pods, use one of the following approaches:

Option 1: Use .Values.env

.. code-block:: yaml

env:
  - name: my_var
    value: "my_value"

Environment variables specified under .Values.env are now passed as-is without the automatic prefix (same behaviour as component-specific env).

Option 2: Use .Values.config.kubernetes_environment_variables

.. code-block:: yaml

config:
  kubernetes_environment_variables:
    my_var: "my_value"

The default Airflow image that is used with the Chart is now 3.1.8, previously it was 3.1.7.

Features

  • Add minute-level log retention to clean-logs script (#61855)
  • Add LOG_MAX_SIZE environment variables to log groomer (#61559)

Improvements

  • Remove automatic KUBERNETES_ENVIRONMENT_VARIABLES and KUBERNETES_SECRETS prefixes from chart helpers (#60750)
  • Remove JWT secrets from triggerer, worker and dag-processor (#63204)
  • Add workers.celery.nodeSelector & workers.kubernetes.nodeSelector (#61957)
  • Add workers.celery.terminationGracePeriodSeconds & workers.kubernetes.terminationGracePeriodSeconds (#61892)
  • Add workers.celery.resources & workers.kubernetes.resources (#61890)
  • Add workers.celery.keda section (#61820)

  • Add workers.celery.containerLifecycleHooks & workers.kubernetes.containerLifecycleHooks (#61369)
  • Refactor Git-Sync livenessProbe & deprecate readinessProbe & add startupProbe (#62334)
  • Warn on deprecated per-component securityContext values (#62729)
  • Add ingress deprecation warnings for apiServer, statsd, and pgbouncer (#62490)
  • Add missing support for: securityContexts and containerLifecycleHook (#60677)

Bug Fixes

  • More restrictive chart rendering logic (#63464)
  • Omit api-server spec.replicas when HPA is enabled (#63187)
  • Add workers.celery.kerberosSidecar & workers.kubernetes.kerberosSidecar sections (#61881)
  • Fix chart NOTES.txt showing deprecation warnings only without secret key (#62722)
  • Fix tpl rendering for TLS hosts in ingress templates #62358 (#62548)
  • Fix webserver.defaultUser.enabled=false not honored (#62143)

Doc only changes

  • Cleanup Helm Chart documentation (#62544)
  • Add missing deprecation warnings for workers section (#63659)

Misc

  • Drop support for all Airflow versions below 2.11 in Helm Chart (#61018)
  • Default airflow version to 3.1.8 (#63392)
  • Add *.iml to .gitignore in all distributions (#63636)
