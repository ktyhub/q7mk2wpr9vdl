エアフロー ヘルムチャート/1.19.0

重大な変更

StatsD メトリクス集約は、長時間実行されるデーモンでのメモリ増大を防ぐために、構成可能な TTL 対応 LRU キャッシュをサポートするようになりました (#60933)

Helm Chart には、StatsD 集計管理のための新しい構成オプションが含まれるようになりました。

  • statsd.cache.type - Enable TTL-enabled lru cache or random cache for metrics aggregation (default: lru)
  • statsd.cache.size - キャッシュするメトリクスの最大数 (デフォルト: 1000)
  • statsd.cache.ttl - Time-to-live for cached metrics in seconds (0s is TTL disabled) (default: 0s) この機能は、古いまたは未使用のメトリック エントリを自動的にクリーンアップすることで、StatsD デーモンの制御されないメモリ増大に対処します。有効にすると、キャッシュは LRU (Least Recent Used) エビクションと TTL (Time To Live) 期限切れの両方を使用して、メモリ使用量を効果的に管理します。 下位互換性を維持するために、デフォルトの動作は変更されません。 StatsD でメモリ増加の問題が発生しているユーザーは、Helm 値に statsd.cache.ttl to value higher than 0 を設定することでこの機能を有効にすることができます。

Helm チャートでの複数の Celery ワーカー セットのサポート (#58547)

この変更により、Apache Airflow Helm Chart に高度な Celery Workers トポロジのサポートが導入され、より柔軟なリソース割り当てと正確な自動スケーリング構成が可能になります。 柔軟なワーカー トポロジ: 新しい workers.celery.enableDefault flag allows users to configure a deployment consisting only of specialized worker sets defined in workers.celery.sets セクション。 マルチキュー自動スケーリングのサポート: KEDA ScaledObject 生成を更新して、カンマ区切りのキュー リストをサポートします。 SQL IN (...) 句を使用することで、KEDA は、割り当てられたすべてのキューの正確な集計ワークロードに基づいてワーカー セットをスケーリングします。 詳細な構成の上書き: この変更により、ワーカー セットごとに現在利用可能なワーカー構成を上書きできるようになります。たとえば、ユーザーは KEDA をグローバルに有効にすることができますが、静的な数のレプリカを必要とする特定のワーカー セットに対しては明示的に無効にすることができます。

デフォルト ユーザーを作成するオプションは、createUserJob セクションに移動されました。

それに応じて構成を更新してください。

  • webserver.defaultUser section is now deprecated in favor of createUserJob (#59767) 以前の構成オプションは引き続き機能しますが、非推奨となり、将来のバージョンでは削除される予定です。 以前のドキュメントでは、オプション apiServer.defaultUser, which was never implemented in the chart. The only supported option is now createUserJob. Using apiServer.defaultUser を使用するとエラーが発生すると説明されていることに注意してください。

Celery 固有の設定オプションは celery section in workers の下に移動されました。

それに応じて構成を更新してください。

  • workers.replicas command is now deprecated in favor of workers.celery.replicas (#59730)
  • workers.revisionHistoryLimit command is now deprecated in favor of workers.celery.revisionHistoryLimit (#60056)
  • workers.args command is now deprecated in favor of workers.celery.args (#60163)
  • workers.livenessProbe section is now deprecated in favor of workers.celery.livenessProbe (#60186)
  • workers.updateStrategy section is now deprecated in favor of workers.celery.updateStrategy (#60351)
  • workers.strategy section is now deprecated in favor of workers.celery.strategy (#60354)
  • workers.podManagementPolicy section is now deprecated in favor of workers.celery.podManagementPolicy (#60359)
  • workers.persistence section is now deprecated in favor of workers.celery.persistence (#60238) 以前の構成オプションは引き続き機能しますが、非推奨となり、将来のバージョンでは削除される予定です。

ポッド起動エグゼキュータの手動サービス アカウント トークン ボリューム構成 (#59156)

ポッド起動エグゼキュータを使用する場合の手動サービス アカウント トークン ボリューム構成のサポートを追加しました (CeleryExecutor, CeleryKubernetesExecutor, KubernetesExecutor, LocalKubernetesExecutor)。 これにより、ServiceAccount とポッド レベルの両方のコントロールを使用して多層防御のセキュリティが実装され、次のことが可能になります。 Kyverno などのセキュリティ ポリシーとの互換性とコンテナ固有の権限割り当ての有効化 最小特権の原則に従います。

imagePullSecrets オプションを追加 (#58094)

レジストリ資格情報を構成するための新しいメカニズムとして「.Values.imagePullSecrets」を追加します。 .Values.registry.secretName and the automatic creation of the <RELEASE_NAME>-registry secret from .Values.registry.connection は両方とも非推奨です。

デフォルトのエアフロー画像が 3.1.7 に更新されました (#61447)

チャートで使用されるデフォルトのエアフロー画像は「3.1.7``, previously it was ``3.0.2」になりました。

airflow helm-chart/1.19.0

Highlights

  • Base images jump to Airflow 3.1.7 and git-sync 4.4.2 — The chart's defaults move from Airflow 3.0.2 → 3.1.7 (#61447) and git-sync 4.3.0 → 4.4.2 (#54085), so a plain helm upgrade now pulls 3.1.x behavior without any opt-in. Pair that with the Airflow 3.x probe-path fix (#58734) and the switch to bitnamilegacy/postgresql (#61156): if you pin or mirror images, or rely on 2.x liveness/readiness paths, audit your overrides before upgrading.

  • Multiple Celery worker sets unlock per-set autoscaling — workers.celery.sets plus workers.celery.enableDefault (#58547) let you drop the generic worker pool entirely and run only specialized sets. KEDA ScaledObject generation now accepts comma-separated queue lists via SQL IN (...) (#58547), and any worker key can be overridden per set (e.g. KEDA on globally, disabled for a static set). Watch the interaction fixes for worker separation (#60420) and the KEDA query switch from queue to the executor field for multi-executor setups (#52840, #55559, #55560) — these change which lag KEDA actually scales on.

  • Two config-key migrations: createUserJob and workers.celery — Default-user settings move from webserver.defaultUser to createUserJob (#59767), and the whole family of Celery worker keys gains workers.celery.* equivalents: replicas (#59730), revisionHistoryLimit (#60056), args (#60163), livenessProbe (#60186), updateStrategy/strategy/podManagementPolicy (#60351/#60354/#60359), and persistence (#60238). Old keys still work but are deprecated, so this is a "migrate on your own schedule" item, not a hard break. Two gotchas: apiServer.defaultUser was never implemented and now errors if set (#59767, #59762), and a planned breaking change to workers.celery was explicitly walked back (#61049).

  • Registry credentials move to imagePullSecrets — .Values.imagePullSecrets becomes the supported mechanism, deprecating both .Values.registry.secretName and the auto-generated <RELEASE_NAME>-registry secret built from registry.connection (#58094). If you use private registries, add the secret to your values and remove reliance on chart-managed creation; note the DB-cleanup CronJob had a separate ImagePullSecrets gap fixed here (#58626).

  • StatsD can now cap memory with a TTL/LRU cache — New statsd.cache.type (lru default, or random), statsd.cache.size (1000), and statsd.cache.ttl (#60933) add LRU eviction plus TTL expiry to aggregation. Default ttl: 0s keeps current behavior, so it's opt-in: if your long-running StatsD daemon has unbounded metric cardinality, set statsd.cache.ttl > 0 and tune size to your label volume.

  • Security and resilience hardening for task pods — Manual Service Account token volume configuration lands for pod-launching executors (Celery, CeleryKubernetes, Kubernetes, LocalKubernetes) (#59156), enabling Kyverno-compatible, least-privilege token mounting. The triggerer moves from pod-log-reader-role to pod-launcher-role (#56872), which can affect RBAC policies. New disruption/autoscaling primitives — PDBs for dag processor (#60294) and triggerer/workers (#59068), HPA for the API server (#52392), KubernetesJobOperator job launching (#52024), and a DB-cleanup CronJob (#58155) — give production clusters more knobs but also new objects to reconcile in GitOps diffs.

No breaking changes: deprecated keys remain functional and the one planned break was reverted (#61049).

Significant Changes

StatsD metrics aggregation now supports configurable TTL-enabled LRU cache to prevent memory growth in long-running daemons (#60933)

The Helm Chart now includes new configuration options for StatsD aggregation management:

  • statsd.cache.type - Enable TTL-enabled lru cache or random cache for metrics aggregation (default: lru)
  • statsd.cache.size - Maximum number of metrics to cache (default: 1000)
  • statsd.cache.ttl - Time-to-live for cached metrics in seconds (0s is TTL disabled) (default: 0s)

This feature addresses uncontrolled memory growth in StatsD daemons by automatically cleaning up stale or unused metric entries. When enabled, the cache uses both LRU (Least Recently Used) eviction and TTL (Time To Live) expiration to manage memory usage effectively.

To maintain backward compatibility, the default behaviour remains unchanged. Users experiencing memory growth issues with StatsD can enable this feature by setting statsd.cache.ttl to value higher than 0 in their Helm values.

Support for Multiple Celery Worker Sets in the Helm Chart (#58547)

This change introduces support for advanced Celery Workers topologies to Apache Airflow Helm Chart, enabling more flexible resource allocation and precise autoscaling configurations.

Flexible Worker Topologies: The new workers.celery.enableDefault flag allows users to configure a deployment consisting only of specialized worker sets defined in workers.celery.sets section.

Multi-Queue Autoscaling Support: Updates the KEDA ScaledObject generation to support comma-separated queue lists. By using the SQL IN (...) clause, we ensure that KEDA scales worker sets based on the precise aggregate workload of all their assigned queues.

Granular Configuration Overrides: This change allows for overwrite of any currently available workers configuration per worker set. For example, a user can enable KEDA globally, but explicitly disable it for a specific worker set that requires a static number of replicas.

Options to create a default user have been moved under the createUserJob section

Please update your configuration accordingly:

  • webserver.defaultUser section is now deprecated in favor of createUserJob (#59767)

The previous configuration options are still working but are deprecated and will be removed in a future version.

Note that the previous documentation described also the option apiServer.defaultUser, which was never implemented in the chart. The only supported option is now createUserJob. Using apiServer.defaultUser will raise an error.

Celery specific config options have been moved under the celery section in workers

Please update your configuration accordingly:

  • workers.replicas command is now deprecated in favor of workers.celery.replicas (#59730)
  • workers.revisionHistoryLimit command is now deprecated in favor of workers.celery.revisionHistoryLimit (#60056)
  • workers.args command is now deprecated in favor of workers.celery.args (#60163)
  • workers.livenessProbe section is now deprecated in favor of workers.celery.livenessProbe (#60186)
  • workers.updateStrategy section is now deprecated in favor of workers.celery.updateStrategy (#60351)
  • workers.strategy section is now deprecated in favor of workers.celery.strategy (#60354)
  • workers.podManagementPolicy section is now deprecated in favor of workers.celery.podManagementPolicy (#60359)
  • workers.persistence section is now deprecated in favor of workers.celery.persistence (#60238)

The previous configuration options are still working but are deprecated and will be removed in a future version.

Manual Service Account Token Volume configuration for pod-launching executors (#59156)

Added support for manual Service Account Token Volume configuration when using pod-launching executors (CeleryExecutor, CeleryKubernetesExecutor, KubernetesExecutor, LocalKubernetesExecutor). This implements defense-in-depth security with both ServiceAccount and Pod-level controls, providing compatibility with security policies like Kyverno and enabling container-specific privilege assignment following the Principle of Least Privilege.

Add imagePullSecrets option (#58094)

Add .Values.imagePullSecrets as the new mechanism for configuring registry credentials, deprecating both .Values.registry.secretName and the automatic creation of the <RELEASE_NAME>-registry secret from .Values.registry.connection.

Default Airflow image is updated to 3.1.7 (#61447)

The default Airflow image that is used with the Chart is now 3.1.7, previously it was 3.0.2.

Default git-sync image is updated to 4.4.2 (#54085)

The default git-sync image that is used with the Chart is now 4.4.2, previously it was 4.3.0.
