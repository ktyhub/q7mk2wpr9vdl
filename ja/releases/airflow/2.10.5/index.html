エアフロー 2.10.5

重大な変更

DAG 実行が失敗に設定されている場合にティアダウン タスクが実行されるようにする (#45530)

以前は、DAG 実行が手動で「失敗」または「成功」状態に設定されていた場合、ターミナル状態はすべてのタスクに設定されていました。 しかし、これはセットアップ タスクとティアダウン タスクが定義されている場合のギャップでした。ティアダウンがインフラストラクチャのクリーンアップに使用された場合 または他のリソースもスキップされるため、リソースは割り当てられたままになる可能性があります。 現時点では、セットアップ タスクが以前に実行されており、DAG が手動で「失敗」または「成功」に設定されてからティアダウンされる場合 タスクが実行されます。セットアップもスキップされた場合、ティアダウンタスクもスキップされます。 副作用として、これは、DAG に分解タスクが含まれている場合、DAG が「失敗」または「成功」として手動でマークされることを意味します。 分解タスクが確実にスケジュールされるように、DAG を実行状態に維持する必要があります。彼らは予定されていないでしょう DAG が直接「失敗」または「成功」に設定されている場合。

airflow 2.10.5

Highlights

  • Teardown tasks on manual DAG state changes (#45530, #45581) — Marking a DAG run manually "failed"/"success" used to set a terminal state on every task, skipping teardown and leaving cleaned-up infrastructure allocated. Now teardown tasks run when setup had previously executed (skipped only if setup was skipped). Migration caveat: for DAGs with teardown tasks, a manual failed/success marking must leave the DAG in a running state for teardown to be scheduled — setting it directly to failed/success means teardown is not scheduled. Teams using teardown for cleanup must adjust their manual-intervention workflow.
  • Custom operators affected: scheduling deps removed, conf deprecated (breaking/deprecation) — Operators can no longer define their own "scheduling deps" (#45713, #45742) — a removal that breaks any custom operator relying on that hook — and conf is deprecated from the Task Context (#44993). Custom operator authors should audit/test before upgrading; stock DAGs are unaffected.
  • Dynamic task mapping & trigger-rule correctness — Several real scheduling fixes: trigger_rule=TriggerRule.ALWAYS is blocked in task-generated mapping within bare tasks (#44751), ShortCircuitOperator mapped tasks fixed (#44912), premature evaluation of rules like ONE_DONE in mapped task groups fixed (#44937), task_id validation in BaseOperator (#44938), and dynamic tasks can be filtered by rendered_map_index (#45109, #45122). Worth it if you use mapped tasks with non-default trigger rules.
  • Webserver, API & XCom fixes — New webserver parameters max_form_parts and max_form_memory_size (#46243, #45749); XCom keys with a forward slash are fetchable via API and escaped in the UI (#45134); map_index added to the extra-links API (#46337); login form sets autocomplete off (#44929, #44940). Plus reliability fixes for empty task-instance logs (#45702, #45703), endless sensor rescheduling (#45224, #45250), event-log JSON request bodies (#45546, #45560), and thread-local access in the BaseOperator.execute safeguard (#44646, #46280).
  • Upgrade verdict — A genuine bugfix/patch release, not a no-op or metadata-only re-tag: one meaningful behavioral change (teardown), one breaking removal (operator scheduling deps), otherwise correctness fixes. Most 2.10.x users — especially those using mapped tasks or teardown-based cleanup — should upgrade; no major-version migration is involved. Test first if you maintain custom operators using scheduling deps; users with none of mapped tasks, teardown, or custom scheduling deps can safely skip.

Significant Changes

Ensure teardown tasks are executed when DAG run is set to failed (#45530)

Previously when a DAG run was manually set to "failed" or to "success" state the terminal state was set to all tasks. But this was a gap for cases when setup- and teardown tasks were defined: If teardown was used to clean-up infrastructure or other resources, they were also skipped and thus resources could stay allocated.

As of now when setup tasks had been executed before and the DAG is manually set to "failed" or "success" then teardown tasks are executed. Teardown tasks are skipped if the setup was also skipped.

As a side effect this means if the DAG contains teardown tasks, then the manual marking of DAG as "failed" or "success" will need to keep the DAG in running state to ensure that teardown tasks will be scheduled. They would not be scheduled if the DAG is directly set to "failed" or "success".

Bug Fixes

  • Prevent using trigger_rule=TriggerRule.ALWAYS in a task-generated mapping within bare tasks (#44751)
  • Fix ShortCircuitOperator mapped tasks (#44912)
  • Fix premature evaluation of tasks with certain trigger rules (e.g. ONE_DONE) in a mapped task group (#44937)
  • Fix task_id validation in BaseOperator (#44938) (#44938)
  • Allow fetching XCom with forward slash from the API and escape it in the UI (#45134)
  • Fix FileTaskHandler only read from default executor (#46000)
  • Fix empty task instance for log (#45702) (#45703)
  • Remove skip_if and run_if decorators before TaskFlow virtualenv tasks are run (#41832) (#45680)
  • Fix request body for json requests in event log (#45546) (#45560)
  • Ensure teardown tasks are executed when DAG run is set to failed (#45530) (#45581)
  • Do not update DR on TI update after task execution (#45348)
  • Fix object and array DAG params that have a None default (#45313) (#45315)
  • Fix endless sensor rescheduling (#45224) (#45250)
  • Evaluate None in SQLAlchemy's extended JSON type decorator (#45119) (#45120)
  • Allow dynamic tasks to be filtered by rendered_map_index (#45109) (#45122)
  • Handle relative paths when sanitizing URLs (#41995) (#45080)
  • Set Autocomplete Off on Login Form (#44929) (#44940)
  • Add Webserver parameters max_form_parts, max_form_memory_size (#46243) (#45749)
  • Fixed accessing thread local variable in BaseOperators execute safeguard mechanism (#44646) (#46280)
  • Add map_index parameter to extra links API (#46337)

Miscellaneous

  • Add traceback log output when SIGTERMs was sent (#44880) (#45077)
  • Removed the ability for Operators to specify their own "scheduling deps" (#45713) (#45742)
  • Deprecate conf from Task Context (#44993)
