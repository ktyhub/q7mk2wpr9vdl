argo-cd v3.5.5

Highlights

  • Config Management Plugin reliability — A CMP failure could leave reposerver serving stale manifests from the last successful render and leak goroutines (#29870, backported in #30140). If you generate manifests through plugins, this restores freshness after plugin errors and stops the leak — prioritize if apps have ever appeared "stuck" on old output following a render failure.
  • OCI Helm chart caching — Two fixes harden OCI-backed Helm repos: the tag list is now cached (#30117/#30119), and cache cleanup is synchronized with extraction (#30020/#30103). Expect fewer registry round trips and no cleanup/extraction race that could evict a chart mid-pull — relevant if you pull charts from OCI registries at high concurrency.
  • Archive and API hardening — Tar extraction now performs the inbound check even when dstPath is a symlink (#28881/#30053), closing a path-traversal edge case, and write repo-credentials endpoints correctly route escaped URLs (#29940/#29958). If your Argo CD API is reachable beyond a fully trusted operator group, these are the changes that justify patching promptly.
  • Dependency refreshes — gRPC jumps 1.81.1 → 1.84.0 (#30056), alongside go-git (#30047), ORAS 2.6.1 → 2.6.2 (#30057), the golang.org/x group (#30072), and Go 1.26.9 (#30092). No intended API surface changes, but gRPC and go-git touch transport and git operations — smoke-test repo connectivity and credentials after the upgrade.
  • Events API fidelity — Events from events.k8s.io now get their count and first/last timestamps populated (#30015/#30111). Consumers building alerting or audit views on the events API/UI now see the same aggregation metadata previously available only on core events.
  • Manifest hydrator resilience — Notes pushes now retry on cannot lock ref errors (#28469/#29905). If you use hydration with git notes under concurrent writes, transient ref-lock contention no longer silently drops notes.

No breaking changes in this patch release.

kubectl create namespace argocd

Release Signatures and Provenance

All Argo CD container images are signed by cosign. A Provenance is generated for container images and CLI binaries which meet the SLSA Level 3 specifications. See the documentation on how to verify.
