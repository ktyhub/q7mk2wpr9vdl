リリースの署名と来歴

すべての Argo CD コンテナ イメージは連署によって署名されています。 SLSA レベル 3 仕様を満たすコンテナー イメージと CLI バイナリに対して来歴が生成されます。確認方法についてはドキュメントを参照してください。

argo-cd v3.5.7

Highlights

  • ApplicationSet parameter isolation — Reserved cluster annotations are no longer exposed as generator parameters (#30482), preventing templates from consuming controller-owned metadata. Audit any ApplicationSet templates that referenced these annotations and replace them with explicit fields or labels.

  • Sync recovery and event accuracy — Operations blocked by sync windows can now be terminated, and hook finalizers are removed when live objects disappear from the reconciliation cache (#30503, #30660), reducing stuck syncs. Multi-source applications now include all revisions in sync completion events (#30471), so event consumers expecting a single revision should be reviewed.

  • More accurate resource health — Unestablished CRDs report Progressing, Crossplane health checks handle missing or inactive conditions, Config Connector resources use status.healthy, and SealedSecrets wait for the current generation (#30575, #30627, #30421, #30655, #30355). Expect transient status changes after upgrading and adjust alerts that assume immediate Healthy states.

  • CLI proxy and authentication compatibility — gRPC-web connections now honor HTTP_PROXY, HTTPS_PROXY, and NO_PROXY, while --header values survive expired-token refreshes (#30497, #30546). This removes common failures for CLI users behind enterprise proxies or custom authentication gateways.

  • Server stability and probes — Goroutine leaks in exec and PodLogs paths are fixed, canceled Git commands receive SIGTERM before SIGKILL, interrupted manifest generation preserves its gRPC error code, and gRPC health checks work without authentication (#30436, #30460, #30407, #30552, #30568). Long-lived API servers should cancel and clean up resources more reliably.

  • Release artifact verification — All container images are signed with cosign, and qualifying image and CLI artifacts include SLSA Level 3 provenance. Teams can pin v3.5.7 by digest and enforce signature or provenance verification in CI and admission pipelines.

No breaking changes.

Quick Start

Non-HA:

kubectl create namespace argocd
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.7/manifests/install.yaml

kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.7/manifests/ha/install.yaml

Release Signatures and Provenance

All Argo CD container images are signed by cosign. A Provenance is generated for container images and CLI binaries which meet the SLSA Level 3 specifications. See the documentation on how to verify.
