リリースの署名と来歴

すべての Argo CD コンテナ イメージは連署によって署名されています。 SLSA レベル 3 仕様を満たすコンテナー イメージと CLI バイナリに対して来歴が生成されます。確認方法についてはドキュメントを参照してください。

argo-cd v3.4.13

Highlights

  • Sync lifecycle reliability — Operations blocked by sync windows can now be terminated (#30502), and Jobs can terminate cleanly instead of waiting on cancelled Git subprocesses (#30408). #30659 also removes hook finalizers when live objects disappear from the reconciliation cache, preventing stuck hook cleanup.
  • Custom-resource health checks become more accurate — Crossplane, Config Connector, and SealedSecret handling now recognizes provider conditions, treats inactive managed-resource definitions as healthy, uses status.healthy where appropriate, and waits for the current SealedSecret generation before reporting health (#30625, #30424, #30654, #30353), reducing misleading health states and premature sync decisions.
  • ApplicationSet safety and GitLab MR discovery — Reserved cluster annotations are no longer exposed as generator parameters (#30479), preventing accidental override of internal metadata. GitLab pull-request generators now refresh correctly when configured with a project path (#30621).
  • CLI connectivity fixes for restricted environments — gRPC-web connections now honor HTTP_PROXY, HTTPS_PROXY, and NO_PROXY (#30499), while --header values are retained when refreshing expired authentication tokens (#30547). This avoids failed CLI sessions behind proxies and custom auth middleware.
  • Unauthenticated health endpoint and reconciliation race fix — The server permits unauthenticated gRPC health checks (#30569), restoring standard probe compatibility. The GitOps engine also fixes an empty-UID backfill race (#30526), reducing incorrect live-object association during reconciliation.
  • Repository, observability, and UI edge cases — OCI Helm repositories now accept host:port URLs (#30516), escaped write-credentials routes are handled correctly (#29955), user-info cache limits are honored when responses omit expires (#30624), and sync-completion events include all multi-source revisions (#30470), improving automation, event auditability, and cache behavior.

No breaking changes.
