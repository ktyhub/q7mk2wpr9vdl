コードホエール v0.9.7

Codewhale は Shannon Labs の公開製品です。 codewhale コマンド、npm パッケージ、リリースアセット名は技術的に小文字のままです 識別子。従来の npm パッケージ deepseek-tui は非推奨になりました。 今後のリリースは受け付けません。 v0.8.x レガシー deepseek からのユーザー / deepseek-tui 名は docs/REBRAND.md とともに移行する必要があります。

インストール

推奨 — npm (1 つのコマンド、両方のエントリポイント)

npm install -g codewhale

ラッパーは、一致する codewhale および codew コマンド アセットをダウンロードします。 このリリースから。どちらにも同じコンパイル済みランタイムが含まれています。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.7

このイメージは、codewhale と codew の両方と同じランタイムを公開します。の latestタグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli --locked

Cargo パッケージには codewhale がインストールされます。 Cargo は 2 番目のコマンドを作成できません 1 つのバイナリ ターゲットからのエイリアス。スペルを短くしたいユーザーは、 codew は、インストールされた実行可能ファイルへのシンボリックリンクです。 npm、Homebrew、アーカイブ、 シェルインストーラーとコンテナー チャネルは、両方のコマンド名を直接インストールします。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale での同じランタイムが含まれています。 codew コマンド名とインストール スクリプト:

|プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。インストールします codewhale.exe および codew.exe の下 %LOCALAPPDATA%\Programs\CodeWhale\bin を実行し、そのディレクトリを 現在のユーザーのパス。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します

ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。

各プラットフォームには、ベア、アーカイブされていない codewhale-<platform> と codew-<platform> アセット。 7 つの codewhale-tui-<platform> ファイル名 v0.9.5 に添付されているものは、バイト同一の互換性コピーであり、目的にのみ使用されます。 すでにインストールされている v0.9.4 clients は、この単一バイナリを発見して通過します。 移行。現在のインストーラーは 3 番目のランタイムを公開していません。従来の npm パッケージ deepseek-tui は非推奨であり、再公開されていません。移行用 v0.8.x 従来のバイナリ名からの変更については、docs/REBRAND.md を参照してください。

v0.9.7 の内容

Codewhale v0.9.7 はカタログを普通に保ちます。 Grok 4.6 が通常のカタログとして登場 OrcaRouter は、プロバイダー型の特別なケースの山ではなく、行として参加します。 指定されたプロバイダーであり、lru のパニック安全勧告は、 その周りに住んでいるのではなく、それを引き起こしたピン。

追加

  • Grok 4.6 は直接の xAI デフォルトであり、grok エイリアスがそれに移動します。 grok-4.5 は引き続き明示的に選択できます。 500K コンテキスト、テキスト/画像入力、 ツールと構造化出力のサポート、low/medium/high/xhigh 推論 取り組み (デフォルト high) とサーバー側の Web 検索はすべて、 モデル固有のコードではなく、Models.dev 形式のカタログ。 reasoning_effort 正確なファーストパーティ https://api.x.ai/v1 ルートでのみワイヤに到達します。 そして、使用量を意識した 200,000 トークンの価格境界は、直接 xAI に限定されているため、 モデル スラグを再利用するアグリゲーター ルートは、xAI の課金を継承できません。
  • OrcaRouter はファーストクラスの名前付きプロバイダーです: ORCAROUTER_API_KEY、デフォルトのベース URL https://api.orcarouter.ai/v1、deepseek/deepseek-v4-pro デフォルト、 orcarouter/auto ルーティング、CLI --provider セレクター、および TUI ピッカー エントリ (#5321)。

変更されました

  • 推論労力の正規化とモデルピッカーは、パブリッシュされたモデルを読み取ります。 すべてのルートを折りたたむのではなく、カタログから reasoning_options リストを取得します。 歴史的な低/中はしご。取り組みリストを公開するカタログ行 独自の語彙を保持します。
  • ドキュメントは、DeepSeek のライブ DeepSeek-V4-Pro-0813 バックエンド ラベルを記録します。 呼び出し可能な API ID は deepseek-v4-pro のままです。エイリアスは再マップされず、 deepseek-v4-pro[1m]セレクターを出品します。

修正済み

  • ユーザーまたはアシスタントのメッセージをコピーすると、代わりに正規のコンテンツが取得されます。 再シリアル化されたトランスクリプト行、役割グリフの保持、継続レール、 作成された Unicode を維持しながら、clipboard を視覚的にラッピングします。 マークダウンと強制改行。ツールと思考のセルは既存のまま 完全な転写パス (#5319)。
  • load_session は、読み取りごとにクラッシュ リカバリを実行しなくなりました。スナップショットの読み取りが完了します 副作用のないload_session_snapshotを使用し、回復は明示的です recover_session_for_resume 経由なので、埋め込みホストは耐久性のあるものを検査します。 ツールがまだ実行中のセッションでは、偽のクラッシュ修復が行われなくなりました (#5320)。

セキュリティ

  • lru は 0.18 に移動し、LruCache::pop() があった RUSTSEC-2026-0253 をクリアします。 パニックセーフではなく、未解決のリスト ポインターが残る可能性があります。 ratatui-core lru ^0.16 を推移的に強制する =0.1.0 ピンがリフトされるため、 ColorCompatBackend は追跡されたカーソルから get_cursor_position() に応答するようになりました state — 起動時の CPR レースに対するアップストリーム推奨の回避策 (ratatui/ratatui#2483、ratatui/ratatui#2640) ピンは元々機能していました 周り。 ratatui 自体は =0.30.0 に固定されたままであるため、API の表面は 変わらない。

既知の問題

  • 結合テスト exec_persistent_service::failed_exec_kills_pending_service_and_exits_nonzero 並列ロード下で確認されたフレークです (「サービス PID ファイルが表示されませんでした」)。 これは単独で通過し、v0.9.7 の変更とは無関係です。

Codewhale v0.9.7

Highlights

  • Catalog-driven Grok 4.6 — The grok alias and direct xAI default now select Grok 4.6, with 500K context, image input, tools, structured output, web search, and low/medium/high/xhigh reasoning (high by default) defined in the shared catalog. reasoning_effort is sent only to exact https://api.x.ai/v1 requests, and the 200K-token pricing boundary is direct-xAI-only, preventing aggregator routes from inheriting xAI-specific behavior. Pickers now preserve each model’s published reasoning_options; grok-4.5 remains explicitly selectable.
  • First-class OrcaRouter support — Configure ORCAROUTER_API_KEY to use the default https://api.orcarouter.ai/v1 endpoint. The provider is available through --provider and the TUI picker, defaults to deepseek/deepseek-v4-pro, and exposes orcarouter/auto for automatic routing (#5321).
  • Cleaner clipboard output and safer session reads — Message copying now preserves authored Unicode, Markdown, and hard breaks without UI glyphs or wrapping; Tool and Thinking cells still use full-transcript copying (#5319). load_session no longer performs implicit crash recovery, so hosts inspecting active sessions should use side-effect-free load_session_snapshot; resume-time repair now requires recover_session_for_resume (#5320).
  • Rust security fix without API churn — Upgrading lru to 0.18 clears RUSTSEC-2026-0253, where LruCache::pop() could leave dangling pointers after a panic. The transitive pin is removed, and ColorCompatBackend now uses tracked cursor state to handle the startup CPR race; ratatui remains pinned at =0.30.0, so no public API migration is expected.
  • Installation and legacy-name migration — npm, containers, archives, and shell installers provide both codewhale and cod; Cargo installs only codewhale, so users wanting the shorter command must create a cod symlink. The legacy deepseek-tui package is deprecated with no further releases, and v0.8.x users should follow docs/REBRAND.md.
  • Compatibility — No breaking changes.

Codewhale is the public product from Shannon Labs. The codewhale command, npm package, and release-asset names remain lowercase technical identifiers. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Install

Recommended — npm (one command, both entrypoints)

npm install -g codewhale

The wrapper downloads the matched codewhale and codew command assets from this Release. Both contain the same compiled runtime.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/hmbown/codewhale:v0.9.7

The image exposes the same runtime as both codewhale and codew. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli --locked

The Cargo package installs codewhale. Cargo cannot create a second command alias from one binary target; users who want the shorter spelling can add a codew symlink to that installed executable. The npm, Homebrew, archive, shell-installer, and container channels install both command names directly.

What's in v0.9.7

Codewhale v0.9.7 keeps the catalog ordinary. Grok 4.6 lands as a normal catalog row instead of a provider-shaped pile of special cases, OrcaRouter joins as a named provider, and a panic-safety advisory in lru is cleared by lifting the pin that caused it rather than living around it.

Added

  • Grok 4.6 is the direct xAI default, with the grok alias moving onto it and grok-4.5 still explicitly selectable. Its 500K context, text/image input, tool and structured-output support, low/medium/high/xhigh reasoning efforts (default high), and server-side web search all come from the Models.dev-shaped catalog rather than model-specific code. reasoning_effort reaches the wire only on the exact first-party https://api.x.ai/v1 route, and the usage-aware 200K-token pricing boundary is scoped to direct xAI so aggregator routes reusing the model slug cannot inherit xAI billing.
  • OrcaRouter is a first-class named provider: ORCAROUTER_API_KEY, default base URL https://api.orcarouter.ai/v1, deepseek/deepseek-v4-pro default, orcarouter/auto routing, CLI --provider selector, and TUI picker entries (#5321).

Changed

  • Reasoning-effort normalization and the model picker read a model's published reasoning_options list from the catalog instead of collapsing every route to the historic Low/Medium ladder. Any catalog row that publishes an effort list keeps its own vocabulary.
  • Docs record DeepSeek's live DeepSeek-V4-Pro-0813 backend label while the callable API ID stays deepseek-v4-pro. No aliases are remapped and no deepseek-v4-pro[1m] selector is sent.

Fixed

  • Copying a user or assistant message takes its canonical content instead of reserialized transcript lines, keeping role glyphs, continuation rails, and visual wrapping out of the clipboard while preserving authored Unicode, Markdown, and hard line breaks. Tool and Thinking cells stay on the existing full-transcript path (#5319).
  • load_session no longer runs crash recovery on every read. Snapshot reads go through a side-effect-free load_session_snapshot and recovery is explicit via recover_session_for_resume, so an embedding host inspecting a durable session while a tool is still running no longer gets a spurious crash repair (#5320).

Security

  • lru moves to 0.18 to clear RUSTSEC-2026-0253, where LruCache::pop() was not panic-safe and could leave dangling list pointers. The ratatui-core =0.1.0 pin that transitively forced lru ^0.16 is lifted, so ColorCompatBackend now answers get_cursor_position() from tracked cursor state — the upstream-recommended workaround for the startup CPR race (ratatui/ratatui#2483, ratatui/ratatui#2640) that the pin originally worked around. ratatui itself stays pinned at =0.30.0, so the API surface is unchanged.

Known issues

  • The integration test exec_persistent_service::failed_exec_kills_pending_service_and_exits_nonzero is a confirmed flake under parallel load ("service pid file never appeared"). It passes in isolation and is unrelated to any v0.9.7 change.
