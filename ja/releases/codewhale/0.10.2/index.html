コードホエール v0.10.2

v0.10.2 の内容

Codewhale v0.10.2 は、ライブ ターミナル作業であるアニメーション ペット ビュー (/pet on) を追加します ドック、チャットごとのコンポーザー カラー (/color)、および最初の 1 回限りのメモ 何が変更されたかを示すアップデート後に開始します。 3つのセッションを終了します データ損失パスと codewhale web セッション リーク。デフォルトのランタイムを追加します デーモンソケットの場所をサンドボックス拒否リストに追加します。をアップロードする curl または wget を保持します。 資格情報;目に見えない Unicode を含むシェルコマンドを拒否します。を維持します Linux サンドボックスは、非表示の資格情報ディレクトリがシンボリックリンクの場合に動作します。そして アイドル状態の TUI 再描画作業を削減します。 /undo は丸ごと取り戻します 長いプロンプトや複数行のプロンプトを含むリクエスト。 exec --auto が説明します フルアクセスのデフォルト、より厳密なサンドボックスを明示的に尊重し、保存 ツールを有効にした実行とその失敗の受信。ローカル ランタイムは次のように表示されます。 オンボーディング、/diff は Git リポジトリの外部で動作、DeepSeek の応答ルート 再生されたツール履歴を拒否しなくなり、貢献者の修正によりトークンが改善されました アカウンティング、リレー モデル リスト、ローカライズされた応答、および Windows ランチャー 指導。委任された作業は、モデルが考案したターン数や時間の制限なしで継続されます。 また、別の子が失敗した後も、独立したワークフロー ステップを続行できます。

インストール

推奨 — 公式 GitHub リリース

新しい macOS/Linux インストール (このリリースのチェックサム済みバイナリ):

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.2" sh
"$HOME/.local/bin/codewhale" --version

Windows の場合は、以下の対応するインストーラーまたはアーカイブを使用してください。既存の 直接インストールして、codewhale update を実行します。実行可能パスを出力し、 新しいビルドを維持します。インストール ディレクトリが別のビルドによって占有されている場合、 インストール ガイド の新しいディレクトリの移行を使用してください。

二次パッケージング — npm と Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

ラッパーは、一致する codewhale および codew コマンド アセットをダウンロードします。 このリリースから。どちらにも同じコンパイル済みランタイムが含まれています。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/codewhale-hq/codewhale:v0.10.2

このイメージは、codewhale と codew の両方と同じランタイムを公開します。の latestタグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli --locked

Cargo パッケージには codewhale がインストールされます。 Cargo は 2 番目のコマンドを作成できません 1 つのバイナリ ターゲットからのエイリアス。スペルを短くしたいユーザーは、 codew は、インストールされた実行可能ファイルへのシンボリックリンクです。 npm、Homebrew、アーカイブ、 シェルインストーラーとコンテナー チャネルは、両方のコマンド名を直接インストールします。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale での同じランタイムが含まれており、 codew コマンド名とインストール スクリプト:

|プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (ポータブル) | codewhale-windows-arm64-portable.zip | — |

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。インストールします codewhale.exe、codew.exe、および codewhale.bat の下 %LOCALAPPDATA%\Programs\CodeWhale\bin、そのディレクトリを 現在のユーザーの PATH を指定し、優先するスタート メニューのショートカットを作成します。 Windows ターミナル (wt.exe) がインストールされている場合。
  • マシンのアーカイブを抽出します: codewhale-windows-x64.zip または codewhale-windows-arm64.zip
  • ダブル click codewhale.bat (生の .exe ではありません) を起動します
  • install.bat を実行して、バイナリとランチャーを %USERPROFILE%\bin にコピーします。
  • %USERPROFILE%\bin を PATH に追加します

ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから codewhale.bat を抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。

各プラットフォームには、ベア、アーカイブされていない codewhale-<platform> と codew-<platform> アセット。 7 つの codewhale-tui-<platform> ファイル名 v0.9.5 に添付されているものは、バイト同一の互換性コピーであり、目的にのみ使用されます。 すでにインストールされている v0.9.4 clients は、この単一バイナリを発見して横断します 移行。現在のインストーラーは 3 番目のランタイムを公開していません。従来の npm パッケージ deepseek-tui は非推奨であり、再公開されていません。移行用 v0.8.x の従来のバイナリ名については、docs/REBRAND.md を参照してください。

Codewhale v0.10.2

Highlights

  • Live workspace controls — The live Terminal work dock and animated /pet on view bring operational feedback into the chat UI, while per-chat /color makes concurrent sessions easier to distinguish. A one-time post-update note surfaces changes without permanent clutter.
  • Session durability — Three session data-loss paths and a codewhale web session leak are fixed. Session resume/Herdr state handling (#7064) and Codewhale home relocation that preserves sub-agent state (#6949) further protect long-running work across restarts and moves.
  • Credential and command hardening — Default Runtime daemon sockets are now sandbox-denied, credential-bearing curl/wget uploads are intercepted, and shell commands containing invisible Unicode are refused. Linux sandboxing with symlinked hidden credential directories is repaired (#7007); previously accepted automation may now require permission or policy changes.
  • Rollback and execution policy — /undo rewinds a complete request, including long or multiline prompts, and correctly reports when only conversation state was rewound (#6970). exec --auto still defaults to Full Access but now discloses that default, honors an explicitly stricter sandbox, and saves tool-enabled runs with failure receipts—review permissions before unattended use.
  • Workflow and provider interoperability — Delegated work is no longer cut short by model-invented turn/time limits, and independent workflow steps can continue after a sibling child fails. DeepSeek Responses accepts replayed tool history, custom relay discovery is fixed (#7013), /diff works outside Git, and local runtimes appear during onboarding.
  • Compatibility — No breaking changes.

What's in v0.10.2

Codewhale v0.10.2 adds an animated pet view (/pet on), a live Terminal work dock, per-chat composer colors (/color) and a one-time note on the first start after an update that says what changed. It closes three session data-loss paths and a codewhale web session leak; adds the default Runtime daemon socket locations to the sandbox deny-list; holds a curl or wget that uploads a credential; refuses shell commands containing invisible Unicode; keeps the Linux sandbox working when a hidden credential directory is a symlink; and reduces idle TUI redraw work. /undo takes back a whole request, including long and multiline prompts. exec --auto explains its Full Access default, honors an explicitly stricter sandbox, and saves tool-enabled runs and their failure receipts. Local runtimes appear during onboarding, /diff works outside a Git repository, DeepSeek's Responses route no longer rejects replayed tool history, and contributor fixes improve token accounting, relay model lists, localized replies and Windows launcher guidance. Delegated work continues without model-invented turn or time caps, and independent workflow steps can continue after another child fails.

Install

Recommended — official GitHub release

New macOS/Linux install (checksummed binaries from this release):

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.2" sh
"$HOME/.local/bin/codewhale" --version

For Windows, use the matching installer or archive below. For an existing direct install, run codewhale update; it prints the executable path and keeps newer builds. If the install directory is occupied by a different build, use the fresh-directory migration in the installation guide.

Secondary packaging — npm and Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

The wrapper downloads the matched codewhale and codew command assets from this Release. Both contain the same compiled runtime.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/codewhale-hq/codewhale:v0.10.2

The image exposes the same runtime as both codewhale and codew. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli --locked

The Cargo package installs codewhale. Cargo cannot create a second command alias from one binary target; users who want the shorter spelling can add a codew symlink to that installed executable. The npm, Homebrew, archive, shell-installer, and container channels install both command names directly.

Manual download — platform archives (recommended)

Each archive below contains the same runtime under the codewhale and codew command names, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (portable) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs codewhale.exe, codew.exe, and codewhale.bat under %LOCALAPPDATA%\Programs\CodeWhale\bin, adds that directory to the current-user PATH, and creates a Start Menu shortcut that prefers Windows Terminal (wt.exe) when it is installed.
  • Extract the archive for your machine: codewhale-windows-x64.zip or codewhale-windows-arm64.zip
  • Double-click codewhale.bat (not the raw .exe) to launch
  • Run install.bat to copy the binaries and launcher to %USERPROFILE%\bin
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run codewhale.bat from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Each platform also has bare, unarchived codewhale-<platform> and codew-<platform> assets. The seven codewhale-tui-<platform> filenames attached to v0.9.5 are byte-identical compatibility copies used only to let already-installed v0.9.4 clients discover and cross this single-binary transition; current installers do not expose a third runtime. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.
