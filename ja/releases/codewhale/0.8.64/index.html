Codewhale v0.8.64

コードホエール v0.8.64

CodeWhale は正規のプロジェクト、コマンド、npm パッケージであり、 リリースアセット名。従来の npm パッケージ deepseek-tui は 非推奨となり、今後のリリースはありません。からのユーザー v0.8.x レガシー deepseek / deepseek-tui 名は移行する必要があります docs/REBRAND.md で。

インストール

推奨 — npm (1 つのコマンド、両方のバイナリ)

npm install -g codewhale

ラッパーは、このリリースから両方のバイナリをダウンロードし、同じディレクトリに配置します。

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.64

このイメージには、codewhale ディスパッチャと codewhale-tui ランタイムが同梱されています。 latest タグもリリース時に更新されます。

カーゴ (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

両方のクレートが必要です。codewhale-cli は codewhale ディスパッチャーを生成し、codewhale-tui はディスパッチャーが委任する対話型ランタイムを生成します。バイナリを 1 つだけインストールすると、実行時に MISSING_COMPANION_BINARY エラーが発生して失敗します。

手動ダウンロード — プラットフォーム アーカイブ (推奨)

以下の各アーカイブには、codewhale ディスパッチャと codewhale-tui ランタイムの両方、およびインストール スクリプトが含まれています。 |プラットフォーム |アーカイブ |スクリプトをインストールする | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (インストーラー) | CodeWhaleSetup.exe | NSIS セットアップ | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (ポータブル) | codewhale-windows-x64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • インストーラー パスの場合は、CodeWhaleSetup.exe を実行します。両方のバイナリを %LOCALAPPDATA%\Programs\CodeWhale\bin にインストールし、そのディレクトリを現在のユーザーの PATH に追加します。
  • codewhale-windows-x64.zip の抽出
  • install.bat を実行します (%USERPROFILE%\bin にコピー)
  • %USERPROFILE%\bin を PATH に追加します ポータブル Windows アーカイブはインストール スクリプトをスキップし、任意のディレクトリから抽出して実行します。 NSIS インストーラーは現在署名されていないため、署名証明書がリリース パイプラインに組み込まれるまで Windows SmartScreen をトリガーする可能性があります。 各プラットフォームには、アーカイブされていない ベアのバイナリ (codewhale-<platform> および codewhale-tui-<platform>) も添付されています。これらは npm ラッパーとアプリ内 codewhale update がダウンロードするものですが、上記の .tar.gz / .zip アーカイブは推奨される手動ダウンロードであり、さらにインストール スクリプトがバンドルされています。従来の npm パッケージ deepseek-tui は非推奨となり、再公開されません。 v0.8.x のレガシー バイナリ名からの移行については、docs/REBRAND.md を参照してください。

確認する (推奨)

このリリースからチェックサム マニフェストをダウンロードし、次のことを確認します。

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

v0.8.64 の内容

追加

  • シームレスな自動圧縮のデフォルト。 既知のラージコンテキストルートが維持されるようになりました。 サマリーを転送する間、デフォルトで自動圧縮がオンになります。 安定したプロンプト パスにより、変更を加えずに予期せぬコンテキスト損失が軽減されます。 明示的なオプトアウト動作。
  • ランタイム Web オートメーションの準備完了。 ローカル アプリのオートメーションは、 ループバック専用の開発サーバー準備プリミティブにより、エージェントは TCP を待機でき、 ブラウザ検証前のオプションの HTTP ヘルスチェック。から収穫 #3376 by @cyq1017。
  • モデルと統合の改良。 /model pro および /model flash のショートカット 既存のモデルを維持しながら、現在の DeepSeek V4 ルートに解決されるようになりました ID。 @KUK4 によって #3350 から収集されました。 WeCom ブリッジは次のように着陸しました。 状態権限とチャット対応エラーに対するメンテナーのフォローアップ強化 @pkeging による #3370 からのレポート。

修正済み

  • セキュリティと trust 境界強化。 プロジェクト ローカル構成はできなくなりました。 ユーザー所有のシェルまたは命令ファイルのポリシーを緩めると、ファイル編集には ターゲット ファイルの新規読み取り、git 履歴入力がオプション形式または 制御文字のリビジョン、インタラクティブな実行画面には承認が必要、 ローカル ツール パスは、ワークスペース/ルート検証によって絞り込まれます。
  • ランタイムと診断の編集。 生成されたランタイム/アプリサーバートークン、 未処理のセッションリネージ識別子、プロバイダー レジストリ ドリフト値、レビュー レシートの内部情報と Webhook URL が人間の目に映るメッセージにエコーされなくなりました。 ログまたは診断。
  • ネットワークとアラートの安全性。 プロバイダー TLS 検証バイパス要求が可能になりました フェール クローズ、フリート アラート Webhook には HTTPS が必要、フェッチ URL のホスト名は次のとおりです。 リクエストの前に解決され、ランタイムモバイル認証は依存しなくなりました。 トークンを含む URL。
  • パス状態の強化。 構成兄弟ファイル、プロジェクト MCP cwd 値、 ランタイム スレッド ストア ファイル、サブエージェント状態、プロジェクト ローカル状態ルート、および アプリサーバーのサイドカー構成パスは、事前にチェックされたルートを通じて解決されるようになりました。 読み取り/書き込み。
  • CI 修復をリリースします。 夜間のクロスターゲット ビルドは Rust ターゲットをインストールします 一時的なカーゴ障害を明示的に再試行します。自動タグの実行はシリアル化されます すでに作成されているリモート タグを何も行わないものとして扱います。安全なスライスを収穫 @donglovejava の #3374 より。
  • プロバイダー待機とサイドバーの回帰。 プロバイダー待機フッターの抑制 タイムアウト警告を表示したまま有効になるまで騒々しいカウントダウン、 @idling11 によって #3375 から収集されました。固定されたサイドバーは、 @donglovejava によって #3371 から収集された、より狭い 64 列の境界。
  • 委任されたサーバーのクリーンアップ。 委任された serve / app-server の子は利益を得る サポートされているプラットフォームでの OS レベルの親の死のクリーンアップ、#3259 の完了 @wuisabel-gif による #3378 と #3317 からのフォローアップ。
  • ACP とサンドボックスの正確性。 ACP セッションはマルチターンを保持します。 プロンプト ターン全体の会話履歴。@xulongzhe による #3372 から収集。 Worktree Git メタデータの書き込みは、サンドボックス ポリシーを通じて許可されます。 広範な trust モード エスカレーション、@cyq1017 による #3356 および @cyq1017 による #3355 レポートから @リンレティアン。

変更されました

  • コミュニティと依存関係の収穫。 リリース トレインには重点が置かれています。 @greyfreedom による #3379、@nightt5879 による #3348 からのコミュニティ クレジット スライス @hongqitai による #3346、@cyq1017 による #3345/#3333、および dependabot の更新 windows、toml、tokio、lru、similar、および Web ツールのセキュリティ ロック。
  • 公開リリース表面のクリーンアップ。 ベンチマーク固有のマテリアルは保持されました。 公開リリース リポジトリから外します。ベンチマーク ソース フラグメントは、 別のcodewhale-benchレーン。 このリリースの貢献者のクレジットは、上記の changelog エントリに記載されています — レポート、PR、レビュー、複製によってこの記事を形作ってくれたすべての人に感謝します。 完全なメモについては CHANGELOG.md を、古いリリースについては docs/CHANGELOG_ARCHIVE.md を参照してください。

Codewhale v0.8.64

Highlights

  • Canonical package and binary rename — deepseek-tui is deprecated and will receive no further releases; migrate legacy installations with docs/REBRAND.md. Install both codewhale-cli and codewhale-tui via Cargo, or use the npm/archive bundles that provide both—the dispatcher fails with MISSING_COMPANION_BINARY if its runtime is absent.
  • Automatic compaction for large-context routes — Known long-context routes now enable compaction by default and carry summaries through the stable prompt path, reducing unexpected context loss. Explicit opt-outs still work, but existing scripts should verify their compaction settings.
  • Security and trust-boundary hardening — Project-local configuration can no longer weaken user-owned shell or instruction-file policies; file edits require a fresh read, and git revision inputs reject option-shaped strings and control characters. Interactive execution now requires approval, while workspace/root validation narrows local tool and state-file access.
  • Safer network and diagnostic behavior — TLS-verification bypass requests now fail closed, webhook alerts require HTTPS, and fetch hostnames are resolved before requests. Runtime/app-server tokens, session lineage identifiers, provider drift values, and webhook URLs are redacted from user-visible logs.
  • ACP multi-turn history fix — ACP sessions now retain conversation history across prompt turns instead of behaving as isolated requests, fixing stateful agent workflows affected by the regression (#3372).
  • Server lifecycle and sandbox correctness — Delegated serve/app-server children gain OS-level parent-death cleanup on supported platforms (#3378, #3317), preventing orphaned processes. Worktree Git metadata writes are permitted without broadly escalating sandbox trust (#3356).

No breaking changes.

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Install

Recommended — npm (one command, both binaries)

npm install -g codewhale

The wrapper downloads both binaries from this Release and places them in the same directory.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.64

The image ships the codewhale dispatcher and codewhale-tui runtime. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Both crates are required — codewhale-cli produces the codewhale dispatcher and codewhale-tui produces the interactive runtime that the dispatcher delegates to. Installing only one binary will fail at runtime with a MISSING_COMPANION_BINARY error.

Manual download — platform archives (recommended)

Each archive below contains both the codewhale dispatcher and codewhale-tui runtime, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs both binaries under %LOCALAPPDATA%\Programs\CodeWhale\bin and adds that directory to the current-user PATH.
  • Extract codewhale-windows-x64.zip
  • Run install.bat (copies to %USERPROFILE%\bin)
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Each platform also has bare, unarchived binaries attached below (codewhale-<platform> and codewhale-tui-<platform>) — these are what the npm wrapper and the in-app codewhale update download, whereas the .tar.gz / .zip archives above are the recommended manual download and additionally bundle an install script. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.

Verify (recommended)

Download the checksum manifests from this Release and verify:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt
shasum -a 256 -c codewhale-artifacts-sha256.txt

What's in v0.8.64

Added

  • Seamless auto-compaction defaults. Known large-context routes now keep automatic compaction on by default while carrying summaries forward through the stable prompt path, reducing surprise context loss without changing explicit opt-out behavior.
  • Runtime web automation readiness. Local app automation gains a loopback-only dev-server readiness primitive so agents can wait for TCP and optional HTTP health checks before browser verification. Harvested from #3376 by @cyq1017.
  • Model and integration polish. /model pro and /model flash shortcuts now resolve to the current DeepSeek V4 routes while preserving existing model IDs. Harvested from #3350 by @KUK4. The WeCom bridge landed with maintainer follow-up hardening for state permissions and chat-facing error reporting, from #3370 by @pkeging.

Fixed

  • Security and trust-boundary hardening. Project-local config can no longer loosen user-owned shell or instruction-file policy, file edits now require a fresh read of the target file, git history inputs reject option-shaped or control-character revisions, interactive execution surfaces require approval, and local tool paths are narrowed through workspace/root validation.
  • Runtime and diagnostics redaction. Generated runtime/app-server tokens, raw session lineage identifiers, provider registry drift values, review receipt internals, and webhook URLs are no longer echoed into human-facing logs or diagnostics.
  • Network and alert safety. Provider TLS verification bypass requests now fail closed, fleet alert webhooks require HTTPS, fetch URL hostnames are resolved before requests, and runtime mobile auth no longer relies on token-bearing URLs.
  • Path-state hardening. Config sibling files, project MCP cwd values, runtime thread store files, sub-agent state, project-local state roots, and app-server sidecar config paths now resolve through checked roots before reads/writes.
  • Release CI repair. Nightly cross-target builds install Rust targets explicitly and retry transient cargo failures; auto-tag runs are serialized and treat an already-created remote tag as a no-op. Safe slices harvested from #3374 by @donglovejava.
  • Provider wait and sidebar regressions. Provider-wait footers suppress noisy countdowns until useful while keeping timeout warnings visible, harvested from #3375 by @idling11. The pinned sidebar can render at a narrower 64-column boundary, harvested from #3371 by @donglovejava.
  • Delegated server cleanup. Delegated serve / app-server children gain OS-level parent-death cleanup on supported platforms, completing the #3259 follow-up from #3378 and #3317 by @wuisabel-gif.
  • ACP and sandbox correctness. ACP sessions preserve multi-turn conversation history across prompt turns, harvested from #3372 by @xulongzhe. Worktree Git metadata writes are allowed through sandbox policy without broad trust-mode escalation, from #3356 by @cyq1017 and the #3355 report by @linletian.

Changed

  • Community and dependency harvests. The release train carries focused community-credit slices from #3379 by @greyfreedom, #3348 by @nightt5879, #3346 by @hongqitai, #3345/#3333 by @cyq1017, and Dependabot updates for windows, toml, tokio, lru, similar, and web tooling security locks.
  • Public release surface cleanup. Benchmark-specific materials were kept out of the public release repo; benchmark source fragments belong in the separate codewhale-bench lane.

Contributor credits for this release live in the changelog entry above — thank you to everyone whose reports, PRs, reviews, and reproductions shaped it.

See CHANGELOG.md for full notes and docs/CHANGELOG_ARCHIVE.md for older releases.
