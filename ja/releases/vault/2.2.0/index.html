保管庫 v2.2.0

2026 年 10 月 15 日

重大な変更:

  • コンテナ: ビルド時に vault の cap_ipc_lock 機能を削除し、共通のコンテナ ランタイムで Vault を実行できるようにします。コンテナ内の Vault は、メモリをロックするために mlock() を呼び出すことができなくなります。オペレータは、Vault の構成で disable_mlock = true を設定する必要があります。ランタイム オペレーターは、データの安全性を保証するためにスワッピングを無効にすることをお勧めします。
  • コンテナー: gnupg、openssl、procps のパッケージが UBI ベースのコンテナー イメージから削除されました。
  • コンテナー: ビルド時にボールトに cap_ipc_lock 機能を設定します。コンテナー ランタイムは、Vault コンテナーを実行するときに IPC_LOCK 機能を追加する必要があります。
  • 物理/postgresql: 重大な変更 - PostgreSQL ストレージ バックエンド認証では、マネージド ID よりも Azure Workload Identity が優先されるようになりました。 go-pgmultiauth を v1.1.0 に更新します。 Workload Identity が構成されている場合、既存のマネージド ID ベースの PostgreSQL 構成が機能しなくなる可能性があります。 影響を受けるユーザーは、PostgreSQL 認証を Workload Identity に移行する必要があります。
  • pki: デフォルトの sign-verbatim ディレクトリ ポリシーによる ACME ファイナライゼーションは、URI SAN、電子メール SAN、またはその他の SAN を含む CSR を拒否するようになりました。 ACME チャレンジは DNS 名と IP アドレスのみを検証します。これらの SAN タイプは決して検証されず、発行された証明書に含めてはなりません。以前の動作を必要とするオペレーターは、結果として得られる証明書に未検証の ID 要求が含まれる可能性があることを受け入れて、config/acme に default_directory_policy = "sign-verbatim-unsafe" を設定できます。
