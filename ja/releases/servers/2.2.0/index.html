サーバー v2.2.0

セキュリティ: Node.js ランタイムおよび CA 証明書の更新 (2026 年 10 月)

2026 年 10 月 20 日、eMudhra は、8 つの中間 CA 証明書の秘密キーが公開証明書から復元できることを明らかにしました。 10 月 21 日、Node.js は、セキュリティ侵害に対してバンドルされた CA 証明書を更新し、関連性のない重要度の高いランタイム CVE をいくつか修正する セキュリティ リリース を出荷しました。 10 月 23 日、Python の certifi 2026.10.23 は eMudhra のルート emSign Root CA - C1 と emSign ECC Root CA - C3 を削除しました。 これらのサーバーの現状

  • TypeScript サーバーは、証明書チェックのために Node.js ランタイムに依存しています。 独自の CA 証明書は提供されません。 server-everything のみがアウトバウンド HTTPS リクエスト (gzip-file-as-resource) を作成し、それを実行する Node.js がそれらを検証します。 server-filesystem、server-memory、server-sequential-thinking はネットワーク接続を行いません。
  • mcp-server-fetch は、httpx を通じて certifi バンドルに対して HTTPS を検証します。 PyPI (uvx mcp-server-fetch、pip install mcp-server-fetch) からインストールすると、現在の certifi、2026.10.23 以降が解決されます。リポジトリの fetch Docker ファイルはロックファイルからインストールされますが、このリリースではロックファイルが certifi 2026.10.23 (#5341) に移動されます。
  • mcp-server-git および mcp-server-time はネットワーク接続を行いません。 npm から TypeScript サーバーを実行する場合 (npx またはグローバル インストール) Node.js で動作しますが、更新することはできません。 Node.js 24.22.1 または 26.12.1 以降を実行し、node --version で確認してください。パッケージの engines フィールドはあらゆる Node.js 24 を受け入れるため、npm はパッチが適用されていない古いランタイムについて警告しません。 既存の環境から mcp-server-fetch を実行する場合 10 月 23 日より前に作成された環境では、古い certifi が保持されます。 uvx --refresh mcp-server-fetch、またはpip install -U certifiでリフレッシュしてください。

servers v2.2.0

Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped security releases that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's certifi 2026.10.23 removed the eMudhra roots emSign Root CA - C1 and emSign ECC Root CA - C3.

How these servers stand

  • The TypeScript servers rely on the Node.js runtime for certificate checks. They ship no CA certificates of their own. Only server-everything makes outbound HTTPS requests (gzip-file-as-resource), and the Node.js it runs on verifies them. server-filesystem, server-memory and server-sequential-thinking make no network connections.
  • mcp-server-fetch verifies HTTPS against the certifi bundle, through httpx. Installing from PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolves the current certifi, 2026.10.23 or later. The repository's fetch Dockerfile installs from its lockfile, which this release moves to certifi 2026.10.23 (#5341).
  • mcp-server-git and mcp-server-time make no network connections.

If you run a TypeScript server from npm (npx or a global install)

It runs on your Node.js, which we can't update for you. Please run Node.js 24.22.1 or 26.12.1, or later, and check with node --version. The packages' engines field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

If you run mcp-server-fetch from an existing environment

An environment created before October 23 keeps its older certifi. Refresh it with uvx --refresh mcp-server-fetch, or pip install -U certifi.
