servers v2.1.0

サーバー v2.1.0

セキュリティ修正

v2.1.0 は 3 つのサーバーの 8 つの脆弱性を修正します。アップグレード @modelcontextprotocol/server-filesystem および @modelcontextprotocol/server-everything 2.0.1、mcp-server-fetch から 2026.10.24 まで。 |パッケージ |影響を受ける | | で修正されました | --- | --- | --- | | @modelcontextprotocol/server-filesystem | 1.0.0 から 2.0.0 まで、日付バージョンは 2026.8.31 まで | 2.0.1 | | @modelcontextprotocol/server-everything | 1.0.0 ～ 2.0.0、日付バージョン 2025.9.24 ～ 2026.8.31 | 2.0.1 | | mcp-server-fetch | 2026.10.19を通して | 2026.10.24 |

@modelcontextprotocol/server-filesystem 2.0.1

  • 書き込みはチェックされたディレクトリ内に残ります (Linux および macOS)。アクセス チェックと書き込みの間でシンボリック リンク用に交換された親ディレクトリは、許可されたディレクトリの外に write_file、edit_file、create_directory、または move_file 宛先をリダイレクトできなくなります。 Windows では、これは部分的にのみ修正されています。アドバイザリには、依然として公開されているものと、それを回避する設定方法が記載されています (GHSA-53mr-w429-c597)
  • パスは使用されるとおりに正確にチェックされます。 アクセス チェックでは、ファイル操作で保持される末尾の引用符や空白が削除されなくなりました。そのため、そのサフィックスを持つ許可されたディレクトリにちなんで名付けられた兄弟ディレクトリにはアクセスできなくなります (GHSA-7rgq-gccq-qphx)
  • **大文字と小文字が異なるシンボリックリンクは、macOS のデフォルトなど、大文字と小文字を区別しないボリューム上の新しいパスのシンボリックリンク チェックに合格しなくなりました。これは 2026.8.31 (GHSA-4gxg-m5jx-9j57) における回帰でした。
  • list_directory_with_sizes は、サイズを読み取る前に各エントリをチェックします。そのため、許可されたディレクトリ内のシンボリックリンクでは、その外側のファイルのサイズと変更時刻が明らかになりません (GHSA-hhwq-wxfx-cj7g)

@modelcontextprotocol/server-everything 2.0.1

  • HTTP および SSE トランスポートは、他の Web オリジンからのリクエストを拒否します。 Origin ヘッダーをチェックし、Access-Control-Allow-Origin: * を送信しなくなりました。そのため、ユーザーがアクセスした Web ページは、サーバーのツール (get-env など) を呼び出したり、その結果を読み取ったりすることができなくなりました (GHSA-mvf5-2qqv-rg3c)。

mcp-server-fetch 2026.10.24

  • アドレス チェックと接続では同じホスト名が使用されます。 国際化 (IDNA) ホスト名の場合、サーバーは名前の 1 つの形式をチェックし、内部アドレスに到達する可能性のある別の形式に接続していました (GHSA-v38p-wf49-hx2j)
  • NAT64 アドレスは、伝送される IPv4 アドレスによって判断されます。 プライベート、ループバック、またはリンクローカル IPv4 アドレスをラップする 64:ff9b::/96 のアドレスは、IPv4 にマップされたものとしてすでに拒否されるようになりました (GHSA-66qx-2266-pmj6)。
  • robots.txt は、最初にリクエストされた URL (GHSA-3jqg-r5pp-rmp2) だけでなく、リダイレクトのたびに再度チェックされます

日付バージョンの npm リリースからのアップグレード

TypeScript サーバーは、日付バージョン (2025.x、2026.x) から 1.0.0 のセマンティック バージョンに移行しました。パッケージ マネージャーは、2.0.1 を 2025.x および 2026.x の各バージョンよりも下にランク付けするため、アップグレードとして提供しません。日付バージョンを使用している場合は、2.0.1 (例: npm install @modelcontextprotocol/server-filesystem@2.0.1) を明示的にインストールします。

servers v2.1.0

Security fixes

v2.1.0 fixes eight vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem and @modelcontextprotocol/server-everything to 2.0.1, and mcp-server-fetch to 2026.10.24.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | 1.0.0 through 2.0.0, and date versions through 2026.8.31 | 2.0.1 | | @modelcontextprotocol/server-everything | 1.0.0 through 2.0.0, and date versions 2025.9.24 through 2026.8.31 | 2.0.1 | | mcp-server-fetch | through 2026.10.19 | 2026.10.24 |

@modelcontextprotocol/server-filesystem 2.0.1

  • Writes stay inside the directory that was checked (Linux and macOS). A parent directory swapped for a symlink between the access check and the write can no longer redirect write_file, edit_file, create_directory or the move_file destination outside the allowed directories. On Windows this is only partly fixed; the advisory says what is still exposed and how to configure around it (GHSA-53mr-w429-c597)
  • Paths are checked exactly as they are used. The access check no longer strips a trailing quote or whitespace that the file operation keeps, so a sibling directory named after an allowed one with that suffix is no longer reachable (GHSA-7rgq-gccq-qphx)
  • A symlink spelled in a different letter case no longer passes the symlink check for a new path on a case-insensitive volume, such as macOS's default. This was a regression in 2026.8.31 (GHSA-4gxg-m5jx-9j57)
  • list_directory_with_sizes checks each entry before reading its size, so a symlink inside an allowed directory no longer reveals the size and modification time of a file outside it (GHSA-hhwq-wxfx-cj7g)

@modelcontextprotocol/server-everything 2.0.1

  • The HTTP and SSE transports refuse requests from other web origins. They now check the Origin header and no longer send Access-Control-Allow-Origin: *, so a web page the user visits can no longer call the server's tools (such as get-env) or read their results (GHSA-mvf5-2qqv-rg3c)

mcp-server-fetch 2026.10.24

  • The address check and the connection use the same host name. For an internationalized (IDNA) host name, the server used to check one form of the name and connect to another, which could reach an internal address (GHSA-v38p-wf49-hx2j)
  • NAT64 addresses are judged by the IPv4 address they carry. An address in 64:ff9b::/96 that wraps a private, loopback or link-local IPv4 address is now refused, as an IPv4-mapped one already was (GHSA-66qx-2266-pmj6)
  • robots.txt is checked again after every redirect, not only for the URL first requested (GHSA-3jqg-r5pp-rmp2)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.0.1 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version, install 2.0.1 explicitly, for example npm install @modelcontextprotocol/server-filesystem@2.0.1.
