DeepSpeed v0.18.4

Highlights

  • DeepCompile on newer PyTorch — Compatibility fixes for PyTorch 2.8/2.9 remove a blocker for compiled training on those versions (#7755). CI now covers Python 3.11/3.12 (#7007), although deterministic compile testing is disabled and AMP tests were removed (#7720, #7745), reducing coverage for those paths.
  • Gradient-scaling behavior — The engine now scales gradients only when scale_wrt_gas=True (#7724). Custom loops that relied on unconditional scaling should verify scaling ownership to avoid double-scaling or missed updates. The sqrt learning-rate scheduler also uses math.sqrt, avoiding tensor-related type issues (#7735).
  • Checkpoint reliability and MoE migration — Fixes address Nebula’s checkpoint commit() API mismatch and DecoupledCheckpointEngine deadlocks (#7740, #7742), improving distributed-save reliability. MoE checkpointing replaces dp_world_size with seq_dp_world_size (#7732); audit custom checkpoint readers and writers that reference the old field.
  • Optimizer and backward-hook robustness — Fixes cover missing param_names in Stage 3 SuperOffload, None entries in backward hooks, OnebitLamb NaN propagation with empty parameters, and BF16 DummyOptimizer teardown failures (#7715, #7725, #7736, #7763). These reduce crashes in mixed-parameter configurations and optimizer cleanup paths.
  • PEFT with context-parallel attention — UlyssesSPAttentionHF.register_with_transformers() no longer crashes with PEFT models (#7737), removing a blocker to combining Ulysses sequence parallelism with adapter-based fine-tuning.
  • ROCm and runtime stability — AMD/ROCm support improvements (#7448), releasing the Python GIL during Async I/O waits (#7727), and removing a premature MPI environment-variable check (#7751) reduce platform-specific launch failures and rare I/O hangs.

No breaking changes are declared.
