DeepSpeed v0.19.3

Highlights

  • ZeRO-3 mixed-precision correctness — Several fixes correct how ZeRO-3 gathers parameters with mixed dtypes: _allgather_params_coalesced now uses per-param dtype for output buffers (PR #8073) and quantize-scale buffers (PR #8128), autocast gathers of mixed-dtype params are fixed (PR #8113), and ZeRO-3 hooks now work with attribute-delegating modules (PR #8144). If you train with ZeRO-3 under bf16/fp16 or quantization, these are real correctness fixes, not cosmetic ones.

  • Changed defaults that alter training behavior — Defaults shifted silently: gradient_clipping now defaults to 1.0 (PR #8068), bf16 check_grad_overflow is enabled by default to match fp16 (PR #8035), activation_checkpointing defaults num_layers to None so the configure() assertion fires (PR #8041), and fp16 dynamic loss-scaling params are validated as positive (PR #8050). Review your configs before upgrading — runs that relied on the old implicit defaults may behave differently.

  • Deprecations and config migration — ZeRO-3 elastic checkpoint is deprecated (PR #8099); users relying on it need a migration path. Muon + reduce_scatter under ZeRO-1/2 was first rejected (PR #8090) then given proper support in the same release (PR #8141), backed by numerical-correctness tests (PR #8091). New validation lands in save_checkpoint and warmup LR schedulers (PR #8126), plus a ZeroDivisionError guard when total_num_steps == warmup_num_steps (PR #8142).

  • New capabilities — Hybrid Engine rollout for the On-Policy Distillation (OPSD) Trainer (PR #8027), AutoEP + AutoTP parallel folding (PR #8064) and AutoEP support for ZeRO-3 zero.Init source modules (PR #8060), an optional torchembed backend for apply_rotary_pos_emb (PR #8052), EXAONE 4.5 support in Inference V2 (PR #8121), a configurable engine log level (PR #8067), and type hints across public APIs (PR #8079, PR #8118).

  • DeepCompile/stability fixes and upgrade verdict — DeepCompile gets multiple fixes (profile metadata backfill PR #8094, profiling memory cleanup PR #8106, gather in dynamo-skipped frames for ZeRO-3 PR #8059, scalar-output fallback PR #8149), alongside a security-relevant buffer-length check in shm.cpp (PR #8082), an fd-leak fix in deepspeed_io_handle_t::wait() (PR #8075), and a Python 3.9 AutoEP import fix (PR #8119). Upgrade if you use ZeRO-3, DeepCompile, AutoEP/AutoTP, or Python 3.9; the rest is CI/DCO/docs churn (incl. version bump PR #8070) with no runtime impact, so stable non-ZeRO-3 setups can skip.
