DeepSpeed v0.19.6

Highlights

  • Apple Silicon (MPS) support enters Phase 1 — ZeRO Stages 1–3 now run on MPS backends (#8293), backed by a new Metal FusedAdam kernel and CPU Adam build (#8300), async staging of isend/irecv through nonblocking backend methods (#8303), and fewer redundant copies in MPS P2P staging (#8314). This is the headline capability for adopters: it opens local Mac-based training with familiar ZeRO semantics, but it is explicitly a first phase — kernel/op parity with CUDA is incomplete, so validate convergence and unsupported ops before moving real workloads onto it.
  • AutoTP matures toward production use — A compiler pass for automatic tensor parallelism lands as the first of a series (#8204), uneven sharding and universal-checkpoint support are completed (#8185), and correctness fixes cover unsharded-module metadata (#8299), lm_head training routing (#8302), HF embedding_rowwise plans mapped to SKIP specs (#8294), and a ZeRO-3 crash in universal-checkpoint metadata (#8270). For adopters this meaningfully reduces silent checkpoint/layout-mismatch risk, but the feature is still spread across many in-flight PRs — pin the version and re-validate checkpoint portability on upgrade.
  • DeepCompile and memory offload get faster and safer — Fixes cover frozen parameters under ZeRO-3 (#8214), last-use handling for unconsumed waits (#8254), Python 3.9 staticmethods (#8240), and pass-contract alignment with actually scheduled passes (#8251). On top of that come activation offloading (#8255), non-reentrant CPU checkpoint offload (#8282), a new compile.offload_activation_pin_memory flag (#8258), and native DeepNVMe host-memory pinning registered with CUDA for GPU DMA (#8211, #8283), with pin sites routed through accelerator.pin_memory (#8256, #8257). The practical takeaway: offload paths now depend on pinning behavior, so re-tune offload settings and watch host-memory registration on your accelerators.
  • Behavioral changes to watch — NCCL and other process-group backends now default to a 10-minute timeout instead of 30 (#8253); long jobs with slow checkpoint saves, elastic scaling, or straggling ranks can now fail faster on watchdog timeouts, so set a longer timeout explicitly if you relied on the old window. Also: DeepSpeedConfig no longer writes max_grad_norm back into the caller's dict (#8289), OneCycle now honors the documented per-parameter-group lists (#8201), the nonexistent grad_hooks ZeRO option is dropped from docs (#8242), and OnebitLamb.get_lamb_coeffs returns a copy (#8227). Audit any code that read values back from the config dict or relied on shared mutable coefficient arrays.
  • RL rollout and MoE kernel throughput — HybridEngine generation gains CUDA graph support (#8271), rollout profiling (#8295), and shared prompt prefill across rollout samples (#8296), while a fused Triton SwigLU kernel (#8244), an int32-overflow fix in grouped-GEMM expert offsets (#8261), and parameter-dtype preservation through ZeRO-3 weight quantization (#8215) target MoE training. If you run RLHF-style training or MoE models these are the wins to look for, but the kernel and quantization fixes can shift numerics — validate against your baselines.
  • Breaking changes — None; this is a backward-compatible patch release, with the changes above being additive capabilities, correctness fixes, and the noted behavioral adjustments.
