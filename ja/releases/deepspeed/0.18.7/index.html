  • XPU は、https://github.com/deepspeedai/DeepSpeed/pull/7877 の @delock による Intel Extension for PyTorch の代わりにストック pytorch を使用します
  • https://github.com/deepspeedai/DeepSpeed/pull/7879 の @delock により抽象アクセラレータから amp() を削除
  • https://github.com/deepspeedai/DeepSpeed/pull/7883 に @tohtana によるオートキャストのネストを説明するドキュメント セクションを追加
  • https://github.com/deepspeedai/DeepSpeed/pull/7886 の @tohtana による v0.18.5 からのフック数のパフォーマンスの低下を修正

DeepSpeed v0.18.7

Highlights

  • Faster ZeRO-1/2 initialization — Parameter groups are now flattened on the accelerator when enough free device memory exists for the aligned flat buffer, avoiding CPU-side copies and transfers (#7828). Upstream’s 8×H100 benchmark for a 32-layer Qwen3-30B ZeRO-2 configuration drops from ~382s to ~130s; memory-constrained runs retain the CPU path, while the fast path requires temporary device memory.
  • ZeRO backward performance and PyTorch 2.3 compatibility — Expected hook counts are cached at backward-phase boundaries instead of rescanned for every gradient hook, eliminating the v0.18.5 quadratic overhead in ZeRO-2/3 (#7886). Grad-accumulation lookup now enables grad mode during backward hooks, fixing PyTorch 2.3 AttributeError failures (#7841).
  • Stricter GatheredParameters mutation rules — With ZeRO-3 sanity checks enabled, in-place edits inside GatheredParameters(..., modifier_rank=None) now raise a rank-synchronized RuntimeError rather than allowing uncoordinated updates (#7832). Use modifier_rank=<rank> when one rank modifies parameters and the result must be broadcast; audit rank-local mutation code.
  • XPU and autocast breaking migrations — Intel XPU now uses upstream PyTorch’s torch.xpu and SYCL extension machinery instead of IPEX; xpu.external and the IPEX-backed XPU inference builder are removed (#7877). Custom accelerator code must replace get_accelerator().amp() with torch.amp.* and explicit device_type; pre-2.4 fallbacks are gone (#7879). XPU deployments should use an official XPU wheel and an icpx version matching its SYCL runtime.
  • Broader inference and hardware support — Inference V2 adds EXAONE 4.0 (#7853), replaces CUDA-only BF16 conversion intrinsics with ROCm-compatible paths while preserving CUDA behavior (#7846), and fixes Evoformer compilation (#7862). Arm gains shm_comm support (#7800), widening shared-memory communication options on Arm hosts.
  • Partial-training and failure-handling fixes — Muon parameter groups now exclude requires_grad=False parameters, preventing empty-group failures when frozen layers leave only one optimizer type active (#7869). Replacing 35 bare except clauses with except Exception lets KeyboardInterrupt and SystemExit propagate instead of being swallowed (#7873).
