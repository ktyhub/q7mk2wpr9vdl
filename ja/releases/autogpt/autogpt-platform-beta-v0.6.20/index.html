AutoGPT autogpt-platform-beta-v0.6.20

Highlights

  • New model providers land in the platform — #10559, #10574, #10575 add OpenAI's open-weight models, GPT-5, and Claude Opus 4.1. If you pin model identifiers in block configs or templates, verify the new IDs and re-run any prompt evaluation: GPT-5 in particular changes reasoning/parameter behavior, so "drop-in" is likely not literal for tuned prompts.
  • AgentExecutor switches from processes to threads — #10540 moves execution from ProcessPoolExecutor to ThreadPoolExecutor. This is the most consequential behavioral change for adopters: you lose process-level isolation (a segfault or global-state leak now affects the host), but gain cheaper spawning and shared memory. Watch CPU-bound, GIL-serialized workloads for throughput regressions and re-check any code that relied on cross-process state not being shared.
  • Standardized health checks via UnhealthyServiceError — #10584 unifies how services report degraded state. Custom service integrations and any code that parses or catches health-check failures should be updated to the new exception type; this is the kind of change that surfaces only when a dependency actually goes unhealthy, so test failure paths explicitly rather than just the happy path.
  • Notifications decoupled from the scheduler and made fully async — #10579 splits the notification service out of the scheduler, while #10564 and #10578 fix RabbitMQ connection handling (full async migration; no more operations on closed/closing connections) and #10566 closes leaking HTTP client sessions. Together these target stability under load — expect fewer mysterious notification drops and connection/resource leaks, but re-validate any deployment that assumed notifications were scheduled inline.
  • Errors and recurring jobs become more observable and safer — #10562 persists any non-interruption node-execution error as output, so failures stop vanishing and become debuggable from results; #10568 adds graph validation before scheduling recurring jobs, meaning invalid graphs now fail early instead of silently producing broken schedules. Existing automations should be checked against validation rules before upgrading.
  • Smaller fixes worth noting — #10576 extends time/date blocks with ISO 8601 and custom formats (review parse-sensitive flows), #10573 fixes Airtable OAuth losing the ID on token refresh (re-auth affected integrations), and #10577 reverts the Docker Compose frontend service addition — if you adopted that setup, the frontend is no longer composed automatically and needs manual wiring.

No breaking API changes in this release.
