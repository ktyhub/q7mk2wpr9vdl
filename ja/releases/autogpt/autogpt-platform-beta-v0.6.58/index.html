AutoGPT autogpt-platform-beta-v0.6.58

Highlights

  • Usage-based billing is now unit-aware — BlockCostType supports SECOND, ITEMS, COST_USD, and TOKENS, with E2B/FAL adopting dynamic costing (#12894). Dynamic USD billing, per-post Ayrshare charges, and corrected LLM/block rates close multiple cost-leak paths (#12909, #12893, #12912). Custom blocks using fixed cost assumptions should migrate to the new unit-aware model, including COST_USD where appropriate.
  • Pricing and subscription rollout are remotely configurable — The new MAX tier, LaunchDarkly-configurable pricing, hidden unconfigured tiers, and adjustable rate-limit multipliers let operators change plans without redeploying (#12903, #12910). Subscription credits, paywalls, and onboarding plan selection are gated by ENABLE_PLATFORM_PAYMENT; validate the plan and credit configuration before enabling it (#12933, #12935, #12943).
  • Copilot handles longer sessions more reliably — The baseline tool-round limit increases to 100 with graceful finish hints, while tunable Kimi compaction, transport-based model normalization, reconnect/hydration fixes, and pending-tool idle handling improve long-running sessions (#12892, #12889, #12932, #12813, #12927). The ask_question tool is temporarily disabled pending a UX rework (#12887), although interrupted partial work is now preserved on final failure (#12918).
  • Custom inputs and sandbox exit handling changed — run_block now supports inline picker-backed inputs and accepts AgentInputBlock subclasses, enabling richer block UIs (#12880). Non-zero E2B exits are returned as normal results instead of sandbox errors (#12904); execution handlers must inspect result/exit status rather than relying on an exception.
  • Feature-flag and deployment configurations require migration — Six LaunchDarkly flags consolidate into two JSON flags, and four Copilot model-routing flags into one (#12915, #12917). Update existing dashboard or deployment configurations that reference the old individual flags. SQL migrations now use {schema_prefix} rather than hard-coded platform., improving compatibility with non-default schemas (#12905).
  • New platform surfaces and infrastructure support — Settings v2 covers API keys, integrations, profiles, preferences, and creator dashboards behind SETTINGS_V2 (#12885, #12907, #12911, #12924, #12925, #12934). Claude Opus 4.7 is now supported (#12826), alongside Redis Cluster support, atomic notification upserts, and VAPID web push for background delivery (#12900, #12919, #12723).
