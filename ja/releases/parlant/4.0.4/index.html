parlant v4.0.4

#パーラントv4.0.4

[4.0.4] - 2026-11-08

追加されました

  • Agent.queue_response() は、バックグラウンドのフォローアップと他の準備済みの結果または顧客ターンを組み合わせます。 after=coroutine を渡して、開始前に作業を登録します。遅延応答のみが登録されたバッチを待ちます。調整は 1 つのプロセス内で行われ、セッション ルーティング アフィニティが必要です。保留中の作業は再起動後に回復されません。キューに入れられた返信は履歴の編集を許容し、古いテキストを追加することなく中断されたストリームを終了します。

変更されました

  • ツールのプリアンブルが推奨される場合、エージェントはそれを作成し、それに続く進捗状況を顧客の言語で更新します。
  • エージェントは、別の質問に回答できない場合に、新しい質問をすでに回答済みのものとして扱うことなく、情報のギャップが繰り返し発生することを認識します。
  • エージェントは、タスクの詳細を収集する前に、顧客が曖昧な場合にどのレコードまたはリクエストを意味するのか、およびいくつかの未完了のリクエストのうちどれを最初に処理するかを尋ねます。

修正済み

  • Gemini の会話は、履歴がクリアされた後、無効なツール応答の順序付けエラーが発生することなく、バックグラウンドの結果から再開できます。
  • Parlant ダッシュボードでは、エージェントがメッセージをストリーミングするときに、エージェント アクティビティの下にエージェントの推論が表示されるようになりました (create_agent のデフォルト)。各ステップの推論は、loop.reasoning トレース イベントとして記録されるようになりました。以前は、ログ行としてのみダッシュボードに到達し、ダッシュボードはブロック出力モードでエージェントからのみ読み取りました。 parlant[anthropic] は現在の Anthropic SDK で動作します。新規インストールでは、人造 1.0 以降が選択されましたが、その client が Parlant の要求タイムアウトを拒否したため、Claude モデルは起動できませんでした。追加には anthropic>=1.0.0 が必要になりました。これを回避するために、プロジェクトで人間の上限が 1.0 未満になっている場合は、上限を外してください。
  • チャット ウィジェットは、英語の単語、URL、またはコードで開いた場合でも、ヘブライ語などの右から左への返信を右から左にレイアウトします。以前は最初の文字の方向を採用していたため、そのような返信は左から右に読まれ、句読点は反対側にありました。各段落、メッセージ ボックス、提案ボタンは、ほとんどの単語が含まれるスクリプトに従うようになりました。

[4.0.3] - 2026-11-05

変更されました

  • parlant ダッシュボード コマンドは、どのコマンドが各リクエストを送信したかを Parlant ダッシュボードに通知するようになりました。すべてのリクエストには、User-Agent: parlant-cli/<version>、X-Parlant-CLI-Command 内のコマンド名 (たとえば、parlant ダッシュボード セッション リスト。その引数やオプション値は含まれません)、および 1 回の実行のすべてのリクエストで共有される X-Parlant-CLI-Invocation ID が含まれます。ダッシュボードはこれらを使用して、実行したコマンドとして CLI アクティビティを表示します。

parlant v4.0.4

[4.0.4] - 2026-11-08

Added

  • Agent.queue_response() combines background follow-ups with other ready results or a customer turn. Pass after=coroutine to register work before it starts; only the deferred reply waits for the registered batch. Coordination lives in one process and requires session routing affinity; pending work is not recovered after a restart. Queued replies tolerate history edits and terminate interrupted streams without appending stale text.

Changed

  • When tool preambles are encouraged, the agent writes them, and the progress updates that follow, in the customer's language.
  • Agents acknowledge recurring information gaps when different questions cannot be answered, without treating a new question as one already answered.
  • Agents ask which record or request the customer means when it's ambiguous, and which of several unfinished requests to handle first, before collecting task details.

Fixed

  • Gemini conversations can resume from background results after history is cleared, without an invalid tool-response ordering error.
  • The Parlant dashboard now shows your agent's reasoning under Agent activity when the agent streams its messages, the default for create_agent. Each step's reasoning is now recorded as a loop.reasoning trace event. Before, it reached the dashboard only as a log line, which the dashboard read only from agents in block output mode. parlant[anthropic] works with the current Anthropic SDK. A fresh install picked anthropic 1.0 or later, whose client refused Parlant's request timeout, so no Claude model could start. The extra now requires anthropic>=1.0.0; if your project capped anthropic below 1.0 to work around this, drop the cap.
  • The chat widget lays out a right-to-left reply, such as Hebrew, right to left even when it opens with an English word, a URL or code. It used to take the direction from the first letter, so such a reply read left to right with its punctuation on the wrong side. Each paragraph, the message box and the suggestion buttons now follow the script most of their words are in.

[4.0.3] - 2026-11-05

Changed

  • parlant dashboard commands now tell the Parlant dashboard which command sent each request. Every request carries User-Agent: parlant-cli/<version>, the command's name in X-Parlant-CLI-Command (for example parlant dashboard session list, never its arguments or option values), and an X-Parlant-CLI-Invocation id shared by every request from one run. The dashboard uses them to show your CLI activity as the commands you ran.
