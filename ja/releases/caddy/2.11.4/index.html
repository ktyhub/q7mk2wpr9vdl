#キャディv2.11.4

このリリースでは、より多くのセキュリティ、セキュリティ関連のバグ、および通常のバグにパッチが適用されます。 FrankenPHP プロジェクトは、PHP に関連するパッチに関して協力してきました。これには感謝しています。

最近のパッチの急増は、主にトークン予測子によるものです。 「セキュリティ」レポートの 75% 以上を、AI のスロップスパム (または単に怠惰/不正確) だったため、拒否しなければなりませんでした。貴重なメンテナのリソースを無駄にしないように、LLM とエージェントを賢く使用してください。スパム報告を行った問題のあるアカウントのブロックを開始しました。プロジェクトをより良いものにするために、セキュリティ ポリシーに従って責任あるレポートを提出してくださった皆様に感謝します。コミュニティが Caddy プロジェクトをより広範なエコシステムの改善に貢献する価値があるとみなしていることに感謝します。

セキュリティ関連のパッチ:

  • caddyhttp: パスマッチャーで Windows のバックスラッシュを正規化 (@Vincent550102 に感謝)
  • 書き換え: 挿入されたクエリでのプレースホルダーの再展開を防止します (@WhiskerEnt に感謝)
  • テンプレート: 不正な HTML をより確実に削除するために stripHTML アクションを改善しました (@jmrcsnchz に感謝)
  • caddyhttp: 衝突を防ぐためにアンダースコアのあるヘッダー フィールドを無視します (@Vincent550102 のレポートと @dunglas のパッチに感謝します)

:警告: アプリケーションがバグのある動作に依存している場合、これらのセキュリティ パッチは壊れる可能性があります。

また、他の多くの貢献者によるさまざまな修正や機能強化もいくつかあります。参加してくれた皆さん、ありがとうございました！

caddy v2.11.4

Highlights

  • Security hardening with breaking potential — v2.11.4 lands four fixes the maintainers flag as possibly breaking if you depended on the buggy behavior: Windows backslashes are now normalized in path matchers (#7763), injected query strings no longer re-expand placeholders (#7761), stripHTML more aggressively strips malformed markup (#7785, GHSA-vcc4-2c75-vc9v), and header fields containing underscores are ignored to prevent collisions (patch by @dunglas). If your Caddyfile relied on \ in path matching, nested placeholders in rewritten queries, or underscore-named headers, regression-test those routes before rollout. Note the maintainers' warning about the patch surge — they rejected >75% of "security" reports as AI slop and are blocking repeat offenders, so expect a higher signal-to-noise bar on future advisories.
  • TLS correctness under load and IDN — client authentication is repaired (#7727, fixing #7724), TLS state races and ECH rotation retries are addressed (#7756), and connection policies now match IDN SNI values correctly (#7742) while skipping idna.ToASCII for pure-ASCII SNI as a fast path (#7770). If you run mTLS or ECH, these are the most operationally relevant fixes — upgrade to eliminate intermittent handshake failures rather than treating them as config drift.
  • Reverse proxy body lifecycle — two related patches (#7715, #7719) further prevent upstream request bodies from being closed on dial errors or when the body was never read, plus a regression test locking in the DialInfo network override (#7758). This matters for retry/load-balancing setups: previously a failed dial could close a body still needed for a retry, producing confusing 502s under transient network faults.
  • Behavioral changes in encoding and caching — content negotiation now prioritizes zstd and br over gzip (#7772), so clients advertising modern encodings will see different Content-Encoding headers and smaller payloads; separately, Last-Modified is omitted when the mod time is unusable (#7740), which should reduce bogus 304/conditional-request behavior on generated content. Both are observable wire-level changes worth checking against any downstream caching or snapshot tests.
  • Usability and platform fixes — caddy start now works on IPv6-only hosts (#7744), Caddyfile parsing preserves implicit TLS issuer semantics (#7743), authentication gains candidate placeholders for rejected identities (#7698), and the replacer allocates less for file placeholders (#7773). Together these lower friction for IPv6 deployments and auth-debugging workflows, with a small memory-allocation win on high-throughput request paths.

This release patches more security, security-adjacent, and normal bugs. The FrankenPHP project has collaborated on PHP-adjacent patches, which we are grateful for.

The recent surge of patches is mostly attributed to token predictors. We have had to reject more than 75% of "security" reports because they were AI slop spam (or just lazy/incorrect). Please use LLMs and agents wisely to avoid wasting precious maintainer resources. We have started blocking offending accounts that spam slop reports. Thank you to all who submit responsible reports following our security policy to make the project better. We appreciate that the community deems the Caddy project worthy of contribution to improve the broader ecosystem!

Security-related patches:

  • caddyhttp: Normalize Windows backslashes in path matcher (thanks @Vincent550102)
  • rewrite: Prevent placeholder re-expansion in injected query (thanks @WhiskerEnt)
  • templates: Improved stripHTML action to more reliably remove malformed HTML (thanks to @jmrcsnchz)
  • caddyhttp: Ignore header fields with underscores to prevent collisions (thanks @Vincent550102 for the report and @dunglas for the patch)

:warning: These security patches may be breaking if your application relies on the buggy behaviors.

There are also several other various fixes and enhancements by many other contributors. Thank you everyone who participated!
