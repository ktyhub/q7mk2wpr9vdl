gstack v1.91.318.0 (regular release)

76 versions since v1.91.242.0, one line each. Compare or read the full changelog.

Team-mode installs follow the stable branch, which now points here; gstack-config set update_channel main follows every merge instead (docs/releases.md).

  • 1.91.317.0 (2026-10-29): In OpenClaw, Hermes and other agent tools, each registered gstack skill opens with when to use it, and OpenClaw lists the main task skills (review, investigate, qa, ship, plan-eng-review) directly. (#3555)
  • 1.91.316.0 (2026-10-29): /ship takes a token cap (--token-cap) and stops cleanly when it reaches it, and long runs hand heavy steps to fresh subagents. (#3593)
  • 1.91.315.0 (2026-10-29): After a stacked PR's parent merges and the child is retargeted to main, the child keeps its /ship review as long as its own changes are unchanged. (#3572)
  • 1.91.314.0 (2026-10-29): When a later /autoplan approval question asks nothing new, gstack reuses the owner's earlier answer instead of asking again. (#3583)
  • 1.91.313.0 (2026-10-29): The PII scanner stops flagging two kinds of ordinary text: a bare power-of-two or hash constant in code, and a package@version-style filename. (#3578)
  • 1.91.312.0 (2026-10-29): An install check run from inside /ship no longer upgrades gstack under it. (#3573)
  • 1.91.311.0 (2026-10-29): A sealed-files policy can block sealed/<set>/tasks.json while allowing the MANIFEST.json next to it, and can match HELDOUT/ regardless of case. (#3556)
  • 1.91.308.0 (2026-10-29): gstack's version renumbering no longer cuts a four-part package.json version to three parts in a repository that uses four. (#3557)
  • 1.91.307.0 (2026-10-29): /ship's review depth now matches what the diff can break: light, standard or full. (#3567)
  • 1.91.306.0 (2026-10-29): /ship's review record now survives a base merge that only regenerates generated files, and a rebase onto the code it reviewed. (#3564)
  • 1.91.305.0 (2026-10-29): You can now render gstack with whole skills, skill sections, model overlays or preamble pieces left out, as a byte-exact tree with a lock file, so an eval can measure which instructions a model actually needs. (#3554)
  • 1.91.304.0 (2026-10-29): Running the Capy installer for a second workflow on the same machine no longer revokes the first workflow's install check. (#3563)
  • 1.91.303.0 (2026-10-29): gstack-pr-shots no longer edits your .gitignore in the middle of /ship, which made /ship's checks go stale and its final record fail to write. (#3562)
  • 1.91.298.0 (2026-10-28): Support for the Dia browser is removed: gstack no longer imports cookies from it. (#3551)
  • 1.91.297.0 (2026-10-28): The terminal agent on Windows no longer waits on PowerShell to learn its own start time, so it boots in about a second and a slow PowerShell can no longer leave it without an identity. (#3545)
  • 1.91.295.0 (2026-10-28): Deleting or renaming a test no longer makes /ship's test check fail with no test to run. (#3534)
  • 1.91.294.0 (2026-10-28): gstack-doctor and setup's hook check start far fewer processes, which makes them much faster on Windows. (#3540)
  • 1.91.293.0 (2026-10-28): gstack-harness errors print again, and register qm says plainly that QM cannot import gstack yet. (#3532)
  • 1.91.292.0 (2026-10-28): A fix for a regression on the stable channel can skip the 72-hour wait, like a security fix. (#3533)
  • 1.91.291.0 (2026-10-28): /ship and /autoplan scale their review to the size of the diff. (#3527)
  • 1.91.290.0 (2026-10-28): Installing gstack inside an agent harness now gives that harness gstack's skills, the harness's own way. (#3526)
  • 1.91.289.0 (2026-10-28): /plan-design-review, /office-hours and /design-review load 15 to 40 percent fewer bytes per run, with the same or better task results. (#3525)
  • 1.91.288.0 (2026-10-28): The stable channel moves twice a week, and never twice within 72 hours unless a security fix needs it. (#3523)
  • 1.91.287.0 (2026-10-28): New /write-skill writes, changes and slims down skills; its first pass halves /learn's template with the same results. (#3524)
  • 1.91.284.0 (2026-10-27):
    • New /modernize brings an aging pull request onto its current base and decides whether it should still exist. Adapted from Theo Browne's tstack (MIT), as are the next three. (#3497)
    • A skill can set the default prompt Codex's skill picker inserts when you choose it. (#3497)
    • gstack-post --attribute can open a PR or issue comment with a note naming the model and the person it was written for. (#3497)
    • docs/unattended.md says what an unattended session may do (never merge; force-push only its own branch), and CONTRIBUTING.md explains how to port a contributor's PR. (#3497)
  • 1.91.283.0 (2026-10-27): /benchmark's collection, comparison, budget and trend phases now agree with its vet-the-number section. (#3520)
  • 1.91.278.0 (2026-10-27): gstack-pr-wait --exclude <check> leaves a named optional check out of its verdict, and the merge queue no longer fails a PR for problems its own tools could see. (#3514)
  • 1.91.277.0 (2026-10-27): /office-hours stops carrying its own copy of the shared question-asking instructions, so it loads less text. (#3453)
  • 1.91.276.0 (2026-10-27): Larger skills load the shared preamble once per session instead of on every use. (#3434)
  • 1.91.275.0 (2026-10-27): A repository policy that uses docs.caps now requires gstack 1.91.270.0, the release that actually added it, instead of an earlier version that can't read it. (#3511)
  • 1.91.274.0 (2026-10-27): /design-html and /design-review run gstack's design lint, which reports each content problem at its line. (#3507)
  • 1.91.273.0 (2026-10-27): A PR body /ship writes opens with the problem it solves and what else the change touches, and its prose is checked for machine-written tells before it goes out. (#3501)
  • 1.91.272.0 (2026-10-27):
    • /investigate gains a blast-radius pass, read before changing a shared helper, library call or data format, that names what the change is safe because of and how far the evidence goes. Adapted from Lauren Tan's pstack (MIT), as are the next three. (#3500)
    • /context-restore rebuilds a brief from this project's own past transcripts (Claude Code or Codex) when no saved checkpoint exists. (#3500)
    • /benchmark checks a number before reporting a comparison (what limited it, does it reproduce, is the gap bigger than run-to-run variation) and ends with faster, slower, no measurable difference or inconclusive. (#3500)
    • /plan-eng-review compares a second, structurally different design before a plan adds a new module, service or package. (#3500)
  • 1.91.270.0 (2026-10-27):
    • /ship works in repositories with no VERSION file: it ships without a version change instead of creating one. (#3487)
    • /ship records the outcome of its documentation check, and a repository can cap the size of its doc files with docs.caps in its ship policy. (#3487)
    • /ship checks that the counts a PR body quotes (review passes, deferred findings, tests passed) match its own record of the run. (#3487)
    • New gstack-coauthor-trailers adds the Co-authored-by lines a set of ported commits owes, keeping co-authors already listed. (#3487)
    • /ship runs its review specialists in batches when the host has fewer free subagents than reviewers (--review-fanout auto|serial|parallel). (#3487)
    • /review's checklist adds two rules: flag a preregistration shipped together with its results, and a browser test that reaches an element by counting key presses. (#3487)
    • Reusing a /ship review across new commits needs git 2.39 or later, and gstack now says so by name on an older git. (#3487)
  • 1.91.269.0 (2026-10-27): An /autoplan approval question now shows its cost, and the approvals record is saved where every agent on the project can read it. (#3496)
  • 1.91.268.0 (2026-10-27): Two helpers adapted from Lauren Tan's pstack: gstack-decision-trail keeps a record of decisions a reviewer can read without the transcript, and gstack-worktree-audit says which Conductor worktrees are safe to remove. (#3494)
  • 1.91.266.0 (2026-10-27):
    • New gstack-pr-wait watches a pull request and prints one line per real event (a check failed, a review arrived, the PR merged), so an agent waits on CI with one call instead of polling; its design is adapted from Theo Browne's tstack (MIT). (#3495)
    • /land-and-deploy waits for CI with one gstack-pr-wait call instead of 4-minute polling rounds capped at 15 minutes. (#3495)
    • Two gstack-config keys choose which review bots gstack-pr-wait --until ready waits for and which it only reports. (#3495)
  • 1.91.265.0 (2026-10-27): ETHOS.md adds four principles from pstack, and gstack stops asking three questions it can answer by looking. (#3493)
  • 1.91.264.0 (2026-10-27): New /design-motion turns an approved design into a short looping showcase video for X and the website; adapted from Elaya's design-to-motion. (#3430)
  • 1.91.261.0 (2026-10-27): gstack's version renumbering moves a PR's quoted since: rows when its VERSION already matches the base. (#3491)
  • 1.91.260.0 (2026-10-27):
    • /design-review checks a sales or landing page, or a redesign, for craft problems (placeholder people and brands, lorem ipsum, dead links, images without alt text and more) and files each as a finding with its fix. (#3433)
    • /plan-design-review runs the same checks on a plan for a sales or landing page and rejects proof that has no source. (#3433)
  • 1.91.259.0 (2026-10-26): New /ubicloud skill runs heavy tests on Ubicloud VMs, with time-limited VMs that clean themselves up, a quota check before starting and a hang watchdog. (#3482)
  • 1.91.258.0 (2026-10-26): gstack's session check stops failing on warnings, such as being a few versions behind or a Node-only version mismatch, and a repository can set the oldest gstack version it accepts with min_gstack_version. (#3475)
  • 1.91.257.0 (2026-10-26): A remote test run that finished before the version bump now counts for the bumped commit, so a PR no longer pays for a second full test run. (#3486)
  • 1.91.256.0 (2026-10-26): /ship's review loop now settles: later passes review only what changed, a pass can return "no findings", and the review record survives a base merge. (#3481)
  • 1.91.254.0 (2026-10-26): /ship's test check is easier to adopt in other repositories: with no policy file it warns and offers a starter policy instead of failing, a policy can allowlist known-harmless findings, and a missing tool is reported apart from a real test failure. (#3480)
  • 1.91.253.0 (2026-10-26): New /captain skill for running many agents that merge into one main branch without turning it red, with templates and a team guide. (#3473)
  • 1.91.252.0 (2026-10-26): /retro can show whether your team's shipping is getting better (lead time, test cost, failure and flaky rates), and a new guide takes a new team from zero to its first batched merge with gstack and Capy. (#3471)
  • 1.91.251.0 (2026-10-26): A free, deterministic design lint ships with gstack: bin/gstack-design-lint checks a page's HTML, CSS and components for the tells that make it read as machine-made, in under a second, and with --render measures what only a browser can. (#3459)
  • 1.91.248.0 (2026-10-26): The browser ($B) in direct mode no longer picks up a proxy from environment variables. (#3448)
  • 1.91.247.0 (2026-10-26): /plan-eng-review no longer points its reader at three things its own text never defines. (#3421)
  • 1.91.246.0 (2026-10-26): The README is a first-ten-minutes page again: what gstack is, how to install it, the first three skills to try, the skills tables, platform notes, and links to docs/ for everything else. (#3428)
  • 1.91.245.0 (2026-10-26): gstack-ship-queue ready counts CI the way GitHub's checks summary does, and says how to resolve a conflict that is only in the CHANGELOG. (#3460)
  • 1.91.244.0 (2026-10-26): A version-bump-only PR no longer fails /ship's test check for the files it bumps. (#3461)
  • 1.91.243.0 (2026-10-26): On Capy, gstack commands get their launch settings from a private file, and no skill step may print the environment. (#3449)

For gstack contributors

  • 1.91.318.0: /office-hours gets eval tasks, and /write-skill locks its tasks before a paid run. (#3550)
  • 1.91.310.0: The browser-cookies workflow judge asks for structured output, so an unescaped quote can't fail it. (#3581)
  • 1.91.309.0: Two judged eval prompts give one rule each, and a judge that times out says what it was waiting on. (#3544)
  • 1.91.302.0: Three flaky eval cases repaired. (#3553)
  • 1.91.301.0: Four paid eval cases that failed correct runs are fixed. (#3547)
  • 1.91.300.0: Three randomly failing free tests fixed. (#3543)
  • 1.91.299.0: The plan-approval summary explains what the recommended reply does when an approval reuses earlier decisions. (#3549)
  • 1.91.296.0: A docs-sync eval case accepts the agent asking the docs helper for its usage. (#3542)
  • 1.91.286.0: Batched merges respect /ship's size limit across all their PRs, and a batch whose PRs all merged long ago no longer freezes the queue. (#3522)
  • 1.91.285.0: gstack's guide for running many agents on one repository says each agent plans with /autoplan before it builds. (#3521)
  • 1.91.282.0: A batched merge accepted before landing no longer freezes the queue afterward. (#3518)
  • 1.91.281.0: Four paid eval checks stop failing honest runs, and /review's scope check reports in one place. (#3516)
  • 1.91.280.0: Three free tests now measure what they check, and the Ubicloud quota wait no longer eats its own time budget. (#3517)
  • 1.91.279.0: A licence or changelog edit no longer triggers the full paid eval run, and review stops repeating findings already ruled minor. (#3515)
  • 1.91.271.0: The batched-merge bisect can run in CI. (#3509)
  • 1.91.267.0: The guide for coordinating agents lists which questions never need to reach a person. (#3503)
  • 1.91.263.0: Batched merges read test results from the CI run itself, can be followed with one resumable command, and refuse steps that would waste a paid eval run. (#3484)

  • 1.91.255.0: Batched merges start at 3 ready PRs or one hour after the first. (#3478)
  • 1.91.250.0: Three free test fixtures stop racing themselves. (#3474)
  • 1.91.249.0: Five flaky paid eval cases repaired at their causes. (#3472)
