gstack v1.102.1.0

パッチ 公開日2026年11月20日 出典garrytan/gstack English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#gスタックv1.102.1.0 gstack 1.102.1.0 は、スラッシュの後に書かれたシークレットが隠されずに出力されるギャップを埋め、gstack の使用状況レポートをロックダウンして、オプトインするユーザーにとってより便利なものにし、gstack がプロンプトに適切なスキルを選択する方法に関する一連のバグを修正し、クロード コードがスキルをロードするときに gstack スキルの開始ステップを実行するようにして、スキップできないようにします。 使用状況レポート (テレメトリ、オプトイン)

  • 使用状況レポート バックエンドは、独自のチェック済みエンドポイントを介してのみデータを受け入れるようになりました。リポジトリ内の公開キーはテーブルの読み書きができなくなり、サインインした Supabase ユーザーはすべてを拒否されます。 gstack 独自のテスト実行では使用状況データは送信されず、テスト トラフィックは gstack-community-dashboard から除外され、週ごとのアクティブ数は更新チェックではなく実際のインストールをカウントするようになりました。 v0.11.16.0 (2026 年 3 月) より古い gstack バージョンは、テーブルに直接書き込むため、使用状況データの送信を停止します。 (#4537)
  • オプトインすると、各スキル実行で 9 つの新しいフィールドも送信されるようになります。それぞれのフィールドは固定リストから選択されます: どのコーディング エージェントが実行したか、モデル ファミリ、開始したのはあなたかモデルか別のスキルか、終了理由、独自のチェックに合格したかどうか、gstack のルーティング セクションとフックが設定されているかどうか、ランダムなセッション ID、アップグレードの場合は元のバージョンとアップグレードが失敗した理由。 CI と gstack 自身の evals ラベル自体から実行され、gstack が測定できなかった期間は 0 ではなく空で送信されます。オプトインの質問には新しいフィールドがリストされ、匿名モードでは「デバイス ID なし、再利用されることのないエージェント セッションごとのランダムな ID」を送信するようになりました。コード、ファイル パス、プロンプト、またはリポジトリ名を含むフィールドはありません。すべてのフィールドは docs/privacy.md にリストされています。 (#4542) スキルとスキルの提案
  • クロード コードでは、スキルのロード中に各 gstack スキルの開始ステップが実行されるようになったため、モデルはそれをスキップできなくなりました (テスト実行では、モデルはセッションの 45% ～ 62% でのみロードされたスキルの開始ステップに従いました)。読み込みが失敗した場合、スキルはその旨を 1 行で通知し、モデルは以前と同様に開始ステップ自体を実行します。 Codex と他のエージェントは古い指示を保持しています。 (#4509) この開始ステップをチェックする gstack の有料テストは、ロード中に実行されたステップをカウントするようになりました。 (#4543)
  • プロンプトがバグレポートのようになった場合、スキル提案フックはインストールされているバグ修正スキルのみに名前を付け、その前に /verify を提案することはありません。 60 件の実際のバグ修正プロンプトで、46 件のバグ レポートすべてのバグ修正スキルに名前が付けられるようになりました。 (#4539)
  • スキル提案フックはバッククォートとコード ブロック内の単語を無視するようになりました。そのため、「gh pr review 123 を実行する」などの引用符で囲まれたコマンドは /review をトリガーしなくなり、貼り付けられたログ内の --fix フラグによってプロンプトがバグ レポートのように見えなくなりました。これを見つけて最初に修正した @vilano93 に感謝します。 (#4566)
  • gstack は、バックグラウンド ジョブ (gbrain autopilot) または gstack ブラウザ拡張機能をインストールする前に、追加する内容 (削除方法も含む) を 1 行で通知するようになりました。今後のインストール手順でその行が省略された場合、新しいテストは失敗します。 (#4538) 安全・安心
  • 破壊的コマンド チェック (/careful) は、ディスク ワイプおよび強制プッシュ ブロックを回避する方法をさらに増やします。wipefs -a はすべてのターゲットでブロックされ、より多くのスペルでは、そのパスが引用符で囲まれている場合、または /dev へのリンクを経由する場合、ディスクへの書き込みはブロックされ、git push -fn --no-dry-run は実際の強制プッシュとしてカウントされます。以前にブロックされたり質問されたりしたものは、現在は許可されません。 (#4534)
  • /cso は、シンボリック リンクを含むリポジトリを監査できるようになりました。これは、レポート内の各リンクとそのターゲットをリストし、単一のリンク (CLAUDE.md -> AGENTS.md でさえ) が監査を停止する前に、それをたどることはありません。レポートと最初の修正をしてくれた @nathanshox に感謝します。 (#4567)
  • gstack の Secret Hider は、以前は行頭でのみ検出されていたパスワード、API キー、またはスラッシュの後に name=value として記述されたトークン (cfg/api_key=… や https://host/cb/token=… など) も非表示にするようになりました。 /cso の履歴レポートにはそのような値が出力されていました。それと他のすべての場所で、gstack はシークレット (レビュー資料、使用状況データ、/ship ログ) を非表示にしました。 (#4571) /出荷およびコードレビュー
  • リポジトリのストレージがいっぱいであるために GitHub が実行ファイルの保存を拒否した場合でも、緑の CI 実行は /ship およびマージにカウントされます。gstack は、同じチェックの下でジョブのログから同じレコードを読み取ることができるようになりました。 (#4536)
  • /ship は、マシン上でテスト スイート全体を開始するのではなく、停止して、CI の以前のテスト実行を再利用できない場合に何をすべきかを指示するようになりました。 (#4565)
  • 所有者が停止したレビューの結果をオープンノートとして許容できると裁定した場合、それらの裁定により /ship が終了するようになり (#4552)、レビュー記録にはどの結果がまだ裁定を待っているかが示され (#4553)、レビューの結果が別のファイルに保存された場合にも裁定は機能します (#4568)。
  • eval のプランとそのプレーン データ ファイル (事前登録) のみを追加するプル リクエストは、書き込みを目的とした軽量の 1 レビューア レビューを取得するようになり、gstack がレビューのサイズを設定するときにデータ行がコード行としてカウントされなくなりました。 (#4544)
  • /ship の承認レコード内の実行 ID (507-7192673 など) が電話番号と間違われてブロックされることがなくなり、名前が「GStack」で始まるチームは裁定を記録できるようになりました。 (#4549) ブラウザとテスト
  • ブラウザ ヘルパーは、Chrome が開くことを拒否するポート 10080 を選択しなくなり、39,000 回に 1 回の起動で独自のページの読み込みに失敗することがなくなりました。不安定なテストも 1 つ修正されました。 (#4554)
  • gstack の document-sync eval は、/ship がレビュー担当者の結果行を許可された方法で修復するときに失敗しなくなりました。 (#4555)
  • gstack で作業している人向け: gstack の無料テスト実行で失敗し、再試行で合格したすべてのテストが記録されるようになりました。これには、ブランチ上で手動で開始された実行も含まれるため、不安定なテストはカウントされて修正されます。 (#4572)
  • gstack で作業している人向け: テストを分割するジョブが以前のチェックの後ではなく、並行して実行されるようになったため、プル リクエストでのテスト実行が 1 ステップ早く開始されます。 (#4570)

gstack v1.102.1.0

gstack 1.102.1.0 closes a gap where a secret written after a slash could be printed unhidden, locks down gstack's usage reporting and makes it more useful for people who opt in, fixes a set of bugs in how gstack picks the right skill for a prompt, and makes a gstack skill's start step run as Claude Code loads the skill, so it can't be skipped.

Usage reporting (telemetry, opt-in)

  • The usage-reporting backend now accepts data only through its own checked endpoint: the public key in the repo can no longer read or write the tables, and a signed-in Supabase user is denied everything. gstack's own test runs never send usage data, test traffic is left out of gstack-community-dashboard, and its weekly active count now counts real installs instead of update checks. gstack versions older than v0.11.16.0 (March 2026) stop sending usage data, because they wrote straight to the tables. (#4537)
  • If you opt in, each skill run now also sends nine new fields, each a pick from a fixed list: which coding agent ran it, the model family, whether you, the model or another skill started it, why it ended, whether its own checks passed, whether gstack's routing section and hooks are set up, a random session id, and for upgrades the version you came from and why an upgrade failed. Runs from CI and gstack's own evals label themselves, and a duration gstack couldn't measure is sent empty instead of 0. The opt-in question lists the new fields, and anonymous mode now says it sends "no device ID; a random id per agent session that is never reused". No field carries code, file paths, prompts or repo names; every field is listed in docs/privacy.md. (#4542)

Skills and skill suggestions

  • In Claude Code, each gstack skill's start step now runs while the skill loads, so the model can no longer skip it (in test runs, models had followed a loaded skill's start step in only 45% to 62% of sessions). If loading fails, the skill says so in one line and the model runs the start step itself, as before. Codex and other agents keep the old instructions. (#4509) gstack's paid test that checks this start step now counts one that ran during loading. (#4543)
  • When a prompt reads like a bug report, the skill-suggestion hook now names your installed bug-fix skill alone and never suggests /verify ahead of it. On 60 real bug-fix prompts it now names the bug-fix skill on all 46 bug reports. (#4539)
  • The skill-suggestion hook now ignores words inside backticks and code blocks, so a quoted command such as "Run gh pr review 123" no longer triggers /review, and a --fix flag in a pasted log no longer makes a prompt look like a bug report. Thanks to @vilano93, who found and first fixed it. (#4566)
  • gstack now tells you in one line what it's about to add before it installs a background job (gbrain autopilot) or the gstack browser extension, including how to remove it. A new test fails if a future install step leaves that line out. (#4538)

Safety and security

  • The destructive-command check (/careful) closes more ways around its disk-wipe and force-push blocks: wipefs -a is blocked on every target and in more spellings, a write into a disk is blocked when its path is quoted or goes through a link to /dev, and git push -fn --no-dry-run counts as a real force-push. Nothing that was blocked or asked about before is allowed now. (#4534)
  • /cso can now audit repositories that contain symbolic links. It lists each link and its target in the report and never follows it, where before a single link (even CLAUDE.md -> AGENTS.md) stopped the audit. Thanks to @nathanshox for the report and first fix. (#4567)
  • gstack's secret hider now also hides a password, API key or token written as name=value after a slash (such as cfg/api_key=… or https://host/cb/token=…), where before it caught them only at the start of a line. /cso's history report had printed such values; it and every other place gstack hides secrets (review material, usage data, /ship logs) now hide them. (#4571)

/ship and code review

  • A green CI run still counts toward /ship and merging when GitHub refuses to store the run's files because the repository's storage is full: gstack can now read the same record from the job's log, under the same checks. (#4536)
  • /ship now stops and tells you what to do when CI's earlier test run can't be reused, instead of starting the whole test suite on your machine. (#4565)
  • When the owner rules a stopped review's findings acceptable as open notes, those rulings now let /ship finish (#4552), the review record says which findings are still waiting for a ruling (#4553), and rulings also work when the review's findings were saved in a separate file (#4568).
  • A pull request that adds only an eval's plan and its plain data files (a preregistration) now gets the lighter one-reviewer review meant for write-ups, and rows of data no longer count as lines of code when gstack sizes a review. (#4544)
  • Run ids in /ship's approval records, such as 507-7192673, are no longer mistaken for phone numbers and blocked, and a team whose name starts with "GStack" can record rulings. (#4549)

Browser and tests

  • The browser helper no longer picks port 10080, which Chrome refuses to open, so about one start in 39,000 no longer fails to load its own pages; one flaky test was fixed too. (#4554)
  • gstack's documentation-sync eval no longer fails when /ship repairs a reviewer's result line in the allowed way. (#4555)
  • For people working on gstack: every test that failed and then passed on its retry in gstack's free test runs is now recorded, including runs started by hand on a branch, so flaky tests get counted and fixed. (#4572)
  • For people working on gstack: test runs on pull requests start one step sooner, because the job that splits the tests now runs alongside the earlier checks instead of after them. (#4570)
