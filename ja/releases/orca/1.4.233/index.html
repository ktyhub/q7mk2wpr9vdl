orca v1.4.233

パッチ 公開日2026年10月20日 出典stablyai/orca English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#シャチv1.4.233 いつもオルカをご利用いただき、誠にありがとうございます。 ❤️ 本日 2 つのリリースを出荷しました。見逃した方は【v1.4.232 release notes】(https://github.com/stablyai/orca/releases/tag/v1.4.232)もチェックしてみてください。ハイライトには、手動/自動/Yolo エージェントの権限、ネイティブ チャットの OpenCode 2、ファイル添付とインライン スキルを備えた優れた電話コンポーザー、スムーズな SSH リカバリ、高速な Mac アップデートを備えた小型アプリが含まれます。 電話の更新: デスクトップ上の Orca を更新すると、接続されている電話上のアプリも更新されます。電話はアプリをデスクトップから直接ロードします。

ショートバージョン

  • SSH とリモート ワークスペース: SSH ホストへの接続は、どちらのマシンも Node.js をダウンロードできない場合に機能し、1 つの click ミラーを Orca が記憶して再試行します。古い W​​indows ホスト (Windows 10 1809 および Server 2019) は Orca のサーバーを実行でき、ポートが古い SSH 接続によって保持されている場合、トンネルは回復します。
  • [設定] のリモート サーバー: リモート Orca サーバーは 6 つのセクションではなく 1 つのリストであり、SSH ホストは一括で削除し、削除したままにすることができます。 Orca は同じサーバーが 2 回保存されたことを通知し、すでに保存したサーバーを追加すると代わりに更新されます。
  • 電話: 電話からのワークスペースの作成ははるかに速く、ワークスペースのリストはデスクトップと連動し、セッション タブのアイコンは長いタイトルの横にあるサイズを維持します。
  • 編集者: Orca は、ディスク上のファイルに加えられた、まだ見ていない変更を上書き保存することを拒否し、その後のリロードと元に戻すは予想どおりに動作します。
  • 毎日の磨き: 異なるマシン上で同じ名前を持つプロジェクトは短い名前を維持し、どのマシン上にあるのかを示します。長期間保存された会話は、Orca がセッション履歴をスキャンする際に使用するメモリの量がはるかに少なくなります。

製品体験

SSH、管理対象サーバー、リモート

SSH ホストはより多くの状況で接続し、リモート Orca サーバーは 1 つの明確なリストであり、編集は常にワークスペースを所有するマシンに送信されます。

  • どちらのマシンも https://github.com/stablyai/orca/pull/31069 の @nwparker によってノードをダウンロードできない場合、1 つの click Node.js ミラーリング
  • 実行中の接続が同じ方法で失敗したら、保存された Node.js ミラーで再試行します (https://github.com/stablyai/orca/pull/31089 の @nwparker による)
  • Windows 1809 / Server 2019 ホストが https://github.com/stablyai/orca/pull/31056 の @nwparker によってデプロイできるように、node-pty の winpty バックエンドを出荷します
  • 転送を開始できない管理対象トンネルは標準入出力ブリッジを使用し、古い ControlMaster が https://github.com/stablyai/orca/pull/31062 の @nwparker によって保持しているポートを再利用します。
  • 同じソケットで再起動された従来のリレーは、https://github.com/stablyai/orca/pull/31068 の @nwparker によって開いているタブを引き継ぐことはありません
  • https://github.com/stablyai/orca/pull/31077 の @nwparker により、SSH と WSL 全体で Linux ライブラリを確実に検出します
  • リモート Orca サーバー: 6 つのセクションではなく 1 つのリスト。 SSH ホスト: https://github.com/stablyai/orca/pull/31082 の @nwparker によって削除されたままになる一括削除
  • 既に保存したサーバーを追加すると、https://github.com/stablyai/orca/pull/31080 の @nwparker によって 2 回保存されるのではなく、サーバーが更新されます。
  • どの保存済みサーバーが同じマシンを 2 回ペアリングしているかを示し、https://github.com/stablyai/orca/pull/31100 の @nwparker によってそれを修正する方法を教えてください。
  • https://github.com/stablyai/orca/pull/31099 の @nwparker による UI で「管理対象サーバー」の代わりに「Orca on <host>」と言う
  • 移動された SSH ホストは、https://github.com/stablyai/orca/pull/31064 の @nwparker によってプロジェクトの利用可能なホストに一度リストされます。
  • 新しいローカル プロジェクトは、https://github.com/stablyai/orca/pull/31055 の @nwparker によって同じパスの SSH プロジェクトに重複排除されることはありません
  • PR/MR ワークツリー ベースは、https://github.com/stablyai/orca/pull/31054 の @nwparker によって、executionHostId のみで指定された SSH プロジェクトを拒否します
  • ワークツリー作成は、https://github.com/stablyai/orca/pull/31066 の @nwparker によって選択されたホスト --project/--host を送信します
  • エディターの書き込みと非修飾削除は行ごとにルーティングされ、https://github.com/stablyai/orca/pull/31036 の @nwparker によるアクティブ サーバー フォーカスは行われません。
  • アクティブ サーバーのフォーカスを読み取る所有者ルートがないため、https://github.com/stablyai/orca/pull/31058 の @nwparker によってローカル行がフォーカスされたサーバーにルーティングされることはありません
  • 破損したブラウザ ファイル リストにより、ブラウザ client のみが無効になり、https://github.com/stablyai/orca/pull/31025 の @nwparker によるリモート サーバーは無効になりません
  • ライブ orcad のブラウザ ヘルパーは、macOS デスクトップのインストールのために一時停止します (https://github.com/stablyai/orca/pull/31059 の @nwparker による)

電話

電話機からワークスペースをより迅速に作成し、電話機のワークスペース リストとセッション タブを正確に保ちます。

  • https://github.com/stablyai/orca/pull/31167 の @AmoabaKelvin によって新しいワークスペース フォームが開かれている間に、ワークツリーのチェックアウトを準備します。
  • 電話リストは失われたオプションの変更を再送信し、フィードの行ファクトを trust し、https://github.com/stablyai/orca/pull/31088 で @Jinwoo-H によって読み取られた失敗したフィードを再試行します。
  • https://github.com/stablyai/orca/pull/31169 の @AmoabaKelvin による長いタイトルの横にあるセッション タブのアイコンをフルサイズに保つ

ワークスペース、サイドバー、タブ

異なるマシン上の同じ名前のプロジェクトは簡単に区別でき、サイドバーのエージェントのステータスと表示設定は正確なままです。

  • プロジェクト名は短くし、https://github.com/stablyai/orca/pull/28250 の @nwparker によってそのマシンを表示してください。
  • エージェント フェーズ履歴が 1 つあるため、圧縮によって未読が発生せず、タイトル開始ターンによって終了が押し上げられます (https://github.com/stablyai/orca/pull/31103 の @Jinwoo-H)
  • 可視性設定によりワークスペースの行が更新されます。プレギャップのペアサーバーの回答は、https://github.com/stablyai/orca/pull/31106 の @Jinwoo-H によって検証できないままです

エディター、ファイル、マークダウン

保存してもディスク上で行われた変更が上書きされることはなくなり、プレビューと名前変更は適切なファイルに対して機能します。

  • https://github.com/stablyai/orca/pull/30417 の @nwparker による気付かれないディスク変更を上書きする保存を拒否する
  • ディスクチェックされた保存のフォローアップ: 反復可能な古いリロード、Markdown ホワイトスペース、https://github.com/stablyai/orca/pull/31113 の @nwparker によるリロードの取り消し
  • ターミナルで開かれたファイルのマークダウン プレビューは、https://github.com/stablyai/orca/pull/31060 の @nwparker によるソース タブの許可を使用して読み込まれます。
  • 名前変更は、https://github.com/stablyai/orca/pull/31091 の @nwparker による名前変更ホストが自身の所有者である編集者のみを再ターゲットします。

ブラウザ

SSH ホストからのブラウザのスクリーンショットは、取得時と応答時にチェックされます。

  • SSH ホストのキャプチャは、各キャプチャ時と、https://github.com/stablyai/orca/pull/31072 の @nwparker による応答時に許可されます。

パフォーマンスと信頼性

長期間保存された会話は、Orca がインデックスを作成する際にメモリ内で数倍のサイズを必要としなくなりました。

  • [mem] https://github.com/stablyai/orca/pull/30702 の @OrcaWin による保存されたトランスクリプトをストリーミングし、大規模な検索書き込みをステージングします

リレーサービス

ホスト型リレーは、デスクトップを独自のリージョンに保持し、更新中にトラフィックを均等に分散します。

  • https://github.com/stablyai/orca/pull/31042 の @Jinwoo-H により、リージョン修正の再接続とロール再配置にリージョン内リザーブ フォールバックが与えられます。
  • デプロイが 1 つのインスタンスに到達しないように、ディレクタ トラフィックを 2 つのステップで移動します (https://github.com/stablyai/orca/pull/31051 の @Jinwoo-H)
  • https://github.com/stablyai/orca/pull/31067 の @Jinwoo-H により、同じキャップの trust プローブがロード バランサーのウォームアップよりも長持ちするようにします

テスト、CI、メンテナンス

ビルドとチェックがより速く、より軽くなります。新しいレイアウトとサイドバーの作業は、無効になったビルド スイッチの背後に残ります。

  • https://github.com/stablyai/orca/pull/31024 の @Jinwoo-H による有料ランナー プールでのセル フラグとリザーブウォッチの実行
  • https://github.com/stablyai/orca/pull/31031 の @nwparker により、リリース ビルドの同時実行グループから Mac の資格が実行されないようにする
  • Mac と一緒に Windows を構築し、https://github.com/stablyai/orca/pull/31032 の @nwparker による署名割り当てを維持します
  • https://github.com/stablyai/orca/pull/31046 の @nwparker による Bun を使用してエンドツーエンドのタイプチェック メモリをカット
  • https://github.com/stablyai/orca/pull/31043 の @nwparker による Bun 型チェックを使用して CLI コンパイル メモリを半分にします
  • https://github.com/stablyai/orca/pull/31098の@Jinwoo-Hによりクロックに応じてコールド権限スコープテストを停止します
  • 共有スイッチオン器具により、https://github.com/stablyai/orca/pull/31076 の @Jinwoo-H がレイアウトを所有するメインで 71 のレイアウト テストに合格
  • https://github.com/stablyai/orca/pull/31097 の @Jinwoo-H によってパッケージ化が拒否されるテスト専用のスイッチオン サーバー テンプレート
  • https://github.com/stablyai/orca/pull/31045 の @Jinwoo-H による古い保存された端末レコード (ダーク、レイアウト所有者ビルドのみ) からの空の追加端末タブはありません
  • 1 つのステータス バッチからのエージェント タイトルは、https://github.com/stablyai/orca/pull/31048 の @Jinwoo-H による 1 つの名前変更 (ダーク、レイアウト所有者ビルドのみ) としてメインに到達します。

  • 2 つのホスト上の同じ ID のワークスペースは、独自にソート、ネスト、保持されます。ネストされたグループとプロジェクトの順序はホスト セクション (ダーク スイッチ) で保持されます (https://github.com/stablyai/orca/pull/31111 の @Jinwoo-H により)

orca v1.4.233

Thank you so much for using Orca and for your continued support! ❤️

We shipped two releases today! If you missed it, check out the v1.4.232 release notes too. Highlights include Manual / Auto / Yolo agent permissions, OpenCode 2 in native chat, a better phone composer with file attachments and inline skills, smoother SSH recovery, and a smaller app with faster Mac updates.

Phone updates: Updating Orca on your desktop also updates the app on your connected phone—the phone loads it directly from your desktop.

The short version

  • SSH & remote workspaces: Connecting to an SSH host works when neither machine can download Node.js, with a one-click mirror Orca remembers and retries. Older Windows hosts (Windows 10 1809 and Server 2019) can run Orca's server, and tunnels recover when a port is held by an old SSH connection.
  • Remote servers in Settings: Remote Orca Servers is one list instead of six sections, and SSH hosts can be removed in bulk and stay removed. Orca tells you when the same server was saved twice, and adding a server you already saved updates it instead.
  • Phone: Creating a workspace from the phone is much faster, the workspace list stays in step with the desktop, and session tab icons keep their size beside long titles.
  • Editor: Orca refuses to save over changes made to a file on disk that you haven't seen, and Reload and Undo behave predictably afterwards.
  • Everyday polish: Projects with the same name on different machines keep short names and show which machine they're on. Long saved conversations use far less memory when Orca scans them for Session History.
