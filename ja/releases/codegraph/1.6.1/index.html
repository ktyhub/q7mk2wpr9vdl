コードグラフ v1.6.1

[1.6.1] - 2026-09-29

ハイライト

  • codegraph_explore からのより鋭い回答。 これは、非常に大きなファイルや、同じ名前のオーバーライドでいっぱいのファイルからでも、指定した関数とメソッドを返します。クエリ内の行番号を尊重し、回答を完全なものと呼ぶのではなく、いつ短縮したかを示します。
  • アプリのナビゲーションとリクエストがグラフに表示されます。 Expo Router、Next.js、React Router、TanStack Router、Vue Router / Nuxt、SvelteKit ページとそれらの間のリンクはルートと navigates エッジであり、ページの fetch はそれを提供するルートに到達するため、「これはどこに行くのか」と「このエンドポイントを何と呼ぶのか」は codegraph_explore にとって 1 つの質問です。
  • 呼び出しが発生すると Explore が表示します。 codegraph_explore のフロー セクションの各ホップには、JavaScript、TypeScript、Swift、Python、Java、Kotlin、C#、Go、および C の実行条件が伝えられます。
  • 間違ったリンクが減少しました。 TypeScript、JavaScript、Python、Java、Kotlin、Go、Rust、Scala、PHP、および C/C++ での呼び出し、インポート、継承の解決方法に対する多くの修正が行われたため、偶然その名前を共有する無関係なシンボルに呼び出しが到達しなくなります。
  • 信頼できるライブ同期。 MCP サーバーは codegraph index 後に再構築されたインデックスに従い、同期が途中で中断されてもクリーンなインデックスの内容を回復し、シンボリックリンクされたフォルダーは同期を維持し、Windows ドライブ上の WSL プロジェクトは独自のインデックスを取得します。
  • 大規模なリポジトリでの軽量化。 MCP サーバーからの繰り返しの探索でグラフ全体が再スキャンされなくなり、サイズ超過のファイルや .ts ビデオ フィクスチャがインデックス作成中に読み取られたり解析されたりすることがなくなりました。
  • アップグレード: このリリース後にプロジェクトのインデックスを再作成します。インデックス作成中にいくつかの修正と新しいナビゲーション リンクが書き込まれます。

新機能

  • Codex と Astra は、AGENTS.md からプロジェクト ガイダンスを読み取ります。 正規のエージェント ガイドは現在、AGENTS.md にあります (長い検証メモ用にネストされた docs/AGENTS.md があります)。 CLAUDE.md は、Claude Code 用の薄型 @AGENTS.md ラッパーです。 Codex/Ast​​ra は、古い CLAUDE のみの命令を見逃すことがなくなりました。
  • Next.js ページとそのナビゲーションがグラフに表示されます。 App Router ページ (app/(group)/blog/[slug]/page.tsx → /blog/:slug) と Pages Router ページは、エクスポートするコンポーネントにバインドされたルートであり、<Link href>、内部 <a href>、router.push / router.replace (next/navigation および next/router)、redirect() / permanentRedirect()、およびミドルウェアのNextResponse.redirect(…) はそれらの間の navigates エッジです。 app/api/**/route.ts エクスポート (GET、POST など) はその関数にバインドされたエンドポイントであり、pages/api/* ハンドラーは ANY /api/… です。アップグレード後にインデックスを再作成します。
  • TanStack Router のルートとナビゲーションがグラフに表示されます。 ルートは TanStack アプリが宣言する両方の方法で読み取られます。ファイル ベースでは createFileRoute('/posts/$postId') がパス全体を伝え、コード ベースでは各 createRoute({ path, getParentRoute }) がその親を通じて構成されます。また、navigate({ to })、スローされた redirect({ to }) および <Link to> / <Navigate to> は、名前を付けたルートへの navigates エッジです。パスのない _auth レイアウト、(group) フォルダー、および __root はページではなく、計算された宛先は推測されずに除外されます。アップグレード後にインデックスを再作成します。
  • Vue Router、Nuxt、および SvelteKit ナビゲーションがグラフに表示されます。 Vue: ルートは、遅延 component: () => import('@/views/Login') を含む createRouter({ routes: [...] }) から読み取られ、router.push / router.replace / $router.push、Nuxt の navigateTo および <router-link> / <RouterLink> / <NuxtLink> は navigates エッジであり、次のように解決されます。ルート名とパスによる。 SvelteKit: ロードまたはフォーム アクションからの goto('/login')、redirect(303, …)、およびプレーン <a href> は navigates エッジであり、ページは、それを提供するページ ファイルとその隣の +page.server.js に結合されます。計算された宛先または何も宣言されていないパスは、推測されるのではなく除外されます。アップグレード後にインデックスを再作成します。
  • React Router ナビゲーションがグラフに表示されます。 history.push / history.replace、useNavigate の navigate(…)、ローダーまたはアクションの redirect()、および <Link to> / <NavLink to> / <Navigate to> / React-router-bootstrap の <LinkContainer to> は、開いたルートへの navigates エッジになり、オプションのルートになりますパラメーター (/cart/:id?) は、/cart と /cart/5 の両方によって到達されます。計算された目的地やルートが提供しない経路は推測されるのではなく除外され、配列上の通常の paths.push('/x') がナビゲーションと間違われることはありません。アップグレード後にインデックスを再作成します。
  • codegraph_explore は、その層全体で Web アプリに従います。 ページの fetch('/api/users', { method: 'POST' }) (または axios / ky / got / $fetch 呼び出し (axios.create({ baseURL }) インスタンス経由の呼び出しを含む)) は、同じインデックスでサービスを提供するルートに到達するようになりました。 BullMQ / Bull キューに置かれたジョブは、@Process メソッド、それを消費する Worker または queue.process ハンドラー、NestJS EventEmitter2 イベントの @OnEvent リスナー、ゲートウェイの @SubscribeMessage ハンドラーと戻ってくるソケット メッセージ、および client ファイルから呼び出される Next.js サーバー アクションに到達します。それぞれは、フロー セクションで接続された場所とともに名前が付けられる合成ホップです。リテラルのパスまたはイベント名のペアのみ。インデックスを再作成して新しいエッジを選択します。
  • codegraph_explore は、各呼び出しがいつ発生するかを示します。 フロー セクションのすべてのホップには、その呼び出しサイトが置かれている条件 (↓ calls (when isCollected)) が伝えられます。これは、呼び出し前後の if / else、switch / when / match、3 進、try および && / and 分岐から読み取られ、その前の早期リターンも含まれます。 (if (busy) return は !busy と読み取られ、Go の if err != nil { return } は err == nil と読み取られます)。 JavaScript、TypeScript、Swift、Python、Java、Kotlin、C#、Go、C で動作し、ソースからそのまま読み取られます。ルールのない言語は推測するだけで何も言いません。
  • React Native アプリ: Swift ネイティブ モジュールとそのイベントはエンドツーエンドで接続されます。 captureView.finalizeCaptureSession() のような JS 呼び出し (captureView が NativeModules.CaptureView にバインドされ、モジュールが RCT_EXTERN_MODULE shim を通じて公開される Swift クラスである) は、定数で停止するのではなく Swift メソッド自体に解決されるため、codegraph_explore はコードをネイティブにたどります。ネイティブ → JS イベントは、インラインで記述されたリスナー (ZZPH100​​ZZ) にも到達するようになり、リスナーを登録するコンポーネントに起因します。アップグレード後にインデックスを再作成して、新しいエッジを選択します。
  • Expo Router アプリ: 画面とナビゲーションがグラフ内に表示されます。 app/ (または src/app/) の下のすべての画面ファイルは、パス (/object-detail、/item/[id]、(group) フォルダーが取り除かれたもの) で名付けられたルート ノードになり、レンダリングされるコンポーネントにリンクされます。 router.push('/object-detail?…')、router.navigate({ pathname: '/item/[id]', params })、テンプレートリテラル hrefs、ローカルの const、ヘルパーが画面パス (返すことができる画面ごとに 1 つのエッジ) を返す router.push(await pickRoute()) などの呼び出しは、href を記憶する新しい navigates エッジとして開く画面に解決されるため、「タップした場所はどこに行くのか」と「この画面を誰が開くのか」は codegraph_explore の 1 ホップです。文字列での行き止まりの代わりに callers。アップグレード後にインデックスを再作成して、新しいエッジを選択します。

修正

  • クロード コードのプロンプト フックは、バックグラウンド エージェントの終了時にクロード コードが挿入するタスク通知メッセージで実行されなくなり、そのようなターンごとに数秒かかる停止が解消されました。 (#1832)
  • self の Rust 呼び出しは、無関係な型の同じ名前のメソッドにリンクするのではなく、囲んでいる型に留まるようになりました。ありがとう@L4XB。 (#1861)
  • テレメトリをオフにすると、その ID がリセットされ、実行中のプロセスによる未送信データの記録、送信、復元が停止されるようになりました。 (#1869)
  • JavaScript、JSX、および TypeScript ファイル間の呼び出しでは、呼び出し元とコールバック フローが維持されます。
  • Zustand アクションは、型付きストアを読み取ったとき、ストア状態から構造化されていないとき、またはフックによって選択されたときに、呼び出し元を保持します。
  • Direct React Native ブリッジ呼び出しは、ネイティブ実装とクロスプラットフォーム関係を保持します。
  • WebAssembly パーサーを使用する場合、Dart 拡張タイプのゲッターは引き続き検索可能です。
  • 待機値に対して組み込みメソッドを呼び出しても、たまたま同じ名前のメソッドを宣言する無関係なクラスへの呼び出しは記録されなくなり、待機呼び出しにバインドされた変数は呼び出しが返す型でメソッドを解決するようになりました。ありがとう@maxmilian。 (#1840)
  • Spring マッピングには、宣言されたすべてのパスの組み合わせが含まれ、同じファイルで宣言された定数が解決されるようになりましたが、未解決のパスは偽のルート ルートとして表示されなくなりました。 (#1461)
  • codegraph node は、ファイルがインデックス付けされていないと報告するのではなく、行番号 (src/app.ts:42、src/app.ts:42-80、src/app.ts#L42、src/app.ts#L42-L80) を持つファイル参照を受け入れるようになりました。行範囲が読み取られるウィンドウとなり、自分自身で渡した --offset/--limit が引き続き勝ちます。実際にそのように名前が付けられたパスは、書かれたとおりに検索されます。 (#1831)
  • codegraph callers、codegraph callees、および codegraph impact は、定義により修飾名を解決し、結果と JSON エッジをグループ化し、曖昧な名前を絞り込むために --file を受け入れるようになりました。ありがとう@ferrine。 (#1512、#1656)
  • codegraph callers、codegraph callees、および codegraph impact (CLI および MCP) は、別のシンボルの結果ではなく、もしかしてという提案とともに欠落している名前を報告するようになり、呼び出し元のない完全一致は空のままになります。ありがとう@uvmplus。 (#1473、#1481)
  • codegraph_explore が大きなファイルをトリミングするとき、ソース内のギャップは、ファイルの予算が残っているスペースのみを使用して、取り残されたシンボルに名前を付けるようになりました。そのため、名前がコード自体を押し出すことはありません。 (#1711)
  • codegraph_explore は、メソッドを宣言していない基本クラスを通じて「ランタイム ディスパッチ」を報告しなくなりました。そのため、無関係な多くのサブクラスで共有される共通名によって、数千の実装のリストが表示されることはなくなりました。
  • 1 つのファイル内で複数の関数に名前を付け、無関係なコードがそれらの間にある場合、codegraph_explore は、そのコードにファイルのスペースを費やしたり、要求された関数の 1 つをまったくソースなしのままにする代わりに、その周囲のコードの前に名前を付けた関数を返すようになりました。
  • codegraph_explore は、同じ名前のオーバーライドが含まれるファイル内であっても、SQLCompiler.as_sql など、名前を付けたメソッドの本体をそのクラスとともに返すようになりました。以前は、要求したメソッドを署名行まで縮小していましたが、その周囲の小さなメソッドは完全に戻ってきました。答えを得るには長すぎるメソッドは、その冒頭の行と、指定した他のシンボルを呼び出す場所が、残りを返す正確なフォローアップ クエリとともに返されるようになりました。
  • codegraph_explore はクエリ内の行番号を考慮するようになりました。compiler.py:776 はその行を含むメソッドを返し、compiler.py lines 900-1003 (または :900-1003、#L900-L1003、L900-L1003) は正確にそれらの行を返します。以前はファイルを固定し、番号を無視していました。
  • codegraph_explore クエリ内のファイル名が複数のフォルダー内のファイルと一致する場合、クエリでも名前が指定されている関数またはクラスを定義するファイルのみが固定され、概要行には除外されたファイルがリストされます。以前はすべての一致が固定されていたため、名前を省略した場合に得られるスペースの半分が、意図したファイルに割り当てられていました。 models.py など、多くのファイルで共有される名前は、あいまいなものとして報告されるのではなく、同じ方法で解決されるようになりました。

MCP / インデックス作成

  • Windows では、共有 MCP デーモンは、別のプログラム (ウイルス対策スキャン、インデクサー、またはロック ファイルを読み取っている別のセッション) がそのファイルを解放するのをより長く待機するようになりました。そのため、共有 MCP デーモンは、セッションを離れる代わりに起動して、より遅いインプロセス サーバーにフォールバックします。 (#1773)
  • サイズ制限を超えたファイルはスキップされるまで読み取られなくなりました。コミットされた大規模なビデオと BLOB フィクスチャは、インデックス作成パスごとに 1 回、完全にメモリにロードされ、破棄されるだけでした。インデックス作成と変更検出は、代わりにファイルのサイズによって行われるようになりました。ありがとう@danusha2345。 (#1910)
  • 偶然 .ts という名前の MPEG トランスポート ストリーム ビデオ (testdata/、e2e clips の下のゴールデン フィクスチャ) は、シンボルなしの各 clip に長い時間を費やす TypeScript パーサーに供給されるのではなく、最初のバイトから認識され、スキップされるようになりました。実際の TypeScript ファイルには引き続きインデックスが付けられます。ありがとう@danusha2345。 (#1910)
  • 実行中の MCP サーバーから codegraph_explore 呼び出しを繰り返しても、プロジェクトのコア ファイルを見つけるために毎回グラフ全体を再ランク付けすることがなくなりました。回答はインデックスが変更されるまで再利用されます。ありがとう@danusha2345。 (#1864)
  • ファイル監視では、同期が失敗したときに削除されたディレクトリに要求される完全な再スキャンが削除されなくなりました。そのため、削除されたファイルは残らずインデックスに残ります。 (#1964)
  • MCP サーバーの実行中に codegraph index を実行すると、古い置き換えられたインデックスへのライブ自動同期書き込みが残されなくなりました。サーバーは次の更新の前に再構築されたインデックスに切り替わり、他の方法では見逃していたすべてのものを追いつきます。ありがとう@danusha2345。 (#1902)
  • デーモンの起動とクリーンアップは、ライブのレガシー PID のみのロックを保持しながら、死んだレコードや ID が証明されなかったレコードを再利用するようになり、2 人のライターが同じプロジェクトを提供するのを防ぎます。
  • (中断された codegraph init または決して設定されなかった ~/.codegraph/ によって) 親ディレクトリに残された空またはテーブルのない codegraph.db は、初期化されたプロジェクトとしてカウントされなくなりました。そのため、その下にあるすべてのプロジェクトの実際のインデックスを隠すことができなくなりました。コードグラフ スキーマを実際に保持するデータベースのみが初期化済みとして扱われ、壊れたファイルのあるディレクトリ内の codegraph init は、「すでに初期化済み」で拒否するのではなく、修復するようになりました。ありがとう@danusha2345。 (#1895)
  • 増分同期により、エッジの再バインドがクラッシュ セーフに保たれるようになりました。解決されたエッジをその回復参照で置き換えると、アトミックにコミットされるため、中断によって関係が永久に削除されることはありません。
  • ステータスは、すべてのソース ファイルをスキャンすることなく、コミットされたがインデックスされていない変更と復元された編集を検出するようになりました。ありがとう@inth3shadows。 (#1829)
  • プロンプト フックは、ホーム ディレクトリまたは野良ワークスペース マニフェストを含むより広範なディレクトリから実行した場合に、無関係なプロジェクトを挿入しなくなりました。 (#1454)
  • codegraph_explore は、インデックスが保持しない拡張子のないファイルをクエリで指定した場合に、その旨を表示するようになりました。 scripts/deploy のようなパスは、最後のセグメントに拡張子がないため、スパンが疑いの余地のないパスであると判断する形状テストに失敗しました。名前はクエリに残され、scripts と deploy に細断され、名前を付けたファイルが決して参照されていないというヒントのない、無関係なソースの山として答えが返されました。このようなスパンは、プロジェクト ディレクトリに対してチェックされるようになりました。それが実際のファイルの場合、回答には、スペルミスのある src/foo.ts がすでに取得したものと同じ No indexed file uniquely matches ... メモが含まれます。スラッシュ散文 — and/or、input/output、gen_server:call/2 — には背後にファイルがなく、クエリ内にそのまま残されています。 (#1830)

ルートとフレームワークの検出

  • SvelteKit レイアウトは、ページのアドレスの 2 番目のルートではなくなりました。 +layout.svelte と +error.svelte は、隣の +page.svelte と同じパスにあり、それぞれルートとしてインデックス付けされていたため、1 つのアドレスがインデックスに 2 回、3 回出現しました。現在はページのみがルートです。
  • サブフォルダーにパッケージが存在するフレームワークが再び検出されました。 依存関係を 1 レベル下 (frontend/ と backend/、または apps/web/) に保持するプロジェクトでは、ファイルのインデックスが作成される前にフレームワーク チェックが 1 回実行され、調べるフォルダーが見つからず、残りの実行でその空の答えが記憶されていました。 React、React Router、Next.js のすべての動作は、フレームワークが存在するかどうかを認識していることに依存しており、これらのプロジェクトには何も影響しません。
  • app.use('/api', router) の背後にあるエクスプレス ルートは、リクエストが通過するパスによって名前が付けられます。 インポートまたは require によって、アプリのネストと同じ数の router.use('/users', usersRouter) レベルを介してプレフィックスにマウントされたルーターは、そのルートに POST / ではなく POST /api/users という名前を付けるようになり、連鎖形式 router.route('/:id').get(getProduct).put(protect, updateProduct) (行にまたがるかどうかにかかわらず) はメソッドごとに 1 つのルートを登録します。 client のリクエストは、その実際のパスによってそのルートとペアになります。
  • ラッパーを通じて記述された Express ハンドラーは、エンドポイントのハンドラーです。 const authUser = asyncHandler(async (req, res) => { … }) (express-async-handler イディオム) は、そのルートがバインドされているハンドラーになりました。
  • ワークスペースの package.json で宣言されたフレームワークが検出されます。 React、Next.js、Expo Router、Express、および NestJS は、依存関係がリポジトリ ルートではなく frontend/、backend/、apps/web/、または packages/api/ に存在する場合に検出されます。そのため、モノリポジトリのページとエンドポイントはインデックスに存在します。

codegraph v1.6.1

[1.6.1] - 2026-09-29

Highlights

  • Sharper answers from codegraph_explore. It returns the functions and methods you name — even from a very large file, or one full of same-named overrides — honours line numbers in a query, and says when it shortened an answer instead of calling it complete.
  • Your app's navigation and requests are in the graph. Expo Router, Next.js, React Router, TanStack Router, Vue Router / Nuxt and SvelteKit pages and the links between them are routes and navigates edges, and a page's fetch reaches the route that serves it, so "where does this go" and "what calls this endpoint" are one question to codegraph_explore.
  • Explore says when a call happens. Each hop in codegraph_explore's Flow section carries the condition it runs under, for JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go and C.
  • Fewer wrong links. Many fixes to how calls, imports and inheritance resolve in TypeScript, JavaScript, Python, Java, Kotlin, Go, Rust, Scala, PHP and C/C++, so a call stops landing on an unrelated symbol that happens to share its name.
  • Live sync you can rely on. The MCP server follows a rebuilt index after codegraph index, a sync interrupted halfway recovers what a clean index would have, symlinked folders stay in sync, and a WSL project on a Windows drive gets an index of its own.
  • Lighter on big repositories. Repeated explores from the MCP server no longer rescan the whole graph, and oversize files and .ts video fixtures are no longer read or parsed while indexing.
  • Upgrading: re-index your projects after this release — several fixes and the new navigation links are written while indexing.

New Features

  • Codex and Astra read project guidance from AGENTS.md. The canonical agent guide now lives in AGENTS.md (with a nested docs/AGENTS.md for long validation notes); CLAUDE.md is a thin @AGENTS.md wrapper for Claude Code. Codex/Astra no longer miss the old CLAUDE-only instructions.

  • Next.js pages and their navigation are in the graph. App Router pages (app/(group)/blog/[slug]/page.tsx → /blog/:slug) and Pages Router pages are routes bound to the component they export, and <Link href>, an internal <a href>, router.push / router.replace (next/navigation and next/router), redirect() / permanentRedirect() and the middleware's NextResponse.redirect(…) are navigates edges between them. app/api/**/route.ts exports (GET, POST, …) are endpoints bound to their functions, and pages/api/* handlers are ANY /api/…. Re-index after upgrading.

  • TanStack Router routes and navigation are in the graph. Routes are read both ways a TanStack app declares them — file-based, where createFileRoute('/posts/$postId') carries the whole path, and code-based, where each createRoute({ path, getParentRoute }) is composed through its parent — and navigate({ to }), a thrown redirect({ to }) and <Link to> / <Navigate to> are navigates edges to the route they name. A pathless _auth layout, a (group) folder and __root are not pages, and a computed destination is left out rather than guessed. Re-index after upgrading.

  • Vue Router, Nuxt and SvelteKit navigation is in the graph. Vue: routes are read from createRouter({ routes: [...] }), including a lazy component: () => import('@/views/Login'), and router.push / router.replace / $router.push, Nuxt's navigateTo and <router-link> / <RouterLink> / <NuxtLink> are navigates edges, resolved by route name as well as by path. SvelteKit: goto('/login'), redirect(303, …) from a load or a form action, and a plain <a href> are navigates edges, and a page is joined to the page file that serves it and the +page.server.js beside it. A computed destination or a path nothing declares is left out rather than guessed. Re-index after upgrading.

  • React Router navigation is in the graph. history.push / history.replace, navigate(…) from useNavigate, redirect() in a loader or an action, and <Link to> / <NavLink to> / <Navigate to> / react-router-bootstrap's <LinkContainer to> are now navigates edges to the route they open, and a route with an optional parameter (/cart/:id?) is reached by both /cart and /cart/5. A computed destination or a path no route serves is left out rather than guessed, and an ordinary paths.push('/x') on an array is never mistaken for navigation. Re-index after upgrading.

  • codegraph_explore follows a web app across its tiers. A page's fetch('/api/users', { method: 'POST' }) — or an axios / ky / got / $fetch call, including one through an axios.create({ baseURL }) instance — now reaches the route that serves it in the same index. A job put on a BullMQ / Bull queue reaches the @Process method, Worker or queue.process handler that consumes it, a NestJS EventEmitter2 event its @OnEvent listeners, a socket message the gateway's @SubscribeMessage handler and back, and a Next.js server action called from a client file is a crossing to the server. Each is a synthesized hop that the Flow section names, with where it was wired up. Only a literal path or event name pairs. Re-index to pick the new edges up.

  • codegraph_explore says when each call happens. Every hop in the Flow section carries the condition its call site sits under — ↓ calls (when isCollected) — read from the if / else, switch / when / match, ternary, try and && / and branches around the call and the early returns before it (if (busy) return reads as !busy, Go's if err != nil { return } as err == nil). It works for JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go and C, is read from the source as it stands, and a language without rules says nothing rather than guess.

  • React Native apps: Swift native modules and their events connect end to end. A JS call like captureView.finalizeCaptureSession() — where captureView is bound to NativeModules.CaptureView and the module is a Swift class exposed through an RCT_EXTERN_MODULE shim — now resolves to the Swift method itself instead of stopping at the constant, so codegraph_explore follows the code into native. Native → JS events now also land on listeners written inline (addListener('onZipComplete', (data) => { … })), attributed to the component that registers them. Re-index after upgrading to pick the new edges up.

  • Expo Router apps: screens and navigation are in the graph. Every screen file under app/ (or src/app/) is now a route node named by its path — /object-detail, /item/[id], with (group) folders stripped — linked to the component it renders. Calls like router.push('/object-detail?…'), router.navigate({ pathname: '/item/[id]', params }), template-literal hrefs, an href held in a local const, and router.push(await pickRoute()) where the helper returns screen paths (one edge per screen it can return) resolve to the screen they open as a new navigates edge that remembers the href, so "where does tapping this go" and "who opens this screen" are one hop in codegraph_explore and callers instead of a dead end at a string. Re-index after upgrading to pick the new edges up.

Thanks @bompus and @inth3shadows for the reports and @danusha2345. (#1963, #1356)

Links and navigation

  • A <Card/> is the Card that file imports, not the first one in the repo. When two components share a name — Section, Picker, FrameCard, one per feature folder — the render link out of a component picked whichever happened to be indexed first, ignoring what the file actually declares or imports, so a component gained a link to something it never renders and callers and impact dead-ended at the one it does. It now follows the file's own declaration or import, and a JavaScript tag prefers a JavaScript component over a same-named class in a mobile app's native half. Re-index after upgrading.

  • A navigation that goes to one of several places now links to all of them. A destination written as a choice — a paginator's !isAdmin ? keyword ? \/search/${keyword}/page/${x}` : `/page/${x}` : `/admin/productlist/${x}`, redirect(307, user ? `/profile/@${user.username}` : '/login')in a loader,router.push(cond ? '/a' : '/b')— used to produce no edge at all, because one edge carried one destination and picking an arm would have been a guess. Every arm is now its ownnavigates` edge to the route it names; arms that name the same route still make one.

  • A conditional inside a conditional no longer reads the wrong arm. A paginator written !isAdmin ? keyword ? '/search/…' : '/page/…' : '/admin/…' was split at the first : rather than the matching one, so an admin's page links pointed at the storefront's pagination. The arms are paired properly now, and a three-way choice — which is more destinations than one link can name — is left alone.

  • In a repository with several apps, a link no longer points into a different one. Every app has a / and most have a /login, and the route table was built for the whole repository at once, so whichever app was indexed first claimed each address — a <Link to="/posts"> in one app resolved to another app's /posts. Measured on a monorepo of 477 apps: 82% of navigations pointed at a route belonging to a different app, and all of them now point within their own.

  • A client call with a type argument — useSWR<Team>('/api/team', fetcher), ky.get<User>('/api/users/1') — now reaches its route like the untyped form.

Routes and framework detection

  • A SvelteKit layout is no longer a second route at a page's address. +layout.svelte and +error.svelte sit at the same path as the +page.svelte beside them and were each indexed as a route, so one address appeared in the index two and three times over. Only a page is a route now.

  • A framework whose package lives in a subfolder is detected again. In a project that keeps its dependencies one level down — a frontend/ and a backend/, or an apps/web/ — the framework check ran once before any file had been indexed, found no folders to look in, and remembered that empty answer for the rest of the run. Every React, React Router and Next.js behaviour that depends on knowing the framework is there silently did nothing for those projects.

  • Express routes behind app.use('/api', router) are named by the path a request takes. A router mounted at a prefix — through as many router.use('/users', usersRouter) levels as the app nests, by import or require — now names its routes POST /api/users instead of POST /, and the chained form router.route('/:id').get(getProduct).put(protect, updateProduct) (split across lines or not) registers one route per method. A client's request is paired with its route by that real path too.

  • An Express handler written through a wrapper is the endpoint's handler. const authUser = asyncHandler(async (req, res) => { … }) — the express-async-handler idiom — is now the handler its route is bound to.

  • A framework declared in a workspace's package.json is detected. React, Next.js, Expo Router, Express and NestJS are found when their dependency lives in frontend/, backend/, apps/web/ or packages/api/ rather than at the repository root, so a monorepo's pages and endpoints exist in the index.

  • FastAPI routes are named by the path a request takes. APIRouter(prefix="/items") and a literal app.include_router(router, prefix="/api/v1") — nested through an aggregate router, through a module import or an alias — now compose onto the route names (GET /api/v1/items/{id} instead of GET /{id}); a prefix that is a setting rather than a string leaves that mount alone rather than guessing.

  • ASP.NET Minimal API endpoint groups are routes. The handler-first form — groupBuilder.MapPost(CreateTodoItem), MapPut(UpdateTodoItem, "{id}") inside an IEndpointGroup / EndpointGroupBase class (the Clean Architecture template and its descendants) — now registers POST /api/TodoItems and PUT /api/TodoItems/{id}, with the /api/ head read from the app's own MapGroup($"/api/{groupName}") and a class's RoutePrefix honoured, each bound to its handler.

  • A FastAPI service that lives in one directory of a monorepo is detected. backend/pyproject.toml and backend/app/main.py count, not only files at the repository root, so the official full-stack template's routes are indexed.

  • React Router routes are now read from each <Route> tag's own attributes and each route object's own fields, so an element no longer bleeds into a sibling or parent route. Thanks @inth3shadows. (#1348)

  • MyBatis mappers with whitespace inside a closing tag, and <include refid> references to another namespace, are now extracted correctly. Thanks @ESPINS for the report and @fengshao1227. (#1209)

  • render, include, section and assign written inside a {% liquid %} block are now extracted with their real line numbers, and commented or raw content is ignored. Thanks @Puma7. (#1906)

  • Rust functions annotated #[tauri::command] are no longer reported as dead code. Thanks @vdavid. (#1543)

Symbols and tests

  • Kotlin functions and methods now carry their signature — (params): ReturnType — in codegraph_explore and node, instead of no signature at all. Re-index Kotlin projects after upgrading. (#1495)

  • TypeScript/JavaScript value aliases — export const alias = fn, export { fn as alias }, object-literal api = { run: fn }, and same-file const local = fn — now forward calls edges to the aliased function, so callers and impact on the implementation include consumers that call through the alias instead of stopping at the binding. Genuine wrappers (() => fn()) are unchanged. Re-index after upgrading. Thanks @valkyriweb. (#1482, #1485)

  • codegraph affected now finds Go, Python and JVM test files that previously went unreported, while preserving custom --filter behavior (thanks @danusha2345; #1507, #1688).

  • Calls inside declaration initializers in Kotlin, Java, TypeScript, JavaScript, Scala, Rust and Python now appear under the declaration that owns them, making callers and impact results more accurate after re-indexing with codegraph index -f (thanks @danusha2345; #1510, #1511).

  • Java fields initialized with anonymous classes now expose their methods and calls in the graph.

  • Kotlin property accessors, initialization blocks and destructuring declarations now retain their calls with the correct owner.

  • codegraph_explore again lists a dynamic-dispatch link when the same two symbols are also joined by an ordinary call.

  • Rust unit structs (struct Unit;) and their trait implementation relationships now appear in the graph after re-indexing. (#1513, #1514)

  • Imports from Node built-ins or npm packages no longer connect to unrelated type members with matching names; re-index after upgrading to clear existing false dependencies. Thanks @ctype-lab. (#1537)

  • Inheritance relationships no longer attach external Rust or npm supertypes to unrelated local symbols with the same name, including in Svelte, Vue and Astro components; re-index after upgrading to clear existing false relationships. A TypeScript class implementing a service that is declared as both a value and an interface under one name, the pattern VS Code uses for every service, now links to the interface instead of the value. Thanks @ctype-lab. (#1536)

  • Spring's dependency-injection resolution patterns no longer capture inheritance references or references from other languages. In a polyglot repository where Spring is detected (a sibling Java module is enough), a Scala or Kotlin extends/implements reference could be resolved by Spring's directory-convention heuristics to an unrelated same-named class — for example a test fixture — corrupting the inheritance graph that codegraph_impact and codegraph_explore walk. Inheritance now always resolves through imports and name matching, and the Spring DI patterns only apply to Java/Kotlin references. Re-index after upgrading. (#1825)

  • PHP static calls through imported class aliases now reach the correct class when services and repositories share method names, so callers and impact analysis show the right dependencies after re-indexing. (#1545)

  • TypeScript/JavaScript: a call through a field of the enclosing class — this.mailer.send() — now resolves on the field's declared type, so a delegating wrapper that shares the method's name no longer records itself as its own callee and callers, impact and trace stop lying on that shape. A field whose type is external or a builtin stays unresolved rather than guessed. Re-index after upgrading. (#1496)

  • TypeScript and JavaScript collection calls through local variables and their nested properties no longer link to unrelated project methods; re-index after upgrading. (#1566)

  • Objective-C headers now index in a project that has no .m file. A .h file is read as C from its name alone, and only later — once its contents are read — recognized as Objective-C; the grammar for that was never loaded up front, so the file failed with a parser error and nothing in it reached the index. Adding any .m file used to make the same header work, which is what made this look arbitrary. Thanks @Juddd. (#1628)

  • TypeScript interface methods and properties are now indexed, so node, callers and impact can find platform .d.ts APIs while declaration-only files keep their lower ranking on flow queries, and an interface's members don't pull unrelated files into answers to plain-English questions; re-index TypeScript projects after upgrading. (#1638)

  • Lua and Luau function expressions assigned to locals, table members, or keyed table fields are now indexed as callable nodes. Calls from local f = function() ... end, M.f = function() ... end, and callback tables such as M.handlers = { onClick = function() ... end } are attributed to the named function or method instead of collapsing onto the file node, so callers and impact no longer omit these handlers. Re-index after upgrading. (#1616, #1650)

  • Functions bound with const inside another function are symbols now. const handleClear = () => {…} inside a React component — every handler that skips useCallback — was invisible to callers, callees and impact, answering "Symbol not found" exactly the way a function with no callers would. It is indexed like its module-level twin, contained by the enclosing function, with its own calls. Re-index after upgrading. (#1669)

  • codegraph callers, callees, and query now clearly report when their result limit hides additional matches, including exact totals in callers/callees JSON output; the codegraph_callers and codegraph_callees MCP answers carry the same "showing N of M" note. (#1639, #1674)

  • CommonJS controllers written as exports.getItems = async (req, res) => {…} or module.exports.x = function () {…} are now indexed as exported functions, so node, callers and impact find every Express handler in that style and the calls inside them belong to the handler instead of the file. Re-index JavaScript projects after upgrading. (#1675)

  • Python parameters annotated with a quoted forward reference — def f(o: "Alpha"), or anything under from __future__ import annotations — now resolve the methods called on them, the same as the unquoted annotation. Re-index Python projects after upgrading. (#1684)

  • A C macro call written with designated initializers no longer swallows every function after it. Betaflight resets each config struct with RESET_CONFIG(type, dst, .field = value, …), a shape the C grammar cannot parse; past a hundred or so fields its error recovery ran the enclosing function to the end of the file, the next function vanished from the index and every later one was filed under the first, where name matching then treated it as an unreachable closure. The argument list of such a call is now blanked before parsing, offsets kept, so the file's functions come out with their real extents. On that tree 45 functions in pid.c alone moved back to top level and their 117 callers resolve at exact-match confidence. Re-index after upgrading. (#1729)

  • A method called on the result of another call — d.setdefault(k, []).append(v), make().run() — no longer produces a call edge to an unrelated top-level function that merely shares the name, in Python and JavaScript/TypeScript. The receiver is kept so the inner call still resolves; the outer method stays unresolved rather than guessed. Re-index after upgrading. (#1683, #1681)

  • A Python call through an imported project module whose name collides with a builtin collection method — ledger.append(row) after from . import ledger — is no longer dropped as list.append. The builtin-method filter now lets the receiver through when it is an imported module that resolves to a file in the project, so resolveViaImport can attach the real edge; a stdlib/PyPI receiver (os.remove) still produces none. Re-index after upgrading. (#1681, via #1704)

  • Python method calls on module-scope builtin collections no longer create false calls or file dependencies to unrelated project methods with the same name; re-index after upgrading. (#1652)

  • A definition its language makes file-local no longer captures calls from other files. A C static in another source file (.c/.cc/… — not a header's static inline, which is textually included), a Kotlin/Java/C#/Swift/Scala/Dart/PHP private member, a Go unexported name in another package, and a Rust non-pub item outside its module subtree cannot be what a name in another file means, but name matching accepted them whenever the names agreed: an Android editor.apply() onto an unrelated class's private fun apply, a JavaScript fail(...) onto a Go func fail, a Rust .count() onto a private fn count in another crate, and C USB helpers onto a static in a .c they never link. Such a target is now declined after the whole name-matching pipeline settles — the reference stays unresolved rather than falling through to a fuzzy namesake. Same-file definitions, a child Rust module reaching its ancestors' private items, and Rust impl Trait for Type methods stay resolvable. Re-index after upgrading. (#1730, #1731)

  • A binding in a module that exports nothing is no longer a cross-file target. On vite, every import { defineConfig } from 'vite' across the playground resolved onto a const vite = await createServer(…) sitting at module scope in playground/ssr-html/test-stacktrace.js — a file with an import and no export, so that binding is reachable from nowhere but itself. Name matching commits as soon as one candidate survives, and nothing asked whether an import could reach the survivor; that one binding took 157 edges. A JS/TS file holding an import and no export of any kind now offers its locals to no other file. Classic scripts, CommonJS (including exports["x"] = …), a later export { … }, and names contributed through declare global are all unaffected. Across vite this removed 320 wrong edges and added 18, each addition a reference that was previously ambiguous rather than newly invented. Re-index after upgrading. (#1719)

  • A bare call inside a JavaScript or TypeScript method no longer resolves to the method itself. When a method and a module-scope function share a name, serialize(this.raw) written inside Record.serialize means the function, but the nearest same-named definition won the tie and the graph recorded the method calling itself. A call written without a receiver can never reach a method in JS/TS, so methods are no longer candidates for it; this.serialize() and other.serialize() resolve as before. (#1714)

  • Fuzzy matching no longer lands on a closure it cannot reach. A function nested inside another function is only callable from inside its container, and exact-name matching already declined such candidates; the fuzzy fallback did not, so a builtin method call (res.text(), items.push()) whose only same-named project symbol was some file's closure resolved onto that closure. The fallback now checks that the one candidate it would commit to is reachable, and declines otherwise — it does not filter the candidate list first, which would turn a crowd of same-named definitions into a single "unique" survivor and hand it every call of that name. On vite that removes the 12 edges onto nested functions and adds none. Re-index after upgrading. Thanks @bompus. (#1708, #1709)

  • An import that names the emitted extension resolves to its source. Under moduleResolution: node16 | nodenext | bundler TypeScript requires import { x } from './util.js' for util.ts, and no file of that name exists, so the import resolver returned nothing and every name imported that way fell through to bare-name matching: a method wrapping the same-named helper it imports (renderDockStyles() { return renderDockStyles(); }) resolved to itself, and cross-module edges in such projects were name guesses. .js / .jsx / .mjs / .cjs specifiers now retry with the source extensions TypeScript compiles from when the emitted file is absent; a real .js beside the .ts still wins. On a 582-file repo whose .ts files import this way, import-backed calls/imports edges went from 4,002 to 7,312 and the eight wrapper-method self-edges disappeared. Re-index after upgrading. Thanks @bompus. (#1705, #1706)

  • Files under an e2e/ directory now count as tests.

  • Production code under a samples or examples package path is no longer treated as test code. A Kotlin or Java project whose package path runs through com/google/samples/… (Now in Android, for one) had nearly every file counted as a test fixture. Only the project layout above a src/ folder decides now; the package path below it never does.

  • React handlers written with useCallback are now symbols. const handleSubmit = useCallback(() => {…}, []) — the way nearly every handler in a React or React Native component is written — is extracted as a function named by its binding (also React.useCallback, useEffectEvent), so onPress={handleSubmit} and addListener('x', handleSubmit) resolve to it, its calls are its own rather than the component's, and a tap's handler shows up in codegraph_explore. A JSX attribute value (onPress={handleSubmit}, renderItem={renderRow}) and a handler a hook hands back in an object (return { handleSubmit, handleRetake }) are now function-as-value references from the component or hook, so the graph knows which functions are wired as handlers.

  • Stores exported on a later line are read like any other. const useStore = create((set, get) => ({ … })) followed by export default useStore (or export { useStore }) now has its actions extracted as functions, the same as an export const store — previously the two-statement form, common in React Native apps, left every action invisible.

  • API objects exported as a default namespace resolve through to their functions. import Api from './api' + Api.upload() where the module ends in const Api = { upload, createFolder }; export default Api now links the call to upload itself (through the object's own imports), and a default import of any const named by an export default NAME statement finds that const rather than guessing the file's first exported function.

  • The Claude Code prompt hook's context now arrives inline. The hook capped its injection at 16,000 characters, but Claude Code shows hook output inline only up to 10,000 and otherwise persists it to a file with a 2 KB preview, so on any repo where explore filled the cap the model saw a file path and the first 2 KB. The cap is now 9,000 characters, under the limit with room for the wrapper. (#1694)

  • codegraph_explore is loaded from the first prompt in Claude Code. Claude Code defers every MCP tool behind a tool-search step, so a fresh session saw only the tool's name until the model searched for it, and the server's "call codegraph_explore instead of Read" had nothing loaded to act on. The tool now carries anthropic/alwaysLoad in its _meta, which exempts it on existing installs, and codegraph install writes alwaysLoad: true on the Claude Code server entry (re-run it to add the key). Copilot CLI's tool search holds MCP tools back the same way once ~30 tools are connected, so its entry now carries deferTools: "never". (#1696)
