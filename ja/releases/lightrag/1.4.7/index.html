LightRAG v1.4.7

パッチ 公開日2025年8月29日 出典HKUDS/LightRAG English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ライトラグv1.4.7

重要な注意事項

  • Doc-id ベースのチャンク フィルタリング機能は PostgreSQL ベクトル ストレージから削除されました。
  • プロンプト テンプレートが更新され、すべての LLM キャッシュが無効になりました
  • FORCE_LLM_SUMMARY_ON_MERGE 環境変数のデフォルト値が 4 から 8 に変更されました。この調整により、ドキュメントのインデックス作成フェーズ中の LLM 呼び出しの数が大幅に減少し、ドキュメント全体の処理時間が短縮されます。
  • 複数の再ランク プロバイダー (Cohere AI、Jina AI、Aliyun Dashscope) のサポートを追加しました。再ランク付けが以前に有効になっており、再ランク付けを再度有効にするには新しい環境変数を設定する必要がある場合:
RERANK_BINDING=cohere
  • 特に大規模言語モデル (LLM) のタイムアウトを制御するために、新しい環境変数 LLM_TIMEOUT が導入されました。既存の TIMEOUT 変数は、Gunicorn ワーカーのタイムアウトを排他的に管理するようになりました。デフォルトの LLM タイムアウトは 180 秒に設定されています。以前に LLM タイムアウト構成に TIMEOUT 変数を使用していた場合は、代わりに LLM_TIMEOUT を使用するように設定を更新してください。
LLM_TIMEOUT=180
  • OpenAI および Ollama 大規模言語モデル (LLM) バインディング用の包括的な環境変数設定を追加します。 LLM 温度制御用の汎用 TEMPERATURE 環境変数は非推奨になりました。代わりに、LLM 温度はバインディング固有の環境変数を使用して設定されるようになりました。
# Temperature setting for OpenAI binding
OPENAI_LLM_TEMPERATURE=0.8

# Temperature setting for Ollama binding
OLLAMA_LLM_TEMPERATURE=1.0

無限の出力ループを軽減し、Qwen3 の貪欲なデコードを防ぐには、温度パラメーターを 0.8 と 1.0 の間の値に設定します。 モデルの「思考」モードを無効にするには、次の構成を参照してください。

### Qwen3 Specific Parameters depoly by vLLM
# OPENAI_LLM_EXTRA_BODY='{"chat_template_kwargs": {"enable_thinking": false}}'

### OpenRouter Specific Parameters
# OPENAI_LLM_EXTRA_BODY='{"reasoning": {"enabled": false}}'

サポート オプションの完全なリストを表示するには、次のコマンドを使用します。

lightrag-server --llm-binding openai --help
lightrag-server --llm-binding ollama --help
lightrag-server --embedding-binding ollama --help
  • 追加された新しい環境変数または新しいデフォルト値の完全なリスト:
# Timeout for LLM requests (seconds)
LLM_TIMEOUT=180

# Timeout for embedding requests (seconds)
EMBEDDING_TIMEOUT=30

### Number of summary segments or tokens to trigger LLM summary on entity/relation merge (at least 3 is recommended)
FORCE_LLM_SUMMARY_ON_MERGE=8

### Max description token size to trigger LLM summary
SUMMARY_MAX_TOKENS = 1200

### Recommended LLM summary output length in tokens
SUMMARY_LENGTH_RECOMMENDED=600

### Maximum context size sent to LLM for description summary
SUMMARY_CONTEXT_SIZE=12000

### RERANK_BINDING type:  null, cohere, jina, aliyun
RERANK_BINDING=null

### Enable rerank by default in query params when RERANK_BINDING is not null
# RERANK_BY_DEFAULT=True

### chunk selection strategies
###     VECTOR: Pick KG chunks by vector similarity, delivered chunks to the LLM aligning more closely with naive retrieval
###     WEIGHT: Pick KG chunks by entity and chunk weight, delivered more solely KG related chunks to the LLM
###     If reranking is enabled, the impact of chunk selection strategies will be diminished.
KG_CHUNK_PICK_METHOD=VECTOR

### Entity types that the LLM will attempt to recognize
ENTITY_TYPES=["person", "organization", "location", "event", "concept"]

LightRAG v1.4.7

Highlights

  • LLM bindings gain finer-grained controls — OpenAI options, AWS Bedrock support, and explicit OpenRouter/vLLM thinking controls expand provider flexibility. The generic TEMPERATURE variable is deprecated: migrate to OPENAI_LLM_TEMPERATURE or OLLAMA_LLM_TEMPERATURE. For Qwen3, use 0.8–1.0 to avoid greedy-decoding loops; OpenRouter and vLLM deployments can disable reasoning through OPENAI_LLM_EXTRA_BODY (#1910, #1948, #1987).

  • Reranking requires explicit reconfiguration — Cohere, Jina AI, and Aliyun Dashscope are now supported, but RERANK_BINDING defaults to null. Existing rerank deployments will silently lose reranking unless they set a provider, such as RERANK_BINDING=cohere (#1993). The new vector-based KG chunk selection is the default; once reranking is enabled, that selection strategy has less influence on final results (#1959).

  • Timeout and indexing-cost settings change behavior — TIMEOUT now controls only Gunicorn workers; migrate LLM timeout configuration to LLM_TIMEOUT (default 180 seconds), with embeddings separately controlled by EMBEDDING_TIMEOUT=30 (#2024). Raising FORCE_LLM_SUMMARY_ON_MERGE from 4 to 8 reduces merge-time LLM calls and indexing duration, though deployments with tight quality requirements may want to tune it back (#2006).

  • PostgreSQL retrieval paths are reworked — Vector indexes and optimized batch queries improve scalability and search performance (#1922, #1964), but deprecated doc-id-based chunk filtering has been removed from PostgreSQL vector storage (#2025). Audit custom retrieval code and integrations that relied on that filter before upgrading.

  • Cache and context semantics change — Updated prompt templates invalidate existing LLM caches, so expect a cold-start latency and cost spike after deployment. Cache-key generation now includes all LLM query parameters, improving correctness across options while reducing some cross-configuration cache hits (#1915). Query context also drops entity/relation file_path and created_at metadata (#1976), which may affect custom context parsers or prompts.

  • Operational recovery becomes more robust — Offline deployments can cache tiktoken assets (#1914), failed documents can be reprocessed without the original file (#1954), and clearer initialization diagnostics help distinguish configuration failures from storage outages (#1978, #1979). Workspace-isolation fixes across storage backends and repeated UTF-8 handling fixes are especially important for multi-tenant or document-heavy deployments (#1941, #1952, #2017).

Important Notes

  • Doc-id based chunk filtering feature is remove from PostgreSQL vector storage.
  • Prompt template has been updated, invalidating all LLM caches
  • The default value of the FORCE_LLM_SUMMARY_ON_MERGE environment variable has been changed from 4 to 8. This adjustment significantly reduces the number of LLM calls during the documentation indexing phase, thereby shortening the overall document processing time.
  • Added support for multiple Rerank Providers (Cohere AI, Jina AI, Aliyun Dashscope). If Rerank was previously enabled, and new env var must be set to enable rerank again:
RERANK_BINDING=cohere
  • Introduced a new environment variable, LLM_TIMEOUT, to specifically control the Large Language Model (LLM) timeout. The existing TIMEOUT variable now exclusively manages the Gunicorn worker timeout. The default LLM timeout is set to 180 seconds. If you previously relied on the TIMEOUT variable for LLM timeout configuration, please update your settings to use LLM_TIMEOUT instead:
LLM_TIMEOUT=180
  • Add comprehensive environment variable settings for OpenAI and Ollama Large Language Model (LLM) Bindings. The generic TEMPERATURE environment variable for LLM temperature control has been deprecated. Instead, LLM temperature is now configured using binding-specific environment variables:
# Temperature setting for OpenAI binding
OPENAI_LLM_TEMPERATURE=0.8

# Temperature setting for Ollama binding
OLLAMA_LLM_TEMPERATURE=1.0

To mitigate endless output loops and prevent greedy decoding for Qwen3, set the temperature parameter to a value between 0.8 and 1.0. To disable the model's "Thinking" mode, please refer to the following configuration:

### Qwen3 Specific Parameters depoly by vLLM
# OPENAI_LLM_EXTRA_BODY='{"chat_template_kwargs": {"enable_thinking": false}}'

### OpenRouter Specific Parameters
# OPENAI_LLM_EXTRA_BODY='{"reasoning": {"enabled": false}}'

For a full list of support options, use the following command:

lightrag-server --llm-binding openai --help
lightrag-server --llm-binding ollama --help
lightrag-server --embedding-binding ollama --help
