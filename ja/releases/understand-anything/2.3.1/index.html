何でもわかる v2.3.1

新機能

/understand-knowledge — ナレッジベース分析

Karpathy パターン LLM Wiki ナレッジ ベースを分析するための新しいスキル。ウィキリンクを使用して生のソースとウィキ マークダウンを検出し、エンティティ抽出、暗黙的な関係、5 つのフェーズ (検出 → スキャン → 分析 → マージ → 保存) にわたるトピックのクラスタリングを使用してインタラクティブなナレッジ グラフを生成します。 2 つの新しいエージェントが付属しています。

  • article-analyzer — ウィキ記事から暗黙的知識を抽出します: エンティティ (人、ツール、論文)、主張 (決定、主張)、およびセマンティック エッジ (builds_on、contradicts、exemplifies、authored_by、cites)
  • assemble-reviewer — ドロップされたノード/エッジを回復し、未知のタイプを再マップし、バッチ間の整合性を検証するマージ後の品質レビュー担当者 専用の KnowledgeGraphView ダッシュボード コンポーネントは、検索、ツアーの強調表示、および関係タイプのエッジ スタイルを備えた強制的な視覚化を提供します。

.understandignore のサポート

/understand 分析用のユーザー構成可能なファイル除外:

  • IgnoreFilter — ハードコーディングされたデフォルト (node_modules、ビルド出力、ロック ファイル、バイナリ) と .understand-anything/ およびプロジェクト ルートからの階層化された .understandignore ファイルを使用したランタイム フィルタリング
  • IgnoreGenerator — 既存の .gitignore を解析し、プロジェクト ディレクトリを検出することにより、スターター .understandignore を自動生成します。
  • /understand ワークフローの新しい フェーズ 0.5 は、無視ファイルの生成後にユーザー確認のために一時停止します

/understand パイプラインの改善

  • サブドメイン グラフのマージ (フェーズ 0) — 複数のドメイン固有のグラフを重複排除を使用して 1 つの統合グラフにマージします。
  • バッチ グラフ マージ — ID の正規化、複雑さのマッピング、および詳細な修正レポートを備えた新しい Python スクリプト
  • 増分更新 — --auto-update / --no-auto-update フラグによる構造フィンガープリンティング
  • **アーキテクチャ分析のための 言語/フレームワーク コンテキスト インジェクション
  • レビュー パスの拡張 — インライン検証と --review による完全な LLM レビュー

スキーマと型の拡張

  • ノード タイプを 13 → 21 に拡張 (domain、flow、step、article、entity、topic、claim、source を追加)
  • エッジ タイプは 35 に拡張され、構造、動作、データ フロー、依存関係、セマンティック、インフラストラクチャ、ドメイン、および知識関係をカバーします。
  • 柔軟な入力のタイプエイリアス (func → function、doc → document など)

プロジェクトスキャナーの改善

  • 明示的な fileCategory 割り当てを使用して非コード ファイル (構成、ドキュメント、インフラストラクチャ、データ) を処理するようになりました。
  • 言語とフレームワークの検出が改善された決定的なスクリプトベースのファイル検出

ドキュメントと国際化

  • 韓国語 (README.ko-KR.md) およびスペイン語 (README.es-ES.md) README の翻訳
  • 構造ビューとドメイン ビューのアニメーション ショーケース GIF
  • マルチプラットフォーム バッジ (Codex、Copilot、Gemini CLI、OpenCode)

修正

  • ダッシュボード URL にアクセス トークンが含まれるようになりました
  • ノード選択時に接続されたエッジが正しくハイライト表示される
  • グラフ ビューの安定したレイアウトとスコープ指定されたインフラストラクチャ フィルター
  • マーケットプレイス JSON スキーマ検証の修正
  • グラフマージスクリプトのエッジウェイト強制

Understand-Anything v2.3.1

Highlights

  • Knowledge-base analysis — New /understand-knowledge turns linked wiki content into an interactive relationship graph through DETECT → SCAN → ANALYZE → MERGE → SAVE. The article-analyzer extracts implicit entities, claims, and semantic edges, while assemble-reviewer repairs lost or inconsistent graph elements after merging; KnowledgeGraphView adds search, guided tours, and relationship-typed edges.

  • Analysis scoping with ignore rules — /understand now applies built-in exclusions plus layered .understandignore files from the project root and .understand-anything/. A starter file can be generated from .gitignore, followed by a new Phase 0.5 confirmation gate—review it before proceeding, especially because the scanner now intentionally includes documentation, configuration, infrastructure, and data files.

  • Unified and incremental graphs — Subdomain graphs and batch merges now deduplicate into one graph; the Python merger normalizes IDs, maps complexity, and emits detailed fix reports. Structural fingerprinting enables incremental updates controlled by --auto-update and --no-auto-update; automated workflows should choose a policy explicitly and inspect merge reports before treating the result as canonical.

  • Expanded graph schema — Node types grow from 13 to 21, including domain, flow, step, article, entity, topic, claim, and source, while edge types expand to 35. Downstream consumers with hard-coded type allowlists should be updated; aliases such as func → function and doc → document ease ingestion of varied inputs.

  • Broader architecture context — Non-code files receive explicit fileCategory assignments, and deterministic script-based discovery improves language and framework detection. That context now feeds architecture analysis, and --review separates lightweight inline validation from a full LLM review—use ignore rules to prevent unrelated assets from entering the graph.

  • Breaking changes — None listed.

What's New

/understand-knowledge — Knowledge Base Analysis

New skill for analyzing Karpathy-pattern LLM wiki knowledge bases. Detects raw sources and wiki markdown with wikilinks, then produces interactive knowledge graphs with entity extraction, implicit relationships, and topic clustering across five phases (DETECT → SCAN → ANALYZE → MERGE → SAVE).

Comes with two new agents:

  • article-analyzer — extracts implicit knowledge from wiki articles: entities (people, tools, papers), claims (decisions, assertions), and semantic edges (builds_on, contradicts, exemplifies, authored_by, cites)
  • assemble-reviewer — post-merge quality reviewer that recovers dropped nodes/edges, remaps unknown types, and verifies cross-batch consistency

A dedicated KnowledgeGraphView dashboard component provides force-directed visualization with search, tour highlighting, and relationship-typed edge styling.

.understandignore Support

User-configurable file exclusion for /understand analysis:

  • IgnoreFilter — runtime filtering with hardcoded defaults (node_modules, build outputs, lock files, binaries) plus layered .understandignore files from .understand-anything/ and project root
  • IgnoreGenerator — auto-generates a starter .understandignore by parsing your existing .gitignore and detecting project directories
  • New Phase 0.5 in the /understand workflow pauses for user confirmation after generating the ignore file

/understand Pipeline Improvements

  • Subdomain graph merging (Phase 0) — merges multiple domain-specific graphs into one unified graph with deduplication
  • Batch graph merging — new Python script with ID normalization, complexity mapping, and detailed fix reports
  • Incremental updates — structural fingerprinting with --auto-update / --no-auto-update flags
  • Language/framework context injection for architecture analysis
  • Expanded review paths — inline validation vs. full LLM review via --review

Schema & Type Expansion

  • Node types expanded from 13 → 21 (added domain, flow, step, article, entity, topic, claim, source)
  • Edge types expanded to 35 covering structural, behavioral, data flow, dependency, semantic, infrastructure, domain, and knowledge relationships
  • Type aliases for flexible input (func → function, doc → document, etc.)

Project Scanner Improvements

  • Now handles non-code files (configs, docs, infrastructure, data) with explicit fileCategory assignment
  • Deterministic script-based file discovery with improved language and framework detection

Documentation & Internationalization

  • Korean (README.ko-KR.md) and Spanish (README.es-ES.md) README translations
  • Animated showcase GIFs for structural and domain views
  • Multi-platform badges (Codex, Copilot, Gemini CLI, OpenCode)

Fixes

  • Dashboard URL now includes access token
  • Connected edges highlight correctly on node selection
  • Stable layout and scoped infrastructure filter in graph view
  • Marketplace JSON schema validation fixes
  • Edge weight coercion for graph merge scripts
