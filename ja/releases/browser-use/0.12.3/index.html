ブラウザ用 0.12.3

ブラウザを使用 CLI 2.0

AI コーディング エージェント向けの最速のブラウザ自動化。 2 倍高速になり、トークンが 50% 減り、あらゆる CLI エージェント (Claude Code、Codex など) で動作します。 Playwright ではなく直接 CDP (Chrome DevTools Protocol) 上に構築されており、永続的なバックグラウンド デーモンを介して ~50ms のコマンド遅延を実現します。 https://github.com/user-attachments/assets/a604895b-4ff9-47be-8161-56c48773f93b

インストール

# Install the CLI
curl -fsSL https://browser-use.com/cli/install.sh | bash

# Install the skill (for Claude Code / Codex)
mkdir -p ~/.claude/skills/browser-use
curl -o ~/.claude/skills/browser-use/SKILL.md \
  https://raw.githubusercontent.com/browser-use/browser-use/main/skills/browser-use/SKILL.md

あらゆる CLI コーディング エージェント (Claude Code、Codex、OpenClaw など) で動作します。 CLIとスキルをインストールするだけです。

クイックスタート

browser-use open https://example.com   # Navigate (starts browser if needed)
browser-use state                      # Returns clickable elements: [0] button "Submit", [1] input "Email"...
browser-use click 0                    # Click by index
browser-use input 3 "hello@example.com" # Click element, then type
browser-use type "search query"        # Type into focused element
browser-use screenshot page.png        # See the page
browser-use close                      # Done

CLI は state の要素インデックスを使用します。維持するセレクターはありません。 browser-use state はエージェント向けに最適化されており、高速でトークン効率が高く、ページ上の対話可能なすべての要素を返します。

🖥️ ブラウザモード

|モード |コマンド |説明 | |-----|----------|---------------| |ヘッドレス | browser-use open <url> |デフォルト、高速、非表示 | |見出し | browser-use --headed open <url> |デバッグ用の表示ウィンドウ | |リアルクローム | browser-use --profile "Default" open <url> |既存のログインと Cookie を使用した Chrome | |接続 | browser-use --connect open <url> |自動検出し、CDP 経由で実行中の Chrome に接続 | | CDP URL | browser-use --cdp-url ws://localhost:9222/... open <url> | CDP URL 経由で任意のブラウザに接続 | | ☁️クラウド | browser-use cloud connect |ステルス クラウド ブラウザ + プロキシが含まれる |

Chrome のみ。 CLI は、Chrome/Chromium 固有の Chrome DevTools プロトコル (CDP) を使用します。 Safari および Firefox はサポートされていません。 クラウド ブラウザには、cloud.browser-use.com の BROWSER_USE_API_KEY が必要です。クラウドは、検出防止、プロキシ、および大規模な並列化を備えたエージェント対応ブラウザを提供します。

🔗 実行中の Chrome に接続する

最もリクエストの多い機能の 1 つ — すべてのログイン、Cookie、拡張機能を使用して、すでに実行されている Chrome に接続します。

# Auto-discover running Chrome's CDP endpoint
browser-use --connect open https://github.com

# Or use an existing Chrome profile directly
browser-use --profile "Default" open https://github.com    # Already logged in!
browser-use --profile "Profile 1" open https://gmail.com   # Named profile

# List available profiles
browser-use profile list

WSL2 ユーザーへのヒント: WSL2 からホスト ブラウザを制御するには、CLAUDE.md に browser-use --cdp-url を追加します。

🔀 複数のセッション

browser-use -s work open https://work.example.com
browser-use -s personal open https://gmail.com
browser-use sessions       # List all
browser-use close --all    # Close all

📤 フォーム、アップロード、インタラクション

CLI は、フォームの入力と複雑なインタラクションに優れています。

browser-use input 5 "user@example.com"   # Fill email field
browser-use input 6 "password123"        # Fill password
browser-use click 7                      # Submit button
browser-use select 3 "United States"     # Dropdown selection
browser-use upload 4 ./resume.pdf        # Upload a file
browser-use hover 2                      # Hover over element
browser-use keys "Enter"                 # Send keyboard keys

📊 データ抽出

browser-use get title                    # Page title
browser-use get html --selector "table"  # Scoped HTML
browser-use get text 5                   # Element text
browser-use eval "document.title"        # Run JavaScript
browser-use screenshot --full page.png   # Full-page screenshot

🐍 永続的な Python セッション

browser-use python "browser.goto('https://example.com')"
browser-use python "items = browser.html"
browser-use python "print(len(items))"    # Variables persist across calls
browser-use python --vars                  # Show defined variables

🌐 トンネル (ローカル開発を公開)

browser-use tunnel 3000                   # → https://abc.trycloudflare.com
browser-use open https://abc.trycloudflare.com
browser-use tunnel stop --all

仕組み

CLI はスクリーンショットや画像検出を使用しません。代わりに、CDP 経由でブラウザの DOM ツリーを直接読み取り、構造化されたトークン効率の高い要素データを返します。コーディング エージェントがコンテンツを処理します。 CLI はブラウザのコンテキストとコマンドの実行を処理します。すべてのコマンドは、ブラウザー用の Python ライブラリと同じ、実戦テストされた実装を共有します。 アーキテクチャ: バックグラウンド デーモンにより、コマンド間でブラウザが稼働し続けるため、コマンドごとの起動コストは発生せず、遅延はわずか約 50 ミリ秒です。

よくある質問

Codex / 他の CLI エージェントでも動作しますか? はい - あらゆる CLI コーディング エージェントで動作します。 CLIとスキルファイルをインストールします。 ヘッドレスで実行できますか? はい、ヘッドレスがデフォルトです。ブラウザで見たい場合は--headedを使用してください。 Claude Chrome 拡張機能と比較するとどうですか? ブラウザ使用 CLI も無料で、高速かつトークン効率が高く、Chrome 拡張機能を必要とせず、(クロードだけでなく) あらゆる CLI エージェントで動作します。 Vercel Agent Browser との違いは何ですか? 半分のコマンドで半分のコストで 2 倍の速度。 Safari/Firefox では動作しますか? いいえ、Chrome DevTools Protocol (CDP) を使用します。これは Chrome/Chromium のみです。 ファイルをアップロードできますか? はい！ browser-use upload <index> <path>を使用してください。 セキュリティ/侵入テストについてはどうですか? はい - 一般的な使用例には、フォーム入力、QA/ペネトレーションテスト、一般的な Web 自動化などがあります。

browser-use 0.12.3

Highlights

  • CLI 2.0 architecture — The standalone CLI now drives Chrome directly through CDP, using DOM snapshots and element indices instead of screenshots or selectors. A persistent daemon eliminates per-command browser startup; upstream claims 2× faster automation, ~50 ms command latency, and 50% fewer tokens (#4364). The CLI supports Chrome/Chromium only—not Firefox or Safari.

  • Existing-browser and multi-session workflows — --connect, --profile, and --cdp-url let agents reuse running Chrome instances, profiles, cookies, and extensions, while named sessions (-s work, -s personal) isolate automation contexts. Adoption requires installing the CLI and agent skill; index-based interactions mean agents should refresh browser-use state after navigation or DOM changes.

  • More reliable page interactions — Cross-origin iframe elements are now indexed reliably (#4452), clicks that open tabs automatically switch context with a checkbox-toggle fallback (#4433), and highlight removal no longer blocks screenshots (#4381). Chrome 145+ extension handling was also repaired following Manifest V2 removal and flag changes (#4466).

  • Privacy and supply-chain hardening — Password field values are excluded from DOM snapshots sent to LLMs (#4388), reducing credential exposure but changing workflows that previously read those values back. Repository fixes also restrict workflow permissions, upgrade vulnerable dependencies, and remove unused authentication code (#4468).

  • Model support and extraction quality — LiteLLM integration (#4384) and revised ChatVercel API-key handling (#4270) expand provider options. Data-grounding fixes reduce unsupported completion claims (#4416, #4417), compaction hallucination is addressed (#4403), and extracted Markdown retains image URLs (#4427)—important for faithful scraping and document generation.

  • Breaking change: code agent removed — The built-in code agent was removed (#4438). Automation that depended on it must move orchestration to the standalone CLI plus an agent skill, or invoke the Python library directly.

Browser Use CLI 2.0

The fastest browser automation for AI coding agents. 2x faster, 50% fewer tokens, and works with any CLI agent — Claude Code, Codex, and more.

Built on direct CDP (Chrome DevTools Protocol) instead of Playwright, giving ~50ms command latency via a persistent background daemon.

Quick Start

browser-use open https://example.com   # Navigate (starts browser if needed)
browser-use state                      # Returns clickable elements: [0] button "Submit", [1] input "Email"...
browser-use click 0                    # Click by index
browser-use input 3 "hello@example.com" # Click element, then type
browser-use type "search query"        # Type into focused element
browser-use screenshot page.png        # See the page
browser-use close                      # Done

The CLI uses element indices from state — no selectors to maintain. browser-use state is optimized for agents: fast, token-efficient, and returns every interactable element on the page.

🖥️ Browser Modes

| Mode | Command | Description | |------|---------|-------------| | Headless | browser-use open <url> | Default, fast, invisible | | Headed | browser-use --headed open <url> | Visible window for debugging | | Real Chrome | browser-use --profile "Default" open <url> | Your Chrome with existing logins & cookies | | Connect | browser-use --connect open <url> | Auto-discover and attach to running Chrome via CDP | | CDP URL | browser-use --cdp-url ws://localhost:9222/... open <url> | Connect to any browser via CDP URL | | ☁️ Cloud | browser-use cloud connect | Stealth cloud browser + proxies included |

Chrome only. The CLI uses Chrome DevTools Protocol (CDP), which is Chrome/Chromium-specific. Safari and Firefox are not supported.

Cloud browser requires BROWSER_USE_API_KEY from cloud.browser-use.com. Cloud gives you agent-ready browsers with anti-detection, proxies, and massive parallelization.

How It Works

The CLI doesn't use screenshots or image detection. Instead, it directly reads the browser's DOM tree via CDP and returns structured, token-efficient element data. Your coding agent processes the content; the CLI handles browser context and command execution. Every command shares the same battle-tested implementation as the browser-use Python library.

Architecture: A background daemon keeps the browser alive between commands, so there's no startup cost per command — just ~50ms latency.

FAQ

Does it work with Codex / other CLI agents? Yes — it works with any CLI coding agent. Install the CLI and the skill file.

Can it run headless? Yes, headless is the default. Use --headed when you want to see the browser.

How does it compare to the Claude Chrome extension? The Browser Use CLI is also free, faster and more token efficient, doesn't require a Chrome extension, and works with any CLI agent (not just Claude).

How does it compare to Vercel Agent Browser? 2x the speed for half the cost with half the commands.

Does it work with Safari/Firefox? No — it uses Chrome DevTools Protocol (CDP), which is Chrome/Chromium only.

Can it upload files? Yes! Use browser-use upload <index> <path>.

What about security/pentesting? Yes — popular use cases include form filling, QA/pentesting, and general web automation.
