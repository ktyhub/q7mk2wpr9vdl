browser-use 0.13.9

Highlights

  • LLM defaults and provider behavior — ChatBrowserUse again defaults to bu-2-0, with mini opt-in (#5488), and DeepSeek now defaults to deepseek-v4-flash (#5563). Pin models explicitly if cost or output stability matters. Ollama no longer nests format/stream inside options (#5561), so check custom proxies; OrcaRouter is also available as a named provider (#5451).
  • Better agent grounding and error reporting — Clickable elements and directly clickable images now expose image context (#5541, #5586), prefilled inputs expose their live values (#5650), and failed tab switches return errors instead of silent success (#5500). This reduces blind clicks and false completion signals; callers should handle tool failures explicitly.
  • More stable browser sessions — Fixes cover WebSocket drops during reconnects, early browser-process exits, and session handlers lost after an event-bus reset (#5373, #4599, #5230), plus Storage-domain cookie clearing, UTF-8 persisted state, and Chrome argument ordering (#5562, #5359, #5621). BROWSER_USE_HEADLESS is now honored (#5475), which can change behavior in CI or container profiles that already set it.
  • Security and dependency compatibility — Vulnerable Click, MCP, and pypdf pins are updated (#5526), Pydantic 2.13 is supported (#5577), and datamodel-code-generator moves to 0.75.1 (#5588). Refresh lockfiles and container images, and review committed generated models after upgrading.
  • Cloud integration baseline — Documentation and skills now use API V4 and CLI 3.0 rather than retired V1 examples (#5578, #5591, #5553, #5583), and the release includes Browser Harness 0.1.12 (#5666). Migrate copied scripts and remote-browser tooling that still target the old API or CLI.
  • Breaking changes — None.
