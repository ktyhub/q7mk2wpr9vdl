browser-use 0.12.7

Highlights

  • Security and privacy — upgrade recommended for all runtime users — Dependency updates patch aiohttp 3.13.4 (CVE-2026-34515, memory exhaustion), requests 2.33.0 (temp-file path traversal), pillow 12.2.0 (CVE-2026-40192), and pypdf 6.10.2 (CVE-2026-40260). The release also adds per-session daemon-socket authentication, blocks obfuscated IP forms in block_ip_addresses, contains upload_file and download paths, sanitizes download filenames, and fixes sensitive_data logging leaks.

  • Default browser behavior may affect existing setups — Sessions now prefer Playwright’s Chromium over system Chrome, with improved Mac/ARM Chromium discovery. Workflows dependent on Chrome’s version, profiles, or extensions should be retested and explicitly select system Chrome if needed. BrowserSession.close is an additive alias for stop.

  • CLI additions and SDK compatibility — New record start/stop commands support session video capture, alongside broader CLI and connection-error UX changes. browser-use-sdk moves from 2.0.15 to 3.4.2. No migration instructions or explicit breaking changes are listed, but the major SDK jump and browser-default change warrant smoke testing before broad rollout.

  • Fewer hangs, stale reads, and lost results — Per-action timeouts prevent stuck handlers; DOM cache invalidation and iframe-detach handling reduce stale extraction; partial batch results are preserved when a later action fails. Input clearing, multi-character CDP typing, and pagination classification are also corrected. Long-running agents and scripts using scrolling or batch actions gain concrete reliability improvements.

  • Compatibility and verdict — Python 3.14 event-loop handling, Pydantic-related ainvoke patching, MCP startup and BrokenPipeError handling, locked Chrome profile copies, and proxy_country_code=None behavior are fixed. This is a substantive security and correctness release: most users should upgrade; only consumers who never execute browser-use can reasonably skip.
