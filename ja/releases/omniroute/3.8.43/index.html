  • メモリ (型付き減衰): オプトイン型付きメモリ減衰 (TV6) を追加して、会話型メモリ ストアが古い episodic ノイズを蓄積しないようにします。注入された各メモリは、access_count + last_accessed_at (常時オン、非破壊テレメトリ、移行 111_memory_typed_decay) を追跡し、オプトイン、デフォルト オフ スイープ (MEMORY_TYPED_DECAY_ENABLED、デフォルト false) により、タイプごとの TTL を過ぎて免疫のないメモリが削除されます。デフォルトでは episodic のみが減衰します (30d、環境調整可能)。 factual/procedural/semantic は免疫であり、>= 3 回アクセスされたメモリはアクセス免疫を獲得します (「ガードレール/規約/決定は決して減衰しない」を反映)。減衰クロックは最後のアクセスに基づいて再設定されるため、使用されたメモリは残ります。削除では deleteMemory (SQLite + sqlite-vec + Qdrant は同期を維持します) が再利用され、フェール オープンが行われます。オプションの定期スイープは二重オプトインです (MEMORY_TYPED_DECAY_SWEEP_INTERVAL>0 も必要です)。フラグがオフの場合、何も削除されることはありません (ルール #20 の精神)。新品src/lib/memory/typedDecay.tsです。リグレッション ガード: tests/unit/memory/typed-decay.test.ts (15)。ギャップ v3.8.42 — T10/TV6。

Highlights

  • Compression gains an opt-in engine suite (all default-off) — v3.8.43 adds five gated compression features: an llm prose condenser whose default backend is a no-op pass-through until you wire one via setLlmCompressorBackend() (fails open on every error), a lossy read-lifecycle engine that collapses superseded file-Read tool results, a per-engine process-local circuit breaker (COMPRESSION_PIPELINE_BREAKER_ENABLED), a graded CCR retrieval ramp (retrievalRampFactor, default 2; set 1 for the old binary cliff), and usage-observed prefix freezing (COMPRESSION_PREFIX_FREEZE_ENABLED) that preserves recurring system prompts to keep prompt-cache hits. None join the default pipeline, so upgrading is byte-identical until enabled — watch that read-lifecycle is semantic/lossy and that breaker default-off still propagates a throwing engine (enable TV1 for per-request bail-out).

  • Usage output changes: percentages replace USD, flat-rate providers read $0 — @@om-usage and /api/usage now report personal-key quotas as remaining percentages (USD no longer appears in command output), provider quota is scaled by the configured cutoff so the protected reserve reads 0% left, and a management-auth-gated provider USD drilldown returns (/api/usage/provider-window-costs, ProviderUsdCostModal, #5863). No breaking changes.

A non-empty response (recvBytes > 0) was therefore classified as empty_choices and turned into a 502 that also cooled the account down.   • embedded services (Windows): fix CLIProxyAPI install failing instantly with spawn unzip ENOENT on Windows. The binary extractor spawned unzip, which is not a Windows system command — it only ships inside Git for Windows' usr/bin, a directory Node's spawn PATH never sees, so even users with Git installed hit the error. On Windows the extractor now uses PowerShell's built-in Expand-Archive (via execFileAsync, no shell — paths pass as a single non-interpreted arg, with ''-escaping + -LiteralPath as defense in depth); other platforms keep using unzip.   • storage (daemon): fix a Node.js out-of-memory crash on startup when storage.sqlite grows large (~170 MB+). The boot-time call-log cleanup (cleanupExpiredLogs → rotateCallLogs) ran two unbounded SELECT … FROM call_logs … .all() queries — listReferencedArtifacts (every artifact path) and deleteCallLogsBefore (every id before the retention cutoff). node:sqlite's StatementSync.all() materializes the entire result set as JS objects at once, so on a large table the V8 heap blew up and the process crashed before binding (FATAL ERROR: … heap out of memory, native frame node::sqlite::StatementSync::All). Both queries now page through call_logs in bounded 5 000-row chunks (new src/lib/usage/callLogsBoundedQueries.ts), keeping peak memory flat regardless of table size — no more manual --max-old-space-size bump required. Regression guard: tests/unit/call-log-oom-unbounded-5618.test.ts. (#5618)
