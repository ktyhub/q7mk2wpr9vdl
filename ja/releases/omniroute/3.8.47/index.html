OmniRoute v3.8.47

Highlights

  • 9router Codex import compatibility — POST /api/oauth/codex/import now normalizes 9router’s camelCase token fields and nested providerSpecificData, including {accounts:[...]} wrappers, without overwriting supplied snake_case values (#6665). Teams migrating account exports can submit 9router files directly without rewriting payloads.

  • Routing controls and budget enforcement — auto/* combos add opt-in strict budget enforcement through X-OmniRoute-Budget-Fallback: strict or config.budgetFallback: "strict"; over-cap requests return HTTP 402 instead of silently selecting a potentially still-over-budget target (#3470). Combo context requirements (#6907), parameter filtering learned from upstream 400s (#6649), and manual context-window overrides (#4125) reduce avoidable routing failures. The default cheapest behavior remains unchanged.

  • Provider authentication coverage — Kiro now supports enterprise External IdP token refresh and long-lived CodeWhisperer API keys, with SSRF-checked IdP endpoints and per-account model discovery (#6363, #6587). ClinePass offers both OAuth and BYOK under the corrected cp routing alias (#6126), giving organization-managed and API-key-based accounts a supported connection path.

  • Chaos Mode is opt-in, not a default routing change — Parallel/collaborative multi-model execution requires global and per-key chaosModeEnabled; the engine caps concurrency at 10, rejects streaming, and fixes an external Bearer-auth bypass and stale-config leakage (#6728). Use it deliberately for diagnostics or collaborative workflows rather than as a transparent replacement for normal routing.

  • Operational visibility and protocol hardening — Langfuse adds provider observability (#6577), while HEAD responses now terminate across authenticated, unauthenticated, matched, and unmatched routes instead of hanging clients (#6400). Local CLI/skill detection endpoints now require management authentication and loopback access (#6294, #6318); the skill-install MCP tool also reports action: "planned" instead of claiming installation succeeded.

  • Breaking changes — None documented.

  • 9router Codex import: the Codex bulk-import endpoint (POST /api/oauth/codex/import) now accepts 9router's camelCase account export (accessToken/refreshToken/idToken/expiresAt + nested providerSpecificData), not just snake_case — normalizeCodexImportRecord maps the camelCase aliases onto the existing snake_case keys, filling each only when absent so snake_case/mixed exports keep working unchanged (#6665) — thanks @deadcoder0904.
