何が変わったのか

  • https://github.com/google/gson/pull/2948 の @eamonnmcmanus による java.time クラスの型アダプターを追加

    java.time API が使用可能な場合、Gson は自動的に Instant や Duration などのクラスのインスタンスの読み取りと書き込みを行うことができます。使用する形式は、java.time クラスのプライベート フィールドに基づいて、ReflectiveTypeAdapterFactory がデフォルトで確立した JSON 表現を基本的に凍結します。これはあまり良い表現ではありませんが、理解できます。他の形式に変更すると、現在の形式を想定しているシステムとの互換性が失われます。

    この変更により、Gson はリフレクションを使用してこれらのクラスのプライベート フィールドにアクセスしようとしなくなりました。したがって、最近の JDK では、これらのクラスを --add-opens で実行する必要はなくなりました。

  • https://github.com/google/gson/pull/2990. 内の @eamonnmcmanus による com.google.gson.graph を削除

    このパッケージはリリースされたアーティファクトの一部ではなく、潜在的に問題のある方法で Gson 内部に依存していました。

  • https://github.com/google/gson/pull/2995 の @eamonnmcmanus により、整数として解析される文字列が ASCII 文字で構成されていることを検証します

    以前は、文字列に非 ASCII Unicode 数字が含まれていても、整数として解析できました。これは、JSON 番号の処理方法と矛盾します。

  • 最初の値が null の場合の重複キーの検出を修正 (https://github.com/google/gson/pull/3006 の @andrewstellman による)

    これにより、誤った動作に依存していたコードが破損する可能性があります。たとえば、この JSON 文字列は以前は受け入れられていましたが、今後は {"foo": null, "foo": bar} になります。

  • 内部 Type 実装クラスから Serializable を削除します。 @eamonnmcmanus 著、https://github.com/google/gson/pull/3011

    GsonTypes のネストされたクラス ParameterizedTypeImpl、GenericArrayTypeImpl、および WildcardTypeImpl は、java.lang.reflect の対応する型 (Impl なし) の実装です。 java.lang.reflect 実装はシリアライズ可能ではないにもかかわらず、何らかの理由でシリアル化可能でした。不必要にシリアル化可能なクラスを持つことは、シリアル化を使用する大規模なエクスプロイトの一部である場合、_おそらく__セキュリティ上の問題になる可能性があります。 (私たちはこれが起こり得るシナリオとは考えていませんし、この変更を取得するためだけに Gson を更新する必要があるとは考えていません。)

※LegacyProtoTypeAdapterFactoryを追加します。 @eamonnmcmanus 著、https://github.com/google/gson/pull/3014

これはリリースされたアーティファクトの一部ではありませんが、現在リフレクションを介して protobuf クラスの内部にアクセスしているコードを修正しようとするときに役立つ可能性があります。

  • https://github.com/google/gson/pull/2925 の @MukjepScarlet によって委任オブジェクトがサポートされている場合、AppendableWriter がフラッシュして閉じるようにする

その他の目に見えにくい変更点

  • https://github.com/google/gson/pull/2959 の @MukjepScarlet によってデフォルトの容量を EnumTypeAdapter マップに追加
  • リファクタリング: https://github.com/google/gson/pull/2951 の @MukjepScarlet により、派生アダプターを Gson から TypeAdapters に移動
  • https://github.com/google/gson/pull/2864 の @MukjepScarlet による new Gson() の最適化

gson gson-parent-2.14.0

What's Changed

  • Add type adapters for java.time classes by @eamonnmcmanus in https://github.com/google/gson/pull/2948

    When the java.time API is available, Gson automatically can read and write instances of classes like Instant and Duration. The format it uses essentially freezes the JSON representation that ReflectiveTypeAdapterFactory established by default, based on the private fields of java.time classes. That's not a great representation, but it is understandable. Changing it to anything else would break compatibility with systems that are expecting the current format.

    With this change, Gson no longer tries to access private fields of these classes using reflection. So it is no longer necessary to run with --add-opens for these classes on recent JDKs.

  • Remove com.google.gson.graph by @eamonnmcmanus in https://github.com/google/gson/pull/2990.

    This package was not part of any released artifact and depended on Gson internals in potentially problematic ways.

  • Validate that strings being parsed as integers consist of ASCII characters by @eamonnmcmanus in https://github.com/google/gson/pull/2995

    Previously, strings could contain non-ASCII Unicode digits and still be parsed as integers. That's inconsistent with how JSON numbers are treated.

  • Fix duplicate key detection when first value is null by @andrewstellman in https://github.com/google/gson/pull/3006

    This could potentially break code that was relying on the incorrect behaviour. For example, this JSON string was previously accepted but will no longer be: {"foo": null, "foo": bar}.

  • Remove Serializable from internal Type implementation classes. by @eamonnmcmanus in https://github.com/google/gson/pull/3011

    The nested classes ParameterizedTypeImpl, GenericArrayTypeImpl, and WildcardTypeImpl in GsonTypes are implementations of the corresponding types (without Impl) in java.lang.reflect. For some reason, they were serializable, even though the java.lang.reflect implementations are not. Having unnecessarily serializable classes could conceivably have been a security problem if they were part of a larger exploit using serialization. (We do not consider this a likely scenario and do not suggest that you need to update Gson just to get this change.)

  • Add LegacyProtoTypeAdapterFactory. by @eamonnmcmanus in https://github.com/google/gson/pull/3014

    This is not part of any released artifact, but may be of use when trying to fix code that is currently accessing the internals of protobuf classes via reflection.

  • Make AppendableWriter do flush and close if delegation object supports by @MukjepScarlet in https://github.com/google/gson/pull/2925

Other less visible changes

  • Add default capacity to EnumTypeAdapter maps by @MukjepScarlet in https://github.com/google/gson/pull/2959
  • refactor: move derived adapters from Gson to TypeAdapters by @MukjepScarlet in https://github.com/google/gson/pull/2951
  • Optimize new Gson() by @MukjepScarlet in https://github.com/google/gson/pull/2864
