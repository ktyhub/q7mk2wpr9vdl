#FastGPT v4.17.2

📦 アップグレード ガイド

ミラーアップデート

  • fastgpt-app (FastGPT メイン サービス) イメージ タグを更新します: v4.17.2
  • fastgpt-pro (FastGPT 商用版) イメージ タグを更新します: v4.17.2

アップグレードスクリプト

このアップグレードには、次の手動でトリガーされるアップグレード スクリプトが含まれています (「管理者 > バージョン アップグレード」で表示および実行できます)。

  1. 履歴チャンク トレーニング タスクの移行 (20261008_migrate_chunk_training): 既存の古いチャンク トレーニング タスクを、正式なデータ行に関連付けられた新しいモデルにスムーズに変換します。これは手動でトリガーされるタスクです (サービスの起動はブロックされません)。 「実行」をクリックする前に、クラスター内のすべての古いバージョンの FastGPT App および Pro インスタンスが完全に停止し、古いタスクのリース期限が切れていることを確認してください。
  2. ナレッジ ベースの再構築状態の移行 (20261009_migrate_dataset_rebuild_status): 上記のトレーニング タスクの移行の完了に基づいて、これは手動でトリガーされるタスク (サービスの起動をブロックしません) であり、履歴ナレッジ ベース データ行内の古い rebuilding マークと遷移状態は、新しい indexStatus 再構築状態システムに均一に移行されます。

🚀 新しいコンテンツ

  1. ナレッジ ベース データが事前にデータベースにドロップされ、トレーニング リンクが再構築されます:
    • ブロックの解析、イメージのインポート、およびバックアップ/テンプレートのインポートは、コンテンツの解析が完了した後、すぐに表示されるデータ行にドロップされ、プロセス全体が一意の dataId にバインドされます。トレーニングが完了すると、ベクトルとインデックスが同じデータに直接書き戻されるため、長いトレーニング サイクルでデータがなくなったり、トレーニングが中断された後に孤立データが残ったりする問題が完全に回避されます。
    • 新しいデータ インデックスの 3 状態フロー (parsed -> indexing -> indexed): インデックス付けされるデータは検索層で自然に分離され、リコールされません。フロントエンドは読み取り専用の表示を提供し、バックエンドはデータの編集、削除、インデックスの変更のための安全な傍受を提供します。トレーニングに失敗したデータは、直接編集または削除をサポートします。
    • QA 分割 1 対多最適化: ソース データは最初の分割アイテムとして直接再利用され、残りのリーフ ノードは新しいプレドロップ データを作成し、キュー エントリ、データ書き込み、ソース タスクのクリーンアップが 1 つのデータベース トランザクションに収束されます。
    • 知識ベース モデルの切り替えと同義語再構築の最適化: インデックス付けされたデータ (indexed) の再構築のみをトリガーし、インデックス付けされるデータは再構築チェーンに参加しません。変更されていないベクトル データはシノニムの再構築中に自動的に再利用されるため、再計算のオーバーヘッドが大幅に削減されます。
    • 洗練されたトレーニング進行状況ダッシュボード: トレーニング ポップアップ ウィンドウは、処理モード (ベクター、QA など) ごとに現在のステージのトレーニング進行状況の表示をサポートし、トレーニング エラーの表示と再試行エクスペリエンスを最適化します。
  2. ナレッジ ベースとファイル リストの検索は、現在のディレクトリとサブツリーへの制限をサポートします: ナレッジ ベース リストまたはファイル コレクション リストで指定されたディレクトリ内で検索する場合、範囲は自動的に現在のパス自体とすべてのサブフォルダーの下のコンテンツに制限され、ヒット結果はタイルで表示されます。ルート ディレクトリの下を検索すると、コンテンツ全体が取得されます。最下位層では、効率的なメモリ バケット化とレベル順序トラバーサルが使用され、ループ形成と最大深さ/ノード数切り捨て保護が含まれます。

⚙️ 最適化

  1. コア コンソールと管理ページをクライアント側レンダリング (CSR) に移行し、浅いルーティングを有効にします。エージェント、スキル、MCP、システム ツール、テンプレート マーケット、評価などのワークベンチ ページ、アカウント センター モジュール、管理者の背景、および価格設定ページはすべてクライアント側レンダリングに移行され、完全な SSR ラウンドトリップ リクエストとページ切り替え時の白い画面の再レンダリングが回避され、対話型応答の速度が大幅に向上します。
  2. 国際化 (i18n) リソース読み込みパフォーマンスの最適化: クライアント言語パッケージをプリロード用に 1 つのチャンクにパッケージ化し、安全な変換フック (useSafeTranslation) を均一に使用し、冗長な名前空間の非同期ネットワーク要求を削除し、初期化オーバーヘッドを削減し、ハイドレーションちらつきを排除します。
  3. 非同期タスク キュー (BullMQ) 障害保持ポリシーの最適化: 共有 BullMQ キューとワーカーのデフォルト設定を抽出し、時間ごとの有効期限から最新 10,000 アイテムの保持まで、すべてのバックグラウンド タスク (アプリケーションの削除、ナレッジ ベースの削除、ナレッジ ベースの同期、評価、S3 ファイルのクリーンアップ、スキルの作成/削除、チームの削除、商用バージョンのアカウントのログアウト) の失敗したタスクの保持ポリシーを統合します。 (removeOnFail: { count: 10000 }) を数量別に設定し、一律 5000 ミリ秒を採用します。指数バックオフ再試行により、例外発生時の失敗履歴レコードの早期損失が防止され、タスクのトラブルシューティングとリプレイの回復が容易になります。
  4. システム モデルのステータス検出とアラームの最適化: モデルの健全性ステータスの検出が最大再試行回数に達し、すべて失敗した場合、エラー メッセージの先頭にモデル名が自動的に含まれるため、アラーム通知および監視プラットフォームで障害のあるモデルを視覚的に特定しやすくなります。
  5. 数値ローカライゼーション単位フォーマットのラウンドの最適化: 小数点以下 2 桁に丸めると次の単位に正確に達する場合に、より高いレベルの単位 (例: 100,000,1M) を使用して formatNumberWithUnit が正しく修正されました (例: 99,999,999 丸めで 10000 万、999,999 丸めで 1000K)。
  6. 知識ベースでのマルチチャンネルリコール検索中に異なるピクチャを誤って削除する問題: フュージョン重複除去中に正規化されたテキストと元のピクチャ imageId を結合して、同じまたは空の説明を持つ異なるピクチャが完全に保持されるようにします。
  7. filename* に破損したエンコーディングが含まれている場合、ファイル ダウンロード ヘッダー解析 (parseContentDispositionFilename) が解析に失敗します。ダウンロードされたファイル名が失われないように、通常の filename パラメータに安全にフォールバックします。

🐛 修正

  1. ワークフロー条件判定機能 (If/Else) の「含む/含まない」条件で文字列以外の値が異常に判定される問題を修正しました。実行時に数値やブール値などの文字列以外の値が型変数に入力される場合、文字列以外の値が直接 false を返すことを防ぐため、文字列に変換してからマッチングを実行すると、「含まない」条件が常に true となり、処理分岐が間違った方向に進むことになります。
  2. ワークフロー条件ジャジャ (If/Else) の「通常」条件が文字列以外の値のエラーを報告する問題を修正しました。文字列以外の値が入力されると、照合する前に自動的にテキストに変換されました。参照変数を通常のパターンとして使用した場合に文字列以外の値が TypeError を引き起こす問題が修正され、空のパターンが厳密に不一致と判断されました。また、条件入力ボックスの通常の携帯電話番号にバックスラッシュがない問題により、不正な通常エラーが発生しました。
  3. オープン ソース バージョンで管理者メニュー表示の問題が発生し、ライセンスがアクティベートされない問題 (#7929) を修正しました。ルーティング ホワイトリストを使用して管理者ナビゲーション メニュー項目を厳密にフィルタリングし、ライセンスがない場合にホワイトリスト以外のサブ項目 (未承認のアプリケーション テンプレートなど) がサイドバーに表示されるのを防ぎます。
  4. システム ツールで [プラグイン マーケットからインストール] をクリックしたときにジャンプ パスが正しくない問題を修正しました。正しい管理者プラグイン マーケット ルート /config/tool/marketplace を復元し、対応するページ レイアウトを改善しました。
  5. ナレッジベースリストをスクロールするときに初期ロードスケルトン画面がトリガーされ、ロードが繰り返される問題を修正しました。また、メンバー情報同期機能 (addSourceMember) では、関連付けられたメンバーが存在しないか退会した場合、リストの長さがページング ロジックと一致するように退会情報がバックフィルされ、ページ ジャンプやデータの欠落が回避されます。
  6. チャット入力ガイドワードカウントインターフェイスで権限検証が欠落している問題を修正しました。countTotalインターフェイスのアプリケーション読み取り権限検証が完了し、権限のないメンバーはガイドワードの検出または読み取りを禁止されます。
  7. 隠しアプリのチームメンバー間の権限分割が緩い問題を修正しました。同じチームの通常のメンバーはアプリケーションの読み取り専用権限と会話権限のみを持ち、デフォルトではアプリケーションのチャットログ権限を持ちません。ログはチーム管理者のみが公開されます。
  8. Markdown 画像構文を解析する際の宛先アドレスとオプションのタイトルの間の混同の問題を修正しました。CommonMark の仕様に厳密に従い、画像の宛先とタイトルを分離し、山かっこで囲まれた URL と複数行のタイトルをサポートします。ナレッジ ベースの画像を転送し、代替説明を埋め戻すときに、元の宛先アドレスの形式とタイトルを保持して、画像リンクの損傷や解析の切り詰めを回避します。
  9. リクエストで pageSize が省略され、offset=0 の正しい識別をサポートすると、ユニバーサル ページング パラメーター パーサー (parsePaginationRequest) が offset または pageNum を失う問題を修正します。

🛠️ コードの最適化

  1. ClientRouteReadyGate ルート ガード コンポーネントと useRequiredQueryParam フックを追加して、クライアント レンダリング ページのルーティング パラメーターの準備ができていない場合に状態インターセプトとポップアップ ウィンドウの初期化タイミングを一元的に処理し、競合状態を排除します。
  2. チーム メンバー管理ロジックのリファクタリング: メンバー編集ポップアップ ウィンドウを開く前に完全なメンバー情報を取得し、一部の情報が読み込まれていないときに保存されることによるデータの上書きを回避します。

FastGPT v4.17.2

Highlights

  • Knowledge-base training pipeline rebuilt around early persistence (#7861) — Parsing, image import, and backup/template import now write visible rows immediately under a single dataId, with vectors/index written back to that same row after training. A new tri-state flow (parsed → indexing → indexed) keeps pending data out of retrieval and lets the backend reject edits/deletes/index changes until indexing completes; failed-training rows become directly editable or deletable. This removes the long-standing "no data during training" and orphan-row problems — but adopters with custom scripts that assume data appears only after training, or that mutate rows freely, must account for the new state gates. QA splitting also reuses the source row as the first child and wraps enqueue/write/cleanup in one DB transaction.

  • Two manual, ordered migration scripts are required — 20261008_migrate_chunk_training converts legacy chunk-training jobs to the new row-linked model, and 20261009_migrate_dataset_rebuild_status (dependent on the first) folds old rebuilding flags into the new indexStatus scheme. Both are non-blocking, admin-triggered tasks, but you must stop all old App/Pro instances and let stale task leases expire before running them. Skip or reverse the order and historical datasets stay stuck in transitional states with inconsistent recall — this is the main operational risk of the upgrade.

  • Dashboard moves to CSR with shallow routing (#7829, plus i18n chunking) — Agent, skill, MCP, system-tool, template-market, evaluation, account, and admin pages are now client-rendered, eliminating full SSR round-trips and white-screen re-renders on navigation; language packs are bundled into one preloaded chunk to kill hydration flicker. The flip side for anyone extending the UI: route-param readiness is now gated by ClientRouteReadyGate / useRequiredQueryParam, so custom pages that read query params synchronously can hit races.

  • Failed-job retention policy changed (#7907) — All BullMQ-backed tasks (app/dataset/team deletion, sync, eval, S3 cleanup, skill ops, account closure) now keep the newest 10,000 failures (removeOnFail: { count: 10000 }) instead of expiring by time, with a shared 5000 ms exponential-backoff retry config. Better for debugging and replay after incidents, but ops teams should note that failure stores no longer age out and will grow until the count cap.

  • Workflow If/Else fixes that can change live branch behavior (#7924, #7903) — "contains/not contains" and "regex" previously coerced non-string values poorly: non-strings returned false outright (making "not contains" always true) or threw TypeError on regex. Values are now stringified first, empty patterns count as non-match, and the editor's broken sample phone regex was corrected. Workflows relying on the old buggy outcomes may route differently after upgrade, so re-check any branch that fed numbers/booleans into text conditions.

  • Permission and platform hardening (#7929, #7926, #7920) — Admin menus are now filtered by a route whitelist without a License (no more leaked app-template entries), the input-guide countTotal endpoint requires app read permission, and hidden-app regular members lose chat-log access (admins only). The default STT model also migrates to gpt-transcribe, so transcription behavior/output may shift. Expect members who previously saw logs or guide counts to lose them.

No breaking API changes in this release.

🚀 新增内容

  1. 知识库数据提前落库与训练链路重构：
    • 解析分块、图片导入及备份/模板导入在内容解析完成后立即落库为可见数据行，全流程绑定唯一 dataId；训练完成后直接把向量与索引写回同一条数据，彻底避免长训练周期中无数据、训练中断残留孤儿数据的问题。
    • 新增数据索引三态流转（parsed -> indexing -> indexed）：待索引数据在检索层天然隔离不被召回，前端提供只读查看，后端对编辑、删除数据及修改索引提供安全拦截；训练失败数据支持直接编辑或删除。
    • QA 拆分一对多优化：源数据直接复用为首条拆分项，其余叶子节点新建预落库数据，入队、数据写入与源任务清理收敛在单数据库事务中。
    • 知识库模型切换与同义词重建优化：仅对已完成索引（indexed）的数据触发重建，待索引数据不参与重建链；同义词重建时自动复用未变更的向量数据，大幅降低重算开销。
    • 训练进度精细化看板：训练弹窗支持按处理模式（Vector、QA 等）分类展示当前阶段的训练进度，优化训练错误查看与重试体验。
  2. 知识库与文件列表搜索支持限定在当前目录及子树：在知识库列表或文件集合列表指定目录下搜索时，范围自动限制为当前路径自身及其全部子文件夹下的内容，命中结果平铺展示；在根目录下搜索则保持检索全量内容。底层采用高效内存分桶与层序遍历，并包含成环与最大深度/节点数截断保护。

⚙️ 优化

  1. 核心控制台与管理页面迁移至客户端渲染（CSR）并启用浅路由（shallow routing）：将智能体、技能、MCP、系统工具、模板市场、评测等工作台页面，账号中心各模块，管理员后台以及定价页全面迁移为客户端渲染，避免页面切换时的完整 SSR 往返请求与白屏重渲染，显著提升交互响应速度。
  2. 国际化（i18n）资源加载性能优化：将客户端语言包打包为单一 chunk 预加载，统一采用安全翻译 hook（useSafeTranslation），移除冗余的 namespace 异步网络请求，减少初始化开销并消除水合闪烁。
  3. 异步任务队列（BullMQ）失败保留策略优化：提取共享的 BullMQ 队列与 Worker 默认配置，将所有后台任务（应用删除、知识库删除、知识库同步、评测、S3 文件清理、技能创建/删除、团队删除及商业版账号注销）的失败任务保留策略统一由按时间过期改为按数量保留最新 10,000 条（removeOnFail: { count: 10000 }），并统一采用 5000ms 指数退避重试，防止突发异常时历史失败记录过早丢失，便于任务排查与重放恢复。
  4. 系统模型状态探测告警优化：当模型健康状态探测达到最大重试次数全部失败时，错误信息开头自动附带模型名称，便于在告警通知与监控平台中直观识别故障模型。
  5. 数字本土化单位格式化进位优化：修复 formatNumberWithUnit 在四舍五入到两位小数后正好达到下一单位时（如 99,999,999 进位到 10000 万、999,999 进位到 1000K），正确使用更高一级的单位（如 1 亿、1M）。
  6. 知识库多路召回检索去重时误删不同图片的问题：在融合去重时结合归一化文本与原始图片 imageId，确保描述相同或为空的不同图片均被完整保留。
  7. 文件下载 Header 解析（parseContentDispositionFilename）在 filename* 包含损坏编码时解析失败的问题，安全回退到常规 filename 参数，避免下载文件名丢失。

🐛 修复

  1. 修复工作流条件判断器（If/Else）「包含/不包含」条件对非字符串值判断异常的问题：针对 any 类型变量在运行时输入数字、布尔等非字符串值的情况，先转为字符串再进行匹配，避免非字符串值直接返回 false 导致「不包含」条件恒为真、流程分支误走向。
  2. 修复工作流条件判断器（If/Else）「正则」条件对非字符串值报错的问题：输入非字符串值时自动转换为文本后再匹配；修复引用变量作为正则模式时非字符串值导致 TypeError 的问题，对空模式严格判定为不匹配；并修复条件输入框中示例手机号正则丢失反斜杠导致非法正则报错的问题。
  3. 修复开源版与未激活 License 状态下管理员菜单展示问题（#7929）：使用路由白名单严格过滤管理员导航菜单项，防止非白名单子项（如未授权的应用模板）在无 License 时暴露在侧边栏中。
  4. 修复系统工具点击「从插件市场安装」跳转路径错误的问题：恢复正确的管理员插件市场路由 /config/tool/marketplace，并完善对应页面布局。
  5. 修复知识库列表滚动翻页时触发初始加载骨架屏导致重复加载的问题；并在成员信息同步函数（addSourceMember）中，当关联成员不存在或已离职时回填离职兜底信息，保证列表长度与分页逻辑一致，避免跳页或遗漏数据。
  6. 修复聊天输入引导词计数接口权限校验缺失的问题：为 countTotal 接口补全应用读权限校验，未授权成员禁止探测或读取引导词。
  7. 修复隐藏应用（Hidden App）同团队成员权限划分不严格的问题：同团队普通成员仅具备应用只读与对话权限，不再默认附带应用聊天日志权限，日志仅对团队管理员开放。
  8. 修复 Markdown 图片语法解析时目的地址与可选标题混淆的问题：严格遵循 CommonMark 规范分离图片 destination 与 title，支持尖括号包裹的 URL 与多行标题；知识库图片转存与 alt 描述回填时保留原有的目的地址格式与标题，避免图片链接损坏或解析截断。
  9. 修复通用分页参数解析器（parsePaginationRequest）在请求省略 pageSize 时丢失 offset 或 pageNum 的问题，并支持正确识别 offset=0。

🛠️ 代码优化

  1. 新增 ClientRouteReadyGate 路由守卫组件与 useRequiredQueryParam hook，集中处理客户端渲染页面路由参数未就绪时的状态拦截与弹窗初始化时序，消除竞态问题。
  2. 团队成员管理逻辑重构：在打开编辑成员弹窗前先拉取完整成员信息，避免部分信息未加载时保存导致数据覆盖。
