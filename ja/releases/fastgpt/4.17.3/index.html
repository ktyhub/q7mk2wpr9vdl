#FastGPT v4.17.3

アップグレード ガイド

構成の変更

  • ソース コードからデプロイされた Node.js バージョンは ^22.23.4 || ^24.22.1 || ^26.12.1 を満たす必要があります。アップグレードする前に、動作環境がこの範囲を満たしていることを確認してください。
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED は引き続きデフォルトで false になります。有効にすると、新しいチームのデフォルトの全メンバー グループに、アプリケーション、スキル、ナレッジ ベースを作成する権限だけでなく、API キーの作成権限も付与されます。既存のチームには、追加の権限が自動的に付与されません。
  • エージェント サンドボックスのアクティブ インスタンスの合計上限が、AGENT_SANDBOX_MAX を通じて設定されるように変更され、デフォルト値は 100 です。クォータはアプリケーション セッションとスキル編集間で共有されます。オリジナルの AGENT_SANDBOX_MAX_EDIT_DEBUG は使用されなくなりました。単一チームの上限を設定するための AGENT_SANDBOX_MAX_PER_TEAM を追加しました。デフォルトでは制限はありません。製品版管理コンソールのクォータ設定は、環境変数よりも優先されます。
  • OpenSandbox は AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR と AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR を追加します。デフォルト値は 1 で、値は 1 以上である必要があります。これは、Kubernetes が実行中で、OpenSandbox サーバーが v0.2.1 以上である場合にのみ有効になります。リソースの予約は減りますが、リソースの上限は変わりません。新しく作成または再構築されたサンドボックスにのみ影響します。 ・製品版管理コンソールでは「最大同時ベクトル取得数」(systemEnv.vectorRecallConcurrency)が追加され、0～1000まで設定可能となりました。デフォルト値の 0 は制限がないことを意味します。正の数値を指定すると、すべてのサービス インスタンスとすべてのベクター ライブラリの共有呼び出しの同時実行が制限されます。オープン ソース バージョンではこの制限が有効になっておらず、対応する環境変数がありません。
  • スキル、エージェント、およびワークフロー支援によって生成された操作の詳細エントリを表示するかどうかを制御するための AUXILIARY_GENERATION_SHOW_RUN_DETAIL (デフォルトは false) を追加しました。
  • App Market のデフォルト アドレス (MARKETPLACE_URL) は https://v3.marketplace.fastgpt.cn に更新され、明示的に構成されたカスタム アドレスは引き続き元の値を使用します。

アップグレードスクリプト

システムは最初に必要な起動タスクとその前提条件となる依存関係チェーンを完了し、次に各アプリ インスタンスがモデルを再読み込みしてビジネスを開始します。次に、次の 3 つの新しいタスクがバックグラウンドで自動的に実行され、共有クラスター内で最大 3 つの同時クォータが設定されます。失敗しても、依存関係のないタスクはブロックされません。管理ページで結果を確認し、失敗したデータを修復して再試行できます。

  • バックフィル サンドボックス インスタンスのチーム所属 (20261009_backfill_agent_sandbox_team_id): ソース アプリケーションまたはチーム クォータ統計のスキルに基づいて、履歴インスタンスのチーム所属を完了します。ソースが削除された孤立レコードはスキップされ、カウントされます。
  • ディレクトリの祖先パスのバックフィル (20261022_backfill_folder_ancestor_ids): アプリケーション、ツール、ナレッジ ベースのディレクトリ パスを再構築し、非フォルダー リソースの残りのフィールドをクリーンアップします。他の種類のディレクトリ ツリーの直下にぶら下がっているフォルダーは、このチームのルート ディレクトリに移動され、古い親の継承権限がクリアされます。上位レベルのクロスツリー祖先パスは境界で切り詰められます。親の欠落、クロスチーム、ループなどの例外レコードは失敗したアイテムとして保持され、修復後に再試行されます。
  • システム モデルの価格を百万単位に移行 (20261025_token_prices_per_million): 過去のシステム モデルの価格を変換して pricing に書き込み、古いフィールドの元の値を保持し、すでに正当な pricing を持つモデルをスキップします。チーム モデルは移行に参加しません。

互換性に関する説明

  • root アクティベーションとパスワード: DEFAULT_ROOT_PSW を削除すると、起動時に既存の root パスワードが上書きされなくなります。新しい root の初期パスワードは 123456 です。初めてログインするときは、新しいパスワードを設定する必要があります。履歴ルート status が保存されていない場合は、元のパスワードを使用してログインし、アクティベーションを完了する必要があります。毎日のパスワード変更はアカウント情報ページで実行されます。パスワードを忘れた場合は、root パスワード リセット スクリプトを使用して、新しいパスワードを明示的に指定します。
  • モデル価格単位: LLM は pricing.tiers を使用し、他のモデルは pricing.unitPrice を使用します。トークン単価とラダー maxInputTokens 上限が 100 万トークンに変更され、TTS が 100 万文字に変更され、STT は 60 秒ごとのままで、単価は小数点第 2 位までに維持されます。アップグレード後、バックグラウンド移行が成功したことを確認し、システム モデルの価格を確認します。 pricing に移行されていないシステム モデルは一時的に無料として扱われ、チーム モデルは無料です。
  • ワークフロー オーケストレーションの検証: キャンバス、デバッグ、および補助生成は均一に [配置ルール] (/guide/build/workflow/rules) に従います。純粋なシリアル ループバック、クロスツール プロセス接続、および同じツール入口を共有する複数の呼び出しノードは禁止されており、有効な条件出口によって制御されるリフローは許可されています。ツールのサブプロセスは呼び出し元の上流を読み取ることができますが、呼び出し元自体が生成していない出力を参照することはできません。古いワークフローでは既存の接続が保持され、下書きを保存できます。ルールに準拠していない接続は、デバッグおよび公開する前に修正する必要があります。
  • ナレッジ ベース管理権限: ナレッジ ベースの基本情報、モデル構成、およびファイル名、タグ、無効ステータスなどの独自の属性を変更するには、管理可能な (manage) 権限が必要です。コンテンツ操作では、元の編集権限が引き続き使用されます。ファイルを移動するときに属性を変更するには、ファイルに対する管理者権限も必要です。
  • ナレッジ ベースのエクスポート: /api/core/dataset/exportAll は 1 つのナレッジ ベースのみをサポートしており、ディレクトリのエクスポートはベースごとにリクエストする必要があります。ファイルレベルのアクセス許可が有効になっている場合、現在のメンバーが読み取り可能なファイルのみがエクスポートされます。
  • 会話ファイル タイプ: 添付ファイル カテゴリに document および unknown を追加しました。古い file 入力パラメータと履歴レコードは引き続き互換性があり、ファイル名、リンク、および応答情報によって分類されます。カスタム クライアントは新しい分類と互換性があり、文書の判定に file のみを使用する必要はありません。
  • ページングとエラー応答: 一般的なページングは​​、500 を超える pageSize を 500 として扱います。一部のインターフェイスにはまだ小さい制限があります。 offset と pageNum が同時に渡されると、offset=0 を含めて offset が最初に使用され、不正なオフセットはページ番号にロールバックされません。ユーザー構成エラーとして識別される API 要求は HTTP 400 を返すため、アクセス側はそれを失敗応答として処理する必要があります。

🚀 新しいコンテンツ

[ワークフローとエージェント] 製品版では、[ワークフロー支援生成] (https://doc.fastgpt.io/zh-CN/guide/build/workflow/assisted-generation) が追加されます。自然言語を通じてソリューションを確認した後、同じエージェントが継続的に構築、検証、修復し、候補バージョンを配信します。中断後は、保存されたダイアログ、計画、タスクのステータスに基づいて続行できます。候補バージョン カードは、好き嫌いのフィードバックをサポートしており、保存して公開する前に手動で適用、確認、デバッグする必要があります。使用する場合は、アプリケーションの編集権限があり、補助生成およびサンドボックス機能を有効にする必要があります。
  2. [ワークフローとエージェント] ユーザー選択ノードとフォームの単一選択および複数選択フィールドは変数参照の動的オプションをサポートしており、動的オプションが空の場合は明確なエラーが返されます。
  3. [ワークフローとエージェント] パスワード入力、ツール キー、および HTTP/MCP 認証リクエスト ヘッダーは変数参照をサポートしており、アップストリーム ノードまたはアプリケーション変数を使用して実行時に資格情報を提供できます。
  4. [モデルと請求] チーム メンバーが専用の AI モデルとチャネルを構成し、リソースの分離、認証、AI プロキシの統合を改善できるようにサポートします。チーム所有者は、無効な言語を置き換えたり、音声を再生したり、ナレッジ ベース、アプリケーション、履歴バージョンをカバーするモデル参照をバッチで再配置したり、処理統計を表示したりできます。 Null 値、動的参照モデル、およびインデックス モデルは置換に参加しません。
  5. [チームと権限] 新しいアカウントをアクティブ化し、初回パスワードを設定するプロセスでは、root はアカウント情報ページでパスワードを変更できます。アクティベーションまたはパスワード変更後、現在のログイン セッションは保持され、他のセッションはクリアされます。商用バージョンの管理コンソールでは、すべて、アクティブ、アクティブ化保留中、無効、およびログアウト ステータスごとにユーザーをフィルタリングできます。
  6. [チームと権限] アプリケーション、ツール、およびナレッジベースのフォルダーを作成するときに、権限を継承するかどうかを選択できます。リソース ディレクトリ ナビゲーションは、親パスに沿った承認されたサブリソースへのアクセスをサポートします。親ディレクトリはナビゲーションの入り口としてのみ使用され、追加の管理権限は付与されません。
  7. [チームと権限] チーム監査は、ナレッジ ベースのトレーニング タスクの再試行、削除、インデックス モデルの切り替え、リソース回復権限の継承およびその他の操作記録を補足し、リソース パスとモデル識別子を保持し、イベント タイプによるフィルタリングをサポートします。
  8. [会話エクスペリエンス] メンバー、アプリケーション、セッションごとに分離された、入力下書きと正常にアップロードされた添付ファイル参照の回復をサポートします。現在のブラウザ タブには、最後の編集から 1 時間の間、最大 10 件の下書きが保持され、投稿が正式に受け入れられるとクリアされます。
  9. [会話エクスペリエンス] Markdown は、限定的な HTML レンダリングをサポートし、リッチ テキスト コンポーネントの対話を改善します。
  10. [ツールとチャネル] システム プラグインの名前、概要、サブツール、パラメーター、キー、スキーマ、および README は多言語表示をサポートしています。既存のワークフロー ノードとエージェント固定ツールは、追加時に言語スナップショットを保持します。
  11. [ツールとチャネル] MCP と外部チャネルのユニファイド アクセス チームのダイアログ QPM 制限、超過した返品クォータと待機時間、重複排除カウント後の外部チャネル。会話をブロックする障害を回避するために、依存するサービスが異常な場合はログを記録し、チェックをスキップします。

  13. [システムおよび運用および保守] リクエスト ヘッダー x-fastgpt-profile: 1 によって有効になるパフォーマンス収集を追加しました。これは、フェーズ時間の消費、Mongo の運用およびプロセスの指標を要約し、OTel レポートをサポートします。
  14. [ナレッジベースとドキュメント] [OXR 自己展開アクセス ガイド] (https://doc.fastgpt.io/zh-CN/self-host/custom-models/oxr) を追加して、カスタム PDF 解析構成とソース ファイル名の追跡を補足し、展開と解析問題の特定を容易にしました。

⚙️ 最適化

  1. [ワークフローとエージェント] ワークフローとエージェントの補助生成は、ローカル セッション キャッシュがない場合にサーバー上に最新のレコードを復元します。復元が失敗した場合は、再試行できます。新しいセッションを作成すると、現在のセッションが切り替わるだけで、履歴とワークフロー バージョンのアーカイブが保持されます。
  2. [ワークフローとエージェント] オンデマンドのサンドボックス準備の生成を支援し、計画またはキャンバスのベースラインが大幅に変更されたときに再確認します。サンドボックスが失われた場合、保存されたコンテキストに基づいてサンドボックスを再構築します。候補バージョンを適用する場合、使用可能なシステム キーの関連付けが優先され、使用可能なキーのないツールはアクティブ化されたままになります。
  3. [ワークフローとエージェント] ワークフロー候補バージョンの適用ステータスはカードと最上部のプロンプトの間で同期され、有効期限が切れていないバージョンを再度適用できます。実際のアプリケーションが完了すると、エージェント設定は成功を求めるプロンプトを表示します。
  4. [ワークフローとエージェント] モデルのネイティブ ツール呼び出しフローの互換性を向上させ、並列パラメーターの混乱、重複または遅延した名前、functions. プレフィックスおよび空のパラメーターを処理します。ツール呼び出しステータスで終了するが有効なツールがない場合は、明らかにエラーを返します。
  5. [ワークフローとエージェント] ノード サイズとキャンバス レイアウトを統一し、問題分類のデフォルトのコピーがインターフェイス言語とともに表示されます。プロンプト ワード エディターは、入力ガイダンスとシステムおよびカスタム変数セレクターを補足します。
  6. [ナレッジベースとファイル] API ファイル ライブラリの同期では、最初にディレクトリのプルと差分検証が完了し、次にレベル、名前、およびアクセス許可の継承がバッチで更新されます。リモート要求が失敗すると、誤って削除されることを避けるために、現在のラウンドの同期が中止されます。サービス アドレスは、過去のネイキッド ドメイン名と互換性があり、デフォルトで https:// となります。
  7. [ナレッジベースとファイル] 同義語機能が有効になっている場合、検索結果はヒットする可能性のある参照標準語にマッピングされ、再配置では元のテキストと同義語の標準化されたテキストが考慮され、元のテキストを書き換えることなく高いスコアが維持されます。有効になっていない場合は、元の動作が維持されます。
  8. [ナレッジベースとファイル] AI 会話、エージェント、ツール、外部チャネルの添付ファイル分類を統一し、ドキュメント、不明なファイルと画像、オーディオとビデオを区別し、古いファイル タイプと互換性を持たせます。文書が解析リンクに入り、不明なファイルも文書読み取りツールで読み取ることができることを明確にします。接尾辞のないリンクは、応答ヘッダーと限定されたコンテンツからの検出をサポートし、ファイル名と要求内キャッシュを再利用します。
  9. [ナレッジベースとファイル] シンプルなアプリケーション、エージェント、ワークフローのラベルフィルタリングの相互作用を統合し、変数選択を最適化し、ステータスとポップアップウィンドウのスクロールを有効にします。ナレッジ ベースを切り替えて無効なカスタム ラベル条件をクリアし、手動入力が閉じられたときに構成された条件を保持します。ワークフロー ラベル フィルタリングは、構造例とホバー指示を補足します。
  10. [ナレッジベースとファイル] listV2 は、withFileCount を通じてオンデマンドですべてのレベルの非ディレクトリ ファイルの数を取得できます。アプリケーション、スキル、ナレッジ ベースは ID による部分更新をサポートし、ページングとスクロールの位置は権限の調整後も保持されます。ユニバーサル ページングが非配列リストを受信すると、元の有効なデータを保持してロードを終了します。
  11. [ナレッジ ベースとファイル] エージェントは、再配置前に候補スナップショットを補足するためにログを取得し、ナレッジ ベース検索ノードと連携して retrievalResults を使用します。実際の再配置が RETRIEVAL_RESULTS_LIMIT > 0 の場合にのみ記録され、デフォルトでは記録されません。
  12. [会話エクスペリエンス] 再試行と編集では、削除に成功した後のローカル履歴のトリミングが優先され、追加の履歴リクエストが減ります。ページが欠落している場合に更新を保持し、切り取る前に期限切れのページング応答を破棄します。

FastGPT v4.17.3

Highlights

  • Runtime and upgrade path — Source deployments now require Node.js ^22.23.4 || ^24.22.1 || ^26.12.1 (images use 24.22.1). DEFAULT_ROOT_PSW is removed: existing root passwords are no longer overwritten, new roots start with 123456 and must set a password on first login, and legacy roots without status must activate with their existing password. Three background migrations backfill sandbox team ownership, folder ancestors and pricing; retry failures before trusting quotas, ACL paths or billing. SeekDB data now survives container restart/recreation (#7942).
  • Billing units change — LLM pricing.tiers and other models’ pricing.unitPrice now express prices per million tokens; tier maxInputTokens is also in millions, TTS is per million characters, and STT remains per 60 seconds, rounded to two decimals. Migration preserves legacy fields and skips valid pricing; team models are excluded. Audit migrated system-model prices—unmigrated system models and team models are treated as free.
  • Workflow/Agent authoring — Pro adds resumable assisted workflow generation, but candidates still require manual application, inspection and debugging before save/publish; it needs edit rights plus assisted-generation and sandbox capabilities. Variables can now supply select options, passwords, tool secrets and HTTP/MCP auth headers. Canvas, debug and assistance share stricter validation: pure serial loops, cross-tool edges and multiple callers sharing one tool entry are rejected, while valid conditional backflow is allowed. Existing invalid drafts remain editable but must be corrected before debug/publish.
  • Permissions and tenant isolation — Team members can configure isolated models/channels with AI Proxy integration (#7895), and owners can bulk-replace invalid model references. Dataset metadata, model and file-attribute changes—including file moves—now require manage; content operations retain edit. App test/debug paths enforce edit rights before node execution and run system tools as the actual member (#7927). Cross-team PG/OpenGauss recall and cross-dataset image access are fixed; folder inheritance is opt-in at creation (#7966).
  • Sandbox capacity controls — Replace AGENT_SANDBOX_MAX_EDIT_DEBUG with AGENT_SANDBOX_MAX (default 100), shared by app sessions and skill editing; AGENT_SANDBOX_MAX_PER_TEAM adds a per-team cap and defaults to unlimited. Kubernetes with OpenSandbox Server ≥ v0.2.1 supports CPU/memory overcommit factors (default and minimum 1), lowering reservations without raising hard limits and affecting only new/rebuilt sandboxes. Pro admin quota settings override environment variables (#7917).
  • API and integration contracts — Pagination caps pageSize at 500 (some endpoints lower), prefers offset over pageNum even for offset=0, and no longer falls back on invalid offsets; recognized user-config errors return HTTP 400. /api/core/dataset/exportAll is single-dataset and respects readable-file ACLs. Chat attachments add document/unknown while retaining legacy file, so clients must stop using file alone to detect documents. Pro streamed/raw responses survive NextAPI (#7971); MCP and external channels now share team QPM limits, with dependency failures failing open.

升级指南

配置变更

  • 源码部署的 Node.js 版本须满足 ^22.23.4 || ^24.22.1 || ^26.12.1，升级前请先确认运行环境符合该范围。
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED 仍默认 false；启用时，新团队默认全员组除应用、技能和知识库创建权限外，还会获得 API Key 创建权限，已有团队不自动补授。
  • Agent 沙盒活跃实例总上限改为通过 AGENT_SANDBOX_MAX 配置，默认 100，应用会话与技能编辑共用额度；原 AGENT_SANDBOX_MAX_EDIT_DEBUG 不再使用。新增 AGENT_SANDBOX_MAX_PER_TEAM 设置单团队上限，默认不限制。商业版管理台中的配额配置优先于环境变量。
  • OpenSandbox 新增 AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR 与 AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR，默认均为 1，取值须不小于 1。仅在 Kubernetes 运行态且 OpenSandbox Server 不低于 v0.2.1 时生效，降低资源预留但保持资源上限不变，仅影响新建或重建的沙盒。
  • 商业版管理台新增「向量检索最大并发数」（systemEnv.vectorRecallConcurrency），允许配置 0–1000，默认 0 表示不限制。正数限制所有服务实例、所有向量库的共享召回并发；开源版不启用此限制，无对应环境变量。
  • 新增 AUXILIARY_GENERATION_SHOW_RUN_DETAIL，默认 false，控制技能、Agent 和工作流辅助生成的运行详情入口是否展示。
  • 应用市场默认地址（MARKETPLACE_URL）更新为 https://v3.marketplace.fastgpt.cn，显式配置的自定义地址继续使用原值。
