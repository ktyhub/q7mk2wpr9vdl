rust 1.91.0

マイナー 公開日2025年10月30日 出典rust-lang/rust English original

#rust 1.91.0 <a id="1.91.0-Language"></a>

言語

  • 下位のパターン バインディングは記述された順序で、基本的なドロップ順序はプライマリ バインディングの順序に基づいています
  • sysv64、win64、efiapi、および aapcs ABI の C スタイルの可変個引数関数の宣言を安定化。これにより、これらの ABI は C ABI と一致します。可変個引数関数は extern ブロックで宣言できますが、定義はできません。
  • ローカル変数からのダングリングポインターを警告する dangling_pointers_from_locals lint を追加
  • semicolon_in_expressions_from_macros を警告から拒否にアップグレード
  • LoongArch32インラインアセンブリの安定化
  • 整数からポインターへの変換に対してデフォルトで警告する integer_to_ptr_transmutes lint を追加
  • sse4aおよびtbmのターゲット機能の安定化
  • target_env = "macabi" および target_env = "sim" cfgs を追加 を、同じ値を持つ target_abi cfgs の代替として追加します。 <a id="1.91.0-Compiler"></a>

コンパイラ

  • 決して到達しない as キャストについては到達不能として警告しない <a id="1.91.0-Platform-Support"></a>

プラットフォームのサポート

  • ホスト ツールを使用して aarch64-pc-windows-gnullvm および x86_64-pc-windows-gnullvm を Tier 2 に昇格します。 注: llvm-tools と MSI インストーラーはありませんが、将来のリリースで追加される予定です。
  • aarch64-pc-windows-msvc を Tier 1 に昇格 Rust の階層型プラットフォーム サポートの詳細については、Rust の プラットフォーム サポート ページ を参照してください。 <a id="1.91.0-Libraries"></a>

ライブラリ

  • パニックメッセージにスレッドIDを出力
  • core::panic::Location::file 戻り型の過度に制限された有効期間を修正
  • std::cmp の min / max/ minmax の _by() バリアントのパラメーター順序を保証
  • Clone および Eq の特性に関する仮定を文書化する
  • std::thread: スレッド スタック サイズの設定に失敗した場合にエラーを返す これにより、標準ライブラリ内でパニックが発生していました。 <a id="1.91.0-Stabilized-APIs"></a>

貨物

  • 🎉 build.build-dir を安定させます。この構成は、中間ビルド アーティファクトが保存されるディレクトリを設定します。これらのアーティファクトは、ビルド プロセス中に Cargo および rustc によって生成されます。通常、エンド ユーザーはそれらを操作する必要はありません。build-dir 内のレイアウトは実装の詳細であり、予告なく変更される可能性があります。 (構成ドキュメント) (ビルド キャッシュ ドキュメント) #15833 #15840
  • --target フラグと build.target 設定はリテラル "host-tuple" 文字列を受け取ることができるようになり、これは内部でホスト マシンのターゲット トリプルに置き換えられます。 #15838 #16003 #16032 <a id="1.91.0-Rustdoc"></a>

Rustdoc

  • 検索結果で、ドキュメント エイリアスを同じ名前の非エイリアス項目よりも低くランク付けします
  • 生のポインタが参照のような型ベースの検索で機能するようになりました。つまり、*const u8 -> などを検索できるようになり、さらに、生のポインターを取得または返す関数の署名が検索結果に適切に表示されるようになりました。 <a id="1.91.0-Compatibility-Notes"></a>

互換性に関する注意事項

  • コルーチン キャプチャがドロップライブであることを常に要求する
  • Apple: cc とリンクするときは常に SDK ルートを渡し、それを SDKROOT 環境変数経由で渡します。これにより、Xcode 内で実行されている ZZPH100​​ZZ のリンクの問題が修正されるはずです。 /usr/local/lib のライブラリは自動的にリンクされなくなる可能性があります。これに依存するクレートを開発または使用する場合は、build.rs スクリプトで cargo::rustc-link-search=/usr/local/lib を明示的に設定する必要があります。
  • TraitRef<AssocTy: ?Sized> のような、関連付けられたタイプの境界位置での緩和された境界は、正しく禁止されるようになりました
  • 同じ名前の手続き型マクロをシャドウする不安定な #[sanitize(xyz = "on|off")] 組み込み属性を追加
  • let-else で宣言されたバインディングに対してより寛容なドロップ チェッカーを修正
  • 属性を解析するときにより厳密になり、多くの無効な属性でエラーが発生します
    • 無効な #[should_panic] 属性に関するエラー
    • 無効な #[link] 属性に関するエラー
  • 名前解決ですべての非推奨の lint をデフォルトで拒否としてマークし、依存関係でもレポートします
  • セミコロン (;) で終わるまで展開される式位置の macro_rules! マクロの lint semicolon_in_expressions_from_macros は、デフォルトで拒否されるようになりました。これはすでにデフォルトで警告されており、依存関係でも警告する将来の互換性警告 (FCW) でした。この糸くずは将来的には重大なエラーになるでしょう。
  • 固有の impl 内のトレイト impl 修飾子 (unsafe、!、default など) は構文的に有効ではなくなりました
  • 依存関係における ill_formed_attribute_input の将来の破損の報告を開始
  • Rust Edition 2024 の if let 検査のマクロ pin!、format_args!、write!、および writeln! によって作成された一時スコープを制限します。 これは [Rust Edition 2024 の if let 一時スコープを制限します。] rules](https://doc.rust-lang.org/edition-guide/rust-2024/temporary-if-let-scope.html) をこれらの一時ファイルに追加します。以前は、エディションに関係なく、if 式を超えて存続する可能性がありました。
  • タプルのインデックス付け、タプル構造体のインデックス付け、および構造体のフィールド名の位置にある無効な数値リテラル接尾辞が正しく拒否されるようになりました
  • キーワード static でマークされたクロージャーは構文的に無効になりました
  • --cfg および --check-cfg 引数内のシェバンは許可されなくなりました
  • Rust 1.92 での一時的な寿命短縮のため、将来の非互換性リントを追加 貨物の互換性に関する注意事項:
  • build.build-dir が設定されている場合、cargo publish は最終ビルド アーティファクトとして .crate tarball を保持しなくなりました。これらの tarball は、以前は見落としがあったため含まれていましたが、現在は中間アーティファクトとして扱われます。 .crate tarball を最終成果物として取得するには、cargo package を使用します。将来のバージョンでは、この変更は build.build-dir に関係なく適用されます。 #15910
  • rustc の診断スタイルに合わせてカーゴ メッセージを調整します。これにより、Cargo メッセージで使用されるターミナルの色の一部が変更されます。 #15928
  • Cargo の build-dir の内部詳細 に依存するツールやプロジェクトは、build-dir のレイアウトを変更するユーザーには機能しない可能性があります。そうする場合は、特に将来的に build-dir のデフォルトの場所 (cargo#16147) を変更することを検討しているため、これらのケースを積極的にテストすることをお勧めします。 Cargo の内部詳細を移行できない場合は、build-dir (cargo#15010) のレイアウトを変更する準備をする際に、お客様のユースケースについて詳しく知りたいと考えています。 <a id="1.91.0-Internal-Changes"></a>

内部変更

これらの変更は、Rust のパブリック インターフェイスには影響しませんが、rustc および関連ツールのパフォーマンスや内部機能が大幅に向上します。

  • LLVM 21へのアップデート

rust 1.91.0

<a id="1.91.0-Language"></a>

Language

  • Lower pattern bindings in the order they're written and base drop order on primary bindings' order
  • Stabilize declaration of C-style variadic functions for sysv64, win64, efiapi, and aapcs ABIs. This brings these ABIs in line with the C ABI: variadic functions can be declared in extern blocks but not defined.
  • Add dangling_pointers_from_locals lint to warn against dangling pointers from local variables
  • Upgrade semicolon_in_expressions_from_macros from warn to deny
  • Stabilize LoongArch32 inline assembly
  • Add warn-by-default integer_to_ptr_transmutes lint against integer-to-pointer transmutes
  • Stabilize sse4a and tbm target features
  • Add target_env = "macabi" and target_env = "sim" cfgs as replacements for the target_abi cfgs with the same values.

<a id="1.91.0-Compiler"></a>

Compiler

  • Don't warn on never-to-any as casts as unreachable

<a id="1.91.0-Platform-Support"></a>

Platform Support

  • Promote aarch64-pc-windows-gnullvm and x86_64-pc-windows-gnullvm to Tier 2 with host tools. Note: llvm-tools and MSI installers are missing but will be added in future releases.
  • Promote aarch64-pc-windows-msvc to Tier 1

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.91.0-Libraries"></a>

Libraries

  • Print thread ID in panic message
  • Fix overly restrictive lifetime in core::panic::Location::file return type
  • Guarantee parameter order for _by() variants of min / max/ minmax in std::cmp
  • Document assumptions about Clone and Eq traits
  • std::thread: Return error if setting thread stack size fails This used to panic within the standard library.

<a id="1.91.0-Cargo"></a>

Cargo

  • 🎉 Stabilize build.build-dir. This config sets the directory where intermediate build artifacts are stored. These artifacts are produced by Cargo and rustc during the build process. End users usually won't need to interact with them, and the layout inside build-dir is an implementation detail that may change without notice. (config doc) (build cache doc) #15833 #15840
  • The --target flag and the build.target configuration can now take literal "host-tuple" string, which will internally be substituted by the host machine's target triple. #15838 #16003 #16032

<a id="1.91.0-Rustdoc"></a>

Rustdoc

  • In search results, rank doc aliases lower than non-alias items with the same name
  • Raw pointers now work in type-based search like references. This means you can now search for things like *const u8 ->, and additionally functions that take or return raw pointers will now display their signature properly in search results.

<a id="1.91.0-Compatibility-Notes"></a>

Compatibility Notes

  • Always require coroutine captures to be drop-live
  • Apple: Always pass SDK root when linking with cc, and pass it via SDKROOT env var. This should fix linking issues with rustc running inside Xcode. Libraries in /usr/local/lib may no longer be linked automatically, if you develop or use a crate that relies on this, you should explicitly set cargo::rustc-link-search=/usr/local/lib in a build.rs script.
  • Relaxed bounds in associated type bound position like in TraitRef<AssocTy: ?Sized> are now correctly forbidden
  • Add unstable #[sanitize(xyz = "on|off")] built-in attribute that shadows procedural macros with the same name
  • Fix the drop checker being more permissive for bindings declared with let-else
  • Be more strict when parsing attributes, erroring on many invalid attributes
    • Error on invalid #[should_panic] attributes
    • Error on invalid #[link] attributes
  • Mark all deprecation lints in name resolution as deny-by-default and also report in dependencies
  • The lint semicolon_in_expressions_from_macros, for macro_rules! macros in expression position that expand to end in a semicolon (;), is now deny-by-default. It was already warn-by-default, and a future compatibility warning (FCW) that warned even in dependencies. This lint will become a hard error in the future.
  • Trait impl modifiers (e.g., unsafe, !, default) in inherent impls are no longer syntactically valid
  • Start reporting future breakage for ill_formed_attribute_input in dependencies
  • Restrict the scope of temporaries created by the macros pin!, format_args!, write!, and writeln! in if let scrutinees in Rust Edition 2024. This applies Rust Edition 2024's if let temporary scope rules to these temporaries, which previously could live past the if expression regardless of Edition.
  • Invalid numeric literal suffixes in tuple indexing, tuple struct indexing, and struct field name positions are now correctly rejected
  • Closures marked with the keyword static are now syntactically invalid
  • Shebangs inside --cfg and --check-cfg arguments are no longer allowed
  • Add future incompatibility lint for temporary lifetime shortening in Rust 1.92

Cargo compatibility notes:

  • cargo publish no longer keeps .crate tarballs as final build artifacts when build.build-dir is set. These tarballs were previously included due to an oversight and are now treated as intermediate artifacts. To get .crate tarballs as final artifacts, use cargo package. In a future version, this change will apply regardless of build.build-dir. #15910
  • Adjust Cargo messages to match rustc diagnostic style. This changes some of the terminal colors used by Cargo messages. #15928
  • Tools and projects relying on the internal details of Cargo's build-dir may not work for users changing their build-dir layout. For those doing so, we'd recommend proactively testing these cases particularly as we are considering changing the default location of the build-dir in the future (cargo#16147). If you can't migrate off of Cargo's internal details, we'd like to learn more about your use case as we prepare to change the layout of the build-dir (cargo#15010).

<a id="1.91.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • Update to LLVM 21
