ECC v1.10.0

Highlights

  • Scope: hardening, not features — v1.10.0 is deliberately scoped to harness reliability, cross-platform compatibility, and operator ergonomics rather than new surface area. For adopters that makes this a low-risk "upgrade for stability" release: expect fewer harness failures and more consistent behavior across OSes, with little new API to learn. Treat it as a stability baseline before layering on more automation.
  • Install coordinates — Distribute via the npm package ecc-universal and reference the Claude marketplace/plugin as everything-claude-code@everything-claude-code. Pin these exact identifiers in install scripts and plugin manifests; the "universal" build name lines up with the stated cross-platform focus, so confirm your target platform is covered before standardizing.
  • Eval-driven quality work — The team explicitly says changes were validated through evaluations rather than ad hoc checks. The practical upside is behavioral consistency, but it also means agent/prompt output can shift even without an explicit "breaking" label — run your own regression tests against v1.9.0 outputs after upgrading.
  • Operator ergonomics changes to watch — Workflow and operator-facing improvements (configuration, invocation, day-to-day running) are the most likely area to alter your scripts or runbooks even in a stability release. Diff your operator config and command invocations against v1.9.0 as part of the upgrade; this is where hidden friction tends to surface.
  • Contributor surge, broad PR surface — An unusually large wave of first-time contributors landed across a wide PR range (roughly #548–#1054, including #649, #716, #952, #1042, #1054). That's strong community momentum, but a broad review surface is exactly where subtle regressions hide; the eval-driven emphasis is likely the intended guardrail. Scan the full v1.9.0…v1.10.0 diff, prioritizing PRs touching components you depend on.
  • Breaking changes — None documented in this release.
