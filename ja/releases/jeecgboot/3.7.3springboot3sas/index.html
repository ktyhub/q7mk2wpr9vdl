JeecgBoot v3.7.3springboot3sas

Highlights

  • Spring Boot 3 and JDK 17 baseline — This branch moves the platform to Spring Boot 3 and JDK 17, with matching JDK 17 Docker images (#5563, #7317). Adopters should validate runtime, build, and deployment configurations against this baseline before upgrading.
  • Shiro removed in favor of Spring Authorization Server — Authentication is reworked to support third-party login and Spring Authorization Server (#5819, #6243, #6646). Custom authentication, tenant handling, and permission checks need retesting; this is the most consequential architectural change in the release.
  • Updated token tooling and client compatibility — Adds token validation, client helper utilities, forced logout, and manual token generation (#5965, #6014). Shorter tokens improve compatibility with the main-branch frontend (#6899), but clients assuming the previous token format may need verification.
  • Security and authorization fixes — Removes authorization-denied exception stack traces and caches permission loading to reduce repeated lookups (#5995). Redis authentication-serialization handling is revised again after a revert (#7327, #7329, #7332); clear affected caches during rollout and verify session restoration.
  • Dependency and generation fixes — Fastjson moves to 2.0.43, Tomcat is replaced by Undertow (#5716), and Druid 1.2.22 compatibility fixes support the upgraded stack (#6081, #6091, #6092). Review container-specific configuration and JSON-library assumptions rather than treating this as a drop-in patch.
  • Operational and online-form reliability — Fixes cover WAR startup failures, WebSocket connections, online database synchronization and form loading, dashboard 401 responses, and Redis key scanning (#6182, #6194, #6199, #6878, #7564, #7950). The CVE-2023-6378 fix in #8007 is a specific reason to prioritize this release.

No breaking changes declared.
