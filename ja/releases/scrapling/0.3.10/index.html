v0.3.10 をスクラップする

多くの重要な変更と重大な変更が含まれるメンテナンス アップデート

  • エンコーディングが正しく宣言されていない Web ページを処理する、より良いアプローチを使用することですべてのエンコーディングの問題を解決しました (#110 #111 でそれを指摘してくれた @Kemsty2 の努力に感謝します)
  • 解決 v0.3 以降存在していたすべてのブラウザベースのフェッチャーで、セッション レベルのパラメーターをリクエスト レベルのパラメーターでオーバーライドする際の論理的な問題
  • 対話型 Web scraping シェルのショートカットの署名を修正しました。これにより、シェル内のショートカットのオートコンプリート エクスペリエンスが完璧になりました。この問題は v0.3 以降も発生しています。
  • Maxmind データベースのバージョンを強化しました。これにより、StealthyFetcher とそのセッション クラスの geoip 引数が改善されます。
  • 使用されているすべてのブラウザのバージョンを利用可能な最新のものに更新しました。
  • 速報 - すべてのフェッチャーは大規模なリファクタリングを行っており、その結果、コードを壊す可能性のある興味深いものがいくつか発生しました。
    1. スラップリング コードベースは約 750 行小さくなり、多くの変更が加えられたため、将来のメンテナンスが非常に簡単になり、使用するリソースが少し少なくなります。
    2. すべてのフェッチャーとそのセッション クラスの検証が大幅に高速になり、全体的な速度に反映されます。
    3. これを実現するために、すべてのフェッチャーは url 引数以外の標準引数を受け入れることができなくなりました。残りの引数はキーワード引数でなければならないため、何らかの理由でコードを実行する場合、コードは Fetcher.get('https://google.com', True) ではなく Fetcher.get('https://google.com', stealthy_headers=True) のようになる必要があります。
    4. v0.3 以降、ブラウザベースのフェッチャーとそのセッション クラスの厄介な違いは、リクエストごとにカスタム パーサー設定を渡すために使用される引数が custom_config と呼ばれるのに対し、セッション クラスでは selector_config という名前であったことです。このリファクタリングにより、コードを壊すことなく名前を selector_config に統一できるようになりました。そのため、メインの名前は custom_config 引数の下位互換性を持つ selector_config になりました。オートコンプリートのサポートは、selector_config 引数でのみ使用できます。
    5. また、これらすべてを実現するには、フェッチャー関数の型ヒントを動的に生成する必要がありました。そのため、IDE で適切なオートコンプリートが得られない場合は、最新バージョンを使用していることを確認してください。私たちはほぼすべての既知の IDE/エディタをテストしました。

また、すべてのベンチマーク テーブルを、すべての代替ライブラリの最新バージョンに対する現在の数値で更新しました。 🙏 継続的なテストとフィードバックに対して Discord コミュニティ に深く感謝します

Scrapling v0.3.10

Highlights

  • Keyword-only fetcher options — The fetcher refactor now allows only url as a positional argument. Convert calls such as Fetcher.get(url, True) to Fetcher.get(url, stealthy_headers=True); positional options will break.
  • Unified parser configuration — Use selector_config consistently across browser fetchers and session classes. custom_config remains supported as a backward-compatible alias, but only selector_config receives autocompletion support.
  • Session and request precedence fixed — Browser-based fetchers now apply request-level parameters over session defaults correctly. Re-test configurations that may have depended on the previous incorrect behavior.
  • IDE compatibility consideration — Fetcher signatures and type hints are now generated dynamically. If autocompletion or static analysis degrades after upgrading, update your IDE and language-server tooling.
  • Improved handling of undeclared encodings — A new decoding approach handles pages with missing or incorrect charset declarations, reducing garbled scraped content. This addresses the issues reported in #110 and fixed in #111.
  • Lower overhead and updated browser dependencies — The roughly 750-line refactor and faster validation target reduced resource usage and better fetcher performance. Embedded browser versions are also refreshed, while the updated MaxMind database should improve StealthyFetcher GeoIP behavior.

A maintenance update with many significant changes and possible breaking changes

  • Solved all encoding issues by using a better approach which will handle web pages where encoding is not correctly declared (Thanks to @Kemsty2's efforts for pointing that out in #110 #111 )
  • Solved a logical issue with overriding session-level parameters with request-level parameters in all browser-based fetchers that was present since v0.3
  • Fixed the signatures of the shortcuts in the interactive web scraping shell, which made a perfect autocompletion experience for the shortcuts in the shell. This issue has been present since v0.3 as well.
  • Pumped up the version for the Maxmind database, which will improve the geoip argument for StealthyFetcher and its session classes.
  • Updated all used browser versions to the latest available ones.
  • BREAKING - all fetchers had gone through a big refactor, which resulted in some interesting things that might break your code:
    1. Scrapling codebase is now smaller by ~750 lines and many changes which would make maintenance very much easier in the future and use a bit less resources.
    2. The validation for all fetchers and their session classes became much faster, which will reflect on their overall speed.
    3. To achieve this, now all fetchers can't accept standard arguments other than the url argument; the rest of the arguments must be keyword-arguments so your code must be like Fetcher.get('https://google.com', stealthy_headers=True) not Fetcher.get('https://google.com', True) if you were doing that for some reason!
    4. An annoying difference between browser-based fetchers and their session classes since v0.3 was that the argument used to pass custom parser settings per request was called custom_config, while it was named selector_config in the session classes. This refactor allowed us to unify the naming to selector_config without breaking your code, so the main one is now selector_config with backward compatibility for the custom_config argument. The autocompletion support will be available only for the selector_config argument.
    5. Also, to achieve all of this, we had to make the type hints of the fetchers' functions dynamically generated, so if you don't get a proper autocompletion in your IDE, make sure you are using a modern version of it. We have tested almost all known IDEs/editors.

We have also updated all benchmark tables with the current numbers against the latest versions of all alternative libraries.
