v0.4.5 をスクラップする

スパイダー開発者向けの 1 つの大きな生活の質を向上させる機能と、いくつかの重要な修正を含む集中アップデート 🎉

[!NOTE] 毎日のヒントやコツについては X でフォローしてください

🚀 新しいものと生活の質の変化

  • スパイダー開発モード: スパイダーの parse() ロジックを反復することは、実行のたびにターゲット サーバーを再ヒットすることを意味していました。これは遅くてノイズが多く、セレクターを検討している間にレート制限を受ける優れた方法です。新しい開発モードでは、最初の実行時にすべての応答がディスクにキャッシュされ、それ以降の実行ごとにディスクから再生されるため、コールバックを微調整して、ネットワーク リクエストを 1 つも作成せずに何度でも再実行できます。 1 つのクラス属性で有効にします。

    class MySpider(Spider):
    name = "my_spider"
    start_urls = ["https://example.com"]
    development_mode = True

    async def parse(self, response):
        yield {"title": response.css("title::text").get("")}

    キャッシュはデフォルトで .scrapling_cache/{spider.name}/ に存在し、development_cache_dir を使用してどこにでもリダイレクトできます。 2 つの新しい統計カウンター cache_hits および cache_misses を使用すると、キャッシュがどのように実行されたかを確認できます。キャッシュのリプレイは、download_delay、レート制限、およびブロックされたリクエストの再試行パスをバイパスするため、ディスクの許容範囲内で反復が高速になります。スパイダーを development_mode = True とともに出荷しないでください。これは開発ツールであり、運用キャッシュではありません。詳細については、ドキュメント を参照してください。

  • デフォルトでのより安全なリダイレクト: すべての HTTP フェッチャー、MCP サーバー、およびシェルで、follow_redirects がデフォルトで "safe" になるようになりました。リダイレクトは引き続き追跡されますが、内部/プライベート IP (ループバック、プライベート ネットワーク、リンクローカル) をターゲットとするリダイレクトは拒否されます。これにより、ユーザーが指定した URL を scraping するときに SSRF から保護されます。 follow_redirects="all" を渡して古い動作を取得するか、False を渡してリダイレクトを完全に無効にします。

🐛 バグ修正

  • 強制停止によってチェックポイントが失われることはなくなりました: crawldir が有効になっているスパイダーで Ctrl+C を 2 回押す (強制停止) と、チェックポイントの書き込みと競合していました。キャンセル スコープは、ピクルが終了する前にタスクを破棄し、paused=False を残し、前のチェックポイントを 削除するクリーンアップ パスをトリガーします。その結果、長いクロールを強制的に停止すると、保存しようとしていた進行状況がすべて失われる可能性がありました。エンジンは、cancel_scope.cancel() を呼び出す前にチェックポイントを書き込むようになりました。そのため、強制停止では常に最新の保留状態が保持されます。 @voidborne-d による #230。

🙏 継続的なテストとフィードバックに対してコミュニティに感謝します

Scrapling v0.4.5

Highlights

  • Spider development mode — Set development_mode = True on a Spider subclass and the first run caches every response to disk in .scrapling_cache/{spider.name}/ (relocatable via development_cache_dir); every later run replays from disk with zero network requests. Replay bypasses download_delay, rate limiting, and the blocked-request retry path, so selector/callback iteration is bounded by disk speed rather than politeness delays — and the new cache_hits/cache_misses stats confirm whether you're actually hitting the cache. The thing to watch: this is a development tool, not a production cache; shipping a spider with it left enabled serves stale responses indefinitely.

  • Safer redirect defaults (SSRF hardening) — follow_redirects now defaults to "safe" across all HTTP fetchers, the MCP server, and the shell: redirects still get followed, but any hop resolving to loopback, private, or link-local addresses is rejected. That closes an SSRF hole when crawling user-supplied URLs, but it is a genuine behavior change if you legitimately scrape internal hosts. Restore the old behavior with follow_redirects="all", or pass False to disable redirects entirely.

  • Force-stop no longer destroys your checkpoint (#230) — Fixed a race where a double Ctrl+C tore down the task via cancel_scope.cancel() before the checkpoint pickle finished, leaving paused=False and letting the cleanup path delete the previous checkpoint — so a hard stop could wipe the exact progress you were trying to preserve. The engine now flushes the checkpoint before cancelling, so force-stops retain the latest pending state. Credit @voidborne-d, PR #230; most relevant to long-running crawls using crawldir.

  • Breaking changes — None in this release; no migration steps required.

A focused update with one big quality-of-life feature for spider developers and a couple of important fixes 🎉

[!NOTE] Follow us on X for daily tips and tricks

🚀 New Stuff and quality of life changes

  • Spider Development Mode: Iterating on a spider's parse() logic used to mean re-hitting the target servers on every run, which is slow, noisy, and a great way to get rate-limited while you're still figuring out your selectors. The new development mode caches every response to disk on the first run and replays them from disk on every subsequent run, so you can tweak your callbacks and re-run as many times as you want without making a single network request. Enable it with one class attribute:

    class MySpider(Spider):
    name = "my_spider"
    start_urls = ["https://example.com"]
    development_mode = True

    async def parse(self, response):
        yield {"title": response.css("title::text").get("")}

    The cache lives in .scrapling_cache/{spider.name}/ by default and can be redirected anywhere with development_cache_dir. Two new stat counters, cache_hits and cache_misses, let you see how the cache performed. Cache replay bypasses download_delay, rate limiting, and the blocked-request retry path so iteration is as fast as the disk allows. Don't ship a spider with development_mode = True -- it's a development tool, not a production cache. See the docs for the full story.

  • Safer redirects by default: follow_redirects now defaults to "safe" across all HTTP fetchers, the MCP server, and the shell. Redirects are still followed, but ones targeting internal/private IPs (loopback, private networks, link-local) are rejected. This protects you from SSRF when scraping user-supplied URLs. Pass follow_redirects="all" to get the old behavior, or False to disable redirects entirely.

🐛 Bug Fixes

  • Force-stop no longer loses your checkpoint: Pressing Ctrl+C twice (force-stop) on a spider with crawldir enabled used to race against the checkpoint write -- the cancel scope would tear down the task before the pickle finished, leaving paused=False and triggering the cleanup path that deletes the previous checkpoint. The result was that force-stopping a long crawl could lose all the progress you were trying to save. The engine now writes the checkpoint before calling cancel_scope.cancel(), so a force-stop always preserves the latest pending state. By @voidborne-d in #230.
