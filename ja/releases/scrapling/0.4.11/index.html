v0.4.11 をスクラップする

最初のプラットフォーム スパイダー テンプレート、高速パーサー、重要な修正を含む確実なアップデート 🎉

[!NOTE] 毎日のヒントやコツについては X でフォローしてください

🚀 新しいものと生活の質の変化

  • 最初のプラットフォーム スパイダー テンプレートである ShopifySpider を追加しました! Web サイトの HTML に触れることなく、JSON API を通じて Shopify を利用したストアからすべての商品を抽出します。それをサブクラス化し、ストアのドメインを設定すれば完了です (ドキュメント を確認してください) 
    from scrapling.spiders import ShopifySpiderclass MyStore(ShopifySpider):    target_website = "example.com"result = MyStore().start()
  • --executable-path を CLI ブラウザ コマンドに追加。 scrapling extract fetch と scrapling extract stealthy-fetch はどちらもカスタムの Chromium 互換ブラウザ実行可能ファイルを受け入れるようになり、オプションが渡されない場合は SCRAPLING_EXECUTABLE_PATH 環境変数にフォールバックし、MCP サーバーと完全に同等になります (#371 を解決) 
    scrapling extract fetch "https://example.com" page.html --executable-path "/path/to/chromium"

🤖 生活の質が変わります

  • first_match が有効 (デフォルト) の場合、検索が最初の一致で停止するように要素を遅延ラップすることにより、find_by_text と find_by_regex を最大 2 倍高速化しました (#370 の @yetval により)
  • すべてのライブラリの最新バージョンに対する新しい数値でベンチマークを更新しました。
  • 投稿ルールを更新

🐛 バグ修正

  • **制御文字を含むページでエラー All strings must be XML compatible が発生してクラッシュする MCP サーバーのフェッチ ツールを修正しました。@yetval による #368 (修正 #366)

🙏 継続的なテストとフィードバックに対してコミュニティに感謝します

Scrapling v0.4.11

Highlights

  • ShopifySpider platform template — v0.4.11 introduces the first "platform spider": subclass scrapling.spiders.ShopifySpider, set target_website to a store domain, and start() pulls every product through Shopify's JSON API instead of scraping HTML. For adopters this means structured, schema-stable extraction that survives storefront redesigns, and it signals a new extension pattern — expect more platform-specific spiders to follow. It is Shopify-only, so custom or non-Shopify catalogs still need a hand-rolled spider.
  • --executable-path reaches the CLI — Both scrapling extract fetch and stealthy-fetch accept a custom Chromium-compatible binary and fall back to the SCRAPLING_EXECUTABLE_PATH env var when omitted (#371), closing the gap with the MCP server. This lets you pin a specific or patched Chromium for reproducible stealth fetches without mutating global install paths. The change is opt-in: existing setups behave identically unless you set the flag or env var.
  • Faster text/regex matching — find_by_text and find_by_regex are up to ~2x faster when first_match is on (the default), by lazily wrapping elements and stopping at the first hit (#370, @yetval). It is a transparent performance win for the common case with no API change; the optimization is scoped to the default first_match=True path, while callers that disable it retain the full-scan behavior.
  • MCP fetch tools handle control characters — Pages containing non-XML-safe control characters previously crashed fetch calls with All strings must be XML compatible (#366); fixed in #368 (@yetval). If your agent pipelines hit intermittent MCP fetch failures on messy or binary-ish pages, this release removes that failure mode with no configuration changes.
  • Fresh benchmark numbers — The parser benchmarks were re-run against current versions of competing libraries, so published performance claims now reflect the present landscape. Worth re-checking before making a parser choice based on older figures.

No breaking changes in this release.

A solid update bringing the first platform spider template, a faster parser, and important fixes 🎉

🚀 New Stuff and quality of life changes

  • Added ShopifySpider, the first platform spider template! Extract every product from any Shopify-powered store through its JSON API without touching the website's HTML. Subclass it, set the store's domain, and you are done (Check the docs) 
    from scrapling.spiders import ShopifySpiderclass MyStore(ShopifySpider):    target_website = "example.com"result = MyStore().start()
  • Added --executable-path to the CLI browser commands. Both scrapling extract fetch and scrapling extract stealthy-fetch now accept a custom Chromium-compatible browser executable, and fall back to the SCRAPLING_EXECUTABLE_PATH environment variable when the option isn't passed, bringing full parity with the MCP server (Solves #371) 
    scrapling extract fetch "https://example.com" page.html --executable-path "/path/to/chromium"

🤖 Quality of life changes

  • Made find_by_text and find_by_regex up to ~2x faster when first_match is enabled (the default) by wrapping elements lazily so the search stops at the first match, by @yetval in #370
  • Updated the benchmarks with the new numbers against the latest versions of all libraries.
  • Updated contribution rules

🐛 Bug Fixes

  • Fixed the MCP server's fetch tools crashing on pages containing control characters with the error All strings must be XML compatible, by @yetval in #368 (Fixes #366)
