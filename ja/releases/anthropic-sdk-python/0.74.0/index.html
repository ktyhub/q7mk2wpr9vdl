anthropic-sdk-python v0.74.0

Highlights

  • Microsoft Foundry integration — Adds AnthropicFoundry and AsyncAnthropicFoundry, with resource-based endpoint construction, ANTHROPIC_FOUNDRY_* environment defaults, API-key or Microsoft Entra ID token-provider authentication, and sync/async streaming. Use these clients instead of Anthropic/AsyncAnthropic; note that Foundry does not support the models endpoint or message batches, so audit dependencies on those features.
  • Corrected memory and tool-use flow — #1049 scopes assistant_content to each message and stores the assistant turn before tool results. This prevents content leaking across iterations and preserves the required assistant → tool-result ordering when adapting the memory example for multi-step agents.
  • Windows-compatible file uploads — File collection now emits POSIX-style paths, fixing beta.skills.create failures where Windows backslashes triggered a 400 “invalid characters” response (#1051). Developers uploading Skills through the _files APIs no longer need to normalize directory paths themselves.
  • Simpler snapshot maintenance — Removal of the external-snapshot wrapper and documentation of the refresh process (#1040) make contract fixtures easier for contributors to update; this is maintainer-facing rather than a runtime behavior change.

No breaking changes are listed.
