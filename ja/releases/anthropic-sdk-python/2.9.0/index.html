anthropic-sdk-python v2.9.0

anthropic-sdk-python v2.9.0

機能

  • api: ソース コードとエラー コードを RBAC ロール読み取りエンドポイントに追加します
  • api: クロード タグ バンドルの命令を設定する更新バンドルを追加し、バンドルに命令を返します

バグ修正

  • 資格情報: Python 3.12 以前を使用して Windows に資格情報ファイルを書き込みます
  • ツール: ファイル ツールを制限するときにディレクトリ名を正確に比較し、Windows でパスをアップロードします
  • tools: ダングリング シンボリックリンクを通過するファイル ツール パスを完全に解決します。
  • ツール: エージェント ツールセットの grep ツール内の ripgrep 構成ファイルを無視します。
  • ツール: 既存のスキル ディレクトリを置き換えるダウンロードまたは抽出が失敗した場合に、既存のスキル ディレクトリを保持します。
  • ツール: セッション スレッドが終了したときにセッション ツール ランナーの max_idle カウントダウンを実行し続ける 再接続後にランナーがセッションのイベント履歴の読み取りに失敗した場合でも、その後イベント ストリームに到着する終了によって、次のアイドル状態または読み取りの成功までカウントダウンがキャンセルされます。
  • ツール: /memories の外側を指すシンボリックリンクをリストから除外します
  • tools: エージェント ツールセットの grep ツールの絶対 PATH エントリでのみ ripgrep を検索します。 このツールは、相対または空の PATH エントリから、または Windows では現在のディレクトリから rg を実行しなくなりました。 Windows では、rg.exe が検索されるため、rg.cmd、rg.bat、または rg.com は使用されなくなりました。 PATH 上に他に rg がない場合、ツールは組み込みの検索を使用します。
  • tools: エージェント ツールセットのファイル ツールが書き込むことができるディレクトリ内の rg を渡します grep は、名前の大文字小文字に関係なく、workdir または allowed_roots 内のどこかに解決される rg を渡します。 PATH の次の rg を使用するか、存在しない場合は組み込みの検索を使用します。ホスト上のすべての rg を保持する workdir (/ など) では、すべての検索が組み込み検索になります。 rg は、bash のシェルのように、プロセスの ANTHROPIC_* 変数を取得しなくなります。
  • ツール: 検証されたパス経由でのみメモリ ファイルを読み取ります
  • tools: grep ツールの組み込み検索では通常のファイルのみを読み取ります grep の組み込み検索は、ripgrep と同様に、FIFO またはディレクトリ内のデバイスを通過します。これを読み取ると、検索とそれに伴うイベント ループが永久にブロックされる可能性があります。
  • tools: 終了したセッションに対して、EnvironmentWorker がツールを実行するのを停止します。 セッションが終了した場合、ワーカーはセッションを取得した直後、スキルまたはメモリ ストアをダウンロードする前に作業項目を強制停止するようになりました。このようなセッションに対して SessionMemoryError が発生しなくなりました。 API は、アーカイブされたセッションを terminated として報告します。
  • tools: ripgrep がインストールされていない場合は、CPU 時間が 30 秒経過した後に grep ツールを停止します。
  • tools: セッション ツール ランナーが終了したセッション スレッドのツール呼び出しを実行しないようにします。 また、ランナーは、拒否された呼び出し (confirmation="deny") や所有していないツールへの呼び出しなど、これらの呼び出しを放棄しなくなりました。 1 つの例外は、スレッドの終了時にツールがすでに実行されている呼び出しです。ランナーは posted=False で呼び出しを返し、結果をポストしません。

雑用

  • api: 古いベータ版ヘッダー値は非推奨です API は引き続きこれらの値を受け入れますが、後のリリースでは SDK からこれらの値が削除されます。リクエストから prompt-caching-2024-07-31、pdfs-2024-09-25、token-counting-2024-11-01、token-efficient-tools-2025-02-19、extended-cache-ttl-2025-04-11、cache-diagnosis-2026-04-07、ce-user-management-2026-07-13 を削除します。 files-api-2025-04-14 および skills-2025-10-02 はベータ応答形状を選択するため、これらを削除する前に、ファイル API およびスキル移行ガイドに従ってください。 C# では、AnthropicBeta 列挙型のメンバーに新しい番号が付けられるため、以前の SDK バージョンに対してコンパイルされたコードは、再構築するまで、エラーなしで別のベータ値を送信します。
  • api: バッチ リクエストでの古いベータ ヘッダーの送信を停止します beta.messages.batches は、API が必要としない message-batches-2024-09-24 を送信しなくなりました。 client がデフォルトの anthropic-beta ヘッダーを設定している場合、これらのリクエストはそのヘッダーを送信するようになりますが、一部の SDK では古い値に置き換えられます。 API は引き続き古い値を受け入れます。自分で設定した場合は、削除してください。後のリリースでは、SDK から削除されます。
  • docs: ワークスペース名のサンプル値を追加します
  • ドキュメント: 自動許可ポリシーがツール呼び出しを拒否する場合を明確にする
  • ドキュメント: 外部キーをアタッチできるワークスペースを明確にする
  • ドキュメント: コーディネーター タイプよりも multiagent_20261001 を推奨します
  • ドキュメント: プラグインの読み取り時にorganization_idが必要な場合を言う
  • テスト: アイドル状態のテスト ワーカーにキューに入れられたテストを実行させます

anthropic-sdk-python v2.9.0

Highlights

  • New API surface: RBAC role provenance and Tag Bundle instructions — Role read endpoints now return source and error codes, so you can tell where a role originated and why a read failed without separate introspection. A new Update Bundle operation lets you set a Claude Tag Bundle's instructions, and Bundle reads now return them — the first time this text is round-trippable programmatically, which matters if you manage tag bundles via automation rather than the console.

  • Beta header deprecations — start removing them now — Seven values are deprecated: prompt-caching-2024-07-31, pdfs-2024-09-25, token-counting-2024-11-01, token-efficient-tools-2025-02-19, extended-cache-ttl-2025-04-11, cache-diagnosis-2026-04-07, ce-user-management-2026-07-13. The API still accepts them, but a later SDK release drops them. Do not blanket-delete yet: files-api-2025-04-14 and skills-2025-10-02 still select the beta response shapes, so follow the Files API and Skills migration guides before removing those two, or your response schemas will change underneath you.

  • C# consumers face a silent enum renumbering — AnthropicBeta members have new numeric values. Assemblies compiled against an older SDK keep emitting the old numbers with no error until rebuilt, so upgrading the package without recompiling can quietly change which beta a request targets. Treat this as a rebuild-and-redeploy item, not a drop-in package swap — there is no runtime signal that anything changed.

  • Batch requests stop sending message-batches-2024-09-24 — beta.messages.batches drops the legacy header the API never needed. The subtle effect: if your client configures a default anthropic-beta header, it now actually reaches batch requests where some SDKs previously overwrote it with the old value. The API still tolerates the old value, but remove it from your own config — it too is scheduled for removal from the SDKs.

  • Agent toolset hardening closes execution and hang vectors — The grep tool now resolves rg only from absolute PATH entries (no relative or empty entries, no Windows current directory, and on Windows only rg.exe — .cmd/.bat/.com no longer count), ignores ripgrep config files, and skips any rg located inside workdir or allowed_roots regardless of case, falling back to the next rg or the built-in search. It also stops passing ANTHROPIC_* variables to rg, reads only regular files (FIFOs and devices are skipped so they can't block the event loop forever), and caps the built-in search at 30s of CPU. File paths are fully resolved through dangling symlinks, Windows path confinement compares directory names exactly, symlinks pointing outside /memories are excluded from listings, and memory reads go only through the validated path. Expect searches to fall back to the built-in engine if you relied on a locally installed or writable rg; on Windows, Python 3.12-and-earlier users also get a credentials-file write fix.

  • Terminated sessions stop doing work; memory and skill state are preserved — EnvironmentWorker now force-stops a terminated session's work item immediately after fetching the session, before downloading skills or memory stores, and no longer raises SessionMemoryError (archived sessions surface as terminated). The session tool runner no longer yields calls from a terminated thread — including denied calls and calls to tools it doesn't own — with the one exception of an already-running tool, which is yielded with posted=False and no result posted. The max_idle countdown also keeps ticking when a thread terminates, including after a reconnect event-history read failure. A failed skill download/extraction no longer wipes the existing skill directory. For long-lived agents this removes zombie tool execution, stale idle timeouts, and a destructive skill-update failure mode.

Features

  • api: add source and error codes to the RBAC Role read endpoints
  • api: add Update Bundle, which sets a Claude Tag Bundle's instructions, and return instructions on Bundle

Bug Fixes

  • credentials: write the credentials file on Windows with Python 3.12 and earlier

  • tools: compare directory names exactly when confining file tool and upload paths on Windows

  • tools: fully resolve file tool paths that pass through a dangling symlink

  • tools: ignore ripgrep config files in the agent toolset's grep tool

  • tools: keep an existing skill directory when the download or extraction that would replace it fails

  • tools: keep the session tool runner's max_idle countdown running when a session thread terminates

    If the runner fails to read the session's event history after a reconnect, a termination that then arrives on the event stream still cancels the countdown, until the next idle or successful read.

  • tools: leave symlinks that point outside /memories out of listings

  • tools: look for ripgrep only in absolute PATH entries in the agent toolset's grep tool

    The tool no longer runs an rg from a relative or empty PATH entry or, on Windows, from the current directory. On Windows it looks for rg.exe, so an rg.cmd, rg.bat or rg.com is no longer used. With no other rg on PATH, the tool uses its built-in search.

  • tools: pass over an rg inside the directories the agent toolset's file tools can write

    grep passes over an rg that resolves to somewhere inside workdir or allowed_roots, whatever the letter case of the names. It uses the next rg on PATH, or the built-in search when there is none. With a workdir that holds every rg on the host, such as /, every search is a built-in search. rg no longer gets the ANTHROPIC_* variables of the process, like the shell of bash.

  • tools: read memory files only through the path that was validated

  • tools: read only regular files in the grep tool's built-in search

    The built-in search of grep passes over a FIFO or a device in the directory it walks, as ripgrep does. Reading one could block the search, and the event loop with it, forever.

  • tools: stop EnvironmentWorker from running tools for a terminated session

    For a terminated session, the worker now force-stops the work item right after it retrieves the session, before it downloads skills or memory stores. It no longer raises SessionMemoryError for such a session. The API reports an archived session as terminated.

  • tools: stop the grep tool after 30 seconds of CPU time when ripgrep is not installed

  • tools: stop the session tool runner from running the tool calls of a terminated session thread

    The runner also no longer yields these calls, including a denied call (confirmation="deny") and a call to a tool that it does not own. The one exception is a call whose tool is already running when the thread terminates: the runner yields it with posted=False and posts no result.

Chores

  • api: deprecate old beta header values

    The API still accepts these values, but a later release removes them from the SDKs. Delete prompt-caching-2024-07-31, pdfs-2024-09-25, token-counting-2024-11-01, token-efficient-tools-2025-02-19, extended-cache-ttl-2025-04-11, cache-diagnosis-2026-04-07 and ce-user-management-2026-07-13 from your requests. files-api-2025-04-14 and skills-2025-10-02 select the beta response shapes, so follow the Files API and Skills migration guides before you delete them.

    In C#, the AnthropicBeta enum's members have new numbers, so code compiled against an earlier SDK version sends a different beta value, with no error, until you rebuild it.

  • api: stop sending an old beta header on batch requests

    beta.messages.batches no longer sends message-batches-2024-09-24, which the API doesn't need. If your client sets a default anthropic-beta header, these requests now send it, where in some SDKs the old value replaced it. The API still accepts the old value. If you set it yourself, delete it: a later release removes it from the SDKs.

  • docs: add an example value for the workspace name

  • docs: clarify when the auto permission policy denies a tool call

  • docs: clarify which workspaces an external key can be attached to

  • docs: recommend multiagent_20261001 over the coordinator type

  • docs: say when organization_id is required on plugin reads

  • tests: let idle test workers take queued tests
