QwenPaw v2.3.0.post1

Highlights

  • Plugin-first agent architecture — Third-party agents are extracted out of core into plugins (#8426), with channels gaining plugin updates, version guards, and an official marketplace plus versioned OSS publishing (#8699, #8800). If you maintain custom agents out-of-tree, restructure them as plugins; enablement now retries recovery first (#8721), and PR CI no longer enforces plugin version bumps (#8765).

  • Sandbox and auth hardening — Inline Office COM automation is guarded before any unsandboxed fallback (#8048), sandbox ACLs are never written on volume roots (#8018), password login defers to deployment access controls (#8679), and terminal status checks are gated on auth (#8660). Deployments relying on permissive fallbacks should audit their configuration.

  • Tool-schema and provider compatibility — Boolean additionalProperties are now preserved in tool schemas (#8607), which matters for strict tool-call validators; AnthropicProvider presets expose request_headers (#8729), and the Whisper transcription model name is configurable (#8052) if you pin a specific deployment.

  • Channel and scheduler reliability — Fixes cover WeChat receipts carrying only message_id (#8715) and false bot conflicts with workspace isolation (#8720), Feishu reconnect supervision (#8749) and percent-encoded filenames (#8753), WeCom bodyless upload acks (#8767), plus cron reload deadlocks and runtime directory context for channel workers (#8772, #8692). Expect fewer dropped messages and stuck workers.

  • Install, desktop, and bundle — Console's initial bundle shrinks and the dev recovery proxy is fixed (#8761); early startup errors persist and surface as native dialogs (#8697); Windows upgrades clean bundled runtimes (#8769); venv seeding honors the selected PyPI mirror (#8704). Channels now accept QwenPaw 2.3.0.post1 as the minimum (#8795), with Docker build and empty-chat fixes in #8801.

  • Compatibility — No breaking changes in this release.
