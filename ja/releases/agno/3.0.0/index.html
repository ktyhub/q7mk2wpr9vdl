agno v3.0.0

メジャー 公開日2026年8月24日 出典agno-agi/agno English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#アグノv3.0.0 ⚠️ 最新リリース。 v3.0 がトラフィックを処理する前に、データベースの移行が必要です。まず、v3 移行ガイド を読み、すべての変更について完全な v3.0 Changelog を確認してください。

新機能

  • ツール結果のオフロード: Agent(offload_tool_results=True) / Team(...) は、16,000 文字を超えるツール結果を AgentFS に書き込み、メッセージ内に短いエンベロープ (プレビュー、サイズ、result_id) を残します。エージェントは read_result / search_result (+ 非同期) を取得して残りを取得します。書き込みパスにモデル呼び出しがありません。 ResultStore(threshold_chars=..., ttl_seconds=...) 経由でチューニングします。 (#9436、#9684)
  • メディア オフロード: エージェント/チーム/ワークフロー上の media_storage=S3MediaStorage(bucket=...) は、永続化の前に画像、音声、ビデオ、ファイルをローカル ディスク、S3、または GCS にアップロードします。行は、base64 ではなく小さな MediaReference を保持します (113 KB JPEG は約 151,000 文字から 2,897 文字に減少します)。スキーマの変更はありません。 (#9340) ドキュメント
  • コードモード: CodeMode(tools=[...]) は、セッション全体にわたって持続する 1 つのプログラム可能な IPython カーネルの幅広いツール スキーマを交換します。モデルは Python を書き込み、ツールを待機可能なハンドルとして呼び出し、トランスクリプトをラウンドトリップすることなくツール (変数、ループ、ヘルパー) を構成します。
  • FinanceTools: 交換可能なデータ プロバイダーを備えた 1 つの統合財務ツールキット。
  • RampRouter モデル: Ramp Router の新しいモデル プロバイダー (router.com)。
  • SuperGrok OAuth: xAI モデルのデバイスコード認証。

データベース

  • 実行は独自のテーブルを取得します: 各実行は、実際の列 (session_id、run_type、agent_id、team_id、workflow_id、user_id、parent_run_id、status、run_index) + JSON ペイロードを含む agno_runs の行です。セッション書き込み増幅を O(N²) から O(N) に引き上げ、DynamoDB/Firestore アイテムサイズの上限を取り除きます。 session.get_messages()、get_chat_history()、db.get_session()、および AgentOS セッション ルートは変更されません (読み取り時に再接続が実行されます)。 (#8350)
    • 直接実行 API: db.get_run()、db.get_runs(session_id=..., status=..., limit=..., page=...)、db.upsert_run()、db.delete_run()、db.delete_runs() (同期 + 非同期)。 db.get_session(runs_limit=N) および db.get_sessions(include_runs=False)。 (#8350)
    • 1 行の移行: MigrationManager(db).up() は実行ストアを作成し、12 個の同期 + 4 個の非同期バックエンド上で非破壊的かつべき等にレガシー実行をコピーします。移行されていない DB は引き続き機能します (レガシー BLOB とマージ実行テーブルを読み取ります)。すべてのアダプターで追跡されるスキーマのバージョン。 (#8350)
    • タイプされた古い DB エラー: MigrationRequiredError / SchemaMismatchError 両方の救済策の名前を入力します。 AgentOS は、JSON 本体に error_id: "migration_required_error" を搭載しています。 (#9669、#9631)
    • 3 つの新しいテーブル: agno_runs、agno_jobs (耐久性バックグラウンド キュー)、agno_tool_results (オフロード インデックス) - すべて自動作成されます。

ユーザーごとの分離

  • セッションを超えて、メトリクス、スケジュール、評価、ナレッジ、コンポーネント、エンティティ メモリ、および 17 のベクトル データベースに拡張します。メトリクスはユーザーごとに 1 日ごとに集計されます。所有されていないコンポーネント/ナレッジは共有される (全員が読み取り可能、管理者が編集可能) ため、分離を有効にしても、分離前の構成要素は使用されません。 (#8245、#8262)

AgentOS と Studio

  • 永続的なバックグラウンド実行: AgentOS(queue=QueueConfig(durable=True)) — 受け入れられた実行は、クラッシュ/再起動/デプロイ後に存続するコミットされた行であり、任意のレプリカによって実行されます。制限された同時実行数（デフォルトは 32、AGNO_BACKGROUND_MAX_CONCURRENCY）、キューに入れられている間にキャンセル可能、Idempotency-Key 重複排除、キューがいっぱいの場合は 429。キュー REST サーフェス (GET /queue/jobs、.../{job_id}、POST .../requeue、GET /queue/stats)。 Redisはオプションコーディネートです、決して真実ではありません。 (#9079、#9504)
  • スタジオ 3.0 — 管理カタログ: create_* は、publish_component まで誰にも提供されないドラフトを作成します。比較および設定ガード (タイプ付き 409)、廃棄済み削除、アーカイブ/復元、依存追跡。 StudioTools は、約 31 個のツールにわたって機械可読エンベロープ ({ok, status, data, error{...}, warnings}) を返します。 (#9604)

ツール

  • MiniMax ビデオ生成ツール。 (#9529)
  • ツールキットには、AgentOS がツールを参照するために使用する安定した id が含まれるようになりました。

モデルの更新

  • Cerebras / CerebrasOpenAI のデフォルトは gpt-oss-120b (以前は llama-4-scout-17b-16e-instruct) です。 (#9244)
  • Gemini のデフォルトは 3.7 Flash に更新されました。 (#9666)
  • Groq: 非推奨の llama-3.3-70b-versatile を openai/gpt-oss-120b に置き換えました。 (#9588)
  • OpenAI: reasoning_effort、reasoning_summary、service_tier、verbosity は、完全な API 値セットを受け入れます (拡張タイプ、通話中断なし)。
  • クロードは anthropic 1.0.0 (#9686) で動作します: クロード モデル用の SDK 互換アップデート

⚠️重大な変更

すべての 2.x ユーザーはこれを読む必要があります。 v3.0 がトラフィックを処理する前に、データベースの移行が必要です。

ストレージと移行

  • 実行はセッション テーブル内の JSON blob ではなくなり、agno_runs に存在します。サービスを提供する前に、MigrationManager(db).up()（または AgentOS POST /databases/all/migrate）を実行します。 v2→v3 の移行では、従来の runs 列がバックアップとして保存されます。確認した後、db.cleanup_legacy_runs_column() (SQL) / db.cleanup_legacy_runs_field() (ドキュメント/KV) を使用して再利用します。
  • 古いデータベースや移行されていないデータベースでは、静かに誤動作するのではなく、型指定エラーが発生します。
  • ページネーション: limit (または page < 1) のない page は、無制限/負の結果を返すのではなく、ValueError を引き起こすようになりました。

エージェントOS

  • JWT: secret_key は JWTMiddleware および authorization_config から削除されました。verification_keys (リスト) を使用してください。
  • メタデータ ルート: GET /models が削除されました (モデル データは available_models の下の GET /config に移動されました)。 GET / は最小限の着地応答を返します。 GET /info は、単一の未認証メタデータ エンドポイントです。
  • MCP サーバー設定: AgentOS(enable_mcp_server=..., mcp_config=...) が削除されました — 代わりに 1 つの mcp_server= を渡します。
  • バックグラウンド実行 には、コンポーネントに db が必要です (1 つがない場合は 400 を返します)。外部フレームワーク エージェント（LangGraph、Claude、DSPy など）は、background=true に対してインラインでストリーミングするため、再開できません。

エージェント

  • パラメータの名前が変更されました:
    • enable_user_memories → update_memory_on_run
    • search_session_history → search_past_sessions
    • num_history_sessions → num_past_sessions_to_search
    • num_past_session_runs → num_past_session_runs_in_search
  • reasoning=True が削除されました — reasoning_model=<native reasoning model> を明示的に設定します。
  • continue_run / acontinue_run: updated_tools が削除されました — requirements を渡します (一時停止された実行出力からの RunRequirement のリスト)。
  • 培養機能の削除: enable_agentic_culture、add_culture_to_context、CulturalKnowledge、培養ツール、agno_culture テーブル。クロスユーザー情報を共有するにはナレッジを使用します。

チームとワークフロー

  • Workflow コンストラクターはキーワードのみ: Workflow(name=..., steps=[...])。 Team は変更されていません。Team([agent_1, agent_2]) も引き続き機能しますが、Team(members=[...]) が優先されます。
  • ステップ/ステップ/ループ/条件/ルーターのフラット HITL クワーグが削除されました （requires_confirmation、confirmation_message、on_reject、requires_user_input、user_input_message、user_input_schema、requires_output_review、output_review_message、requires_iteration_review、iteration_review_message、on_error、hitl_max_retries、hitl_timeout、on_timeout）。 human_review=HumanReview(...)（agno.workflow.typesから）を使用します。 hitl_max_retries → max_retries、hitl_timeout → timeout を除き、名前は変更されていません。

ツール

  • MultiMCPTools が削除されました (allow_partial_failure とともに) - サーバーごとに 1 つの MCPTools を使用します。
  • MCPToolbox: auth_tokens / auth_headers は削除されました。auth_token_getters を使用してください。
  • DuckDuckGoTools.duckduckgo_search → web_search、duckduckgo_news → search_news (現在は WebSearchTools 上に構築されています)。
  • フラット Google ツール モジュールが削除されました（agno.tools.gmail、googlesheets、googlecalendar、google_maps、google_drive、google_bigquery） - agno.tools.google.* からインポートします。
  • Google ツール: creds_path / auth_port → credentials_path / oauth_port; Sheets enable_read_sheet など → 裸のメソッド名。
  • FileTools.check_escape → Toolkit._check_path (LocalFileSystemTools.check_escape 影響なし)。
  • SQLTools: enable_list_tables / enable_describe_table / enable_run_sql_query → 裸のメソッド名。
  • セルツ: max_documents → max_results。
  • StudioTool エイリアスが削除されました。StudioTools を使用してください。
  • BrightData.get_screenshot: 未使用のoutput_pathが削除されました。 PgVector.enable_prefix_matching が削除されました（死亡したヘルパー）。

ナレッジ & ベクトル DB

  • Knowledge.add_content / add_content_async / add_contents_async が削除されました → insert() / ainsert() / ainsert_many() を使用します。
  • GDriveContextProvider の名前が → GoogleDriveContextProvider に変更されました。
  • LanceDB: use_tantivy は削除/無視されました。
  • user_id を使用して v3 より前のベクター テーブルを検索すると、空の結果が返されるのではなく、ValueError が発生します (ベクター DB 移行に誘導されます)。

スケジューラ

  • update_schedule が許可リストに登録されました（name、description、method、endpoint、payload、cron_expr、timezone、timeout_seconds、max_retries、retry_delay_seconds、enabled、next_run_at、disabled_reasonのみ）;他のキーでは ValueError が発生します。所有権/出所/ロック状態は、汎用パス経由で書き込むことができなくなりました。 v3.0.0 の移行により、新しい来歴列が追加されました。
  • スケジュールの一意のキーが name から (user_id, name) に変更されます。同じユーザー間で重複したスケジュール名が存在する場合、移行は中止されます。つまり、移行前に重複を排除します。

評価

  • eval_id → run_id (#9739): eval クラスでは eval_id が使用されなくなりました。実行ごとに独自の run_id が取得されます。 store_result_in_file は、eval_id パラメータの名前を run_id に変更し、file_path_to_save_results テンプレートの {eval_id} プレースホルダーは受け入れられなくなり（{run_id} を使用）、POST /eval-runs は行が実際に保存されていた ID（run_id）を返します。再実行によって相互に上書きされなくなりました。

モデルと学習

  • ミストラル: mistralai v1 互換性レイヤーが削除されました - agno[mistral] には mistralai>=2.0.0 が必要です (models エクストラに戻ります)。
  • agno.models.metrics モジュールと Metrics エイリアスが削除 → agno.metrics (RunMetrics) からインポートします。
  • Model.classify_error を削除 → ModelProviderError.classify(error) を使用します。
  • namespace="user" の下の エンティティ メモリ はユーザーごとに分離されるようになりました (行キーには user_id ダイジェストが埋め込まれます)。 v3.0.0 移行 (agno.learn.migrations.rekey_user_entity_learnings) によってキーが再設定された v3 より前の行。 EntityMemoryStore.delete/get には、その名前空間にキーワードのみの user_id が必要です。
  • 学習エイリアスの削除: MemoriesConfig → UserMemoryConfig; MemoriesStore → UserMemoryStore; Decision → DecisionLog。

非推奨になりました (まだ機能します)

  • knowledge_retriever(dependencies=...) → run_context を好みます。シグネチャ名が依然として dependencies であるレトリバーは、明示的な下位互換ブランチを介して動作し続けます。 両方が存在する場合は、run_context が優先されます。
  • 範囲: system:read / system:write → config:read / config:write。古い名前は有効なエイリアスのままであり、既存のトークンは引き続き機能します。
  • RedisDB (ベクター DB) → RedisDb。 agno.db.redis ストレージ アダプタとのあいまいさを避けるために、RedisVectorDb もまだエクスポートされていることに注意してください。

移行クイックリファレンス

ドキュメント: ステップバイステップ ガイド、データベース移行、およびコーディング エージェント プロンプトへの貼り付け

import asyncio
from agno.db.migrations.manager import MigrationManager

# Step 1: run before serving v3.0 traffic (up() is async)
asyncio.run(MigrationManager(db).up())

# Step 2: VERIFY the runs landed before any cleanup
assert len(db.get_runs(limit=5)) > 0, "Migration copied nothing - do NOT clean up"

# Step 3 (optional, destructive): reclaim the legacy blob column.
# The migration preserves it as a backup, so force=True is required.
db.cleanup_legacy_runs_column(force=True)   # SQL adapters
# db.cleanup_legacy_runs_field(force=True)  # document / KV adapters

AgentOS の場合: POST /databases/all/migrate。詳細については、v3.0 changelog ドキュメントをご覧ください。

agno v3.0.0

Highlights

  • Migration is mandatory before you serve traffic — Every 2.x user must run MigrationManager(db).up() (or POST /databases/all/migrate on AgentOS) before v3.0 takes requests: runs have moved out of the sessions runs blob into a dedicated agno_runs table. The migration is non-destructive, idempotent, and covers 12 sync + 4 async backends, keeping the legacy column as a backup — verify with db.get_runs() before reclaiming space via cleanup_legacy_runs_column(force=True). Watch for typed MigrationRequiredError/SchemaMismatchError on stale DBs (#9669, #9631), page without limit (or page < 1) now raising ValueError, and duplicate schedule names aborting the migration under the new (user_id, name) unique key — dedupe first.

  • Runs become first-class rows, and that changes the scaling math — #8350 takes session write amplification from O(N²) to O(N) and removes the DynamoDB/Firestore item-size ceiling that silently capped long sessions. New db.get_run()/get_runs()/upsert_run()/delete_runs() APIs (sync + async) support filtering by status/session/page. Crucially, reads stay backward compatible — session.get_messages(), get_chat_history(), db.get_session() and AgentOS routes re-attach runs automatically — so this is a storage-layer fix with no read-path rewrite on your side.

  • Offloading attacks context bloat and payload limits — Tool results over 16,000 chars are written to AgentFS with only a preview/size/result_id envelope left in the message, and the agent fetches the rest via read_result/search_result; no model call on the write path, tunable through ResultStore(threshold_chars=..., ttl_seconds=...) (#9436, #9684). media_storage=S3MediaStorage(bucket=...) uploads images/audio/video/files before persistence and stores a MediaReference instead of base64 — a 113 KB JPEG drops from ~151,000 chars to 2,897, with no schema change (#9340). Net effect: smaller transcripts, lower token spend, and no more provider payload-size failures.

  • Durable background execution makes AgentOS deploy-safe — With AgentOS(queue=QueueConfig(durable=True)), accepted runs are committed rows that survive crashes/restarts/deploys and can be picked up by any replica, with bounded concurrency (default 32, AGNO_BACKGROUND_MAX_CONCURRENCY), cancellable queued jobs, Idempotency-Key dedupe, and 429 on a full queue (#9079, #9504). Redis is optional coordination, never the source of truth. Caveats: a db is required on the component (400 otherwise), and external-framework agents (LangGraph, Claude, DSPy) stream inline and are not resumable.

  • Expect a broad set of API renames and removals on day one — enable_user_memories → update_memory_on_run, search_session_history → search_past_sessions, reasoning=True removed in favor of an explicit reasoning_model, and continue_run's updated_tools → requirements (list of RunRequirement). Workflow(...) is now keyword-only; flat HITL kwargs on Steps/Loops/Routers must move into human_review=HumanReview(...); MultiMCPTools is deleted (use one MCPTools per server); flat Google tool modules moved under agno.tools.google.*; and Knowledge.add_content → insert(). The culture feature and agno_culture table are gone entirely — move shared info into Knowledge. Evals drop eval_id for per-run run_id (#9739), and Mistral users must move to mistralai>=2.0.0.

  • AgentOS auth and metadata surface reshaped — JWT secret_key is removed from JWTMiddleware/authorization_config in favor of verification_keys (a list). GET /models is gone (model data now under GET /config → available_models), GET / returns a minimal landing response, and GET /info is the sole unauthenticated metadata endpoint. MCP setup collapses from enable_mcp_server=/mcp_config= to a single mcp_server=. Deprecated but still working: system:read/write aliased to config:read/write and knowledge_retriever(dependencies=...) (prefer run_context, which wins when both are present).

⚠️ Breaking release. A database migration is required before v3.0 serves traffic. Read the v3 Migration Guide first, and see the full v3.0 Changelog for every change.

New Features

  • Tool result offloading: Agent(offload_tool_results=True) / Team(...) writes any tool result over 16,000 chars to AgentFS and leaves a short envelope (preview, size, result_id) in the message; the agent gets read_result / search_result (+ async) to fetch the rest. No model call on the write path. Tune via ResultStore(threshold_chars=..., ttl_seconds=...). (#9436, #9684)
  • Media offloading: media_storage=S3MediaStorage(bucket=...) on an Agent/Team/Workflow uploads images, audio, video and files to local disk, S3 or GCS before persistence; the row keeps a small MediaReference instead of base64 (a 113 KB JPEG drops from ~151,000 chars to 2,897). No schema change. (#9340) Docs
  • CodeMode: CodeMode(tools=[...]) swaps a wide tool schema for one programmable IPython kernel that persists across a session — the model writes Python and calls tools as awaitable handles, composing them (variables, loops, helpers) without round-tripping through the transcript.
  • FinanceTools: One unified finance toolkit with swappable data providers.
  • RampRouter model: New model provider for Ramp Router (router.com).
  • SuperGrok OAuth: Device-code auth for the xAI model.

Database

  • Runs get their own table: each run is a row in agno_runs with real columns (session_id, run_type, agent_id, team_id, workflow_id, user_id, parent_run_id, status, run_index) + JSON payload. Takes session write amplification from O(N²) to O(N) and removes the DynamoDB/Firestore item-size ceiling. session.get_messages(), get_chat_history(), db.get_session() and AgentOS session routes are unchanged (runs re-attach on read). (#8350)
    • Direct run APIs: db.get_run(), db.get_runs(session_id=..., status=..., limit=..., page=...), db.upsert_run(), db.delete_run(), db.delete_runs() (sync + async); db.get_session(runs_limit=N) and db.get_sessions(include_runs=False). (#8350)
    • One-line migration: MigrationManager(db).up() creates the runs store and copies legacy runs across, non-destructively and idempotently, on 12 sync + 4 async backends; un-migrated DBs still work (reads merge runs table with legacy blob). Schema versions tracked on every adapter. (#8350)
    • Typed stale-DB errors: MigrationRequiredError / SchemaMismatchError name both remedies; AgentOS carries error_id: "migration_required_error" in the JSON body. (#9669, #9631)
    • Three new tables: agno_runs, agno_jobs (durable background queue), agno_tool_results (offload index) — all auto-created.

Per-user isolation

  • Extends beyond sessions to metrics, schedules, evals, knowledge, components, entity memory, and 17 vector databases. Metrics aggregate per user per day; unowned components/knowledge are shared (readable by all, editable by admin) so enabling isolation doesn't 404 pre-isolation building blocks. (#8245, #8262)

AgentOS & Studio

  • Durable background execution: AgentOS(queue=QueueConfig(durable=True)) — accepted runs are committed rows that survive crashes/restarts/deploys, executed by any replica. Bounded concurrency (default 32, AGNO_BACKGROUND_MAX_CONCURRENCY), cancellable while queued, Idempotency-Key dedupe, 429 on full queue. Queue REST surface (GET /queue/jobs, .../{job_id}, POST .../requeue, GET /queue/stats). Redis is optional coordination, never truth. (#9079, #9504)
  • Studio 3.0 — governed catalog: create_* writes a DRAFT that serves nobody until publish_component; compare-and-set guards (typed 409s), tombstoned deletes, archive/restore, dependent-tracking. StudioTools returns a machine-readable envelope ({ok, status, data, error{...}, warnings}) across ~31 tools. (#9604)

Tools

  • MiniMax video generation tools. (#9529)
  • Toolkits now have a stable id used by AgentOS to reference tools.

Model Updates

  • Cerebras / CerebrasOpenAI default to gpt-oss-120b (was llama-4-scout-17b-16e-instruct). (#9244)
  • Gemini defaults updated to 3.7 Flash. (#9666)
  • Groq: replaced deprecated llama-3.3-70b-versatile with openai/gpt-oss-120b. (#9588)
  • OpenAI: reasoning_effort, reasoning_summary, service_tier, verbosity accept the full API value set (widened types; no call breaks).
  • Claude works with anthropic 1.0.0 (#9686): SDK-compat update for Claude models

⚠️ Breaking Changes

Every 2.x user must read this. A database migration is required before v3.0 serves traffic.

Storage & migrations

  • Runs are no longer a JSON blob in the sessions table — they live in agno_runs. Run MigrationManager(db).up() (or AgentOS POST /databases/all/migrate) before serving. The v2→v3 migration preserves the legacy runs column as a backup; reclaim it with db.cleanup_legacy_runs_column() (SQL) / db.cleanup_legacy_runs_field() (document/KV) after verifying.
  • Stale/unmigrated databases raise typed errors instead of silently misbehaving.
  • Pagination: page without a limit (or page < 1) now raises ValueError instead of returning unbounded/negative results.

AgentOS

  • JWT: secret_key removed from JWTMiddleware and authorization_config — use verification_keys (a list).
  • Metadata routes: GET /models removed (model data moved to GET /config under available_models); GET / returns a minimal landing response; GET /info is the single unauthenticated metadata endpoint.
  • MCP server config: AgentOS(enable_mcp_server=..., mcp_config=...) removed — pass a single mcp_server= instead.
  • Background execution requires a db on the component (returns 400 without one). External-framework agents (LangGraph, Claude, DSPy, etc.) stream inline for background=true and are not resumable.

Agents

  • Renamed params:
    • enable_user_memories → update_memory_on_run
    • search_session_history → search_past_sessions
    • num_history_sessions → num_past_sessions_to_search
    • num_past_session_runs → num_past_session_runs_in_search
  • reasoning=True removed — set reasoning_model=<native reasoning model> explicitly.
  • continue_run / acontinue_run: updated_tools removed — pass requirements (list of RunRequirement from the paused run output).
  • Culture feature removed: enable_agentic_culture, add_culture_to_context, CulturalKnowledge, culture tools, and the agno_culture table. Use Knowledge for shared cross-user info.

Teams & Workflows

  • The Workflow constructor is keyword-only: Workflow(name=..., steps=[...]). Team is unchanged — Team([agent_1, agent_2]) still works, though Team(members=[...]) is preferred.
  • Flat HITL kwargs removed on Step/Steps/Loop/Condition/Router (requires_confirmation, confirmation_message, on_reject, requires_user_input, user_input_message, user_input_schema, requires_output_review, output_review_message, requires_iteration_review, iteration_review_message, on_error, hitl_max_retries, hitl_timeout, on_timeout). Use human_review=HumanReview(...) (from agno.workflow.types); names unchanged except hitl_max_retries → max_retries, hitl_timeout → timeout.

Tools

  • MultiMCPTools deleted (along with allow_partial_failure) — use one MCPTools per server.
  • MCPToolbox: auth_tokens / auth_headers removed — use auth_token_getters.
  • DuckDuckGoTools.duckduckgo_search → web_search, duckduckgo_news → search_news (now built on WebSearchTools).
  • Flat Google tool modules deleted (agno.tools.gmail, googlesheets, googlecalendar, google_maps, google_drive, google_bigquery) — import from agno.tools.google.*.
  • Google tools: creds_path / auth_port → credentials_path / oauth_port; Sheets enable_read_sheet etc. → bare method names.
  • FileTools.check_escape → Toolkit._check_path (LocalFileSystemTools.check_escape unaffected).
  • SQLTools: enable_list_tables / enable_describe_table / enable_run_sql_query → bare method names.
  • Seltz: max_documents → max_results.
  • StudioTool alias removed — use StudioTools.
  • BrightData.get_screenshot: unused output_path removed. PgVector.enable_prefix_matching removed (dead helper).

Knowledge & Vector DBs

  • Knowledge.add_content / add_content_async / add_contents_async removed → use insert() / ainsert() / ainsert_many().
  • GDriveContextProvider renamed → GoogleDriveContextProvider.
  • LanceDB: use_tantivy removed/ignored.
  • Searching a pre-v3 vector table with a user_id raises ValueError (directing you to the vector DB migration) instead of returning empty results.

Scheduler

  • update_schedule is now allow-listed (only name, description, method, endpoint, payload, cron_expr, timezone, timeout_seconds, max_retries, retry_delay_seconds, enabled, next_run_at, disabled_reason); any other key raises ValueError. Ownership/provenance/lock state are no longer writable via the generic path. New provenance columns added by the v3.0.0 migration.
  • The schedules unique key changes from name to (user_id, name). If duplicate schedule names exist across the same user, the migration aborts — deduplicate before migrating.

Evals

  • eval_id → run_id (#9739): eval classes no longer carry eval_id; every run gets its own run_id. store_result_in_file renames the eval_id parameter to run_id, the {eval_id} placeholder in file_path_to_save_results templates is no longer accepted (use {run_id}), and POST /eval-runs returns the id the row was actually stored under (run_id). Re-runs no longer overwrite each other.

Models & Learning

  • Mistral: mistralai v1 compatibility layer removed — agno[mistral] requires mistralai>=2.0.0 (and is back in the models extra).
  • agno.models.metrics module and the Metrics alias removed → import from agno.metrics (RunMetrics).
  • Model.classify_error removed → use ModelProviderError.classify(error).
  • Entity memory under namespace="user" is now isolated per user (row keys embed a user_id digest); pre-v3 rows re-keyed by the v3.0.0 migration (agno.learn.migrations.rekey_user_entity_learnings); EntityMemoryStore.delete/get require a keyword-only user_id in that namespace.
  • Removed learn aliases: MemoriesConfig → UserMemoryConfig; MemoriesStore → UserMemoryStore; Decision → DecisionLog.

Deprecated (still working)

  • knowledge_retriever(dependencies=...) → prefer run_context. A retriever whose signature still names dependencies keeps working via an explicit backward-compat branch; run_context wins when both are present.
  • Scopes: system:read / system:write → config:read / config:write. The old names remain valid aliases and existing tokens keep working.
  • RedisDB (vector DB) → RedisDb. Note RedisVectorDb is also still exported, to disambiguate from the agno.db.redis storage adapter.

Migration quick-reference

Docs: Step-by-step guide, database migration, and a paste-into-your-coding-agent prompt

import asyncio
from agno.db.migrations.manager import MigrationManager

# Step 1: run before serving v3.0 traffic (up() is async)
asyncio.run(MigrationManager(db).up())

# Step 2: VERIFY the runs landed before any cleanup
assert len(db.get_runs(limit=5)) > 0, "Migration copied nothing - do NOT clean up"

# Step 3 (optional, destructive): reclaim the legacy blob column.
# The migration preserves it as a backup, so force=True is required.
db.cleanup_legacy_runs_column(force=True)   # SQL adapters
# db.cleanup_legacy_runs_field(force=True)  # document / KV adapters

On AgentOS: POST /databases/all/migrate. Full details in the v3.0 changelog docs.
