#アグノv2.6.0 #Changelog

新機能:

  • チーム HITL: ループ内のチーム人間用に API レイヤーを追加し、AgentOS チャット ページでサポートしました。
  • チームの承認: チーム内および AgentOS チャット ページでの承認のサポートが追加されました。
  • ワークフロー実行者 HITL: ワークフローの特定のステップでエージェント/チームに一時停止ツール フローが設定されている場合に、ループ内の実行者レベルの人間のサポートを追加しました。
  • AgentOS (ベータ) でのマルチフレームワークのサポート: AgentOS ランタイムで動作するバックボーンとして単一の AgentProtocol を使用する、ClaudeAgentSDK、Langgraph、および DSPy の基本サポートが追加されました。
  • 再接続と実行の再開: SSE を使用してバックグラウンドで実行されているエージェント/チームは、中断 (更新) の場合に再接続して AgentOS で再開できるため、中断したところから開始できます。
  • ファクトリー: AgentFactory、TeamFactory、WorkflowFactory を使用してエージェント/チーム/ワークフローを実行時に動的に作成できるようになり、より多くのマルチテナントのユースケースが可能になります。
  • コンテキスト プロバイダー: agno.context を追加しました。外部ソース (ファイル システム、Web、SQL データベース、Slack、Google ドライブ、MCP サーバー) を自然言語ツールとしてエージェントに接続するためのファーストパーティ API です。

バグ修正:

  • 呼び出し可能なファクトリー:
    • エージェント/チームがコピーされるときに、工場出荷時のツールとメンバーが保持されるように修正されました。
    • Agent.deep_copy で呼び出し可能なファクトリ ツールの反復をスキップするように修正されました。
  • 電報インターフェース:
    • Telegram 429 レート制限エラーの retry_after を尊重するように修正
    • Telegramインターフェースにquoted_responsesオプションを追加しました
  • エージェント OS ルーター: 応答からネストされたワークフロー ステップと Condition.else_steps (その中のエージェントとともに) を省略していた GET /workflows/{id} を修正しました。
  • ワークフロー: ワークフロー ステップとしてのワークフローの場合に、ネストされたワークフロー エンリッチメント レイヤーを通じて parent_step_id を保持するように修正されました。
  • MCP: MCP ツールで初期ヘッダーをマージするときに None ヘッダーを処理するように修正されました。
  • Claude: agno.utils.models.claude で人間のインポートが遅延するように修正されました。
  • リモート コンテンツ ソース: 異なるリモート ソース (GitHub リポジトリ、S3 バケット、GCS バケットなど) から同じファイル名の 2 つのアップロードが同一の content_hash 値を生成する問題を修正しました。
  • FileTools: exclude_patterns を FileTools に追加するように修正されました。
  • エージェント HITL: 後続のツール呼び出しを処理しない一時停止/続行フローを修正しました。

重大な変更:

  • セッション タイプ フィルター: /sessions エンドポイントは、デフォルトですべてのセッション タイプ (エージェント、チーム、ワークフロー) を返すようになり、1 回の呼び出しでセッションの完全なビューが得られます。特定のタイプでフィルターするには、リクエストで ?type=agent ?type=team または ?type=workflow を渡します。

agno v2.6.0

Highlights

  • HITL and Approvals expand beyond single agents — Human-in-the-loop gets a Team API layer plus AgentOS chat page support, Team Approvals land in both, and Workflows gain executor-level pauses for agents/teams at a specific step; a companion fix corrects Agent HITL pause-continue dropping subsequent tool calls. If you've been blocked on gating Team or Workflow execution, this is the release that unblocks it.

  • AgentOS goes polyglot (Beta) and resumable — A single AgentProtocol backbone adds basic ClaudeAgentSDK, Langgraph, and DSPy support, while SSE background runs can now reconnect and resume after a refresh. Treat the new frameworks as Beta/"basic support" — don't bet production on them yet — but the resume behavior is a real win for long-running jobs.

  • Runtime-built agents for multi-tenancy — AgentFactory, TeamFactory, and WorkflowFactory let you create agents/teams/workflows dynamically, backed by fixes so copied agents preserve factory tools and members and skip callable-factory tools in Agent.deep_copy. Worth upgrading if you serve many tenants from one app; otherwise skippable.

  • Breaking: /sessions default scope changes — The endpoint now returns all session types (agent, team, workflow) by default rather than a single type. If your code relied on the old default, add ?type=agent, ?type=team, or ?type=workflow explicitly — this is the one change that actually requires a code edit on upgrade.

  • agno.context and data-source fixes — New first-party context provider plugs external sources (filesystem, web, SQL, Slack, Google Drive, MCP server) into an agent as a natural-language tool; alongside it, content_hash collisions when the same filename is uploaded from different remote sources are fixed and FileTools gains exclude_patterns. Relevant if you're wiring external data into agents; otherwise low impact.

Changelog

New Features:

  • Team HITL: Added API layer for Team human in the loop and support in AgentOS chat page.
  • Team Approvals: Added support for Approvals in Team, along with in AgentOS chat page.
  • Workflow Executor HITL: Added support for executor level human in the loop in case when a pause tool flow is setup on an agent/team in a particular step of a workflow.
  • Multi-framework support in AgentOS (Beta): Added basic support for ClaudeAgentSDK, Langgraph and DSPy using a single AgentProtocol as the backbone which works with AgentOS runtime.
  • Reconnection and Resume Runs: Agent/Team running in background using SSE can now be reconnected and resumed in AgentOS in case of a interruption (refresh) so you start from where you left.
  • Factories: Agent/Team/Workflow can now be created dynamically at run-time using AgentFactory, TeamFactory and WorkflowFactory allowing for more multi-tenant usecases.
  • Context Provider: Added agno.context — a first-party API for plugging an external source (filesystem, web, SQL database, Slack, Google Drive, MCP server) into anagent as a natural-language tool.

Bug Fixes:

  • Callable Factory:
    • Fixed to preserve factory tools and members when Agent/Team is copied.
    • Fixed to skip iteration of callable-factory tools in Agent.deep_copy.
  • Telegram Interface:
    • Fixed to respect retry_after on Telegram 429 rate limit errors
    • Added quoted_responses option to Telegram interface
  • Agent OS Router: Fixed GET /workflows/{id} which omitted nested workflow steps and Condition.else_steps (along with the agents inside them) from the response
  • Workflow: Fixed to preserve parent_step_id through nested workflow enrichment layers in case of workflow as a workflow step.
  • MCP: Fixed to handle None headers when merging init headers in MCP tools.
  • Claude: Fixed to make anthropic imports lazy in agno.utils.models.claude.
  • Remote Content Source: Fixed where two uploads of the same filename from different remote sources (GitHub repos, S3 buckets, GCS buckets, etc.) produced identical content_hash values.
  • FileTools: Fixed to add exclude_patterns to FileTools.
  • Agent HITL: Fixed pause-continue flow not handling subsequent tool calls.

Breaking Changes:

  • Session Type Filter: The /sessions endpoint now returns all session types (agent, team, and workflow) by default, giving you a complete view of your sessions in a single call. To filter for a specific type, pass?type=agent ?type=team, or ?type=workflow in your request.
