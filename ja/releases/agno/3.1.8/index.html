agno v3.1.8

#アグノv3.1.8

#Changelog

新機能

  • Postgres サンドボックス チェックポイント ストア: サンドボックス チェックポイントを PostgreSQL に直接保存するための PostgresCheckpointStore が追加され、マルチ レプリカ デプロイメントで S3 または共有ファイル システムなしでセッションを復元できるようになります。チェックポイントはチャンク化され、トランザクション的に書き込まれ、SHA-256 によって重複排除され、読み取り時に検証されます。それはオプトインです。既存のチェックポイントのデフォルトは変更されません。 (#11186)
  • ルーチン実行者としてのフレームワーク マネージャー: 企業ルーチンは、宣言、ルーチン API、およびヒューマン チャット設定を通じて、社内のプロダクト マネージャーまたは OS マネージャーを実行者として使用できるようになりました。予約済みマネージャー ID は、所有する AgentOS からのみ解決され、保存されたコンポーネントまたはユーザー定義のコンポーネントで置き換えることはできません。オプションで毎週のプロダクト マネージャーによるレビューが含まれます。 (#11193)
  • サンドボックス チェックポイントの保持: サンドボックスは、デフォルトでセッションごとに 3 つの最新チェックポイントを保持するようになりました。すべてのチェックポイントを保存するように retain_checkpoints=None を設定します。未公開または置き換えられたチェックポイントは、実行結果が安全に保存された後に廃止され、削除されます。 (#11187)

改善点

  • サンドボックス セッションのクリーンアップ: サンドボックスを利用したセッションを削除すると、データベース トランザクションのコミット後にウォーム コンピュータと関連するチェックポイント オブジェクトが削除されるようになりました。単一セッション、一括削除、およびユーザー スコープのセッション削除は、呼び出し元が所有していないセッションに影響を与えることなくサポートされています。 (#11187)
  • OS Manager スペシャリストの可視性: Platform Builder と Platform Manager が、/teams と /teams/os-manager-internal で OS Manager のメンバーとして表示されるようになりました。これらは、再利用可能なアプリケーション レジストリ、トップレベル エージェントの検出、およびスタンドアロン エージェント ルートから除外されたままになります。 (#11198)
  • クロードのデフォルトは Sonnet 5.5 です: Claude() のデフォルトは claude-sonnet-5-5 になり、廃止される前の非推奨の claude-sonnet-4-5-20250929 に置き換わります。デフォルト以外の temperature、top_p、top_k の値は、これらのサンプリング パラメータを拒否する新しいクロード モデルの場合、警告とともに削除されます。この動作は、Anthropic、Bedrock、Foundry、および Vertex プロバイダー全体に適用されます。 (#11212)

動作の変更

  • チェックポイントの保持: デフォルトでは、最新の 3 つのサンドボックス チェックポイントのみが保持されます。古い実行のチェックポイントを開くと、CheckpointObjectNotFound が発生する可能性があります。 retain_checkpoints=None を設定すると、以前の無制限の保持動作が復元されます。 (#11187)
  • デュラブル サンドボックスの起動検証: デュラブル キュー サンドボックスがホストローカルのデフォルト チェックポイント ストアを使用する場合、AgentOS が起動時に失敗するようになりました。すべてのレプリカで共有されるチェックポイント ストア（PostgresCheckpointStore や S3CheckpointStore など）を構成します。以前は、この無効な構成は最初の送信時にのみ失敗していました。 (#11187)

バグ修正

  • サンドボックス チェックポイントの欠落: コミットされたチェックポイントがストレージに欠落していると、明確な再試行不可能なエラーでターンが終了し、新しく作成されたコンピューターがリタイアされ、セッションが解放されます。以前は、実行は RUNNING のままで、キューの再試行が使い果たされ、後でブロックされてセッションがオンになりました。 (#11187)
  • 会社ルーチンの実行: ステータスの書き込みが拒否され、Studio ランナーの委任が失敗した場合に、ルーチンが正しく失敗するようになりました。古いアーカイブされたカタログ エントリは、所有されている予約済みマネージャーと衝突しなくなりました。 (#11193)

何が変わったのか

  • 修正: https://github.com/agno-agi/agno/pull/11187 の @ysolanky によるサンドボックス チェックポイントの回復、保持、セッション削除のクリーンアップ
  • 修正: OS マネージャーの下にプラットフォーム スペシャリストを表示 (https://github.com/agno-agi/agno/pull/11198 の @ashpreetbedi により)
  • 功績: Postgres のサンドボックス チェックポイントに PostgresCheckpointStore を追加 (https://github.com/agno-agi/agno/pull/11186 の @ysolanky により)
  • 功績: 社内ルーティンの実行者としてフレームワーク マネージャーをサポート (https://github.com/agno-agi/agno/pull/11193 の @ashpreetbedi 著)
  • 修正: https://github.com/agno-agi/agno/pull/11212 の @kausmeows によってsonnet-4-5 が引退する前に、デフォルトのクロードを Sonnet-5-5 に設定
  • 修正: https://github.com/agno-agi/agno/pull/10824 の @23821 によるデフォルトの OpenAITools イメージ生成を gpt-image-2 にしました
  • 雑用: test-db から Company db スイートを分割し、https://github.com/agno-agi/agno/pull/11213 の @harshsinha03 による 6 番目の単体テスト シャードを追加します。
  • 修正: クロード モデルが思考予算を拒否した場合に適応的思考を送信 (https://github.com/agno-agi/agno/pull/11215 の @harshsinha03 による)
  • 雑用: @kausmeows による v3.1.8 を https://github.com/agno-agi/agno/pull/11208 でリリース

agno v3.1.8

Highlights

  • Postgres checkpoint store for multi-replica sandboxes — New PostgresCheckpointStore (#11186) persists sandbox checkpoints directly in PostgreSQL, removing the need for S3 or a shared filesystem. Checkpoints are chunked, written transactionally, deduplicated by SHA-256 and verified on read. It's opt-in with defaults unchanged, so this is a zero-migration upgrade for existing single-replica users — but it's the enabling piece for horizontally scaling AgentOS without shared storage.

  • Checkpoint retention capped at three by default — (#11187) Only the three newest checkpoints per session are kept; older ones are retired and deleted once the run outcome is safely stored. Opening a checkpoint from an older run can now raise CheckpointObjectNotFound. If you depend on long checkpoint history for replay or audit, set retain_checkpoints=None before upgrading to restore unlimited retention.

  • Fail-fast validation for durable-queue sandboxes — (#11187) AgentOS now refuses to start if a durable-queue sandbox uses the host-local default checkpoint store; previously the misconfiguration surfaced only on the first submission. Point every replica at a shared store such as PostgresCheckpointStore or S3CheckpointStore. Related fixes turn a missing committed checkpoint into a clear non-retryable error that retires the new computer and releases the session, instead of leaving the turn stuck RUNNING and burning through queue retries.

  • Full cleanup on sandbox session deletion — (#11187) Deleting a sandbox-backed session now removes its warm computer and associated checkpoint objects after the DB transaction commits, for single, bulk and user-scoped deletes, without touching sessions the caller doesn't own. Expect reclaimed compute and less orphaned checkpoint state.

  • Framework managers become Routine executors — (#11193) Company Routines can use the internal Product/OS Manager as executors via declarations, the Routine API and human-chat configuration, plus an optional weekly Product Manager review. Reserved manager IDs resolve only from the owning AgentOS and cannot be overridden by saved or user-defined components — safer, but you can't shadow them with custom agents. Separately, #11198 surfaces Platform Builder and Platform Manager under OS Manager in /teams, while keeping them out of the reusable registry and standalone agent routes.

  • Claude default shifts to Sonnet 5.5 — (#11212) Claude() now defaults to claude-sonnet-5-5 ahead of Sonnet 4.5's retirement, across Anthropic, Bedrock, Foundry and Vertex. Newer models reject temperature, top_p and top_k, so non-default values are dropped with a warning — audit any call sites that set sampling parameters explicitly. Also worth watching: adaptive-thinking fallback when a Claude model rejects a thinking budget (#11215) and OpenAITools image generation defaulting to gpt-image-2 (#10824).

Changelog

New Features

  • Postgres Sandbox Checkpoint Store: Added PostgresCheckpointStore for storing sandbox checkpoints directly in PostgreSQL, allowing multi-replica deployments to restore sessions without S3 or shared filesystems. Checkpoints are chunked, written transactionally, deduplicated by SHA-256 and verified on read. It is opt-in; existing checkpoint defaults are unchanged. (#11186)
  • Framework Managers as Routine Executors: Company Routines can now use the internal Product Manager or OS Manager as executors through declarations, the Routine API and human-chat configuration. Reserved manager IDs resolve only from the owning AgentOS and cannot be replaced by saved or user-defined components. Includes an optional weekly Product Manager review. (#11193)
  • Sandbox Checkpoint Retention: Sandboxes now retain the three newest checkpoints per session by default. Configure retain_checkpoints=None to preserve every checkpoint. Unpublished or superseded checkpoints are retired and deleted after the run outcome is safely stored. (#11187)

Improvements

  • Sandbox Session Cleanup: Deleting a sandbox-backed session now removes its warm computer and associated checkpoint objects after the database transaction commits. Single, bulk and user-scoped session deletion are supported without affecting sessions the caller does not own. (#11187)
  • OS Manager Specialist Visibility: Platform Builder and Platform Manager now appear as members of OS Manager in /teams and /teams/os-manager-internal. They remain excluded from the reusable application registry, top-level agent discovery and standalone agent routes. (#11198)
  • Claude Defaults to Sonnet 5.5: Claude() now defaults to claude-sonnet-5-5, replacing the deprecated claude-sonnet-4-5-20250929 before its retirement. Non-default temperature, top_p and top_k values are dropped with a warning for newer Claude models that reject those sampling parameters. This behavior applies across Anthropic, Bedrock, Foundry and Vertex providers. (#11212)

Behavior Changes

  • Checkpoint Retention: Only the three newest sandbox checkpoints are retained by default. Opening a checkpoint for an older run can now raise CheckpointObjectNotFound. Set retain_checkpoints=None to restore the previous unlimited-retention behavior. (#11187)
  • Durable Sandbox Startup Validation: AgentOS now fails at startup when a durable-queue sandbox uses the host-local default checkpoint store. Configure a checkpoint store shared by every replica, such as PostgresCheckpointStore or S3CheckpointStore. Previously this invalid configuration failed only on the first submission. (#11187)

Bug Fixes

  • Missing Sandbox Checkpoints: A committed checkpoint missing from storage now ends the turn with a clear, non-retryable error, retires the newly created computer and releases the session. Previously the run remained RUNNING, exhausted queue retries and blocked later turns on the session. (#11187)
  • Company Routine Execution: Denied status writes and failed Studio runner delegation now correctly fail the Routine. Stale archived catalog entries no longer collide with owned reserved managers. (#11193)
