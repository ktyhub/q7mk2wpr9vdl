#アグノv3.1.1 #Changelog

新機能

  • ページ同期のライブ進行状況とキャンセル: Knowledge.stream_sync_pages() / astream_sync_pages() 生成タイプの PageSyncProgress スナップショットと 1 つの端末 SyncReport および sync_pages / async_sync_pages は on_progress オブザーバーを受け入れます。ワークフロー関数ステップは、既存のワークフロー実行/ステップ ID の下でネイティブ StepProgressEvent として出力され、StepOutput の前に StepProgress(content=..., data=...) を生成できるようになりました。AgentOS は既存のワークフロー REST/SSE ルート上でそれをストリーミングし、AgentOSClient.run_workflow_stream() を解析します。同期をキャンセルすると、最後まで消耗するのではなく、実際に作業が完了するようになりました。 (#10098)
  • ページ同期レポートは失敗したページに名前を付けます。SyncReport.failed_paths は、公開/削除に失敗したページのサイト パスをリストします（errors のように最初の 20 が上限です。failed は完全な数を保持します。デフォルトは () なので、既存の呼び出し元/保存されているレポートは影響を受けません）。ログはページとその原因チェーンに名前を付けるようになりました。 Page sync failed for /guides/setup.md (SyncFailed: sync_failed <- ConnectError: [Errno 104] Connection reset by peer)、およびプルーン パス上の新しい Page delete failed for … 警告。 (#10729)

バグ修正

  • バックオフを使用して一時的なページ取得エラーを再試行します。大規模なコーパス (例: docs.agno.com、3,913 ページ) では、Connection reset by peer を使用すると、実行ごとに 1 ～ 2 個のランダムなページが失敗しました。以前は、各試行で 30 秒のフェッチ期限全体が消費され (再試行する時間がなくなり)、再試行が短すぎました。両方とも試行ごとの制限されたタイムアウトとバックオフで修正されました。 (#10730)
  • Mintlify スタイルのサイトの完全なページ同期: 大規模な Mintlify サイト (例: docs.langchain.com) は、すべてのページがインデックスに登録されている場合でも、partial として同期されます。partial の結果ではプルーニングがスキップされるため、削除されたページは無期限に検索可能のままです。 Discovery は、ページ以外のファイル (.json、.yaml、.xml、.csv、.pdf、画像/音声/ビデオ、アーカイブ、フォント) へのリンクをスキップし、.js/.css を /guides/node.js のような有効なページ名として保持するようになり、ネストされたインデックス、MDX コード ブロック、リダイレクト エイリアスを処理するようになりました。オフホスト ページ リンクは依然としてプルーニングをブロックします (仕様による)。 (#10726)

何が変わったのか

  • 特技: https://github.com/agno-agi/agno/pull/10729 の @kausmeows によるページ同期レポートで失敗したページとその原因に名前を付ける
  • 修正: https://github.com/agno-agi/agno/pull/10730 の @kausmeows によるバックオフによる一時的なページ取得失敗の再試行
  • 功績: https://github.com/agno-agi/agno/pull/10098 の @ashpreetbedi によるナレッジ ページ同期のための AgentOS ライフサイクル サポートを追加
  • 修正: Mintlify スタイルのサイト (非ページ リンク、ネストされたインデックス、MDX コード、リダイレクト エイリアス) の完全なページ同期 (https://github.com/agno-agi/agno/pull/10726 の @kausmeows による)

agno v3.1.1

Highlights

  • Observable, cancellable page sync — stream_sync_pages() / astream_sync_pages() now emit typed PageSyncProgress snapshots and a terminal SyncReport, while the blocking APIs accept an on_progress observer. Cancellation reaches active work instead of letting the sync drain, making long-running corpus updates practical to control (#10098).

  • Native workflow progress streaming — Workflow steps can yield StepProgress(content=..., data=...) before StepOutput; AgentOS exposes it through existing REST/SSE routes, and AgentOSClient.run_workflow_stream() parses it. Existing run and step IDs are preserved, so clients can surface intermediate progress without introducing a separate event protocol (#10098).

  • Actionable sync failure reporting — SyncReport.failed_paths identifies up to 20 affected site paths, while failed retains the full count; the new field defaults to (). Logs now include page-level cause chains and prune failures, helping distinguish publish errors from deletion errors instead of debugging an opaque partial result (#10729).

  • More resilient page fetching — Bounded per-attempt timeouts and backoff prevent a single connection reset from consuming the entire 30-second fetch budget and eliminating retry opportunities. This targets the intermittent failures observed on large documentation corpora (#10730).

  • Correct discovery and pruning for Mintlify-style sites — Sync now ignores non-page assets, handles nested indexes, MDX code blocks, and redirect aliases, and retains valid .js / .css page names. Previously, false partial results skipped pruning and left removed pages searchable indefinitely. Off-host page links still intentionally block pruning, so external link structures remain a migration consideration (#10726).

  • Breaking changes — None listed.

Changelog

New Features

  • Live progress & cancellation for page sync: Knowledge.stream_sync_pages() / astream_sync_pages() yield typed PageSyncProgress snapshots plus one terminal SyncReport, and sync_pages / async_sync_pages accept an on_progress observer. A workflow function step can now yield StepProgress(content=..., data=...) before its StepOutput, emitted as a native StepProgressEvent under the existing workflow run/step ID — AgentOS streams it over the existing workflow REST/SSE route, and AgentOSClient.run_workflow_stream() parses it. Cancelling a sync now actually reaches the work instead of draining to the end. (#10098)
  • Page sync reports name failed pages: SyncReport.failed_paths lists the site paths of pages that failed to publish/delete (capped at the first 20, like errors; failed keeps the full count; defaults to () so existing callers/stored reports are unaffected). Logs now name the page and its cause chain, e.g. Page sync failed for /guides/setup.md (SyncFailed: sync_failed <- ConnectError: [Errno 104] Connection reset by peer), plus a new Page delete failed for … warning on the prune path. (#10729)

Bug Fixes

  • Retry transient page-fetch failures with backoff: on large corpora (e.g. docs.agno.com, 3,913 pages) 1–2 random pages failed per run with Connection reset by peer. Each attempt previously consumed the entire 30s fetch deadline (leaving no time to retry) and retries were too short — both are fixed with a bounded per-attempt timeout and backoff. (#10730)
  • Complete page sync for Mintlify-style sites: large Mintlify sites (e.g. docs.langchain.com) synced as partial even when every page indexed — and a partial result skips pruning, so removed pages stayed searchable indefinitely. Discovery now skips links to non-page files (.json, .yaml, .xml, .csv, .pdf, images/audio/video, archives, fonts — while keeping .js/.css as valid page names like /guides/node.js), and handles nested indexes, MDX code blocks and redirect aliases. Off-host page links still block pruning (by design). (#10726)

What's Changed

  • feat: name failed pages and their causes in page sync reports by @kausmeows in https://github.com/agno-agi/agno/pull/10729
  • fix: retry transient page fetch failures with backoff by @kausmeows in https://github.com/agno-agi/agno/pull/10730
  • feat: add AgentOS lifecycle support for Knowledge page synchronization by @ashpreetbedi in https://github.com/agno-agi/agno/pull/10098
  • fix: complete page sync for Mintlify-style sites (non-page links, nested indexes, MDX code, redirect aliases) by @kausmeows in https://github.com/agno-agi/agno/pull/10726
  • chore: Release v3.1.1 by @kausmeows in https://github.com/agno-agi/agno/pull/10736
