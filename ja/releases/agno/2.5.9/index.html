#アグノv2.5.9 #Changelog

新機能:

  • フォローアップ: エージェントとチームに対する組み込みのフォローアップ提案を追加しました。 クックブックを参照してください。
  • 日時形式: エージェントとチームに datetime_format パラメーターが追加され、日時コンテキストのカスタム strftime 形式 (ISO-8601、日付のみ、ローカライズなど) が可能になりました。
  • ツール フックのメッセージ履歴: ツールの事前/事後フックおよびエージェント レベルのツールフックは、run_context.messages 経由で現在の実行のメッセージ履歴にアクセスできるようになりました。
  • GoogleCalendarTools: 新しいツール、サービス アカウント認証、クックブックを備えた GoogleCalendarTools の拡張。

バグ修正:

  • HITL: 走行中のマルチラウンド会話中に add_history_to_context をサポートするためにループ内の人間を修正しました
  • ツール: ツール パラメーターの説明からプレフィックスを削除 (なし)
  • Siliconflow モデル プロバイダー: 正しいデフォルトの base_url を .com から .cn に使用するように更新されました。
  • 提案モードの学習: マルチターン確認のために LearningMode.PROPOSE のチャット履歴を自動的に有効にします。
  • AgentOS API ドキュメント: OpenAPI/Swagger の可視性のために、エージェント、チーム、ワークフロー API エンドポイント全体のすべての Form/File パラメーターに説明を追加しました。

agno v2.5.9

Highlights

  • Followup suggestions built in — PR #6672 adds native followup suggestions to both Agent and Team, so you can surface "what to ask next" prompts without hand-rolling conversational UI logic. Purely additive and opt-in; see the linked AgentOS cookbook for the wiring.
  • Customizable datetime context — PR #6649 introduces a datetime_format parameter on Agent and Team, letting you render datetime context via strftime (ISO-8601, date-only, localized) instead of post-processing strings yourself. Matters if your prompts rely on stable, parseable dates — but it's opt-in, so existing output is untouched.
  • Tool hooks can read the conversation — PR #6652 exposes run_context.messages to tool pre/post hooks and agent-level tool_hooks, enabling context-aware hook decisions (e.g., varying behavior by prior turns). Watch the caveat: it's mutation-safe, so mutating that list will not rewrite the actual run history — don't build side effects on it.
  • HITL multi-round history restored — PR #6888 fixes continue_run dropping history messages, so human-in-the-loop flows using add_history_to_context now retain earlier turns across rounds. If you added workarounds for missing history in running conversations, they can come out.
  • Siliconflow endpoint flips to .cn — PR #6933 changes the Siliconflow provider's implicit default base_url from .com to .cn. This is the behavioral change to watch: anyone relying on the old default will now hit a different regional host — pin base_url explicitly if you need the previous endpoint.
  • Calendar and learning-mode upgrades — PR #6926 extends GoogleCalendarTools with new tools, service-account auth, and cookbooks; PR #6928 auto-enables chat history for LearningMode.PROPOSE, making multi-turn confirmation work without extra config. PR #6941 also adds Form/File parameter descriptions so they surface in AgentOS OpenAPI/Swagger docs.

No breaking changes in this release.

Changelog

New Features:

  • Followups: Added built-in followup suggestions for Agent and Team. See cookbook.
  • Datetime Format: Added datetime_format parameter to Agent and Team, allowing custom strftime formatting for datetime context (e.g., ISO-8601, date-only, localized).
  • Tool Hook Message History: Tool pre/post hooks and agent-level tool_hooks can now access the current run's message history via run_context.messages
  • GoogleCalendarTools: Extended GoogleCalendarTools with new tools, service account auth, and cookbooks.

Bug Fixes:

  • HITL: Fixed human in the loop to support add_history_to_context during multi-round conversations while running
  • Tools: Removed (None) prefix from tool parameter descriptions
  • Siliconflow Model Provider: Updated to use correct default base_url from .com to .cn
  • Learning PROPOSE Mode: Auto-enable chat history for LearningMode.PROPOSE for multi-turn confirmation.
  • AgentOS API Docs: Added descriptions to all Form/File parameters across agent, team, and workflow API endpoints for OpenAPI/Swagger visibility
