#アグノv3.1.3

#Changelog

新機能:

  • 永続的な外部エージェント セッション: ClaudeAgent セッションが任意のレプリカで再開されるようになりました。クロード SDK セッション ID は Agno セッション (#10903) に保存され、トランスクリプト ストレージ (PostgresDb、AsyncPostgresDb、SqliteDb、AsyncSqliteDb) をサポートするデータベースを使用すると、すべてのトランスクリプト行が新しい agno_transcripts テーブルにミラーリングされるため、後で別のマシンの電源をオンにしたときに、ローカル ファイルではなくデータベースから再開されます。再開できない保存されたセッションは、Agno 履歴がシードされた新しい SDK セッションにフォールバックします。クロードおよびコーデックスの非ストリーミング実行では、ツール呼び出しと結果が実行履歴に保存されるようになりました。 クックブックを参照してください。 (#10904)
  • 外部エージェントのバックグラウンド実行とキャンセル: ClaudeAgent および CodexAgent は、background=True、永続キュー実行 ID、再開可能なインデックス付き SSE、および /agents/{id}/runs/{run_id}/cancel によるキャンセルをサポートし、ネイティブ エージェントのバックグラウンド タスク、スロット、およびイベント ストリーム インフラストラクチャを共有します。 Claude は実行ごとの SDK client を使用し、Codex はターン ハンドルを保持するため、所有プロセスはいずれかの SDK に割り込むことができます。 クックブックを参照してください。 (#10905)
  • ClaudeAgent のステップ リプレイ: ClaudeAgent.continue_run / acontinue_run は、stream=True および background=True とともに、Agent.continue_run と同じ continue_from、fork、および input 引数を受け取ります。各ツールの結果は、GET /agents/{id}/runs/{run_id}/checkpoints によってリストされるチェックポイントです。続行すると、保存されている SDK トランスクリプトがそのメッセージでフォークされるため、モデルはそれまでに何が起こったかだけを記憶し、continue_from="last_user" はそのターンを再生します。終了した実行がその場で書き換えられることはありません。その継続は新しい兄弟実行となります。 クックブックを参照してください。 (#10917)
  • 外部エージェントの再試行: ClaudeAgent および CodexAgent は、Agent と同じデフォルトの retries、delay_between_retries、および exponential_backoff を受け取ります。失敗した試行は同じ実行 ID で再試行され、開始された SDK セッションまたは Codex スレッドが再開されます。制限 (max_turns、max_budget_usd、Codex の予算と使用制限) および永続的なエラー (認証、請求、不正なリクエスト、コンテキスト ウィンドウ、ポリシー) は再試行されません。失敗した試行によるツール呼び出しは 1 回だけ保持され、ストリーミング コンシューマは試行と試行の間に type: "retry" 警告イベントを受け取り、再試行された実行では metadata["attempts"] が記録され、ワー​​カーの再起動時など、エージェントがエラーに再試行不可のマークを付けると、永続キューはジョブを一度に失敗します。 クックブックを参照してください。 (#10937)
  • 外部エージェントのメトリクス: ClaudeAgent および CodexAgent を実行するたびに、RunOutput.metrics のトークン、キャッシュ使用量、およびコスト (クロード) がレポートされます。metrics.details["model"] のモデルごとに 1 つのエントリと、Agno のウォールクロック duration および time_to_first_token がレポートされます。完了した実行はセッションの session_metrics に蓄積され、AgentOS はセッション リスト、セッション ビュー、および /metrics に表示します。 Codex は、最後のリクエストだけでなく、ターン内のすべてのモデル リクエストを合計します。 クックブックを参照してください。 (#10925)
  • 外部エージェントの圧縮: Claude Code の /compact はデータベースにバックアップされたセッション ストアを通じて機能するため、圧縮されたセッションは任意のレプリカ上の概要から再開され、CodexAgent.compact / acompact は Agno セッションの背後で Codex スレッドを圧縮します。セッションの実行中に圧縮が拒否されます。 クックブックを参照してください。 (#10924)
  • 外部エージェント用の保存されたイベント: BaseExternalAgent は、Agent と同様に、store_events および events_to_skip を受け取ります。 AgentOS は外部エージェントに対してこれを有効にするため、実行ビューと /agents/{id}/runs/{run_id}/resume は、イベント ストリームの保持期限が切れると、last_event_index を尊重して順番にデータベースから完了した実行を再生します。 (#10957、#10958)
  • 外部エージェントの構造化出力: ClaudeAgent および CodexAgent の output_schema は、エージェント上または実行ごとに Pydantic モデルまたは JSON スキーマ辞書を受け取り、実行のコンテンツは、Agent と同様に、content_type が設定された解析済みモデル (または辞書) です。クロードは、構造化出力ツールを通じてオブジェクトを配信しますが、これはツール呼び出しとして記録されません。 Codex は厳密なスキーマを受け取ります。スキーマは JSON オブジェクトを記述する必要があります。配列またはスカラー ルートは実行前に拒否されます。 AgentOS のリクエストごとの output_schema フォーム フィールドが外部エージェントに適用されるようになりました。 クックブックを参照してください。 (#10965)
  • 外部エージェント用のメディア: 画像とファイルは、直接、または AgentOS API および UI を介して、ClaudeAgent および CodexAgent の実行に添付できます。添付ファイルは <cwd>/.agno/uploads/<run_id>/ でステージングされ、プロンプトで名前が付けられ (Codex は画像もネイティブに受け取ります)、実行の入力に記録され、後でレプリカをオンにするために復元され、keep_uploads=True を除いて実行後に​​削除されます。オーディオとビデオは、サーバー エラーではなく 400 で拒否されます。 クックブックを参照してください。 (#10926)
  • セッション API の外部エージェント ID: GET /sessions、GET /sessions/{session_id}、およびセッション実行読み取りには、エージェント API ("codex"、"claude-agent-sdk") と同じ metadata.sdk 値が含まれており、agent_data 外部エージェントからの読み取り時にオーバーレイされているため、既存のセッションには移行なしのラベルが付けられ、保存されたメタデータは変更されません。ネイティブ、チーム、ワークフロー セッションは変更されません。 RunSchema は metadata フィールドを取得します。これにより、再試行 attempts や warnings などの実行メタデータも表示されます。 (#11020)
  • AnakinTools: Anakin.io の 4 つのフラグ ゲート メソッドとして API をスクレイピング、クロール、マップ、検索するための新しいツールキットで、非同期ジョブが完了するまでポーリングするため、モデルはジョブ ID ではなくページ コンテンツまたはリンクを受け取ります。 クックブックを参照してください。 (#10650)

改善点:

  • 外部エージェント API: ClaudeAgent および CodexAgent は、型なしの _kwargs 辞書の代わりに、型付きのネイティブ オプション (ツール、権限、MCP サーバー、スレッドおよびターン オプション) を受け取りますが、警告は表示されますが、引き続き機能します。アダプター コンストラクターはキーワードのみであり、agent.sdk は SDK に名前を付けます (API およびセッション メタデータは sdk のみを出力します。framework エイリアスは Python オブジェクトに残ります)。print_response / aprint_response は最終実行を返し、失敗時に発生します。フレームワーク クックブックは、ネイティブ SDK の比較、サンプル プロジェクト、再現可能な信頼性キットを使用して再作成されました。 (#10926)
  • 外部エージェントのモデル ID: ClaudeAgent および CodexAgent は、ネイティブ エージェントと同様にレコード model および model_provider を実行するため、AgentOS メトリクス ページのモデル実行カードにカウントされます。エージェントまたはそのオプションにモデルが設定されていない場合、ネイティブ モデルにはデフォルト ID があるため、model は、Claude の場合は claude-sonnet-4-6、Codex の場合は gpt-5.6-luna にデフォルト設定されます。デフォルトは、SDK が実行するように要求されるものです。オプションで設定されたモデルが引き続き優先されます。以前の未設定モデルでは、CLI が選択可能でした。 (#11018)
  • セッションごとのキューに登録されたターン数: キューに登録された外部エージェントが 1 つのセッションをオンにしても、試行をまとめて要求して SessionBusyError に書き込むことがなくなりました。各組み込みキュー ストア (Postgres、Redis、メモリ内) は、試行またはワーカー スロットを消費する前に、セッションの次のターンを選択します。 (#10974)
  • ハーネス クックブック: クロード クックブックとコーデックス クックブックは、フェーズ 1 受け入れテスト後に更新され、ネイティブ オプション全体が型指定され、信頼性ランナーが修正され、各フォルダーのテスト ログに記録されたライブ結果が含まれます。 (#10973)
  • セッションごとに 1 ターン: クロード コードとコーデックスは、セッションごとに 1 つの会話を側で保持するため、飛行中に開始された 2 番目のターンは、受け入れられて後で失敗するのではなく、SessionBusyError (HTTP 409、error_type: session_busy) で拒否されるようになりました。保留中の実行またはクラッシュによって実行された実行をキャンセルすると、そのセッションが解放されます。 (#10958)
  • サブエージェント ツール リネージ: クロード サブエージェントによって行われたツール呼び出しは、ToolExecution およびツール イベントで parent_tool_call_id を運ぶため、トレースでは委任ツールの下にネストされたツール スパンが表示されます。 クックブックを参照してください。 (#10959)
  • 開発セットアップ: scripts/dev_setup.sh と scripts/demo_setup.sh は同じ依存関係をインストールするため、クックブックはどちらの環境からも実行できます。 (#10920)

バグ修正:

  • セッション ビジー キープアライブ: ビジーな外部エージェント セッションの 409 は、キャッチオールではなく専用の SessionBusyError ハンドラーによって応答されるため、キープアライブ接続は開いたままとなり、競合はトレースバックではなく警告として記録されます。応答本文は変更されず、他の例外は新しいパスを使用しません。 クックブックを参照してください。 (#11017)
  • 添付ファイルのステージング: 外部エージェントの実行に添付されたファイルは、アクティブなワークスペースでのみステージングおよび復元され、履歴パスが移動したときにハーネスに通知されます。ステージングが失敗すると、部分的な書き込みや keep_uploads=True を含む、作成したすべてのファイルがロールバックされますが、既存のファイルは保持されます。トラバーサル実行 ID とシンボリックリンクされたアップロード パスは拒否されます。 (#10971)
  • 実行入力検証: 実行リクエストの不正な形式の JSON images、audio、videos、および input_files は、実行中に消失または失敗するのではなく、ディスパッチ前に HTTP 422 で拒否されます。また、不正な形式またはスカラールートの output_schema は、サイレントに削除されるのではなく拒否されます。 (#11005)
  • CodexAgent: 失敗したツール呼び出し (ゼロ以外の終了、declined コマンド、MCP ツール エラー) は、ストリーミング実行および非ストリーミング実行で、null ではなく tool_call_error=True で保存されます。 (#10958)
  • CodexAgent: スレッドを再開できない場合、新しいスレッドに再生される履歴には、ユーザーとアシスタントのテキストのみではなく、以前のツール呼び出しとその結果がそれぞれ 2000 文字に切り詰められて含まれるようになりました。 (#10909)
  • 外部エージェントの再開: stream=false とともに送信された実行の /resume は、実行中に実行が完了したと主張するのではなく、実行の実際のステータスを報告し、実行エンドポイントをポーリングするように指示します。 (#10958)
  • テスト: 部分ツール衝突テストは、FastMCP のツールの名前に依存しなくなりました。 (#10914)

agno v3.1.3

Highlights

  • Durable, replica-safe external agent sessions — ClaudeAgent/CodexAgent state is no longer pinned to a local SDK file: the Claude session id is persisted on the Agno session and every transcript line is mirrored into a new agno_transcripts table when you run on PostgresDb/SqliteDb (and async variants) (#10903, #10904). Why it matters: turns can now round-robin across replicas and survive restarts. Budget a schema migration for the new table, and note that a session that can't be resumed silently falls back to a fresh SDK session seeded with Agno history rather than erroring — so verify resume behavior before trusting it in production.

  • Background runs, cancellation, and step replay — External agents now share the native agent background/slot/event-stream plumbing: background=True, durable queue run ids, resumable indexed SSE, and cancellation via /agents/{id}/runs/{run_id}/cancel (#10905). ClaudeAgent.continue_run/acontinue_run accept the same continue_from/fork/input as Agent, replaying from per-tool-result checkpoints listed by GET /agents/{id}/runs/{run_id}/checkpoints (#10917). Continuations are always new sibling runs, never in-place rewrites — good for auditability, but anything keyed on a single run id must now follow the child run.

  • Retries with deliberate boundaries — retries, delay_between_retries, and exponential_backoff land on both external agents with native defaults (#10937). Attempts reuse the same run id and resume the SDK session/Codex thread; permanent errors (auth, billing, bad requests, context window, policy) and budget/turn limits are not retried. Watch for the new type: "retry" streaming event, metadata["attempts"], and the guarantee that failed-attempt tool calls are kept exactly once — relevant if you dedupe tool events or count attempts.

  • API and behavioral shifts to plan for — Adapter constructors are now keyword-only, untyped _kwargs still work but warn, and agent.sdk replaces framework in API/session metadata (the alias survives only on the Python object); print_response/aprint_response now return the final run and raise on failure (#10926). An unset model now defaults to claude-sonnet-4-6/gpt-5.6-luna instead of letting the CLI decide, while an explicit option still wins (#11018). A second turn on an in-flight session is now rejected up front with HTTP 409 error_type: session_busy rather than being accepted and failing later (#10958, #11017), and malformed media/output_schema is rejected with HTTP 422 before dispatch (#11005). New RunSchema.metadata surfaces SDK identity and retry attempts (#11020).

  • Observability and capability parity with native agents — Runs report tokens, cache, and cost on RunOutput.metrics with per-model details["model"], accumulating into session_metrics that AgentOS renders (#10925). output_schema accepts Pydantic or JSON Schema with an object root only — array/scalar roots are refused (#10965); /compact and CodexAgent.compact now work through the DB-backed store (#10924); images/files attach under .agno/uploads/<run_id>/ and are removed post-run unless keep_uploads=True, with audio/video returning 400 (#10926). Together with store_events replay after SSE retention expires (#10957), this closes the gap that made external agents second-class citizens to native Agent.

  • AnakinTools — New four-method toolkit for Anakin.io's scrape/crawl/map/search APIs that polls async jobs to completion, so the model receives page content or links instead of a job id (#10650). Niche, but useful for grounding agents on live web data without wiring your own polling loop.

Changelog

New Features:

  • Durable External Agent Sessions: ClaudeAgent sessions now resume on any replica. The Claude SDK session id is stored on the Agno session (#10903), and with a database that supports transcript storage (PostgresDb, AsyncPostgresDb, SqliteDb, AsyncSqliteDb) every transcript line is mirrored into the new agno_transcripts table, so a later turn on another machine resumes from the database instead of a local file. A stored session that cannot be resumed falls back to a fresh SDK session seeded with the Agno history. Claude and Codex non-streaming runs now keep tool calls and results in run history. See cookbook. (#10904)
  • Background Runs & Cancellation for External Agents: ClaudeAgent and CodexAgent support background=True, durable-queue run ids, resumable indexed SSE and cancellation through /agents/{id}/runs/{run_id}/cancel, sharing the background task, slot and event-stream infrastructure of native agents. Claude uses a per-run SDK client and Codex retains turn handles, so the owning process can interrupt either SDK. See cookbook. (#10905)
  • Step Replay for ClaudeAgent: ClaudeAgent.continue_run / acontinue_run take the same continue_from, fork and input arguments as Agent.continue_run, with stream=True and background=True. Each tool result is a checkpoint listed by GET /agents/{id}/runs/{run_id}/checkpoints; continuing forks the stored SDK transcript at that message, so the model only remembers what happened up to it, and continue_from="last_user" replays the turn. A finished run is never rewritten in place: its continuation is a new sibling run. See cookbook. (#10917)
  • Retries for External Agents: ClaudeAgent and CodexAgent take retries, delay_between_retries and exponential_backoff with the same defaults as Agent. A failed attempt is retried with the same run id and resumes the SDK session or Codex thread it started; limits (max_turns, max_budget_usd, Codex budget and usage limits) and permanent errors (authentication, billing, bad requests, context window, policy) are not retried. Tool calls from failed attempts are kept exactly once, streaming consumers get a type: "retry" warning event between attempts, a retried run records metadata["attempts"], and the durable queue fails a job at once when the agent marks its error non-retryable, including across worker restarts. See cookbook. (#10937)
  • Metrics for External Agents: Every ClaudeAgent and CodexAgent run reports tokens, cache usage and cost (Claude) on RunOutput.metrics, with one entry per model in metrics.details["model"], plus Agno's wall-clock duration and time_to_first_token. Completed runs accumulate into the session's session_metrics, which AgentOS shows in the sessions list, the session view and /metrics. Codex sums every model request in a turn, not only the last one. See cookbook. (#10925)
  • Compaction for External Agents: Claude Code's /compact works through the database-backed session store, so a compacted session resumes from its summary on any replica, and CodexAgent.compact / acompact compact the Codex thread behind an Agno session. Compaction refuses while a run on the session is in flight. See cookbook. (#10924)
  • Stored Events for External Agents: BaseExternalAgent takes store_events and events_to_skip like Agent. AgentOS turns it on for external agents, so the run view and /agents/{id}/runs/{run_id}/resume replay a finished run from the database once the event stream's retention has expired, in order and honouring last_event_index. (#10957, #10958)
  • Structured Output for External Agents: output_schema on ClaudeAgent and CodexAgent takes a Pydantic model or a JSON Schema dict, on the agent or per run, and the run's content is the parsed model (or dict) with content_type set, as for Agent. Claude delivers the object through its structured output tool, which is not recorded as a tool call; Codex receives a strict schema. The schema must describe a JSON object; an array or scalar root is refused before the run. The AgentOS per-request output_schema form field now applies to external agents. See cookbook. (#10965)
  • Media for External Agents: Images and files can be attached to ClaudeAgent and CodexAgent runs, directly and through the AgentOS API and UI. Attachments are staged under <cwd>/.agno/uploads/<run_id>/, named in the prompt (Codex also receives images natively), recorded on the run's input, restored for later turns on any replica and removed after the run unless keep_uploads=True. Audio and video are rejected with a 400 instead of a server error. See cookbook. (#10926)
  • External Agent Identity on Session APIs: GET /sessions, GET /sessions/{session_id} and the session run reads carry the same metadata.sdk value as the agents API ("codex", "claude-agent-sdk"), overlaid at read time from the agent_data external agents already persist, so existing sessions are labelled with no migration and stored metadata is untouched. Native, team and workflow sessions are unchanged. RunSchema gains a metadata field, which also surfaces run metadata such as retry attempts and warnings. (#11020)
  • AnakinTools: New toolkit for Anakin.io's scrape, crawl, map and search APIs as four flag-gated methods, polling asynchronous jobs until they complete so the model receives page content or links rather than a job id. See cookbook. (#10650)

Improvements:

  • External Agent APIs: ClaudeAgent and CodexAgent take typed native options (tools, permissions, MCP servers, thread and turn options) instead of untyped _kwargs dictionaries, which still work with a warning. Adapter constructors are keyword-only, agent.sdk names the SDK (API and session metadata emit only sdk; the framework alias remains on the Python object), and print_response / aprint_response return the final run and raise on failure. Framework cookbooks were reworked with native SDK comparisons, a sample project and a reproducible reliability kit. (#10926)
  • Model Identity for External Agents: ClaudeAgent and CodexAgent runs record model and model_provider like native agents, so they count on the Models Runs card of the AgentOS metrics page. When no model is set on the agent or in its options, model defaults to claude-sonnet-4-6 for Claude and gpt-5.6-luna for Codex, as a native model has a default id; the default is what the SDK is asked to run. A model set in options still wins. Previously an unset model left the choice to the CLI. (#11018)
  • Queued Turns Per Session: Queued external-agent turns on one session no longer claim attempts together and burn them on SessionBusyError. Each built-in queue store (Postgres, Redis, in-memory) elects the next turn for a session before it spends an attempt or a worker slot. (#10974)
  • Harness Cookbooks: The Claude and Codex cookbooks were refreshed after Phase 1 acceptance testing with typed native options throughout, a corrected reliability runner, and live results recorded in each folder's test log. (#10973)
  • One Turn Per Session: Claude Code and Codex keep one conversation per session on their side, so a second turn started while one is in flight is now refused with SessionBusyError (HTTP 409, error_type: session_busy) instead of being accepted and failing later. Cancelling a run left pending or running by a crash frees its session. (#10958)
  • Subagent Tool Lineage: Tool calls made by Claude subagents carry parent_tool_call_id on ToolExecution and on tool events, so tracing shows nested tool spans under the delegating tool. See cookbook. (#10959)
  • Development Setup: scripts/dev_setup.sh and scripts/demo_setup.sh install the same dependencies, so cookbooks run from either environment. (#10920)

Bug Fixes:

  • Session Busy Keep-Alive: The 409 for a busy external-agent session is answered by a dedicated SessionBusyError handler instead of the catch-all, so the keep-alive connection stays open and the conflict is logged as a warning rather than a traceback. The response body is unchanged and no other exception takes the new path. See cookbook. (#11017)
  • Attachment Staging: Files attached to external-agent runs are staged and restored only under the active workspace, with the harness told when historical paths moved. A failed staging rolls back every file it created, including partial writes and with keep_uploads=True, while preexisting files are preserved. Traversal run ids and symlinked upload paths are rejected. (#10971)
  • Run Input Validation: Malformed JSON images, audio, videos and input_files on run requests are rejected with HTTP 422 before dispatch instead of vanishing or failing mid-run, and a malformed or scalar-root output_schema is rejected instead of being silently dropped. (#11005)
  • CodexAgent: Failed tool calls (a non-zero exit, a declined command, an MCP tool error) are stored with tool_call_error=True instead of null, on streamed and non-streamed runs. (#10958)
  • CodexAgent: When a thread cannot be resumed, the history replayed into the fresh thread now includes earlier tool calls and their results, truncated to 2000 characters each, instead of only user and assistant text. (#10909)
  • External Agent Resume: /resume on a run submitted with stream=false reports the run's real status and says to poll the run endpoint, instead of claiming the run completed while it was still running. (#10958)
  • Tests: The partial-tool collision test no longer depends on FastMCP's tool naming. (#10914)
