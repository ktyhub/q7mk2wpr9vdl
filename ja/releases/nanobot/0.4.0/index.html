#ナノボットv0.4.0

🐈 nanobot v0.4.0 は、耐久性のある会話履歴、より機能的なワークベンチ、次のアップデートへの明確な道筋により、日常業務の継続を容易にします。

動き続けてください。 ゲートウェイはモデル履歴とブラウザーのトランスクリプトを SQLite に保存し、既存の会話をインポートし、保存された状態に関する更新を調整します。安定したオプトイン プレビュー リリースは 1 つの更新フローを共有し、インストールと再起動の前に明示的な確認が行われます。

ブラウザー ワークベンチは、ナビゲートと接続がより簡単になりました。完全なプロンプト履歴ナビゲーション、リモート インスタンス、より明確な委任タスクの詳細、より豊富な添付ファイル、より一貫したモバイル コントロールが備わっています。端末は、マーメイド ダイアグラムの表示とターゲット固有のネイティブ バンドルを取得します。両方の client は引き続き同じ Python ゲートウェイを使用します。

このリリースでは、インストールの所有権も明示的になります。サポートされている管理対象インストールでは、アプリを通じてプログラムを更新および回復できます。他のインストールでは、元のパッケージ マネージャーまたは展開に関する指示を受け取ります。回復とは、チャットの古いコピーを復元することを意味するものではありません。既存のインストールを置き換える前に、アップグレードに関する注意事項をお読みください。

ハイライト

  • 確認を伴う 1 つの更新フロー - [設定] → [バージョン情報] でリリースを確認し、プレビュー更新を受信するかどうかを選択し、正確なバージョンを確認して、インストールを確認して再起動します。サポートされている公式インストーラーおよび POSIX uv 環境では、公開リリースで承認証明が確認されると、アプリ内フローを使用できます。
  • 現在のデータを保護する回復 — インストーラー管理の更新では修復を試み、安全な場合には元のプログラムとサービスを復元できます。構成と会話は古いバックアップに自動的に置き換えられません。フロー外のインストール所有者は、独自の修復ルートを維持します。
  • 永続的な会話履歴 — SQLite は、モデル履歴と WebUI 表示履歴をゲートウェイの所有権下に置きます。既存の JSONL 履歴は、ソース バックアップを保持したままインポートされます。ページング、ライブ出力調整、キューに入れられたフォローアップ、および目標の継続では、信頼性に関する修正が行われます。
  • より明確なブラウザ ワークベンチ — 制限付き読み込みで完全なプロンプト履歴をナビゲートし、読み込まれたメッセージとセッション ハンドルを検索し、トピックの名前をインラインで変更し、トピックをバッチでアーカイブします。委任されたタスクには、より明確な実行状態と詳細ビューが表示されます。
  • 適切なホスト上のワークベンチ - 明示的なホスト ID、ペアリング、再接続フィードバックを使用して既存のリモート インスタンスに接続します。更新手順では、ページを表示しているデバイスであると想定するのではなく、ゲートウェイ コンピューターを識別します。
  • より豊富なファイルとより優れた小画面エクスペリエンス — ローカル ファイルとビデオの添付ファイル、画像のサムネイル、ファイル カード、Markdown ソース ビュー、読み取りサイズのコントロール、タッチとテーマの改善。外部 Web サイトは、任意の埋め込みプレビューではなく、ブラウザーで開きます。
  • ターミナル内の図 — 会話を離れることなく、Mermaid 図を表示、ズーム、パン、コピーできます。プラットフォーム ホイールには、対応するネイティブ TUI と構築された WebUI が含まれています。サポートされているホイールのインストールには、Bun も初回起動時の TUI ダウンロードも必要ありません。
  • モデルと統合のさらなる制御 — 検索可能なプロバイダー、明示的な API の選択、プリセットごとのリクエストのオーバーライド、共有プロキシの選択、リニアおよび WhatsApp エージェント プラットフォーム チャネル、QQ QR セットアップ、および DeepSeek 検索。スケジュールされたジョブはその場で編集、有効化、無効化することができ、最近の実行を検査に利用できます。
  • Windows アイドル メモリ増加の修正 - プロセス ステータス ポーリングは、ライブ プロセス チェックとハンドル クリーンアップを維持しながら、3.14 より前のバージョンの Python でネイティブ タイプと API バインディングを再利用するようになりました。

アップグレードに関する注意事項

  • 配布の可用性 検証済みの v0.4.0 パッケージは、この GitHub リリースおよび PyPI で入手できます。このリリースではアプリ内自動インストールがまだ有効になっていません。検証済みのリリース承認証明と該当する公開リリース ソースが必要です。これらのファイルを公開しても、ユーザーをプレビューに登録したり、更新を開始したりすることはありません。
  • 最初に元のインストール方法で v0.3.5 をアップグレードしてください。 そのリリースには、この新しいアプリ内アップデーターは含まれていません。ゲートウェイ コンピューター上で、元の OS アカウントでインストーラー、パッケージ マネージャー、またはコンテナーの置換を実行します。既存のインストールは、サイレントに公式インストーラー環境に変換されません。記録された追加機能、制約、カスタム オプションなど、インストール所有者の指示 に従ってください。
  • 共有ライターを停止し、完全なインスタンスをバックアップします。 アクティブな作業を終了し、環境またはデータを使用しているすべての nanobot プロセスを停止し、選択した構成ディレクトリとワークスペースを一緒にバックアップします。認証、セッション、WebUI 状態が含まれます。ライブ SQLite データベース ファイルのみをコピーしないでください。アップグレード後、元のランチャーを使用し、実行中のバージョンを確認し、古い会話を開いて、新しいメッセージを書き込み、再度再起動することを確認します。
  • SQLite はダウングレード手順を変更します。 JSONL インポートは 0.4.x 全体で引き続き利用可能です。古い JSONL のみのインストールは、0.5.0 より前のインポート可能なリリースを経由する必要があります。インポートされたソースのバックアップと古い WebUI ディレクトリを保持します。古いバージョンでは、新しい SQLite 表示履歴を読み取ることができません。ダウングレードには、バックアップ以降に作成されたメッセージを考慮した、停止したライターのバックアップ/復元手順が必要です。これは自動データ ロールバックではありません。 セッションストレージを参照してください。
  • 更新によりゲートウェイが再起動される場合があります。 インストールを確認すると、実行中のタスクが中断される場合があります。プレビューをオフにするとサブスクリプションは保存されますが、インストールされているプレビューはダウングレードされません。リカバリでは、永続的なストレージの損傷、互換性のないデータ書き込み、または両方のリカバリ プロセスの喪失後のサービスの復元は保証できません。公開資産が欠落しているか検証できない場合は、インストールが成功したものとして扱ってはなりません。 nanobot の更新 を参照してください。
  • 最新の公式インストーラー インスタンスはバックグラウンドに残ります。 通常の WebUI ランチャーが永続インスタンスを開始します。端末やブラウザを閉じても停止しません。同じ構成とワークスペース セレクターで nanobot gateway stop を使用します。既存の未記録のインストールは、元のライフサイクルを保持します。ローカル macOS WebUI セッションでは Dock アイコンが表示されることがあります。 --no-dock はそれを抑制します。
  • 保存する前に、移行された構成を確認してください。 従来のプロキシ変換は、0.4.x で引き続きサポートされます。古い OpenAI apiType / api_type セレクターは、0.4.0 およびその直後のリリースでは api に変換されます。そのウィンドウ中に現在の形式を保存します。 構成を参照してください。
  • プラットフォーム要件は引き続き明示的です。 Python 3.11+ が必要です。ネイティブ ホイールは、macOS 13 以降 arm64/x64、glibc 2.17+ Linux arm64/x64、および Windows x64 をターゲットとしています。 x64 では SSE4.2 が必要です。 Windows ARM64 および musl Linux にはネイティブ ホイールがありません。中国語の端末図には、適切なフォントがインストールされている必要があります。macOS では Heiti SC、Linux では Noto Sans CJK、Windows では Microsoft YaHei です。レンダリングが利用できない場合でも、図のソースには引き続きアクセスできます。
  • コンテナーのデータ ボリュームを保持し、clients に再接続します。 デプロイメント所有者を通じてコン​​テナーを置き換えます。実行中のコンテナ内のパッケージをアップグレードしないでください。対象のゲートウェイをアップグレードした後、WebUI/TUI clients を再接続またはリロードし、表示されている client/ホスト互換性ガイダンスに従ってください。

コミュニティ

コードを提供し、変更をレビューし、問題を報告し、複製を提供し、日常使用でナノボットをテストしてくださったすべての方々に感謝します。明確なバグレポートと有用な使用例は依然として重要な貢献です。私たちは、エージェントを小規模で検査しやすい状態に保ちながら、日常業務でより簡単に利用できるようにしたいと考えています。

nanobot v0.4.0

🐈 nanobot v0.4.0 makes everyday work easier to continue — with durable conversation history, a more capable workbench, and a clearer path to the next update.

Keep moving. The gateway now stores model history and browser transcripts in SQLite, imports existing conversations, and coordinates updates around saved state. Stable and opt-in Preview releases share one update flow, with explicit confirmation before installation and restart.

The browser workbench is easier to navigate and connect: complete prompt-history navigation, remote instances, clearer delegated-task details, richer attachments, and more consistent mobile controls. The terminal gains Mermaid diagram viewing and target-specific native bundles. Both clients continue to use the same Python gateway.

This release also makes installation ownership explicit. Supported managed installations can update and recover the program through the app; other installations receive instructions for their original package manager or deployment. Recovery does not mean restoring an old copy of your chats. Please read the upgrade notes before replacing an existing installation.

Highlights

  • One update flow, with your confirmation — Check releases in Settings → About, choose whether to receive Preview updates, review the exact version, and confirm installation and restart. Supported official-installer and POSIX uv environments can use the in-app flow once the public release has verified approval proof.
  • Recovery that protects current data — Installer-managed updates can attempt repair and, when safe, restore the original program and service. Configuration and conversations are not automatically replaced with an older backup. Installation owners outside that flow keep their own repair route.
  • Durable conversation history — SQLite brings model history and WebUI display history under gateway ownership. Existing JSONL history is imported with source backups retained. Paging, live-output reconciliation, queued follow-ups and goal continuation receive reliability fixes.
  • A clearer browser workbench — Navigate the full prompt history with bounded loading, search loaded messages and session handles, rename topics inline, and archive topics in batches. Delegated tasks have clearer run state and detail views.
  • Your workbench, on the right host — Connect to existing remote instances with explicit host identity, pairing and reconnect feedback. Update instructions identify the gateway computer, rather than assuming it is the device displaying the page.
  • Richer files and a better small-screen experience — Local-file and video attachments, image thumbnails, file cards, Markdown source views, reading-size controls, and touch and theme improvements. External websites open in the browser instead of an arbitrary embedded preview.
  • Diagrams in the terminal — View, zoom, pan and copy Mermaid diagrams without leaving the conversation. Platform wheels contain the matching native TUI and built WebUI; supported wheel installations need neither Bun nor a first-launch TUI download.
  • More control over models and integrations — Searchable providers, explicit API choices, per-preset request overrides, shared proxy choices, Linear and WhatsApp Agent Platform channels, QQ QR setup, and DeepSeek Search. Scheduled jobs can be edited, enabled and disabled in place, with recent runs available for inspection.
  • A fix for Windows idle memory growth — Process-status polling now reuses native type and API bindings on Python versions before 3.14, while keeping live process checks and handle cleanup.

Upgrade Notes

  • Distribution availability. The verified v0.4.0 packages are available in this GitHub Release and on PyPI. In-app automatic installation is not enabled for this release yet: it requires verified release approval proof and the applicable public release sources. Publishing these files does not enroll users in Preview or start an update.
  • Upgrade v0.3.5 through its original installation method first. That release does not contain this new in-app updater. Run the installer, package manager or container replacement on the gateway computer under its original OS account. Existing installations are not silently converted into official-installer environments. Follow the installation-owner instructions, including recorded extras, constraints and custom options.
  • Stop shared writers and back up the complete instance. Finish active work, stop all nanobot processes using the environment or data, and back up the selected configuration directory and workspace together. Include authentication, sessions and WebUI state. Do not copy only a live SQLite database file. After upgrading, use the original launcher, check the running version, open older conversations, write a new message and verify another restart.
  • SQLite changes the downgrade procedure. JSONL import remains available throughout 0.4.x; older JSONL-only installations must pass through an import-capable release before 0.5.0. Keep imported source backups and the old WebUI directory. Older versions cannot read new SQLite display history. A downgrade requires a stopped-writer backup-restoration procedure that accounts for messages created since the backup; it is not an automatic data rollback. See Session Storage.
  • An update can restart the gateway. Confirming installation can interrupt running tasks. Turning Preview off saves the subscription but does not downgrade an installed Preview. Recovery cannot guarantee service restoration after permanent storage damage, incompatible data writes, or loss of both recovery processes. Missing or unverifiable public assets must not be treated as a successful install. See Updating nanobot.
  • Fresh official-installer instances stay in the background. Their normal WebUI launcher starts a persistent instance. Closing the terminal or browser does not stop it; use nanobot gateway stop with the same configuration and workspace selectors. Existing unrecorded installations retain their original lifecycle. Local macOS WebUI sessions can show a Dock icon; --no-dock suppresses it.
  • Review migrated configuration before saving. Legacy proxy conversion remains supported in 0.4.x. The old OpenAI apiType / api_type selector is converted to api in 0.4.0 and the immediately following release; save the current format during that window. See Configuration.
  • Platform requirements remain explicit. Python 3.11+ is required. Native wheels target macOS 13+ arm64/x64, glibc 2.17+ Linux arm64/x64, and Windows x64; x64 requires SSE4.2. Windows ARM64 and musl Linux do not have native wheels. Chinese terminal diagrams require suitable installed fonts: Heiti SC on macOS, Noto Sans CJK on Linux, or Microsoft YaHei on Windows. Diagram source remains accessible if rendering is unavailable.
  • Keep container data volumes and reconnect clients. Replace the container through its deployment owner; do not upgrade packages inside a running container. Reconnect or reload WebUI/TUI clients after upgrading the intended gateway, and follow any client/host compatibility guidance shown.
