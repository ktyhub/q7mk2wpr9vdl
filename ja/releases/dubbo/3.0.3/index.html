dubbo 3.0.3

パッチ 公開日2021年9月19日 出典apache/dubbo English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ダボダボ-3.0.3

機能

  • トリプルの応答が例外である場合のアタッチメントをサポート（#8488）
  • DubboSpringInitializer を抽出し、初期化のカスタマイズをサポート（#8495）
  • トリプルサーバーストリームをサポート（#8542）
  • チェック設定の強化と修正（#8483）
  • Dubbo コンパイラ サポート ストリーム（#8566）
  • 無視されたネットワークインターフェイスのサポート（#8616）
  • トリプル void レスポンスをサポート（#8608）
  • トライインナーヘルスサービス追加（#8644）
  • マルチインスタンスサポート（#8662、#8669、#8684、#8717、#8728、#8736、#8737、#8766、#8779、#8789 、#8786、#8810、#8818、#8819、#8825、#8823、#8829、#8831、#8824、#8835、#8832）
  • HTTP2設定をサポート（#8700）

バグ修正

  • destroyの呼び出し中にリソースが解放されないようにします（#8459）
  • トリプルプロトコルを使用すると使用できない場合に実際の例外が返される問題を修正（#8458）
  • Triple：添付ファイルがオブジェクトインスタンスの場合の自動折り返しを削除（#8473）
  • サービス検出シナリオにおけるアドレス配信の問題を解決（#8492）
  • ポート2181の使用エラーのアドレスを修正（#8466）
  • ブロードキャストログフォーマットのバグを修正（#8484）
  • TRIプロトコル使用時にスキームHTTPを使用するTLSを修正（#8497）
  • いくつかのコメントを修正（#8526）
  • クラスキャストエラーを修正し、ZoneAwareClusterInvokerの単体テストを追加（#8503）
  • コンシューマ側で nacos グループが実行不可能になる問題を修正（#8533）
  • リクエストがタイムアウトした場合のシリアル化チェックにおける NPE を修正しました（#8547）
  • farbic-io を使わずに dubbo-all でコンパクトにする（#8546）
  • BroadcastClusterInvokerのバグ修正とテストケースの追加（#8532）
  • MetadataService 接続リークを修正（#8555）
  • モック:トゥルー構成を修正（#8558）
  • 重複した設定初期化を修正（#8578）
  • 非ダボナコスサービスを無視する（#8573）
  • フィルターエラーがclientに戻らない問題を修正（#8615）
  • コンパイラのバージョンを 0.0.3 リリースにバンプ（#8687）
  • clientがトレーラーのみを認識できない問題を修正（#8664）
  • ランダムアサーションの失敗を修正（#8703）
  • トライストリームメソッドがmethodDescriptorを見つけられない問題を修正（#8705）
  • TripleClientHandlerのconsumerModelのNPEを修正（#8734）
  • 無視されたインターフェース名一致メソッドを修正（#8723）
  • コンシューマーとプロバイダーが同じタグを持っているがプロバイダーが見つからない問題を修正（#8763）
  • トリプルクラスローダーを修正し、ServiceMetadata の後方を追加（#8800）
  • DubboProtocol の状態を修正し、破棄時の NPE を修正（#8809）
  • URL直接接続を使用するコンシューマーがServerContextを取得できない問題を修正（#8757）
  • Javaassist ClassPool ClassPathを修正（#8828）
  • nacos 管理プロトコルがインターフェース名を取得できない問題を修正（#8782）

最適化

  • トライヘッダ定数を最適化し、添付ファイルのトライヘッダを回避（#8481）
  • トリプル：接続の最適化とエグゼキュータの削除（#8486）
  • アドレスなしの一部のレジストリを圧縮（#8496）
  • サービス情報リビジョン構造の変更（#8478）
  • ShortResponseLoadBalanceに関する最適化（#8441、#8519）
  • ダボモニター構成の最適化（#8477、#8549）
  • リファレンス構成のリファクタリング（#8455）
  • タイプミスといくつかの最適化を修正（#8499）
  • すべてのテストケースで zookeeper タイムアウトを最適化（#8564）
  • Reference作成時の例外を無視する(ジェネリックコール用)（#8534）
  • ListenableRouterの一部の変数にvolatile修飾子を追加（#8579）
  • アプリ、グループ、URLのバージョン値の取得を調整（#8582）
  • サービスのエクスポートと参照の悪臭を修正（#8594）
  • アプリのメタデータ情報をレポートする前に、リモート レポート メタデータを有効にするかどうかを確認します（#8597）
  • トリプルプロトコル用のヘッダーフィルターを追加（#8585）
  • オペレーションハンドラの削除（#8637）
  • spi拡張機能のスコープを調整（#8600）
  • スロー可能な tw-bin ヘッダーを削除し、例外を切り詰めました（#8642）
  • サービスのエクスポートに遅延を使用する場合、例外をキャッチしてログに記録します。（#8584）
  • 最適化: トリプルプロトコルのデモを追加する例（#8643）
  • 有効なgen MethodDescriptorを追加し、奇妙な状況を回避（#8651）
  • ApplicationModel destroy サポートと ut サポートを追加（#8673）
  • 無害な例外をキャッチする（#8663）
  • エグゼキュータのOnError（#8668）
  • Java シリアル化にシリアル化警告メッセージを追加（#8716）
  • 優先プロトコルフォールバック戦略を追加（#8699）
  • 破棄または停止する前にリソースをクリーンアップ（#8636）
  • Interface-appNameマッピングでユーザー視点で成功か失敗かを判断（#8721）
  • ローカルアドレス取得方法の簡素化と統一（#8677）
  • RegistryProtocol.unexport で非 null リスナーのみサブスクライブ解除する（#8682）
  • TripleRpcException（#8712）を削除
  • 類似コードを削除（#8671）
  • エラー通知時のログ出力を追加（#8729）
  • ServiceAddressURLに適応するConsumerUrlを追加（#8731）
  • 重複した catch ブロックを削除（#8750）
  • フェイルバックのリトライ失敗を先に判定する（#8719）
  • InternalThreadLocalMapのデフォルトコンストラクタで容量を計算（#8697）
  • DefaultFuture はチャネルのロギング最適化をオフにします（#8775）
  • 未使用の呼び出し元を破棄する場合は、直ちに client を閉じる（#8755）
  • Java コレクションの非効率的な使用法 (#8784)
  • Promise catchサーバーを使用して大きなヘッダー例外を送信（#8774）
  • AbstractRegistryFactoryのリファクタリング（静的フィールドそのもの） （#8808）

依存関係の変更

  • キュレーターバージョンのアップグレード：5.0.0 -> 5.1.0
  • ナコスのアップグレード ： 2.0.2 -> 2.0.3
