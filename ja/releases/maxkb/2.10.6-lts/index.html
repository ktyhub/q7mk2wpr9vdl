MaxKB v2.10.6-lts

MaxKB v2.10.6-lts

セキュリティ脆弱性の修正

  • セキュリティ: チャット ファイルのアップロードによりアプリケーションの属性が偽装され、匿名で読み取られ、アプリケーションの名前空間へのコンテンツの挿入が可能になるセキュリティ脆弱性を修正しました。
  • セキュリティ: ドキュメント/段落の移行でソース ナレッジ ベースのアクセス許可のみが検証され、クロステナント コンテンツ インジェクションと RAG ポイズニングにつながるセキュリティ脆弱性を修正しました。
  • セキュリティ: XLSX 埋め込み画像解凍にピクセル数制限がなく、認証されたユーザーがメモリを使い果たすサービス拒否 (DoS) を引き起こす可能性があるというセキュリティ脆弱性を修正しました。
  • セキュリティ: 問題/batch_association に所有権の検証が不足し、テナント間の段落コンテンツの開示 (IDOR) につながるセキュリティの脆弱性を修正しました。
  • セキュリティ: 匿名アプリケーション プロファイル エンドポイントがデータをシリアル化しすぎ、機密構成の漏洩を引き起こすセキュリティ脆弱性を修正しました (/chat/api/application/profile)。
  • セキュリティ: パスワード リセット検証コード エンドポイントに推測試行制限がなく、不正なアカウント乗っ取りが可能になるというセキュリティ脆弱性を修正しました。
  • セキュリティ: 関数ライブラリのサンドボックスがバイパスされる可能性があるセキュリティ脆弱性を修正しました (dlopen スタック チェックはバイパス可能 + dlsym(RTLD_NEXT) はインターセプトされません) (CVE-2026-79919)。
  • セキュリティ: Python のファイル記述子形式 os.execve(fd,...) のサポートを利用して libc fexecve 呼び出しパスに入り、サンドボックス バイパスを引き起こす可能性があるセキュリティ脆弱性を修正しました (NVDB-CAIVD-2026208648)。
  • セキュリティ: ゲスト セッションの所有権の検証が欠落し、ゲスト セッション間の書き込み (セッション整合性違反) を引き起こすセキュリティ脆弱性を修正しました。
  • セキュリティ: デフォルトのハードコーディングされた Django SECRET_KEY により署名付きトークンがオフラインで偽造され、その結果不正なファイル アクセスが発生するセキュリティ脆弱性を修正しました。

新機能

  • ワークフローのデフォルトモデル設定 MaxKB v2.10.6 LTS コミュニティ エディションでは、エージェント ワークフロー、ナレッジ ベース ワークフロー、およびワークフロー ツールにワークフローのデフォルト モデル設定が導入されました。以前は、マルチ AI ノードのワークフローでは、各ノードを個別に開いてモデル構成を変更する必要があり、比較的面倒でした。現在では、単一の構成がグローバルに有効になり、メンテナンス コストが大幅に削減され、バッチ モデル切り替えの一貫性と効率が向上します。デフォルトのモデル設定の中核となる機能は次のとおりです。
  • ワークフローレベルのデフォルトのモデル構成エントリ。
  • 新しく作成されたノードはデフォルトのモデルを自動的に継承します。
  • ノードは柔軟なモデル選択モードをサポートします (ノード タイプに応じて、デフォルト / カスタム / 参照変数)。
  • デフォルト モデルは 1 つの click ですべてのノードに適用でき、すべてのノードのモデル ソースをデフォルト モデルに均一に切り替えます。
  • デフォルト モデルへの 1 つの変更は、複数のノードにわたって有効になります。
  • 公開前に構成の完全性が保証されます。
  • Tencent Hunyuan と Tencent クラウド プロバイダーが新しい「Tencent Cloud」プロバイダーに統合 (Tencent Cloud TokenHub と統合) Tencent Cloud による調整により、MaxKB v2.10.6 LTS コミュニティ エディションでは、Tencent Hunyuan と Tencent Cloud プロバイダーが新しい「Tencent Cloud」プロバイダーに統合されました。 Tencent Hunyuan または従来の Tencent クラウド プロバイダー統合に基づいて以前に構成されたすべてのモデルは、アップグレード後は使用できなくなります。アップグレード後、「モデル プロバイダー」ページに移動し、プロバイダー リストから「Tencent Cloud」を選択し、TokenHub 統合要件に従ってモデル アクセス情報を再構成してください。設定が完了すると、モデルは再び利用できるようになります。 機能の最適化
  • ナレッジ ベース: ナレッジ ベース/ドキュメント リスト セレクターは、ドキュメント/段落の移行時の検索をサポートするようになりました。
  • エージェント: ユーザー入力領域のナレッジ ベース コンポーネントが検索をサポートするようになりました。
  • エージェント: 会話ログ ページの「ナレッジ ベースに追加」機能で、ナレッジ ベースとドキュメント リスト セレクターが検索をサポートするようになりました。

バグ修正

  • ナレッジベース: サイズが大きすぎるセル内容を含む CSV ファイルをインポートすると空の読み取りが発生し、バックエンドで「フィールドがフィールド制限を超えています (131072)」エラーが発生する問題 (#6756) を修正しました。
  • ナレッジベース: データ境界を認識せずに Excel スプレッドシートをインポートすると、多数の空の列がインポートされ、インポート タイムアウトが発生する問題を修正しました (#6355)。
  • ナレッジベース: ヒットテスト中の全文検索で 33 文字連続の「-」を入力すると検索エラーが発生する問題を修正しました。
  • エージェント: 出力コンテンツに null 文字 (\u0000、\x00 など) が含まれている場合に会話エラーが発生する問題を修正しました (#6722)。
  • エージェント: Ascend MindIE ラージ モデルを使用しているときに、アドバンスト エージェントの AI ノードが以前のノードから渡されたデータを受信できない問題を修正しました (#6681)。
  • エージェント: 高度なオーケストレーション AI ノードの「ロール設定」が空の場合にモデルの呼び出しがエラーになる問題を修正しました (#6662)。
  • エージェント: ツールを呼び出した後、ツール実行レコードに表示される実行ソースにエージェント名ではなくツール名が表示される問題を修正しました (#6647)。
  • エージェント: ワークフローナレッジベースにアップロードされたファイルが一時ファイルであり、ファイルがクリーンアップされた後にプレビューとダウンロードが失敗する問題を修正しました (#6785)。
  • エージェント：AI会話ノードのスキルとして使用されるエージェントがメッセージ以外のパラメータを渡せない問題を修正しました。
  • エージェント: ユーザー入力パラメータのコンポーネント タイプをナレッジ ベースに変更した後、デフォルトのナレッジ ベースを設定できないアドバンスト エージェントの問題を修正しました。
  • エージェント: チャット ログをクリアするときにエラーが発生する問題を修正しました (#6690)。
  • モデル: MiniMax H3 テキストからビデオへのモデルが、統合が成功した後の使用中にエラーを報告する問題を修正しました。

MaxKB v2.10.6-lts

Highlights

  • Security posture, not just another patch — This LTS is effectively a security release: 10 fixes spanning multi-tenant isolation, sandbox escapes, and auth. The ones that should drive upgrade urgency are the hardcoded Django SECRET_KEY (offline signing of tokens → unauthorized file access), two function-library sandbox bypasses (CVE-2026-79919 via dlopen/dlsym(RTLD_NEXT), and NVDB-CAIVD-2026208648 via os.execve(fd,...)/fexecve), and a rate-limit-free password-reset code endpoint enabling account takeover. If you expose /chat/api/application/profile or run multi-tenant, note the cross-tenant issues too (document/paragraph migration validation, problem/batch_association IDOR, guest-session writes, chat-file attribution spoofing, and anonymous profile over-serialization). Practical follow-up: set a real secret and rotate/expire outstanding signed tokens, since a forgeable key means old tokens can't be trusted retroactively.
  • Breaking: Tencent Hunyuan + legacy Tencent Cloud collapse into one "Tencent Cloud" provider — Upstream changes mean any model configured against Tencent Hunyuan or the old Tencent Cloud integration stops working immediately after upgrade. There is no compatibility shim: go to Model Providers, select the new "Tencent Cloud" provider, and re-enter credentials per the TokenHub integration before touching workflows. Watch out for agents/workflows that reference those models — they'll fail at runtime until re-pointed, so schedule this as a planned migration, not a drop-in restart.
  • Workflow default model settings — New workflow-level model defaults for agent workflows, knowledge-base workflows, and workflow tools. Newly created nodes inherit the default, nodes can choose Default/Custom/Reference Variable modes as allowed by node type, a one-click "apply to all" rewrites every node's model source, a single default edit fans out across nodes, and completeness is validated before publish. This targets the real pain of multi-AI-node workflows — avoid opening each node to swap models — and reduces config drift. Caveat for existing workflows: saved nodes keep their custom model config until you explicitly use apply-to-all, so consolidation isn't automatic.
  • Ingestion and agent-runtime reliability fixes — Several blockers for real deployments: CSV imports with cells over 131072 chars no longer fail with field larger than field limit (#6756); Excel imports detect data boundaries to avoid empty-column blowups and timeouts (#6355); null characters in model output no longer crash conversations (#6722); Ascend MindIE AI nodes now receive upstream node data (#6681); empty Role Settings no longer error (#6662); uploaded workflow-KB files are persisted so preview/download survive cleanup (#6785). Also fixed: tool records showing tool name instead of agent name (#6647), agents-as-skills dropping non-message params, full-text search choking on 33 consecutive hyphens, chat-log clearing (#6690), and MiniMax H3 text-to-video errors.
  • Search where it was missing — The knowledge base/document selectors used for document/paragraph migration, the agent input-area knowledge-base component, and the conversation-log "Add to Knowledge Base" pickers now support search. Minor on its own, but it removes a genuine scaling problem when selecting among many KBs/documents during the very migration flows touched by the security fixes above.

Security Vulnerability Fixes

  • Security: Fixed a security vulnerability where Chat file uploads could spoof APPLICATION attribution and be read anonymously, allowing content injection into the application namespace.
  • Security: Fixed a security vulnerability where document/paragraph migration only validated source knowledge base permissions, leading to cross-tenant content injection and RAG poisoning.
  • Security: Fixed a security vulnerability where XLSX embedded image decompression lacked a pixel count limit, allowing authenticated users to trigger memory-exhaustion denial of service (DoS).
  • Security: Fixed a security vulnerability where problem/batch_association lacked ownership validation, leading to cross-tenant paragraph content disclosure (IDOR).
  • Security: Fixed a security vulnerability where the anonymous application profile endpoint over-serialized data, causing sensitive configuration disclosure (/chat/api/application/profile).
  • Security: Fixed a security vulnerability where the password reset verification code endpoint lacked a guessing attempt limit, allowing unauthorized account takeover.
  • Security: Fixed a security vulnerability where the function library sandbox could be bypassed (dlopen stack check bypassable + dlsym(RTLD_NEXT) not intercepted) (CVE-2026-79919).
  • Security: Fixed a security vulnerability where Python's support for file descriptor form os.execve(fd,...) could be leveraged to enter the libc fexecve call path, causing sandbox bypass (NVDB-CAIVD-2026208648).
  • Security: Fixed a security vulnerability where guest session ownership validation was missing, leading to cross-guest-session writes (Session Integrity Violation).
  • Security: Fixed a security vulnerability where the default hardcoded Django SECRET_KEY allowed signed tokens to be forged offline, resulting in unauthorized file access.

New Features

  • Workflow Default Model Settings In the MaxKB v2.10.6 LTS community edition, workflow default model settings have been introduced for agent workflows, knowledge base workflows, and workflow tools. Previously, multi-AI-node workflows required opening each node individually to modify model configurations, which was relatively cumbersome. Now, a single configuration takes effect globally, significantly reducing maintenance costs and improving the consistency and efficiency of batch model switching. Core features of the default model settings include:
  • A workflow-level default model configuration entry;
  • Newly created nodes automatically inherit the default model;
  • Nodes support flexible model selection modes (Default / Custom / Reference Variable, depending on node type);
  • The default model can be applied to all nodes with one click, uniformly switching all nodes' model sources to the default model;
  • A single change to the default model takes effect across multiple nodes;
  • Configuration completeness is ensured before publishing.
  • Tencent Hunyuan & Tencent Cloud Providers Merged into the New "Tencent Cloud" Provider (Integrated with Tencent Cloud TokenHub) Due to adjustments by Tencent Cloud, in the MaxKB v2.10.6 LTS community edition, the Tencent Hunyuan and Tencent Cloud providers have been merged into a new "Tencent Cloud" provider. All models previously configured based on the Tencent Hunyuan or legacy Tencent Cloud provider integration will no longer be usable after the upgrade. After upgrading, please go to the "Model Providers" page, select "Tencent Cloud" from the provider list, and reconfigure your model access information according to the TokenHub integration requirements. Once configured, the models will be available again. Feature Optimizations
  • Knowledge Base: The knowledge base/document list selector now supports search when migrating documents/paragraphs.
  • Agent: The knowledge base component in the user input area now supports search.
  • Agent: In the "Add to Knowledge Base" feature on the conversation log page, the knowledge base and document list selectors now support search.

Bug Fixes

  • Knowledge Base: Fixed an issue where importing a CSV file with over-sized cell content resulted in empty reads and a "field larger than field limit (131072)" error in the backend (#6756).
  • Knowledge Base: Fixed an issue where importing Excel spreadsheets without recognizing data boundaries caused large numbers of empty columns to be imported, leading to import timeouts (#6355).
  • Knowledge Base: Fixed an issue where entering 33 consecutive "-" characters in full-text search during hit testing caused a search error.
  • Agent: Fixed an issue where conversations errored when output content contained null characters (\u0000, \x00, etc.) (#6722).
  • Agent: Fixed an issue where AI nodes in advanced agents could not receive data passed from previous nodes when using the Ascend MindIE large model (#6681).
  • Agent: Fixed an issue where calling the model errored when the "Role Setting" of an advanced orchestration AI node was empty (#6662).
  • Agent: Fixed an issue where, after invoking a tool, the execution source shown in tool execution records displayed the tool name instead of the agent name (#6647).
  • Agent: Fixed an issue where files uploaded to workflow knowledge bases were temporary files, causing preview and download failures after the files were cleaned up (#6785).
  • Agent: Fixed an issue where an agent used as a skill of an AI conversation node could not pass parameters other than message.
  • Agent: Fixed an issue in advanced agents where the default knowledge base could not be set after changing the component type of user input parameters to knowledge base.
  • Agent: Fixed an issue where an error occurred when clearing chat logs (#6690).
  • Model: Fixed an issue where the MiniMax H3 text-to-video model reported errors during use after successful integration.
