angular v22.1.3

Highlights

  • DOM and hydration failures are easier to diagnose in production — Hydration now throws NG0500 for unexpected node types and NG0502 for missing nodes instead of raw TypeErrors (#69981, #70199); stale insertBefore references now produce NG05106 rather than an opaque NotFoundError (#70186). Update error-monitoring mappings, but fix the underlying DOM or template mismatch rather than suppressing these errors.

  • Effect flushes stop after view destruction — If an effect destroys its view, Angular now skips the remaining effects in that flush, preventing execution against torn-down state and crashes from a null effects list (#65698). Register onCleanup() before destroying the view; cleanup registered afterward is no longer guaranteed to run.

  • Oversized fetch responses release their connections — FetchBackend cancels an unread response body before throwing NG02825 when the declared Content-Length exceeds maxResponseSize (#70210). This prevents lingering SSR connections after rejection without changing the error contract.

  • Named-outlet deactivation guards receive the actual component — For named outlets beneath componentless parent routes, canDeactivate previously received null; outlet contexts are now resolved per child and switched correctly across component boundaries (#69591, fixing #34614). Re-test unsaved-changes guards that rely on component identity.

  • Forms and metadata validation are stricter — [formField] now reports unsupported two-way bindings at compile time (#70220); dev mode emits NG01354 when ngModel cannot reach a parent NgForm across a component boundary, suggesting viewProviders or standalone: true (#69585); and Meta.addTag()/updateTag() reject on* attributes with NG05203 (#70127). Audit dynamic meta definitions and move event behavior out of inline attributes.

  • Type and template fidelity fixes remove avoidable workarounds — KeyValuePipe.transform() preserves literal key unions instead of widening them to string (#70200), generated decorator reflection metadata accepts readonly arrays and tuples, and the compiler retains &ngsp; between unrelated sibling control-flow blocks (#69583). Typed pipe consumers can drop casts, while affected templates avoid spacing regressions.

No breaking changes announced.
