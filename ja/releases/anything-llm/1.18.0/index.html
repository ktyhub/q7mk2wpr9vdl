anything-llm v1.18.0

Highlights

  • Attachment and chat-state reliability — A large cluster of fixes makes file/image handling dependable: no crash when removing a parsed file while an image is attached (#6585), the correct image opens when attachments share a filename (#6586), attachment/upload state is isolated per conversation (#6635), MBOX attachments survive orphan cleanup (#6633), transcription/OCR settings reach linked files (#6697), and unsent prompt text is preserved when attaching a file spawns a new thread (#6704). History attachments are no longer sent to providers that build prompts from raw chat history (#6591), avoiding provider-side errors. Anyone with multi-attachment conversations benefits most.

  • Agent tool-calling and provider compatibility — Required tool params are now sent on every provider path (#6595), Anthropic agent providers are asked for serial tool use (#6708), and the workspace similarity threshold is applied to agent rag-memory search (#6648). The SDK honors ANYTHINGLLM_MAX_RETRIES (#6597), and TOOL_CALL_APPROVAL_TIMEOUT_MS now applies to Telegram tool approvals (#6601). Agent users running multiple providers should upgrade to avoid silently dropped tool parameters and inconsistent behavior.

  • Scheduled jobs, timezones, and multi-user correctness — Hourly schedules convert the minute to UTC correctly in half-hour-offset timezones (#6605), stopped runs finalize on Windows (#6637), queued runs are cancelled when a job is disabled or resynced (#6710), and jobs stop after switching to multi-user mode (#6656); raw "think" blocks in scheduled responses after tool calls are cleaned up (#6663). Important if you rely on scheduled jobs, especially outside UTC or on Windows.

  • Ingestion, collector, and vector-store correctness — The collector stops treating converter-less binary types as text (#6670), de-duplicates bulk links differing only by #fragment (#6619), and writes same-named scraped pages to separate files (#6650); Confluence (#6652) and Paperless-ngx (#6699, #6698) failures are surfaced instead of silently reported as empty, and YouTube channel URLs are no longer misread as videos (#6644). Document embedding is restored for AstraDB (#6654), PGVector transaction failures propagate the original error (#6706), Kubernetes probes now point at /api/ping (#6592), and unknown workspaces on manage-users/update-pin return 404 (#6625).

  • Verdict — no breaking changes, worth upgrading for most — There are no breaking changes or migration steps, and this is not a no-op/re-tag: it is a broad bug-fix release (the final PR #6711 is only version tagging). Notably, unknown usernames and wrong passwords now return the same login error (#6693), closing a user-enumeration leak, and prompt variable expansion preserves $$ and $& (#6676). Upgrade if you use attachments, agents, scheduled jobs, the collector, or k8s/AstraDB/PGVector deployments; only a narrow single-user setup using none of these, with no need for the security hardening, can safely skip.
