career-ops web-v0.15.0

Highlights

  • Reports become a workbench, not a read-only scorecard — The report view gains ATS keyword coverage (#4579), a company evidence card (#4581, which also fixes the data root it reads from), an interview prep pack per report (#5216), and cover-letter drafting inline (#5258). Combined with the new CV studio edit model + API for tailored CVs (#5232) and a generated-documents dashboard (#4856, #4958), this release turns report data into something you can act on and export. If you generate tailored CVs or cover letters, this is the headline reason to upgrade.

  • Follow-ups and pipeline get real workflow control — New Assessment lifecycle and follow-up status controls (#4317), the ability to turn follow-ups off entirely (#5164), upcoming follow-ups surfaced on the follow-ups page (#5129), bulk status edits across several tracker rows from the pipeline table (#5187), and side-by-side comparison of 2–3 pipeline rows (#5223). Teams stuck with fixed follow-up behavior now have opt-out and bulk-edit levers — worth upgrading for anyone running a high-volume pipeline.

  • Analytics and "Today" change shape — and the numbers change with them — Analytics expands into progress and search stats (#4310); Today cards now show the evaluator's call and reason (#5215) and are ranked by score with an apply-next link (#5235); and modes/_profile.md can be filled from the assistant behind a confirm gate with a live onboarding panel (#4256). Important: analytics now counts only in-flight rows as active applications (#5186), so dashboards will show fewer "active applications" after the upgrade — treat that as a metric-definition change, not data loss.

  • Security and input hardening (behavioral changes, not flagged as breaking) — Evaluating untrusted JDs now denies Write/Bash tools (#3629), the Apply session rejects private URLs (#3627), a non-object JSON body returns 400 instead of 500 (#5188), tailored CVs attach to localized resume upload fields (#5162), and non-ASCII CV/cover PDF filenames are served correctly (#5163). No migration steps are called out, but automation that relied on Write/Bash during JD evaluation or private URLs in Apply sessions will find those paths blocked — review those flows before upgrading.

  • Harness/platform reliability and the upgrade verdict — test-all now runs inline sections alongside discovered suites (#5146, #5150); the harness links the dependency tree a worktree inherits (#5055) and runs against a scratch data root while guarding the real one (#5137); Windows gets EPERM/EACCES lock-mkdir retries (#4917) and no stale-console inheritance (#4253, closes #3809); and the scheduler preserves the original recurrence anchor (#5006). These are safety/quality fixes, not user features. Overall this is a substantive minor release with no explicit breaking changes or migration steps: upgrade if you use reports/documents, follow-ups, analytics, or run the harness/CI on Windows; you can skip if you only need the core tracker and are happy with current report output and metric definitions.
