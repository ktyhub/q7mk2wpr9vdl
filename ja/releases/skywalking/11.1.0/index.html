OTLP トレースからのメトリクスとトポロジ

OpenTelemetry SDK を搭載したアプリケーションでは、サービス ダッシュボード、トポロジ、トレース検索に SkyWalking エージェントが必要なくなりました。 OAP は、到着した OTLP トレースを保存し、新しい Trace Analysis Language (TAL) は、すべてのスパンをサービス、インスタンス、エンドポイントのメトリック、トポロジ、およびサービスが呼び出すデータベース、キャッシュ、メッセージ キューのダッシュボードに変換します。 OpenTelemetry 天文学ショップを 1 つのコマンドでクイック スタートするには、OpenTelemetry Traces in SkyWalking を参照してください。

プロジェクト

  • e2e モック送信者の OTLP プロトを v1.11.1 に更新します。現在の OpenTelemetry コレクターは、メトリックの metadata など、古いコピーに欠けていたフィールドを追加しますが、送信者の厳密な JSON パーサーは、それらを含む記録を拒否しました。 Windows e2e は、GitHub がホストする Windows ランナー上で取得された Windows_exporter 0.31.8 から OpenTelemetry Collector 0.158.0 までの記録を再生し、そのメモリ メトリックをアサートするようになりました。

  • BanyanDB 資格情報ローテーション e2e は、CA ローテーション e2e と同様に、トポロジがコンシューマのプロバイダーへの呼び出しを表示するまで待機してからローテーションします。適用される不完全な資格情報はそのウィンドウでの書き込みに失敗し、ネットワーク アドレス エイリアスの最初の書き込みが含まれていた場合、エイリアスは 5 分後の次の更新までストレージ外に留まり、そのためトポロジ アサーションがタイムアウトしました。

Metrics and Topology from OTLP Traces

Applications instrumented with the OpenTelemetry SDKs no longer need a SkyWalking agent for service dashboards, topology and trace search. OAP stores OTLP traces as they arrive, and the new Trace Analysis Language (TAL) turns every span into service, instance and endpoint metrics, a topology, and dashboards for the databases, caches and message queues the services call. Read OpenTelemetry Traces in SkyWalking for a one-command quick start with the OpenTelemetry Astronomy Shop.

  • Fix Kafka broker throughput and topic metrics. meter_kafka_broker_topic_bytesin_per_second read kafka_server_brokertopicmetrics_bytesout_total, so per-topic inbound traffic matched outbound; it now reads bytesin_total. The Prometheus JMX exporter exports Kafka's BrokerTopicMetrics message, byte and request meters per topic and again as the all-topics total without a topic label, so meter_kafka_broker_messages_per_second, meter_kafka_broker_bytes_in_per_second and meter_kafka_broker_bytes_out_per_second summed both and reported twice the real rate, and every meter_kafka_broker_topic_* metric carried an extra topic="" series holding the broker total, which the Topic Rates chart drew as an extra line. Broker rules now read only the all-topics total and topic rules only the per-topic series. meter_kafka_broker_network_processor_avg_idle_percent applied rate to Kafka's idle-ratio gauge, so it reported how fast the idle percentage changed; it now reports the idle percentage. Values stored before the upgrade keep the old numbers, so these charts step at the upgrade.
  • Fix RabbitMQ node singleblock allocator meters reading multiblock carriers. meter_rabbitmq_node_allocated_singleblock_used / _unused copied kind=mbcs, so the Singleblock charts matched Multiblock; they now use kind=sbcs, and _unused subtracts the used blocks size from the carriers size, as RabbitMQ's Erlang memory allocators dashboard does, instead of reporting the whole carriers size. Values stored before the upgrade keep the old numbers, so these charts step at the upgrade.
  • Fix PostgreSQL temporary-files rate reading temp bytes. meter_pg_temporary_files_rate / meter_pg_instance_temporary_files_rate used pg_stat_database_temp_bytes, so the Temporary Files / s charts showed byte throughput; they now use pg_stat_database_temp_files, and no chart shows the temporary-file byte throughput. Values stored before the upgrade keep the old numbers, so these charts step at the upgrade.
  • Fix Zabbix agent filesystem usage percentage reading inode usage. meter_vm_filesystem_percentage used vfs.fs.inode pused, so the File System Mountpoint Usage chart showed inode occupancy; it now uses the agent's vfs.fs.size[/,pused], the space usage df and the Telegraf VM rule report, which leaves the space reserved for root out (the OTEL VM rule counts that space as used, so it reads higher on the same disk). Add vfs.fs.size[/,pused] to the required item keys, and drop unused vfs.fs.inode[/,pused] and the duplicate vm.memory.size[pavailable]. Values stored before the upgrade keep the old numbers, so this chart steps at the upgrade.
  • AI agent conversations read a tool call as its arguments, as the AI Sessionizer does (apache/skywalking-ai-sessionizer#94). A step on one part of a record reads that part alone. A tool call that shares a record with the agent's text read as that text, and now reads as its arguments. A queued command reads as the prompt inside its own part, never as text another part of the record holds.
  • Add the OTLP_MESH layer for the spans of service mesh sidecars that report over OTLP, such as Istio's Envoy. No shipped TAL rule analyzes it, so the sidecars' spans are stored and searchable ({resource.service.layer="OTLP_MESH"} in TraceQL) but not analyzed.
  • The OTLP service catalog keeps each service's service.layer, UNDEFINED when absent or unregistered, in the otlp_service_layer column, and the stored span carries the same value. A TraceQL q on resource.service.layer alone lists the services from the catalog.
  • Write a network address alias only when its mapping changes, or once per five minutes to keep it in the alias cache's ten-minute reload window; a changed mapping is written at the next flush. The alias's last_update_time_bucket is the minute OAP received it rather than the span's time, so an agent's clock skew or a late segment cannot leave a changed alias outside the cache reload. NetworkAddressAlias#combine used to rewrite every alias at every persistence period, about 140 writes an hour for a stable alias, now about twelve.
  • Fix RabbitMQ node multiblock and multiblock-pool unused meters reporting whole carriers size. meter_rabbitmq_node_allocated_multiblock_unused / _multiblock_pool_unused now subtract the used blocks size from the carriers size, matching the singleblock unused formula and RabbitMQ's Erlang memory allocators dashboard. Values stored before the upgrade keep the old numbers, so these charts step at the upgrade.
  • Fix RabbitMQ node publisher count using channels minus channel consumers. meter_rabbitmq_node_publisher_total computed rabbitmq_channels - rabbitmq_channel_consumers, which counts channels without a consumer rather than publishers: a basic.get polling channel counted as a publisher, a channel that both publishes and consumes did not, and a channel with several consumers drove the value below zero, stored as 0. It now reads rabbitmq_global_publishers, which RabbitMQ counts correctly from 3.10.11 and 3.11.3. Values stored before the upgrade keep the old numbers, so this chart steps at the upgrade.
  • Fix MySQL connection-errors-for-max-connections reading a mistyped exporter label. meter_mysql_connection_errors_max_connections / meter_mysql_instance_connection_errors_max_connections filtered error=max_connection, while mysqld_exporter exposes Connection_errors_max_connections as error=max_connections, so live scrapes never matched and the chart stayed empty; the filter now uses max_connections.
  • Add server clusters, server-clusters.yml and its dynamic configuration item core.default.serverClusters, to show a message broker, a database or a cache that clients reach at more than one address as one service. An address listed under a cluster's members or aliases, or a list of addresses, such as a Kafka client's bootstrap servers, whose every element is listed under one cluster in any order, is renamed to the cluster by the native trace analysis where no network alias maps the address, and by the OpenTelemetry trace analysis through the new TAL function findServerClusterName, which the shipped tal/otlp-general.yaml calls for brokers, databases and caches. A cluster may declare the scheme its clients write before an address, as written, such as pulsar://, and kinds, names of the user's choosing that a custom TAL rule may pass as findServerClusterName(address, kind) to match only the clusters of that kind; the native trace analysis and the shipped TAL rules do not use kinds. The file is empty by default, so nothing is renamed until a cluster is listed.
  • Bump dependencies to clear CVE alerts on shipped OAP jars: jackson 2.18.8 → 2.18.12, guava 32.0.1-jre → 33.7.2-jre, micrometer 1.14.4 → 1.16.8, log4j 2.25.4 → 2.25.5, freemarker 2.3.31 → 2.3.35 and postgresql 42.7.11 → 42.7.14. Micrometer 1.14.x has no open-source fix, and Armeria 1.34.2 is built against micrometer 1.16.0, which the old pin downgraded.
  • Bump dependencies to clear CVEs on shipped OAP jars that Dependabot does not see, because their versions come from a BOM or a transitive dependency: netty 4.2.15.Final → 4.2.19.Final (with netty-tcnative-boringssl-static 2.0.77.Final → 2.0.84.Final, the version netty 4.2.19.Final is built with), and, pulled in by kafka-clients, lz4-java 1.10.1 → 1.11.4 and snappy-java 1.1.10.5 → 1.1.10.12.
  • Add HTTP alarm hook delivery self-observability metrics, alarm_http_delivery_total, alarm_http_delivery_status_total and alarm_http_delivery_latency_seconds, on telemetry.prometheus, labeled by hook_type and by result or status_class. result names why a delivery failed (auth_failed, rate_limited, rejected, server_error, token_error, timeout, io_error, interrupted) and reads the error code DingTalk, WeCom, Feishu and WeLink return in a 2xx body, so such a refused message is now logged as a failure instead of passing as delivered. A WeLink access-token response without a token now skips the messages of that webhook URL instead of sending them with an empty token. The otel-rules/oap.yaml rules add meter_oap_instance_alarm_http_delivery_count, meter_oap_instance_alarm_http_delivery_status_count and meter_oap_instance_alarm_http_delivery_latency_percentile to the OAP self-observability layer, and the OAP Grafana dashboards chart the raw series.
