tempo v3.0.0

メジャー 公開日2026年5月28日 出典grafana/tempo English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#テンポv3.0.0 Tempo 3.0 は、新しい取り込み/書き込みアーキテクチャへの移行を完了し、非推奨の 2.x コンポーネントを削除し、TraceQL メトリクスを一般提供に段階的に移行し、Tempo 2.x ユーザー向けの移行ツールを追加するメジャー リリースです。 このリリースには、構成およびデプロイメントに重大な変更が含まれています。特にレガシー インジェスター、レガシー オーバーライド、v2 ブロック、OpenCensus、ローカルブロック、またはカスタムの live-store/query-frontend 設定を使用している場合は、アップグレードする前に移行ガイドを確認してください。

ハイライト

  • 新しい取り込み/書き込みアーキテクチャが従来のインジェスタを置き換えます。
  • TraceQL メトリクスは一般提供されています。 TraceQL メトリクスに関するアラートと高速読み取りパスは実験段階のままです。
  • vParquet5 の改善とメトリクス クエリ パスの高速化。
  • カーディナリティ管理のためのメトリクス ジェネレーター コントロールを拡張しました。
  • トレース編集のサポート。
  • オテルパイロスコープによるスパンプロファイリングのサポート。
  • ライブストアとブロックビルダーの正確性と可観測性を修正しました。 役立つリンク:
  • Release note: https://grafana.com/docs/tempo/latest/release-notes/v3-0/
  • 移行ガイド: https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/migrate-to-3/
  • アップグレードガイド: https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/upgrade/
  • Changelog: https://github.com/grafana/tempo/blob/v3.0.0/CHANGELOG.md#v300

特徴

  • #7012 の @stoewer による構成およびクエリ ヒントを介して個々の AST 変換をスキップ可能にします
  • otelpyrscope を介したスパン プロファイリングのサポートを追加します。 #7063 の @simonswine により、span_profiling: true または -span-profiling CLI フラグを使用して OTel スパンに pprof ラベルを付加できるようにします
  • #6982 の @mapno により、Tempo 2.x 設定を 3.0 に移行するための tempo-cli migrate config コマンドを追加
  • jsonnet: #6970 の @mapno によるマイクロサービス デプロイメント用の KEDA ベースの水平ポッド自動スケーリング サポートを追加
  • 自動 GOMEMLIMIT 構成のための automemlimit サポートを追加します。 #6313 の @oleg-kozlyuk-grafana による memory.automemlimit_enabled: true で有効化
  • TraceQL メトリクス クエリでの比較演算子をサポート (#6474 の @ruslan-mikhailov による)
  • metrics-generator: #6453 の @javiermolinar による filter_policies を通じてサービス グラフにスパン フィルタリングを追加
  • #6392 の @javiermolinar によるスパンメトリクス フィルター用の新しい include_any フィルター ポリシーを追加
  • span_multiplier_key をオーバーライドに追加します。これにより、テナントは、#6260 の @carles-grafana によるヘッドベースのサンプリングを補正するために、スパン乗数の値に使用される属性キーを指定できるようになります。
  • metrics-generator: #6414 の @electron0zero によりカーディナリティを制御するラベルごとのリミッターを追加
    • テナントごとの max_cardinality_per_label オーバーライドと、ラベルごとのカーディナリティの需要を推定するための新しいメトリクスを追加します。
  • #6758 で @stoewer によるテナントごとのオーバーライドのための拡張メカニズムを追加
  • #6811 の @stoewer による ErrTraceHidden 経由の完全なトレースの非表示をサポートするために TraceRedactor インターフェイスを拡張しました。
  • シングルバイナリ モード: #6729 の @javiermolinar により、Kafka を使用せずにディストリビュータのローカル インジェストをライブストアとメトリクス ジェネレータに直接プッシュします
  • 試験的なドレイン リミッター/スパン名のサニタイズをメトリクス ジェネレーターに追加し、#6098 の @Logiraptor によって類似のスパン名をクラスタリングすることでメトリクスのカーディナリティを削減します。

機能強化

  • クエリ フロントエンド: デフォルトの client との互換性を向上させるために、ストリーム検索とメトリクスの応答をより小さな gRPC パケットに分割し、#6607 / #7239 で @mdisibio によってメトリクス シリーズの制限に達した後の最終ストリーミング更新を修正しました。
  • live-store: atomic.Pointer[blockSnapshot] を介したロックフリーのブロック読み取り。 #7132 の @zhxiaogg によるブロック削除は 2 段階でクラッシュセーフです
  • #6827 の @ie-pham によるタグ名とタグ値のオートコンプリートの OR 条件のサポート (検索タグ v2)
  • #6561 の @rwhitty による S3 設定経由で MinIO 再試行設定を公開
  • デフォルトのライブストア WAL サイズを削減し、クエリのデフォルトを調整します: max_block_duration 1 分から 30 秒、max_block_bytes 100MiB から 50MiB、complete_block_timeout 1 時間から 20 分、メトリクス query_backend_after 30m から 15m (#6974 の @zhxiaogg による)
  • tempo_request_duration_seconds を含むすべての promauto 登録ヒストグラムのネイティブ ヒストグラム出力を有効にします。クラシック形式とネイティブ形式の両方が同時に出力されます。既存のスクレーパーは #6910 の @zalegrala の影響を受けません。 -tempo-cli: #6768 の @Nouuu により、カスタム ヘッダーの api コマンドをクエリするための --header フラグを追加しました。
  • Tempo-cli: #6832 の @zalegrala により、トレース編集ジョブをバックエンド スケジューラに送信するための redact コマンドを追加しました。
  • ブロック ビルダー: ブロック作成中にトレース内のスパンを重複排除し、#6539 の @zhxiaogg による tempo_block_builder_spans_deduped_total メトリクスを介して削除された重複を追跡します。
  • metrics-generator: #6684 の @csmarchbanks による enable_tracestate_span_multiplier 設定オプションを介して、W3C トレースステート OTel 確率サンプリングしきい値からのスパン乗数の抽出をサポートします。
  • @javiermolinar による新しいアラートと Runbook エントリを #6276 に追加
  • vParquet5 の専用文字列列の最大数を 2 倍にし、#6282 の @mdisibio によってデータの最適な数を決定するために、tempo-cli を更新します。
  • TraceQL メトリクス: ほとんどのメトリクス クエリに対する実験的な高速読み取りパス。#6359 で @mdisibio によって unsafe_query_hints が有効になっている場合、クエリ ヒント spanonly_fetch=true の背後でアクセスできます。
  • TraceQL メトリクス: #6849 の @mdisibio により、ほとんどのメトリクス クエリに対する新しい実験的な高速読み取りパスをオプトインまたはオプトアウトするための新しいテナントごとのオーバーライドを追加します。
  • Vulture: データ整合性チェックを拡張して、リソース/スパン/イベント スコープでより多くの文字列、整数、BLOB を含めるようにし、#6731 の @mdisibio によるより詳細なトレース コンテンツ チェックを実行します。
  • #6400 の @javiermolinar による属性切り捨て可観測性の向上
  • @carles-grafana による #6467 の切り詰められた特大属性のログ
  • ライブストア: #6371 の @carles-grafana による trace_too_large ログ行を洞察にします
  • #6409 の @oleg-kozlyuk-grafana による古い所有者のエントリを防ぐために、シャットダウン時にリングからライブストアのパーティション所有者を削除します。
  • ライブ ストアの準備状況チェックが改善され、readiness_target_lag および readiness_max_wait 構成パラメーターが追加されました。 Live ストアは、readiness_target_lag が設定されている場合、#6238 と #6405 の @oleg-kozlyuk-grafana と @ruslan-mikhailov によって Kafka ラグが指定された値以下になるまで、/ready を報告しなくなりました。
  • #6343 の @javiermolinar により、クエリ分布ごとのジョブを追跡するための新しいヒストグラム メトリクスを公開します。
  • #6407 の @electron0zero によるユーザー構成可能なオーバーライド API でフィルター ポリシーの詳細な検証を実行します。
  • #6411 の @Logiraptor によるユーザー構成可能なオーバーライド API を介して span_name_sanitization を設定できるようにする
  • #6363、#6567、#7066 で @ruslan-mikhailov と @carles-grafana によって遅れている場合にライブストアが失敗できるように fail_on_high_lag パラメーターを追加しました。
  • #6489 の @mapno によるテナントごとのトレース ID の左パディングのサポートを追加
  • ジェネレーターリングサイズの新しいメトリクスを追加: #5686 の @zalegrala による tempo_distributor_metrics_generator_tenant_ring_size
  • vParquet5 コンパクター/ブロック作成での明示的な runtime.GC() 呼び出しと #6603 の @oleg-kozlyuk-grafana による CLI を削除
  • #6863 の @mapno による WAL 書き込みおよびブロック作成中の extendReuseSlice 成長パスの割り当てを削減します。
  • #6757 の @zhxiaogg により、同じライブストア ゾーン内のポッドのアンチアフィニティが実装されました。
  • ライブストア: #6839 で @zhxiaogg によりシャットダウン中に WAL 完了操作をスキップしました
  • @zhxiaogg によるライブストアのブロックカット理由を追跡するためのメトリクスを #6922 で追加
  • #6967 の @zhxiaogg により、WAL 完了パスの非同期寄木細工読み取りモードを有効にします
  • metrics-generator: #6575 の @zalegrala によるセッション タイムアウトを待つ代わりに、シャットダウン時に LeaveGroup を送信して即時パーティションの再割り当てを行うために leave_consumer_group_on_shutdown を追加しました。

重大な変更

テンポ 3.0 には、オペレータに影響を与えるいくつかの削除とデフォルトの変更が含まれています。アップグレードする前に移行ガイドを確認してください。

  • 従来のインジェスターベースの書き込みパスは削除されました。デプロイメントは、3.0 取り込み/書き込みアーキテクチャに移行する必要があります。
    • #6504 / #6959 の @javiermolinar によるインジェスターとインジェスター モジュールを削除
    • #6667 / #6873 の @javiermolinar による残りのアプリ インジェスター設定と ingest.enabled を削除しました
    • #6981 の @javiermolinar によるパーティション リング ライブストア設定を削除しました。
    • #6369 の @javiermolinar によるインジェスターとコンパクターのアラートを削除しました
  • #6273 の @joe-elliott による v2 ブロック エンコーディングとレガシー v2 コンパクター コンポーネントを削除しました。
    • v2 固有の CLI コマンド: list block、list index、view index、gen index、および gen bloom を削除しました。
  • 集中ブロックと WAL 構成: block_builder と live_store は常に storage.trace.block 設定を使用するようになりました。モジュールごとのブロック設定フィールドは #6647 で @stoewer によって削除されました
  • 最近のデータ クエリは、インスタンスが遅れているときに失敗することで完全な結果を保証するようになりました。 #7210 / #7232 の @mapno によるデフォルトの query_frontend.query_end_cutoff から 30s および live_store.fail_on_high_lag から true
  • デフォルトでレガシー (フラット、スコープなし) オーバーライドを無効にしました。レガシーオーバーライドが検出された場合、Tempo は開始を拒否します。 enable_legacy_overrides: true または -config.enable-legacy-overrides=true を一時的にオプトインに戻すように設定します。レガシーオーバーライドは、#6741 の @electron0zero によって将来のリリースで削除される予定です
  • ユーザー構成可能なオーバーライド設定 metrics_generator.processors は、ランタイム オーバーライドとマージされなくなりました。 metrics_generator.processors は実行時オーバーライドよりも優先され、ユーザー構成可能なオーバーライド内の他のすべての構成と一致します。 processors: [] を設定すると、#7176 / #7185 の @electron0zero によってテナントのすべてのプロセッサが無効になります
  • RetryInfo をデフォルトで有効にしました。 distributor.retry_after_on_resource_exhausted はデフォルトで 5s (以前は 0) になったので、OTLP clients は #7088 の @electron0zero によって ResourceExhausted エラーに関する再試行ヒントを受け取ります。
    • 0 に設定してクラスター全体で無効にするか、テナントごとのオーバーライド ingestion.retry_info_enabled: false を設定して単一のテナントに対して無効にします。
  • #6909 の @electron0zero により、CompactorConfig CLI フラグから重複した compaction プレフィックスを削除しました。
    • compaction.compaction.block-retention → compaction.block-retention
    • compaction.compaction.max-objects-per-block → compaction.max-objects-per-block
    • compaction.compaction.max-block-bytes → compaction.max-block-bytes
    • compaction.compaction.compaction-window → compaction.compaction-window
  • #6523 で @javiermolinar によって OpenCensus レシーバーを削除
  • #6403 の @orkhan-huseyn による従来の mem-ballast-size-mbs CLI フラグを削除しました -tempo-cli: 開始/終了引数の相対時間 (now、now-1h) をサポートし、#6458 の @electron0zero によりすべてのコマンドで RFC3339 に標準化されました。
    • query search コマンドは、タイムゾーンのないタイムスタンプ (例: 2024-01-01T00:00:00) を受け入れなくなりました。代わりに RFC3339 (例: 2024-01-01T00:00:00Z)、または相対時間を使用してください。
  • 最近のデータカットオフのための統合された読み取り構成。 #6507 の @mapno により、query_frontend.search.query_ingesters_until が削除され、query_frontend.search.query_backend_after のみが優先されました
  • 非推奨の querier.query_live_store 構成を削除しました。このフィールドは、#7048 の @javiermolinar によってアップグレード時に構成から削除する必要があります
  • #6353 の @stoewer によって同じ属性の条件を同等の配列に書き換えることにより、TraceQL AST を最適化しました。
    • != および !~ 演算子の配列一致セマンティクスをわずかに変更し、正規表現リテラルに対してより厳格なルールを導入します。
  • #6618 の @javiermolinar によるスパンメトリクスの残り物と遅延初期化ジェネレーター clients を削除しました。
  • @javiermolinar によるライブストア MetricsGenerator クエリ サービスの廃止 (#6615)
  • #6555 の @javiermolinar によるメトリクスジェネレーターのローカルブロックプロセッサーと関連するローカルブロックストレージの配管を削除しました。
  • #6496 と #6510 で SpanMetricsSummary が削除され、クエリア コードが @javiermolinar によって簡略化されました。
  • all ターゲットを 3.0-compatible に設定し、#6283 の @joe-elliott によって scalable-single-binary ターゲットを削除しました。
  • #6505 で @javiermolinar によってエンタープライズ jsonnet がクリーンアップされました

変更点

  • 32 ビット ARM バイナリ アーカイブの公開を停止します。リリース アーティファクトには、#7106 の @javiermolinar による amd64 および arm64 バイナリが引き続き含まれます。
  • #6443 の @stoewer による Go 1.26.2 へのテンポのアップグレード

  • #6285 の @javiermolinar により、TraceQL メトリクス クエリのデフォルトの最大期間を最大 1 日に更新しました
  • Vulture で TraceQL クエリ メトリクス チェックをデフォルトで設定 (#6275 の @javiermolinar による)
  • #7033 の @javiermolinar によるローカル バックエンドを使用する Tempo シングルバイナリの例を作成します
  • #7034 の @javiermolinar による摂取制限の引き上げ
  • #7291 の @javiermolinar により、リリース例と生成された操作構成が grafana/tempo:3.0.0 に追加されました。
  • TraceQL メトリクス: #6413 の @mdisibio により、新しい vParquet5 タイムスタンプ列に合わせてデフォルトのステップ間隔を変更します。
  • #6352 の @javiermolinar により、ダッシュボードからインジェスターの痕跡をすべて削除します。
  • jsonnet: #6648 の @mapno により、emptyDir データ ボリュームをブロック ビルダー StatefulSet に追加
  • #6696 の @javiermolinar によるテンポ ミックスイン Runbook へのクイック チェックの追加
  • #6707 で @javiermolinar による metrics-generator no-local-blocks を非推奨にする
  • #6808 の @javiermolinar による独自のローカル ブロックおよびパーティション リング ヘルパー
  • #6799 で @javiermolinar による無効なトレースとスパン ID の破棄を追跡します
  • query_frontend.rf1_after を非推奨にし、非メトリック パスのレプリケーション係数に関係なくすべてのブロックをクエリします。 #6969 の @mapno により、2.x から 3.0 への移行が簡素化されます。
  • シングルバイナリモードでライブストアからバックエンドストレージにブロックをフラッシュ (#6941 の @javiermolinar による)
  • #6980 の @javiermolinar による例から古い構成を削除 -tempo-cli: #6793 の @electron0zero により、従来のフラット オーバーライドを新しいスコープ形式に移行できるように、migrate overrides-config を書き換えて migrate overrides-per-tenant コマンドを追加しました。
  • #6506 と #6535 の @javiermolinar によるメトリクスジェネレーターからライブストアを切り離す
  • @javiermolinar による Docker の例の OTLP HTTP および gRPC ポートを #6296 で公開

tempo v3.0.0

Tempo 3.0 is a major release that completes the transition to the new ingest/write architecture, removes deprecated 2.x components, graduates TraceQL metrics to general availability, and adds migration tooling for Tempo 2.x users.

This release contains breaking configuration and deployment changes. Review the migration guide before upgrading, especially if you use legacy ingesters, legacy overrides, v2 blocks, OpenCensus, localblocks, or custom live-store/query-frontend settings.

Highlights

  • New ingest/write architecture replaces legacy ingesters.
  • TraceQL metrics is generally available; alerting on TraceQL metrics and the faster read path remain experimental.
  • vParquet5 improvements and faster metrics query paths.
  • Expanded metrics-generator controls for cardinality management.
  • Trace redaction support.
  • Span profiling support via otelpyroscope.
  • Live-store and block-builder correctness and observability fixes.

Breaking Changes

Tempo 3.0 includes several operator-impacting removals and default changes. Review the migration guide before upgrading.

  • The legacy ingester-based write path has been removed. Deployments must migrate to the 3.0 ingest/write architecture.
    • Removed ingesters and the ingester module by @javiermolinar in #6504 / #6959
    • Removed remaining app ingester config and ingest.enabled by @javiermolinar in #6667 / #6873
    • Removed partition ring livestore config by @javiermolinar in #6981
    • Removed ingester and compactor alerts by @javiermolinar in #6369
  • Removed v2 block encoding and the legacy v2 compactor component by @joe-elliott in #6273
    • Removed v2-specific CLI commands: list block, list index, view index, gen index, and gen bloom.
  • Centralized block and WAL config: block_builder and live_store now always use storage.trace.block settings; per-module block config fields are removed by @stoewer in #6647
  • Recent data queries now guarantee complete results by failing when an instance is lagging. Defaults query_frontend.query_end_cutoff to 30s and live_store.fail_on_high_lag to true by @mapno in #7210 / #7232
  • Disabled legacy (flat, unscoped) overrides by default. Tempo refuses to start if legacy overrides are detected. Set enable_legacy_overrides: true or -config.enable-legacy-overrides=true to opt back in temporarily. Legacy overrides will be removed in a future release by @electron0zero in #6741
  • User-configurable overrides config metrics_generator.processors no longer merges with runtime overrides. metrics_generator.processors now takes precedence over runtime overrides, matching every other config in user-configurable overrides. Setting processors: [] disables all processors for the tenant by @electron0zero in #7176 / #7185
  • Enabled RetryInfo by default. distributor.retry_after_on_resource_exhausted now defaults to 5s (was 0) so OTLP clients receive a retry hint on ResourceExhausted errors by @electron0zero in #7088
    • Set to 0 to disable cluster-wide, or set the per-tenant override ingestion.retry_info_enabled: false to disable for a single tenant.
  • Removed duplicate compaction prefix from CompactorConfig CLI flags by @electron0zero in #6909
    • compaction.compaction.block-retention → compaction.block-retention
    • compaction.compaction.max-objects-per-block → compaction.max-objects-per-block
    • compaction.compaction.max-block-bytes → compaction.max-block-bytes
    • compaction.compaction.compaction-window → compaction.compaction-window
  • Removed OpenCensus receiver by @javiermolinar in #6523
  • Removed legacy mem-ballast-size-mbs CLI flag by @orkhan-huseyn in #6403
  • tempo-cli: Support relative time (now, now-1h) for start/end args and standardize on RFC3339 in all commands by @electron0zero in #6458
    • query search command no longer accepts timestamps without timezone, for example 2024-01-01T00:00:00; use RFC3339, for example 2024-01-01T00:00:00Z, or relative time instead.
  • Consolidated read configuration for recent data cutoff. query_frontend.search.query_ingesters_until is removed in favor of only query_frontend.search.query_backend_after by @mapno in #6507
  • Removed deprecated querier.query_live_store config. This field must be removed from configs on upgrade by @javiermolinar in #7048
  • Optimized TraceQL AST by rewriting conditions on the same attribute to their array equivalent by @stoewer in #6353
    • Slightly changes the array matching semantics of != and !~ operators and introduces stricter rules for regex literals.
  • Removed span-metrics leftovers and lazy-init generator clients by @javiermolinar in #6618
