#ディープチューター v1.5.13

ディープチューター v1.5.13 Release Notes

発売日: 2026.08.17 v1.5.12 は、回答の素材の出所に関するものでした。これは主に本に関するものです。つまり、その資料をチャットするものではなく、読むものに変える表面です。本は生成できても、実際には使用されませんでした。作成中にページがフリーズし、追跡するはずの進捗状況が決して書き留められず、得たものはアプリから出ることができませんでした。このギャップがこのリリースの大部分を占めています。ホーム画面でも、空のコンポーザーから開始するように求めるメッセージが表示されなくなります。ドロップイン — 移行や再インデックスの必要はありません。

新機能

本が書かれているのを見て、読み終えて持ち歩きましょう

コンパイルは、それを開始したリクエストよりも長く続きます。confirm_spine は、ページ シェルが存在するとすぐに戻りますが、キューに入れられた作業は数分間実行されます。イベント バスはそのリクエストによって所有され、リクエストとともに閉じられたため、後続のすべてのイベントは削除され、「本が書かれているのを見てください」とフリーズしたページに劣化しました。ストリームはプロセスによって ブック ごとに所有されるようになったため、リクエスト、更新、再接続後も存続します。 読書の進行状況が実際に記録されるようになりました。 visited_page_ids と bookmarked_page_ids は宣言されていましたが、この機能が存続するまで書かれることはありませんでした。訪問したページ、ブックマーク、クイズの回答が完了スコアと苦手な章のリストにまとめられるようになりました。 また、書籍はアプリから離れることができます: 自己完結型の Markdown ドキュメントにエクスポート。すべてのブロック タイプはテキスト プロジェクションを取得し、本質的に視覚的なブロック (レンダリングされたアニメーション、インタラクティブ ウィジェット) は、静かに消えるのではなく、説明とポインターに分解されます。非 ASCII タイトルはダウンロード後も存続します。中国語またはアクセント付きの書籍名が使用されると、リクエストは完全に失敗します。

承認する前に書籍の価格を把握し、二重に支払わないようにしましょう

脊椎の確認には、数十回の LLM コールと何分もの作業が始まります。エディターには、セクション アーキテクト独自のテンプレートから導出された章ごとのライブ推定値が表示されるようになりました。そのため、数値が実際に生成された値から変動することはなく、章を追加、削除、または再入力しても正確な値が維持されます。 実稼働環境では見えなかった 2 つのスケジュール上の欠陥が修正されました。同じページが同時に 2 回コンパイルされる可能性があり (2 回請求され、1 つの結果はサイレントに破棄されます)、プロバイダーの停止中も書籍は各章が半分生成されるまで継続されます。ソーススイープも制限されています。ゲートされていない場合、12 のクエリに対して 8 つのナレッジ ベースが約 100 の同時プロバイダー呼び出しを実行しました。キャップはラウンドロビンで割り当てられるようになったため、最初の数ベースに全額が費やされるわけではありません。

接続されたナレッジ ベースは、黙って何も貢献しなくなる

接続された KB (Obsidian ボールト、リモート LightRAG または IMA ライブラリ、サブエージェント CLI) にはローカル インデックスがないため、rag_search は何も返しません。とにかく本の生成が彼らを席巻し、空の結果は関連コンテンツのないソースと区別がつきませんでした。金庫を添付しても、それが貢献度ゼロであるとは何も言われませんでした。取得では、インデックス付きのベースと接続されたポインタを区別し、それに応じてそれぞれをルーティングするようになりました。

実際に行っていたことから抜粋した 3 つの開始点

ホーム コンポーザーは、L3 合成とサーフェス全体にわたる最後のいくつかのアクティビティという、記憶から構築された 3 つのスターター提案を提供します。歴史を再考する方法ではなく、理解すべき具体的な内容を提案しており、オーバーフローしないように言語ごとにサイズが調整されています。新しい recall メモリがそれらをリードバックし、エンティティ コンテンツをロードせずにスナップショット スタンプが読み取られます。

会話の後にマスタリーパスが続きます

パスは 1 つのチャットよりも存続し、チャットは複数のパスを順番に動作させる可能性があります。パス間でのライブ ターンの移動は 1 か所で行われるようになりました。リース、セッション設定、ライブ ターンは一緒に変更され、取得前にリリースされます。そのため、ハンドオフが拒否された場合、学習者は途中で移動するのではなく、元の場所に残ります。パスの状態とターンの回復は強化され、教育コンテンツは表示されたままになり、定性的なレビューがスケジュールされ、セッションを削除するとパスがクリーンアップされます。

Tencent IMA 資格情報がアカウントに移動します

IMA 資格情報は、以前は各 KB にのみ存在していました。また、PageIndex のキーと同様に、ナレッジ → IMA エンジン ページ からアカウント レベルでも解決されるようになり、完了した時点でも KB ごとのペアが優先されます。既存のバインディングはそのまま機能し続け、アカウント キーをローテーションすると、それに依存するすべての KB が更新されます。読み取り専用の IMA 接続とソーステキストの取得も同時に修正されています。

各種詰め合わせ

  • EPUB はサポートされているナレッジベース形式であり、Docling は、ローカル インストールやモデルのダウンロードを行わずに、Docling サーバー (mode=remote) に対してリモートで解析できます。
  • 生成されたコードは、ユーザーに届く前に解析されます。 切り詰められたスニペットは、未チェックのマークを何も付けずに出荷されていました。
  • 概要の章は単一のままです。 スパインを再確認すると、そのたびに 2 つ目のスパインが成長し、ページは完全に再構築されました。これは、edited_by_user 保護をバイパスする 1 つのパスです。その文言も中国語や英語にハードコーディングされなくなりましたが、ピッカーは 11 か国語を提供します。
  • クイズ ブロックは、最も遅いブロックからの進行状況を破棄する従来のファサードの代わりに、質問パイプラインを直接読み取ります。
  • 知識: 大規模なアップロードは Web レイヤーを介してストリームされ、ドキュメントの解析はイベント ループから実行され、docstore プローブは kb list でキャッシュおよび重複排除され、GraphRAG モデル/埋め込みの互換性は強化されます。
  • パートナー: データはユーザーごとに分離され、無効なチャネル構成によって他のチャネルがダウンすることはなくなり、ツール リストはグローバル チャットの切り替えに従い、パートナーはタブが非アクティブになった後に再接続します。
  • モデルとプロバイダー: モデル カタログとプロバイダー トランスポートは壊れたままではなく回復し、カタログ シークレットは設定 API で保護され、GPT-5 エージェント ツールは応答 API を使用し、プロバイダー ストリーム障害境界は存続し、完了したターン メッセージ ID は再接続後も持続します。
  • 実行時: アクティブな virtualenv は bwrap サンドボックス内に表示され、無効なホームとプレースホルダー OpenAI キーは拒否され、Windows .cmd シムは CLI が生成される前に解決され、コンソール例外トレースバックは保持され、mcp はデフォルトでインストールされるため PageIndex MCP サーバーが接続されます。

アップグレードに関する注意事項

pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。スキーマの変更、インデックスの再作成、移行は必要ありません。

  • このリリースより前に編集された書籍には、進行状況が記録されていません。 完了スコアと弱い章は、次回読んだときから蓄積され始めます。何もバックフィルされず、既存のページが書き換えられることもありません。
  • アップグレード時にコンパイル途中だったブックは、そのままではなく再開する必要があります。イベント ストリームはブックごとに所有されるようになったため、再度開くとフリーズしたページが表示されるのではなく、ライブ コンパイルに再アタッチされます。
  • settings/ima.json は新しいで、オプションです。既存の KB ごとの IMA 資格情報は、以前とまったく同じように機能し続けます。アカウント レベルのペアは、独自の KB を持たない KB のみを埋めます。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.12...v1.5.13

DeepTutor v1.5.13

Highlights

  • Book compilation outlives the request — The event bus is now owned per book by the process instead of by the originating HTTP request. confirm_spine returns once page shells exist while queued work runs for minutes; the old request-scoped bus closed with the request and dropped every later event, so "watch it being written" froze. Behavioral change for adopters: a book that was mid-compile at upgrade time should be reopened/resumed — reconnecting now reattaches to the live stream rather than showing a stale page.
  • Reading state is persisted, with no backfill — visited_page_ids and bookmarked_page_ids were declared but never actually written; visits, bookmarks, and quiz attempts now roll up into a completion score and a weak-chapter list. Books compiled before v1.5.13 have no recorded history — scores accumulate from your next read, nothing is backfilled and no existing page is rewritten, so don't expect progress dashboards to populate retroactively.
  • Books can leave the app (as lossy Markdown) — Export produces a self-contained Markdown document with a text projection for every block; visual/interactive blocks degrade to their description plus a pointer instead of vanishing silently, and non-ASCII titles no longer fail the download. Treat this as a reading artifact, not a round-trip format — animation and widget fidelity is intentionally not preserved.
  • Cost is visible and bounded — Live per-chapter estimates derive from the Section Architect's own templates, so the figure can't drift from what is generated and stays accurate as chapters are edited. Three production-invisible defects are fixed: the same page compiled twice concurrently (double-billed, one result discarded), books grinding through a provider outage until every chapter was half-generated, and source sweeps firing ~100 concurrent provider calls across 8 KBs/12 queries — the cap is now round-robin allocated so early bases can't starve the rest.
  • Connected knowledge bases stop being silent zeros — Obsidian vaults, remote LightRAG/IMA libraries, and subagent CLIs have no local index, so rag_search returned nothing and book generation couldn't tell that apart from a source with no relevant content. Retrieval now distinguishes indexed bases from connected pointers and routes each appropriately, so attaching a vault means it is actually queried rather than silently contributing nothing.
  • IMA credentials resolve at the account level — Keys can now come from Knowledge → the IMA engine page, mirroring PageIndex, while a complete per-KB pair still wins; existing bindings are untouched and rotating the account key updates every dependent KB. settings/ima.json is new and optional — zero-migration, but note it if you script config management.

No breaking changes.

DeepTutor v1.5.13 Release Notes

Release Date: 2026.08.17

v1.5.12 was about where an answer's material comes from. This one is mostly about Book — the surface that turns that material into something you read rather than something you chat with. A book could be generated but not really used: the page froze while it was being written, the progress it claimed to track was never written down, and what you got could not leave the app. That gap is the bulk of this release. The home screen also stops asking you to start from a blank composer. Drop-in — no migrations, nothing to re-index.

What's New

Watch a book being written, then finish it and take it with you

Compilation outlives the request that started it: confirm_spine returns as soon as the page shells exist, while the work it queued runs for minutes. The event bus was owned by that request and closed with it, so every subsequent event was dropped and "watch your book being written" degraded into a frozen page. The stream is now owned per book by the process, so it survives the request, a refresh, and a reconnect.

Reading progress is now actually recorded. visited_page_ids and bookmarked_page_ids had been declared but never written for the life of the feature; visited pages, bookmarks, and quiz attempts now roll up into a completion score and a list of weak chapters.

And a book can leave the app: export to a self-contained Markdown document. Every block type gets a text projection, and inherently visual blocks (a rendered animation, an interactive widget) degrade to their description plus a pointer instead of vanishing silently. Non-ASCII titles survive the download — a Chinese or accented book name used to fail the request outright.

Know what a book costs before you approve it — and don't pay twice

Confirming a spine kicks off dozens of LLM calls and many minutes of work. The editor now shows a live per-chapter estimate derived from the Section Architect's own templates, so the number cannot drift from what actually gets generated, and it stays accurate while you add, remove, or retype chapters.

Two scheduling defects that were invisible in production are fixed: the same page could be compiled twice concurrently — billed twice, one result silently discarded — and a book would grind on through a provider outage until every chapter was half-generated. The source sweep is bounded too. Ungated, eight knowledge bases against a dozen queries fired roughly a hundred concurrent provider calls; the cap is now allocated round-robin, so it isn't spent entirely on the first few bases.

Connected knowledge bases stop silently contributing nothing

A connected KB — an Obsidian vault, a remote LightRAG or IMA library, a subagent CLI — has no local index, so rag_search returns nothing for it. Book generation swept them anyway, and the empty result was indistinguishable from a source with no relevant content: attach your vault, and nothing ever told you it contributed zero. Retrieval now tells indexed bases and connected pointers apart and routes each accordingly.

Three places to start, drawn from what you were actually doing

The home composer now offers three starter suggestions built from your memory — the L3 synthesis plus your last several activities across surfaces. They propose a specific thing to understand rather than a way to revisit history, and they're sized per language so they don't overflow. A new recall memory read backs them, and snapshot stamps are read without loading entity content.

Mastery paths follow the conversation

A path outlives any one chat, and a chat may work several paths in sequence. Moving a live turn between paths now happens in one place — lease, session preference, and live turn changed together, release before acquire — so a rejected handoff leaves the learner where they were instead of half-moved. Path state and turn recovery are hardened, teaching content stays visible, qualitative reviews are scheduled, and deleting a session cleans up its path.

Tencent IMA credentials move up to the account

IMA credentials used to live only on each KB. They now also resolve at the account level from Knowledge → the IMA engine page, the way PageIndex's key does, with the per-KB pair still winning when it is complete. Existing bindings keep working untouched, and rotating the account key updates every KB that relies on it. Read-only IMA connections and source-text retrieval are fixed alongside.

Assorted

  • EPUB is a supported knowledge-base format, and Docling can parse remotely against a Docling Serve server (mode=remote) with no local install or model downloads.
  • Generated code is parsed before it reaches you. A truncated snippet used to ship with nothing marking it unchecked.
  • The Overview chapter stays singular. Re-confirming a spine grew a second one each time, and the page was rebuilt wholesale — the one path that bypassed edited_by_user protection. Its wording is also no longer hard-coded to Chinese-or-English while the picker offers eleven languages.
  • Quiz blocks read the question pipeline directly instead of a legacy facade that discarded progress from the slowest block.
  • Knowledge: large uploads stream through the web layer, document parsing runs off the event loop, docstore probes are cached and deduped in kb list, and GraphRAG model/embedding compatibility is hardened.
  • Partners: data is isolated per user, an invalid channel config no longer takes the others down, the tool list follows the global chat toggles, and a partner reconnects after its tab goes inactive.
  • Models & providers: the model catalog and provider transport recover instead of staying broken, catalog secrets are protected in the settings API, GPT-5 agentic tools use the Responses API, provider stream-failure boundaries survive, and completed turn message IDs persist across reconnects.
  • Runtime: the active virtualenv is visible inside the bwrap sandbox, invalid homes and placeholder OpenAI keys are rejected, Windows .cmd shims resolve before a CLI is spawned, console exception tracebacks are preserved, and mcp installs by default so the PageIndex MCP server connects.

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No schema changes, no re-index, no migration.

  • Books compiled before this release have no recorded progress. Completion scores and weak chapters start accumulating from your next read; nothing is backfilled and no existing page is rewritten.
  • A book that was mid-compile when you upgrade should be resumed, not left. The event stream is now owned per book, so reopening it reattaches to the live compile rather than showing a frozen page.
  • settings/ima.json is new and optional. Existing per-KB IMA credentials keep working exactly as before — the account-level pair only fills in for KBs that don't carry their own.
