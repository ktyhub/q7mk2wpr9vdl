#ディープチューターv1.4.8 #ディープチューター v1.4.8 Release Notes 発売日: 2026.06.18 v1.4.7 への重点的なフォローアップ: 接続するエージェント 私のエージェントにはあなた自身のパートナーが含まれるようになり、すべてのパートナーは 自分だけのプライベートな記憶。ローカルのクロードコードの横にあるパートナーを接続します / Codex をチャットで選択すると、DeepTutor がそのペルソナ、ライブラリをライブで参照します。 そしてパートナー自身のループを通じて応答するスキル。ドロップイン - 移行はありません。

パートナーの記憶は現在、パートナーと共に生きています。 以前はパートナーが読んでいた そして 所有者 の共有メモリを書き込みました。現在、各パートナーは独自を保持しています ワークスペース内の長期記憶を維持しながら、所有者の共有データを読み取ります 文脈としての記憶。これは非破壊的であり、所有者の記憶は影響を受けません。 そして、読みやすい状態を保ちます。パートナーの 新しい 記憶が到達する場所のみが変更されます。 アップグレードに関しては何もする必要はありません。

新機能

接続されたエージェントとしてパートナーに相談する

マイ エージェント では、パートナー がローカルのクロード コード / コーデックスの隣にリストされるようになりました。 1 つ接続してコンポーザーで選択すると、ターンは 1 つで実行されます。 consult_subagent パートナー自身のチャット ループに対するツール — その魂、ライブラリ スキルとそのトレースをサイドバーでライブストリーミングします。すべてのコンサルトを 1 回以内に行う DeepTutor チャットは単一のパートナー セッションにスレッド化され、そのパートナーのセッションにアーカイブされます。 最初の質問の履歴とタイトルがあり、接続には パートナー自身のアバター。

パートナーは自分自身の記憶を得る

パートナーは、分割 メモリ モデルを使用しており、3 つの常時接続を通じて公開されています。 パートナーのターンごとにチャットの read_memory / write_memory を置き換えるツール:

  • partner_read — 所有者の共有メモリおよびパートナー自身の共有メモリを読み取ります。 連結された。
  • partner_memorize — パートナー自身のワークスペースにのみ書き込みます。パートナーはできる 所有者の記憶には決して触れないでください。
  • partner_search — パートナー自身の会話履歴に対するキーワード検索。 これらは必須であるため、パートナーごとの read_memory / write_memory パートナーツールの設定からトグルが消えました。

パートナーの会話をコンテキストとして参照する

パートナーの会話を参照先として DeepTutor チャットに取り込むことができるようになりました。 トランスクリプト (管理者のみ)、パートナー自身の名前で第三者として構成 — インポートされたエージェントの履歴も同様です。

  • v1.4.7 からのドロップイン: pip install -U deeptutor; Dockerユーザーが引く ghcr.io/hkuds/deeptutor:latest。移行はありません。
  • 上記のパートナーメモリの変更は自動かつ非破壊的です: 既存 パートナーは所有者の共有記憶を読み取り続け、単に自分自身の記憶を取得します 書き込み可能なストア。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.4.7...v1.4.8

DeepTutor v1.4.8

Highlights

  • Partners become first-class connected agents — My Agents now lists your Partners alongside local Claude Code / Codex; selecting one in the composer routes the turn through a single consult_subagent tool into that partner's own chat loop (its soul, library, and skills), with the trace streamed live in the sidebar. Every consult in a DeepTutor chat threads into one partner session, archived in the partner's history and titled from your first question, wearing the partner's avatar. Practically, partners are no longer a separate surface — they sit on the same footing as local agents, so the existing "connect an agent" workflow carries over.

  • Memory is now partitioned per partner — On every partner turn, three mandatory tools replace chat's read_memory / write_memory: partner_read returns the owner's shared memory concatenated with the partner's own, partner_memorize writes only to the partner's workspace (a partner can never mutate the owner's memory), and partner_search keyword-searches the partner's own history. This is the substantive behavioral change: memory is namespaced, so partners can't pollute the owner's long-term store — but note the tools are always-on, not opt-in, so you can't dial memory access back per partner.

  • Per-partner memory toggles removed — The per-Partner read_memory / write_memory switches are gone from Partner tool settings because the new tools are unconditional. No data migration is involved, but any setup docs or automation that relied on those toggles are now no-ops and should be updated.

  • Partner transcripts usable as context (admin-only) — A partner conversation can now be pulled into a DeepTutor chat as a referenced transcript, framed as a third party under the partner's own name just like imported agent histories. Good for cross-agent context reuse, but it's gated to admins — ordinary users won't see it.

  • No breaking changes — Drop-in from v1.4.7 via pip install -U deeptutor or ghcr.io/hkuds/deeptutor:latest; no migrations. The memory split is automatic and non-destructive: existing partners keep reading the owner's shared memory and simply gain their own writable store, with the owner's memory left untouched.

DeepTutor v1.4.8 Release Notes

Release Date: 2026.06.18

A focused follow-up to v1.4.7: the agents you connect under My Agents now include your own Partners, and every Partner gains a private memory of its own. Connect a partner beside your local Claude Code / Codex, select it in chat, and DeepTutor consults it live — its persona, library and skills answering through the partner's own loop. Drop-in — no migrations.

A partner's memory now lives with the partner. Previously a partner read and wrote the owner's shared memory; now each partner keeps its own long-term memory in its workspace, while still reading the owner's shared memory as context. This is non-destructive — the owner's memory is untouched and stays readable — it only changes where a partner's new memories land. Nothing to do on upgrade.

What's New

Consult a Partner as a Connected Agent

My Agents now lists your Partners next to a local Claude Code / Codex. Connect one and select it in the composer, and the turn runs on a single consult_subagent tool against that partner's own chat loop — its soul, library and skills — streaming its trace live in the sidebar. Every consult within one DeepTutor chat threads into a single partner session, archived in that partner's history and titled from your first question, and the connection wears the partner's own avatar.

Partners Get Their Own Memory

A partner now has a split memory model, exposed through three always-on tools that replace chat's read_memory / write_memory on every partner turn:

  • partner_read — reads the owner's shared memory and the partner's own, concatenated.
  • partner_memorize — writes only to the partner's own workspace; a partner can never touch the owner's memory.
  • partner_search — keyword search over the partner's own conversation history.

Because these are mandatory, the per-Partner read_memory / write_memory toggles are gone from Partner tool settings.

Reference a Partner Conversation as Context

A partner conversation can now be pulled into a DeepTutor chat as a referenced transcript (admin-only), framed as a third party under the partner's own name — the same way imported agent histories are.

Upgrade Notes

  • Drop-in from v1.4.7: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations.
  • The partner-memory change above is automatic and non-destructive: existing partners keep reading the owner's shared memory and simply gain their own writable store.
