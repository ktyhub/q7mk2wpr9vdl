DeepTutor v1.3.3

パッチ 公開日2026年4月30日 出典HKUDS/DeepTutor English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディープチューター v1.3.3 #ディープチューター v1.3.3 Release Notes 発売日: 2026.04.30 v1.3.3 は、v1.3.2 の後の迅速なフォローアップ リリースです。プロバイダーの対象範囲を拡大します NVIDIA NIM および Gemini エンベディングを使用すると、Space を接続するための統合された場所にします チャット履歴、ノート、質問バンク項目、スキル、ターンまでの記憶、および RAG の再インデックス作成、思考モデルのクリーンアップに関する安定化作業を継続します。 TutorBot の履歴、および永続化されたセッション コンテキスト。

ハイライト

プロバイダーと埋め込みの対象範囲

DeepTutor は、すぐに使用できるホスト型プロバイダーのセットアップをさらにカバーし、 セットアップ ツアーおよび .env の例に合わせたランタイム構成パス。

  • NVIDIA NIM はファーストクラスの LLM プロバイダーです - プロバイダーの自動検出が可能になりました nvapi- キーと NVIDIA API ベースを認識します。デフォルトは https://integrate.api.nvidia.com/v1、送信を回避します stream_options.include_usage は、そのオプションが有効な場合に NIM がハングする可能性があるためです。 現在。
  • Gemini 埋め込みはエンドツーエンドで利用可能 - ランタイム メタデータの埋め込み、 エンドポイントの検証、セットアップ ツアーの選択、モデルの提案、および .env 例には、gemini-embedding-001、3072 次元の Gemini が含まれるようになりました。 GEMINI_API_KEY フォールバックのサポート。
  • プロバイダー固有の埋め込みキーは設定の書き込みでも存続します - .env の書き込み 代わりに、SiliconFlow、DashScope、Cohere、Jina、Gemini などのキーを保持します。 古いコアプロバイダーセットのみを保持します。
  • 依存関係の解決はそれほど脆弱ではありません - NumPy の上限が緩和されました deeptutor[all] での現在の Manim インストールと Windows セットアップ ドキュメントをサポートするため 次に、Visual Studio Build Tools / C++ ワークロードの前提条件を呼び出します。

スペース、チャット コンテキスト、スキル、および記憶

チャット コンポーザーは、すべての学習コンテキストをスペース コンテキストとして扱うようになりました。 参照、スキル、メモリを別々のコントロールに分割します。

  • チャット履歴でスペースが開きます - スペースのエントリ ポイントが新しいチャット履歴に表示されます。 チャット履歴ページでは、以前の会話を検索、更新、 スペース ワークスペースから直接、名前変更、削除、および再度開くことができます。
  • One Space メニューがツールバーと @ メンションを強化 - 古いインライン AtMentionPopup はチャット履歴の共有スペース メニューに置き換えられました。 ノートブック、質問バンクのアイテム、スキル、および記憶。 ツールバーを使用するか、「@」と入力します。
  • スキルの選択がより明確になりました - スキルがフルピッカーで開くようになりました。 検索、タグ、明示的な複数選択、小さなインラインの代わりに自動モード 作曲家の横のドロップダウン。
  • メモリはターンごとに接続可能 - ユーザーは実行中の概要を選択でき、 プロファイル、または新しいメモリ ピッカーを介してその両方を実行します。リクエストは送信されます memory_references であり、バックエンドは選択されたメモリ ファイルのみを挿入します。
  • コンテキスト チップにはフル ターンのセットアップが表示されます - 選択された履歴、ノートブック、 質問バンクのアイテム、スキル、メモリはすべて、以前は取り外し可能なチップとして表示されていました。 送信します。送信されたユーザー メッセージには、一致するリクエスト スナップショット バッジも表示されます。
  • 今すぐ応答し、セッション ハイドレーションでコンテキストを維持 - ターンをリプレイしてロード セッションでは、ノートブック、歴史のリファレンス、質問バンクのリファレンスが充実するようになりました。 スキル、メモリ参照、および永続化されたメッセージ メタデータからの添付ファイル。

セッションの永続化とメッセージの正規化

会話状態は、ユーザーの実際の送信時のコンテキストをより多く記録するようになりました。 非テキスト メッセージ コンテンツをより防御的に処理します。

  • メッセージ メタデータは保持されます - SQLite セッション ストアにより、 metadata_json 列にユーザー メッセージの request_snapshot を格納します。 機能、ツール、選択した KB、言語、構成、添付ファイル、 空間参照、スキル、記憶の選択。
  • WebSocket はメモリとスキルを明示的に受け入れます - 受信ペイロード memory_references を summary / profile に正規化し、スキルを 文字列リストを作成し、両方をメッセージ メタデータに具体化します。
  • TutorBot 履歴はマルチモーダル コンテンツを処理します - ボット履歴と最近のボット プレビューは文字列、配列、オブジェクト、画像スタイルのコンテンツを安全なものに正規化します。 表示テキスト、内部 reasoning_content は API から削除されます 応答。
  • フロントエンド メッセージのプレビューがより安全 - 共有メッセージ コンテンツ ユーティリティ 不明なコンテンツを受け入れ、カスタム オブジェクトを文字列化し、画像部分を次のようにレンダリングするようになりました。 [image]、チャット リストとセッション リスト全体で一貫してプレビューを切り詰めます。

メモリ、ノートブック、思考モデルのクリーンアップ

v1.3.2 で導入された思考出力クリーンアップの耐久性がさらに向上しました。 ストレージが表面を保護し、不正なメモリの書き換えを破損する前に拒否します。 プロファイルまたは概要ファイル。

  • メモリの書き換えは予想される形状と一致する必要があります - プロファイルと概要 更新では、書き込む前に許可されたセクション見出しを確認するようになりました。思考なら モデルは構造化メモリを返す代わりにユーザーに応答します。書き込みは次のようになります。 固執するのではなく拒否されました。
  • メモリ コンテキストは明示的です - build_memory_context() にはのみが含まれるようになりました これらのファイルが要求されたときの summary および/または profile (新しいファイルと一致) ターンごとのメモリ ピッカーと、誤ったデフォルト メモリ インジェクションを回避します。
  • ノートブックの概要がクリーンアップおよび修復されます - ノートブックの書き込み、ストリーミング 概要を保存し、ノートブックをロードすると、概要から思考タグが削除されます。年上の ノートブックのレコードは、可能な場合には読み取り時に修復されます。
  • ストリーミングの概要チャンクがよりクリーンになります - 生成されたノートブックの概要は 組み立て、クリーニング、クリーンアップ後に放出されるため、空またはスクラッチパッドのみ チャンクは client にストリーミングされません。

RAG とナレッジベースの回復力

RAG 検証は、取得前により多くの無効な永続化インデックスを検出するようになりました。 ユーザーがインデックスを再作成する必要がある場合、より明確なイベントを返します。

  • インデックスの準備が完了すると、古い処理 KB が回復します - kb_config.json の場合 processing または initializing でスタックしていますが、準備ができている LlamaIndex バージョンは すでにディスク上にあるため、ナレッジベース情報は ready を報告し、古い情報を非表示にします。 UI を永続的な処理状態のままにするのではなく、進行状況バーを表示します。
  • より多くのベクター ストアが検証されています - LlamaIndex ストレージは、 デフォルトのベクター ストア、storage_context.vector_stores、および永続化 *vector_store.json null、ドロップ、非数値、 非有限ベクトル、または一貫性のないベクトル。
  • 無効なインデックスの障害により、ユーザー向けのステータス イベントが生成される - RAG 検索が開始されました ツール イベントを通じて needs_reindex の構造化エラー ステータスを送信します ストリーミングし、既知の無効なインデックスの失敗を成功として扱うことを回避します。 取得の試み。
  • 低レベルのベクトル エラーはあまり露出されません - 既知の無効な埋め込み/インデックス 失敗はログに記録され、生の代わりに再インデックスのガイダンスとして表示されます。 ユーザー向けログ内の NoneType * float スタイルのトレースバック。

テスト

  • 古い processing を促進するための Knowledge Manager のカバレッジを追加 / 有効なインデックス バージョンがすでに存在する場合は、initializing ステータスが ready に変わります。
  • NVIDIA NIM レジストリ メタデータ、ストリーム オプションのプロバイダー カバレッジを追加しました 動作、Gemini 埋め込みランタイムのデフォルト、エンドポイントの検証、セットアップ ツアー プロバイダーの選択、および .env キーの保存。
  • metadata_json のセッションと WebSocket のカバレッジ、スナップショットのリクエストを追加しました。 スキルの正規化、メモリ参照の解析、ターンの実体化などです。
  • 思考タグの除去、無効なメモリのためのメモリとノートブックのカバレッジを追加しました 書き換え拒否、選択的メモリコンテキスト注入、サマリー修復 読んでください。
  • マルチベクターストア検証用に RAG/LlamaIndex のカバレッジを追加しました。 ディスクに永続化された無効なベクトル、needs_reindex ステータス イベント、およびサニタイズ済み 生のログ。
  • TutorBot と非文字列のフロントエンド メッセージ コンテンツ カバレッジを追加しました。 マルチモーダル、オブジェクト、画像、および切り詰められたメッセージ コンテンツ。

アップグレードに関する注意事項

  • 既存の SQLite セッション データベースは、新しい SQLite セッション データベースとともに移行されます。 セッション ストアが最初にそれらを開くときに、messages.metadata_json 列が表示されます。
  • 暗黙的メモリ注入に依存していたカスタム WebSocket clients は、今後は memory_references: ["summary"]、["profile"]、またはその両方を渡します。空か不在 メモリ参照は意図的に「長期記憶を付加しない」ことを意味します。
  • 依然として無効な永続ベクトルを報告するナレッジ ベースは、次のようにする必要があります。 アクティブな埋め込みプロバイダー、モデル、ディメンションを確認した後、インデックスが再作成されます。 およびエンドポイント URL。
  • ノートブック サマリー ストリーミング clients は、クリーンアップされたサマリー出力を期待する必要があります。 転送されるすべての生のモデル チャンクに依存するのではなく、アセンブリを実行します。
  • NVIDIA NIM ユーザーは、新しい環境で OpenAI 互換モデルを構成する必要があります。 プロバイダーを削除し、このゲートウェイに対して stream_options.include_usage を無効のままにします。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.3.2...v1.3.3

DeepTutor v1.3.3

DeepTutor v1.3.3 Release Notes

Release Date: 2026.04.30

v1.3.3 is a fast follow-up release after v1.3.2. It expands provider coverage with NVIDIA NIM and Gemini embeddings, makes Space the unified place to attach chat history, notebooks, question-bank items, skills, and memory to a turn, and continues the stability work around RAG re-indexing, thinking-model cleanup, TutorBot history, and persisted session context.

Highlights

Provider and Embedding Coverage

DeepTutor now covers more hosted provider setups out of the box and keeps the runtime configuration path aligned with the Setup Tour and .env examples.

  • NVIDIA NIM is a first-class LLM provider - provider auto-detection now recognizes nvapi- keys and NVIDIA API bases, defaults to https://integrate.api.nvidia.com/v1, and avoids sending stream_options.include_usage because NIM can hang when that option is present.
  • Gemini embeddings are available end to end - embedding runtime metadata, endpoint validation, Setup Tour choices, model suggestions, and .env examples now include Gemini, with gemini-embedding-001, 3072 dimensions, and GEMINI_API_KEY fallback support.
  • Provider-specific embedding keys survive Settings writes - .env writes preserve keys such as SiliconFlow, DashScope, Cohere, Jina, and Gemini instead of only preserving the older core provider set.
  • Dependency resolution is less fragile - the NumPy upper bound was relaxed to support current Manim installs in deeptutor[all], and Windows setup docs now call out the Visual Studio Build Tools / C++ workload prerequisite.

Space, Chat Context, Skills, and Memory

The chat composer now treats all learning context as Space context, instead of splitting references, skills, and memory across separate controls.

  • Space opens on Chat History - the Space entry point now lands on the new Chat History page, where previous conversations can be searched, refreshed, renamed, deleted, and reopened directly from the Space workspace.
  • One Space menu powers toolbar and @ mentions - the old inline AtMentionPopup was replaced by a shared Space menu for chat history, notebooks, question-bank items, skills, and memory, whether opened from the toolbar or by typing @.
  • Skills selection is clearer - skills now open in a full picker with search, tags, explicit multi-select, and Auto mode, instead of a small inline dropdown beside the composer.
  • Memory can be attached per turn - users can select the running summary, profile, or both through the new Memory picker. The request sends memory_references, and the backend only injects the selected memory files.
  • Context chips show the full turn setup - selected history, notebooks, question-bank items, skills, and memory all appear as removable chips before send; sent user messages also show matching request-snapshot badges.
  • Answer Now and session hydration keep context - replayed turns and loaded sessions now hydrate notebooks, history references, question-bank references, skills, memory references, and attachments from persisted message metadata.

Session Persistence and Message Normalization

Conversation state now records more of the user's actual send-time context and handles non-text message content more defensively.

  • Message metadata is persisted - the SQLite session store adds a metadata_json column and stores a request_snapshot for user messages, including capability, tools, selected KBs, language, config, attachments, Space references, skills, and memory selections.
  • WebSocket turns accept memory and skills explicitly - incoming payloads normalize memory_references to summary / profile, normalize skills into a string list, and materialize both into message metadata.
  • TutorBot history handles multimodal content - bot history and recent bot previews normalize string, array, object, and image-style content into safe display text, while internal reasoning_content is stripped from API responses.
  • Frontend message previews are safer - shared message-content utilities now accept unknown content, stringify custom objects, render image parts as [image], and truncate previews consistently across chat and session lists.

Memory, Notebook, and Thinking-Model Cleanup

The thinking-output cleanup introduced in v1.3.2 now reaches more durable storage surfaces and rejects malformed memory rewrites before they can corrupt profile or summary files.

  • Memory rewrites must match the expected shape - profile and summary refreshes now verify allowed section headings before writing. If a thinking model answers the user instead of returning structured memory, the write is rejected rather than persisted.
  • Memory context is explicit - build_memory_context() now only includes summary and/or profile when those files are requested, matching the new per-turn Memory picker and avoiding accidental default memory injection.
  • Notebook summaries are cleaned and repaired - notebook writes, streaming summary saves, and notebook loads strip thinking tags from summaries; older notebook records are repaired on read when possible.
  • Streaming summary chunks are cleaner - generated notebook summaries are assembled, cleaned, and emitted after cleanup, so empty or scratchpad-only chunks are not streamed to clients.

RAG and Knowledge Base Resilience

RAG validation now catches more invalid persisted indexes before retrieval and returns clearer events when the user needs to re-index.

  • Stale processing KBs recover when an index is ready - if kb_config.json is stuck at processing or initializing but a ready LlamaIndex version is already on disk, Knowledge Base info reports ready and hides the stale progress bar instead of leaving the UI in a perpetual processing state.
  • More vector stores are validated - LlamaIndex storage now checks the default vector store, storage_context.vector_stores, and persisted *vector_store.json embedding dictionaries for null, dropped, non-numeric, non-finite, or inconsistent vectors.
  • Invalid-index failures emit user-facing status events - RAG search now sends a structured error status with needs_reindex through the tool event stream and avoids treating known invalid-index failures as successful retrieval attempts.
  • Low-level vector errors are less exposed - known invalid embedding/index failures are logged and surfaced as re-index guidance instead of raw NoneType * float style tracebacks in user-facing logs.

Tests

  • Added Knowledge Manager coverage for promoting stale processing / initializing status to ready when a valid index version already exists.
  • Added provider coverage for NVIDIA NIM registry metadata, stream-option behavior, Gemini embedding runtime defaults, endpoint validation, Setup Tour provider choices, and .env key preservation.
  • Added session and WebSocket coverage for metadata_json, request snapshots, skills normalization, memory reference parsing, and turn materialization.
  • Added memory and notebook coverage for thinking-tag stripping, invalid memory rewrite rejection, selective memory-context injection, and summary repair on read.
  • Added RAG/LlamaIndex coverage for multi-vector-store validation, disk-persisted invalid vectors, needs_reindex status events, and sanitized raw logs.
  • Added TutorBot and frontend message-content coverage for non-string, multimodal, object, image, and truncated message content.

Upgrade Notes

  • Existing SQLite session databases are migrated in place with a new messages.metadata_json column the first time the session store opens them.
  • Custom WebSocket clients that relied on implicit memory injection should now pass memory_references: ["summary"], ["profile"], or both. Empty or absent memory references intentionally mean "do not attach long-term memory".
  • Knowledge bases that still report invalid persisted vectors should be re-indexed after confirming the active embedding provider, model, dimension, and endpoint URL.
  • Notebook summary streaming clients should expect cleaned summary output after assembly rather than relying on every raw model chunk being forwarded.
  • NVIDIA NIM users should configure an OpenAI-compatible model under the new provider and keep stream_options.include_usage disabled for this gateway.
