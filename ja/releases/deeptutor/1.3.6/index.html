#ディープチューター v1.3.6

ディープチューター v1.3.6 Release Notes

発売日: 2026.05.03 v1.3.6 は、DeepTutor 全体でモデルのルーティングを明示的に行うことに重点を置いています。ユーザーは次のことができます チャットおよび TutorBot フロー、ランタイム サービスから構成済みの LLM プロファイルを選択します プロバイダーの秘密や RAG/ナレッジベースを漏らすことなく、これらの選択を解決します。 永続化された埋め込みが無効な場合、インデックス処理はより防御的になります。

ハイライト

カタログに基づいたモデルの選択

  • チャットは設定されたモデルをターゲットにすることができます - 統合されたチャット ターンには、 WebSocket ペイロード、セッションによる profile_id および model_id の選択 設定、スナップショットの回転、フローの再生成を行います。
  • 設定により安全な LLM オプションが公開 - 新しい設定オプション エンドポイント 認証情報を省略して、表示可能なプロバイダー/モデルの選択肢を返します。 応答からの接続シークレット。
  • ランタイム モデルのオーバーライドはターンごとにスコープ指定されます - 選択されたプロファイルは 書き込みを行わずに、アクティブなリクエストのプロバイダー カタログを通じて解決されます。 一時的な選択をディスクに戻すか、グローバルなデフォルトを変更します。
  • モデルセレクター UI は共有されています - チャットと TutorBot 画面は同じものを使用します ローカライズされたラベルとシステムのデフォルト処理を備えた構成モデル セレクター。

TutorBot モデル コントロール

  • ボットはモデル選択を保持できます - TutorBot の作成/更新フローが受け入れられるようになりました llm_selection、構成されたカタログに対して検証し、次のように保存します。 各ボット。
  • 実行中のボットは LLM をリロードできます - ボットのモデルを変更すると、 ボットを完全に再起動する必要がなく、アクティブなエージェント ループが可能になります。
  • 最近のボット履歴がより安定しています - TutorBot 履歴アセンブリが次の基準で並べ替えられるようになりました。 最新のコンテキストを取得する前に、安定したタイブレークを使用してメッセージのタイムスタンプを取得します。
  • ボット チャット ルートの変更がより明確になりました - Web チャット ページは進行中にキャンセルされます ボットは、ボットを切り替えるときに一時的な推論状態を要求してリセットします。

RAG と知識の信頼性

  • 無効なベクトルにより再構築がトリガーされる - インデックスの再作成では一致が扱われなくなりました 既存のベクター ストアの埋め込みに失敗した場合にドキュメント署名を再利用可能にする 検証。
  • 完全な再構築では新しいバージョンのディレクトリを使用します - 完全なナレッジベース 障害が発生した古いストレージを残したまま、新しいフラット インデックス バージョンに書き込みを再構築します。 検査可能です。
  • RAG ツール ログは clients にストリーミング可能 - 取得実行によりキャプチャされたデータを転送可能 イベント シンクが使用可能な場合、INFO レベルのプロセス ログが生のツール イベントとして記録されます。
  • ナレッジ ヘルス チェックで不正な埋め込みが認識される - 無効な永続化 ベクトルは、不透明な検索エラーを生成するのではなく、より早く表面化されます。

プロバイダーと起動の修正

  • OpenAI 応答のトークン制限が正規化されました - 応答 API 呼び出しがマップされるようになりました チャット形式 max_completion_tokens および max_tokens から max_output_tokens、 #437 で新しい OpenAI モデルについて報告された SDK エラーを修正しました。
  • Azure と OpenAI 互換のパスはマッピングを共有します - ストリーミングと 非ストリーミング応答 API ルートは同じ変換ヘルパーを使用します。
  • 起動ポートは .env および環境変数から取得されます - セットアップと起動 ヘルパーはバックエンド/フロントエンド ポートの動作をプロジェクトに沿って調整するようになりました。 古いランタイム設定 JSON の代わりに .env ファイルを使用します。

Web UX の磨き

  • スキル名は保存前に検証されます - スキル エディターでは名前が遅くなります。 無効な入力をインラインでフラグ付けし、大文字のサイレント API エラーを防止します 文字、スペース、アンダースコア、またはその他のサポートされていない文字。
  • スキル エディターのモーダルはテーマ間で不透明です - エディターは現在、 ページ背景トークン。半透明のテーマでのテキストのにじみを防ぎます。
  • スペース ナビゲーションがスキャンしやすくなりました - スペース ミニ ナビゲーション、ノートブック、 質問バンク、スキル、セッションリストの間隔が狭くなり、より明確になりました カードと仕切りの処理。

テスト

  • 安全なオプションリスト、アクティブマーカー、 無効なプロファイル/モデルの拒否、および非変更カタログのオーバーライド。
  • 永続的な LLM 選択に対する統合 WebSocket ターンランタイム テストを追加しました。 無効な選択、モデルの切り替え、スナップショット、および再生成動作。
  • TutorBot API と llm_selection 永続性のマネージャー テストを追加しました。 検証、実行時のリロード、およびデフォルトのモデルの動作。
  • スコープ指定されたカタログの設定、プロバイダー ランタイム、および LLM 構成テストを追加しました 選択とターンごとの設定の優先順位。
  • 無効なベクター ストアに対する RAG およびナレッジ ルーター テストを追加し、インデックスを再作成 再構築の決定とストレージのバージョンの解決。
  • トークン制限エイリアス、優先順位、 None フィルタリング、および入力の不変性。
  • スキル名の正規化と検証のためのフロントエンド スラグ テストを追加しました。

アップグレードに関する注意事項

  • 明示的なモデル ルーティングを必要とするチャットおよび TutorBot clients は、送信する必要があります。 llm_selection は { "profile_id": "...", "model_id": "..." } となります。省略すると 構成されたシステムのデフォルトが引き続き使用されます。
  • TutorBot 設定ファイルに llm_selection が含まれるようになりました。既存のボット そのフィールドのない構成はロードされ続け、レガシー model 値は残ります。 モデル名のオーバーライドとして使用できます。
  • 起動ポートは .env またはプロセス環境変数で構成する必要があります (BACKEND_PORT / FRONTEND_PORT)。旧型data/user/settings/env.json ポート ブロックは起動ポート ソースとして使用されなくなりました。
  • 古いベクターまたは無効な永続ベクターを含むナレッジ ベースは、 次回は、ドキュメントの署名が変更されていない場合でもインデックスを再作成します。
  • スキル名が正規化され、最大 64 文字の小文字のスラッグとして検証されるようになりました。 文字、数字、ハイフンを使用した文字。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.3.5...v1.3.6

DeepTutor v1.3.6

DeepTutor v1.3.6 Release Notes

Release Date: 2026.05.03

v1.3.6 focuses on making model routing explicit across DeepTutor. Users can choose configured LLM profiles from chat and TutorBot flows, runtime services resolve those choices without leaking provider secrets, and RAG/knowledge-base index handling is more defensive when persisted embeddings are invalid.

Highlights

Catalog-Based Model Selection

  • Chat can target a configured model - unified chat turns now carry a profile_id and model_id selection through the WebSocket payload, session preferences, turn snapshots, and regenerate flows.
  • Settings exposes safe LLM options - the new settings options endpoint returns display-ready provider/model choices while omitting credentials and connection secrets from the response.
  • Runtime model overrides are scoped per turn - selected profiles are resolved through the provider catalog for the active request without writing temporary choices back to disk or changing global defaults.
  • Model-selector UI is shared - chat and TutorBot screens use the same configured-model selector, with localized labels and system-default handling.

TutorBot Model Control

  • Bots can persist model selections - TutorBot create/update flows now accept llm_selection, validate it against the configured catalog, and store it with each bot.
  • Running bots can reload their LLM - changing a bot's model updates the active agent loop instead of requiring a full bot restart.
  • Recent bot history is steadier - TutorBot history assembly now sorts by message timestamp with stable tie-breaking before taking the latest context.
  • Bot chat route changes are cleaner - the web chat page cancels in-flight bot requests and resets transient reasoning state when switching bots.

RAG and Knowledge Reliability

  • Invalid vectors trigger rebuilds - re-indexing no longer treats a matching document signature as reusable when the existing vector store fails embedding validation.
  • Full rebuilds use fresh version directories - complete knowledge-base rebuilds write to a new flat index version while leaving failed old storage available for inspection.
  • RAG tool logs can stream to clients - retrieval runs can forward captured INFO-level process logs as raw tool events when an event sink is available.
  • Knowledge health checks recognize bad embeddings - invalid persisted vectors are surfaced earlier instead of producing opaque search failures.

Provider and Launch Fixes

  • OpenAI Responses token limits are normalized - Responses API calls now map chat-style max_completion_tokens and max_tokens to max_output_tokens, fixing the SDK error reported for newer OpenAI models in #437.
  • Azure and OpenAI-compatible paths share the mapping - both streaming and non-streaming Responses API routes use the same conversion helper.
  • Launch ports come from .env and environment variables - setup and launch helpers now keep backend/frontend port behavior aligned around the project .env file instead of the older runtime settings JSON.

Web UX Polish

  • Skill names validate before save - the Skills editor slugifies names, flags invalid input inline, and prevents silent API failures for uppercase letters, spaces, underscores, or other unsupported characters.
  • Skill editor modals are opaque across themes - the editor now uses the page background token, avoiding text bleed-through in translucent themes.
  • Space navigation is easier to scan - Space mini-navigation, notebook, question-bank, skills, and session-list spacing were tightened with clearer card and divider treatment.

Tests

  • Added model-selection service tests for safe option listing, active markers, invalid profile/model rejection, and non-mutating catalog overrides.
  • Added unified WebSocket turn-runtime tests for persisted LLM selections, invalid selections, model switching, snapshots, and regenerate behavior.
  • Added TutorBot API and manager tests for llm_selection persistence, validation, runtime reload, and default-model behavior.
  • Added settings, provider-runtime, and LLM-config tests for scoped catalog selection and per-turn config precedence.
  • Added RAG and knowledge-router tests for invalid vector stores, re-index rebuild decisions, and storage version resolution.
  • Added OpenAI Responses converter tests for token-limit aliases, precedence, None filtering, and input immutability.
  • Added frontend slug tests for skill-name normalization and validation.

Upgrade Notes

  • Chat and TutorBot clients that want explicit model routing should send llm_selection as { "profile_id": "...", "model_id": "..." }. Omitting it continues to use the configured system default.
  • TutorBot configuration files may now contain llm_selection. Existing bot configs without that field continue to load, and legacy model values remain usable as model-name overrides.
  • Launch ports should be configured in .env or process environment variables (BACKEND_PORT / FRONTEND_PORT). The old data/user/settings/env.json port block is no longer used as a launch-port source.
  • Knowledge bases with stale or invalid persisted vectors may rebuild on the next re-index even when document signatures have not changed.
  • Skill names are now normalized and validated as lowercase slugs of up to 64 characters using letters, numbers, and hyphens.
