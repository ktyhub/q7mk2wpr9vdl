DeepTutor v1.4.1

パッチ 公開日2026年5月27日 出典HKUDS/DeepTutor English original

#ディープチューター v1.4.1 #ディープチューター v1.4.1 Release Notes 発売日: 2026.05.27 v1.4.1 は、v1.4.0 のセキュリティおよび安定性パッチです。ロックダウンしてしまう TutorBot ツールのサンドボックス、ユーザーごとのリソースの分離、v1.4.0 チャットの修正 回帰、特定の TutorBot と通信するための HTTP API を追加し、 プロバイダー向けのマルチモーダル イメージ フォールバック修正 DeepTutor にはビジョン エントリがありません。

新機能

TutorBot ツール サンドボックスはオプトインです

管理者が設定しない限り、シェル exec ツールは登録されなくなりました。 allow_shell_exec、すべてのファイルシステムとシェルへのアクセスはボットに限定されます デフォルトではワークスペース。コマンド拒否リストがコマンドで再固定されました 境界があり、更新ペイロードを介して allow_shell_exec をオンにすることはできません。

ユーザーごとのリソースの分離

ブックルート、セッションデータベース、ターンランタイムストア、および TutorBot ディレクトリ スコープはユーザーごとに設定され、Web/API の会話はセッションごとにキー設定されます。 クロスユーザーリクエストは相互のデータに到達できません。

TutorBot の HTTP / SSE API

新しい POST /{bot_id}/chat および /chat/execute-stream (SSE) エンドポイント 自動開始と永続的なセッションごとのコンテキスト、マルチターン会話用 外部 clients の特定のボットを使用します。

マルチモーダル画像フォールバック

画像はすべてのプロバイダーに楽観的に送信されます。画像を含むリクエストの場合 失敗し、モデルが既知ビジョンのホワイトリストにない場合、ターンは再試行します。 テキストのみ。 Doubao / VolcEngine などでサイレントにドロップされた画像を修正 機能エントリのないマルチモーダル モデル。

安全な ZIP アップロード + ネットワーク設定

.zip ナレッジのアップロードは、ドキュメント検証ツールを通じてメンバーごとに拡張されます サイズ/カウント/圧縮率の境界とパスエスケープガード付き。の アーカイブ自体にはインデックスが付けられません。新しい /settings/network ページにポートが表示されます。 パブリック API ベース、および CORS オリジン (host:port および 末尾のスラッシュ)、さらに、モデル ID をリストする「モデルの取得」アクション OpenAI 互換エンドポイント。

コミュニティの修正と変更

セキュリティ — シェル ツール (#518) 経由で閉じた TutorBot RCE、パス トラバーサル ファイルシステム ツール (#517)、クロスボット ファイル管理認証バイパス (#516)、 クロスセッションターン再生認証バイパス (#515)、ブック確認認証 バイパス (#514)、チャット経由で LLM シェル コマンドを実行する ExecTool (#506、 PR #507 で最初に硬化されます)。 バグ修正 — 最初のターン後にチャット入力が無効になる (v1.4.0 回帰、 #520)、長い文書でのナレッジベースの埋め込みエラー (#521 / PR #509)、 新規ユーザーが Docker (#512 / PR #513) でプロファイルを作成できない、Qwen 推論モデルがネイティブ ツール呼び出しに失敗する (#527 / PR #528)、および GPT-5 init-wizard トークン パラメーター (PR #508)。 マージ/再加工された PR — 推論モデルを呼び出すネイティブ ツール (#528)、 特大のセッション イベントの切り捨て (#524)、空の状態のプロファイル ボタン (#513)、 チャンキングパイプラインの修正 (#509)、GPT-5 プローブ (#508)、ExecTool の強化 (#507)。 コントリビューション #522 (zip アップロード) および #523 (モデルの取得 + ノートブックのルックアップ) ローカルで再実装され、ここで出荷されます。 機能リクエスト — 特定の TutorBot とのマルチターン チャット用の HTTP API (#511)。

アップグレードに関する注意事項

  • v1.4.0 からのドロップイン: pip install -U deeptutor; Dockerユーザープル ghcr.io/hkuds/deeptutor:latest。
  • TutorBot シェル実行はデフォルトで無効になりました。 これに依存していた場合は、設定してください ボット上の allow_shell_exec。ツールへのアクセスはワークスペースに限定されます。
  • クロスサイト HTTPS 認証の場合、明示的な CORS 起点と cookie_secure=true を設定します。

何が変わったのか

  • 修正(設定): https://github.com/HKUDS/DeepTutor/pull/513 で @wedone によるプロファイルが存在しない場合にプロファイル ボタンを追加
  • https://github.com/HKUDS/DeepTutor/pull/508 の @lezhimiffyliu による init ウィザード プローブの GPT-5 トークン制限パラメーターを修正
  • 修正(セキュリティ): https://github.com/HKUDS/DeepTutor/pull/507 の @kagura-agent によるコマンド インジェクション (#506) に対して ExecTool のデフォルトを強化
  • 修正: https://github.com/HKUDS/DeepTutor/pull/509 の @washi4 によるドキュメント ノードがチャンク パイプラインをバイパスできないようにしました。
  • 功績: https://github.com/HKUDS/DeepTutor/pull/524 の @xiongjnu によるセッション応答の特大イベント ペイロードを切り詰める
  • 修正 (チャット): OpenAI 互換エンドポイント経由で推論モデルを呼び出すネイティブ ツールを有効にする (https://github.com/HKUDS/DeepTutor/pull/528 の @wedone による)

DeepTutor v1.4.1

Highlights

  • Security: TutorBot sandbox locked down — The shell exec tool is no longer registered by default; filesystem and shell access is confined to the bot workspace, command deny-lists are re-anchored at command boundaries, and allow_shell_exec can't be flipped via the update payload. This closes a chain of real vulnerabilities: TutorBot RCE via the shell tool (#518), filesystem path traversal (#517), cross-bot file-management authz bypass (#516), cross-session turn-regeneration bypass (#515), book-confirmation authz bypass (#514), and ExecTool running LLM shell commands over chat (#506, first hardened in PR #507). For anyone exposing bots or multiple users, this is the main reason to upgrade.

  • Breaking change / migration steps — Shell exec is now opt-in: bots that relied on it must explicitly set allow_shell_exec, and tool access stays workspace-confined. For cross-site HTTPS auth you must set explicit CORS origins and cookie_secure=true (the new /settings/network page normalizes origins to tolerate host:port and trailing slashes). Otherwise it's a drop-in from v1.4.0 via pip install -U deeptutor or ghcr.io/hkuds/deeptutor:latest.

  • Per-user isolation and a new bot API — Book roots, session databases, turn-runtime stores, and TutorBot directories are now scoped per user, and web/API conversations keyed per session, so cross-user/cross-session requests can no longer reach each other's data — complementing the authz fixes for shared or multi-tenant deployments. New POST /{bot_id}/chat and /chat/execute-stream (SSE) endpoints (feature request #511) add auto-start and persistent per-session context, enabling multi-turn conversations with a specific bot from external clients; there's no equivalent in v1.4.0.

  • Bug fixes, multimodal fallback, and safer uploads — Fixes the v1.4.0 regression where chat input disabled after the first turn (#520), long-document embedding failures (#521 / PR #509), Docker new-user profile creation (#512 / PR #513), Qwen reasoning models' native tool calling (#527 / PR #528), the GPT-5 init-wizard token parameter (PR #508), plus oversized session-event truncation (#524). Images are sent optimistically with a text-only retry for models lacking a known vision entry, fixing silently dropped images on Doubao/VolcEngine; .zip uploads now expand member-by-member through the document validator with size/count/compression-ratio bounds and path-escape guards (the archive itself is never indexed).

  • Verdict: upgrade if… — Upgrade if you run a shared/multi-user or network-exposed instance, depend on TutorBot tools, hit any of the fixed bugs (#520 is a day-one v1.4.0 regression), or want the new bot chat API. A single-user local install that never enabled shell exec and needs none of the fixes can reasonably skip; given the RCE/authz fixes, skipping is hard to recommend for anything internet-facing. Not a no-op or re-tag — this is a substantive security/stability patch.

DeepTutor v1.4.1 Release Notes

Release Date: 2026.05.27

v1.4.1 is a security and stability patch on v1.4.0. It locks down the TutorBot tool sandbox, isolates per-user resources, fixes a v1.4.0 chat regression, adds an HTTP API for talking to a specific TutorBot, and ships a multimodal image-fallback fix for providers DeepTutor has no vision entry for.

What's New

TutorBot Tool Sandbox Is Opt-In

The shell exec tool is no longer registered unless an admin sets allow_shell_exec, and all filesystem + shell access is confined to the bot workspace by default. Command deny-lists were re-anchored at command boundaries, and allow_shell_exec can't be flipped on via the update payload.

Per-User Resource Isolation

Book roots, session databases, turn-runtime stores, and TutorBot directories are scoped per user, and web/API conversations are keyed per session — so cross-user requests can't reach each other's data.

HTTP / SSE API For A TutorBot

New POST /{bot_id}/chat and /chat/execute-stream (SSE) endpoints with auto-start and persistent per-session context, for multi-turn conversations with a specific bot from external clients.

Multimodal Image Fallback

Images are sent optimistically to every provider; if a request carrying images fails and the model isn't in the known-vision allowlist, the turn retries text-only. Fixes silently dropped images on Doubao / VolcEngine and other multimodal models that lack a capability entry.

Safe ZIP Upload + Network Settings

.zip knowledge uploads expand member-by-member through the document validator with size / count / compression-ratio bounds and path-escape guards; the archive itself is never indexed. A new /settings/network page surfaces ports, public API base, and CORS origins (normalized to tolerate host:port and trailing slashes), plus a "fetch models" action listing model IDs from an OpenAI-compatible endpoint.

Community Fixes & Changes

Security — closed TutorBot RCE via the shell tool (#518), path traversal in the filesystem tool (#517), cross-bot file-management authz bypass (#516), cross-session turn-regeneration authz bypass (#515), book-confirmation authz bypass (#514), and ExecTool executing LLM shell commands over chat (#506, first hardened in PR #507).

Bug fixes — chat input disabled after the first turn (v1.4.0 regression, #520), knowledge-base embedding failure on long documents (#521 / PR #509), new users unable to create a profile under Docker (#512 / PR #513), Qwen reasoning models failing native tool calling (#527 / PR #528), and the GPT-5 init-wizard token parameter (PR #508).

Merged / reworked PRs — native tool calling for reasoning models (#528), oversized session-event truncation (#524), empty-state profile button (#513), chunking-pipeline fix (#509), GPT-5 probe (#508), ExecTool hardening (#507). Contributions #522 (zip upload) and #523 (model fetching + notebook lookup) were reimplemented locally and ship here.

Feature request — HTTP API for multi-turn chat with a specific TutorBot (#511).

Upgrade Notes

  • Drop-in from v1.4.0: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest.
  • TutorBot shell exec is now disabled by default. If you relied on it, set allow_shell_exec on the bot; tool access stays confined to the workspace.
  • For cross-site HTTPS auth, set explicit CORS origins and cookie_secure=true.
