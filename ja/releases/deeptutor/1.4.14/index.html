DeepTutor v1.4.14

パッチ 公開日2026年6月29日 出典HKUDS/DeepTutor English original

このページは機械翻訳です。内容は必ず英文原文をご確認ください。

#ディープチューター v1.4.14 #ディープチューター v1.4.14 Release Notes 発売日: 2026.06.29 v1.4.13 の修正と洗練のフォローアップ: 割り当てられたパートナーを 1 つの click とのチャットに直接開き、サブトピックを完了できなかった場合に Deep Research レポートがフラグを立て、MinerU がインストールされていない LightRAG インデックスが作成され、FAISS は非 ASCII パスを処理し、PocketBase セッションはユーザーごとに分離されます。デフォルトのバックエンドのドロップイン - 移行はありません。

新機能

割り当てられたパートナーを直接チャットに開く

管理者以外のユーザーの場合、管理者が割り当てたパートナーを clicking すると、そのパートナーがエージェントとして接続され、すでにそのパートナーを対象としている新しいチャットに参加できます。マイ エージェントを別途経由する必要はありません。管理者は、以前と同様にパートナーの管理ページに click を経由します。

Deep Research が部分的な結果にフラグを立てる

一部の研究サブトピックが完了できない場合、つまりブロックが終了せずにイテレーション予算を引き上げたり、使い果たしたりする場合、レポートは完全に成功したようには見えなくなります。この実行により警告通知が表示され、結果エンベロープには partial、failed_block_count、failed_block_titles が含まれるため、発信者はレポートが部分的な証拠に基づいていることを知ることができます (問題 #595)。

MinerU を使用しない LightRAG インデックス

RAG-Anything がデフォルトのパーサーで 1 回限りのインストール チェックを実行したため、別の解析エンジンを選択した場合でも、LightRAG インデックス作成が「パーサー 'mineru' が適切にインストールされていません」というメッセージでハード失敗しました。 DeepTutor はすでに解析済みのコンテンツをフィードしているため、偽のチェックはスキップされ、選択した解析エンジンに関係なくインデックス作成が続行されます (問題 #594)。

非 ASCII パス上の FAISS インデックス

パスに非 ASCII 文字 (中国語のナレッジ ベース名または C:\Users\张三 ホーム ディレクトリ) が含まれている場合、FAISS でサポートされたナレッジ ベースを再構築すると Windows でクラッシュしました。 FAISS インデックスは永続化され、Unicode パスを処理する Python バイト ストリームを通じてロードされるようになりました。ディスク上のフォーマットは変更されず、ストック FAISS との相互読み取りが可能です。

PocketBase セッションはユーザーごとに分離

オプションの PocketBase バックエンドでは、すべてのセッションが user_id でスタンプされ、フィルタリングされるようになり、デフォルトの SQLite バックエンドがすでに提供しているユーザーごとのファイル分離と一致します。セッションのメッセージとターンにはそのセッションを通じてのみ到達できるため、あるユーザーが別のユーザーの会話を読んだり変更したりすることはできなくなります。

アップグレードに関する注意事項

デフォルトの JSON/SQLite バックエンドの v1.4.13 からのドロップイン: pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。既存のシングルユーザー設定の移行や動作の変更はありません。 オプションの PocketBase バックエンドでは、セッションは user_id によってスコープされるようになりました。このアップグレード前に作成されたセッションには user_id が含まれず、再作成されるまで (または現在のユーザー ID でバックフィルされるまで) セッション リストに表示されません。 PocketBase はシングルユーザー統合のままです。マルチユーザー展開の場合は、integrations.pocketbase_url を空白にしておきます。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.4.13...v1.4.14

DeepTutor v1.4.14

Highlights

  • One-click assigned-partner chat — Non-admin users clicking an administrator-assigned partner now connect to it as an agent and open a fresh chat targeting that partner, eliminating the detour through My Agents. Admins still land on the management page, so test both roles if you customize navigation.

  • Partial Deep Research results are explicit — Failed or budget-exhausted subtopics now trigger a warning instead of presenting an apparently complete report. Result envelopes expose partial, failed_block_count, and failed_block_titles, allowing clients to handle incomplete evidence programmatically (issue #595).

  • LightRAG no longer requires MinerU — DeepTutor skips RAG-Anything’s default-parser installation check because it already supplies pre-parsed content. Indexing now proceeds with the selected parsing engine instead of failing with Parser 'mineru' is not properly installed (issue #594).

  • Unicode-safe FAISS persistence — FAISS-backed knowledge bases now save and load through a Python byte stream, avoiding Windows crashes caused by non-ASCII knowledge-base names or home paths such as C:\Users\张三. The on-disk format remains unchanged and compatible with stock FAISS, so existing indexes need no conversion.

  • PocketBase sessions are isolated by owner — Sessions are now stamped and filtered by user_id, preventing one user from reading or mutating another user’s messages and turns. Pre-upgrade sessions lack this field and disappear from listings until recreated or backfilled; PocketBase remains single-user, so keep integrations.pocketbase_url blank for multi-user deployments.

  • Default-backend upgrade remains drop-in — Existing JSON/SQLite deployments can run pip install -U deeptutor or pull ghcr.io/hkuds/deeptutor:latest without migrations. The PocketBase legacy-session handling above is the main upgrade caveat.

DeepTutor v1.4.14 Release Notes

Release Date: 2026.06.29

A fixes-and-polish follow-up to v1.4.13: open an assigned partner straight into chat with one click, Deep Research reports flag when a subtopic couldn't be completed, LightRAG indexes without MinerU installed, FAISS handles non-ASCII paths, and PocketBase sessions are isolated per user. Drop-in for the default backend — no migrations.

What's New

Open an assigned partner straight into chat

For a non-admin user, clicking a partner the administrator assigned now connects it as an agent and drops you into a fresh chat already targeting it — no separate trip through My Agents. Admins still click through to the partner's management page as before.

Deep Research flags partial results

When some research subtopics can't be completed — a block raises, or exhausts its iteration budget without finishing — the report no longer looks like a clean success. The run surfaces a warning notice and the result envelope carries partial, failed_block_count, and failed_block_titles, so callers can tell the report rests on partial evidence (issue #595).

LightRAG indexes without MinerU

LightRAG indexing hard-failed with "Parser 'mineru' is not properly installed" even when you'd picked a different parsing engine, because RAG-Anything ran a one-time install check on its default parser. DeepTutor already feeds it pre-parsed content, so that spurious check is now skipped and indexing proceeds regardless of which parse engine you chose (issue #594).

FAISS indexes on non-ASCII paths

Rebuilding a FAISS-backed knowledge base crashed on Windows when the path held non-ASCII characters — a Chinese knowledge-base name, or a C:\Users\张三 home directory. FAISS indexes now persist and load through a Python byte stream that handles Unicode paths; the on-disk format is unchanged and stays cross-readable with stock FAISS.

PocketBase sessions isolated per user

On the optional PocketBase backend, every session is now stamped with and filtered by user_id, matching the per-user-file isolation the default SQLite backend already provides. A session's messages and turns are reachable only through that session, so one user can no longer read or mutate another's conversations.

Upgrade Notes

Drop-in from v1.4.13 on the default JSON/SQLite backend: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations and no behavior changes for existing single-user setups.

On the optional PocketBase backend, sessions are now scoped by user_id. Sessions created before this upgrade carry no user_id and won't appear in the session list until re-created (or backfilled with the current user's id). PocketBase stays a single-user integration — keep integrations.pocketbase_url blank for multi-user deployments.
