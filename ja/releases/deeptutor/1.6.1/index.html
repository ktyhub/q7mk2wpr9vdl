#ディープチューターv1.6.1

ディープチューター v1.6.1 Release Notes

発売日: 2026.08.30 v1.6.0 がラーニングワークスペースに接続されました。 v1.6.1 は、あなたが毎日触れる部分に関するものです。モデル設定は一度入力する資格情報と目的別の割り当てに分割され、設定はカードの壁ではなくナビゲーターになり、サイドバー ファイルはトピックの下での会話を学習し、自分でアレンジできるようになり、LightRAG はラッパー経由ではなくファーストパーティ エンジンとして実行されます。ドロップイン — 移行や再インデックスは必要ありません。

新機能

1 つのキーを 1 回入力

モデル構成は 1 つのレイヤーを 7 回複製しました。各サービスは独自の資格情報を持つ独自のプロファイルを保持するため、単一の OpenRouter キーを 5 つの別々のページに貼り付ける必要がありました。 接続は、1 つのベンダー資格情報 (API キー、バージョン、追加ヘッダー、オプションのエンドポイント オーバーライド) を保持し、ベンダーが提供できるすべてのサービスにリンクします。 1 か所でキーを回転すると、リンクされているすべてのプロファイルに到達します。接続を削除すると、ワイプではなくリンクが解除されます。サービスごとに異なるキーが必要ですか?絶対に接続しないでください。

タスクモデル

誰も求めていない 2 つの呼び出し (最初のやり取りにちなんで会話に名前を付け、コンポーザーの下で開始点を記述する) は、実際の推論のために選択したモデルで実行する必要がなくなりました。カタログには、llm とまったく同じ形状の task サービスが含まれているため、その構成は同じ操作であり、プロバイダーを再度入力するのではなく、LLM サービスから引き継ぐことができます。空のままにすると (デフォルト)、どちらの呼び出しも以前とまったく同じように解決されます。

設定はハブではなくナビゲーターです

カードグリッドが消えてしまいました。永続的で検索可能なナビゲーターは 1 つの click 内のどのページにもアクセスでき、モデル / チャット / エージェントのカテゴリは 1 ページとしてスクロールし、下書きはナビゲーションを維持します — 下書きを保存すると実際に保存されるようになりました。接続を開くと、接続が独自のプロファイルに基づいてフィードするサービスが表示されます。

Mastery Path は独自の会話をファイルします

研究の会話はすでに mastery_path_id を運ぶ通常のセッションでした。サイドバーには必要なものがすべて揃っていましたが、どれも使用されませんでした。彼らは今、/home に着地して 3 つすべてをドロップするのではなく、トピックの下に座って、そのアウトライン、ウェイポイント ヘッダー、およびコンポーザーを含むチューターで開きます。 Composer プレースホルダーはビュー内のウェイポイントに対してタスク モデルによって書き込まれ、Tab はそれを受け入れます。

あなたが配置するサイドバー

特集ページは More グループに折りたたまれ、ナビゲーションとチャット履歴の両方がドラッグによって並べ替えられます。プレスは数ピクセル移動した後にのみドラッグになるため、行は clickable のままです。配置はビュー設定であり、配置したマシン上に存在します。

読書仲間はチャット サーフェスです

開いているドキュメントの横にあるパネルは、380 ピクセルで再実装されたものではなく、/home 独自のコンポーネント (同じメッセージ リスト、コンポーザー、アクティビティ ドロワー、アウトライン) から組み立てられるようになりました。読書にとってローカルに残るものは、実際にあるものです。開いている資料、選択した文章、リンクされた会話、およびビュー内のページに対して書かれたプレースホルダーです。読書セッションもサイドバーから除外されなくなり、コレクションの下にグループ化されます。

LightRAG、ファーストパーティ

LightRAG エンジンは、RAG-Anything を経由せずに、SDK と直接通信します。 pip install 'deeptutor[rag-lightrag]' は、サポートされている LightRAG リリースのみをプルするようになり、MinerU を推移的にドラッグしなくなりました。MinerU は独立して選択されたパーサーのままであり、強制的に競合する pdfplumber ピンは解除されます。部分的に受け入れられたイングレスおよび不確実な最初の候補は、追加時に破棄されずに保存されます。

修正

DeepSeek Pro ネイティブ Web 検索が有効になり、OpenAI バインディングではフラッシュ思考がオフになります。 Anthropic SDK 1.x では、再び temperature から extra_body が採用されます。 Jina 埋め込み検索の役割が尊重されます。スキャンされた PDF では、何も見つからなかったことが報告されるのではなく、解析に失敗した理由が説明されます。認証シークレットおよびトークン ファイルは所有者のみが作成されます。 ClawHub のインストールは、複数のユーザーがスラッグを共有し、新しく送信されたチャット ブランチが選択され、ask_user ペイロードが Unicode エスケープをリークしなくなったときに、パブリッシャーによってスコープが設定されます。

アップグレードに関する注意事項

pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。手動による移行やインデックスの再作成は必要ありません。既存のモデル プロファイルはそのまま機能し続け、接続とタスク モデルは両方ともオプトインされます。

  • そのエンジンを使用する場合は、LightRAG エクストラを再インストールします。 pip install -U 'deeptutor[rag-lightrag]' は、raganything を lightrag-hku に置き換えます。既存のインデックスはそのまま読み込まれます。この追加機能とともに提供される MinerU を信頼していた場合は、今すぐ意図的にインストールしてください。設定 → ドキュメント解析 で選択し、クラウド モードを設定するか、ローカル CLI をインストールしてください。
  • 接続はオプションです。 既存のサービスごとの資格情報は変更されず、従来どおりの方法で解決され続けます。 1 つのキーで複数のサービスを提供する場合にのみ接続を行ってください。リンクすると、保存時に資格情報がミラーリングされるため、すべてのコンシューマーは自己完結型プロファイルを読み続けます。
  • 英語と中国語のガイドを deeptutor.info でまとめて更新しました。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.6.0...v1.6.1

DeepTutor v1.6.1

Highlights

  • Connections decouple credentials from services — Model config splits into one vendor credential (API key, version, extra headers, optional endpoint override) and per-purpose assignment. One key now serves every service that vendor supports; rotate it once and all linked profiles follow, while deleting a connection unlinks rather than wipes. It's opt-in: existing per-service credentials keep resolving untouched, and linking mirrors the credential down on save so consumers still read self-contained profiles. The counterintuitive bit — if you actually want different keys per service, just never create a connection.

  • Task models split cheap calls from reasoning — A new task service, catalog-shaped exactly like llm, takes over conversation naming and composer starter suggestions so those two calls no longer bill against your reasoning model. Configure it identically and copy a provider over from LLM instead of re-typing. Left empty (the default) both calls resolve exactly as before, so this is a cost/latency win you can adopt without changing behavior.

  • LightRAG goes first-party — the one real migration item — The engine now calls the SDK directly rather than through RAG-Anything; reinstall with pip install -U 'deeptutor[rag-lightrag]' to swap raganything for lightrag-hku. The extra no longer drags in MinerU transitively (and the conflicting pdfplumber pin is lifted), so if you relied on MinerU arriving for free you must now install it deliberately and select it under Settings → Document Parsing (cloud mode or local CLI). Existing indexes are read as-is, no re-index, and partially accepted ingress / uncertain initial candidates are preserved instead of discarded on append.

  • Settings and sidebar become navigators you arrange — The Settings card grid is replaced by a persistent, searchable navigator with Models/Chat/Agents scrolling as one page; drafts survive navigation and "Save draft" now actually persists. Nav and chat history are drag-reorderable with a few-pixel press threshold so rows stay clickable — but the arrangement is a local view preference, not synced across machines. Mastery Path conversations (already tagged with mastery_path_id) now file under their topic and open in the tutor with outline, waypoint header and composer instead of dumping to /home, and reading sessions stop being excluded from the sidebar.

  • Reading companion reuses the chat surface — The document-side panel is assembled from /home's own message list, composer, activity drawer and outline instead of a 380 px fork, so behavior stays consistent; only genuinely local state remains (open material, selected passage, linked conversations, page-scoped placeholder written by the task model and accepted with Tab). Notable fixes: auth secret and token files are created owner-only, ask_user payloads stop leaking Unicode escapes, Anthropic SDK 1.x accepts temperature via extra_body again, DeepSeek Pro native web search is enabled with flash thinking off on OpenAI bindings, Jina embedding retrieval roles are honored, scanned PDFs explain why parsing failed, ClawHub installs are scoped by publisher on slug collisions, and newly sent chat branches are selected.

  • No breaking changes — Drop-in release: no manual migration or re-index, existing profiles work untouched, and both connections and task models are opt-in.

DeepTutor v1.6.1 Release Notes

Release Date: 2026.08.30

v1.6.0 connected the learning workspace. v1.6.1 is about the parts you touch every day: model configuration splits into a credential you enter once and a per-purpose assignment, Settings becomes a navigator instead of a wall of cards, the sidebar files study conversations under their topic and lets you arrange it yourself, and LightRAG runs as a first-party engine rather than through a wrapper. Drop-in — no migrations, no re-index.

What's New

One key, entered once

Model configuration was one layer replicated seven times: every service kept its own profile with its own credentials, so a single OpenRouter key had to be pasted into five separate pages. A connection now holds one vendor credential — API key, version, extra headers, an optional endpoint override — and links it down to every service that vendor can serve. Rotating the key in one place reaches every linked profile; deleting a connection unlinks rather than wipes. Want a different key per service? Simply never make a connection.

Task models

The two calls nobody asks for — naming a conversation after its first exchange, and writing the starting points under the composer — no longer have to run on the model you picked for actual reasoning. The catalog carries a task service shaped exactly like llm, so configuring it is the same act, and a provider can be brought over from the LLM service rather than typed again. Left empty, which is the default, both calls resolve exactly as before.

Settings is a navigator, not a hub

The card grid is gone. A persistent, searchable navigator reaches any page in one click, Models / Chat / Agents categories scroll as one page, and drafts survive navigation — Save draft now actually saves. Opening a connection shows the services it feeds on their own profiles.

Mastery Path files its own conversations

Study conversations were already ordinary sessions carrying a mastery_path_id; the sidebar had everything it needed and used none of it. They now sit under their topic and open in the tutor — with its outline, waypoint header and composer — instead of landing on /home and dropping all three. The composer placeholder is written by the task model against the waypoint in view, and Tab accepts it.

A sidebar you arrange

Feature pages fold into a More group, and both the nav and the chat history reorder by dragging — a press becomes a drag only after it travels a few pixels, so rows stay clickable. The arrangement is a view preference and lives on the machine you arranged it on.

The reading companion is the chat surface

The panel beside an open document is now assembled from /home's own components — the same message list, composer, activity drawer and outline — rather than a 380 px reimplementation of them. What stays local to reading is what actually is: the open material, the selected passage, the linked conversations, and a placeholder written against the page in view. Reading sessions also stop being excluded from the sidebar, and group under their collection.

LightRAG, first-party

The LightRAG engine talks to the SDK directly instead of going through RAG-Anything. pip install 'deeptutor[rag-lightrag]' now pulls only the supported LightRAG release and no longer drags MinerU in transitively — MinerU stays an independently selected parser, and the pdfplumber pin that conflict forced is lifted. Partially accepted ingress and uncertain initial candidates are preserved rather than discarded on append.

Fixes

DeepSeek Pro native web search is enabled and flash thinking is off on OpenAI bindings; Anthropic SDK 1.x takes temperature through extra_body again; Jina embedding retrieval roles are honored. Scanned PDFs explain why they failed to parse instead of reporting nothing found. Auth secret and token files are created owner-only. ClawHub installs are scoped by publisher when several share a slug, newly sent chat branches are selected, and ask_user payloads no longer leak Unicode escapes.

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No manual migration or re-index is required — existing model profiles keep working untouched, and connections and task models are both opt-in.

  • Reinstall the LightRAG extra if you use that engine. pip install -U 'deeptutor[rag-lightrag]' swaps raganything for lightrag-hku. Existing indexes are read as-is. If you relied on MinerU arriving with this extra, install it deliberately now — select it under Settings → Document Parsing and either configure its cloud mode or install its local CLI.
  • A connection is optional. Existing per-service credentials are untouched and keep resolving the way they always did. Make a connection only when you want one key to serve several services; linking mirrors the credential down on save, so every consumer keeps reading self-contained profiles.
  • The English and Chinese guides have been updated together at deeptutor.info.
