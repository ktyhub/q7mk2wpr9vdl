#ディープチューターv1.4.10

ディープチューター v1.4.10 Release Notes

発売日: 2026.06.21 v1.4.9 の展開とアカウントのフォローアップ: セルフサービス アバター付きのプロフィール ページ、ルートレスで実行できる強化されたコンテナ ストーリー 単一ポートの背後にあり、マルチユーザー展開では MCP ツールへのアクセスが強化されます。 全員のためのドロップイン - 1 つの動作変更は、管理者以外のユーザーを対象としています。 マルチユーザーモード。

マルチユーザー展開について注意してください。 MCP ツールは デフォルトで拒否されるようになりました 管理者以外のユーザーの場合: 通常のユーザーは検出またはロードできなくなります 管理者が特定のツール名を付与するまで、展開全体の MCP ホスト ツール 彼らの助成金で。管理者は無制限で、シングルユーザー/認証なしでインストール可能 は影響を受けません (セッションは管理者として実行されます)。何も移行せず、何もありません アップグレード時に中断 — 管理者以外が MCP ツールを必要とする場合は、 ユーザーの許可。

新機能

アバターを含むプロフィール ページ

サインインしているすべてのユーザーにはセルフサービス プロフィール ページが表示されます: 組み込みアイコンを選択してください (色付き) または独自の画像をアバターとしてアップロードし、アカウントと役割を確認します。 そしてサインアウトします。アバターがサイドバーに表示され、管理リングのマークが表示されます。 管理者アカウントの概要。

ルートレス対応のコンテナで DeepTutor を実行する

新しい CONTAINERIZATION.md ガイドは、プレーン docker run、docker compose の 3 つの形状をカバーします。 PocketBase サイドカー、および強化されたルートレス Podman パス (compose.yaml、 読み取り専用のルート ファイルシステム、tmpfs システム ディレクトリ) — 開始するための .env.example を追加 から。フロントエンドは、要求に応じて /api/* および /ws/* をバックエンドにプロキシするようになりました。 time* であるため、ブラウザは 1 つのポート (:3782) とのみ通信します。API URL はベイクされません JS バンドルに追加すると、sed は起動しません。単一のポートをマッピングすれば完了です。

マルチユーザー モードでの MCP ツールへのアクセスが強化されました

上で述べたように、管理者以外のユーザーは、管理者がアクセスするまで MCP ツールでフェールクローズされるようになりました。 名前を付与します。付与エディターには、MCP ツールの付与が表示されます。 組み込みツールのホワイトリストにより、各ユーザーがアクセスできる範囲を正確に確認して設定できます。

ログの静か化

ルーチン 200 — /settings、/tools、 /knowledge/list とその友人たち — コンソールに洪水が起こることはもうありません。ユビコーンの リクエストごとのアクセス ログが すべて の起動パスで無効になりました (deeptutor start、ランチャー、Docker エントリーポイント)、および単一のミドルウェア 200 以外の、実際に見る価値のあるもののみを表示します。

修正

  • Client 認証状態は、リクエスト時に新しいプロキシを通じて解決されます。 アップロードのリクエスト本文 (アバター画像、添付ファイル) のサイズを設定します。
  • アバターのレンダリングは、未知の色に対して向きを変える代わりに安全にフォールバックします 目に見えない;認証ステータスのフェッチは重複排除されます。
  • docker-compose.yml PocketBase マウント パスを修正しました。

アップグレードに関する注意事項

v1.4.9 からのドロップイン: pip install -U deeptutor; Dockerユーザープル ghcr.io/hkuds/deeptutor:latest。移行や構成の変更は必要ありません。 マルチユーザー展開のみ: 管理者以外のユーザーが MCP ツールに依存している場合、 ユーザーごとに特定のツール名を付与します。そうするまでツールはフェールクローズされます。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.4.9...v1.4.10

DeepTutor v1.4.10

Highlights

  • Single-port container deployment — The frontend now proxies /api/* and /ws/* to the backend at request time, so the browser only talks to :3782: no API URL baked into the JS bundle and no startup sed to rewrite it. If you've maintained custom image-URL wiring or entrypoint hacks, you can drop them and just map one port. The new CONTAINERIZATION.md documents three shapes — plain docker run, Compose with the PocketBase sidecar, and a hardened rootless Podman path (read-only root filesystem, tmpfs system dirs) — plus a .env.example; worth reading before migrating, especially since the PocketBase mount path in docker-compose.yml was corrected here.
  • MCP tools fail closed for non-admins — In multi-user mode, regular users can no longer discover or load deployment-wide MCP host tools until an admin grants the specific tool names in that user's grant. Admins stay unrestricted and single-user/no-auth installs are unaffected (their session runs as admin). This is the only behavioral change in the release, and it's a quiet one: an existing non-admin workflow that called MCP tools simply loses access on upgrade, and nothing migrates automatically. Audit grants and add the tool names before rollout if non-admins depend on them; the grant editor now surfaces MCP grants alongside the built-in tool whitelist.
  • Self-service profile and avatars — Signed-in users get a Profile page to pick a built-in icon with a color or upload an image, see account and role, and sign out; the avatar appears in the sidebar and an admin ring marks privileged accounts. For integrators: avatar and attachment uploads now traverse the new request-time proxy, which correctly sizes request bodies, unknown avatar colors fall back safely instead of rendering invisible, and the auth-status fetch is de-duplicated — fewer redundant calls on load.
  • Access logging overhauled — Routine 200s from chatty frontend polling (/settings, /tools, /knowledge/list, etc.) no longer flood the console, and uvicorn's per-request access log is disabled on every launch path (deeptutor start, the launcher, and the Docker entrypoint). A single middleware surfaces only non-200s. Operators get much less noise, but note you lose the 200-level request trail — adjust any log-based monitoring or debugging that relied on it.
  • Drop-in upgrade path — From v1.4.9: pip install -U deeptutor, or pull ghcr.io/hkuds/deeptutor:latest for Docker; no migrations and no configuration changes. The sole action item is conditional — grant MCP tool names per user if your non-admins relied on them.

No breaking changes.

DeepTutor v1.4.10 Release Notes

Release Date: 2026.06.21

A deployment-and-account follow-up to v1.4.9: a self-service profile page with avatars, a hardened container story you can run rootless behind a single port, and tighter MCP tool access in multi-user deployments. Drop-in for everyone — the one behavior change is scoped to non-admin users in multi-user mode.

Heads-up for multi-user deployments. MCP tools are now deny-by-default for non-admin users: a regular user can no longer discover or load deployment-wide MCP host tools until an admin grants the specific tool names in their grant. Admins stay unrestricted, and single-user / no-auth installs are unaffected (their session runs as admin). Nothing migrates and nothing breaks on upgrade — if your non-admins need MCP tools, grant the names in the user's grant.

What's New

Profile page with avatars

Every signed-in user gets a self-service Profile page: pick a built-in icon (with a color) or upload your own image as an avatar, see your account and role, and sign out. Your avatar then shows up in the sidebar, and an admin ring marks admin accounts at a glance.

Run DeepTutor in a container, rootless-ready

A new CONTAINERIZATION.md guide covers three shapes — plain docker run, docker compose with the PocketBase sidecar, and a hardened rootless Podman path (compose.yaml, read-only root filesystem, tmpfs system dirs) — plus a .env.example to start from. The frontend now proxies /api/* and /ws/* to the backend at request time, so the browser only ever talks to one port (:3782): no API URL baked into the JS bundle, no startup sed. Map a single port and you're done.

Tighter MCP tool access in multi-user mode

As noted above, non-admin users now fail closed on MCP tools until an admin grants the names. The grant editor surfaces MCP tool grants alongside the built-in tool whitelist, so you can see and set exactly what each user can reach.

Quieter logs

Routine 200s — the chatty frontend polling of /settings, /tools, /knowledge/list, and friends — no longer flood the console. uvicorn's per-request access log is now disabled on every launch path (deeptutor start, the launcher, and the Docker entrypoint), and a single middleware surfaces only non-200s, the ones actually worth seeing.

Fixes

  • Client auth state resolves at request time through the new proxy, which also sizes the request body for uploads (avatar images, attachments).
  • Avatar rendering falls back safely for unknown colors instead of turning invisible; the auth-status fetch is de-duplicated.
  • docker-compose.yml PocketBase mount path corrected.

Upgrade Notes

Drop-in from v1.4.9: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations, no configuration changes. Multi-user deployments only: if your non-admin users rely on MCP tools, grant the specific tool names per user — they fail closed until you do.
