DeepTutor v1.5.5

#ディープチューター v1.5.5 #ディープチューター v1.5.5 Release Notes 発売日: 2026.07.26 v1.5.4 のフォローアップで、モデルを導入するための 2 つの新しい方法 - 独自の ChatGPT プランでサインインするか、Eden AI のゲートウェイを経由するルート - 実際に何を保持しているかを最終的に明らかにできるナレッジ ベース、およびループ回避策が不要になった GraphRAG インデックス作成。ドロップイン、移行なし。 v1.5.4 を実行した場合は、以下のチャット分岐修正を適用する必要があります。

新機能

ChatGPT プランでサインインします (実験的)

OpenAI Codex はファーストパーティ OAuth プロバイダー (#690) になりました。 [設定] → [モデル] → [LLM] で選択すると、ブラウザーのサインインにより、API キー フィールドがそのアカウントのライブ カタログから読み取られたモデル リストに置き換えられます。リモート ボックスでは代わりに deeptutor provider login openai-codex を実行します。資格情報は所有者のみのアクセス許可で <user-root>/private/openai-codex/ に保持され、~/.codex が読み取られたり変更されたりすることはありません。トークンは 1 人のユーザーのプランを承認するため、プロファイルはアカウントごとです。ユーザー許可によって割り当てることはできません。サインインは、LLM がまだ構成されていない場合にのみアクティブなモデルになります。これにより、背後で展開が再ポイントされることはありません。この互換性パスは実験的なものです。上流インターフェイスは変更される可能性があります。

エデンAI

Eden AI は、35 番目の LLM バインディング (#671) として参加します。これは、<provider>/<model> としてアドレス指定されたモデルを備え、1 つのキーの背後で多くのプロバイダーに到達する OpenAI 互換ゲートウェイです。

保持している内容を把握しているナレッジベース

ナレッジ ベースにファイルがいくつあるか、またはその中にドキュメントが含まれているかどうかを尋ねても、クエリが偶然一致したチャンクから答えが得られることはなくなりました。添付された各 KB は実際のドキュメント インベントリをターンに持ち込むようになりました。さらに、グロブ フィルターと部分文字列フィルターを使用してオンデマンドで列挙する新しい kb_files ツールが追加されました。KB が添付されるたびにマウントされ、他のツールと同様にパートナーごとに拒否できます。リンクされたフォルダーと Obsidian Vault は所定の位置に列挙されます。リモートの LightRAG サーバーは、ゼロを報告するのではなく、自身をリスト不可能であると宣言します。 KB ページとチャットの回答は同じ定義を参照するようになったため、同じライブラリについて意見が相違することはなくなりました。

追跡可能な RAG 引用

rag ツールは、独自のクエリの単なるエコーである単一の「ソース」を報告し、出所のない根拠のある回答を残していました。現在は、チャンク、エンティティ、および実際に返された取得レポート (#694) を転送します。ローカルの LightRAG パイプラインは合成された回答のみを保持するため、1 つのエンジンには引用するものがまだありません。

ループ回避策を使用しない GraphRAG インデックス作成

GraphRAG は、uvloop を拒否するパッチをインポートします (ループ uvicorn[standard] が macOS と Linux のバックエンドに提供します)。したがって、アプリ全体で UVICORN_LOOP=asyncio を強制しない限り、インデックス作成はインポート時に停止します。すべての GraphRAG エントリ ポイントは、独自のストック非同期ループ (#695) を備えたワーカー スレッドで実行されるようになり、最初のインデックス作成の実行を中断した 2 つの構成エラー (ファイル パターン内のエスケープされていない $ と未登録のキャッシュ タイプ) が修正されました (#699)。

さまざまな修正

  • オプティミスティック メッセージ ID が再び一意になりました (#698): ユーザー行とアシスタント プレースホルダーは同じミリ秒内に作成され、1 つの永続化された ID に折りたたまれ、リロードされるまで表示されているスレッドから応答を削除できます。 v1.5.4 のその場でのターン調整によって明らかになります。
  • パートナー チャットで上にスクロールすると、下に引っ張られるのではなく、スクロールした場所に留まります (#704)。
  • claude-opus-5 はエフォートベースのモデルとして認識されるため、リクエストは拒否された temperature の送信を停止します (#703)。 Kimi ブランドの Moonshot モデルでは、パラメーターを 1.0 に固定するのではなく、完全に省略するようになりました。
  • deeptutor start は、レガシー Windows コード ページ (#702) でログをリレーし続けます。Next.js バナー内の ✓ は、cp950/cp936/cp932 のリレー スレッドを強制終了し、セッションをサイレントのままにするために使用されます。

アップグレードに関する注意事項

v1.5.4 からのドロップイン: pip install -U deeptutor; Docker ユーザーは ghcr.io/hkuds/deeptutor:latest を引きます。移行やスキーマや構成の変更はありません。

  • GraphRAG インデックス作成を回避するために UVICORN_LOOP=asyncio を設定している場合は、それを削除できます。
  • OpenAI Codex のサインインは設計上アカウントごとです。各ユーザーは自分でサインインし、プロファイルを助成金を通じて配布することはできません。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.4...v1.5.5 </コンテンツ> </invoke>

DeepTutor v1.5.5

Highlights

  • New model access — Experimental first-party OpenAI Codex OAuth lets you sign in with your own ChatGPT plan and use its live model catalog; remote installs use deeptutor provider login openai-codex. This is a per-account provider, cannot be assigned through user grants, and only activates when no LLM is configured. Eden AI adds an OpenAI-compatible gateway binding using <provider>/<model> addresses. Worth trying if either access method fits your setup; existing API-key configurations remain untouched.
  • More trustworthy knowledge-base answers — Attached KBs now receive a real document inventory, and the new kb_files tool enumerates files with glob/substring filters, including linked folders and Obsidian vaults. Remote LightRAG servers report themselves as unlistable instead of falsely showing zero files. The rag tool also returns actual chunks, entities, and reports as citation provenance rather than echoing its query, though local LightRAG still has no retrievable provenance to cite.
  • GraphRAG indexing works without a loop override — GraphRAG entry points now run on worker threads with a stock asyncio loop, avoiding the uvloop conflict supplied by uvicorn[standard]. First-run failures from an unescaped $ in the file pattern and an unregistered cache type are also fixed. Migration: remove UVICORN_LOOP=asyncio if you added it solely for this workaround.
  • Chat and model-compatibility fixes — Unique optimistic message IDs prevent replies disappearing until reload, scrolling up in partner chats no longer snaps back, claude-opus-5 avoids unsupported temperature, Kimi-branded Moonshot models omit it entirely, and deeptutor start survives legacy Windows code pages. These are targeted reliability fixes rather than new workflows.
  • Upgrade recommendation — Drop-in from v1.5.4 with pip install -U deeptutor or ghcr.io/hkuds/deeptutor:latest; there are no breaking changes, migrations, or schema/config changes. v1.5.4 users should upgrade for the chat fixes, and GraphRAG users benefit directly; others can skip if the new providers, KB introspection, and citation provenance are not useful to them.

DeepTutor v1.5.5 Release Notes

Release Date: 2026.07.26

A follow-up to v1.5.4 with two new ways to bring a model — sign in with your own ChatGPT plan, or route through Eden AI's gateway — knowledge bases that can finally say what they actually hold, and GraphRAG indexing that no longer needs a loop workaround. Drop-in, no migrations; if you ran v1.5.4, the chat-branching fix below is the one to take.

What's New

Sign in with your ChatGPT plan (experimental)

OpenAI Codex is now a first-party OAuth provider (#690). Pick it under Settings → Models → LLM and a browser sign-in replaces the API-key fields, with the model list read from that account's live catalog; on a remote box run deeptutor provider login openai-codex there instead. Credentials stay in <user-root>/private/openai-codex/ with owner-only permissions, and ~/.codex is never read or modified. Because a token authorizes one person's plan, the profile is per-account: it is not assignable through user grants, and signing in only becomes the active model when no LLM is configured yet — it never repoints a deployment behind your back. This compatibility path is experimental; the upstream interface may change.

Eden AI

Eden AI joins as the 35th LLM binding (#671) — an OpenAI-compatible gateway that reaches many providers behind one key, with models addressed as <provider>/<model>.

Knowledge bases that know what they hold

Ask how many files a knowledge base has, or whether some document is in it, and the answer no longer comes from whichever chunks the query happened to match. Each attached KB now carries a real document inventory into the turn, plus a new kb_files tool that enumerates on demand with glob and substring filters — mounted whenever a KB is attached, and deniable per partner like any other tool. Linked folders and Obsidian vaults are enumerated in place; a remote LightRAG server declares itself unlistable rather than reporting zero. The KB page and the chat answer now read the same definition, so they can no longer disagree about the same library.

Traceable RAG citations

The rag tool used to report a single "source" that was just an echo of its own query, leaving grounded answers with no provenance. It now forwards the chunks, entities, and reports retrieval actually returned (#694). The local LightRAG pipeline keeps only its synthesised answer, so that one engine still has nothing to cite.

GraphRAG indexing without the loop workaround

GraphRAG imports a patch that refuses uvloop — the loop uvicorn[standard] gives the backend on macOS and Linux — so indexing died at import unless you forced UVICORN_LOOP=asyncio for the whole app. Every GraphRAG entry point now runs on a worker thread with its own stock asyncio loop (#695), and two config faults that broke the first indexing run — an unescaped $ in the file pattern and an unregistered cache type — are fixed (#699).

Assorted fixes

  • Optimistic message ids are unique again (#698): the user row and the assistant placeholder could be minted in the same millisecond, collapse onto one persisted id, and drop the reply from the visible thread until a reload. Exposed by v1.5.4's in-place turn reconciliation.
  • Scrolling up in a partner chat stays where you put it instead of being yanked back down (#704).
  • claude-opus-5 is recognized as an effort-based model, so requests stop carrying the temperature it rejects (#703); Kimi-branded Moonshot models now omit the parameter entirely rather than pinning it to 1.0.
  • deeptutor start keeps relaying logs on legacy Windows code pages (#702) — a ✓ in the Next.js banner used to kill the relay thread on cp950/cp936/cp932 and leave the session silent.

Upgrade Notes

Drop-in from v1.5.4: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations, no schema or config changes.

  • If you set UVICORN_LOOP=asyncio to work around GraphRAG indexing, you can drop it.
  • OpenAI Codex sign-in is per-account by design — each user signs in for themselves, and the profile cannot be handed out through grants.
