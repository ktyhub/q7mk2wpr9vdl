DeepTutor v1.5.8

#ディープチューター v1.5.8 #ディープチューター v1.5.8 Release Notes 発売日: 2026.08.02 メンテナンス リリースのターゲットは 1 つです。climbing の代わりにメモリが保持されます。 v1.5.7 ソース デプロイメントは、V8 がセッション途中で終了する前に 14 GB を超えました。原因は独立していることが判明しました。フロントエンド開発サーバーのヒープ上限が、メモリ、無制限のインプロセス キャッシュ、および毎ターン構築される新しい HTTP client を保持するプロセスに達することがありませんでした。ドロップイン — 移行はありませんが、ソース チェックアウトの開始方法が変わります。

新機能

開発サーバーは実際には上限が設定されていませんでした

next dev は、自身が生成するワーカー内でレンダリングされ、argv 内の V8 フラグは子プロセスに継承されません。そのため、長年存在する node --max-old-space-size=4096 …/next dev は、メモリを保持するプロセスに到達しませんでした。 NODE_OPTIONS に上限がないことが判明したため、Next は合計 RAM の 50%、つまり 24 GB マシン上の 12 GB ヒープを置き換えました。V8 は、単一マーク コンパクト内で 63 秒後に Ineffective mark-compacts near heap limit で終了する前に、実際にこの領域を埋めようとしました。 web/scripts/dev.mjs は NODE_OPTIONS を介して上限を通過するようになりました。これはワーカーが継承し、Next が尊重します。4 GB に固定され、ホストの RAM ではなくコンテナー内の cgroup 制限に合わせてサイズ設定されます。

ソース インストールは実稼働ビルドを提供します

チェックアウトからの deeptutor start は、フロントエンドを .next-deeptutor に一度ビルドしてスタンドアロン出力を提供し、入力が実際に変更されるまでそのビルドを再利用します (web/ ツリーのフィンガープリント、バージョン ファイル、およびビルド時のパブリック設定)。ホット リロードは deeptutor start --dev に移動し、.next (別のディレクトリ) を使用し続けるため、どちらのモードも実行中に他のモードの出力を無効にします。長時間実行されるデプロイメントでは、開発コンパイラーのキャッシュに料金が発生しなくなります。

LLM clients をターンごとに 1 つではなく境界付きにする

チャット、調査、質問の各パイプラインは、毎回新しい OpenAI 互換の client を構築し、それを使用して新しい HTTP 接続プールを構築しました。エージェント client とサービス層プロバイダーは両方とも、2 つの小さなイベント ループ ローカル LRU プールから取得され、バインディング、モデル、資格情報、およびベース URL に基づいてキー設定され、シャットダウン時に閉じられ、設定が変更されるとリタイアされます。選択したバックエンドの SDK のみがインポートされます。

上限のあるキャッシュ

ナレッジタスクのログ ストリームは、タスクごとのイベントとバイト数に上限を設け、タスク終了後 1 時間で期限切れになり、小さな完了のトゥームストーンを残すため、遅れたサブスクライバーでもタスクが完了したことがわかります。完了タスク テーブルには 256 のエントリが保持されます。 LlamaIndex インデックス キャッシュは 8 エントリから 2 エントリに減少し、10 分間アイドル状態のエントリをすべて削除します。ブック ランタイムは、プロセスの間存続するのではなく、キューが空になると解放されます。

すでに解放されているものを取り戻す

ターン、完了した本のジョブ、または完了したナレッジベースのタスクの後、DeepTutor はサイクルを収集し、Linux 上では malloc_trim を呼び出します。これにより、Glibc は、RSS が永続的に固定されているように見えるアリーナを保持する代わりに、ヒープ ページをハンズフリーで戻します。コンテナーと deeptutor start は、MALLOC_ARENA_MAX=2 と下位トリムしきい値も設定します。どちらも、独自に調整したオペレーターによってオーバーライドできます。

500 番台として浮上したキープアライブ レース

web/proxy.ts はノードの http.globalAgent を介してバックエンドに転送し、5 秒タイマーでアイドル状態のソケットを取得します (uvicorn のデフォルトと同じ)。両端が同じソケット上で同じタイマーを作動させ、それを閉じるために競走しました。サーバーの FIN が、プールが同時に新しいリクエストを処理しているソケットに到達すると、そのリクエストは ECONNRESET で終了し、「セッションのロードに失敗しました」として UI に到達しました。 uvicorn を起動するたびに --timeout-keep-alive 300 が設定されるようになり、アイドル状態の接続を解除する側は client だけになります。

各種詰め合わせ

  • deeptutor.agents、deeptutor.core.agentic、プロバイダー コア パッケージ、ドキュメント抽出プログラムのパーサー ライブラリ (PyMuPDF、pypdf、python-docx、openpyxl、python-pptx)、および LLM エラー マッピング ルールはすべて、インポート時ではなく最初の使用時に解決されます。
  • python -m deeptutor.api.run_server は --reload で始まらなくなりました。 DEEPTUTOR_DEV_RELOAD=1 をエクスポートします。 Reload はスーパーバイザとワーカーを実行し、開発機構であるファイル ウォッチャーの状態を保持します。 deeptutor serve --reloadは変更ありません。

アップグレードに関する注意事項

v1.5.7 からのドロップイン: pip install -U deeptutor; Dockerユーザーはghcr.io/hkuds/deeptutor:latestを引きます。スキーマや構成の変更はありません。

  • ソース チェックアウトは、提供される前に構築されます。 アップグレード後の最初の deeptutor start は npm run build を実行し、それに応じて時間がかかります。後で起動すると、ソースが変更されるまでそれが再利用されます。以前のホットリロード ループには deeptutor start --dev を使用します。新しい web/.next-deeptutor/ ビルド ディレクトリは git 無視されます。
  • python -m deeptutor.api.run_server はデフォルトでリロードされなくなりました。 DEEPTUTOR_DEV_RELOAD=1 をエクスポートして復元します。 フル Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.7...v1.5.8

DeepTutor v1.5.8

Highlights

  • Dev-server heap limits now work — The 4 GB V8 ceiling moves into NODE_OPTIONS, which Next’s spawned worker actually inherits; previously, flags in argv never capped the memory-holding process. Container deployments size the limit against the cgroup allocation rather than host RAM.

  • Source installs default to production builds — deeptutor start now builds standalone frontend output into .next-deeptutor and reuses it until fingerprinted inputs change. The first launch takes longer; use deeptutor start --dev for hot reload. Separately, python -m deeptutor.api.run_server no longer reloads unless DEEPTUTOR_DEV_RELOAD=1 is exported; deeptutor serve --reload is unchanged.

  • LLM clients and SDK imports are bounded — Chat, research, and question pipelines share an event-loop-local, two-entry LRU client pool keyed by binding, model, credentials, and base URL instead of creating an HTTP connection pool every turn. Clients close on shutdown or settings changes, and only the selected backend’s SDK is imported.

  • Caches now have explicit ceilings — Task streams cap events and bytes, expire an hour after completion, and retain a completion tombstone for late subscribers. Completed tasks keep 256 entries, LlamaIndex indexes keep two with 10-minute idle eviction, and book runtimes are released after their queues drain. Linux also runs malloc_trim; MALLOC_ARENA_MAX=2 and trim thresholds remain operator-overridable.

  • Keep-alive socket races are reduced — Uvicorn now launches with --timeout-keep-alive 300, leaving Node’s proxy agent to retire idle connections instead of racing the server. This targets the ECONNRESET failures that surfaced as “Failed to load sessions.”

  • Breaking changes — None; this is a drop-in upgrade with no schema or configuration migration.

DeepTutor v1.5.8 Release Notes

Release Date: 2026.08.02

A maintenance release with one target: memory that stays put instead of climbing. A v1.5.7 source deployment grew past 14 GB before V8 gave up mid-session, and the causes turned out to be independent — a frontend dev server whose heap ceiling never reached the process holding the memory, unbounded in-process caches, and a fresh HTTP client built for every turn. Drop-in — no migrations, but a source checkout now starts differently.

What's New

The dev server was never actually capped

next dev renders in a worker it spawns itself, and V8 flags in argv are not inherited by child processes — so the long-standing node --max-old-space-size=4096 …/next dev never reached the process that holds the memory. Finding no ceiling in NODE_OPTIONS, Next substituted 50% of total RAM: a 12 GB heap on a 24 GB machine, which V8 genuinely tried to fill before dying in Ineffective mark-compacts near heap limit after 63 seconds inside a single mark-compact. web/scripts/dev.mjs now passes the ceiling through NODE_OPTIONS, which the worker does inherit and Next honors — clamped to 4 GB, and sized against the cgroup limit inside a container rather than the host's RAM.

Source installs serve a production build

deeptutor start from a checkout now builds the frontend once into .next-deeptutor and serves the standalone output, reusing that build until an input actually changes (a fingerprint over the web/ tree, the version file, and the build-time public settings). Hot reload moves to deeptutor start --dev, which keeps using .next — separate directories, so neither mode invalidates the other's output while it is running. A long-running deployment no longer pays for a dev compiler's caches.

Bounded LLM clients instead of one per turn

The chat, research and question pipelines each built a fresh OpenAI-compatible client — and with it a new HTTP connection pool — on every turn. Both the agentic client and the services-layer provider now come from a small event-loop-local LRU pool of 2, keyed on binding, model, credentials and base URL, closed on shutdown and retired when settings change. Only the selected backend's SDK is imported.

Caches with a ceiling

Knowledge-task log streams now cap events and bytes per task, expire an hour after a task ends, and leave a small completion tombstone so a late subscriber still learns the task finished. The completed-task table keeps 256 entries. The LlamaIndex index cache drops from 8 entries to 2 and evicts anything idle for 10 minutes. A book runtime is released once its queue drains instead of living for the process.

Reclaiming what was already freed

After a turn, a finished book job, or a completed knowledge-base task, DeepTutor collects cycles and — on Linux — calls malloc_trim so glibc hands free heap pages back instead of holding arenas that make RSS look permanently pinned. Containers and deeptutor start also set MALLOC_ARENA_MAX=2 and a lower trim threshold, both overridable by an operator who has tuned their own.

A keep-alive race that surfaced as 500s

web/proxy.ts forwards to the backend over Node's http.globalAgent, which reaps idle sockets on a 5s timer — identical to uvicorn's default. Both ends armed the same timer on the same socket and raced to close it; when the server's FIN landed on a socket the pool was simultaneously handing to a new request, that request died with ECONNRESET and reached the UI as "Failed to load sessions". Every uvicorn launch now sets --timeout-keep-alive 300, leaving the client as the only side that retires an idle connection.

Assorted

  • deeptutor.agents, deeptutor.core.agentic, the provider-core package, the document extractor's parser libraries (PyMuPDF, pypdf, python-docx, openpyxl, python-pptx) and the LLM error-mapping rules all resolve on first use rather than at import time.
  • python -m deeptutor.api.run_server no longer starts with --reload; export DEEPTUTOR_DEV_RELOAD=1 for it. Reload runs a supervisor plus a worker and retains file-watcher state, which is development machinery. deeptutor serve --reload is unchanged.

Upgrade Notes

Drop-in from v1.5.7: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No schema or config changes.

  • Source checkouts build before they serve. The first deeptutor start after upgrading runs npm run build and takes correspondingly longer; later launches reuse it until the source changes. Use deeptutor start --dev for the previous hot-reload loop. The new web/.next-deeptutor/ build directory is git-ignored.
  • python -m deeptutor.api.run_server no longer reloads by default. Export DEEPTUTOR_DEV_RELOAD=1 to restore it.
