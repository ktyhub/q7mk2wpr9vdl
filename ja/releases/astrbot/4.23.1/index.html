#アストラボットv4.23.1

何が変わったのか

これは v4.23.0 のホットフィックス バージョンです: v4.23.1

  • python-ripgrep 依存関係を 0.0.8 にダウングレードし、Python、3.13、および 3.14 バージョンが正常に起動できない問題を修正します。 (#7514)
  • セッションIDにコロン:が含まれる場合、プラットフォームルートがダッシュボードに表示されない問題を修正しました。 (#7517)
  • DeerFlow 2.0、更新された DeerFlow Runner、API Client、セッション コマンド、プロバイダー管理ロジック、構成ドキュメント、および関連テストに適応しました。 (#7500)
  • ダッシュボードv-mainの不要な余白を削除します。余分な余白によって背景色が見えるため、視覚的には右側に余分な境界線があるように見えます。 (#7481) ・プラグインのインストール状況確認時の形式不一致による判定不具合を修正しました。 (#7493)
  • ダッシュボードのコード ブロックの強調表示が Shiki に切り替えられ、ダーク/ライト テーマのレンダリングが同期され、README、更新ログ、チャット メッセージのコード ブロックの表示効果が最適化されます。 (#7497)

追加 (v4.23.0)

  • ファイルの読み取り (read)、書き込み (write)、編集 (edit)、Grep 検索 (ripgrep)、およびコンピューター使用機能のためにセッションごとに分離されたワークスペースをサポートします。 (#7402)
  • WeChat 個人アカウント アダプターは、参照メッセージの解析をサポートします。 (#7380)
  • Brave Search Web 検索ツールを追加し、古いデフォルトの Web 検索実装を削除しました。 (#6847)
  • Mattermost プラットフォーム アダプターのサポートを追加しました。 (#7369)
  • NVIDIA リランク プロバイダーを追加しました。 (#7227)
  • LongCat LLM プロバイダーを追加しました。 (#7360)
  • OpenAI および Gemini オーディオ入力モードのサポートを追加し、ChatUI 録音に関連する問題を修正しました。 (#7378)
  • Discord プラットフォームには新しいボット メッセージ フィルタリング構成が追加され、他のボットからメッセージを受信するかどうかを制御できるようになります。 (#6505)
  • モデルがツール呼び出しを繰り返す状況を軽減するために、ツール呼び出しの繰り返しをガイドする LLM の機能を追加しました。 (#7388)
  • QQ 公式 API は、ファイル送信の安定性を向上させるために、ファイル アップロードのリトライ メカニズムを追加します。 (#7430)

最適化 (v4.23.0)

  • ChatUI スタイル、メッセージ レンダリング、および入力エクスペリエンスを再構築し、チャット インターフェイスの全体的な保守性と対話の一貫性を向上させます。 (#7485)
  • Cron 関連ツールを統合管理ツールに統合し、Cron タスク編集機能を追加します。 (#7445)
  • 組み込みツール管理ロジックを再構築し、AstrBot 組み込みツールの登録と呼び出しのメンテナンスを改善します。 (#7418)
  • 頻度の低い組み込みコマンドの大部分を削除してコマンド機能を統合し、これらのコマンドを builtin-command-extension プラグインに移動し、ドキュメントを更新しました。 (#7478)
  • デフォルトの Web 検索実装を削除し、新しい検索ツール リンクに置き換えました。 (#7416)
  • インストールのサイズと依存関係の複雑さを軽減するために、lxml および beautifulsoup4 の依存関係を削除しました。 (#7449)
  • 無効な構成によって引き起こされる起動の失敗とトラブルシューティングのコストを削減するために、MCP stdio 構成の検証を追加しました。 (#7477)
  • Docker は、実行構成で no-new-privileges を有効にして、コンテナーのデフォルトのセキュリティを向上させます。 (コミット)
  • MCP サーバーのステータスのポーリング頻度を減らし、バックグラウンド要求のオーバーヘッドを減らします。 (#7399)
  • ヘルプ コマンドは、ヘルプ リストのノイズを減らすために、dashboard_update などの内部の有効なコマンドを無視します。 (コミット)
  • プラグイン開発保管ドキュメントがユーザーを誤解させないように、ドキュメント内のパス スプライシングの例を修正しました。 (#7448)
  • Matrix プラットフォーム定数、プラットフォーム アイコン、および関連ドキュメントを追加しました。 (#7368)

  • Telegram ネットワーク異常後のポーリング回復問題を修正し、関連テストを追加しました。 (#7468)
  • 長い Telegram メッセージの最後のセグメントが長すぎる問題を修正しました。 (#7432)
  • Telegram sendMessageDraft が空のテキストを送信するときに 400 エラーを引き起こす問題を修正しました。 (#7398)
  • プラグイン ハンドラーが star_map になく、Telegram がコマンドを収集するときに KeyError が発生する問題を修正しました。 (#7405)
  • Discord Slash Command が時間内に延期されず、10062 Unknown interaction が発生する問題を修正しました。 (#7474)
  • WeChat 個人アカウント アダプターにコンテキスト トークンがない場合の警告メッセージを修正しました。 (コミット)
  • group_icl_enable がメッセージ処理時に UMO バインディング設定を使用しない問題を修正しました。 (#7397) ・プラグイン機能ツールのモジュールパスとプラグインメインモジュールのパスが一致しない問題を修正しました。 (#7462)
  • プラグイン バージョン チェック ロジックのプレリリース バージョンのサポートを修正しました。 (コミット)
  • シェルコマンド実行JSONの応答で非ASCII文字がエスケープされる問題を修正しました。 (#7475)
  • Windows デスクトップ プラグインの依存関係の読み込みが安全でないか、失敗する問題を修正しました。 (#7446)
  • faiss が起動フェーズ中に途中でインポートされ、一部の環境が起動に失敗する問題を修正しました。 (#7400)
  • WebUI ダーク モード レンダリングと複数のインタラクションの問題を修正しました。 (#7173)
  • 欠落していた ChatUI プロジェクト定数を修正し、関連するテスト ケースを追加しました。 (#7414)
  • ページを切り替えるときにフローティング ボタンがジャンプする問題を修正しました。 (#7214)
  • ダイアログ管理ページの依存関係 MessageList.vue が欠落しており、Linux 環境のダッシュボードの構築に失敗する問題を修正しました。 (コミット)
  • MDI サブセットの欠落しているアイコンを使用したツール呼び出しアイコンによって引き起こされる表示の問題を修正しました。 (コミット)
  • ダッシュボード ストアでの defineStore のタイプ使用の問題を修正しました。 (#7490)
  • 作成ファイル内の Docker イメージ名のエラーを修正しました。 (#7488) <a id="english"></a>

AstrBot v4.23.1

Highlights

  • Python 3.13/3.14 startup fix (the reason for this hotfix) — python-ripgrep is pinned back to 0.0.8 (#7514) because the newer resolution broke startup on Python 3.13/3.14; if v4.23.0 crashed on boot for you, this is the fix. The same PR widens the smoke-test matrix across OSes and Python versions and adds a startup-check script, so this class of dependency regression should be caught earlier. Watch out: treat the pin as a compatibility ceiling and don't bump python-ripgrep independently.

  • Computer Use gains real filesystem tools — v4.23.0 adds local read/write/edit/Grep (ripgrep) tools plus a per-session isolated workspace (#7402). This is what moves "computer use" from demo to usable, and the per-session workspace boundary matters most for multi-tenant bots — it's what stops one session's agent touching another's files. It's also why the ripgrep dependency above is load-bearing, not incidental.

  • Search stack replaced — action required — The old default web search implementation is removed (#7416) and replaced by a new Brave Search tool (#6847). This is effectively breaking: agents that relied on built-in search lose web access until you configure Brave Search and supply a Brave API key. Related cleanup drops lxml and beautifulsoup4 (#7449), so any plugin that was leaning on those transitively must now declare them itself.

  • Built-in commands and Cron tools reorganized — migration required — Most low-frequency built-in commands were pulled out of core into the builtin_commands_extension plugin (#7478); install that plugin if you need them back. Cron tools were consolidated into one management tool and gained task editing (#7445), so callers invoking the old separate cron tools need updating, and the built-in tool registration refactor (#7418) may affect custom tool integrations.

  • Providers, platforms, and behavior changes — New LongCat LLM (#7360) and NVIDIA Rerank (#7227) providers, a Mattermost adapter (#7369), OpenAI/Gemini audio input (#7378), and configurable Discord bot-message filtering (#6505) widen the surface. Behavioral changes to test in your flows: disabled STT/TTS providers now return None instead of being resolved (#7363), and repeated-tool-call guidance (#7388) tries to break agents out of tool loops. DeerFlow 2.0 support also lands in this hotfix (#7500) — DeerFlow users should re-verify their runner/API-client/provider integration.

  • Dashboard and stability polish — Code-block highlighting moves to Shiki with synced dark/light themes (#7497), platform routes now display when session IDs contain a colon : (#7517), and plugin install-status checks were corrected (#7493). Startup/runtime hardening includes deferred faiss import (#7400), a corrected Docker image name in compose (#7488), no-new-privileges enabled for Docker (#68a195e12) — which can break containers that relied on gaining privileges — and Telegram/Discord fixes for polling recovery and 10062 Unknown interaction errors (#7468, #7474).
