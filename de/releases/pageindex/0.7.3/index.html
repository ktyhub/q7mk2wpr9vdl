PageIndex v0.7.3

Patch Veröffentlicht19. Nov. 2026 QuelleVectifyAI/PageIndex Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

SeitenIndex v0.7.3

  • Günstiger als Vektor-RAG: sowohl für Index als auch für Abfrage.
  • Schneller: Bäume werden aus Layoutstatistiken erstellt.
  • Unified SDK: vektorloses RAG. Lokal oder Cloud, für Index und Chat.
  • Läuft mit Ihrem Claude-Abonnement. Index, zum Chatten, zur Agentenintegration, ein client. Der lokale Modus erfordert keinen Server, keine Vektor-DB und keinen PageIndex API-Schlüssel.
client = PageIndexClient()
client.submit_document("report.pdf")
client.chat("What does the report conclude?")

Highlights

  • Flash-Engine: der lokale Standard (mode="standard" behält die klassische LLM-Pipeline bei). Eingebettete Lesezeichen werden verbraucht, wenn trustworthy und die Baumoptimierung standardmäßig aktiviert ist – optimize="merge" für den deterministischen LLM-freien Durchgang, "full" (Standard) fügt LLM-Erweiterung hinzu, die eine Welle von Knoten gleichzeitig statt jeweils einen Roundtrip ausführt.
  • Eine vollständige Oberfläche, lokal und Cloud: PageIndexLocalClient(storage_path=...) ist das gleiche client wie die Cloud – Übermittlungs-, Baum-, Seiteninhalts-, Chat- und Agenten-Tools sind alle in beiden Modi vorhanden, sodass sich der Code unverändert zwischen ihnen bewegt.
  • Cloud-Dokumente, Ihr eigenes Modell: api_key entscheidet, wo Ihre Dokumente gespeichert sind; Ein konfiguriertes Chat-Modell entscheidet, wer antwortet – und beides zusammen. PageIndexClient(api_key="pi-...", chat_model="openai/gpt-5.2") führt die gleiche In-Process-Dokumenten-QA-Engine über das Live-Cloud-Toolset aus. Der Seiteninhalt fließt durch Ihren Prozess über Ihre Anmeldeinformationen an Ihren Anbieter. doc_id zielt auf die Eingabeaufforderungsebene; enable_citations bleibt beim verwalteten Chat.
  • Agent-Integration: der Cloud-MCP-Tool-Vertrag, in Bearbeitung – client.agent_tools() (einfache Funktionen), as_openai_tools(), as_anthropic_tools(), as_claude_mcp(), plus One-Call-Pakete openai_agent_config()/anthropic_runner_config()/claude_agent_config() und agent_instructions() für die Systemaufforderung. Cloud clients erhalten das Live-Server-Tool-Set über die MCP-Brücke (standardmäßig schreibgeschützter Endpunkt); Lokale clients erhalten die In-Process-Teilmenge mit denselben Schemata und Umschlägen – der Agent-Prompt-Port bleibt unverändert.
  • Chat-Oberflächen: chat() – Frage rein, Antwort raus, auf jedem Backend; chat(stream=True) zeigt den Lauf, während er geschieht, indem Denk- und Werkzeugaufrufe in den Text eingewebt werden, oder als getippte Ereignisse über .events; chat(protocol="responses" | "messages") steuert die OpenAI-Antworten oder Anthropic Messages API nativ mit den eigenen Formen dieses Protokolls, und chat_completions() behält den OpenAI-kompatiblen Rahmen bei – alles mit doc_id-Targeting, Streaming, ehrlicher Nutzungsabrechnung und Prompt-Cache-Kontinuität über Runden hinweg. Transkripte werden wörtlich angehängt: Die Ausgabe einer Protokollspur geht unverändert in die nächste Anfrage zurück.
  • Modell- und Verbindungsknöpfe: index_model / chat_model, index_backend / chat_backend (und pro Anruf backend) werden wörtlich an jede Spur übergeben – LiteLLM-geroutete Anbieter, schlüssellose OpenAI-kompatible Server, einschließlich Azure/Bedrock/Vertex.
  • index= / chat=-Slots: die gruppierte Schreibweise der flachen Argumente – eine String-Kurzschrift oder eine Zuordnung (index={"model": ..., "storage_path": ...}, chat={"model": ..., "backend": ...}). "cloud" / "local" benennen eine Seite, ein optionaler mode= gleicht sie ab und PageIndexLocalClient / PageIndexCloudClient belegen die gleichen Plätze. PageIndexCloudClient() liest PAGEINDEX_API_KEY; Ein bloßer PageIndexClient() bleibt lokal, unabhängig von der Umgebung.
  • Typisierte Konfigurationsformen: IndexConfig / CloudIndexConfig / LocalIndexConfig / ChatConfig, mit py.typed ausgeliefert, damit Ihr Typprüfer sie sieht.
  • Nichts scheitert stillschweigend: Unbekannte Schlüssel, gemischte Seiten, leere Werte und Modus-/Inhaltskonflikte verweigern die Konstruktion mit dem juristischen Vokabular in der Nachricht; Tote Anmeldeinformationen oder ein fehlendes Modell lassen den Indexierungslauf fehlschlagen, anstatt ein Dokument mit leeren Zusammenfassungen zu speichern. Jeder Cloud-Fehler trägt seinen HTTP-Status.
  • Abhängigkeiten: Python >= 3.10; openai-agents in der Basisinstallation (der Chat-Engine); [anthropic]- und [claude]-Extras für diese SDKs. Pillow >= 9.0 ist jetzt eine erforderliche Abhängigkeit für highlight_region.

PageIndex v0.7.3

  • Cheaper than vector RAG: for both index and query.
  • Faster: trees are created from layout stats.
  • Unified SDK: vectorless RAG. Local or cloud, for index and chat.
  • Runs on your Claude subscription.

Index, to chat, to agent integration, one client. Local mode needs no server, no vector DB, no PageIndex API key.

client = PageIndexClient()
client.submit_document("report.pdf")
client.chat("What does the report conclude?")

Highlights

  • Flash engine: the local default (mode="standard" keeps the classic LLM pipeline). Embedded bookmarks are consumed when trustworthy, and tree optimization is on by default — optimize="merge" for the deterministic LLM-free pass, "full" (default) adds LLM expand, which runs a wave of nodes concurrently instead of one round-trip at a time.
  • One complete surface, local and cloud: PageIndexLocalClient(storage_path=...) is the same client as cloud — submit, tree, page content, chat, and agent tools all present in both modes, so code moves between them unchanged.
  • Cloud documents, your own model: api_key decides where your documents live; a configured chat model decides who answers — and the two combine. PageIndexClient(api_key="pi-...", chat_model="openai/gpt-5.2") runs the same in-process document-QA engine over the live cloud tool set. Page content flows through your process to your provider on your credentials; doc_id targets at the prompt level; enable_citations stays with the managed chat.
  • Agent integration: the cloud MCP tool contract, in-process — client.agent_tools() (plain functions), as_openai_tools(), as_anthropic_tools(), as_claude_mcp(), plus one-call openai_agent_config() / anthropic_runner_config() / claude_agent_config() bundles and agent_instructions() for the system prompt. Cloud clients get the live server tool set over the MCP bridge (read-only endpoint by default); local clients get the in-process subset with the same schemas and envelopes — agent prompts port unchanged.
  • Chat surfaces: chat() — question in, answer out, on any backend; chat(stream=True) shows the run as it happens, thinking and tool calls woven into the text, or as typed events via .events; chat(protocol="responses" | "messages") drives the OpenAI Responses or Anthropic Messages API natively with that protocol's own shapes, and chat_completions() keeps the OpenAI-compatible envelope — all with doc_id targeting, streaming, honest usage accounting, and prompt-cache continuity across turns. Transcripts append verbatim: a protocol lane's output goes back into the next request unchanged.
  • Model & connection knobs: index_model / chat_model, index_backend / chat_backend (and per-call backend) passed verbatim to each lane — LiteLLM-routed providers, keyless OpenAI-compatible servers, Azure/Bedrock/Vertex included.
  • index= / chat= slots: the grouped spelling of the flat arguments — a string shorthand or a mapping (index={"model": ..., "storage_path": ...}, chat={"model": ..., "backend": ...}). "cloud" / "local" name a side, an optional mode= cross-checks it, and PageIndexLocalClient / PageIndexCloudClient take the same slots. PageIndexCloudClient() reads PAGEINDEX_API_KEY; a bare PageIndexClient() stays local no matter what the environment holds.
  • Typed config shapes: IndexConfig / CloudIndexConfig / LocalIndexConfig / ChatConfig, with py.typed shipped so your type checker sees them.
  • Nothing fails quietly: unknown keys, mixed sides, empty values and mode/content conflicts refuse at construction with the legal vocabulary in the message; dead credentials or a missing model fail the indexing run instead of storing a document with blank summaries; every cloud error carries its HTTP status.
  • Dependencies: Python >= 3.10; openai-agents in the base install (the chat engine); [anthropic] and [claude] extras for those SDKs. Pillow >= 9.0 is now a required dependency for highlight_region.
