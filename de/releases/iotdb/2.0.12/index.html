iotdb v2.0.12

Funktionen und Verbesserungen

SQL-Injection-Verhinderung: Das PreparedStatement des Tabellenmodells wurde umgestaltet, um SQL-Injection zu verhindern Clusterverwaltung: Unterstützt die IPv6-Clusterbereitstellung REST: REST API unterstützt das Festlegen der Zeitzone client Datensynchronisierung: Optimierte Filterleistung für nicht erste TAG-Spalten im Tabellenmodell Datenimport-/Exporttools: Verschlechterungsstrategie für Ladedateien Datenbankverwaltung: SHOW CREATE DATABASE/TOPIC/PIPE Berechnung – Abfrageausführung – SQL-Klauseln: Optimieren Sie die Fehlermeldung, wenn eine select *-Abfrage zu viele Spalten hat Funktionen: Zeit-Frequenz-Analysefunktion (FFT) hinzugefügt Funktionen: Filterfunktionen hinzugefügt (HighPass, LowPass) Letzter Punkt-Cache: Der neueste Punkt-Cache unterstützt die Aktivierung/Deaktivierung auf Tabellen-/Datenbank-Granularität Funktionen: Integrierte Rate/Erhöhung/Irate/Delta-Aggregatfunktionen für das Tabellenmodell Funktionen: Sequenzkorrelationsfunktion (XCorr) hinzugefügt Funktionen: Integrierte M4-Tabellenwertfunktion Funktionen: Zeitreihentrend-Matching-Tabellenwertfunktion Funktionen: Die integrierte Tabellenwertfunktion read_tsfile wurde hinzugefügt und unterstützt direkte Abfragen aus einer angegebenen TS-Datei mithilfe von SQL Metadaten des Baummodells: Ignorieren Sie beim Erstellen einer neuen Zeitreihe unter einem vorhandenen Gerät die in der Erstellungsanweisung angegebenen ausgerichteten/nicht ausgerichteten Attribute und verwenden Sie die ausgerichteten/nicht ausgerichteten Attribute des aktuellen Geräts, anstatt einen Fehler zu melden Messung: Das Validierungsergebnis der Messung während Cache-Schreibvorgängen wurde optimiert Gerätegranularitätslöschung: Es wurde ein Problem behoben, bei dem die Abfrage dieser Tabelle nach dem Löschen einer Tabelle mit einer großen Datenmenge und dem anschließenden Neuerstellen der Tabelle und dem Schreiben von Daten eine hohe Latenz aufwies Speicheroptimierung: Speicheroptimierung beim Kopieren der Memtable TVList während Abfragen Pipe Data Sync: Der Matching-Algorithmus für ** wurde optimiert Metadaten des Baummodells: Den Geräteknoten wurde ein boolesches Flag hinzugefügt, das angibt, ob sich darunter weitere Geräte befinden, und die Abfrage select measurement from xxx.** wurde optimiert SQL-Klauseln: Leistungsoptimierung für die vollständige Tabelle order by time + limit im Tabellenmodell SQL-Klauseln: Speicheroptimierung für vollständige Tabellenabfragen im Tabellenmodell Pipe-Datensynchronisierung: Der Erweiterungs-/Verkleinerungsalgorithmus des Pipe-Speicherblocks wurde optimiert

Fehler

Online-Dateizusammenführung: Es wurde ein Problem behoben, bei dem show disk_usage dazu führte, dass die Zusammenführung hängen blieb Metadaten des Baummodells: Das Problem „keine übereinstimmende Datenbank“ wurde behoben Datensynchronisierung: Unterstützt das Speichern des TsFile-Parsing-Checkpoint-Fortschritts, sodass bei einem erneuten Versuch nach einem Fehler nicht die gesamte Datei erneut analysiert werden muss Basic Write: Es wurde ein Problem behoben, bei dem für dasselbe ausgerichtete Gerät das erste Schreiben einer Anfrage mit weniger Spalten und mehr Zeilen und das anschließende Schreiben einer Anfrage mit mehr Spalten und einer Zeile eine WAL generierte, die beim Neustart des DataNode zu einer schwerwiegenden Memtable-Nullwerterweiterung führte und letztendlich dazu führte, dass der DataNode-Neustart hängen blieb TsFile-Synchronisierung: Ändern Sie beim Laden einer Ts-Datei die Replikatsatz-Vergleichslogik: Achten Sie beim Vergleich von Replikatsätzen nicht mehr auf die Listenreihenfolge, sondern vergleichen Sie nur, ob die Elemente innerhalb der Sätze genau identisch sind. Ändern Sie den Listenvergleich in einen Mengenvergleich Pipe-Datensynchronisierung: Es wurde ein Problem behoben, bei dem Pipe beim Konvertieren eines teilweisen Einfügungsschreibvorgangs in ein Tablet einen NPE für Nullmesspunkte auslöste Pipe-Datensynchronisierung: Es wurde ein Problem behoben, bei dem Pipe nach einer Zeitüberschreitung beim Parsen der TS-Datei angehalten wurde Online-Dateizusammenführung: Es wurde ein Problem behoben, bei dem die Zusammenführung nicht auf das Kopieren zurückgriff, wenn die Erstellung von Hardlinks fehlschlug Pipe-Datensynchronisierung: Unabhängige Speicherkontingentgrenzen pro Pipe oder faire Planung hinzugefügt Pipe Data Sync: Exponentielles Backoff und Leistungsschalterschutz für Szenarien implementiert, in denen die Festplatte voll ist oder der Empfänger nicht verfügbar ist Pipe-Datensynchronisierung: Globale und Pipe-Beschränkungen für TsFiles im Flug hinzugefügt Pipe Data Sync: Es wurde ein Problem behoben, bei dem drop pipe nicht auf die Rückkehr der Senke wartete Datenimport-/Exporttools: Es wurde ein Fehler behoben, der beim Ausführen von tsfile load auftrat, während bereits eine Datenbank mit dem Namen root.-Präfix vorhanden war Tabellenmodell-Metadaten: Die Handhabung von Sonderzeichen, die mit Backticks in Tabellenansichten maskiert werden, wurde optimiert Pipe-Datensynchronisierung: Beim Löschen einer Pipe gibt es asynchrone Prozesse (z. B. Wiederherstellen); Das Ergebnis der asynchronen Ausführung muss dem Benutzer mitgeteilt werden Pipe-Datensynchronisierung: Drop pipe wartet nicht mehr auf die Rückkehr der Senke und gewährleistet so die vollständige Entfernung der Pipe Pipe-Datensynchronisierung: Die Verzögerung im Zuweisungsteil beim Ausführen von Pipe-Erstellungs-/Start-/Stopp-/Löschbefehlen wurde behoben Pipe-Datensynchronisierung: Das Problem mit der übermäßigen Protokollierung wurde behoben, indem die Anzahl der Protokolle auf der Pipe-Empfängerseite reduziert wurde Pipe-Datensynchronisierung: Es wurde ein Problem behoben, bei dem das Aufteilen einer TS-Datei in 1.3.x zum Synchronisieren von Teildaten mit 2.x fehlschlug

Englisches Original / English original

iotdb v2.0.12

Features & Improvements

SQL Injection Prevention: Refactored the table model's PreparedStatement to prevent SQL injection Cluster Management: Support IPv6 cluster deployment REST: REST API supports setting the client timezone Data Sync: Optimized filtering performance for non-first TAG columns in the table model Data Import/Export Tools: Degradation strategy for Load files Database Management: SHOW CREATE DATABASE/TOPIC/PIPE Computation - Query Execution - SQL Clauses: Optimize the error message when a select * query has too many columns Functions: Added time-frequency analysis function (FFT) Functions: Added filtering functions (HighPass, LowPass) Latest Point Cache: The latest point cache supports being enabled/disabled at table/database granularity Functions: Built-in rate/increase/irate/delta aggregate functions for the table model Functions: Added sequence correlation function (XCorr) Functions: Built-in M4 table-valued function Functions: Time-series trend matching table-valued function Functions: Added the built-in table-valued function read_tsfile, supporting direct querying from a specified tsfile using SQL Tree Model Metadata: When creating a new time series under an existing device, ignore the aligned/unaligned attributes specified in the create statement and use the current device's aligned/unaligned attributes instead of reporting an error Measurement: Optimized the validation result of Measurement during cache writes Device-Granularity Deletion: Fixed an issue where, after deleting a table with a large amount of data and then re-creating the table and writing data, querying that table had high latency Memory Optimization: Memory optimization when copying the memtable TVList during queries Pipe Data Sync: Optimized the matching algorithm for ** Tree Model Metadata: Added a boolean flag to device nodes indicating whether there are other devices below, and tuned the query select measurement from xxx.** SQL Clauses: Performance optimization for full-table order by time + limit in the table model SQL Clauses: Memory optimization for full-table queries in the table model Pipe Data Sync: Optimized the Pipe memory block expansion/contraction algorithm

Bugs

Online File Merge: Fixed an issue where show disk_usage caused the merge to hang Tree Model Metadata: Fixed the "no matched database" issue Data Sync: Support storing TsFile parsing checkpoint progress, so that on retry after failure there is no need to re-parse the entire file Basic Write: Fixed an issue where, for the same aligned device, first writing a request with fewer columns and more rows and then writing a request with more columns and one row generated a WAL that, upon restarting the DataNode, caused severe memtable null-value expansion and ultimately caused the DataNode restart to hang TsFile Sync: When loading a tsfile, modify the replica set comparison logic: when comparing replica sets, no longer care about list order, only compare whether the elements within the sets are exactly identical; change the list comparison to a set comparison Pipe Data Sync: Fixed an issue where Pipe threw an NPE for null measurement points when converting a partial insert write into a tablet Pipe Data Sync: Fixed an issue where Pipe stopped after a tsfile parsing timeout Online File Merge: Fixed an issue where the merge did not fall back to copying when creating hard links failed Pipe Data Sync: Added per-Pipe independent memory quota limits or fair scheduling Pipe Data Sync: Implemented exponential backoff and circuit breaker protection for scenarios where the disk is full or the receiver is unavailable Pipe Data Sync: Added global and per-Pipe limits on in-flight TsFiles Pipe Data Sync: Fixed an issue where drop pipe did not wait for the sink's return Data Import/Export Tools: Fixed an error when executing tsfile load while a database named with a root. prefix already exists Table Model Metadata: Optimized the handling of special characters escaped with backticks in table views Pipe Data Sync: When deleting a Pipe there are asynchronous processes (e.g., recover); the asynchronous execution result needs to be communicated to the user Pipe Data Sync: Drop pipe no longer waits for the sink's return, ensuring complete removal of the Pipe Pipe Data Sync: Fixed the lag in the assigner portion when executing Pipe create/start/stop/delete commands Pipe Data Sync: Fixed the excessive logging issue by reducing the amount of logs on the Pipe receiver side Pipe Data Sync: Fixed an issue where splitting a tsfile in 1.3.x to sync partial data to 2.x failed
