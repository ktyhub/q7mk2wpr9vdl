Scrapling v0.2.7

Was hat sich geändert?

Neue Funktionen

  • Wenn Sie nun das Argument wait_selector mit den Klassen StealthyFetcher und PlayWrightFetcher verwendet haben, wartet Scrapling erneut darauf, dass der JS vollständig geladen und wie gewohnt ausgeführt wird. Wenn Sie das Argument network_idle verwendet haben, wird Scrapling nach dem Warten auf all das erneut darauf warten. Wenn alle Zustände erfüllt sind, gibt es natürlich keine Wartezeiten. – Jetzt können Sie Anzeigen auf StealthyFetcher mit dem Argument disable_ads aktivieren und deaktivieren. Dies ist standardmäßig aktiviert und installiert das Add-on ublock origin. – Jetzt können Sie das von PlayWrightFetcher verwendete Gebietsschema mit dem Argument locale festlegen. Der Standardwert ist weiterhin en-US. – Jetzt können die über Fetcher durchgeführten Basisanfragen Proxys in diesem Format http://username:password@localhost:8030 akzeptieren.
  • Der Stealth-Modus für PlayWrightFetcher wurde etwas verbessert.

Fehler behoben/Verbesserungen

  1. Das Aktivieren von Proxys für die Klasse PlayWrightFetcher ist jetzt nicht mehr daran gebunden, dass der stealth-Modus ein- oder ausgeschaltet ist (Danke an @AbdullahY36 für den Hinweis)
  2. Nun testet der ResponseEncoding, ob die von der Antwort zurückgegebene Codierung mit der Seite verwendet werden kann oder nicht. Wenn die zurückgegebene Codierung einen Fehler ausgelöst hat, verwendet Scrapling standardmäßig utf-8

[!NOTE] Eine freundliche Erinnerung daran, dass die Wartung und Verbesserung von Scrapling viel Zeit und Mühe erfordert, was ich seit Monaten gerne tue, auch wenn es immer schwieriger wird. Wenn Ihnen Scrapling gefällt und Sie möchten, dass es sich weiter verbessert, können Sie mir helfen, indem Sie mich über den [Sponsor-Button] (https://github.com/sponsors/D4Vinci) unterstützen.

Englisches Original / English original

Scrapling v0.2.7

Highlights

  • Wait-state semantics corrected — wait_selector on StealthyFetcher and PlayWrightFetcher no longer short-circuits: after the selector resolves, Scrapling re-runs its normal JS-execution wait and, if network_idle was requested, waits for that again on top. Fetches now return genuinely settled pages instead of a DOM caught mid-render. The upside is more reliable content for JS-heavy sites; the trade-off is longer request times, and any automation that depended on wait_selector returning early will now block until all configured states are satisfied (if they're already met, there's no added delay).
  • Ads blocked by default — StealthyFetcher gains a disable_ads flag that is on by default and installs the ublock origin addon. This is a real behavioral change to the DOM you receive: ad containers vanish out of the box, so selectors or text extraction built around an ad-heavy layout can break. If you need the untouched page, pass disable_ads=False explicitly rather than assuming the old behavior.
  • Proxies decoupled from stealth mode — proxy support on PlayWrightFetcher is no longer gated on stealth being enabled (credit to @AbdullahY36 for flagging it). Previously routing through a proxy required turning stealth on; now you can use a proxy with stealth off. Migration is simply deleting the stealth=True workaround — no config changes otherwise, and stealth-only users see no difference.
  • Authenticated proxies for basic requests — the plain Fetcher now accepts credentialed proxy URLs in the form http://username:password@localhost:8030. This closes a gap where only the browser-based fetchers could talk to authenticated upstreams, so scrapers behind a password-protected proxy can stay on the lighter Fetcher path instead of spinning up a full browser.
  • Locale pinning — PlayWrightFetcher accepts a locale argument, defaulting to en-US. Useful for geo- and language-sensitive content where Accept-Language and navigator locale affect what's served; worth setting explicitly if you were previously getting US-flavored results from a non-US target.
  • Encoding-resilient responses — ResponseEncoding now checks whether the server-declared encoding is actually usable for the page and silently falls back to utf-8 when it triggers an error. More robust against mislabeled headers, but note the behavioral shift: a page that previously raised a hard decoding error may now return utf-8-decoded (possibly garbled) text instead, so sanity-check non-UTF-8 sources.

No breaking changes in this release — all additions and fixes are backward-compatible and require no migration.

What's changed

New features

  • Now if you used the wait_selector argument with StealthyFetcher and PlayWrightFetcher classes, Scrapling will wait again for the JS to fully load and execute like normal. If you used the network_idle argument, Scrapling will wait for it again too after waiting for all of that. If the states are all fulfilled then no waiting happens, of course.
  • Now you can enable and disable ads on StealthyFetcher with the disable_ads argument. This is enabled by default and it installs the ublock origin addon.
  • Now you can set the locale used by PlayWrightFetcher with the locale argument. The default value is still en-US.
  • Now the basic requests done through Fetcher can accept proxies in this format http://username:password@localhost:8030.
  • The stealth mode improved a bit for PlayWrightFetcher.

Bugs Squashed/Improvements

  1. Now enabling proxies on the PlayWrightFetcher class is not tied to the stealth mode being on or off (Thanks to @AbdullahY36 for pointing that out)
  2. Now the ResponseEncoding tests if the encoding returned from the response can be used with the page or not. If the returned encoding triggered an error, Scrapling defaults to utf-8

[!NOTE] A friendly reminder that maintaining and improving Scrapling takes a lot of time and effort which I have been happily doing for months even though it's becoming harder. So, if you like Scrapling and want it to keep improving, you can help by supporting me through the Sponsor button.
