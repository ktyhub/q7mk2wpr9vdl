Scrapling v0.3.13

Dies ist ein großes Update mit vielen Verbesserungen an vielen Stellen, aber aus guten Gründen auch vielen wichtigen Änderungen. Bitte lesen Sie das Folgende, bevor Sie aktualisieren

  • Aus vielen Gründen haben wir beschlossen, Camoufox von nun an nicht mehr vollständig zu verwenden und möglicherweise in Zukunft wieder darauf umzusteigen, wenn die Entwicklung fortgesetzt wird. Wenn Sie Camoufox lieber wie vor dieser Version verwenden möchten, finden Sie in diesem Abschnitt Anweisungen dazu.

  • Zuvor haben wir Patchright im Stealth-Modus innerhalb von DynamicFetcher und seinen Sitzungsklassen verwendet. Jetzt haben wir den Stealth-Modus von ihnen entfernt und begonnen, Patchright innerhalb von StealthyFetcher und seinen Sitzungsklassen zu verwenden, mit VIELEN Verbesserungen, wie Sie sehen werden, die den Stealth-Modus zusätzlich zu Patchright insgesamt verbessern.

Dadurch sind StealthyFetcher und seine Sitzungsklassen 101 % schneller als zuvor, verbrauchen weniger Speicher und Platz und haben etwa 400 Codezeilen kürzer, sind aber vor allem stabiler als bei der vorherigen Verwendung von Camoufox.

Dadurch wird auch die Installationszeit des scrapling install-Befehls verkürzt, die Größe des Docker-Images verringert, die Testsicherheit im CI von GitHub verbessert und das Scrapling für neue Benutzer weniger verwirrend gemacht.

Breaking Changes

  1. Das Argument stealth wurde aus der Klasse DynamicFetcher und ihrer Sitzungsklasse entfernt, während das Argument hide_canvas in die Klasse StealthyFetcher und ihre Sitzungsklassen verschoben wurde.
  2. Das Argument disable_webgl wurde von DynamicFetcher in die Klasse StealthyFetcher verschoben und in allow_webgl umbenannt. Auch alle Session-Kurse.
  3. Die Klasse StealthyFetcher ist nun im Grunde die neue getarnte Version von DynamicFetcher, daher werden die folgenden Argumente entfernt: block_images, humanize, addons, os_randomize, disable_ads und geoip. Ich habe versucht, sie in Chromium zu replizieren, aber jedes hatte sein eigenes Problem. Dies könnte sich mit kommenden Veröffentlichungen vor v0.4 ändern.

Nun zu den guten Nachrichten, wir haben viele Dinge verbessert und behoben :)

Verbesserungen

  • Sie wissen bereits, dass die Klasse StealthyFetcher und ihre Sitzungsklassen jetzt 101 % schneller sind als zuvor, aber jetzt sind auch die Klasse DynamicFetcher und ihre Sitzungsklasse 20 % schneller. – Der Lösungsalgorithmus von Cloudflare wurde gegenüber bisher verbessert, um schneller fertig zu werden und mehr Fälle zu bearbeiten. Dank des neuen Refaktors können Sie außerdem damit rechnen, dass der Löser das Captcha doppelt so schnell löst!
  • Alle Fetcher verbrauchen jetzt weniger Speicher.
  • Der MCP-Server verwendet jetzt weniger Token, um mehr Geld zu sparen!
  • Das Docker-Bild ist jetzt 60 % kleiner.
  • Die gesamte Dokumentationswebsite wurde mit den neuen Inhalten aktualisiert. Gleichzeitig wurde es expliziter gemacht, viele Abschnitte gekürzt, mehr Beispiele hinzugefügt, fehlende Argumente eingefügt, der API-Referenzabschnitt mit Grafiken aktualisiert und viele andere Verbesserungen vorgenommen. Die Website lädt jetzt 130 % schneller, verbraucht weniger Daten und ist besser für SEO.

Korrekturen

  • Die Argumente, die zuvor in den Web-Scraping-Shell-Verknüpfungen fehlten, wurden hinzugefügt und genauer gemacht. – Das Problem wurde behoben, bei dem das Argument google_search einen Google-Referrer erstellte, selbst wenn die URL ein lokaler Host/eine lokale IP war.

Englisches Original / English original

Scrapling v0.3.13

Highlights

  • Stealth engine overhaul — StealthyFetcher and its session classes now use Patchright instead of Camoufox, with reported gains in speed, stability, memory use, and CAPTCHA handling. The Cloudflare solver is also reported to run roughly twice as fast and cover more cases.
  • DynamicFetcher API cleanup — The stealth argument is removed, hide_canvas moves to StealthyFetcher, and disable_webgl becomes allow_webgl on the stealth fetcher and all session classes. Audit constructor calls and configuration files before upgrading.
  • Fewer stealth customization options — StealthyFetcher drops block_images, humanize, addons, os_randomize, disable_ads, and geoip. Code relying on these arguments needs alternative handling or should be pinned to the previous release; Camoufox users can follow the documented opt-in instructions.
  • Performance and deployment improvements — DynamicFetcher is reported to be 20% faster, all fetchers use less memory, and the Docker image is 60% smaller. Faster scrapling install and a leaner image should shorten CI setup, though the changelog does not provide benchmark details.
  • Scraping behavior fixes — google_search no longer emits a Google referrer for localhost or IP-literal targets, avoiding misleading headers in local and internal scraping workflows. Shell shortcuts also expose previously missing arguments and reflect updated option names.
  • MCP and documentation updates — The MCP server consumes fewer tokens, while refreshed documentation adds missing arguments, graphs, and examples. Consult the updated API reference for the new fetcher boundaries before migrating.

Breaking changes: yes.

This is a big update with many improvements across many places, but also many breaking changes for good reasons. Please read the below before updating

  • For many reasons, we decided that from now on, we will stop using Camoufox entirely, and we might switch back to it in the future if its development continues. If you prefer to continue using Camoufox as before this release, there are instructions for that in this section.

  • Previously, we were using patchright in the stealth mode inside DynamicFetcher and its session classes. Now we removed the stealth mode from them and started using patchright inside StealthyFetcher and its session classes, with A LOT of improvements, as you will see, improving the stealth overall on top of patchright.

This makes StealthyFetcher and its session classes 101% faster than before, use less memory and space, and have ~400 lines of code shorter, but, most importantly, are more stable than when we used Camoufox before.

This will also shorten the installation time of the scrapling install command, reduce the size of the Docker image, improve test smoothness in GitHub's CI, and make scrapling less confusing for new users.

Breaking changes

  1. The stealth argument was removed from the DynamicFetcher class and its session class, while the hide_canvas argument was moved to the StealthyFetcher and its session classes.
  2. The disable_webgl argument has been moved from DynamicFetcher to the StealthyFetcher class and renamed as allow_webgl. All session classes as well.
  3. The StealthyFetcher class is now basically the new stealthy version of DynamicFetcher, so the following arguments are removed: block_images, humanize, addons, os_randomize, disable_ads, and geoip. I tried to replicate them in Chromium, but each had its own problem. This might change with upcoming releases before v0.4.

Now to the good news, we have improved and fixed a lot of stuff :)

Improvements

  • You already know that the StealthyFetcher class and its session classes are now 101% faster than before, but now also the DynamicFetcher class and its session class are 20% faster.
  • Cloudflare's solver algorithm has been improved over before now to finish faster and handle more cases. Also, thanks to the new refactor, expect the solver to solve the captcha twice as fast!
  • All fetchers now use less memory.
  • The MCP server now uses fewer tokens to save more money!
  • The Docker image is now 60% smaller.
  • The whole documentation website has been updated with the new stuff. At the same time, it was made more explicit, many sections were shortened, more examples were added, missing arguments were included, the API reference section was updated with graphs, and many other improvements were made. The Website now loads 130% faster, uses less data, and is better for SEO.

Fixes

  • Added the arguments that were missing before in the Web Scraping shell shortcuts and made them more accurate.
  • Fixed the issue where the google_search argument was creating a Google referrer even if the URL is a localhost/IP.
