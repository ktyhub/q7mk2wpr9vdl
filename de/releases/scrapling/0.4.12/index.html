Scrapling v0.4.12

Eine Veröffentlichung, die sich darauf konzentriert, Ihre Spider intelligenter in Bezug auf die von ihnen gecrawlten Websites zu machen

[!NOTE] Folgen Sie uns auf X für tägliche Tipps und Tricks

🚀 Neue Dinge und Lebensqualität verändern sich

  • Spider können jetzt mit AutoThrottle ihre eigene Geschwindigkeit anpassen. Anstatt einen download_delay zu erraten, der entweder zu langsam ist oder Ihnen eine Sperre einbringt, misst der Spider, wie schnell jede Website antwortet, und passt die Verzögerung jeder Domain selbst an. Wenn eine Website anfängt, Sie zu blockieren oder die Geschwindigkeit zu begrenzen, verdoppelt sie die Verzögerung (oder wartet genau das, was der Retry-After-Header verlangt), bis dies aufhört, und beschleunigt dann wieder. Ihr download_delay und alle robots.txt Crawl-delay werden weiterhin als Minimum respektiert. (Überprüfen Sie die Dokumente)

    class MySpider(Spider):
    name = "adaptive"
    start_urls = ["https://example.com"]
    autothrottle_enabled = True
    autothrottle_start_delay = 2.0
    autothrottle_max_delay = 30.0
    autothrottle_block_backoff = True

  • Exportieren Sie Ihre Ergebnisse in CSV und XML, neben den JSON/JSONL-Exportprogrammen, die Sie bereits hatten. Elemente, die nicht alle dieselben Schlüssel haben, werden trotzdem exportiert, ohne etwas zu verlieren, und verschachtelte Werte werden als JSON geschrieben. (Überprüfen Sie die Dokumente)

    result = MySpider().start()
result.items.to_csv("products.csv")
result.items.to_xml("products.xml")

  • Der MCP-Server kann jetzt eine Authentifizierung erfordern, sodass Sie ihn sicher offenlegen können, anstatt ihn auf Ihrem eigenen Computer zu behalten. Jede Anfrage ohne das Token wird abgelehnt und Sie können auch einschränken, auf welche Hostnamen der Server antwortet. (Überprüfen Sie die Dokumente)

    scrapling mcp --http --auth-token "$(openssl rand -hex 32)"

  • Browser akzeptieren jetzt CDP-URLs über HTTP, nicht nur WebSocket-URLs. Neben den wss://-Endpunkt-verwalteten Browser-Anbietern können Sie jetzt jeden Browser-Abrufer oder jede MCP-Sitzung auf einen Chrome verweisen, den Sie selbst mit --remote-debugging-port=9222 gestartet haben.

  • Veröffentlichte Docker-Bilder werden jetzt mit ihrer Release-Version getaggt statt nur mit latest, sodass Sie genau die gewünschte Version anpinnen können, von @JanRK in #384.

🐛 Fehlerbehebungen

– Behoben, dass zwischengespeicherte Antworten alle ihre Cookies verloren, wenn die Antwort von einer Browser-Engine kam, die stillschweigend alle darauf basierenden Sitzungen oder Authentifizierungslogiken unterbrach, während der Entwicklungsmodus der Spiders verwendet wurde, von @amitvijapur in #379. (Behebt #376)

  • Behoben: StealthyFetcher erzwingt das Gebietsschema en-US in jedem Browser, anstatt dem Ihres Systems zu folgen, was dazu führte, dass Websites eine Nichtübereinstimmung zwischen Ihrem Gebietsschema und Ihrer IP-Adresse erkannten und Sie als verdächtig behandelten, so als würde Google mit 429 antworten. (Behebt #381)

  • Eine irreführende Fehlermeldung im Speichersystem wurde behoben und ein toter Aufruf nach Einfügungen von @fix2015 in #377 entfernt.

Leistung

  • get_all_text() ist jetzt O(Knoten), anstatt die Vorfahren jedes einzelnen Textknotens nach oben zu durchlaufen, was es auf tief verschachtelten Seiten etwa 5-6x schneller macht, von @yetval in #378.

🙏 Besonderer Dank geht an die Community für all die kontinuierlichen Tests und Rückmeldungen

Scrapling v0.4.12

Highlights

  • Adaptive crawling via AutoThrottle — Spiders can now self-tune per-domain request delays instead of you guessing a static download_delay. Enabling autothrottle_enabled makes each domain measure response speed and back off when blocked or rate-limited — doubling the delay or honouring Retry-After exactly — then ramp back up; your download_delay and any robots.txt Crawl-delay remain the floor. This matters for fragile targets: fewer bans without hand-tuning every site, and existing configured delays stay a safe lower bound.

  • CSV and XML exporters — result.items.to_csv() and to_xml() join the JSON/JSONL exporters. Heterogeneous item schemas survive intact (missing keys don't truncate rows) and nested values are serialized as JSON. The practical win is a direct hand-off to spreadsheets or ETL tools with no post-processing step.

  • MCP server authentication and host restrictions — scrapling mcp --http --auth-token ... rejects requests without the token, and you can limit which hostnames it answers. You can now expose the MCP server beyond localhost rather than keeping it machine-local. Note the opt-in nature: passing --auth-token is what enforces auth, so purely local setups are unaffected, but any newly exposed instance must hand out the token to every client or requests will be rejected.

  • Connect to your own Chrome over HTTP CDP — Browser fetchers and MCP sessions now accept http:// CDP endpoints alongside wss://, so you can attach to a Chrome you launched yourself with --remote-debugging-port=9222 instead of relying solely on managed-provider WebSocket URLs. Paired with version-tagged Docker images (#384, replacing the latest-only tags), this makes self-hosted, reproducible deployments practical — pin an exact release instead of floating on latest.

  • Behavioral fixes worth auditing — Two fixes change observable behavior: cached browser-engine responses no longer strip all cookies (#379, fixes #376), which silently broke session/auth logic in spider development mode, so re-check any dev-mode flows that depended on that broken state; and StealthyFetcher no longer forces en-US, inheriting the system locale instead, eliminating the locale-vs-IP mismatch that caused 429s (e.g. Google, #381) — if you relied on the forced fingerprint, your requests will now look different. Also #377 removes a misleading storage error message and a dead post-insert call.

  • Faster text extraction — get_all_text() was rewritten from walking the ancestors of every text node to O(nodes), roughly 5–6× faster on deeply nested pages (#378). No API change; if you scrape deep DOM trees, expect a measurable speedup in text extraction.

No breaking changes in this release.

A release focused on making your spiders smarter about the websites they crawl

🚀 New Stuff and quality of life changes

  • Spiders can now tune their own speed with AutoThrottle. Instead of guessing a download_delay that's either too slow or gets you banned, the spider measures how fast each website answers and adjusts the delay of every domain on its own. When a website starts blocking or rate-limiting you, it doubles the delay (or waits exactly what the Retry-After header asks for) until that stops, then speeds back up. Your download_delay and any robots.txt Crawl-delay are still respected as the minimum. (Check the docs)

    class MySpider(Spider):
    name = "adaptive"
    start_urls = ["https://example.com"]
    autothrottle_enabled = True
    autothrottle_start_delay = 2.0
    autothrottle_max_delay = 30.0
    autothrottle_block_backoff = True

  • Export your results to CSV and XML, next to the JSON/JSONL exporters you already had. Items that don't all share the same keys are still exported without losing anything, and nested values are written as JSON. (Check the docs)

    result = MySpider().start()
result.items.to_csv("products.csv")
result.items.to_xml("products.xml")

  • The MCP server can now require authentication, so you can safely expose it instead of keeping it on your own machine. Any request without the token is rejected, and you can also restrict which hostnames the server answers to. (Check the docs)

    scrapling mcp --http --auth-token "$(openssl rand -hex 32)"

  • Browsers now accept CDP URLs over HTTP, not just WebSocket ones. So next to the wss:// endpoints managed browser providers hand out, you can now point any browser fetcher or MCP session at a Chrome you started yourself with --remote-debugging-port=9222.

  • Published Docker images are now tagged with their release version instead of only latest, so you can pin the exact version you want, by @JanRK in #384.

🐛 Bug Fixes

  • Fixed cached responses losing all their cookies when the response came from a browser engine, which silently broke any session or auth logic relying on them while using the spiders' development mode, by @amitvijapur in #379. (Fixes #376)

  • Fixed StealthyFetcher forcing the en-US locale on every browser instead of following your system's, which made websites see a mismatch between your locale and your IP address and treat you as suspicious, like Google answering with 429s. (Fixes #381)

  • Fixed a misleading error message in the storage system and removed a dead call left after inserts, by @fix2015 in #377.

Performance

  • get_all_text() is now O(nodes) instead of walking up the ancestors of every single text node, which makes it around 5-6x faster on deeply nested pages, by @yetval in #378.
