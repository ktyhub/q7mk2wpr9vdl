oh-my-pi v19.1.0

@oh-my-pi/pi-agent-core

Hinzugefügt

– Unterstützung für Standby-Tools durch Agent.setStandbyTools() und AgentContext.standbyTools hinzugefügt, sodass Tools inaktiv bleiben können, bis eine Anforderung die Tool-Nutzung explizit aktiviert.

@oh-my-pi/pi-ai

Hinzugefügt

– Anbieter-Hooks hinzugefügt (setProviderHooks in @oh-my-pi/pi-ai/provider-hooks), die den Stream-Adapter oder die Bildgenerierung eines Anbieters ersetzen, während seine Modelle ihren api behalten.

  • Opt-in-Prompt-Störung hinzugefügt: Im Modell sichtbare Prosa-Prompt- und Tool-Beschreibungen verwenden eine Formulierung pro Installation, die aus einem festen Paraphrasenpool ausgewählt wird, der jede statische System- und Tool-Prompt-Zeile abdeckt. Modelle ermöglichen es mit der prompt-perturbation KDL-Achse; OMP_PROMPT_PERTURBATION=1/0 erzwingt das Ein- oder Ausschalten.

Geändert

– Der Cursor-Anbieter leitet bash anstelle von write weiter, sodass bereitgestellte Vorschauen abgeschlossen werden können – Die Standardwerte für den Stream-Watchdog des Anbieters wurden von 5 auf 15 Minuten erhöht, um zu verhindern, dass langsame One-Shot-Abschlüsse vorzeitig unterbrochen werden.

  • Erweiterter Schutz des Gemini Reasoning-Streams, um längere Planungssequenzen vor Unterbrechungen zu ermöglichen.

Behoben

– Von Brokern unterstützte Anmeldeinformationsspeicher erkennen jetzt ein vom Broker gespeichertes Login, stellen es aber nicht bereit und behalten es im lokalen agent.db (HybridAuthCredentialStore), anstatt es beim nächsten Snapshot zu verlieren; Bei einem Nur-Broker-RemoteAuthCredentialStore schlägt der Upload mit AuthBrokerUnservedProviderError fehl. – OpenAI-Codex-Anfragen senden nicht mehr die Header session_id und conversation_id; Die Sitzung geht nur als session-id aus, wie der Codex CLI, sodass Proxys, die Unterstrich-Header-Namen ablehnen (Envoy, Nginx-Standardeinstellungen), diese weitergeben (#20018) – Bei Modellen, die Benutzernachrichten nach Tool-Ergebnissen falten, wurde die beabsichtigte Konversationsstruktur beibehalten, wenn eine Benutzernachricht auf ein Tool-Ergebnis folgt. – LiteLLM-Anfragen wechseln jetzt zu einem anderen konfigurierten API-Schlüssel, wenn eine 422-Budgetüberschreitungsantwort den aktuellen Schlüssel deaktiviert. (#19860) – GPT-6.2-Systemaufforderungen werden jetzt als führende Entwicklernachrichten über Responses-Proxys von Drittanbietern gesendet, was das Zwischenspeichern von Aufforderungen ermöglicht und unnötige Eingabegebühren in voller Höhe bei nachfolgenden Runden vermeidet. (openai/codex#62312)

  • Verbesserte Erkennung des Denkmodus über alle Anforderungsformate hinweg, wodurch unnötige Wiederholungsversuche vermieden und vom Server akzeptierte oder abgelehnte Formate korrekt gespeichert werden. (#19758 von @eggpeat) – Fehler bei der Authentifizierungsaktualisierung, die dazu führen könnten, dass ein Zugriffstoken vor dem nächsten Wiederholungsversuch abläuft, werden jetzt mit einer Warnung angezeigt, anstatt nur in Debug-Protokollen sichtbar zu bleiben. (#19590 von @will-bogusz)
  • Chat-Abschlüsse behalten jetzt die Argumentation bei, die nur in reasoning_details zurückgegeben wird, einschließlich der Argumentation von Bifrost Gemini. (#19595 von @Xytronix) – Die Erschöpfung des Antigravitationskontingents wird jetzt als 429-Rate-Limit-Fehler gemeldet, sodass konfigurierte Wiederholungsversuche, Anmeldeinformationsrotation und Modell-Fallback-Verhalten korrekt angewendet werden können, anstatt die Antwort als Assistententext zu behandeln. (#19382 von @gimso2x) – Anthropic-Anfragen behalten jetzt das Prompt-Caching bei, wenn Tools später in einer Konversation aktiviert werden, wodurch unnötige System-Prompt- und Transkript-Cache-Umschreibungen vermieden werden. (#19826)

@oh-my-pi/browser-relay

Breaking Changes

– Die omp-Erweiterung verwendet jetzt eine angeheftete Chrome-Erweiterungs-ID und stellt über ihren nativen Host eine Verbindung zum Browser-Relay her. Installieren Sie die Erweiterung mithilfe des Chrome-Ablaufs „Entpackt laden“ neu. Die Relay-Port- und Token-Optionen wurden entfernt.

Hinzugefügt

– Ein omp-Chrome-Seitenfeld mit Sitzungsmodellauswahl, Rollenverknüpfungen, Denksteuerungen, Eingabeverknüpfungen, Nachrichtenwarteschlangen und Laufunterbrechungssteuerungen hinzugefügt.

  • Browser-Interaktionsfunktionen hinzugefügt, darunter Seitenüberlagerungen, Bild- und Elementauswahl, Teach, geplante Verknüpfungen und GIF-Export.

Geändert

– Im Chrome-Seitenbereich werden kurze Beschriftungen für Werkzeugschritte mit strukturierten Absichten angezeigt. – Die Erweiterung hält jetzt registrierte Installationen bei OMP-Upgrades und Neuladevorgängen im Leerlauf auf dem neuesten Stand.

  • Browser-Relay-Ports werden automatisch zugewiesen und lokal vom Terminal clients erkannt, während Sidebar-Chats weiterhin ihre bestehende Verbindung verwenden. – Sidepanel-Sitzungen steuern jetzt den verbundenen Chrome-Browser direkt, anstatt einen separaten Headless-Browser zu öffnen.

Behoben

– Verbesserte Relay-Wiederherstellung, sodass Chrome automatisch wieder eine Verbindung herstellt, wenn der native Host nicht verfügbar ist oder eine veraltete Verbindung unterbrochen wird.

@oh-my-pi/pi-catalog

Breaking Changes

– Der integrierte Gemini CLI OAuth-Anbieter (google-gemini-cli) wurde entfernt. Google Antigravity und Antigravity CLI bleiben verfügbar.

Hinzugefügt

  • Regeln für Laufzeitanbieter hinzugefügt (setRuntimeProviderRule in compat/cascade). Sie wenden KDL-Anweisungen auf die Modelle eines Anbieters an, stellen Verknüpfungen mit gebündelten Regeln her und löschen von Regeln abgeleitete Caches, wenn sie sich ändern. – Die prompt-perturbation-Katalogachse wurde hinzugefügt, die einen Anbieter oder ein Modell für die Umschreibung von Eingabeaufforderungen pro Installation auswählt. – Das uncached-instructions-Kompatibilitätsflag für GPT-6.2-Modelle auf allen Hosts hinzugefügt, wodurch Systemaufforderungen aus dem nicht zwischengespeicherten Feld „Antworten instructions“ verschoben werden.

Behoben

– Die Aktualisierung des Vercel AI Gateway-Modells wurde behoben, sodass öffentliche Modelle weiterhin erkennbar bleiben, wenn ein gespeicherter API-Schlüssel abgelaufen ist. – OpenRouter-Modelle behoben, die eine Begründung erfordern, aber keine Aufwandsstufen angeben; Anfragen, die das Denken deaktivieren, verwenden jetzt den niedrigsten unterstützten Argumentationsaufwand, anstatt fehlzuschlagen. – Behoben: Gemini 4-Modelle (Argon, Kohlenstoff, Wasserstoff und Neon), die mit leeren, fehlerhaften Antworten fehlschlugen, wenn Nachrichten unmittelbar nach den Werkzeugergebnissen eintrafen. – Aktualisierte Preise für neu bereitgestellte Cursor-Modelle, um ihre dokumentierten Pro-Token-Tarife zu verwenden, anstatt als kostenlos gemeldet zu werden. – Das Caching der Codex client-Version wurde korrigiert, sodass die Cache-Datei im konfigurierten $XDG_CACHE_HOME/omp-Verzeichnis gespeichert wird.

Breaking Changes

  • xd://-Tool-Geräte durch Tool-Befehle ersetzt: Selten verwendete Tools werden jetzt als Bash-Befehle (<tool> --help, <tool> <args>) ausgeführt, während bash aktiv ist, und sind ansonsten normale Tools

  • Die tui.completeScrollback-Einstellung wurde entfernt; Transkriptzeilen, die vom HUD, von Dialogen oder vom Entwurf abgedeckt werden, werden jetzt immer zum Zurückscrollen verschoben, und die Eingabe kehrt zur unteren Zeile zurück, wenn Überlagerungen geschlossen werden. – Die eigenständigen MCP-Transport- und Tool-Cache-Exporte SDK wurden ersetzt und DeferredMCPTool plus MCP-Cache- und Reconnect-Policy-Manager-Optionen entfernt. Der Zugriff auf MCP-Server erfolgt jetzt über den MCP-Host APIs. – Das Browser-Relay-Hosting läuft jetzt über den nativen Host der omp-Erweiterung, während Chrome geöffnet ist. Der On-Demand-Serverbefehl omp browser-relay und seine Optionen --port, --token und --no-group wurden entfernt. browser.relayUrl bleibt für Relays verfügbar, die von einer anderen Maschine weitergeleitet werden. Laden Sie die omp-Erweiterung nach dem Upgrade einmal neu oder starten Sie Chrome neu. – archive.search(query) wurde geändert, um Sitzungstitel, Leerlaufrückblicke und Benutzer-/Assistenteninhalte im gesamten Verlauf zu durchsuchen und übereinstimmende Sitzungsdatensätze zurückzugeben; Verwenden Sie archive.prompts({ query }) für reine Eingabeaufforderungssuchen. Bei Suchanfragen werden Suchbegriffe am Wortanfang gefunden.
  • RPC-Hosts müssen das ask-Tool als eine vollständige HTML-Formular-form-Anfrage verarbeiten und mit übermittelten Daten oder einem Abbruch antworten. Es werden keine Feld-für-Feld-Eingabeaufforderungen mehr ausgegeben.

B. prompt-perturbation) für seine Modelle fest. – Der magic-Bearbeitungsmodus wurde hinzugefügt, der Markdown-Änderungsbeschreibungen mit Aufzählungszeichen akzeptiert, die unter # path-Überschriften gruppiert sind, und ein konfigurierbares schnelles Modell oder eine konfigurierbare Rolle zum Generieren und Anwenden von Patches verwendet. Es unterstützt präzise Beschreibungen zum Ersetzen, Löschen, Verschieben und Umbenennen von Blöcken und stellt die resultierenden Unterschiede dar. – Remote-Sitzungsmodellsteuerungen über RPC hinzugefügt, einschließlich Modellauswahl, Denkebenen- und Rollenauswahl, auto-Denken und Befehle zum Fortsetzen, Abbrechen während der Übermittlung von Nachrichten in der Warteschlange oder Fortfahren des Host-Agenten. Collab-Gäste können jetzt fortfahren, unterbrechen und Folgeaufforderungen für den Gastgeber in die Warteschlange stellen. – Unterstützung für den Unicode-Set-Modus (v) in durch Schrägstriche getrennten regulären secrets.yml-Ausdrücken hinzugefügt. – MCP-Server in den omp-Daemon verschoben, mit optionaler Prozessfreigabe über Sitzungen hinweg, verzögertem Start, Herunterfahren im Leerlauf, gemeinsamem Discovery-Caching und /mcp list-Status einschließlich Prozess- und Sitzungsinformationen. Konfigurieren Sie die Freigabe mit mcp.shared und das Herunterfahren im Leerlauf mit mcp.idleStopMinutes. – Unterstützung für die MCP-Protokollrevision 2026-07-28 hinzugefügt, einschließlich Servererkennung, Metadaten pro Anfrage, Root-Eingaberunden, Abonnements und Cache-Kontrollen, während die Kompatibilität mit Servern gewahrt bleibt, die den Initialisierungs-Handshake erfordern. – Native Browser-Relay-Integration für die Chrome-Erweiterung hinzugefügt, einschließlich Sidepanel-Sitzungen, Installation und Synchronisierung der Erweiterung, automatische Profilregistrierung und In-Tab-Aktions-Overlays. Sidepanel-Sitzungen bleiben von den Terminal-Resume-, Recent-Session-, --continue- und ACP-Sitzungslisten getrennt, sofern sie nicht explizit fortgesetzt werden.

  • Eine farbige Erweiterungsstatusvariante zu omp gallery --segment status hinzugefügt. – Benachrichtigungen und Wartestatus hinzugefügt, wenn ein Programm, das in einem Bash pty ausgeführt wird, auf Tastatureingaben wartet, z. B. ein Passwort oder eine Bestätigungsaufforderung; Deaktivieren Sie Benachrichtigungen mit pty.notify. – Eval completion() zeichnet jetzt rohe Provider-Frames für die /debug-Inspektion auf und speichert Frames von fehlgeschlagenen Aufrufen als Protokolldateien im Verzeichnis der Sitzungsartefakte. – parentToolCallId zu den Erweiterungsereignissen tool_call und tool_result hinzugefügt, sodass verschachtelte Toolaufrufe der Evaluierungszelle oder dem Kernel-definierten Tool zugeordnet werden können, das sie ausgelöst hat. – Volltext-Transkriptsuchindizierung für archive.search hinzugefügt, die Benutzer- und Assistentennachrichten im gesamten Sitzungsverlauf abdeckt. – Sitzungsdateien zeichnen jetzt Genehmigungsanfragen und deren Ergebnisse auf, sodass Dashboards und Seitenleisten anzeigen können, wann eine Sitzung auf die Tool-Genehmigung wartet. – Live-Sichtbarkeit der Ausgabe hinzugefügt, die von Hintergrund-Bash-Jobs an Dateien umgeleitet wird, einschließlich Job-Streams, Job-Blatt, Job-Widgets und Befehlskarten; Wenn Sie einen Befehl auswählen, wird die Ausgabe für die entsprechende Pipeline oder den umgeleiteten Stream angezeigt. – Binary Ninja als Disassembler-Backend für Leseanalyseansichten und den dsm-Namespace hinzugefügt. Wählen Sie es mit disassembler.backend = binja aus und konfigurieren Sie seine Installation mit binja.installDir oder $BN_INSTALL_DIR.
  • CliDas Durchsuchen des Nutzungsbeschränkungssegments in nativen Terminal-Hosts wie Tern öffnet jetzt /usage. Durch Ändern der Agenten-Tray-Einstellung von Tern wird sofort zwischen den Tray-Karten und den laufenden Agenten- und Jobzählern umgeschaltet, ohne dass omp neu gestartet werden muss.

Geändert

– Bilder, die ein Befehl als Kitty- oder Sixel-Grafiken ausgibt, werden in einer temporären Datei gespeichert und in der Bash-Ausgabe verknüpft sowie angehängt

  • generate_image gibt seine Bilder als Anhänge zurück
  • Spotlight-Tool-Aufrufe verwenden Label: detail; Bei der Aktivität wird nur die Bezeichnung angezeigt, während beim Ausgaberanking die vollständige Absicht verwendet wird. – Verbesserte Regex-Leistung für TTSR- und Secret-Redaction-Scans, einschließlich SIMD-Beschleunigung und schnellerem Kandidaten-Matching, ohne die Matching-Semantik zu ändern. – Verbesserte Leistung beim Auflisten von Sitzungen über alle Projekte hinweg, insbesondere bei Tausenden von Projektverzeichnissen.
  • Interactive wait wartet beim ersten Aufruf jetzt bis zu vier Minuten auf Hintergrundjobs, anstatt nach fünf Sekunden zurückzukehren. – Der MCP-OAuth-Name client wurde auf Codex aktualisiert. – Automatische Wiederholungsversuche stören weniger: Fehlversuche werden nicht im Transkript angezeigt, der Wiederholungsstatus erklärt den Grund und eine erfolgreiche Wiederherstellung hinterlässt nur einen kurzen Hinweis. – Selektive Commits ordnen Änderungen im Bearbeitungstool und in der Shell jetzt genauer zu, unterscheiden externe Programmänderungen zur Überprüfung und verwenden ein wesentlich kleineres Änderungsjournal. Lange Commit-Vorschauen heben jetzt nur die geänderten Wörter hervor, während der ursprüngliche Patch erhalten bleibt.
  • TTSR-Regeln, die das Streaming nicht unterbrechen können, werden am Ende der entsprechenden Antwort, Begründung oder des Toolaufrufs ausgewertet, wodurch unnötige Arbeit reduziert und gleichzeitig Übereinstimmungen und Erinnerungen erhalten bleiben.
  • Eval completion() akzeptiert jetzt vom Benutzer markierte Modellagenten, z. B. mit ^model gepinnte Modelle, und verwendet deren markierten Aufwandsgrad.
  • read erkennt SQLite-gestützte .i64- und .idb-Dateien als IDA-Datenbanken und meldet Unstimmigkeiten zwischen Disassembler und Backend deutlich.

  • Spotlight behält kurze relevante Passagen aus mehreren großen Funktionskörpern zusammen mit ihren Signaturen bei, auch wenn eine Codegliederung erneut ausgeschnitten wird. – Auf ein Zurücksetzen des Nutzungslimits innerhalb von retry.maxDelayMs wird jetzt auch ohne Retry-After-Header gewartet. – Wenn Sie sich anmelden, während ein Authentifizierungsbroker konfiguriert ist, wird kein Erfolg mehr für einen Anbieter gemeldet, den der Broker speichert, aber nicht bedient (z. B. einen Anbieter, den ein älterer Broker pausiert); Die Anmeldung wird stattdessen im agent.db dieses Computers gespeichert, überlebt Neustarts und beim Anmelden/Abmelden wird jetzt angegeben, wo die Anmeldeinformationen gespeichert wurden. – Spotlight behält mehr hochrelevante Zeilen mit ihren Nachbarn in langen Ergebnissen und großen Codeumrissen bei und behält gleichzeitig sichtbare Absichtsübereinstimmungen innerhalb des Fensterbudgets bei.
  • Problem behoben, bei dem Tern-Tray-Karten und Subagenten-Live-Vorschauen veraltete Anrufe, Modelle oder Denkzustände anzeigten, während ein Agent ausgeführt wurde oder nach einem Modellwechsel; Fertige Karten behalten jetzt das verwendete Modell und die verwendete Denkstufe. – Problem behoben, bei dem Sitzungen im Sidepanel der Erweiterung den omp-eigenen Browser starteten, anstatt nur das Chrome-Fenster des Benutzers zu steuern.
  • Antwortfußzeilen und Kopiersteuerelemente in Tern bleiben nach dem Fortsetzen, Komprimieren oder Neuerstellen eines Transkripts erhalten. – Es wurde verhindert, dass --continue und autoResume eine Verbindung zu einer Sitzung herstellen, die gerade von einem anderen OMP-Prozess geschrieben wird.
  • Sichtbare Fortschrittsberichte hinzugefügt, während /handoff seine Zusammenfassung schreibt. – Der Zugriff auf reine Cloud-Dateien auf macOS iCloud Drive, Desktop & Documents, Google Drive und Dropbox-Speicherorten wurde korrigiert. – Verhindert, dass pathologische TTSR-Zustände und geheime Redaktions-reguläre Ausdrücke Sitzungen oder Anfragen einfrieren. – Die Verarbeitung des Prompt-Cache für IRC-aktivierte Subagenten und Sitzungen, deren Kontext-Hooks eine erste Nachricht bereitstellen, wurde korrigiert.
  • Verbesserte Pfadausgabe und Optionsbehandlung der Shell rg und fd, um sie an ihre nativen Tools anzupassen, einschließlich Pfaden, die mit - beginnen, durch Nullen getrennter Ausgabe und expliziten Präfixen für das aktuelle Verzeichnis. – Die Validierung durch schlampige Bearbeitung und den Blockabgleich für unvollständige Aktionen, numerische ||-Ausdrücke, verschachtelte oder teilweise Blockenden, JSDoc-Kommentare und Hashline-Header mit nachgestellten Leerzeichen wurden korrigiert. – Die OpenCode v2 MCP-Konfigurationserkennung von mcp.servers wurde korrigiert, während die Unterstützung für ältere flache mcp-Einträge beibehalten wurde. – ovnfs-Befehle korrigiert, wenn ovnfs.path Windows-Backslashes, Leerzeichen oder $-Zeichen enthält. – Fehlgeschlagene Browserstarts durch Protokollierung von URL-Anmeldeinformationen, Abfragezeichenfolgen, OAuth-Gerätecodes oder Fragmenten wurden gestoppt. – web_search wurde korrigiert, um die für die aktuelle Sitzung konfigurierte Suchreihenfolge und Ausschlüsse zu berücksichtigen. – MCP OAuth-Aktualisierung für Microsoft Entra-Server behoben, bei denen client auch die Ressource ist; Für zuvor gespeicherte Anmeldeinformationen ist möglicherweise ein /mcp reauth erforderlich. – Die Modellauflösung für OpenRouter-Routenvarianten, die von Subagenten und Rollen pro Anruf verwendet werden, wurde korrigiert. – Die Schwärzung von Geheimnissen in gemeinsamen Sitzungen wurde behoben, sodass vom Anbieter verschlüsselte Argumente nicht unerwartet beibehalten werden. – Die Handhabung der Bash-Genehmigung für zusammengesetzte Befehle mit Umgebungszuweisungen und Flags, einschließlich Platzhalter-Zulassungsregeln, wurde korrigiert. – Selektive Commits behoben, wenn sich HEAD während eines Commit-Hooks ändert und wenn Bearbeitungen von mehreren Autoren neu angeordnet werden oder sich überschneiden; Mehrdeutige Änderungen werden jetzt zur Überprüfung gesendet, anstatt dupliziert oder stillschweigend falsch angewendet zu werden.
  • Die Archivdatensätze wurden korrigiert, um alle dokumentierten Schlüssel mit null für fehlende Werte einzuschließen. – Unnötige leere Sitzungsprotokolldateien für die Inline-Bash-/Eval-Ausgabe und die Wiederherstellung nach Zeitüberschreitung bei Anfragen behoben. – Verbesserte read-Vorschläge für Zeilen-, Bereichs- und Spaltenselektoren und beibehaltene Quellzeilenmetadaten für In-Memory- und konvertierte Textlesevorgänge.
  • Es wurden Fehler im Agenten-Lebenszyklus behoben, bei denen es zu doppelten IDs, ausstehenden Nachrichten, Herunterfahren und Wiederbelebung kam. – Die Handhabung von Browser-Tabs auf CDP-Engines, die separate Verbindungen pro Seite verwenden, wurde korrigiert, einschließlich der Wiederherstellung nach Zeitüberschreitungen oder Worker-Exits. – Die Browser-Interaktionsberichte für Nur-Overlay-clicks, ausgeblendete Frames mit Inline-SVG oder MathML und Suchfelder, die bei wichtigen Ereignissen aktualisiert werden, wurden korrigiert. – Die Überprüfung der Browser-Computernutzung bei minimierten macOS-Fenstern und vollständig abgedeckten Windows Chrome-, Edge- und Electron-Fenstern wurde behoben. – Behoben, dass /goal auf Anthropic die zwischengespeicherte Systemaufforderung und das Transkript unnötigerweise neu schrieb. – Isolierte Task-Subagenten in reinen Git-Repositorys wurden behoben, indem sie frühzeitig abgelehnt und verfügbare Arbeitsbäume identifiziert wurden, anstatt ohne einen verwendbaren Arbeitsbaum zu beginnen. – Nix-Browser-Relay-Builds wurden korrigiert, um alle Abhängigkeiten abzurufen, ohne auf die NPM-Registrierung zurückzugreifen. – Das Laden von Erweiterungen, Plugins, benutzerdefinierten Tools, Hooks, Befehlen und Freigabeskripten für Pfade, die ? enthalten, wurde korrigiert, mit einem nützlichen Fehler bei der Identifizierung des Pfads und der Lösung.

oh-my-pi v19.1.0

@oh-my-pi/pi-agent-core

Added

  • Added standby tools support through Agent.setStandbyTools() and AgentContext.standbyTools, allowing tools to remain inactive until a request explicitly enables tool use.

@oh-my-pi/pi-ai

Added

  • Added provider hooks (setProviderHooks in @oh-my-pi/pi-ai/provider-hooks), which replace a provider's stream adapter or image generation while its models keep their api.
  • Added opt-in prompt perturbation: model-visible prompt prose and tool descriptions use a per-install wording chosen from a committed paraphrase pool covering every static system- and tool-prompt line. Models enable it with the prompt-perturbation KDL axis; OMP_PROMPT_PERTURBATION=1/0 forces it on or off.

Changed

  • The Cursor provider forwards bash instead of write so staged previews can be finalized
  • Increased provider stream watchdog defaults from 5 to 15 minutes, preventing slow one-shot completions from being interrupted prematurely.
  • Extended Gemini reasoning-stream protection to allow longer planning sequences before interruption.

Fixed

  • Broker-backed credential stores now detect a login the broker stores but does not serve and keep it in the local agent.db (HybridAuthCredentialStore) instead of losing it on the next snapshot; a broker-only RemoteAuthCredentialStore fails the upload with AuthBrokerUnservedProviderError.
  • OpenAI Codex requests no longer send the session_id and conversation_id headers; the session goes out only as session-id, like the Codex CLI, so proxies that reject underscore header names (Envoy, nginx defaults) pass them (#20018)
  • Preserved the intended conversation structure when a user message follows a tool result for models that fold user messages after tool results.
  • LiteLLM requests now rotate to another configured API key when a 422 budget-exceeded response disables the current key. (#19860)
  • GPT-6.2 system prompts are now sent as leading developer messages through third-party Responses proxies, enabling prompt caching and avoiding unnecessary full-rate input charges on subsequent turns. (openai/codex#62312)
  • Improved thinking-mode detection across request formats, avoiding unnecessary retries and correctly remembering formats accepted or rejected by the server. (#19758 by @eggpeat)
  • Auth refresh failures that could cause an access token to expire before the next retry are now surfaced with a warning instead of remaining visible only in debug logs. (#19590 by @will-bogusz)
  • Chat Completions now preserve reasoning returned only in reasoning_details, including reasoning from Bifrost Gemini. (#19595 by @Xytronix)
  • Antigravity quota exhaustion is now reported as a 429 rate-limit error, allowing configured retries, credential rotation, and model fallback behavior to apply correctly instead of treating the response as assistant text. (#19382 by @gimso2x)
  • Anthropic requests now preserve prompt caching when tools are activated later in a conversation, avoiding unnecessary system-prompt and transcript cache rewrites. (#19826)

@oh-my-pi/browser-relay

Breaking Changes

  • The omp extension now uses a pinned Chrome extension ID and connects to the browser relay through its native host. Reinstall the extension using Chrome’s “Load unpacked” flow; the relay port and token options have been removed.

Added

  • Added an omp Chrome side panel with session model selection, role shortcuts, thinking controls, input shortcuts, message queuing, and run interruption controls.
  • Added browser interaction features including page overlays, image and element picking, Teach, scheduled shortcuts, and GIF export.

Changed

  • The Chrome side panel shows brief labels for tool steps with structured intents.
  • The extension now keeps registered installations up to date across omp upgrades and reloads when idle.
  • Browser relay ports are assigned automatically and discovered locally by terminal clients, while sidebar chats continue using their existing connection.
  • Side panel sessions now control the connected Chrome browser directly instead of opening a separate headless browser.

Fixed

  • Improved relay recovery so Chrome reconnects automatically when the native host is unavailable or a stale connection drops.

@oh-my-pi/pi-catalog

Breaking Changes

  • Removed the built-in Gemini CLI OAuth provider (google-gemini-cli). Google Antigravity and Antigravity CLI remain available.

Added

  • Added runtime provider rules (setRuntimeProviderRule in compat/cascade). They apply KDL directives to one provider's models, win ties with bundled rules, and clear rule-derived caches when they change.
  • Added the prompt-perturbation catalog axis, which opts a provider or model into per-install prompt paraphrasing.
  • Added the uncached-instructions compatibility flag for GPT-6.2 models across all hosts, moving system prompts out of the uncached Responses instructions field.

Fixed

  • Fixed Vercel AI Gateway model refreshes so public models remain discoverable when a stored API key has expired.
  • Fixed OpenRouter models that require reasoning but do not advertise effort levels; requests that disable thinking now use the lowest supported reasoning effort instead of failing.
