OpenHands v1.15.0

Highlights

  • Local agent-server model configuration — The new provider-connections UI makes LLM setup available directly from the local agent server (#16616). Selection behavior is now more predictable: the home-page LLM choice overrides an agent profile’s pinned model (#16671), while failed ACP discovery no longer persists model choices or silently downgrades profiles (#16701, #16523).
  • High-throughput streaming reliability — Streaming deltas are batched so fast models do not overwhelm the UI (#16164); non-native streamed XML tool calls are reconciled (#16220); and event sockets survive data refetches with hung handshakes bounded (#16732). Together, these changes matter for long-running sessions with heavy tool-call output.
  • Manifest-driven automations — Catalog entries can now install script bundles (#16680), and the automation interface is served from the manifest alone (#16676). Custom automation authors should treat the manifest as the authoritative interface definition and validate bundled scripts against openhands-automation 1.8.0.
  • Correct Git and workspace routing — Remote URLs with trailing slashes are normalized (#16536), repository ports are no longer mistaken for path components (#16723), and backend-selection parameters preserve URL fragments (#16619). This fixes repository resolution and deep-link behavior for nonstandard Git endpoints.
  • More reviewable conversation and file workflows — The new overview panel and unified commits drawer centralize session review (#16230). Files view now displays the workspace path (#16362) and shows every grouped workspace folder regardless of pagination (#16444), reducing ambiguity in multi-folder workspaces.
  • Breaking changes — None identified.
