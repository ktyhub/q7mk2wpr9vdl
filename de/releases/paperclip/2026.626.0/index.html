paperclip v2026.626.0

Papierclip v2026.626.0

Veröffentlicht: 26.06.2026

Diese Veröffentlichung erhält 122 Commits von 17 Mitwirkenden.

Highlights

  • Hermes, jetzt integriert (lokales und Remote-Gateway) – Hermes ist in dieser Version ein erstklassiger Adapter. Mieten Sie hermes_local-Agenten, die auf Ihrem eigenen Computer ausgeführt werden, oder hermes_gateway-Agenten, die Hermes remote über ein Gateway ausführen – keine manuelle Plugin-Installation erforderlich, mit sicheren Onboarding-Standardeinstellungen für die Gateway-URL und den API-Schlüssel. Externe Hermes-Pakete können die integrierten Pakete weiterhin über den Adapter-Manager überschreiben oder überschatten. (#8543, @cryppadotta)
  • Task-Watchdogs – Mit einer erstklassigen Watchdog-Kontrollebene können Sie automatisierte Prüfungen an eine Aufgabe anhängen und Paperclip diese für Sie überwachen lassen – Watchdog-Status, Ergebnisse und ausstehende Arbeit werden direkt im Issue-Thread angezeigt, anstatt Sie mit der Betreuung eines langwierigen Agenten zu betrauen. (#8339, @cryppadotta)
  • Fragen-Arbeitsmodus – Probleme können jetzt in einem „Fragen“-Arbeitsmodus für Frage-und-Antwort-Aufgaben ausgeführt werden, sodass Sie einen Agenten auf eine Frage verweisen und eine Antwort erhalten können, ohne dass dadurch ein vollständiger Ausführungsworkflow in Gang gesetzt wird. (#8334, @cryppadotta)
  • Sandbox-Laufzeitstatus, live in Ihren Threads – Kurzlebige Sandbox-Laufzeitumgebungen melden ihren Status jetzt direkt in Issue-Threads und Daytona-Sandbox-Leases werden über alle Läufe hinweg wiederverwendet – so ist die Ausführung in der Cloud/Sandbox besser sichtbar und kann schneller gestartet werden. (#8594, #8593, @devinfoley; #8513, @devinfoley)
  • Workspace-Dateidownloads und externe Objektreferenzen - Holen Sie sich Arbeitsergebnisse aus Paperclip: Laden Sie die von Ihren Agenten erstellten Dateien direkt aus dem Workspace herunter und referenzieren Sie externe Objekte (Links, Assets) über Problemoberflächen hinweg, damit der richtige Kontext mit der Aufgabe übertragen wird. (#8512, #8229, @cryppadotta)

Verbesserungen

  • Aktualisiertes Onboarding – Der Onboarding-Ablauf wurde überarbeitet und der ältere klassische Assistent wurde eingestellt, zusammen mit einer Reihe von Korrekturen im UI-Stil – so ist das Einrichten einer neuen Instanz übersichtlicher und die Standard-Aufgaben-Benutzeroberfläche (Arbeitsmodusbezeichnungen, Statusfarben, Teamerstellungskopie) ist sofort einheitlich. (#8628, @cryppadotta)
  • Symbole und Farben für den Aufgabenstatus – Der Aufgabenstatus lässt sich jetzt auf einen Blick ablesen, mit speziellen Symbolen und Farben im gesamten Bereich und in den Problemlisten. (#8580, @scotttong; #8376, @tonio-alucema)
  • Routine-Datumsvariablen – Routinen erhalten Datumsvariablensteuerungen, sodass eine wiederkehrende Routine das Ausführungsdatum parametrisieren kann, ohne die Eingabeaufforderung jedes Mal manuell bearbeiten zu müssen. (#8655, @cryppadotta)
  • Bearbeitung von Fertigkeitskategorien – Sie können jetzt Fertigkeitskategorien in den Einstellungen bearbeiten, was die Organisation eines installierten Fertigkeitskatalogs erleichtert. (#8615, @cryppadotta)
  • Paperclip-Seiten und -Kapseln veröffentlichen – Mit einer gebündelten Fähigkeit zur Seitenveröffentlichung können Agenten statische HTML-Seiten und Asset-Ordner auf einem zugelassenen Host veröffentlichen, und eine gebündelte Kapselfähigkeit liefert das Paperclip-Kapsel-Identicon-Toolkit. (#8664, #8669, @cryppadotta) – Begrenzte Arbeitsbereichsübersicht – Der Endpunkt „Arbeitsbereichsübersicht“ ist jetzt begrenzt, was die Nutzlast und Latenz für Instanzen mit großen Arbeitsbereichen drastisch reduziert. (#8627, @cryppadotta)
  • Standardmäßig optimierte Seitenleiste – Die optimierte Seitenleiste ist jetzt das Standardlayout. (#8496, @devinfoley)
  • Sortierte Arbeitsbereichsroutinen – Arbeitsbereichsroutinen sind jetzt nach Namen sortiert, sodass die Routinenliste vorhersehbar bleibt. (#8666, @cryppadotta)
  • Plugin-Installations-Targeting – Der CLI zeigt den Plugin-Installationszielhost an und fügt einen plugin target-Befehl hinzu, sodass Sie immer wissen, in welcher Instanz ein Plugin installiert wird. (#8575, @cryppadotta)
  • Bessere Arbeitsbereichsauswahl-Suche – Die wiederverwendbare Arbeitsbereichsauswahl verfügt über eine verbesserte Suche, sodass Sie schneller den richtigen Arbeitsbereich auswählen können. (#8597, @cryppadotta)
  • Instanzenbezogene Ausführungsumgebungen – Ausführungsumgebungen sind jetzt instanzenbezogener Natur und werden über einen Dialog bearbeitet, mit übersichtlicherer Kopie und einem aufgeräumteren Treiber-Dropdown-Menü auf dem Bildschirm „Unternehmensumgebungen“. (#8375, #8391, #8400, #8398, #8329, @cryppadotta)
  • Heartbeat-Preflight-Budgetobergrenzen – Heartbeats respektiert jetzt Preflight-Budgetobergrenzen und gibt Ihnen eine feste Obergrenze für die Ausgaben, die ein einzelnes Wake ausgeben kann. (#8347, @levineam)
  • Skill-Mutationen durch Berechtigung geschützt – Das Erstellen/Bearbeiten/Löschen von Skills ist jetzt durch eine dedizierte skills:create-Berechtigung geschützt, sodass Prinzipale mit niedrigeren Rechten Skills durchsuchen können, ohne sie ändern zu können. (#8616, @cryppadotta)
  • Beobachtbarer Sandbox-Synchronisierungsfortschritt – Adapterdienstprogramme können jetzt den Sandbox-Synchronisierungsfortschritt melden, sodass lange Dateisynchronisierungen in eine Sandbox keine Blackbox mehr darstellen. (#8395, @cryppadotta)
  • Codex Local erbt die Host-Anmeldung – codex_local-Agenten erben standardmäßig die Host-Codex-Anmeldung und verteilen die verwaltete Authentifizierung auf isolierte Homes, sodass sie ohne erneute Authentifizierung funktionieren. (#8425, #8403, @cryppadotta)
  • Lokaler Inaktivitätsmonitor von Codex – Der codex_local-Adapter überwacht jetzt die Ausgabeinaktivität und bevorzugt die Loopback-Laufzeit-URL API für lokale Agenten, wodurch die Zuverlässigkeit langer lokaler Ausführungen verbessert wird. (#5017, #5102, @neerazz)
  • Claude-Ablehnungssignal – Der claude_local-Adapter gibt bei einer stop_reason-Ablehnung ein errorCode von claude_refusal aus, sodass Ablehnungen als erstklassiges Ergebnis behandelt werden. (#8314, @uky333)
  • Claude 4.5-Modellaliase - claude_local verwendet jetzt direkte 4.5-Modellaliase. (#3800, @LeonSGP43)
  • Agent-ID-Header für claude_local – claude_local stempelt die Agent-ID über einen X-Anthropic-Agent-Id-Header. (#8322, @zenprocess)
  • Sauberere Agentenkonfiguration und Unternehmenskopie – Die Umgebungsauswahl für die Agentenkonfiguration ist sauberer, die Unternehmenserstellungskopie wird aktualisiert und die Adaptertestschaltfläche testet nur (keine versehentlichen Speicherungen). (#8504, #8653, #8405, @cryppadotta)
  • Agent-Konfigurationsprüfung für günstiges Modell – Agent-Konfigurationsprüfungen werden jetzt mit einem günstigen Modell getestet, sodass bei der Validierung einer Konfiguration keine Premium-Token verbrannt werden. (#8632, @cryppadotta)

Korrekturen

  • Mobiler Problem-Chat – Der Problem-Chat-Abstand auf Mobilgeräten, der Erwähnungswarnungsabstand und der horizontale Bildlauf im Ansichtsfenster auf kleinen Bildschirmen wurden korrigiert. (#8493, #8486, #8370, @cryppadotta)
  • Scrollposition bei der Vorwärts-/Rückwärtsnavigation – Der Hauptinhaltsbereich stellt jetzt seine Scrollposition bei der Vorwärts-/Rückwärtsnavigation des Browsers wieder her. (#8636, @devinfoley)
  • UI-Detailregressionen – Eine Reihe von Issue-Detail- und Rich-Object-Regressionen wurden behoben, einschließlich generischer URL-Rich-Object-Bezeichnungen. (#8613, #8662, @cryppadotta)
  • Synchronisierung der Secret-Ref-Bindung – Die Secret-Referenzbindung der obersten Ebene bleibt jetzt synchron und Agent-Secret-Bindungen werden über Lebenszyklusflüsse hinweg erzwungen, sodass ein neu zugewiesener oder erneut ausgeführter Agent immer die richtigen Secrets sieht. (#8630, #8307, @cryppadotta)
  • Sandbox-Wiederherstellung und -Veröffentlichung – Sandbox-Wiederherstellungsindexdrift, Sandbox-Git-Veröffentlichung, große Arbeitsbereich-Uploads behoben und vorübergehende Codex-Home-Verzeichnisse von der Sandbox-Synchronisierung ausgeschlossen. (#8595, #8422, #8581, @cryppadotta)
  • Daytona-Festplatte und -Ressourcen – Daytona-Sandboxes archivieren standardmäßig automatisch, sodass sie das Festplattenkontingent belassen, Ressourcenüberschreibungen funktionieren für Image-gestützte Sandboxes und das Env-Konfigurationsformular akzeptiert gültige Speichereingaben mit Größenvoreinstellungen. (#8561, #8564, #8389, @cryppadotta)
  • Intelligentere Wiederherstellung - Die Wiederherstellung gestrandeter Probleme wandelt Fortsetzungen, die aufgrund von Überprüfungen geparkt wurden, in Abhängigkeitswartezeiten um und befreit routinemäßige übergeordnete Probleme von der Übergabe aufgrund fehlender Disposition, sodass Agenten nicht von rechtmäßig wartenden Aufgaben abgezogen werden. (#8371, @cryppadotta; #8157, @BuyWhere)
  • Abgebrochene untergeordnete Blocker werden ignoriert – Aufmerksamkeitsberechnungen ignorieren jetzt abgebrochene untergeordnete Blocker, sodass eine abgebrochene Unteraufgabe ihre übergeordnete Aufgabe nicht mehr hängen lässt. (#7577, @MrBlackTongue)
  • Leseberechtigung für Probleme – Kommentare zu einzelnen Ausgaben und Listen mit Ausgabethreads erzwingen jetzt eine Leseberechtigung, und Kommentare zu geschlossenen Ausgaben mit Erwähnung berücksichtigen die Absicht des Lebenslaufs. (#8346, #8331, #8350, @nickyleach)
  • Härtung der CEO-Berechtigung – Die CEO-Berechtigung des gleichen Unternehmens ist gegen unternehmensübergreifenden Zugriff geschützt. (#8276, @cryppadotta)
  • Isolierte Remote-Claude-Konfiguration – Die Remote-Claude-Konfiguration ist von lokalen Anmeldeinformationen isoliert, sodass ein Claude-Lauf in einer Sandbox Ihre Host-Anmeldung nicht abrufen kann. (#7676, @lennies)
  • Socket-Härtung für Live-Events – Upgrade-Sockets für Live-Events sind gegen fehlerhafte Upgrades gehärtet. (#8383, @cryppadotta)
  • Gemini-Headless-Störungen - Problem behoben, bei dem der Headless-Gemini-Aufruf ins Stocken geriet. (#8368, @chekos)
  • Cursor-Streaming-Text – Der cursor-Adapter fügt gestreamten Assistententext in saubere Prosablöcke zusammen. (#8544, @seb-veto)
  • OpenClaw Gateway-Root-Parameter – Das OpenClaw Gateway leitet keine Root-Paperclip-Parameter mehr weiter. (#4416, @serenakeyitan)
  • Benutzeroberfläche für die Erstellung und Einstellung von Agenten – Die leere Seite beim Erstellen eines Agenten wurde behoben und Einstellungsgenehmigungen im Posteingang werden jetzt gelöscht, wenn auf der Detailseite eine Genehmigung oder Kündigung erfolgt. (#8336, #8340, @cryppadotta)
  • Routine-Zeitplan-Editor – Der Routine-Zeitplan-Editor ist stabilisiert, einschließlich der Beschriftungen für unterbrochene Läufe. (#8333, @cryppadotta)
  • Schaltflächen zum Kopieren über HTTP – Schaltflächen zum Kopieren von Problemen funktionieren wieder, wenn sie über einfaches HTTP bereitgestellt werden. (#8212, @joegalbert-ai)
  • Neue Arbeitsbäume verfolgen Ursprung/Master – Neue Arbeitsbäume basieren auf origin/master und nicht gestartete Wiederverwendungen werden aktualisiert, sodass Ausführungsarbeitsbereiche nicht mit veraltetem Code beginnen. (#8412, @cryppadotta)
  • Dauerhafte Agentenpause – Die Agentenpause bleibt jetzt beim Ausführungsstart dauerhaft. (#8317, @Tattoofamily)
  • CLI-Board-Authentifizierung – Der CLI behandelt einen Headless-Browser-Öffnungsfehler während der Board-Authentifizierung, anstatt zu hängen. (#8328, @AayushThakur1999)
  • Pipelines-Installation - Interne Grundlagenarbeiten für mehrstufige Pipeline-Fälle, die unter der Haube gelandet sind (Stufen, Fallübergänge, Drifterkennung); Es handelt sich noch nicht um eine benutzerorientierte Oberfläche. (#7903, @cryppadotta)

paperclip v2026.626.0

Paperclip v2026.626.0

Released: 2026-06-26

This release lands 122 commits from 17 contributors.

Highlights

  • Hermes, now built in (local & remote gateway) - Hermes is a first-class adapter in this release. Hire hermes_local agents that run on your own machine, or hermes_gateway agents that run Hermes remotely through a gateway — no manual plugin install required, with secure onboarding defaults for the gateway URL and API key. External Hermes packages can still override or shadow the built-ins through Adapter manager. (#8543, @cryppadotta)
  • Task watchdogs - A first-class watchdog control plane lets you attach automated checks to a task and have Paperclip watch it for you — surfacing watchdog state, outcomes, and outstanding work right in the issue thread instead of leaving you to babysit a long-running agent. (#8339, @cryppadotta)
  • Ask work mode - Issues can now run in an "ask" work mode for question-and-answer tasks, so you can point an agent at a question and get an answer back without it spinning up a full execution workflow. (#8334, @cryppadotta)
  • Sandbox runtime status, live in your threads - Ephemeral sandbox runtimes now report their status directly in issue threads, and Daytona sandbox leases are reused across runs — so cloud/sandboxed execution is both more visible and faster to spin up. (#8594, #8593, @devinfoley; #8513, @devinfoley)
  • Workspace file downloads & external object references - Get work products out of Paperclip: download the files your agents produced straight from the workspace, and reference external objects (links, assets) across issue surfaces so the right context travels with the task. (#8512, #8229, @cryppadotta)

Improvements

  • Refreshed onboarding - The onboarding flow has been reworked and the older classic wizard retired, alongside a batch of UI style fixes — so getting a new instance set up is cleaner and the default task UI (work-mode labels, status colors, team-creation copy) is consistent out of the box. (#8628, @cryppadotta)
  • Task status icons & colors - Task status now reads at a glance with dedicated icons and colors across the board and issue lists. (#8580, @scotttong; #8376, @tonio-alucema)
  • Routine date variables - Routines gain date variable controls, so a recurring routine can parameterize on the run date without hand-editing the prompt each time. (#8655, @cryppadotta)
  • Skill category editing - You can now edit skill categories in settings, making it easier to organize an installed skill catalog. (#8615, @cryppadotta)
  • Publish Paperclip pages & capsules - A bundled page-publishing skill lets agents publish static HTML pages and asset folders to an approved host, and a bundled capsules skill ships the Paperclip capsule identicon toolkit. (#8664, #8669, @cryppadotta)
  • Bounded workspace overview - The workspace overview endpoint is now bounded, dramatically cutting the payload and latency for instances with large workspaces. (#8627, @cryppadotta)
  • Streamlined sidebar by default - The streamlined sidebar is now the default layout. (#8496, @devinfoley)
  • Sorted workspace routines - Workspace routines are now sorted by name, so the routine list stays predictable. (#8666, @cryppadotta)
  • Plugin install targeting - The CLI surfaces the plugin install target host and adds a plugin target command, so you always know which instance a plugin is being installed into. (#8575, @cryppadotta)
  • Better workspace selector search - The reusable workspace selector gets improved search, making it quicker to pick the right workspace. (#8597, @cryppadotta)
  • Instance-scoped execution environments - Execution environments are now instance-scoped and edited through a dialog, with cleaner copy and a tidier driver dropdown on the Company Environments screen. (#8375, #8391, #8400, #8398, #8329, @cryppadotta)
  • Heartbeat preflight budget caps - Heartbeats now respect preflight budget caps, giving you a hard ceiling on what a single wake can spend. (#8347, @levineam)
  • Skill mutations gated by permission - Skill create/edit/delete is now gated behind a dedicated skills:create permission, so lower-privileged principals can browse skills without being able to change them. (#8616, @cryppadotta)
  • Observable sandbox sync progress - Adapter utilities can now report sandbox sync progress, so long file syncs into a sandbox are no longer a black box. (#8395, @cryppadotta)
  • Codex local inherits host login - codex_local agents inherit the host Codex login by default and seed managed auth into isolated homes, so they work without re-authenticating. (#8425, #8403, @cryppadotta)
  • Codex local inactivity monitor - The codex_local adapter now monitors output inactivity and prefers the loopback runtime API URL for local agents, improving reliability of long local runs. (#5017, #5102, @neerazz)
  • Claude refusal signal - The claude_local adapter emits an errorCode of claude_refusal on a stop_reason refusal, so refusals are handled as a first-class outcome. (#8314, @uky333)
  • Claude 4.5 model aliases - claude_local now uses direct 4.5 model aliases. (#3800, @LeonSGP43)
  • Agent id header for claude_local - claude_local stamps the agent id via an X-Anthropic-Agent-Id header. (#8322, @zenprocess)
  • Cleaner agent config & company copy - The agent config environment selector is cleaner, the company creation copy is refreshed, and the adapter test button only tests (no accidental saves). (#8504, #8653, #8405, @cryppadotta)
  • Cheap-model agent config check - Agent configuration checks now test with a cheap model, so validating a config doesn't burn premium tokens. (#8632, @cryppadotta)

Fixes

  • Mobile issue chat - Fixed issue-chat spacing on mobile, the mention warning spacing, and horizontal viewport scroll on small screens. (#8493, #8486, #8370, @cryppadotta)
  • Scroll position on back/forward - The main content area now restores its scroll position on browser back/forward navigation. (#8636, @devinfoley)
  • UI detail regressions - A batch of issue-detail and rich-object regressions are fixed, including generic URL rich-object labels. (#8613, #8662, @cryppadotta)
  • Secret ref binding sync - Top-level secret reference binding now stays in sync, and agent secret bindings are enforced across lifecycle flows so a reassigned or re-run agent always sees the right secrets. (#8630, #8307, @cryppadotta)
  • Sandbox restore & publishing - Fixed sandbox restore index drift, sandbox git publishing, large workspace uploads, and excluded transient Codex home dirs from sandbox sync. (#8595, #8422, #8581, @cryppadotta)
  • Daytona disk & resources - Daytona sandboxes default to auto-archive so they leave the disk quota, resource overrides work for image-backed sandboxes, and the env config form accepts valid memory input with size presets. (#8561, #8564, #8389, @cryppadotta)
  • Smarter recovery - Stranded-issue recovery converts review-parked continuations into dependency waits and exempts routine-parent issues from missing-disposition handoff, so agents aren't yanked off legitimately-waiting work. (#8371, @cryppadotta; #8157, @BuyWhere)
  • Cancelled child blockers ignored - Attention calculations now ignore cancelled child blockers, so a cancelled subtask no longer keeps its parent stuck. (#7577, @MrBlackTongue)
  • Issue read authorization - Single-issue comments and issue-thread lists now enforce read authorization, and mention-granted closed-issue comments respect resume intent. (#8346, #8331, #8350, @nickyleach)
  • CEO authorization hardening - Same-company CEO authorization is hardened against cross-company access. (#8276, @cryppadotta)
  • Isolated remote Claude config - Remote Claude config is isolated from local credentials, so a sandboxed Claude run can't pick up your host login. (#7676, @lennies)
  • Live events socket hardening - Live-events upgrade sockets are hardened against malformed upgrades. (#8383, @cryppadotta)
  • Gemini headless stalls - Fixed headless Gemini invocation stalls. (#8368, @chekos)
  • Cursor streamed text - The cursor adapter coalesces streamed assistant text into clean prose blocks. (#8544, @seb-veto)
  • OpenClaw Gateway root params - The OpenClaw Gateway no longer forwards root Paperclip params. (#4416, @serenakeyitan)
  • Agent creation & hire UI - Fixed the blank page when creating an agent, and inbox hire approvals now clear when approving or terminating from the detail page. (#8336, #8340, @cryppadotta)
  • Routine schedule editor - The routine schedule editor is stabilized, including interrupted-run labels. (#8333, @cryppadotta)
  • Copy buttons over HTTP - Issue copy buttons work again when served over plain HTTP. (#8212, @joegalbert-ai)
  • Fresh worktrees track origin/master - New worktrees are based on origin/master and unstarted reuses are refreshed, so execution workspaces don't start from stale code. (#8412, @cryppadotta)
  • Durable agent pause - Agent pause now stays durable at execution-start. (#8317, @Tattoofamily)
  • CLI board auth - The CLI handles a headless browser-open failure during board auth instead of hanging. (#8328, @AayushThakur1999)
  • Pipelines plumbing - Internal groundwork for multi-stage pipeline cases landed under the hood (stages, case transitions, drift detection); it's not a user-facing surface yet. (#7903, @cryppadotta)
