graphify 0.9.106

– Fix: install requires-python ist auf >=3.10,<3.15 begrenzt, sodass uv tool install graphifyy (und Pip) auf einem neuen Computer nicht mehr Python 3.15 auswählt – für das tree-sitter kein Rad hat – und dann mit einem Quellbuild fehlschlägt, der einen C-Compiler benötigt (No such file or directory: 'cc'). uv wählt jetzt standardmäßig einen Wheel-Interpreter (3.14) aus, ohne --python-Flag und ohne Compiler erforderlich. Die Ubuntu/Debian README-Zeile, in der nach python3.12 gefragt wurde (fehlt unter Debian 12 und Ubuntu 22.04), wird durch das UV-Installationsprogramm oder eine einfache python3/pipx-Zeile ersetzt (#5134).

  • Fix: cpp eine einfache Klassen-/Struktur-Forward-Deklaration wird in ihre eindeutige, genau qualifizierte Definition eingefügt, wenn eine Datei die andere über bedingungslose, exakt in Anführungszeichen gesetzte Includes erreicht, und eine Parameterlose Member-Deklaration wird in ihre bewährte Out-of-Line-Definition eingefügt, indem Rückgabetyp und Qualifikationsmerkmale abgeglichen werden; Überladungen, Vorlagen, bedingte Deklarationen und unbewiesene Includes bleiben getrennt (#5117, danke @xRedLeader). – Fix: cpp ein Mitgliedsaufruf wird über einen bereichsbezogenen Typalias (using Alias = ns::Type;) und über geerbte Felder/Methoden aufgelöst, und ein vorwärts deklarierter Pointee-Typ wird am Verwendungsstandort vervollständigt; Mehrdeutige, virtuelle oder Diamond-vererbte Empfänger schlagen fehl (#5118, danke @xRedLeader).
  • Fix: cpp, ein Out-of-Line-Vorlagenmitglied behält seinen bewährten Besitzer der primären Vorlage und Aufrufe innerhalb eines #if-geschützten Initialisierers oder einer Argumentliste werden aus byteerhaltenden Zweigansichten wiederhergestellt (begrenzt, fehlgeschlagen, wenn fehlerhafte Eingaben/über das Budget hinausgehende Eingaben erfolgen); Abhängige Empfänger bleiben ungelöst (#5115, danke @xRedLeader).
  • Fix: python eine gepunktete tiefgestellte Annotation (mod.MyBox[Foo]) zählt ihren Wert einmal als Typ und nicht auch als eigenes generisches Argument, sodass die falsche generic_arg-Referenz nicht mehr die echte parameter_type/return_type-Kante ersetzt (#5113, danke @rohit-jsfreaky).
  • Fix: ts/js ein Aufruf über einen ESM-Namespace-Import (import * as ns from './m'; ns.f()), eine CommonJS-Gesamtmodulanforderung (const m = require('./m'); m.f()) oder einen TS import = require wird in die echte Deklaration aufgelöst; Fail-Closed bei einem unbekannten Modul, einem nicht exportierten Namen oder einem mehrdeutigen Barrel (#5114, #5129, danke @mohitdixit02).
  • Fix: llm eine vorberechnete FileSlice-Eingabe wird durch extract_corpus_parallel beibehalten, anstatt abzustürzen oder ein teilweises übergeordnetes Element als vollständig zu stempeln; Ein Slice, das nur einen Teil seiner Datei abdeckt, markiert den übergeordneten Teil zum erneuten Versand (#5106, #5128, danke @aadilrizwan). – Fix: Abfrage BFS durchläuft Ebenen in einer festen, Hash-unabhängigen Reihenfolge, sodass die Randlinien einer Abfrage (und die das Token-Budget überleben) nicht mehr mit PYTHONHASHSEED variieren (#5109, #5112, danke @rohit-jsfreaky).
  • Feat: Abfrage --no-doc-demotion (und der demote_docs-RC-Schlüssel / MCP-Arg) deaktiviert die weiche Gewichtung „Source-over-Docs“ für einen Docs-First-Korpus; Codekorpora sind standardmäßig nicht betroffen (#5084, #5116, danke @mohitdixit02).
  • Leistung: Auflösung _collision_aware indiziert gesalzene Geschwister-IDs einmal, anstatt alle Knoten pro Verwendung erneut zu scannen, wodurch die Auflösungszeit bei großen kollisionsintensiven Korpora verkürzt wird (Grafikausgabe byteidentisch) (#5108, #5111, danke @rohit-jsfreaky).
  • Fix: Manifest eines pom.xml mit einem vorangestellten, in einfache Anführungszeichen oder Leerzeichen gesetzten xmlns behält sein Maven-Paket und seine Abhängigkeitsknoten, anstatt sie zu verlieren; Ein fremder Namespace wird nicht doppelt gezählt (#5126, danke @sdivyanshu90).
  • Fix: merge-graphs graphify merge-graphs meldet, wie viele externe Knoten über Repos hinweg vereint wurden, anstatt sie stillschweigend zu übernehmen; Das Zusammenführungsergebnis bleibt unverändert (#5127, danke @igorpugatschev).
  • Fix: Diagnose diagnose_extraction stürzt nicht mehr bei einem fehlerhaften nodes-Container (null oder skalar) ab; Die fehlerhafte Extraktion wird immer noch durch den Build-Fehler angezeigt (#5125, danke @sdivyanshu90).
  • Fix: html Das interaktive Diagramm zeichnet keinen Hyperedge-Bereich mehr über Mitgliedern, die durch einen Community-Schalter ausgeblendet wurden. Eine Region verschwindet, sobald weniger als zwei ihrer Mitglieder sichtbar bleiben (#5122, danke @Yi-111-a). Das AST-Cache-Schema wird auf 43 erhöht; Warme Caches führen die betroffenen Python- und C++-Extraktionen erneut aus.

Englisches Original / English original

graphify v0.9.106

graphify 0.9.106

  • Fix: install requires-python is capped to >=3.10,<3.15, so uv tool install graphifyy (and pip) on a fresh machine no longer selects Python 3.15 — for which tree-sitter has no wheel — and then fails with a source build that needs a C compiler (No such file or directory: 'cc'). uv now picks a wheel-having interpreter (3.14) by default, with no --python flag and no compiler needed. The Ubuntu/Debian README line that asked for python3.12 (absent on Debian 12 and Ubuntu 22.04) is replaced with the uv installer or a plain python3/pipx line (#5134).
  • Fix: cpp a plain class/struct forward declaration folds into its unique exactly-qualified definition when one file reaches the other through unconditional exact quoted includes, and a parameterless member declaration folds into its proven out-of-line definition by matching return type and qualifiers; overloads, templates, conditional declarations and unproven includes stay separate (#5117, thanks @xRedLeader).
  • Fix: cpp a member call resolves through a scoped type alias (using Alias = ns::Type;) and through inherited fields/methods, and a forward-declared pointee type is completed at the use site; ambiguous, virtual or diamond-inherited receivers fail closed (#5118, thanks @xRedLeader).
  • Fix: cpp an out-of-line template member keeps its proven primary-template owner, and calls inside a #if-guarded initializer or argument list are recovered from byte-preserving branch views (bounded, fail-closed on malformed/over-budget input); dependent receivers stay unresolved (#5115, thanks @xRedLeader).
  • Fix: python a dotted subscript annotation (mod.MyBox[Foo]) counts its value once as the type instead of also as its own generic argument, so the false generic_arg reference no longer replaces the real parameter_type/return_type edge (#5113, thanks @rohit-jsfreaky).
  • Fix: ts/js a call through an ESM namespace import (import * as ns from './m'; ns.f()), a CommonJS whole-module require (const m = require('./m'); m.f()), or a TS import = require resolves to the real declaration; fail-closed on an unknown module, a non-exported name, or an ambiguous barrel (#5114, #5129, thanks @mohitdixit02).
  • Fix: llm a precomputed FileSlice input is preserved through extract_corpus_parallel instead of crashing or stamping a partial parent complete; a slice that covers only part of its file marks the parent partial for re-dispatch (#5106, #5128, thanks @aadilrizwan).
  • Fix: query BFS walks levels in a fixed, hash-independent order, so a query's edge lines (and which survive the token budget) no longer vary with PYTHONHASHSEED (#5109, #5112, thanks @rohit-jsfreaky).
  • Feat: query --no-doc-demotion (and the demote_docs rc key / MCP arg) disables the source-over-docs soft weight for a docs-first corpus; code corpora are unaffected by default (#5084, #5116, thanks @mohitdixit02).
  • Perf: resolution _collision_aware indexes salted sibling ids once instead of rescanning all nodes per use, cutting resolution time on large collision-heavy corpora (graph output byte-identical) (#5108, #5111, thanks @rohit-jsfreaky).
  • Fix: manifest a pom.xml using a prefixed, single-quoted or spaced xmlns keeps its Maven package and dependency nodes instead of losing them; a foreign namespace is not double-counted (#5126, thanks @sdivyanshu90).
  • Fix: merge-graphs graphify merge-graphs reports how many external nodes were unified across repos instead of silently absorbing them; the merge result is unchanged (#5127, thanks @igorpugatschev).
  • Fix: diagnostics diagnose_extraction no longer crashes on a malformed nodes container (null or scalar); the malformed extraction is still surfaced through the build error (#5125, thanks @sdivyanshu90).
  • Fix: html the interactive graph no longer draws a hyperedge region over members hidden by a community toggle; a region vanishes once fewer than two of its members stay visible (#5122, thanks @Yi-111-a).

The AST cache schema is bumped to 43; warm caches re-run the affected Python and C++ extractions.
