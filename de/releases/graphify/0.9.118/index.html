graphify v0.9.118

Eine Reihe von Korrekturen für Extraktor, Auflösung, Bereitstellung, Export, Clustering und Berichterstellung für vierzehn Community-Pull-Anfragen. Die Objective-C-, C- und C#-Änderungen verändern die Node-/Edge-Ausgabe, sodass das AST-Cache-Schema ansteigt (51 auf 53) und der erste Build nach dem Upgrade die betroffenen Sprachen erneut extrahiert; Die anderen Korrekturen müssen nicht neu erstellt werden.

  • Behebung: csharp ein lokaler Parameter oder ein Feld namens partial, required, async, nint, nuint oder with (kontextbezogene Schlüsselwörter), das der Baumsitter c-sharp falsch analysiert, wo eine Anweisung damit beginnt, entgleist die Datei nicht mehr; Es wird vor dem Parsen in seine wörtliche @name-Form umgeschrieben (Beibehaltung der Bytelänge), sodass der einschließende Typ und die darauf folgenden Mitglieder beibehalten werden, anstatt stillschweigend gelöscht zu werden (#5043, danke @ThatAblaze).
  • Fix: c ein Aufruf über ein Struktur-Funktionszeigerfeld (ops->run(), ops.run()) erzeugt keine calls-Kante mehr zu einer gleichnamigen freien Funktion; Der Feldname ist kein Hinweis auf das Laufzeitziel des Zeigers, daher wird die Vermutung verworfen. Ein einfacher direkter Anruf wird immer noch aufgelöst (#5410, danke @sdivyanshu90).
  • Fix: objc eine Objective-C-Methode, deren Name sich auf die ID eines Geschwisters innerhalb eines @interface/@implementation/@protocol (ein führender/nachgestellter _ wie in -setup/-_setup oder ein Unterschied nur zwischen Groß- und Kleinschreibung) faltet, erhält seine eigene gesalzene Knoten-ID, anstatt sie zu überschreiben; Die Deklaration und Definition einer Methode teilen sich immer noch einen einzigen Knoten (#5390, danke @ayushcodes10). – Fix: go Der Eigentümertyp eines Strukturfelds ist auf sein eigenes Paket beschränkt, sodass ein Feld eines Typs, dessen Name in zwei Paketen deklariert ist, an das richtige Paket gebunden wird und seine Mitgliedsaufrufe „resolve“ aufruft, anstatt als mehrdeutig verworfen zu werden (#5408, danke @azizur100389).
  • Fix: Extrahieren eines Svelte-Imports, der über ein export *-Lauf erfolgt, wird jetzt in das eigentliche definierende Modul aufgelöst, das dem einfachen .ts entspricht. Der dateiübergreifende Resolver maskierte .vue, aber nicht .svelte, sodass die Svelte <script>-Importe aufgrund eines Vorlagenanalysefehlers verloren gingen. Angekettete Fässer lösen sich auf und unklare Reexporte scheitern geschlossen. Führen Sie graphify extract . --force einmal aus, um ein bereits zwischengespeichertes Diagramm zu reparieren (#5403, danke @Max17190).
  • Korrektur: Audio- und Videodateien extrahieren, die erkannt, aber nicht extrahiert wurden (Headless-Extrakt hat keinen Transkriptionsschritt), werden jetzt in der Zusammenfassung gemeldet, anstatt stillschweigend zu verschwinden, passend zu den anderen Übersprungshinweisen; Für sie werden keine Knoten erstellt (#5076, danke @ayushcodes10). – Fix: Abschnitte Beim Wiederholungsversuch von get_section wird der Trigramm-Suchindex des vollständigen Diagramms nicht mehr wiederverwendet. Der Wiederholungsversuch wurde für eine Netzwerk-Subgraph-Ansicht ausgeführt, deren .graph-Dikt das gleiche Objekt ist, auf dem der Index zwischengespeichert wird. Daher hat der Wiederholungsversuch nach veralteten IDs außerhalb des Abschnitts gesucht und KeyError ausgelöst. Die Wiederholungsansicht erhält jetzt ihre eigenen Diagrammmetadaten, wodurch auch die Gefahr der Indexbeschädigung gemeinsamer Diagramme für gleichzeitige Serveraufrufer beseitigt wird (#5385, danke @Deepjyoti-Sarmah). – Fix: serve der MCP-Server lädt graph.json aus der Ereignisschleife, sodass ein großes Neuladen des Diagramms gleichzeitige Anforderungen nicht mehr blockiert; Eine Anfrage während eines Neuladens wird dem aktuellen Diagramm zugestellt und ein beschädigtes Neuladen lässt das alte Diagramm intakt (#5371, danke @Deepjyoti-Sarmah).
  • Fix: Aktualisieren ein geclusterter GRAPH_REPORT.md, der gelöscht wird, während das Diagramm ansonsten unverändert bleibt, wird neu generiert, anstatt vom No-Change-Gate übersprungen zu werden; Das Diagramm selbst bleibt byteidentisch (aus dem Partitionscache wiederhergestellt), sodass kein unnötiger Neuaufbau erforderlich ist (#5402, danke @Max17190). – Fix: Abfrage-Bildknoten werden in der Seed-Bewertung zusammen mit Dokumenten und Dokumenten herabgestuft, sodass ein Bild mit vielen Bildunterschriften nicht mehr den echten Code für eine Abfrage übertrifft, deren Begriffe sich wiederholen (#445, danke @ayushcodes10).
  • Fix: Export-Exportdateinamen berücksichtigen den NAME_MAX des Zieldateisystems (geprüft über pathconf, nicht als 255 angenommen), sodass graphify export obsidian/wiki/canvas nicht mehr mit ENAMETOOLONG auf Dateisystemen abbricht, die einen unteren Grenzwert melden, wie z. B. eCryptfs (143); Lange Namen werden mit einem Hash-Suffix gekürzt und interne Links verwenden die gekürzten Namen (#2109, danke @Synvoya).
  • Fix: Wiki-Exporte gerichteter Diagramme umfassen jetzt eingehende Kanten, sodass ein Community-Audit nicht mehr die Zuverlässigkeit unterschätzt (eine eingehende MEHRDEUTIGE Kante könnte unsichtbar sein, während auf der Seite „100 % EXTRAHIERT“ angezeigt wird). Auf God-Node-Seiten sind eingehende Kanten mit (incoming) gekennzeichnet, sodass eine Beziehung wie calls nicht rückwärts gelesen wird (#5369, danke @sdivyanshu90).
  • Fix: config .graphifyrc analysiert jetzt demote_docs / query_demote_docs, sodass ein Projekt die Herabstufung von Dokumenten in der RC-Datei festlegen kann, anstatt nur über das CLI-Flag; ein explizites Flag überschreibt es immer noch (#5290, danke @debojyoti10CC).
  • Leistung: Cluster-Community-Überlappungszählung während eines Neuaufbaus wird aus gemeinsam genutzten Knoten in einem Durchgang berechnet, anstatt jedes Community-Paar zu schneiden, wodurch ein O-Schritt (Communitys im Quadrat) in einen linearen Schritt mit byteidentischen Ergebnissen umgewandelt wird (#5382, danke @Max17190).

Englisches Original / English original

graphify v0.9.118

A batch of extractor, resolution, serve, export, clustering and reporting fixes across fourteen community pull requests. The Objective-C, C and C# changes alter node/edge output, so the AST cache schema bumps (51 to 53) and the first build after upgrading re-extracts the affected languages; the other fixes need no rebuild.

  • Fix: csharp a local, parameter or field named partial, required, async, nint, nuint or with (contextual keywords) that tree-sitter-c-sharp mis-parses where a statement starts with it no longer derails the file; it is rewritten to its verbatim @name form before parsing (byte-length preserving), so the enclosing type and the members after it are kept instead of being silently dropped (#5043, thanks @ThatAblaze).
  • Fix: c a call through a struct function-pointer field (ops->run(), ops.run()) no longer fabricates a calls edge to a same-named free function; the field name is no evidence of the pointer's runtime target, so the guess is dropped. A plain direct call still resolves (#5410, thanks @sdivyanshu90).
  • Fix: objc an Objective-C method whose name folds onto a sibling's id within one @interface/@implementation/@protocol (a leading/trailing _ as in -setup/-_setup, or a case-only difference) gets its own salted node id instead of overwriting it; the declaration and definition of one method still share a single node (#5390, thanks @ayushcodes10).
  • Fix: go a struct field's owner type is scoped to its own package, so a field of a type whose name is declared in two packages binds to the right one and its member calls resolve instead of being dropped as ambiguous (#5408, thanks @azizur100389).
  • Fix: extract a Svelte import that comes through an export * barrel now resolves to the real defining module, matching plain .ts. The cross-file resolver was masking .vue but not .svelte, so the Svelte <script> imports were lost to a template parse error; chained barrels resolve and ambiguous re-exports fail closed. Run graphify extract . --force once to repair an already-cached graph (#5403, thanks @Max17190).
  • Fix: extract audio and video files that are detected but not extracted (headless extract has no transcription step) are now reported in the summary instead of silently vanishing, matching the other skip notices; no nodes are fabricated for them (#5076, thanks @ayushcodes10).
  • Fix: sections get_section's retry no longer reuses the full graph's trigram search index. The retry ran against a networkx subgraph view whose .graph dict is the same object serve caches the index on, so the retry searched stale, out-of-section ids and raised KeyError; the retry view now gets its own graph metadata, which also removes a shared-graph index-corruption hazard for concurrent serve callers (#5385, thanks @Deepjyoti-Sarmah).
  • Fix: serve the MCP server loads graph.json off the event loop, so a large graph reload no longer blocks concurrent requests; a request during a reload is served the current graph and a corrupt reload leaves the old graph intact (#5371, thanks @Deepjyoti-Sarmah).
  • Fix: update a clustered GRAPH_REPORT.md that is deleted while the graph is otherwise unchanged is regenerated instead of being skipped by the no-change gate; the graph itself is left byte-identical (restored from the partition cache) so there is no needless rebuild (#5402, thanks @Max17190).
  • Fix: query image nodes are demoted in seed scoring alongside documents and papers, so a caption-rich image no longer out-seeds real code for a query whose terms it happens to repeat (#445, thanks @ayushcodes10).
  • Fix: export export filenames honor the target filesystem's NAME_MAX (probed via pathconf, not assumed to be 255), so graphify export obsidian/wiki/canvas no longer aborts with ENAMETOOLONG on filesystems that report a lower limit such as eCryptfs (143); long names are truncated with a hash suffix and internal links use the shortened names (#2109, thanks @Synvoya).
  • Fix: wiki directed-graph exports now include incoming edges, so a community audit no longer under-reports confidence (an incoming AMBIGUOUS edge could be invisible while the page read "EXTRACTED 100%"). On god-node pages incoming edges are marked (incoming) so a relation like calls is not read backwards (#5369, thanks @sdivyanshu90).
  • Fix: config .graphifyrc now parses demote_docs / query_demote_docs, so a project can set doc demotion in the rcfile instead of only via the CLI flag; an explicit flag still overrides it (#5290, thanks @debojyoti10CC).
  • Perf: cluster community-overlap counting during a rebuild is computed from shared nodes in one pass instead of intersecting every pair of communities, turning an O(communities squared) step into a linear one with byte-identical results (#5382, thanks @Max17190).
