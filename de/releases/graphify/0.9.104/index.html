graphify 0.9.104

– Sicherheit: Skill Das /graphify-Runbook ersetzt den Scanpfad nicht mehr im Python-Code. Jeder generierte Codeblock (Erkennung, AST und semantische Extraktion, Build, Diagnose, Label, Manifest und --update) liest jetzt den aufgelösten Scan-Root aus dem trusted graphify-out/.graphify_root-Sidecar, den Schritt 1 über ein in Anführungszeichen gesetztes Heredoc schreibt, anstatt den vom Agenten bereitgestellten Pfad in ein Zeichenfolgenliteral einzufügen. Ein Verzeichnis, dessen Name ein Anführungszeichen oder $(...) enthielt, konnte zuvor aus Path('INPUT_PATH') ausbrechen und als Code ausgeführt werden; es wird jetzt als inerte Daten gelesen. Deckt die zusammengebauten Hosts und die Aider/Devin-Monolithen ab (#4762, danke @danikdanik).

  • Fix: Solidität ein Aufruf an einen Empfänger eines Vertrags- oder Schnittstellentyps (IERC20 token; token.transfer(), IERC20(a).transfer(), token().balanceOf()) bindet nach Name und Arität durch die Linearisierung dieses Typs an die eigene Deklaration des Typs, anstatt keine Kante zu erzeugen; auf einen einzelnen sichtbaren Vertrag/eine einzelne sichtbare Schnittstelle beschränkt und bei einem unbekannten oder mehrdeutigen Typ fehlgeschlagen (#5060, danke @rohit-jsfreaky).
  • Fix: Solidität ein durch eine using A for T-Direktive (using SafeCast for uint256; x.toUint48()) angehängter Aufruf bindet an die Bibliothek oder freie Funktion, die er anfügt, angepasst an den Typ des Empfängers und eine um eins größere Arität als der Aufruf; Fail-Closed, wenn der Empfängertyp unbekannt ist, die Bibliothek nicht eindeutig ist oder zwei Funktionen passen (#5062, danke @rohit-jsfreaky). – Fix: Solidity-Mitglieder, freie Funktionen und Typen in einem Bereich, deren Namen sich nur durch ein führendes _ oder durch die Groß-/Kleinschreibung (_grantRole / grantRole) unterscheiden, erhalten separate Knoten-IDs, sodass das _-Symbol nicht mehr in seinem Zwilling verschwindet und seine Aufrufe auf dem richtigen Knoten landen (#5027, danke @rohit-jsfreaky).
  • Fix: csharp ein Konstruktor (Instanz, statisch oder primär) ist ein eigener Knoten, der seinem Typ gehört, wobei sein Hauptteil und die : base(...)/: this(...)-Aufrufe ihm gutgeschrieben werden; new X(...), : base(...) und : this(...) verknüpfen die aritätskorrekte Überladung additiv, und zwei passende Überladungen oder eine unaufgelöste Basis ergeben keinen Konstruktorvorteil (#5054, danke @rohit-jsfreaky). – Fix: csharp-Aufrufe innerhalb eines Eigenschafts- oder Indexer-Accessors, eines Ausdruckskörpers oder eines Operator-/Konvertierungskörpers werden diesem Mitglied gutgeschrieben, anstatt verloren zu gehen; Ein Indexer wird zu einem this[]-Knoten und ein Operator zu einem .operator +()-Knoten (#5056, danke @rohit-jsfreaky). – Fix: Abfragen eines Knotens mit demselben Label, der die einzige Übereinstimmung für einen Abfragebegriff darstellt, wird als Startwert beibehalten, anstatt durch die Obergrenze pro Label gelöscht zu werden, sodass jeder eindeutige Begriff mindestens einen Startwert behält, während die Überflutung mit generischen Labels begrenzt bleibt (#5027, danke @Vaibhav2824).
  • Fix: Nur-Lese-Ereignisse vom Typ watch werden über ein Nur-Änderungs-event_filter von der Inotify-Maske ferngehalten, sodass ein großer Baum den Watchdog nicht mehr in eine sich selbst erhaltende Warteschlangenüberlaufschleife treibt; Fällt bei Watchdog-Versionen ohne event_filter-Unterstützung mit einer Warnung zurück (#5033, danke @Deepjyoti-Sarmah).
  • Fix: Cache der Langpfad-Schreibweise \\?\ wird von der Cache-Identität ferngehalten, sodass dieselbe Datei, die über \\?\C:\... und C:\... erreicht wird, einen Eintrag teilt; Behebt außerdem leere Stat-Index-Schreibvorgänge unter UNC-Freigaben, eine falsche Warnung „Stat-Index gewechselt“ unter Windows und einen Junction-/Symlink-Alias, der den Digest seines Ziels fälschlicherweise teilt (#5035, danke @Bortlesboat). – Fix: Cache-Stat-Index-Schlüssel bleiben root-relativ unter einem Windows-Root mit langem Pfad, sodass ein verschobener oder geklonter Korpus den Fastpath für tragbare Schlüssel behält (#5035, danke @Vaibhav2824). – Fix: testet, dass das TypeScript-Unicode-Fixture auf jeder Plattform als UTF-8 geschrieben ist, sodass Byte-Offsets mit dem Extraktor auf Windows-Hosts (cp1252) übereinstimmen (#5064, danke @ayushcodes10). – Fix: testet, dass der Hook-Freshness-Quellmock durch os_long_path normalisiert wird, sodass der Lesefehler/Veraltungszweig tatsächlich unter Windows ausgeführt wird (#5065, danke @ayushcodes10).
  • Fix: testet den Watch-Pending-Queue-Test und vergleicht Path-Objekte, sodass die Trennzeichen / und \ unter Windows gleich sind (#5039, danke @Yi-111-a).
  • Fix: Extrahieren der Platzhalter-Knoten-ID eines mehrdeutigen Python-Imports wird aus checkout-unabhängigen Daten (Modulname, Scan-Root-relative Quelldatei, Speicherort) anstelle des absoluten Pfads gehasht, sodass dasselbe Projekt an einem anderen Pfad oder in einem verschobenen Cache dieselben IDs erhält (#5045, danke @Fardin7798). – Fix: yaml eine Vorlage, die intrinsische CloudFormation-Tags (!Ref, !GetAtt, !Sub) verwendet, schlägt nicht mehr beim Parsen fehl: Ein bereichsbezogener permissiver Loader baut die Form jedes mit ! markierten Knotens neu auf, ohne sie auszuwerten, während !!python/...-Tags immer noch ausgelöst und nie ausgeführt werden (#5077, danke @ayushcodes10). – Fix: Beobachten, ein inkrementelles --watch-Update erstellt den vollständigen Korpus neu, wenn graph.json fehlt, anstatt nur einen Teilgraphen aus dem Manifest zu schreiben (#5020, danke @azizur100389).
  • Fix: Beobachten Eine Änderung an einer JS/TS-Auflösungseingabe (tsconfig.json, jsconfig.json, eine Sperrdatei) löst eine vollständige Neuerstellung aus, sodass Importeure die neue Auflösung übernehmen, anstatt veraltete imports_from-Kanten zurückzulassen (#5020, danke @azizur100389).
  • Fix: Aufnahme zweier gleichzeitiger graphify add-Captures für dieselbe URL überlasten sich nicht mehr gegenseitig: Die Capture-Datei wird exklusiv erstellt (O_EXCL) und bei einer Kollision wird ein neuer Name erneut versucht, wobei die Nutzlast einmal abgerufen wird (#5020, danke @azizur100389). – Fix: Reflektieren eines fehlerhaften Eintrags im Lern-Overlay wird übersprungen, anstatt den gesamten Ladevorgang zum Absturz zu bringen, und ein alter Nullquelleneintrag wird als quellenlose Anmerkung beibehalten (#5020, danke @azizur100389). – Fix: global ein fehlerhafter Repo-Eintrag im globalen Manifest wird von selbst gelöscht, die anderen verfolgten Repos bleiben erhalten, und nur eine Nicht-Objekt-Root- oder Repos-Map wird gesichert und zurückgesetzt (#5020, danke @azizur100389).
  • Fix: Abfrage eines frisch in einem Unterordner erstellten Diagramms wird nicht mehr als Build vor #1504 gekennzeichnet (was zu einem No-Op-extract --force führte): Das Legacy-ID-Probe entfernt den .graphify_root-Offset, bevor Dateistämme abgeleitet werden, und ein echtes Legacy-Diagramm wird immer noch abgefangen (#5019, danke @neumannpeter1231-lang).
  • Fix: Baum graphify export tree erkennt den Knotenalias src (und file/path/filepath), sodass ein Diagramm, das diese Schlüssel trägt, einen bevölkerten Baum anstelle eines leeren darstellt; Ein reines Konzeptdiagramm meldet immer noch leer (#5030, danke @Adityakk9031).
  • Fix: cli graphify provider add akzeptiert --pricing-input=VALUE/--pricing-output=VALUE-Gleichheitssyntax und lehnt einen nicht numerischen, nicht endlichen oder negativen Preis mit einem sauberen Fehler anstelle eines Tracebacks oder einer verfälschten Kostenschätzung ab (#5031, danke @Adityakk9031). Das AST-Cache-Schema wird auf 40 erhöht; Warme Caches führen die betroffenen Solidity- und C#-Extraktionen erneut aus. Für die oben genannten Korrekturen für Python und YAML ist keine Erhöhung erforderlich (Platzhalter-IDs werden nach dem Cache pro Datei aufgelöst, und zuvor fehlgeschlagene YAML wurden nie zwischengespeichert).

graphify v0.9.104

graphify 0.9.104

  • Security: skill the /graphify runbook no longer substitutes the scan path into Python code. Every generated code block (detect, AST and semantic extraction, build, diagnose, label, manifest, and --update) now reads the resolved scan root from the trusted graphify-out/.graphify_root sidecar that Step 1 writes through a quoted heredoc, instead of pasting the agent-supplied path into a string literal. A directory whose name carried a quote or $(...) could previously break out of Path('INPUT_PATH') and run as code; it is now read as inert data. Covers the assembled hosts and the Aider/Devin monoliths (#4762, thanks @danikdanik).
  • Fix: solidity a call on a receiver of a contract or interface type (IERC20 token; token.transfer(), IERC20(a).transfer(), token().balanceOf()) binds by name and arity through that type's linearization to the type's own declaration, instead of producing no edge; gated to a single visible contract/interface and fail-closed on an unknown or ambiguous type (#5060, thanks @rohit-jsfreaky).
  • Fix: solidity a call attached by a using A for T directive (using SafeCast for uint256; x.toUint48()) binds to the library or free function it attaches, matched by the receiver's type and an arity one greater than the call; fail-closed when the receiver type is unknown, the library is ambiguous, or two functions fit (#5062, thanks @rohit-jsfreaky).
  • Fix: solidity members, free functions and types in one scope whose names differ only by a leading _ or by case (_grantRole / grantRole) get separate node ids, so the _ symbol no longer vanishes into its twin and its calls land on the right node (#5027, thanks @rohit-jsfreaky).
  • Fix: csharp a constructor (instance, static or primary) is its own node owned by its type, with its body and : base(...)/: this(...) calls credited to it; new X(...), : base(...) and : this(...) additively link the arity-correct overload, and two fitting overloads or an unresolved base give no constructor edge (#5054, thanks @rohit-jsfreaky).
  • Fix: csharp calls inside a property or indexer accessor, an expression body, or an operator/conversion body are credited to that member instead of being lost; an indexer becomes a this[] node and an operator a .operator +() node (#5056, thanks @rohit-jsfreaky).
  • Fix: query a same-label node that is the only match for a query term is kept as a seed instead of being dropped by the per-label cap, so every distinct term keeps at least one seed while generic-label flooding stays capped (#5027, thanks @Vaibhav2824).
  • Fix: watch read-only events are kept out of the inotify mask via a change-only event_filter, so a large tree no longer drives watchdog into a self-sustaining queue-overflow loop; falls back with a warning on watchdog versions without event_filter support (#5033, thanks @Deepjyoti-Sarmah).
  • Fix: cache the \\?\ long-path spelling is kept out of cache identity, so the same file reached through \\?\C:\... and C:\... shares one entry; also fixes empty stat-index writes under UNC shares, a spurious "stat index switched" warning on Windows, and a junction/symlink alias wrongly sharing its target's digest (#5035, thanks @Bortlesboat).
  • Fix: cache stat-index keys stay root-relative under a Windows long-path root, so a moved or cloned corpus keeps the portable-key fastpath (#5035, thanks @Vaibhav2824).
  • Fix: tests the TypeScript unicode fixture is written as UTF-8 on every platform, so byte offsets match the extractor on Windows (cp1252) hosts (#5064, thanks @ayushcodes10).
  • Fix: tests the hook-freshness source mock is normalized through os_long_path, so the read-error/stale branch is actually exercised on Windows (#5065, thanks @ayushcodes10).
  • Fix: tests the watch pending-queue test compares Path objects so / and \ separators compare equal on Windows (#5039, thanks @Yi-111-a).
  • Fix: extract an ambiguous Python import's placeholder node id is hashed from checkout-independent data (module name, scan-root-relative source file, location) instead of the absolute path, so the same project at a different path or a moved cache gets the same ids (#5045, thanks @Fardin7798).
  • Fix: yaml a template using CloudFormation intrinsic tags (!Ref, !GetAtt, !Sub) no longer fails to parse: a scoped permissive loader rebuilds each !-tagged node's shape without evaluating it, while !!python/... tags still raise and never execute (#5077, thanks @ayushcodes10).
  • Fix: watch a --watch incremental update rebuilds the full corpus when graph.json is missing, instead of writing a partial graph from the manifest alone (#5020, thanks @azizur100389).
  • Fix: watch a change to a JS/TS resolution input (tsconfig.json, jsconfig.json, a lockfile) triggers a full rebuild so importers pick up the new resolution, instead of leaving stale imports_from edges (#5020, thanks @azizur100389).
  • Fix: ingest two concurrent graphify add captures for the same URL no longer clobber each other: the capture file is created exclusively (O_EXCL) and a collision retries a fresh name, with the payload fetched once (#5020, thanks @azizur100389).
  • Fix: reflect a malformed entry in the learning overlay is skipped instead of crashing the whole load, and a legacy null-source entry is preserved as a source-less annotation (#5020, thanks @azizur100389).
  • Fix: global a malformed repo entry in the global manifest is dropped on its own, keeping the other tracked repos, and only a non-object root or repos map is backed up and reset (#5020, thanks @azizur100389).
  • Fix: query a graph freshly built on a subfolder is no longer flagged as a pre-#1504 build (which nagged a no-op extract --force): the legacy-id probe strips the .graphify_root offset before deriving file stems, and a genuine legacy graph is still caught (#5019, thanks @neumannpeter1231-lang).
  • Fix: tree graphify export tree recognises the src node alias (and file/path/filepath) so a graph carrying those keys renders a populated tree instead of an empty one; a concept-only graph still reports empty (#5030, thanks @Adityakk9031).
  • Fix: cli graphify provider add accepts --pricing-input=VALUE/--pricing-output=VALUE equals-syntax and rejects a non-numeric, non-finite or negative price with a clean error instead of a traceback or a poisoned cost estimate (#5031, thanks @Adityakk9031).

The AST cache schema is bumped to 40; warm caches re-run the affected Solidity and C# extractions. The Python and YAML fixes above need no bump (placeholder ids are resolved after the per-file cache, and previously-failing YAML was never cached).
