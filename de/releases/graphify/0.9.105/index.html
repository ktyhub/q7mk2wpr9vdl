v0.9.105 grafisch darstellen

graphify 0.9.105

– Fix: Von watch ignorierte Verzeichnisse (node_modules, .git, Build-Ausgabe) werden aus dem Linux-Überwachungsbaum entfernt, sodass ein großes Projekt nicht mehr Zehntausende verschwendeter Inotify-Überwachungen und Risiken ENOSPC registriert; Der rekursive Watcher für Nicht-Linux bleibt unverändert und wird weiterhin bei jeder echten Änderung ausgelöst (#5074, #5091, danke @Deepjyoti-Sarmah).

  • Fix: cpp eine Member-Aufrufkette, die über in anderen Headern deklarierte Klassenfelder (client.actions->Execute(), mit dem Wert ., Rohzeiger -> und Einzelargument-Empfänger unique_ptr/shared_ptr) geleitet wird, wird im gesamten Include-Satz zum Member des Feldtyps aufgelöst, auf einen eindeutigen Typ und Member beschränkt und andernfalls fehlgeschlagen; Ein typisiertes Local, dessen Klasse sich in einem anderen Repo befindet, wird für die Cross-Repo-Zusammenführung geparkt (#5098, danke @xRedLeader). – Fix: Markdown eines Code-Spans, der eine großgeschriebene \-Namespace-Klasse (\Foo\Bar, App\API) oder einen typqualifizierten Methodenaufruf (Type::member()) benennt, wird als Symbolerwähnung beibehalten, anstatt gelöscht zu werden, während ein Nicht-Aufruf Type::CONST/Type::class gelöscht bleibt (#5093, danke @Adityakk9031). – Fix: ts/js ein Aufruf über ein destrukturiertes CommonJS-Barrel erfordert (const { Thing } = require('./barrel'), wobei das Barrel Thing erneut exportiert) wird in die echte Deklaration aufgelöst, indem es den Exporten des Barrels folgt, anstatt die Kante fallen zu lassen (#5034, #5104, danke @qq2514568380).
  • Fix: Wiki der Orphan-Sweep faltet Slugs mit casefold (nicht lower), sodass zwei Artikelnamen, die nur bei vollständiger Unicode-Groß-/Kleinschreibung kollidieren (Straße/STRASSE, Σ/ς), jeweils ihre eigene Datei behalten, anstatt dass eine als Waisendatei gelöscht wird; Eine in diesem Lauf geschriebene Datei wird nie gelöscht (#5087, #5102, danke @nothariharan).
  • Fix: Build-Hyperedges bleiben in einem inkrementellen graphify update vollständig erhalten: Sie werden aus dem verschachtelten Diagrammslot gelesen, den ein JSON-only-Writer verwendet, und nach einem Bereinigen der gelöschten Quelle löscht ein Hyperedge nur seine entfernten Mitglieder (und sich selbst nur, wenn keine übrig sind), anstatt stillschweigend baumelnde Hyperedges zu verlieren oder zurückzulassen (#5081, #5103, danke @nothariharan).
  • Fix: cache ein verschlechterter (zu wenig produzierender) semantischer Cache-Eintrag fixiert den Korpus nicht mehr: Nachdem der Shrink Guard erkennt, dass eine erneute Extraktion kleiner als das gespeicherte Diagramm wird, wird der Eintrag mit partial gestempelt, sodass er beim nächsten Lauf erneut gesendet wird, anstatt das verschlechterte Ergebnis für immer wiederzugeben (#5083, #5101, danke @nothariharan). – Fix: betroffen graphify affected <file> setzt die verschachtelten Mitgliedsknoten der Datei (eine Methode innerhalb einer Klasse) transitiv und nicht nur einen Hop, sodass die Auswirkungsanalyse Aufrufer, die an ein verschachteltes Mitglied binden, nicht mehr unterbewertet (#5094, danke @Adityakk9031). – Fix: Baum build_tree leitet den gemeinsamen Verzeichnisstamm von den übergeordneten Dateien ab, sodass ein Einzeldatei- oder Einzelverzeichnisbaum nicht mehr selbst unter der Datei selbst verschachtelt ist (#5092, danke @Adityakk9031).
  • Fix: Abfragen eines Labels, dessen Name sich hinter einem Schema- oder Namespace-Qualifizierer (public.sweep_widget_state(), fmt.Println) befindet, wird am Ende von der gesamten Abfrage abgeglichen und über den Ebenen pro Token eingestuft, sodass es nicht mehr von Einzel-Token-Kollisionsknoten verdrängt und aus den Seeds entfernt wird (#5080, #5095, danke @sunhouy). – Fix: Erkennen einer inkrementellen Veraltungsprüfung, die eine Datei hasht, deren Stempel im Zeitversatzfenster auf beiden Seiten ihrer Mtime landet, sodass ein Umschreiben mit demselben Tick, das die Mtime nicht verschiebt, immer noch abgefangen wird, anstatt veraltet zu sein (#5090, danke @sunhouy). – Fix: Pfad graphify path A B lehnt einen Endpunkt ab, dessen Wörter nirgendwo im Diagramm erscheinen (Exit nicht gefunden), anstatt eine irreführende Route zurückzugeben, die aus lose überlappenden Tokens erstellt wurde (#5085, danke @sunhouy).
  • Fix: csharp, ein klassischer Erweiterungsmethodenaufruf (x.Foo(), wobei Foo als static ... Foo(this X x, ...) deklariert ist), bindet an die Deklaration der Erweiterungsmethode durch einen additiven Durchgang, der nach dem nominalen Versand ausgeführt wird und auf einen sichtbaren Namespace, einen passenden this-Typ und eine eindeutige anwendbare Methode beschränkt ist; Eine Instanzmethode mit demselben Namen gewinnt, eine statische Nicht-Erweiterung oder eine nicht importierte Erweiterung erhält keine Kante und die Mehrdeutigkeit schlägt fehl (#4828, #4849, danke @Deepjyoti-Sarmah).
  • Fix: Markdown eine bloße, unqualifizierte Erwähnung freier Funktionen in Prosa (token, kein () und kein Namespace) bindet nur dann an eine gleichnamige Funktion, wenn ihre definierende Datei (oder ein anderes Symbol daraus) in der Abschnittskette der Überschrift zitiert wird, anstatt mit einem gleichnamigen Callable im Korpus übereinzustimmen; Links im Referenzstil ([text][label]) werden auf der Verwendungsseite aufgelöst (#4804, #4806, danke @madanlalit).
  • Fix: Beim Exportieren des to_json-Verkleinerungsschutzes werden semantische Quellen, die beim erneuten Extrahieren ersetzt oder als Löschungen bereinigt wurden, nicht mehr als „verloren“ gezählt, sodass ein legitimer graphify update nicht abgelehnt wird. Ein echter unerklärlicher Psychiater wird immer noch abgelehnt (#5107, danke @khkar).
  • Fix: Build eines Knotens, dessen file_type oder confidence als strukturierter Wert (Liste/Dikt) aus einem driftenden LLM-Durchgang eintrifft, führt nicht mehr zum Absturz der Validierungs-/Build-Mitgliedschaftsprüfungen: Die Validierung zeigt ihn als Schemafehler an und der Build faltet ihn zu concept/INFERRED, ohne einen Score zu erstellen (#5088, danke @sdivyanshu90).
  • Fix: llm ein teilbares Dokument unterhalb der Zeichenobergrenze, dessen Modellausgabe abgeschnitten wird, wird zu einem Vollbereichs-Slice heraufgestuft und halbiert (und erneut versucht), anstatt als abgeschnittenes Teilergebnis behalten zu werden; Eine nicht teilbare oder Code-/Binäreinheit schlägt beim Schließen immer noch fehl (#5072, #5078, danke @aadilrizwan).
  • Feat: llm extra_headers eines benutzerdefinierten OpenAI-kompatiblen Anbieters werden als default_headers an den client weitergeleitet, auf diesen Anbieter beschränkt und mit gelöschtem Authorization-Header, sodass die konfigurierten Anmeldeinformationen nicht überschrieben werden können (#3680, #4783, danke @jaimemartinez).
  • Perf: Extrahieren ganzer Graph-Zwischenprodukte (das Parse-Memo auf dem One-Shot CLI, Build-/Cluster-/Export-Arbeitslisten) werden freigegeben, sobald sie verbraucht werden, wodurch Spitzenspeicher auf einem großen Korpus reduziert wird; Die Grafikausgabe ist byteidentisch (#5063, danke @TPAteeq).
  • Fix: skillgen Die Eingabeaufforderung des Claw/Kiro/Pi-Subagenten weist den Worker jetzt an, seinen Block in CHUNK_PATH zu schreiben, sodass ein Disk-Dispatch-Block nicht mehr inline zurückgegeben wird und beim Zusammenführungsschritt verloren geht (#5040, danke @connhodendatabase).
  • Fix: deps der pypdf-Boden wird in den Extras pdf und all auf 6.21.4 angehoben, um seine Sicherheitskorrekturen zu übernehmen (#5015, danke @yotamleo). Das AST-Cache-Schema wird auf 42 erhöht; Warme Caches führen die betroffenen C++-, Markdown- und C#-Extraktionen erneut aus.

graphify v0.9.105

graphify 0.9.105

  • Fix: watch ignored directories (node_modules, .git, build output) are pruned from the Linux watch tree, so a large project no longer registers tens of thousands of wasted inotify watches and risks ENOSPC; the non-Linux recursive watcher is unchanged and still fires on every real change (#5074, #5091, thanks @Deepjyoti-Sarmah).

  • Fix: cpp a member-call chain routed through class fields declared in other headers (client.actions->Execute(), with value ., raw-pointer -> and single-arg unique_ptr/shared_ptr receivers) resolves to the field type's member across the include set, gated to a unique type and member and fail-closed otherwise; a typed local whose class is in another repo is parked for the cross-repo merge (#5098, thanks @xRedLeader).

  • Fix: markdown a code span naming an uppercase \-namespace class (\Foo\Bar, App\API) or a type-qualified method call (Type::member()) is kept as a symbol mention instead of being dropped, while a non-call Type::CONST/Type::class stays dropped (#5093, thanks @Adityakk9031).

  • Fix: ts/js a call through a destructured CommonJS barrel require (const { Thing } = require('./barrel') where the barrel re-exports Thing) resolves to the real declaration by following the barrel's exports, instead of dropping the edge (#5034, #5104, thanks @qq2514568380).

  • Fix: wiki the orphan sweep folds slugs with casefold (not lower), so two article names that collide only under full Unicode case-folding (Straße/STRASSE, Σ/ς) each keep their own file instead of one being deleted as an orphan; a file written this run is never swept (#5087, #5102, thanks @nothariharan).

  • Fix: build hyperedges are kept whole across an incremental graphify update: they are read from the nested graph slot a JSON-only writer uses, and after a deleted-source prune a hyperedge drops only its removed members (and itself only when none remain), instead of silently losing or leaving dangling hyperedges (#5081, #5103, thanks @nothariharan).

  • Fix: cache a degraded (under-producing) semantic cache entry no longer pins the corpus: after the shrink guard sees a re-extraction come back smaller than the stored graph, the entry is stamped partial so the next run re-dispatches it instead of replaying the degraded result forever (#5083, #5101, thanks @nothariharan).

  • Fix: affected graphify affected <file> seeds the file's nested member nodes (a method inside a class) transitively, not just one hop, so impact analysis no longer under-reports callers that bind to a nested member (#5094, thanks @Adityakk9031).

  • Fix: tree build_tree derives the common directory root from file parents, so a single-file or single-directory tree is no longer self-nested under the file itself (#5092, thanks @Adityakk9031).

  • Fix: query a label whose name is behind a schema or namespace qualifier (public.sweep_widget_state(), fmt.Println) is matched on its tail by the whole query and ranked above the per-token tiers, so it is no longer out-competed by single-token collision nodes and dropped from the seeds (#5080, #5095, thanks @sunhouy).

  • Fix: detect an incremental staleness check hashes a file whose stamp lands within the clock-skew window on either side of its mtime, so a same-tick rewrite that does not move mtime is still caught instead of being served stale (#5090, thanks @sunhouy).

  • Fix: path graphify path A B refuses an endpoint whose words appear nowhere in the graph (exit not-found) instead of returning a misleading route built from loosely-overlapping tokens (#5085, thanks @sunhouy).

  • Fix: csharp a classic extension-method call (x.Foo() where Foo is declared static ... Foo(this X x, ...)) binds to the extension method's declaration through an additive pass that runs after nominal dispatch, gated to a visible namespace, a matching this type and a unique applicable method; an instance method of the same name wins, a non-extension static or an unimported extension gets no edge, and ambiguity fails closed (#4828, #4849, thanks @Deepjyoti-Sarmah).

  • Fix: markdown a bare, unqualified free-function mention in prose (token, no () and no namespace) binds to a same-named function only when its defining file (or another symbol from it) is cited within the heading's section chain, instead of matching any same-named callable in the corpus; reference-style links ([text][label]) resolve at the use site (#4804, #4806, thanks @madanlalit).

  • Fix: export the to_json shrink guard no longer counts semantic sources that were replaced on re-extract or pruned as deletions as "lost", so a legitimate graphify update is not refused; a genuine unexplained shrink is still refused (#5107, thanks @khkar).

  • Fix: build a node whose file_type or confidence arrives as a structured value (list/dict) from a drifting LLM pass no longer crashes the validate/build membership checks: validation surfaces it as a schema error, and the build folds it to concept/INFERRED without fabricating a score (#5088, thanks @sdivyanshu90).

  • Fix: llm a splittable document below the character cap whose model output truncates is promoted to a full-range slice and bisected (and retried) instead of being kept as a truncated partial result; a non-splittable or code/binary unit still fails closed (#5072, #5078, thanks @aadilrizwan).

  • Feat: llm a custom OpenAI-compatible provider's extra_headers are forwarded to the client as default_headers, scoped to that provider and with any Authorization header dropped so it cannot override the configured credential (#3680, #4783, thanks @jaimemartinez).

  • Perf: extract whole-graph intermediates (the parse memo on the one-shot CLI, build/cluster/export working lists) are freed as soon as they are consumed, cutting peak memory on a large corpus; graph output is byte-identical (#5063, thanks @TPAteeq).

  • Fix: skillgen the claw/kiro/pi subagent prompt now tells the worker to write its chunk to CHUNK_PATH, so a disk-dispatch chunk is no longer returned inline and lost at the merge step (#5040, thanks @connhodendatabase).

  • Fix: deps the pypdf floor is raised to 6.21.4 in the pdf and all extras to pick up its security fixes (#5015, thanks @yotamleo).

The AST cache schema is bumped to 42; warm caches re-run the affected C++, Markdown and C# extractions.
