graphify v0.9.109

– Fix: csharp eine Nicht-UTF-8-Quelldatei (Windows-1252/UTF-16), die eine Präprozessoranweisung enthält, wird dekodiert, bevor die Direktive ausgeblendet wird, sodass ein Nicht-ASCII-Bezeichner nicht mehr abgeschnitten wird und spätere Mitglieder nicht mehr gelöscht werden (#5194, danke @JensD-git). – Fix: csharp eine explizite Schnittstellenimplementierung (void IFoo.Bar()) wird von der Überlastungsbindung ferngehalten und erhält einen eigenen Knoten, sodass sie nicht mehr bei einer öffentlichen Bar-Überladung zusammenbricht und Dispatch an das richtige Mitglied aufruft (#5193, danke @JensD-git).

  • Fix: IDs-Mitglieder oder Funktionen eines Bereichs, deren Namen sich nur durch ein führendes/nachgestelltes _ oder nur durch die Groß-/Kleinschreibung unterscheiden, erhalten unterschiedliche Knoten-IDs, anstatt dass eine die andere verschluckt, jetzt in Kotlin (#5206), Swift (#5204), Dart (#5200) und C++ (einschließlich eines Konstruktors Foo vs. Destruktor ~Foo und eines abschließenden Unterstrichs name_, #5202); Ein eindeutiger öffentlicher Name behält die einfache ID bei und die Zwillinge werden gesalzen, wie es bereits für Python, C#, Java und PHP geschehen ist (danke @rohit-jsfreaky). – Fix: llm, wenn während der parallelen Extraktion ein Rückruf pro Chunk ausgelöst wird, werden die verbleibenden Chunks in der Warteschlange abgebrochen, anstatt weiter ausgeführt zu werden, sodass ein fehlgeschlagener Lauf sofort ohne verschwendete Modellaufrufe stoppt (#5187, danke @MaxWang007). – Fix: Beim Extrahieren eines AST-Fehlers pro Datei während eines inkrementellen Builds bleiben die letzten guten AST-Datensätze der Quelle erhalten, anstatt sie zu löschen, markiert den Lauf als unvollständig und löscht den Manifest-Hash der Datei, sodass er beim nächsten Lauf erneut versucht wird (#5191, danke @sdivyanshu90).
  • Fix: llm eine Antwort, die zwei oder mehr unabhängige Diagrammfragmente (oder ein Array mit mehreren Elementen) enthält, wird abgelehnt und erneut versucht, anstatt nur das erste als vollständig zwischenzuspeichern; Ein einzelnes Objekt oder ein Array mit einem Element, das ein gültiges Fragment umschließt, wird weiterhin akzeptiert (#5192, danke @sdivyanshu90).
  • Fix: Extrahieren unter einem symbolisch verknüpften Scan-Root, eine In-Root-Datei behält ihren reporelativen source_file, anstatt auf einen bloßen Basisnamen zu reduzieren (wodurch verschiedene Dateien zu einer zusammengeführt und das Diagramm geleert wurden); Nur das übergeordnete Element wird aufgelöst, daher ist ein Datei-Symlink, der #2832 eindeutig bleibt, immer noch (#4624, danke @maruf-asterbyte). – Fix: Extrahieren eines variablen Parameters verweist auf seinen Elementtyp (xs ...T in Go, T... xs in Java, params T[] in C#, T* in Scala, ...$xs in PHP), anstatt keine Typkante auszugeben (#4638, danke @madhusudanpatnaik). – Fix: Dart, eine Legacy-Typdefinition, die einen Funktionstyp (typedef int Function(int) Make();) zurückgibt, wird mit ihrem eigenen deklarierten Namen statt mit Function benannt (#4641, danke @madhusudanpatnaik).
  • Fix: Skill Eine Datei, die ein semantischer Subagent versandt hat, aber nie einen Coverage-Eintrag gemeldet hat, wird als ungelesen behandelt und erneut versendet, anstatt zwischengespeichert und als vollständig von Knoten gestempelt zu werden, die anhand ihres Namens erraten wurden; Die Eingabeaufforderung des Subagenten fragt nun nach einem Coverage-Eintrag (0 = nie geöffnet) für jede Datei (#2225, danke @Kalessin-Roke). Das AST-Cache-Schema wird auf 46 erhöht; Warme Caches führen die betroffenen C#-, Kotlin-, Swift-, Dart-, C++-, Go-, Java-, Scala- und PHP-Extraktionen erneut aus.

Englisches Original / English original

graphify v0.9.109

  • Fix: csharp a non-UTF-8 source file (Windows-1252/UTF-16) that contains a preprocessor directive is decoded before the directive is blanked, so a non-ASCII identifier is no longer cut short and later members are no longer dropped (#5194, thanks @JensD-git).
  • Fix: csharp an explicit interface implementation (void IFoo.Bar()) is kept out of overload binding and gets its own node, so it no longer collapses with a public Bar overload, and calls dispatch to the correct member (#5193, thanks @JensD-git).
  • Fix: ids members or functions of one scope whose names differ only by a leading/trailing _, or only by case, get distinct node ids instead of one swallowing the other, now in Kotlin (#5206), Swift (#5204), Dart (#5200) and C++ (including a constructor Foo vs destructor ~Foo, and a trailing-underscore name_, #5202); a unique public name keeps the plain id and the twins are salted, as already done for Python, C#, Java and PHP (thanks @rohit-jsfreaky).
  • Fix: llm when a per-chunk callback raises during parallel extraction, the remaining queued chunks are cancelled instead of continuing to run, so a failed run stops promptly without wasted model calls (#5187, thanks @MaxWang007).
  • Fix: extract a per-file AST failure during an incremental build preserves the source's last good AST records instead of deleting them, marks the run incomplete, and clears the file's manifest hash so the next run re-attempts it (#5191, thanks @sdivyanshu90).
  • Fix: llm a response carrying two or more independent graph fragments (or a multi-element array) is rejected and retried instead of caching only the first as if complete; a single object, or a single-element array wrapping one valid fragment, is still accepted (#5192, thanks @sdivyanshu90).
  • Fix: extract under a symlinked scan root, an in-root file keeps its repo-relative source_file instead of collapsing to a bare basename (which merged distinct files into one and emptied the graph); only the parent is resolved, so a file symlink that #2832 keeps distinct still is (#4624, thanks @maruf-asterbyte).
  • Fix: extract a variadic parameter references its element type (xs ...T in Go, T... xs in Java, params T[] in C#, T* in Scala, ...$xs in PHP), instead of emitting no type edge (#4638, thanks @madhusudanpatnaik).
  • Fix: dart a legacy typedef that returns a function type (typedef int Function(int) Make();) is named by its own declared name instead of by Function (#4641, thanks @madhusudanpatnaik).
  • Fix: skill a file a semantic subagent dispatched but never reported a coverage entry for is treated as unread and re-dispatched, instead of being cached and stamped complete from nodes guessed off its name; the subagent prompt now asks for a coverage entry (0 = never opened) for every file (#2225, thanks @Kalessin-Roke). The AST cache schema is bumped to 46; warm caches re-run the affected C#, Kotlin, Swift, Dart, C++, Go, Java, Scala and PHP extractions.
