WeKnora v0.8.2

Highlights

  • Sandbox and browser tooling — Sandboxes now default to root execution and gain an interactive terminal, files tab, live shell/install output, reconnection, and a graphical desktop. Agent sandbox tools are unified and host-preloaded skills are removed, so migration is required if you depend on host-provided skills. Browser automation adds local Chrome connection, task controls, screenshots, cancellation, handoff/resume, and picture-in-picture. Upgrade if you use agent-driven execution or browser automation; otherwise this is optional.
  • MCP breaking changes — feat(mcp)! changes in #3118 and #3127 persist tool catalogs, add guided configuration, use short routing handles, and streamline setup. Tools are discovered/invoked on demand, schema discovery is required before calls, per-tool enable toggles and manual-knowledge updates are supported, and advanced_config.timeout is honored. Existing MCP configurations and tool routing may need migration; MCP users should upgrade, while non-MCP deployments can skip this portion.
  • Security and correctness fixes — #3066 rejects path traversal in local prefixes, task IDs, and wiki sorting; #3241 enforces host-origin allowlists on framed pages; #3243 isolates skill drops from global uploads. Other fixes prevent misleading search citations, preserve OCR/caption and Feishu image content, handle Unicode paths, expose embedding-dimension and Qdrant update errors, recover expired-token streams, and improve memory ranking/progress. These favor multi-user, retrieval-heavy, or internet-facing deployments.
  • Data sources, deployment, and APIs — Adds DingTalk Docs (#2313) and Confluence sync (final PR URL is truncated), plus Bocha AI Search, Japanese locale support, XMind imports, Milvus multilingual BM25, and Helm’s global.maxFileSizeMB. The Docker frontend build no longer requires host npm. Create-user idempotency and HTTP status are now explicit, and $httpStatus exposes response status—API/frontend integrators should review these response semantics. Upgrade for new connectors or self-hosted build/deployment improvements; stable single-user setups without these needs can reasonably skip.
