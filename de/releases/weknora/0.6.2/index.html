WeKnora v0.6.2

Highlights

  • Breaking CLI changes (v0.9) — Authentication now targets the active profile: run profile add <name> --host <url> --use before auth login. Automation should use auth login --with-token, since password login is interactive-only. Change agent create --kb to --attach-kb and MCP integrations from agent_invoke to session_ask. Uniform JSON envelopes, typed exit codes, mutation --dry-run, and WEKNORA_AGENT_HELP=1 improve agent determinism, but existing output parsers need updating (#1551).
  • Faster bge-m3 vector search — A partial HNSW index now covers 1024-dimensional embeddings, matching the retriever’s halfvec(1024) cosine expression; previously these deployments silently fell back to sequential scans. The author’s 63k-row benchmark improved from roughly 100–500 ms to 27–30 ms per vector query. For large production tables, pre-create the identically named index with CREATE INDEX CONCURRENTLY before migration to avoid a blocking build (#1609, #1624).
  • Observability migration — Jaeger support—including middleware, Go dependencies, and Docker configuration—has been removed, so Jaeger-based deployments must replace that tracing path (#1629). Langfuse initialization is fixed by documenting LANGFUSE_INIT_ORG_ID and LANGFUSE_INIT_PROJECT_ID; custom .env files should include both to enable organization, project, and API-key bootstrap (#1634).
  • More reliable agent and tool contracts — Provider-specific tool-call metadata now survives ReAct execution, replay, and persisted history through ProviderMetadata; Gemini’s required thought_signature remains isolated in its adapter, preventing multi-step tool flows from losing state (#1625). The get_document_info schema now makes knowledge_ids and faq_ids optional/omitempty, so generated clients and validators should not treat either as required (#1640).
  • Deployment portability and traceability — Locked-down environments can set DUCKDB_SKIP_EXTENSION_LOAD=1 or true to bypass startup extension installation/loading; defaults remain unchanged, but xlsx/xls parsing should be verified separately (#1615). JIEBA_DICT_DIR enables runtime-provided tokenizer dictionaries (#1627), while frontend builds now embed the commit ID to identify the exact deployed revision (#1635).
  • Ingestion controls and UI correctness — Uploads and reparsing accept optional process_config overrides for parser rules and chunking, allowing different processing profiles within one knowledge base. Note that chunking overrides no longer expose enable_multimodal, and graph processing requires node extraction (#1636). Fixes also restore anonymous share-link registration, prevent empty knowledge-base lists with two or more KBs, and refresh wiki status after document polling (#1618, #1620, #1622).
