WeKnora v0.8.3

Highlights

  • Plugin system shipped, then ripped out — A large plugin stack landed across #3711–#3733 (Go and Python SDKs, plugin host, declarative installs of MCP servers/skills/model vendors, sandboxed UI pages with @weknora/plugin-ui, webhooks, OAuth connections, and plugin-served agent tools), then was fully reverted in #3735. Do not build against it in v0.8.3 — treat the plugin system as absent from this release and watch a later version for its return.
  • Unified reranking and new score semantics — #3675 consolidates rerank behavior across the search APIs and exposes diagnostics, while #3687 fixes recall correctness, score scales, and associated cost/agent-tool behavior. If you consume relevance scores or tune thresholds, re-baseline: the numbers and costs mean something different now.
  • Silent failures become explicit errors — A broad hardening pass stops swallowing errors: Elasticsearch _bulk per-item failures and SQLite index writes now fail BatchSave with rollback instead of leaving half-written state (#3842, #3843), Qdrant/Milvus keyword batches error rather than masquerading as "no matches" (#3847), and oversized/truncated RSS responses and truncated Notion queries are rejected instead of accepted (#3658, #3845). Callers that assumed best-effort success will surface new errors.
  • Index-copy fixes make cloning safe under concurrency — CopyIndices now preserves vectors and enabled state on Elasticsearch (#3678), reads Milvus source chunks by ID in batches instead of offset windows (#3883), and tolerates a class another worker created first in Weaviate (#3689). Multi-worker index rebuilds are substantially less fragile.
  • Agent and LLM reliability — Merging adjacent assistant messages no longer drops tool_calls into orphan tool messages that 400 the whole turn (#3574); compaction cancellation isn't reported as an empty-summary success (#3772); Retry-After survives HTTPError and is honored in LLM retries (#3737); and query_knowledge_graph truncation is now visible to both models and the UI (#3885). Together these make long, tool-heavy runs far less brittle.
  • New surfaces and behavioral changes to watch — Cross-KB Wiki search via POST /wiki-search (#3535), an image gallery with schema-driven filters (#3694, #3703), a system-admin model catalog (#3662), invite-only registration (#3900), and citations that open at the cited passage (#3700, #3794). Docs moved under /docs/ (#3664) and frontend doc links now point to the public docs site (#3674) — update bookmarks and integrations that assumed old paths. arm64 sandbox images (#3897) and Helm images pinned to chart version (#3669) improve deployments.
