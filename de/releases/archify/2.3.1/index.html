archify v2.3.1

Auditgesteuerter Patch. Drei Opus-Rezensenten fanden nach der Veröffentlichungssequenz 2.0 -> 2.3 eine Handvoll veralteter Aussagen und Ecken und Kanten; Dadurch werden die Korrekturen in einem zusammenhängenden Durchgang versendet.

Behoben

  • Veraltete Dokumente. `SKILL.md` Frontmatter und zwei „2x Retina“-Bullets wurden auf die aktuelle 4×-Pipeline aktualisiert. `README.md` wurde an vier Stellen bereinigt (Einleitungsabsatz, Tabelle „Was ist neu“ – enthält jetzt eine Spalte v2.2 –, Beschreibung des Exportmenüs und Abschnitt mit technischen Details).
  • Canvas-Size-Klemme. `rasterize()` wählt jetzt die größte Ganzzahlskala in `{4,3,2,1}` aus, deren Ziel-Canvas unter 16 Mpx passt. Standarddiagramme bleiben bei 4×; Sehr große ViewBoxes (~1600×1200+) werden automatisch verkleinert, anstatt leere Leinwände in älteren iOS Safari zu erzeugen.
  • `?openExport=1` Schriftartenrasse. `setTimeout(open, 60)` ersetzt durch `document.fonts.ready.then(open)` + doppeltes `requestAnimationFrame`. Kein Flash mehr bei langsamen Verbindungen.

Hinzugefügt

  • Menütrennzeichen exportieren. Zwei `<hr role="separator">`-Trennzeichen teilen das Menü in Kopie / Raster / Vektor. „PNG kopieren“ / „PNG herunterladen“ stehen optisch nicht mehr nebeneinander.
  • „PNG kopieren“ umbenannt in „Auf clipboard kopieren“ (PNG wurde zum Hinweis-Badge verschoben). Das Ziel befindet sich jetzt im primären Etikett.
  • CSS-Aufarbeitung drucken. `@page { size: landscape; margin: 1.5cm; }`, Zusammenfassungskarten werden im Druck zu einem zweispaltigen Raster (keine Waisen), die Containerbreite wurde angehoben, `page-break-inside: avoid` wurde neben `break-inside: avoid` hinzugefügt.

Installieren

Claude.ai: Einstellungen → Fähigkeiten → Fähigkeiten → + Hinzufügen → `archify.zip` hochladen. Claude-Code CLI: ```bash rm -rf ~/.claude/skills/archify entpacken Sie archify.zip -d ~/.claude/skills/ ``` Siehe CHANGELOG.md für zeilenweise Details.

archify v2.3.1

Highlights

  • Documentation accuracy — SKILL.md frontmatter and two "2x retina" bullets now reflect the current 4× pipeline, and README.md was corrected in four spots (intro, "What's new" table with a new v2.2 column, Export menu description, technical details). Anyone who relied on the old docs to set up or tune the export scale was being misled; this patch makes the written guidance match actual behavior, but it changes no code paths you configure against.

  • Canvas-size clamp in rasterize() — The renderer now selects the largest integer scale in {4,3,2,1} whose target canvas stays under 16 Mpx. Default diagrams still render at 4×, but very large viewBoxes (~1600×1200+) step down automatically instead of producing blank canvases on older iOS Safari. This is the most functional fix in the release — if you export big diagrams or support older iOS devices, upgrading directly prevents failed exports; small-diagram users see no change.

  • ?openExport=1 font race — setTimeout(open, 60) was replaced with document.fonts.ready.then(open) plus a double requestAnimationFrame, eliminating the export-menu flash on slow connections. Worth it for anyone who deep-links into the export UI or works on flaky networks; otherwise invisible.

  • Export menu and print polish — Two <hr role="separator"> dividers now group the menu into Copy / Raster / Vector, "Copy PNG" was renamed to "Copy to clipboard" (PNG moved to a hint badge), and print CSS adds @page { size: landscape; margin: 1.5cm; }, a 2-column summary-card grid, wider container, and page-break-inside: avoid alongside break-inside: avoid. The label rename is the only thing that could break UI-automation or docs that key off the literal "Copy PNG" text; otherwise cosmetic.

  • Upgrade verdict — No breaking changes and no migration steps: this is an audit-driven patch of stale docs and rough edges, not a feature or API change, so there is nothing to rewrite. Anyone on 2.0–2.3 who exports large diagrams, targets older iOS Safari, deep-links via ?openExport=1, or cares about accurate docs/print output should take it; users happy with the current behavior can safely skip, since none of the fixes alter output for typical small diagrams. Reinstall is the standard rm -rf ~/.claude/skills/archify + unzip archify.zip -d ~/.claude/skills/ (or replacing archify.zip in Claude.ai settings) — this is a real code/docs fix, not a no-op or metadata-only re-tag.

Audit-driven patch. Three Opus reviewers found a handful of stale statements and rough edges after the 2.0 -> 2.3 release sequence; this ships the fixes in one cohesive pass.

Fixed

  • Stale docs. `SKILL.md` frontmatter and two "2x retina" bullets updated to the current 4× pipeline. `README.md` cleaned in four places (intro paragraph, "What's new" table — now includes a v2.2 column —, Export menu description, and technical-details section).
  • Canvas-size clamp. `rasterize()` now picks the largest integer scale in `{4,3,2,1}` whose target canvas fits under 16 Mpx. Default diagrams stay at 4×; very large viewBoxes (~1600×1200+) step down automatically instead of producing blank canvases on older iOS Safari.
  • `?openExport=1` font race. `setTimeout(open, 60)` replaced with `document.fonts.ready.then(open)` + double `requestAnimationFrame`. No more flash on slow connections.

Added

  • Export menu separators. Two `<hr role="separator">` dividers split the menu into Copy / Raster / Vector. "Copy PNG" / "Download PNG" are no longer visually adjacent.
  • "Copy PNG" renamed to "Copy to clipboard" (PNG moved to hint badge). Destination is now in the primary label.
  • Print CSS polish. `@page { size: landscape; margin: 1.5cm; }`, summary cards become a 2-column grid in print (no orphans), container width lifted, `page-break-inside: avoid` added alongside `break-inside: avoid`.

Install

Claude.ai: Settings → Capabilities → Skills → + Add → upload `archify.zip`.

Claude Code CLI: ```bash rm -rf ~/.claude/skills/archify unzip archify.zip -d ~/.claude/skills/ ```

See CHANGELOG.md for line-by-line detail.
