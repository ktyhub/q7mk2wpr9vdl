TencentDB-Agent-Memory v2.0.0

[2.0.0] – 03.08.2026

Die offizielle Version von v2.0.0 ist veröffentlicht. Im Vergleich zu Beta.1, neue Fähigkeit zur erzwungenen Archivierung, geplante CodeGraph-Synchronisierung, Das Panel verfügt über Funktionen wie chinesisches und englisches Switching/Administrator-Asset-Management, und der Bereitstellungsprozess und die Zugriffsdokumentation wurden verbessert.

Produktpositionierung: Lassen Sie die Erfahrung, Dokumente und den Code des Agenten zu wiederverwendbaren Vermögenswerten für den nächsten Agenten werden Dateien direkt lesen. Weitere Informationen finden Sie unter README_CN.md.

🧠 Vier Speicherressourcen · Zum ersten Mal vollständig Open Source

Aus „Gesprächs-/Arbeitsspuren“ werden automatisch vier Arten von Vermögenswerten hinterlegt:

  • Chat-Speicher – Extrahieren Sie Schicht für Schicht L0-Originaldatensatz → L1-Fakt → L2-Szene → L3 aus der Konversation Langzeitkognition; Beibehaltung von Präferenzen, Entscheidungen und Interaktionsverlauf über Sitzungen hinweg.
  • Fähigkeit – Extrahieren Sie wiederverwendbare SOPs aus abgeschlossenen Aufgaben mit Versionen/Ressourcendateien/Triggergrenzen/ Ausführungsschritte/Validierungsregeln. Neu Funktion zur erzwungenen Archivierung wurde hinzugefügt, um sicherzustellen, dass Schlüsselkompetenzen nicht übersehen werden.
  • Wiki – Dokumente in strukturierte Seiten + Linkdiagramm umwandeln (inspiriert von der LLM-Wissensdatenbank von Karpathy). üben).
  • CodeGraph – Lagersymbole/Dateien/Aufrufbeziehungen/Einflusspfade indizieren, Agent ändert Code Führen Sie zunächst eine Wirkungsanalyse durch. Neu Synchronisieren Sie die Codebasisfunktion automatisch in regelmäßigen Abständen, ohne dass Sie dies manuell tun müssen, nachdem das Warehouse geändert wurde. auslösen.

🎛️ Memory Hub · Teamorientierte Konsole

Verwaltungspanel (agentmemory/memory-hub-Bild, einschließlich Panel + Knowledge Service):

  • Erstellen Sie ein Team/einen Agenten und verwalten Sie Assets einheitlich nach Eigentümer/Version/Status/Sichtbarkeit
  • Sichtbarkeit der Ebene 3: private/team/restricted (Benutzer-/Rollen-/Agent-ACL), Plus agent Richtungsmontage
  • Agent Loadout: Binden Sie verschiedene Assets an verschiedene Agenten, passen Sie Prioritäten und Verwendungsmethoden an
  • Der Wiki + CodeGraph-Workshop ist in den Hub integriert und kann durch Importieren der Codebibliothek/Dokumentation automatisch erstellt werden
  • Neuer Administrator (Systemadministrator) kann auch die Asset-Management-Funktion nutzen
  • Neues Panel unterstützt den Wechsel zwischen Chinesisch und Englisch vollständig; einheitlicher Seitendesignstil, optimierte Listeninteraktion und Paging-Erlebnis

🔀 Speicher-Proxy · Agent legt den Speicherkanal auf

agentmemory/memory-proxy ermöglicht Programmieragenten wie Claude Code die direkte Nutzung des Teamspeichers:

  • Anthropic / OpenAI Dual-Protokoll: /claude-code/<spaceId>/v1/messages und /v1/chat/completions alle akzeptiert
  • Erste Boot-Runde: sessionInit ermöglicht Benutzern die Auswahl von Team/Agent/über AskUserQuestion Aufgabe, Proxy-Speicherbindung
  • Injektion in jeder Runde: Injizieren Sie den L2/L3-Speicher, den passenden Skill, das Wiki/den Code-Graph des Agenten Geben Sie die Systemaufforderung ein und leiten Sie das Upstream-LLM weiter
  • Authentifizierung: x-tdai-user-key → Kernel /v3/meta/auth/verify ersetzt durch user_id, Steuern Sie die Asset-Sichtbarkeit nach Benutzerdimension

Englisches Original / English original

TencentDB-Agent-Memory v2.0.0

Highlights

  • Complete four-asset memory stack — v2.0.0 open-sources Chat Memory’s L0–L3 extraction pipeline, versioned Skills, structured Wiki pages, and CodeGraph indexing for symbols, files, calls, and impact analysis. Mandatory Skill archiving reduces the risk of validated workflows being lost, while scheduled CodeGraph synchronization keeps repository context current without manual rebuilds; review the sync schedule against your repository’s change rate.

  • Team-scale access control and asset assembly — Memory Hub manages ownership, versions, status, and visibility through private, team, and ACL-backed restricted access for Users, Roles, and Agents. Agent Loadout controls which assets each agent receives, their priority, and how they are used; admins can now manage assets directly, and the panel supports English/Chinese switching.

  • Drop-in memory for Anthropic and OpenAI-compatible agents — Memory Proxy exposes /claude-code/<spaceId>/v1/messages and /v1/chat/completions. It persists team/agent/task selection during sessionInit, then injects L2/L3 memories, matched Skills, Wiki, and CodeGraph context every turn. Because x-tdai-user-key is verified into a user_id, asset ACLs directly affect which knowledge enters the system prompt—not merely what the dashboard displays.

  • TypeScript SDK now defaults to v3 isolation — Despite the memory-sdk-ts-v2 package name, its root export is the v3 API with strict isolation; legacy compatibility remains under .../v2/v3. Audit imports and isolation assumptions before upgrading. Python’s v3 module provides the full API through both synchronous and asynchronous clients.

  • Container deployment is easier to bootstrap—and reset — The three memory-core, memory-hub, and memory-proxy images support linux/amd64 and linux/arm64. start-all.sh initializes an administrator, generates .admin-key, runs self-checks, and prints a ready-to-copy claude command. Protect that key, and treat stop-all.sh --purge as destructive: it removes volumes and the admin key.

  • Breaking changes — None explicitly declared.

[2.0.0] - 2026-08-03

v2.0.0 正式版发布，相比 beta.1 新增 Skill 强制归档、CodeGraph 定时同步、 面板中英文切换 / 管理员资产管理等特性，并完善了部署流程与接入文档。

产品定位：让 Agent 的经验、文档、代码沉淀成可复用资产，让下一位 Agent 直接读档。详见 README_CN.md。

🧠 四种记忆资产 · 首次完整开源

四类资产从"对话/工作痕迹"里自动沉淀出来：

  • Chat Memory — 从对话中逐层提取 L0 原始记录 → L1 事实 → L2 场景 → L3 长期认知；跨会话保留偏好、决策、交互历史。
  • Skill — 从跑通的任务里提炼可复用 SOP，附版本 / 资源文件 / 触发边界 / 执行步骤 / 验证规则。新增强制归档功能，确保关键 Skill 不遗漏。
  • Wiki — 把文档变成结构化页面 + 链接图谱（灵感来自 Karpathy 的 LLM 知识库 实践）。
  • CodeGraph — 索引仓库的符号 / 文件 / 调用关系 / 影响路径，Agent 改代码 前先做 impact analysis。新增定时自动同步代码库功能，仓库变更后无需手动 触发。

🎛️ Memory Hub · 面向团队的操作台

管控面板（agentmemory/memory-hub 镜像，含 Panel + Knowledge Service）：

  • 建 Team / Agent，把资产按 Owner / 版本 / 状态 / 可见性统一管理
  • 三级可见性：private / team / restricted（User / Role / Agent ACL）， 外加 agent 定向装配
  • Agent Loadout：给不同 Agent 绑定不同资产、调整优先级和使用方式
  • Wiki + CodeGraph 工坊内置在 Hub，导入代码库/文档就能自动构建
  • 新增管理员（System Admin）也可使用资产管理功能
  • 新增面板全面支持中英文切换；统一页面设计风格，优化列表交互和分页体验

🔀 Memory Proxy · Agent 挂上记忆的通道

agentmemory/memory-proxy 让 Claude Code 等 coding agent 直接用上团队记忆：

  • Anthropic / OpenAI 双协议：/claude-code/<spaceId>/v1/messages 和 /v1/chat/completions 都接
  • 首轮引导：sessionInit 通过 AskUserQuestion 让用户选 team / agent / task，proxy 记住绑定
  • 每轮注入：把该 agent 的 L2/L3 记忆、matched skill、wiki/code-graph 拼进 system prompt，转发上游 LLM
  • 鉴权：x-tdai-user-key → 内核 /v3/meta/auth/verify 换 user_id， 按用户维度控制资产可见性

🚀 部署方式

| 方式 | 说明 | |------|------| | Docker 三件套 | agentmemory/memory-core / agentmemory/memory-hub / agentmemory/memory-proxy，多架构（linux/amd64 + linux/arm64），一键 start-all.sh 拉起。首次启动自动 init-admin 并生成 .admin-key，start-all.sh 自检通过后打印可复制的 claude 启动命令 | | 源码运行 | 参考 INSTALL_CN.md / INSTALL.md |

stop-all.sh --purge 可彻底清理 volume + admin key，方便重置环境。

🧰 官方 SDK
