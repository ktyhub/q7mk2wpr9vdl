nacos 2.4.0

Bitte verwenden Sie zuerst 2.4.0.1. Diese Version ist eine wichtige Version, die viele neue Funktionen unterstützt. Die wichtigste Funktion besteht darin, dass der Nacos-Support-Betreuer das Kennwort des Administratorbenutzers nacos initialisiert, anstatt das Standardkennwort zu verwenden, um die Standardsicherheit für die Bereitstellung von Nacos-Clustern zu verbessern. Eine weitere Sache ist die standardmäßig deaktivierte Derby-Operation API, um Fehlalarme hinsichtlich entsprechender Risiken für Benutzer ohne aktivierte Authentifizierung bei der Bereitstellung im Standalone-Modus zu verhindern. Wenn Betreuer diesen API zum Verwalten und Abfragen von Daten im Derby verwenden möchten, können Betreuer nacos.config.derby.ops.enabled=true verwenden, um diesen API zu öffnen. Weitere Hauptfunktionen sind die Unterstützung der TLS-Grpc-Kommunikation zwischen Nacos-Clusterknoten als optionale Funktion zur Verbesserung der Nacos-Sicherheit, was bedeutet, dass Nacos nicht nur die TLS-Kommunikation zwischen client und Server unterstützt; Darüber hinaus unterstützt Nacos die Benutzererweiterung Selector vor dem Rückruf Subscriber für das Benennungsmodul und kann nicht nur Instanzen von Diensten nach Fehlern und Clustern auswählen. Und Nacos client unterstützt Callback-Service-Unterschiede nach neuem Ereignis, um den Subscriber-Cache zu reduzieren und Logiken zu vergleichen. Die dritten Hauptfunktionen sind die Unterstützung einiger Konfigurationsverwendungen in der Nacos-Konsole und die Unterstützung weiterer Erweiterungen für Plugins, wie z. B. die Unterstützung des Hinzufügens aller Metadaten zum SD-Protokoll prometheus und die Unterstützung der Aliyun-RAM-v4-Signatur. Neben umfangreichen Funktionsaktualisierungen behebt diese Version auch einige Fehler aus früheren Versionen und aktualisiert bestimmte Abhängigkeiten mit Sicherheitslücken. Detail siehe:

nacos 2.4.0

Please use 2.4.0.1 first

This version is an important version which support many new features.

The most mainly feature is Nacos support maintainer to initialize the admin user nacos password instead of using default password to improve the default security for deploy nacos clusters.

One more thing is default disabled derby ops API to prevent false alarms regarding corresponding risks for users without authentication enabled when deploying in standalone mode. If maintainers want use this API to maintain and query data in derby, maintainers can use nacos.config.derby.ops.enabled=true to open this API.

And other mainly features are support TLS Grpc communication between Nacos cluster nodes as an optional feature to improve Nacos security, which means nacos not only support TLS communication between client and server; What's more, Nacos start to support user extend Selector before callback Subscriber for naming module, not only can select instance of services by healthy and clusters. And Nacos client support callback service diffs by new event to reduce Subscriber cache and compare logics.

Third mainly features are support some configs usages in Nacos console and support more enhancement usage for plugins, such as support add all metadata to prometheus sd protocol and support aliyun ram v4 signature.

In addition to substantial feature updates, this version also fixes some bugs from previous versions and upgrades certain dependencies with security vulnerabilities.
