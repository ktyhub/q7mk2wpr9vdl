v5.7.0 verfassen

Was hat sich geändert?

ℹ️ Hinweis für Benutzer von Compose als Bibliothek: Up führt seine Erstellungs- und Startphasen jetzt als einzelner Plan über einen einzelnen Daemon-Snapshot aus, für up -d (#14290) und interaktives up (#14305), wie scale, Watch Rebuilds und start bereits (#14291, #14296). Der CLI verhält sich wie zuvor. Wenn Sie api.Compose.Up aus Ihrem eigenen Programm aufrufen:

  • Up validiert nun zuerst seine Optionen, mit den gleichen Regeln wie die CLI-Flags: UpOptions.Validate() gibt einen *api.IncompatibleOptionsError (errors.Is(err, api.ErrIncompatibleOptions)) für Start.Wait in Kombination mit Start.Attach und für einen getrennten Up (kein Start.Attach) in Kombination mit OnExit, ExitCodeFrom oder Watch zurück. Diese Kombinationen wurden früher stillschweigend ignoriert (#14306).
  • Up arbeitet an dem ihm zugewiesenen Projekt und ignoriert StartOptions.Project.
  • Der Daemon wird zwischen den beiden Phasen nicht erneut beobachtet: Ein Container, der nach der Erstellung des Plans beendet wird, wird nicht erneut gestartet, und ein dazwischen entfernter Container führt dazu, dass sein Start fehlschlägt, anstatt übersprungen zu werden. Ein Planungsfehler der Startphase schlägt jetzt fehl, bevor ein Container erstellt wird.
  • Ein Vordergrund-Up gibt einem use_api_socket-Dienst jetzt seinen /run/secrets/docker/config.json, wie es up -d tut, und zeigt die Ausgabe von pre_start-Hooks an.
  • Das Tastaturmenü eines interaktiven up wird nicht mehr von der Bibliothek erstellt: Setzen Sie NavigationMenu: true und übergeben Sie eine Implementierung mit compose.WithNavigationMenu(...), andernfalls wird kein Menü angezeigt und eine Warnung wird angezeigt (#14324).

Weitere Änderungen an der Bibliotheksoberfläche in dieser Version: DownOptions.Images ist jetzt ein api.ImagePruneMode (untypisierte Konstanten werden weiterhin kompiliert, eine string-Variable benötigt eine Konvertierung) und ein ungültiger Wert wird abgelehnt, bevor Down etwas entfernt (#14149); compose.ServiceHash, compose.NetworkHash und compose.VolumeHash werden nicht mehr exportiert, da die Helfer in ein internes Paket verschoben wurden (#14405); api.Compose wird jetzt aus sechs kleineren Schnittstellen mit demselben Methodensatz zusammengesetzt (#14322); PushOptions.IgnoreMissing wird hinzugefügt.

compose v5.7.0

What's Changed

ℹ️ Heads-up for users of Compose as a library: Up now runs its Create and Start phases as a single plan over a single daemon snapshot, for up -d (#14290) and interactive up (#14305), as scale, watch rebuilds and start already do (#14291, #14296). The CLI behaves as before. If you call api.Compose.Up from your own program:

  • Up now validates its options first, with the same rules as the CLI flags: UpOptions.Validate() returns an *api.IncompatibleOptionsError (errors.Is(err, api.ErrIncompatibleOptions)) for Start.Wait combined with Start.Attach, and for a detached Up (no Start.Attach) combined with OnExit, ExitCodeFrom or Watch. Those combinations used to be silently ignored (#14306).
  • Up works on the project it is given and ignores StartOptions.Project.
  • The daemon is not observed again between the two phases: a container that exits after the plan is built is not started again, and one removed in between makes its start fail instead of being skipped. A planning error of the Start phase now fails before any container is created.
  • A foreground Up now gives a use_api_socket service its /run/secrets/docker/config.json, as up -d does, and shows the output of pre_start hooks.
  • The keyboard menu of an interactive up is no longer built by the library: set NavigationMenu: true and pass an implementation with compose.WithNavigationMenu(...), otherwise no menu is displayed and a warning says so (#14324).

Other changes to the library surface in this release: DownOptions.Images is now an api.ImagePruneMode (untyped constants still compile, a string variable needs a conversion) and an invalid value is rejected before Down removes anything (#14149); compose.ServiceHash, compose.NetworkHash and compose.VolumeHash are no longer exported, the helpers having moved to an internal package (#14405); api.Compose is now assembled from six smaller interfaces, with the same method set (#14322); PushOptions.IgnoreMissing is added.
