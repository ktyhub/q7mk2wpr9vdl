go-ethereum v1.17.4

<!-- Flexibles Polymergehäuse (v1.17.4) -->

Dies ist eine Wartungsversion mit gesammelten Fehlerbehebungen und Verbesserungen und wird allen Benutzern empfohlen. Außerdem werden die Implementierungsarbeiten für den kommenden Amsterdam Hardfork fortgesetzt.

Eines ist hervorzuheben:

  • Schlüssel wurde entfernt. Der eigenständige clef-Unterzeichner wurde nach https://github.com/ethereum/clef verschoben (#35097).

Fork-Implementierung (Amsterdam)

  • EIP-7928: Zugriffslisten auf Blockebene: Die Blockzugriffsliste wird jetzt während der Blockausführung erstellt und überprüft, wobei die Bereitstellungsseite der eth/71-BAL-Nachrichten implementiert ist (#34652, #34803, #34879, #34957, #34967, #34972, #34977, #35110)
  • EIP-8189: snap/2, ein neues State-Sync-Protokoll basierend auf Zugriffslisten auf Blockebene, wurde hinzugefügt (#34626, #34807, #35098, #35155, #35158, #35163, #35178, #35180, #35181)
  • EIP-8037: Erhöhung der staatlichen Gaskosten wurde umgesetzt (#33601)
    • Das Suchsystem bietet einen neuen OnGasChangeV2-Haken für mehrdimensionales Gas (#34946) – engine_newPayloadWithWitnessV5 wurde hinzugefügt und das Zeugenformat verwendet jetzt die kanonische Spezifikationsfeldreihenfolge (#35009) – Die evm t8n-Tools wurden für Amsterdam aktualisiert und bieten BAL- und Slot-Nummern-Unterstützung sowie Binär-Trie-Blatt-Export (#34843, #35025). – Für EIP-7843 ist die Steckplatznummer jetzt für den ausstehenden Block nach Amsterdam festgelegt (#34792, #35036)

Geth

– Die Größe der Caches richtet sich jetzt nach der cgroup-Speicherobergrenze (z. B. Docker --memory), wenn eine festgelegt ist (#34947). – Eine Reihe kleiner Befehlszeilen-Flags und Protokollierungsprobleme wurden behoben (#33880, #34732, #34943, #34948, #35011, #35104, #35116, #35136) – Eine Reihe seit langem veralteter Befehlszeilen-Flags wurden entfernt (#35021)

RPC

  • eth_baseFee wurde hinzugefügt und gibt die Grundgebühr des nächsten Blocks zurück (#34904, #35023) – eth_capabilities wurde hinzugefügt, sodass clients herausfinden können, welche historischen Daten ein Knoten bereitstellen kann (#33886)
  • debug_clearTxpool wurde hinzugefügt, um den Transaktionspool zu löschen (#33347, #35130)
  • Zustandslesemethoden (eth_getBalance, eth_getCode, eth_getStorageAt usw.) setzen den Blockparameter jetzt standardmäßig auf latest, wenn er weggelassen wird (#35100)
  • Korrekturen für eth_simulateV1: ein falscher Fehlercode „Grundgebühr zu niedrig“ und eine Regression vor der Auszahlung in Shanghai (#34951, #34939) – debug_setHead gibt nun Rückspulfehler weiter, anstatt sie stillschweigend zu ignorieren (#35001) – EIP-7702-Transaktionen mit einer Null-To-Adresse werden jetzt abgelehnt (#35094) – HTTP-RPC-Antworten setzen jetzt immer Content-Length und ein WebSocket-Handshake-Statuscode-Fehler wurde behoben (#35072, #35111)

– Der client kann jetzt die Trace-Kontextweitergabe über den traceparent-Header konfigurieren und Antwortschreibvorgänge werden jetzt verfolgt (#35132, #35049)

GraphQL

– GraphQL-Anfragetexte sind jetzt auf 5 MiB begrenzt (#35034)

  • Log-Range-Abfragen mit begin > 0 und end == 0 werden jetzt abgelehnt (#35032)
  • Der Block.raw-Resolver gibt jetzt leere Bytes zurück, wenn der Blockkörper fehlt (#35027)

Kern

– Ein globaler Cache für JUMPDEST-Bitmaps beschleunigt die EVM-Ausführung (#34850) – EVM-Stack-Operationen werden jetzt direkt berechnet, wodurch Kopien pro Operand vermieden werden (#35156)

  • Neue Code-Cache-Hit/Miss-Anzeigen wurden hinzugefügt (#34821)
  • Ein Shutdown-Race bei der Snapshot-Generierung wurde behoben (#33540)

Motor API & Blobs

– Die Kodierung der Engine API JSON für große Blob-Nutzlasten wurde optimiert und gzip ist auf der Engine API deaktiviert (#33969, #35057) – engine_hasBlobs wurde hinzugefügt und engine_getBlobs zählt jetzt nur tatsächlich verfügbare Blobs (#34859, #35028) – Ein Cache für GetBlobs-Anfragen reduziert die Engine-API-Latenz und Otel-Tracing wurde zu den GetBlobs-Endpunkten hinzugefügt (#35124, #35026) – Neu organisierte V0-Blob-Sidecar-Transaktionen werden jetzt verworfen und nicht konvertiert (#35099)

  • testing_commitBlockV1 wurde als Schreibbegleiter zu testing_buildBlockV1 hinzugefügt (#34995) – Neue Payloads werden jetzt unabhängig vom Synchronisierungsstatus bei Genesis importiert (#32673)

Networking

– Die NAT-STUN-Erkennung schlägt auf IPv6-Servern nicht mehr fehl (#35084) – Mehrere Snap-Sync-Robustheitskorrekturen: Der nicht abgedeckte Status wird vor der Wiederaufnahme entfernt, ein Aufholstopp wurde behoben, die Synchronisierung wird neu gestartet, wenn die erforderliche BAL nicht verfügbar ist, und der Pivot wird eingefroren, sobald der Status-Download abgeschlossen ist (#35159)

Eine vollständige Übersicht über die Änderungen finden Sie im Release-Meilenstein von Geth 1.17.4.

Wie bei allen unseren vorherigen Veröffentlichungen finden Sie Folgendes:

  • Vorgefertigte Binärdateien für alle Plattformen auf unserer Download-Seite.
  • Docker-Bilder veröffentlicht unter ethereum/client-go (verwenden Sie das Tag „stable“).
  • Ubuntu-Pakete in unserem Launchpad PPA-Repository.
  • macOS-Pakete in unserem Homebrew Tap-Repository.

go-ethereum v1.17.4

<!-- Flexible Polymer Casing (v1.17.4) -->

This is a maintenance release with accumulated bug fixes and improvements, and is recommended for all users. It also continues the implementation work for the upcoming Amsterdam hardfork.

One thing worth highlighting:

  • Clef has been removed. The standalone clef signer has moved to https://github.com/ethereum/clef (#35097).

Fork Implementation (Amsterdam)

  • EIP-7928: Block-Level Access Lists: the block access list is now constructed and verified during block execution, with the serving side of the eth/71 BAL messages implemented (#34652, #34803, #34879, #34957, #34967, #34972, #34977, #35110)
  • EIP-8189: snap/2, a new state-sync protocol based on block-level access lists, has been added (#34626, #34807, #35098, #35155, #35158, #35163, #35178, #35180, #35181)
  • EIP-8037: state-creation gas cost increase, has been implemented (#33601)
    • The tracing system provides a new OnGasChangeV2 hook for multi-dimensional gas (#34946)
  • engine_newPayloadWithWitnessV5 has been added and the witness format now uses the canonical spec field ordering (#35009)
  • The evm t8n tooling has been updated for Amsterdam, adding BAL and slot-number support and binary-trie leaf export (#34843, #35025)
  • For EIP-7843, the slot number is now set for the pending block post-Amsterdam (#34792, #35036)

Geth

  • Caches are now sized against the cgroup memory cap (e.g. Docker --memory) when one is set (#34947)
  • A number of small command-line flag and logging issues have been fixed (#33880, #34732, #34943, #34948, #35011, #35104, #35116, #35136)
  • A number of long-deprecated command-line flags have been removed (#35021)

RPC

  • eth_baseFee has been added, returning the base fee of the next block (#34904, #35023)

  • eth_capabilities has been added, letting clients discover which historical data a node can serve (#33886)

  • debug_clearTxpool has been added to clear the transaction pool (#33347, #35130)

  • State-reading methods (eth_getBalance, eth_getCode, eth_getStorageAt, etc.) now default the block parameter to latest when omitted (#35100)

  • Fixes for eth_simulateV1: an incorrect "base fee too low" error code and a pre-Shanghai withdrawal regression (#34951, #34939)

  • debug_setHead now propagates rewind errors instead of silently ignoring them (#35001)

  • EIP-7702 transactions with a nil To address are now rejected (#35094)

  • HTTP RPC responses now always set Content-Length, and a WebSocket handshake status-code bug was fixed (#35072, #35111)

  • The client can now configure trace-context propagation via the traceparent header, and response writes are now traced (#35132, #35049)

GraphQL

  • GraphQL request bodies are now limited to 5 MiB (#35034)
  • Log-range queries with begin > 0 and end == 0 are now rejected (#35032)
  • The Block.raw resolver now returns empty bytes when the block body is missing (#35027)

Core

  • A global cache for JUMPDEST bitmaps speeds up EVM execution (#34850)
  • EVM stack operations are now computed in place, avoiding per-operand copies (#35156)
  • New code-cache hit/miss meters have been added (#34821)
  • A shutdown race in snapshot generation has been fixed (#33540)

Engine API & Blobs

  • Engine API JSON encoding for large blob payloads has been optimized, and gzip is disabled on the engine API (#33969, #35057)
  • engine_hasBlobs has been added, and engine_getBlobs now counts only actually-available blobs (#34859, #35028)
  • A cache for GetBlobs requests reduces engine API latency, and otel tracing has been added to the GetBlobs endpoints (#35124, #35026)
  • Reorged v0 blob sidecar transactions are now dropped rather than converted (#35099)
  • testing_commitBlockV1 has been added as the write companion to testing_buildBlockV1 (#34995)
  • New payloads are now imported at genesis regardless of sync status (#32673)

Networking

  • NAT STUN discovery no longer fails on IPv6 servers (#35084)
  • Several snap-sync robustness fixes: uncovered state is removed before resuming, a catch-up stall was fixed, sync restarts when the required BAL is unavailable, and the pivot is frozen once state download completes (#35159)

For a full rundown of the changes please consult the Geth 1.17.4 release milestone.

As with all our previous releases, you can find the:

  • Pre-built binaries for all platforms on our downloads page.
  • Docker images published under ethereum/client-go (use "stable" tag).
  • Ubuntu packages in our Launchpad PPA repository.
  • macOS packages in our Homebrew Tap repository.
