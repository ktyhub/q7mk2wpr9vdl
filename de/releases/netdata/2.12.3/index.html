netdata v2.12.3

Release notes

Netdata v2.12.3 ist eine Patch-Version zur Behebung von Problemen, die seit v2.12.2 entdeckt wurden.

Mit dieser Version erkennt der Agent eine unterbrochene Netdata-Cloud-Verbindung, selbst wenn der Datenverkehr weiter fließt, behebt „Use-after-free“-Abstürze, wenn ein veralteter Knoten entfernt wird, während ein untergeordnetes Element oder Plugin ihn noch verwendet, verhindert, dass mit parent using h2o konfigurierte untergeordnete Elemente bei jeder Verbindung abstürzen, sorgt dafür, dass eine negierte IP in einer Zugriffsliste Vorrang vor der Hostnamenübereinstimmung hat, lehnt fehlerhafte Prozent-Escapezeichen in URLs ab, begrenzt MCP-Batch-Anfragen, entfernt globale SQLite-Störungen, behebt Abstürze bei veralteten Diagrammen werden bereinigt, während sie noch gelesen werden, verhindert, dass der Agent beim Start hängen bleibt, wenn keine dbengine-Ebene erstellt werden kann, verhindert, dass übergeordnete Knoten, die die Speichermodi ram oder alloc verwenden, den Verlauf ihrer untergeordneten Knoten nach einer Lücke verschieben und bei Metrikkorrelationen mit mehreren Knoten abstürzen, lässt SNMP und andere virtuelle Knoten wieder offline gehen, wenn ihr Collector sie nicht mehr meldet, sorgt dafür, dass PowerStore-Diagramme die vom Array gemeldeten Werte anstelle von Nullen anzeigen, sorgt dafür, dass die eBPF-Plugins Verzeichnisse ignorieren überschreibt die Umgebung, wenn sie mit erhöhten Rechten ausgeführt werden, und lädt Hostbezeichnungen aus der Konfigurationsdatei neu, die der Agent tatsächlich geladen hat.

Streaming und Netdata Cloud

– Das MQTT-Keepalive der Cloud-Verbindung wurde behoben. Es wurde nur überprüft, wenn die Verbindung inaktiv war, sodass eine Verbindung mit stetigem eingehendem Datenverkehr nie einen unbeantworteten Ping bemerkte und auf unbestimmte Zeit blockiert bleiben konnte. Die Ping- und Bestätigungsfristen folgten ebenfalls der Wanduhr, sodass ein Taktschritt zu einem falschen Ping-Timeout oder einer verzögerten Erkennung führte und auf Boards ohne RTC-Bestätigungen nie vor der ersten NTP-Synchronisierung eine Zeitüberschreitung auftrat. Fristen verwenden jetzt eine monotone Uhr und eine unterbrochene Verbindung wird 60 Sekunden nach einem unbeantworteten Ping erkannt (#24427, @stelfrag) – Der HTTPS client des Agenten für Netdata Cloud überprüft jetzt die Blockgrößen von Chunk-Antworten streng und begrenzt solche Antworten auf 1 MiB. Eine fehlerhafte oder sehr große Chunk-Größe könnte dazu führen, dass der Agent beendet wird, während ihm Speicher zugewiesen wird (#24483, @stelfrag) – Abstürze bei der Verwendung nach dem Freigeben behoben, wenn netdatacli remove-stale-node oder die Bereinigung verwaister und kurzlebiger Hosts einen Host entfernte, der noch verwendet wurde, entweder durch ein erneutes Herstellen einer Verbindung durch ein Kind oder durch ein Plugin, das ihn als virtuellen Knoten ausgewählt hatte. Ein Kind, das sich während einer Entfernung erneut verbindet, wird nun aufgefordert, es erneut zu versuchen, und ein von einem Plugin ausgewählter virtueller Knoten wird als online gemeldet und in Ruhe gelassen (#24353, @stelfrag)

  • Die Option [stream] parent using h2o wurde entfernt. Der H2O-Webserver wurde in v2.7.0 entfernt, und seit v2.8.0 stürzte ein untergeordneter Server mit aktivierter Option bei jedem Verbindungsversuch zu seinem übergeordneten Server ab. Ein stream.conf, der es noch setzt, wird akzeptiert und die Option wird ignoriert (#24426, @stelfrag)

Webserver und APIs

  • Zugriffslisten: Ein client, dessen IP mit einem negierten Eintrag übereinstimmt, z. B. !203.0.113.7 in allow connections from = !203.0.113.7 *, wird jetzt abgelehnt, ohne dass sein Hostname mit der Liste verglichen wird. Dies gilt für jede Zugriffsliste in netdata.conf, wenn DNS-Prüfungen aktiviert sind, einschließlich des standardmäßigen heuristic-Modus für Listen mit einem Platzhalter (#24404, @ArjunD3456). – URLs mit fehlerhaften Prozent-Escapezeichen werden jetzt mit HTTP 400 abgelehnt. Einem % mussten zwei hexadezimale Ziffern folgen, wurde aber nicht überprüft, und eine URL, die nicht dekodiert werden konnte, wurde mit dem bisher dekodierten Teil bedient, sodass /api/v1/info%zz als /api/v1/info beantwortet wurde. Eine Anfrage, die ein Literal % enthält, dem keine zwei Hexadezimalziffern folgen, wie z. B. ?x=100%, erhält jetzt 400 (#24248, @stelfrag) – Der MCP-Schlüssel API und der Verwaltungsschlüssel API werden jetzt in konstanter Zeit verglichen, sodass die Antwortzeit nicht mehr verrät, wie nah ein erratener Schlüssel ist (#24418, @ArjunD3456)
  • MCP: JSON-RPC-Batches sind auf 64 Anfragen und 16 MiB Antworten beschränkt, WebSocket-Nachrichten auf 1 MiB, genau wie HTTP-Anfragen. Anfragen, deren ID keine Zeichenfolge, Zahl oder Null ist, werden abgelehnt (#24425, @stelfrag)
  • X-Forwarded-For: Der Agent behält jetzt nur die erste Adresse des Headers und nur dann, wenn es sich um eine gültige IPv4- oder IPv6-Adresse handelt. Dies ist die weitergeleitete client-Adresse, die im Zugriffsprotokoll und in den Audit-Einträgen dynamischer Konfigurationsänderungen angezeigt wird. Andere Werte wie unknown werden gelöscht (#24452, @ArjunD3456) – Registrierung: Die netdata_registry_id-Identität wird jetzt nur aus dem Cookie-Header gelesen, nicht von irgendwo anders in der Anfrage, wie etwa der Abfragezeichenfolge. Dies betrifft nur Agenten mit aktivierter Registrierung, die standardmäßig deaktiviert ist (#24494, @ArjunD3456)
  • Anspruch: Eine Anfrage an /api/v2/claim oder /api/v3/claim mit einem falschen Schlüssel generiert die Anspruchsherausforderung nicht mehr neu, sodass ein Anspruch eines Administrators nicht unterbrochen werden kann. Die Challenge wird beim Start und nach einer Inanspruchnahme mit einem gültigen Schlüssel weiterhin neu generiert (#24531, @stelfrag)

Datenbank

– SQLite-Störungen im gesamten Agenten wurden behoben. Für SQLite-Aufrufe wurde eine globale Sperre festgelegt, sodass eine langsame Anweisung jeden Thread blockierte, der SQLite verwendete, nicht nur diejenigen, die dieselbe Datenbankverbindung verwendeten (#24099, @stelfrag) – Beschädigungen der Metadatendatenbank, die während der Ausführung des Agenten auftreten, werden jetzt bei der ersten fehlgeschlagenen Abfrage zur Wiederherstellung markiert, anstatt nur bei einem ordnungsgemäßen Herunterfahren oder nie nach einem Absturz. Die SQLite-Abfragestatistik zählt einen später erfolgreichen Auslastungsversuch nicht mehr als fehlgeschlagene Abfrage (#24225, @stelfrag)

– Eltern, die die Speichermodi ram oder alloc verwenden, verschieben den gestreamten und replizierten Verlauf ihrer Kinder nicht mehr nach einer Lücke. Jede Lücke hat alle älteren Werte um ein Intervall nach vorne verschoben und die Beibehaltung um ein Intervall überbewertet (#24434, @stelfrag)

  • dbengine lädt jetzt nur Datendateien mit dem genauen Namen, den es schreibt. Eine Kopie wie datafile-1-0000000001.ndf.bak wurde ein zweites Mal zusammen mit der echten Datei geladen, und ein verirrter datafile-2-*.ndf stoppte den Agenten beim Start. Andere Namen werden jetzt als unbekannte Dateien gemeldet und übersprungen (#24436, @stelfrag) – Es wurden Abstürze behoben, die auftraten, wenn bei der Bereinigung veralteter Diagramme ein Diagramm oder seine Beschriftungen freigegeben wurden, während Zustandsvariablensuchen, Prometheus-Export, Warnungen und Kontextanfragen oder Abfragen es noch lasen. Dazu gehört, dass der Agent bei einer sehr großen Zuweisung aussteigt (#24466, #24474, @stelfrag)
  • dbengine: Der Agent bleibt beim Start nicht mehr hängen, wenn das Verzeichnis einer Ebene nicht erstellt werden kann oder der Initialisierungsthread nicht gestartet werden kann. Eine fehlende Stufe über Stufe 0 lässt den Agent nun mit den darunter liegenden Stufen laufen, und eine fehlende Stufe 0 stoppt den Start mit einem Fehler (#24435, @stelfrag)

Abfragen

– Ein Absturz bei Metrikkorrelationen und anderen Gewichtungsabfragen über zwei oder mehr Knoten auf Agenten ohne dbengine-Ebene wurde behoben, z. B. ein übergeordnetes Element, das die Speichermodi ram oder alloc verwendet. Solche Agenten verarbeiten nun die Knoten einzeln (#24433, @stelfrag) – Der Abschnitt summary.nodes[] der Abfrageantworten enthält jetzt die Abfragezeit des letzten Knotens, die fehlte. Mit options=percentage wird die Anomalierate der Dimensionsansicht nicht mehr erhöht. Die chart_labels-Arrays von /api/v1/data haben jetzt einen Eintrag pro Dimension, mit null, wo einem Diagramm die Beschriftung fehlt (#24460, #24474, @stelfrag)

Maschinelles Lernen

– [ml] dimension anomaly score threshold ist jetzt auf 0.01 bis 1.00 beschränkt, mit einer Warnung im Protokoll, wenn der konfigurierte Wert geändert wird. Werte bis zu 5.00 wurden akzeptiert, aber alles über 1.00 hat die Anomalieerkennung stillschweigend deaktiviert, da die Anomaliebewertung eines Modells 100 nicht überschreiten darf. Solche Werte werden jetzt bei 1.00 ausgeführt, der am wenigsten empfindlichen Einstellung (#24499, @stelfrag)

Sammler

  • ebpf.plugin und ebpf-go.plugin werden als Setuid-Root installiert. Wenn sie mit erhöhten Rechten ausgeführt werden, ignorieren sie jetzt die Umgebungsvariablen NETDATA_*_DIR und verwenden die Plugin-, Konfigurations- und Protokollverzeichnisse, mit denen sie erstellt wurden. Standardinstallationen sind nicht betroffen. Eine [directories]-Überschreibung in netdata.conf, die diese Verzeichnisse an eine andere Stelle verweist, erreicht die eBPF-Plugins nicht mehr, die eine Zeile für jede ignorierte Variable protokollieren (#24412, @stelfrag)
  • Redfish: Manager-Netzwerkports werden jetzt standardmäßig angezeigt. Portressourcen werden jetzt erfasst, einschließlich ihres Verbindungsstatus und ihrer Geschwindigkeit. Sie wurden abgelehnt, wodurch die Sammlung dauerhaft unvollständig blieb (#24270, @ilyam8)
  • PAN-OS: panos.ipsec.tunnels zählt jetzt die eingerichteten IPsec-Tunnel, anstatt die konfigurierten zu melden, und ein Tunnel mit überlappenden SAs während der Neuschlüsselung zählt einmal. Die verbleibende SA-Lebensdauer gibt jetzt die längste gültige Lebensdauer eines Tunnels anstelle eines variierenden oder summierten Werts an (#24385, @macmandr197) – go.d.plugin: Fehler behoben, bei dem Collectors wie Cato Networks einen Erfassungszyklus mit einem Host-Bereichskonflikt scheitern ließen, wenn sich die Metadaten eines Hosts änderten, während seine Identität gleich blieb (#24415, @ktsaou)
  • Cato Networks: Die Topologiefunktion verbindet jetzt jeden Standort mit seinen Geräten, behält jeden beobachteten WAN-Tunnel bei, anstatt parallele zusammenzuführen, und markiert Tunnel als verbunden, getrennt oder unbekannt. Standorte, Geräte und Tunnel enthalten weitere Details zur Fehlerbehebung, z. B. HA-Rollen, Verlust, Jitter, Last-Mile-Messungen und BGP-Sitzungen, und das Diagramm weist darauf hin, wenn Inventar, Metriken oder BGP-Daten fehlen. Der Kollektor verwendet jetzt Cato SDK v1.1.0 (#24413, @ktsaou, #24362, @ilyam8)
  • ebpf.plugin: Die Anzahl der verfolgten PIDs in ebpf.monitoring_pid wächst auf Hosts mit kurzlebigen Prozessen nicht mehr weiter. Ein Prozess, der beendet wurde, bevor sein /proc-Eintrag gelesen wurde, wurde ohne Subtraktion freigegeben (#24423, @stelfrag)
  • statsd.plugin: Wenn [statsd] set charts as obsolete after aktiviert ist (standardmäßig deaktiviert), stürzt der Agent nicht mehr ab, wenn eine Leerlaufmetrik zum ersten Mal entfernt wird. Beim Entfernen gehen auch die Werte der Metrik nicht mehr verloren, und die von synthetischen Diagrammen verwendeten Metriken bleiben erhalten. Die Anzahl der privaten Diagramme ändert sich nicht mehr und blockiert nicht mehr jedes neue private Diagramm (#24440, @stelfrag)
  • Virtuelle Knoten: Das von einem Kollektor festgelegte Inaktivitäts-Timeout, wie es beispielsweise von SNMP-Geräten verwendet wird, funktioniert wieder. Es wurde verworfen, als der Knoten definiert wurde, sodass ein virtueller Knoten nie offline ging, nachdem sein Collector dies nicht mehr gemeldet hatte. Bei einem virtuellen Knoten, der erneut von seinem lokalen Kollektor übernommen wurde, nachdem eine gestreamte Kopie davon gestoppt wurde, werden jetzt seine Zustandsprüfungen und der normale Betrieb wiederhergestellt (#24495, @ilyam8)
  • SNMP: Eine Abfrage, bei der das Gerät keine Anfrage beantwortet hat, schlägt jetzt fehl. Für den virtuellen Knoten des Geräts wurden weiterhin Profilstatistiken gemeldet, die aus zwischengespeicherten Metadaten erstellt wurden, sodass dieser aktiv blieb, nachdem seine Messungen gestoppt wurden (#24497, @ilyam8)
  • PowerStore: Leistungs-, Ethernet- und Kapazitätsdiagramme zeigen jetzt die Werte an, die das Array meldet. Der Collector las die Feldnamen der Rohproben, während die von ihm angeforderten fünfminütigen und täglichen Rollups unterschiedliche Namen verwenden, sodass diese Diagramme Nullen zeigten oder fehlten. Die CPU zeigt jetzt die Spitzenauslastung des Intervalls als Prozentsatz an und die durchschnittliche Anmeldeanzahl behält ihre Bruchteile bei (#24448, @ilyam8) – log2journal: JSON-Zeilen, die innerhalb eines Backslash-Escape enden, werden jetzt abgelehnt, anstatt mit Bytes von jenseits des Zeilenendes analysiert zu werden (#24365, @ArjunD3456)
  • log2journal: Eine benannte Gruppe eines PCRE2-Musters oder einer Umschreiberegel, die nicht an einer Übereinstimmung teilnimmt, wie z. B. eine optionale Gruppe, veranlasst den Parser nicht mehr, ein Byte vor ihrem Puffer zu lesen. Die Ausgabe ändert sich nicht (#24380, @ArjunD3456)
  • log2journal: Mehrere JSON-Analyse- und Ausgabeprobleme wurden behoben. Sehr lange Zahlen mit einem Exponenten könnten den Zahlenpuffer überlaufen oder den Prozess zum Absturz bringen, \u000a- und \u0009-Escapes ließen den Rest des Werts fallen, ungepaarte Ersatzzeichen erzeugten ungültiges UTF-8 und eine Zeile, die nicht analysiert werden konnte, ließ ihre Felder sowohl im JSON- als auch im logfmt-Modus in der nächsten Zeile zurück. Ein --inject ersetzt nun einen aus dem Protokoll gelesenen Wert, anstatt daran angehängt zu werden, und ein Rewrite, der auf seinen eigenen Schlüssel verweist, liest den ursprünglichen Wert (#24443, @stelfrag)
  • go.d.plugin: Zwei Shutdown-Rennen im Job-Manager behoben. Ein Herunterfahren oder ein fehlgeschlagener Neustart konnte bis zum Ablauf der Frist warten, anstatt abgeschlossen zu werden, und eine bereits akzeptierte Funktionsanforderung konnte als abgelehnt gemeldet werden, weil das Plugin gestoppt wurde (#24491, @ilyam8)
  • go.d.plugin-Diensterkennung: Erkannte Namen und Adressen werden jetzt als Daten in den Jobs codiert, die von Erkennungsregeln generiert werden. Sie wurden als Text in YAML eingefügt, sodass eine IPv6-Adresse dazu führen konnte, dass die Analyse eines Jobs fehlschlug und ein Name wie on zu einem booleschen Wert wurde. Aktienregeln verwenden einen neuen job-Vorlagenhelfer, zum Beispiel {{ job "name" .Name "url" .Address }}, den auch benutzerdefinierte Regeln verwenden können. Vorhandene Regeln und gespeicherte dynamische Konfigurationen funktionieren weiterhin (#24469, @ilyam8) – go.d.plugin: Collector-Protokolle und -Fehler, einschließlich derjenigen, die von dynamischen Konfigurationsprüfungen zurückgegeben werden, enthalten keine Rohinhalte aus den Dateien, die ein Collector liest, wie Protokollbeispiele, Konfigurationszeilen oder Zertifikate mehr. Sie benennen stattdessen Datei, Zeile, Feld und Grund, sodass einige Nachrichten weniger detailliert sind (#24496, @ilyam8) – go.d.plugin und ibm.d.plugin: Von Collectors gelesene HTTP-Antworten, einschließlich Prometheus- und OpenMetrics-Endpunkten, sind jetzt auf 64 MiB begrenzt, gemessen nach der gzip-Dekomprimierung. Bei einer größeren Antwort schlägt die Sammlung fehl, anstatt den Speicher unbegrenzt zu vergrößern. HTTPCheck meldet eine solche Antwort als bad_content; Verwenden Sie einen kleineren Endpunkt für Gesundheitsprüfungen (#24490, @ilyam8)
  • SNMP-Traps und S3: Die von diesen Collectors gespeicherten Statusdateien werden jetzt sicher gelesen und geschrieben. Symlinks und spezielle Dateien werden abgelehnt und eine temporäre Datei, die bei einem Absturz zurückbleibt, blockiert spätere Schreibvorgänge nicht mehr (#24462, @ilyam8)
  • Probleme mit Aktienwarnungen und Metadaten behoben: Die Portcheck portcheck_connection_fails-Warnung sucht nicht mehr nach einer Dimension, die nicht existiert, die Elasticsearch-, OpenSearch- und Unbound-Metadaten stimmen jetzt mit den Diagrammen überein, die sie beschreiben, und die Unbound- und Ethtool-Moduldiagramme tragen wieder den Titel „Module ...“ anstelle von „CollectorV1 ...“ (#24308, @ilyam8)

Funktionen

  • Die Fortschrittsfunktion zeigt jetzt API-Aufrufe, die mit einem Serverfehler fehlgeschlagen sind, als Fehler an. Sie wurden mit einem Schweregrad versehen, den das Dashboard nicht erkennt, und sahen aus wie erfolgreiche Anrufe (#24185, @ilyam8)

Agent

– Host-Bezeichnungen werden jetzt aus der Konfigurationsdatei gelesen, die der Agent geladen hat, einschließlich einer mit -c angegebenen, beim Start und auf netdatacli reload-labels. Aus dieser Datei entfernte Beschriftungen werden auch beim erneuten Laden entfernt (#24117, @stelfrag) – Absturzberichte enthalten jetzt einen Stack-Trace für SIGABRT, der außerhalb der eigenen schwerwiegenden Fehlerbehandlung des Agenten ausgelöst wird (#24094, @stelfrag) – Bei macOS- und Linux-Builds ohne libbacktrace speichert der Agent bei einem Absturz erneut seine Statusdatei, sodass beim nächsten Start der Beendigungsgrund und das Signal gemeldet werden (#24345, @stelfrag) – Ein „Use-After-Free“ beim Herunterfahren von Eltern mit archivierten untergeordneten Elementen wurde behoben, wenn das Laden ihrer Kontexte die Wartezeit beim Herunterfahren überdauerte (#24492, @stelfrag) – Problem behoben, bei dem ratenbegrenzte Protokollmeldungen häufiger als zulässig ausgegeben wurden, wenn mehrere Threads gleichzeitig über denselben Begrenzer protokolliert wurden (#24249, @stelfrag) – Wenn [db] update every über 3600 liegt, meldet die Warnung jetzt den Wert, auf den es geklemmt wurde (3600) statt 1. Die Klemme selbst war bereits korrekt (#24378, @stelfrag) – Wenn ein Collector versucht, eine Dimension ohne ID hinzuzufügen, sagt der schwerwiegende Fehler jetzt dies, anstatt die Zerstörung des Dimensionsindex des Diagramms dafür verantwortlich zu machen (#24528, @stelfrag)

Installation und Verpackung

– Das Installationsprogramm und der Updater behandeln jetzt den Curl-Exit-Status 56, den einige Curl-Versionen bei Protokollfehlern zurückgeben, als Download-Fehler, wie die Exit-Status 22 und 78 (#24276, @Ferroin) – Windows-Pakete enthalten jetzt aktualisierte MSYS2-Pakete zusätzlich zur gebündelten MSYS2-Basis, einschließlich OpenSSL 3.6.5, Curl 8.23.0 und msys2-runtime 3.6.11. Jedes Update wird durch URL und Prüfsumme angeheftet und die gebündelte Paketdatenbank stimmt mit den Dateien überein, die geliefert werden (#24473, @stelfrag) – Wenn für die Erstellung aus dem Quellcode eine Go-Toolchain erforderlich ist und keine installiert ist, lädt das Installationsprogramm jetzt Go 1.27.3 anstelle von 1.27.0 herunter. Go 1.27.0 und höher werden weiterhin unterstützt (#24411, @ilyam8)

netdata v2.12.3

Release notes

Netdata v2.12.3 is a patch release to address issues discovered since v2.12.2.

This release makes the Agent detect a dead Netdata Cloud connection even while traffic keeps flowing, fixes use-after-free crashes when a stale node is removed while a child or plugin is still using it, stops children configured with parent using h2o from crashing on every connection, makes a negated IP in an access list take precedence over hostname matching, rejects malformed percent escapes in URLs, bounds MCP batch requests, removes global SQLite stalls, fixes crashes when obsolete charts are cleaned up while they are still being read, keeps the Agent from hanging at startup when a dbengine tier cannot be created, keeps Parents using the ram or alloc storage modes from shifting their children's history after a gap and from crashing on multi-node metric correlations, lets SNMP and other virtual nodes go offline again when their collector stops reporting them, makes PowerStore charts show the values the array reports instead of zeros, makes the eBPF plugins ignore directory overrides from the environment when they run with elevated privileges, and reloads host labels from the configuration file the Agent actually loaded.

Streaming and Netdata Cloud

  • Fixed the MQTT keepalive of the Cloud connection. It was only checked when the connection was idle, so a link with steady inbound traffic never noticed an unanswered ping and could stay stalled indefinitely. The ping and acknowledgement deadlines also followed the wall clock, so a clock step caused a false ping timeout or delayed detection, and on boards without an RTC acknowledgements never timed out before the first NTP sync. Deadlines now use a monotonic clock, and a dead connection is detected 60 seconds after an unanswered ping (#24427, @stelfrag)
  • The Agent's HTTPS client for Netdata Cloud now checks the chunk sizes of chunked responses strictly and caps such responses at 1 MiB. A malformed or very large chunk size could make the Agent exit while allocating memory for it (#24483, @stelfrag)
  • Fixed use-after-free crashes when netdatacli remove-stale-node or the orphan and ephemeral host cleanup removed a host that was still in use, either by a child reconnecting to it or by a plugin that had it selected as a virtual node. A child that reconnects during a removal is now asked to retry, and a virtual node selected by a plugin is reported as online and left alone (#24353, @stelfrag)
  • Removed the [stream] parent using h2o option. The h2o web server was removed in v2.7.0, and since v2.8.0 a child with this option enabled crashed on every connection attempt to its Parent. A stream.conf that still sets it is accepted and the option is ignored (#24426, @stelfrag)

Web server and APIs

  • Access lists: a client whose IP matches a negated entry, such as !203.0.113.7 in allow connections from = !203.0.113.7 *, is now denied without its hostname being checked against the list. This applies to every access list in netdata.conf when DNS checks are enabled, including the default heuristic mode for lists with a wildcard (#24404, @ArjunD3456)
  • URLs with malformed percent escapes are now rejected with HTTP 400. A % had to be followed by two hex digits but was not checked, and a URL that failed to decode was served using the part decoded so far, so /api/v1/info%zz was answered as /api/v1/info. A request containing a literal % that is not followed by two hex digits, such as ?x=100%, now gets 400 (#24248, @stelfrag)
  • The MCP API key and the management API key are now compared in constant time, so response timing no longer reveals how close a guessed key is (#24418, @ArjunD3456)
  • MCP: JSON-RPC batches are limited to 64 requests and 16 MiB of responses, and WebSocket messages to 1 MiB, the same as HTTP requests. Requests whose id is not a string, number or null are rejected (#24425, @stelfrag)
  • X-Forwarded-For: the Agent now keeps only the first address of the header, and only when it is a valid IPv4 or IPv6 address. This is the forwarded client address shown in the access log and in the audit entries of dynamic configuration changes. Other values, such as unknown, are dropped (#24452, @ArjunD3456)
  • Registry: the netdata_registry_id identity is now read only from the Cookie header, not from anywhere else in the request, such as the query string. This affects only Agents with the registry enabled, which is off by default (#24494, @ArjunD3456)
  • Claiming: a request to /api/v2/claim or /api/v3/claim with a wrong key no longer regenerates the claim challenge, so it cannot interrupt a claim an administrator is making. The challenge is still regenerated at startup and after a claim with a valid key (#24531, @stelfrag)

Database

  • Fixed SQLite stalls across the Agent. A global lock was held around SQLite calls, so one slow statement blocked every thread using SQLite, not only those using the same database connection (#24099, @stelfrag)

  • Corruption of the metadata database that appears while the Agent is running is now marked for recovery on the first failing query, instead of only at a clean shutdown or never after a crash. The SQLite query statistics no longer count a busy retry that later succeeded as a failed query (#24225, @stelfrag)

  • Parents using the ram or alloc storage modes no longer shift their children's streamed and replicated history after a gap. Every gap moved all older values one interval earlier and overstated retention by one interval (#24434, @stelfrag)

  • dbengine now loads only datafiles with the exact name it writes. A copy such as datafile-1-0000000001.ndf.bak was loaded a second time alongside the real file, and a stray datafile-2-*.ndf stopped the Agent at startup. Other names are now reported as unknown files and skipped (#24436, @stelfrag)

  • Fixed crashes when the cleanup of obsolete charts freed a chart, or its labels, while health variable lookups, Prometheus export, alert and context API requests or queries were still reading it. These include the Agent exiting on an allocation of a huge size (#24466, #24474, @stelfrag)

  • dbengine: the Agent no longer hangs at startup when the directory of a tier cannot be created or its initialization thread cannot start. A missing tier above tier 0 now leaves the Agent running with the tiers below it, and a missing tier 0 stops startup with an error (#24435, @stelfrag)

Queries

  • Fixed a crash in metric correlations and other weights queries over two or more nodes on Agents without a dbengine tier, such as a Parent using the ram or alloc storage modes. Such Agents now process the nodes one at a time (#24433, @stelfrag)
  • The summary.nodes[] section of query responses now includes the query time of the last node, which was missing. With options=percentage, the anomaly rate of the dimensions view is no longer inflated. The chart_labels arrays of /api/v1/data now have one entry per dimension, with null where a chart lacks the label (#24460, #24474, @stelfrag)

Machine learning

  • [ml] dimension anomaly score threshold is now limited to 0.01 to 1.00, with a warning in the log when the configured value is changed. Values up to 5.00 were accepted, but anything above 1.00 silently turned off anomaly detection, because a model's anomaly score cannot exceed 100. Such values now run at 1.00, the least sensitive setting (#24499, @stelfrag)

Collectors

  • ebpf.plugin and ebpf-go.plugin are installed setuid root. When they run with elevated privileges, they now ignore the NETDATA_*_DIR environment variables and use the plugin, configuration and log directories they were built with. Standard installations are not affected. A [directories] override in netdata.conf that points these directories elsewhere no longer reaches the eBPF plugins, which log one line for each ignored variable (#24412, @stelfrag)
  • Redfish: manager network ports exposed as standard Port resources are now collected, including their link state and speed. They were rejected, leaving the collection permanently partial (#24270, @ilyam8)
  • PAN-OS: panos.ipsec.tunnels now counts the established IPsec tunnels instead of reporting the configured ones, and a tunnel with overlapping SAs during rekeying counts once. The remaining SA lifetime now reports the longest valid lifetime of a tunnel instead of a varying or summed value (#24385, @macmandr197)
  • go.d.plugin: fixed collectors such as Cato Networks failing a collection cycle with a host scope conflict when a host's metadata changed while its identity stayed the same (#24415, @ktsaou)
  • Cato Networks: the topology Function now connects each site to its devices, keeps every observed WAN tunnel instead of merging parallel ones, and marks tunnels as connected, disconnected or unknown. Sites, devices and tunnels carry more detail for troubleshooting, such as HA roles, loss, jitter, last-mile measurements and BGP sessions, and the graph notes when inventory, metrics or BGP data are missing. The collector now uses Cato SDK v1.1.0 (#24413, @ktsaou, #24362, @ilyam8)
  • ebpf.plugin: the number of tracked PIDs in ebpf.monitoring_pid no longer keeps growing on hosts with short-lived processes. A process that exited before its /proc entry was read was released without being subtracted (#24423, @stelfrag)
  • statsd.plugin: with [statsd] set charts as obsolete after enabled (off by default), the Agent no longer crashes the first time an idle metric is removed. Removal also no longer leaks the metric's values, and metrics used by synthetic charts are kept. The private chart count no longer wraps around and blocks every new private chart (#24440, @stelfrag)
  • Virtual nodes: the inactivity timeout set by a collector, such as the one SNMP devices use, works again. It was discarded when the node was defined, so a virtual node never went offline after its collector stopped reporting it. A virtual node taken over again by its local collector after a streamed copy of it stops now has its health checks and normal operation restored (#24495, @ilyam8)
  • SNMP: a poll in which the device answered no request now fails. Profile statistics built from cached metadata were still reported for the device's virtual node, keeping it active after its measurements had stopped (#24497, @ilyam8)
  • PowerStore: performance, Ethernet and capacity charts now show the values the array reports. The collector read the field names of raw samples, while the five-minute and daily rollups it requests use different names, so these charts showed zeros or were missing. CPU now shows the peak utilization of the interval as a percentage, and average login counts keep their fractions (#24448, @ilyam8)
  • log2journal: JSON lines that end inside a backslash escape are now rejected instead of being parsed with bytes from beyond the end of the line (#24365, @ArjunD3456)
  • log2journal: a named group of a PCRE2 pattern or rewrite rule that does not take part in a match, such as an optional group, no longer makes the parser read one byte before its buffer. Output does not change (#24380, @ArjunD3456)
  • log2journal: fixed several JSON parsing and output issues. Very long numbers with an exponent could overflow the number buffer or crash the process, \u000a and \u0009 escapes dropped the rest of the value, unpaired surrogates produced invalid UTF-8, and a line that failed to parse left its fields to the next line in both JSON and logfmt mode. An --inject now replaces a value read from the log instead of being appended to it, and a rewrite that refers to its own key reads the original value (#24443, @stelfrag)
  • go.d.plugin: fixed two shutdown races in the job manager. A shutdown or failed restart could wait until its deadline instead of finishing, and a Function request that had already been accepted could be reported as rejected because the plugin was stopping (#24491, @ilyam8)
  • go.d.plugin service discovery: discovered names and addresses are now encoded as data in the jobs that discovery rules generate. They were inserted into the YAML as text, so an IPv6 address could make a job fail to parse and a name such as on became a boolean. Stock rules use a new job template helper, for example {{ job "name" .Name "url" .Address }}, which custom rules can use too. Existing rules and saved dynamic configurations keep working (#24469, @ilyam8)
  • go.d.plugin: collector logs and errors, including those returned by dynamic configuration checks, no longer include raw content from the files a collector reads, such as log samples, configuration lines or certificates. They name the file, line, field and reason instead, so some messages are less detailed (#24496, @ilyam8)
  • go.d.plugin and ibm.d.plugin: HTTP responses read by collectors, including Prometheus and OpenMetrics endpoints, are now limited to 64 MiB, measured after gzip decompression. A larger response fails the collection instead of growing memory without bound. HTTPCheck reports such a response as bad_content; use a smaller endpoint for health checks (#24490, @ilyam8)
  • SNMP traps and S3: the state files these collectors keep are now read and written safely. Symlinks and special files are rejected, and a temporary file left by a crash no longer blocks later writes (#24462, @ilyam8)
  • Fixed stock alert and metadata issues: the Portcheck portcheck_connection_fails alert no longer looks up a dimension that does not exist, the Elasticsearch, OpenSearch and Unbound metadata now match the charts they describe, and the Unbound and ethtool module charts are titled "Module ..." again instead of "CollectorV1 ..." (#24308, @ilyam8)

Functions

  • The progress Function now shows API calls that failed with a server error as errors. They were styled with a severity the dashboard does not recognize and looked like successful calls (#24185, @ilyam8)

Agent

  • Host labels are now read from the configuration file the Agent loaded, including one given with -c, at startup and on netdatacli reload-labels. Labels removed from that file are also removed on reload (#24117, @stelfrag)
  • Crash reports now include a stack trace for SIGABRT raised outside the Agent's own fatal error handling (#24094, @stelfrag)
  • On macOS and Linux builds without libbacktrace, the Agent again saves its status file when it crashes, so the next start reports the exit reason and signal (#24345, @stelfrag)
  • Fixed a use-after-free at shutdown on Parents with archived children, when loading their contexts outlasted the shutdown wait (#24492, @stelfrag)
  • Fixed rate-limited log messages being emitted more often than their limit when several threads logged through the same limiter at once (#24249, @stelfrag)
  • When [db] update every is above 3600, the warning now reports the value it was clamped to (3600) instead of 1. The clamp itself was already correct (#24378, @stelfrag)
  • When a collector tries to add a dimension without an id, the fatal error now says so, instead of blaming the destruction of the chart's dimension index (#24528, @stelfrag)

Installation and packaging

  • The installer and updater now treat curl exit status 56, which some curl versions return on protocol errors, as a download failure, like exit statuses 22 and 78 (#24276, @Ferroin)
  • Windows packages now include updated MSYS2 packages on top of the bundled MSYS2 base, including OpenSSL 3.6.5, curl 8.23.0 and msys2-runtime 3.6.11. Each update is pinned by URL and checksum, and the bundled package database matches the files that ship (#24473, @stelfrag)
  • When building from source needs a Go toolchain and none is installed, the installer now downloads Go 1.27.3 instead of 1.27.0. Go 1.27.0 and later remain supported (#24411, @ilyam8)

We would like to thank our dedicated, talented contributors that make up this amazing community. The time and expertise that you volunteer is essential to our success.

Support options <a id="v2123-support-options"></a>

As we grow, we stay committed to providing the best support ever seen from an open-source solution. Should you encounter an issue with any of the changes made in this release or any feature in the Netdata Agent, feel free to contact us through one of the following channels:

  • Netdata Learn: Find documentation, guides, and reference material for monitoring and troubleshooting your systems with Netdata.
  • GitHub Issues: Make use of the Netdata repository to report bugs or open a new feature request.
  • GitHub Discussions: Join the conversation around the Netdata development process and be a part of it.
  • Community Forums: Visit the Community Forums and contribute to the collaborative knowledge base.
  • Discord Server: Jump into the Netdata Discord and hang out with like-minded sysadmins, DevOps, SREs, and other troubleshooters. More than 2000 engineers are already using it!
