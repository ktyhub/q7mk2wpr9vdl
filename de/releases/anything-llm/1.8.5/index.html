Bemerkenswerte Änderungen

Mobiler Support

Jetzt können Sie, derzeit unter [Experimentelle Funktionen] (https://docs.anythingllm.com/beta-preview/enable-feature), die [AnythingLLM Mobile App – Android Beta] (https://anythingllm.com/mobile) mit Ihrer Instanz verbinden, um ein On-Device- und Off-Device-Erlebnis nahtlos zu verbinden. Nutzen Sie die Fähigkeiten und Abläufe Ihres Instanzagenten in einer einzigen, einheitlichen Oberfläche!

Der Chat mit Dokumenten wurde überarbeitet

https://github.com/user-attachments/assets/0e4ab18d-fb58-480a-94f5-907664dd8f3f Als wir AnythingLLM zum ersten Mal erstellten, war das durchschnittliche Kontextfenster 4 KB groß – kaum Platz für ein vollständiges Dokument. Deshalb haben wir beschlossen, immer RAG an erster Stelle zu stehen. Dies hat seine Nachteile, da RAG semantisch davon abhängt, Fragen zum Inhalt des Dokuments zu stellen. Dies führt zu schlechten Ergebnissen für „Dieses Dokument zusammenfassen“, nur um im Dokument zu erfahren, „worüber sprechen Sie“. Nun, jetzt haben wir das Beste aus beiden Welten. Dokumente sind auf einen Arbeitsbereichsthread und Benutzer beschränkt und wir werden versuchen, den vollständigen Dokumenttext zu verwenden, wenn dies möglich ist und Ihr Modell dies unterstützen kann. Wenn Sie diesen Betrag überschreiten, können wir Sie bitten, das Dokument einzubetten, damit Sie das Langzeitgedächtnis freischalten können. <img width="1394" height="906" alt="context-warning" src="https://github.com/user-attachments/assets/c28c24d9-a696-4ff6-8d77-7ca708592071" /> Sie können Ihr Kontextfenster auch einfach verwalten und anzeigen, um Dateien zu entfernen, die nicht mehr relevant sind, aber den Konversationsverlauf beibehalten. <img width="1804" height="732" alt="manage-attached-docs" src="https://github.com/user-attachments/assets/566c6cbd-e67e-4339-82c6-61dfbddde7fd" /> Sie können Dateien auch weiterhin direkt im Workspace-Dateimanager einbetten :)

anything-llm v1.8.5

Highlights

  • Chat-with-documents overhaul — Moves from RAG-first to attempting full-document text where the model's context window allows (#4261); documents are now scoped per workspace thread and user, with a visible context-window manager to drop stale files while keeping history, plus an embed prompt when you overflow into long-term memory. This matters because queries like "summarize this document" now work well instead of returning "what are you talking about" — the strongest reason to upgrade for anyone doing document analysis.
  • Mobile support (experimental) — You can connect the AnythingLLM Mobile App - Android Beta to your instance behind the Experimental features flag and use its Agent Skills and flows in one unified interface (#4173). Worth enabling only if you want on-device/off-device continuity; it's explicitly experimental, so skip if you need stable, supported surfaces.
  • New providers and model choice — Adds Moonshot AI as an LLM/agent provider (#4178), Chroma Cloud as a vector DB (#4273), Exa as a search provider (#4258), native embedder model selection including multilingual support (#3835), and a model field for generic OpenAI TTS (#4171). Upgrade if any of these match your stack — otherwise these are additive and low-risk.
  • Developer-facing signature/config changes (migration-relevant) — No formal "breaking change" is declared, but writeToServerDocuments now takes a config object (#4213), sendCommand uses a non-positional call signature (#4218), validFuncCall only checks required args and undefined options (#4214), and custom JWT TTL is configurable (#4234). If you script against these internals or rely on default JWT expiry, audit your integrations before upgrading; typical UI users are unaffected.
  • Targeted fixes and who can skip — Fixes multimodal chats via the OpenAI-compatible API (#4135), the export-chats API endpoint import error (#4220), the app-version metrics endpoint (#4209), and PostgreSQL queries against non-public schemas (#4202), alongside translation additions (Romanian #4247, Spanish #4263, Hebrew #4241). Upgrade if you hit any of these or want the document/mobile features; if you're stable on v1.8.4 and use none of the affected paths, this is a safe wait — it's a substantial feature release, not a no-op or metadata-only re-tag.

AnythingLLM v1.8.5 is live

Notable Changes

Mobile support

Now, currently under Experimental features, you can connect the AnythingLLM Mobile App - Android Beta to your instance to seamlessly blend an on-device and off-device experience. Leverage your instance Agent Skills and flows all within a single unified interface!

Chat with documents has been overhauled

https://github.com/user-attachments/assets/0e4ab18d-fb58-480a-94f5-907664dd8f3f

When we first built AnythingLLM, the average context window was 4K - hardly anything to fit a full document. So we decided to always be RAG first. This has its drawbacks since RAG is semantically dependent on asking questions about content in the document. This leads to poor results for "Summarize this document," only to be told by the document, "what are you talking about".

Well, now we have the best of both worlds. Documents are scoped to a workspace thread & user and we will attempt to use the full document text when possible and your model can support it. If you overflow this amount, we can then ask you to embed the document so you can unlock that long-term memory.

<img width="1394" height="906" alt="context-warning" src="https://github.com/user-attachments/assets/c28c24d9-a696-4ff6-8d77-7ca708592071" />

You can also easily manage and see your context window to remove files that are no longer relevant, but retain the conversation history. <img width="1804" height="732" alt="manage-attached-docs" src="https://github.com/user-attachments/assets/566c6cbd-e67e-4339-82c6-61dfbddde7fd" />

You can also still embed files directly in the workspace file manager too :)
