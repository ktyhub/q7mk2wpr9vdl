pi v1.5.1

Neue Funktionen

  • Shell-Anmeldung und -Abmeldung: Verwenden Sie pi auth login <provider> und pi auth logout <provider>, ohne eine Sitzung zu starten, mit API-Schlüssel und Anmeldeoptionen ohne Browser. Siehe Anmeldeinformationsbefehle.
  • Cache-Aufwärmung im Leerlauf: Geeignete Caches bleiben jetzt zwischen den Läufen bis zu 30 Minuten lang warm, wenn sich eine Aktualisierung voraussichtlich amortisiert. Siehe cacheWarming.
  • Anthropic Message Threads: Anfragen senden nur neue Nachrichten, während der Server die Konversation fortsetzt, mit vollständigem Anfrage-Fallback, wenn sich frühere Kontexte ändern. Siehe Anthropische Kompatibilität.
  • Reichhaltigere Mermaid-Diagramme: Kreisdiagramme, vom Autor definierte Stile, clickable-Beschriftungen auf unterstützten Terminals und Diagramme in erweiterten Verzweigungs- und Komprimierungszusammenfassungen. Siehe Anzeigeeinstellungen und Markdown-Transformatoren. – GitHub Copilot-Klassifikatoren: Rufen Sie Microsoft-Decision-1 über den Codemodus models.classify() auf, um typisierte Entscheidungen und Wahrscheinlichkeiten zu erhalten. Siehe Klassifikatormodelle verwenden.
  • Paket-Update-Zusammenfassungen: pi update --extensions meldet die NPM-Version oder Git-Commit-Änderung jedes Pakets und unterscheidet zwischen unveränderten, übersprungenen und gewarnten Updates. Siehe Pi oder Pakete aktualisieren.

Breaking Changes

  • Benutzerdefinierte GrepOperations.readFile-Rückrufe werden nicht mehr für Kontextzeilen aufgerufen. Das Feld wird weiterhin als optional und veraltet akzeptiert, sodass bestehende Integrationen weiterhin kompiliert werden können. Das grep-Tool übernimmt jetzt Kontextzeilen von ripgrep und liest übereinstimmende Dateien nicht mehr selbst. Um ein Remote-System zu durchsuchen, überschreiben Sie greps execute(); siehe Remote-Ausführung (#9276) – OpenAI-kompatible Modelle senden nicht mehr "tools": [], wenn alle Tools in einer Sitzung deaktiviert sind, in der Tools verwendet wurden; das Feld wird weggelassen. Dadurch werden 400 Fehler (tools must not be an empty array) von vLLM 0.20+ behoben, auch hinter LiteLLM. Wenn Ihr Proxy tools erfordert, sobald der Verlauf Toolaufrufe enthält, wie z. B. ältere LiteLLM-Versionen vor Anthropic, legen Sie compat.requiresToolsWithToolHistory: true für dieses Modell in models.json fest (#11843).

Hinzugefügt

– pi update listet jetzt jedes aktualisierte Paket mit seiner NPM-Version oder Git-Commit-Änderung auf, zum Beispiel npm:foo 1.2.0 -> 1.3.0, und gibt Packages are already up to date aus, wenn sich nichts geändert hat. Wenn sich nichts geändert hat, aber ein Update eine Warnung ausgegeben hat, beispielsweise weil npm die alte Version nach dem Auflösen veralteter Registrierungsmetadaten installiert gelassen hat, wird stattdessen No packages were updated, see the warnings above ausgegeben. Im Offline-Modus wird Skipped package updates (offline mode) gedruckt. PackageManager.update() meldet jedes geänderte Paket als neues result-Fortschrittsereignis, dessen message diese Zeile enthält (#11707, #11711)

  • Anthropic-Sitzungen verwenden jetzt Nachrichtenthreads: Jede Anfrage sendet nur die neuen Nachrichten und der Server fährt mit der vorherigen Antwort fort und greift auf die vollständige Anfrage zurück, wenn sich die Konversation ändert (z. B. nach einer Komprimierung oder einer Änderung der Toolliste). Standardmäßig aktiviert für den anthropic-Anbieter auf api.anthropic.com; Legen Sie compat.supportsMessageThreads in models.json fest, um es für Gateways zu aktivieren, die das thread-Feld weiterleiten, oder um es zu deaktivieren. Die Cache-Erwärmung wirkt sich nicht auf den Thread der Sitzung aus (#11545)
  • pi.registerMarkdownTransformer() benötigt einen optionalen { messageTypes }, der die Markdown-Oberflächen auswählt, auf denen ein Transformator läuft. Neben Benutzer-, Assistenten- und Denk-Markdown können sich Transformer jetzt für custom (benutzerdefinierte Nachrichten und Fertigkeitsblöcke), summary (Verzweigungs- und Komprimierungszusammenfassungen) und changelog (Neuigkeiten, /changelog, den Hinweis zu Erweiterungsaktualisierungen und den Hinweis zu verfügbaren Updates) entscheiden. Ohne Optionen läuft ein Transformer wie bisher auf Benutzer-, Assistenten- und Denk-Markdown. Der integrierte Mermaid-Renderer zeichnet Diagramme jetzt auch in erweiterten Zweig- und Komprimierungszusammenfassungen
  • pi auth login <provider> meldet sich von der Shell aus bei einem Anbieter an, ohne eine Sitzung zu starten, zum Beispiel pi auth login radius. Es meldet sich mit einem Konto im Browser an und wird beendet. --api-key speichert stattdessen einen API-Schlüssel und --no-browser verwendet stattdessen die Gerätecode- oder Kopiercode-Anmeldung. Durch die Anmeldung bei Radius wird auch der Radius MCP-Server konfiguriert. pi auth logout <provider> entfernt die gespeicherten Anmeldeinformationen, wie /logout
  • ctx.ui.custom()-Overlays berücksichtigen jetzt die Option blocked: pi meldet den blockierten Programmstatus (OSC 7501) von der Anzeige des Overlays bis zum Aufruf von done(), auch während es mit setHidden() ausgeblendet ist. Durch das Schließen eines Overlays bleiben andere offene Fragen blockiert (#11816) – Der qwen-token-plan-individual-cn-Anbieter für Qwen Token Plan Individual auf dem China-Endpunkt hinzugefügt, unter Verwendung von QWEN_TOKEN_PLAN_CN_API_KEY (#7989 von @bigoldcat123) – Microsoft-Decision-1-Klassifikatorunterstützung durch GitHub Copilot hinzugefügt, einschließlich Codemodus models.classify() (#11679 von @Marvae) – compat.promptCacheKeyMode ("auto", "enabled" oder "disabled") hinzugefügt, um Prompt-Cache-Schlüssel für kompatible Proxys zu aktivieren oder sie für Endpunkte wegzulassen, die sie ablehnen. Legen Sie es in models.json fest, wenn Sie pi verwenden (#9442 von @dannote) – compat.requiresNonNullAssistantContent für OpenAI-kompatible Endpunkte hinzugefügt, die in Assistentenmeldungen, die nur Toolaufrufe enthalten, eine leere Zeichenfolge anstelle von null erfordern. Legen Sie es in models.json fest, wenn Sie pi verwenden (#8118 von @gaoyk19) – Syntaxhervorhebung für Dart-, Nix-, Groovy- und Gradle-Dateien in Lese- und Schreibansichten hinzugefügt (#11643) – GLM 5.3 zur Zulassungsliste für Qwen-Token-Plan-Einzelmodelle hinzugefügt (#11658) – Claude Fable 5.2 (claude-fable-5-2) zum anthropic-Anbieter hinzugefügt (8 $/40 $ pro Million Eingabe-/Ausgabe-Tokens, 1 Mio. Kontext, 128.000 Ausgabe). Wie Fable 5.1 verwendet es den Aufwand pro Nachricht und Systemnachrichten während der Konversation; fordert seine Sicherheitsklassifizierer auf, die Ablehnung abzulehnen, bevor Ausgaben von Claude Opus 5 durch serverseitiges Fallback beantwortet und zum Preis von Opus 5 abgerechnet werden. Claude Fable 5.2 und Mythos 5.2 auf anderen Anbietern, wie z. B. anthropic/claude-fable-5.2 von OpenRouter, erhalten die gleiche Unterstützung für den Aufwand pro Nachricht

  • Standardmodelle wurden zu neueren Modellen zum gleichen oder einem niedrigeren Preis verschoben: amazon-bedrock Claude Opus 5.5, azure GPT-6.1 Sol, google und google-vertex Gemini 4 Argon, vercel-ai-gateway GLM 5.3, baseten GLM 5.3, minimax und minimax-cn MiniMax-M3, qwen-token-plan und qwen-token-plan-cn Qwen3.8 Max, opencode-go Kimi K3.1 Pro und Kimi K2.7 Code anstelle von Kimi K2.6 für moonshotai, moonshotai-cn, huggingface, opencode, openrouter, cloudflare-workers-ai und cloudflare-ai-gateway – cacheWarming ist jetzt standardmäßig "idle" anstelle von "streaming": pi hält außerdem geeignete Eingabeaufforderungscaches zwischen Agentenläufen bis zu 30 Minuten lang warm, jedoch nur, wenn sich eine Aktualisierung voraussichtlich amortisiert. Legen Sie "cacheWarming": "streaming" in den globalen Einstellungen für das vorherige Verhalten fest – Aufeinanderfolgende Cache-Warmvorgänge werden jetzt als eine Cache warmed: $<total>-Zeile mit den kumulierten Kosten angezeigt, anstatt als eine Zeile pro Warmlauf
  • Der OpenAI Codex-Anbieter wird in /login und der Modellauswahl wieder als „OpenAI Codex“ anstelle von „OpenAI Codex (legacy)“ angezeigt
  • Die Anbieterlisten /login und /logout sowie die Vervollständigungen /login <provider> zeigen jetzt zuerst die bevorzugten Partner Radius und OpenRouter an, dann alle anderen Anbieter alphabetisch. In den Anbieterlisten sind Partner mit ✦ gekennzeichnet, die ausgewählte Radius-Zeile schimmert in den Farben des Radius-Logos und die ausgewählte OpenRouter-Zeile leuchtet in der Markenfarbe von OpenRouter (Limette bei dunklen Themes, Violett bei hellen Themes). – Verbessertes Terminal-Mermaid-Rendering zur Unterstützung weiterer Diagrammtypen, einschließlich Kreisdiagramme, vom Autor definierte Stile und cliaktivierbare Beschriftungen auf Terminals mit Hyperlink-Unterstützung (#8158 von @xl0)

Behoben

– Der glob-Abgleich des grep-Tools mit dem Ordner, in dem pi gestartet wurde, und nicht mit path wurde behoben: Bei path: "repo" gab glob: "migrations/main/*.js" No matches found zurück, obwohl repo/migrations/main/a.js vorhanden war. Globs sind jetzt relativ zu path, der gleichen Form, in der grep seine Ergebnisse ausgibt, auch wenn path ein symbolischer Link ist. Ein führendes ./ (./src/*.ts) wird ignoriert, anstatt mit nichts übereinzustimmen (#11807, #10998)

  • Argumente in Eingabeaufforderungsvorlagen behoben, die Apostrophe wegließen und Wörter zusammenführten: Ein Apostroph innerhalb eines Wortes, wie in doesn't, öffnet kein Zitat mehr; ein Zitat ohne Schlussübereinstimmung wird als Text beibehalten; und \" innerhalb von "..." (oder \' innerhalb von '...') ergibt ein wörtliches Zitat (#11861) – Problem behoben, bei dem das Bash-Tool nur Command timed out meldete, wenn der Befehl bereits beendet wurde, aber ein gestarteter Hintergrundprozess bis zum Timeout weiterhin in seine Ausgabe schrieb. Der Fehler meldet jetzt auch den Exit-Code der Shell und wann sie beendet wurde (#11613)
  • Bilder in Steuerungs- und Folgenachrichten, einschließlich prompt() beim Streaming, werden jetzt wie Bilder in Leerlaufaufforderungen in der Größe geändert, anstatt in voller Größe gesendet und gespeichert zu werden (#11738) – Eine fehlgeschlagene Tokenaktualisierung einer MCP-Verbindung registriert keinen OAuth-client mehr oder ersetzt den PKCE-Verifizierer einer laufenden Anmeldung, wodurch diese Anmeldung fehlgeschlagen ist. Die MCP-Anmeldung aktualisiert jetzt die gespeicherten Token mit dem gespeicherten client, ​​selbst wenn sich der Loopback-Callback-Port geändert hat, anstatt einen neuen client zu registrieren und den Browser zu öffnen. Strg+C in /mcp und --timeout von pi mcp login stoppt jetzt auch eine Anmeldung, während bis zu 25 Sekunden auf die Tokenaktualisierung eines anderen Pi-Prozesses gewartet wird, und eine Aktualisierungssperre, die aus einem anderen Grund als dieser Wartezeit fehlschlägt, lässt nun die Anmeldung fehlschlagen, anstatt den Browser zu öffnen. – Problem behoben, bei dem pi mcp list MCP-Server mit "auth": { "provider": "<provider>" }, wie z. B. Radius, meldete, dass eine Anmeldung erforderlich sei, obwohl der Anbieter angemeldet war: Der Shell-Befehl sendete kein Token. Es sendet nun das /login-Token des Anbieters und aktualisiert es, wenn es abgelaufen ist. Für diese Server verweisen die Anmeldehinweisnamen /login <provider> anstelle von pi mcp login sowie pi mcp login und pi mcp logout auf /login und /logout, anstatt mit „OAuth wird nicht verwendet“ fehlzuschlagen. – Der RPC-Modus ignorierte den ctx.shutdown() einer Nebenstelle im Leerlauf, beispielsweise von einem Timer: Der Prozess lief weiter, bis der client einen weiteren Befehl sendete. pi wird jetzt sofort heruntergefahren, wenn es inaktiv ist, und ein durch einen Erweiterungsbefehl angefordertes Herunterfahren wartet, bis die prompt-Antwort des Befehls geschrieben wird (#11599) – Behoben: changelog-Notizen wiederholten sich bei jedem Neustart, wenn die installierte Paketversion ein Vorabversionssuffix wie 0.1.5-20261020.7 hatte: Die gespeicherte Version wurde als 0.1.0 gelesen, sodass die Notizen 0.1.1 bis 0.1.5 jedes Mal als neu gezählt wurden. Eine gespeicherte Version ohne major.minor.patch zeigt jetzt keine Notizen an und wird durch die installierte Version ersetzt, anstatt die gesamte changelog anzuzeigen (#11703) – Problem behoben, bei dem der RPC-Modus die Bereinigung beim Herunterfahren unterbrach, z. B. eine ausstehende MCP-Token-Aktualisierung, wenn stdin geschlossen wurde und SIGTERM gleichzeitig ankam, was Prozessmanager wie Paseo und systemd tun. Pi hat das aktualisierte Token verloren und der MCP-Server hat die Anmeldung widerrufen. Sobald ein Herunterfahren begonnen hat, wird es nicht mehr durch einen Standard-EOF oder ein einzelnes Signal unterbrochen. ein zweites Signal ertönt trotzdem sofort. Der Druckmodus bricht ebenfalls nicht mehr aufgrund eines Signals ab, das während der letzten Bereinigung eintrifft (#11599) – Problem behoben, bei dem das grep-Tool jede übereinstimmende Datei in den Speicher las, wenn context festgelegt war, was bei großen Dateien zu Speichermangel führte; Der Kontext kommt jetzt von Ripgrep, das auch UTF-16-Dateien und einzelne CRs in übereinstimmenden Zeilen behebt, und der Match-Limit-Hinweis erscheint nicht mehr, wenn genau limit-Matches vorhanden sind (#9276, #11423) – Problem behoben, bei dem das Suchtool das Ergebnislimit meldete, wenn genau limit-Dateien übereinstimmen, und limit: 0 in find und ls jedes Ergebnis oder eine leere Liste zurückgibt; Grenzwerte unter 1 bedeuten jetzt 1 (#7121) – Korrektur von Grep-Übereinstimmungszeilen, Codemodus-Ausgabe, Komprimierungszusammenfassungen der Tool-Ergebnisse sowie MCP-Fehler- und Serverzusammenfassungen, bei denen ein Emoji oder ein anderes Nicht-BMP-Zeichen beim Abschneiden halbiert wurde, wodurch ein ungültiges einzelnes Ersatzzeichen im Text zurückblieb (#7121) – Problem behoben, bei dem das Suchtool unter Windows keine Ergebnisse für Muster mit Windows-Trennzeichen wie src\**\*.ts und für jedes Pfadmuster wie src/**/*.ts mit fd 10.5.1 zurückgab, das pi jetzt herunterlädt. Windows-Pfadmuster stimmen jetzt mit jeder fd-Version auf die gleiche Weise überein: src/**/*.ts findet Dateien auch direkt in src/ und src/*.ts findet keine Dateien mehr in Unterverzeichnissen (#9262)

pi v1.5.1

New Features

  • Shell login and logout: use pi auth login <provider> and pi auth logout <provider> without starting a session, with API-key and no-browser sign-in options. See Credential commands.
  • Idle prompt cache warming: eligible caches now stay warm for up to 30 minutes between runs when a refresh is expected to pay for itself. See cacheWarming.
  • Anthropic message threads: requests send only new messages while the server continues the conversation, with full-request fallback when earlier context changes. See Anthropic compatibility.
  • Richer Mermaid diagrams: pie charts, author-defined styles, clickable labels on supported terminals, and diagrams in expanded branch and compaction summaries. See Display settings and Markdown transformers.
  • GitHub Copilot classifiers: call Microsoft-Decision-1 through codemode models.classify() for typed decisions and probabilities. See Use classifier models.
  • Package update summaries: pi update --extensions reports each package's npm version or git commit change and distinguishes unchanged, skipped, and warned updates. See Update Pi or packages.

Breaking Changes

  • Custom GrepOperations.readFile callbacks are no longer called for context lines. The field remains accepted as optional and deprecated so existing integrations still compile. The grep tool now takes context lines from ripgrep and no longer reads matched files itself. To search a remote system, override grep's execute(); see Remote Execution (#9276)
  • OpenAI-compatible models no longer send "tools": [] when all tools are disabled in a session that has used tools; the field is omitted. This fixes 400 errors (tools must not be an empty array) from vLLM 0.20+, also behind LiteLLM. If your proxy requires tools once the history has tool calls, such as older LiteLLM versions in front of Anthropic, set compat.requiresToolsWithToolHistory: true for that model in models.json (#11843)

Added

  • pi update now lists each updated package with its npm version or git commit change, for example npm:foo 1.2.0 -> 1.3.0, and prints Packages are already up to date when nothing changed. When nothing changed but an update printed a warning, for example because npm left the old version installed after resolving stale registry metadata, it prints No packages were updated, see the warnings above instead; in offline mode it prints Skipped package updates (offline mode). PackageManager.update() reports each changed package as a new result progress event whose message holds that line (#11707, #11711)
  • Anthropic sessions now use message threads: each request sends only the new messages and the server continues from the previous reply, falling back to the full request when the conversation changed (for example after compaction or a tool list change). On by default for the anthropic provider on api.anthropic.com; set compat.supportsMessageThreads in models.json to enable it for gateways that forward the thread field, or to turn it off. Besides user, assistant, and thinking Markdown, transformers can now opt into custom (custom messages and skill blocks), summary (branch and compaction summaries), and changelog (What's New, /changelog, the Extension Updates notice, and the Update Available note). Without options a transformer runs on user, assistant, and thinking Markdown as before. The built-in Mermaid renderer now also draws diagrams in expanded branch and compaction summaries

  • Fixed ! and !! commands omitting the truncation notice and full-output file link when earlier output chunks had been discarded (#10165 by @acmerfight)
  • Fixed extension selection dialogs growing beyond the terminal height; they now show a scrolling window of up to ten options (#11072 by @DivineDominion)
  • Fixed pi config ignoring custom keybindings from keybindings.json (#11651)
  • Fixed concurrent OAuth refreshes through symlinked paths to the same auth.json by sharing the lock on the resolved file (#11655)
  • Fixed provider connection errors hiding their underlying cause, such as connection refusal or certificate errors, behind generic messages (#11695)
  • Fixed Ctrl+V not pasting clipboard images or text on Windows and WSL; both Ctrl+V and Alt+V are now default paste shortcuts there (#11765)
  • Fixed llama.cpp connection errors omitting the server URL and underlying network error (#11745)
  • Fixed Alacritty hyperlinks not being enabled when TERM_PROGRAM is unset; detection now also uses TERM and ALACRITTY_WINDOW_ID (#11767)
  • Fixed OpenAI Codex SSE retries retaining abort listeners after each backoff, causing listener buildup on repeated retries (#11708)
  • Azure OpenAI models now keep OpenAI's long-context price tier, so requests above 272K input tokens are costed at Azure's long-context rates (#11948)
  • Fixed Anthropic and Bedrock sending strict: "prefer" tools strict again on every request after Claude rejected them for exceeding its strict tool limits, which cost a rejected request (400) per turn. Later requests with the same sessionId now send those tools non-strict right away, until cleanupSessionResources(sessionId) (#11626)
  • Fixed tool arguments for Type.BigInt() and Type.Undefined() parameters being rejected: they convert as TypeBox converted them ("42" and 42 to 42n, null to undefined), now that pi-schema supports both types. Type.Void() still rejects every JSON argument.
  • Fixed Azure GPT-6 Astra, Luna, Sol, GPT-6.1 Sol, and GPT-6.1 Terra using a 272K context window instead of the 1,050,000 tokens Azure Foundry deploys them with (#11742)
  • Fixed OpenRouter rejecting requests with a 400 (This endpoint's maximum context length is ...) for models whose output limit is close to the context window, such as DeepSeek flash. OpenRouter counts the input with its own tokenizer, which can be several percent higher than the provider's count, and pi left only 4,096 tokens spare. pi then treated the 400 as a context overflow and compacted the session, even at around 20% of the window. The default output limit now leaves 15% of the estimated input unused, and near a full window at most 32,768 output tokens are requested (#10497)
  • Fixed Anthropic non-strict tool schemas dropping root $defs and definitions, which left property $refs pointing at nothing. Claude then produced wrong arguments for such tools (common in MCP servers), for example a JSON string instead of an object, and some Anthropic-compatible gateways rejected the request outright (#9557)
  • Fixed OpenCode Go Claude Haiku 5.5 failing with a 400 (Invalid signature in thinking block ... bound to a different conversation) after the tool list, system prompt, or earlier history changed, which left the session failing on every retry. OpenCode Go and Zen Claude 5.5 models, Opus 5, and Fable 5.1 now use per-message effort and send thinking.block_binding: drop_block, like the Anthropic provider (#10954)
  • Fixed Markdown displaying HTML comments (<!-- ... -->) as visible text (#11710)
  • Fixed codemode console.* output and thrown non-Error values printing NaN, Infinity, and -Infinity as null (#11901)
  • Fixed large MCP stdio messages being repeatedly copied and scanned as chunks arrived, causing slow tool responses (#11761)
  • Fixed MCP Streamable HTTP SSE replies with CR-only line endings failing with "stream ended without a response" (#11764)
  • Fixed oversized MCP SSE responses keeping their HTTP connections open after the message-size limit rejected them (#11729)
  • Fixed MCP stdio server subprocesses surviving disconnect or pi exit on POSIX when the server's main process had already exited (#11721)
  • Fixed MCP Streamable HTTP JSON replies bypassing message-size limits and HTTP errors buffering entire response bodies. Oversized replies and error-body content beyond the first 8 KiB are now cancelled (#11335)
  • Fixed valid tool arguments being rejected when their schema combined local $refs with a relative root $id, such as schemas/tool.json (#11697)
  • Fixed the find tool starting an untracked fd process when cancelled during its parent-directory lookup (#11974 by @petrroll)
