pi v0.99.0

Neue Funktionen

  • Codemode und MCP – Verbinden Sie MCP-Server und lassen Sie Modelle JavaScript ausführen, das Tools parallel aufruft. Siehe MCP-Server und Codemodus aktivieren.
  • Systemdesign – Die Farben von Pi stammen jetzt standardmäßig aus der eigenen Palette Ihres Terminals. Siehe Farben Ihres Terminals verwenden.
  • Mit ChatGPT anmelden – Verwenden Sie ein ChatGPT-Abonnement beim OpenAI-Anbieter über /login openai. Siehe Interaktiv authentifizieren.
  • Virtuelle Modelle – Erweiterungen können jede Anfrage an ein anderes physisches Modell weiterleiten. Siehe Virtuelle Modelle.
  • Klassifikatormodelle – Führen Sie Jev-Klassifikatoren aus Codemodus-Skripten aus oder verwenden Sie ein beliebiges llama.cpp-Modell als Klassifikator. Siehe Funktionsweise des Codemodus und Klassifizierung.

Hinzugefügt

  • Codemodus, Toolsuche und MCP-Unterstützung als integrierte Erweiterungen hinzugefügt. Das codemode-Tool führt das modellgeschriebene JavaScript in einer QuickJS-Sandbox aus, die die Pi-Tools aufruft; Aktivieren Sie es mit defaultTools oder --tools und konfigurieren Sie es mit codemode.mode und codemode.inlineBudget. tool_search findet Werkzeuge, die nicht für das Modell deklariert sind, und deklariert sie. MCP-Server über stdio oder streambares HTTP mit OAuth stammen von mcp.json (global oder pro Projekt einmal trusted) oder pi.registerMcpServer() und werden mit /mcp und pi mcp add|remove|list|login|logout verwaltet. Siehe MCP-Server und Codemodus aktivieren (#10040). – Erweiterungstool APIs für Orchestrierungstools hinzugefügt: exposure (direct, model-only, codemode, deferred oder hidden), namespace, annotations, outputSchema mit structuredContent-, isError-Ergebnissen, prepareLoadout() und ctx.executeTool() für verschachtelte Toolaufrufe, die Gibt Ereignisse mit parentToolCallId aus und wird als begrenztes nestedCalls im Ergebnis des aufrufenden Tools aufgezeichnet. Siehe Werkzeugbelichtung. – Es wurde eine Warnung hinzugefügt, wenn eine Erweiterung, die dasselbe Tool, denselben Befehl oder dasselbe Flag registriert, eine integrierte Erweiterung ersetzt (#10174 von @cristinaponcela).
  • Experimentelle virtuelle Modelle hinzugefügt: Erweiterungen registrieren sie bei pi.registerVirtualModel() und wählen für jede Anfrage ein physisches Modell und eine Denkebene aus. Die Fußzeile zeigt das geroutete Modell, /session listet die Kosten pro physischem Modell auf und examples/extensions/jev-router.ts führt Routen mit dem Jev-Klassifikator aus. Siehe Virtuelle Modelle. – Anmeldung mit ChatGPT beim OpenAI-Anbieter in /login hinzugefügt, der ein ChatGPT-Abonnement mit OpenAI API verwendet. Pi speichert in den globalen Einstellungen für diesen Login einen stabilen deviceId und lässt ihn in Fehlerberichten weg. – Das system-Design wurde hinzugefügt, jetzt die Standardeinstellung, das die Pi-Farben aus dem gemeldeten Vordergrund, Hintergrund und der ANSI-Palette des Terminals ableitet und sie neu aufbaut, wenn das Terminal zwischen hell und dunkel wechselt. Siehe Farben Ihres Terminals verwenden.
  • Farben #rgb, oklch() und okhsl() und ein optionales appearance-Feld zu Designdateien sowie theme.style(), theme.colors und theme.appearance für Erweiterungen hinzugefügt. Siehe Themen und TUI. – Für jedes llama.cpp-Chat-Modell wurde ein Klassifikatormodell hinzugefügt, das anhand der Wahrscheinlichkeiten der nächsten Token-Beschriftung beantwortet wird. Siehe Klassifizierung. – Geerbte Jev-Klassifikatormodelle auf OpenRouter, Cloudflare Workers AI, Vercel AI Gateway und OpenCode Zen hinzugefügt. – Die Einstellung fullscreenWheelScrollLines und der Eintrag /settings für das Scrollen mit dem Mausrad im Vollbildmodus wurden hinzugefügt. Der Standard-"auto" beschleunigt schnelle Raddrehungen außerhalb lokaler macOS-Terminals (#9758). – Eingabedisposition für erfolgreiche RPC-Antworten prompt, steer und follow_up, AgentSession.steer()/followUp() und RpcClient.prompt()/steer()/followUp() hinzugefügt; RpcClient.prompt() akzeptiert auch streamingBehavior (#9098, #9803). – Bildgenerierung zu ModelRuntime hinzugefügt: generateImages() mit zur Laufzeit aufgelöster Authentifizierung (gespeicherte Anmeldeinformationen, OAuth, Laufzeit-API-Schlüssel, models.json-Header) sowie getModelsOfType(), getModelOfType(), getAvailableOfType(), getAllModels() und getAllAvailable(). OpenRouter-Image-Modelle werden unter dem Anbieter openrouter aufgeführt und teilen sich dessen Anmeldeinformationen. Eine Upstream-ID kann separate Chat- und Bildeinträge haben. models.json-Anbieter und Erweiterungsregistrierungen ohne Modellliste behalten die integrierte Bildgenerierung bei. Erweiterungsmodelllisten können diskriminierte Chat-, Bild- und Klassifizierereinträge mit Operationsimplementierungen enthalten; Bei Auslieferung ersetzen sie betriebsübergreifend den Anbieterkatalog. Lesevorgänge im Chat (getModels(), getAvailableSnapshot(), Modellauswahl) bleiben unverändert. – Klassifikatorunterstützung zu ModelRuntime hinzugefügt, einschließlich classify(), Klassifikatormodell-Accessoren, laufzeitaufgelöster Authentifizierung und dem integrierten TypeSafe jev-latest-Modell. – types=chat,image,classifier zu pi.dev-Modellkataloganfragen hinzugefügt, sodass Remote-Aktualisierungen jeden unterstützten Modelltyp überlagern; Einträge unbekannter Modelltypen werden ignoriert. – Das Erweiterungsereignis provider_stream_event zum Beobachten geparster Anbieterereignisse vor der Normalisierung wurde mit einem optionalen /debug-provider-Beispielviewer hinzugefügt (#9784, #9901 von @davidbrai). – Ein Ein-/Ausblenden-Schalter (H) in HTML-Exporten für benutzerdefinierte Nachrichten mit der Markierung display: false hinzugefügt. Nachrichten bleiben standardmäßig ausgeblendet und können auch über die Seitenleiste angezeigt werden (#8896, #10020 von @rwachtler).
  • Geerbte Claude Sonnet 5.5-Unterstützung für Anthropic mit adaptivem Denken und einem 1M-Kontextfenster hinzugefügt. – In pi config wurde ein integrierter Abschnitt hinzugefügt, um die integrierten Erweiterungen mcp, llama.cpp, codemode und tool-search global oder pro Projekt zu deaktivieren, die als -builtin:<name> in der extensions-Einstellung gespeichert sind. SDK-Inline-Erweiterungen können mit builtin: true aktiviert werden. – Einträge +name und -name zur Einstellung defaultTools hinzugefügt, um Werkzeuge hinzuzufügen oder zu entfernen, ohne die Standardeinstellungen zu wiederholen, zum Beispiel "defaultTools": ["+codemode"]. Projekteinträge dieser Form gelten zusätzlich zur Benutzereinstellung. Dokumentiert, wie man codemode ohne MCP aktiviert und wie man Klassifikatormodelle wie Jev aus Codemode-Skripten verwendet. – Die Token-Nutzung und die Kosten von Codemode-models.classify()-Aufrufen wurden zum Ergebnis des Codemode-Tools hinzugefügt, sodass sie auf die Sitzungskosten angerechnet werden. Das Codemode-Ergebnis zeigt die Kosten jedes Anrufs.

Geändert

– Der Build wurde von der nativen Vorschau TypeScript auf TypeScript 7.0 mit einem ES2024-Ziel umgestellt und tsx durch das in Node integrierte Typ-Stripping für die Ausführung aus der Quelle ersetzt (#9965). – Der Abschnitt „[Themes]“ wurde aus dem Startbanner entfernt. Benutzerdefinierte Designs bleiben in /settings verfügbar und Designkonflikte werden weiterhin gemeldet.

  • Der Start-Header wurde geändert, um das Pi-Logo mit der Version anstelle des App-Namens anzuzeigen.
  • Die integrierten Themes dark und light wurden in die überarbeiteten Pi-Farben geändert, geschrieben in OKHSL.
  • Die Hell/Dunkel-Terminalerkennung wurde so geändert, dass zuerst die gemeldete Hintergrundfarbe, dann der Hell/Dunkel-Bericht des Terminals und dann COLORFGBG verwendet werden. Bei der Ersteinrichtung wird das erkannte Erscheinungsbild nicht mehr angezeigt. – Der geerbte OpenAI Codex-Anbieter wurde in „OpenAI Codex (Legacy)“ umbenannt. Die Anmeldung mit ChatGPT beim OpenAI-Anbieter hat Vorrang. – Geerbte Terminalerkennung geändert, um TERM=*-direct als Truecolor zu behandeln. – Integrierte Erweiterungen und Tools werden in Fehlern, Diagnosen, RPC-Quelleninformationen und Fehlerberichten als builtin:<name> (z. B. builtin:mcp und builtin:read) anstelle von <inline:name> und <builtin:name> bezeichnet. Ihre Slash-Befehle tragen nicht mehr das Autocomplete-Tag [t]. – --no-extensions deaktiviert auch die integrierten Erweiterungen, einschließlich des Anbieters llama.cpp. Laden Sie eines explizit mit -e builtin:<name>, zum Beispiel pi -ne -e builtin:mcp. – Tool-Aufrufe ohne benutzerdefinierten Aufruf-Renderer, einschließlich direkter MCP-Tool-Aufrufe, zeigen jetzt ihre Argumente an: als key=value-Paare in der Titelzeile, wenn sie reduziert sind, und als eine key: value-Zeile pro Argument, wenn sie erweitert sind. MCP-Aufrufe tragen den Titel server/tool und ihre Ergebnisse werden auf 5 Zeilen reduziert. – Die strukturierten Ergebnisse bash und powershell, die Codemodus-Skripte empfangen, enthalten jetzt bis zu 1 MiB Ausgabe anstelle der modellbezogenen 2000 Zeilen oder 50 KB und fügen truncated und full_output_path hinzu. Bei längerer Ausgabe bleiben die ersten und letzten 512 KiB erhalten. Die leere Ausgabe ist "" anstelle von (no output).

Behoben

– Behoben: X11 clipboard-Text wurde fälschlicherweise als Bild identifiziert, wenn der clipboard-Eigentümer nicht angekündigte Bildziele akzeptiert (#9786). – Verhindert, dass verwaltete Git-Pakete Pi-Peer-Abhängigkeiten automatisch installieren, und Warnungen für Erweiterungspakete hinzugefügt, die vom Host bereitgestellte Module in dependencies auflisten (#9863). – Behoben: Angeheftete Git-Erweiterungen, die mit -e geladen wurden, verwendeten weiterhin den ersten heruntergeladenen Commit, nachdem sich die Referenz geändert hatte (#9982). – Problem behoben, bei dem RpcClient den nächsten Ereignis-Listener übersprang, wenn sich ein Listener während der Bearbeitung eines Ereignisses abmeldet, was zu einer Zeitüberschreitung von waitForIdle() nach collectEvents() führen konnte (#9990). – Die Darstellung vollständiger read-Aufrufe in der Datei wurde als :1 behoben, wenn Modelle null für ausgelassene offset und limit senden (#9996). – Behoben, dass neue Sitzungen verloren gingen, wenn Pi vor der ersten Antwort des Assistenten beendet wurde. Die Sitzungsdatei wird jetzt erstellt, wenn die erste Benutzernachricht gesendet wird (#10000). – Problem behoben, bei dem entladene llama.cpp-Autoload-Voreinstellungen ein zwischengespeichertes Laufzeitkontextfenster mit dem GGUF-Trainingskontext überschrieben (#10077, #10158 von @cristinaponcela). – Problem behoben, bei dem benutzerdefinierte Designs terminal.trueColor und andere Überschreibungen von Terminalfunktionen ignorierten und mit 256 Farben gerendert wurden (#9973, #10039 von @christianklotz).

  • Das Einfügen von im Finder kopierten Dateien wurde behoben, wobei das Bild des Dateisymbols anstelle der Dateipfade eingefügt wurde; Pfade werden im Bash-Modus in Anführungszeichen gesetzt (#9999, #10136 von @christianklotz).
  • Der Start-Header, die geladenen Ressourcen und die Chat-Benachrichtigungen behalten nach einem Theme-Wechsel ihre alten Farben bei.
  • Problem behoben, bei dem das Fireworks-Standardmodell auf das entfernte Modell Kimi K2.6 zeigte; Die Standardeinstellung ist jetzt Kimi K3. – Problem behoben, bei dem das Standardmodell von OpenCode Go auf das entfernte Kimi K2.6-Modell zeigte; Die Standardeinstellung ist jetzt Kimi K3.
  • Problem behoben, bei dem das Standardmodell von Together auf das entfernte Modell Kimi K2.6 zeigte; Die Standardeinstellung ist jetzt Kimi K3. – Reduzierte CPU-Auslastung beim Streamen in langen Sitzungen und bei der Vorschau von Themen: Die Fußzeile speichert die Sitzungsnutzungsgesamtwerte im Cache, reduzierte Bash-Ergebnisse speichern ihre Vorschau im Cache und sanitizeBinaryOutput() teilt die Ausgabe nicht mehr in Arrays pro Zeichen auf. – Die Verwendung von Tools, die über ctx.executeTool() aufgerufen wurden, beispielsweise aus Codemodus-Skripten, wurde behoben und aus den Sitzungskosten entfernt. Es wird nun zur Ergebnisverwendung des aufrufenden Tools hinzugefügt. – Behoben: Die geerbte automatische Vervollständigung von /skill erschien leer, wenn geladene Fertigkeitsnamen nicht die Buchstaben in skill enthielten (#9944). – Behoben, dass der geerbte Pfad und die automatische Vervollständigung von @ nach dem Öffnen von Wrappern wie (, [, {, < oder einem Backtick nicht funktionierten.
  • Vererbtes Bilddehnen in Terminals behoben, die das Kitty-Grafikprotokoll verwenden (#8938, #9957 von @rwachtler). – Problem behoben, bei dem der geerbte Shell-Cursor nach dem Beenden verborgen blieb, wenn eine Erweiterung beim Herunterfahren ein Overlay schloss (#10026). – Behoben, dass übernommene Tastatureingaben verloren gingen, nachdem eine Maus click in einem /settings-Untermenü dieses geschlossen hatte. – Behoben, dass geerbte 1-stündige Anthropic-Cache-Schreibvorgänge über das Vercel AI Gateway zum 5-Minuten-Tarif abgerechnet wurden (#9210). – Behoben, dass geerbte samplingParams auf Modellebene durch direkte stream()/complete()-Aufrufe auf OpenAI-kompatiblen APIs gelöscht wurden (#9506). – Behoben, dass geerbte Mistral-GLM-Anfragen mit „Höchstens ein führender ThinkChunk erwartet“ nach leeren Inhaltsdeltas fehlschlugen (#9674). – Behoben, dass geerbte OpenAI-Fast-Modus-Anfragen zum Standardpreis abgerechnet wurden (#10034).
  • Behoben, dass geerbte Mistral-Denkungsmodelle die angeforderte Denkebene ignorierten (#9678). – Der geerbte OpenCode Zen- und OpenCode Go qwen3.8-flash-Dinge wurde behoben, der in späteren Runden als Klartext wiedergegeben wurde (#10047). – Geerbte OpenAI-Antwort-Streams von Servern, die output_index auslassen, wie z. B. llama.cpp, behoben und verwechselte Tool-Aufrufe ausgeführt; Solche Streams enden jetzt mit einem Fehler (#9974). – Behoben: Die geerbte Anthropic- und OpenAI-Codex-Browseranmeldung wartete auf unbestimmte Zeit, nachdem der Anbieter mit einem Autorisierungsfehler umgeleitet wurde, und die Anthropic-Anmeldung schlug fehl, wenn der Rückrufport verwendet wurde. – Der geerbte GitHub Copilot Claude Opus 5.5 wurde behoben, der nicht unterstützte Denkebenen anbot, wenn die Metadaten des Upstream-Modells unvollständig waren.

Englisches Original / English original

pi v0.99.0

New Features

  • Codemode and MCP — Connect MCP servers and let models run JavaScript that calls tools in parallel. See MCP Servers and Enable codemode.
  • System theme — Pi's colors now come from your terminal's own palette by default. See Use your terminal's colors.
  • Sign in with ChatGPT — Use a ChatGPT subscription with the OpenAI provider through /login openai. See Authenticate interactively.
  • Virtual models — Extensions can route each request to a different physical model. See Virtual Models.
  • Classifier models — Run Jev classifiers from codemode scripts, or use any llama.cpp model as a classifier. See How codemode works and Classification.

Added

  • Added codemode, tool search, and MCP support as built-in extensions. The codemode tool runs model-written JavaScript in a QuickJS sandbox that calls pi's tools; enable it with defaultTools or --tools and configure it with codemode.mode and codemode.inlineBudget. tool_search finds tools that are not declared to the model and declares them. MCP servers over stdio or streamable HTTP, with OAuth, come from mcp.json (global, or per project once trusted) or pi.registerMcpServer() and are managed with /mcp and pi mcp add|remove|list|login|logout. See MCP Servers and Enable codemode (#10040).
  • Added extension tool APIs for orchestrating tools: exposure (direct, model-only, codemode, deferred, or hidden), namespace, annotations, outputSchema with structuredContent, isError results, prepareLoadout(), and ctx.executeTool() for nested tool calls, which emit events with parentToolCallId and are recorded as bounded nestedCalls on the calling tool's result. See Tool exposure.
  • Added a warning when an extension that registers the same tool, command, or flag replaces a built-in extension (#10174 by @cristinaponcela).
  • Added experimental virtual models: extensions register them with pi.registerVirtualModel() and pick a physical model and thinking level for each request. The footer shows the routed model, /session lists cost per physical model, and examples/extensions/jev-router.ts routes with the Jev classifier. See Virtual Models.
  • Added Sign in with ChatGPT to the OpenAI provider in /login, which uses a ChatGPT subscription with the OpenAI API. Pi stores a stable deviceId in the global settings for this login and omits it from bug reports.
  • Added the system theme, now the default, which derives pi's colors from the terminal's reported foreground, background, and ANSI palette and rebuilds them when the terminal switches between light and dark. See Use your terminal's colors.
  • Added #rgb, oklch(), and okhsl() colors and an optional appearance field to theme files, and theme.style(), theme.colors, and theme.appearance for extensions. See Themes and TUI.
  • Added a classifier model for every llama.cpp chat model, answered from next-token label probabilities. See Classification.
  • Added inherited Jev classifier models on OpenRouter, Cloudflare Workers AI, Vercel AI Gateway, and OpenCode Zen.
  • Added the fullscreenWheelScrollLines setting and /settings entry for fullscreen mouse-wheel scrolling. The default "auto" accelerates fast wheel spins outside local macOS terminals (#9758).
  • Added per-input disposition to successful RPC prompt, steer, and follow_up responses, AgentSession.steer()/followUp(), and RpcClient.prompt()/steer()/followUp(); RpcClient.prompt() also accepts streamingBehavior (#9098, #9803).
  • Added image generation to ModelRuntime: generateImages() with runtime-resolved auth (stored credentials, OAuth, runtime API keys, models.json headers), plus getModelsOfType(), getModelOfType(), getAvailableOfType(), getAllModels(), and getAllAvailable(). OpenRouter image models are listed under the openrouter provider and share its credential; an upstream ID can have separate chat and image entries. models.json providers and extension registrations without a model list keep built-in image generation. Extension model lists can include discriminated chat, image, and classifier entries with operation implementations; when supplied, they replace the provider catalog across every operation. Chat-facing reads (getModels(), getAvailableSnapshot(), the model picker) are unchanged.
  • Added classifier support to ModelRuntime, including classify(), classifier model accessors, runtime-resolved authentication, and the built-in TypeSafe jev-latest model.
  • Added types=chat,image,classifier to pi.dev model catalog requests so remote refreshes overlay every supported model type; entries of unknown model types are ignored.
  • Added the provider_stream_event extension event for observing parsed provider events before normalization, with an opt-in /debug-provider example viewer (#9784, #9901 by @davidbrai).
  • Added a show/hide toggle (H) in HTML exports for custom messages marked display: false. Messages remain hidden by default and can also be revealed from the sidebar (#8896, #10020 by @rwachtler).
  • Added inherited Claude Sonnet 5.5 support for Anthropic with adaptive thinking and a 1M context window.
  • Added a Built-in section in pi config to disable the built-in mcp, llama.cpp, codemode, and tool-search extensions globally or per project, stored as -builtin:<name> in the extensions setting. SDK inline extensions opt in with builtin: true.
  • Added +name and -name entries to the defaultTools setting to add or remove tools without repeating the defaults, for example "defaultTools": ["+codemode"]. Project entries of this form apply on top of the user setting. Documented how to enable codemode without MCP and how to use classifier models such as Jev from codemode scripts.
  • Added the token usage and cost of codemode models.classify() calls to the codemode tool result, so they count toward the session cost; the codemode result shows each call's cost.

Changed

  • Switched the build from the TypeScript native preview to TypeScript 7.0 with an ES2024 target, and replaced tsx with Node's built-in type stripping for running from source (#9965).
  • Removed the [Themes] section from the startup banner. Custom themes remain available in /settings, and theme conflicts are still reported.
  • Changed the startup header to show the pi logo with the version instead of the app name.
  • Changed the built-in dark and light themes to the revised pi colors, written in OKHSL.
  • Changed light/dark terminal detection to use the reported background color first, then the terminal's light/dark report, then COLORFGBG. The first-time setup no longer shows the detected appearance.
  • Renamed the inherited OpenAI Codex provider to "OpenAI Codex (legacy)"; Sign in with ChatGPT on the OpenAI provider supersedes it.
  • Changed inherited terminal detection to treat TERM=*-direct as truecolor.
  • Built-in extensions and tools are named builtin:<name> (for example builtin:mcp and builtin:read) in errors, diagnostics, RPC source info, and bug reports, instead of <inline:name> and <builtin:name>. Their slash commands no longer carry a [t] autocomplete tag.
  • --no-extensions also disables the built-in extensions, including the llama.cpp provider. Load one explicitly with -e builtin:<name>, for example pi -ne -e builtin:mcp.
  • Tool calls without a custom call renderer, including direct MCP tool calls, now show their arguments: as key=value pairs on the title line when collapsed and one key: value line per argument when expanded. MCP calls are titled server/tool and their results collapse to 5 lines.
  • bash and powershell structured results, which codemode scripts receive, now hold up to 1 MiB of output instead of the model-facing 2000 lines or 50KB, and add truncated and full_output_path. Longer output keeps its first and last 512 KiB. Empty output is "" instead of (no output).

Fixed

  • Fixed X11 clipboard text being misidentified as an image when the clipboard owner accepts unadvertised image targets (#9786).
  • Prevented managed git packages from automatically installing Pi peer dependencies and added warnings for extension packages that list host-provided modules in dependencies (#9863).
  • Fixed pinned git extensions loaded with -e continuing to use the first downloaded commit after the ref changes (#9982).
  • Fixed RpcClient skipping the next event listener when a listener unsubscribes while handling an event, which could make waitForIdle() time out after collectEvents() (#9990).
  • Fixed full-file read calls rendering as :1 when models send null for omitted offset and limit (#9996).
  • Fixed new sessions being lost when pi exits before the first assistant response. The session file is now created when the first user message is sent (#10000).
  • Fixed unloaded llama.cpp autoload presets overwriting a cached runtime context window with the GGUF training context (#10077, #10158 by @cristinaponcela).
  • Fixed custom themes ignoring terminal.trueColor and other terminal capability overrides and rendering with 256 colors (#9973, #10039 by @christianklotz).
  • Fixed pasting files copied in Finder inserting the file icon image instead of the file paths; paths are quoted in bash mode (#9999, #10136 by @christianklotz).
  • Fixed the startup header, loaded resources, and chat notices keeping their old colors after a theme change.
  • Fixed the Fireworks default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Fixed the OpenCode Go default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Fixed the Together default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Reduced CPU use while streaming in long sessions and when previewing themes: the footer caches session usage totals, collapsed bash results cache their preview, and sanitizeBinaryOutput() no longer splits output into per-character arrays.
  • Fixed the usage of tools called through ctx.executeTool(), for example from codemode scripts, being dropped from the session cost; it is now added to the calling tool's result usage.
  • Fixed inherited /skill autocomplete appearing empty when loaded skill names did not contain the letters in skill (#9944).
  • Fixed inherited path and @ autocomplete not working after opening wrappers such as (, [, {, <, or a backtick.
  • Fixed inherited image stretching in terminals that use the Kitty graphics protocol (#8938, #9957 by @rwachtler).
  • Fixed inherited shell cursor staying hidden after exit when an extension closed an overlay during shutdown (#10026).
  • Fixed inherited keyboard input being lost after a mouse click in a /settings submenu closed it.
  • Fixed inherited 1-hour Anthropic cache writes through Vercel AI Gateway being priced at the 5-minute rate (#9210).
  • Fixed inherited model-level samplingParams being dropped by direct stream()/complete() calls on OpenAI-compatible APIs (#9506).
  • Fixed inherited Mistral GLM requests failing with "Expected at most one leading ThinkChunk" after empty content deltas (#9674).
  • Fixed inherited OpenAI Fast mode requests being priced at the standard rate (#10034).
  • Fixed inherited Mistral reasoning models ignoring the requested thinking level (#9678).
  • Fixed inherited OpenCode Zen and OpenCode Go qwen3.8-flash thinking being replayed as plain text on later turns (#10047).
  • Fixed inherited OpenAI Responses streams from servers that omit output_index, such as llama.cpp, running mixed-up tool calls; such streams now end with an error (#9974).
  • Fixed inherited Anthropic and OpenAI Codex browser sign-in waiting indefinitely after the provider redirected with an authorization error, and Anthropic sign-in failing when its callback port is in use.
  • Fixed inherited GitHub Copilot Claude Opus 5.5 offering unsupported thinking levels when upstream model metadata is incomplete.
