Verteilt

  • LocalTensor:
    • LocalTensor ist ein leistungsstarkes Debugging- und Simulationstool im verteilten Tensor-Ökosystem von PyTorch. Damit können Sie verteilte Tensorberechnungen über mehrere SPMD-Ränge (Single Program, Multiple Data) in einem einzigen Prozess simulieren. Dies ist unglaublich wertvoll für: 1) das Debuggen von verteiltem Code, ohne mehrere Prozesse hochzufahren; 2) Verständnis des DTensor-Verhaltens durch Untersuchung der Tensorzustände pro Rang; 3) Testen von DTensor-Operationen mit ungleichmäßigem Sharding über die Ränge hinweg; 4) rapid Prototyping verteilter Algorithmen. Beachten Sie, dass LocalTensor nur für Debugging-Zwecke konzipiert ist. Es verursacht einen erheblichen Overhead und eignet sich nicht für verteiltes Produktionstraining. – LocalTensor ist eine torch.Tensor-Unterklasse, die intern eine Zuordnung von Rang-IDs zu lokalen Tensor-Shards enthält. Wenn Sie eine PyTorch-Operation auf einem LocalTensor ausführen, wird die Operation unabhängig auf jeden lokalen Shard angewendet und ahmt verteilte Berechnungen nach (LocalTensor simuliert kollektive Operationen lokal ohne tatsächliche Netzwerkkommunikation). LocalTensorMode ist der Kontextmanager, der den LocalTensor-Versand ermöglicht. Es fängt PyTorch-Operationen ab und leitet sie entsprechend weiter. Der @maybe_run_for_local_tensor-Dekorator ist für die Handhabung rangspezifischer Logik bei der Implementierung von verteiltem Code unerlässlich. – Um mit LocalTensor zu beginnen, importieren Benutzer aus torch.distributed._local_tensor, initialisieren eine gefälschte Prozessgruppe und verpacken ihren verteilten Code in einen LocalTensorMode-Kontext. In diesem Zusammenhang erzeugen DTensor-Operationen automatisch LocalTensors.
    • PRs: (#164537, #166595, #168110,#168314,#169088,#169734)

Distributed

  • LocalTensor:

    • LocalTensor is a powerful debugging and simulation tool in PyTorch's distributed tensor ecosystem. It allows you to simulate distributed tensor computations across multiple SPMD (Single Program, Multiple Data) ranks on a single process. This is incredibly valuable for: 1) debugging distributed code without spinning up multiple processes; 2) understanding DTensor behavior by inspecting per-rank tensor states; 3) testing DTensor operations with uneven sharding across ranks; 4) rapid prototyping of distributed algorithms. Note that LocalTensor is designed for debugging purposes only. It has significant overhead and is not suitable for production distributed training.
    • LocalTensor is a torch.Tensor subclass that internally holds a mapping from rank IDs to local tensor shards. When you perform a PyTorch operation on a LocalTensor, the operation is applied independently to each local shard, mimicking distributed computation (LocalTensor simulates collective operations locally without actual network communication.). LocalTensorMode is the context manager that enables LocalTensor dispatch. It intercepts PyTorch operations and routes them appropriately. The @maybe_run_for_local_tensor decorator is essential for handling rank-specific logic when implementing distributed code.
    • To get started with LocalTensor, users import from torch.distributed._local_tensor, initialize a fake process group, and wrap their distributed code in a LocalTensorMode context. Within this context, DTensor operations automatically produce LocalTensors.
    • PRs: (#164537, #166595, #168110,#168314,#169088,#169734)
