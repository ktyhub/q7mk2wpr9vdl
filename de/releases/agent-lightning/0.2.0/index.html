agent-lightning v0.2.0

Agent-Lightning v0.2.0 führt wichtige Framework-Verbesserungen, neue Ausführungsstrategien, erweiterte Dokumentation und verbesserte Zuverlässigkeit im gesamten Agentenschulungs- und Bereitstellungsworkflow ein. Diese Version enthält 78 Pull-Requests seit v0.1.2.

Kernverbesserungen

  • Lightning Store: Einheitliche Schnittstelle und Implementierung für den Kernspeicher von Agent-Lightning hinzugefügt.
  • Emitter: Gibt beliebige Objekte als Spannen an den Speicher aus.
  • Adapter und Tracer: Anpassung an OpenAI-ähnliche Nachrichten und OpenTelemetry-Dummy-Tracer.
  • LLM-Proxy: LLM-Proxy als erstklassiger Bürger in Agent-Lightning hinzugefügt.
  • Agent Runner: Neue Version mit einem modulareren und robusteren Runner-Design.
  • Eingebettete Algorithmen: Der Einfachheit halber sind Algorithmen jetzt direkt in Trainer eingebettet.
  • Neue Ausführungsstrategien: Einführung der Ausführungsmodelle Client-Server und Shared Memory.
  • Trainer-Updates: Integrierte v0.2-Schnittstellen und FastAlgorithm-Validierung.

Dokumentation und Beispiele

  • Überarbeitete Dokumentation mit neuen Anleitungen für Agentenerstellung, Schulung, Debugging und Store-Konzepte.
  • Verbesserte Schnellstart-Tutorials, klarere Installation und neue ausführliche Artikel.
  • Hinzugefügte und aktualisierte Beispiele: SQL Agent, Calc-X, Local SFT, Search-R1 und APO-Algorithmus.

Entwicklererfahrung

  • Build- und CI-Pipelines zu 1ES migriert, Arbeitsabläufe aufgeteilt und Abzeichen zur besseren Übersichtlichkeit zusammengefasst.
  • uv als Abhängigkeitsmanager übernommen.
  • GPU-basierte Pytest-Workflows für vollständige Testabdeckung hinzugefügt.
  • Verbesserte Debugging-UX, Pre-Commit-Konfigurationen und Linting (Pyright-Korrekturen, Importsortierung).

Ökosystem und Integrationen

  • Unterstützung für Agenten hinzugefügt, die mit Agent-Framework erstellt wurden.
  • Neue Community-Einträge hinzugefügt: DeepWerewolf und AgentFlow.

agent-lightning v0.2.0

Highlights

  • Lightning Store and the span pipeline — v0.2.0 lands a unified storage interface (Lightning Store), an Emitter that writes arbitrary objects into it as spans, and Adapter/Tracer layers that normalize OpenAI-style messages and supply a no-op OpenTelemetry tracer. This is the new backbone for capturing and inspecting agent trajectories: if you had custom logging or trace plumbing in v0.1.x, plan to rewire it onto the store instead of maintaining a parallel path.

  • LLM Proxy becomes a first-class citizen — The proxy is promoted from edge utility to a core primitive, giving you one interception point for model calls (logging, replay, reward attribution) rather than patching each provider client. Combined with the modular Agent Runner rewrite, the integration shape changes — instrumentation now lives at the proxy boundary, so custom client wrappers need to be migrated to hook there.

  • Client-Server and Shared Memory execution strategies — Two new execution models join the runner, letting you trade process isolation against IPC overhead. This is a real deployment decision: choose Shared Memory to avoid serialization costs on a single host, Client-Server when agents and trainer run on different machines. Validate your topology against these strategies before upgrading, since the runner contract has changed.

  • Embedded algorithms and trainer interface updates — Algorithms now ship embedded directly inside trainers, and trainers integrate the v0.2 interfaces with FastAlgorithm validation. This is the most migration-relevant change: out-of-tree algorithm wiring from v0.1.x must be folded into the embedded model, and FastAlgorithm validation may reject previously permissive configs — budget time to rework custom trainers.

  • Toolchain shift to uv and 1ES CI — Dependency management moves to uv, build/CI migrates to 1ES with split workflows and aggregate badges, and GPU-based pytest workflows add broader coverage. Contributors must switch lockfiles and local commands, and maintainers may need to reconfigure branch protections/badges after the workflow split — but the payoff is more consistent CI signal and full GPU-backed test coverage.

  • Agent-framework support and refreshed docs/examples — First-class support for agents built with Microsoft Agent-framework arrives alongside revamped guides (agent creation, training, debugging, store concepts) and updated examples (SQL Agent, Calc-X, Local SFT, Search-R1, APO). Good news for adoption — the learning curve is lower — but older tutorials are now stale, so follow the v0.2 docs rather than cached versions.

No formally declared breaking changes in the upstream release notes.

Agent-Lightning v0.2.0 introduces major framework improvements, new execution strategies, expanded documentation, and enhanced reliability across the agent training and deployment workflow. This release includes 78 pull requests since v0.1.2.

Core Enhancements

  • Lightning Store: Added unified interface and implementation for Agent-lightning's core storage.
  • Emitter: Emitting any objects as spans to the store.
  • Adapter and Tracer: Adapting to OpenAI-like messages, and OpenTelemetry dummy tracer.
  • LLM Proxy: Added LLM Proxy as the first-class citizen in Agent-lightning.
  • Agent Runner: New version providing a more modular and robust runner design.
  • Embedded Algorithms: Algorithms are now embedded directly into trainers for simplicity.
  • New Execution Strategies: Introduced Client-Server and Shared Memory execution models.
  • Trainer Updates: Integrated v0.2 interfaces and FastAlgorithm validation.

Documentation & Examples

  • Revamped documentation with new guides for agent creation, training, debugging, and store concepts.
  • Improved quickstart tutorials, clarified installation and new deep-dive articles.
  • Added and updated examples: SQL Agent, Calc-X, Local SFT, Search-R1, and APO algorithm.

Developer Experience

  • Migrated build and CI pipelines to 1ES, split workflows and aggregate badges for clarity.
  • Adopted uv as the dependency manager.
  • Added GPU-based pytest workflows for full test coverage.
  • Enhanced debugging UX, pre-commit configs, and linting (Pyright fixes, import sorting).

Ecosystem & Integrations

  • Added support for agents built with Agent-framework.
  • Added new community listings: DeepWerewolf and AgentFlow.

New Contributors

A warm welcome to our first-time contributors: @hzy46, @lunaqiu, @syeehyn, @linhx1999, @SiyunZhao, and @acured 🎉
