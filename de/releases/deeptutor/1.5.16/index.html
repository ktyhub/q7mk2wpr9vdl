DeepTutor v1.5.16 Release Notes

Veröffentlichungsdatum: 2026.08.22 v1.5.15 hat einen Capture-Posteingang unter dem Book Reader hinzugefügt und dadurch das Umblättern der Seiten verhindert. Das wird hier behoben, zusammen mit einer neuen verbundenen Wissensquelle – einer MarginNote 4-Bibliothek, die ihr eigenes Add-on füllt – und einer Reihe von Fehlern, die nur über ein bestimmtes Gateway erreichbar waren: Tool-Aufruf-IDs, die wuchsen, bis der Anbieter sie ablehnte, Einbettungen, die wegen eines Parameters abgelehnt wurden, den wir bewusst weggelassen haben, und eine Temperaturbegrenzung, die nur galt, wenn Sie die richtige Bindung benannt hatten. Drop-in – keine Migrationen, nichts, was neu indiziert werden muss.

Was ist neu?

MarginNote 4 als Wissensdatenbank

Verbinden Sie eine Bibliothek und das MN4-Add-on schiebt Ihre Notizen, Auszüge, Karten und Mindmap-Knoten hinein – kein Hochladen, kein Index, nichts, was aus MarginNote kopiert wird. Koppeln Sie ein Gerät über die Registerkarte Geräte der Bibliothek, fügen Sie das einmalige Token in das Add-on ein, und die Synchronisierungen werden schrittweise in einem Store eingetroffen, der DeepTutor besitzt. Wenn man diese Bibliothek aktiviert, läuft sie mit sieben eigenen Tools statt mit rag: Durchsuchen von Auszügen und Notiztexten, Lesen eines einzelnen Objekts, Auflisten nach Typ, Durchgehen der untergeordneten Elemente eines Dokuments, Folgen von Links, Filtern nach Tags und Lesen von Mindmap-Karten. Die Chat-Schleife übergibt ihnen den Zug wie bei einem Obsidian-Tresor, da eine Bibliothek, die keinen Index enthält, nichts zum Abrufen zum Teilen hat. Beigetragen als #931 von @evan188199-tech. Dies ist Phase eins – schreibgeschützte Navigation; eine Rückschreibung ist geplant.

Die Buchseiten werden erneut umgeblättert

Der Capture-Posteingang landete als zweites untergeordnetes Element der Flex-Zeile des Lesers, ohne diese Zeile zu einer Flex-Spalte zu machen, sodass h-full von PageReader zu auto reduziert wurde: Der Text hörte auf zu scrollen und die Fußzeile zum Umblättern wurde cli vollständig aus der Sicht entfernt. Eine einzeilige Layoutkorrektur; Jedes von uns ausgeführte Tor war während der Regression grün, da hier für Typen oder Tests nichts sichtbar ist.

Gestreamte Werkzeugaufruf-IDs hören auf zu wachsen

Ein Router vor einem OpenAI-kompatiblen Anbieter kann den gesamten Tool-Aufruf id bei jedem Delta-Chunk erneut senden. Drei Kernstandorte fügten es an, anstatt es zuzuweisen, sodass die ID um eine Kopie pro Block wuchs – #937 sah 47.241 Zeichen – und jenseits der 64-Zeichen-Obergrenze des Anbieters starb jede Runde mit Invalid 'messages[i].tool_calls[0].id': string too long und tauchte als „Ich konnte aus der Modellausgabe keine nützliche Antwort erzeugen“ auf. name hatte an beiden Standorten den gleichen Fehler, der bei diesem Gateway latent war und bei allen, die den Namen wiederholen, fatal war. Die drei Standorte teilen sich nun einen Akkumulator: id und name kommen als Ganzes an und werden zugewiesen, arguments kommt in Fragmenten an und wird verkettet.

Modellgrenzen folgen dem Modell, nicht der Route

Kimi-Modelle sperren die Temperatur serverseitig und lehnen einen expliziten Wert mit HTTP 400 ab. Die Überschreibung dafür existierte schon vor v1.5.5, wurde aber aus der Spezifikation der konfigurierten Bindung aufgelöst – daher wurde sie nie für #938 ausgelöst, der das Gewöhnliche tat und binding="openai" auf Moonshot zeigte. Es ist nicht die Route, die das Limit erzwingt, daher entscheidet die Route nicht mehr: Die konfigurierte Spezifikation gewinnt, wenn sie etwas über das Modell aussagt, andernfalls antwortet die eigene Herstellerspezifikation des Modells. Jede modellinterne Überschreibung ging auf die gleiche Weise hinter einer generischen Bindung verloren.

Einbettungen werden von einem Gateway wiederhergestellt, das encoding_format erfordert

ModelScope liest ein fehlendes encoding_format als '' und lehnt die Anfrage ab (#934); SiliconFlow lehnt es ab, wenn das Feld vorhanden ist, weshalb wir es weglassen. Auf beiden Seiten dieser Meinungsverschiedenheit werden die gleichen Qwen3-Einbettungsgewichte bereitgestellt, sodass keine Standard- und keine Modellfamilienregel beides erfüllen kann. Der glückliche Pfad ist byteidentisch – das Feld wird immer noch weggelassen – und eine 400, die sowohl den Parameter als auch den Wert benennt, den wir senden möchten, verdient mit encoding_format="float" genau einen Wiederholungsversuch.

Bilder in einem Index beschreiben parallel

Die LlamaIndex-Pipeline beschrieb extrahierte Bilder einzeln. Sie laufen jetzt gleichzeitig mit einem Timeout pro Bild und einer Fortschrittszeile, einstellbar über image_description_concurrency (Standard 4) und image_description_timeout_seconds (Standard 60). Ein Modell, das Bilder nicht akzeptiert, wird ohne sie nicht mehr erneut versucht – das Bild ist dort die Frage, und eine aus dem umgebenden Text erfundene Beschreibung würde als Tatsache indiziert. Beitrag als #933.

LightRAG konvergiert statt zu hängen

Transportfehler für eine LightRAG-Basis werden jetzt klassifiziert, bevor sie erneut versucht werden: Wiederholbare HTTP-Status erhalten bis zu drei begrenzte Versuche mit einem begrenzten Retry-After, alles andere schlägt sofort fehl und die beiden Wiederholungsebenen vervielfachen sich nicht mehr. Die Stornierung bereinigt die Daten, statt sie zu verlieren, und ein Codex-Transportfehler breitet sich aus, statt geschluckt zu werden. Beitrag als #940.

Sortiert

  • Indexierungsfortschrittszeilen sind übersetzbar. Alle 22 Produzenten haben hartcodiertes Englisch an die Protokollbox gesendet. Die Leitung trägt nun die Vorlage und ihre Werte und das Frontend rendert sie in Ihrer Sprache; Verbraucher ohne i18n – Protokolle, Snapshots, der CLI – lesen genau das, was sie zuvor gelesen haben.
  • Eine gelöschte Wissensdatenbank verfolgt Ihre Sitzungen nicht mehr. Ihr Name verbleibt in den Kontextchips jeder Sitzung (#936).
  • Das Entwicklungsimage Docker hat wieder ein Frontend. Sein Supervisor hat node scripts/dev.mjs für ein eigenständiges Produktionspaket ausgeführt, das keine Quellen, keine Konfigurationen und kein scripts/ enthält, sodass docker compose -f docker-compose.dev.yml up nicht mehr funktionierte (#906). Die Bühne nimmt nun den gesamten web/-Baum des Builders ein. Das Produktionsbild wurde nie beeinträchtigt.
  • Der Ablehnungstext eines Anbieters wird begrenzt, bevor er das Protokoll erreicht. Dieses Protokoll existiert, damit Sie deeptutor.jsonl an einen Fehlerbericht anhängen können, und einige Anbieter geben die abgelehnte Anfrage – Schemata, manchmal Nachrichten – wieder zurück (#930).
  • Zwei MarginNote-Bibliotheken können nicht mehr einen Speicher beanspruchen. „My Lib“ und „My/Lib“ leiten beide My_Lib.db ab; Bei der Registrierung wird die Kollision jetzt namentlich abgelehnt und durch das Löschen einer Bibliothek wird der dafür erstellte Store entfernt.
  • Die MN4-Gerätebrücke prüft zuerst die Anmeldeinformationen. /sync und /heartbeat haben ihren Speicher vor der Validierung des Tokens aufgelöst, sodass ein nicht authentifizierter POST eine Datenbank pro eindeutigem Header-Wert erstellt hat – und die Paarung hat in den Arbeitsbereich des Aufrufers geschrieben, während der Gerätepfad den Standardwert gelesen hat, der jede Synchronisierung für immer auf 403 setzen könnte.

Upgrade-Hinweise

pip install -U deeptutor; Docker-Benutzer ziehen ghcr.io/hkuds/deeptutor:latest. Keine Schemaänderungen, keine Neuindizierung, keine Migration.

  • Eine MarginNote 4-Bibliothek beginnt leer. Schließen Sie sie an, koppeln Sie ein Gerät über die Registerkarte Geräte und fügen Sie dann das einmalige Token in das MN4-Add-on ein – das Token wird einmal angezeigt und nur sein Hash bleibt erhalten. Der Speicher befindet sich unter data/user/marginnote4/<name>.db und wird mit der Bibliothek gelöscht. Nichts in MarginNote selbst wird berührt.
  • MarginNote-Bibliotheken werden nicht von rag durchsucht. Wie ein Obsidian-Tresor sind sie nur über ihre eigenen Tools erreichbar, sodass Book und rag_search sie überspringen, anstatt ein leeres Ergebnis zu melden.
  • Die neuen Bildbeschreibungsknöpfe gelten für die nächste Indexerstellung, nicht für die nächste Frage, und sind unter Einstellungen → Wissensdatenbank verfügbar. Voll Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.15...v1.5.16

DeepTutor v1.5.16

Highlights

  • MarginNote 4 knowledge bases — This read-only integration incrementally syncs notes, excerpts, cards, and mind-map nodes into a DeepTutor-owned SQLite store, using seven dedicated tools instead of rag (#931). Pair a device under Devices, then paste the one-time token into the add-on; libraries start empty, are skipped by Book and rag_search, and their stores are deleted with the library.

  • Streaming tool calls no longer corrupt IDs — OpenAI-compatible gateways may repeat complete id and name values in every delta; three call sites appended them, producing a 47,241-character ID in #937 and provider-side string too long failures. IDs and names are now assigned whole, while only fragmented arguments are concatenated.

  • Model limits now follow the model — Intrinsic overrides such as Kimi’s locked temperature resolve from the model’s configured or vendor spec rather than the route’s binding spec. This fixes generic configurations such as binding="openai" pointing at Moonshot (#938) and restores other model-specific overrides previously hidden behind generic bindings.

  • Targeted embedding gateway fallback — Requests still omit encoding_format by default, preserving SiliconFlow compatibility. Only a 400 naming both the missing parameter and the intended value triggers one retry with encoding_format="float", accommodating ModelScope without breaking the normal path (#934).

  • Indexing and retrieval hardening — Image descriptions now run concurrently with a default concurrency of 4 and a 60-second per-image timeout; these settings apply to the next index build, and vision-incapable models no longer receive invented text-only descriptions (#933). LightRAG retries are now limited to transient HTTP statuses, capped at three attempts with bounded Retry-After, and no longer multiply across retry layers; cancellation cleanup and Codex transport error propagation also improve (#940).

  • Upgrade — Drop-in: no schema migration or re-indexing required. No breaking changes.

DeepTutor v1.5.16 Release Notes

Release Date: 2026.08.22

v1.5.15 added a capture inbox under the Book reader and, in doing so, stopped its pages from turning. That is fixed here, alongside a new connected knowledge source — a MarginNote 4 library that its own add-on fills — and a run of failures that were only reachable through a particular gateway: tool-call ids that grew until the provider refused them, embeddings rejected for a parameter we deliberately omit, and a temperature limit that only applied if you had named the right binding. Drop-in — no migrations, nothing to re-index.

What's New

MarginNote 4 as a knowledge base

Connect a library and the MN4 add-on pushes your notes, excerpts, cards and mindmap nodes into it — no upload, no index, nothing copied out of MarginNote. Pair a device from the library's Devices tab, paste the one-time token into the add-on, and syncs arrive incrementally into a store DeepTutor owns.

A turn on that library runs on seven tools of its own rather than on rag: search across excerpt and note text, read a single object, list by type, walk a document's children, follow links, filter by tag, and read mindmap cards. The chat loop hands the turn to them the way it does for an Obsidian vault, because a library that holds no index has nothing for retrieval to chunk.

Contributed as #931 by @evan188199-tech. This is phase one — read-only navigation; write-back is planned.

Book pages turn again

The capture inbox landed as a second child of the reader's flex row without making that row a flex column, so PageReader's h-full collapsed to auto: the body stopped scrolling and the page-turn footer was clipped out of view entirely. A one-line layout fix; every gate we run was green through the regression, since nothing here is visible to types or tests.

Streamed tool-call ids stop growing

A router in front of an OpenAI-compatible provider may re-send the whole tool-call id on every delta chunk. Three core sites appended it instead of assigning it, so the id grew one copy per chunk — #937 saw 47,241 characters — and past the provider's 64-character ceiling every round died with Invalid 'messages[i].tool_calls[0].id': string too long, surfacing as "I could not produce a useful response from the model output." name had the identical defect at both sites, latent on that gateway and fatal on any that repeats the name. The three sites now share one accumulator: id and name arrive whole and are assigned, arguments arrives in fragments and is concatenated.

Model limits follow the model, not the route

Kimi models lock temperature server-side and reject an explicit value with HTTP 400. The override for that has existed since before v1.5.5, but it was resolved from the configured binding's spec — so it never fired for #938, who did the ordinary thing and pointed binding="openai" at Moonshot. The route is not what enforces the limit, so the route no longer decides: the configured spec wins when it says something about the model, otherwise the model's own vendor spec answers. Every model-intrinsic override was being lost the same way behind a generic binding.

Embeddings recover from a gateway that demands encoding_format

ModelScope reads a missing encoding_format as '' and refuses the request (#934); SiliconFlow refuses it when the field is present, which is why we omit it. The same Qwen3-Embedding weights are served on both sides of that disagreement, so no default and no model-family rule can satisfy both. The happy path is byte-identical — the field is still omitted — and a 400 that names both the parameter and the value we are about to send earns exactly one retry with encoding_format="float".

Images in an index describe in parallel

The LlamaIndex pipeline described extracted images one at a time. They now run concurrently with a per-image timeout and a progress line, tunable via image_description_concurrency (default 4) and image_description_timeout_seconds (default 60). A model that turns out not to accept images is no longer retried without them — the image is the question there, and a description invented from the text around it would be indexed as fact. Contributed as #933.

LightRAG converges instead of hanging

Transport failures against a LightRAG base are now classified before they are retried: retryable HTTP statuses get up to three bounded attempts with a capped Retry-After, anything else fails immediately, and the two retry layers no longer multiply. Cancellation cleans up rather than leaking, and a Codex transport failure propagates instead of being swallowed. Contributed as #940.

Assorted

  • Indexing progress lines are translatable. All 22 producers sent hardcoded English to the log box. The wire now carries the template plus its values and the frontend renders it in your language; consumers without i18n — logs, snapshots, the CLI — read exactly what they read before.
  • A deleted knowledge base stops haunting your sessions. Its name lingered in each session's context chips (#936).
  • The development Docker image has a frontend again. Its supervisor ran node scripts/dev.mjs against a production standalone bundle that contains no sources, no configs and no scripts/, so docker compose -f docker-compose.dev.yml up came up dead (#906). The stage now takes the builder's whole web/ tree. The production image was never affected.
  • A provider's rejection body is capped before it reaches the log. That log exists so you can attach deeptutor.jsonl to a bug report, and some providers echo the rejected request — schemas, sometimes messages — back into it (#930).
  • Two MarginNote libraries can no longer claim one store. "My Lib" and "My/Lib" both derive My_Lib.db; registration now rejects the collision by name, and deleting a library removes the store we created for it.
  • The MN4 device bridge checks the credential first. /sync and /heartbeat resolved their store before validating the token, so an unauthenticated POST created a database per distinct header value — and pairing wrote into the caller's workspace while the device path read the default one, which could 403 every sync forever.

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No schema changes, no re-index, no migration.

  • A MarginNote 4 library starts empty. Connect it, pair a device from the Devices tab, then paste the one-time token into the MN4 add-on — the token is shown once and only its hash is kept. The store lives at data/user/marginnote4/<name>.db and is deleted with the library; nothing in MarginNote itself is touched.
  • MarginNote libraries are not swept by rag. Like an Obsidian vault, they are reached only through their own tools, so Book and rag_search skip them instead of reporting an empty result.
  • The new image-description knobs apply to the next index build, not the next question, and live under Settings → Knowledge Base.
