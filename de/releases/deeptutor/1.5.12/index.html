DeepTutor v1.5.12 Release Notes

Veröffentlichungsdatum: 2026.08.13 In v1.5.11 ging es darum, was passiert, während eine Antwort geschrieben wird. Hier geht es darum, woher das Material kommt. Die Web-Suchebene wurde in einer einzigen Tabelle neu aufgebaut – so wurden drei Fehler gefunden, die Ihnen stillschweigend Ergebnisse gekostet hatten – und darüber hinaus wurden sechs Anbieter hinzugefügt, von denen die meisten vom chinesischen Festland aus erreichbar sind. Eine sechste Engine zum Parsen von Dokumenten wird aktiviert, und ein MCP-Server, dessen Anmeldeinformationen Sie geändert haben, stellt nun eine erneute Verbindung her, anstatt mit der einen Erklärung zu antworten, die die wahre Ursache ausschließt. Drop-in – keine Migrationen, nichts, was neu indiziert werden muss.

Was ist neu?

Websuche neu aufgebaut, mit sechs neuen Anbietern

Die Anbieterliste war an sieben Stellen kopiert worden – die Backend-Registrierung, die Laufzeitkonfiguration, den Einstellungsrouter, den CLI-Assistenten, den Frontend-Katalog, i18n und die Tests – und sie waren auseinandergedriftet; Das Frontend war als „Serper veraltet“ gekennzeichnet, während das Backend es noch anbot. Alle sieben stammen jetzt aus einer SEARCH_PROVIDERS-Spezifikationstabelle. Bei der Konsolidierung traten drei stille Mängel ans Licht: Serpers num erreichte nie den API, also hat max_results nichts unternommen; Serper hat seine Proxy-Konfiguration aufgegeben; und Jina hatte überhaupt kein Ergebniszähllimit. An diesem Tisch schließen sich sechs Anbieter an: Doubao, Bocha, Zhipu, Firecrawl, Baidu Qianfan und Aliyun IQS. Sie erscheinen unter Einstellungen → Katalog → Suche mit ihren aus der Spezifikation abgeleiteten Anmeldeinformationsfeldern, und deeptutor init bietet sie auch an. Doubao gibt eine Antwort und nicht nur Links zurück; Firecrawl fügt die Ganzseitenextraktion hinzu. Baidu kehrt als qianfan auf dem offiziellen Qianfan API zurück – der alte baidu-Schlüssel bleibt veraltet und wird nicht wiederbelebt.

Ein Suchfehler lässt den Zug nicht mehr scheitern

Ein Ratenlimit, eine Zeitüberschreitung oder ein nicht erreichbarer Host führten dazu, dass der gesamte Zug beendet wurde. Die Anfrage durchläuft nun Ihre anderen angemeldeten Suchprofile und schließlich DuckDuckGo und zeichnet auf, was sie versucht hat, unter einem search_fallback-Schlüssel der obersten Ebene, sodass die Ablaufverfolgung die Herabstufung anzeigt, anstatt sie zu verbergen. Der Proxy wandert mit der Anfrage, sodass ein Fallback immer noch von hinten funktioniert. Ein fehlender API-Schlüssel wird als umgekehrtes Problem behandelt und schlägt bei den sechs neuen Anbietern trotzdem sofort fehl. Fünf davon werden in China gehostet, und DuckDuckGo ist in diesen Netzwerken nicht erreichbar – ein stillschweigendes Downgrade würde dazu führen, dass „Sie haben keinen Schlüssel konfiguriert“ an anderer Stelle zu einem unerklärlichen Timeout führt.

LiteParse schließt sich den Parsing-Engines an

Eine sechste Engine zum Parsen von Dokumenten, auswählbar unter Einstellungen → Wissensdatenbank neben Nur-Text, MinerU, Docling, Markitdown und PyMuPDF4LLM. Leicht, ohne lokale Modell-Downloads. Mit pip install deeptutor[parse-liteparse] installieren.

MCP-Server verbinden sich erneut, wenn sich Anmeldeinformationen ändern

Durch das Rotieren eines gespeicherten Berechtigungsnachweises blieb die Live-Verbindung unberührt: Die gespeicherte Konfiguration enthielt immer noch eine ${secret:...}-Referenz, sodass ihr Fingerabdruck byteidentisch war und der Reload-Diff zu dem Schluss kam, dass sich nichts geändert hatte. Verbindungen werden jetzt anhand der aufgelösten Konfiguration per Fingerabdruck erfasst, sodass sich das Konto erneut mit dem Schlüssel verbindet, den es gerade festgelegt hat. Unabhängig davon wurde ein Transportfehler während eines Tool-Aufrufs – am häufigsten bei der Authentifizierung – innerhalb der eigenen Aufgabengruppe des SDK ausgelöst und ließ den Anrufer auf die volle Tool-Zeitüberschreitung warten, wobei er die einzige Ursache meldete, die ausgeschlossen worden war. Die Verbindung wird jetzt während des Anrufs überwacht, sodass der eigentliche Fehler darin besteht, was dem Modell und dem Benutzer in der Sekunde mitgeteilt wird, in der er dauert. URLs werden aus diesen Nachrichten entfernt, da ein Server seine Anmeldeinformationen in einem Abfrageparameter übertragen kann.

CodeBuddy und OrcaRouter

Zwei weitere Modellanbieter: CodeBuddy/WorkBuddy, der die CodeBuddy SDK-Authentifizierung validiert und bei Bedarf eine Browser-Anmeldung startet, und OrcaRouter, ein benanntes OpenAI-kompatibles Gateway, das sowohl für Chat als auch für Einbettungen verfügbar ist.

Codex behält seine Argumentationsbemühungen bei und kann sehen

Eine verwaltete Überschreibung des Argumentationsaufwands bleibt jetzt bestehen, anstatt zwischen Sitzungen zurückgesetzt zu werden, und OpenAI Codex ist als visionfähig markiert, sodass Bilder ihn erreichen, anstatt gelöscht zu werden. Gemini 3 und 2.5 Pro, die reasoning_effort="none" ablehnen, verwenden jetzt standardmäßig minimal – die niedrigste Stufe, die diese Familien akzeptieren.

Sortiert

  • RAG-Zitate lesen die strukturierte Nutzlast. Die Zitationsextraktion bevorzugt ToolResult.metadata["sources"] gegenüber dem Parsen der Textantwort, die normalerweise überhaupt keine Quellen ergab; Das Parsen bleibt der Fallback für ältere Spuren.
  • Antwort-Tool-Aufrufe sind nicht mehr Cross-Dispatch. Eine fehlende Ausgabeelement-ID wurde mit einem Literal fc_0 gefüllt und als Identität registriert, sodass der nächste Aufruf, der seine ID wegließ, in den Puffer des vorherigen Aufrufs aufgelöst und unter seinem Namen und seinen Argumenten ausgeführt wurde. Der Platzhalter ist kein Alias ​​mehr.
  • Meisterschaftspfade sind unabhängig von Chatsitzungen, sodass das Öffnen eines Pfads die Sitzung, in der Sie sich befanden, nicht mehr stört.
  • Der Chat-Verlauf wird nach dem Laden unten angezeigt, anstatt mitten beim Scrollen zu landen.
  • Die Assistentenausgabe rendert **bold** korrekt, wenn das Modell Streuabstände innerhalb der Markierungen ausgibt.
  • Das veraltete Typer-Extra ist aus beiden Verpackungsmanifesten verschwunden.

Upgrade-Hinweise

pip install -U deeptutor; Docker-Benutzer ziehen ghcr.io/hkuds/deeptutor:latest. Keine Schemaänderungen, keine Neuindizierung, keine Migration.

  • GET /api/v1/settings/provider-choices hat seine Form geändert. Jeder Eintrag im search-Array hat requires_api_key, requires_base_url, soft_fallback und status erhalten, und das Array gibt jetzt auch exa, baidu und openrouter mit status: "deprecated" zurück – absichtlich, damit ein client eine veraltete Konfiguration anhand eines falsch geschriebenen Namens erkennen kann. DeepTutors eigene UI-Filter auf status; Jeder andere Verbraucher, der das Array direkt rendert, zeigt drei veraltete Optionen an, bis er dasselbe tut.
  • get_providers_info()-Einträge erhalten requires_base_url, was deeptutor config show und die /api/v1/system-Diagnose erreicht.
  • Der Name eines unbekannten Suchanbieters wird jetzt auf DuckDuckGo zurückgesetzt, anstatt ihn zu erhöhen. Bisher wurden nur exa, baidu und openrouter herabgestuft und alle anderen unbekannten Namen erhöht. Ein expliziter none löst immer noch aus, da dies bedeutet, dass die Suche ausgeschaltet ist.
  • get_available_providers() gibt mehr als früher zurück. Es hat zuvor jeden Anbieter instanziiert und den Anmeldeinformationsfehler verschluckt, sodass es effektiv nur den aktiven Anbieter und die beiden gemeldet hat, die keinen Schlüssel benötigen; Es meldet jetzt jedes Profil, dessen Anmeldeinformationen vollständig sind.
  • Brave trägt in der CLI-Diagnose die Bezeichnung Brave, nicht Brave Search – die Benutzeroberfläche zeigte bereits den kürzeren Namen an. Vollständig Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.5.11...v1.5.12

DeepTutor v1.5.12

Highlights

  • Web search rebuilt on a single spec, plus six new providers — The provider list was copied into seven places and had drifted (the frontend marked Serper deprecated while the backend still served it); all now derive from one SEARCH_PROVIDERS table. Consolidation surfaced three silent defects: Serper never passed num, so max_results did nothing; Serper dropped its proxy config; Jina had no result-count limit. Doubao, Bocha, Zhipu, Firecrawl, Baidu Qianfan and Aliyun IQS join — five hosted in mainland China, with Doubao returning answers rather than just links and Firecrawl adding full-page extraction. Baidu arrives as qianfan on the official Qianfan API; the old baidu key stays deprecated rather than revived.

  • Search failures downgrade instead of ending the turn — Rate limits, timeouts and unreachable hosts now walk your other credentialed search profiles and finally DuckDuckGo, recording what was tried under a top-level search_fallback key in the trace, with the proxy carried along. A missing API key is deliberately the opposite case and still fails immediately for the six new providers: DuckDuckGo is unreachable from mainland China, so silent downgrading would disguise an unset key as a timeout elsewhere.

  • MCP credential rotation now reconnects for real — Connections were fingerprinted against the stored config, whose ${secret:...} reference stayed byte-identical after rotation, so reload saw no change; fingerprints now use the resolved config. A transport/auth failure during a tool call no longer leaves the caller waiting out the full tool timeout with the one cause already ruled out — the connection is watched during the call so the real error surfaces in seconds, with URLs redacted because servers can embed credentials in query strings.

  • New parser and model options, plus quieter correctness fixes — A sixth parsing engine, LiteParse (pip install deeptutor[parse-liteparse]), needs no local model download. CodeBuddy/WorkBuddy (browser sign-in when SDK auth is missing) and OrcaRouter (chat and embeddings) join as model providers; Codex now persists its reasoning effort across sessions and is marked vision-capable, while Gemini 3/2.5 Pro default to minimal because they reject reasoning_effort=\"none\". Notable fixes: RAG citations prefer ToolResult.metadata[\"sources\"] over parsing answer text, and the literal fc_0 placeholder no longer aliases Responses tool calls into dispatching under a previous call's identity.

  • Drop-in upgrade with one API contract to check — pip install -U deeptutor or ghcr.io/hkuds/deeptutor:latest; no schema changes, migration, or re-index, so this is not a no-op or metadata-only release. Breaking for custom consumers: GET /api/v1/settings/provider-choices search entries gained requires_api_key, requires_base_url, soft_fallback and status, and now include exa, baidu, openrouter as status: \"deprecated\" (the built-in UI filters on status; anything rendering the array raw must too); get_providers_info() gained requires_base_url in deeptutor config show and /api/v1/system; unknown provider names now fall back to DuckDuckGo (explicit none still raises); get_available_providers() reports all complete profiles rather than the active one; Brave is labelled Brave, not Brave Search, in CLI diagnostics. Upgrade if you depend on web search — especially from China — rotate MCP credentials, or consume these APIs; if none of that applies, the parser and model additions make it optional.

DeepTutor v1.5.12 Release Notes

Release Date: 2026.08.13

v1.5.11 was about what happens while an answer is being written. This one is about where its material comes from. The web-search layer was rebuilt onto a single table — which is how three defects that had been quietly costing you results got found — and six providers were added on top of it, most of them reachable from mainland China. A sixth document-parsing engine lands, and an MCP server whose credential you rotated now reconnects instead of answering with the one explanation that rules out the real cause. Drop-in — no migrations, nothing to re-index.

What's New

Web search rebuilt, with six new providers

The provider list had been copied into seven places — the backend registry, runtime config, the settings router, the CLI wizard, the frontend catalog, i18n, and the tests — and they had drifted apart; the frontend marked Serper deprecated while the backend still offered it. All seven now derive from one SEARCH_PROVIDERS spec table. Consolidating it surfaced three silent defects: Serper's num never reached the API, so max_results did nothing; Serper dropped its proxy configuration; and Jina had no result-count limit at all.

Six providers join on that table — Doubao, Bocha, Zhipu, Firecrawl, Baidu Qianfan, and Aliyun IQS. They appear in Settings → Catalog → Search with their credential fields derived from the spec, and deeptutor init offers them too. Doubao returns an answer rather than only links; Firecrawl adds full-page extraction. Baidu returns as qianfan on the official Qianfan API — the old baidu key stays deprecated rather than revived.

A search failure no longer fails the turn

A rate limit, timeout, or unreachable host used to end the whole turn. The request now walks your other credentialed search profiles and finally DuckDuckGo, recording what it tried under a top-level search_fallback key so the trace shows the downgrade instead of hiding it. The proxy travels with the request, so a fallback still works from behind one.

A missing API key is treated as the opposite kind of problem and still fails immediately for the six new providers. Five of them are China-hosted, and DuckDuckGo is unreachable on those networks — silently downgrading would turn "you did not configure a key" into an unexplained timeout somewhere else.

LiteParse joins the parsing engines

A sixth document-parsing engine, selectable in Settings → Knowledge Base alongside Text-only, MinerU, Docling, markitdown, and PyMuPDF4LLM. Lightweight, with no local model downloads. Install with pip install deeptutor[parse-liteparse].

MCP servers reconnect when a credential changes

Rotating a stored credential left the live connection untouched: the stored config still held a ${secret:...} reference, so its fingerprint was byte-identical and the reload diff concluded nothing had changed. Connections are now fingerprinted against the resolved config, so the account reconnects with the key it just set. Separately, a transport failure during a tool call — most often auth — was raised inside the SDK's own task group and left the caller waiting for the full tool timeout, reporting the one cause that had been ruled out. The connection is now watched during the call, so the real error is what the model and the user are told, in the second it took. URLs are redacted from those messages, since a server can carry its credential in a query parameter.

CodeBuddy and OrcaRouter

Two more model providers: CodeBuddy/WorkBuddy, which validates CodeBuddy SDK auth and starts a browser sign-in when needed, and OrcaRouter, a named OpenAI-compatible gateway available for both chat and embeddings.

Codex keeps its reasoning effort, and can see

A managed reasoning-effort override now persists instead of resetting between sessions, and OpenAI Codex is marked vision-capable, so images reach it rather than being dropped. Gemini 3 and 2.5 Pro, which reject reasoning_effort="none", now default to minimal — the lowest level those families accept.

Assorted

  • RAG citations read the structured payload. Citation extraction prefers ToolResult.metadata["sources"] over parsing the textual answer, which usually yielded no sources at all; parsing remains the fallback for older traces.
  • Responses tool calls no longer cross-dispatch. A missing output-item id was filled with a literal fc_0 and registered as an identity, so the next call that omitted its id resolved to the previous call's buffer and ran under its name and arguments. The placeholder is no longer an alias.
  • Mastery paths are independent of chat sessions, so opening a path no longer disturbs the session you were in.
  • Chat history settles at the bottom after loading, instead of landing mid-scroll.
  • Assistant output renders **bold** correctly when the model emits stray spacing inside the markers.
  • The obsolete Typer extra is gone from both packaging manifests.

Upgrade Notes

pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No schema changes, no re-index, no migration.

  • GET /api/v1/settings/provider-choices changed shape. Each entry in the search array gained requires_api_key, requires_base_url, soft_fallback, and status, and the array now also returns exa, baidu, and openrouter with status: "deprecated" — deliberately, so a client can tell a stale configuration from a misspelled name. DeepTutor's own UI filters on status; any other consumer that renders the array directly will show three deprecated options until it does the same.
  • get_providers_info() entries gained requires_base_url, which reaches deeptutor config show and the /api/v1/system diagnostics.
  • An unrecognized search provider name now falls back to DuckDuckGo rather than raising. Previously only exa, baidu, and openrouter were downgraded and any other unknown name raised. An explicit none still raises, because that means search is switched off.
  • get_available_providers() returns more than it used to. It previously instantiated each provider and swallowed the credential error, so it effectively reported only the active provider plus the two that need no key; it now reports every profile whose credentials are complete.
  • Brave is labelled Brave, not Brave Search, in CLI diagnostics — the UI already showed the shorter name.
