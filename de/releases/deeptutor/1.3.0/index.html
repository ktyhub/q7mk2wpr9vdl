DeepTutor v1.3.0

DeepTutor v1.3.0 Release Notes

Veröffentlichungsdatum: 2026.04.27

Highlights

Versionierte Wissensdatenbank-Indizes und Neuindizierungs-Workflow

Wissensdatenbanken behalten jetzt Vektorindizes pro Einbettungskonfiguration bei, anstatt ein llamaindex_storage/-Verzeichnis als die ganze Wahrheit zu behandeln. Jede neue Indexversion zeichnet eine eingebettete Signatur und Metadaten auf, sodass beim Wechseln des Modells der vorherige Index nicht mehr überschrieben werden muss und beim Zurückwechseln eine fertige Version wiederverwendet werden kann, wenn die Signatur übereinstimmt.

  • Versioniertes Speicherlayout – neue Indizes werden als flache version-N/-Verzeichnisse mit meta.json geschrieben; Legacy-Root- und verschachtelte llamaindex_storage-Layouts bleiben für bestehende Installationen lesbar.
  • Einbettungsfähige Lese- und Schreibvorgänge – RAG-Suche, Dokumentzusätze, Managerstatistiken und Lösch-/Bereinigungspfade lösen jetzt den Speicher über die aktive Einbettungssignatur auf. Wenn keine fertige Version mit dem aktuellen Einbettungsmodell übereinstimmt, gibt der Abruf ein klares needs_reindex-Signal zurück, anstatt später mit einem undurchsichtigen Speicherfehler fehlzuschlagen.
  • Neuindizierung im Hintergrund API – POST /api/v1/knowledge/{kb_name}/reindex erstellt eine KB anhand der aktiven Einbettungskonfiguration neu, streamt Protokolle über den vorhandenen Aufgabenkanal und gibt noop: true zurück, wenn bereits ein passender Bereitschaftsindex vorhanden ist.
  • Der Indexstatus wird auf der Benutzeroberfläche angezeigt – KB-Zusammenfassungen enthalten jetzt Metadaten der Indexversion, den Status der aktiven Übereinstimmung, Markierungen für eingebettete Nichtübereinstimmungen, den Fortschritt und die Bereitschaft zur Neuindizierung, sodass das Frontend erklären kann, warum eine KB neu erstellt werden muss.

Neuerstellung der Knowledge Management-Seite

Die Knowledge-Seite wurde von einem monolithischen Bildschirm in einen fokussierten Master-Detail-Arbeitsbereich für alltägliche KB-Vorgänge aufgeteilt.

  • Spezielle KB-Detailregisterkarten – Dateien, Dokumente hinzufügen, Indexversionen und Einstellungen sind jetzt als separate Abschnitte mit einer kompakten Kopfzeile verfügbar, die Anbieter, Einbettungsmodell, Standardstatus, Aktualisierungszeit und Live-Aufgabenstatus anzeigt.
  • Rohdateibrowser und Inline-Vorschau – Die neue Registerkarte „Dateien“ listet Dokumente aus dem KB-raw/-Verzeichnis auf und öffnet sie in einem Inline-Vorschaufenster, wobei die Chat-Vorschau-Pipeline für PDFs, Bilder, Markdown, Code/Text und Fallback-Downloads wiederverwendet wird. Die Dateiliste kann ausgeblendet werden, um Vorschauraum freizugeben.
  • Steuerelemente und Protokolle neu indizieren – Der Abschnitt „Versionen indizieren“ zeigt aktive, veraltete, veraltete und inaktive Versionen mit einer click-Aktion „Neu indizieren“ und Live-Prozessprotokollen für Neuerstellungsaufgaben.
  • Fortschritts- und Verlaufs-Hooks – useKnowledgeBases, useKnowledgeProgress und useKnowledgeHistory führen den Serverstatus mit dem Live-WebSocket/SSE-Fortschritt zusammen, aktualisieren aktive Arbeit automatisch und halten die Ergebnisse der letzten Erstellung/Upload/Neuindizierung sichtbar.

Einbettung von Laufzeit, Anbieterabdeckung und Dimensionserkennung

Der Einbettungsstapel wurde auf anbieterspezifisches Verhalten ausgerichtet, anstatt davon auszugehen, dass sich jeder Dienst wie der Standardendpunkt von OpenAI verhält. – Keine fest codierte 3072-Standardeinstellung mehr – die Einbettungsdimension beginnt jetzt als unbekannt/leer und wird nach einer erfolgreichen Testverbindung automatisch aus der Anbieterantwort ausgefüllt. Die Testsonde vermeidet bewusst das Senden von dimensions, sodass sie die native Vektorlänge des Modells vor einer Matryoshka-Kürzung misst.

  • Vollständige Endpunkt-URL-Semantik – httpx-basierte Einbettungsadapter behandeln jetzt EMBEDDING_HOST/Katalog-URLs als den genauen Endpunkt, der aufgerufen werden soll, während der neue openai_sdk-Adapter das SDK-artige /v1-Basis-URL-Verhalten beibehält. .env.example dokumentiert konkrete Endpunktbeispiele für OpenAI, Cohere, Jina, Ollama, SiliconFlow und Aliyun DashScope.
  • Neue Einbettungsadapter und Bindungen – offizielle OpenAI SDK-Einbettungsunterstützung, native multimodale Einbettungen von Aliyun DashScope, SiliconFlow-Voreinstellungen, OpenRouter/benutzerdefinierte OpenAI-SDK-Profile, Anbieter-Batch-Limits, multimodale Anbieter-Flags und anbieterspezifische API-Schlüssel-Fallbacks hinzugefügt.
  • Multimodale Einbettungsanfragen – EmbeddingRequest akzeptiert jetzt strukturiertes contents plus DashScope enable_fusion; Cohere v2, Jina, OpenAI-kompatible Gateways und DashScope verarbeiten multimodale Nutzlasten über ihre eigenen Adapterregeln.
  • Bessere Anbieterfehler – Einbettungsfehler behalten jetzt den Anbieterstatus, den Text, das Modell und den URL-Kontext bei, mit klarerer Handhabung für 4xx-Antworten und Nicht-JSON/HTML-Gateway-Antworten.

LLM Reasoning Streams und Vision Attachment Robustness

Argumentationsspuren und Bildanhänge fließen jetzt über mehr Anbieterpfade mit weniger anbieterspezifischen Überraschungen.

  • Begründungsdeltas – on_reasoning_delta ist über den Basis-LLM-Anbietervertrag, OpenAI-kompatibles Streaming, Azure SDK-Streaming, Anthropic Paths und OpenAI Responses-Analyse verbunden. Bei der Streaming-Ausgabe wird der Begründungstext in <think>...</think> eingeschlossen, bevor der normale Inhalt fortgesetzt wird.
  • DeepSeek-Argumentation-Standards – DeepSeek-Argumentationsmodellmuster können automatisch einen hohen Argumentationsaufwand einbringen, wenn der Aufrufer keinen angegeben hat, und passen zu Anbietern, die einen expliziten Wechsel zur Oberflächen-Thinking-Ausgabe erfordern.
  • Flags für Vision-URL-Funktionen – Anbieter-/Modellfunktionen unterscheiden jetzt zwischen „unterstützt Vision“ und „akzeptiert Bild-URLs“. Moonshot/Kimi-Vision-Modelle und Adapter im Anthropic-Stil erzwingen, wenn möglich, lokale Anhang-URLs in Inline-Base64.
  • Lokale Anhang-URL-Auflösung – /api/attachments/...-Bild-URLs können über den Anhangspeicher wieder aufgelöst und als Base64 an Anbieter gesendet werden, die Remote-URL-Formulare ablehnen; Nicht aufgelöste externe URLs werden als verworfene Bildeingaben gezählt, anstatt stillschweigend so zu tun, als wären sie gesendet worden.

Space Hub, Skills Tags und Personal Library UX

Persönliche Lernartefakte wurden in einem neuen Space-Bereich in der Seitenleiste gesammelt.

  • Raumnavigation – /space leitet zu /space/notebooks und den neuen Mini-Navigationsgruppen „Notizbücher“, „Fragenbank“, „Fähigkeiten“ und „Speicher“ mit einem gemeinsamen Abschnittskopfstil weiter.
  • Notizbuchbereich – Notizbücher können erstellt, gelöscht, durchsucht, geöffnet und mit gerenderten Datensatzvorschauen überprüft werden. Gespeicherte TutorBot-, Chat-, Recherche- und Co-Writer-Ausgaben erhalten eindeutige Abzeichen und können mit der ursprünglichen Chat-Sitzung verknüpft werden, wenn Metadaten verfügbar sind.
  • Abschnitt „Fragenbank“ – Quizeinträge können nach „Alle“, „Gemerkt“ oder „Nur falsch“ gefiltert, mit Kategorien gruppiert, umbenannt, aus Kategorien entfernt, mit Lesezeichen versehen, gelöscht und wieder in ihrem Quellkontext geöffnet werden.
  • Speicherbereich – die Speicherseite wird in den Bereich verschoben, mit Bearbeitungs-/Vorschaumodi für Zusammenfassung und Profil, manuelles Speichern, Aktualisierung aus Sitzung, klare Aktionen, Status nicht gespeicherter Änderungen und lokalisiertes Feedback.
  • Skills-Bereich – Von Benutzern erstellte Skills unterstützen jetzt Tags in Frontmatter sowie ein .tags.json-Vokabular. Der API fügt Tag-Listen/Erstellen/Umbenennen/Löschen von Endpunkten hinzu, und die Benutzeroberfläche kann nach Tags filtern, Tags verwalten, Fertigkeiten umbenennen und Tag-Zuweisungen bearbeiten, während der bestehende SKILL.md-Workflow erhalten bleibt.

Abhängigkeitsebenen, TutorBot-Debugging und Windows-Start

Die Installationsgeschichte wurde um Pyproject-Extras herum neu organisiert, wobei die Anforderungsdateien als Spiegel für Docker/CI-Umgebungen beibehalten wurden. Dies macht auch die TutorBot-Einrichtung und das Kanal-Debugging weniger eindeutig: Die Agent-Engine, die Kanal-SDKs, die nativen Abhängigkeiten von Matrix und die Importe von Kernserveranbietern befinden sich jetzt in klar getrennten Ebenen.

  • Extras-Hierarchie – .[cli] umfasst jetzt RAG, Dokumentparsing und integrierte Anbieter SDKs; .[server] baut auf CLI mit FastAPI/uvicorn auf; Die optionalen Layer-Funktionen .[tutorbot], .[matrix], .[math-animator], .[dev] und .[all] explizit.
  • TutorBot-Abhängigkeitsgrenze – requirements/tutorbot.txt spiegelt jetzt .[tutorbot], hängt von server.txt ab und behält Kanal-/Agent-Abhängigkeiten wie Cron, MCP, Telegram, Feishu/Lark, DingTalk, Slack, QQ, Socket.IO, Socks und Message-Pack-Tools in der TutorBot-Ebene, anstatt sie in die Basisinstallation zu mischen.
  • Aufteilung des Matrix-Kanals – Die Matrix-/Element-Unterstützung verfügt über ein eigenes .[matrix]-Extra und requirements/matrix.txt mit matrix-nio[e2e], Markdown-Bereinigungshilfen und expliziten libolm-Setup-Hinweisen für native Verschlüsselungsabhängigkeiten.
  • Laufzeitabhängigkeitskorrektur (#391) – loguru und json-repair wurden in die Serverabhängigkeitsschicht verschoben, da Provider-Core-Importe sie benötigen, bevor TutorBot beteiligt ist. Dies behebt saubere Serverinstallationen, die zuvor aufgrund fehlender Module abstürzten.
  • Windows-Launcher-Robustheit (#391, #398) – scripts/start_web.py liest jetzt die Ausgabe von Backend-/Frontend-Unterprozessen als UTF-8 mit Ersatz, wodurch UnicodeDecodeError auf Windows-Gebietsschemas wie GBK vermieden wird.
  • Dokumente und CLI-Hinweise – Die Fehlermeldungen README, chinesische README, CLI README und CLI verweisen Benutzer jetzt auf pip install -e ".[cli]" / pip install -e ".[server]" statt auf ältere Befehle, bei denen die Anforderungen an erster Stelle stehen. Ein neuer requirements/matrix.txt spiegelt das Matrix-Extra wider und dokumentiert die native libolm-Voraussetzung.

Fehlerbehebungen

  • Wissens-Upload/Diagnose erstellen (#392, #405) – KB-Initialisierungs-, Upload- und Neuindizierungsaufgaben geben jetzt Fehlerdetails und Stack-Traces über Aufgabenprotokolle weiter; Die Benutzeroberfläche kann umfangreichere Fehler anzeigen, anstatt den Anschein zu erwecken, dass sie nichts unternimmt, wenn die Hintergrundaufnahme fehlschlägt.
  • KB-Namensvalidierung – HTTP- und CLI-Erstellungspfade lehnen jetzt pfadähnliche oder URL-reservierte Zeichen ab und behalten gleichzeitig Unicode-freundliche Namen bei, wodurch ungültige KB-Ordner und unsichere Routen verhindert werden.
  • Dokumentenerkennung ohne Berücksichtigung der Groß-/Kleinschreibung – Das Scannen von KB-Verzeichnissen und die Dokumentensammlung CLI verwenden jetzt den Shared File Router, sodass Großbuchstabenerweiterungen wie .PDF und .MD konsistent akzeptiert werden.
  • Sicherere Dokumentdateinamen – hochgeladene Dateinamen werden normalisiert, Pfadfragmente werden entfernt und Erweiterungen werden vor der Validierung und Speicherung in Kleinbuchstaben geschrieben.
  • Rohdatei dient der Sicherheit – KB-Rohdatei-Endpunkte lösen Pfade ausschließlich im raw/-Verzeichnis auf und lehnen Durchlaufversuche ab.
  • Modellkatalog-Umgebungsüberlagerung – .env-Werte werden nur mit dem Katalog synchronisiert, solange dieser noch makellos aussieht, wodurch versehentliches Überschreiben vermieden wird, wenn Benutzer über mehrere benutzerdefinierte Profile verfügen.
  • Fallback für Forschungsberichte (#404) – Die JSON-Fallback-Warnung des Meldeagenten verwendet jetzt einen F-String, sodass Logger, die die %-Formatierung nicht anwenden, den Abschnittstitel weiterhin sauber einschließen.

Erweiterung der Testsuite

  • Wissen/RAG ​​– neue Abdeckung für KB-Benennung, Indexversionszuordnung und Lesepriorität, Legacy-zu-Flat-Speicherkompatibilität, LlamaIndex-Speicherlayout, Rohverzeichnisinitialisierung, Dateirouting ohne Berücksichtigung der Groß-/Kleinschreibung, KB-Löschung und API-Upload-Randfälle.
  • Einbettung/Konfiguration – neue Tests umfassen das automatische Ausfüllen von Dimensionen aus Testsonden, das Überlagerungsverhalten des Katalogs .env, DashScope- und OpenAI-Adapter SDK, Qwen3 send_dimensions, URL-Transparenz, Nicht-JSON-Anbieterantworten und multimodale Einbettungsanfragen.
  • LLM/multimodal – neue Tests validieren das Denk-/Sehfähigkeitsverhalten und die lokale URL-Konvertierung von Anhängen für Anbieter, die Inline-Base64-Bilder benötigen.
  • CLI und Validierung – CLI KB-Sammlungs- und Dokumentenvalidierungstests decken Großbuchstabenerweiterungen, chinesische Dateinamen und Pfadentfernung im Windows-Stil ab.

Community-Beiträge

  • @jonathanzhan1975 – Behebung des Windows-Serverstarts und fehlender Serverlaufzeitabhängigkeiten, die sich auf saubere Web-/TutorBot-Installationen auswirken (#391)
  • @kagura-agent – Reporting-Agent-Fallback-Protokollierung für JSON-Analysefehler bereinigen (#404) Die jüngsten offenen Diskussionen nach v1.2.5 prägten dieses Veröffentlichungsfenster ebenfalls, insbesondere Fehler beim Hochladen/Erstellen von KB (Nr. 392, Nr. 405), Neustart-/Statusberichte des TutorBot-Agenten (Nr. 385), Windows-Startberichte (Nr. 398), Probleme bei der Installation von Abhängigkeiten (Nr. 402), JSON-Robustheits-Feedback (Nr. 400) und die nächste Welle von Anfragen nach Speicherplatz/Speicher/Projektorganisation (Nr. 397, Nr. 401, #403). DeepTutor v1.3.0

DeepTutor v1.3.0 Release Notes

Release Date: 2026.04.27

Highlights

Versioned Knowledge Base Indexes and Re-index Workflow

Knowledge bases now keep vector indexes per embedding configuration instead of treating one llamaindex_storage/ directory as the whole truth. Each new index version records an embedding signature and metadata, so switching models no longer has to overwrite the previous index, and switching back can reuse a ready version when the signature matches.

  • Versioned storage layout — new indexes are written as flat version-N/ directories with meta.json; legacy root and nested llamaindex_storage layouts remain readable for existing installs.
  • Embedding-aware reads and writes — RAG search, document additions, manager statistics, and delete/cleanup paths now resolve storage through the active embedding signature. If no ready version matches the current embedding model, retrieval returns a clear needs_reindex signal instead of failing later with an opaque storage error.
  • Background re-index API — POST /api/v1/knowledge/{kb_name}/reindex rebuilds a KB against the active embedding configuration, streams logs through the existing task channel, and returns noop: true when a matching ready index already exists.
  • Index status surfaced to the UI — KB summaries now include index-version metadata, active-match state, embedding mismatch flags, progress, and re-index readiness so the frontend can explain why a KB needs rebuilding.

Knowledge Management Page Rebuild

The Knowledge page has been split from a monolithic screen into a focused master-detail workspace for day-to-day KB operations.

  • Dedicated KB detail tabs — Files, Add documents, Index versions, and Settings now live as separate sections with a compact header showing provider, embedding model, default status, update time, and live task status.
  • Raw file browser and inline preview — the new Files tab lists documents from the KB raw/ directory and opens them in an inline preview pane, reusing the chat preview pipeline for PDFs, images, Markdown, code/text, and fallback downloads. The file list can collapse to reclaim preview space.
  • Re-index controls and logs — the Index versions section shows active, stale, legacy, and inactive versions, with a one-click Re-index action and live process logs for rebuild tasks.
  • Progress and history hooks — useKnowledgeBases, useKnowledgeProgress, and useKnowledgeHistory merge server state with live WebSocket/SSE progress, auto-refresh active work, and keep recent create/upload/re-index outcomes visible.

Embedding Runtime, Provider Coverage, and Dimension Discovery

The embedding stack was tightened around provider-specific behavior instead of assuming every service behaves like OpenAI's default endpoint.

  • No more hard-coded 3072 default — embedding dimension now starts as unknown/empty and is auto-filled from the provider response after a successful test connection. The test probe deliberately avoids sending dimensions so it measures the model's native vector length before any Matryoshka truncation.
  • Full endpoint URL semantics — httpx-based embedding adapters now treat EMBEDDING_HOST / catalog URLs as the exact endpoint to call, while the new openai_sdk adapter keeps SDK-style /v1 base URL behavior. .env.example documents concrete endpoint examples for OpenAI, Cohere, Jina, Ollama, SiliconFlow, and Aliyun DashScope.
  • New embedding adapters and bindings — added official OpenAI SDK embedding support, Aliyun DashScope native multimodal embeddings, SiliconFlow presets, OpenRouter/custom OpenAI-SDK profiles, provider batch limits, multimodal provider flags, and per-provider API-key fallbacks.
  • Multimodal embedding requests — EmbeddingRequest now accepts structured contents plus DashScope enable_fusion; Cohere v2, Jina, OpenAI-compatible gateways, and DashScope handle multimodal payloads through their own adapter rules.
  • Better provider errors — embedding failures now preserve provider status, body, model, and URL context, with clearer handling for 4xx responses and non-JSON/HTML gateway replies.

LLM Reasoning Streams and Vision Attachment Robustness

Reasoning traces and image attachments now flow through more provider paths with less provider-specific surprise.

  • Reasoning deltas — on_reasoning_delta is wired through the base LLM provider contract, OpenAI-compatible streaming, Azure SDK streaming, Anthropic paths, and OpenAI Responses parsing. Streaming output wraps reasoning text in <think>...</think> before normal content resumes.
  • DeepSeek reasoning defaults — DeepSeek reasoning model patterns can auto-inject a high reasoning effort when the caller has not specified one, matching providers that require an explicit switch to surface thinking output.
  • Vision URL capability flags — provider/model capabilities now distinguish "supports vision" from "accepts image URLs." Moonshot/Kimi vision models and Anthropic-style adapters force local attachment URLs into inline base64 when possible.
  • Local attachment URL resolution — /api/attachments/... image URLs can be resolved back through the attachment store and sent as base64 to providers that reject remote URL form; unresolved external URLs are counted as dropped image inputs instead of silently pretending they were sent.

Space Hub, Skills Tags, and Personal Library UX

Personal learning artifacts have been gathered under a new Space area in the sidebar.

  • Space navigation — /space redirects to /space/notebooks and the new mini-nav groups Notebooks, Question Bank, Skills, and Memory with a shared section header style.
  • Notebooks section — notebooks can be created, deleted, searched, opened, and inspected with rendered record previews. Saved TutorBot, chat, research, and Co-Writer outputs receive distinct badges and can link back to the original chat session when metadata is available.
  • Question Bank section — quiz entries can be filtered by all/bookmarked/wrong-only, grouped with categories, renamed, removed from categories, bookmarked, deleted, and opened back in their source context.
  • Memory section — the Memory page moves into Space with edit/preview modes for summary and profile, manual save, refresh-from-session, clear actions, unsaved-change status, and localized feedback.
  • Skills section — user-authored skills now support tags in frontmatter plus a .tags.json vocabulary. The API adds tag list/create/rename/delete endpoints, and the UI can filter by tag, manage tags, rename skills, and edit tag assignments while preserving the existing SKILL.md workflow.

Dependency Layers, TutorBot Debugging, and Windows Startup

The install story has been reorganized around pyproject extras, with requirements files kept as mirrors for Docker/CI environments. This also makes TutorBot setup and channel debugging less ambiguous: the agent engine, channel SDKs, Matrix native dependencies, and core server provider imports now live in clearly separated layers.

  • Extras hierarchy — .[cli] now includes RAG, document parsing, and built-in provider SDKs; .[server] builds on CLI with FastAPI/uvicorn; .[tutorbot], .[matrix], .[math-animator], .[dev], and .[all] layer optional capabilities explicitly.
  • TutorBot dependency boundary — requirements/tutorbot.txt now mirrors .[tutorbot], depends on server.txt, and keeps channel/agent dependencies such as cron, MCP, Telegram, Feishu/Lark, DingTalk, Slack, QQ, Socket.IO, socks, and message-pack tooling in the TutorBot layer instead of mixing them into the base install.
  • Matrix channel split-out — Matrix / Element support has its own .[matrix] extra and requirements/matrix.txt, with matrix-nio[e2e], Markdown sanitization helpers, and explicit libolm setup notes for native encryption dependencies.
  • Runtime dependency fix (#391) — loguru and json-repair moved into the server dependency layer because provider-core imports need them before TutorBot is involved. This fixes clean server installs that previously crashed on missing modules.
  • Windows launcher robustness (#391, #398) — scripts/start_web.py now reads backend/frontend subprocess output as UTF-8 with replacement, avoiding UnicodeDecodeError on Windows locales such as GBK.
  • Docs and CLI hints — README, Chinese README, CLI README, and CLI error messages now point users to pip install -e ".[cli]" / pip install -e ".[server]" instead of older requirements-first commands. A new requirements/matrix.txt mirrors the Matrix extra and documents the native libolm prerequisite.

Bug Fixes

  • Knowledge upload/create diagnostics (#392, #405) — KB initialization, upload, and re-index tasks now propagate failure details and stack traces through task logs; the UI can show richer errors instead of appearing to do nothing when background ingestion fails.
  • KB name validation — HTTP and CLI creation paths now reject path-like or URL-reserved characters while preserving Unicode-friendly names, preventing invalid KB folders and unsafe routes.
  • Case-insensitive document discovery — KB directory scanning and CLI document collection now use the shared file router, so uppercase extensions such as .PDF and .MD are accepted consistently.
  • Safer document filenames — uploaded filenames are normalized, path fragments are stripped, and extensions are lowercased before validation and storage.
  • Raw file serving safety — KB raw-file endpoints resolve paths strictly under the raw/ directory and reject traversal attempts.
  • Model catalog environment overlay — .env values are only synced into the catalog while it still looks pristine, avoiding accidental overwrites once users have multiple custom profiles.
  • Research reporting fallback (#404) — the reporting agent's JSON-fallback warning now uses an f-string so loggers that do not apply % formatting still include the section title cleanly.

Test Suite Expansion

  • Knowledge/RAG — new coverage for KB naming, index-version allocation and read priority, legacy-to-flat storage compatibility, LlamaIndex storage layout, raw directory initialization, case-insensitive file routing, KB deletion, and API upload edge cases.
  • Embedding/config — new tests cover dimension auto-fill from test probes, catalog .env overlay behavior, DashScope and OpenAI SDK adapters, Qwen3 send_dimensions, URL transparency, non-JSON provider responses, and multimodal embedding requests.
  • LLM/multimodal — new tests validate reasoning/vision capability behavior and local attachment URL conversion for providers that require inline base64 images.
  • CLI and validation — CLI KB collection and document validator tests cover uppercase extensions, Chinese filenames, and Windows-style path stripping.

Community Contributions

  • @jonathanzhan1975 — Fix Windows server startup and missing server runtime dependencies affecting clean Web/TutorBot installs (#391)
  • @kagura-agent — Clean up reporting-agent fallback logging for JSON parse failures (#404)

Recent open discussions after v1.2.5 also shaped this release window, especially KB upload/create failures (#392, #405), TutorBot Agent restart/state reports (#385), Windows startup reports (#398), dependency-installation pain (#402), JSON robustness feedback (#400), and the next wave of Space/Memory/project organization requests (#397, #401, #403).
