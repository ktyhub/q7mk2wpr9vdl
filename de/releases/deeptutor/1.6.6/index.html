DeepTutor v1.6.6 Release Notes

Veröffentlichungsdatum: 2026.09.08 v1.6.6 ist eine Fixversion und eine ungewöhnlich klarstellende Version. Die Durchsicht des v1.6.5-Feedbacks zeigte, dass es sich bei den meisten Meldungen nicht um eine Regression handelte: v1.6.5 entfernte größtenteils Dinge, die ältere Fehler maskiert hatten, also Antworten, die stillschweigend nicht übermittelt werden konnten, eine Schaltfläche zum Kopieren, die Erfolg meldete, die es nie gegeben hatte, und unbrauchbare Leseaktionen, da v1.6.0 alles auf einmal sichtbar wurde. Diese werden hier behoben, zusammen mit den dahinter stehenden Community-Pull-Requests. Drop-in – keine Migrationen.

Was ist neu?

Antworten, die Sie einreichen, kommen tatsächlich an

Eine ask_user-Karte, deren Zug bereits beendet war, konnte das Backend nicht mehr erreichen, sodass das Absenden nichts bewirkte. Schlimmer noch, die drei Komponisten verwarfen, was Sie eingegeben hatten, als eine Einreichung abgelehnt wurde, während der Fehler Sie aufforderte, eine neue Nachricht zu senden – was genau das war, was blockiert wurde. Beides ist festgelegt: Eine beendete Runde, die noch eine unbeantwortete Karte besitzt, behält ihre Adresse, und eine abgelehnte Antwort wird als normale Nachricht erneut gesendet, anstatt weggeworfen zu werden. Notizbucheinträge mit Antwortbildern konnten seit v1.6.3 überhaupt nicht mehr gespeichert werden – die Einfügung listete 23 Spalten gegenüber 22 Werten auf und erhöhte jedes Mal OperationalError.

Eine spürbar leichtere erste Ladung

Die generierte Markensymboltabelle – jedes Store-Logo, etwa 95 KB – befand sich im App-Shell-Block, den jede Route gemeinsam nutzt, um einen Fußzeilenlink zu erhalten. Es ist draußen, die Sitzungsorganisations-Benutzeroberfläche der Seitenleiste und die Co-Writer-Notizbuchauswahl werden jetzt bei Bedarf geladen, und die Home-Route ist von 305 KB auf 203 KB bei einem Budget von 300 KB gesunken. Keine Route liegt mehr über dem Budget.

Kopieren kopiert tatsächlich

Die Schaltfläche „Kopieren“ meldete den Erfolg, unabhängig davon, ob etwas das clipboard erreichte oder nicht, und meldete diesen falschen Erfolg über aria-live – sodass einem Benutzer eines Bildschirmlesegeräts mitgeteilt wurde, dass die Kopie funktionierte, obwohl dies nicht der Fall war. Der Clipboard-Zugriff wird jetzt vor dem ersten await geprüft (die zugrunde liegende Ursache war die zu frühe Ausgabe der Benutzergesten-Zulage) und ein echter Fehler wird als solcher angezeigt.

Wissensdatenbanken: Namen, Uploads, leere Datenbanken

Eine mit einem Schrägstrich benannte Wissensdatenbank könnte erstellt und dann nie gelöscht werden. Die Validierung erfolgt nun auf dem Manager, sodass sie von allen acht Registrierungseinstiegspunkten gemeinsam genutzt wird und ein bereits vorhandener schlechter Ruf entfernt werden kann. Große Uploads, die mitten in der Übertragung fehlgeschlagen sind und nur die Meldung „Failed to fetch“ (Abrufen fehlgeschlagen) haben, funktionieren ebenfalls: Der Proxy hat den Expect: 100-continue-Header von client wiedergegeben, was Undici komplett ablehnt. Das Erstellen einer leeren Wissensdatenbank führt nicht mehr zu Fortschrittsfehlern.

Partner können Ihre verbundenen Wissensdatenbanken nutzen

Die Zuweisung eines Obsidian-Tresors, eines verknüpften Indexes, von WeKnora oder IMA an einen Partner scheiterte früher völlig: Die Bereitstellung wusste nur, wie ein Ordner kopiert werden sollte, und eine Zeiger-Wissensdatenbank verfügt von Natur aus nicht über solche Funktionen. Verbundene Basen werden nun als Zeiger registriert, bleiben in der Bibliothek des Partners sichtbar und können wieder entfernt werden. Obsidian-, MarginNote- und Subagentenbasen sind bewusst declined – jede steuert eine exklusive Fähigkeit, die jeden Zug dieses Partners übernehmen würde. Dateien, die ein Partner im Chat-Download für die Person vorlegt, die gefragt hat, und eine Partnerunterhaltung zeigt jetzt an, aus welchem ​​Chat sie stammt, sodass ein Feishu-Gruppenthread nicht mehr nicht mehr von einer Direktnachricht zu unterscheiden ist.

Chat greift nicht mehr nach Tools, die es nicht hat

read_source gehört zum Kontextermittler, der vor der Antwortschleife ausgeführt wird, nicht zur Schleife selbst. Die Eingabeaufforderung und das Manifest der angehängten Quellen besagten etwas anderes, sodass das Modell ständig versuchte, PDFs über ein Dateitool erneut zu öffnen, das ihm nie zur Verfügung gestellt wurde.

Die Argumentation kommt dort an, wo sie gefehlt hat

Die gemeinsame Agentenschleife erfasste nie die Argumentation einer Runde – das Feld war in seinem Ergebnistyp nicht vorhanden –, sodass darauf basierende Oberflächen, einschließlich Buchquiz, Argumentationsfehler des Anbieters anstelle von Inhalten aufdeckten. Es wird jetzt durchgeführt.

Die Codex-Anmeldung wird in Docker abgeschlossen

Wenn der Browser den Loopback-Callback des Containers nicht erreichen kann, können Sie die Adresse einfügen, auf der der Browser gelandet ist, und die Anmeldung abschließen. Die eingefügte Adresse muss genau mit dem für diesen Versuch registrierten Umleitungs-URI übereinstimmen und doppelte OAuth-Parameter werden als mehrdeutig abgelehnt. Es wird analysiert und verworfen, niemals abgerufen, gespeichert oder zurückgegeben. Die Katalogkompatibilitätsversion wurde ebenfalls angehoben, sodass jetzt berechtigte Modelle angezeigt werden, die in älteren Versionen weggelassen wurden.

Kleinere Korrekturen, die es wert sind, erwähnt zu werden

Vier Leseaktionen, die eine Textauswahl erfordern, waren seit v1.6.0 mit der Maus unbrauchbar – das Anmerkungs-Popover deaktivierte die Symbolleiste, bevor der click landete. Einen Tutor nach einer anderen Sprache zu fragen, funktioniert, und die Browser- und Serverkopien dieser Präferenz driften nicht mehr auseinander. Mastery Path erkennt mastery_mode als ein Werkzeug, das den Pfad neu verbindet. Mit Lernerkonten können Kurse wieder geöffnet werden. Fehlerhafter ###heading-Text wird normalisiert, ohne #include innerhalb eines Codezauns zu berühren.

Korrekturen

Die Moonshot Kimi k3-Familie wird einmal statt pro veröffentlichter ID benannt, sodass k3-256k und spätere Varianten ihre Temperaturüberschreibung behalten; Antwortanfragen, die für ein nicht unterstütztes input[N].status abgelehnt wurden, versuchen Sie es einmal ohne es und merken Sie sich das Modell. der LightRAG SDK wechselt vom Release Candidate zu 1.5.7; und der README-Übersichts-Screenshot ist aktuell.

Upgrade-Hinweise

Führen Sie pip install -U deeptutor aus; Docker-Benutzer ziehen ghcr.io/hkuds/deeptutor:latest. Nichts muss migriert werden.

  • Durch ein Zurücksetzen auf v1.6.4 wird fast nichts davon behoben. Die meisten dieser Fehler sind älter als v1.6.5; Lediglich die Wissensdatenbank-Benennungs- und Mastery-Pfad-Probleme haben eine wirklich neue v1.6.5-Oberfläche. – Wenn eine benutzerdefinierte Eingabeaufforderung oder ein Plugin die Antwortschleife angewiesen hat, read_source aufzurufen, verschieben Sie diese Arbeit in den Kontextermittler – die Schleife stellt sie nicht bereit.
  • Die englischen und chinesischen Anleitungen wurden gemeinsam unter deeptutor.info aktualisiert. Vollständig Changelog: https://github.com/HKUDS/DeepTutor/compare/v1.6.5...v1.6.6

DeepTutor v1.6.6

Highlights

  • Answers you submit finally arrive — An ask_user card whose turn had ended couldn't reach the backend, so submission did nothing; a finished turn that still owns an unanswered card now keeps its address, and a refused answer is re-sent as an ordinary message instead of being discarded (the old error told you to send a new message — exactly what was blocked). Notebook entries with answer images had failed since v1.6.3 on a 23-columns/22-values insert OperationalError. Both are fixed, restoring the core tutor loop that v1.6.5 only appeared to break.

  • Copy and reading interactions stop lying — The copy button reported success whether or not anything reached the clipboard and announced that false success through aria-live; clipboard access is now probed before the first await (spending the user-gesture allowance too early was the root cause), and real failures surface. Four selection-based reading actions, unusable by mouse since v1.6.0 because the annotation popover disarmed the toolbar before the click landed, work again. Smaller but real: mastery_mode now rebinds Mastery Path, learner accounts can open courses again, the language preference stops drifting between browser and server, and malformed ###heading text is normalized without touching #include inside a code fence.

  • Noticeably lighter first load — The generated brand-icon table (~95 KB of store logos) was riding in the app-shell chunk shared by every route, all for the sake of one footer link; it's removed, and the sidebar's session-organization UI and Co-Writer notebook picker now load on demand. Home route drops 305 KB → 203 KB against a 300 KB budget, and no route is over budget. For adopters this is a genuine bandwidth/TTI win, not a cosmetic metric.

  • Knowledge bases: stricter names, working uploads, partner sharing — Slash-containing names are validated on the manager so all eight registration entry points agree, and a bad pre-existing name can finally be deleted; large uploads that died with a bare "Failed to fetch" are fixed by not replaying the client's Expect: 100-continue header through the proxy (undici rejects it outright), and empty bases no longer raise progress errors. Partner behavior changes materially: connected/pointer bases (Obsidian vault, linked index, WeKnora, IMA) can now be assigned instead of failing on folder-only provisioning, while Obsidian, MarginNote and subagent bases are deliberately declined because their exclusive capabilities would take over every partner turn. Files a partner presents download for the requester, and partner chats now show their origin, so a Feishu group thread is distinguishable from a DM.

  • Agentic-loop contract changes worth migrating for — read_source is mounted only on the pre-answer context investigator, never on the answer loop; the old prompt and attached-sources manifest said otherwise, so the model kept trying to reopen PDFs through a tool it was never given. If a custom prompt or plugin tells the loop to call it, move that work to the context investigator — the one upgrade note with actual work attached. Separately, the shared loop now carries a round's reasoning on its result type (previously the field didn't exist), so surfaces built on it, including book quizzes, stop surfacing provider reasoning errors instead of content.

  • Codex sign-in and model compatibility in Docker — When the browser can't reach the container's loopback callback, you can paste the address it landed on to finish sign-in; it must match the redirect URI registered for that attempt exactly, duplicate OAuth parameters are refused as ambiguous, and the value is parsed then discarded — never fetched, stored, or echoed back. The catalog compatibility version was raised, so eligible models older versions omitted now appear. Model-side fixes: Moonshot Kimi k3 is named once rather than per released id so k3-256k and later keep their temperature override; Responses requests rejected for unsupported input[N].status retry once without it and remember the model; LightRAG SDK moves off the RC to 1.5.7.

No breaking changes — drop-in upgrade, nothing to migrate; rolling back to v1.6.4 would fix almost none of this.

DeepTutor v1.6.6 Release Notes

Release Date: 2026.09.08

v1.6.6 is a fix release, and an unusually clarifying one. Working through the v1.6.5 feedback showed that most of what people reported was not a regression: v1.6.5 mostly removed things that had been masking older breakage, so answers that silently failed to submit, a copy button that reported success it never had, and reading actions unusable since v1.6.0 all became visible at once. Those are fixed here, along with the batch of community pull requests behind them. Drop-in — no migrations.

What's New

Answers you submit actually arrive

An ask_user card whose turn had already ended could no longer reach the backend, so submitting did nothing. Worse, the three composers discarded what you had typed when a submission was refused, while the error told you to send a new message — which was the very thing being blocked. Both are fixed: a finished turn that still owns an unanswered card keeps its address, and a refused answer is re-sent as an ordinary message instead of being thrown away.

Notebook entries with answer images could not be saved at all since v1.6.3 — the insert listed 23 columns against 22 values and raised OperationalError every time.

A noticeably lighter first load

The generated brand-icon table — every store logo, about 95 KB — was riding in the app-shell chunk that every route shares, for the sake of one footer link. It is out, the sidebar's session-organization UI and the Co-Writer notebook picker now load on demand, and the home route dropped from 305 KB to 203 KB against a 300 KB budget. No route is over budget any more.

Copy actually copies

The copy button reported success whether or not anything reached the clipboard, and announced that false success through aria-live — so a screen-reader user was told the copy worked when it had not. Clipboard access is now probed before the first await (spending the user-gesture allowance too early was the underlying cause) and a real failure is shown as one.

Knowledge bases: names, uploads, empty bases

A knowledge base named with a slash could be created and then never deleted. Validation now lives on the manager, so all eight registration entry points share it, and a bad name that already exists can be removed. Large uploads that failed mid-transfer with a bare "Failed to fetch" also work: the proxy was replaying the client's Expect: 100-continue header, which undici rejects outright. Creating an empty knowledge base no longer raises progress errors.

Partners can use your connected knowledge bases

Assigning an Obsidian vault, a linked index, WeKnora or IMA to a partner used to fail outright: provisioning only knew how to copy a folder, and a pointer knowledge base has none by design. Connected bases are now registered as pointers, stay visible in the partner's library, and can be removed again. Obsidian, MarginNote and subagent bases are deliberately declined — each drives an exclusive capability that would take over every one of that partner's turns.

Files a partner presents in chat download for the person who asked, and a partner conversation now shows which chat it came from, so a Feishu group thread is no longer indistinguishable from a direct message.

Chat stops reaching for tools it does not have

read_source belongs to the context investigator that runs before the answer loop, not to the loop itself. The prompt and the attached-sources manifest said otherwise, so the model kept trying to reopen PDFs through a file tool it was never given.

Reasoning arrives where it was missing

The shared agentic loop never captured a round's reasoning — the field did not exist on its result type — so surfaces built on it, including book quizzes, surfaced provider reasoning errors instead of content. It is carried through now.

Codex sign-in finishes inside Docker

When the browser cannot reach the container's loopback callback, you can paste the address the browser landed on and complete the sign-in. The pasted address must match the redirect URI registered for that attempt exactly, and duplicated OAuth parameters are refused as ambiguous; it is parsed and discarded, never fetched, stored, or echoed back. The catalog compatibility version was also raised, so eligible models that older versions omitted now appear.

Smaller fixes worth naming

Four reading actions that need a text selection have been unusable by mouse since v1.6.0 — the annotation popover disarmed the toolbar before the click landed. Asking a tutor for another language works, and the browser and server copies of that preference stop drifting apart. Mastery Path recognises mastery_mode as a tool that rebinds the path. Learner accounts can open courses again. Malformed ###heading text is normalized without touching #include inside a code fence.

Fixes

The Moonshot Kimi k3 family is named once instead of per released id, so k3-256k and later variants keep their temperature override; Responses requests rejected for an unsupported input[N].status retry once without it and remember the model; the LightRAG SDK moves off the release candidate to 1.5.7; and the README overview screenshot is current.

Upgrade Notes

Run pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. Nothing needs migrating.

  • Rolling back to v1.6.4 fixes almost none of this. Most of these defects predate v1.6.5; only the knowledge-base naming and Mastery Path issues have genuinely new v1.6.5 surface area.
  • If a custom prompt or plugin told the answer loop to call read_source, move that work to the context investigator — the loop does not mount it.
  • The English and Chinese guides have been updated together at deeptutor.info.
