open-webui v0.13.1

Hinzugefügt

  • 🦾 Codierungsagenten als Modelle. Auf einem offenen Terminal, das Agenten anbietet, erscheinen jetzt Codierungsagenten wie Claude Code, Codex und Pi in der Modellauswahl. Sie können mit ihnen chatten oder sie telefonisch anrufen, ihren Argumentationsaufwand und ihre Servicestufe auswählen und ihre Tool-Anfragen im Chat genehmigen. Jede Konversation verwendet einen Agenten und Agenten-Chats können nicht neu generiert, fortgesetzt oder bearbeitet und erneut gesendet werden. Wenn das Terminal eines Agenten ausfällt, werden dessen Chats und neue Chats auf das Standardmodell zurückgesetzt und frühere Antworten behalten den Namen des Agenten. Die automatische Vervollständigung in Agenten-Chats verwendet das Aufgabenmodell oder wird übersprungen, wenn keins vorhanden ist. #33843, #33860, #33880, #33857
  • 🪢 Wir stellen vor: Tether. Tether ist die neue Desktop-Begleit-App für macOS, Windows und Linux, die Ihren eigenen Computer mit Open WebUI verbindet. Melden Sie sich einmal an und Ihr Computer wird im Terminalmenü unter „Ihre Geräte“ angezeigt, sodass Modelle, Codierungsagenten und Automatisierungen in Ihren realen Dateien, Repositorys und Tools funktionieren und Sie von jedem Browser, einschließlich Ihrem Telefon, darauf zugreifen können. Tether stellt eine Verbindung zu Open WebUI her, sodass keine Ports geöffnet werden müssen, die Terminalausgabe wird nach einer unterbrochenen Verbindung wieder aufgenommen und es sendet Benachrichtigungen an Ihren Desktop, auch wenn keine Open WebUI-Seite geöffnet ist. Die Anmeldung erfolgt mit einer verlängerbaren Sitzung, die standardmäßig nach 90 Tagen ohne Nutzung abläuft und mit „SESSION_EXPIRES_IN“ festgelegt ist.
  • 💸 Viel günstigere Tool-Chats. Chats, die Tools verwenden, kosten jetzt viel weniger. Zitieranweisungen, Gedächtnisabruf, die Fertigkeitenliste und das zugehörige Wissen werden nicht mehr bei jeder Tool-Runde neu in die Systemeingabeaufforderung oder Ihre Nachricht geschrieben, sodass der Beginn der Konversation zwischen den Anfragen gleich bleibt und die Anbieter sie aus ihrem Eingabeaufforderungs-Cache bedienen können. Benutzerdefinierte Pipes sehen daher ein anderes Nachrichtenlayout; siehe „Kontext als ausgeblendete Werkzeugergebnisse“ unter „Geändert“. #33852
  • 🚦 Auto-Tool-Berechtigungen. Administratoren können jetzt „Auto“ aktivieren, einen dritten Tool-Berechtigungsmodus neben „Vollzugriff“ und „Um Genehmigung bitten“ (standardmäßig deaktiviert). Ein Überprüfungsmodell überprüft jeden Toolaufruf und führt ihn nur dann sofort aus, wenn es zu dem Schluss kommt, dass keine Bestätigung erforderlich ist. Die Überprüfung sendet das Tool, seine Argumente und Ihre letzten Nachrichten an die konfigurierte Bewertung API, und jeder Aufruf, den es aufgrund eines Fehlers, einer Zeitüberschreitung oder zu viel Kontext nicht überprüfen kann, bittet um Genehmigung.
  • 📚 Volltext für kleine Dateien. Dateien, deren extrahierter Text kürzer als ein neuer Schwellenwert ist (standardmäßig 50.000 Zeichen, festgelegt mit „RAG_FULL_TEXT_CHAR_THRESHOLD“ oder in den Admin-Dokumenteinstellungen), werden jetzt vollständig einbezogen, anstatt sie abzurufen. Dies gilt sowohl, wenn „Dateien vorladen“ den Inhalt zur Konversation hinzufügt, als auch, wenn das Modell eine angehängte Datei mit seinem Dateisuchtool liest und der Datei-Viewer anzeigt, wann dies geschieht.
  • ⏱️ Schnellere große Chats. Große Chats öffnen sich jetzt etwa doppelt so schnell, und das Markieren eines Chats als gelesen oder ungelesen oder das Entfernen eines Tags daraus geht vier- bis sechsmal schneller. #33665, #33666
  • 🏎️ Schnellere Überprüfung des Chat-Zugriffs. Das Senden von Nachrichten, Eingabeindikatoren, freigegebene Links, Kommentare und Dateizugriff laden nicht mehr die gesamte Konversation, nur um zu überprüfen, wer darauf zugreifen darf, was bei großen Chats am hilfreichsten ist. #33667, #33669
  • 🔧 Verzeihendere Tool-Aufrufe. Tool-Aufrufe mit Argumenten, die in Code-Fences eingeschlossen, doppelt codiert oder als Text anstelle von Zahlen und booleschen Werten gesendet werden, werden jetzt ausgeführt, und Tool-Aufrufe, die ein Modell als Klartext-Markup ausschreibt, werden erkannt und ausgeführt. #33868
  • 🛑 Tool-Schleife stoppt. Ein Tool-Aufruf, der zweimal hintereinander mit denselben Argumenten fehlschlägt, beendet jetzt die Tool-Schleife, sodass das Modell eine endgültige Antwort schreibt und eine durch das Token-Limit abgeschnittene Antwort seine unvollendeten Tool-Aufrufe nicht mehr ausführt.
  • 🛠️ Standardwerkzeuge für Modelle. Der Abschnitt „Modellstandards“ in den Admin-Modelleinstellungen verfügt jetzt über eine Werkzeugauswahl. Modelle ohne eigene Werkzeugliste starten neue Chats mit diesen aktivierten Werkzeugen und das neue Modellformular wählt sie vorab aus. #33749, #33787
  • 🚀 Schnellere Kanäle. Die Kanalliste, die Kanalnachrichten und die beantworteten Nachrichten in einem Kanal werden jetzt viel schneller geladen, insbesondere bei vielen Kanälen oder vielen Antworten, und neue Datenbankindizes beschleunigen Kanalthreads und -reaktionen. #33690, #33691, #33688
  • 🪶 Leichtere Reasoning-Streams. Lange Reasoning-Antworten von Anbietern wie OpenRouter senden jetzt beim Streamen weitaus weniger Daten an den Browser und an Redis. #33698
  • 🗂️ Schnellere Chat-Liste in der Seitenleiste. Die Chat-Liste in der Seitenleiste erscheint jetzt, sobald die eigenen Daten bereit sind, anstatt auf die Kanalliste zu warten. #33686
  • ⌨️ Schnelleres Tippen nach großen Einfügungen. Das Eingeben der Chat-Eingabe nach dem Einfügen von 16.000 Textzeilen ist jetzt etwa 117-mal schneller, von 8.6 Sekunden auf 74 Millisekunden pro Tastendruck. #33729, #12087
  • 🧮 Schnellere Redis-Filtersuche. Wenn Redis aktiviert ist, suchen Chat-Anfragen jetzt schneller nach den Filtern eines Modells. #33668
  • 🪟 Tab-Bereiche teilen. Wenn Sie auf großen Bildschirmen einen Tab oder einen Chat an den Rand des Arbeitsbereichs ziehen oder auf die neue Schaltfläche „Bildschirm teilen“ klicken, wird dieser in veränderbare Bereiche aufgeteilt, sodass mehrere Tabs, einschließlich des Chats, nebeneinander sichtbar bleiben. Durch langes Drücken und Ziehen auf Touchscreens können Registerkarten auch neu angeordnet und zwischen Fenstern verschoben werden. Commit
  • 🧳 Tabs werden pro Chat gespeichert. Die geöffneten Tabs, das geteilte Layout und das ausgewählte Terminal jedes Chats werden jetzt für jeden Benutzer privat auf dem Server gespeichert und wiederhergestellt, wenn Sie den Chat erneut öffnen, auch auf einem anderen Gerät. Wenn Sie sich abmelden, werden Sie vor nicht gespeicherten Dateiänderungen gewarnt. #33899, #33885
  • 🪣 Batch-Aufrufe zur Werkzeugsuche. Wenn die Werkzeugsuche aktiviert ist, kann das Modell mehrere unabhängige Werkzeuge ausführen, die es in einer einzigen call_tool-Anfrage gefunden hat, was Modellrunden spart und so die Kosten für werkzeugintensive Chats senkt.
  • 🧭 Tool-Suchmaschinen. Die Tool-Suche in den Einstellungen der Admin-Schnittstelle kann jetzt Tools mit Einbettungen aus dem Dokumenteinbettungsmodell abgleichen (im Speicher gehalten, nicht gespeichert) oder indem die Abfrage- und Tool-Definitionen zusätzlich zur Standardschlüsselwortsuche an einen Relevanzbewertungs-API gesendet werden.
  • 🏷️ Lesbare Werkzeugaufrufbezeichnungen. Administratoren können jetzt Werkzeugaufrufbezeichnungen in den Admin-Einstellungen > Benutzeroberfläche oder mit „ENABLE_TOOL_CALL_LABELS“ (standardmäßig deaktiviert) aktivieren, um das Modell um kurze Beschreibungen in der Sprache des Benutzers zu bitten, was jeder Werkzeugaufruf tut und was er bewirkt hat. Festschreiben
  • ✂️ Chat-Leselimit. Administratoren können mit „VIEW_CHAT_MAX_CHARS“ oder dem neuen Feld „Chat-Leselimit“ unter „Admin-Einstellungen“ > „Allgemein“ begrenzen, wie viel von einem früheren Chat die Chat-Verlaufstools zurückgeben, und die neuesten Nachrichten bleiben erhalten, während ältere ausgeschnitten werden. #33695, #33608
  • 🌍 Client IP-Header-Platzhalter. Benutzerdefinierte Header von Verbindungen können jetzt „{{USER_IP}}“ und „{{X_FORWARDED_FOR}}“ verwenden, um die client-Adresse an den Upstream-Anbieter weiterzugeben, und beide sind für Automatisierungen und Hintergrundjobs leer. #33833, #33819
  • ✉️ Nicht-ASCII-E-Mail-Adressen. Die Anmeldeseite und die Dialogfelder zum Hinzufügen und Bearbeiten von Benutzern akzeptieren jetzt E-Mail-Adressen mit Nicht-ASCII-Zeichen. #33693, #33681
  • 🕒 Endzeit der Antwort. In den Antworten des Assistenten wird jetzt die Zeit angezeigt, zu der sie abgeschlossen wurden, und nicht die Zeit, zu der die Aufforderung gesendet wurde. #33895
  • 🧐 Suche nach Kanalnachrichten. Jeder Kanalkopf verfügt über eine Suchschaltfläche, mit der die Nachrichten dieses Kanals durchsucht werden.
  • 🔔 Benachrichtigungen öffnen ihren Chat. CliDas Klicken auf eine Desktop-Benachrichtigung bringt Open WebUI jetzt in den Vordergrund und öffnet den zugehörigen Chat, Kanal oder Kalender.
  • 📮 MCP Apps senden eine Nachricht an den Chat. Eine MCP-App kann jetzt eine Textnachricht an den Chat senden, die Sie zuerst in einem Dialogfeld „Einbettungsaufforderung bestätigen“ bestätigen. #33907
  • 🖱️ Chats in die Seitenleiste ziehen. Wenn Sie einen Chat aus der Seitenleiste in den Chatbereich ziehen, wird dieser als Seitenchat-Registerkarte geöffnet, und ein Seitenchat kann jetzt auch aus einem leeren neuen Chat gestartet werden.
  • 🪄 Schnelles Öffnen von Dateien. Eine neue Tastenkombination, Cmd+P (an anderer Stelle Strg+P), öffnet ein Suchfeld, das Dateien im ausgewählten Terminal anhand des Namens oder Pfads findet und die von Ihnen ausgewählte Datei in einem Tab öffnet.
  • 🎹 Tab-Tastaturkürzel. Neue Tastenkombinationen, die unter Einstellungen > Tastatur geändert werden können. Öffnen Sie die Registerkarten „Dateien“, „Desktop“, „Kommentare“, „Neuer Chat“, „Neue Datei“, „Neues Terminal“ und „Neuer Browser“, schließen Sie die Registerkarten, wechseln Sie zwischen ihnen und schalten Sie den geteilten Bildschirm um.
  • 🗺️ Arbeitsverzeichnisauswahl. Die Nachrichteneingabe verfügt über ein Arbeitsverzeichnismenü mit Ordnersuche, eine Liste der zuletzt verwendeten Benutzer, die pro Benutzer auf dem Terminal geführt wird, und ein Dialogfeld zum Öffnen von Ordnern.
  • 📂 Ordner-Standardterminal. Ein Ordner kann jetzt in seinen erweiterten Einstellungen ein Standardterminal und ein Arbeitsverzeichnis haben, die für neue Chats in diesem Ordner verwendet werden.
  • 🧾 Bearbeitbare Tabellenkalkulationen. Excel-Dateien in der Dateiansicht können jetzt in der Vorschau mit einer Formelleiste bearbeitet, aus anderen Tabellenkalkulationen und in der Größe veränderbaren Spalten eingefügt und wieder in der Datei gespeichert werden, während Formelzellen und geschützte Blätter schreibgeschützt bleiben.
  • 🖋️ Markdown und Codebearbeitung. Markdown-Dateien in der Dateiansicht werden jetzt in einem Rich-Text-Editor geöffnet, der sie wieder in Markdown speichert, wo eingefügte oder abgelegte Bilder auf das Terminal hochgeladen werden und der Code-Editor Wörter vorschlägt, die bereits in der Datei vorkommen. Andere Textdateien und die Quellansicht von Vorschauen verwenden jetzt den Code-Editor direkt, ohne einen separaten Bearbeitungsschritt. Festschreiben
  • 🌳 Git-Repositorys klonen. Der Dateibrowser und die Ordnerauswahl können jetzt ein Git-Repository von einer HTTP(S)- oder SSH-URL in den ausgewählten Ordner des ausgewählten Terminals klonen.
  • 🧬 Git-Änderungen im Editor. Der Code-Editor markiert jetzt die Zeilen einer Datei, die seit dem letzten Commit hinzugefügt oder geändert wurden.
  • 🔖 Git-Status des Dateibrowsers. Dateien und Ordner im Dateibrowser sind mit einem Git-Statusbuchstaben wie M, A, D oder U gekennzeichnet und Ordner zeigen an, dass sie Änderungen enthalten.
  • 🌿 Feedback und Größenänderung des Git-Bedienfelds. Das Git-Bedienfeld zeigt jetzt an, was es tut, z. B. Staging, Pushen oder Abrufen, und die Größe seiner Dateiliste kann geändert werden.
  • 🧹 Alle Git-Änderungen verwerfen. Das Git-Bedienfeld kann jetzt auch bereitgestellte und neue Dateien verwerfen, und seine Bestätigung warnt, dass Dateien, die nicht im letzten Commit enthalten waren, gelöscht werden und dass dies nicht rückgängig gemacht werden kann.
  • 🧲 Dateien in den Chat ziehen. Dateien aus dem Terminal-Dateibrowser können einzeln oder mehrere gleichzeitig in die Nachrichteneingabe gezogen werden, um sie anzuhängen, auch durch langes Drücken auf Touchscreens.
  • 🗃️ Mehrere Dateiregisterkarten. Das +-Menü kann jetzt mehrere Dateiregisterkarten für dasselbe Terminal öffnen, jede mit ihrem eigenen Ordner und dem Ordnernamen als Registerkartentitel, und durch das Verschieben von Dateien werden die anderen Dateiregisterkarten auf diesem Terminal aktualisiert. Festschreiben
  • 🔲 Ziehen Sie, um Dateien auszuwählen. Mehrere Dateien im Dateibrowser können jetzt ausgewählt werden, indem Sie ein Auswahlfeld darüber ziehen.
  • 🪂 Spring-geladene Dateiregisterkarten. Wenn Sie eine gezogene Datei eine halbe Sekunde lang über eine Dateiregisterkarte halten, wird zu dieser Registerkarte gewechselt, sodass Dateien in Ordner einer anderen Registerkarte verschoben werden können.
  • ⚡ Schnelleres Terminal-Rendering. Die Registerkarte „Terminal“ wird jetzt mit WebGL gerendert, wenn der Browser dies unterstützt, und nimmt Ausgabestöße in größeren Stapeln auf, sodass umfangreiche Ausgaben schneller verarbeitet werden.
  • 🩺 Terminalsysteminformationen. Das Terminalmenü verfügt jetzt über eine Systeminfoansicht mit der CPU, dem Speicher, der Festplatte, dem Netzwerk, der Betriebszeit und den wichtigsten Prozessen des Terminals.
  • 🖌️ Bilder vom Terminal aus bearbeiten. Das Bildbearbeitungstool kann jetzt Quellbilder vom ausgewählten Terminal nach Dateipfad als PNG, JPEG, WebP oder GIF mit bis zu 25 Megapixeln apixel übernehmen. #33824
  • 🎙️ Sprachnotizen in Dateien. Eine neue Tastenkombination, Cmd+Alt+M (Strg+Alt+M an anderer Stelle), zeichnet eine Sprachnotiz auf, kann sie transkribieren und speichert die Aufnahme mit einer Markdown-Notiz im aktuellen Ordner des ausgewählten Terminals und öffnet die Notiz dann in einem Tab. Escape bricht eine Aufnahme ab. #33902, #33903
  • 📢 Modellverfügbarkeitsereignisse. Open WebUI veröffentlicht jetzt model.available- und model.unavailable-Ereignisse, wenn ein Modell in der Liste der abgerufenen Modelle erscheint oder daraus verschwindet.
  • 🗒️ Beschreibungen in der Modellauswahl. Die Tool-, Skill-, Filter-, Aktions- und Subagentenauswahl im Modelleditor zeigt jetzt die Beschreibung jedes Elements unter seinem Namen an. #33723
  • 🔢 Gruppierte Token-Anzahl. Ganze Zahlen im Token-Nutzungs-Tooltip werden jetzt für die Schnittstellensprache nach Tausendern gruppiert, zum Beispiel 26.678.623. #33896
  • 🎼 Benachrichtigungston-Stile. Die Benachrichtigungston-Einstellung bietet jetzt Glocken-, Leise-, Glocken- und Klopftöne mit jeweils einer Wiedergabetaste zur Vorschau.
  • 🔄 Allgemeine Verbesserungen. In der gesamten Anwendung wurden verschiedene Verbesserungen implementiert, um Leistung, Stabilität und Sicherheit zu verbessern.
  • 🌐 Übersetzungsaktualisierungen. Übersetzungen für Portugiesisch (Brasilien), Aserbaidschanisch, Baskisch, Bengali, Bosnisch, Bulgarisch, Cebuano, Kroatisch, Tschechisch, Dänisch, Niederländisch, Estnisch, Färöisch, Philippinisch, Galizisch, Georgisch, Deutsch, Griechisch, Hebräisch, Hindi, Ungarisch, Indonesisch, Irisch, Japanisch, Kabyle, Koreanisch, Litauisch, Malaiisch, Norwegisch (Bokmål), Persisch, Polnisch, Punjabi, Rumänisch, Russisch, Serbisch, Slowakisch, Slowenisch, Spanisch (Spanien), Schwedisch, Tamilisch, Thailändisch, Tibetisch, Türkisch, Turkmenisch, Ukrainisch, Urdu, Uigurisch und Vietnamesisch wurden verbessert und erweitert.

Behoben

  • 🛡️ Sicherheitshinweis: Diese Version enthält Sicherheitsfixes. Wir empfehlen dringend, alle Bereitstellungen so bald wie möglich zu aktualisieren, um über die neuesten Sicherheitsfixes zu verfügen. Diese Korrekturen sind in diesem changelog nicht aufgeführt; Wir werden die Sicherheitshinweise für sie unmittelbar nach der CVE-Zuweisung veröffentlichen. Hinweise
  • 🗄️ Redis-Cluster-Chats. Das Senden einer Chat-Nachricht bei einer Redis-Cluster-Bereitstellung schlägt nicht mehr fehl, während das persönliche Terminal-Relay startet. #33766
  • 🚪 Automatische SSO-Anmeldung. Wenn die automatische SSO-Umleitung aktiviert ist, meldet Sie eine abgelaufene Sitzung jetzt wieder an, ohne dass ein Statuskonfliktfehler auftritt. #33791, #33783
  • 🎨 OpenAI-Image-Standardmodell. Die Image-Generierung mit der OpenAI-Engine verwendet jetzt standardmäßig GPT-IMAGE 2 anstelle des heruntergefahrenen DALL·E 2, und die heruntergefahrenen DALL·E-Modelle werden nicht mehr angeboten. #33694, #33578
  • 🖼️ Standard-GPT-Bildanfragen. OpenAI-Bildgenerierung und -bearbeitung ohne explizit festgelegtes Modell senden kein nicht unterstütztes Antwortformat mehr an das Standard-GPT-Bildmodell. #33875
  • 🔐 Terminalsitzungsauthentifizierung. Terminalverbindungen, die auf Sitzungsauthentifizierung eingestellt sind, akzeptieren jetzt einen API-Schlüssel, sodass Verbindung überprüfen, die Richtlinieneinstellungen und die Terminaltools wieder funktionieren. #33699, #30001, #33579
  • 🦙 Ollama defekte Toolaufrufe. Chats mit Ollama-Modellen bleiben nach einem Toolaufruf mit abgeschnittenen, abgelehnten oder leeren Argumenten nicht mehr hängen. #33697, #33671
  • 🧠 Vollständige Komprimierungszusammenfassungen. Kontextkomprimierungszusammenfassungen werden nicht mehr bei 1000 Token abgeschnitten, was dazu führen könnte, dass Argumentationsmodelle eine leere oder abgeschnittene Zusammenfassung haben. #33726
  • 💾 Prompter Cache für Tool-Ergebnisse. Tool-Ergebnisse, die über OpenAI-kompatible Gateways gesendet werden, behalten jetzt ihre Prompt-Cache-Markierung, sodass Anthropic-Modelle hinter OpenRouter oder LiteLLM das Präfix in Tool-Schleifen zwischenspeichern können. #33757, #33755
  • 📖 Größenbeschränkung für Dateilesevorgänge. Das Lesen einer Datei nach Zeilenbereich stoppt jetzt bei der gleichen Größenbeschränkung wie andere Lesevorgänge, sodass ein Lesevorgang nicht mehr über das Kontextfenster des Modells hinauslaufen kann. #33696, #33607
  • 🧰 Tool-Suche wiederholt. Ein fehlerhafter Tool-Aufruf mit aktivierter Tool-Suche deaktiviert die Tools nicht mehr für den Rest der Antwort, sodass das Modell seine Argumente korrigieren und es erneut versuchen kann. #33872
  • 🧩 Werkzeugaufrufe aufteilen. Wenn ein Modell mehrere Werkzeugaufrufe zusammengefasst sendet, wird im Chat kein zusätzlicher Werkzeugaufruf mehr angezeigt, der nie ein Ergebnis liefert. #33779, #33778
  • 🔎 Externe Wissensdatenbankabfragen. Externe Wissensdatenbanken durchsuchen jetzt jede generierte Abfrage gleichzeitig, anstatt nur die Ergebnisse der ersten zu verwenden. #33704, #33184
  • 📊 Große Tabellen hochladen. Das Hochladen einer großen, spärlich gefüllten Tabelle dauert nicht mehr Minuten und blockiert den Server. #33770, #33768
  • 🧱 Milvus-Wissensdatenbank-Uploads. Durch das Hinzufügen einer Datei zu einer Wissensdatenbank auf Milvus wird die Datei nicht mehr ein zweites Mal verarbeitet oder ihre Teile werden nicht mehr zweimal gespeichert. #33745, #33744
  • 📄 MinerU 4.1-Server. Der MinerU-Dokumentenlader im lokalen Modus funktioniert jetzt mit MinerU 4.1-Servern, bei denen früher jedes Dokument fehlschlug. #33719, #33718
  • 🔑 MCP OAuth bleibt angemeldet. Die Anmeldung bei einem MCP-Tool-Server, der OAuth verwendet, geht nicht mehr verloren, wenn der Anbieter während der Aktualisierung des Tokens vorübergehend ausfällt. #33805, #33803
  • 📍 Verzögerungen bei der Standortsuche. Wenn der Standortzugriff aktiviert ist, wartet das Senden einer Nachricht nicht mehr auf eine langsame oder unbeantwortete Standortanfrage des Browsers.
  • 🗓️ Beispiele für Automatisierungszeitpläne. Modelle, die Automatisierungen über das integrierte Tool erstellen, erhalten nicht mehr die Fehlermeldung „Ungültige RRULE“, die durch ein falsches Beispielzeitplanformat verursacht wird. #33732, #33730
  • ♿ Korrekturen bei Tastatur und Bildschirmleser. Der Tastaturfokus bleibt jetzt dort, wo er hingehört: auf Schaltflächen beim Speichern, an Ort und Stelle, wenn Sie die Bearbeitung einer Nachricht abbrechen, Nachrichtenversionen wechseln oder einen Arbeitsbereich oder eine Notizenliste sortieren und blättern, auf den Schaltflächen für die erste und letzte Seite und im Titelfeld, während ein Notiztitel generiert wird. Durch das Schließen eines Kanal-Threads, eines Notizbereichs oder eines Chat-Menüs kehrt der Fokus dorthin zurück, wo er war, und der Link zum Überspringen der Anmeldung verschiebt den Fokus auf das Formular. Die Schaltfläche „Passwort anzeigen“ ist jetzt breit genug, um sie zu drücken, und das Halten der Umschalttaste vertauscht die Zeilenschaltflächen nicht mehr mit „Löschen“, während ein Tastaturbenutzer den Fokus hat.
  • 🕵️ Geheimnismaskierung des Überwachungsprotokolls. Bei aktivierter Anforderungsüberwachung maskiert das Überwachungsprotokoll jetzt API-Schlüssel, Token und Geheimnisse, die in den Admin-Einstellungen gespeichert sind, nicht nur Passwörter. #33746
  • 🔇 Abfragen werden nicht in die Protokolle aufgenommen. Das Standardserverprotokoll enthält nicht mehr Ihre Suchanfragen oder die Anbieteradresse eines fehlerhaften externen Rerankers. #33701
  • 💬 Chat-Nachrichtensuche. Die Workspace-Suche findet jetzt Nachrichtentext und zeigt passende Auszüge in Chats an, deren Nachrichten getrennt vom Chat-Datensatz gespeichert werden. Festschreiben
  • 🔃 Suchergebnisse bleiben aktuell. Notizen, archivierte und geteilte Chats, die Admin-Benutzerliste und die Wissens- und Dateiauswahl in der Nachrichteneingabe lassen nicht mehr zu, dass eine ältere Suche die Ergebnisse einer neueren ersetzt. Commit
  • 👎 Feedback-Details gespeichert. Ein Daumen-nach-unten-Grund und ein Kommentar gehen nicht mehr verloren, wenn sie gespeichert werden, bevor die Generierung der Feedback-Tags abgeschlossen ist. #33716
  • 🎒 Standardtools für Nebenchats. Neue Nebenchats starten jetzt mit denselben Standardtools, Fähigkeiten, Filtern und Websuche wie ein normaler Chat mit diesem Modell. #33788
  • ✅ Side-Chat-Tool-Genehmigungen. Tool-Aufrufe in Side-Chats zeigen jetzt funktionierende Genehmigungskontrollen an und setzen die Antwort nach der Genehmigung fort. #33889
  • ❓ Fragen im Side-Chat. Fragen, die über das ask_user-Tool des Models gestellt werden, erscheinen jetzt in Side-Chats und können beantwortet oder abgewiesen werden, auch nach dem erneuten Öffnen des Chats. #33901
  • ⏩ Fortgesetzte Antworten auf Responses-Verbindungen. Beim Fortsetzen einer Antwort auf einer Responses API-Verbindung wird jetzt der neue Text zur vorhandenen Antwort hinzugefügt.

open-webui v0.13.1

Added

  • 🦾 Coding agents as models. On an Open Terminal that offers agents, coding agents such as Claude Code, Codex and Pi now appear in the model picker. You can chat with them or call them by voice, choose their reasoning effort and service tier, and approve their tool requests in the chat. Each conversation uses one agent, and agent chats cannot be regenerated, continued or edited and resent. If an agent's terminal goes away, its chats and new chats fall back to the default model and earlier replies keep the agent's name. Autocompletion in agent chats uses the task model, or is skipped when there is none. #33843, #33860, #33880, #33857
  • 🪢 Introducing Tether. Tether is the new desktop companion app for macOS, Windows and Linux that ties your own computer to Open WebUI. Sign in once and your computer shows up under Your devices in the terminal menu, so models, coding agents and automations can work in your real files, repositories and tools, and you can reach them from any browser, including your phone. Tether connects out to Open WebUI, so there are no ports to open, its terminal output resumes after a dropped connection, and it delivers notifications to your desktop even when no Open WebUI page is open. It signs in with a renewable session that expires after 90 days without use by default, set with "SESSION_EXPIRES_IN".
  • 💸 Much cheaper tool chats. Chats that use tools now cost much less. Citation instructions, memory recall, the skills list and attached knowledge are no longer rewritten into the system prompt or your message on every tool round, so the start of the conversation stays the same between requests and providers can serve it from their prompt cache. Custom pipes see a different message layout as a result; see Context as hidden tool results under Changed. #33852
  • 🚦 Auto tool permissions. Administrators can now turn on Auto, a third tool permission mode next to Full access and Ask for approval (off by default). A review model checks each tool call and runs it right away only when it judges that no confirmation is needed. The review sends the tool, its arguments and your last few messages to the configured scoring API, and any call it cannot review, because of an error, a timeout or too much context, asks for approval.
  • 📚 Full text for small files. Files whose extracted text is shorter than a new threshold (50,000 characters by default, set with "RAG_FULL_TEXT_CHAR_THRESHOLD" or in the admin Documents settings) are now included in full instead of through retrieval. This applies both when Preload files adds the content to the conversation and when the model reads an attached file with its file search tool, and the file viewer shows when it happens.
  • ⏱️ Faster large chats. Large chats now open about twice as fast, and marking a chat as read or unread or removing a tag from it is 4 to 6 times faster. #33665, #33666
  • 🏎️ Faster chat access checks. Sending messages, typing indicators, shared links, comments and file access no longer load the whole conversation just to check who may access it, which helps most on large chats. #33667, #33669
  • 🔧 More forgiving tool calls. Tool calls with arguments wrapped in code fences, encoded twice or sent as text instead of numbers and booleans now run, and tool calls a model writes out as plain text markup are recognised and executed. #33868
  • 🛑 Tool loop stops. A tool call that fails twice in a row with the same arguments now ends the tool loop so the model writes a final answer, and a reply cut off by the token limit no longer runs its unfinished tool calls.
  • 🛠️ Default tools for models. The Model Defaults section in the admin Models settings now has a Tools picker, models without their own tool list start new chats with those tools enabled, and the new model form preselects them. #33749, #33787
  • 🚀 Faster channels. The channel list, the channel messages and the replied-to messages in a channel now load much faster, especially with many channels or many replies, and new database indexes speed up channel threads and reactions. #33690, #33691, #33688
  • 🪶 Lighter reasoning streams. Long reasoning replies from providers such as OpenRouter now send far less data to the browser and to Redis while they stream. #33698
  • 🗂️ Faster sidebar chat list. The chat list in the sidebar now appears as soon as its own data is ready instead of waiting for the channel list. #33686
  • ⌨️ Faster typing after large pastes. Typing in the chat input after pasting 16,000 lines of text is now about 117 times faster, down from 8.6 seconds to 74 milliseconds per keystroke. #33729, #12087
  • 🧮 Faster Redis filter lookups. With Redis enabled, chat requests now look up the filters of a model faster. #33668
  • 🪟 Split tab panes. On large screens, dragging a tab or a chat to the edge of the workspace, or pressing the new Split screen button, splits it into resizable panes, so several tabs, including the chat, stay visible side by side. Tabs can also be reordered and moved between panes with a long press and drag on touch screens. Commit
  • 🧳 Tabs remembered per chat. The open tabs, split layout and selected terminal of each chat are now saved privately for each user on the server and restored when you reopen the chat, even on another device. Signing out warns you about unsaved file edits. #33899, #33885
  • 🪣 Batched Tool Search calls. With Tool Search on, the model can run several independent tools it found in a single call_tool request, which saves model turns and so lowers the cost of tool-heavy chats.
  • 🧭 Tool Search engines. Tool Search in the admin Interface settings can now match tools with embeddings from the Documents embedding model (kept in memory, not stored) or by sending the query and tool definitions to a relevance-scoring API, besides the default keyword search.
  • 🏷️ Readable tool call labels. Administrators can now turn on Tool Call Labels in Admin Settings > Interface or with "ENABLE_TOOL_CALL_LABELS", off by default, to ask the model for short descriptions in the user's language of what each tool call is doing and what it did. Commit
  • ✂️ Chat read limit. Admins can limit how much of an earlier chat the Chat History tools return, with "VIEW_CHAT_MAX_CHARS" or the new Chat Read Limit field in Admin Settings > General, and the newest messages are kept while older ones are cut. #33695, #33608
  • 🌍 Client IP header placeholders. Custom headers of connections can now use "{{USER_IP}}" and "{{X_FORWARDED_FOR}}" to pass the client address on to the upstream provider, and both are empty for automations and background jobs. #33833, #33819
  • ✉️ Non-ASCII email addresses. The sign-up page and the add and edit user dialogs now accept email addresses with non-ASCII characters. #33693, #33681
  • 🕒 Reply finish time. Assistant replies now show the time they finished instead of the time the prompt was sent. #33895
  • 🧐 Channel message search. Each channel header has a Search button that searches the messages of that channel.
  • 🔔 Notifications open their chat. Clicking a desktop notification now brings Open WebUI to the front and opens the related chat, channel or calendar.
  • 📮 MCP Apps message the chat. An MCP App can now send a text message to the chat, which you confirm first in a Confirm Prompt from Embed dialog. #33907
  • 🖱️ Drag chats into side panel. Dragging a chat from the sidebar onto the chat area opens it as a side chat tab, and a side chat can now also be started from an empty new chat.
  • 🪄 Quick open files. A new shortcut, Cmd+P (Ctrl+P elsewhere), opens a search box that finds files in the selected terminal by name or path and opens the one you pick in a tab.
  • 🎹 Tab keyboard shortcuts. New shortcuts, which can be changed in Settings > Keyboard, open the Files, Desktop, Comments, new chat, new file, new terminal and new browser tabs, close and switch between tabs and toggle the split screen.
  • 🗺️ Working directory picker. The message input has a working directory menu with folder search, a Recently Used list kept per user on the terminal and an Open Folder dialog.
  • 📂 Folder default terminal. A folder can now have a default terminal and working directory in its Advanced settings, used for new chats in that folder.
  • 🧾 Editable spreadsheets. Excel files in the file view can now be edited in the preview, with a formula bar, pasting from other spreadsheets and resizable columns, and saved back to the file, while formula cells and protected sheets stay read-only.
  • 🖋️ Markdown and code editing. Markdown files in the file view now open in a rich text editor that saves back to Markdown, where pasted or dropped images are uploaded to the terminal, and the code editor suggests words that already appear in the file. Other text files and the Source view of previews now use the code editor directly, without a separate Edit step. Commit
  • 🌳 Clone Git repositories. The file browser and the folder pickers can now clone a Git repository from an HTTP(S) or SSH URL into the chosen folder of the selected terminal.
  • 🧬 Git changes in the editor. The code editor now marks the lines of a file that were added or changed since the last commit.
  • 🔖 File browser Git status. Files and folders in the file browser are marked with a Git status letter such as M, A, D or U, and folders show that they contain changes.
  • 🌿 Git panel feedback and resizing. The Git panel now shows what it is doing, such as staging, pushing or fetching, and its file list can be resized.
  • 🧹 Discard any Git change. The Git panel can now discard staged and new files too, and its confirmation warns that files not in the last commit are deleted and that this cannot be undone.
  • 🧲 Drag files into chat. Files from the terminal file browser can be dragged, one or several at once, into the message input to attach them, also with a long press on touch screens.
  • 🗃️ Multiple Files tabs. The + menu can now open several Files tabs for the same terminal, each with its own folder and the folder name as its tab title, and moving files refreshes the other Files tabs on that terminal. Commit
  • 🔲 Drag to select files. Several files in the file browser can now be selected by dragging a selection box over them.
  • 🪂 Spring-loaded Files tabs. Holding a dragged file over a Files tab for half a second switches to that tab, so files can be moved into folders of another tab.
  • ⚡ Faster terminal rendering. The terminal tab now renders with WebGL where the browser supports it and takes in bursts of output in larger batches, so heavy output is handled faster.
  • 🩺 Terminal system info. The terminal menu now has a System info view with the terminal's CPU, memory, disk, network, uptime and top processes.
  • 🖌️ Edit images from the terminal. The image edit tool can now take source images from the selected terminal by file path, as PNG, JPEG, WebP or GIF up to 25 megapixels. #33824
  • 🎙️ Voice notes in files. A new shortcut, Cmd+Alt+M (Ctrl+Alt+M elsewhere), records a voice note, can transcribe it, and saves the recording with a Markdown note in the current folder of the selected terminal, then opens the note in a tab. Escape cancels a recording. #33902, #33903
  • 📢 Model availability events. Open WebUI now publishes model.available and model.unavailable events when a model appears in or disappears from the fetched model list.
  • 🗒️ Descriptions in model pickers. The tool, skill, filter, action and sub-agent pickers in the model editor now show each item's description under its name. #33723
  • 🔢 Grouped token counts. Whole numbers in the token usage tooltip are now grouped by thousands for the interface language, for example 26,678,623. #33896
  • 🎼 Notification sound styles. The notification sound setting now offers Chime, Soft, Bell and Tap sounds, with a play button to preview each one.
  • 🔄 General improvements. Various improvements were implemented across the application to enhance performance, stability, and security.
  • 🌐 Translation updates. Translations for Portuguese (Brazil), Azerbaijani, Basque, Bengali, Bosnian, Bulgarian, Cebuano, Croatian, Czech, Danish, Dutch, Estonian, Faroese, Filipino, Galician, Georgian, German, Greek, Hebrew, Hindi, Hungarian, Indonesian, Irish, Japanese, Kabyle, Korean, Lithuanian, Malay, Norwegian Bokmål, Persian, Polish, Punjabi, Romanian, Russian, Serbian, Slovak, Slovenian, Spanish (Spain), Swedish, Tamil, Thai, Tibetan, Turkish, Turkmen, Ukrainian, Urdu, Uyghur and Vietnamese were enhanced and expanded.

  • 🛂 Model required before sending. The file ask box, follow-up suggestions and queued messages now report "Model not selected" instead of trying to send when no model is selected. #33838
  • 👻 Temporary chat button with tabs. The Temporary Chat button is back on new chats when the tabbed layout is on. #33680
  • 🪧 Stable MCP app views. MCP apps in chat no longer reload and lose their state while the message around them updates.
  • 🎴 Artifacts keep the chat visible. Opening an HTML or SVG preview from a reply now uses the side pane instead of replacing the visible chat tab. #33894
  • 📣 Banners in tabbed view. Admin banners and license notices now show on the new chat page when the terminal tabs split the screen. #33789
  • 📡 Tabs over plain HTTP. The New File, New Terminal and Browser tabs in the side panel now open when Open WebUI is reached over plain HTTP on a LAN or Docker address. #33847, #33845
  • 🕶️ Per-chat terminals in temporary chats. Per-chat workspace terminals are no longer offered in temporary chats, where sending to them failed, and one already selected is deselected when Temporary mode is turned on. #33866, #33861
  • 🖥️ Terminal kept on model switch. Switching to a model without its own default terminal no longer turns off the terminal selected in the chat.
  • 📁 Working folder in new chats. The terminal working folder of a new chat is no longer reset to the root when the chat is created before the file browser has finished loading.
  • 📞 Return to call. The Return to call button now reopens the active voice call after switching to the chat tab. #33898
  • 🔕 Channel notifications clear on read. Opening a channel now marks its notifications as read.
  • 🪝 Webhooks window stability. The channel Webhooks window no longer jumps back to the webhook list when a new message arrives, so edits in progress are kept. #33776, #33775
  • 🎧 Background audio on iOS. With Auto-Playback Response off, tapping in Open WebUI or opening a chat no longer stops audio playing in other apps on iOS. #33780
  • 🖨️ Scanned PDF preview. PDF previews no longer show blank pages for scanned PDFs that store their pages as JPEG2000 images. #33906, #33905
  • 🔬 Preview zoom stability. Zooming in PDF, Word and PowerPoint previews no longer resets or drifts when you switch tabs, change slides or resize the pane. #33836, #33835
  • 📌 File preview from Controls. A file preview opened from the Controls menu no longer closes when you click inside it. #33831, #33828
  • 🔭 Tab bar and UI scale. Tab content no longer slides under the tab bar when the UI scale is above 1. #33830, #33829
  • 🔘 Desktop app top clicks. In the desktop app, banners and menus near the top of the window now take clicks instead of dragging the window.
  • 📱 Mobile menu keyboard. Closing the + menu on a phone no longer opens the keyboard. #33893
  • 📝 File rename in terminal. Renaming a file or folder in the Open Terminal file browser no longer shows a false error after the rename succeeded. #33786
  • 📋 Stable file selection. Selecting files no longer shifts the file rows when the bulk action bar appears, and clicking an empty area of the file list clears the selection. Commit
  • 🫥 Selection popups on scroll. Scrolling the file view dismisses its Ask box, and scrolling a rich text editor dismisses its floating formatting menus until the selection changes. Commit, Commit
  • 🙈 Empty control groups hidden. When every control of a group is hidden with Visible controls, the empty group heading or submenu no longer shows. #33867
  • 🌄 Chat background behind tabs. The chat tab bar no longer covers the chat background with a solid strip. #33849
  • 🌫️ Top bar blur. The top bars of Workspace, Admin Panel, Playground and Calendar no longer blur a page background image. #33799, #33798
  • 🗑️ Feedback model filter. Deleting the last feedback of a model in the Evaluations feedback list now clears the model filter. #33794, #33793
  • 🔤 Visible controls labels. Six toggles under Visible controls in the Admin Interface settings now show their names instead of raw translation keys. #33734
  • 🤫 Quiet terminal disconnects. Closing the file panel or a terminal view right after opening it no longer logs an error traceback on the server. #33863, #33850
  • 📜 Quieter MCP connection logs. Logs no longer fill with a warning for every MCP server a user has not connected yet each time they load Open WebUI. #33663
  • 🪪 OAuth token refresh warnings. Refreshing OAuth tokens with a client secret no longer logs deprecation warnings on every call. #33700, #33297

Changed

  • ⚠️ Database Migrations: This release includes database schema changes; we strongly recommend backing up your database and all associated data before upgrading in production environments. If you are running a multi-worker, multi-server, or load-balanced deployment, all instances must be updated simultaneously, rolling updates are not supported and will cause application failures due to schema incompatibility.
  • 💥 Preload files off by default. With native function calling, the default, attached files are no longer added to the conversation automatically, and models read them with their file tools instead. Models without tool support or without the Files built-in tool can no longer see attached files until you turn on Preload files in the model's Capabilities. Legacy function calling, and API requests that do not come from a chat in the web UI, keep the old behavior. #33815
  • 🎯 Retrieval defaults. Unless you saved your own values, "RAG_TOP_K" and "RAG_TOP_K_RERANKER" now default to 10 instead of 3, and "CHUNK_SIZE" to 1024 instead of 1000. Each query now retrieves more text, so prompts with knowledge get longer. The new chunk size applies to files processed from now on; existing knowledge keeps its chunks until it is reindexed.
  • 🧷 Context as hidden tool results. With native function calling, memory recall, the skills list and the attached knowledge list now arrive as hidden tool results after your message instead of in the system prompt. This is what keeps tool chats cacheable, and it means custom pipes can see a tool message as the last message.
  • 🗨️ Side chats are saved. Side chats, which were always temporary in 0.13.0, are now saved as regular chats and appear in the chat list. They stay temporary only when you turn on Temporary Chat in the side chat or your admin enforces temporary chats.
  • 🚧 Tool call limit. Reaching the tool call limit now makes the model write a final answer without tools, instead of ending the reply with the "Tool-call limit reached" error.
  • 🔦 Tool Search prompt. With Tool Search on, the model no longer sees a list of the hidden tools and finds them only by searching.
  • ✏️ Always Use Full Text. The Full Context Mode setting in the admin Documents settings is now called Always Use Full Text and includes complete documents regardless of the full text threshold.
  • ↔️ Always full-width tabs. On large screens the tabbed workspace now always fills the chat area, with the chat as one of its tabs, and the full-width toggle added in 0.13.0 is gone.
  • 🔀 Integrations moved into + menu. The Integrations button is now part of the + menu in the message input, and the new Show Input Selections setting, off by default, controls whether selected tools, skills, filters and capabilities are shown beside it.
  • 🔓 Side chat permission. The Allow Side Chat permission no longer requires the Temporary Chat permission.
  • 🕸️ Chrome first in Browser tab. The Browser tab now starts in Chrome mode when the terminal offers it, and switches to Proxy mode with a message if Chrome fails to start.
  • ⛔ Terminal select setting removed. The Show Files on Terminal Select setting has been removed from the Interface settings. #33855, #33840
