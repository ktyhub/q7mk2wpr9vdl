open-webui v0.13.4

Hinzugefügt

  • Bringen Sie Ihren eigenen Computer mit Tether mit. Tether macht Ihren eigenen Computer zu einem Teil von Open WebUI: Modelle von Ollama, LM Studio oder jedem OpenAI-kompatiblen Server, OpenAPI- und MCP-Tool-Server und Open Terminal-Server, die Sie in der Tether-App hinzufügen, werden jetzt nur für Sie in der Modellauswahl, der Tools-Liste des +-Menüs und dem Terminal-Menü jedes Open WebUI angezeigt, das Sie verbinden, von jedem Gerät aus, auf dem Sie es öffnen, und Open WebUI erreicht sie über Tether, also ihre Adressen, Befehle und Schlüssel verlassen niemals Ihren Computer. Hierfür ist Tether 0.1.14 oder höher oder 0.1.16 für MCP-Server, Tool-Server und Terminals erforderlich. „ENABLE_TOOL_SERVERS“ muss aktiviert sein, und ein Tether-Modell, dessen ID mit einem bereits in Open WebUI vorhandenen Modell übereinstimmt, bleibt verborgen. Tether ersetzt Direktverbindungen. #34397
  • Sandbox-Agenten auf Ihrem eigenen Computer. Tether 0.1.13 oder höher kann das Terminal auf Ihrem Computer in einer Sandbox sperren, sodass Modelle und Codierungsagenten in Ihren echten Dateien arbeiten, ohne den Rest Ihres Computers zu erreichen: Auf macOS und unterstützten Windows-Geräten können Open Terminal und alles, was es startet, einschließlich Codierungsagenten, nur den einen Ordner berühren, den Sie auswählen, und offline ausgeführt werden, es sei denn, Sie aktivieren den Netzwerkzugriff und akzeptieren keine eingehenden Verbindungen, ohne dass Docker, eine virtuelle Maschine oder ein Administrator-Setup erforderlich sind. Wenn die Sandbox nicht erzwungen werden kann, bleibt das Terminal angehalten, anstatt stillschweigend ohne sie zu laufen, und die Browser- und Desktop-Steuerung bleibt ausgeschaltet, während sie eingeschaltet ist. Aktivieren Sie es in Tether unter Einstellungen > Terminal öffnen > Sandbox.
  • Lokale MCP-Server über Tether. Open WebUI kann jetzt MCP-Server verwenden, die als lokaler Befehl über stdio ausgeführt werden, so wie viele MCP-Server verteilt sind, indem Sie sie über Tether 0.1.16 oder höher auf Ihrem Computer starten, ohne Proxy wie mcpo und ohne zu öffnenden Port. Fügen Sie einen in Tether unter Einstellungen > Integrationen > Tools mit seinem Befehl hinzu oder verbinden Sie einen MCP-Server über seine Webadresse und wählen Sie ihn aus der Tools-Liste des Menüs „+“ aus. Lokale Befehle werden mit dem Zugriff Ihres eigenen Kontos außerhalb der Workspace-Sandbox von Tether ausgeführt.
  • Ein Computer für jeden Benutzer. Wenn Terminals 0.4.0 oder höher angeschlossen sind, verteilt Open WebUI jetzt Sandbox-Computer bei Bedarf: Jeder mit Schreibzugriff auf die Verbindung kann direkt über das Terminalmenü der Nachrichteneingabe ein Terminal erstellen, auswählen, ob jeder einen Computer teilt oder jeder Benutzer, Chat oder Modell seinen eigenen erhält, und dessen Image, CPU, Speicher, Speicher, Netzwerkprofil, Umgebungsvariablen, Startverzeichnis und ein Setup-Skript festlegen, das beispielsweise ein Repository klont und seine Abhängigkeiten installiert, ohne dass eine Administratoreinstellung erforderlich ist jeden einzelnen auf. Terminals können mit Benutzern und Gruppen geteilt und ihre Instanzen gestartet, gestoppt, neu gestartet oder gelöscht werden. Eine Option zum Anzeigen von Dateien öffnet die Dateien eines beliebigen Terminals, ohne es für den Chat auszuwählen. Systeminformationen zeigen, wie das Setup-Skript gelaufen ist, und diejenigen, die ein Terminal verwalten, können die Dateien und Systeminformationen der laufenden Instanzen anderer Personen öffnen. Start und Stop benötigen Terminals 0.4.1 oder höher, das Startverzeichnis und das Setup-Skript benötigen Open Terminal 0.17.7 oder höher im Image des Terminals und Netzwerkprofile sind diejenigen, die ein Administrator mit „TERMINALS_NETWORK_PROFILES“ definiert hat.
  • Codierungsagenten als Chat-Modelle. Codierungsagenten funktionieren jetzt ähnlich wie jedes andere Modell im Chat. Hermes, Antigravity, GitHub Copilot, Goose und Qwen Code schließen sich Codex, Claude Code, Cursor, Grok, OpenCode, Cline, Gemini CLI und Pi an, und jeder andere ACP-Agent, der mit „OPEN_TERMINAL_ACP_AGENTS“ zu Open Terminal hinzugefügt wurde, funktioniert ebenfalls, sobald er auf dem Terminal installiert und angemeldet ist. Mit Auto für Tool-Berechtigungen können Codex, Claude Code und Grok jetzt Routineaktionen selbst genehmigen und nur das weitergeben, was sie eskalieren. Der Argumentationsaufwand in den erweiterten Parametern gilt jetzt auch für Claude Code-, Pi- und ACP-Agenten, die Aufwandsstufen anbieten, wie z. B. OpenCode, die mit einem Fehler anhalten, wenn die gewählte Stufe für das Modell nicht angeboten wird. Antworten können jetzt neu generiert und frühere Nachrichten bearbeitet werden, und ein abgezweigter oder geklonter Agenten-Chat macht dort weiter, wo der ursprüngliche aufgehört hat: Codex setzt seine eigene Konversation von diesem Punkt an fort, andere Agenten beginnen mit dem bisherigen Chat von vorne und Dateiänderungen, die der Agent bereits vorgenommen hat, bleiben bestehen. Claude Code setzt seine eigene Konversation auch mit der nächsten Open Terminal-Version nach 0.17.20 fort und bittet Sie bis dahin, stattdessen Open Terminal zu aktualisieren. Die neuen Agenten und Auto für Claude Code und Grok benötigen Open Terminal 0.17.19 oder höher, und der Aufwand für Claude Code-, Pi- und ACP-Agenten erfordert 0.17.9 oder höher. #34167
  • Seiten werden als Registerkarten geöffnet. Notizen, Kanäle, der Arbeitsbereich, Automatisierungen, der Kalender, der Spielplatz, die Startseite und neue Chats von angehefteten Modellen werden jetzt als Registerkarten neben dem aktuellen Chat geöffnet, wenn Sie sie aus der Seitenleiste auswählen oder ziehen, sie im Benutzermenü auswählen oder einem Link zu einer davon in einer Chat-Nachricht folgen. Beim Starten eines neuen Chats, ebenfalls aus einem Seitenleistenordner, bleiben die Registerkarten geöffnet.
  • Nachrichten in der Warteschlange steuern Antworten. Eine Nachricht, die Sie an Ihren eigenen Chat senden, während noch eine Antwort ausgeführt wird, wartet jetzt auf dem Server, sodass sie beibehalten wird, wenn Sie die Seite verlassen, und die Antwort im nächsten Schritt abgeschlossen wird, sodass Ihre Nachricht sofort mit dem beantwortet wird, was sie bisher getan hat.
  • Sofortige erste Nachricht. Die erste Nachricht eines neuen Chats wird jetzt sofort angezeigt, während der Chat noch erstellt wird, und nicht erst, wenn er existiert, es sei denn, es werden noch Dateien damit hochgeladen.
  • Vollständiger Chat in Nebenchats. Nebenchats führen jetzt denselben Chat wie die Hauptansicht aus, daher funktionieren dort jetzt auch Nachrichtenschaltflächen, Quellen, Token-Nutzung, Folgevorschläge, Slash-Befehle, Nachrichten in der Warteschlange, Chatvariablen, Websucheinstellungen, Toolereignisse wie Codeausführung und Eingabeanforderungen, HTML- und SVG-Vorschauen, Benachrichtigungen, während das Fenster im Hintergrund ist, nicht gesendeter Text nach dem Neuladen einer Seite und Antworten von mehreren Modellen gleichzeitig, und die Registerkarte eines Nebenchats verfügt jetzt über das Chat-Menü. #34064, #34165, #34147, #34031
  • Interaktive Visualisierungen. Modelle können jetzt interaktive Diagramme, Diagramme, Taschenrechner und Erklärungen direkt im Chat mit dem neuen integrierten Tool „Visualisierungen“ zeichnen, das standardmäßig deaktiviert und pro Modell unter „Eingebaute Tools“ aktiviert ist. Administratoren können seine Anweisungen unter Admin-Einstellungen > Schnittstelle > Visualisierungsaufforderung oder mit „VISUALIZATION_PROMPT_TEMPLATE“ umschreiben.
  • Videogenerierung. Modelle können jetzt Videos mit einem integrierten Tool generieren, auch beginnend mit einem Bild im Chat, sobald ein Administrator die Videogenerierung unter Admin-Einstellungen > Videos aktiviert, Verbindungen zu OpenAI, LiteLLM oder OpenRouter hinzufügt, das Modelle wie Veo und Kling mit einem Standardvideomodell, Standardeinstellungen pro Modell und Zugriffseinstellungen bietet und die Berechtigung zur Videogenerierung erteilt, die standardmäßig deaktiviert ist. Anschließend können Benutzer Video im Menü „+“ aktivieren, das Modell dort auswählen und das Ergebnis ansehen der Chat. #13780, #13927
  • Mehrere Bildmodelle. Administratoren können jetzt unter Admin-Einstellungen > Bilder mehrere Bildverbindungen hinzufügen, jeweils einen OpenAI-kompatiblen Server wie LiteLLM, Gemini, ComfyUI oder AUTOMATIC1111 mit eigenen Modellen, Größen, Arbeitsabläufen und Zugriffen, die zum Generieren, Bearbeiten oder beidem von Bildern verwendet werden, wobei OpenAI-kompatible Verbindungen dieselben Anmeldeoptionen und benutzerdefinierten Header wie Modellverbindungen bieten und die Bildmodelle eines LiteLLM-Servers einzeln auflisten, wenn keine Modell-IDs eingegeben werden. Wählen Sie die aus Sie können Modelle standardmäßig generieren und bearbeiten und einem Modell in seinen Einstellungen ein eigenes Standardbildmodell zuweisen. Benutzer mit mehr als einem Bildmodell wählen eines aus dem Eintrag „Bild“ im Menü „+“ der Nachrichteneingabe aus. #10344
  • Git-Panel wird zu einer GitHub-Workbench. Mit Open Terminal 0.17.8 oder höher und dem am Terminal angemeldeten GitHub CLI, wie in den vollständigen Agenten- und Cuda-Images enthalten, deckt das Git-Panel jetzt die gesamte GitHub-Schleife ab: Durchsuchen, Suchen, Erstellen, Bearbeiten, Kommentieren, Schließen und erneutes Öffnen der Repository-Probleme, Anzeigen der Prüfungen jeder Pull-Anfrage, Überprüfungsstatus, Beschriftungen, Aktivitäten und Konflikte mit einem Statusfilter und einer Auswahl an Zusammenführungsmethoden und durchsuchen Sie Probleme und Pull-Anfragen im gesamten Repository statt nur in der geladenen Liste. Schaltflächen wie „Daran arbeiten“, „Beheben“, „Feedback adressieren“ und „Konflikte im Chat lösen“ übergeben das Problem, die Überprüfung oder den Konflikt als vorgefertigte Anfrage in der Nachrichteneingabe an das Modell. Geänderte Dateien können mit Strg oder Umschalt click ausgewählt werden, um mehrere auf einmal oder alle zu verwerfen.
  • Terminals folgen Ihren Chats. Jeder Chat speichert jetzt sein Terminal und seinen Arbeitsordner und wechselt zu diesen zurück, wenn Sie ihn erneut öffnen, einschließlich eines Terminals, das Sie ausgeschaltet haben, und Administratoren können unter Admin-Einstellungen > Modelle > Modellstandards ein Standardterminal auswählen, mit dem neue Chats für jedes Modell ohne eigenes Terminal beginnen, sodass jeder Chat mit angeschlossenem Computer beginnen kann. Chats aus früheren Versionen werden ohne Terminal geöffnet, es sei denn, es handelt sich um Coding-Agent-Chats.
  • Ordner-Chat-Board. Ordnerseiten listen ihre Chats jetzt mit einer Suche nach Titeln und Nachrichten und Filtern nach Status, Tags, Personen, Aktivität und letzter Aktualisierung auf und können sie als Board mit Spalten und Zeilen nach Status, Tag oder Aktivität wie „ungelesen“, „generiert“ oder „wartend auf Genehmigung“ anzeigen. Außerdem gibt es für jeden Chat dort das Chat-Menü der Seitenleiste zum Umbenennen, Verschieben, Archivieren oder Löschen, und das Abzeichen eines Ordners in der Seitenleiste zählt jetzt auch Chats, die auf Genehmigung warten. #33771
  • Chat-Status in Ordnern. Ordner können jetzt Status für ihre Chats unter „Status bearbeiten“ einrichten, wobei „Rückstand“, „Zu erledigen“, „In Bearbeitung“, „Warten“ und „Fertig“ als Vorschläge angeboten werden. Chats erhalten dann einen Status aus ihrem Menü auf der Ordnerseite oder durch Ziehen zwischen den Board-Spalten können Personen, die einen freigegebenen Ordner bearbeiten können, den Status jedes Chats darin festlegen, und jeder Chat zeigt an, wie lange er sich bereits in seinem Status befindet.
  • Ordnerautomatisierungen. Ordnerseiten haben jetzt einen Abschnitt „Automatisierungen“, der die Automatisierungen des Ordners mit ihrem Status und ihrer letzten Ausführung auflistet und dort neue erstellt. Von einer Automatisierung erstellte Chats werden mit einer Uhr markiert und Automatisierungen können jetzt in freigegebenen Ordnern gepostet werden, die ihr Ersteller bearbeiten kann, wo jeder, der den Ordner bearbeiten kann, sie anhalten und ausführen und ihre Ausführungen sehen kann.
  • Wissen auf Ordnerseiten. Ordnerseiten haben jetzt einen Wissensbereich, der die Wissensdatenbanken, Notizen, Chats und Dateien auflistet, die neue Chats im Ordner verwenden können, wo Sie sie hinzufügen, hochladen, löschen, öffnen und entfernen können.
  • Farbige Chat-Tags. Tags können jetzt auf der Ordnerseite eine Farbe erhalten, die überall dort gilt, wo das Tag verwendet wird. Das Chat-Menü verfügt über ein Tags-Untermenü zum Suchen, Hinzufügen und Erstellen von Tags. Personen, die einen freigegebenen Ordner bearbeiten können, können jeden darin enthaltenen Chat mit Tags versehen.
  • Automatisierungen direkt bearbeiten. Auf der Seite einer Automatisierung werden jetzt Name, Anweisungen, Status, Zeitplan, Modell, Terminal und Ziel direkt dort bearbeitet. Die Schaltfläche „Speichern“ erscheint, sobald sich etwas geändert hat. Sie zeigt gespeicherte Anweisungen eingeblendet hinter „Mehr anzeigen“ an, listet ihre Ausführungen unten als Aktivität auf und verfügt im Menü „Mehr“ über „Link kopieren“ und „Duplizieren“.
  • Lesbare Agenten- und Terminalschritte. Schritte von Codierungsagenten und Terminaltoolaufrufen anderer Modelle werden im Chat jetzt als das angezeigt, was sie getan haben, ein Befehl mit seiner Ausgabe und seinem Exit-Code, wenn er fehlgeschlagen ist, ein Vergleich jeder bearbeiteten Datei mit ihren hinzugefügten und entfernten Zeilen oder den gelesenen Dateien, Code- und Websuchen, aufgelisteten Ordnern und abgerufenen Seiten, und eine Gruppe von Schritten wird beispielsweise als „2 Befehle ausgeführt“, „1 Datei bearbeitet“, „3 Dateien gelesen“ zusammengefasst. Für Dateiunterschiede, die andere Modelle über die Terminal-Tools bearbeiten, ist Open Terminal 0.17.20 oder höher erforderlich.
  • Models können Personen erwähnen. Mit dem integrierten Tool „Chat-Verlauf“ können Models jetzt Benutzer anhand ihres Namens oder ihrer E-Mail-Adresse suchen und sie in einer Antwort erwähnen. Jeder erwähnte Benutzer, der den Chat sehen kann, erhält eine Posteingangsbenachrichtigung, die den Chat bei dieser Antwort öffnet.
  • OpenAI-kompatible Vektorspeicher. Externe Wissensquellen unter Admin-Einstellungen > Integrationen können jetzt OpenAI-kompatible Vektorspeicher auf OpenAI, Azure OpenAI oder LiteLLM sein, die auf dem Server durchsucht werden, sodass kein passendes Einbettungsmodell erforderlich ist, und Sie wählen entweder einen oder mehrere Speicher für eine Wissensdatenbank aus oder aktivieren „Speicher als Wissensdatenbanken auflisten“, um alle Speicher der Verbindung oder nur ausgewählte als schreibgeschützte Wissensdatenbanken anzuzeigen, die mit dem Endpunkt synchron bleiben und den Zugriff der Verbindung teilen Einstellungen.
  • Überprüfen Sie die Einstellungen vor dem Speichern. Auf den Admin-Einstellungsseiten wird jetzt neben „Speichern“ angezeigt, wie viele Einstellungen seit dem Laden oder Speichern geändert wurden. Durch Klicken auf diese Zahl oder „Speichern“ wird jede Änderung mit ihrem alten und neuen Wert zur Bestätigung aufgelistet, wobei Passwörter und API Schlüssel ausgeblendet bleiben. #34534, #34532
  • Flüssigere Antworten mit Codeblöcken. Lange Antworten mit vielen Codeblöcken verzögern den Tab beim Streamen nicht mehr mit jedem neuen Codeblock etwas länger, sodass eine Antwort mit 300 Codeblöcken, die auf einmal eintrifft, jetzt in 9 Sekunden statt in mehr als zwei Minuten angezeigt wird. #34495, #34492
  • Schnellere große PDF-Vorschauen. Lange PDFs in der Dateivorschau werden jetzt in etwa einer Sekunde geöffnet und verbrauchen deutlich weniger Speicher, da nur die Seiten in der Nähe des Bildschirms gezeichnet und die Seiten in der Ferne freigegeben werden, sodass ein 1500-seitiges Handbuch nicht mehr länger als eine halbe Minute dauert und eine große gescannte Datei den Browser nicht mehr über viele Gigabyte hinausschiebt. Die Suchfunktion des Browsers (Strg+F) findet jetzt nur Text auf Seiten in der Nähe des Bildschirms. #34602, #29576
  • Schnelleres erneutes Öffnen von Ordnern. Beim erneuten Öffnen eines Ordners werden jetzt sofort dessen Chats, Details und Codierungsagentenmodelle angezeigt und im Hintergrund aktualisiert. Seitenleistenordner behalten ihre geladenen Chats, wenn sie minimiert und wieder erweitert werden, und Ordner-Chatlisten werden sofort aktualisiert, wenn ein Chat umbenannt, verschoben, archiviert oder gelöscht wird.
  • Schnellere Modellliste mit Redis. Mit Redis wird die Modellliste jetzt schneller geladen und Redis speichert nicht mehr eine Kopie jedes Modellprofilbilds, was bei großen animierten oder importierten Bildern am meisten hilft, und Funktionen und Tools empfangen das Modell jetzt ohne sein Profilbild. #34595, #34594
  • Schnellere Profilbilder und Wissensexporte. Große Profilbilder von Benutzern, Modellen und Kanal-Webhooks sowie Wissensdatenbankexporte werden jetzt in einem Stück gesendet, sodass ein 2 MB großes Bild in etwa 15 ms statt in einigen Hundert geladen wird und eine Seite voller großer Avatare nicht mehr Sekunden dauert und der Export einer Wissensdatenbank nicht länger die Anfragen anderer Benutzer auf demselben Serverprozess verzögert, während das Archiv gepackt wird. #34598, #34597, #34600, #34599
  • Gemeinsame Chat-Terminals. Personen, die auf einen mit „Antworten zulassen“ geteilten Chat antworten können, können jetzt im Terminal dieses Chats arbeiten, wie der Freigabedialog jetzt zeigt: Mit einer Terminal-Vorlage, die jedem Chat seinen eigenen Computer zuweist, und in Codierungsagenten-Chats arbeiten sie auf demselben Computer und in denselben Dateien wie der Eigentümer, während sie bei anderen Terminals ihren eigenen Zugriff darauf verwenden. #34103
  • Upgrades der Registerkarte „Dateien“. Bei einem Terminal, das Dateiänderungen meldet, aktualisiert sich die Registerkarte „Dateien“ jetzt von selbst ohne Lade-Spinner, wenn sich Dateien in den angezeigten Ordnern ändern, auch durch Befehle, die außerhalb des Chats ausgeführt werden. CliWenn Sie den Pfad darüber anklicken, können Sie einen Ordner eingeben, zu dem Sie gehen möchten, absolut oder relativ zum aktuellen, wobei die Tabulatornamen die Ordnernamen vervollständigen, oder den vollständigen Pfad einer geöffneten Datei auswählen und kopieren. Markdown-Dateien erhalten eine Gliederungsschaltfläche, die ihre Überschriften auflistet und zu dem von Ihnen ausgewählten springt, und Ordner im Arbeitsverzeichnismenü der Nachrichteneingabe verfügen über eine Schaltfläche „Ordner öffnen“, die sie in einer neuen Registerkarte „Dateien“ öffnet. #34494, #34525
  • Terminal-Tab-Upgrades. Terminal-Tabs werden jetzt nach dem Titel benannt, den das darin ausgeführte Programm festlegt, oder nach dem laufenden Programm selbst mit Open Terminal 0.17.8 oder höher auf macOS und Linux und zeigen ein Symbol für bekannte Programme wie Claude Code, Codex, Python oder Node.js. Wenn kein Terminal für den Chat ausgewählt ist, bietet das Menü zum Öffnen eines neuen Tabs weiterhin Dateien, neue Dateien, Terminals, den Browser, den Desktop und Sprachnotizen. Wenn Sie zuerst eines auswählen, werden Sie aufgefordert, ein Terminal aus einer durchsuchbaren Liste auszuwählen.
  • Gruppierte Werkzeuge und Fertigkeiten. Die Listen „Werkzeuge und Fertigkeiten“ im +-Menü der Nachrichteneingabe sind jetzt nach der Herkunft jedes Eintrags gruppiert, z. B. dem Arbeitsbereich, den Werkzeugservern oder dem Terminal. #34085
  • Antwortfortschritt auf Tabs. Auf dem Chat-Tab und den seitlichen Chat-Tabs wird jetzt ein Spinner angezeigt, während eine Antwort geschrieben wird, sodass Sie auf einem anderen Tab sehen können, wann noch eine Antwort kommt.
  • Über die Registerkarte umbenennen. Double-cliWenn Sie auf die Registerkarte „Chat“ klicken, wird jetzt der Chat umbenannt, auch ein Chat, den jemand anderes in einem Ordner erstellt hat, der Ihnen gehört, und auf einer Ordnerseite wird der Ordner umbenannt.
  • Ordner über ihr Menü freigeben. Das Ordnermenü in der Seitenleiste und auf der Ordnerseite verfügt jetzt über eine Freigabeoption für Administratoren und für Besitzer, die Ordner freigeben dürfen.
  • Subagenten-Berechtigung. Administratoren können Subagenten jetzt auf ausgewählte Benutzer und Gruppen beschränken, indem sie den Schalter „Subagenten“ unter „Funktionen“ in den Standard- und Gruppenberechtigungen verwenden oder „USER_PERMISSIONS_FEATURES_SUBAGENTS“ verwenden. Benutzer ohne Subagenten erhalten weder den Subagenten noch das Timer-Tool. #34040, #34038
  • Leichtere Coding-Agent-Antworten. Während ein Coding-Agent seine Antwort schreibt, wird der Chat nicht mehr etwa einmal pro Sekunde vollständig gespeichert, sodass lange Agent-Chats für jede Antwort ein Vielfaches weniger in die Datenbank schreiben. #34062
  • Beschriftungen für fehlgeschlagene Tool-Aufrufe. Tool-Aufrufe, die fehlgeschlagen sind, behalten jetzt die kurze Beschriftung, die ihnen das Modell gegeben hat, auch in einer Gruppe von Aufrufen, bei der ein fehlgeschlagener Aufruf früher jede Beschriftung verbarg. #34000, #34529
  • Dateien in Skills ablegen. Dateien und Ordner, die auf die Dateien eines Skills im Arbeitsbereich gezogen werden, werden jetzt in den geöffneten Ordner hochgeladen, wie es die Upload-Schaltflächen tun.
  • Bearbeitbare Kalender. Kalender können jetzt umbenannt und mit einer anderen Farbe versehen werden, nachdem sie erstellt wurden, und zwar über einen Stift neben jedem Kalender in der Kalenderseitenleiste. #34136
  • Modellnamen in Analysen. Admin-Analysen benennen Coding-Agent-Modelle jetzt nach Agent und Modell für Antworten, die von nun an erfolgen, und in den Tooltips der Sitzungszeitleiste werden Modellnamen anstelle von Modell-IDs angezeigt.
  • Arena-Modellverwaltung. Der Ansichtsfilter in Admin-Einstellungen > Modelle verfügt jetzt über eine Option „Arena-Modelle“, die nur die Arena-Modelle auflistet, und jedes Arena-Modell in Admin-Einstellungen > Bewertungen verfügt über eine Schaltfläche „Klonen“, die ein neues Arena-Modell öffnet, das daraus ausgefüllt wird. #34137, #34138
  • OAuth-Sitzungsentfernungen protokolliert. Beim Entfernen einer gespeicherten OAuth-Sitzung aufgrund des „OAUTH_MAX_SESSIONS_PER_USER“-Limits, einer vom Identitätsanbieter oder einem erneut verbundenen MCP-Server gesendeten Abmeldung wird jetzt eine Warnung protokolliert, in der der Benutzer, die Sitzung und der Grund genannt werden. #34583, #34580
  • Verbesserungen der Barrierefreiheit. Eine mit Alt+Umschalt+Pfeiltasten verschobene Registerkarte behält jetzt den Tastaturfokus bei, sodass sie an mehrere Stellen hintereinander verschoben werden kann.
  • Allgemeine Verbesserungen. In der gesamten Anwendung wurden verschiedene Verbesserungen implementiert, um Leistung, Stabilität und Sicherheit zu verbessern.
  • Übersetzungsaktualisierungen. Übersetzungen für Aserbaidschanisch, Baskisch, Bengali, Bosnisch, Bulgarisch, Cebuano, Kroatisch, Tschechisch, Dänisch, Niederländisch, Estnisch, Färöisch, Philippinisch, Galizisch, Georgisch, Deutsch, Griechisch, Hebräisch, Hindi, Ungarisch, Indonesisch, Irisch, Italienisch, Japanisch, Kabyle, Koreanisch, Lettisch, Litauisch, Malaiisch, Norwegisch (Bokmål), Persisch, Polnisch, Portugiesisch (Brasilien), Punjabi, Rumänisch, Russisch, Serbisch, Slowakisch, Slowenisch, Spanisch (Spanien), Schwedisch, Tamilisch, Thailändisch, Tibetisch, Türkisch, Turkmenisch, Ukrainisch, Urdu, Uigurisch und Vietnamesisch wurden verbessert und erweitert.

Behoben

Added

  • Bring your own computer with Tether. Tether turns your own computer into part of Open WebUI: models from Ollama, LM Studio or any OpenAI-compatible server, OpenAPI and MCP tool servers and Open Terminal servers that you add in the Tether app now show up just for you in the model selector, the Tools list of the + menu and the terminal menu of any Open WebUI you connect, from whatever device you open it on, and Open WebUI reaches them through Tether, so their addresses, commands and keys never leave your computer. This needs Tether 0.1.14 or later, or 0.1.16 for MCP servers, tool servers and terminals need "ENABLE_TOOL_SERVERS" turned on, and a Tether model whose ID matches a model already in Open WebUI stays hidden. Tether replaces Direct Connections. #34397
  • Sandboxed agents on your own computer. Tether 0.1.13 or later can lock the terminal on your computer into a sandbox, so models and coding agents work in your real files without reaching the rest of your machine: on macOS and supported Windows devices, Open Terminal and everything it launches, coding agents included, can only touch the one folder you pick, run offline unless you turn on Network access and accept no incoming connections, with no Docker, virtual machine or administrator setup needed. If the sandbox cannot be enforced, the terminal stays stopped instead of quietly running without it, and browser and desktop control stay off while it is on. Turn it on in Tether under Settings > Open Terminal > Sandbox.

Open WebUI can now use MCP servers that run as a local command over stdio, the way many MCP servers are distributed, by launching them on your computer through Tether 0.1.16 or later, with no proxy such as mcpo and no port to open. Add one in Tether under Settings > Integrations > Tools with its command, or connect an MCP server by its web address, and pick it from the Tools list of the + menu. Local commands run with your own account's access, outside Tether's workspace sandbox.

With Terminals 0.4.0 or later connected, Open WebUI now hands out sandboxed computers on demand: anyone with Write access to the connection can create a terminal right from the terminal menu of the message input, pick whether everyone shares one machine or each user, chat or model gets its own, and set its image, CPU, memory, storage, network profile, environment variables, start directory and a setup script that, for example, clones a repository and installs its dependencies, without an administrator setting up each one. Terminals can be shared with users and groups and their instances started, stopped, restarted or deleted, a View files option opens any terminal's files without selecting it for the chat, System info shows how the setup script went, and those who manage a terminal can open the files and system info of other people's running instances. Start and Stop need Terminals 0.4.1 or later, the start directory and setup script need Open Terminal 0.17.7 or later in the terminal's image, and network profiles are the ones an administrator defined with "TERMINALS_NETWORK_PROFILES".

Hermes, Antigravity, GitHub Copilot, Goose and Qwen Code join Codex, Claude Code, Cursor, Grok, OpenCode, Cline, Gemini CLI and Pi, and any other ACP agent added to Open Terminal with "OPEN_TERMINAL_ACP_AGENTS" works as well, once it is installed and signed in on the terminal. Replies can now be regenerated and earlier messages edited, and a forked or cloned agent chat picks up where the original left off: Codex continues its own conversation from that point, other agents start over from the chat so far, and file changes the agent already made stay. Claude Code continues its own conversation too with the next Open Terminal release after 0.17.20 and until then asks you to update Open Terminal instead. The new agents and Auto for Claude Code and Grok need Open Terminal 0.17.19 or later, and effort for Claude Code, Pi and ACP agents needs 0.17.9 or later. #34167
  • Pages open as tabs. Notes, channels, the workspace, automations, the calendar, the playground, the home page and new chats from pinned models now open as tabs beside the current chat when you click or drag them from the sidebar, pick them in the user menu or follow a link to one of them in a chat message, and starting a new chat, also from a sidebar folder, keeps the open tabs.

With native function calling, the list of available skills and the attached knowledge are no longer added to the chat again before every reply, only when they changed or after compaction, and recalled memories already in the chat are not sent again, so long chats use fewer tokens and need compaction later. #34257
  • Tool call turns without text. Replies in which a model called a tool without writing any text are now sent back to the model without an empty text, so proxies such as LiteLLM no longer turn them into a placeholder line that the model then starts copying into its answers. #34265, #34264
  • Final answers on vLLM. When tool use stops, the request for a final answer no longer ends in a 400 error on vLLM, and Ollama models are kept from calling tools in it. #34176, #34169
  • Ollama proxy tool calls. OpenAI-compatible clients that send back an assistant turn with only tool calls and no text no longer get a 400 "Field required" error from the Ollama OpenAI-compatible chat endpoint, so multi-turn tool calling works through it. #34442, #34441
  • Timed-out tool calls explained. A terminal command or tool server call that runs past "AIOHTTP_CLIENT_TIMEOUT_TOOL_SERVER" now reaches the model as a timeout error instead of an empty one, so the model can tell you the call timed out. #34119, #34096
  • Tool calls in summaries. Conversation summaries written with the plain summary prompt, as for models with a filter, now include the tool calls of earlier replies in saved chats. #34139
  • MCP tools reconnect. When an MCP server drops its connection during a reply, for example because it restarted, the next call to one of its tools now connects again instead of every later call in that reply failing with an "MCP client is not connected" error. #34170
  • Large MCP tool lists. MCP servers whose tool list or a single tool result is larger than 1 MB connect and answer again, also through Tether, instead of failing with "Failed to connect to MCP server". #34421, #34201
  • MCP sign-ins with rotating tokens. Two tool calls that refresh the same MCP sign-in at the same time no longer delete the connection with providers that hand out a new refresh token on every refresh, because the refreshes now wait for each other, across workers when Redis is used. #34582
  • MCP OAuth with HS256 tokens. Connecting an MCP server over OAuth 2.1 now works when the server signs its ID token with the client secret, as Readwise does, instead of failing with "Algorithm 'HS256' requires 'oct' key". #34593, #34504
  • MCP OAuth with large headers. Adding an MCP server with OAuth 2.1 and refreshing its tokens now work when its authorization server sends a very large response header, as monday.com does, instead of failing with "Connection error". #34084, #34078
  • Sign-in prompt for SSO tools. When the single sign-on session whose token a tool server forwards has ended, those tools now show as needing a sign-in in the + menu and picking one takes you to sign in again, instead of the tools failing on every call with no hint. #34579
  • OAuth sessions on other devices. Signing in past "OAUTH_MAX_SESSIONS_PER_USER" now removes the stored provider sessions used least recently instead of the ones created first, so a device signed in early and still in use keeps its session, and signing out now removes that browser's stored session unless it is the person's only one for that provider. #34586, #34581
  • Quieter search logs. Knowledge searches and several web search engines no longer write found file names or full search results to the server log at the default level, only with "GLOBAL_LOG_LEVEL" set to "DEBUG". #34146, #34129
  • Deleted accounts leave access lists. Deleting an account now also removes it from the access lists of everything it was given access to, where it used to stay as a row showing only the deleted account's ID. #34223, #30023
  • Local speech-to-text on pip installs. Local speech-to-text in Open WebUI installed with pip now transcribes again instead of failing every recording with an error about "metadata_errors". #34280, #34278
  • OpenAI image generation defaults. Generating images with OpenAI now works with the stock settings, because GPT image models get the auto size instead of the old 512x512 default they reject and Auto can be saved with the model field left empty, and a failed request now shows the provider's own error, such as "Invalid size".
  • Fuller web page text. With the Playwright web loader, the text of definition lists, of figures with their captions and of collapsible sections, open or closed, now reaches the model, so attached web pages and web search results no longer lose content such as the function and parameter descriptions on many documentation sites. #34282, #34281, #34277, #34272
  • Unreachable sites skipped sooner. With SSL verification on, the Playwright, Tavily and Microsoft Web IQ web loaders now skip a site that never answers after 10 seconds instead of waiting about two minutes per link. #34490, #14241
  • Web pages behind internal certificates. With SSL verification on, the Playwright, Tavily and Microsoft Web IQ web loaders now load pages signed by an internal certificate authority set through "AIOHTTP_CLIENT_SSL_CERT_FILE" or "AIOHTTP_CLIENT_SESSION_SSL", and links that spell out a port or a username, instead of rejecting them. #34482, #34479, #34462
  • No keyboard pop-up on phones. On a phone, opening a chat, switching chats or starting a new chat no longer puts the cursor in the message input and brings up the on-screen keyboard over the conversation. #34059
  • Smooth Firefox scrolling. Scrolling up through a long chat in Firefox no longer throws the view back down, sometimes by several screens, while older messages load. #33998, #33994
  • Temporary chat choice kept. With Temporary Chat by default turned on in the interface settings, a new chat switched to a normal chat now stays normal after a page reload.
  • Permission changes reach open pages. When an admin changes permissions, open pages now follow without a reload, so a new chat that is open becomes a temporary chat once Enforce Temporary Chat is turned on instead of failing on the first message, Compare in the model selector turns off and only the first selected model stays once Multiple Models in Chat is turned off, an open channel shows the permission notice in place of the channel once Channels is turned off, and turning off Folders removes Move from the chat menu and closes an open Create Folder window. #34513, #34512, #34515, #34514, #34511, #34510, #34509, #34508, #34507, #34506
  • Images reach coding agents. Images attached to a message in a coding agent chat now reach the agent with the message instead of being dropped without a word. #33993, #33992, #33991
  • Coding agent chat titles. Chats with a coding agent now get a generated title once the agent has replied, instead of keeping the default title. #33971, #33970
  • Agent model switches keep sessions. Switching a coding agent chat to another model of the same agent now resumes the agent's existing session and working folder instead of starting a new session.
  • Readable coding agent errors. When the terminal refuses to start a coding agent, the reply now shows a short error instead of a technical dump containing the whole system prompt. #34173, #34172
  • Sub-agents with browser questions. A sub-agent no longer hangs on "Executing Sub-agent" when a filter or tool asks the browser something, because the script, confirmation or form now appears in the tab that has the chat open. #34045, #34041
  • Sub-agent reports stay together. Two background sub-agent reports that finish close together no longer split the chat into two branches that hide the first report and the reply to it. #34542, #34540
  • Shared chat changes saved. Someone replying in a chat shared with Allow replies can now change its model, terminal and working folder, and the choice is saved to the chat instead of being dropped when it is reopened.
  • Terminal choice kept in folders. In a new chat inside a folder with a default terminal, a terminal you pick or turn off now stays that way when the model changes, instead of going back to the folder default, and a new chat in a folder without a default terminal keeps the terminal you had selected instead of turning it off. #33973
  • Terminal locked during replies. The terminal and working folder pickers in the message input now stay locked while a reply is still being written, so the chat's terminal can no longer be switched in the middle of a reply. #34383
  • Steadier Tether connections. Requests to a computer connected through Tether are no longer cut off after five minutes while data keeps flowing, read-only requests interrupted by a brief disconnect are repeated once Tether reconnects, and a busy computer now refuses new operations right away instead of letting some of them time out.
  • Your devices list updates live. A computer that connects through Tether after the page has loaded now appears under Your devices in the terminal menu right away, and the menu also picks up disconnects and device name changes, instead of needing a page reload.
  • Unsaved terminal file edits kept. An edit not yet saved in a file opened from a terminal's Files tab now comes back with its unsaved mark after you open another chat and return, and a workbook saved while you leave the chat keeps the worksheet you had open. #34135, #34107
  • Long Markdown files. Opening a long Markdown file from a terminal's Files, or typing in one of its code blocks, no longer freezes the page for many seconds, because code blocks without a known language now show as plain text instead of being checked against every language, which also keeps notes and the rich text message input responsive. #34491, #34486
  • File cards follow the terminal. A file shown inline in a reply now gets its preview, Download and Open back as soon as its terminal is picked again, and stops reaching the file once another terminal is picked, instead of keeping its first state until a page reload. #34101
  • Working folder stays put. Browsing to another folder in a Files tab no longer changes the working folder shown in the working directory menu and used by a new chat, and opening Files again shows an existing Files tab where you left it instead of moving it to the working folder.
  • Terminal skill mentions after reload. A sent message that mentions a skill of the picked terminal now still shows it as a chip after a page reload, and the + menu lists that terminal's skills right away, instead of both only working after the skill list was opened once. #34102
  • File sizes after Refresh. In a terminal's file viewer, Refresh and the back and forward arrows now keep the open file's real size instead of showing 0 B, and Refresh shows the new size when the file changed. #34459, #34458
  • Files menu near edges. The menu from a right click on the empty part of a Files list now opens upwards or to the left when there is no room below or beside the pointer, so all of its entries stay inside the window. #34125, #34097
  • Local embedding model folders. With the embedding model set to a folder on disk, saving Admin Settings > Documents no longer shows a "Model filesystem path detected" error and now also saves the embedding settings such as the batch size, which were skipped before. #33978, #33977
  • PowerPoint decks with sections. PowerPoint files that use sections now preview in the chat and the knowledge base file viewer and show their comments, instead of failing with "Missing slide relationship". #34276, #34270
  • Large workbook sheets. Excel workbooks with a sheet too large to preview now still open with their sheet tabs in a terminal's Files tab, the chat and the knowledge base, where that sheet says it is too large to preview and can be downloaded, instead of the whole file failing to preview. #34247
  • Notes with footnotes. Notes containing footnote references such as "[^1]" now open and show their content instead of failing with an error. #33987, #33986
  • Note recordings on S3 storage. Recordings made in a note now upload to S3-compatible storage that rejects colons in file names and are named like "Recording-2026-11-16 15-25-06.webm" in every language, instead of after a date that slashes could cut short. #34545, #34543
  • Optional valves set to Custom. Switching an optional valve, such as an on/off setting, from Default to Custom in the Valves section of the chat controls no longer fails with "Error updating function user valves", and emptying an optional on/off or number valve sets it back to its default. #34478, #34475
  • Math in table headers. Formulas in table headers now keep their letters as written instead of being capitalized along with the header text. #34245, #34238
  • Math next to hyphens. Inline formulas written directly next to a hyphen or non-breaking hyphen, as some models write them, now render instead of staying plain text or showing a math error. #34244, #34237
  • Pinning keeps chat order. Pinning, unpinning, archiving or restoring a chat no longer moves it to the top of the chat list as if it had just been updated, and pinning a chat or moving it to a folder no longer marks it as read.
  • Drafts kept per folder. Unsent text in a new chat now stays with the folder or home page you typed it on, so opening another folder shows that folder's own unsent text instead of bringing yours along.
  • Links in messages. A link to a folder in a chat or channel message now opens the folder in Open WebUI instead of a new browser tab, and Ctrl or Cmd clicking a link to a chat, note or channel in a message now opens it in a new browser tab instead of the current one. #34464
  • Tagging chats in parallel. Adding the same new tag to several chats at the same time, as an API client tagging a batch of chats or two chat imports can do, no longer fails with a server error for all but one chat and leaves the others untagged. #34144, #34143
  • Thread reply notifications. Clicking the browser notification for a reply in a channel thread now opens that thread instead of the channel with the thread closed. #34233, #34232
  • Side chats after reload. A saved side chat tab restored after a page reload or on another device now shows only the side conversation again, instead of also listing the messages copied from the parent chat. #34002
  • Browser tab in two windows. With the same chat open in two windows, a Browser tab in Chrome mode no longer keeps reconnecting in both, and the window that lost the tab shows that the browser opened in another viewer. #34133, #34095
  • Ports open in new tabs. The Open in new tab button beside a port on the start page of a Browser tab now opens the server running on that port instead of a "404: Not Found" page. #34120, #34108
  • Smooth Browser tab resizing. Dragging the divider of the side panel no longer makes the Browser tab flicker and resize the page in slow motion. #33989, #33988
  • Terminal proxy headers. A "TERMINAL_PROXY_HEADERS" entry written in a different letter case now replaces the terminal's own header instead of being sent next to it, and repeated headers from the terminal such as several cookies are all passed on. #34092
  • Groups need a name. A new group can no longer be saved without a name from a tab other than General, because Save stays off until a name is typed and the server now rejects empty or blank group names. #34518
  • User list API groups. The admin endpoint that lists all users now includes each user's groups instead of an empty list. #34489, #26156
  • Model filter tags update. The tag filter of the model selector now also lists tags that models gain while a chat is open, instead of only the tags present when the page loaded. #33990, #33806
  • Mark folder chats read. Mark all as read in the menu on a folder page now marks the folder's chats as read instead of doing nothing. #34404, #34403
  • Folder page kept. Opening a chat in another browser tab no longer sends a folder's chat list back to page 1. #34145, #34142
  • Same-folder chat drops. Dropping a chat back on the folder it is already in no longer moves it there again and reloads every folder in the sidebar. #34461, #34460
  • Comment box on Android. Writing a comment on selected text on an Android phone no longer closes the comment box as soon as the keyboard opens.
  • Steadier menu placement. Menus that open above their button, such as Model controls and the + menu of the message input, now grow upward when their content changes instead of briefly covering the message input, and right-aligned menus in Firefox no longer creep sideways while they open. #34052, #34051, #34227, #34226
  • Long settings text boxes. Long prompt templates and JSON fields in Admin Settings now stop growing at a set height and scroll, instead of stretching the page to fit all of their text. #34569
  • Hover preview behind menus. A chat's hover preview in the sidebar no longer opens on top of another chat's open menu and covers its items. #34231, #34230
  • Hover preview without bubbles. With Chat Bubble UI turned off, your messages in a chat's hover preview now show as padded bubbles instead of text squeezed onto a grey block. #34347
  • Translated automation schedules. The Schedule button in the dialog that creates an automation now shows the schedule in the chosen language instead of always in English. #34428, #34426
  • Qdrant version warning. Connecting to a Qdrant 1.20 server, as the vector database or for external Qdrant knowledge bases, no longer logs a client version warning, which servers on Qdrant 1.18 or older now get instead. #34485, #34483
  • Image zoom reset. Resetting the zoom of an image preview from below 10% now returns it to 100% and centers it again. #34080, #34079
  • Steady Tools count. The count on the Tools tab of the workspace no longer drops to 0 for a moment when the Tools page opens. #34236
  • Unpin tooltip on notes. The Unpin button on a pinned note in the sidebar now shows a tooltip, as it does on pinned models. #34568, #34567

Changed

  • Terminals 0.4.0 required. Connections to a Terminals server no longer carry a policy in Admin Settings > Integrations, so the Policy ID, image, resource, storage, idle timeout and Terminal Contexts settings and the Refresh Terminals button are gone, the server has to run Terminals 0.4.0 or later, and models, folders, automations and chats that used the old connection need one of the new terminals selected. Upgrading Terminals from 0.3.x takes its manual migration, as there is no automatic one, new Terminals installations start without a template, Open WebUI now connects with the Terminals server key, and "TERMINALS_OPEN_WEBUI_URL" and "TERMINALS_TOKEN_CACHE_TTL" should be removed from the Terminals settings. Open Terminal and Tether terminal connections are not affected.
  • Direct connections move to Tether. Settings > Connections and Settings > Tools are gone together with the Direct Connections and Direct Integrations switches in Admin Settings, the Direct Tool Servers permission and the "ENABLE_DIRECT_CONNECTIONS", "ENABLE_DIRECT_INTEGRATIONS" and "USER_PERMISSIONS_FEATURES_DIRECT_TOOL_SERVERS" settings, so models, tool servers and terminals that users added in their own settings no longer appear. Users add them in the Tether app (0.1.14 or later, 0.1.16 for MCP servers) instead, where they stay on their own computer and work in every Open WebUI they connect.
  • Image settings become connections. On the first start of this version, the image generation and editing settings are turned into image connections that everyone who could use them before keeps using, and from then on the image environment variables such as "IMAGE_GENERATION_ENGINE", "IMAGES_OPENAI_API_BASE_URL" and "COMFYUI_BASE_URL" are no longer read unless "ENABLE_PERSISTENT_CONFIG" is turned off.
  • Locked Docker dependencies. The standard and slim Docker images now install every Python package except PyTorch from lock files pinned with hashes, so rebuilding the same version installs the same packages, and custom images that edit "backend/requirements.txt" must regenerate the locks with "backend/update-locks.sh" for the edit to take effect. #33981, #33979
  • New coding agent model IDs. Coding agent models now get IDs made only of letters, digits, dashes and underscores, which makes pinned Cursor and Pi models work, and pins, default models and automations that point at an agent model whose name had other characters, dots included as in most Codex models, need the model picked again. #34171, #34168
  • Coding agent sessions restart once. The first new message in a coding agent chat from an earlier version starts a new agent session that gets the chat so far as text, instead of resuming the agent's own session.
  • Image API model checks. Image generation and edit requests sent through the API now run on the model they name, which has to be one of the caller's image models or the request fails with an error, instead of image generation ignoring the named model.
  • Live update events renamed. Real-time updates for notes, comments, the inbox, access changes, encrypted channels and channel app errors now arrive as typed messages on the main "events" socket channel, so custom clients that listened for the old event names such as "events:note" or "note:presence" need to listen there instead.
  • Chat write access field. Chat responses from the API now carry the saved sharing mode in "share_mode" and report whether you can reply in a new "write_access" field, so custom clients that read "share_mode" for that need to switch.
  • Terminal uploads go to files. New terminal connections now start with Chat Uploads set to Filesystem and computers connected through Tether always use it, so files attached in a chat are saved into the selected terminal's working folder instead of being processed as regular chat uploads, while existing connections keep their setting. Open Terminal 0.17.20 or later is recommended, as it fixes uploads becoming unreadable in multi-user setups.
  • Chat menu items moved. Overview, Artifacts and Comments are no longer in the chat's menu and now open from the + menu of the tab bar, where Overview opens as a tab beside the chat instead of a full-screen window.
  • Note comments button. Comments on a note now open from a button in the note's top bar instead of from its menu, and in a note you can edit, commenting on selected text is now a Comment button in the formatting toolbar.
  • One heading menu. The formatting toolbar of the message input and of notes now offers Heading 1, 2 and 3 in a single heading menu instead of three separate buttons.
  • Attachments menu renamed. The Add Context entry in the + menu of the message input, which holds the options to attach web pages, files, notes, knowledge and chats, is now called Attachments. #34431
  • Capabilities now Features. The Capabilities section of the model editor is now called Features. #34433
  • Knowledge base labels. The knowledge picker in the chat, the knowledge selector of the model editor and attached knowledge bases now call them Knowledge or Knowledge Base instead of Collection, the vector database term, and the search box inside a knowledge base now says Search Files. #34432
