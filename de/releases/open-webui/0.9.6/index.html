Behoben

  • 🛡️ Sicherheitshinweis: Diese Version enthält Sicherheits- und Zugriffskontrollkorrekturen. Wir empfehlen, Produktionsbereitstellungen so bald wie möglich zu aktualisieren. Möglicherweise werden nicht alle Sicherheitsfixes in dieser Version im Abschnitt „Fixed“ aufgeführt – einige werden möglicherweise für kurze Zeit zurückgehalten, um Administratoren Zeit für das Upgrade zu geben. Hinweise
  • 🛡️ Erzwingung der Tool-Server-Berechtigung. Die benutzerspezifische Berechtigung für Inline-Tool-Server wird jetzt bei Chat-Abschlussanfragen erzwungen, sodass Benutzer ohne diese Berechtigung die Administratoreinstellung nicht mehr umgehen können, indem sie Tool-Server direkt in ihren Anfragen angeben. Commit
  • 🔒 Wissensdatenbank-Zugriffsprüfung im Suchtool. Das integrierte Wissenssuchtool überprüft jetzt, ob der Anrufer auf eine Wissensdatenbank zugreifen kann, bevor er diese anhand der ID durchsucht, und verhindert so, dass Benutzer den Inhalt von Wissensdatenbanken lesen, auf die ihnen kein Zugriff gewährt wurde. #25113
  • 🗄️ Benutzerübergreifender Zugriff auf Abrufsammlungen. Beim Auflösen der zum Abruf verwendeten Dokumente wird nun der Zugriff des Aufrufers auf jede referenzierte Datei überprüft und von client bereitgestellte Sammlungsnamen abgelehnt, wodurch verhindert wird, dass eine gestaltete Anfrage die Dateien oder Vektorsammlungen eines anderen Benutzers in ihren Kontext zieht. Commit
  • 🔣 Validierung von Sammlungsnamen. Vektorsammlungsnamen werden jetzt abgelehnt, es sei denn, sie enthalten nur sichere Zeichen, wodurch verhindert wird, dass fehlerhafte Namen den Vektorspeicher erreichen oder aus einem Datenbankabfrageausdruck ausbrechen. #24982
  • 🚫 Unscoped Retrieval Collections werden standardmäßig abgelehnt. Abrufanfragen für Sammlungsnamen, die keiner bekannten Datei, keinem bekannten Speicher, keiner Websuche oder Wissensdatenbank entsprechen, werden Nicht-Administratoren jetzt standardmäßig verweigert, mit einer neuen Einstellung „ENABLE_RETRIEVAL_UNSCOPED_COLLECTIONS“, um bei Bedarf das vorherige Verhalten wiederherzustellen. Festschreiben
  • 📜 Autorisierung des Eingabeaufforderungsverlaufs. Beim Vergleichen, Löschen und Wiederherstellen von Eingabeaufforderungsversionen wird jetzt überprüft, ob der Verlaufseintrag zu der Eingabeaufforderung gehört, für die Sie berechtigt sind, wodurch der Zugriff auf oder die Änderung des Versionsverlaufs einer anderen Eingabeaufforderung verhindert wird. #25056
  • 🚦 Code-Interpreter-Berechtigung für den Legacy-Pfad. Der Legacy-Code-Ausführungspfad erzwingt jetzt die gleichen Berechtigungs- und Fähigkeitsprüfungen wie der aktuelle, sodass Benutzer ohne Code-Interpreter-Berechtigung keine Codeausführung mehr über ihn auslösen können. #24724
  • 🧱 Umgehung der Endpunktbeschränkung des API-Schlüssels. Die Endpunkt-Zulassungsliste, die einschränkt, welche Pfade ein API-Schlüssel erreichen darf, wird jetzt direkt mit dem weitergeleiteten Anforderungspfad abgeglichen, wodurch verhindert wird, dass eine manipulierte Anforderung die Beschränkung überschreitet. #25123
  • 🚧 Umgehung der Systemeingabeaufforderung über Anforderungsparameter. Das Flag, das die konfigurierte Systemeingabeaufforderung eines Modells überspringt, kann nicht mehr von externen clients über einen Anforderungsparameter gesetzt werden, sodass vom Administrator konfigurierte Systemeingabeaufforderungen nicht vom API aus umgangen werden können. #25156
  • 🚪 Terminal-Proxy-Pfaddurchquerung. Der Terminal-Proxy dekodiert Anforderungspfade jetzt vollständig, bevor er sie validiert, und blockiert so mehrfach codierte Nutzdaten, die andernfalls dem vorgesehenen Pfad entkommen könnten. #25157
  • 🪤 Cache-Dateipfaddurchquerung. Der Cache-Dateiserver erfordert jetzt eine genaue Übereinstimmung der Verzeichnisgrenzen und schließt damit eine Lücke, in der ein Geschwisterverzeichnis, dessen Name mit dem Namen des Cache-Verzeichnisses begann, verwendet werden könnte, um Dateien von außerhalb bereitzustellen. #25086
  • 🔀 Zugriffsprüfung für die Ollama-Backend-Auswahl. Anfragen können nicht mehr per Index auf ein beliebiges Ollama-Backend abzielen; Ein vom Aufrufer bereitgestellter Backend-Selektor wird nun anhand der Backends überprüft, die tatsächlich das angeforderte Modell bedienen. Festschreiben
  • 🔓 Benutzerübergreifende Dateiexfiltration über Bild-URLs. Wenn eine Chat-Nachricht in einem „image_url“-Feld auf eine Datei anhand ihrer ID verweist, löst der Server diese Datei jetzt nur für ihren Eigentümer, einen Administrator oder einen Benutzer mit einer expliziten Leseberechtigung auf und verhindert so, dass andere authentifizierte Benutzer den Inhalt einer Datei extrahieren, indem sie sie durch das Modell weiterleiten. #24625, Commit
  • 📌 Zugriffsprüfungen für Chat-Dateianhänge. Durch das Anhängen von Dateien an einen Chat werden jetzt nur Dateien verknüpft, die der Anrufer lesen kann, wodurch verhindert wird, dass ein Benutzer die Datei eines anderen Benutzers mit seinem Chat verknüpft, um auf dessen Inhalte zuzugreifen. #25054
  • 🧾 Überprüfung des Besitzes von Modellwissensdateien. Beim Erstellen oder Aktualisieren eines Modells wird jetzt überprüft, ob alle daran angehängten Wissensdateien Dateien sind, auf die der Editor zugreifen kann, wodurch verhindert wird, dass die Dateien eines anderen Benutzers an ein Modell angehängt werden. #25055, Commit
  • 📅 Autorisierung zum Verschieben von Kalenderereignissen. Das Aktualisieren eines Kalenderereignisses, um es in einen anderen Kalender zu verschieben, erfordert jetzt Schreibzugriff auf den Zielkalender, wodurch verhindert wird, dass Benutzer Ereignisse in Kalender einfügen, in die sie nicht schreiben können. #24764
  • 📣 Kanal-Chat-Zugriffskontrolle. Das Generieren einer Antwort in einem Kanalkontext überprüft jetzt den Zugriff des Anrufers auf diesen Kanal und begrenzt die enthaltenen Nachrichten, wodurch der Zugriff auf Kanäle oder Nachrichten verhindert wird, die der Benutzer nicht sehen darf. #24725
  • 🕸️ Webloader-SSRF-Gating mit Playwright. Wenn der Playwright-basierte Webloader verwendet wird, werden Seitennavigation und Weiterleitungen jetzt auf die gleiche Weise wie beim Standardlader validiert, wodurch eine Lücke geschlossen wird, durch die der Playwright-Pfad interne oder anderweitig blockierte URLs erreichen könnte. #24756
  • 🛂 DNS-Rebinding-Schutz für URL-Abrufe. Die für einen ausgehenden URL-Abruf validierte IP-Adresse ist jetzt dieselbe, die für die tatsächliche Verbindung verwendet wird. Dadurch wird ein DNS-Rebinding-Fenster geschlossen, in dem ein vom Angreifer kontrollierter Hostname während der Sicherheitsüberprüfung in eine öffentliche IP und dann beim Öffnen der Verbindung in eine private IP aufgelöst werden könnte. #24759
  • 🪞 OAuth-Profilbild-Umleitungsbehandlung. Der OAuth-Profilbildabruf folgt Umleitungen jetzt nur dann, wenn Administratoren dies ausdrücklich zugelassen haben, wodurch ein Fenster geschlossen wird, in dem eine Umleitung von einer extern validierten URL zum Erreichen interner Adressen verwendet werden könnte. #24809
  • 🧼 Modellprofilbild-Skriptinjektion. Modellprofilbilder werden jetzt beim Speichern validiert und nur dann inline bereitgestellt, wenn es sich um einen bekanntermaßen sicheren Bildtyp handelt. Dadurch wird verhindert, dass ein manipuliertes SVG-Profilbild Skripte in den Browsern anderer Benutzer ausführt, während vorhandene Legacy-Bilder, die die Validierung nicht bestehen, ordnungsgemäß gelöscht werden, anstatt die Modellliste zu zerstören. #25060, #25173
  • 🧯 Diagramm-Rendering-Skript-Injektion. Im Chat gerenderte Meerjungfrauen-Diagramme werden jetzt vor der Anzeige bereinigt, wodurch verhindert wird, dass ein gestaltetes Diagramm Skripte im Browser des Betrachters ausführt. #25219
  • 🔐 Schreibschutz für Dateien im geteilten Chat. Der Zugriff auf eine Datei über einen geteilten Chat gewährt jetzt nur Lesezugriff, sodass Benutzer, die einen geteilten Chat lesen können, daran angehängte Dateien nicht mehr ändern oder löschen können. #24755
  • 🔏 Cross-Origin-Einbettungs-Eingabeaufforderungssteuerung. Wenn Open WebUI in einen Iframe auf einem anderen Ursprung eingebettet ist, kann die Einbettungsseite jetzt nur dann die Chat-Eingabe steuern oder Eingabeaufforderungen senden, wenn der Benutzer sich ausdrücklich über die Einstellung „iframe Sandbox Allow Same Origin“ dafür entschieden hat, wodurch verhindert wird, dass untrusted-Hostseiten Bestätigungsdialoge auslösen oder den Chat steuern. #24767, Commit
  • 🗂️ Überprüfung der Inhaberschaft von Chat-Ordnern. Beim Erstellen eines Chats oder beim Aktualisieren eines Chat-Ordners wird jetzt überprüft, ob der referenzierte Ordner dem aktuellen Benutzer gehört, wodurch verhindert wird, dass Chats mit Ordnern verknüpft werden, die anderen Personen gehören. #24588
  • 🧩 Chat-Wiederherstellung nach beschädigtem Verlauf. Chats, deren internes Nachrichtendiagramm aufgrund einer fehlgeschlagenen Neugenerierung in einem fehlerhaften Zustand zurückblieb, werden jetzt korrekt geöffnet und geladen, wobei fehlende Rollen, übergeordnete Referenzen und aktuelle Nachrichtenzeiger automatisch wiederhergestellt werden, anstatt den Chat zu unterbrechen. #24424, #24157, #20474, #24799, Commit
  • 📨 Importierte Chats mit Ordnern werden korrekt angezeigt. Beim Importieren gruppierter Chats bleiben diese nicht mehr unsichtbar, wenn ein referenzierter Ordner fehlt; Solche Chats erscheinen jetzt in der Chat-Liste, anstatt stillschweigend verwaist zu sein. #24910, Commit
  • 🎟️ MCP-Tool-Serversitzungen bleiben verbunden. OAuth-authentifizierte MCP-Tool-Serversitzungen werden nicht mehr versehentlich vom Single-Sign-On-Sitzungshandler aktualisiert und gelöscht, sodass diese Verbindungen aktiv bleiben. #24618, Commit
  • 🤝 MCP-OAuth-Bereichserkennung. Der OAuth-Fluss für MCP-Tool-Server liest jetzt die Bereiche, die ein Server über seine geschützten Ressourcenmetadaten ankündigt, sodass die Verbindung zu Servern erfolgreich ist, die ihre eigenen Bereiche deklarieren. #24730, #24690
  • 🔍 Zuverlässigkeit der Websuche. Die Websuche ruft Seiteninhalte wieder zuverlässig mit der Standard-Webloader-Engine ab, eine neue Umgebungsvariable „USER_AGENT“ ermöglicht es Administratoren, einen echten Browser-Benutzeragenten festzulegen, sodass Abrufe nicht von Cloudflare, Wikipedia und anderen Bot-Erkennungssystemen blockiert werden, und das Startskript startet nicht mehr, wenn diese neuen Umgebungsvariablen deaktiviert sind. #24560, #24793, #24683, Commit
  • 🔥 Firecrawl-Websuchergebnisse. Die Websuche mit Firecrawl gibt jetzt korrekte Ergebnisse zurück, unabhängig davon, welches Antwortformat die Firecrawl-Version verwendet. #24712
  • 🦅 Kagi-Websuche. Die Websuche mit Kagi funktioniert wieder, nachdem der Endpunkt API und die Anforderungsmethode aktualisiert wurden, um mit Kagis aktuellem API übereinzustimmen. #25015
  • 🔢 Zahlen in Klammern in Codeblöcken. Zahlen in eckigen Klammern wie „[0]“ innerhalb von Codeblöcken werden nicht mehr entfernt, als wären sie Quellenangaben, sodass Code korrekt angezeigt und kopiert wird. #24948, Commit

Das Generieren und Bearbeiten von Bildern über ein ComfyUI-Backend funktioniert jetzt wieder, auch wenn ComfyUI in einem privaten oder internen Netzwerk gehostet wird, in dem die URL-Validierung zuvor den vom Administrator konfigurierten Endpunkt blockierte. #24565, Commit, Commit

  • 🐘 Wissenssuche in großen Dokumenten. Die Suche in Wissensdatenbanken auf PostgreSQL schlägt nicht mehr fehl, wenn Dokumente mit sehr großem extrahierten Textinhalt gescannt werden. #24670, Commit

Automatisch generierte Chattitel verwenden jetzt das Modell, das aktuell in der Dropdown-Liste für den aktiven Chat ausgewählt ist, und greifen andernfalls auf das Modell aus dem aktiven Nachrichtenzweig zurück.   • 🧮 Konsistenz bei Nachrichtensuche und Analyse. In einem Chat vorgenommene Bearbeitungen, Löschungen und Zweigänderungen werden jetzt in den Nachrichtensuchergebnissen und Analysezählungen widergespiegelt, anstatt veraltete Einträge zu hinterlassen. #25205, Commit
  • 🩹 Anmutiger Umgang mit Aufgabenfehlern im Chat. Changed

  • ⚠️ Database Migrations: This release includes database schema changes; we strongly recommend backing up your database and all associated data before upgrading in production environments. If you are running a multi-worker, multi-server, or load-balanced deployment, all instances must be updated simultaneously, rolling updates are not supported and will cause application failures due to schema incompatibility.
  • ⚙️ Tool-call iteration cap renamed and raised. The environment variable that limits how many tool calls a single chat response may make is now "CHAT_RESPONSE_MAX_TOOL_CALL_ITERATIONS", with its default raised from 30 to 256 and a new "-1" value for unlimited; the previous "CHAT_RESPONSE_MAX_TOOL_CALL_RETRIES" name continues to work as a fallback, and chats that hit the cap now show a clear error in-chat instead of stopping silently. #24918, Commit
  • 🔐 Reduced public "/api/config" exposure. The "/api/config" response no longer includes several feature flags ("enable_api_keys", "enable_password_change_form", "enable_version_update_check", "enable_public_active_users_count", "enable_easter_eggs") for unauthenticated callers, reducing information disclosure to anonymous visitors. Commit, Commit
  • 🔑 "WEBUI_SECRET_KEY" is now a hard requirement even for unsupported deployments. Deployments that start the backend in an explicitly unsupported way (such as invoking uvicorn directly) without setting "WEBUI_SECRET_KEY" will now refuse to start instead of falling back to an empty key; the supported start methods (start.sh, start_windows.bat, and "open-webui serve") still set or auto-generate it automatically, so standard deployments are unaffected.
