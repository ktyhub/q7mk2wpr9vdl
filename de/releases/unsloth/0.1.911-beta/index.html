unsloth v0.1.911-beta

Diese Version fügt geplante Aufgaben, FLUX-3-Bearbeitungsunterstützung, Leistungsverbesserungen und mehr hinzu. Ebenfalls neu: MiniMax-M3.1-Flash, Gesichtsretuschierungen für Bilder und schnellere Leistung + Chats auf dem Mac.

Highlights

  • Geplante Aufgaben: Führen Sie eine Eingabeaufforderung nach einem Zeitplan mit einem lokalen Modell oder einem API aus
  • MiniMax-M3.1-Flash: 428B MoE von MiniMax (23B aktiv) Anleitung
  • FLUX 3-Bearbeitung: FLUX 3 unterstützt jetzt die Bearbeitung von Bildern mit Eingabeaufforderungen
  • Leistungsverbesserungen: Große Mac-Leistungssteigerungen, weniger Verzögerung, reduzierte Binärgrößen
  • Gespeicherte Voreinstellungen: Speichern Sie Ihre Laufeinstellungen als benannte Voreinstellungen für jedes Modell

Geplante Aufgaben

  • Öffnen Sie „Geplant“ über das Menü „Mehr“ in der Seitenleiste, um einmal, täglich, an Wochentagen, wöchentlich oder monatlich eine Eingabeaufforderung auszuführen. Jede Antwort wird als neuer Chat gespeichert.
  • Jede Aufgabe kann auf dem geladenen Modell, einem Modell auf Ihrem Gerät oder einem Modell eines verbundenen API-Anbieters ausgeführt werden.
  • Wenn das Modell einer Aufgabe nicht geladen ist, fragt Unsloth vor dem Laden nach, es sei denn, Sie aktivieren Automatisch wechseln, wenn ich weg bin.
  • Jede Aufgabe kann Sie nach jeder Ausführung benachrichtigen, nur wenn sie fehlschlägt oder nie.
  • Aufgaben werden nur ausgeführt, während Unsloth ausgeführt wird, ohne Tools oder Websuche.

UI + UX

  • Speichern Sie die Laufeinstellungen in der Modellauswahl als benannte Voreinstellungen für jedes Modell und benennen Sie sie dann um, löschen Sie sie oder wechseln Sie zwischen ihnen. – Die zuletzt ausgewählte Voreinstellung ist die Voreinstellung, mit der das Modell beim nächsten Mal geladen wird, einschließlich des Ladens über den API.
  • Chat-Einstellungen können Ihre Sampling-Einstellungen für ein Modell speichern oder sie auf die empfohlenen Werte des Modells zurücksetzen.
  • GGUF-Chats zeigen jetzt den Fortschritt und die verbleibende Zeit beim Verarbeiten einer langen Eingabeaufforderung an, bevor die Antwort beginnt. – Auf der Seite API werden jetzt die Kontextnutzung, die Geschwindigkeit und die Anzahl der Anfragen für jedes bediente Modell angezeigt.
  • Jede Art von Schaltfläche und Symbol sieht jetzt überall in der App gleich aus. – Auf den Seiten „Bibliothek“ und „System“ in den Einstellungen wird der Speicher als Nutzungsleiste angezeigt, aufgeteilt in Modelle, Caches und freien Speicherplatz.

##Mac

  • MLX-Chats antworten jetzt mit Entwurfsmodellen bis zu 16 % schneller. – MLX-Modelle, die mit einem integrierten Entwurfsmodell ausgeliefert werden, verwenden dieses jetzt automatisch, ohne dass ein separater Download erforderlich ist.
  • Das Rendern von Bildern und Videos benötigt am Ende weitaus weniger Speicher, sodass Macs mit wenig Speicher selten langsamer werden, wenn sie ausgetauscht werden. – Auf Apple Silicon erstellen Z-Image GGUFs jetzt standardmäßig Bilder aus Text mit der MLX-Engine, 1.5-2x schneller als zuvor.

Bilder + Video

  • Erstellen Sie mit NVIDIAs Cosmos3-Edge auf der Videoseite Videos aus Text oder einem Bild.
  • Aktivieren Sie auf der Seite „Bilder“ den Detailer, um Gesichter, Hände oder andere Dinge, die Sie benennen, in höherer Auflösung neu zu zeichnen. Es benötigt SAM 3 und ein Modell, das Inpaint kann. – Auf NVIDIA-GPUs, die älter als die RTX-30-Serie sind, wird Wan2.1 1.3B Text-to-Video clips etwa fünfmal schneller gerendert. – Auf NVIDIA-GPUs werden viele Bild- und Videomodelle nach dem ersten Mal schneller geladen, da Unsloth die Version speichert, die es beim ersten Laden erstellt.
  • FLUX.3 Klein kann jetzt Fotos unter „Bilder“ > „Bearbeiten“ bearbeiten und dabei die Abmessungen des Fotos beibehalten.

Ausbildung

– Teilen Sie jede Schicht eines Modells auf GPUs für LoRA- und QLoRA-Training auf, sodass jede GPU weniger enthält: Setzen Sie UNSLOTH_TP_SIZE auf die Anzahl der GPUs und starten Sie mit torchrun.

  • Die Feinabstimmung der 4-Bit-GPT-OSS-Kontrollpunkte von Unsloth stürzt nicht mehr beim ersten Trainingsschritt ab.
  • GRPO, das mit vLLM generiert wird, läuft mit 16-Bit-LoRA unter Linux mit NVIDIA-GPUs bis zu 1,9-mal schneller pro Schritt.
  • GRPO, das ohne vLLM generiert, läuft für Llama und Qwen3 auf NVIDIA-GPUs bis zu 4,4-mal schneller pro Schritt.

Kodiermittel + API

– Apps, die einen Unsloth API-Schlüssel verwenden, können ihre eigenen Python- oder Terminalaufrufe nicht mehr zur Ausführung außerhalb der Sandbox genehmigen.

  • Unsloth leitet standardmäßig keine client-IPs mehr weiter; Legen Sie hinter Ihrem eigenen Reverse-Proxy UNSLOTH_STUDIO_TRUST_FORWARDED=1 fest, oder alle Benutzer teilen sich ein Login-Ratenlimit.

Modelle + Hardware

  • Führen Sie MiniMax-M3.1-Flash aus, das MoE-Modell von MiniMax für Codierung, Tool-Nutzung und Agenten-Workflows, mit bis zu 1 Million Kontext-Tokens. GGUF
  • Bei 1-Bit benötigt MiniMax-M3.1-Flash mindestens 130 GB RAM und VRAM zusammen. – Auf einigen Windows-PCs werden GGUF-Modelle erneut geladen, anstatt jedes Mal mit „Lama-Server konnte nicht gestartet werden“ abzubrechen.

unsloth v0.1.911-beta

This release adds scheduled tasks, FLUX-3 edit support, perf improvements and more. Also new: MiniMax-M3.1-Flash, face touch-ups for images and faster performance + chats on Mac.

Highlights

  • Scheduled tasks: Run a prompt on a schedule with a local model or an API
  • MiniMax-M3.1-Flash: MiniMax's 428B MoE (23B active) Guide
  • FLUX 3 Editing: FLUX 3 now supports editing of images with prompts
  • Perf improvements: Large Mac perf gains, less lag, reduced binary sizes
  • Saved presets: Save your Run settings as named presets for each model

Scheduled tasks

  • Open Scheduled from the sidebar's More menu to run a prompt once, daily, on weekdays, weekly or monthly; each answer is saved as a new chat.
  • Each task can run on the loaded model, a model on your device, or a model from a connected API provider.
  • When a task's model isn't loaded, Unsloth asks before loading it, unless you turn on Switch automatically when I'm away.
  • Each task can notify you after every run, only when it fails, or never.
  • Tasks run only while Unsloth is running, without tools or web search.

UI + UX

  • Save Run settings in the model picker as named presets for each model, then rename, delete or switch between them.
  • The preset you picked last is what that model loads with next time, including loads through the API.
  • Chat settings can remember your sampling settings for a model, or reset them to the model's recommended values.
  • GGUF chats now show progress and time left while processing a long prompt, before the reply starts.
  • The API page now shows each served model's context use, speed and request count.
  • Each kind of button and icon now looks the same everywhere in the app.
  • The Library and System pages in Settings show storage as a usage bar, split into models, caches and free space.

Mac

  • MLX chats now reply up to 16% faster with draft models.
  • MLX models that ship with a built-in draft model now use it automatically, with no separate download.
  • Image and video renders need far less memory at the end, so low-memory Macs rarely slow down from swapping.
  • On Apple Silicon, Z-Image GGUFs now make images from text with the MLX engine by default, 1.5-2x faster than before.

Images + video

  • Make videos from text or an image with NVIDIA's Cosmos3-Edge on the Video page.
  • On the Images page, turn on Detailer to redraw faces, hands or other things you name at higher resolution; it needs SAM 3 and a model that can inpaint.
  • On NVIDIA GPUs older than RTX 30-series, Wan2.1 1.3B text-to-video clips render about 5x faster.
  • On NVIDIA GPUs, many image and video models load faster after the first time, since Unsloth saves the version it builds on first load.
  • FLUX.3 Klein can now edit photos in Images > Edit, keeping the photo's dimensions.

Training

  • Split each layer of a model across GPUs for LoRA and QLoRA training, so each GPU holds less: set UNSLOTH_TP_SIZE to the number of GPUs and launch with torchrun.
  • Fine-tuning Unsloth's 4-bit gpt-oss checkpoints no longer crashes on the first training step.
  • GRPO that generates with vLLM runs up to 1.9x faster per step with 16-bit LoRA on Linux with NVIDIA GPUs.
  • GRPO that generates without vLLM runs up to 4.4x faster per step for Llama and Qwen3 on NVIDIA GPUs.

Coding agents + API

  • Apps using an Unsloth API key can no longer approve their own Python or terminal calls to run outside the sandbox.
  • Unsloth no longer trusts forwarded client IPs by default; behind your own reverse proxy, set UNSLOTH_STUDIO_TRUST_FORWARDED=1 or all users share one login rate limit.

Models + hardware

  • Run MiniMax-M3.1-Flash, MiniMax's MoE model for coding, tool use and agent workflows, with up to 1M tokens of context. GGUF
  • At 1-bit, MiniMax-M3.1-Flash needs at least 130 GB of RAM and VRAM combined.
  • On some Windows PCs, GGUF models load again instead of failing every time with "llama-server failed to start".
