QwenPaw v2.0.1

Was hat sich geändert?

✨ Hinzugefügt

PawApp-Plattform

  • PawApp SDK & Kanban App: Eine neue Mini-App-Plattform, die es Plugins ermöglicht, umfangreiche interaktive Benutzeroberflächen auf QwenPaw aufzubauen. Wird mit einer integrierten Kanban-Taskboard-App für das Projektmanagement geliefert (#6150) Benutzerdefinierte Agent-Modi
  • Vom Benutzer editierbarer Agent-Modus: Erstellen und bearbeiten Sie benutzerdefinierte Agent-Loop-Modi direkt über die Konsole – definieren Sie Iterationsgrenzen, Stoppbedingungen und Genehmigungs-Gates, ohne den Code zu berühren (#6270)
  • Oh-My-Paw-Plugin: Fünf gebrauchsfertige Agentenschleifen (UltraQA, Ralph, Ultrawork, Autopilot, Team) für die Zusammenarbeit mehrerer Agenten und lang laufende Aufgaben (#5882) Speicher und Beobachtbarkeit
  • ReMe Light-Indexwartung: Explizite Indexneuerstellung über die Konsolenschaltfläche oder API, verbesserte Selbstreparatur beim Start und optimiertes Markdown-Chunking für große Dokumente (#6235)
  • Verbesserungen der ReMe-Zuverlässigkeit: Überprüfung der Laufzeitspeicherstatistiken, CJK-Einbettungssicherheit und ordnungsgemäßes Herunterfahren der Hintergrundzusammenfassung (#6098)
  • ReMe-Indizierungsschutz: Verbesserte Konfigurationsvalidierung und Indizierungsstabilität (#6153)
  • Langfuse-Trace-Anreicherung: Traces enthalten jetzt Benutzer-ID, Sitzungs-ID und Paketversion für eine bessere Filterung und Analyse (#5922)
  • Verlaufsaufbewahrungskonfiguration: Scroll-Kontextaufbewahrungstage jetzt über die Konsole konfigurierbar (#6214) Konsole und Desktop
  • Chat-Archivierung: Alte Konversationen archivieren, um die Sitzungsliste sauber zu halten (#6078)
  • Datei-Upload per Drag-and-Drop: Dateien direkt im Chat-Eingabebereich in der Desktop-App ablegen (#6327)
  • Plugin-Marktsortierung: Plugins nach Downloads, Aktualisierungszeit oder Favoriten sortieren (#6349)
  • One-click-Agentenkonfigurationskopie: Duplizieren Sie eine Agentenkonfiguration mit einem einzelnen click (#6262)
  • Konfigurierbare Protokollrotation: Legen Sie die Rotationsgrenzen für Protokolldateien in der Konfiguration fest (#6183) Sicherheit und Governance
  • Sandbox mit eingeschränktem Windows-Token: Codeausführung isoliert über eingeschränkte Windows-Token für eine zusätzliche Sandbox-Option (#5931)
  • Governance-Regeln: Neue Governance-Regeldefinitionen für eine detailliertere Zugriffskontrolle (#6215)
  • Erkennung vertraulicher Dateien: Weitere Dateitypen wurden als vertraulich erkannt; Globale Dateilesevorgänge sind jetzt standardmäßig für nicht sensible Pfade zulässig (#6067) Laufzeit und Multi-Agent
  • Multi-Agent-Startsteuerung: Begrenzte Start-Parallelität mit teilweiser Bereitschaftsanzeige in der Konsole (#6198)
  • Stille Cron-Zustellung: Geplante Aufgaben können Ergebnisse stillschweigend und ohne Benachrichtigungen liefern (#6080)
  • Bewahrung von Ereignismetadaten: Plugin- und Erweiterungsmetadaten werden jetzt über Echtzeit-Ausgabeumschläge übertragen (#6224) – Bereitschaftstest: Neuer /api/healthz-Endpunkt für Integritätsprüfung und Container-Orchestrierung (#6028)
  • Trusted-Proxy-Authentifizierung: trusted-Proxys überprüfen und echte client-IPs für Bereitstellungen hinter Load Balancern auflösen (#6030) CLI
  • gh CLI in der Governance zulässig: GitHub CLI-Befehle sind jetzt durch die Governance-Richtlinie zulässig (#6031)

🔄 Geändert

– Die Standard-ReAct-Schleife wird jetzt als erstklassiges DefaultMode modelliert, wodurch jeder Modus explizit Eigentümer seines Lebenszyklus und seiner Gates wird (#6210) – ACP-Slash-Befehle vom Kern entkoppelt, Sicherheitsprüfungen in ein eigenständiges Modul extrahiert und Bootstrap-Flow vereinheitlicht (#5796)

  • Kanal-Tool-Aufruf und Tool-Ergebnisanzeige verfügen jetzt über separate Umschaltsteuerungen (#6233) – ToolGuard-Erkennungsregeln werden jetzt zur einheitlichen Auswertung in die Governance-Richtlinien-Engine integriert (#6390) – Die automatische Synchronisierung von DEFAULT_USER_RULES erfordert keine manuelle Whitelist mehr (#6025)
  • Die Werkzeuggenehmigungsschaltfläche verwendet jetzt toolSource anstelle von executionLevel für die Steuerung „Immer zulassen“ (#6095) – Optimierte Agenten-Argumentation, um redundante Denkschleifen und doppelte Tool-Aufrufe zu reduzieren (v2.0.0.post4)

QwenPaw v2.0.1

Highlights

  • PawApp mini-app platform — Plugins can now build rich interactive UIs instead of relying solely on text-based tool output. The bundled Kanban app provides a concrete reference for project-management workflows and SDK adoption (#6150).
  • Configurable agent loops — The ReAct loop is now a first-class DefaultMode with explicit lifecycle and approval gates. Console-editable modes and the Oh-My-Paw presets make custom iteration limits, stop conditions, and multi-agent workflows accessible without code changes; integrations hooking the built-in loop should align with the new mode lifecycle (#6210, #6270, #5882).
  • Unified governance, wider default file access — ToolGuard rules now feed the governance policy engine, while global reads are allowed by default for paths classified as non-sensitive. This centralizes enforcement but widens effective filesystem access: review sensitive-file classifications and existing allowlists, and note that persistent “Always Allow” decisions now use toolSource rather than executionLevel (#6390, #6067, #6095).
  • MCP credential migration and policy timing — ${VAR} header credentials are migrated to environment references through a schema-watermarked, one-shot process. Validate required environment variables after upgrading; policy changes now apply immediately, and MCP connection timeouts no longer block workspace startup, so successful startup does not guarantee every server is connected (#6091, #6133, #5949, #6174).
  • More controllable automatic memory — Automatic memory capture is restricted to external user queries, excluding internal or tool-generated context. Teams relying on the previous behavior should review stored memory and rebuild indexes; automatic memory can be disabled entirely with auto_memory_interval=0, while console/API-triggered rebuilds and startup self-repair improve recovery (#6120, #6135, #6235).
  • Production health checks and trace attribution — The new /api/healthz endpoint supports container orchestration, and trusted-proxy handling resolves real client IPs behind load balancers—configure proxy trust carefully to prevent IP spoofing. Langfuse traces now include user, session, and package-version dimensions with valid hexadecimal IDs, improving filtering and deployment-level analysis (#6028, #6030, #5922, #6277).

No breaking changes are listed in this release.
