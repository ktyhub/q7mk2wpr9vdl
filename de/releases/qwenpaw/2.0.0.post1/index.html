QwenPaw v2.0.0.post1

Highlights

  • Trusted-proxy authentication requires configuration — X-Forwarded-For and X-Real-IP are trusted only when the direct peer matches security.trusted_proxies; XFF is parsed right-to-left and loopback auth bypass is hardened (#6030). If you run behind a reverse proxy, configure its IP or CIDR during the upgrade, or client-IP rules, rate limits, and audit logs will see the proxy; catch-all ranges such as 0.0.0.0/0 are rejected.
  • Approval and sandbox defaults change — Unmatched non-shell tool calls with zero deep-scan findings now ALLOW in SMART/AUTO/OFF instead of prompting, while STRICT still asks; sandboxing is off by default, and shell fallback runs unsandboxed when isolation is disabled or unavailable (#6054). Set security.sandbox_enabled to true if isolation is required; secret-file and dangerous-command protections remain, and STRICT approval cards no longer expose “Always Allow” (#6019).
  • Background offload is temporarily disabled — The old offload transition signaled cancellation, which killed the subprocess instead of backgrounding it; tools now remain running until their normal completion or timeout, so long calls can hold the turn and clients should not rely on an offloaded state (#6058). Hint messages are also flattened to avoid orphan tool-result blocks.
  • Session and tool-result continuity is repaired — Legacy file-content sessions load again (#6010), new-chat message queues migrate from temporary IDs and are cleared on session deletion (#6040, #6045), and duplicate-ID filtering plus orphan-result defenses reduce malformed multi-turn histories (#6032, #5989, #5935).
  • Reasoning models and plugin tools need fewer workarounds — GPT-5/O-series requests now use max_completion_tokens, automatically mapping existing max_tokens settings while preserving explicit newer values; other model families retain max_tokens (#6015). api.register_tool() now bridges tools into the runtime ToolRegistry pipeline, fixing tools that appeared in configuration but were invisible to agents (#6044).
  • Production deployment is easier to automate — GET /api/healthz returns 503 until async agent startup succeeds and 200 with loaded-agent details afterward, making it suitable for Kubernetes readiness probes and load balancers (#6028). AgentScope resources are bundled (#6026), ReMe session IDs are Windows-safe (#6022), and the quickstart adds AgentScope Platform deployment (#6033).
