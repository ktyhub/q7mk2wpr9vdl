open_clip v4.2.1

Die erste 4.x-Version auf PyPI, die offizielle vorab trainierte NaFlex CLAP-Audiotextmodelle hinzufügt. Es verschiebt auch das Training nach einen neuen Stapel und fügt mehrere Modellfamilien hinzu. Frühere 4.x-Versionsnummern waren nur Entwicklungsversionen. Die vorab trainierte Bild-Text-Inferenz soll kompatibel bleiben, Trainingsskripte und nachgelagerte Integrationen müssen jedoch überprüft werden. Siehe den Migrationsleitfaden. Um auf 3.x zu bleiben, führen Sie „pip install“ aus 'open_clip_torch<4''.

Highlights

  • NaFlex CLAP: fünf Apache 2.0 Audio-Text-Modelle (27M bis 340M Parameter), die Audio variabler Länge verwenden, trainiert auf LAION-Audio-XL: XXS, XS, S, M, L
  • NaFlex CLIP: Bildtürme mit variabler Auflösung und variablem Seitenverhältnis mit Token-Budget-Batching
  • NaFlex GenLIP / GenLAP: generative Bild- und Audiountertitelung mit Präfix-LM-Aufmerksamkeit (Trainingskonfigurationen, noch keine vortrainierten Gewichte)
  • Moderne Texttürme: RoPE-, SwiGLU/ReLU²- und RMSNorm-Optionen, Batch-Text mit variabler Länge und Hugging Face ModernBERT-Türme
  • MaMMUT und CoCa v2: MaMMUT mit den veröffentlichten LAION-Gewichten sowie korrigierten coca2_*-Konfigurationen
  • Trainingsstapel: TrainingTask-Wrapper, dict-basierte Batches, FSDP2 (--fsdp), torch.compile-Strategien und Längen-Bucketing
  • Sichereres Laden von Checkpoints: Alle Checkpoint-Ladevorgänge verwenden weights_only=True und OpenAI-Gewichte werden jetzt vom Hugging Face Hub geladen anstelle von JIT-Archiven

Upgrade-Hinweise

  • PyPI erfordert jetzt torch>=2.6 (vorher >=2.0)
  • Der Standard---precision ist jetzt amp_bf16 (vorher amp), und --loss-dist-impl von SigLIP ist jetzt standardmäßig gather – --horovod, --torchscript und --trace werden entfernt – load_openai_model, list_openai_models, build_model_from_openai_state_dict und trace_model wurden entfernt; verwenden create_model_from_pretrained(..., pretrained='openai') für OpenAI-Gewichte – Datenlader geben jetzt Diktat-Batches aus und Trainingscode sollte ein TrainingTask anstelle eines separaten Modells und Verlusts übergeben – python -m open_clip_train.legacy_main bleibt als Kompatibilitätspfad für ältere Bild-Text-Trainingsskripte verfügbar Die vollständige Liste der Änderungen finden Sie im Migrationsleitfaden.

Englisches Original / English original

open_clip v4.2.1

The first 4.x release on PyPI, and it adds official pretrained NaFlex CLAP audio-text models. It also moves training to a new stack and adds several model families. Earlier 4.x version numbers were development versions only.

Pretrained image-text inference is intended to remain compatible, but training scripts and downstream integrations need review. See the migration guide. To stay on 3.x, run pip install 'open_clip_torch<4'.

Highlights

  • NaFlex CLAP: five Apache 2.0 audio-text models (27M to 340M parameters) that take variable-length audio, trained on LAION-Audio-XL: XXS, XS, S, M, L
  • NaFlex CLIP: variable-resolution and variable-aspect image towers with token-budget batching
  • NaFlex GenLIP / GenLAP: generative image and audio captioning with prefix-LM attention (training configs, no pretrained weights yet)
  • Modern text towers: RoPE, SwiGLU/ReLU², and RMSNorm options, per-batch variable-length text, and Hugging Face ModernBERT towers
  • MaMMUT and CoCa v2: MaMMUT with the released LAION weights, plus corrected coca2_* configs
  • Training stack: TrainingTask wrappers, dict-based batches, FSDP2 (--fsdp), torch.compile strategies, and length bucketing
  • Safer checkpoint loading: all checkpoint loads use weights_only=True, and OpenAI weights now load from the Hugging Face Hub instead of JIT archives

Upgrade notes

  • PyPI now requires torch>=2.6 (was >=2.0)
  • The default --precision is now amp_bf16 (was amp), and SigLIP's --loss-dist-impl now defaults to gather
  • --horovod, --torchscript, and --trace are removed
  • load_openai_model, list_openai_models, build_model_from_openai_state_dict, and trace_model are removed; use create_model_from_pretrained(..., pretrained='openai') for OpenAI weights
  • Dataloaders now emit dict batches, and training code should pass a TrainingTask instead of a separate model and loss
  • python -m open_clip_train.legacy_main remains available as a compatibility path for older image-text training scripts

See the migration guide for the full list of changes.
