OpenSandbox v1.1.0

Minor Veröffentlicht26. Aug. 2026 Quelleopensandbox-group/OpenSandbox Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

OpenSandbox docker/execd/v1.1.0

Was ist neu?

✨ Funktionen

  • execd als Sandbox-Init (OSEP-0018). execd kann jetzt als PID 1 ausgeführt werden: einzelner Reaper mit einer managedProcess-Abstraktion auf jedem Startpfad, Signalweiterleitung (TERM/HUP/USR1/USR2/WINCH), einstiegseigener Exit-Code-Weitergabe und einem Subreaper-Fallback für den Pool-Pfad. Opt-in über EXECD_INIT=1 (eingefügt durch runtime.execd_run_as_init des Servers für Docker/K8s Batch/Agent/Pool); Die klassische Topologie bleibt unverändert und die Standardeinstellung ist deaktiviert. (#1474)
  • Pre-exec-Härtungsboden. Der neue native opensandbox-launcher-Helfer wendet Env-Strip an → KEEPCAPS → Bounding-Set-Trim → no_new_privs → Identity Drop → Seccomp → Execve; [landlock] fügt eine Dateisystem-Zulassungsliste hinzu (Fail-Open unter ABI/Kernel 5.13, gemeldet als unsupported). GET /v1/isolated/capabilities erhält ein hardening-Objekt mit Status pro Ebene; Jede Schicht wird durch Fail-Open beeinträchtigt. (#1474) – eBPF-Beobachtungsvariante. execd-ebpf (CGO + cilium/ebpf) verbindet exec/connect/privilege mit CO-RE, ist auf die Sandbox-Cgroup beschränkt und gibt ein rotierendes JSONL-Audit aus; benötigt Kernel ≥5.10 mit BTF. Das Standardbild bleibt unverändert. (#1474 #1562)
  • preStart- und periodic-Lebenszyklus-Hooks (OSEP-0020). CreateSandboxRequest.lifecycle wird über die interne OPEN_SANDBOX_LIFECYCLE-Umgebung (Kubernetes; der Docker-Anbieter lehnt Lebenszyklusanforderungen ab) zur Sandbox transportiert. execd startet HTTP vor preStart, führt nicht überlappende periodic-Hooks über den Reaper-fähigen verwalteten Prozesspfad aus und gibt den Benutzerprozess erst frei, nachdem preStart erfolgreich war. Die Konfiguration bleibt bei $HOME/.execd/lifecycle.toml bestehen, mit EXECD_LIFECYCLE_CONFIG als exakter Überschreibung; Die Bootstrap-Synchronisierung und das Herunterfahren vor dem Start werden mit TERM/KILL-Watchdogs fehlerfrei geschlossen und interne Transportvariablen werden aus dem Benutzercode entfernt. API-Modelle, die über Go/Python/JS/Kotlin/C# SDKs ausgerichtet sind. (#1587 #1588 #1589)

🐛 Fehlerbehebungen

  • In-Namespace-Signale dringen im Init-Modus nicht mehr in /command ein. kill -HUP 1 hat zuvor alles abgebrochen, was /command ausgeführt hat (signal: hangup); Signale gehören jetzt nur noch dem Init-Forwarder. (#1546) – Der PTY-Erstellungsfehler hat einen zweiten Erfolgstext ausgegeben. POST /pty stoppt jetzt sofort nach der Fehlerantwort, anstatt einen Erfolgstext und eine nicht vorhandene Sitzungs-ID anzuhängen. (#1603) – Die cwd-Validierung berücksichtigt jetzt anforderungsbezogene Umgebungen. Vordergrund-/Hintergrund-/command-Anfragen können eine cwd-Variable aus ihrer eigenen envs-Zuordnung verwenden, anstatt mit 400 abgelehnt zu werden. (#1611)
  • Nicht-Root-Workloads konnten nicht gestartet werden: /bootstrap.sh wurde auf 0755 normalisiert. Ein bereitgestelltes Image trug bootstrap.sh als 0751 root:root und sendete Images mit einem Nicht-Root-Standardbenutzer (z. B. admin) an CrashLoopBackOff, bevor Hooks ausgeführt wurden. Der Image-Build erzwingt nun Exec-Bits für execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh, unabhängig von den Checkout-Berechtigungen. (#1619 #1606)
  • preStart-Timeout von 300 Sekunden auf 10.800 Sekunden (3 Stunden) erhöht. periodic.timeoutSeconds bleibt bei 300 Sekunden; Produktrichtliniengrenzen werden jetzt nur serverseitig durchgesetzt, wobei execd nur einen technischen Überlaufschutz verwaltet. (#1637)

📦 Sonstiges

  • OSEP-0018-Abdeckung geschlossen: Serverpfad und Kubernetes-Härtung e2e (ConfigMap-getragenes Isolations-TOML, keine Änderung der Serverlogik), PTY-Unterhärtung, Bwrap + Init-Reaper-Integration, benutzerdefinierte [seccomp]/keep_capabilities-Richtlinie, EXECD_INIT↔TOML-Drift-Pin, K8s Restart Recycle gegen Init-Modus-Pods, Laufzeitinitiierter Stopp und ein execd-ebpf-Bare-Container-Smoke (dient gleichzeitig der Kernel-5.10-Validierung). Testredundanz und toter Code gekürzt (-359 Zeilen). (#1554 #1555 #1562 #1574)
  • Automatische OTLP-Endpunktzulassung in den gemeinsam genutzten Komponenten enthalten (Ausgang berücksichtigt OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT; PTY-Viewer-Leseschleife wurde im Laufe der Zeit umgestaltet). (#1504)
  • Lebenszyklus-Hook-Anleitung mit Zeitdiagramm und Beispielen für die Erstellung pro SDK; SDK client-seitige Timeout-Validierung, abgestimmt auf den Server. (#1605)

Englisches Original / English original

OpenSandbox docker/execd/v1.1.0

Highlights

  • Opt-in PID 1 sandbox init (EXECD_INIT=1) — execd can now act as the sandbox init process, with single-process reaping, managed-process handling, signal forwarding, and entrypoint exit-code propagation; a subreaper fallback covers the Pool path. The server enables this through runtime.execd_run_as_init for Docker/K8s Batch/Agent/Pool, while classic topology remains the default. This also fixes kill -HUP 1 leaking into /command workloads in init mode. (#1474 #1546)
  • Pre-exec hardening and optional eBPF auditing — opensandbox-launcher applies capability, privilege, seccomp, and optional Landlock restrictions before execve; every hardening layer fails open when unsupported, with status exposed through GET /v1/isolated/capabilities. The separate execd-ebpf image adds cgroup-scoped exec/connect/privilege audit logs and requires kernel ≥5.10 with BTF. Treat these as defense-in-depth, not an unconditional security guarantee. (#1474 #1562)
  • Lifecycle hooks with important provider and timeout behavior — New preStart and periodic hooks are delivered through CreateSandboxRequest.lifecycle; startup waits for preStart, and internal transport variables are stripped from user code. Breaking limitation: the Docker provider rejects lifecycle requests, so this is currently for Kubernetes-compatible paths. preStart now permits up to 10,800 seconds while periodic.timeoutSeconds remains 300 seconds, with product bounds enforced server-side. (#1587 #1588 #1589 #1637)
  • Operational fixes worth taking — Fixes include malformed double responses after /pty creation failures, cwd resolution from request-scoped envs on /command, and image build permissions that previously prevented non-root images from starting in CrashLoopBackOff. (#1603 #1611 #1619 #1606)
  • Upgrade guidance — Worth upgrading for Kubernetes users adopting lifecycle hooks, non-root images hitting bootstrap permission failures, workloads needing reliable signal/reaping behavior, and security-sensitive sandboxes evaluating hardening or eBPF audit; Docker-only users cannot use lifecycle hooks and can skip unless the command/PTY fixes apply. Init mode is opt-in and remains off by default, so existing deployments do not need to change topology.

What's New

✨ Features

  • execd as sandbox init (OSEP-0018). execd can now run as PID 1: single reaper with a managedProcess abstraction on every launch path, signal forwarding (TERM/HUP/USR1/USR2/WINCH), entrypoint-owned exit-code propagation, and a subreaper fallback for the Pool path. Opt-in via EXECD_INIT=1 (injected by the server's runtime.execd_run_as_init for Docker/K8s Batch/Agent/Pool); classic topology unchanged and default off. (#1474)

  • Pre-exec hardening floor. The new opensandbox-launcher native helper applies env strip → KEEPCAPS → bounding-set trim → no_new_privs → identity drop → seccomp → execve; [landlock] adds a filesystem allowlist (fail-open below ABI/kernel 5.13, reported as unsupported). GET /v1/isolated/capabilities gains a hardening object with per-layer state; every layer degrades fail-open. (#1474)

  • eBPF observation variant. execd-ebpf (CGO + cilium/ebpf) hooks exec/connect/privilege with CO-RE, scoped to the sandbox cgroup, emitting a rotating JSONL audit; needs kernel ≥5.10 with BTF. The default image is unchanged. (#1474 #1562)

  • preStart and periodic lifecycle hooks (OSEP-0020). CreateSandboxRequest.lifecycle is transported to the sandbox via the internal OPEN_SANDBOX_LIFECYCLE env (Kubernetes; the Docker provider rejects lifecycle requests). execd starts HTTP before preStart, runs non-overlapping periodic hooks through the reaper-aware managed-process path, and only releases the user process after preStart succeeds. Config persists at $HOME/.execd/lifecycle.toml, with EXECD_LIFECYCLE_CONFIG as exact override; bootstrap sync and preStart shutdown are fail-closed with TERM/KILL watchdogs, and internal transport vars are stripped from user code. API models aligned across Go/Python/JS/Kotlin/C# SDKs. (#1587 #1588 #1589)

🐛 Bug Fixes

  • In-namespace signals no longer leak into /command in init mode. kill -HUP 1 previously killed whatever /command was running (signal: hangup); signals are now owned by the init forwarder only. (#1546)

  • PTY creation failure emitted a second success body. POST /pty now stops immediately after the error response instead of appending a success body and a nonexistent session id. (#1603)

  • cwd validation now honors request-scoped envs. Foreground/background /command requests can use a cwd variable from their own envs map instead of being rejected with 400. (#1611)

  • Non-root workloads could not start: /bootstrap.sh normalized to 0755. A deployed image carried bootstrap.sh as 0751 root:root, sending images with a non-root default user (e.g. admin) into CrashLoopBackOff before hooks ran. The image build now forces exec bits on execd/execd-ebpf/opensandbox-supervisor/bootstrap.sh regardless of checkout permissions. (#1619 #1606)

  • preStart timeout raised from 300s to 10800s (3h). periodic.timeoutSeconds stays at 300s; product policy bounds are now enforced Server-side only, with execd keeping just a technical overflow guard. (#1637)

📦 Misc

  • OSEP-0018 coverage closed out: server-path and Kubernetes hardening e2e (ConfigMap-carried isolation TOML, no server logic change), PTY-under-hardening, bwrap + init-reaper integration, custom [seccomp]/keep_capabilities policy, EXECD_INIT↔TOML drift pin, K8s Restart recycle against init-mode pods, runtime-initiated stop, and an execd-ebpf bare-container smoke (doubles as kernel-5.10 validation). Test redundancy and dead code trimmed (-359 lines). (#1554 #1555 #1562 #1574)

  • OTLP endpoint auto-allow shipped in the shared components (egress honors OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/OTEL_EXPORTER_OTLP_ENDPOINT; PTY viewer read loop refactored along the way). (#1504)

  • Lifecycle hook guide with timing diagram and per-SDK creation examples; SDK client-side timeout validation aligned with the Server. (#1605)
