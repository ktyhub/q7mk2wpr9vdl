OpenSandbox-Release-1.2.1

Stabile Patch-Version für Benutzer, die ein Upgrade von 1.2.0 durchführen, einschließlich 1.2.1-Release-Kandidaten und nachfolgender Fixes. Server, CLI, SDKs, Diagramme und Plattformbilder werden zusammen unter 1.2.1 geliefert.

Highlights

  • Dynamische Anmeldeinformationen: Credential Vault Exchange löst Anmeldeinformationen pro Anfrage über den Server, den Ausgang und alle fünf SDKs auf, ohne dass die aufgelösten Geheimnisse im Tresor bestehen bleiben (#2457 #2535 #2534 #2560).
  • Fast Sandbox VMMs mit mehreren Versionen: verwaltete Firecracker 1.16.1/1.17.0-Bundles ermöglichen es neuen Vorlagenbuilds, die höchste installierte Version auszuwählen, während vorhandene Artefakte mit ihrer genauen aufgezeichneten VMM-Version wiederhergestellt werden, was explizit fehlschlägt, wenn sie nicht verfügbar ist (#2795 #2812 fast-sandbox#189).
  • Sichereres Daten- und Kapazitätsmanagement: Gestaffelte Uploads reduzieren den Verlust von Überschreibdaten, wenn atomar Ersatz verfügbar ist, Controller-Neustarts bewahren Live-Sandbox-Pods und Docker erzwingt angeforderte beschreibbare Festplattenkontingente (#2433 #2478 #2398 #2716).

Server

  • Übertragen Sie Vorlagen-CPU-/Speicherformen durch die Erstellung und Snapshot-Wiederherstellung in ResourceAware-Pools. Legacy-Pools behalten ihr bestehendes Verhalten bei (#2602 #2619 #2623 #2628 #2633). – Erzwingen Sie Docker resourceLimits.disk auf der beschreibbaren Containerebene und geben Sie 400 für nicht unterstützte Treiber oder ungültige Grenzwerte zurück, anstatt sie stillschweigend zu ignorieren (#2716). – Docker-Snapshots direkt aus angehaltenen Sandboxes zulassen (#1941).
  • Verschieben Sie den Server-Proxy-Datenpfad in den Wartungsmodus. Vorhandener Datenverkehr wird weiterhin unterstützt, Bereitstellungen sollten jedoch zum Ingress-Gateway migriert werden (#2548). – Unbekannte Felder in geschlossenen Anforderungsobjekten ablehnen, anstatt falsch geschriebene Optionen stillschweigend zu akzeptieren (#2576). – Reduzieren Sie den Kubernetes API-Verkehr und die Listenkosten durch Informer-Invalidierung pro Objekt und serverseitige Metadatenselektoren (#2599 #2559). – OCI-Vorlagenartefakte müssen im erwarteten Repository SHA-256-fixiert sein (#2491). – Start schlägt fehl, wenn die Durchsetzung des Ablaufs Docker nicht wiederhergestellt werden kann, außer bei gleichzeitig entfernten Containern (#2533). – Weitere Korrekturen verbessern die Erstellungs-Timeout-Diagnose und die Leerlauf-Pause-Probe-Grenzen (#2434 #2596); Docker Mount-, Hostpfad- und Ressourcenvalidierung (#2421 #2505 #2474 #2701 #2751); Proxy-GET-Körper und Erschöpfungsfehler (#2518 #2519); und leere Metadatenfilter, Namensvalidierung und API-Fehlercodes (#2461 #2499 #2702 #2703).

SDKs

– Alle fünf SDKs unterstützen Exchange-Anmeldeinformationsquellen und eine nur auf Anmeldeinformationen beschränkte verbindliche Authentifizierung. Kotlin/C#-Konsumenten müssen erweiterte Anmeldeinformationstypen neu kompilieren und überprüfen (#2534 #2560).

  • Optionaler detaillierter Download von APIs, der Status, Header, Bereiche und Partial-Response-Erkennung offenlegt, ohne dass Änderungen an vorhandenen Adaptern erforderlich sind; Python/JavaScript/C# meldet unbekannte Gesamtwerte, wenn codierte Längen die decodierte Ausgabe nicht beschreiben können (#1597 #2592). – Die Dokumentation erweitert Lebenszyklus-/Netzwerkoptionen, Austauschanmeldeinformationen, Vorlagenworkflows und S3-Beispiele (#2590 #2597 #2620 #2506).

Python

– MCP fügt command_get_status und command_get_logs für Hintergrundbefehlsabfrage und inkrementelle Ausgabe hinzu (#2648).

  • Zeitüberschreitung bei SSE-Streams für stille Befehle; Abgebrochene Downloads geben Verbindungen frei und Streaming-Fehler verwenden durchgängig SDK-Ausnahmen (#2527 #2487 #2531 #2570 #2515 #2525).
  • Durch das ordnungsgemäße Herunterfahren des Pools werden Bereinigungs-Kills abgeführt, anstatt Sandboxen aufzugeben. Kleinere Korrekturen betreffen Endpunktungültigmachung, Adapterumleitungen/-Hooks und umsetzbare MCP-Fehler (#2507 #2409 #2553 #2524).

JavaScript

  • Verhindern, dass positive Befehls-Timeouts im Sub-Millisekunde-Bereich unbegrenzt werden; Beheben Sie unbegrenzte Umleitungsfristen, strukturierte isolierte Sitzungsfehler und das Schließen von Downloads während der Iteration (#2440 #2488 #2466 #2514).

Kotlin

– Runden Sie gebrochene Befehls-/Sitzungs-Timeout-Millisekunden nach oben, um zu verhindern, dass Werte unter einer Millisekunde unbegrenzt werden (#2537).

C#

  • Verwenden Sie das gemeinsame CredentialSource-Modell für Inline- und Exchange-Varianten; Beim Neukompilieren nur Inline-Annahmen aktualisieren (#2560).

Los

– Code-Interpreter-Ausgabefragmente in Execution.Text() beibehalten, ohne Zeilenumbrüche einzufügen (#2447). – Erzwingen Sie Wake-, Running-State- und Interpreter-Bereitschaftsbudgets, ohne etablierte Streams zu kürzen oder nicht abgeschlossene Bereitschaftsprüfungen zu akzeptieren (#2572 #2611 #2528 #2668 #2480 #2504).

  • Behalten Sie die Verantwortung für die Bereinigung bei abgebrochenen Poolvorgängen bei und verhindern Sie eine unvollständige Zerstörung für einen erneuten Versuch. Abgebrochene Erfassungen verbrauchen keine gesunde Leerkapazität mehr (#2542 #2617 #2580 #2616). – Sperren Sie veraltete Endpunktsuchen nach Lebenszyklusänderungen, ohne Abrufe abzubrechen, die noch von anderen Aufrufern benötigt werden (#2503 #2564 #2579). – Weitere Korrekturen betrafen Wiederholungsüberläufe und vom Server bereitgestellte Verzögerungen (#2452 #2508 #2509); SSE-Analyse, mehrteilige Grenzen und Header-Zusammenführung verbessern (#2439 #2618 #2468 #2529); und korrekte Poolwartung, Telemetriefristen und Timeout-Tests (#2453 #2565 #2540 #2479).

Controller

– Fügen Sie Namespace-bezogene Caches, konfigurierbare Anführerwahl-Timings und controller.extraArgs für die Bereitstellungsoptimierung hinzu (#2571 #2651 #2566). – Stellen Sie Poolzuordnungen vor der Räumung wieder her und schützen Sie Live-Sandbox-Pods nach dem Neustart des Controllers (#2398). – Rootfs-Snapshots ohne erforderliche Digests ablehnen und ihre Pods behalten, anstatt die einzige fortsetzbare Laufzeit zu löschen (#2482). – Andere Fixes verhindern lebenszyklusbedingtes Speicherwachstum, entfernen überschüssige inaktive Pods nach poolMax-Reduzierungen und platzieren die Wiederherstellungs-ConfigMap im richtigen Namespace (#2646 #2470 #2694).

Execd

– Ermitteln Sie Jupyter-Laufzeittoken, wenn JUPYTER_TOKEN nicht festgelegt ist (#2448).

  • Hochladen und Ersetzen isolierter Dateien vor dem Umbenennen, um vorhandene Inhalte zu schützen; Atomizität erfordert ein beschreibbares Verzeichnis mit einem unten beschriebenen In-Place-Berechtigungs-Fallback (#2433 #2478). – Behalten Sie Inhalte und Modi isolierter Arbeitsbereiche beim Kopieren/Umbenennen bei, berücksichtigen Sie Overlay-Löschungen und lehnen Sie Symlink-Chmod ab, anstatt Hostzielen zu folgen (#2638 #2469). – Aktualisieren Sie MITM trust nach der Kubernetes Egress-Sidecar-CA-Rotation, um dauerhafte TLS-Fehler zu vermeiden (#2582).
  • Isolierte Läufe verbrauchen keine Shell-Steuerungseingaben mehr; Durch das Löschen von Bash-Sitzungen werden alle aktiven Ausführungen beendet, und beim Schließen von PTY werden normale Hintergrundjobs angehalten, während das terminalähnliche Verhalten für HUP-ignorierende Jobs beibehalten wird (#2517 #2731 #2733). – Stellen Sie Jupyter-Startwiederholungen und Sitzungsbereinigung wieder her, schlagen Sie nicht unterstützte Sprachen sofort fehl und stellen Sie Ausgaben/Fehler bereit, bevor der Abschluss gemeldet wird (#2486 #2689 #2606). – Stellen Sie die SQL-Ausführung nach vorübergehenden Setup-Fehlern wieder her, ohne Abfragen automatisch erneut abzuspielen (#2757).
  • Sicherheitshärtung: Kontrollbytes in Download-Headern prozentual kodieren und RFC 8187-Dateinamenkodierung korrigieren (#2741 #2516). – Weitere Korrekturen betreffen die Korrelation und Validierung von Befehlsprotokollen (#2598 #2686); PTY-Ausgabe und exportierte Escapezeichen (#2644 #2772); Download-/Suchvalidierung und Dateizeitstempel (#2451 #2687 #2604); cgroup-v1-Metriken und SQL-Byte-Rendering (#2641 #2685); und eine Opt-in-Alt-SSE-Problemumgehung für ältere Kotlin/JVM-Bereitstellungen (#2472).

Vernetzung

Ausgang

  • Credential Vault Exchange: löst neue Header über UDS/HTTPS mithilfe von ausgehender Sandbox-Identität und Anforderungszielen auf; Die Auflösung schlägt fehl und aufgelöste Geheimnisse werden vom Tresor weder beibehalten noch zwischengespeichert (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563). – Erzwingen Sie Fast Sandbox-TCP-Port- und IP/CIDR-plus-Port-Richtlinien pro Subjekt, einschließlich Originalzielprüfungen durch MITM (#2662).
  • Hot-Reload von Fast-Sandbox-Operatoren zum Verweigern/Zulassen von Regeln und Erreichbarkeits-Port-Obergrenzen, ohne den ausgehenden Datenverkehr neu zu starten; Änderungen gelten atomar für alle aktiven Subjekte, wobei die vorherige Richtlinie bei Fehlern beibehalten wird und veraltete DNS-Antworten nach dem Widerruf abgelehnt werden. Der Leitfaden zur Netzwerksicherheit dokumentiert Bereitstellungs-, Prioritäts- und Durchsetzungsgrenzen und behält dabei alte Leitfaden-URLs bei (#2727 #2814). – Erlauben Sie der DNS+NFT-Sidecar-Richtlinie PATCH/DELETE, sich für die Blockierung des etablierten Datenverkehrs mit dropEstablished=true zu entscheiden; Fast Sandbox wird nicht unterstützt (#2346).
  • [EXPERIMENTAL] Verstärken Sie die strikte Besitz-/Persistenz- und Subjektbereitschaft von Actions v2 mit dauerhaften Zäunen, authentifizierten untergeordneten Sitzungen und bestätigten Richtlinien-/Vault-Snapshots; Die Standardeinstellungen bleiben unverändert (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708).
  • [EXPERIMENTAL] – nicht für die Produktion: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound wählt ein budgetiertes TLS-Handshake-Experiment aus, bei dem die Anmeldeinformationsinjektion oder Anforderungsweiterleitung nicht funktioniert: Der gesamte entschlüsselte HTTP/1.1- und HTTP/2-Ursprungsverkehr wird weiterhin abgelehnt. all bleibt die Standardeinstellung; Der OSEP-0023-Rollout beschreibt unvollendete Arbeiten (#2737 #2797 #2777). – Sicherheitskorrekturen: Richtlinien-PATCH behält unberührte Verweigerungsregeln bei und ungültige defaultAction-Werte werden abgelehnt, anstatt zu einer inkonsistenten, möglicherweise Fail-Open-Erzwingung zu führen (#2664 #2662 #2693). – Erneuern Sie die Fast Sandbox-DNS-Leases im Kernel und behalten Sie die Leases anderer Subjekte beim Löschen bei (#2652 #2653). – Weitere Härtung umfasst experimentelle Interception-Port-Validierung, idempotente Readiness-Hooks und NFT-Rauch-/Rückleseprüfungen (#2587 #2510 #2543 #2735).

Eingang

  • Verwenden Sie ein Wake-Budget für Warteschlange und Wartezeit und validieren Sie es anhand der Fluglebensdauer. Gemischtes reguläres/Fast-Sandbox-Wake-Routing gerät beim Start nicht mehr in Panik (#2511 #2513 #2600). – Andere Fixes validieren Legacy-Hostnamen-Ports, korrigieren die Telemetrie für final-status/client-IP und entfernen ein Wake-Test-Race (#2578 #2484 #2688 #2512).

Schnelle Sandbox

– Bündeln Sie verwaltete Firecracker 1.16.1/1.17.0-Binärdateien für Laufzeit- und Vorlagen-Builds und wählen Sie die exakte, mit Artefakten aufgezeichnete Version für die Wiederherstellung aus, anstatt stillschweigend das zuletzt installierte VMM zu verwenden (#2795 #2812 fast-sandbox#189). – Isolieren Sie ResourceAware Direct-Firecracker-VMMs in einem begrenzten cgroup-Unterbaum, um Fastlet vor poollokalem OOM zu schützen und gleichzeitig fehlgeschlagene Laufzeitidentitäten für die Bereinigung beizubehalten (#2626 fast-sandbox#162).

  • Aktivieren Sie die Berichterstellung für freie Seiten in neuen Objektspeichervorlagen und geben Sie vom Gast freigegebenen Speicher an den Host zurück, ohne die statischen Ressourcenverpflichtungen zu ändern. OCI-Vorlagen werden noch nicht unterstützt (#2546 fast-sandbox#114). – Verbessern Sie den OCI-Speicher mit wiederverwendbaren Warm-UBLK-Geräten und Best-Effort-Checkpoint-/RootFS-Layer-Komprimierung (#2594 fast-sandbox#163 #2546 fast-sandbox#158). – Wiederverwendung lokal veröffentlichter OCI-Prüfpunkt-Blobs für eine schnellere Wiederaufnahme auf demselben Knoten, mit begrenztem Speicher, Schutz für Live-Gerätereferenzen und Registrierungs-Fallback (#2812 fast-sandbox#178).
  • [EXPERIMENTAL] RootfsOnly-OCI-Snapshots erstrecken sich jetzt von der Laufzeiterfassung auf Fast Sandbox's FastPath und SandboxSnapshot CRD, mit Funktionsprüfungen, Validierung im produzierten Modus und protokollierter Wiederherstellung. Stellt den Kaltstart wieder her, ohne den Speicher zu bewahren; OpenSandbox REST/SDK-Modusauswahl und RootfsOnly Pause/Resume werden weiterhin nicht unterstützt (#2706 fast-sandbox#173 #2812 fast-sandbox#177).
  • OverlayBD-Vorlagen-Builds integrieren jetzt standardmäßig die Gaststeuerung und validieren das Einfrieren/Auftauen. Vorhandene Vorlagen müssen neu erstellt werden, um die RootfsOnly-Erfassungsfunktion zu erhalten (#2812 fast-sandbox#183). – Fügen Sie die gemeinsam genutzte YAML-konfigurierte Dateiprotokollierung und -Rotation für Kubernetes-Komponenten von Erstanbietern hinzu, mit optionaler stderr-Spiegelung; Protokollsammler und benutzerdefinierte Startflags müssen migriert werden (#2812 fast-sandbox#197). – Machen Sie zeitgestempelte Vorlagenerstellungsphasen, verstrichene Zeiten und Fehler bei Image-Pull, Rootfs-Vorbereitung, Gastbereitschaft, Snapshotting und Veröffentlichung sichtbar (#2815 fast-sandbox#201).
  • [EXPERIMENTAL] Fence verzögerte strikte Actions v2-Vorgänge mit dauerhafter Eigentümeridentität und bestätigtem Ruhestand; v1 bleibt die Standardeinstellung (#2546 fast-sandbox#152). – Namespace/API-client-Tuning, Chart-Scheduling-Hooks, optionale Direct-Origin-Lieferung und Template-Baked-Execd-Init-Modus hinzufügen (#2581 fast-sandbox#161 #2566 #2494 #2497). – Sofortige Erstellungs-/Pause-/Fortsetzungsübergänge konvergieren jetzt ohne Verzögerungen bei der Abwicklung, und aktive Pools ersetzen Terminal-Fastlet-Pods, anstatt sie als Kapazität zu zählen (#2626 fast-sandbox#166 #2706 fast-sandbox#172).
  • Wiederherstellen inaktiver, gemeinsam genutzter Snapfile-Anhänge nach Verlust des ublkd-Geräts ohne manuelles Löschen des Caches; Anhänge mit anderen Sandbox-Leases bleiben geschützt und werden nicht unter Live-Konsumenten neu erstellt (#2812 fast-sandbox#193). – Weitere Korrekturen betreffen die BusyBox-basierte Vorlagenbereitschaft, die Zeitstempelgenauigkeit und das Rendering bestehender Geheimnisse (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695); Stellen Sie den Cache-Affinitätsabgleich für Firecracker-Bild-/Vorlagenverweise wieder her (#2812 fast-sandbox#119).
  • Erweitern Sie die Rollout-Abdeckung von ResourceAware und korrigieren Sie die CPU-Budgets der Geräte, ohne die Sättigungskapazität zu ändern (#2622 #2637 #2647 #2669 #2812); Verbesserung der UBLK-Wiederherstellung, Exchange-/Konsolen-Integrationstests, KVM-Auswahl und Snapshot-Staging-Dokumentation (#2454 #2561 #2676 #2665 #2714); Gate PR KVM läuft auf dem vom Betreuer hinzugefügten ok-to-test, ohne dass unabhängige Labels einen aktiven Lauf abbrechen (#2813).

Upgrade und Kompatibilität

  • Verwalteter Firecracker: Bereitstellung passender Diagramme, Laufzeit- und Builder-Images; runtimeEnvironments → firecracker.firecracker.vmmDir wird jetzt unterstützt und muss auf ein absolutes verwaltetes Binärverzeichnis verweisen. Neue verwaltete Builds wählen die höchste installierte Version (derzeit 1.17.0); Vollständige/RootfsOnly-Wiederherstellungen erfordern die im Manifest aufgezeichnete Version und schlagen fehl, wenn sie nicht verfügbar ist, anstatt auf die neueste Version zurückzugreifen. Behalten Sie 1.16.1-Binärdateien für vorhandene Artefakte bei, ohne sie neu zu kennzeichnen. Das Beibehalten alter Binärdateien garantiert keine Downgrade-Kompatibilität für den beibehaltenen Fast Sandbox-Status (#2795 #2812 fast-sandbox#189).
  • Anfragevalidierung: unbekannte Schlüssel aus geschlossenen Anfrageobjekten entfernen und nur eine Alias-Schreibweise verwenden; diese geben nun 422 zurück. Ersetzen Sie die ImageAuth.token/Docker-config-Extras durch unterstützte username/password, entfernen Sie abschließende Zeilenumbrüche aus Namen/Adressen und verwenden Sie nur allow/deny für die Richtlinie defaultAction (#2576 #2499 #2693).
  • SDK-Anmeldeinformationsmodelle: Kotlin/C# sind nicht ABI-kompatibel mit 1.2.0; Kompilieren und überprüfen Sie erweiterte Quellen und nullfähige/typlose Authentifizierungsannahmen neu. Exchange-Authentifizierung enthält nur credential; Python-Inline-Quellen lehnen zusätzliche Schlüssel ab und Benutzer generierter Modelle sollten handgeschriebene Modelle bevorzugen. Verwenden Sie verschlüsselte Go-Literale für geänderte Quell-/Metadatenmodelle und Execution; Durch das Roundtripping von JSON geht der private Formatierungsmodus von Execution.Text() verloren (#2560 #2534 #2447).
  • Proxy/Ingress: Server-Proxy-Optionen, die nur für die Wartung bestimmt sind, auf Ingress migrieren; Legacy-Hostnamen-Ports müssen kanonische Dezimalzahlen in 1–65535 sein und --wake-park-budget muss unter --wake-max-flight-lifetime liegen (#2548 #2578 #2511).
  • Docker-Kontingente: Die bereitgestellten disk/storage/ephemeral-storage-Grenzwerte müssen positiv sein und vom Speichertreiber unterstützt werden. Andernfalls wird bei der Erstellung der Wert 400 zurückgegeben. Es wird nur die beschreibbare Ebene abgedeckt, nicht jedoch Bind-Mounts, Volumes oder Image-Ebenen. Windows behält sein bestehendes Festplattengrößenverhalten bei (#2716).
  • Docker Preflight/Startup: korrekte Duplikat-, Root-, Doppelpunkt-enthaltende oder reservierte Mount-Ziele und Mengen über signiertem int64; Eine explizite /-Hostpfad-Zulassungsliste autorisiert alle POSIX-Nachkommen. Ablauf-Wiederherstellungsfehler verhindern jetzt den Start, es sei denn, der Container wurde gleichzeitig entfernt; Untersuchen Sie persistente Daemon-Fehler (#2421 #2505 #2751 #2474 #2533).
  • Downloads: detaillierte APIs bleiben für benutzerdefinierte Adapter optional; Überprüfen Sie 206/isPartial und Bereiche vor dem Anhängen und schließen Sie Antworttexte. Unbekannte Summen verwenden -1; Verschlüsselte HTTP-Längen/-Bereiche sind keine dekodierten Fortschritts- oder Fortsetzungsoffsets. Python-Aufrufer sollten SDK-Ausnahmen abfangen und nicht rohe httpx-Fehler (#1597 #2592 #2515 #2525).
  • Zeitüberschreitungen und Abfragen: Python-Befehlsströme laufen nach max(request_timeout, 30s) ohne Bytes ab; Erhebe request_timeout für legitimes Schweigen. MCP-Poller müssen Protokolle nach Abschluss noch einmal lesen und undurchsichtige Cursor beibehalten; Eine leere Ausgabe ist keine Vollendung. Benutzerdefinierte Go-Pool-Stores müssen eine Stornierung akzeptieren und eine unvollständige Zerstörung bleibt für einen erneuten Versuch geschützt (#2527 #2648 #2580).
  • Upload-Atomizität: beschreibbare Verzeichnisse für gestaffelte Uploads/isolierte Ersetzungen verwenden; Vorhandene beschreibbare Dateien greifen bei Staging-Berechtigungsfehlern auf nicht-atomare Kürzung zurück. Der normale /files/replace bleibt an Ort und Stelle. Beim gestaffelten Ersetzen bleiben Modi erhalten, nicht xattrs/ACLs/capabilities/SELinux-Labels; Der Besitz ist Best Effort für gewöhnliche Schreibvorgänge und Sitzungs-UID/GID für isolierte Schreibvorgänge (#2433 #2478).
  • Upload-Speicher: Hardlinks/offene Reader behalten den alten Inode, mehrteilige Überschreibungen erfordern möglicherweise etwa das Dreifache der Dateigröße und unterbrochene Writer können Staging-Dateien hinterlassen. Vermeiden Sie reservierte .osb-upload-/.osb-staging--Namen, insbesondere ein Präfix plus 16 Hexadezimalziffern; bestehende Kollisionen direkt umbenennen. Spezielle Dateiziele werden abgelehnt, während gebundene/geöffnete Dateien das Umbenennen verhindern können; Verzeichnissynchronisierung ist Best-Effort (#2433 #2478).
  • Sitzungslebenszyklus: isolierter Vordergrund-Stdin ist jetzt /dev/null; Verwenden Sie Dateien oder Hier-Dokumente. Durch das Löschen einer Bash-Sitzung werden alle überlappenden Ausführungen beendet. PTY-Schließen fügt SIGHUP und bis zu 500 ms vor dem Gruppenkill hinzu, während nohup/HUP-ignorierende Jobs überleben können (#2517 #2731 #2733).
  • Jupyter/JVM: Benutzerdefinierte Images benötigen ein explizites Token oder erkennbare Laufzeit-Token-Dateien und den angeforderten Kernel. Bevorzugen Sie schattiertes sandbox-api 1.0.18+ gegenüber EXECD_SSE_LEGACY_COMPAT, das standardmäßig deaktiviert ist und strukturierte exit_code-Werte entfernt (#2448 #2689 #2472).
  • Controller-Konfiguration: Der Cache-Bereich muss alle verwalteten Namespaces sowie Fast Sandbox-Vorlagen-/Laufzeitumgebungs-Namespaces umfassen. Es ändert weder RBAC noch sorgt es für Mandantenisolierung. Überprüfen Sie controller.podRecovery.*, das jetzt wirksam wird, und entfernen Sie veraltete ConfigMaps, die durch Plain-Manifest-Upgrades entstanden sind. Benutzerdefinierte Wahlzeiten erfordern Lease > Erneuern > 1.2×Retry (#2571 #2581 fast-sandbox#161 #2694 #2651).
  • Exchange-Bereitstellung: Server/SDK/Egress-Versionen ausrichten; Die Sidecar-Live-Revisionslaufzeit unterstützt keinen Austausch. Die Authentifizierung des Resolver-Anrufers ist nicht implementiert – Ed25519/JWKS bleibt nur im Design. Verwenden Sie ein geschütztes UDS oder trusted-egress-only HTTPS mit trusted-CAs. Sandbox-Zulassungsregeln dürfen keine Resolver verfügbar machen, und der MITM-UID-Ausschluss allein stellt keine Isolation dar (#2501 #2549 #2631 #2547). – [EXPERIMENTAL] Strict Actions v2: ermöglichen den Abgleich der OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion-Werte von sandbox.fast.io/actions/v2 nur bei Clean-Base-Direct-Firecracker-Bereitstellungen mit dauerhaftem Status, isolierten Verwaltungsports und Managerautorisierung. Anhalten/Fortsetzen, Snapshots/Wiederherstellung, Live-Bindungsentfernung, Besitzermigration und Wiederverwendung derselben UID werden weiterhin nicht unterstützt; Terminallöschung/neue UIDs verwenden, Zäune beibehalten und Fencing niemals als Authentifizierung behandeln oder den vorhandenen Status auf v1 herabstufen (#2441 #2460 #2493 #2546 Fast-Sandbox#152).
  • [EXPERIMENTAL] Anmeldeinformationsgebundenes Abfangen: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound verweigert weiterhin die Weiterleitung entschlüsselter Anwendungen und darf in der Produktion nicht aktiviert werden. Wenn der Schalter nicht aktiviert ist, bleiben beide aktivierten Legacy-Gates ein veralteter Alias. revision-runtime allein dient nur der Installation. Explizite Modus-/Gate-Konflikte, leere/unbekannte Werte und das Setzen dieses Schalters beim Sidecar-Fehlerstart (#2737 #2797).
  • Experimentelle Startanforderungen: Der anmeldeinformationsgebundene Modus erfordert transparentes MITM, dns+nft und nur Standard-Abhörports 80,443; Entfernen Sie unsichere TLS-Überprüfung, verkettete Proxys und effektive ignore_hosts/allow_hosts. Der Laufzeitbenutzer config.yaml und dann config.yml werden überprüft. Lese-/Analysefehler schlagen fehl. Um zu all zurückzukehren, deaktivieren Sie beide Legacy-Gates. Die Sidecar-Live-Revision lehnt auch zusätzliche Abfangports ab (#2587 #2797).
  • Port-Richtlinien: Fast Sandbox unterstützt nur TCP, höchstens 256 Ports pro Regel und keine Domain-plus-Port-Kombinationen; Bei normalen Updates bleiben etablierte Abläufe erhalten. dropEstablished wird nur auf DNS+NFT-Sidecar-PATCH/DELETE unterstützt, von POST ignoriert und in den Modi „Fast Sandbox“, „DNS-only“, „Live-Revision“ oder „Chained-Proxy-plus-Transparent-MITM“ nicht unterstützt; Es werden Paketverluste installiert, keine TCP-Resets. Das alleinige Entfernen einer Nur-Port-Zulassung löst keine Blockierung des etablierten Datenflusses aus (#2662 #2346).
  • Neuladen von Operatorregeln: Fast Sandbox lädt zur Laufzeit veränderbare Regeldateien in einem Minutentakt neu; Mounten Sie ConfigMaps als Verzeichnisse, nicht als subPath, und berücksichtigen Sie die Verzögerung der Kubelet-Projektion. Imagebasierte Regeln erfordern immer noch ein neues Image und eine Neugestaltung. Erfolgreiche Neuladevorgänge löschen DNS-gelernte Leases, sodass zulässige Domänen erneut gesucht werden müssen. Bei fehlgeschlagenen Neuladevorgängen bleibt das vorherige Overlay erhalten und bestehende Verbindungen werden nicht zwangsweise beendet (#2727 #2814).
  • Netzwerksicherheitsgrenzen: Domain verweigert Filter-DNS, keine direkten Verbindungen zu bekannten IPs; Verwenden Sie für diese Pfade explizite IP/CIDR-Ablehnungen oder Standard-Ablehnungsrichtlinien. Der Betreiber verweigert das Außerkraftsetzen der vom Betreiber zugelassenen Dienste, sodass zulässige interne Dienste eine Ausgliederung des Verweigerungsbereichs erfordern. Die klassische Docker/Kubernetes-Erstellung injiziert ausgehenden Datenverkehr nur, wenn networkPolicy bereitgestellt wird. poolRef plus networkPolicy wird nicht unterstützt. Konfigurieren Sie daher gepoolte Steuerelemente in der Vorlage (#2814).
  • ResourceAware-Rollout: Direct-Firecracker resource-admission.json wechselt von v2 auf v3; Alte/neue Fastlets lehnen die andere Konfigurationsversion ab, also koordinieren Sie Controller-/Fastlet-Upgrades pro Pool. Heartbeats bleiben v2. Hosts erfordern beschreibbare cgroup v2, clone3(CLONE_INTO_CGROUP) und keinen effektiven Pool-Swap; Die Obergrenze für gemeinsam genutzten Speicher bietet keinen Schutz pro VM oder eine Garantie für das Überleben beim Austausch von Containern (#2626 fast-sandbox#162).
  • Größe wiederherstellen: ResourceAware-Pools verwenden Vorlagen-CPU-/Speicherformen; Neue Snapshots geben die Grenzwerte der Wiedergabequelle wieder, mit denen die Aufrufergrenzwerte für die Wiederherstellungszeit übereinstimmen müssen. Legacy-Pools und Snapshots ohne aufgezeichnete Grenzwerte behalten ihr vorheriges Verhalten bei (#2623 #2628 #2633).
  • [EXPERIMENTAL] RootfsOnly: Full bleibt die Standardeinstellung; Der explizite RootfsOnly-Modus ist über Fast Sandbox FastPath/CRDs für wiederverwendbare OCI-Snapshots verfügbar, nicht für Pause/Fortsetzung oder OpenSandbox REST/SDK-Modusauswahl. Für die neue Erfassung sind qualifizierte, gepatchte Firecracker 1.17.0-Vorlagen, ein Live-Gast-Helfer, ein qualifiziertes Kernel-/OverlayBD-Backend, exklusiver ext4-Besitz und ein absolutes FAST_SANDBOX_ROOTFS_QUALIFICATION-Profil mit passenden Digests/Speicherbescheinigungen erforderlich. Benutzerdefinierte Binärdigests umgehen das Versionstor nicht. Aktualisieren Sie Laufzeit, Fastlet/Proxy, Builder und Tools gemeinsam, erstellen Sie qualifizierte Vorlagen neu und bewahren Sie Journale/Zäune auf. Kaltstarts wiederherstellen und Einstiegspunkt erneut ausführen; Es wird keine Erhaltung des Anwendungsspeichers oder validierte CPU-/architekturübergreifende Portabilität versprochen (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189).
  • OverlayBD-Vorlagen-Builds: Gastkontrollinjektion und Freeze/Thaw-Validierung sind jetzt für den OCI-Builder obligatorisch; FSB_GUEST_CONTROL_ENABLED ist kein Opt-out mehr. Fehlende/inkompatible Hilfsprogramme oder fehlgeschlagene Tests stoppen den Build. Native Vorlagen bleiben unverändert; Vorhandene OCI-Vorlagen müssen neu erstellt und nicht Metadaten bearbeitet werden, um die Erfassungsfähigkeit zu erhalten (#2812 fast-sandbox#183).
  • Schnelle Sandbox-Protokolle: abgedeckte Kubernetes-Komponenten schreiben jetzt standardmäßig rotierende Dateien unter /var/log/fast-sandbox (100 MiB pro Datei, 10 Backups, 7-tägige Backup-Aufbewahrung, gzip); Anwendungsprotokolle werden nicht mehr in kubectl logs angezeigt, es sei denn, alsoStderr: true ist konfiguriert. Ersetzen Sie alte Klog-Ausgabeflags durch die gemeinsame Protokollierung YAML, verbinden Sie ConfigMap/Log-Volume-Mounts für diagrammverwaltete statische Workloads und konfigurieren Sie jeden Mandanten-Namespace separat. Die Konfiguration ist nur beim Start möglich: Verwenden Sie für Fastlets eine kontrollierte Poolentleerung/-ersetzung, nicht das Löschen von Live-Pods, und veranlassen Sie die Erfassung, bevor kurzlebige Protokolle verloren gehen. Explizite fehlende/ungültige Konfiguration oder nicht beschreibbare Ausgabe verhindern den Start; Rotationslimits sind kein Festplattenkontingent und gelten nicht für Gast-/VM-Protokolle (#2812 fast-sandbox#197).
  • OCI-Checkpoint-Cache: Reservieren Sie Speicherplatz für den zusätzlichen Blob-Cache (Standard: 16 GiB, 4096 Dateien, 1 GiB freie Speicherplatzreserve), getrennt vom Block-Cache von OverlayBD. Behalten Sie den Staging-/Cache-/Gerätestatus in einem Dateisystem bei, um die Wiederverwendung von Hardlinks zu ermöglichen. Bei dateisystemübergreifender Platzierung oder Konflikten wird auf die Registrierung zurückgegriffen. Legen Sie FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 fest, um das Einfügen/Suchen im Blob-Cache zu deaktivieren. Die Pins aktiver Geräte bleiben geschützt, auch wenn die Budgets schrumpfen (#2812 fast-sandbox#178).
  • ublkd-Wiederherstellung: Die automatische Wiederherstellung gemeinsam genutzter Snapfiles erfolgt nur, wenn kein anderer Sandbox-Leasing den Anhang benötigt. Es handelt sich nicht um eine transparente Wiederherstellung laufender VMs. Entfernen Sie betroffene Sandboxes über ihren normalen Lebenszyklus, bevor Sie es erneut versuchen, wenn andere Leases verbleiben, anstatt gemeinsam genutzte Caches manuell zu löschen (#2812 fast-sandbox#193).
  • Vorlagen-Neuerstellungen: Opt-in runtime.execd_run_as_init benötigt neu erstellte Vorlagen; execd bleibt ein Subreaper unter Gast-PID 1. Free-Page-Reporting erfordert auch neu erstellte Objektspeichervorlagen und kompatible VMM-/Kernel-Unterstützung, kann den wiederhergestellten Gerätestatus nicht umschalten und ermöglicht kein OCI-Reporting und rechtfertigt kein höheres Overcommit; Rollback verwendet eine ältere Vorlage (#2494 #2497 #2546 fast-sandbox#114).
  • OCI-Diagramm-Standardwerte: inaktive ublk-Geräte sind jetzt reserviert; Legen Sie runtime.oci.poolLow=0 für die bedarfsgesteuerte Zuweisung fest und passen Sie poolSizeGB an die aufgerundete Rootfs-Kapazität an. P2P bleibt standardmäßig aktiviert; Das benutzerdefinierte runtime.config erfordert eine separate Anpassung für die Direktzustellung (#2594 fast-sandbox#163 #2566).
  • Snapshot-Integrität: Fehlende Commit-Digests schlagen jetzt fehl, während Pods beibehalten werden; Alte Snapshots werden nicht repariert. OCI-Vorlagenverweise müssen einen vollständigen SHA-256-Digest im erwarteten Repository enthalten; Ungültige Referenzen neu erstellen (#2482 #2491).
  • CLI-Skripte: Nicht positive Anforderungszeitüberschreitungen und leere Regelziele sind Nutzungsfehler; Die Überschreibverweigerung osb config init wird jetzt beendet 1, ohne dass die Datei geändert wird (#2742 #2692 #2743).

  • Artefaktüberprüfung: Umbrella-Workflows bieten keine pauschale Unterzeichnungs-/Herkunftsabdeckung; Der Stücklisten-Digest-Abgleich ist kein Herkunftsnachweis und Signaturanforderungen dürfen nicht umgangen werden (#2467).

OpenSandbox release-1.2.1

Stable patch release for users upgrading from 1.2.0, including both 1.2.1 release candidates and subsequent fixes. Server, CLI, SDKs, charts, and platform images ship together at 1.2.1.

Highlights

  • Dynamic credentials: Credential Vault Exchange resolves credentials per request across the server, egress, and all five SDKs, without vault persistence of resolved secrets (#2457 #2535 #2534 #2560).
  • Multi-version Fast Sandbox VMMs: managed Firecracker 1.16.1/1.17.0 bundles let new template builds select the highest installed version while existing artifacts restore with their exact recorded VMM version, failing explicitly if it is unavailable (#2795 #2812 fast-sandbox#189).
  • Safer data and capacity management: staged uploads reduce overwrite data loss where atomic replacement is available, controller restarts preserve live-sandbox Pods, and Docker enforces requested writable-layer disk quotas (#2433 #2478 #2398 #2716).

Server

  • Carry template CPU/memory shapes through creation and snapshot restore on ResourceAware pools; legacy pools retain their existing behavior (#2602 #2619 #2623 #2628 #2633).
  • Enforce Docker resourceLimits.disk on the writable container layer, returning 400 for unsupported drivers or invalid limits instead of silently ignoring them (#2716).
  • Allow Docker snapshots directly from paused sandboxes (#1941).
  • Move the server-proxied data path into maintenance mode; existing traffic remains supported, but deployments should migrate to the ingress gateway (#2548).
  • Reject unknown fields in closed request objects rather than silently accepting misspelled options (#2576).
  • Reduce Kubernetes API traffic and list costs through per-object informer invalidation and server-side metadata selectors (#2599 #2559).
  • Require OCI template artifacts to be SHA-256-pinned in the expected repository (#2491).
  • Fail startup when Docker expiration enforcement cannot be restored, except for concurrently removed containers (#2533).
  • Other fixes improve create-timeout diagnostics and idle-pause probe bounds (#2434 #2596); Docker mount, host-path, and resource validation (#2421 #2505 #2474 #2701 #2751); proxy GET bodies and exhaustion errors (#2518 #2519); and empty metadata filters, name validation, and API error codes (#2461 #2499 #2702 #2703).

SDKs

  • All five SDKs support exchange credential sources and credential-only binding auth; Kotlin/C# consumers must recompile and review widened credential types (#2534 #2560).
  • Optional detailed download APIs expose status, headers, ranges, and partial-response detection without requiring changes to existing adapters; Python/JavaScript/C# report unknown totals when encoded lengths cannot describe decoded output (#1597 #2592).
  • Documentation expands lifecycle/network options, exchange credentials, template workflows, and S3 examples (#2590 #2597 #2620 #2506).

Python

  • MCP adds command_get_status and command_get_logs for background-command polling and incremental output (#2648).
  • Silent command SSE streams now time out; abandoned downloads release connections, and streaming failures consistently use SDK exceptions (#2527 #2487 #2531 #2570 #2515 #2525).
  • Graceful pool shutdown drains cleanup kills rather than abandoning sandboxes; smaller fixes cover endpoint invalidation, adapter redirects/hooks, and actionable MCP errors (#2507 #2409 #2553 #2524).

JavaScript

  • Prevent positive sub-millisecond command timeouts from becoming unbounded; fix unlimited redirect deadlines, structured isolated-session errors, and closing downloads during iteration (#2440 #2488 #2466 #2514).

Kotlin

  • Round fractional command/session timeout milliseconds upward, preventing sub-millisecond values from becoming unbounded (#2537).

C#

  • Use the common CredentialSource model for inline and exchange variants; update inline-only assumptions when recompiling (#2560).

Go

  • Preserve code-interpreter output fragments in Execution.Text() without inserting newlines (#2447).
  • Enforce wake, Running-state, and interpreter-readiness budgets without truncating established streams or accepting unfinished readiness probes (#2572 #2611 #2528 #2668 #2480 #2504).
  • Preserve cleanup ownership during cancelled pool operations and fence incomplete destruction for retry; cancelled acquires no longer consume healthy idle capacity (#2542 #2617 #2580 #2616).
  • Fence stale endpoint lookups after lifecycle changes without cancelling fetches still needed by other callers (#2503 #2564 #2579).
  • Other fixes bound retry overflow and server-supplied delays (#2452 #2508 #2509); improve SSE parsing, multipart boundaries, and header merging (#2439 #2618 #2468 #2529); and correct pool maintenance, telemetry deadlines, and timeout tests (#2453 #2565 #2540 #2479).

Controller

  • Add namespace-scoped caches, configurable leader-election timings, and controller.extraArgs for deployment tuning (#2571 #2651 #2566).
  • Recover pool allocations before eviction, protecting live-sandbox Pods after controller restarts (#2398).
  • Reject rootfs snapshots missing required digests and retain their Pods instead of deleting the only resumable runtime (#2482).
  • Other fixes prevent lifecycle-related memory growth, remove excess idle Pods after poolMax reductions, and place the recovery ConfigMap in the correct namespace (#2646 #2470 #2694).

Execd

  • Discover Jupyter runtime tokens when JUPYTER_TOKEN is unset (#2448).
  • Stage uploads and isolated-file replacements before rename to protect existing content; atomicity requires a writable containing directory, with an in-place permission fallback described below (#2433 #2478).
  • Preserve isolated-workspace contents and modes during copy-up/rename, honor overlay deletions, and reject symlink chmod rather than following host targets (#2638 #2469).
  • Refresh MITM trust after Kubernetes egress-sidecar CA rotation, avoiding persistent TLS failures (#2582).
  • Isolated runs no longer consume shell control input; deleting Bash sessions terminates all active runs, and PTY close hangs up ordinary background jobs while retaining terminal-like behavior for HUP-ignoring jobs (#2517 #2731 #2733).
  • Restore Jupyter startup retries and session cleanup, fail unsupported languages promptly, and deliver output/errors before reporting completion (#2486 #2689 #2606).
  • Recover SQL execution after temporary setup failures without automatically replaying queries (#2757).
  • Security hardening: percent-encode control bytes in download headers and correct RFC 8187 filename encoding (#2741 #2516).
  • Other fixes cover command-log correlation and validation (#2598 #2686); PTY output and exported escapes (#2644 #2772); download/search validation and file timestamps (#2451 #2687 #2604); cgroup-v1 metrics and SQL byte rendering (#2641 #2685); and an opt-in legacy SSE workaround for older Kotlin/JVM deployments (#2472).

Networking

egress

  • Credential Vault Exchange: resolve fresh headers through UDS/HTTPS using egress-derived sandbox identity and request targets; resolution fails closed, and resolved secrets are neither persisted nor cached by the vault (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563).
  • Enforce Fast Sandbox per-subject TCP port and IP/CIDR-plus-port policies, including original-destination checks through MITM (#2662).
  • Hot-reload Fast Sandbox operator deny/allow rules and reachable-port caps without restarting egress; changes apply atomically across active subjects, retaining the previous policy on failure and rejecting stale DNS answers after revocation. The network-security guide documents deployment, precedence, and enforcement boundaries while preserving old guide URLs (#2727 #2814).
  • Allow dns+nft sidecar policy PATCH/DELETE to opt into blocking established traffic with dropEstablished=true; Fast Sandbox is not supported (#2346).
  • [EXPERIMENTAL] Harden strict Actions v2 ownership/persistence and subject readiness with durable fences, authenticated child sessions, and acknowledged policy/Vault snapshots; defaults remain unchanged (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708).
  • [EXPERIMENTAL] — not for production: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound selects a budgeted TLS handshake experiment, not working credential injection or request forwarding: all decrypted HTTP/1.1 and HTTP/2 origin traffic is still denied. all remains the default; the OSEP-0023 rollout describes unfinished work (#2737 #2797 #2777).
  • Security fixes: policy PATCH preserves untouched deny rules, and invalid defaultAction values are rejected rather than producing inconsistent, potentially fail-open enforcement (#2664 #2662 #2693).
  • Renew Fast Sandbox DNS leases in the kernel and preserve other subjects' leases during deletion (#2652 #2653).
  • Other hardening covers experimental interception-port validation, idempotent readiness hooks, and nft smoke/read-back checks (#2587 #2510 #2543 #2735).

ingress

  • Use one queue-plus-wait wake budget and validate it against flight lifetime; mixed regular/Fast Sandbox wake routing no longer panics at startup (#2511 #2513 #2600).
  • Other fixes validate legacy hostname ports, correct final-status/client-IP telemetry, and remove a wake-test race (#2578 #2484 #2688 #2512).

Fast Sandbox

  • Bundle managed Firecracker 1.16.1/1.17.0 binaries for runtime and template builds, selecting the exact artifact-recorded version for restore rather than silently using the latest installed VMM (#2795 #2812 fast-sandbox#189).
  • Isolate ResourceAware direct-Firecracker VMMs in a bounded cgroup subtree, protecting Fastlet from pool-local OOM while retaining failed-runtime identities for cleanup (#2626 fast-sandbox#162).
  • Enable free-page reporting in new object-store templates, returning guest-freed memory to the host without changing static resource commitments; OCI templates are not yet supported (#2546 fast-sandbox#114).
  • Improve OCI storage with reusable warm ublk devices and best-effort checkpoint/rootfs layer compaction (#2594 fast-sandbox#163 #2546 fast-sandbox#158).
  • Reuse locally published OCI checkpoint blobs for faster same-node resume, with bounded storage, protection for live-device references, and registry fallback (#2812 fast-sandbox#178).
  • [EXPERIMENTAL] RootfsOnly OCI snapshots now extend from runtime capture to Fast Sandbox's FastPath and SandboxSnapshot CRD, with capability checks, produced-mode validation, and journaled recovery. Restores cold-boot without preserving memory; OpenSandbox REST/SDK mode selection and RootfsOnly pause/resume remain unsupported (#2706 fast-sandbox#173 #2812 fast-sandbox#177).
  • OverlayBD template builds now inject guest-control and validate freeze/thaw by default; existing templates need rebuilding to gain RootfsOnly capture capability (#2812 fast-sandbox#183).
  • Add shared YAML-configured file logging and rotation for first-party Kubernetes components, with optional stderr mirroring; log collectors and custom launch flags need migration (#2812 fast-sandbox#197).
  • Expose timestamped template-build phases, elapsed times, and failures across image pull, rootfs preparation, guest readiness, snapshotting, and publication (#2815 fast-sandbox#201).
  • [EXPERIMENTAL] Fence delayed strict Actions v2 operations with durable owner identity and confirmed retirement; v1 remains the default (#2546 fast-sandbox#152).
  • Add namespace/API-client tuning, chart scheduling hooks, optional direct-origin delivery, and template-baked execd init mode (#2581 fast-sandbox#161 #2566 #2494 #2497).
  • Immediate create/pause/resume transitions now converge without settle delays, and active pools replace terminal Fastlet Pods instead of counting them as capacity (#2626 fast-sandbox#166 #2706 fast-sandbox#172).
  • Recover idle shared snapfiles attachments after ublkd device loss without manual cache wipes; attachments with other Sandbox leases remain protected rather than being rebuilt under live consumers (#2812 fast-sandbox#193).
  • Other fixes cover BusyBox-based template readiness, timestamp precision, and existing-secret rendering (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695); restore cache-affinity matching for Firecracker image/template references (#2812 fast-sandbox#119).
  • Expand ResourceAware rollout coverage and correct fixture CPU budgets without changing saturation capacity (#2622 #2637 #2647 #2669 #2812); improve ublk recovery, exchange/console integration tests, KVM selection, and snapshot-staging documentation (#2454 #2561 #2676 #2665 #2714); gate PR KVM runs on maintainer-added ok-to-test, without unrelated labels cancelling an active run (#2813).

Misc

  • Console: add a browser PTY shell with BFF-held credentials and automatic session cleanup, improve disconnect feedback, and translate the interface into English (#2233 #2639 #2657).
  • Node-agent: collect guest kernel/init console output through an opt-in vm-console source, using node-local VM metadata and restart-safe offsets rather than cluster-wide Sandbox watches (#2234 #2677 #2546 fast-sandbox#154).
  • CLI fixes preserve literal output and string configuration (#2520 #2522); improve config, argument, timeout, and overwrite-refusal errors (#2521 #2551 #2692 #2742 #2748 #2743); and repair PTY cleanup, metrics watching, and table output, including osb template get's missing manifest_ref (#2523 #2691 #2747 #2745).
  • Examples add an ACK PeerPods/TDX walkthrough and adopt Google ADK 2.13.0's native environment/toolset, while correcting the Python network-isolation example (#2545 #2734 #2711).
  • Governance/docs publish the AAIF charter and DCO/CC-BY-4.0 contribution rules, clarify voting and ownership, reconcile proposal statuses, and document signing/provenance gaps (#2490 #2678 #2679 #2680 #2624 #2670 #2671 #2672 #2673 #2674 #2467).
  • Maintenance covers orphan node-agent streams, dead-code/test cleanup, single-platform Kind imports, and Linux/eBPF test setup (#2471 #2496 #2640 #2736 #2573 #2473).
  • Release preparation includes candidate version bumps, notes, and generated BOMs (#2583 #2584 #2585 #2588 #2720 #2723 #2724 #2725 #2726).

Upgrade & Compatibility

  • Managed Firecracker: deploy matching charts, runtime, and builder images; runtimeEnvironments → firecracker.firecracker.vmmDir is now supported and must reference an absolute managed-binary directory. New managed builds choose the highest installed version (currently 1.17.0); Full/RootfsOnly restores require the manifest-recorded version and fail if it is unavailable, rather than falling back to latest. Keep 1.16.1 binaries for existing artifacts without relabeling them; retaining old binaries does not guarantee downgrade compatibility for persisted Fast Sandbox state (#2795 #2812 fast-sandbox#189).
  • Request validation: remove unknown keys from closed request objects and use only one alias spelling; these now return 422. Replace ImageAuth.token/Docker-config extras with supported username/password, remove trailing newlines from names/addresses, and use only allow/deny for policy defaultAction (#2576 #2499 #2693).
  • SDK credential models: Kotlin/C# are not ABI-compatible with 1.2.0; recompile and review widened sources and nullable/typeless auth assumptions. Exchange auth contains only credential; Python inline sources reject extra keys, and generated-model users should prefer handwritten models. Use keyed Go literals for changed source/metadata models and Execution; JSON round-tripping loses Execution.Text()'s private formatting mode (#2560 #2534 #2447).
  • Proxy/ingress: migrate maintenance-only server-proxy options to ingress; legacy hostname ports must be canonical decimals in 1–65535, and --wake-park-budget must be below --wake-max-flight-lifetime (#2548 #2578 #2511).
  • Docker quotas: supplied disk/storage/ephemeral-storage limits must be positive and supported by the storage driver or creation returns 400. Only the writable layer is covered, not bind mounts, volumes, or image layers; Windows retains its existing disk-size behavior (#2716).
  • Docker preflight/startup: correct duplicate, root, colon-containing, or reserved mount destinations and quantities above signed int64; an explicit / host-path allowlist authorizes all POSIX descendants. Expiration-restore failures now prevent startup unless the container was concurrently removed; investigate persistent daemon errors (#2421 #2505 #2751 #2474 #2533).
  • Downloads: detailed APIs remain optional for custom adapters; check 206/isPartial and ranges before appending, and close response bodies. Unknown totals use -1; encoded HTTP lengths/ranges are not decoded progress or resume offsets. Python callers should catch SDK exceptions rather than raw httpx errors (#1597 #2592 #2515 #2525).
  • Timeouts and polling: Python command streams time out after max(request_timeout, 30s) without bytes; raise request_timeout for legitimate silence. MCP pollers must read logs once more after completion and retain opaque cursors; empty output is not completion. Custom Go pool stores must honor cancellation, and incomplete destruction stays fenced for retry (#2527 #2648 #2580).
  • Upload atomicity: use writable containing directories for staged uploads/isolated replacements; existing writable files fall back to non-atomic truncation on staging permission errors. Ordinary /files/replace remains in-place. Staged replacement preserves modes, not xattrs/ACLs/capabilities/SELinux labels; ownership is best effort for ordinary writes and session UID/GID for isolated writes (#2433 #2478).
  • Upload storage: hardlinks/open readers retain the old inode, multipart overwrites may need roughly three times the file size, and interrupted writers can leave staging files. Avoid reserved .osb-upload-/.osb-staging- names, especially a prefix plus 16 hex digits; rename existing collisions directly. Special-file targets are rejected, while bind-mounted/open files can prevent rename; directory sync is best effort (#2433 #2478).
  • Session lifecycle: isolated foreground stdin is now /dev/null; use files or here-documents. Bash-session deletion terminates all overlapping runs; PTY close adds SIGHUP and up to 500 ms before group kill, while nohup/HUP-ignoring jobs can survive (#2517 #2731 #2733).
  • Jupyter/JVM: custom images need an explicit token or discoverable runtime token files and the requested kernel. Prefer shaded sandbox-api 1.0.18+ over EXECD_SSE_LEGACY_COMPAT, which is off by default and removes structured exit_code values (#2448 #2689 #2472).
  • Controller configuration: cache scope must include all managed namespaces, plus Fast Sandbox template/runtime-environment namespaces; it does not change RBAC or provide tenant isolation. Review controller.podRecovery.*, which now takes effect, and remove obsolete ConfigMaps left by plain-manifest upgrades. Custom election timings require lease > renew > 1.2×retry (#2571 #2581 fast-sandbox#161 #2694 #2651).
  • Exchange deployment: align server/SDK/egress versions; the sidecar live revision runtime does not support exchange. Resolver caller authentication is not implemented—Ed25519/JWKS remains design-only. Use a protected UDS or trusted-egress-only HTTPS with trusted CAs; sandbox allow rules must not expose resolvers, and MITM UID exclusion alone is not isolation (#2501 #2549 #2631 #2547).
  • [EXPERIMENTAL] Strict Actions v2: enable matching OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion values of sandbox.fast.io/actions/v2 only on clean-base direct-Firecracker deployments with durable state, isolated management ports, and manager authorization. Pause/resume, snapshots/restore, live binding removal, owner migration, and same-UID reuse remain unsupported; use terminal deletion/new UIDs, preserve fences, and never treat fencing as authentication or downgrade existing state to v1 (#2441 #2460 #2493 #2546 fast-sandbox#152).
  • [EXPERIMENTAL] Credential-bound interception: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound still denies decrypted application forwarding and must not be enabled in production. With the switch unset, both legacy gates enabled remain a deprecated alias; revision-runtime alone is installation-only. Explicit mode/gate conflicts, empty/unknown values, and setting this switch on sidecar fail startup (#2737 #2797).
  • Experimental startup requirements: credential-bound mode requires transparent MITM, dns+nft, and only default interception ports 80,443; remove insecure TLS verification, chained proxies, and effective ignore_hosts/allow_hosts. Runtime-user config.yaml then config.yml are checked; read/parse errors fail closed. To return to all, unset both legacy gates; sidecar live revision also rejects extra interception ports (#2587 #2797).
  • Port policies: Fast Sandbox supports TCP only, at most 256 ports per rule, and no domain-plus-port combinations; normal updates preserve established flows. dropEstablished is supported only on dns+nft sidecar PATCH/DELETE, ignored by POST, and unsupported in Fast Sandbox, dns-only, live-revision, or chained-proxy-plus-transparent-MITM modes; it installs packet drops, not TCP resets. Removing a port-only allow alone does not trigger established-flow blocking (#2662 #2346).
  • Operator-rule reload: Fast Sandbox reloads runtime-mutable rule files on a one-minute tick; mount ConfigMaps as directories, not subPath, and allow for kubelet projection delay. Image-baked rules still require a new image and recreation. Successful reloads clear DNS-learned leases, so allowed domains need another lookup; failed reloads retain the previous overlay, and established connections are not forcibly terminated (#2727 #2814).
  • Network-security boundaries: domain denies filter DNS, not direct connections to known IPs; use explicit IP/CIDR denies or default-deny policies for those paths. Operator denies override operator allows, so permitted internal services require a deny-range carve-out. Classic Docker/Kubernetes creation injects egress only when networkPolicy is supplied; poolRef plus networkPolicy is unsupported, so configure pooled controls in the template (#2814).
  • ResourceAware rollout: direct-Firecracker resource-admission.json moves from v2 to v3; old/new Fastlets reject the other configuration version, so coordinate controller/Fastlet upgrades per pool. Heartbeats remain v2. Hosts require writable cgroup v2, clone3(CLONE_INTO_CGROUP), and zero effective pool swap; the shared memory ceiling is not per-VM protection or a guarantee of survival across container replacement (#2626 fast-sandbox#162).
  • Restore sizing: ResourceAware pools use template CPU/memory shapes; new snapshots replay source limits, which restore-time caller limits must match. Legacy pools and snapshots without recorded limits retain their prior behavior (#2623 #2628 #2633).
  • [EXPERIMENTAL] RootfsOnly: Full remains the default; explicit RootfsOnly mode is available through Fast Sandbox FastPath/CRDs for reusable OCI snapshots, not pause/resume or OpenSandbox REST/SDK mode selection. New capture requires qualified patched Firecracker 1.17.0 templates, a live guest helper, qualified kernel/OverlayBD backend, exclusive ext4 ownership, and an absolute FAST_SANDBOX_ROOTFS_QUALIFICATION profile with matching digests/storage attestation; custom binary digests do not bypass the version gate. Upgrade runtime, Fastlet/Proxy, builder, and tools together, rebuild qualified templates, and preserve journals/fences. Restore cold-boots and reruns the entrypoint; no application-memory preservation or validated cross-CPU/architecture portability is promised (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189).
  • OverlayBD template builds: guest-control injection and freeze/thaw validation are now mandatory for the OCI builder; FSB_GUEST_CONTROL_ENABLED is no longer an opt-out. Missing/incompatible helpers or failed probes stop the build. Native templates are unchanged; existing OCI templates need rebuilding rather than metadata edits to gain capture capability (#2812 fast-sandbox#183).
  • Fast Sandbox logs: covered Kubernetes components now write rotating files under /var/log/fast-sandbox by default (100 MiB per file, 10 backups, 7-day backup retention, gzip); application logs no longer appear in kubectl logs unless alsoStderr: true is configured. Replace legacy klog output flags with the shared logging YAML, wire ConfigMap/log-volume mounts for chart-managed static workloads, and configure each tenant namespace separately. Configuration is startup-only: use controlled Pool draining/replacement for Fastlets, not deletion of live Pods, and arrange collection before ephemeral logs are lost. Explicit missing/invalid configuration or unwritable output prevents startup; rotation limits are not a hard disk quota and do not cover guest/VM logs (#2812 fast-sandbox#197).
  • OCI checkpoint cache: reserve space for the additional blob cache (defaults: 16 GiB, 4096 files, 1 GiB free-space reserve), separately from OverlayBD's block cache. Keep staging/cache/device state on one filesystem for hard-link reuse; cross-filesystem placement or contention falls back to the registry. Set FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 to disable blob-cache insertion/lookups; active-device pins remain protected, including when budgets shrink (#2812 fast-sandbox#178).
  • ublkd recovery: automatic shared-snapfiles rebuilding applies only when no other Sandbox lease needs the attachment; it is not transparent recovery of running VMs. Remove affected Sandboxes through their normal lifecycle before retrying when other leases remain, rather than manually wiping shared caches (#2812 fast-sandbox#193).
  • Template rebuilds: opt-in runtime.execd_run_as_init needs rebuilt templates; execd remains a subreaper beneath guest PID 1. Free-page reporting also needs rebuilt object-store templates and compatible VMM/kernel support, cannot toggle restored device state, and does not enable OCI reporting or justify higher overcommit; rollback uses an older template (#2494 #2497 #2546 fast-sandbox#114).
  • OCI chart defaults: idle ublk devices are now reserved; set runtime.oci.poolLow=0 for on-demand allocation and match poolSizeGB to rounded-up rootfs capacity. P2P remains enabled by default; custom runtime.config needs separate adjustment for direct-origin delivery (#2594 fast-sandbox#163 #2566).
  • Snapshot integrity: missing commit digests now fail pause while retaining Pods; old snapshots are not repaired. OCI template references must carry a full SHA-256 digest in the expected repository; rebuild invalid references (#2482 #2491).
  • CLI scripts: non-positive request timeouts and empty rule targets are usage errors; osb config init overwrite refusal now exits 1 without changing the file (#2742 #2692 #2743).
  • VM console collection: opt in to vm-console, align hostPaths.vmConsole with the runtime state root, cover every runtime node, and manage file-sink retention (#2234 #2677).
  • Artifact verification: umbrella workflows do not provide blanket signing/provenance coverage; BOM digest matching is not proof of origin, and signature requirements must not be bypassed (#2467).

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.1            # Python
npm install @alibaba-group/opensandbox@1.2.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.1")

go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.1

uvx opensandbox-server==1.2.1
