OpenSandbox-Release-1.2.1-rc.1

Erster Release-Kandidat der 1.2.1-Patchreihe, herausgeschnitten aus release-1.2.0 (27.10.2026). Überschrift: OSEP-0025 Credential Vault Exchange – eine exchange-Anmeldeinformationsquelle mit Header-Auflösung pro Anfrage durch einen steckbaren Resolver, verkabelter End-to-End-Ausgang, Server, alle fünf SDKs, Fast-Sandbox e2e und der Credential Vault-Leitfaden. Ebenfalls bemerkenswert: atomare Execd-Uploads, Digest-Validierung für RootFS-Snapshots, Kubernetes-Erstellungs-Timeout-Startdiagnose und Informer-Cache-Scoping für große Cluster. Die Basislinie für jeden Abschnitt ist release-1.2.0. rc-Releases veröffentlichen Bilder, halten aber Pakete zurück – SDK/CLI-Artefakte werden mit dem stabilen 1.2.1-Bump ausgeliefert.

Highlights

– Credential Vault Exchange (OSEP-0025): Dynamische Header-Auflösung pro Anfrage, ausfallsicher und nie dauerhaft, über den Server und alle fünf SDKs (#2457 #2535 #2534 #2560) – Datensicherheit: Execd-Uploads werden atomar ersetzt, sodass bei einem fehlgeschlagenen Schreibvorgang die alte Datei erhalten bleibt (#2433); Der Controller lehnt RootFS-Snapshots ab, deren Commit-Ergebnis keine Digests enthält (#2482)

  • Bedienbarkeit: Zeitüberschreitungen erstellen, die den Grund für den Pod-Startfehler melden (#2434); Controller und FSB-Controller gewinnen --namespaces-Cache-Scoping (#2571 #2581)

Server

– Die Sandbox-Liste verschiebt Metadaten-Gleichheitsfilter in den Label-Selektor Kubernetes, sodass große Namespaces nicht mehr jede Arbeitslast vor dem Filtern materialisieren (#2559)

  • OCI-Härtung der Vorlage: Die Syntax des Veröffentlichungs-Repositorys wird beim Erstellen validiert, und die Sandbox-Erstellung erfordert eine an den Digest angeheftete Veröffentlichungsreferenz – eine erfolgreiche Vorlage kann nicht mehr in ein veränderbares oder nicht verwandtes Manifest aufgelöst werden (#2491) – Kubernetes erstellt Zeitüberschreitungen und hängt vor dem Rollback den Grund für den Pod-Startfehler (nicht planbar, ImagePullBackOff, Warnereignisse) an – Image-Pull- und Planungsfehler können erneut über API diagnostiziert werden (#2434) – Docker: Durch das gleichzeitige Entfernen eines Containers wird die Wiederherstellung des Startablaufs nicht mehr abgebrochen, und verbleibende Docker-Fehler schlagen beim Start fehl, anstatt dass Timer stillschweigend gelöscht werden (#2533); Duplikat-, Root- und Server-Mount-kollidierende Ziele werden vor der Bereitstellung mit 400 abgelehnt (#2421 #2505)
  • Ein expliziter POSIX-Root in storage.allowed_host_paths deckt jetzt seine Nachkommen ab; Die Nachkommenprüfung ergab // und ergab nie eine Übereinstimmung (#2474) – Proxy: Ein GET, das einen Text deklariert, wird mit weitergeleitet, sodass Anfragen im Elasticsearch-Stil mit 500 nicht mehr fehlschlagen (#2518); Pool-Erschöpfung gibt 503 PROXY_POOL_EXHAUSTED statt einer 180-sekündigen Wartezeit zurück, die mit 500 endet (#2519) – Kleinere Korrekturen: metadata=env= filtert nach dem leeren Wert, anstatt alles abzugleichen (#2461); Gateway-, Bucket-Name- und Env-Name-Validatoren lehnen nachfolgende Zeilenumbrüche ab (#2499)

SDKs

Exchange-Anmeldeinformations-Vault-Nutzlasten (exchange-Quelle + typlose Bindungsauthentifizierung) werden in allen fünf SDKs akzeptiert, abgestimmt auf den Server- und Ausgangsleitungsvertrag (#2534 #2560); Weitere Informationen finden Sie im Kotlin/C#-ABI-Hinweis unter Upgrade und Kompatibilität. Detaillierte Download-Methoden stellen Antwortmetadaten (Status, Content-Range, isPartial) in allen fünf Sprachen bereit; Vorhandene Signaturen bleiben unverändert, benutzerdefinierte Dateisystemimplementierungen müssen sie hinzufügen (#1597)

Python

– SSE-Befehlsströme erhalten ein Lese-Timeout: commands.run() löst SandboxTimeoutException nach max(request_timeout, 30s) der Stille aus, anstatt bei einer blockierten Ausführung für immer zu blockieren (#2527) – Durch das ordnungsgemäße Herunterfahren des asynchronen Pools werden ausstehende Kills abgelassen, anstatt sie abzubrechen und nicht verfolgte Sandboxen bis TTL zu belassen (#2507) – Download-Streams geben die HTTP-Antwort frei, wenn sie gelöscht, vorzeitig geschlossen oder mitten in der Iteration abgebrochen werden – keine Erschöpfung des Verbindungspools mehr (#2487 #2531) – Transportfehler während Stream-Anfragen und Body-Lesevorgängen lösen SDK-Ausnahmen aus, anstatt rohe httpx-Fehler zu verlieren (#2515 #2525) – Kleinere Korrekturen: Endpunkt-Cache-Ungültigmachung beschränkt auf den Inflight-Schlüssel (#2409); NetworkPolicyAdapter verbreitet Umleitungsoptionen und Ereignis-Hooks (#2553); Der MCP-Server meldet SDK-Fehler anstelle einer generischen Nachricht (#2524)

JavaScript

– Anfragen für isolierte Sitzungen lösen SandboxApiException mit Status/Anfrage-ID/Fehlercode anstelle eines flachen Error aus (#2466) – Eine unendliche oder negative Umleitungsfrist wird als keine behandelt – requestTimeoutSeconds: Infinity schlägt nicht mehr bei jeder authentifizierten Anfrage fehl (#2488) – Das Schließen eines Download-Streams innerhalb seiner eigenen Schleife beendet die Iteration sauber, anstatt ein TypeError auszulösen (#2514)

Kotlin

  • Befehls-Timeouts im Submillisekundenbereich werden auf 1 ms aufgerundet; 500 µs, zuvor serialisiert als 0, was von exec als unbegrenzt behandelt wird (#2537)

C#

Abgedeckt durch die Cross-SDK-Austauschmodelle (#2560).

Los

– Wiederholungs-/Timeout-Härtung: Die Retry-After-Sättigung und die 60-Sekunden-Obergrenze gelten jetzt für den generischen Wiederholungspfad (#2452 #2508); Backoff sättigt, anstatt negativ zu umbrechen (#2509); ReadyTimeout wird bei längeren Anruferfristen erzwungen (#2528); Interpreter-Bereitschaftsprüfungen sind termingebunden und erfordern einen bestätigten Null-Exit (#2504 #2480); Telemetrie-POSTs erhalten ihre eigene Fünf-Sekunden-Grenze (#2540) – Endpunkt-Cache: In-Flight-Abrufe werden durch Invalidierung abgeschirmt (#2503); Lebenszyklusmutationen machen zwischengespeicherte Endpunkte ungültig (#2564); der letzte Kellner, der geht, bricht den gemeinsamen Abruf ab (#2579); Konfigurations-/Endpunkt-Header werden ohne Berücksichtigung der Groß-/Kleinschreibung zusammengeführt (#2529) – Pool: Leerlauf-FIFO überlebt Entfernen/Neueinfügen (#2453); Shutdown-Kellner berücksichtigen Anruferabsage (#2542); Destroy begrenzt die Entleerung des staatlichen Speichers (#2580)

  • Execution.Text() verkettet Codefragmente ohne Trennzeichen, sodass "Loading" + "...done\n" keinen Zeilenumbruch mehr erhalten; Befehlsformatierung unverändert (#2447) – Kleinere Korrekturen: SSE-Parser akzeptiert CR-getrennte Ereignisse (#2439); Mehrteilige Uploads behalten ihre generierte Grenze (#2468); Eine unzuverlässige Diagnoseaussage prüft net.Error.Timeout() (#2479)

Controller

– Rootfs-Snapshot-Commits, deren Ergebnis keine Digests enthält, schlagen jetzt fehl (CommitResultUnavailable/CommitResultIncomplete) und melden PauseFailed mit beibehaltenen Pods – zuvor wurde bei der Pause ein Erfolg gemeldet, die Pods wurden gelöscht und jedes spätere Fortsetzen schlug dauerhaft fehl (#2482) – --namespaces begrenzt den Informer-Cache und behebt Start-OOM auf großen gemeinsam genutzten Clustern; Der leere Standardwert behält die Semantik des vollständigen Clusters bei. Diagrammwert controller.namespaces (#2571)

Execd

– Uploads sind atomar: temporäre temporäre Datei + Umbenennen, Beibehaltung von Modus/Eigentümer und folgenden Symlinks – ein fehlgeschlagener Upload (ENOSPC, E/A-Fehler, Kill) zerstört die ersetzte Datei nicht mehr (#2433) – Das Jupyter-Token wird aus dem jpserver-*.json des Code-Interpreter-Images erkannt, wenn JUPYTER_TOKEN nicht festgelegt ist; explizite Konfiguration gewinnt (#2448) – Die Jupyter-Startwartezeit wird auf ~5 Minuten wiederhergestellt – eine Backoff-Cap-Interaktion wurde nach ~11 s gegen kalte Bilder abgebrochen (#2486) – EXECD_SSE_LEGACY_COMPAT (standardmäßig deaktiviert) lässt exit_code aus SSE-Ereignissen für SDKs vor 1.0.18 aus, deren Kotlinx-Laufzeit auf dem unbekannten Schlüssel abstürzt (#2472) – filename* ist mit RFC 8187-Attributzeichen codiert, daher werden Namen mit =, :, ' in strengen clients analysiert (#2516)

Vernetzung

Ausgang

– Credential Vault Exchange (OSEP-0025): exchange-Quelle (UDS/HTTPS-Resolver-Endpunkt), typlose Bindungsauthentifizierung, Nur-Marker-Snapshot-Bindungen, ein POST /credential-vault/_resolve-Endpunkt und Add-on-Integration, die aufgelöste Header mit Fail-Closed 407/Stream-Kill einfügt – aufgelöstes Material wird niemals beibehalten, zwischengespeichert oder zurückgelesen; Nur Inline-Tresore unverändert (#2457 #2495 #2501 #2500 #2535 #2538); Sidecar-Profil durchgängig mit Fast-Sandbox e2e integriert (#2549 #2547 #2561); Leitfadenkapitel hinzugefügt (#2563) – Die Authentifizierung des Resolver-Aufrufers wird zurückgestellt (D5): https://-Resolver-Endpunkte müssen als aktuelle trust-Grenze nur für ausgehenden Verkehr erreichbar sein (UDS-Berechtigungen oder netzwerkbezogene NFT-Regeln) (#2549)

  • OSEP-0023-Grundarbeiten werden fortgesetzt [EXPERIMENTELL]: Sicherer Vault v2-Leser (#2441), strikte Legacy-Verwaltung mit Eigentümerabgrenzung (#2460), Vault v2-Writer im strengen Modus mit Serveraufrufer (#2493) – Standardeinstellungen bleiben v1; Der strikte Modus erfordert den gepaarten Fast-Sandbox-Produzenten – Ein wiederholter data-plane-ready-Hook ist idempotent (200) anstelle eines falschen 409 (#2510)

Eingang

  • Startvalidierung: --wake-park-budget muss unter --wake-max-flight-lifetime liegen; Die Fehlkonfiguration beantwortete zuvor geparkte Anfragen mit 400 oder leeren 200 statt 503 + Retry-After (#2511) – Eine in der Warteschlange befindliche Weckanfrage ist durch ein Parkbudget begrenzt, statt durch fast zwei (#2513) – Kleinere Korrekturen: Der endgültige Status wird nach einer 1xx-Antwort aufgezeichnet, sodass 103 Early Hints nicht mehr als Anforderungsstatus maskiert wird (#2484); Legacy-Host-Route-Ports werden validiert (sb-70000 nicht mehr 502s, sb-08080 erreicht Port 8080 nicht mehr) (#2578); ein reiner Testdatenwettlauf behoben (#2512)

Schnelle Sandbox

– Checkpoint-Ketten bleiben begrenzt: Checkpoint-Layer-Ketten zum Anhalten/Wiederherstellen werden während des Commits durch Overlaybd-Merge gequetscht, sodass wiederholte Zyklen die Wiederherstellungskette nicht mehr unbegrenzt vergrößern (#2546 fast-sandbox#158)

  • Knotenlokale VM-Erkennung: Die Firecracker-Laufzeit schreibt einen einmal beschreibbaren fast-sandbox.json-Datensatz pro VM – vollständige Sandbox-UID, Namespace, Name, Platzierung – neben dem Prozessprotokoll, sodass knotenlokale Agenten lokale VMs durch Verzeichnisscan erkennen, anstatt Sandbox-CRs Cluster-weit zu überwachen; Die Veröffentlichung blockiert niemals die Bereitstellung und beim Teardown wird der Datensatz entfernt (#2546 fast-sandbox#154) – Speicher: Opt-in-Gastspeicherrückgewinnung mit druckbasierter Zulassung und standardmäßig aktivierter Free-Page-Berichterstellung in integrierten Vorlagen (#2546 fast-sandbox#114) – Fastlet-Härtung: der strikt verwaltete Actions v2-Transport (Produzentenhälfte des Egress-Strict-Management-Receivers dieser Version), Fehlerbehebungen für Besitzerrückzug, Terminal-Fence-Erhaltung bei fehlendem Inventar und parallelisierte Zulassungsprüfungen (#2546 fast-sandbox#152)
  • FSB-Controller: --namespaces legt den Gültigkeitsbereich des Informer-Cache fest (verweigert den Start, wenn der Satz den Namespace der Laufzeitumgebung verfehlt) und --kube-client-qps/--kube-client-burst optimieren den gemeinsam genutzten API-Server. client-Ratenbegrenzer – Opt-in-Diagrammwerte controller.namespaces/controller.kubeClientQPS/controller.kubeClientBurst, Standardwerte rendern keine neuen Flags (#2581 fast-sandbox#161) – Init-Topologie: runtime.execd_run_as_init backt jetzt EXECD_INIT=1 in fsb-Golden-Image-Template-Envs – wurde zuvor auf fsb ignoriert, daher übernahm exec nie die OSEP-0018-Init-Rolle; der injizierte Wert gewinnt über einen von client bereitgestellten Schlüssel (#2494); Die Integrationsumgebung pinnen die vollständige In-Guest-Topologie an und die gesamte E2E-Oberfläche legt sie standardmäßig fest (#2497)
  • Integrationsumgebung: Overlaybd-Vorlagen-Builds prüfen den ublk-Add/Del-Pfad im Vorhinein und reparieren verkeilte Kernel-Geräte selbst, anstatt etwa 16 Minuten nach Beginn eines zum Scheitern verurteilten Builds auszufallen, und Teardown gibt verwaiste Geräte frei (#2454); Smoke-Behauptungen zeigen echte NFT-Fehler auf, anstatt sie als fehlende Regeln zu lesen (#2543); eine vollständige Exchange-Resolver-Überprüfungsphase (Server-Relay → Egress _resolve → vom Gast beobachtete injizierte Header) fährt verify-native/verify-overlaybd (#2561)

Sonstiges

– CLI: Text wird maskiert, statt als Rich-Markup analysiert – Pfade wie /tmp/notes[draft].txt werden korrekt gedruckt und schlagen bei erfolgreichen Befehlen nicht mehr fehl (#2520); Defekte Konfigurationsdateien melden sauber, anstatt jeden Befehl zum Absturz zu bringen (#2521); config set speichert Zeichenfolgenschlüsselwerte wörtlich (007123 bleibt 007123) (#2522); Die PTY-Sitzung wird gelöscht, wenn der WebSocket nie geöffnet wird (#2523) – Node-Agent: Ein Protokollstream, dessen Verzeichnis nie angezeigt wurde, wird nach dem Aufbewahrungsfenster vergessen, anstatt für immer bestehen zu bleiben (#2471) – Dokumente: Bildsignierungsansprüche im Einklang mit der tatsächlichen Workflow-Abdeckung (#2467); AAIF-Charta und Governance-Konsolidierung – Kodexbeiträge erfordern jetzt die Genehmigung durch den DCO (#2490); Beispielsatz für S3-Vorlagen format: native (#2506); OSEP-0025 Status- und Vertragspins (#2539)

  • Housekeeping: toter Code modulübergreifend entfernt (#2496); execd CI mountet Tracefs für den eBPF-Rauch (#2473)

Upgrade und Kompatibilität

– Kotlin/C# SDKs sind quellkompatibel, aber nicht ABI-kompatibel mit 1.2.0 – neu kompilieren; keine Kabeländerungen (#2560) – Python: Stille SSE-Streams lösen jetzt SandboxTimeoutException nach max(request_timeout, 30s) aus (#2527); Download-Body-Fehler lösen SDK-Ausnahmen anstelle von rohen httpx-Fehlern aus (#2525)

  • Go: Execution.Text() fügt keine Trennzeichen mehr zwischen Codefragmenten ein (#2447); Nicht leere positionelle Execution{...}-Literale werden nicht mehr kompiliert – verwenden Sie verschlüsselte Literale – Ausgeführte atomare Uploads: beschreibbare Datei in nicht beschreibbarem Verzeichnis wird abgelehnt, Geräte-/FIFO-Ziele werden abgelehnt, xattrs/ACLs/setgid-Bits werden nicht übertragen, per Bind gemountete Ziele schlagen fehl (EBUSY), ein SIGKILL während des Uploads kann eine .osb-upload-*-Staging-Datei hinterlassen, maximale Festplattengröße beträgt das Dreifache der Dateigröße (#2433) – Serverstart: Ein Docker-Fehler während der Wiederherstellung nach Ablauf (mit Ausnahme der gleichzeitigen Entfernung) verhindert jetzt den Start – unter einem Neustart-Supervisor ausführen (#2533) – Ingress: --wake-park-budget unter --wake-max-flight-lifetime wird jetzt beim Start erzwungen; Standardeinstellungen bleiben davon unberührt (#2511)
  • Vorlagenliste: metadata=env= filtert jetzt nach dem leeren Wert (#2461) – OSEP-0025: Austausch ist additiv und Opt-in, aber die Authentifizierung des Resolver-Aufrufers wird zurückgestellt – https://-Resolver-Endpunkte müssen nur ausgehenden Verkehr erreichbar sein (#2549 #2563)
  • Fast Sandbox: Kostenlose Seitenberichte standardmäßig aktiviert; fast-sandbox.json-Eintrag pro VM; controller.namespaces muss Pools/Sandboxen und den Namespace der Laufzeitumgebung abdecken, sonst weigert sich der Controller zu starten (#2546 #2581)
  • Bilder: opensandbox/<component>:release-1.2.1-rc.1 (alle drei Register; FSB-Bilder für Fast-Sandbox) – Pakete: unverändert – SDK/CLI-Artefakte werden in der stabilen Version 1.2.1 veröffentlicht

  • Kubernetes: unterstützter Bereich v1.21 – v1.34
  • Skew: Server ↔ CLI/SDK gleiche Leitung unterstützt; ±1 geringfügige Warnung

OpenSandbox release-1.2.1-rc.1

First release candidate on the 1.2.1 patch line, cut from release-1.2.0 (2026-10-27). Headline: OSEP-0025 Credential Vault Exchange — an exchange credential source with per-request header resolution through a pluggable resolver, wired end to end across egress, server, all five SDKs, fast-sandbox e2e, and the Credential Vault guide. Also notable: execd atomic uploads, digest validation for rootfs snapshots, Kubernetes create-timeout startup diagnostics, and informer-cache scoping for large clusters. Baseline for every section is release-1.2.0. rc releases publish images but hold packages — SDK/CLI artifacts ship at the 1.2.1 stable bump.

Highlights

  • Credential Vault Exchange (OSEP-0025): per-request dynamic header resolution, fail-closed and never persisted, across server and all five SDKs (#2457 #2535 #2534 #2560)
  • Data-safety: execd uploads replace atomically so a failed write keeps the old file (#2433); the controller refuses rootfs snapshots whose commit result lacks digests (#2482)
  • Operability: create timeouts report the pod startup failure reason (#2434); controller and fsb controller gain --namespaces cache scoping (#2571 #2581)

Server

  • Sandbox list pushes metadata equality filters into the Kubernetes label selector, so large namespaces no longer materialize every workload before filtering (#2559)
  • Template OCI hardening: publish repository syntax is validated at create, and sandbox creation requires a digest-pinned publish reference — a succeeded template can no longer resolve to a mutable or unrelated manifest (#2491)
  • Kubernetes create timeouts append the pod startup failure reason (unschedulable, ImagePullBackOff, warning events) before rollback — image pull and scheduling failures are diagnosable through the API again (#2434)
  • Docker: a concurrent container removal no longer aborts the startup expiration restore, and remaining Docker errors fail startup instead of silently dropping timers (#2533); duplicate, root, and server-mount-clashing destinations are rejected with 400 before provisioning (#2421 #2505)
  • An explicit POSIX root in storage.allowed_host_paths now covers its descendants; the descendant check produced // and never matched (#2474)
  • Proxy: a GET that declares a body is forwarded with it, so Elasticsearch-style requests stop failing with 500 (#2518); pool exhaustion returns 503 PROXY_POOL_EXHAUSTED instead of a 180-second wait ending in 500 (#2519)
  • Smaller fixes: metadata=env= filters on the empty value instead of matching everything (#2461); gateway, bucket-name, and env-name validators reject trailing newlines (#2499)

SDKs

Exchange credential vault payloads (exchange source + typeless binding auth) are accepted across all five SDKs, aligned with the server and egress wire contract (#2534 #2560); see the Kotlin/C# ABI note in Upgrade & Compatibility. Detailed download methods expose response metadata (status, Content-Range, isPartial) in all five languages; existing signatures unchanged, custom filesystem implementations must add them (#1597)

Python

  • SSE command streams get a read timeout: commands.run() raises SandboxTimeoutException after max(request_timeout, 30s) of silence instead of blocking forever on a stalled execd (#2527)
  • Async pool graceful shutdown drains pending kills instead of cancelling them and leaving untracked sandboxes until TTL (#2507)
  • Download streams release the HTTP response when dropped, closed early, or abandoned mid-iteration — no more connection-pool exhaustion (#2487 #2531)
  • Transport errors during stream requests and body reads raise SDK exceptions instead of leaking raw httpx errors (#2515 #2525)
  • Smaller fixes: endpoint cache invalidation scoped to the inflight key (#2409); NetworkPolicyAdapter propagates redirect options and event hooks (#2553); the MCP server reports SDK errors instead of a generic message (#2524)

JavaScript

  • Isolated-session requests throw SandboxApiException with status/request id/error code instead of a flat Error (#2466)
  • An infinite or negative redirect deadline is treated as none — requestTimeoutSeconds: Infinity no longer fails every authenticated request (#2488)
  • Closing a download stream inside its own loop ends iteration cleanly instead of throwing a TypeError (#2514)

Kotlin

  • Sub-millisecond command timeouts round up to 1 ms; 500 µs previously serialized as 0, which execd treats as unbounded (#2537)

C#

Covered by the cross-SDK exchange models (#2560).

Go

  • Retry/timeout hardening: Retry-After saturation and the 60 s cap now apply on the generic retry path (#2452 #2508); backoff saturates instead of wrapping negative (#2509); ReadyTimeout is enforced under longer caller deadlines (#2528); interpreter readiness probes are deadline-bounded and require a confirmed zero exit (#2504 #2480); telemetry POSTs get their own five-second bound (#2540)
  • Endpoint cache: in-flight fetches fenced across invalidation (#2503); lifecycle mutations invalidate cached endpoints (#2564); the last waiter leaving cancels the shared fetch (#2579); config/endpoint headers merge case-insensitively (#2529)
  • Pool: idle FIFO survives remove/reinsert (#2453); shutdown waiters honor caller cancellation (#2542); Destroy bounds state-store draining (#2580)
  • Execution.Text() concatenates code fragments without separators, so "Loading" + "...done\n" no longer gains a newline; command formatting unchanged (#2447)
  • Smaller fixes: SSE parser accepts CR-delimited events (#2439); multipart uploads keep their generated boundary (#2468); a flaky diagnostic assertion checks net.Error.Timeout() (#2479)

Controller

  • Rootfs snapshot commits whose result lacks digests now fail (CommitResultUnavailable/CommitResultIncomplete) and report PauseFailed with pods kept — previously pause reported success, deleted the pods, and every later resume failed permanently (#2482)
  • --namespaces scopes the informer cache, fixing startup OOM on large shared clusters; empty default keeps full-cluster semantics; chart value controller.namespaces (#2571)

Execd

  • Uploads are atomic: staged temp file + rename, preserving mode/owner and following symlinks — a failed upload (ENOSPC, I/O error, kill) no longer destroys the replaced file (#2433)
  • The Jupyter token is discovered from the code-interpreter image's jpserver-*.json when JUPYTER_TOKEN is unset; explicit config wins (#2448)
  • The Jupyter startup wait is restored to ~5 minutes — a backoff Cap interaction had aborted after ~11 s against cold images (#2486)
  • EXECD_SSE_LEGACY_COMPAT (default off) omits exit_code from SSE events for pre-1.0.18 SDKs whose kotlinx runtime crashes on the unknown key (#2472)
  • filename* is encoded with RFC 8187 attr-chars, so names with =, :, ' parse in strict clients (#2516)

Networking

egress

  • Credential Vault Exchange (OSEP-0025): exchange source (UDS/HTTPS resolver endpoint), typeless binding auth, marker-only snapshot bindings, a POST /credential-vault/_resolve endpoint, and addon integration injecting resolved headers with fail-closed 407/stream-kill — resolved material is never persisted, cached, or read back; inline-only vaults unchanged (#2457 #2495 #2501 #2500 #2535 #2538); sidecar profile integrated end to end with fast-sandbox e2e (#2549 #2547 #2561); guide chapter added (#2563)
  • Resolver caller auth is deferred (D5): https:// resolver endpoints must be egress-only reachable (UDS permissions or network-scoped nft rules) as the current trust boundary (#2549)
  • OSEP-0023 groundwork continues [EXPERIMENTAL]: Vault v2 safe reader (#2441), strict legacy management with owner fencing (#2460), strict-mode Vault v2 writer with server caller (#2493) — defaults remain v1; strict mode requires the paired fast-sandbox producer
  • A replayed data-plane-ready hook is idempotent (200) instead of a spurious 409 (#2510)

ingress

  • Startup validation: --wake-park-budget must be below --wake-max-flight-lifetime; the misconfiguration previously answered parked requests with 400 or empty 200 instead of 503 + Retry-After (#2511)
  • A queued wake request is bounded by one park budget instead of nearly two (#2513)
  • Smaller fixes: the final status is recorded after a 1xx response, so 103 Early Hints no longer masquerades as the request status (#2484); legacy host-route ports are validated (sb-70000 no longer 502s, sb-08080 no longer reaches port 8080) (#2578); a test-only data race fixed (#2512)

Fast Sandbox

  • Checkpoint chains stay bounded: pause/restore checkpoint layer chains are squashed through overlaybd-merge during commit, so repeated cycles no longer grow the restore chain without limit (#2546 fast-sandbox#158)
  • Node-local VM discovery: the firecracker runtime writes a write-once fast-sandbox.json record per VM — full sandbox UID, namespace, name, placement — next to the process log, so node-local agents discover local VMs by directory scan instead of watching Sandbox CRs cluster-wide; publication never blocks provisioning and teardown removes the record (#2546 fast-sandbox#154)
  • Memory: opt-in guest memory reclamation with pressure-based admission, and free-page reporting enabled by default in built templates (#2546 fast-sandbox#114)
  • Fastlet hardening: the strict managed Actions v2 transport (producer half of this release's egress strict-management receiver), owner-retirement race fixes, terminal-fence preservation across absent inventory, and parallelized admission probes (#2546 fast-sandbox#152)
  • fsb controller: --namespaces scopes the informer cache (refuses to start when the set misses the runtime-environment namespace) and --kube-client-qps/--kube-client-burst tune the shared API-server client rate limiter — opt-in chart values controller.namespaces/controller.kubeClientQPS/controller.kubeClientBurst, defaults render no new flags (#2581 fast-sandbox#161)
  • Init topology: runtime.execd_run_as_init now bakes EXECD_INIT=1 into fsb golden-image template envs — previously ignored on fsb, so execd never took the OSEP-0018 init role; the injected value wins over a client-provided key (#2494); the integration environment pins the full in-guest topology and the whole e2e surface defaults it on (#2497)
  • Integration environment: overlaybd template builds probe the ublk add/del path up front and self-heal wedged kernel devices instead of failing ~16 minutes into a doomed build, and teardown releases orphan devices (#2454); smoke assertions surface real nft errors instead of reading them as missing rules (#2543); a full-chain exchange-resolver verify stage (server relay → egress _resolve → injected headers observed by the guest) rides verify-native/verify-overlaybd (#2561)

Misc

  • CLI: text is escaped instead of parsed as Rich markup — paths like /tmp/notes[draft].txt print correctly and no longer fail successful commands (#2520); broken config files report cleanly instead of crashing every command (#2521); config set stores string-key values verbatim (007123 stays 007123) (#2522); the PTY session is deleted when the WebSocket never opens (#2523)
  • node-agent: a log stream whose directory never appeared is forgotten after the retention window instead of persisting forever (#2471)
  • Docs: image-signing claims aligned with actual workflow coverage (#2467); AAIF charter and governance consolidation — code contributions now require DCO sign-offs (#2490); S3 template examples set format: native (#2506); OSEP-0025 status and contract pins (#2539)
  • Housekeeping: dead code removed across modules (#2496); execd CI mounts tracefs for the eBPF smoke (#2473)

Upgrade & Compatibility

  • Kotlin/C# SDKs are source-compatible but not ABI-compatible with 1.2.0 — recompile; no wire changes (#2560)
  • Python: silent SSE streams now raise SandboxTimeoutException after max(request_timeout, 30s) (#2527); download-body errors raise SDK exceptions instead of raw httpx errors (#2525)
  • Go: Execution.Text() no longer inserts separators between code fragments (#2447); nonempty positional Execution{...} literals no longer compile — use keyed literals
  • Execd atomic uploads: writable file in non-writable directory is rejected, device/FIFO destinations refused, xattrs/ACLs/setgid bits not carried, bind-mounted destinations fail (EBUSY), a SIGKILL mid-upload can leave a .osb-upload-* staging file, peak disk ~3× file size (#2433)
  • Server startup: a Docker error during expiration restore (other than concurrent removal) now prevents startup — run under a restarting supervisor (#2533)
  • Ingress: --wake-park-budget below --wake-max-flight-lifetime is now enforced at startup; defaults unaffected (#2511)
  • Template list: metadata=env= now filters on the empty value (#2461)
  • OSEP-0025: exchange is additive and opt-in, but resolver caller auth is deferred — https:// resolver endpoints must be egress-only reachable (#2549 #2563)
  • Fast Sandbox: free-page reporting on by default; per-VM fast-sandbox.json record; controller.namespaces must cover pools/sandboxes and the runtime-environment namespace or the controller refuses to start (#2546 #2581)
  • Images: opensandbox/<component>:release-1.2.1-rc.1 (all three registries; fsb images for fast-sandbox)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.1 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns
