OpenSandbox-Release-1.2.0-rc.1

Erster Release Candidate der 1.2.0-Reihe, der alles seit release-1.1.1 zusammengeführt hat – die Überschrift lautet OSEP-0024: Auto-Pause und Wake-on-Access für schnelle Sandboxes, End-to-End-Landung. Bilder jetzt veröffentlichen; SDK/CLI-Pakete werden mit der stabilen Beule 1.2.0 versendet. Bitte testen und melden Sie Probleme.

Highlights

– Auto-Pause und Wake-on-Access für schnelle Sandboxes (OSEP-0024) landen durchgehend: Ingress-Aktivitätsverfolgung und Wake-Pfad, serverseitiger Leerlauf-Sweeper, Opt-in-lifecycle.idlePolicy-Erstellungsfeld und Wake-Retry-Vertrag in allen fünf SDKs – standardmäßig deaktiviert, nur additiv (#2156 #2180 #2192 #2198 #2218) – Egress-Sidecar (experimentell, Opt-in): Live-Zugang zum Vault mit anmeldeinformationengebundenem Zugriff, HTTP/2-Unterstützung mit begrenztem Drain, atomare Richtliniendateipersistenz und Eindämmung von Laufzeitfehlern (#2176 #2201 #2182 #2162 #2172)

  • SDK-Zuverlässigkeit: Datei-Uploads und -Downloads werden in keinem der fünf SDKs mehr nach dem 30-Sekunden-Anfrage-Timeout abgebrochen; execd meldet jetzt Sandbox-bezogene CPU-/Speicher- und OOM-Kills (#2165 #2186 #2196 #2206 #2191 #2200)

Server

  • Implementieren Sie die serverseitige automatische Pause von OSEP-0024 für schnelle Sandboxen: Das Lebenszyklus-Erstellungsfeld lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) wird mit pydantischen Grenzen validiert und bleibt als reservierte sandbox.opensandbox.io/idle-policy-Sandbox-CR-Annotation bestehen (Annotations-Schreibfehler bleibt ausfallsicher – die Sandbox wird ohne Richtlinien erstellt); ein Leerlauf-Sweeper zählt die aktivierten FSB-Sandboxen aus dem Informer-Cache auf, prüft die Aktivität in Redis (monotonische maximale Schreibvorgänge, Tombstones mit fehlenden Schlüsseln können eine Pause nur verzögern), nimmt eine Pausensperre pro Sandbox mit erneuter Überprüfung unter Sperre vor und gibt einen idempotenten FastPath PauseSandbox aus; ein deklariertes activeProbe wird über das Eingangs-Gateway ausgeführt und eine Besetzt-Antwort zeichnet normale Aktivitäten auf; Ein OpenSandbox-Skip-Activity: skip-Sentinel unterdrückt die Beobachtung für eine Anfrage und wird sowohl bei Gateway- als auch bei Server-Proxy-Hops entfernt (#2192 #2181) – Konfigurieren Sie die Leerlaufpause unter dem Dach der neuen Lebenszyklusautomatisierung: [idle_pause] wird zu [automation.idle_pause] und das redundante redis.enabled-Gate wird entfernt – redis.dsn ist erforderlich (beim Laden validiert), wenn enabled = true lautstark ausfällt, anstatt lautlos den Sweeper nicht zu starten; configuration.md wurde aus Gründen der Übersichtlichkeit neu geschrieben und dokumentiert nun ingress.secure_access und die fehlenden Env-Var-Überschreibungen (#2215)
  • Standardmäßige BatchSandbox-Pods auf restartPolicy: Never: Durch einen direkten Kubelet-Container-Neustart wurde der Hauptcontainer aus seinem Image neu erstellt – wobei die beschreibbare Ebene und der In-Memory-Status gelöscht wurden – während die Sandbox weiterhin Succeed meldete; Ein Neustart ist für eine Sandbox nie eine sinnvolle Wiederherstellung, daher ist die ehrliche Standardeinstellung kein Neustart, wodurch auch der Terminalfehlerpfad des Controllers erreichbar ist. Ein expliziter restartPolicy in der Vorlage gewinnt immer noch, das Windows-Profil erzwingt weiterhin Always (die mehrphasige Installation ist darauf angewiesen) und der Poolmodus bleibt unverändert (#2128) – Behandeln Sie pasta/slirp4netns/none als Container-Laufzeit-Netzwerkmodi und leiten Sie sie direkt durch, wodurch Podmans Netzwerk auf Kernelebene auswählbar wird – unter Windows 11 + WSL2, wo Netavark den Bridge-Modus unterbricht, war pasta das einzige funktionierende Netzwerk und scheiterte zuvor beim Erstellen mit einem 400, bei dem nach einem benutzerdefinierten Docker-Netzwerk gefragt wurde; networkPolicy wird jetzt für diese Modi abgelehnt, da es keine Brücke gibt, an die der Egress-Sidecar angeschlossen werden kann (zuvor wurde stillschweigend für none akzeptiert) (#2203)
  • Analysieren Sie Docker-Zeitstempel, deren Sekundenbruchteile nicht aus 3 oder 6 Ziffern bestehen: Docker schreibt RFC3339Nano (nachgestellte Nullen entfernt), Python 3.10s fromisoformat lehnt 5-stellige Brüche ab, und der Helfer ist auf datetime.now() zurückgefallen – daher haben createdAt und status.lastTransitionAt stillschweigend berichtet die aktuelle Uhrzeit; Der Bruch wird jetzt mit Nullen auf 6 Ziffern aufgefüllt (#2220)

SDKs

Die folgenden Codeänderungen gelten für die stabile Version 1.2.0 – rc liefert keine SDK-Pakete aus. – Fügen Sie den OSEP-0024 SDK-Vertrag zu allen fünf Sprachen hinzu: ein typisiertes lifecycle.idlePolicy-Erstellungsfeld (IdlePolicy/ActivityProbe-Modelle mit client-seitiger Fail-Fast-Validierung, die den Server spiegelt: Zeitüberschreitung 30–86400 s, onIdle: "pause"-Paarung, Prüfpfad-/Zeitüberschreitungsgrenzen; sowohl über Standard- als auch über Vorlagenerstellung verkabelt) und den Wake-Retry-Vertrag – aktiviert ein 503, der den Gateway-eigenen OpenSandbox-Wake: expired-Marker trägt (sein Vorhandensein beweist, dass die Anfrage geparkt und nie weitergeleitet wurde, wodurch Wiederholungsversuche bei jeder Methode sicher sind), der SDK sendet erneut nach Retry-After unter einem begrenzten Budget (Standard 5 Versuche/60 s, pro client-Regler), Erschöpfung löst eine typisierte Wake-Timeout-Ausnahme aus, die Versuche und Wartezeit auf der Serverseite überträgt Die Wiederaufnahme wird nie abgebrochen, die bloße 503-Verarbeitung bleibt unverändert und SSE/Streaming-Transporte umgehen den Aktivierungswiederholungsversuch (#2198 #2218) – Das Begrenzen von Datei-Uploads und -Downloads wird in allen vier verbleibenden SDKs auf das Anforderungszeitlimit (Standardeinstellung 30 s) eingestellt – das Zeitlimit für den gesamten Aufruf (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) deckt das Senden des Anforderungstexts und das Lesen der Antwort ab, sodass jede große oder langsame Übertragung mitten im Flug fehlschlägt, auch wenn sie fehlerfrei ist. Übertragungen werden jetzt auf einem dedizierten client ohne Frist für den gesamten Anruf ausgeführt, wodurch das Warten auf Antwortheader immer noch begrenzt wird, sodass eine blockierte Übertragung immer noch fehlschlägt, anstatt zu hängen (#2165 #2186 #2196 #2206) – Unterdrücken Sie sandbox.create client-Metriken für client-Pool-Warmup-Erstellung in Go, Python und JavaScript, in Übereinstimmung mit Kotlin: Warmup-Verkehr (hartcodiertes skipHealthCheck, Hunderte von ms) zuvor in benutzerbezogene Erstellungslatenz-Metriken gemischt und p50/p99 nach unten gezogen; Durch direktes Erstellen aus Pool-Akquise und benutzerorientierter Erstellung bleiben Berichte erhalten (#2199)

Python

– Bereinigen des abgebrochenen asynchronen Poolstarts: Das Abbrechen von SandboxPoolAsync.start() mitten im Warten ließ die Instanz in STARTING stecken, wo ein nachfolgendes start() stillschweigend zurückkehrte und die Startup-eigenen Ressourcen die Bereinigung übersprangen; Beim Abbruch wird jetzt der Abgleichsbereinigungspfad wiederverwendet, zu STOPPED verschoben und erneut erhöht, damit der Anrufer es erneut versuchen kann (#2209)

  • Fehlgeschlagene Dateiersetzungen nicht mehr als erfolgreich melden: Die normalen Dateisystemadapter haben die generierten clients JSONDecodeError abgefangen und verworfen, sodass ein leerer oder nicht-JSON HTTP 400/500 von replace_contents() Erfolg zurückgegeben hat und ein Agent mit einer nicht angewendeten Bearbeitung weitermachen konnte; Die Sperre wird entfernt und der dokumentierte SandboxException-Fehlervertrag wird wiederhergestellt (Adapter für isolierte Sitzungen behalten ihre Kompatibilitätssperre für leere Körper) (#2222)

Los

– Entfernen Sie alle OPEN-SANDBOX-*/OPENSANDBOX-*-Header und alle konfigurierten Authentifizierungsheader (einschließlich X-EXECD-ACCESS-TOKEN, X-API-Key und benutzerdefinierte WithAuthHeader-Namen) bei ursprungsübergreifenden Weiterleitungen und vergleichen Sie jedes Ziel mit dem Schema, dem Host und dem effektiven Port der ursprünglichen Anfrage, damit Anmeldeinformationen bei späteren Hops mit fremden Ursprüngen nicht wieder angezeigt werden können. Wird über Lebenszyklus, Ausführung, Ausgang, Dateiübertragungen, SSE und Erstellungsmetriken angewendet und behält benutzerdefinierte CheckRedirect-Richtlinien bei (#2178)

Controller

– Behalten Sie eine BatchSandbox bei, bis die Bereinigung abgeschlossen ist: Eine gelöschte Sandbox könnte aus dem Lebenszyklus API (GET 404) verschwinden, während ihr eigener Pod noch ausgeführt wird, sodass eine Ersatz-Sandbox dasselbe persistente Verzeichnis schreiben kann, bevor der alte Writer beendet wird; Beim Löschen wird jetzt das kaskadierende Löschen im Vordergrund zusammen mit den vorhandenen Task-Cleanup- und Pool-Release-Finalisierern verwendet, und der TTL-Abgleich stoppt, sobald der Löschvorgang akzeptiert wird – DELETE gibt bei Annahme immer noch 204 zurück, Abfragen melden Stopping während der verwalteten Bereinigung und 404 kommt erst, wenn die Laufzeit abgelaufen ist; Die kill-Dokumente und Protokolle aller fünf SDKs beschreiben die Semantik der akzeptierten Löschung (#2154)

Execd

– OOM-Kills über cgroupfs-Abfragen melden: Kernelseitige Beweise waren aus einer Sandbox heraus nicht erreichbar (kein CAP_SYSLOG, kein /dev/kmsg), sodass OOM-Ereignisse nicht beobachtbar waren; exec fragt jetzt alle 5 Sekunden die Sandbox-Kontrollgruppe ab und unterscheidet den Kernel-OOM-Kill-Zähler (memory.events auf Version 2, Best-Effort auf Version 1) – die hierarchischen Zähler decken verschachtelte Kontrollgruppen wie isolierte Bwrap-Sitzungen ab – Export von execd.system.oom.kills mit einem local/descendant-Level-Attribut sowie strukturierten Warnprotokollen mit Best-Effort-Opferzuordnung; Der Watcher läuft unabhängig vom OTLP-Export und benötigt keine Funktionen (#2191)

  • Sandbox-bezogene CPU-/Speichermetriken melden: GET /metrics und die Messgeräte execd.system.cpu.usage/execd.system.memory.usage_bytes lesen /proc über gopsutil aus, das in einem Container den Host beschreibt – Dashboards zeigten hostweiten Speicher und CPU; Wenn die Sandbox-Kontrollgruppe konfigurierte Grenzwerte aufweist, kommt die Nutzung jetzt von der eigenen Kontrollgruppe der Sandbox (cpu.stat/cpu.max, memory.current/memory.max, v1-Fallback, Hybrid-Hosts bevorzugen v1), wobei die vorherige Hostansicht für unbegrenzte Gäste wie schnelle Sandbox-MicroVMs beibehalten wird; Das Drahtformat bleibt unverändert (#2200)
  • Prozentkodierte Anführungszeichen und Backslashes in Content-Disposition: Ein Dateiname, der " oder \ enthält, erzeugte eine Zeichenfolge in Anführungszeichen, die kein Standardparser akzeptiert (mime.ParseMediaType lehnte sie ab und clients erhielt überhaupt keinen Dateinamen); Solche Namen durchlaufen jetzt die gleiche filename*=UTF-8''-Codierung wie Nicht-ASCII-Namen (#2161)
  • Analysieren Sie den Range-Header, bevor Sie Download-Header festlegen: Ein fehlerhafter Bereich antwortete mit 416, wobei die Content-Disposition und Content-Length der Datei noch angehängt waren, wodurch der JSON-Körper abgeschnitten oder ganz gelöscht wurde – was im Python SDK als Verbindungsfehler statt als 416 SandboxApiException auftauchte; Die Fehlerantwort ist jetzt eine saubere JSON 416 und 200/206 Antworten sind unverändert (#2216)

Vernetzung

Ausgang

Alle folgenden Punkte betreffen die standardmäßig deaktivierte experimentelle Revisionslaufzeit OSEP-0023; Legacy- und reine DNS-Bereitstellungen bleiben unverändert.

  • Fügen Sie experimentellen Live-Zugang zum Vault mit Zugangsdaten hinzu: Vault-Mutationen durchlaufen die Revisionstransaktion und installieren den privaten authentifizierten Snapshot, bevor das öffentliche Ergebnis veröffentlicht wird. Gebundene HTTPS-Verbindungen werden zugelassen und Header-Anmeldeinformationen werden erst dann eingefügt, wenn die Anfrage genau mit der SNI/HTTP/1-Berechtigungsvereinbarung übereinstimmt (ECH-Erweiterung ClientHellos bleibt undurchsichtig), mit Anmeldeinformationsrotation pro Anfrage, Einzäunung entfernter Bindungen für bestehende Verbindungen und Transportabschaltung zum Ablaufdatum; Geltungsbereich ist Exact-Host-HTTPS auf 443 mit HTTP/1.1 und Inline-Header-Anmeldeinformationen (#2176)
  • Bestätigen Sie Live-Richtlinienrevisionen vor der Veröffentlichung: Die Richtlinie API und die automatischen deny.always/allow.always-Neuladevorgänge werden jetzt der Reihe nach festgeschrieben – optionale Dateipersistenz, NFT-Anwendung, genaue Empfängerbestätigung oder abgeglichenes Rücklesen, dann Proxy-Veröffentlichung und API-Erfolg – mit Fail-Closed-Wiederherstellung, wenn der Empfänger ausfällt, nachdem NFT in Kraft getreten ist, und 30-Sekunden-Drain-Fristen für reine Richtlinienaktualisierungen, die nie erfolgen Übergreifen Sie spätere Revisionen (#2182)
  • Fügen Sie experimentelle HTTP/2-Zulassung und begrenzten Drain hinzu: Snapshots binden sich atomar an tatsächliche client-Stream-IDs in Requestheadern, Post-Fence-Anfragen erhalten REFUSED_STREAM, bevor sie den Ursprung erreichen, GOAWAY wartet auf ausstehende Ausgabeverpflichtungen, während der Ablauf einen abnormalen Abschluss verwendet, und ein einmaliger Mitmdump-Exit-Fallback deckt nicht überprüfbare Bereinigungseigentum ab; Der Adapter ist an CPython 3.10/3.11 angeheftet und lehnt konfigurierte verkettete Upstream-Proxys ab (#2201) – Laufzeitwiederherstellungsfehler im Sidecar-Netzwerk-Namespace enthalten: Ein unerwarteter MITM-Exit löst jetzt einen unabhängigen, durch Rücklesen verifizierten IPv4/IPv6-Zaun aus, der für die gesamte Prozesslebensdauer an den ursprünglichen Namespace gebunden ist – und den gesamten Eingabe-/Ausgabe-/Weiterleitungsverkehr einschließlich bestehender Verbindungen und Loopback blockiert – wobei QuarantineConfirmed erst nach dem echten Regel-Readback gemeldet wird; Normale erfolgreiche Mutationen führen niemals zu einem Zaun (#2172)
  • Experimentelle Revisionsrichtliniendateien atomar beibehalten: Schreibvorgänge durchlaufen einen temporären Inode im selben Verzeichnis mit fsync + umbenennen + Verzeichnis fsync, Wiederherstellungen stellen die genauen vorherigen Bytes (oder synchronisierte Abwesenheit) zurück und nicht unterstützter Speicher – Dateibindungs-Mounts, schreibgeschützte oder symbolisch verknüpfte Pfade, Hardlinks, unsicherer Besitz, nicht unterstützte SELinux/IMA-Metadaten – wird abgelehnt, bevor das Original berührt wird; Betreiber müssen einen vorhandenen Egress-eigenen, exklusiv geschriebenen Verzeichnis-Mount bereitstellen (#2162)
  • NFT-Anwendungseffekte vor der Richtlinienwiederherstellung klassifizieren: lokaler Aufbau, Abbruch vor dem Start und Startfehler sind unverändert (Status bleibt erhalten, Wiederholungsversuch nach Wiederherstellung zulässig), erfolgreiche Ausführung ist festgeschrieben, und jeder Fehler nach dem Start oder nicht klassifizierter Fehler ist unbekannt – Schreibzugriff wird geschlossen und Wiederherstellung wird vor der Best-Effort-Wiederherstellung verriegelt; Der Fallback für fehlende Tabellen behält beide Fehler bei und stuft niemals ein unbekanntes Ergebnis herab (#2167)

Eingang

  • Implementieren Sie OSEP-0024-Aktivitätsverfolgung und Wake-on-Access: Mit --activity-enabled zeichnet jede weitergeleitete Anfrage einen monotonen Aktivitätszeitstempel auf Redis auf – Fire-and-Forget, niemals auf dem heißen Pfad – mit Schreibkoaleszenz pro Replikat, Lua-Monotonic-Max-Updates, sodass Schreibvorgänge außerhalb der Reihenfolge niemals die neueste Beobachtung zurückführen, und Pipeline-Batching; Mit --wake-enabled wird eine an eine angehaltene schnelle Sandbox weitergeleitete Anfrage geparkt statt mit 503 beantwortet: ein ResumeSandbox pro Replikat pro Sandbox unter einem durch einen Kontrollpunkt eingezäunten Einzelflug, einem begrenzten Parkplatz und begrenztem Budget (Überlauf-/Timeout-Antwort 503 + Retry-After, während die Wiederherstellung fortgesetzt wird, wird nie abgebrochen) und der Wiedereintritt einer veralteten Route wird nur dann auf einer neuen Route wiedergegeben, wenn sie sicher wiederholbar ist; Wenn beide Flags nicht gesetzt sind, ist das Verhalten Byte-identisch mit dem heutigen (#2156)
  • Vollständige OSEP-0024-Wake-Hardening: Post-Forward-Wiedergabe veralteter Routen ist auf idempotente Methoden mit reproduzierbaren Körpern beschränkt (ein weitergeleiteter POST wird niemals stillschweigend erneut ausgeführt); Die Pre-Forward-Wake-Timeout-Antwort trägt den von OSEP definierten Marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired + einen sandbox_wake_timeout-Körper, der die Sandbox benennt), der aus jeder Upstream-Antwort entfernt wird, sodass eine Sandbox die Herkunft nicht fälschen kann; eine separate Wiederherstellungsgenehmigung (--wake-restore-max, vorgehalten am Flugterminal) beschränkt gleichzeitige Wiederherstellungen unabhängig vom Parkplatz; und Wake erfordert jetzt das Opt-in pro Sandbox lifecycle.idlePolicy, das ausschließlich aus der Sandbox-CR-Anmerkung gelesen wird – fehlt oder fehlerhaft bedeutet, dass keine Richtlinie und der heutige permanente 503 vorliegen, niemals ein implizites Opt-in; gateway.wake.*-Diagrammwerte verbinden die Flags und fügen schreibgeschütztes RBAC nur hinzu, wenn es aktiviert ist (#2180)

Schnelle Sandbox

  • Sandbox-Löschung zuverlässig machen: Beim Löschen wird jetzt vor jeder Laufzeit-Abwesenheitsprüfung eine abgeschirmte Fastlet-Löschung gesendet, sodass ein fehlender Registrierungseintrag, ein Transportfehler oder eine leere Inspektionsantwort nicht mehr als Beweis dafür gewertet werden, dass die Sandbox nicht mehr vorhanden ist (was dazu führen könnte, dass die Mikro-VM verwaist, während die CR verschwindet). Das Fastlet zeichnet einen Tombstone pro Identität auf, sodass eine verzögerte Erstellung eine gelöschte Sandbox nicht wiederbeleben kann, und der Bereinigungsfinalizer bleibt bei der CR-Erstellung bestehen (#2214)
  • Schnellere Wiederherstellung der Erstellungsplatzierung: Nach nachgewiesenen Ablehnungen aktualisiert FastPath seine Kandidatenliste innerhalb eines begrenzten Budgets (ausgenommen bereits ausprobierte Fastlets) und wartet bis zu 2 s, bis der Zuweisungsstatus vor dem Wechsel auf dem neuesten Stand ist, und ein prozesslokaler Erstellungs-Tracker verhindert, dass ein gelöschter oder ersetzter Fastlet-Pod die Projektion der neuen Zuweisung oder die Wiederherstellung nach Rennpod-Verlusten blockiert – der glückliche Pfad für die erste Erstellung bleibt unverändert (#2214) – Batch-Gast-NAT-Updates: Neue Gast-VM-Slots bereiten dedizierte DNAT/SNAT-Ketten vor und die Wiederherstellung ersetzt nur diese Ketten in einem iptables-restore --noflush-Batch, sodass beim erneuten Anwenden derselben Gastadresse keine Regeln mehr angehäuft werden, wobei eine neue fast_sandbox_network_guest_apply_stage_latency_seconds-Metrik die Anwendungsphasen trennt (#2214)

Sonstiges

  • Konsole: Landen Sie den ersten Teil einer neuen optionalen Webkonsole – eine FastAPI BFF mit httpOnly-Sitzungen und Mandanten-/Administrator-Login, die den Lebenszyklus /sandboxes API (mit einem runtimeSummary auf Liste/Get) proxyt, plus eine React SPA, die Mandantenübersicht, Sandbox-Liste/Erstellen/Detaillieren, Erneuern/Löschen und den Endpunkt abdeckt; erste von fünf geplanten Konsolen-PRs, die Admin-Benutzeroberfläche folgt (#2129)
  • CLI: Konfigurationsdateiwerte in ihre deklarierten Typen umwandeln, sodass ein numerischer api_key nicht mehr stillschweigend in Null aufgelöst wird (wodurch jeder Befehl mit einem ValidationError unterbrochen wird) und ein numerischer defaults.timeout nicht mehr zum Absturz von sandbox create führt (#2169); Halten Sie die Ausgabe auf Nicht-UTF-8-Streams beschreibbar – GBK/cp1252/C-locale-Benutzer konnten keinen osb-Befehl ausführen, da das Emoji-Rendering UnicodeEncodeError auslöste, oft nachdem die Arbeit bereits erledigt war; Streams maskieren jetzt nicht codierbare Zeichen und die YAML-Ausgabe wird erneut ausgegeben, maskiert, um gültig zu bleiben (#2187); Schreiben Sie installierte Fähigkeiten dort, wo jedes Tool sie tatsächlich liest – das claude-Ziel schreibt jetzt .claude/skills/<name>/SKILL.md (die vorherige Flatfile wurde stillschweigend nie geladen), und globale cline/copilot-Ziele schreiben ~/.cline/rules/opensandbox-<name>.md und ~/.copilot/copilot-instructions.md; Zuvor installierte inerte Dateien werden nicht migriert (#2194 #2208)
  • Schnelle Sandbox-Integrationsumgebung: Führen Sie die Überprüfungsphasen über das veröffentlichte osb CLI anstelle des rohen curl aus (Vorlagenerstellung, Sandbox-Erstellung/Tötung, Endpunktabruf, Pause/Fortsetzung, Snapshot-Erstellung/Abruf/Liste/Löschen/Wiederherstellen, Erneuern), wobei server_api nur für Aufrufe beibehalten wird, die CLI nicht offenlegt (Netzwerkrichtlinie ersetzt PUT, RFC). 7396 Merge-Patch, der Snapshot-Re-Entry-Code-Zaun, Gateway-Prüfungen) (#2171); Fügen Sie ein optionales IDLE_PAUSE=1-Profil hinzu, das flüchtiges Redis bereitstellt, den [automation.idle_pause]-Sweeper und die Gateway-Aktivitäts-/Wake-Werte aktiviert und die vollständige Auto-Pause → Wake-on-Access-Schleife auf up sowie eine SDK e2e-Suite und einen nächtlichen KVM-Workflow-Job überprüft (#2202)
  • Dokumente: Akzeptieren und dokumentieren Sie OSEP-0024 – den Vorschlag selbst (#2152) sowie eine Architekturseite und ein Benutzerhandbuch zur Aktivierung, die Feldreferenz idlePolicy, den Activity-Probe-Vertrag, das Wake-Retry-Verhalten SDK und ein interaktives Diagramm (#2217); Vereinheitlichung der Komponententelemetriemetriken von sieben verstreuten Standorten in einer Referenz bei docs/guides/telemetry.md (#2205); Aktualisieren Sie die Netzwerkarchitekturseiten mit neu gestalteten SVG-Diagrammen, einer komprimierten Ausgangsseite und der Neupositionierung des Netzwerkisolationsleitfadens (#2210); Richten Sie CONTRIBUTING mit dem Code aus (Go 1.25, Gin – nicht Beego) (#2175), deduplizieren Sie die AGENTS.md-Regeln und geben Sie die Platzierungsregel „Architecture vs. Guides“ einmal an (#2211) und korrigieren Sie die Fehlbezeichnung „gemeinsam genutztes Fastlet-Ausgangsprofil“ in „gemeinsamer Ausgangsprozess pro Fastlet-Pod“ mit einem Hinweis darauf gRPC endet bei FastPath (#2225) – Tests/CI: Richten Sie die e2e-Assertion der Node-Agent-Protokollsammlung an der beibehaltenen abschließenden neuen Zeile von execd aus (#2164); Machen Sie den Umbrella-Release-Workflow nur für den Dispatch, indem Sie den wöchentlichen geplanten Probelauf löschen (#2223)

Upgrade und Kompatibilität

– Verhaltensänderung: BatchSandbox-Pods verwenden jetzt standardmäßig restartPolicy: Never (implizites Always → Never) – Bereitstellungen, die sich auf die implizite Standardeinstellung verlassen und Neustarts wünschen, müssen restartPolicy: Always explizit in ihrem batchsandbox_template_file festlegen (eine Startwarnung weist auf den Kompromiss hin) (#2128) – Verhaltensänderung: Gelöschte Sandboxes bleiben in Stopping abfragbar, bis die Laufzeitbereinigung abgeschlossen ist, und geben erst dann 404 zurück – clients, die ein persistentes Verzeichnis teilen, sollten auf den 404 warten, bevor sie mit dem Ersetzen beginnen (#2154) – Verhaltensänderung: Execd-CPU-/Speichermetriken melden sandboxbezogene Werte, wenn für die Sandbox-Kontrollgruppe Grenzwerte konfiguriert sind (zuvor hostweit); GET /metrics-Feldsemantik und OTel-Metriknamen bleiben unverändert, aber Dashboards werden verschoben (#2200) – Verhaltensänderung: networkPolicy wird für Docker-Netzwerkmodi none/pasta/slirp4netns abgelehnt – zuvor stillschweigend für none akzeptiert (#2203)

Englisches Original / English original

OpenSandbox release-1.2.0-rc.1

First release candidate on the 1.2.0 line, carrying everything merged since release-1.1.1 — the headline is OSEP-0024: auto-pause and wake-on-access for fast sandboxes, landing end to end. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: ingress activity tracking and the wake path, the server-side idle sweeper, the opt-in lifecycle.idlePolicy create field, and the wake-retry contract in all five SDKs — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Egress sidecar (experimental, opt-in): live credential-bound Vault admission, HTTP/2 support with bounded drain, atomic policy-file persistence, and runtime fault containment (#2176 #2201 #2182 #2162 #2172)
  • SDK reliability: file uploads and downloads are no longer aborted at the 30-second request timeout in any of the five SDKs; execd now reports sandbox-scoped CPU/memory and OOM kills (#2165 #2186 #2196 #2206 #2191 #2200)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle create field lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) validates with pydantic bounds and persists as the reserved sandbox.opensandbox.io/idle-policy Sandbox CR annotation (annotation-write failure stays fail-safe — the sandbox is created unpolicied); an idle sweeper enumerates opted-in fsb sandboxes from the informer cache, checks activity in Redis (monotonic-max writes, missing-key tombstones can only delay a pause), takes a per-sandbox pause lock with re-verify under lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe executes through the ingress gateway and a busy answer records ordinary activity; an OpenSandbox-Skip-Activity: skip sentinel suppresses the observation for one request and is stripped on both gateway and server-proxy hops (#2192 #2181)
  • Configure idle-pause under the new lifecycle-automation umbrella: [idle_pause] becomes [automation.idle_pause] and the redundant redis.enabled gate is removed — redis.dsn is required (validated at load) when enabled = true, failing loudly instead of silently not starting the sweeper; configuration.md is rewritten for conciseness and now documents ingress.secure_access and the missing env-var overrides (#2215)
  • Default BatchSandbox pods to restartPolicy: Never: a kubelet in-place container restart recreated the main container from its image — wiping the writable layer and in-memory state — while the sandbox kept reporting Succeed; restarting is never a meaningful recovery for a sandbox, so the honest default is no restart, which also makes the controller's terminal-failure path reachable. An explicit restartPolicy in the template still wins, the Windows profile keeps forcing Always (multi-phase installation relies on it), and pool mode is unchanged (#2128)
  • Treat pasta/slirp4netns/none as container-runtime network modes and pass them straight through, making podman's kernel-level networking selectable — on Windows 11 + WSL2 where netavark breaks bridge mode, pasta was the only working network and previously failed create with a 400 asking for a user-defined Docker network; networkPolicy is now rejected for these modes since there is no bridge for the egress sidecar to attach to (previously silently accepted for none) (#2203)
  • Parse Docker timestamps whose fractional second is not 3 or 6 digits: Docker writes RFC3339Nano (trailing zeros dropped), Python 3.10's fromisoformat rejects 5-digit fractions, and the helper fell back to datetime.now() — so createdAt and status.lastTransitionAt silently reported the current time; the fraction is now zero-padded to 6 digits (#2220)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the OSEP-0024 SDK contract to all five languages: a typed lifecycle.idlePolicy create field (IdlePolicy/ActivityProbe models with client-side fail-fast validation mirroring the server: timeout 30–86400 s, onIdle: "pause" pairing, probe path/timeout bounds; wired through both standard and template create) and the wake-retry contract — on a 503 carrying the gateway-owned OpenSandbox-Wake: expired marker (its presence proves the request was parked and never forwarded, making any-method retry safe), the SDK resends after Retry-After under a bounded budget (default 5 attempts / 60 s, per-client knobs), exhaustion raises a typed wake-timeout exception carrying attempts and waited time, the server-side resume is never canceled, bare 503 handling is unchanged, and SSE/streaming transports bypass wake retry (#2198 #2218)
  • Stop capping file uploads and downloads at the request timeout (30 s default) in all four remaining SDKs — the whole-call timeout (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) covered sending the request body and reading the response, so any large or slow transfer failed mid-flight even while healthy; transfers now run on a dedicated client with no whole-call deadline that still bounds the wait for response headers, so a stalled transfer still fails instead of hanging (#2165 #2186 #2196 #2206)
  • Suppress sandbox.create client metrics for client-pool warmup creates in Go, Python, and JavaScript, aligning with Kotlin: warmup traffic (hardcoded skipHealthCheck, hundreds of ms) previously mixed into user-facing create-latency metrics and dragged p50/p99 down; direct-create from pool acquire and user-facing creates keep reporting (#2199)

Python

  • Clean up cancelled async pool startup: cancelling SandboxPoolAsync.start() mid-await left the instance stuck in STARTING, where a subsequent start() silently returned and startup-owned resources skipped cleanup; cancellation now reuses the reconciliation cleanup path, moves to STOPPED, and re-raises so the caller can retry (#2209)
  • Stop reporting failed file replacements as successful: the ordinary filesystem adapters caught and discarded the generated client's JSONDecodeError, so an empty or non-JSON HTTP 400/500 from replace_contents() returned success and an agent could keep building on an unapplied edit; the catch is removed and the documented SandboxException failure contract is restored (isolated-session adapters keep their empty-body compatibility catch) (#2222)

Go

  • Strip all OPEN-SANDBOX-*/OPENSANDBOX-* headers and every configured authentication header (including X-EXECD-ACCESS-TOKEN, X-API-Key, and custom WithAuthHeader names) on cross-origin redirects, comparing each destination against the initial request's scheme, host, and effective port so credentials cannot reappear on later foreign-origin hops; applied across lifecycle, execd, egress, file transfers, SSE, and creation metrics while preserving custom CheckRedirect policies (#2178)

Controller

  • Retain a BatchSandbox until cleanup completes: a deleted sandbox could disappear from the lifecycle API (GET 404) while its owned pod still ran, letting a replacement sandbox write the same persistent directory before the old writer exited; deletion now uses foreground cascading deletion alongside the existing task-cleanup and pool-release finalizers, and TTL reconciliation stops once deletion is accepted — DELETE still returns 204 when accepted, queries report Stopping during managed cleanup, and 404 arrives only after the runtime is gone; all five SDKs' kill docs and logs describe the accepted-deletion semantics (#2154)

Execd

  • Report OOM kills via cgroupfs polling: kernel-side evidence was out of reach from inside a sandbox (no CAP_SYSLOG, no /dev/kmsg), so OOM events were unobservable; execd now polls the sandbox cgroup every 5 s and diffs the kernel OOM kill counter (memory.events on v2, best-effort on v1) — the hierarchical counters cover nested cgroups like bwrap isolated sessions — exporting execd.system.oom.kills with a local/descendant level attribute plus structured warn logs with best-effort victim attribution; the watcher runs independently of OTLP export and needs no capabilities (#2191)
  • Report sandbox-scoped CPU/memory metrics: GET /metrics and the execd.system.cpu.usage/execd.system.memory.usage_bytes gauges read /proc through gopsutil, which inside a container describes the host — dashboards showed host-wide memory and CPU; when the sandbox cgroup carries configured limits, usage now comes from the sandbox's own cgroup (cpu.stat/cpu.max, memory.current/memory.max, v1 fallback, hybrid hosts prefer v1), with the previous host view kept for unlimitied guests such as fast-sandbox microVMs; the wire format is unchanged (#2200)
  • Percent-encode quotes and backslashes in Content-Disposition: a filename containing " or \ produced a quoted-string no standard parser accepts (mime.ParseMediaType rejected it and clients got no filename at all); such names now route through the same filename*=UTF-8'' encoding as non-ASCII names (#2161)
  • Parse the Range header before setting download headers: a malformed range answered 416 with the file's Content-Disposition and Content-Length still attached, truncating the JSON body or dropping it entirely — surfacing in the Python SDK as a connection error instead of a 416 SandboxApiException; the error response is now a clean JSON 416, and 200/206 responses are unchanged (#2216)

Networking

egress

All items below concern the default-off OSEP-0023 experimental revision runtime; legacy and DNS-only deployments are unchanged.

  • Add experimental live credential-bound Vault admission: Vault mutations flow through the revision transaction and install the private authenticated snapshot before publishing the public result; bound HTTPS connections are admitted and header credentials injected only after exact request matching with SNI/HTTP/1 authority agreement (ECH-extension ClientHellos stay opaque), with per-request credential rotation, fencing of removed bindings on existing connections, and transport retirement at the drain deadline; scope is exact-host HTTPS on 443 with HTTP/1.1 and inline header credentials (#2176)
  • Acknowledge live Policy revisions before publication: the Policy API and automatic deny.always/allow.always reloads now commit in order — optional file persistence, nft application, exact receiver acknowledgement or reconciled readback, then proxy publication and API success — with fail-closed recovery when the receiver fails after nft has taken effect, and 30-second drain deadlines on policy-only updates that never extend across later revisions (#2182)
  • Add experimental HTTP/2 admission and bounded drain: snapshots bind atomically to actual client stream IDs at requestheaders, post-fence requests get REFUSED_STREAM before reaching origin, GOAWAY waits for outstanding output obligations while expiry uses abnormal closure, and a once-only mitmdump exit fallback covers unverifiable cleanup ownership; the adapter is pinned to CPython 3.10/3.11 and rejects configured chained upstream proxies (#2201)
  • Contain runtime recovery faults in the sidecar network namespace: an unexpected MITM exit now triggers an independent, read-back-verified IPv4/IPv6 fence pinned to the original namespace for the process lifetime — blocking all input/output/forward traffic including existing connections and loopback — with QuarantineConfirmed reported only after real rule readback; normal successful mutations never introduce a fence (#2172)
  • Persist experimental revision policy files atomically: writes go through a same-directory temporary inode with fsync + rename + directory fsync, restores put back the exact previous bytes (or synchronized absence), and unsupported storage — file bind mounts, read-only or symlinked paths, hardlinks, unsafe ownership, unsupported SELinux/IMA metadata — is rejected before the original is touched; operators must provide an existing egress-owned, exclusively written directory mount (#2162)
  • Classify nft apply effects before policy recovery: local construction, pre-start cancellation, and start failures are Unchanged (state preserved, retry allowed after restore), successful execution is Committed, and every post-start or unclassified error is Unknown — closing writer admission and latching recovery before best-effort restoration; the missing-table fallback retains both errors and never downgrades an Unknown result (#2167)

ingress

  • Implement OSEP-0024 activity tracking and wake-on-access: with --activity-enabled, every routed request records a monotonic activity timestamp to Redis — fire-and-forget, never on the hot path — with per-replica write coalescing, Lua monotonic-max updates so out-of-order writes never regress the newest observation, and pipeline batching; with --wake-enabled, a request routed to a paused fast sandbox is parked instead of answered 503: one ResumeSandbox per replica per sandbox under a checkpoint-fenced singleflight, a bounded parking lot and budget (overflow/timeouts answer 503 + Retry-After while the restore continues, never canceled), and stale-route re-entry replayed on a fresh route only when safely replayable; with both flags unset, behavior is byte-identical to today (#2156)
  • Complete OSEP-0024 wake hardening: post-forward stale-route replay is restricted to idempotent methods with reproducible bodies (a forwarded POST is never silently re-executed); the pre-forward wake-timeout answer carries the OSEP-defined marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired + a sandbox_wake_timeout body naming the sandbox), stripped from every upstream response so a sandbox cannot forge provenance; a separate restore permit (--wake-restore-max, held to flight terminal) bounds concurrent restores independently of the parking lot; and wake now requires the per-sandbox lifecycle.idlePolicy opt-in read strictly from the Sandbox CR annotation — missing or malformed means no policy and today's permanent 503, never an implicit opt-in; gateway.wake.* chart values wire the flags and add read-only RBAC only when enabled (#2180)

Fast Sandbox

  • Make sandbox deletion reliable: deletion now sends a fenced Fastlet delete before any runtime-absence check, so a missing registry entry, transport failure, or empty inspect response is no longer treated as proof the sandbox is gone (which could orphan the microVM while the CR disappeared); the Fastlet records a per-identity tombstone so a delayed create cannot revive a deleted sandbox, and the cleanup finalizer is persisted at CR creation (#2214)
  • Make create placement recover faster: after proven rejections FastPath refreshes its candidate list within a bounded budget (excluding Fastlets already tried) and waits up to 2 s for assignment status to catch up before switching, and a process-local create tracker stops a deleted or replaced Fastlet pod from blocking the new assignment's projection or racing pod-loss recovery — the first-create happy path is unchanged (#2214)
  • Batch guest NAT updates: new guest-VM slots prepare dedicated DNAT/SNAT chains and restore replaces only those chains in one iptables-restore --noflush batch, so reapplying the same guest address no longer accumulates rules, with a new fast_sandbox_network_guest_apply_stage_latency_seconds metric separating the apply stages (#2214)

Misc

  • Console: land the first slice of a new optional web console — a FastAPI BFF with httpOnly sessions and tenant/admin login proxying the lifecycle /sandboxes API (with a runtimeSummary on list/get), plus a React SPA covering tenant overview, sandbox list/create/detail, renew/delete, and the endpoint; first of five planned console PRs, with the admin UI to follow (#2129)
  • CLI: coerce config-file values to their declared types so a numeric api_key no longer silently resolves to null (breaking every command with a ValidationError) and a numeric defaults.timeout no longer crashes sandbox create (#2169); keep output writable on non-UTF-8 streams — GBK/cp1252/C-locale users could not run any osb command because emoji rendering raised UnicodeEncodeError, often after the work was already done; streams now escape unencodable characters and YAML output is re-dumped escaped to stay valid (#2187); write installed skills where each tool actually reads them — the claude target now writes .claude/skills/<name>/SKILL.md (the previous flat file was silently never loaded), and global cline/copilot targets write ~/.cline/rules/opensandbox-<name>.md and ~/.copilot/copilot-instructions.md; previously installed inert files are not migrated (#2194 #2208)
  • Fast-sandbox integration environment: drive the verify stages through the published osb CLI instead of raw curl (template build, sandbox create/kill, endpoint fetch, pause/resume, snapshot create/get/list/delete/restore, renew), with server_api kept only for calls the CLI does not expose (networkpolicy replace PUT, RFC 7396 merge-patch, the snapshot re-entry code fence, gateway probes) (#2171); add an opt-in IDLE_PAUSE=1 profile that deploys ephemeral Redis, enables the [automation.idle_pause] sweeper and gateway activity/wake values, and verifies the full auto-pause → wake-on-access loop on up, plus an SDK e2e suite and a nightly KVM workflow job (#2202)
  • Docs: accept and document OSEP-0024 — the proposal itself (#2152) plus an architecture page and user guide covering enablement, the idlePolicy field reference, the activity-probe contract, SDK wake-retry behavior, and an interactive diagram (#2217); unify component telemetry metrics from seven scattered locations into one reference at docs/guides/telemetry.md (#2205); refresh the network architecture pages with restyled SVG diagrams, a condensed egress page, and the network-isolation guide relocation (#2210); align CONTRIBUTING with the code (Go 1.25, Gin — not Beego) (#2175), dedupe AGENTS.md rules and state the architecture-vs-guides placement rule once (#2211), and fix the "shared Fastlet egress profile" misnomer to "shared egress process per Fastlet pod" with a note that gRPC ends at FastPath (#2225)
  • Tests/CI: align the node-agent log-collection e2e assertion with execd's preserved trailing newline (#2164); make the umbrella release workflow dispatch-only by dropping the weekly scheduled dry-run (#2223)
  • release: bump platform version to 1.2.0-rc.1 across charts and image references

Upgrade & Compatibility

  • Behavior change: BatchSandbox pods now default to restartPolicy: Never (implicit Always → Never) — deployments that relied on the implicit default and want restarts must set restartPolicy: Always explicitly in their batchsandbox_template_file (a startup warning will note the trade-off) (#2128)
  • Behavior change: deleted sandboxes stay queryable in Stopping until runtime cleanup completes, and only then return 404 — clients sharing a persistent directory should wait for the 404 before starting a replacement (#2154)
  • Behavior change: execd CPU/memory metrics report sandbox-scoped values when the sandbox cgroup has limits configured (previously host-wide); GET /metrics field semantics and OTel metric names are unchanged, but dashboards will shift (#2200)
  • Behavior change: networkPolicy is rejected for Docker network modes none/pasta/slirp4netns — previously accepted silently for none (#2203)
