OpenSandbox-Release-1.2.0-rc.2

Zweiter Release-Kandidat in der 1.2.0-Reihe, der alles zusammenführt, was seit release-1.2.0-rc.1 zusammengeführt wurde – die Schlagzeile ist der Credential Vault (OSEP-0022), der durchgängig für schnelle Sandboxen landet: ein Egress-gehaltener Vault mit dauerhafter Per-Subjekt-Persistenz und Pause/Fortsetzungsübertragung, der vom Benutzer erreichbare, servergeroutete Vault API und eine im Pool verankerte MITM-CA. Die Netzwerkrichtlinie folgt dem gleichen Egress-Hold-Muster, und NetworkRule erhält portbezogene Regeln im klassischen Profil – schnelle Sandboxen lehnen sie bei Fail-Closing ab, bis der Fastlet-NFT-Pfad sie durchsetzt. Bilder jetzt veröffentlichen; SDK/CLI-Pakete werden mit der stabilen 1.2.0-Beule geliefert. Bitte testen und melden Sie Probleme.

Highlights

– Credential Vault (OSEP-0022) ist durchgängig für schnelle Sandboxes geeignet: Der Egress-Sidecar speichert den Tresor mit dauerhaften Pro-Subjekt-Dateien, versiegelter Snapshot-Übertragung zum Anhalten/Fortsetzen und Übernahme veralteter Subjekte bei Slot-Wiederverwendung (#2249 #2252 #2255 #2250); Der Server stellt den für den Benutzer erreichbaren POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API über das FastPath-Handler-Relay bereit, wobei Anmeldeinformationswerte bei keinem öffentlichen Lesevorgang angezeigt werden (#2263), und die MITM-CA ist pro Pool fixiert, sodass ein Ausgangsneustart den trust-Anker nicht mehr unter Live-Sandboxen rotiert (#2251) – Die Netzwerkrichtlinie spiegelt den Tresor wider: Die aufgezeichnete Fast-Sandbox-Richtlinie wird mit Relay-CRUD, dauerhafter Persistenz und Pause/Fortsetzung der Snapshot-Übertragung in den Status „Egress Hold“ versetzt (#2309), und NetworkRule erhält im klassischen Profil durchgängig portbezogene Regeln – Spezifikation, Sidecar-NFTables, Servervalidierung und alle fünf SDKs, während schnelle Sandboxen dies ablehnen ports ist vorerst fehlgeschlagen – plus eine betreiberseitige TCP-Port-Untergrenze, die keine Benutzerrichtlinie öffnen kann (#2212) – Lebenszyklus- und Diagnosepolierung: lifecycle.renewalPolicy ersetzt den undurchsichtigen Erneuerungserweiterungsschlüssel (OSEP-0009) (#2296); Der Diagnosekontext API erreicht den Server, alle fünf SDKs und den CLI (#2292); Execd-Korrekturen machen Startfehler erkennbar, behalten die Sitzungsausgabe Byte für Byte bei und stoppen das stille Festplattenwachstum (#2303 #2318 #2295)

Server

  • Implementieren Sie die Serverseite des Credential Vault (OSEP-0022, Fast-Sandbox-Profil): Der für den Benutzer erreichbare POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API überträgt vollständige Vault-Revisionen über das FastPath InvokeHandlerAction-Handler-Relay und behandelt die Relay-Antwort als synchrone, vom Ausgang validierte Bestätigung – der CRD überträgt niemals Vault-Material und jeder öffentliche Lesevorgang wird serverseitig bereinigt; PATCH wird im Speicher erstellt (delete → replace → add, jeder Name wird höchstens einmal aufgelöst), wobei expectedRevision als Cross-Replica-Backstop dient, Nicht-FSB-Backends die /credential-vault-Oberfläche des Sidecars als Proxy verwenden und die Ablehnung der FSB-credentialProxy-Erstellungszeit aufgehoben wird (#2263) – Backen Sie die angeheftete MITM-CA in vom Server erstellte SandboxTemplates (OSEP-0022): Die neue [kubernetes] template_mitm_ca_secret/template_mitm_ca_secret_key-Konfiguration (Standardeinstellung deaktiviert) gibt spec.egressMitmCertificate – nur den Zertifikateintrag, niemals den privaten Schlüssel – für jede vom Server erstellte Vorlage aus; Das Geheimnis muss in jedem Vorlagen-Namespace (ops-runbook-Verteilung) vorhanden sein, und eine verpasste Kopie schlägt den Build beobachtbar fehl (#2288) – Fügen Sie lifecycle.renewalPolicy (OSEP-0009) hinzu: Das Opt-in für die Verlängerung bei Zugriff wechselt vom undurchsichtigen Erstellungsschlüssel extensions["access.renew.extend.seconds"] zu einem strukturierten renewalPolicy.extendSeconds (300–86400), der das idlePolicy-Muster widerspiegelt. Der Legacy-Schlüssel ist veraltet (in 1.x unterstützt, in 2.0 entfernt). Die Einstellung beider wird nur akzeptiert, wenn die analysierten Werte übereinstimmen, der Wert in die vorhandene Docker-Beschriftung/Kubernetes-Annotation normalisiert wird, sodass Sandboxen vor dem Upgrade ständig erneuert werden und die schnelle Sandbox ihn mit 400 ablehnt, anstatt stillschweigend ein No-Op zu akzeptieren (#2296) – Implementieren Sie den Diagnosekontextendpunkt (OSEP-Vertrag von rc.1): GET /v1/sandboxes/{sandboxId}/diagnostics/context gibt die Sandbox-ID, den Lebenszyklusstatus, den Backend-Typ und die vom Backend definierten Bezeichner für Docker, Kubernetes und Fast Sandbox zurück, ohne eine Verbindung zu exec herzustellen – der Kubernetes-Kontext bleibt verfügbar, bevor ein Pod zugewiesen wird, und Erweiterungs-Backends, die ihn nicht implementieren, geben 501 zurück (#2292)
  • Leiten Sie den noch codierten Pfad über den Sandbox-Proxy weiter: Starlette hat die {full_path:path}-Route vom prozentual decodierten Pfad gebunden und der Proxy hat diesen Wert wieder in die Upstream-URL eingefügt, sodass ein decodierter ? eine Abfrage startete, # ein Fragment, %2F ein Trennzeichen wurde, %25- und Nicht-UTF-8-Escapezeichen neu geschrieben wurden und %2E%2E-Segmente aufgelöst wurden – der Proxy übernimmt nun die clients noch codiertes Ende vom Rohpfad (überprüft die Dekodierung in den gerouteten Pfad mit einem Neucodierungs-Fallback) und liest die Abfrage aus der Rohabfragezeichenfolge; Backends empfangen Anforderungsziele Byte für Byte, passend zum Eingangs-Gateway, und das %2E%2E-Präfix-Escape auf Docker-Host-zugeordneten Endpunkten ist geschlossen (#2228) – BatchSandbox-Ablauf melden, während der Pod noch läuft: Ein früherer spec.expireTime wurde immer noch als Running (Bereitschafts-Pod mit IP) gemeldet, sodass die Wall-Clock-Abrechnung nach dem konfigurierten Timeout weiter anstieg; Der Ablauf prüft nun, ob der Bereitschaftsstatus vorliegt, und gibt Terminated / SANDBOX_EXPIRED zurück, wobei last_transition_at auf expireTime selbst gesetzt ist (#2238) – gVisor-Snapshots ablehnen, die Schreibvorgänge stillschweigend löschen würden: docker commit unter gVisors Standard --overlay2=root:self kann READY melden, während keine der Schreibvorgänge der Sandbox wiederhergestellt werden (nur der undurchsichtige /.gvisor.filestore.*-Eintrag ist sichtbar); Snapshot-Preflight löst jetzt die Laufzeit des Containers auf und lehnt gVisor ab, es sei denn, die effektiven Argumente enthalten --overlay2=none, und die Erstellung schlägt beim Schließen fehl, wenn das Dateisystem-Diff nur auf den Dateispeicher beschränkt ist (#2241) – Wenden Sie die Sicherheitsprofile [docker] und secure_runtime auf den Execd-Cache-Container an: apparmor_profile / seccomp_profile / docker_runtime wurden ignoriert, sodass auf einem Host, dessen Standard-Seccomp-Profil das Execd-Image blockiert, jedes POST /sandboxes mit 503 ohne Konfigurations-Escape fehlgeschlagen ist (#2254)
  • Machen Sie gleichzeitige Docker-Metadaten-Patches sicher: Das Lesen, Ändern und Schreiben des Speichers wurde entsperrt und jeder Schreibvorgang teilte einen temporären Namen, sodass zwei gleichzeitige PATCH /metadata-Anfragen für eine Sandbox in eine 500 (FileNotFoundError beim Umbenennen) stürzten oder stillschweigend den Schlüssel des anderen löschten; eine speicherweite Sperre plus temporäre Namen pro Schreibvorgang serialisieren Patches (letzter Schreibvorgang gewinnt pro Schlüssel), ein fehlgeschlagener Schreibvorgang hinterlässt seine temporäre Datei nicht mehr und der Endpunktvertrag wird jetzt pro Laufzeit dokumentiert – Kubernetes-Patches schreiben den gesamten gelesenen Etikettensatz zurück, FSB-Patches senden nur ihre eigenen Schlüssel, eingegrenzt durch UID und Generierung (#2267 #2281)
  • Proxy-Endpunkte außerhalb der Ereignisschleife auflösen: HTTP/WebSocket-Proxy-Handler haben den synchronen get_endpoint direkt aufgerufen – ein Docker-Socket-Aufruf pro Proxy-Anfrage auf Docker, ein api-Server liest auf Kubernetes-Cache-Fehlern – und blockiert die Schleife für jede andere Anfrage und jeden anderen Stream; Ein langsamer Docker-Daemon (z. B. während eines Image-Pulls) reichte aus, um den Server einzufrieren. Die Suche wird jetzt über asyncio.to_thread ausgeführt, wobei der Mandantenkontext erhalten bleibt (#2268) – Wenden Sie die Erneuerungs-Abklingzeit an, wenn der Redis-Verbraucher aktiviert ist: Proxy-Erneuerungen übersprungen min_interval_seconds vollständig (jede Proxy-Anfrage führte eine get_sandbox + Ablauferneuerung aus) und Warteschlangenabsichten wurden nur pro Eingangsreplikat gedrosselt, sodass N Replikate bis zu N-mal pro Intervall erneuert wurden; Die Abklingzeit gilt jetzt für jede Erneuerungsquelle und beginnt erst nach einer erfolgreichen Erneuerung (#2276 #2279)

SDKs

Die folgenden Codeänderungen beziehen sich auf die stabile Version 1.2.0 – rc liefert keine SDK-Pakete aus. – Fügen Sie den Credential Vault client-Vertrag zu allen fünf SDKs hinzu (OSEP-0022): Vorlagengestützte Sandboxen leiten Vault-Aufrufe über den Server mit demselben Vorlagenursprungssignal wie die Netzwerkrichtlinie (OPEN-SANDBOX-ORIGIN: template oder das lokale createFromTemplate-Flag), während Sidecar-Direct-Adapter unberührt bleiben; Sandbox.credential_vault von Python gibt jetzt den Tresordienst für beide Profile zurück, und Go erhält Tresormethoden auf Sandbox-Ebene, die auf demselben Signal verzweigen (#2263) – Fügen Sie lifecycle.renewalPolicy zu allen fünf SDKs hinzu (OSEP-0009): ein typisiertes Erstellungsfeld mit client-seitiger Fail-Fast-Validierung (extendSeconds 300–86400), das über die Erstellungskonverter verbunden ist und den undurchsichtigen Erweiterungsschlüssel ersetzt (#2296) – Implementieren Sie Diagnosen auf der SDK-Oberfläche (mit #2292): context wird sowohl über die Manager- als auch die Sandbox-Fassade in allen fünf Sprachen verfügbar gemacht, und JavaScript, Go und C# erhalten öffentliche Protokolle/Ereignisse. APIs entsprechen der vorhandenen Python/JVM-Oberfläche (benutzerdefinierte Fabriken funktionieren weiterhin – der neue Diagnosedienst ist optional). – Unterstützt portbezogene Ausgangsregeln in allen fünf SDKs (#2212): NetworkRule.ports (TCP 1–65535, höchstens 256 pro Regel, target jetzt optional) mit client-seitiger Validierung, die den Server spiegelt (Bereich, Duplikate, Obergrenze, abgelehnte Domäne+Ports, abgelehnte Netzmasken-CIDR+Ports); JavaScript kodiert die Ziel-oder-Ports-Invariante als Union-Typ, Python normalisiert ein leeres Drahtziel beim Zurücklesen

Python

– Stoppen Sie die Weitergabe eines abgebrochenen Endpunktabrufs an Kellner: Der Shared-Fetch-Endpunkt-Cache setzt den CancelledError des Abrufaufrufers auf die gemeinsame Zukunft, sodass gleichzeitige Kellner – z. B. TaskGroup-Geschwister – haben CancelledError großgezogen, obwohl nichts sie aufgehoben hat; Kellner lösen jetzt neu auf (zwischengespeicherter Endpunkt, neuerer In-Flight-Abruf oder ihr eigener), während der abgesagte Anrufer weiterhin wie zuvor meldet (#2277) – Leiten Sie credential_proxy über Sandbox-Pools weiter: PoolCreationSpec.credential_proxy wurde sowohl von synchronen als auch von asynchronen Erstellungspfaden gelöscht, sodass Aufwärm- und Direkterstellungs-Sandboxen stillschweigend die angeforderte Anmeldeinformations-Proxy-Konfiguration verloren haben; Benutzerdefinierte Fabriken bleiben kompatibel (das Schlüsselwort wird weggelassen, wenn es nicht festgelegt ist) (#2283) – Generieren Sie den Lebenszyklus client neu, um veraltete hartcodierte Standardeinstellungen (timeout_seconds: 2, wake_on_access: true → UNSET) zu löschen, die durch die Spezifikationsänderung in #2212 zurückgeblieben sind. Das Leitungsverhalten bleibt unverändert – der Server wendet dieselben Standardeinstellungen an (#2280)

Los

– Authentifizieren Sie Proxy-Datenebenenanfragen mit dem API-Schlüssel: Der Proxymodus sendete den Mandantenschlüssel API – eine Anmeldeinformation, die jede Sandbox des Mandanten erstellen, anhalten und löschen kann – als X-EXECD-ACCESS-TOKEN (und als Ausgangsauthentifizierung) in die untrusted-Sandbox, während der OPEN-SANDBOX-API-KEY-Header weggelassen wurde, den die Server-Middleware liest, sodass Multi-Tenant-Proxy-Anfragen 401 fehlschlugen und tauchten als Bereitschaftszeitüberschreitungen auf; Der Mandantenschlüssel läuft jetzt über den Server-Header und wird nie in die Sandbox oder den Egress-Sidecar geschmuggelt, vom Endpunkt und vom Anrufer bereitgestellte Proxy-Schlüssel haben unabhängig von der Groß-/Kleinschreibung Vorrang und der Direktmodus bleibt schlüsselfrei (#2274)

Controller

– Problem behoben, bei dem der Task-Executor eine leere Exit-Datei als Exit-Code 0 behandelt: Der Shim erstellt die Exit-Datei, bevor er sie schreibt, und Inspect ignorierte den Parse-Fehler – ein Shim, der zwischendurch getötet wurde (oder ein fehlgeschlagener Schreibvorgang, z. B. volle Festplatte), meldete eine fehlgeschlagene oder unterbrochene Aufgabe als Succeeded; Eine ungültige oder leere Datei durchläuft jetzt die PID-Prüfung (Running im laufenden Betrieb, ProcessCrashed, sobald sie verschwunden ist) (#2270)

Execd

– Zeilenenden der Bash-Sitzungsausgabe bleiben erhalten: run_in_session-Standardereignisse haben \n/\r-Bytes verloren, sodass Leerzeilen nicht wiederhergestellt werden konnten und die Verkettung der Ereignisse eines Laufs seine Ausgabe nicht rekonstruieren konnte; Ereignistext trägt jetzt sein ursprüngliches Zeilenende (Leerzeilen werden als Ereignisse angezeigt, die nur das Ende enthalten), wodurch der Sitzungsstrom an den Vordergrund-/command-Vertrag angepasst wird – Verbraucher sollten Ereignistext pro Lauf verketten, anstatt jedes Ereignis als Zeile ohne Zeilenumbruch zu behandeln (#2318)

  • Melden Sie exit_code bei Befehlsfehlern: Ein Befehl, der ungleich Null ausgeführt und beendet wurde, und ein Befehl, dessen Prozess nie gestartet wurde (z. B. fork/exec: argument list too long), meldeten dasselbe Fehlerereignis, sodass clients, die den Exit-Status von evalue lesen, einen Startfehler als Erfolg melden konnten; Das neue optionale error.exit_code ist nur vorhanden, wenn der Prozess ungleich Null ausgeführt und beendet wurde (-1 bei Signalbeendigung) (#2303) – Bereitstellen von binds-Mount-Punkten über die isolierten Sitzungsdateien API: Der Merged-View-Router registrierte nur Overlay-Mounts, sodass session.files mit ErrPathOutsideOverlays an denselben Bindungszielen fehlschlug, die session.run lesen konnte; Jede Bindung registriert jetzt eine geroutete Ansicht (dest → source, schreibgeschützte Bindungen lehnen Schreibvorgänge ab, Bindungsansichten überlagern Schattenüberlagerungen auf Präfixbindungen) (#2299)
  • Befehlsausgabedateien vor dem Aufheben der Verknüpfung abschneiden: Gezweigte untergeordnete Elemente (Daemons) überleben Befehle rechtmäßig, während sie den Ausgabe-FD behalten, sodass eine nicht verknüpfte Datei weiterhin die Festplatte als unsichtbares (deleted)-Wachstum verbrauchte, bis der letzte Inhaber beendet wurde; Jeder vorhandene Löschpunkt wird jetzt zuerst auf Null gekürzt und die Hintergrundausgabe wird nur zum Zeitpunkt der Löschung durch den Hausmeister berührt, sodass das Aufbewahrungsfenster lesbar bleibt (#2295) – Ungültige obere Nutzungsmetriken bei Scanfehlern weglassen: Ein fehlgeschlagener Dateisystemscan hat einen irreführenden execd.isolation.upper.usage_bytes von 0 ausgegeben, während Sitzungen und Daten noch vorhanden waren; Ungültige Messwerte werden jetzt weggelassen (ein gültiger leerer oberer Wert meldet immer noch 0) und die Quotenzulassung schlägt fehl, wenn upper_max_bytes > 0 und ein Scan fehlschlägt, anstatt die Buchhaltung stillschweigend zu umgehen (#2257)
  • Vermeiden Sie redundante JDK-MITM-CA-Importe: Sandboxen mit mehreren installierten JDKs teilen sich oft einen trust-Speicher, aber jedes JDK hat den Keytool-Import erneut ausgeführt (~6.2 s für vier JDKs); Die Initialisierung wird jetzt durch den aufgelösten trust-Speicherpfad mit Zertifikatinhaltsvergleich dedupliziert, wodurch die Phase auf ~0.6 s verkürzt wird, während weiterhin rotierte Zertifikate ersetzt werden (#2310)
  • Standardmäßige PTY-Sitzungen auf TERM=xterm-256color, wenn die aufgelöste Benutzerumgebung kein verwendbares TERM hat, sodass interaktive Programme Farben erhalten; ein explizites TERM gewinnt immer (#2313)

Vernetzung

Ausgang

Die OSEP-0022-Tresorelemente betreffen die Credential-Vault-Oberfläche des Profils fast-sandbox; Die OSEP-0023-Folgemaßnahmen bleiben auf die standardmäßig deaktivierte experimentelle Revisionslaufzeit beschränkt. – Fügen Sie den Egress-gehaltenen Tresor für schnelle Sandboxes (OSEP-0022) hinzu, der in Etappen landet: die interne /vault/{sandboxUid}-Relay-Oberfläche mit Nur-Erstellen-POST (409 bei Duplikat, atomar über Serverreplikate hinweg), Vollrevisions-PUT mit expectedRevision und einer expectedIncarnation-Vorbedingung, damit ein veralteter Writer nie auf dem Nachfolger eines Resets landen kann, werthaltiges GET und DELETE, das die Richtlinie beibehält (#2249); Dauerhafte Persistenz pro Subjekt – eine Datei pro Subjekt unter einem Pod-Volume (optional tmpfs), dasselbe Commit-Protokoll wie Richtliniendateien, daher bedeutet acked dauerhaft und angewendet, inkarnationsgeschütztes Neuladen und Bereinigen beim Aufheben der Bindung (#2252); und die ersetzte Fastlet-Proxy-Vault-Route wurde mit ihrem Pending-Push-Cache entfernt (#2247)

  • Übertragen Sie den Tresor über Pause/Fortsetzen (OSEP-0022 „Vault-Lebenszyklus“): VAULT_EXPORT kopiert die Tresordatei strikt vor dem Herunterfahren zur Laufzeit in das Snapshot-Bundle und versiegelt das Subjekt (alle Vault-Operationen antworten im Pausenzustand mit 409; die Durchsetzung wird fortgesetzt), und VAULT_IMPORT ist die einzige autorisierte Inkarnationsübertragung – das Bundle wird vor data-plane-ready erneut mit dem wiederhergestellten Zaun versehen und gegen den Strom validiert Politik vor jeder dauerhaften Wirkung; Bei einem echten Exportfehler bleibt das Subjekt unversiegelt und der Pause-Prüfpunkt schlägt fehl, sodass der Teardown nie ohne ein Bundle ausgeführt wird und der Egress-Local-Tresor für den erneuten Versuch überlebt (#2255); Ein vaultTransfer-Fähigkeitssignal ermöglicht es einem Ausgang ohne Tresorpersistenz, die Übertragung vollständig zu überspringen – der Prüfpunkt wird ohne den Tresor fortgesetzt (Semantik vor der Übertragung), anstatt fehlzuschlagen (#2290)
  • Definieren Sie die Übernahme veralteter Subjekte bei der Wiederverwendung von Slots: Der Fast-Sandbox-Dispatch-Schlüssel ist die Slot-IP und Slots werden wiederverwendet, sodass ein SET_BINDING einen Schlüssel beanspruchen kann, der noch von einem toten, aber registrierten Subjekt gehalten wird – Egress behandelt dies jetzt als maßgeblich und löscht die NFT-Regeln, die DNS-Refcount, die MITM-Umleitung und den Tresor-Slice des veralteten Subjekts unter der Registrierungssperre, bevor der Nachfolger deny-first registriert wird; Der Datenverkehr wird niemals an veraltete Regeln weitergeleitet, verspätete Entladungen bleiben im No-Ops-Modus geschützt und jeder Fehlerpfad führt dazu, dass jedes Subjekt entweder vollständig registriert oder vollständig entfernt wird (#2250)
  • Anheften der Fast-Sandbox-MITM-CA (OSEP-0022 „MITM Trust-Anker“): Die an den Pool angeheftete, versionierte CA wird von einem schreibgeschützten geheimen Mount in das mitmdump-Konfdir geseedet (idempotent, ausfallsicher auf einem nicht ladbaren Paar) und ersetzt „Generieren beim Start“ – ein Egress-Neustart rotiert die CA nicht mehr und macht das TLS trust jeder Live-Sandbox stillschweigend ungültig; Eine fehlende oder nicht übereinstimmende Zertifizierungsstelle lehnt nur das MITM-Add-on ab (Richtliniendurchsetzung bleibt davon unberührt), wobei mitmCaFingerprint/mitmCaDown auf /healthz und dem Aktionsstatus angezeigt wird, sodass eine falsche Paarung von Vorlage↔Pool-Geheimnissen auf einen Blick sichtbar ist (#2251)
  • Richten Sie die Fast-Sandbox-Netzwerkrichtlinie mit dem Tresormuster aus: Die aufgezeichnete Richtlinie wird in den Status „Austritt gehalten“ umgewandelt – eine /policy/{sandboxUid}-Relay-Oberfläche mit Revisionsvorbedingungen (unbekanntes Subjekt 404, Nichtübereinstimmung der Inkarnation 412, versiegelt 409), dauerhafte Dateien pro Subjekt, die das gleiche Festschreibungsprotokoll verwenden, POLICY_EXPORT/POLICY_IMPORT-Snapshot-Übertragung, die den Tresor spiegelt, und nach einem Neustart des Austritts die festgeschriebene Datei Ersetzt die wiederholte Bindungseingabe zum Erstellungszeitpunkt (#2309) – Unterstützung portbezogener Ausgangsregeln durchgängig (klassisches Profil): NetworkRule.ports (TCP 1–65535, ≤256 pro Regel) macht target optional – Regeln nur für Ports oder Ports kombiniert mit einer IP/CIDR; domain+ports wird abgelehnt, da Domänenregeln auf der DNS-Proxy-Ebene ausgewertet werden. Die Vorrangstellung „Deny-Before-Allow“ gilt für alle Bereiche, und ein PATCH-Merge-Key-Fehler, der es einer zweiten Nur-Port-Regel ermöglichte, die erste zu entfernen, wurde behoben; Eine vom Betreiber bereitgestellte reachable.ports.cap-Whitelist wird als Vorrang vor jeder Benutzerregel erzwungen, sodass selbst defaultAction: allow keinen Port öffnen kann, der nicht auf der Whitelist steht. Die Fast-Sandbox-Route lehnt ports mit 400 ab, bis der Fastlet-NFT-Pfad sie durchsetzen kann (nicht geschlossen, dokumentiert) (#2212) – Fügen Sie der experimentellen Live-Revisionslaufzeit statische TLS-Passthrough-Selektoren hinzu: OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS ist ein begrenztes Exact/Wildcard-Host-Array, das bei ClientHello mit 443-Überlappungs-Ablehnung angewendet wird; vorhandene nicht leere native ignore_hosts/allow_hosts jetzt Start im Live-Modus ablehnen – statische TLS-Bypass-Einträge in das Array migrieren (Legacy-Modus unverändert, kein öffentlicher InterceptionMode hinzugefügt) (#2229) – TLS-Zulassungszähler ausgeben: ein Best-Effort-Ereignis pro finalem ClientHello-Zulassungs-Feed egress.mitm.tls.connections_total mit geschlossenen mode/decision/reason-Labels – es misst Zulassungsentscheidungen, keine Handshakes oder Anfragen, und ist ausdrücklich kein Sicherheitsbeweis (#2265)
  • Fügen Sie die IPC-Grundlage für nur die Installation betreffende Subjektrevision hinzu (OSEP-0023 Phase 4): Ein authentifizierter v2-Unix-Socket-Kanal leitet zielgebundene Revisionstransaktionen an unabhängige Installationsempfänger mit deaktivierter Zulassung weiter, mit eingefrorenen Anforderungsbytes und einem Abgleich verlorener Antworten. Noch kein Produktionsaufrufer (#2284)
  • Versenden Sie egress-trace, einen schreibgeschützten Zulassungsbetrachter im Egress-Image: Live-Richtlinienstatus, NFT-Sets und DNS-Leases mit TTLs, echte ausgehende Verbindungen mit Anmerkungen zu ihrem Zulassungsurteil und einen probe <domain>-Unterbefehl, der die Richtlinienverweigerung vom Resolver-Fehler trennt; Keine Änderung des Sidecar-Verhaltens und entschlüsselte L7-Inhalte werden absichtlich nie angezeigt (#2230)

OpenSandbox release-1.2.0-rc.2

Second release candidate on the 1.2.0 line, carrying everything merged since release-1.2.0-rc.1 — the headline is the Credential Vault (OSEP-0022) landing end to end for fast sandboxes: an egress-held vault with durable per-subject persistence and pause/resume transfer, the user-reachable server-routed vault API, and a pool-pinned MITM CA. Network policy follows the same egress-held pattern, and NetworkRule gains port-scoped rules in the classic profile — fast sandboxes reject them fail-closed until the fastlet nft path enforces them. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject files, sealed snapshot transfer for pause/resume, and stale-subject takeover on slot reuse (#2249 #2252 #2255 #2250); the server exposes the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API over the FastPath handler relay with credential values never appearing on any public read (#2263), and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes (#2251)
  • Network policy mirrors the vault: the recorded fast-sandbox policy becomes egress-held state with relay CRUD, durable persistence, and pause/resume snapshot transfer (#2309), and NetworkRule gains port-scoped rules end to end in the classic profile — spec, sidecar nftables, server validation, and all five SDKs, while fast sandboxes reject ports fail-closed for now — plus an operator-side TCP port floor that no user policy can open (#2212)
  • Lifecycle and diagnostics polish: lifecycle.renewalPolicy replaces the opaque renew extensions key (OSEP-0009) (#2296); the diagnostics context API reaches server, all five SDKs, and the CLI (#2292); execd fixes make start failures distinguishable, preserve session output byte-for-byte, and stop silent disk growth (#2303 #2318 #2295)

Server

  • Implement the server side of the Credential Vault (OSEP-0022, fast-sandbox profile): the user-reachable POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault API pushes complete vault revisions over the FastPath InvokeHandlerAction handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material, and every public read is sanitized server-side; PATCH composes in memory (delete → replace → add, each name resolving at most once) with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret / template_mitm_ca_secret_key config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every server-created template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] create key to a structured renewalPolicy.extendSeconds (300–86400), mirroring the idlePolicy pattern; the legacy key is deprecated (supported throughout 1.x, removed in 2.0), setting both is accepted only when the parsed values match, the value normalizes into the existing Docker label / Kubernetes annotation so pre-upgrade sandboxes keep renewing, and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)
  • Implement the diagnostics context endpoint (OSEP contract from rc.1): GET /v1/sandboxes/{sandboxId}/diagnostics/context returns the sandbox ID, lifecycle state, backend type, and backend-defined identifiers for Docker, Kubernetes, and Fast Sandbox without connecting to execd — Kubernetes context stays available before a Pod is allocated, and extension backends that don't implement it return 501 (#2292)
  • Forward the still-encoded path through the sandbox proxy: Starlette bound the {full_path:path} route from the percent-decoded path and the proxy pasted that value back into the upstream URL, so a decoded ? started a query, # a fragment, %2F became a separator, %25 and non-UTF-8 escapes were rewritten, and %2E%2E segments were resolved — the proxy now takes the client's still-encoded tail from the raw path (validating it decodes to the routed path, with a re-encode fallback) and reads the query from the raw query string; backends receive request targets byte-for-byte, matching the ingress gateway, and the %2E%2E prefix-escape on Docker host-mapped endpoints is closed (#2228)
  • Report BatchSandbox expiry while the pod is still Running: a past spec.expireTime was still reported as Running (Ready pod with IP), so wall-clock billing kept growing after the configured timeout; expiry now checks before the ready states and returns Terminated / SANDBOX_EXPIRED with last_transition_at set to the expireTime itself (#2238)
  • Reject gVisor snapshots that would silently drop writes: docker commit under gVisor's default --overlay2=root:self can report READY while restoring none of the sandbox's writes (only the opaque /.gvisor.filestore.* entry is visible); snapshot preflight now resolves the container's runtime and refuses gVisor unless the effective args include --overlay2=none, and create fails closed when the filesystem diff is filestore-only (#2241)
  • Apply [docker] security profiles and secure_runtime to the execd cache container: it ignored apparmor_profile / seccomp_profile / docker_runtime, so on a host whose default seccomp profile blocks the execd image, every POST /sandboxes failed 503 with no configuration escape (#2254)
  • Make concurrent Docker metadata patches safe: the store's read-modify-write was unlocked and every write shared one temporary name, so two concurrent PATCH /metadata requests for a sandbox raced into a 500 (FileNotFoundError on rename) or silently dropped the other's key; a store-wide lock plus per-write temp names serialize patches (last write wins per key), a failed write no longer leaves its temp file behind, and the endpoint contract is now documented per runtime — Kubernetes patches write back the whole label set it read, fsb patches send only their own keys fenced by UID and generation (#2267 #2281)
  • Resolve proxy endpoints off the event loop: HTTP/WebSocket proxy handlers called the synchronous get_endpoint directly — a Docker socket call per proxied request on Docker, an apiserver read on Kubernetes cache misses — blocking the loop for every other request and stream; a slow Docker daemon (e.g. during an image pull) was enough to freeze the server; the lookup now runs via asyncio.to_thread with tenant context preserved (#2268)
  • Apply the renew cooldown when the Redis consumer is enabled: proxy renews skipped min_interval_seconds entirely (every proxied request ran a get_sandbox + expiration renew) and queue intents were only throttled per ingress replica, so N replicas renewed up to N times per interval; the cooldown now applies to every renew source and starts only after a successful renew (#2276 #2279)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the Credential Vault client contract to all five SDKs (OSEP-0022): template-backed sandboxes route vault calls through the server on the same template-origin signal as network policy (OPEN-SANDBOX-ORIGIN: template or the local createFromTemplate flag), while sidecar-direct adapters stay untouched; Python's Sandbox.credential_vault now returns the vault service for both profiles, and Go gains Sandbox-level vault methods branching on the same signal (#2263)
  • Add lifecycle.renewalPolicy to all five SDKs (OSEP-0009): a typed create field with client-side fail-fast validation (extendSeconds 300–86400) wired through the create converters, replacing the opaque extensions key (#2296)
  • Implement diagnostics across the SDK surface (with #2292): context is exposed through both the manager and sandbox facades in all five languages, and JavaScript, Go, and C# gain public logs/events APIs matching the existing Python/JVM surface (custom factories keep working — the new diagnostics service is optional)
  • Support port-scoped egress rules in all five SDKs (#2212): NetworkRule.ports (TCP 1–65535, at most 256 per rule, target now optional) with client-side validation mirroring the server (range, duplicates, cap, domain+ports rejected, netmask-CIDR+ports rejected); JavaScript encodes the target-or-ports invariant as a union type, Python normalizes a blank wire target on read-back

Python

  • Stop propagating a cancelled endpoint fetch to waiters: the shared-fetch endpoint cache set the fetching caller's CancelledError on the shared future, so concurrent waiters — e.g. TaskGroup siblings — raised CancelledError though nothing cancelled them; waiters now re-resolve (cached endpoint, newer in-flight fetch, or their own), while the cancelled caller still raises as before (#2277)
  • Forward credential_proxy through sandbox pools: PoolCreationSpec.credential_proxy was dropped by both sync and async creation paths, so warmup and direct-create sandboxes silently lost the requested credential-proxy configuration; custom factories stay compatible (the keyword is omitted when unset) (#2283)
  • Regenerate the lifecycle client to drop stale hardcoded defaults (timeout_seconds: 2, wake_on_access: true → UNSET) left behind by the spec change in #2212; wire behavior is unchanged — the server applies the same defaults (#2280)

Go

  • Authenticate proxied data-plane requests with the API key: proxy mode sent the tenant API key — a credential that can create, pause, and delete every sandbox of the tenant — into the untrusted sandbox as X-EXECD-ACCESS-TOKEN (and as egress auth) while omitting the OPEN-SANDBOX-API-KEY header the server middleware reads, so multi-tenant proxy requests failed 401 and surfaced as readiness timeouts; the tenant key now rides the server header and is never smuggled into the sandbox or egress sidecar, endpoint-supplied and caller-supplied proxy keys win regardless of casing, and direct mode stays key-free (#2274)

Controller

  • Fix task-executor treating an empty exit file as exit code 0: the shim creates the exit file before writing it, and Inspect ignored the parse error — a shim killed in between (or a failed write, e.g. full disk) reported a failed or interrupted task as Succeeded; an invalid or empty file now falls through to the pid check (Running while alive, ProcessCrashed once gone) (#2270)

Execd

  • Preserve bash session output line endings: run_in_session stdout events dropped \n/\r bytes, so blank lines were unrecoverable and concatenating a run's events did not reconstruct its output; event text now carries its original line ending (blank lines surface as events containing only the ending), aligning the session stream with the foreground /command contract — consumers should concatenate event text per run instead of treating each event as a newline-free line (#2318)
  • Report exit_code on command errors: a command that ran and exited non-zero and a command whose process never started (e.g. fork/exec: argument list too long) reported the same error event, so clients reading the exit status from evalue could report a start failure as success; the new optional error.exit_code is present only when the process ran and finished non-zero (-1 on signal termination) (#2303)
  • Serve binds mount points through the isolated session files API: the merged-view router only registered overlay mounts, so session.files failed with ErrPathOutsideOverlays on the same bind destinations that session.run could read; each bind now registers a routed view (dest → source, read-only binds reject writes, bind views shadow overlays on prefix ties) (#2299)
  • Truncate command output files before unlink: forked children (daemons) legitimately outlive commands while holding the output fd, so an unlinked file kept consuming disk as invisible (deleted) growth until the last holder exited; every existing deletion point now truncates to zero first, and background output is only touched at janitor deletion time so the retention window stays readable (#2295)
  • Omit invalid upper-usage metrics on scan errors: a failed filesystem scan emitted a misleading execd.isolation.upper.usage_bytes of 0 while sessions and data still existed; invalid readings are now omitted (a valid empty upper still reports 0), and quota admission fails closed when upper_max_bytes > 0 and a scan fails instead of silently bypassing accounting (#2257)
  • Avoid redundant JDK MITM CA imports: sandboxes with several installed JDKs often share one trust store, but each JDK re-ran the keytool import (~6.2 s for four JDKs); initialization is now deduplicated by resolved trust-store path with certificate-content comparison, cutting the stage to ~0.6 s while still replacing rotated certificates (#2310)
  • Default PTY sessions to TERM=xterm-256color when the resolved user environment has no usable TERM, so interactive programs get colors; an explicit TERM always wins (#2313)

Networking

egress

The OSEP-0022 vault items concern the fast-sandbox profile's credential-vault surface; the OSEP-0023 follow-ups remain scoped to the default-off experimental revision runtime.

  • Add the egress-held vault for fast sandboxes (OSEP-0022), landing in stages: the internal /vault/{sandboxUid} relay surface with create-only POST (409 on duplicate, atomic across server replicas), full-revision PUT with expectedRevision and an expectedIncarnation precondition so a stale writer can never land on a reset's successor, value-including GET, and DELETE that keeps the policy (#2249); durable per-subject persistence — one file per subject under a Pod-scoped volume (optional tmpfs), the same commit protocol as policy files so acked means durable and applied, incarnation-fenced reload, and purge on unbind (#2252); and the superseded fastlet-proxy vault route removed with its pending-push cache (#2247)
  • Carry the vault across pause/resume (OSEP-0022 "Vault Lifecycle"): VAULT_EXPORT copies the vault file into the snapshot bundle strictly before runtime teardown and seals the subject (all vault ops answer 409 while paused; enforcement continues), and VAULT_IMPORT is the only authorized incarnation transfer — the bundle re-stamps with the restored fence before data-plane-ready, validated against the current policy before any durable effect; a genuine export failure leaves the subject unsealed and fails the pause checkpoint, so teardown never runs without a bundle and the egress-local vault survives for the retry (#2255); a vaultTransfer capability signal lets an egress without vault persistence skip the transfer entirely — the checkpoint proceeds without the vault (pre-transfer semantics) instead of failing (#2290)
  • Define stale-subject takeover on slot reuse: the fast-sandbox dispatch key is the slot IP and slots are reused, so a SET_BINDING can claim a key still held by a dead-but-registered subject — egress now treats that as authoritative, tearing down the stale subject's nft rules, DNS refcount, MITM redirect, and vault slice under the registry lock before registering the successor deny-first; traffic is never dispatched to stale rules, late unloads stay fence-guarded no-ops, and every failure path leaves each subject either fully registered or fully evicted (#2250)
  • Pin the fast-sandbox MITM CA (OSEP-0022 "MITM Trust Anchor"): the pool-pinned, versioned CA is seeded from a read-only secret mount into the mitmdump confdir (idempotent, fail-closed on an unloadable pair), replacing generate-on-start — an egress restart no longer rotates the CA and silently invalidates every live sandbox's TLS trust; a missing or mismatched CA refuses only the MITM addon (policy enforcement unaffected) with mitmCaFingerprint / mitmCaDown surfaced on /healthz and the actions status, so a template↔pool Secret mispairing is visible at a glance (#2251)
  • Align the fast-sandbox network policy with the vault pattern: the recorded policy becomes egress-held state — a /policy/{sandboxUid} relay surface with revision preconditions (unknown subject 404, incarnation mismatch 412, sealed 409), durable per-subject files using the same commit protocol, POLICY_EXPORT/POLICY_IMPORT snapshot transfer mirroring the vault, and, after an egress restart, the committed file superseding the replayed create-time binding input (#2309)
  • Support port-scoped egress rules end to end (classic profile): NetworkRule.ports (TCP 1–65535, ≤256 per rule) makes target optional — port-only rules, or ports combined with an IP/CIDR; domain+ports is rejected since domain rules evaluate at the DNS proxy layer; deny-before-allow precedence holds across scoping, and a PATCH merge-key bug that let a second port-only rule evict the first is fixed; an operator-shipped reachable.ports.cap whitelist is enforced as an always-deny ahead of every user rule so even defaultAction: allow cannot open a non-whitelisted port; the fast-sandbox route rejects ports with 400 until the fastlet nft path can enforce them (fail-closed, documented) (#2212)
  • Add static TLS passthrough selectors to the experimental live-revision runtime: OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS is a bounded exact/wildcard host array applied at ClientHello with 443-overlap rejection; existing nonempty native ignore_hosts/allow_hosts now reject startup in live mode — migrate static TLS bypass entries to the array (legacy mode unchanged, no public interceptionMode added) (#2229)
  • Emit TLS admission counters: one best-effort event per final ClientHello admission feeds egress.mitm.tls.connections_total with closed mode/decision/reason labels — it measures admission decisions, not handshakes or requests, and is explicitly not security evidence (#2265)
  • Add the installation-only subject revision IPC foundation (OSEP-0023 Phase 4): an authenticated v2 Unix-socket channel routes target-bound revision transactions to independent, admission-disabled installation receivers with frozen request bytes and lost-reply reconciliation; no production caller yet (#2284)
  • Ship egress-trace, a read-only admission viewer inside the egress image: live policy state, nft sets and DNS leases with TTLs, real outbound connections annotated with their admission verdict, and a probe <domain> subcommand separating policy denial from resolver failure; no sidecar behavior change, and decrypted L7 contents are deliberately never shown (#2230)

Misc

  • Console: land the third of five planned console PRs — admin and platform ops, with /api/admin/sandboxes aggregation, per-tenant detail proxying, a pools API (documented as not tenant-isolated), and admin global sandbox list / pools / overview KPIs in the web UI (#2131); preserve empty successful upstream responses in the BFF proxy instead of failing JSON decode on 200/201/205 (#2271)
  • CLI: add osb terminal <sandbox-id>, attaching the local terminal to a real PTY inside the sandbox over the execd PTY WebSocket — raw mode with SIGWINCH-driven resize, replay on reconnect, remote exit code propagation, and support for both direct and server-proxy connection modes (interactive TTY, POSIX) (#2313); report out-of-range duration inputs as Click validation errors instead of uncaught OverflowError/ValueError (#2272)
  • OSEPs: OSEP-0022 revised — the vault rides the action binding as an AES-256-GCM-sealed revision on one control channel, with the per-pool pinned CA as the MITM trust anchor (#2174); the planned OpenSandbox runtime driver ask is withdrawn (the firecracker driver ships as-is; deny-first timing replaces the pre-create healthz probe) (#2259); MITM CA namespace distribution becomes an ops-runbook deployment prerequisite instead of a resident sync controller (#2282)
  • Examples: add an all-in-one Docker image for the DeerFlow example bundling the OpenSandbox server (host Docker runtime) and the DeerFlow backend, for one-command workshop starts without a local Python toolchain (#2262)
  • Docs: reflow hard-wrapped markdown prose into single-line paragraphs across 148 files (~7.4k collapsed fragments, rendering unchanged) and codify the prose style rule in AGENTS.md (#2285)
  • Tests/CI: cache Go modules for the five Kubernetes nightly e2e jobs (setup-go silently skipped its cache without a root go.sum, re-downloading the full module graph nightly) (#2306); close the credential-vault happy path in the fast-sandbox smoke — relay CRUD, injection through the real mitm for every auth type, rotation, restart durability, and purge (#2256); dump every fastlet Pod container's logs (including egress) on pause/resume verify failure (#2290)
  • release: bump platform version to 1.2.0-rc.2 across charts and image references

Upgrade & Compatibility

  • Breaking: bash-session stdout event text now includes its original line endings, and blank lines appear as events — consumers must concatenate event text per run to recover exact output instead of treating each event as a newline-free line (#2318)
  • Behavior change: a BatchSandbox past its spec.expireTime now reports Terminated / SANDBOX_EXPIRED instead of Running, even while the pod is still Ready — callers that treat Running as alive should check expiry (#2238)
  • Behavior change: Docker-backed snapshots of gVisor containers without --overlay2=none are rejected with SNAPSHOT::UNSUPPORTED_RUNTIME (409) instead of publishing a silently incomplete image (#2241)

  • Behavior change: execd upper-directory quota admission fails closed when upper_max_bytes > 0 and a usage scan fails (previously the quota check was silently bypassed) (#2257)
