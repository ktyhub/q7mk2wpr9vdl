hermes-agent v2026.3.30

Hermes Agent v0.6.0 (v2026.3.30)

Veröffentlichungsdatum: 30. März 2026

Die Multi-Instanz-Version – Profile zum Ausführen isolierter Agenteninstanzen, MCP-Servermodus, Docker-Container, Fallback-Anbieterketten, zwei neue Messaging-Plattformen (Feishu/Lark und WeCom), Telegram-Webhook-Modus, Slack Multi-Workspace OAuth, 95 PRs und 16 gelöste Probleme in 2 Tagen.

✨ Highlights

  • Profile – Multi-Instanz-Hermes – Führen Sie mehrere isolierte Hermes-Instanzen von derselben Installation aus. Jedes Profil erhält seine eigene Konfiguration, seinen eigenen Speicher, seine eigenen Sitzungen, seine eigenen Fähigkeiten und seinen eigenen Gateway-Dienst. Erstellen mit hermes profile create, Wechseln mit hermes -p <name>, Export/Import zum Teilen. Die vollständige Token-Lock-Isolierung verhindert, dass zwei Profile dieselben Bot-Anmeldeinformationen verwenden. (#3681)
  • MCP-Servermodus – Stellen Sie Hermes-Konversationen und -Sitzungen über hermes mcp serve jedem MCP-kompatiblen client (Claude Desktop, Cursor, VS Code usw.) zur Verfügung. Durchsuchen Sie Konversationen, lesen Sie Nachrichten, suchen Sie sitzungsübergreifend und verwalten Sie Anhänge – alles über das Model Context Protocol. Unterstützt sowohl stdio- als auch streambare HTTP-Transporte. (#3795)
  • Docker Container – Offizielle Docker-Datei zum Ausführen von Hermes Agent in einem Container. Unterstützt sowohl den CLI- als auch den Gateway-Modus mit Volume-montierter Konfiguration. (#3668, schließt #850)
  • Geordnete Fallback-Anbieterkette – Konfigurieren Sie mehrere Inferenzanbieter mit automatischem Failover. Wenn Ihr primärer Anbieter Fehler meldet oder nicht erreichbar ist, versucht Hermes automatisch den nächsten Anbieter in der Kette. Konfigurieren Sie über fallback_providers in config.yaml. (#3813, schließt #1734)
  • Unterstützung der Feishu/Lark-Plattform – Vollständiger Gateway-Adapter für Feishu (飞书) und Lark mit Veranstaltungsabonnements, Nachrichtenkarten, Gruppenchat, Bild-/Dateianhängen und interaktiven Kartenrückrufen. (#3799, #3817, schließt #1788)
  • Unterstützung der WeCom-Plattform (Enterprise WeChat) – Neuer Gateway-Adapter für WeCom (企业微信) mit Text-/Bild-/Sprachnachrichten, Gruppenchats und Rückrufüberprüfung. (#3847)
  • Slack Multi-Workspace OAuth – Verbinden Sie ein einzelnes Hermes-Gateway über eine OAuth-Token-Datei mit mehreren Slack-Workspaces. Jeder Arbeitsbereich erhält sein eigenes Bot-Token, das dynamisch pro eingehendem Ereignis aufgelöst wird. (#3903)
  • Telegram-Webhook-Modus und Gruppensteuerung – Führen Sie den Telegram-Adapter im Webhook-Modus als Alternative zum Polling aus – schnellere Antwortzeiten und besser für Produktionsbereitstellungen hinter einem Reverse-Proxy. Neue Gruppenerwähnungs-Gating-Kontrollen, wenn der Bot antwortet: immer, nur wenn @erwähnt wird oder über Regex-Trigger. (#3880, #3870)
  • Exa Search Backend – Fügen Sie Exa als alternatives Backend für die Websuche und Inhaltsextraktion neben Firecrawl und DuckDuckGo hinzu. Legen Sie EXA_API_KEY fest und konfigurieren Sie es als bevorzugtes Backend. (#3648)
  • Skills und Anmeldeinformationen auf Remote-Backends – Hängen Sie Skill-Verzeichnisse und Anmeldeinformationsdateien in Modal- und Docker-Containern ein, sodass Remote-Terminalsitzungen Zugriff auf dieselben Skills und Geheimnisse haben wie bei der lokalen Ausführung. (#3890, #3671, schließt #3665, #3433)

🏗️ Kernagent und Architektur

Anbieter- und Modellunterstützung

– Geordnete Fallback-Anbieterkette – automatisches Failover über mehrere konfigurierte Anbieter hinweg (#3813)

  • Behebung von api_mode beim Anbieterwechsel – Beim Anbieterwechsel über hermes model werden veraltete api_mode jetzt ordnungsgemäß gelöscht, anstatt chat_completions fest zu codieren. Dadurch werden 404-Fehler für Anbieter mit Anthropic-kompatiblen Endpunkten behoben (#3726, #3857, schließt #3685)
  • Stillen OpenRouter-Fallback stoppen – wenn kein Anbieter konfiguriert ist, gibt Hermes jetzt einen eindeutigen Fehler aus, anstatt stillschweigend an OpenRouter weiterzuleiten (#3807, #3862)
  • Gemini 3.1-Vorschaumodelle – zu OpenRouter- und Nous Portal-Katalogen hinzugefügt (#3803, schließt #3753) – Gemini direkte API-Kontextlänge – vollständige Kontextlängenauflösung für direkte Google AI-Endpunkte (#3876) – gpt-5.4-mini zum Codex-Fallback-Katalog hinzugefügt (#3855)
  • Kuratierte Modelllisten bevorzugt gegenüber der Live-Probe API, wenn die Probe weniger Modelle zurückgibt (#3856, #3867)
  • Benutzerfreundliche 429-Rate-Limit-Meldungen mit Retry-After-Countdown (#3809) – Hilfsplatzhalterschlüssel client für lokale Server ohne Authentifizierungsanforderungen (#3842) – Protokollierung auf INFO-Ebene für die Auflösung von Hilfsanbietern (#3866)

Agentenschleife und Konversation

Profile und Multiinstanzen

  • Profilsystem – hermes profile create/list/switch/delete/export/import/rename. Jedes Profil erhält einen isolierten HERMES_HOME, Gateway-Dienst und CLI-Wrapper. Token-Sperren verhindern Kollisionen bei Anmeldeinformationen. Tab-Vervollständigung für Profilnamen. (#3681)

hermes-agent v2026.3.30

Hermes Agent v0.6.0 (v2026.3.30)

Release Date: March 30, 2026

The multi-instance release — Profiles for running isolated agent instances, MCP server mode, Docker container, fallback provider chains, two new messaging platforms (Feishu/Lark and WeCom), Telegram webhook mode, Slack multi-workspace OAuth, 95 PRs and 16 resolved issues in 2 days.

✨ Highlights

  • Profiles — Multi-Instance Hermes — Run multiple isolated Hermes instances from the same installation. Each profile gets its own config, memory, sessions, skills, and gateway service. Create with hermes profile create, switch with hermes -p <name>, export/import for sharing. Full token-lock isolation prevents two profiles from using the same bot credential. (#3681)

  • MCP Server Mode — Expose Hermes conversations and sessions to any MCP-compatible client (Claude Desktop, Cursor, VS Code, etc.) via hermes mcp serve. Browse conversations, read messages, search across sessions, and manage attachments — all through the Model Context Protocol. Supports both stdio and Streamable HTTP transports. (#3795)

  • Docker Container — Official Dockerfile for running Hermes Agent in a container. Supports both CLI and gateway modes with volume-mounted config. (#3668, closes #850)

  • Ordered Fallback Provider Chain — Configure multiple inference providers with automatic failover. When your primary provider returns errors or is unreachable, Hermes automatically tries the next provider in the chain. Configure via fallback_providers in config.yaml. (#3813, closes #1734)

  • Feishu/Lark Platform Support — Full gateway adapter for Feishu (飞书) and Lark with event subscriptions, message cards, group chat, image/file attachments, and interactive card callbacks. (#3799, #3817, closes #1788)

  • WeCom (Enterprise WeChat) Platform Support — New gateway adapter for WeCom (企业微信) with text/image/voice messages, group chats, and callback verification. (#3847)

  • Slack Multi-Workspace OAuth — Connect a single Hermes gateway to multiple Slack workspaces via OAuth token file. Each workspace gets its own bot token, resolved dynamically per incoming event. (#3903)

  • Telegram Webhook Mode & Group Controls — Run the Telegram adapter in webhook mode as an alternative to polling — faster response times and better for production deployments behind a reverse proxy. New group mention gating controls when the bot responds: always, only when @mentioned, or via regex triggers. (#3880, #3870)

  • Exa Search Backend — Add Exa as an alternative web search and content extraction backend alongside Firecrawl and DuckDuckGo. Set EXA_API_KEY and configure as preferred backend. (#3648)

  • Skills & Credentials on Remote Backends — Mount skill directories and credential files into Modal and Docker containers, so remote terminal sessions have access to the same skills and secrets as local execution. (#3890, #3671, closes #3665, #3433)

🏗️ Core Agent & Architecture

Provider & Model Support

  • Ordered fallback provider chain — automatic failover across multiple configured providers (#3813)
  • Fix api_mode on provider switch — switching providers via hermes model now correctly clears stale api_mode instead of hardcoding chat_completions, fixing 404s for providers with Anthropic-compatible endpoints (#3726, #3857, closes #3685)
  • Stop silent OpenRouter fallback — when no provider is configured, Hermes now raises a clear error instead of silently routing to OpenRouter (#3807, #3862)
  • Gemini 3.1 preview models — added to OpenRouter and Nous Portal catalogs (#3803, closes #3753)
  • Gemini direct API context length — full context length resolution for direct Google AI endpoints (#3876)
  • gpt-5.4-mini added to Codex fallback catalog (#3855)
  • Curated model lists preferred over live API probe when the probe returns fewer models (#3856, #3867)
  • User-friendly 429 rate limit messages with Retry-After countdown (#3809)
  • Auxiliary client placeholder key for local servers without auth requirements (#3842)
  • INFO-level logging for auxiliary provider resolution (#3866)

Agent Loop & Conversation

  • Subagent status reporting — reports completed status when summary exists instead of generic failure (#3829)
  • Session log file updated during compression — prevents stale file references after context compression (#3835)
  • Omit empty tools param — sends no tools parameter when empty instead of None, fixing compatibility with strict providers (#3820)

Profiles & Multi-Instance
