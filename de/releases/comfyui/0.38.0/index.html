ComfyUI v0.38.0

Highlights

  • Qwen-Image 2.1 gets faster and more configurable — Transformer-block compilation, improved KV-cache placement, tiny-VAE support, and union FUN ControlNet reduce latency and VRAM pressure while expanding conditioning options. FP16 activations are now clamped in place to prevent overflow; check output parity for numerically sensitive pipelines (#16430, #16552, #16519, #16608).
  • Attention backends move into model metadata — Model files can specify the attention implementation for each block (#16419), enabling per-block choices instead of one global path. Lumina and Flux also gain comfy_attention optimizations, alongside w6a8 quantization and NPU async weight-offload streams for memory-constrained deployments (#16515, #16488, #16483, #16057).
  • TextGenerate separates instructions from reasoning — A new system_prompt input and dedicated thinking output give LLM workflows finer control. Migrate any logic that extracted reasoning from generated text to use the thinking output directly (#16442). Partner integrations also add Arrow 2 reasoning-effort control, GPT-6 Sol/Luna, Claude Opus 5.5, Seedream 5.0 Flash, and Seedance 2.5 Draft.
  • HDR and image handling are hardened — Convert Color Space adds LogC3 and ACEScct support and fixes negative-value handling. RGBA inputs no longer crash Qwen-VL preprocessing or model upscaling, while H3 VAE tile blending reduces seams during tiled decoding (#16541, #16565, #16548, #16500, #16436).
  • Asset scans are safer and less blocking — Earlier write-lock acquisition, reads moved outside write transactions, and folder-based scanning reduce database contention and UI stalls. With --enable-assets, missing asset packages now produce a clear warning and disable assets instead of blocking startup (#16480, #16486, #16546, #16580).
  • Breaking removals require cleanup — Deprecated Sora nodes have been removed, so workflows referencing them must migrate to supported nodes (#16609). torchaudio is no longer bundled; custom nodes that import it must declare and install the dependency themselves (#16457).
