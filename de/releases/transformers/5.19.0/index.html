Neue Modellergänzungen

EmbeddingGemma2

<img width="2716" height="2308" alt="image" src="https://github.com/user-attachments/assets/84734e74-163d-4d12-b166-ffcf6749d563" />

EmbeddingGemma 2 ist ein multimodales Einbettungsmodell von Google, das auf der Gemma 4-Architektur basiert. Es kodiert Text, Bilder, Audio und Video, einzeln oder kombiniert in einer Eingabe, in einen gemeinsamen 768-dimensionalen Vektorraum für modalübergreifenden Abruf, semantische Ähnlichkeit, Clustering und Klassifizierung. Es nutzt Matryoshka Representation Learning, sodass Einbettungen auf 512, 256 oder 128 Dimensionen gekürzt werden können. Es bietet außerdem konfigurierbare visuelle und Video-Token-Budgets und ungenutzte Bild- oder Audiotürme können beim Laden deaktiviert werden, um Speicherplatz zu sparen.

Links: Dokumentation

  • Smthn smthn (#49364) von @vasqu in #49364

Breaking Changes

Alle MoE-Modelle, deren Router Protokolle berechnen, geben diese jetzt zurück, wenn output_router_logits=True, nach dem Qwen3-MoE-Muster (ein router_logits-Recorder auf dem Basismodell, MoeModelOutputWithPast vom Backbone und ein MoE-kausaler LM-Ausgang vom Kopf), sodass Code, der sich auf die vorherigen Ausgaben oder deren Abwesenheit stützte, die Router-Protokolle aus diesen Ausgabeklassen lesen sollte.

  • 🚨 Router-Logits von jedem MoE-Modell zurückgeben, das sie berechnet (#48920) von @qgallouedec

Owlv2ForObjectDetection.embed_image_query wählt jetzt wie im ursprünglichen OWLv2-Notizbuch anstelle der OWL-ViT-Heuristik das Abfragefeld mit der höchsten Objektivitätsbewertung aus, sodass bildgesteuerte Abfrageeinbettungen und -erkennungen möglicherweise von früheren Versionen abweichen.

  • 🚨 Wählen Sie die OWLv2-Bildabfrage nach Objektivität (#49200) von @qgallouedec

Das Präfix "paged|" für SDPA- und Flash-Attention-Implementierungen ist veraltet, daher sollten Benutzer die reguläre Attention-Implementierung (z. B. sdpa oder flash_attention_2) für kontinuierliche Stapelverarbeitung anstelle von paged|sdpa oder paged|flash_attention_2 festlegen.

  • 🚨 Achtung 🚨 „paged|“ ablehnen Präfix für SDPA und Flash (#49112) von @remi-or

Die regulären Flash- und SDPA-Aufmerksamkeitsfunktionen (flash_attention.py, sdpa_attention.py) unterstützen jetzt kontinuierliches Batching direkt, und "paged|..."-Implementierungen für diese werden auf sie umgeleitet, während Eager weiterhin das Präfix "paged|eager" erfordert.

  • 🚨 Achtung 🚨 Machen Sie regelmäßig auf sich aufmerksam und unterstützen Sie CB (#49101) von @remi-or

Beim kontinuierlichen Batching wird die Cache-Aktualisierung für die indexbasierten und Blocktabellenpfade jetzt in einem einzigen Aufruf zusammengefasst, was das Verhalten der Cache-Aktualisierungsfunktion geringfügig ändert und sich auf jeden benutzerdefinierten Code auswirkt, der die separaten Aktualisierungspfade aufruft.

  • 🚨 [CB] 🚨 Sicherungsaktualisierung für Index- und Blocktabellenpfad (#49088) von @remi-or

Kontinuierliche Batch-Einbauten wurden in Vorbereitung auf die Entfernung von "paged" geändert: „max

  • 🚨 [CB] 🚨 Kleine Korrekturen vor dem Entfernen von „paged“ (#49069) von @remi-or

Parallelisierung

Expertenparallelität erhält eine Token-Dispatch-Implementierung, die über die neue Planregel ep_dispatch_experts ausgewählt wird und jetzt die Standardeinstellung für Qwen3 MoE und Mellum ist, wodurch die Anforderung entfällt, dass die EP-Größe der TP-Größe entsprechen muss. Der Trainer wurde auch für die Arbeit mit Expertenparallelität angepasst, und in den Dokumenten wird nun darauf hingewiesen, dass PEFT-Adapter Tensorparallelität unterstützen. Ein CI-bezogener Fix für die Pipeline-parallele Chart2Table-Inferenz war ebenfalls enthalten.

  • [distributed]: Trainer an die Arbeit mit Expert Parallel (#48873) von @3outeille in [#48873] anpassen
  • [distributed] Expert-parallelen Token-Versand hinzufügen, Standard für Qwen3 MoE (#48865) von @3outeille in [#48865]
  • PP-Chart2table-Inferenz (#49225) von @zucchini-nlp in [#49225] behoben
  • [docs] TP für PEFT-Adapter (#49060) von @stevhliu in [#49060]

Cache

Diese Version behebt die Handhabung des quantisierten Caches: generate mutiert nicht mehr den cache_config des Benutzers und QuantizedLayer.reorder_cache ist repariert. Außerdem wird eine Cache-Konfiguration pro Ebene hinzugefügt, sodass DynamicCache und StaticCache jede Ebene über ihre eigene Konfiguration initialisieren (gleitendes Fenster, Aufmerksamkeitsblockgröße, Conv-Status und Aufmerksamkeitskopfanzahl), um heterogene Modelle besser zu unterstützen. New Model additions

EmbeddingGemma2

<img width="2716" height="2308" alt="image" src="https://github.com/user-attachments/assets/84734e74-163d-4d12-b166-ffcf6749d563" />

EmbeddingGemma 2 is a multimodal embedding model from Google built on the Gemma 4 architecture. It encodes text, images, audio, and video, individually or combined in one input, into a shared 768-dimensional vector space for cross-modal retrieval, semantic similarity, clustering, and classification. It uses Matryoshka Representation Learning, so embeddings can be truncated to 512, 256, or 128 dimensions. It also offers configurable visual and video token budgets, and unused vision or audio towers can be disabled at load time to save memory.

Links: Documentation

  • Smthn smthn (#49364) by @vasqu in #49364

Breaking changes

All MoE models whose routers compute logits now return them when output_router_logits=True, following the Qwen3-MoE pattern (a router_logits recorder on the base model, MoeModelOutputWithPast from the backbone, and a MoE causal LM output from the head), so code that relied on the previous outputs or their absence should read the router logits from these output classes.

  • 🚨 Return router logits from every MoE model that computes them (#48920) by @qgallouedec

Owlv2ForObjectDetection.embed_image_query now selects the query box with the highest objectness score, as in the original OWLv2 notebook, instead of the OWL-ViT heuristic, so image-guided query embeddings and detections may differ from earlier releases.

  • 🚨 Select the OWLv2 image query by objectness (#49200) by @qgallouedec

The "paged|" prefix for SDPA and flash attention implementations is deprecated, so users should set the regular attention implementation (e.g. sdpa or flash_attention_2) for continuous batching instead of paged|sdpa or paged|flash_attention_2.

  • 🚨 Attention 🚨 Deprecate "paged|" prefix for SDPA and flash (#49112) by @remi-or

The regular flash and SDPA attention functions (flash_attention.py, sdpa_attention.py) now support continuous batching directly, and "paged|..." implementations for these are redirected to them, while eager still requires the "paged|eager" prefix.

  • 🚨 Attention 🚨 Make regular attention support CB (#49101) by @remi-or

In continuous batching, the cache update for the index-based and block-table paths is now fused into a single call, which slightly changes the cache update function's behavior and affects any custom code that calls the separate update paths.

  • 🚨 [CB] 🚨 Fuse update for index and block table path (#49088) by @remi-or

Continuous batching internals changed in preparation for removing "paged": `max

  • 🚨 [CB] 🚨 Little fixes before removing "paged" (#49069) by @remi-or

Parallelization

Expert parallelism gains a token-dispatch implementation, selected via the new ep_dispatch_experts plan rule and now the default for Qwen3 MoE and Mellum, which removes the requirement that EP size equal TP size. The Trainer was also adapted to work with expert parallelism, and the docs now note that PEFT adapters support tensor parallelism. A CI-related fix for pipeline-parallel chart2table inference was also included.

  • [distributed]: adapt Trainer to work Expert Parallel (#48873) by @3outeille in [#48873]
  • [distributed] Add expert-parallel token dispatch, default for Qwen3 MoE (#48865) by @3outeille in [#48865]
  • Fix pp chart2table inference (#49225) by @zucchini-nlp in [#49225]
  • [docs] TP for PEFT adapters (#49060) by @stevhliu in [#49060]

Cache

This release fixes quantized cache handling: generate no longer mutates the user's cache_config, and QuantizedLayer.reorder_cache is repaired. It also adds per-layer cache configuration, so DynamicCache and StaticCache initialize each layer from its own config (sliding window, attention chunk size, conv states, and attention head counts) to better support heterogeneous models.
