CC-Schalter v4.0.39

CC-Schalter v4.0.39

Diese Version ist hauptsächlich für Reparaturen gedacht. Dem API-Schlüsseleingabefeld wurde eine Schaltfläche zum Kopieren hinzugefügt. Backup kann die Obergrenze der Gesamtgröße festlegen. Wenn die Grenze überschritten wird, wird sie aus der ältesten Datei gelöscht. Wenn Claude Code GPT-6.2 Sol / Astra über Codex OAuth verwendet, wird die vom System angezeigte Cache-Trefferrate erheblich verbessert. Darüber hinaus wurden die nativen Anbieter von Claude Code und Claude Desktop behoben und müssen bis zu 600 Sekunden vor dem Failover warten; Eine lange Streaming-Antwort führt dazu, dass der durch Nutzung und Protokollsammlung belegte Speicher immer größer wird. Es wird immer noch ein Bestätigungsfeld angezeigt, nachdem die Konfiguration zum Zusammenführen von Importlinks mit einem Klick fehlgeschlagen ist. Wenn nur die Codex-Desktopversion installiert ist, wird auf der Plug-in-Seite „Codex ist nicht installiert“ angezeigt. die Plug-in-Seite erstellt einen leeren Konfigurationsordner für deinstallierte Anwendungen; OpenCode Gos DeepSeek V4.1 Flash fehlt max Nachdenken über Zahnräder; Probleme wie Popup-Ebenen und Dropdown-Menüs flackern, wenn schnell darauf geklickt wird. Hinzufügen

API Schlüsseleingabefeld kann mit einem Klick kopiert werden

Neben dem Eingabefeld „API-Schlüssel“ im Lieferantenformular befindet sich eine Schaltfläche zum Kopieren (#9232). Was kopiert wird, ist der Schlüssel, wobei die führenden und nachgestellten Leerzeichen entfernt wurden. Erfolg oder Misserfolg werden angezeigt. Es wird nicht angezeigt, wenn das Eingabefeld leer ist oder nicht bearbeitet werden kann.

Maximale Gesamtsicherungsgröße

Den Sicherungseinstellungen wurde eine neue „Maximale Gesamtsicherungsgröße“ hinzugefügt (#9011, bezogen auf #6706). Die Standardeinstellung ist „Kein Limit“ und nach dem Upgrade wird kein Backup gelöscht.

  • Wenn der Backup-Ordner nach dem Festlegen der Obergrenze diese Größe überschreitet, wird er beginnend mit dem ältesten Backup gelöscht. – Das neueste Backup und das für die Wiederherstellung verwendete Backup bleiben immer erhalten. Wenn also ein einzelnes Backup größer als die Obergrenze ist, kann es sein, dass der Ordner trotzdem die Obergrenze überschreitet.
  • Die Obergrenze wird beim nächsten Backup oder der nächsten täglichen Wartung wirksam. Durch die tägliche Wartung werden auch temporäre Dateien bereinigt, die durch Backup-Abstürze zurückgeblieben sind und älter als 24 Stunden sind.

Ändern

  • Claude Code hat eine höhere Cache-Trefferrate, wenn GPT-6.2 Sol/Astra über Codex OAuth verwendet wird (#9848, siehe #9847): Die Systemaufforderung wird so geändert, dass sie in der ersten Entwicklernachricht platziert wird und das ChatGPT-Backend sie zusammen mit der Konversation zwischenspeichert. Die tatsächliche Trefferquote aus der zweiten Runde liegt bei etwa 98 %. Andere Modelle und Routing mit API-Schlüssel bleiben unverändert.
  • Datenschutzfilter schneller (#9826): Filterergebnisse unverändert.

Fix

  • Wenn der native Anbieter von Claude Code und Claude Desktop hängen bleibt und keine Wörter drucken kann, dauert der Failover bis zu 600 Sekunden (#9754): Diese Art von Streaming-Anfrage nutzt das Timeout von Nicht-Streaming-Anfragen und verwendet nun wie andere Streaming-Anfragen das erste Wort-Timeout (Standard 60 Sekunden). – Lange oder endlose Streaming-Antworten führen dazu, dass die Auslastung und der Speicherverbrauch für die Protokollsammlung weiter ansteigen (#9846, siehe #9843): Der Puffer ist jetzt bis zu 64 MiB groß und kann nach extrem großen Ereignissen mit der Analyse nachfolgender Inhalte fortfahren.
  • Nachdem die Ein-Klick-Import-Link-Zusammenführungskonfiguration fehlschlägt, wird das Bestätigungsfeld weiterhin angezeigt (#9844, siehe #9841): Jetzt wird nur noch ein Fehler angezeigt und das Bestätigungsfeld wird nicht mehr angezeigt.
  • Wenn nur die Desktop-Version von Codex installiert ist, wird auf der Plug-in-Seite „Codex ist nicht installiert“ angezeigt (siehe #9850): Beispielsweise ist unter Windows nur die Desktop-Version von Codex (MSIX) installiert. Wenn nun das separat installierte codex nicht gefunden werden kann, verwenden die Plug-in-Seite und andere Stellen, die die Codex-Befehlszeile verwenden, stattdessen die Seite, die mit der Desktop-Version geliefert wird. Die Installation, Aktualisierung und Deinstallation der Seite „Anwendung“ gelten weiterhin nur für den separat installierten Codex CLI.
  • Die Plug-in-Seite erstellt leere Konfigurationsordner für deinstallierte Anwendungen (siehe #9852): Beim Öffnen der Plug-in-Seite werden auch leere Ordner wie ~/.codex und ~/.grok für nicht installierte Anwendungen wie Codex, Grok Build, OpenClaw, Pi oder MiniMax Code erstellt. Jetzt finde ich das Befehlszeilentool und baue es dann. Wenn es nicht installiert ist, wird weiterhin „nicht installiert“ angezeigt.
  • In DeepSeek V4.1 Flash von OpenCode Go fehlt die max-Denkausrüstung (siehe #9853): Standardmäßig werden in der Modellliste von OpenCode Go jetzt low, high und max aufgeführt. OpenCode kehrt nicht mehr zum universellen low / medium / high zurück.
  • Die Popup-Ebene und das Dropdown-Menü blinken, wenn schnell darauf geklickt wird (#9176, siehe #9175): Durch erneutes Klicken während der Öffnungs- oder Schließanimation wird nicht zweimal hintereinander gewechselt.

Danksagungen

Vielen Dank an @H15teve (GPT-6.2-Cache-Treffer), @minimote (Kopie des API-Schlüssels), @zayokami (maximale Gesamtsicherungsgröße), @vastStage (Timeout für Streaming-Anfragen), @HaiYangBG1 (Streaming-Antwortspeicher, Ein-Klick-Importfehlermeldung, Testisolierung), @YUZHEthefool (Beschleunigung des Datenschutzfilters), @Delta1035 (Flashen der Popup-Ebene), @allenxu09 (Rezensionsänderung), @SaladDay (Codeorganisation). Vielen Dank an @IndexEeve, @Thanatos-Z, @beiqixingnang, @muchenkezhan für die Meldung von Problemen und die Bereitstellung von Reproduktionsinformationen. Ausführliche technische Details finden Sie unter CHANGELOG.

cc-switch v4.0.39

Highlights

  • Claude Code 流式可靠性 — 原生供应商卡住时的故障转移从最长 600 秒降至默认 60 秒的首字超时；长流式响应的用量/日志缓冲限制为 64 MiB，降低内存持续增长的风险。依赖长请求或故障转移的用户值得升级。
  • Codex OAuth 缓存优化 — 仅针对 Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 的路径，系统提示改放入首条 developer 消息，官方实测第二轮起缓存命中率约 98%；其他模型和 API Key 路由不受影响。使用该组合的用户优先升级。
  • 备份大小上限 — 新增可选的「备份总大小上限」，超限时从最旧备份开始删除，但最新备份和正在用于恢复的备份始终保留。默认「不限制」，升级不会自动删除备份；需要控制磁盘占用的用户可配置此选项，但单份备份超过上限时仍可能超限。
  • 插件与模型预设修复 — 仅安装 Codex 桌面版（MSIX）时会回退使用其内置 CLI，打开插件页也不再为未安装应用创建空配置目录；OpenCode Go 的 DeepSeek V4.1 Flash 补齐 low / high / max 思考档位。相关用户值得升级。
  • 小修复与升级建议 — API Key 复制按钮会去除首尾空格并提示复制结果；导入失败不再误弹确认框，快速点击不再导致弹层和菜单闪烁；隐私过滤器提速但结果不变。未发现破坏性变更或必需迁移步骤；未使用相关功能的用户可跳过本次升级。

CC Switch v4.0.39

本版本以修复为主。API Key 输入框加了复制按钮；备份可以设置总大小上限，超过时从最旧的开始删；Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时，系统提示的缓存命中率大幅提高。

另外修复了 Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，要等最长 600 秒才故障转移；很长的流式响应让用量和日志收集占用的内存一直增长；一键导入链接合并配置失败后仍弹出确认框；只装了 Codex 桌面版时，插件页显示「未安装 Codex」；插件页给没装的应用建了空配置文件夹；OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位；快速点击时弹出层和下拉菜单闪烁等问题。

新增

API Key 输入框可以一键复制

供应商表单的 API Key 输入框旁边多了复制按钮（#9232），复制的是去掉首尾空格后的 Key，成功或失败都会提示。输入框为空或不可编辑时不显示。

备份总大小上限

备份设置里新增「备份总大小上限」（#9011，相关 #6706），默认「不限制」，升级后不会删任何备份。

  • 设置上限后，备份文件夹超过这个大小时，会从最旧的备份开始删除。
  • 最新的一份备份和恢复正在使用的备份始终保留，所以单份备份比上限还大时，文件夹仍可能超过上限。
  • 上限在下次备份或每日维护时生效。每日维护还会清理备份中途崩溃留下、超过 24 小时的临时文件。

变更

  • Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时缓存命中率更高（#9848，见 #9847）：系统提示改放在第一条 developer 消息里，ChatGPT 后端会把它和对话一起缓存。实测从第二轮起命中率约 98%。其他模型和用 API Key 的路由不变。
  • 隐私过滤器更快（#9826）：过滤结果不变。

修复

  • Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，最长要等 600 秒才故障转移（#9754）：这类流式请求用的是非流式请求的超时，现在和其他流式请求一样用首字超时（默认 60 秒）。
  • 很长或一直不结束的流式响应，让用量和日志收集占用的内存一直增长（#9846，见 #9843）：缓冲现在最多 64 MiB，遇到超大的事件后也能继续解析后面的内容。
  • 一键导入链接合并配置失败后，仍弹出确认框（#9844，见 #9841）：现在只提示错误，不再弹确认框。
  • 只装了 Codex 桌面版时，插件页显示「未安装 Codex」（见 #9850）：比如 Windows 上只装了 Codex 桌面版（MSIX）。现在找不到单独安装的 codex 时，插件页等用到 Codex 命令行的地方会改用桌面版自带的那份。「应用」页的安装、升级和卸载仍只管单独安装的 Codex CLI。
  • 插件页给没装的应用建了空配置文件夹（见 #9852）：打开插件页时，没装 Codex、Grok Build、OpenClaw、Pi 或 MiniMax Code 也会建出 ~/.codex、~/.grok 等空文件夹。现在找到命令行工具后才建，没装的照常显示「未安装」。
  • OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位（见 #9853）：预设现在按 OpenCode Go 的模型列表写明 low、high、max 三档，OpenCode 不再退回通用的 low / medium / high。
  • 快速点击时，弹出层和下拉菜单闪烁（#9176，见 #9175）：在打开或关闭的动画过程中再点一下，不会再连着切换两次。

致谢

感谢 @H15teve（GPT-6.2 缓存命中）、@minimote（复制 API Key）、@zayokami（备份总大小上限）、@vastStage（流式请求超时）、@HaiYangBG1（流式响应内存、一键导入失败提示、测试隔离）、@YUZHEthefool（隐私过滤器提速）、@Delta1035（弹出层闪烁）、@allenxu09（评审修改）、@SaladDay（代码整理）的贡献。

感谢 @IndexEeve、@Thanatos-Z、@beiqixingnang、@muchenkezhan 报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
