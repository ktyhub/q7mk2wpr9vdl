CC-Schalter v4.0.33

CC-Schalter v4.0.33

Diese Version behebt das Problem, dass nach dem Zurückwechseln zu Claude Official von einem Drittanbieter die bereits geöffnete Claude Code-Sitzung die Anfrage immer noch an den vorherigen Anbieter sendet und die Sitzung zur Wiederherstellung neu gestartet werden muss. Ollama Cloud wurde zur Paketkontingentabfrage hinzugefügt; Antigravity-Kontowechsel im Autorisierungscenter unterstützt jetzt auch Windows. Darüber hinaus hat der Anbieter von Claude Code/Claude Desktop den Bericht „API-Schlüssel ist ungültig oder hat keine Berechtigung“ beim Abrufen der Modellliste bei Auswahl des Gemini Native-Formats behoben; Einige Dienstanbieter werden von Cloudflare daran gehindert, die Modellliste zu erhalten. Einige Anfragen für Antigravity Orchestrator werden immer noch als unbezahlt angezeigt. Die WebDAV-Synchronisierung ist auf einigen NAS überhaupt nicht verfügbar; Bei einem WebDAV/S3-Upload-Fehler wird nur „Anforderungserstellung fehlgeschlagen“ angezeigt. Fragen Sie xAI ab. Probleme wie die Aufforderung, sich erneut anzumelden, wenn bei der Beantragung von Kontingenten Netzwerkschwankungen auftreten; Es gelingt nicht, eine Fertigkeit auf halbem Weg zu aktualisieren und die ursprüngliche Fertigkeit zu löschen usw. Hinzufügen

Ollama Cloud-Paketkontingent

Der Lieferant mit der Adresse ollama.com kann nun das Token-Plan-Kontingent abfragen (Anforderungen siehe #9382): Das aktuelle Paket zeigt den verbleibenden Anteil des Kontingents und die Reset-Zeit im aktuellen Paket an, und die alte Version des Pakets zeigt den verbleibenden Anteil von 5 Stunden und zwei Fenstern pro Woche an. Das separat erworbene Kontingent wird nicht angezeigt; Für Pay-as-you-go-Konten gibt es keine Paketkontingente. Die Gründe dafür werden erläutert. Ollama (localhost:11434), das nativ ausgeführt wird, hat keinen Plan und wird nicht erkannt.

  • Für neu hinzugefügte Ollama Cloud-Lieferanten oder Ein-Klick-Import ist die Quotenabfrage standardmäßig aktiviert; Klicken Sie für bestehende Lieferanten auf der Karte auf „Nutzungsabfrage konfigurieren“. Die Token-Plan-Vorlage wird automatisch ausgewählt. Öffnen Sie „Nutzungsabfrage aktivieren“ und speichern Sie es.

Antigravity-Konto unter Windows wechseln

Die Antigravity-Kontoumschaltung im Autorisierungscenter unterstützte früher nur macOS, jetzt ist sie auch unter Windows nutzbar: Nach der Umstellung liest agy das neue Konto aus. Die offizielle Antigravity-Karte kann das Konto binden und das Limit des gebundenen Kontos überprüfen. Außerdem wird vor dem Öffnen des Terminals gefragt, zu welchem ​​Konto gewechselt werden soll. Linux wird noch nicht unterstützt.

Fix

  • Nach dem Zurückwechseln zu Claude Official von einem Drittanbieter sendet die offene Claude Code-Sitzung die Anfrage immer noch an den vorherigen Anbieter und muss neu gestartet werden, um fortzufahren (#9247, siehe #7808, #3057): Der laufende Claude Code liest nur settings.json-Umgebungsvariablen, die in der Sitzung hinzugefügt und geändert werden, und gelöschte verbleiben in der Sitzung. Schreiben Sie nun beim Wechsel zunächst die zu löschende Adresse, Anmeldeinformationen und Modellzuordnung als Nullwerte. Die nächste Anfrage der offenen Sitzung verwendet die vorherige nicht mehr und löscht sie dann nach etwa 10 Sekunden aus der Datei. Das beim Start der Sitzung festgelegte Hauptmodell (ANTHROPIC_MODEL) ändert sich nicht: Wenn es im vorherigen Modell festgelegt war, wählen Sie nach dem Zurückschalten im Modellmenü „Standard“ aus oder öffnen Sie eine neue Sitzung.
  • Wenn der Anbieter von Claude Code/Claude Desktop das Gemini Native-Format auswählt, meldet „Get Model List“ immer „API Key ist ungültig oder hat keine Berechtigung“: Übergeben Sie den Schlüssel nun auf die von Google geforderte Weise. Die eigentliche Anforderung, die weitergeleitet wird, ist bereits normal, nur das Abrufen der Modellliste ist betroffen. Darüber hinaus können Sie für Pi, Oh My Pi und Kimi Code, wenn Sie den Anbieter der Google-Schnittstelle auswählen, eine Modellliste erhalten, in der zuvor nur bis zu 50 Modelle aufgeführt sind, jetzt können Sie jedoch alle auflisten.
  • Beim Erhalt der Modellliste lehnten einige Dienstanbieter hinter Cloudflare diese direkt ab und wurden fälschlicherweise als „API-Schlüssel ist ungültig oder hat keine Berechtigung“ gemeldet (#7429, siehe #7427): Die Anfrage trägt jetzt standardmäßig User-Agent; Wenn User-Agent im Lieferanten- oder Anforderungsheader festgelegt ist, hat die Einstellung Vorrang.
  • Wenn Antigravity Orchestrator auswählt, werden einige Anfragen immer noch ohne Preis angezeigt (#9542, siehe #9493): Die als „Gemini 4 Hydrogen (Orchestrator)“ angezeigten Schritte richten sich nach dem Preis von Gemini 4 Hydrogen und der Verlauf der letzten 30 Tage wird die Gebühr ebenfalls ausgleichen. Die individuelle Preisgestaltung hat weiterhin Vorrang.
  • Die WebDAV-Synchronisierung ist auf einigen NAS überhaupt nicht verfügbar und Testverbindungen, Uploads und Downloads schlagen alle fehl (#5623, siehe #5621): Diese NAS geben immer noch 400 an „Verzeichnis erstellen“ zurück, wenn der freigegebene Ordner bereits vorhanden ist. Früher wurde der Vorgang sofort abgebrochen, jetzt wird erneut überprüft, ob das Verzeichnis vorhanden ist.
  • Wenn der WebDAV-/S3-Upload vom Server getrennt wird, wird nur „Anforderungskonstruktion fehlgeschlagen“ angezeigt (siehe #9559): Jetzt ist klar, ob die Anforderung nicht erstellt wurde oder beim Senden fehlschlägt, und der spezifische Grund wird angehängt, um die Feststellung zu erleichtern, ob es sich um ein Netzwerk-, TLS- oder Serverproblem handelt. Die Passwort- und Signaturparameter in der Adresse werden nicht im Fehlerbericht angezeigt.
  • Die automatische S3-Synchronisierung kann nach dem Ausschalten möglicherweise immer noch erneut hochgeladen werden (#9528): Automatische Uploads, die während einer anderen Synchronisierung in die Warteschlange gestellt werden, lesen jetzt die Einstellungen vor dem Start erneut und werden nicht mehr hochgeladen, wenn die automatische Synchronisierung oder S3-Synchronisierung während des Zeitraums deaktiviert ist. WebDAV ist genau das.
  • Wenn Sie beim Abfragen des xAI-Kontostands auf Netzwerkjitter oder einen xAI-Dienstfehler stoßen, werden Sie aufgefordert, sich erneut anzumelden (#9526, siehe #9522): Diese Aufforderung wird nur angezeigt, wenn die Anmeldung wirklich ungültig ist. Vorübergehende Fehler werden wie gewohnt gemeldet und der zuletzt gefundene Saldo bleibt erhalten. Versuchen Sie es beim nächsten Mal noch einmal.
  • Nachdem ein nicht standardmäßiges xAI-Konto abgelaufen war, wurde das im Autorisierungscenter ausgewählte Standardkonto durch ein anderes Konto ersetzt (#9548, siehe #9543).
  • Wenn das Kopieren beim Aktualisieren eines Skills auf halbem Weg fehlschlägt, wird der ursprüngliche Skill gelöscht, er wird jedoch weiterhin als installiert in der Liste angezeigt (siehe #9521): Jetzt wird die neue Version erst ersetzt, nachdem sie vollständig kopiert wurde, und die ursprüngliche Version bleibt erhalten, wenn sie fehlschlägt.
  • Wenn der Codex per Routing in das Chat-Format konvertiert wird, wird required: null in der Tool-Definition vom strikten Upstream abgelehnt (#7023, siehe #7019).
  • Wenn der Pfad zur Shell-Konfigurationsdatei unter macOS/Linux einen Doppelpunkt enthält, wird bei „Systemumgebungsvariablenkonflikt erkannt“ das Löschen oder Wiederherstellen von Variablen fehlgeschlagen (#7170, siehe #7169).
  • Die Pi-Standardeinstellungen von PIPELLM, AICodeWith und E-FlowCode werden als alter Modellname in der Modellauswahl angezeigt (#9514): Beispielsweise wird Claude Opus 5.5 als claude-opus-5 angezeigt und die eigentliche Anfrage ist das neue Modell. Die mit diesen Voreinstellungen generierten Voreinstellungen DeepSeek Harness, Copilot CLI, Oh My Pi, MiniMax Code und Kimi Code werden gemeinsam geändert; Bereits hinzugefügte Lieferanten behalten ihre ursprünglich gespeicherten Namen.
  • Lieferanten mit Adressen im Format api.commandcode.ai/providers werden als Befehlscode-Paketabfragekontingent verwendet (#9518).

cc-switch v4.0.33

Highlights

  • Claude Code 切换供应商 — 修复从第三方供应商切回 Claude 官方后，已打开的会话仍请求上一家的问题（#9247）。切换时先将被删除的地址、凭据和模型映射写成空值，约 10 秒后再从文件中删除，使会话的下一条请求立即生效。但 ANTHROPIC_MODEL 在会话启动时已固定，不会自动改变；若上一家配置过它，切回后需在模型菜单选择一次 Default 或新开会话。经常切换供应商的用户应优先升级。

  • 模型列表与协议兼容性 — Claude Code / Claude Desktop 使用 Gemini Native 格式时，模型列表不再误报「API Key 无效或无权限」；实际路由请求此前正常，本次只修列表获取。Pi、Oh My Pi、Kimi Code 的 Google 接口列表不再限制为 50 个模型；Cloudflare 后的服务商默认携带 User-Agent，自定义值仍优先。同时修复 Codex 转 Chat 格式时工具定义中的 required: null 被严格上游拒绝的问题。

  • 同步与 Skill 更新可靠性 — WebDAV 现在能兼容部分在目录已存在时仍返回 400 的 NAS；WebDAV / S3 上传失败会区分请求构造错误与发送错误，给出具体原因，并避免暴露密码和签名参数。关闭自动同步后，已排队的 S3 上传不会再执行。Skill 更新改为完整复制成功后才替换，失败会保留原版本，避免更新失败导致 Skill 丢失。使用 NAS、S3 或频繁更新 Skill 的用户值得升级。

  • 额度、账号与计价 — 新增 Ollama Cloud Token Plan 额度查询；新添加或导入的供应商默认启用，已有供应商需在卡片「配置用量查询」中选择 Token Plan 模板并保存。Windows 现已支持 Antigravity 账号切换、绑定和额度查看，Linux 仍不支持。xAI 查询遇到临时网络或服务错误时不再要求重新登录，并保留上次额度；非默认账号过期也不会再顶替默认账号。Antigravity Orchestrator 的 Hydrogen 步骤按 Gemini 4 Hydrogen 计价，近 30 天历史费用会补算，自定义价格仍优先。

  • 升级判断 — 未声明破坏性变更，也没有强制迁移步骤；可选功能除外，现有配置无需调整。另外修复了 macOS / Linux 冒号路径下的环境变量冲突处理、部分 Pi 预设的旧模型名，以及 api.commandcode.ai/providers 被误判为 Command Code 套餐的问题。命中上述问题的用户建议升级；完全未使用相关功能、且当前没有这些故障的用户可以跳过。

CC Switch v4.0.33

本版本修复了从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家、要重开会话才恢复的问题。套餐额度查询新增 Ollama Cloud；授权中心的 Antigravity 账号切换现在也支持 Windows。

另外修复了 Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时获取模型列表总报「API Key 无效或无权限」；部分服务商获取模型列表被 Cloudflare 拦下；Antigravity Orchestrator 仍有部分请求显示未定价；WebDAV 同步在一些 NAS 上完全用不了；WebDAV / S3 上传失败只显示「请求构造失败」；查询 xAI 额度时遇到网络抖动就被要求重新登录；更新 Skill 中途失败把原来的 Skill 删掉等问题。

新增

Ollama Cloud 套餐额度

地址是 ollama.com 的供应商现在可以查询 Token Plan 额度（需求见 #9382）：现行套餐显示本期套餐内额度的剩余比例和重置时间，旧版套餐显示 5 小时和每周两个窗口的剩余比例。单独购买的额度不显示；按量付费的账号没有套餐额度，会说明原因。本机运行的 Ollama（localhost:11434）没有套餐，不会被识别。

  • 新添加或一键导入的 Ollama Cloud 供应商默认开启额度查询；已有的供应商在卡片上点「配置用量查询」，Token Plan 模板会自动选好，打开「启用用量查询」后保存即可。

Windows 上切换 Antigravity 账号

授权中心的 Antigravity 账号切换以前只支持 macOS，现在 Windows 也能用：切换后 agy 读到的是新账号，Antigravity 官方卡可以绑定账号、查看所绑账号的额度，打开终端前也会提示将切换到哪个账号。Linux 暂不支持。

修复

  • 从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家，要重开会话才恢复（#9247，见 #7808、#3057）：运行中的 Claude Code 只会读入 settings.json 里新增和改动的环境变量，被删掉的仍留在会话里。现在切换时先把要删的地址、凭据和模型映射写成空值，开着的会话下一条请求就不再用上一家，约 10 秒后再从文件里删掉。会话启动时就定下的主模型（ANTHROPIC_MODEL）不会跟着变：如果上一家设了它，切回后在模型菜单里选一次 Default，或者新开会话。
  • Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时，「获取模型列表」总是报「API Key 无效或无权限」：现在按 Google 要求的方式传 Key。经路由的实际请求本来就正常，只有获取模型列表受影响。另外，Pi、Oh My Pi、Kimi Code 选 Google 接口的供应商，获取模型列表以前最多只列出 50 个，现在能列全。
  • 获取模型列表时，部分放在 Cloudflare 后面的服务商直接拒绝，被误报为「API Key 无效或无权限」（#7429，见 #7427）：请求现在默认带上 User-Agent；供应商或请求头里设了 User-Agent 的，仍以设置的为准。
  • Antigravity 选 Orchestrator 时，仍有部分请求显示未定价（#9542，见 #9493）：显示为「Gemini 4 Hydrogen (Orchestrator)」的步骤按 Gemini 4 Hydrogen 的价格计价，近 30 天内的历史也会补上费用。自定义价格仍然优先。
  • WebDAV 同步在部分 NAS 上完全用不了，测试连接、上传、下载都失败（#5623，见 #5621）：这些 NAS 在共享文件夹已存在时仍对「建目录」回 400，以前会直接中止，现在会再查一次目录是否存在。
  • WebDAV / S3 上传被服务器中途断开时，只显示「请求构造失败」（见 #9559）：现在分清是请求没构造出来还是发送时失败，并附上具体原因，方便判断是网络、TLS 还是服务器的问题。地址里的密码和签名参数不会出现在报错里。
  • S3 自动同步在关掉之后仍可能再上传一次（#9528）：另一次同步进行中时排队的自动上传，现在开始前会重新读取设置，期间关掉了自动同步或 S3 同步就不再上传。WebDAV 本来就是这样。
  • 查询 xAI 账号额度时，遇到网络抖动或 xAI 服务出错就提示需要重新登录（#9526，见 #9522）：只有登录真的失效才这样提示，临时错误照常报错并保留上次查到的额度，下次查询再试。
  • 一个非默认的 xAI 账号过期后，授权中心里选好的默认账号被换成了别的账号（#9548，见 #9543）。
  • 更新 Skill 时如果复制到一半失败，原来的 Skill 被删掉，列表里却仍显示已安装（见 #9521）：现在新版本完整复制好之后才替换，失败时保留原来的版本。
  • Codex 经路由转成 Chat 格式时，工具定义里的 required: null 被要求严格的上游拒绝（#7023，见 #7019）。
  • macOS / Linux 上 shell 配置文件的路径里带冒号时，「检测到系统环境变量冲突」删除或恢复变量会失败（#7170，见 #7169）。
  • PIPELLM、AICodeWith、E-FlowCode 的 Pi 预设在模型选择里显示成旧模型名（#9514）：比如 Claude Opus 5.5 显示成 claude-opus-5，实际请求的是新模型。用这几个预设生成的 DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code 预设一起修正；已经添加的供应商保留原来保存的名字。
  • 地址形如 api.commandcode.ai/providers 的供应商被当成 Command Code 套餐查询额度（#9518）。
