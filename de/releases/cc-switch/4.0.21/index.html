CC-Schalter v4.0.21

CC-Schalter v4.0.21

Diese Version fügt das Umschalten zwischen mehreren offiziellen Abonnementkonten für Claude Code hinzu: Fügen Sie mehrere Claude-Konten im Autorisierungscenter hinzu, wählen Sie eines für jede offizielle Karte aus, und egal zu welcher Karte Sie wechseln, Claude Code verwendet diese Nummer; Wenn Sie mehrere Nummern gleichzeitig verwenden möchten, öffnen Sie das Terminal von der Karte aus. Dieses Terminal verwendet immer die Nummer auf der Karte. Melden Sie sich an und folgen Sie dem offiziellen Claude Code-Prozess. Der Token verbleibt nur im Claude-Code des lokalen Rechners. CC Switch lädt nicht hoch, aktualisiert es nicht und meldet sich nicht ab. An Konten gebundene Karten und das Autorisierungscenter zeigen das Paket und den Restsaldo jedes Kontos an. Darüber hinaus wurde „Open Terminal“ auf die Karte verschoben und die Modellliste von Codex kann gezogen und sortiert werden, was nach dem Neustart im Lightweight-Modus erhalten bleibt. Das Problem des falschen Anmeldeablaufs nach dem Neustart des verwalteten ChatGPT-Kontos wurde behoben, die Codex-Anfrage wird beim Routing an eine andere Adresse gesendet, es gibt zusätzliche timeout/autoApprove in der MCP-Konfiguration des Codex, OpenCode und Grok Build werden unter npm 12 nicht ordnungsgemäß installiert, die Kimi-Code-Nutzungszeit ist falsch und es gibt &, *, ! in Oh My Pi's models.yml. Probleme wie die Unfähigkeit, etwas zu bearbeiten. Den vollständigen Update-Inhalt von 4.0 finden Sie in den [Versionshinweisen zu v4.0] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Hinzufügen

Wechseln Sie zwischen mehreren offiziellen Claude-Abonnementkonten

Wenn Sie mehr als ein Claude-Abonnement haben (z. B. ein persönliches Max- und Firmenteam oder mehrere Pro-Konten), können Sie in Claude Code nur /logout und dann /login erstellen oder selbst ein Konfigurationsverzeichnis für jedes Konto erstellen. Es ist jetzt möglich, mehrere Konten in CC Switch zu verwalten (#1928). Informationen zur grafischen Nutzung und zum Compliance-Vergleich einzelner Artikel finden Sie unter Verwenden Sie CC Switch, um mehrere offizielle Claude-Abonnements und Compliance-Probleme zu wechseln. **Sicherheit und Compliance. ** Das Abonnementkonto wird vom Tool verwaltet. Das Wichtigste ist, dass der Token sicher ist und nicht gegen die Bedingungen von Anthropic verstößt. Diese Funktion ist gemäß der offiziellen Dokumentation von Claude Code implementiert. Der Token befindet sich immer nur in Ihrem lokalen Claude-Code:

  • **Melden Sie sich an und folgen Sie dem offiziellen Prozess. ** Wenn Sie ein Konto hinzufügen, führen Sie claude auth login --claudeai aus, das mit Claude Code geliefert wird. Das Passwort und die Autorisierung werden auf der offiziellen Seite von claude.ai vervollständigt. CC Switch verfügt weder über ein eigenes Claude-Login noch über einen eigenen OAuth-Client. Anthropics [Rechts- und Compliance-Seite] (https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) verlangt, dass die Anmeldung bei einem Claude-Konto über den eigenen Prozess von Anthropic erfolgen muss, und schränkt Benutzer ausdrücklich nicht daran ein, sich mit ihren eigenen Abonnements bei unverändertem Claude-Code anzumelden.
  • **Mehrere Konten verwenden die offiziell empfohlene Methode. ** Jedes Konto verfügt über ein unabhängiges Konfigurationsverzeichnis, gekennzeichnet durch CLAUDE_CONFIG_DIR. Die Methode ist dieselbe wie im Abschnitt „Mit mehreren Konten anmelden“ in Claude Code [Zertifizierungsdokument] (https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). CC Switch erstellt lediglich das Verzeichnis und öffnet das Terminal für Sie.
  • **Der Token verlässt den Automaten nicht. ** Das Token existiert nur am eigenen Speicherort von Claude Code (Schlüsselbund für macOS, .credentials.json für Linux und Windows) und wird nicht hochgeladen, mit der Cloud synchronisiert oder in die CC Switch-Datenbank geschrieben. CC Switch selbst merkt sich nur Kontoinformationen wie E-Mail, Organisation, Paket und Ablaufzeit der Anmeldung, nicht jedoch Token.
  • **Sendet keine Anfragen für Sie. ** CC Switch verfügt über keinen Server und erfordert kein Abonnement-Token zum Aufrufen des Modells; Dialoganfragen werden vom lokalen, unveränderten Claude-Code direkt an Anthropic gesendet und die Nutzung wird Ihrem eigenen Konto in Rechnung gestellt. Überprüfen Sie bei der Überprüfung des Limits direkt die offizielle Limit-Schnittstelle von Anthropic auf diesem Computer. Dabei handelt es sich um dieselben Daten wie bei Claude Codes eigenem /usage.
  • **Keine Aktualisierung, kein Abmelden, keine Änderung des Claude-Codes. ** Token werden immer von Claude Code selbst aktualisiert. Durch das Löschen eines Kontos wird nur das von CC Switch dafür erstellte Verzeichnis gelöscht (zusammen mit dem Eintrag dieses Verzeichnisses im Schlüsselbund unter macOS) und das Konto kann sich nirgendwo abmelden. CC Switch verändert die Programmdateien von Claude Code nicht.
  • **Kontrollieren Sie einfach Ihr eigenes Konto. ** Konten werden weder automatisch entsprechend den Kontingenten rotiert, noch bietet es die Funktion, Abonnements mit anderen zu teilen. Die Karte und die Nummer werden zwischen den Speicherorten des lokalen Claude Code verschoben und angemeldet (nur im Claude Code-eigenen Format). In der offiziellen Dokumentation wird diese Verwendung nicht ausdrücklich erwähnt. Wenn Sie nur die im Dokument angegebene Methode nutzen möchten, behalten Sie die Karte „Login mit Claude Code“, andere Konten können nur über die Karte „Open Terminal“ genutzt werden. Anwendung:
  • **Konto hinzufügen. ** Klicken Sie in der Claude-Gruppe des Autorisierungscenters auf „Konto hinzufügen“. Der Browser öffnet die offizielle Autorisierungsseite von claude.ai und das Konto wird nach der Anmeldung automatisch in der Liste angezeigt. Wenn der Browser nach der Autorisierung nicht zum Gerät zurückkehren kann, können Sie die Adresse in die Adressleiste oder den Code auf der Seite zurück einfügen. Die Verzeichnisse der einzelnen Konten beeinträchtigen sich nicht gegenseitig und synchronisieren Ihre Einstellungen in ~/.claude, MCP und CLAUDE.md (mit Ausnahme der Anmeldeinformationen und Routing-bezogenen Einstellungen).
  • **Wählen Sie ein Konto für die offizielle Karte. ** Das Dropdown-Menü „Anmeldemethode“ von Claudes offizieller Karte ist dasselbe wie das von Codex‘ offizieller Karte: Oben ist das angemeldete Konto und unten ist „Claude-Konto hinzufügen oder verwalten“ (springen Sie zum Autorisierungscenter) und „Mit Claude Code anmelden“. Erstellen Sie einfach eine Karte für ein Konto.
  • **Schneiden Sie die Karte aus und die Zahl wird ausgeschnitten. ** Beim Wechsel zur offiziellen Karte des ausgewählten Kontos setzt CC Switch das Login dieses Kontos an die Position, an der es standardmäßig von Claude Code gelesen wird, und das ursprüngliche Konto wird wieder in sein eigenes Verzeichnis verschoben. claude im Terminal, im IDE-Plug-in und im Skript verwenden alle diese Nummer, und der bereits laufende Claude-Code wird ebenfalls sofort ohne Neustart geändert. Beim Wechsel auf die offizielle Karte des ausgewählten Kontos wird zunächst der aktuelle Login erfasst, sofern dieser nicht bereits im Autorisierungscenter vorhanden ist. Claude Code hält beim Umschalten seine eigene Sperre; Wenn CC Switch während des Umschaltens versehentlich beendet wird, wird es beim nächsten Umschalten oder Starten automatisch abgeschlossen oder zurückgezogen. Karten, die „Mit Claude Code anmelden“ wählen, werden nicht angemeldet, und diejenigen, die kein Konto hinzufügen, sind nicht betroffen.
  • **Es werden mehrere Nummern gleichzeitig verwendet. ** „Terminal öffnen“ auf der Karte mit dem ausgewählten Konto. Dieses Terminal ist mit der Nummer auf der Karte festgelegt. Ein späterer Kartenwechsel hat keine Auswirkungen darauf.
  • **Paket und Kontingent. ** Der Untertitel der Karte zeigt die Kontonummer und das Paket (z. B. Max 20x) und eine Meldung wird angezeigt, wenn der Login aktualisiert werden muss; Das verbleibende Limit dieses Kontos wird standardmäßig unten auf der Karte angezeigt, und jedes Konto im Autorisierungscenter verfügt auch über dieselbe Limitspalte. Wenn das Token eines ungenutzten Kontos abläuft, führt CC Switch das eigene claude -p /usage von Claude Code einmal in seinem Verzeichnis aus (bis zu einmal alle 10 Minuten für jedes Konto). Claude Code aktualisiert die Anmeldung und fragt das Kontingent selbst ab, und CC Switch liest nur die Ergebnisse. /usage ruft das Modell nicht auf und verbraucht nicht das Dialogguthaben. Bei offiziellen Karten ohne ausgewähltes Konto wird auch das aktuell angemeldete Paket angezeigt. Ein paar Punkte, die Sie beachten sollten:
  • Die von Ihnen verwendete Fernbedienung wird nach der Änderung der Nummer getrennt. Die erste Nachricht nach der Nummernänderung muss den Prompt-Cache neu aufbauen, was langsamer ist und mehr Guthaben verbraucht. – Wenn das Claude-Konfigurationsverzeichnis in den Einstellungen überschrieben wird (einschließlich Verweis auf WSL), wechselt Cheka die Anmeldungen nicht und die Schnittstelle fordert stattdessen zur Verwendung von „Terminal öffnen“ auf.

Die Modellliste von Codex kann durch Ziehen sortiert werden

Die Modellliste im Codex-Lieferantenformular verfügt über einen Ziehpunkt am Anfang jeder Zeile und die Reihenfolge kann mit der Maus oder der Tastatur angepasst werden (#8870). Diese Reihenfolge ist die Reihenfolge des /model-Menüs im Codex. Wenn die erste Zeile das Standardmodell darstellt, wird das in die erste Zeile gezogene Modell zum neuen Standardmodell. Früher musste ich es löschen und wieder hinzufügen, um es zu verschieben.

Fix

  • Nach dem Neustart des verwalteten ChatGPT-Kontos wird „Login ist abgelaufen“ angezeigt und ein Wechsel ist nicht möglich. Es erholt sich nach einer Weile (#8901). In der Vergangenheit wurde jedes beim Aktualisieren der Anmeldung aufgetretene HTTP 403 als Anmeldefehler gewertet und Netzwerkfehler wurden auch als abgelaufen angezeigt. Jetzt gelten, wie bei Codex CLI, nur 401- oder Clear-Token-Invalidierungsfehler als abgelaufen; Temporäre Netzwerkprobleme werden wie gewohnt wiederholt und das Kontingent behält das letzte Ergebnis. Nach dem Wechsel des Tabletts wird auch der Saldo, der in der Hauptoberfläche nicht abgefragt werden konnte, erneut abgefragt. – Wenn Codex lokal weitergeleitet wurde, wurde die Anfrage an andere Adressen gesendet (#8849, #8848). Wenn in config.toml mehrere Lieferantentabellen vorhanden sind oder oben eine Zeile mit alten Adressen auskommentiert ist, wurde zuvor die erste base_url im Text abgerufen und der Schlüssel des ausgewählten Lieferanten wird an eine andere Stelle gesendet. Drücken Sie nun model_provider, um die Adresse aus der ausgewählten Tabelle zu erhalten. – Die Verwendung der Codex-Remotekomprimierung wird manchmal übersehen (#8879).
  • Es gibt zusätzliche timeout und autoApprove in der MCP-Konfiguration von Codex, die Desktop-Version von Codex hat unbekannte Einstellungen gemeldet und --strict-config konnte nicht geladen werden (#8843). Diese beiden Felder gehören anderen Kunden. Sie wurden wie zuvor in config.toml geschrieben. Wenn sie manuell gelöscht werden, werden sie bei der nächsten Synchronisierung wieder zurückgeschrieben. Jetzt beim Schreiben in Codex entfernt, andere Anwendungen sind nicht betroffen. – Wenn Codex über Relay mit mehreren Azure-Ressourcen verbunden ist, wird mitten in der Sitzung die Meldung 400 „unter einer anderen Azure OpenAI-Ressource erstellt“ gemeldet und kann nicht fortgesetzt werden (#8877). Nachdem Sie diesen Fehler erhalten haben, versuchen Sie es erneut und entfernen Sie die Eintrags-ID aus dem Verlauf. Normale Anfragen sind nicht betroffen.
  • ClinePass ist ein Upstream, der Chat-Abschlussergebnisse in data zurückgibt. Nicht-Streaming-Anfragen melden 422 „Keine Auswahl als Antwort“ (#5658).
  • Unter npm 12 meldet der auf der Seite „Anwendung“ installierte OpenCode unter Windows „Inkompatibel mit der Windows-Version, die Sie ausführen“, und Grok Build führt nach dem Upgrade immer noch die alte Version aus (#8863). npm 12 führt das Installationsskript nicht standardmäßig aus, und diese beiden Pakete sind darauf angewiesen, echte Programme zu platzieren. Ihre Installationsskripte sind jetzt bei der Installation und Aktualisierung zulässig.
  • Hermes unter Windows wird auf der Seite „Anwendungen“ als zwei Installationen angezeigt (#8839). hermes.cmd, das im selben Verzeichnis verbleibt, wird nicht mehr als Installation gezählt.
  • Bei Verwendung des Kimi-Codes ist die Anforderungszeit für eine ganze Dialogrunde gleich, und wenn sie nach Stunden berechnet wird, wird sie auf die letzte Stunde gequetscht (#8899). Notieren Sie nun die Zeit, zu der jede Anfrage abgeschlossen ist. Importierte Datensätze werden bei der nächsten Änderung der Sitzungsdatei korrigiert.
  • Wenn Oh My Pi's models.yml name: Search & Fetch enthält, das Werte wie &, * und ! enthält, meldet der Lieferant „Dieser YAML verwendet ein Format oder eine Syntax, die von CC Switch nicht sicher bearbeitet werden kann“ (#8897).
  • Wenn ~/.gemini/.env als export GEMINI_API_KEY=... geschrieben ist, gibt es nach dem Import keinen Schlüssel und er wird aus der Datei gelöscht, wenn zum Standardlieferanten zurückgeschaltet wird (#8862, #8861).
  • **Beim Wechsel von einem Projekt mit aktivierten Aufforderungswörtern zu einem Projekt ohne Aufforderungswörter werden die ursprünglichen Aufforderungswörter nicht deaktiviert. **
  • Wenn die Seitenleiste der Nutzungsstatistikseite erweitert oder reduziert wird, springt der rechte Rand des Trenddiagramms (#8548).

cc-switch v4.0.21

Highlights

  • Multiple official Claude accounts, switchable per card — CC Switch can now manage several Claude.ai subscriptions (personal Max vs. company Team, multiple Pro seats) and swap which one claude uses (#1928). Accounts are added through the official claude auth login --claudeai flow, each in its own CLAUDE_CONFIG_DIR — the same pattern Claude Code's own docs recommend — with settings, MCP config and CLAUDE.md seeded from ~/.claude but credentials and routing left alone. Switching a card moves that account's login into Claude Code's default credential store (macOS Keychain / .credentials.json) under Claude Code's own lock, with automatic completion or rollback on the next launch if the app dies mid-swap; running sessions follow immediately, no restart needed. Tokens never reach CC Switch's database or any server — it stores only email, org and plan metadata, never refreshes or logs out accounts, and deletion only removes the directories it created. For genuinely parallel use, launch a terminal from the card: that shell is pinned to the card's account and unaffected by later switches. Watch-outs: Remote Control sessions disconnect on account change, the first message after a switch rebuilds the prompt cache (slower, extra usage), and if you've overridden the Claude config directory — including pointing it at WSL — card switching deliberately won't move credentials; use "Open Terminal" instead.

  • Codex routing and auth correctness — With multiple provider tables in config.toml, or a commented-out old address above the active one, CC Switch previously grabbed the first base_url in the text and paired it with the selected provider's key — sending both to the wrong host. The address is now resolved from the table named by model_provider (#8849, #8848). Related fixes: Azure relay sessions hit by 400 "created under a different Azure OpenAI resource" now retry once with the prior entry IDs stripped (#8877), remote-compaction usage is no longer lost (#8879), and managed ChatGPT accounts no longer show a false "login expired" and lock out switching on any 403 — only 401 or an explicit token-invalid error counts, matching Codex CLI, with transient failures retried and the last quota result kept (#8901). If you somehow depended on that commented-out URL being used, that behavior is gone.

  • Generated config stays valid under strict validation — CC Switch stops writing timeout and autoApprove into Codex's MCP config (#8843): those fields belong to other clients and triggered "unknown setting" errors in Codex Desktop and outright load failures under --strict-config, with manual deletion undone on the next sync; other applications' configs are unaffected. SSE selection now warns up front (#8882) — Codex accepts only stdio and HTTP and will try to talk HTTP to an SSE-only server, while Pi and Antigravity reject it on save. Editing robustness also improved: ~/.gemini/.env entries written as export GEMINI_API_KEY=... import correctly and no longer get deleted when switching back to the default provider (#8862, #8861), and Oh My Pi models.yml values containing &, *, or ! (e.g. name: Search & Fetch) no longer block saving with "unsupported YAML format" (#8897).

  • Installs and usage metering — npm 12 stopped running install scripts by default, which made the OpenCode install on Windows report "incompatible with your Windows version" and left Grok Build running the old binary after an upgrade; install and upgrade now explicitly allow those packages' scripts (#8863). A leftover hermes.cmd no longer registers as a second Windows installation (#8839), and ClinePass-style upstreams that wrap Chat Completions payloads in data no longer produce 422 "No choices in response" on non-streaming calls (#5658). Kimi Code usage is now timestamped per request completion instead of stamping a whole conversation identically and bunching it into the last hour (#8899); already-imported records correct themselves on the next session-file change.

  • Model and card workflow polish — The Codex provider form's model list is drag-reorderable with mouse or keyboard, and that order is literally the /model menu order — drag a model to the top to make it the default, replacing the delete-and-re-add workaround (#8870). "Open Terminal" moved from the ⋯ menu to an icon next to "Edit," with an "(environment isolated)" tooltip on cards pinned to an account or custom endpoint; lightweight mode now survives restarts, though a cold ccswitch:// launch still opens the main window so import dialogs can render. Presets were refreshed too: DeepSeek standardized on Flash, Kimi gained K3.1 Pro / Pro HighSpeed with low/high/max reasoning (#8867), and ClinePass (#8885) and TeamoRouter Claude (#8266) were added.

  • Breaking changes — None.

CC Switch v4.0.21

本版本为 Claude Code 增加了多个官方订阅账号的切换：在授权中心添加几个 Claude 账号，每张官方卡选一个，切到哪张卡，Claude Code 就用哪个号；想几个号同时用，从卡片上「打开终端」，那个终端固定用卡片上的号。登录走 Claude Code 官方的流程，令牌只留在本机的 Claude Code 里，CC Switch 不上传、不刷新、不登出。绑了账号的卡片和授权中心都会显示每个号的套餐和剩余额度。另外，「打开终端」挪到了卡片上，Codex 的模型列表可以拖动排序，轻量模式重启后保持。修复了托管 ChatGPT 账号重启后误报登录过期、Codex 经路由时请求发到了别的地址、Codex 的 MCP 配置里多出 timeout / autoApprove、npm 12 下 OpenCode 和 Grok Build 装不好、Kimi Code 用量的时间不对、Oh My Pi 的 models.yml 里有 &、*、! 时无法编辑等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

在多个 Claude 官方订阅账号之间切换

手上有不止一个 Claude 订阅（比如个人 Max 和公司 Team，或者多个 Pro 账号）时，以前只能在 Claude Code 里 /logout 再 /login，或者自己给每个号建配置目录。现在可以在 CC Switch 里管理多个号（#1928）。

图文用法和逐条的合规对照见 使用 CC Switch 切换多个 Claude 官方订阅以及合规问题。

安全与合规。 订阅账号交给工具管理，最要紧的是令牌安全、不违反 Anthropic 的条款。这个功能按 Claude Code 官方文档的做法实现，令牌始终只在你本机的 Claude Code 里：

  • 登录走官方流程。 添加账号时运行的是 Claude Code 自带的 claude auth login --claudeai，密码和授权都在 claude.ai 的官方页面完成。CC Switch 没有自己的 Claude 登录，也没有自己的 OAuth 客户端。Anthropic 的法律与合规页要求 Claude 账号的登录必须通过 Anthropic 自己的流程完成，并且明确不限制用户用自己的订阅登录未经修改的 Claude Code。
  • 多账号用的是官方推荐的方法。 每个号一个独立的配置目录，用 CLAUDE_CONFIG_DIR 区分，和 Claude Code 认证文档里「Log in with multiple accounts」一节的方法一样，CC Switch 只是替你建好目录、打开终端。
  • 令牌不离开本机。 令牌只存在 Claude Code 自己的位置（macOS 的钥匙串，Linux、Windows 的 .credentials.json），不上传，不随云同步，也不写进 CC Switch 的数据库。CC Switch 自己只记邮箱、组织、套餐这类账号资料和登录过期时间，不记令牌。
  • 不替你发请求。 CC Switch 没有服务器，不用订阅令牌调用模型；对话请求都由本机未经修改的 Claude Code 直接发给 Anthropic，用量计在你自己的账号上。查额度时在本机直接查 Anthropic 官方的额度接口，和 Claude Code 自己的 /usage 查的是同一份数据。
  • 不刷新、不登出、不改 Claude Code。 令牌一律由 Claude Code 自己刷新。删除账号只删 CC Switch 为它建的目录（macOS 上连同这个目录在钥匙串里的条目），不会让这个号在任何地方退出登录。CC Switch 不修改 Claude Code 的程序文件。
  • 只管你自己的账号。 不按额度自动轮换账号，也不提供把订阅共享给别人的功能。

切卡即切号会在本机 Claude Code 的存储位置之间移动登录（只按 Claude Code 自己的格式），官方文档没有专门讲到这种用法。只想用文档写明的方式的话，卡片保持「跟随 Claude Code 登录」，其他号只从卡片「打开终端」使用。

怎么用：

  • 添加账号。 在授权中心的 Claude 组点「添加账号」。浏览器会打开 claude.ai 的官方授权页，登录后账号自动出现在列表里。浏览器授权后回不到本机时，可以把地址栏里的地址或页面上的代码粘贴回来。每个号的目录互不干扰，会同步你在 ~/.claude 里的设置、MCP 和 CLAUDE.md（登录凭据和路由相关的设置除外）。
  • 给官方卡选账号。 Claude 官方卡的「登录方式」下拉和 Codex 官方卡一样：上面是已登录的账号，下面是「添加或管理 Claude 账号」（跳到授权中心）和「跟随 Claude Code 登录」。一个号建一张卡就行。
  • 切卡即切号。 切到选了账号的官方卡时，CC Switch 把这个号的登录放进 Claude Code 默认读取的位置，原来那个号放回它自己的目录。终端、IDE 插件、脚本里的 claude 都改用这个号，已经在运行的 Claude Code 也会立即跟着换，不用重启。切到选了账号的官方卡时，现在的登录如果还不在授权中心会先收进来。切换时持有 Claude Code 自己的锁；切换中途 CC Switch 意外退出的话，下次切换或启动时会自动补完或撤回。选「跟随 Claude Code 登录」的卡不碰登录，不添加账号的人不受影响。
  • 几个号同时用。 在选了账号的卡上「打开终端」，这个终端固定用卡片上的号，之后切换卡片不影响它。
  • 套餐和额度。 卡片副标题显示账号和套餐（如 Max 20x），登录需要更新时带一个提示；卡片底部默认显示这个号的剩余额度，授权中心里每个号也有一样的额度列。不在用的号令牌过期时，CC Switch 在它的目录里运行一次 Claude Code 自带的 claude -p /usage（每个号最多 10 分钟一次），由 Claude Code 自己刷新登录、查询额度，CC Switch 只读结果。/usage 不调用模型，不消耗对话额度。没选账号的官方卡也会显示当前登录的套餐。

几点注意：

  • 切号后正在用的 Remote Control 会断开；换号后第一条消息要重建提示缓存，会慢一点、多用一点额度。
  • 在设置里覆盖了 Claude 配置目录（包括指向 WSL）时，切卡不会切换登录，界面会提示改用「打开终端」。

Codex 的模型列表可以拖动排序

Codex 供应商表单里的模型列表，每行开头有拖动手柄，可以用鼠标或键盘调整顺序（#8870）。这个顺序就是 Codex 里 /model 菜单的顺序。第一行代表默认模型时，拖到第一行的模型成为新的默认模型。以前要删掉再加回来才能挪位置。

改进

「打开终端」挪到卡片上。 以前在 ⋯ 菜单里，现在是「编辑」左边的一个图标按钮。悬停提示是「以此供应商打开终端」，终端固定用这张卡时（填了自己的地址和 Key 的卡、选了 Claude 账号的官方卡）会写「（环境隔离）」。

授权中心每组的「添加账号」按钮固定在标题右边。 以前没有账号时按钮会挪到空白提示里，几组卡片的按钮高低不一。ChatGPT 的登录方式改成按钮旁边的一个小下拉。标题里的「删除全部账号」菜单去掉了，账号在各自那一行的菜单里删除。各个账号的额度条现在对齐，长度一致。

轻量模式重启后保持。 在轻量模式下退出 CC Switch，下次启动仍是轻量模式，不再弹出主界面。从 ccswitch:// 链接冷启动时照常打开主界面，好显示导入对话框。

Hermes 卡片显示「默认」，「设为默认」移到 ⋯ 菜单里。 Hermes 把添加的供应商都写进 config.yaml，当前那家只是默认值，和 OpenClaw、OpenCode、Kimi Code 一样。以前的电源图标「启用」按钮看起来像开关。

卡片变成「使用中」时，用量一栏不再左右挪动。

MCP 选了 SSE 时提示哪些应用不支持（#8882）。Codex 只支持 stdio 和 HTTP，会把 SSE 地址当作 HTTP 连接，服务端只支持 SSE 时连不上；Pi 和 Antigravity 保存时会报错。现在「写入到」下面会提前提示。

Claude Desktop 的上游地址填 githubcopilot.com 时，上游格式显示为「由路由按模型自动选择」（#8838），和选 GitHub Copilot 供应商时一样。

OpenCode 的 OMO、OMO Slim 卡片不再显示「检测连通」（#8842）。它们只是代理和模型的对应关系，没有地址可测，以前点了会报错。

土耳其语翻译补全（#8836）。

预设： DeepSeek 一律改用 Flash 模型；Kimi 官方预设加入 K3.1 Pro 和 K3.1 Pro HighSpeed，可以选 low / high / max 思考程度（#8867）；OpenClaw 的 MiniMax M3.1 Flash 可以选 max；新增 ClinePass（#8885）、TeamoRouter Claude（#8266）；Claude Desktop 的 OpenCode Go 改用官方文档的地址，额度也能查了（#8720、#8779）。

修复

  • 托管 ChatGPT 账号重启后显示「登录已过期」、不能切换，过一会儿又自己好了（#8901）。以前刷新登录时遇到任何 HTTP 403 都当成登录失效，网络错误也显示成过期。现在和 Codex CLI 一样，只有 401 或明确的令牌失效错误才算过期；一时的网络问题照常重试，额度保留上一次的结果。托盘切换后，主界面里查询失败的额度也会重新查询。
  • Codex 经本地路由时，请求发到了别的地址（#8849、#8848）。config.toml 里有多个供应商表、或上面有一行注释掉的旧地址时，以前取的是文本里第一个 base_url，会带着选中供应商的 Key 发到别处。现在按 model_provider 选中的那张表取地址。
  • Codex 远程压缩的用量有时漏记（#8879）。
  • Codex 的 MCP 配置里多出 timeout、autoApprove，Codex 桌面版报未知设置，--strict-config 拒绝加载（#8843）。这两个字段是别的客户端的，以前原样写进了 config.toml，手动删掉下次同步又会写回来。现在写给 Codex 时去掉，其他应用不受影响。
  • Codex 经中转连到多个 Azure 资源时，会话中途报 400「created under a different Azure OpenAI resource」，无法继续（#8877）。现在收到这个错误后重试一次，去掉历史记录的条目 ID。正常的请求不受影响。
  • ClinePass 这类把 Chat Completions 结果包在 data 里返回的上游，非流式请求报 422「No choices in response」（#5658）。
  • npm 12 下，「应用」页装的 OpenCode 在 Windows 上报「与你运行的 Windows 版本不兼容」，Grok Build 升级后仍在跑旧版本（#8863）。npm 12 默认不运行安装脚本，这两个包要靠它放置真正的程序。现在安装和升级时允许它们的安装脚本。
  • Windows 上 Hermes 在「应用」页显示成两处安装（#8839）。同一目录里遗留的 hermes.cmd 不再算一处安装。
  • Kimi Code 的用量，一整轮对话的请求时间都一样，按小时统计时挤在最后一小时（#8899）。现在按每次请求完成的时间记。已导入的记录在会话文件下次变化时会更正。
  • Oh My Pi 的 models.yml 里有 name: Search & Fetch 这类含 &、*、! 的值时，保存供应商时报「此 YAML 使用了 CC Switch 无法安全编辑的格式或语法」（#8897）。
  • ~/.gemini/.env 里写成 export GEMINI_API_KEY=... 时，导入后没有 Key，切回默认供应商还会把它从文件里删掉（#8862、#8861）。
  • 从启用了提示词的项目切到没有提示词的项目，原来的提示词没有停用。
  • 用量统计页展开或收起侧栏时，趋势图右边缘跳动（#8548）。
