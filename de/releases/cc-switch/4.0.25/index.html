CC-Schalter v4.0.25

CC-Schalter v4.0.25

Diese Version fügt der MCP-Seite eine Konnektivitätsprüfung hinzu, die mit einem Klick prüfen kann, ob alle aktivierten MCP-Server verbunden werden können; Wenn Codex das offizielle Konto über lokales Routing verwendet, kann die offizielle Anfrage automatisch ausgesetzt werden, bevor das Kontingent fast aufgebraucht ist und Modelle von Drittanbietern weiterhin verfügbar sind. Darüber hinaus kann der Wechselkurs auf der Nutzungsseite automatisch abgerufen werden und das Codex-Lieferantenformular kann das Parallelitätslimit für Subagenten festlegen. Wenn Claude Code und Claude Desktop weitergeleitet oder aggregiert werden, wird im Modellmenü angezeigt, von welchem ​​Lieferanten jedes Modell stammt und um welches Modell es sich tatsächlich handelt. Kimi Code-Sitzungen können auch in der Sitzungsverwaltung gelöscht werden. Es wurden außerdem Probleme wie „offenes Terminal“ behoben, das Routing- und Aggregationseinstellungen vermischte, Anbieter wie OpenCode Go im Routing-Modus aufforderten, sich erneut anzumelden, Fehler, die jedes Mal nach dem Senden einer Datei an ein Nur-Text-Modell gemeldet wurden, Lieferantenformularinhalte unter Windows, die hin und her blinkten, das Tray-Panel, das beim Start nicht geöffnet wurde, und die doppelte Zählung der Nutzung, wenn Codex Modellzuordnung verwendet. Den vollständigen Update-Inhalt von 4.0 finden Sie in den v4.0-Versionshinweisen. Englisch → | Japanische Version →

Hinzufügen

MCP-Konnektivitätsprüfung

Bisher war nach der Konfiguration des MCP-Servers nur bekannt, ob er verbunden werden konnte, wenn er im Programmiertool verwendet wurde (#4498). Jetzt gibt es oben auf der MCP-Seite die Schaltfläche „Konnektivität prüfen“, mit der alle aktivierten Server überprüft werden. Außerdem gibt es im Menü jeder Zeile eine „Verbindung testen“, und nur diese wird überprüft.

  • Es wird beim Öffnen der Seite nicht automatisch aktiviert und „nicht aktiviert“ wird angezeigt, wenn es nicht aktiviert wurde. Nach einer Änderung der Verbindungskonfiguration eines bestimmten Servers werden dessen Ergebnisse zurückgesetzt. – Die Prüfmethode besteht darin, einen MCP-Handshake mit dem Server abzuschließen, und alle drei Verbindungsmethoden, lokaler Befehl (stdio), HTTP und SSE der alten Version, werden unterstützt. Warten Sie bis zu 30 Sekunden pro Server und die gesamte Anwendung kann bis zu 3 gleichzeitig prüfen.
  • Nachdem der durch den lokalen Befehl gestartete Server überprüft wurde, wird er zusammen mit dem von ihm gestarteten untergeordneten Prozess beendet und es bleibt kein Hintergrundprozess übrig. Befehle wie npx und uvx sind auch unter macOS und Linux zu finden, wenn CC Switch nicht vom Terminal aus gestartet wird.

Offizieller Quotenschutz des Codex

Wenn Codex das offizielle ChatGPT-Konto verwendet, wechselt es in den Reservemodus, wenn das Fünf-Stunden- oder Wochenkontingent aufgebraucht ist. Nun können Sie behördliche Anfragen aussetzen, wenn das Kontingent fast erschöpft ist, das Kontingent belassen und Modelle von Drittanbietern weiterhin wie gewohnt genutzt werden können. Aktivieren Sie „Offizieller Kontingentschutz“ unter „Einstellungen → Anwendungskonfiguration → Codex-Anwendungsverbesserung“, Sie können Nutzungsschwellenwerte für fünf Stunden und wöchentlich festlegen (Standard 95 % und 98 %) und neue offizielle Anfragen aussetzen, wenn einer dieser Schwellenwerte erreicht ist. – Wird nur für offizielle Codex-Anfragen wirksam, die lokal über CC Switch weitergeleitet werden, und ist standardmäßig deaktiviert.

  • Die Nutzungsrate liest direkt die in der offiziellen Antwort enthaltenen Quoteninformationen ab. Bei normaler Nutzung werden keine Mehrfachanfragen gesendet; Eine gesonderte Abfrage erfolgt erst, wenn die Nutzung gerade begonnen wurde oder ca. 5 Minuten im Leerlauf war.
  • Wenn das Kontingent nicht gefunden werden kann (Netzwerkprobleme, Ablauf der Anmeldung usw.), wird das System wie gewohnt freigegeben und es kommt zu keiner Fehlblockierung. Angehaltene Anfragen geben direkt Fehler zurück und werden nicht an andere Anbieter in der Failover-Warteschlange weitergeleitet.

Den Wechselkurs automatisch auf der Nutzungsseite abrufen

Der Bereich „Anzeige“ in den „Nutzungseinstellungen“ auf der Nutzungsseite verfügt über eine „Wechselkursquelle“. Sie können zwischen „Manuelles Ausfüllen“ (Standard) und „Automatischer Abruf“ wählen. Erst wenn der automatische Abruf ausgewählt ist, wird das Netzwerk verbunden. Der Wechselkurs wird automatisch aktualisiert, wenn er 12 Stunden überschreitet. Schlägt der Abruf fehl, wird weiterhin der letzte Wechselkurs verwendet. Der automatisch ermittelte und der manuell ausgefüllte Wechselkurs werden getrennt gespeichert. Wenn Sie wieder zur manuellen Eingabe wechseln, ist der von Ihnen eingegebene Wert weiterhin vorhanden. Gebühren werden weiterhin in US-Dollar erfasst und erst bei entsprechender Angabe umgerechnet.

Codex-Subagenten-Parallelitätslimit

Unter dem „Subagentenmodell“ im Codex-Lieferantenformular gibt es ein „Subagenten-Parallelitätslimit“, das die maximale Anzahl von Subagenten festlegt, die gleichzeitig in einer Codex-Sitzung geöffnet werden können (#9055). Dies ist die globale Einstellung von Codex. Das in config.toml geschriebene [agents] max_threads bleibt beim Anbieterwechsel unverändert und kann auch auf der offiziellen Karte geändert werden; Wenn es leer bleibt, wird der Standardwert von Codex verwendet.

Das Modellmenü zeigt den Lieferanten und das tatsächliche Modell an

Claude Code Im Routing-Modus stand in jeder Datei im /model-Menü bisher nur „Benutzerdefiniertes Sonnet-Modell“ und es war unmöglich zu erkennen, welches Modell welchem Lieferanten entsprach. Es wird nun als „Lieferant · Tatsächliches Modell · Fenster“ geschrieben (das Fenster wird nur angezeigt, wenn sich der Cursor 1M nach oben befindet), und das Gleiche gilt für Modelle im Aggregationsmodus. Wenn der Lieferant die Modellbeschreibung selbst verfasst hat, ist die von Ihnen verfasste maßgebend. Claude Desktop Im Routing- und Aggregationsmodus verwendet die Beschreibung unten das Modell, um die offizielle Kopie gemäß Opus und Sonnet im Namen anzuwenden, und das Aggregationsmodell zeigt immer den gleichen Satz an. Ändern Sie es nun auch in „Supplier·Actual Model·Window“.

Kimi Code-Sitzung löschen

Kimi Code-Sitzungen können direkt in der Sitzungsverwaltung gelöscht werden. Bisher konnten sie nur in Kimi Code gelöscht werden. Die Löschmethode ist dieselbe wie die von Kimi Code, und der Verlauf des Subagenten wird gemeinsam gelöscht. Preise: GPT-6.1 Terra zur integrierten Preisliste hinzugefügt.

Ändern

  • Lokales Routing akzeptiert keine Anfragen mehr von Webseiten. Die lokale Route ersetzt die Anfrage durch Ihre gespeicherten Provider-Anmeldeinformationen und leitet sie dann weiter. Wenn die Webseite die Anfrage also an die lokale Route senden kann, kann Ihr Kontingent aufgebraucht sein. Anfragen mit einem Browser-Ursprungs-Tag werden nun abgelehnt und der Zugriff auf diesen Computer über einen gemeinsamen Domänennamen wird nicht mehr akzeptiert. Von Programmiertools gesendete Anfragen sind nicht betroffen.
  • Die Symbolleiste der Seite „Entdecken“ von Skills ist an der Seite „Installiert“ ausgerichtet (#9125): Die Position und Breite des Suchfelds sind konsistent, die Aktualisierungsschaltfläche wurde in die Textschaltfläche „Warehouse aktualisieren“ geändert, die Quelle, der Warehouse-Filter und „Nur deinstallierte anzeigen“ werden in die Kopfzeile verschoben und „Installieren auf“ wird auf der rechten Seite der Kopfzeile platziert. Eine Zeile fehlt, aber die Funktionalität bleibt gleich.
  • Wenn das bevorzugte Terminal unter Windows PowerShell ist und PowerShell 7 installiert ist, verwenden Sie es zum Öffnen (#8992, #3271). Wenn nicht, verwenden Sie die mit dem System gelieferte Windows PowerShell. Dies gilt für das „Öffnen des Terminals“ der Lieferantenkarte sowie für die Installation und Aktualisierung von Anwendungen.
  • Standard: Der Pay-as-you-go- und Token-Plan von Qianwen AI Platform und QwenCloud werden auf den neuen MaaS-Domänennamen geändert und der Codierungsplan bleibt unverändert.

Fix

  • Im Routing- oder Aggregationsmodus mischt das „Open Terminal“ der Claude Code-Karte Routing- und Aggregationseinstellungen. Der Claude-Code im Terminal bringt gleichzeitig die Platzhalter-Zugangsdaten der Route und den Schlüssel dieser Karte. Die Modelldatei, die nicht mit dieser Karte übereinstimmt, verwendet den Modellnamen in der Aggregation und die an diese Karte gesendete Adresse wird nicht verwendet. Modelle anderer Anbieter erscheinen ebenfalls im /model-Menü. Jetzt werden nur noch die eigenen Einstellungen dieser Karte im Terminal verwendet, Ihre anderen globalen Einstellungen bleiben wie gewohnt erhalten.
  • Im Routing-Modus fordern Anbieter wie OpenCode Go, die ANTHROPIC_API_KEY zum Speichern von Schlüsseln verwenden, Claude Code auf, den benutzerdefinierten Schlüssel zu bestätigen. Wenn Sie standardmäßig „Nein“ auswählen, sind Sie nicht angemeldet (#8111, #8104). Jetzt werden im Routing-Modus Platzhalteranmeldeinformationen immer in ANTHROPIC_AUTH_TOKEN geschrieben und an den Upstream gesendete Anforderungen bleiben unverändert.
  • Nach dem Senden einer Datei oder Audiodatei an das Nur-Text-Modell werden in jeder weiteren Runde 400 gemeldet (#6274, #6151). Beim Senden an ein Nur-Text-Modell per Routing werden nun die Dateien und Audiodaten in der Konversation durch eine Textbeschreibung ersetzt; Auch der chinesische Fehlerbericht von GLM ist zu erkennen. Die Bearbeitung der Bilder bleibt unverändert.
  • Namen und andere Inhalte im Lieferantenformular unter Windows blinken hin und her (#6420, #6349). Dies ist das automatische Ausfüllen von WebView2, das den Formularinhalt überlagert und jetzt für das Hauptfenster deaktiviert ist.
  • Die Fachabdeckung kann für einen bestimmten Zeitraum nach dem Start nicht geöffnet werden und das Fach kann nicht verlassen werden (#9154). Die importierte Sitzungsnutzung belegt beim Start die Datenbank und das Tray-Panel muss auf Daten warten. Nun öffnet sich zunächst das Panel, „Hauptfenster öffnen“ und „Beenden“ sind sofort verfügbar und die Liste wird dann geladen. – Wenn Codex die Modellzuordnung über Routing verwendet, wird die Verwendung derselben Anfrage zweimal gezählt (#7643, #5526). Was im Sitzungsprotokoll aufgezeichnet wird, ist der von Codex verwendete Modellname, und was im Routing aufgezeichnet wird, ist der zugeordnete Modellname, der während der Deduplizierung nicht abgeglichen werden kann. Jetzt können sich die beiden Seiten gegenüberstehen.
  • Die vom Subagenten im offiziellen Pi-Beispiel verwendete Quote ist nicht in der Statistik enthalten (#8386, #8340). Jetzt wird es separat nach Lieferant und Modell jedes Unteragenten erfasst. Nach dem Upgrade wird die vorherige Pi-Sitzung erneut gelesen und wiederhergestellt.
  • Beim Importieren von MCP aus Pi wurden auch Server importiert und aktiviert, die nicht von Pi unterstützt wurden, und jede nachfolgende Synchronisierung schlug fehl (#7888). Server mit SSE-Verbindungsmethoden, nicht konformen Namen und Servern, deren Namen sich nur von - und _ unterscheiden, werden jetzt übersprungen und aufgefordert; Die MCP-Konfigurationsdatei von Pi wird nicht mehr erstellt, wenn Pi nicht installiert ist.
  • Wenn nur der Agent im Terminal oder CC Switch eingerichtet ist und kein Systemagent eingerichtet ist, schlägt die Preissynchronisierung von models.dev immer wieder fehl (#8739, #6696). Jetzt wird es von CC Switch im Hintergrund heruntergeladen und der von Ihnen festgelegte Agent wird verwendet; Das Gleiche gilt für den Import von Modellpreisen und das automatische Ausfüllen von Modellparametern im Formular.
  • Wenn Claude Code über einen Router eine Verbindung zu xAI herstellt, wird die Anfrage für eine erzwungene Netzwerksuche von xAI abgelehnt und meldet 422 (#8664).
  • MiniMax M3.1 Flash Thinking Gears in Pi (#8540): Die beiden offiziellen MiniMax-Voreinstellungen entfernen „Aus“ und „Minimum“, die von diesem Modell nicht akzeptiert werden, und die restlichen Gänge werden wie gewohnt gesendet.

cc-switch v4.0.25

Highlights

  • MCP connectivity checks — The MCP page gains a "check connectivity" button that handshakes every enabled server (stdio, HTTP, and legacy SSE), with a 30s per-server timeout and a cap of three concurrent checks; each row also gets a "test connection" for a single server. This matters because previously you only found out a server was dead when a coding tool actually tried to use it (#4498). Watch out: results are lazy, not live — nothing is checked on page open, and editing a server's connection config resets its status, so a green result is a point-in-time signal.

  • Codex official quota protection — Opt-in under Settings → App Config → Codex App Enhancements: once 5-hour or weekly usage on an official ChatGPT account crosses a threshold (95%/98% by default), new official requests are paused while third-party models keep working. It applies only to official requests through CC Switch's local router, reads quota data already in responses (no extra calls in steady state), and fails open if quota can't be read. Important behavioral caveat: paused requests return an error outright rather than falling through to your failover queue — plan for a hard stop, not a graceful handoff.

  • Breaking: local router rejects web-origin requests — Requests carrying a browser origin marker, and access to the local router via a normal domain pointing at localhost, are now refused; coding-tool traffic is unaffected. This closes a hole where any web page could spend your stored provider credentials (reported responsibly by @yukitakasama). If you had a custom web UI or dashboard calling the local router, that integration will break and needs to move to a non-browser client.

  • Model menus show provider and actual model — Claude Code's /model menu in route mode, and Claude Desktop in route/aggregate mode, now label entries as "provider · actual model · window" (window only when 1M is in play), replacing the generic "Custom Sonnet model" and name-based Opus/Sonnet guesses. Custom descriptions you set on a provider take precedence. This is a genuine debugging win for tracing which upstream a request hit — especially paired with the auth fix below.

  • Usage accounting fixes — Two long-standing billing bugs are resolved: Codex requests using model mapping were double-counted because session logs and router logs disagreed on the model name (#7643, #5526), and Pi official-example subagent usage was omitted entirely (#8386, #8340). On upgrade, past Pi sessions are re-read to backfill missing usage. Also in route mode, placeholder credentials now go into ANTHROPIC_AUTH_TOKEN instead of ANTHROPIC_API_KEY, fixing Claude Code prompting for a custom key and ending up logged out after choosing "no" (#8111, #8104) — upstream requests are unchanged.

  • Subagent concurrency and exchange rates — Codex provider forms gain a "subagent concurrency limit" that writes [agents] max_threads into config.toml; it's a global setting that survives provider switches (also editable on the official card), and blank means the Codex default (#9055). The usage page can now auto-fetch exchange rates (12h refresh, falls back to the last known rate, stored separately from manual entries), and Kimi Code sessions can finally be deleted from session management, including subagent history.

新增

MCP 连通性检查

以前 MCP 服务器配好以后，只有在编程工具里用到时才知道能不能连上（#4498）。

现在 MCP 页面顶部多了「检查连通性」按钮，会检查所有已启用的服务器；每一行的菜单里也有「测试连接」，只检查这一个。

  • 打开页面时不会自动检查，没检查过的显示「未检查」；改了某个服务器的连接配置后，它的结果会重置。
  • 检查方式是和服务器完成一次 MCP 握手，本地命令（stdio）、HTTP 和旧版 SSE 三种连接方式都支持。每个服务器最多等 30 秒，整个应用同时最多检查 3 个。
  • 本地命令启动的服务器检查完会连同它启动的子进程一起结束，不会留下后台进程。macOS 和 Linux 上不从终端启动 CC Switch 时，也能找到 npx、uvx 这类命令。

Codex 官方额度保护

Codex 用官方 ChatGPT 账号时，五小时或每周额度用完会进入 Reserve 模式。现在可以在额度快用完时先暂停官方请求，留着额度，第三方模型照常可用。

在「设置 → 应用配置 → Codex 应用增强」里打开「官方额度保护」，可以设置五小时和每周使用率的阈值（默认 95% 和 98%），任一达到就暂停新的官方请求。

  • 只对经过 CC Switch 本地路由的 Codex 官方请求生效，默认关闭。
  • 使用率直接读官方响应里自带的额度信息，正常使用时不会多发请求；刚开始用或空闲约 5 分钟后，才会先单独查询一次。
  • 查不到额度（网络问题、登录过期等）时照常放行，不会误挡。被暂停的请求会直接返回错误，不会转到故障转移队列里的其他供应商。

用量页汇率自动获取

用量页「用量设置」里的「显示」区多了「汇率来源」，可以选「手动填写」（默认）或「自动获取」。选了自动获取才会联网，汇率超过 12 小时会自动更新，获取失败时继续用上次的汇率。自动获取的汇率和手动填的分开保存，切回手动填写时你自己填的值还在。费用仍按美元记录，只在显示时换算。

Codex 子代理并发上限

Codex 供应商表单的「子代理模型」下面多了「子代理并发上限」，设置一个 Codex 会话里最多同时开多少个子代理（#9055）。这是 Codex 的全局设置，写进 config.toml 的 [agents] max_threads，切换供应商时保持不变，官方卡片上也能改；留空就用 Codex 的默认值。

模型菜单写明供应商和实际模型

Claude Code 在路由模式下，/model 菜单里每一档以前只写「Custom Sonnet model」，看不出对应哪家供应商的哪个模型。现在会写成「供应商 · 实际模型 · 窗口」（窗口只在上游标了 1M 时显示），聚合模式下的模型也一样。供应商里自己写过模型说明的，以你写的为准。

Claude Desktop 在路由和聚合模式下，模型下面的说明以前按名字里的 Opus、Sonnet 套用官方文案，聚合模型一律显示同一句。现在也改成「供应商 · 实际模型 · 窗口」。

删除 Kimi Code 会话

会话管理里可以直接删除 Kimi Code 会话了，以前只能去 Kimi Code 里删。删除方式和 Kimi Code 自己的一样，子代理的历史会一起删掉。

定价： 内置价格表新增 GPT-6.1 Terra。

变更

  • 本地路由不再接受网页发来的请求。本地路由会把请求换成你保存的供应商凭据再转发，所以网页如果能把请求发到本地路由，就能用掉你的额度。现在带浏览器来源标记的请求会被拒绝，通过普通域名指向本机的访问也不再接受。编程工具发的请求不受影响。
  • Skills「发现」页的工具栏和「已安装」页对齐（#9125）：搜索框位置和宽度一致，刷新按钮改为「刷新仓库」文字按钮，来源、仓库筛选和「只看未安装」挪进表头，「安装到」放在表头右侧。少了一行，功能不变。
  • Windows 上首选终端是 PowerShell 时，装了 PowerShell 7 就用它打开（#8992、#3271），没装才用系统自带的 Windows PowerShell。供应商卡片的「打开终端」和应用的安装、升级都是这样。
  • 预设： 千问 AI 平台和 QwenCloud 的按量付费、Token Plan 改用新的 MaaS 域名，Coding Plan 不变。

修复

  • 在路由或聚合模式下，Claude Code 卡片的「打开终端」混入了路由和聚合的设置。终端里的 Claude Code 会同时带上路由的占位凭据和这张卡片的 Key，这张卡片没配的模型档位会用上聚合里的模型名，发到这张卡片的地址上用不了；/model 菜单里也会出现其他供应商的模型。现在终端里只用这张卡片自己的设置，你的其他全局设置照常保留。
  • 路由模式下，OpenCode Go 等用 ANTHROPIC_API_KEY 存 Key 的供应商会让 Claude Code 要求确认自定义 Key，默认选「否」后就是未登录（#8111、#8104）。现在路由模式下占位凭据一律写进 ANTHROPIC_AUTH_TOKEN，发给上游的请求不变。
  • 给纯文本模型发过一个文件或音频后，之后每一轮都报 400（#6274、#6151）。现在经路由发给纯文本模型时，对话里的文件和音频会换成一段文字说明；智谱 GLM 的中文报错也能认出来。图片的处理不变。
  • Windows 上供应商表单里的名称等内容来回闪（#6420、#6349）。这是 WebView2 的自动填充在覆盖表单内容，现在已对主窗口关掉。
  • 启动后的一段时间里托盘面板打不开，也没法从托盘退出（#9154）。启动时导入会话用量会占着数据库，托盘面板要等数据。现在面板会先弹出，「打开主窗口」和「退出」马上能用，列表随后加载。
  • Codex 经路由用了模型映射时，同一个请求的用量被算两遍（#7643、#5526）。会话日志里记的是 Codex 用的模型名，路由记的是映射后的模型名，去重时对不上。现在两边能对上了。
  • Pi 官方示例的子代理用的额度没有统计进来（#8386、#8340）。现在会按每个子代理的供应商和模型分别记录，升级后会把以前的 Pi 会话重新读一遍补上。
  • 从 Pi 导入 MCP 时，Pi 不支持的服务器也被导入并启用，之后每次同步都失败（#7888）。SSE 连接方式、名字不合规、名字只差 - 和 _ 的服务器现在会跳过并提示；没装 Pi 时也不会再创建 Pi 的 MCP 配置文件。
  • 只在终端或 CC Switch 里设了代理、没设系统代理时，models.dev 价格同步一直失败（#8739、#6696）。现在改由 CC Switch 后台下载，会走你设的代理；导入模型价格和表单自动填模型参数也一样。
  • Claude Code 经路由连 xAI 时，强制联网搜索的请求被 xAI 拒绝，报 422（#8664）。
  • Pi 里的 MiniMax M3.1 Flash 思考档位（#8540）：两个 MiniMax 官方预设去掉了这个模型不接受的「关闭」和「最小」，其余档位照常发送。
