CC-Schalter v4.0.34

CC-Schalter v4.0.34

Diese Version des Skill-Repositorys unterstützt GitLab, Gitea und Forgejo (einschließlich selbst erstellter Instanzen und Codeberg), und Sie können Repositorys nicht mehr nur auf GitHub hinzufügen. Sie können die Sitzung von Antigravity CLI jetzt direkt in der Sitzungsverwaltung löschen; Nachdem Sie den automatischen Download von Updates aktiviert haben, wird der Download der neuen Version sofort gestartet. Darüber hinaus können manuell hinzugefügte WorkBuddy-Modelle die Denkintensität festlegen, und die S3-Synchronisierung kann auch lokal gespeicherte Konfigurationen wie WebDAV löschen. Darüber hinaus meldete der Anbieter „Get Model List“ von Gemini CLI, dass der Schlüssel ungültig ist oder eine leere Liste erhält; Das Copilot-Modell GitHub im Codex gilt als nicht unterstützend für Bilder. Alibaba Cloud OSS, Tencent Cloud COS und Huawei Cloud OBS können die S3-Synchronisierung nicht verwenden. Der gesamte Upload der Cloud-Synchronisierung schlägt fehl, wenn im Skills-Verzeichnis ungültige Links vorhanden sind. Fable 5.2 wird im Routing-Modus als Fable 5 angezeigt; Copilot Die Cache-Trefferquote des Gemini-Modells auf Copilot ist niedrig; Copilot hat Probleme wie eine fehlgeschlagene Anfrage für das 1M Fable-Modell. Hinzufügen

Skill Warehouse unterstützt GitLab, Gitea und Forgejo

„Management Skills Warehouse“ akzeptierte früher nur die Adresse von github.com, kann aber jetzt auch öffentliche Warehouses auf GitLab, Gitea und Forgejo hinzufügen (Anforderungen siehe #1324, #4227), einschließlich selbst erstellter Instanzen und Codeberg:

  • Füllen Sie owner/name aus und verarbeiten Sie es weiterhin als GitHub. Wenn Sie die vollständige Adresse anderer Websites eingeben, fragt CC Switch zunächst, ob es sich bei der Website um Gitea / Forgejo oder GitLab handelt, und lädt sie dann auf die entsprechende Weise herunter. Benutzerdefinierte Ports, mehrstufige Gruppierung von GitLab und auf der Gitea-Seite kopierte Adressen können alle verwendet werden.
  • Die Links „Skills durchsuchen“, „Installation“, „Nach Updates suchen“ und „Dokument öffnen“ führen alle zu der Site, auf der sich das Repository befindet.
  • Es werden nur öffentliche Lager unterstützt und die Adresse muss https sein. Gitee unterstützt es noch nicht (für die Download-Schnittstelle ist ein Token erforderlich).
  • Derselbe owner/name kann nur auf einer Site aufbewahrt werden. Durch das Hinzufügen eines Lagers mit demselben Namen zu einem anderen Standort wird das ursprüngliche Lager ersetzt.

Antigravity CLI-Sitzung in der Sitzungsverwaltung löschen

Bisher konnten Antigravity-Sitzungen nur in agy gelöscht werden. Jetzt können Sie die Sitzung von Antigravity CLI direkt in der Sitzungsverwaltung löschen. Beim Löschen werden der Sitzungsindex und die Zusammenfassung genau wie Agy selbst bereinigt. Nach dem Neustart von agy wird es nicht mehr angezeigt.

  • Die Sitzung kann nicht gelöscht werden, während sie in agy geöffnet ist. Schließen Sie es zuerst. – Antigravity-IDE-Sitzungen sowie Sitzungen, die nur Indizes und keine Sitzungsdatensätze enthalten, müssen weiterhin in Antigravity gelöscht werden.

Beginnen Sie sofort mit dem automatischen Herunterladen der neuen Version, nachdem Sie sie entdeckt haben

Nach der Aktivierung von „Updates automatisch herunterladen“ musste etwa eine Minute nach dem Start auf eine Hintergrundüberprüfung gewartet werden, um mit dem Herunterladen zu beginnen. Auf der Seite „Über“ wurde nur angezeigt, dass es eine neue Version gibt, was den Anschein erweckt, dass der Wechsel nicht in Kraft getreten ist. Jetzt beginnt der Download, sobald beim Start eine neue Version gefunden wird, und „Neue Version wird im Hintergrund heruntergeladen …“ oder „Download abgeschlossen“ wird unter der Eingabeaufforderung für die neue Version auf der Seite „Info“ angezeigt. Die Symbole, Texte und Schaltflächen des Installationsbestätigungsfelds wurden ebenfalls neu ausgerichtet.

Manuell hinzugefügte WorkBuddy-Modelle können die Denkintensität festlegen

Das standardmäßige WorkBuddy-Modell konnte die Denkintensität bereits im WorkBuddy-Modellmenü auswählen, aber die Modelle, die manuell hinzugefügt oder aus der Modellliste ausgewählt wurden, verfügen nur über den Denkschalter (siehe #9599). Nachdem Sie nun das Denken aktiviert haben, können Sie die in den Modelldetails bereitzustellende „Denkintensität“ überprüfen und „Denken kann ausgeschaltet werden“ festlegen. Wenn keines von beiden aktiviert ist, wird weiterhin nur der Denkschalter angezeigt. Aus der Modellliste erhaltene Modelle werden gemäß den Regeln der Pi-Form auch automatisch mit verfügbaren Stärken gefüllt.

S3-Synchronisierung kann die lokale Konfiguration löschen

Die S3-Synchronisierungseinstellungen verfügen über eine neue „Clear Configuration“, die mit WebDAV identisch ist: Löschen Sie den gespeicherten Bereich, den Bucket, den Schlüssel, den Endpunkt und das Remote-Verzeichnis vom lokalen Computer und stoppen Sie die automatische Synchronisierung. Die hochgeladenen Daten im Bucket werden nicht gelöscht.

Fix

  • Der Anbieter „Get Model List“ von Gemini CLI meldet, dass der Schlüssel ungültig ist oder bei Verwendung eines kompatiblen Gateways eine leere Liste abgerufen wird (siehe #8546): Wenn Sie in der Vergangenheit Authorization: Bearer gedrückt haben, um einen AI Studio-Schlüssel zu senden, wurde dieser von Google nicht erkannt; Jetzt erhalten Sie es über die native Methode von Gemini. Die letzte Version wurde von Claude Code / Claude Desktop repariert, die sich für den Anbieter des Gemini Native-Formats entschieden. Diesmal wurde die Reparatur vom eigenen Lieferanten von Gemini CLI durchgeführt.
  • Wenn GitHub Copilot in Codex verwendet wird, werden Modelle, die Bilder unterstützen, nur als unterstützender Text behandelt (#8027, siehe #7977): Beim Abrufen der Modellliste wird die von Copilot deklarierte Bildeingabefunktion gelesen. Für hinzugefügte Copilot-Lieferanten rufen Sie bitte die Modellliste erneut ab und speichern Sie sie. Beenden Sie dann Codex vollständig und starten Sie es neu.
  • Alibaba Cloud OSS, Tencent Cloud COS und Huawei Cloud OBS können die S3-Synchronisierung nicht verwenden und werden mit einem Zugriffsschlüsselfehler aufgefordert (siehe #3996): Die neuen Buckets dieser drei Unternehmen lehnen die alte pfadbasierte Adresse ab und verwenden nun automatisch die Adresse, die den Bucket im Domänennamen platziert. Andere Dienste wie MinIO und R2 bleiben unverändert.
  • Der in den S3-Synchronisierungseinstellungen ausgewählte Dienstanbieter wird nach dem erneuten Öffnen der Einstellungsseite nicht gespeichert (#8644).
  • Wenn im Skills-Verzeichnis ungültige Links vorhanden sind, schlägt der gesamte Cloud-Synchronisierungs-Upload fehl (siehe #9615): Ungültige symbolische Links oder Verzeichnisverbindungen, die unter Windows nicht geöffnet werden konnten, führten bisher zum Abbruch des gesamten Uploads (Windows meldete os error 5), und der Download konnte auch vorhandene Skills nicht sichern. Solche Links werden jetzt übersprungen und eine Warnung protokolliert.
  • Wenn der Upstream Fable 5.2 im Routing-Modus ist, zeigt /model von Claude Code immer noch Fable 5 an (siehe #9608): Fable 5.2 / 5.1 wird jetzt als Modell-ID der entsprechenden Version geschrieben, und Claude Desktop wird ebenfalls korrigiert.
  • Wenn GitHub Copilot das Gemini-Modell verwendet, beträgt die Cache-Trefferquote für lange Sitzungen nur etwa 27 % (siehe #9613): Claude Code hängt jede Runde eine Systemnachricht an, und Copilot scheint sie an den Anfang der Anfrage zu verschieben, was dazu führt, dass sich der Anfang jeder Anfragerunde ändert. Jetzt nur noch für das Gemini-Modell auf Copilot: Systemnachrichten in der Mitte der Sitzung werden als Benutzernachrichten an ihren ursprünglichen Positionen gesendet, und der Anfang ändert sich nicht. Andere Anbieter und Modelle sind nicht betroffen.
  • Wenn GitHub Copilot das Fable-Modell verwendet und 1M prüft, meldet die Anfrage 400: Copilot verfügt nicht über eine 1M-Version des Claude-Modells und gibt jetzt das normale Modell derselben Version zurück. Nach Erhalt der Copilot-Modellliste können Modelle, die keine 1M-Version haben (und deren Kontext weniger als 1M beträgt), nicht auf 1M überprüft werden; diejenigen, die bereits überprüft wurden, werden in der Eingabeaufforderung aufgelistet. Es wird empfohlen, abzubrechen, da Claude Code den Kontext weiterhin gemäß 1M plant.
  • Nach Änderung des Hermes-Konfigurationsverzeichnisses in den Einstellungen wurde der Lieferant nicht in das neue Verzeichnis geschrieben (#9567). – Nachdem ein interner Fehler bei der MCP-Konnektivitätserkennung oder der DeepSeek Harness-Anmeldung auftritt, muss CC Switch neu gestartet werden, bevor er erneut verwendet werden kann (#9572).
  • Wenn der Name, die Adresse oder der Modellname des Lieferanten das Wort Mistral enthält, wird es als Mistral behandelt. Denkintensität (#9573): Jetzt wird nur noch die offizielle Adresse api.mistral.ai erkannt.
  • Qwen4-Maximalpreis hinzugefügt (#9612).

Upgrade-Anweisungen

Datenbankversion von 26 auf 27 erhöht, damit das Skill Warehouse die Site aufzeichnen kann, auf der es sich befindet. Die Datenbank wird vor dem Upgrade automatisch gesichert; Wenn Sie nach dem Upgrade ein Rollback auf die alte Version durchführen, meldet die alte Version, dass die Datenbankversion zu neu ist und nicht geöffnet werden kann.

cc-switch v4.0.34

Highlights

  • One-way database migration (v26 → v27) — The only breaking change: the schema now records which host each skill repo lives on. Upgrade auto-backs-up the DB, but rollback is off the table — older builds refuse to open the newer database ("version too new"). If you need an escape hatch, keep that pre-upgrade backup yourself before deploying.
  • Skill repos escape GitHub (#4227) — "Manage skill repos" now accepts GitLab, Gitea and Forgejo, including self-hosted instances and Codeberg. owner/name still means GitHub; a full URL triggers a one-time Gitea/Forgejo-vs-GitLab prompt, and custom ports, GitLab nested groups and URLs copied from Gitea all work — browsing, install, update checks and "open docs" follow the repo's host. Watch the limits: public repos and HTTPS only (no Gitee, whose download API needs a token), and since an owner/name may exist on only one host, adding the same name elsewhere silently replaces the original entry.
  • Copilot fixes demand a manual refresh and restart — Image-capable Copilot models were misdetected as text-only (#8027); existing providers must re-fetch and save the model list, then fully quit and restart Codex. The 1M checkbox is also now honest: Copilot has no 1M Claude variants, so requests fall back to the standard model, models without 1M can no longer be flagged, and any still-checked ones are listed for you to uncheck — Claude Code otherwise keeps planning against a 1M context it won't get.
  • Copilot + Gemini cache-hit rate repaired — Long sessions through GitHub Copilot were hitting ~27% cache because Claude Code appends a system message every turn, which Copilot hoists to the front and thereby changes the prompt prefix each round (#9613). The fix re-sends mid-session system messages in place as user messages, scoped to Gemini models on Copilot only — expect better cache reuse there, no behavior change elsewhere.
  • S3 sync: virtual-hosted addressing and local config clearing — Alibaba OSS, Tencent COS and Huawei OBS buckets reject legacy path-style URLs, so sync now uses bucket-in-domain addressing (#3996); MinIO/R2 are untouched. A new "Clear config" action (like WebDAV) wipes locally stored region, bucket, keys, endpoint and remote dir and stops auto-sync — uploaded data in the bucket is safe, and the chosen provider now survives reopening settings (#8644).
  • Smaller operational fixes worth noting — Gemini CLI providers now fetch models the native way instead of sending an Authorization: Bearer AI Studio key that Google rejects or that yields empty lists via gateways (#8546). Cloud sync skips dead symlinks / broken Windows junctions with a warning instead of aborting the whole upload (#9615). Auto-download now starts the moment an update is detected at launch rather than waiting for the ~1-minute background check. And Mistral thinking-strength handling now keys off the official api.mistral.ai host, so any provider/name/model containing the string "mistral" is no longer misclassified (#9573).

CC Switch v4.0.34

本版本的技能仓库支持 GitLab、Gitea 和 Forgejo（包括自建实例和 Codeberg），不再只能添加 GitHub 上的仓库。会话管理里现在可以直接删除 Antigravity CLI 的会话；开启自动下载更新后，发现新版本会立刻开始下载。另外，WorkBuddy 手动添加的模型可以设置思考强度，S3 同步也可以像 WebDAV 一样清除本机保存的配置。

另外修复了 Gemini CLI 的供应商「获取模型列表」报 Key 无效或拿到空列表；Codex 里的 GitHub Copilot 模型被当成不支持图片；阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步；Skills 目录里有失效链接时整个云同步上传失败；路由模式下 Fable 5.2 被显示成 Fable 5；Copilot 上的 Gemini 模型缓存命中率低；Copilot 上勾了 1M 的 Fable 模型请求失败等问题。

新增

技能仓库支持 GitLab、Gitea 和 Forgejo

「管理技能仓库」以前只接受 github.com 的地址，现在也能添加 GitLab、Gitea、Forgejo 上的公开仓库（需求见 #1324、#4227），包括自建实例和 Codeberg：

  • 填 owner/name 仍按 GitHub 处理；填其他站点的完整地址时，CC Switch 会先问一次这个站点是 Gitea / Forgejo 还是 GitLab，再按对应的方式下载。自定义端口、GitLab 的多级分组、Gitea 页面上复制的地址都能用。
  • 浏览技能、安装、检查更新和「打开文档」链接都会去仓库所在的站点。
  • 只支持公开仓库，地址必须是 https。Gitee 暂不支持（它的下载接口需要令牌）。
  • 同一个 owner/name 只能保留在一个站点上，在另一个站点添加同名仓库会替换原来的。

在会话管理里删除 Antigravity CLI 会话

以前 Antigravity 的会话只能在 agy 里删。现在可以在会话管理里直接删除 Antigravity CLI 的会话，删除时会和 agy 自己一样，把它的会话索引和摘要一并清理，重启 agy 后不会再冒出来。

  • 会话正在 agy 里打开时不能删，先在 agy 里关掉它。
  • Antigravity IDE 的会话，以及只有索引、没有会话记录的会话，仍然要在 Antigravity 里删除。

发现新版本后立刻开始自动下载

开启「自动下载更新」后，以前要等启动约 1 分钟后的后台检查才开始下载，「关于」页只显示有新版本，看起来像开关没生效。现在启动时一发现新版本就开始下载，「关于」页的新版本提示下会显示「正在后台下载新版本…」或「已下载完毕」。安装确认框的图标、文字和按钮也重新对齐了。

WorkBuddy 手动添加的模型可以设置思考强度

预设里的 WorkBuddy 模型早就能在 WorkBuddy 的模型菜单里选思考强度，手动添加或从模型列表选的模型却只有思考开关（见 #9599）。现在打开思考后，模型详情里可以勾选要提供的「思考强度」，并设置「可以关闭思考」；都不勾时仍只显示思考开关。从模型列表获取的模型也会按 Pi 表单的规则自动填上可用的强度。

S3 同步可以清除本机配置

S3 同步设置新增「清除配置」，和 WebDAV 一样：从本机删除保存的区域、存储桶、密钥、端点和远程目录，并停止自动同步，存储桶里已经上传的数据不会删除。

修复

  • Gemini CLI 的供应商「获取模型列表」报 Key 无效，或者用兼容网关时拿到空列表（见 #8546）：以前按 Authorization: Bearer 发 AI Studio Key，Google 不认；现在按 Gemini 原生方式获取。上一版修好的是 Claude Code / Claude Desktop 选 Gemini Native 格式的供应商，这次修的是 Gemini CLI 自己的供应商。
  • Codex 里用 GitHub Copilot 时，支持图片的模型被当成只支持文字（#8027，见 #7977）：获取模型列表时会读取 Copilot 声明的图片输入能力。已经添加的 Copilot 供应商，请重新获取模型列表并保存，再完全退出并重启 Codex。
  • 阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步，被提示 Access Key 错误（见 #3996）：这三家的新存储桶拒绝旧的路径式地址，现在会自动改用把存储桶放在域名里的地址。MinIO、R2 等其他服务不变。
  • S3 同步设置里选的服务商，重新打开设置页后没记住（#8644）。
  • Skills 目录里有失效的链接时，云同步整个上传失败（见 #9615）：失效的符号链接，或 Windows 上打不开的目录联接，以前会让上传整体中止（Windows 上报 os error 5），下载时也会在备份现有 Skills 这一步失败。现在跳过这类链接并记录警告。
  • 路由模式下上游是 Fable 5.2 时，Claude Code 的 /model 仍显示 Fable 5（见 #9608）：Fable 5.2 / 5.1 现在写成对应版本的模型 ID，Claude Desktop 同样修正。
  • 经 GitHub Copilot 用 Gemini 模型时，长会话的缓存命中率只有约 27%（见 #9613）：Claude Code 每一轮都会追加一条系统消息，Copilot 看起来会把它们都挪到请求开头，导致每轮请求的开头都变了。现在只对 Copilot 上的 Gemini 模型，把会话中途的系统消息按原位置作为用户消息发送，开头不再变化。其他供应商和模型不受影响。
  • 经 GitHub Copilot 用 Fable 模型并勾选 1M 时，请求报 400：Copilot 没有 1M 版本的 Claude 模型，现在会退回同版本的普通模型。获取过 Copilot 模型列表后，没有 1M 版本（上下文也不到 1M）的模型不能再勾 1M；已经勾了的会列在提示里，建议取消，因为 Claude Code 仍会按 1M 规划上下文。
  • 在设置里改了 Hermes 的配置目录后，供应商没有写进新目录（#9567）。
  • MCP 连通性检测或 DeepSeek Harness 登录出过一次内部错误后，要重启 CC Switch 才能再用（#9572）。
  • 供应商名称、地址或模型名里带 mistral 字样，就会被当成 Mistral 处理思考强度（#9573）：现在只认官方地址 api.mistral.ai。
  • 新增 Qwen4 Max 的价格（#9612）。

升级说明

数据库版本从 26 升到 27，为技能仓库记录它所在的站点。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
