CC-Schalter v4.0.32

CC-Schalter v4.0.32

Diese Version fügt Updates automatisch im Hintergrund herunterladen hinzu: Nachdem Sie „Updates automatisch herunterladen“ unter „Einstellungen → Info“ aktiviert haben, wird die neue Version heruntergeladen und im Hintergrund überprüft. In der unteren rechten Ecke wird eine Eingabeaufforderung angezeigt, in der Sie gefragt werden, ob Sie es installieren möchten. Ohne Bestätigung wird kein Neustart durchgeführt. „Einstellungen → Netzwerk“ hat IP-Erkennung hinzugefügt, mit der Sie die Ausgangs-IP und -Region anzeigen können, wenn auf CC Switch über einen globalen Proxy, einen temporären Proxy oder das aktuelle Netzwerk zugegriffen wird. Darüber hinaus haben wir Probleme behoben, z. B. wenn Codex eine alte Sitzung über Routing- und Anbieterwechsel fortsetzt, der Upstream zuerst 200 zurückgibt und dann „Entschlüsselung nicht möglich“ meldet, was dazu führt, dass die gesamte Runde verworfen wird; Codex fordert den Bericht 422 an, wenn über Routing oder Aggregation eine Verbindung zu Mistral AI hergestellt wird; Nachdem ein Vorgang in CC Switch abstürzt, wird das Fach leer und der Anbieter kann erst nach einem Neustart gewechselt werden. Mit Mise installierte Tools zeigen auf der Seite „Anwendung“ zwei Installationsdatensätze an. Englisch → | Japanische Version →

Hinzufügen

Updates automatisch im Hintergrund herunterladen

„Einstellungen → Info“ fügt den Schalter „Updates automatisch herunterladen“ hinzu, der standardmäßig deaktiviert ist und für jedes Gerät individuell eingestellt werden kann.

  • Nach dem Einschalten überprüft CC Switch eine Minute nach dem Start und dann alle sechs Stunden. Wenn es eine neue Version gibt, wird diese im Hintergrund heruntergeladen und überprüft.
  • Nach dem Herunterladen werden Sie in der unteren rechten Ecke der Hauptoberfläche gefragt, ob Sie es installieren möchten. Die Installation startet CC Switch neu und Anfragen, die über das lokale Routing laufen, werden unterbrochen. Sie müssen also auf „Installieren und neu starten“ klicken, um fortzufahren. Dies wird in der Eingabeaufforderung angegeben, wenn das Routing aktiviert ist.
  • Wenn Sie auf „Später“ klicken, werden Sie nicht mehr nach dieser Version gefragt. Der rote Punkt in den Einstellungen, der Button auf der „Info“-Seite und das neue „Neustarten und auf vX aktualisieren“ im Tray-Menü und Shortcut-Panel können weiterhin installiert werden.
  • Das deb/rpm-Installationspaket der tragbaren Version und von Linux kann nicht automatisch installiert werden. Der Schalter wird ausgegraut und der Grund wird erklärt.

IP-Erkennung

„Einstellungen → Netzwerk“ fügt eine IP-Erkennung unter dem globalen Proxy hinzu (#9449, siehe #9448 für Anforderungen): Wählen Sie den gespeicherten globalen Proxy aus oder geben Sie einen temporären Proxy ein (wird nur für diese Erkennung verwendet, nicht gespeichert). Nachdem Sie auf „IP erkennen“ geklickt haben, werden die Exit-IP, ob die Ergebnisse der beiden Erkennungsdienste konsistent sind, sowie Informationen wie Land oder Region, Stadt, Betreiber usw. angezeigt. Wenn kein globaler Proxy vorhanden ist, wird der System-Proxy oder die direkte Verbindung zur Erkennung verwendet. Wenn ein Proxy angegeben ist, wird die direkte Verbindung nicht verwendet, wenn der Proxy keine Verbindung herstellen kann.

  • Erst nach dem Klicken ausführen, wird icanhazip.com und ipify.org besucht und die gemessene IP an ipwho.is gesendet, um den Standort abzufragen.
  • Gemessen wird der eigene Ausgang des CC-Switches über diese Leitung, der nicht unbedingt dem Ausgang von Clients wie Claude Code und Codex entspricht.

Andere

  • Auf der Rücklieferantenkarte von GitHub Copilot wird das gebundene GitHub-Konto angezeigt (#9228, Anforderungen siehe #9480): Bisher wurde nur die offizielle Website-Adresse von GitHub Copilot angezeigt und es war schwierig, zwischen mehreren Konten zu unterscheiden. Wenn es nicht gebunden ist, wird das Standardkonto des Autorisierungscenters angezeigt. Wenn die Bemerkung ausgefüllt ist, hat die Bemerkung Vorrang.

Fix

  • Wenn Codex die alte Sitzung über den Switching-Anbieter fortsetzt, gibt der Upstream zunächst 200 zurück und meldet dann „Verschlüsselter Funktionsausgabeinhalt konnte nicht entschlüsselt oder dekodiert werden“. Nachdem Codex fünfmal die Verbindung wiederhergestellt hat, wird diese Runde verworfen (#9476): Wenn die Anfrage den vom vorherigen Anbieter generierten Gedankendatensatz oder verschlüsselten Inhalt enthält, wartet CC Switch, bis der Upstream mit der Ausgabe beginnt, bevor er sie übergibt. Wenn Codex zu diesem Zeitpunkt abgelehnt wird, entfernen Sie diese Inhalte und versuchen Sie es automatisch erneut bei derselben Firma. Die Sitzung kann dann fortgesetzt werden. Anfragen ohne diesen Inhalt werden wie gewohnt zurückgesendet.
  • Wenn der Codex über Routing oder Aggregation mit Mistral AI verbunden ist, meldet die Anfrage 422 extra_forbidden (#9507): Das vom Codex getragene Sonderfeld „Antworten“, die automatisch hinzugefügten Denkparameter für das DeepSeek-/GLM-Modell auf Mistral und das in jeder Runde nach der Verwendung des Tools mitgeführte reasoning_content werden entfernt, wenn es an api.mistral.ai gesendet wird. Andere Upstreams sind nicht betroffen.
  • Nachdem ein interner Vorgang von CC Switch einmal abstürzt, wird das Tray-Menü leer, der Anbieter kann nicht gewechselt werden und die Direktverbindung kann beim Beenden nicht wiederhergestellt werden. Es kann nur neu gestartet werden (#9472, #9483, siehe #8058): Datenbank, Einstellungen, Schreiben von Konfigurationsdateien, MCP, Eingabeaufforderungswörter, Preise, Sicherung und andere Vorgänge können jetzt nach einem Absturz wiederhergestellt werden, und nicht abgeschlossene Änderungen zum Zeitpunkt des Absturzes werden rückgängig gemacht.
  • Bei Verwendung von Claude Code / Claude Desktop über GitHub Copilot meldeten Modelle wie Grok, die nur die Responses-Schnittstelle in Copilot unterstützen, „nicht zugänglich über den /chat/completions-Endpunkt“ (#6954, #9473): Dieser Modelltyp verwendet jetzt die Responses-Schnittstelle und die von beiden Schnittstellen unterstützten Modelle bleiben unverändert.
  • Wenn Antigravity Orchestrator auswählt, wird die gesamte Nutzung unter dem Namen eines virtuellen Modells aufgezeichnet und die Kosten betragen 0 (#9493, #9494): Jetzt basiert der Preis auf dem tatsächlich verwendeten Modell bei jedem Schritt und der Preis von Gemini 4 Hydrogen wird hinzugefügt. Der importierte Antigravity-Verlauf wird erneut analysiert und die Kosten werden kompensiert.
  • Nach dem Aktivieren von „Unified Codex Session History“ oder dem Migrieren des Verlaufs werden Sitzungen von vor einigen Monaten in codex resume an erster Stelle gereiht (#3866, #9471): Beim Neuschreiben gewöhnlicher .jsonl-Sitzungsdateien wird die ursprüngliche Änderungszeit beibehalten, und die komprimierten Dateien bleiben erhalten. Die geänderte Änderungszeit wird nicht wiederhergestellt.
  • Für in Hermes gelöschte Lieferanten ist der Lösch-Button in CC Switch immer grau (#4816, #9470): Lieferanten, die nicht mehr in Hermes vorhanden sind, können jetzt bearbeitet und gelöscht werden; Sie sind weiterhin gesperrt, wenn die Hermes-Konfiguration nicht gelesen werden kann.
  • Beim Hinzufügen eines OpenClaw-Lieferanten aus einer Voreinstellung listet /model die Modelle auf, die mit der Voreinstellung geliefert werden, nicht das zuletzt im Formular gespeicherte Modell (#9474, siehe #6729): Die gelöschten Modelle im Formular werden nicht wieder angezeigt und die neu hinzugefügten Modelle können ebenfalls ausgewählt werden; Beim direkten Speichern ohne Änderung der Voreinstellung werden alle voreingestellten Modelle registriert. Das Bearbeiten eines vorhandenen Lieferanten wird noch nicht synchronisiert, #6729 wird weiterhin verfolgt.
  • Mit Mise installierte Tools, auf der Seite „Anwendung“ werden zwei Installationsdatensätze angezeigt (einer davon ist als Homebrew gekennzeichnet, wenn Mise mit Homebrew installiert wird) (#9515): Der Shim von Mise zählt jetzt als die Installation, auf die er tatsächlich verweist.
  • Wenn das Fenster kurz ist, wird die Bestätigungsschaltfläche des Dialogfelds „Terminal öffnen“ aus dem Bildschirm herausgedrückt und kann nicht angeklickt werden (#9478): Der Inhalt des Dialogfelds kann unabhängig gescrollt werden, und die Schaltfläche ist unten fixiert; Sie können das Terminal auch direkt öffnen, indem Sie im Eingabefeld „Zusätzliche Parameter (optional)“ die Eingabetaste drücken.
  • Beim Wechselkursstatus auf der Nutzungsseite fehlt ein Punkt und er hängt mit der folgenden Beschreibung zusammen (#9436).

cc-switch v4.0.32

Highlights

  • Automatic update downloads, manual installation — Enable the opt-in setting to check one minute after launch, then every six hours; updates are downloaded and verified in the background. Installation still requires confirmation and restarts CC Switch, interrupting requests through its local router. Portable and Linux deb/rpm builds cannot auto-install. “Later” suppresses the prompt for that version without removing the other update entry points.
  • Proxy-aware IP diagnostics (#9449) — Check the exit IP and geolocation for a saved global proxy or an unsaved temporary proxy. Results show agreement between two IP services, and a failed selected proxy does not fall back to direct access. Note that this measures CC Switch’s own route, not necessarily Claude Code’s or Codex’s traffic.
  • Reliable Codex provider routing (#9476, #9507) — If a new provider rejects encrypted content from a previous provider after starting a 200 response, CC Switch strips that content and retries once with the same provider. Requests to Mistral AI also omit Responses-only fields, model-specific thinking parameters, and stale reasoning_content, eliminating 422 extra_forbidden errors.
  • Copilot model compatibility and account visibility (#9473, #9228) — Models such as Grok that Copilot exposes only through Responses are routed to that endpoint instead of failing on /chat/completions. Provider cards now distinguish accounts using the bound GitHub identity or a custom note.
  • Crash recovery and accurate accounting (9472, #9483, #9494) — Database, settings, configuration, MCP, prompt, pricing, and backup operations can recover after an internal crash and roll back incomplete writes, preventing a broken tray and direct-connect state. Antigravity Orchestrator usage is now charged to the model used at each step, and imported history is reparsed to backfill costs.
  • Provider management fixes — Hermes providers deleted externally become editable and removable (#9470); new OpenClaw providers now register the models actually saved in the form (#9474), though editing existing providers still does not sync them. Codex history ordering is also corrected by preserving original .jsonl modification times (#9471).

No breaking changes.

CC Switch v4.0.32

本版本新增后台自动下载更新：在「设置 → 关于」打开「自动下载更新」后，新版本会在后台下载并校验好，右下角弹出提示问你是否安装，不会未经确认就重启。「设置 → 网络」新增 IP 检测，可以查看 CC Switch 经全局代理、临时代理或当前网络访问时的出口 IP 和所在地区。

另外修复了 Codex 经路由换供应商续接旧会话后，上游先回 200 再报「无法解密」导致整轮报废；Codex 经路由或聚合接 Mistral AI 时请求报 422；CC Switch 内部某个操作崩溃一次后，托盘变空、切不了供应商，直到重启；用 mise 装的工具在「应用」页显示两条安装记录等问题。

新增

后台自动下载更新

「设置 → 关于」新增「自动下载更新」开关，默认关闭，每台设备单独设置。

  • 打开后，CC Switch 启动一分钟后检查一次，之后每六小时检查一次，有新版本就在后台下载并校验。
  • 下载好后，主界面右下角会问你是否安装。安装会重启 CC Switch，正在经本地路由的请求会中断，所以一定要你点「安装并重启」才会进行；路由开着时提示里会写明这一点。
  • 点「稍后」只是不再为这个版本弹提示，设置里的红点、「关于」页的按钮，以及托盘菜单和快捷面板里新增的「重启并更新到 vX」仍然可以安装。
  • 便携版和 Linux 的 deb / rpm 安装包不能自动安装，开关会置灰并说明原因。

IP 检测

「设置 → 网络」在全局代理下方新增 IP 检测（#9449，需求见 #9448）：选已保存的全局代理或填一个临时代理（只用于这次检测，不保存），点「检测 IP」后会显示出口 IP、两个检测服务的结果是否一致，以及国家或地区、城市、运营商等信息。没设全局代理时，按系统代理或直连检测；指定了代理时，代理连不上不会改用直连。

  • 只在点击后运行，会访问 icanhazip.com、ipify.org，并把测得的 IP 发给 ipwho.is 查询位置。
  • 测的是 CC Switch 自己经这条线路的出口，不一定等于 Claude Code、Codex 等客户端的出口。

其他

  • GitHub Copilot 反代供应商卡片显示绑定的 GitHub 账号（#9228，需求见 #9480）：以前只显示 GitHub Copilot 的官网地址，多个账号时分不清。没绑定时显示授权中心的默认账号，填了备注时备注优先。

修复

  • Codex 经路由换供应商续接旧会话时，上游先回 200、再报「Encrypted function output content could not be decrypted or decoded」，Codex 重连五次后这一轮报废（#9476）：请求里带着上一家生成的思考记录或加密内容时，CC Switch 会先等上游开始输出再交给 Codex，这时被拒就去掉这些内容后在同一家自动重试一次，会话可以继续。不带这类内容的请求照常直接流式返回。
  • Codex 经路由或聚合接 Mistral AI 时，请求报 422 extra_forbidden（#9507）：Codex 带的 Responses 专用字段、为 Mistral 上的 DeepSeek / GLM 模型自动加的思考参数，以及用过工具之后每轮都带的 reasoning_content，发往 api.mistral.ai 时都会去掉。其他上游不受影响。
  • CC Switch 内部某个操作崩溃一次后，托盘菜单变空、切不了供应商，退出时也恢复不了直连，只能重启（#9472、#9483，见 #8058）：数据库、设置、配置文件写入、MCP、提示词、价格、备份等操作现在都能在崩溃后恢复，崩溃时没写完的改动会回滚。
  • 经 GitHub Copilot 用 Claude Code / Claude Desktop 时，Grok 这类在 Copilot 里只支持 Responses 接口的模型报「not accessible via the /chat/completions endpoint」（#6954、#9473）：这类模型现在改走 Responses 接口，两种接口都支持的模型不变。
  • Antigravity 选 Orchestrator 时，用量全部记在一个虚拟模型名下、费用为 0（#9493、#9494）：现在按每一步实际使用的模型计价，并新增 Gemini 4 Hydrogen 的价格。已导入的 Antigravity 历史会重新解析一次，补上费用。
  • 开启「统一 Codex 会话历史」或迁移历史后，几个月前的会话在 codex resume 里排到了最前面（#3866、#9471）：改写普通 .jsonl 会话文件时会保留原来的修改时间，压缩过的文件本来就会保留。已经被改乱的修改时间不会恢复。
  • 在 Hermes 里删掉的供应商，CC Switch 里删除按钮一直是灰的（#4816、#9470）：Hermes 里已经没有的供应商现在可以编辑和删除；读不到 Hermes 配置时仍然锁定。
  • 从预设新增 OpenClaw 供应商时，/model 里列的是预设自带的模型，不是表单里最后保存的（#9474，见 #6729）：在表单里删掉的模型不会再出现，新加的模型也能选；不改动预设直接保存时，会登记预设的全部模型。编辑已有供应商时还不会同步，#6729 仍在跟进。
  • 用 mise 安装的工具，「应用」页显示两条安装记录（mise 用 Homebrew 安装时其中一条标成 homebrew）（#9515）：mise 的 shim 现在算作它实际指向的那个安装。
  • 窗口较矮时，「打开终端」对话框的确认按钮被挤出屏幕，点不到（#9478）：对话框内容可以单独滚动，按钮固定在底部；在「附加参数（可选）」输入框里按回车也可以直接打开终端。
  • 用量页的汇率状态缺句号，和后面的说明连在一起（#9436）。
