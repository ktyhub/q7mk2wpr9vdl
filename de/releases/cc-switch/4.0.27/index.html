CC-Schalter v4.0.27

CC-Schalter v4.0.27

Mit dieser Version kann die Sitzungsverwaltung den Nachrichtentext durchsuchen, Einstellungen für Schnittstellendichte und Schnittstellenskalierung hinzufügen, Modellpreistabellen durchsuchen und von Grok Build verwendete Lieferanten können das Terminal ebenfalls öffnen. Die installierte Seite von Skills wurde neu gestaltet und die Lieferantensymbole folgen dem dunklen und hellen Thema. Darüber hinaus wurde die Konfigurationsdatei durch eine normale Datei ersetzt oder konnte nicht geschrieben werden, wenn es sich um einen Softlink handelte, der Lieferant steckte in der Wiederherstellung des Leistungsschalters fest, bis er nach dem Abbrechen der Anfrage neu gestartet wurde, der Planmodus meldete einen Fehler, nachdem der Codex benutzerdefinierte Berechtigungen festgelegt hatte, der Lauf-Skill wurde fälschlicherweise als aktualisiert gemeldet, das Skills-Warehouse zeigte 0 Skills an, pi.exe von Python wurde unter Windows als Pi erkannt, die Modellpreissynchronisierung war abgelaufen, das Fenster konnte beim Öffnen des Dialogs nicht gezogen werden Box, das Browser-Menü wird durch Klicken mit der rechten Maustaste angezeigt, und Linux-Probleme wie eine abnormale Anzeige des Verknüpfungsfelds. Den vollständigen Update-Inhalt von 4.0 finden Sie in den [Versionshinweisen zu v4.0] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Hinzufügen

Durchsuchen Sie den Nachrichtentext einer Konversation

In der Vergangenheit konnte die Suche auf der Sitzungsverwaltungsseite nur den Titel, das Verzeichnis und die Sitzungs-ID finden. Es konnte nicht gefunden werden, als ich mich daran erinnerte, worüber ich gesprochen hatte, konnte mich aber nicht erinnern, um welche Sitzung es sich handelte (#7896, #7420). Jetzt können Sie „Nachrichtentext suchen“ öffnen: Öffnen Sie es im Menü „⋯“ in der oberen rechten Ecke der Seite oder klicken Sie direkt auf die Schaltfläche in der Eingabeaufforderung, wenn die Suche keine Ergebnisse liefert. Nach dem Öffnen werden in den Suchergebnissen die getroffenen Textfragmente und die Anzahl der getroffenen Nachrichten aufgelistet.

  • Standardmäßig deaktiviert. Nach dem Öffnen indiziert CC Switch den Nachrichtentext lokal und der Fortschritt wird während der Erstellung angezeigt. Zu diesem Zeitpunkt sind die Körperergebnisse möglicherweise noch nicht vollständig.
  • Der Index ist eine separate lokale Datei session-index.db, die nicht an der Cloud-Synchronisierung oder -Sicherung teilnimmt; Wenn Sie diesen Schalter ausschalten, wird er gelöscht.

Schnittstellendichte und Schnittstellenskalierung

Unter „Einstellungen → Allgemein → Erscheinungsbild“ (#9209) wurden zwei neue Elemente hinzugefügt:

  • Schnittstellendichte: „Kompakt“ ist die Originalgröße und der Standardwert; „Komfortabel“ bedeutet eine größere Schriftgröße und die Schaltflächen und Eingabefelder sind höher.
  • Interface-Zoom: 90 %, 100 %, 110 %, 125 % vier Stufen, Sie können zum Anpassen auch Strg (⌘ unter macOS) plus +, - drücken, zum Wiederherstellen Strg/⌘ plus 0 drücken. Beide Einstellungen werden, genau wie das Theme, nur lokal gespeichert. Die Fachzugangsklappe bleibt in ihrer Größe kompakt.

Modellpreistabelle kann durchsucht werden

Über der Modellpreistabelle wurde ein Suchfeld hinzugefügt, um nach Modell-ID oder -Namen zu filtern (#9205). Durch Drücken der Eingabetaste wird das erste Ergebnis bearbeitet. Wenn kein passendes Modell vorhanden ist, wird durch Drücken der Eingabetaste ein neuer Preis für das eingegebene Modell hinzugefügt.

Grok Build Öffnen Sie das Terminal

Die Lieferantenkarte von Grok Build verfügt außerdem über eine Schaltfläche „Terminal öffnen“ (#9234). Grok CLI kann nicht zulassen, dass nur ein Terminal den Lieferanten wechselt, daher erscheint diese Schaltfläche nur bei dem verwendeten Lieferanten. Das geöffnete Terminal verwendet direkt die von CC Switch verwaltete Grok-Konfiguration. --always-approve wird hinzugefügt, wenn die Berechtigungsbestätigung übersprungen wird.

Ändern

  • Skills haben die Neuformatierung der Seite installiert (#9210):
    • Die Namensspalte ist links fixiert und die Spalten jeder Anwendung scrollen horizontal darunter, wenn das Fenster schmal ist.
    • Status- und Quellenfilterung werden in die gleiche Symbolleiste wie die Seite „Entdecken“ verschoben und Fertigkeiten werden nach der Auswahl nicht blockiert; Batch-Vorgänge behalten Aktualisierung, Deinstallation und „Aktivieren“/„Deaktivieren“ für die Anwendung bei.
    • Der Link „N aktualisierbar“ in der Kopfzeile wurde entfernt und der Link „Alle aktualisieren“ in der Symbolleiste hat die Nummer bereits geschrieben; Klicken Sie in jeder Zeile auf die Markierung „Aktualisierbar“, um diese Fähigkeit zu aktualisieren.
    • Das Menü „…“ jeder Zeile enthält „Dokument öffnen“, „Verzeichnis öffnen“ und „Deinstallieren“. Wenn das Schreiben fehlschlägt, wird die Fehlermeldung an der beschriebenen Stelle angezeigt.
  • Lieferantensymbol folgt Thema (#8438): Der feste weiße Hintergrund hinter dem Kartensymbol wurde entfernt. Einfarbige dunkle Symbole ändern sich mit der Textfarbe und sind im dunklen Modus deutlich zu erkennen; Mehrfarbige Symbole mit dunklen Strichen, Bildsymbole und von Ihnen hochgeladene Symbole haben im dunklen Modus weiterhin einen hellen Hintergrund.
  • Rechtsklick öffnet nicht mehr das Browsermenü (#8919, #8921): In der Vergangenheit öffnete ein Rechtsklick im Hauptfenster und in der Taskleiste das eigene Menü des Browsers (unter Windows war es „Zurück“, „Neu laden“, „Speichern unter“, „Drucken“ usw.). Nicht mehr; Eingabefelder, Code-Editoren und ausgewählter Text können weiterhin mit der rechten Maustaste angeklickt und kopiert und eingefügt werden.
  • Das Leistungsschalterprotokoll gibt an, um welchen Lieferanten es sich handelt (#9292): Die Protokolle des Leistungsschalters (CB-001 bis CB-006) tragen alle „Anwendung: Lieferanten-ID“; Wenn der Leistungsschalter einen Lieferanten ablehnt, zeichnet er auch eine Zeile FWD-004 mit dem Namen des Lieferanten auf und überspringt diese nicht mehr stillschweigend. Lediglich die Protokolle wurden geändert, aber das Routing- und Schutzschalterverhalten bleibt unverändert.
  • Voreinstellungen: Das Standardmodell der Mistral-KI-Voreinstellungen wurde in mistral-large-4 geändert (Mistral Medium 3.5 wurde von Mistral als veraltet angekündigt), und Mistral-KI-Voreinstellungen für Claude Code, Codex und Claude Desktop werden nicht mehr ausgeblendet. Das Mistral Vibe-Paket und API teilen sich das gleiche Kontingent. „Get API Key“ wird geändert, um die Schlüsselseite von Vibe CLI zu öffnen, die kostenlos, im Abonnement und mit nutzungsbasierter Bezahlung verfügbar ist; Sie können es auch finden, indem Sie beim Hinzufügen eines Lieferanten nach „Vibe“ suchen. Genesis (#9269) und TokenPlus (#9296) hinzugefügt. Bereits hinzugefügte Lieferanten sind nicht betroffen.

Fix

  • Wenn es sich bei der Konfigurationsdatei um einen Softlink handelt, wird sie beim Wechsel des Anbieters durch eine normale Datei ersetzt und ein Fehler wird direkt unter Windows gemeldet (#6764, #9283). Wenn Sie das Dotfiles-Tool oder den Synchronisierungsordner zum Verwalten von ~/.claude/settings.json-, ~/.codex/config.toml-, opencode.json- usw. Dateien verwenden, handelt es sich normalerweise um Softlinks. Früher wurde der Link selbst beim Schreiben ersetzt. Unter macOS und Linux wurde der Link in eine normale Datei umgewandelt und von der Originaldatei entkoppelt. Unter Windows wurde der Fehler „Atomic Replacement failed“ (OS-Fehler 1464) gemeldet. Jetzt wird die eigentliche Datei geschrieben, auf die der Link verweist, und der Link bleibt unverändert.
  • Nachdem die Anforderung auf halbem Weg abgebrochen wurde, befindet sich der Anbieter möglicherweise bis zum Neustart in der Wiederherstellung des Leistungsschalters (#7206, #9292). Während der Erholungsphase des Leistungsschalters übersteht der Leistungsschalter nur eine Erkennungsanforderung; Wenn die Verbindung des Kunden vor Abschluss der Anfrage getrennt wird, wird das Kontingent nicht zurückgegeben und alle nachfolgenden Anfragen an diesen Lieferanten werden abgelehnt. Unabhängig davon, wie die Anfrage endet, wird der Platz zurückgegeben. – Nachdem Sie benutzerdefinierte Berechtigungen für Codex festgelegt haben, verwenden Sie den Planmodus, um Fehler zu melden (#7349, #7294). Der neuere Codex erfordert, dass model_catalog_json beim Lesen benutzerdefinierter Berechtigungen ein absoluter Pfad ist. In der Vergangenheit schrieb CC Switch den Dateinamen und der Codex meldete AbsolutePathBuf deserialized without a base path. Schreiben Sie nun den absoluten Pfad; Schreiben Sie weiterhin den Dateinamen, wenn sich das Konfigurationsverzeichnis in WSL befindet.
  • Skills, die einmal ausgeführt wurden, werden als „aktualisierbar“ angezeigt und durch Klicken auf „Aktualisieren“ wird das gesamte Verzeichnis abgedeckt (#7780, #7772). Die beim Ausführen von Python generierten Dateien __pycache__ und .pyc sind im Skill-Inhalt enthalten. Diese Dateien werden jetzt bei der Suche nach Updates ignoriert; Alte Datensätze aus früheren Versionen werden automatisch konvertiert und führen nicht zu Fehlalarmen.
  • Skills Warehouse zeigt „0 erkannte Skills“ an (#9273). Die beim Import hinzugefügte Lagerfiliale wird als HEAD erfasst. Wenn die Standardfiliale des Lagers Master ist, aber der Hauptfiliale zugewiesen ist, ist die Menge immer 0. Jetzt basiert die Zählung auf den tatsächlich gelesenen Filialen. Das Warehouse, das nicht lesen kann, zeigt „Lesefehler“ und den Grund an. Nach dem Importieren von Skill und dem Hinzufügen eines neuen Lagers wird es beim nächsten Öffnen erneut gelesen.
  • Windows behandelt pi.exe im Python-Paket als Pi (#9267). Es gibt ein nicht verwandtes pi-Paket auf PyPI, das Scripts\pi.exe installiert, und auf der Anwendungsseite wird es als „Ausführung nicht möglich“ angezeigt. Pi wird nur über npm freigegeben und jetzt wird pi.exe im Verzeichnis Python Scripts nicht mehr als Pi erkannt. – Die Modellpreissynchronisierung ist fehlgeschlagen, es wird nur error decoding response body angezeigt (#9262). Beim Herunterladen der Preisliste von models.dev kommt es auf halbem Weg zu einem langsamen Netzwerk oder Proxy. Das Timeout wurde jetzt von 15 Sekunden auf 60 Sekunden gelockert und der wahre Grund wird im Synchronisierungsstatus geschrieben, wenn die Synchronisierung fehlschlägt.
  • Beim Hinzufügen des DeepSeek Harness-Lieferanten wird nur Invalid DeepSeek Harness profile YAML angezeigt. Ich weiß nicht, um welche Datei es sich handelt (#9297). Jetzt schreibt der Fehlerbericht den Pfad der Fehlerkonfigurationsdatei und den spezifischen Fehler von YAML aus, wodurch es einfacher wird, die zu reparierende Datei zu finden. – Der Konnektivitätstest stellt fest, dass die Umleitungsstation nicht erreichbar ist (#9253, #5747). Einige Gateways leiten sich gegenseitig zwischen /v1 und /v1/ um. Jetzt testen wir, ob sie eine Verbindung herstellen können, auch wenn sie die Weiterleitung erhalten.
  • Das Fenster kann beim Öffnen eines Dialogfelds nicht gezogen werden (#9140). Fenster können jetzt gezogen werden, während ein Dialogfeld geöffnet ist; Die Schaltflächen zum Minimieren, Maximieren und Schließen sind weiterhin verfügbar, wenn Sie In-App-Fensterschaltflächen unter Windows und Linux verwenden.
  • Linux-Verknüpfungspanel-Anzeigeausnahme: Das im Lightweight-Modus erneut geöffnete Panel und Fenster werden falsch gerendert (#9233, #9216) und ein Teil des Panels wird abgeschnitten, wenn der Anzeigezoom eingestellt ist (#9287, #8556). Panels unter Linux wurden auf einen undurchsichtigen Hintergrund geändert.
  • Wenn der Name des Lieferanten mit Zeichen wie Emojis beginnt oder ihm ein Leerzeichen vorangestellt ist, ist das erste Zeichen, das auf einer Karte ohne Symbol angezeigt wird, verstümmelt oder leer (#8139). – In der Risikowarnung des One-Click-Import-Links fehlt die IPv6-Adresse mit eingebetteter IPv4-Adresse (#8127). Diese Art von Adresse wird nun anhand der IPv4-Adresse beurteilt, auf die sie tatsächlich verweist, ob es sich um den lokalen Computer oder das Intranet handelt.

cc-switch v4.0.27

Highlights

  • Full-text session search is opt-in — Search can now match message bodies, not just titles, directories, and IDs (#7896). CC Switch builds a separate local session-index.db; it is excluded from cloud sync and backups, deleted when the feature is disabled, and results may be incomplete during initial indexing—important if you rely on cross-device session history.
  • Configuration writes preserve symlinks — Provider switches now write through to the target of linked files such as ~/.claude/settings.json, ~/.codex/config.toml, and opencode.json instead of replacing the link (#9283). This keeps dotfiles and synced configurations connected and fixes Windows atomic-replacement error 1464; existing links need no migration.
  • Two reliability blockers are fixed — Codex custom-permission configurations now use an absolute model_catalog_json path, resolving plan-mode deserialization failures (#7349); WSL configuration directories intentionally still use a filename. Canceled requests now return circuit-breaker probe slots, preventing providers from remaining stuck in recovery until restart (#9292).
  • Skill updates no longer chase runtime artifacts — Update checks ignore __pycache__ and .pyc, preventing used Python Skills from being falsely marked stale and then overwritten during updates (#7780); old records are converted automatically. Repository discovery now counts the branch actually read and reports failures with reasons instead of showing “0 skills” (#9273).
  • Provider setup gains safer defaults and Grok terminal access — New Mistral AI presets default to mistral-large-4 because Medium 3.5 is deprecated; existing providers are unchanged. Grok Build’s terminal action appears only on the active provider because Grok CLI cannot switch providers per terminal; it uses CC Switch’s managed configuration and adds --always-approve when permission confirmation is skipped (#9234).
  • Breaking changes — None.

CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 pi.exe 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（#7896、#7420）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

  • 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
  • 索引是单独的本地文件 session-index.db，不参与云同步，也不进备份；关闭这个开关会删除它。

界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（#9209）：

  • 界面密度：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
  • 界面缩放：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 +、- 调整，按 Ctrl/⌘ 加 0 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（#9205）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（#9234）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 --always-approve。

变更

  • Skills 已安装页重新排版（#9210）：
    • 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
    • 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
    • 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
    • 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
  • 供应商图标跟随主题（#8438）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
  • 右键不再弹出浏览器菜单（#8919、#8921）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
  • 熔断日志写明是哪家供应商（#9292）：熔断器的日志（CB-001 到 CB-006）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 FWD-004，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
  • 预设： Mistral AI 预设的默认模型改为 mistral-large-4（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（#9269）、TokenPlus（#9296）。已添加的供应商不受影响。

修复

  • 配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错（#6764、#9283）。用 dotfiles 工具或同步文件夹管理 ~/.claude/settings.json、~/.codex/config.toml、opencode.json 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
  • 请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启（#7206、#9292）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
  • Codex 设置了自定义权限后，用 plan 模式报错（#7349、#7294）。较新的 Codex 读取自定义权限时要求 model_catalog_json 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 AbsolutePathBuf deserialized without a base path。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
  • 运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录（#7780、#7772）。Python 运行时生成的 __pycache__ 和 .pyc 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
  • Skills 仓库显示「识别到 0 个技能」（#9273）。导入时添加的仓库分支记为 HEAD，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
  • Windows 上把 Python 包里的 pi.exe 当成 Pi（#9267）。PyPI 上有一个无关的 pi 包会装出 Scripts\pi.exe，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python Scripts 目录里的 pi.exe 不再被识别为 Pi。
  • 模型价格同步失败，只提示 error decoding response body（#9262）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
  • 添加 DeepSeek Harness 供应商时只提示 Invalid DeepSeek Harness profile YAML，不知道是哪个文件（#9297）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
  • 连通性测试把会重定向的中转站判为不通（#9253、#5747）。有的网关在 /v1 和 /v1/ 之间互相重定向，现在测试收到重定向就算连得上。
  • 打开对话框时窗口拖不动（#9140）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
  • Linux 快捷面板显示异常：轻量模式下重新打开的面板和窗口渲染出错（#9233、#9216），设置了显示缩放时面板被裁掉一部分（#9287、#8556）。Linux 上的面板改为不透明背景。
  • 供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白（#8139）。
  • 一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址（#8127）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
