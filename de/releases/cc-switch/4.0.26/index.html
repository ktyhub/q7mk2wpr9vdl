CC-Schalter v4.0.26

CC-Schalter v4.0.26

Mit dieser Version können das Autorisierungszentrum und die offiziellen Lieferantenkarten den Abonnementplan jedes Kontos anzeigen. Das GitHub Copilot-Konto listet alle begrenzten Kontingente auf; Über den Ein-Klick-Importlink können jetzt auch Anbieter von Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness und Oh My Pi importiert werden. Die Codex-Karte kann die offizielle Fast-Datei des GPT-Modells beibehalten. CC Switch erinnert Sie daran, wenn der Systemagent die Anfragen von Codex und Grok Build an das lokale Routing übernimmt. DeepSeek Harness kann ein Konfigurationsverzeichnis einrichten und dieses auch verwalten, wenn es in WSL installiert ist. Diese Version hat auch eine Runde der Leistungsoptimierung durchgeführt: Lieferantenliste, Laden des Hauptfensters, Start, Sitzungslesen und Routenweiterleitung sind alle schneller, und die Schnittstelle bleibt nicht mehr hängen, wenn die Sitzungssynchronisierung die Datenbank beansprucht. Darüber hinaus bleibt die Routing-Anfrage länger als zwei Minuten hängen, wenn IPv6 nicht verfügbar ist, der MCP-Server, der angemeldet werden muss, zeigt an, dass die Verbindung fehlschlägt, die Claude Desktop-Routing-Karte ändert das Modell und wird nicht wirksam, die Cache-Trefferrate sinkt, wenn der Codex per Routing in den Chat übertragen wird, die Grok-Anfrage von GitHub Copilot meldet 422 und die Antwort wird wiederholt angezeigt und das Popup-Fenster ist auf Nicht-Retina-Displays unscharf. Den vollständigen Update-Inhalt von 4.0 finden Sie in den [v4.0-Versionshinweisen] (https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md). Hinzufügen

Konto-Abonnementplan

In der Vergangenheit schrieb nur das Claude-Konto im Autorisierungscenter den Abonnementplan und andere Konten zeigten nur das Anmeldedatum an. Das Max-Konto und das Free-Konto desselben Dienstes würden genau gleich aussehen. Jetzt werden für die Konten GitHub Copilot, ChatGPT, Kimi, Antigravity und xAI auch Abonnementpläne am Anfang der zweiten Zeile angegeben. Den offiziellen Karten von Codex, Kimi, Antigravity und Gemini CLI sowie den Copilot- und xAI-Kontokarten wird nach dem Untertitel auch „· Projektname“ hinzugefügt.

  • Der Planname auf der Karte basiert direkt auf dem Ergebnis der Quotenabfrage und es werden keine Mehrfachanfragen gesendet (Kimi, Antigravity und xAI erhalten bei der Prüfung der Quote eine weitere parallele Anfrage zum Abrufen des Plannamens). Der Planname wird erst angezeigt, nachdem das Kontingent geladen wurde, und Karten, die das Kontingent nicht überprüfen, werden nicht angezeigt.
  • Wenn der Planname nicht gefunden werden kann, wird er einfach nicht angezeigt und der Betrag wird wie gewohnt angezeigt; Wenn die Aktualisierung fehlschlägt, wird der zuletzt gefundene Plan beibehalten.
  • Die mit Grok CLI angemeldete Grok Build-Karte und die Antigravity-Karte ohne Konto haben noch keinen Plannamen und diese Informationen können nicht über ihre Methode zur Überprüfung des Kontostands abgerufen werden.

GitHub Copilot Alle Salden anzeigen

Copilot-Konten zeigten bisher nur den Prozentsatz der erweiterten Anfragen an. Jetzt hat jedes Element mit einer Obergrenze eine eigene Zeile. Sie können den Mauszeiger bewegen, um „Verbleibend/Gesamt“ anzuzeigen. Außerdem können Sie die Code-Vervollständigung und die Anzahl der Chats für das kostenlose Konto sehen.

  • Die erweiterte Anfrage wird in „Credits“ umbenannt, was mit dem Namen im Codex übereinstimmt und in der Taskleiste derselbe ist.
  • Das kostenlose Konto hat kein Guthaben. Früher wurde dort „100 % verbleibend“ angezeigt, jetzt steht dort „Der aktuelle Plan beinhaltet nicht“ und dieser Artikel wird nicht mehr auf der Lieferantenkarte angezeigt.

Ein-Klick-Import unterstützt mehr Anwendungen

Bisher wurden Anbieterlinks für Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness und Oh My Pi direkt abgelehnt. Nun können auch Links zu diesen Apps importiert werden.

  • Claude Desktop: Wenn der Link im Anthropic-Format vorliegt und der Modellname mit claude- beginnt (oder kein Modell geschrieben ist), wird er in eine Direktverbindungskarte importiert; Andernfalls wird es in eine Modellzuordnungskarte importiert und die vier Slots werden entsprechend dem Modell im Link ausgefüllt.
  • MiniMax-Code, Kimi-Code, DeepSeek Harness, Oh My Pi: Als einzelnes Modell wie Pi importiert, muss das Modell im Link enthalten sein.
  • Oh My Pi liest den auf bestimmte Weise geschriebenen Schlüssel als Namen oder Befehl einer Umgebungsvariablen. Nach dem Import wird Ihr lokaler Schlüssel möglicherweise an die Adresse im Link gesendet. Daher wird der Import dieses Schlüsseltyps (beginnend mit !, keine Kleinbuchstaben usw.) verweigert.

Codex-Karten behalten die offizielle Fast-Datei

Bei den GPT-Modellen in der Codex-Drittanbieter-Kartenmodellliste wurde früher die offizielle Fast-Geschwindigkeitsdatei entfernt und Fast konnte nicht ausgewählt werden (#5234). Überweisungen, die offizielle ChatGPT-Konten (wie CPA) weiterleiten, unterstützen tatsächlich Fast. Jetzt gibt es in den „Erweiterten Optionen“ des Codex-Lieferantenformulars unter „Upstream-Format“ die Option „Keep Official Fast File“. Es ist standardmäßig deaktiviert und wird nur angezeigt, wenn das Upstream-Format „Antworten“ lautet. Nachdem Sie den Codex geöffnet und Schnell ausgewählt haben, enthält die Anfrage service_tier=priority.

  • Es werden nur Überweisungen erkannt, die offizielle ChatGPT-Konten weiterleiten, wodurch das Kontingent schneller verbraucht wird. Andere Upstreams melden möglicherweise einen Fehler oder müssen einen höheren Preis in Rechnung stellen.
  • Wenn Sie zuvor unter der offiziellen Karte Schnell ausgewählt haben, wird dies hier sofort nach dem Öffnen wirksam. Im Aggregationsmodus wird es nicht wirksam. Codex muss nach der Änderung neu gestartet werden.

Warnung, wenn der Systemagent die lokale Route übernimmt

Wenn Proxy-Tools wie Clash aktiviert sind, werden von Codex und Grok Build an die lokale Route (http://127.0.0.1:<port>) gesendete Anforderungen möglicherweise vom System-Proxy abgeholt und an den Remote-Knoten übertragen, bevor eine leere 502 zurückgegeben wird (#9221). Codex zeigt nur „502 Bad Gateway“ an und CC Switch kann keine Anfragen empfangen. Da keine Protokolle vorhanden sind, ist die Überprüfung schwierig. Nachdem Codex oder Grok Build nun in den Routing-Modus wechseln, sendet CC Switch im Hintergrund eine Anfrage an die lokale Route gemäß denselben Proxy-Regeln wie der Client. Wenn die Anfrage nicht zurückgegeben werden kann, wird eine Warnung im Protokoll aufgezeichnet. Wenn Sie den Routing-Modus manuell aufrufen, wird auf der Benutzeroberfläche eine Eingabeaufforderung angezeigt, in der erläutert wird, wie die lokale Adresse im Proxy-Tool direkt verbunden wird (fügen Sie beispielsweise IP-CIDR,127.0.0.0/8,DIRECT,no-resolve am Anfang der Clash-Regel hinzu).

DeepSeek Harness-Konfigurationsverzeichnis

In der Vergangenheit erkannte DeepSeek Harness nur DSH_HOME oder ~/.dsh und der in WSL installierte DSH konnte in der Windows-Version von CC Switch nicht verwaltet werden (#9239). Nun gibt es unter „Einstellungen → Anwendungskonfiguration“ eine DeepSeek Harness-Spalte, in der Sie das Konfigurationsverzeichnis festlegen können. Lieferanten, Fertigkeiten, Richtliniendateien, Sitzungen und Nutzungsimporte folgen alle diesem Verzeichnis. Wenn Sie den Pfad in WSL eingeben, werden Versionserkennung, Installation und Upgrade auch in dieser WSL-Distribution durchgeführt.

Ändern

  • Leistungsoptimierung:
    • Die Lieferantenliste wird schneller gelesen und je mehr Lieferanten vorhanden sind, desto offensichtlicher ist sie. Unveränderte Lieferanten werden nicht mehr wiederholt in die Datenbank geschrieben und die Cloud-Synchronisierung wird nicht ausgelöst (#9180).
    • Die Sekundärseite und der Lieferanteneditor werden so geändert, dass sie bei ihrer Verwendung geladen werden, und die beim Start des Hauptfensters zu ladenden Skripte werden um die Hälfte reduziert (#9181).
    • Die Protokollbereinigung beim Start wird in den Hintergrund verschoben. Die geplante Aktualisierung wird angehalten, wenn das Fenster ausgeblendet oder minimiert ist, und wie gewohnt aktualisiert, wenn das Fenster sichtbar, aber nicht im Vordergrund ist (#9182). – Kopieren Sie beim Lesen von Sitzungsdatensätzen die Daten einmal weniger, und der Sitzungscache wird nach dem Wechsel in den Lightweight-Modus freigegeben (#9183). – Das Routing leitet Streaming-Antworten weiter, ohne dass viel Speicher kopiert werden muss, insbesondere wenn die Antwort lang ist. Failover liest die Datenbank seltener (#9161).
  • Die Schnittstelle bleibt während der Sitzungssynchronisierung nicht mehr hängen (#9178): Große Sitzungsdateien belegen während der Synchronisierung mehrere zehn Sekunden lang die Datenbank. Während dieser Zeit führen das Öffnen der Skills-Seite, der Wechsel zu Pi oder Oh My Pi, das Öffnen von Netzwerk- oder Dateneinstellungen, die Symbolauswahl, das einheitliche Lieferantenpanel, der Geschwindigkeitstest und andere Vorgänge dazu, dass das gesamte Fenster und die Taskleiste hängen bleiben, bis die Synchronisierung abgeschlossen ist. Jetzt warten diese Vorgänge im Hintergrund und die Schnittstelle reagiert wie gewohnt.
  • Neugestaltung der Symbolleiste auf der Sitzungsleseseite (#9109): Die erste Zeile enthält den Pfad und die Lesewerkzeuge, und die zweite Zeile enthält Zeit, Sitzungsstatistiken, Modelle und Nutzung; Die leicht fallende Trennstelle am Anfang und Ende der Linie wird entfernt. Ist der Modellname zu lang, wird er in einer neuen Zeile angezeigt. Sie können den Mauszeiger bewegen, um den vollständigen Namen anzuzeigen.
  • Standard: Das Standardmodell von Grok Build wird in grok-4.7 geändert, das Standardmodell der Kimi-Voreinstellung (außer Codex) wird in kimi-k3.1-pro geändert, das Standardmodell von Hermes' Qianwen Coding Plan wird in qwen3.7-plus geändert (#9193); TeamoRouter ändert sich zum Domänennamen teamorouter.com; Der Download-Link der offiziellen Claude Desktop-Karte wird in claude.com/download geändert. Bereits hinzugefügte Lieferanten sind nicht betroffen.

Fix

– Wenn IPv6 nicht verfügbar ist, werden Routing-Anfragen mehr als zwei Minuten verzögert, bevor sie gesendet werden (#9212). Die Domänennamen von Diensten wie Zhipu GLM und Alibaba Cloud Bailian lösen zunächst IPv6-Adressen auf. In einem Netzwerk, in dem IPv6 blockiert ist, muss das lokale Routing warten, bis das System jede IPv6-Adresse abgelaufen ist, bevor es zu IPv4 wechselt. Dies dauert unter macOS etwa 150 Sekunden und unter Windows etwa 43 Sekunden. Wenn nun die IPv6-Adresse nicht innerhalb von 300 Millisekunden verbunden werden kann, wird gleichzeitig IPv4 versucht und der Inhalt der Anfrage bleibt unverändert. – Der MCP-Server, der eine Anmeldung erfordert, die Konnektivitätsprüfung zeigt „Verbindung fehlgeschlagen“ (#9190). Server wie Notion und Sentry erfordern eine OAuth-Anmeldung. Nach der Anmeldung am Client können diese normal genutzt werden. Wenn CC Switch jedoch ohne die Anmeldeinformationen des Clients eine Prüfung durchführt, wird dies als fehlgeschlagen gewertet. In dieser Situation wird nun ein gelber Punkt angezeigt, und wenn Sie den Mauszeiger darüber bewegen, wird angezeigt, dass eine Verbindung zum Server hergestellt werden kann, aber nur eine Anmeldung erforderlich ist. CC Switch liest die gespeicherten Anmeldeinformationen des Clients immer noch nicht.

  • Nachdem das Modell der Claude Desktop-Routing-Karte geändert wurde, befindet sich das alte Modell immer noch in Claude Desktop, also löschen Sie es und erstellen Sie es neu (#9203). Wenn beim Speichern das Feld „Menü-Anzeigename“ leer bleibt, wird der Modellname automatisch ausgefüllt. Wenn Sie das Modell erst später ändern, ist der Anzeigename weiterhin der alte. Wenn nun der Anzeigename mit dem alten Modellnamen übereinstimmt, wird er zusammen mit dem neuen Modell geändert und der von Ihnen selbst vergebene Name bleibt unverändert.
  • Wenn Codex per Routing an den Chat übertragen wird, sinkt die Cache-Trefferquote, nachdem die Einstellungen während der Konversation geändert werden. Nach dem Wechsel zu sandbox_mode in der Mitte fügt Codex beispielsweise zu Beginn dieser Runde eine Beschreibung ein. Zuvor wurde es am Anfang der Konversation eingefügt, wodurch der gesamte Verlauf neu geschrieben wurde und alle Upstream-Caches ungültig wurden. Dieser Hinweis bleibt bestehen und die bisherige Historie bleibt unverändert.
  • Wenn Codex über den Chat weitergeleitet wird, können die Denkinhalte einer anderen Sitzung in die aktuelle Sitzung eingemischt werden. Die vom Upstream bereitgestellte Tool-Aufruf-ID kann leicht wiederholt werden (z. B. exec_command:0). Nachdem die lokale Route neu gestartet oder der Cache entleert wurde, werden möglicherweise Anrufe mit demselben Namen in anderen Sitzungen gefunden. Jetzt nach Codex-Sitzung unterschieden, nur innerhalb derselben Sitzung suchen.
  • Wenn die Routing-Anfrage fehlschlägt, wird der Modellname des Clients im Anfrageprotokoll aufgezeichnet. Beispielsweise verwendet die Hintergrundaufgabe von Claude Desktop claude-haiku-4-5-20251001. Nach der Zuordnung zum Modell dieser Karte meldet der Upstream 429, aber das Protokoll zeigt Haiku. Es sieht so aus, als würde ein Modell aufgerufen, das Sie nicht konfiguriert haben. Jetzt werden fehlgeschlagene Anfragen genau wie erfolgreiche als „claude-haiku-4-5-20251001 → tatsächliches Modell“ geschrieben.
  • Auf der offiziellen Karte von Claude, die auf die lokale Anmeldung folgt, wird nach Ablauf der Anmeldung immer „Zu aktualisierendes Token“ angezeigt, und Sie müssen Claude Code zur Wiederherstellung erneut ausführen. Wenn nun die Anmeldung abläuft, fordert CC Switch Claude Code auf, die Anmeldung selbst zu aktualisieren und das Kontingent erneut zu lesen. Überspringen, wenn das Claude-Konfigurationsverzeichnis festgelegt ist.
  • Wenn der Sicherheitsklassifikator des automatischen Modus von Claude Code und Claude Desktop nicht verfügbar ist, versucht der Client es erneut und verbraucht weiterhin das Kontingent (#9201, #9199). Wenn nun drei aufeinanderfolgende Runden von Tool-Ergebnissen melden, dass der Klassifikator nicht verfügbar ist, gibt die lokale Route direkt einen Fehler zurück und sendet ihn nicht mehr an den Upstream; Senden Sie eine neue Nachricht, um fortzufahren.
  • Codex über GitHub Copilot mit Grok-Modell mal 422 (#7989, #7988). Jetzt werden die Grok-Anfragen von Copilot genauso behandelt wie direkte xAI.
  • Wenn der Codex GitHub Copilot besteht, wird dieselbe Antwort zweimal angezeigt (#8025, #7977).
  • Beim Installieren oder Aktualisieren einer Anwendung wird eine vorhandene Datei mit demselben Namen gefunden und die Eingabeaufforderung enthält nur --force (#9196, #9173), empfohlen von npm. Diese Datei stammt wahrscheinlich von einer anderen Installationsmethode und wird von --force direkt überschrieben. Jetzt gibt die Eingabeaufforderung den in Konflikt stehenden Dateipfad aus. Es wird empfohlen, das Backup umzubenennen und es erneut zu versuchen. – Die automatische WebDAV-Synchronisierung schlägt fehl, wenn in Skills Datei-Softlinks vorhanden sind (#9197). Wenn beispielsweise CLAUDE.md und GEMINI.md beide mit AGENTS.md verknüpft sind, werden Dateien mit demselben Namen im Paket angezeigt. Jede Datei behält jetzt ihren eigenen Namen.
  • Zwei Probleme mit der gleichzeitigen Obergrenze des Codex-Subagenten (#9148): Wenn config.toml Kommentare hinter dem Tabellenkopf hat, kann eine Änderung der Obergrenze [features.multi_agent_v2] überschreiben; Wenn [agents] als Schlüsselname mit Anführungszeichen geschrieben wird, wird ein zusätzliches Duplikatfeld geschrieben, das von Codex nicht erkannt wird. In der Beschreibung wird außerdem hinzugefügt, dass die Änderungen nur für neue Sitzungen wirksam werden.
  • DeepSeek Harness kann den von CC Switch gespeicherten Schlüssel bei Verwendung des Headless-Profils nicht finden und meldet MISSING_CREDENTIAL. Das Lesen von Anmeldeinformationen wird jetzt gemäß dem DSH-Dokument beim Schreiben in ein Headless-Profil aktiviert. Profile, die Sie in diesem Element geändert haben, bleiben unverändert.
  • Auf 1x-Monitoren erscheinen Popups wie „Modell auswählen“ verschwommen (#9238). Wenn das Popup-Fenster zentriert ist, kann es auf ein halbes Pixel herunterfallen und der Text und die Ränder werden auf Nicht-Retina-Displays unscharf angezeigt.
  • Unter macOS wird beim Eingeben von Eingabefeldern wie MCP-Formularen, Eingabeaufforderungsworteditoren, Skills Warehouse, Sitzungssuche usw. der erste Buchstabe automatisch in Großbuchstaben geändert und Umgebungsvariablennamen, Anforderungsheader, Befehle und Adressen werden dadurch möglicherweise falsch gespeichert.
  • Linux AppImage verpackt die alte Version von libwayland-client (#9229, #8723), die möglicherweise nicht in einer Umgebung mit Intel Core Graphics und Wayland geöffnet wird.

cc-switch v4.0.26

Highlights

  • Subscription visibility — Authorization and official-provider cards now show plan names and every metered GitHub Copilot quota, including Free-tier chat and completions. Free accounts report “not included” instead of a misleading 100% for Credits; plan names appear only after quota loading and silently disappear on lookup failure.

  • Broader one-click imports — Links now work for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness, and Oh My Pi. Claude Desktop links become direct connections only when using Anthropic-format claude-* models or no model; otherwise they become model-mapping cards. The other four require an explicit model, and dangerous Oh My Pi key syntax—such as !-prefixed values—is rejected to prevent accidental credential exposure.

  • Codex Fast tier and new behavior — Responses-format Codex providers can opt into Preserve official Fast tier, adding service_tier=priority when Fast is selected. This works only with gateways that forward official ChatGPT accounts, may consume quotas faster or fail elsewhere, does not apply in aggregate mode, and requires restarting Codex. Prior Fast selections activate once enabled.

  • Proxy and WSL diagnostics — Codex and Grok Build now probe local routes under the client’s proxy rules, warning when requests may escape to a proxy node and return an empty 502; add 127.0.0.0/8 to your proxy’s direct rules. DeepSeek Harness gains a configurable directory covering providers, Skills, instructions, sessions, and usage, with WSL paths also used for detection, installation, and upgrades.

  • Faster, more responsive routing — Lazy loading, reduced database writes and copies, background startup maintenance, and streamlined streaming reduce startup, session, and forwarding overhead (#9180, #9181, #9183, #9161). Session synchronization now queues UI actions instead of freezing the window and tray (#9178), while IPv6 connection failures fall back to IPv4 after 300 ms rather than waiting roughly 150 seconds on macOS (#9212).

  • Routing correctness fixes — Failed requests now log both the client-requested and actual upstream models, making mapping-related 429s diagnosable. Codex-to-Chat preserves history when settings change, preventing cache invalidation, and isolates tool-call lookup by session to stop cross-session reasoning leakage (#9203 covers a related Claude Desktop model-rename fix). Also notable: unavailable safety classifiers now stop after three rounds instead of retrying indefinitely (#9201); manually customized Claude configuration directories skip automatic login refresh.

CC Switch v4.0.26

本版本让授权中心和官方供应商卡片显示每个账号的订阅计划，GitHub Copilot 账号会列出所有有上限的额度；一键导入链接现在也能导入 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商。Codex 卡片可以选择保留 GPT 模型的官方 Fast 档；系统代理把 Codex、Grok Build 发往本地路由的请求接走时，CC Switch 会提醒你。DeepSeek Harness 可以设置配置目录，装在 WSL 里也能管理。这一版还做了一轮性能优化：供应商列表、主窗口加载、启动、会话读取和路由转发都更快，会话同步占着数据库时界面也不再卡住。另外修复了 IPv6 不通时经路由请求先卡两分多钟、需要登录的 MCP 服务器显示连接失败、Claude Desktop 路由卡片改了模型不生效、Codex 经路由转 Chat 时缓存命中率下降、GitHub Copilot 的 Grok 请求报 422 和回复重复显示、非 Retina 显示器上弹窗模糊等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

账号订阅计划

以前授权中心里只有 Claude 账号会写订阅计划，其他账号只显示登录日期，同一个服务的 Max 账号和 Free 账号看起来一模一样。

现在 GitHub Copilot、ChatGPT、Kimi、Antigravity、xAI 账号的第二行开头也会写订阅计划。Codex、Kimi、Antigravity、Gemini CLI 的官方卡片，以及 Copilot、xAI 账号卡片，副标题后面也会加上「· 计划名」。

  • 卡片上的计划名直接用额度查询的结果，不会多发请求（Kimi、Antigravity、xAI 查额度时会多一个并行请求取计划名）；额度加载出来后计划名才出现，不查额度的卡片不显示。
  • 计划名查不到时只是不显示，额度照常显示；刷新失败时保留上次查到的计划。
  • 跟随 Grok CLI 登录的 Grok Build 卡片、没绑账号的 Antigravity 卡片暂时还没有计划名，它们查额度的方式拿不到这项信息。

GitHub Copilot 显示全部额度

Copilot 账号以前只显示高级请求的百分比。现在每一项有上限的额度各占一行，悬停可以看到「剩余 / 共」，Free 账号的代码补全和聊天次数也能看到了。

  • 高级请求改叫 Credits，和 Codex 的叫法一致，托盘里也一样。
  • Free 账号没有 Credits，以前会显示成「还剩 100%」，现在写「当前计划不含」，供应商卡片上不再显示这一项。

一键导入支持更多应用

以前 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商链接会直接被拒绝。现在这些应用的链接也能导入了。

  • Claude Desktop：链接是 Anthropic 格式、模型名都以 claude- 开头（或没写模型）时，导入成直连卡片；其他情况导入成模型映射卡片，四个档位按链接里的模型填好。
  • MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi：和 Pi 一样导入成单个模型，链接里必须带模型。
  • Oh My Pi 会把某些写法的 Key 当成环境变量名或命令来读，导入后可能把你本机的密钥发到链接里的地址。所以这类 Key（以 ! 开头、没有小写字母等）会被拒绝导入。

Codex 卡片保留官方 Fast 档

Codex 第三方卡片模型列表里的 GPT 模型以前一律去掉了官方的 Fast 速度档，选不了 Fast（#5234）。转发官方 ChatGPT 账号的中转（如 CPA）其实支持 Fast。

现在 Codex 供应商表单「高级选项」里，「上游格式」下面多了「保留官方 Fast 档」，默认关闭，只在上游格式为 Responses 时显示。打开后 Codex 选了 Fast 时请求会带 service_tier=priority。

  • 只有转发官方 ChatGPT 账号的中转才认，会更快消耗额度；其他上游可能报错或按更高价格计费。
  • 以前在官方卡片下选过 Fast 的，打开后会马上在这家生效。聚合模式下不生效，改完需要重启 Codex。

系统代理接走本地路由时提醒

开着 Clash 这类代理工具时，Codex 和 Grok Build 发往本地路由（http://127.0.0.1:<port>）的请求可能被系统代理接走，转到远程节点后返回一个空的 502（#9221）。Codex 只显示「502 Bad Gateway」，CC Switch 这边也收不到请求，没有任何日志，很难查。

现在 Codex 或 Grok Build 进入路由模式后，CC Switch 会在后台按客户端同样的代理规则给本地路由发一次请求。请求回不来时，日志里会记一条警告；如果是你手动进入路由模式，界面上也会弹出提示，说明怎么在代理工具里让本机地址直连（例如在 Clash 规则最前面加 IP-CIDR,127.0.0.0/8,DIRECT,no-resolve）。

DeepSeek Harness 配置目录

以前 DeepSeek Harness 只认 DSH_HOME 或 ~/.dsh，装在 WSL 里的 DSH 在 Windows 版 CC Switch 里管不了（#9239）。

现在「设置 → 应用配置」里多了 DeepSeek Harness 一栏，可以设置配置目录。供应商、Skills、指令文件、会话和用量导入都会跟着这个目录走。填 WSL 里的路径时，版本检测、安装和升级也会在那个 WSL 发行版里进行。

变更

  • 性能优化：
    • 供应商列表读取更快，供应商越多越明显；没改动的供应商不再重复写入数据库，也就不会因此触发云同步（#9180）。
    • 次要页面和供应商编辑器改为用到时才加载，主窗口启动要加载的脚本少了一半（#9181）。
    • 启动时的日志清理挪到后台进行；窗口隐藏或最小化时暂停定时刷新，窗口可见但不在前台时照常刷新（#9182）。
    • 读取会话记录时少复制一遍数据，进入轻量模式后会释放会话缓存（#9183）。
    • 路由转发流式响应时少了大量内存复制，响应很长时尤其明显；故障转移读数据库的次数也更少（#9161）。
  • 会话同步时界面不再卡住（#9178）：大会话文件同步时会占着数据库几十秒，这期间打开 Skills 页、切到 Pi 或 Oh My Pi、打开网络或数据设置、图标选择、统一供应商面板、测速等操作会让整个窗口和托盘卡住，直到同步结束。现在这些操作都在后台等待，界面照常响应。
  • 会话阅读页的工具栏重新排版（#9109）：第一行放路径和阅读工具，第二行放时间、会话统计、模型和用量；去掉了容易落在行首行尾的分隔点，模型名太长时换行显示，悬停可看完整名称。
  • 预设： Grok Build 默认模型改为 grok-4.7，Kimi 预设（Codex 的除外）默认模型改为 kimi-k3.1-pro，Hermes 的千问 Coding Plan 默认模型改为 qwen3.7-plus（#9193）；TeamoRouter 改用 teamorouter.com 域名；Claude Desktop 官方卡片的下载链接改为 claude.com/download。已添加的供应商不受影响。

修复

  • IPv6 不通时，经路由的请求要先卡两分多钟才发出（#9212）。智谱 GLM、阿里云百炼等服务的域名会先解析出 IPv6 地址，在 IPv6 不通的网络里，本地路由要等系统把每个 IPv6 地址都超时一遍才改用 IPv4，macOS 上约 150 秒、Windows 上约 43 秒。现在 IPv6 地址 300 毫秒内连不上就同时尝试 IPv4，发出的请求内容不变。
  • 需要登录的 MCP 服务器，连通性检查显示「连接失败」（#9190）。Notion、Sentry 这类服务器需要 OAuth 登录，客户端里登录后能正常用，但 CC Switch 检查时不带客户端的登录凭据，就被判成了失败。现在这种情况显示黄色圆点，悬停会说明服务器能连上、只是要求登录。CC Switch 仍然不读取客户端保存的登录凭据。
  • Claude Desktop 路由卡片改了模型后，Claude Desktop 里还是旧模型，删掉重建才行（#9203）。保存时「菜单显示名」留空会自动填成模型名，之后只改模型时显示名还是旧的。现在显示名和旧模型名一样时会跟着新模型一起改，你自己起的名字保持不变。
  • Codex 经路由转 Chat 时，对话中途改了设置后缓存命中率下降。比如中途切换 sandbox_mode 后，Codex 会在这一轮开头插入一条说明，以前它被合并到对话最开头，改写了整段历史，上游缓存就全部失效了。现在这条说明留在原位，之前的历史保持不变。
  • Codex 经路由转 Chat 时，可能把另一个会话的思考内容混进当前会话。上游给的工具调用 ID 容易重复（如 exec_command:0），本地路由重启或缓存被挤掉后，可能找到别的会话里同名的调用。现在按 Codex 会话区分，只在同一个会话里找。
  • 路由请求失败时，请求日志里记的是客户端的模型名。比如 Claude Desktop 的后台任务用的是 claude-haiku-4-5-20251001，映射到这张卡片的模型后上游报 429，日志里却显示 Haiku，看起来像调用了一个你没配过的模型。现在失败的请求和成功的一样，会写成「claude-haiku-4-5-20251001 → 实际模型」。
  • 跟随本机登录的 Claude 官方卡片，登录过期后一直显示「令牌待刷新」，要再跑一次 Claude Code 才恢复。现在登录过期时 CC Switch 会让 Claude Code 自己刷新登录，再读取额度。设置了 Claude 配置目录时跳过。
  • Claude Code 和 Claude Desktop 自动模式的安全分类器不可用时，客户端会一直重试、持续消耗额度（#9201、#9199）。现在连续 3 轮工具结果都报告分类器不可用时，本地路由直接返回错误，不再发给上游；发一条新消息即可继续。
  • Codex 通过 GitHub Copilot 用 Grok 模型时报 422（#7989、#7988）。现在 Copilot 的 Grok 请求和直连 xAI 一样做兼容处理。
  • Codex 通过 GitHub Copilot 时，同一条回复显示两遍（#8025、#7977）。
  • 安装或升级应用时撞上已有的同名文件，提示里只有 npm 建议的 --force（#9196、#9173）。这个文件多半来自另一种安装方式，用 --force 会直接覆盖它。现在提示会写出冲突的文件路径，建议先改名备份再重试。
  • Skills 里有文件软链接时，WebDAV 自动同步失败（#9197）。比如 CLAUDE.md 和 GEMINI.md 都链接到 AGENTS.md 时，打包会出现重名文件。现在每个文件保留自己的名字。
  • Codex 子代理并发上限的两个问题（#9148）：config.toml 里表头后面带注释时，改上限可能覆盖掉 [features.multi_agent_v2]；[agents] 写成带引号的键名时，会多写一个 Codex 不认的重复字段。说明文字也补充了改动只对新会话生效。
  • DeepSeek Harness 用 headless profile 时找不到 CC Switch 保存的 Key，报 MISSING_CREDENTIAL。现在写入 headless profile 时会按 DSH 文档开启凭据读取；你自己改过这一项的 profile 保持不变。
  • 在 1x 显示器上，「选择模型」等弹窗显示模糊（#9238）。弹窗居中时可能落在半个像素上，非 Retina 显示器上文字和边框会发虚。
  • macOS 上，在 MCP 表单、提示词编辑、Skills 仓库、会话搜索等输入框里打字时首字母被自动改成大写，环境变量名、请求头、命令、地址可能因此被存错。
  • Linux AppImage 打包了旧版 libwayland-client（#9229、#8723），在 Intel 核显加 Wayland 的环境下可能打不开。
