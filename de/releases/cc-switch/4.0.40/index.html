CC-Schalter v4.0.40

CC-Schalter v4.0.40

Mit dieser Version kann die offizielle Karte von Grok Build an das xAI-Konto im Autorisierungscenter gebunden werden und zwischen mehreren Grok-Konten wie den offiziellen Karten von Claude und Codex gewechselt werden. Plug-in-Seite unterstützt Antigravity CLI; Nutzungsstatistik hat die Cache-Trefferquote zur Lieferanten- und Modellliste hinzugefügt; Xiaomi MiMo verfügt über eine integrierte Guthaben- und Token-Plan-Limit-Abfrage; Die Kontokarte im Autorisierungscenter folgt der Reihenfolge und den versteckten Einstellungen der Seitenleistenanwendung. Diese Version verstärkt außerdem die Sicherheitsprüfungen von Deep-Link-Import-MCP, Nutzungsskripten, SQL-Import und nicht-nativen Abhöradressen und verbessert die Geschwindigkeit der Datenbank, des lokalen Routings, der Nutzungssynchronisierung, der Sitzungssuche und der Anwendungsseite. Darüber hinaus wird die Nutzung des Hauptagenten von Kimi Code Desktop nicht mitgezählt; Die Ausgabegeschwindigkeit der Antigravitation ist ab 4.0.38 fälschlicherweise hoch. Die Antigravitationssitzung im T3-Code und das allein laufende ACP sind nicht zu sehen. Die offizielle Antwort von Mistral API ist leer, nachdem mit dem Nachdenken begonnen wurde. Native Kimi-Antworten melden immer 400, nachdem das Parallelansicht-Tool aufgerufen wurde; WorkBuddy-Enterprise-Kontopunkte werden als verbraucht angezeigt; ist in der Taskleiste nicht zu sehen. Das xAI-Kontingent und das offizielle Konto werden als Website-Domänennamen angezeigt. doppelte Fertigkeiten werden im Bereich „Entdeckung“ der Fertigkeitsseite angezeigt; Auf der Seite „Anwendung“ wird der Installationsstatus erst angezeigt, wenn die Version überprüft wird. Hinzufügen

Die offizielle Grok-Karte ist an das xAI-Konto gebunden

Die offizielle Grok-Form von Grok Build hat eine „Anmeldemethode“ hinzugefügt (#9321, schließen #8599). Sie können das xAI-Konto im Autorisierungscenter auswählen, das xAI-Konto hinzufügen oder verwalten oder sich mit Grok CLI anmelden. Die Verwendung ist die gleiche wie bei den offiziellen Karten von Claude und Codex.

  • Jedes gebundene Konto ist eine separate Karte. Mit der Kontonummer im Namen können Sie beliebig viele Karten hinzufügen; Wer nicht an ein Konto gebunden ist, hat weiterhin die gleiche feste Karte.
  • Beim Wechsel zur Karte mit einem daran gebundenen Konto aktualisiert CC Switch zunächst die Anmeldung dieses Kontos und schreibt sie dann in ~/.grok/auth.json von Grok CLI, und andere Inhalte in der Datei ändern sich nicht. Grok CLI wird nicht geschrieben, wenn dieses Konto bereits angemeldet ist; Wenn das Netzwerk vorübergehend ausfällt, werden Sie aufgefordert, es später noch einmal zu versuchen. Wenn das Konto tatsächlich ungültig ist, werden Sie aufgefordert, sich erneut im Autorisierungscenter anzumelden.
  • Vor der Änderung der Nummer wird die aktuell von Grok CLI angemeldete Nummer im Autorisierungszentrum erfasst; Beim Zurückwechseln zur Karte „Login mit Grok CLI“ wird die Nummer vor dem ersten Nummernwechsel wiederhergestellt.
  • Wenn Grok CLI beim Löschen des Kontos im Autorisierungscenter CC Switch verwendet, um sich für dieses Konto anzumelden, wird die ursprüngliche Anmeldung wiederhergestellt. Wenn das ursprüngliche Konto nicht mehr vorhanden ist, melden Sie sich ab.
  • Bei Karten, die an eine Kontonummer gebunden sind, werden die Karten-, Nutzungs- und Palettenlimits anhand dieser Nummer überprüft. Wenn die Grok CLI-Anmeldung für eine Karte ohne Konto abläuft, verwenden Sie das Konto desselben Benutzers im Autorisierungscenter, um das Limit zu überprüfen.

Antigravity CLI-Plug-in

Die Seite „Plugins“ unterstützt Antigravity CLI (#9882, #9885). Genau wie andere Anwendungen können Sie die eigene Befehlszeile von agy aufrufen. Sie können in „Entdecken“ nach offiziellen Plug-ins und Partnermarkt-Plugins suchen, um sie zu installieren, zu aktivieren, zu deaktivieren, zu deinstallieren und zu aktualisieren.

  • Vergleichen Sie vor dem Update die Versionsnummer auf dem Markt. Wenn es sich um die neueste Version handelt, installieren Sie sie nicht erneut.
  • Wenn das Plug-in durch eine laufende Antigravity-Sitzung oder einen Hintergrunddienst belegt ist, werden Sie aufgefordert, es zunächst zu schließen und es erneut zu versuchen.
  • Die von der alten Antigravity-Anwendung installierten Plug-Ins werden in einem numerisch benannten Verzeichnis abgelegt. CC Switch kann sie nicht aktualisieren. Sie werden aufgefordert, sie in „Discover“ zu deinstallieren und erneut zu installieren.

Nutzungsstatistik: Cache-Trefferrate nach Anbieter und Modell anzeigen

Die Listen „Lieferant“ und „Modell“ der Nutzungsstatistiken fügen nach den Tokens eine Spalte „Trefferquote“ hinzu, sodass Sie sehen können, welcher Lieferant und welches Modell den Cache nicht verwendet haben. Der Algorithmus ist derselbe wie die Trefferquote im Anforderungsprotokoll (Cache-Treffer ÷ zwischenspeicherbare Eingaben). Die Cache-Treffer und zwischenspeicherbaren Eingaben jeder Zeile ergeben oben die Gesamtsumme; Zeilen ohne zwischenspeicherbare Eingaben zeigen „—“ an.

Xiaomi MiMo-Guthaben und Token-Plan-Limit

Der Anbieter von Xiaomi MiMo verfügt über zwei integrierte offizielle Abfragen (geschlossen #9404), sodass Sie sich nicht mehr auf das Konsolen-Cookie-Nutzungsskript verlassen müssen:

  • Token-Plan (Schlüssel beginnend mit tp-): Zeigt das genutzte und Gesamtkontingent sowie die Endzeit dieses Zeitraums an.
  • Saldo (Taste beginnend mit sk-): Zeigt den verfügbaren Saldo an (abzüglich des eingefrorenen Teils). Ein Saldo von 0 wird nicht als ungültiger Schlüssel betrachtet.

Die Karte des Autorisierungszentrums folgt der Anwendung in der Seitenleiste

Die Kontokarten im Autorisierungscenter sind in der Reihenfolge der auf der Seite „Anträge“ gezogenen Anträge angeordnet. Die Karte wird nur ausgeblendet, wenn alle Anwendungen, die dieses Konto verwenden, ausgeblendet sind (Copilot-, ChatGPT- und xAI-Konten werden auch von Anbietern von Anwendungen wie Claude Code verwendet). Die aus dem Lieferantenformular übersprungene Karte wird immer angezeigt.

Neue Voreinstellung hinzufügen

StringAI hinzugefügt.

Ändern

  • Datenbank und lokales Routing sind schneller (#9820, #9821): Die Hauptdatenbank wird in den WAL-Modus umgeschaltet, die Konfigurations-, Routing-, Preis- und Failover-Warteschlangen, die für jede Routing-Anfrage gelesen werden sollen, werden so geändert, dass sie aus dem Cache lesen, Routing-Datenbankoperationen werden in einen separaten Thread verschoben, der den Thread, der die Anfrage verarbeitet, nicht mehr belegt; Der Konversationsinhalt wird beim Weiterleiten der Anfrage einmal weniger kopiert und die Datenschutzfilterung wird für Anfragen, die nicht umgeschrieben wurden, nicht mehr wiederholt.
  • Nutzungssynchronisierung ist schneller (#9817, #9818): Sitzungsprotokolle jeder Anwendung werden parallel gescannt; Nutzungsskripte werden in separaten Threads ausgeführt und verlangsamen andere Anfragen nicht mehr.
  • Die Suche nach Konversationsinhalten ist schneller (#9827, #9896): Bei der Suche nach einem oder zwei Wörtern wird nicht mehr der gesamte Text durchsucht; Wenn die Eingabe fortgesetzt wird, wird die letzte nicht abgeschlossene Suche abgebrochen. Das Suchindexformat hat sich geändert und der Index wird für die erste Suche nach dem Upgrade neu erstellt.
  • Die Seite „Anwendung“ öffnet sich schneller (#9418, #9886, schließen #9884): Zeigen Sie zunächst die Gruppe „Installiert/Nicht installiert“ entsprechend dem Installationspfad der Maschine an, ohne auf die Versionsprüfung jedes Tools zu warten; Die Versionen jedes Tools werden gleichzeitig überprüft und jedes Tool wird einzeln nach der Überprüfung angezeigt.

Sicherheit

  • Deep Link Import MCP (#9831): Im Bestätigungsfeld werden alle Felder des MCP-Servers angezeigt (einschließlich Arbeitsverzeichnis, Anforderungsheader usw.), und Felder mit hohem Risiko sind rot markiert. Liest die lokalen Umgebungsvariablen, führt Hilfsbefehle aus, zeigt das Arbeitsverzeichnis auf den Netzwerkfreigabepfad oder die Konfigurationsadresse ist nicht http / https und lehnt den Import direkt ab.
  • Nutzungsskript (#9829): Vom Skript gesendete Anforderungen folgen keinen Weiterleitungen mehr und können nicht an den eigenen Routing-Port von CC Switch gesendet werden. Die Antwort kann bis zu 2 MiB groß sein; Schlüssel, Adresse und andere im Skript ausgefüllte Variablen werden korrekt maskiert. Auch die Nutzungsabfrageadresse im Deeplink wird überprüft. Wenn es sich um eine Intranet- oder lokale Adresse handelt, wird ein Bestätigungsfeld angezeigt.
  • SQL-Import (#9832): Beim Importieren einer SQL-Sicherung oder eines WebDAV-/S3-Synchronisierungs-Snapshots ist die Erstellung von Triggern und Ansichten nicht zulässig, die maximale Dateigröße beträgt 512 MiB und die Ausführung wird nach mehr als 30 Sekunden abgebrochen.
  • Host-Prüfung auf nicht-lokale Abhöradressen (#9833): Wenn der Routing-Dienst auf 0.0.0.0 / :: lauscht, müssen Anforderungen vom lokalen Computer auch die Host-Prüfung bestehen, um eine erneute DNS-Bindung zu verhindern.

Fix

  • Die Hauptagentennutzung von Kimi Code Desktop wird nicht gezählt (#9505, siehe #9498): Kimi Code Desktop 1.3.5 hat das Sitzungsprotokollformat geändert, die Hauptagentennutzung wird übersprungen und das Subagentenmodell wird als unknown angezeigt. Beide Formate können nun ohne Doppelberechnungen gelesen werden; Nach dem Upgrade werden die alten Protokolle erneut gescannt, um die zuvor fehlende Nutzung und Modelle auszugleichen.
  • Antigravity-Ausgabegeschwindigkeit ist fälschlicherweise hoch (#9858): Ab 4.0.38 können Anfragen, die über einen längeren Zeitraum berücksichtigt wurden, Zehntausende tok/s anzeigen. Der Ausgabetoken von Antigravity enthält verborgenes Denken, und das erste Wort Zeit beinhaltet auch die Denkzeit. Jetzt wird auf Basis der Gesamtzeit berechnet.
  • Antigravitationssitzungen im T3-Code und im eigenständigen ACP sind nicht sichtbar (#9857, siehe #9838): Diese Sitzungen werden jetzt in der Sitzungsliste und den Nutzungsstatistiken angezeigt. Für sie ist kein Wiederherstellungsbefehl verfügbar und sie können in CC Switch nicht gelöscht werden. Die durch den T3-Code außerhalb der Frage hinzugefügte Beschreibung wird entfernt und im Titel wird die ursprüngliche Frage angezeigt.
  • Die Antwort des offiziellen API von Mistral ist leer, nachdem das Denken aktiviert wurde (Siehe #9902): Das offizielle API von Mistral (einschließlich des von ihm bereitgestellten Drittanbietermodells) teilt die Antwort in Denk- und Textfragmente auf und gibt sie zurück. Die lokale Route kann nicht gelesen werden und die Antwort ist leer oder weist keinen Denkprozess auf. Beide Fragmente können nun nacheinander gelesen werden; Anfragen an den Upstream bleiben unverändert.
  • Kimis native Antworten melden weiterhin 400, nachdem das Bild parallel angezeigt wurde (#8825, siehe #7504): Codex Desktop fügt Eingabeaufforderungen zwischen den Ergebnissen paralleler Toolaufrufe ein. Strenge native Antworten wie Kimis Upstream verwerfen Ergebnisse, die dem Aufruf nicht folgen, und nach dieser Sitzung werden in jeder Runde 400 gemeldet. Lassen Sie uns nun alle Ergebnisse zusammentragen und dann die Einfügeaufforderung einfügen.
  • WorkBuddy-Unternehmenskontopunkte werden als verbraucht angezeigt (siehe #9694): Das Unternehmenskonto wird geändert, um die Unternehmensnutzung zu überprüfen, wobei der Gesamtbetrag, die Nutzung und die Ablaufzeit angezeigt werden; Die unbegrenzte Menge wird als „unbegrenzt, N verwendet“ angezeigt. Wenn der Betrag nicht gefunden wird, schlägt die Abfrage fehl und „aufgebraucht (Gesamt 0)“ wird nicht mehr angezeigt.
  • xAI-Kontingent ist in der Taskleiste nicht sichtbar (siehe #9899): xAI-OAuth-Anbieter in Codex und Claude Code (einschließlich Mitgliedern der Codex-Aggregation) zeigen auch Kontingente in der Taskleiste entsprechend dem gebundenen xAI-Konto an. Wenn keine Bindung besteht, wird das Standardkonto des Autorisierungszentrums verwendet, das mit der Hauptschnittstellenkarte übereinstimmt.
  • Das offizielle Konto in der Taskleiste wird als Website-Domänenname angezeigt (#9863): Die offizielle Codex-Karte mit dem verwalteten Konto ist gebunden, ebenso wie die Codex OAuth-, GitHub Copilot- und xAI OAuth-Karten. Der Untertitel der Taskleiste zeigt das angemeldete Konto an (manuelle Notizen haben Vorrang). Die xAI OAuth-Karte auf der Hauptschnittstelle zeigt auch die Kontonummer an; Die Taskleiste wird nach der Anmeldung beim Autorisierungscenter, dem Wechsel des Standardkontos, dem Löschen oder Abmelden aktualisiert.
  • Doppelte Fertigkeiten werden unter „Entdecken“ auf der Fertigkeitsseite angezeigt: Zwei Fertigkeiten mit demselben Namen im letzten Verzeichnis im selben Lager werden in dasselbe Verzeichnis geladen. „Discover“ zeigte ursprünglich zwei Zeilen an, jetzt wird jedoch nur die Zeile angezeigt, die dem Stammverzeichnis des Warehouses am nächsten liegt.
  • CLI, das mit OpenCode Desktop geliefert wird, wird aufgefordert, npm zum Upgrade zu verwenden (#9099): Die Installationsquelle dieses CLI wird als OpenCode Desktop angezeigt und erklärt, dass es mit der Desktop-Anwendung aktualisiert wird und nicht mehr in den „Alle Upgrades“ gezählt wird; Separat installierter OpenCode wird wie gewohnt aktualisiert.
  • Streaming-Ereignisse, die nahe an der Obergrenze von 64 MiB liegen, werden fälschlicherweise übersprungen (#9867): Die von 4.0.39 hinzugefügte Pufferobergrenze wird so geändert, dass sie auf der Grundlage eines einzelnen Ereignisses beurteilt wird. Normale Ereignisse, die nahe an der Obergrenze liegen, werden nicht mehr zusammen mit dem nächsten im selben Block verworfen.

Upgrade-Anweisungen

  • Wenn der Routing-Dienst 0.0.0.0 / :: überwacht und einen benutzerdefinierten Hostnamen (der nicht mit .local, .internal, .localhost endet) verwendet, um auf die Route auf diesem Computer zuzugreifen, erhalten Sie nach dem Upgrade eine 403. Sie müssen diesen Hostnamen in die „Verbindungsadresse“ der „Lokalen Route“ eingeben (diese Adresse wird auch in die Konfiguration jedes Clients geschrieben). Andere Geräte im LAN, WSL und Docker sind nicht betroffen. – Der Index für die Suche nach Sitzungsinhalten wird bei der ersten Suche nach dem Upgrade neu erstellt. Bei vielen Sitzungen ist die erste Suche langsamer.

cc-switch v4.0.40

Highlights

  • Grok Official now supports xAI account switching — #9321 adds account-bound Grok cards that refresh credentials and write only the selected identity to ~/.grok/auth.json, preserving its other contents. Quotas follow the bound account, while deleting an account or returning to “Follow Grok CLI login” restores the previous CLI identity.

  • Antigravity CLI joins the plugin manager — #9882 and #9885 support discovering and managing official and partner-market plugins through agy. Updates skip current versions and require stopping active sessions; plugins installed by older Antigravity versions into numbered directories must be uninstalled and reinstalled because CC Switch cannot update them.

  • Quota diagnostics are more actionable — Supplier and model tables now expose cache-hit rate, making cache-unfriendly workloads visible. Xiaomi MiMo also gains built-in queries for tp- Token Plan usage and sk- balance, including frozen-fund adjustments, removing the need for cookie-scraping usage scripts.

  • Import and routing surfaces are hardened — #9831, #9829, and #9832 reject risky deep-link MCP configurations, restrict usage-script redirects and response size, and block SQL triggers/views with new size and execution-time limits. Migration: if routing listens on 0.0.0.0 or :: and local requests use a custom hostname, expect HTTP 403 until that hostname is added under Local Routing → Connection Address (#9833).

  • Routing, usage collection, and search are faster — WAL, cached request-path configuration, and dedicated database threads reduce routing contention (#9820, #9821); session logs are scanned in parallel, and usage scripts run off the request path. Migration: the search-index format changed, so the first search after upgrading rebuilds the index and may take longer for large histories (#9827).

  • Provider compatibility fixes prevent empty or stuck sessions — Mistral responses now preserve reasoning/body fragment order, and Kimi native Responses groups parallel image-tool results before intervening prompts to prevent subsequent turns from repeatedly returning HTTP 400 (#8825). Antigravity throughput is recalculated against full elapsed time so hidden thinking no longer inflates tok/s, while the 64 MiB streaming fix avoids dropping valid near-limit events (#9867).

CC Switch v4.0.40

本版本让 Grok Build 的官方卡可以绑定授权中心里的 xAI 账号，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。插件页支持 Antigravity CLI；用量统计的供应商和模型列表加了缓存命中率；小米 MiMo 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

新增

Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（#9321，关闭 #8599），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

  • 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
  • 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 ~/.grok/auth.json，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
  • 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
  • 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
  • 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

Antigravity CLI 插件

「插件」页支持 Antigravity CLI（#9882、#9885），和其他应用一样调用 agy 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

  • 更新前先比对市场上的版本号，已是最新就不重装。
  • 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
  • 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 #9404），不用再靠抓控制台 Cookie 的用量脚本：

  • Token Plan（tp- 开头的 Key）：显示已用和总额度，以及本期结束时间。
  • 余额（sk- 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

新增预设

新增 StringAI。

变更

  • 数据库与本地路由更快（#9820、#9821）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
  • 用量同步更快（#9817、#9818）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
  • 会话内容搜索更快（#9827、#9896）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
  • 「应用」页打开更快（#9418、#9886，关闭 #9884）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

安全

  • 深链接导入 MCP（#9831）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
  • 用量脚本（#9829）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
  • SQL 导入（#9832）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
  • 非本机监听地址的 Host 检查（#9833）：路由服务监听 0.0.0.0 / :: 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

修复

  • Kimi Code Desktop 主 agent 的用量没统计（#9505，见 #9498）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 unknown。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
  • Antigravity 输出速度虚高（#9858）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
  • T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到（#9857，见 #9838）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
  • Mistral 官方 API 开思考后回复为空（见 #9902）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
  • Kimi 原生 Responses 在并行看图后一直报 400（#8825，见 #7504）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
  • WorkBuddy 企业账号积分显示为已用完（见 #9694）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
  • 托盘里看不到 xAI 额度（见 #9899）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
  • 托盘里官方账号显示成网站域名（#9863）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
  • Skills 页的「发现」里出现重复的技能：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
  • OpenCode Desktop 自带的 CLI 被提示用 npm 升级（#9099）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
  • 快到 64 MiB 上限的流式事件被误跳过（#9867）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

升级说明

  • 路由服务监听 0.0.0.0 / ::、又在本机用自定义主机名（不以 .local、.internal、.localhost 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
  • 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
