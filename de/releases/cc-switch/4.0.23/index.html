CC-Schalter v4.0.23

Diese Version ermöglicht es dem Lieferanteneditor von Kimi Code, MiniMax Code und Oh My Pi, den Teil der Konfigurationsdatei im eigenen Format der Anwendung anzuzeigen; Wenn Claude Code und Claude Desktop über Routing mit dem Upstream des OpenAI-Formats und Gemini verbunden sind, kann die vom Client ausgewählte Denkausrüstung an mehr Modelle gesendet werden, und Sie können auch auswählen, wie sie auf der Karte gesendet werden soll. Das Autorisierungscenter kann das Kontingent aller Konten mit einem Klick aktualisieren. Antigravitation, MiniMax-Code Der Nutzungsdatensatz enthält Zeitverbrauch und Zeit für das erste Wort. Darüber hinaus kann das Hauptfenster nach dem Wechsel in den Lightweight-Modus unter Windows nicht zurückgegeben werden, der Modellwechsel schlägt fehl, wenn eine Verbindung zum Upstream einiger OpenAI-Formate hergestellt wird, Lieferanten können nicht bearbeitet werden, wenn das Konfigurationsverzeichnis von DeepSeek Harness verknüpft ist, die Verwendung von Grok Build-Sitzungen über 50 MiB wird nicht gezählt, die Verwendung von Codex-Zweigsitzungssitzungen wird nie importiert, DeepSeek Harness und andere Anwendungen melden beim Testen des offiziellen Gleichgewichts, dass der Schlüssel leer ist, und mehrere Editoren im Lieferantenformular verdecken sich gegenseitig. Hinzufügen

Lieferanteneditoren für Kimi Code, MiniMax Code und Oh My Pi werden im nativen Format angezeigt

In der Vergangenheit zeigte der Lieferanteneditor dieser drei Anwendungen den JSON der Karte an, der nicht mit ihren tatsächlichen Konfigurationsdateien übereinstimmte, und die Konfigurationsausschnitte in den Upstream-Dokumenten konnten nicht eingefügt werden. Jetzt zeigt der Editor nur diesen Teil der Konfigurationsdatei an und der Speicherort und das Format stimmen mit der Datei überein:

  • Kimi-Code: [providers.<key>] in config.toml und sein Gegenstück [models."..."].
  • MiniMax-Code: custom_provider.<key> in YAML.
  • Oh mein Pi: providers.<key> in models.yml. The title shows the actual file path, which changes with directory overrides and variables like KIMI_CODE_HOME. Wenn der Entwurf Formatfehler aufweist, andere Knoten geschrieben werden oder globale Einstellungen wie default_model geschrieben werden, werden Sie aufgefordert, das Speichern abzulehnen. Die oben genannten Formularfelder können vorübergehend nicht geändert werden, um ein Überschreiben des Entwurfs zu vermeiden. Im Editor verfasste Kommentare werden nicht gespeichert. Der Anbieter von DeepSeek Harness nutzt weiterhin den JSON-Editor im Profil-Patch.

Bei der Verbindung zu Gemini über einen Router kann die Denkausrüstung auch dorthin gesendet werden.

Wenn in der Vergangenheit Claude Code und Claude Desktop über Routing in das native Format von Gemini konvertiert wurden, wurden die vom Kunden ausgewählten Denkgeräte und „Close Thinking“ verworfen und Gemini verwendete immer die Standardeinstellungen des Modells. Nun gemäß der Konvertierungsmethode der OpenAI-kompatiblen Schnittstelle von Gemini:

  • Zwillinge 2.5: Niedrig, mittel und hoch sind Denkbudgets von 1024, 8192 bzw. 24576. Wenn das Denken ausgeschaltet ist, senden Flash und Flash-Lite 0. Pro kann nicht ausgeschaltet werden und sendet den kleinsten Wert von 128.
  • Gemini 3 und höher: Niedrige, mittlere und hohe Gänge senden (Gemini 3 Pro verfügt nicht über mittlere, hohe Gänge senden). Keines dieser Modelle kann zum Denken ausgeschaltet werden. Dies ist die niedrigste Stufe, die im ausgeschalteten Zustand unterstützt wird.
  • Nicht erkennbare Modelle, Bilder und Stimmen sowie Übertragungsaliase mit Zahnrädern im Namen (z. B. gemini-3-pro-high) werden nicht gesendet, und sie werden auch nicht gesendet, wenn in der Anfrage keine Einstellung vorhanden ist.

Autorisierungscenter „Alle aktualisieren“

In der Kopfzeile des Autorisierungscenters gibt es eine Schaltfläche „Alle aktualisieren“, um die Salden aller Konten auf der Seite erneut abzufragen (DeepSeek ist der Saldo), und jede Zeile wird wie gewohnt als aktualisiert angezeigt (#9073).

Verbesserungen

Wenn Claude Code und Claude Desktop über Routing mit dem Upstream des OpenAI-Formats verbunden sind, berücksichtigen Sie die Dateigröße, um mehr Modelle senden zu können (#9062). In der Vergangenheit erhielten nur o-Serien, GPT-5 und höher sowie Grok 4.5 und höher die Denkausrüstung. Andere Modelle wie DeepSeek wurden stillschweigend verworfen und es gab keinen Eintrag im Protokoll. Jetzt:

  • Anerkannte Lieferanten senden die Daten entsprechend den unterstützten Bereichen. DeepSeek sendet beispielsweise Low, High und Max und OpenRouter sendet Up bis xhigh. OpenAI interfaces such as Kimi, GLM, Qwen, and MiniMax will not send the data if they do not accept this parameter.
  • Der nicht erkannte Upstream sendet nur Low, Medium und High. Wenn xhigh und max ausgewählt sind, wird high gesendet.
  • GPT-3.5, GPT-4, Llama, Mistral werden nicht gesendet; Sie werden nicht gesendet, wenn das Denken ausgeschaltet ist.
  • Die Lieferantenformulare der beiden Anwendungen haben „Denkgetriebe“ in diesen beiden Formaten hinzugefügt: „Automatisch (empfohlen)“ wird gemäß den oben genannten Regeln gesendet; „Senden wie es ist“: Der Client wählt aus, welche Datei gesendet werden soll, und es wird ein Fehler gemeldet, wenn der Upstream xhigh oder max nicht unterstützt; „Nicht senden“ wird verwendet, wenn der Upstream aufgrund dieses Parameters einen Fehler meldet. Auf der Karte „Verwaltetes Konto“ wird dieses Element nicht angezeigt. Die Gangumwandlung beim Herstellen einer Verbindung zu DeepSeek über Codex wurde ebenfalls geändert, um mit der offiziellen DeepSeek-Funktion übereinzustimmen: Minimal und Niedrig werden als Niedrig, Mittel, Hoch und XHoch als Hoch übersetzt und Max wird als Max übersetzt. Zuvor wurde „niedrig“ auf „hoch“ und „xhoch“ auf „max“ bezogen. **Die Nutzungsaufzeichnungen von Antigravity und MiniMax Code enthalten Zeitverbrauch und Zeit für das erste Wort. ** Bisher wurden Geschwindigkeit und Zeit des ersten Wortes bei der Verwendung dieser beiden Anwendungen nicht berücksichtigt. Zuvor importierte Datensätze werden ebenfalls hinzugefügt. Skills-Erkennungsseite und installierte Seite werden in denselben Zeilenstil geändert (#9081). Der Warehouse-Name wird in kleinen, gleich breiten Zeichen neben dem Namen platziert und der Verzeichnispfad wird nicht mehr angezeigt. die Schaltfläche „Dokument öffnen“ wird ganz nach rechts verschoben; „Installierte · N Anwendungen“ wird in „Installiert ›“ geändert. When jumping from the discovery page to "Installed", that line will flash yellow twice and then restore. Claude’s official card with an account number tied to it shows the account number in the tray (#9071). In the past, the subtitle was always www.anthropic.com, and it was hard to tell when there were several official cards. Wenn nun Notizen vorhanden sind, werden die Notizen angezeigt. Wenn keine Notizen vorhanden sind, wird die Kontonummer (E-Mail-Adresse) angezeigt. Wenn keine E-Mail-Adresse vorhanden ist, wird der Name der Organisation angezeigt. if the account number is not on this computer, the official website will still be displayed. In Claude Desktop routing mode, the model name of Haiku file is changed to claude-haiku-5-5 (#9096). Claude Desktop betrachtet claude-haiku-4-5 als altes Modell und der Haiku-Modus kann den Denkmodus nicht auswählen. Der Upstream selbst ist die alte Version von Claude Haiku ohne Änderungen. Direct connection mode is not affected. Grok Build hat Preise für grok-4.6-build, grok-4.7-build, grok-4.7-build-fast (#9026) hinzugefügt. Voreinstellungen: OpenAI API Key-Voreinstellung, Gemini CLI / Antigravity-Voreinstellung von 13 Anbietern (#9089) und iFlytek Astron MaaS Pay-as-you-go Claude Code-Voreinstellung (#9036) hinzugefügt.

cc-switch v4.0.23

Highlights

  • Provider editors now use the app's native config format — Kimi Code, MiniMax Code and Oh My Pi no longer show the card's JSON; editors show only that provider's section in the real file (config.toml [providers.<key>] plus its [models."..."] tables, YAML custom_provider.<key>, models.yml providers.<key>), so upstream config snippets paste in unchanged and the title tracks path overrides such as KIMI_CODE_HOME. Drafts with syntax errors, other providers' nodes, or global settings like default_model are rejected and the form fields above stay locked until corrected; inline comments are not saved. DeepSeek Harness still uses the JSON editor in profile patches.

  • Reasoning-effort forwarding is broader — and changes two behaviors — Claude Code/Desktop routed to OpenAI-format upstreams now forward the client's thinking level to more models (DeepSeek low/high/max, OpenRouter up to xhigh; GPT-3.5/GPT-4/Llama/Mistral still excluded), via a new 「思考档位」 field with 「自动（推荐）」「原样发送」「不发送」 modes (absent on managed cards). Gemini-native routing maps levels to budgets (2.5: 1024/8192/24576; 3+: low/medium/high, with aliases like gemini-3-pro-high and image/voice models skipped). Watch the two behavior changes: Codex→DeepSeek now follows DeepSeek's official mapping (minimal/low→low, medium/high/xhigh→high, max→max; previously low→high and xhigh→max), and Claude Desktop Haiku in routing mode is renamed to claude-haiku-5-5. Use 「不发送」 if you need the old pass-nothing behavior.

  • Operational improvements worth having — Authorization center gains a 「全部刷新」 button that re-queries every account's quota in one click (#9073); Antigravity and MiniMax Code usage records now include latency and time-to-first-token, backfilled for past imports; tray titles for bound official Claude cards show the note or account instead of the generic www.anthropic.com (#9071); Skills discovery/installed pages share one row style (#9081); new presets include an OpenAI API Key preset, Gemini CLI / Antigravity presets for 13 providers (#9089), and iFlytek Astron MaaS pay-as-you-go for Claude Code (#9036).

  • Substantive fixes, and no breaking changes or migration steps — Notable repairs: Windows light-mode softlock where the main window never returned (#9090), model-switch failures when an OpenAI-format upstream returns SSE to non-streaming requests (#9097/#9095), symlinked DeepSeek Harness profiles falsely reporting conflicts (#9101/#9100), Grok Build sessions over 50 MiB skipped from usage (#9026/#6660), Codex branch sessions never imported (#9093/#9094), "API key is empty" on balance/Coding-Plan tests (#9108/#9107), form fields overwriting each other (#6777), startup UI blocked on usage sync (#9098/#9084), and ChatGPT login expiry being retried as a transient error (#9049). No explicit breaking changes or migration steps are documented for v4.0.23; the items in the reasoning-effort bullet are behavior changes to verify, not required migrations.

  • Upgrade verdict — Not a no-op or metadata-only re-tag: this is a real feature-and-fix release. Users of Kimi Code, MiniMax Code, Oh My Pi, DeepSeek Harness, Grok Build, Codex or Claude Desktop through the router, anyone hitting the Windows light-mode or startup-blocking bugs, and heavy users of the authorization center should upgrade. Anyone on v4.0.x using none of those apps or affected paths, and satisfied with current thinking-level behavior, can safely skip; full v4.0 context lives in the v4.0 release notes rather than this patch.

新增

Kimi Code、MiniMax Code、Oh My Pi 的供应商编辑器按原生格式显示

以前这三个应用的供应商编辑器显示的是卡片的 JSON，和它们实际的配置文件对不上，上游文档里的配置片段也贴不进来。现在编辑器只显示配置文件里这一家的部分，位置和格式都和文件一致：

  • Kimi Code：config.toml 里的 [providers.<key>] 和它的 [models."..."] 表。
  • MiniMax Code：YAML 里的 custom_provider.<key>。
  • Oh My Pi：models.yml 里的 providers.<key>。

标题显示实际的文件路径，会跟着目录覆盖和 KIMI_CODE_HOME 这类变量变化。草稿有格式错误、写了别家的节点、或者写了 default_model 这类全局设置时会提示并拒绝保存，改好之前上方的表单字段暂时不能改，避免把草稿覆盖掉。在编辑器里写的注释不会保存。DeepSeek Harness 的供应商在 profile 补丁里，仍用 JSON 编辑器。

经路由连 Gemini 时，思考档位也能发过去

以前 Claude Code、Claude Desktop 经路由转成 Gemini 原生格式时，客户端选的思考档位和「关闭思考」都被丢掉，Gemini 一律用模型的默认设置。现在按 Gemini 自己的 OpenAI 兼容接口的换算方式发：

  • Gemini 2.5：低、中、高分别是 1024、8192、24576 的思考预算。关闭思考时 Flash 和 Flash-Lite 发 0，Pro 不能关，发最小的 128。
  • Gemini 3 及以后：发 low、medium、high 档位（Gemini 3 Pro 没有 medium，发 high）。这些模型都不能关闭思考，关闭时发支持的最低档。
  • 认不出的模型、图片和语音这类模型、名字里已经带档位的中转别名（如 gemini-3-pro-high）不发，请求里本来没有思考设置时也不发。

授权中心「全部刷新」

授权中心页头多了「全部刷新」按钮，一次重新查询页面上所有账号的额度（DeepSeek 是余额），各行照常显示更新中（#9073）。

改进

Claude Code、Claude Desktop 经路由连 OpenAI 格式的上游时，思考档位能发给更多模型（#9062）。以前只有 o 系列、GPT-5 以上和 Grok 4.5 以上会收到思考档位，DeepSeek 等其他模型静默丢掉，日志里也没有记录。现在：

  • 认得出的供应商按它支持的档位发，比如 DeepSeek 发 low、high、max，OpenRouter 最高到 xhigh；Kimi、GLM、Qwen、MiniMax 这类 OpenAI 接口不收这个参数的不发。
  • 认不出的上游只发 low、medium、high，选 xhigh、max 时发 high。
  • GPT-3.5、GPT-4、Llama、Mistral 不发；关掉思考时不发。
  • 两个应用的供应商表单在这两种格式下多了「思考档位」：「自动（推荐）」按上面的规则发；「原样发送」客户端选哪档发哪档，上游不支持 xhigh 或 max 时会报错；「不发送」用于上游因这个参数报错的情况。托管账号的卡片不显示这一项。

Codex 经路由连 DeepSeek 时的档位换算也改成和 DeepSeek 官方一致：minimal、low 发 low，medium、high、xhigh 发 high，max 发 max。以前 low 会被提到 high，xhigh 会被提到 max。

Antigravity、MiniMax Code 的用量记录有了耗时和首字时间。 以前这两个应用的用量里没有速度和首字时间。以前导入的记录也会补上。

Skills 的发现页和已安装页改成同一种行样式（#9081）。仓库名用小号等宽字放在名称旁边，不再显示目录路径；「打开文档」按钮移到最右边；「已安装 · N 个应用」改成「已安装 ›」。从发现页点「已安装」跳过去时，那一行会黄色闪两下再恢复。

托盘里绑了账号的 Claude 官方卡显示账号（#9071）。以前副标题都是 www.anthropic.com，有好几张官方卡时分不出来。现在有备注显示备注，没有备注显示账号（邮箱，没有邮箱时显示组织名）；账号不在这台电脑上时仍显示官网。

Claude Desktop 路由模式下，Haiku 档的模型名改成 claude-haiku-5-5（#9096）。Claude Desktop 把 claude-haiku-4-5 当成旧模型，Haiku 档选不了思考档位。上游本身是旧版 Claude Haiku 时不改。直连模式不受影响。

Grok Build 补上了 grok-4.6-build、grok-4.7-build、grok-4.7-build-fast 的价格（#9026）。

预设： 新增 OpenAI API Key 预设、13 家供应商的 Gemini CLI / Antigravity 预设（#9089），以及讯飞 Astron MaaS 按量付费的 Claude Code 预设（#9036）。

修复

  • Windows 上进入轻量模式后，再次启动 CC Switch，主窗口不出来，托盘也没反应，重启也没用（#9090）。
  • 经路由连 OpenAI 格式的上游、且上游对非流式请求也返回 SSE 时，切换模型报「Unable to validate model」（#9097、#9095）。现在非流式请求会收到完整的 JSON 响应。
  • DeepSeek Harness 的 profile 通过符号链接指向同一个文件时，编辑供应商、MCP 一律报冲突（#9101、#9100）。
  • Grok Build 的会话日志超过 50 MiB 后整个跳过，长会话的用量一直不统计（#9026、#6660）。现在逐行读取，之后只读新增的部分。
  • Codex 的分支会话在父会话闲置一段时间后一直不导入，用量统计不到（#9093、#9094）。
  • DeepSeek Harness、MiniMax Code、Kimi Code 在用量查询里测试官方余额或 Coding Plan 时提示「API key is empty」（#9108、#9107）。已保存的查询本来就正常，只是测试和自定义模板读不到供应商的 Key 和地址。
  • 供应商表单里，改了地址、Key、模型这些字段，再改下方的配置编辑器（或反过来），先改的内容有时被覆盖回去（#6777）。
  • 启动时界面要等后台的会话用量同步做完才响应（#9098、#9084）。
  • Codex 经 OpenRouter 用 DeepSeek V4 Flash 0731 时，对话里有图片就报 404（#6194、#6176）。
  • Windows 上「本地环境检查」会打开 OpenCode 桌面版（#7027、#6973）。
  • macOS 上添加供应商时，图标选择页的返回按钮被红绿灯挡住（#9076、#9075）。
  • 开着本地路由时，MiniMax Code、DeepSeek Harness 表单里拉取到的模型列表两秒后就消失（#9068）。
  • MiniMax Code、DeepSeek Harness、Kimi Code 的 Key 输入框用输入法输入时字母重复（#9069）。
  • 用 mise 安装的 Claude Code，在授权中心添加 Claude 账号时报「default installation is ambiguous」。
  • ChatGPT 登录真的过期时，CC Switch 一直当成临时错误重试，不提示重新登录（#9049）。同一个 PR 还修了 Gemini 的 .env 里 export 开头的泄漏凭据清不掉。
