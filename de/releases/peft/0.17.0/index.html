Neue Methoden

SHiRA

@kkb-code hat Sparse High Rank Adapters (SHiRA, paper) beigesteuert, die einen potenziellen Leistungsgewinn gegenüber LoRAs versprechen – insbesondere wird der Konzeptverlust bei der Verwendung mehrerer Adapter verbessert. Da die Adapter nur 1–2 % der Gewichte trainieren und von Natur aus spärlich sind, kann der Wechsel zwischen Adaptern günstiger sein als bei LoRAs. (#2584)

Fräulein

@JL-er hat in #2604 eine neue PEFT-Methode hinzugefügt, MiSS (Matrix Shard Sharing). Diese Methode ist eine Weiterentwicklung von Bone, die laut unserem PEFT-Methodenvergleichsbenchmark hervorragende Ergebnisse in Bezug auf Leistung und Speichereffizienz liefert. Wenn Sie es noch nicht ausprobiert haben, sollten Sie es jetzt nachholen.

Gleichzeitig wird Bone zugunsten von MiSS veraltet und in PEFT v0.19.0 entfernt. Wenn Sie bereits über einen Bone-Checkpoint verfügen, können Sie ihn mit scripts/convert-bone-to-miss.py in einen MiSS-Checkpoint umwandeln und mit dem Training mit MiSS fortfahren.

Verbesserungen

LoRA für nn.Parameter

LoRA kann jetzt nn.Parameter direkt anvisieren (#2638, #2665)! Hatten Sie jemals diesen komplizierten nn.Module mit vielversprechenden Parametern im Inneren, der aber zu individuell war, um von Ihrer bevorzugten Feinabstimmungsbibliothek unterstützt zu werden? Keine Sorge, jetzt können Sie nn.Parameters direkt ansprechen, indem Sie das Konfigurationsattribut target_parameters verwenden, das ähnlich wie target_modules funktioniert.

Diese Option kann besonders für Modelle mit Mixture of Expert (MoE)-Ebenen nützlich sein, da diese häufig nn.Parameters direkt verwenden und nicht mit target_modules als Ziel verwendet werden können. Verwenden Sie beispielsweise für die Llama4-Modellfamilie die folgende Konfiguration, um die MoE-Gewichte als Ziel festzulegen:

config = LoraConfig(
    ...,
    target_modules=[],  # <= prevent targeting any modules
    target_parameters=["feed_forward.experts.down_proj", "feed_forward.experts.gate_up_proj"],
)

Beachten Sie, dass diese Funktion noch experimentell ist, da sie mit einigen Einschränkungen verbunden ist und sich daher in Zukunft ändern kann. Außerdem können die MoE-Gewichte bei vielen Experten ziemlich groß sein, sodass Sie mit einer höheren Speichernutzung rechnen müssen als bei der Ausrichtung auf normale nn.Linear-Ebenen.

Einspritzadapter basierend auf einem state_dict

Manchmal ist es möglich, dass es einen PEFT-Adapter-Prüfpunkt gibt, die entsprechende PEFT-Konfiguration jedoch aus irgendeinem Grund nicht bekannt ist. Um die PEFT-Ebenen für diesen Prüfpunkt einzufügen, müssten Sie normalerweise die entsprechende PEFT-Konfiguration, insbesondere das Argument target_modules, basierend auf dem state_dict des Prüfpunkts rückentwickeln. Dies kann umständlich und fehleranfällig sein. Um dies zu vermeiden, ist es auch möglich, inject_adapter_in_model aufzurufen und den geladenen state_dict als Argument zu übergeben:

from safetensors.torch import load_file
from peft import LoraConfig, inject_adapter_in_model

model = ...
state_dict = load_file(<path-to-safetensors-file>)
lora_config = LoraConfig()  # <= no need to specify further
model = inject_adapter_in_model(lora_config, model, state_dict=state_dict)

Weitere Informationen zur state_dict-basierten Injektion finden Sie in den Dokumenten.

Änderungen

Kompatibilität

Ein Fehler in den Prompt-Learning-Methoden führte dazu, dass modules_to_save ignoriert wurde. Betroffen sind vor allem Klassifizierungsaufgaben, da sie in der Regel die Klassifizierungs-/Score-Ebene zu modules_to_save hinzufügen. Folglich wurden diese Schichten nach dem Training weder trainiert noch gespeichert. Dies wurde mittlerweile korrigiert. (#2646)

New Methods

SHiRA

@kkb-code contributed Sparse High Rank Adapters (SHiRA, paper) which promise to offer a potential gain in performance over LoRAs - especially the concept loss when using multiple adapters is improved. Since the adapters only train on 1-2% of the weights and are inherently sparse, switching between adapters may be cheaper than with LoRAs. (#2584)

MiSS

@JL-er added a new PEFT method, MiSS (Matrix Shard Sharing) in #2604. This method is an evolution of Bone, which, according to our PEFT method comparison benchmark, gives excellent results when it comes to performance and memory efficiency. If you haven't tried it, you should do so now.

At the same time, Bone will be deprecated in favor of MiSS and will be removed in PEFT v0.19.0. If you already have a Bone checkpoint, you can use scripts/convert-bone-to-miss.py to convert it into a MiSS checkpoint and proceed with training using MiSS.

Enhancements

LoRA for nn.Parameter

LoRA is now able to target nn.Parameter directly (#2638, #2665)! Ever had this complicated nn.Module with promising parameters inside but it was too custom to be supported by your favorite fine-tuning library? No worries, now you can target nn.Parameters directly using the target_parameters config attribute which works similarly to target_modules.

This option can be especially useful for models with Mixture of Expert (MoE) layers, as those often use nn.Parameters directly and cannot be targeted with target_modules. For example, for the Llama4 family of models, use the following config to target the MoE weights:

config = LoraConfig(
    ...,
    target_modules=[],  # <= prevent targeting any modules
    target_parameters=["feed_forward.experts.down_proj", "feed_forward.experts.gate_up_proj"],
)

Note that this feature is still experimental as it comes with a few caveats and therefore might change in the future. Also, MoE weights with many experts can be quite huge, so expect a higher memory usage than compared to targeting normal nn.Linear layers.

Injecting adapters based on a state_dict

Sometimes, it is possible that there is a PEFT adapter checkpoint but the corresponding PEFT config is not known for whatever reason. To inject the PEFT layers for this checkpoint, you would usually have to reverse-engineer the corresponding PEFT config, most notably the target_modules argument, based on the state_dict from the checkpoint. This can be cumbersome and error prone. To avoid this, it is also possible to call inject_adapter_in_model and pass the loaded state_dict as an argument:

from safetensors.torch import load_file
from peft import LoraConfig, inject_adapter_in_model

model = ...
state_dict = load_file(<path-to-safetensors-file>)
lora_config = LoraConfig()  # <= no need to specify further
model = inject_adapter_in_model(lora_config, model, state_dict=state_dict)

Find more on state_dict based injection in the docs.

Changes

Compatibility

A bug in prompt learning methods caused modules_to_save to be ignored. Especially classification tasks are affected since they usually add the classification/score layer to modules_to_save. In consequence, these layers were neither trained nor stored after training. This has been corrected now. (#2646)
