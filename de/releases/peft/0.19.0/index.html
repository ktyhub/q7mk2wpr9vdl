peft v0.19.0

Highlights

Diese PEFT-Version enthält nicht weniger als neun neue PEFT-Methoden, die unten beschrieben werden. Es enthält außerdem zahlreiche Verbesserungen, die PEFT für viele Benutzer nützlicher machen dürften.

Neue Methoden

GraLoRA

@yeonjoon-jung01 hat "GraLoRA: Granular Low-Rank Adaptation for Parameter-Efficient Fine-Tuning" zu PEFT hinzugefügt (#2851). Diese Methode unterteilt das Basisgewicht in kleinere Blöcke und wendet LoRA auf diese an. Diese detailliertere Anpassung verspricht eine Steigerung der Ausdruckskraft und eine Verbesserung der Leistung, insbesondere bei höheren Rängen (64+), und schließt die Lücke zur vollständigen Feinabstimmung.

BD-LoRA

@Conzel hat BD-LoRA beigesteuert: "Block-Diagonal LoRA for Eliminating Communication Overhead in Tensor Parallel LoRA Serving" (#2895). Bei BD-LoRA werden die LoRA-Gewichte blockdiagonal umgesetzt. Dies ermöglicht eine Reduzierung des Kommunikationsaufwands bei Verwendung von Tensorparallelität (TP) und somit eine schnellere Bereitstellung.

Es gibt einen Experimentzweig für die BD-LoRA-Unterstützung in vLLM: vllm-project/vllm#28136.

Patronen

Dank @kashif unterstützt PEFT jetzt auch Patronen (#2953). Der Hauptzweck dieser Methode besteht darin, ein Präfix zu trainieren, um [einen langen Kontext auf eine kurze Größe zu komprimieren] (https://hazyresearch.stanford.edu/blog/2025-06-08-cartridges) und so Token zu sparen. Auf einer niedrigen Ebene ähnelt dies der Präfix-Optimierung. Der PR hat außerdem ein Beispielrezept hinzugefügt, um schnell loslegen zu können.

PVeRA

„PVeRA: Probabilistic Vector-Based Random Matrix Adaptation“ wurde von @leofillioux in #2952 zu PEFT hinzugefügt. Es handelt sich um eine Erweiterung von VeRA, einer PEFT-Methode, die die Gewichtsverteilung zwischen Schichten nutzt, um besonders Parametereffizient zu sein. PVeRA baut darauf auf, indem es ein probabilistisches Element hinzufügt, Stichproben aus den gemeinsam genutzten Parametern zieht und insgesamt eine bessere Leistung verspricht.

PSOFT

@fei407 hat PSOFT, "Efficient Orthogonal Fine-Tuning with Principal Subspace Adaptation", zu PEFT in #3037 hinzugefügt. Orthogonale Feinabstimmungstechniken wie OFT und BOFT sind gut geeignet, die Struktur und damit die Fähigkeiten des zugrunde liegenden Basismodells zu bewahren. PSOFT verbessert die Effizienz dieser Technik, indem es die Anpassung auf den Hauptunterraum mit niedrigem Rang beschränkt.

Lilie

@yibozhong hat Lily: "Low-Rank Interconnected Adaptation across Layers" zu PEFT in #2563 hinzugefügt. Oberflächlich gesehen ähnelt Lily LoRA, verfügt jedoch über ein ausgeklügeltes Schema zur Parameterfreigabe. Die A-Parameter werden blockweise gemeinsam genutzt (z. B. teilen sich 4 aufeinanderfolgende q_proj-Ebenen dasselbe A). Es gibt einen Pool von B-Parametern, der global gemeinsam genutzt wird. Die tatsächlichen B-Parameter werden datenabhängig über einen Router ausgewählt. Dadurch kann Lily höhere Ränge als LoRA verwenden und gleichzeitig eine niedrige Anzahl trainierbarer Parameter beibehalten.

ERDNUSS

In #3084 wurde "PEANuT: Parameter-Efficient Adaptation with Weight-aware Neural Tweakers" zu PEFT hinzugefügt, wiederum von @yibozhong. PEANuT fügt dem Basismodell ein kleines neuronales Netz (sogenannte gewichtsbewusste neuronale Tweaker) hinzu. Im Vergleich zu LoRA erhöht dies die Expressivität bei gleicher Anzahl trainierbarer Parameter oder ermöglicht eine deutliche Reduzierung der Parameteranzahl ohne Einbußen bei der Expressivität. Dies geht mit einem höheren Speicherbedarf bei gleicher Parameteranzahl und einer geringeren Geschwindigkeit einher.

TinyLoRA

Wir haben mit @kashif einen weiteren Serienautor, der auch [TinyLoRA: „Learning to Reason in 13 Parameters“] (https://arxiv.org/abs/2602.04118) in #3024 beigesteuert hat. Hierbei handelt es sich um eine PEFT-Methode, die es ermöglicht, eine extrem kleine Anzahl von Parametern zu trainieren, viel weniger als selbst mit LoRA-Rang 1 erreicht werden könnte. Die Arbeit zeigt, dass es insbesondere beim Reinforcement Learning oft ausreichen kann, nur wenige Parameter zu trainieren, um gute Ergebnisse zu erzielen.

AdaMSS

@LonglongaaaGo hat [„AdaMSS: Adaptive Multi-Subspace Approach for Parameter-Efficient Fine-Tuning“] (https://neurips.cc/virtual/2025/loc/san-diego/poster/119606) zu PEFT hinzugefügt. Diese Methode segmentiert die Basisgewichte des Modells in kleinere Unterräume, die für die Feinabstimmung vorgesehen sind. Darüber hinaus ist es möglich, weniger wichtigen Unterräumen während des Trainings dynamisch ein niedrigeres Parameterbudget zuzuweisen, ähnlich wie es AdaLoRA tut. Dies verspricht eine höhere Aussagekraft und bessere Generalisierung als ähnliche PEFT-Methoden.

Verbesserungen

Konvertieren Sie Nicht-LoRA-Adapter in LoRA

In #2939 haben wir Funktionen zu PEFT hinzugefügt, um die [Konvertierung von Prüfpunkten vieler Nicht-LoRA-Methoden in LoRA-Prüfpunkte] zu ermöglichen (https://huggingface.co/docs/peft/main/en/package_reference/lora_conversion). Dies kann nützlich sein, da viele andere Pakete nur LoRA, aber keine anderen PEFT-Methoden unterstützen, z. B. Diffusoren und vLLM. Mit den neuen Konvertierungstools können somit mehr PEFT-Methoden als nur LoRA mit diesen Paketen verwendet werden. Die Konvertierung ist verlustbehaftet, aber empirische Tests haben gezeigt, dass der Fehler bei einem ausreichend hohen LoRA-Rang recht gering sein kann.

LoRA-GA

@sambhavnoobcoder hat mit "LoRA-GA: Low-Rank Adaptation with Gradient Approximation" (#2926) eine neue Möglichkeit zur Initialisierung von LoRA-Gewichten hinzugefügt. Dadurch können Sie die LoRA-Gewichte so initialisieren, dass die Farbverläufe mit vollständiger Feinabstimmung ausgerichtet werden und zu einer schnelleren Trainingskonvergenz führen sollten.

Reduzierung der Eindringlingsmaße

In [„LoRA vs Full Fine-tuning: An Illusion of Equivalence“] (https://huggingface.co/papers/2410.21228) zeigten die Autoren, dass die LoRA-Feinabstimmung sogenannte „Eindringlingsdimensionen“ einführen kann, die zum Vergessen beitragen. Wir haben jetzt eine [Dienstprogrammfunktion zum Entfernen der Eindringlingsdimension] (https://huggingface.co/docs/peft/main/en/developer_guides/lora#recovering-base-model-performance-via-intruder-dimension-reduction) in PEFT, reduce_intruder_dimension. Wenn man dies auf ein fein abgestimmtes LoRA-Modell anwendet, sollte das Vergessen reduziert werden, während die fein abgestimmte Aufgabenleistung nahezu gleich bleiben sollte.

Transformer Engine

In #3048 fügte @balvisio PEFT Unterstützung für Transformer Engine, eine Quantisierungsmethode von NVIDIA, hinzu.

Tensor-Parallel-Unterstützung

In einer Reihe von PRs (#3079, #3091, #3096) fügte @michaelbenayoun Unterstützung für Tensor-Parallelität zu LoRA hinzu.

Verbesserungen bei der Gewichtsbindung

In vielen LLMs haben die Einbettung und der LM-Kopf gebundene Gewichte, um Parameteranzahl zu sparen. Dies kann jedoch bei der Feinabstimmung dieser Ebenen zu kniffligen Situationen führen. Durch eine Reihe von PRs (#2803, #2922, #2870, #2879, #3126) haben wir dabei die Benutzererfahrung verbessert. Vor allem können Benutzer jetzt ensure_weight_tying=True an ihre PEFT-Konfiguration übergeben, um die Aufrechterhaltung der Gewichtsbindung zu erzwingen. Bitte überprüfen Sie die [PEFT-Dokumente zur Gewichtsbindung] (https://huggingface.co/docs/peft/main/en/developer_guides/lora#weight-tying), um zu erfahren, wie die Gewichtsbindung jetzt gehandhabt wird. Vielen Dank an @romitjain, @sambhavnoobcoder und @Cursx für ihre Beiträge.

Unterstützung für schwebende Typen mit geringer Präzision

#3055 sorgt dafür, dass LoRA mit Basismodellen funktioniert, die Floats mit sehr geringer Präzision wie torch.float8_e4m3fn verwenden. Ein Beispiel hierfür wäre MiniMax-M2.5.

Nullinitialisierung für PrefixTuning

#3128 führt Zero-Init für das Präfix-Tuning ein, was unseren Benchmarks zufolge die Ergebnisvarianz erheblich reduzierte und eine gute Aufgabengenauigkeit ergab, ohne dass eine schnelle Entwicklung erforderlich war.

LoftQ + int8 Quantisierung

Mit #3088 unterstützt die LoftQ-Implementierung nun die Korrektur von Fehlern für die int8-Quantisierung, ohne Aktivierungsschwellenwerte neben der bereits vorhandenen nf4-Quantisierung zu verwenden.

Änderungen

Entfernung von Knochen

Die Bone PEFT-Methode wurde in #3115 entfernt. Benutzer werden angewiesen, stattdessen MiSS zu verwenden, den verbesserten Ersatz für Bone. Verwenden Sie dieses Bone-zu-MiSS-Konvertierungsskript, wenn Sie alte Bone-Checkpoints portieren möchten.

AutoGPTQ und AutoAWQ

Diese beiden Quantisierungsmethoden verwenden dank @ZX-ModelCloud jetzt GPTQModel als Backend (#2932).

Behandlung von requires_grad in modules_to_save

Zuvor aktivierte PEFT requires_grad auf dem Originalmodul, wenn das entsprechende modules_to_save deaktiviert war. Dies ist fast nie erwünscht und wurde daher behoben. Obwohl diese Änderung technisch nicht rückwärtskompatibel ist, handelt es sich um einen extremen Nischenfall, sodass wir nicht erwarten, dass irgendein Benutzer dadurch negativ beeinflusst wird.

peft v0.19.0

Highlights

This PEFT release contains no less than nine new PEFT methods, described below. It also contains numerous enhancements that should make PEFT more useful to many users.

New Methods

GraLoRA

@yeonjoon-jung01 added "GraLoRA: Granular Low-Rank Adaptation for Parameter-Efficient Fine-Tuning" to PEFT (#2851). This method subdivides the base weight into smaller blocks and applies LoRA to those. This more granular adaptation promises to increase expressiveness and improve performance, especially at higher ranks (64+), closing the gap to full fine-tuning.

BD-LoRA

@Conzel contributed BD-LoRA: "Block-Diagonal LoRA for Eliminating Communication Overhead in Tensor Parallel LoRA Serving" (#2895). With BD-LoRA, the LoRA weights are implemented in a block-diagonal way. This allows to reduce communication overhead when using tensor parallelism (TP) and thus faster serving.

There is an experiment branch for BD-LoRA support in vLLM: vllm-project/vllm#28136.

Cartridges

Thanks to @kashif, PEFT now also supports Cartridges (#2953). The main purpose of this method is to train a prefix to compress a long context to a short size and thus save on tokens. On a low level, this is similar to prefix tuning. The PR also added an example recipe to quickly get started.

PVeRA

"PVeRA: Probabilistic Vector-Based Random Matrix Adaptation" was added to PEFT by @leofillioux in #2952. It is an extension of VeRA, a PEFT method that uses weight sharing between layers to be especially parameter efficient. PVeRA builds on top of that by adding a probabilistic element, sampling from the shared parameters and promising better performance overall.

PSOFT

@fei407 added PSOFT, "Efficient Orthogonal Fine-Tuning with Principal Subspace Adaptation", to PEFT in #3037. Orthogonal fine-tuning techniques like OFT and BOFT are good at preserving the structure and thus capabilities of the underlying base model. PSOFT improves efficiency of this technique by constraining the adaptation to low-rank principal subspace.

Lily

@yibozhong added Lily: "Low-Rank Interconnected Adaptation across Layers" to PEFT in #2563. Lily is on the surface similar to LoRA but has a sophisticated parameter sharing scheme. The A parameters are shared blockwise (e.g. 4 consecutive q_proj layers share the same A). There is a pool of B parameters that is shared globally, the actual B's are chosen in a data-dependent way through a router. This allows Lily to use higher ranks than LoRA while maintaining a low trainable parameter count.

PEANuT

In #3084, "PEANuT: Parameter-Efficient Adaptation with Weight-aware Neural Tweakers" was added to PEFT, again by @yibozhong. PEANuT adds a small, neural net (so called weight-aware neural tweakers) to the base model. Compared to LoRA, this increases expressivity for the same trainable parameter count or allows to greatly lower the parameter count without sacrificing expressivity. This comes at the expensive of a higher memory requirement for the same parameter count and decreased speed.

TinyLoRA

We have another serial contributor in @kashif, who also contributed TinyLoRA: "Learning to Reason in 13 Parameters" in #3024. This is a PEFT method that allows to train an extremely small number of parameters, much lower than what could be achieved even with LoRA rank 1. The paper shows that in particular with reinforcement learning, it can often be enough to train just a few parameters to achieve good results.

AdaMSS

@LonglongaaaGo added "AdaMSS: Adaptive Multi-Subspace Approach for Parameter-Efficient Fine-Tuning" to PEFT. This method segments the base weights of the model into smaller subspaces that are targeted for fine-tuning. Moreover, it's possible to dynamically assign a lower parameter budget to less important subspaces during training, similar to what AdaLoRA does. This promises to provide higher expressiveness and better generalization than similar PEFT methods.

Enhancements

Convert non-LoRA adapters to LoRA

In #2939, we added functions to PEFT to allow converting checkpoints of many non-LoRA methods into LoRA checkpoints. This can be useful because many other packages support only LoRA but not other PEFT methods, e.g. Diffusers and vLLM. With the new conversions tools, more PEFT methods than just LoRA can thus be used with those packages. Conversion is lossy but empirical testing showed that with a sufficiently high LoRA rank, the error can be quite low.

LoRA-GA

@sambhavnoobcoder added a new way to initialize LoRA weights with "LoRA-GA: Low-Rank Adaptation with Gradient Approximation" (#2926). This allows you to initialize the LoRA weights in a way that aligns the gradients with full fine-tuning and should lead to faster training convergence.

Reducing intruder dimensions

In "LoRA vs Full Fine-tuning: An Illusion of Equivalence", the authors showed that LoRA fine-tuning can introduce so-called "intruder dimensions" which contribute to forgetting. We now have a utility function to remove intruder dimension in PEFT, reduce_intruder_dimension. When calling this on a fine-tuned LoRA model, forgetting should be reduced while the fine-tuned task performance should remain almost the same.

Transformer Engine

In #3048, @balvisio added support for Transformer Engine, a quantization method by NVIDIA, to PEFT.

Tensor Parallel Support

In a series of PRs (#3079, #3091, #3096), @michaelbenayoun added support for Tensor Parallelism to LoRA.

Weight tying improvements

In many LLMs, the embedding and the LM head have tied weights to save on parameter count. This can, however, lead to tricky situations when trying to fine-tune those layers. Through a series of PRs (#2803, #2922, #2870, #2879, #3126), we improved the user experience when doing so. Most notably, users can now pass ensure_weight_tying=True to their PEFT config to force weight tying to be upheld. Please check the PEFT weight tying docs for how weight tying is now being handled. Thanks to @romitjain, @sambhavnoobcoder, and @Cursx for their contributions.

Low precsion floating type support

#3055 makes LoRA work with base models that use very low precision floats like torch.float8_e4m3fn. An example of that would be MiniMax-M2.5.

Zero init for PrefixTuning

#3128 introduces zero init to Prefix Tuning which, according to our benchmarks, reduced the result variance significantly and yielded good task accuracy without the need for prompt engineering.

LoftQ + int8 quantization

With #3088 the LoftQ implementation now supports correcting errors for int8 quantization without utilizing activation thresholding alongside the already existing nf4 quantization.

Changes

Removal of Bone

The Bone PEFT method was removed in #3115. Users are directed to use MiSS instead, which is the improved replacement for Bone. Use this Bone-to-MiSS conversion script if you want to port old Bone checkpoints.

AutoGPTQ and AutoAWQ

These two quantization methods now use GPTQModel as their backend (#2932) thanks to @ZX-ModelCloud.

Handling of requires_grad in modules_to_save

Previously, PEFT would enable requires_grad on the original module if the corresponding modules_to_save was disabled. This is almost never desirable and was thus fixed. Although this change is technically backwards-incompatible, it's an extreme niche case, so we don't expect any user to be negatively affected by it.
