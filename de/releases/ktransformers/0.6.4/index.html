ktransformers v0.6.4

KTransformers v0.6.4: Leistungsstarke End-to-End-Vollparameter- und LoRA-Feinabstimmung

KTransformers v0.6.4 ist ein wichtiges Upgrade des KT-Feinabstimmungspfads für große MoE-Modelle mit geringer Dichte. Diese Version erweitert KT SFT von der durchgängigen Vollparameter-Feinabstimmung auf LoRA und verbessert gleichzeitig den heterogenen BF16-CPU-GPU-Trainingsdurchsatz und die Speichereffizienz im gesamten Host-RAM und GPU-VRAM.

🚀 Kern-Highlights

  • End-to-End Full-Parameter und LoRA SFT: Trainieren Sie große, spärliche MoE-Modelle mit Full Fine-Tuning, LoRA oder Hybrid-Konfigurationen über den bekannten LLaMA-Factory-Workflow.
  • Hoher Trainingsdurchsatz: In echten End-to-End-Trainingsläufen – nicht in isolierten Kernel-Benchmarks – erreichte KTransformers ungefähr 400 Token/s mit Full-FT und 600 Token/s mit LoRA auf Qwen3-30B-A3B mit 2× AMD EPYC 9355 CPUs und 2× RTX 5090 GPUs. Ein separates LoRA-Setup mit einer RTX 4090 und einer AMX-fähigen CPU hielt mehr als 700 Token/s durch. Die resultierenden Prüfpunkte zeigten auch deutliche Fortschritte bei der End-to-End-Feinabstimmungsvalidierung.
  • DeepSeek V4 auf Ampere-GPUs: BF16-Aufmerksamkeits-Fallbacks und ein FP8-MoE-Marlin-Pfad erweitern die DeepSeek V4-Flash-Unterstützung auf GPUs ohne native FP8-Tensorkerne.
  • RAWINT4-Kompatibilität und Beschleunigung: breitere Packgewichtskompatibilität, AVX-VNNI-256-Expertenladen und ein schnellerer Kimi K2-Vorfüllpfad.
  • Experimentelles Intel iGPU-Backend: neue SYCL-basierte GPTQ INT4 MoE-Inferenzunterstützung für integrierte Intel-GPUs.

📌 Vollparameter, LoRA und Hybrid-SFT

Diese Version vervollständigt den heterogenen KT-CPU-GPU-Trainingsworkflow für große MoE-Modelle mit geringer Dichte:

  • Vollständige Feinabstimmung aktualisiert die von KT verwalteten CPU-Expertengewichte zusammen mit den regulären trainierbaren Parametern des Modells.
  • LoRA deckt reguläre lineare Schichten, Router und Gates sowie verschmolzene MoE-Experten ab.
  • Hybrid-Training ermöglicht das gemeinsame Training von Full-FT- und LoRA-Parametern.
  • Zuverlässiges mehrstufiges Training unterstützt Gradientenakkumulation, Aktivierungs-Checkpointing, verteilte Ausführung, Optimierungsaktualisierungen und Profilerstellung. Der neue Schulungspfad zielt in erster Linie auf die Schulung zum CPU-Experten BF16 KT ab. 👉 Hauptimplementierung: ktransformers PR #2094

📌 DeepSeek V4- und Ampere-GPUs

Die gebündelte sglang-kt-Integration bietet umfassendere DeepSeek V4 Flash- und FP8 MoE-Unterstützung auf Ampere-GPUs:

  • BF16 KV-Cache und Aufmerksamkeits-Fallbacks für GPUs ohne native FP8-Tensorkerne. – FP8 MoE Marlin-Unterstützung für GPU-Experten, GPU-Prefill und dynamische Experten-Updates.
  • Stabilitätskorrekturen für die Planung langer Eingaben, den Start von AMXINT4/8 und die Dequantisierung der FP16 FE8M0-Skala. Verwandte Änderungen: – DeepSeek V4 Flash-Inferenz auf Ampere-GPUs
  • V4 SWA-Token-Pool-Größe korrigieren
  • AMXINT4/8 SwiGLU-Parameterbehandlung behoben – FP8 MoE Marlin für GPU Expert und GPU Prefill
  • FP16 FE8M0 Dequantisierung der Marlin-Skala

📌 RAWINT4-Kompatibilität und Prefill-Beschleunigung

KTransformers v0.6.4 verbessert den RAWINT4 CPU Expert-Pfad mit: – Unterstützung für Prüfpunkte mit komprimierten Tensoren, die gepackte INT4-Gewichte in int32 speichern.

  • Laden von RAWINT4 pro Experte auf AVX-VNNI-256-Systemen.
  • Ein blockierter Matrixmultiplikationspfad für eine schnellere Kimi K2 RAWINT4-Vorfüllung, während der vorhandene Decodierungspfad für kurze Sequenzen beibehalten wird. Verwandte Änderungen:
  • Komprimierte RAWINT4-Gewichte normalisieren
  • AVX-VNNI-256 RAWINT4 pro Experte wird geladen
  • K2 RAWINT4 Vorfüllmatten-Versand

📌 Experimentelles Intel iGPU SYCL Backend

In dieser Version wird ein experimentelles SYCL-Backend für die GPTQ INT4 MoE-Inferenz auf integrierten Intel-GPUs eingeführt. Kompatibilität und Leistung hängen von der Intel-GPU, dem Treiber, der SYCL-Toolchain und der Modellkonfiguration ab. 👉 Intel iGPU SYCL GPTQ INT4 MoE-Backend

🔐 Sicherheit

Der balance_serve-Scheduler bindet seinen ZMQ-ROUTER-Endpunkt jetzt an 127.0.0.1 statt an alle Netzwerkschnittstellen, wodurch die Gefährdung durch nicht authentifizierte Remote-Pickle-Deserialisierung verringert wird.

  • Sicherheitsfix PR #2091
  • GHSA-83vp-v6wg-x93x

📦 Installation

KT SFT

pip install "ktransformers[sft]"

KT SFT verwendet weiterhin den LLaMA-Factory-Schulungseintrag und den YAML-Workflow.

KT-Schlussfolgerung

pip install kt-kernel sglang-kt

Von der Quelle installieren

git clone https://github.com/kvcache-ai/ktransformers.git
cd ktransformers
git submodule update --init --recursive
cd kt-kernel && ./install.sh
cd .. && ./install.sh

CUDA 12.0 oder neuer ist erforderlich. Für einzelne Backends gelten möglicherweise zusätzliche Anforderungen an CPU ISA, GPU-Architektur, Treiber oder Compiler.

ktransformers v0.6.4

KTransformers v0.6.4: High-Performance End-to-End Full-Parameter and LoRA Fine-Tuning

KTransformers v0.6.4 is a major upgrade to the KT fine-tuning path for large sparse MoE models. This release extends KT SFT from end-to-end Full-Parameter Fine-Tuning to LoRA, while improving BF16 CPU-GPU heterogeneous training throughput and memory efficiency across host RAM and GPU VRAM.

🚀 Core Highlights

  • End-to-end Full-Parameter and LoRA SFT: train large sparse MoE models with Full Fine-Tuning, LoRA, or Hybrid configurations through the familiar LLaMA-Factory workflow.
  • High training throughput: in real end-to-end training runs—not isolated kernel benchmarks—KTransformers reached approximately 400 tokens/s with Full-FT and 600 tokens/s with LoRA on Qwen3-30B-A3B using 2× AMD EPYC 9355 CPUs and 2× RTX 5090 GPUs. A separate LoRA setup using one RTX 4090 and an AMX-enabled CPU sustained more than 700 tokens/s. The resulting checkpoints also showed clear gains in end-to-end fine-tuning validation.
  • DeepSeek V4 on Ampere GPUs: BF16 attention fallbacks and an FP8 MoE Marlin path expand DeepSeek V4 Flash support to GPUs without native FP8 Tensor Cores.
  • RAWINT4 compatibility and acceleration: broader packed-weight compatibility, AVX-VNNI-256 expert loading, and a faster Kimi K2 prefill path.
  • Experimental Intel iGPU backend: new SYCL-based GPTQ INT4 MoE inference support for Intel integrated GPUs.

📌 Full-Parameter, LoRA, and Hybrid SFT

This release completes the KT CPU-GPU heterogeneous training workflow for large sparse MoE models:

  • Full Fine-Tuning updates KT-managed CPU expert weights together with the model's regular trainable parameters.
  • LoRA covers regular linear layers, routers and gates, and fused MoE experts.
  • Hybrid training allows Full-FT and LoRA parameters to be trained together.
  • Reliable multi-step training supports gradient accumulation, activation checkpointing, distributed execution, optimizer updates, and profiling.

The new training path primarily targets BF16 KT CPU expert training.

👉 Main implementation: ktransformers PR #2094

📌 DeepSeek V4 and Ampere GPUs

The bundled sglang-kt integration adds broader DeepSeek V4 Flash and FP8 MoE support on Ampere GPUs:

  • BF16 KV-cache and attention fallbacks for GPUs without native FP8 Tensor Cores.
  • FP8 MoE Marlin support for GPU Experts, GPU Prefill, and dynamic expert updates.
  • Stability fixes for long-input scheduling, AMXINT4/8 startup, and FP16 FE8M0 scale dequantization.

Related changes:

  • DeepSeek V4 Flash inference on Ampere GPUs
  • Fix V4 SWA token-pool sizing
  • Fix AMXINT4/8 SwiGLU parameter handling
  • FP8 MoE Marlin for GPU Expert and GPU Prefill
  • FP16 FE8M0 Marlin scale dequantization

📌 RAWINT4 Compatibility and Prefill Acceleration

KTransformers v0.6.4 improves the RAWINT4 CPU Expert path with:

  • Support for compressed-tensors checkpoints that store packed INT4 weights in int32.
  • Per-expert RAWINT4 loading on AVX-VNNI-256 systems.
  • A blocked matrix-multiplication path for faster Kimi K2 RAWINT4 prefill, while keeping the existing decode path for short sequences.

Related changes:

  • Normalize compressed RAWINT4 weights
  • AVX-VNNI-256 per-expert RAWINT4 loading
  • K2 RAWINT4 prefill mat-mat dispatch

📌 Experimental Intel iGPU SYCL Backend

This release introduces an experimental SYCL backend for GPTQ INT4 MoE inference on Intel integrated GPUs. Compatibility and performance depend on the Intel GPU, driver, SYCL toolchain, and model configuration.

👉 Intel iGPU SYCL GPTQ INT4 MoE backend

🔐 Security

The balance_serve scheduler now binds its ZMQ ROUTER endpoint to 127.0.0.1 instead of all network interfaces, reducing exposure to unauthenticated remote pickle deserialization.

  • Security fix PR #2091
  • GHSA-83vp-v6wg-x93x
