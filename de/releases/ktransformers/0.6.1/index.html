ktransformers v0.6.1

KTransformers v0.6.1 ist eine vollständige Umgestaltung und ein großes Upgrade des bestehenden KT-Feinabstimmungspfads für LoRA SFT mit großem MoE. In dieser Version wird das KT SFT-Backend um kt-kernel herum neu erstellt, der SFT-Stack hinter dem ktransformers[sft]-Eintrag gepackt und der LLaMA-Factory-Schulungseintrag und der YAML-Workflow für Benutzer vertraut gehalten. In gemessenen Benchmark-Einstellungen erreicht KT SFT eine Trainingsleistung von 6-12x im Vergleich zur ZeRO-Offload-Basislinie. Unabhängig davon wird die CPU-Speicherauslastung im Vergleich zum vorherigen KT-SFT-Pfad auf etwa 1/2 reduziert, bei geringerer GPU-Speicherauslastung im gleichen Benchmark-Kontext. Diese Ergebnisse hängen mit dem Benchmark-Setup zusammen und sollten zusammen mit Modell, Hardware, Kontextlänge, LoRA-Konfiguration und Baseline-Details gelesen werden.

🚀 Kern-Highlights

  • Umgestaltetes SFT-Backend für große MoE: Neuaufbau des KT-SFT-Pfads um AMX-MoE-Kernel mit LoRA-Unterstützung, einschließlich SFT-spezifischer AMX-Kernel, LoRA-Fused-Add-Tests, Umpacktests, Python-SFT-Wrapper, Autograd-Integration, Layer-Definitionen und Gewichtungshelfer (#1936). – Pip-installierbarer SFT-Stack: ktransformers[sft] installiert jetzt den KT SFT-Stack über reguläre Python-Pakete: ktransformers, kt-kernel, transformers-kt und accelerate-kt.
  • LLaMA-Factory-Workflow-Integration: KT SFT ist für die Verwendung nach der Installation von LLaMA-Factory konzipiert, wobei der Standard-Workflow accelerate launch / src/train.py / YAML erhalten bleibt. Begleiter LLaMA-Factory PR: hiyouga/LLaMA-Factory#10430.
  • Cleaner-Paketgrenze: Das alte kt-sft-Paket wurde archiviert; SFT verwendet jetzt ktransformers[sft], während KT-Inferenz kt-kernel + sglang-kt verwendet (#1954, #1955).
  • Aktuelle Torch-Basislinie: Paketmetadaten und der validierte öffentliche Installationspfad sind auf torch==2.9.1 ausgerichtet, mit torchaudio==2.9.1 und torchvision==0.24.1 für das aktuelle Full-Stack-Setup.

📌 Modelle, Hardware und Werkzeuge

SFT und Verpackung

  • Bereiten Sie die SFT-Radverpackung v0.6.1 auf main vor, einschließlich Aktualisierungen der Verpackung ktransformers[sft], kt-kernel, Aktualisierungen des Release-Workflows und einer leichten Paketunterlage der obersten Ebene (#1945). – Richten Sie kt-kernel und zugehörige Paketmetadaten an der aktuellen Release-Abhängigkeitsbasislinie aus (#1948).
  • Glätten Sie die Unterlegscheibe des ktransformers-Pakets für eine sauberere Radverpackung (#1955). – Archivieren Sie das Legacy-Paket kt-sft unter archive/kt-sft/, damit das aktive Paketlayout leichter nachvollziehbar ist (#1954).

Kernel- und Hardware-Verbesserungen

– AVX512F+BW-Fallback-Unterstützung für FP8 und BF16 unter dem AMX-Backend hinzugefügt, um die CPU-Fallback-Abdeckung zu verbessern, wenn AMX-spezifische Pfade nicht verfügbar sind (#1908). – Fügen Sie VNNI-256-Unterstützung für GPTQ INT4 MoE hinzu, einschließlich eines neuen gptq_int4_avxvnni-Pfads und einer Genauigkeitstestabdeckung pro Commit (#1926). – Fügen Sie SFT-spezifische AMX-MoE-Kernel, tensorparallele MoE-SFT-Helfer, LoRA-Kerneltests, Umpacktests und Python-SFT-Modul-Wrapper hinzu (#1936).

Inferenz und Laufzeitintegration

– Synchronisieren Sie das gebündelte sglang-Submodul für KT-Layer-Prefill-Updates und spätere Paketierungskorrekturen (#1920). – Aktualisieren Sie den SGLang-KT-Release-Workflow, um einen gehosteten Runner zu verwenden, um Release-Blockierungen bei nicht verfügbaren selbst gehosteten Runnern zu vermeiden.

Modellaktivierung

– GLM-5.1-Tutorial und Hinweise zu den Voraussetzungen für den kt-kernel-Pfad hinzufügen (#1916, #1932).

  • Aktualisieren Sie die README- und Modelldokumentationslinks für Kimi-K2.5-, MiniMax-M2.5-, Qwen3.5-, DeepSeek-V3.2- und SFT-Dokumente.

📦 Installation

KT SFT mit LLaMA-Factory

Verwenden Sie einen LLaMA-Factory-Checkout, der die KT-Beispiele und requirements/ktransformers.txt enthält.

cd /path/to/LLaMA-Factory
pip install -e .
pip install -r requirements/ktransformers.txt

Für die direkte Paketinstallation außerhalb dieser Anforderungsdatei:

pip install "ktransformers[sft]"

KT-Schlussfolgerung

Die KT-Inferenz verwendet den SGLang-KT-Pfad:

pip install kt-kernel sglang-kt

Behalten Sie kt-kernel im Inferenzinstallationspfad bei. LLaMA-Factory SFT verwendet weiterhin ktransformers[sft].

Englisches Original / English original

ktransformers v0.6.1

KTransformers v0.6.1 is a full refactor and major upgrade of the existing KT fine-tuning path for large-MoE LoRA SFT. This release rebuilds the KT SFT backend around kt-kernel, packages the SFT stack behind the ktransformers[sft] entry, and keeps the LLaMA-Factory training entry and YAML workflow familiar for users.

In measured benchmark settings, KT SFT reaches 6-12x training performance compared with the ZeRO-Offload baseline. Separately, CPU memory usage is reduced to about 1/2 compared with the previous KT SFT path, with lower GPU memory pressure in the same benchmark context. These results are tied to the benchmark setup and should be read together with the model, hardware, context length, LoRA config, and baseline details.

🚀 Core Highlights

  • Refactored large-MoE SFT backend: rebuilt the KT SFT path around AMX MoE kernels with LoRA support, including SFT-specific AMX kernels, LoRA fused add tests, repacking tests, Python SFT wrappers, autograd integration, layer definitions, and weight helpers (#1936).
  • Pip-installable SFT stack: ktransformers[sft] now installs the KT SFT stack through regular Python packages: ktransformers, kt-kernel, transformers-kt, and accelerate-kt.
  • LLaMA-Factory workflow integration: KT SFT is designed to be used after installing LLaMA-Factory, while preserving the standard accelerate launch / src/train.py / YAML workflow. Companion LLaMA-Factory PR: hiyouga/LLaMA-Factory#10430.
  • Cleaner package boundary: the old kt-sft package has been archived; SFT now uses ktransformers[sft], while KT inference uses kt-kernel + sglang-kt (#1954, #1955).
  • Current torch baseline: package metadata and the validated public install path are aligned on torch==2.9.1, with torchaudio==2.9.1 and torchvision==0.24.1 for the current full-stack setup.

📌 Models, Hardware & Tooling

SFT and Packaging

  • Prepare v0.6.1 SFT wheel packaging on main, including ktransformers[sft], kt-kernel packaging updates, release workflow updates, and a lightweight top-level package shim (#1945).
  • Align kt-kernel and related package metadata with the current release dependency baseline (#1948).
  • Flatten the ktransformers package shim for cleaner wheel packaging (#1955).
  • Archive the legacy kt-sft package under archive/kt-sft/ so the active package layout is easier to reason about (#1954).

Kernel and Hardware Improvements

  • Add AVX512F+BW fallback support for FP8 and BF16 under the AMX backend, improving CPU fallback coverage where AMX-specific paths are unavailable (#1908).
  • Add VNNI-256 support for GPTQ INT4 MoE, including a new gptq_int4_avxvnni path and per-commit accuracy test coverage (#1926).
  • Add SFT-specific AMX MoE kernels, tensor-parallel MoE SFT helpers, LoRA kernel tests, repacking tests, and Python SFT module wrappers (#1936).

Inference and Runtime Integration

  • Sync the bundled sglang submodule for KT layerwise prefill updates and later packaging fixes (#1920).
  • Update SGLang-KT release workflow to use a hosted runner, avoiding release blocking on unavailable self-hosted runners.

Model Enablement

  • Add GLM-5.1 tutorial and prerequisite notes for the kt-kernel path (#1916, #1932).
  • Refresh README and model documentation links for Kimi-K2.5, MiniMax-M2.5, Qwen3.5, DeepSeek-V3.2, and SFT docs.

📦 Installation

KT SFT with LLaMA-Factory

Use a LLaMA-Factory checkout that contains the KT examples and requirements/ktransformers.txt.

cd /path/to/LLaMA-Factory
pip install -e .
pip install -r requirements/ktransformers.txt

For direct package installation outside that requirements file:

pip install "ktransformers[sft]"

KT Inference

KT inference uses the SGLang-KT path:

pip install kt-kernel sglang-kt

Keep kt-kernel in the inference installation path. LLaMA-Factory SFT continues to use ktransformers[sft].

  • Refresh KT installation commands and package boundaries in README / README_ZH and SFT docs (#1958).
  • Add GOSIM 2026 announcement and update roadmap link to Q2 (#1937).

🐛 Bug Fixes

  • Revert the CPUInfer stream bridge for ROCm after compatibility concerns (#1918, #1925).
