ktransformers v0.7.0.post4

KTransformers 0.7.0.post4

Kimi K2.5-Text-LoRA-Schulung, Checkpoint-Lebenslauf und Laden des SGLang-Adapters mit nativen RAWINT4-Routing-Experten.

Python 3.11 / 3.12-Installation

Beginnen Sie mit der Schritt-für-Schritt-Anleitung und dem r2-Benutzerkit. Überprüfen Sie SHA256SUMS-r2.txt, bevor Sie es extrahieren. Der aktualisierte Leitfaden ist in PR #2207 nachverfolgt. Das Kit enthält drei YAMLs, Datenvorbereitungs- und LoRA-Konvertierungstools sowie separate Abhängigkeitssperren Python 3.11 / 3.12. Nur Modell- und Ausgabepfade müssen geändert werden. Kernpakete werden von PyPI installiert; Das zugelassene LF-Zweigrad und die Nur-Metadaten-PEFT/TRL-Räder sind im Lieferumfang des Kits enthalten. Installieren Sie in diesen Umgebungen keine überlappenden Transformers/Accelerate-Upstream-Pakete.

  • Linux x86_64, glibc 2.35+, Python 3.11 oder 3.12, CUDA 12.8, Torch 2.9.1.
  • Validierte Hardware: Dual AMD EPYC 9355, ca. 1.5 TiB RAM; 8 RTX 5090-GPUs für das Training und 4 für Inferenz. Dies ist kein Anspruch auf Mindestanforderungen.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4; Transformatoren-kt 5.6.0.post5; beschleunigt-kt 1.14.0.post3.
  • Das Packen ist deaktiviert. Verwenden Sie das angeheftete Originalmodell und den expliziten Datenvorbereitungsschritt. Hosts ohne Hugging Face-Zugriff müssen die angehefteten Modell-/Daten-Snapshots separat erhalten. Die Ergänzung vom 14. September fügt ein echtes CPython 3.11-Laufrad hinzu, einschließlich passender nativer Bindungen. Vorhandene Versionen, die Originaldateien für fünf Räder und das R1-Kit bleiben unverändert. Python 3.11 erfordert r2; Verwenden Sie die Sperrdateien r1 Python 3.12 nicht wieder und benennen Sie ein cp312-Rad nicht um. Wenn ein Spiegel die neue Datei nicht synchronisiert hat, verwenden Sie den offiziellen PyPI-Index.

Validierung und Umfang

Separate saubere Kandidatenumgebungen Python, 3.11 und 3.12 haben das Kimi-Basistraining bestanden, einen bitgenauen Neuprozess-Lebenslauf über 20 Zustandsvergleiche hinweg, eine gewöhnliche/Experten-LoRA-Konvertierung und eine neue SGLang-Generierung mit allen 60 Experten-LoRA-Ebenen geladen. Der unabhängige Umbau des gefrorenen Hauptteils Python 3.12 wurde ebenfalls bestanden. Kandidatennachweise und eingefrorene Quellenangaben sind in r2 enthalten. Der ursprüngliche öffentliche PyPI-Lebenszyklus Python 3.12 endete am 13. September; siehe PUBLIC_WHEEL_VERIFICATION.json. Die R2-Installation und Lebenszyklusüberprüfung nach der Veröffentlichung läuft jetzt; Die alleinige Veröffentlichung gilt nicht als Abschluss dieser Prüfung. Der separat trainierte Neko Checkpoint-100 wurde in beiden Python-Versionen neu geladen und vervollständigte 32 vorgehaltene Antworten pro Version mit passendem Text. Es zeigt den beabsichtigten Stil an, besteht jedoch einige strenge Format- und Inhaltsqualitätsprüfungen nicht. Das Rauchtraining in vier Schritten ist kein vollständiges Stil-Konvergenz-Experiment oder eine allgemeine Qualitäts-/Sicherheitsgarantie. Die Validierung früherer Versionen umfasste Qwen3-30B-A3B BF16-Training/Inferenz, DeepSeek-V3.1 natives FP8-Training und vom Benutzer festgelegte GLM Next-0808-Textinferenz; diese wurden für diese Python-Ergänzung nicht wiederholt. K2.5 ist hardwarevalidiert. Der gemeinsame Architekturpfad von K2.6 wurde nicht separat auf Hardware getestet. Sehtraining, andere Architekturen und beliebige Sequenzlängen werden hier nicht zertifiziert. Die ursprüngliche Quellenäquivalenz bleibt in main-equivalence.json aufgezeichnet. Unabhängig umgebaute Räder derselben Version ersetzen keine veröffentlichten Artefakte.

ktransformers v0.7.0.post4

KTransformers 0.7.0.post4

Kimi K2.5 text LoRA training, checkpoint resume, and SGLang adapter loading with native RAWINT4 routed experts.

Python 3.11 / 3.12 installation

Start with the step-by-step guide and the r2 user kit. Check SHA256SUMS-r2.txt before extracting it. The updated guide is tracked in PR #2207.

The kit contains three YAMLs, data preparation and LoRA conversion tools, and separate Python 3.11 / 3.12 dependency locks. Only model and output paths need changing. Core packages install from PyPI; the approved LF branch wheel and metadata-only PEFT/TRL wheels are bundled with the kit. Do not install overlapping upstream Transformers/Accelerate packages into these environments.

  • Linux x86_64, glibc 2.35+, Python 3.11 or 3.12, CUDA 12.8, Torch 2.9.1.
  • Validated hardware: dual AMD EPYC 9355, approximately 1.5 TiB RAM; 8 RTX 5090 GPUs for training and 4 for inference. This is not a minimum-spec claim.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4; transformers-kt 5.6.0.post5; accelerate-kt 1.14.0.post3.
  • Packing is disabled. Use the pinned original model and explicit data-preparation step. Hosts without Hugging Face access must obtain the pinned model/data snapshots separately.

The September 14 supplement adds one real CPython 3.11 wheel, including matching native bindings. Existing versions, the original five wheel files, and the r1 kit are unchanged. Python 3.11 requires r2; do not reuse the r1 Python 3.12 lock files or rename a cp312 wheel. If a mirror has not synchronized the new file, use the official PyPI index.

Validation and scope

Separate Python 3.11 and 3.12 clean candidate environments passed Kimi base training, bit-exact new-process resume across 20 state comparisons, ordinary/expert LoRA conversion, and fresh SGLang generation with all 60 expert-LoRA layers loaded. The independent frozen-main Python 3.12 rebuild also passed. Candidate evidence and frozen source references are included in r2.

The original Python 3.12 public-PyPI lifecycle passed on September 13; see PUBLIC_WHEEL_VERIFICATION.json. Post-publication r2 installation and lifecycle verification is now running; publication alone is not reported as completion of that check.

The separately trained Neko checkpoint-100 was reloaded in both Python versions and completed 32 held-out answers per version with matching text. It displays the intended style, but still fails some strict-format and content-quality checks. Four-step smoke training is not a full style-convergence experiment or a general-quality/safety guarantee.

Earlier release validation covered Qwen3-30B-A3B BF16 training/inference, DeepSeek-V3.1 native FP8 training, and user-designated GLM next-0808 text inference; these were not repeated for this Python supplement. K2.5 is hardware-validated. K2.6's shared architecture path was not separately hardware-tested. Vision training, other architectures, and arbitrary sequence lengths are not certified here.

Original source equivalence remains recorded in main-equivalence.json. Same-version independently rebuilt wheels do not replace published artifacts.
