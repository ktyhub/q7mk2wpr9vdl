agno v2.9.0

Changelog

Neue Funktionen

  • StudioRunnerTools: Neues identitätsbewusstes Dispatch-Toolkit (agno.tools.studio_runner.StudioRunnerTools), das die Ausführung von StudioTools aufteilt. Jede Komponente (Teamleiter, Router) kann es bereitstellen, um in Studio erstellte Agenten/Teams/Workflows zu erkennen und auszuführen, ohne die Oberfläche zum Erstellen/Bearbeiten/Löschen von Studio zu erhalten. run_*-Tools fädeln die user_id des Anrufers in den Unterlauf ein, sodass der Status pro Benutzer bei der richtigen Person landet.
  • list_components-Namensfilter: Ein name-Filter wurde zu list_components hinzugefügt.

Fehlerbehebungen

  • A2A: Der A2A-Stream client hat das Löschen von Metadaten auf Aufgabenebene behoben, indem er bei der Statusaktualisierung unterbrochen wurde.
  • Workflow (WebSocket): Berücksichtigen Sie die ausgewählte Workflow-Version über WebSocket.
  • Team HITL: Angehaltene Mitgliedsläufe bleiben erhalten, damit die HITL-Wiederaufnahme des Teams ein erneutes Laden der Sitzung übersteht.
  • Rehydrierung: Bewahren Sie die Anweisungen des Toolkits zur Rehydrierung auf.
  • Framework-Anmerkungen: Guard-Framework-Rückgabeanmerkungen.

Verhalten und bahnbrechende Änderungen

– Überschreibung des MCP-Tools tool_name blockiert (Sicherheit): MCP-Tool-Einstiegspunkte erlauben keine Überschreibung der Anrufzeit tool_name mehr. Zuvor konnte ein Modell tool_name="delete_repo" an jedes MCP-Tool übergeben und der Server führte dieses Tool aus, während Zulassungslisten, requires_confirmation, HITL-Genehmigung und Protokollierung alle vom deklarierten Namen aufgelöst wurden – und umging dabei jedes HITL-/Genehmigungstor. Der Name des ausgeführten Tools wird jetzt von tool.name geschlossen. Vom Modell bereitgestellte tool_name-Argumente werden als gewöhnliche Argumente weitergeleitet (nicht zur Auswahl des Tools verwendet), sodass Tools, die einen tool_name-Parameter legitim deklarieren, weiterhin funktionieren.

  • Tool-Ergebnis-Caching verwendet jetzt benutzerspezifische Schlüssel (Sicherheits-/Verhaltensänderung): Mit cache_results=True enthält der Cache-Schlüssel jetzt eine stabile Ausführungskontextidentität (user_id, session_id), wodurch ein benutzerübergreifendes Cache-Leck behoben wird, bei dem ein zwischengespeichertes Tool, das run_context nimmt (z. B. MemoryTools), das Ergebnis eines Benutzers an einen anderen weiterleitete. run_id bleibt außerhalb des Schlüssels, sodass das Caching über die gesamten Läufe eines Benutzers hinweg nützlich bleibt. Bestehende Cache-Verhaltensänderungen – Schlüssel sind anders zusammengesetzt, sodass frühere Cache-Treffer nicht auf die gleiche Weise ausgerichtet werden. – Rehydrierung schlägt jetzt lautstark fehl (Verhaltensänderung): Deserialisieren einer persistenten Komponente mit nicht auflösbaren Referenzen, die zum stillen Herabsetzen verwendet wurde (die Tools eines Agenten wurden zu [], ein Team verlor Mitglieder, Schemata/Wissen wurden gelöscht) und dann ausgeführt. Nicht auflösbare Verweise lösen jetzt ComponentRehydrationError (an AgnoError, status_code=422) auf strengen Pfaden aus. Strenge ist eine Aufrufeigenschaft: public from_dict/load default strict=False (Roundtrips funktionieren weiterhin), aber AgentOS-Lookups und jeder Versandpfad (REST POST /runs, Weiter, MCP-Ausführungstools, StudioRunner) sind standardmäßig strict=True und geben jetzt einen 422 zurück, der das nicht auflösbare Teil benennt, anstatt eine beeinträchtigte Komponente auszuführen. Angepinnte Mitgliederversionen werden ebenfalls berücksichtigt.

Englisches Original / English original

agno v2.9.0

Highlights

  • Security: MCP tool_name override no longer bypasses approval gates — Previously a model could pass tool_name="delete_repo" to any MCP tool and have the server execute it while allow-lists, requires_confirmation, HITL approval, and logging all resolved from the declared name — a complete approval bypass. The executed name is now closed over from tool.name; model-supplied tool_name args are forwarded as ordinary arguments, so tools that legitimately declare a tool_name parameter still work. Anyone exposing MCP tools with confirmation/HITL should upgrade immediately — no migration unless you relied on overriding the tool at call time (PR #9379).
  • Security: tool result caching keys now include user identity (breaking cache behaviour) — With cache_results=True, the key now includes stable run-context identity (user_id, session_id) but deliberately not run_id, fixing a cross-user leak where a cached tool taking run_context (e.g. MemoryTools) served one user's result to another. Migration note: keys are composed differently, so prior cache entries won't line up — expect a cold-cache period after upgrading.
  • Rehydration now fails loudly on unresolved references (breaking behaviour) — Deserializing a persisted component with unresolvable references used to silently degrade (tools became [], teams lost members, schemas/knowledge dropped) and then run. It now raises ComponentRehydrationError (an AgnoError, status_code=422). Strictness is a caller property: public from_dict/load default strict=False so round-trips keep working, but AgentOS lookups and every dispatch path — REST POST /runs, continue, MCP run tools, StudioRunner — default strict=True and return a 422 naming the unresolvable piece instead of running a degraded component; pinned member versions are now honored. Validate persisted components before upgrading dispatch-heavy deployments (PR #9381).
  • New StudioRunnerTools for identity-aware dispatch — agno.tools.studio_runner.StudioRunnerTools splits execution out of StudioTools, letting any component (team lead, router) discover and run Studio-built agents/teams/workflows without gaining the create/edit/delete surface; run_* tools thread the caller's user_id into the sub-run so per-user state lands on the right person. Also adds a name filter to list_components. Relevant if you compose Studio components into teams or routers; a no-op for everyone else (PR #9371).
  • Verdict: security-driven upgrade, few reasons to skip — Upgrade promptly if you use MCP tools with confirmation/HITL, cache_results=True (multi-tenant leakage), or AgentOS/StudioRunner dispatch paths (new 422s); budget a cache cold-start and a check of persisted references. The remainder are incremental fixes worth having but not blockers: A2A stream client preserving Task-level metadata, WebSocket honoring the selected workflow version, team HITL resume surviving session reload via persisted paused member runs, toolkit instructions preserved on rehydration, and guarded framework return annotations. No release-specific reason to stay on v2.8.7 given the approval-bypass fix.

Changelog

New Features

  • StudioRunnerTools: New identity-aware dispatch toolkit (agno.tools.studio_runner.StudioRunnerTools) that splits execution out of StudioTools. Any component (team lead, router) can mount it to discover and run Studio-built agents/teams/workflows without getting the Studio's create/edit/delete surface. run_* tools thread the caller's user_id into the sub-run so per-user state lands on the right person.
  • list_components name filter: Added a name filter to list_components.

Bug Fixes

  • A2A: Fixed the A2A stream client dropping Task-level metadata by breaking on status-update.
  • Workflow (WebSocket): Honor the selected workflow version over WebSocket.
  • Team HITL: Persist paused member runs so team HITL resume survives a session reload.
  • Rehydration: Preserve toolkit instructions on rehydration.
  • Framework annotations: Guard framework return annotations.

Behaviour & Breaking Changes

  • MCP tool tool_name override blocked (Security): MCP tool entrypoints no longer allow a call-time tool_name override. Previously a model could pass tool_name="delete_repo" to any MCP tool and the server would execute that tool while allow-lists, requires_confirmation, HITL approval, and logging all resolved from the declared name — bypassing any HITL/approval gate. The executed tool name is now closed over from tool.name. Model-supplied tool_name args are forwarded as ordinary arguments (not used to pick the tool), so tools that legitimately declare a tool_name parameter keep working.
  • Tool result caching now uses per-user keys (Security / behaviour change): With cache_results=True, the cache key now includes stable run-context identity (user_id, session_id), fixing a cross-user cache leak where a cached tool taking run_context (e.g. MemoryTools) served one user's result to another. run_id stays out of the key so caching remains useful across a user's runs. Existing cache behaviour changes — keys are composed differently, so prior cache hits won't line up the same way.
  • Rehydration now fails loudly (behaviour change): Deserializing a persisted component with unresolvable references used to silently degrade (an agent's tools became [], a team lost members, schemas/knowledge dropped) and then run. Unresolvable references now raise ComponentRehydrationError (an AgnoError, status_code=422) on strict paths. Strictness is a caller property: public from_dict/load default strict=False (round-trips keep working), but AgentOS lookups and every dispatch path (REST POST /runs, continue, MCP run tools, StudioRunner) default strict=True and now return a 422 naming the unresolvable piece instead of running a degraded component. Pinned member versions are also honored.
