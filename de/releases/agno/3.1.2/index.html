agno v3.1.2

Changelog

Neue Funktionen:

  • Konversationskomprimierung: Agent(compaction=True) hält lange Sitzungen im Kontextfenster, indem ältere Konversationen in eine Zusammenfassung gefaltet werden. Gespeicherte Nachrichten werden nie neu geschrieben: Ein CompactionRecord in der neuen agno_compactions-Tabelle steuert eine abgeleitete Modellnutzlast, sodass durch Entfernen des Datensatzes die vollständige Konversation wiederhergestellt wird. Mit Compaction(model=..., compact_at_tokens=..., uncompacted_runs=...) abstimmen, bei Bedarf mit agent.compact() / acompact() falten und run.compaction prüfen. Mit searchable=True erhält der Agent ein search_compacted_history-Tool, ein Regex-Grep über das archivierte Transkript. Siehe Kochbuch. (#9873)
  • Externer Codex-Agent: CodexAgent hinzugefügt, ein Adapter für OpenAI Codex, der auf dem openai-codex SDK basiert, zusammen mit den Claude Agent SDK-, LangGraph-, DSPy- und Antigravity-Adaptern. Codex führt seine eigene Agentenschleife aus; Der Adapter übersetzt seine Benachrichtigungen in Agno-Ausführungs- und Toolaufrufereignisse, ordnet jede Agno-Sitzung einem Codex-Thread zu (der bestehen bleibt, wenn ein db festgelegt ist) und stellt sandbox, approval_mode, reasoning_effort, output_schema und die MCP-Konfiguration bereit. Funktioniert eigenständig und über AgentOS. Siehe Kochbuch. (#10901)
  • HyDE-Abfragetransformation: QueryTransformer als neuer Abruf-Hook und HyDE als erste Implementierung hinzugefügt: Knowledge(vector_db=..., query_transformer=HyDE()) sucht mit einer hypothetischen Antwort anstelle der Rohfrage, während Reranker immer noch anhand der ursprünglichen Abfrage punkten. HyDE verwendet sein eigenes model, dann das Modell des anrufenden Agenten oder Teams und dann den Framework-Standard. Siehe Kochbuch. (#10527)
  • Browser-Ursprungsrichtlinie: AgentOS(cors=CORSConfig(origins=..., origin_regex=..., merge_base_app=...)) und Opt-in PublicSurface(enforce_browser_origins=True) hinzugefügt. Eine Ursprungsrichtlinie wird jetzt von CORS-Preflights, der öffentlichen Ausführungs- und Löschzulassung, Authentifizierungsfehler-Headern, Workflow-WebSockets und MCP-Aliasnamen gemeinsam genutzt, und CORS ist die äußerste Middleware, sodass Fehlerantworten konsistente Header tragen. cors_allowed_origins behält sein bestehendes Verhalten bei. Siehe Kochbuch. (#10869)
  • Konfigurierbare Follow-ups: followups: bool | FollowupConfig für Agent und Team. FollowupConfig legt einen Zählbereich (num_followups oder min_followups / max_followups), ein separates Modell und benutzerdefinierte Anweisungen fest, die nur für den Folgeanruf gelten. Die Standardeingabeaufforderung bleibt jetzt innerhalb der Antwortgrenzen und bietet einer Anfrage nicht mehr die Antwort declined erneut an. Bestehende num_followups-Anrufer bekommen immer wieder genau N Vorschläge. Siehe Kochbuch. (#10087)
  • Heabsy: Heabsy als OpenAI-kompatibler Modellanbieter hinzugefügt, auch als "heabsy:<model>" auflösbar. Siehe Kochbuch. (#10828)
  • FlexAI: FlexAI als OpenAI-kompatibler Modellanbieter für Open-Weight-Modelle hinzugefügt, auch als "flexai:<model>" auflösbar. Siehe Kochbuch. (#10871)
  • SixtyDBTools: Neues Toolkit für die 60-dB-gehostete Sprache API: Entdecken Sie Stimmen im Arbeitsbereich und generieren Sie Sprache als WAV-Audioartefakte. Siehe Kochbuch. (#10786)

Verbesserungen:

  • Seitensynchronisierungsprotokolle: Die Seitensynchronisierung protokolliert jetzt Sperrwartezeiten, Erkennung, Fortschritt alle 25 Seiten und Endzählungen, sodass lange Synchronisierungen den Fortschritt ohne einen benutzerdefinierten Rückruf anzeigen. Es wurde ein AgentOS-Kochbuch hinzugefügt, das die Dokumentation mit PostgreSQL-gestützten Wissensseiten synchronisiert und sie über das Dateisystem des Agenten verfügbar macht. Siehe Kochbuch. (#10868)
  • OpenAIResponses & OpenRouterResponses: Erkennen Sie GPT-6 (OpenAI) und GPT-5/6 (OpenRouter) als Reasoning-Modelle, sodass Reasoning-State-Chaining und verschlüsselte Reasoning-Wiedergabe angewendet werden und Werkzeugaufruf-Nachverfolgungen nicht mehr mit fehlenden Reasoning-Item-Fehlern fehlschlagen. (#10830)
  • PerplexitySearch: Anfragen senden jetzt einen X-Pplx-Integration: agno-Header, damit Perplexity den Datenverkehr von der Integration zuordnen kann. (#10827)

Fehlerbehebungen:

  • Genehmigungen: Jeder @approval-Tool-Aufruf in einem Lauf erhält jetzt seinen eigenen Genehmigungsdatensatz für Agenten und Teams. Zuvor wurde bei einer zweiten Pause im selben Lauf kein Datensatz erstellt und bei der nächsten Fortsetzung wurde der neue Anruf entgegen der für den ersten festgelegten Genehmigung ausgeführt. (#10812)
  • Modellantwort-Cache: Pydantic output_schema-Klassen werden durch ihr JSON-Schema statt durch ihren Klassennamen kodiert, sodass zwei Schemas mit demselben Namen, aber unterschiedlichen Feldern keine zwischengespeicherte Antwort mehr gemeinsam nutzen. (#10621)
  • Nutzungsmetriken: MessageMetrics.cache_write_tokens wird jetzt aus der Nutzung von OpenAI Chat Completions and Responses (#10313) und aus LiteLLMs prompt_tokens_details (#10476) gefüllt. Bisher war es immer Null.
  • JsonDb: Tabellen werden in eine Staging-Datei serialisiert und mit os.replace veröffentlicht, sodass bei einem fehlgeschlagenen Schreibvorgang die zuletzt erfolgreich gespeicherte Tabelle lesbar bleibt und nicht eine abgeschnittene Datei. (#10794)
  • MongoDb & MongoVectorDb: session_name, search_content und Schlüsselwortsuchfilter sind mit Regex-Escapezeichen versehen, sodass ein Wert wie (draft nicht mehr HTTP 500 von GET /sessions und GET /memories zurückgibt und v1.2 nicht mehr mit v1x2 übereinstimmt. (#10709)
  • Tool-Schemas: Annotated[T, ...]-Hinweise werden vor der JSON-Schemagenerierung in T entpackt, anstatt in ein leeres Objektschema zu gelangen. (#10858)
  • SQLTools: Verbindungs-URLs werden mit URL.create erstellt, sodass ein Passwort wie p@ssword nicht mehr in Passwort p und Host ssword@... aufgeteilt wird. (#10800)
  • FileTools: replace_file_chunk lehnt negative, umgekehrte und außerhalb der Grenzen liegende Zeilenbereiche mit einem Fehler ab und lässt die Datei unberührt; Bei einer gültigen Ersetzung bleibt der nachfolgende Zeilenumbruch erhalten. (#10798)
  • GoogleCalendarTools: find_available_slots vergleicht das Ende des gesamten Slots mit der Schließungszeit am Startdatum, sodass ein 45-Minuten-Slot nicht mehr um 16:30 Uhr für einen Abschluss um 17:00 Uhr angeboten wird und Slots nicht über Mitternacht hinausgehen können. (#10878)
  • BaiduSearchTools, Searxng & SpiderTools: Ein explizites max_results=0 / fixed_max_results=0 bedeutet jetzt keine Ergebnisse, anstatt auf den Standardwert zurückzugreifen. (#10877)
  • Leser: TextReader, MarkdownReader (#10779) und JSONReader (#10634) akzeptieren Streams, deren name eine Ganzzahl oder None ist, wie z. B. deskriptorgestützte temporäre Dateien, anstatt nichts zurückzugeben oder einen Anstieg zu verursachen.
  • Kochbücher: Der DynamoDb-Importpfad in der DynamoDB-Speicher-README-Datei wurde korrigiert. (#10788)

agno v3.1.2

Highlights

  • Conversation compaction without losing history — Enable Agent(compaction=True) to fold older turns into a derived model payload while preserving stored messages; deleting the CompactionRecord from agno_compactions restores the full conversation. Thresholds and retained context are configurable, searchable=True adds regex-based archive search, and agent.compact() supports manual control (#9873).
  • Codex as an external agent — CodexAgent delegates execution to Codex’s own loop while translating notifications into Agno events, so tool execution and approvals remain governed by Codex. Each Agno session maps to a Codex thread, persisted when a database is configured; sandbox, approval, reasoning, schema, and MCP settings need explicit review before exposing it through AgentOS (#10901).
  • Unified browser-origin enforcement — AgentOS now shares one origin policy across CORS, run and cancel admission, authentication error headers, workflow WebSockets, and MCP aliases. Adopters should test browser clients and MCP aliases against enforce_browser_origins=True; the existing cors_allowed_origins behavior remains unchanged (#10869).
  • Retrieval and follow-up controls — Knowledge(query_transformer=HyDE()) searches using a generated hypothetical answer while rerankers still evaluate the original query, at the cost of an extra model call. followups: FollowupConfig supports bounded counts, separate models, and call-specific instructions; legacy num_followups=N still returns exactly N suggestions (#10527, #10087).
  • New model and tool integrations — Heabsy and FlexAI can be selected directly or through "heabsy:<model>" / "flexai:<model>", while SixtyDBTools adds hosted voice discovery and WAV generation (#10828, #10871, #10786).
  • Correctness and observability fixes worth adopting — Repeated @approval pauses now receive separate records (#10812), model caching includes the output schema to prevent cross-schema collisions (#10621), cache-write usage metrics are populated for OpenAI and LiteLLM (#10313, #10476), and JsonDb writes publish atomically to protect saved tables (#10709).
  • No breaking changes are listed.

Changelog

New Features:

  • Conversation Compaction: Agent(compaction=True) keeps long sessions inside the context window by folding older turns into a summary. Stored messages are never rewritten: a CompactionRecord in the new agno_compactions table drives a derived model payload, so removing the record restores the full conversation. Tune with Compaction(model=..., compact_at_tokens=..., uncompacted_runs=...), fold on demand with agent.compact() / acompact(), and inspect run.compaction. With searchable=True the agent gets a search_compacted_history tool, a regex grep over the archived transcript. See cookbook. (#9873)
  • Codex External Agent: Added CodexAgent, an adapter for OpenAI Codex built on the openai-codex SDK, alongside the Claude Agent SDK, LangGraph, DSPy and Antigravity adapters. Codex runs its own agent loop; the adapter translates its notifications into Agno run and tool-call events, maps each Agno session to one Codex thread (persisted when a db is set), and exposes sandbox, approval_mode, reasoning_effort, output_schema and MCP config. Works standalone and through AgentOS. See cookbook. (#10901)
  • HyDE Query Transform: Added QueryTransformer as a new retrieval hook and HyDE as its first implementation: Knowledge(vector_db=..., query_transformer=HyDE()) searches with a hypothetical answer instead of the raw question, while rerankers still score against the original query. HyDE uses its own model, then the calling agent or team's model, then the framework default. See cookbook. (#10527)
  • Browser Origin Policy: Added AgentOS(cors=CORSConfig(origins=..., origin_regex=..., merge_base_app=...)) and opt-in PublicSurface(enforce_browser_origins=True). One origin policy is now shared by CORS preflights, public run and cancel admission, auth error headers, workflow WebSockets and MCP aliases, and CORS is the outermost middleware so error responses carry consistent headers. cors_allowed_origins keeps its existing behaviour. See cookbook. (#10869)
  • Configurable Follow-ups: followups: bool | FollowupConfig on Agent and Team. FollowupConfig sets a count range (num_followups or min_followups / max_followups), a separate model and custom instructions that go only to the follow-up call. The default prompt now stays within the answer's boundaries and no longer re-offers a request the answer declined. Existing num_followups callers keep getting exactly N suggestions. See cookbook. (#10087)
  • Heabsy: Added Heabsy as an OpenAI-compatible model provider, also resolvable as "heabsy:<model>". See cookbook. (#10828)
  • FlexAI: Added FlexAI as an OpenAI-compatible model provider for open-weight models, also resolvable as "flexai:<model>". See cookbook. (#10871)
  • SixtyDBTools: New toolkit for the 60db hosted speech API: discover workspace voices and generate speech as WAV audio artifacts. See cookbook. (#10786)

Improvements:

  • Page Sync Logs: Page synchronization now logs lock waits, discovery, progress every 25 pages and final counts, so long syncs show progress without a custom callback. Added an AgentOS cookbook that syncs documentation into PostgreSQL-backed knowledge pages and exposes them through the agent's filesystem. See cookbook. (#10868)
  • OpenAIResponses & OpenRouterResponses: Recognise GPT-6 (OpenAI) and GPT-5/6 (OpenRouter) as reasoning models, so reasoning-state chaining and encrypted reasoning replay apply and tool-call follow-ups no longer fail with missing reasoning-item errors. (#10830)
  • PerplexitySearch: Requests now send an X-Pplx-Integration: agno header so Perplexity can attribute traffic from the integration. (#10827)

Bug Fixes:

  • Approvals: Each @approval tool call in a run now gets its own approval record, for agents and teams. Previously a second pause in the same run created no record and the next continue ran the new call against the approval resolved for the first one. (#10812)
  • Model Response Cache: Pydantic output_schema classes are keyed by their JSON schema instead of their class name, so two schemas with the same name but different fields no longer share a cached response. (#10621)
  • Usage Metrics: MessageMetrics.cache_write_tokens is now populated from OpenAI Chat Completions and Responses usage (#10313) and from LiteLLM's prompt_tokens_details (#10476). Previously it was always zero.
  • JsonDb: Tables are serialized to a staging file and published with os.replace, so a failed write leaves the last successfully saved table readable instead of a truncated file. (#10794)
  • MongoDb & MongoVectorDb: session_name, search_content and keyword-search filters are regex-escaped, so a value like (draft no longer returns HTTP 500 from GET /sessions and GET /memories, and v1.2 no longer matches v1x2. (#10709)
  • Tool Schemas: Annotated[T, ...] hints are unwrapped to T before JSON schema generation instead of falling through to an empty object schema. (#10858)
  • SQLTools: Connection URLs are built with URL.create, so a password like p@ssword is no longer split into password p and host ssword@.... (#10800)
  • FileTools: replace_file_chunk rejects negative, reversed and out-of-bounds line ranges with an error and leaves the file untouched; a valid replacement preserves the trailing newline. (#10798)
  • GoogleCalendarTools: find_available_slots compares the full slot end against closing time on its start date, so a 45 minute slot is no longer offered at 16:30 for a 17:00 close and slots cannot cross midnight. (#10878)
  • BaiduSearchTools, Searxng & SpiderTools: An explicit max_results=0 / fixed_max_results=0 now means no results instead of falling back to the default. (#10877)
  • Readers: TextReader, MarkdownReader (#10779) and JSONReader (#10634) accept streams whose name is an integer or None, such as descriptor-backed temporary files, instead of returning nothing or raising.
  • Cookbooks: Fixed the DynamoDb import path in the DynamoDB storage README. (#10788)
