Changelog

Neue Funktionen:

  • Benutzerdefinierte, bereichsbezogene, identitätsbewusste MCP-Tools: Der AgentOS MCP-Server (bereitgestellt unter /mcp) ist jetzt ein echter Erweiterungspunkt, der über ein einzelnes MCPServerConfig-Objekt konfiguriert wird. Sie können benutzerdefinierte Tools registrieren (einfache Callables oder Agno @tool/Functions), die integrierten Funktionen festlegen (enable_builtin_tools=False oder mit include_tags/exclude_tags filtern), die authentifizierte Anruferidentität in ein Tool einfügen (user_id deklarieren und AgentOS stellt das JWT-Subjekt bereit, während es vor dem client-Schema ausgeblendet wird), Aufrufe mit einer einzeiligen Autorisierungsfunktion blockieren und sich für den integrierten DNS-Rebinding-Schutz entscheiden erlaubte_hosts/erlaubte_origins. Alles mit Daten, keine benutzerdefinierten Middleware-Klassen. Vollständig abwärtskompatibel: Ohne mcp_config registrieren sich alle integrierten Tools genau wie zuvor.

Fehlerbehebungen:

  • Zusammenführung von Call-Site-Abhängigkeiten: Call-Site-Abhängigkeiten, die an agent.run()/team.run() übergeben wurden, ersetzten die konfigurierten Agent.dependencies/Team.dependencies im Großen und Ganzen, wodurch Prompt-Template-Variablen über Schnittstellen gelöscht wurden, die immer Call-Site-Abhängigkeiten übergeben (z. B. Slack/WhatsApp). Sie führen jetzt zusammen ({**configured, **call_site}, Call-Site gewinnt bei Konflikt) und stimmen damit überein, wie metadata/knowledge_filters bereits zusammengeführt werden.

agno v2.6.15

Highlights

  • AgentOS /mcp becomes a real extension point (PR #8404) — The server at /mcp is now configured through a single MCPServerConfig object instead of being a fixed built-in toolset. You can register your own tools (plain callables or Agno @tool/Functions objects) on that same endpoint, letting consumers reach domain-specific capabilities without a second server or custom middleware classes — the entire surface is data-driven.

  • Scoping the built-ins — enable_builtin_tools=False disables built-ins outright, or include_tags/exclude_tags filter them. This matters because you previously had to accept every built-in to use /mcp; you can now ship a least-privilege tool surface, which is especially relevant once the endpoint is reachable outside a trusted network.

  • Identity-aware, gated tool calls (PR #8404) — Declaring a user_id parameter makes AgentOS inject the authenticated JWT subject and hide the field from the client-facing schema, so tools can be user/tenant-scoped without trusting a client-supplied ID. A one-line authorize function gates calls, and allowed_hosts/allowed_origins opt into DNS-rebinding protection — the pieces you need before exposing /mcp to browsers or untrusted callers.

  • Call-site dependencies now merge rather than replace (PR #8404) — agent.run()/team.run() dependencies used to overwrite Agent.dependencies/Team.dependencies wholesale, silently dropping prompt-template variables on transports that always pass call-site dependencies (notably Slack and WhatsApp). They now merge as {**configured, **call_site} with call-site winning on conflict, matching how metadata and knowledge_filters already behave. Watch this if you relied on the overwrite to clear configured dependencies — you must now pass explicit overrides.

  • Docs and cookbook refresh — Model guidance updated to gpt-5.5 (PR #8383) and 08_learning refreshed with an AgentOS learning demo (PR #8379); PR #8380 is formatting-only cleanup. No runtime impact for adopters.

  • Breaking changes — None; without mcp_config, all built-in tools register exactly as before, so existing /mcp consumers are unaffected.

Changelog

New Features:

  • Custom, Scoped, Identity-Aware MCP Tools: The AgentOS MCP server (served at /mcp) is now a real extension point, configured through a single MCPServerConfig object. You can register custom tools (plain callables or Agno @tool/Functions), scope the built-ins (enable_builtin_tools=False, or filter with include_tags/exclude_tags), inject the authenticated caller identity into a tool (declare user_id and AgentOS supplies the JWT subject while hiding it from the client schema), gate calls with a one-line authorize function, and opt into built-in DNS-rebinding protection via allowed_hosts/allowed_origins. All with data, no custom middleware classes. Fully backward compatible: without mcp_config, all built-in tools register exactly as before.

Bug Fixes:

  • Call-Site Dependencies Merge: Call-site dependencies passed to agent.run()/team.run() replaced the configured Agent.dependencies/Team.dependencies wholesale, which dropped prompt-template vars over interfaces that always pass call-site dependencies (e.g. Slack/WhatsApp). They now merge({**configured, **call_site}, call-site wins on conflict), matching how metadata/knowledge_filters already merge.
