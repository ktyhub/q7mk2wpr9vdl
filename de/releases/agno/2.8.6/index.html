agno v2.8.6

Changelog

Neue Funktionen

  • Kleinste KI: SmallestTools hinzugefügt, ein Text-to-Speech-Toolkit für die kleinste KI mit text_to_speech (gibt Audio als ToolResult-Artefakt zurück, optional auf der Festplatte gespeichert) und get_voices. Unterstützt die Modelle lightning_v3.1 und lightning_v3.1_pro.
  • AgentOS: GET /metrics/refresh/status hinzugefügt, um Aktualisierungen von Hintergrundmetriken zu beobachten: – Meldet idle, running, completed oder failed mit started_at, finished_at und error, sodass clients den Abschluss abfragen können, anstatt stillschweigend eine Zeitüberschreitung zu verursachen. Der Status wird auch dann aktualisiert, wenn eine Aktualisierung abgeschlossen ist, ohne dass neue Daten geschrieben werden.
    • Verfügbar auf dem client als AgentOSClient.get_metrics_refresh_status()
  • OpenSearch: OpenSearch-Vektordatenbankunterstützung (agno.vectordb.opensearch) mit Vektor-, Schlüsselwort- und Hybridsuche in synchronen und asynchronen Varianten hinzugefügt, installierbar über das agno[opensearch]-Extra. Enthält Kochbuchbeispiele und ein run_opensearch.sh-Skript für die lokale Einrichtung.

Verbesserungen

  • Tools: Die Pydantic-Versionssuche wurde beim Tool-Wrapping zwischengespeichert. Die Paketmetadaten wurden bei jedem Wrap neu gelesen, wodurch das wiederholte Tool-Wrapping zu einem Hot Path wurde (100-Wrap-Benchmark: 65.9 ms bis 11.0 ms).

Fehlerbehebungen

  • AgentOS: POST /metrics/refresh blockiert Uvicorn-Worker nicht mehr bei großen Datensätzen: – Der sync calculate_metrics()-Aufruf wird jetzt im Threadpool ausgeführt, sodass andere Anforderungen während einer Aktualisierung weiter verarbeitet werden. Gleiche Listenantwort mit mehr als 200 Metriken wie zuvor. – Der neue Opt-In-Abfrageparameter ?background=true gibt sofort 202 zurück und führt die Aktualisierung als Hintergrundaufgabe aus. Hintergrundaktualisierungen erfolgen im Einzelflug pro Datenbank. – GET /metrics mit einer Synchronisierung BaseDb verschiebt auch seine verzögerte Aktualisierung in den Threadpool.
  • Kodierung: open()-Aufrufe im Textmodus übergeben jetzt explizites encoding="utf-8", sodass auf einer Plattform geschriebene JSON-Cache- und Konfigurationsdateien auf einer anderen lesbar bleiben (Windows verwendet standardmäßig cp1252).

  • Dokumente: Defekte Links in den Kochbuch-READMEs und CONTRIBUTING.md von @devdattatalele in https://github.com/agno-agi/agno/pull/9195 reparieren
  • [Fix] Cache-Pydantic-Versionssuche während des Tool-Wrappings durch @basnijholt in https://github.com/agno-agi/agno/pull/9210
  • Fix: explizite Kodierung="utf-8" zu open()-Aufrufen im Textmodus von @Ghraven in https://github.com/agno-agi/agno/pull/7984 hinzufügen
  • Fix: Führen Sie die Aktualisierung der Metriken im Hintergrund aus, um das Blockieren von Workern durch @Mustafa-Esoofally in https://github.com/agno-agi/agno/pull/9263 zu vermeiden
  • Leistung: Opensearch-Datenbank von @anhphong22 in https://github.com/agno-agi/agno/pull/3611 unterstützen

agno v2.8.6

Highlights

  • Smallest AI text-to-speech — Adds SmallestTools (PR #9015) with text_to_speech and get_voices, targeting lightning_v3.1 and lightning_v3.1_pro. Audio arrives as a ToolResult artifact instead of raw bytes, with optional disk persistence — so it drops into existing tool/artifact pipelines rather than needing a separate output path.
  • AgentOS metrics refresh stops blocking workers — PR #9263 moves the sync calculate_metrics() call into the threadpool, so a large refresh no longer stalls uvicorn; the response contract is unchanged (still 200 + metrics list). ?background=true is opt-in and returns 202 immediately — note refreshes are single-flight per database, so overlapping triggers coalesce instead of queueing.
  • Pollable refresh status — New GET /metrics/refresh/status plus AgentOSClient.get_metrics_refresh_status() (PR #9263) report idle/running/completed/failed with started_at, finished_at, and error. State updates even when a refresh writes no new data, letting clients replace silent timeouts with real completion checks.
  • OpenSearch vector backend — PR #3611 adds agno.vectordb.opensearch behind the agno[opensearch] extra, with vector, keyword, and hybrid search in both sync and async variants. Ships run_opensearch.sh and cookbook examples; hybrid search is the draw if you already operate OpenSearch.
  • Faster tool wrapping — PR #9210 caches the Pydantic version lookup instead of re-reading package metadata on every wrap. The reported 100-wrap benchmark falls from 65.9 ms to 11.0 ms (~6x) — worth noting if you wrap tools dynamically or in bulk at startup.
  • Cross-platform file encoding — PR #7984 forces encoding="utf-8" on text-mode open() calls for JSON caches and config files. Without it, files written under Windows' cp1252 default could be unreadable elsewhere — relevant when sharing cache/config artifacts across OSes or CI.

No breaking changes.

Changelog

New Features

  • Smallest AI: Added SmallestTools, a text-to-speech toolkit for Smallest AI with text_to_speech (returns audio as a ToolResult artifact, optionally saved to disk) and get_voices. Supports the lightning_v3.1 and lightning_v3.1_pro models.
  • AgentOS: Added GET /metrics/refresh/status to observe background metrics refreshes:
    • Reports idle, running, completed or failed with started_at, finished_at and error, so clients can poll for completion instead of timing out silently. The state updates even when a refresh finishes without writing new data.
    • Available on the client as AgentOSClient.get_metrics_refresh_status()
  • OpenSearch: Added OpenSearch vector database support (agno.vectordb.opensearch) with vector, keyword and hybrid search in both sync and async variants, installable via the agno[opensearch] extra. Includes cookbook examples and a run_opensearch.sh script for local setup.

Improvements

  • Tools: Cached the Pydantic version lookup during tool wrapping. The package metadata was re-read on every wrap, which made repeated tool wrapping a hot path (100-wrap benchmark: 65.9 ms to 11.0 ms).

Bug Fixes

  • AgentOS: POST /metrics/refresh no longer blocks uvicorn workers on large datasets:
    • The sync calculate_metrics() call now runs in the threadpool, so other requests keep flowing during a refresh. Same 200 + metrics list response as before.
    • New opt-in ?background=true query param returns 202 immediately and runs the refresh as a background task. Background refreshes are single-flight per database.
    • GET /metrics with a sync BaseDb also moves its lazy refresh to the threadpool.
  • Encoding: Text-mode open() calls now pass explicit encoding="utf-8", so JSON cache and config files written on one platform stay readable on another (Windows defaults to cp1252).
