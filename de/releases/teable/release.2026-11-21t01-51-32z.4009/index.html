Funktionsaktualisierungen

– Strikte und schreibgeschützte MCP-Endpunkte hinzugefügt. Der strikte Endpunkt trennt Lese- und Schreibaktionen, sodass kompatible AI clients eine Bestätigung anfordern können, bevor sie Änderungen vornehmen. Der schreibgeschützte Endpunkt unterstützt clients, die Schreibvorgänge nicht bestätigen können. Bestehende MCP-Integrationen bleiben unverändert.

  • Für jede Basis wurde eine Abfragebibliothek hinzugefügt. Mitglieder können standardmäßig private Abfragerevisionen speichern, suchen, vergleichen und freigeben. Abfragen werden mit den aktuellen Datenberechtigungen des Aufrufers ausgeführt und veröffentlichte Apps können eine bestimmte Revision anheften. Durch das Widerrufen des Zugriffs wird verhindert, dass Apps die angeheftete Abfrage ausführen, bis der Zugriff wiederhergestellt oder die App aktualisiert wird. Für diese Funktion müssen sowohl die Abfragebibliothek als auch die native Abfrageausführung aktiviert sein.
  • Das Einfügen von Klartext in Tabellen unterstützt jetzt bidirektionale Viele-zu-Viele-Links. Eingefügte Titel stimmen mit vorhandenen Datensätzen in der verknüpften Tabelle überein und wechselseitige Links werden aktualisiert, ohne dass Duplikate entstehen.
  • Tabellenmitglieder können jetzt sehen, ob die Suchbeschleunigung aktiv ist, welche Felder sie abdeckt und wann sich ihr Status ändert. Geteilte Ansichten zeigen die Verfügbarkeit nur für Felder an, die in der Ansicht sichtbar sind.

Fehlerbehebungen und Verbesserungen

– Das OpenAI-Plugin-Paket wurde auf die Version 1.0.1 aktualisiert und die AI-Anweisungen gekürzt, sodass sie in Claude Code nicht mehr abgeschnitten sind.

  • Verbesserte Zuverlässigkeit der berechneten Felder der Version 2 bei gleichzeitiger Reduzierung unnötiger Datenbanklast. – Verbesserte Zuverlässigkeit beim Wiederherstellen und Löschen von Ressourcen, einschließlich eines Fixes für wiederhergestellte v2-Tabellen, die möglicherweise im Papierkorb aufgeführt bleiben.
  • Das Vorfüllen von Zeilen behält jetzt zulässige Werte bei und überspringt nur neue Auswahloptionen, die der Editor nicht erstellen kann. Wenn das Einfügen nur eine eingeschränkte Option enthält, wird dennoch ein Berechtigungsfehler zurückgegeben. – Fehler behoben, die auftraten, wenn Felder gleichzeitig in derselben Tabelle erstellt wurden oder während ein lang andauernder Vorgang ausgeführt wurde. Neue Felder werden jetzt zuverlässig in der Feldliste und der Standardansicht angezeigt.
  • Cuppy erklärt jetzt, wenn eine Aufgabe stoppt, weil nicht mehr genügend Speicher vorhanden ist. Abgeschlossene Schritte bleiben sichtbar und Webbenutzer können mit der letzten Antwort fortfahren, ohne von vorne beginnen zu müssen.
  • Gefilterte Suchvorgänge und Rollups wurden korrigiert, sodass beim Löschen verknüpfter Datensätze nur die betroffenen übergeordneten Datensätze neu berechnet werden. Bei großen verknüpften Datensätzen erfolgt das Löschen außerdem schneller. – Verbesserte Basisfreigabesicherheit, sodass Besucher nur auf Inhalte innerhalb des konfigurierten Freigabebereichs zugreifen können. – Fehler in Dashboard-Diagrammen behoben, die Tabellendaten verwenden. Die Diagrammsummen spiegeln jetzt die Daten wider, zu deren Lesen jeder Betrachter berechtigt ist, einschließlich Einschränkungen auf Zeilenebene. – Verbesserte V2 API-Leistung für Stapelaktualisierungen über mehrere Felder mit verknüpften Datensätzen hinweg, wobei die Verknüpfungsreihenfolge beibehalten und gegenseitige Verknüpfungen synchron gehalten werden.

teable release.2026-11-21T01-51-32Z.4009

Feature Updates

  • Added strict and read-only MCP endpoints. The strict endpoint separates read and write actions so compatible AI clients can ask for confirmation before making changes. The read-only endpoint supports clients that cannot confirm writes. Existing MCP integrations are unchanged.
  • Added a Query Library for each Base. Members can save, find, compare, and share private-by-default query revisions. Queries run with the caller’s current data permissions, and published apps can pin a specific revision. Revoking access prevents apps from running the pinned query until access is restored or the app is updated. This feature requires both Query Library and native query execution to be enabled.
  • Plain-text paste across tables now supports two-way many-to-many links. Pasted titles match existing records in the linked table, and reciprocal links are updated without creating duplicates.
  • Table members can now see whether search acceleration is active, which fields it covers, and when its status changes. Shared views show availability only for fields visible in the view.

Bug Fixes & Improvements

  • Updated the OpenAI plugin package to version 1.0.1 and shortened AI instructions so they are no longer cut off in Claude Code.
  • Improved v2 computed-field reliability while reducing unnecessary database load.
  • Improved resource restore and deletion reliability, including a fix for restored v2 tables that could remain listed in the trash.
  • Row prefilling now keeps permitted values and skips only new select options the editor cannot create. If the paste contains only a restricted option, it still returns a permission error.
  • Fixed failures when fields were created concurrently on the same table or while a long-running operation was in progress. New fields now reliably appear in the field list and default view.
  • Cuppy now explains when a task stops because it runs out of memory. Completed steps remain visible, and web users can resume from the latest reply without starting over.
  • Fixed filtered lookups and rollups so deleting linked records recalculates only the affected parent records. Deletion is also faster for large linked datasets.
  • Improved Base share security so visitors can access only content within the configured share scope.
  • Fixed errors in Dashboard charts that use table data. Chart totals now reflect the data each viewer has permission to read, including row-level restrictions.
  • Improved V2 API performance for batch updates across multiple linked-record fields while preserving link order and keeping reciprocal links in sync.
