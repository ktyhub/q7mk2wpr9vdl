vault v2.1.0

Tresor v2.1.0

2.1.0

01. September 2026

SICHERHEIT:

  • Kern: Aktualisieren Sie go.etcd.io/etcd/client/pkg/v3 auf v3.7.1, um die Sicherheitslücke GO-2026-6107 zu schließen.
  • Kern: Aktualisieren Sie software.sslmate.com/src/go-pkcs12 auf v0.7.2, um die Sicherheitslücke GO-2026-5052 zu schließen. ÄNDERUNGEN:
  • Lizenz: Fügen Sie Agentic IAM-Bedingungen zum client-Lizenzmodell hinzu und aktualisieren Sie die Bedingungen für das Vault-Plattform-Lizenzmodell.
  • Kern: Bump Go-Version auf 1.26.7.
  • oauth-resource-server (Enterprise): Verhindern Sie, dass die Issuer-ID nach der Erstellung des OAuth-Ressourcenserver-Profils geändert wird. Betreiber müssen Profile löschen und neu erstellen, um die Issuer_ID zu ändern.
  • oauth-resource-server (Enterprise): Verhindert, dass unique_id_claim nach der Erstellung des OAuth-Ressourcenserver-Profils mutiert wird. Betreiber müssen Profile löschen und neu erstellen, um den unique_id_claim zu ändern.
  • oauth-resource-server (Enterprise): Die OAuth-Ressourcenserver-Funktion erfordert keine Aktivierung mehr über den sys/activation-flags/oauth-resource-server/activate-Endpunkt.
  • oauth-resource-server (Unternehmen): Aktualisieren Sie die Konfiguration des OAuth-Ressourcenservers, um benutzerdefinierte Anspruchsoptionen für die eindeutige Kennung und den Akteur des Tokens einzuschließen.
  • Secrets/openldap (Enterprise): Plugin auf v0.18.4+ent aktualisieren EIGENSCHAFTEN:
  • Benutzeroberfläche der Agentenregistrierung (Unternehmen): Fügt der primären Navigation einen neuen Abschnitt „Agentensicherheit“ mit einer Agentenregistrierungsseite hinzu, auf der Bediener registrierte KI-Agenten, ihre zugehörigen Vault-Entitäten und Aliase, zugewiesenen Richtlinien und den Betriebsstatus anzeigen, suchen und verwalten können.
  • Automatische DNS-01-Herausforderungserfüllung für externe PKI-CA: Integrieren Sie die folgenden DNS-Anbieter für die automatische DNS-01-Herausforderungserfüllung: AWS Route53, Azure DNS, Google Cloud DNS und BIND sowie andere RFC2136-kompatible Server.
  • PKI PKCS#12- und JKS-Unterstützung: Fügt Unterstützung für PKCS#12- (PFX) und Java Keytool- (JKS) Zertifikatpakete für relevante PKI-Endpunkte hinzu. Bundles werden als Base64-codierte, passwortgeschützte Dateien zurückgegeben.
  • SLH-DSA-Unterstützung für hybrides Signieren/Verifizieren in der Transit-Engine (Unternehmen): Unterstützung für SLH-DSA als PQC-Komponente für Hybrid-Signieren/Verifizieren-Vorgänge hinzufügen. Dies ist sowohl mit ECDSA (p-256, P-384, P-521) als auch mit Ed25519 kompatibel.
  • Secrets/pki-external-ca (Enterprise): Unterstützung für die Handhabung von DNS-01-Herausforderungen für Azure, AWS, GCP und rfc2136 DNS hinzugefügt. VERBESSERUNGEN:
  • agent-registry (enterprise): Die Einschränkung, die die Verwendung von „deny“ in Obergrenzenrichtlinien untersagte, was zu Anforderungsfehlern führte, wurde entfernt.
  • agent/pkiexternalca: Ersetzen Sie go.uber.org/atomic durch sync/atomic (stdlib) für atomare boolesche Operationen im pkiexternalca-Paket.
  • Auth/Token: Fügen Sie eine globale Sperrliste zum Widerrufen von OAuth-JWTs hinzu, um die Autorisierung bestimmter Token über alle Namespaces hinweg zu verhindern.
  • core/seal (enterprise): Aktualisieren Sie die Oracle Cloud-Bibliothek, um die Seal-Integration mit neueren Regionen zu ermöglichen.
  • ui: Erhöhen Sie dompurify von 3.4.6 auf 3.4.13.
  • ui: Bump-Shell-Zitat von 1.8.4 zu 1.9.0.
  • ui: Offenlegung des RSA-Privatschlüsselfelds in der Benutzeroberfläche beim Generieren von Anmeldeinformationen mit der Snowflake-Datenbankgeheimnis-Engine. Bisher wurde dieses Feld nur im cli angezeigt.
  • ui: Das Modal zur Bestätigung des Löschens der Secrets-Engine erfordert jetzt die Eingabe von delete-engine zur Bestätigung. Es werden der Name der Engine, die Anzahl der Secrets (nur KV-Engines) und eine Liste dessen angezeigt, was dauerhaft gelöscht wird. ConfirmModal wurde jetzt aktualisiert und enthält nun einen optionalen Bestätigungstyp. FEHLERBEHEBUNGEN:
  • agent/pki-external-ca: Korrektur der CA-Kettenextraktion aus Vault PKI API-Antworten, bei denen das Feld ca_chain in Vorlagen aufgrund einer falschen Typbehandlung von Array-Antworten immer leer war
  • api: Berücksichtigen Sie den HTTP-Age-Header bei der Berechnung der verbleibenden Lebensdauer eines Leases, sodass über einen Caching-Proxy wie Vault Agent gelesene oder erneuerte Leases erneuert werden, bevor sie ablaufen.
  • Kern (Unternehmen): Behebung eines Datenwettlaufs und möglicher Panik beim Versiegeln/Entsiegeln
  • Kern (Unternehmen): Behebung der Panik in collectOperatorImportMetrics, wenn router.Route beim Lesen von KVv2-Metadaten auf sekundären Leistungsknoten eine Null-Antwort ohne Fehler zurückgibt. Dieser Zustand tritt während der WAL-Stream-Teilsynchronisierungsphase eines ersten Joins auf.
  • core/login: Panik bei fehlerhaften Anmeldeanfragen behoben. Vault gibt jetzt einen Fehler für fehlerhafte Anmeldenutzdaten zurück, anstatt die client-Verbindung zu trennen (kein Datenverlust).
  • core/metrics: Es wurde ein Fehler behoben, bei dem log_format = „json“ keine Auswirkung auf Telemetriesenkenfehler von statsd- und statsite-Backends hatte.
  • core/wrapping: sys/wrapping/wrap erzwingt jetzt Wrapping-Token im UUID-Format und ignoriert jedes vom Aufrufer angeforderte Wrap-Format.
  • Kern: vault operator migrate -start-Befehl bei der Migration zum integrierten Raft-Speicher behoben.
  • core: vault kv put/get funktioniert jetzt mit externen OAuth-Tokens.
  • cubbyhole: Cubbyhole-Schreibvorgänge für JWT-Tokens in Nicht-Root-Namespaces wurden behoben
  • Standardauthentifizierung: Behebung eines Problems mit älteren Standardauthentifizierungskonfigurationen, das im Rahmen eines Upgrades auf eine neuere Version von Vault fehlerhaft war.
  • Identität: Es wurde behoben, dass die Erstellung eines Entitätsalias mit der Fehlermeldung „Mount-Accessor-Namespace stimmt nicht mit Anforderungs-Namespace überein“ fehlschlug, wenn ein synthetischer Mount-Accessor in einem Namespace-Kontext verwendet wurde
  • oauth-resource-server (Enterprise): Behebung eines Problems, bei dem optional_authorization_details für delegierte (OBO) Workflows fälschlicherweise ignoriert wurde, wenn der Betreff keine Agentenregistrierung hatte, was dazu führte, dass RAR in diesen Anfragen nicht obligatorisch war.
  • Plugins: Beim Lesen eines nur versionierten Plugins ohne Angabe von -version wird es jetzt automatisch ausgewählt, wenn nur eine Version vorhanden ist, oder es wird ein Fehler mit der Auflistung der verfügbaren Versionen anstelle einer stillen 404 zurückgegeben.
  • Proxy/Cache (Unternehmen): Es wurde ein Fehler im statischen geheimen Cache behoben, bei dem GET-Anfragen mit ?list=true fälschlicherweise zwischengespeichert und veraltet bereitgestellt wurden.
  • sdk/Rotation: Nachfolgende Aufrufe ermöglichen nicht mehr die gleichzeitige Festlegung der Felder rotation_period und rotation_schedule. Der SDK leert nun explizit das Gegenfeld, um einen gegenseitigen Ausschluss zu gewährleisten.
  • Secret/PKI: Behebung der ACME-Bestellungsfinalisierungs-Race-Bedingung, bei der gleichzeitige Anfragen dazu führen konnten, dass Zertifikate doppelt ausgestellt und eines aus der auftragsbezogenen Nachverfolgung verwaist wurden
  • Secret/PKI: Verhindert, dass die Schlüsselumbenennung einen Namen akzeptiert, der bereits von einem anderen Schlüssel gehalten wird.
  • Geheimnisse/Datenbank: Bereinigen Sie den vom Anrufer gesteuerten DisplayName, bevor er in generierten Benutzernamen verwendet wird, um SQL-Injection über Benutzernamenvorlagen zu verhindern. Fügt eine Konfigurationswarnung hinzu, wenn ein username_template ohne eine Truncate-Funktion auf DisplayName verweist.
  • Secrets/LDAP: Durch die manuelle Rotation eines statischen Rollenkennworts wird die Rotations-TTL noch einmal neu gestartet, was dem Verhalten vor v2.0.0 entspricht
  • Secrets/Nomad: Behebung der Verbindungserschöpfung bei hoher Parallelität durch Einführung eines gemeinsam genutzten, gepoolten HTTP client mit einer Verbindungsobergrenze pro Host. Zuvor wurde für jede Anmeldeinformationsanforderung eine neue TCP-Verbindung geöffnet, was dazu führte, dass Nomad den HTTP-Fehler 429 „zu viele gleichzeitige Verbindungen“ zurückgab, wenn mehr als 100 Leases gleichzeitig generiert wurden.
  • serviceregistration/consul: Es wurde ein Problem behoben, bei dem sich Vault dauerhaft aus dem Consul-Dienstkatalog abmeldete, wenn ein SIGHUP/Reload-Signal gesendet wurde und die Konfiguration Consul als Speicher-Backend ohne eine explizite service_registration-Strophe verwendete.
  • ui/secrets/pki: Problem behoben, bei dem die Seite mit der Emittentenliste nicht geladen werden konnte, wenn die Anzahl der Emittenten 10 übersteigt
  • ui: 403-Fehler bei der Authentifizierungsmethode behoben. Konfigurieren Sie die Seite für Richtlinien, die das Lesen auf sys/auth*, aber nicht auf sys/auth/* gewähren.
  • ui: Behebung, dass die Kubernetes-Authentifizierungsmethode token_reviewer_jwt nicht speichert – der falsche OpenAPI-Schemaschlüssel (KubernetesConfigureRequest) wurde anstelle von KubernetesConfigureAuthRequest verwendet, was dazu führte, dass das JWT-Feld im Formular und in der API-Nutzlast beim Speichern weggelassen wurde.
  • ui: Korrigieren Sie das Rand-clipping in Dashboard-Widget-Tabellen durch Anwenden eines überlaufversteckten Stils.
  • ui: Fehler bei der offenen Umleitung in der Route des OIDC-Anbieters behoben.
  • ui: Das Flyout des Richtliniengenerators, das Speichern ablehnt, wenn keine Funktionen für eine Regel ausgewählt sind, wurde behoben.
  • ui: Fügen Sie die Eigenschaft „totalItems“ hinzu, um die Paginierung gefilterter Listen zu korrigieren, die eine falsche Gesamtseitenzahl anzeigt
  • ui: Falsches „Kein Zugriff“-Banner beim Navigieren zur Vault-Benutzeroberfläche mit ?namespace=root in der URL behoben

vault v2.1.0

2.1.0

September 01, 2026

SECURITY:

  • core: Update go.etcd.io/etcd/client/pkg/v3 to v3.7.1 to fix security vulnerability GO-2026-6107.
  • core: Update software.sslmate.com/src/go-pkcs12 to v0.7.2 to fix security vulnerability GO-2026-5052.

CHANGES:

  • License: Add Agentic IAM terms to client licensing model and update terms for Vault Platform licensing model.
  • core: Bump Go version to 1.26.7.
  • oauth-resource-server (enterprise): Prevent issuer_id from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the issuer_id.
  • oauth-resource-server (enterprise): Prevent unique_id_claim from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the unique_id_claim.
  • oauth-resource-server (enterprise): The OAuth Resource Server feature no longer requires activation via the sys/activation-flags/oauth-resource-server/activate endpoint.
  • oauth-resource-server (enterprise): Update OAuth Resource Server config to include custom claim options for the token's unique identifier and actor.
  • secrets/openldap (enterprise): Update plugin to v0.18.4+ent

FEATURES:

  • Agent Registry UI (enterprise): Adds a new Agentic Security section to the primary navigation with an Agent Registry page where operators can view, search, and manage registered AI agents, their associated Vault entities and aliases, assigned policies, and operational status.
  • Automatic DNS-01 Challenge Fulfillment for PKI External CA: Integrate with the following DNS providers for automatic DNS-01 challenge fulfillment: AWS Route53, Azure DNS, Google Cloud DNS, and BIND and other RFC2136-compliant servers.
  • PKI PKCS#12 and JKS Support: Adds support for PKCS#12 (PFX) and Java keytool (JKS) certificate bundles to relevant PKI endpoints. Bundles are returned as base64-encoded, password-protected files.
  • SLH-DSA support for Hybrid sign/verify in Transit engine (enterprise): Add support for SLH-DSA as the PQC component for Hybrid sign/verify operations. This is compatible with both ECDSA (p-256, P-384, P-521) and Ed25519.
  • secrets/pki-external-ca (enterprise): Add support for handling dns-01 challenges for Azure, AWS, GCP, and rfc2136 DNS.

IMPROVEMENTS:

  • agent-registry (enterprise): Removed the restriction that disallowed the use of 'deny' in ceiling policies, resulting in request errors.
  • agent/pkiexternalca: Replace go.uber.org/atomic with sync/atomic (stdlib) for atomic boolean operations in the pkiexternalca package.
  • auth/token: Add global denylist for revoking OAuth JWTs to prevent authorization of specific tokens across all namespaces.
  • core/seal (enterprise): Update Oracle Cloud library to enable seal integration with newer regions.
  • ui: Bump dompurify from 3.4.6 to 3.4.13.
  • ui: Bump shell-quote from 1.8.4 to 1.9.0.
  • ui: Exposing the RSA Private Key field in the UI when generating credentials with the snowflake database secrets engine. Previously, this field was only shown in the cli.
  • ui: Secrets engine delete confirmation modal now requires typing delete-engine to confirm, displays the engine name, secret count (KV engines only), and a list of what will be permanently deleted. ConfirmModal has now been updated to include a optional type-to-confirm.

BUG FIXES:

  • agent/pki-external-ca: Fix CA chain extraction from Vault PKI API responses where ca_chain field was always empty in templates due to incorrect type handling of array responses
  • api: Account for the HTTP Age header when calculating a lease's remaining lifetime, so that leases read or renewed through a caching proxy such as Vault Agent are renewed before they expire.
  • core (enterprise): Fix a data race and potential panic during seal/unseal
  • core (enterprise): Fix panic in collectOperatorImportMetrics when router.Route returns a nil response with no error during KVv2 metadata reads on performance secondary nodes. This condition occurs during the WAL-stream partial-sync phase of an initial join.
  • core/login: Fix panic on malformed login requests. Vault now returns an error for malformed login payloads instead of dropping the client connection (no data loss).
  • core/metrics: Fixed a bug where log_format = "json" had no effect on telemetry sink errors from statsd and statsite backends.
  • core/wrapping: sys/wrapping/wrap now enforces uuid-format wrapping tokens, ignoring any caller-requested wrap format.
  • core: Fix vault operator migrate -start command when migrating to raft integrated storage.
  • core: vault kv put/get now works with external OAuth tokens.
  • cubbyhole: Fix cubbyhole writes for JWT tokens in non-root namespaces
  • default-auth: Fix issue with legacy default-auth configs that would break as part of upgrading to a newer version of Vault.
  • identity: Fixed entity alias creation failing with "mount accessor namespace does not match request namespace" when using a synthetic mount accessor in a namespaced context
  • oauth-resource-server (enterprise): Fix issue where optional_authorization_details was incorrectly ignored for delegated (OBO) workflows when the subject has no agent registration, resulting in RAR not being mandatory in those requests.
  • plugins: Reading a versioned-only plugin without specifying -version now auto-selects it when only one version exists, or returns an error listing available versions, instead of a silent 404.
  • proxy/cache (enterprise): Fixed a bug in the static secret cache where GET requests with ?list=true were incorrectly cached and served stale.
  • sdk/rotation: Subsequent calls will no longer allow both the rotation_period and rotation_schedule fields to be set simultaneously. The SDK now explicitly empties the opposing field to guarantee mutual-exclusion.
  • secret/pki: Fix ACME order finalize race condition where concurrent requests could double-issue certificates and orphan one from order-keyed tracking
  • secret/pki: prevent key rename from accepting a name already held by a different key.
  • secrets/database: Sanitize the caller-controlled DisplayName before it is used in generated usernames to prevent SQL injection via username templates. Adds a configuration warning when a username_template references DisplayName without a truncate function.
  • secrets/ldap: manually rotating a static role password will restart the rotation TTL once again, matching the behavior prior to v2.0.0
  • secrets/nomad: Fix connection exhaustion under high concurrency by introducing a shared, pooled HTTP client with a per-host connection cap. Previously, a new TCP connection was opened for every credential request, causing Nomad to return HTTP 429 "too many concurrent connections" errors when more than 100 leases were generated simultaneously.
  • serviceregistration/consul: Fixed an issue where Vault would permanently deregister itself from the Consul service catalog when a SIGHUP/reload signal was sent and the configuration used Consul as the storage backend without an explicit service_registration stanza.
  • ui/secrets/pki: Fix issuers list page failing to load when issuer count exceeds 10
  • ui: Fix 403 error on auth method Configure page for policies that grant read on sys/auth* but not sys/auth/*.
  • ui: Fix Kubernetes auth method not saving token_reviewer_jwt — the wrong OpenAPI schema key (KubernetesConfigureRequest) was used instead of KubernetesConfigureAuthRequest, causing the JWT field to be omitted from the form and API payload on save.
  • ui: Fix border clipping on dashboard widget tables by applying overflow-hidden styling.
  • ui: Fix open redirect bug in OIDC provider route.
  • ui: Fix policy generator flyout rejecting saves when no capabilities are selected for a rule.
  • ui: add totalItems property to fix filtered list pagination showing incorrect total page count
  • ui: fix spurious "No access" banner when navigating to Vault UI with ?namespace=root in the URL
