vault v2.0.4

Tresor v2.0.4

2.0.4

04. August 2026

WICHTIGSTE ÄNDERUNGEN:

  • Container: Die folgenden Pakete wurden aus dem UBI-basierten Container entfernt Bilder: Gnupg, OpenSSL, Procps. SICHERHEIT:
  • acl: Behebung einer Sicherheitslücke bei der Rechteausweitung, bei der eine denied_parameters-Einschränkung im Anforderungsfeld policies umgangen werden konnte, indem ein Richtlinienname mit gemischter Groß-/Kleinschreibung übermittelt wurde (z. B. „Super-Admin“ statt „Super-Admin“). Vault normalisiert jetzt den Parameter policies auf Kleinbuchstaben, bevor die Einschränkungen allowed_parameters/denied_parameters ausgewertet werden.
  • Identität/Scim (Unternehmen): Der identity/entity/merge-Endpunkt lehnt jetzt Anfragen ab, die eine von SCIM verwaltete Entität betreffen, und verhindert so, dass privilegierte Betreiber die SCIM-Eigentumsregeln umgehen, um Aliase, Gruppenmitgliedschaften oder Richtlinien über SCIM-Grenzen hinweg zu übertragen.
  • Identität: Verhindern Sie, dass der Entitäts-Batch-Delete-Endpunkt (identity/entity/batch-delete) den zugrunde liegenden Speicher von Entitäten löscht, die zu einem anderen Namespace gehören.
  • Identität: Entitäts-/Namensaktualisierungen lehnen jetzt nicht übereinstimmende ID- oder external_id-Selektoren ab, um ein Retargeting von Aktualisierungen auf eine andere Entität zu verhindern ÄNDERUNGEN:
  • auth/oci: Plugin auf v0.21.3 aktualisieren
  • Kern: Bump Go-Version auf 1.26.5.
  • core: Unterstützung für doppelte Attribute in HCL-Konfigurationsdateien und Richtliniendefinitionen entfernen. HCL analysieren mit Duplikate von Attributen schlagen jetzt immer fehl, und die Umgebung VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES Die Variable, die zuvor das alte Verhalten wiederherstellte, wurde entfernt. EIGENSCHAFTEN:
  • Geheimnisse: Möglichkeit hinzugefügt, Geheimnisse im YAML-Format anzuzeigen VERBESSERUNGEN:
  • Auth/Cert: Unterstützt die Anmeldung über X-Forwarded-Cert-Header, auch wenn TLS im Vault-Listener deaktiviert ist.
  • core (enterprise): Fügen Sie einen Endpunkt bei sys/config/oauth-resource-server/id/:config_id hinzu, um OAuth-Ressourcenserverprofile von config_id zu lesen
  • Kern (Unternehmen): Machen Sie die JWT-typ-Validierung des OAuth-Ressourcenservers für Token von IdPs wie Okta freizügiger, indem Sie einen fehlenden typ-Header zulassen und gleichzeitig die aktuellen typ-Werte auf at+jwt, application/at+jwt und JWT beschränken.
  • core (entreprise): Sealwrap-Sperrkonflikt für Core-Pfade abändern.
  • core/acl: Fügt eine globale deny_slash_in_templated_path-Konfigurationsoption hinzu, um das Vorhandensein von Schrägstrichen in gerenderten Identitätsvorlagen in Richtlinien abzulehnen, standardmäßig false.
  • core/identity: Fügt eine globale deny_slash_in_templated_path-Konfigurationsoption hinzu, um das Vorhandensein von Schrägstrichen in gerenderten Identitätsvorlagen in Richtlinien abzulehnen, standardmäßig false.
  • core/managed-keys/PKCS#11 (Enterprise): Die Bereitstellung eines nicht leeren Werts für ein Feld, während das andere bereits gespeichert ist, wird abgelehnt. Um den Adressierungsmodus zu wechseln, müssen Sie das alte Feld explizit löschen, indem Sie es als leere Zeichenfolge („“) in derselben Anfrage zusammen mit dem neuen Wert senden.
  • core/managed-keys/PKCS#11 (Enterprise): Slot und token_label werden jetzt strikt als sich gegenseitig ausschließende Bezeichner für ein HSM-Token erzwungen
  • Ereignisse: Fügen Sie die Umgebungsvariable VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE hinzu, um begrenzte Ereigniswarteschlangen für Abonnenten von Ereignisbenachrichtigungen zu konfigurieren. Legen Sie eine positive Ganzzahl (z. B. 16) fest, um gepufferte Kanäle dieser Größe (maximal 1000) zu aktivieren. Dies verhindert eine Ressourcenerschöpfung in Bereitstellungen mit hohen Abonnentenzahlen, geht jedoch zu Lasten der Möglichkeit, dass Abonnenten Ereignisse verpassen. Aus Gründen der Abwärtskompatibilität ist der Standardwert 0 (ungepuffert).
  • Identität/Scim (Unternehmen): Filterunterstützung für die Endpunkte GET /scim/v2/Users und GET /scim/v2/Groups gemäß RFC 7644 hinzugefügt. Unterstützte Filter: userName eq, externalId eq, active eq und meta.lastModified gt/ge/lt/le für Benutzer; displayName eq und meta.lastModified gt/ge/lt/le für Gruppen. Nicht unterstützte Filterausdrücke geben HTTP 400 zurück. ServiceProviderConfig kündigt jetzt filter.supported: true an.
  • Identität/Scim (Unternehmen): Verbessern Sie die Leistung des SCIM-Benutzer- und Gruppenlistenendpunkts durch die Verwendung einer Präfixsortierung anstelle eines separaten Sortierdurchlaufs.
  • Identität: Entitätsstatus und Entitäts-/Alias-Zeitstempeldetails in Entitätslisten-key_info-Antworten einbeziehen.
  • oauth-resource-server: Unterstützung für differenzierte Richtlinienkontrolloptionen (Parametereinschränkungen) in Rich Authorization Requests (RAR) hinzugefügt, einschließlich allowed_parameters, denied_parameters und required_parameters innerhalb von authorization_details.
  • oauth-resource-server: Unterstützung für Identitätsvorlagenausdrücke (z. B. {{identity.entity.id}}) in Rich Authorization Requests (RAR) hinzugefügt.
  • scim: Benutzerressourcen enthalten jetzt ein schreibgeschütztes groups-Feld, das die direkten Gruppenmitgliedschaften auflistet, die vom anfordernden SCIM client gemäß RFC 7643 verwaltet werden.
  • Secrets/kv (Unternehmen): Unterstützt das Lesen und Wiederherstellen von KVv2-Geheimnissen aus einem geladenen Snapshot, einschließlich direkter Wiederherstellung und Kopieren aus dem Pfad innerhalb desselben Mounts und Namensraums.
  • UI: Fügen Sie neben den vorhandenen UI- und JSON-Ansichten eine schreibgeschützte YAML-Ansichtsoption zur KV v2-Secret-Detailseite hinzu.
  • ui: Bump pnpm.overrides Eintrag für tmp von 0.2.6 auf 0.2.7.
  • ui: Bump pnpm.overrides Eintrag für ws von 8.20.1 auf 8.21.0. FEHLERBEHEBUNGEN:
  • Proxy/Agent: Es wurde ein Fehler behoben, bei dem sich Authentifizierungsmethoden-Header über Re-Authentifizierungszyklen hinweg auf dem gemeinsam genutzten API client ansammelten.
  • Proxy: Es wurde ein Fehler behoben, bei dem der Vault-Token-Header bei allen WebSocket-Wiederverbindungen im statischen Secret-Cache-Updater doppelte Werte ansammelte.
  • Secrets Recovery (Unternehmen): Leiten Sie für Listenanfragen an sys/storage/raft/snapshot-load oder Lese-/Löschanfragen an sys/storage/raft/snapshot-load/{id} nicht zum aktiven Knoten um. Behandeln Sie diese Anfragen nach Möglichkeit auf dem Performance-Standby, andernfalls leiten Sie die Anfragen an den aktiven Knoten weiter.
  • Audit: Behebung einer Regression von CVE-2025-6000, die bei der Konfiguration eines Plugin-Verzeichnisses dazu führte, dass die Aktivierung von Audit-Geräten unter Windows nicht mehr möglich war.
  • Audit: Machen Sie die Serialisierung von Audit-Senken für Dateien und Sockets kontextsensitiv, sodass abgebrochene oder abgelaufene Anforderungen nicht mehr hinter blockierten Audit-Schreibvorgängen warten müssen, wodurch der Aufbau von Goroutinen, Speicher, Verbindungen und Dateideskriptoren während Audit-Senken-Konflikten reduziert wird
  • auth/cert: Unterstützung für x-weitergeleitete Zertifikatsheader hinzugefügt, die von AWS ALBs stammen.
  • auth/spiffe (Enterprise): Verwenden Sie bei der Überprüfung von Zertifikaten die vollständige Peer-Zertifikatskette.
  • aws/auth: EC2-Instanz-Metadatenwerte aus AWS-Authentifizierungsfehlermeldungen redigieren.
  • Verbrauchsabrechnung: Fehler behoben, bei dem PKI-, SSH- und SSH-OTP-Zertifikat-Abrechnungseinheiten von Leistungs-Standby-Knoten nicht zur Speicherung an aktive Knoten weitergeleitet wurden, was dazu führte, dass Abrechnungsereignisse auf Standby-Knoten verloren gingen.
  • Verbrauchsabrechnung: Fehler behoben, bei dem SPIFFE-JWT-Token-Abrechnungseinheiten von Performance-Standby-Knoten nicht zur Speicherung an aktive Knoten weitergeleitet wurden, was dazu führte, dass Abrechnungsereignisse auf Standby-Knoten verloren gingen.
  • Verbrauchsabrechnung: Es wurde ein Fehler behoben, bei dem an die SSH-Dauer angepasste Zertifikatsanzahlen und OTP-Zählungen, deren Dezimaldarstellung mit „4“ begann, nicht aus dem Speicher zurückgelesen werden konnten, was dazu führte, dass sys/billing/overview einen 500-Fehler mit „lz4: bad magic number“ zurückgab. Die Speicherkodierung verwendet jetzt einfache Dezimalzeichenfolgen, die mit anderen Abrechnungsmetriken konsistent sind, wodurch eine Fehlidentifizierung als lz4-komprimierte Daten vermieden wird.
  • Verbrauchsabrechnung: Fehler behoben, bei dem OIDC-Token-Dauerzählungen von Leistungs-Standby-Knoten nicht zur Speicherung an aktive Knoten weitergeleitet wurden, was dazu führte, dass Abrechnungsereignisse auf Standby-Knoten verloren gingen.
  • Verbrauchsabrechnung: Deadlocks in KMIP- und Mount-Scanning-Abrechnungspfaden wurden behoben, indem die Erfassung verschachtelter Sperren während der Mount- und Plugin-Aufzählung vermieden wurde.
  • Verbrauchsabrechnung: Behebt die dynamische und statische Rollenzählung von LDAP und OpenLDAP bei der Abrechnung von Anwendungsfällen dedizierte Zählendpunkte (role-count, static-role-count) anstelle der LIST-basierten Zählung zu verwenden, die zu einer Unterzählung der Rollen führte.
  • core (enterprise): Behebung eines Fehlers, der zu unnötigem Umwickeln des Siegels führte.
  • core (enterprise): Wrapping-Metadaten beibehalten, wenn das Control Group Unwrap eine genehmigte Anfrage wiedergibt, die eine verpackte Antwort zurückgibt.
  • Kern (Unternehmen): Aktualisierungsstatusprüfung des Sever-Side Consistent Token (SSCT) bei Verwendung auf sekundären Leistungsclustern. Bei ungültigen Cluster-übergreifenden Token-Anfragen an sekundäre aktive Knoten werden die Antwortcodes 403 gegenüber 412 bevorzugt.
  • core/managed-keys (Unternehmen): Erlauben Sie Steckplatznummern über 32 Bit in verwalteten PKCS#11-Schlüsseln.
  • core/seal: Goroutine-Leck behoben, das auftrat, wenn die Verschlüsselungs- und Entschlüsselungsfunktionen eine Zeitüberschreitung hatten.
  • Kern: URL-Abfrageparameter bleiben erhalten, wenn API-Anfragen, die doppelte Schrägstriche enthalten, auf ihren kanonischen Pfad umgeleitet werden. Zuvor wurden bei der Umleitung Parameter wie ?list=true gelöscht, was möglicherweise das Ergebnis der Anfrage veränderte.
  • Ereignisse (Unternehmen): Behebung eines Fehlers, bei dem Ereignisse nicht mehr an Leistungssekundäre weitergeleitet wurden, nachdem der aktive Knoten neu gestartet wurde oder ein Änderungsereignis (Versiegelung/Entsiegelung usw.) auftrat.
  • export API: Normalisieren Sie den end_time-Parameter im Aktivitätsexport API auf das Monatsende, um dem in der Dokumentation angegebenen Verhalten zu entsprechen.
  • oauth-resource-server (Unternehmen): Die OAuth-Ressourcenserver-Autorisierung behandelt jetzt ein leeres authorization_details-Array wie einen fehlenden Anspruch, wenn Autorisierungsdetails optional sind. Bisher wurden Token, die ein leeres Array enthielten, mit RAR_NO_MATCH abgelehnt, anstatt mit der normalen Identitäts- und Richtlinienautorisierung fortzufahren.
  • Secrets-Sync (Enterprise): Falsche Fehlerantwortcodezuordnung für GCP Secrets Sync Customer Controlled Encryption-Validierungen behoben, die als 500 Internal Server Error statt als 400 Bad Request zurückgegeben wurden.
  • Secrets-Sync: Behebung eines Problems, bei dem GCP Secret Manager-Ziele beim Vault-Neustart ihren regionalen KMS-Schlüssel verlieren.
  • Secrets-Sync: Korrigiert das Feld „Benutzerdefinierte Tags“ in der Detailansicht, sodass Schlüssel mit leerem Wert angezeigt werden
  • Secrets/pki-external-ca (Unternehmen): Fügen Sie den privaten Schlüssel in die PEMs des Antwortfelds des Zertifikats API ein, wenn Certificate_format auf pem_bundle festgelegt ist
  • Geheimnisse/Transit (Unternehmen): Fügen Sie der CSR-Signatur verwaltete Schlüsselunterstützung hinzu und legen Sie Endpunkte für Zertifikatsketten fest.
  • ui: Behandeln Sie Zeichenfolgenwerte („true“/„false“) für tls_disable korrekt, wenn der TLS-Status im Clusterkonfigurations-Widget angezeigt wird.
  • ui: Korrigiert die PKI-Generierung von Root, so dass sie nicht mehr gültig ist, nachdem die Eingaben zum Ablauf des Zertifikats korrekt gesteuert wurden.

vault v2.0.4

2.0.4

August 04, 2026

BREAKING CHANGES:

  • containers: The following packages have been removed from UBI based container images: gnupg, openssl, procps.

SECURITY:

  • acl: Fix privilege-escalation vulnerability where a denied_parameters constraint on the policies request field could be bypassed by submitting a mixed-case policy name (e.g. "Super-Admin" instead of "super-admin"). Vault now normalizes the policies parameter to lowercase before evaluating allowed_parameters/denied_parameters constraints.
  • identity/scim (enterprise): The identity/entity/merge endpoint now rejects requests that involve any SCIM-managed entity, preventing privileged operators from bypassing SCIM ownership guardrails to transfer aliases, group memberships, or policies across SCIM boundaries.
  • identity: Prevent the entity batch-delete endpoint (identity/entity/batch-delete) from deleting the underlying storage of entities that belong to another namespace.
  • identity: entity/name updates now reject mismatched id or external_id selectors to prevent retargeting updates to a different entity

CHANGES:

  • auth/oci: Update plugin to v0.21.3
  • core: Bump Go version to 1.26.5.
  • core: remove support for duplicate attributes in HCL configuration files and policy definitions. Parsing HCL with duplicate attributes now always fails, and the VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES environment variable that previously restored the legacy behavior has been removed.

FEATURES:

  • secrets: Added ability to view secrets in YAML format

IMPROVEMENTS:

  • auth/cert: Support login via x-forwarded cert headers even with tls disabled on the vault listener.
  • core (enterprise): Add an endpoint at sys/config/oauth-resource-server/id/:config_id to read oauth resource server profiles by config_id
  • core (enterprise): Make OAuth resource server JWT typ validation more permissive for tokens from IdPs such as Okta by allowing a missing typ header, while restricting present typ values to at+jwt, application/at+jwt, and JWT.
  • core (entreprise): Ameriolate sealwrap lock contention for core paths.
  • core/acl: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/identity: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/managed-keys/PKCS#11 (enterprise): Providing a non-empty value for one field while the other is already saved is rejected. To switch addressing modes, you must explicitly clear the old field by sending it as an empty string ("") in the same request alongside the new value.
  • core/managed-keys/PKCS#11 (enterprise): slot and token_label are now strictly enforced as mutually exclusive identifiers for an HSM token
  • events: Add VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE environment variable to configure bounded event queues for event notification subscribers. Set to a positive integer (e.g., 16) to enable buffered channels of that size (maximum 1000). This prevents resource exhaustion in deployments with high subscriber counts, but comes at the cost of the potential for subscribers to miss events. Defaults to 0 (unbuffered) for backward compatibility.
  • identity/scim (enterprise): Added filtering support to the GET /scim/v2/Users and GET /scim/v2/Groups endpoints per RFC 7644. Supported filters: userName eq, externalId eq, active eq, and meta.lastModified gt/ge/lt/le for Users; displayName eq and meta.lastModified gt/ge/lt/le for Groups. Unsupported filter expressions return HTTP 400. ServiceProviderConfig now advertises filter.supported: true.
  • identity/scim (enterprise): Improve SCIM User and Group listing endpoint performance by using prefix sort instead of a separate sort pass.
  • identity: Include entity status and entity/alias timestamp details in entity list key_info responses.
  • oauth-resource-server: Add support for fine-grained policy control options (parameter constraints) in Rich Authorization Requests (RAR), including allowed_parameters, denied_parameters, and required_parameters inside authorization_details.
  • oauth-resource-server: Add support for identity template expressions (e.g. {{identity.entity.id}}) in Rich Authorization Requests (RAR).
  • scim: User resources now include a read-only groups field listing the direct group memberships managed by the requesting SCIM client, per RFC 7643.
  • secrets/kv (enterprise): Support reading and recovering KVv2 secrets from a loaded snapshot, including in-place recover and copy-from-path within the same mount and namespace.
  • ui: Add a read-only YAML view option to the KV v2 secret details page, alongside the existing UI and JSON views.
  • ui: Bump pnpm.overrides entry for tmp from 0.2.6 to 0.2.7.
  • ui: Bump pnpm.overrides entry for ws from 8.20.1 to 8.21.0.

BUG FIXES:

  • Proxy/Agent: Fixed a bug where auth method headers accumulated on the shared API client across re-auth cycles.
  • Proxy: Fixed a bug where the Vault token header accumulated duplicate values across WebSocket reconnects in the static secret cache updater.
  • Secrets Recovery (enterprise): Do not redirect to the active node for list requests to sys/storage/raft/snapshot-load or read/delete requests to sys/storage/raft/snapshot-load/{id}. If possible, handle these requests on the performance standby, otherwise forward the requests to the active node.
  • audit: Fix a regression from CVE-2025-6000 that broke enabling audit devices on Windows when a plugin directory was configured.
  • audit: make file and socket audit sink serialization context-aware so canceled or expired requests stop waiting behind blocked audit writes, reducing buildup of goroutines, memory, connections, and file descriptors during audit sink contention
  • auth/cert: Add support for x-forwarded cert headers coming from AWS ALBs.
  • auth/spiffe (enterprise): Use the full peer certificate chain when verifying certificates.
  • aws/auth: Redact EC2 instance metadata values from AWS auth error messages.
  • consumption-billing: Fix bug where PKI, SSH and SSH OTP certificate billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fix bug where SPIFFE JWT token billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed a bug where SSH duration-adjusted certificate counts and OTP counts whose decimal representation began with '4' could not be read back from storage, causing sys/billing/overview to return a 500 error with "lz4: bad magic number". The storage encoding now uses plain decimal strings consistent with other billing metrics, avoiding misidentification as lz4-compressed data.
  • consumption-billing: Fixed bug where OIDC token duration counts from performance standby nodes were not forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed deadlocks in KMIP and mount-scanning billing paths by avoiding nested lock acquisition during mount and plugin enumeration.
  • consumption-billing: Fixes LDAP and OpenLDAP dynamic and static role counting in use-case billing to use dedicated count endpoints (role-count, static-role-count) instead of LIST-based counting, which was undercounting roles.
  • core (enterprise): Fix a bug that causes unnecessary seal rewrapping.
  • core (enterprise): Preserve wrapping metadata when Control Group unwrap replays an approved request that returns a wrapped response.
  • core (enterprise): Update state checking of Sever-Side Consistent Token (SSCT) when used on performance secondary clusters. 403 response codes will be preferred over 412 for invalid, cross cluster token requests to secondary active nodes.
  • core/managed-keys (enterprise): Allow slot numbers above 32 bits in PKCS#11 managed keys.
  • core/seal: Fixed goroutine leak occurring when Encryption and Decryption functions time out.
  • core: Preserve URL query parameters when redirecting API requests containing duplicate slashes to their canonical path. Previously, the redirect dropped parameters such as ?list=true, potentially changing the result of the request.
  • events (enterprise): Fix a bug where events stopped being forwarded to performance secondaries after the active node restarted or had a change event (seal/unseal, etc).
  • export API: Normalize the end_time parameter in the activity export API to the end of the month to match the behavior stated in the documentation.
  • oauth-resource-server (enterprise): OAuth Resource Server authorization now treats an empty authorization_details array like an absent claim when authorization details are optional. Previously, tokens containing an empty array were rejected with RAR_NO_MATCH instead of continuing through normal identity and policy authorization.
  • secrets-sync (enterprise):fixed incorrect error response code mapping for GCP Secrets Sync Customer Controlled Encryption validations, which were returned as 500 Internal Server Error instead of 400 Bad Request.
  • secrets-sync: Fix GCP Secret Manager destinations losing their per-region KMS key on Vault restart.
  • secrets-sync: Fixes Custom Tags field in Details view to display keys with empty value
  • secrets/pki-external-ca (enterprise): Include the private key within the certificate API response field's PEMs when certificate_format is set to pem_bundle
  • secrets/transit (enterprise): Add managed key support to CSR sign and set certificate chain endpoints.
  • ui: Correctly handle string values ("true"/"false") for tls_disable when displaying TLS status in the Cluster Configuration widget.
  • ui: Fixes PKI generate root so Not valid after correctly controls cert expiration inputs.
