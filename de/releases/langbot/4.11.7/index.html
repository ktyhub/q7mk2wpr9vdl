#LangBot v4.11.7

LangBot ist eine Open-Source-KI-Chatbot- und Agentenplattform, die mehrere Instant-Messaging-Plattformen, große Sprachmodelle, Wissensdatenbanken und Plug-ins unterstützt, um Sie bei der Erstellung, Bereitstellung und Verwaltung von KI-Assistenten zu unterstützen. LangBot ist eine Open-Source-KI-Chatbot- und Agentenplattform, die Messaging-Plattformen, große Sprachmodelle, Wissensdatenbanken und Plugins verbindet, um Sie bei der Erstellung, Bereitstellung und Verwaltung von KI-Assistenten zu unterstützen.

LangBot v4.11.7

Die letzte stabile Version der 4.11.x-Reihe. Es ersetzt v4.11.6, das zurückgezogen wurde: v4.11.6 lehnte gleichzeitige Token-Zählungen in einem gemeinsam genutzten Modell ab, sodass gleichzeitig laufende LocalAgent-Konversationen auf grobe Schätzungen zurückgreifen und fehlschlagen könnten. Wenn Sie v4.11.6 installiert haben, aktualisieren Sie auf v4.11.7.

Diese Version ist die endgültige stabile Version von 4.11.x und ersetzt die zurückgezogene v4.11.6. v4.11.6 lehnt gleichzeitige Token-Zählungen ab, wenn mehrere Sitzungen gleichzeitig dasselbe Modell verwenden. Daher verwendet LocalAgent stattdessen grobe Schätzungen und einige Konversationen schlagen fehl. Benutzer, die v4.11.6 installiert haben, aktualisieren bitte auf v4.11.7.

Es enthält keine neuen Funktionen. Es behebt die von 4.11.x-Instanzen über LangBot Space-Telemetrie gemeldeten Fehler und aktualisiert das Plugin SDK und die beteiligten offiziellen Plugins.

Korrekturen / Reparaturen

  • Gleichzeitiges Token-Zählen (v4.11.6-Regression): Das gleichzeitige Zählen auf demselben Modell wird nicht mehr abgelehnt; Nur die Zählung, die nach einer Zeitüberschreitung oder einem Abbruch noch läuft, verhindert eine erneute Zählung. Gleichzeitige Tokenzählungen auf einem Modell werden nicht mehr abgelehnt. nur ein Zählwert, der seinen Aufrufer überlebt hat, blockiert neue.
  • Windows-Plugins / Windows-Plug-ins: Das Plug-in print Chinesisch oder Emoji führt nicht mehr dazu, dass das Plug-in beim Ausführen getrennt wird und der 'gbk' codec can't encode-Fehler (SDK 0.7.24) nicht mehr auftritt. Ein Plugin, das chinesischen Text oder Emojis druckt, trennt die Plugin-Laufzeitumgebung unter Windows mit chinesischem Gebietsschema nicht mehr.
  • Windows-Token-Zählung / Windows-Token-Zählung: Die Tokenizer-Datei, die mit dem Windows-Installationspaket von LiteLLM geliefert wird, ist CRLF Newline. Wenn die Überprüfung fehlschlägt, wird es erneut von openaipublic heruntergeladen. Wenn das Netzwerk nicht verfügbar ist, bleibt die erste Konversation jedes Prozesses hängen (30 Sekunden count_tokens call timed out in der Telemetrie). LangBot konvertiert diese Dateien nun in LF und speichert sie beim Start in data/tiktoken_cache, und die Zählung erfolgt komplett offline. Wenn die Zählung abläuft oder fehlschlägt, verwendet LocalAgent außerdem lokale Schätzungen, um die Konversation fortzusetzen, anstatt die gesamte Runde fehlzuschlagen. Die Windows-Räder von LiteLLM versenden CRLF-Tokenizer-Dateien, die die Hash-Prüfung von Tiktoken nicht bestehen und einen Download auslösen; LangBot behält jetzt eine normalisierte Offline-Kopie bei und ein Zählfehler führt nicht mehr dazu, dass der LocalAgent-Turnus fehlschlägt.
  • Runner-Verfügbarkeit / Runner-Verfügbarkeit: Warten Sie während des Starts oder der erneuten Verbindung, bis das installierte Plug-in die Initialisierung abgeschlossen hat, bevor Sie es versenden, und melden Sie Agent runner not found: plugin:langbot-team/LocalAgent/default nicht mehr.
  • Plugin-Laufzeit: Während der erneuten Verbindung zur Laufzeit warten die Workspace-Synchronisierung und der Ereignisversand auf den Abschluss der erneuten Verbindung (bis zu 30 Sekunden) und schlagen nicht mehr innerhalb des Trennungsfensters fehl; Die tatsächliche Größe und Verarbeitungsvorschläge werden angezeigt, wenn das Anhang- und Stream-Volumen den Grenzfehler (SDK) überschreitet.
  • Wissensbasis/Wissensbasis: Das Backend der Vektorbibliothek wird in einem Hintergrundthread initialisiert. Bisher blockierte das erste Repository auf langsameren Maschinen die Ereignisschleife, was dazu führte, dass das Plug-in während der Laufzeit getrennt wurde und nicht zum Repository gelangte. Das Vektor-Backend wird außerhalb der Ereignisschleife erstellt. Bei der ersten Aufnahme auf einem langsamen Host wird die Plugin-Laufzeitverbindung nicht mehr unterbrochen.
  • SQLite/SQLAlchemy: Das Problem von unknown ON CONFLICT update shape beim ersten Schreiben in den Plug-in-Speicher für Nicht-Docker-Installationen (pip/uvx) auf SQLAlchemy 2.1 wurde behoben und die Abhängigkeitsgrenze ist auf <2.2 gesetzt; Die SQLite-Schreibsperre wird während der Bildaktualisierung aufgehoben, wodurch database is locked reduziert wird.
  • Box-Sandbox / Box-Sandbox: Übermäßig lange Befehle werden stattdessen über temporäre Skripte ausgeführt, behebt Argument list too long und Fehler beim Importieren großer Anhänge (SDK).
  • Runners: Coze/Dify verarbeitet abgeschlossene und Workflow-Typ-Ausgaben und behandelt solche Antworten nicht mehr als leere Antworten; Meldet keinen Fehler mehr, wenn die LocalAgent-Inferenzkonfiguration leer ist. Die Deserialisierung von Befehlsfehlerantworten stürzt nicht mehr ab (SDK).
  • Runner-Interaktionen/Runner-Interaktion: Auf älteren Adaptern wie HTTP Bot und OneBot melden vom Runner initiierte Interaktionen (wie der manuelle Eingabeknoten des Dify-Workflows) keinen get_interaction_capabilities-Fehler mehr und werden in Text-Fragen und Antworten geändert. Runner-Interaktionen auf älteren Adaptern (HTTP Bot, OneBot usw.) greifen auf Text zurück, anstatt zu scheitern.
  • Telemetrie/Telemetrie-Attribution: Abgebrochene Ausführungen werden als abgebrochen statt als fehlgeschlagen aufgezeichnet; Fehlerdetails bleiben erhalten, wenn das Routing fehlschlägt; Ausführungen, die sich bereits im Endzustand befinden, melden keine Konvertierungsfehler mehr; Das Plattformfeld der Ausführungskette wird nicht mehr von der Tool-Quelle (MCP/Skill usw.) überschrieben.
  • Offizielle Plugins/Offizielle Plugins: EssentialCommands 0.1.12 behebt !func; HelloPlugin 0.1.6 entfernt Debugging-Ausgabe; LocalAgent 0.2.10, CozeAgent 0.2.5 und DifyAgent 0.2.8 wurden auf dem Marktplatz gelistet.
  • SDK: langbot-plugin von 0.7.23 auf 0.7.24 korrigiert.

Release-Überprüfung

  • Erforderliche Prüfungen (Unit-Tests, schnelle Integration, PostgreSQL-Vertrag, SQLAlchemy 2.0/2.1-Matrix, Box-Integration, E2E-Startup, Core Smoke, Regressionstools, Lint) wurden beim Release-Commit übergeben. – Vor dem Markieren wurde der Release Candidate installiert und durch Routinevorgänge mit Docker (docker compose --profile box) und uvx (uvx --from <wheel> langbot, Abhängigkeiten aufgelöst von PyPI: SDK 0.7.24, SQLAlchemy 2.1.8) ausgeführt. Bei jedem Lauf wurde ein neues Datenverzeichnis verwendet. Die Prüfungen umfassten die Kontoeinrichtung, die WebUI, die Marketplace-Installation mit Berechtigungsbestätigung, Aktivierung und Deinstallation, Modelle, eine LocalAgent-Pipeline über HTTP-Bot mit einem Tool-Aufruf in der Box-Sandbox, die !help !cmd !func !plugin !version-Befehle, die Aufnahme und den Abruf der Wissensdatenbank sowie die Persistenz nach einem Neustart. Die gleichen Prüfungen wurden mit uvx unter Windows 11 (Codepage 936) für den Kandidaten v4.11.6 durchgeführt; v4.11.7 ändert darüber hinaus lediglich die plattformunabhängige Zähllogik, darunter ein Plugin zum Drucken von Chinesisch und Emojis sowie eine erste LocalAgent-Konversation mit blockierten Tokenizer-Downloads (ca. 4 s, kein Netzwerkzugriff). – Dify 1.18.0-Workflows mit menschlicher Eingabe wurden durchgehend über DifyAgent über HTTP-Bot ausgeführt. – v4.11.7 fügt eine Parallelitätsprüfung hinzu: 8–24 gleichzeitige LocalAgent-Konversationen auf einem Modell, ohne Ablehnungen der Tokenanzahl (v4.11.6 lehnte 3–6 Zählungen pro 24-Konversationsrunde ab). Ein direktes Upgrade von v4.11.6-Daten wurde ebenfalls überprüft.

LangBot v4.11.7

Highlights

  • Upgrade now if you're on v4.11.6 — That build was withdrawn: it rejected concurrent token counts on a shared model, so simultaneous LocalAgent sessions silently degraded to rough estimates and could fail mid-turn. v4.11.7 is the final stable 4.11.x release, contains no new features, and was verified with an in-place upgrade of 4.11.6 data — treat it as a drop-in corrective patch, not a feature drop.
  • Concurrent token counting restored — Counts against the same model are no longer rejected simply because another is in flight; only a count that has outlived its caller (timed out or cancelled) now blocks new ones. The release added a stress check of 8–24 simultaneous LocalAgent conversations on one model with no rejections, versus 3–6 rejected counts per 24-conversation round on 4.11.6 — the core regression for anyone running multi-session bots.
  • Windows: offline, encoding-safe token counting — LiteLLM's Windows wheels ship CRLF tokenizer files that fail tiktoken's hash check and trigger a download; with no network, every process's first conversation stalls ~30s (count_tokens call timed out). LangBot now normalizes those files into data/tiktoken_cache at startup for fully offline counting, and a timeout/failure falls back to a local estimate instead of failing the whole turn. Plugin print of Chinese text or emoji also no longer disconnects the runtime with 'gbk' codec can't encode (SDK 0.7.24).
  • Plugin and runner lifecycle hardened — Startup/reconnect now waits for installed plugins to finish initializing before dispatching, eliminating spurious Agent runner not found: plugin:langbot-team/LocalAgent/default errors, and reconnects hold workspace sync and event dispatch for up to 30s rather than failing in the disconnect window. The knowledge-base vector backend is created off the event loop, so first-time ingestion on a slow host no longer blocks the loop and drops the plugin runtime.
  • Non-Docker, sandbox, and legacy-adapter fixes — pip/uvx installs on SQLAlchemy 2.1 hit unknown ON CONFLICT update shape on the first plugin-storage write; the dependency is now capped at <2.2 and the SQLite write lock is released during image refresh to curb database is locked. Box sandbox runs overlong commands via a temp script (fixing Argument list too long and large-attachment imports), and runner interactions such as Dify human-input nodes now fall back to text on HTTP Bot/OneBot instead of throwing get_interaction_capabilities.
  • SDK, plugins, and telemetry housekeeping — langbot-plugin is pinned 0.7.23 → 0.7.24, a prerequisite for the Windows/SDK fixes; EssentialCommands 0.1.12 repairs !func, HelloPlugin 0.1.6 drops debug output, and LocalAgent 0.2.10 / CozeAgent 0.2.5 / DifyAgent 0.2.8 are on the Marketplace. Telemetry now records cancelled executions as cancelled rather than failed, preserves error details on routing failures, and stops tool sources (mcp/skill) from overwriting the platform field.

No breaking changes.

LangBot v4.11.7

The final stable release of the 4.11.x line. It replaces v4.11.6, which has been withdrawn: v4.11.6 rejected concurrent token counts on a shared model, so LocalAgent conversations running at the same time could fall back to rough estimates and fail. If you installed v4.11.6, upgrade to v4.11.7.

本版本是 4.11.x 的最终稳定版，取代已撤回的 v4.11.6。v4.11.6 在多个会话同时使用同一模型时会拒绝并发的 token 计数，LocalAgent 因此改用粗略估算，部分对话会失败。已安装 v4.11.6 的用户请升级到 v4.11.7。

It contains no new features. It fixes the failures reported by 4.11.x instances through LangBot Space telemetry, and updates the plugin SDK and the official plugins involved.

Fixes / 修复

  • Concurrent token counting / 并发 Token 计数（v4.11.6 回归）：同一模型上的并发计数不再被拒绝；只有超时或被取消后仍在运行的计数，才会阻止新的计数。Concurrent token counts on one model are no longer rejected; only a count that outlived its caller blocks new ones.
  • Windows plugins / Windows 插件：插件 print 中文或 emoji 不再导致插件运行时断连，也不再出现 'gbk' codec can't encode 报错（SDK 0.7.24）。A plugin printing Chinese text or emoji no longer disconnects the plugin runtime on Chinese-locale Windows.
  • Windows token counting / Windows Token 计数：LiteLLM 的 Windows 安装包自带的 tokenizer 文件是 CRLF 换行，校验失败后会重新从 openaipublic 下载；网络不通时，每个进程的首次对话都会卡住（遥测里的 30 秒 count_tokens call timed out）。LangBot 现在启动时会把这些文件转成 LF 存到 data/tiktoken_cache，计数完全离线。另外，计数超时或失败时 LocalAgent 改用本地估算继续对话，不再整轮失败。LiteLLM's Windows wheels ship CRLF tokenizer files that fail tiktoken's hash check and trigger a download; LangBot now keeps a normalized offline copy, and a counting failure no longer fails the LocalAgent turn.
  • Runner availability / Runner 可用性：启动或重连期间，等待已安装插件完成初始化后再派发，不再报 Agent runner not found: plugin:langbot-team/LocalAgent/default。
  • Plugin runtime / 插件运行时：运行时重连期间，工作区同步和事件派发会先等待重连完成（最多 30 秒），不再在断连窗口内失败；附件和流的体积超限报错会给出实际大小和处理建议（SDK）。
  • Knowledge base / 知识库：向量库后端在后台线程中初始化。之前在较慢的机器上，首次入库会阻塞事件循环，导致插件运行时断连、入库失败。The vector backend is created off the event loop; the first ingestion on a slow host no longer drops the plugin runtime connection.
  • SQLite / SQLAlchemy：非 Docker 安装（pip / uvx）在 SQLAlchemy 2.1 上首次写入插件存储时报 unknown ON CONFLICT update shape 的问题已修复，依赖上限设为 <2.2；图片刷新期间释放 SQLite 写锁，减少 database is locked。
  • Box sandbox / Box 沙箱：过长的命令改为通过临时脚本执行，修复 Argument list too long 和大附件导入失败（SDK）。
  • Runners：Coze / Dify 处理已完成和 workflow 类型的输出，不再把这类响应当成空响应；LocalAgent 推理配置为空时不再报错。命令错误响应的反序列化不再崩溃（SDK）。
  • Runner interactions / Runner 交互：HTTP Bot、OneBot 等旧版适配器上，Runner 发起的交互（例如 Dify 工作流的人工输入节点）不再报 get_interaction_capabilities 错误，改为文本问答。Runner interactions on legacy adapters (HTTP Bot, OneBot, …) fall back to text instead of failing.
  • Telemetry / 遥测归因：取消的执行记为 cancelled 而不是失败；路由失败时保留错误详情；已经是终态的执行不再报转换错误；执行链的平台字段不再被工具来源（mcp / skill 等）覆盖。
  • Official plugins / 官方插件：EssentialCommands 0.1.12 修复 !func；HelloPlugin 0.1.6 去掉调试输出；LocalAgent 0.2.10、CozeAgent 0.2.5、DifyAgent 0.2.8 已在 Marketplace 上架。
  • SDK：langbot-plugin 由 0.7.23 固定到 0.7.24。

Release verification

  • Required checks (unit tests, fast integration, PostgreSQL contract, SQLAlchemy 2.0 / 2.1 matrix, Box integration, E2E startup, Core smoke, regression tools, lint) passed on the release commit.
  • Before tagging, the release candidate was installed and run through routine operations with both Docker (docker compose --profile box) and uvx (uvx --from <wheel> langbot, dependencies resolved from PyPI: SDK 0.7.24, SQLAlchemy 2.1.8). Each run used a fresh data directory. The checks covered account setup, the WebUI, Marketplace install with permission confirmation, enable and uninstall, models, a LocalAgent pipeline over HTTP Bot with a tool call in the Box sandbox, the !help !cmd !func !plugin !version commands, knowledge-base ingestion and retrieval, and persistence after a restart. The same checks were run with uvx on Windows 11 (code page 936) for the v4.11.6 candidate; v4.11.7 only changes platform-independent counting logic on top of it, including a plugin printing Chinese and emoji, and a first LocalAgent conversation with tokenizer downloads blocked (about 4 s, no network access).
  • Dify 1.18.0 human-input workflows were run end to end through DifyAgent over HTTP Bot.
  • v4.11.7 adds a concurrency check: 8–24 simultaneous LocalAgent conversations on one model, with no token-count rejections (v4.11.6 rejected 3–6 counts per 24-conversation round). An in-place upgrade from v4.11.6 data was also verified.
