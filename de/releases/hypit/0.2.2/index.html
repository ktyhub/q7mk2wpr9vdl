hypit v0.2.2

Patch Veröffentlicht17. Sept. 2026 Quellehypit-ai/hypit Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

#hypit v0.2.2

Korrektheit der Windows Media-Umgebung und des Anmeldeinformationsspeichers

Diese Version enthält Windows-Ausführungskorrekturen und eine Änderung an der Auswahl des Anmeldeinformationsverzeichnisses. Vorhandene Profile mit einem Datei- oder Plattformspeicherpfad außerhalb des Host-Statusstamms werden von 0.2.2 abgelehnt; Dies ist eine Verhaltensänderung gegenüber 0.2.1. Die Auswahl des neuen Starter-Stores gilt nur für neu initialisierte Profile.

Windows Media-Ausführung

ffmpeg und ffprobe werden mit einer Whitelist von Umgebungsvariablen gestartet, sodass die Host-Umgebung von untergeordneten Medien ferngehalten wird. Diese Whitelist wurde für POSIX geschrieben, daher erhielten Windows-Kinder weder %TEMP% noch %TMP% und konnten ihre temporären Dateien nicht erstellen. Sowohl der HyperFrames-Renderpfad als auch der Shared-Media-Ausführungspfad enthalten jetzt neben der POSIX-Liste auch eine Windows-Liste. Gastgebergeheimnisse werden weiterhin geheim gehalten. (#259, #260)

Anmeldeinformationsspeicher

  • runtime init schreibt ein Starterprofil, das @hypit/credential-store-platform auswählt, sodass das von ihm erstellte Profil sowohl unter Linux als auch unter macOS und Windows geöffnet und geschrieben wird. macOS und Windows behalten den Plattform-Schließer unter demselben Dienst und Schlüssel, sodass vorhandene Anmeldeinformationen weiterhin gefunden werden. os, file und env bleiben namentlich auswählbar. (#247) – Der config.path eines Profils für die Datei- und Plattformspeicher wird anhand des Host-Statusstamms aufgelöst und auf Eindämmung überprüft. Ein Pfad, der diesem Stamm entgeht, wird beim Öffnen des Stores abgelehnt. Bisher wurde ein absoluter Pfad außerhalb des Stammverzeichnisses akzeptiert, jetzt jedoch nicht mehr. (#265)
  • Das Lesen und Ersetzen eines Ausweisdokuments erfolgt innerhalb eines Prozesses abwechselnd. resolve hält das Dokument für den gesamten Lesevorgang geöffnet, während put es durch eine Umbenennung ersetzt, und die Windows-Umbenennungsimplementierung von Node verwendet MoveFileExW, das die Ersetzung verweigern kann, während das Ziel geöffnet ist. Die prozesslokale Ordnung reduziert diese Überlappung innerhalb eines Prozesses; Es koordiniert keine separaten CLI- und Worker-Prozesse. Fehler beim prozessübergreifenden Ersetzen bleiben in 0.2.2 bestehen. Schlüssel bleiben unabhängig. (#276) – Der Windows-Anmeldeinformationsmanager-Helfer ist an das gleiche 10-Sekunden-Timeout wie der macOS-Aufruf security(1) gebunden, sodass ein blockierter Schließfach fehlschlägt, anstatt den CLI aufzuhängen. (#261)

Laufzeit und CLI

– programs down behandelt ein Programm ohne gültige Hypit-PID und ohne start-Befehl so, als hätte es nichts zu stoppen, und meldet No external programs to stop, anstatt 1 zu beenden. Die media.local und hyperframes.local des Starterprofils deklarieren nur probe(), sodass ein bereiter Prüfpunkt bedeutet, dass das Tool installiert ist und nicht, dass ein Prozess ausgeführt wird. Ein startfähiges Programm, das ohne Hypit-PID bereit ist, meldet immer noch not-ours. (#272)

  • Die Übersichtshilfe listet programs prepare|up|status|down auf, und programs und runtime ohne ausgewähltes Profil melden denselben Wiederherstellungssatz, den build, pricing, auth und die Ausführungsbefehle bereits verwenden. (#266) – Drei Pakete deklarieren die Arbeitsbereichspakete, die ihre Quellen importieren. (#253)

Dokumentation

– Der Build-Workflow-Abschnitt des englischen Schnellstarts enthält die Abhängigkeitsvorbereitung, .gitignore, die gemeinsam genutzte Asset-Bibliothek und das Archivbefehlsmaterial, über das das chinesische Gegenstück bereits verfügte. (#275) – auth status-Beispiele enthalten das erforderliche Endpunktargument. (#254)

Englisches Original / English original

hypit v0.2.2

Windows media environment and credential store correctness

This release includes Windows execution fixes and a change to credential directory selection. Existing Profiles with a file or platform Store path outside the Host state root are rejected by 0.2.2; this is a behavior change from 0.2.1. The new starter Store selection applies only to newly initialized Profiles.

Windows media execution

ffmpeg and ffprobe are started with a whitelist of environment variables so the Host environment stays out of media children. That whitelist was written for POSIX, so Windows children received neither %TEMP% nor %TMP% and failed to create their temporary files. Both the HyperFrames render path and the shared media execution path now carry a Windows list alongside the POSIX one. Host secrets are still withheld. (#259, #260)

Credential storage

  • runtime init writes a starter Profile that selects @hypit/credential-store-platform, so the Profile it produces opens and writes on Linux as well as macOS and Windows. macOS and Windows keep the platform locker under the same service and key, so an existing credential is still found. os, file and env remain selectable by name. (#247)
  • A Profile's config.path for the file and platform stores is resolved against the Host state root and checked for containment. A path that escapes that root is rejected when the Store opens. An absolute path outside the root was previously accepted and now is not. (#265)
  • Reads and replacements of one credential document take their turn within a process. resolve holds the document open for the whole read while put replaces it with a rename, and Node’s Windows rename implementation uses MoveFileExW, which can refuse replacement while the destination is open. The process-local ordering reduces this overlap within one process; it does not coordinate separate CLI and Worker processes. Cross-process replacement failures remain in 0.2.2. Keys stay independent. (#276)
  • The Windows Credential Manager helper is bounded to the same 10 second timeout as the macOS security(1) call, so a stuck locker fails instead of hanging the CLI. (#261)

Runtime and CLI

  • programs down treats a Program with no valid Hypit PID and no start command as having nothing to stop, and reports No external programs to stop instead of exiting 1. The starter Profile's media.local and hyperframes.local declare only probe(), so a ready probe means the tool is installed, not that a process is running. A startable Program that is ready without a Hypit PID still reports not-ours. (#272)
  • The overview help lists programs prepare|up|status|down, and programs and runtime without a selected Profile report the same recovery sentence that build, pricing, auth and the execution commands already use. (#266)
  • Three packages declare the workspace packages their sources import. (#253)

Documentation

  • The English quickstart's Build workflow section carries the dependency preparation, .gitignore, shared asset library and archive command material its Chinese counterpart already had. (#275)
  • auth status examples carry the required endpoint argument. (#254)
