ECC v2.0.0

ECC 2.0.0 ist die stabile Weiterentwicklung der 2.0-Linie: ECC als Cross-Harness-Betriebssystem für Agentenarbeit. Claude Code bleibt erstklassig; Codex-, OpenCode-, Cursor-, Gemini-, Zed- und Terminal-Workflows verfügen über dieselben Fähigkeiten, Regeln, Hooks, MCP-Konventionen, Release-Gates und Bediener-Workflows. Dies ist die seit Monaten in Arbeit befindliche Veröffentlichung, auf die der rc.1-Kandidat hingearbeitet hat.

Der Kontrollbereich (früher Build)

Die ECC 2.0-Bedienoberfläche, die lokal ausgeführt wird (node scripts/control-pane.js): Operator-Rückrufsuche, Live-Sitzungsmetriken, ein Arbeitselement-Board mit den Spuren „Bereit“, „Läuft“, „Blockiert“ und „Erledigt“ sowie eine Operator-Spalte, die die Wissenssynchronisierung/-abfrage steuert, Diagramm-Backfill und die TUI. Die folgenden Sitzungsadapter und das MCP-Inventar versorgen dieses Board. Build-in-public wird im Discord #control-pane-Kanal fortgesetzt.

Was ist neu?

  • 261 öffentliche Fähigkeiten in den Bereichen Codierung, Forschung, Sicherheit, Medien, Unternehmensbetrieb und Agenten-Workflows (rc.1 wurde mit 243 ausgeliefert) – plus 64 Agenten und 84 Befehle.
  • Das Bedienfeldsubstrat – die Grundlage der ECC 2.0-Bedienoberfläche:
    • Harness-neutrale Sitzungsadapter (ecc.session.v1), die Claude Code, Codex, OpenCode und dmux abdecken – ein Schema für „Welcher Agent ist wo und tut was?“
    • MCP-Inventar (ecc.mcp.v1) – eine normalisierte Ansicht jeder MCP-Serverkonfiguration über mehrere Kabelbäume hinweg, mit Fragmentierungs-/Drift-Erkennung und geheimer Schwärzung (während der Entwicklung wurde ein echtes arg-getragenes Schlüsselleck entdeckt)
    • Worktree-Lifecycle-Dienst – deterministische Zusammenführungskonfliktvorhersage und sichere GC für parallele Agenten-Arbeitsbäume
  • orch-* Orchestrator-Skill-Familie plus dynamische Workflow-Team-Orchestrierung – Multi-Agent-Fanout als erstklassige Oberfläche.
  • Einzel-Connector-MCP-Standardrichtlinie – der Standardsatz umfasst jetzt genau einen Connector (chrome-devtools); Die anderen sechs haben sich nach einer Prüfung im Juni 2026 zurückgezogen, um sich für die Teilnahme zu entscheiden. Richtlinie + Begründung pro Connector: docs/MCP-CONNECTOR-POLICY.md.
  • Vom Rollout abgeleitetes Optimierungspaket: parallel-execution-optimizer, benchmark-optimization-loop, data-throughput-accelerator, latency-critical-systems, recursive-decision-ledger.

Verhärtung seit rc.1 (~30 PRs)

  • Plugin-Hooks waren stillschweigend No-Ops auf Knoten 21+ (#2184) – der Hook-Runner war von require.main unter node -e abhängig; Jeder Plugin-Hook wurde sauber beendet, ohne ausgeführt zu werden. Wenn Sie auf Knoten 21+ sind, aktualisieren Sie jetzt. – Windows-Zuverlässigkeit: CLAUDE_PLUGIN_ROOT-Normalisierung (#2139), Standard-Eingabeaufforderungsübergabe (#2174), Symlink/chmod-Testwächter (#2171, #2176). – Sicherheit: Curl-Anmeldeinformationen aus argv (#2175), Gateguard-Destructive-Checkout-Gating (#2158) + Env-Knöpfe (#2161), beratende Einlasshärtung. – Korrektheit: $-Sequenzbeschädigung am Sitzungsende (#2180), Übereinstimmung der Projekterkennungsgrenzen (#2181), Lücken im Installationsmanifest (#2172), Legacy-Shim-Kürzung (#2167).
  • Schlankere Standardeinstellungen: kleinere OpenCode-Oberfläche (#2140), rules/zh aus der Standardinstallation (#2170).

Englisches Original / English original

ECC v2.0.0

Highlights

  • Stable cross-harness release, not a no-op — v2.0.0 graduates the 2.0 line from rc.1 into a stable "operating system" for agentic work: the same skills, rules, hooks, MCP conventions, and release gates now span Claude Code (still first-class), Codex, OpenCode, Cursor, Gemini, Zed, and terminal-only workflows. Real content growth — 261 public skills vs. 243 in rc.1, plus 64 agents and 84 commands — and a new orch-* orchestrator family with dynamic workflow team orchestration making multi-agent fan-out a first-class surface. This is a substantive release, not a re-tag or metadata-only update.

  • Breaking — MCP connector defaults narrowed and install slimmed — The default MCP set is now exactly one connector, chrome-devtools; the other six were retired to opt-in after a June 2026 audit (policy and per-connector rationale in docs/MCP-CONNECTOR-POLICY.md). Anyone who relied on those six being enabled by default must now explicitly opt in. Defaults also got thinner: a smaller OpenCode surface (#2140) and rules/zh removed from the default install (#2170) — verify your install manifest if you depended on either.

  • Critical fix — plugin hooks were silent no-ops on Node 21+ (#2184) — The hook runner depended on require.main under node -e, so on Node 21+ every plugin hook exited cleanly without ever executing. If you're on Node 21+, this alone makes updating urgent. Hardening also moved curl credentials out of argv (#2175), added gateguard destructive-checkout gating (#2158) with env knobs (#2161), and fixed session-end $-sequence corruption (#2180) and project-detect boundary matching (#2181).

  • New but early — control pane operating surface — A locally run operator UI (node scripts/control-pane.js) built on harness-neutral session adapters (ecc.session.v1), an MCP inventory (ecc.mcp.v1) with drift detection and secret redaction, and a worktree-lifecycle service with merge-conflict prediction and safe GC. It's explicitly an early build under active development (Discord #control-pane), so treat it as foundational infrastructure rather than a finished feature.

  • Upgrade guidance — Upgrade if you're on rc.1 (this is the stable it was building toward), on Node 21+ (hooks fix), or relying on the retired MCP defaults/language rules (you'll need to adapt). Skip if you're a single-harness Claude Code user below Node 21 who doesn't need cross-harness support or the control pane — for you the gain is mostly ~18 more skills and hardening. Upgrade with /plugin update ecc (fresh installs: /plugin marketplace add https://github.com/affaan-m/ECC then /plugin install ecc).

ECC 2.0.0 is the stable graduation of the 2.0 line: ECC as a cross-harness operating system for agentic work. Claude Code stays first-class; Codex, OpenCode, Cursor, Gemini, Zed, and terminal-only workflows share the same skills, rules, hooks, MCP conventions, release gates, and operator workflows. This is the months-in-the-making release the rc.1 candidate was building toward.

The control pane (early build)

The ECC 2.0 operating surface, running locally (node scripts/control-pane.js): operator recall search, live session metrics, a work-items board with ready/running/blocked/done lanes, and an operator column that drives knowledge sync/recall, graph backfill, and the TUI. The session adapters and MCP inventory below feed this board. Build-in-public continues in the Discord #control-pane channel.

What is new

  • 261 public skills across coding, research, security, media, enterprise ops, and agent workflows (rc.1 shipped 243) — plus 64 agents and 84 commands.
  • The control-pane substrate — the foundation of the ECC 2.0 operating surface:
    • harness-neutral session adapters (ecc.session.v1) covering Claude Code, Codex, OpenCode, and dmux — one schema for "which agent is where, doing what"
    • MCP inventory (ecc.mcp.v1) — one normalized view of every MCP server config across harnesses, with fragmentation/drift detection and secret redaction (it caught a real arg-carried key leak during development)
    • worktree-lifecycle service — deterministic merge-conflict prediction and safe GC for parallel agent worktrees
  • orch-* orchestrator skill family plus dynamic workflow team orchestration — multi-agent fan-out as a first-class surface.
  • Single-connector MCP default policy — the default set is now exactly one connector (chrome-devtools); the other six retired to opt-in after a June 2026 audit. Policy + per-connector rationale: docs/MCP-CONNECTOR-POLICY.md.
  • Rollout-derived optimization pack: parallel-execution-optimizer, benchmark-optimization-loop, data-throughput-accelerator, latency-critical-systems, recursive-decision-ledger.

Hardening since rc.1 (~30 PRs)

  • Plugin hooks were silently no-ops on Node 21+ (#2184) — the hook runner depended on require.main under node -e; every plugin hook exited cleanly without running. If you are on Node 21+, update now.
  • Windows reliability: CLAUDE_PLUGIN_ROOT normalization (#2139), stdin prompt passing (#2174), symlink/chmod test guards (#2171, #2176).
  • Security: curl credentials out of argv (#2175), gateguard destructive-checkout gating (#2158) + env knobs (#2161), advisory intake hardening.
  • Correctness: session-end $-sequence corruption (#2180), project-detect boundary matching (#2181), install manifest gaps (#2172), legacy shim truncation (#2167).
  • Slimmer defaults: smaller OpenCode surface (#2140), rules/zh out of the default install (#2170).
