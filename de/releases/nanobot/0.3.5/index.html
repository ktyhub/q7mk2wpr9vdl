Nanobot v0.3.5

🐈 Nanobot v0.3.5 bringt die Werkbank auf das Terminal – und erleichtert die Fortsetzung von Gesprächen über den Browser, das Terminal und die Chat-Apps.

Die Überschrift lautet ein Agent, mehr Arbeitsplätze. Führen Sie nanobot für das native Terminal client oder nanobot webui für den Browser aus. Beide verwenden dasselbe Gateway und speichern WebSocket-Konversationen. Terminalsitzungen können fortgesetzt, gegabelt, überprüft und getrennt werden, ohne dass eine separate Agentenlaufzeit erstellt werden muss.

Die Browser-Workbench ist rund um echtes Multitasking gewachsen: gruppierte Konversationsbereiche, temporäre Chats, dauerhafte Seitenleistenreihenfolge, Sitzungserwähnungen, ein Skills-Marktplatz, tragbare Agent-Plugins und Browser-OAuth für Remote-MCP-Server. Automatisierungen verfügen jetzt über Aufgaben- und Kalenderansichten, klarere Planungskontrollen und Antworten pro Lauf. Mobile Komposition, Einstellungen, Kontextdiagramme, App-Logos und Markenerwähnungen erhielten eine weitere Runde gezielter Verfeinerung.

Die andere Geschichte ist Kontinuität, die Sie überprüfen können. Kontextnutzung und Komprimierung sind sichtbar, unterbrochene Arbeit verfügt über klarere Wiederherstellungskontrollen und der Sitzungsverlauf ist bei Paginierung, erneuten Verbindungen und Upgrades langlebiger. Diese Version verschärft außerdem die Grenzen für Anhänge, Prozesse, Arbeitsbereiche und E-Mail-Authentifizierung. Bitte lesen Sie die Upgrade-Hinweise, bevor Sie eine bestehende Installation ersetzen.

Highlights

  • Eine native Terminal-Workbench – Beginnen Sie mit nanobot, wechseln Sie Sitzungen, fügen Sie unterstützte clipboard-Bilder ein, vervollständigen Sie App- und Skill-Referenzen, überprüfen Sie Kontext- und Dateiunterschiede, stellen Sie Nachverfolgungen in die Warteschlange und verwenden Sie /detach, um das Gateway laufen zu lassen.
  • Browser-Konversationen nebeneinander – Ordnen Sie bis zu vier Themen in veränderbaren Gruppen an, behalten Sie die Reihenfolge in der Seitenleiste bei, ziehen Sie gespeicherte Sitzungen in Erwähnungen und verwenden Sie temporäre Chats, wenn Sie kein dauerhaftes Thema wünschen.
  • Automatisierungen, die einfacher zu verwalten sind – Wechseln Sie zwischen Aufgaben- und Kalenderansichten, überprüfen Sie Laufantworten und passen Sie Zeitpläne mit klareren Steuerelementen an. Beim Bearbeiten eines Jobs bleiben ausstehende Ausführungen erhalten; Durch das Löschen wird die Navigation nicht mehr blockiert.
  • Sichtbarer Kontext und gleichmäßigere lange Sitzungen – Token-/Cache-Diagramme pro Runde, Fortschritt der Kontextkomprimierung, seitenweise Suche nach Verlauf, kumulative Zusammenfassungen und Dateilesededuplizierung, die auf den tatsächlichen Modellkontext beschränkt ist.
  • Apps und Skills mit klareren Identitäten – SkillHub-Erkennung, tragbare Agent-Plugins, Remote-MCP-OAuth und Token-Aktualisierung, sichtbare Verbindungsfehler und konsistente App-Logos und Markennamen im Chat.
  • Ein besseres Erlebnis auf kleinen Bildschirmen – Installation auf dem Startbildschirm durch PWA-Unterstützung, schmalere Composer-Steuerelemente, ziehbare Kontextblätter, berührungsfreundliche Diagrammdetails und eine Einstellungsnavigation, die der Öffnungsrichtung entspricht.
  • Breitere Modell- und Suchoptionen – DeepSeek Responses und V4 Vision-Unterstützung, Eden AI- und OrcaRouter-Gateways, AnySearch, Online-OAuth-Modellkataloge und robusteres Anbieter-Fallback und Responses-Verlaufsmanagement.
  • Zuverlässigere Kanäle und Laufzeitgrenzen – Umfangreiches Telegram-Streaming, verbessertes Feishu-Onboarding, sicherere QQ-Anhänge, trusted-E-Mail-Authentifizierungsergebnisse, optionale macOS Seatbelt-Isolation und weniger durchgesickerte Anmeldeinformationen in Unterprozessumgebungen.
  • Einbettung und Betrieb – SDK-Host-Integrations-Hooks, expliziter Desktop-Anhang, Gateway-Bereitschaftsberichte und überprüfte, versionierte Terminalverteilungen.

Upgrade-Hinweise

  • Konfiguration, Arbeitsbereiche und Sitzungsspeicher sichern; Stoppen Sie zuerst alte Prozesse. Sitzungs-JSONL-Dateien befinden sich jetzt im sessions/<workspace-id>/-Baum des Konfigurationsverzeichnisses. Der erste aktualisierte Start migriert vorhandene Arbeitsbereichssitzungen nach Überprüfung der Kopie. Lassen Sie nicht zu, dass alte und neue Versionen gleichzeitig denselben Arbeitsbereich schreiben. Stoppen Sie vor dem Downgrade den Nanobot und verwenden Sie nanobot sessions restore-workspace --config <config.json> --workspace <workspace>. Der Befehl weigert sich, eine andere vorhandene Datei zu überschreiben. Weitere Informationen finden Sie im Anleitung zu Sitzungsspeicherung und Rollback.
  • Die E-Mail-Verifizierung erfordert einen expliziten Empfängeranker trust. Wenn verifySpf oder verifyDkim aktiviert ist, konfigurieren Sie channels.email.trustedAuthservIds mit der genauen Identität, die von Ihrem empfangenden E-Mail-Dienst bestätigt wurde. Dieser Dienst muss gefälschte Header entfernen, die seine Identität beanspruchen, und einen konsolidierten Header für Authentifizierungsergebnisse bereitstellen. Vorhandene verifizierte E-Mail-Konfigurationen ohne dieses Feld werden nicht gestartet. E-Mail bis zur Konfiguration deaktiviert lassen; Deaktivieren Sie die Überprüfung nicht als Problemumgehung. Befolgen Sie die E-Mail-Upgrade-Anleitung.
  • Einfaches nanobot öffnet die native Terminal-Benutzeroberfläche. Verwenden Sie nanobot --classic für die Python-Eingabeaufforderung oder nanobot -m "Hello!" für die einmalige Verwendung. Plattformräder umfassen sowohl die WebUI als auch die passende TUI, sodass für den ersten TUI-Start weder Bun noch ein GitHub-Download erforderlich sind. Unterstützte Räder zielen auf macOS 13+ arm64/x64, glibc 2.17+ Linux arm64/x64 und Windows x64. Andere Plattformen und Quellverteilungs-Builds können die klassische Eingabeaufforderung oder die WebUI verwenden. Die Entwicklung bearbeitbarer Quellen verwendet Bun.
  • Der zuletzt angeschlossene client besitzt die Lebensdauer des On-Demand-Gateways. Das Schließen des letzten interaktiven WebUI/TUI-Launchers stoppt dieses Gateway. Verwenden Sie /detach im Terminal oder nanobot gateway --background für Arbeiten, die ohne client fortgesetzt werden müssen.
  • Remote-Projektauswahl verwendet Pfade auf dem Nanobot-Host. Es erfordert eingeschränkten Zugriff. Es wird kein Verzeichnis vom Browsergerät ausgewählt und entfernte clients können den Vollzugriff nicht aktivieren.
  • Die Antwort auf den Gateway-Zustand ist informativer. /health kann HTTP 503 zurückgeben, wenn sein aktivierter WebSocket-Kanal nicht ausgeführt wird. Es werden keine Modell-, MCP- oder andere Kanalkonnektivität zertifiziert. Update-Überwachung, bei der zuvor davon ausgegangen wurde, dass jeder Live-Prozess 200 zurückgab.
  • Überprüfen Sie die Parallelitäts- und Zeitüberschreitungsgrenzen erneut. NANOBOT_MAX_CONCURRENT_REQUESTS ist unbegrenzt, sofern es nicht auf eine positive Ganzzahl festgelegt ist. Konfigurieren Sie eine explizite Obergrenze, wenn Ihre Bereitstellung eine solche erfordert. Die Subagenten-Parallelität ist standardmäßig auf vier eingestellt und überschüssige Arbeit wartet auf Kapazität. Die alten Felder agents.defaults.failOnToolError und NANOBOT_LLM_TIMEOUT_S werden nicht mehr verwendet. Modellströme, einschließlich interner Aufgaben, verwenden NANOBOT_STREAM_IDLE_TIMEOUT_S (standardmäßig 90 Sekunden), das bei jedem Ereignis erneuert wird, und nicht ein festes Zeitlimit für die Gesamtdauer.

nanobot v0.3.5

🐈 nanobot v0.3.5 brings the workbench to the terminal — and makes conversations easier to continue across the browser, terminal, and chat apps.

The headline is one agent, more places to work. Run nanobot for the native terminal client or nanobot webui for the browser. Both use the same gateway and saved WebSocket conversations. Terminal sessions can be resumed, forked, inspected, and detached without building a separate agent runtime.

The browser workbench has grown around real multitasking: grouped conversation panes, temporary chats, persistent sidebar ordering, session mentions, a skills marketplace, portable Agent Plugins, and browser OAuth for remote MCP servers. Automations now have task and calendar views, clearer scheduling controls, and per-run replies. Mobile composition, settings, context charts, app logos, and branded mentions received another round of focused polish.

The other story is continuity you can inspect. Context usage and compaction are visible, interrupted work has clearer recovery controls, and session history is more durable across pagination, reconnects, and upgrades. This release also tightens attachment, process, workspace, and email-authentication boundaries. Please read the upgrade notes before replacing an existing installation.

Highlights

  • A native terminal workbench — Start with nanobot, switch sessions, paste supported clipboard images, complete app and skill references, inspect context and file diffs, queue follow-ups, and use /detach to leave the gateway running.
  • Browser conversations side by side — Arrange up to four topics in resizable groups, keep sidebar ordering, drag saved sessions into mentions, and use temporary chats when you do not want a persistent topic.
  • Automations that are easier to manage — Switch between task and calendar views, inspect run replies, and adjust schedules with clearer controls. Editing a job preserves pending executions; deleting one no longer leaves navigation blocked.
  • Visible context and steadier long sessions — Per-round token/cache charts, context-compaction progress, paged history search, cumulative summaries, and file-read deduplication scoped to the actual model context.
  • Apps and skills with clearer identities — SkillHub discovery, portable Agent Plugins, remote MCP OAuth and token refresh, visible connection failures, and consistent app logos and brand names in chat.
  • A better small-screen experience — Home-screen installation through PWA support, narrower composer controls, draggable context sheets, touch-friendly chart details, and settings navigation that matches its opening direction.
  • Broader model and search choices — DeepSeek Responses and V4 vision support, Eden AI and OrcaRouter gateways, AnySearch, online OAuth model catalogs, and more resilient provider fallback and Responses-history handling.
  • More reliable channels and runtime boundaries — Rich Telegram streaming, improved Feishu onboarding, safer QQ attachments, trusted email authentication results, optional macOS Seatbelt isolation, and fewer leaked credentials in subprocess environments.
  • Embedding and operations — SDK host integration hooks, explicit Desktop attachment, gateway readiness reporting, and checked, version-matched terminal distributions.

Upgrade Notes

  • Back up configuration, workspaces, and session storage; stop old processes first. Session JSONL files now live under the configuration directory's sessions/<workspace-id>/ tree. The first upgraded start migrates existing workspace sessions after verifying the copy. Do not let old and new versions write the same workspace concurrently. Before downgrading, stop nanobot and use nanobot sessions restore-workspace --config <config.json> --workspace <workspace>; the command refuses to overwrite a different existing file. See the session storage and rollback guide.
  • Email verification requires an explicit receiver trust anchor. If verifySpf or verifyDkim is enabled, configure channels.email.trustedAuthservIds using the exact identity confirmed by your receiving mail service. That service must remove forged headers claiming its identity and provide one consolidated authentication-results header. Existing verified Email configurations without this field will not start. Keep Email disabled until configured; do not disable verification as a workaround. Follow the Email upgrade guide.
  • Plain nanobot opens the native terminal UI. Use nanobot --classic for the Python prompt or nanobot -m "Hello!" for one-shot usage. Platform wheels include both the WebUI and the matching TUI, so first TUI launch needs neither Bun nor a GitHub download. Supported wheels target macOS 13+ arm64/x64, glibc 2.17+ Linux arm64/x64, and Windows x64. Other platforms and source-distribution builds can use the classic prompt or WebUI; editable source development uses Bun.
  • The last attached client owns the on-demand gateway lifetime. Closing the last interactive WebUI/TUI launcher stops that gateway. Use /detach in the terminal or nanobot gateway --background for work that must continue without a client.
  • Remote project selection uses paths on the nanobot host. It requires Restricted access. It does not select a directory from the browser device, and remote clients cannot enable Full Access.
  • The gateway health response is more informative. /health can return HTTP 503 when its enabled WebSocket channel is not running. It does not certify model, MCP, or other channel connectivity; update monitoring that previously assumed every live process returned 200.
  • Recheck concurrency and timeout limits. NANOBOT_MAX_CONCURRENT_REQUESTS is unlimited unless set to a positive integer; configure an explicit cap if your deployment needs one. Subagent concurrency defaults to four and excess work waits for capacity. The old agents.defaults.failOnToolError field and NANOBOT_LLM_TIMEOUT_S are no longer used. Model streams, including internal tasks, use NANOBOT_STREAM_IDLE_TIMEOUT_S (90 seconds by default), renewed by each event rather than a fixed total-duration timeout.
