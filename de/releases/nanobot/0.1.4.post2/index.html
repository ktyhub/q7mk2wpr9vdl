Nanobot v0.1.4.post2

🐈 nanobot v0.1.4.post2 ist da – 32 PRs zusammengeführt, 14 neue Mitwirkende! Die Community brennt 🔥 Diese Version konzentriert sich auf Zuverlässigkeit: ein komplett neu gestalteter Heartbeat, sofortiges Caching für niedrigere API-Kosten, verbesserte Anbieterkompatibilität und Dutzende von Korrekturen auf Kanalebene. Weniger Überraschungen, mehr Stabilität.

Highlights

  • Heartbeat-Überholung – Fragile Token-Erkennung durch einen virtuellen Tool-Call-Entscheidungsmechanismus ersetzt; Heartbeat ist jetzt im Leerlauf wirklich still (#1102, #1054, #1039, #1036)
  • Prompt-Cache-Optimierung – Dynamischer Kontext (Zeit, Sitzung) wurde von der System-Eingabeaufforderung in die Benutzernachricht verschoben, wodurch dauerhafte Treffer im Eingabeaufforderungs-Cache möglich sind (#1115)
  • Agent-Zuverlässigkeit – Verhaltenseinschränkungen, vollständiger Tool-Verlauf im Kontext und umsetzbare Fehlerhinweise (#1046)
  • Slack – Thread-isolierte Sitzungen, mrkdwn-Nachbearbeitung für Fett-/Header-Artefakte, Socket-Fehlerbehandlung (#1048, #1107, #957)
  • Feishu – Rich-Text-Bildextraktion in Post-Nachrichten, Datei-Download API-Fix (#1090, #986)
  • E-Mail – Proaktives Versenden von Aufgaben, auch wenn die automatische Antwort deaktiviert ist, intelligentere Deduplizierungsentfernung (#1077, #959)
  • Anbieterkorrekturen – DeepSeek reasoning_content-Normalisierung, Filterung leerer Inhaltsblöcke, API-Schlüssel-Hot-Reload über @property (#947, #955, #949, #1071, #1098)
  • Sicherheit – Pfaddurchquerungsverhinderung mit relative_to() anstelle von startswith() (#956)
  • MCP – Konfigurierbare Zeitüberschreitungen zur Verhinderung von Agent-Hängen, widersprüchliche Standardeinstellungen für HTTP-Transport entfernt (#950, #1062)
  • Speicher – TypeError behoben, wenn LLM während der Konsolidierung Diktargumente zurückgibt (#1061)
  • Discord – Tipp-Indikatorschleife bei anhaltendem HTTP-Fehler unterbrechen (#1029)
  • CLI – DingTalk, QQ, E-Mail zur nanobot status-Ausgabe hinzugefügt (#982)
  • Verpackung – Arbeitsbereichsvorlagen wurden zur ordnungsgemäßen Pip-Verpackung nach nanobot/templates/ verschoben (#1043)
  • Dokumente – Leitfaden zur Bereitstellung des Systemd-Benutzerdienstes (#968)

nanobot v0.1.4.post2

🐈 nanobot v0.1.4.post2 is here — 32 PRs merged, 14 new contributors! The community is on fire 🔥

This release focuses on reliability: a completely redesigned heartbeat, prompt caching for lower API costs, hardened provider compatibility, and dozens of channel-level fixes. Fewer surprises, more stability.

Highlights

  • Heartbeat Overhaul — Replaced fragile token detection with a virtual tool-call decision mechanism; heartbeat is now truly silent when idle (#1102, #1054, #1039, #1036)
  • Prompt Cache Optimization — Dynamic context (time, session) moved from system prompt to user message, enabling persistent prompt cache hits (#1115)
  • Agent Reliability — Behavioral constraints, full tool history in context, and actionable error hints (#1046)
  • Slack — Thread-isolated sessions, mrkdwn post-processing for bold/header artifacts, socket error handling (#1048, #1107, #957)
  • Feishu — Rich-text image extraction in post messages, file download API fix (#1090, #986)
  • Email — Proactive sends work even when autoReply is disabled, smarter dedup eviction (#1077, #959)
  • Provider Fixes — DeepSeek reasoning_content normalization, empty content block filtering, API key hot-reload via @property (#947, #955, #949, #1071, #1098)
  • Security — Path traversal prevention using relative_to() instead of startswith() (#956)
  • MCP — Configurable timeouts to prevent agent hangs, removed conflicting defaults for HTTP transport (#950, #1062)
  • Memory — Fixed TypeError when LLM returns dict arguments during consolidation (#1061)
  • Discord — Break typing indicator loop on persistent HTTP failure (#1029)
  • CLI — DingTalk, QQ, Email added to nanobot status output (#982)
  • Packaging — Workspace templates moved to nanobot/templates/ for proper pip packaging (#1043)
  • Docs — systemd user service deployment guide (#968)
