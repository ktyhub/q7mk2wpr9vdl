Nanobot v0.1.4.post4

🐈 nanobot v0.1.4.post4 ist da – 58 PRs zusammengeführt, 29 neue Mitwirkende und viel echter Feinschliff aus der Community. Diese Version ist eine große Neuerung: sicherere Standardeinstellungen, bessere Unterstützung mehrerer Instanzen, höhere MCP-/Tool-Zuverlässigkeit und wesentliche Verbesserungen bei Telegram, Feishu, QQ, DingTalk, Discord, WhatsApp, Matrix und mehr. In diesem Zyklus wurden eine Menge scharfkantiger Fälle bereinigt – die Art von Korrekturen, die dafür sorgen, dass sich der Nanobot von Tag zu Tag viel stabiler anfühlt.

Highlights

  • Standardmäßig sicherer – Die Zugangskontrolle ist jetzt strenger. Diese Version enthält einen echten Fix zur Autorisierungsumgehung und eine stärkere Standardbehandlung rund um allowFrom, wodurch Bereitstellungen sofort sicherer werden. (#1403, #1677)
  • Multi-Instanz-Unterstützung ist endlich real – --config-Unterstützung eingeführt, Laufzeitpfad-Handhabung wurde bereinigt und der CLI-Agent unterstützt jetzt auch --workspace / --config. Das Ausführen separater Bots, Mandanten oder Umgebungen ist jetzt viel einfacher. (#1581, #1635)
  • MCP wurde härter – SSE-Transportunterstützung ist vorhanden, die automatische Erkennung ist intelligenter und MCP-Tool-Aufrufe unterbrechen den Prozess viel seltener, wenn Abbrüche oder seltsame Fehler auftreten. (#1488, #1728)
  • Werkzeuge sind nachsichtiger geworden – Auto-Casting-Werkzeugparameter, sicherere Validierung, elegante Datums-/Uhrzeitverarbeitung und read_file-Größenbeschränkungen tragen dazu bei, dass Nanobots weniger schlimm ausfallen, wenn Werkzeuge oder Eingaben seltsam werden. (#1610, #1507, #1508, #1511)
  • Die Anbieterunterstützung wächst weiter – Azure OpenAI-Unterstützung ist da, Alibaba Cloud Coding Plan API-Unterstützung wurde eingeführt, Prompt-Caching-Affinitätsheader wurden hinzugefügt und die Kompatibilität von GitHub Copilot/Codex verbessert sich weiter. (#1618, #1563, #1428, #1555, #1637, #1525)
  • Cron ist viel stabiler geworden – Externe jobs.json-Änderungen werden berücksichtigt, die Handhabung des Jobkontexts ist besser und Cron-Jobs dürfen nicht mehr für immer rekursiv weitere Cron-Jobs planen. (#1371, #1375, #1399, #1458)
  • Der Kontext wurde sauberer – Aufeinanderfolgende Benutzernachrichten werden zusammengeführt, um anbieterseitige Fehler zu vermeiden, interne Argumente werden vor benutzerbezogenen Fortschrittsaktualisierungen ausgeblendet, die Bild-MIME-Erkennung ist zuverlässiger und die Eingabeaufforderungs-/Plattformführung ist ausgefeilter. (#1456, #1655, #1573, #1579)
  • Telegram hat viel Zuspruch erhalten – Die Proxy-Verarbeitung wurde korrigiert, Gruppenthemen werden unterstützt, /stop funktioniert besser, Streaming-Nachrichten sind angekommen und generische Dokumente behalten jetzt die richtigen Dateierweiterungen. (#1535, #1476, #1482, #1660, #1522, #436)
  • Feishu wird immer besser – Rich-Text-Analyse, Tabellen-/Kartenaufteilung, intelligentere Formatauswahl, Groq Whisper-Transkription, Audio-/Video-Kompatibilitätskorrekturen und eine sauberere Ereignisbehandlung – all das ist in dieser Version enthalten. (#1361, #1384, #1648, #1605, #1531, #1594, #332, #1568)
  • Mehr Kanäle, mehr Glanz – DingTalk-Gruppenchat-Unterstützung, QQ-Gruppenhandling und Markdown-Versand, Discord-Gruppenrichtlinie + Anhänge, WhatsApp-Medienunterstützung, Slack-Fallback-Korrekturen und Matrix-Mediennormalisierung haben es geschafft. (#1467, #532, #1727, #553, #1613, #1638, #673, #1406)
  • Plattformübergreifende Stabilität verbessert – Bessere Windows-Signalverarbeitung, weniger fehlende Importe/Abhängigkeiten, sauberere Tests und insgesamt mehr Vertrauen, dass sich Nanobot in verschiedenen Umgebungen gut verhält. (#1598, #1485, #1533, #1546, #1339, #1521)

Gemeinschaft

Ein großes Willkommen an unsere 29 neuen Mitwirkenden in dieser Version – vielen Dank an alle, die mitgemacht und Nanobot über Kanäle, Anbieter, Tools, Dokumente und Infrastruktur hinweg verbessert haben. Durch solche Beiträge wird dieses Projekt immer besser.

nanobot v0.1.4.post4

🐈 nanobot v0.1.4.post4 is here — 58 PRs merged, 29 new contributors, and a lot of real-world polish from the community.

This release is a big one: safer defaults, better multi-instance support, stronger MCP/tool reliability, and major improvements across Telegram, Feishu, QQ, DingTalk, Discord, WhatsApp, Matrix, and more. A ton of sharp edge cases got cleaned up in this cycle — the kind of fixes that make nanobot feel much more solid day to day.

Highlights

  • Safer by default — Access control is tighter now. This release includes a real authorization-bypass fix and stronger default handling around allowFrom, making deployments much safer out of the box. (#1403, #1677)

  • Multi-instance support is finally real — --config support landed, runtime path handling got cleaned up, and the CLI agent now supports --workspace / --config too. Running separate bots, tenants, or environments is much easier now. (#1581, #1635)

  • MCP got tougher — SSE transport support is in, auto-detection is smarter, and MCP tool calls are much less likely to take down the process when cancellations or weird failures happen. (#1488, #1728)

  • Tooling got more forgiving — Auto-casting tool params, safer validation, graceful datetime handling, and read_file size limits all help nanobot fail less badly when tools or inputs get weird. (#1610, #1507, #1508, #1511)

  • Provider support keeps growing — Azure OpenAI support is here, Alibaba Cloud Coding Plan API support landed, prompt-caching affinity headers were added, and GitHub Copilot / Codex compatibility keeps improving. (#1618, #1563, #1428, #1555, #1637, #1525)

  • Cron got much sturdier — External jobs.json changes are respected, job context handling is better, and cron jobs are no longer allowed to recursively schedule more cron jobs forever. (#1371, #1375, #1399, #1458)

  • Context got cleaner — Consecutive user messages are merged to avoid provider-side errors, internal reasoning is hidden from user-facing progress updates, image MIME detection is more reliable, and prompt/platform guidance is more polished. (#1456, #1655, #1573, #1579)

  • Telegram got a lot of love — Proxy handling was fixed, group topics are supported, /stop works better, streaming messages landed, and generic documents now keep the right file extensions. (#1535, #1476, #1482, #1660, #1522, #436)

  • Feishu keeps getting better — Rich text parsing, table/card splitting, smarter format selection, Groq Whisper transcription, audio/video compatibility fixes, and cleaner event handling all landed in this release. (#1361, #1384, #1648, #1605, #1531, #1594, #332, #1568)

  • More channels, more polish — DingTalk group chat support, QQ group handling and markdown sending, Discord group policy + attachments, WhatsApp media support, Slack fallback fixes, and Matrix media normalization all made it in. (#1467, #532, #1727, #553, #1613, #1638, #673, #1406)

  • Cross-platform stability improved — Better Windows signal handling, fewer missing imports/dependencies, cleaner tests, and overall more confidence that nanobot behaves well across different environments. (#1598, #1485, #1533, #1546, #1339, #1521)

Community

A huge welcome to our 29 new contributors in this release — thank you all for jumping in and improving nanobot across channels, providers, tooling, docs, and infrastructure. This project keeps getting better because of contributions like these.
