Nanobot v0.1.5.post1

🐈 Nanobot v0.1.5.post1 ist da 🎉 – 80 PRs zusammengeführt, 25 neue Mitwirkende. Der Agent lernte, sich selbst zu verwalten. Ging es bei v0.1.5 darum, das Gebäude bewohnbar zu machen, geht es bei v0.1.5.post1 darum, dass das Gebäude lernt, für sich selbst zu sorgen. Der Agent komprimiert jetzt seinen eigenen Kontext, bevor er zu lang wird, fügt mitten in der Runde Folgenachrichten ein, anstatt Sie warten zu lassen, entdeckt wiederverwendbare Fähigkeiten aus seinen eigenen Arbeitsabläufen und öffnet einen WebSocket, damit alles mit ihm kommunizieren kann. Mittlerweile haben mehr als 40 Fehlerkorrekturen in den Bereichen Cron, Speicher, Wiederholung und Kanäle dazu geführt, dass aus „es funktioniert die meiste Zeit“ ein „es funktioniert“ geworden ist.

Highlights

  • Mid-Turn-Injektion – Folgenachrichten warten nicht in der Warteschlange – Wenn Sie eine weitere Nachricht senden, während der Agent noch arbeitet, steht er nicht mehr hinter einer Sperre in der Warteschlange. Das Follow-up wird in die aktive Runde eingefügt und auf Streaming-Kanälen wird die Antwort in derselben Live-Antwort fortgesetzt. Dadurch wirken lange Tool-Aufrufketten interaktiv und nicht einseitig. Das Edge-Case-Draining auf Fehlerpfaden wurde in einem Folgedurchlauf gehärtet. (#3042, #3110)
  • Dream erlernt Fähigkeiten, nicht nur Fakten – Der Konsolidierungsfluss von Dream kann jetzt wiederholte Arbeitsabläufe erkennen und sie unter skills/ in eigenständige Workspace-Fähigkeiten umwandeln. In Kombination mit der disabledSkills-Konfiguration zum Ausschließen unerwünschter Fertigkeiten wächst die Fertigkeitsoberfläche des Agenten nun organisch und bleibt überschaubar. (#3048, #2959)
  • Automatische Komprimierung – der Agent verwaltet seinen eigenen Kontext – Sitzungen wachsen nicht mehr, bis sie an die Wand stoßen. Die automatische Komprimierung überwacht Leerlaufzeiten und fasst dann proaktiv älteren Kontext zusammen, während aktuelle Live-Nachrichten erhalten bleiben. Wenn Sie also zurückkommen, merkt sich der Agent, was wichtig ist, ohne alles mitzuschleppen, was nicht wichtig ist. Dies ist nicht der alte „Nuke the Session“-Ansatz; Es ist die chirurgische Kompression, die dafür sorgt, dass sich das Gespräch kontinuierlich anfühlt. Koppeln Sie es mit idleCompactAfterMinutes in der Konfiguration für eine fein abgestimmte Steuerung. (#3007, #3081, #3093)
  • WebSocket-Kanal – alles verbinden – Ein neuer websocket-Kanal betreibt einen WebSocket-Server mit Streaming (delta + stream_end-Ereignisse), tokenbasierter Authentifizierung (statisch oder ausgestellt), Sitzungen pro Verbindung und TLS-Unterstützung. Web-Apps, CLIs, Chrome-Erweiterungen, Skripte – alles, was einen Socket öffnen kann, kann jetzt in Echtzeit mit dem Agenten kommunizieren. (#2964)
  • Kanäle sind tiefer geworden – Telegram hat die Standortfreigabe erhalten. Discord erhielt Streaming-Antworten und Proxy-Unterstützung. Feishu fügte den Fertig-Emoji-Lebenszyklus, Inline-Tool-Hinweise und die globale Lark-Domänenkonfiguration hinzu. QQ und WeCom erhielten volle Medienunterstützung. Das message-Tool von Slack löst jetzt #channel_name und @user in echte IDs auf. Der API-Endpunkt akzeptiert Datei-Uploads über JSON Base64 und Multipart mit automatischer Dokumentenextraktion (PDF, DOCX, XLSX, PPTX) über alle Kanäle. Und die Verstärkung der Wiederholungsversuche – bei der ein fehlgeschlagener Versand kaskadierende Wiederholungsversuche auslösen würde – wurde auf allen Kanälen behoben. (#2910, #2939, #2960, #2993, #3046, #3044, #3138, #2938, #3053)
  • Anbieter – adaptives Denken und Kimi – Anthropics adaptive-Argumentationsmodus ist gelandet und lässt Claude entscheiden, wann und wie viel er denken möchte. Denkfähige Kimi-Modelle (kimi-k2.5, k2.6-code-preview) erhalten jetzt über reasoningEffort eine automatische extra_body.thinking-Einspritzung. Die Argumentationsfelder von StepFun Plan API werden korrekt zurückgesetzt. Nicht-Claude-Anbieter erhalten eine ordnungsgemäße Durchsetzung des Rollenwechsels. Und Tool-Call-Argumente werden für strikte Anbieter normalisiert, die fehlerhafte JSON ablehnen. (#2882, #3124, #2903, #2637, #3154)
  • MCP, Tools und Suche – MCP-Ressourcen und Eingabeaufforderungen werden jetzt als schreibgeschützte Tools angezeigt – der Agent kann sie direkt abfragen. Mehrere MCP-Server verbinden sich in isolierten Aufgaben, anstatt gegeneinander anzutreten. Das Notizbuch-Bearbeitungstool ist angekommen. Kagi ist der Reihe der Websuchanbieter beigetreten. Und das Exec-Tool wurde enger: Die Windows-Unterstützung ist gelandet, mit allowed_env_keys können Sie Umgebungsvariablen selektiv weiterleiten, interne Statusdateien sind schreibgeschützt und working_dir außerhalb des Arbeitsbereichs wird abgelehnt. (#2907, #3019, #3017, #2945, #2893, #2962, #3061)
  • Cron hat aufgehört, Jobs zu löschen – Vier separate Cron-Korrekturen betrafen wiederkehrende Speicherneuladungen während der Jobausführung, die Duplizierung von Aufgaben in festen Intervallen aufgrund gleichzeitiger Speicherersetzungen, das Nicht-Neuladen der Jobkonfiguration und die nicht Beibehaltung des manuellen Ausführungsstatus. Wenn Sie sich auf geplante Aufgaben verlassen, werden diese in dieser Version langweilig. (#3038, #3034, #2895, #2930)

nanobot v0.1.5.post1

🐈 nanobot v0.1.5.post1 is here 🎉 — 80 PRs merged, 25 new contributors. The agent learned to manage itself.

If v0.1.5 was about making the building livable, v0.1.5.post1 is about the building learning to take care of itself. The agent now compresses its own context before it gets too long, injects follow-up messages mid-turn instead of making you wait, discovers reusable skills from its own workflows, and opens a WebSocket so anything can talk to it. Meanwhile, 40+ bug fixes across cron, memory, retry, and channels turned "it works most of the time" into "it works."

Highlights

  • Mid-turn injection — follow-ups don't wait in line — If you send another message while the agent is still working, it no longer queues behind a lock. The follow-up gets injected into the active turn, and on streaming channels the reply continues in the same live response. This makes long tool-call chains feel interactive instead of one-way. Edge-case draining on error paths was hardened in a follow-up pass. (#3042, #3110)

  • Dream learns skills, not just facts — Dream's consolidation flow can now recognize repeated workflows and promote them into standalone workspace skills under skills/. Combined with disabledSkills config for excluding skills you don't want, the agent's skill surface is now something that grows organically and stays manageable. (#3048, #2959)

  • Auto compact — the agent manages its own context — Sessions no longer grow until they hit the wall. Auto compact watches for idle periods, then proactively summarizes older context while preserving recent live messages — so when you come back, the agent remembers what matters without dragging along everything that doesn't. This isn't the old "nuke the session" approach; it's surgical compression that keeps the conversation feeling continuous. Pair it with idleCompactAfterMinutes in config for fine-grained control. (#3007, #3081, #3093)

  • WebSocket channel — connect anything — A new websocket channel runs a WebSocket server with streaming (delta + stream_end events), token-based auth (static or issued), per-connection sessions, and TLS support. Web apps, CLIs, Chrome extensions, scripts — anything that can open a socket can now talk to the agent in real time. (#2964)

  • Channels got deeper — Telegram gained location sharing. Discord got streaming replies and proxy support. Feishu added done-emoji lifecycle, inline tool hints, and Lark global domain config. QQ and WeCom received full media support. Slack's message tool now resolves #channel_name and @user to real IDs. The API endpoint accepts file uploads via JSON base64 and multipart, with automatic document extraction (PDF, DOCX, XLSX, PPTX) across all channels. And retry amplification — where a failed send would trigger cascading retries — was fixed across every channel. (#2910, #2939, #2960, #2993, #3046, #3044, #3138, #2938, #3053)

  • Providers — adaptive thinking and Kimi — Anthropic's adaptive reasoning mode landed, letting Claude decide when and how much to think. Kimi thinking-capable models (kimi-k2.5, k2.6-code-preview) now get automatic extra_body.thinking injection via reasoningEffort. StepFun Plan API reasoning fields fall back correctly. Non-Claude providers get proper role alternation enforcement. And tool-call arguments are normalized for strict providers that reject malformed JSON. (#2882, #3124, #2903, #2637, #3154)

  • MCP, tools, and search — MCP resources and prompts are now exposed as read-only tools — the agent can query them directly. Multiple MCP servers connect in isolated tasks instead of racing each other. The notebook editing tool arrived. Kagi joined the web search provider lineup. And the exec tool got tighter: Windows support landed, allowed_env_keys lets you selectively forward env vars, internal state files are write-protected, and working_dir outside the workspace is rejected. (#2907, #3019, #3017, #2945, #2893, #2962, #3061)

  • Cron stopped dropping jobs — Four separate cron fixes addressed reentrant store reloads during job execution, fixed-interval tasks duplicating due to concurrent store replacement, job config not reloading, and manual run state not being preserved. If you rely on scheduled tasks, this release is the one where they become boring. (#3038, #3034, #2895, #2930)
