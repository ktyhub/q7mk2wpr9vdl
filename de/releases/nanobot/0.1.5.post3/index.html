Nanobot v0.1.5.post3

🐈 Nanobot v0.1.5.post3 ist da 🎉 – 57 PRs zusammengeführt, 12 neue Mitwirkende. Der Agent lernte, in Threads zu sprechen. Wenn es bei v0.1.5.post2 um Reichweite und Glanz ging, geht es bei v0.1.5.post3 darum, dass Gespräche zu erstklassigen Bürgern ihrer Plattform werden. Feishu-Gruppenthemen erhalten isolierte Sitzungen. Discord-Threads erben übergeordnete Zulassungslisten und behalten ihren eigenen Kontext. Telegram kann Inline-Tastaturoptionen wiedergeben. MSTeams bereinigt veraltete Konversationsreferenzen, sodass ausgehende Nachrichten nicht mehr unbemerkt fehlschlagen. Und auf allen Kanälen können sendProgress und sendToolHints jetzt pro Kanal überschrieben werden – leisere Geräusche, behalte die ausführlichen. Darunter wird DeepSeek-V4 durchgängig unterstützt: Denkmodus und Legacy-Sitzungskompatibilität werden zusammen geliefert, mit Folgekorrekturen für unvollständigen Argumentationsverlauf und Nicht-String-Nachrichteninhalte, damit lange Threads stabil bleiben. Ein neues ask_user-Tool ermöglicht es dem Agenten, mitten in der Aufgabe zu pausieren und Sie aufzufordern, etwas auszuwählen. Olostep und Hugging Face sind der Anbieterreihe beigetreten, und ein Paar Timeout-Env-Variablen (NANOBOT_LLM_TIMEOUT_S und NANOBOT_OPENAI_COMPAT_TIMEOUT_S) verhindern, dass hängengebliebene Anfragen Ihre Sitzung als Geisel nehmen. Die WebUI hat sich weiterentwickelt – Bild-Uploads, Video-Rendering, Benutzerauswahlmöglichkeiten, Modelleinstellungen –, dient aber weiterhin nur der Quellvorschau und ist nicht im Rad gebündelt.

Highlights

  • Threads überall – Feishu, Discord, Slack, MSTeams – Jeder Kanal ist in dieser Version gewachsen. Feishu-Gruppenthemen isolieren jetzt Sitzungen, sodass Nachrichten in einem Thema nicht in ein anderes eindringen; Streaming-Karten und Tool-Hinweise folgen dem ursprünglichen Thema. Discord-Threads erben das allowChannels ihres übergeordneten Kanals und erhalten Sitzungsisolation, was auch bedeutet, dass Slash-Befehle die Zulassungsliste respektieren. Slack verliert bei proaktiven Antworten keinen Thread-Kontext mehr. MSTeams-Konversationsreferenzen erhielten eine TTL-basierte Bereinigung (refTtlDays), eine automatische Bereinigung für Web-Chat-Referenzen und ein Berührungsintervall, um aktive Referenzen am Leben zu halten. Das Thema ist konsistent: Gespräche gehören zu ihrem Thread, nicht zum gesamten Kanal. (#3449, #3397, #3440, #3462, #3475, #3447, #3487)
  • Fortschritts- und Interaktionskontrollen pro Kanal – sendProgress und sendToolHints waren früher globale Ein- oder Ausschalter. Jetzt können Sie sie in jede einzelne Kanalkonfiguration einfügen, um den globalen Standard zu überschreiben – halten Sie Telegram ruhig, während WebSocket ausführlich bleibt. Mit dem neuen ask_user-Tool lernte der Agent außerdem, Benutzern während der Aufgabe strukturierte Fragen zu stellen: In WebUI werden diese als Schaltflächen dargestellt, in anderen Kanälen greifen sie auf Text zurück. Telegram verfügt über Inline-Tastaturen (inline_keyboards: true) zum Rendern der Auswahl der message-Werkzeugtasten. Mit dem Befehl /history [n] können Sie aktuelle Nachrichten überprüfen, ohne scrollen zu müssen. (#3487, #2791, #3398, #3454, #3466)
  • DeepSeek-V4 und der breitere Anbieter-Stack – Diese Version macht DeepSeek-V4 zu einem erstklassigen Ziel: Denkmodus und Legacy-Sitzungskompatibilität landen in einem Schritt (#3420), sodass Sie den Agenten auf V4 verweisen können, ohne ältere Gespräche aufzugeben. Transkripte aus der realen Welt deckten zwei Lücken auf, die gezielt weiterverfolgt wurden – abgeschnittener oder unvollständiger Argumentationsverlauf (#3453) und heterogener Nachrichteninhalt (keine Zeichenfolgen) (#3458) – damit Tool-lastige Sitzungen nicht mitten in der Laufzeit ins Stocken geraten. Darüber hinaus kamen Hugging Face Inference Providers als erstklassiger Anbieter hinzu (#3496), Olostep trat der Websuche bei (#3505), OpenAI-kompatible Endpunkte erhielten extraBody für vLLM-geführte Dekodierung und Freunde (#3491) und das Timeout-Paar NANOBOT_LLM_TIMEOUT_S / NANOBOT_OPENAI_COMPAT_TIMEOUT_S trennte äußere Turn-Limits von inneren HTTP-Grenzen (#3428, #3478). GitHub Copilot leitet GPT-5- und O-Serie-Modelle korrekt weiter (#3380); Gemini-Routing greift reasoning_effort="none" und Gemma auf (#3515).
  • Speicher- und Sitzungshärtung – Mit consolidationRatio (0.1–0.95) können Sie einstellen, wie aggressiv die durch Token ausgelöste Konsolidierung den Kontext komprimiert. maxMessages (Standard 120) begrenzt das Wiedergabefenster, ohne die Persistenz zu berühren. History.jsonl gewann atomare Schreibvorgänge mit fsync und Verzeichnissynchronisierung und schloss das letzte Datenverlustfenster bei unerwarteten Abschaltungen. Ein aufgeblähter Raw_Archive-Pfad und mehrere feststeckende Konsolidierungskanten wurden versiegelt. Sitzungen werden jetzt beim ordnungsgemäßen Herunterfahren synchronisiert. Das Ergebnis: Der Speicher ist besser anpassbar und langlebiger. (#3285, #3482, #3508, #3369, #3412, #3415, #3459)
  • macOS LaunchAgent und Bereitstellung – Ein neuer docs/deployment.md-Abschnitt führt durch die Bereitstellung von nanobot gateway als macOS LaunchAgent – Plist, launchctl bootstrap/enable/kickstart, Protokollpfade und das unvermeidliche Portkonflikt-Problem, wenn Sie vergessen, ein manuelles Gateway zu stoppen. Nützlich für alle, die den Agenten beim Anmelden online haben möchten, ohne ein Terminal offen zu halten. (#3441)
  • Sicherheits- und Zuverlässigkeitskorrekturen – Ein Shell-Injection-Vektor über path_append auf Nicht-Windows-Plattformen wurde geschlossen. Verstöße gegen Arbeitsbereichsverzeichnisse stoppen jetzt die Agentenschleife, anstatt eine Warnung zu protokollieren. resolve_config_env_vars hat das Entfernen ausgeschlossener Felder gestoppt. Anthropic image_url-Blöcke innerhalb von tool_result-Inhalten werden korrekt konvertiert. MCP-Funktionsnamen werden für die Kompatibilität mit dem Modell API bereinigt. Windows MCP Stdio-Launcher vermeiden WinError 193. Strukturierte Tool-Event-Payloads liefern Kanälen umfangreichere Fortschrittsdaten. Dokumentparser lazy-importieren, um die Kaltstartzeit zu verkürzen. Ungefähr zwanzig kleinere Korrekturen bei Anbietern, Kanälen und der Agentenschleife runden die Veröffentlichung ab. (#3366, #3493, #3383, #3387, #3470, #3379, #3399, #3423)

Gemeinschaft

Herzlichen Dank an alle, die v0.1.5.post3 verschickt haben – 57 PRs, 27 Mitwirkende und ein großes Willkommen an 12 Erstmitwirkende. Jede Überprüfung, jeder Patch und jeder Fehlerbericht hat geholfen; Diese Veröffentlichung ist ein gemeinsamer Gewinn. 🎉

nanobot v0.1.5.post3

🐈 nanobot v0.1.5.post3 is here 🎉 — 57 PRs merged, 12 new contributors. The agent learned to talk in threads.

If v0.1.5.post2 was about reach and polish, v0.1.5.post3 is about conversations becoming first-class citizens of their platform. Feishu group topics get isolated sessions. Discord threads inherit parent allowlists and keep their own context. Telegram can render inline keyboard choices. MSTeams prunes stale conversation references so outbound messages stop failing silently. And across all channels, sendProgress and sendToolHints can now be overridden per channel — quiet the noisy ones, keep the verbose ones. Underneath, DeepSeek-V4 is supported end to end: thinking mode and legacy session compatibility ship together, with follow-up fixes for incomplete reasoning history and non-string message content so long threads stay stable. A new ask_user tool lets the agent pause and ask you to choose mid-task. Olostep and Hugging Face joined the provider lineup, and a pair of timeout env vars (NANOBOT_LLM_TIMEOUT_S and NANOBOT_OPENAI_COMPAT_TIMEOUT_S) keep hung requests from holding your session hostage. The WebUI continued to evolve — image uploads, video rendering, ask-user choices, model settings — but remains source-preview only, not bundled into the wheel.

Highlights

  • Threads everywhere — Feishu, Discord, Slack, MSTeams — Each channel grew up this release. Feishu group topics now isolate sessions so messages in one topic don't leak into another; streaming cards and tool hints follow the original topic. Discord threads inherit their parent channel's allowChannels and get session isolation, which also means slash commands respect the allowlist. Slack stopped losing thread context on proactive replies. MSTeams conversation references gained TTL-based pruning (refTtlDays), auto-cleanup for Web Chat refs, and a touch interval to keep active refs alive. The theme is consistent: conversations belong to their thread, not to the channel at large. (#3449, #3397, #3440, #3462, #3475, #3447, #3487)

  • Per-channel progress and interaction controls — sendProgress and sendToolHints used to be global on-or-off switches. Now you can place them inside any individual channel config to override the global default — keep Telegram quiet while WebSocket stays verbose. The agent also learned to ask users structured questions mid-task via the new ask_user tool: in WebUI these render as buttons, in other channels they fall back to text. Telegram got inline keyboards (inline_keyboards: true) for rendering message tool button choices. The /history [n] command lets you review recent messages without scrolling. (#3487, #2791, #3398, #3454, #3466)

  • DeepSeek-V4 and the wider provider stack — This release makes DeepSeek-V4 a first-class target: thinking mode and legacy session compatibility land in one go (#3420), so you can point the agent at V4 without abandoning older conversations. Real-world transcripts exposed two gaps that got dedicated follow-ups — truncated or incomplete reasoning history (#3453) and heterogeneous (non-string) message content (#3458) — so tool-heavy sessions don’t fall over mid-run. On top of that, Hugging Face Inference Providers arrived as a first-class provider (#3496), Olostep joined web search (#3505), OpenAI-compatible endpoints gained extraBody for vLLM guided decoding and friends (#3491), and the timeout pair NANOBOT_LLM_TIMEOUT_S / NANOBOT_OPENAI_COMPAT_TIMEOUT_S split outer turn limits from inner HTTP bounds (#3428, #3478). GitHub Copilot routes GPT-5 and o-series models correctly (#3380); Gemini routing picks up reasoning_effort="none" and Gemma (#3515).

  • Memory and session hardening — consolidationRatio (0.1–0.95) lets you tune how aggressively token-triggered consolidation compresses context. maxMessages (default 120) caps the replay window without touching persistence. History.jsonl gained atomic writes with fsync and directory sync, closing the last data-loss window on unexpected shutdowns. A raw_archive bloat path and several stuck-consolidation edges were sealed. Sessions now fsync on graceful shutdown. The result: memory is both more tunable and more durable. (#3285, #3482, #3508, #3369, #3412, #3415, #3459)

  • macOS LaunchAgent and deployment — A new docs/deployment.md section walks through deploying nanobot gateway as a macOS LaunchAgent — plist, launchctl bootstrap/enable/kickstart, log paths, and the inevitable port-conflict gotcha when you forget to stop a manual gateway. Useful for anyone who wants the agent online at login without keeping a terminal open. (#3441)

  • Security and reliability fixes — A shell injection vector via path_append on non-Windows platforms was closed. Workspace directory violations now stop the agent loop instead of logging a warning. resolve_config_env_vars stopped stripping excluded fields. Anthropic image_url blocks inside tool_result content get converted correctly. MCP capability names are sanitized for model API compatibility. Windows MCP stdio launchers avoid WinError 193. Structured tool-event payloads give channels richer progress data. Document parsers lazy-import to cut cold-start time. Twenty-odd smaller fixes across providers, channels, and the agent loop round out the release. (#3366, #3493, #3383, #3387, #3470, #3379, #3399, #3423)
