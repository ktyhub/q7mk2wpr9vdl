trl v1.11.0

Funktionen

Verwenden Sie den vLLM-eigenen Server anstelle der TRLs

trl vllm-serve führte früher eine benutzerdefinierte FastAPI-App rund um LLM von vLLM aus, mit einem eigenen datenparallelen Fanout und einer Worker-Erweiterung für die Gewichtssynchronisierung. Der vLLM-eigene Server deckt all das ab. Der benutzerdefinierte Server ist weg: trl/scripts/vllm_serve.py sinkt von 1218 auf ~130 Zeilen und übersetzt seine Flags nun in vllm serve, gibt den entsprechenden Befehl aus, leitet alle zusätzlichen Argumente weiter und legt die drei Einstellungen fest, die TRL benötigt (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn und pydantic lassen den vllm extra übrig. Die Gewichtssynchronisierung verwendet jetzt die NCCL-Gewichtsübertragungs-Engine von vLLM – Tensoren werden einmal angekündigt und in einem einzigen gepackten Broadcast gestreamt, statt einer HTTP-Anfrage + Broadcast pro Tensor. Destillationslehrer-Logprobs stammen von prompt_logprobs. Benchmark (GRPO-Servermodus auf H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, gleicher Seed, gleiche Daten): | Einrichtung | vor | nach | Beschleunigung | | --- | --- | --- | --- | | Text, TP=1 | 1.08, 0.91 s/step | 0.63, 0.62 s/Schritt | 1.59× | | Text, TP=2 | 0.96, 0.96 s/step | 0.62, 0.60 s/Schritt | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/step | 1.48, 1.48 s/Schritt | 1.44× | Bitidentische Vervollständigungen im Vergleich zum alten Server (16/16 über 4 Eingabeaufforderungen × n=4, Logprobs identisch mit 0.0 über 499 Token). trl vllm-serve akzeptiert immer noch die gleichen Flags – es wird jetzt nur an vllm serve weitergeleitet. von @qgallouedec in https://github.com/huggingface/trl/pull/6765

Neues experimentelles AsyncDistillationTrainer (+ MOPD für mehrere Lehrer)

Asynchrone richtlinienkonforme Destillation, aufgebaut wie AsyncGRPOTrainer: Ein Hintergrund-Rollout-Worker generiert die eigenen Vervollständigungen des Schülers und bewertet sie mit einem Lehrer, der über HTTP bereitgestellt wird, sodass sich Generierung und Training überschneiden, anstatt sich abzuwechseln. Der Lehrer wird nie lokal geladen, sondern nur eine vLLM-Server-URL. Unterstützt auch MOPD (Multi-Teacher-On-Policy-Destillation): Übergeben Sie mehr als einen Eintrag in teacher_server_urls und leiten Sie jede Stichprobe über eine teacher_id-Spalte an einen Lehrer weiter (z. B. einen Mathematiklehrer und einen Codelehrer, die jeweils unabhängig voneinander bedient werden).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

Beispiele in Beispielordnern neu organisiert

examples/ wurde nach Format aufgeteilt (scripts/ vs. notebooks/), wodurch verwandte Dateien verstreut waren (z. B. existierte sft_nemotron_3 sowohl als Skript und als Notizbuch in verschiedenen Ordnern; OpenEnv-Notizbücher lebten getrennt von OpenEnv-Skripten). Alles ist jetzt ein Ordner pro Story – der Name sagt die Methode und die Aufgabe aus (grpo_wordle, sft_gpt_oss, ppo_tldr), und der Ordner enthält alle Dateien, die das Beispiel benötigt (Skripte, Notizbücher, Eingabeaufforderungen, Chat-Vorlagen, Evaluierungscode). Dünne Demoskripte für einzelne Trainer werden entfernt (sie befinden sich in trl/scripts/ und jede Trainerdokumentseite verfügt über einen ausführbaren Snippet). Alte examples/scripts/…- und examples/notebooks/… GitHub / Colab-Links werden 404 – es lohnt sich, sie in nachgelagerten Beiträgen zu kennzeichnen. von @qgallouedec in https://github.com/huggingface/trl/pull/6820

trl v1.11.0

Features

Use vLLM's own server instead of TRL's

trl vllm-serve used to run a custom FastAPI app around vLLM's LLM, with its own data-parallel fan-out and a worker extension for weight sync. vLLM's own server covers all of that. The custom server is gone: trl/scripts/vllm_serve.py drops from 1218 to ~130 lines and now translates its flags into vllm serve, prints the equivalent command, forwards any extra argument, and sets the three settings TRL needs (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn and pydantic leave the vllm extra.

Weight sync now uses vLLM's NCCL weight-transfer engine — tensors are announced once and streamed in a single packed broadcast, instead of one HTTP request + broadcast per tensor. Distillation teacher logprobs come from prompt_logprobs.

Benchmark (GRPO server-mode on H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, same seed, same data):

| Setup | before | after | speedup | | --- | --- | --- | --- | | Text, TP=1 | 1.08, 0.91 s/step | 0.63, 0.62 s/step | 1.59× | | Text, TP=2 | 0.96, 0.96 s/step | 0.62, 0.60 s/step | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/step | 1.48, 1.48 s/step | 1.44× |

Bit-identical completions vs the old server (16/16 over 4 prompts × n=4, logprobs identical to 0.0 over 499 tokens). trl vllm-serve still accepts the same flags — it just forwards to vllm serve now.

by @qgallouedec in https://github.com/huggingface/trl/pull/6765

New experimental AsyncDistillationTrainer (+ multi-teacher MOPD)

Async on-policy distillation, architected like AsyncGRPOTrainer: a background rollout worker generates the student's own completions and scores them against a teacher served over HTTP, so generation and training overlap instead of alternating. The teacher is never loaded locally — just a vLLM server URL.

Also supports MOPD (multi-teacher on-policy distillation): pass more than one entry in teacher_server_urls and route each sample to a teacher via a teacher_id column (e.g. a math teacher and a code teacher, each served independently).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

by @kashif in https://github.com/huggingface/trl/pull/6705

Examples reorganized into per-example folders

examples/ was split by format (scripts/ vs notebooks/), which scattered related files (e.g. sft_nemotron_3 existed as both a script and a notebook, in different folders; OpenEnv notebooks lived apart from OpenEnv scripts). Everything is now one folder per story — the name says the method and the task (grpo_wordle, sft_gpt_oss, ppo_tldr), and the folder holds every file the example needs (scripts, notebooks, prompts, chat templates, eval code). Thin single-trainer demo scripts are removed (they live in trl/scripts/ and each trainer doc page has a runnable snippet). Old examples/scripts/… and examples/notebooks/… GitHub / Colab links will 404 — worth flagging in downstream posts.
