Funktionen

🎓 KTO ist jetzt ein stabiler Trainer

Nach vielen Zyklen der Ausrichtungsarbeit KTOTrainer ↔ DPOTrainer steigt KTO von trl.experimental.kto auf das Paket der obersten Ebene trl auf. Gleiches API wie DPO/GRPO/SFT – Importe werden von experimentell verschoben, Tests werden in den Haupttestbaum verschoben, Dokumente kennzeichnen es nicht mehr als experimentell. Der experimentelle Pfad funktioniert weiterhin und gibt ein FutureWarning aus (Entfernung in v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Laut unserer Telemetrie ist KTO der am vierthäufigsten genutzte Trainer in TRL – dieser Abschluss war überfällig. von @albertvillanova in https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 und https://github.com/huggingface/trl/pull/6345

Umgebungseigene Belohnungen und Unterstützung für mehrere Umgebungen

Drei miteinander verbundene Änderungen machen das Agenten-RL-Training in Umgebungen wesentlich ergonomischer. Umgebungseigene Belohnung. Wenn Ihre environment_factory-Umgebung eine reservierte get_reward()-Methode definiert (keine Argumente → float), wird sie einmal pro abgeschlossenem Rollout aufgerufen und als Belohnungsquelle behandelt. reward_funcs wird optional – keine Weitergabe des Umgebungsstatus mehr an Trainer-eigene Belohnungsfunktionen.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Unterstützung für mehrere Umgebungen. environment_factory akzeptiert jetzt dict[str, factory] zusätzlich zu einem einzelnen Callable. Jede Datensatzzeile wählt ihre Umgebung über eine environment-Spalte aus, und nur die Tools dieser Umgebung werden in der Eingabeaufforderung dieser Zeile angezeigt – so können eine Codierungsaufgabe und ein Spiel gemeinsam in einem Lauf trainiert werden, ohne dass die Toolschemata des anderen verloren gehen. Die Single-Callable-Nutzung bleibt unverändert. Die gleiche Verkabelung findet sich in GRPO, AsyncGRPO, DPPO und GRPO-with-replay-buffer. Env-eigene Belohnung von @qgallouedec in https://github.com/huggingface/trl/pull/6238; Multi-Env in https://github.com/huggingface/trl/pull/6001 und https://github.com/huggingface/trl/pull/6002

Entropie-Regularisierung für GRPO

GRPOConfig unterstützt jetzt sowohl die statische als auch die adaptive Entropie-Regularisierung (Skywork-OR1). Der Bonus fördert die Erkundung und hilft, einen vorzeitigen Zusammenbruch der Politik zu verhindern.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

Der adaptive Modus passt den Koeffizienten einmal pro Optimierungsschritt anhand der fensteraggregierten Entropie an (Gradientenakkumulation bewusst) und behält entropy_coef im Prüfpunkt für die Wiederaufnahme bei. Nicht kompatibel mit dem Liger-Kernel. von @albertvillanova in https://github.com/huggingface/trl/pull/6140

quantization_config Trainerargument (optimiertes QLoRA)

QLoRA erfordert nicht mehr den Zugriff auf model_init_kwargs oder das manuelle Vorladen des Modells.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Zu SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer und KTOTrainer hinzugefügt. Steht neben peft_config (dem anderen nicht serialisierbaren QLoRA-Bestandteil), fließt in from_pretrained und erhöht sich, wenn es ebenfalls in args.model_init_kwargs festgelegt ist. Außerdem entfällt die redundante get_kbit_device_map()-Leitung – QLoRA trainiert ohne sie in allen getesteten Konfigurationen identisch. von @qgallouedec in https://github.com/huggingface/trl/pull/6157 und https://github.com/huggingface/trl/pull/6276

MoE-Aux-Verlust erstreckt sich auf DPO und KTO

v1.7 fügte den Router-Lastausgleichs-Hilfsverlust zu GRPOTrainer / RLOOTrainer / AsyncGRPOTrainer hinzu. Es ist jetzt auch auf DPOTrainer und KTOTrainer verfügbar, so dass MoE-Modelle nach dem Training mit Präferenzdaten die Experten im Gleichgewicht halten. von @qgallouedec in https://github.com/huggingface/trl/pull/6208 und https://github.com/huggingface/trl/pull/6275

Neuronenfreundlicher chunked_nll über statische Token-Packung

Der Chunked-NLL-Pfad verfügte über eine datenabhängige Indizierung, die die XLA/Neuron-Kompilierung unterbrach. Diese PR überarbeitet es, um gültige Token über ein stabiles argsort auf der Gültigkeitsmaske nach vorne zu packen, über ganze ceil(n_valid / chunk_size) * chunk_size-Chunks zu iterieren (ein Tensor, keine Python-int-Synchronisierung) und ignore_index=-100 in jedem Chunk zu verwenden. Das GPU-Verhalten bleibt unverändert. Neuron funktioniert jetzt auch – der gleiche geringe Speicherbedarf (~1.33 GiB im Vergleich zur naiven 5.94 GiB-Alternative) ohne Neukompilierung pro Maske. von @michaelbenayoun in https://github.com/huggingface/trl/pull/6314

Verpackungsbewusstes dynamisches Batching in AsyncGRPO

Das AsyncGRPO-Mikrobatching wird über den auffüllfreien Pfad von v1.7 hinaus packungsbewusst und tokenbegrenzt:

  • Σ Lᵢ²-Zeilenausgleich – eine gierige längste-zuerst-Zuweisung gibt jeder DP-Zeile das gleiche Σ Lᵢ² anstelle der gleichen Token-Anzahl (Achtung ist O(L²), FFN ist O(L), also gleicht gleiche Token-Anzahl die Wanduhr nicht aus). Rangübergreifende Nachzügler verschwinden; +19 % MFU bei 4B im Benchmark.
  • Token-Budget-Packung (Opt-in) – Begrenzen Sie jede Zeile auf token_budget-Tokens mit einer variablen Stichprobenanzahl, wodurch der Spitzenspeicher von per_device_train_batch_size entkoppelt wird. Nützlich in speichergebundenen Regimen (kein Gradienten-Checkpointing, langer Kontext, sehr große Modelle). Beide nutzen die bestehende Gradientenakkumulation von HF Trainer – keine Trainingsschleifenoperation, FSDP/EP-Kollektive bleiben im Gleichschritt. von @AmineDiro in https://github.com/huggingface/trl/pull/6092

trl v1.8.0

Features

🎓 KTO is now a stable trainer

After many cycles of KTOTrainer ↔ DPOTrainer alignment work, KTO graduates from trl.experimental.kto to the top-level trl package. Same API as DPO/GRPO/SFT — imports move from experimental, tests move to the main test tree, docs no longer flag it as experimental. The experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Per our telemetry, KTO is the 4th most used trainer in TRL — this graduation was overdue.

by @albertvillanova in https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 and https://github.com/huggingface/trl/pull/6345

Environment-owned rewards & multi-environment support

Three interrelated changes make agentic RL training with environments substantially more ergonomic.

Environment-owned reward. If your environment_factory env defines a reserved get_reward() method (no args → float), it's called once per completed rollout and treated as a reward source. reward_funcs becomes optional — no more leaking env state back out to trainer-owned reward funcs.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Multi-environment support. environment_factory now accepts dict[str, factory] in addition to a single callable. Each dataset row selects its environment via an environment column, and only that env's tools are exposed in that row's prompt — so a coding task and a game can train together in one run without leaking each other's tool schemas. Single-callable usage is unchanged.

Same wiring lands in GRPO, AsyncGRPO, DPPO, and GRPO-with-replay-buffer.

Env-owned reward by @qgallouedec in https://github.com/huggingface/trl/pull/6238; multi-env in https://github.com/huggingface/trl/pull/6001 and https://github.com/huggingface/trl/pull/6002

Entropy regularization for GRPO

GRPOConfig now supports both static and adaptive entropy regularization (Skywork-OR1). The bonus encourages exploration and helps prevent premature policy collapse.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

Adaptive mode adjusts the coefficient once per optimizer step from window-aggregated entropy (gradient accumulation-aware) and persists entropy_coef in the checkpoint for resume. Not compatible with the Liger kernel.

by @albertvillanova in https://github.com/huggingface/trl/pull/6140

quantization_config trainer argument (streamlined QLoRA)

QLoRA no longer requires reaching into model_init_kwargs or pre-loading the model manually.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Added to SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer, and KTOTrainer. Sits next to peft_config (the other non-serializable QLoRA ingredient), flows into from_pretrained, and raises if also set in args.model_init_kwargs. Also drops the redundant get_kbit_device_map() line — QLoRA trains identically without it across all tested configurations.

by @qgallouedec in https://github.com/huggingface/trl/pull/6157 and https://github.com/huggingface/trl/pull/6276

v1.7 added the router load-balancing auxiliary loss to GRPOTrainer / RLOOTrainer / AsyncGRPOTrainer. It's now on DPOTrainer and KTOTrainer too, so post-training MoE models with preference data keeps experts balanced.

Neuron-friendly chunked_nll via static-shape token packing

The chunked NLL path had data-dependent indexing that broke XLA/Neuron compilation. This PR reworks it to pack valid tokens to the front via a stable argsort on the validity mask, iterate over ceil(n_valid / chunk_size) * chunk_size whole chunks (a tensor, no Python-int sync), and use ignore_index=-100 inside each chunk. GPU behavior is unchanged; Neuron now works too — same tiny memory footprint (~1.33 GiB vs the naive 5.94 GiB alternative) with no per-mask recompilation.

by @michaelbenayoun in https://github.com/huggingface/trl/pull/6314

Packing-aware dynamic batching in AsyncGRPO

AsyncGRPO micro-batching becomes packing-aware and token-bounded on top of the padding-free path from v1.7:

  • Σ Lᵢ² row balancing — a greedy longest-first assignment gives every DP row the same Σ Lᵢ² instead of the same token count (attention is O(L²), FFN is O(L), so equal token counts don't equalize wall-clock). Cross-rank stragglers vanish; +19% MFU at 4B in the benchmark.
  • Token-budget packing (opt-in) — cap each row at token_budget tokens with a variable sample count, decoupling peak memory from per_device_train_batch_size. Useful in memory-bound regimes (no gradient checkpointing, long context, very large models).

Both ride HF Trainer's existing gradient accumulation — no training-loop surgery, FSDP/EP collectives stay in lockstep.
