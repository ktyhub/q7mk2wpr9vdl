trl v1.7.0

Funktionen

SFT-Standard loss_type ist jetzt "chunked_nll"

Der in v1.6 angekündigte Flip ist gelandet. Das Festlegen von loss_type ist optional und die Standardeinstellung wird jetzt auf "chunked_nll" aufgelöst. Dadurch erhält jeder SFTTrainer-Lauf im Durchschnitt ~30 % weniger Spitzen-VRAM (bis zu ~50 % bei Modellen mit großem Vokabular) bei neutraler oder etwas schnellerer Wanduhrzeit. Es sind keine Maßnahmen erforderlich. Bei use_liger_kernel=True fällt die automatische Auflösung auf "nll" zurück (die beiden Pfade sind inkompatibel). Wenn Sie das alte Verhalten wünschen – z. für benutzerdefinierte Köpfe – explizit anpinnen:

SFTConfig(loss_type="nll")

von @qgallouedec in https://github.com/huggingface/trl/pull/5846

MoE-Hilfsverlust in GRPO / RLOO / AsyncGRPO

MoE-Modelle nach dem Training enthalten jetzt korrekt den Router-Lastausgleichs-Hilfsverlust, der mit der eigenen Referenzweiterleitung und SFTTrainer des Modells übereinstimmt. Freigabe über model_init_kwargs:

GRPOConfig(
    ...,
    model_init_kwargs={"output_router_logits": True, "router_aux_loss_coef": 0.001},
)

Durch _get_per_token_logps_and_entropies ausgelotet (gibt jetzt ein 3-Tupel einschließlich aux_loss zurück), in den Richtlinienverlust mit abgeglichener Grad-Akkumulation-Skalierung pro Trainer eingefügt und als aux_loss protokolliert. AsyncGRPO berechnet es über load_balancing_loss_func im Chunked-LM-Head-Pfad neu (identisch mit dem Chunked-Pfad von SFT). von @AmineDiro in https://github.com/huggingface/trl/pull/6083, plus router_aux_loss_coef-Konfigurationsverkabelung von @qgallouedec in https://github.com/huggingface/trl/pull/6085

Neuer experimenteller GMPO-Trainer

[Geometrisch-mittlere Richtlinienoptimierung] (https://huggingface.co/papers/2507.20673) landet als experimenteller Trainer. Ersetzt das arithmetische Mittel der Wichtigkeitsverhältnisse pro Token von GRPO durch ein geometrisches Mittel auf Sequenzebene (Mittelwert von clipped Log-Verhältnissen, dann exp); clipping ist einseitig durch Vorteilszeichen und wird im Protokollbereich angewendet. Standardmäßig epsilon=0.4 gemäß Papier.

from trl.experimental.gmpo import GMPOConfig, GMPOTrainer

trainer = GMPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GMPOConfig(epsilon=0.4),
    reward_funcs=accuracy_reward,
    train_dataset=dataset,
)

von @raghulchandramouli in https://github.com/huggingface/trl/pull/6078

Kontinuierliche Stapelverarbeitung von Transformatoren in GRPO / RLOO

use_transformers_paged wurde in v1.4 veraltet; Es wurde jetzt durch die richtige [kontinuierliche Stapelverarbeitung von Transformatoren] (https://huggingface.co/docs/transformers/main/en/main_classes/text_generation#transformers.GenerationMixin.generate_batch) ersetzt. Der alte Zweig hat die Wichtigkeitsstichprobenkorrektur stillschweigend umgangen (logprobs = None); Der neue Pfad erfasst Logprobs von output.logprobs und stellt einen ContinuousBatchingConfig für die KV-Cache-Optimierung bereit.

GRPOConfig(
    ...,
    use_transformers_continuous_batching=True,
    transformers_continuous_batching_config={
        "use_cuda_graph": False,
        "max_memory_percent": 0.4,  # leave headroom for training
    },
)

Benchmark (Llama-3.2-1B-Instruct, A100 80 GB, GSM8K): 1.25× schneller bei N=64 Generationen mit -16 GB Spitzen-VRAM im Vergleich zum Standard-generate(). Verwendung, wenn N ≥ 32 mit variablen Abschlusslängen. use_transformers_paged=True funktioniert weiterhin und leitet mit einem FutureWarning an die neue Flagge weiter. Erfordert transformers>=5.8.0. von @sergiopaniego in https://github.com/huggingface/trl/pull/5765

AsyncGRPO: native Gewichtssynchronisierung mit vLLM ≥ 0.22.0

WeightTransferClient steuert jetzt vLLMs native 4-Phasen-RL-Gewichtsübertragung API anstelle des älteren 2-Aufruf-Ablaufs: pause(mode="keep") → start_weight_update → Threaded update_weights + NCCL-Broadcast → finish_weight_update → resume. End-to-End-Validierung auf H100 über Einzelknoten, FSDP2×4 + TP=4 und 2-Knoten FSDP2×4 + DP=2×TP=4 (Gewichtssynchronisationszeit ≈ 0.18-0.8 s). von @AmineDiro in https://github.com/huggingface/trl/pull/5892

Padding-freies Training in AsyncGRPO

AsyncGRPO unterstützt jetzt denselben auffüllfreien Pfad, den SFT bereits hatte. Reduziert den Stapel und verwendet position_ids-basierte Dokumentgrenzen, anstatt rechts auf die längste Sequenz aufzufüllen – eine erhebliche Beschleunigung und Speichereinsparung bei Workloads mit heterogener Länge. von @qgallouedec in https://github.com/huggingface/trl/pull/5854

Experimentelle Harbor-Integration

Ein neuer trl.experimental.harbor-Adapter verbindet die Agenten-Task-Suites von Harbor über environment_factory mit GRPOTrainer. Gleiches Muster wie bei der OpenReward-Integration – eine Spezifikation verbindet alle drei Trainer-Slots:

from trl import GRPOConfig, GRPOTrainer
from trl.experimental.harbor import HarborSpec

spec = HarborSpec("AdithyaSK/data_agent_rl_environment_train", agent="bash", num_tasks=64)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(num_generations=8, max_steps=50, max_tool_calling_iterations=25),
    train_dataset=spec.train_dataset,
    environment_factory=spec.environment_factory,
    reward_funcs=spec.reward_funcs,
)

Integrierter bash-Kabelbaum sowie Beispielkabelbäume jupyter und terminal_notes. Gesteuert durch das neue trl[harbor]-Extra. von @adithya-s-k in https://github.com/huggingface/trl/pull/6018

trust_remote_code in Trainerkonfigurationen

Ein einzelnes trust_remote_code: bool = False-Feld in den Trainerkonfigurationen deckt jetzt die gesamte Ladeoberfläche ab – Modell, Prozessor/Tokenizer, Referenzmodell, Belohnungsmodell, Belohnungs-Tokenizer, Lehrer – anstatt Benutzer zu zwingen, es durch mehrere unabhängige Kwarg-Dikte zu führen.

SFTConfig(trust_remote_code=True)

ModelConfig.trust_remote_code wurde entfernt, um doppelte --trust_remote_code beim Kombinieren von Datenklassen zu vermeiden; Das Verhalten von CLI bleibt unverändert. von @qgallouedec in https://github.com/huggingface/trl/pull/5802

SFT-Refaktor: Labels während der Datensatzvorbereitung erstellen

Die Beschriftungskonstruktion verlagert sich aus dem Collator in die Datensatzvorbereitung, sodass „was trainierbar ist“ an genau einer Stelle definiert wird. Ein einzelner map-Batch erzeugt eine labels-Spalte, in der jedes Token seine ID behält, wenn jede anwendbare Maske 1 ist, andernfalls -100. Einfaches LM bleibt lagerungsneutral; Vorab tokenisierte Datensätze mit Maskenspalten durchlaufen jetzt denselben Pfad. Schritt 1 zur Behebung von #3927. von @0xadvait in https://github.com/huggingface/trl/pull/6037

trl v1.7.0

Features

SFT default loss_type is now "chunked_nll"

The flip announced in v1.6 has landed. Setting loss_type is optional, and the default now resolves to "chunked_nll" — giving every SFTTrainer run ~30% less peak VRAM on average (up to ~50% on large-vocab models) with wall-clock time neutral or slightly faster. No action needed.

The auto-resolve falls back to "nll" when use_liger_kernel=True (the two paths are incompatible). If you want the old behavior — e.g. for custom heads — pin it explicitly:

SFTConfig(loss_type="nll")

by @qgallouedec in https://github.com/huggingface/trl/pull/5846

MoE auxiliary loss in GRPO / RLOO / AsyncGRPO

Post-training MoE models now correctly include the router load-balancing auxiliary loss, matching the model's own reference forward and SFTTrainer. Enable via model_init_kwargs:

GRPOConfig(
    ...,
    model_init_kwargs={"output_router_logits": True, "router_aux_loss_coef": 0.001},
)

Plumbed through _get_per_token_logps_and_entropies (now returns a 3-tuple including aux_loss), folded into the policy loss with grad-accum scaling matched per trainer, and logged as aux_loss. AsyncGRPO recomputes it via load_balancing_loss_func in the chunked LM-head path (same as SFT's chunked path).

by @AmineDiro in https://github.com/huggingface/trl/pull/6083, plus router_aux_loss_coef config wiring by @qgallouedec in https://github.com/huggingface/trl/pull/6085

New experimental GMPO trainer

Geometric-Mean Policy Optimization lands as an experimental trainer. Replaces GRPO's per-token arithmetic mean of importance ratios with a sequence-level geometric mean (mean of clipped log-ratios, then exp); clipping is one-sided by advantage sign and applied in log space. Default epsilon=0.4 per the paper.

from trl.experimental.gmpo import GMPOConfig, GMPOTrainer

trainer = GMPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GMPOConfig(epsilon=0.4),
    reward_funcs=accuracy_reward,
    train_dataset=dataset,
)

by @raghulchandramouli in https://github.com/huggingface/trl/pull/6078

Transformers continuous batching in GRPO / RLOO

use_transformers_paged was deprecated in v1.4; it's now replaced with proper transformers continuous batching. The old branch silently bypassed importance-sampling correction (logprobs = None); the new path captures logprobs from output.logprobs and exposes a ContinuousBatchingConfig for KV-cache tuning.

GRPOConfig(
    ...,
    use_transformers_continuous_batching=True,
    transformers_continuous_batching_config={
        "use_cuda_graph": False,
        "max_memory_percent": 0.4,  # leave headroom for training
    },
)

Benchmark (Llama-3.2-1B-Instruct, A100 80GB, GSM8K): 1.25× faster at N=64 generations with -16 GB peak VRAM vs default generate(). Use when N ≥ 32 with variable completion lengths.

use_transformers_paged=True still works and forwards to the new flag with a FutureWarning. Requires transformers>=5.8.0.

by @sergiopaniego in https://github.com/huggingface/trl/pull/5765

AsyncGRPO: native weight sync with vLLM ≥ 0.22.0

WeightTransferClient now drives vLLM's native 4-phase RL weight-transfer API instead of the older 2-call flow: pause(mode="keep") → start_weight_update → threaded update_weights + NCCL broadcast → finish_weight_update → resume. Validated end-to-end on H100 across single-node, FSDP2×4 + TP=4, and 2-node FSDP2×4 + DP=2×TP=4 (weight-sync time ≈ 0.18-0.8 s).

by @AmineDiro in https://github.com/huggingface/trl/pull/5892

Padding-free training in AsyncGRPO

AsyncGRPO now supports the same padding-free path SFT already had. Flattens the batch and uses position_ids-based document boundaries instead of right-padding to the longest sequence — meaningful speedup and memory savings on heterogeneous-length workloads.

by @qgallouedec in https://github.com/huggingface/trl/pull/5854

Experimental Harbor integration

A new trl.experimental.harbor adapter plugs Harbor agentic task suites into GRPOTrainer via environment_factory. Same pattern as the OpenReward integration — one spec wires all three trainer slots:

from trl import GRPOConfig, GRPOTrainer
from trl.experimental.harbor import HarborSpec

spec = HarborSpec("AdithyaSK/data_agent_rl_environment_train", agent="bash", num_tasks=64)

trainer = GRPOTrainer(
    model="Qwen/Qwen3-4B",
    args=GRPOConfig(num_generations=8, max_steps=50, max_tool_calling_iterations=25),
    train_dataset=spec.train_dataset,
    environment_factory=spec.environment_factory,
    reward_funcs=spec.reward_funcs,
)

Built-in bash harness, plus jupyter and terminal_notes example harnesses. Gated by the new trl[harbor] extra.

by @adithya-s-k in https://github.com/huggingface/trl/pull/6018

trust_remote_code in trainer configs

A single trust_remote_code: bool = False field on the trainer configs now covers the whole load surface — model, processor / tokenizer, reference model, reward model, reward tokenizer, teacher — instead of forcing users to thread it through several independent kwarg dicts.

SFTConfig(trust_remote_code=True)

ModelConfig.trust_remote_code is removed to avoid duplicate --trust_remote_code when combining dataclasses; CLI behavior is unchanged.

by @qgallouedec in https://github.com/huggingface/trl/pull/5802

KTO ↔ DPO alignment: tests, evaluate, sync_ref_model

The last alignment cycle before graduation: KTO now has parity with DPO on pad_to_multiple_of, sync_ref_model, evaluate(), method order/signature, metric placement (all moved into _compute_loss), and a real text + VLM (including multi-image) test suite.
