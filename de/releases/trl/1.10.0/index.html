Funktionen

🎓 DistillationTrainer ist jetzt ein Stalltrainer

Nach einer ~30-PR-Umgestaltung, bei der der Datenvertrag, der Verlustpfad, der Generierungsstapel, die Konfigurationsoberfläche und die Tests umgestaltet wurden, steigen DistillationTrainer und DistillationConfig von trl.experimental.distillation zum Paket der obersten Ebene trl auf. Gleiche Importoberfläche wie SFT / DPO / GRPO / KTO. Der alte experimentelle Pfad funktioniert immer noch und gibt ein FutureWarning aus (Entfernung in v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Landet außerdem einen trl distillation CLI und verschiebt die Tests auf tests/. Der vollständige Refaktorierungsbogen: Signaturspalten auf prompt (veraltetes messages-Format) umgestellt, den Generierungsstapel an GRPOs angeheftet, den Chunked-JSD-Verlust verbunden und den Full-Logit-Pfad gelöscht, den Liger-Pfad bereinigt, um die Extraktion mit dem Chunked-Pfad zu teilen, GRPOs log()/training_step-Timing/_save_checkpoint übernommen, die Testsuite in GRPO-Form umgebaut und vieles mehr. von @qgallouedec über ~30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: Schleifenbesitzer-Agentenschulung (OpenEnv-Harness)

Neuer experimenteller Loop-Owning (Black-Box)-Pfad für AsyncGRPOTrainer – zum Trainieren externer Agenten wie opencode, die ihre eigene Tool-Schleife ausführen, anstatt wie im White-Box-Pfad environment_factory jede Runde durch TRL zu steuern. Der Agent wird in einer OpenEnv-Sitzung im transparent_proxy-Modus ausgeführt; Ein In-Sandbox-Proxy erfasst die Token-IDs und Logprobs jeder Runde. Nach Abschluss liest TRL die Ablaufverfolgung, erstellt die Trainingszeilen pro Runde neu und bewertet den Arbeitsbereich mit dem verify() der Sitzung. Wird mit drei vom Anrufer bereitgestellten Richtlinien-Hooks (rollout_reward_fn, train_turn_fn, agent_turn_fn) geliefert, sodass Sie Framework-Aux-Aufrufe (Titelgenerator, Kontextzusammenfassung) löschen und nur die gewünschten Wendungen verstärken können. Enthält einen eigenständigen examples/scripts/openenv/opencode.py (lokale Subprozess-Sandbox + von DeepCoder bereitgestellter stdin/stdout-Verifizierer), der durchgängig auf Qwen3-4B validiert ist. von @AmineDiro in https://github.com/huggingface/trl/pull/6420, plus HF-Sandbox-Variante von @sergiopaniego in https://github.com/huggingface/trl/pull/6565

DiffusionGemma-Blockdiffusions-SFT-Beispiel

Ein neues SFT-Beispiel für google/diffusiongemma-26B-A4B-it, das das Referenzrezept implementiert: ein Antwortblock pro Schritt, einheitliche zufällige Token-Korruption mit t ~ U(eps, 1), Selbstkonditionierung in zwei Durchgängen, flache Kreuzentropie über die gesamte Leinwand sowie ein autoregressiver Co-Verlust auf dem Encoder. LoRA zielt auf Aufmerksamkeit + dichte MLP-Lineare ab. Erfordert transformers >= 5.12.0. Wird mit Chat-Vorlagen diffusion_gemma.jinja / diffusion_gemma_training.jinja (mit {% generation %}-Markierungen) geliefert, sodass assistant_only_loss=True sofort einsatzbereit ist. von @kashif in https://github.com/huggingface/trl/pull/6003

Features

🎓 DistillationTrainer is now a stable trainer

After a ~30-PR refactor that reshaped its data contract, loss path, generation stack, config surface, and tests, DistillationTrainer and DistillationConfig graduate from trl.experimental.distillation to the top-level trl package. Same import surface as SFT / DPO / GRPO / KTO. The old experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Also lands a trl distillation CLI and moves the tests to tests/. The full refactor arc: switched signature columns to prompt (deprecated messages-format), pinned the generation stack to GRPO's, wired the chunked JSD loss and deleted the full-logit path, cleaned the Liger path to share extraction with the chunked path, adopted GRPO's log() / training_step timing / _save_checkpoint, rebuilt the test suite to GRPO shape, and much more.

by @qgallouedec across ~30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: loop-owning agent training (OpenEnv harness)

New experimental loop-owning (black-box) path for AsyncGRPOTrainer — for training external agents like opencode that run their own tool loop, rather than TRL driving each turn as in the environment_factory white-box path.

The agent runs in an OpenEnv session in transparent_proxy mode; an in-sandbox proxy captures each turn's token ids and logprobs. On completion, TRL reads the trace, rebuilds per-turn training rows, and scores the workspace with the session's verify(). Ships with three caller-supplied policy hooks (rollout_reward_fn, train_turn_fn, agent_turn_fn) so you can drop framework aux calls (title generator, context summarizer) and reinforce only the turns you want.

Includes a self-contained examples/scripts/openenv/opencode.py (local subprocess sandbox + DeepCoder held-out stdin/stdout verifier), validated end-to-end on Qwen3-4B.

by @AmineDiro in https://github.com/huggingface/trl/pull/6420, plus HF-sandbox variant by @sergiopaniego in https://github.com/huggingface/trl/pull/6565

DiffusionGemma block-diffusion SFT example

A new SFT example for google/diffusiongemma-26B-A4B-it implementing the reference recipe: one response block per step, uniform random token corruption with t ~ U(eps, 1), two-pass self-conditioning, flat cross-entropy over the whole canvas plus an autoregressive co-loss on the encoder. LoRA targets attention + dense MLP linears. Requires transformers >= 5.12.0.

Ships with diffusion_gemma.jinja / diffusion_gemma_training.jinja chat templates (with {% generation %} markers) so assistant_only_loss=True works out of the box.
