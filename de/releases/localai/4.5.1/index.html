LocalAI v4.5.1

Highlights

  • Apple Silicon backend expansion — macOS gains vLLM acceleration through vllm-metal/MLX (#10489), Metal builds for liquid-audio, supertonic, TRL, privacy filtering, and several vision backends (#10486–#10488, #10511–#10513), plus Darwin acoustic echo cancellation via localvQE (#10512). Required packaging for Darwin Go backend images is also fixed (#10522), making more workloads viable without Linux offloading.

  • More llama.cpp control and portable CPU builds — cpu_moe/n_cpu_moe and generic upstream-flag passthrough expose additional MoE tuning without patching LocalAI (#10490). Single-build CPU_ALL_VARIANTS artifacts for llama.cpp and turboquant simplify x86, ARM64, and Apple CPU deployment (#10497).

  • Safer automatic GPU concurrency — VRAM headroom and parallel-slot defaults are now evaluated per device, with Blackwell-specific adjustments (#10494, #10507). This should reduce out-of-memory failures, but affected installations may see different automatic concurrency than in v4.5.0.

  • Configurable PII detector startup — Default detectors now load at startup, and LOCALAI_PII_DEFAULT_DETECTORS controls the active set (#10474). Review this setting before upgrading if your data-handling policy requires a narrower detector configuration.

  • Request-handling correctness — URL-decoded agent path parameters support encoded names (#10471), while self-referential URLs behind HTTPS reverse proxies now use the correct scheme and host (#10504). Distributed SoundDetection requests also gain in-flight tracking, with coverage enforced at compile time to prevent future request types from silently bypassing accounting (#10475, #10476).

  • Breaking changes — None announced.
