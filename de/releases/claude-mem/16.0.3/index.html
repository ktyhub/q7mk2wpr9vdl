claude-mem v16.0.3

Patch Veröffentlicht21. Nov. 2026 Quellethedotmack/claude-mem Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

claude-mem v16.0.3

Kritischer Fix

  • Der OMP-Hook funktioniert mit der Serverlaufzeit (#6367, danke @flipcyde101, schließt #6366, berichtet von @walynde). Wenn CLAUDE_MEM_RUNTIME server oder server-beta war, sendete der OMP-Hook immer noch alles an den lokalen Worker, sodass OMP-Sitzungen gelöscht wurden. Der Hook liest nun CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY und CLAUDE_MEM_SERVER_PROJECT_ID (oder die CLAUDE_MEM_SERVER_BETA_*-Namen; Umgebungsvariablen gewinnen über settings.json) und kommuniziert direkt mit dem /v1 API des Servers: Sitzungsstart, Tool- und Antwortereignisse, Kontext und Sitzungsende. Es wendet die gleichen Regeln an, die der Worker anwendet, bevor er etwas speichert: <private>-Blöcke werden entfernt, ausgeschlossene Projekte und CLAUDE_MEM_SKIP_TOOLS werden berücksichtigt, jede Eingabeaufforderung wird aufgezeichnet und der Projektname stammt von git. Wenn die Servereinstellungen unvollständig sind, fällt es wie zuvor an den Worker.
  • OMP-Benutzer: Führen Sie npx claude-mem install --ide omp einmal aus, um diesen Fix zu erhalten. Der OMP-Hook ist eine kopierte Datei, sodass ein Plugin-Update allein ihn nicht ersetzt.

Korrekturen

  • Wissensabfragen und Korpusanfragen können nicht länger ewig hängen bleiben (#6368, danke @flipcyde101, schließt #6364, berichtet von @soarkit). Ein blockierter Stream des Agenten SDK sorgte dafür, dass die Anfrage und ihr Kind Claude CLI ohne Ende am Leben blieben. Eine Wissensabfrage oder Primzahl stoppt jetzt nach 10 Minuten und eine Korpusanforderung nach 15 Minuten mit einem 504-Fehler. Der Korpus bleibt gesperrt, bis die Arbeit aufgrund der Zeitüberschreitung wirklich gestoppt wurde, sodass er nach einem Löschvorgang oder einer Neuerstellung nicht mehr schreiben kann.
  • Der Hinweis „Speichern von Erinnerungen angehalten“ verschwindet, sobald Codex speichert (#6374, danke @ryrenz, schließt #6372, berichtet von @raw34). Nachdem Sie CLAUDE_MEM_PROVIDER nach einer Claude-Kontingentpause auf codex umgestellt haben, hieß es in jeder neuen Sitzung immer noch, dass die Erfassung angehalten wurde, bis die alte Claude-Abklingzeit abgelaufen war. Der Hinweis wird jetzt neu berechnet, wenn Codex einen Speicher speichert.
  • server api-key create --scope ohne Wert wird abgelehnt (#6375, danke @ryrenz, schließt #6373, gemeldet von @soarkit). Früher wurde ein Schlüssel mit der Literalzeichenfolge true erstellt, der dann bei jeder Anfrage abgelehnt wurde. Ein nackter --scope, --name, --team oder --project gibt jetzt --<flag> requires a value aus und beendet 1, ohne etwas zu schreiben, sowohl auf create als auch auf migrate-scopes.
  • Der Agentenkostenbericht stürzt nicht mehr bei Beobachtungen ohne Modell ab (#6376, danke @ZedingZhang, schließt #6371, gemeldet von @Realauster). acr.py rollup löste einen TypeError aus, als in einem Fenster sowohl ein fehlendes als auch ein benanntes, unbepreistes Modell auftrat.
  • Das Docker-Server-Image wird erneut erstellt (#6386, schließt #6379, gemeldet von @InfoALR). Es verwendet jetzt node:20-trixie, da der Baumsitter 0.26 eine neuere Glibc benötigt als node:20 ausgeliefert wird.
  • Die Aktualisierung meiner Arbeit läuft auf OpenCode 2.x (#6361, Refs #6339 gemeldet von @Realauster). OpenCode 2.x lehnt die Flags --pure und --dir ab, sodass jeder Aktualisierungsschritt mit 1 beendet wurde. Der Schritt überprüft nun opencode --version und verwendet die eigene Isolation jeder Version. 2.0.0 bis 2.2.2 und 3.x werden mit Begründung abgelehnt, da sie Plugins nicht fernhalten können. In jeder Version werden dem Aktualisierungsagenten jetzt alle Tools verweigert.
  • OMP und Hermes lesen einen als Nummer gespeicherten Worker-Port (#6363, danke @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} in settings.json wurde früher ignoriert, sodass ihre Anfragen an den Standardport gingen.
  • Das OpenClaw-Installationsprogramm löscht keinen Ordner mehr, den es nicht installiert hat (#6381, danke @DeryFerd). Es lief rm -rf auf dem Installationspfad mit dem Namen ~/.openclaw/openclaw.json. Es ersetzt jetzt einen Ordner nur dann, wenn er fehlt, leer ist oder das eigene OpenClaw-Manifest von claude-mem enthält. Alles andere wird mit einer Warnung in Ruhe gelassen und der Standard-Erweiterungsordner wird verwendet; Wenn das auch von etwas anderem übernommen wird, stoppt der Installer.
  • Der Worker kann jedes gestartete Claude-Kind stoppen (#6385, danke @DeryFerd). Die Feldkomprimierung und die Telegram-Nachbearbeitung starteten ihren Claude-Prozess außerhalb der Prozessliste des Workers, sodass ein Worker, der ihn hart beendete, sie weiterlaufen ließ. Sie stehen jetzt auf dieser Liste und belegen keinen Parallelitätsplatz.
  • Ein hängengebliebener CLI-Druck kann den Arbeitsspeicher nicht unbegrenzt vergrößern (#6384, danke @DeryFerd). Die von claude, codex, gemini und opencode gesammelte Ausgabe ist auf 128 Mi Zeichen begrenzt, etwa das 2.5-fache der größten gemessenen realen Umdrehung. Über die Obergrenze hinaus werden Anfang und Ende beibehalten, eine Warnung protokolliert und die Antwort abgelehnt, anstatt als Teilantwort gelesen zu werden. Kleinere Leistungen bleiben unverändert.
  • Ein Transkriptdatensatz ohne Ende kann den Speicher des Arbeiters nicht unbegrenzt erweitern (#6383, danke @DeryFerd). Ein JSONL-Datensatz über 64 MiB (der größte tatsächlich gemessene Datensatz war 44 MiB) wird übersprungen, mit einer Warnung, die die Datei, den Offset des Datensatzes und seine Größe nennt. Die Zeilen danach werden wie gewohnt gelesen.
  • Der nicht authentifizierte /v1/info zeigt den Redis-Fehlertext nicht mehr an (#6380, danke @DeryFerd). Eine Warteschlangenspur, die nicht gelesen werden konnte, um den Fehler des Treibers zu veröffentlichen, z. B. ein Host und ein Port. Der Grund bleibt jetzt im Serverprotokoll.

Neu

  • Opt-in-CPU-Obergrenze für chroma-mcp (#6369, danke @flipcyde101, behebt teilweise #6365, berichtet von @FengJie2004). Setzen Sie CLAUDE_MEM_CHROMA_MAX_THREADS auf 2, wenn Chroma-MCP mehrere Kerne beschäftigt. Es begrenzt die Threads des Embedders und unter Linux mit taskset die CPUs, die chroma-mcp verwenden kann. Es ist standardmäßig deaktiviert (0), da eine immer aktive Obergrenze den ersten Backfill verlangsamte. #6365 bleibt offen.
  • AIGROW-Voreinstellung für den OpenAI-kompatiblen Anbieter (#6370, danke @guglielmo-io).

Gehosteter Synchronisierungsdienst

  • Die Synchronisierungsdienste vergleichen ihre internen Projektor-Anmeldeinformationen in konstanter Zeit (#6382, danke @DeryFerd). Ein einfacher String-Vergleich könnte das gemeinsame Geheimnis durch das Antwort-Timing preisgeben. Dadurch werden services/sync-api und services/sync-hub geändert, die nicht Teil des npm-Pakets sind: Sie erreichen Benutzer erst, wenn diese Dienste bereitgestellt werden, nicht über diese Version.

Tests

– Ein unzuverlässiger Transkripttest zählt jetzt die Stöße der Anhängeumfrage, anstatt die Dateiprüfung zu beschleunigen (#6360). Vollständig changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3

Englisches Original / English original

claude-mem v16.0.3

Critical fix

  • The OMP hook works with the server runtime (#6367, thanks @flipcyde101, closes #6366 reported by @walynde). When CLAUDE_MEM_RUNTIME was server or server-beta, the OMP hook still sent everything to the local worker, so OMP sessions were dropped. The hook now reads CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY and CLAUDE_MEM_SERVER_PROJECT_ID (or the CLAUDE_MEM_SERVER_BETA_* names; environment variables win over settings.json) and talks to the server's /v1 API directly: session start, tool and reply events, context, and session end. It applies the same rules the worker applies before it saves anything: <private> blocks are stripped, excluded projects and CLAUDE_MEM_SKIP_TOOLS are honored, every prompt is recorded, and the project name comes from git. If the server settings are incomplete, it falls back to the worker as before.
  • OMP users: run npx claude-mem install --ide omp once to get this fix. The OMP hook is a copied file, so a plugin update alone does not replace it.

Fixes

  • Knowledge queries and corpus requests can no longer hang forever (#6368, thanks @flipcyde101, closes #6364 reported by @soarkit). A stalled Agent SDK stream used to keep the request and its Claude CLI child alive with no end. A knowledge query or prime now stops after 10 minutes and a corpus request after 15, with a 504 error. The corpus stays locked until the timed-out work has really stopped, so it cannot write after a delete or rebuild.
  • The "paused saving memories" notice goes away once Codex is saving (#6374, thanks @ryrenz, closes #6372 reported by @raw34). After you switched CLAUDE_MEM_PROVIDER to codex following a Claude quota pause, every new session still said capture was paused until the old Claude cooldown ran out. The notice is now recomputed when Codex stores a memory.
  • server api-key create --scope with no value is refused (#6375, thanks @ryrenz, closes #6373 reported by @soarkit). It used to create a key scoped to the literal string true, which every request then rejected. A bare --scope, --name, --team or --project now prints --<flag> requires a value and exits 1 without writing anything, on both create and migrate-scopes.
  • The Agent Cost Report no longer crashes on observations with no model (#6376, thanks @ZedingZhang, closes #6371 reported by @Realauster). acr.py rollup raised a TypeError when one window had both a missing model and a named, unpriced one.
  • The Docker server image builds again (#6386, closes #6379 reported by @InfoALR). It now uses node:20-trixie, because tree-sitter 0.26 needs a newer glibc than node:20 ships.
  • My Work refresh runs on OpenCode 2.x (#6361, refs #6339 reported by @Realauster). OpenCode 2.x rejects the --pure and --dir flags, so every refresh step exited 1. The step now checks opencode --version and uses each version's own isolation. 2.0.0 to 2.2.2 and 3.x are refused with a reason, because they cannot keep plugins out. On every version the refresh agent now has all tools denied.
  • OMP and Hermes read a worker port saved as a number (#6363, thanks @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} in settings.json used to be ignored, so their requests went to the default port.
  • The OpenClaw installer no longer deletes a folder it did not install (#6381, thanks @DeryFerd). It ran rm -rf on whatever install path ~/.openclaw/openclaw.json named. It now replaces a folder only when it is missing, empty, or holds claude-mem's own OpenClaw manifest. Anything else is left alone with a warning and the default extensions folder is used; if that is also taken by something else, the installer stops.
  • The worker can stop every Claude child it starts (#6385, thanks @DeryFerd). Field compression and the Telegram wrap-up started their Claude process outside the worker's process list, so a worker that exited hard left them running. They are now on that list, and they do not take a concurrency slot.
  • A CLI stuck printing can't grow the worker's memory without limit (#6384, thanks @DeryFerd). Output collected from claude, codex, gemini and opencode is capped at 128 Mi characters, about 2.5 times the largest real turn measured. Past the cap, the start and end are kept, a warning is logged, and the reply is refused instead of read as a partial answer. Smaller outputs are unchanged.
  • A transcript record with no end can't grow the worker's memory without limit (#6383, thanks @DeryFerd). A JSONL record over 64 MiB (the largest real record measured was 44 MiB) is skipped, with a warning that names the file, the record's offset and its size. The lines after it are read as normal.
  • The unauthenticated /v1/info no longer shows Redis error text (#6380, thanks @DeryFerd). A queue lane that could not be read used to publish the driver's error, such as a host and port. The reason now stays in the server log.

New

  • Opt-in CPU cap for chroma-mcp (#6369, thanks @flipcyde101, partly addresses #6365 reported by @FengJie2004). Set CLAUDE_MEM_CHROMA_MAX_THREADS to 2 if chroma-mcp keeps several cores busy. It caps the embedder's threads and, on Linux with taskset, the CPUs chroma-mcp can use. It is off by default (0), because an always-on cap slowed the first backfill. #6365 stays open.
  • AIGROW preset for the OpenAI-compatible provider (#6370, thanks @guglielmo-io).

Hosted sync service

  • The sync services compare their internal projector credential in constant time (#6382, thanks @DeryFerd). A plain string compare could leak the shared secret through response timing. This changes services/sync-api and services/sync-hub, which are not part of the npm package: it reaches users only once those services are deployed, not through this release.

Tests

  • A flaky transcript test now counts the append poll's pokes instead of racing its file check (#6360).

Full changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3
