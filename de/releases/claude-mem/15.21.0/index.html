claude-mem v15.21.0

Minor Veröffentlicht17. Nov. 2026 Quellethedotmack/claude-mem Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

claude-mem v15.21.0

claude-mem schaltet den Codemodus von Claude Code nicht mehr aus

  • Der Codemodus startet mit aktiviertem claude-mem (#6278, danke @naive000; berichtet in #6209 von @nasif-naseef). Der Codemodus (experimentell, Claude Code 2.1.323 und höher) weigert sich zu starten, wenn das Hooks-Modul eines Plugins tool.call einhakt. Der Auto-Clear-Mod von claude-mem hat das getan, daher war der Code-Modus für alle deaktiviert, die claude-mem aktiviert hatten, auch wenn die automatische Löschung deaktiviert war. Der Mod liest jetzt Werkzeugergebnisse stattdessen über session.append. Die automatische Löschung funktioniert weiterhin auf jeder Claude Code-Version, auf der Mods ausgeführt werden (2.1.287 und höher).

Auto-Clear macht dort weiter, wo es aufgehört hat

Die automatische Löschung ist immer noch deaktiviert, es sei denn, Sie setzen CLAUDE_MEM_AUTO_CLEAR_ENABLED auf true. Wenn es eingeschaltet ist:

  • Es wird mit einer Fortsetzungsaufforderung anstelle des bloßen Wortes „Weiter“ fortgesetzt (#6294). Vor dem Löschen speichert Claude ein letztes Mal seinen Arbeitsstatus und benennt dabei die Liste, anhand derer gearbeitet wird, die gerade erledigte Aufgabe und das Gesamtziel. Nach /clear sendet die automatische Löschung Folgendes: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. Wenn beim Speichern einer der drei Punkte fehlt, wird wie zuvor „Weiter“ gesendet und der Grund dafür protokolliert.
  • Es beginnt bei 40 % des Kontextfensters statt bei 33 % (#6294). Ein CLAUDE_MEM_AUTO_CLEAR_PERCENT, den Sie in settings.json festlegen, oder die Umgebung gewinnt immer noch.

Neue Möglichkeiten der Verbindung

  • Hermes Desktop, suchen und speichern über MCP (#6284, danke @krishnadobhal; Teil von #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> fügt claude-mem als MCP-Server für Hermes One und Hermes Desktop hinzu, ohne es zum Speicheranbieter zu machen. Sie erhalten die Funktion „Suchen und Speichern“, wenn Sie danach fragen. nichts wird einzeln erfasst oder injiziert. claude-mem hermes uninstall entfernt nur das, was es geschrieben hat, und stellt config.yaml Byte für Byte wieder her.
  • GitHub Copilot im VS-Code (#6286, danke @krishnadobhal; Teil von #5895). npx claude-mem install --ide copilot-vscode schreibt den MCP-Eintrag, den der Copilot-Agent von VS Code liest (~/.copilot/mcp-config.json, dieselbe Datei, die Copilot CLI verwendet). Der Eintrag enthält jetzt "tools": ["*"]. Ohne sie stellte VS Code eine Verbindung zu claude-mem her, bot dem Modell jedoch nie seine Tools an. Noch keine automatische Erfassung.
  • ModelGo-Voreinstellung (#6277, danke @lichloe1116-gif vom ModelGo-Team). Der OpenAI-kompatible Anbieter verfügt über eine modelgo-Voreinstellung für https://api.modelgo.ai/v1. Es wird kein Standardmodell festgelegt. Wählen Sie daher eines aus, das Ihr Schlüssel verwenden kann.

Auch neu

  • Arbeitsstatus-Schreibprüfungen (#6217, danke @vieGPT). Sie können work_state_write veranlassen, einen lokalen Prüfbefehl auszuführen, bevor es in von Ihnen ausgewählte Listen schreibt, die in ~/.claude-mem/work-state-write-guard.json festgelegt sind. Ein abgelehnter Schreibvorgang gibt HTTP 409 zurück und es wird nichts gespeichert. Ohne Datei ändert sich nichts.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, danke @Moep90; #6223). Ein JSON-Objekt, das jeder Anfrage hinzugefügt wird, die der api-Agent sendet (die Aktualisierung „Meine Arbeit“ und der Korpus-Agent mit api). Für ein Qwen-Modell auf vLLM deaktiviert {"chat_template_kwargs":{"enable_thinking":false}} die Argumentation. Felder wie model, messages und max_tokens werden mit einer Warnung verworfen und nie an das cmem.ai-Gateway gesendet.

Meine Arbeit aktualisieren

  • Langsame Antworten Ihres eigenen Modells scheitern nicht mehr nach etwa 5 Minuten (#6224, danke @Moep90; #6222). Buns Abruf gab eine Verbindung auf, die 5 Minuten lang inaktiv war, bevor das 10-Minuten-Anforderungslimit des api-Agenten in Kraft trat. Nun ist diese Grenze die einzige. – Endpunkte, die max_completion_tokens funktionieren lassen sollen (#6242). Wenn ein Endpunkt max_tokens ablehnt, sendet der api-Agent die Anfrage noch einmal mit max_completion_tokens, anstatt jeden Anruf mit HTTP 400 fehlzuschlagen.
  • Eine Aktualisierung bleibt bei einer Antwort, die zweimal abgelehnt wurde, nicht mehr hängen (#6212, danke @Moep90). Bei einem erneuten Versuch zum Gruppieren, Fokussieren oder Überprüfen werden die Teile, die die Prüfungen nicht bestehen, verworfen und der Rest gespeichert. Zuvor schlug bei jedem Durchlauf derselbe Stapel fehl.
  • Die Build-Story ist in Teilen geschrieben (#6279, danke @0xABCD01; berichtet in #6226 von @Moep90). Der Story-Schritt sendete jede geänderte Bewertung in einer Frage. Diese Frage ging über das Kontextfenster des Modells hinaus und jede Aktualisierung danach schlug fehl. Es werden nun Teile gesendet, die zum gleichen Fragenbudget passen, das auch die anderen Schritte verwenden. – Lange Gespräche werden nach ihren letzten Anfragen gruppiert, nicht nach ihren ersten zehn (#6243, danke @Afloat16). – Mit git commit --message oder --message= vorgenommene Commits werden erkannt (#6236, danke @Afloat16). – Ein Commit erhält nur dann einen GitHub-Link, wenn der Beweis ein Repository benennt (#6237, danke @Afloat16). – Während „Meine Regeln“ auf einen Agenten wartet, verlinkt es die Anweisungen zum Einrichten einer API-Aktualisierung (#6214, danke @liuyinchu).

Einrichtung, Import und Export

  • Setup wird beendet, wenn Ihr Eingabeaufforderungsverlauf umfangreich ist (#6280, danke @0xABCD01; #6266; gemeldet in #6227 von @deserteaglemj). Das Setup wurde bei 99 % bei „Finden Sie Ihre aktuelle Arbeit“ gestoppt, als die letzten Eingabeaufforderungen über dem gehosteten Upload-Limit von 2 MiB lagen, und jeder Wiederholungsversuch schlug auf die gleiche Weise fehl. Die Einrichtung auf Ihrem Computer ist nun abgeschlossen und dies wird angezeigt. Im Einwilligungsschritt wird außerdem angezeigt: „Zu viel für einen Upload. Deaktivieren Sie ein Tool oder überspringen Sie den Scan.“ und schaltet den Upload-Button aus, bis die Auswahl passt.
  • Große Exporte importieren (#6261, danke @Afloat16). Eine Datei, die das 5-MiB-Anforderungslimit des Workers überschreitet, wurde abgelehnt (HTTP 413), bevor etwas gespeichert wurde. Große Dateien werden jetzt in Teilen, zuerst in Sitzungen, mit ihrem vollständigen Inhalt gesendet. – Importierte Beobachtungen werden durch Deduplizierung genauso gefunden wie Live-Beobachtungen, wenn CLAUDE_MEM_DEDUP_ENABLED aktiviert ist (#6263, danke @Afloat16). – claude-mem import --dry-run stoppt nicht mehr bei einer schlechten Worker-Einstellung, da eine Vorschau den Worker nie aufruft (#6215, danke @liuyinchu). – Von einem anderen Agenten importierte Konversationen, die Codex Desktop importiert, werden nicht mehr als in Codex eingegebene Eingabeaufforderungen gezählt (#6219, danke @rigel905; #6218).
  • Beim Exportieren nach /dev/stdout, /dev/stderr, einem Symlink zu einem von beiden oder einem FIFO wird dort sauberes JSON geschrieben, und Fortschrittszeilen und Warnungen gehen an den anderen Stream (#6288, von #6258 von @Afloat16).

Korrekturen

  • Windows: Claude Code lädt RULES-AND-TOOLS.md erneut (#6234, danke @QuantScorpus). claude-mem hat seine @-Importzeilen mit Backslashes geschrieben. Claude Code überspringt diese wortlos, und claude-mem hat dann auch seine andere Kopie der Anweisungen weggelassen, sodass keines von beiden das Modell erreicht hat. Die Zeilen verwenden jetzt Schrägstriche. Ein in einem eingezäunten Codebeispiel angezeigter @-Import zählt nicht mehr als der echte (#6293, aus #6241 von @Afloat16).
  • claude-mem start führt den installierten Worker aus (#6235, danke @ZedingZhang; berichtet in #6228 von @ExactDoug), nicht die Kopie, auf die ein alter Shell-Alias ​​verweist, der seine Abhängigkeiten fehlen können.
  • Backups behalten den neuen Snapshot, nachdem die Uhr zurückgestellt wurde (#6273, danke @Afloat16). Zuvor konnte die Bereinigung den Snapshot löschen, der gerade als gespeichert gemeldet wurde. – teambrain join aktiviert die neue Synchronisierungsverbindung, auch wenn der optionale Freigabeschritt fehlschlägt (#6275, danke @Afloat16).
  • Zusammenfassungen ohne Fortschritt werden nicht gespeichert (#6202, danke @ShitK). Früher wurde eine Zusammenfassung mit nur einem Titel oder Zukunftsplänen gespeichert und als Erfolg angekündigt.
  • Die automatischen Nachrichten von Claude Code teilen eine Anfrage nicht mehr auf (#6251, danke @Afloat16). Die Advisor- und Deliverable-Scans behandelten sie als neue Anfragen und verloren frühere Ratschläge und Dateischreibvorgänge aus derselben Runde.
  • Corpus erstellt über 250.000 Beobachtungen (#6271, danke @Afloat16). Sie scheiterten mit too many SQL variables.
  • Codex: Ein Plugin, das mit einer gepunkteten TOML-Taste deaktiviert wurde, bleibt ausgeschaltet (#6239, danke @Afloat16), zum Beispiel plugins."claude-mem@claude-mem-local".enabled = false.
  • Der Frontmatter des Mem-Search-Skills ist gültig YAML (#6276, danke @Afloat16; gemeldet in #6267 von @orbiutyt).
  • Aider: Das Installationsprogramm bearbeitet die Konfigurationsdatei, die Aider tatsächlich verwendet (zuerst Arbeitsverzeichnis, dann Git-Root, dann Home) (#6289, von #6230 von @Afloat16) und behält zitierte Dateipfade in read:-Listen bei (#6290, von #6231 von @Afloat16).
  • Cursor- und Grok-Kontextdateien behalten den neueren Kontext, wenn sich zwei Aktualisierungen überschneiden (#6291, von #6232 von @Afloat16).
  • Selbstgehosteter Server: Ein Job mit einem widerrufenen Schlüssel oder einer Bereichsverletzung wird einmal statt dreimal ausgeführt (#6252) und claude-mem server jobs retry veröffentlicht erneut mit den Wiederholungsversuchen und dem Backoff der Warteschlange (#6253), danke @HEOJUNFO. Der OpenRouter-Anbieter liest höchstens 64 KiB, wenn er eine Antwort auf einen Token-Feld-Fehler prüft (#6238, danke @Afloat16). Ein nicht lesbares Agentenereignis unterbricht nicht mehr jeden Lesevorgang dieser Tabelle (#6199, danke @DeryFerd).

Sicherheit

  • Shell-Zitat 1.11.0 (#6205, danke @manippoudel; berichtet in #6200 von @lucasbritolubro). Die Version 1.9.0 liegt im Bereich CVE-2026-102422 (kritisch). Kein Codepfad in claude-mem hat den betroffenen Code erreicht; Dies nimmt es aus den Schiffen.
  • adm-zip 0.6.1 und zod 4.6.7 in der Plugin-Laufzeit, aus ihren High-Advisorys (#6220, danke @LeviReisJs; berichtet in #6211 von @noumanbhatti).
  • Der Gemini API-Schlüssel kommt in einen Header, nicht in die Anforderungs-URL (#6196, danke @DeryFerd), sodass Proxys und Zugriffsprotokolle ihn nicht aufzeichnen.
  • Temporäre Dateien erhalten einen zufälligen Namen und werden ausschließlich auf den verbleibenden Atomic-Write-Sites erstellt (#6198, #6193, danke @DeryFerd), sodass ein platzierter Symlink das Schreiben von Einstellungen oder Statusdateien nicht umleiten kann.
  • Der nicht authentifizierte /v1/info des selbstgehosteten Servers zeigt nur den Status an (#6195, danke @DeryFerd): Kein Authentifizierungsmodus, keine Schemaversion, kein Redis-Host- oder Treiberfehlertext.
  • CI: Die Postinstall-Zulassungslistenprüfung prüft jede direkte Plugin-Abhängigkeit (#6197), und die Spawn-Umgebungsprüfung liest über einem Spawn deklarierte Env-Blöcke und scannt die Plugin-Laufzeit (#6194), danke @DeryFerd.

Für Mitwirkende

  • TypeScript 7.0.2 (#6207, danke @krishnadobhal; #6188). Die Skripte und Tests, die den Compiler API verwenden, behalten TypeScript 6 über einen Alias. – Der Import-Smoke-Test schließt seine SQLite-Reader vor dem endgültigen Scan (#6216, danke @liuyinchu).

Englisches Original / English original

claude-mem v15.21.0

claude-mem no longer turns off Claude Code's Code Mode

  • Code Mode starts with claude-mem enabled (#6278, thanks @naive000; reported in #6209 by @nasif-naseef). Code Mode (experimental, Claude Code 2.1.323 and later) refuses to start when a plugin's hooks module hooks tool.call. claude-mem's auto-clear mod did, so Code Mode was off for everyone with claude-mem enabled, even with auto-clear off. The mod now reads tool results through session.append instead. Auto-clear still works on every Claude Code version that runs mods (2.1.287 and later).

Auto-clear picks up where it left off

Auto-clear is still off unless you set CLAUDE_MEM_AUTO_CLEAR_ENABLED to true. When it is on:

  • It resumes with a continuation prompt instead of the bare word "continue" (#6294). Before clearing, Claude saves its work state one last time, naming the list it is working from, the task it just finished and the overall goal. After /clear, auto-clear sends: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. If that save left any of the three out, it sends "continue" as before and logs why.
  • It starts at 40% of the context window instead of 33% (#6294). A CLAUDE_MEM_AUTO_CLEAR_PERCENT you set in settings.json or the environment still wins.

New ways to connect

  • Hermes Desktop, search and save over MCP (#6284, thanks @krishnadobhal; part of #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> adds claude-mem as an MCP server for Hermes One and Hermes Desktop without making it the memory provider. You get search and save when you ask for them; nothing is captured or injected on its own. claude-mem hermes uninstall removes only what it wrote and restores config.yaml byte for byte.
  • GitHub Copilot in VS Code (#6286, thanks @krishnadobhal; part of #5895). npx claude-mem install --ide copilot-vscode writes the MCP entry that VS Code's Copilot agent reads (~/.copilot/mcp-config.json, the same file Copilot CLI uses). The entry now includes "tools": ["*"]. Without it, VS Code connected to claude-mem but never offered its tools to the model. No automatic capture yet.
  • ModelGo preset (#6277, thanks @lichloe1116-gif of the ModelGo team). The OpenAI-compatible provider has a modelgo preset for https://api.modelgo.ai/v1. It sets no default model, so pick one your key can use.

Also new

  • Work-state write checks (#6217, thanks @vieGPT). You can make work_state_write run a local check command before it writes to lists you choose, set in ~/.claude-mem/work-state-write-guard.json. A refused write returns HTTP 409 and nothing is saved. With no file, nothing changes.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, thanks @Moep90; #6223). A JSON object added to every request the api agent sends (the My Work refresh and the corpus agent with api). For a Qwen model on vLLM, {"chat_template_kwargs":{"enable_thinking":false}} turns reasoning off. Fields such as model, messages and max_tokens are dropped with a warning, and it is never sent to the cmem.ai gateway.

My Work refresh

  • Slow answers from your own model no longer fail at about 5 minutes (#6224, thanks @Moep90; #6222). Bun's fetch gave up on a connection that had been quiet for 5 minutes, before the api agent's 10-minute request limit applied. Now that limit is the only one.
  • Endpoints that want max_completion_tokens work (#6242). When an endpoint refuses max_tokens, the api agent sends the request once more with max_completion_tokens, instead of failing every call with HTTP 400.
  • A refresh no longer stalls on an answer that was refused twice (#6212, thanks @Moep90). On the one retry for grouping, focus or review, the parts that fail the checks are dropped and the rest is saved. Before, the same batch failed on every run.
  • The build story is written in parts (#6279, thanks @0xABCD01; reported in #6226 by @Moep90). The story step sent every changed review in one question. That question grew past the model's context window, and every refresh after that failed. It now sends parts that fit the same question budget the other steps use.
  • Long conversations are grouped by their latest requests, not their first ten (#6243, thanks @Afloat16).
  • Commits made with git commit --message or --message= are recognized (#6236, thanks @Afloat16).
  • A commit gets a GitHub link only when the evidence names one repository (#6237, thanks @Afloat16).
  • While My Rules waits for an agent, it links the instructions for setting up an API refresh (#6214, thanks @liuyinchu).

Setup, import and export

  • Setup finishes when your prompt history is large (#6280, thanks @0xABCD01; #6266; reported in #6227 by @deserteaglemj). Setup stopped at 99% on "Finding your recent work" when the recent prompts were over the 2 MiB hosted upload limit, and every retry failed the same way. It now finishes setup on your machine and says so. The consent step also shows "Too much for one upload. Untick a tool or skip the scan." and turns off the upload button until the selection fits.
  • Large exports import (#6261, thanks @Afloat16). A file over the worker's 5 MiB request limit was refused (HTTP 413) before anything was saved. Large files are now sent in parts, sessions first, with their full content.
  • Imported observations are found by deduplication the same way live ones are, when CLAUDE_MEM_DEDUP_ENABLED is on (#6263, thanks @Afloat16).
  • claude-mem import --dry-run no longer stops on a bad worker setting, since a preview never calls the worker (#6215, thanks @liuyinchu).
  • Conversations Codex Desktop imported from another agent are no longer counted as prompts typed in Codex (#6219, thanks @rigel905; #6218).
  • Exporting to /dev/stdout, /dev/stderr, a symlink to either, or a FIFO writes clean JSON there, and progress lines and warnings go to the other stream (#6288, from #6258 by @Afloat16).

Fixes

  • Windows: Claude Code loads RULES-AND-TOOLS.md again (#6234, thanks @QuantScorpus). claude-mem wrote its @ import lines with backslashes. Claude Code skips those without a word, and claude-mem then also left out its other copy of the instructions, so neither reached the model. The lines now use forward slashes. An @ import shown inside a fenced code example no longer counts as the real one (#6293, from #6241 by @Afloat16).
  • claude-mem start runs the installed worker (#6235, thanks @ZedingZhang; reported in #6228 by @ExactDoug), not the copy an old shell alias points at, which can be missing its dependencies.
  • Backups keep the new snapshot after the clock is set back (#6273, thanks @Afloat16). Before, cleanup could delete the snapshot it had just reported as saved.
  • teambrain join turns on the new sync connection even when the optional sharing step fails (#6275, thanks @Afloat16).
  • Summaries with no progress in them are not stored (#6202, thanks @ShitK). A summary with only a title or future plans used to be saved and announced as a success.
  • Claude Code's automatic messages no longer split a request (#6251, thanks @Afloat16). The advisor and deliverable scans treated them as new requests and lost earlier advice and file writes from the same turn.
  • Corpus builds over 250,000 observations work (#6271, thanks @Afloat16). They failed with too many SQL variables.
  • Codex: a plugin turned off with a dotted TOML key stays off (#6239, thanks @Afloat16), for example plugins."claude-mem@claude-mem-local".enabled = false.
  • The mem-search skill's frontmatter is valid YAML (#6276, thanks @Afloat16; reported in #6267 by @orbiutyt).
  • Aider: the installer edits the config file Aider actually uses (working directory first, then git root, then home) (#6289, from #6230 by @Afloat16), and keeps quoted file paths intact in read: lists (#6290, from #6231 by @Afloat16).
  • Cursor and Grok context files keep the newer context when two refreshes overlap (#6291, from #6232 by @Afloat16).
  • Self-hosted server: a job with a revoked key or a scope violation runs once instead of three times (#6252), and claude-mem server jobs retry republishes with the queue's retries and backoff (#6253), thanks @HEOJUNFO. The OpenRouter provider reads at most 64 KiB when it checks an answer for a token-field error (#6238, thanks @Afloat16). One unreadable agent event no longer breaks every read of that table (#6199, thanks @DeryFerd).

Security

  • shell-quote 1.11.0 (#6205, thanks @manippoudel; reported in #6200 by @lucasbritolubro). Version 1.9.0 is in the range of CVE-2026-102422 (critical). No code path in claude-mem reached the affected code; this takes it out of what ships.
  • adm-zip 0.6.1 and zod 4.6.7 in the plugin runtime, out of their High advisories (#6220, thanks @LeviReisJs; reported in #6211 by @noumanbhatti).
  • The Gemini API key goes in a header, not the request URL (#6196, thanks @DeryFerd), so proxies and access logs don't record it.
  • Temp files get a random name and are created exclusively at the remaining atomic-write sites (#6198, #6193, thanks @DeryFerd), so a planted symlink can't redirect a write of settings or state files.
  • The self-hosted server's unauthenticated /v1/info shows state only (#6195, thanks @DeryFerd): no auth mode, schema version, Redis host or driver error text.
  • CI: the postinstall allowlist check inspects every direct plugin dependency (#6197), and the spawn environment check reads env blocks declared above a spawn and scans the plugin runtime (#6194), thanks @DeryFerd.

For contributors

  • TypeScript 7.0.2 (#6207, thanks @krishnadobhal; #6188). The scripts and tests that use the compiler API keep TypeScript 6 through an alias.
  • The import smoke test closes its SQLite readers before the final scan (#6216, thanks @liuyinchu).
