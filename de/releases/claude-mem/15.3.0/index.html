claude-mem v15.3.0

claude-mem v15.3.0

Was hat sich geändert?

Leistungen auf der Karte „Meine Arbeit“ (#5109)

Bitten Sie einen Agenten um eine Präsentation, einen Bericht, eine HTML-Seite oder eine andere Datei, und diese finden Sie nur einen click entfernt auf der Vorderseite der Anfragekarte in „Meine Arbeit“ unter Leistungen.

  • Der Stop-Hook kopiert das, was die Runde für Sie gemacht hat in ~/.claude-mem/deliverables/<project>/, inhaltsadressiert (report-3f9a1c2b.md), sodass die Kopie den Arbeitsbaum, den Arbeitsordner oder das temporäre Verzeichnis überdauert, in dem sie erstellt wurde. Dateien, die ein Agent über work_state_write anhängt (work_product, deliverable oder ein beliebiges Feld, das eine Datei benennt, die eine Person öffnet), zählen ebenso wie Decks, Dokumente, Seiten, Bilder, Videos und Tabellenkalkulationen, die außerhalb des Quellbaums geschrieben wurden. Quelldateien werden niemals durch Rückschluss kopiert. SubagentStop erfasst, was ein Subagent aus seinem eigenen Transkript erstellt hat.
  • Der Worker zeichnet jede Kopie auf und stellt sie bereit bei GET /api/deliverables/:id/:filename, mit denselben Loopback-, Same-Origin- und Sandbox-Regeln wie bei aufgezeichneten Dateien; Markdown und Text werden inline geöffnet. Während sich eine Kopie auf der Festplatte befindet und die Datei seitdem nicht mehr geschrieben wurde, dient sie als Aufzeichnung darüber, wo die Datei erstellt wurde.
  • Datenschutz und Einschränkungen sind explizit. Eine Runde, deren Eingabeaufforderung ausschließlich <private> ist, hinterlässt keine Kopie und keine Aufzeichnung. Für einen Worker auf einem anderen Host, der die Kopie nicht öffnen konnte, wird nichts kopiert. 50 Dateien pro Stopp und 512 MiB pro Datei, bei Treffer gemeldet, niemals stumm. CLAUDE_MEM_DELIVERABLES_ENABLED=false schaltet die Kopie aus. – Die Arbeitsstatusregel „SessionStart“ fordert Agenten jetzt auf, das von Ihnen angeforderte Objekt als Datei zu schreiben und es als work_product anzuhängen, bevor sie fertig sind.

Auch neu

  • Automatische lokale Datenbank-Snapshots mit absturzsicherer Wiederherstellung: npx claude-mem backup [run|status|list] und npx claude-mem restore. Standardmäßig deaktiviert; CLAUDE_MEM_BACKUP_ENABLED=true mit CLAUDE_MEM_BACKUP_INTERVAL_HOURS und CLAUDE_MEM_BACKUP_RETAIN_COUNT. (#3751)
  • Notion-Export. Jede neue Beobachtung wird in eine Notion-Datenbank übernommen, sobald sie gespeichert wird. Opt-in über CLAUDE_MEM_NOTION_ENABLED, ein Token und eine Datenbank-ID; Blockiert niemals die Erfassung. (#4799)
  • Codex-Subagenten beginnen mit der Speicherzeitleiste. Ein neuer SubagentStart-Hook gibt einem neuen Subagenten den gleichen Kontext, den SessionStart einer Sitzung gibt; Forks, die den Verlauf ihrer Eltern erben, werden übersprungen. Codex fragt einmal nach dem neuen Hook trust. (#4760)
  • Runcrate-Voreinstellung für den OpenAI-kompatiblen Anbieter. (#5067)

Korrekturen

  • Antigravity CLI: claude-mem registriert PreToolUse nicht mehr, wodurch jeder Agy-Tool-Aufruf automatisch genehmigt und jeder Aufruf zweimal in die Warteschlange gestellt wurde (#5085). Agy-Eingabeaufforderungen werden jetzt einmal pro Runde aufgezeichnet, sodass Agy-Arbeiten in „Meine Arbeit“ angezeigt werden und in Agy gelesene Dateien ihren Beobachtungsverlauf erhalten (#5092).
  • Redaktion: Temporäre AWS-Anmeldeinformationen werden vollständig redigiert: ASIA-Zugriffsschlüssel-IDs, Sitzungstoken und der SecretAccessKey in der aws sts JSON-Ausgabe (#5066, #5073, #5080).
  • Transkripte: Beobachterkontrollpunkte werden gehalten, bis gepufferte Arbeit gespeichert ist (#5072); Der Transcript-Watch-Konfigurationspfad folgt CLAUDE_MEM_DATA_DIR (#5070).
  • Beobachter-Parser: liest den Typ, auf dem sich das Modell festgelegt hat, und markiert niemals ihn (#5077).
  • Windows: Der Launcher kompiliert über den kurzen Pfad 8.3, wenn sich bun.exe auf einem Nicht-ASCII-Pfad befindet (#5089).
  • SessionStart-Terminalvorschau lässt Platz für die Fußzeile (#5084); In der Installationshilfe heißt es, welche Anbieter eine cmem.ai-Anmeldung benötigen (#5086).
  • Release-Tooling: Jedes ausgelieferte Plugin-Manifest enthält dieselbe Version, die vom Build synchronisiert und im CI überprüft wird (#5083, #5082, #5075). Vollständig Changelog: https://github.com/thedotmack/claude-mem/compare/v15.2.1...v15.3.0

Englisches Original / English original

claude-mem v15.3.0

What changed

Deliverables on the My Work card (#5109)

Ask an agent for a deck, a report, an HTML page or any other file, and it is one click away on the front of the request's card in My Work, under Deliverables.

  • The Stop hook copies what the turn made for you into ~/.claude-mem/deliverables/<project>/, content-addressed (report-3f9a1c2b.md), so the copy outlives the worktree, scratch folder or temp directory it was made in. Files an agent attaches through work_state_write (work_product, deliverable, or any field naming a file a person opens) count, as do decks, documents, pages, images, video and spreadsheets written outside the source tree. Source files are never copied by inference. SubagentStop captures what a subagent made from its own transcript.
  • The worker records and serves each copy at GET /api/deliverables/:id/:filename, with the same loopback, same-origin and sandbox rules as recorded files; markdown and text open inline. While a copy is on disk and the file has not been written since, it stands in for the record of where the file was made.
  • Privacy and limits are explicit. A turn whose prompt is entirely <private> leaves no copy and no record. Nothing is copied for a worker on another host, which could not open the copy. 50 files per Stop and 512 MiB per file, reported when hit, never silent. CLAUDE_MEM_DELIVERABLES_ENABLED=false turns the copy off.
  • The SessionStart work-state rule now asks agents to write the thing you asked for as a file and attach it as work_product before they finish.

Also new

  • Automatic local database snapshots with crash-safe restore: npx claude-mem backup [run|status|list] and npx claude-mem restore. Off by default; CLAUDE_MEM_BACKUP_ENABLED=true with CLAUDE_MEM_BACKUP_INTERVAL_HOURS and CLAUDE_MEM_BACKUP_RETAIN_COUNT. (#3751)
  • Notion export. Each new observation is upserted into a Notion database as soon as it is stored. Opt-in through CLAUDE_MEM_NOTION_ENABLED, a token and a database id; never blocks capture. (#4799)
  • Codex subagents start with the memory timeline. A new SubagentStart hook gives a fresh subagent the same context SessionStart gives a session; forks, which inherit their parent's history, are skipped. Codex asks once to trust the new hook. (#4760)
  • Runcrate preset for the openai-compatible provider. (#5067)

Fixes

  • Antigravity CLI: claude-mem no longer registers PreToolUse, which auto-approved every agy tool call and queued each call twice (#5085). agy prompts are now recorded once per turn, so agy work shows up in My Work, and files read in agy get their observation history (#5092).
  • Redaction: temporary AWS credentials are redacted in full: ASIA access key IDs, session tokens, and the SecretAccessKey in aws sts JSON output (#5066, #5073, #5080).
  • Transcripts: watcher checkpoints are held until buffered work is stored (#5072); the transcript-watch config path follows CLAUDE_MEM_DATA_DIR (#5070).
  • Observer parser: reads the type the model settled on, never markup around it (#5077).
  • Windows: the launcher compiles through the 8.3 short path when bun.exe is on a non-ASCII path (#5089).
  • SessionStart terminal preview leaves room for its footer (#5084); install help says which providers need a cmem.ai sign-in (#5086).
  • Release tooling: every shipped plugin manifest carries the same version, synced by the build and checked in CI (#5083, #5082, #5075).

Full Changelog: https://github.com/thedotmack/claude-mem/compare/v15.2.1...v15.3.0
