claude-mem v16.0.1

Kritische Korrekturen

  • Die Anmeldung bei Codex funktioniert wieder unter Windows, während claude-mem ausgeführt wird (#6332, danke @ffe111, schließt #6331). Das private Codex-Home, das der App-Server von claude-mem verwendet, erhielt seinen auth.json über eine feste Verbindung zu Ihrem echten ~/.codex/auth.json. Codex weigert sich, eine Anmeldeinformationsdatei durch mehr als einen Hardlink (persist_failed: atomic credential replacement does not support hard-linked files) zu ersetzen, daher schlugen codex login und die Token-Aktualisierung fehl, solange dieses Home existierte. Das Privathaus erhält nun einen Symlink, dem Codex folgt. Nur unter Windows und nur wenn ein Symlink nicht zulässig ist (kein Entwicklermodus oder Erhöhung), erhält er stattdessen eine private Kopie. Jeder andere Fehler schlägt immer noch lautstark fehl.
  • Eine mit <skip_summary/> beantwortete Sonde beendet die Kontingent-Abklingzeit (#6324, danke @vaibhav375, schließt #6322). Nach einem Quota-Treffer testet der Worker den Anbieter und löscht die Abklingzeit, sobald eine Probe einen Speicher speichert. Eine Prüfung, die der Anbieter mit einem gültigen <skip_summary/> beantwortet hat, speichert nichts, sodass die Abklingzeit nie gelöscht wurde und der Arbeiter alle 5 Minuten eine erneute Prüfung durchführte, solange diese Sitzung nur übersprungen wurde. Ein gültiger Sprung löst jetzt auch die Abklingzeit aus, sowohl auf dem Speicherpfad als auch auf dem frühen Pfad, bevor die Speichersitzungs-ID bekannt ist. Der Erfolg der Beobachtergesundheit braucht immer noch einen echten Laden.

Korrekturen

– Die Suche greift auf SQLite zurück, anstatt fehlzuschlagen, wenn Chroma langsam ist (#6327, danke @REI-330, schließt #6323). Der MCP client führt eine Suche 30 s lang durch, während jeder Chroma-Lesevorgang bis zu 60 s wartete. Daher wurde immer noch eine langsame Abfrage ausgeführt, als der Aufrufer aufgab, und der SQLite/FTS5-Fallback wurde nie ausgeführt. Eine Suche teilt nun ein 20-Sekunden-Budget auf alle Chroma-Lesevorgänge und greift zurück, wenn es aufgebraucht ist, ohne dass ein fehlerfreier Chroma-MCP neu gestartet werden muss.

  • Chroma-Neuaufbauten halten einen Kern nicht mehr stundenlang (#6299, danke @srieteja). Ein vollständiger Backfill pausiert jetzt nach jeder Zeile für die Schreibzeit von CLAUDE_MEM_CHROMA_BACKFILL_PAUSE_RATIO (Standard 1, 0 schaltet ihn aus), und chroma-mcp startet unter nice (CLAUDE_MEM_CHROMA_PROCESS_NICE, Standard 10) außerhalb von Windows. Die Live-Synchronisierung bleibt unverändert.
  • Windows-Prozessbereinigung liest Taskkill korrekt (#6328, danke @REI-330; #6307). Ein Taskkill-Exit 255 wird jetzt danach beurteilt, ob die genannten Prozesse noch aktiv sind, und nicht nach seinem Wortlaut. Daher wird während des Chroma-Teardowns keine lokalisierte Meldung mehr ausgegeben und eine gemischte Meldung meldet keinen Erfolg mehr, während ein Prozess noch ausgeführt wird.
  • Observer stoppt das Durchsickern von SQLite-Anweisungen (#6306). Die Anweisungen, die eine Beobachterrunde speichern, werden zwischengespeichert und nicht bei jeder Runde vorbereitet. Dies kann sich anhäufen, bis SQLite nicht mehr genügend Speicher hat und die gesamte Runde zurückgesetzt wird.
  • Der Anmeldehinweis besagt, dass der Beobachter, wenn er kein Claude-Code-Login hat, diesen verwenden kann (#6321, Ref. #6319). Anstatt Sie aufzufordern, /login auszuführen, wenn das Terminal bei einem anderen Anmeldeprofil angemeldet ist, protokolliert der Mitarbeiter eine Warnung mit dem Grund und den Hinweisnamen, die er gelesen hat, und schlägt claude setup-token vor. – Der Legacy-Shell-Alias ​​claude-mem wird bei der Installation und Aktualisierung gefunden und entfernt (#6300, danke @0xABCD01). doctor meldet es, status warnt, wenn der Worker außerhalb des aufgelösten Plugin-Stammverzeichnisses ausgeführt wird, mehrzeilige Aliase bleiben mit einer Warnung unberührt und es ändert sich nichts, wenn Sie die Neuinstallation abbrechen.
  • /api/health veröffentlicht nur den Sondenstatus (#6309, danke @DeryFerd). Die Authentifizierungsmethode, der Redis-Warteschlangendeskriptor, absolute Installationspfade oder die letzte Interaktion mit nicht authentifizierten Anrufern werden nicht mehr angezeigt. – Ein nicht lesbarer Aktualisierungsstatus „Meine Arbeit“ unterbricht das Setup nicht mehr (#6305). Bei einem beschädigten refresh.json wird kein Betrieb angezeigt und er wird ersetzt; Der automatische Updater behandelt es immer noch als ausgelastet. – Lokale Arbeit bleibt angehalten, wenn der Computer keine Dateideskriptoren mehr hat (#6303). Die Setup-Prüfung behandelt EMFILE/ENFILE als „Setup noch aktiv“ und protokolliert eine Warnung pro Episode.
  • Timeline-Dateibeschriftungen sehen auf jeder Plattform gleich aus (#6301, danke @POWDER-RANGER).
  • Durch Drücken einer beliebigen Stelle auf der Fokuskarte „Meine Arbeit“ wird der entsprechende Bereich geöffnet (#6315). Derselbe Fix betrifft die Zeilen „Liste“, „Team“ und „Nach Agent“.

Neu

  • Devin-Cloud-Sitzungen und Devin-Bots (#6334). Eine Organisation kann plugin/ als Devin-Plugin installieren und in jeder Sitzung Hooks, MCP-Suche und Fähigkeiten erhalten.
  • Aktualisierung meiner Arbeit auf OpenCode (#6330, danke @REI-330). Melden Sie sich mit CLAUDE_MEM_WORK_VIEW_AGENT=opencode an; sonst ändert sich nichts.
  • PostgreSQL-Suche findet Begriffe in CJK-, Kana- und Hangul-Text (#6329, danke @REI-330, Ref. #3982).
  • Meine Arbeitskartentitel benennen die Aufgabe in 5 bis 7 Wörtern, anstatt den ersten Satz der Frage zu kopieren (#6317).
  • Der Bildbetrachter verdunkelt und verwischt die Seite dahinter und wirft einen Schatten (#6313).
  • Das Installationsprogramm fragt vor der GUI-Einrichtung nach Ihrer geschäftlichen E-Mail-Adresse und einer Nachricht im Terminal (#6308).

Tests und Dokumente

  • Grok Bot- und Zed-Tests bestehen unter Windows (#6311, #6312, danke @Lupin133). – Installation der Community-Sweep-Arbeitsbäume mit bun install (#6325).

Englisches Original / English original

claude-mem v16.0.1

Critical fixes

  • Signing in to Codex works again on Windows while claude-mem runs (#6332, thanks @ffe111, closes #6331). The private Codex home that claude-mem's app-server uses got its auth.json through a hard link to your real ~/.codex/auth.json. Codex refuses to replace a credential file with more than one hard link (persist_failed: atomic credential replacement does not support hard-linked files), so codex login and token refresh failed for as long as that home existed. The private home now gets a symlink, which Codex follows. Only on Windows, and only when a symlink is not permitted (no Developer Mode or elevation), it gets a private copy instead. Any other error still fails loudly.
  • A probe answered with <skip_summary/> ends the quota cooldown (#6324, thanks @vaibhav375, closes #6322). After a quota hit, the worker probes the provider and clears the cooldown once a probe stores a memory. A probe the provider answered with a valid <skip_summary/> stores nothing, so the cooldown never cleared and the worker re-probed every 5 minutes for as long as that session only skipped. A valid skip now releases the cooldown too, on both the store path and the early path before the memory session id is known. Observer-health success still needs a real store.

Fixes

  • Search falls back to SQLite instead of failing when Chroma is slow (#6327, thanks @REI-330, closes #6323). The MCP client gives a search 30 s, while each Chroma read waited up to 60 s, so a slow query was still running when the caller gave up and the SQLite/FTS5 fallback never ran. A search now shares one 20 s budget across its Chroma reads and falls back when it runs out, without restarting a healthy chroma-mcp.
  • Chroma rebuilds no longer hold a core for hours (#6299, thanks @srieteja). A full backfill now pauses after each row for its write time times CLAUDE_MEM_CHROMA_BACKFILL_PAUSE_RATIO (default 1, 0 turns it off), and chroma-mcp starts under nice (CLAUDE_MEM_CHROMA_PROCESS_NICE, default 10) outside Windows. Live sync is unchanged.
  • Windows process cleanup reads taskkill correctly (#6328, thanks @REI-330; #6307). A taskkill exit 255 is now judged by whether the named processes are still alive, not by its wording, so a localized message no longer throws during Chroma teardown, and a mixed message no longer reports success while a process still runs.
  • Observer turns stop leaking SQLite statements (#6306). The statements that store an observer turn are cached instead of prepared on every turn, which could pile up until SQLite ran out of memory and rolled back the whole turn.
  • The login notice says when the observer has no Claude Code login it can use (#6321, refs #6319). Instead of telling you to run /login when the terminal is signed in to another credential profile, the worker logs a warning with the reason and the notice names which login it read and suggests claude setup-token.
  • The legacy claude-mem shell alias is found and removed on install and update (#6300, thanks @0xABCD01). doctor reports it, status warns when the worker runs outside the resolved plugin root, multiline aliases are left untouched with a warning, and nothing is changed if you cancel the reinstall.
  • /api/health publishes probe state only (#6309, thanks @DeryFerd). It no longer shows the auth method, the Redis queue descriptor, absolute install paths or the last interaction to unauthenticated callers.
  • An unreadable My Work refresh status no longer breaks setup (#6305). A damaged refresh.json reads as no run and gets replaced; the auto-updater still treats it as busy.
  • Local work stays paused when the machine runs out of file descriptors (#6303). The setup check treats EMFILE/ENFILE as "setup still active" and logs one warning per episode.
  • Timeline file labels look the same on every platform (#6301, thanks @POWDER-RANGER).
  • A press anywhere on a My Work focus card opens its area (#6315). The same fix covers the List, Team and By agent rows.

New

  • Devin cloud sessions and Devin Bots (#6334). An organization can install plugin/ as a Devin plugin and get hooks, MCP search and skills in every session.
  • My Work refresh on OpenCode (#6330, thanks @REI-330). Opt in with CLAUDE_MEM_WORK_VIEW_AGENT=opencode; nothing changes otherwise.
  • PostgreSQL search finds terms inside CJK, kana and Hangul text (#6329, thanks @REI-330, refs #3982).
  • My Work card titles name the task in 5 to 7 words instead of copying the first sentence of the ask (#6317).
  • The image viewer darkens and blurs the page behind it and casts a shadow (#6313).
  • The installer asks for your work email and a message in the terminal before GUI setup (#6308).

Tests and docs

  • Grok Bot and Zed tests pass on Windows (#6311, #6312, thanks @Lupin133).
  • Community sweep worktrees install with bun install (#6325).
