nocodb 2026.06.0

<img width="1865" height="1147" alt="Feature release – 2026 06 0" src="https://github.com/user-attachments/assets/c067f887-1e4f-4bfc-865d-ed56591dedb7" /> ## Verfügbarkeit | Funktion | CE / Kostenlos | Bezahlt / Unternehmen | |---|:---:|:---:| | NocoDB-Synchronisierung | – | ✅ | | Dokumentversionsverlauf | – | ✅ | | Mehrwöchige Kalenderansichten | ✅ | ✅ | | Gruppenumschaltung | – | ✅ | ## NocoDB-Synchronisierung <img width="1920" height="1321" alt="image" src="https://github.com/user-attachments/assets/b6849489-7921-42b0-ae2e-d873ed0373b6" /> **NocoDB Sync** spiegelt eine gemeinsame Ansicht von einer NocoDB-Basis in eine andere als synchronisierte Tabelle, die immer mit ihrer Quelle auf dem neuesten Stand bleibt. Egal, ob Sie mehrere Teambasen in einem einzigen Reporting-Hub zusammenfassen, einen nachgelagerten Workflow aus einer einzigen Quelle der Wahrheit speisen oder einen kuratierten Datenausschnitt teilen, ohne das Original herauszugeben, NocoDB Sync hält beide Seiten auf dem Laufenden, ohne dass manuelles Kopieren erforderlich ist. Vorhandene integrationsbasierte Synchronisierungen werden jetzt unter **App-Synchronisierung** gruppiert. [Erfahren Sie mehr über NocoDB Sync →](https://nocodb.com/docs/product-docs/sync/nocodb-sync) ## Dokumentversionsverlauf <img width="1199" height="782" alt="version-history-modal" src="https://github.com/user-attachments/assets/ab12d894-abb2-4751-b3aa-4667d0ece39d" /> Der **Versionsverlauf** speichert jede Bearbeitung automatisch auf einer NocoDocs-Seite, sodass nichts, was Sie schreiben, jemals wirklich verloren geht. Ganz gleich, ob Sie einen gestern gelöschten Abschnitt wiederherstellen, die Entwicklung eines freigegebenen Dokuments verfolgen oder eine unerwünschte Änderung rückgängig machen möchten: Sie können jede frühere Version erneut aufrufen, genau sehen, was sich geändert hat, und sie in einem einzigen click wiederherstellen. Zuschauer können den gesamten Verlauf durchsuchen, während Redakteure ihn wiederherstellen können. Wie weit zurückreicht, hängt von Ihrem Plan ab, von 3 Tagen bei Free bis zu einem ganzen Jahr bei Enterprise. [Erfahren Sie mehr über den Versionsverlauf →](https://nocodb.com/docs/noco-docs/version-history) ## Mehrwöchige Kalenderansichten <img width="1131" height="518" alt="calendar-week-modes" src="https://github.com/user-attachments/assets/5a8d3d7e-247c-40e9-9382-7f22655e0fec" /> Die **Kalenderansicht** erhält zwei neue Layouts zwischen den Wochen- und Monatsoptionen, **2 Wochen** und **6 Wochen**, sodass Sie genau das Fenster einrahmen können, das Sie planen. Egal, ob Sie einen zweiwöchigen Sprint entwerfen, einen sechswöchigen Inhaltskalender aufstellen oder einfach mehr Kontext als eine einzelne Woche ohne die Ausuferung eines ganzen Monats wünschen – mit diesen Layouts sehen Sie auf einen Blick die richtige Zeitspanne. Ihr gewähltes Layout wird pro Ansicht gespeichert, sodass jeder Kalender so geöffnet wird, wie Sie ihn verlassen haben. ## Gruppenumschaltung <img width="838" height="346" alt="group-by-toggle" src="https://github.com/user-attachments/assets/9bc69fc3-198e-476e-8aab-a0e02d2e123a" /> Jede Gruppierung verfügt jetzt über ein Kontrollkästchen, sodass Sie eine Gruppierung deaktivieren können, ohne sie zu löschen, und sie später mit derselben intakten Konfiguration wieder aktivieren. Dies ist praktisch, um eine Ansicht vorübergehend zu reduzieren oder gruppierte und nicht gruppierte Layouts zu vergleichen, ohne die Einrichtung neu erstellen zu müssen. ## Verbesserungen und Korrekturen - **Massenaktionen für mehrere Felder.** Umschalt-click oder Cmd/Strg-click Rasterspaltenüberschriften, um mehrere Felder gleichzeitig auszuwählen und sie dann alle zusammen in einem einzigen Schritt auszublenden, zu löschen, zu gruppieren oder nach ihnen zu filtern, anstatt die Änderung Feld für Feld zu wiederholen. - **Einen Datensatz aus dem Raster duplizieren.** Klicken Sie mit der rechten Maustaste auf eine beliebige Zeile, um direkt eine Kopie davon zu erstellen. - **Auswahlfeldoptionen alphabetisch sortieren.** Ein dauerhafter Umschalter von A bis Z ordnet die Auswahlmöglichkeiten in einem Einzel- oder Mehrfachauswahlfeld und behält diese Reihenfolge bei, während Sie arbeiten. - **AutoNumber kann der Anzeigewert einer Tabelle sein.** AutoNumber-Felder können jetzt als primäre Anzeigespalte fungieren. - **Aufgeräumtere Symbolleiste auf schmalen Bildschirmen.** Wenn der Platz knapp ist, wird die Ansichtssuche auf ein einzelnes Symbol reduziert, anstatt die Symbolleiste zu überfüllen. - **Link- und Benutzerfelder werden in E-Mails korrekt dargestellt.** In Formularübermittlungs- und Datensatz-E-Mails werden verknüpfte Datensätze und Benutzerfelder jetzt ordnungsgemäß anstelle von Platzhaltertext angezeigt. - **Zuverlässigere Webhooks.** Webhooks, die auf bestimmte Triggerfelder beschränkt sind, werden nicht mehr stillschweigend übersprungen, wenn die geänderten Spalten nicht ermittelt werden können, und ein POST-, PUT- oder PATCH-Webhook mit leerem Text wird jetzt im Hook-Protokoll als Fehler gekennzeichnet, anstatt als erfolgreich zu erscheinen. - **Sicherere Schemasynchronisierung.** Bei der Schemasynchronisierung werden Links oder Beziehungen nicht mehr gelöscht, wenn eine verknüpfte Tabelle keinen Primärschlüssel hat, und vom Benutzer festgelegte Primärschlüssel bleiben über Schemaänderungen hinweg erhalten. ## API-Updates - **Zeitleisten- und Gantt-Ansichten über V3 API.** Sie können jetzt Zeitleisten- und Gantt-Ansichten über [V3 REST API](https://nocodb.com/apis/v3/meta#tag/Views/operation/view-create) erstellen und aktualisieren, einschließlich ihrer Datumsabhängigkeitsoptionen. - **Zahlentrennzeichenoption im V3 API.** Zahlen-, Dezimal- und Rollup-Felder legen jetzt ihre `separator`-Einstellung (Komma-, Punkt- und Leerzeichenstile) über [V3 API](https://nocodb.com/apis/v3/meta#tag/Fields/operation/field-create) und Skripte offen. - **Zuverlässiges Hochladen von Anhängen über V3 API.** Das Anhängen von Dateien über V3 API, sei es über Base64-Inhalt oder per URL, folgt jetzt dem korrekten Dateireferenzfluss, sodass der Upload ordnungsgemäß gespeichert und verknüpft wird. ## Hinweise zum Selbsthosting - **SQLite als externe Datenquelle ist jetzt auf die kostenlose selbstgehostete Edition beschränkt.** Es bleibt in der Community Edition und nicht lizenzierten selbstgehosteten Instanzen auswählbar und ist auf lizenzierten selbstgehosteten Instanzen und in der Cloud blockiert. Es ist keine Konfigurationsänderung erforderlich. - **In dieser Version werden neue Datenbankmigrationen ausgeliefert** (Gruppierung nach Umschaltstatus, Dokumentversionsverlaufstabellen und eine breitere Revisions-ID-Spalte). Sie werden beim Upgrade automatisch angewendet und der Einzelabfrage-Cache wird automatisch ungültig, wenn sich die Version ändert. - **Abhängigkeitssicherheitsbatch.** Diese Version löscht den verbleibenden Batch von Abhängigkeitssicherheitshinweisen im gesamten Stapel und fixiert Pakete einschließlich `express-rate-limit` und `path-to-regexp`, ohne Änderungen an öffentlichen APIs. ------------ ## Geschlossene Probleme - [**geschlossen**] 🐛 Fehler: DRINGEND! NocoDB Sync

<img width="1920" height="1321" alt="image" src="https://github.com/user-attachments/assets/b6849489-7921-42b0-ae2e-d873ed0373b6" />

NocoDB Sync mirrors a shared view from one NocoDB base into another as a synced table that always stays up to date with its source. Whether you're rolling several team bases into a single reporting hub, feeding a downstream workflow from a single source of truth, or sharing a curated slice of data without handing over the original, NocoDB Sync keeps both sides in step without any manual copying. Existing integration-based syncs are now grouped under App Sync.

Learn more about NocoDB Sync →

Document Version History

<img width="1199" height="782" alt="version-history-modal" src="https://github.com/user-attachments/assets/ab12d894-abb2-4751-b3aa-4667d0ece39d" />

Version History automatically saves every edit to a NocoDocs page, so nothing you write is ever truly lost. Whether you're recovering a section you deleted yesterday, tracing how a shared document evolved, or rolling back an unwanted change, you can revisit any earlier version, see exactly what changed, and restore it in a single click. Viewers can browse the full history while editors can restore, and how far back it reaches depends on your plan, from 3 days on Free up to a full year on Enterprise.

Learn more about Version History →

Calendar Multi-Week Views

<img width="1131" height="518" alt="calendar-week-modes" src="https://github.com/user-attachments/assets/5a8d3d7e-247c-40e9-9382-7f22655e0fec" />

Calendar view gains two new layouts between its week and month options, 2 Weeks and 6 Weeks, so you can frame exactly the window you're planning around. Whether you're mapping out a two-week sprint, lining up a six-week content calendar, or simply wanting more context than a single week without the sprawl of a full month, these layouts let you see the right slice of time at a glance. Your chosen layout is remembered per view, so each calendar opens the way you left it.

Group Toggle

<img width="838" height="346" alt="group-by-toggle" src="https://github.com/user-attachments/assets/9bc69fc3-198e-476e-8aab-a0e02d2e123a" />

Each grouping now has a checkbox, so you can switch a group-by off without deleting it and turn it back on later with the same configuration intact. It's handy for temporarily flattening a view or comparing grouped and ungrouped layouts without rebuilding the setup.

Improvements & Fixes

  • Bulk actions on multiple fields. Shift-click or Cmd/Ctrl-click grid column headers to select several fields at once, then hide, delete, group by, or filter by all of them together in a single step instead of repeating the change field by field.
  • Duplicate a record from the grid. Right-click any row to create a copy of it in place.
  • Sort select-field options alphabetically. A persistent A to Z toggle orders the choices in a Single or Multi Select field and keeps that order as you work.
  • AutoNumber can be a table's display value. AutoNumber fields are now eligible to act as the primary display column.
  • Tidier toolbar on narrow screens. When space is tight, view search collapses to a single icon instead of crowding the toolbar.
  • Link and User fields render correctly in emails. Form-submission and record emails now show linked records and user fields properly instead of placeholder text.
  • More reliable webhooks. Webhooks scoped to specific trigger fields no longer get silently skipped when the changed columns can't be determined, and a POST, PUT, or PATCH webhook with an empty body is now flagged as an error in the hook log instead of appearing to succeed.
  • Safer schema sync. Syncing schema no longer drops links or relations when a related table has no primary key, and user-set primary keys are preserved across schema changes.

API Updates

  • Timeline and Gantt views via the V3 API. You can now create and update Timeline and Gantt views through the V3 REST API, including their date-dependency options.
  • Number separator option in the V3 API. Number, Decimal, and Rollup fields now expose their separator setting (comma, period, and space styles) through the V3 API and Scripts.
  • Reliable attachment uploads via the V3 API. Attaching files through the V3 API, whether by base64 content or by URL, now follows the correct file-reference flow so the upload is stored and linked properly.

Self-Hosting Notes

  • SQLite as an external data source is now limited to the free self-hosted edition. It remains selectable on Community Edition and unlicensed self-hosted instances, and is blocked on licensed self-hosted and on Cloud. No configuration change is required.
  • New database migrations ship in this release (group-by toggle state, document version-history tables, and a wider revision-id column). They apply automatically on upgrade, and the single-query cache is invalidated automatically when the version changes.
  • Dependency security batch. This release clears the remaining batch of dependency security advisories across the stack, pinning packages including express-rate-limit and path-to-regexp, with no changes to public APIs.
