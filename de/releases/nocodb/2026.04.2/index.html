🚀 NocoDB: Feature-Release

<img width="1865" height="1147" alt="Feature Release – 2026 04 2-CE" src="https://github.com/user-attachments/assets/f10adcd5-68c5-48b6-b2f5-826725f3f297" /> ## Noco-Dokumente <img width="900" height="512" alt="noco-docs" src="https://github.com/user-attachments/assets/0a725474-d6b7-49d4-9633-99af5b192065" /> <br></br> **NocoDocs** ist ein voll ausgestatteter Dokumenteneditor, der direkt in Ihre NocoDB-Datenbank integriert ist. Egal, ob Sie ein internes Wiki pflegen, Produktanforderungen zusammen mit Ihrem Feature-Tracker schreiben, Onboarding-Prozesse dokumentieren oder eine client-bezogene Wissensdatenbank aufbauen, NocoDocs hält Ihre Dokumentation direkt neben den Daten, auf die sie verweist. - **Umfangreiche Bearbeitung:** Überschriften, Codeblöcke, Beschriftungen, Tabellen, Bilder, Dateianhänge, Einbettungen, mathematische Ausdrücke und eine Slash-Befehlspalette zum Einfügen von rapid-Blöcken - **Zusammenarbeit in Echtzeit:** Thread-Diskussionen zum Einbinden von Teamkollegen, ohne das Dokument zu verlassen - **Hierarchische Organisation:** Ziehen Sie den Dokumentbaum per Drag-and-Drop, um Ihre Wissensdatenbank mit verschachtelten Seiten zu strukturieren - **Automatisch speichern:** Jede Änderung wird während der Eingabe automatisch gespeichert, sodass Sie nie Arbeit verlieren - **Überall exportieren:** Markdown oder HTML mit einem einzigen click 👉 [Erfahren Sie mehr über NocoDocs →](https://nocodb.com/docs/noco-docs) ## Redakteure können jetzt Ansichten verwalten Wir haben dich laut und deutlich gehört. Diese Änderung ist eine direkte Reaktion auf das, was unsere Community uns ausdrücklich gewünscht hat, zurückzubringen, und wir freuen uns, dass es zurückkommt. Die Rolle **Editor** deckt jetzt den gesamten Lebenszyklus von **kollaborativen** Ansichten ab, sodass routinemäßige Layoutarbeiten nicht mehr über einen Ersteller oder Eigentümer geleitet werden müssen. Ganz gleich, ob Ihre Analysten Filter für eine wöchentliche Überprüfung anpassen müssen, Ihr Vertriebsteam eine Pipeline-Ansicht für eine neue Region duplizieren möchte oder ein Teamkollege eine Sortierung in eine gemeinsame Ansicht einfügen möchte, die Redakteure können dies direkt erledigen. [Weitere Informationen zu kollaborativen, persönlichen und gesperrten Ansichten →](https://nocodb.com/docs/product-docs/views/actions-on-view) **Was Redakteure jetzt tun können** - Erstellen, umbenennen, duplizieren, löschen und konfigurieren Sie **kollaborative** Ansichten (Filtern, Sortieren, Gruppieren usw.). **Was weiterhin Ersteller oder Eigentümer erfordert** (unverändert) - Sperren oder entsperren Sie eine Ansicht. - Ändern oder löschen Sie eine gesperrte Ansicht. #### Rollenänderungen auf einen Blick Die folgenden Aktionen haben jetzt eine geringere Mindestrolle. „Ersteller+“ bedeutet Ersteller oder Eigentümer; „Herausgeber+“ bedeutet Herausgeber, Ersteller oder Eigentümer. | Aktion | Mindestrolle (vorher) | Mindestrolle (jetzt) ​​| |---|:---:|:---:| | Verwalten Sie kollaborative Ansichten (erstellen, umbenennen, duplizieren, löschen, konvertieren oder Filter bearbeiten, sortieren, gruppieren usw.) | Ersteller+ | Editor+ | ## Verbesserungen - **Standardeinstellung für Benutzerfelder ist „Aktueller Benutzer“** – Benutzerfelder können jetzt „Aktueller Benutzer“ als Standardwert verwenden, sodass jeder neue Datensatz automatisch demjenigen zugewiesen wird, der ihn erstellt, ohne dass eine manuelle Auswahl erforderlich ist. - **Rollup-Präzision für Währungsfelder** – Es wurde ein Problem behoben, bei dem die Option für die Genauigkeit (Dezimalstellen) nicht sichtbar war, wenn ein Rollup auf ein Währungsfeld abzielte. Die Dezimalformatierung kann wieder konfiguriert werden. – **Kommentaranzahl bei gruppierten Ansichten** – Es wurde ein Problem behoben, bei dem die Kommentaranzahlanzeige nicht korrekt gerendert wurde, wenn eine Ansicht gruppiert wurde. Die Zählungen werden nun wie erwartet in jedem Datensatz angezeigt. ### Probleme geschlossen - [**geschlossen**] 🐛 Fehler: Fehler bei der Neuformatierung mehrzeiliger Felder von klein auf capital-Buchstabenfehler [#13563](https://github.com/nocodb/nocodb/issues/13563) - [**geschlossen**] 🐛 Fehler: „Link zu einem anderen Datensatz“ erstellt eine unerwartete `_nc_m2m_*`-Tabelle in der Benutzeroberfläche in v2026.04.1 [#13540](https://github.com/nocodb/nocodb/issues/13540) - [**geschlossen**] 🐛 Fehler: Init-Projektfehler [#13534](https://github.com/nocodb/nocodb/issues/13534) - [**geschlossen**] 🐛 Fehler: Single/Multi machen – Farben besser auswählen [#13532](https://github.com/nocodb/nocodb/issues/13532) - [**geschlossen**] 🐛 Fehler: Farbe der Feldoption auswählen wird in v2026.04.0 falsch angezeigt [#13514](https://github.com/nocodb/nocodb/issues/13514) - [**geschlossen**] Fehler: Das Symbol für die Kommentarzählung verschwindet bei der Seitenaktualisierung und fehlt in der gruppierten Ansicht [#13062](https://github.com/nocodb/nocodb/issues/13062) - [**🔦 Typ: Funktion**][**👮 Geltungsbereich: Authentifizierung**] 🔦 Funktion: Zwei-Faktor-Authentifizierung (2FA) [#2731](https://github.com/nocodb/nocodb/issues/2731) --- > **Quelle** [nocodb/nocodb](https://github.com/nocodb/nocodb) · `2026.04.2` · 22.04.2026 · [Upstream-Version](https://github.com/nocodb/nocodb/releases/tag/2026.04.2) *Zum Indexieren wörtlich gespiegelt. 🚀 NocoDB : Feature Release

Noco Docs

<img width="900" height="512" alt="noco-docs" src="https://github.com/user-attachments/assets/0a725474-d6b7-49d4-9633-99af5b192065" />

<br></br>

NocoDocs is a full-featured document editor built directly into your NocoDB base. Whether you're maintaining an internal wiki, writing product requirements alongside your feature tracker, documenting onboarding processes, or building a client-facing knowledge base, NocoDocs keeps your documentation right next to the data it references.

  • Rich editing: Headings, code blocks, callouts, tables, images, file attachments, embeds, math expressions, and a slash command palette for rapid block insertion
  • Real-time collaboration: Threaded discussions to loop in teammates without leaving the document
  • Hierarchical organisation: Drag-and-drop document tree to structure your knowledge base with nested pages
  • Auto-save: Every change is saved automatically as you type, so you never lose work
  • Export anywhere: Markdown or HTML with a single click

👉 Learn more about NocoDocs →

Editors Can Now Manage Views

We heard you loud and clear. This change is a direct response to what our community explicitly asked us to bring back, and we're glad to see it return.

The Editor role now covers the full lifecycle of collaborative views, so routine layout work no longer has to route through a Creator or Owner. Whether your analysts need to tweak filters for a weekly review, your sales team wants to duplicate a pipeline view for a new region, or any teammate wants to drop a sort into a shared view, Editors can handle it directly.

Learn more about collaborative, personal, and locked views →

What Editors can now do

  • Create, rename, duplicate, delete, and configure collaborative views (filter, sort, group-by, and so on).

What still requires Creator or Owner (unchanged)

  • Lock or unlock a view.
  • Modify or delete a locked view.

Role Changes at a Glance

The actions below now have a lower minimum role. "Creator+" means Creator or Owner; "Editor+" means Editor, Creator, or Owner.

| Action | Minimum role (before) | Minimum role (now) | |---|:---:|:---:| | Manage collaborative views (create, rename, duplicate, delete, convert, or edit filter, sort, group-by, and so on) | Creator+ | Editor+ |

Improvements

  • User field default set to Current User - User fields can now use Current User as their default value, so every new record is automatically assigned to whoever creates it, no manual picker needed.
  • Rollup precision for Currency fields - Fixed an issue where the precision (decimal places) option was not visible when a Rollup targeted a Currency field. Decimal formatting can be configured again.
  • Comment count on grouped views - Fixed an issue where the comment count indicator did not render correctly when a view was grouped. Counts now appear on each record as expected.
