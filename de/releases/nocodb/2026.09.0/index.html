nocodb 2026.09.0

<img width="1865" height="1147" alt="Feature release – 2026 09 0-OSS (1)" src="https://github.com/user-attachments/assets/77f634b7-695a-4f98-88ed-dcaa9b75175b" /> ## Verfügbarkeit | Funktion | Community-Edition | Cloud-kostenloser Plan | Bezahlte Pläne in der Cloud/vor Ort | | --- | :---: | :---: | :---: | | NocoDB in Claude Connectors | ✅ | ✅ | ✅ | | 1200 % mehr MCP-Tools | – | ✅ | ✅ | | Rich-Text-E-Mails in Workflows | – | – | ✅ | Für Rich-Text-E-Mails ist der Plus-Plan und höher in der NocoDB Cloud erforderlich. In der Community Edition behält der MCP-Server seine Aufzeichnungstools. ## NocoDB in Claude Connectors NocoDB ist jetzt in Claude Connectors verfügbar, sodass eine Basis über das Connectors-Verzeichnis mit Claude verbunden werden kann, anstatt die MCP-URL manuell hinzuzufügen. Sobald die Verbindung hergestellt ist, kann Claude jedes MCP-Tool verwenden, das die Rolle des verbindenden Benutzers zulässt. Ab dieser Version umfasst ein Satz von 149 Tools den gesamten Arbeitsbereich. <img width="1280" height="1102" alt="claude-connectors" src="https://github.com/user-attachments/assets/9a241a7f-c90d-4bde-b3c4-665914eeb13d" /> ## 1200 % mehr MCP-Tools Der MCP-Server wurde von 11 auf 149 Tools erweitert und deckt den gesamten Arbeitsbereich ab, nicht nur Datensätze. Claude, ChatGPT, Cursor oder ein beliebiger MCP client können jetzt in NocoDB erstellen: eine Tabelle erstellen, einen Workflow mit einem Webhook verbinden, eine Schnittstellenseite zusammenstellen oder Berechtigungen sperren – alles in einer Konversation. Die Tools umfassen Tabellen, Felder, Ansichten, Filter, Sortierungen, Workflows, Schnittstellen, Dashboards, Widgets, Skripte, Dokumente, Webhooks, Kommentare, Berechtigungen, Sicherheit auf Datensatzebene, Zeilenfärbung, Ordner, Mitglieder sowie CSV-Import und -Export. Jeder umschließt denselben Dienst wie sein REST API, sodass Validierung, Berechtigungen und Prüfung identisch sind und jeder Aufruf die Rolle des Aufrufers respektiert: Betrachter lesen, Redakteure schreiben, Ersteller ändern das Schema. <img width="1008" height="868" alt="mcp-tools" src="https://github.com/user-attachments/assets/d61251cb-7e12-491e-9ca2-fb353087bc21" /> [Erfahren Sie mehr über MCP →](https://nocodb.com/docs/apis-and-mcp/mcp) 149 ist nur der Anfang. Wir bauen bereits den nächsten Satz, und dieser wird Unternehmenssoftware nachhaltig verändern. ## Rich-Text-E-Mails in Workflows Workflow-E-Mails können jetzt formatiert werden. Die Knoten „E-Mail senden“, „SMTP“, „Gmail“ und „Outlook“ teilen sich einen Rich-Text-Editor, der Überschriften, Textformate, Listen, Farben und Links mit benutzerdefiniertem Ankertext unterstützt. Workflowvariablen können an einer beliebigen Stelle im Textkörper eingefügt werden. <img width="1137" height="781" alt="rich-text-email" src="https://github.com/user-attachments/assets/eb80d79a-974c-44c6-bb28-bffdfb1fcd71" /> [Erfahren Sie mehr über den Knoten „E-Mail senden“ →](https://nocodb.com/docs/workflows/nodes/action-nodes/send-email) ## Verbesserungen - **Schaltflächen auf allen Schnittstellenseiten** – Schaltflächen können jetzt in Tabellenseitenkopfzeilen, Datensatzüberprüfungssymbolleisten, Dashboard-Gruppenkopfzeilen und Feldgruppen innerhalb eines Datensatzblatts platziert werden. Schaltflächen auf Seitenebene führen eine Automatisierung ohne Datensatz aus, und *Zur Schnittstellenseite gehen* kann eine Seite in jeder Schnittstelle in der Basis öffnen. [Weitere Informationen](https://nocodb.com/docs/interfaces/elements#buttons) - **Drag & Drop in der Listenansicht** – Datensätze in der Listenansicht können über die Hierarchie gezogen werden: Legen Sie sie auf eine andere, um sie zu verschachteln, oder auf ein anderes übergeordnetes Element, um sie dorthin zu verschieben. Unterdatensätze werden mit ihren übergeordneten Datensätzen übertragen und die zugrunde liegenden Links werden für Sie aktualisiert. [Weitere Informationen](https://nocodb.com/docs/product/tables/views/view-types/list) - **Inline ein verknüpftes Datensatzfeld erstellen** – Wenn Listenansichtsebenen oder verschachtelte Datensätze einen Link benötigen, der noch nicht vorhanden ist, click *Erstellen Sie ein verknüpftes Datensatzfeld*, um es sofort zu erstellen, sowohl in der Basisansicht als auch im Interface Builder. [Weitere Informationen](https://nocodb.com/docs/product/tables/views/view-types/list#nested-records) - **Datumshelfer in Workflow-Ausdrücken** - `$now()` gibt die aktuelle Zeit zurück und `$dateAdd(date, amount, unit)` versetzt sie, zum Beispiel `$dateAdd($now(), 3, 'days')`. - **Schnelleres Kanban** – Das optimierte Kanban-Board, früher eine Funktionsvorschau, ist jetzt überall Standard, auch in der Community Edition. Beim Scrollen werden die Stapel nach und nach geladen. - **Excel-Downloads großer Tabellen** – Excel-Exporte werden gestreamt, sodass sehr große Tabellen zuverlässig heruntergeladen werden und kleinere Dateien entstehen. - **Aufgabenfortschritt in langen Dokumenten** – Die Aufgabenanzahl eines Checklistendokuments folgt Ihnen in der Kopfzeile, sobald der Titel nicht mehr angezeigt wird. ## Was wurde behoben? - **Verschachtelte Suchvorgänge** – Ein Suchvorgang zeigt jeden Wert im Raster an und wird über Viele-zu-Eins-Links auf MySQL, SQL Server und Oracle korrekt aufgelöst. - **Bedingte Rollups mit aktuellem Benutzer** – Rollup-, Such- und Linkfelder, deren Bedingungen den aktuellen Benutzer verwenden, werden für jeden Benutzer berechnet und nicht aus einem gemeinsam genutzten Cache bereitgestellt. - **Synchronisierungszuverlässigkeit** – Eine Tabellensynchronisierung wird jetzt immer abgeschlossen, anstatt im Synchronisierungsstatus zu bleiben, und das Bearbeiten einer App-Synchronisierung wird ohne Fehler gespeichert. - **Workflow-Datensatzknoten** – Beim Testen eines Knotens „Datensatz erstellen“ oder „Datensatz aktualisieren“ wird jeder Feldschlüssel gemeldet, der nicht mit der Zieltabelle übereinstimmt, anstatt einen leeren Datensatz zu schreiben. - **Interface-Datensatzblätter** – Änderungen, die beim Blättern durch Datensätze vorgenommen werden, werden sofort im Raster angezeigt, Verknüpfungs- und Verknüpfungsaktionen bieten *Rückgängig* und ein innerhalb einer Gruppe erstellter Datensatz bleibt in dieser Gruppe. - **Navigation über die Tastatur der Benutzeroberfläche** – Wenn ein Datensatzblatt geöffnet ist, bewegen sich die Pfeiltasten durch das Raster und das Blatt folgt, und Alt+Links und Alt+Rechts wechseln zwischen Datensätzen. - **Schnittstellen-Builder** – Durch das Hinzufügen einer Sortierung bleibt das Dropdown-Menü geöffnet, durch das Gruppieren einer eingebetteten verknüpften Ansicht bleibt die Seite dahinter an Ort und Stelle und eine gestartete Schnittstelle spiegelt Änderungen wider, die von einer anderen Registerkarte veröffentlicht wurden. - **Dokumentenchecklisten** – Das Ankreuzen einer Aufgabe wird für jeden Mitarbeiter in Echtzeit angezeigt, und ein neuer, nicht markierter Unterpunkt unter einer abgeschlossenen Aufgabe wird ohne Durchstreichung dargestellt. - **Integrationsberechtigungen** – Beim Versuch, eine von jemand anderem erstellte Integration zu bearbeiten, wird eine klare Meldung angezeigt, anstatt Sie abzumelden. - **MCP** – Das Sortieren von Datensätzen funktioniert in der Community Edition, Token ohne Basisrolle erhalten eine eindeutige Antwort „Zugriff verweigert“ und die OAuth-Autorisierung wird von clients wie der OpenAI-Plattform abgeschlossen. - **Externe Quellen** – Eine übergroße Ergebnisseite erklärt, wie man Felder oder Seitengröße reduziert, anstatt die Quelle als nicht erreichbar zu melden. - **Ordner** – Die Schaltfläche *+* auf einer externen Datenquelle bietet jetzt *Ordner* neben *Tabelle* an, und ein Ordner, der über das Menü *Verschieben nach* eines Elements erstellt wird, nimmt die Position des Elements in der Seitenleiste statt am Ende der Liste ein. ## Hinweise zum Selbsthosting - **Im Community-Modus bleiben kostenlose Funktionen sichtbar** – Wenn *Nur Community-Edition-Funktionen anzeigen* aktiviert ist, bleiben Arbeitsabläufe, Schnittstellen und Ordner verfügbar und plangesperrte Unterfunktionen werden ausgeblendet und nicht als tote Steuerelemente angezeigt. - **Sicherheitshärtung** – Deaktivierte oder abgelaufene API-Tokens werden in der Community Edition abgelehnt, ausgeblendete Felder bleiben in freigegebenen Ansichten hinter Zeilenfarbregeln verborgen, Kommentare werden auf ihre Basis beschränkt und die Tabellensichtbarkeit wird auf jeder Route erzwungen. – **Beseitigung von PostgreSQL-Berechtigungsfehlern** – Eine Schemaänderung, die ohne Tabelleneigentum versucht wird, benennt die betroffene Tabelle vollständig, einschließlich Namen in Anführungszeichen mit Leerzeichen oder gemischter Groß-/Kleinschreibung. - **Kostenpflichtige Feldtypen bei nicht lizenzierten Bereitstellungen** – Feldtypen, die nicht in der Community Edition enthalten sind (UUID, AutoNumber, Farbe, eindeutige Einschränkungen und Suchlimits), werden jetzt sowohl vom API als auch von der Benutzeroberfläche abgelehnt. ## Geplante bahnbrechende Änderung des Datetime-Formats API <Callout type="info">Diese Änderung wurde erstmals in 2026.08.2 angekündigt und ist noch für eine kommende Veröffentlichung geplant. Es ist nicht Teil von 2026.09.0. Wir bewahren den Hinweis hier auf, damit Integrationen vorbereitet werden können.</Callout> Bei PostgreSQL- und SQLite-Bereitstellungen ändern sich die von NocoDB zurückgegebenen Datums-/Uhrzeitwerte von Sekunden- auf Millisekundengenauigkeit: | Heute | Kommende Veröffentlichung | | --- | --- | | `2026-07-25 12:34:56+00:00` | `2026-07-25 12:34:56.000+00:00` | - **Geltungsbereich:** REST API-Antworten, Webhook-Nutzlasten und CSV-/Dateiexporte. Werte werden beim Lesen formatiert, sodass auch vorhandene Datensätze im neuen Format zurückgegeben werden. Es ist keine Datenmigration oder Backfill erforderlich. - **Was zu prüfen ist:** Verbraucher, die Datumsangaben mit einem strengen oder festen Format analysieren, müssen möglicherweise die Millisekundenkomponente akzeptieren. Tolerante Parser wie Day.js und die meisten ISO 8601-Parser sind nicht betroffen. - **Filter:** Bereichsfilter und Sortierung sind davon nicht betroffen. Exakte Datum/Uhrzeit-Gleichheitsfilter vergleichen mit Sekundengenauigkeit, daher stimmen sie möglicherweise nicht mit Werten überein, die Millisekunden ungleich Null enthalten. Als Folgemaßnahme ist eine millisekundenbewusste Filterung geplant. - **Nicht betroffen:** MySQL-, SQL Server- und Oracle-Verbindungen behalten die Sekundengenauigkeit bei, durch Formeln gerenderte Datums- und Uhrzeitangaben bleiben bei der Sekundengenauigkeit und die Datums-/Uhrzeitanzeige in der App bleibt unverändert. --- Weitere Einzelheiten zu den in 2026.08.2 eingeführten Funktionen finden Sie unter [2026.08.2 changelog](https://nocodb.com/docs/changelog/2026.08.2). ## Geschlossene Probleme - [**geschlossen**] 🐛 Fehler:Knex Timeout beim Erfassen einer Verbindung [#14467](https://github.com/nocodb/nocodb/issues/14467) - [**geschlossen**] 🐛 Fehler: Link-Datensatzauswahl (Kompakt-/Suchansicht) zeigt die Reihenfolge der Rohtabellenfelder inkl. Rich Text Emails require the Plus plan and above on NocoDB Cloud. In the Community Edition, the MCP server keeps its record tools.

NocoDB in Claude Connectors

NocoDB is now available in Claude Connectors, so a base can be connected to Claude from the connectors directory rather than adding the MCP URL manually. Once connected, Claude can use every MCP tool the connecting user's role allows, which as of this release is a set of 149 covering the whole workspace.

<img width="1280" height="1102" alt="claude-connectors" src="https://github.com/user-attachments/assets/9a241a7f-c90d-4bde-b3c4-665914eeb13d" />

1200% More MCP Tools

The MCP server has gone from 11 tools to 149, covering the whole workspace, not just records. Claude, ChatGPT, Cursor, or any MCP client can now build in NocoDB: stand up a table, wire a workflow to a webhook, assemble an interface page, or lock down permissions, all in one conversation.

Tools span tables, fields, views, filters, sorts, workflows, interfaces, dashboards, widgets, scripts, documents, webhooks, comments, permissions, Record-Level Security, row coloring, folders, members, and CSV import and export. Each wraps the same service as its REST API, so validation, permissions, and audit are identical, and every call respects the caller's role: viewers read, editors write, creators change schema.

149 is just the start. We are already building the next set, and that is the one that changes business software for good.

Rich Text Emails in Workflows

Workflow emails can now be formatted. The Send Email, SMTP, Gmail, and Outlook nodes share a rich text editor that supports headings, text styling, lists, colors, and links with custom anchor text. Workflow variables can be inserted anywhere in the body.

Improvements

  • Buttons across interface pages - Buttons can now be placed on table page headers, record review toolbars, dashboard group headers, and field groups inside a record sheet. Page-level buttons run an automation without a record, and Go to interface page can open a page in any interface in the base. Learn more
  • Drag and drop in List View - Records in List View can be dragged across the hierarchy: drop one onto another to nest it, or onto a different parent to move it there. Sub-records travel with their parent, and the underlying links are updated for you. Learn more
  • Create a linked record field inline - When List View levels or nested records need a link that does not exist yet, click Create a linked record field to create it on the spot, in both the base view and the interface builder. Learn more
  • Date helpers in workflow expressions - $now() returns the current time and $dateAdd(date, amount, unit) offsets it, for example $dateAdd($now(), 3, 'days').
  • Faster Kanban - The optimized Kanban board, previously a feature preview, is now the default everywhere, including the Community Edition. Stacks load progressively as you scroll.
  • Excel downloads of large tables - Excel exports are streamed, so very large tables download reliably and produce smaller files.
  • Task progress in long documents - The task count of a checklist document follows you into the header once the title scrolls out of view.

What's Fixed

  • Nested lookups - A lookup of a lookup shows every value in the grid and resolves correctly over many-to-one links, on MySQL, SQL Server, and Oracle.
  • Conditional rollups with Current User - Rollup, lookup, and link fields whose conditions use Current User are computed for each user rather than served from a shared cache.
  • Sync reliability - A table sync now always completes rather than staying in the syncing state, and editing an app sync saves without error.
  • Workflow record nodes - Testing a Create record or Update record node reports any field key that does not match the target table, instead of writing a blank record.
  • Interface record sheets - Edits made while stepping through records appear in the grid immediately, link and unlink actions offer Undo, and a record created inside a group stays in that group.
  • Interface keyboard navigation - With a record sheet open, arrow keys move through the grid and the sheet follows, and Alt+Left and Alt+Right step between records.
  • Interface builder - Adding a sort keeps the dropdown open, grouping an embedded linked view leaves the page behind it in place, and a launched interface reflects changes published from another tab.
  • Document checklists - Ticking a task is reflected for every collaborator in realtime, and a new unchecked sub-item under a completed task renders without strikethrough.
  • Integration permissions - Attempting to edit an integration created by someone else shows a clear message instead of signing you out.
  • MCP - Sorting records works in the Community Edition, tokens without a base role receive a clear access denied response, and OAuth authorization completes from clients such as OpenAI's platform.
  • External sources - An oversized page of results explains how to reduce fields or page size instead of reporting the source as unreachable.
  • Folders - The + button on an external data source now offers Folder alongside Table, and a folder created from an item's Move to menu takes the item's position in the sidebar instead of the end of the list.

Self-Hosting Notes

  • Community mode keeps Free features visible - With Show only community edition features on, Workflows, Interfaces, and folders stay available, and plan-locked sub-features are hidden rather than shown as dead controls.
  • Security hardening - Disabled or expired API tokens are rejected in the Community Edition, hidden fields stay hidden behind row color rules on shared views, comments are scoped to their base, and table visibility is enforced on every route.
  • Clearer PostgreSQL permission errors - A schema change attempted without table ownership names the affected table in full, including quoted names with spaces or mixed case.
  • Paid field types on unlicensed deployments - Field types not included in the Community Edition (UUID, AutoNumber, Color, unique constraints, and lookup limits) are now rejected by the API as well as the UI.

Planned Breaking Change to API Datetime Format

<Callout type="info">This change was first announced in 2026.08.2 and is still planned for an upcoming release. It is not part of 2026.09.0. We are keeping the notice here so integrations can be prepared.</Callout>

On PostgreSQL and SQLite deployments, datetime values returned by NocoDB will move from second to millisecond precision:

| Today | Upcoming release | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Scope: REST API responses, webhook payloads, and CSV/file exports. Values are formatted on read, so existing records are returned in the new format too. No data migration or backfill is required.
  • What to check: Consumers that parse datetimes with a strict or fixed format may need to accept the millisecond component. Tolerant parsers such as Day.js and most ISO 8601 parsers are unaffected.
  • Filters: Range filters and sorting are unaffected. Exact datetime equality filters compare at second precision, so they may not match values carrying non-zero milliseconds. Millisecond-aware filtering is planned as a follow-up.
  • Not affected: MySQL, SQL Server, and Oracle connections keep second precision, formula-rendered datetimes stay at second precision, and the datetime display in the app is unchanged.

For more details on the features introduced in 2026.08.2, see the 2026.08.2 changelog.
