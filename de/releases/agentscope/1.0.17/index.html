agentscope v1.0.17

Highlights

  • Model & provider compatibility — This patch hardens provider integrations you're likely to hit in production: OpenAI-compatible models now parse the newer vLLM reasoning field (#1271), Gemini streaming parsing tolerates None usage payloads instead of crashing (#1251), DashScopeChatModel moves onto the async multimodal conversation path (#1290), and generate_kwargs now sits after defaults so callers can actually override parameters (#1304). If you run vLLM backends, stream Gemini, or tune DashScope generation params, these directly remove failure modes and unlock overrides that were previously ignored.

  • Breaking (migration required): JsonSession file I/O is now async — #1313 converts JsonSession read/write operations to coroutines. Anyone calling these methods directly must now await them and run inside an async context; synchronous call sites will break. This is the only change in the release with real migration impact, so scan for direct JsonSession usage before upgrading.

  • Hooks and Studio resilience — Several fixes target runtime stability around observability: the Agent no longer crashes when Studio disconnects (#1298), hooks now fire when recovering historical plans (#1279), and set_console_output_enabled is scoped to console printing only instead of leaking into other output behavior (#1186). Worth upgrading if you rely on Studio, plan recovery, or fine-grained output control; otherwise these are invisible improvements.

  • Deep research agent and file/path handling — Multi-turn deep research is fixed (#1239) and register_mcp_client is now properly awaited (#1299), so MCP-backed research flows should stop misbehaving across turns. Separately, text-file tools expand ~ in paths (#1262), base64 saves no longer produce a double-dot extension (#1289), and formatter local-path detection is corrected (#1284) — small but concrete fixes if you work with user home paths or saved artifacts.

  • Upgrade guidance — This is a maintenance/bugfix patch (plus a Node 24 GitHub Actions bump, #1283, and typo/doc cleanups) with no new features beyond two small enablements above. Upgrade if you're on vLLM/Gemini/DashScope, use JsonSession, Studio, plan recovery, or deep research with MCP — most of these are crash or correctness fixes. You can safely skip if you're on a quiet, synchronous, single-provider setup and don't touch those APIs; just budget a quick pass for the async JsonSession migration. No re-tag or metadata-only caveat applies — there are substantive code changes here.
