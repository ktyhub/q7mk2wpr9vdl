1.061 Commits von 412 Mitwirkenden (120 neue). Vielen Dank!

TL;DR

  • 10 neue Modelle (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe und mehr!)
  • Der erweiterbare KV-Cache ist standardmäßig aktiviert: vLLM dimensioniert den KV-Cache nach dem Aufwärmen tatsächlich aus dem Speicher, sodass die meisten Modelle einen größeren Cache und mehr Durchsatz erhalten.
  • Model Runner V1 ist weg. Model Runner V2 ist jetzt der einzige GPU-Runner.
  • Große Geschwindigkeitssteigerungen bei Blackwell und MI355X: bis zu 1.95× Dekodierung (Step5 auf GB200), 1.6× Durchsatz (GLM-5.3-Flash), 1.24–1.40× schnelleres TTFT mit langer Eingabeaufforderung (GLM-5.3).
  • Upgrade-Prüfung: Die Standardblockgröße beträgt jetzt 64, ROCm-7.2-Bilder sind nicht mehr vorhanden und huggingface_hub >= 2.0.0 ist erforderlich. Siehe Vor dem Upgrade.

Highlights

Erweiterbarer KV-Cache, standardmäßig aktiviert

– Bei CUDA und ROCm wird die Größe des KV-Cache anhand des tatsächlich freien Speichers nach der Erfassung und Aufwärmung des CUDA-Diagramms ermittelt, nicht anhand einer Schätzung (#56492).

  • Ergebnis: ein größerer Cache (z. B. MiniMax-M3 auf H200: 433.000 → 672.000 Token), daher ist der Durchsatz höher und die TTFT niedriger bei hoher Parallelität.
  • Kompromiss: Die Dekodierlatenz pro Token kann bei einigen Modellen ansteigen (TPOT +6–18 % bei einigen H200-Modellen bei Parallelität 128). Mit --gpu-memory-utilization 0.9 oder --no-enable-extensible-kv-cache abmelden. – Gehärtet mit Korrekturen für Allokatorfragmentierung, Start-OOMs und KV-Anschlüsse (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Nur Model Runner V2

– Model Runner V1 wurde entfernt (#63373). – Dual-Batch-Überlappung läuft jetzt auf MRV2, auch mit spekulativer Dekodierung und DCP (#61464).

Spekulative Dekodierung

  • Suffix-Dekodierung läuft auf MRV2 mit einem GPU-Spekulator; Arctic Inference wird nicht mehr benötigt (#60339).
  • Benutzerdefinierte Spekulanten: deklarative Konfigurationen plus ein register_speculative_method-Plugin API (#63205).
  • CUDA-Diagramme für MRV2-Entwurfsmodell-Spekulanten (#60989).
  • Adaptive Verifizierung funktioniert mit XPress (#65175). – Draft-KV-Cache entspricht dem Dtype des Ziels, sodass ein FP8-Ziel einen FP8-Draft-Cache erhält (#65198).

AMD ROCm

  • Release-Bilder und Räder sind nur ROCm 10.0 (#61939).
  • MoRI EPv2 über --all2all-backend mori (#61361).
  • Kimi-K3-Spezialdekodierung auf MI355X, Opt-in (#61435). – TRITON_ATTN ist das Standard-Aufmerksamkeits-Backend auf RDNA3 und RDNA4 (#60418).

Bedienung und Betrieb

– Prüfpunkt/Wiederherstellung (CRIU + cuda-checkpoint) über /checkpoint/prepare, /checkpoint/status und /checkpoint/restore, sowohl in den Frontends Python als auch Rust (#62570).

  • Fehlertolerante DP+EP-Skalierung: tote Ränge werden entfernt und ihre Experten redistributed ohne Neustart (#46370). – Best-Effort-NUMA-Bindung standardmäßig aktiviert (#61258). – Opt-in-Bestellung mit cachebasierter Zulassung (#54625).
  • Rust-Frontend: zustandslos Antworten API (#63902) und n > 1 (#65625).

v0.34.0

1,061 commits from 412 contributors (120 new). Thank you!

TL;DR

  • 10 new models (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, and more!)
  • Extensible KV cache is on by default: vLLM sizes the KV cache from memory actually free after warmup, so most models get a bigger cache and more throughput.
  • Model Runner V1 is gone. Model Runner V2 is now the only GPU runner.

  • Upgrade check: default block size is now 64, ROCm 7.2 images are gone, and huggingface_hub >= 2.0.0 is required. See Before you upgrade.

Highlights

Extensible KV cache, on by default

  • On CUDA and ROCm, the KV cache is sized from memory actually free after CUDA graph capture and warmup, not from an estimate (#56492).
  • Result: a larger cache (e.g. MiniMax-M3 on H200: 433k → 672k tokens), so throughput is higher and TTFT lower at high concurrency.
  • Trade-off: per-token decode latency can rise on some models (TPOT +6–18% on some H200 models at concurrency 128). Opt out with --gpu-memory-utilization 0.9 or --no-enable-extensible-kv-cache.
  • Hardened with fixes for allocator fragmentation, startup OOMs and KV connectors (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Model Runner V2 only

  • Model Runner V1 is removed (#63373).
  • Dual-batch overlap now runs on MRV2, including with speculative decoding and DCP (#61464).

Speculative decoding

  • Suffix decoding runs on MRV2 with a GPU speculator; Arctic Inference is no longer needed (#60339).
  • Custom speculators: declarative configs plus a register_speculative_method plugin API (#63205).
  • CUDA graphs for MRV2 draft-model speculators (#60989).
  • Adaptive verification works with XPress (#65175).
  • Draft KV cache matches the target's dtype, so an FP8 target gets an FP8 draft cache (#65198).

  • Release images and wheels are ROCm 10.0 only (#61939).
  • MoRI EPv2 via --all2all-backend mori (#61361).
  • Kimi-K3 specialized decode on MI355X, opt-in (#61435).
  • TRITON_ATTN is the default attention backend on RDNA3 and RDNA4 (#60418).

Serving and operations

  • Checkpoint/restore (CRIU + cuda-checkpoint) through /checkpoint/prepare, /checkpoint/status and /checkpoint/restore, in both the Python and Rust frontends (#62570).
  • Fault-tolerant DP+EP scale-down: dead ranks are removed and their experts redistributed without a restart (#46370).
  • Best-effort NUMA binding on by default (#61258).
  • Opt-in cache-aware admission ordering (#54625).
  • Rust frontend: stateless Responses API (#63902) and n > 1 (#65625).
