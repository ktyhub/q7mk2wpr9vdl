Paket neuer Funktionen

– Ein neues chinesisches Erkennungsmodell für Dokumentenszenarien, das einige seltene chinesische Schriftzeichen berücksichtigt, unterstützt eine Zeichenanzahl von mehr als 15.000. Die Verwendung von CLI ist wie folgt:

paddleocr --image_dir xxx.png --lang ch_doc

Ebenso müssen Sie beim Python API nur den Parameter lang in ch_doc ändern.

PaddleOCR v2.10.0

Highlights

  • NumPy 2.0 migration and dependency slimming — The project now targets NumPy 2.0 and drops imgaug in the same change (#13937), removes the Python-2 compatibility shim six (#14202), and scrubs Python 3.7 references (#14818). This is the real migration cost of the release: NumPy 2.0 breaks the C ABI, so any compiled extensions in your environment must be rebuilt against 2.x, and code with custom imgaug transforms must be ported to albumentations, whose version pin is loosened to ease that transition (#14746). Budget a dependency audit before upgrading.
  • More control over ONNX Runtime deployment — create_predictor now accepts an array of ONNX Execution Providers (#14078), letting you define fallback ordering (e.g., CUDA → CPU) instead of a single provider. Two correctness fixes matter in production: KIE-mode ONNX inference errors are resolved (#14138) and isnan_v2 is now handled by paddle2onnx (#14060); SLANet weights were also refreshed for Paddle 3.0b2 (#14467). If you ship ONNX models, re-run your KIE and NaN-edge-case tests.
  • Paddle 3.0 / PIR export path lands — Model export gains dual PIR and non-PIR support (#14379, #14441) plus export version control (#14513), aligning the toolchain with PaddlePaddle 3.0. Alongside this, paddle.shape now returns int64 tensors (#14318, #14376), which changes how dynamic dimensions propagate through exported graphs — re-verify any shape-sensitive operators and saved-model consumers after upgrading.
  • New recognition model families — Adds UniMERNet (#14357), SLANeXt (#14374), and PP-FormulaNet (#14429) for formula/table understanding, a Thai recognition dictionary (#14620), and a ppocrv4_doc dictionary (#14499); a CLI recognition model flag (#14740) lowers the barrier to trying them. These are additive, but each new model/dict may need corresponding HPI config and weight updates — check the config repo when pinning versions.
  • Production stability, new hardware, and a behavior change — Long-running inference servers benefit from a GPU memory growth fix (#14037) and NaN fixes in PP-OCRv4 (#14043, #14072), while TensorRT recognition models get corrected dynamic shapes (#14654). Enflame GCU inference support (#14142) adds another backend, and model download paths can now be overridden with the PADDLE_OCR_BASE_DIR environment variable (#14678, #14686) — useful for containers and air-gapped setups. Watch for one behavioral change: images containing no text now emit a warning (#14132), which may affect log volume in batch pipelines.

Package New Features

  • A new Chinese recognition model for document scenarios, addressing some rare Chinese characters, supports a character count exceeding 15,000. CLI usage is as follows:
paddleocr --image_dir xxx.png --lang ch_doc

Similarly, in the Python API, you only need to change the lang parameter to ch_doc.
