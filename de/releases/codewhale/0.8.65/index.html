Codewal v0.8.65

CodeWhale ist das kanonische Projekt, der Befehl, das NPM-Paket und Name des Release-Assets. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer kommen aus Die alten v0.8.x-Namen deepseek/deepseek-tui sollten migriert werden mit docs/REBRAND.md.

Installieren

Empfohlen – npm (ein Befehl, beide Binärdateien)

npm install -g codewhale

Der Wrapper lädt die passenden Laufzeitbinärdateien aus dieser Version herunter und platziert sie im selben Verzeichnis.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.65

Das Image enthält den codewhale-Dispatcher, das codew-Shim und die codewhale-tui-Laufzeit. Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Beide Kisten sind erforderlich – codewhale-cli produziert den codewhale-Dispatcher und das codew-Shim, während codewhale-tui die interaktive Laufzeit produziert, an die der Dispatcher delegiert. Die Installation nur einer Kiste schlägt zur Laufzeit mit dem Fehler MISSING_COMPANION_BINARY fehl.

Manueller Download – Plattformarchive (empfohlen)

Jedes der folgenden Archive enthält den codewhale-Dispatcher, den codew-Shim und die codewhale-tui-Laufzeit sowie ein Installationsskript: | Plattform | Archiv | Skript installieren | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (Installer) | CodeWhaleSetup.exe | NSIS-Setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (tragbar) | codewhale-windows-x64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

  • Für den Installationspfad führen Sie CodeWhaleSetup.exe aus; Es installiert codewhale.exe, codew.exe und codewhale-tui.exe unter %LOCALAPPDATA%\Programs\CodeWhale\bin und fügt dieses Verzeichnis dem PATH des aktuellen Benutzers hinzu.
  • Extrahieren Sie codewhale-windows-x64.zip
  • Führen Sie install.bat aus (kopiert nach %USERPROFILE%\bin)
  • Fügen Sie %USERPROFILE%\bin zu Ihrem PATH hinzu Das tragbare Windows-Archiv überspringt das Installationsskript – extrahieren Sie es und führen Sie es aus einem beliebigen Verzeichnis aus. An jede Plattform sind unten auch nackte, nicht archivierte Binärdateien angehängt (codewhale-<platform>, codew-<platform> und codewhale-tui-<platform>) – der npm-Wrapper und der In-App-codewhale update laden die passenden Laufzeitbinärdateien herunter, während die oben genannten .tar.gz-/.zip-Archive der empfohlene manuelle Download sind und zusätzlich ein Installationsskript bündeln. Das alte NPM-Paket deepseek-tui ist veraltet und wird nicht erneut veröffentlicht. Informationen zur Migration von v0.8.x-Legacy-Binärnamen finden Sie unter docs/REBRAND.md.

Was ist in v0.8.65

Hinzugefügt

  • Anbieter-/Modell-/Routenauflösung (EPIC #2608). Kanonischer Anbieter, Modell, Angebot und Routentypen mit einem einzigen RouteResolver, der ein erzeugt ReadyRouteCandidate behoben (Endpunkt, Wire-Protokoll, Modell-ID, Kontext Limit, Preis) für jeden Schalter (#3458, #3084, #3384). Der ausführende client ist Jetzt aus dem aufgelösten Kandidaten erstellt und nicht erneut aus der Konfiguration abgeleitet (#3384). Ein engagierter, netzwerkfreier Models.dev-Katalog bietet echte Modelle Kontextfenster und Preise, mit geheimnisfreiem Live-Cache (#3497, #3498, #3385). Angebotspreise mit Herkunft werden auf Kandidaten projiziert (#3501, #3085) und Routenlimits versorgen einen routenbewussten Kontextbudgetdienst (#3508, #3523, #3086).
  • Flottenausführungssubstrat (EPIC #3154). Flottenprofiltypen und -konfiguration (#3469), dauerhafter Manager-Lebenslauf, Laden des Workspace-Agentenprofils behoben in die Worker-Laufzeit (#3367), die in den Aufgabenspezifikationen enthaltene Loadout-Absicht (#3512) und Belege, die die aufgelöste Route zur Prüfung beibehalten (#3154, #3166). Arbeiter Der Status wird in die einheitliche /fleet-Oberfläche integriert und durch die freigelegt Laufzeit API.
  • Anbieteroberflächen. Ein /provider-Bereitschafts-Dashboard mit Begründung Bereitschaft, ein experimenteller/unterstützter Reifegradmarker und ein „offenes Modell für“. Aktion „dieser Anbieter“ (#3083, #2984, #3485); anbieterübergreifende /model-Suche mit Scroll- und Provider-Type-Ahead (#3484, #3075); Inline-<think> Reasoning-Stream-Routing mit Overrides pro Anbieter (#3222); Nutzungstelemetrie normalisiert in kanonische Token-Klassen, einschließlich Antworten, Cache-Miss und Argumentationstoken (#2961, #3509); und Remote-MCP-OAuth-Anmeldung mit Bearer/Header Authentifizierungspriorität (#3527).
  • Mehr Anbieter und Routen. Benutzerdefinierte OpenAI-kompatible benutzerdefinierte Anbieter über [providers.<name>] (#1519); eine DeepSeek Anthropic-kompatible Route (#2963, #3449); eine Qianfan-Route (#3425); Zhipu faltete sich mit gleicher Behandlung in Z.ai ein Modellnormalisierung (#3539); DashScope/Together-Geräte.
  • Lokalisierte Modus-Auswahl- und Composer-Anzeigen. Die /mode-Auswahl-Eingabeaufforderung, Modusnamen und Hinweise sowie die Vim-Modusanzeige des Komponisten werden jetzt gerendert alle sieben ausgelieferten Gebietsschemas (Modellbezeichnungen bleiben englisch). Geerntet aus #2239 von @gordonlu.
  • Website und Automatisierung. Eine Laufzeit-/Integrationsseite, Herkunft und Mirror-trust-Kopie, ein Fact-Drift-CI-Gate, ein veröffentlichtes Installationsskript und a Wöchentliches Community-Digest-Archiv auf codewhale.net (#3419, #3421, #3415, #3482, #3420); Per-Automation-Modus/Shell/trust/Genehmigungseinstellungen (#3467).
  • Modellreferenzbrowser. Ein schreibgeschützter /modeldb-Befehl (Aliase model-reference, modelref) öffnet einen Pager über dem gebündelten Katalog – alle Sachkontextfenster des Modells, maximale Ausgabe, Modalität und Preis, gruppiert nach Anbieter/Art. Nur Beschriftungen: Es wird niemals ein Modell ausgewählt, weitergeleitet oder gestuft (#3205, #2300).
  • Transkript-Voreinstellungen. Ein /config preset <name> [--save]-Mechanismus mit a erste calm-Voreinstellung – Ruhemodus, ruhiges Zusammenklappen des Werkzeugs, komfortabler Abstand und Low Motion – nur Präsentation und Beweissicherung (#3478).
  • Modellfähigkeitsprofile. Ein typisiertes model_profile-Modul trennt sich Intrinsische Modellfakten aus aufgelöster Provider-Route-Fähigkeit, also kompakt Routen verzögern schwerere, nicht unbedingt erforderliche Werkzeuge, während Standard-/vollständige Routen dies beibehalten eifrige Werkzeugoberfläche (#3451, #3365).
  • Aktualisierung des Live-Anbieterkatalogs. Eine geheimnisfreie /models-Live-Abrufebene (401/403/404/429 zugeordnet zu typisierten Ergebnissen) speist den Katalog-Cache; der API Der Schlüssel autorisiert die Anforderung, wird jedoch niemals im Delta oder Cache gespeichert (#3385).

Geändert

  • Modularisierung konfigurieren (#3311). ProviderKind (#3505), Kabelbaumhaltung (#3507) und Anbieter-Standard-Seeds (#3503) wurden in dedizierte Module verschoben, und Der config.rs-Monolith ist in saubere Blattmodule aufgeteilt (Pfade, Suche, Modell-/Basis-URL-Konstanten, Subagenten-Limits) hinter einer pub use-Fassade. AppMode-Helfer wurden zentralisiert (#3510) und die Modus-gegen-Berechtigungs-Richtlinie ist zentralisiert jetzt über einen einzelnen base_policy_for_mode-Resolver abgeleitet statt Streumutation (#3386, beratendes Überprüfungsabsichtsverhalten erhalten).
  • Schlankere Werkzeugoberfläche. task_shell_* aus dem aktiven Satz entfernt und gefaltet tool_search_* (#3463); Der wiederum loop_guard wurde entfernt und die Argumentation codiert Verfügungen (#3462); fügte der Satzung die Anordnung zur Orchestrierung hinzu.
  • Routing. Anbieter-/Modellwechsel und die fähigkeitsbewusste Fallback-Kette Lösung durch RouteResolver; Der Argumentationsaufwand wird für die normalisiert aufgelöster Anbieter; Die Fallback-Kette überspringt jetzt Anbieter ohne Authentifizierung (#2574); und Kontextfenster und Speicherdruck kommen von der aufgelösten Route (#3086).
  • UX. Das Genehmigungsmodal erhielt einen Gruppenteiler und ein Caretzeichen für ausgewählte Zeilen (#3515); Auswahl-Scroll/Vorschrift und Auswahlkontrast gehärtet (#3500); die README wurde als Architektur-Endkappe umgeschrieben (#3087); und die Anleitung des Repo-Agenten war de-hardcodiert, um die Wahrheit zu leben.
  • Flottenidentität und Standardeinstellungen Flottenarbeiter betreten jetzt mit einem expliziten Betriebsvertrag „herbeigerufenes Flottenmitglied“, Setup-/Profilaufforderungen behalten die Standardmodellverhalten als Same-Route-Vererbung und generierter Worker Anweisungen verhindern, dass rekursive Topologien verloren gehen, die nur dem Orchestrator vorbehalten sind Bedürfnisse.
  • Alte Schwarmbereinigung. Der veraltete /swarm-Kernbefehl/Menü wurde entfernt Registrierung, sodass /fleet die Produktoberfläche ist, während /subagents eine bleibt Kompatibilitätsverknüpfung zum Worker-Status.
  • Animation des Betriebszustands. Werkzeugkarten und Hintergrundaufgabenzeilen teilen sich jetzt eine Schnellere Braille-Spinner-Kadenz, sodass Bash/Hintergrundarbeit konsistent gelesen wird lebendig im Transkript und in der Seitenleiste.
  • Mitwirkender-Gutschrift wiederhergestellt. Maschinenlesbare Gutschrift mit Thread (docs/CONTRIBUTORS.md + .github/AUTHOR_MAP) für frühere zusammengeführte Arbeiten Wird ohne geliefert, einschließlich der /jobs cancel-all-Aktion und der NPM Retry-Timeout-Hinweis (#1538) von @jieshu666 und der Community-ACP-Adapter Referenz von @rockeverm3m.

Behoben

  • Release-Hygiene. Die strikte Cargo clippy --workspace --all-targets --locked -- -D warnings gate passes; npm run build verunreinigt die generierten Dateien nicht mehr Web-Fakten; die Site setzt metadataBase; Die Community-Digest-Seite analysiert jeden nimmt selbstständig auf und lokalisiert sein Chrom; und cargo audit ist sauber mit die starlark-transitiven, nicht gepflegten Hinweise dokumentiert.
  • Korrektheit von Routing und Modus. Es gibt keinen gewöhnlichen Eingabeaufforderungstext mehr wird als Modusschalter interpretiert (#3387, #3491); Modellkandidaten sind auf die beschränkt aktiver Anbieter; Gemeinsame DeepSeek-Routen werden akzeptiert (#3426); unsicher Benutzerdefinierte http://-Endpunkte lösen eine Hinweiswarnung aus (#1519); und die Flotte Die Rollen-/Modellauswahl des Setup-Planers bestimmt nun das generierte Profil.
  • Laufzeitstabilität. MCP-Verbindungsabbrüche sind explizit (#3524), HTTP API Anrufe verwenden einen gemeinsam genutzten MCP-Pool (#3532) und ein Subagenten-Postfach pro Agent Die Telemetrie wird gedrosselt, um die Verzögerung der Benutzeroberfläche zu verringern (#3454).
  • YOLO-Hintergrund-Shell-Genehmigungen. Ein Hintergrund-Shell-Befehl erscheint nicht mehr ein Genehmigungsmodal im YOLO-Modus. classify_risk markiert alle Shell-Befehle destruktiv, daher hielt der Sicherheitsboden der automatischen Überprüfung jede Hintergrund-Shell für zurück Rezension, und die ForcePrompt-Site hat auto_approve nie überprüft – nur Hintergrundbefehle haben es aufgetaucht, da Vordergrund-Shells das übernehmen Interactive origin und überspringen Sie diesen Zweig.
  • Bash-Genehmigungsmodal-Passform. Das Shell-Genehmigungsmodal beschriftet jetzt Bash Befehle direkt, vermeidet die Wiederholung von command/workdir in der Auswirkungszusammenfassung, Umschließt lange Befehle und wechselt auf kurze Terminals zu kompakten Steuerelementen Die Entscheidungsschlüssel bleiben sichtbar.
  • Benutzerdefinierte Provider-Auswahlzeilen. Konkrete [providers.<name>]-Einträge jetzt werden in der Anbieterauswahl angezeigt (ID, Endpunkt, Authentifizierungsbereitschaft, Übertragungsprotokoll, aktuelles Modell) anstelle nur des generischen Platzhalters; Auszeichnungen für die Authentifizierungsbereitschaft Schlüssel pro Eintrag/env/metadata/no-auth/loopback.
  • Passive MCP-Tool-Erkennung. Runtime API-eigene stdio MCP-Prozesse sind nein länger aus passiven /v1/apps/mcp/tools-Anfragen hervorgegangen; Live-Entdeckung bleibt über ?connect=true verfügbar. doctor warnt jetzt auf dem relativen Pfad stdio MCP-Befehle ohne cwd.

Codewhale v0.8.65

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Install

Recommended — npm (one command, both binaries)

npm install -g codewhale

The wrapper downloads the matched runtime binaries from this Release and places them in the same directory.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.65

The image ships the codewhale dispatcher, codew shim, and codewhale-tui runtime. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Both crates are required — codewhale-cli produces the codewhale dispatcher and codew shim, while codewhale-tui produces the interactive runtime that the dispatcher delegates to. Installing only one crate will fail at runtime with a MISSING_COMPANION_BINARY error.

Manual download — platform archives (recommended)

Each archive below contains the codewhale dispatcher, codew shim, and codewhale-tui runtime, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs codewhale.exe, codew.exe, and codewhale-tui.exe under %LOCALAPPDATA%\Programs\CodeWhale\bin and adds that directory to the current-user PATH.
  • Extract codewhale-windows-x64.zip
  • Run install.bat (copies to %USERPROFILE%\bin)
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Each platform also has bare, unarchived binaries attached below (codewhale-<platform>, codew-<platform>, and codewhale-tui-<platform>) — the npm wrapper and the in-app codewhale update download the matched runtime binaries, whereas the .tar.gz / .zip archives above are the recommended manual download and additionally bundle an install script. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.

What's in v0.8.65

Added

  • Provider/model/route resolution (EPIC #2608). Canonical provider, model, offering, and route types with a single RouteResolver that produces a resolved ReadyRouteCandidate (endpoint, wire protocol, model id, context limit, price) for every switch (#3458, #3084, #3384). The executing client is now constructed from the resolved candidate rather than re-derived from config (#3384). A committed, network-free Models.dev-shaped catalog gives models real context windows and pricing, with a secret-free live cache (#3497, #3498, #3385). Offering pricing with provenance is projected onto candidates (#3501, #3085), and route limits feed a route-aware context-budget service (#3508, #3523, #3086).
  • Fleet execution substrate (EPIC #3154). Fleet profile types and config (#3469), durable manager resume, workspace agent-profile loading resolved into the worker runtime (#3367), loadout intent carried in task specs (#3512), and receipts that persist the resolved route for inspection (#3154, #3166). Worker status is folded into the unified /fleet surface and exposed through the Runtime API.
  • Provider surfaces. A /provider readiness dashboard with reasoning readiness, an experimental/supported maturity marker, and an "open models for this provider" action (#3083, #2984, #3485); cross-provider /model search with scroll and provider type-ahead (#3484, #3075); inline <think> reasoning-stream routing with per-provider overrides (#3222); usage telemetry normalized into canonical token classes including Responses cache-miss and reasoning tokens (#2961, #3509); and remote MCP OAuth login with bearer/header auth precedence (#3527).
  • More providers and routes. User-defined OpenAI-compatible custom providers via [providers.<name>] (#1519); a DeepSeek Anthropic-compatible route (#2963, #3449); a Qianfan route (#3425); Zhipu folded into Z.ai with equal-treatment model normalization (#3539); DashScope/Together fixtures.
  • Localized mode picker and composer indicators. The /mode picker prompt, mode names, and hints, plus the composer's Vim mode indicator, now render in all seven shipped locales (model-facing mode labels stay English). Harvested from #2239 by @gordonlu.
  • Website and automation. A runtime/integrations page, provenance and mirror-trust copy, a fact-drift CI gate, a published install script, and a weekly community digest archive on codewhale.net (#3419, #3421, #3415, #3482, #3420); per-automation mode/shell/trust/approval settings (#3467).
  • Model reference browser. A read-only /modeldb command (aliases model-reference, modelref) opens a pager over the bundled catalog — every model's factual context window, max output, modality, and price, grouped by provider/kind. Labels only: it never selects, routes, or tiers a model (#3205, #2300).
  • Transcript presets. A /config preset <name> [--save] mechanism with a first calm preset — calm mode, calm tool collapse, comfortable spacing, and low motion — presentation-only and evidence-preserving (#3478).
  • Model capability profiles. A typed model_profile module separates intrinsic model facts from resolved provider-route capability, so compact routes defer heavier nonessential tools while standard/full routes keep the eager tool surface (#3451, #3365).
  • Live provider catalog refresh. A secret-free /models live-fetch layer (401/403/404/429 mapped to typed outcomes) feeds the catalog cache; the API key authorizes the request but is never persisted into the delta or cache (#3385).

Changed

  • Config modularization (#3311). ProviderKind (#3505), harness posture (#3507), and provider default seeds (#3503) moved into dedicated modules, and the config.rs monolith split into clean leaf modules (paths, search, model/base-URL constants, sub-agent limits) behind a pub use facade. AppMode helpers were centralized (#3510), and mode-vs-permission policy is now derived through a single base_policy_for_mode resolver instead of scattered mutation (#3386, advisory review-intent behavior preserved).
  • Leaner tool surface. Dropped task_shell_* from the active set and folded tool_search_* (#3463); ablated the in-turn loop_guard and encoded reasoning dispositions (#3462); added the Orchestration disposition to the constitution.
  • Routing. Provider/model switches and the capability-aware fallback chain resolve through RouteResolver; reasoning effort is normalized for the resolved provider; the fallback chain now skips providers that lack auth (#2574); and context window and memory-pressure come from the resolved route (#3086).
  • UX. Approval modal gained a group divider and selected-row caret (#3515); picker scroll/type-ahead and selection contrast hardened (#3500); the README was rewritten as an architecture end-cap (#3087); and repo agent guidance was de-hardcoded to live truth.
  • Fleet identity and defaults. Fleet workers now enter with an explicit "summoned Fleet member" operating contract, setup/profile prompts keep the default model behavior as same-route inheritance, and generated worker instructions avoid leaking recursive topology that only the orchestrator needs.
  • Legacy swarm cleanup. Removed the obsolete /swarm core command/menu registration so /fleet is the product surface, while /subagents remains a compatibility shortcut to worker status.
  • Running-state animation. Tool cards and background-task rows now share one faster braille spinner cadence, so Bash/background work reads consistently alive across the transcript and sidebar.
  • Restored contributor credit. Threaded machine-readable credit (docs/CONTRIBUTORS.md + .github/AUTHOR_MAP) for earlier merged work that shipped without it, including the /jobs cancel-all action and the npm retry-timeout hint (#1538) by @jieshu666, and the community ACP adapter reference by @rockeverm3m.

Fixed

  • Release hygiene. The strict cargo clippy --workspace --all-targets --locked -- -D warnings gate passes; npm run build no longer dirties the generated web facts; the site sets metadataBase; the community digest page parses each record independently and localizes its chrome; and cargo audit is clean with the starlark-transitive unmaintained advisories documented.
  • Routing and mode correctness. Ordinary prompt text is no longer interpreted as a mode switch (#3387, #3491); model candidates are scoped to the active provider; Together-owned DeepSeek routes are accepted (#3426); insecure http:// custom endpoints raise an advisory warning (#1519); and the Fleet setup planner's role/model selection now drives the generated profile.
  • Runtime stability. MCP connection drops are explicit (#3524), HTTP API calls reuse a shared MCP pool (#3532), and per-agent sub-agent mailbox telemetry is throttled to cut UI lag (#3454).
  • YOLO background-shell approvals. A background shell command no longer pops an approval modal in YOLO mode. classify_risk marks all shell commands destructive, so the auto-review safety floor held every background shell for review, and the ForcePrompt site never checked auto_approve — only background commands surfaced it, since foreground shells take the Interactive origin and skip that branch.
  • Bash approval modal fit. The shell approval modal now labels Bash commands directly, avoids repeating command/workdir in the impact summary, wraps long commands, and switches to compact controls on short terminals so the decision keys stay visible.
  • Custom-provider picker rows. Concrete [providers.<name>] entries now appear in the provider picker (id, endpoint, auth readiness, wire protocol, current model) instead of only the generic placeholder; auth readiness honors per-entry key/env/metadata/no-auth/loopback.
  • Passive MCP tool discovery. Runtime API-owned stdio MCP processes are no longer spawned from passive /v1/apps/mcp/tools requests; live discovery remains available through ?connect=true. doctor now warns on relative-path stdio MCP commands without cwd.
