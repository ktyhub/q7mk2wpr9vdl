Codewal v0.8.63

CodeWhale ist das kanonische Projekt, der Befehl, das NPM-Paket und Name des Release-Assets. Das alte NPM-Paket deepseek-tui ist veraltet und erhält keine weiteren Veröffentlichungen. Benutzer kommen aus Die alten v0.8.x-Namen deepseek/deepseek-tui sollten migriert werden mit docs/REBRAND.md.

Installieren

Empfohlen – npm (ein Befehl, beide Binärdateien)

npm install -g codewhale

Der Wrapper lädt beide Binärdateien aus dieser Version herunter und legt sie im selben Verzeichnis ab.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.63

Das Image enthält den codewhale-Dispatcher und die codewhale-tui-Laufzeit. Das latest-Tag wird bei der Veröffentlichung ebenfalls aktualisiert.

Fracht (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Beide Kisten sind erforderlich – codewhale-cli erzeugt den codewhale-Dispatcher und codewhale-tui erzeugt die interaktive Laufzeit, an die der Dispatcher delegiert. Die Installation nur einer Binärdatei schlägt zur Laufzeit mit dem Fehler MISSING_COMPANION_BINARY fehl.

Manueller Download – Plattformarchive (empfohlen)

Jedes der folgenden Archive enthält sowohl den codewhale-Dispatcher als auch die codewhale-tui-Laufzeitumgebung sowie ein Installationsskript: | Plattform | Archiv | Skript installieren | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (Installer) | CodeWhaleSetup.exe | NSIS-Setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (tragbar) | codewhale-windows-x64-portable.zip | — | Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Führen Sie für den Installationspfad CodeWhaleSetup.exe aus. Es installiert beide Binärdateien unter %LOCALAPPDATA%\Programs\CodeWhale\bin und fügt dieses Verzeichnis dem PATH des aktuellen Benutzers hinzu.
  • Extrahieren Sie codewhale-windows-x64.zip
  • Führen Sie install.bat aus (kopiert nach %USERPROFILE%\bin)
  • Fügen Sie %USERPROFILE%\bin zu Ihrem PATH hinzu Das tragbare Windows-Archiv überspringt das Installationsskript – extrahieren Sie es und führen Sie es aus einem beliebigen Verzeichnis aus. Das NSIS-Installationsprogramm ist derzeit nicht signiert und löst möglicherweise Windows SmartScreen aus, bis ein Signaturzertifikat in die Release-Pipeline eingebunden wird. An jede Plattform sind unten außerdem nackte, nicht archivierte Binärdateien angehängt (codewhale-<platform> und codewhale-tui-<platform>) – diese werden vom npm-Wrapper und dem In-App-Download codewhale update heruntergeladen, wohingegen die oben genannten .tar.gz-/.zip-Archive der empfohlene manuelle Download sind und zusätzlich ein Installationsskript enthalten. Das alte NPM-Paket deepseek-tui ist veraltet und wird nicht erneut veröffentlicht. Informationen zur Migration von v0.8.x-Legacy-Binärnamen finden Sie unter docs/REBRAND.md.

Was ist in v0.8.63

Hinzugefügt

  • Subagenten-Fanout-Schutzmaßnahmen (#3318, #3319). Workflow-Ausführungen mit hohem Fanout können Jetzt stehen mehr Agenten in der Warteschlange und entladen sie, als die momentane Parallelitätsbeschränkung vorsieht Standardmäßig ist [subagents] max_admitted verfügbar, um diese Grenze abzustimmen Aufnahmebevölkerung. Eindeutige agent-Anrufe werden nicht mehr durch die begrenzt Schleifenwächter pro Runde vor dem Start der Laufzeit, Parallelität und Anbieter Es kann ein Rate-Limit-Backoff gelten. [subagents] token_budget wendet eine gemeinsame an Aggregierte Token-Obergrenze für einen Root-agent-Lauf und seine Nachkommen.
  • Durchsetzung des Subagenten-Tokens pro Worker (#3321). A token_budget / max_tokens, das für einen einzelnen agent-Aufruf festgelegt ist, bindet nun diesen einzelnen Worker Mid-Run: Sobald die angesammelten Modell-Tokens die Obergrenze überschreiten, stoppt es sauber mit einem budget_exhausted-Status, anstatt bis max_steps zu laufen. Dies ergänzt das Zulassungstor auf Umfangsebene (Nr. 3319) – die Obergrenze pro Mitarbeiter endet ein außer Kontrolle geratener Arbeiter, die Scope-Obergrenze begrenzt die totale Auffächerung – ohne Doppelzählung. Geerntet aus #3321 von @donglovejava.
  • Anbieterspezifische Subagent-Fanout-Konfiguration [subagents.providers.<provider>] Profile überschreiben jetzt enabled, max_concurrent, max_admitted, launch_concurrency, max_depth, Token-Budget, API-Timeout und Heartbeat Timeout für den aktiven Anbieter. Verwenden Sie breite Direct-API-Profile wie z [subagents.providers.deepseek] und engere Abonnementprofile wie z [subagents.providers.glm]; /config subagents status zeigt beides global und vom aktiven Anbieter aufgelöste Werte.
  • Kontrolle und Isolierung von Subagenten. Das einzelne agent-Tool wird jetzt verfügbar gemacht Status-, Blick- und Abbruchaktionen für laufende untergeordnete Elemente und akzeptiert worktree: true zum Erstellen eines isolierten Git-Arbeitsbaums/Zweigs für die parallele Bearbeitung Lanes, anstatt vom Anrufer zu verlangen, einen cwd von Hand zu würfeln.

Behoben

  • Korrektheit von Modus und Werkzeugkatalog. Kernaktionswerkzeuge bleiben erkennbar in der modellbezogenen Katalog-/Werkzeugsuche und Flags zur Konsistenzselbstprüfung registrierte Händler, die vom beworbenen Katalog abweichen. Rezensionsaussehend Eingabeaufforderungen im expliziten Agent/YOLO-Modus behalten jetzt den angeforderten Modus und die angeforderten Tools bei. mit nur einem beratenden Rezensionshinweis.
  • Wiederherstellung der Subagenten-Orchestrierung. Untergeordnete Agenten versuchen es jetzt vorübergehend erneut Es kommt zu Zeitüberschreitungen im Provider-Header/SSE, bevor ein Fehler auftritt, und die Synthese übergeordneter Läufe wird fehlgeschlagen Untergeordnete Vervollständigungen aus dem untergeordneten Terminalstatus, sodass die Orchestrierung nicht hängen bleiben kann Abschlussereignis verloren.
  • DeepSeek Thinking Tool-Aufrufe. DeepSeek-Chat-Abschlussanfragen werden jetzt weggelassen explizites tool_choice, wann immer Argumentation/Denken aktiviert ist, Vermeiden Provider-Ablehnungen, während unüberlegte Routen unverändert bleiben.
  • Verknüpfungen und Zuordnung in der Aufgabenseitenleiste. Strg-K bleibt palette/emacs-kill, während Strg-X auf das Abbrechen der Tasks-Sidebar-Hintergrund-Shell beschränkt ist. Muschel Von Unteragenten gestartete Jobs werden jetzt mit ihrem untergeordneten Agenten-Eigentümer im gerendert Aufgabenseitenleiste und Transkript.
  • Benchmark-Turn-Wiederherstellung und Kontextökonomie. Wiederholte schreibgeschützte Suche Schleifenblöcke geben jetzt Anleitungen statt schwerwiegender Werkzeugausfälle zurück, Build Python Fehler, bei denen setuptools fehlt, enthalten einen langen Installations-/Wiederholungshinweis Zeitüberschreitungen der Vordergrund-Shell lenken Modelle in Richtung Hintergrundausführung und verursachen Rauschen Shell-/Test-/Web-Ausgaben werden für Routen mit großem Kontext früher komprimiert.
  • Anzeigeschwärzung konfigurieren. codew config get/list maskiert jetzt rekursiv Token-, Geheim-, Passwort-, Anmeldeinformations- und autorisierungsähnliche Schlüssel darin unbekannte extras-Tabellen und schwärzen zuvor vertrauliche HTTP-Header-Werte Drucken der Konfigurationsausgabe.
  • Folgehinweise in der Warteschlange und Force-Steer-Tasten. Jetzt die Vorschau der ausstehenden Eingaben kündigt Ctrl+S send now an, wenn in der Warteschlange befindliche Follow-ups vorhanden sind, und Strg/Befehl+Eingabetaste Force-Steering akzeptiert auch das übliche Strg+J-Terminal Codierung, während eine Runde läuft.
  • Standardsichtbarkeit der Seitenleiste wiederhergestellt (#3328). Neue und aktualisierte Sitzungen Verwenden Sie jetzt standardmäßig eine angeheftete zusammengesetzte Seitenleiste, wenn das Terminal breit ist genug, sodass Live-Agenten und Aufgaben angezeigt werden, ohne dass man sich dafür entscheiden muss, wieder in den Leerlauf zu wechseln automatisches Zusammenklappen. Ältere Einstellungsdateien, die die automatische Reduzierung des v0.8.62 erfasst haben Standardmäßig wird jetzt auf pinned migriert, es sei denn, /sidebar auto --save zeichnet eine auf explizites Opt-in. /sidebar meldet jetzt, wann Breite oder automatisches Reduzieren Unterdrückt das Rendern, anstatt anzuzeigen, dass die Seitenleiste sichtbar ist. Berichtet von @dxfq. – JavaScript Ausführungs-Proxy-Umgebungsbehandlung (#3273, #3331). js_execution Aktiviert jetzt den Umgebungs-Proxy-Modus des Knotens, wenn Proxy-Variablen vorhanden sind. spiegelt Kleinbuchstaben-Proxy-Variablen für den untergeordneten Prozess und Backfills HTTP_PROXY / HTTPS_PROXY von ALL_PROXY. Berichtet von @lordwedggie und geerntet aus #3331 von @cyq1017. – Legacy-App-Server-Nicht-Loopback-Authentifizierungshärtung (#3258). Nicht verfügbar codewhale app-server --host 0.0.0.0 schlägt jetzt schnell fehl, es sei denn, es wird explizit angegeben --auth-token oder CODEWHALE_APP_SERVER_TOKEN wird mitgeliefert und bleibt generiert einmalige cwapp_*-Tokens, nur Loopback. – Alte .deepseek-Status-Schreibpfad-Migration (#3240). Status-Unterverzeichnisse (sessions, slop_ledger, trophies, catalog) werden jetzt immer darunter geschrieben ~/.codewhale/, und der erste Schreibvorgang eines Unterverzeichnisses verschiebt alle bereits vorhandenen ~/.deepseek/<sub>-Inhalte werden am primären Speicherort gespeichert, sodass der Legacy-Baum stoppt wächst, während alte Daten erhalten bleiben. Der Leseauflöser findet weiterhin Altdaten zum Auffüllen, bis jedes Unterverzeichnis migriert wird. Gemeldet von @Final527; Onboarding Marker-Slice aus #3302 von @nightt5879.
  • Status-Unterverzeichnisvalidierung unter Windows (#3240). Statuspfad-Härtung jetzt lehnt verwurzelte/präfixierte Unterverzeichniszeichenfolgen wie /etc vor der Auflösung ab oder Migrieren von Statusverzeichnissen unter Beibehaltung des Schreibresolvers .codewhale seine Statuswurzel plattformübergreifend. Die Mitwirkenden für diese Veröffentlichung finden Sie im changelog-Eintrag oben – Vielen Dank an alle, deren Berichte, PRs, Rezensionen und Reproduktionen es geprägt haben. Vollständige Hinweise finden Sie unter CHANGELOG.md und unter docs/CHANGELOG_ARCHIVE.md für ältere Versionen.

Codewhale v0.8.63

Highlights

  • Rebrand and dual-binary install — deepseek-tui is deprecated and no longer published; anyone on legacy v0.8.x deepseek/deepseek-tui names must migrate via docs/REBRAND.md. Every install path now ships two cooperating binaries — the codewhale dispatcher and the codewhale-tui runtime — so Cargo users must install both crates (codewhale-cli + codewhale-tui) or hit MISSING_COMPANION_BINARY at runtime. Watch out for the unsigned NSIS installer on Windows, which will trigger SmartScreen until signing is wired up.

  • Bounded, tunable sub-agent fanout — #3318/#3319 replace the hard instantaneous concurrency cap with a queue-and-drain admission model ([subagents] max_admitted) and stop counting distinct agent calls against the per-turn loop guard, so high-fanout workflows can finally launch instead of being silently throttled. Cost control comes from two deliberately non-overlapping ceilings: a scope-wide [subagents] token_budget for a root run and its descendants (#3319), and a per-worker token_budget/max_tokens that ends a single child cleanly with budget_exhausted rather than grinding to max_steps (#3321).

  • Provider-scoped sub-agent policy and control — [subagents.providers.<provider>] profiles override concurrency, depth, timeouts, and token budgets per provider, so you can run loose settings for direct-API routes like deepseek and tighter caps for subscriptions like glm; /config subagents status now shows both resolved globals and the active-provider values — check this when a fanout behaves differently than expected. The agent tool also gains status/peek/cancel actions and worktree: true, which spins up an isolated branch/worktree for parallel edit lanes instead of making you hand-roll cwd.

  • Auth and config-redaction behavior changes — #3258 makes codewhale app-server --host 0.0.0.0 fail fast unless you pass --auth-token or CODEWHALE_APP_SERVER_TOKEN; generated cwapp_* tokens stay loopback-only, so any non-loopback deployment must now supply explicit auth or it won't start. Separately, codew config get/list recursively masks token/secret/password/credential/authorization keys inside extras tables and redacts sensitive HTTP headers — scripts that scrape config output for those values will now see redacted output.

  • State migration to ~/.codewhale — #3240 moves sessions, slop_ledger, trophies, and catalog writes under ~/.codewhale/ and relocates any pre-existing ~/.deepseek/<sub> data on first write, while reads still backfill from legacy paths; expect a one-time relocation and verify your data landed before deleting the old tree. Windows state-path validation now rejects rooted/prefixed subdir strings, so custom subdir names like /etc will be refused rather than silently resolved.

  • Provider and runtime robustness, plus UI behavior shifts — DeepSeek reasoning routes now omit tool_choice to avoid provider rejections, child agents retry transient header/SSE timeouts and parents synthesize missed completions so orchestration can't hang, and js_execution honors proxy env vars again (mirrors lowercase variants, backfills HTTP_PROXY/HTTPS_PROXY from ALL_PROXY, #3273/#3331). On the UI side, #3328 re-pins the composed sidebar on wide terminals and auto-migrates v0.8.62 auto-collapse settings to pinned, Ctrl-X is now scoped to Tasks-sidebar shell cancellation while Ctrl-K stays kill/palette, and Ctrl/Cmd+Enter force-steering now also accepts the Ctrl+J terminal encoding.

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

The wrapper downloads both binaries from this Release and places them in the same directory.

  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \

The image ships the codewhale dispatcher and codewhale-tui runtime. The latest tag is also updated on release.

What's in v0.8.63

Added

  • Sub-agent fanout safeguards (#3318, #3319). High-fanout Workflow runs can now queue and drain more agents than the instantaneous concurrency cap by default, with [subagents] max_admitted available to tune that bounded admission population. Distinct agent calls are no longer capped by the per-turn loop guard before runtime launch concurrency and provider rate-limit backoff can apply. [subagents] token_budget applies a shared aggregate token ceiling to a root agent run and its descendants.
  • Per-worker sub-agent token enforcement (#3321). A token_budget / max_tokens set on an individual agent call now bounds that single worker mid-run: once its accumulated model tokens exceed the cap it stops cleanly with a budget_exhausted status instead of running to max_steps. This complements the scope-level admission gate (#3319) — the per-worker cap stops one runaway worker, the scope cap bounds total fan-out — without double-counting. Harvested from #3321 by @donglovejava.
  • Provider-specific sub-agent fanout config. [subagents.providers.<provider>] profiles now override enabled, max_concurrent, max_admitted, launch_concurrency, max_depth, token budget, API timeout, and heartbeat timeout for the active provider. Use broad direct-API profiles such as [subagents.providers.deepseek] and tighter subscription profiles such as [subagents.providers.glm]; /config subagents status shows both global and active-provider resolved values.
  • Sub-agent control and isolation. The single agent tool now exposes status, peek, and cancel actions for running children, and accepts worktree: true to create an isolated git worktree/branch for parallel edit lanes instead of requiring callers to hand-roll a cwd.

Fixed

  • Mode and tool catalog correctness. Core action tools remain discoverable in the model-facing catalog/tool search, and a consistency self-check flags registered handlers that drift out of the advertised catalog. Review-looking prompts in explicit Agent/YOLO mode now keep the requested mode and tools, with only an advisory review hint.
  • Sub-agent orchestration recovery. Child agents now retry transient provider header/SSE timeouts before failing, and parent runs synthesize missed child completions from terminal child state so orchestration cannot hang on a lost completion event.
  • DeepSeek thinking tool calls. DeepSeek chat-completions requests now omit explicit tool_choice whenever reasoning/thinking is enabled, avoiding provider rejections while leaving no-thinking routes unchanged.
  • Task sidebar shortcuts and attribution. Ctrl-K stays palette/emacs-kill, while Ctrl-X is scoped to Tasks-sidebar background shell cancellation. Shell jobs launched by sub-agents now render with their child-agent owner in the Tasks sidebar and transcript.
  • Benchmark-turn recovery and context economy. Repeated read-only search loop blocks now return guidance instead of fatal tool failures, Python build failures that are missing setuptools include an install/retry hint, long foreground shell timeouts steer models toward background execution, and noisy shell/test/web outputs are compacted earlier for large-context routes.
  • Config display redaction. codew config get/list now recursively masks token-, secret-, password-, credential-, and authorization-like keys inside unknown extras tables and redacts sensitive HTTP header values before printing config output.
  • Queued follow-up hints and force-steer keys. The pending-input preview now advertises Ctrl+S send now whenever queued follow-ups exist, and Ctrl/Cmd+Enter force-steering also accepts the common Ctrl+J terminal encoding while a turn is running.
  • Sidebar default visibility restored (#3328). New and upgraded sessions now use a pinned composed sidebar by default when the terminal is wide enough, so live Agents and Tasks surface without opting back into idle auto-collapse. Older settings files that captured the v0.8.62 auto-collapse default now migrate to pinned unless /sidebar auto --save records an explicit opt-in. /sidebar now reports when width or auto-collapse suppresses rendering instead of saying the sidebar is visible. Reported by @dxfq.
  • JavaScript execution proxy env handling (#3273, #3331). js_execution now enables Node's environment-proxy mode when proxy variables are present, mirrors lowercase proxy variables for the child process, and backfills HTTP_PROXY / HTTPS_PROXY from ALL_PROXY. Reported by @lordwedggie and harvested from #3331 by @cyq1017.
  • Legacy app-server non-loopback auth hardening (#3258). Bare codewhale app-server --host 0.0.0.0 now fails fast unless an explicit --auth-token or CODEWHALE_APP_SERVER_TOKEN is supplied, keeping generated one-time cwapp_* tokens loopback-only.
  • Legacy .deepseek state write-path migration (#3240). State subdirectories (sessions, slop_ledger, trophies, catalog) are now always written under ~/.codewhale/, and the first write of a subdir relocates any pre-existing ~/.deepseek/<sub> contents into the primary location so the legacy tree stops growing while old data is preserved. The read resolver still finds legacy data for backfill until each subdir migrates. Reported by @Final527; onboarding marker slice from #3302 by @nightt5879.
  • State subdir validation on Windows (#3240). State path hardening now rejects rooted/prefixed subdir strings such as /etc before resolving or migrating state directories, keeping the .codewhale write resolver inside its state root across platforms.
