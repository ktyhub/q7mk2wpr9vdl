github-mcp-server v1.10.0

Highlights

v1.10.0 ist eine umfassende Sicherheits-, Zuverlässigkeits- und Kompatibilitätsversion für den GitHub MCP-Server.

Standardmäßig sicherer

– Bestätigtes Repository-Löschen mit Formularerhebung und geschütztem Multi-Round-Trip-Status hinzugefügt (#3076). – Beschränkte Inhaberanmeldeinformationen auf konfigurierte GitHub-Berechtigungen (#3056). – Erzwungenes HTTPS für GitHub Enterprise-Hosts (#3069). – Ungültige statische --tools-Konfiguration konnte nicht geschlossen werden (#3050). – Verstärkte Sperrung, Anforderungslimits, Cache-Isolation, URL-Traversal und Antwortbereinigung (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Bessere Kompatibilität mit GitHub Enterprise Server

– list_issues und search_issues werden jetzt sicher beeinträchtigt, wenn benutzerdefinierte GraphQL-Feldtypen nicht verfügbar sind (#3086, #2897). – list_issues gibt jetzt zugewiesene Anmeldungen und stabile leere Arrays für nicht zugewiesene Probleme zurück (#3064). – Validierungsfehler legen sichere Regelsatzdetails offen, wenn sie von GitHub API bereitgestellt werden (#3081).

Sicherere Repository-Dateivorgänge

  • get_file_contents identifiziert jetzt symbolische Links und kennzeichnet dereferenzierte Inhalte eindeutig. – Für symbolische Link-Schreibvorgänge ist ein explizites allow_symlink_write: true-Opt-in erforderlich (#3071). – Problem behoben, bei dem binäre MCP-Ressourcen zweimal Base64-kodiert waren (#3098).

Zuverlässigere Werkzeugverträge

  • Korrigierte add_issue_comment-Eingabemodi (#3085). – issue_write.issue_fields[].delete: false ist jetzt ein gültiger No-Op für clients mit strengem Schema (#3077). – Null-Parameter-Tools akzeptieren eine ausgelassene arguments-Eigenschaft, während sie explizite null und fehlerhafte JSON ablehnen (#3099). – Tools für Benachrichtigungsabonnements kündigen destruktives Verhalten explizit an (#2936).
  • Bei Ablehnungen von Copilot-Überprüfungsanfragen werden jetzt umsetzbare Hinweise statt nur 404 zurückgegeben (#3119).

Projekte, Aktionen und Effizienz

– Lebenszyklusoperationen der Projektansicht und Konfiguration des sichtbaren Felds hinzugefügt (#2961, #2988). – Reduzierte Aktionen und andere erfolgreiche Antwortnutzlasten (#3047, #3055). – Verbesserte Bereinigungsleistung und aktualisierte UI-/Build-Abhängigkeiten (#3120, #3100).

Zu beachtende Verhaltensänderungen

  • Unbekannte statische --tools-Namen verhindern jetzt den Start.
  • Aktualisierungen symbolischer Links erfordern eine ausdrückliche Zustimmung. – Anfragen können die vom Server erzwungene Sperrung nicht lockern. – Übergroße HTTP-Anfragetexte werden frühzeitig abgelehnt. – add_issue_comment führt eine strengere, sich gegenseitig ausschließende Modusvalidierung durch. – Zum Löschen des Repositorys sind ein berechtigter moderner MCP client, ​​Unterstützung für die Formularerhebung und die entsprechenden Bereiche erforderlich.

github-mcp-server v1.10.0

Highlights

v1.10.0 is a substantial security, reliability, and compatibility release for the GitHub MCP Server.

Safer by default

  • Added confirmed repository deletion with form elicitation and protected multi-round-trip state (#3076).
  • Restricted bearer credentials to configured GitHub authorities (#3056).
  • Enforced HTTPS for GitHub Enterprise hosts (#3069).
  • Made invalid static --tools configuration fail closed (#3050).
  • Hardened lockdown, request limits, cache isolation, URL traversal, and response sanitization (#3109, #3112, #3113, #3111, #3108, #3114, #3110).

Better GitHub Enterprise Server compatibility

  • list_issues and search_issues now degrade safely when issue custom-field GraphQL types are unavailable (#3086, #2897).
  • list_issues now returns assignee logins and stable empty arrays for unassigned issues (#3064).
  • Validation failures expose safe ruleset details when supplied by the GitHub API (#3081).

Safer repository file operations

  • get_file_contents now identifies symbolic links and clearly labels dereferenced content.
  • Symbolic-link writes require explicit allow_symlink_write: true opt-in (#3071).
  • Fixed binary MCP resources being base64-encoded twice (#3098).

More reliable tool contracts

  • Corrected add_issue_comment input modes (#3085).
  • issue_write.issue_fields[].delete: false is now a valid no-op for strict-schema clients (#3077).
  • Zero-parameter tools accept an omitted arguments property while rejecting explicit null and malformed JSON (#3099).
  • Notification subscription tools explicitly advertise destructive behavior (#2936).
  • Copilot review-request denials now return actionable guidance instead of a bare 404 (#3119).

Projects, Actions, and efficiency

  • Added Project view lifecycle operations and visible-field configuration (#2961, #2988).
  • Reduced Actions and other successful response payloads (#3047, #3055).
  • Improved sanitization performance and refreshed UI/build dependencies (#3120, #3100).

Behavior changes to note

  • Unknown static --tools names now prevent startup.
  • Symbolic-link updates require explicit opt-in.
  • Requests cannot relax server-enforced lockdown.
  • Oversized HTTP request bodies are rejected early.
  • add_issue_comment performs stricter mutually exclusive mode validation.
  • Repository deletion requires an eligible modern MCP client, form elicitation support, and the appropriate scopes.
