DocsGPT 0.19.0

Highlights

  • Sandboxed code execution & artifacts — PR #2568 introduces artifacts alongside a sandboxed execution layer for tools, workflows, and document I/O, effectively turning DocsGPT from a Q&A engine into an agent runtime. Self-hosters should plan for the new Daytona sandbox dependency: #2603 adds graceful handling of invalidated sandboxes and #2652 hardens tool-call durability on long calls, so state survives more failure modes but there is new infrastructure to provision and watch.

  • Accurate token metering and context guards — #2595 fixes per-call token accounting and adds oversized-context guards. This is a behavioral change to watch: requests that previously sailed past context limits will now be guarded/rejected, so clients relying on silent truncation should add their own chunking. #2645 also tightens source authorization, surfaces silent retrieval failures, and restructures prompts — retrieval that quietly failed before will now show up as explicit errors.

  • Capability negotiation and API hardening — #2620 advertises agent capabilities in the prompt and via the endpoint, complementing the endpoint work in #2593. Integrators should re-check capability negotiation: #2608 fixes an API tool encoding bug, #2609 fixes OpenAI-compatible file uploads, and #2622 adds agent key rotation plus guardrails initialization (#2664), all of which affect how clients authenticate and discover what an agent can do.

  • Workflow and chat UX — Workflows gain undo/redo (#2582), and chat gets inline streaming of reasoning and tool-call steps (#2636), a shadcn message scroller that fixes jitter (#2591), and unified live-step state with bubble avatar chrome removed (#2665). #2599 fixes multi-tool-call handling and #2605 makes pause more durable. If you build custom UI on these components, expect visual and state-shape changes.

  • Attachments pipeline tightened — Explicit Docling file-size caps (#2634), attachment provenance (#2670), stricter pre-send guards (#2672), graceful degradation on workflow attachment errors (#2635), Docling parse-error/schedule-status fixes (#2637), and an image refactor (#2669). Uploads now fail earlier and with clearer errors; callers should handle the new size limits and provenance metadata rather than assuming silent acceptance.

  • Toolchain migration — Frontend now targets Node 22 and fixes the Vite native config loader warning (#2668), while Docker-on-Windows HMR gets Chokidar polling (#2574). Major dev-dependency jumps — Vitest 3→4 (#2540) and react-dropzone 15→20 (#2617) — mean test config and file-input APIs may need adjustment, and a new DB migration adds a user_logs agent lookup index (#2638).

No breaking API changes.
