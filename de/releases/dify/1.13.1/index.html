dify 1.13.1

Patch Veröffentlicht17. März 2026 Quellelanggenius/dify Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

verifizieren 1.13.1

🚀 Wichtige funktionale Änderungen

Datenplattform- und Datensatzoperationen

  • Hologres als unterstützte Backend-Option sowohl für die Vektorabfrage als auch für die Volltextsuche hinzugefügt. – Service API-Endpunkte für das Herunterladen von Datensatzdokumenten hinzugefügt:
    • Batch-ZIP-Download für ausgewählte Dokumente.
    • Signierter URL-Download für Einzeldokument-Originaldateien.

Verbesserungen des Workflows und des Chat-Erlebnisses

  • Breaking Change: HITL-E-Mail-Inhalte verwenden jetzt Markdown-Rendering vor der Zustellung. Vorhandene E-Mail-Vorlagen, die auf dem Raw/Plain-Verhalten basieren, werden nach dem Upgrade möglicherweise anders dargestellt.
  • Entwurfsvariablen sind jetzt benutzerbezogen statt anwendungsbezogen. Historische Entwurfsvariablen sind nach dem Upgrade nicht verfügbar. – Unterstützung für Kantenkontextmenüs im Workflow-Canvas hinzugefügt, einschließlich direkter Kantenlöschung.
  • Bestehende Verbindungen beim Ändern von Knotentypen in der Workflow-Bearbeitung beibehalten.
  • Konfigurierbares Sendeschlüsselverhalten (Enter vs. Shift+Enter) für eingebettete Chat-Eingaben hinzugefügt. – Dateinutzlasten in Stream-Antworten am Ende der Nachricht hinzugefügt. – GPT-4-spezifisches hartcodiertes Verhalten aus der Standardmodellauswahllogik entfernt. – Ein neuer Befehl export-app-messages CLI hinzugefügt, um Anwendungsnachrichten und zugehöriges Feedback nach JSONL.GZ (lokaler oder Cloud-Speicher) zu exportieren.

🔐 Sicherheitsupdates

– Verhinderung von SQL-Injection-Risiken in Vektorspeicher-Abfragepfaden durch Umstellung auf parametrisiertes SQL in betroffenen Implementierungen.

  • Gehärtete HITL-E-Mail-Zustellung:
    • Bereinigen Sie Betreff- und Textinhalte.
    • Entfernen Sie CR/LF von Subjekten, um SMTP-Header-Injection-Vektoren zu verhindern.
  • Erzwungene Besitzüberprüfungen für APIs zum Löschen von Konversationen. – Veraltete Anbieteranmeldeinformationen wurden während der Plugin-Deinstallation gelöscht, um das verbleibende Anmeldeinformationsrisiko zu verringern. – Verbesserte Fehlerbehandlung für Unternehmen API und Verhalten bei der Durchsetzung von Lizenzen bei ungültigen/abgelaufenen Lizenzstatus.

🏗️ Konfigurations-, Architektur- und Bereitstellungsaktualisierungen

Bereitstellung und Betrieb

– Eine dedizierte Celery-Warteschlange hinzugefügt: dataset_summary für LLM-intensive Aufgaben zur Zusammenfassungsgenerierung. – Stellen Sie sicher, dass die Mitarbeiter diese Warteschlange abonnieren, um einen Rückstand bei Sammelaufträgen zu vermeiden. – Telemetriemetriken für Aufbewahrungsbereinigungsaufgaben (Nachrichten/Workflow-Ausführungen) sowie Flush-Verhalten für kurzlebige Befehlsjobs hinzugefügt.

Konfigurationsänderungen

  • REDIS_MAX_CONNECTIONS hinzugefügt. – Veraltete PUBSUB_*-Ereignisbuseinstellungen zugunsten der EVENT_BUS_*-Einstellungen.

🛠 Weitere bemerkenswerte Änderungen

– Problem behoben, bei dem workflow_runs.started_at beim Fortsetzen überschrieben wurde. – Fehler bei der stillen Metadaten-Stapelbearbeitung behoben, die durch Edge-Fälle mit geteilter Transaktion verursacht wurden. – Probleme bei der Extraktion von Metadatenfiltern beim Wissensabruf behoben ({{...}}-Bedingungen).

  • Die Sichtbarkeit von Zitaten in erweiterten Chat-Anwendungen wurde wiederhergestellt. – Das Verhalten beim Zurücksetzen der Konversationsvariablen nach HITL-Knoten wurde behoben. – Ein Seitenabsturz im Konfigurationsablauf des Knowledge-Retrieval-Knotens wurde behoben.
  • Problem behoben, bei dem der Chat-Assistent das Verhalten im Antwortmodus blockierte.
  • doc_type-Behandlung in Weaviate-Vektorattributen für bessere Kompatibilität hinzugefügt. – Aktualisierte OpenTelemetry-Abhängigkeiten, um Kontexttrennungsfehler zu beheben.

Upgrade-Anleitung

[!IMPORTANT] Wenn Sie benutzerdefiniertes CELERY_QUEUES verwenden, stellen Sie sicher, dass workflow_based_app_execution enthalten ist.
Wenn ENABLE_API_TOKEN_LAST_USED_UPDATE_TASK=true, schließen Sie auch api_token ein.

Hintergrundinformationen und Details finden Sie oben im ⚠️Wichtigen Upgrade-Hinweis und 🔧Betriebshinweis.

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre angepasste docker-compose YAML-Datei (optional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Holen Sie sich den neuesten Code aus der Hauptniederlassung

    git checkout main
git pull origin main

  3. Stoppen Sie den Dienst. Bitte im Verzeichnis docker ausführen

    docker compose down

  4. Daten sichern

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Upgrade-Dienste

    docker compose up -d

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und den Web-Frontend-Server.

  2. Holen Sie sich den neuesten Code aus dem Release-Zweig:

    git checkout 1.13.1

  3. Aktualisieren Sie die Python-Abhängigkeiten:

    cd api
uv sync

  4. Dann führen wir das Migrationsskript aus:

    uv run flask db upgrade

  5. Führen Sie abschließend den API-Server, den Worker und den Web-Frontend-Server erneut aus.

dify 1.13.1

🚀 Major Functional Changes

Data platform and dataset operations

  • Added Hologres as a supported backend option for both vector retrieval and full-text search.
  • Added Service API endpoints for dataset document downloads:
    • Batch ZIP download for selected documents.
    • Signed URL download for single-document original files.

Workflow and chat experience improvements

  • Breaking change: HITL email content now uses markdown rendering before delivery. Existing email templates that relied on raw/plain behavior may render differently after upgrade.
  • Draft variables are now user-scoped instead of app-scoped. Historical draft variables will not be available after upgrading.
  • Added edge context menu support in workflow canvas, including direct edge deletion.
  • Preserved existing connections when changing node types in workflow editing.
  • Added configurable send-key behavior (Enter vs Shift+Enter) for embedded chat input.
  • Added file payloads in message-end stream responses.
  • Removed GPT-4-specific hardcoded behavior from default model selection logic.
  • Added a new export-app-messages CLI command to export application messages and related feedback to JSONL.GZ (local or cloud storage).

🔐 Security Updates

  • Prevented SQL injection risks in vector-store query paths by switching to parameterized SQL in affected implementations.
  • Hardened HITL email delivery:
    • Sanitize subject and body content.
    • Strip CR/LF from subjects to prevent SMTP header-injection vectors.
  • Enforced ownership checks for conversation deletion APIs.
  • Cleared stale provider credentials during plugin uninstall to reduce residual credential risk.
  • Improved enterprise API error handling and license-enforcement behavior for invalid/expired license states.

🏗️ Configuration, Architecture, and Deployment Updates

Deployment and operations

  • Added a dedicated Celery queue: dataset_summary for LLM-heavy summary generation tasks.
    • Ensure workers subscribe to this queue to avoid summary-job backlog.
  • Added telemetry metrics for retention cleanup tasks (messages/workflow runs), plus flush behavior for short-lived command jobs.

Configuration changes

  • Added REDIS_MAX_CONNECTIONS.
  • Deprecated PUBSUB_* event-bus settings in favor of EVENT_BUS_* settings.

🛠 Other Noteworthy Changes

  • Fixed workflow_runs.started_at being overwritten on resume.
  • Fixed metadata batch-edit silent failures caused by split-transaction edge cases.
  • Fixed metadata filter extraction issues in knowledge retrieval ({{...}} conditions).
  • Restored citation visibility in advanced chat applications.
  • Fixed conversation variable reset behavior after HITL nodes.
  • Fixed a page crash in knowledge-retrieval node configuration flow.
  • Fixed chat assistant blocking response-mode behavior.
  • Added doc_type handling in Weaviate vector attributes for better compatibility.
  • Upgraded OpenTelemetry dependencies to resolve context-detach errors.
