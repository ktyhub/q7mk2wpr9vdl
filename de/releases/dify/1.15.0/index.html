Neue Funktionen

difyctl – Dify über die Befehlszeile steuern (Dokumente)

  • difyctl ist ein Befehlszeilen-client für Dify: Sie können jetzt Apps und Workflows direkt von Ihrem Terminal aus ausführen, sodass persönliche Agenten, Skripte und CI-Pipelines Dify-Workflows aufrufen können, ohne die Web-Benutzeroberfläche zu öffnen (#37036)
  • Installieren Sie es auf jeder Plattform (macOS, Linux, Windows) mit einem einzigen Befehl und ohne Zugriffstoken – Binärdateien werden als öffentliche Versionen mit Prüfsummenüberprüfung veröffentlicht (#37036, #37454)
  • Übergeben Sie bereichsbezogene Umgebungsvariablen an CLI-Toolausführungen und erhalten Sie klarere, konsistente Fehlermeldungen (einschließlich benutzerfreundlicher Handhabung von Ratenbegrenzungen) sowohl für difyctl als auch für /openapi/v1 API (#37324, #37285, #37313, #36896).

Siehe CoT in Workflow & Chatflow & CLI

  • Chat Flow/Workflow kann jetzt die Argumentation des Modells in ein spezielles Live-„Denk“-Panel streamen und dabei die endgültige Antwort sauber und lesbar halten. Die Begründung bleibt erhalten, sodass sie nach einer Seitenaktualisierung immer noch vorhanden ist. Die gleiche Begründung ist in der Vorschau von CLI und Workflow-Ausführungen sichtbar (#37460, #37828).

Reichhaltigere Human-in-the-Loop-Formulare – Wenn ein Workflow pausiert, um eine Person um Eingaben zu bitten, kann das Formular jetzt Dropdown-Auswahlmöglichkeiten und Datei-/Mehrdatei-Uploads enthalten – nicht nur Freitext –, sodass Benutzer mit strukturierten Auswahlmöglichkeiten und Anhängen antworten können (#36322)

Unterstützung für langsame, lang laufende Modelle

  • Workflows können jetzt über einen Abfragemechanismus Generierungsmodelle verwenden, deren Reaktion lange dauert (z. B. Bild- oder Videogenerierung): Der Knoten wartet geduldig auf das Endergebnis, anstatt eine Zeitüberschreitung zu verursachen (#37462)

Wissen aus umfangreicheren Tabellenkalkulationen – In Excel-Dateien eingebettete Bilder werden jetzt beim Wissensimport extrahiert, sodass Tabelleninhalte, die auf Bildern basieren (Diagramme, Screenshots, Diagramme), nicht mehr verloren gehen (#37104)

Tiefere Beobachtbarkeit – Legen Sie Ihre eigene Trace-Sitzungs-ID für Phoenix fest, damit Traces mit den Sitzungen Ihrer Anwendung übereinstimmen, und befolgen Sie die Schritte zum Abrufen von Dokumenten in Traces, um zu verstehen, wie RAG-Ergebnisse erzeugt wurden (#37056, #37283)

Verfeinerung des Workflow-Authorings – Ein aktualisierter Startknoten macht deutlicher, wie ein Workflow beginnt, und ein intelligenterer Ausgabeknoten gibt Ihnen mehr Kontrolle darüber, was ein Workflow zurückgibt (#37348, #35511) – Freundlichere Fehler, wenn eine App- oder Workspace-ID fehlerhaft ist, statt verwirrende Fehler (#37212)

Schnellere Plugin-Installationen in bestimmten Regionen – Der Plugin-Daemon erkennt jetzt automatisch Ihre Region beim Start und wählt bei schlechter Netzwerkverbindung zu PyPI automatisch einen Paketspiegel in der Nähe aus – so ist die Installation von Plugins schneller und zuverlässiger, ohne dass eine manuelle Einrichtung erforderlich ist. Sie können bei Bedarf immer noch einen bestimmten Spiegel anpinnen (dify-plugin-daemon#750)

Upgrade-Anleitung

Modelltypmigration

[!IMPORTANT]

Einmalige Migration des Legacy-Modelltyps für selbst gehostete Upgrades

Wenn diese Bereitstellung von einer Dify-Version vor 1.15.0 aktualisiert wurde und diese Migration noch nicht angewendet wurde, führen Sie sie nach dem Upgrade aus.

Diese Migration ist nicht in flask db upgrade enthalten. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Sichern Sie die Datenbank, bevor Sie die Migration anwenden. Der Befehl wird standardmäßig im Probelaufmodus ausgeführt. Überprüfen Sie die Ausgabe, bevor Sie sie mit --apply erneut ausführen. Die Migration ist idempotent und kann sicher wiederholt werden.

Docker Verfassen

Aus dem docker-Verzeichnis ausführen.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Quellcode-Bereitstellung

Nach Abschluss von flask db upgrade vom Repository-Stamm ausführen.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Führen Sie nach der Migration den Befehl „Probelauf“ erneut aus. Wenn keine weiteren Zeilenaktualisierungen oder -löschungen gemeldet werden, starten Sie die entsprechenden Dienste neu und überprüfen Sie, ob vorhandene Modelle erfolgreich geladen und aufgerufen werden können.

[!IMPORTANT]

– Diese Version enthält neue Datenbankmigrationen. Führen Sie sie als Teil des Upgrades aus.

  • Plugin auto-upgrade is now configured per plugin category. After running flask db upgrade, you MUST also run flask backfill-plugin-auto-upgrade to migrate existing tenants' auto-upgrade settings into the new category-scoped model. Wenn Sie diesen Schritt überspringen, werden die von Benutzern zuvor konfigurierten Plugin-Einstellungen für die automatische Aktualisierung möglicherweise nicht mehr wirksam.
  • Umgebungsvariablen geändert (19 hinzugefügt, 2 entfernt, 1 geändert). Sehen Sie sich den Abschnitt „Änderungen der Umgebungsvariablen“ an und aktualisieren Sie Ihren .env entsprechend.
  • Docker Compose-Konfigurationsdateien geändert. Wenn Sie einen angepassten docker-compose.yaml verwalten, überprüfen Sie die Änderungen und wenden Sie die lokalen Anpassungen sorgfältig erneut an.

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre benutzerdefinierten docker-compose YAML- und env-Dateien. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Holen Sie sich den neuesten Code für die 1.15.0-Version. 
    git fetch --tagsgit checkout 1.15.0
  3. Stoppen Sie die Dienste (führen Sie sie im Verzeichnis docker aus). 
    docker compose down
  4. Daten sichern. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Überprüfen Sie alle Änderungen an der Umgebungsdatei und wenden Sie die lokalen Anpassungen erneut an.
  6. Upgrade-Dienste. 
    docker compose up -d
  7. Backfill-Strategien für kategoriebezogene Plugin-Auto-Upgrades (erforderlich). 
    docker compose exec api flask backfill-plugin-auto-upgrade

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und den Web-Frontend-Server.
  2. Holen Sie sich den neuesten Code für die 1.15.0-Version. 
    git fetch --tagsgit checkout 1.15.0
  3. Aktualisieren Sie die Python-Abhängigkeiten. 
    cd apiuv sync
  4. Führen Sie Datenbankmigrationen durch. 
    uv run flask db upgrade
  5. Backfill-Kategorie-bezogene Plugin-Auto-Upgrade-Strategien (erforderlich). 
    uv run flask backfill-plugin-auto-upgrade
  6. Starten Sie den API-Server, den Worker und den Web-Frontend-Server neu.

New Features

difyctl — drive Dify from the command line (Docs)

  • difyctl is a command-line client for Dify: you can now run apps and workflows straight from your terminal, so personal agents, scripts, and CI pipelines can invoke Dify workflows without opening the web UI (#37036)
  • Install it on any platform (macOS, Linux, Windows) with a single command and no access token — binaries are published as public releases with checksum verification (#37036, #37454)
  • Pass scoped environment variables to CLI tool runs, and get clearer, consistent error messages (including friendly rate-limit handling) across both difyctl and the /openapi/v1 API (#37324, #37285, #37313, #36896)

See CoT in Workflow & Chatflow & CLI

  • Chat Flow / Workflow can now stream the model's reasoning into a dedicated live "thinking" panel while keeping the final answer clean and readable. The reasoning is preserved so it's still there after a page refresh, and the same reasoning is visible in CLI and workflow run previews (#37460, #37828)

Richer Human-in-the-Loop forms

  • When a workflow pauses to ask a person for input, the form can now include dropdown selects and file / multi-file uploads — not just free text — so people can answer with structured choices and attachments (#36322)

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

[!IMPORTANT]

  • This release includes new database migrations. Run them as part of the upgrade.
  • Plugin auto-upgrade is now configured per plugin category. After running flask db upgrade, you MUST also run flask backfill-plugin-auto-upgrade to migrate existing tenants' auto-upgrade settings into the new category-scoped model. If you skip this step, plugin auto-upgrade settings users previously configured may stop taking effect.
  • Environment variables changed (19 added, 2 removed, 1 modified). Review the Environment Variable Changes section and update your .env accordingly.
  • Docker Compose configuration files changed. If you maintain a customized docker-compose.yaml, review the changes and re-apply local customizations carefully.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML and env files. 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Get the latest code for the 1.15.0 release. 
    git fetch --tagsgit checkout 1.15.0
  3. Stop the services (run inside the docker directory). 
    docker compose down
  4. Back up data. 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Review any env file changes and re-apply local customizations.
  6. Upgrade services. 
    docker compose up -d
  7. Backfill category-scoped plugin auto-upgrade strategies (required). 
    docker compose exec api flask backfill-plugin-auto-upgrade

  1. Stop the API server, Worker, and Web frontend server.
  2. Get the latest code for the 1.15.0 release. 
    git fetch --tagsgit checkout 1.15.0
  3. Update Python dependencies. 
    cd apiuv sync
  4. Run database migrations. 
    uv run flask db upgrade
  5. Backfill category-scoped plugin auto-upgrade strategies (required). 
    uv run flask backfill-plugin-auto-upgrade
  6. Restart the API server, Worker, and Web frontend server.
