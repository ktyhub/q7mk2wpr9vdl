verifizieren 1.17.0

Neue Funktionen

Agent: E2B-Sandbox, Home-Snapshots und Skill-Management

  • E2B-Sandbox-Backend: Die Shell-/Codeausführung des Agenten kann jetzt zusätzlich zur lokalen Sandbox auf E2B Cloud-Sandboxen ausgeführt werden. Wählen Sie das Backend mit DIFY_AGENT_RUNTIME_BACKEND aus; Ein neues docker-compose.e2b.yaml versendet den E2B-Stack, der E2B-Verkehr wird authentifiziert und die E2B-Vorlage wird bei der Veröffentlichung synchronisiert (#39480, #39705, #39873, #39996, #40858, #40871, #40891, #40892).
  • Home-Snapshots zur Erstellungszeit: Wenn ein Agent-Build angewendet (veröffentlicht) wird, wird das Sandbox-Home-Verzeichnis des Agenten – installierte Pakete, vorbereitete Dateien, Arbeitsstatus – erfasst und nachfolgende Ausführungen des veröffentlichten Agenten stellen sein Home-Verzeichnis aus diesem Snapshot wieder her, sodass der Agent genau mit dem Dateisystemstatus startet, den er zum Build-Zeitpunkt hatte. (#39702, #40876, #40996).
  • Skill-Management auf Arbeitsbereichsebene: Skills sind wiederverwendbare, versionierte Funktionen, verpackt mit Code- und Tooldefinitionen, die Agenten erkennen und aufrufen können. Ein neuer Skills-Manager auf Arbeitsbereichsebene mit Lebenszyklus „Entwurf → Veröffentlichen → Version“ wird zusammen mit einer Web-Benutzeroberfläche (Skill-Liste, Builder-Panel, Dateieditor) ausgeliefert. (#39675, #39798, #39799, #41180).
  • Kontextsensitive Verlaufskomprimierung: Lange Agentengespräche gehen nicht mehr über das Kontextfenster des Modells hinaus – Dify löst die effektive Fenster- und Ebenenkomprimierung jedes Modells auf (löscht zuerst die Ergebnisse des alten Tools und fasst dann den älteren Verlauf zusammen), sodass die Ausführungen innerhalb des Budgets bleiben, ohne den aktuellen Kontext zu verlieren (#40872).

Wiederverwendbare LLM-Umgebungsvariablen in Workflows

  • Definieren Sie einmal eine gemeinsam genutzte Anbieter-/Modell-/Modus-/Parameterkonfiguration (z. B. for_summarize, for_research) und referenzieren Sie sie von jedem LLM-Knoten aus. Koordinierte Modelländerungen erfolgen jetzt an einem Ort, anstatt von Knoten zu Knoten zu wandern, und die Referenzen überdauern den DSL-Import/Export, Snippets, RAG-Pipelines und die gemeinsame Bearbeitung (#39125).

Menschlicher Input in Schleifen und Iterationen – Human-in-the-Loop-Formulare funktionieren jetzt innerhalb von Schleifen- und Iterationsknoten und werden bei Seitenaktualisierungen sowohl für Debug- als auch für installierte Apps korrekt angehalten und fortgesetzt – was Überprüfungs-/Genehmigungsschritte bei wiederholten Arbeiten ermöglicht (#39243).

Anbieterneutrale einheitliche Nachverfolgung – Opt-in-einheitliches Tracing (OPS_TRACE_UNIFIED_ENABLED) stellt den gesamten übergeordneten und untergeordneten Span-Tree (Workflows, Chatflows, Nachrichten, Knoten, Schleifen, Iterationen, verschachtelte Workflows) einmal im Kern zusammen und delegiert nur den Transport an leichtgewichtige Adapter. Phoenix- und LangSmith-Adapter werden zuerst ausgeliefert; Standardmäßig deaktiviert und vollständig abwärtskompatibel (#39451). – Das neue GenAI umfasst Oberflächen-LLM-TTFT, Agent-ReAct-Schritte, Tool-Aufrufe und ausgefallene LLM-Knoten für eine tiefere Beobachtbarkeit (#39339).

Cloudflare Turnstile (CAPTCHA)-Unterstützung – Optionale Turnstile-Herausforderung bei der Anmeldung und E-Mail-Code-Anmeldung, um Authentifizierungsendpunkte vor Missbrauch zu schützen, mit konfigurierbaren Site-/Geheimschlüsseln und zulässigen Hostnamen (#40494).

Azure Key Vault/Pluggable KMS – Führt eine KMS-Anbieterabstraktion mit Azure Key Vault-Unterstützung für Schlüsselbereitstellung, Verschlüsselung und Entschlüsselung sowie Schlüsselrotationskonfiguration ein – ein Schritt hin zu extern verwalteten Verschlüsselungsschlüsseln (#39933).

TiDB Vector Volltext- und Hybridsuche – TiDB Vector-Bereitstellungen können jetzt den Volltext- und Hybridabruf (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH, standardmäßig deaktiviert) ermöglichen, indem neben der Vektorsuche ein mehrsprachiger Volltextindex verwendet wird (#38112).

Breiteres Modell und Dateihandhabung – LLM-Knoten und Agenten können Bilddateien jetzt direkt an multimodale Modelle übergeben, und Nicht-Vision-Anhänge werden nicht mehr stillschweigend aus Agenten-Chats gelöscht (#39848, #40179). – Neue multimodale Abrufanleitung hilft Benutzern, Einbettungsmodelle für bildtragende Wissensdatenbanken richtig auszuwählen (#40566). – Audio ASR akzeptiert jetzt audio/x-m4a und Audio-MIME-Typen werden genauer validiert (#40776, #41043).

Gehe zu „Alles“ (⌘K / Strg+K)

  • Drücken Sie ⌘K (Strg+K unter Windows/Linux) an einer beliebigen Stelle in der Konsole, um die Befehlspalette zu öffnen und zu Apps, Agenten, Fertigkeiten, Wissensdatenbanken, Plugins oder Workflow-Knoten zu springen oder schnelle Aktionen über Schrägstrichbefehle auszulösen. Neu in dieser Version: Agenten und Fertigkeiten sind durchsuchbar und das Symbol-Befehlssystem wurde aus Gründen der Konsistenz in allen Domänen umgestaltet (#40620, #40621, #40646–#40649, #41160).

Andere Ergänzungen

  • ODT-Dokumentextraktionsunterstützung (OpenDocument Text) (#39973).
  • Neuer Parametertyp date / date-picker für Tool-Plugins (#36163).
  • Unterstützung der laotischen (lo-LA) Sprache (#39474). – Automatische Bereinigungsaufgabe für alte Konversationen (ENABLE_CONVERSATION_CLEANUP_TASK), um das Datenwachstum zu begrenzen (#40889-era). – Marktplatz direkt in Integrationskategorien eingebettet für eine reibungslosere Tool-/Plugin-Erkennung (#40744).

Verbesserungen

Barrierefreiheit (großer 11-Jahres-Pass) – Eine sehr große Reihe von Änderungen macht die Konsole tastatur- und bildschirmleserfreundlich: echte <button>-Semantik für Dutzende interaktiver Steuerelemente, zugängliche Namen für Nur-Symbol-Aktionen (Kopieren, Schließen, Löschen, Menüs), primäre Überschriften auf Authentifizierungs-/Installationsseiten, über die Tastatur zugängliche Element-/Tool-Auswahl und korrekte ARIA-Status (#40192–#40377 und viele andere).

Workflow-Erstellung – Der Workflow-Generator bevorzugt jetzt beim Vorschlagen von Knoten bereits installierte und konfigurierte Tools, sodass Builder nach den Tools greifen, die sie tatsächlich haben (#40611, #39850).

Workflow- und Laufzeitstabilität – Reproduzierbare Web-Workflow-Ausführungen, beibehaltener Canvas-Status nach Verlaufsaktualisierungen, keine Aktualisierungs-Renderschleifen mehr und SSE-Streams enden jetzt sauber bei Terminalereignissen (#40010, #40489, #41105, #40042). – stop wird jetzt zwischen Nicht-Streaming-Knoten und angehaltenen Workflows berücksichtigt, um veraltete Abbruchsignale korrekt zu löschen (#41090, #40905, #40972). – Die Standardwerte für APP_MAX_EXECUTION_TIME und WORKFLOW_MAX_EXECUTION_TIME wurden von 1200s → 3600s angehoben, um länger laufende Workflows zu berücksichtigen.

Interne Qualität – Umfangreiche Migration von Unit-Tests zu echten ORM-Modellen/SQLite-Sitzungen für eine zuverlässigere Abdeckung sowie eine stärkere Typisierung über migrierte Tests hinweg (viele #38xxx–#39xxx). Keine Verhaltensänderung beim Benutzer.

Sicherheitsverbesserungen

  • Verstärkung der Authentifizierung: Drehkreuz-Herausforderung bei Anmelde-/E-Mail-Code-Abläufen, verschärfte E-Mail-Code-Überprüfung mit Versuchslimits und Token-Ablauf (EMAIL_CODE_LOGIN_MAX_ATTEMPTS, EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES), Handhabung gesperrter E-Mail-Domänen und kurzlebige Agentenautorisierungstoken (#40494, #40960, #41004, #40884).
  • Zugriffskontrolle/Besitzbereich: Datensatz-, Dokument-, RAG-, Konversations-, Workspace-Anmeldeinformationen- und OAuth-client-Ressourcen sind jetzt konsistent an ihre Besitzer und den App-Bereich gebunden, wodurch mehrere Pfade für nicht autorisierten Zugriff geschlossen werden (#40989, #40888, #40790, #40745, #40893, #40786 und verwandte).
  • SSRF und ausgehende Härtung: Die ausgehenden HTTP-Verbindungsphasen sind begrenzt (5 Sekunden), Zeitüberschreitungen beim Herunterladen und Ausführen von Agenten/Bindungen sind konfigurierbar und die Fehlermeldung „SSRF blockiert“ weist jetzt auf das richtige Problem hin (#40807, #41027, #40605).

Upgrade-Anleitung

Modelltypmigration

[!IMPORTANT]

Einmalige Migration des Legacy-Modelltyps für selbst gehostete Upgrades

Wenn diese Bereitstellung von einer Dify-Version vor 1.15.0 aktualisiert wurde und diese Migration noch nicht angewendet wurde, führen Sie sie nach dem Upgrade aus.

Diese Migration ist nicht in flask db upgrade enthalten. Ohne sie können ältere Modelldatensätze dazu führen, dass modellbezogene API-Anfragen mit Fehlern fehlschlagen und betroffene Modelle nicht geladen oder verwendet werden können.

Sichern Sie die Datenbank, bevor Sie die Migration anwenden. Der Befehl wird standardmäßig im Probelaufmodus ausgeführt. Überprüfen Sie die Ausgabe, bevor Sie sie mit --apply erneut ausführen. Die Migration ist idempotent und kann sicher wiederholt werden.

Docker Verfassen

Aus dem Verzeichnis docker ausführen.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Quellcode-Bereitstellung

Nach Abschluss von flask db upgrade vom Repository-Stamm ausführen.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Führen Sie nach der Migration den Befehl „Probelauf“ erneut aus. Wenn keine weiteren Zeilenaktualisierungen oder -löschungen gemeldet werden, starten Sie die entsprechenden Dienste neu und überprüfen Sie, ob vorhandene Modelle erfolgreich geladen und aufgerufen werden können.

[!IMPORTANT] – Diese Version umfasst neue Datenbankmigrationen – führen Sie diese als Teil des Upgrades aus. – Umgebungsvariablen haben sich erheblich geändert (viele hinzugefügt, Editionsvariable umbenannt EDITION → DEPLOYMENT_EDITION, mehrere Standardeinstellungen geändert). Sehen Sie sich den Abschnitt „Änderungen der Umgebungsvariablen“ an und aktualisieren Sie Ihren .env entsprechend. Insbesondere benennen Sie EDITION in DEPLOYMENT_EDITION um, wenn Sie es festlegen.

  • Docker Compose-Konfiguration geändert und ein neues docker-compose.e2b.yaml hinzugefügt. Wenn Sie einen angepassten docker-compose.yaml verwalten, wenden Sie die lokalen Anpassungen sorgfältig erneut an. – Die Migration add_conversation_cleanup_index erstellt einen Index auf vorhandenen Daten. Die Ausführung kann länger dauern, wenn die Tabelle conversations groß ist.

Docker Bereitstellungen erstellen

  1. Sichern Sie Ihre benutzerdefinierten Compose- und Env-Dateien: 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Holen Sie sich den neuesten Code: 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Dienste stoppen (aus dem Verzeichnis docker): 
    docker compose down
  4. Daten sichern: 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Überprüfen Sie die Umgebungsänderungen und wenden Sie die lokalen Anpassungen erneut an (denken Sie an EDITION → DEPLOYMENT_EDITION).
  6. Upgrade: 
    docker compose up -d

Quellcode-Bereitstellungen

  1. Stoppen Sie den API-Server, den Worker und das Web-Frontend.
  2. Holen Sie sich den neuesten Code: 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Aktualisieren Sie die Python-Abhängigkeiten: 
    cd apiuv sync
  4. Migrationen ausführen: 
    uv run flask db upgrade
  5. Erstellen/starten Sie das Web-Frontend neu und starten Sie dann den API-Server und Worker neu.

dify 1.17.0

New Features

Agent: E2B Sandbox, Home Snapshots, and Skill Management

  • E2B sandbox backend: agent shell/code execution can now run on E2B cloud sandboxes in addition to the local sandbox. Select the backend with DIFY_AGENT_RUNTIME_BACKEND; a new docker-compose.e2b.yaml ships the E2B stack, E2B traffic is authenticated, and the E2B template is synced on release (#39480, #39705, #39873, #39996, #40858, #40871, #40891, #40892).
  • Build-time Home Snapshots: when an agent build is applied (published), the agent's sandbox home directory — installed packages, prepared files, working state — is captured and subsequent runs of the published agent restore their home directory from that snapshot, so the agent starts from the exact filesystem state it had at build time. (#39702, #40876, #40996).
  • Workspace-level Skill management: Skills are reusable, versioned capabilities packaged with code and tool definitions that agents can discover and invoke. A new workspace-level skills manager with draft → publish → version lifecycle ships alongside a web UI (skill listing, builder panel, file editor). (#39675, #39798, #39799, #41180).
  • Context-aware history compaction: long agent conversations no longer blow past the model's context window — Dify resolves each model's effective window and tiers compaction (clear old tool results first, then summarize older history) so runs stay within budget without losing recent context (#40872).

Reusable LLM Environment Variables in Workflows

  • Define a shared provider/model/mode/parameter configuration once (e.g. for_summarize, for_research) and reference it from any LLM node. Coordinated model changes now happen in one place instead of drifting node-by-node, and the references survive DSL import/export, snippets, RAG pipelines, and collaborative editing (#39125).

Human Input in Loops and Iterations

  • Human-in-the-loop forms now work inside Loop and Iteration nodes, pausing and resuming correctly across page refreshes for both debug and installed apps — enabling review/approval steps within repeated work (#39243).

Provider-Neutral Unified Tracing

  • Opt-in unified tracing (OPS_TRACE_UNIFIED_ENABLED) assembles the full parent-child span tree (workflows, chatflows, messages, nodes, loops, iterations, nested workflows) once in core and delegates only transport to lightweight adapters. Phoenix and LangSmith adapters ship first; disabled by default and fully backward compatible (#39451).
  • New GenAI spans surface LLM TTFT, agent ReAct steps, tool calls, and failed LLM nodes for deeper observability (#39339).

Cloudflare Turnstile (CAPTCHA) Support

  • Optional Turnstile challenge on sign-in and email-code login to protect authentication endpoints from abuse, with configurable site/secret keys and allowed hostnames (#40494).

Azure Key Vault / Pluggable KMS

  • Introduces a KMS provider abstraction with Azure Key Vault support for key provisioning, encryption, and decryption, plus key rotation configuration — a step toward externally-managed encryption keys (#39933).

TiDB Vector Full-Text & Hybrid Search

  • TiDB Vector deployments can now enable full-text and hybrid retrieval (TIDB_VECTOR_ENABLE_FULLTEXT_SEARCH, default off), using a multilingual full-text index alongside vector search (#38112).

Broader Model & File Handling

  • LLM nodes and agents can now pass image files directly to multimodal models, and non-vision attachments are no longer silently dropped from agent chats (#39848, #40179).
  • New multimodal retrieval guidance helps users pick embedding models correctly for image-bearing knowledge bases (#40566).
  • Audio ASR now accepts audio/x-m4a, and audio MIME types are validated more accurately (#40776, #41043).

Go to Anything (⌘K / Ctrl+K)

  • Press ⌘K (Ctrl+K on Windows/Linux) anywhere in the console to open the command palette and jump to apps, agents, skills, knowledge bases, plugins, or workflow nodes, or trigger quick actions via slash commands. New in this release: agents and skills are searchable, and the icon-command system was refactored across all domains for consistency (#40620, #40621, #40646–#40649, #41160).

Other Additions

  • ODT (OpenDocument Text) document extraction support (#39973).
  • New date / date-picker parameter type for tool plugins (#36163).
  • Lao (lo-LA) language support (#39474).
  • Automatic cleanup task for old conversations (ENABLE_CONVERSATION_CLEANUP_TASK) to bound data growth (#40889-era).
  • Marketplace embedded directly into integration categories for smoother tool/plugin discovery (#40744).

Improvements

Accessibility (large a11y pass)

  • A very large set of changes makes the console keyboard- and screen-reader-friendly: real <button> semantics for dozens of interactive controls, accessible names for icon-only actions (copy, close, delete, menus), primary headings on auth/install pages, keyboard-accessible member/tool selectors, and correct ARIA states (#40192–#40377 and many others).

Workflow Authoring

  • The workflow generator now prefers already-installed and configured tools when suggesting nodes, so builders reach for the tools they actually have (#40611, #39850).

Workflow & Runtime Stability

  • Reproducible web workflow runs, preserved canvas state after history updates, no more refresh render loops, and SSE streams now end cleanly on terminal events (#40010, #40489, #41105, #40042).
  • stop is now honored between non-streaming nodes and paused workflows clear stale cancellation signals correctly (#41090, #40905, #40972).
  • APP_MAX_EXECUTION_TIME and WORKFLOW_MAX_EXECUTION_TIME defaults raised from 1200s → 3600s to accommodate longer-running workflows.

Internal Quality

  • Large migration of unit tests to real ORM models / SQLite sessions for more reliable coverage, plus stronger typing across migrated tests (many #38xxx–#39xxx). No user-facing behavior change.

Security Enhancements

  • Authentication hardening: Turnstile challenge on login/email-code flows, hardened email-code verification with attempt limits and token expiry (EMAIL_CODE_LOGIN_MAX_ATTEMPTS, EMAIL_CODE_LOGIN_TOKEN_EXPIRY_MINUTES), suspended-email-domain handling, and short-lived agent authorization tokens (#40494, #40960, #41004, #40884).
  • Access-control / ownership scoping: dataset, document, RAG, conversation, workspace-credential, and OAuth-client resources are now consistently bound to their owners and app scope, closing several unauthorized-access paths (#40989, #40888, #40790, #40745, #40893, #40786, and related).
  • SSRF & outbound hardening: outbound HTTP connect phases are bounded (5s), agent/binding download and run timeouts are configurable, and the SSRF-blocked error message now points to the correct issue (#40807, #41027, #40605).

Bug Fixes (selected)

  • Prevent dropped workflow_started events in Redis Streams and dropped/duplicated runs from superseded executions (#40964, #40699).
  • Normalize workflow timestamps to naive UTC and preserve run snapshots/history for failed, cancelled, and interrupted runs (#40947, #40876, #40972).
  • Prevent cross-tab chat conversation switching and stop dropping non-vision attachments in agent chat (#40709, #40179).
  • Correct Qwen/VL system-message ordering by merging system messages first (#39136).
  • Fix Elasticsearch-JA adapter document_id mapping and VectorType (#40400); avoid empty Bedrock schema fields (#40443).
  • Use dynamic DNS resolution for all nginx upstreams (#39155); preserve UTF-8 byte size for text uploads (#40034).
  • Numerous webapp/UI fixes: restore email-code and password form submissions, mobile sign-in overflow, toast stacking, model selector spacing (#40227, #40222, #40921, #40970, #8d612895).

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

[!IMPORTANT]

  • This release includes new database migrations — run them as part of the upgrade.
  • Environment variables changed substantially (many added, edition variable renamed EDITION → DEPLOYMENT_EDITION, several defaults changed). Review the Environment Variable Changes section and update your .env accordingly. In particular, rename EDITION to DEPLOYMENT_EDITION if you set it.
  • Docker Compose configuration changed and a new docker-compose.e2b.yaml was added. If you maintain a customized docker-compose.yaml, re-apply local customizations carefully.
  • The migration add_conversation_cleanup_index builds index on existing data, which could take longer to execute if the conversations table is big.

Docker Compose Deployments

  1. Back up your customized compose and env files: 
    cd dockercp docker-compose.yaml docker-compose.yaml.$(date +%s).bakcp .env .env.$(date +%s).bak 2>/dev/null || true
  2. Get the latest code: 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Stop services (from the docker directory): 
    docker compose down
  4. Back up data: 
    tar -cvf volumes-$(date +%s).tgz volumes
  5. Review env changes and re-apply local customizations (remember EDITION → DEPLOYMENT_EDITION).
  6. Upgrade: 
    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend.
  2. Get the latest code: 
    git fetch --tagsgit checkout main   # or the target release tag once cut
  3. Update Python dependencies: 
    cd apiuv sync
  4. Run migrations: 
    uv run flask db upgrade
  5. Rebuild/restart the Web frontend, then restart the API server and Worker.
