🚀 LobeHub-Release v2.3.1

Hochstufen Sie den vollständigen aktuellen canary-Snapshot auf main für eine normale stabile Version und ersetzen Sie den geschlossenen, nicht zusammengeführten Hotfix-Vorschlag #22186. Dies ist kein Hotfix mit zwei Commits.

  • Vorheriger Stall: v2.3.0.
  • Kanarienvogel-Schnappschuss: 1a6ba7ad3853f140cc5795c5baf5ae37f78c9a13.
  • Geltungsbereich: 87 Upstream-Commits/PRs, einschließlich #22122 (automatische Genehmigung) und #22069 (Release-Veröffentlichungs-Token-Fix). – Der Release-Zweig startet direkt von diesem Canary-Snapshot, plus dem Bot-eigenen Versions-Upgrade und der Linux-Paketreparatur in #22190. Es werden keine Hotfix-Pickers oder zusätzliche Anwendungsfunktionen überlagert.

Highlights

  • Genehmigungen und Agentenzuverlässigkeit: Wechseln Sie direkt von der Genehmigungskarte zur automatischen Genehmigung; Verhindern Sie doppelte Genehmigungseinreichungen, doppelte Tool-Ausführungen bei der Wiederaufnahme und steckengebliebene Interventionsfortsetzungen. (#22122, #22058, #22060, #22068)
  • Aufgaben und linear: Mehrfachauswahl- und Stapelaktionen mit großen Listen, Filter im linearen Stil, Aktionen zum Erstellen von Aufgabengruppen, seitenweise Aktivität, lineare Kommentarsynchronisierung, Importe abgeschlossener Probleme und Zuverlässigkeit der Hintergrundsynchronisierung. (#22055, #22083, #22136, #22155, #22087, #22086, #22050)
  • Seiten, Dokumente und Dateien: Titel-/Textbearbeitung als ein Dokument, Korrekturen beim Umschreiben des Seitenagenten, Dokumentfavoriten, Laufwerks-Downloads und Ordner-ZIPs sowie glattere große Ordner. (#22154, #22141, #22147, #22095, #22106)
  • Projekte, Kanäle und Bots: Projekt-Avatare und Hauptagentenauswahl, Bestätigung der Projektlöschung, Auswahl von Kanalmitgliedern, Wiederherstellungs-/Bereinigungskorrekturen, ausgelagerte Wake-Records und nächtliche Bot-Retrospektiven. (#22091, #22101, #22161, #22163, #22081, #22098)
  • Suche, Dashboards und Modelle: DeepSeek-Suche/Crawling, Sandbox-HTML-Widget-Karten, Korrekturen für die strukturierte Ausgabe, Korrekturen für die Nutzungs-/Kostenrechnung und offizielle Modellkarten-Metadaten. (#21298, #22123, #21385, #22071, #22079, #22124)
  • Desktop und CLI: Bild kopieren, Desktop-Verknüpfungslisten, schnellere Desktop-Paketierung, Verbesserungen beim Neustart/Update des Connectors und CLI v0.0.74. (#22067, #22113, #22121, #22165, #22166, #22179)
  • Rollouts und Infrastruktur: Integration eines neuen Plans und prozentuale Rollout-Unterstützung; Die alternative Schienenanordnung verbleibt hinter im_layout. Bei der Release-Veröffentlichung wird explizit das App-Token verwendet, sodass nachgelagerte Veröffentlichungsworkflows gestartet werden können. (#22115, #22143, #22003, #22069)

Aktualisieren und veröffentlichen Sie Quellen

– Diese Version umfasst die Datenbankmigration 0199_topic_analyses.sql und das Hinzufügen der Themenanalysetabelle, Fremdschlüssel und Indizes. Selbstgehostete Betreiber sollten beim Upgrade das normale Datenbanksicherungs-/Migrationsverfahren einschließen.

  • Verwenden Sie den normalen Release-Initialisierungsablauf: Lösen Sie die Cloud-Revision für diese neue Version auf und pinnen Sie sie an. Erben Sie nicht den v2.3.0-Hotfix-Cloud-Pin.
  • Behalten Sie den genauen Titel 🚀 release: v2.3.1 bei, damit der Versions-Bot und der Tag-Workflow sich auf die beabsichtigte Version einigen.

Linux-Paketreparatur (#22190)

Der erste Linux-Desktop-Build ist fehlgeschlagen, weil das Vorlagen-Snap-Ziel des Electron-Builders 26.16.1 chrome-sandbox aus dem freigegebenen linux-unpacked-Verzeichnis gelöscht hat, während AppImage es gelesen hat. Windows bestanden; Die macOS-Jobs wurden von Matrix Fail-Fast abgebrochen. – Electron-Builder auf 26.18.0 aktualisiert und die isolierte Desktop-Sperrdatei aktualisiert, einschließlich des Upstream-Fix Electron-Userland/Electron-Builder#10333. – Integrationsregression gegen den installierten Packager und echte temporäre Dateien hinzugefügt: schlägt mit ENOENT auf 26.16.1 fehl, gibt 26.18.0 weiter. Downloads/Kompressorausführung werden gestoppt; Es werden echte Staging-, Filter- und Dateisystemmutationen durchgeführt. Der Helfer bleibt für andere Ziele intakt, wird jedoch von Snap-Eingaben ausgeschlossen.

  • Veränderter Datei-Lint, die Regressions- und integrierten Kernverpackungstests (2 bestanden), die Installation der eingefrorenen Sperrdatei und git diff --check bestanden. – Die Reparatur wurde über #22190 zusammengeführt, da release/*-Zweige PRs erfordern; Es wurde kein Zweigschutz umgangen. – Für diese reine Build-Tool-Reparatur ist keine neue UI-Akzeptanz erforderlich. Die vollständige Multiplattform-Paketierung wird durch den neuen PR-CI-Lauf erneut überprüft; Die lokalen Tests erheben keinen Anspruch auf einen echten Installer-Build oder -Start.

Summary

Contribution source: AI-assisted

🚀 LobeHub Release v2.3.1

Promote the complete current canary snapshot to main for a normal Stable release, replacing the closed, unmerged hotfix proposal #22186. This is not a two-commit hotfix.

  • Previous Stable: v2.3.0.
  • Canary snapshot: 1a6ba7ad3853f140cc5795c5baf5ae37f78c9a13.
  • Scope: 87 upstream commits/PRs, including both #22122 (auto approve) and #22069 (release publication token fix).
  • The release branch starts directly from that Canary snapshot, plus the bot-owned version bump and the Linux packaging repair in #22190. No hotfix cherry-picks or additional application features are layered on top.

Highlights

  • Approvals and agent reliability: switch to auto approve directly from the approval card; prevent duplicate approval submissions, duplicate tool execution on resume, and stuck intervention continuations. (#22122, #22058, #22060, #22068)
  • Tasks and Linear: large-list multi-select and batch actions, Linear-style filters, task-group create actions, paged activity, Linear comment sync, completed-issue imports, and background sync reliability. (#22055, #22083, #22136, #22155, #22087, #22086, #22050)
  • Pages, documents and files: title/body editing as one document, page-agent rewrite fixes, document favorites, drive downloads and folder ZIPs, and smoother large folders. (#22154, #22141, #22147, #22095, #22106)
  • Projects, channels and bots: project avatars and main-agent selection, project deletion confirmation, channel member picking, restore/purge fixes, paged wake records, and nightly bot retrospectives. (#22091, #22101, #22161, #22163, #22081, #22098)
  • Search, dashboards and models: DeepSeek search/crawling, sandboxed HTML widget cards, structured-output fixes, usage/cost accounting fixes, and official model-card metadata. (#21298, #22123, #21385, #22071, #22079, #22124)
  • Desktop and CLI: Copy Image, desktop shortcut listings, faster desktop packaging, connector restart/update improvements, and CLI v0.0.74. (#22067, #22113, #22121, #22165, #22166, #22179)
  • Rollouts and infrastructure: new-tier plan integration and percentage rollout support; the alternate rail layout remains behind im_layout. Release publication explicitly uses the App token so downstream publishing workflows can start. (#22115, #22143, #22003, #22069)

Upgrade and release sources

  • This release includes database migration 0199_topic_analyses.sql, adding the topic-analysis table, foreign keys and indexes. Self-hosted operators should include the normal database backup/migration procedure when upgrading.
  • Use the ordinary release initialization flow: resolve and pin the Cloud revision for this new release. Do not inherit the v2.3.0 hotfix Cloud pin.
  • Keep the exact title 🚀 release: v2.3.1 so the version bot and tag workflow agree on the intended version.

Linux packaging repair (#22190)

The first Linux desktop build failed because electron-builder 26.16.1's template Snap target deleted chrome-sandbox from the shared linux-unpacked directory while AppImage was reading it. Windows passed; the macOS jobs were cancelled by matrix fail-fast.

  • Upgraded electron-builder to 26.18.0 and updated the isolated desktop lockfile, including the upstream fix electron-userland/electron-builder#10333.
  • Added an integration regression against the installed packager and real temporary files: fails with ENOENT on 26.16.1, passes on 26.18.0. Downloads/compressor execution are stubbed; real staging, filtering and filesystem mutations are exercised. The helper stays intact for other targets but is excluded from Snap inputs.
  • Changed-file lint, the regression and builtin-core packaging tests (2 passed), frozen-lockfile installation and git diff --check passed.
  • The repair was merged through #22190 because release/* branches require PRs; no branch protection was bypassed.
  • No new UI acceptance is needed for this build-tool-only repair. Full multi-platform packaging is being rechecked by the new PR CI run; the local tests do not claim a real installer build or launch.
