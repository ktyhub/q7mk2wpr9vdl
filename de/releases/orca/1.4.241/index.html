Orca v1.4.241

Chats und ein Browser, der sich so verhält, wie Sie es erwarten 🧭

Mit dieser Version folgen Chats Ihren Agenteneinstellungen, bringen Chrome-ähnliche Tools in den integrierten Browser und unterstützen die Wiederherstellung von SSH-Verbindungen und verwalteten Servern. Sie finden außerdem eine Chat-Schriftarteinstellung, Live-Agent-Browsing und stabilere Hermes-, Kimi-, Kiro- und Windows-Terminals.

Die Kurzversion

  • Chats, die Ihren Einstellungen folgen: Neue Chats verwenden die Berechtigung jedes Agenten unter Einstellungen → Agenten, umbenannte Chats behalten ihre Namen im Sitzungsverlauf und ein Chat schreibt keine Konversation, wenn das Terminal noch läuft.
  • Ein Browser, der näher an Chrome ist: Docken Sie DevTools im Bereich an, schalten Sie die Tonwiedergabe von Tabs stumm, sehen Sie sich die URL eines Links an, wenn Sie mit der Maus darüber fahren, und verwenden Sie Orca-Verknüpfungen und die Maus innerhalb von Seiten vor/zurück.
  • Beobachten Sie, wie Agenten stöbern: Ein Cursor und ein Badge zeigen an, wo ein Agent clitippt oder tippt, der Chat leitet Sie zur Seite weiter und Links von Terminals und Chat werden neben ihrer Quelle geöffnet.
  • SSH mit weniger Sackgassen: Gespeicherte Portweiterleitungen kehren nach einem Neustart zurück und erklären Fehler, Nur-Zertifikat-Hosts verbinden sich über Ihr System ssh und verwaltete Server werden aktualisiert, ohne Terminals zu schließen.
  • Agenten, die zuverlässig starten und fortfahren: Hermes- und Kimi-Fenster werden nach einem Neustart fortgesetzt, Kiro meldet den Status auf seiner V3-Engine und während des Starts eines Agenten eingegebene Schlüssel werden als Entwurf gespeichert.
  • Polnisch, wo es darauf ankommt: Wählen Sie eine Schriftart für den Chat, zoomen Sie mit Cmd/Strg + + auf Nicht-US-Tastaturen, öffnen Sie nur Cloud-Dateien von macOS-Terminals und sorgen Sie für stabilere Windows-Terminals und das Einfügen. Telefon- und Web-Updates: Telefone lassen keine Teile der Terminalausgabe mehr fallen und Chat-Umbenennungen sowie der Berechtigungsmodus jedes Chats werden jetzt dort angezeigt. Sitzungsregisterkarten funktionieren auch weiterhin und Needs You für Windows-Agenten, die nie einen Titel festlegen.

Kompatibilitäts- und Upgrade-Hinweise

  • Neuer Terminal-Host: Neue Terminals starten auf einem neuen Terminal-Host, daher gelten die Terminal-Korrekturen dieser Version. Terminals, die bereits vor dem Update geöffnet waren, laufen auf dem vorherigen Host weiter und bleiben mit diesem verbunden, bis Sie sie schließen.
  • Chat-Berechtigungen: Einstellungen → Chat hat kein eigenes Berechtigungs-Dropdown mehr; Legen Sie es pro Agent unter Einstellungen → Agenten fest. Bestehende Chats behalten ihre gespeicherten Berechtigungen und das eigene Berechtigungsmenü eines Chats ändert nur diesen Chat.
  • In einem Terminal geöffnete Konversationen: Wenn ein Terminal möglicherweise noch eine Konversation schreibt, wird sein Chat nicht gesendet und Sie werden aufgefordert, den Agenten dort zu verlassen oder das Terminal zu schließen. Durch das Schließen dieses Terminals kann der nächste Sendevorgang durchgeführt werden.
  • Verwaltete SSH-Server: Trotzdem aktualisieren führt weiterhin laufende Terminals durch, die das Update durchlaufen. Das Angebot, Chats nach einem Neustart fortzusetzen, erfordert einen Server, auf dem diese Version bereits ausgeführt wird.
  • OpenCode-Modellauswahl: OpenCode 2.0.14, 2.0.15, 2.0.17 und 2.0.18 lassen die erste Nachricht ungesendet, wenn ein Modell ausgewählt wird, sodass Orca Modellauswahlen für diese Versionen ablehnt.

orca v1.4.241

Chats and a browser that behave the way you expect 🧭

This release makes chats follow your agent settings, brings Chrome-style tools to the built-in browser, and helps SSH connections and managed servers recover. You’ll also find a chat font setting, live agent browsing, and steadier Hermes, Kimi, Kiro and Windows terminals.

The short version

  • Chats that follow your settings: New chats use each agent’s permission from Settings → Agents, renamed chats keep their names in Session History, and a chat won’t write a conversation a terminal is still running.
  • A browser closer to Chrome: Dock DevTools inside the pane, mute tabs playing sound, see a link’s URL on hover, and use Orca shortcuts and mouse back/forward inside pages.
  • Watch agents browse: A cursor and badge show where an agent is clicking or typing, chat jumps you to the page, and links from terminals and chat open beside their source.
  • SSH with fewer dead ends: Saved port forwards return after a restart and explain failures, certificate-only hosts connect through your system ssh, and managed servers update without closing terminals.
  • Agents that start and resume reliably: Hermes and Kimi panes resume after a restart, Kiro reports status on its V3 engine, and keys typed while an agent starts are kept as a draft.
  • Polish where it counts: Pick a font for chat, zoom with Cmd/Ctrl + + on non-US keyboards, open cloud-only files from macOS terminals, and get steadier Windows terminals and pasting.

Phone & web updates: Phones no longer drop pieces of terminal output, and chat renames and each chat’s permission mode now show there. Session tabs also keep Working and Needs You for Windows agents that never set a title.

Compatibility & upgrade notes

  • Fresh terminal host: New terminals start on a fresh terminal host so this release’s terminal fixes apply. Terminals already open before you update keep running, and stay attached, on the previous host until you close them.
  • Chat permissions: Settings → Chat no longer has its own permission dropdown; set it per agent in Settings → Agents. Existing chats keep their saved permission, and a chat’s own permission menu changes only that chat.
  • Conversations open in a terminal: If a terminal might still be writing a conversation, its chat won’t send and asks you to quit the agent there or close that terminal. Closing that terminal lets the next send go through.
  • Managed SSH servers: Update anyway keeps running terminals going through the update. The offer to resume chats after a restart needs a server already running this release.
  • OpenCode model picks: OpenCode 2.0.14, 2.0.15, 2.0.17 and 2.0.18 leave the first message unsent when a model is picked, so Orca refuses model picks on those versions.
