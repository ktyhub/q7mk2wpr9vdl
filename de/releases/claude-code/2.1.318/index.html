Claude-Code v2.1.318

Was hat sich geändert?

  • Es wurde eine Aufzeichnung Ihrer Antwort hinzugefügt, wenn Claude Code Sie auffordert, die Mods zu aktivieren, die es in einer Sitzung schreibt – assume_role auf mantle-Upstreams des Claude-Apps-Gateways hinzugefügt, für eine Rolle in einem anderen AWS-Konto und für die AWS-Kostenzuordnung pro Entwickler
  • Dem $.model.fork eines Mods wurde eine effort-Option hinzugefügt, sodass ein schneller Nebenjob bei low ausgeführt werden kann, egal wie viel Aufwand die Sitzung erfordert. Das Ergebnis gibt den gesendeten Aufwand an
  • Das Datum, an dem eine gespeicherte claude.ai-Anmeldung endet, wurde zu claude auth status (loginExpiresAt) und zu den Ergebnissen claude -p JSON (credential_expires_at) hinzugefügt. – Der claude -p-Textausgabe wurde eine einzeilige stderr-Warnung hinzugefügt, die 10 Tage vor dem Ende einer gespeicherten claude.ai-Anmeldung beginnt – Behoben, dass --continue manchmal die frühere Konversation verlor, nachdem die Wiederholungsversuche eines fehlerhaften Tool-Aufrufs abgelaufen waren (Regression in 2.1.314) – Behoben: macOS-Sitzungen, bei denen viele laufende Bash-Befehle ins Stocken gerieten, während der Speicher zunahm – Problem behoben, bei dem Berechtigungsaufforderungen durch Tastenbeantwortung beantwortet wurden, die direkt nach dem Senden einer Nachricht oder vor dem Erscheinen einer langsamen Aufforderung eingegeben wurden – Fehler bei der Erfolgsmeldung von /logout, claude auth logout und claude mcp remove sowie bei Änderungen an trust, Zustimmung oder MCP-Einstellungen, die ohne Wort verworfen wurden, wenn die Konfigurationsdatei in einem freigegebenen Netzwerk-Home-Verzeichnis nicht aktualisiert werden konnte, behoben – Behoben, dass Jobs mit Not logged in beendet wurden, wenn sich ein anderes Terminal oder Host erneut bei demselben Konto und derselben Organisation im selben Zuhause anmeldet – Problem mit claude mcp add und remove beim Schreiben der Konfiguration ohne Sperre behoben: Sie warten jetzt darauf oder beenden 1, obwohl die Speicherung eines anderen Jobs immer noch einen gespeicherten Server ersetzen kann – Behoben, dass claude plugin-Befehle beendet wurden, bevor eine langsame Token-Aktualisierung gespeichert wurde, was dazu führen konnte, dass Sie bei der nächsten Ausführung abgemeldet wurden – Problem behoben, bei dem claude plugin validate eine benutzerdefinierte Marktplatzdatei übergab, die claude plugin marketplace add ablehnte – Problem behoben, bei dem stdio MCP-Server beendet wurden, wenn die Versionsprüfung bei jedem Start erneut überprüft wurde; Ein Server, der aus eigenem Grund in weniger als 3 Sekunden ausfällt, ist ebenfalls 7 Tage lang an den alten Handshake gebunden – Behebung eines Problems, bei dem Sitzungen beim Start durch eine allowedProviders-Liste abgelehnt wurden, die bei einer anderen Anmeldung auf demselben Computer gespeichert war – Problem behoben, bei dem die Leerlaufkomprimierung eine Konversation durch eine Antwort ersetzte, die keine Zusammenfassung war – Der Hinweis „Jetzt werden Nutzungsguthaben verwendet“ wurde behoben, der etwa alle 30 Sekunden erneut angezeigt wurde, während ein Hintergrund-Subagent ausgeführt wurde – Fehler bei benutzerdefinierten Schrägstrichbefehlen behoben, die fehlschlugen oder die nur Claude aufrufen konnte und die in claude -p- und SDK-Sitzungen nichts druckten – Problem behoben, bei dem claude -p- und Agent SDK-Sitzungen Erfolg meldeten, wenn ein API-Fehler eine Antwort unterbrach, während ein Mod turn.step einhakte – Es wurde eine Nachricht behoben, die unmittelbar nach einer Modelländerung gesendet wurde und nach „Stopp“ in Headless-Sitzungen immer noch ausgeführt wurde: „Stopp“ bricht sie jetzt ab oder stoppt sie, wie es bei einer Nachricht in der Warteschlange der Fall wäre – Ein Problem wurde behoben, bei dem ein gelöschtes Sitzungsprotokoll mit der letzten Eingabeaufforderung neu erstellt wurde, wenn eine inaktive, nicht interaktive Sitzung beendet wurde – Problem behoben, bei dem claude remote-control-Hosts, der Hintergrund-Daemon und selbstgehostete Läufer keine neuen Sitzungen starten konnten (spawn ENOENT), nachdem durch ein Update oder eine Versionsbereinigung die Binärdatei eines noch laufenden Prozesses entfernt wurde – Behoben: Ein laufender Claude Code-Prozess, der einem anderen Benutzer gehört (z. B. einer, der von sudo claude verlassen wurde), wurde durch die Versionsbereinigung als tot behandelt, wodurch seine Binärdatei gelöscht werden konnte – Problem behoben, bei dem /remote-control eine Sitzung nach einer fehlgeschlagenen Verbindung als verfügbar anzeigte – Problem behoben, bei dem /design revoke den Erfolg meldete, wenn die Anfrage mit 404 fehlschlug – Ein Shell-Befehl wurde behoben, der nach dem Neustart eines selbstgehosteten Läufers oder einer Cloud-Sitzung im Startordner der Sitzung und nicht im Ordner, in dem er angefordert wurde, ausgeführt wurde. Wenn dieser Ordner nicht eingegeben werden kann, wird er nicht ausgeführt – Problem behoben, bei dem Claude nach einem Neustart der Cloud-Sitzung nicht darüber informiert wurde, wenn ein genehmigtes Connector-Tool nicht verfügbar war – Behoben: Cloud-Sitzungen wurden mitten in einer Runde gestoppt, wenn der Dienst mehrere Minuten lang Uploads verweigerte – Behoben, dass Variablen, die ein Setup-Hook in CLAUDE_ENV_FILE schreibt, in einigen Cloud-Sitzungen das Bash-Tool nicht erreichten – Problem behoben, bei dem die iPhone-App den Zug einer Cloud-Sitzung als beendet anzeigte, während sie weiterlief, nachdem eine Antwort bei einem Tool-Aufruf abgebrochen oder ein abgelehntes Bild oder Dokument entfernt wurde – Behebung eines Fehlers bei einer neu gestarteten Sitzung, bei der eine Nachricht, die mit einem API-Fehler fehlgeschlagen war, erneut gesendet wurde, bevor die neuere Nachricht dahinter wartete – Es wurde ein Problem behoben, bei dem eine neu gestartete Sitzung ihre unterbrochene Runde verlor, wenn der Neustart erfolgte, direkt nachdem Claude ein großes Bild gelesen oder einen Tool-Aufruf erneut versucht hatte – Es wurde behoben, dass jede Verbindung fehlschlug, wenn die NODE_EXTRA_CA_CERTS-Datei leer ist, nicht PEM, oder mit einem beschädigten Zertifikat startet: Es werden jetzt lesbare Zertifikate verwendet, mit einer Warnung auf stderr – Problem behoben, bei dem Workflows abgeschlossene Agenten erneut ausführten, wenn sie nach einer Nutzungsbeschränkung fortgesetzt wurden – /mcp in Zähltools für Cloud-Sitzungen behoben, die das Modell nicht verwenden kann; In der Zeile eines Servers wird nun angezeigt, wie viele seiner Tools verfügbar sind – Eine doppelte Benachrichtigung behoben, wenn Claude das Statusfeld außerhalb eines PushNotification-Anrufs verließ – Der Fehler bei einem zu großen Bild in einer Anfrage mit mehr als 20 Bildern wurde behoben und es wurde immer angezeigt, dass die Grenze 2000 Pixel betrug; es zeigt jetzt das Limit des API an – Behoben, dass die Runtime-Details der Hintergrund-Shell nicht aktualisiert wurden, während das Dialogfeld geöffnet war – Der turn.step-Hook eines Mods wurde behoben, der dazu führte, dass eine gestoppte Antwort in Headless-Runs als Erfolg gewertet wurde – Die Aufbewahrungsbereinigung wurde behoben und hinterließ ein Heim, auf dem nur claude -p ohne ~/.claude.json-Backup ausgeführt wird: Es wird jetzt ein neues Backup erstellt, bevor das letzte gute Backup gelöscht wird – Es wurde behoben, dass die gespeicherten Anmeldedaten durch eine leere Datei ersetzt wurden, wenn in einem Netzwerk-Home-Verzeichnis kein Platz mehr für Daten vorhanden war, aber dennoch neue Dateien aufgenommen wurden – Problem behoben, bei dem Token von setup-token beim Start auf Computern mit forceLoginOrgUUID abgelehnt wurden, wenn der Token einer zugelassenen Organisation gehörte
  • Nicht interaktive Starts wurden behoben, bei denen ein ~/.claude.json, der nicht gültig ist, JSON durch Standardeinstellungen ersetzt wurde. Der Start schlägt jetzt fehl, sagt, wie die Datei wiederhergestellt werden soll, und lässt sie unverändert (anthropics/claude-code#87551) – Ein leeres ~/.claude.json ohne Backup wurde als beschädigt gemeldet. Claude Code startet jetzt wie bei fehlender Datei – Der Wiederherstellungsbefehl, der für ein beschädigtes oder fehlendes ~/.claude.json ausgegeben wurde und ein leeres oder abgeschnittenes Backup nannte oder bei einer schreibgeschützten Datei fehlschlug, wurde behoben
  • Der Anmeldefehler wurde behoben, wenn ein gespeicherter claude.ai-Login sein Zeitlimit erreicht: Jetzt wird dies angezeigt und in claude -p werden die Namen claude auth login und claude setup-token angezeigt – Die Art und Weise, wie ~/.claude.json, Einstellungsdateien und die gespeicherten Anmeldedaten in freigegebenen Netzwerk-Home-Verzeichnissen gespeichert werden, wurde verbessert: Sie werden seltener gelöscht, kurzzeitig geleert oder durch eine fast leere oder ältere Kopie ersetzt – Verbesserte Sitzungen auf Netzwerkdateisystemen, die erneut suchen, wenn die Konfigurationsdatei fälschlicherweise als fehlend gemeldet wird, sodass weniger Sitzungen ohne Ihre MCP-Server und trusted-Ordner gestartet werden
  • Verbesserte MCP-Tool-Fehler: Ein Aufruf, der vor dem Laden des Tools erfolgt, gibt jetzt sein Eingabeschema zurück – Die Zuverlässigkeit von Git-Commits und der Erstellung von Pull-Anfragen wurde verbessert, wenn das Bash-Tool das in macOS integrierte /bin/bash ausführt
  • „Bitten Sie Ihren Administrator um mehr Nutzung“ im Menü „Nutzungsbeschränkung“ wurde verbessert, um die Anfrage in einem Schritt zu senden – Die Geschwindigkeit, mit der Remote-Sitzungen nach einer Pause oder einem Ruhezustand wieder verbunden werden, wurde verbessert
  • Verbessert Sie sollten wissen, dass Toasts „Erneut versuchen“ statt „2 drücken“ sagen sollen, was nur im Terminal funktioniert
  • Verbesserte Zuverlässigkeit der automatischen Aktualisierung: Ein kurzer Netzwerkfehler während der Überprüfung einer Version wird jetzt sofort erneut versucht, anstatt auf die nächste Überprüfung zu warten – Verbesserte unbeaufsichtigte Ausführungen (claude -p-, SDK-Apps), um das Neuschreiben von ~/.claude.json bei jeder Ausführung zu stoppen, wenn sich darin nichts geändert hat – Claude Code wurde so geändert, dass die IDE-Erweiterung nicht mehr installiert oder aktualisiert wird, wenn sie in einem IDE-Terminal gestartet wird; Verwenden Sie /ide von einem externen Terminal oder der Erweiterungsansicht Ihres Editors – Subagenten wurden so geändert, dass sie anhalten, anstatt das Modell zu wechseln, wenn „Modell wechseln, wenn eine Nachricht markiert ist“ auf „Jedes Mal fragen“ eingestellt ist. – Hintergrundsubagenten wurden geändert, um einen Shell-Befehl bei allen Anbietern nach 3 Minuten in den Hintergrund zu verschieben, sodass der Eingabeaufforderungscache während der Ausführung nicht abläuft

  • [Codeüberprüfung] Die Analyseseite für die Codeüberprüfung wurde verbessert, sodass sie nach einem Server- oder Netzwerkausfall einmal erneut versucht und dann anstelle leerer Karten ein Banner „Erneut versuchen“ anzeigt

claude-code v2.1.318

What's changed

  • Added a record of your answer when Claude Code asks to turn on the mods it writes in a session
  • Added assume_role on mantle upstreams of the Claude apps gateway, for a role in another AWS account and for per-developer AWS cost attribution
  • Added an effort option to a mod's $.model.fork, so a quick side job can run at low whatever effort the session uses; the result reports the effort sent
  • Added the date a stored claude.ai sign-in ends to claude auth status (loginExpiresAt) and to claude -p JSON results (credential_expires_at)
  • Added a one-line stderr warning to claude -p text output, starting 10 days before a stored claude.ai sign-in ends
  • Fixed --continue sometimes losing the earlier conversation after a malformed tool call's retries ran out (regression in 2.1.314)
  • Fixed macOS sessions with many running Bash commands stalling while memory grew
  • Fixed permission prompts being answered by keys typed just after sending a message, or before a slow prompt appeared
  • Fixed /logout, claude auth logout and claude mcp remove reporting success, and changes to trust, consent or MCP settings being dropped with no word, when the config file could not be updated on a shared network home directory
  • Fixed jobs exiting with Not logged in when another terminal or host signs in again to the same account and organization on the same home
  • Fixed claude mcp add and remove writing the config without its lock: they now wait for it or exit 1, though another job's save can still replace a saved server
  • Fixed claude plugin commands exiting before a slow token refresh was saved, which could sign you out on the next run
  • Fixed claude plugin validate passing a custom-named marketplace file that claude plugin marketplace add rejects
  • Fixed stdio MCP servers that exit on the version probe being re-probed on every start; a server that dies in under 3s for its own reason is also pinned to the legacy handshake for 7 days
  • Fixed sessions being refused at startup by an allowedProviders list that another login on the same machine had stored
  • Fixed idle compaction replacing a conversation with a reply that was not a summary
  • Fixed the "Now using usage credits" notice reappearing about every 30 seconds while a background subagent is running
  • Fixed custom slash commands that fail, or that only Claude can invoke, printing nothing in claude -p and SDK sessions
  • Fixed claude -p and Agent SDK sessions reporting success when an API error cut off a reply while a mod hooked turn.step
  • Fixed a message sent right after a model change still running after Stop in headless sessions: Stop now cancels or stops it as it would a queued message
  • Fixed a deleted session transcript being re-created with its last prompt when an idle non-interactive session exited
  • Fixed claude remote-control hosts, the background daemon and self-hosted runners failing to start new sessions (spawn ENOENT) after an update or version cleanup removed the binary of a still-running process
  • Fixed a running Claude Code process owned by another user (for example one left by sudo claude) being treated as dead by version cleanup, which could delete its binary
  • Fixed /remote-control showing a session as available after a failed connection
  • Fixed /design revoke reporting success when the request failed with a 404
  • Fixed a shell command approved after a self-hosted runner or cloud session restart running in the session's start folder, not the folder it was asked in; if that folder can't be entered, it is not run
  • Fixed Claude not being told when an approved connector tool was unavailable after a cloud session restart
  • Fixed cloud sessions being stopped in the middle of a turn when the service refuses uploads for several minutes
  • Fixed variables a Setup hook writes to CLAUDE_ENV_FILE not reaching the Bash tool in some cloud sessions
  • Fixed the iPhone app showing a cloud session's turn as finished while it kept running, after a response was cut off at a tool call or a refused image or document was removed
  • Fixed a restarted session re-sending a message that failed with an API error, ahead of the newer message waiting behind it
  • Fixed a restarted session dropping its interrupted turn when the restart came right after Claude read a large image or retried a tool call
  • Fixed every connection failing when the NODE_EXTRA_CA_CERTS file is empty, not PEM, or starts with a damaged certificate: readable certificates are now used, with a warning on stderr
  • Fixed workflows re-running finished agents when resumed after a usage limit
  • Fixed /mcp in cloud sessions counting tools the model can't use; a server's row now shows how many of its tools are available
  • Fixed a duplicate notification when Claude left the status field out of a PushNotification call
  • Fixed the error for a too-large image in a request with more than 20 images always saying the limit was 2000px; it now shows the API's limit
  • Fixed the runtime in background shell details not updating while the dialog is open
  • Fixed a mod's turn.step hook making a stopped reply finish as a success in headless runs
  • Fixed retention cleanup leaving a home that only runs claude -p with no ~/.claude.json backup: it now takes a fresh backup before deleting the last good one
  • Fixed the stored login being replaced by an empty file when a network home directory has no room left for data but still takes new files
  • Fixed tokens from setup-token being refused at start on machines with forceLoginOrgUUID, when the token belongs to a permitted organization
  • Fixed non-interactive launches replacing a ~/.claude.json that isn't valid JSON with defaults; the start now fails, says how to restore the file, and leaves it as is (anthropics/claude-code#87551)
  • Fixed an empty ~/.claude.json with no backup being reported as corrupted; Claude Code now starts as it does when the file is missing
  • Fixed the restore command printed for a damaged or missing ~/.claude.json naming an empty or cut-off backup, or failing on a read-only file
  • Fixed the sign-in failure when a stored claude.ai login reaches its time limit: it now says so, and in claude -p names claude auth login and claude setup-token
  • Improved how ~/.claude.json, settings files and the stored login survive saves on shared network home directories: they are less often deleted, briefly emptied or replaced by a near-empty or older copy
  • Improved sessions on network file systems to look again when the configuration file is wrongly reported as missing, so fewer start without your MCP servers and trusted folders
  • Improved MCP tool errors: a call made before the tool is loaded now returns its input schema
  • Improved the reliability of git commits and pull request creation when the Bash tool runs macOS's built-in /bin/bash
  • Improved "Ask your admin for more usage" in the usage limit menu to send the request in one step
  • Improved how fast remote sessions reconnect after a pause or sleep
  • Improved You should know toasts to say "try again" instead of "press 2", which only works in the terminal
  • Improved auto-update reliability: a brief network failure while verifying a release is now retried right away instead of waiting for the next check
  • Improved unattended runs (claude -p, SDK apps) to stop rewriting ~/.claude.json on every run when nothing in it changed
  • Changed Claude Code to no longer install or update the IDE extension when started in an IDE terminal; use /ide from an outside terminal or your editor's extensions view
  • Changed subagents to stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time"
  • Changed background subagents to move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs
  • Changed subagent progress summaries on Bedrock, Vertex, Foundry, or with telemetry off: on a cold prompt cache, one can now wait up to 5 minutes for the subagent's pending response
  • Changed what a mod attaches at prompt.submit to stay in the user's turn rather than go out as a system message
  • Changed deniedMcpServers URL entries to also block Anthropic-provided servers whose upstream URL matches, and connectors in cloud sessions and on self-hosted runners, where the session is given the connector's own URL; otherwise deny a connector by name
  • Changed the /permissions rule details, built-in rules and delete confirmation views to use the standard dialog; pressing Ctrl+C twice there now goes back or cancels instead of quitting
  • Changed /claude-api managed-agents-onboard to give a new agent's built-in tools, and a quickstart template's MCP tools, the auto permission policy ("Judge risky actions") by default, matching the Claude Console; say "run without asking" to opt out
  • Removed the 2.1.288 fix that kept the model's earlier thinking when resuming a conversation started on 2.1.286 or earlier; that thinking can now be dropped
  • Gateway: Added a log warning when the Google access token from a federation (external_account) credentials file is about to expire
  • Gateway: Improved the log hints about listen.trusted_proxies: they now say to list only a proxy that adds the connecting address to X-Forwarded-For itself
  • Gateway: Improved the warning when AWS CountTokens fails on Amazon Bedrock: it says Claude Code, not the gateway, counts after the 501, and points at IAM only when AWS denies access
  • Self-hosted runner: Added CLAUDE_RUNNER_SPAWN_REASON to the orchestrator's spawn-runner hook environment: why Anthropic sent the request (e.g. runner_lost, resumed); unset when none was sent
  • Self-hosted runner: Added a startup warning when --release-idle-session-min is the last argument with no value (still ignored) or has a value of only spaces (still read as 0)
