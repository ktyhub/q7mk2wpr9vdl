Claude-Code v2.1.259

Was hat sich geändert?

– Verwaltete Einstellung managedMcpServers hinzugefügt: Organisationen können jedem Benutzer HTTP/SSE-MCP-Server bereitstellen (gleiche Eintragsform wie .mcp.json); Einträge, die einen auszuführenden Befehl benennen, werden übersprungen – --permission-prompts none für unbeaufsichtigte Headless-Hosts hinzugefügt: Alles, was dazu führen würde, wird automatisch abgelehnt, während der aktive Berechtigungsmodus (einschließlich Auto-Modus) weiterhin entscheidet – Erkennung von glab mr create/merge/close/reopen/note/update hinzugefügt, sodass GitLab-Zusammenführungsanfragen in der minimierten Tool-Zusammenfassung als MR !N angezeigt werden und das MR-Badge in der Fußzeile aktualisiert wird – --json zu claude plugin validate für einen maschinenlesbaren Validierungsbericht hinzugefügt – Problem behoben, bei dem gleichzeitige Sitzungen stillschweigend die ~/.claude.json-Änderungen der anderen Sitzungen rückgängig machten – der Arbeitsbereich trust wird nicht mehr zurückgesetzt und der MCP-/Projektstatus geht nicht mehr verloren, wenn viele Sitzungen gleichzeitig ausgeführt werden

  • Es wurde ein Problem behoben, bei dem ein Gespräch, dessen Gedanken einmal abgelehnt wurden, in jeder späteren Runde erneut abgelehnt wurde – Bash Read()-Verweigerungsregeln behoben, die Dateien nicht abdeckten, die als Optionswerte (--ignore-revs-file=.env, -f.env, @file), git diff/git grep-Dateioperanden oder cd DIR && cat FILE-Verbindungen angegeben wurden; grep -r/cp -r über ein Verzeichnis, das eine abgelehnte Datei enthält, fragt jetzt – Es wurde behoben, dass der Eingabeaufforderungscache ungültig wurde, wenn das OAuth-Token in Sitzungen mit deaktivierter Telemetrie aktualisiert wurde
  • Problem behoben, bei dem im Vollbildmodus nach einer langen Runde mit Hunderten von Werkzeugaufrufen ein leeres Gespräch angezeigt wurde
  • Der automatische Modus, bei dem eine Runde bei einem Modell ausgeführt wurde, wurde behoben, das nicht unterstützt wurde, wenn ein Befehl oder eine Fertigkeitsfrontmatter model: einen benannt hat; Der Turn behält nun das Sitzungsmodell bei – Problem behoben, bei dem CLAUDE_CODE_MAX_CONTEXT_TOKENS für Modell-IDs im Vertex-Stil (Suffix @YYYYMMDD) von Modellversionen ignoriert wurde, die Claude Code nicht erkennt – Die Live-Ausgabevorschau eines laufenden Shell-Befehls hat ein Problem behoben, bei dem die neuesten Zeilen ausgeblendet wurden, wenn eine frühere Zeile umbrochen wurde
  • Eine GitHub-Verbindungsprüfung im Hintergrund wurde behoben, die bei jedem Start für claude.ai-Benutzer durchgeführt wurde. Das Ergebnis wird nun bei allen Produkteinführungen gespeichert – Fehler behoben, bei dem --resume fehlschlug (und --continue eine leere Konversation öffnete), wenn eine gespeicherte Sitzung einen Anhangeintrag ohne Nutzlast enthielt
  • Frontmatter model: bei benutzerdefinierten Befehlen und Fertigkeiten wurde behoben, die in interaktiven Sitzungen ignoriert wurden – Es wurde behoben, dass die Veröffentlichung von Artefakten einmal mit dem Fehler „Unerwarteter Parameter note“ in Konversationen fehlschlug, die von einer älteren Version fortgesetzt wurden – Behoben: Verwaltetes forceRemoteSettingsRefresh wurde beim Start ignoriert, wenn ein von MDM konfigurierter Richtlinienhelfer oder die verwaltete Einstellungsdatei bereits ausgeführt wurde – Die Worktree-Isolation wurde behoben, wodurch von Hooks erstellte Worktrees auf Computern abgelehnt wurden, auf denen git rev-parse mit einer anderen Meldung als „Kein Git-Repository“ fehlschlägt. – OpenTelemetry-Metriken und Ereignisse aus Cloud-Sitzungen behoben, bei denen die Attribute user.email, organization.id und user.account_uuid fehlten – Behoben: MCP-Server, die die Verbindung trennen, während ihre Tools beim Start aufgelistet werden, werden als verbunden ohne Tools angezeigt, anstatt den Fehler zu melden
  • Das Dialogfeld mit der Berechtigung zum Bearbeiten von Dateien zeigte manchmal eine abgeschnittene geänderte Zeile ohne Angabe an – Die Repository-Erkennung hat das Löschen einer bekannten Repo-Identität nach einem vorübergehenden Git-Probe-Fehler behoben – Behoben, dass verwaltete Einstellungen stillschweigend nicht erzwungen wurden, wenn die Datei mit verwalteten Einstellungen, ein Drop-In, die MDM-Plist oder der HKLM-Wert nicht analysiert werden können: Claude Code weigert sich jetzt zu starten und benennt die Quelle – Behoben: Stop stoppt Hintergrundagenten und Workflows in Fernsteuerungssitzungen nicht wirklich: Abgebrochene Aufgaben bleiben jetzt sichtbar und können erneut gestoppt werden, bis ihre Prozesse beendet werden – Das Wiederaufnehmen einer Workflow-Ausführung, während die vorherige gestoppte Ausführung noch beendet wurde, wurde behoben, was dazu führen konnte, dass doppelte Kopien seiner Agenten ausgeführt wurden
  • Marktplatz-Repo-URLs auf github.com mit einem abschließenden Schrägstrich oder baumelnden ?/# behoben, was zu einer unbrauchbaren .git-Klon-URL führte
  • Blockierende Stop-Hooks wurden behoben, die dazu führten, dass die Runde nach einem Block die Argumentation des Modells aus dieser Runde verlor und bei einigen Modellen der Prompt-Cache fehlte – Problem behoben, bei dem Remote-Sitzungen (claude.ai) 60 Sekunden brauchten, um eine Runde zu starten, nachdem die Seite eines im Browser gehosteten MCP-Servers verschwunden war – Behoben: Arbeitsbaum-isolierte Sitzungen, die allgemeine Bash-Schleifen, XARGS-Pipelines und vom Launcher umschlossene Befehle ablehnten, die den Haupt-Checkout nicht erreichen konnten – Verbesserte Terminal-Größenänderung und Leistung beim ersten Rendern für lange Antworten durch Wiederverwendung von Textmaßen
  • Verbesserte /workflows-Agentendetails: JSON-Ergebnisse werden hübsch mit Syntaxfarben und echten Zeilenumbrüchen gedruckt, und lange Ergebnisse werden hinter einem Erweiterungsschalter gefaltet – Verbesserter Headless-/SDK-Sitzungsstart: Die erste Runde beginnt bis zu 50 ms früher, wenn die MCP-Server die Verbindung abgeschlossen haben – /install-github-app wurde verbessert, um zu erklären, dass es nur für GitHub gilt und auf die CI/CD-Dokumente von GitLab verweist, wenn es in einem GitLab-Repository ausgeführt wird – Verbesserte Ergebnisse verschachtelter Hintergrund-Subagenten werden im Transkript des übergeordneten Subagenten gespeichert, sodass fortgesetzte Subagenten sie behalten und freigegebene Transkripte die Zustellung anzeigen – allowedMcpServers wurde geändert, um nur Server zu verwalten, die Benutzer hinzugefügt haben: Ein wörtlicher managed-mcp.json-Server, den Ihre Zulassungsliste zum Herausfiltern verwendet hat, wird jetzt beim Upgrade geladen; Verwenden Sie deniedMcpServers, um es ausgeschaltet zu halten
  • [VSCode] Der Sitzungslisten-Seitenleiste wurden ein Aktiv-Schnellfilter und ein Statusfiltermenü (Eingabe erforderlich, In Arbeit, Abgeschlossen) hinzugefügt – Problem behoben, bei dem Remote- und geplante Sitzungen nichts bewirkten, nachdem eine Connector-Tool-Berechtigungsaufforderung genehmigt wurde, während die Sitzung angehalten war

Englisches Original / English original

claude-code v2.1.259

What's changed

  • Added managedMcpServers managed setting: organizations can provide HTTP/SSE MCP servers to every user (same entry shape as .mcp.json); entries that name a command to run are skipped
  • Added --permission-prompts none for unattended headless hosts: anything that would prompt is denied automatically while the active permission mode (including auto mode) keeps deciding
  • Added recognition of glab mr create/merge/close/reopen/note/update so GitLab merge requests show as MR !N in the collapsed tool summary and refresh the footer MR badge
  • Added --json to claude plugin validate for a machine-readable validation report
  • Fixed concurrent sessions silently reverting each other's ~/.claude.json changes — workspace trust no longer resets and MCP/project state is no longer lost when running many sessions at once
  • Fixed a conversation whose thinking was rejected once being rejected again on every later turn
  • Fixed Bash Read() deny rules not covering files given as option values (--ignore-revs-file=.env, -f.env, @file), git diff/git grep file operands, or cd DIR && cat FILE compounds; grep -r/cp -r over a directory holding a denied file now asks
  • Fixed the prompt cache being invalidated when the OAuth token refreshed in sessions with telemetry disabled
  • Fixed fullscreen mode showing a blank conversation after a long turn with hundreds of tool calls
  • Fixed auto mode running a turn on a model it doesn't support when a command or skill's frontmatter model: named one; the turn now keeps the session model
  • Fixed CLAUDE_CODE_MAX_CONTEXT_TOKENS being ignored for Vertex-style model IDs (@YYYYMMDD suffix) of model versions Claude Code doesn't recognize
  • Fixed the live output preview of a running shell command hiding its newest lines when an earlier line wrapped
  • Fixed a background GitHub connection check that ran on every launch for claude.ai users; the result is now remembered across launches
  • Fixed --resume failing (and --continue opening an empty conversation) when a saved session contains an attachment entry with no payload
  • Fixed frontmatter model: on custom commands and skills being ignored in interactive sessions
  • Fixed Artifact publishing failing once with an "unexpected parameter note" error in conversations continued from an older version
  • Fixed managed forceRemoteSettingsRefresh being ignored at startup when a policy helper configured by MDM or the managed settings file had already run
  • Fixed worktree isolation refusing hook-created worktrees on machines where git rev-parse fails with a message other than "not a git repository"
  • Fixed OpenTelemetry metrics and events from cloud sessions missing the user.email, organization.id, and user.account_uuid attributes
  • Fixed MCP servers that disconnect while their tools are being listed at startup showing as connected with no tools instead of reporting the error
  • Fixed the file edit permission dialog sometimes showing a changed line cut short with no indication
  • Fixed repository detection dropping a known repo identity after a transient git probe failure
  • Fixed managed settings silently going unenforced when the managed-settings file, a drop-in, the MDM plist, or the HKLM value cannot be parsed: Claude Code now refuses to start and names the source
  • Fixed Stop not actually stopping background agents and workflows in remote-control sessions: killed tasks now stay visible and re-stoppable until their processes exit
  • Fixed resuming a workflow run while its previous stopped run was still exiting, which could run duplicate copies of its agents
  • Fixed marketplace repo URLs on github.com with a trailing slash or dangling ?/# producing an unusable .git clone URL
  • Fixed blocking Stop hooks causing the turn after a block to lose the model's reasoning from that turn and, on some models, miss the prompt cache
  • Fixed remote (claude.ai) sessions taking 60 seconds to start a turn after a browser-hosted MCP server's page had gone away
  • Fixed worktree-isolated sessions refusing common Bash loops, xargs pipelines and launcher-wrapped commands that cannot reach the main checkout
  • Improved terminal resize and first-render performance for long responses by reusing text measurements
  • Improved /workflows agent detail: JSON outcomes are pretty-printed with syntax colors and real line breaks, and long outcomes fold behind an expand toggle
  • Improved headless/SDK session start: the first turn begins up to 50 ms sooner when MCP servers finish connecting
  • Improved /install-github-app to explain it is GitHub-only and point to the GitLab CI/CD docs when run inside a GitLab repository
  • Improved nested background subagent results to be saved in the parent subagent's transcript, so resumed subagents keep them and shared transcripts show the delivery
  • Changed allowedMcpServers to govern only servers users add: a literal managed-mcp.json server your allowlist used to filter out now loads on upgrade; use deniedMcpServers to keep it off
  • [VSCode] Added an Active quick filter and a status filter menu (Needs input, Working, Completed) to the session list sidebar
  • Fixed remote and scheduled sessions doing nothing after a connector-tool permission prompt was approved while the session was paused
