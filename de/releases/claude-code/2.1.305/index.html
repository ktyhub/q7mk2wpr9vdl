Claude-Code v2.1.305

Was hat sich geändert?

– sandbox.allowNestedUserNamespaces hinzugefügt, damit Sandbox-Befehle unter Linux Benutzernamensräume erstellen können (Chromium, rootless podman); Dadurch können sie den Dateischutz der Sandbox umgehen – CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS hinzugefügt, sodass der unbeaufsichtigte Wiederholungsmodus (CLAUDE_CODE_RETRY_WATCHDOG) ein Nutzungslimit erkennt, das vor dem Zurücksetzen aufgehoben wurde – Es wurde behoben, dass jede Anfrage bei Vertex, Bedrock und anderen Anbietern fehlschlug, wenn der Endpunkt oder ein Gateway die Tool-Suche ablehnte, und hinter Gateways, bei denen ToolSearch nicht zugelassen oder aus --tools ausgeschlossen wurde (eine 2.1.304-Regression): Claude Code versucht jetzt ohne die ToolSearch erneut – Behoben, dass die Einstellungen /effort und /autocompact nicht angewendet wurden, wenn sich der Modellname von einem modelOverrides-Wert durch Groß-/Kleinschreibung oder ein [1m]-Tag unterschied – Behoben, dass neue Arbeitsbäume in einem nackten Repository manchmal vom lokalen HEAD anstelle des Standardzweigs ausgingen und dass unveränderte Subagenten-Arbeitsbäume manchmal nicht bereinigt wurden – Fehler behoben, bei dem Bash-Befehle auf einer vollen Festplatte mit einem unformatierten ENOSPC-Dateipfad fehlschlugen: Der Fehler besagt nun, dass die Festplatte voll ist und nichts ausgeführt wurde – Problem behoben, bei dem ein MCP-Server, der von einer Cloud-Sitzung oder vom setMcpServers des SDK übergeben wurde, später in der Sitzung durch einen gleichnamigen Server aus Ihren eigenen Einstellungen ersetzt wurde – Problem behoben, bei dem Claude das falsche Modell für die Arbeit eines Subagenten benannte, nachdem der Subagent zu einem Fallback-Modell gewechselt war

  • Behoben: Cloud-Sitzungen und Teamkollegen teilten Claude nicht mit, wann eine Komprimierung die ältesten Nachrichten aus ihrer Zusammenfassung weglassen musste, damit sie hineinpassten – Es wurden weitere Fälle behoben, in denen geplante Cowork-Cloud-Sitzungen fünf Minuten auf jeden Subagenten warteten, dessen WebFetch eine URL-Genehmigung benötigte, die niemand geben konnte – Problem behoben, bei dem der Workflow-Lebenslauf bereits abgeschlossene pipeline()- und parallel()-Agenten erneut ausführte, anstatt sie aus dem Journal der Ausführung zu bedienen – Problem behoben, bei dem Remote Control leere „(Sitzung)“-Einträge in /resume hinterließ, nachdem Gespräche mit /resume gewechselt wurden – Das Abschneiden von /usage-Reihen in schmalen Terminals wurde behoben – Problem behoben, bei dem Startwarnungen als Rohtext über dem Logo gedruckt wurden: Sie werden jetzt im Debug-Protokoll angezeigt, und Berechtigungsregeln, die nichts einschränken, werden als Warnzeilen unter dem Banner angezeigt
  • Korrigierter Screenreader-Modus: Suchfelder sagen jetzt „Suchen:“ statt eines Symbols, das VoiceOver als „Telefonrekorder“ liest, und hervorgehobener Eingabeaufforderungstext, wie z. B. Strg+R-Suchtreffer und „Ultrathink“, enthält keine Leerzeichen mehr in Wörtern – Selbstgehosteter Läufer: Es wurde ein Startskript behoben, das nur seine Standardausgabe mit dem Läufer oder Orchestrator teilt und mit Resource temporarily unavailable fehlschlägt, wenn TERM festgelegt ist (eine 2.1.300-Regression). – Selbstgehosteter Läufer: Fehler beim Repository-Zugriff seit 2.1.296 behoben, wenn ein Git-Anmeldeinformations-Helfer oder ein Askpass-Programm seine Einstellungen über GIT_CONFIG liest – Selbstgehosteter Runner: Problem behoben, bei dem der Orchestrator einen Spawn-Runner-Hook als Zeitüberschreitung meldete, wenn ein Runner, den er im Hintergrund startete, seine Ausgabe offen hielt
  • Verbesserter /usage: Jede Warnung ist jetzt ein einzeiliger Fix, der ihre Quelle benennt, und f wendet die Fixes an; Die gleichen Korrekturen erscheinen in VS Code und /doctor – Verbesserte MCP-Zustimmungsdialoge, sodass eine Eingabe, die für die Eingabeaufforderung gedacht ist, weniger wahrscheinlich als Akzeptieren gewertet wird
  • Der Image eines Mods wurde verbessert, um sein Bild in iTerm2 3.5 und später mit Vollbild-Rendering zu zeichnen, wobei nur der alt-Text angezeigt wurde
  • Fernsteuerung: Die Spawn-Modus-Meldungen wurden verbessert: Durch Drücken von w wird jetzt angezeigt, dass der neue Modus für den Ordner gespeichert ist, und bei einem späteren Start von claude remote-control, der den gespeicherten Modus verwendet, wird angezeigt, woher er stammt – allowedMcpServers wurde geändert, um die Filterung von managed-mcp.json-Standardservern, die ${VAR} verwenden, nur in env zu stoppen: Einer, den Sie in Ihrer Zulassungsliste ausgelassen haben, wird jetzt beim Upgrade geladen; Verwenden Sie deniedMcpServers, um es ausgeschaltet zu halten – Plugins, die Claude Desktop über den Pfad einbindet, wurden so geändert, dass sie ihren allowed-tools nicht mehr behalten, wenn die verwalteten Einstellungen Ihrer Organisation allowManagedPermissionRulesOnly festlegen – Die /artifacts-Löschbestätigung wurde dahingehend geändert, dass 1 oder Enter zum Behalten, 2 zum Löschen und Esc zum Abbrechen erforderlich sind. y und n antworten nicht mehr
  • Der angedockte Bereich eines Mods wurde so geändert, dass er innerhalb von 45 % der Breite des Terminals bleibt, einschließlich der Breite, die bei einem breiteren Terminal beibehalten wurde – [VSCode] Es wurde ein Spinner-Status „Start-Hooks werden ausgeführt“ mit einer Bildschirmleseankündigung hinzugefügt, während SessionStart- oder Setup-Hooks ausgeführt werden – [VSCode] Der Spinner hat „Komprimieren…“ abgeschnitten, wenn Ihre spinnerVerbs-Einstellung die integrierten Verben durch kurze ersetzt – [VSCode] Die Meldung, die angezeigt wird, wenn eine Sitzung nicht rechtzeitig startet und kein Hook ausgeführt wird, wurde geändert: Sie führt jetzt mit den Ausgabeprotokollen und listet die Ursachen auf, anstatt zuerst auf die Anmeldung und das Netzwerk zu verweisen – [Cloud-Sitzungen] Die Admin-Seite der Cloud-Umgebungen weigerte sich fälschlicherweise, eine vorhandene Umgebung mit dem Fehler „Installiert Pakete“ zu speichern – [Cloud-Sitzungen] Das Löschen einer selbst gehosteten Umgebung wurde verbessert, sodass im Dialogfeld und in den Fehlermeldungen angegeben wird, was den Löschvorgang blockiert und welche Auswirkungen er hat
  • [Claude Tag] Öffentliche Slack-Kanäle hinzugefügt. Claude ist dem Claude Tag-Administrator nicht beigetreten. Ortssuche hinzufügen, sodass Administratoren von dort aus einen einrichten können
  • [Claude Tag] Claude Tag-Zugriffspakete wurden korrigiert, sodass ein Repository, das zu einem anderen GitHub-Konto verschoben wurde, erneut hinzugefügt werden kann
  • [Claude Tag] Eine in einem Slack-DM-Thread eingerichtete Routine wurde behoben, die nicht mehr postete, nachdem eine andere Routine in diesem Thread die Konversation neu gestartet hatte; beide posten jetzt weiterhin dort
  • [Claude Tag] In einem Slack-Thread eingerichtete Routinen zur Erfolgsmeldung ohne Posting nach Ende der Konversation wurden korrigiert; Diese Läufe werden jetzt übersprungen und der Ersteller wird darüber informiert
  • [Claude Tag] Die Admin-Seiten von Claude Tag in großen Organisationen wurden verbessert, sodass Plugin-, Skill- und Bundle-Änderungen funktionieren, während die Kanalliste noch geladen wird – [Codeüberprüfung] Problem behoben, bei dem Codeüberprüfung manchmal nicht den neuesten Commit überprüfte, wenn während einer Überprüfung mehrere Pushs auf einer Pull-Anfrage landeten – [Codeüberprüfung] Die erneuten Überprüfungen der Codeüberprüfung wurden geändert, sodass sie nicht mehr mit LGTM geöffnet werden, während frühere Blockierungsbefunde noch offen sind

claude-code v2.1.305

What's changed

  • Added sandbox.allowNestedUserNamespaces so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman); this lets them get around the sandbox's file protections
  • Added CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS so unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG) notices a usage limit that was lifted before its reset
  • Fixed every request failing on Vertex, Bedrock and other providers when the endpoint or a gateway rejects tool search, and behind gateways with ToolSearch disallowed or left out of --tools (a 2.1.304 regression): Claude Code now retries without it
  • Fixed /effort and /autocompact settings not applying when the model name differed from a modelOverrides value by letter case or a [1m] tag
  • Fixed new worktrees in a bare repository sometimes starting from local HEAD instead of the default branch, and unchanged subagent worktrees sometimes not being cleaned up
  • Fixed Bash commands on a full disk failing with a raw ENOSPC file path: the error now says the disk is full and that nothing ran
  • Fixed an MCP server passed by a cloud session or by the SDK's setMcpServers being replaced later in the session by a same-named server from your own settings
  • Fixed Claude naming the wrong model for a subagent's work after the subagent switched to a fallback model
  • Fixed cloud sessions and teammates not telling Claude when a compaction had to leave the oldest messages out of its summary to fit
  • Fixed more cases of scheduled Cowork cloud sessions waiting five minutes for each subagent whose WebFetch needed a URL approval that nobody was there to give
  • Fixed Workflow resume re-running already-completed pipeline() and parallel() agents instead of serving them from the run's journal
  • Fixed Remote Control leaving empty "(session)" entries in /resume after switching conversations with /resume
  • Fixed /usage rows being cut off in narrow terminals
  • Fixed startup warnings printing as raw text above the logo: they now go to the debug log, and permission rules that restrict nothing show as warning rows under the banner
  • Fixed screen reader mode: search boxes now say "Search:" instead of a symbol VoiceOver read as "telephone recorder", and highlighted prompt text, such as Ctrl+R search matches and "ultrathink", no longer has spaces inside words
  • Self-hosted runner: Fixed a start script that shares only its stdout with the runner or orchestrator failing with Resource temporarily unavailable when TERM is set (a 2.1.300 regression)
  • Self-hosted runner: Fixed repository access failing since 2.1.296 when a git credential helper or askpass program reads its settings through GIT_CONFIG
  • Self-hosted runner: Fixed the orchestrator reporting a spawn-runner hook as timed out when a runner it started in the background kept its output open
  • Improved /usage: each warning is now a one-line fix that names its source, and f applies the fixes; the same fixes appear in VS Code and /doctor
  • Improved MCP consent dialogs so an Enter meant for the prompt is less likely to be taken as Accept
  • Improved a mod's Image to draw its picture in iTerm2 3.5 and later with fullscreen rendering, where it showed only its alt text
  • Remote Control: Improved the spawn-mode messages: pressing w now says the new mode is saved for the folder, and a later claude remote-control start that uses the saved mode says where it came from
  • Changed allowedMcpServers to stop filtering managed-mcp.json stdio servers that use ${VAR} only in env: one your allowlist left out now loads on upgrade; use deniedMcpServers to keep it off
  • Changed plugins that Claude Desktop mounts by path to no longer keep their allowed-tools when your organization's managed settings set allowManagedPermissionRulesOnly
  • Changed the /artifacts delete confirmation to take 1 or Enter to keep, 2 to delete, and Esc to cancel; y and n no longer answer it
  • Changed a mod's docked pane to stay within 45% of the terminal's width, including a width kept from a wider terminal
  • [VSCode] Added a "Running start-up hooks" spinner status, with a screen reader announcement, while SessionStart or Setup hooks run
  • [VSCode] Fixed the spinner cutting off "Compacting..." when your spinnerVerbs setting replaces the built-in verbs with short ones
  • [VSCode] Changed the message shown when a session does not start in time and no hook is running: it now leads with the output logs and lists causes instead of pointing to sign-in and network first
  • [Cloud sessions] Fixed the Cloud environments admin page wrongly refusing to save an existing environment with an "installs packages" error
  • [Cloud sessions] Improved deleting a self-hosted environment so the dialog and error messages say what blocks the delete and what it will affect
  • [Claude Tag] Added public Slack channels Claude hasn't joined to the Claude Tag admin Add place search, so admins can set one up from there
  • [Claude Tag] Fixed Claude Tag access bundles so a repository that moved to another GitHub account can be added again
  • [Claude Tag] Fixed a routine set up in a Slack DM thread no longer posting after another routine in that thread restarted the conversation; both now keep posting there
  • [Claude Tag] Fixed routines set up in a Slack thread reporting success without posting after the conversation ended; those runs are now skipped and the creator is told
  • [Claude Tag] Improved Claude Tag admin pages in large organizations so plugin, skill and bundle edits work while the channel list is still loading
  • [Code Review] Fixed Code Review sometimes not reviewing the newest commit when several pushes landed on a pull request during a review
  • [Code Review] Changed Code Review re-reviews so they no longer open with LGTM while earlier blocking findings are still open
