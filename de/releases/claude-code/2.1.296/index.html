Claude-Code v2.1.296

Was hat sich geändert?

  • Dem managed.policies[] des Claude-Apps-Gateways wurde ein code-Schlüssel hinzugefügt: dieselben Einstellungen wie cli, auch auf der Registerkarte „Code“ von Claude Desktop angewendet; neben desktop wird der Gateway-Modus von Claude Desktop aktiviert – autoCompactWindow zu den Subagenten-Frontmatter- und --agents-Definitionen hinzugefügt, sodass ein Subagent früher als das Fenster der Hauptkonversation automatisch komprimieren kann – CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL hinzugefügt, um jeden Workflow-Agenten auf einem Modell auszuführen, während andere Subagenten ihre behalten – Umgebungsvariable CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS hinzugefügt, um eine längere maximale Verzögerung für den Backoff festzulegen, wenn eine überlastete (529) Anfrage erneut versucht wird – In /plugin wurde ein Hinweis zu einem Plugin hinzugefügt, dessen Hooks weggelassen wurden, weil ein anderes aktiviertes Plugin denselben Namen hat – Dem Lesetool wurde eine allow_large-Option hinzugefügt, damit Claude eine Textdatei über die üblichen Größenbeschränkungen hinaus in einem Aufruf lesen kann, wenn die gesamte Datei benötigt wird und der Kontext Platz bietet
  • Die verwalteten PreToolUse-Hooks, die einen Werkzeugaufruf mit "continue": false verweigern, wurden behoben, und die verwalteten prompt-Hooks, die einen Werkzeugaufruf blockieren, verweigern den Aufruf, beenden aber die Runde nicht – Problem behoben, bei dem PostToolUse-Hooks in verwalteten Einstellungen updatedMCPToolOutput in einigen Sitzungen nicht anwendeten – Problem behoben, bei dem Headless-Sitzungen den .mcp.json- oder Plugin-MCP-Server eines Ordners starteten, der für diesen Ordner ausgeschaltet war, nachdem das Verzeichnis geändert oder Plugins neu geladen wurden – Ein Claude-Apps-Gateway, das allowedProviders bedient, wurde behoben, wobei "gateway" Laptops aussperrte, die dieses Gateway in den Benutzereinstellungen benennen – Es wurde behoben, dass eine gespeicherte Claude-Apps-Gateway-Anmeldung auf Computern ignoriert wurde, deren verwaltete Einstellungen forceLoginMethod auf gateway ohne forceLoginGatewayUrl festgelegt hatten (Regression in 2.1.295). – Problem behoben, bei dem --teleport eine leere Konversation öffnete, wenn der Sitzungsverlauf nicht gelesen werden konnte
  • Die Token-Zählungen für Haiku 5.5 und andere Modelle, die nur adaptives Denken nutzen, wurden korrigiert, was hinter einigen Gateways fehlschlug und an anderer Stelle mit Budget-Denken gezählt wurde – Behoben: Wiederaufgenommene Subagenten wurden darüber informiert, dass der Benutzer einen Tool-Aufruf abgelehnt hat, der durch das Herunterfahren der Sitzung unterbrochen wurde – Problem behoben, bei dem die Hook-Ausgabe geändert wurde, wenn sie Text enthielt, der einem Plugin-Hinweis-Tag ähnelte – Bei der geheimen Schwärzung in freigegebenen Transkripten und Debug-Protokollen fehlten einige Werte, die einem Schlüssel ohne Wert folgten, einschließlich JSON, das in eine Shell-Zeichenfolge geschrieben wurde – Es wurde eine verirrte 52;c;…-Escape-Sequenz behoben, die nach dem Kopieren in älteren VTE-basierten Terminals wie dem MATE-Terminal auf dem Bildschirm angezeigt wurde – Problem behoben, bei dem Toasts und Benachrichtigungen nicht angezeigt wurden, solange das /diff-Bedienfeld oder der Dialog geöffnet war
  • Esc oder ein Interrupt während eines UserPromptSubmit-Hooks oder des prompt.submit-Hooks eines Mods behoben, der Headless-Sitzungen beendete, die eingegebene Eingabeaufforderung löschte oder die ungeprüfte Eingabeaufforderung durchließ – Problem behoben, bei dem SessionStart-Hooks eines Plugins, das geladen wurde, nachdem eine Headless-Sitzung gestartet wurde, übersprungen wurden, wenn bereits ein anderes Plugin mit demselben Namen oder einer anderen Schreibweise davon ausgeführt wurde – Irreführende Fehler beim Drucken von claude self-hosted-runner bei Ablehnung der Registrierung behoben: Es wird jetzt die Organisationsadministratoreinstellung genannt oder es wird angegeben, dass ein neu gestarteter On-Demand-Läufer einen neuen Arbeitsauftrag benötigt – Problem behoben, bei dem Git-Abruf, -Pull und -Push einer selbstgehosteten Runner-Sitzung fehlschlugen, während eine andere Sitzung desselben Repositorys auf einem Runner mit --capacity über 1 gestartet wurde – Problem behoben, bei dem Workflow-Skripte Ergebnisse, Agentenoptionen und andere Werte, die tiefer als etwa 20.000 Ebenen verschachtelt waren, stillschweigend abgeschnitten haben und tief verschachtelte Ergebnisse große Aufgabenausgabedateien geschrieben haben – Die bereitgestellten $-Methoden eines Plugins wurden behoben, die im Arbeitsverzeichnis der Hauptsitzung statt im Arbeitsverzeichnis des aufrufenden Agenten ausgeführt wurden und die Runde ignorierten, die ihr aufrufender Hook ausführt
  • Behoben, dass $.agent.register über den Hook eines Mods erfolgreich war, der noch lief, nachdem der Mod neu geladen oder entfernt wurde; Der Anruf wird nun abgelehnt
  • $.http.fetch in Mods behoben, die eine HEAD-Anfrage ablehnten, wenn die Antwort einen Content-Length über dem 4-MiB-Body-Limit deklarierte – Behoben, dass claude plugin marketplace add, marketplace update und plugin install mit einem internen Fehler für einen Marktplatz namens constructor fehlschlugen; add lehnt solche Namen nun klar ab – Ein Plugin-Geheimnis namens constructor oder prototype wurde behoben, das beim nächsten Speichern der Plugin-Optionen gelöscht wurde – Problem behoben, bei dem Cloud-Sitzungen die Überprüfungen des automatischen Modus für Claude in Chrome-Aktionen übersprangen, die eine gespeicherte Berechtigung zulässt, wenn ihre Funktionsflags nicht geladen wurden – Problem behoben, bei dem CLAUDE_CODE_RESUME_INTERRUPTED_TURN eine abgeschlossene Runde nach einem Neustart erneut ausführte, wenn ein MCP-Tool-Ergebnis diese Runde beendet hatte – Fehler bei der Bash-Berechtigungsprüfung bei der automatischen Genehmigung einiger Befehle behoben, die die Shell-Variable BASH_ARGV0 zuweisen und dann verwenden; diese bedürfen nun der Genehmigung – Problem behoben, bei dem Edit und NotebookEdit jedes Nicht-ASCII-Zeichen in Dateien ersetzen, die kein gültiges UTF-8 sind (Windows-1252, Shift-JIS, GBK); Solche Änderungen werden jetzt abgelehnt – Es wurde eine Eingabeaufforderung behoben, die direkt nach der zweimaligen Ausführung von ← gesendet wurde, einmal unsichtbar im Vordergrund, wenn der Hintergrunddienst langsam antwortete – Es wurde eine Eingabeaufforderung behoben, die gesendet wurde, während SessionStart-Hooks noch ausgeführt wurden und verschwand, als ← die Sitzung in den Hintergrund verschob. Es wird immer noch nicht gesendet, aber ↑ bringt es jetzt zurück – Problem behoben, bei dem die SessionStart-Hook-Ausgabe eines Plugins mit spätem Laden die neue Konversation nach /clear in Headless-Sitzungen erreichte – Problem behoben, bei dem PowerShell-Befehle Variablen nicht sahen, die das Schreiben in CLAUDE_ENV_FILE verknüpfen (wenn die Datei nur einfache Zuweisungen enthält) – Problem behoben, bei dem Claude Cloud-Sitzungen als nicht interaktiv bezeichnete und /mcp oder claude mcp vorschlug, wenn ein MCP-Server eine Authentifizierung benötigt – Problem behoben, bei dem /code-review in Cloud-Sitzungen, dem Agent SDK und IDE-Integrationen auf einem rohen JSON-Array endete; Die Ergebnisse werden nun als nummerierte Liste gedruckt
  • Problem behoben, bei dem der automatische Modus gelegentlich eine Aktualisierung Ihres eigenen Artefakts verweigerte, mit der Meldung, dass sich die Freigabe geändert habe, obwohl dies nicht der Fall war – Problem behoben, bei dem Skills, die von claude.ai synchronisiert wurden, ihre Installation nie beendeten und bei jeder Synchronisierung erneut heruntergeladen wurden, wenn mehrere Sitzungen ein Konfigurationsverzeichnis gemeinsam nutzen – Ein von claude.ai synchronisiertes Plugin wurde behoben, das deaktiviert wurde, wenn die deklarierte Marktplatzabhängigkeit auch von claude.ai synchronisiert wurde – Es wurde ein Startproblem unter macOS behoben, das auftrat, wenn Plugin-Pfade, die von einem Linux-Rechner kopiert wurden, unter /home zeigten – Problem behoben, durch das das Workflow-Tool Skriptdateien mit CRLF-Zeilenenden ablehnte, wie z. B. unter Windows ausgecheckte Dateien
  • OpenTelemetry tool_result-Ereignisse behoben, bei denen git_commit_id nach git commit -q oder git -C <dir> commit fehlte – Problem behoben, bei dem CLAUDE_CODE_TRANSCRIPT_LOCAL_GC eine Nachricht aus dem gespeicherten Transkript entfernte, wenn der Text ein Unicode-Zeilen- oder Absatztrennzeichen (U+2028, U+2029) enthielt. – Problem behoben, bei dem claude purge eine Eingabeaufforderung in der Verlaufsdatei hinterließ, wenn der Text ein Unicode-Zeilen- oder Absatztrennzeichen (U+2028, U+2029) enthielt.
  • Windows: Behoben: PowerShell-Befehle, die länger als etwa 1 KB sind und immer nach einer Berechtigung fragen, wurden behoben. Daher gelten Zulassungsregeln und Leseschutzerkennung jetzt bis zu 32 KB
  • Windows: Problem behoben, bei dem stdio MCP-Server beim Herunterfahren zwangsweise beendet wurden; stdin wird jetzt zuerst geschlossen und der Prozessbaum wird nur dann beendet, wenn der Server nach 300 ms noch läuft
  • Windows: claude plugin install-Fehler für GitHub owner/repo-Plugin-Quellen auf Maschinen ohne GitHub-SSH-Schlüssel behoben; Der Klon wird nun über HTTPS erneut versucht
  • Windows: Problem behoben, bei dem rm -rf /c/Users/<name> in Git Bash nicht im Bypass-Berechtigungsmodus nachfragte
  • Verbesserter Vollbildmodus: Der Link unter dem Mauszeiger ist jetzt unterstrichen, um anzuzeigen, dass er geöffnet werden kann – Verbesserte Reaktionsfähigkeit beim Umschalten des Transkripts (Strg+O) in codeintensiven Konversationen durch Zwischenspeichern syntaxhervorgehobener Codeblöcke
  • Verbesserte Registerkarte „Code“ von Claude Desktop hinter einem Claude-Apps-Gateway: Wenn eine Sitzung nicht gestartet werden kann, auch auf einem Computer, der nicht für die code-Einstellungen des Gateways eingerichtet ist, wird der Grund als Antwort angezeigt – Die Fehler für eine abgelehnte Cloud-Sitzung wurden verbessert: Sie sagen jetzt, warum die Richtlinie Ihrer Organisation nicht geladen werden konnte, und benennen einen API-Schlüssel oder Authentifizierungstoken, der Ihre claude.ai-Anmeldung überschreibt – Die --debug-Ausgabe wurde verbessert, um nicht erkannte Frontmatter-Felder in benutzerdefinierten Agent-Dateien zu benennen, mit einem Hinweis auf wahrscheinliche Tippfehler
  • Verbesserter Auto-Modus: Ein Werkzeugaufruf, der nicht ausgeführt wurde, weil die Prüfung im Auto-Modus keine brauchbare Antwort lieferte, wird jetzt als dunkle Zeile „Nicht ausgeführt“ anstelle eines roten Fehlers angezeigt
  • Verbesserte --debug-Ausgabe für Hooks: Befehls-Hooks bei Tool-Aufrufen, Eingabeaufforderungen, SessionStart und Stop protokollieren jetzt ihren Befehl, ihr Plugin, ihr Ergebnis und ihre Dauer, wenn sie beendet sind, sodass ein langsamer Hook erkennbar ist
  • Verbessertes CLAUDE_CODE_TRANSCRIPT_LOCAL_GC: Eine große Transkriptdatei wird nicht mehr neu geschrieben, wenn dadurch weniger als 10 % davon freigegeben würden
  • /cost, die Statuszeile, --max-budget-usd und die Kostenzahlen des SDK aktualisiert, um den Preis für Sonnet 5.5-Cache-Lesevorgänge bei 75 $ ZZPH pro Million Token festzulegen (vorher 76 $ ZZPH) – Die gebündelte Dataviz-Fähigkeit wurde aktualisiert: helleres Violett für die siebte Serie im hellen Modus, weicherer Primärtext im dunklen Modus und kompakte Y-Achsenbeschriftungen wie 1K – Die Standardbeschränkung für MCP-Toolbeschreibungen, die im Voraus gesendet werden, und für MCP-Serveranweisungen wurde von 2.048 auf 4.096 Zeichen geändert
  • ← geändert: Eine Drehung oder ein !-Befehl, der gestartet wird, während die Sitzung in den Hintergrund geht, wird jetzt gestoppt, anstatt außer Sichtweite zu enden – [VSCode] Das Fehlen von claudeCode.spinnerVerbs in den Einstellungen der Erweiterung wurde behoben, sodass „settings.json“ es nun vervollständigt und validiert. Ein fehlerhafter Wert führt nicht mehr zu Störungen im Chat-Panel
  • [VSCode] Claude in Chrome so geändert, dass er in jeder Sitzung vor Browseraktionen fragt, einschließlich einer Sitzung, die mit @browser verbunden ist, wie es das Terminal tut; Wenn Sie eine Site für die Sitzung zulassen, werden wiederholte Anfragen gestoppt – [VSCode] Chat-Links, die als vollständiger Windows-Pfad geschrieben wurden, wie C:\repo\file.ts oder file:///C:/repo/file.ts, wurden korrigiert und öffneten die Datei nicht unter Windows – [VSCode] Problem behoben, bei dem die Arbeitsanzeige weiterhin animiert, wenn die reduzierte Bewegung in Ihrem Betriebssystem, in VS Code oder mit der prefersReducedMotion-Einstellung aktiviert ist – [VSCode] Die Meldung, dass die Cache-Uhr warm angezeigt wurde, nachdem das Panel verspätete Meldungen empfangen hatte, z. B. nachdem die Anzeige ausgeschaltet oder die Verbindung zu einem Remote-Fenster wiederhergestellt wurde, wurde behoben
  • [Cloud-Sitzungen] Den Sitzungs- und Läuferlisten auf der Registerkarte „Aktivität“ einer selbst gehosteten Umgebung in den Administratoreinstellungen wurde ein Statusfilter hinzugefügt. Sie können mehrere Status gleichzeitig auswählen
  • [Cloud-Sitzungen] Problem behoben, bei dem jede Cloud-Sitzung darauf wartete, dass ein selbst gehosteter Läufer dieselbe Warteschlangenposition anzeigte; Jeder zeigt nun an, wie viele Sitzungen vor ihm liegen
  • [Cloud-Sitzungen] Es wurde behoben, dass eine Nachricht, die Sie gesendet haben, während Claude noch in einer Cloud-Sitzung antwortet, über die Antwort hinausgesprungen ist, wenn diese beendet ist; es bleibt jetzt darunter, auch nach einem Neuladen
  • [Claude Tag] Claude in Slack wurde geändert, um die Fußzeile mit dem Sitzungslink, dem Modell und den Kosten nur bei der neuesten Antwort in einem Thread anzuzeigen; die Antwort, bevor die Fußzeile gelöscht wird
  • [Claude Tag] Korrigiert wurden Links zu URLs, die Klammern enthielten, die in einigen von Claudes Slack-Antworten und Aufgabenchecklisten unterbrochen wurden, wodurch Text in losen Klammern angezeigt wurde und die falsche Seite geöffnet wurde
  • [Claude Tag] Problem behoben, bei dem Claudes Slack-Antworten Farbfelder neben Codes zeigten, die nur wie Hex-Farben aussahen, wie etwa sechsstellige Pull-Request-Nummern
  • [Claude Tag] Das Erstellen, Bearbeiten und Löschen von Arbeitsbereichs- und Kanalspeicherdateien wurde auf der Registerkarte „Speicher“ der Aktivitätsseite für Mitglieder mit der Claude Tag-Administratorberechtigung hinzugefügt
  • [Claude Tag] Die Plugin-Bestätigungskarte, die Claude in einem Slack-Kanal postet, hat die ID eines Plugins anstelle seines Namens angezeigt
  • [Claude Tag] Problem behoben, bei dem Claude in Slack eine Karte gepostet hat, um ein Plugin zu entfernen, das in den eigenen Einstellungen des Kanals nicht enthalten ist; Stattdessen wird nun erklärt, woher das Plugin kommt
  • [Claude Tag] Problem behoben, bei dem Claude in Slack manchmal seine Antwort verlor, wenn eine Sitzung in einer selbst gehosteten Umgebung während einer Aufgabe zu einem neuen Läufer wechselte
  • [Codeüberprüfung] Problem behoben, bei dem die Codeüberprüfung bei einer Pull-Anfrage manchmal „in Bearbeitung“ blieb, nachdem die Überprüfung abgeschlossen war; es zeigt nun das Ergebnis der Überprüfung an

claude-code v2.1.296

What's changed

  • Added a code key to the Claude apps gateway's managed.policies[]: the same settings as cli, also applied in Claude Desktop's Code tab; beside desktop, it turns on Claude Desktop's gateway mode
  • Added autoCompactWindow to subagent frontmatter and --agents definitions, so a subagent can auto-compact earlier than the main conversation's window
  • Added CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL to run every workflow agent on one model while other subagents keep theirs
  • Added CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS environment variable to set a longer maximum delay for the backoff when retrying an overloaded (529) request
  • Added a note in /plugin on a plugin whose hooks are left out because another enabled plugin has the same name
  • Added an allow_large option to the Read tool so Claude can read a text file past the usual size limits in one call when it needs the whole file and the context has room
  • Fixed managed-settings PreToolUse hooks that deny a tool call with "continue": false, and managed prompt hooks that block one, refusing the call but not ending the turn
  • Fixed PostToolUse hooks in managed settings not applying updatedMCPToolOutput in some sessions
  • Fixed headless sessions starting a folder's .mcp.json or plugin MCP server that was switched off for that folder, after changing directory or reloading plugins
  • Fixed a Claude apps gateway that serves allowedProviders with "gateway" locking out laptops that name that gateway in user settings
  • Fixed a saved Claude apps gateway sign-in being ignored on machines whose managed settings set forceLoginMethod to gateway with no forceLoginGatewayUrl (regression in 2.1.295)
  • Fixed --teleport opening an empty conversation when the session's history could not be read
  • Fixed token counts for Haiku 5.5 and other models that take only adaptive thinking, which failed behind some gateways and were counted with budget thinking elsewhere
  • Fixed resumed subagents being told that the user rejected a tool call that a session shutdown had interrupted
  • Fixed hook output being altered when it contained text resembling a plugin hint tag
  • Fixed secret redaction in shared transcripts and debug logs missing some values that follow a key with no value, including in JSON written inside a shell string
  • Fixed a stray 52;c;… escape sequence printed on screen after copying in older VTE-based terminals such as MATE Terminal
  • Fixed toasts and notifications waiting unseen for as long as the /diff panel or dialog was open
  • Fixed Esc or an interrupt during a UserPromptSubmit hook or a mod's prompt.submit hook ending headless sessions, clearing the typed prompt, or letting the unchecked prompt through
  • Fixed SessionStart hooks of a plugin loaded after a headless session starts being skipped when a different plugin with the same name, or another spelling of it, had already run
  • Fixed claude self-hosted-runner printing misleading errors when registration is refused: it now names the org admin setting, or says a restarted on-demand runner needs a fresh work order
  • Fixed a self-hosted runner session's git fetch, pull and push failing while another session of the same repository starts on a runner with --capacity above 1
  • Fixed workflow scripts silently truncating results, agent options and other values nested deeper than about 20,000 levels, and deeply nested results writing huge task output files
  • Fixed a plugin's served $ methods running in the main session's working directory instead of the calling agent's, and ignoring the turn their calling hook holds
  • Fixed $.agent.register succeeding from a mod's hook that was still running after the mod was reloaded or removed; the call is now refused
  • Fixed $.http.fetch in mods refusing a HEAD request when the response declares a Content-Length over the 4 MiB body limit
  • Fixed claude plugin marketplace add, marketplace update and plugin install failing with an internal error for a marketplace named like constructor; add now refuses such names clearly
  • Fixed a plugin secret named constructor or prototype being deleted by the next save of that plugin's options
  • Fixed cloud sessions skipping auto mode's checks on Claude in Chrome actions that a saved permission allows when their feature flags had not loaded
  • Fixed CLAUDE_CODE_RESUME_INTERRUPTED_TURN re-running a finished turn after a restart when an MCP tool result had ended that turn
  • Fixed Bash permission checks auto-approving some commands that assign the BASH_ARGV0 shell variable and then use it; these now prompt for approval
  • Fixed Edit and NotebookEdit replacing every non-ASCII character in files that are not valid UTF-8 (Windows-1252, Shift-JIS, GBK); such edits are now refused
  • Fixed a prompt sent just after ← being run twice, once unseen in the foreground, when the background service was slow to answer
  • Fixed a prompt sent while SessionStart hooks were still running vanishing when ← moved the session to the background; it is still not sent, but ↑ now brings it back
  • Fixed a late-loading plugin's SessionStart hook output reaching the new conversation after /clear in headless sessions
  • Fixed PowerShell commands not seeing variables that hooks write to CLAUDE_ENV_FILE (when the file holds only plain assignments)
  • Fixed Claude calling cloud sessions non-interactive and suggesting /mcp or claude mcp when an MCP server needs authentication
  • Fixed /code-review ending on a raw JSON array in cloud sessions, the Agent SDK and IDE integrations; the findings now print as a numbered list
  • Fixed auto mode occasionally refusing one update to your own artifact, saying its sharing had changed when it had not
  • Fixed skills synced from claude.ai never finishing their install, and being downloaded again at every sync, when several sessions share a config directory
  • Fixed a plugin synced from claude.ai being disabled when the marketplace dependency it declares was also synced from claude.ai
  • Fixed a startup hang on macOS when plugin paths copied from a Linux machine pointed under /home
  • Fixed the Workflow tool refusing script files with CRLF line endings, such as files checked out on Windows
  • Fixed OpenTelemetry tool_result events missing git_commit_id after git commit -q or git -C <dir> commit
  • Fixed CLAUDE_CODE_TRANSCRIPT_LOCAL_GC dropping a message from the saved transcript when its text held a Unicode line or paragraph separator (U+2028, U+2029)
  • Fixed claude purge leaving a prompt in the history file when its text held a Unicode line or paragraph separator (U+2028, U+2029)
  • Windows: Fixed PowerShell commands longer than about 1 KB always asking for permission, so allow rules and read-only detection now apply up to 32 KB
  • Windows: Fixed stdio MCP servers being force-killed at shutdown; stdin now closes first and the process tree is killed only if the server is still running after 300 ms
  • Windows: Fixed claude plugin install failing for GitHub owner/repo plugin sources on machines with no GitHub SSH key; the clone is now retried over HTTPS
  • Windows: Fixed rm -rf /c/Users/<name> in Git Bash not asking in bypass permissions mode
  • Improved fullscreen mode: the link under the mouse pointer is now underlined to show it can be opened
  • Improved transcript toggle (ctrl+o) responsiveness in code-heavy conversations by caching syntax-highlighted code blocks
  • Improved Claude Desktop's Code tab behind a Claude apps gateway: when a session can't start, including on a machine not set up for the gateway's code settings, the reason shows as a reply
  • Improved the errors for a refused cloud session: they now say why your organization's policy couldn't be loaded, and name an API key or auth token that overrides your claude.ai login
  • Improved --debug output to name unrecognized frontmatter fields in custom agent files, with a hint for likely typos
  • Improved auto mode: a tool call that wasn't run because auto mode's check had no usable answer now shows as a dim "Not run" row instead of a red error
  • Improved --debug output for hooks: command hooks on tool calls, prompts, SessionStart and Stop now log their command, plugin, outcome and duration when they finish, so a slow hook is identifiable
  • Improved CLAUDE_CODE_TRANSCRIPT_LOCAL_GC: a large transcript file is no longer rewritten when that would free under 10% of it
  • Updated /cost, the status line, --max-budget-usd and the SDK's cost figures to price Sonnet 5.5 cache reads at $0.10 per million tokens (was $0.20)
  • Updated the bundled dataviz skill: lighter violet for the seventh series in light mode, softer primary text in dark mode, and compact y-axis labels like 1K
  • Changed the default limit on MCP tool descriptions sent up front and on MCP server instructions from 2,048 to 4,096 characters
  • Changed ←: a turn or ! command started while the session moves to the background is now stopped instead of finishing out of sight
  • [VSCode] Fixed claudeCode.spinnerVerbs missing from the extension's settings, so settings.json now completes and validates it; a malformed value no longer breaks the chat panel
  • [VSCode] Changed Claude in Chrome to ask before browser actions in every session, including one connected with @browser, as the terminal does; allowing a site for the session stops repeat asks
  • [VSCode] Fixed chat links written as a full Windows path, such as C:\repo\file.ts or file:///C:/repo/file.ts, not opening the file on Windows
  • [VSCode] Fixed the working indicator still animating when reduced motion is turned on in your OS, in VS Code, or with the prefersReducedMotion setting
  • [VSCode] Fixed the prompt cache clock reading warm after the panel caught up on messages late, such as after the display was off or a remote window reconnected
  • [Cloud sessions] Added a status filter to the Sessions and Runners lists on a self-hosted environment's Activity tab in admin settings; you can pick several statuses at once
  • [Cloud sessions] Fixed every cloud session waiting for a self-hosted runner showing the same queue position; each now shows how many sessions are ahead of it
  • [Cloud sessions] Fixed a message you send while Claude is still replying in a cloud session jumping above that reply when it finishes; it now stays below it, including after a reload
  • [Claude Tag] Changed Claude in Slack to show the footer with the session link, model and cost only on its newest reply in a thread; the reply before it drops the footer
  • [Claude Tag] Fixed links to URLs that contain parentheses breaking in some of Claude's Slack replies and task checklists, which showed stray bracket text and opened the wrong page
  • [Claude Tag] Fixed Claude's Slack replies drawing color swatches beside codes that only look like hex colors, such as six-digit pull request numbers
  • [Claude Tag] Added creating, editing and deleting workspace and channel memory files on the Activity page's Memory tab for members with the Claude Tag Admin permission
  • [Claude Tag] Fixed the plugin confirmation card Claude posts in a Slack channel showing a plugin's ID instead of its name
  • [Claude Tag] Fixed Claude in Slack posting a card to remove a plugin the channel's own settings don't include; it now explains where the plugin comes from instead
  • [Claude Tag] Fixed Claude in Slack sometimes losing its reply when a session in a self-hosted environment moved to a new runner partway through a task
  • [Code Review] Fixed the Code Review check sometimes staying "in progress" on a pull request after the review finished; it now shows the review's result
