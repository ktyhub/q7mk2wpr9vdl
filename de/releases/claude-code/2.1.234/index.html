claude-code v2.1.234

Patch Veröffentlicht17. Aug. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.234

Was hat sich geändert?

– Die optionale Umgebungsvariable CLAUDE_CODE_PROJECT_DIR_NAME wurde hinzugefügt: Hosts, die jeder Sitzung ein eigenes Konfigurationsverzeichnis zuweisen, können einen Kurznamen für das Transkriptverzeichnis pro Projekt wählen – Die Tastenkombinationsaktion selection:clear wurde hinzugefügt, sodass eine Taste zum Löschen einer In-App-Textauswahl gebunden werden kann. Funktioniert auch in der Agentenansicht – Der Fußzeile und der Statuszeile wurde ein GitLab-Merge-Request-Badge hinzugefügt: Repos mit einer GitLab-Fernbedienung und einem authentifizierten Glab CLI zeigen MR !N mit den Status „Entwurf/Ausstehend/Grün“.

  • Claude Code setzt Ihre Sitzung jetzt automatisch fort, wenn ein claude.ai-Nutzungslimit zurückgesetzt wird; schalten Sie es in /config aus („Automatisch bei Nutzungslimit fortfahren“)
  • Claude wird nun angewiesen, die E-Mail-Adresse Ihres Kontos nur zu Ihrer Identifizierung zu verwenden und diese nicht an unabhängige Dienste zu senden, es sei denn, Sie fragen danach
  • Sicherheit: Remote-Dateilesevorgänge, Sitzungswiederherstellung, CLAUDE.md-Includes, Workflow-Skripte und Datei-Uploads lehnen jetzt Windows NT-Namespace-Pfade (\??\) ab, wodurch die verbleibenden Dateizugriffe vor der Genehmigung gegen den NTLM-Anmeldeinformationsleck-Vektor geschützt werden – Problem behoben, bei dem der automatische Modus in sehr langen Sitzungen den Netzwerkzugriff von Sandbox-Befehlen wiederholt erneut überprüfte und verweigerte, nachdem die Konversation komprimiert wurde – Behoben, dass sitzungsbezogene Berechtigungsantworten (einschließlich Verweigerungen) gelöscht wurden, wenn auf Berechtigungsaufforderungen des Subagenten-Tools im Hintergrund geantwortet wurde – Es wurde ein Absturz behoben, wenn eine API-Antwort auf dem Nicht-Streaming-Fallback-Pfad (normalerweise über Gateways von Drittanbietern) einen Denkblock enthielt, dem sein Denkfeld fehlte, oder einen Textblock, dem sein Textfeld fehlte – Problem behoben, bei dem das Markdown-Rendering für einige Nachrichten, die ungewöhnliche Unicode-Sequenzen enthielten, extrem langsam wurde – Problem behoben, bei dem SendMessage einen von ListAgents kopierten Empfänger ablehnte, wenn der Sitzungsname die 200-Zeichen-Grenze überschreitet oder viele Emojis enthält – Die Repository-Erkennung hat den Host von Git-Remotes mit ungewöhnlichen Benutzerinformationen falsch gelesen, was zu Links und Repo-spezifischem Verhalten für den falschen Host geführt hat – Problem behoben, bei dem die MCP-Diagnose aufgelöste Geheimnisse druckte: Bereichskonfliktwarnungen zeigen jetzt das konfigurierte ${VAR}-Formular an, und Details zu Verbindungsfehlern zeigen nur den Serverursprung an – Problem behoben, bei dem strictKnownMarketplaces-Zulassungslisten Git-Marktplatzquellen im SCP-Stil akzeptierten, deren Host sich von dem unterscheidet, zu dem Git tatsächlich eine Verbindung herstellen würde – Problem behoben, bei dem modaler Text wie die OAuth-URL /login Zeichen verlor, wenn er im Vollbildmodus kopiert wurde – Es wurde eine horizontale Linie --- im gerenderten Markdown behoben, die in die Zeile danach verlief
  • Aufeinanderfolgende Shell-Befehle wurden behoben, die sich in mehrere „Ran 1 Shell-Befehl“-Zeilen aufteilten, wenn Aufgaben-/Aufgabenaktualisierungen zwischen ihnen verschachtelt waren – Problem behoben, bei dem Dialoge wie „/permissions“, die geöffnet wurden, während ein !-Shell-Befehl ausgeführt wurde, nach Abschluss des Befehls geschlossen wurden – Ein in der Warteschlange befindlicher !-Shell-Befehl wurde behoben, der als Klartext an das Modell gesendet wurde, nachdem zum Bearbeiten der in der Warteschlange befindlichen Eingabe der Aufwärtspfeil gedrückt wurde – Behoben: Nachrichten in der Warteschlange tauchten erneut im Eingabeaufforderungsverlauf auf, während sie sich noch in der Warteschlange befanden. Esc beim Auswählen einer Nachricht in der Warteschlange unterbricht den Zug nicht mehr und der !-Modus bleibt nach einer Übermittlung mitten im Zug nicht mehr hängen
  • Das Akzeptieren der Meldung „Neuen Vollbild-Renderer ausprobieren?“ wurde behoben. Eingabeaufforderung zum Neustarten der Sitzung ohne Berechtigungsmodus (z. B. --dangerously-skip-permissions), Tool-Zulassungs-/Verweigerungsregeln, Modell oder Aufwandsflags – Problem behoben, bei dem /tui beim Neustart die Startregeln --allowed-tools/--disallowed-tools fallen ließ; Es ist nun erforderlich, zu wechseln, mit der Begründung, dass ein Neustart nicht übertragen werden kann, wenn die Sitzung Einschränkungen aufweist – Problem behoben, bei dem trust-Eingabeaufforderungen die Repository-weite Bereichswarnung ausließen, wenn das Verzeichnis zum ersten Mal gesehen wurde, bevor das Repository dort existierte – Es wurde ein Fall behoben, bei dem ein IDE-Diff-Tab, der während einer erneuten Berechtigungsaufforderung geschlossen wurde, die neue Aufforderung mit der vorherigen Eingabe beantworten konnte
  • Behoben: Dateien, die während von Claude Code Desktop oder VS Code gehosteten Fernsteuerungssitzungen an den Benutzer gesendet wurden, werden jetzt hochgeladen, sodass sie auf dem Telefon und im Internet geöffnet werden, anstatt eine leere Karte anzuzeigen
  • Behoben: Nach /login, während CLAUDE_CODE_OAUTH_TOKEN gesetzt ist, dringt die Erinnerung an veraltete Token nicht mehr in Claudes automatisch wieder aufgenommenen Zug ein – sie erscheint jetzt nur noch für Sie
  • Behoben: Berechtigungsvorschauen werden jetzt nur an Kanalserver weitergeleitet, die vom eingehenden trust-Gate zugelassen sind, und die explizite Abmeldung der Berechtigungsfunktion eines Servers wird berücksichtigt
  • Behoben: Durch die Anmeldeinformationsmaskierung in der Vorschau weitergeleiteter Berechtigungen können Befehle, Pfade oder Ziele nicht mehr vor dem Genehmiger verborgen werden. Übergroße Private-Key-Blöcke werden jetzt mit voller Schwärzung geschwärzt
  • Behoben: Anbieter-API-Tokens, die bei Berechtigungsvorschauen maskiert werden, werden jetzt auch dann maskiert, wenn ihnen direkt Shell-Trennzeichen folgen – Problem behoben, bei dem sitzungsübergreifende Claude Desktop-Nachrichten von der Empfängersitzung stillschweigend verworfen wurden, wenn sitzungsübergreifende Nachrichten als deaktiviert gelesen wurden, was dazu führte, dass die Abfrage des Absenders viele Minuten lang „nachdachte“.
  • Fernsteuerung: Wenn Sie diesen Computer bei einem anderen claude.ai-Konto oder einer anderen Organisation anmelden, wird die laufende Sitzung jetzt innerhalb von Sekunden beendet und der Grund dafür angegeben, anstatt Stunden später ein irreführendes HTTP 404 anzuzeigen
  • Fernsteuerungssitzungen, die über Claude Code Desktop oder VS Code gestartet wurden, halten Telefone und claude.ai/code jetzt über den Berechtigungsmodus der Sitzung (und claude.ai/code über das Modell) auf dem Laufenden, wenn sie sich ändern
  • Fernsteuerung: Auf einem Telefon oder auf claude.ai/code vorgenommene Aufwandsauswahlen gelten jetzt für Terminal- und Desktop-/VS-Code-gehostete Sitzungen, und die Sitzung veröffentlicht ihren Aufwandsgrad an verbundene clients
  • SendMessage und ListAgents sagen jetzt, wenn die Sitzungsliste Ihres Kontos zu lang war, um sie vollständig zu überprüfen, anstatt nicht gesehene Sitzungen als abwesend zu behandeln – Abgelaufene Anmeldeinformationen für das Anthropic-Profil weisen Sie jetzt auf /login hin, wenn ein claude.ai-Login Vorrang hätte
  • Das Transkript wurde verbessert: Ihre eigenen Eingabeaufforderungen rendern jetzt Markdown (hervorgehobene Codeblöcke, Inline-Code, Listen) auf die gleiche Weise wie Antworten – Der Fehler „API hat eine leere oder fehlerhafte Antwort zurückgegeben“ wurde verbessert, um anzugeben, was zurückgegeben wurde (Inhaltstyp, Texttyp, Größe, Anforderungs-ID) und warum die ursprüngliche Streaming-Anfrage fehlgeschlagen ist
  • Verbesserte automatisch generierte Sitzungstitel, die als kurze, spezifische Namen gelesen werden können (z. B. „Fehler bei der Anmeldeschaltfläche“), statt als Sätze, die Ihre Anfrage wiederholen (z. B. „Korrigieren Sie die Anmeldeschaltfläche auf Mobilgeräten“). – Die Kontextkosten für das Laden des integrierten claude-api-Skills wurden von ca. 200.000+ Token auf ca. 25.000 reduziert, indem Referenzdokumente bei Bedarf geladen wurden – /permissions kann jetzt geöffnet werden, während Claude arbeitet – Regeländerungen gelten für den Rest der aktuellen Runde
  • /add-dir <path> kann jetzt verwendet werden, während Claude arbeitet; Die Dialoge /add-dir, /autocompact, /theme, /help, /config und /advisor werden während der Drehung in der Vollbild-TUI geöffnet – /goal löscht sich jetzt mit einer Benachrichtigung, wenn eine Runde aufgrund eines nicht behebbaren Fehlers (z. B. widerrufene Authentifizierung, erschöpftes Guthaben oder Kontextüberlauf) endet, anstatt aktiviert zu bleiben
  • /goal: Wenn Hintergrundaufgaben ein Ziel länger als 30 Minuten warten lassen, meldet sich Claude jetzt bei ihnen, anstatt auf unbestimmte Zeit zu warten (setzen Sie CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 auf „Opt-Out“). – claude setup-token weist jetzt unerwartete zusätzliche Argumente zurück, anstatt sie stillschweigend zu ignorieren
  • Esc im Vollbildmodus wurde so geändert, dass eine Maustextauswahl nicht mehr gelöscht wird: Sie unterbricht oder schließt wie üblich und die Auswahl bleibt hervorgehoben – Die redundante Zeile „Vom Auto-Modus-Klassifikator zugelassen“ wurde entfernt, die im Auto-Modus bei jedem Agent-Tool-Aufruf angezeigt wurde
  • Die Einstellung „Standard-Teamkameradenmodell“ wurde von /config entfernt; Agent-Team-Teammitglieder verwenden jetzt das Modell des Anführers, es sei denn, der Spawn benennt einen
  • Der Zähler für die verstrichene Zeit in der Kopfzeile des laufenden Werkzeugs wurde abgeblendet, sodass er nicht mehr mit den fett gedruckten Zählern konkurriert
  • Hintergrundaufgabenbenachrichtigungen, die zwischen Runden zugestellt werden, werden jetzt innerhalb von <system-reminder>-Tags an das Modell gesendet, passend zur Zustellung in der Mitte der Runde
  • Mantle: Überspringen Sie die Admin-Pin-Verfügbarkeitsprüfung beim Start, wenn bereits ein Hauptschleifenmodell ausgewählt ist
  • Windows: Der Startvorgang bleibt bei wiederholten Umbenennungsversuchen nicht mehr hängen, wenn ~/.claude.json schreibgeschützt ist

Englisches Original / English original

claude-code v2.1.234

What's changed

  • Added the optional CLAUDE_CODE_PROJECT_DIR_NAME environment variable: hosts that give each session its own config directory can choose a short name for the per-project transcript directory
  • Added the selection:clear keybinding action, so a key can be bound to clear an in-app text selection; also works in the agents view
  • Added a GitLab merge request badge to the footer and statusline: repos with a GitLab remote and an authenticated glab CLI show MR !N with draft/pending/green states
  • Claude Code now continues your session automatically when a claude.ai usage limit resets; turn it off in /config ("Continue automatically at usage limit")
  • Claude is now told to use your account email only to identify you, and not to send it to unrelated services unless you ask
  • Security: remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (\??\) paths, hardening the remaining pre-approval file accesses against the NTLM credential-leak vector
  • Fixed auto mode in very long sessions repeatedly re-checking and denying sandboxed commands' network access after the conversation had been compacted
  • Fixed session-scoped permission answers (including denies) being dropped when answering background subagent tool permission prompts
  • Fixed a crash when an API response on the non-streaming fallback path (typically via third-party gateways) contained a thinking block missing its thinking field or a text block missing its text field
  • Fixed markdown rendering becoming extremely slow for some messages containing unusual Unicode sequences
  • Fixed SendMessage rejecting a recipient copied from ListAgents when the session name is at the 200-character cap or emoji-heavy
  • Fixed repository detection mis-reading the host of git remotes with unusual userinfo, producing links and repo-specific behavior for the wrong host
  • Fixed MCP diagnostics printing resolved secrets: scope-conflict warnings now show the configured ${VAR} form, and connection-failure details show only the server origin
  • Fixed strictKnownMarketplaces allowlists accepting SCP-style git marketplace sources whose host differs from the one git would actually connect to
  • Fixed modal text such as the /login OAuth URL losing characters when copied in fullscreen
  • Fixed a --- horizontal rule in rendered markdown running into the line after it
  • Fixed consecutive shell commands splitting into multiple "Ran 1 shell command" rows when todo/task updates were interleaved between them
  • Fixed dialogs like /permissions opened while a ! shell command was running being dismissed when the command finished
  • Fixed a queued ! shell command being sent to the model as plain text after pressing up-arrow to edit the queued input
  • Fixed queued messages reappearing in the prompt history while still queued, Esc while selecting a queued message no longer interrupts the turn, and ! mode no longer sticks after a mid-turn submit
  • Fixed accepting the "Try the new fullscreen renderer?" prompt restarting the session without its permission mode (e.g. --dangerously-skip-permissions), tool allow/deny rules, model or effort flags
  • Fixed /tui dropping launch --allowed-tools/--disallowed-tools rules when it restarts; it now declines to switch, with the reason, when the session has restrictions a restart can't carry over
  • Fixed trust prompts omitting the repository-wide scope warning when the directory was first seen before the repository existed there
  • Fixed a case where an IDE diff tab closing during a permission re-prompt could answer the new prompt with the previous input
  • Fixed: files sent to the user during Remote Control sessions hosted by Claude Code Desktop or VS Code now upload, so they open on phone and web instead of showing an empty card
  • Fixed: after /login while CLAUDE_CODE_OAUTH_TOKEN is set, the stale-token reminder no longer leaks into Claude's automatically resumed turn — it now appears only to you
  • Fixed: permission previews now relay only to channel servers admitted by the inbound trust gate, and a server's explicit permission-capability opt-out is honored
  • Fixed: credential masking on relayed permission previews can no longer hide commands, paths, or destinations from the approver; oversized private-key blocks now redact under full-strength redaction
  • Fixed: provider API tokens that mask on permission previews now mask even when directly followed by shell delimiters
  • Fixed Claude Desktop inter-session messages being silently dropped by the recipient session when cross-session messaging read as disabled, which left the sender's query "thinking" for many minutes
  • Remote Control: signing this computer in to a different claude.ai account or organization now stops the running session within seconds and says why, instead of a misleading HTTP 404 hours later
  • Remote Control sessions started from Claude Code Desktop or VS Code now keep phones and claude.ai/code updated on the session's permission mode (and claude.ai/code on the model) as they change
  • Remote Control: effort picks made on a phone or on claude.ai/code now apply to terminal- and Desktop/VS Code-hosted sessions, and the session publishes its effort level to connected clients
  • SendMessage and ListAgents now say when your account's session list was too long to check completely, instead of treating unseen sessions as absent
  • Expired Anthropic profile credential now points you at /login when a claude.ai login would take precedence
  • Improved the transcript: your own prompts now render markdown (highlighted code blocks, inline code, lists) the same way replies do
  • Improved the "API returned an empty or malformed response" error to say what came back (content type, body kind, size, request ID) and why the original streaming request failed
  • Improved auto-generated session titles to read as short, specific names (e.g. "Login button bug") rather than sentences restating your request (e.g. "Fix the login button on mobile")
  • Reduced the context cost of loading the built-in claude-api skill from ~200k+ tokens to ~25k by loading reference docs on demand
  • /permissions can now be opened while Claude is working — rule changes apply to the rest of the current turn
  • /add-dir <path> can now be used while Claude is working; /add-dir, /autocompact, /theme, /help, /config and /advisor dialogs open mid-turn in the fullscreen TUI
  • /goal now clears itself with a notice when a turn dies on an unrecoverable error (e.g. revoked auth, an exhausted credit balance, or a context overflow) instead of staying armed
  • /goal: when background tasks keep a goal waiting for 30+ minutes, Claude now checks in on them instead of waiting indefinitely (set CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 to opt out)
  • claude setup-token now rejects unexpected extra arguments instead of silently ignoring them
  • Changed Esc in fullscreen mode to no longer clear a mouse text selection: it interrupts or dismisses as usual and the selection stays highlighted
  • Removed the redundant "Allowed by auto mode classifier" line that auto mode showed under every Agent tool call
  • Removed the "Default teammate model" setting from /config; agent-team teammates now use the leader's model unless the spawn names one
  • Dimmed the elapsed-time counter on the running tool header so it no longer competes with the bold counts
  • Background task notifications delivered between turns are now sent to the model inside <system-reminder> tags, matching mid-turn delivery
  • Mantle: skip the admin-pin availability probe at startup when a main-loop model is already picked
  • Windows: startup no longer stalls on repeated rename retries when ~/.claude.json is read-only
