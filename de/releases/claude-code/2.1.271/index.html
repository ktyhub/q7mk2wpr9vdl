Claude-Code v2.1.271

Was hat sich geändert?

– Schnellmodus in Claude Code Remote-Sitzungen (Cloud- und selbstgehostete Läufer) hinzugefügt: Die Schnellmodus-Einstellung des Hosts oder das in der Sitzung eingegebene /fast gilt, sofern Ihre Organisation dies zulässt

  • Mausunterstützung zum /config-Bedienfeld im Vollbildmodus hinzugefügt: Das Rad scrollt durch die Einstellungsliste, ein click auf den Wert einer Einstellung ändert ihn und die Zeile unter dem Zeiger wird hervorgehoben – claude self-hosted-runner --drain-marker-file <path> hinzugefügt: Wenn diese Datei an einem SIGTERM-Drain vorhanden ist, meldet der Runner seinen Ausgang als Host-Drain an den Server (nur Telemetrie). – Per Befehl allowed_domains zu Bash, PowerShell und Monitor im automatischen Modus mit Sandboxing hinzugefügt: Die Hosts, die ein Befehl benötigt, werden damit überprüft und nur für ihn geöffnet; andere Hosts werden abgelehnt – omitClaudeMd zum Agenten-Frontmatter und --agents JSON hinzugefügt, wodurch benutzerdefinierte und Plugin-Subagenten ohne Benutzer-, Projekt- und lokale CLAUDE.md-Dateien ausgeführt werden können; Verwaltete Richtliniendateien werden weiterhin geladen – --accept-command <sha256> zu claude plugin install und claude plugin update hinzugefügt, um genau den Befehl zu akzeptieren, der bei einem vorherigen --json-Lauf angezeigt wurde, anstelle von -y – Unterstützung für einen multiplier über 1, bis zu 10, in der verwalteten modelPricing-Einstellung und im Claude-Apps-Gateway-pricing-Block für markierte interne Rückbuchungsraten hinzugefügt – Es wurde ein Spinner-Tipp hinzugefügt, der Bedrock-, Vertex AI-, Foundry- und LLM-Gateway-Benutzer auf die Claude-Desktop-App verweist; Der Desktop-App-Tipp von claude.ai schlägt nun /desktop vor, das den Download der App anbietet – Es wurde behoben, dass eine zwischengespeicherte Organisationsrichtlinie nach dem Wechseln von Konten, Organisationen oder API-Schlüsseln wiederverwendet wurde und die Richtlinie erst bei der stündlichen Überprüfung aktualisiert wurde, wenn sich die Anmeldeinformationen mitten in der Sitzung änderten – Problem behoben, bei dem die Tool- und Befehlslisten nicht aktualisiert wurden, wenn die Organisationsrichtlinie nach dem Start vollständig geladen wurde oder sich mitten in der Sitzung änderte – Es wurde behoben, dass ein Unternehmens-managed-mcp.json, das nicht gelesen oder geparst werden konnte, ignoriert wurde: Es behält jetzt die exklusive MCP-Kontrolle (Benutzer-, Projekt- und Plugin-Server werden nicht geladen) und warnt beim Start – Problem behoben, bei dem Organisationsrichtlinien über über ANTHROPIC_UNIX_SOCKET festgelegte lokale Proxys von Drittanbietern abgerufen und von diesen abgelehnt wurden; Sie werden wieder wie andere benutzerdefinierte Gateways behandelt, auch für die Fernsteuerung – Behoben: Cloud-Sitzungen lehnten jeden Aufruf des Subagenten-Tools ab („updatedInput … fehlgeschlagene Schemavalidierung“), wenn nach dem Neustart des Workers der Sitzung eine Workflow- oder Agentengenehmigung angewendet wurde – Problem behoben, bei dem /fast off mit „Schnellmodus nicht verfügbar“ geantwortet hat, anstatt den Schnellmodus auszuschalten, wenn die Organisation den Schnellmodus deaktiviert hat – Behoben, dass Sitzungen, die mit CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK gestartet wurden, jede Runde erneut schnelle Anfragen sendeten, nachdem der API den Schnellmodus abgelehnt hatte; Die Ablehnung ist nun gültig und der Grund wird angezeigt – Problem behoben, bei dem der schnelle Modus unter CLAUDE_CODE_RETRY_WATCHDOG bei einem Nutzungs-Credits-Limit fehlschlug oder eine Überlastung mit hoher Geschwindigkeit erneut versuchte, anstatt auf die Standardgeschwindigkeit zurückzufallen – Behoben: Bei Bash-Berechtigungsprüfungen fehlt die Datei, die von fmt, column und ähnlichen Befehlen gelesen wird, wenn sie einer Option folgt, die der Prüfer nicht erkennt – Problem behoben, bei dem Bash-Berechtigungsprüfungen Dateien überspringen, auf die ein Platzhalter erweitert wird, wenn der Platzhalter im Muster oder Optionswert eines Befehls steht (z. B. grep -v dir/* file) – Die Überprüfung der Bash-Berechtigungen wurde korrigiert, sodass die Flags zur Deklaration von Shell-Variablen den ausgeführten Befehl nicht falsch darstellen können – Problem behoben, bei dem Bash-Befehle mit zwei Verzeichniswechseln, einer Subshell oder einer cd+git-Kette die Eingabeaufforderung unter permissions.blockReadsOutsideWorkingDirectories im Bypass- und Auto-Modus übersprangen – Ein veralteter .git/config.lock wurde behoben, der git checkout -b, git push -u und git config für den Rest einer Sitzung unterbrach, nachdem ein Sandbox-Befehl nicht gestartet werden konnte (Linux) – Behoben: Außerhalb der Sitzung vorgenommene Änderungen an Einstellungsdateien blieben auf macOS-Computern, deren Systemdateiereignisdienst ausgelastet ist, unbemerkt. Der Beobachter greift nun wieder auf die Umfrage zurück – Behoben: Wiederaufgenommene claude -p-Sitzungen, deren Tools alle von MCP-Servern stammen, scheiterten mit „Mindestens ein Tool muss defer_loading=false haben“ – Problem behoben, bei dem Turns mit „API hat eine leere oder fehlerhafte Antwort zurückgegeben“ fehlschlugen, wenn ein LLM-Gateway die Nicht-Streaming-Antwort als text/plain zurückgab – Anhaltend hohe CPU-Auslastung und wiederholte Tool-List-Anfragen behoben, wenn ein MCP-Server list_changed-Benachrichtigungen in einer engen Schleife sendet – Fehler bei der fehlerhaften Behandlung von client-Registrierungen durch MCP OAuth behoben: Durch die Verweigerung der Zustimmung wurde ein neuer Umleitungs-URI erzwungen, einer für einen anderen Umleitungs-URI wurde wiederverwendet und ein gleichzeitiger Schreibvorgang konnte einen gültigen löschen oder einen nicht übereinstimmenden beibehalten – Problem behoben, bei der die Werkzeugsuche keine Übereinstimmung zurückgab, wenn Claude ein MCP-Werkzeug anhand seines bloßen Namens anstelle seines vollständigen mcp__server__tool-Namens auswählt – Problem behoben, bei dem Strg+O den Abbruch ausstehender MCP-Server-Wiederverbindungen verursachte und das von der Fernbedienung gesendete /mcp fehlschlug, während die Transkriptansicht geöffnet war – Die Claude-in-Chrome-Eingabeaufforderung, die das Modell auffordert, Werkzeuge über ToolSearch zu laden, wenn ToolSearch nicht verfügbar ist, wurde behoben – Es wurde ein Problem behoben, bei dem sitzungsübergreifende Nachrichten, die von der Berechtigungsmodus-Richtlinie der empfangenden Sitzung zurückgehalten wurden, keine Spuren hinterließen: Headless-Absender erhalten jetzt eine Zustellungsbenachrichtigung und SendMessage-Ergebnisse deuten nicht mehr darauf hin, dass sie gelesen wurden – Problem behoben, bei dem Claude eine zweite Kopie eines Hintergrundbefehls (z. B. einer Überwachungsaufgabe oder eines Entwicklungsservers) startete, der nach der Komprimierung der Konversation noch ausgeführt wurde – Die /model-Warnung über den Verlust des Konversationscaches beim Zurückwechseln zu dem Modell, auf dem die Konversation tatsächlich lief, wurde behoben – Problem behoben, bei dem /reload-skills eine Fertigkeitszählung meldete, die nicht mit dem Slash-Menü nach /cd übereinstimmte
  • Problem behoben, bei dem /resume und /continue auf kurzen Terminals nur 1-2 Sitzungen im Vollbildmodus anzeigten
  • Behoben: /resume und /teleport behalten die Dateileseverfolgung der vorherigen Konversation bei, sodass Claude Dateien bearbeiten konnte, die die fortgesetzte Konversation nie gelesen hatte – Problem behoben, bei dem --resume das 1M-Kontextfenster ([1m]) fallen ließ, wenn die Modellfamilie der fortgesetzten Sitzung vom konfigurierten Standardmodell abweicht – Behoben, dass Artefakte, die mit /artifacts verbunden waren, nach --resume aus der Sitzung verschwanden – Problem behoben, bei dem Hintergrundsitzungen (claude --bg, claude agents) die von ihnen veröffentlichten Artefakte nicht auf an anderer Stelle vorgenommene Neuveröffentlichungen überwachten – Behoben: Benutzerdefinierte Agents, Slash-Befehle und Ausgabestile, die über den ersten hinausgingen und nicht von einem virtuellen Laufwerk geladen wurden, das Inode 0 meldet, z. claude-code v2.1.271

What's changed

  • Added fast mode in Claude Code Remote sessions (cloud and self-hosted runners): the host's fast-mode setting or /fast typed in the session applies where your organization allows it
  • Added mouse support to the /config panel in fullscreen mode: the wheel scrolls the settings list, a click on a setting's value changes it, and the row under the pointer is highlighted
  • Added claude self-hosted-runner --drain-marker-file <path>: when that file exists at a SIGTERM drain, the runner reports its exit to the server as a host drain (telemetry only)
  • Added per-command allowed_domains to Bash, PowerShell and Monitor in auto mode with sandboxing: the hosts a command needs are reviewed with it and opened for it alone; other hosts are refused
  • Added omitClaudeMd to agent frontmatter and --agents JSON, letting custom and plugin subagents run without user, project and local CLAUDE.md files; managed policy files still load
  • Added --accept-command <sha256> to claude plugin install and claude plugin update to accept exactly the command a previous --json run displayed, instead of -y
  • Added support for a multiplier above 1, up to 10, in the modelPricing managed setting and the Claude apps gateway pricing block, for marked-up internal chargeback rates
  • Added a spinner tip pointing Bedrock, Vertex AI, Foundry and LLM gateway users to the Claude desktop app; the claude.ai desktop app tip now suggests /desktop, which offers to download the app
  • Fixed a cached organization policy being reused after switching accounts, organizations, or API keys, and the policy not refreshing until the hourly check when the credential changes mid-session
  • Fixed the tool and command lists not updating when the organization policy finishes loading after startup or changes mid-session
  • Fixed an enterprise managed-mcp.json that can't be read or parsed being ignored: it now keeps exclusive MCP control (user, project and plugin servers don't load) and warns at startup
  • Fixed org policy being fetched through, and rejected by, third-party local proxies set via ANTHROPIC_UNIX_SOCKET; they are again treated like other custom gateways, including for Remote Control
  • Fixed cloud sessions rejecting every subagent tool call ("updatedInput … failed schema validation") when a workflow or agent approval was applied after the session's worker restarted
  • Fixed /fast off answering "Fast mode unavailable" instead of turning fast mode off when the organization has fast mode disabled
  • Fixed sessions started with CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK re-sending fast requests every turn after the API rejected fast mode; the rejection now stands and its reason is shown
  • Fixed fast mode under CLAUDE_CODE_RETRY_WATCHDOG failing the turn on a usage-credits limit, or retrying an overload at fast speed, instead of falling back to standard speed
  • Fixed Bash permission checks missing the file that fmt, column and similar commands read when it follows an option the checker doesn't recognize
  • Fixed Bash permission checks skipping files a wildcard expands to when the wildcard sits in a command's pattern or option value (for example grep -v dir/* file)
  • Fixed Bash permission checks so that shell variable declaration flags cannot misrepresent the command being run
  • Fixed Bash commands with two directory changes, a subshell, or a cd+git chain skipping the prompt under permissions.blockReadsOutsideWorkingDirectories in bypass and auto mode
  • Fixed a stale .git/config.lock breaking git checkout -b, git push -u and git config for the rest of a session after a sandboxed command failed to start (Linux)
  • Fixed settings file changes made outside the session going unnoticed on macOS machines whose system file-event service is saturated; the watcher now falls back to polling
  • Fixed resumed claude -p sessions whose tools all come from MCP servers failing with "At least one tool must have defer_loading=false"
  • Fixed turns failing with "API returned an empty or malformed response" when an LLM gateway returns the non-streaming reply as text/plain
  • Fixed sustained high CPU usage and repeated tool-list requests when an MCP server sends list_changed notifications in a tight loop
  • Fixed MCP OAuth mishandling client registrations: denying consent forced a new one, one for another redirect URI was reused, and a concurrent write could delete a valid one or keep a mismatched one
  • Fixed tool search returning no match when Claude selects an MCP tool by its bare name instead of its full mcp__server__tool name
  • Fixed Ctrl+O cancelling pending MCP server reconnects, and /mcp sent from Remote Control failing while the transcript view is open
  • Fixed the Claude in Chrome prompt telling the model to load tools through ToolSearch when ToolSearch is unavailable
  • Fixed cross-session messages held by the receiving session's permission-mode policy leaving no trace: headless senders now get a delivery notice, and SendMessage results no longer imply it was read
  • Fixed Claude starting a second copy of a background command (such as a watch task or dev server) that was still running after the conversation was compacted
