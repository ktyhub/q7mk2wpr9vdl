Claude-Code v2.1.265

Was hat sich geändert?

– user.email und user.groups zur Telemetrie hinzugefügt, die Claude Desktop und Cowork über ein Claude-Apps-Gateway senden, passend zu Terminalsitzungen – Unterstützung hinzugefügt, um --plugin-dir auf einen Plugin-Ordner zu verweisen: Jeder untergeordnete Ordner mit einem Manifest wird geladen und während der Ausführung hinzugefügte oder entfernte untergeordnete Ordner werden übernommen

  • Es wurde eine Obergrenze von 1 GB für auf der Festplatte gespeicherte Tool-Ergebnisse hinzugefügt. In der Vorschau im Gespräch wird angezeigt, wenn eine gespeicherte Datei abgeschnitten wurde – Das Fortsetzen eines im Vordergrund erzeugten Subagenten, der seine Toolliste und sein System-Eingabeaufforderungspräfix änderte, wurde behoben, wodurch die Wiederverwendung des Eingabeaufforderungs-Cache für diesen Agenten unterbrochen wurde – Problem behoben, bei dem Agenten-Teamkollegen und wieder aufgenommene Subagenten den SubagentStart-Hook-Kontext und vorinstallierte Fertigkeiten in späteren Runden aus dem Prompt-Präfix verschoben haben, wodurch die Wiederverwendung des Prompt-Cache unterbrochen wurde
  • Wiederaufnahme behoben, nachdem der vorherige Prozess abgebrochen wurde, während ein Tool ausgeführt wurde: Die letzte Eingabeaufforderung wird nicht mehr neu geschrieben und der unterbrochene Tool-Aufruf wird beibehalten und als unterbrochen markiert – Problem behoben, bei dem /model opusplan[1m] mit der Fehlermeldung „Modell nicht gefunden“ abgelehnt wurde. – Syntaxhervorgehobener Code in Berechtigungsaufforderungen und -nachrichten wurde behoben, bei dem manchmal ein Zeichen nach einem Ruby-?-, Erlang-$- oder Perl-$-Siegel weggelassen wurde – Das Problem, dass das Vollbild-Transkript um eine Zeile sprang, wenn der Schrägstrich-Befehl oder die @-Datei-Vorschlagsliste geöffnet oder geschlossen wurde, wurde behoben – Ein Plugin-Pfad, der einen Backslash enthielt, wurde behoben, wodurch die Symlink-Einschlussprüfung unter macOS und Linux umgangen wurde
  • Problem behoben, bei dem Plugin-Verzeichnisse, deren Namen mit zwei Punkten beginnen, fälschlicherweise als außerhalb des Plugin-Stammverzeichnisses liegend abgelehnt wurden – Behoben, dass VS-Code- und SDK-Sitzungen gelegentlich eine erneute Anmeldung erforderten, wenn eine Sitzung geschlossen wurde, während ihr Token aktualisiert wurde
  • Problem behoben, bei dem Fernsteuerungssitzungen vor der letzten Antwortnachricht das Endsignal sendeten, was dazu führen konnte, dass eine Antwort in der Claude-App als abgeschlossen angezeigt wurde, bevor der letzte Teil eintraf – Problem behoben, bei dem Hintergrundsitzungen (--bg) gelegentlich mitten in der Runde abgebrochen wurden, wenn eine Nachricht kurz vor dem Leerlauf-Timeout eintraf – Die eigenen Git-Status- und Diff-Probes von Claude Code, die saubere Filter ausführen, die von einem verschachtelten Repository im Arbeitsbaum konfiguriert wurden, wurden behoben – Problem behoben, bei dem das Advisor-Tool und seine Anweisungen pro Anfrage aus dem Modell der Anfrage neu entschieden wurden; Die Entscheidung wird nun einmalig getroffen und im Gespräch bekannt gegeben, wenn sie sich ändert – Problem behoben, bei dem die Veröffentlichung von Artefakten Connector-Tool-Namen akzeptierte, die der Connector nicht offenlegt; Die Veröffentlichung wird jetzt abgelehnt, wenn keines der deklarierten Tools vorhanden ist, und eine Warnung wird ausgegeben, wenn nur einige nicht vorhanden sind – Behoben: /add-dir <subdirectory> weigerte sich, die Agenten eines Unterverzeichnisses zu laden, wenn verwaltete Einstellungen nur Fertigkeiten für Plugins sperren, und versprach Agenten, wenn nur Agenten gesperrt waren
  • Behoben, dass Zwei-Tasten-Tastaturkürzel lautlos abgebrochen wurden, wenn die zweite Taste mehr als eine Sekunde später eintraf, wie es in tmux der Fall ist; Sie warten jetzt 3 Sekunden und zeigen eine Benachrichtigung an, wenn eine Zeitüberschreitung auftritt
  • Problem behoben, bei dem gespaltene Fertigkeiten (context: fork) ihre Kickoff-Eingabeaufforderung nicht streamten und bei --forward-subagent-text ihre Texte als Fortschrittsereignisse im Stream-json angezeigt wurden – Problem behoben, bei dem der Standardkomponentenordner eines Plugins, den das Betriebssystem nicht überprüfen kann, z. B. eine Symlink-Schleife, stillschweigend übersprungen wurde; es wird jetzt in /plugin mit dem Fehlercode gemeldet – Problem behoben, bei dem das OTLP-Telemetrie-Relay des Claude-Apps-Gateways die gesamte Weiterleitung an einen Collector für 30 Sekunden pausierte, nachdem es einige Nutzlasten als fehlerhaft oder zu groß abgelehnt hatte – Problem behoben, bei dem /plugin Discover/Browse und claude plugin list --json --available keine Beschreibung oder keinen Anzeigenamen für Marktplatz-Plugins anzeigten, deren Metadaten nur in ihrem plugin.json vorhanden sind – Behoben: /login zeigte „keine Gateway-URL konfiguriert“ an, wenn es in einer Sitzung erneut ausgeführt wurde, bei der man sich bei einem Claude-Apps-Gateway anmeldete, das durch verwaltete Einstellungen festgelegt wurde – Problem behoben, bei dem /model behauptete, ein Modell sei „als Standard gespeichert“, wenn die Einstellungsdatei nicht geschrieben werden konnte; Jetzt wird angezeigt, dass der Speichervorgang fehlgeschlagen ist und warum – Problem behoben, bei dem /clear von Remote Control auf SessionStart-Hooks und offene Terminaldialoge wartete, bevor es abgeschlossen wurde – Problem behoben, bei dem sich die Höhe des /config-Dialogs beim Wechseln zwischen seinen Registerkarten änderte – Die Wiederaufnahme einer Workflow-Ausführung nach dem Neustart des Containers wurde behoben. Ein Lebenslauf, dessen Ausführungsjournal fehlt, schlägt jetzt mit einem eindeutigen Fehler fehl, anstatt jeden Agenten erneut auszuführen – Die Fehlercode-Referenz des claude-api-Skills wurde korrigiert: Modellzugriffsfehler geben 404 zurück und nicht verfügbare Beta-Header geben 400 und nicht 403 zurück – Nicht interaktive Sitzungen (-p mit Stream-json-Eingabe, Agent SDK, Cloud-Sitzungen) behoben, bei denen das Shell-Arbeitsverzeichnis bei jeder neuen Benutzernachricht zurückgesetzt wurde; Ein cd bleibt nun über Kurven hinweg bestehen – Als http konfigurierte MCP-Server, die nur den alten HTTP+SSE-Transport sprechen und nie eine Verbindung herstellten, wurden behoben. Claude Code greift nun auf SSE zurück, wie in der MCP-Spezifikation beschrieben – Einige claude.ai-Konnektoren in Cloud-Sitzungen wurden behoben, die anzeigten, dass sie eine Authentifizierung benötigen, obwohl sie in claude.ai verbunden sind (Server, die eine nicht unterstützte Anfrage mit HTTP 401 beantworten) – Problem behoben, bei dem Remote-Sitzungen ihren Sandbox-Container am Leben hielten, während ein Connector-Genehmigungs- oder Anmeldelink auf Sie wartete – Es wurde ein Problem behoben, bei dem bei fortgesetzten Sitzungen lange, dem Modell zugewandte Wiederherstellungsanweisungen in der Meldung „Hintergrundaufgabe wurde nicht abgeschlossen“ anstelle einer kurzen Statuszeile angezeigt wurden
  • Windows: Behoben: Lesen, Schreiben und Bearbeiten verweigerten jede Datei („Symlink-Auflösung wurde geändert, nachdem die Berechtigung überprüft wurde“), wenn sie in einem AppContainer oder einer Sandbox mit eingeschränktem Token ausgeführt wurde
  • Verbesserter --worktree-Start auf großen Repositories: Der neue Arbeitsbaum wird jetzt parallel ausgecheckt (git 2.32+)
  • Verbesserte /workflows-Agentendetails: Tool-Aufrufe werden als ausgeführt, fehlgeschlagen oder erledigt markiert, die Aufgabenliste des Subagenten wird angezeigt, wenn er eine hat, und die Eingabetaste blendet die aufgelisteten Aufrufe mit ihren Eingaben und Ergebnissen ein
  • Verbesserte Slash-Befehle, die mitten in der Eingabeaufforderung eingegeben werden: Übereinstimmungen werden jetzt in einer Liste (Tab öffnet sie außerhalb des Vollbildmodus) anstelle eines einzelnen Vorschlags angezeigt, und eine Plugin-Fähigkeit wird jetzt anhand ihres bloßen Namens gefunden
  • Verbesserte Remote-MCP-Server, die eine Anmeldung erfordern: Claude Code registriert keinen OAuth-client mehr bei ihnen, bis Sie sich tatsächlich authentifizieren – Die Zeit zum Fortsetzen langer Sitzungen, bei denen viele Dateien gelesen werden, wurde verbessert – Der Fehler, der angezeigt wird, wenn ein Bild, das die Größenbeschränkung überschreitet, nicht dekodiert werden kann, wurde verbessert: Es werden nun die Ursache und die Lösungsansätze genannt, anstatt nur die Beschränkung anzugeben
  • Das Lesen eines von jemand anderem geschriebenen Artefakts durch das Artefakt-Tool wurde verbessert: Die Zusammenfassung behandelt die Seite jetzt als nicht untrusted-Inhalt und kennzeichnet eingebettete Anweisungen, anstatt sie weiterzuleiten – Die Berechtigungsoption für den .claude-Ordner wurde aktualisiert, um anzugeben, was sie tatsächlich erlaubt: Bearbeiten von Dateien im .claude-Ordner (oder ~/.claude) des Projekts für die Sitzung – Maschinen mit forceLoginGatewayUrl in den verwalteten Einstellungen wurden vom Start an zu Claude-Apps-Gateway-Sitzungen geändert, wie forceLoginMethod: "gateway"; ein übrig gebliebener claude.ai-Login oder API-Schlüssel wird nicht verwendet
  • Bildverarbeitung geändert, um die integrierte Bildunterstützung der Laufzeit zu nutzen; Der CLI extrahiert kein natives Image-Modul mehr in das temporäre Verzeichnis
  • Die Anzeigemetadaten des Plugins wurden geändert, um den Marktplatzeintrag gegenüber plugin.json auf der Registerkarte „Installiert“ und claude plugin details zu bevorzugen, wodurch Lücken von plugin.json geschlossen werden – Claude-Apps-Gateway-Sitzungen wurden geändert, um OpenTelemetry direkt an einen Collector zu exportieren, den Namen der verwalteten Einstellungen des Gateways in OTEL_EXPORTER_OTLP_ENDPOINT, anstatt über das Relay des Gateways; Sitzungen ohne benannten Collector verwenden weiterhin das Relay
  • [VSCode] Automatische Archivierung von Sitzungen hinzugefügt, die für einen festgelegten Zeitraum inaktiv waren (neue Einstellung „Inaktive Sitzungen archivieren“, Standard 14 Tage) – [VSCode] Problem behoben, bei dem der Seitenleisten-Chat nach dem Neuladen des Fensters oder einem Neustart leer blieb, wenn die Konversation länger als 10 Minuten geöffnet war – [VSCode] Der Timeline-Punkt, der unter dem Text in der Meldung „Fernbedienung ist aktiv“ saß, wurde behoben

Englisches Original / English original

claude-code v2.1.265

What's changed

  • Added user.email and user.groups to the telemetry Claude Desktop and Cowork send through a Claude apps gateway, matching terminal sessions
  • Added support for pointing --plugin-dir at a folder of plugins: each child folder with a manifest loads, and children added or removed while running are picked up
  • Added a 1 GB cap on tool results saved to disk; the in-conversation preview says when a saved file was truncated
  • Fixed resuming a foreground-spawned subagent changing its tool list and system prompt prefix, which broke prompt-cache reuse for that agent
  • Fixed agent teammates and resumed subagents moving SubagentStart hook context and preloaded skills out of the prompt prefix on later turns, which broke prompt-cache reuse
  • Fixed resume after the previous process died while a tool was running: the last prompt is no longer rewritten, and the interrupted tool call is kept and marked interrupted
  • Fixed /model opusplan[1m] being rejected with "Model not found"
  • Fixed syntax-highlighted code in permission prompts and messages sometimes omitting a character after a Ruby ?, Erlang $, or Perl $ sigil
  • Fixed the fullscreen transcript jumping by one row whenever the slash-command or @-file suggestion list opened or closed
  • Fixed a plugin path containing a backslash bypassing the symlink containment check on macOS and Linux
  • Fixed plugin directories whose names begin with two dots being wrongly refused as outside the plugin root
  • Fixed VS Code and SDK sessions occasionally requiring re-login when a session was closed while refreshing its token
  • Fixed Remote Control sessions sending the end-of-turn signal before the reply's last message, which could show a reply as finished in the Claude app before its last part arrived
  • Fixed background (--bg) sessions occasionally being retired mid-turn when a message arrived just before the idle timeout
  • Fixed Claude Code's own git status and diff probes running clean filters configured by a nested repository inside the working tree
  • Fixed the advisor tool and its instructions being re-decided per request from the request's model; the decision is now made once and announced in the conversation when it changes
  • Fixed artifact publish accepting connector tool names the connector doesn't expose; the publish is now refused when none of the declared tools exist, and warned when only some don't
  • Fixed /add-dir <subdirectory> refusing to load a subdirectory's agents when managed settings lock only skills to plugins, and promising agents when only agents are locked
  • Fixed two-key keyboard shortcuts cancelling silently when the second key arrived more than a second later, as happens inside tmux; they now wait 3 seconds and show a notice when they time out
  • Fixed forked skills (context: fork) not streaming their kickoff prompt and, with --forward-subagent-text, their text turns as progress events in stream-json
  • Fixed a plugin's default component folder that the OS cannot check, such as a symlink loop, being silently skipped; it is now reported in /plugin with the error code
  • Fixed the Claude apps gateway's OTLP telemetry relay pausing all forwarding to a collector for 30 seconds after it rejected a few payloads as malformed or too large
  • Fixed /plugin Discover/Browse and claude plugin list --json --available showing no description or display name for marketplace plugins whose metadata lives only in their plugin.json
  • Fixed /login showing "no gateway URL is configured" when re-run in a session that signed in to a Claude apps gateway set by managed settings
  • Fixed /model claiming a model was "saved as your default" when the settings file couldn't be written; it now says the save failed and why
  • Fixed /clear from Remote Control waiting on SessionStart hooks and on open terminal dialogs before completing
  • Fixed the /config dialog changing height when switching between its tabs
  • Fixed resuming a workflow run after its container restarted; a resume whose run journal is missing now fails with a clear error instead of rerunning every agent
  • Fixed the claude-api skill's error-code reference: model access failures return 404 and unavailable beta headers return 400, not 403
  • Fixed non-interactive sessions (-p with stream-json input, Agent SDK, cloud sessions) resetting the shell working directory at each new user message; a cd now persists across turns
  • Fixed MCP servers configured as http that only speak the legacy HTTP+SSE transport never connecting; Claude Code now falls back to SSE as the MCP spec describes
  • Fixed some claude.ai connectors in cloud sessions showing as needing authentication even though they are connected in claude.ai (servers that answer an unsupported request with HTTP 401)
  • Fixed remote sessions keeping their sandbox container alive while a connector approval or sign-in link waits for you
  • Fixed resumed sessions showing long model-facing recovery instructions in "background task didn't finish" notices instead of a short status line
  • Windows: Fixed Read, Write and Edit refusing every file ("symlink resolution changed after permission was checked") when running inside an AppContainer or restricted-token sandbox
  • Improved --worktree startup on large repositories: the new worktree is now checked out in parallel (git 2.32+)
  • Improved /workflows agent detail: tool calls are marked running, failed or done, the subagent's task list is shown when it has one, and Enter unfolds the listed calls with their inputs and results
  • Improved slash commands typed mid-prompt: matches now show in a list (Tab opens it outside fullscreen) instead of a single suggestion, and a plugin skill is now found by its bare name
  • Improved remote MCP servers that need sign-in: Claude Code no longer registers an OAuth client with them until you actually authenticate
  • Improved the time to resume long sessions that read many files
  • Improved the error shown when an image over the size limits cannot be decoded: it now names the cause and how to fix it instead of only citing the limit
  • Improved the Artifact tool's read of an artifact someone else wrote: the summary now treats the page as untrusted content and flags embedded instructions rather than relaying them
  • Updated the .claude folder permission option to say what it actually allows: editing files in the project's .claude folder (or ~/.claude) for the session
  • Changed machines with forceLoginGatewayUrl in managed settings to be Claude apps gateway sessions from startup, like forceLoginMethod: "gateway"; a leftover claude.ai login or API key is not used
  • Changed image processing to use the runtime's built-in image support; the CLI no longer extracts a native image module to the temp directory
  • Changed plugin display metadata to prefer the marketplace entry over plugin.json on the Installed tab and claude plugin details, filling gaps from plugin.json
  • Changed Claude apps gateway sessions to export OpenTelemetry directly to a collector the gateway's managed settings name in OTEL_EXPORTER_OTLP_ENDPOINT, instead of through the gateway's relay; sessions without a named collector still use the relay
  • [VSCode] Added automatic archiving of sessions inactive for a set period (new "Archive inactive sessions" setting, default 14 days)
  • [VSCode] Fixed the sidebar chat coming back blank after Reload Window or a restart when the conversation had been open for more than 10 minutes
  • [VSCode] Fixed the timeline dot sitting below the text on the "Remote Control is active" message
