Claude-Code v2.1.212

Was hat sich geändert?

  • /fork kopiert Ihre Konversation jetzt in eine neue Hintergrundsitzung (eine eigene Zeile in claude agents), während Sie weiterarbeiten; Der In-Session-Subagent, mit dem er gestartet wurde, ist jetzt /subtask – claude auto-mode reset hinzugefügt, um die Standardkonfiguration für den automatischen Modus wiederherzustellen, mit einer Bestätigungsaufforderung (zum Überspringen --yes übergeben) – Es wurde ein sitzungsweites Limit für WebSearch-Tool-Aufrufe hinzugefügt (Standard 200, einstellbar über CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION), um außer Kontrolle geratene Suchschleifen zu stoppen – Es wurde eine Obergrenze pro Sitzung für Subagenten-Spawns hinzugefügt (Standard 200, Überschreibung mit CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION), um außer Kontrolle geratene Delegationsschleifen zu stoppen. /clear setzt das Budget zurück
  • MCP-Tool-Aufrufe, die länger als 2 Minuten dauern, werden jetzt automatisch in den Hintergrund verschoben, sodass die Sitzung nutzbar bleibt. Konfigurieren Sie den Schwellenwert oder deaktivieren Sie ihn mit CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS – Durch die Eingabe von /resume in der Agentenansicht wird jetzt eine Auswahl vergangener Sitzungen geöffnet – einschließlich der aus der Liste gelöschten Sitzungen – und Ihre Auswahl wird als Hintergrundsitzung fortgesetzt – Das automatische Ausführen von dateimodifizierenden Bash-Befehlen (z. B. touch, rm) im Planmodus ohne Erlaubnisaufforderung oder SDK canUseTool-Rückruf wurde behoben – Die Erstellung des Arbeitsbaums nach einem vom Repository festgeschriebenen Symlink bei .claude/worktrees wurde korrigiert, wodurch Dateien außerhalb des Repositorys erstellt werden konnten – Es wurde behoben, dass der Stopp eines continue:false-Hooks verworfen wurde, wenn das Tool mitten im Stream fehlschlägt oder abgeschlossen wird, und dass Hook-Infrastrukturfehler fälschlicherweise als Benutzerablehnungen gemeldet wurden – Problem behoben, bei dem SIGTERM während eines laufenden Bash-Tools den Prozessbaum des Befehls im Druck-/SDK-Modus verwaiste; Der CLI bricht nun den Turn ab, tötet den Baum und verlässt 143 – Behebung eines Fehlers bei /background und claude --bg mit „EUNKNOWN: unbekannter Fehler, uv_spawn“ unter Windows, wenn Gruppenrichtlinien PowerShell 5.1 blockieren; Der Daemon bevorzugt jetzt PowerShell 7 – Behoben: Der Shell-Modus (!) führte keine Befehle aus, die Dateipfade enthielten, während das Popup zur automatischen Pfadvervollständigung geöffnet war
  • Fehler bei Ablehnungsbenachrichtigungen im automatischen Modus behoben, die fehlerhafte Zeichen darstellten, wenn ein langer Ablehnungsgrund mitten im Emoji abgeschnitten wurde – Problem behoben, bei dem Strg+J keine neue Zeile in die Dispatch-Eingabe der Agentenansicht auf Terminals mit erweiterter Tastenberichterstattung einfügte, und die neue Zeilenverknüpfung im ?-Hilfe-Overlay angezeigt wurde – Problem behoben, bei dem /ultrareview PR-Referenzen wie #123, PR 123 und eingefügte PR-URLs ablehnte; Fehlerhinweise benennen nun den Befehl, den Sie tatsächlich eingegeben haben – Problem behoben, bei dem /ultrareview <branch> den Zweig nicht vom Ursprung abholte, wenn er remote existierte; Bei Tippfehlern wird jetzt der nächstgelegene Filialname vorgeschlagen – Problem behoben, bei dem /ultrareview die Rechnungsbestätigung in einer neuen Konversation nach /clear übersprang – Der Fehler „Kein Git-Repository“ von /ultrareview auf Claude Desktop wurde behoben, der jetzt den Repository-Ordner des Projekts anstelle von Terminalbefehlen vorschlägt – Behoben, dass gehostete (vom Host verwaltete) Sitzungen beim Start fehlschlugen, wenn in den Repository-Einstellungen mTLS-Zertifikate, zusätzliche CA-Bundles oder OAuth-Bereiche konfiguriert wurden; Diese Transporteinstellungen werden jetzt mit einer Warnung ignoriert – Es wurde ein falscher Fehler „Datei wurde noch nicht gelesen“ behoben, der beim Bearbeiten einer Datei auftrat, die vor der Fortsetzung einer Sitzung mit Offset/Limit gelesen wurde – Fehler behoben, bei dem ExitWorktree mit „keine aktive EnterWorktree-Sitzung“ fehlschlug, nachdem eine Sitzung mit --continue/--resume im Druck-/SDK-Modus fortgesetzt wurde – Problem behoben, bei dem das Workflow-Agent-Raster für Remote Control clients, die mitten in einer Sitzung beitreten, leer blieb – Behoben: Steuerungsanfragen im Streaming-Modus wurden als abgeschlossen markiert, bevor ihr Handler fertig war, was dazu führen konnte, dass die Anfrage beim Neustart der Sitzung verloren ging – Problem behoben, bei dem Hintergrundsitzungen, die mit /fork erstellt wurden, nach einem Zustandsschreibfehler ihren Live-Parent-Schutz verloren – Problem behoben, bei dem das erneute Öffnen einer gestoppten Hintergrundsitzung aus der Agentenansicht unbemerkt fehlschlug – die Sitzung wird jetzt fortgesetzt oder angezeigt, warum dies nicht möglich ist, und Sie können einen Neustart erzwingen
  • Behobene Agententeams: Ein stoppender Teamkollege konnte dem Anführer doppelte Leerlaufbenachrichtigungen senden, wenn die Teaminitialisierung innerhalb einer Sitzung erneut ausgeführt wurde – Die Fußzeile des Plangenehmigungsdialogs wurde behoben, bei der „Strg+G zum Bearbeiten in <Editor>“ getrennt wurde, wenn der Dateipfad lang war – Problem behoben, bei dem das Willkommensbanner nach einer kombinierten Breite+Höhe-Terminalgrößenänderung im Vollbildmodus seine alten Panelbreiten beibehielt
  • Problem behoben, bei dem Diff-Vorschauen in schmalen Layouts ihre Zeilennummern und +/- Markierungen verloren
  • Behoben: @-Erwähnungen, die nach einem teilweisen Lesen einer Datei nichts anhängten, die Plugin-Deinstallation, die auf den falschen Marktplatz abzielte, und die falsche Meldung „Befehlszeitüberschreitung“ bei Exit-Code 143 wurden behoben – Problem behoben, bei dem OpenTelemetry-HTTP-Exporte mit 411/400 von Azure Monitor und anderen Endpunkten abgelehnt wurden, die keine Chunked-Transfer-Codierung akzeptieren – Es wurde behoben, dass OTLP-Ereignisprotokolleinträge trace_id/span_id fehlten, wenn TRACEPARENT im SDK/Headless-Modus eingestellt war – Es wurde behoben, dass Konversationen mit vielen Bildern fälschlicherweise mit der Fehlermeldung „Anfrage zu groß“ fehlschlugen, und die Fehlermeldung wurde verbessert, um die eigentliche Ursache zu erklären – Problem behoben, bei dem Websuche und Webabruf den Text „API-Fehler“ als Suchergebnisse oder Seiteninhalt zurückgaben, wenn API überlastet war – Verbesserte Websuche und Webabrufzuverlässigkeit durch Wiederholung von 529 Fehlern und ratenbegrenzten Anfragen mit begrenztem Backoff
  • Verbessertes Zwischenspeichern von Eingabeaufforderungen: Der Systemblock während der Konversation funktioniert jetzt hinter LLM-Gateways und benutzerdefinierten Basis-URLs (Bedrock, Vertex, 1P).
  • Verbessertes Anhängen von Agenten im Hintergrund: Beim Kaltanhängen wird jetzt sofort das formatierte Transkript angezeigt, während die Sitzung startet, statt einer leeren Wartezeit – Reduzierte Token-Nutzung bei der Nachrichtenübermittlung zwischen Agenten: SendMessage-Körper werden nicht mehr im wiedergegebenen Verlauf und in den Tool-Ergebnissen dupliziert – /fork wurde geändert, um die Kopie nach Ihrer Eingabeaufforderung zu benennen, wenn die Sitzung keinen Titel hat, sodass die Zeile in der Agentenansicht erkennbar ist
  • /btw wurde geändert, um das Nebenfragenfenster bei Ihrem letzten Austausch wieder zu öffnen, sodass Sie frühere Antworten durchsuchen können
  • Der ←-Fußzeilenhinweis wurde geändert, um N done für einen Moment zu pulsieren, wenn ein Hintergrundagent fertig ist, während nichts Ihrer Eingabe bedarf – Der mode-Parameter des Task-Tools ist veraltet (wird jetzt ignoriert); Subagenten erben standardmäßig den Berechtigungsmodus der übergeordneten Sitzung – Enterprise forceLoginMethod wurde so geändert, dass es für die VS-Code-Erweiterung, SDK-, setup-token- und install-github-app-Anmeldungen erzwungen wird, nicht nur für das Terminal
  • Die Sitzungsprotokolle wurden geändert, um den Grad des Argumentationsaufwands für jede Assistentennachricht aufzuzeichnen
  • Headless/SDK-Sitzungen wurden geändert, um eine set_model-Steuerungsanforderung mitten in der Runde anzuwenden; Bei der nächsten Modellumrundung wird das neue Modell verwendet, anstatt auf die nächste Runde zu warten – Geänderte Agentenansicht / claude agents --json: Sitzungen, die auf eine Sandbox, eine MCP-Eingabe oder eine Eingabeaufforderung für verwaltete Einstellungen warten, werden jetzt als „Eingabe erforderlich“ statt als „Wird ausgeführt“ angezeigt. – Der Titel des Authentifizierungsstatus-Panels wurde von „Cloud-Authentifizierung“ zu „Authentifizierung“ aktualisiert.
  • Ein früheres release note (2.1.200) wurde korrigiert: tmux durch die 3.6-Serie weist keine synchronisierte Ausgabe auf; Neuere tmux mit Unterstützung werden automatisch erkannt

claude-code v2.1.212

What's changed

  • /fork now copies your conversation into a new background session (its own row in claude agents) while you keep working; the in-session subagent it used to launch is now /subtask
  • Added claude auto-mode reset to restore the default auto-mode configuration, with a confirmation prompt (pass --yes to skip)
  • Added a session-wide limit on WebSearch tool calls (default 200, tunable via CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION) to stop runaway search loops
  • Added a per-session cap on subagent spawns (default 200, override with CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION) to stop runaway delegation loops; /clear resets the budget
  • MCP tool calls running longer than 2 minutes now move to the background automatically so the session stays usable; configure the threshold or disable with CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS
  • Typing /resume in the agent view now opens a picker of past sessions — including sessions deleted from the list — and resumes your pick as a background session
  • Fixed plan mode auto-running file-modifying Bash commands (e.g. touch, rm) without a permission prompt or SDK canUseTool callback
  • Fixed worktree creation following a repository-committed symlink at .claude/worktrees, which could create files outside the repository
  • Fixed a continue:false hook's halt being dropped when the tool fails or completes mid-stream, and hook infrastructure errors being misreported as user rejections
  • Fixed SIGTERM during a running Bash tool orphaning the command's process tree in print/SDK mode; the CLI now aborts the turn, kills the tree, and exits 143
  • Fixed /background and claude --bg failing with "EUNKNOWN: unknown error, uv_spawn" on Windows when Group Policy blocks PowerShell 5.1; the daemon now prefers PowerShell 7
  • Fixed shell mode (!) not executing commands containing file paths while the path autocomplete popup was open
  • Fixed auto-mode denial notifications rendering broken characters when a long denial reason was truncated mid-emoji
  • Fixed Ctrl+J not inserting a newline in the agent view dispatch input on terminals with extended key reporting, and surfaced the newline shortcut in the ? help overlay
  • Fixed /ultrareview rejecting PR references like #123, PR 123, and pasted PR URLs; error hints now name the command you actually typed
  • Fixed /ultrareview <branch> not fetching the branch from origin when it exists remotely; it now suggests the closest branch name on typos
  • Fixed /ultrareview skipping the billing confirmation in a new conversation after /clear
  • Fixed /ultrareview's "not a git repository" error on Claude Desktop now suggesting the project's repository folder instead of terminal commands
  • Fixed hosted (host-managed) sessions failing at startup when repository settings configured mTLS certs, extra CA bundles, or OAuth scopes; these transport settings are now ignored with a warning
  • Fixed a spurious "File has not been read yet" error when editing a file that had been read with offset/limit before resuming a session
  • Fixed ExitWorktree failing with "no active EnterWorktree session" after resuming a session with --continue/--resume in print/SDK mode
  • Fixed the workflow agent grid staying empty for Remote Control clients that join a session mid-run
  • Fixed streaming-mode control requests being marked complete before their handler finished, which could lose the request on session restart
  • Fixed background sessions created with /fork losing their live-parent protection after a state write failure
  • Fixed reopening a stopped background session from the agent view failing silently — it now resumes the session, or shows why it can't and lets you force a restart
  • Fixed agent teams: a stopping teammate could send the leader duplicate idle notifications when team initialization re-ran within a session
  • Fixed the plan-approval dialog footer splitting "ctrl+g to edit in <editor>" apart when the file path is long
  • Fixed the welcome banner keeping its old panel widths after a combined width+height terminal resize in fullscreen mode
  • Fixed diff previews losing their line numbers and +/- markers in narrow layouts
  • Fixed @-mentions attaching nothing after a partial file read, plugin uninstall targeting the wrong marketplace, and false "Command timed out" on exit code 143
  • Fixed OpenTelemetry HTTP exports being rejected with 411/400 by Azure Monitor and other endpoints that don't accept chunked transfer encoding
  • Fixed OTLP event log records missing trace_id/span_id when TRACEPARENT is set in SDK/headless mode
  • Fixed conversations with many images incorrectly failing with "Request too large" errors, and improved the error message to explain the actual cause
  • Fixed web search and web fetch returning "API Error" text as search results or page content when the API was overloaded
  • Improved web search and web fetch reliability by retrying 529 errors and rate-limited requests with bounded backoff
  • Improved prompt caching: the mid-conversation system block now works behind LLM gateways and custom base URLs (Bedrock, Vertex, 1P)
  • Improved background agent attach: cold-attaching now instantly shows the formatted transcript while the session boots, instead of a blank wait
  • Reduced token usage in inter-agent messaging: SendMessage bodies are no longer duplicated into replayed history and tool results
  • Changed /fork to name the copy after your prompt when the session has no title, so the row is recognizable in the agent view
  • Changed bare /btw to reopen the side-question panel on your most recent exchange so you can browse earlier answers
  • Changed the ← footer hint to pulse N done for a moment when a background agent finishes while nothing needs your input
  • Deprecated the Task tool's mode parameter (now ignored); subagents inherit the parent session's permission mode by default
  • Changed Enterprise forceLoginMethod to be enforced for VS Code extension, SDK, setup-token, and install-github-app logins, not just the terminal
  • Changed session transcripts to record the reasoning effort level on each assistant message
  • Changed headless/SDK sessions to apply a set_model control request mid-turn; the next model round-trip uses the new model instead of waiting for the next turn
  • Changed agent view / claude agents --json: sessions waiting on a sandbox, MCP-input, or managed-settings prompt now show as "Needs input" instead of "Working"
  • Updated the auth status panel title from "Cloud authentication" to "Authentication"
  • Corrected an earlier release note (2.1.200): tmux through the 3.6 series lacks synchronized output; newer tmux with support is detected automatically
