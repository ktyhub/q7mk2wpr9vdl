Was hat sich geändert?

– Es wurde eine sichtbare Warnung hinzugefügt, wenn die Speichernutzung kritisch ist, mit Schritten zum Freigeben von Speicher oder zum sicheren Neustart – CLAUDE_CODE_MCP_STARTUP_WAIT_MS hinzugefügt, um zu begrenzen, wie lange die erste nicht interaktive Runde auf die Verbindung mit MCP-Servern wartet (0 = nicht warten) – Attribut effort zur Ablaufverfolgungsspanne claude_code.llm_request OpenTelemetry hinzugefügt, passend zum Ereignis api_request – claude_code.managed_settings_resolved OTel-Ereignis hinzugefügt: verwaltete Einstellungsquellen und Richtlinienhilfsstatus; redigierte Einstellungen und Digests mit OTEL_LOG_MANAGED_SETTINGS=1 – store.connect_timeout_seconds zur Claude-Apps-Gateway-Konfiguration hinzugefügt, um das Postgres-Verbindungszeitlimit zu verlängern (Standard 5 Sekunden) und den Startfehler verbessert, wenn die Datenbank nicht erreichbar ist, um auf store.postgres_url und das konfigurierte Zeitlimit zu verweisen – enduser.sub, das IdP-Subjekt, zur Telemetrie hinzugefügt, die Claude Desktop und Cowork über ein Claude-Apps-Gateway senden – Es wurde eine Claude-Apps-Gateway-Warnung hinzugefügt, wenn für ein Replikat mehr Anfragen offen sind als die 256, die es gleichzeitig an den Upstream sendet, sowie eine Startprotokollzeile, die dieses Limit anzeigt – click-to-expand für ausgeblendete Nachrichten von Teamkollegen und Agenten im Vollbildmodus hinzugefügt – Es wurde behoben, dass Sitzungen beim endlosen Wiederholen von „unexpected tool_use_id“ 400-Fehlern hängen blieben: Beschädigte Transkripte reparieren sich jetzt, wo möglich, selbst, andernfalls beendet ein eindeutiger Fehler (mit einem /rewind-Hinweis) die Schleife – Problem behoben, bei dem als http konfigurierte MCP-Server, die nur Legacy-HTTP+SSE sprechen, keine Verbindung herstellen konnten, wenn sie die erste Anfrage mit 422 oder einem anderen 4xx-Fehler beantworteten – Problem behoben, bei dem Streamable HTTP MCP-Tool-Aufrufe nach etwa 5 Minuten zu Zeitüberschreitungen führten, selbst wenn ein längerer timeout pro Server festgelegt wurde – Problem behoben, bei dem MCP-Eingabeaufforderungen und -Ressourcen nicht aktualisiert wurden, wenn ein Server Listenänderungsbenachrichtigungen sendete, ohne listChanged zu deklarieren – Behoben, dass MCP-Tool-Aufrufe, die mit 403 unzureichender_Bereich abgelehnt wurden, als abgelaufene Anmeldung gemeldet wurden: Der Fehler benennt jetzt die fehlenden Berechtigungen und weist auf eine erneute Authentifizierung durch /mcp hin – Problem behoben, bei dem Hook-gesteuerte Sitzungen (z.   • Problem behoben, bei dem Vorschaunotizen von AskUserQuestion an eine zuvor ausgewählte Option angehängt wurden, anstatt an die hervorgehobene – Problem behoben, bei dem im AskUserQuestion-Vorschaumodus die hervorgehobene Option wegfiel, wenn eine Notiz mit der Eingabetaste übermittelt wurde – Ein wieder aufgenommener Hintergrundagent, der die Hälfte eines unterbrochenen Werkzeugstapels behielt, wurde behoben, wenn einer seiner Anrufe mit einer Nachricht genehmigt wurde – Ein lokaler claude -p --resume wurde behoben, der so gestartet wurde, dass CLAUDE_CODE_RESUME_INTERRUPTED_TURN keine Hintergrundaufgaben meldete, die der vorherige Prozess nicht abgeschlossen hatte – Problem behoben, bei dem die erste Runde einer Cloud-Sitzung manchmal ohne die Tools eines SDK-gehosteten MCP-Servers startete, der noch eine Verbindung herstellte – Benachrichtigungen des Hintergrundagenten behoben, die besagten, dass der Agent keine Live-Hintergrundarbeit hatte, während er noch auf seine eigene Hintergrundaufgabe wartete und fortfahren würde – Fehlerhinweise in Claude Desktop-Sitzungen behoben, um Slash-Befehle wie /usage-credits anstelle von CLI-Flags vorzuschlagen, die dort nicht verwendet werden können – Problem behoben, bei dem /schedule die Eingabeaufforderung einer Routine ohne ihre Nachrichtenrolle speicherte, wenn Claude die Routine in der Form schreibt, die das Auflisten von Routinen zurückgibt – Problem behoben, bei dem /status den apiKeyHelper-Fehler nicht anzeigte, den das eigene Fehlerbanner zur Überprüfung aufforderte – Problem mit /fast on in nicht interaktiven Sitzungen behoben, bei dem Berichte über die verwaltete Schnellmodus-Richtlinie einer Organisation gemeldet und dann deaktiviert wurden; claude-code v2.1.274

What's changed

  • Added a visible warning when memory usage is critical, with steps to free memory or restart safely
  • Added CLAUDE_CODE_MCP_STARTUP_WAIT_MS to bound how long the first non-interactive turn waits for connecting MCP servers (0 = don't wait)
  • Added effort attribute to the claude_code.llm_request OpenTelemetry trace span, matching the api_request event
  • Added claude_code.managed_settings_resolved OTel event: managed-settings sources and policy helper state; redacted settings and digests with OTEL_LOG_MANAGED_SETTINGS=1
  • Added store.connect_timeout_seconds to the Claude apps gateway config to lengthen the Postgres connect timeout (default 5 seconds), and improved the boot error when the database is unreachable to point to store.postgres_url and the configured timeout
  • Added enduser.sub, the IdP subject, to the telemetry Claude Desktop and Cowork send through a Claude apps gateway
  • Added a Claude apps gateway warning when a replica has more requests open than the 256 it sends upstream at once, and a startup log line showing that limit
  • Added click-to-expand for collapsed teammate and agent messages in fullscreen mode
  • Fixed sessions getting stuck endlessly retrying "unexpected tool_use_id" 400 errors: corrupted transcripts now self-heal where possible, and otherwise a clear error (with a /rewind hint) ends the loop
  • Fixed MCP servers configured as http that only speak legacy HTTP+SSE failing to connect when they answer the first request with 422 or another 4xx error
  • Fixed Streamable HTTP MCP tool calls timing out after about 5 minutes even when a longer per-server timeout was set
  • Fixed MCP prompts and resources not refreshing when a server sends list-changed notifications without declaring listChanged
  • Fixed MCP tool calls refused with 403 insufficient_scope being reported as an expired sign-in: the error now names the missing permissions and points to /mcp re-authentication
  • Fixed hook-driven sessions (such as an active /goal) ending with "Prompt is too long" instead of compacting when the context overflowed again after a reactive compaction
  • Fixed an active /goal being lost when resuming (--continue / --resume) a session that had compacted
  • Fixed claude agents losing --model, --effort, --permission-mode, --allow-dangerously-skip-permissions and --agent after an auto-update relaunch
  • Fixed a per-turn slowdown when a language server publishes project-wide diagnostics for thousands of files
  • Fixed subagents with model: "opus" on Bedrock, Vertex or Foundry leaving the session's model when its id has no recognizable model family (unless ANTHROPIC_DEFAULT_OPUS_MODEL is set)
  • Fixed self-hosted runner sessions failing every turn with a 401 after a few failed token refreshes, until the next scheduled refresh; the runner now keeps retrying, and fetches a new token after a 401
  • Fixed clickable links to local file paths doing nothing in VS Code and other terminals that require a file:// URI
  • Fixed the transcript renumbering ordered lists in your own messages (typing "3. 2. 1." displayed "3. 4. 5."); numbers and "N)" markers now show as typed
  • Fixed AskUserQuestion preview notes being attached to a previously chosen option instead of the highlighted one
  • Fixed AskUserQuestion preview mode dropping the highlighted option when submitting a note with Enter
