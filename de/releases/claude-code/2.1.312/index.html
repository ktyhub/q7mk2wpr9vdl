Claude-Code v2.1.312

Was hat sich geändert?

– oidc.user_id_claim zum Claude-Apps-Gateway hinzugefügt, um Personen anhand eines anderen id_token-Anspruchs als sub zu identifizieren, z. B. oid der Microsoft Entra-ID

  • click zum Senden hinzugefügt: Im Vollbildmodus sendet click auf den Hinweis „Jetzt senden“ unter einer Nachricht in der Warteschlange diese sofort, wie es der Schlüssel tut – Behoben, dass verwaltete Einstellungen und Organisationsrichtlinien für den Rest der Sitzung nach der Anmeldung über die VS Code-Erweiterung nicht abgerufen wurden – Problem behoben, durch das Claude eine sehr große CLAUDE.md-, Regeldatei- oder @-included-Datei in einem Unterverzeichnis überschrieb, nachdem nur deren Anfang gesehen wurde; „Jetzt schreiben“ fordert Claude auf, alles zu lesen oder direkt zu bearbeiten – Problem behoben, bei dem verzeichnisspezifische und paths:-Skills nach einem Bash cd tiefer in ein Git-Repository nicht gefunden wurden – Es wurde ein seltener Fall behoben, bei dem die erste Antwort nach der Wiederaufnahme einer Sitzung im Terminal beim nächsten Wiederaufnehmen der Sitzung fehlen konnte – Ein Befehl mit einem ungültigen Namen wurde behoben, der das Laden aller Befehle verhinderte, was dazu führen konnte, dass claude -p keine Ausgabe erhielt – Es wurde ein Problem behoben, bei dem das Lesetool manchmal auf PDF-Seiten mit der Fehlermeldung „pdftoppm fehlgeschlagen: Bild konnte nicht geschrieben werden“ fehlschlug, wenn gleichzeitig die Bereinigung alter Sitzungsdateien ausgeführt wurde
  • Der Spinner, OpenTelemetry effort-Werte und Transkripte, die während einer Aufgabe eine neu ausgewählte Aufwandsstufe benennen, bevor das Modell sie anwendet, wurden korrigiert; Sie zeigen jetzt den geltenden Pegel an – Die Cache-Warnung /model und /effort behoben, die besagte, dass das erneute Lesen auf Ihre nächste Nachricht wartet; Eine Änderung, die während der Arbeit von Claude vorgenommen wird, kann es früher auslösen
  • Einige Sitzungen wurden als auf Sie wartend angezeigt, obwohl in der letzten Nachricht nur mitten im Satz auf Sie wartende Elemente erwähnt wurden – Problem mit der Wiederherstellung des Eingabetexts in der Agentenansicht beim nächsten Start behoben, nachdem dieser kurz vor dem Beenden mit Strg+C gelöscht wurde – Das erneute Öffnen der Agentenansicht im Shell-Modus nach dem Beenden mit Strg+D aus einer leeren !-Eingabe wurde behoben – Behoben: vim-Modus d, c und y mit einer gj- oder gk-Anzahl, die größer als die verbleibenden Zeilen ist und Text löscht oder kopiert; Wie Vim bewegen sie jetzt nur noch den Cursor
  • Problem behoben, bei dem /verify in /help und im Befehlsmenü / eine lange Beschreibung für Claude anstelle einer kurzen anzeigte
  • Die Aufwandsanzeige der Eingabeaufforderung wurde verbessert: Eine mitten in der Aufgabe vorgenommene Änderung besagt nun, dass möglicherweise auf Ihre nächste Nachricht gewartet wird, und die Notiz wird gelöscht, wenn sie nicht mehr zutrifft
  • Verbesserte WebFetch-Fehler in Cloud-Sitzungen: Ein Host, der nicht aufgelöst wird, wird jetzt als möglicherweise außerhalb der zulässigen Netzwerkdomänen liegend erklärt, sodass Claude den Host benennt, der zugelassen werden soll – Bedrock, Vertex, Foundry und Mantle wurden geändert, um die kürzere Systemeingabeaufforderung für Modellnamen zu verwenden, die Claude Code nicht erkennt, wie z. B. benutzerdefinierte Bereitstellungsnamen und Inferenzprofil-ARNs, selbst wenn diese vor Sonnet oder Haiku stehen; Legen Sie CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 fest, um die vollständige Eingabeaufforderung beizubehalten
  • Die automatischen Modellwechsel nach einer gekennzeichneten Nachricht wurden geändert, um auch Modellnamen abzudecken, die Claude Code nicht erkennt, wie z. B. benutzerdefinierte Bereitstellungsnamen. Stellen Sie CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 ein, um sie auszuschalten
  • Meldungen zum Nutzungslimit wurden geändert, um das 5-Stunden-Fenster als „5-Stunden-Limit“ statt als „Sitzungslimit“ zu bezeichnen. – Geänderte Cloud-Sitzungen, die vom CLI gestartet wurden, um ihre Namen und Filialnamen vom Server zu erhalten
  • Eingabeaufforderungs- und Agenten-Hooks wurden so geändert, dass maximal 24 gleichzeitig pro Sitzung ausgeführt werden, einschließlich Unteragenten, plus höchstens 12, die länger als das Timeout ihres Ereignisses gewartet haben; ein timeout unter 1 Sekunde zählt jetzt als 1 Sekunde – autoCompactWindow eines Subagenten geändert, um das durch CLAUDE_CODE_AUTO_COMPACT_WINDOW festgelegte Fenster zu verkleinern, wo es zuvor keine Auswirkung hatte; Das Fenster wird immer noch nie geöffnet – OpenTelemetry mcp_server.name geändert, um den tatsächlichen Namen von Remote-MCP-Servern mit fester URL zu melden, die von Plugins vom offiziellen Anthropic-Marktplatz deklariert werden, anstelle von custom – Claude-Code geändert, um das Senden des Ereignisses claude_code.safety_event OpenTelemetry zu stoppen – [VSCode] Problem behoben, bei dem Sitzungen mit einem bloßen Exit-Code endeten, wenn die Einstellungen Ihrer Organisation nicht geladen werden konnten oder beim Start abgelehnt wurden; Auf der Registerkarte wird jetzt der Grund angezeigt und die Option „Wiederholen“ oder „Erneut anmelden“ angeboten
  • [VSCode] Das Zurücksetzen des Nutzungslimits wurde geändert, um eine Uhrzeit anzuzeigen („Zurücksetzen um 15:10 Uhr“) und „5-Stunden-Limit“ zu sagen.
  • [Cloud-Sitzungen] Der Modellauswahl wurde eine Aufwandsstufe hinzugefügt, wenn Sie eine Routine erstellen oder bearbeiten, die in der Cloud ausgeführt wird
  • [Cloud-Sitzungen] Dem Setup-Skriptfeld in den Cloud-Umgebungseinstellungen wurde ein Bash-Editor mit Farben, Zeilennummern und einer Schaltfläche „Kopieren“ hinzugefügt
  • [Cloud-Sitzungen] Der Schritt, der angezeigt wird, wenn Claude ein Repository zu einer Cloud-Sitzung hinzufügt, wurde verbessert: Beim Öffnen wird jetzt eine kurze Tabelle dessen, was passiert ist, anstelle des rohen JSON angezeigt
  • [Cloud-Sitzungen] Problem behoben, bei dem eine unveränderte Nachricht nach einem fehlgeschlagenen Versand in einer Cloud-Sitzung manchmal zweimal gesendet wurde
  • [Cloud-Sitzungen] Ein Fehler bei der Erstellung einer Cloud-Umgebung wurde behoben, dessen Fehler nur als Toast außerhalb des geöffneten Dialogs angezeigt wurde. es erscheint jetzt im Dialog
  • [Cloud-Sitzungen] Problem behoben, bei dem „Bearbeiten“ im Menü einer Routine auf der Seite „Routinen“ zur Seite der Routine führte, ohne den Bearbeitungsdialog zu öffnen
  • [Remote Control] Es wurde ein Problem behoben, bei dem eine nicht archivierte Remote Control-Sitzung als funktionierend angezeigt wurde, bis ein Computer wiederhergestellt wurde. es wird jetzt als inaktiv angezeigt – [Claude Tag] Der Wiederholungshinweis von Claude Tag in Slack wurde verbessert, um das verwendete Modell zu benennen oder anzuzeigen, dass Ratengrenzen erreicht wurden, anstelle eines generischen API-Fehlers
  • [Claude Tag] Der Ein-/Ausschalter und die Agenteneinstellungen eines Claude-Tag-Kanals wurden behoben, die auf die Standardeinstellungen des Arbeitsbereichs zurückgesetzt wurden, wenn ein älterer privater Slack-Kanal öffentlich wird und eine neue ID erhält
  • [Claude Tag] Problem behoben, bei dem Claude in Slack in Kanälen, in deren Umgebung der Netzwerkzugriff auf „Keine“ eingestellt ist, nicht antwortete
  • [Claude Tag] Problem behoben, bei dem Claude in Slack manchmal eine Datei im falschen Thread postete, wenn sie in einem anderen Thread desselben Kanals antwortete
  • [Codeüberprüfung] Problem behoben, bei dem bei der Codeüberprüfung ein veralteter oder gar kein Commit überprüft wurde, wenn GitHub ein Push-Ereignis verspätet übermittelte; Es überprüft nun den aktuellen Commit der Pull-Anfrage

Englisches Original / English original

claude-code v2.1.312

What's changed

  • Added oidc.user_id_claim to the Claude apps gateway, to identify people by an id_token claim other than sub, such as Microsoft Entra ID's oid
  • Added click to send: in fullscreen, clicking the "to send now" hint under a queued message sends it right away, as its key does
  • Fixed managed settings and organization policy not being fetched for the rest of the session after signing in from the VS Code extension
  • Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place
  • Fixed per-directory and paths: skills not being found after a Bash cd deeper into a git repository
  • Fixed a rare case where the first reply after resuming a session in the terminal could be missing the next time the session was resumed
  • Fixed a command with an invalid name stopping all commands from loading, which could leave claude -p with no output
  • Fixed the Read tool sometimes failing on PDF pages with "pdftoppm failed: Could not write image" when the clean-up of old session files ran at the same time
  • Fixed the spinner, OpenTelemetry effort values and transcripts naming a newly picked effort level during a task before the model applied it; they now show the level in force
  • Fixed the /model and /effort cache warning saying the re-read waits for your next message; a change made while Claude is working can trigger it sooner
  • Fixed some sessions showing as waiting on you when the last message only mentioned items waiting on you mid-sentence
  • Fixed agent view restoring input text on the next launch after it was cleared with Ctrl+C just before exiting
  • Fixed agent view reopening in shell mode after exiting with Ctrl+D from an empty ! input
  • Fixed vim mode d, c and y with a gj or gk count larger than the lines left deleting or copying text; like Vim, they now only move the cursor
  • Fixed /verify showing a long description meant for Claude in /help and the / command menu instead of a short one
  • Improved the prompt's effort indicator: a change made mid-task now says it may wait for your next message, and the note clears when it no longer applies
  • Improved WebFetch errors in cloud sessions: a host that does not resolve is now explained as possibly outside the allowed network domains, so Claude names the host to allow
  • Changed Bedrock, Vertex, Foundry and Mantle to use the shorter system prompt for model names Claude Code doesn't recognize, such as custom deployment names and inference profile ARNs, even when they front Sonnet or Haiku; set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to keep the full prompt
  • Changed automatic model switches after a flagged message to also cover model names Claude Code doesn't recognize, such as custom deployment names; set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 to turn them off
  • Changed usage limit messages to call the 5-hour window the "5-hour limit" instead of the "session limit"
  • Changed cloud sessions started from the CLI to get their names and branch names from the server
  • Changed prompt and agent hooks to run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a timeout under 1 second now counts as 1 second
  • Changed a subagent's autoCompactWindow to lower the window set by CLAUDE_CODE_AUTO_COMPACT_WINDOW, where it had no effect before; it still never raises that window
  • Changed OpenTelemetry mcp_server.name to report the real name of fixed-URL remote MCP servers declared by plugins from the official Anthropic marketplace, instead of custom
  • Changed Claude Code to stop sending the claude_code.safety_event OpenTelemetry event
  • [VSCode] Fixed sessions ending on a bare exit code when your organization's settings couldn't be loaded or were refused at startup; the tab now says why and offers Retry or Sign in again
  • [VSCode] Changed usage limit resets to show a clock time ("Resets at 3:10 PM") and to say "5-hour limit"
  • [Cloud sessions] Added an effort level to the model picker when you create or edit a routine that runs in the cloud
  • [Cloud sessions] Added a Bash editor with colors, line numbers and a Copy button to the setup script box in cloud environment settings
  • [Cloud sessions] Improved the step shown when Claude adds a repository to a cloud session: opening it now shows a short table of what happened instead of raw JSON
  • [Cloud sessions] Fixed resending an unchanged message after a failed send in a cloud session sometimes running it twice
  • [Cloud sessions] Fixed a failed cloud environment creation showing its error only as a toast outside the open dialog; it now appears inside the dialog
  • [Cloud sessions] Fixed Edit in a routine's menu on the Routines page going to the routine's page without opening its edit dialog
  • [Remote Control] Fixed an unarchived Remote Control session showing as working until a computer reconnected; it now shows as idle
  • [Claude Tag] Improved Claude Tag's retry notice in Slack to name the model in use, or say rate limits were hit, instead of a generic API error
  • [Claude Tag] Fixed a Claude Tag channel's on/off switch and agent settings falling back to workspace defaults when an older private Slack channel goes public and gets a new ID
  • [Claude Tag] Fixed Claude in Slack not replying in channels whose environment has network access set to None
  • [Claude Tag] Fixed Claude in Slack sometimes posting a file in the wrong thread when it was answering in another thread of the same channel
  • [Code Review] Fixed Code Review reviewing an outdated commit, or none at all, when GitHub delivered a push event late; it now reviews the pull request's current commit
