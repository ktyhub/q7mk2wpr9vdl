Claude-Code v2.1.285

Was hat sich geändert?

– Umgebungsvariable CLAUDE_CODE_DISABLE_WEB_FETCH hinzugefügt, um das WebFetch-Tool zu deaktivieren

  • claude --desktop hinzugefügt, um die Claude-Desktop-App im aktuellen Verzeichnis oder in einer Sitzung mit --continue / --resume <id> zu öffnen – claude plugin configure <plugin> hinzugefügt, um die Optionen eines Plugins anzuzeigen und zu zeigen, welche nicht festgelegt sind, oder um neue Werte zu speichern, die von stdin mit --values-stdin gelesen wurden – <server>.<key>=<value> zu claude plugin install --config hinzugefügt, sodass die eigenen Einstellungen eines gebündelten .mcpb-MCP-Servers bei der Installation festgelegt werden können und er gestartet werden kann, ohne /plugin → Konfigurieren aufzurufen – Verwaltete Einstellung allowedProviders hinzugefügt, um einzuschränken, welche API-Anbieter eine Maschine verwenden darf (Anthropic API, ein benutzerdefinierter Endpunkt, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform auf AWS oder ein Cloud-Gateway). – Die Umgebungsvariable CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES wurde hinzugefügt, um das erneute Senden einer Nicht-Streaming-Fallback-Anfrage zu begrenzen, bei der eine Zeitüberschreitung aufgetreten ist
  • claude -p mit CLAUDE_CODE_FORK_SUBAGENT=1 behoben: Der eigene Agentenaufruf eines Subagenten läuft jetzt im Vordergrund, sodass der Subagent das Ergebnis des untergeordneten Agenten erhält – Problem behoben, bei dem Plugin- und Marketplace-Installationen und -Updates über SSH das in GIT_SSH oder in core.sshCommand Ihrer Git-Konfiguration festgelegte SSH-Programm ignorierten – Problem behoben, bei dem Claude Code den Start verweigerte, wenn das Betriebssystem das Lesen der verwalteten Einstellungsdatei verweigerte; Es gibt jetzt eine Warnung aus und startet ohne die Richtlinien dieser Datei. Andere Lesefehler und nicht analysierbare Dateien stoppen jede Sitzung – Behoben: Cloud-Sitzungen, die nach der Komprimierung ihrer Konversation neu gestartet wurden und die nächste Aktualisierung eines Artefakts ablehnten, das die Sitzung bereits gelesen oder veröffentlicht hatte – Problem behoben, bei dem claude plugin disable und enable mit einer vollständigen name@marketplace-ID einen Einstellungseintrag in einer anderen Groß-/Kleinschreibung anstelle der des installierten Plugins änderten – Problem behoben, bei dem Dateien, die an eine über die Fernbedienung gesendete Nachricht angehängt waren, nach einem einzigen fehlgeschlagenen Download weggelassen wurden; Ein Netzwerkfehler, eine Zeitüberschreitung oder ein Serverfehler wird jetzt bis zu zweimal wiederholt – Das Wechseln von Modellen während der Sitzung mit einer set_model-Anfrage (z. B. setModel des Agenten SDK) wurde behoben, wodurch das neue Modell bis zum Neustart auf dem integrierten Ausgabe-Token-Limit und dem automatischen Komprimierungsfenster belassen wurde – Korrigiert wurden redigierte Protokolle und Transkripte, die einen Teil eines URL-Passworts zeigten, das @ enthielt, oder das gesamte Passwort, wenn die URL ihr @ als %40 schreibt – SSH-Passphrase und Aufforderungen zum neuen Host von Worktree und /teleport-Abrufen, die das Terminal übernehmen, wurden korrigiert; Diese Abrufe schlagen jetzt schnell fehl, anstatt zu fragen – Das Abschalten eines hinzugefügten MCP-Servers während der Sitzung in SDK- und -p-Sitzungen wurde behoben, sodass seine Tools verfügbar blieben – claude -p --permission-prompt-tool behoben: Die Berechtigungsanfrage eines Hintergrund-Subagenten geht jetzt an das Eingabeaufforderungstool, anstatt automatisch abgelehnt zu werden
  • claude mcp list und claude mcp get sowie der nicht gefundene Fehler von claude mcp remove, login und logout wurden behoben, wobei Zeilenumbrüche und Terminal-Escape-Sequenzen aus MCP-Servernamen und -Werten gedruckt wurden – Problem behoben, bei dem die Sandbox bei jeder Ausführung vieler Inline-Skripte (python3 -c, node -e) automatisch zur Genehmigung aufforderte, nur weil sie = enthielten – Problem behoben, bei dem Fork-Subagenten den Planmodus oder den dontAsk-Modus der Sitzung nicht beibehalten: Ein Fork wird jetzt im Berechtigungsmodus seines übergeordneten Zweigs ausgeführt und kann den Planmodus nicht verlassen
  • Problem mit der Meldung claude remote-control --help behoben, dass --[no-]chrome standardmäßig auf die /chrome-Einstellung der Maschine eingestellt ist; Gespawnte Sitzungen halten Claude in Chrome ausgeschaltet, es sei denn, --chrome wird übergeben – Problem behoben, bei dem Hintergrund-Subagenten im automatischen Modus nach jedem Bericht eine zweite, redundante Antwort aufforderten – Die Erstellung von Cloud-Sitzungen wurde behoben und /remote-env liest nur die neuesten 20 Umgebungen eines Kontos
  • Problem behoben, bei dem Remote Control eine Nachricht als gelesen markierte, sobald sie ankam, statt als Claude sie startete, und eine noch in der Warteschlange befindliche Nachricht verlor, wenn das Terminal beendet wurde (sie kommt jetzt beim nächsten Fortsetzen an) – Die Installation eines Plugins mit claude plugin install oder /plugin wurde behoben, indem es in den Cache oder Datenordner eines installierten Plugins verschoben wurde, wenn sich ihre IDs nur in ., -, @ oder (macOS, Windows) capitals unterscheiden; Die Installation wird jetzt abgelehnt – Behoben: Hooks und SDK-Berechtigungsrückrufe, bei denen ein fehlender oder veralteter Plan bei ExitPlanMode angezeigt wurde, wenn der Plan in derselben Antwort geschrieben wurde – Die erste Antwort in Cloud-Sitzungen wurde behoben, die zehn Millisekunden zu spät eintraf, eine Regression in 2.1.283 – Behoben: Sitzungen, die sich mit ANTHROPIC_AUTH_TOKEN gegenüber dem Anthropic API authentifizieren, laden nie die Richtlinien der Organisation – Ein fehlgeschlagener agent()-, parallel()- oder pipeline()-Aufruf, auf den ein Workflow-Skript später oder überhaupt nicht wartet, wurde behoben und als unbehandelte Versprechensablehnung behandelt, die eine Hintergrundsitzung beenden konnte – Problem behoben, bei dem synchrone Hooks Claude Code hängen ließen, während ein Hintergrundprozess, den der Hook startete (z. B. some-daemon &), seine Ausgabe offen hielt; Der Hook wird nun beendet, kurz nachdem sein eigener Prozess beendet wurde – Problem behoben, bei dem WebFetch eine ratenbegrenzte Domänensicherheitsüberprüfung als Netzwerk- oder Unternehmensrichtlinienblock meldete
  • Es wurde behoben, dass das Vollbild-Strg+O-Transkript kurzzeitig einfrierte, wenn es abwechselnd mit Hunderten von Datei-Lesevorgängen oder -Suchen geöffnet wurde; Toolaufrufe, die beim Öffnen des Transkripts noch ausgeführt werden, zeigen jetzt ihre Ergebnisse an, wenn sie beendet sind – Die Fehler modelTimeoutException und serviceUnavailableException in der Mitte des Streams von Amazon Bedrock wurden behoben, bei denen statt der Fehlermeldung ein roher JSON-Text angezeigt wurde – Behoben: /autofix-pr und /schedule sagen, dass die Claude GitHub-App nicht auf einem Repository installiert ist, dessen Installationsstatus noch nicht überprüft wurde – Das Verwerfen einer Zeile (x) in /artifacts wurde behoben, wodurch die Verknüpfung ihrer Datei mit dem Artefakt aufgehoben wurde, sodass beim erneuten Veröffentlichen derselben Datei ein neues Artefakt erstellt wurde, anstatt es zu aktualisieren
  • Problem behoben, bei dem das Artefakt-Tool nach dem Zurückspulen einer Konversation (Esc Esc) den neueren Inhalt einer Datei überschreibt, den Claude in den zurückgespulten Runden nur gelesen hatte; Die Veröffentlichung wird nun abgelehnt, bis Claude die Datei erneut liest – Es wurde eine Artifact-Zulassungsregel („Nicht erneut fragen“) behoben, die es dem Artifact-Tool ermöglichte, eine Datei außerhalb der Arbeitsverzeichnisse zu veröffentlichen, ohne danach zu fragen; Fügen Sie den Ordner der Datei mit --add-dir hinzu, damit die Regel ihn abdeckt

B. server:8443.key – Es wurde ein seltener Authentifizierungsfehler behoben, der auftrat, wenn zwei Sitzungen gleichzeitig eine Anmeldeaktualisierungssperre wiederherstellten, die von einem abgestürzten Prozess hinterlassen wurde – Die Berechtigungsprüfung des PowerShell-Tools wurde behoben, bei der die Deny- und Ask-Regeln übersprungen wurden und dieser Fehler für spätere Prüfungen zwischengespeichert wurde, wenn der Befehlsparser nicht gestartet werden konnte (z. B. wenn der Computer nicht über genügend Arbeitsspeicher verfügte). – Problem behoben, bei dem /ultrareview-Uploads unter macOS und Linux bei einigen ungewöhnlichen Dateinamen langsam liefen und bei der Überprüfung der Anmeldedaten Datei- oder Ordnernamen mit vielen Sicherungs- oder Editormarkierungen fehlten – Ein abgebrochener Shell-Befehl oder Hook wurde behoben, der immer noch startete und bis zum Ende lief, wenn der Abbruch während der Einrichtung eintraf
  • Vim-Modus behoben: Nach der Bearbeitung im externen Editor (Strg+G) unterbricht x oder r im NORMAL-Modus einen Platzhalter für eingefügten Text am Ende der Eingabeaufforderung nicht mehr – Es wurde ein Problem behoben, bei dem Antworten, die durch den Ausgabeinhaltsfilter des API blockiert wurden, manchmal minutenlang erneut gesendet und wiederholt wurden, anstatt den Fehler des Filters sofort anzuzeigen – Problem behoben, bei dem Plugins einen gebündelten MCP-Server .mcpb, der noch konfiguriert werden muss, stillschweigend übersprungen haben: /plugin, die Installationsmeldung und claude plugin install sagen dies jetzt und verweisen auf Konfigurieren – Problem behoben, bei dem das Komprimieren oder Fortsetzen einer Sitzung fehlschlug, ohne Verlauf geöffnet wurde oder abstürzte, wenn das gespeicherte Transkript eine Komprimierungsmarkierung oder einen Schleifenaktivierungseintrag mit fehlenden oder fehlerhaften Feldern enthielt – WSL: Behoben: /ultrareview weigerte sich, einen Checkout auf ein Linux-Volume hochzuladen, wenn der Name einer geänderten Datei einen Doppelpunkt hat oder mit einem Punkt oder Leerzeichen endet
  • Problem behoben, bei dem CLAUDE_CODE_RESUME_INTERRUPTED_TURN eine Runde, die bei --max-turns geendet hatte, noch einmal durchführte – Behebung eines Problems mit der Anmeldung, die ewig warten konnte, nachdem der Browser erfolgreich war

Zeilenbeschriftungen in einer Markdown-Tabelle – Ein kurzes Einfrieren (bis zu einer Sekunde) während längerer Sitzungen außerhalb des Vollbildmodus wurde behoben, das nach /clear oder /compact wieder auftrat – Es wurde ein Problem behoben, bei dem eine genehmigte Bearbeitung nie durchgeführt wurde, wenn das Ziel ein Gerät war, beispielsweise eine mit /dev/null verknüpfte Datei, und die Genehmigung aus der IDE-Diff-Ansicht kam oder die Bearbeitung geändert wurde – Es wurde behoben, dass eine fehlgeschlagene API-Anfrage bis zu 21 Mal wiederholt wurde, wenn das Streaming immer wieder fehlschlug; Der Nicht-Streaming-Fallback teilt jetzt das Wiederholungsbudget der Anfrage, anstatt einen neuen Satz Wiederholungen zu erhalten

claude-code v2.1.285

What's changed

  • Added CLAUDE_CODE_DISABLE_WEB_FETCH environment variable to turn off the WebFetch tool
  • Added claude --desktop to open the Claude desktop app on the current directory, or on a session with --continue / --resume <id>
  • Added claude plugin configure <plugin> to show a plugin's options and which are unset, or save new values read from stdin with --values-stdin
  • Added <server>.<key>=<value> to claude plugin install --config, so a bundled .mcpb MCP server's own settings can be set at install time and it starts without visiting /plugin → Configure
  • Added allowedProviders managed setting to limit which API providers a machine may use (Anthropic API, a custom endpoint, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform on AWS, or a Cloud gateway)
  • Added CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES environment variable to cap re-sends of a non-streaming fallback request that timed out
  • Fixed claude -p with CLAUDE_CODE_FORK_SUBAGENT=1: a subagent's own Agent call now runs in the foreground, so the subagent gets the child's result
  • Fixed plugin and marketplace installs and updates over SSH ignoring the ssh program set in GIT_SSH or in your git config's core.sshCommand
  • Fixed Claude Code refusing to start when the OS denies reading the managed settings file; it now warns and starts without that file's policies. Other read errors and unparseable files stop every session
  • Fixed cloud sessions that restarted after their conversation was compacted refusing the next update to an artifact the session had already read or published
  • Fixed claude plugin disable and enable with a full name@marketplace id changing a settings entry in another letter case instead of the installed plugin's own
  • Fixed files attached to a message sent over Remote Control being left out after a single failed download; a network error, timeout or server error is now retried up to twice
  • Fixed switching models mid-session with a set_model request (such as the Agent SDK's setModel) leaving the new model on the built-in output-token limit and auto-compact window until restart
  • Fixed redacted logs and transcripts showing part of a URL password that contains @, or all of it when the URL writes its @ as %40
  • Fixed SSH passphrase and new-host prompts from worktree and /teleport fetches taking over the terminal; these fetches now fail fast instead of asking
  • Fixed switching off an MCP server added mid-session in SDK and -p sessions leaving its tools available
  • Fixed claude -p --permission-prompt-tool: a background subagent's permission request now goes to the prompt tool instead of being auto-denied
  • Fixed claude mcp list and claude mcp get, and the not-found error of claude mcp remove, login and logout, printing line breaks and terminal escape sequences from MCP server names and values
  • Fixed sandbox auto-allow asking for approval on every run of many inline scripts (python3 -c, node -e) just because they contain =
  • Fixed fork subagents not keeping the session's plan mode or dontAsk mode: a fork now runs under its parent's permission mode and cannot exit plan mode
  • Fixed claude remote-control --help saying --[no-]chrome defaults to the machine's /chrome setting; spawned sessions keep Claude in Chrome off unless --chrome is passed
  • Fixed background subagents in auto mode prompting a second, redundant reply after each report
  • Fixed cloud session creation and /remote-env reading only the newest 20 of an account's environments
  • Fixed Remote Control marking a message as read as soon as it arrived instead of when Claude started on it, and losing a message still queued when the terminal quit (it now arrives on the next resume)
  • Fixed installing a plugin with claude plugin install or /plugin putting it into an installed plugin's cache or data folder when their ids differ only in ., -, @ or (macOS, Windows) capitals; the install is now refused
  • Fixed hooks and SDK permission callbacks seeing a missing or outdated plan on ExitPlanMode when the plan was written in the same response
  • Fixed the first reply in cloud sessions arriving tens of milliseconds late, a regression in 2.1.283
  • Fixed sessions that authenticate with ANTHROPIC_AUTH_TOKEN against the Anthropic API never loading the organization's policy
  • Fixed a failed agent(), parallel() or pipeline() call that a workflow script awaits later, or not at all, being treated as an unhandled promise rejection, which could end a background session
  • Fixed synchronous hooks hanging Claude Code while a background process the hook started (for example some-daemon &) kept its output open; the hook now finishes shortly after its own process exits
  • Fixed WebFetch reporting a rate-limited domain safety check as a network or enterprise policy block
  • Fixed the fullscreen ctrl+o transcript freezing briefly when opened on turns with hundreds of file reads or searches; tool calls still running when the transcript opens now show their results when they finish
  • Fixed Amazon Bedrock mid-stream modelTimeoutException and serviceUnavailableException errors showing a raw JSON body instead of the error message
  • Fixed /autofix-pr and /schedule saying the Claude GitHub App is not installed on a repository whose install status had not been checked yet
  • Fixed dismissing a row (x) in /artifacts unlinking its file from the artifact, so publishing the same file again created a new artifact instead of updating it
  • Fixed Artifact tool publishes after a conversation rewind (Esc Esc) overwriting a file's newer content that Claude had read only in the rewound turns; the publish is now refused until Claude re-reads the file
  • Fixed an Artifact allow rule ("don't ask again") letting the Artifact tool publish a file outside the working directories without asking; add the file's folder with --add-dir for the rule to cover it
  • Fixed /cost and SDK modelUsage reporting a turn under the wrong model when the server answered a refusal with a different fallback model than the client expected
  • Fixed the Artifact tool so that publishing a page no longer lets Claude overwrite its source file without re-reading it when Claude's earlier read was cut short or the file had changed since
  • Fixed auto mode skipping its classifier for Artifact tool asset uploads and reads of someone else's artifact when you had approved that artifact earlier in another permission mode
  • Fixed a misleading "core.worktree is set" error from /ultrareview when the project folder briefly could not be read
  • Fixed /ultrareview on macOS and Linux failing to upload the working tree from a git worktree whose per-worktree config sets core.longpaths
  • Fixed the Artifact tool sometimes reporting a publish as a conflict with another session after retrying a temporary server error, when the first attempt had actually succeeded
  • Fixed /ultrareview uploads including uncommitted changes to credential files whose name has a colon before the extension, such as server:8443.key
  • Fixed a rare auth failure when two sessions recover a login refresh lock left by a crashed process at the same time
  • Fixed the PowerShell tool's permission check skipping deny and ask rules, and caching that failure for later checks, when its command parser failed to start (for example when the machine was out of memory)
  • Fixed /ultrareview uploads on macOS and Linux running slowly on some unusual file names, and their credential-file check missing file or folder names with many backup or editor marks
  • Fixed a cancelled shell command or hook still starting, and running to its end, when the cancel arrived while it was being set up
  • Fixed vim mode: after editing in the external editor (Ctrl+G), x or r in NORMAL mode no longer breaks a pasted-text placeholder at the end of the prompt
  • Fixed responses blocked by the API's output content filter being re-sent and retried, sometimes for minutes, instead of showing the filter's error right away
  • Fixed plugins silently skipping a bundled .mcpb MCP server that still needs configuration: /plugin, the install message and claude plugin install now say so and point to Configure
  • Fixed compacting or resuming a session failing, opening without its history, or crashing when its saved transcript holds a compaction marker or loop wakeup entry with missing or malformed fields
  • WSL: Fixed /ultrareview refusing to upload a checkout on a Linux volume when a changed file's name has a colon or ends in a dot or space

  • Fixed sign-in that could wait forever after the browser showed success

  • Fixed cloud sessions reporting the uploads folder as missing before any file had been uploaded

  • Fixed claude attach, logs, stop, respawn and rm starting a new session with the command name as its prompt when options came before it, such as from a shell alias

  • Fixed &nbsp; showing as literal text in the terminal when a reply uses it to indent text, such as row labels in a markdown table
