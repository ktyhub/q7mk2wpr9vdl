claude-code v2.1.267

Patch Veröffentlicht9. Sept. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.267

Was hat sich geändert?

  • maxEffortLevel-Einstellung hinzugefügt (oberste Ebene oder pro Modell unter modelSettings): Begrenzt das Aufwandsniveau bei jedem Anbieter, einschließlich Bedrock, Vertex und Foundry; Benutzer können immer noch eine niedrigere Stufe wählen – --system-prompt-snapshot off hinzugefügt, um die Systemaufforderung bei jeder Anfrage frisch darzustellen, anstatt die aufgezeichnete Aufforderung der Konversation wiederzuverwenden (zur Iteration des Aufforderungstexts). – Behoben: Geplante Cowork-Aufgaben in der Cloud schlugen beim Start für Organisationen fehl, deren verwaltete Einstellungen Sandboxing erfordern – Problem behoben, bei dem /context und andere lokale Befehlsausgaben auf mobilen clients leer waren – Problem behoben, bei dem Umschalt+Eingabetaste und Wahl+Rücktaste nicht funktionierten, nachdem die Verbindung zu einer tmux- oder ssh-Sitzung innerhalb einer Agentenansicht wiederhergestellt wurde – Der schwache Header der letzten Eingabeaufforderung wurde behoben, der nicht oben in der Konversation angezeigt wurde, wenn im Vollbildmodus nach oben gescrollt wurde – Problem behoben, bei dem Workflow-agent()-Aufrufe mit großen Ausgabeschemata im automatischen Modus abgelehnt wurden, anstatt vom Sicherheitsklassifikator überprüft zu werden – Es wurde ein Fall behoben, bei dem ein Marktplatz-Eintrittspfad, der einen Backslash enthielt, die Eindämmungsprüfung für abgerufene Marktplätze unter macOS und Linux umgehen konnte – Behoben: Abgelaufene AWS- oder Google Cloud-Anmeldeinformationen unter einer Host-App wie Claude Desktop wurden zehnmal mit der Fehlermeldung „Anfrage fehlgeschlagen“ wiederholt, bevor der Fehler bei der erneuten Authentifizierung auftrat – Das Wiederaufnehmen einer Sitzung, nachdem /compact oder ein anderer Slash-Befehl über -p --resume ausgeführt wurde, wurde behoben: ein falsches „Weiter an der Stelle, an der Sie aufgehört haben.“ Drehung wird nicht mehr eingefügt – Das Wiederaufnehmen einer großen Sitzung (Transkript über 5 MB) wurde behoben: Parallele Tool-Aufrufe und ihre Hook-Ausgabe werden nicht mehr aus der neu geladenen Konversation gelöscht – Die verwalteten allowedHttpHookUrls, httpHookAllowedEnvVars und allowedChannelPlugins wurden so korrigiert, dass sie nichts, nicht alles, zulassen, wenn sie nicht lesbar sind – /login auf Computern behoben, deren verwaltete Einstellungen eine Claude-Apps-Gateway-Anmeldung erfordern: Esc schließt jetzt den Dialog, anstatt nichts zu tun
  • Problem behoben, bei dem Artefaktveröffentlichungen durch eine unterbrochene Verbindung während des Hochladens unterbrochen wurden: Sie versuchen jetzt einmal erneut, wenn Claude Code erkennen kann, dass der Upload nie abgeschlossen wurde, anstatt ein unbekanntes Ergebnis zu melden
  • Problem behoben, bei dem effort:-Frontmatter bei benutzerdefinierten Befehlen, Fertigkeiten und Subagenten bei Modellen ignoriert wurde, deren Standardaufwand immer noch angeheftet ist (Opus 4.7, Opus 4.8, Fable 5) – Es wurde behoben, dass die Artefaktveröffentlichung mit einem nicht hilfreichen Fehler fehlschlug, wenn die Auslagerungsdatei kein gültiges UTF-8 ist oder ein Ersetzungszeichen (U+FFFD) enthält. Der Fehler benennt nun die zu behebende Zeile und Spalte – Das Verzeichnismenü claude agents @ listete keine Repositorys auf, die nach dem Start der Sitzung erstellt wurden – Behoben: Fernsteuerungs-clients, die einer Claude Desktop- oder VS Code-Sitzung beitreten, zeigten einen veralteten Berechtigungsmodus an, bis er erneut geändert wurde – Problem behoben, bei dem claude remote-control jede angehängte Sitzung beendete und löschte, wenn die Serveranmeldeinformationen abgelaufen waren (etwa 30 Tage nach dem Start); Der Host registriert sich nun erneut und macht weiter – Das Flackern der Nutzungslimitwarnung während einer Sitzung, wenn Anfragen für verschiedene Modelle oder Modi unterschiedliche Limitfenster meldeten, wurde behoben – Es wurde behoben, dass frühere Argumente verworfen wurden, wenn ein MCP-Server ein bereits geladenes Modell erneut sendete oder ein integriertes Tool erneut renderte – Ein Tool wurde behoben, das mitten im Gespräch, von einem nicht verbundenen MCP-Server oder einem Upgrade verschwand, wodurch die Toolliste neu geschrieben und frühere Überlegungen verworfen wurden – Ein Hintergrund-Worker wurde behoben, der von einer Konversation abgezweigt wurde und EnterWorktree mitten in der Sitzung zum Toolblock der Konversation hinzufügte, wodurch die Wiederverwendung des Eingabeaufforderungs-Cache unterbrochen wurde – Problem behoben, bei dem MCP- und Plugin-Tools während der Sitzung zur Tool-Liste in Sitzungen ohne ToolSearch hinzugefügt wurden, wodurch die Wiederverwendung des Prompt-Cache unterbrochen wurde; Unterstützte Modelle erhalten sie jetzt als verzögerte Definitionen
  • Problem beim Modellwechsel behoben, bei dem /model jede Werkzeugdefinition erneut gesendet hat (ein Prompt-Cache-Fehler); Der Commit- und PR-Attributionstext kommt jetzt als Konversationsnotiz an, die über Modelländerungen informiert – Behoben: Wiederaufgenommene Sitzungen schreiben das Inline-Toolset neu, wenn ein MCP-Connector zu einem anderen Zeitpunkt als zuvor die Verbindung wiederherstellt
  • Problem behoben, bei dem fortgesetzte Sitzungen Werkzeugbeschreibungen neu gerendert haben, anstatt die aufgezeichneten wiederzugeben, wenn in der ersten Runde ein Werkzeug ausgeführt wurde – Fehler im Prompt-Cache behoben und erweitertes Denken verloren gegangen, wenn sich die Tools eines claude.ai-Connectors zwischen einer Sitzung und ihrer Fortsetzung ändern – Behoben: Wiederaufgenommene Sitzungen überschreiben frühere MCP-Tool-Ankündigungen (und verwerfen erweitertes Denken), bevor ihre Konnektoren wieder verbunden werden – Eine Unterbrechung des Prompt-Cache behoben, wenn eine Konversation im Druckmodus (-p) interaktiv fortgesetzt wird: Das System-Prompt-Präfix ändert sich nicht mehr
  • Das /diff-Bedienfeld wurde verbessert: Es blinkt nicht mehr „0 Dateien geändert“ und kein Spinner mehr vor dem Beruhigen, und sein leerer Zustand wird im Bedienfeld zentriert – Die Beschreibungsanleitung des Bash-Tools wurde verbessert, sodass Claude in einfachen Worten beschreibt, was ein Befehl tut, anstatt den Befehl zu wiederholen – Verbesserte Sandbox-Anleitung, sodass Claude /copy vorschlägt, wenn clipboard-Befehle wie pbcopy innerhalb der Sandbox fehlschlagen – Verbesserte --resume-Erstrenderzeit für Sitzungen mit vielen Bash-Tool-Aufrufen
  • Verbesserte Reaktionsfähigkeit bei Eingabeaufforderungen: Tastenanschläge warten nicht mehr gelegentlich einen Frame hinter dem Spinner oder Streaming-Repaints – Verbesserte Stabilität des Prompt-Cache: Subagenten und Sitzungen, die mit --system-prompt oder --append-system-prompt gestartet wurden, zeichnen die System-Prompt- und Tool-Definitionen jetzt einmal auf, anstatt sie erneut zu rendern
  • Verbesserte Veröffentlichungsfehler im Artefakt-Tool: Wenn eine Veröffentlichung abgelehnt wird, wird in der Meldung jetzt der Grund dafür angezeigt und was dagegen zu tun ist – Selbstgehosteter Läufer: --use-anthropic-git-proxy wurde so geändert, dass es bei der Registrierung an den Server gemeldet wird und eine Warnung für jede Sitzung ausgibt, die weiterhin über den alten Git-Proxy klont
  • Gateway: forward_user_identity-Upstreams wurden geändert, um eine 429 unverändert an einen Entwickler zurückzugeben, dessen E-Mail weitergeleitet wurde, anstatt ein Failover zum nächsten Upstream durchzuführen, sodass die Pro-Benutzer-Grenzwerte des Proxys gelten – [VSCode] Es wurde behoben, dass der Erweiterungshost beim Forken, Bearbeiten einer früheren Nachricht oder Zurückspulen in einer Konversation, deren gespeichertes Transkript einen übergeordneten cyclic-Link enthält, bei 100 % CPU hängen blieb
  • [VSCode] Das Einfügen eines Screenshots auf WSL2/WSLg wurde korrigiert, wodurch rohe Bildbytes in die Chat-Eingabe eingefügt wurden; Das Bild wird nun angehängt, wenn das clipboard es bereitstellt, andernfalls wird das Einfügen ignoriert
  • [VSCode] Problem behoben, bei dem Chat-Diff-Blöcke immer mit einem dunklen Editor-Design gerendert wurden; Sie folgen jetzt dem aktiven VS-Code-Farbthema, einschließlich hohem Kontrast
  • [VSCode] Die gemischte Darstellung von Rechts-nach-Links- und englischem Text in der falschen Reihenfolge beim Eingeben der Nachrichteneingabe wurde behoben – [VSCode] Problem behoben, bei dem das Akzeptieren einer Bearbeitung in der Diff-Ansicht einer Datei mit Windows-Zeilenenden (CRLF) mit der Fehlermeldung „String not found in file“ fehlschlug.
  • [VSCode] @-Erwähnungen behoben, bei denen Dateien gelöscht wurden, deren Pfade Leerzeichen enthalten – [VSCode] Es wurde behoben, dass die Sitzungslistenansicht in Windows, die über Remote-SSH verbunden waren, nicht geladen werden konnte, wenn der Arbeitsbereichsordner nur auf dem Remote-Host vorhanden war
  • [VSCode] Außer Kontrolle geratene Ripgrep-Prozesse beim Anzeigen von Dateien in großen oder Symlink-lastigen Arbeitsbereichen wurden behoben
  • [Claude Code im Web] Problem behoben, bei dem GitHub Enterprise Server-Sitzungen Ihr GitHub-Konto als getrennt anzeigten, sobald sein Token abgelaufen war; PR- und Issue-Vorgänge aktualisieren es jetzt automatisch
  • [Claude Code im Web] Fehler bei gh- und GitHub API-Anrufen in Organisationen ohne die Claude GitHub-App behoben; Sie verwenden jetzt Ihr verbundenes GitHub-Konto und sagen dies, wenn keines verbunden ist
  • [Claude Tag] Den voreingestellten Verbindungsformularen in den Admin-Einstellungen von Claude Tag wurde ein Link „Benutzerdefinierten Connector verwenden“ hinzugefügt, sodass Sie zu einer benutzerdefinierten Verbindung wechseln können, ohne von vorne beginnen zu müssen
  • [Claude Tag] Problem mit der Antwort von Claude „Der API hat die Anfrage als ungültig abgelehnt“ behoben, wenn die Organisation keine Nutzungsguthaben mehr hat; Die Antwort sagt es jetzt und erklärt, wie man weitere hinzufügen kann
  • [Claude Tag] Problem behoben, bei dem Thread-Anfragen zum Bearbeiten oder Löschen einer Nachricht, die Claude auf der obersten Ebene des Kanals gepostet hatte, mit einer Korrektur beantwortet wurden, anstatt die Sitzung zu erreichen, die sie gepostet hatte
  • [Claude Tag] Problem behoben, bei dem Connect bei Tool-Zugriffsanfragen unter Admin-Einstellungen > Überprüfungsanfragen mit „Autorisierung fehlgeschlagen“ fehlschlug oder das angeforderte Zugriffspaket als gelöscht angezeigt wurde

Englisches Original / English original

claude-code v2.1.267

What's changed

  • Added maxEffortLevel setting (top-level or per model under modelSettings): caps the effort level on every provider, including Bedrock, Vertex and Foundry; users can still pick a lower level
  • Added --system-prompt-snapshot off to render the system prompt fresh on every request instead of reusing the conversation's recorded prompt (for iterating on prompt text)
  • Fixed Cowork scheduled tasks in the cloud failing at startup for organizations whose managed settings require sandboxing
  • Fixed /context and other local command output rendering blank on mobile clients
  • Fixed shift+enter and option+backspace not working after reconnecting to a tmux or ssh session inside an agent view
  • Fixed the dim last-prompt header not appearing at the top of the conversation when scrolling up in fullscreen mode
  • Fixed Workflow agent() calls with large output schemas being refused in auto mode instead of being checked by the safety classifier
  • Fixed a case where a marketplace entry path containing a backslash could bypass the containment check for fetched marketplaces on macOS and Linux
  • Fixed expired AWS or Google Cloud credentials under a host app such as Claude Desktop retrying ten times with a generic "request failed" before the re-authenticate error appeared
  • Fixed resuming a session after /compact or another slash command ran via -p --resume: a spurious "Continue from where you left off." turn is no longer inserted
  • Fixed resuming a large session (transcript over 5 MB): parallel tool calls and their hook output are no longer dropped from the reloaded conversation
  • Fixed managed allowedHttpHookUrls, httpHookAllowedEnvVars and allowedChannelPlugins to admit nothing, not everything, when unreadable
  • Fixed /login on machines whose managed settings require Claude apps gateway sign-in: Esc now closes the dialog instead of doing nothing
  • Fixed artifact publishes cut off by a dropped connection mid-upload: they now retry once when Claude Code can tell the upload never completed, instead of reporting an unknown outcome
  • Fixed effort: frontmatter on custom commands, skills, and subagents being ignored on models whose default effort is still pinned (Opus 4.7, Opus 4.8, Fable 5)
  • Fixed artifact publish failing with an unhelpful error when the page file isn't valid UTF-8 or contains a replacement character (U+FFFD); the error now names the line and column to fix
  • Fixed claude agents @ directory menu not listing repositories created after the session started
  • Fixed Remote Control clients that join a Claude Desktop or VS Code session showing a stale permission mode until it was changed again
  • Fixed claude remote-control exiting and dropping every attached session when its server credential expires (about 30 days after start); the host now re-registers and keeps going
  • Fixed the usage-limit warning flickering on and off during a session when requests for different models or modes report different limit windows
  • Fixed earlier reasoning being dropped when an MCP server re-sends, or a built-in tool re-renders, a tool the model already loaded
  • Fixed a tool that disappears mid-conversation, from a disconnected MCP server or an upgrade, rewriting the tool list and discarding earlier thinking
  • Fixed a background worker forked from a conversation adding EnterWorktree to the conversation's tool block mid-session, which broke prompt-cache reuse
  • Fixed mid-session MCP and plugin tools being added to the tool list in sessions without ToolSearch, which broke prompt-cache reuse; supported models now receive them as deferred definitions
  • Fixed switching models with /model re-sending every tool definition (a prompt-cache miss); commit and PR attribution text now arrives as a conversation note that updates on model changes
  • Fixed resumed sessions rewriting the inline tool set when an MCP connector reconnects at a different moment than before
  • Fixed resumed sessions re-rendering tool descriptions instead of replaying the recorded ones when the first turn ran a tool
  • Fixed prompt-cache misses and dropped extended thinking when a claude.ai connector's tools change between a session and its resume
  • Fixed resumed sessions rewriting earlier MCP tool announcements (and dropping extended thinking) before their connectors reconnect
  • Fixed a prompt-cache break when a print-mode (-p) conversation is resumed interactively: the system prompt prefix no longer changes
  • Improved the /diff panel: it no longer flashes "0 files changed" and a spinner before settling, and its empty state is centered in the panel
  • Improved the Bash tool's description guidance so Claude describes what a command does in plain words instead of echoing the command
  • Improved sandbox guidance so Claude suggests /copy when clipboard commands such as pbcopy fail inside the sandbox
  • Improved --resume first-render time for sessions with many Bash tool calls
  • Improved prompt input responsiveness: keystrokes no longer occasionally wait a frame behind spinner or streaming repaints
  • Improved prompt-cache stability: subagents and sessions started with --system-prompt or --append-system-prompt now record the system prompt and tool definitions once instead of re-rendering them
  • Improved Artifact tool publish errors: when a publish is refused, the message now says why and what to do about it
  • Self-hosted runner: Changed --use-anthropic-git-proxy to be reported to the server at registration and to print a warning for each session that still clones through the legacy git proxy
  • Gateway: Changed forward_user_identity upstreams to return a 429 as-is to a developer whose email was forwarded, instead of failing over to the next upstream, so the proxy's per-user limits hold
  • [VSCode] Fixed the extension host hanging at 100% CPU when forking, editing an earlier message, or rewinding in a conversation whose saved transcript contains a cyclic parent link
  • [VSCode] Fixed pasting a screenshot on WSL2/WSLg inserting raw image bytes into the chat input; the image is now attached when the clipboard provides it, otherwise the paste is ignored
  • [VSCode] Fixed chat diff blocks always rendering with a dark editor theme; they now follow the active VS Code color theme, including high contrast
  • [VSCode] Fixed mixed right-to-left and English text rendering in the wrong order while typing in the message input
  • [VSCode] Fixed accepting an edit in the diff view on a file with Windows (CRLF) line endings failing with "String not found in file"
  • [VSCode] Fixed @-mentions dropping files whose paths contain spaces
  • [VSCode] Fixed the sessions list view failing to load in windows connected over Remote-SSH when the workspace folder exists only on the remote host
  • [VSCode] Fixed runaway ripgrep processes when viewing files in large or symlink-heavy workspaces
  • [Claude Code on the web] Fixed GitHub Enterprise Server sessions showing your GitHub account as disconnected once its token expired; PR and issue operations now refresh it automatically
  • [Claude Code on the web] Fixed gh and GitHub API calls failing in organizations without the Claude GitHub App; they now use your connected GitHub account and say so when none is connected
  • [Claude Tag] Added a "Use a custom connector" link to the preset connection forms in Claude Tag admin settings, so you can switch to a custom connection without starting over
  • [Claude Tag] Fixed Claude replying "The API rejected the request as invalid" when the organization has run out of usage credits; the reply now says so and explains how to add more
  • [Claude Tag] Fixed thread requests to edit or delete a message Claude posted at the channel's top level being answered with a correction instead of reaching the session that posted it
  • [Claude Tag] Fixed Connect on Tool access requests under Admin settings > Review requests failing with "Authorization failed" or showing the requested access bundle as deleted
