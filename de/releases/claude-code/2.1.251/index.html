claude-code v2.1.251

Patch Veröffentlicht28. Aug. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.251

Was hat sich geändert?

  • Hook-Ereignisse PreModelSwitch und PostModelSwitch hinzugefügt (Blockieren, Bestätigen oder Kommentieren eines Modellwechsels); SessionStart-Resume-Hooks erhalten jetzt Sitzungsveraltung und die geschätzten Re-Cache-Kosten – Live-Streaming der Toolaufrufe und Ergebnisse eines Vordergrund-Subagenten zu Remote Control clients hinzugefügt (Hintergrund-Subagenten zeigen standardmäßig weiterhin nur den Status an) – Eine Ausgabenlimitleiste zu /usage und ein rate_limits.spend_limit-Statuszeilenfeld für Entwickler hinter einem Claude-Apps-Gateway mit Ausgabenlimits hinzugefügt – /cost wurde eine Pro-Session-Prompt-Cache-Zeile hinzugefügt (Trefferquote, Fehlschläge, erneut zwischengespeicherte Token, warm/kalt) und ein passendes prompt_cache-Objekt für Statuszeilenskripte
  • attach, logs, stop, respawn und rm zu claude --help hinzugefügt; Die --resume-Nachricht für eine laufende Hintergrundsitzung nennt jetzt den genauen claude attach <id>-Befehl
  • Dateitools (Lesen, Schreiben, Bearbeiten) behoben, die einem symbolischen Link folgten, der nach der Berechtigungsprüfung innerhalb des Arbeitsverzeichnisses ausgetauscht wurde und außerhalb des genehmigten Speicherorts lesen oder schreiben konnte
  • Problem behoben, bei dem Plugin-Befehle, die in einem Marktplatzeintrag deklariert wurden, außerhalb des Plugin-Verzeichnisses verweisen konnten; Solche Pfade werden nun mit einem Pfaddurchquerungsfehler abgelehnt – Problem mit Projekteinstellungen, die eine detaillierte Beta-Ablaufverfolgung oder rohe API-Body-Protokollierung sowie einen Beta-Ablaufverfolgungsendpunkt mit niedrigerem Umfang ermöglichen, der einen OTLP-Kollektor umgeht, der durch verwaltete Einstellungen oder eine Host-App angeheftet ist, wurde korrigiert – Problem behoben, durch das das Workflow-Tool einen scriptPath las (und in Fehlern zitierte), der außerhalb dessen lag, was die Sitzung lesen konnte, bevor die Berechtigungsprüfung ausgeführt wurde – Problem behoben, bei dem Grep und Glob die Read(...)-Verweigerungsregeln nicht auf Dateien anwendeten, die über einen symbolischen Suchpfad erreicht wurden
  • Es wurde ein Problem behoben, bei dem Konversationen beim Fehler „Textinhaltsblöcke dürfen nicht leer sein“ hängen blieben, wenn das Modell nach einer Runde nur Denken produzierte – Der erste Start bei einer Neuinstallation wurde behoben, der im Standardmodus statt im automatischen Modus für Konten startete, deren Startstandard der automatische Modus ist – Problem behoben, bei dem Opus 5-Anfragen mit „Anstrengung … wird nicht unterstützt, wenn das Denken deaktiviert ist“ fehlschlugen, wenn die Anstrengung xhoch/maximal war und das Denken ausgeschaltet war; Der Aufwand wird in diesem Fall nun als high gesendet
  • Das Beantworten einer von Claude Desktop aus einer anderen Sitzung zugestellten Nachricht wurde korrigiert: SendMessage an diese Sitzungs-ID wird jetzt über Claude Desktop zugestellt, anstatt mit „nicht erreichbar“ fehlzuschlagen.
  • TUI-Verzögerung bei vielen parallelen Subagenten behoben: Fortschritts-Ticks pro Sekunde ersetzen jetzt ihren Vorgänger, anstatt sich im Transkript zu häufen
  • Behoben: Agententeams: Die endgültige Antwort eines Teamkollegen erreicht den Teamleiter nicht – sie erscheint jetzt in der Leerlaufbenachrichtigung anstelle einer inhaltslosen „Verfügbar“-Benachrichtigung – Problem behoben, bei dem Hintergrund-Subagenten nicht auf eine Nachricht von einem unbenannten Geschwister- oder übergeordneten Agenten antworten konnten (from war der Agententyp, der keine Adresse ist) – Behoben, dass verwaltete Einstellungen disableAutoMode mitten in der Sitzung eintrafen und eine bereits laufende Auto-Modus-Sitzung nicht zurück in den Standardmodus verschob – Ein Tipp „Wechseln Sie zu Opus 1M für 5x mehr Kontext“ wurde behoben, der auch dann angezeigt wurde, wenn das aktuelle Opus-Modell bereits über ein 1M-Kontextfenster verfügt – Problem behoben, bei dem Claude-Apps-Gateway-Sitzungen ein gespeichertes Anthropic-Profil (z. B. eine Konsolenanmeldung) als aktiv behandelten: Es wurde in /status aufgelistet und Gateway 401s wurden damit wiederholt, obwohl Anfragen es nie verwenden – Problem behoben, bei dem Cloud-Sitzungen Claude mitteilten, dass sich das Modell geändert hatte, wenn der Host nur das ursprüngliche Modell der Sitzung festlegte – Problem behoben, bei dem Remote Control einen Fehler meldete, wenn die Richtlinie einer Organisation es deaktivierte; Stattdessen wird jetzt ein einzelner stiller Hinweis angezeigt – Problem behoben, bei dem /mcp reconnect in der Fernsteuerung einen generischen Fehler mit zurückgehaltenen Details anstelle der eigentlichen Lösung anzeigte, wenn ein Server in einer anderen Sitzung deaktiviert wurde
  • --input-format stream-json behoben: client-injizierte Assistenten-Tool-Aufrufe, die ohne Nachrichten-ID gesendet wurden, wurden mit dem ersten zusammengeführt und ihre Ergebnisse gingen verloren, auch beim Fortsetzen älterer Sitzungen – Problem behoben, bei dem Sitzungstranskripte stillschweigend überschrieben wurden, wenn eine Verzeichnisänderung eine Sitzung auf ein vorhandenes Transkript mit derselben ID verschob – Problem behoben, bei dem Hintergrundsitzungen und ihre Subagenten keine Dateien in einem Git-Arbeitsbaum bearbeiten konnten, den sie mit git worktree add erstellt hatten
  • Problem behoben, bei dem Hintergrundsitzungen gelegentlich ohne Plugin-Kenntnisse starteten (und auch so blieben), wenn gleichzeitig ein anderer Claude-Code-Prozess den Plugin-Marktplatz aktualisierte – Das Auswählen von Text in einer geöffneten Hintergrundsitzung in tmux über SSH wurde korrigiert: Es wird jetzt wie bei einer Vordergrundsitzung in den tmux-Puffer kopiert, anstatt auf OSC 52 zurückzugreifen – Problem behoben, bei dem SDK- und Cloud-Sitzungen auf unbestimmte Zeit hängen blieben, wenn die Handshake-Bestätigung eines SDK-MCP-Servers verloren ging; Die Wartezeit läuft nun nach 70 Sekunden ab und markiert nur diesen Server als ausgefallen – Problem behoben, bei dem der selbst gehostete Runner die Bash-Tool-Prozesse einer hängengebliebenen Sitzung weiterlaufen ließ, nachdem die Sitzung zwangsweise beendet wurde – /usage-credits für Team- und Enterprise-Mitglieder behoben, deren Administrator das Nutzungsguthabenlimit der Organisation auf 0 $ festgelegt hat: Es wird nun angeboten, den Administrator zu fragen, anstatt zu sagen, dass eine Obergrenze erreicht wurde – Problem mit --worktree --tmux mit einer Merge-Request-Nummer auf einem gitlab.com-Ursprung behoben, der zuerst einen zum Scheitern verurteilten Abruf im GitHub-Stil versuchte, anstatt die GitLab-Referenz direkt abzurufen – Behebung eines Fehlers bei Strg+G mit der Meldung „Emacs wurde unerwartet beendet“ in Hintergrundsitzungen für Editoren, die /dev/tty öffnen, wie z. B. emacs -nw und micro – Ein additionalDirectories-Eintrag wurde behoben, der ein Nullbyte enthielt, das den Start abstürzte oder /add-dir und spätere Einstellungsaktualisierungen unterbrach, wenn er von einem SDK-Host, einer IDE oder einem Hook kam; es wird jetzt übersprungen – Die Kopierverknüpfung des MCP-Servermenüs wurde korrigiert: Es wird jetzt angezeigt, wie die Anmelde-URL kopiert wurde, anstatt immer Erfolg zu melden – Die Darstellung von kursivem Text (z. B. der Sitzungszusammenfassungszeile) als hervorgehobene Blöcke im GNU-Bildschirm und in tmux-Sitzungen mit einem screen-Terminaltyp wurde korrigiert
  • Die Hilfetexte claude mcp add --header und claude mcp add-json mit der Benennung der falschen Transportmittel wurden korrigiert – Problem behoben, bei dem claude ultrareview und /ultrareview die vollen 30 Minuten warteten, wenn die Cloud-Sitzung nicht gestartet werden konnte; Sie hören jetzt frühzeitig auf und melden den Grund – Die Bash-Berechtigung prüft die automatische Genehmigung von Befehlen, die einer ganzzahligen Shell-Variablen einen arithmetischen Ausdruck zuweisen (z. B. OPTIND=1/0, RANDOM=2+2). diese bedürfen nun der Genehmigung – Problem behoben, bei dem bei Hintergrundsitzungen (←, /background, --bg) ein in der Shell exportiertes Vertex/Bedrock-Gateway (ANTHROPIC_*_BASE_URL + CLAUDE_CODE_SKIP_*_AUTH) verloren ging, sodass jede Anfrage fehlschlug – Problem mit claude --bg --model fable bei Max-Plänen behoben, bei dem nicht mehr nach Nutzungsguthaben gefragt wurde, während für die interaktive Sitzung auf demselben Konto noch Fable-Zugriff vorhanden war
  • Das einmalige Angebot „Automatischen Modus zu Ihrer Standardeinstellung machen“ wurde behoben, das in unbeaufsichtigten Sitzungen (z. B. Agent-Team-Teamkollegen-Fenster) angezeigt wurde und bei dem ein versehentlicher Tastendruck das Angebot ungelesen annehmen konnte – Behoben, dass die Aufforderung zur Genehmigung verwalteter Einstellungen erneut angezeigt wurde, nachdem man sich erneut beim gleichen Claude-Apps-Gateway angemeldet hatte, wenn die Einstellungen unverändert waren – Die deaktivierten /bug und /share wurden behoben und meldeten, dass /feedback deaktiviert war. Tipps, /help und Ablehnungsmeldungen schlagen /feedback nicht mehr vor, wenn eine Organisationsrichtlinie oder eine Umgebungsvariable dies deaktiviert – Die Erstellung einer Cloud-Sitzung mit der Empfehlung zur Einrichtung von GitHub nach einem vorübergehenden GitHub-Verbindungsfehler wurde behoben – stattdessen wird in der Meldung angezeigt, dass es erneut versucht werden soll
  • Verbesserte CPU-Auslastung während der Runden in interaktiven Sitzungen durch Reduzierung redundanter UI-Neudarstellungen
  • Verbesserte Installationsgröße: Die native Binärdatei ist etwa 5 MB kleiner
  • Verbesserte Cloud-Sitzungen: Wenn der Netzwerk-Proxy der Sitzung während eines Bash-Befehls eine Verbindung trennt, nennt das Tool-Ergebnis jetzt den Host und den Grund, anstatt nur „Verbindung zurücksetzen“. – /schedule wurde verbessert, um zu erklären, dass in Claude Code konfigurierte MCP-Server nicht an Cloud-Routinen angehängt werden können, statt der bloßen Meldung „Keine MCP-Konnektoren“.
  • Verbessertes Framing von Nachrichten von Ihren eigenen Subagenten: Claude wird mitgeteilt, dass der Absender ein Mitarbeiter dieser Sitzung ist und nicht eine unabhängige Claude-Sitzung – Der Eingabeaufforderungsplatzhalter wurde verbessert, um „Nachricht @name…“ zu lesen, während ein Hintergrund-Subagent oder ein Fork-Transkript angezeigt wird, das über das Subagent-Panel oder /tasks geöffnet wird – Verbesserte Bereinigung von MCP-Servernamen in Fehlermeldungen, Menüs und Befehlsergebnissen – Verbesserter Amazon Bedrock-Sitzungsstart unter CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST (z. B. Claude Desktop): Eine Sitzung mit einer Bedrock-Modell-ID oder einem ARN wartet nicht mehr auf die Erkennung des Inferenzprofils – Das Dialogfeld zur Genehmigung verwalteter Einstellungen wurde verbessert, um nur die Einstellungen aufzulisten, die seit Ihrer letzten Genehmigung geändert wurden – Verbesserter Wiederholungsversuch, wenn der Werkzeugaufruf des Modells fehlerhaft ist: Die fehlerhafte Ausgabe wird jetzt aus dem Wiederholungskontext entfernt, einschließlich auf Bedrock, Vertex und Foundry – /radio wurde so geändert, dass es auf Bedrock, Vertex AI, Foundry und Claude Platform auf AWS verfügbar ist und wenn Telemetrie deaktiviert ist – Claude in Chrome geändert, sodass Browseraktionen immer die Berechtigungsprüfungen von Claude Code durchlaufen, auch in Sitzungen mit deaktivierter Telemetrie, bei denen zuvor die eigenen Eingabeaufforderungen der Chrome-Erweiterung verwendet wurden – CLAUDE_CODE_SUBAGENT_MODEL wurde geändert, um das Standard-Subagentenmodell festzulegen, anstatt alles zu überschreiben: Der model: einer Agentendefinition und ein explizites Pro-Spawn-Modell haben jetzt Vorrang davor – Der Standard-Commit-Trailer wurde in Co-Authored-By: Claude Code geändert, wenn das aktive Modell kein erkanntes Claude-Modell ist (z. B. Modelle von Drittanbietern hinter einem benutzerdefinierten ANTHROPIC_BASE_URL). – Das Standardmodell für platzbasierte Enterprise-Abonnements wurde auf Opus 5 geändert, um es an andere Premium-Pläne anzupassen
  • /effort wurde geändert, um Ihr Standard-Aufwandsniveau pro Modell zu speichern, sodass jedes Modell beim Wechsel seine eigene Einstellung behält – Die Analyse wurde so geändert, dass sie vor der Anmeldung nicht mehr deaktiviert wird, nur weil verwaltete Einstellungen eine Gateway-Anmeldung erzwingen (oder nicht gelesen werden können). Sie bleiben ausgeschaltet, sobald Sie sich am Gateway oder über DISABLE_TELEMETRY angemeldet haben
  • Das PR-Abzeichen in der Fußzeile von Bedrock, Vertex und Foundry wurde geändert und bei deaktivierter Telemetrie wird GitHub API direkt (über gh auth token, GH_TOKEN oder GITHUB_TOKEN) anstelle von gh pr view aufgerufen – Es wurde geändert, wie Bash-Befehlsausgabedateien erstellt und zurückgelesen werden, wenn Befehle in der Sandbox ausgeführt werden, sodass ein Sandbox-Befehl sie nicht umleiten oder ersetzen kann – Die Plugin-/LSP-Installationsvorschläge und der automatische Modus, der standardmäßig vorschlägt, zu warten, bis Sie Ihre Eingabe gesendet oder gelöscht haben, wurden geändert, sodass die Eingabetaste, die Ihre Eingabeaufforderung sendet, diese nicht beantworten kann – Geänderte serververwaltete Einstellungen, die Sandbox-TLS beenden, Sandbox-Verkehr über Ihren eigenen Proxy weiterleiten, Anmeldeinformationen einschleusen oder die Sandbox-Isolation schwächen, sodass vor ihrer Anwendung eine Genehmigung erforderlich ist – ANTHROPIC_CUSTOM_HEADERS wurde von den verwalteten oder Projekteinstellungen so geändert, dass eine Genehmigung erforderlich ist, wenn ein Anmeldeinformations-, Organisations-/Mandanten-, Routing- oder API-Verhaltensheader festgelegt wird (z. B. Authorization, Host).
  • Projektebene .claude/settings.json env geändert, um nicht mehr CLAUDE_CONFIG_DIR, CLAUDE_CODE_TMPDIR oder TMPDIR/TMP/TEMP festzulegen; Legen Sie sie stattdessen in Ihren Shell-, Benutzer- oder verwalteten Einstellungen fest
  • Syntaxhervorhebung für sechs selten verwendete Sprachen (1c, gml, isbl, mathematica, maxima, sqf) entfernt; Die Binärdatei ist 2.5 MB kleiner – [VSCode] Die Schaltfläche „Bedrock, Foundry oder Vertex“ des Anmeldebildschirms, die die Dokumente oben auf der Seite öffnete, wurde korrigiert, anstatt den Abschnitt „Einrichtung des Drittanbieters“ anzuzeigen – [VSCode] Das Remote Control-Banner wurde in ein Fußzeilensymbol geändert (wird angezeigt, während Remote Control aktiviert ist oder fehlgeschlagen ist), das die Sitzung auf claude.ai/code öffnet; Schalten Sie es mit /remote-control ein oder aus

Englisches Original / English original

claude-code v2.1.251

What's changed

  • Added PreModelSwitch and PostModelSwitch hook events (block, confirm, or annotate a model switch); SessionStart resume hooks now receive session staleness and the estimated re-cache cost
  • Added live streaming of a foreground subagent's tool calls and results to Remote Control clients (background subagents, the default, still show status only)
  • Added a Spend limit bar to /usage and a rate_limits.spend_limit status line field for developers behind a Claude apps gateway with spend limits
  • Added a per-session prompt-cache line to /cost (hit ratio, misses, tokens re-cached, warm/cold) and a matching prompt_cache object for status line scripts
  • Added attach, logs, stop, respawn, and rm to claude --help; the --resume message for a running background session now names the exact claude attach <id> command
  • Fixed file tools (Read, Write, Edit) following a symlink swapped inside the working directory after the permission check, which could read or write outside the approved location
  • Fixed plugin commands declared in a marketplace entry being able to point outside the plugin directory; such paths are now rejected with a path-traversal error
  • Fixed project settings being able to enable detailed beta tracing or raw API body logging, and a lower-scope beta tracing endpoint bypassing an OTLP collector pinned by managed settings or a host app
  • Fixed the Workflow tool reading (and quoting in errors) a scriptPath outside what the session may read before the permission check ran
  • Fixed Grep and Glob not applying Read(...) deny rules to files reached through a symlinked search path
  • Fixed conversations getting stuck on "text content blocks must be non-empty" errors after a turn where the model produced only thinking
  • Fixed the first launch on a fresh install starting in default mode instead of auto mode for accounts whose startup default is auto mode
  • Fixed Opus 5 requests failing with "effort … is not supported when thinking is disabled" when effort was xhigh/max and thinking was turned off; effort is now sent as high in that case
  • Fixed replying to a message Claude Desktop delivered from another session: SendMessage to that session id now delivers through Claude Desktop instead of failing with "not reachable"
  • Fixed TUI lag with many parallel subagents: per-second progress ticks now replace their predecessor instead of piling up in the transcript
  • Fixed agent teams: a teammate's final answer not reaching the team lead — it now arrives in the idle notification instead of a content-free "available" notice
  • Fixed background subagents being unable to reply to a message from an unnamed sibling or parent agent (from was the agent type, which is not an address)
  • Fixed managed-settings disableAutoMode arriving mid-session not moving an already-running auto-mode session back to default mode
  • Fixed a "switch to Opus 1M for 5x more context" tip that appeared even when the current Opus model already has a 1M context window
  • Fixed Claude apps gateway sessions treating a stored Anthropic profile (e.g. a Console sign-in) as active: listing it in /status and retrying gateway 401s with it, though requests never use it
  • Fixed cloud sessions telling Claude the model had changed when the host was only setting the session's initial model
  • Fixed Remote Control reporting a failure when an organization's policy disables it; it now shows a single quiet notice instead
  • Fixed /mcp reconnect on Remote Control showing a generic withheld-detail error instead of the real remedy when a server was disabled in another session
  • Fixed --input-format stream-json: client-injected assistant tool calls sent without a message id were merged into the first one and their results lost, including when resuming older sessions
  • Fixed session transcripts being silently overwritten when a directory change relocated a session onto an existing same-ID transcript
  • Fixed background sessions and their subagents being unable to edit files inside a git worktree they created with git worktree add
  • Fixed background sessions occasionally starting without any plugin skills (and staying that way) when another Claude Code process was refreshing the plugin marketplace at the same moment
  • Fixed selecting text in an opened background session inside tmux over SSH: it now copies to the tmux buffer like a foreground session instead of falling back to OSC 52
  • Fixed SDK and cloud sessions hanging indefinitely when an SDK MCP server's handshake acknowledgment was lost; the wait now times out after 70 seconds and marks only that server failed
  • Fixed self-hosted runner leaving a stuck session's Bash tool processes running after the session was force-stopped
  • Fixed /usage-credits for Team and Enterprise members whose admin set the org's usage-credit limit to $0: it now offers to ask the admin instead of saying a cap was reached
  • Fixed --worktree --tmux with a merge-request number on a gitlab.com origin trying a doomed GitHub-style fetch first instead of fetching the GitLab ref directly
  • Fixed Ctrl+G failing with "Emacs quit unexpectedly" in background sessions for editors that open /dev/tty, such as emacs -nw and micro
  • Fixed an additionalDirectories entry containing a null byte crashing startup, or breaking /add-dir and later settings updates when it came from an SDK host, IDE, or hook; it is now skipped
  • Fixed the MCP server menu's copy shortcut: it now says how the sign-in URL was copied instead of always claiming success
  • Fixed italic text (such as the session recap line) rendering as highlighted blocks in GNU screen and in tmux sessions using a screen terminal type
  • Fixed claude mcp add --header and claude mcp add-json help text naming the wrong transports
  • Fixed claude ultrareview and /ultrareview waiting the full 30 minutes when the cloud session fails to start; they now stop early and report the reason
  • Fixed Bash permission checks auto-approving commands that assign an arithmetic expression to an integer shell variable (e.g. OPTIND=1/0, RANDOM=2+2); these now prompt for approval
  • Fixed backgrounded sessions (←, /background, --bg) losing a Vertex/Bedrock gateway (ANTHROPIC_*_BASE_URL + CLAUDE_CODE_SKIP_*_AUTH) exported in the shell, so every request failed
  • Fixed claude --bg --model fable on Max plans stopping to ask for usage credits while the interactive session on the same account still had Fable allowance
  • Fixed the one-time "make auto mode your default" offer appearing in unattended sessions (e.g. agent-team teammate panes), where a stray keypress could accept it unread
  • Fixed the managed-settings approval prompt re-appearing after signing in again to the same Claude apps gateway when the settings are unchanged
  • Fixed disabled /bug and /share reporting that /feedback was disabled; tips, /help, and refusal messages no longer suggest /feedback when an org policy or env var turns it off
  • Fixed cloud session creation advising GitHub setup after a transient GitHub connection failure — the message now says to retry instead
  • Improved CPU usage during turns in interactive sessions by cutting redundant UI re-renders
  • Improved install size: the native binary is about 5 MB smaller
  • Improved cloud sessions: when the session's network proxy drops a connection during a Bash command, the tool result now names the host and reason instead of only "connection reset"
  • Improved /schedule to explain that MCP servers configured in Claude Code can't be attached to cloud routines, instead of a bare "No MCP connectors" message
  • Improved framing of messages from your own subagents: Claude is told the sender is a worker inside this session, not an unrelated Claude session
  • Improved the prompt placeholder to read "Message @name…" while viewing a background subagent or fork transcript opened from the subagent panel or /tasks
  • Improved sanitization of MCP server names in error messages, menus, and command results
  • Improved Amazon Bedrock session start under CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST (e.g. Claude Desktop): a session given a Bedrock model ID or ARN no longer waits for inference-profile discovery
  • Improved the managed settings approval dialog to list only the settings that changed since you last approved them
  • Improved retry when the model's tool call is malformed: the broken output is now dropped from the retry context, including on Bedrock, Vertex, and Foundry
  • Changed /radio to be available on Bedrock, Vertex AI, Foundry, and Claude Platform on AWS, and when telemetry is disabled
  • Changed Claude in Chrome so browser actions always go through Claude Code's permission checks, including in sessions with telemetry disabled, which previously used the Chrome extension's own prompts
  • Changed CLAUDE_CODE_SUBAGENT_MODEL to set the default subagent model rather than override everything: an agent definition's model: and an explicit per-spawn model now take precedence over it
  • Changed the default commit trailer to Co-Authored-By: Claude Code when the active model isn't a recognized Claude model (e.g. third-party models behind a custom ANTHROPIC_BASE_URL)
  • Changed the default model for seat-based Enterprise subscriptions to Opus 5, matching other premium plans
  • Changed /effort to save your default effort level per model, so each model keeps its own setting when you switch
  • Changed analytics to no longer turn off before sign-in solely because managed settings force gateway login (or cannot be read); they stay off once signed in to the gateway or via DISABLE_TELEMETRY
  • Changed the footer PR badge on Bedrock, Vertex, and Foundry, and when telemetry is off, to call the GitHub API directly (via gh auth token, GH_TOKEN, or GITHUB_TOKEN) instead of gh pr view
  • Changed how Bash command output files are created and read back when commands run in the sandbox, so a sandboxed command cannot redirect or replace them
  • Changed plugin/LSP install suggestions and the auto-mode default offer to wait until you've sent or cleared what you're typing, so the Enter that sends your prompt can't answer them
  • Changed server-managed settings that terminate sandbox TLS, route sandbox traffic through your own proxy, inject credentials, or weaken sandbox isolation to require approval before they apply
  • Changed ANTHROPIC_CUSTOM_HEADERS from managed or project settings to require approval when it sets a credential, org/tenant, routing, or API-behavior header (e.g. Authorization, Host)
  • Changed project-level .claude/settings.json env to no longer set CLAUDE_CONFIG_DIR, CLAUDE_CODE_TMPDIR, or TMPDIR/TMP/TEMP; set them in your shell, user, or managed settings instead
  • Removed syntax highlighting for six rarely used languages (1c, gml, isbl, mathematica, maxima, sqf); the binary is 2.5 MB smaller
  • [VSCode] Fixed the sign-in screen's "Bedrock, Foundry, or Vertex" button opening the docs at the top of the page instead of the third-party provider setup section
  • [VSCode] Changed the Remote Control banner to a footer pill (shown while Remote Control is on or has failed) that opens the session on claude.ai/code; turn it on or off with /remote-control
