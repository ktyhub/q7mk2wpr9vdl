claude-code v2.1.246

Patch Veröffentlicht25. Aug. 2026 Quelleanthropics/claude-code Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Claude-Code v2.1.246

Was hat sich geändert?

– Es wurde eine Startwarnung für Bash-Zulassungsregeln mit einem Platzhalter vor dem Unterbefehl (z. B. Bash(git * main)) hinzugefügt, da diese auch mit den vor dem Unterbefehl eingefügten Optionen übereinstimmen – /permissions wurde eine Registerkarte „Automatischer Modus“ zum Anzeigen und Bearbeiten der Klassifizierungsregeln für den automatischen Modus hinzugefügt

  • Die Abschlusszeit der Runde wurde zur Zeile für die Dauer der Runde hinzugefügt, z. B. ✻ Sautéed for 23s · done 6:05 PM
  • Im Vollbildmodus wurde ein leeres Transkript angezeigt, nachdem die Größe des Terminals geändert und bis zum nächsten Tastendruck nach unten gesprungen wurde – Eine schwerwiegende Verlangsamung des Transkripts wurde behoben, wenn ein Diff eine sehr lange einzelne Zeile enthielt (z. B. eine Base64-Zeichenfolge). Solche Linien werden jetzt mit einer Markierung abgeschnitten dargestellt – Fehler beim Scrollen im Vollbildmodus behoben, wenn die Nachricht bei einer früheren Nachricht positioniert wurde, einschließlich des Hängenbleibens beim Springen nach unten mitten im Transkript – Behoben: Hintergrundsitzungen konnten nach 45 Sekunden nicht geöffnet werden, wenn das Startverzeichnis von Claude Code gelöscht wurde, der Computer im Ruhezustand war oder der Host Prozesse nur langsam startete – Behebung eines Problems, bei dem Hintergrundsitzungen nicht mit der Meldung „Der Hintergrunddienst … EACCES konnte nicht gestartet werden“ geöffnet werden konnten, wenn zu diesem Zeitpunkt ein anderer Claude Code-Prozess das npm-Paket neu installierte – Problem behoben, bei dem das Markdown-Rendering für eine ganze Nachricht deaktiviert wurde, wenn die ersten 500 Zeichen keinen Markdown enthielten, sowie für +/N)-Listen und Settext-Überschriften – Behoben: MCP-Tool-Aufrufe, die durch eine eingehende Nachricht in Headless-/Remote-Sitzungen unterbrochen wurden, wurden dem Modell als „abgeschlossen ohne Ausgabe“ gemeldet, anstatt als expliziter unterbrochener Fehler – Problem behoben, bei dem MCP-Tool-Argumente als JSON-Strings gesendet wurden, wenn das Schema des Parameters leer ist ({}), und nicht als ihr tatsächlicher Typ
  • Ein mitten im Lauf unterbrochener Befehl wurde behoben, der als „Ran 1 Shell Command“ angezeigt wurde, ohne dass es ein Anzeichen dafür gab, dass er unterbrochen wurde – Das Drücken von ← oder das Ausführen von /background während eines dynamischen Workflows, bei dem die abgeschlossenen Subagenten neu gestartet wurden, wurde behoben. es fragt nun zuerst und sagt, wie viele Subagenten neu starten würden – Problem behoben, bei dem das Öffnen einer gerade gestarteten Sitzung in claude agents, während der Worker noch bootete (üblich unter Windows), gestoppt wurde mit „wurde gestoppt, während der Respawn im Flug war“ – Problem behoben, bei dem claude agents eine benannte Sitzung im Hintergrund zweimal auflistete; Beim erneuten Hintergrund derselben Konversation wird nun die neue Zeile nummeriert (z. B. my-session (2)). – Der Hintergrund-Aufbewahrungs-Sweep wurde behoben, der Git-Arbeitsbäume unter .claude/worktrees/ entfernte, die Sie selbst erstellt hatten, als ein alter Hintergrundsitzungsdatensatz auf sie zeigte – Es wurde behoben, dass Toolaufrufe im automatischen Modus bei sehr großen Sitzungen als „vorübergehend nicht verfügbar“ abgelehnt wurden, indem die Sicherheitsüberprüfungsfrist mit der Eingabeaufforderungsgröße skaliert wurde – Der Plugin-Cache hat dazu geführt, dass für dasselbe Plugin doppelte SHA-benannte Verzeichnisse erstellt wurden
  • Plugin-Skills behoben, deren Frontmatter name bereits das Präfix <plugin>: enthält, das im Slash-Menü doppelt angezeigt wird (z. B. /plugin:plugin:skill) – Fehler behoben, bei dem claude plugin update für ein installiertes Plugin aufgrund seines bloßen Namens fehlschlug (nur der vollständig qualifizierte Name funktionierte) – Fehler bei der Plugin-Installation behoben, wenn plugin.json mit einer UTF-8-Byte-Order-Markierung (BOM) gespeichert wurde. – Problem behoben, bei dem /reload-plugins 0 Fertigkeiten für Plugins meldete, die Fertigkeiten unter skills/*/SKILL.md definieren – Hook-Fehlermeldungen behoben, die ein wörtliches ${CLAUDE_PLUGIN_ROOT} anstelle des aufgelösten Plugin-Pfads anzeigten – Problem behoben, bei dem /rename die Eingabeaufforderungsrahmenfarbe des Themes (einschließlich promptBorder eines benutzerdefinierten Themes) durch das Standard-Cyan ersetzte; Der Rand behält jetzt die Farbe Ihres Themas, es sei denn, Sie wählen eine mit /color aus – Behoben, dass benutzerdefinierte Theme-Diff-Farben (diffAdded/diffRemoved und ihre abgeblendeten Varianten) in Diffs und der /theme-Vorschau ignoriert wurden – Es wurde eine keybindings.json-Bindung mit einem unbekannten Aktionsnamen behoben, die diese Taste stillschweigend stumm machte; Sie wird jetzt übersprungen, sodass die Standardbindung weiterhin funktioniert und eine Warnung unter --debug protokolliert wird – Die Aktivitäts-Heatmap /stats wurde korrigiert und zeigte in Zeitzonen östlich von UTC die Aktivität jedes Tages eine Zelle weiter an (Zählung des Sonntags unter Montag). – /fork aus einer bereits gegabelten oder im Hintergrund liegenden Sitzung behoben, die die neue Sitzung mit einer leeren Konversation startete – Problem behoben, bei dem Eingabeaufforderungen, die mit /-- begannen (z. B. Lean-Dokumentkommentare), als unbekannter Schrägstrichbefehl abgelehnt und nicht an Claude gesendet wurden – Problem behoben, bei dem die @-Dateiauswahl geöffnet blieb, nachdem der eingegebene Text nicht mehr mit einem echten Pfad übereinstimmte – Das Problem, dass die Kosten und die Dauer der Statuszeile nach dem Navigieren zur Agentenansicht und zurück auf Null zurückgesetzt wurden, wurde behoben – Problem behoben, bei dem der Tastaturfokus im Vollbildmodus auf das Steuerelement unter dem Zeiger verschoben wurde, wenn Sie das Terminalfenster cliklickten, nur um es wieder in den Fokus zu bringen – Fehler bei der Pfadvervollständigung behoben, wenn das Vervollständigungstoken oder das Arbeitsverzeichnis ein Nullbyte enthielt – Windows/macOS: Problem behoben, bei dem Headless-Sitzungen veraltete Einträge in ~/.claude/sessions nicht bereinigten, die von Sitzungen hinterlassen wurden, die unsauber beendet wurden – Behoben, dass die Benutzeroberfläche beim ersten Tool-Aufruf mit einem Renderfehler anhielt, wenn ein Anthropic-kompatibler Endpunkt eines Drittanbieters (ANTHROPIC_BASE_URL) einen tool_use-Block ohne id streamt – Problem behoben, bei dem das Schreibtool nach dem Überschreiben einer sehr großen vorhandenen Datei „Nicht genügend Speicher“ meldete oder lange Zeit einfrierte, obwohl die Datei bereits geschrieben wurde – Problem behoben, bei dem claude plugin install <name> stillschweigend beendet wurde (oder in einem Terminal hängen blieb), anstatt einen Fehler zu melden, wenn ~/.claude/plugins/known_marketplaces.json leer oder beschädigt ist – Es wurde ein Problem behoben, bei dem fortgesetzte Sitzungen in jeder Runde mit 400 fehlschlugen, wenn der gespeicherte Verlauf Werkzeugblöcke enthielt, die der Anthropic API nicht akzeptierte (normalerweise von einem API-Proxy eines Drittanbieters geschrieben). – Behebung eines Fehlers bei curl -fsSL https://claude.ai/install.sh | bash mit der Fehlermeldung „Raw-Modus wird nicht unterstützt“ für einige Team-/Enterprise-Benutzer mit serververwalteten Einstellungen – Behoben, dass Sitzungen, die im Planmodus endeten, außerhalb des Planmodus in der VS Code-Erweiterung und in claude -p --continue/--resume mit einem Berechtigungsaufforderungstool wieder aufgenommen wurden, wenn kein Berechtigungsmodus festgelegt war – Der Notification-Hook wurde behoben, der nicht ausgelöst wurde, während die Sandbox-Berechtigungsaufforderung „Netzwerkanforderung außerhalb der Sandbox“ wartete – Die Bash-Berechtigungsprüfungen wurden so korrigiert, dass für fehlerhafte Befehle mit einem hängenden &&- oder ||-Operator immer eine Genehmigung erforderlich ist – Problem behoben, bei dem --strict-mcp-config-Sitzungen dazu aufgefordert wurden, .mcp.json-Server zu genehmigen, die sie nie laden würden, wodurch Hintergrundsitzungen beim Start warten mussten – Telemetrie- und Metrikanfragen an Anthropic mit dem für ein Drittanbieter-Gateway (ANTHROPIC_BASE_URL) konfigurierten API-Schlüssel behoben; Ein Berechtigungsnachweis wird jetzt nur noch an seinen eigenen Host gesendet – Es wurde ein sichtbarer API-Fehler bei der ersten Eingabeaufforderung nach dem Leerlauf behoben, wenn apiKeyHelper kurzlebige JWTs zurückgibt: Ein abgelaufenes zwischengespeichertes Token wird jetzt vor dem Senden aktualisiert, und 401/403-Authentifizierungsfehler werden stillschweigend erneut versucht – Der mit der Sitzungslänge in der Vollbild- und Strg+O-Transkriptansicht wachsende Speicher wurde behoben: Jede gerenderte Nachrichtenzeile behält nicht mehr eine vollständige Kopie der transkriptweiten Tool-Suchen bei – Behoben: /ultrareview-Läufe und Cloud-Sitzungen, die gleichzeitig von einem Repository (z. B. von mehreren Arbeitsbäumen) gestartet wurden, begannen manchmal mit den nicht festgeschriebenen Änderungen eines anderen Starts – Der Fortschrittszähler für Aufgaben (z. B. 3/5), der bei Hintergrund-Cloud-Sitzungen wie /autofix-pr angezeigt wurde, wurde behoben. Manchmal fehlte eine Aufgabe – Problem behoben, bei dem Fernsteuerungssitzungen ihren Platzhalternamen in claude.ai und der Claude-App bis zur zweiten Eingabeaufforderung behielten; Der automatisch generierte Titel erscheint nun nach der ersten Eingabeaufforderung – Problem behoben, bei dem MCP-Tools mit der Kennzeichnung requiresUserInteraction immer noch „Ja, und nicht noch einmal fragen“ in ihrer Berechtigungsaufforderung anboten; Die Option hat eine Zulassungsregel geschrieben, die das Tool dann ignoriert hat – Problem behoben, bei dem der selbstgehostete Runner seine Live-Sitzungen beendete oder beendete, wenn eine Arbeitsumfrage-Antwort fehlerhaft war (z. B. die HTML-Seite eines abfangenden Proxys); Jetzt wird die Umfrage erneut durchgeführt
  • Verbessertes /cd: Die Projekteinstellungen, Hooks, .mcp.json-Server (hinter der üblichen Genehmigungsaufforderung), Fertigkeiten und Agenten des neuen Verzeichnisses werden jetzt direkt nach dem Umzug wirksam, anstatt auf --resume – Verbesserte Latenz des Bash-Tools auf Bash-Shells durch die Wiedergabe von Snapshot-Funktionen ohne eine Base64-Subshell pro Funktion
  • Verbesserte Subagent-Ergebnisse: Ein Subagent, der an seinem maxTurns-Limit stoppt, gibt seine Ausgabe jetzt als teilweise markiert zurück, mit einem Hinweis, sie über SendMessage fortzusetzen, anstatt als fertig zu erscheinen – Verbesserte nicht interaktive Sitzungen (-p, SDK, Cloud-Sitzungen), um eine Antwort, die während des Streams aufgrund eines Serverfehlers, eines Verbindungsverlusts oder eines Stillstands unterbrochen wurde, automatisch fortzusetzen, anstatt mit einem Fehler zu enden – Verbesserte Zuordnung der Nutzungstelemetrie zu Ihrer Organisation für Workload Identity Federation-Sitzungen, gesendete Ereignisse während der Ausführung von apiKeyHelper beim Start und nach Ablauf eines Anmeldetokens im Leerlauf – /code-review wurde geändert, sodass Claude es auch alleine auf Bedrock, Vertex AI und Foundry starten kann, über das Claude-Apps-Gateway und wenn Telemetrie oder nicht notwendiger Datenverkehr deaktiviert sind
  • /goal: Leerlaufsitzungen wurden so geändert, dass bei lang andauernder Hintergrundarbeit pro Ziel höchstens drei Check-Ins gestartet werden. Ihre nächste Nachricht erlaubt drei weitere – claude install und claude update wurden geändert, um eine ausstehende Einwilligungsaufforderung für verwaltete Einstellungen auf die nächste interaktive Sitzung zu verschieben, anstatt sie mitten im Befehl aufzufordern
  • OpenTelemetry-Plugin-Ereignisse für von claude.ai synchronisierte Plugins geändert: plugin_id_hash spiegelt jetzt den tatsächlichen Marktplatz des Plugins wider und enabled_via ist admin-install für vom Administrator installierte Plugins – Problem behoben, bei dem die Dateisystemkonfiguration der Befehlssandbox --setting-sources nicht berücksichtigte

Englisches Original / English original

claude-code v2.1.246

What's changed

  • Added a startup warning for Bash allow rules with a wildcard before the subcommand (e.g. Bash(git * main)), since they also match options inserted before the subcommand
  • Added an Auto mode tab to /permissions for viewing and editing auto mode classifier rules
  • Added the turn's completion time to the end-of-turn duration line, e.g. ✻ Sautéed for 23s · done 6:05 PM
  • Fixed fullscreen mode showing a blank transcript after resizing the terminal and jumping to the bottom until the next keypress
  • Fixed a severe transcript slowdown when a diff contained a very long single line (e.g. a base64 string); such lines now render truncated with a marker
  • Fixed erratic fullscreen scrolling when positioned at an earlier message, including jump-to-bottom getting stuck mid-transcript
  • Fixed background sessions failing to open after 45 seconds when Claude Code's starting directory had been deleted, the machine had slept, or the host is slow to start processes
  • Fixed background sessions failing to open with "Couldn't start the background service … EACCES" when another Claude Code process was re-installing the npm package at that moment
  • Fixed markdown rendering being disabled for a whole message when its first 500 characters contained no markdown, and for +/N) lists and setext headings
  • Fixed MCP tool calls interrupted by an incoming message in headless/remote sessions being reported to the model as "completed with no output" instead of an explicit interrupted error
  • Fixed MCP tool arguments being sent as JSON strings when the parameter's schema is empty ({}), instead of their real type
  • Fixed a command interrupted mid-run showing as "Ran 1 shell command" with no sign it was cut
  • Fixed pressing ← or running /background during a dynamic workflow restarting its finished subagents; it now asks first and says how many subagents would restart
  • Fixed opening a just-started session in claude agents while its worker was still booting (common on Windows) stopping it with "was stopped while the respawn was in flight"
  • Fixed claude agents listing a backgrounded named session twice; backgrounding the same conversation again now numbers the new row (e.g. my-session (2))
  • Fixed the background retention sweep removing git worktrees under .claude/worktrees/ that you created yourself when an old background-session record pointed at them
  • Fixed auto mode tool calls being denied as "temporarily unavailable" on very large sessions by scaling the safety-check deadline with prompt size
  • Fixed the plugin cache creating duplicate SHA-named directories for the same plugin
  • Fixed plugin skills whose frontmatter name already includes the <plugin>: prefix showing it doubled in the slash menu (e.g. /plugin:plugin:skill)
  • Fixed claude plugin update failing for an installed plugin given its bare name (only the fully-qualified name worked)
  • Fixed plugin installation failing when plugin.json was saved with a UTF-8 byte-order mark (BOM)
  • Fixed /reload-plugins reporting 0 skills for plugins that define skills under skills/*/SKILL.md
  • Fixed hook error messages showing a literal ${CLAUDE_PLUGIN_ROOT} instead of the resolved plugin path
  • Fixed /rename replacing the theme's prompt border color (including a custom theme's promptBorder) with the default cyan; the border now keeps your theme's color unless you pick one with /color
  • Fixed custom theme diff colors (diffAdded/diffRemoved and their dimmed variants) being ignored in diffs and the /theme preview
  • Fixed a keybindings.json binding with an unknown action name silently deadening that key; it is now skipped so the default binding keeps working, and a warning is logged under --debug
  • Fixed /stats activity heatmap showing each day's activity one cell off (Sunday's count under Monday) in timezones east of UTC
  • Fixed /fork from an already-forked or backgrounded session starting the new session with an empty conversation
  • Fixed prompts beginning with /-- (e.g. Lean doc comments) being rejected as an unknown slash command instead of being sent to Claude
  • Fixed the @ file picker staying open after the typed text stopped matching a real path
  • Fixed the status line's cost and duration resetting to zero after navigating to the agents view and back
  • Fixed fullscreen mode moving keyboard focus onto the control under the pointer when you clicked the terminal window only to bring it back into focus
  • Fixed path completion failing when the completion token or working directory contained a null byte
  • Windows/macOS: Fixed headless sessions not cleaning up stale entries in ~/.claude/sessions left by sessions that exited uncleanly
  • Fixed the UI stopping with a render error on the first tool call when a third-party Anthropic-compatible endpoint (ANTHROPIC_BASE_URL) streams a tool_use block without an id
  • Fixed the Write tool reporting "Out of memory" or freezing for a long time after overwriting a very large existing file, even though the file had been written
  • Fixed claude plugin install <name> exiting silently (or hanging in a terminal) instead of reporting an error when ~/.claude/plugins/known_marketplaces.json is empty or corrupted
  • Fixed resumed sessions failing every turn with a 400 when the saved history contains tool blocks the Anthropic API does not accept (typically written by a third-party API proxy)
  • Fixed curl -fsSL https://claude.ai/install.sh | bash failing with "Raw mode is not supported" for some Team/Enterprise users with server-managed settings
  • Fixed sessions that ended in plan mode resuming outside plan mode in the VS Code extension, and in claude -p --continue/--resume with a permission prompt tool, when no permission mode was set
  • Fixed the Notification hook not firing while the sandbox "Network request outside of sandbox" permission prompt is waiting
  • Fixed Bash permission checks to always require approval for malformed commands with a dangling && or || operator
  • Fixed --strict-mcp-config sessions prompting to approve .mcp.json servers they would never load, which left background sessions waiting at startup
  • Fixed telemetry and metrics requests to Anthropic carrying the API key configured for a third-party gateway (ANTHROPIC_BASE_URL); a credential is now only sent to its own host
  • Fixed a visible API error on the first prompt after idle when apiKeyHelper returns short-lived JWTs: an expired cached token is now refreshed before sending, and 401/403 auth errors retry quietly
  • Fixed memory growing with session length in the fullscreen and Ctrl+O transcript views: each rendered message row no longer retains a full copy of the transcript-wide tool lookups
  • Fixed /ultrareview runs and cloud sessions launched at the same time from one repository (e.g. from several worktrees) sometimes starting with another launch's uncommitted changes
  • Fixed the task progress count (e.g. 3/5) shown for background cloud sessions such as /autofix-pr occasionally missing a task
  • Fixed Remote Control sessions keeping their placeholder name in claude.ai and the Claude app until the second prompt; the auto-generated title now appears after the first prompt
  • Fixed MCP tools marked requiresUserInteraction still offering "Yes, and don't ask again" in their permission prompt; the option wrote an allow rule the tool then ignored
  • Fixed the self-hosted runner ending its live sessions or exiting when a work-poll response is malformed (e.g. an intercepting proxy's HTML page); it now retries the poll
  • Improved /cd: the new directory's project settings, hooks, .mcp.json servers (behind the usual approval prompt), skills, and agents now take effect right after the move instead of on --resume
  • Improved Bash tool latency on bash shells by replaying snapshot functions without a base64 subshell per function
  • Improved subagent results: a subagent that stops at its maxTurns limit now returns its output marked as partial, with a hint to continue it via SendMessage, instead of appearing finished
  • Improved non-interactive sessions (-p, SDK, cloud sessions) to automatically continue a response cut off mid-stream by a server error, connection loss, or stall instead of ending with an error
  • Improved attribution of usage telemetry to your organization for workload identity federation sessions, events sent while apiKeyHelper runs at startup, and after a login token expired while idle
  • Changed /code-review so Claude can also start it on its own on Bedrock, Vertex AI, and Foundry, through the Claude apps gateway, and when telemetry or non-essential traffic is disabled
  • /goal: Changed idle sessions to start at most three check-ins on long-running background work per goal; your next message allows three more
  • Changed claude install and claude update to defer a pending managed-settings consent prompt to the next interactive session instead of prompting mid-command
  • Changed OpenTelemetry plugin events for plugins synced from claude.ai: plugin_id_hash now reflects the plugin's real marketplace, and enabled_via is admin-install for admin-installed plugins
  • Fixed the command sandbox's filesystem configuration not respecting --setting-sources
