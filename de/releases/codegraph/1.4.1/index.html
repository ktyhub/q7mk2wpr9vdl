Codegraph v1.4.1

[1.4.1] – 10.07.2026

Neue Funktionen

– Der MCP-Server erkennt jetzt, wenn eine neuere CodeGraph-Version vorhanden ist, und teilt Ihnen dies mit – ein Server mit langer Laufzeit, der früher stillschweigend hinter Versionen herdriftete, bis etwas kaputt ging. Beim Start überprüft es die neueste Version im Hintergrund (niemals blockierend, höchstens einmal am Tag, wird auf allen Servern auf dem Computer zwischengespeichert) und zeigt eine einzeilige Meldung „Update verfügbar – codegraph upgrade ausführen“ im Serverprotokoll, in den Anweisungen, die Ihr Agent beim Herstellen einer Verbindung sieht, und in codegraph_status an. Nichts aktualisiert sich von selbst, und offline zu sein bedeutet einfach, keine Benachrichtigung zu erhalten. Mit CODEGRAPH_NO_UPDATE_CHECK=1 abmelden; DO_NOT_TRACK=1 deaktiviert es auch. (#1243)

Korrekturen

– codegraph upgrade führt bei einer Windows-npm-Installation tatsächlich npm erneut aus – ein moderner Knoten weigert sich, npm.cmd direkt zu starten, sodass das Upgrade mit einem Spawn-Fehler fehlschlug, bevor etwas unternommen wurde. npm wird jetzt so aufgerufen, wie es von einem Terminal ausgeführt werden würde. (#1238)

  • codegraph uninstall deinstalliert CodeGraph jetzt tatsächlich. Früher wurden nur die Agent-Konfigurationen entfernt und alle installierten Binärdateien zurückgelassen, sodass codegraph danach immer noch ausgeführt wurde – besonders verwirrend, wenn sowohl eine globale NPM-Installation als auch eine eigenständige Installation vorhanden waren und das Entfernen einer davon immer noch die Antwort der anderen auf PATH zurückließ. Uninstall findet jetzt jede Installation auf dem Computer (das Standalone-Bundle, das globale NPM-Paket, den Launcher-Link) und entfernt sie alle, nachdem es Ihnen genau angezeigt hat, was es gefunden hat, und zuerst nachgefragt hat (--yes überspringt die Eingabeaufforderung). Einstellungen auf Maschinenebene wie Ihre Telemetrieauswahl bleiben erhalten, ein Quell-Checkout wird nie berührt und das neue --keep-cli-Flag stellt das alte Nur-Konfigurationsverhalten wieder her. (#1071)
  • codegraph_explore lässt nicht länger zu, dass gewöhnliche englische Wörter in einer Frage in natürlicher Sprache die Rangfolge kapern, wenn sie zufällig mit dem Namen eines Codesymbols übereinstimmen. Bei einer Frage wie „Wie überprüft der Upgrade-Ablauf die neueste Version?“ wird „check“ als Symbol behandelt, nach dem der Agent namentlich gefragt hat, die Datei dieser nicht verwandten Definition wird zuerst eingestuft und die Dateien, um die es in der Frage tatsächlich geht, werden vollständig aus der Antwort gestrichen. Präzise geschriebene Symbolnamen (camelCase, PascalCase, Snake_case, qualifizierte Namen) erhalten nach wie vor die höchste Abrechnung, ebenso wie Klarwort-Symboltaschen, deren Wörter in derselben Datei zusammengehören.
  • PHP-Methodenaufrufe, die über eine Klasseneigenschaft erfolgen – $this->dep->method(), die dominierende Aufrufform in Konstruktor-Injection-Codebasen (Symfony, Laravel) – werden jetzt in die Methode des deklarierten Typs der Eigenschaft aufgelöst, sodass Aufrufer und Auswirkungsanalysen Produktionsaufrufseiten sehen, anstatt eine DI-lastige Methode als nicht aufgerufen oder nur zum Testen zu melden. Heraufgestufte Konstruktorparameter, typisierte Eigenschaften, klassische Konstruktorzuweisung (einschließlich mehrzeiliger Signaturen) und typisierte Setter-Injektion zählen alle; Schnittstellentypeigenschaften werden in die Schnittstellenmethode aufgelöst, und geerbte Methoden werden über die Typhierarchie aufgelöst. Es werden nur eigenschaftsförmige Deklarationen herangezogen – eine gleichnamige lokale Variable oder ein gleichnamiger Parameter an anderer Stelle kann die Eigenschaft nie falsch schreiben – und eine Eigenschaft, deren Typ nicht statisch wiederhergestellt werden kann, bleibt unverknüpft und wird nicht erraten. Danke @w0lan. (#1220) – codegraph upgrade aktualisiert jetzt auch die in Ihren Agents installierten Vorgängerversionen – den CodeGraph-Abschnitt in CLAUDE.md / AGENTS.md / GEMINI.md und den MCP-Eintrag – sodass Agents bei der Aktualisierung nicht mehr den Anweisungen folgen müssen, die für Tools geschrieben wurden, die inzwischen umbenannt oder entfernt wurden. Nur aktualisieren: Agenten, die Sie nie konfiguriert haben, werden nicht berührt und Ihre Berechtigungs- und Hook-Auswahl bleibt erhalten. Auch manuell als codegraph install --refresh verfügbar und mit CODEGRAPH_NO_INSTALL_REFRESH=1 überspringbar. (#1238) – codegraph upgrade führt bei einer npm-Installation jetzt erneut ein Upgrade über npm durch, anstatt stillschweigend eine zweite Kopie zu erstellen, die nie das PATH-Rennen gewinnt – zuvor hat codegraph --version immer die alte Version gemeldet, egal wie oft Sie ein Upgrade durchgeführt haben. (#1238) – Nach jedem Upgrade überprüft CodeGraph nun, ob der von Ihrem Terminal aufgelöste Befehl codegraph tatsächlich die frisch installierte Version bereitstellt – um zu bestätigen, dass Sie kein neues Terminal benötigen, oder um Ihnen genau mitzuteilen, welche veraltete Installation die neue Version überschattet. (#1071) – Der Sicherheits-Watchdog beendet keinen fehlerfreien Index mehr bei stark beeinträchtigtem Speicher. Früher wurde die Aktivität ausschließlich anhand der Ereignisschleife beurteilt, sodass ein langer Datenbankschreibvorgang auf einer Festplatte mit Problemen genauso aussah wie ein hängender Prozess und dazu führen konnte, dass ein gültiger, laufender Index beendet wurde. Während codegraph index/codegraph init prüft der Watchdog jetzt auch, ob die Indexdateien auf der Festplatte voranschreiten, bevor er eingreift: Langsame, aber fortschreitende Arbeit wird in Ruhe gelassen (durch eine feste Obergrenze begrenzt), während ein wirklich hängender Prozess immer noch genauso schnell beendet wird wie zuvor. (#1231) – Die inkrementelle Synchronisierung erfasst jetzt dateiübergreifende Beziehungen, die erst nach einer Bearbeitung aufgelöst werden können – zum Beispiel, wenn eine Datei einen Export erhält, den eine andere, unveränderte Datei bereits importiert oder aufgerufen hat. Zuvor wurde die Referenz in der unveränderten Datei nie erneut aufgerufen, sodass Aufrufer, Impact- und Flow-Ergebnisse die neue Kante stillschweigend wegließen (während der Status einen sauberen Index meldete), bis eine vollständige Neuindizierung erfolgte. Referenzen, die noch nicht aufgelöst werden können, werden jetzt gespeichert und automatisch erneut versucht, wenn durch eine Änderung ein Symbol eingeführt wird, das sie erfüllen könnte. Dies gilt auch für eine Klasse, die eine neue Methode erhält, die bereits von anderen Dateien aufgerufen wird. Danke @loadcosmos für den Bericht mit minimaler Reproduktion. (#1240) – Der umgekehrte Fall wurde ebenfalls behoben: Wenn eine Bearbeitung ein Symbol entfernt oder verschiebt (oder seine Datei löscht), werden Aufrufer in unveränderten Dateien jetzt während derselben Synchronisierung neu aufgelöst – sie binden sich erneut an die neue Heimat des Symbols, wenn es verschoben wurde, oder warten darauf, automatisch wieder eine Verbindung herzustellen, wenn es zurückkommt – anstatt ihre Beziehung stillschweigend bis zu einer vollständigen Neuindizierung zu verlieren. (#1240)

codegraph v1.4.1

[1.4.1] - 2026-07-10

New Features

  • The MCP server now notices when a newer CodeGraph release exists and tells you — a long-running server used to drift behind releases silently until something broke. On startup it checks the latest release in the background (never blocking, at most once a day, cached across all servers on the machine) and surfaces a one-line "update available — run codegraph upgrade" notice in the server log, in the instructions your agent sees on connect, and in codegraph_status. Nothing updates by itself, and being offline just means no notice. Opt out with CODEGRAPH_NO_UPDATE_CHECK=1; DO_NOT_TRACK=1 disables it too. (#1243)

Fixes

  • codegraph upgrade on a Windows npm install actually runs npm again — modern Node refuses to launch npm.cmd directly, so the upgrade failed with a spawn error before doing anything. npm is now invoked the way a terminal would run it. (#1238)
  • codegraph uninstall now actually uninstalls CodeGraph. It used to remove only the agent configurations and leave every installed binary behind, so codegraph still ran afterward — especially confusing when both an npm global install and a standalone install were present and removing one still left the other answering on PATH. Uninstall now finds every install on the machine (the standalone bundle, the npm global package, the launcher link) and removes them all, after showing you exactly what it found and asking first (--yes skips the prompt). Machine-level settings like your telemetry choice are preserved, a source checkout is never touched, and the new --keep-cli flag restores the old configs-only behavior. (#1071)
  • codegraph_explore no longer lets ordinary English words in a natural-language question hijack the ranking when they happen to match a code symbol's name. A question like "how does the upgrade flow check the latest version" used to treat "check" as a symbol the agent asked for by name, rank that unrelated definition's file first, and crowd the files the question is actually about out of the answer entirely. Precisely written symbol names (camelCase, PascalCase, snake_case, qualified names) still get top billing exactly as before, as do plain-word symbol bags whose words belong together in the same file.
  • PHP method calls made through a class property — $this->dep->method(), the dominant call shape in constructor-injection codebases (Symfony, Laravel) — now resolve to the method on the property's declared type, so callers and impact analysis see production call sites instead of reporting a DI-heavy method as uncalled or test-only. Promoted constructor parameters, typed properties, classic constructor assignment (including multi-line signatures), and typed setter injection all count; interface-typed properties resolve to the interface method, and inherited methods resolve through the type hierarchy. Only property-shaped declarations are consulted — a same-named local variable or parameter elsewhere can never mistype the property — and a property whose type can't be recovered statically stays unlinked rather than guessed. Thanks @w0lan. (#1220)
  • codegraph upgrade now also refreshes what previous versions installed into your agents — the CodeGraph section in CLAUDE.md / AGENTS.md / GEMINI.md and the MCP entry — so upgrading no longer leaves agents following instructions written for tools that have since been renamed or removed. Refresh-only: agents you never configured are not touched, and your permission and hook choices are preserved. Also available manually as codegraph install --refresh, and skippable with CODEGRAPH_NO_INSTALL_REFRESH=1. (#1238)
  • codegraph upgrade on an npm install now upgrades through npm again instead of quietly creating a second copy that never wins the PATH race — previously codegraph --version kept reporting the old version forever, no matter how many times you upgraded. (#1238)
  • After every upgrade, CodeGraph now checks that the codegraph command your terminal resolves actually serves the freshly installed version — confirming you don't need a new terminal, or telling you exactly which stale install is shadowing the new one. (#1071)
  • The safety watchdog no longer kills a healthy index on severely degraded storage. It used to judge liveness purely by the event loop, so one long database write on a struggling disk looked identical to a hung process and could get a valid, in-progress index terminated. During codegraph index/codegraph init the watchdog now also checks whether the index files on disk are advancing before it acts: slow-but-progressing work is left alone (bounded by a hard cap), while a genuinely hung process is still killed exactly as fast as before. (#1231)
  • Incremental sync now picks up cross-file relationships that only become resolvable after an edit — for example, when a file gains an export that another, unchanged file was already importing or calling. Previously the reference in the unchanged file was never revisited, so callers, impact, and flow results silently omitted the new edge (while status reported a clean index) until a full re-index. References that can't be resolved yet are now remembered and automatically retried whenever a change introduces a symbol that could satisfy them — this also covers a class gaining a new method that other files already call. Thanks @loadcosmos for the report with a minimal reproduction. (#1240)
  • The reverse case is fixed too: when an edit removes or moves a symbol (or deletes its file), callers in unchanged files now re-resolve during the same sync — rebinding to the symbol's new home when it moved, or waiting to reconnect automatically when it comes back — instead of silently losing their relationship until a full re-index. (#1240)
