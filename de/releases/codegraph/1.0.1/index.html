Codegraph v1.0.1

[1.0.1] – 13.06.2026

Neue Funktionen

– Neuer Befehl codegraph daemon (Alias daemons) – ein interaktiver Manager für die Hintergrunddämonen. Es zeigt an, was ausgeführt wird (zuerst der Daemon Ihres aktuellen Projekts, vorausgewählt), und Sie können mit der Pfeiltaste auf einen klicken und die Eingabetaste drücken, um ihn zu stoppen, oder Sie wählen „Alle stoppen“. Bisher bestand die einzige Möglichkeit, einen Daemon herunterzufahren, darin, nach seiner PID zu suchen und sie manuell mit kill zu versehen. (#845)

  • Die Überprüfung Ihrer installierten Version ist jetzt ganz einfach, egal wie Sie sie erraten: codegraph version, codegraph -v und codegraph -version drucken sie alle zusammen mit der vorhandenen codegraph --version aus. (#864) – Der CodeGraph MCP-Server führt jetzt eine Selbstheilung durch, wenn sein Hauptthread jemals abstürzt. Ein schlanker Watchdog erkennt, wenn der Prozess nicht mehr reagiert, und stoppt ihn, sodass bei Ihrer nächsten Anfrage ein neuer Prozess gestartet wird – er kann nicht länger auf 100 % CPU fixiert bleiben und keine Möglichkeit zur Wiederherstellung haben. Optimieren Sie das Erkennungsfenster mit CODEGRAPH_WATCHDOG_TIMEOUT_MS oder schalten Sie es mit CODEGRAPH_NO_WATCHDOG=1 vollständig aus. (#850)

Korrekturen

– Git-Arbeitsbäume, die in Ihrem Projekt verschachtelt sind – wie der .claude/worktrees/, den Claude Code erstellt – werden nicht mehr als doppelte Kopien Ihrer gesamten Codebasis indiziert. CodeGraph indiziert absichtlich echte eingebettete Repos (ein echtes zweites Projekt, das in Ihrem ausgecheckt wurde), aber ein Arbeitsbaum ist nur eine weitere Arbeitsansicht eines Repos, das es bereits indiziert hat, sodass jedes einzelne Symbol jedes Symbol multiplizierte – ein Bericht stieg von ~1.850 Dateien auf über 24.000, wobei Suche und explore mit veralteten Duplikaten überschwemmt wurden. CodeGraph erkennt jetzt Arbeitsbäume und überspringt sie, während echte eingebettete Repos und Submodule weiterhin indiziert werden. Danke @tphakala. (#848)

  • Das manuelle Ausführen von codegraph serve --mcp bleibt nicht länger still stehen. Dieser Befehl ist der MCP-Server, den Ihr KI-Agent selbst startet – kein Schritt, den Sie direkt ausführen – und in einem Terminal saß er früher da und wartete auf Eingaben, die nie eintrafen, und sah kaputt aus. Es erkennt jetzt, wenn jemand es ausführt, und erklärt, was stattdessen zu tun ist (codegraph status, codegraph daemon). Außerdem wurde es aus der Befehlsliste entfernt, sodass es nicht mehr wie etwas aussieht, das Sie starten müssen.
  • Dateiübergreifende statische Methodenaufrufe wie ClassName.staticMethod() werden jetzt korrekt aufgelöst. CodeGraph verknüpfte den Aufruf mit der Klasse statt mit der Methode (und zeichnete ihn als Konstruktion auf), sodass callers und impact für eine statische Methode leer zurückblieben – ein echter blinder Fleck in den Codebasen TypeScript und JavaScript, die auf statischen Dienstprogrammklassen basieren (Python und andere Sprachen mit derselben Aufrufform profitieren ebenfalls). Der Aufruf verknüpft nun die Methode selbst. Danke @contextFlow-lab. (#825) – codegraph affected akzeptiert jetzt ./-präfixierte und absolute Dateipfade, nicht nur bloße projektrelative. Die Übergabe von ./src/x.ts oder eines absoluten Pfads – häufig, wenn die Dateiliste von einem anderen Tool stammt – wird verwendet, um stillschweigend nichts zu finden und keine betroffenen Tests zu melden. Danke @contextFlow-lab. (#825) – Es besteht nicht mehr die Gefahr, dass der CodeGraph MCP-Server nach einem unerwarteten internen Fehler bei 100 % CPU hängen bleibt. Zuvor wurde ein solcher Fehler protokolliert, aber der Prozess lief in einem fehlerhaften Zustand weiter, in dem er einen CPU-Kern auf unbestimmte Zeit drehen konnte und manuell beendet werden musste. Der Server protokolliert nun den Fehler und beendet den Vorgang sauber, sodass bei der nächsten Anfrage ein neuer Fehler gestartet wird. Danke @songhlc. (#850)
  • CodeGraph indiziert nicht mehr versehentlich Ihr gesamtes Home-Verzeichnis. Das Ausführen des Installationsprogramms – oder codegraph init / codegraph index – von Ihrem Home-Ordner oder einem Dateisystem-Stammverzeichnis aus würde alles darunter indizieren (Caches, Library, jedes andere Projekt), was zu einem Multi-Gigabyte-Index und einer ständigen Abwanderung bei der Dateiüberwachung führt. CodeGraph lehnt diese Wurzeln jetzt ab und verweist Sie stattdessen auf ein bestimmtes Projekt. Übergeben Sie --force, wenn Sie es wirklich wollen. (In Kombination mit dem macOS-Dateideskriptor-Fix bereits in 1.0.0 schließt dies den Bericht eines außer Kontrolle geratenen Beobachters, der das Systemdateilimit erschöpft.) Danke @ligson. (#845)

codegraph v1.0.1

[1.0.1] - 2026-06-13

New Features

  • New codegraph daemon command (alias daemons) — an interactive manager for the background daemons. It shows what's running (your current project's daemon first, pre-selected), and you arrow-key to one and press enter to stop it, or pick "Stop all". Previously the only way to shut a daemon down was to hunt for its pid and kill it by hand. (#845)
  • Checking your installed version is now easy to reach however you guess at it: codegraph version, codegraph -v, and codegraph -version all print it, alongside the existing codegraph --version. (#864)
  • The CodeGraph MCP server now self-heals if its main thread ever locks up. A lightweight watchdog notices when the process has stopped responding and stops it so a fresh one starts on your next request — it can no longer sit pinned at 100% CPU with no way to recover. Tune the detection window with CODEGRAPH_WATCHDOG_TIMEOUT_MS, or turn it off entirely with CODEGRAPH_NO_WATCHDOG=1. (#850)

Fixes

  • Git worktrees nested inside your project — like the .claude/worktrees/ that Claude Code creates — are no longer indexed as duplicate copies of your whole codebase. CodeGraph deliberately indexes genuine embedded repos (a real second project checked out inside yours), but a worktree is just another working view of a repo it already indexed, so each one was multiplying every symbol — one report went from ~1,850 files to over 24,000, with search and explore flooded by stale duplicates. CodeGraph now recognizes worktrees and skips them, while still indexing real embedded repos and submodules. Thanks @tphakala. (#848)
  • Running codegraph serve --mcp by hand no longer just hangs in silence. That command is the MCP server your AI agent starts for itself — not a step you run directly — and in a terminal it used to sit there waiting for input that never comes, looking broken. It now recognizes when a person runs it and explains what to do instead (codegraph status, codegraph daemon), and it's been dropped from the command listing so it stops looking like something you need to launch.
  • Cross-file static method calls like ClassName.staticMethod() now resolve correctly. CodeGraph was linking the call to the class instead of the method (and recording it as a construction), so callers and impact for a static method came back empty — a real blind spot in TypeScript and JavaScript codebases that lean on static utility classes (Python and other languages with the same call shape benefit too). The call now links to the method itself. Thanks @contextFlow-lab. (#825)
  • codegraph affected now accepts ./-prefixed and absolute file paths, not just bare project-relative ones. Passing ./src/x.ts or an absolute path — common when the file list comes from another tool — used to silently match nothing and report no affected tests. Thanks @contextFlow-lab. (#825)
  • The CodeGraph MCP server no longer risks getting stuck at 100% CPU after an unexpected internal error. Previously such an error was logged but the process was left running in a broken state, where it could spin a CPU core indefinitely and had to be killed by hand. The server now logs the error and exits cleanly, so a fresh one starts on the next request. Thanks @songhlc. (#850)
  • CodeGraph no longer indexes your entire home directory by accident. Running the installer — or codegraph init / codegraph index — from your home folder or a filesystem root would index everything underneath it (caches, Library, every other project), producing a multi-gigabyte index and constant file-watching churn. CodeGraph now refuses these roots and points you at a specific project instead; pass --force if you genuinely mean to. (Combined with the macOS file-descriptor fix already in 1.0.0, this closes the report of a runaway watcher exhausting the system file limit.) Thanks @ligson. (#845)
