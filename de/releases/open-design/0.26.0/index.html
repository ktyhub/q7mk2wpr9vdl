🌟 Codename: Teilen, Überprüfen, Verfeinern

🔗 Die Arbeit kann das Projekt verlassen – und das Feedback kann seinen Weg nach Hause finden. Teilen Sie ein interaktives Design- oder Bewegungsvideo mit den Personen, die es überprüfen müssen; Lassen Sie sie zuschauen, es ausprobieren und im Kontext kommentieren. Wählen Sie dann das Feedback aus, das Ihnen wichtig ist, senden Sie es an einen Agenten und halten Sie die Bewertung mit der nächsten Bearbeitungsrunde in Verbindung.

🔥 Highlights

  • 🎞️ Motion Design – bringen Sie die Idee in Bewegung. Motion Design erscheint jetzt auf der Startseite und in der Community, mit kuratierten Helfern und Beispielen. Beginnen Sie mit einer bearbeitbaren Quelle, erstellen Sie Bewegungen für ein Video-Briefing und exportieren Sie eine MP4-Datei, wenn die Arbeit übertragen werden muss. (#8619)
  • 🔗 Ein Link für das Team und den client. Kopieren Sie einen Arbeitslink und versenden Sie ihn: Angemeldete Prüfer können die Arbeit in einem Browser ansehen und ausprobieren, ohne die Desktop-App zu installieren. Bewegte Videos können auf die gleiche Weise übertragen werden. Auf der freigegebenen Seite werden die Arbeitsvorschau und ihre Kommentare angezeigt – nicht die KI-Konversationen oder die Codeansicht des Projekts. (#8408) Danke @alchemistklk.
  • 💬 Kommentieren Sie den Teil, der geändert werden muss. Wählen Sie die Stelle im Werk aus, die Ihrer Aufmerksamkeit bedarf, und hinterlassen Sie einen Kommentar wie „Diesen Titel hervorheben“ oder „Farbe dieser Schaltfläche ändern“. Jeder sieht das gleiche Feedback auf derselben Seite, mit weniger Screenshot-Markup und weniger Klärungsschleifen. (#8408) Danke @alchemistklk.
  • 🤖 Bringen Sie Feedback zum Projekt zurück – und übergeben Sie die Überarbeitung an einen Agenten. Kommentare werden mit Open Design synchronisiert. Wählen Sie das Feedback aus, auf das Sie reagieren möchten, senden Sie es an einen Agenten und überprüfen Sie das Ergebnis vor dem nächsten Durchgang. (#8408) Danke @alchemistklk.
  • 🔄 Aktualisieren Sie die Arbeit, nicht den Link. Aktualisieren Sie nach einer Überarbeitung den freigegebenen Inhalt manuell, und Prüfer können weiterhin dieselbe URL verwenden. Sie sehen, dass eine neuere Version verfügbar ist und können sie aktualisieren, um sie anzuzeigen. Beenden Sie die Freigabe, sobald die Überprüfung abgeschlossen ist. (#8408) Danke @alchemistklk.
  • 🧩 Plugins bleiben mit der von Ihnen gesendeten Arbeit verbunden. Wenn Sie ein Plugin in einem vorhandenen Projekt anwenden, bleibt jetzt der ausgewählte Snapshot erhalten und die von Ihnen bereits gewährten Funktionen werden berücksichtigt. (#7597) Danke @lorenzonee.
  • 🧠 Bringen Sie das Modell mit, das Sie tatsächlich verwenden. Geben Sie beim BYOK-Onboarding ein benutzerdefiniertes Modell ein, anstatt sich auf die vorgeschlagene Liste zu beschränken – nützlich für lokales Ollama, selbstgehostete Endpunkte und neuere Modelle. (#6076) Danke @dpeterson01.
  • 🌀 Ein festgefahrener Chat kann seinen Weg zurückfinden. Wenn ein Chat-Protokoll nicht mehr seinem Layout folgt, stellt Open Design das Scrollen wieder her und hält die Rad- und Tastaturnavigation verfügbar. (#8251) Danke @lefarcen.
  • 🖼️ Fertig gestellte Arbeiten werden dort angezeigt, wo Sie sie erwarten. Nachdem ein Lauf ein Bild oder eine Datei erstellt hat, aktualisiert Open Design dessen Schnappschuss und öffnet das Ergebnis nach den bestehenden Regeln – ohne eine von Ihnen ausgewählte Vorschau zu übernehmen. (#8744)

✨ Hinzugefügt

🎨 Studio, Bearbeitung und Leinwand

  • Motion Design bietet kuratierte Fähigkeiten, gebündelte Beispiele, bearbeitbare Quellen und MP4-Produktion für videoorientierte Arbeit. (#8619)

🔑 Modelle und Plugins

  • BYOK-Onboarding akzeptiert neben den integrierten Vorschlägen auch benutzerdefinierte Modellnamen. (#6076) Danke @dpeterson01.
  • Bestehende Projekte behalten den Plugin-Snapshot und die gewährten Funktionen bei, die für eine Anwendung ausgewählt wurden. (#7597) Danke @lorenzonee.

🐛 Behoben

🤝 Teilen und Zusammenarbeiten

  • Angemeldete Prüfer können freigegebene Arbeiten oder Videos im Browser ansehen und mit ihnen interagieren; Geteilte Seiten halten Projekt-KI-Gespräche und Codeansichten absichtlich privat. (#8408) Danke @alchemistklk.
  • Kontextbezogene Kommentare werden mit dem Projekt synchronisiert, wo ausgewähltes Feedback zur nächsten Überarbeitung an einen Agenten gesendet werden kann. (#8408) Danke @alchemistklk.
  • Ein freigegebener Arbeitslink bleibt über manuell aktualisierte Revisionen hinweg stabil und kann gestoppt werden, wenn die Überprüfung abgeschlossen ist. (#8408) Danke @alchemistklk.
  • Vorhandene Cloud-Dateiidentitäten und Aliase werden vor der Veröffentlichung wiederhergestellt, sodass fortgesetzte oder aktualisierte Freigaben ihre ursprünglichen Links behalten, wenn lokale Zuordnungen fehlen. (#8859, #8867) Danke @alchemistklk.
  • Durch das Hochladen doppelter Dateinamen in einem Stapel bleiben Namen und Inhalte in der Übermittlungsreihenfolge. (#8742)

🧠 Agenten, Läufe und Zuhause

  • Home hält einen Wechsel blockiert, wenn die Finanzierungsbestätigung unzureichend oder unbekannt ist; Bei Rechnungsänderungen wird der Hinweis aktualisiert, ohne dass der Entwurf für Sie gesendet wird. (#8688, #8775, #8786) – Das Standard-AMR-Modell wird aus dem verfügbaren Katalog des Aufrufers aufgelöst, wodurch ein vermeidbarer Fehler beim ersten Start vermieden wird. (#8519) Danke @Siri-Ray. – Bei zwischengespeicherten Offline-Inhalten werden nun Widerruf und Ablauf bei Neustarts berücksichtigt. (#8676)

🖥️ Desktop und Arbeitsbereich

– Workspace-Benutzer können die Sicherheitsprüfung für Desktop-Updates abschließen, ohne dass eine nicht bereichsbezogene Active-Run-Anfrage den Neustart blockiert. (#8462) Danke @Siri-Ray. – Eine gespeicherte leere lokale Dateiauswahl überlebt die Wiederherstellung, anstatt durch ein Standardartefakt ersetzt zu werden. (#8745) Danke @open-design-crew.

🙏 Vielen Dank an alle, die 0.26.0 verschickt haben

open-design open-design-v0.26.0

🌟 Codename: Share, Review, Refine

🔗 The work can leave the project—and the feedback can find its way home. Share an interactive design or motion video with the people who need to review it; let them watch, try it, and comment in context. Then choose the feedback that matters, send it to an Agent, and keep the review connected to the next round of making.

🔥 Highlights

  • 🎞️ Motion Design—make the idea move. Motion Design now appears on Home and in Community, with curated helpers and examples. Start from an editable source, create motion for a video brief, and export an MP4 when the work needs to travel. (#8619)
  • 🔗 One link for the team and the client. Copy a work link and send it out: signed-in reviewers can view and try the work in a browser, without installing the desktop app. Motion videos can travel the same way. The shared page shows the work preview and its comments—not the project's AI conversations or code view. (#8408) Thanks @alchemistklk.
  • 💬 Comment on the part that needs changing. Select the place in the work that needs attention and leave a comment such as “make this title stand out” or “change this button color.” Everyone sees the same feedback on the same page, with less screenshot markup and fewer clarification loops. (#8408) Thanks @alchemistklk.
  • 🤖 Bring feedback back to the project—and hand the revision to an Agent. Comments sync into Open Design. Select the feedback to act on, send it to an Agent, then review the result before the next pass. (#8408) Thanks @alchemistklk.
  • 🔄 Update the work, not the link. After a revision, manually refresh the shared content and reviewers can keep using the same URL. They see that a newer version is available and can refresh to view it; end the share whenever the review is done. (#8408) Thanks @alchemistklk.
  • 🧩 Plugins stay attached to the work you send. Applying a plugin in an existing project now preserves its selected snapshot and respects the capabilities you already granted. (#7597) Thanks @lorenzozanee.
  • 🧠 Bring the model you actually use. During BYOK onboarding, enter a custom model instead of being limited to the suggested list—useful for local Ollama, self-hosted endpoints, and newer models. (#6076) Thanks @dpeterson01.
  • 🌀 A stuck chat can find its way back. When a chat log stops following its layout, Open Design recovers scrolling and keeps wheel and keyboard navigation available. (#8251) Thanks @lefarcen.
  • 🖼️ Finished work shows up where you expect it. After a run creates an image or file, Open Design refreshes its snapshot and opens the result by the existing rules—without taking over a preview you selected yourself. (#8744)

✨ Added

🎨 Studio, editing and canvas

  • Motion Design adds curated skills, bundled examples, editable sources, and MP4 production for video-oriented work. (#8619)

🔑 Models and plugins

  • BYOK onboarding accepts custom model names alongside the built-in suggestions. (#6076) Thanks @dpeterson01.
  • Existing projects retain the plugin snapshot and granted capabilities chosen for an apply. (#7597) Thanks @lorenzozanee.

🐛 Fixed

🤝 Sharing and collaboration

  • Signed-in reviewers can view and interact with shared work or motion video in the browser; shared pages intentionally keep project AI conversations and code views private. (#8408) Thanks @alchemistklk.
  • Contextual comments sync back to the project, where selected feedback can be sent to an Agent for the next revision. (#8408) Thanks @alchemistklk.
  • A shared work link stays stable across manually refreshed revisions and can be stopped when the review is complete. (#8408) Thanks @alchemistklk.
  • Existing cloud file identities and aliases are recovered before publishing, so resumed or updated shares keep their original links when local mappings are missing. (#8859, #8867) Thanks @alchemistklk.
  • Uploading duplicate filenames in one batch keeps names and contents in submission order. (#8742)

🧠 Agents, runs and Home

  • Home keeps a draft blocked when funding confirmation is insufficient or unknown; billing changes refresh the hint without sending that draft for you. (#8688, #8775, #8786)
  • The default AMR model is resolved from the caller's available catalog, avoiding an avoidable first-run failure. (#8519) Thanks @Siri-Ray.
  • Cached offline content now respects revocation and expiry across restarts. (#8676)

🖥️ Desktop and workspace

  • Workspace users can complete the desktop update safety check without an unscoped active-run request blocking restart. (#8462) Thanks @Siri-Ray.
  • A saved empty local file selection survives restore instead of being replaced by a default artifact. (#8745) Thanks @open-design-crew.

🙏 Thanks to everyone who shipped 0.26.0

@alchemistklk · @hihicheems · @Siri-Ray · @dpeterson01 · @lefarcen · @lorenzozanee
