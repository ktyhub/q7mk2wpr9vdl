📁 Artefakte

Eine neue Seite Artefakte führt die in Ihren Konversationen erstellten Dateien sowohl in der Webkonsole als auch auf dem Desktop client zusammen:

  • Automatische Sammlung: Dokumente, Webseiten, Bilder und Videos, die Ihre Agenten erstellen, werden automatisch in Artefakten auf einer Zeitleiste für alle Agenten angezeigt.
  • Vorschau und Rückverfolgung: Nach Typ oder Agent filtern, suchen, direkt in der Vorschau anzeigen und zu der Konversation zurückspringen, die eine Datei erstellt hat (Danke @rudycelekli #3732).
  • Anheften und verwalten: Artefakte anheften, umbenennen oder entfernen; Eine Karteikarte in einem Gespräch führt Sie direkt dorthin in Artefakte. Die Seite „Artefakte“ ist standardmäßig ausgeblendet und kann im Menüeditor aktiviert werden.

Zugehörige Dokumente: Webkonsole – Artefakte

🧭 Benutzerdefinierte Menü- und Konsolenverbesserungen

  • Benutzerdefiniertes Menü: Passen Sie die Gruppen, Reihenfolge, Namen, Symbole und Sichtbarkeit von Menüeinträgen in der Webkonsole und dem Desktop client mit einer gemeinsamen Konfiguration an; Artefakte und Weblinks können als Menüeinträge hinzugefügt werden. Siehe Benutzerdefiniertes Menü.
  • Token-Nutzung: Jede Antwort zeigt die in dieser Runde tatsächlich verwendeten Token, einschließlich Cache-Treffer. Danke @Harbor404 (#3440)
  • Meerjungfrau-Diagramme: Meerjungfrau-Codeblöcke können zu einem gerenderten Diagramm mit Zoom und Vollbild wechseln. Danke @akushonkamen (#3620)
  • Schnellere lange Sitzungen: Lange Sitzungen mit vielen Tool-Aufrufen werden schneller geöffnet.
  • Korrekturen: Neue Sitzungstitel gehen nicht mehr verloren und Sitzungsaktionen auf dem Standardagenten schlagen nicht mehr fehl (Danke @6vision #3625, #3617); Zusammen gespeicherte Einstellungen werden jetzt alle wirksam und Arbeitsbereichsdateien werden unter dem Agenten gespeichert, zu dem sie gehören (Danke @aniruddhaadak80 #3454, #3488).
  • Zusammenklappbare Seitenleiste: Die Seitenleiste der Webkonsole kann zu einer Symbolleiste zusammengeklappt werden.

🔌 Öffnen Sie den Agenten-Chat API

Agenten sind jetzt über einen Standard-Chat API erreichbar, sodass Sie clients von Drittanbietern verbinden oder einen Agenten direkt von Ihren eigenen Systemen aus anrufen können:

  • Schalter und Schlüssel: Schalten Sie den API ein und generieren Sie einen API-Schlüssel in einem click auf der Konfigurationsseite; Der Schlüssel bleibt erhalten, wenn der API ausgeschaltet wird. Es kann auch über die Konfigurationsdatei oder Umgebungsvariablen aktiviert werden (Danke @AaronZ345 #3068, @Bdysj #3342).
  • Agenten- und Modellauswahl: Wählen Sie den Agenten mit agent_id und das Modell mit model; Ohne Modell wird das Standardmodell des Agenten verwendet.
  • Multi-Turn-Gespräche: Standardmäßig sendet der Anrufer den vollständigen Nachrichtenverlauf; Bei einem conversation_id behält der Server den Verlauf und es muss nur die neueste Nachricht gesendet werden.
  • Vollständige Ausgabe: Streaming- und Nicht-Streaming-Antworten, einschließlich Begründung, Token-Nutzung und Tool-Aufruf-Trace (Danke @AaronZ345 #3068, @c020627 #3545, #3588).

Zugehörige Dokumente: Chat API

📐 Schnelles Caching und Kontextkosten

  • Claude-Eingabeaufforderungs-Caching: Die Systemeingabeaufforderung, die Tooldefinitionen und das Konversationspräfix werden zwischengespeichert, was die Cache-Trefferraten erheblich verbessert und Token-Kosten und Latenz senkt. Die Cache-Lebensdauer ist über claude_cache_ttl konfigurierbar.
  • Headroom nach dem Trimmen: Das Trimmen des Kontexts lässt jetzt Headroom, sodass das Präfix für die nächsten Runden unverändert bleibt und lange Sitzungen weiterhin auf den Cache zugreifen.
  • Budgetänderungen gelten sofort: Änderungen am Kontextbudget und den maximalen Schritten gelten für die sofortige Ausführung von Agenten, ohne dass die Sitzung beendet werden muss.
  • Werkzeugdatensätze werden in der Komprimierung gespeichert: Komprimierte Windungen behalten eine Zusammenfassung ihrer Werkzeugaufrufe, sodass das Modell keine Ergebnisse erstellt (Danke @tsumon #3634).
  • Korrekturen: Während der Komprimierung eintreffende Nachrichten gehen nicht mehr verloren und verwaiste Tool-Ergebnisse werden genauer bereinigt (Danke @c020627 #3518, @rudycelekli #3652, #3653).

🤖 Modellfähigkeiten

  • Claude erweitertes Denken: Die Verbindung bleibt während des langen Denkens offen, und wenn die Ausgabe ins Stocken gerät, wird die Anfrage mit geringerem Denkaufwand erneut versucht.
  • Benutzerdefinierte Header: Anbieter benutzerdefinierter Modelle unterstützen headers mit Unterstützung für OpenCode Go.
  • Modellerkennung: Beim Bearbeiten einer Modellliste können verfügbare Modelle automatisch vom Anbieter abgerufen werden. Danke @Harbor404 (#3441)
  • Begründungsinhalt: Sowohl die Felder reasoning als auch thinking werden unterstützt und ein nicht geschlossenes <think>-Tag schneidet die Antwort nicht mehr ab (Danke @a1094174619 #3601, @fly0sheep-1734 #3538).
  • Fallback-Modelle: Das Fallback-Modell wird zu Beginn jeder Runde zurückgesetzt, anstatt weiterhin verwendet zu werden.
  • OpenAI: verbesserte Handhabung der Antworten API und Streaming-Antworten (Danke @rudycelekli #3659, #3660, #3661, #3663, @aniruddhaadak80 #3486).
  • Modellliste: Behoben, dass sich gleichzeitige Bearbeitungen gegenseitig überschrieben, benutzerdefinierte Primärmodelle nicht wirksam wurden und Fähigkeits-Tag-Übereinstimmung (Danke @rudycelekli #3577, #3662, #3666, @aniruddhaadak80 #3501).
  • Andere Anbieter: Kompatibilitätsprobleme mit MiniMax, ModelScope, Baidu ERNIE und Azure DALL·E behoben (Danke @aniruddhaadak80 #3464, #3476, #3479, #3507, #3512, @rudycelekli #3678).
  • Fehlerbehandlung: Abgelehnte Anfragen werden nicht mehr erneut gesendet, Fehler werden genauer erkannt und die Kontextverwendung zeigt echte Token-Zählungen an (Danke @c020627 #3442, #3443, #3445, @aniruddhaadak80 #3505, @6vision #3624).
  • Bilder: Die Bildgenerierung behält das ursprüngliche Format und die Eingabeaufforderung bei, und das Bildverständnis unter macOS skaliert Bilder nicht mehr hoch (Danke @aniruddhaadak80 #3503, #3504, @rudycelekli #3568).

🧠 Speicher und Wissensdatenbank

  • Wissensbearbeitung und Fertigkeitserstellung: Bearbeiten Sie Wissensdatenbankseiten direkt in der Konsole mit automatisch aktualisiertem Index, schreiben Sie Fertigkeiten von Grund auf und bearbeiten Sie die Dateien im Verzeichnis einer Fertigkeit. Danke @zkjqd (#3377)
  • Trefferbasiertes Ranking: Ein neues optionales memory.hit_boost stuft häufig abgerufene Erinnerungen etwas höher ein. Standardmäßig deaktiviert. Danke @foreverjix (#3621)
  • Zeitverfall: gilt nur für tägliche Speicherdateien, sodass veraltete Wissensdatenbankseiten nicht mehr nach unten gereiht werden (Danke @fly0sheep-1734 #3376).
  • Indizierung: Behoben: Inhalt ging in sehr langen Zeilen verloren, Blöcke überstiegen das Budget und veraltete Indexeinträge nach dem Löschen von Notizen (Danke @fly0sheep-1734 #3585, @rudycelekli #3426, #3578, #3616).
  • Abruf: Verbesserter Fallback für die Volltextsuche, Unicode-Schlüsselwörter und Handhabung ungültiger Parameter und Vektoren (Danke @aniruddhaadak80 #3480, #3481, #3482, #3483, @rudycelekli #3559, #3656, #3658).
  • Speicherschreibvorgänge: Fehlgeschlagene Schreibvorgänge können wiederholt werden und Sitzungsdaten aus älteren Versionen können importiert werden (Danke @aniruddhaadak80 #3406, @c020627 #3590, @rudycelekli #3387).
  • Wissensdatenbank: Diagrammpfade unter Windows und Dokumenten mit nicht angezeigten Großbuchstabenerweiterungen korrigiert und Importpfadvalidierung verschärft (Danke @Lesereingrape #3332, @rudycelekli #3612, #3649, #3651).

🤝 Multi-Agenten-Zusammenarbeit

  • Berechtigungen und Delegierung: Delegierung und Übergabe behalten den Berechtigungsmodus des Initiators bei, und der empfangende Agent überprüft die Delegierungszulassungsliste, -tiefe und -wartezeit erneut (Danke @c020627 #3541, #3546, #3547, #3548, #3552).

chatgpt-on-wechat 2.2.1

Highlights

  • New user-facing capabilities — Artifacts automatically collects generated files in the Web console and desktop client, with search, preview, conversation links, and file management; the page is hidden by default and must be enabled through the menu editor. Custom Menu lets both clients share configured groups, order, names, icons, and visibility. Token usage per reply, rendered Mermaid diagrams, and a collapsible sidebar also improve day-to-day use.

  • Open Agent Chat API — Agents can now be exposed through a standard chat API, including streaming and non-streaming responses, reasoning, token usage, and tool-call traces. Select an Agent with agent_id and a model with model; without model, the Agent default applies. Enable it on the Config page or through config/environment variables, and supply either full message history or a server-managed conversation_id.

  • Lower cost and more reliable long sessions — Claude prompt caching now covers the system prompt, tool definitions, and conversation prefix, with configurable claude_cache_ttl. Context trimming preserves cache-friendly headroom, compaction retains tool-call summaries, and context-budget/max-step changes apply immediately without clearing sessions. This is particularly valuable for long-running or tool-heavy Claude sessions.

  • Broad correctness, compatibility, and security fixes — Notable fixes protect original files after failed writes, prevent concurrent model/session-setting edits from overwriting each other, improve Office document parsing and MCP reliability, support QQ files over 5 MB, clean up long-running instance memory, and repair multiple channel-specific messaging failures. Security hardening expands read-only restrictions, path/download validation, and log secret redaction; outside full-access mode, MCP configuration and session permissions can no longer be changed, so review any workflows that depend on modifying those at runtime.

  • Upgrade recommendation — Worth upgrading for API integrators, Claude users, long-session users, and anyone relying on affected providers, channels, or multi-Agent permission controls. No explicit breaking changes or required migration steps are stated; stable single-user setups unaffected by the new features can skip this release, but deployments using restricted permissions should test MCP and session-permission workflows. 📁 Artifacts

A new Artifacts page brings together the files created in your conversations, in both the Web console and the desktop client:

  • Automatic collection: documents, web pages, images, and videos your Agents create show up in Artifacts automatically, on one timeline across all Agents.
  • Preview and trace back: filter by type or Agent, search, preview in place, and jump back to the conversation that produced a file (Thanks @rudycelekli #3732).
  • Pin and manage: pin, rename, or remove artifacts; a file card in a conversation takes you straight to it in Artifacts. The Artifacts page is hidden by default and can be turned on in the menu editor.

  • Custom menu: customize the groups, order, names, icons, and visibility of menu entries in the Web console and desktop client, with one shared configuration; artifacts and web links can be added as menu entries. See Custom Menu.
  • Token usage: each reply shows the tokens actually used in that turn, including cache hits. Thanks @Harbor404 (#3440)
  • Mermaid diagrams: Mermaid code blocks can switch to a rendered diagram, with zoom and full screen. Thanks @akushonkamen (#3620)
  • Faster long sessions: long sessions with many tool calls open faster.
  • Fixes: new session titles are no longer lost, and session actions on the default Agent no longer fail (Thanks @6vision #3625, #3617); settings saved together now all take effect, and workspace files are saved under the Agent they belong to (Thanks @aniruddhaadak80 #3454, #3488).
  • Collapsible sidebar: the Web console sidebar can collapse into an icon rail.

🔌 Open Agent Chat API

Agents are now available through a standard chat API, so you can connect third-party clients or call an Agent directly from your own systems:

  • Switch and key: turn the API on and generate an API key in one click on the Config page; the key is kept when the API is turned off. It can also be enabled through the config file or environment variables (Thanks @AaronZ345 #3068, @Bdysj #3342).
  • Agent and model selection: choose the Agent with agent_id and the model with model; without a model, the Agent's default model is used.
  • Multi-turn conversations: by default the caller sends the full message history; with a conversation_id, the server keeps the history and only the latest message needs to be sent.
  • Complete output: streaming and non-streaming responses, including reasoning, token usage, and the tool call trace (Thanks @AaronZ345 #3068, @c020627 #3545, #3588).

📐 Prompt Caching & Context Cost

  • Claude prompt caching: the system prompt, tool definitions, and conversation prefix are cached, greatly improving cache hit rates and cutting token cost and latency. The cache lifetime is configurable via claude_cache_ttl.
  • Headroom after trimming: trimming the context now leaves headroom, so the prefix stays unchanged for the next several turns and long sessions keep hitting the cache.
  • Budget changes apply immediately: changes to the context budget and maximum steps apply to running Agents right away, without clearing the session.
  • Tool records kept in compaction: compacted turns keep a summary of their tool calls, so the model does not make up results (Thanks @tsumon #3634).
  • Fixes: messages arriving during compaction are no longer lost, and orphaned tool results are cleaned up more accurately (Thanks @c020627 #3518, @rudycelekli #3652, #3653).

🤖 Model Capabilities

  • Claude extended thinking: the connection stays open during long thinking, and when output stalls the request is retried at a lower thinking effort.
  • Custom headers: custom model providers support headers, with support for OpenCode Go.
  • Model discovery: when editing a model list, available models can be fetched from the provider automatically. Thanks @Harbor404 (#3441)
  • Reasoning content: both reasoning and thinking fields are supported, and an unclosed <think> tag no longer cuts off the reply (Thanks @a1094174619 #3601, @fly0sheep-1734 #3538).
  • Fallback models: the fallback model is reset at the start of each turn instead of staying in use.
  • OpenAI: improved handling of the Responses API and streaming responses (Thanks @rudycelekli #3659, #3660, #3661, #3663, @aniruddhaadak80 #3486).
  • Model list: fixed concurrent edits overwriting each other, custom primary models not taking effect, and capability tag matching (Thanks @rudycelekli #3577, #3662, #3666, @aniruddhaadak80 #3501).
  • Other providers: fixed compatibility issues with MiniMax, ModelScope, Baidu ERNIE, and Azure DALL·E (Thanks @aniruddhaadak80 #3464, #3476, #3479, #3507, #3512, @rudycelekli #3678).
  • Error handling: rejected requests are no longer resent, errors are recognized more accurately, and context usage shows real token counts (Thanks @c020627 #3442, #3443, #3445, @aniruddhaadak80 #3505, @6vision #3624).
  • Images: image generation keeps the original format and prompt, and image understanding on macOS no longer upscales images (Thanks @aniruddhaadak80 #3503, #3504, @rudycelekli #3568).

🧠 Memory & Knowledge Base

  • Knowledge editing and skill authoring: edit knowledge base pages directly in the console with the index updated automatically, write skills from scratch, and edit the files in a skill's directory. Thanks @zkjqd (#3377)
  • Hit-based ranking: a new optional memory.hit_boost ranks frequently retrieved memories slightly higher. Off by default. Thanks @foreverjix (#3621)
  • Time decay: applies only to daily memory files, so dated knowledge base pages are no longer ranked down (Thanks @fly0sheep-1734 #3376).
  • Indexing: fixed content lost on very long lines, chunks exceeding the budget, and stale index entries after clearing notes (Thanks @fly0sheep-1734 #3585, @rudycelekli #3426, #3578, #3616).
  • Retrieval: improved full-text search fallback, Unicode keywords, and handling of invalid parameters and vectors (Thanks @aniruddhaadak80 #3480, #3481, #3482, #3483, @rudycelekli #3559, #3656, #3658).
  • Memory writes: failed writes can be retried, and session data from older versions can be imported (Thanks @aniruddhaadak80 #3406, @c020627 #3590, @rudycelekli #3387).
  • Knowledge base: fixed graph paths on Windows and documents with upper-case extensions not showing, and tightened import path validation (Thanks @Lesereingrape #3332, @rudycelekli #3612, #3649, #3651).

🤝 Multi-Agent Collaboration

  • Path access: stricter path checks for uploads, static assets, skill uninstall, backup restore, and more, and credential files are blocked (Thanks @aniruddhaadak80 #3409, #3460, #3461, #3463, @c020627 #3446, @rudycelekli #3527, #3528, @Harbor404 #3436).

📦 How to Upgrade

  • Source deployment: run cow update for a one-click upgrade, update from the version menu in the Web console sidebar, or pull the latest code and restart. See the upgrade guide.
  • Desktop client: check for updates and update with one click inside the client, or get the latest version from the download page.
