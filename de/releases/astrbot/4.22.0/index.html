AstrBot v4.22.0

Was hat sich geändert?

Neu

  • Persönliche WeChat-Zugriffsfunktion hinzugefügt (offiziell bereitgestellt von WeChat). Einzelheiten finden Sie unter Persönlicher WeChat-Zugriff(#6777)
  • Bildkomprimierungsfunktionen hinzugefügt, die Bildgrößen- und JPEG-Qualitätsbeschränkungen unterstützen. (#6794) – Es wurde die Möglichkeit hinzugefügt, installierte Plug-Ins oben zu platzieren und per Drag-and-Drop die WebUI neu anzuordnen. (#6776)

Optimierung

  • Automatisches Überspringen des Abrufs, wenn die Wissensdatenbank leer ist, um ungültige Suchaufrufe zu vermeiden. (#6750) – Korrigieren Sie das Verhalten bei der Beibehaltung von frontmatter-Escape-Neuzeilenzeichen und aktualisieren Sie zugehörige Tests und CI-Workflows (einschließlich Dokument- und Konfigurationssynchronisierung). (#6783)

Beheben

– Telegram-Adapter importiert stattdessen Forbidden und ersetzt das veraltete Unauthorized (Kompatibilitätsfix). (#6769) – Behandeln Sie das abnormale Szenario, wenn token usage metrics im OpenAI-Anbieter None ist. (#6788)

  • Behalten Sie alle content-Elemente von CallToolResult bei, um zu verhindern, dass der Inhalt des Tool-Aufrufkontexts verloren geht. (#6149)

Neue Funktionen

(#6777) – Anheften und Drag-Sortierung für installierte WebUI-Plugins hinzugefügt. (#6776) – Bildkomprimierung mit Handhabung maximaler Größe und Lebenszyklusverwaltung temporärer Dateien für verbesserte Bildeffizienz hinzugefügt. (#6794)

Verbesserungen

– Die Suchausführung wurde übersprungen, wenn die gesamte Wissensdatenbank leer ist. (#6750) – Mit Escapezeichen versehene Zeilenumbrüche in frontmatter mit zugehörigen Test- und CI-Workflow-Updates beibehalten. (#6783)

Fehlerbehebungen

– Veralteter Telegram-Adapter-Import von Unauthorized durch Forbidden ersetzt. (#6769) – Verarbeitete None-Werte im OpenAI-Anbieter token usage metrics.（#6788） – Alle CallToolResult.content-Elemente wurden beibehalten, um zu verhindern, dass der Tool-Aufruf-Kontext verloren geht. (#6149)

AstrBot v4.22.0

Highlights

  • Personal WeChat access — #6777 adds official personal WeChat account support, with a QR-code-driven setup flow, a refactored message pipeline, and improved media handling. This is a new platform adapter to onboard, so expect new config/login steps (QR scan rather than a bot token) rather than a drop-in swap. Because it touches core message dispatch, pilot it on a secondary account before routing production traffic, and verify that media (images/voice) round-trips correctly through the refactored flow.
  • Image compression pipeline — #6794 introduces configurable compression with max-dimension and JPEG-quality limits plus temporary-file lifecycle management. For image-heavy deployments this directly cuts bandwidth, storage, and upstream API costs. Watch the temp-file cleanup under error paths — confirm files are removed on failed compressions to avoid disk leaks over long-running instances.
  • Leaner knowledge-base retrieval — #6750 skips search execution entirely when the knowledge base is empty, eliminating wasted embedding/vector queries and their latency. #6783 complements this by fixing preservation of escaped newlines in YAML frontmatter (with test and CI updates). If you parse frontmatter metadata, re-index your corpus after upgrading so documents parse as intended.
  • Tool-call context fidelity — #6149 now retains all CallToolResult.content items instead of discarding some. For agent/MCP workflows whose tools return multiple content blocks (text + image + embedded resource), this prevents silent context loss that could degrade downstream reasoning. No config change is needed, but audit any consumer code that assumed a single content item — result payloads will be richer.
  • Adapter and provider hardening — #6769 replaces the deprecated Telegram Unauthorized import with Forbidden, a compatibility fix tracking an upstream library deprecation. Check your pinned python-telegram-bot version, since the new import implies a minimum supported release. #6788 handles None token-usage metrics in the OpenAI provider, so usage reporting no longer crashes when a model/provider omits usage data.
  • WebUI plugin management — #6776 adds pinning and drag-to-reorder for installed plugins, speeding access to frequently used ones. Pure UI/UX improvement with no API or data-model impact.

No breaking changes.

What's Changed

新增

  • 新增个人微信接入能力（微信官方提供）。详见 个人微信接入（#6777）
  • 新增图片压缩能力，支持图片尺寸、JPEG 质量限制。（#6794）
  • 新增 WebUI 已安装插件置顶与拖拽重排能力。（#6776）

优化

  • 知识库为空时自动跳过检索，避免无效搜索调用。（#6750）
  • 修复 frontmatter 转义换行符保留行为并更新相关测试与 CI 工作流（含文档与配置同步）。（#6783）

修复

  • Telegram 适配器改为导入 Forbidden，替代已弃用的 Unauthorized（兼容性修正）。（#6769）
  • 处理 OpenAI Provider 中 token usage metrics 为 None 时的异常场景。（#6788）
  • 保留全部 CallToolResult 的 content 项，避免工具调用上下文内容丢失。（#6149）

What's Changed (EN)

New Features

  • Added WeChat personal account support, including QR-code driven setup, message flow refactor, and media handling improvements.（#6777）
  • Added pinning and drag-sorting for installed WebUI plugins.（#6776）
  • Added image compression with max-size handling and temporary-file lifecycle management for improved image efficiency.（#6794）

Improvements

  • Skipped search execution when the entire knowledge base is empty.（#6750）
  • Preserved escaped newlines in frontmatter, with related test and CI workflow updates.（#6783）

Bug Fixes

  • Replaced deprecated Telegram adapter import of Unauthorized with Forbidden.（#6769）
  • Handled None values in OpenAI provider token usage metrics.（#6788）
  • Kept all CallToolResult.content items to prevent losing tool-call context.（#6149）
