AstrBot v4.16.0

Was hat sich geändert?

Neu

  • Die offizielle Roboterplattform von QQ unterstützt aktive Push-Nachrichten und private Chat-Szenarien unterstützen den Empfang von Dateien (#5066)
  • Funktion hinzugefügt, um automatisch „Tippen“, „Bilder hochladen“ und andere Status beim Warten auf eine AI-Antwort an den Telegram-Plattform-Adapter anzuzeigen (#5037)
  • Für den Feishu-Adapter wurde die Möglichkeit hinzugefügt, Dateien zu empfangen und den Inhalt von Referenznachrichten (einschließlich referenzierter Bilder, Videos, Dateien, Texte usw.) zu lesen (#5018) – Unterstützung für benutzerdefinierten Plattformadapter i18n hinzugefügt (#5045)
  • Es wurden Funktionen zur Verarbeitung temporärer Dateien hinzugefügt, mit denen Sie die maximale Größe des Verzeichnisses data/temp in der Systemkonfiguration begrenzen können. (#5026)
  • Funktion zur Ankündigung des ersten Starts hinzugefügt, unterstützt Mehrsprachen- und WebUI-Integration

Beheben

– Chunk-Fehler im OpenRouter DeepSeek-Szenario behoben (#5069) – Das Problem der fehlenden Zuordnung von Personality-Ordnern während der Sicherung wurde behoben (#5042) – Das Problem der doppelten Bildlaufleisten im Update-Protokoll und in offiziellen Dokument-Popups wurde behoben (#5060) – Die abnormale Anzeige des Schlüssels im Popup-Fenster für zusätzliche Parameter des Anbieters wurde behoben – Das Problem ungenauer Fehlerprotokoll-Eingabeaufforderungen bei fehlgeschlagener Verbindung wurde behoben – Das Problem mit der Ressourcenbereinigung wurde behoben, das dadurch verursacht wurde, dass bei vorzeitiger Rückkehr nicht auf die Reset-Coroutine gewartet wurde (#5033) – Verbessern Sie die Startstabilität der gepackten Version des Desktops und optimieren Sie die Plug-in-Abhängigkeitsverarbeitung (#5031) – Größenrotation für Electron- und Backend-Protokolle hinzufügen (#5029) – Verstärkt den Ladevorgang für eingefrorene App-Laufzeit-Plug-in-Abhängigkeiten (#5015)

Optimierung

– Verbessern Sie Zusammenführungsnachrichten, Referenzauflösung und Bild-Rollback und unterstützen Sie die Konfigurationssteuerung (#5054) – Die Konfigurationsseite unterstützt das Umschalten zwischen normaler Konfiguration/Systemkonfiguration über Unterelemente in der Seitenleiste und relevante Routing-Korrekturen wurden hinzugefügt. – Optimieren Sie die Initialisierungslogik des segmentierten Antwortintervalls (#5068)

Dokumentation und Wartung

  • Synchronisieren und korrigieren Sie den Inhalt und die Rechtschreibung des README-Dokuments (#5055, #5014)
  • AUR-Installationsanweisungen hinzugefügt (#4879)
  • Codeformatierung durchführen (Ruff)

AstrBot v4.16.0

Highlights

  • QQ official bot adapter goes bidirectional — #5066 adds proactive message push and file receiving in private chats, so QQ bots can now initiate conversations and accept media instead of only reacting to incoming messages. For developers this unlocks push-based workflows (scheduled reports, alerts, proactive follow-ups) but watch out: proactive sends depend on the bot's granted privileges and are subject to QQ's platform-side frequency/permission limits, so build in rate limiting and graceful failure handling.

  • Richer message context on Telegram and Feishu — #5037 introduces send_chat_action, giving Telegram bots "typing…"/"uploading image…" presence while the AI is thinking — a small change that materially improves perceived responsiveness. #5018 lets the Feishu adapter receive files and read quoted message content (images, video, files, text), which means quoted media can now feed into multimodal prompts. Expect larger payloads and new Feishu permission scopes; verify your app's file/read permissions before relying on quoted attachments.

  • i18n lands for custom platform adapters — #5045 adds internationalization support to custom adapters, so adapter-authored strings can be localized rather than hard-coded in Chinese. If you maintain or ship third-party adapters, this is the hook to make them viable for non-Chinese deployments; budget a pass to wire your message templates into the new i18n layer.

  • Bounded temp-file lifecycle — #5026 adds TempDirCleaner and a configurable maximum size for data/temp. This matters for long-running, media-heavy instances that previously risked unbounded disk growth. Set the cap deliberately before enabling heavy file workflows — an aggressive default can evict temp files still needed by in-flight media processing.

  • Runtime reliability and correctness hardening — #5033 fixes an unawaited reset coroutine on early returns (real resource-leak prevention under error paths), while #5015 and #5031 harden plugin dependency loading in frozen/packaged desktop runtimes and #5029 adds size-based log rotation for Electron and backend logs. On the correctness side, #5069 fixes OpenRouter/DeepSeek chunk errors, #5054 improves forwarded-quote parsing with configurable image fallback, and #5042 restores missing persona-folder mappings in backups. If you run packaged desktop builds or OpenRouter DeepSeek, these are worth upgrading for alone.

  • Breaking changes — None; v4.16.0 is a backward-compatible feature and fix release, so no migration steps are required.

What's Changed

新增

  • QQ 官方机器人平台支持主动推送消息，私聊场景支持接收文件 (#5066)
  • 为 Telegram 平台适配器新增等待 AI 回复时自动展示 “正在输入”、“正在上传图片” 等状态的功能 (#5037)
  • 为飞书适配器增加接收文件、读取引用消息的内容（包括引用的图片、视频、文件、文字等） (#5018)
  • 新增自定义平台适配器 i18n 支持 (#5045)
  • 新增临时文件处理能力，可在系统配置中限制 data/temp 目录的最大大小。 (#5026)
  • 增加首次启动公告功能，支持多语言与 WebUI 集成

修复

  • 修复 OpenRouter DeepSeek 场景下的 chunk 错误 (#5069)
  • 修复备份时人格文件夹映射缺失问题 (#5042)
  • 修复更新日志与官方文档弹窗双滚动条问题 (#5060)
  • 修复 provider 额外参数弹窗 key 显示异常
  • 修复连接失败时错误日志提示不准确的问题
  • 修复提前返回时未等待 reset 协程导致的资源清理问题 (#5033)
  • 提升打包版桌面端启动稳定性并优化插件依赖处理 (#5031)
  • 为 Electron 与后端日志增加按大小轮转 (#5029)
  • 加固冻结运行时（frozen app runtime）插件依赖加载流程 (#5015)

优化

  • 完善合并消息、引用解析与图片回退，并支持配置化控制 (#5054)
  • 配置页面支持通过侧边栏子项切换普通配置/系统配置，并补充相关路由修复
  • 优化分段回复间隔时间初始化逻辑 (#5068)

文档与维护

  • 同步并修正 README 文档内容与拼写 (#5055, #5014)
  • 新增 AUR 安装方式说明 (#4879)
  • 执行代码格式化（ruff）
