#AstrBot v4.28.0

4.28.0 – 08.09.2026

Die Landschaft in den vier Jahreszeiten ist anders und die Freude ist grenzenlos.

Jede Jahreszeit bringt ihre eigene Schönheit mit sich und die Freude ist grenzenlos.

📢 Aufgrund der Optimierung einiger Konfigurationsdateien führt ein Downgrade nach dem Upgrade dazu, dass einige Konfigurationsinhalte zurückgesetzt werden. Bitte seien Sie vorsichtig, wenn Sie nach einem Upgrade ein Downgrade durchführen. Aufgrund struktureller Optimierungen in der Konfigurationsdatei führt ein Downgrade nach einem Upgrade zum Zurücksetzen einiger Konfigurationsinhalte. Seien Sie bitte vorsichtig, wenn Sie nach einem Upgrade ein Downgrade durchführen.

Wichtige Ergänzungen

– Die WebUI-Seiten für Modellanbieter, Bots und Profile wurden neu gestaltet und Protokolle, Ablaufverfolgungen, Konversationsverwaltung und Daten auf der Seite Daten & Protokolle zusammengefasst. Der Agent Runner wurde von den Modellanbietern entfernt und seine Einstellungen in jedes Profil eingebettet. (#9820, #9825, #9821, #9883, #9846)

  • Das standardmäßige und lokale T2I-Rendering wurde neu gestaltet. (#9803) – Angereicherte einheitliche Gruppenmetadaten für alle Messaging-Plattformadapter. (#9851)
  • Erfassen Sie automatisch lesbare Namen für Unified Message Origins (UMOs), wie z. B. Gruppen- und Benutzernamen, damit sie in der WebUI leichter zu finden sind. (#9909) – Maskierte geheime Felder für vertrauliche Werte in der WebUI und den Plugin-Konfigurationen hinzugefügt. (#9824) – Batch-Löschung zur WebUI-Skill-Management-Seite hinzugefügt. (#9906)
  • AnySearch als integrierten Websuchanbieter hinzugefügt. (#9767)
  • Standardmäßig Unterstützung für Plugin-Konfigurationsfelder im Passwortstil und maskierte vertrauliche Profilfelder hinzugefügt. (#9824)

Wichtige Optimierungen

– Die Art und Weise, wie Browser-Passwortmanager die WebUI-Anmeldeseite erkennen, wurde verbessert. (#9830)

  • Angepasste Modellanbieter-Symbole für den Dunkelmodus. (#9647)
  • Verbesserte Kontextverarbeitung für Agenten für zukünftige Aufgaben. (#9818)
  • Der Dialog des Skill-Editors reagiert jetzt auf kleineren Bildschirmen. (#9873) – Die Schemareihenfolge der OpenAI-Tools wurde stabilisiert, indem die Tools alphabetisch nach Namen sortiert wurden. (#9798)

Wichtige Korrekturen

– Es wurde ein Problem behoben, bei dem DingTalk nach dem Scannen des QR-Codes in einem unbekannten CREATING-Status bleiben konnte, wodurch die App-Erstellung nicht fortgesetzt werden konnte. (#9808) – Es wurde ein Problem behoben, bei dem Befehle in Lark-Gruppen nicht ausgelöst wurden, wenn die Bot-Erwähnung vor dem Befehl erschien. (#9872)

  • Isolierte Ratenbegrenzungen durch Unified Message Origin (UMO). (#9814)
  • Anthropic API-Basis-URL-Verarbeitung mit OpenAI API abgestimmt; /v1 muss nun in der konfigurierten URL enthalten sein. (#9802)
  • Die Abrechnung der Cache-Token-Nutzung für Anthropic und Gemini wurde korrigiert. (#9880, #9881) – Die max_agent_step-Konfiguration wurde auf Agenten für geplante Aufgaben und Hintergrundaufgaben angewendet. (#9801)
  • Erhaltener Text in gemischten Text- und Bildnachrichten von Lark. (#9841) – Die Schaltfläche „Ordner erstellen“ wurde im mobilen Persona-Manager angezeigt. (#9812)

AstrBot v4.28.0

Highlights

  • WebUI restructuring — Model provider, bot, and profile management were redesigned, while logs, traces, conversations, and data now live under Data & Logs. Agent Runner settings moved from model providers into individual profiles, so existing deployments need their runner configuration reviewed after upgrading (#9820, #9821, #9883, #9846).
  • Anthropic endpoint migration — API Base URL handling now matches OpenAI’s convention: configured Anthropic URLs must include /v1 (#9802). Update endpoint configuration before upgrading to avoid failed requests.
  • More predictable agent limits and quotas — max_agent_step now applies to scheduled and background agents, not just interactive sessions (#9801), while rate limits are isolated per unified message origin, preventing busy groups or users from exhausting a shared limit (#9814).
  • Search, secrets, and plugin controls — AnySearch is available as a built-in web search provider (#9767); sensitive WebUI and plugin values use masked/password-style fields (#9824); and skills support batch deletion (#9906), improving both integration options and day-to-day administration.
  • More reliable platform and model integrations — Fixes address leading-mention commands and mixed text/image preservation in Lark (#9872, #9841), DingTalk onboarding stuck in CREATING (#9808), Gemini thinking-level serialization (#9899), and Anthropic/Gemini cached-token accounting (#9880, #9881). Tool schemas are now sorted by name for stable OpenAI requests (#9798).
  • Context and runtime correctness — Tool parameter re-querying preserves the existing context prefix instead of rewriting the initial system message (#9957), and proactive agents now honor computer-runtime settings, defaulting to disabled when settings are absent (#9971). Cross-platform unit-test CI also now covers Windows, macOS, and Linux (#9954).
  • No backward compatibility: structural configuration changes mean downgrading can reset some settings.
