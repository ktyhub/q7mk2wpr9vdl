AstrBot v4.26.5

[4.26.5] – 07.07.2026

Hinzugefügt

– Unterstützung für das Festlegen einer benutzerdefinierten Bot-ID beim Erstellen einer Plattform durch Scannen eines QR-Codes hinzugefügt. (#9067)

  • ChatUI-Projektarbeitsbereiche hinzugefügt. (#9066)
  • Verbesserte Anzeige von ChatUI-Anhängen hinzugefügt. (#9134)
  • Behebung fehlerhafter Tool-Aufrufnamen in ToolLoopAgentRunner hinzugefügt. (#9144)
  • Modellmetadaten in Selektoren und eine Chat-Token-Nutzungsanzeige hinzugefügt. (#9161)
  • Ereignisschleifendiagnose und erweiterte Diagnosedokumentation hinzugefügt. (#9168)
  • Dokumentation für plattformübergreifende Kompatibilität und Python-Versionsunterstützung hinzugefügt. – Testabdeckung für die Erhaltung des POSIX-Datei-URI-Stamms hinzugefügt. (#8906)

Geändert

  • Protokollieren Sie den Start des Event-Loop-Watchdogs auf der Informationsebene.
  • Halten Sie Modellmetadaten von Anbietern getrennt. (#9161)
  • Polnisches Snackbar-Design in der WebUI. (#9173)

Behoben

– Nur synchronisierte ModelScope MCP-Server aktiviert. (#9084) – Verbesserte Handhabung beim Starten und Herunterfahren von MCP client, um Leerlauf-Spinning zu vermeiden und Fehler, Zeitüberschreitungen und Abbrüche zu beseitigen. (#9070) – Fragiler Fehlerabgleich bei doppelten Namen in der Wissensdatenbank durch eine Vorabprüfung ersetzt. (#9121)

  • Verbesserte Widerstandsfähigkeit beim Abruf der Wissensdatenbank bei Fehlern pro Wissensdatenbank und bei der Neuordnung der Auswahl. (#9122) – Bereinigte KBMedia-Datensätze zum Löschen von Dokumenten und korrigierte Aktualisierungen der Wissensdatenbankstatistiken. (#9120) – Der Wissensdatenbank-CRUD-Vertrag API wurde mit kb_name, kanonischen Nutzlastfeldern und OpenAPI-Typen abgeglichen. (#9000) – Eingeschränkte benutzerdefinierte Arbeitsbereichspfade und Beibehaltung absoluter benutzerdefinierter Arbeitsbereichspfade.
  • Verbessertes Failover des API-Schlüssels für die Websuche.
  • Erzwungener Besitz beim Lesen von ChatUI-Sitzungen. (#9141)
  • Gesicherte temporäre Bereitstellung von Projektaktualisierungen. (#9083) – Verbessertes QQ-Official-Wiederholungsverhalten, wenn der Websocket-Sendevorgang None zurückgibt. (#8977)
  • Der von QQ offiziell zitierte Nachrichtenkontext bleibt erhalten. (#9164) – Offizielle QQ-Antwort-IDs im proaktiven Fallback entfernt, sodass übergroße passive Antworten durch proaktives Senden erfolgreich sein können. (#9169) – MiMo STT an V2.5-Modelle angepasst und Nicht-WAV-Audio-Nutzlasten abgelehnt. (#9118)
  • Serialisierte Zeitstempel des Webchat-Verlaufs als UTC-fähige ISO-Zeichenfolgen. (#9159)
  • Synchronisierter Plugin-Aktivierungsstatus bei Aktivierung in der WebUI. (#9156) – MCP anyio-Kontexte in der Lebenszyklusaufgabe wurden beim Deaktivieren beendet. (#9132) – Durchgesickerte SSE-Exit-Stack-Verarbeitung behoben, die zu MCP-Epoll-Busy-Wait führen konnte. (#8307) [4.26.5]: https://github.com/AstrBotDevs/AstrBot/compare/v4.26.4...v4.26.5

AstrBot v4.26.5

Highlights

  • ChatUI workspaces and isolation — Project workspaces (#9066) let teams organize chat projects, while session reads now enforce ownership (#9141) and project-update staging is hardened (#9083). Custom workspace paths are constrained but absolute paths remain supported; verify existing path configurations after upgrading.

  • Knowledge-base API migration and resilience — The CRUD contract now standardizes on kb_name, canonical payload fields, and matching OpenAPI types (#9000). API clients should update request fields and regenerate models from the revised schema. Duplicate-name checks are more deterministic (#9121), retrieval tolerates individual knowledge-base failures (#9122), and document deletion now removes associated KBMedia records and fixes stats (#9120).

  • MCP lifecycle stability — Startup and shutdown handling now prevents idle spinning and cleans up correctly after errors, timeouts, and cancellation (#9070). Related fixes close anyio contexts on disable (#9132), repair leaked SSE exit stacks that could cause Linux epoll busy-waits (#8307), and enable only synchronized ModelScope servers (#9084). Expect unsynchronized ModelScope entries to remain disabled.

  • Tool-loop safety and runtime visibility — Malformed tool-call names are sanitized in ToolLoopAgentRunner (#9144), reducing failures caused by invalid model-generated tool names. Model metadata is now shown in selectors (#9160) and stored separately from providers (#9161), while chat token-usage indicators (#9162) and event-loop diagnostics (#9168) make cost tracking and stalled-agent investigations easier.

  • QQ Official delivery recovery — Quoted-message context is preserved (#9164), websocket sends returning None gain retry handling (#8979), and oversized passive replies can fall back to proactive sending by dropping the reply ID (#9169). Together, these changes reduce lost context and delivery failures for long messages or transient websocket errors.

  • MiMo STT input compatibility — The speech-to-text adapter now targets MiMo V2.5 models and rejects non-WAV audio payloads (#9118). This is a behavioral tightening: integrations must convert audio to WAV before calling the adapter rather than assuming compressed formats are accepted.

4.26.5 - 2026-07-07

Added

  • Added support for setting a custom bot ID while creating a platform by scanning a QR code. (#9067)
  • Added ChatUI project workspaces. (#9066)
  • Added improved ChatUI attachment display. (#9134)
  • Added malformed tool-call name sanitation in ToolLoopAgentRunner. (#9144)
  • Added model metadata in selectors and a chat token usage indicator. (#9161)
  • Added event-loop diagnostics and expanded diagnostics documentation. (#9168)
  • Added documentation for cross-platform compatibility and Python version support.
  • Added test coverage for POSIX file URI root preservation. (#8906)

Changed

  • Log event-loop watchdog startup at the info level.
  • Keep model metadata separate from providers. (#9161)
  • Polish snackbar styling in the WebUI. (#9173)

Fixed

  • Enabled only synced ModelScope MCP servers. (#9084)
  • Improved MCP client startup and shutdown handling to avoid idle spinning and clean up on errors, timeouts, and cancellation. (#9070)
  • Replaced fragile knowledge-base duplicate-name error matching with a pre-check. (#9121)
  • Improved knowledge-base retrieval resilience on per-knowledge-base failures and rerank selection. (#9122)
  • Cleaned up KBMedia records on document deletion and fixed knowledge-base stats updates. (#9120)
  • Aligned the knowledge-base CRUD API contract with kb_name, canonical payload fields, and OpenAPI types. (#9000)
  • Constrained custom workspace paths and preserved absolute custom workspace paths.
  • Improved web search API key failover.
  • Enforced ownership when reading ChatUI sessions. (#9141)
  • Secured project update temporary staging. (#9083)
  • Improved QQ Official retry behavior when websocket send returns None. (#8977)
  • Preserved QQ Official quoted message context. (#9164)
  • Removed QQ Official reply IDs on proactive fallback so oversized passive replies can succeed via proactive sending. (#9169)
  • Adapted MiMo STT to V2.5 models and rejected non-WAV audio payloads. (#9118)
  • Serialized webchat history timestamps as UTC-aware ISO strings. (#9159)
  • Synced plugin activation status on enable in the WebUI. (#9156)
  • Exited MCP anyio contexts in the lifecycle task on disable. (#9132)
  • Fixed leaked SSE exit stack handling that could cause MCP epoll busy-wait. (#8307)
