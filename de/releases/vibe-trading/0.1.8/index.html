Vibe-Trading v0.1.8

🧬 v0.1.8 – Alpha Zoo v1 + Politur des Forschungsworkflows

v0.1.8 ist eine wichtige Inhaltsveröffentlichung für Vibe-Trading. Die Überschrift ist der Alpha-Zoo: 452 vorgefertigte quantitative Alphas in vier gebündelten Bibliotheken – qlib158, alpha101, gtja191 und academic – mit einem einzeiligen CLI zum Benchmarking jedes Zoos in Ihrem Universum, Agentenintegration über zwei neue Tools, vier neue REST-Routen mit SSE-Streaming-Fortschritt und einer Web-Benutzeroberfläche zum Durchsuchen/Detaillieren/Benchmarken unter /alpha-zoo. Die Veröffentlichung bringt außerdem die langjährige MCP client-Integration, eine Trust-Layer-Run-Karte in der Web-Benutzeroberfläche, den öffentlichen Wiki-Start unter vibetrading.wiki, das Hypothesis Registry MVP und einen umfassenden Sicherheits- und Härtungsdurchgang, der von Community-PRs vorangetrieben wird. Diese Version ist auf den Versionen PyPI, ClawHub und GitHub verfügbar.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🧬 Alpha Zoo – 452 vorgefertigte Quant Alphas in 4 Zoos

Querschnittsformel-Alphas mit Metadaten, auf der Operatorebene durch Lookahead gesperrt, registrierungsvalidiert und über CLI, Agent, REST API und Web-Benutzeroberfläche erreichbar:

  • qlib158 – 154 Alphas. Apache-2.0-Port des Alpha158-Feature-Handlers von Microsoft Qlib, wobei der Upstream-Commit-SHA im Header jedes angepassten Moduls angeheftet und der Upstream-HINWEIS gebündelt ist.
  • alpha101 – 101 Alphas. Umsetzung von Kakushadze (2015) „101 Formulaic Alphas“ (arXiv:1601.00991), geschrieben aus dem Papieranhang. 19 branchenneutrale Alphas markieren requires_sector=True und überspringen sauber Universen ohne Sektor-Tags.
  • gtja191 – 191 Alphas. Umsetzung des Forschungsberichts „191 Short-period Trading Alpha Factors“* von Guotai Junan Securities aus dem Jahr 2014. Operator-Mapping-Entscheidungen (SMA-/WMA-/REGBETA-/HIGHDAY-Interpretationen) per Alpha dokumentiert.
  • akademisch – 6 Faktoren. Fama-French 5 + Carhart-Momentum, geliefert als ehrliche preisbasierte Proxys (die kanonische FF-Serie benötigt Book-to-Market-/Rentabilitäts-/Investitionswachstums-Grundlagen, die wir nicht bündeln). Die Spitznamen tragen das Präfix [PRICE PROXY]; Für Benutzer, die die kanonischen monatlichen Renditen benötigen, wird auf die Datenbibliothek von Kenneth French verwiesen. Jedes Alpha trägt ein __alpha_meta__-Diktat (Formel LaTeX, Thema, Universum, Spalten_erforderlich, Aufwärmen, Abklinghorizont, Notizen), validiert durch ein pydantisches extra="forbid"-Schema.

🖥️ Einzeiliges CLI

vibe-trading alpha list --zoo gtja191 --theme momentum --limit 10
vibe-trading alpha show gtja191_171
vibe-trading alpha bench --zoo gtja191 --universe csi300 --period 2018-2025 --top 20
vibe-trading alpha compare --all
vibe-trading alpha export-manifest --out wiki/alpha-library/manifest.json

bench steuert einen Rich-Fortschrittsbalken mit Live-Alpha-ID + ETA-Banner, gibt bei Fehlern die richtigen Exit-Codes zurück und unterdrückt scharfsinniges ConstantInputWarning-Geräusch. Alle fünf Unterbefehle berücksichtigen TTY-Hinweise und einen --json-Modus für die Skripterstellung.

🌐 Web-UI bei /alpha-zoo + 4 REST-Routen mit SSE

Drei Ansichten in der React-Web-Benutzeroberfläche: Durchsuchen (4 Zookarten, Filterleiste, paginierte Tabelle), Detail (Formel, Metadaten, Quellcode), Bench (Formular → SSE-gestreamter Fortschritt → Alive/Reversed/Dead-Statistikkarten + Top-5-nach-IR + Tabellen mit den meisten Umkehrungen + Balkendiagramm nach Thema). Auto-Vite-Route bei /alpha-zoo, Navigationseintrag im Layout.

GET  /alpha/list?zoo=&theme=&universe=&limit=
GET  /alpha/{alpha_id}
POST /alpha/bench               (body: {zoo, universe, period, top}) → 202 + job_id
GET  /alpha/bench/{job_id}/stream   (SSE: progress / result / done / error)

Hintergrund-Bench-Jobs werden über asyncio.to_thread mit einem Semaphor für zwei gleichzeitige Jobs (429 bei Sättigung), einem In-Memory-Status mit 1-stündiger TTL, 15-sekündigen Heartbeat-Kommentarframes ausgeführt, um zu verhindern, dass Proxys inaktive Streams schließen, und bereinigten Fehlermeldungen, damit unerwartete Ausnahmen keine serverseitigen Pfade preisgeben.

🤖 Agentenintegration

Zwei neue automatisch erkannte Tools (AlphaZooTool, AlphaBenchTool) sowie eine ZooSignalEngine.from_zoo(...)-Fabrik im Panel-Stil im Multi-Faktor-Skill, die ein oder mehrere Alphas zu einem Long-Short-Signal zusammensetzt, das mit den vorhandenen Backtest-Engines kompatibel ist. Das veraltete Symbol example_signal_engine.py bleibt aus Gründen der Abwärtskompatibilität erhalten.

🛡️ Sicherheitsboden

Qualitätstore, die bei jedem PR- und vibe-trading alpha bench-Lauf ausgelöst werden:

  • AST-Reinheitstor (test_alpha_purity.py) – scannt jedes zoo/**/*.py-Modul und erlaubt nur Importe von pandas, numpy, scipy.*, src.factors.base, __future__, typing, math, dataclasses; Verbote os / sys / subprocess / socket / urllib / requests / httpx / pathlib / Path / open / eval / exec / compile / __import__ plus breakpoint / input / globals / locals / vars / __class__ / __subclasses__ / __mro__ / __globals__ / __builtins__, plus Dunder-String-getattr-Zugriff (einschließlich BinOp-verketteter Dunder).
  • Lookahead-Sentinel-Test (test_lookahead.py) – 300-reihige synthetische Platte; beschädigte Zeilen hinter der Sonde; Behauptungsfaktor an der Sonde bleibt innerhalb von 1e-9 unverändert.
  • pytest-socket-Integration – Faktoren-Testsuite läuft netzwerkbehindert.
  • CI-Grep-Gates (tools/ci_grep_gates.sh) – lehnt yaml.load( ohne safe_load, die Zeichenfolge mit markenrechtlich geschütztem Namen in gelieferten Artefakten und alle Datenlecks pro Aktiencode in wiki/**/*.{json,csv,html} ab.

📡 MCP client-Integration (stdio v1)

Der Agent kann jetzt Tools von externen MCP-Servern über ~/.vibe-trading/agent.json laden und sich pro Sitzung über ALLOW_SESSION_MCP_SERVERS=1 anmelden. Stdio-Transport nur in Version 1; HTTP/SSE zurückgestellt. Kollisionen zwischen Werkzeugnamen erhalten ein deterministisches Hash-Suffix. Remote-Tool-Fehler führen zu Fehlern in der Nutzlast, anstatt zu sprudeln. Großes Dankeschön an @shadowinlife (#83) für die End-to-End-Implementierung und die sicherheitsbewussten Standardeinstellungen.

🪪 Trust Layer-Ausführungskarte in der Web-Benutzeroberfläche

Die Ausführungsdetailseite rendert jetzt run_card.json zusammen mit Metriken und Artefakten und vervollständigt damit die UI-Hälfte der trust-Ebenenarbeit, die zuvor gelandet war.

🧠 Hypothesenregister (Backend-MVP)

create_hypothesis / update_hypothesis / link_backtest / search_hypotheses geben Forschungshypothesen einen dauerhaften Lebenszyklus, Links zu Laufkarten und Ungültigkeitsnotizen. UI-Integration folgt.

Vorbehalte / Bekannte Einschränkungen

  • Das btc-usdt-Universum besteht aus einem einzigen Vermögenswert. Querschnitts-IC benötigt ≥2 Instrumente, daher gibt alpha101_btc konstruktionsbedingt lebendig/umgekehrt/tot = 0/0/0 zurück. Für 0.2 ist ein kuratierter crypto-majors-Multisymbolkorb geplant.
  • Das SP500-Universum verwendet die heutige Konstituentenliste als Proxy für die Indexzugehörigkeit zu einem bestimmten Zeitpunkt, was zu einem Survivorship-Bias führt. Dokumentiert in bench_summary.json["meta"] und im Wiki-Blog-Vorbehaltsbereich. Die Zeitpunktbestandteilquelle ist ein 0.2-Follow-up.
  • Der MCP-Server stellt die Tools alpha_zoo/alpha_bench noch nicht bereit. Die Agentenebene Python, REST API, CLI und die Web-Benutzeroberfläche stellen sie alle bereit; MCP-Zusammenfassung für 0.1.9 geplant.
  • 19 branchenneutrale Alpha101-Alphas (Nr. 48, 56, 58, 59, 63, 67, 69, 70, 76, 79, 80, 82, 87, 89, 90, 91, 93, 97, 100) benötigen ein Sektor-Tag. Tushare bietet dies; Bei yfinance ist dies nicht der Fall, daher überspringen SP500-Banken diese 19. Bei der branchenübergreifenden SP500-Nachfolge wird eine Sektordatenquelle angeschlossen.
  • docs/ wird ignoriert, nur interne Planung. Inhalte von docs/ nicht an öffentliche Zweige weiterleiten.

Vibe-Trading v0.1.8

🧬 v0.1.8 — Alpha Zoo v1 + research workflow polish

v0.1.8 is a major content release for Vibe-Trading. The headline is the Alpha Zoo: 452 pre-built quantitative alphas across four bundled libraries — qlib158, alpha101, gtja191, and academic — with a one-line CLI to bench any zoo on your universe, agent integration via two new tools, four new REST routes with SSE-streamed progress, and a browse/detail/bench Web UI at /alpha-zoo. The release also lands the long-running MCP client integration, a Trust Layer run card in the Web UI, the public wiki launch at vibetrading.wiki, the Hypothesis Registry MVP, and a substantial security + hardening pass driven by community PRs.

This release is available on PyPI, ClawHub, and GitHub Releases.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🧬 Alpha Zoo — 452 pre-built quant alphas across 4 zoos

Cross-sectional formulaic alphas with metadata, lookahead-banned at the operator layer, registry-validated, and reachable from CLI, agent, REST API, and Web UI:

  • qlib158 — 154 alphas. Apache-2.0 port of Microsoft Qlib's Alpha158 feature handler, with the upstream commit SHA pinned in every adapted module's header and the upstream NOTICE bundled.
  • alpha101 — 101 alphas. Implementation of Kakushadze (2015) "101 Formulaic Alphas" (arXiv:1601.00991), written from the paper appendix. 19 industry-neutral alphas flag requires_sector=True and skip cleanly on universes without sector tags.
  • gtja191 — 191 alphas. Implementation of Guotai Junan Securities' 2014 "191 Short-period Trading Alpha Factors" research report. Operator-mapping decisions (SMA / WMA / REGBETA / HIGHDAY interpretations) documented per alpha.
  • academic — 6 factors. Fama-French 5 + Carhart momentum, shipped as honest price-based proxies (the canonical FF series need book-to-market / profitability / investment growth fundamentals we don't bundle). The nicknames carry a [PRICE PROXY] prefix; Kenneth French's data library is referenced for users who need the canonical monthly returns.

Each alpha carries a __alpha_meta__ dict (formula LaTeX, theme, universe, columns_required, warmup, decay horizon, notes) validated by a pydantic extra="forbid" schema.

🖥️ One-line CLI

vibe-trading alpha list --zoo gtja191 --theme momentum --limit 10
vibe-trading alpha show gtja191_171
vibe-trading alpha bench --zoo gtja191 --universe csi300 --period 2018-2025 --top 20
vibe-trading alpha compare --all
vibe-trading alpha export-manifest --out wiki/alpha-library/manifest.json

bench drives a Rich progress bar with live alpha-id + ETA banner, returns proper exit codes on failure, and silences scipy ConstantInputWarning noise. All five subcommands honour TTY hints and a --json mode for scripting.

🌐 Web UI at /alpha-zoo + 4 REST routes with SSE

Three views in the React Web UI: Browse (4 zoo cards, filter bar, paginated table), Detail (formula, metadata, source code), Bench (form → SSE-streamed progress → Alive/Reversed/Dead stat cards + Top-5-by-IR + Most-Reversed tables + by-theme bar chart). Auto-Vite route at /alpha-zoo, nav entry in the Layout.

GET  /alpha/list?zoo=&theme=&universe=&limit=
GET  /alpha/{alpha_id}
POST /alpha/bench               (body: {zoo, universe, period, top}) → 202 + job_id
GET  /alpha/bench/{job_id}/stream   (SSE: progress / result / done / error)

Background bench jobs run via asyncio.to_thread with a 2-concurrent-job semaphore (429 on saturation), in-memory state with 1-hour TTL, 15-second heartbeat comment frames to keep proxies from closing idle streams, and sanitised error messages so unexpected exceptions don't leak server-side paths.

🤖 Agent integration

Two new auto-discovered tools (AlphaZooTool, AlphaBenchTool) plus a panel-style ZooSignalEngine.from_zoo(...) factory in the multi-factor skill that composes one or more alphas into a long-short signal compatible with the existing backtest engines. The legacy per-symbol example_signal_engine.py is preserved for backward compatibility.

🛡️ Safety floor

Quality gates that fire on every PR and vibe-trading alpha bench run:

  • AST purity gate (test_alpha_purity.py) — scans every zoo/**/*.py module, allows only pandas, numpy, scipy.*, src.factors.base, __future__, typing, math, dataclasses imports; bans os / sys / subprocess / socket / urllib / requests / httpx / pathlib / Path / open / eval / exec / compile / __import__ plus breakpoint / input / globals / locals / vars / __class__ / __subclasses__ / __mro__ / __globals__ / __builtins__, plus dunder-string getattr access (including BinOp-concatenated dunders).
  • Lookahead sentinel test (test_lookahead.py) — 300-row synthetic panel; corrupt rows past the probe; assert factor at probe unchanged within 1e-9.
  • pytest-socket integration — factors test suite runs network-disabled.
  • CI grep gates (tools/ci_grep_gates.sh) — rejects yaml.load( without safe_load, the trademarked-name string in shipped artifacts, and any per-stock-code data leak in wiki/**/*.{json,csv,html}.

📡 MCP client integration (stdio v1)

The agent can now load tools from external MCP servers via ~/.vibe-trading/agent.json, opt-in per session via ALLOW_SESSION_MCP_SERVERS=1. Stdio transport only in v1; HTTP/SSE deferred. Tool-name collisions get a deterministic hash suffix; remote-tool failures normalise to error payloads instead of bubbling. Big thank-you to @shadowinlife (#83) for the end-to-end implementation and the security-conscious defaults.

🪪 Trust Layer run card in Web UI

The run detail page now renders run_card.json alongside metrics and artifacts, completing the UI half of the trust-layer work that landed earlier.

🧠 Hypothesis Registry (backend MVP)

create_hypothesis / update_hypothesis / link_backtest / search_hypotheses give research hypotheses a durable lifecycle, links to run cards, and invalidation notes. UI integration to follow.

🔬 Memory, swarm, and tooling hardening

A focused PR cycle from @Teerapat-Vatpitak strengthened the lower-level surfaces this release leans on:

  • PersistentMemory.add() hardened against length overflow, empty / whitespace-only names, and C0/C1 control bytes (#112)
  • Swarm error surfacing + output contract, Windows-safe store, path redaction (#119)
  • MCP unresolved-symbol, finite options validation, row cap (#120)
  • Bounded CCXT + OKX fetch with timeout / retry / budget (#121)
  • read_url Jina dependency disclosure + cache opt-out (#122)
  • API path-ID validation for run/session routes (#80, via @SJoon99)

Plus @hp083625 taught memory recall to treat underscores as token boundaries (#87) so mcp_wiring_test matches "mcp wiring", @voidborne-d kept the Vite dev proxy honoring VITE_API_URL and fixed CJK slug preservation (#82, #95), and @ykykj added the CLI startup preflight (#96).

🌐 Public wiki at vibetrading.wiki

The wiki ships its own Alpha Library renderer (wiki/scripts/build_alpha_library.py) that reads the manifest JSON and emits 452 per-alpha pages + 4 per-zoo overview pages, each with script-src 'none' CSP. The research-lab gains its first long-form post: "Which of the 191 GTJA alphas still work in 2026?" — aggregate IC, theme survival rates, and the top alphas that survive eight years of out-of-sample data on CSI 300 (2018-2025), with a survivorship-bias caveat.

Caveats / Known limitations

  • btc-usdt universe is single-asset. Cross-sectional IC needs ≥2 instruments, so alpha101_btc returns alive/reversed/dead = 0/0/0 by construction. A curated crypto-majors multi-symbol basket is planned for 0.2.
  • SP500 universe uses today's constituent list as a proxy for point-in-time index membership, introducing survivorship bias. Documented in bench_summary.json["meta"] and in the wiki blog caveat section. Point-in-time constituent source is a 0.2 follow-up.
  • MCP server does not yet expose alpha_zoo / alpha_bench tools. The Python agent layer, REST API, CLI, and Web UI all expose them; MCP wrap-up planned for 0.1.9.
  • 19 industry-neutral alpha101 alphas (#48, 56, 58, 59, 63, 67, 69, 70, 76, 79, 80, 82, 87, 89, 90, 91, 93, 97, 100) need a sector tag. Tushare provides this; yfinance does not, so SP500 benches skip these 19. Cross-zoo SP500 follow-up will plug a sector data source.
  • docs/ is gitignored, internal planning only. Do not push contents of docs/ to public branches.
