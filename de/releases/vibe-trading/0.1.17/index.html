Vibe-Trading v0.1.17

Highlights

  • Daily paper trading that cannot reach a broker (#1939) — The headline is a real sandbox: paper_trade_step (agent + MCP), vibe-trading paper step, POST /api/paper-trade/step, and saved accounts via the vibe-trading paper CLI, REST /api/paper-accounts, and a Web page — matching orders or a strategy file against completed daily bars for cn_a, hk and us. Design clients around two constraints: accounts move forward only, and an advance carries the revision it read, so a stale or concurrent advance is refused (HTTP 409) and a failed step leaves the ledger unchanged. Strategy code runs in a child process that sees only bars strictly before the execution day — that is your lookahead guarantee — but fills are daily-close and all-or-none with simplified fees, board lots and A-share T+1, corporate actions and cash dividends are unmodelled, and NAV is not total return. Price caliber is enforced hard: adjusted, unknown or non-finite prices are rejected and split-like jumps return PAPER_DATA_NOT_READY instead of rescaling holdings, so expect data-pipeline work before a backtest-to-paper handoff.

  • Undefined values now say null, not 0 — The widest behavioral change in this cycle is also the quietest: a profit factor with no losing trade, an undefined correlation, a factor benchmark with too few IC observations, upside at a zero price and an unbounded ratio now return null or a refusal rather than a plausible-looking number, and a missing price no longer bridges a return pair, a VaR transition or a lag pair. That is the right correctness default, but it is a downstream contract change — dashboards, alert thresholds and NOT NULL columns that assumed a float must handle nulls or rows will silently disappear. Upgrade for two related fixes too: an after-close SEC filing can no longer reach the IC a bar early, and misspelled backtest settings are surfaced in the run card instead of being silently ignored, so runs that previously "passed" may now report errors.

  • Runtime control changes: budgeted model decisions and hardened custom endpoints (closes #1854, #1264) — Safety checks still run every minute, but model decisions now default to every 15 minutes in a fresh conversation, capped at 26 decisions and 1,000,000 reported tokens per broker per UTC day; configure once-daily timing, timezone and an operator-set USD ceiling via Runtime → Model schedule, the chat runner panel, vibe-trading connector runner-settings or GET/PUT /live/runner/settings, with spending history surviving restarts. Limits are checked only after a provider responds, so a single response can overshoot, and exhaustion or missing usage trips the existing kill switch with its cancel/flatten behavior; treat estimates as guardrails, not billing truth. The new custom OpenAI-compatible provider manager (vibe-trading provider custom list|add|activate) saves a profile only after a live test completion, keeps keys in the OS credential vault ([keyring]), and refuses credential-bearing URLs and any host that is or resolves to loopback, private, link-local, reserved or 100.64.0.0/10 — so a localhost model cannot be registered and host re-resolution is not rechecked after save. Active profiles are immutable (save a changed endpoint under a new ID), LANGCHAIN_MAX_TOKENS now caps adapter output, and the PR's per-channel config API did not merge.

  • Adaptation is evidence-bound, and research can stay on one snapshot — adapt_strategy (agent/MCP), vibe-trading strategy-evidence adapt and POST /api/strategy-adaptations can clone a registered strategy to a new name, universe, window and sizing only from adequate, non-stale evidence; the SDM keeps the parent's signal/entry/exit definitions, never its metrics, and refreshes are scoped (--scope strategies, POST /api/strategy-adaptations/evidence). Adapted runs are refused unless config, code, metrics, equity and trades match hashes sealed in the run card — good provenance, but note the hash binds evidence to a persisted run, not a guarantee that generated code implements its description. Pair this with #1769: portfolio_summary now returns and accepts snapshot_id/read_identity (also portfolio show --snapshot-id and GET /api/portfolio/analysis-context?snapshot_id=), so multi-step analysis keeps reading one stored observation after a refresh; snapshots with an older valuation version or a now-disabled source are reported unavailable rather than silently replaced.

  • Scheduled jobs are editable in place, and reports become real PDFs (#1649, #1680, #1709) — PATCH /scheduled-runs/{id} and the Scheduled page change prompt, cadence, timezone, end date and destination without deleting the job, so its id and history survive; running jobs or in-flight sends refuse edits with 409, and a destination change clears the delivery receipt but keeps the session link. Email delivery gains plain text, sanitized HTML (mistune + nh3) and a PDF attachment, with a failed render failing the send and missing consent or SMTP host failing visibly instead of logging and skipping. A private pdf_password on the Email channel plus --protect-pdf yields AES-256-encrypted attachments via pypdf; the password never enters job configs and never appears in errors, and protected jobs without it are refused. Separately, write_file on a .pdf path now renders a paginated PDF via bundled ReportLab with an OFL Noto Sans CJK subset, replacing Markdown text in a .pdf-named file.

  • Breaking changes — None.

The headline is daily paper trading. A paper_trade_step tool for the agent and MCP, and saved paper accounts through vibe-trading paper, /api/paper-accounts and a Web page, match orders or a strategy against completed daily bars without ever reaching a broker; saved accounts move forward only. Most of the rest of the cycle is correctness, and much of it has one shape: a value that cannot be computed now says so instead of turning into a plausible number. A profit factor with no losing trade, an undefined correlation, a factor benchmark with too few IC observations, an upside at a zero price and an unbounded ratio come back as null or a refusal rather than 0; a missing price no longer bridges a return pair, a VaR transition or a lag pair; an after-close SEC filing no longer reaches the IC a bar early; and a misspelled backtest setting is reported in the run card instead of silently ignored. Brazil (B3) joins as a market, the Alpha Zoo grows from 462 to 478 factors, Slack and Discord join the guided channel setup, scheduled reports can arrive by Email as HTML or a password-protectable PDF, token usage shows in Run Detail, chat and swarm, a claude-cli provider runs the agent on a local Claude Code login, and the Web UI adds Persian and Turkish for 11 languages.

Added

  • Daily paper trading with saved accounts (#1939, thanks @shadowinlife). A new paper_trade_step agent and MCP tool matches explicit orders, or the per-day orders of a strategy file, against completed daily bars for cn_a, hk and us; nothing in it can reach a broker order path. The same stateless step is served as vibe-trading paper step and POST /api/paper-trade/step. Saved paper accounts are built on it and reachable three ways: vibe-trading paper create|list|show|history|advance, authenticated REST under /api/paper-accounts (list, create, read, history, POST .../{id}/advance) and a Paper trading page in the Web sidebar in all eleven UI languages. An account starts from the cash and positions you enter, today or at the next session, and moves forward only: an advance settles sessions whose regular close is at least 30 minutes past and carries the revision it read, so a stale or concurrent request is refused (HTTP 409 over REST) instead of committing twice, and a failed step leaves the ledger unchanged. Ledgers live in <runtime_root>/paper-trading/accounts.db; there is no background scheduler. A strategy under <runtime_root>/strategies/ runs in a child process that sees only bars strictly before the execution day and the ledger after earlier fills; orders fill at that day's close, and any strategy failure discards the whole call. Matching is daily-close and all-or-none, with simplified fees, price limits, board lots and A-share T+1. Execution prices must be raw: adjusted or unknown price calibers and non-finite prices are rejected, A-shares need a complete ClickHouse trading calendar, and a split-like jump returns PAPER_DATA_NOT_READY rather than rescaling holdings. Corporate-action reconciliation and cash dividends are not modelled and NAV is not total return; intraday, margin, options and cross-market phases remain open under #1938.

  • Live runner model calls have their own cadence and daily budget (closes #1854). Safety checks still run every minute, but a model decision now defaults to every 15 minutes, each in a fresh conversation, with at most 26 decisions and 1,000,000 reported tokens per broker per UTC day; an optional once-daily time, timezone and operator-priced USD limit are set in Runtime → Model schedule and spending limits, the chat runner panel, vibe-trading connector runner-settings or GET/PUT /live/runner/settings. Spending history survives restarts. Limits are checked after each provider response, so one response can overshoot; estimates ignore cache discounts and auxiliary calls and are not a provider billing cap. Exhaustion or missing usage trips the existing kill switch and its cancel/flatten behaviour, and a decision left unfinished by a crash is blocked for inspection.

  • Strategy adaptation runs from preparation to evidence. A registered strategy with adequate, non-stale evidence can be adapted to a new name, universe, date window and position sizing through adapt_strategy (agent and MCP), vibe-trading strategy-evidence adapt, authenticated POST /api/strategy-adaptations and a Web welcome prompt. The SDM child keeps the parent's signal, entry and exit definitions and gets its own run directory, SignalEngine and backtest; it never inherits parent metrics. Refreshing with scope=strategies (strategy-evidence refresh --scope strategies, or POST /api/strategy-adaptations/evidence) replaces only the named strategies' evidence, and refuses an adapted run unless its config, code, metrics, equity and trades match the hashes sealed in its run card. The hash binds evidence to the persisted run; it does not certify that the generated code implements its description.

  • extraETF holdings exports feed the portfolio, with allocation proposals. vibe-trading portfolio import-extraetf, POST /api/portfolio/imports/extraetf and Portfolio → Manage accounts → Import extraETF Investments store an Investments CSV as a local source. The whole import fails on an unreadable row, a holdings count that differs from the one you confirm, a missing price, a future file time or an export older than the freshness limit you choose; transactions, dividend and X-Ray exports are refused. Portfolio ID keeps accounts apart when they hold the same ISIN. Totals are exported quantity × price and exclude cash and assets absent from the export. EUR joins USD, CNY and HKD as a display currency, valued at Frankfurter reference rates whose date is shown apart from the fetch time. An allocation proposal (portfolio rebalance --snapshot-id, POST /api/portfolio/rebalance, portfolio_summary(snapshot_id=..., target_weights=...), or the Web page) shows value changes for target percentages that total 100%; it creates no orders, quantities, tax or fee estimates, and an incomplete snapshot or stale cached rates cannot produce one. Imported holdings stay out of historical risk tools until their trading venue is resolved.

  • Portfolio research can stay on one snapshot (#1769, thanks @zeus229). portfolio_summary returns snapshot_id and read_identity and accepts a snapshot_id back, so a multi-step analysis keeps reading the same stored observation after a later refresh. vibe-trading portfolio show --snapshot-id ID and GET /api/portfolio/analysis-context?snapshot_id= read the same way, and the Web Portfolio page exports the sanitized research snapshot it displays as JSON. An unknown snapshot, one valued under an older valuation version, or one containing a source that is no longer enabled is reported as unavailable and never replaced by newer data.

  • mStock (India) read-only connector (#1675, thanks @Jackzigen). The mstock-live-rest-readonly profile sends only GET requests for the Type B holdings, net-position and fund-summary resources, with the API key and current session token kept in the connection's OS credential vault; it never logs in, refreshes a session or calls an order endpoint, and both order entry points refuse before any network call. Holdings and net positions stay separate books. Fund limits are shown raw because they are not cash or net liquidation, so the profile withholds account.read and is not a portfolio source. connector account and connector positions gain --connection-id. Tests replay the documented reply shapes; no real mStock account was available.

  • Five example options strategies and a candidate study (#1774, thanks @mdb1230). The options-strategy skill ships covered call, cash-secured put, iron condor, volatility-gated short strangle and protective put OptionsSignalEngines, and agent/scripts/options_candidates_backtest.py picks one parameter per strategy on 2016–2020 SPY/QQQ, then reports 2021 onward on SPY, QQQ, AAPL and MSFT with those parameters fixed. This is research code for choosing what to paper-trade; no engine changed and no order path exists.

  • Custom OpenAI-compatible model endpoints (#1264, thanks @Emad211). Settings gains a custom-provider manager and the CLI gains vibe-trading provider custom list|add|activate. A profile is saved only after a test chat completion with the same URL, model and key succeeded in the last five minutes; the key goes to the OS credential vault (the [keyring] extra), never to the profile JSON or argv, and activation needs an explicit confirmation. An active profile cannot be edited: save the changed endpoint under a new id. Base URLs carrying credentials, and hosts that are or resolve to any non-public address (loopback, private, link-local, reserved, or the shared 100.64.0.0/10 range that holds Alibaba Cloud's metadata service), are refused, so a model served on localhost cannot be registered this way. The host is checked when the profile is tested and saved; a name that later re-resolves to a private address is not re-checked. The test is a real request and may be billed. LANGCHAIN_MAX_TOKENS, when set, now caps output tokens on the OpenAI-compatible adapter. The PR's per-channel configuration API was not merged; channel settings stay where 0.1.16 put them.

  • Persian and Turkish join the Web UI, which now has 11 languages (#1264, #1616, thanks @Emad211 and @bygordon130-hub). Persian (fa, right-to-left) and Turkish (tr) are registered in SUPPORTED_LANGUAGES and the language switcher, and all 11 locale files carry the same keys. The Turkish file arrived with English placeholders and UTF-8 decoded as Windows-1252; both were replaced before release, and a test now rejects copied-English Turkish strings and that mojibake in tr and fa. The custom-provider strings, first merged in English in every locale, are translated in all 11. Chat messages, the composer and error lines take their direction from their own text, so a Persian or Arabic message reads right-to-left inside an English UI and the reverse. Some strings are still English in some locales.

  • Pixel Office, a shared manual research-task board (#1616, thanks @bygordon130-hub). The /pixel-office page, the vibe-trading office CLI, authenticated GET /api/pixel-office and POST /api/pixel-office/actions, and the pixel_office agent tool share one transactional SQLite board (pixel-office.sqlite3 under the runtime root, mode 0600), so separate processes see the same tasks. Tasks are created, assigned to a role, completed with a required result, and roles carry Operator / Senior / Lead ranks. Assigning a task does not start an agent or place an order, ranks grant no trading permission, and a recorded result is not an execution audit. The PR proposed a JSON file plus browser state; the merge replaced it with this shared store. The unsigned Windows review installer now builds the bundled Python backend before packaging.

  • Scheduled jobs are edited in place, with channel-aware destinations (#1649, thanks @zeus229). PATCH /scheduled-runs/{id} and the Scheduled page change a job's prompt, cadence, timezone, end date and delivery without deleting it, so its id and history stay. A job that is running, or whose delivery is being sent, refuses edits with 409. Each channel adapter describes the destination it accepts (label, placeholder, input type), and Telegram suggests numeric private-chat ids already in its allow_from; a suggestion only fills the manual target field. Changing the destination clears the old delivery receipt but keeps the session link, and a timezone-only edit does not move an interval schedule's next run.

  • Scheduled Email reports as HTML or a PDF attachment (#1680, thanks @zeus229). Email delivery takes a format: plain text (the default), sanitized HTML (Markdown rendered by mistune and cleaned by nh3), or a PDF attachment with a short notice in the body. It is chosen on the Web Scheduled page, in CLI playbooks (--delivery-format) and in agent proposals, whose confirmations show it. A PDF that fails to render fails the send instead of going out as plain text. Where WeasyPrint's native libraries are missing, the PDF comes from the bundled ReportLab renderer with embedded fonts, so desktop installs get PDFs too. A scheduled send now fails visibly when the Email channel lacks consent or an SMTP host instead of being skipped with a log line. The format selector is translated in every UI locale.

  • Password-protected PDF reports (#1709, thanks @zeus229). An operator sets a private pdf_password on the Email channel; a PDF Email job can then request protection, and the attachment is encrypted with AES-256 through pypdf. Web, CLI playbooks (--protect-pdf) and agent proposals store only the yes/no choice, a job config containing pdf_password is rejected, confirmations show the choice, and creating, editing or confirming a protected job without a configured password is refused. An encryption failure never echoes the password.

  • The agent can save a report as a real PDF. Before this, write_file wrote Markdown text into a file named .pdf. A .pdf path now renders the Markdown into a paginated PDF with ReportLab, without Pango or Cairo. Text uses a bundled Noto Sans CJK subset (VibeCJK-Regular.ttf, OFL) covering Latin, Greek, Cyrillic, CJK, kana and Hangul; Arabic lines are shaped with arabic-reshaper and python-bidi (now base dependencies) in matplotlib's DejaVu Sans and wrap across pages without clipping. A character neither font covers fails the render instead of printing empty boxes, and the write is atomic, so a failed render leaves an existing file untouched. The result carries the path, the real byte count and an authenticated /api/reports/{id} link, which the reply adds even when the model leaves it out and the Web chat downloads; IM channels that accept files receive the PDF as an attachment, taken only from this attempt's staged reports, never from a path the model wrote. Staged copies live under generated_reports/ in the runtime root; if staging fails, the written file is kept and the result reports download_error. The bundled font adds about 19.9 MB to the package.

  • Shadow Account reports render a PDF without WeasyPrint (#1683, thanks @he-yufeng). When WeasyPrint is missing or fails, the report renders the same eight sections and charts through ReportLab in a simpler layout, and only then falls back to HTML-only; the payload's engine can now read reportlab. A process no longer loses the fallback after its first render on a host without a CJK font. The PR used Helvetica when no CJK font was found; the bundled font is now tried first, and a host where no embeddable font loads gets HTML-only, because an unembedded face can print blank pages.

  • Feishu joins the guided Web UI channel setup (#1572, closes #1614, thanks @shadowinlife). The Feishu panel gets field hints and a setup guide in every UI locale. Test connection is a standalone probe that requests a tenant access token from feishu.cn or larksuite.com, whichever the config's domain names, without starting the bot. stop() now closes the lark WebSocket and stops its dedicated event loop, so a hot reload no longer leaves the old connection answering messages beside the new one.

Discord requires a bot identity from users/@me; privileged intents cannot be checked over REST, so the setup guide covers them. The shared token probe, also behind DingTalk, QQ and Feishu, now reports HTTP 408 and 429 as a temporary network failure rather than rejected credentials, and a failed probe leaves saved settings unchanged. Discord's allowlists, group policy and emoji settings, and Slack's allowlist and emoji, refresh without reconnecting. #1757 and #1758 landed through #1764.

  • Token usage in Run Detail, chat and swarm (#1890, closes #1889, thanks @shadowinlife). Run Detail gains a Token usage tab built from the run's existing llm_usage, chat shows a live counter from the llm_usage stream event (replay cannot double-count), and swarm cards and the dashboard show run and per-agent totals. GET /swarm/runs/{id} now returns token totals, provider and model, and swarm workers record prompt-cache tokens and whether a count is provider-reported or estimated; an estimate is labelled as one and a missing label reads "unlabeled". A reported zero stays zero beside a nonzero count, and a missing cache field is never shown as 0. These are token counts, not cost or cross-run totals.

  • get_southbound_flow serves the Stock-Connect net flow that is still published (#1486, closes #1483, thanks @shadowinlife). The new read-only agent and MCP tool returns market-wide southbound daily net buy into Hong Kong, split into the Shanghai and Shenzhen channels, in 100M HKD. Eastmoney's datacenter report is the primary source; Eastmoney's NET_DEAL_AMT arrives in million HKD and is scaled to the envelope unit, and a rejected report is an error rather than an empty history. The keyless fallback is HKEX's official daily statistics (Buy minus Sell turnover), which serves only the latest trading day. There is deliberately no Tushare path: its southbound fields now carry the cumulative stock, not a daily flow.

  • Gildata research tools and off-exchange fund NAV (#1485, thanks @sambazhu). With GILDATA_TOKEN set, three tools wrap Gildata's natural-language endpoint: get_cn_macro_series (China macro, regional and industry series), get_cn_announcements (A-share, HK and fund announcements) and search_broker_reports. Each echoes the vendor APIs its query was routed to and returns at most 200 rows (default 50); GILDATA_SRV_TOOL_URL overrides the endpoint. get_fund_nav returns unit, accumulated and adjusted NAV for funds such as 110022.OF, and only those three NAV fields count as price evidence for grounding. The Gildata loader now also serves Hong Kong equities, stamped raw, and CN indices, each resolved only when the vendor's ref_code matches the symbol exactly. It stays at the tail of each chain so paid quota is spent last. Without a token none of this registers.

  • Run cards flag backtests that may sit inside the model's training data (#1618, closes #1613, thanks @lorenzozanee). Strategy writes record the provider and model that produced config.json and code/signal_engine.py, and the run card shows them. Set model_training_cutoff (an ISO date) in config.json: a window ending before it is marked as exposed, and an unset or invalid cutoff is reported as unknown and treated as exposed. No cutoff is inferred from the model name. vibe-trading alpha bench --strict takes --training-cutoff to start the out-of-sample segment after that date, and now returns an error instead of ok when no alpha rows qualify.

  • Loader-health reports say why a source came back empty (#1643, #1698, thanks @cgycorey). The weekly public loader-health lane attaches up to three of the loader's own warnings to an unhealthy row, so an anti-bot refusal and a broken loader no longer look identical. The report is a public artifact: each message is capped at 200 characters, URLs and credential-shaped values are redacted (including a labelled Authorization: Bearer token: VALUE), and a warning that contains a filesystem path is omitted in full. The health tests now register real loaders before stubbing one, so running a single test no longer reaches the network.

  • A free BaoStock fallback for A-share val:* panels (#1799, thanks @Jackzigen). Without a Tushare token, or when Tushare returns nothing for a field, val:pe_ttm, val:pb and val:ps_ttm come from BaoStock's daily peTTM / pbMRQ / psTTM. val:pe and val:dv_ttm have no BaoStock counterpart and stay NaN rather than being filled from another field. A BaoStock outage or login failure degrades to NaN panels, not an exception. Token holders see no change.

  • Hong Kong orders are sized on each symbol's board lot (#1813, thanks @alexwan02). A backtest config may carry hk_lot_sizes: {symbol: lot}; 00700.HK, 0700.HK and 700.hk share one entry and five-digit counters such as 80700.HK stay distinct. Any HK symbol without a configured lot is sized on 100 shares and listed under lot_assumptions in the run metrics, also when no table is given. Mixed-market runs carry each sub-engine's assumptions under market_diagnostics.

  • Brazil (B3) market data and an opt-in ZimaOS template (#1783, thanks @incorpore). A .SA symbol is market br_equity, quoted in BRL and served by yahoo → yfinance → b3_cotahist → local, with BOVA11.SA as the default benchmark. The Brazil engine applies configurable B3 fees, R$0.01 ticks and a default lot of one share (br_lot_size=100 for round lots); it does not model income tax, stock-borrow cost or settlement cash locks. python -m src.br_data sync stores official B3 COTAHIST, CVM, Banco Central and Tesouro Direto data outside the checkout, and the get_br_market_data agent tool reads it. COTAHIST bars are raw, and CVM statements are latest revisions, not point-in-time inputs. zimaos/ holds a Compose file and a fork publishing example that each need explicit setup; upstream gains no scheduled publishing job.

  • A complete pip + Telegram quick start in the README (#1954). It covers installing the Telegram extra, sender authorization with allow_from, matching the API port between serve and channels start, and recovering when vibe-trading channels is missing because the package was installed into a different environment.

  • Thirteen fundamental and valuation factors (#1787, #1788, thanks @shadowinlife). Ten read point-in-time SEC XBRL filings: accruals, book-to-market, cash-to-assets, CFO yield, earnings growth, FCF yield, leverage, operating margin, revenue growth and ROA. Growth is year over year through a 365-day as-of lag, and earnings growth divides by the absolute prior value, so a loss turning into a profit reads as growth. Three read a new val:* namespace of daily A-share valuation data (fund_pb, fund_ps_ttm, fund_dividend_yield). Those are keyed by trade date and attached only on the CSI 300 universe; a nonpositive P/B or P/S is excluded rather than ranked as cheap. XOM keeps its current SEC filer, and filings by its pre-reorganisation filer that predate the change extend its history. Basic shares never stand in for missing diluted shares, and price-times-diluted-shares ratios are valuation proxies, not reported market capitalisation.

  • Industry-neutral A-share value factors (#1802, closes #1789, thanks @shadowinlife). fund_pb_ind_neutral, fund_ps_ttm_ind_neutral and fund_dividend_yield_ind_neutral z-score each name against its Shenwan (SW2021) level-1 peers on each date instead of the whole cross-section. A CSI 300 benchmark attaches a point-in-time sector tag built from Tushare index_member_all membership dates, and only when at least 90% of names carry a label. A name with no label, or a group too small for a statistic, stays NaN; there is no fallback to a whole-market z-score. Membership is point-in-time, but the SW2021 taxonomy itself is applied retroactively, and each factor's notes say so. With #1787 and #1788 the registry holds 478 factors, 20 of them fundamental (462 and 4 in 0.1.16).

  • Factor benchmarks at a longer horizon (#1801, #1802, thanks @shadowinlife). alpha bench --horizon N (1 to 252, also on the tool and MCP wrapper) measures IC against N-bar forward returns, sampled without overlap and anchored at the end of the panel; a missing close never bridges the horizon. horizon=1 is the previous next-bar formula. Result envelopes now state their horizon, sampling and universe_excluded list. SEC-fundamental factors requested on a universe other than the S&P 500 are listed as excluded instead of failing the whole run, and alpha compare shows them as skipped with the reason. The alive/dead thresholds were calibrated on daily IC and are not re-derived for N > 1.

  • Factor benchmarks feed fund:* factors their SEC inputs. Benchmarks now load each selected factor's declared fundamental fields as point-in-time SEC panels; before, those inputs never reached the benchmark. This needs the S&P 500 universe. The S&P 500 price panel goes through the shared fallback chain and reports requested, fetched and missing instruments and the price sources used.

  • Factor neutralisation and PCA in the quant library (#1817, thanks @BHhhh-123). neutralization.neutralize_factor regresses a factor on named numeric and categorical controls (OLS or WLS) separately at every time on the panel, at any bar frequency. Controls are either all required or selected greedily on coverage, rank and sample size, and every time records what was dropped and the exposure before and after. pca_factors fits cross-sectional PCA per time. Neither function fills, pools or resamples rows, and a rank-deficient time is skipped instead of being demeaned. The caller has to supply exposures known at that time. The finishing commit rescales inputs before squaring so very large or very small units neither overflow nor change the answer, keeps covariance PCA in common units, and breaks equal-loading sign ties by input order. Reachable through quantlib_call and MCP.

  • Technical indicators can be read as of a date (#1768, thanks @zeus229). technical_indicators accepts an optional end_date (strict YYYY-MM-DD; anything else is an error) as the acquisition boundary. Every response carries read_identity: the boundary mode, requested end date, bar count, serving provenance and a SHA-256 fingerprint of the exact interval, dates, closes and volumes used, so two reads can be shown to have used the same bars.

  • A claude-cli provider that runs on the local Claude Code login (#1804, closes #1800, thanks @alexwan02). Each turn runs one claude -p --restricted --strict-mcp-config --tools "" subprocess that only picks the next step (call tools or answer); Vibe-Trading executes the tools itself, so the evidence ledger, the grounding gate and swarm delivery checks run as they do for any other provider. No API key is needed. CLAUDE_CLI_DENY_TOOL_PREFIXES (default trading_,etoro_) hides tools from the model and CLAUDE_CLI_BASH_POLICY (default python-only, or off) limits bash to python scripts and read-only listing commands; refused calls are fed back at most three times. Both are convenience filters, not a security boundary: a Python script can still do anything, and live orders stay behind the mandate gate. Settings lists the models the login can run and offers only the reasoning efforts the chosen model accepts. The grounding gate

  • Indexed and container field refs resolve, and a miss lists the refs that would work (#1633, thanks @zeus229). a.0.b and a[0].b now name the same evidence element; an unindexed field still selects none. When a call::field ref matches nothing, the correction lists exact call_id::path[i] refs, value matches first. A ref naming a container lists its numeric descendants that hold the figure's value, and a tool name shared by several calls ranks those calls by value match, most recent first. These are hints only: no hint authorizes a value, and a maintainer follow-up keeps them to the figure's own instrument and to the element an indexed ref names.

  • A ref naming no call of the session gets real refs to copy (#1638, thanks @zeus229). A scope::field ref whose scope names no call, tool or run stays rejected, now with the unknown_call_id reason and up to five exact call_id::field candidates. The system prompt tells the model to copy tool_call_id verbatim instead of inventing a short alias. A maintainer follow-up applies the same instrument and figure-kind limits a real ref has, so a candidate is never one that would be refused.

  • A correction keeps the figures that already passed (#1702, thanks @he-yufeng). The correction prompt listed only what failed, and a model facing 65 issues rewrote whole numeric sections as prose, deleting valid Risk X-Ray values and a benchmark table that had no issue. It now also lists up to 24 measured figures that checked clean and tells the model to keep them as written. A value that fails anywhere in the draft is not listed, and bare integers never are. When more than 24 issues exist, the prompt says how many are not shown and that unlisted figures are not assumed to pass.

  • Only the engine's own output grounds a backtest report (#1685, thanks @cgycorey). The active run's metrics.csv could credit an earlier run's Sharpe to the current call; that archived copy now counts only when its manifest names the full directory the call declared and the exact call id, and a model-written manifest is ignored. A metrics.csv or metrics.json the model wrote is no longer engine evidence, a date cell with an explicit year must match that year, and a resolver step that failed, was refused or came back empty no longer erases a locked or conflicting identity.

  • A derived figure's ref must name evidence that exists (#1835, #1837, thanks @zeus229). A comma- or semicolon-separated ref is resolved member by member, and an empty or unknown member fails with no_evidence instead of falling back to every value in the session. A single ref that names no call, tool, field, artifact or observed symbol is refused the same way rather than borrowing a coincidentally equal value. Unattributed multi-symbol arithmetic keeps its no_symbol diagnostic.

  • Derived notes after a label parse, and process metadata is not evidence (#1728, #1767, thanks @zeus229). A note such as scenario result: 125 / 10000 * 100 was not evaluable because only the full-width ： was a separator; the ASCII : now is too. Top-level exit_code, returncode, elapsed_seconds and duration_seconds of a code-running tool's result are no longer recorded as observed values, so a backtest's runtime cannot ground a figure.

  • Percent-named fields are read as percentage points (#1823, closes #1820, thanks @he-yufeng). A-share rows carry changepercent values that are already points, so 0.52 - 1.41 refused the correct "-0.89%" and passed "-89%". When every data operand anchors only to fields named percent, pct or ending in %, the result is read in points; an operand whose value also appears under a plain field keeps the fraction reading. A maintainer follow-up converts the operands before evaluating, so ratios and compound factors of two point values come out right.

  • Every data operand of a derived figure must be observed. Only added or subtracted terms were checked, so a numerator or denominator the session never fetched could pass. A chosen multiplier or divisor (a discount factor, a weight) now needs a count declaration and its value and label on the same visible line of the answer. Literal 1 and square or cube exponents are structural, and an explicit trailing *100 on a percent claim is read as a unit conversion without exempting any other operand.

  • Instrument identity survives matrices and ticker-keyed results (#1850, #1851, thanks @zeus229). In a square Markdown matrix with an empty top-left header (a correlation table), each row's symbol is taken from its first cell, bold removed, when the row and column symbol sets are complete, unique and equal; anything else stays unscoped. A result keyed by instrument (risk_contribution_pct.ABC.US) keeps each value's instrument and exact ref, so the same number cannot ground a claim about another instrument. List-indexed scalars such as positions[0].contribution_pct keep their indexed-ref meaning.

  • A figure that names its currency must match evidence in that currency (#1905, thanks @ThreeTima). An ISO code or an unambiguous mark (€, £, ₩, ₹, 人民币, 美元, 円) fixes the figure's currency for observed, derived and proposed checks, and SEC XBRL amounts carry their declared unit (CHF, NZD, BRL, ARS and VND included).   • Profit factor is undefined when no trade lost (#1602, thanks @davidalmeida90). profit_factor and profit_loss_ratio were 0.0 for a run whose trades all won, which ranked it below every run with a loss. Both are now None (an empty metrics.csv cell, null in JSON) in the daily metrics and the options engine. A run with no closed trade, or only losing trades, keeps 0.0.

  • Sortino uses zero-target downside deviation over every period (#1693, #1727, thanks @MetaAviator). The denominator was the sample standard deviation of the losing returns, so equal losses looked riskless and a single loss left the ratio huge or undefined. It is now the root mean square of negative returns divided by the full return count, in the shared metrics and in the options engine.

  • The first bar's result counts against initial capital everywhere (#1750, #1818, #1844, closes #1749 and #1843, thanks @he-yufeng and @DrDLyuan). The options engine's drawdown peak and the drawdown column in artifacts/equity.csv start from initial cash, so a first-bar loss shows up and the column agrees with max_drawdown. Per-bar returns measure the first bar from initial cash too, so Sharpe and Sortino see it, the ret column compounds to total_return, and bootstrap validation uses the same series.

  • Calmar stays finite and zero-bar trades count in holding periods (#1901, #1876, thanks @Bortlesboat and @MetaAviator). Calmar falls back to 0.0 when an overflowed annual return makes it non-finite, like the other ratios; annual_return itself is unchanged. Completed same-bar trades now count in the average holding period. avg_holding_days remains the engine's bar-based measure, not calendar days.

  • Options legs are priced on the run's bar cadence (#1753, thanks @remote-controlled-man). Historical volatility was always annualised at 252 bars a year, so a crypto or hourly options run priced its legs on one cadence and reported metrics on another. Pricing now receives the run's factor. A cross-market run estimates each bar's cadence from the intervals observed up to that bar, so extending a run cannot change earlier option prices.

  • trades.csv reports the opening fill and keeps break-even exits (#1779, #1780, thanks @MetaAviator and @alexwan02). Each entry and exit row carries an event column. The entry row shows the price and size of the fill that opened the position, not the weighted cost after later scale-ins; those stay in fills.jsonl. Validation and run-artifact readers pick exits by the event column, so zero-PnL exits are no longer dropped. Unmarked older files keep the previous convention.

  • Benchmarks follow the symbol's exchange and the run's source (#1712, #1781, thanks @rudycelekli and @alexwan02). .SH, .SS, .SZ and .BJ symbols take the CSI 300 benchmark whatever the source; local, BaoStock and yfinance runs could fall through to SPY. A source that forbids network fallback, local included, fetches its benchmark through that same loader. When the declared benchmark cannot be resolved, the run card says that benchmark-relative metrics were graded against the equal-weight basket.

  • Crypto spellings get crypto rules (#1740, #1748, #1861, #1862, #1864, closes #1751 and #1863, thanks @he-yufeng, @rudycelekli and @Jackzigen). BTC/USD, ETH/USD and four other known slash-USD pairs are classified before the forex rule, in backtests, correlation and Agent/MCP data routing, while XAU/USD stays forex. Digit-leading bases (1INCH-USDT, 1000PEPE-USDT), separated USDC and BUSD quotes (BTC-USDC, ETH/USDC) and BASE-USDT-PERP perpetuals no longer fall through to A-share rules, where board-lot rounding rejected every order.   • A-share price limits cover every board's codes (#1913, thanks @rudycelekli). ChiNext 301xxx and STAR 689xxx codes get the ±20% band, and Beijing 920xxx and legacy 4xxxxx / 8xxxxx codes get ±30%; they had fallen back to ±10% and blocked legal fills. ST status and listing-day exemptions still cannot be inferred from a code.

  • Contract specs for Yahoo forex pairs and ICE softs (#1930, #1944, thanks @wavebyrd). EURUSD=X-style symbols, and .FX in any case, are normalised before the spread and swap tables are read, so they stop paying the default 2-pip spread and swap. Coffee, sugar and cotton multipliers are dollars per cent (375, 1120, 500), like the grains; they were full contract pounds, a hundred times too large.

  • Backtests warn about config keys that nothing reads (#1935, #1947, thanks @he-yufeng and @rudycelekli). Quant Library and analysis tools

  • Brinson attribution reads the book, not its liquidation (#1782, thanks @alexwan02). A run closes every position on its last bar, so the final positions.csv row is all zeros. When it is, attribution uses the row before it and the report notes that row's timestamp. It steps back only one row: a book already flat before the close is still reported as flat.

  • Attribution annualises with the run's recorded rate (#1948, thanks @rudycelekli). When the run card records annualisation.bars_per_year, attribution uses it instead of re-deriving the rate from the requested interval, which disagreed for crypto's 365-day year and any run whose served bar spacing differed from the request.

  • Attribution inputs and Carino linking (#1659, #1943, thanks @rudycelekli). brinson_fachler and carino_factor reject non-finite weights, returns and tolerances by name instead of returning NaN effects. Carino's near-coincidence branch now compares the two returns relative to the remaining wealth. Two returns close to -100% can differ by a tiny absolute amount while their wealth relatives differ severalfold, and those used to take the limit branch.

  • VaR backtests no longer join observations across a gap (#1658, thanks @rudycelekli). A pair dropped for a non-finite return or forecast still leaves the coverage counts, and now also breaks the Christoffersen independence transitions. The breaches either side of it are no longer counted as consecutive days.

  • Implied volatility meets its price tolerance (#1657, thanks @rudycelekli). The bracketing fallback passed tol, a price tolerance, to brentq as a volatility tolerance. It now solves tightly and returns NaN unless the repriced option is within tol of the market price, the same check the Newton path applies.

  • Turnover-aware optimiser and min-weight floor (#1652, #1653, #1885, thanks @rudycelekli). Turnover is measured on signed holdings: reversing a 50% long into a 50% short counts 0.5, both the close and the reopen. Allocations kept without optimisation (all cash, short history, a failed fit) now update the prior holdings the next penalty is measured against. A single-asset book is checked against its per-name and group caps and raises when the allocation exceeds them or is not finite. When a min_weight floor cannot be funded by the names above it, the date falls back to equal weights over the active names, keeping their signs and gross exposure, instead of pushing a funding name through zero.

  • Risk X-ray returns and downside deviation (#1717, #1875, thanks @rudycelekli). Returns are computed per symbol before incomplete dates are dropped, so a missing close no longer becomes a multi-bar move booked as one period. Downside deviation is the zero-target root mean square over all bars, as the backtest's Sortino computes it. The standard deviation of the losing bars alone read zero for a book that lost 1% on every losing bar.

  • Missing observations stay missing in time-series and validation helpers (#1713, #1714, #1715, thanks @rudycelekli). fit_ornstein_uhlenbeck builds lag pairs before dropping missing values, so a gap is no longer fitted as a one-step transition. purged_walk_forward_splits skips a fold whose training set purging has emptied, as its contract states. Regime edge density stays unknown on a bar where any pair's correlation is undefined (a constant or missing series) instead of counting that pair as no edge.

  • Grouped purged K-fold purges groups whose labels reach the test block (#1700, thanks @Shizoqua). group_purged_kfold_splits takes label_end_times. An earlier group whose labels resolve inside the test block is purged, as is a later group inside the test labels' horizon, and the embargo starts after the furthest test label ends. The finishing commit made the argument keyword-only, so existing positional calls keep their meaning. It also requires contiguous, chronological groups when the argument is given. Without it, only the embargo applies, as before.

  • Event-study fitting stays before the event (#1920, thanks @rudycelekli). For an event window that opens after the event, for example (1, 5), the estimation window used to end at the window's start and so took in the event day. With estimation_gap=0 it also took in the days in between. It now ends before both the event and the window, for every normal-return model.

  • Credit, stochastic-volatility and factor-model inputs (#1716, #1718, #1719, #1928, thanks @rudycelekli). cds_price keeps premium dates on the requested frequency and prices a final stub for a fractional maturity. Before, it spread the periods evenly over the tenor. portfolio_style_exposure drops an asset with any missing factor exposure and reports its weight as unmatched_weight, instead of summing NaN into a zero exposure. heston_price rejects non-finite parameters and a nonpositive integration limit before integrating. factor_risk_decomposition rejects a specific variance below -1e-8 instead of clipping it to zero idiosyncratic risk.

  • Non-finite bond and Sharpe-summary inputs are refused by name (#1824, #1821, #1822, thanks @he-yufeng and @rudycelekli). An infinite coupon frequency used to price any bullet bond near par, and an on-coupon-date shortcut in accrued_interest turned a NaN face into 0.0. ytm_solve checks its price and bracket, key_rate_duration its tenors and dv01 its par amount. probabilistic_sharpe_ratio checks all five of its inputs; a NaN benchmark used to come back as NaN "confidence". expected_maximum_sharpe refuses NaN or infinite trial counts. #1824 supersedes the narrower reports in #1821 and #1822.

  • Fund math and cash-flow ingestion refuse ambiguous inputs (#1732, #1739, #1919, thanks @he-yufeng, @Shizoqua and @rudycelekli). american_waterfall refuses a bare as_of date, which it used to ignore silently; per-deal dates are a mapping. A NaN preferred rate used to hand every profit dollar to the LP as preferred return, and the result still reconciled. Hurdle and waterfall amounts must now be finite. Cash-flow and entity-panel ingestion refuse a single dot followed by exactly three digits (12.000 is 12 in a US export and 12000 in a European one) unless decimal_separator is given. Scientific notation such as 1.2e5 is still accepted.

  • Drawdown duration and three-statement tolerance (#1784, #1786, thanks @rudycelekli and @remote-controlled-man). max_drawdown_analysis dates the peak at the latest visit to the high-water mark before the trough, so revisiting a peak starts a new underwater period. project_three_statement applies the caller's balance_tolerance inside each projected period too; a widened tolerance used to fail there at the module default.

  • Portfolio-weight and copula numerics (#1694, #1695, thanks @rudycelekli). Inverse-variance weights no longer overflow on very small positive variances. Inverse-variance weights and HRP reject a non-finite diagonal, and HRP now checks a single-asset matrix as well. A Gaussian copula fitted from a Kendall's tau that rounds to correlation ±1 is nudged back inside the open interval, and its CDF accepts the near-singular covariance.

  • quantlib_call, VPIN and options-payoff results (#1826, #1836, #1897, thanks @rudycelekli). The 5,000-value result budget is enforced while encoding. Before, a long series past the budget still emitted one <truncated> string per remaining element. Accounting parentheses, ASCII or full-width, are negative: (25.3)亿 is read as -25.3 亿 with its unit, where it used to read as +25.3 with no unit. -25M, −25M, -$25M and $-25M keep their minus sign, and (-25) is still a negative. A zero reported market cap matches only a zero product, and against a zero cross-source median only an exact zero agrees. Either way the percent deviation is null. Three-scenario upside is null at a nonpositive price, where it used to report 0% ("fairly valued"), and negative years is an error.

  • Swing-based skill signals no longer fire before the swing is known (#1873, thanks @rudycelekli). The bundled Elliott-wave and harmonic example engines stamped a signal on the swing bar itself, which is only confirmed swing_window bars later. A missing run_dir, a list of patterns, a null or non-integer window now get a JSON error or their default instead of raising out of the tool.

The extractor and the scanner share one implementation, so the RSI bounds a profile extracts are the ones the scanner tests.

  • Small-price indicators keep their digits (#1925, thanks @rudycelekli). MACD and Bollinger values were rounded to 4 and 2 decimals, so a 1.2e-5 crypto price came back as zeros.   • Renamed conversations show their new name in search (#1832, thanks @rudycelekli). The REST rename and auto-title routes now update the search index's title as well. Auto-titling reloads the session after the model answers, so updates saved meanwhile are kept, and a manual rename made meanwhile is kept with status kept.

  • Reconnecting to a session's event stream no longer repeats an event (#1798, closes #1796, thanks @Shizoqua). An event published between the replay snapshot and the new subscription reached the client twice, once in the replay and once live. Both steps now happen under one lock.

  • Memory search snippets and titles read back as written (#1682, thanks @Shizoqua). A CJK snippet could show its span twice ("使用用移移动…") because the index stores both single characters and pairs. A title mixing Chinese with a ticker, number or punctuation came back with extra spaces (比特币A策略 became 比特币 A 策略). Since 8ec3b80f, highlights and ... truncation markers also survive in snippets built only from character pairs.

  • Memory removal, links and recall (#1697, #1771, #1772, thanks @Shizoqua). remove(), which the remember tool's forget action uses, accepts a filename stem as find() already did. Before, it reported "not found" for an entry that find() and vibe-trading memory forget could see. A blank name is refused (f6e72428). Semantic links match two-character identifiers such as BP or GE; the minimum used to be three. FTS recall skips index rows whose memory file was deleted outside the process. The PR fetched four times the requested count; 54e225de replaced that with a window that doubles until enough current memories are found or the index runs out.

  • Verifying an archived audit ledger reports a corrupt line instead of crashing (#1721, thanks @Shizoqua). verify_chain_with_archives parsed every segment with a bare json.loads, so a damaged line raised JSONDecodeError. It now uses the same parser as single-file verification and returns a malformed_json break at that line's position across all segments.

Credential redaction

  • Environment-style credential names and URL credentials are redacted (#1765, thanks @cgycorey). TUSHARE_TOKEN=…, AWS_SECRET_ACCESS_KEY=… and aws_secret_access_key lines in ~/.aws/credentials are now caught. Lowercase identifiers such as pad_token and max_token are still left alone. scheme://user:password@host becomes scheme://[redacted]@host, and a password containing @ is handled. A bare username before @ is redacted only when it is a 20-plus-character token, so git@github.com stays readable.

  • Authorization: Basic and other non-bearer schemes are redacted (#1846, thanks @cgycorey). The key pattern used to redact the scheme word and leave the base64 user:password visible. Basic, Digest, Token, Negotiate and NTLM values are now redacted, but only right after an authorization label, so prose like "basic information" is untouched.

  • More secret formats are redacted (#1874, #1866, #1867, #1868, #1869, #1870, thanks @rudycelekli). #1874 combined the five smaller PRs. These are now redacted:

    • unlabelled GitHub fine-grained (github_pat_), GitLab (glpat-), npm, Hugging Face, Stripe (sk_/rk_ live and test), Google API (AIza) and AWS ASIA keys;
    • PEM and PGP private-key blocks, including a block cut off before its END line, which is redacted to the end of the text;
    • Cookie: and Set-Cookie: header values;
    • fields named like cookie or private_key in structured payloads.

    Public keys and certificates are left as they are, and running redaction twice changes nothing. Since 47de62de, a quoted header such as curl -H "Cookie: a=\"x\"; b=y" is redacted up to its closing quote.

  • Telegram bot tokens, Slack and Discord webhook URLs, Groq and NVIDIA keys are redacted (#1880, thanks @rudycelekli). The Telegram token is caught inside https://api.telegram.org/bot<token>/…, which HTTP error messages repeat in full. For a webhook URL, only the secret last path segment is replaced. The PR accepted only 8–10 digit Telegram bot ids and lowercase hooks.slack.com. 2c00cd20 widened that to any length of numeric id, to GovSlack (hooks.slack-gov.com) and to webhook hostnames in any letter case.

CLI, API and scheduling

  • vibe-trading update leaves a Git install alone (#1655, thanks @rudycelekli). An install made from a Git URL was treated as a PyPI wheel, so the update replaced the user's chosen revision with a released wheel. The command now detects vcs_info in the install metadata, reports the newer PyPI version and tells the user to update from the original source.

  • The terminal dashboard matches parallel tool results to the right call (#1859, closes #1856, thanks @Shizoqua). When several calls to the same tool ran at once, progress and results were matched by tool name and recency, so results could be swapped between calls. They are now matched by call id. Since 47de62de, a result whose id matches no step gets its own step and no longer completes a different call that is still running.

  • CLI limits and number formatting (#1886, #1926, thanks @rudycelekli). vibe-trading list --limit and memory search --limit reject zero and negative values instead of passing them on. Token counts, abbreviated numbers and durations switch unit when rounding reaches the next one: 999,950 tokens shows as 1.0M tokens instead of 1000.0k tokens, 999.6 ms as 1.0s, and 59.96 s as 1m 00s instead of 60.0s.

  • A cancelled upload leaves no partial file (#1945, thanks @rudycelekli). If the upload request was cancelled while a chunk was being read, the half-written file stayed in the uploads directory with no reference to it. The file is now deleted and the cancellation is re-raised.

  • More runtime files follow VIBE_TRADING_HOME (#1896, #1904, #1887, thanks @rudycelekli). These paths were fixed to ~/.vibe-trading and now use the runtime root:

    • persistent memory and its search index (memory/, memory_index.db);
    • autopilot run directories;
    • the alpha-bench panel cache and reports;
    • the Gildata code cache.

    The Shadow Account report route also reads from the runtime root, which is where the report writer saves. Report links therefore work again when VIBE_TRADING_HOME is set. Existing files under ~/.vibe-trading are not moved, and the memory paths are read when the process starts.

Channels and scheduled delivery

  • IM channels show agent progress again, without repeated lines (#1878, thanks @alexwan02). Channel replies now forward the attempt's status lines (working, waiting for the model, using a tool, checking the figures), tool hints and opt-in reasoning while the agent runs, so Feishu's streaming card and other streaming channels update again (reported in #1792). Only those labels go out: answer drafts and tool results stay private, and the final answer still passes grounding first. #1878 applies the channel's own visibility settings before deduplicating, so hidden tool hints no longer break the dedupe and a chat no longer stacks one "Waiting for the model" per tool round.

  • Streamed replies are no longer lost or split (#1860, #1903, #1929, closes #1857, thanks @Shizoqua). Telegram (#1860) and Matrix (#1903) dropped the whole answer when the live preview message could never be created; they now send the accumulated reply as a new message. CI installs the matrix extra so the Matrix test runs instead of skipping. WeCom (#1929) generated a new stream id for every chunk, so progress and the final answer arrived as unrelated messages; one id now covers each reply.

  • Email sender authentication cannot be satisfied by forged headers (#1508, thanks @Shizoqua). SPF and DKIM checks read only the single Authentication-Results header bearing the configured trusted_authserv_id; with none configured, or with two matching headers, verification fails closed. A pass counts only when its domain equals the From domain or an aligned dmarc=pass is in the same header, and comments or quoted text cannot pose as results. The receiving provider must strip forged copies bearing its id; the id is not a signature. The guided Email setup exposes the setting, and a blank one rejects inbound mail while SPF or DKIM checks are on. The PR described trusting the topmost header; what shipped selects by configured id instead.

  • URL credentials in channel settings are neither leaked nor erased (#1742, #1744, thanks @cgycorey). Status and config redaction strips user:password@ even when the port is malformed or out of range or the URL is followed by punctuation, where it used to return the URL untouched (#1741). Saving or testing a form that echoes the redacted URL keeps the stored credential instead of overwriting it (#1743); a different URL or a clear flag still applies. Connection-test and reset messages, including raised SDK exceptions, are scrubbed too.

  • Unchanged empty fields no longer block channel saves (#1681, thanks @zeus229). A nullable setting such as Email's post_action was submitted by the form as an empty string and rejected with a 422 on unrelated edits. An empty value now maps back to null where the adapter's default is null, for both Save and Test.

Web UI and locales

  • Run trades list every trade, newest first (#1865, #1877, #1831, thanks @alexwan02 and @he-yufeng). The Trades tab and its CSV download used the first 500 rows of trade_log, which dropped the newest trades of a long run; they now use the full trades.csv rows (#1865). Rows sort newest first with a header toggle, keeping same-time fills in engine order, and the symbol filter lists codes in order (#1877). #1831 removes a race in the Settings effort-level test that intermittently failed frontend CI; the component is unchanged.
