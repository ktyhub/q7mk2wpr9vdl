Vibe-Trading v0.1.10

🌍 v0.1.10 – Globale Datenschicht + Rollup seit 0.1.9

v0.1.10 ist eine Rollup-Version. Die Schlagzeile ist die Globale Datenschicht: Das Marktdatenregister wächst von 10 auf 18 Quellen und erhält 18 schreibgeschützte Datentools, die über OHLCV hinaus bis hin zu Grundlagen und Datenfluss reichen und alles über MCP offengelegt werden. Um ihn herum wird alles geliefert, was sich seit 0.1.9 angesammelt hat – 10 Broker-SDK-Konnektoren, der Alpha Zoo alpha compare-Full-Stack, eine Überarbeitung der Anbieterzuverlässigkeit, Forschungs-Autopilot-Phase 1, ein Opt-in-lokaler Datencache und eine von der Community gesteuerte Sicherheitsverstärkungswelle. Diese Version ist auf den Versionen PyPI, ClawHub und GitHub verfügbar.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🌍 Globale Datenschicht – 18 Quellen + 18 schreibgeschützte Datentools

Das Loader-Register wächst von 10 auf 18 Marktdatenquellen:

  • Kostenlos, kein Schlüssel – tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus vier neue Direkt-API-Zusätze: Eastmoney, Sina, Stooq und ein Direkt-HTTP Yahoo client.
  • Optionale schlüsselgesteuerte US-Anbieter – Finnhub, Alpha Vantage, Tiingo, FMP; Fehlende Schlüssel werden in der Fallback-Kette übersprungen, stürzen Sie sie niemals ab. Fallback-Ketten werden nach dem IP-Verbotsrisiko (leichter, drosselungstoleranter führender öffentlicher Endpunkte; schlüsselgesteuerte REST-Trails) hinter einem gemeinsam genutzten gedrosselten HTTP-Gate (backtest/loaders/_http.py) mit Rate-Buckets pro Host, Jitter und Sitzungswiederverwendung neu geordnet. An der Spitze stehen 18 schreibgeschützte Datentools – Fondsfluss, Dragon-Tiger-Board, Northbound-Flow (Stock-Connect), Margin-Handel, Block-Trades, Anzahl der Aktionäre, Ablauf der Sperrfrist, Sektormitgliedschaft, Forschungsberichte, Nachrichten, SEC-Einreichungen (EDGAR + HK**, alle über MCP exponiert. Drei gemeinsame clients (eastmoney / yahoo / sec_edgar) unterstützen die Lader und Werkzeuge, und ein konsolidierter data-routing-Index plus eastmoney / sec-edgar-Fähigkeiten pro Quelle dokumentieren die Ebene.

💱 10 Broker SDK-Anschlüsse – lesen + Papier, mandatgesteuert live

Beim Handel geht es um Connector-First: Wählen Sie ein Profil aus, und „Paper/Live“ ist ein Attribut des Connectors. Mit dieser Version erweitert sich die Liste auf 10 Broker – IBKR (lokales schreibgeschütztes TWS/Gateway) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (Indien NSE/BSE + F&O). Direct-SDK-Anschlüsse teilen sich einen broker_sdk-Transport und jeder kann Lese- und Papierkontobestellungen ausführen; Die Live-Platzierung passiert ein einzelnes Fail-Closed-Bounded-Autonomy-Gate (sdk_order_gate.py: Mandat + Kill-Switch + Audit). Broker mit kein Laufzeitpapier/Live-Diskriminator (Longbridge, Dhan, Shoonya) sind strukturell auf Papier + schreibgeschützt begrenzt – ihre place_order / cancel_order lehnen jegliche Nicht-Papierkonfiguration in der ersten Zeile strikt ab. Auftragserteilungstools bleiben von MCP fern (nur Agent + CLI).

📊 Alpha-Vergleich zwischen CLI / REST / Web / Agent-Tool

vibe-trading alpha compare ordnet alle Alpha-Zoo-Faktoren nach IC/IR in Ihrem Universum und teilt sich einen compare_runner.compare_alphas-Kern hinter dem CLI, eine POST /alpha/compare-REST-Route mit SSE-Streaming-Fortschritt, die Alpha Zoo-Web-UI-Vergleichsansicht und ein schreibgeschütztes alpha_compare-Agententool. Ein run_bench(only=…)-Teilmengenfilter prüft nur die verglichenen Faktoren und nicht den gesamten Zoo.

🔌 Überarbeitung der Anbieterzuverlässigkeit

Eine Fähigkeitsschicht des Anbieters steuert die Erfassung/Wiedergabe von Argumenten, Gemini-Gedankensignaturen, Kimi-Benutzeragenten und OpenRouter-Argumentationskörper pro Anbieter. vibe-trading provider doctor druckt einen redigierten Diagnose-Snapshot. Streaming-Fehler lösen jetzt ein explizites, redigiertes ProviderStreamError (mit status_code + .retryable) aus, mit einem Wiederholungsversuch für Transienten und Fail-Fast auf 4xx; Ein gedrosselter reasoning_delta SSE steuert einen „Reasoning…“-Aktivitätsindikator in der Web-Benutzeroberfläche. Außerdem: ein optionaler nativer DeepSeek-Adapter (VIBE_TRADING_DEEPSEEK_ADAPTER), Hard-Timeouts für schreibgeschützte Tools (VIBE_TRADING_TOOL_TIMEOUT_SECONDS) und Temperaturbehandlung pro Anbieter (Kimi-k2 auf 1.0 erzwungen, MiniMax auf > 0 geklemmt).

🔬 Forschungsautopilot Phase 1

run_research_autopilot wandelt einen hypothesis_id in ein Forschungsziel um (These als objektiv, Backtest-relevante Akzeptanzkriterien, Hinweise zum nächsten Schritt), und generate_backtest_config schreibt automatisch einen Backtest config.json aus dem Universum und den Datenquellen der Hypothese – sodass der Agent direkt von der Idee → signal_engine.py → Ausführung übergeht.

🗃️ Lokaler Datencache + local-Loader aktivieren

VIBE_TRADING_DATA_CACHE=1 speichert abgerechnete Bars in ~/.vibe-trading/cache (Benutzer-Home, nie das Repo) zwischen; Ein Staleness Guard speichert niemals einen Bereich, der heute endet, zwischen, und zwischengespeicherte Frames sind Byte-identisch mit Live-Abrufen. Ein neuer local-Loader liest OHLCV direkt aus Ihren eigenen CSV-/Parquet-/DuckDB-Dateien über ~/.vibe-trading/data-bridge/config.yaml, mit normaler Fallback-Chain-Unterstützung.

🛡️ Sicherheits- und Verhärtungswelle

Ein Community-gesteuerter Härtungsdurchgang: API-Einstellungen-Schreibauthentifizierung (#245), Agent-Shell-Tool-Opt-In (#243), Loopback-Host-Rebinding-Ablehnung (#242), explizite lokale Shutdown-Authentifizierung (#241) und Identifikatoreindämmung für Mandatsvorschlags-IDs (#256), persistente Speichertypen (#257) und MCP-Schwarm-Run-IDs (#258). Plus reaktionsfähiger Stop Mid-Stream + SSE-Wiederverbindung bei Rückkehr zu einer laufenden Sitzung (#229), Multi-Engine-web_search-Fallback (#231) und Gemini thoughtSignature-Roundtrip durch OpenAI-kompatible Tool-Aufrufe (#176, #184).

🪪 Die Versionsberichterstattung ist jetzt konsistent

--version, der REST API (/docs + /api), der MCP-Server-Handshake und die Web-UI-Fußzeile stammen alle aus einer Quelle – der REST API war zu einem falsch fest codierten 5.0.0 abgedriftet. Die Verpackung enthält jetzt auch Skill-Beispielskripte im Rad, und das Docker-Image installiert die nativen Bibliotheken von weasyprint, damit PDF-Berichte gerendert werden.

Installieren/Upgrade

| Kanal | Befehl | |---|---| | PyPI | pip install -U vibe-trading-ai | | UV-Werkzeug | uv tool install --reinstall vibe-trading-ai | | ClawHub (Claude Desktop / OpenClaw / MCP clients) | clawhub install vibe-trading oder aktualisieren Sie den installierten Skill | | Docker | docker compose pull && docker compose up -d | Remote-API/Web-Bereitstellungen sollten API_AUTH_KEY und explizite trusted CORS-Ursprünge festlegen. Lokale CLI- und localhost-Web-UI-Workflows bleiben reibungslos.

Vibe-Trading v0.1.10

🌍 v0.1.10 — Global data layer + roll-up since 0.1.9

v0.1.10 is a roll-up release. The headline is the Global data layer: the market-data registry grows from 10 to 18 sources and gains 18 read-only data tools that reach past OHLCV into fundamentals and flow, all exposed over MCP. Around it ships everything accumulated since 0.1.9 — 10 broker SDK connectors, the Alpha Zoo alpha compare full stack, a provider-reliability overhaul, Research Autopilot Phase 1, an opt-in local data cache, and a community-driven security-hardening wave.

This release is available on PyPI, ClawHub, and GitHub Releases.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🌍 Global data layer — 18 sources + 18 read-only data tools

The loader registry grows from 10 to 18 market-data sources:

  • Free, no key — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus four new direct-API additions: Eastmoney, Sina, Stooq, and a direct-HTTP Yahoo client.
  • Optional key-gated US providers — Finnhub, Alpha Vantage, Tiingo, FMP; absent keys are skipped in the fallback chain, never crash it.

Fallback chains are re-ordered by IP-ban risk (lightweight, throttle-tolerant public endpoints lead; key-gated REST trails) behind a shared throttled HTTP gate (backtest/loaders/_http.py) with per-host rate buckets, jitter, and session reuse. On top sit 18 read-only data tools — fund flow, dragon-tiger board, northbound (Stock-Connect) flow, margin trading, block trades, shareholder count, lockup expiry, sector membership, research reports, news, SEC filings (EDGAR + XBRL), financial statements, options chains, institutional holdings, full-market screening, symbol search, FRED macro, and iwencai natural-language A-share search — across A-share / US / HK, all exposed over MCP. Three shared clients (eastmoney / yahoo / sec_edgar) back the loaders and tools, and a consolidated data-routing index plus per-source eastmoney / sec-edgar skills document the layer.

💱 10 broker SDK connectors — read + paper, mandate-gated live

Trading is connector-first: pick a profile, and paper/live is an attribute of the connector. This release brings the roster to 10 brokers — IBKR (local read-only TWS/Gateway) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (India NSE/BSE + F&O). Direct-SDK connectors share a broker_sdk transport and each does read + paper-account order placement; live placement passes a single fail-closed bounded-autonomy gate (sdk_order_gate.py: mandate + kill switch + audit). Brokers with no runtime paper/live discriminator (Longbridge, Dhan, Shoonya) are structurally capped at paper + read-only — their place_order / cancel_order hard-refuse any non-paper config at the first line. Order-placing tools stay off MCP (agent + CLI only).

📊 Alpha compare across CLI / REST / Web / agent tool

vibe-trading alpha compare ranks any set of Alpha Zoo factors by IC / IR on your universe, sharing one compare_runner.compare_alphas core behind the CLI, a POST /alpha/compare REST route with SSE-streamed progress, the Alpha Zoo Web UI Compare view, and a read-only alpha_compare agent tool. A run_bench(only=…) subset filter benches only the compared factors instead of the whole zoo.

🔌 Provider-reliability overhaul

A provider capability layer gates reasoning capture/replay, Gemini thought signatures, Kimi user-agent, and OpenRouter reasoning bodies per provider. vibe-trading provider doctor prints a redacted diagnostic snapshot. Streaming failures now raise an explicit, redacted ProviderStreamError (carrying status_code + .retryable) with one retry for transients and fail-fast on 4xx; a throttled reasoning_delta SSE drives a "Reasoning…" liveness indicator in the Web UI. Also: an optional native DeepSeek adapter (VIBE_TRADING_DEEPSEEK_ADAPTER), read-only tool hard-timeouts (VIBE_TRADING_TOOL_TIMEOUT_SECONDS), and per-provider temperature handling (Kimi-k2 forced to 1.0, MiniMax clamped > 0).

🔬 Research Autopilot Phase 1

run_research_autopilot turns a hypothesis_id into a research goal (thesis as objective, backtest-relevant acceptance criteria, next-step hints), and generate_backtest_config auto-writes a backtest config.json from the hypothesis's universe and data sources — so the agent goes straight from idea → signal_engine.py → run.

🗃️ Opt-in local data cache + local loader

VIBE_TRADING_DATA_CACHE=1 caches settled bars to ~/.vibe-trading/cache (user home, never the repo); a staleness guard never caches a range ending today, and cached frames are byte-identical to live fetches. A new local loader reads OHLCV straight from your own CSV / Parquet / DuckDB files via ~/.vibe-trading/data-bridge/config.yaml, with normal fallback-chain support.

🛡️ Security & hardening wave

A community-driven hardening pass: API settings-write auth (#245), agent shell-tool opt-in (#243), loopback-host rebinding rejection (#242), explicit local-shutdown auth (#241), and identifier containment for mandate proposal-ids (#256), persistent-memory types (#257), and MCP swarm run-ids (#258). Plus responsive Stop mid-stream + SSE reconnect on returning to a running session (#229), multi-engine web_search fallback (#231), and Gemini thoughtSignature round-trip through OpenAI-compat tool calls (#176, #184).

🪪 Version reporting is now consistent

--version, the REST API (/docs + /api), the MCP server handshake, and the Web UI footer all derive from one source — the REST API had drifted to a wrong hardcoded 5.0.0. Packaging also now ships skill example scripts in the wheel, and the Docker image installs weasyprint's native libs so PDF reports render.

Remote API/Web deployments should set API_AUTH_KEY and explicit trusted CORS origins. Local CLI and localhost Web UI workflows remain low-friction.
