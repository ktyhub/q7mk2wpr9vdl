Fixed

Regressions in 0.1.18

  • A retried provider error no longer halts live model decisions for the day. 0.1.18 announced every failed stream, compaction call or cancelled response that reported no usage as missing usage, which the live decision budget treats as a reason to halt; a connection reset followed by a successful retry stopped live decisions until the next UTC day. Such calls are now counted as unreported_calls in llm_usage.json; an ordinary response without usage still halts the runner as before.

  • A research goal's final answer is delivered even when it crosses the goal's token budget. 0.1.18 discarded a finished text answer whose own usage reached token_budget — the text had already streamed — and reported the run as failed. The answer is now released and the run succeeds with the budget reason; a tool call from a response past the budget is still not executed, and the exhausted goal still refuses further spending. The message says to end the goal, since a budget cannot be raised after the goal is created.

The grounding gate

  • Figures quoted from an uploaded document can be grounded (#2058, thanks @Jackzigen; closes #2050). read_document answers in prose, so its numbers never became evidence and the gate cut every figure quoted from a PDF. Up to 400 marked figures per document (percent, currency, decimal) are now recorded under its file name, never a page number or year. A document the run wrote, or one inside the run directory, is not evidence. A maintainer follow-up lets an explicitly referenced table cell be restated with the unit its header gives (1.92亿元) and used in money arithmetic, without admitting a different value, currency or a ratio. A missing file_path now names the uploads/<name> handle.

  • Percentage-point figures ground against the bare declaration (#2108, thanks @Jackzigen; closes #2107). 1.13个百分点 is conventionally declared 1.13; the gate cut such figures even when the document held the value. The borrow is one-way and exact, for whole and decimal points alike: 37% in prose still needs a percent declaration. pct / ppt / ppts / 百分点 now read as point marks, and a declared range 20%-30% becomes two endpoint declarations instead of a malformed line and a bogus -30%.

  • A percent figure can borrow a bare declaration only when its document wrote the percent (closes #2149). +17.10% grounds against a declared 17.10 | observed when the referenced document printed 17.10%, or printed 17.10 in a table column headed % / (%), including tables a PDF reader flattened to whitespace. The same number as a weight or an amount, or from another document, still fails.

  • Comma-grouped integers from a document are evidence (#2135, thanks @remote-controlled-man; refs #2126). 165,200 in a filing's plain text was read as a bare integer and left out of the ledger, so a correctly quoted table cell was refused. A visible thousands separator now marks a number as a measurement everywhere, so the same spelling in an answer needs a declaration or matching evidence too. Unmarked integers, dates and run-generated documents keep their exclusions.

  • Period valuations, dotted thousands, horizon labels and percent-point derivations (#2072, thanks @zeus229). An object naming its own ISO currency stamps the value_start / value_end and other amount fields directly beside it (a maintainer follow-up stops nested objects inheriting it). 1.618.596 is one number in any notation; 45.850 keeps its decimal reading. A 1Y / 10y table cell is a label, not a figure. A derived percent over percent-named fields the ref names grounds 41.2% for 61.56 - 20.36 and refuses 4120%.

  • Magnitude marks in a derivation are part of the operand (adapted from #2134, thanks @he-yufeng; closes #2125). ÷ 1亿, 2.5万, 3M or a currency word in a formula was evaluated as 1, 2.5 or 3, so a correct derived figure was refused. The supported marks are expanded before labels are stripped; the expanded operands still need observed or declared evidence. Magnitude marks may also follow a figure after a space (1.92 亿), from the Gildata work in #2117 (thanks @TWJxi and @lishuanghong1989-netizen).

  • A ticker's last letter is no longer read as an A-share constraint. 分析NVDA股票 matched A股, and 比较NVDA和HOOD or NVDA/HOOD matched the A/H cross-listing pattern, so the resulting market filter removed NVDA.US and the answer went ambiguous. Agent loop, providers and swarm

  • Stop ends a swarm run, not only the chat turn (#2059, thanks @Jackzigen; closes #2055). The swarm tool slept through its whole wait budget without checking the stop flag, so workers kept calling the model. One cancel event per turn now reaches the swarm tool, which cancels the run and returns cancelled at once; live runs are indexed per session, so a stop after the tool returned still lands and POST /swarm/runs/{id}/cancel no longer answers 404 for agent-started runs. An exhausted wait budget still does not cancel a run.

  • Background tasks belong to their owner (#2092, thanks @he-yufeng). Task reads, cancellation and completion notices are scoped to the session (or Swarm worker / isolated host) that started them, so one session can neither read nor cancel nor drain another's results; later attempts in the same session still see earlier tasks.

  • Stop and shutdown reap background processes (#2098, thanks @he-yufeng; closes #2095). A stopped or failed turn cancels its owner's running commands, including ones an earlier turn started; a successful turn leaves them running as before. Cancelling before spawn never starts the command, and the force-stop signals the process group even after the shell exited. API shutdown refuses new runs, cancels owned work off the event loop for up to five seconds and logs any task still running.

  • Background outcomes survive a restart (#2100, thanks @he-yufeng; closes #2097). Each task keeps a small redacted record under <runtime_root>/background-tasks/; after a restart a task left running reads interrupted and one left cancelling outcome_unknown, with a recovery reason, and is never re-run or signalled by its stored PID. Undelivered completion notices are restored to their owner, at least once (adapted from #2157, thanks @he-yufeng; closes #2156); corrupt or unknown-version records are reported, not dropped.

  • A silent provider stream is interrupted instead of hanging (#2099, thanks @he-yufeng; closes #2096). The wait for the next chunk is raced against the idle and total timeouts (VIBE_TRADING_LLM_TIMEOUT_SECONDS, 300 s; 0 disables) and the stop flag, so Stop reaches a stalled stream. A stopped or timed-out stream no longer falls back to a plain request that would resend an abandoned turn, and a chunk that already arrived keeps its usage. A blocking third-party adapter can still hold its socket until it returns.

  • Usage keeps cache and reasoning tokens (#2109, thanks @he-yufeng; closes #2103). Claude CLI reports cache reads and writes separately and bills every feedback retry, while context sizing uses the last prompt rather than the sum of resent prompts; Codex passes cached and reasoning tokens through. A reply with refused native tool calls, or more than two CLI turns, is sent back with a note that the host tools still work, within the existing three retries; an ordinary two-turn structured answer is accepted. The system prompt and load_tools now say to request tools through the host's tool-call protocol.

When the last iteration's answer contains tool-call syntax or a tool call, the agent gets one more text-only turn beyond the iteration cap; it cannot run tools or continue a goal, still obeys Stop and goal budgets, and the neutral fallback is released if it fails again.

  • Anthropic runs survive an empty reply (adapted from #2120, thanks @he-yufeng; closes #2115). The empty-response retry, the tool-markup retry and the pending-write directive were sent as mid-run system messages, which langchain-anthropic refuses, so one empty Claude reply failed the run. U+2028/U+2029 inside a swarm heartbeat hid the run's liveness, so the reaper could fail a live run; the same splitlines() fault dropped records when reading traces, rebuilding the session search index and walking the audit ledger. It now uses the fractional span; daily runs are unchanged, and a span under one day still counts as one year.

Validation and run artifacts

  • Backtest validation refuses equity at or below zero (#2161, closes #2160, thanks @he-yufeng). Percentage returns and drawdown are undefined once equity reaches zero, yet validation still reported numbers for them. Monte Carlo (the observed trade path or any shuffled one), the bootstrap Sharpe CI and each walk-forward window now return only an error when observed equity is zero, negative or non-finite, and the bootstrap also refuses a non-positive initial capital. Monte Carlo errors no longer carry a placeholder p_value_sharpe of 1.0; the Web validation panel shows the error alone. Landed through a maintainer commit.

Quant Library and analysis tools

  • Historical VaR and CVaR use the documented number of tail losses (#1950, thanks @rudycelekli). The tail rank ceil((1 − c) × n) − 1 was computed in binary floating point, where (1 − 0.95) × 100 is 5.000000000000004, so 100 returns at 95% took the sixth-worst loss instead of the fifth and CVaR averaged six, understating both. The rank now comes from the confidence's decimal spelling, with no tolerance, so nearby probabilities keep distinct ranks. historical_var, historical_cvar and the VaR/CVaR of analyze_mc_results move at such boundaries.

  • The Corrado rank test's S(K) includes event days (#2000, thanks @rudycelekli). event_study divided corrado_rank_z by an S(K) averaged over estimation days only; Corrado (1989) averages the squared mean rank deviation over the combined estimation and event period. With a real event effect the left-out days carry the most extreme ranks, so the statistic overstated significance exactly when it rejected. Ranking and numerator are unchanged.

  • Drawdown day counts use calendar dates (#2026, thanks @rudycelekli). max_drawdown_analysis counted underwater_days and recovery_days with Timedelta.days, so on a timezone-aware series a 23-hour spring-forward day counted as 0. Both now subtract civil dates; naive midnight-stamped series are unchanged.

  • Market impact functions refuse arrays (#1960, thanks @rudycelekli). fixed_slippage, linear_impact and sqrt_impact are documented scalar-only and typed -> float, but broadcast a list, array or Series and returned an ndarray, dropping a Series' index; quantlib_call's __series__ envelope reached this. Price, volume, ADV, bps, coefficient, volatility and eta arguments now raise TypeError for a container or a bool. Scalar results are unchanged.

  • Heston prices are right for short expiries (#2140, thanks @kadyrbekovhamit-cyber). heston_price integrated its pricing formula only up to u = 200. An option a day or less from expiry has an integrand that has not decayed by then, and the truncated price can be off by more than 10%. The default is now integration_limit=None, which integrates to infinity (0–200 plus the tail); an explicit finite limit keeps the old truncation.

  • Run attribution keeps benchmark returns aligned (#2044, thanks @dajiaohuang). GET /runs/{run_id}/attribution dropped an equity.csv row with an unusable portfolio return together with that row's benchmark equity, so the next benchmark return spanned two bars and was paired with a one-bar portfolio return in the alpha/beta regression. The row now stays as a gap and only its own pair is left out.

  • The options payoff API refuses boolean quantities (#2049, thanks @dajiaohuang). POST /options/payoff accepted "qty": true as one contract, because the request model coerces booleans to integers. A boolean qty is now a validation error, as zero already was.

Alpha Zoo, factors and alpha bench

  • Twenty GTJA 191 alphas read A-share VWAP in yuan (#2039, thanks @rudycelekli). Alphas 7, 8, 12, 13, 16, 17, 26, 36, 39, 41, 44, 45, 61, 64, 73, 74, 77, 87, 90 and 92 built VWAP inline as amount / (volume × 100 + 1). On Tushare units (amount in thousand CNY, vol in lots) that is a thousandth of the traded price, and a vwap column already in the panel was ignored. They now call the shared vwap(panel, "equity_cn"), which uses vwap when present and otherwise scales amount by 1,000. Alphas that use VWAP only through ranks or correlations are insensitive to the scale; those that mix it with price levels (13's sqrt(H × L) − VWAP, the weighted prices in 74, 77, 87 and 92) change value.

  • GTJA alpha 17 keeps the sign of its exponent (#2051, thanks @rudycelekli). The report's RANK(VWAP − MAX(VWAP,15)) ^ DELTA(CLOSE,5) was computed as |base| ^ |exponent|, so after a five-day fall a base of 0.5 and a change of −2 gave 0.25 instead of 4. The base is a percentile rank in (0, 1], so the power is now taken directly with the signed change. The merge also corrected the golden fixture and the factor's English and Chinese notes. Values change wherever the five-day close change is negative (and, via #2039, wherever the VWAP scale mattered). A release follow-up keeps the value missing whenever the base or the exponent is: IEEE pow gives 1 for NaN ** 0 and 1 ** NaN, so a flat close during the 15-bar VWAP warmup, or the top-ranked name on a bar with no close change, had started to report 1.0.

  • GTJA alpha 55 has the swing index's third denominator branch (#2036, thanks @rudycelekli). The denominator chose between the high-gap form |H−C₋₁| + |L−C₋₁|/2 + |C₋₁−O₋₁|/4 and the low-gap form only. When neither of those gaps is the largest range, the report uses |H−L₋₁| + |C₋₁−O₋₁|/4, and the code now does too. Values change on those bars and on every 20-day sum that contains one.

  • GTJA alpha 170 scales by the 5-day mean of HIGH (#2037, thanks @rudycelekli). The middle term HIGH × RANK(HIGH − CLOSE) / (SUM(HIGH,5)/5) divided by the 5-day mean of CLOSE instead of HIGH, contrary to the report and the factor's own formula metadata. Every value changes.

  • GTJA alpha 140 drops an extra TSRANK (#2038, thanks @rudycelekli). The correlation leg ranked the correlation over 7 days before decaying it. The report's leg is TSRANK(DECAYLINEAR(CORR(TSRANK(CLOSE,8), TSRANK(MEAN(VOLUME,60),20), 8), 7), 3), which is what is computed now. Values change wherever that leg is the smaller of the two.

  • GTJA alpha 101 uses the report's right-hand leg (#2040, thanks @rudycelekli). It compared against RANK(CORR(RANK(HIGH), RANK(MEAN(VOLUME,10)), 11)); the report's leg is RANK(CORR(RANK(HIGH × 0.1 + VWAP × 0.9), RANK(VOLUME), 11)). Code, formula metadata and golden fixture now follow the report, and a bar is NaN unless VWAP was observed across the 11-day window. The 0 / −1 signal flips on bars where the comparison changes.

  • Qlib BETA and RESI are least-squares trend statistics (#2062, thanks @he-yufeng). Alpha158 defines BETAd = Slope(close, d) / close and RESId = Resi(close, d) / close. The five BETA factors (5, 10, 20, 30, 60) computed the endpoint slope (close − close₋d) / (d × close), and the five RESI factors the gap to the moving average (close − mean(close, d)) / close. Both now use new ts_slope / ts_resi operators: the OLS slope of close on time over a full window, and the latest close's residual from that fit. Every value changes.

  • Qlib ROC and CORD match Alpha158 (#2069, thanks @he-yufeng). The five ROC factors returned the d-day return close / close₋d − 1; Alpha158's ROCd is close₋d / close, a decreasing function of that return, so each ROC factor's rank IC changes sign and a bench may now call one reversed that it called alive, or the reverse. The five CORD factors correlated the price ratio with log((v + 1) / (v₋₁ + 1)) instead of Alpha158's log(v / v₋₁ + 1), which they now use. Formula metadata follows.

Valuation, rigor checks and report audit

  • Valuation workbooks keep text literal (#1949, thanks @rudycelekli). export_dcf_workbook, export_comps_workbook and export_three_statement_workbook let openpyxl read a string starting with = as a formula and #N/A as an Excel error, so an assumption basis such as = 2% inflation + 1% real growth read back empty. Every text cell is now written as a string; numbers and booleans keep their types.

  • financial_rigor refuses non-finite and boolean inputs (#2053, thanks @yufengsika). NaN, Infinity and true (read as 1) were accepted and answered status: "ok" with NaN or Infinity in a payload that is not valid JSON, and a finite price such as 1e308 could overflow to infinity. Every command that converts a number now returns an error envelope for such input, and a result that cannot be written as finite JSON is an error.

  • Earnings and FCF yield are omitted at a zero price (#2033, thanks @rudycelekli). verify_valuation raised DivisionByZero when the price was 0 and EPS or FCF per share was not. Those two yields are now left out, as dividend yield already was; P/E, P/FCF and the other ratios with price in the numerator are still reported.

  • Report audit skips fenced examples (#1951, thanks @rudycelekli). report_audit dropped fenced code only from its label: value pass, so a template table inside a fence was sampled as a real claim, and tilde fences or a longer fence around a shorter one were mishandled. Fenced blocks (backtick or tilde, closed by a fence at least as long, or unclosed to the end) are now blanked before both passes, keeping the report's line numbers.

Governance ledger and entity ingestion

  • The audit ledger rotates past its first segment (#1962, thanks @rudycelekli). rotate_if_needed verified only the active file before sealing it. After one rotation that file legitimately starts mid-chain, so the check reported a sequence gap on a healthy ledger and every later rotation raised LedgerCorruptionError. It now verifies the whole history, sealed segments included. A maintainer follow-up numbers a new archive after the highest existing one (past gaps and beyond four digits), orders segments numerically, and seals through a hard link so an existing archive is never overwritten. No runtime path calls the rotation automatically.

  • Run manifests detect an edited tool list (#2017, thanks @rudycelekli). RunManifest.verify_hash covered tools_hash but not the tool names it summarises, so a run_manifest.json whose tool_names gained, lost or renamed a tool still verified. It now rebuilds the snapshot from the names and fails on a mismatch, and the evaluation harness's manifest-integrity verdict inherits the check. Untampered round trips still verify.

  • Imported amounts read dot grouping, and only valid grouping (#1964, thanks @rudycelekli). In load_cashflows and load_panel, 1.234.567 failed as an unusable amount while 1,234,567 parsed. Repeated dots now group digits too. A maintainer follow-up accepts grouping, inferred or implied by a declared decimal_separator, only when every group is valid (threes, or Indian 2-2-3 grouping), so a malformed amount or a separator inside the fraction is refused instead of concatenated. 1,234 and 12.000 still ask for decimal_separator.

Paper trading

  • Strategy steps no longer hang on the stdio MCP transport (closes #2089). The strategy worker was a multiprocessing spawn child, which on Windows could be blocked by the MCP host's pending read of the server's stdin, so every strategy_path call timed out. The worker is now a fresh interpreter that talks to the server over its own private pipes, and strategy prints never reach the protocol stream. A regression test that starts the worker while the host's stdin read is blocked now also runs in CI on native Windows x64 and ARM64. Startup and per-day deadlines, sandboxing and hard teardown are unchanged.

  • ST stocks outside the main board keep their board's price limit (#1984, thanks @rudycelekli). When the exchange limit table has no row and the band is derived from the previous close, every ST stock was given a ±5% band, so a ChiNext or STAR ST stock moving 8% had its buy or sell rejected as limit_up / limit_down. Only main-board ST stocks narrow to ±5% now; ChiNext and STAR keep ±20% and Beijing ±30%.

  • A 3:2 split priced just inside the neutral band is still caught (#1985, thanks @rudycelekli). The split detector ignored any close-to-close ratio inside (2/3, 3/2), so a 3:2 split quantized to the cent (30.00 to 20.01, a ratio of 0.667) passed as an ordinary one-third loss. A ratio within 0.1% of 2:3 or 3:2 is now a candidate: with matching volume and NAV continuity the step returns PAPER_DATA_NOT_READY, otherwise that day's orders on the symbol are rejected corporate_action_unresolved. Holdings are still never rescaled from prices alone.

Live trading, brokers and portfolio

  • Robinhood portfolio positions are priced, and long accounts are read in full (#2054, closes #1428, thanks @Jackzigen). The read-only Robinhood source now declares quotes.read and prices each equity position through get_equity_quotes instead of listing it unpriced, and position and order reads follow the next cursor to the last page; a failed follow-up page fails the read rather than returning part of the account. A quote refresh never opens a browser for OAuth. A maintainer follow-up requires the quote to name the requested symbol, prices only an active instrument that has traded, uses the newer timestamped regular- or extended-hours trade and shows its as-of time; anything else stays unpriced with a price_error. The mapping follows a third-party capture of the server's schema and has not been checked against a live account.

  • Portfolio errors no longer carry credentials, and Binance HTTP 451 is explained (#1937, thanks @goatyyc). Connector read errors go through the shared redactor before they are stored, sent as refresh progress or returned: URL query strings and signature / api_key / secret values are replaced, and the latest and historical snapshot reads clean errors stored before the upgrade. A Binance HTTP 451 "restricted location" failure gets the code binance_restricted_location and a localized explanation on the Portfolio page.

  • Longbridge keeps per-currency cash and financing limits (#1940, thanks @alexwan02). Longbridge's total_cash nets every currency into one number, so a borrowed (negative) currency leg disappeared behind a positive one. Balance rows now carry each currency's available, withdrawable, frozen and settling cash and the account's maximum and remaining financing amount, through account reads, Portfolio snapshots (balance_details), the portfolio and connector-balance CLI output, the API, the agent's portfolio context and the Web account card. They are not added to totals; negative values keep their sign and unreported ones stay empty.

  • Binance spot open orders can be listed across all symbols (closes #2090). get_open_orders without a symbol always raised, because CCXT refuses a symbol-less fetchOpenOrders by default to warn about its request weight. The spot client now acknowledges that warning; CCXT's rate limiter stays on, and exchange, authentication and network failures still surface. Fill history without a symbol still reports that Binance needs one.

  • Deleting a connection keeps its vault protection (#2153, thanks @TerryF7). Deleting an OAuth or local-gateway connection, whose profile declares no credential fields, no longer needs the OS keyring; it used to fail without the keyring extra. A connection with stored credentials is still kept when the vault is unavailable or cannot confirm the secrets were removed, and the API answers HTTP 503 with the reason instead of a server error. The connection center shows the failure on that connection's card, with a localized message when the portfolio still uses the connection.

  • Zerodha and Shoonya paper orders refuse fractional quantities (#1991, thanks @rudycelekli). The local paper simulators truncated the quantity, so 0.5 shares was acknowledged as a simulated fill of 0 shares and 2.7 as 2. A quantity must now be a finite whole number of at least 1, otherwise the order is refused with "quantity must be a positive whole number of shares". Both brokers remain paper-only.

  • The broker key . can no longer act on the global kill switch (#2003, thanks @rudycelekli). A broker's live directory is <runtime_root>/live/<broker>, and . resolved to the live root itself, so that broker's HALT sentinel was the global one: halting or clearing broker . halted or released every broker. . is now rejected alongside path separators and ...

  • MT5 keeps a configured deviation_points of 0 (#2019, thanks @rudycelekli). An explicit zero slippage tolerance was read as "unset" and replaced by 20 points on every market order; only a missing or empty value defaults to 20 now.

Shadow account

  • Shadow-account backtests trade every documented entry condition (#2073, thanks @cgycorey). The generated signal_engine.py recognised only two-sided {"min", "max"} bounds, so ("<=", -0.08) pairs, bare scalars and one-sided bounds were dropped and the backtest traded a looser rule than the profile stated. Pairs and scalars (read as >=, as the live scanner reads them) now map onto inclusive bounds, each side applies on its own, and scanner and engine share one operator vocabulary. A strict > or <, ==, != or a non-string market, which the engine cannot express exactly, now raises an error instead of being widened.

  • The shadow-account result cache no longer serves stale runs (#2075, thanks @cgycorey). A cached run was keyed by window and journal hash only, so an edited rule or market selection silently reused numbers from the old definition; the key now also covers the rules, the source and preferred markets and an engine epoch. A cached report also dropped excluded_currencies and read as if every currency had been summed; the disclosure is restored. Existing caches miss once and re-run.

Trade journal and cash flows

  • Journal buys and sells need a valid quantity (#2052, thanks @MetaAviator). A buy or sell row whose quantity was missing, zero, negative or non-finite reached FIFO matching. The analysis now returns an error asking for finite positive quantities before any filter is applied. Cash dividends may still have zero quantity.

  • Cash-flow transfers are sign-checked (#2023, thanks @dajiaohuang). transfer_in and transfer_out carried no sign rule, so a transfer written from the portfolio's side entered XIRR and money-weighted returns with the wrong sign. They now follow the holder's convention used for contributions and distributions: a transfer into the portfolio is negative and a transfer out positive, and a contradicting amount is refused with a hint to flip the sign or use another kind. The cashflow_performance schema states it.

Channels and scheduled delivery

  • Feishu tool hints land on the streaming card that is already open (#1957, thanks @Shizoqua). The hint path looked up the reply's buffer by the inbound message id, but it wrote through send_delta without that metadata, so the write resolved to the chat id instead. The hint then opened a second card whose "generating" indicator never cleared. The metadata is now forwarded, so both lookups use the same stream.

  • Teams replies to a multi-paragraph message keep the quote out of the user's text (#1958, thanks @Shizoqua). For the "Reply wrapper" shape, the parser split only at the first blank line, so later paragraphs of the quoted message reached the agent as the user's reply. It now splits at every blank line and treats only the last block as the reply. Limit: if the reply itself has several paragraphs, all but its last are folded into the quote.

  • Weixin attachments with the same name no longer overwrite each other (#1967, thanks @Shizoqua). A sender-supplied filename was written as-is into the media directory, so a second report.pdf replaced the first one, which an earlier turn still pointed to. Each download is now created exclusively under a unique name that keeps the original stem (up to 32 characters) and extension. Repeated names, identical URLs, same-second retries and concurrent downloads each get their own file. The maintainer follow-up replaced the PR's timestamp-and-hash suffix, which could still collide.

  • Voice notes reach the agent as attachments on five channels (#2078, #2106, thanks @Shizoqua and @VectorPeak). WhatsApp (#2078) and Telegram, Feishu, Matrix and Weixin (#2106) called a transcribe_audio method that no channel defines. As a result, a voice note was dropped or logged as a failed download. Each adapter now forwards the downloaded audio with the same media marker it builds for other attachments. No speech-to-text runs: the agent gets the audio file, not a transcript.

  • Discord streams no longer fail on a long first message or repeat overflow (#2114, thanks @Shizoqua). The first message of a stream sent the whole buffer, so a first delta longer than Discord's 2,000-character limit failed the stream. The first message now sends only the first chunk, as later edits already did, and the remaining text goes out once when the stream finishes. The maintainer merge removed the PR's extra sends at stream start, which would have duplicated that overflow.

  • Channel path containment has boundary tests (#2094, thanks @Shizoqua). Matrix uses is_path_within to keep outbound attachments inside the workspace when that restriction is on. It is now tested against a sibling directory that shares the root's prefix, .. traversal both out of and within the root, and a symlink that points outside. Behaviour is unchanged.

Web UI and locales

  • Stopping a chat also stops its swarm run and freezes the card (#2060, thanks @Jackzigen). The stop button cancelled only the session, so a swarm that had already started kept its card spinning, and a late event could repaint it as completed. Stop now marks every pending or running swarm card in the chat as cancelled, including its running and waiting agents. It also sends POST /swarm/runs/{id}/cancel for each run and ignores any later event for a cancelled card. Limit: the card shows cancelled even when the cancel request fails, because every error is swallowed, not only the 404 from a run that already finished.
