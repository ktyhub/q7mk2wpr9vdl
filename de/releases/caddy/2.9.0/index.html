Caddy v2.9.0

Frohes neues Jahr! Wir freuen uns, den Caddy 2.9 herauszubringen. Abgesehen von einigen kleineren neuen Funktionen konzentriert sich diese Version hauptsächlich auf Verfeinerungen und Fehlerbehebungen in vielen Bereichen, darunter:

  • Laden der Konfiguration
  • Veranstaltungen
  • Protokollierung
  • Platzhalter
  • Reverse-Proxy- und HTTP-Serverleistung
  • Matcher
  • HTTP (insbesondere HTTP/3)
  • Metriken (Metriken pro Host)
  • Sicherheit
  • TLS-Automatisierung und ACME ARI Wir sind uns bewusst, dass großes Interesse an Encrypted Client Hello (ECH) und Post-Quanten-Chiffren besteht. Diese sollen in Go 1.24 unterstützt werden, dessen stabile Veröffentlichung etwa im Februar geplant ist. Wir wollten die Benutzer nicht dazu zwingen, die Unannehmlichkeiten auf sich zu nehmen, vorab veröffentlichte, nicht auf Lager befindliche Installationen von Go zu installieren, obwohl die RCs recht stabil und produktionsbereit sind, um überhaupt Caddy zu kompilieren, was angesichts unseres Plugin-Ökosystems durchaus üblich ist. Wir erwarten in naher Zukunft eine Veröffentlichung des Caddy 2.10 mit diesen Funktionen, basierend auf dem Go 1.24. Wir hoffen, dass Ihnen die 2.9-Veröffentlichung gefällt. Vielen Dank an alle Mitwirkenden, Fehlerreporter und Helfer sowie an die Organisationen, die Vorabversionen in der Produktion bereitgestellt haben, um bei der Überprüfung von Patches und Funktionen zu helfen.

caddy v2.9.0

Highlights

  • Safer, faster HTTP runtime — Caddy now defaults ReadHeaderTimeout to one minute, mitigating slow-header attacks. HTTP/3 shuts down gracefully (#6213), while uncompressed responses use sendfile when possible (#6749) and lazy logging/event serialization cuts per-request overhead (#6671, #6560). IP matchers reject 0-RTT early data, and proxied requests carry an Early-Data header (#6427), so authentication rules can distinguish replayed requests.

  • WebSockets over HTTP/2 — reverse_proxy now rewrites WebSocket request and response frames for HTTP/2 (#6567) and restricts upgrade handling to actual WebSocket traffic (#6740). This enables standards-compliant WebSockets through HTTP/2 backends; retest clients or middleware that relied on nonstandard Connection/Upgrade behavior.

  • More controllable reverse proxying — Active health checks support configurable methods and request bodies (#6453, #6520), plus host and network-address placeholders in headers (#6440, #6450). http.reverse_proxy.retries exposes retry counts to logs and routing logic (#6553), and weighted round-robin now accepts zero weights (#6681), letting operators drain an upstream without removing it from configuration.

  • Metrics and tracing upgrade requires config migration — In JSON configurations, move the metrics object out of servers to the top level (#6606). The relocated configuration supports per-host metrics and new Go/process collectors (#6704); log sampling (#6682) and http.vars.span_id/spanID access-log fields (#6646) improve observability and control log volume.

  • Expanded static-file and matcher tooling — try_files gains first_exist_fallback (#6699), directory browsing gains sorting (#6468, #6502) and an experimental file_limit (#6648), and new {?query} (#6714) and Transfer-Encoding matching/logging (#6629) simplify routing and diagnostics. Runtime placeholders for selected TLS and HTTP matchers (#6480) also make match decisions available downstream.

  • Plugin authors must adapt; deprecated TLS settings are removed — ListenerFunc changes signature (#6651), run is reorganized around a public BuildContext (#6378), and internal address helpers are renamed (#6622), so plugins must be updated and recompiled. The deprecated TLS automation rate_limit and burst settings are also removed (#6611); delete those keys before upgrading.

  • ECH and post-quantum support are deferred — 2.9 remains buildable with stock Go rather than requiring a prerelease toolchain. Encrypted Client Hello and post-quantum cipher support are planned for Caddy 2.10 on Go 1.24; do not upgrade expecting those capabilities yet.

Happy New Year! We're pleased to release Caddy 2.9. Aside from some minor new features, this release is mainly focused on refinements and bug fixes in many areas, including:

  • Config loading
  • Events
  • Logging
  • Placeholders
  • Reverse proxy and HTTP server performance
  • Matchers
  • HTTP (esp. HTTP/3)
  • Metrics (per-host metrics)
  • Security
  • TLS automation & ACME ARI

We realize there is extensive interest in Encrypted Client Hello (ECH) and post-quantum ciphers. These are slated to be supported in Go 1.24, which is scheduled for a stable release in approximately February. We did not want to force users to go through the inconvenience of installing pre-release, non-stock installations of Go, even though the RCs are quite stable and production-ready, in order to even compile Caddy, which is quite common given our plugin ecosystem. We anticipate a Caddy 2.10 release in the near future with these capabilities, built on Go 1.24.

We hope you will enjoy the 2.9 release. Thanks to all contributors, bug reporters, and helpers, and those organizations which deployed pre-release versions to production to help verify patches and features.
