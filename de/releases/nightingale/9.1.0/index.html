nightingale v9.1.0

Minor Veröffentlicht6. Aug. 2026 Quelleccfos/nightingale Englisches Original

Diese Seite ist maschinell übersetzt. Maßgeblich ist der englische Originaltext.

Nachtigall v9.1.0

Was hat sich geändert?

  • Leistung: integrierte Zeitreihendatenbank – von Categraf gepushte Metriken werden lokal gespeichert, sodass für den Einstieg kein externes Prometheus/VictoriaMetrics erforderlich ist; Eine Prometheus-Datenquelle mit dem Namen embedded-tsdb wird beim ersten Start automatisch registriert. Vorhandene Setups werden berücksichtigt: Wenn bereits eine aktivierte Prometheus-Datenquelle vorhanden ist, wird die Datenquelle nicht automatisch erstellt – Proben werden weiterhin lokal geschrieben und Sie können eine Prometheus-Datenquelle hinzufügen, die auf die integrierte TSDB verweist, um sie abzufragen (#3283)
  • Kunststück: Datenquellen aus Grafana in einen click importieren, mit einer Ergebniszusammenfassung pro Datenquelle (#3295)
  • Leistung: Überarbeitung der Datenquellenseite – Nach dem Speichern einer Datenquelle prüft Nightingale diese mit Sentinel-Metriken, um zu melden, welche integrierten Dashboard-/Benachrichtigungsregelvorlagen bereits Daten enthalten, und leitet Sie zu Ihrer ersten Abfrage (#3301)
  • Leistung: Warnungsauswertungsaufzeichnungen pro Zyklus – jede Regelauswertung speichert das, was sie abgefragt hat und wie sie es beurteilt hat, auf der lokalen Festplatte der Warnungs-Engine, einsehbar in einer Schublade auf der Warnungsregelseite (#3305)
  • Kunststück: Benachrichtigungskanalkonfigurationen können getestet und Nachrichtenvorlagen in der Vorschau angezeigt werden, bevor sie gespeichert werden (#3302)
  • feat: Categraf-Collect-Config-Assistent – ein neuer /agents/categraf/collect.sh-Endpunkt bedient das Applier-Skript, mit Plugin-Vorlagen und Metriküberprüfung in der Konsole (#3286) – Leistung: Die Ereignispipeline unterstützt Scheinereignisse in Try-Run, Zeitbereichsfilterung für Ausführungsdatensätze, Batch-Aktivierung/-Deaktivierung und eine neue Änderung API (#3281, #3285)
  • feat: integrierte Warnregelvorlagen in Integrationen stark erweitert und überarbeitet, mit en_US i18n (#3282)
  • Kunststück: MySQL-Datenquellen können zusätzliche Parameter an den DSN anhängen (#3299)
  • Leistung: Doris-Datenquellen unterstützen doris.internal_addr, damit der Edge-Prozess FE MySQL erreicht (#3298)
  • feat: Alarmregelliste unterstützt das Filtern nach Auslösertyp
  • Leistung: Die Liste der aktiven Alarmereignisse zeigt den Wert zum Zeitpunkt des Auslösens an, fügt Tags mit drei Zuständen hinzu und speichert das Filterfeld, das Intervall für die automatische Aktualisierung und den Zeitbereich für alle Besuche
  • Leistung: Der Protokoll-Explorer fügt eine Schaltfläche zum Abfragen von Dokumenten für Loki und VictoriaLogs hinzu, ermöglicht das Anhängen eines Feldfilters direkt aus dem Protokoll-Viewer und unterstützt BCE BLS-Drilldown
  • feat: Dashboard TableNG-Panel unterstützt eine Zeilendetail-Schublade
  • Leistung: Host-Seiten-Onboarding – One-click-Hostüberwachungspaket, Testalarmaktion und Karten für die nächsten Schritte
  • feat: Datenquellen-Proxy und Protokollabfragezugriff werden jetzt mit dem Benutzer und der Nutzlast in das Audit-Protokoll geschrieben
  • Kunststück: Edge versucht die Ereignispersistenz erneut in die Mitte zu bringen, mit einem verschärften Timeout pro Anfrage
  • Feature: neues API, um zu prüfen, ob eine Benachrichtigung jemals erfolgreich zugestellt wurde (#3300)
  • perf: Beschleunigen Sie Abfragen von Benachrichtigungsdatensätzen und die tägliche Bereinigung, unterstützt durch zwei neue notification_record-Indizes, die online beim Start erstellt werden (#3311) – Korrektur: Ereignisse werden tief kopiert, bevor sie in die Warteschlange verschoben werden, sodass ein Wiederherstellungsereignis ein noch nicht konsumiertes Triggerereignis an der Stelle nicht mehr überschreibt
  • Fix: Eine leere DingTalk-App-Konfiguration unterbricht Gruppenroboterbenachrichtigungen nicht mehr (#3309) – Fix: Anheften expliziter Spaltentypen an die ai_*-Modelle, um die AutoMigrate-Schemadrift zu stoppen, die dazu geführt hat, dass die Migration dieser Tabellen fehlgeschlagen ist
  • Fix: Unterstützung von max_completion_tokens für neuere OpenAI-Modelle (#3306)
  • Fix: Ungültige Labelnamen in der Warnregel event_relabel_config schützen (#3287, #3296)
  • Fix: YAML-Inhalte zum Sammeln integrierter Nutzlasten akzeptieren (#3307)
  • Fix: Erzwungenes Speichern einer Datenquelle zulassen, die ihre Integritätsprüfung nicht besteht (#3304)
  • Fix: Überprüfen Sie die globale Standarddatenquelle anhand der vollständigen Datenquellenliste vor der Filterung pro Engine-Cluster, sodass eine Standarddatenquelle, die einem anderen Cluster gehört, nicht mehr gelöscht wird
  • Fix: Korrekte Alarmregeleinheiten
  • Fix: Reparieren Sie den eingebauten Skill YAML frontmatter und stellen Sie Code-Suchtools im Chat bereit
  • Fix: Geben Sie der asynchronen Tabellenmigration eine eigene Gorm-Sitzung, damit eine fehlgeschlagene Anweisung den Rest nicht mehr vergiftet

V9 neue Funktion

  • Leistung: Einführung von Nightingale AI – integrierter KI-Assistent, Skills-Marktplatz, LLM-Konfigurationsverwaltung, mit seitenspezifischen Eingabeaufforderungsempfehlungen
  • feat: Integrierte Zeitreihendatenbank – funktioniert sofort, kein externes Prometheus/VictoriaMetrics für kleine Setups erforderlich
  • Kunststück: Neu gestaltetes Navigationsmenü, globales Layout und Tabellen-Benutzeroberfläche
  • feat: Benachrichtigungskanalverwaltung überarbeitet
  • feat: Neue Event-Pipeline-Ausführungsverfolgungsseite mit detaillierter Ausführungsansicht

Upgrade-Hinweis ⚠️

– Der neue KI-Assistent basiert auf Redis-Streams, daher ist Redis 5.0 oder höher erforderlich (Redis 7.0+ wird für Cluster-Benutzer empfohlen, um Sharded Pub/Sub zu aktivieren).

  • Alarmauswertungsdatensätze sind standardmäßig aktiviert. Die Alarm-Engine schreibt sie auf die lokale Festplatte unter ./evallog, speichert sie 8 Tage lang und ist auf 20 GB begrenzt. Stimmen Sie dies mit dem [Alert.EvalLog]-Bereich ab oder schalten Sie es aus – sehen Sie sich das neue etc/config.toml an. – Die integrierte TSDB wird durch ein direktes Binär-Upgrade nicht aktiviert: [EmbeddedTSDB] existiert nur im neuen etc/config.toml, daher wird es in einer von einer früheren Version übernommenen Konfigurationsdatei weggelassen. Kopieren Sie den Abschnitt, um ihn zu aktivieren. Es wird nur vom Center-Prozess verarbeitet (n9e-edge / n9e-alert / n9e-pushgw ignorieren es) und speichert Daten auf der lokalen Festplatte dieser einen Center-Instanz, sodass es für Einzelinstanzbereitstellungen geeignet ist – verwenden Sie bei mehreren Center-Replikaten stattdessen eine externe TSDB.

Englisches Original / English original

nightingale v9.1.0

What's Changed

  • feat: built-in time series database — metrics pushed by Categraf are stored locally, so no external Prometheus / VictoriaMetrics is required to get started; a Prometheus datasource named embedded-tsdb is auto-registered on first start. Existing setups are respected: if any enabled Prometheus datasource is already present, the datasource is not auto-created — samples are still written locally, and you can add a Prometheus datasource pointing at the built-in TSDB to query them (#3283)
  • feat: import datasources from Grafana in one click, with a per-datasource result summary (#3295)
  • feat: datasource page revamp — after saving a datasource, Nightingale probes it with sentinel metrics to report which built-in dashboard / alert rule templates already have data, and guides you to your first query (#3301)
  • feat: per-cycle alert evaluation records — each rule evaluation persists what it queried and how it judged to the alert engine's local disk, inspectable from a drawer on the alert rule page (#3305)
  • feat: notification channel configs can be tested, and message templates previewed, before they are saved (#3302)
  • feat: Categraf collect-config wizard — a new /agents/categraf/collect.sh endpoint serves the applier script, with plugin templates and metric verification in the console (#3286)
  • feat: event pipeline supports mock events in try-run, time-range filtering on execution records, batch enable/disable, and a new change API (#3281, #3285)
  • feat: built-in alert rule templates in integrations greatly expanded and revised, with en_US i18n (#3282)
  • feat: MySQL datasources can append extra params to the DSN (#3299)
  • feat: Doris datasources support doris.internal_addr for the edge process to reach FE MySQL (#3298)
  • feat: alert rule list supports filtering by trigger type
  • feat: active alert event list shows the value at trigger time, adds three-state tags, and remembers filter panel, auto-refresh interval and time range across visits
  • feat: log explorer adds a query doc button for Loki and VictoriaLogs, lets you append a field filter straight from the logs viewer, and supports BCE BLS drilldown
  • feat: dashboard TableNG panel supports a row detail drawer
  • feat: host page onboarding — one-click host monitoring pack, test alert action, and next-steps cards
  • feat: datasource proxy and log query access are now written to the audit log with the user and the payload
  • feat: edge retries event persistence to center, with a tightened per-request timeout
  • feat: new API to check whether any notification was ever delivered successfully (#3300)
  • perf: speed up notification record queries and the daily cleanup, backed by two new notification_record indexes created online at startup (#3311)
  • fix: deep copy events before pushing them to the queue, so a recovery event no longer overwrites a not-yet-consumed trigger event in place
  • fix: a blank DingTalk app config no longer breaks group robot notifications (#3309)
  • fix: pin explicit column types on the ai_* models to stop AutoMigrate schema drift, which had been failing the migration of those tables
  • fix: support max_completion_tokens for newer OpenAI models (#3306)
  • fix: guard invalid label names in alert rule event_relabel_config (#3287, #3296)
  • fix: accept YAML content for collect builtin payloads (#3307)
  • fix: allow force-saving a datasource that fails its health check (#3304)
  • fix: probe the global default datasource against the full datasource list before per-engine cluster filtering, so a default datasource owned by another cluster is no longer cleared
  • fix: correct alert rule units
  • fix: repair builtin skill YAML frontmatter and expose code search tools in chat
  • fix: give the async table migration its own gorm session, so one failed statement no longer poisons the rest

V9 new feature

  • feat: Introduce Nightingale AI — built-in AI assistant, Skills marketplace, LLM config management, with page-specific prompt recommendations
  • feat: Built-in time series database — works out of the box, no external Prometheus / VictoriaMetrics needed for small-scale setups
  • feat: Redesigned navigation menu, global layout, and table UI
  • feat: Refactored notification channel management
  • feat: New event pipeline execution tracking page with detailed execution view

Upgrade note ⚠️

  • The new AI assistant relies on Redis Streams, so Redis 5.0 or later is required (Redis 7.0+ recommended for Cluster users to enable sharded Pub/Sub).
  • Alert evaluation records are enabled by default. The alert engine writes them to its local disk at ./evallog, retained for 8 days and capped at 20GB. Tune or turn this off with the [Alert.EvalLog] section — see the new etc/config.toml.
  • The built-in TSDB is not enabled by an in-place binary upgrade: [EmbeddedTSDB] only exists in the new etc/config.toml, so a config file carried over from an earlier version leaves it off. Copy the section over to enable it. It is handled by the center process only (n9e-edge / n9e-alert / n9e-pushgw ignore it), and it stores data on the local disk of that one center instance, so it fits single-instance deployments — with multiple center replicas, use an external TSDB instead.
