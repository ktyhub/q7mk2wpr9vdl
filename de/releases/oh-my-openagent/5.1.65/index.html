oh-my-openagent v5.1.65

Eine Nachricht, die ein Agent an eine Sitzung auf einem anderen Gerät sendet, gibt jetzt an, wer sie gesendet hat. Früher kam sie dort als einfacher Text an, der nicht vom eigenen Benutzer dieser Sitzung zu unterscheiden war. Es trägt jetzt dieselbe Absenderzeile und Berechtigungsmitteilung wie eine Nachricht zwischen Sitzungen auf einem Gerät (die sendende Sitzung, ihr Arbeitsbereich und Projekt und das Gerät, von dem sie kam), und ein führendes / darin führt keinen Befehl mehr aus und erweitert keine Eingabeaufforderungsvorlage auf der Empfangsseite. omo remote send von einem Terminal bleibt unverändert. (#12858, Teil von #12852)

Bei der Speicheraufbewahrung wird der Wächter für den Abschlussdatensatz nicht mehr zweimal pro Datensatz ausgewertet. Der Abschluss-Sweep liest den Wächter jetzt einmal und behält oder entfernt den Datensatz für diese einzelne Antwort, und die Aufbewahrungstests überprüfen ihre eigenen Vorbedingungen, anstatt sie zu behaupten. Keine Änderung dessen, was durch die Aufbewahrung beibehalten oder entfernt wird. (#12783, Folgemaßnahme zu #12532)

Der omo doctor der eigenständigen omo-Binärdatei meldet erneut die Speicherlaufzeitgröße, wie die npm-Installation. Die Laufzeitgröße jeder Speicheridentität gegenüber ihrer Obergrenze und die Summe aller Identitäten werden von beiden Verteilungen gedruckt, sodass die Binär-/Npm-Doktorparität gilt (#12785). (#12783)

Alte binäre Laufzeiten werden sicher bereinigt, wenn zwei omo-Starts gleichzeitig starten. Ein Start löscht eine Laufzeit nicht mehr, ein anderer Start bereinigt noch, und eine Laufzeit, die bereits entfernt wurde, wird nicht als Fehler gemeldet. omo --version, --help und omo update beschneiden niemals. (#12770, Folgemaßnahme zu #12627)

Eine untergeordnete Aufgabe, deren Engine die festgelegte Modellkette nicht halten kann, wird nicht mehr gestartet. Wenn zuvor die Engine eines untergeordneten Prozesses ihre Kette nicht übernehmen konnte (eine ältere Engine, ein abgelehnter set_retry_fallback oder keine rechtzeitige Antwort) oder ein Task-Host retry_fallback_profile nicht ankündigte, wurde das untergeordnete Element immer noch dazu aufgefordert und lief mit den eigenen Fallback-Einstellungen der Engine, die Modelle außerhalb seiner Kette erreichen können. Der Start schlägt nun vor der ersten Eingabeaufforderung fehl und nennt jedes angegebene Modell und den Grund, und ein solcher Host wird als inkompatibel abgelehnt und nennt dieselben Modelle. (#12759) (#12761)

Ein Befehl in einer geschlossenen Sitzung auf einem anderen Gerät meldet jetzt denselben Fehler wie auf diesem Gerät. Es antwortete session_not_found remote und unknown_session lokal; beide antworten jetzt mit unknown_session. (#12755) (#12756)

omo übergibt seine Geräteschlüssel aus dem Speicher an den Gerätedienst, ohne dass der Anmeldeinformationsspeicher für die Weiterleitung gelesen wird. Eine neue Anmeldung (omo login, omo account adopt) löscht die Abmeldemarkierung und übergibt dann seine speicherinternen Schlüssel und sein Konto an einen laufenden Gerätedienst. Die Speichersynchronisierungssitzung übernimmt erneut die Anmeldeinformationen, über die sie bereits verfügt, wenn der Dienst kein übernommenes Gerät meldet. Jeder Abmeldepfad (Abmelden, Vergessen, eine Sitzung, die der Dienst beendet hat) weist den Dienst an, das Gerät zu vergessen. Der Start-Bootstrap liest die gespeicherten Anmeldeinformationen nicht mehr. device.adopt überträgt account nur an einen Gerätedienst mit 0.1.3 oder neuer, und der angeheftete Gerätedienst wird auf 0.1.3 (Design D PR 4) erhöht. (#12735) omo remote kann Sitzungen auf Ihren anderen Geräten öffnen, senden, das Modell wechseln, unterbrechen und schließen. omo remote open <device> [--project P] [--model M] startet dort eine Sitzung und druckt <device>/<session>; omo remote send <device>/<session> <text> druckt die Antwort aus, während sie einströmt, und kehrt zurück, wenn die Runde abgeschlossen ist (--steer steuert die laufende Runde, --follow-up stellt sich dahinter in die Warteschlange, --no-wait kehrt zurück, sobald die Sitzung die Nachricht angenommen hat); model, interrupt und close halten, was sie sagen. Jedes Verb ist derselbe Remote-Op, den die Thread-Tools des Agenten verwenden, und --json gibt das eingegebene Ergebnis aus. Eine Steuerung zu einer Sitzung auf einem anderen Gerät wird jetzt erreicht, wenn die Engine dieses Geräts ihre laufende Runde meldet, anstatt immer abgelehnt zu werden. (#12709, Teil von #12320)

Beim Erstellen oder Verzweigen eines Threads auf einem anderen Gerät muss nicht mehr auf einen separaten session.locate-Roundtrip gewartet werden: Die Erstellung fragt das Relay nach der neuen Sitzungs-ID in der open_session-Antwort und verwendet diese. Ein Relay-Daemon ohne diese Antwort (ein älterer Host oder ein älterer Dienst auf diesem Gerät) wird wie zuvor mit session.locate behandelt. (#12686)

omo update in der eigenständigen Binärdatei ersetzt jetzt das installierte omo. Früher wurde ein Ersetzungsbefehl für die Kopie unter ~/.omo/binary-runtime/<version>/ ausgegeben, der beim nächsten Start zurückgesetzt wurde, sodass das Update nie durchgeführt wurde. Ein Start entfernt dort auch alte Laufzeitversionen, wobei die vorherige für ein Rollback und jede noch laufende Version erhalten bleibt. (#12627, behebt #12626)

Das Laufzeitverzeichnis jeder Speicheridentität ist auf 2 GiB begrenzt, und omo doctor und /doctor zeigen an, wie viel es enthält. Nach der Aufbewahrung löscht der 12-Stunden-Speicherwartungsdurchlauf die ältesten zuerst, bis die Identität in memory.runtime.max_bytes passt (Standard 2 GiB, 0 für unbegrenzt, pro Agent überschreibbar unter memory.agents.<id>.runtime). Es entfernt zuerst gefaltete Reflexionsläufe, dann die Transkripte vollständig reflektierter Sitzungen, inaktive Sidecars und schließlich alte fehlgeschlagene Läufe über die neuesten zehn hinaus. Journale, die nie oder nur teilweise berücksichtigt wurden, werden standardmäßig beibehalten; memory.runtime.discard_unreflected_journals: true lässt sich auch von der Obergrenze vertreiben, und zwar nur, solange die Reflexion über die Identität gelingt. Live-Sessions, In-Flight-Runs und das Run-ID-Hochwasser werden nie berührt. omo doctor gibt die Laufzeitgröße jeder Identität und die Gesamtsumme aus und warnt, wenn eine Identität 80 % ihrer Obergrenze erreicht. /doctor fügt einen runtime-size-Check mit den größten Geschäften hinzu und welche Aufbewahrung noch kostenlos wäre. (#12538)

Der Speicher wächst nicht mehr ohne Bindung auf der Festplatte. Der Hintergrundspeicherwartungsdurchgang entfernt jetzt abgeschlossene Reflexionsläufe, vollständig reflektierte Transkripte, Rückruf-Sidecars und Legacy-Speicher über konfigurierbare Fenster (memory.runtime.retention_days 7, completions_days 30) hinaus in zeitlich begrenzten Slices, die dort fortgesetzt werden, wo sie aufgehört haben. Die Reflexion der Transkripteingabe wird nie in den Speicher übernommen und bleibt erhalten, es sei denn, Sie aktivieren discard_unreflected_journals (wird dann nach abandoned_journal_days, 14 entfernt, nur solange die Reflexion für diesen Agenten funktioniert). Nichts, was eine Live-Sitzung besitzt, keine gesperrte oder unvollendete Arbeit und keine Run-ID-Reflexion, die noch benötigt wird, wird berührt. (#12532)

Eine Reflexionssperre, die von einem Lauf zurückgeblieben ist, dessen Prozesse abgebrochen sind (Launcher vor Beginn des Laufs beendet, Supervisor und Kind ohne Ergebnis verschwunden, ein unleserliches Laufbuch oder ein zerrissener active.lock), wird jetzt beim Sitzungsstart, in der nächsten Runde und durch den neuen omo doctor --fix (--dry-run zur Vorschau, /doctor --fix in einer Sitzung) freigegeben, anstatt jede spätere Reflexion in der Warteschlange zu halten; omo doctor --fix fordert auch Laufzeitsperren zurück, deren Besitzer verschwunden ist. (#12517)

oh-my-openagent v5.1.65

A message an agent sends to a session on another device now says who sent it. It used to arrive there as plain text, indistinguishable from that session's own user. It now carries the same sender line and authority notice as a message between sessions on one device (the sending session, its workspace and project, and the device it came from), and a leading / in it no longer runs a command or expands a prompt template on the receiving side. omo remote send from a terminal is unchanged. (#12858, part of #12852)

Memory retention no longer evaluates its completion-record guard twice per record. The completion sweep now reads the guard once and keeps or removes the record on that single answer, and the retention tests check their own preconditions instead of asserting them away. No change to what retention keeps or removes. (#12783, follow-up to #12532)

The standalone omo binary's omo doctor reports memory runtime size again, like the npm install. Each memory identity's runtime size against its cap and the total across identities are printed by both distributions, so binary/npm doctor parity holds (#12785). (#12783)

Old binary runtimes are pruned safely when two omo launches start at once. A launch no longer deletes a runtime another launch is still pruning, and a runtime that launch already removed is not reported as a failure. omo --version, --help and omo update never prune. (#12770, follow-up to #12627)

A task child whose engine cannot hold its designated model chain is no longer started. Before, when a process child's engine could not take its chain (an older engine, a refused set_retry_fallback, or no answer in time) or a task host did not advertise retry_fallback_profile, the child was still prompted and ran on the engine's own fallback settings, which can reach models outside its chain. The start now fails before the first prompt and names every designated model and the reason, and such a host is refused as incompatible, naming the same models. (#12759) (#12761)

A command on a closed session on another device now reports the same error as on this device. It answered session_not_found remotely and unknown_session locally; both now answer unknown_session. (#12755) (#12756)

omo hands its device keys to the device service from memory, with no credential store read for relay. A fresh sign-in (omo login, omo account adopt) deletes the signed-out marker and then hands its in-memory keys and account to a running device service. The memory sync session re-adopts from the credential it already holds when the service reports no adopted device. Every sign-out path (logout, forget, a session the service ended) tells the service to forget the device. The start-up bootstrap no longer reads the stored credential. device.adopt carries account only to a device service at 0.1.3 or newer, and the pinned device service is raised to 0.1.3 (design D PR 4). (#12735)

omo remote can open, send, switch model, interrupt and close sessions on your other devices. omo remote open <device> [--project P] [--model M] starts a session there and prints <device>/<session>; omo remote send <device>/<session> <text> prints the answer as it streams in and returns when the turn settles (--steer steers the running turn, --follow-up queues behind it, --no-wait returns once the session took the message); model, interrupt and close do what they say. Each verb is the same remote op the agent's thread tools use, and --json prints its typed result. A steer to a session on another device now reaches it when that device's engine reports its running turn, instead of always being refused. (#12709, part of #12320)

Creating or forking a thread on another device no longer waits for a separate session.locate round trip: the create asks the relay for the new session's id on the open_session reply and uses it. A relay daemon without that answer (an older host, or an older service on this device) is handled as before, with session.locate. (#12686)

omo update on the standalone binary now replaces the installed omo. It used to print a replace command for the copy under ~/.omo/binary-runtime/<version>/, which the next launch put back, so the update never took. A launch also removes old runtime versions there, keeping the previous one for a rollback and any version still running. (#12627, fixes #12626)

Each memory identity's runtime directory is capped at 2 GiB, and omo doctor and /doctor show how much it holds. After retention, the 12-hour memory maintenance pass evicts oldest-first until the identity fits memory.runtime.max_bytes (default 2 GiB, 0 for unbounded, per-agent overridable under memory.agents.<id>.runtime). It removes folded reflection runs first, then the transcripts of fully reflected sessions, idle sidecars, and finally old failed runs beyond the newest ten. Journals that were never or only partly reflected are kept by default; memory.runtime.discard_unreflected_journals: true lets the cap evict them too, and only while reflection is succeeding on the identity. Live sessions, in-flight runs and the run-id high water are never touched. omo doctor prints each identity's runtime size and the total, and warns when an identity reaches 80 % of its cap. /doctor adds a runtime-size check with the largest stores and what retention would still free. (#12538)

Memory no longer grows without bound on disk. The background memory maintenance pass now removes finished reflection runs, fully reflected transcripts, recall sidecars and legacy stores past configurable windows (memory.runtime.retention_days 7, completions_days 30), in time-boxed slices that resume where they stopped. Transcript input reflection never folded into memory is kept unless you turn on discard_unreflected_journals (then removed after abandoned_journal_days, 14, only while reflection works for that agent). Nothing a live session owns, no locked or unfinished work and no run id reflection still needs is touched. (#12532)

A reflection lock left behind by a run whose processes died (launcher killed before the run started, supervisor and child gone with no outcome, an unreadable run ledger, or a torn active.lock) is now released at session start, on the next turn, and by the new omo doctor --fix (--dry-run to preview, /doctor --fix in a session), instead of keeping every later reflection queued; omo doctor --fix also reclaims runtime locks whose owner is gone. (#12517)

The doctor now reports outdated-extension and tells the user to update the extension and delete the saved groups. (#12663)

A moved note's links follow it, and the moved note's own relative links keep pointing at their targets. A note the run archived, meaning its ARCHIVE.md entry names the file (its path, or its file name when no other note shares it), is linked as [[ARCHIVE.md|<old path> (archived)]]. Links to any other removed note, such as one the user asked to forget, become plain text. A targeted /dream --to <doc> that removes its own target is no longer refused because of these link updates. Facts extraction also no longer writes into a month ledger path that was archived or deleted: that month's new facts go to notes/facts/<month>-2.md (then -3, ...), so an old link can never start pointing at unrelated new content. (#12642) (#12645)
  • Runtime fallback keeps compaction retries separate from the primary model chain and preserves substantive retry prompts. Compaction watchdogs defer within a bounded budget, exhausted native retry signals do not trigger an abort, and stuck-session watchdogs still return control when no replacement can be dispatched. Thanks @mradwankhalil. (#11907, fixes #9786)
  • Background tasks let runtime fallback decide who recovers a session error before starting a replacement or finalizing the task. Exhausted and refused retries release recovery ownership, model-less retry errors can finish the task, and a slow decision never starts a competing replacement. (#9683, #11907)
  • Runtime fallback keeps its place in the fallback chain when its own abort echoes back as a stop or idle event, and no longer mistakes its own retry for a manual model change. A failing fallback now moves on to the next model instead of going back to the model that just failed. (#11901, fixes #6751)
  • Runtime fallback: a session timeout whose fallback dispatch is rejected now uses up the attempt, stops at max_fallback_attempts, and ends with an abort the caller sees instead of re-arming the timer forever. (#11898, fixes #6637)
  • First-prompt refusal tests now await launch settlement when the bounded start report arrives first, preserving both untyped and non-credential refusal diagnostics without depending on subprocess startup speed (#11732). (#11852)
