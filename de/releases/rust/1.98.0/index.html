rust 1.98.0

<a id="1.98.0-Language"></a>

Sprache

  • Verkürzung der Lebensdauer von &mut zulassen, wenn die Größenänderung aufgehoben wird, auch in einer invarianten Position. Beispielsweise können Sie jetzt eine Cell<&'long mut i32> in eine Cell<&'short mut dyn Send> umwandeln. Solche Verkürzungen waren bereits zuvor beim Umwandeln eines &mut in einen & oder beim Umwandeln eines & in einen & zulässig.
  • Standardmäßig verweigernden invalid_runtime_symbol_definitions-Lint und standardmäßigen Warn-suspicious_runtime_symbol_definitions-Lint hinzufügen – Die Lints zielen derzeit speziell auf core-Laufzeitsymbole wie memcmp, memset, strlen usw. ab und sollen in den nächsten Versionen erweitert werden. – Fügen Sie den standardmäßigen c_void_returns-Lint hinzu, um core::ffi::c_void als Rückgabetyp zu prüfen <a id="1.98.0-Platform-Support"></a>

  • powerpc64-unknown-linux-gnuelfv2 als Tier 3 hinzufügen
  • aarch64-unknown-linux-pauthtest als Tier-3-Ziel hinzufügen
  • thumbv7a-none-eabi auf Stufe 2 befördern
  • thumbv7a-none-eabihf auf Stufe 2 befördern
  • thumbv7r-none-eabi auf Stufe 2 befördern

  • thumbv8r-none-eabihf auf Stufe 2 befördern Weitere Informationen zur abgestuften Plattformunterstützung von Rust finden Sie auf der [Plattform-Support-Seite] (https://doc.rust-lang.org/rustc/platform-support.html) von Rust. <a id="1.98.0-Libraries"></a>

Kompatibilitätshinweise

  • Bei vollständiger Eliminierung können die Lebensdauergrenzen von Merkmalsobjekttypen jetzt anders aufgelöst werden oder in sehr spezifischen Nischenszenarien sogar abgelehnt werden
  • Fehler in mehreren Fällen mehrdeutiger Importe – Ändern Sie die Destruktorimplementierung für Thread-Locals unter Windows, um Fiber Local Storage (FLS) zu verwenden
  • Einige Fälle des ambiguous_glob_imports-Lints in einen harten Fehler umwandeln
  • Where-Grenzen der Form Type = Type und Type == Type sind syntaktisch nicht mehr zulässig – Stellen Sie sicher, dass Send/Sync für std::env::Vars{,Os} nicht implementiert ist
  • Behebung, dass Argumente in einigen Attributen nicht ordnungsgemäß abgelehnt wurden – repr(transparent) legt jetzt strenger fest, welche Felder ein „triviales“ Layout haben und daher ignoriert werden können: repr(C)-Typen, Typen mit privaten Feldern und #[non_exhaustive]-Typen gelten nicht mehr als „trivial“
  • Überprüfen Sie korrekt, ob Typen in transmute() die gleiche Größe haben, wenn einige repr-Attribute beteiligt sind.
  • Beim Drucken von Zeichenfolgen und Zeichen werden mehr Zeichen maskiert
  • Schnellpfad für derive(PartialOrd) beim Ableiten von Ord implementieren Dies kann in der Praxis zu Fehlern bei Kisten führen, bei denen die PartialOrd- und Ord-Implementierungen eines Typs nicht miteinander übereinstimmten.
  • Temporären Bereich zu assert_eq und assert_ne hinzufügen – Es wurde eine Lücke in der Musterübereinstimmungsprüfung [strukturelle Gleichheit] (https://doc.rust-lang.org/reference/patterns.html#constant-patterns) geschlossen, wodurch Fälle verhindert wurden, in denen eine Übereinstimmung einer Konstante zulässig wäre, obwohl eine manuell geschriebene PartialEq-Implementierung nicht zutrifft, wenn auch eine derive(PartialEq)-Implementierung für diesen Typ vorhanden ist.
  • Auf Emscripten wird die WASM-Ausnahmebehandlungs-ABI jetzt bedingungslos verwendet Das -Zemscripten-wasm-eh=false-Flag zum Zurückschalten auf JS-Ausnahmen wurde entfernt. – Der UNSAFE_CODE-Lint wird jetzt konsistent für alle unsicheren Attribute ausgegeben
  • Solaris: File::lock-Implementierung entfernen, sie hat die falsche Semantik (stattdessen „nicht unterstützt“ zurückgeben) – Windows-GNU-Ziele geben jetzt Baseline-Tools-Versionen an
  • rustfmt erkennt jetzt Moduldateien, die in cfg_select! definiert sind Dies kann dazu führen, dass mehr Code formatiert wird, der zuvor ignoriert wurde.

rust 1.98.0

<a id="1.98.0-Language"></a>

Language

  • Allow shortening lifetime of &mut when unsize-coercing, even in an invariant position. For example, you can now coerce a Cell<&'long mut i32> to a Cell<&'short mut dyn Send>. Such shortenings were already previously allowed when coercing a &mut to a &, or coercing a & to a &.
  • Add deny-by-default invalid_runtime_symbol_definitions lint and warn-by-default suspicious_runtime_symbol_definitions lint
    • The lints currently specifically targets core runtime symbols like memcmp, memset, strlen, ... and is planned to be expanded in the next few releases.
  • Add warn-by-default c_void_returns lint to check core::ffi::c_void as a return type

<a id="1.98.0-Platform-Support"></a>

Platform Support

  • Add powerpc64-unknown-linux-gnuelfv2 as Tier 3
  • Add aarch64-unknown-linux-pauthtest as Tier 3 target
  • Promote thumbv7a-none-eabi to Tier 2
  • Promote thumbv7a-none-eabihf to Tier 2
  • Promote thumbv7r-none-eabi to Tier 2
  • Promote thumbv7r-none-eabihf to Tier 2
  • Promote thumbv8r-none-eabihf to Tier 2

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.98.0-Libraries"></a>

Libraries

  • Change Location<'_> lifetime to 'static in Panic[Hook]Info
  • Document panic in RangeInclusive::from(legacy::RangeInclusive)
  • Document that ManuallyDrop's Box interaction has been fixed
  • Stabilize LoongArch CRC Intrinsics
  • The derive macro is available at {core,std}::derive. This was previously unintentionally stabilized in 1.96, but is now explicitly accepted as a stabilized API.
    • Please note that the MSRV for {core,std}::derive will be 1.96, and not 1.98.

<a id="1.98.0-Compatibility-Notes"></a>

Compatibility Notes

  • If fully elided, lifetime bounds of trait object types may now resolve differently or even get rejected in very specific niche scenarios
  • Error in more cases of ambiguous imports
  • Switch the destructors implementation for thread locals on Windows to use Fiber Local Storage (FLS)
  • Convert some cases of the ambiguous_glob_imports lint into a hard error
  • Where-bounds of the form Type = Type and Type == Type are no longer syntactically allowed
  • Ensure Send/Sync is not implemented for std::env::Vars{,Os}
  • Fix that in some attributes, arguments were not properly rejected
  • repr(transparent) is now more strict about which fields have "trivial" layout and hence can be ignored: repr(C) types, types with private fields, and #[non_exhaustive] types are no longer considered "trivial"
  • Correctly check whether types have equal size in transmute() when some repr attributes are involved.
  • More characters are escaped when printing strings and chars
  • Implement fast path for derive(PartialOrd) when deriving Ord This can break crates in practice where a type's PartialOrd and Ord impls were inconsistent with each other.
  • Add temporary scope to assert_eq and assert_ne
  • Closed a hole in the pattern matching structural equality check, preventing cases where a match of a constant would be allowed, despite disagreeing with a manually written PartialEq implementation, when a derive(PartialEq) implementation for that type also exists.
  • On Emscripten the WASM exception handling ABI is now unconditionally used The -Zemscripten-wasm-eh=false flag to switch back to JS exceptions has been removed.
  • The UNSAFE_CODE lint is now consistently emitted for all unsafe attributes
  • Solaris: remove File::lock implementation, it has the wrong semantics (return "unsupported" instead)
  • Windows-gnu targets now specify baseline tools versions
  • rustfmt now discovers module files that are defined in cfg_select! This may cause more code to be formatted which was previously ignored.
