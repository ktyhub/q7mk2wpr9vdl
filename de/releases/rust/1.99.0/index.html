rust 1.99.0

rust 1.99.0

<a id="1.99.0-Language"></a>

Sprache

– Standardmäßig zulässiger raw_borrows_via_references-Lint hinzufügen, der nach Referenzen sucht, die sofort in Rohleihen zerfallen – Erweitern Sie den unconditional_panic-Lint auf Funktionsaufrufe, die in Panik geraten, wenn die Block-/Fenstergröße Null ist

  • C-variadische Funktionsdefinitionen stabilisieren
  • Stabilisierung der Fähigkeit, #[unsafe(naked)]-Funktionen zum Definieren C-variadischer Funktionen zu verwenden (#![feature(c_variadic_naked_functions)]).
  • Trait-Methoden werden jetzt auf einen angepassten Never-Typ aufgelöst (erzeugt ein FCW)
  • Von Inferenzvariablen zu Merkmalsobjekten erzwingen, wenn die Inferenzvariable über Subtypisierung mit einem Typ verknüpft ist, der bekanntermaßen Sized ist
  • #[my_macro] mod foo; stabilisieren. Dies ermöglicht umrissene Module (mod foo;) an einer beliebigen Stelle im Hauptteil eines benutzerdefinierten Attributs oder eines Ableitungsmakros.
  • Die overflowing_literals-Flusen durch wiederholte Negation beheben. Beispielsweise wird jetzt kein Flusen mehr auf --128_i8 ausgeführt, der bereits vom Flusen arithmetic_overflow erkannt wird.
  • POSIX-Symbole zu den Lints invalid_runtime_symbol_definitions und suspicious_runtime_symbol_definitions hinzufügen – Lint nicht verwendete #[path]-Attribute auf Inline-Modulen
  • unreachable_cfg_select_predicates-Lint als Teil der unused-Lint-Gruppe aktivieren
  • Übergabe von 128-Bit-Ganzzahlen über Vektorregister mit asm! auf x86 stabilisieren – Dokumentieren Sie ausdrücklich, dass einige Zuweisungen an Ort und Stelle wachsen dürfen (aber keine verkleinert werden dürfen)
  • Wir garantieren, dass auf den Inhalt eines UnsafeCell zugegriffen werden kann, ohne über get zu gehen
    • Der invalid_reference_casting-Flusen wurde entsprechend angepasst – Konto für global aktivierte Zielfunktionen in global_asm! – Warnung, wenn bei einem Makroaufruf ein ungültiges doc-Attribut verwendet wird <a id="1.99.0-Compiler"></a>

Compiler

  • -Ctarget-cpu in einen Zielmodifikator für AVR, AMDGCN und NVPTX umwandeln
  • static_position_independent_executables auf allen GNU-Zielen aktivieren – Bei der Bereitstellung eines Vorschlags zu einer fehlenden Methode bevorzugt rustc jetzt einen genau passenden Namen aus einem Dokument-Alias-Attribut gegenüber einer Ähnlichkeitssuche aus anderen Methodennamen. Wenn Ihre neuen Benutzer manchmal eine Methode unter einem anderen Namen erwarten, hilft ihnen das Hinzufügen eines Dokumentaliases nun dabei, diese über rustc-Vorschläge zu finden, zusätzlich dazu, dass sie sie über die rustdoc-Suche finden: Bevorzugen Sie beim Vorschlagen von Methodennamen exakte Dokumentaliasnamen gegenüber ähnlichen Namen <a id="1.99.0-Platform-Support"></a>

Plattformunterstützung

  • riscv64-unknown-linux-musl mit Host-Tools auf Tier 2 hochstufen Weitere Informationen zur abgestuften Plattformunterstützung von Rust finden Sie auf der Plattform-Support-Seite von Rust. <a id="1.99.0-Libraries"></a>

Bibliotheken

– Die Iteration auf RangeInclusive (a..=b-Bereiche) ist jetzt [unter bestimmten Umständen besser optimiert] (https://github.com/rust-lang/rust/pull/155114). Als Nebeneffekt hat sich das Verhalten der bereits ausgeschöpften RangeInclusive-Werte (als Iterator) geändert. Beispielsweise können die Rückgabewerte von start() und end() für solche Bereiche unterschiedliche Werte zurückgeben, und die Verwendung solcher Bereiche als Slice-Indizes kann zu unterschiedlichem Verhalten führen. Es wurde nicht garantiert, dass diese Verhaltensweisen stabil sind, daher gelten diese Änderungen nicht als Breaking Changes.

  • transmute_copy entspannen, um ?Sized-Typen zu akzeptieren – transmute_copy aktualisieren, um eine nicht abwickelnde Panik zu verwenden
  • U+FF9E und U+FF9F in escape_debug_ext nicht entkommen
  • core::fmt::NumBuffer in alloc (und std) erneut exportieren <a id="1.99.0-Stabilized-APIs"></a>

Stabilisierte APIs

  • IntoIterator für Box<[T; N]>
  • IntoIterator für &Box<[T; N]>
  • IntoIterator für &mut Box<[T; N]>
  • VecDeque::retain_back
  • core::ffi::VaList
  • Box::into_non_null
  • Box::from_non_null
  • Vec::into_parts
  • Vec::from_parts
  • core::mem::size_of_val_raw
  • core::mem::align_of_val_raw
  • core::alloc::Layout::for_value_raw
  • String::from_utf8_lossy_owned
  • string::FromUtf8Error::into_utf8_lossy
  • FusedIterator for StepBy<I>
  • std::fs::set_times
  • std::fs::set_times_nofollow
  • <LocalKey<Cell<T>>>::update <a id="1.99.0-Cargo"></a>

Fracht

  • Fügen Sie ein neues integriertes Profil debug hinzu. Dies ist eine Vorbereitung für die Umstellung des dev-Profils weg vom Debuggen, um einen vernünftigeren Standard für schnellere Entwicklungsiterationen bereitzustellen. Derzeit gibt es keinen Unterschied zwischen den Profilen dev und debug. Dokumente #17214 – Workspace-Mitglieder der Edition 2024 oder höher können jetzt das default-features-Feld einer geerbten Workspace-Abhängigkeit überschreiben. Beispielsweise deaktiviert serde = { workspace = true, default-features = false } jetzt Standardfunktionen, selbst wenn die Arbeitsbereichsdefinition sie aktiviert. In früheren Ausgaben wird default-features = false mit einer Warnung ignoriert. (RFC 3945) #17126 Siehe auch die vollständige Ladung changelog <a id="1.99.0-Rustdoc"></a>

Rustdoc

  • Neuen unused_footnote_definition rustdoc lint hinzufügen
  • Eine intelligentere Filterung von Trait-Impls führt zu Leistungsverbesserungen von durchschnittlich 20 % und bis zu 40 % bei einigen realen Crates. (1, 2, 3, 4, 5) <a id="1.99.0-Compatibility-Notes"></a>

Kompatibilitätshinweise

– Die veralteten integrierten Module vollständig verwerfen. Beispielsweise sollte stattdessen über i32::MAX auf std::i32::MAX zugegriffen werden.

  • Upgrade von no_mangle_generic_items auf harten Fehler
  • Beim Pin::new_unchecked wurden die Sicherheitsinvarianten leicht geändert
  • Bewerben Sie keine Verweise auf externe Statik
  • Stellen Sie sicher, dass die abgeleiteten Typen der let-Mustertypprüfung durchgeführt werden
  • hermit/fs: unsupported() statt from_raw_os_error(22) zurückgeben
  • Es wurde ein Fehler behoben, bei dem #[repr(simd)] versehentlich bei Makroaufrufen auf dem stabilen Rust zugelassen wurde
  • Const-eval abbrechen, wenn der Typ des erzeugten Werts Generika enthält – Attribute, die auf nichts anwendbar sind, stellen jetzt einen Fehler in Codeblöcken in Dokumentkommentaren dar
  • Box::leak: Sagen Sie den Leuten, sie sollen die Enthüllung vermeiden
  • PowerPC-Inline-ASM: Skalar-Floats behoben, die sich bei Little Endian in der falschen Vektorspur befinden
  • doc(cfg()) beim Filtern von Doctests nicht berücksichtigen
  • Anonyme Lebensdauern in den Typen der zugehörigen Konstanten ableiten als 'static – Makros, die zu einem Semikolon erweitert werden, erzeugen jetzt eine Warnmeldung (semicolon_in_expressions_from_non_local_macros), selbst wenn das Makro aus einer anderen Kiste stammt. Bisher wurden solche Warnungen nur für Makros aus derselben Kiste angezeigt, um zu vermeiden, dass Warnungen angezeigt werden, die nicht lokal behoben werden können. Dies verdeckte jedoch Probleme, da Integrationstests aus der Kiste, die das Makro bereitstellt, als separate Kiste kompiliert wurden, sodass Tests dieses Problem oft nicht aufdeckten. Wenn Sie auf einen solchen Flusen stoßen, melden Sie ihn bitte unbedingt der Kiste, die das Makro bereitstellt, damit diese das Problem beheben kann. Bringen Sie es nicht einfach in Ihrer eigenen Kiste zum Schweigen.
    • semicolon_in_expressions_from_macros: Flusen auch auf nicht-lokalen Makros
    • Nicht-lokales semicolon_in_expressions_from_macros in einen separaten Lint aufteilen – In Cargo ist die inkrementelle Kompilierung jetzt standardmäßig deaktiviert, wenn sie in CI ausgeführt wird. CI wird über die Umgebungsvariable CI erkannt. #17220 – Die Rust-Referenz empfiehlt nicht mehr, ein einzelnes Muster zu verwenden, um eine Union zusammen mit einem anderen Wert abzugleichen, z. B. in einer manuell geschriebenen getaggten Union. Dies lag daran, dass festgestellt wurde, dass ein solcher Code unter bestimmten Umständen dazu führen würde, dass der Compiler den Inhalt der Union liest, bevor er prüft, ob der Rest des Prüfers mit dem Rest des Musters übereinstimmt. Dies kann zu undefiniertem Verhalten im Code führen, ähnlich dem, was in der Referenz zuvor empfohlen wurde. <a id="1.99.0-Internal-Changes"></a>

Interne Änderungen

Diese Änderungen wirken sich nicht auf öffentliche Schnittstellen von Rust aus, stellen jedoch erhebliche Verbesserungen der Leistung oder der internen Funktionen von rustc und verwandten Tools dar.

  • Update auf LLVM 23

Englisches Original / English original

rust 1.99.0

<a id="1.99.0-Language"></a>

Language

  • Add allow-by-default raw_borrows_via_references lint that checks for references that decay immediately into raw borrows
  • Extend unconditional_panic lint to function calls that panic when the chunks/windows size is zero
  • Stabilize C-variadic function definitions
  • Stabilize the ability to use #[unsafe(naked)] functions to define C-variadic functions (#![feature(c_variadic_naked_functions)]).
  • Trait methods are now resolved on an adjusted never type (producing a FCW)
  • Coerce from inference variables to trait objects if the inference variable is related via subtyping to a type that is known to be Sized
  • Stabilize #[my_macro] mod foo;. This allows outlined modules (mod foo;) anywhere in the body of a custom attribute or derive macro.
  • Fix the overflowing_literals lint with repeated negation. For instance, it will now no longer lint on --128_i8, which is already detected by the arithmetic_overflow lint.
  • Add POSIX symbols to the invalid_runtime_symbol_definitions and suspicious_runtime_symbol_definitions lints
  • Lint unused #[path] attributes on inline modules
  • Enable unreachable_cfg_select_predicates lint as part of unused lint group
  • Stabilize passing 128-bit integers via vector registers with asm! on x86
  • Explicitly document that some allocations are allowed to grow in-place (but none are allowed to shrink)
  • We now guarantee that the contents of an UnsafeCell can be accessed without going through get
    • The invalid_reference_casting lint was adjusted accordingly
  • Account for globally enabled target features in global_asm!
  • Warn if an invalid doc attribute is used on a macro invocation

<a id="1.99.0-Compiler"></a>

Compiler

  • Convert -Ctarget-cpu into a target-modifier for AVR, AMDGCN and NVPTX
  • Enable static_position_independent_executables on all gnu targets
  • When providing a suggestion about a missing method, rustc now prefers an exactly matching name from a doc alias attribute over a similarity search from other method names. If your new users sometimes expect a method under a different name, adding a doc alias will now help them find it via rustc suggestions, in addition to helping them find it via rustdoc search: When suggesting method names, prefer exact doc aliases over similar names

<a id="1.99.0-Platform-Support"></a>

Platform Support

  • Promote riscv64-unknown-linux-musl to Tier 2 with host tools

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.99.0-Libraries"></a>

Libraries

  • Iteration on RangeInclusive (a..=b ranges) is now optimized better in some circumstances. As a side effect of this, the behavior of RangeInclusive values that has already been exhausted (as an iterator) has changed. For example, the return values of start() and end() on such ranges may return different values, and using such ranges as slice indexes may have different behavior. These behaviors were not guaranteed to be stable, so these changes are considered to not be breaking changes.
  • Relax transmute_copy to accept ?Sized types
  • Update transmute_copy to use a non-unwinding panic
  • Don't escape U+FF9E and U+FF9F in escape_debug_ext
  • Re-export core::fmt::NumBuffer in alloc (and std)

<a id="1.99.0-Stabilized-APIs"></a>

Stabilized APIs

  • IntoIterator for Box<[T; N]>
  • IntoIterator for &Box<[T; N]>
  • IntoIterator for &mut Box<[T; N]>
  • VecDeque::retain_back
  • core::ffi::VaList
  • Box::into_non_null
  • Box::from_non_null
  • Vec::into_parts
  • Vec::from_parts
  • core::mem::size_of_val_raw
  • core::mem::align_of_val_raw
  • core::alloc::Layout::for_value_raw
  • String::from_utf8_lossy_owned
  • string::FromUtf8Error::into_utf8_lossy
  • FusedIterator for StepBy<I>
  • std::fs::set_times
  • std::fs::set_times_nofollow
  • <LocalKey<Cell<T>>>::update

<a id="1.99.0-Cargo"></a>

Cargo

  • Add a new built-in profile debug. This is a preparation for transitioning the dev profile away from debugging to give a saner default for faster development iterations. Currently there is no difference between dev and debug profiles. docs #17214
  • Workspace members on edition 2024 or later can now override an inherited workspace dependency's default-features field. For example, serde = { workspace = true, default-features = false } now turns off default features even when the workspace definition enables them. On earlier editions, default-features = false is ignored with a warning. (RFC 3945) #17126

See also the full Cargo changelog

<a id="1.99.0-Rustdoc"></a>

Rustdoc

  • Add new unused_footnote_definition rustdoc lint
  • Smarter filtering of trait impls yields performance improvements of 20% on average and up to 40% on some real-world crates. (1, 2, 3, 4, 5)

<a id="1.99.0-Compatibility-Notes"></a>

Compatibility Notes

  • Fully deprecate the legacy integral modules. For example, std::i32::MAX should be accessed via i32::MAX instead.
  • Upgrade no_mangle_generic_items into hard error
  • The Pin::new_unchecked has had its safety invariants changed slightly
  • Do not promote references to extern statics
  • Ensure that the inferred types of let patterns typecheck
  • hermit/fs: Return unsupported() instead of from_raw_os_error(22)
  • Fixed a bug where #[repr(simd)] was accidentally allowed on macro invocations on stable Rust
  • Abort const-eval when there are generics in the type of the value being produced
  • Attributes not applying to anything are now an error in code blocks in doc comments
  • Box::leak: tell people to avoid unleaking
  • PowerPC inline ASM: Fix scalar floats being in the wrong vector lane on little endian
  • Do not take doc(cfg()) into account when filtering doctests
  • Infer anonymous lifetimes in the types of associated consts as 'static
  • Macros that expand to a semicolon now produce a warning lint (semicolon_in_expressions_from_non_local_macros) even when the macro comes from another crate. Previously, such warnings only appeared for macros from the same crate, to avoid showing warnings that can't be fixed locally; however, this masked problems, as integration tests from the crate providing the macro get compiled as a separate crate, so tests often wouldn't reveal this issue. If you encounter a lint like this, please make sure to report it to the crate providing the macro so they can fix it; don't just silence it in your own crate.
    • semicolon_in_expressions_from_macros: Lint on non-local macros too
    • Split non-local semicolon_in_expressions_from_macros into a separate lint
  • In Cargo, incremental compilation is now disabled by default when running in CI. CI is detected via the CI environment variable. #17220
  • The Rust Reference no longer recommends using a single pattern to match a union alongside another value, such as in a manually-written tagged union. This was because it was found that such code would, in some circumstances, result in the compiler reading the contents of the union before checking if the rest of the scrutinee matches the rest of the pattern. This can cause undefined behavior in code similar to what the reference previously recommended.

<a id="1.99.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.
