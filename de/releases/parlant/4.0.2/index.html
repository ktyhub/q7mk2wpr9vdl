Parlant v4.0.2

[4.0.2] – 05.11.2026

Hinzugefügt

  • Mit dem Chat-Widget kann der KI-Agent im Browser eines Besuchers mit Ihrem Agenten sprechen über WebMCP (document.modelContext; in Chrome heute hinter einer Flagge). Auf Auf jeder Seite, auf der es angezeigt wird, registriert das Widget ein mit beschriebenes ask_agent-Tool der Name des Agenten. Ein Anruf startet die Konversation des Widgets, wenn keine vorhanden ist doch als einer, den ein Agent für den Kunden hält (customer_represented_by_an_agent), Sendet die Frage über den Chat, sodass sie dort mit der Antwort angezeigt und geöffnet wird den Chat und antwortet dem Browser-Agenten, sobald die Runde beendet ist. Nachverfolgung Anrufe setzen das gleiche Gespräch fort. Die Botschaft trägt metadata.parlant_widget.asked_by = "customer_agent", also der Chat und dein Tools können den Agenten des Besuchers vom Besucher unterscheiden. In einem passiert nichts Browser ohne WebMCP; webmcp={false} schaltet es aus. ParlantTransports sendMessage akzeptiert ein optionales Metadatenargument und ensureSession ein Option für die Flagge.
  • Server(session_store=..., customer_store=...) akzeptiert einen s3://bucket URL zum Halten von Sitzungen und Kunden in Amazon S3. Geben Sie Parlant einen Eimer davon sein eigenes. Anmeldeinformationen stammen aus der AWS-Anmeldeinformationskette. ?region= hinzufügen oder, für S3-kompatiblen Speicher, ?endpoint=. Der Speicher muss unterstützen Bedingte Schreibvorgänge, die verhindern, dass gleichzeitige Server jeden einzelnen überschreiben andere Updates. Leere Sammlungen überleben Neustarts und eine fehlgeschlagene Migration Beim Schreiben bleiben die Originaldaten erhalten. Jede andere Abfrage als eine Suche nach ID, B. das Auflisten von Sitzungen, liest jedes Objekt in der Sammlung, also verwenden MongoDB, wenn Sie indizierte Abfragen im großen Maßstab benötigen.
  • Das Chat-Widget (parlant widget init) nimmt das Bild des Agenten in einem auf avatar Stütze: { type: "logo", src }, { type: "photo", src, live? } oder { type: "video", src?, poster?, live?, launcher? }. Ein Video-Avatar spielt a Kurze gedämpfte Schleife unter der Kopfzeile, scrollt einmal mit der Konversation weg Es startet und behält seine geöffnete Größe, wenn der Chat erweitert wird. Auf der geschlossenen Launcher, launcher schneidet es auf das Gesicht. Lassen Sie src weg, um das zu verwenden Widget-eigenes Video eines Agenten. live fügt den grünen Punkt auf den Videos hinzu Ecke ebenfalls rot, solange der Server nicht erreichbar ist. Verwenden Sie einen H.264 MP4-Speicher mit -movflags +faststart; iPhone Safari bleibt auf WebM hängen.

Geändert

  • Die dauerhaften Vorschläge des Chat-Widgets heben sich von den ersten ab: in der Hauptfarbe des Themas umrandet und mit Buchstaben auf dem Hintergrund des Chats versehen, anstelle der grauen Füllung.
  • Auf Telefonen und Tablets schließt das Chat-Widget einmal pro Woche die Bildschirmtastatur Die Nachricht wird gesendet, unabhängig davon, ob sie eingegeben oder aus den Vorschlägen ausgewählt wurde, also die Antwort ist nicht dahinter verborgen. – Beim LiteLLM-Anbieter werden Überprüfungsrouten jetzt standardmäßig verwendet gemini/gemini-3.8-flash statt gemini/gemini-3.6-flash, das Gleiche Modell, das der Gemini-Anbieter bereits für sie verwendet.
  • Der Agent des lead-gen-Gerüsts rät nicht mehr, wenn ein Besucher nachfragt Das Unternehmen, seine Produkte oder sein Projekt und sein Produktwissen haben keine Antwort. Es heißt, es sei eine tolle Frage, aber schwer richtig zu beantworten Chat, bietet an, sie mit dem Team zu verbinden, bittet um eine E-Mail oder ein Telefon Nummer und leitet die Frage mit request_team_follow_up weiter. Ohne Zusammenhang Fragen, Bestellfragen bestehender Kunden und Preise werden behandelt vor. Um dies zu ermöglichen, akzeptiert record_lead jetzt einen Vorsprung mit nur einem Ziel und ein Kontakt: buying_for und role sind optional und unbekannt punktet nichts.
  • parlant dashboard project confirm schließt ein lokales oder selbstgehostetes Projekt ab selbst wenn der Server bereits Sitzungen hält, beispielsweise weil er den Agenten ausprobiert hat. Es importiert sie zuerst in das Dashboard, wie es die Synchronisierung des Dashboards tut, und Schließt dann die Einrichtung ab, sodass das Projekt nicht mehr bei „Einrichtung abschließen“ bleibt. Ein Import, der länger als etwa 90 Sekunden dauert, wird mit abgebrochen SYNC_IN_PROGRESS; Führen Sie confirm erneut aus, um weiterhin auf denselben Import zu warten. Ein fehlgeschlagener Import stoppt mit SYNC_FAILED und seinem Grund.
  • parlant init --dashboard --json und parlant dashboard project create --json Für ein lokales oder selbstgehostetes Projekt listen Sie jetzt nextSteps auf und enden mit project confirm. Der gerüstierte AGENTS.md fordert die Programmierer auf, dies zu bestätigen das Projekt, sobald der Server verbunden ist.
  • Nachdem Sie ein verwaltetes Projekt erstellt haben, bei dessen Setup-Überprüfung festgestellt wurde, wie es ausgeführt werden kann, parlant dashboard project create zeigt nun auf parlant dashboard --project ID deploy: Die erste Live-Bereitstellung vervollständigt die einrichten. Zur Überprüfung der Einstellungen ist die Einrichtungsseite des Dashboards optional.

Veraltet

– Die Requisiten avatarUrl, avatarStyle und liveIndicator des Chat-Widgets, in zugunsten von avatar. Sie funktionieren immer noch, wenn avatar nicht eingestellt ist.

Behoben

  • Zwillinge-Argonen können gespeicherte Werkzeugaufrufe mit ihrem ursprünglichen signierten Gedanken wiedergeben Blockierungen, anstatt unnötigerweise auf den Nur-Ergebnis-Verlauf zurückzugreifen.
  • Beim Filtern von Sitzungen nach Labels werden jetzt vollständige und funktionsfähige Seiten zurückgegeben Fortsetzungscursor mit konsistenten Gesamtzahlen in beiden Sortierreihenfolgen. – Die MongoDB-Cursor-Paginierung behält jetzt $or-Filter auf späteren Seiten bei Gefilterte Einträge enthalten keine Datensätze mehr außerhalb des angeforderten Satzes.
  • Vorgefertigte Antworten behalten jetzt separate Suchvektoren für ihren Text und bei jedes Signal, so dass Signale im Relevanzindex nicht mehr kollidieren. Gilt, wenn Antworten erstellt oder aktualisiert werden; vorhandene Indizes nicht automatisch neu aufgebaut.
  • Auf dem iPhone wird die Seite nicht mehr vergrößert, wenn Sie das Nachrichtenfeld des Chat-Widgets fokussieren hinein, was den offenen Chat vom rechten Bildschirmrand verdrängte. Die Kiste Verwendet auf Touchscreens eine 16-Pixel-Schriftart, die Größe, unterhalb derer iOS zoomt. – Lokale und MCP-Tools akzeptieren jetzt durch Kommas getrennte Listenargumente ohne Klammern unter Beibehaltung von Anführungszeichen und leeren Listen.
  • Die neueste Nachricht des Chat-Widgets wird nicht mehr unter den Vorschlägen angezeigt Meldungsfeld, wenn etwas den Platz des Transkripts einnimmt, z. B. das Das Banner „Verbindung unterbrochen“ erscheint unmittelbar nach einem Versand. Das Transkript blieb nur unten angeheftet, als die Nachrichten zunahmen, nicht aber, als die Ansicht schrumpfte.
  • Ungültige Aktualisierungspläne für Kontextvariablen werden vor dem Speichern abgelehnt. Daher bleiben bei einer fehlgeschlagenen Zeitplanaktualisierung die vorhandenen Daten der Variablen intakt. – Eine Kundennachricht, die eintrifft, während der Agent noch daran arbeitet Die vorherige ersetzt jetzt wie vorgesehen diese Kurve, auch wenn der Motor drin war mitten in der Ablehnung eines Schritts: ein Tool-Aufruf oder eine Nachricht, die von a abgelehnt wurde Review-Hook, durch den Rezensenten oder durch die Moderation. Zuvor begann die Ablehnung erneut Er hat den Schritt ausgeführt und die ausstehende Stornierung verworfen, sodass der Agent seine Antwort beendet hat auf die erste Nachricht und beantwortete dann die zweite in einem separaten Zug. Kunden, die zwei Nachrichten kurz hintereinander senden, erhalten jetzt eine Antwort berücksichtigt beides.

Sicherheit

  • Erhöhen Sie die Mindestversion python-multipart auf 0.0.30 für beide UV-Geräte und Pip-Installationen, die die Installation von Versionen verhindern, die davon betroffen sind CVE-2026-53539.

[4.0.1] – 02.11.2026

Geändert

  • parlant init --scaffold lead-gen erstellt jetzt seinen Agenten mit preamble_config=p.PreambleConfiguration.encourage(). Vor seinem ersten Werkzeug Rufen Sie den Agenten an und sagen Sie eine kurze Zeile, z. B. „Lassen Sie mich das überprüfen“. Der Besucher muss nicht schweigend warten. Ohne sie waren die Präambeln nicht zu bewältigen: Was auch immer das Modell geschrieben hat, bevor ein Tool-Aufruf direkt durchgegangen ist.
  • Jedes Werkzeug in den Gerüsten lead-gen und retail-store verfügt jetzt über ein narration, z. B. „Überprüfen Sie, welche Tage frei sind“ oder „Verfolgen Sie Ihre Sendung". Im Chat wird es angezeigt, während das Tool ausgeführt wird, und nicht im generischen Format „Laufwerkzeuge“.

Behoben

– Mit dem Anthropic-Anbieter schlägt die Indizierung auf Claude Opus 4.7 und nicht mehr fehl später oder jedes Claude 5-Modell, einschließlich der Standardrouten (Sonnet 5.5 und Haiku 5.5). Parlant schickte einen temperature, den diese Modelle ablehnen „temperature ist für dieses Modell veraltet.“; es sendet jetzt nur noch eines an Claude 3-Modelle und Claude 4-Modelle bis 4.6, die es noch akzeptieren. – Eine Argumentationsbemühung auf einem Claude-Fable-Modell verwendet jetzt stattdessen adaptives Denken eines denkenden Budgets, das Fable ablehnt.

  • Ein Argumentationsversuch zu Claude Opus 4.5 schlägt nicht mehr fehl. Parlant hat es geschickt adaptives Denken, das es ablehnt („adaptives Denken wird nicht unterstützt“) dieses Modell"); Es bekommt jetzt ein Denkbudget, wie es Sonnet und Haiku 4.5 tun.

parlant v4.0.2

[4.0.2] - 2026-11-05

Added

  • The chat widget lets the AI agent in a visitor's browser talk to your agent over WebMCP (document.modelContext; in Chrome behind a flag today). On every page it's on, the widget registers an ask_agent tool described with the agent's name. A call starts the widget's conversation if there is none yet, as one an agent holds for the customer (customer_represented_by_an_agent), sends the question through the chat, so it shows there with the reply, opens the chat, and answers the browser agent once the turn has ended. Follow-up calls continue the same conversation. The message carries metadata.parlant_widget.asked_by = "customer_agent", so the chat and your tools can tell the visitor's agent from the visitor. Nothing happens in a browser without WebMCP; webmcp={false} turns it off. ParlantTransport's sendMessage takes an optional metadata argument and ensureSession an option for the flag.
  • Server(session_store=..., customer_store=...) accepts an s3://bucket URL to keep sessions and customers in Amazon S3. Give Parlant a bucket of its own. Credentials come from the AWS credential chain; add ?region= or, for S3-compatible storage, ?endpoint=. The storage must support conditional writes, which keep concurrent servers from overwriting each other's updates. Empty collections survive restarts, and a failed migration write leaves the original data in place. Any query other than a lookup by ID, such as listing sessions, reads every object in the collection, so use MongoDB if you need indexed queries at scale.
  • The chat widget (parlant widget init) takes the agent's picture in one avatar prop: { type: "logo", src }, { type: "photo", src, live? } or { type: "video", src?, poster?, live?, launcher? }. A video avatar plays a short muted loop under the header, scrolls away with the conversation once it starts, and keeps its opened size when the chat is expanded. On the closed launcher, launcher crops it onto the face. Leave out src to use the widget's own video of an agent. live adds the green dot, on the video's corner too, red while the server can't be reached. Use an H.264 MP4 saved with -movflags +faststart; iPhone Safari stalls on WebM.

Changed

  • The chat widget's persistent suggestions stand out from its opening ones: outlined and lettered in the theme's primary color on the chat's background, instead of the grey fill.
  • On phones and tablets, the chat widget closes the on-screen keyboard once a message is sent, whether typed or picked from the suggestions, so the reply isn't hidden behind it.
  • With the LiteLLM provider, review routes now default to gemini/gemini-3.8-flash instead of gemini/gemini-3.6-flash, the same model the Gemini provider already uses for them.
  • The lead-gen scaffold's agent no longer guesses when a visitor asks about the business, its products or their project and its product knowledge has no answer. It says it's a great question but hard to answer properly in the chat, offers to connect them with the team, asks for an email or phone number, and passes the question on with request_team_follow_up. Unrelated questions, existing customers' order questions and prices are handled as before. To make that possible, record_lead now accepts a lead with just a goal and a contact: buying_for and role are optional, and an unknown one scores nothing.
  • parlant dashboard project confirm finishes a local or self-hosted project even when its server already holds sessions, such as from trying the agent. It imports them into the dashboard first, as the dashboard's Sync does, and then completes the setup, so the project no longer stays at "Finish setup". An import that takes longer than about 90 seconds stops with SYNC_IN_PROGRESS; run confirm again to keep waiting for the same import. A failed import stops with SYNC_FAILED and its reason.
  • parlant init --dashboard --json and parlant dashboard project create --json for a local or self-hosted project now list nextSteps, ending with project confirm. The scaffolded AGENTS.md tells coding agents to confirm the project once its server is connected.
  • After creating a managed project whose setup check found how to run it, parlant dashboard project create now points to parlant dashboard --project ID deploy: the first live deploy completes the setup. The dashboard's setup page is optional for reviewing the settings.

Deprecated

  • The chat widget's avatarUrl, avatarStyle and liveIndicator props, in favor of avatar. They still work when avatar isn't set.

Fixed

  • Gemini Argon can replay saved tool calls with their original signed thought blocks instead of unnecessarily falling back to result-only history.
  • Filtering sessions by labels now returns complete pages and working continuation cursors, with consistent total counts in either sort order.
  • MongoDB cursor pagination now preserves $or filters on later pages, so filtered listings no longer include records outside the requested set.
  • Canned responses now retain separate search vectors for their text and every signal, so signals no longer collide in the relevance index. Applies when responses are created or updated; existing indexes are not rebuilt automatically.
  • On iPhone, focusing the chat widget's message box no longer zooms the page in, which pushed the open chat off the right edge of the screen. The box uses a 16px font on touch screens, the size below which iOS zooms.
  • Local and MCP tools now accept comma-separated list arguments without brackets while preserving quoted commas and empty lists.
  • The chat widget's latest message no longer slips under the suggestions and message box when something takes the transcript's space, such as the "Connection interrupted" banner appearing just after a send. The transcript stayed pinned to the bottom only as messages grew, not as its view shrank.
  • Invalid context-variable freshness schedules are rejected before saving, so a failed schedule update leaves the variable's existing data intact.
  • A customer message that arrives while the agent is still working on the previous one now replaces that turn, as intended, even when the engine was in the middle of rejecting a step: a tool call or message turned down by a review hook, by the reviewer, or by moderation. Before, the rejection restarted the step and dropped the pending cancellation, so the agent finished replying to the first message and then answered the second one in a separate turn. Customers who send two messages in quick succession now get one reply that takes both into account.

Security

  • Raise the minimum python-multipart version to 0.0.30 for both uv and pip installations, preventing installation of versions affected by CVE-2026-53539.

[4.0.1] - 2026-11-02

Changed

  • parlant init --scaffold lead-gen now creates its agent with preamble_config=p.PreambleConfiguration.encourage(). Before its first tool call the agent says one short line, such as "Let me check that", so the visitor isn't left waiting in silence. Without it, preambles were unmanaged: whatever the model wrote before a tool call went straight through.
  • Every tool in the lead-gen and retail-store scaffolds now has a narration, such as "Checking which days are free" or "Tracking your shipment". The chat shows it while the tool runs, instead of the generic "Running tools".

Fixed

  • With the Anthropic provider, indexing no longer fails on Claude Opus 4.7 and later or any Claude 5 model, including the default routes (Sonnet 5.5 and Haiku 5.5). Parlant sent a temperature, which those models reject with "temperature is deprecated for this model."; it now sends one only to Claude 3 models and Claude 4 models up to 4.6, which still accept it.
  • A reasoning effort on a Claude Fable model now uses adaptive thinking instead of a thinking budget, which Fable rejects.
  • A reasoning effort on Claude Opus 4.5 no longer fails. Parlant sent it adaptive thinking, which it rejects ("adaptive thinking is not supported on this model"); it now gets a thinking budget, as Sonnet and Haiku 4.5 do.
