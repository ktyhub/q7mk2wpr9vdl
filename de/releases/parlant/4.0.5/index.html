Parlant v4.0.5

[4.0.5] – 12.11.2026

Hinzugefügt

  • Gemini 4 Hydrogen funktioniert über den Gemini-Anbieter, einschließlich gestreamter Antworten, Tool-Aufrufe, gespeicherte Konversationswiedergabe und Token-Abrechnung. Wählen Sie es aus als gemini:gemini-4-hydrogen; bestehende Standardmodelle bleiben unverändert. – Das Chat-Widget zeigt Markdown-Tabellen in der Antwort eines Agenten als Tabellen an. Sie früher als Rohrlinien dargestellt. Spaltenausrichtung, Inline-Markdown in Zellen und entkommene Rohrarbeiten. Eine gestreamte Tabelle erscheint, sobald ihre Kopfzeile und ihr Teiler vorhanden sind Zeilen kommen an und werden Zelle für Zelle ausgefüllt. Ein breiter Tisch rollt seitwärts im Inneren die Nachricht, und die eigenen Tabellenstile Ihrer Site ändern sie nicht. Ihr Projekt behält die erstellte Kopie parlant widget init. Um dies aufzuheben, rennen Sie parlant widget init --force, das diese Kopie und alle von Ihnen vorgenommenen Änderungen ersetzt dazu gemacht.
  • Ereignisströme (sse=true) tragen jetzt in jedem Frame ein id und werden ab diesem Zeitpunkt fortgesetzt es. Ein client, der sich wieder mit Last-Event-ID verbindet, nimmt den Empfang nach dem Frame auf zuletzt gesehen, anstatt die Sitzung von Anfang an noch einmal abzuspielen. Streams fragen a Browser erneut verbinden, drei Sekunden warten (retry: 3000) und Leerlauf Stream sendet alle 15 Sekunden einen Keep-Alive-Kommentar, also kein Proxy mehr Schließt eine stille Verbindung, bevor wait_for_data abläuft. Wenn eine Anfrage trägt sowohl min_offset als auch Last-Event-ID, der letztere der beiden gewinnt: a Beim erneuten Verbinden von client ist in der Regel immer noch das ursprüngliche min_offset in der URL enthalten. und es zu würdigen, würde die Sitzung wiederholen. Die Verzögerung und das Keep-Alive Intervall kann mit PARLANT_SSE_RETRY_MS und eingestellt werden PARLANT_SSE_HEARTBEAT_SECONDS; 0 deaktiviert das Keep-Alive und 0 dafür Bei der Verzögerung wird die Zeile retry: weggelassen.
  • Gemini bedient Googles Gemini-Entscheidung 1 (gemini-decision-1), die antwortet viele Ja/Nein-, Auswahl- und Skalenfragen zu einem Gespräch in einem einzigen Gespräch Anfrage. Eine {"*": "gemini"}-Route verwendet es jetzt für das Regelranking am Bemühungen, Regeln in einem Stapel zu bewerten, wie OpenAI- und OpenRouter-Routen bereits mit ihren Entscheidungsmodellen tun. Benennen Sie es auf einer Route mit "matching.rank[capability=decision]": "gemini:gemini-decision-1". Es nutzt Ihr vorhandener GEMINI_API_KEY. Gemini gibt an, dass dafür keine Kosten anfallen, also fügen Sie a hinzu gemini-decision-1-Eintrag bis server.set_pricing(...) (Google listet $0.10 pro auf Millionen Input-Token und nichts für den Output), um einen Preis festzulegen.

Geändert

  • Gemini-Modelle zählen Token auf Ihrem Server, anstatt den Gemini API zu fragen, was pro Zählung etwa 300 ms dauerte. Ein Schritt nach einem Tool-Aufruf machte zwei solcher Anrufe nacheinander und Auswahl vorgefertigter Antworten, also Antworten nach einem Tool-Aufruf Starten Sie jetzt etwa 0.4–0,6 Sekunden früher. Counts verwenden den offenen Gemma 3-Tokenizer und liegen innerhalb von ein oder zwei Tokens von denen von Google. Das gemini-Extra wird jetzt installiert sentencepiece. Der Tokenizer wird einmal von raw.githubusercontent.com heruntergeladen. im Hintergrund, beim ersten Zählen. Bis es fertig ist, oder wenn Ihr Server GitHub kann nicht erreicht werden, Parlant zählt wie zuvor mit API und protokolliert eine Warnung sagen es.
  • Agenten wiederholen nicht mehr, was der Kunde gerade zuvor zu ihnen gesagt hat antwortet („Lead-Generierung für ein Logistik-Startup, also…“). Jetzt eine Reaktion reagiert auf die Bedeutung der Nachricht und darauf, wann der Kunde darauf antwortet Nach der eigenen Frage des Agenten geht der Agent direkt zum nächsten Schritt über. Die Eingabeaufforderung Nr Längere Verbote von namentlich genannten „macht Sinn“-Angaben.
  • Von parlant init erstellte Agenten lernen nicht mehr, die Worte des Besuchers zu wiederholen zurück. Die herzlichen Gastgeber und optimistischen Persönlichkeiten reagieren nun auf eine Botschaft bedeutet, und der herzliche Gastgeber geht direkt zum nächsten Schritt über, wenn der Besucher da ist Beantwortung seiner Frage. Bestehende Projekte behalten ihren eigenen Text; kopiere das neue Formulierung aus einem neuen parlant init, wenn Ihr Agent zustimmt.

Behoben

  • Auf verwalteten (Dashboard-gehosteten) Servern, session.metadata.get(), .set() und .delete(), session.update() und server.get_session() scheiterten mit „Sitzung nicht gefunden“ für Live-Gespräche, weil sie im Store gesucht haben die Startdeklarationen enthält, anstelle der Deklaration, die Sitzungen enthält. Sie Verwenden Sie jetzt denselben Sitzungsspeicher wie die Engine und den API session.labels schon, also ein Retriever oder Tool, das liest oder schreibt Sitzungsmetadaten funktionieren gehostet genauso wie lokal.
  • Preisprüfungen warnen nicht mehr vor ungenutzten Anbieter-Standardmodellen, wenn a Eine spezifischere Modellroute überschreibt sie, z. B. Gemini-Einbettungen in einem Anthropischer Server. Modelle sind weiterhin über andere Routen und Modelle erreichbar tatsächlich im Einsatz beobachteten Mengen bleiben im Preisumfang enthalten. – MCP-Tools, die strukturierte Ergebnisse zurückgeben, z. B. ein pydantisches Modell, sind jetzt verfügbar Der Agent gibt das Ergebnis als schlichtes JSON aus. Vorher lief der Anruf, aber der Agent war da meldete „Tool-Aufruffehler“, sodass ein bereits angenommener Anruf erneut versucht werden konnte Wirkung zeigen oder dem Kunden mitteilen, dass es fehlgeschlagen ist.
  • Gemini-Agenten unter gleichzeitiger Auslastung stehen nicht länger hintereinander in der Warteschlange Es wird ein Prompt-Cache erstellt. Anfragen für andere Caches und Anfragen für deren Cache ist bereits vorhanden, fahren Sie sofort fort; Anfragen für denselben Cache immer noch Teilen Sie eine Kreation, sodass sie einmal erstellt und ihr Speicherplatz berechnet wird. – Server mit MongoDB-Speichern starten schneller, wenn der Sitzungs- und Ereignisverlauf wächst. Wenn die aufgezeichnete Version eines Shops bereits mit der laufenden Version übereinstimmt, wird Start-Nr liest nicht mehr jedes Dokument über seinen Loader zurück. Wenn eine Migration stattfindet Bei Bedarf werden Dokumente wie bisher geladen und migriert.

Englisches Original / English original

parlant v4.0.5

[4.0.5] - 2026-11-12

Added

  • Gemini 4 Hydrogen works through the Gemini provider, including streamed replies, tool calls, saved conversation replay and token accounting. Select it as gemini:gemini-4-hydrogen; existing default models are unchanged.
  • The chat widget shows Markdown tables in an agent's reply as tables. They used to show as lines of pipes. Column alignment, inline Markdown in cells and escaped pipes work. A streamed table appears once its header and divider rows arrive and fills in cell by cell. A wide table scrolls sideways inside the message, and your site's own table styles don't change it. Your project keeps the copy parlant widget init made. To pick this up, run parlant widget init --force, which replaces that copy and any changes you made to it.
  • Event streams (sse=true) now carry an id on every frame and resume from it. A client that reconnects with Last-Event-ID picks up after the frame it last saw, instead of replaying the session from the beginning. Streams ask a reconnecting browser to wait three seconds (retry: 3000), and an idle stream sends a keep-alive comment every 15 seconds, so a proxy no longer closes a quiet connection before wait_for_data expires. When a request carries both min_offset and Last-Event-ID, the later of the two wins: a reconnecting client usually still has the original min_offset in its URL, and honoring it would replay the session. The delay and the keep-alive interval can be set with PARLANT_SSE_RETRY_MS and PARLANT_SSE_HEARTBEAT_SECONDS; 0 disables the keep-alive, and 0 for the delay omits the retry: line.
  • Gemini serves Google's Gemini Decision 1 (gemini-decision-1), which answers many yes/no, choice and scale questions about one conversation in a single request. A {"*": "gemini"} route now uses it for rule ranking at the efforts that rank rules in one batch, as OpenAI and OpenRouter routes already do with their decision models. Name it on a route with "matching.rank[capability=decision]": "gemini:gemini-decision-1". It uses your existing GEMINI_API_KEY. Gemini reports no cost for it, so add a gemini-decision-1 entry to server.set_pricing(...) (Google lists $0.10 per million input tokens and nothing for output) to have it priced.

Changed

  • Gemini models count tokens on your server instead of asking the Gemini API, which took about 300ms per count. A step after a tool call made two such calls in a row while choosing canned responses, so replies after a tool call now start about 0.4–0.6s sooner. Counts use the open Gemma 3 tokenizer and are within a token or two of Google's. The gemini extra now installs sentencepiece. The tokenizer downloads once from raw.githubusercontent.com, in the background, on the first count. Until it's ready, or if your server can't reach GitHub, Parlant counts with the API as before and logs one warning saying so.
  • Agents no longer repeat what the customer just said back to them before replying ("Lead generation for a logistics startup, so…"). A reaction now responds to what the message means, and when the customer is answering the agent's own question, the agent goes straight to its next step. The prompt no longer bans stock acknowledgments such as "makes sense" by name.
  • Agents created by parlant init no longer learn to repeat the visitor's words back. The warm-host and upbeat personalities now react to what a message means, and the warm host goes straight to its next step when the visitor is answering its question. Existing projects keep their own text; copy the new wording from a fresh parlant init if your agent echoes.

Fixed

  • On managed (Dashboard-hosted) servers, session.metadata.get(), .set() and .delete(), session.update() and server.get_session() failed with "Session not found" for live conversations, because they looked in the store that holds startup declarations instead of the one that holds sessions. They now use the same session store as the engine and the API, as session.labels already did, so a retriever or tool that reads or writes session metadata works the same hosted as it does locally.
  • Pricing checks no longer warn about unused provider-default models when a more specific model route overrides them, such as Gemini embeddings on an Anthropic server. Models still reachable through other routes, and models actually observed in use, remain included in pricing coverage.
  • MCP tools that return structured results, such as a pydantic model, now give the agent the result as plain JSON. Before, the call ran but the agent was told "Tool call error", so it could retry a call that had already taken effect or tell the customer it failed.
  • Gemini agents under concurrent load no longer queue behind each other while a prompt cache is being created. Requests for other caches, and requests whose cache already exists, go ahead at once; requests for the same cache still share one creation, so it is created and its storage charged once.
  • Servers with MongoDB stores start faster as session and event history grows. When a store's recorded version already matches the running one, startup no longer reads every document back through its loader. When a migration is needed, documents are loaded and migrated as before.
