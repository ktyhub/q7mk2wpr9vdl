mempalace v3.11.0

Ein Palast kann jetzt in geführten Schritten geprüft und repariert werden, und EmbeddingGemma 2 ist als optionaler Einbetter mit nativer Bild-, Audio- und Videosuche verfügbar. Jeder Palast zeichnet das Einbettungsmodell auf, das ihn gebaut hat, und weigert sich, mit einem anderen zu öffnen. Conversation Mining stoppt das Verwerfen von Text, Status-, Such-, Weck- und Hub-Mines bleiben auf großen Palästen reaktionsfähig, und eine Reihe von Korrektheitskorrekturen aus der 3.11-Überprüfung stärkt Metadatenaktualisierungen, Wiederherstellung und HTTP-Validierung.

Upgrade-Hinweise

  • Bei der ersten Konversationsmine nach dem Upgrade wird jede abgedeckte Konversationsdatei einmal erneut geschürft. Der Exchange-Chunker verwirft keinen Text mehr (#2591), daher gelten Konversationsschubladen, die vor 3.11 abgelegt wurden, als veraltet und werden erneut aufgeteilt und aus Transkripten, die sich noch auf der Festplatte befinden, neu eingebettet. transcripts no longer on disk keep their drawers. Projektdateien werden nicht erneut geschürft. Expect roughly 40 minutes to 3 hours per million drawers, depending on hardware. On a large palace, back up first and run it in batches at a quiet time, for example mempalace mine <dir> --mode convos --limit 200; Ein unterbrochener Lauf wird dort fortgesetzt, wo er gestoppt wurde.
  • Ein Palast weigert sich, mit einem anderen Einbettungsmodell als dem, das ihn erstellt hat, zu öffnen. Suche, Mining und MCP-Schreibvorgänge werden mit einer Meldung beendet, die den Fix benennt: Setzen Sie embedding_model (config.json oder MEMPALACE_EMBEDDING_MODEL) auf das Modell zurück, mit dem der Palast erstellt wurde, oder betten Sie es erneut mit mempalace repair rebuild-index ein. A palace with no recorded model opens with the configured one and a warning that names mempalace palace set-embedder. (#2694, #2717)
  • EntityRegistry.research() und confirm_research() wurden entfernt. Es handelte sich um eine optionale, standardmäßig deaktivierte Wikipedia-Suche, die nichts im CLI, MCP-Server, Minern oder Hooks aufrief. Vorhandene wiki_cache-Einträge in entities.json werden weiterhin von lookup() gelesen. (GHSA-mrj5)

EmbeddingGemma 2 und Embedder-Identität

  • EmbeddingGemma 2 ist als optionaler Embedder verfügbar. Legen Sie embedding_model: embeddinggemma2 fest und installieren Sie mempalace[embeddinggemma2] oder mempalace[multimodal] für Medien (Python 3.10+, PyTorch). Es läuft auf CUDA, sofern vorhanden, auf Apple MPS oder auf der CPU und unterstützt die Abmessungen 768/512/256/128. A CUDA out-of-memory error halves the batch and retries. (#2694, #2717)
  • Nativer Bild-, Audio- und Videoabruf. Ein integrierter media-Quelladapter bettet Originaldateien in eine separate mempalace_assets-Sammlung ein, und die optionale CLI/MCP-Mediensuche gibt eingegebene lokale Asset-Referenzen neben passenden Schubladen zurück. Der Abruf auf Dateiebene ist experimentell. (#2694)
  • Existing palaces are untouched unless you opt in. The default MiniLM path is unchanged and nothing is re-embedded. An unknown embedding_model keeps the MiniLM fallback, while near misses of a known name are refused instead of silently falling back. (#2717)
  • Jeder Palast zeichnet auf, welcher Einbetter ihn erstellt hat, und jeder Schreibpfad schlägt aufgrund einer Nichtübereinstimmung fehl. CLI, MCP, meiner und repair überprüfen die aufgezeichnete Identität; repair rebuild-index und --mode from-sqlite zeichnen es nach einer verifizierten Neuerstellung erneut auf; neue Qdrant- und pgvector-Paläste zeichnen es auf; und MCP weigert sich, anstatt auf Chromas Standard-Embedder zurückzugreifen. (#2717; behebt #2709)

Palace-Audit und geführte Reparatur

  • mempalace audit bewertet, wie gut ein Palast organisiert ist, über fünf Ebenen (Räume, Flügel, Tunnel, Flure und Wissensgraph), mit konkreten Ergebnissen, --json-Ausgabe und --fail-under für Cron oder CI. Es ist schreibgeschützt und läuft gegen einen Palast, den ein MCP-Server bedient. (#2576)
  • Geführte Reparaturwerkzeuge: mempalace instructions audit führt einen Agenten und einen Benutzer durch die Ergebnisse; rooms propose / apply verleihen einem Flügel einen geschlossenen Raum; wings split verwandelt einen Transkriptflügel auf Maschinenebene in einen Flügel pro Projekt. tunnels propose / prune und hallways --rebuild / --prune-spellings bereinigen verrauschte Links; und kg normalize ordnet einmalige Prädikate einem geschlossenen Vokabular zu. Bis --yes ist alles ein Probelauf, unterbrochene Läufe werden bei einem erneuten Versuch beendet. LLM-gestützte Schritte verwenden standardmäßig einen lokalen Endpunkt und benötigen für alles andere --accept-external-llm. (#2576, #2655, #2656, #2657, #2664, #2668, #2669)
  • Nur-Metadaten-Updates auf den SQLite-Backends sind ~6000x schneller, sodass Flügel- und Raumbewegungen in großen Palästen in Sekunden abgeschlossen sind. (#2576)

Korrektheitskorrekturen aus dem 3.11-Test

  • Metadatenfähige Aktualisierungen und Upserts schützen die für die Einbettung verwendeten Eingaben. Gleichzeitige Dokument- oder Metadatenänderungen werden vor der Veröffentlichung abgelehnt und entfernte Felder werden bei der Einbettung von Metadaten ausgelassen. (#2734)
  • Schubladenlisten behalten Metadaten und Seitenvorschauen in einem wiederhergestellten Snapshot und greifen auf Chroma zurück, während die Wiederherstellung aussteht. (#2734)
  • Room Recovery weist beschädigte Zeitschriften zurück, bevor Änderungen übernommen werden und genehmigte Tunnelvorschläge behalten ihren vollständigen Rechtschreibkontext. (#2734) – Falsch formatierte HTTP-Toolnamen geben normale JSON-RPC-Validierungsfehler zurück, anstatt beim Versand fehlzuschlagen. (#2734)

Leistung und große Paläste

  • Status, Suche und Aktivierung bleiben auf großen Palästen reaktionsfähig. Zählcaches laufen nicht mehr ab, bevor sie verwendet werden (8–12 s bis zu etwa 1 ms bei einem Palast mit 360.000 Schubladen), der MCP-Server stoppt das Neuladen des Vektorindex bei fast jedem Aufruf, die Aktivierung liest die letzten Schubladen aus SQLite und das Mining scannt den Palast nicht mehr mit quadratischem Paging erneut. (#2593)
  • Minen auf sehr großen Palästen erledigen weitaus weniger redundante Arbeit und eine Mine auf dem HTTP-Hub gibt Anfragen in der Warteschlange zwischen Dateien nach. (#2567, #2593, #2688, #2689, #2690, #2691)
  • Tagebuch-Lesevorgänge und Einzelschubladen-Suchvorgänge aus SQLite, wenn die Zeilen bereits vorhanden sind. (#2650)

Fehlerbehebungen

  • Conversation Mining verwirft keinen Text mehr nach einer ----Markdown-Regel, vor dem ersten Benutzerzug oder in kurzen Gesprächen. (#2591)
  • mempalace_reconnect läuft nicht mehr unter einer laufenden Mine; es wartet bis zu 10 s und gibt dann MineInProgress zurück, und eine Mine, bei der einige Dateien fehlgeschlagen sind, löst MineFileErrors aus und beendet 1. (#2701, #2705)
  • **In-Prozess-SQLite-Lesevorgänge behalten die Sperren von Chroma bei, sodass Status-, Taxonomie-, BM25- und Integritätsprüfungen kein Risiko mehr für fehlerhafte Lesevorgänge eingehen. (#2506, #2573, #2652, #2658)
  • event_list und event_wait verbergen nicht mehr die Anfrage eines anderen Agenten, da der Anrufer seine eigene from_agent übergeben hat. (#2616)
  • Hub- und Daemon-Routen behalten --include-ignored und --include-subagents bei, und relative sweep/sync-Pfade werden anhand des Verzeichnisses des Aufrufers aufgelöst. (#2582, #2583, #2584, #2733)
  • sync --apply entfernt keine Schubladen mit Dateien mehr, die sich noch auf der Festplatte befinden hinter Mounts und Bind-Mounts. (#2368, #2564)
  • Die Standard-MCP-Server bleiben aktiv und antworten auf nicht analysierbaren Leitungen und wenn ihr Hub nicht mehr vorhanden ist. (#2534, #2555, #2557)
  • Außerdem: mempalace.yml wird von init (#2699, #2704) akzeptiert und aktualisiert; .al- und .ps1-Quellen werden abgebaut (#2702, #2706); Es gelten nur fallweise Flügel-/Raumumbenennungen (#2426); KG schreibt, dass die Peer-Writer-Lease nicht mehr erforderlich ist (#2423); der Vorgänger repair hält das Palastschloss (#2569); Das Aufblähen des q8-Speichers von EmbeddingGemma wurde behoben (#2693); DirectML-Sitzungen werden seriell ausgeführt (#2687); und mehr – die vollständige Liste finden Sie unten.

Sicherheit und Abhängigkeiten

  • ChromaDB-Telemetrie ist explizit deaktiviert, nicht nur stummgeschaltet. Auf der unterstützten 1.x-Leitung wurde nichts übertragen. (GHSA-8h77, #2524)
  • Die nicht verwendete Wikipedia-Suche wurde entfernt, sodass „local-first“ eine Eigenschaft des Codes und kein Standardargument ist. (GHSA-mrj5, #2526, #2527)
  • Pillow 12.3.0, Chromadb 1.5.9 und routinemäßige Sperrstöße. Pillow 12.3.0 benötigt Python 3.10+, daher installiert Python 3.9 Stay on Pillow 11.3.0, das von den in 12.3.0 behobenen Pillow-Hinweisen betroffen ist. SECURITY.md warnt jetzt davor, einen Chroma-HTTP-Server offenzulegen. (#2719) – Schreibgeschützte MCP-Tools bewerben annotations.readOnlyHint, sodass Planmodi und schreibgeschützte Subagenten die Speichersuche ohne hostseitige Zulassungsliste verwenden können. (#2610, #2640)

Installieren/Upgrade

pip install --upgrade mempalace        # or: uv tool upgrade mempalace / pipx upgrade mempalace

Optionale Einbettung von Gemma 2 und Mediensuche (Python 3.10+): pip install -U "mempalace[embeddinggemma2]" oder "mempalace[multimodal]", dann embedding_model: embeddinggemma2 für einen neuen Palast festlegen. Siehe docs/embeddinggemma2.md.

Optionale native Suche nach exakten Vektoren: Die mempalace_native_core-Räder und die eigenständigen ausführbaren mempalace-native-Dateien sind dieser Version beigefügt (siehe crates/README.md).

Installieren: pip install -U mempalace==3.11.0

mempalace v3.11.0

A palace can now be audited and repaired in guided steps, and EmbeddingGemma 2 arrives as an opt-in embedder with native image, audio and video search. Every palace records the embedding model that built it and refuses to open with a different one. Conversation mining stops discarding text, status, search, wake-up and hub mines stay responsive on large palaces, and a round of correctness fixes from the 3.11 review hardens metadata updates, recovery and HTTP validation.

Upgrade notes

  • The first conversation mine after upgrading re-mines each conversation file it covers, once. The exchange chunker no longer discards text (#2591), so conversation drawers filed before 3.11 count as stale and are re-chunked and re-embedded from transcripts still on disk; transcripts no longer on disk keep their drawers. Project files are not re-mined. Expect roughly 40 minutes to 3 hours per million drawers, depending on hardware. On a large palace, back up first and run it in batches at a quiet time, for example mempalace mine <dir> --mode convos --limit 200; an interrupted run resumes where it stopped.
  • A palace refuses to open with a different embedding model than the one that built it. Search, mining and MCP writes stop with a message that names the fix: set embedding_model (config.json or MEMPALACE_EMBEDDING_MODEL) back to the model the palace was built with, or re-embed with mempalace repair rebuild-index. A palace with no recorded model opens with the configured one and a warning that names mempalace palace set-embedder. (#2694, #2717)
  • EntityRegistry.research() and confirm_research() are removed. They were an opt-in, off-by-default Wikipedia lookup that nothing in the CLI, MCP server, miners or hooks called. Existing wiki_cache entries in entities.json are still read by lookup(). (GHSA-mrj5)

EmbeddingGemma 2 and embedder identity

  • EmbeddingGemma 2 is available as an opt-in embedder. Set embedding_model: embeddinggemma2 and install mempalace[embeddinggemma2], or mempalace[multimodal] for media (Python 3.10+, PyTorch). It runs on CUDA when present, on Apple MPS, or on CPU, and supports 768/512/256/128 dimensions. A CUDA out-of-memory error halves the batch and retries. (#2694, #2717)
  • Native image, audio and video retrieval. A built-in media source adapter embeds original files into a separate mempalace_assets collection, and opt-in CLI/MCP media search returns typed local asset references alongside matching drawers. File-level retrieval is experimental. (#2694)
  • Existing palaces are untouched unless you opt in. The default MiniLM path is unchanged and nothing is re-embedded. An unknown embedding_model keeps the MiniLM fallback, while near misses of a known name are refused instead of silently falling back. (#2717)
  • Every palace records which embedder built it, and every write path fails closed on a mismatch. CLI, MCP, mine and repair check the recorded identity; repair rebuild-index and --mode from-sqlite record it again after a verified rebuild; new Qdrant and pgvector palaces record it; and MCP refuses rather than falling back to Chroma's default embedder. (#2717; fixes #2709)

Palace audit and guided repair

  • mempalace audit scores how well a palace is organized, across five layers (rooms, wings, tunnels, hallways and knowledge graph), with concrete findings, --json output and --fail-under for cron or CI. It is read-only and runs against a palace an MCP server is serving. (#2576)
  • Guided repair tooling: mempalace instructions audit walks an agent and user through the findings; rooms propose / apply give a wing a closed room set; wings split turns a machine-level transcript wing into one wing per project; tunnels propose / prune and hallways --rebuild / --prune-spellings clean up noisy links; and kg normalize maps one-off predicates onto a closed vocabulary. Everything is a dry run until --yes, and interrupted runs finish on retry. LLM-backed steps default to a local endpoint and need --accept-external-llm for anything else. (#2576, #2655, #2656, #2657, #2664, #2668, #2669)
  • Metadata-only updates on the SQLite backends are ~6000x faster, so wing and room moves on large palaces finish in seconds. (#2576)

Correctness fixes from the 3.11 review

  • Metadata-aware updates and upserts guard the inputs used for embedding. Concurrent document or metadata changes are refused before publication, and removed fields are omitted from embedding metadata. (#2734)
  • Drawer listings keep metadata and page previews in one recovered snapshot, and fall back to Chroma while recovery is pending. (#2734)
  • Room recovery rejects damaged journals before applying changes, and approved tunnel proposals keep their full spelling context. (#2734)
  • Malformed HTTP tool names return normal JSON-RPC validation errors instead of failing during dispatch. (#2734)

Performance and large palaces

  • Status, search and wake-up stay responsive on large palaces. Count caches no longer expire before they are used (8–12 s down to about 1 ms on a 360k-drawer palace), the MCP server stops reloading the vector index on almost every call, wake-up reads recent drawers from SQLite, and mining no longer rescans the palace with quadratic paging. (#2593)
  • Mines on very large palaces do far less redundant work, and a mine on the HTTP hub yields to queued requests between files. (#2567, #2593, #2688, #2689, #2690, #2691)
  • Diary reads and single-drawer lookups read from SQLite when it already has the rows. (#2650)

Bug fixes

  • Conversation mining no longer discards text after a --- markdown rule, before the first user turn, or in short exchanges. (#2591)
  • mempalace_reconnect no longer runs under a running mine; it waits up to 10 s and then returns MineInProgress, and a mine that failed some files raises MineFileErrors and exits 1. (#2701, #2705)
  • In-process SQLite reads keep Chroma's locks, so status, taxonomy, BM25 and integrity checks no longer risk torn reads. (#2506, #2573, #2652, #2658)
  • event_list and event_wait no longer hide another agent's request because the caller passed its own from_agent. (#2616)
  • Hub and daemon routes keep --include-ignored and --include-subagents, and relative sweep / sync paths resolve against the caller's directory. (#2582, #2583, #2584, #2733)
  • sync --apply no longer removes drawers of files that are still on disk behind mounts and bind mounts. (#2368, #2564)
  • The stdio MCP servers stay up and answer on unparseable lines and when their hub is gone. (#2534, #2555, #2557)
  • Also: mempalace.yml is accepted and updated by init (#2699, #2704); .al and .ps1 sources are mined (#2702, #2706); case-only wing/room renames apply (#2426); KG writes no longer need the peer-writer lease (#2423); the legacy repair holds the palace lock (#2569); EmbeddingGemma's q8 memory blow-up is fixed (#2693); DirectML sessions run serially (#2687); and more — see the full list below.

Security and dependencies

  • ChromaDB telemetry is disabled explicitly, not just silenced. Nothing was transmitted on the supported 1.x line. (GHSA-8h77, #2524)
  • The unused Wikipedia lookup is removed, so local-first is a property of the code rather than a default argument. (GHSA-mrj5, #2526, #2527)
  • Pillow 12.3.0, chromadb 1.5.9 and routine lock bumps. Pillow 12.3.0 needs Python 3.10+, so Python 3.9 installs stay on Pillow 11.3.0, which is affected by the Pillow advisories fixed in 12.3.0. SECURITY.md now warns against exposing a Chroma HTTP server. (#2719)
  • Read-only MCP tools advertise annotations.readOnlyHint, so plan modes and read-only subagents can use memory search without a host-side allowlist. (#2610, #2640)

Install / upgrade

pip install --upgrade mempalace        # or: uv tool upgrade mempalace / pipx upgrade mempalace

Optional EmbeddingGemma 2 and media search (Python 3.10+): pip install -U "mempalace[embeddinggemma2]" or "mempalace[multimodal]", then set embedding_model: embeddinggemma2 for a new palace. See docs/embeddinggemma2.md.

Optional native exact-vector search: the mempalace_native_core wheels and standalone mempalace-native executables are attached to this release (see crates/README.md).

A big thank-you to everyone who contributed. This release includes 79 merged PRs: 76 from 11 contributors, three of them first-time, plus three Dependabot bumps.

Install: pip install -U mempalace==3.11.0
