gstack v1.96.0.0

Eine große Veröffentlichung, die die Versionen 1.92.56.0 bis 1.96.0.0 abdeckt: /ship now trust führt einen grünen CI-Lauf durch, anstatt Ihre Tests erneut auszuführen, und sendet riskanten Code zur tieferen Überprüfung, der Browser erhält Touchscreen-Tests und Registerkarten pro Agent, eine neue /runaway-stopper-Fähigkeit kommt und es gibt mehrere Sicherheitskorrekturen.

Was ist neu?

– Neue Fähigkeit: /runaway-stopper findet Agent-Threads und Subagenten, die Token verbrennen, stoppt sie an einem sauberen Punkt und legt Standardwerte fest, die verhindern, dass sie zurückkommen #3975. – /ship führt nicht mehr Ihre gesamte Testsuite erneut aus, wenn ein CI-Lauf bereits den exakt gleichen Code durchlaufen hat; Es verwendet dieses Ergebnis und führt einen frühen Push durch, sodass seine Prüfungen neben CI #3901 ausgeführt werden. – Vor jedem Push führt /ship jetzt die schnellen Verwaltungsprüfungen Ihres Repositorys (generierte Dateien, Größenwächter und dergleichen) für die von Ihnen berührten Dateien durch und lehnt übrig gebliebene Zusammenführungskonfliktmarkierungen ab #3923, #3965.

  • /ship sendet riskanteren Code an seine vollständige Überprüfung: Ausgaben- und Abrechnungscode, Eval-Scorer, ausgehende Netzwerkaufrufe, Archive, Prozess-Spawning, ausführbare Dateien, Code, der Daten versiegelt oder Dateien vor der Überprüfung verbirgt, und Dokumente, die Geheimnisse drucken können. Ein Repository kann seine eigenen Risikopfade über einen neuen review-Schlüssel in seiner Versandrichtlinie hinzufügen #3920, #3829, #3972, #3959, #3864, #3866. – Die Prüfer von /ship klonen andere Repositorys nicht mehr selbst und ein Repository kann Pfade auflisten, die sie niemals lesen dürfen #4007, #4011. – Ein neuer review_exclude_paths-Schiffsrichtlinienschlüssel lässt Daten, Protokolle und Belege aus der Überprüfung durch /ship aus, während der Code und jede Zeile, die einen Berechtigungsnachweis liest, weiterhin erhalten bleibt #3852. – Die Checkliste von /review beginnt jetzt mit der Art der Pull-Anfrage (Dokumente, CI, Skripte oder Anwendungscode) und fügt eine Prüfung hinzu, ob neue Dateien den eigenen Sprachen, Tools und Plattformen des Repositorys folgen #3852.
  • /ship kann Kommentare von jedem von Ihnen aufgelisteten Bewertungsbot selektieren, nicht nur von Greptile #3852. – Bei einem Anthropic-Modell verwendet die Überprüfung des zweiten Modells von /ship jetzt standardmäßig GPT-6.1 Sol, das Setup, mit dem es getestet wurde, und lehnt einen Prüfer aus derselben Modellfamilie ab #3698.
  • Bewertungen des zweiten Codex-Modells geben jetzt an, wie viele Token sie verwendet haben, danke @omicron-soft #3729.
  • Mehrere Agenten können den Browser von gstack gleichzeitig steuern, ohne den Tab des anderen zu übernehmen. Jede erhält ihre eigene, oder Sie können eine Sitzung mit --session #3858 benennen. – QA kann Telefonseiten mit echter Berührungseingabe testen: $B device "iPhone 15" emuliert das Telefon und $B tap, swipe, pinch und touch senden Berührungen #3858. – gstack-clean stellt alte Arbeitsdateien und übergroße Suchprotokolle im .gstack/-Ordner eines Projekts wieder her; Es wird nur berichtet, bis Sie --apply #3858 passieren. – Claude Opus 5.5-Sitzungen auf Capy erhalten eine leichtere Version der Fähigkeiten von gstack mit weniger Coaching-Text, und Claude Code-Benutzer können sie mit ./setup --loadout lite #3858 auswählen. – /investigate führt das Modell nicht mehr durch ein festes Fünf-Phasen-Verfahren, das laut einer Evaluierung nie befolgt wurde #3858. – Zwei optionale Claude Code-Hooks: ./setup --skill-routing schlägt den Gstack-Skill vor, der zu Ihrer Eingabeaufforderung passt, und ./setup --skill-contracts verhindert, dass ein Skill endet, bevor seine „Fertig bedeutet“-Schritte ausgeführt wurden #3912. – /investigate, /review, /qa und /verify sagen jetzt, wann sie in ihren Beschreibungen verwendet werden sollen, und stimmen mit mehr der Phrasen überein, die tatsächlich eingegeben werden #3909.
  • Claude Code und Cursor starten /land-and-deploy oder /modernize nicht mehr selbstständig; Geben Sie den Befehl ein, um sie auszuführen #3808. – /autoplan überspringt die Planprüfung für Fehlerbehebungen und verwendet einen Lean-Prüfer für Funktionen, und ein übergeordneter Agent kann nur seine CEO-Prüfung mit gstack-autoplan next --ceo-only #3897, #3767 durchführen.
  • /plan-tune lernt aus Antworten auf nicht registrierte Fragen, wenn der Skill markiert, um welche Präferenz es in der Frage geht #3868. – Ein Test, der absichtlich einen alten Wert beibehalten muss, kann jetzt einen einzeiligen Verzichtskommentar enthalten, der den alten Wert und den Grund nennt, anstatt die Pre-Push-Literalprüfung von /ship nicht zu bestehen #3891.
  • Die Bewertungsplanung bewertet jetzt Claude Haiku mit 5.5, GPT-6 Luna und Gemini 4 Argon und /codex benennt die aktuellen GPT-6-Stufen, danke @exGeni und @DanCanadian #3732. – Ein von /ubicloud gestarteter Ubicloud-Lauf kann von einem anderen Computer wiederhergestellt und beendet werden, wenn der Computer, der ihn gestartet hat, ausfällt #3961.

  • Sicherheit: Der Lean-/Autoplan-Prüfer erhält keine .envrc, .env-production, Anmeldeinformationsdateien oder Schlüssel mehr, die in normale Dateien eingefügt werden #3921. – Bei öffentlichen Repositorys fügt /ship die Genehmigungswörter, Lauf-IDs oder Plan-Hashes des Besitzers nicht mehr in die Pull-Request-Beschreibung ein #3918. – gstack-autoplan export --public enthält nicht mehr die eigenen Antworten oder zitierten Wörter des Besitzers #3967. – review_exclude_paths kann native Binärdateien, Code mit einem NUL-Byte oder eine als Binärdatei markierte Datei, die eine Anmeldeinformationszeile enthält, nicht mehr aus der Überprüfung ausblenden #3902. – /design-consultation und /design-review verwenden jetzt Easy-out für Exit-Animationen anstelle von Easy-in, danke @nfitzsimmons #3963.

  • Weniger Fehlalarme bei der Überprüfungsplanung von /ship: Design-Token-Dateien, Dateinamen, die „Kosten“ erwähnen, Autorendateien und Diagramm-SVGs lösen keine zusätzlichen Prüfer mehr aus, und eine sehr lange Schlange kann die Planung nicht mehr aufhalten #3999, #3942, #3906, #3848.

gstack v1.96.0.0

gstack v1.96.0.0

A large release covering versions 1.92.56.0 to 1.96.0.0: /ship now trusts a green CI run instead of rerunning your tests and sends risky code to deeper review, the browser gains touch-screen testing and per-agent tabs, a new /runaway-stopper skill arrives, and there are several security fixes.

What's new

  • New skill: /runaway-stopper finds agent threads and subagents that are burning tokens, stops them at a clean point, and sets defaults that keep them from coming back #3975.
  • /ship no longer reruns your whole test suite when a CI run already passed on the exact same code; it uses that result and pushes early so its checks run beside CI #3901.
  • Before every push, /ship now runs your repository's quick housekeeping checks (generated files, size guards and the like) for the files you touched, and refuses leftover merge conflict markers #3923, #3965.
  • /ship sends more risky code to its full review: spending and billing code, eval scorers, outbound network calls, archives, process spawning, executables, code that seals data or hides files from review, and docs that can print secrets. A repository can add its own risk paths through a new review key in its ship policy #3920, #3829, #3972, #3959, #3864, #3866.
  • /ship's reviewers no longer clone other repositories on their own, and a repository can list paths they must never read #4007, #4011.
  • A new review_exclude_paths ship-policy key leaves data, logs and receipts out of /ship's review while still keeping code and any line that reads a credential #3852.
  • /review's checklist now starts from the kind of pull request (docs, CI, scripts or application code) and adds a check that new files follow the repository's own languages, tools and platforms #3852.
  • /ship can triage comments from any review bot you list, not only Greptile #3852.
  • On an Anthropic model, /ship's second-model review now defaults to GPT-6.1 Sol, the setup it was tested with, and refuses a reviewer from the same model family #3698.
  • Codex second-model reviews now report how many tokens they used, thanks @omicron-soft #3729.
  • Several agents can drive gstack's browser at once without taking over each other's tab; each gets its own, or you can name a session with --session #3858.
  • QA can test phone pages with real touch input: $B device "iPhone 15" emulates the phone, and $B tap, swipe, pinch and touch send touches #3858.
  • gstack-clean reclaims old scratch files and oversized browse logs in a project's .gstack/ folder; it only reports until you pass --apply #3858.
  • Claude Opus 5.5 sessions on Capy get a lighter version of gstack's skills with less coaching text, and Claude Code users can pick it with ./setup --loadout lite #3858.
  • /investigate no longer walks the model through a fixed five-phase procedure, which an eval showed it never followed #3858.
  • Two opt-in Claude Code hooks: ./setup --skill-routing suggests the gstack skill that fits your prompt, and ./setup --skill-contracts stops a skill from ending before its "done means" steps ran #3912.
  • /investigate, /review, /qa and /verify now say when to use them in their descriptions and match more of the phrases people actually type #3909.
  • Claude Code and Cursor no longer start /land-and-deploy or /modernize on their own; type the command to run them #3808.
  • /autoplan skips plan review for bug fixes and uses one lean reviewer for features, and a parent agent can run only its CEO review with gstack-autoplan next --ceo-only #3897, #3767.
  • /plan-tune learns from answers to unregistered questions when the skill tags which preference the question is about #3868.
  • A test that must keep an old value on purpose can now hold a one-line waiver comment naming the old value and the reason, instead of failing /ship's pre-push literals check #3891.
  • Eval planning now prices Claude Haiku 5.5, GPT-6 Luna and Gemini 4 Argon, and /codex names the current GPT-6 tiers, thanks @exGeni and @DanCanadian #3732.
  • A Ubicloud run started by /ubicloud can be recovered and torn down from another machine if the machine that started it dies #3961.

Fixes

  • Security: gstack's browser now runs Chromium 156, which fixes a macOS sandbox escape (CVE-2026-106378), and browse handoff uses the browser GSTACK_CHROMIUM_PATH names #3947.
  • Security: /setup-browser-cookies now warns that the fallback browser still trusts the compromised eMudhra certificate authorities #3871.
  • Security: the qs and @hono/node-server dependencies are pinned past two medium-severity advisories #3870.
  • Security: the lean /autoplan reviewer no longer receives .envrc, .env-production, credential files or keys pasted into ordinary files #3921.
  • On public repositories, /ship no longer pastes the owner's approval words, run ids or plan hashes into the pull request description #3918.
  • gstack-autoplan export --public no longer includes the owner's own replies or quoted words #3967.
  • review_exclude_paths can no longer hide native binaries, code with a NUL byte, or a file marked binary that holds a credential line from review #3902.
  • /design-consultation and /design-review now use ease-out for exit animations instead of ease-in, thanks @nfitzsimmons #3963.
  • /retro keeps its history across git worktrees, so a run in a linked worktree compares against last week instead of starting over #3848.
  • A local main branch behind origin/main no longer changes what /ship and /review count as your change or how deeply they review it #3848, #3852, #3906.
  • /ship works on a checkout whose origin/HEAD points at the pull request branch itself, and stops instead of guessing when origin's default branch can't be read #3852, #3913.
  • Fewer false alarms in /ship's review planning: design-token files, file names that mention "cost", authorship files and chart SVGs no longer trigger extra reviewers, and one very long line can no longer stall planning #3999, #3942, #3906, #3848.
  • /ship no longer treats a reviewer's own "I found nothing CRITICAL." as a critical finding #3990.
  • /ship's second-model review: a "can't verify" reply is no longer read as a pass, numbered findings without a P0-P3 tag are kept, a ## Recommendation heading counts as finished (thanks @nfitzsimmons), and on Capy a hung review is stopped and recorded as missing #3946, #4000, #3895.
  • /ship asks for less re-review: base merges and docs commits keep review credit, a required edit or small change after review gets one scoped re-check instead of another full round, and lines brought in by a base merge don't count against the re-check #3970, #4020, #3926, #3955.
  • A stacked pull request keeps its /ship review after its parent squash-merges into main #3928, #3940.
  • Running /ship's full preflight again during an open /ship run no longer merges the base under its reviewers #3950.
  • /ship no longer crashes when every reviewer comes back clean, and two smaller /ship papercuts are fixed #3945.
  • /ship and /review no longer write exploratory QA reports into your project folder #3898.
  • A finished /ship no longer blocks gstack-upgrade for two hours #3932.
  • On a shared machine, an install for another workflow or reviewer no longer breaks /ship's or /autoplan's install check, and the lean /autoplan reviewer sees the committed draft on a pull request branch #3960, #3919, #3969.
