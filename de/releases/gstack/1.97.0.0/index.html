gstack v1.97.0.0

gstack v1.97.0.0

Meistens /ship, der Befehl von gstack, der eine Pull-Anfrage überprüft, testet und für Sie öffnet: weniger unnötige zusätzliche Überprüfungsrunden, Audits, die Ihrer Modellpräferenz folgen, zwei Opt-in-Gates, die /investigate und /plan-ceo-review bei ihrem Schlüsselschritt festhalten, und eine Browser-Sicherheitskorrektur.

Was ist neu?

  • Ein Opt-in-Gate für /plan-ceo-review verhindert, dass die Sitzung beendet wird, bis die Bewertung ihre bewerteten Ergebnisse verfasst hat. Schalten Sie es mit ./setup --ceo-review-gate #4047 ein. – Ein Opt-in-Gate für /investigate blockiert einen Fix, bis eine Grundursache aufgeschrieben ist, einschließlich Fixes, die über Shell-Befehle vorgenommen wurden; Schalten Sie es mit ./setup --investigate-gate #4045 ein. – Wenn Sie dem Stable-Update-Kanal folgen, werden wichtige Korrekturen (Sicherheit, Regressionen, Datenverlust, Blocker) jetzt innerhalb eines Tages stabil, und Stable liegt nie mehr als eine Woche hinter den getesteten Änderungen im Hauptbereich zurück #4083.

Korrekturen

– Sicherheit: Der gebündelte Browser von gstack verwendet jetzt Playwright 1.65.0 mit Chromium 158, das die kompromittierten eMudhra-Zertifizierungsstellen #4087 nicht mehr trusts unterstützt. – Das Browse-Audit-Log speichert nicht mehr, was Sie auf Seiten eingeben, wie z. B. mit fill oder type gesendete Passwörter, Dialogantworten und Cookie- oder Header-Werte. Gemeldet von @derHaken #4073, #4081. – Das Browser-Überwachungsprotokoll und das Netzwerkprotokoll speichern keine URL-Abfragewerte oder Anmeldeinformationen mehr, sodass die Felder eines übermittelten Anmeldeformulars nicht mehr auf der Festplatte gespeichert werden #4082. – gstack-brain-sync nennt einen abgelehnten Push nicht länger einen Authentifizierungsfehler, nur weil die URL Ihrer Fernbedienung ein Wort wie auth oder 403 enthält, und versucht den Push wie vorgesehen erneut #4035. – Der Browse-Daemon schlägt nicht mehr mit der Meldung „Ist Port … in Verwendung?“ fehl. auf einer ausgelasteten Maschine; Es wählt jetzt seinen Port aus, kurz bevor es mit dem Abhören beginnt #4035. – Der geheime Scan von gstack kennzeichnet gewöhnlichen Code wie config.prod oder server.local(...) nicht mehr als durchgesickerten internen Hostnamen, danke @nazarli-shabnam #4043.

  • /ship's docs, test-coverage und plan audits laufen jetzt auf dem Modell, das Sie in Ihren Einstellungen festgelegt haben, statt immer auf Sonnet 5.5 #4038, #4042. – /ship fragt nicht mehr nach einer weiteren Überprüfungsrunde, wenn seine eigene Dokumentenprüfung Dateien nach der Überprüfung bearbeitet, selbst wenn die Prüfung zweimal ausgeführt wird #4034, #4071. – Das Hinzufügen von review_exclude_paths-Mustern in Ihrem Hauptzweig erzwingt nicht mehr, dass offene Pull-Anfragen erneut überprüft werden, wenn keine ihrer Dateien mit #4030, #4036, #4041 übereinstimmt. – Jeder /ship-Rezensent sieht jetzt das gleiche gekürzte Diff, einschließlich eines Rezensenten, dessen Anweisungen nach einem fehlgeschlagenen Start selbstständig neu erstellt wurden #4048. – Die Überprüfungsplanung von /ship ist bei sehr großen Ergebnisrepositorys in etwa 35 Sekunden abgeschlossen, anstatt dass es zu einer Zeitüberschreitung kommt #4040. – Ergebnis-Pull-Anfragen voller erfasster Modell-Eingabeaufforderungen erreichen nicht mehr die Größenbeschränkung für Bewertungen von /ship, nur weil in diesen Eingabeaufforderungen API-Schlüsselvariablen erwähnt werden #4044.
  • /ship und /review zählen nicht mehr den Schlusssatz eines Rezensenten, wie zum Beispiel „Keiner davon wird zu KRITISCH.“ als kritischer Befund #4075. – Eine gestapelte Pull-Anfrage, deren übergeordnetes Element durch Squash zusammengeführt wurde, weist die eigenen Änderungen von /ship main nicht mehr als nicht überprüfte Änderungen auf #4021. – /ship bleibt nicht mehr hängen, wenn eine Dokumentenzeile mit einer Geld-, Sicherheits- oder numerischen Forderung hinzugefügt wird, nachdem die Überprüfung abgeschlossen ist #4062.
  • /ship bleibt nach einer Basiszusammenführung, die sowohl eine überprüfte Zeile ändert als auch Code daneben verschiebt, nicht mehr hängen. Es wird nun nach einer kleinen erneuten Überprüfung gefragt #4054.
  • /ship fragt nicht mehr nach einer neuen Überprüfung, wenn eine Basiszusammenführung nur eine Versions- oder Regelnummer berührt, die Ihre Schiffsrichtlinie als mechanisch deklariert #4053. – /ship stoppt nicht mehr bei einer Godot .uid-Datei, die nach der Überprüfung hinzugefügt wurde, und Ihre Versandrichtlinie kann jetzt Ihre eigenen Testdateien benennen #4063. – Eine Versandrichtlinie, deren minimale Gstack-Version neuer als die neueste stabile Version ist, wird jetzt namentlich abgelehnt, anstatt Sitzungen an ein Upgrade zu senden, das sie nicht erfüllen kann #4080.
  • Die Prüfung „Nach der letzten Bearbeitung erneut testen“ von /investigate erkennt jetzt Korrekturen, die über Shell-Befehle wie sed -i oder ein Heredoc geschrieben wurden #4078. – Die Gates /investigate und /plan-ceo-review lassen eine Sitzung nicht mehr unkontrolliert enden, wenn ihr Scan langsam läuft #4072. – /runaway-stopper kennzeichnet Agenten, die alle vier Minuten einchecken, während sie auf CI warten, nicht mehr als Ausreißer #4069. – Der Ubicloud-Runner hinter /ubicloud behandelt einen API-Fehler niemals als Erfolg und zerstört niemals eine VM, die ein anderer Aufrufer unter demselben Namen erstellt hat #4039, #4046.

Änderungen für Betreuer

  • Die Finish- und Accept-Schritte von /ship handhaben vom Eigentümer gewährte Korrekturrunden besser: Verkettete Korrekturprüfungen zählen alle, eine gewährte Runde aktualisiert das erneute Lesen von Geld und Sicherheit von selbst, vom Eigentümer gesteuerte Notizen schließen ihre Ergebnisse und das Ergebnis benennt die verwendete Genehmigung #4050, #4064, #4070, #4077. – Der Datensatz zum erneuten Lesen von Geld und Sicherheit überlebt eine spätere Hauptzusammenführung und die Annahme übernimmt ihr CI-Wartelimit von der Basisversandrichtlinie (ci_record_timeout_s) #4058, #4065. – Accept prüft einen Zweig gemäß seiner eigenen Testrichtlinie, wenn dieser Zweig nur Testläufe hinzufügt, und ein Besitzer kann eine Ausnahme für einen Testlauf gewähren #4061. – Die neuen Schiffsrichtlinienschlüssel mechanical_retake und test_code erfordern Gstack 1.97.0.0 #4079. – Auf Capy protokollieren /ship-Helferbefehle jetzt ihre eigenen Anrufe, sodass die Anrufanzahl eines Laufs bekannt ist #4059. – Das eigene Repository von gstack führt jetzt alle 8 Stunden eine kostenpflichtige Release-Überprüfung für main durch, testet eine Pull-Anfrage, die mit dem Tip von main zusammengeführt wurde, erneut, bevor sie zusammengeführt wird, wenn main verschoben wurde, und führt CI-übersprungene Testdateien vor der Zusammenführung erneut aus #4031, #4029, #4028. – Der Zusammenführungsschritt verbirgt seine eigene Umgebung, einschließlich des GitHub-Tokens, vor den Prüfungen, die er unter Linux ausführt #4032. – Die Release-Dateiprüfung akzeptiert eine Release-Ausgabe, die das Release-Tool des Repositorys neu generiert #4033. – Eine Pull-Anfrage, die setup bearbeitet, führt nicht mehr jeden bezahlten Eval-Fall auf einem schmalen Bildschirm aus #4056. – Die Free-CI-Slow-Shard-Warnung berücksichtigt jetzt Shards, die auf parallele Jobs aufgeteilt sind, danke @indraoverflow #4085.
  • Testreparaturen: Zwei Testdateien bestehen jetzt in einem Prozess, und vier fehlerhafte Tests melden, warum sie fehlgeschlagen sind #4068, #4074. – Das Beweisinventar zeichnet die neuesten Routing- und /investigate-Bewertungsurteile auf #4076. – gstack generiert jetzt eine Load-on-Demand-Edition von drei Fähigkeiten (Untersuchung, Überprüfung und Planüberprüfung) für einen anderen Agent-Host #4049.
  • Agentendokumente: Agenten auf Capy kommentieren und fordern Bewertungen nur über die PR-Tools von Capy an, Agenten führen /ship schlafen, bis es fertig ist, und halten ihren Kontext klein, und AGENTS.md listet Fähigkeiten nur nach Namen auf #4027, #4055, #4060. gstack v1.97.0.0

gstack v1.97.0.0

Mostly /ship, gstack's command that reviews, tests and opens a pull request for you: fewer needless extra review rounds, audits that follow your model preference, two opt-in gates that hold /investigate and /plan-ceo-review to their key step, and a browser security fix.

What's new

  • An opt-in gate for /plan-ceo-review keeps the session from finishing until the review has written its ranked findings; turn it on with ./setup --ceo-review-gate #4047.
  • An opt-in gate for /investigate blocks a fix until a root cause is written down, including fixes made through shell commands; turn it on with ./setup --investigate-gate #4045.
  • If you follow the stable update channel, important fixes (security, regressions, data loss, blockers) now reach stable within a day, and stable is never more than a week behind tested changes on main #4083.

Fixes

  • Security: gstack's bundled browser now uses Playwright 1.65.0 with Chromium 158, which no longer trusts the compromised eMudhra certificate authorities #4087.
  • The browse audit log no longer saves what you type into pages, such as passwords sent with fill or type, dialog answers, and cookie or header values. Reported by @derHaken #4073, #4081.
  • The browse audit log and network log no longer keep URL query values or credentials, so a submitted login form's fields stay off disk #4082.
  • gstack-brain-sync no longer calls a rejected push an auth error just because your remote's URL contains a word like auth or 403, so it retries the push as it should #4035.
  • The browse daemon no longer fails with "Is port … in use?" on a busy machine; it now picks its port right before it starts listening #4035.
  • gstack's secret scan no longer flags ordinary code such as config.prod or server.local(...) as a leaked internal hostname, thanks @nazarli-shabnam #4043.
  • /ship's docs, test-coverage and plan audits now run on the model you set in your preferences instead of always on Sonnet 5.5 #4038, #4042.
  • /ship no longer asks for another review round when its own docs audit edits files after the review, even when the audit runs twice #4034, #4071.
  • Adding review_exclude_paths patterns on your main branch no longer forces open pull requests through review again when none of their files match #4030, #4036, #4041.
  • Every /ship reviewer now sees the same trimmed diff, including a reviewer whose instructions were rebuilt on their own after a failed start #4048.
  • /ship's review planning finishes in about 35 seconds on very large results repositories instead of timing out #4040.
  • Results pull requests full of captured model prompts no longer hit /ship's review size limit just because those prompts mention API key variables #4044.
  • /ship and /review no longer count a reviewer's closing sentence such as "None of these rises to CRITICAL." as a critical finding #4075.
  • A stacked pull request whose parent was squash-merged no longer has /ship flag main's own changes as unreviewed edits #4021.
  • /ship no longer gets stuck when a docs line with a money, security or numeric claim is added after the review finished #4062.
  • /ship no longer gets stuck after a base merge that both changes a reviewed line and moves code next to it; it now asks for one small re-check #4054.
  • /ship no longer asks for a new review when a base merge only bumps a version or rules number your ship policy declares as mechanical #4053.
  • /ship no longer stops on a Godot .uid file added after review, and your ship policy can now name your own test files #4063.
  • A ship policy whose minimum gstack version is newer than the latest stable release is now refused by name, instead of sending sessions to an upgrade that cannot satisfy it #4080.
  • /investigate's "test again after your last edit" check now notices fixes written through shell commands such as sed -i or a heredoc #4078.
  • The /investigate and /plan-ceo-review gates no longer let a session end unchecked when their scan runs slowly #4072.
  • /runaway-stopper no longer flags agents that check in every four minutes while waiting on CI as runaways #4069.
  • The Ubicloud runner behind /ubicloud never treats an API error as success and never destroys a VM that another caller created under the same name #4039, #4046.

Changes for maintainers

  • /ship's finish and accept steps handle owner-granted fix rounds better: chained fix-checks all count, a granted round refreshes the money and security re-read on its own, owner-ruled notes close their findings, and the result names the grant it used #4050, #4064, #4070, #4077.
  • The money and security re-read record survives a later main merge, and accept takes its CI wait limit from the base ship policy (ci_record_timeout_s) #4058, #4065.
  • accept checks a branch under its own test policy when that branch only adds test runs, and an owner can grant an exception for one test run #4061.
  • The new ship-policy keys mechanical_retake and test_code require gstack 1.97.0.0 #4079.
  • On Capy, /ship helper commands now log their own calls so a run's call count is known #4059.
  • gstack's own repository now runs one paid release check on main every 8 hours, re-tests a pull request merged onto main's tip before merging it when main has moved, and has CI-skipped test files rerun before merge #4031, #4029, #4028.
  • The merge step hides its own environment, including the GitHub token, from the checks it runs on Linux #4032.
  • The release-file check accepts a release output that the repository's release tool regenerates #4033.
  • A pull request that edits setup no longer runs every paid eval case on a narrow screen #4056.
  • The free-CI slow-shard warning now accounts for shards split across parallel jobs, thanks @indraoverflow #4085.
  • Test repairs: two test files now pass in one process, and four flaky tests report why they failed #4068, #4074.
  • The evidence inventory records the latest routing and /investigate eval verdicts #4076.
  • gstack now generates a load-on-demand edition of three skills (investigate, review and plan review) for another agent host #4049.
  • Agent docs: agents on Capy comment and request reviews only through Capy's PR tools, agents running /ship sleep until it finishes and keep their context small, and AGENTS.md lists skills by name only #4027, #4055, #4060.
