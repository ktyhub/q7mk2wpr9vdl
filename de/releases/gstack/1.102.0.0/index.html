gstack v1.102.0.0

gstack 1.102.0.0 macht Codex zu einem erstklassigen Host: Es erhält jetzt die Skill-Vorschläge von gstack, den Destructive-Command-Check und den Checklist-Hold von /review. Die Prüfung auf zerstörerische Befehle wurde so umgebaut, dass sie deutlich seltener fragt und gleichzeitig viel mehr echten Schaden verursacht. Prüfung auf zerstörerische Befehle (/careful)

  • Es wird nicht mehr nach dem Löschen von Scratch-Dateien (/tmp-, mktemp-Ordner, Caches, Build-Ausgabe) gefragt, und es wird jetzt vor Löschvorgängen außerhalb Ihres Projekts gefragt, wodurch nicht festgeschriebene Arbeit, Verlaufsumschreibungen, Remote-Zweiglöschungen, Datenbank-Resets und Cloud-Löschungen verworfen werden. Ein rekursives Löschen von / oder Ihrem Home-Ordner, ein Force-Push zum Standardzweig und das Löschen einer gesamten Festplatte werden blockiert, egal wie sie geschrieben werden. Bei einer Wiederholung von 254.322 echten Agentenbefehlen sanken harmlose Anfragen von 1.40 % der Befehle auf 0.33 %, und die Zahl der abgefangenen destruktiven Befehle stieg von 443 auf 930 von 948. (#4513)
  • Es liest Befehle sorgfältiger: git push --repo=origin +main, Force-Pushes nach einem cd oder mit --all/--mirror, stille git clean -q, find -L … -delete und wipefs -a in jeder Schreibweise werden abgefangen; git push -nf Probeläufe und Greps für SQL-Text fragen nicht mehr nach. Bei derselben Wiederholung werden nicht weniger destruktive Befehle abgefangen und es kommen 141 harmlose Anfragen hinzu (0.39 % der Befehle insgesamt); Daran wird derzeit gearbeitet. (#4525)
  • Programme des Agenten SDK erhalten eine Warnung anstelle einer Frage, da der SDK eine Frage ablehnt, auf die niemand antwortet. Stellen Sie GSTACK_SESSION_KIND=interactive ein, um die Anfrage beizubehalten. (#4513) Kodex – ./setup --host codex (Codex 0.170+) fügt Hooks hinzu, die den richtigen Gstack-Skill für eine Eingabeaufforderung vorschlagen und die Prüfung auf destruktive Befehle vor jedem Shell-Befehl ausführen. Codex kann nicht nach einem einzelnen Befehl fragen, daher wird ein riskanter Befehl in interaktiven Sitzungen blockiert und unter codex exec gewarnt. Trust die Hooks, wenn Codex beim Start fragt. (#4512)
  • /review auf Codex wird einmal abgehalten, wenn es versucht, ohne seinen gegnerischen Pass oder Bericht zu beenden, wie auf Claude Code. (#4522) Es zählt einen Sol-Subagenten, der mit task_name gestartet wurde, als diesen Durchgang. (#4526)
  • Codex-Hooks funktionieren, wenn der Pfad Ihres Codex-Ordners Shell-Zeichen enthält, die Deinstallation Ihre eigenen Hooks trusted behält, das Setup besser mit dem Hook-Schema von Codex übereinstimmt und die Checkliste von /review zitierte ; liest und fehlgeschlagene Lesevorgänge korrekt sind. (#4528)
  • Fertigkeitsvorschläge, Auswahlaufforderungen und Dokumente benennen Fertigkeiten so, wie Codex sie auflistet ($review, nicht $gstack-review). (#4523, #4524)
  • Bürozeiten, Plan-Design-Überprüfung und Gstack-Upgrade werden erneut auf Codex geladen, ein Skill unter codex exec weiß, dass er unbeaufsichtigt ist, und Codex-Rezensenten beginnen mit einem sauberen Kontext. (#4510) Haken und Führung – Die Hilfs-Hooks sind standardmäßig aktiviert, die Prüfung auf destruktive Befehle wird als Hook ausgeführt und das Prompt-Routing wird bei langen Fehlerberichten ausgelöst. Mit den Fähigkeiten von gstack leitet der Routing-Hook 14 von 60 echten Fehlerberichten weiter (vorher 17); Die Dokumente stimmen jetzt überein. (#4503, #4505)
  • Der Routing-Hook schlägt jetzt auch selbst installierte Skills vor und sendet keine Fehlerberichte mehr an /qa. Mit installierten Fähigkeiten leitet es 40 von 60 echten Fehlerberichten weiter. (#4506) /Versand, Überprüfung und CI
  • Auf Capy bearbeitet oder kommentiert /ship keine Pull-Requests mehr unter Ihrem GitHub-Konto; Es übergibt den Text an Capys eigenes PR-Tool. (#4518) – Ein Befehl, dessen Ausgabe abgeschnitten wurde, schlägt jetzt fehl, anstatt anhand eines Teils seiner Ausgabe beurteilt zu werden. Dies schließt eine Lücke, bei der ein Push, dessen Diff 64 MiB überschritten hat, einen Berechtigungsnachweis über den Pre-Push-Hook hinaus übertragen könnte. (#4492, #4502)
  • Eine fehlgeschlagene Überprüfung des zweiten Modells nennt die Ursache, die sie gestoppt hat, zeichnet einen 402-Fehler als Budgetstopp auf und löscht niemals ihre eigene Eingabeaufforderung. (#4515, #4519)
  • Wenn ein Fix eine Zusammenführungsprüfung berührt, wird er jetzt in der zweiten Überprüfungsrunde überprüft, anstatt als erledigt zu melden. (#4520) – Die Ship-Richtlinie kann veröffentlichte Daten als Inhalt markieren, sodass /ship PRs mit großen Datenmengen überprüfen kann, und ein solcher Ordner kann Quellcode oder Agent-Dateien nicht vor der Überprüfung verbergen. (#4511, #4516)
  • /ship's review funktioniert, wenn der versendete Checkout nicht der Standard-Checkout des Projekts ist. (#4507)
  • Die Zustandsmaschinenprüfung von /ship akzeptiert die Headerzeilen, die sein Leser schreibt. (#4504) – Die Prüfung auf geänderte Nummer stoppt die Markierung von Tests, die nur ein Wort wie limit gemeinsam haben. Danke @dtoelke. (#4496) – PRs, die ein Release zusammengeführt haben, verwenden ihren früheren Testlauf wieder, als das Release nur eine deklarierte Datei neu generierte. (#4483) – Wenn Claude Code /verify vor einem Commit ausführt, erhält es eine schnelle Prüfung statt der vollständigen Fix-Schleife (#4508), und diese Prüfung schlägt bei einer Zeitüberschreitung einwandfrei fehl. (#4527) – Der Rezensionssammler lässt kein echtes P0 mehr fallen, das als zusammenfassendes Aufzählungszeichen geschrieben wurde, und hört auf, die Umfangslisten der Rezensenten als Ergebnisse zu lesen. (#4527) – gstack-ship-queue ready füllt nun seine Testzusammenführungen mit anderen offenen PRs aus und welches zweite Modell den Entscheidungsdatensatz überprüft hat, plus sechs kleine /ship-Tool-Korrekturen, einschließlich der Aufzeichnung einer von einem anderen Agenten weitergeleiteten Entscheidung. (#4529) – Testläufe, deren Worker in ihrer eigenen Sitzung starten, werden nicht mehr als angehalten beendet. Danke @dtoelke. (#4533) – Das Free-Suite-CI übersteht einen langsamen Ubuntu-Spiegel und vier fehlerhafte Tests und Evaluierungsprüfungen wurden behoben. (#4530) GBrain
  • Die Leseprüfung von /sync-gbrain funktioniert, wenn die erste Seite mehr als 64 KB groß ist. (#4497) – Wenn Sie ein zweites Repo synchronisieren, werden Sie nicht mehr vom ersten Repo zu einer erneuten Synchronisierung aufgefordert. Danke @SatriaSuriaAriffin. (#4532)

Englisches Original / English original

gstack v1.102.0.0

gstack 1.102.0.0 makes Codex a first-class host: it now gets gstack's skill suggestions, the destructive-command check and /review's checklist hold. The destructive-command check was rebuilt to ask far less often while catching far more real damage.

Destructive-command check (/careful)

  • It no longer asks about deleting scratch files (/tmp, mktemp folders, caches, build output), and it now asks before deletes outside your project, throwing away uncommitted work, history rewrites, remote branch deletes, database resets and cloud deletes. A recursive delete of / or your home folder, a force-push to the default branch, and wiping a whole disk are blocked however they're written. On a replay of 254,322 real agent commands, harmless asks fell from 1.40% of commands to 0.33%, and destructive commands caught rose from 443 to 930 of 948. (#4513)
  • It reads commands more carefully: git push --repo=origin +main, force-pushes after a cd or with --all/--mirror, quiet git clean -q, find -L … -delete, and wipefs -a in every spelling are caught; git push -nf dry runs and greps for SQL text no longer ask. On the same replay this catches no fewer destructive commands, and it adds 141 harmless asks (0.39% of commands in total); a follow-up is working on those. (#4525)
  • Agent SDK programs get a warning instead of an ask, because the SDK refuses an ask nobody answers. Set GSTACK_SESSION_KIND=interactive to keep the ask. (#4513)

Codex

  • ./setup --host codex (Codex 0.170+) adds hooks that suggest the right gstack skill for a prompt and run the destructive-command check before every shell command. Codex can't ask about a single command, so a risky one is blocked in interactive sessions and warned about under codex exec. Trust the hooks when Codex asks at startup. (#4512)
  • /review on Codex is held once if it tries to finish without its adversarial pass or report, as on Claude Code. (#4522) It counts a Sol subagent started with task_name as that pass. (#4526)
  • Codex hooks work when your Codex folder's path has shell characters, uninstall keeps your own hooks trusted, setup matches Codex's hook schema more closely, and /review's checklist reads quoted ; and failed reads correctly. (#4528)
  • Skill suggestions, picker prompts and docs name skills the way Codex lists them ($review, not $gstack-review). (#4523, #4524)
  • office-hours, plan-design-review and gstack-upgrade load again on Codex, a skill under codex exec knows it's unattended, and Codex reviewers start with a clean context. (#4510)

Hooks and routing

  • The helper hooks are on by default, the destructive-command check runs as a hook, and prompt routing fires on long bug reports. With gstack's own skills the routing hook routes 14 of 60 real bug reports (was 17); the docs now match. (#4503, #4505)
  • The routing hook now also suggests skills you've installed yourself, and stops sending bug reports to /qa. With installed skills it routes 40 of 60 real bug reports. (#4506)

/ship, review and CI

  • On Capy, /ship no longer edits or comments on pull requests under your GitHub account; it hands the text to Capy's own PR tool. (#4518)
  • A command whose output was cut off now fails instead of being judged on part of its output. This closes a gap where a push whose diff passed 64 MiB could carry a credential past the pre-push hook. (#4492, #4502)
  • A failed second-model review names the cause that stopped it, records a 402 as a budget stop, and never deletes its own prompt. (#4515, #4519)
  • When a fix touches a merge check, the second review round now reviews it instead of reporting done. (#4520)
  • Ship policy can mark published data as content so /ship can review large data PRs, and such a folder can't hide source code or agent files from review. (#4511, #4516)
  • /ship's review works when the checkout being shipped isn't the project's default checkout. (#4507)
  • /ship's state-machine check accepts the header lines its reader writes. (#4504)
  • The changed-number check stops flagging tests that only share a word like limit. Thanks @dtoelke. (#4496)
  • PRs that merged a release reuse their earlier test run when the release only regenerated a declared file. (#4483)
  • When Claude Code runs /verify before a commit, it gets a quick check instead of the full fix loop (#4508), and that check fails cleanly on a timeout. (#4527)
  • The review collector no longer drops a real P0 written as a summary bullet, and stops reading reviewers' scope lists as findings. (#4527)
  • gstack-ship-queue ready now fills in its trial merges against other open PRs and which second model checked the decision record, plus six small /ship tool fixes, including recording a ruling relayed from another agent. (#4529)
  • Test runs whose workers start in their own session are no longer killed as stalled. Thanks @dtoelke. (#4533)
  • Free-suite CI survives a slow Ubuntu mirror, and four flaky tests and eval checks were fixed. (#4530)

GBrain

  • /sync-gbrain's read check works when the first page is over 64 KB. (#4497)
  • Syncing a second repo no longer makes the first repo ask you to sync again. Thanks @SatriaSuriaAriffin. (#4532)
