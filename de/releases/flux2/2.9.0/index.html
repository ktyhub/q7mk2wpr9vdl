Flux2 v2.9.0

Highlights

Flux v2.9.0 ist ein Feature-Release. Benutzern wird empfohlen, ein Upgrade durchzuführen, um das beste Erlebnis zu erzielen. Eine ausführliche Übersicht über die neuen Funktionen und API-Änderungen, die in dieser Version enthalten sind, finden Sie im [Ankündigung von Flux 2.9 GA-Blogbeitrag] (https://fluxcd.io/blog/2026/06/flux-v2.9.0/). Die neuen Features im Überblick:

  • Flux CLI Plugin-System mit den Mirror- und Schema-Plugins (flux plugin)
  • Serverseitige Apply-Feld-Ignorierungsregeln für eine feinkörnige Driftkontrolle (Kustomization)
  • SOPS-Entschlüsselung mit der Age-Post-Quantum-Chiffre (Kustomization)
  • Kubernetes Workload Identity-Authentifizierung für OpenBao und Vault (Kustomization)
  • Helm-Post-Render-Strategien, einschließlich Chart-Hooks-Unterstützung (HelmRelease)
  • Literalmodus für Helm-Werte-Referenzen, die helm --set-literal (HelmRelease) spiegeln – Leere Typen in CEL-Zustandsprüfungsausdrücken zulassen (Kustomization, HelmRelease)
  • Git-Commit-Signierung und -Verifizierung mit SSH-Schlüsseln (GitRepository, ImageUpdateAutomation)
  • AWS CodeCommit-Authentifizierung mit Workload Identity (GitRepository)
  • Benutzerdefiniertes Sigstore trusted-Root für die schlüssellose Überprüfung in Umgebungen mit Luftspalt (OCIRepository)
  • Pfadmusterverzeichniserkennung für Monorepos (ArtifactGenerator)
  • Geheimlose, OIDC-gesicherte Webhook-Empfänger (Receiver) ❤️ Vielen Dank an alle Flux-Mitwirkenden, die uns bei dieser Veröffentlichung geholfen haben!

Kubernetes-Kompatibilität

Diese Version ist mit den folgenden Kubernetes-Versionen kompatibel: | Kubernetes-Version | Erforderliches Minimum | |------|----| | v1.34 | >= 1.34.1 | | v1.35 | >= 1.35.0 | | v1.36 | >= 1.36.0 |

[!NOTE] Beachten Sie, dass das Flux-Projekt nur Unterstützung für die neuesten drei Nebenversionen von Kubernetes bietet. Abwärtskompatibilität mit älteren Versionen von Kubernetes und OpenShift wird von Anbietern wie z. B. angeboten ControlPlane, die Unternehmensunterstützung für Flux bieten.

OpenShift-Kompatibilität

Flux kann mit Flux Operator direkt von OperatorHub auf dem Red Hat OpenShift-Cluster installiert werden. Der Betreiber ermöglicht die Konfiguration der Flux-Mehrmandantensperre, Netzwerkrichtlinien, persistenten Speicher, Sharding, vertikale Skalierung und die Synchronisierung des Clusterstatus aus Git-Repositorys, OCI-Artefakten und S3-kompatiblem Speicher.

Upgrade-Verfahren

:warnung: Die Flux APIs image.toolkit.fluxcd.io/v1beta2 und notification.toolkit.fluxcd.io/v1beta2 das Ende ihrer Lebensdauer erreicht haben und aus den CRDs entfernt wurden. Bitte befolgen Sie das Upgrade-Verfahren für Flux v2.7+, um ein reibungsloses Upgrade von älteren Versionen von Flux auf v2.9 zu gewährleisten.

flux2 v2.9.0

Highlights

Flux v2.9.0 is a feature release. Users are encouraged to upgrade for the best experience.

For a compressive overview of new features and API changes included in this release, please refer to the Announcing Flux 2.9 GA blog post.

Overview of the new features:

  • Flux CLI Plugin System with the Mirror and Schema plugins (flux plugin)
  • Server-Side Apply field ignore rules for fine-grained drift control (Kustomization)
  • SOPS decryption with the Age post-quantum cipher (Kustomization)
  • Kubernetes Workload Identity authentication for OpenBao and Vault (Kustomization)
  • Helm post-render strategies, including chart hooks support (HelmRelease)
  • Literal mode for Helm values references mirroring helm --set-literal (HelmRelease)
  • Allow empty kind in CEL health check expressions (Kustomization, HelmRelease)
  • Git commit signing and verification with SSH keys (GitRepository, ImageUpdateAutomation)
  • AWS CodeCommit authentication using Workload Identity (GitRepository)
  • Custom Sigstore trusted root for keyless verification in air-gapped environments (OCIRepository)
  • Path pattern directory discovery for monorepos (ArtifactGenerator)
  • Secret-less, OIDC-secured webhook Receivers (Receiver)

❤️ Big thanks to all the Flux contributors that helped us with this release!

Kubernetes compatibility

This release is compatible with the following Kubernetes versions:

| Kubernetes version | Minimum required | |--------------------|------------------| | v1.34 | >= 1.34.1 | | v1.35 | >= 1.35.0 | | v1.36 | >= 1.36.0 |

[!NOTE] Note that the Flux project offers support only for the latest three minor versions of Kubernetes. Backwards compatibility with older versions of Kubernetes and OpenShift is offered by vendors such as ControlPlane that provide enterprise support for Flux.

OpenShift compatibility

Flux can be installed on Red Hat OpenShift cluster directly from OperatorHub using Flux Operator. The operator allows the configuration of Flux multi-tenancy lockdown, network policies, persistent storage, sharding, vertical scaling and the synchronization of the cluster state from Git repositories, OCI artifacts, and S3-compatible storage.

Upgrade procedure

:warning: The Flux APIs image.toolkit.fluxcd.io/v1beta2 and notification.toolkit.fluxcd.io/v1beta2 have reached end-of-life and have been removed from the CRDs.

Please follow the Upgrade Procedure for Flux v2.7+ for a smooth upgrade from older versions of Flux to v2.9.
