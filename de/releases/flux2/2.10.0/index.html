Flux2 v2.10.0

Highlights

Flux v2.10.0 ist eine Feature-Version. Benutzern wird empfohlen, ein Upgrade durchzuführen, um das beste Erlebnis zu erzielen. Die neuen Features im Überblick:

  • Objektidentität ist allgemein verfügbar; Das Feature-Gate ObjectLevelWorkloadIdentity wurde eingestellt
  • SPIFFE mTLS für die Kommunikation zwischen Controllern
  • Benachrichtigung Event, Alert und Provider APIs hochgestuft zu v1
  • OCIRepository als Diagrammquelle für HelmRelease
  • SOPS-Entschlüsselung für mit Kommentar-Regexes verschlüsselte Dateien und --override-manager-before-dry-run (Kustomization)
  • Stapelverarbeitung von Bildaktualisierungen mit .spec.policyChangeDelay, erneuter Versuch bei abgelehnten Pushs und .Changed.Summary (ImageUpdateAutomation) – Flux-Artefakt-Speicher-Backend standardmäßig für ImageRepository-Tags aktiviert – Namensraumübergreifende Artefakte, Bereitstellung von Mandanten-Namensräumen und Erkennung von Pfadmustern (ArtifactGenerator)
  • Neue Benachrichtigungsanbieter für Zoom, Incident.io und Mastodon
  • Gebaut mit Kubernetes 1.37 und Go 1.27 ❤️ Vielen Dank an alle Flux-Mitwirkenden, die uns bei dieser Veröffentlichung geholfen haben!

Kubernetes-Kompatibilität

Diese Version ist mit den folgenden Kubernetes-Versionen kompatibel: | Kubernetes-Version | Erforderliches Minimum | |------|----| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTE] Beachten Sie, dass das Flux-Projekt nur Unterstützung für die neuesten drei Nebenversionen von Kubernetes bietet. Abwärtskompatibilität mit älteren Versionen von Kubernetes und OpenShift wird von Anbietern wie z. B. angeboten ControlPlane, die Unternehmensunterstützung für Flux bieten.

OpenShift-Kompatibilität

Flux kann mit Flux Operator direkt von OperatorHub auf dem Red Hat OpenShift-Cluster installiert werden. Der Betreiber ermöglicht die Konfiguration der Flux-Mehrmandantensperre, Netzwerkrichtlinien, persistenten Speicher, Sharding, vertikale Skalierung und die Synchronisierung des Clusterstatus aus Git-Repositorys, OCI-Artefakten und S3-kompatiblem Speicher.

Upgrade-Verfahren

⚠️ Wichtige Änderungen in dieser Version: – Die Objektidentität ist immer aktiviert und der Standard-Flux-RBAC gewährt das Verb create für die Ressource serviceaccounts/token nicht mehr. Wenn Ihre Installation auf dem Standard-RBAC basiert, binden Sie vor dem Upgrade eine ClusterRole mit dieser Berechtigung an das Controller-ServiceAccount. Siehe fluxcd/flux2#6139 für die erforderliche ClusterRole und ClusterRoleBinding. – Die Benachrichtigungen Alert und Provider API werden zu v1 hochgestuft. Beim Konvertieren eines v1beta3 Alert oder Provider in v1 werden die veralteten Felder Alert.spec.summary und Provider.spec.interval, das statische JWT-Token für Azure Event Hub und die TLS- oder Proxy-Konfiguration in Provider.spec.secretRef gelöscht. Verwenden Sie stattdessen eventMetadata.summary, proxySecretRef und certSecretRef. – Das Flux-Artefaktspeicher-Backend ist jetzt der Standard für die Tag-Datenbank ImageRepository. Durch den Wechsel des Gates wird die lokale Tag-Datenbank gelöscht, sodass beim ersten Abgleich nach dem Upgrade alle ImageRepository erneut gescannt werden. Legen Sie --feature-gates=FluxStorage=false fest, um BadgerDB weiterhin zu verwenden. – Die Remote-Cluster-Authentifizierung mit .spec.kubeConfig.configMapRef verwendet die Objektidentität. Ersetzen Sie den alten audiences-Schlüssel durch credential.auth.fluxcd.io/audiences. Bitte befolgen Sie das Upgrade-Verfahren für Flux v2.7+ für ein reibungsloses Upgrade von älteren Versionen von Flux auf v2.10.

flux2 v2.10.0

Highlights

Flux v2.10.0 is a feature release. Users are encouraged to upgrade for the best experience.

Overview of the new features:

  • Object identity is generally available; the ObjectLevelWorkloadIdentity feature gate is retired
  • SPIFFE mTLS for inter-controller communication
  • Notification Event, Alert and Provider APIs promoted to v1
  • OCIRepository as a chart source for HelmRelease
  • SOPS decryption for files encrypted with comment regexes, and --override-manager-before-dry-run (Kustomization)
  • Image update batching with .spec.policyChangeDelay, retry on rejected pushes, and .Changed.Summary (ImageUpdateAutomation)
  • Flux artifact storage backend enabled by default for ImageRepository tags
  • Cross-namespace artifacts, tenant namespace provisioning, and path-pattern discovery (ArtifactGenerator)
  • New Zoom, incident.io and Mastodon notification providers
  • Built with Kubernetes 1.37 and Go 1.27

❤️ Big thanks to all the Flux contributors that helped us with this release!

Kubernetes compatibility

This release is compatible with the following Kubernetes versions:

| Kubernetes version | Minimum required | |--------------------|------------------| | v1.35 | >= 1.35.2 | | v1.36 | >= 1.36.1 | | v1.37 | >= 1.37.0 |

[!NOTE] Note that the Flux project offers support only for the latest three minor versions of Kubernetes. Backwards compatibility with older versions of Kubernetes and OpenShift is offered by vendors such as ControlPlane that provide enterprise support for Flux.

OpenShift compatibility

Flux can be installed on Red Hat OpenShift cluster directly from OperatorHub using Flux Operator. The operator allows the configuration of Flux multi-tenancy lockdown, network policies, persistent storage, sharding, vertical scaling and the synchronization of the cluster state from Git repositories, OCI artifacts, and S3-compatible storage.

Upgrade procedure

⚠️ Breaking changes in this release:

  • Object identity is always enabled and the default Flux RBAC no longer grants the create verb on the serviceaccounts/token resource. If your installation relies on the default RBAC, bind a ClusterRole with this permission to the controller ServiceAccount before upgrading. See fluxcd/flux2#6139 for the required ClusterRole and ClusterRoleBinding.
  • The notification Alert and Provider APIs are promoted to v1. Converting a v1beta3 Alert or Provider to v1 drops the deprecated Alert.spec.summary and Provider.spec.interval fields, the static JWT token for Azure Event Hub, and TLS or proxy configuration in Provider.spec.secretRef. Use eventMetadata.summary, proxySecretRef and certSecretRef instead.
  • The Flux artifact storage backend is now the default for the ImageRepository tag database. Switching the gate wipes the local tag database, so the first reconciliation after the upgrade rescans every ImageRepository. Set --feature-gates=FluxStorage=false to keep using BadgerDB.
  • Remote cluster authentication with .spec.kubeConfig.configMapRef uses object identity; replace the legacy audiences key with credential.auth.fluxcd.io/audiences.

Please follow the Upgrade Procedure for Flux v2.7+ for a smooth upgrade from older versions of Flux to v2.10.
