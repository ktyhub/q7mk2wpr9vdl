Endbenutzer Changelog

🛑 Breaking Changes 🛑

  • pkg/confighttp: Stabilisiertes Tor confighttp.framedSnappy entfernen (#15420)
  • pkg/configoptional: Stabilisiertes Tor configoptional.AddEnabledField entfernen. (#15421)
  • pkg/confmap: Stabilisiertes Featuregate confmap.newExpandedValueSanitizer entfernen (#15418)
  • pkg/exporterhelper: Stalltor exporter.PersistRequestContext entfernen. (#15424)
  • pkg/otelcol: Stalltor otelcol.printInitialConfig entfernen (#15425)
  • pkg/service: Stabiles Featuregate telemetry.UseLocalHostAsDefaultMetricsAddress entfernen (#15419)
  • pkg/xpdata: Stalltor pdata.enableRefCounting entfernen. (#15426) – processor/memory_limiter: Veraltete Speicherbegrenzermetriken umbenennen, um das Präfix memory_limiter (z. B. otelcol_processor_memory_limiter_*) einzuschließen, um zu verdeutlichen, dass sie spezifisch für diesen Prozessor sind. (#11203)

🚀 Neue Komponenten 🚀

  • cmd/schemagen: Verschieben Sie schemagen CLI aus opentelemetry-collector-contrib in dieses Repository als cmd/schemagen. (#14543) Die Quelle des Tools ist identisch mit der Upstream-Contrib-Version (github.com/open-telemetry/opentelemetry-collector-contrib/cmd/schemagen) mit Ausnahme des Modulpfads und den Namensraum der Testvorrichtungen, der nun das Kollektormodul widerspiegelt (go.opentelemetry.io/collector/cmd/schemagen). Ein Integrationstest nur mit Beiträgen, der auf drei hinwies Beitragskomponenten wurden entfernt; contribs bestehendes make generate-schemas + git-diff CI bleibt bestehen Üben Sie die FactoryMaps-Funktion anhand realer Komponenten aus.

💡 Verbesserungen 💡

– cmd/mdatagen: Unterstützung für versionierte Metriken hinzugefügt (#15309) Ermöglicht Metadaten die Angabe versionierter Metriken für die Migration zu neuen semantischen Konventionen. Es gibt zwei Szenarios, in denen der Metrikname während der Migration gleich bleibt. Wenn der Name einer Metrik gleich bleibt, ihr Typ jedoch unterschiedlich ist, gilt nur die neueste Metrik mit dem neuen Typ ausgegeben. Wenn der Name einer Metrik gleich bleibt, sich ihre Attribute jedoch unterscheiden, ist dies die neueste Version wird während des Migrationszeitraums mit kombinierten Attributen ausgegeben. – cmd/schemagen: overlayFile-Unterstützung hinzufügen, um handkuratierte Schemafragmente tief in generierte Schemata zusammenzuführen. (#14543) Komponenten können einen overlayFile in .schemagen.yaml deklarieren, der auf eine YAML-Datei verweist deren Schlüssel nach der Generierung rekursiv in das automatisch generierte Schema eingefügt werden. Dies ermöglicht das Einfügen von Beschreibungen, Einschränkungen oder zusätzlichen Eigenschaften, die nicht möglich sind von Go-Typen abgeleitet werden. Ursprünglich zur Beitragskopie von cmd/schemagen hinzugefügt open-telemetry/opentelemetry-collector-contrib#48917 und mit dem Tool übertragen in diesem Schritt. – cmd/schemagen: Flag -p hinzufügen, um ein benutzerdefiniertes Go-Paketmuster für die Konfigurationsstruktur anzugeben. (#14543) Mit dem neuen Flag -p können Aufrufer das Standardpaketmuster . mit einem beliebigen Muster überschreiben Go-Paketselektor (z. B. ein Unterpaket, dessen Schemagen vom Typ Config laufen soll). Ursprünglich zur Beitragskopie von cmd/schemagen hinzugefügt open-telemetry/opentelemetry-collector-contrib#48966 und mit dem Tool übertragen in diesem Schritt.

🧰 Fehlerbehebungen 🧰

– cmd/mdatagen: Behebung eines Problems, wenn das letzte Feature-Gate entfernt wird und veraltete Dateien zurückbleiben. (#15423)

  • cmd/mdatagen: Korrigieren Sie bekannte Akronyme am Ende der generierten Go-Bezeichner so, dass sie nur in Großbuchstaben geschrieben sind, genau wie an jeder anderen Position (#15438)
  • cmd/schemagen: Moduserkennung behoben, wenn -p verwendet wird, um ein Paket außerhalb des aktuellen Verzeichnisses anzusprechen. (#15453) Ein neues -m component|package-Flag ist als manuelle Überschreibung verfügbar, wenn eine automatische Erkennung nicht möglich ist.

API Changelog

🛑 Breaking Changes 🛑

– cmd/mdatagen: Entfernen Sie die Metadateneinstellung reaggregation_enabled und generieren Sie immer eine Reaggregationskonfiguration pro Metrik. (#15305) Ältere Metadatendateien, die noch reaggregation_enabled enthalten, werden akzeptiert, der Wert wird jedoch ignoriert.

🚩 Abwertungen 🚩

  • pkg/service: Veralten Sie service.Settings.CollectorConf und extensioncapabilities.ConfigWatcher zugunsten von service.Settings.ConfigSnapshot und extensioncapabilities.ConfigSnapshotWatcher, die effektive und nicht erweiterte Konfigurationsdarstellungen bereitstellen. (#15432)

💡 Verbesserungen 💡

  • pkg/config/configmiddleware: Middleware-Konfiguration auf Schemabasis migriert (#15440) – pkg/pdata: Fügen Sie die Option DisallowUnknownFields zu JSONUnmarshaler in plog, ptrace, pmetric, pprofile und xpdata hinzu, um Fehler bei JSON-Feldern zu vermeiden, die nicht durch das OTLP-Schema definiert sind. (#15279) Wenn DisallowUnknownFields „false“ ist (Standardeinstellung), werden unbekannte Felder stillschweigend ignoriert, was dem vorherigen Verhalten entspricht. Warnung: Durch die Aktivierung dieser Option wird die Vorwärtskompatibilität mit zukünftigen Weiterentwicklungen des OTLP-Formats beeinträchtigt, da Felder, die dem Format in neueren Versionen hinzugefügt wurden, als unbekannt abgelehnt werden.

🧰 Fehlerbehebungen 🧰

– cmd/mdatagen: Korrigieren Sie bekannte Akronyme am Ende der generierten Go-Bezeichner so, dass sie wie an jeder anderen Position nur in Großbuchstaben geschrieben sind (#15438)

opentelemetry-collector v0.155.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.155.0

End User Changelog

🛑 Breaking changes 🛑

  • pkg/confighttp: Remove stabilized gate confighttp.framedSnappy (#15420)
  • pkg/configoptional: Remove stabilized gate configoptional.AddEnabledField. (#15421)
  • pkg/confmap: Remove stabilized featuregate confmap.newExpandedValueSanitizer (#15418)
  • pkg/exporterhelper: Remove stable gate exporter.PersistRequestContext. (#15424)
  • pkg/otelcol: Remove stable gate otelcol.printInitialConfig (#15425)
  • pkg/service: Remove stable featuregate telemetry.UseLocalHostAsDefaultMetricsAddress (#15419)
  • pkg/xpdata: Remove stable gate pdata.enableRefCounting. (#15426)
  • processor/memory_limiter: Rename deprecated memory limiter metrics to include the memory_limiter prefix (e.g. otelcol_processor_memory_limiter_*) to clarify they are specific to this processor. (#11203)

🚀 New components 🚀

  • cmd/schemagen: Move the schemagen CLI from opentelemetry-collector-contrib to this repository as cmd/schemagen. (#14543) The tool's source is identical to the upstream contrib version (github.com/open-telemetry/opentelemetry-collector-contrib/cmd/schemagen) except for the module path and the test fixtures' namespace, which now reflect the collector module (go.opentelemetry.io/collector/cmd/schemagen). A contrib-only integration test that pointed at three contrib components is removed; contrib's existing make generate-schemas + git-diff CI continues to exercise the FactoryMaps feature against real-world components.

💡 Enhancements 💡

  • cmd/mdatagen: Add support for versioned metrics (#15309) Allows metadata to specify versioned metrics for migrating to new semantic conventions. There are two scenarios catered for when the metric name stays the same during migration. When a metric name stays the same but its type differs, just the latest metric is emitted with the new type. When a metric name stays the same but its attributes differ, the latest version is emitted with combined attributes during the migration period.

  • cmd/schemagen: Add overlayFile support to deep-merge hand-curated schema fragments into generated schemas. (#14543) Components can declare an overlayFile in .schemagen.yaml pointing to a YAML file whose keys are recursively merged into the auto-generated schema after generation. This allows injecting descriptions, constraints, or additional properties that cannot be derived from Go types. Originally added to the contrib copy of cmd/schemagen in open-telemetry/opentelemetry-collector-contrib#48917 and brought over with the tool in this move.

  • cmd/schemagen: Add -p flag to specify a custom Go package pattern for the config struct. (#14543) The new -p flag lets callers override the default . package pattern with an arbitrary Go package selector (e.g. a sub-package whose Config type schemagen should walk). Originally added to the contrib copy of cmd/schemagen in open-telemetry/opentelemetry-collector-contrib#48966 and brought over with the tool in this move.

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix an issue when the last feature gate is removed, stale files are left. (#15423)
  • cmd/mdatagen: Fix known acronyms at the end of generated Go identifiers to be all-caps, same as in any other position (#15438)
  • cmd/schemagen: Fix mode detection when using -p to target a package outside the current directory. (#15453) A new -m component|package flag is available as a manual override when auto-detection is not possible.

API Changelog

🛑 Breaking changes 🛑

  • cmd/mdatagen: Remove the reaggregation_enabled metadata setting and always generate per-metric reaggregation config. (#15305) Legacy metadata files that still contain reaggregation_enabled are accepted, but the value is ignored.

🚩 Deprecations 🚩

  • pkg/service: Deprecate service.Settings.CollectorConf and extensioncapabilities.ConfigWatcher in favor of service.Settings.ConfigSnapshot and extensioncapabilities.ConfigSnapshotWatcher, which provide effective and unexpanded configuration representations. (#15432)

💡 Enhancements 💡

  • pkg/config/configmiddleware: Migrated middleware config to schema based (#15440)
  • pkg/pdata: Add DisallowUnknownFields option to JSONUnmarshaler in plog, ptrace, pmetric, pprofile, and xpdata to error on JSON fields not defined by the OTLP schema. (#15279) When DisallowUnknownFields is false (the default), unknown fields are silently ignored, matching the previous behavior. Warning: enabling this option breaks forwards compatibility with future evolutions of the OTLP format, as fields added to the format in newer versions will be rejected as unknown.

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix known acronyms at the end of generated Go identifiers to be all-caps, same as in any other position (#15438)
