opentelemetry-Kollektor v0.165.0

Bilder und Binärdateien hier: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

Endbenutzer Changelog

🛑 Breaking Changes 🛑

  • pkg/confighttp: Veraltete Felder IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives entfernen. (#15973)

🚀 Neue Komponenten 🚀

– pkg/xreceiverhelper: Fügen Sie xreceiverhelper mit einem ObsReport hinzu, der Profilbeispielmetriken pro Beispieltyp meldet. (#16251) ObsReport.EndProfilesOpBySampleType zeichnet die auf otelcol_receiver_{accepted,refused,failed}_profile_samples-Metriken mit einer zusätzlichen sample_type-Attribut, formatiert als „type:unit“, da eine einzelne Nutzlast mehrere Profile enthalten kann mit unterschiedlichen Probentypen. Verwenden Sie ProfileSampleCountsByType, um die Probenanzahl vorher zu berechnen Die Profile werden an den nächsten Verbraucher weitergegeben, da die Daten nachgelagert möglicherweise verändert werden. Der OTLP-Empfänger verwendet jetzt EndProfilesOpBySampleType.

💡 Verbesserungen 💡

  • pkg/configmiddleware: erlaubt das Überschreiben des von confighttp.ToClient und configgrpc.ToClient verwendeten Dialers (#16019) – pkg/featuregate: Unterstriche in Feature-Gate-IDs zulassen. (#16243)
  • pkg/pdata: Verbessern Sie die Leistung der Funktionen pcommon.Map Get, Range und All. (#16282, #16321)
  • pkg/pdata: Reduzieren Sie die Anzahl der Zuweisungen beim Aktualisieren eines Oneof-Primitivs (#16226)
  • pkg/service: Der Dienst unterstützt jetzt die Konfiguration zusätzlicher Ressourcendetektoren für interne Telemetrie gemäß dem Update auf otelconf v0.26.0. (#15869) – pkg/service: Warnung beim Start, wenn eine Pipeline den Batch-Prozessor mit der Exporterhelper-Batching-Funktion kombiniert. (#15965) Die Erkennung kreuzt keine Konnektoren und prüft keine Exporter-Wrapper, die die Batch-Funktion von exporterhelper verbergen.
  • pkg/xprocessorhelper: Instrument xprocessorhelper.NewProfiles mit otelcol_processor_incoming_items, otelcol_processor_outgoing_items und otelcol_processor_internal_duration, konsistent mit den anderen Signalkonstruktoren. (#15523) – processor/memory_limiter: Konfigurationsabschnitt garbage_collector hinzugefügt, um die Deaktivierung der erzwungenen Garbage Collection über das Feld enabled zu ermöglichen. (#15081) – processor/queue_batch: Heraufstufen des queue_batch-Prozessors auf Beta für Ablaufverfolgungen, Metriken und Protokolle und auf Alpha für Profile. (#12022)
  • processor/queue_batch: Warteschlangen- und Batch-Metriken als Prozessormetriken melden (#14038)

🧰 Fehlerbehebungen 🧰

  • cmd/mdatagen: Panik in Attribute.TestValue() und Attribute.TestValueTwo() bei der Verarbeitung von Einzelelement- oder leeren Enum-Attributen behoben. (#15644) – cmd/mdatagen: Behebung eines Fehlers bei generierten Metriktests, wenn die through_gates-Feature-Gates einer Metrikmigration nach der Alpha hochgestuft werden. (#16249) Die generierten Tests legen nun explizit die Migrationsfeature-Gates für jeden Testfall und jede Wiederherstellung fest Sie erhalten bei der Bereinigung ihren vorherigen Zustand zurück, anstatt davon auszugehen, dass die Tore standardmäßig deaktiviert sind. Wenn die Phase eines Gates den Zustand verbietet, den ein Fall benötigt, beispielsweise das Deaktivieren eines Stable Gates, des Metrik-Builders Der Test überspringt nur seine gatterabhängigen Zähl- und Warnzusicherungen sowie die versionierte Metrik pro Kombination Untertests für diese Kombination werden übersprungen.
  • cmd/mdatagen: Generieren Sie README-Konfigurationsdokumente für exported_configs-Definitionen. (#16164) Objektdefinitionen und Skalartyp-Aliase unter exported_configs werden jetzt in der README-Datei nach der Tabelle config: gerendert. Pakete, die nur exported_configs deklarieren, können jetzt generierte Dokumente erhalten, sobald ihre README-Datei die Konfigurationsmarkierungen enthält. Komponenten, die nur exported_configs deklarieren, erhalten keine leere Konfigurationstabelle mehr.
  • cmd/schemagen: Fehler beim Laden von Schemata aufgrund nicht gefundener Dateien behandeln (#15925) – pkg/configgrpc: Begrenzte das ZSTD-Decoderfenster durch die konfigurierte maximale Empfangsnachrichtengröße anstelle der Bibliotheksvorgabe. (#16280) Ein ZSTD-Frame deklariert sein Fenster im Header und der Decoder weist es zu bevor eine Ausgabe erzeugt wird, so dass eine kleine, gestaltete Nachricht eine große Wirkung erzielen kann Zuordnung unabhängig von max_recv_msg_size_mib. Der Decoder ist auch wird in seinen Pool zurückgegeben, sobald gRPC mit einer Nachricht fertig ist.
  • pkg/confighttp: Das zstd-Decoderfenster wurde durch max_request_body_size anstelle des Bibliotheksstandards gebunden. (#16280) Ein ZSTD-Frame deklariert sein Fenster im Header und der Decoder weist es zu bevor irgendeine Leistung erzeugt wurde, sodass ein kleiner gefertigter Körper einen großen antreiben konnte Zuweisung unabhängig von der konfigurierten Größe des Anforderungstexts. – pkg/confighttp: Content-Encoding: Identität als Äquivalent zu keiner Codierung akzeptieren. (#15122) – pkg/exporterhelper: Behebung einer Cannot unref freed data-Panik, wenn eine persistente Sendewarteschlange Anforderungen an eine andere Pipeline weiterleitet (#15256)
  • pkg/exporterhelper: Mit wait_for_result wird das Abbrechen einer Anfrage, die die Sendewarteschlange bereits angenommen hat, nicht mehr vorzeitig zurückgegeben (#16255) Zuvor führte ein abgebrochener Kontext dazu, dass context.Canceled zurückgegeben wurde, während die Anfrage noch aktiv war zugestellt, sodass Anrufer einen Fehler bei den gesendeten Daten melden konnten. Das Stornieren dauert noch wirksam, solange mit der Anfrage noch nichts gemacht wurde. – pkg/pdata: Rekursionstiefenlimit (100) zum Proto-Unmarshalling von AnyValue, ArrayValue, KeyValueList und KeyValue hinzugefügt, um einen Stapelüberlauf durch in böser Absicht erstellte, tief verschachtelte Nutzlasten zu verhindern. (#15301) – pkg/service: Diagrammknoten überspringen, die beim Herunterfahren nicht erstellt wurden, um eine Panik zu verhindern, wenn ein teilweises Neuladen des Empfängers beim Erstellen eines Empfängers fehlschlägt. (#16261)

Englisches Original / English original

opentelemetry-collector v0.165.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

End User Changelog

🛑 Breaking changes 🛑

  • pkg/confighttp: Remove deprecated fields IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives. (#15973)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types. Use ProfileSampleCountsByType to compute the sample counts before the profiles are passed to the next consumer, as the data may be mutated downstream. The OTLP receiver now uses EndProfilesOpBySampleType.

💡 Enhancements 💡

  • pkg/configmiddleware: allow to override the dialer used by confighttp.ToClient and configgrpc.ToClient (#16019)
  • pkg/featuregate: Allow underscores in feature gate IDs. (#16243)
  • pkg/pdata: Improve performance of pcommon.Map Get, Range, and All functions. (#16282, #16321)
  • pkg/pdata: Reduce number of allocations when updating an oneof primitive (#16226)
  • pkg/service: Service now supports configuring additional resource detectors for internal telemetry as per the update to otelconf v0.26.0. (#15869)
  • pkg/service: Warn at startup when a pipeline combines the batch processor with exporterhelper batching. (#15965) Detection does not cross connectors or inspect exporter wrappers that hide exporterhelper's batching capability.
  • pkg/xprocessorhelper: Instrument xprocessorhelper.NewProfiles with otelcol_processor_incoming_items, otelcol_processor_outgoing_items, and otelcol_processor_internal_duration, consistent with the other signal constructors. (#15523)
  • processor/memory_limiter: Add garbage_collector config section to allow disabling forced garbage collection via enabled field. (#15081)
  • processor/queue_batch: Promote the queue_batch processor to beta for traces, metrics, and logs, and to alpha for profiles. (#12022)
  • processor/queue_batch: Report queue and batch metrics as processor metrics (#14038)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix panic in Attribute.TestValue() and Attribute.TestValueTwo() when handling single-element or empty enum attributes. (#15644)

  • cmd/mdatagen: Fix generated metrics tests failing when a metric migration's through_gates feature gates are promoted past alpha. (#16249) The generated tests now explicitly set the migration feature gates for each test case and restore their previous state on cleanup, instead of assuming the gates are disabled by default. When a gate's stage forbids the state a case needs, such as disabling a stable gate, the metrics-builder test skips only its gate-dependent count and warning assertions, and the per-combination versioned-metric sub-tests for that combination are skipped.

  • cmd/mdatagen: Generate README configuration docs for exported_configs definitions. (#16164) Object definitions and scalar type aliases under exported_configs are now rendered in the README after the config: table. Packages that only declare exported_configs can now get generated docs once their README contains the config markers. Components that only declare exported_configs no longer get an empty configuration table.

  • cmd/schemagen: Handle file-not-found errors when loading schemas (#15925)

  • pkg/configgrpc: Bound the zstd decoder window by the configured maximum receive message size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted message could drive a large allocation regardless of max_recv_msg_size_mib. The decoder is also returned to its pool as soon as gRPC is done with a message.

  • pkg/confighttp: Bound the zstd decoder window by max_request_body_size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted body could drive a large allocation regardless of the configured request body size.

  • pkg/confighttp: Accept Content-Encoding: identity as equivalent to no encoding. (#15122)

  • pkg/exporterhelper: Fix a Cannot unref freed data panic when a persistent sending queue forwards requests into another pipeline (#15256)

  • pkg/exporterhelper: With wait_for_result, canceling a request that the sending queue already accepted no longer returns early (#16255) Previously a canceled context made it return context.Canceled while the request was still delivered, so callers could report a failure for data that had been sent. Canceling still takes effect while nothing has been done with the request.

  • pkg/pdata: Add recursion depth limit (100) to proto unmarshalling of AnyValue, ArrayValue, KeyValueList, and KeyValue to prevent stack overflow from maliciously crafted deeply nested payloads. (#15301)

  • pkg/service: Skip graph nodes that have not been built during shutdown to prevent a panic when a partial receiver reload fails to build a receiver. (#16261)

API Changelog

🚩 Deprecations 🚩

  • pkg/componentstatus: Deprecate componentstatus.Watcher in favour of extensioncapabilities.ComponentStatusWatcher (#16304)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types. Use ProfileSampleCountsByType to compute the sample counts before the profiles are passed to the next consumer, as the data may be mutated downstream. The OTLP receiver now uses EndProfilesOpBySampleType.

💡 Enhancements 💡

  • pkg/confighttp: Mark confighttp as stable (#9380)
  • receiver/otlp: Migrate the OTLP receiver configuration to metadata.yaml and generate its config schema from the metadata. (#16212)
