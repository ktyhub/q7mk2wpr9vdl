Endbenutzer Changelog

❗Bekannte Probleme❗

– service: Der interne Prometheus-Metrikendpunkt des Kollektors (:8888) gibt jetzt OTel-Dienstbezeichnungen mit Unterstrich aus Namen (service_name, service_instance_id, service_version) anstelle von Namen in Punktnotation (service.name, service.instance.id, service.version). Benutzer, die diesen Endpunkt mit dem Prometheus-Empfänger scraping verwenden, werden diese umbenannt sehen Beschriftungen in Ressourcen- und Datenpunktattributen. Um dieses Problem zu umgehen, fügen Sie Ihrem Scrape das folgende metric_relabel_configs hinzu Konfiguration im prometheus-Empfänger:

metric_relabel_configs:
  - source_labels: [service_name]
    target_label: service.name
  - source_labels: [service_instance_id]
    target_label: service.instance.id
  - source_labels: [service_version]
    target_label: service.version
  - regex: service_name|service_instance_id|service_version
    action: labeldrop

Einzelheiten und Aktualisierungen finden Sie unter https://github.com/open-telemetry/opentelemetry-collector/issues/14814.

🛑 Breaking Changes 🛑

  • all: Ändern Sie die metrischen Einheiten in Singulareinheiten, um sie an die OTel-Spezifikation anzupassen, z. B. {requests} -> {request} (#14753)

💡 Verbesserungen 💡

– cmd/mdatagen: Feld „deprecated_type“ hinzugefügt, um die Angabe eines Alias für Komponententypen zu ermöglichen. (#14718) – cmd/mdatagen: Entitätsbezogenen MetricsBuilder API generieren, der Entitäts-Metrik-Zuordnungen zur Kompilierungszeit erzwingt (#14659) – cmd/mdatagen: Überspringen Sie die Generierung von Reaggregationskonfigurationsoptionen für Metriken, die keine aggregierbaren Attribute haben. (#14689) – pkg/service: Der interne Statusreporter löscht nicht mehr wiederholt die Status „OK“ und „RecoverableError“ (#14282) Statusereignisse können jetzt Metadaten enthalten und es ist sinnvoll, die Ausgabe unabhängig vom Statuswert selbst zu ermöglichen nicht ändern.

🧰 Fehlerbehebungen 🧰

– cmd/builder: Fügen Sie .exe hinzu, um beim Erstellen für Windows-Ziele Binärnamen auszugeben. (#12591)

  • exporter/debug: Drucken von metrischen Metadaten in detaillierter Ausführlichkeit hinzugefügt. (#14667)
  • exporter/otlp_grpc: Verhindert Null-Zeiger-Panic, wenn Push-Methoden aufgerufen werden, bevor der OTLP-Exporter seine gRPC clients initialisiert. (#14663) Wenn die Sendewarteschlange und der Wiederholungsversuch deaktiviert sind, rufen Sie ConsumeTraces auf. ConsumeMetrics, ConsumeLogs oder ConsumeProfiles vor dem OTLP-Exporter Die Initialisierung seiner gRPC clients könnte zu einer Null-Zeiger-Dereferenzierungspanik führen. Die Push-Methoden geben jetzt einen Fehler zurück, anstatt in Panik zu geraten. – exporter/otlp_http: Zeigt die tatsächliche Ziel-URL in Fehlermeldungen an, wenn die Anforderungs-URL durch Middleware geändert wird. (#14673) Entpackt den von http.Client.Do() zurückgegebenen *url.Error, um irreführende Fehlerprotokolle zu verhindern, wenn eine Middleware-Erweiterung den Endpunkt dynamisch aktualisiert.
  • pdata/pprofile: Wechseln Sie das Wörterbuch der Wörterbuchtabelleneinträge beim Zusammenführen von Profilen nur einmal (#14709) Für Wörterbuchtabellendaten haben wir dabei die Wörterbücher gewechselt der Schalter für die Daten, die sie verwenden. Wenn ein Eintrag jedoch mit mehreren anderen Daten verknüpft ist (mehrere Proben können denselben Stapel verwenden), hätten wir den geändert Wörterbücher des Eintrags mehrmals durchsuchen. Bisher wechseln wir die Wörterbücher für die Daten der Wörterbuchtabelle nur einmal Wechseln der Ressourcenprofile.

API Changelog

🛑 Breaking Changes 🛑

– cmd/mdatagen: Generieren Sie einen metrischen Konfigurationstyp <MetricName>Config für jede Metrik, wenn reaggregation_enabled: true (#14689) Metriken mit aggregierbaren Attributen erhalten AggregationStrategy und EnabledAttributes []<MetricName>AttributeKey Felder; andere erhalten nur Enabled. Typisierte Attributschlüsselkonstanten (z. B. DefaultMetricAttributeKeyStringAttr) Ersetzen Sie []string und eliminieren Sie Laufzeitattribut-Slice-Zuweisungen. Validierungsfehler listen jetzt gültige Attribute auf und Strategien mit Namen. Komponenten, die reaggregation_enabled: true verwenden, müssen Verweise auf MetricConfig aktualisieren. – pdata/pprofile: ProtoID für Nachrichtenbeispielfelder aktualisieren (#14652)

💡 Verbesserungen 💡

– cmd/mdatagen: Erweitern Sie das mdatagen-Tool, um Go-Konfigurationsstrukturen für OpenTelemetry-Kollektorkomponenten zu generieren. (#14561) Der Go-Code für die Komponentenkonfiguration wird aus dem Abschnitt config der Datei metadata.yaml generiert.

  • cmd/mdatagen: Erweitern Sie das mdatagen-Tool, um das Konfigurations-JSON-Schema für OpenTelemetry-Komponenten zu generieren. (#14543) Das Komponentenkonfigurationsschema JSON wird aus dem Abschnitt config der Datei metadata.yaml generiert.
  • cmd/mdatagen: Schemagenerierung für mdatagen-gesteuerte Konfigurationsteile (#14562) Das Schema wird in einer separaten yaml-Datei generiert und zum Erstellen eines vollständigen Komponentenschemas verwendet.
  • pdata/pprofile: Referenzbasierte Attribute in Profilen implementieren (#14546)
  • pkg/pdata: Aktualisieren Sie die OTLP-Protobuf-Definitionen auf Version 1.10.0 (#14766)
  • pkg/service: Der interne Statusreporter löscht nicht mehr wiederholt die Status „OK“ und „RecoverableError“ (#14282) Statusereignisse können jetzt Metadaten enthalten und es ist sinnvoll, die Ausgabe unabhängig vom Statuswert selbst zu ermöglichen nicht ändern. – pkg/xexporterhelper: Logik hinzufügen, um Partitionen aus dem Speicher zu bereinigen, die für einen bestimmten Zeitraum nicht verwendet wurden. (#14526)
  • pkg/xpdata: NewEntity-Konstruktor, Entity.CopyToResource und EntityAttributeMap.All zu pdata/xpdata/entity hinzufügen (#14659)

🧰 Fehlerbehebungen 🧰

  • cmd/mdatagen: Benutzerdefinierte Erweiterungen (z. B. x-customType, x-pointer) während der Schemareferenzauflösung beibehalten. (#14713, #14565) Behebt ein Problem, bei dem benutzerdefinierte Eigenschaften lokal auf einem Knoten definiert wurden überschrieben und geht verloren, wenn ein $ref in ein externes/internes Schema aufgelöst wird. – pkg/xexporterhelper: Fehler behoben, wenn eine Partition aus LRU entfernt wird und gleichzeitig neue Elemente hinzugefügt werden. (#14526)

opentelemetry-collector v0.148.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.148.0

End User Changelog

❗ Known Issues ❗

  • service: The collector's internal Prometheus metrics endpoint (:8888) now emits OTel service labels with underscore names (service_name, service_instance_id, service_version) instead of dot-notation names (service.name, service.instance.id, service.version). Users scraping this endpoint with the Prometheus receiver will see these renamed labels in resource and datapoint attributes. As a workaround, add the following metric_relabel_configs to your scrape config in prometheus receiver: 
    metric_relabel_configs:  - source_labels: [service_name]    target_label: service.name  - source_labels: [service_instance_id]    target_label: service.instance.id  - source_labels: [service_version]    target_label: service.version  - regex: service_name|service_instance_id|service_version    action: labeldrop
    See https://github.com/open-telemetry/opentelemetry-collector/issues/14814 for details and updates.

🛑 Breaking changes 🛑

  • all: Change metric units to be singular to match OTel specification, e.g. {requests} -> {request} (#14753)

💡 Enhancements 💡

  • cmd/mdatagen: Add deprecated_type field to allow specifying an alias for component types. (#14718)
  • cmd/mdatagen: Generate entity-scoped MetricsBuilder API that enforces entity-metric associations at compile time (#14659)
  • cmd/mdatagen: Skip generating reaggregation config options for metrics that have no aggregatable attributes. (#14689)
  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

🧰 Bug fixes 🧰

  • cmd/builder: Add .exe to output binary names when building for Windows targets. (#12591)

  • exporter/debug: Add printing of metric metadata in detailed verbosity. (#14667)

  • exporter/otlp_grpc: Prevent nil pointer panic when push methods are called before the OTLP exporter initializes its gRPC clients. (#14663) When the sending queue and retry are disabled, calling ConsumeTraces, ConsumeMetrics, ConsumeLogs, or ConsumeProfiles before the OTLP exporter initializes its gRPC clients could cause a nil pointer dereference panic. The push methods now return an error instead of panicking.

  • exporter/otlp_http: Show the actual destination URL in error messages when request URL is modified by middleware. (#14673) Unwraps the *url.Error returned by http.Client.Do() to prevent misleading error logs when a middleware extension dynamically updates the endpoint.

  • pdata/pprofile: Switch the dictionary of dictionary tables entries only once when merging profiles (#14709) For dictionary table data, we used to switch their dictionaries when doing the switch for the data that uses them. However, when an entry is associated with multiple other data (several samples can use the same stack), we would have been switching the dictionaries of the entry multiple times.

    We now switch dictionaries for dictionary table data only once, before switching the resource profiles.

API Changelog

🛑 Breaking changes 🛑

  • cmd/mdatagen: Generate a per-metric config type <MetricName>Config for each metric when reaggregation_enabled: true (#14689) Metrics with aggregatable attributes get AggregationStrategy and EnabledAttributes []<MetricName>AttributeKey fields; others get Enabled only. Typed attribute key constants (e.g. DefaultMetricAttributeKeyStringAttr) replace []string, eliminating runtime attribute slice allocations. Validation errors now list valid attributes and strategies by name. Components using reaggregation_enabled: true will need to update references to MetricConfig.

  • pdata/pprofile: Update protoID for message Sample fields (#14652)

💡 Enhancements 💡

  • cmd/mdatagen: Extend mdatagen tool to generate go config structs for OpenTelemetry collector components. (#14561) The component config go code is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Extend mdatagen tool to generate config JSON schema for OpenTelemetry components. (#14543) The component config JSON schema is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Schema generation for mdatagen-controlled config parts (#14562) The schema is generated in separate yaml file and used to create full component schema.

  • pdata/pprofile: Implement reference based attributes in Profiles (#14546)

  • pkg/pdata: Upgrade the OTLP protobuf definitions to version 1.10.0 (#14766)

  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

  • pkg/xexporterhelper: Add logic to cleanup partitions from memory which are not being used for specific time period. (#14526)

  • pkg/xpdata: Add NewEntity constructor, Entity.CopyToResource, and EntityAttributeMap.All to pdata/xpdata/entity (#14659)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Preserve custom extensions (e.g., x-customType, x-pointer) during schema reference resolution. (#14713, #14565) Fixes an issue where custom properties defined locally on a node were overwritten and lost when resolving a $ref to an external/internal schema.

  • pkg/xexporterhelper: Fix race when partition is being removed from LRU and new items are being added at the same time. (#14526)
