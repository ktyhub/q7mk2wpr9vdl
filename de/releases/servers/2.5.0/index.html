Server v2.5.0

Sicherheitskorrekturen

v2.5.0 behebt acht Schwachstellen in drei Servern. Upgrade von mcp-server-git auf 2026.11.18, @modelcontextprotocol/server-filesystem bis 2.4.0 und @modelcontextprotocol/server-everything bis 2.3.1. | Paket | Betroffen | Behoben in | | --- | --- | --- | | mcp-server-git | über 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | alle Versionen vor 2.4.0 und Datumsversionen 2025.1.14 bis 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | über 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • Eine Zusammenführung startet nicht mehr die automatische Wartung von Git. Ein erfolgreicher git_merge, einschließlich eines schnellen Vorlaufs, endete in git maintenance run --auto, dessen Garbage Collection die Befehle unter den gc.recentObjectsHook-Namen eines Repositorys mit den Berechtigungen des Servers ausführt. maintenance.auto ist jetzt false und gc.auto ist 0 für jeden Git-Befehl, den der Server ausführt (GHSA-h2g3-rwxm-xfm3)
  • Git ruft ein fehlendes Objekt niemals selbst ab. Die Konfiguration eines Repositorys könnte einen Promisor-Remote deklarieren und das Programm benennen, das Git ausführt, um daraus abzurufen (remote.<name>.uploadpack, core.sshCommand), das ein schreibgeschütztes Tool dann startete, wenn es ein Objekt benötigte, das sich nicht auf der Festplatte befand. Lazy Fetching ist deaktiviert (GIT_NO_LAZY_FETCH=1) und ein Git, der zu alt ist, um berücksichtigt zu werden, der ein Repository ablehnt, das einen Promisor-Remote deklariert (GHSA-87qg-cmw8-jc5m)
  • Treiber werden erneut gelesen, nachdem ein Tool den Arbeitsbaum geschrieben hat. Die Konfiguration eines Repositorys kann eine Datei enthalten, die durch ein Zusammenführen oder Auschecken erstellt wird, sodass ein Filter- oder Zusammenführungstreiber erscheinen könnte, nachdem der Server die gefundenen Treiber geleert hat, und während des git merge --abort ausgeführt werden könnte, der auf einen Konflikt folgt. git_checkout, git_merge und dieser Abbruch lesen nun die Treiber erneut, bevor ein anderer Git-Befehl ausgeführt wird. Die --repository-Beschränkungsprüfung wird nach einem solchen Schreibvorgang noch nicht wiederholt (#5599) (GHSA-9vjp-x34c-xg6v)
  • Ein Filter- oder Merge-Treiber mit einem leeren Namen wird ebenfalls geleert. Git akzeptiert [filter ""], ausgewählt von filter= in .gitattributes, und die Liste der Treiber eines Repositorys auf dem Server hat es übersehen, sodass sein Befehl ausgeführt wurde (GHSA-pm7p-vphh-2cg7)
  • Indexeinträge, die außerhalb des Arbeitsbaums verweisen, werden abgelehnt. Mit --repository veranlasste ein manipulierter .git/index, der einen Pfad wie ../outside/secret benennt, dass git_diff_unstaged und git_diff den Inhalt dieser Datei zurückgeben und git_status melden, ob sie existiert. Der Index wird jetzt von oben überprüft, bevor ihn ein Tool liest, und der nicht verfolgte Cache, der ein Verzeichnis außerhalb des Arbeitsbaums benennen kann, ist deaktiviert (GHSA-r2q8-f657-4r56)
  • Die eigene Konfiguration eines Submoduls führt keine Programme mehr aus. Mit diff.submodule=diff in der Konfiguration des Repositorys führte git_diff einen verschachtelten Diff in jedem geänderten Submodul unter den eigenen diff.external- und textconv-Treibern des Submoduls aus, und git_checkout und git_add führten Git ebenfalls in einem Submodul unter seiner eigenen Konfiguration aus. diff.submodule ist jetzt short, die Treiber, die ein ausgechecktes Submodul definiert, werden überschrieben, und ein Git, das älter als 2.33 ist und die Überschreibungen nicht an ein Submodul weitergeben würde, wird für ein Repository abgelehnt, in dem eines ausgecheckt ist (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Verzeichnislisten bleiben bei dem Verzeichnis, das überprüft wurde (Linux und macOS). list_directory, list_directory_with_sizes, directory_tree und search_files listen jetzt ein vorhandenes Verzeichnis auf, nachdem sie es überprüft haben, sodass ein Verzeichnis, das zwischen der Überprüfung und der Auflistung für einen Symlink ausgetauscht wurde, nicht mehr die Namen von Einträgen außerhalb der zulässigen Verzeichnisse zurückgeben kann. Unter Windows ist ein Eintrag noch nicht verankert (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource behandelt eine NAT64-Adresse als die IPv4-Adresse, die sie trägt. Der Private-Address-Guard des Tools liest Adressen in 64:ff9b::/96 als öffentlich, sodass in einem Netzwerk mit einem NAT64-Gateway eine URL über eines eine private IPv4-Adresse erreichen könnte. Die eingebettete IPv4-Adresse wird jetzt überprüft (GHSA-38j4-j742-j7r3)

servers v2.5.0

Security fixes

v2.5.0 fixes eight vulnerabilities in three servers. Upgrade mcp-server-git to 2026.11.18, @modelcontextprotocol/server-filesystem to 2.4.0 and @modelcontextprotocol/server-everything to 2.3.1.

| Package | Affected | Fixed in | | --- | --- | --- | | mcp-server-git | through 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | all versions before 2.4.0, and date versions 2025.1.14 through 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | through 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • A merge no longer starts Git's automatic maintenance. A successful git_merge, a fast-forward included, ended in git maintenance run --auto, whose garbage collection runs the commands a repository's own gc.recentObjectsHook names, with the server's privileges. maintenance.auto is now false and gc.auto is 0 for every Git command the server runs (GHSA-h2g3-rwxm-xfm3)
  • Git never fetches a missing object by itself. A repository's configuration could declare a promisor remote and name the program Git runs to fetch from it (remote.<name>.uploadpack, core.sshCommand), which a read-only tool then started when it needed an object that was not on disk. Lazy fetching is turned off (GIT_NO_LAZY_FETCH=1), and a Git too old to honor that refuses a repository that declares a promisor remote (GHSA-87qg-cmw8-jc5m)
  • Drivers are read again after a tool writes the working tree. A repository's configuration can include a file that a merge or checkout creates, so a filter or merge driver could appear after the server had emptied the ones it found, and run during the git merge --abort that follows a conflict. git_checkout, git_merge and that abort now read the drivers again before any other Git command runs. The --repository confinement check is not yet repeated after such a write (#5599) (GHSA-9vjp-x34c-xg6v)
  • A filter or merge driver with an empty name is emptied too. Git accepts [filter ""], selected by filter= in .gitattributes, and the server's list of a repository's drivers missed it, so its command ran (GHSA-pm7p-vphh-2cg7)
  • Index entries that point outside the working tree are refused. With --repository, a crafted .git/index naming a path such as ../outside/secret made git_diff_unstaged and git_diff return that file's content, and git_status report whether it exists. The index is now checked from its top before any tool reads it, and the untracked cache, which can name a directory outside the working tree, is turned off (GHSA-r2q8-f657-4r56)
  • A submodule's own configuration no longer runs programs. With diff.submodule=diff in the repository's configuration, git_diff ran a nested diff inside each changed submodule under the submodule's own diff.external and textconv drivers, and git_checkout and git_add ran Git inside a submodule under its own configuration too. diff.submodule is now short, the drivers a checked-out submodule defines are overridden, and a Git older than 2.33, which would not pass the overrides into a submodule, is refused for a repository that has one checked out (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Directory listings stay with the directory that was checked (Linux and macOS). list_directory, list_directory_with_sizes, directory_tree and search_files now list a directory in place after checking it, so a directory swapped for a symlink between the check and the listing can no longer return the names of entries outside the allowed directories. On Windows a listing is not yet anchored (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource treats a NAT64 address as the IPv4 address it carries. The tool's private-address guard read addresses in 64:ff9b::/96 as public, so on a network with a NAT64 gateway a URL could reach a private IPv4 address through one. The embedded IPv4 address is now checked (GHSA-38j4-j742-j7r3)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.4.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.4.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.4.0.
