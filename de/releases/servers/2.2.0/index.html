Server v2.2.0

Sicherheit: Node.js-Laufzeit- und CA-Zertifikat-Updates (Oktober 2026)

Am 20. Oktober 2026 gab eMudhra bekannt, dass die privaten Schlüssel für acht seiner Zwischen-CA-Zertifikate aus den öffentlichen Zertifikaten wiederhergestellt werden konnten. Am 21. Oktober hat Node.js [Sicherheitsversionen] (https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) veröffentlicht, die die gebündelten CA-Zertifikate für die Kompromittierung aktualisieren und mehrere unabhängige, hochgradig schwerwiegende Laufzeit-CVEs beheben. Am 23. Oktober entfernten certifi 2026.10.23 von Python die eMudhra-Wurzeln emSign Root CA - C1 und emSign ECC Root CA - C3. So stehen diese Server

  • Die TypeScript-Server verlassen sich bei Zertifikatsprüfungen auf die Node.js-Laufzeitumgebung. Sie versenden keine eigenen CA-Zertifikate. Nur server-everything stellt ausgehende HTTPS-Anfragen (gzip-file-as-resource) und der Node.js, auf dem es ausgeführt wird, überprüft sie. server-filesystem, server-memory und server-sequential-thinking stellen keine Netzwerkverbindungen her.
  • mcp-server-fetch überprüft HTTPS anhand des certifi-Bundles über httpx. Durch die Installation von PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) wird das aktuelle certifi, 2026.10.23 oder höher aufgelöst. Die Datei fetch Docker des Repositorys wird aus seiner Sperrdatei installiert, die in dieser Version nach certifi 2026.10.23 verschoben wird (#5341).
  • mcp-server-git und mcp-server-time stellen keine Netzwerkverbindungen her. Wenn Sie einen TypeScript-Server von npm ausführen (npx oder eine globale Installation) Es läuft auf Ihrem Node.js, das wir nicht für Sie aktualisieren können. Bitte führen Sie Node.js 24.22.1 oder 26.12.1 oder höher aus und überprüfen Sie es mit node --version. Das Feld engines der Pakete akzeptiert alle Node.js 24, sodass npm Sie nicht vor einer älteren, ungepatchten Laufzeit warnt. Wenn Sie mcp-server-fetch in einer vorhandenen Umgebung ausführen Eine vor dem 23. Oktober erstellte Umgebung behält ihren älteren certifi. Aktualisieren Sie es mit uvx --refresh mcp-server-fetch oder pip install -U certifi.

servers v2.2.0

Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped security releases that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's certifi 2026.10.23 removed the eMudhra roots emSign Root CA - C1 and emSign ECC Root CA - C3.

How these servers stand

  • The TypeScript servers rely on the Node.js runtime for certificate checks. They ship no CA certificates of their own. Only server-everything makes outbound HTTPS requests (gzip-file-as-resource), and the Node.js it runs on verifies them. server-filesystem, server-memory and server-sequential-thinking make no network connections.
  • mcp-server-fetch verifies HTTPS against the certifi bundle, through httpx. Installing from PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolves the current certifi, 2026.10.23 or later. The repository's fetch Dockerfile installs from its lockfile, which this release moves to certifi 2026.10.23 (#5341).
  • mcp-server-git and mcp-server-time make no network connections.

If you run a TypeScript server from npm (npx or a global install)

It runs on your Node.js, which we can't update for you. Please run Node.js 24.22.1 or 26.12.1, or later, and check with node --version. The packages' engines field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

If you run mcp-server-fetch from an existing environment

An environment created before October 23 keeps its older certifi. Refresh it with uvx --refresh mcp-server-fetch, or pip install -U certifi.
