Server v2.4.0

Sicherheitskorrekturen

v2.4.0 behebt sechs Schwachstellen in drei Servern. Upgrade von @modelcontextprotocol/server-filesystem auf 2.3.0, und mcp-server-git und mcp-server-fetch bis 2026.11.11. | Paket | Betroffen | Behoben in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | alle Versionen vor 2.3.0 und Datumsversionen 2025.1.14 bis 2026.8.31 | 2.3.0 | | mcp-server-git | über 2026.11.4 | 2026.11.11 | | mcp-server-fetch | über 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Lesevorgänge bleiben bei der Datei, die überprüft wurde (Linux und macOS). Die Lesetools und Dateiressourcen öffnen nun eine Datei relativ zu dem Verzeichnis, das überprüft wurde, wie dies bereits bei Schreibvorgängen der Fall war, sodass ein Verzeichnis, das zwischen der Zugriffsprüfung und dem Lesevorgang für einen Symlink ausgetauscht wurde, keine Datei mehr von außerhalb der zulässigen Verzeichnisse zurückgeben kann. Ein FIFO, Socket oder Gerät wird eher abgelehnt als gelesen. Unter Windows schränkt dies das Rennen ein, ohne es zu schließen, wie bei Schreibvorgängen (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file verschiebt nur die Quelle, die es überprüft hat. Bei einer Verschiebung innerhalb eines Geräts wird die Quelle zunächst aus ihrem eigenen überprüften Verzeichnis unter einem neuen Namen entfernt, sodass ein durch einen Symlink ausgetauschtes Quellverzeichnis eine externe Datei nicht mehr in die zulässigen Verzeichnisse bringen kann, wo sie lesbar werden würde (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • Die eigene Git-Konfiguration eines Repositorys kann den Server nicht mehr dazu veranlassen, ein Programm auszuführen. Ein schreibgeschützter Aufruf wie git_status in einem untrusted-Repository, der zum Ausführen eines in seinem .git/config genannten Befehls (core.fsmonitor, diff.external, Hooks, Filter- und Merge-Treiber, Signieren) mit den Berechtigungen des Servers verwendet wird. Jeder Git-Befehl überschreibt jetzt diese Einstellungen und ein Git, der älter als 2.31 ist und die Überschreibungen ignorieren würde, wird abgelehnt (GHSA-6hqx-gqrx-c5r2)
  • Die Beschränkung von --repository umfasst alternative Objektspeicher, verknüpfte Arbeitsbäume und Links im Git-Verzeichnis. Ein Repository innerhalb des zulässigen Repositorys könnte die Objekte eines anderen Repositorys über objects/info/alternates lesen oder das Git-Verzeichnis eines verknüpften Arbeitsbaums als zulässiges Repository weitergeben. Beides wird abgelehnt, ebenso wie ein Symlink in einem Git-Verzeichnis, der aus dem erlaubten Repository führt. Unter Windows ist eine Verzeichnisverzweigung noch nicht abgedeckt (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • Lokale IPv6-Adressen sind privat. Der Private-Address-Guard liest fec0::/10 als öffentlich. Sie wird jetzt abgelehnt, ebenso wie jede IPv6-Adresse außerhalb des globalen Unicasts (2000::/3), die keine IPv4-Adresse trägt (GHSA-3rxj-6jhw-qfv7).
  • robots.txt wird mit dem Pfad abgeglichen, den die Site auflösen wird, sowie mit dem Pfad wie geschrieben, sodass //private oder /x/../private nicht mehr an Disallow: /private vorbeikommen können (GHSA-f9hh-cmx9-2f23)

Upgrade von einer npm-Version mit Datumsversion

Die TypeScript-Server wurden von Datumsversionen (2025.x, 2026.x) auf semantische Versionen in 1.0.0 umgestellt. Paketmanager stufen 2.3.0 unter jeder 2025.x- und 2026.x-Version ein, sodass sie es nicht als Upgrade anbieten. Wenn Sie eine aktuelle Version von @modelcontextprotocol/server-filesystem verwenden, installieren Sie 2.3.0 explizit: npm install @modelcontextprotocol/server-filesystem@2.3.0.

servers v2.4.0

Security fixes

v2.4.0 fixes six vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem to 2.3.0, and mcp-server-git and mcp-server-fetch to 2026.11.11.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | all versions before 2.3.0, and date versions 2025.1.14 through 2026.8.31 | 2.3.0 | | mcp-server-git | through 2026.11.4 | 2026.11.11 | | mcp-server-fetch | through 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Reads stay with the file that was checked (Linux and macOS). The read tools and file resources now open a file relative to the directory that was checked, as writes already did, so a directory swapped for a symlink between the access check and the read can no longer return a file from outside the allowed directories. A FIFO, socket or device is refused rather than read. On Windows this narrows the race without closing it, as for writes (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file moves only the source it checked. A move within one device first takes the source out of its own checked directory under a fresh name, so a source directory swapped for a symlink can no longer bring an outside file into the allowed directories, where it would become readable (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • A repository's own Git configuration can no longer make the server run a program. A read-only call such as git_status on an untrusted repository used to run a command named in its .git/config (core.fsmonitor, diff.external, hooks, filter and merge drivers, signing) with the server's privileges. Every Git command now overrides those settings, and a Git older than 2.31, which would ignore the overrides, is refused (GHSA-6hqx-gqrx-c5r2)
  • --repository confinement covers alternate object stores, linked worktrees and links in the Git directory. A repository inside the allowed one could read another repository's objects through objects/info/alternates, or pass a linked worktree's Git directory off as the allowed repository's. Both are refused, as is a symlink in a Git directory that leads outside the allowed repository. On Windows a directory junction is not yet covered (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • IPv6 site-local addresses are private. The private-address guard read fec0::/10 as public. It is now refused, and so is any IPv6 address outside global unicast (2000::/3) that does not carry an IPv4 address (GHSA-3rxj-6jhw-qfv7)
  • robots.txt is matched against the path the site will resolve, as well as the path as written, so //private or /x/../private can no longer get past Disallow: /private (GHSA-f9hh-cmx9-2f23)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.3.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.3.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.3.0.
