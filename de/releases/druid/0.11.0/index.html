Druide Druide-0.11.0

Druid 0.11.0 enthält über hundert Leistungsverbesserungen, Stabilitätsverbesserungen und Fehlerbehebungen von fast 40 Mitwirkenden. Diese Version fügt zwei wichtige Sicherheitsfunktionen hinzu: TLS-Unterstützung und Erweiterungspunkte für Authentifizierung und Autorisierung. Zu den wichtigsten neuen Funktionen gehören:

  • TLS-Unterstützung (auch bekannt als SSL).
  • Erweiterungspunkte für Authentifizierung und Autorisierung
  • Unterstützung für Doppelsäulen
  • CachingCost Balancer-Strategie
  • jq-Ausdrucksunterstützung im JSON-Parser
  • Redis Cache-Erweiterung
  • GroupBy-Leistungsverbesserungen
  • Verschiedene Verbesserungen an Druid SQL Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0 Die Dokumentation für diese Version finden Sie unter: http://druid.io/docs/0.11.0/

Highlights

TLS-Unterstützung

Druid unterstützt jetzt TLS und ermöglicht verschlüsselte client- und Kommunikation zwischen Knoten. Einzelheiten zur Konfiguration und zugehörigen Erweiterungen finden Sie unter http://druid.io/docs/0.11.0/operations/tls-support.html. Hinzugefügt von @pjain1 in https://github.com/druid-io/druid/pull/4270.

Authentifizierungs-/Autorisierungserweiterungspunkte

Druid wurden Erweiterungspunkte zur Authentifizierung und Autorisierung von Anfragen hinzugefügt. Weitere Informationen zur Konfiguration und Erweiterungsimplementierung finden Sie unter http://druid.io/docs/0.11.0/configuration/auth.html. Die vorhandene Kerberos-Authentifizierungserweiterung wurde aktualisiert, um die neue Authenticator-Schnittstelle zu implementieren. Weitere Informationen, wenn Sie die Kerberos-Erweiterung verwenden, finden Sie im Abschnitt „Änderungen der Kerberos-Konfiguration“ unter „Aktualisierung von 0.10.1 und früher“. Hinzugefügt von @jon-wei in https://github.com/druid-io/druid/pull/4271

Unterstützung für Doppelspalten

Druid unterstützt jetzt Aggregatorspalten vom Typ Double. Die Dokumentation zu den neuen Double-Aggregatoren finden Sie unter http://druid.io/docs/0.11.0/querying/aggregations.html. Hinzugefügt von @b-slim in https://github.com/druid-io/druid/pull/4491.

CachingCost Balancer-Strategie

Benutzern, die ein Upgrade auf 0.11.0 durchführen, wird empfohlen, die neue Segmentausgleichsstrategie cachingCost auf ihren Koordinatoren auszuprobieren. Diese Strategie bietet große Leistungsverbesserungen gegenüber der bestehenden Kostenausgleichsstrategie und soll in der Veröffentlichung nach 0.11.0 zur Standardstrategie werden. Diese Strategie kann ausgewählt werden, indem die folgende Eigenschaft für Koordinatoren festgelegt wird:

druid.coordinator.balancer.strategy=cachingCost

Hinzugefügt von @dgolitsyn in https://github.com/druid-io/druid/pull/4731

jq-Ausdrucksunterstützung im JSON-Parser

Der Eingabeparser JSON von Druid unterstützt jetzt JQ-Ausdrücke mit jackson-jq und ermöglicht so mehr Eingabetransformationen vor der Aufnahme. Weitere Einzelheiten finden Sie unter http://druid.io/docs/0.11.0/ingestion/flatten-json.html. Hinzugefügt von @knoguchi in https://github.com/druid-io/druid/pull/4171.

Redis Cache-Erweiterung

Eine neue Cache-Implementierung mit Redis wurde in einer Erweiterung hinzugefügt, die von @QiuMM in https://github.com/druid-io/druid/pull/4615. hinzugefügt wurde. Weitere Informationen finden Sie im vorherigen Pull-Request.

GroupBy-Leistungsverbesserungen

In den folgenden PRs wurden der GroupBy-Abfrage von @jihoonson mehrere neue Leistungsoptimierungen hinzugefügt: https://github.com/druid-io/druid/pull/4660 Parallele Sortierung für ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Array-basierte Aggregation für GroupBy-Abfrage https://github.com/druid-io/druid/pull/4668 Fügen Sie IntGrouper hinzu, um unnötiges Boxing/Unboxing bei der Array-basierten Aggregation zu vermeiden PR #4660 bietet eine allgemeine Verbesserung durch Parallelisierung der Teilergebnissortierung, während PR #4576 und #4668 erhebliche Verbesserungen bei der Gruppierung in einer einzelnen String-Spalte bieten.

SQL-Verbesserungen

Verschiedene Verbesserungen und Funktionen wurden von @gianm in den folgenden PRs zu Druid SQL hinzugefügt: https://github.com/druid-io/druid/pull/4750 – TRIM-Unterstützung https://github.com/druid-io/druid/pull/4720 – Rundung für Count Unique https://github.com/druid-io/druid/pull/4561 – Metriken für SQL-Abfragen https://github.com/druid-io/druid/pull/4360 – Unterstützung für SQL-Ausdrücke

Und noch viel mehr!

Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Aktualisierung von 0.10.1 und früher

Nachfolgend finden Sie die Änderungen zwischen 0.10.1 und 0.11.0, die Sie vor dem Upgrade beachten sollten. Wenn Sie von einer früheren Version als 0.10.1 aktualisieren, finden Sie weitere Hinweise in den release notes der entsprechenden Zwischenversionen.

Koordinatoren und Oberherren verbessern

Der folgende Patch ändert die Art und Weise, wie Koordinator->Overlord-Weiterleitungen gehandhabt werden: https://github.com/druid-io/druid/pull/5037 Der Wahlalgorithmus für den Overlord-Anführer hat sich in 0.11.0: https://github.com/druid-io/druid/pull/4699. geändert Aufgrund der beiden oben genannten Patches ist beim Upgrade von Coordinator oder Overlord auf 0.11.0 besondere Vorsicht geboten. Alle Koordinatoren und Overlords müssen gemeinsam heruntergefahren und aufgerüstet werden. Um beispielsweise Koordinatoren zu aktualisieren, würden Sie alle Koordinatoren herunterfahren, sie auf 0.11.0 aktualisieren und sie dann starten. Overlords sollten auf ähnliche Weise aufgewertet werden. Während des Upgrade-Vorgangs darf es keinen Zeitraum geben, in dem ein Nicht-0.11.0-Koordinator oder Overlord gleichzeitig mit einem 0.11.0-Koordinator oder Overlord ausgeführt wird. Beachten Sie, dass mindestens ein Overlord so schnell wie möglich aktiviert werden sollte, nachdem Sie alle ausgeschaltet haben, damit Peons, Ruhe usw. nach einigen Wiederholungsversuchen weiterhin funktionieren. Beachten Sie außerdem, dass die Eigenschaft druid.zk.paths.indexer.leaderLatchPath jetzt nicht mehr verwendet wird.

Dienstnamenänderungen

In früheren Versionen von Druid wurden /-Zeichen in durch druid.service definierten Dienstnamen durch :-Zeichen ersetzt, da diese Dienstnamen in Zookeeper-Pfaden verwendet wurden. Der Druide 0.11.0 führt diese Zeichenersetzungen nicht mehr durch. Beispiel:1 – wenn die alte Konfiguration einen Broker mit dem Dienstnamen test/broker hatte: druid.service=test/broker und ein Router wurde unter der Annahme konfiguriert, dass / im Broker-Dienstnamen durch : ersetzt wird, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"} Die Router-Konfiguration sollte aktualisiert werden, um diese Annahme zu beseitigen: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"} Beispiel:2 – Wenn die alte Konfiguration einen Overlord mit dem Dienstnamen test/overlord hatte, sollte der Wert von druid.coordinator.asOverlord.overlordService oder druid.selectors.indexing.serviceName test/overlord und nicht test:overlord sein Beispiel:3 – Wenn die alte Konfiguration einen Overlord mit dem Dienstnamen test:overlord hatte, sollte der Wert von druid.coordinator.asOverlord.overlordService oder druid.selectors.indexing.serviceName test:overlord und nicht test/overlord sein Die folgenden dienstnamenbezogenen Konfigurationen sind ebenfalls betroffen und sollten aktualisiert werden, damit sie genau mit dem Wert der Eigenschaft druid.service auf anderen erkannten Knoten übereinstimmen. druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/issues/4992.

Kerberos-Konfigurationsänderungen

Das Kerberos-Authentifizierungskonfigurationsformat hat sich aufgrund der durch #4271 eingeführten neuen Schnittstellen geändert. Die neuen Konfigurationseigenschaften finden Sie unter http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html. Benutzer können den AuthorizerName des Kerberos-Authentifikators auf eine Instanz eines „allowAll“-Authorizers verweisen, um das Verhalten eines Clusters vor 0.11.0 mithilfe der Kerberos-Authentifizierung ohne Autorisierung zu replizieren.

Sucht nach API-Pfadänderungen

Die Pfade für die Suchkonfiguration API haben sich aufgrund von #5058 geändert. Konfigurationspfade, die das Format /druid/coordinator/v1/lookups hatten, haben jetzt das Format /druid/coordinator/v1/lookups/config. Den aktuellen API finden Sie unter http://druid.io/docs/0.11.0/querying/lookups.html.

Migration zu Doppelspalten

Vor 0.11.0 speicherten die Double*-Aggregatoren Spaltenwerte als Float auf der Festplatte, während sie Aggregationen mithilfe von Double-Darstellungen durchführten. PR #4491 ermöglicht es den Double-Aggregatoren, Spaltenwerte als Doubles auf der Festplatte zu speichern. Aufgrund von Bedenken im Zusammenhang mit fortlaufenden Updates und Versions-Downgrades ist dieses Verhalten standardmäßig deaktiviert und Druid speichert Double-Aggregatoren weiterhin als Floats auf der Festplatte. Um den Doppelspaltenspeicher zu aktivieren, legen Sie die folgende Eigenschaft in den allgemeinen Laufzeiteigenschaften fest:

druid.indexing.doubleStorage=double

Benutzer sollten diese Eigenschaft während eines ersten fortlaufenden Upgrades auf 0.11.0 nicht festlegen, da Knoten, auf denen Druid vor 0.11.0 ausgeführt wird, nicht in der Lage sind, während des Upgrade-Zeitraums erstellte Doppelspalten zu verarbeiten. Benutzer müssen außerdem alle Segmente mit Doppelspalten neu indizieren, wenn sie ein Downgrade von 0.11.0 auf eine ältere Version durchführen. Weitere Informationen finden Sie unter #4944 und #4605.

Abfrageänderungen scannen

Die Scan-Abfrage wurde von extensions-contrib nach core Druid verschoben. Im Rahmen dieser Migration: https://github.com/druid-io/druid/pull/4751, hat sich die Behandlung der Zeitspalte durch die Scan-Abfrage geändert. Die Zeitspalte wird jetzt als „__time“ und nicht als „timestamp“ zurückgegeben. Sie ist nicht mehr enthalten, wenn Sie nicht ausdrücklich in Ihren „Spalten“ danach fragen, und sie wird als Long- statt als String zurückgegeben. Benutzer können die Zeitverarbeitung der Scan-Abfrage auf das alte Erweiterungsverhalten zurücksetzen, indem sie "legacy" : true in ihren Abfragen festlegen oder die Eigenschaft druid.query.scan.legacy = true festlegen. Dies soll einen Migrationspfad für Benutzer bieten, die zuvor die Contrib-Erweiterung verwendet haben.

Änderungen an der Erweiterungsschnittstelle

Aggregator-Doppelspaltenunterstützung

Die Aggregator-Schnittstelle hat eine getDouble()-Methode erhalten, die standardmäßig das Ergebnis von getFloat() umwandelt. Die getDouble()-Methode sollte für alle benutzerdefinierten Aggregatoren, die Doubles unterstützen können, erneut implementiert werden. Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/4595.

Änderung der QueryRunner-Schnittstelle

Die QueryRunner-Schnittstelle wurde geändert und die alte run()-Methode wurde entfernt und durch eine neue Methode ersetzt, die ein QueryPlus-Objekt akzeptiert. Benutzerdefinierte Abfrageerweiterungen müssen die neue Schnittstelle implementieren. Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/4184 und https://github.com/druid-io/druid/pull/4482.

Änderung der Filterschnittstelle

Die Filter.getBitmapResult()-Methode verfügt nicht mehr über eine Standardimplementierung: https://github.com/druid-io/druid/pull/4481 Benutzerdefinierte Filtererweiterungen müssen jetzt eine Implementierung für getBitmapResult() bereitstellen.

Sonstige Hinweise

jvm/gc/Zeitmetrik

Die Metrik jvm/gc/time wird nicht mehr ausgegeben und aus den hier beschriebenen Gründen durch eine neue Metrik mit dem Namen jvm/gc/cpu ersetzt: https://github.com/druid-io/druid/pull/4480

Standard-Worker-Auswahlstrategie

Bitte beachten Sie, dass sich die standardmäßige Worker-Auswahlstrategie von fillCapacity in equalDistribution geändert hat. Diese Änderung wurde in 0.10.1, der vorherigen Version, eingeführt, wurde jedoch in den 0.10.1 release notes nicht erwähnt, daher wird sie hier noch einmal erwähnt.

V8-Segmenterstellung entfernt

Druid erstellt jetzt immer V9-Segmente, das Erstellen von V8-Segmenten wird nicht mehr unterstützt und die Eigenschaft buildV9Directly für Aufnahmeaufgaben wurde entfernt. Weitere Einzelheiten finden Sie unter https://github.com/druid-io/druid/pull/4420.

LogLevelAdjuster entfernt

Bitte beachten Sie, dass der LogLevelAdjuster entfernt wurde: https://github.com/druid-io/druid/pull/4236 Jeder Benutzer, der MBeans zum Konfigurieren von Protokollebenen verwendet, sollte log4j2 stattdessen mit jmx konfigurieren.

druid druid-0.11.0

Druid 0.11.0 contains over a hundred performance improvements, stability improvements, and bug fixes from almost 40 contributors. This release adds two major security features, TLS support and extension points for authentication and authorization.

Major new features include:

  • TLS (a.k.a. SSL) support
  • Extension points for authentication and authorization
  • Double columns support
  • cachingCost Balancer Strategy
  • jq expression support in JSON parser
  • Redis cache extension
  • GroupBy performance improvements
  • Various improvements to Druid SQL

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Documentation for this release is at: http://druid.io/docs/0.11.0/

Highlights

TLS support

Druid now supports TLS, enabling encrypted client and inter-node communications. Please see http://druid.io/docs/0.11.0/operations/tls-support.html for details on configuration and related extensions.

Added by @pjain1 in https://github.com/druid-io/druid/pull/4270.

Authentication/authorization extension points

Extension points for authenticating and authorizing requests have been added to Druid. Please see http://druid.io/docs/0.11.0/configuration/auth.html for information on configuration and extension implementation.

The existing Kerberos authentication extension has been updated to implement the new Authenticator interface, please see the "Kerberos configuration changes" section under "Updating from 0.10.1 and earlier" for more information if you are using the Kerberos extension.

Added by @jon-wei in https://github.com/druid-io/druid/pull/4271

Double columns support

Druid now supports Double type aggregator columns. Please see http://druid.io/docs/0.11.0/querying/aggregations.html for documentation on the new Double aggregators.

Added by @b-slim in https://github.com/druid-io/druid/pull/4491.

cachingCost Balancer Strategy

Users upgrading to 0.11.0 are encouraged to try the new cachingCost segment balancing strategy on their coordinators. This strategy offers large performance improvements over the existing cost balancer strategy, and it is planned to become the default strategy in the release following 0.11.0.

This strategy can be selected by setting the following property on coordinators:

druid.coordinator.balancer.strategy=cachingCost

Added by @dgolitsyn in https://github.com/druid-io/druid/pull/4731

jq expression support in JSON parser

Druid's JSON input parser now supports jq expressions using jackson-jq, enabling more input transforms before ingestion. Please see http://druid.io/docs/0.11.0/ingestion/flatten-json.html for more details.

Added by @knoguchi in https://github.com/druid-io/druid/pull/4171.

Redis cache extension

A new cache implementation using Redis has been added in an extension, added by @QiuMM in https://github.com/druid-io/druid/pull/4615. Please refer to the preceding pull request for more details.

GroupBy performance improvements

Several new performance optimizations have been added to the GroupBy query by @jihoonson in the following PRs:

https://github.com/druid-io/druid/pull/4660 Parallel sort for ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Array-based aggregation for groupBy query https://github.com/druid-io/druid/pull/4668 Add IntGrouper to avoid unnecessary boxing/unboxing in array-based aggregation

PR #4660 offers a general improvement by parallelizing partial result sorting, while PR #4576 and #4668 offer significant improvements when grouping on a single String column.

SQL improvements

Various improvements and features have been added to Druid SQL, by @gianm in the following PRs:

https://github.com/druid-io/druid/pull/4750 - TRIM support https://github.com/druid-io/druid/pull/4720 - Rounding for count distinct https://github.com/druid-io/druid/pull/4561 - Metrics for SQL queries https://github.com/druid-io/druid/pull/4360 - SQL expressions support

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Updating from 0.10.1 and earlier

Please see below for changes between 0.10.1 and 0.11.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.10.1, please see release notes of the relevant intermediate versions for additional notes.

Upgrading coordinators and overlords

The following patch changes the way coordinator->overlord redirects are handled: https://github.com/druid-io/druid/pull/5037

The overlord leader election algorithm has changed in 0.11.0: https://github.com/druid-io/druid/pull/4699.

As a result of the two patches above, special care is needed when upgrading Coordinator or Overlord to 0.11.0. All coordinators and overlords must be shut down and upgraded together.

For example, to upgrade Coordinators, you would shutdown all coordinators, upgrade them to 0.11.0 and then start them. Overlords should be upgraded in a similar way.

During the upgrade process, there must not be any time period where a non-0.11.0 coordinator or overlord is running simultaneously with an 0.11.0 coordinator or overlord.

Note that at least one overlord should be brought up as quickly as possible after shutting them all down so that peons, tranquility etc continue to work after some retries.

Also note that the druid.zk.paths.indexer.leaderLatchPath property is no longer used now.

Service name changes

In earlier versions of Druid, / characters in service names defined by druid.service would be replaced by : characters because these service names were used in Zookeeper paths. Druid 0.11.0 no longer performs these character replacements.

Example:1 - if the old configuration had a broker with service name test/broker: druid.service=test/broker

and a Router was configured assuming that / will be replaced with : in the broker service name, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"}

the Router configuration should be updated to remove that assumption: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"}

Example:2 - If the old configuration had overlord with service Name test/overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test/overlord and not test:overlord

Example:3 - If the old configuration had overlord with service Name test:overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test:overlord and not test/overlord

Following service name-related configurations are also affected and should be updated to exactly match the value of druid.service property on other node being discovered.

druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap

Please see https://github.com/druid-io/druid/issues/4992 for more details.

Kerberos configuration changes

The Kerberos authentication configuration format has changed as a result of the new interfaces introduced by #4271. Please refer to http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html for the new configuration properties.

Users can point the Kerberos authenticator's authorizerName to an instance of an "allowAll" authorizer to replicate the pre-0.11.0 behavior of a cluster using Kerberos authentication with no authorization.

Lookups API path changes

The paths for the lookups configuration API have changed due to #5058.

Configuration paths that had the form /druid/coordinator/v1/lookups now have the form /druid/coordinator/v1/lookups/config.

Please see http://druid.io/docs/0.11.0/querying/lookups.html for the current API.

Migrating to Double columns

Prior to 0.11.0, the Double* aggregators would store column values on disk as Float while performing aggregations using Double representations.

PR #4491 allows the Double aggregators to store column values on disk as Doubles. Due to concerns related to rolling updates and version downgrades, this behavior is disabled by default and Druid will continue to store Double aggregators on disk as floats.

To enable Double column storage, set the following property in the common runtime properties:

druid.indexing.doubleStorage=double

Users should not set this property during an initial rolling upgrade to 0.11.0, as any nodes running pre-0.11.0 Druid will not be able to handle Double columns created during the upgrade period. Users will also need to reindex any segments with Double columns if downgrading from 0.11.0 to an older version. Please see #4944 and #4605 for more information.

Scan query changes

The Scan query has been moved from extensions-contrib to core Druid. As part of this migration: https://github.com/druid-io/druid/pull/4751, the scan query's handling of the time column has changed.

The time column is now is returned as "__time" rather than "timestamp", it is no longer included if you do not specifically ask for it in your "columns", and it is returned as a long rather than a string.

Users can revert the Scan query's time handling to the legacy extension behavior by setting "legacy" : true in their queries, or setting the property druid.query.scan.legacy = true. This is meant to provide a migration path for users that were formerly using the contrib extension.

Extension Interface Changes

Aggregator double column support

The Aggregator interface has gained a getDouble() method, which defaults to casting the result of getFloat(). The getDouble() method should be re-implemented for any custom aggregators that can support doubles.

See https://github.com/druid-io/druid/pull/4595 for more details.

QueryRunner interface change

The QueryRunner interface has changed and the old run() method has been removed, replaced by a new method that accepts a QueryPlus object.

Custom query extensions will need to implement the new interface.

Please see https://github.com/druid-io/druid/pull/4184 and https://github.com/druid-io/druid/pull/4482 for more details.

Filter interface change

The Filter.getBitmapResult() method no longer has a default implementation: https://github.com/druid-io/druid/pull/4481

Custom filter extensions will need to provide an implementation for getBitmapResult() now.

Other Notes

jvm/gc/time metric

The jvm/gc/time metric is no longer emitted, replaced by a new metric named jvm/gc/cpu for the reasons described here: https://github.com/druid-io/druid/pull/4480

Default worker select strategy

Please note that the default worker select strategy has changed from fillCapacity to equalDistribution. This change was introduced in 0.10.1, the previous release, but was not mentioned in the 0.10.1 release notes, so it is called out again here.

V8 segment creation removed

Druid will now always build V9 segments, creating V8 segments is no longer supported and the buildV9Directly property for ingestion tasks has been removed.

Please see https://github.com/druid-io/druid/pull/4420 for more details.

LogLevelAdjuster removed

Please note that the LogLevelAdjuster has been removed: https://github.com/druid-io/druid/pull/4236

Any user using mbeans to configure log levels should configure log4j2 using jmx instead.
