Druide Druide-0.13.0-incubating

Druid 0.13.0-incubating enthält über 400 neue Funktionen, Leistungs-/Stabilitäts-/Dokumentationsverbesserungen und Fehlerbehebungen von 81 Mitwirkenden. Es ist die erste Veröffentlichung von Druid im Apache Incubator-Programm. Zu den wichtigsten neuen Funktionen und Verbesserungen gehören:

  • Native parallele Batch-Indizierung
  • Automatische Segmentverdichtung
  • Systemschematabellen
  • Verbesserter Status, Statistiken und Fehlerberichte für Indizierungsaufgaben
  • SQL-kompatible Nullbehandlung
  • Broker-Caching auf Ergebnisebene
  • Aufnahme aus RDBMS
  • Bloom-Filter-Unterstützung
  • zusätzliche SQL-Ergebnisformate
  • zusätzliche Aggregatoren (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch) – Unterstützung für mehrere Gruppierungsspezifikationen in der GroupBy-Abfrage
  • gegenseitige TLS-Unterstützung
  • HTTP-basiertes Worker-Management
  • Gegendruck des Brokers – Optimierungskonfiguration für die maxBytesInMemory-Aufnahme
  • materialisierte Ansichten (Community-Erweiterung)
  • Parser für Influx Line Protocol (Community-Erweiterung)
  • OpenTSDB-Emitter (Community-Erweiterung) Die vollständige Liste der Änderungen finden Sie hier: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0 Die Dokumentation für diese Version finden Sie unter: http://druid.io/docs/0.13.0-incubating/

Highlights

Native parallele Batch-Indizierung

Stellt den index_parallel-Supervisor vor, der die parallele Stapelaufnahme teilbarer Quellen verwaltet, ohne dass eine Abhängigkeit von Hadoop erforderlich ist. Weitere Informationen finden Sie unter http://druid.io/docs/latest/ingestion/native_tasks.html. Hinweis: Dies ist die erste einphasige Implementierung und weist Einschränkungen hinsichtlich der erwarteten Partitionierung der Eingabedaten auf. Insbesondere verfügt es nicht über eine shuffle-Implementierung, die in der nächsten Iteration dieser Funktion hinzugefügt wird. Weitere Einzelheiten finden Sie im Vorschlag unter #5543. Hinzugefügt von @jihoonson in #5492.

Automatische Segmentkomprimierung

Bisher erforderte die Komprimierung kleiner Segmente in Segmente mit optimaler Größe zur Verbesserung der Abfrageleistung das Senden und Ausführen von Komprimierungs- oder Neuindizierungsaufgaben. Dies war oft ein manueller Prozess oder erforderte einen externen Planer, der die regelmäßige Übermittlung von Aufgaben erledigte. Dieser Patch implementiert eine automatische Segmentkomprimierung, die vom Koordinatordienst verwaltet wird. Hinweis: Dies ist die Erstimplementierung und weist Einschränkungen hinsichtlich der Interoperabilität mit Echtzeit-Aufnahmeaufgaben auf. Indizierungsaufgaben erfordern derzeit den Erwerb einer Sperre für den Teil der Zeitleiste, den sie ändern, um Inkonsistenzen durch gleichzeitige Vorgänge zu verhindern. Diese Implementierung verwendet Sperren mit niedriger Priorität, um sicherzustellen, dass die Echtzeitaufnahme niemals unterbrochen wird. Dies bedeutet jedoch auch, dass die Komprimierung möglicherweise keinen Fortschritt macht, wenn die Echtzeitaufgaben für das zu komprimierende Zeitintervall kontinuierlich Sperren erwerben. Dies wird in der nächsten Iteration dieser Funktion durch eine feinkörnigere Sperrung verbessert. Weitere Einzelheiten finden Sie im Vorschlag unter #4479. Dokumentation für diese Funktion: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments Hinzugefügt von @jihoonson in #5102.

Systemschematabellen

Fügt der SQL-Schnittstelle ein Systemschema hinzu, das Tabellen enthält, die Informationen zu bereitgestellten und veröffentlichten Segmenten, Knoten des Clusters und Informationen zu laufenden und abgeschlossenen Indizierungsaufgaben bereitstellen. Hinweis: Diese Implementierung enthält einige bekannte Overhead-Ineffizienzen, die in einem zukünftigen Patch behoben werden. Dokumentation für diese Funktion: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema Hinzugefügt von @surekhasaharan in #6094.

Verbesserter Indexierungsaufgabenstatus, Statistiken und Fehlerberichte

Verbessert die Leistung und Details der aufnahmebezogenen APIs, die zuvor recht undurchsichtig waren, was es schwierig machte, die Ursache von Analyseausnahmen, Aufgabenfehlern und die tatsächliche Ausgabe einer abgeschlossenen Aufgabe zu ermitteln. Bietet außerdem verbesserte Berichte zu Aufnahmemetriken, einschließlich Statistiken zum gleitenden Durchschnittsdurchsatz. Hinzugefügt von @surekhasaharan und @jon-wei in #5801, #5418 und #5748.

SQL-kompatible Nullbehandlung

Verbessert die Handhabung von Nullwerten durch Druid, indem diese als fehlende Werte behandelt werden, statt als Äquivalent zu leeren Zeichenfolgen oder einem Nullwert. Dadurch wird Druid SQL-kompatibel und verbessert die Integration mit externen BI-Tools, die ODBC/JDBC unterstützen. Siehe Nr. 4349 für einen Vorschlag. Um diese Funktion zu aktivieren, müssen Sie die systemweite Eigenschaft druid.generic.useDefaultValueForNull=false festlegen. Hinzugefügt von @nishantmonu51 in #5278 und #5958.

Broker-Caching auf Ergebnisebene

Implementiert Caching auf Ergebnisebene auf Brokern, die gleichzeitig mit dem herkömmlichen Cache auf Segmentebene arbeiten können. Siehe Nr. 4843 für einen Vorschlag. Dokumentation für diese Funktion: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching Hinzugefügt von @a2l007 in #5028.

Aufnahme aus RDBMS

Stellt einen sql-Firehose vor, der die Datenaufnahme direkt aus einem RDBMS unterstützt. Hinzugefügt von @a2l007 in #5441.

Bloom-Filterunterstützung

Integriert Unterstützung für die Optimierung von Druid-Abfragen durch Anwenden eines Bloom-Filters, der von einem externen System wie Apache Hive generiert wird. Zukünftig wird #6397 die Generierung von Bloom-Filtern als Ergebnis von Druidenabfragen unterstützen, die dann zur Optimierung zukünftiger Abfragen verwendet werden können. Hinzugefügt von @nishantmonu51 in #6222.

Zusätzliche SQL-Ergebnisformate

Fügt Ergebnisformate für zeilenbasiertes JSON und CSV sowie zusätzlich Antwortheader X-Druid-Column-Names und X-Druid-Column-Types hinzu, die eine Liste der im Ergebnis enthaltenen Spalten enthalten. Hinzugefügt von @gianm in #6191.

'stringLast'- und 'stringFirst'-Aggregatoren

Stellt zwei komplementäre Aggregatoren vor, stringLast und stringFirst, die mit Zeichenfolgenspalten arbeiten und den Wert mit dem maximalen bzw. minimalen Zeitstempel zurückgeben. Hinzugefügt von @andresgomezfrr in #5789.

ArrayOfDoublesSketch

Fügt Unterstützung für numerische Tupel-Skizzen hinzu, die die Funktionalität der Count-Distinct-Theta-Skizzen erweitern, indem Arrays von Double-Werten hinzugefügt werden, die eindeutigen Schlüsseln zugeordnet sind. Hinzugefügt von @AlexanderSaydakov in #5148.

HllSketch

Fügt eine konfigurierbare Implementierung eines Count-Distinct-Aggregators basierend auf HllSketch von https://github.com/DataSketches. hinzu. Der Vergleich mit Druids nativem HyperLogLogCollector zeigt verbesserte Genauigkeit, Effizienz und Geschwindigkeit: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html Hinzugefügt von @AlexanderSaydakov in #5712.

Unterstützung für mehrere Gruppierungsspezifikationen in der GroupBy-Abfrage

Fügt Unterstützung für den subtotalsSpec-Parameter „groupBy“ hinzu, der es Druid ermöglicht, effizient zu arbeiten, indem es Zwischenergebnisse auf Brokerebene wiederverwendet, wenn mehrere Abfragen ausgeführt werden, die nach Teilmengen desselben Spaltensatzes gruppieren. Weitere Informationen finden Sie im Vorschlag in Nr. 5179. Hinzugefügt von @himanshug in #5280.

Gegenseitige TLS-Unterstützung

Integriert die Unterstützung für gegenseitiges TLS (Serverzertifikatsvalidierung + client-Zertifikatsvalidierung). Siehe: https://en.wikipedia.org/wiki/Mutual_authentication Hinzugefügt von @jon-wei in #6076.

HTTP-basiertes Worker-Management

Fügt eine HTTP-basierte Implementierung der Indizierungsaufgabenverwaltung hinzu, um die vorherige auf ZooKeeper basierende Implementierung zu ersetzen. Teil einer Reihe von Verbesserungen, um die Abhängigkeit von Druid von ZooKeeper zu verringern und schließlich zu beseitigen. Siehe Nr. 4996 für einen Vorschlag. Hinzugefügt von @himanshug in #5104.

Broker-Gegendruck

Ermöglicht dem Broker, Gegendruck auf Datenbereitstellungsknoten auszuüben, um zu verhindern, dass der Broker unter Speicherdruck abstürzt, wenn Ergebnisse schneller eingehen, als sie von clients gelesen werden. Hinzugefügt von @gianm in #6313.

'maxBytesInMemory'-Erfassungsoptimierungskonfiguration

Zuvor war die maxRowsInMemory-Konfiguration ein wichtiger Optimierungsparameter für die Speicherverwaltung von Indizierungsaufgaben, die den Schwellenwert für das Übertragen des Speicherinhalts auf die Festplatte festlegte. Dies war schwierig richtig zu konfigurieren, da die „Größe“ einer Zeile von mehreren Faktoren abhängt. maxBytesInMemory macht diese Konfiguration bytebasiert statt zeilenbasiert. Hinzugefügt von @surekhasaharan in #5583.

Materialisierte Ansichten

Unterstützt die Erstellung materialisierter Ansichten, die in bestimmten Situationen die Abfrageleistung auf Kosten von zusätzlichem Speicher verbessern können. Weitere Informationen finden Sie unter http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html. Hinweis: Dies ist eine von der Community bereitgestellte Erweiterung und nicht automatisch in der Druid-Distribution enthalten. Wir freuen uns über Feedback zur Entscheidung, wann dies zu einer Kernerweiterung befördert werden soll. Weitere Informationen finden Sie unter Community-Erweiterungen. Hinzugefügt von @zhangxinyu1 in #5556.

Parser für das Influx Line Protocol

Fügt Unterstützung für die Aufnahme des Influx Line Protocol-Datenformats hinzu. Weitere Informationen finden Sie unter: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/ Hinweis: Dies ist eine von der Community bereitgestellte Erweiterung und nicht automatisch in der Druid-Distribution enthalten. Wir freuen uns über Feedback zur Entscheidung, wann dies zu einer Kernerweiterung befördert werden soll. Weitere Informationen finden Sie unter Community-Erweiterungen. Hinzugefügt von @njhartwell in #5440.

OpenTSDB-Emitter

Fügt Unterstützung für die Ausgabe von Druid-Metriken an OpenTSDB hinzu. Hinweis: Dies ist eine von der Community bereitgestellte Erweiterung und nicht automatisch in der Druid-Distribution enthalten. Wir freuen uns über Feedback zur Entscheidung, wann dies zu einer Kernerweiterung befördert werden soll. Weitere Informationen finden Sie unter Community-Erweiterungen. Hinzugefügt von @QiuMM in #5380.

Aktualisierung von 0.12.3 und früher

Nachfolgend finden Sie die Änderungen zwischen 0.12.3 und 0.13.0, die Sie vor dem Upgrade beachten sollten. Wenn Sie von einer früheren Version als 0.12.3 aktualisieren, lesen Sie bitte die release notes der entsprechenden Zwischenversionen für zusätzliche Hinweise.

Die Metadatenspeichererweiterung MySQL enthält keinen JDBC-Treiber mehr

Die Metadatenspeichererweiterung MySQL ist jetzt zusammen mit der Druid-Distribution enthalten, jedoch ohne den erforderlichen JDBC-Treiber MySQL (aufgrund von Lizenzbeschränkungen). Um diese Erweiterung verwenden zu können, muss der Treiber separat heruntergeladen und dem Erweiterungsverzeichnis hinzugefügt werden. Weitere Einzelheiten finden Sie unter http://druid.io/docs/latest/development/extensions-core/mysql.html.

AWS-Regionskonfiguration für S3-Erweiterung erforderlich

Aufgrund des Wechsels von jets3t zu AWS SDK (#5382) müssen Benutzer der S3-Erweiterung nun die Zielregion explizit festlegen. Dies kann durch Setzen der JVM-Systemeigenschaft aws.region oder der Umgebungsvariablen AWS_REGION erfolgen. So legen Sie beispielsweise die Region über die Systemeigenschaften auf „us-east-1“ fest:

  • Fügen Sie -Daws.region=us-east-1 zur Datei jvm.config für alle Druid-Dienste hinzu
  • Fügen Sie -Daws.region=us-east-1 zu druid.indexer.runner.javaOpts in middleManager/runtime.properties hinzu, damit die Eigenschaft an Peon-(Arbeits-)Prozesse übergeben wird

Änderungen der Aufnahmespezifikation

Aufgrund der Umbenennung der Verpackung von io.druid in org.apache.druid müssen Aufnahmespezifikationen, die Klassen über ihren vollqualifizierten Klassennamen referenzieren, entsprechend geändert werden. Wenn Sie beispielsweise die Parquet-Erweiterung mit Hadoop-Indizierung verwenden, muss das Feld inputFormat von inputSpec von io.druid.data.input.parquet.DruidParquetInputFormat in org.apache.druid.data.input.parquet.DruidParquetInputFormat geändert werden.

Metrikänderungen

Neue Metriken

– task/action/log/time – Es wurden Millisekunden benötigt, um eine Aufgabenaktion im Überwachungsprotokoll zu protokollieren (#5714)

  • task/action/run/time – Millisekunden, die zum Ausführen einer Aufgabenaktion benötigt wurden (#5714) – query/node/backpressure – Nanosekunden, in denen der Kanal aufgrund des angelegten Gegendrucks nicht lesbar ist (#6335) (Beachten Sie, dass dies standardmäßig nicht aktiviert ist und für die Ausgabe eine benutzerdefinierte Implementierung von QueryMetrics erfordert.)

Neue Dimensionen

  • taskId und taskType zu aufgabenbezogenen Metriken hinzugefügt (#5664)

Sonstiges

  • HttpPostEmitterMonitor gibt maxTime und minTime nicht mehr aus, wenn keine Zeiten erfasst wurden (#6418)

Rollback-Einschränkungen

64-Bit-Doppelaggregatoren

Standardmäßig werden jetzt 64-Bit-Doppelaggregatoren verwendet (siehe #5478). Die Unterstützung für 64-Bit-Gleitkommaspalten wurde in Druid 0.11.0 veröffentlicht. Wenn diese Option aktiviert ist, können Versionen vor 0.11.0 die Datensegmente nicht lesen. Um das alte Format zu deaktivieren und beizubehalten, müssen Sie die systemweite Eigenschaft druid.indexing.doubleStorage=float festlegen.

Bitmap-Indizes deaktivieren

0.13.0 bietet Unterstützung für die spaltenweise Deaktivierung von Bitmap-Indizes, was in Fällen, in denen Bitmap-Indizes keinen Mehrwert bieten, Platz sparen kann. Dies erfolgt durch Festlegen des Felds „createBitmapIndex“ im Dimensionsschema. Mit dieser Option geschriebene Segmente sind nicht abwärtskompatibel mit älteren Versionen von Druid (#5402).

Verhaltensänderungen

Namensänderungen des Java-Pakets

Die Paketnamen von Druid wurden alle von io.druid auf org.apache.druid verschoben. Dies wirkt sich auf den Namen der Java-Hauptklasse aus, die Sie beim Starten von Diensten ausführen sollten, der jetzt org.apache.druid.cli.Main lautet. Dies kann sich auch auf die Installation und Konfiguration von Erweiterungen und Monitoren auswirken.

ParseSpec ist jetzt ein Pflichtfeld in Aufnahmespezifikationen

Es gibt keine Standard-ParseSpec mehr (vorher DelimitedParseSpec). Für Aufnahmespezifikationen muss jetzt parseSpec angegeben werden. Wenn Sie zuvor kein parseSpec bereitgestellt haben, sollten Sie eines mit "format": "tsv" verwenden, um das vorhandene Verhalten beizubehalten (#6310).

Ändern Sie die standardmäßige maximale Anzahl an Zeilen, die in einem JDBC-Frame zurückgegeben werden sollen

Der Standardwert für druid.sql.avatica.maxRowsPerFrame wurde von 100 KB auf 5 KB reduziert, um Fehler wegen unzureichendem Arbeitsspeicher zu minimieren (#5409).

Router-Verhalten ändert sich beim Routing an Broker, die für unterschiedliche Zeitbereiche bestimmt sind

Aufgrund von #5595 können Router nun in Konfigurationen, in denen es verschiedene Ebenen von Brokern gibt, die für Abfragen in unterschiedlichen Zeitbereichen vorgesehen sind, einen unerwünschten Broker auswählen. Siehe #1362 für eine Diskussion.

Ruby TimestampSpec ignoriert Millisekunden nicht mehr

Zeitstempel, die mit einer TimestampSpec im Format „Ruby“ analysiert werden, kürzen die Millisekundenkomponente nicht mehr ab. Wenn Sie diesen Parser verwenden und eine Abfragegranularität von SECOND wünschen, stellen Sie sicher, dass er in Ihren Indizierungsspezifikationen entsprechend konfiguriert ist (#6217).

Kleine Vergrößerung der ZooKeeper-Aufgabenankündigungen

Der Datenquellenname wurde zu TaskAnnouncement hinzugefügt, was zu einer geringfügigen Erhöhung der in ZooKeeper gespeicherten Datenmenge pro Aufgabe führt (#5511).

Hinzufügung des Felds „Name“ zu gefilterten Aggregatoren

Aggregatoren vom Typ „gefiltert“ unterstützen jetzt ein „Name“-Feld. Zuvor erbte der gefilterte Aggregator den Namen des Aggregators, den er umhüllte. Wenn Sie das Feld „Name“ sowohl für den gefilterten Aggregator als auch für den umschlossenen Aggregator angegeben haben, wird der Name des gefilterten Aggregators bevorzugt. Es wird der Name des umschlossenen Aggregators verwendet, wenn der Name des gefilterten Aggregators fehlt oder leer ist (#6219).

utf8mb4 ist jetzt der empfohlene Zeichensatz für die Metadatenspeicherung

Für Upgrade-Anweisungen verwenden Sie die hier beschriebenen Anweisungen ALTER DATABASE und ALTER TABLE: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html. Zur Motivation und Referenz siehe Nr. 5377 und Nr. 5411.

Konfigurationseigenschaften entfernt

  • druid.indexer.runner.tlsStartPort wurde entfernt (#6194).
  • druid.indexer.runner.separateIngestionEndpoint wurde entfernt (#6263).

Schnittstellenänderungen für Erweiterungsentwickler

  • Verpackung wurde von io.druid in org.apache.druid umbenannt. Alle Erweiterungen von Drittanbietern müssen ihr META-INF/io.druid.initialization.DruidModule in org.apache.druid.initialization.DruidModule umbenennen und die Verpackung ihrer Erweiterung entsprechend aktualisieren (#6266). – Die DataSegmentPuller-Schnittstelle wurde entfernt (#5461).
  • Eine Reihe von Funktionen unter java-util wurden entfernt (#5461). – Der Konstruktor der Metadata-Klasse hat sich geändert (#5613). – Das Maven-Profil „spark2“ wurde entfernt (#5581).

API veraltete Versionen

Oberherr

– Der Endpunkt /druid/indexer/v1/supervisor/{id}/shutdown wurde zugunsten von /druid/indexer/v1/supervisor/{id}/terminate (#6272 und #6234) veraltet. – Der Endpunkt /druid/indexer/v1/task/{taskId}/segments ist veraltet (#6368). – Das von /druid/indexer/v1/task/ID/status zurückgegebene Feld status wurde zugunsten von statusCode veraltet (#6334). – Die Parameter reportParseExceptions und ignoreInvalidRows für Konfigurationen zur Erfassungsoptimierung wurden zugunsten von logParseExceptions und maxParseExceptions veraltet (#5418).

Makler

– Der Endpunkt /druid/v2/datasources/{dataSourceName}/dimensions ist veraltet. Stattdessen sollte eine Segmentmetadatenabfrage oder die SQL-Tabelle INFORMATION_SCHEMA verwendet werden (#6361). – Der Endpunkt /druid/v2/datasources/{dataSourceName}/metrics ist veraltet. Stattdessen sollte eine Segmentmetadatenabfrage oder die SQL-Tabelle INFORMATION_SCHEMA verwendet werden (#6361).

druid druid-0.13.0-incubating

Druid 0.13.0-incubating contains over 400 new features, performance/stability/documentation improvements, and bug fixes from 81 contributors. It is the first release of Druid in the Apache Incubator program. Major new features and improvements include:

  • native parallel batch indexing
  • automatic segment compaction
  • system schema tables
  • improved indexing task status, statistics, and error reporting
  • SQL-compatible null handling
  • result-level broker caching
  • ingestion from RDBMS
  • Bloom filter support
  • additional SQL result formats
  • additional aggregators (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch)
  • support for multiple grouping specs in groupBy query
  • mutual TLS support
  • HTTP-based worker management
  • broker backpressure
  • maxBytesInMemory ingestion tuning configuration
  • materialized views (community extension)
  • parser for Influx Line Protocol (community extension)
  • OpenTSDB emitter (community extension)

The full list of changes is here: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0

Documentation for this release is at: http://druid.io/docs/0.13.0-incubating/

Highlights

Native parallel batch indexing

Introduces the index_parallel supervisor which manages the parallel batch ingestion of splittable sources without requiring a dependency on Hadoop. See http://druid.io/docs/latest/ingestion/native_tasks.html for more information.

Note: This is the initial single-phase implementation and has limitations on how it expects the input data to be partitioned. Notably, it does not have a shuffle implementation which will be added in the next iteration of this feature. For more details, see the proposal at #5543.

Added by @jihoonson in #5492.

Automatic segment compaction

Previously, compacting small segments into optimally-sized ones to improve query performance required submitting and running compaction or re-indexing tasks. This was often a manual process or required an external scheduler to handle the periodic submission of tasks. This patch implements automatic segment compaction managed by the coordinator service.

Note: This is the initial implementation and has limitations on interoperability with realtime ingestion tasks. Indexing tasks currently require acquisition of a lock on the portion of the timeline they will be modifying to prevent inconsistencies from concurrent operations. This implementation uses low-priority locks to ensure that it never interrupts realtime ingestion, but this also means that compaction may fail to make any progress if the realtime tasks are continually acquiring locks on the time interval being compacted. This will be improved in the next iteration of this feature with finer-grained locking. For more details, see the proposal at #4479.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments

Added by @jihoonson in #5102.

System schema tables

Adds a system schema to the SQL interface which contains tables exposing information on served and published segments, nodes of the cluster, and information on running and completed indexing tasks.

Note: This implementation contains some known overhead inefficiencies that will be addressed in a future patch.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema

Added by @surekhasaharan in #6094.

Improved indexing task status, statistics, and error reporting

Improves the performance and detail of the ingestion-related APIs which were previously quite opaque making it difficult to determine the cause of parse exceptions, task failures, and the actual output from a completed task. Also adds improved ingestion metric reporting including moving average throughput statistics.

Added by @surekhasaharan and @jon-wei in #5801, #5418, and #5748.

SQL-compatible null handling

Improves Druid's handling of null values by treating them as missing values instead of being equivalent to empty strings or a zero-value. This makes Druid more SQL compatible and improves integration with external BI tools supporting ODBC/JDBC. See #4349 for proposal.

To enable this feature, you will need to set the system-wide property druid.generic.useDefaultValueForNull=false.

Added by @nishantmonu51 in #5278 and #5958.

Results-level broker caching

Implements result-level caching on brokers which can operate concurrently with the traditional segment-level cache. See #4843 for proposal.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching

Added by @a2l007 in #5028.

Ingestion from RDBMS

Introduces a sql firehose which supports data ingestion directly from an RDBMS.

Added by @a2l007 in #5441.

Bloom filter support

Adds support for optimizing Druid queries by applying a Bloom filter generated by an external system such as Apache Hive. In the future, #6397 will support generation of Bloom filters as the result of Druid queries which can then be used to optimize future queries.

Added by @nishantmonu51 in #6222.

Additional SQL result formats

Adds result formats for line-based JSON and CSV and additionally X-Druid-Column-Names and X-Druid-Column-Types response headers containing a list of columns contained in the result.

Added by @gianm in #6191.

'stringLast' and 'stringFirst' aggregators

Introduces two complementary aggregators, stringLast and stringFirst which operate on string columns and return the value with the maximum and minimum timestamp respectively.

Added by @andresgomezfrr in #5789.

ArrayOfDoublesSketch

Adds support for numeric Tuple sketches, which extend the functionality of the count distinct Theta sketches by adding arrays of double values associated with unique keys.

Added by @AlexanderSaydakov in #5148.

HllSketch

Adds a configurable implementation of a count distinct aggregator based on HllSketch from https://github.com/DataSketches. Comparison to Druid's native HyperLogLogCollector shows improved accuracy, efficiency, and speed: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html

Added by @AlexanderSaydakov in #5712.

Support for multiple grouping specs in groupBy query

Adds support for the subtotalsSpec groupBy parameter which allows Druid to be efficient by reusing intermediate results at the broker level when running multiple queries that group by subsets of the same set of columns. See proposal in #5179 for more information.

Added by @himanshug in #5280.

Mutual TLS support

Adds support for mutual TLS (server certificate validation + client certificate validation). See: https://en.wikipedia.org/wiki/Mutual_authentication

Added by @jon-wei in #6076.

HTTP based worker management

Adds an HTTP-based indexing task management implementation to replace the previous one based on ZooKeeper. Part of a set of improvements to reduce and eventually eliminate Druid's dependency on ZooKeeper. See #4996 for proposal.

Added by @himanshug in #5104.

Broker backpressure

Allows the broker to exert backpressure on data-serving nodes to prevent the broker from crashing under memory pressure when results are coming in faster than they are being read by clients.

Added by @gianm in #6313.

'maxBytesInMemory' ingestion tuning configuration

Previously, a major tuning parameter for indexing task memory management was the maxRowsInMemory configuration, which determined the threshold for spilling the contents of memory to disk. This was difficult to properly configure since the 'size' of a row varied based on multiple factors. maxBytesInMemory makes this configuration byte-based instead of row-based.

Added by @surekhasaharan in #5583.

Materialized views

Supports the creation of materialized views which can improve query performance in certain situations at the cost of additional storage. See http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html for more information.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @zhangxinyu1 in #5556.

Parser for Influx Line Protocol

Adds support for ingesting the Influx Line Protocol data format. For more information, see: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @njhartwell in #5440.

OpenTSDB emitter

Adds support for emitting Druid metrics to OpenTSDB.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @QiuMM in #5380.

Updating from 0.12.3 and earlier

Please see below for changes between 0.12.3 and 0.13.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.12.3, please see release notes of the relevant intermediate versions for additional notes.

MySQL metadata storage extension no longer includes JDBC driver

The MySQL metadata storage extension is now packaged together with the Druid distribution but without the required MySQL JDBC driver (due to licensing restrictions). To use this extension, the driver will need to be downloaded separately and added to the extension directory.

See http://druid.io/docs/latest/development/extensions-core/mysql.html for more details.

AWS region configuration required for S3 extension

As a result of switching from jets3t to the AWS SDK (#5382), users of the S3 extension are now required to explicitly set the target region. This can be done by setting the JVM system property aws.region or the environment variable AWS_REGION.

As an example, to set the region to 'us-east-1' through system properties:

  • add -Daws.region=us-east-1 to the jvm.config file for all Druid services
  • add -Daws.region=us-east-1 to druid.indexer.runner.javaOpts in middleManager/runtime.properties so that the property will be passed to peon (worker) processes

Ingestion spec changes

As a result of renaming packaging from io.druid to org.apache.druid, ingestion specs that reference classes by their fully-qualified class name will need to be modified accordingly.

As an example, if you are using the Parquet extension with Hadoop indexing, the inputFormat field of the inputSpec will need to change from io.druid.data.input.parquet.DruidParquetInputFormat to org.apache.druid.data.input.parquet.DruidParquetInputFormat.

Metrics changes

New metrics

  • task/action/log/time - Milliseconds taken to log a task action to the audit log (#5714)
  • task/action/run/time - Milliseconds taken to execute a task action (#5714)
  • query/node/backpressure - Nanoseconds the channel is unreadable due to backpressure being applied (#6335) (Note that this is not enabled by default and requires a custom implementation of QueryMetrics to emit)

New dimensions

  • taskId and taskType added to task-related metrics (#5664)

Other

  • HttpPostEmitterMonitor no longer emits maxTime and minTime if no times were recorded (#6418)

Rollback restrictions

64-bit doubles aggregators

64-bit doubles aggregators are now used by default (see #5478). Support for 64-bit floating point columns was release in Druid 0.11.0, so if this is enabled, versions older than 0.11.0 will not be able to read the data segments.

To disable and keep the old format, you will need to set the system-wide property druid.indexing.doubleStorage=float.

Disabling bitmap indexes

0.13.0 adds support for disabling bitmap indexes on a per-column basis, which can save space in cases where bitmap indexes add no value. This is done by setting the 'createBitmapIndex' field in the dimension schema. Segments written with this option will not be backwards compatible with older versions of Druid (#5402).

Behavior changes

Java package name changes

Druid's package names have all moved from io.druid to org.apache.druid. This affects the name of the Java main class that you should run when starting up services, which is now org.apache.druid.cli.Main. It may also affect installation and configuration of extensions and monitors.

ParseSpec is now a required field in ingestion specs

There is no longer a default ParseSpec (previously the DelimitedParseSpec). Ingestion specs now require parseSpec to be specified. If you previously did not provide a parseSpec, you should use one with "format": "tsv" to maintain the existing behavior (#6310).

Change to default maximum rows to return in one JDBC frame

The default value for druid.sql.avatica.maxRowsPerFrame was reduced from 100k to 5k to minimize out of memory errors (#5409).

Router behavior change when routing to brokers dedicated to different time ranges

As a result of #5595, routers may now select an undesired broker in configurations where there are different tiers of brokers that are intended to be dedicated to queries on different time ranges. See #1362 for discussion.

Ruby TimestampSpec no longer ignores milliseconds

Timestamps parsed using a TimestampSpec with format 'ruby' no longer truncates the millisecond component. If you were using this parser and wanted a query granularity of SECOND, ensure that it is configured appropriately in your indexing specs (#6217).

Small increase in size of ZooKeeper task announcements

The datasource name was added to TaskAnnouncement which will result in a small per task increase in the amount of data stored in ZooKeeper (#5511).

Addition of 'name' field to filtered aggregators

Aggregators of type 'filtered' now support a 'name' field. Previously, the filtered aggregator inherited the name of the aggregator it wrapped. If you have provided the 'name' field for both the filtered aggregator and the wrapped aggregator, it will prefer the name of the filtered aggregator. It will use the name of the wrapped aggregator if the name of the filtered aggregator is missing or empty (#6219).

utf8mb4 is now the recommended metadata storage charset

For upgrade instructions, use the ALTER DATABASE and ALTER TABLE instructions as described here: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html.

For motivation and reference, see #5377 and #5411.

Removed configuration properties

  • druid.indexer.runner.tlsStartPort has been removed (#6194).
  • druid.indexer.runner.separateIngestionEndpoint has been removed (#6263).

Interface changes for extension developers

  • Packaging has been renamed from io.druid to org.apache.druid. All third-party extensions will need to rename their META-INF/io.druid.initialization.DruidModule to org.apache.druid.initialization.DruidModule and update their extension's packaging appropriately (#6266).

  • The DataSegmentPuller interface has been removed (#5461).

  • A number of functions under java-util have been removed (#5461).

  • The constructor of the Metadata class has changed (#5613).

  • The 'spark2' Maven profile has been removed (#5581).

API deprecations

Overlord

  • The /druid/indexer/v1/supervisor/{id}/shutdown endpoint has been deprecated in favor of /druid/indexer/v1/supervisor/{id}/terminate (#6272 and #6234).
  • The /druid/indexer/v1/task/{taskId}/segments endpoint has been deprecated (#6368).
  • The status field returned by /druid/indexer/v1/task/ID/status has been deprecated in favor of statusCode (#6334).
  • The reportParseExceptions and ignoreInvalidRows parameters for ingestion tuning configurations have been deprecated in favor of logParseExceptions and maxParseExceptions (#5418).

Broker

  • The /druid/v2/datasources/{dataSourceName}/dimensions endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
  • The /druid/v2/datasources/{dataSourceName}/metrics endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
