Druide Druide-0.9.1

Druid 0.9.1 enthält Hunderte von Leistungsverbesserungen, Stabilitätsverbesserungen und Fehlerbehebungen von über 30 Mitwirkenden. Zu den wichtigsten neuen Funktionen gehören ein experimenteller Kafka Supervisor zur Unterstützung der genau einmaligen Nutzung von Apache Kafka, Unterstützung für Cluster-weite Abfragezeit-Suchen (QTL) und ein verbesserter Segmentausgleichsalgorithmus. Die vollständige Liste der Änderungen finden Sie hier: https://github.com/druid-io/druid/issues?q=milestone%3A0.9.1+is%3Aclosed

Aktualisierung von 0.9.0

Zeitsuche abfragen

Die QTL-Funktionalität (Query Time Lookup) wurde in dieser Version grundlegend überarbeitet. Die meisten Benutzer müssen ihre Konfigurationen und Abfragen aktualisieren. Die Druid-Namespace-Lookup-Erweiterung ist jetzt veraltet und wird in einer zukünftigen Version von Druid entfernt. Benutzer sollten auf die neue druid-lookups-cached-global-Erweiterung migrieren. Beide Erweiterungen können gleichzeitig geladen werden, um die Migration zu vereinfachen. Einzelheiten zur Migration finden Sie unter Umstellung auf Lookups-Cached-Global in der Dokumentation.

Weitere Hinweise

Abgesehen von den QTL-Änderungen beachten Sie bitte die folgenden Änderungen: – Der Standardwert für maxRowsInMemory wurde für alle Formen der Aufnahme pauschal auf 75.000 festgelegt. Dies steht im Einklang mit früheren Standardwerten für Hadoop-Aufgaben und Tranquility-basierte Aufnahme. Wenn Sie Echtzeit-Indexaufgaben direkt erstellt haben (ohne Tranquility), ist dieser Wert niedriger als der vorherige Standardwert von 500.000. – Der REST-Endpunkt /druid/coordinator/v1/datasources/{dataSourceName}?kill=true&interval={myISO8601Interval} ist jetzt veraltet. Stattdessen kann der neue /druid/coordinator/v1/datasources/{dataSourceName}/intervals/{interval}?kill=true REST-Endpunkt verwendet werden. – Die Eigenschaft druid.indexer.runner.separateIngestionEndpoint ist jetzt veraltet. Wenn Sie diese Funktionalität zum Isolieren von Event-Push-Anfragen und Abfragebereitstellungsanfragen für Echtzeitaufgaben verwendet haben, können Sie mit druid.indexer.server.maxChatRequests etwas Ähnliches erreichen. – Beachten Sie für Entwickler von Druid-Erweiterungen, dass die QueryGranularity-Konstanten (ALL, NONE usw.) in #2980 nach io.druid.granularity.QueryGranularities verschoben wurden. Die Abfragesyntax ist nicht betroffen.

Laufende Updates

Für fortlaufende Updates sollte der von http://druid.io/docs/0.9.1/operations/rolling-updates.html beschriebene Standard-Druid-Update-Prozess befolgt werden.

Kafka-Supervisor

Druid 0.9.1 ist die erste Version, die den experimentellen Kafka-Indizierungsdienst enthält und eine neue Indizierungsaufgabe vom Kafka-Typ sowie einen Supervisor nutzt, der im Druid-Overlord ausgeführt wird. Der Kafka-Indizierungsdienst bietet eine Garantie für eine genau einmalige Aufnahme und unterliegt nicht der Einschränkung von Ereignissen, die Zeitstempel erfordern, die in einen Fensterzeitraum fallen. Weitere Einzelheiten zu dieser Funktion finden Sie in der Dokumentation: http://druid.io/docs/0.9.1/development/extensions-core/kafka-ingestion.html. Hinweis: Der Kafka-Indexdienst verwendet den Java Kafka-Consumer, der in Kafka 0.9 eingeführt wurde. Da in dieser Version Protokolländerungen vorgenommen wurden, sind Kafka 0.9-Konsumenten nicht mit älteren Brokern kompatibel und Sie müssen sicherstellen, dass Ihre Kafka-Broker die Version 0.9 oder höher haben. Details zum Upgrade auf die neueste Version von Kafka finden Sie hier: http://kafka.apache.org/documentation.html#upgrade

Englisches Original / English original

druid druid-0.9.1

Druid 0.9.1 contains hundreds of performance improvements, stability improvements, and bug fixes from over 30 contributors. Major new features include an experimental Kafka Supervisor to support exactly-once consumption from Apache Kafka, support for cluster-wide query-time lookups (QTL), and an improved segment balancing algorithm.

The full list of changes is here: https://github.com/druid-io/druid/issues?q=milestone%3A0.9.1+is%3Aclosed

Updating from 0.9.0

Query time lookups

Query time lookup (QTL) functionality has been substantially reworked in this release. Most users will need to update their configurations and queries.

The druid-namespace-lookup extension is now deprecated, and will be removed in a future version of Druid. Users should migrate to the new druid-lookups-cached-global extension. Both extensions can be loaded simultaneously to simplify migration. For details about migrating, see Transitioning to lookups-cached-global in the documentation.

Other notes

Aside from the QTL changes, please note the following changes:

  • The default value for maxRowsInMemory has been set to 75,000 across the board for all forms of ingestion. This is in line with previous defaults for Hadoop tasks and Tranquility-based ingestion. If you were creating realtime index tasks directly (without Tranquility) then this is lower than the previous default of 500,000.
  • The /druid/coordinator/v1/datasources/{dataSourceName}?kill=true&interval={myISO8601Interval} REST endpoint is now deprecated. The new /druid/coordinator/v1/datasources/{dataSourceName}/intervals/{interval}?kill=true REST endpoint can be used instead.
  • The druid.indexer.runner.separateIngestionEndpoint property is now deprecated. If you were using this functionality to isolate event-push requests and query serving requests for realtime tasks, you can accomplish something similar with druid.indexer.server.maxChatRequests.
  • For developers of Druid extensions, note that the QueryGranularity constants (ALL, NONE, etc) have been moved to io.druid.granularity.QueryGranularities in #2980. Query syntax is not affected.

Rolling updates

The standard Druid update process described by http://druid.io/docs/0.9.1/operations/rolling-updates.html should be followed for rolling updates.

Kafka Supervisor

Druid 0.9.1 is the first version to include the experimental Kafka indexing service, utilizing a new Kafka-type indexing task and a supervisor that runs within the Druid overlord. The Kafka indexing service provides an exactly-once ingestion guarantee and does not have the restriction of events requiring timestamps which fall within a window period. More details about this feature are available in the documentation: http://druid.io/docs/0.9.1/development/extensions-core/kafka-ingestion.html.

Note: The Kafka indexing service uses the Java Kafka consumer that was introduced in Kafka 0.9. As there were protocol changes made in this version, Kafka 0.9 consumers are not compatible with older brokers and you will need to ensure that your Kafka brokers are version 0.9 or better. Details on upgrading to the latest version of Kafka can be found here: http://kafka.apache.org/documentation.html#upgrade
