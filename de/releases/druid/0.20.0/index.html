Druide Druide-0.20.0

Apache Druid 0.20.0 enthält rund 160 neue Funktionen, Fehlerbehebungen, Leistungsverbesserungen, Dokumentationsverbesserungen und zusätzliche Testabdeckung von 36 Mitwirkenden. Weitere Einzelheiten finden Sie in der vollständigen Liste der Änderungen und alles, was mit dem Meilenstein markiert ist.

<a name="20-new-features" href="#20-new-features">#</a> Neue Funktionen

<a name="20-ingestion" href="#20-ingestion">#</a> Einnahme

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> InputSource kombinieren

Es wurde eine neue kombinierende Eingabequelle hinzugefügt, die es dem Benutzer ermöglicht, während der Aufnahme mehrere Eingabequellen zu kombinieren. Weitere Einzelheiten finden Sie unter https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source. https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Ermitteln Sie automatisch die Anzahl der Shards für die parallele Aufnahme-Hash-Partitionierung

Wenn Hash-Partitionierung bei der parallelen Batch-Aufnahme verwendet wird, ist es nicht mehr erforderlich, numShards in der Partitionsspezifikation anzugeben. Druid kann nun automatisch eine Anzahl von Shards ermitteln, indem es die Daten in einer neuen Aufnahmephase scannt, die die Kardinalitäten des Partitionierungsschlüssels bestimmt. https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Grenzwerte für die Anzahl der Unteraufgabendateien für die parallele Stapelaufnahme

Der größenbasierte splitHintSpec unterstützt jetzt einen neuen maxNumFiles-Parameter, der begrenzt, wie viele Dateien einzelnen Unteraufgaben bei der parallelen Batch-Aufnahme zugewiesen werden können. Der segmentbasierte splitHintSpec, der zum erneuten Einlesen von Daten aus vorhandenen Druid-Segmenten verwendet wird, verfügt außerdem über einen neuen maxNumSegments-Parameter, der ähnlich funktioniert. Weitere Einzelheiten finden Sie unter https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec. https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Metriken zur Aufgabenslot-Nutzung

Es wurden neue Metriken zur Aufgabenslot-Nutzung hinzugefügt. Weitere Einzelheiten finden Sie in den Einträgen zu den taskSlot-Metriken unter https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service. https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Komprimierung

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Unterstützung für alle Partitionierungsschemata für die automatische Komprimierung

Für die automatische Komprimierung kann jetzt eine Partitionierungsspezifikation definiert werden, die es Benutzern ermöglicht, ihre Daten zum Zeitpunkt der Komprimierung neu zu partitionieren. Weitere Informationen finden Sie in der Dokumentation zur neuen Eigenschaft partitionsSpec in der Komprimierung tuningConfig: https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> Status der automatischen Komprimierung API

Ein neuer Koordinator API, der den Status der automatischen Komprimierung für eine Datenquelle anzeigt, wurde hinzugefügt. Der neue API zeigt an, ob die automatische Komprimierung für eine Datenquelle aktiviert ist, und eine Zusammenfassung darüber, wie weit die Komprimierung fortgeschritten ist. Die Webkonsole wurde ebenfalls aktualisiert, um diese Informationen anzuzeigen: https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png Einzelheiten zum neuen API finden Sie unter https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status und Informationen zu neuen zugehörigen Verdichtungsmetriken unter https://druid.apache.org/docs/latest/operations/metrics.html#coordination. https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Abfragen

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Abfragesegmentbereinigung mit Hash-Partitionierung

Druid unterstützt jetzt die Segmentbereinigung zur Abfragezeit (Ausschluss bestimmter Segmente als Lesekandidaten für eine Abfrage) für Hash-partitionierte Segmente. Diese Optimierung gilt, wenn alle in der Hash-Partitionsspezifikation während der Aufnahmezeit angegebenen partitionDimensions im Filtersatz einer Abfrage vorhanden sind und die Filter in der Abfrage nach diskreten Werten von partitionDimensions filtern (z. B. Auswahlfilter). Segmentbereinigung mit Hash-Partitionierung wird bei nicht diskreten Filtern wie gebundenen Filtern nicht unterstützt. Für bestehende Benutzer mit vorhandenen Segmenten müssen Sie diese Segmente erneut laden, um diese neue Funktion nutzen zu können, da für die Segmentbereinigung zusammen mit den Segmenten ein partitionFunction gespeichert werden muss, das in Segmenten, die mit älteren Versionen von Druid erstellt wurden, nicht vorhanden ist. Es ist nicht erforderlich, partitionFunction explizit anzugeben, da die Standardeinstellung dieselbe Partitionsfunktion ist, die in früheren Versionen von Druid verwendet wurde. Beachten Sie, dass Segmente, die mit einem Standardwert partitionDimensions (Partition nach allen Dimensionen + Zeitspalte) erstellt wurden, nicht auf diese Weise bereinigt werden können. Die Segmente müssen mit einem expliziten partitionDimensions erstellt werden. https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vektorisierung

Um Vektorisierungsfunktionen zu aktivieren, setzen Sie bitte die Eigenschaft druid.query.default.context.vectorizeVirtualColumns auf true oder legen Sie die Eigenschaft vectorize im Abfragekontext fest. Weitere Informationen finden Sie unter https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Vektorisierungsunterstützung für virtuelle Ausdrucksspalten

Virtuelle Ausdrucksspalten verfügen jetzt über Vektorisierungsunterstützung (abhängig von den verwendeten Ausdrücken), was in einigen Fällen zu einer 3- bis 5-fachen Leistungsverbesserung führt. Einzelheiten zu den spezifischen Ausdrücken, die die Vektorisierung unterstützen, finden Sie unter https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support. https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> Mehr Vektorisierungsunterstützung für Aggregatoren

Für mehrere Aggregationstypen wurde Vektorisierungsunterstützung hinzugefügt: numerische Min/Max-Aggregatoren, Varianzaggregatoren, ANY-Aggregatoren und Aggregatoren aus der druid-histogram-Erweiterung. https://github.com/apache/druid/pull/10260 – numerisches Min./Max https://github.com/apache/druid/pull/10304 – Histogramm https://github.com/apache/druid/pull/10338 – JEDER https://github.com/apache/druid/pull/10390 – Varianz Wir haben in einigen Fällen eine Leistungsverbesserung um das 1,3- bis 1,8-fache beobachtet, wenn die Vektorisierung für den Min-, Max- und ANY-Aggregator aktiviert war, und etwa um das 1,04- bis 1,07-fache beim Histogramm-Aggregator.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> offset-Parameter für GroupBy- und Scan-Abfragen

Es ist jetzt möglich, einen offset-Parameter für GroupBy- und Scan-Abfragen festzulegen, der Druid anweist, bei der Rückgabe von Ergebnissen eine Reihe von Zeilen zu überspringen. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.20.0/querying/limitspec.html und https://druid.apache.org/docs/0.20.0/querying/scan-query.html. https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> OFFSET-Klausel für SQL-Abfragen

Druid-SQL-Abfragen unterstützen jetzt eine OFFSET-Klausel. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.20.0/querying/sql.html#offset. https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Substring-Suchoperatoren

Druid hat in seiner Ausdruckssprache und für SQL-Abfragen neue Substring-Suchoperatoren hinzugefügt. Weitere Informationen finden Sie in der Dokumentation zu den Zeichenfolgenfunktionen CONTAINS_STRING und ICONTAINS_STRING für Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) und in der Dokumentation zu contains_string und icontains_string für die Druid-Ausdruckssprache (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions). Wir haben in einigen Fällen eine etwa 2,5-fache Leistungsverbesserung durch die Verwendung dieser Funktionen anstelle von STRPOS beobachtet. https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> UNION ALL-Operator für SQL-Abfragen

Druid-SQL-Abfragen unterstützen jetzt den Operator UNION ALL, der die Ergebnisse mehrerer Abfragen zusammenführt. Einzelheiten dazu, welche Abfrageformen von diesem Operator unterstützt werden, finden Sie unter https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all. https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Clusterweite Standard-Abfragekontexteinstellungen

Es ist jetzt möglich, Cluster-weite Standardeigenschaften für den Abfragekontext festzulegen, indem eine Konfiguration der Form druid.query.override.default.context.* hinzugefügt wird, wobei * durch den Eigenschaftsnamen ersetzt wird. https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Weitere Funktionen

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> Verbesserte Benutzeroberfläche für Aufbewahrungsregeln

Die Benutzeroberfläche für Aufbewahrungsregeln in der Webkonsole wurde verbessert. Es bietet jetzt Vorschläge und eine grundlegende Validierung im Dropdown-Menü „Zeitraum“, zeigt die Cluster-Standardregeln an und erleichtert die Bearbeitung der Standardregeln. https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Verbesserungen der Redis-Cache-Erweiterung

Die Redis-Cache-Erweiterung unterstützt jetzt den Redis-Cluster, die Auswahl der verwendeten Datenbank, die Verbindung zu kennwortgeschützten Servern und periodische Konfigurationen für die Eigenschaften expiration und timeout. https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Deaktivieren Sie das Senden der Serverversion in Antwortheadern

Es ist jetzt möglich, das Senden von Serverversionsinformationen in den Antwortheadern von Druid zu deaktivieren. Dies wird durch eine neue Eigenschaft druid.server.http.sendServerVersion gesteuert, deren Standardwert true ist. https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Geben Sie bytebasierte Konfigurationseigenschaften mit Einheiten an

Druid unterstützt jetzt Einheiten zur Angabe bytebasierter Konfigurationseigenschaften, z. B.:

druid.server.maxSize=300g

gleichbedeutend mit

druid.server.maxSize=300000000000

Weitere Einzelheiten finden Sie unter https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html. https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Fehlerbehebungen

<a name="20-query-correctness" href="#20-query-correctness">#</a> Problem mit der Abfragekorrektheit behoben, wenn der Verlauf keine Segmentzeitleiste hat

Druid 0.20.0 behebt ein Problem mit der Richtigkeit der Abfrage, wenn ein Broker eine Abfrage ausgibt, in der er erwartet, dass ein Verlauf bestimmte Segmente für eine Datenquelle enthält, der Verlauf jedoch bei der Abfrage tatsächlich keine Segmente für diese Datenquelle aufweist (z. B. wurden alle entladen, bevor der Verlauf die Abfrage verarbeitete). Vor 0.20.0 wurde die Abfrage erfolgreich zurückgegeben, jedoch ohne die Ergebnisse aus den Segmenten, die auf die zuvor beschriebene Weise fehlten. In 0.20.0 schlagen Abfragen in solchen Situationen nun fehl. https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Problem behoben, das verhindert, dass der Cache auf Ergebnisebene gefüllt wird

Druid 0.20.0 behebt ein in 0.19.0 (https://github.com/apache/druid/issues/10337) eingeführtes Problem, das verhindern kann, dass Abfrage-Caches gefüllt werden, wenn das Caching auf Ergebnisebene aktiviert ist. https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Korrektur für die Reihenfolge des Varianzaggregators

Der Varianzaggregator verwendete zuvor einen falschen Komparator, der zum Vergleich die interne count-Variable eines Aggregators anstelle der Varianz verwendete. https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Korrigieren Sie falsches Caching für GroupBy-Abfragen mit Grenzwertspezifikationen

Druid 0.20.0 behebt ein Problem mit GroupBy-Abfragen und Caching, bei dem die limitSpec der Abfrage im Cache-Schlüssel nicht berücksichtigt wurde, was zu möglicherweise falschen Ergebnissen führt, wenn Abfragen ausgegeben werden, die bis auf die limitSpec identisch sind. https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Fix für stringFirst und stringLast mit aktiviertem Rollup

https://github.com/apache/druid/issues/7243 wurde behoben. Die Aggregatoren stringFirst und stringLast verursachen keine Ausnahme mehr, wenn sie während der Aufnahme mit aktiviertem Rollup verwendet werden. https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from- previous" href="#20-upgrading-from- previous">#</a> Upgrade auf Druid 0.20.0

Bitte beachten Sie beim Upgrade von 0.19.0 auf 0.20.0 die folgenden Überlegungen. Wenn Sie von einer früheren Version als 0.19.0 aktualisieren, sehen Sie sich bitte die release notes der entsprechenden Zwischenversionen an.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Standard maxSize

druid.server.maxSize verwendet nun standardmäßig die Summe der in druid.segmentCache.locations definierten maxSize-Werte. Der Benutzer kann weiterhin einen benutzerdefinierten Wert für druid.server.maxSize angeben, der Vorrang vor dem Standardwert hat. https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Änderungen der Komprimierungs- und Kill-Task-ID

Den Aufgaben-IDs der vom Koordinator ausgegebenen Komprimierungs- und Kill-Aufgaben wird nun coordinator-issued vorangestellt, während den vom Benutzer ausgegebenen Kill-Aufgaben das Präfix api-issued vorangestellt wird. https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> Neue Größenbeschränkungen für Hinweisspezifikationen zur parallelen Aufnahmeaufteilung

Die größenbasierten und segmentbasierten splitHintSpec für die parallele Batch-Aufnahme wenden jetzt ein Standard-Datei-/Segmentlimit von 1000 pro Unteraufgabe an, das von maxNumFiles bzw. maxNumSegments gesteuert wird. https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> Neue Methoden PostAggregator und AggregatorFactory

Benutzer, die eine Erweiterung mit benutzerdefinierten PostAggregator- oder AggregatorFactory-Implementierungen entwickelt haben, müssen ihre Erweiterungen aktualisieren, da für diese beiden Schnittstellen neue Methoden in 0.20.0 definiert sind. PostAggregator hat jetzt eine neue Methode:

  ValueType getType();

Um Typinformationen zu PostAggregator zu unterstützen, verfügt AggregatorFactory außerdem über zwei neue Methoden:

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Weitere Einzelheiten zu den Schnittstellenänderungen finden Sie unter https://github.com/apache/druid/pull/9638.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> Neue Expr-bezogene Methoden

Benutzer, die eine Erweiterung mit benutzerdefinierten Expr-Implementierungen entwickelt haben, müssen ihre Erweiterungen aktualisieren, da Expr und zugehörige Schnittstellen in 0.20.0 geändert wurden. Weitere Informationen finden Sie in der PR unten: https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> Genauere query/cpu/time-Metrik

In 0.20.0 wurde die Genauigkeit der query/cpu/time-Metrik verbessert. Bisher wurden bestimmte Teile der Arbeit während der Abfrageverarbeitung nicht berücksichtigt, die im folgenden PR ausführlicher beschrieben werden: https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> Neue Metrikspalten für den Überwachungsprotokolldienst

Wenn Sie die Überwachungsprotokollierung verwenden, beachten Sie bitte, dass der Überwachungsprotokolldienstmetrik neue Spalten hinzugefügt wurden (comment, remote_address und created_date). Außerdem wurde eine optionale Spalte payload hinzugefügt, die durch Setzen von druid.audit.manager.includePayloadAsDimensionInMetric auf true aktiviert werden kann. https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext in Anforderungsprotokollen

Wenn Sie die Abfrageanforderungsprotokollierung verwenden, enthalten die Anforderungsprotokollereignisse jetzt sqlQueryContext für SQL-Abfragen. https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> Zusätzlicher Status pro Segment im Metadatenspeicher

Von Druid 0.20.0 erstellte Hash-partitionierte Segmente verfügen nun über zusätzliche partitionFunction-Daten im Metadatenspeicher. Darüber hinaus speichern Komprimierungsaufgaben jetzt zusätzliche Informationen pro Segment im Metadatenspeicher, die zur Verfolgung des Komprimierungsverlaufs verwendet werden. https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Bekannte Probleme

<a name="20-location-strat" href="#20-location-strat">#</a> druid.segmentCache.locationSelectorStrategy Injektionsfehler

Durch die Angabe eines Werts für druid.segmentCache.locationSelectorStrategy wird verhindert, dass Dienste aufgrund eines Injektionsfehlers gestartet werden. Weitere Einzelheiten finden Sie unter https://github.com/apache/druid/issues/10348.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Ressourcenleck im Daten-Sampler der Webkonsole

Wenn beim Abtasten von Daten in der Webkonsole eine Zeitüberschreitung auftritt, werden interne Ressourcen, die zum Lesen aus der Eingabequelle erstellt wurden, nicht ordnungsgemäß geschlossen. Weitere Informationen finden Sie unter https://github.com/apache/druid/pull/10467.

druid druid-0.20.0

Apache Druid 0.20.0 contains around 160 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 36 contributors. Refer to the complete list of changes and everything tagged to the milestone for further details.

<a name="20-new-features" href="#20-new-features">#</a> New Features

<a name="20-ingestion" href="#20-ingestion">#</a> Ingestion

<a name="20-combining-input-source" href="#20-combining-input-source">#</a> Combining InputSource

A new combining InputSource has been added, allowing the user to combine multiple input sources during ingestion. Please see https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#combining-input-source for more details.

https://github.com/apache/druid/pull/10387

<a name="20-auto-num-shards" href="#20-auto-num-shards">#</a> Automatically determine numShards for parallel ingestion hash partitioning

When hash partitioning is used in parallel batch ingestion, it is no longer necessary to specify numShards in the partition spec. Druid can now automatically determine a number of shards by scanning the data in a new ingestion phase that determines the cardinalities of the partitioning key.

https://github.com/apache/druid/pull/10419

<a name="20-split-hint-max-files" href="#20-split-hint-max-files">#</a> Subtask file count limits for parallel batch ingestion

The size-based splitHintSpec now supports a new maxNumFiles parameter, which limits how many files can be assigned to individual subtasks in parallel batch ingestion.

The segment-based splitHintSpec used for reingesting data from existing Druid segments also has a new maxNumSegments parameter which functions similarly.

Please see https://druid.apache.org/docs/0.20.0/ingestion/native-batch.html#split-hint-spec for more details.

https://github.com/apache/druid/pull/10243

<a name="20-task-slot-metrics" href="#20-task-slot-metrics">#</a> Task slot usage metrics

New task slot usage metrics have been added. Please see the entries for the taskSlot metrics at https://druid.apache.org/docs/0.20.0/operations/metrics.html#indexing-service for more details.

https://github.com/apache/druid/pull/10379

<a name="20-compaction" href="#20-compaction">#</a> Compaction

<a name="20-auto-compaction-partition" href="#20-auto-compaction-partition">#</a> Support for all partitioning schemes for auto-compaction

A partitioning spec can now be defined for auto-compaction, allowing users to repartition their data at compaction time. Please see the documentation for the new partitionsSpec property in the compaction tuningConfig for more details:

https://druid.apache.org/docs/0.20.0/configuration/index.html#compaction-tuningconfig

https://github.com/apache/druid/pull/10307

<a name="20-autocompaction-status-api" href="#20-autocompaction-status-api">#</a> Auto-compaction status API

A new coordinator API which shows the status of auto-compaction for a datasource has been added. The new API shows whether auto-compaction is enabled for a datasource, and a summary of how far compaction has progressed.

The web console has also been updated to show this information:

https://user-images.githubusercontent.com/177816/94326243-9d07e780-ff57-11ea-9f80-256fa08580f0.png

Please see https://druid.apache.org/docs/latest/operations/api-reference.html#compaction-status for details on the new API, and https://druid.apache.org/docs/latest/operations/metrics.html#coordination for information on new related compaction metrics.

https://github.com/apache/druid/pull/10371 https://github.com/apache/druid/pull/10438

<a name="20-querying" href="#20-querying">#</a> Querying

<a name="20-hash-segment-pruning" href="#20-hash-segment-pruning">#</a> Query segment pruning with hash partitioning

Druid now supports query-time segment pruning (excluding certain segments as read candidates for a query) for hash partitioned segments. This optimization applies when all of the partitionDimensions specified in the hash partition spec during ingestion time are present in the filter set of a query, and the filters in the query filter on discrete values of the partitionDimensions (e.g., selector filters). Segment pruning with hash partitioning is not supported with non-discrete filters such as bound filters.

For existing users with existing segments, you will need to reingest those segments to take advantage of this new feature, as the segment pruning requires a partitionFunction to be stored together with the segments, which does not exist in segments created by older versions of Druid. It is not necessary to specify the partitionFunction explicitly, as the default is the same partition function that was used in prior versions of Druid.

Note that segments created with a default partitionDimensions value (partition by all dimensions + the time column) cannot be pruned in this manner, the segments need to be created with an explicit partitionDimensions.

https://github.com/apache/druid/pull/9810 https://github.com/apache/druid/pull/10288

<a name="20-vectorization" href="#20-vectorization">#</a> Vectorization

To enable vectorization features, please set the druid.query.default.context.vectorizeVirtualColumns property to true or set the vectorize property in the query context. Please see https://druid.apache.org/docs/0.20.0/querying/query-context.html#vectorization-parameters for more information.

<a name="20-vectorized-virtual-columns" href="#20-vectorized-virtual-columns">#</a> Vectorization support for expression virtual columns

Expression virtual columns now have vectorization support (depending on the expressions being used), which an results in a 3-5x performance improvement in some cases.

Please see https://druid.apache.org/docs/0.20.0/misc/math-expr.html#vectorization-support for details on the specific expressions that support vectorization.

https://github.com/apache/druid/pull/10388 https://github.com/apache/druid/pull/10401 https://github.com/apache/druid/pull/10432

<a name="20-vectorized-aggs" href="#20-vectorized-aggs">#</a> More vectorization support for aggregators

Vectorization support has been added for several aggregation types: numeric min/max aggregators, variance aggregators, ANY aggregators, and aggregators from the druid-histogram extension.

https://github.com/apache/druid/pull/10260 - numeric min/max https://github.com/apache/druid/pull/10304 - histogram https://github.com/apache/druid/pull/10338 - ANY https://github.com/apache/druid/pull/10390 - variance

We've observed about a 1.3x to 1.8x performance improvement in some cases with vectorization enabled for the min, max, and ANY aggregator, and about 1.04x to 1.07x wuth the histogram aggregator.

<a name="20-groupby-offset" href="#20-groupby-offset">#</a> offset parameter for GroupBy and Scan queries

It is now possible set an offset parameter for GroupBy and Scan queries, which tells Druid to skip a number of rows when returning results. Please see https://druid.apache.org/docs/0.20.0/querying/limitspec.html and https://druid.apache.org/docs/0.20.0/querying/scan-query.html for details.

https://github.com/apache/druid/pull/10235 https://github.com/apache/druid/pull/10233

<a name="20-sql-offset" href="#20-sql-offset">#</a> OFFSET clause for SQL queries

Druid SQL queries now support an OFFSET clause. Please see https://druid.apache.org/docs/0.20.0/querying/sql.html#offset for details.

https://github.com/apache/druid/pull/10279

<a name="20-sql-contains" href="#20-sql-contains">#</a> Substring search operators

Druid has added new substring search operators in its expression language and for SQL queries.

Please see documentation for CONTAINS_STRING and ICONTAINS_STRING string functions for Druid SQL (https://druid.apache.org/docs/0.20.0/querying/sql.html#string-functions) and documentation for contains_string and icontains_string for the Druid expression language (https://druid.apache.org/docs/0.20.0/misc/math-expr.html#string-functions).

We've observed about a 2.5x performance improvement in some cases by using these functions instead of STRPOS.

https://github.com/apache/druid/pull/10350

<a name="20-sql-union-all" href="#20-sql-union-all">#</a> UNION ALL operator for SQL queries

Druid SQL queries now support the UNION ALL operator, which fuses the results of multiple queries together. Please see https://druid.apache.org/docs/0.20.0/querying/sql.html#union-all for details on what query shapes are supported by this operator.

https://github.com/apache/druid/pull/10324

<a name="20-cluster-wide-default-query-context" href="#20-cluster-wide-default-query-context">#</a> Cluster-wide default query context settings

It is now possible to set cluster-wide default query context properties by adding a configuration of the form druid.query.override.default.context.*, with * replaced by the property name.

https://github.com/apache/druid/pull/10208

<a name="20-other" href="#20-other">#</a> Other features

<a name="20-improved-retention-rules-ui" href="#20-improved-retention-rules-ui">#</a> Improved retention rules UI

The retention rules UI in the web console has been improved. It now provides suggestions and basic validation in the period dropdown, shows the cluster default rules, and makes editing the default rules more accessible.

https://github.com/apache/druid/pull/10226

<a name="20-redis-extension" href="#20-redis-extension">#</a> Redis cache extension enhancements

The Redis cache extension now supports Redis Cluster, selecting which database is used, connecting to password-protected servers, and period-style configurations for the expiration and timeout properties.

https://github.com/apache/druid/pull/10240

<a name="20-disable-server-version" href="#20-disable-server-version">#</a> Disable sending server version in response headers

It is now possible to disable sending of server version information in Druid's response headers.

This is controlled by a new property druid.server.http.sendServerVersion, which defaults to true.

https://github.com/apache/druid/pull/9832

<a name="20-byte-units" href="#20-byte-units">#</a> Specify byte-based configuration properties with units

Druid now supports units for specifying byte-based configuration properties, e.g.:

druid.server.maxSize=300g

equivalent to

druid.server.maxSize=300000000000

Please see https://druid.apache.org/docs/0.20.0/configuration/human-readable-byte.html for more details.

https://github.com/apache/druid/pull/10203

<a name="20-bugs" href="#20-bugs">#</a> Bug fixes

<a name="20-query-correctness" href="#20-query-correctness">#</a> Fix query correctness issue when historical has no segment timeline

Druid 0.20.0 fixes a query correctness issue when a broker issues a query expecting a historical to have certain segments for a datasource, but the historical when queried does not actually have any segments for that datasource (e.g., they were all unloaded before the historical processed the query). Prior to 0.20.0, the query would return successfully but without the results from the segments that were missing in the manner described previously. In 0.20.0, queries will now fail in such situations.

https://github.com/apache/druid/pull/10199

<a name="20-result-caching" href="#20-result-caching">#</a> Fix issue preventing result-level cache from being populated

Druid 0.20.0 fixes an issue introduced in 0.19.0 (https://github.com/apache/druid/issues/10337) which can prevent query caches from being populated when result-level caching is enabled.

https://github.com/apache/druid/pull/10341

<a name="20-variance-comparator" href="#20-variance-comparator">#</a> Fix for variance aggregator ordering

The variance aggregator previously used an incorrect comparator that compared using an aggregator's internal count variable instead of the variance.

https://github.com/apache/druid/pull/10340

<a name="20-limitspec-cache" href="#20-limitspec-cache">#</a> Fix incorrect caching for groupBy queries with limit specs

Druid 0.20.0 fixes an issues with groupBy queries and caching, where the limitSpec of the query was not considered in the cache key, leading to potentially incorrect results if queries that are identical except for the limitSpec are issued.

https://github.com/apache/druid/pull/10093

<a name="20-string-last-rollup" href="#20-string-last-rollup">#</a> Fix for stringFirst and stringLast with rollup enabled

https://github.com/apache/druid/issues/7243 has been resolved, the stringFirst and stringLast aggregators no longer cause an exception when used during ingestion with rollup enabled.

https://github.com/apache/druid/pull/10332

<a name="20-upgrading-from-previous" href="#20-upgrading-from-previous">#</a> Upgrading to Druid 0.20.0

Please be aware of the following considerations when upgrading from 0.19.0 to 0.20.0. If you're updating from an earlier version than 0.19.0, please see the release notes of the relevant intermediate versions.

<a name="20-default-max-size" href="#20-default-max-size">#</a> Default maxSize

druid.server.maxSize will now default to the sum of maxSize values defined within the druid.segmentCache.locations. The user can still provide a custom value for druid.server.maxSize which will take precedence over the default value.

https://github.com/apache/druid/pull/10255

<a name="20-id-name-change" href="#20-id-name-change">#</a> Compaction and kill task ID changes

Compaction and kill tasks issued by the coordinator will now have their task IDs prefixed by coordinator-issued, while user-issued kill tasks will be prefixed by api-issued.

https://github.com/apache/druid/pull/10278

<a name="20-new-size-limit-split" href="#20-new-size-limit-split">#</a> New size limits for parallel ingestion split hint specs

The size-based and segment-based splitHintSpec for parallel batch ingestion now apply a default file/segment limit of 1000 per subtask, controlled by the maxNumFiles and maxNumSegments respectively.

https://github.com/apache/druid/pull/10243

<a name="20-new-agg-methods" href="#20-new-agg-methods">#</a> New PostAggregator and AggregatorFactory methods

Users who have developed an extension with custom PostAggregator or AggregatorFactory implementions will need to update their extensions, as these two interfaces have new methods defined in 0.20.0.

PostAggregator now has a new method:

  ValueType getType();

To support type information on PostAggregator, AggregatorFactory also has 2 new methods:

  public abstract ValueType getType();

  public abstract ValueType getFinalizedType();

Please see https://github.com/apache/druid/pull/9638 for more details on the interface changes.

<a name="20-new-expr-methods" href="#20-new-expr-methods">#</a> New Expr-related methods

Users who have developed an extension with custom Expr implementions will need to update their extensions, as Expr and related interfaces hae changed in 0.20.0. Please see the PR below for details:

https://github.com/apache/druid/pull/10401

<a name="20-sequence-time" href="#20-sequence-time">#</a> More accurate query/cpu/time metric

In 0.20.0, the accuracy of the query/cpu/time metric has been improved. Previously, it did not account for certain portions of work during query processing, described in more detail in the following PR:

https://github.com/apache/druid/pull/10377

<a name="20-audit-log-cols" href="#20-audit-log-cols">#</a> New audit log service metric columns

If you are using audit logging, please be aware that new columns have been added to the audit log service metric (comment, remote_address, and created_date). An optional payload column has also been added, which can be enabled by setting druid.audit.manager.includePayloadAsDimensionInMetric to true.

https://github.com/apache/druid/pull/10373

<a name="20-request-log-sql-context" href="#20-request-log-sql-context">#</a> sqlQueryContext in request logs

If you are using query request logging, the request log events will now include the sqlQueryContext for SQL queries.

https://github.com/apache/druid/pull/10368

<a name="20-last-compaction-state" href="#20-last-compaction-state">#</a> Additional per-segment state in metadata store

Hash-partitioned segments created by Druid 0.20.0 will now have additional partitionFunction data in the metadata store.

Additionally, compaction tasks will now store additional per-segment information in the metadata store, used for tracking compaction history.

https://github.com/apache/druid/pull/10288 https://github.com/apache/druid/pull/10413

<a name="20-known-issues" href="#20-known-issues">#</a> Known issues

<a name="20-location-strat" href="#20-location-strat">#</a> druid.segmentCache.locationSelectorStrategy injection failure

Specifying a value for druid.segmentCache.locationSelectorStrategy prevents services from starting due to an injection error. Please see https://github.com/apache/druid/issues/10348 for more details.

<a name="20-timed-shutoff" href="#20-timed-shutoff">#</a> Resource leak in web console data sampler

When a timeout occurs while sampling data in the web console, internal resources created to read from the input source are not properly closed. Please see https://github.com/apache/druid/pull/10467 for more information.
