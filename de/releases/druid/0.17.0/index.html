Druide Druide-0.17.0

Apache Druid 0.17.0 enthält über 250 neue Funktionen, Leistungsverbesserungen, Fehlerbehebungen und wichtige Dokumentationsverbesserungen von 52 Mitwirkenden. Sehen Sie sich die vollständige Liste der Änderungen und alles, was mit dem Meilenstein markiert ist an.

Highlights

Verbesserungen bei der Batch-Aufnahme

Druid 0.17.0 enthält ein bedeutendes Update des nativen Batch-Ingestion-Systems. Dieses Update fügt das interne Framework zur Unterstützung von Nicht-Text-Binärformaten hinzu, mit anfänglicher Unterstützung für ORC und Parquet. Darüber hinaus können native Batch-Aufgaben jetzt Daten aus HDFS lesen. Diese Überarbeitung ändert die Art und Weise, wie die Aufnahmequelle und das Datenformat in der Aufnahmeaufgabe angegeben werden. Informationen zur Nutzung der neuen Funktionen finden Sie in der Dokumentation zu InputSources und InputFormats. Weitere Informationen finden Sie in der folgenden Dokumentation: https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec https://github.com/apache/druid/issues/8812

Partitionierung einzelner Dimensionsbereiche für parallele native Batch-Aufnahme

Die parallele Indexaufgabe unterstützt jetzt die Partitionsspezifikation vom Typ single_dim, die eine bereichsbasierte Partitionierung auf einer einzelnen Dimension ermöglicht. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html.

Komprimierungsänderungen

Hinweise zur parallelen Indexaufgabenaufteilung

Die parallele Indizierungsaufgabe verfügt jetzt über eine neue Konfiguration, splitHintSpec, in tuningConfig, damit Bediener Hinweise bereitstellen können, um die Datenmenge zu steuern, die jede Unteraufgabe der ersten Phase liest. Derzeit gibt es einen Split-Hinweis-Spezifikationstyp, SegmentsSplitHintSpec, der für die erneute Aufnahme von Druid-Segmenten verwendet wird.

Parallele automatische Komprimierung

Die automatische Komprimierung kann jetzt die parallele Indizierungsaufgabe verwenden, was einen höheren Komprimierungsdurchsatz ermöglicht. Um den Grad der Parallelität zu steuern, verfügt die automatische Komprimierung tuningConfig über die neuen Parameter maxNumConcurrentSubTasks und splitHintSpec. Weitere Informationen finden Sie unter https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration. https://github.com/apache/incubator-druid/pull/8570

Zustandsbehaftete automatische Komprimierung

Die automatische Komprimierung verwendet jetzt die PartitionSpec, um Änderungen zu verfolgen, die durch vorherige Komprimierungsaufgaben vorgenommen wurden, sodass der Koordinator redundante Komprimierungsvorgänge reduzieren kann. Weitere Informationen finden Sie unter https://github.com/apache/druid/issues/8489. Wenn Sie die automatische Komprimierung aktiviert haben, lesen Sie vor dem Upgrade bitte die Informationen unter „Änderungen der zustandsbehafteten automatischen Komprimierung“ im Abschnitt „Upgrade auf Druid 0.17.0“.

Parallele Abfragezusammenführung bei Brokern

Der Druid-Broker kann nun Abfrageergebnisse mithilfe mehrerer Threads opportunistisch parallel zusammenführen. Einzelheiten zur Konfiguration dieser neuen Funktion finden Sie unter druid.processing.merge.useParallelMergePool im Abschnitt „Broker“ der Konfigurationsreferenz. Die parallele Zusammenführung ist standardmäßig aktiviert (gesteuert durch die Eigenschaft druid.processing.merge.useParallelMergePool), und die meisten Benutzer sollten keine der in der Konfigurationsreferenz beschriebenen erweiterten Konfigurationseigenschaften ändern müssen. Darüber hinaus kann die Merge-Parallelität mithilfe des Abfragekontexts für jede einzelne Abfrage gesteuert werden. Informationen zu den neuen Abfragekontextparametern finden Sie unter https://druid.apache.org/docs/0.17.0/querying/query-context.html. https://github.com/apache/incubator-druid/pull/8578

SQL-kompatible Nullbehandlung

In 0.17.0 haben wir die offizielle Dokumentation für den SQL-kompatiblen Nullverarbeitungsmodus von Druid hinzugefügt. Weitere Informationen finden Sie unter https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling und https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling. Mehrere Fehler, die in diesem zuvor undokumentierten Modus vorhanden waren, wurden behoben, insbesondere im Zusammenhang mit der Nullbehandlung in numerischen Spalten. Wir empfehlen Benutzern, nach dem Upgrade auf 0.17.0 darüber nachzudenken, ihre Cluster auf diesen neuen Modus umzustellen. Die vollständige Liste der in 0.17.0 behobenen Fehler bei der Nullbehandlung finden Sie unter https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+

LDAP-Erweiterung

Druid unterstützt jetzt die LDAP-Authentifizierung. Die Autorisierung mithilfe von LDAP-Gruppen wird auch durch die Zuordnung von LDAP-Gruppen zu Druid-Rollen unterstützt. – Die LDAP-Authentifizierung wird durch die Angabe eines LDAP-Typ-Anmeldeinformationsvalidators gehandhabt. – Die Autorisierung mithilfe von LDAP wird durch die Angabe eines LDAP-Typ-Rollenanbieters und die Definition von LDAP-Gruppen->Druid-Rollenzuordnungen innerhalb von Druid gehandhabt. Für die LDAP-Integration ist die Kernerweiterung druid-basic-security erforderlich. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html. Da dies die erste Version mit LDAP-Unterstützung ist und es eine große Vielfalt an LDAP-Ökosystemen gibt, werden einige LDAP-Anwendungsfälle und -Funktionen möglicherweise noch nicht unterstützt. Bitte melden Sie ein Problem, wenn Sie Verbesserungen dieser neuen Funktionalität benötigen. https://github.com/apache/incubator-druid/pull/6972

Dropwizard-Emitter

Als Contrib-Erweiterung wurde ein neuer Dropwizard-Metrik-Emitter hinzugefügt. Die derzeit unterstützten Dropwizard-Metriktypen sind Zähler, Messgerät, Messgerät, Timer und Histogramm. Diese Metriken können entweder über eine Konsole oder einen JMX-Reporter ausgegeben werden. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html. https://github.com/apache/incubator-druid/pull/7363

Ressource zur Selbstfindung

Allen Druid-Diensten wurde ein neues Endpunktpaar hinzugefügt, das vom zentralen Diensterkennungsmechanismus (derzeit ZooKeeper) Informationen darüber zurückgibt, ob der Druid-Dienst eine Bestätigung erhalten hat, dass der Dienst zum Cluster hinzugefügt wurde. Diese Endpunkte können als Zustands-/Bereitschaftsprüfungen nützlich sein. Die neuen Endpunkte sind:

  • /status/selfDiscovered/status
  • /status/selfDiscovered Weitere Informationen finden Sie in der Druid-API-Referenz. https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Supervisor-Systemtabelle

Aufgabenbetreuer (z. B. Kafka- oder Kinesis-Betreuer) werden nun in den Systemtabellen in einer neuen sys.supervisors-Tabelle erfasst. Weitere Informationen finden Sie unter https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table. https://github.com/apache/incubator-druid/pull/8547

Schneller historischer Start mit Lazy Loading

Eine neue boolesche Konfigurationseigenschaft für historische Daten, druid.segmentCache.lazyLoadOnStart, wurde hinzugefügt. Mit dieser neuen Eigenschaft können historische Daten das Laden eines Segments bis zur ersten Abfrage dieses Segments verzögern, was die historischen Startzeiten für Cluster mit einer großen Anzahl von Segmenten erheblich verkürzen kann. Weitere Informationen finden Sie in der Konfigurationsreferenz. https://github.com/apache/incubator-druid/pull/6988

Änderung der historischen Segment-Cache-Verteilung

Eine neue historische Immobilie, druid.segmentCache.locationSelectorStrategy, wurde hinzugefügt. Wenn in druid.segmentCache.locations mehrere Segmentspeicherorte angegeben sind, kann der Benutzer mit der neuen Eigenschaft locationSelectorStrategy angeben, welche Strategie zum Füllen der Orte verwendet wird. Derzeit unterstützte Optionen sind roundRobin und leastBytesUsed. Weitere Informationen finden Sie in der Konfigurationsreferenz. https://github.com/apache/incubator-druid/pull/8038

Neue Bereitschaftsendpunkte

Ein neuer Broker-Endpunkt wurde hinzugefügt: /druid/broker/v1/readiness. Ein neuer historischer Endpunkt wurde hinzugefügt: /druid/historical/v1/readiness. Diese Endpunkte ähneln den vorhandenen Endpunkten /druid/broker/v1/loadstatus und /druid/historical/v1/loadstatus. Sie unterscheiden sich dadurch, dass sie keine Authentifizierungs-/Autorisierungsprüfungen erfordern und anstelle eines JSON-Bodys nur einen 200-Erfolgs- oder 503-HTTP-Antwortcode zurückgeben. https://github.com/apache/incubator-druid/pull/8841

Zuweisung von Supportaufgaben basierend auf MiddleManager-Kategorien

Es ist jetzt möglich, für jeden MiddleManager eine Namenseigenschaft „Kategorie“ zu definieren. Es wurden neue kategoriebezogene Strategien zur Arbeiterauswahl hinzugefügt, mit denen der Benutzer steuern kann, wie Aufgaben MiddleManagern basierend auf den konfigurierten Kategorien zugewiesen werden. Weitere Informationen finden Sie in der Dokumentation für druid.worker.category in der Konfigurationsreferenz und unter den folgenden Links: https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec https://github.com/apache/druid/pull/7066

Updates zu Sicherheitslücken

Eine große Anzahl von Abhängigkeiten wurde auf neuere Versionen aktualisiert, um Sicherheitslücken zu schließen. Weitere Informationen finden Sie in den PRs unten:

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

Upgrade auf Druid 0.17.0

Native Abfrage auswählen wurde ersetzt

Der veraltete Select Native-Abfragetyp wurde in 0.17.0 entfernt. Wenn Sie native Abfragen haben, die Select verwenden, müssen Sie diese ändern, um stattdessen Scan zu verwenden. Einzelheiten zur Syntax und zum Ausgabeformat finden Sie in der Scan-Abfragedokumentation (https://druid.apache.org/docs/0.17.0/querying/scan-query.html). Für Druid-SQL-Abfragen, die Select verwenden, sind keine Änderungen erforderlich. Der SQL-Planer verwendet unter dem Deckmantel bereits den Abfragetyp „Scan“ für Auswahlabfragen. https://github.com/apache/incubator-druid/pull/8739

Alte Konsolen wurden entfernt

Die alten Coordinator- und Overlord-Konsolen wurden entfernt und durch die neue Webkonsole auf dem Coordinator und Overlord ersetzt. https://github.com/apache/incubator-druid/pull/8838

Calcite 1.21-Upgrade, Druid SQL-Nullbehandlung

Druide 0.17.0 aktualisiert Calcit auf Version 1.21. Diese neuere Version von Calcite kann zusätzliche Optimierungen vornehmen, die bei der Planung von Abfragen ein SQL-konformes Nullverarbeitungsverhalten voraussetzen. Wenn Sie Druid SQL verwenden und sich auf das Verhalten bei der Nullbehandlung verlassen, lesen Sie bitte die Informationen unter https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling und stellen Sie sicher, dass Ihr Druid-Cluster vor dem Upgrade im SQL-kompatiblen Nullbehandlungsmodus ausgeführt wird. https://github.com/apache/incubator-druid/pull/8566

Protokollierungsanpassungen

Druid 0.17.0 hat seinen Lebenszyklus, Abfragen und Aufnahmeprotokollierung aufgeräumt. Eine detaillierte Liste der Änderungen finden Sie unter https://github.com/apache/incubator-druid/pull/8889. Wenn Sie sich bei externen Integrationen auf bestimmte Protokollmeldungen verlassen haben, überprüfen Sie bitte vor dem Upgrade die neuen Protokollierungsänderungen. Der vollständige Satz an Protokollmeldungen ist weiterhin sichtbar, wenn die Protokollierung auf DEBUG-Ebene eingestellt ist. Vorlagen-Log4j2-Konfigurationsdateien, die zeigen, wie die DEBUG-Protokollierung pro Paket aktiviert wird, werden im Konfigurationsordner _common in den Beispielclustern unter conf/druid bereitgestellt.

Änderungen bei der zustandsbehafteten automatischen Komprimierung

Die Planungslogik für die automatische Komprimierung in 0.17.0 verfolgt zusätzliche Segmentpartitionierungsinformationen im Metadatenspeicher von Druid, die in älteren Versionen nicht vorhanden sind. Anhand dieser Informationen wird ermittelt, ob eine Reihe von Segmenten bereits unter den aktuellen automatischen Komprimierungskonfigurationen des Clusters komprimiert wurde. Wenn diese neuen Metadaten nicht vorhanden sind, wird immer eine Reihe von Segmenten für eine anfängliche Komprimierung eingeplant und diese neuen Metadaten werden nach der Komprimierung erstellt, sodass der Planer sie später überspringen kann, wenn die Konfiguration der automatischen Komprimierung unverändert bleibt. Da diese zusätzlichen Segmentpartitionierungsmetadaten vor 0.17.0 nicht vorhanden sind, komprimiert die Planungslogik für die automatische Komprimierung alle Segmente innerhalb einer Datenquelle nach dem Upgrade auf 0.17.0 einmal neu. Diese erneute Komprimierung des gesamten Segmentsatzes für jede Datenquelle, für die die automatische Komprimierung aktiviert ist, bedeutet Folgendes: – Nach dem Upgrade wird es eine Übergangszeit geben, in der insgesamt mehr Komprimierungsaufgaben in die Warteschlange gestellt werden als unter normalen Bedingungen – Die Deep-Storage-Nutzung nimmt zu, wenn der gesamte Segmentsatz neu komprimiert wird (der alte Segmentsatz bleibt weiterhin im Deep-Storage, sofern er nicht explizit entfernt wird). Benutzern wird empfohlen, sich der vorübergehenden Zunahme geplanter Komprimierungsaufgaben und der Auswirkungen auf die Deep-Storage-Nutzung bewusst zu sein. Die Dokumentation zum Entfernen alter Segmente finden Sie unter https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

targetCompactionSizeBytes-Eigenschaft entfernt

Die Eigenschaft targetCompactionSizeBytes wurde aus der Komprimierungsaufgabe und der Konfiguration der automatischen Komprimierung entfernt. Für die automatische Komprimierung ist maxRowsPerSegment jetzt eine obligatorische Konfiguration. Für nicht automatische Verdichtungsaufgaben kann jeder partitionsSpec verwendet werden. https://github.com/apache/incubator-druid/pull/8573

Komprimierungsaufgabe tuningConfig

Aufgrund der durch #8570 eingeführten parallelen automatischen Komprimierungsänderungen müssen alle manuell übermittelten Komprimierungsaufgabenspezifikationen aktualisiert werden, um einen index_parallel-Typ für den Abschnitt tuningConfig anstelle von index zu verwenden. Diese Spezifikationsänderungen sollten angewendet werden, nachdem der Cluster auf 0.17.0 aktualisiert wurde. Vorhandene Konfigurationen für die automatische Komprimierung können nach dem Update unverändert bleiben; Durch die automatische Komprimierung werden nicht parallele Komprimierungsaufgaben erstellt, bis die Konfigurationen für die automatische Komprimierung aktualisiert werden, um nach dem Upgrade Parallelität zu verwenden. Um den Grad der Parallelität zu steuern, verfügt die automatische Komprimierung tuningConfig über die neuen Parameter maxNumConcurrentSubTasks und splitHintSpec. Weitere Informationen finden Sie unter https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration.

Komprimierungsaufgabe ioConfig

Für die Komprimierungsaufgabe ist nun ein ioConfig in der Aufgabenspezifikation erforderlich. Einzelheiten finden Sie unter https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig. ioConfig muss nicht zu vorhandenen Konfigurationen für die automatische Komprimierung hinzugefügt werden. Der Koordinator erstellt nach dem Upgrade automatisch Aufgabenspezifikationen mit ioConfig-Abschnitten. https://github.com/apache/incubator-druid/pull/8571

Partitionsspezifikationsfelder umbenannt

Die Felder targetPartitionSize und maxSegmentSize in den Partitionsspezifikationen sind veraltet. Sie wurden in targetNumRowsPerSegment bzw. maxRowsPerSegment umbenannt. https://github.com/apache/incubator-druid/pull/8507

Cache-Metriken sind standardmäßig deaktiviert

Cache-Metriken sind jetzt standardmäßig deaktiviert. Um Cache-Metriken zu aktivieren, fügen Sie "org.apache.druid.client.cache.CacheMonitor" zur Eigenschaft druid.monitoring.monitors hinzu. https://github.com/apache/incubator-druid/pull/8561

Supervisor API wurde geändert, um mit der Aufgabe API übereinzustimmen

Supervisor-Aufgabenspezifikationen sollten jetzt die Abschnitte dataSchema, tuningConfig und ioConfig als Unterfelder eines spec-Felds einfügen. Beispiele finden Sie unter https://github.com/apache/incubator-druid/pull/8810. Das alte Format wird in 0.17.0 weiterhin akzeptiert.

Segmente API Semantikänderung

Der /datasources/{dataSourceName}/segments-Endpunkt auf dem Koordinator gibt jetzt alle verwendeten Segmente (einschließlich überschattet) in den angegebenen Intervallen zurück und nicht nur die sichtbaren. https://github.com/apache/incubator-druid/pull/8564

Passwortanbieter für die Basisauthentifizierung von HttpEmitterConfig

Die Eigenschaft druid.emitter.http.basicAuthentication akzeptiert jetzt einen Passwortanbieter. Wir empfehlen, Ihre Konfigurationen zu aktualisieren, um einen Passwortanbieter zu verwenden, wenn Sie den HTTP-Emitter verwenden. https://github.com/apache/incubator-druid/pull/8618

Änderung der Transformation mehrwertiger Ausdrücke

Die Wiederverwendung mehrwertiger Spalten in Ausdrücken führt nicht mehr zu unnötigen kartesischen Explosionen. Weitere Informationen finden Sie unter den folgenden Links. https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Kafka/Kinesis-Aufnahme während fortlaufender Upgrades

Wenn während eines fortlaufenden Upgrades Aufgaben vorhanden sind, auf denen 0.17.0 ausgeführt wird, und Overlords, auf denen ältere Versionen ausgeführt werden, und eine Aufgabe beim Lesen von Daten aus ihrem Stream Fortschritte gemacht hat, aber alle Datensätze abgelehnt hat, die sie gesehen hat (z. B. waren alle nicht analysierbar), werden NullPointerExceptions auf Overlords angezeigt, auf denen ältere Versionen ausgeführt werden, wenn die Aufgabe den Overlord mit seinen aktuellen Stream-Offsets aktualisiert. Zuvor gab es in diesem Bereich einen Fehler (https://github.com/apache/incubator-druid/issues/8765), bei dem solche Aufgaben ihre aktuellen Offsets nicht an den Overlord mitteilen konnten. Das Task-/Overlord-Veröffentlichungsprotokoll wurde aktualisiert, um dieses Problem zu beheben, aber ältere Overlords erkennen diese Protokolländerung nicht. Dieser Zustand sollte ziemlich selten sein.

Änderung der Standard-Hadoop-Version

Druid 0.17.0 bündelt jetzt Hadoop 2.8.5-Bibliotheken anstelle von 2.8.3. Wenn Sie in Ihrer Konfiguration über die Eigenschaft druid.indexer.task.defaultHadoopCoordinates oder die Eigenschaft hadoopDependencyCoordinates in Ihren Hadoop-Aufnahmespezifikationen auf die gebündelten 2.8.3-Bibliotheken verwiesen haben, müssen Sie diese Verweise aktualisieren, sodass sie stattdessen auf die gebündelten 2.8.5-Bibliotheken verweisen.

ParseSpec.verify-Methode entfernt

Wenn Sie eine benutzerdefinierte Erweiterung verwaltet haben, die eine Implementierung für die ParseSpec-Schnittstelle bereitstellt, wurde die verify-Methode entfernt, und die @Override-Annotation für die Methode muss in allen benutzerdefinierten Implementierungen entfernt werden. https://github.com/apache/druid/pull/8744

Bekannte Probleme

Filterung nach langen Spalten im SQL-kompatiblen Nullverarbeitungsmodus

Uns ist derzeit ein Fehler beim Anwenden bestimmter Filtertypen auf Nullwerte aus langen Spalten bekannt, wenn die SQL-kompatible Nullbehandlung aktiviert ist (https://github.com/apache/druid/issues/9255). Bitte reichen Sie ein Problem ein, wenn Sie auf andere Probleme bei der Nullverarbeitung stoßen.

Vorschau der Aufnahmespezifikation in der Webkonsole

Die angezeigten Vorschauspezifikationen für native Batch-Aufnahmeaufgaben, die im Data Loader der Webkonsole erstellt wurden, sind nicht korrekt formatiert und schlagen fehl, wenn Sie sie kopieren und manuell übermitteln. Durch die Übermittlung dieser Spezifikationen über den Data Loader wird jedoch eine korrekt formatierte Spezifikation übermittelt. https://github.com/apache/druid/issues/9144

Weitere bekannte Probleme

Eine vollständige Liste der offenen Probleme finden Sie unter https://github.com/apache/druid/labels/Bug

druid druid-0.17.0

Apache Druid 0.17.0 contains over 250 new features, performance enhancements, bug fixes, and major documentation improvements from 52 contributors. Check out the complete list of changes and everything tagged to the milestone.

Highlights

Batch ingestion improvements

Druid 0.17.0 includes a significant update to the native batch ingestion system. This update adds the internal framework to support non-text binary formats, with initial support for ORC and Parquet. Additionally, native batch tasks can now read data from HDFS.

This rework changes how the ingestion source and data format are specified in the ingestion task. To use the new features, please refer to the documentation on InputSources and InputFormats.

Please see the following documentation for details: https://druid.apache.org/docs/0.17.0/ingestion/data-formats.html#input-format https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#input-sources https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html#partitionsspec

https://github.com/apache/druid/issues/8812

Single dimension range partitioning for parallel native batch ingestion

The parallel index task now supports the single_dim type partitions spec, which allows for range-based partitioning on a single dimension.

Please see https://druid.apache.org/docs/0.17.0/ingestion/native-batch.html for details.

Compaction changes

Parallel index task split hints

The parallel indexing task now has a new configuration, splitHintSpec, in the tuningConfig to allow for operators to provide hints to control the amount of data that each first phase subtask reads. There is currently one split hint spec type, SegmentsSplitHintSpec, used for re-ingesting Druid segments.

Parallel auto-compaction

Auto-compaction can now use the parallel indexing task, allowing for greater compaction throughput.

To control the level of parallelism, the auto-compactiontuningConfig has new parameters, maxNumConcurrentSubTasks and splitHintSpec.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration for details.

https://github.com/apache/incubator-druid/pull/8570

Stateful auto-compaction

Auto-compaction now uses the partitionSpec to track changes made by previous compaction tasks, allowing the coordinator to reduce redundant compaction operations.

Please see https://github.com/apache/druid/issues/8489 for details.

If you have auto-compaction enabled, please see the information under "Stateful auto-compaction changes" in the "Upgrading to Druid 0.17.0" section before upgrading.

Parallel query merging on brokers

The Druid broker can now opportunistically merge query results in parallel using multiple threads.

Please see druid.processing.merge.useParallelMergePool in the Broker section of the configuration reference for details on how to configure this new feature.

Parallel merging is enabled by default (controlled by the druid.processing.merge.useParallelMergePool property), and most users should not have to change any of the advanced configuration properties described in the configuration reference.

Additionally, merge parallelism can be controlled on a per-query basis using the query context. Information about the new query context parameters can be found at https://druid.apache.org/docs/0.17.0/querying/query-context.html.

https://github.com/apache/incubator-druid/pull/8578

SQL-compatible null handling

In 0.17.0, we have added official documentation for Druid's SQL-compatible null handling mode.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling and https://druid.apache.org/docs/0.17.0/design/segments.html#sql-compatible-null-handling for details.

Several bugs that existed in this previously undocumented mode have been fixed, particularly around null handling in numeric columns. We recommend that users begin to consider transitioning their clusters to this new mode after upgrading to 0.17.0.

The full list of null handling bugs fixed in 0.17.0 can be found at https://github.com/apache/druid/issues?utf8=%E2%9C%93&q=label%3A%22Area+-+Null+Handling%22+milestone%3A0.17.0+

LDAP extension

Druid now supports LDAP authentication. Authorization using LDAP groups is also supported by mapping LDAP groups to Druid roles.

  • LDAP authentication is handled by specifying an LDAP-type credentials validator.
  • Authorization using LDAP is handled by specifying an LDAP-type role provider, and defining LDAP group->Druid role mappings within Druid.

LDAP integration requires the druid-basic-security core extension. Please see https://druid.apache.org/docs/0.17.0/development/extensions-core/druid-basic-security.html for details.

As this is the first release with LDAP support, and there are a large variety of LDAP ecosystems, some LDAP use cases and features may not be supported yet. Please file an issue if you need enhancements to this new functionality.

https://github.com/apache/incubator-druid/pull/6972

Dropwizard emitter

A new Dropwizard metrics emitter has been added as a contrib extension.

The currently supported Dropwizard metrics types are counter, gauge, meter, timer and histogram. These metrics can be emitted using either a Console or JMX reporter.

Please see https://druid.apache.org/docs/0.17.0/design/extensions-contrib/dropwizard.html for details.

https://github.com/apache/incubator-druid/pull/7363

Self-discovery resource

A new pair of endpoints have been added to all Druid services that return information about whether the Druid service has received a confirmation that the service has been added to the cluster, from the central service discovery mechanism (currently ZooKeeper). These endpoints can be useful as health/ready checks.

The new endpoints are:

  • /status/selfDiscovered/status
  • /status/selfDiscovered

Please see the Druid API reference for details.

https://github.com/apache/incubator-druid/pull/6702 https://github.com/apache/incubator-druid/pull/9005

Supervisors system table

Task supervisors (e.g. Kafka or Kinesis supervisors) are now recorded in the system tables in a new sys.supervisors table.

Please see https://druid.apache.org/docs/0.17.0/querying/sql.html#supervisors-table for details.

https://github.com/apache/incubator-druid/pull/8547

Fast historical start with lazy loading

A new boolean configuration property for historicals, druid.segmentCache.lazyLoadOnStart, has been added.

This new property allows historicals to defer loading of a segment until the first time that segment is queried, which can significantly decrease historical startup times for clusters with a large number of segments.

Please see the configuration reference for details.

https://github.com/apache/incubator-druid/pull/6988

Historical segment cache distribution change

A new historical property, druid.segmentCache.locationSelectorStrategy, has been added.

If there are multiple segment storage locations specified in druid.segmentCache.locations, the new locationSelectorStrategy property allows the user to specify what strategy is used to fill the locations. Currently supported options are roundRobin and leastBytesUsed.

Please see the configuration reference for details.

https://github.com/apache/incubator-druid/pull/8038

New readiness endpoints

A new Broker endpoint has been added: /druid/broker/v1/readiness.

A new Historical endpoint has been added: /druid/historical/v1/readiness.

These endpoints are similar to the existing /druid/broker/v1/loadstatus and /druid/historical/v1/loadstatus endpoints.

They differ in that they do not require authentication/authorization checks, and instead of a JSON body they only return a 200 success or 503 HTTP response code.

https://github.com/apache/incubator-druid/pull/8841

Support task assignment based on MiddleManager categories

It is now possible to define a "category" name property for each MiddleManager. New worker select strategies that are category-aware have been added, allowing the user to control how tasks are assigned to MiddleManagers based on the configured categories.

Please see the documentation for druid.worker.category in the configuration reference, and the following links, for more details: https://druid.apache.org/docs/0.17.0/configuration/index.htmlEqual-Distribution-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#Fill-Capacity-With-Category-Spec https://druid.apache.org/docs/0.17.0/configuration/index.html#WorkerCategorySpec

https://github.com/apache/druid/pull/7066

Security vulnerability updates

A large number of dependencies have been updated to newer versions to address security vulnerabilities.

Please see the PRs below for details:

  • https://github.com/apache/incubator-druid/pull/8878
  • https://github.com/apache/incubator-druid/pull/8980

Upgrading to Druid 0.17.0

Select native query has been replaced

The deprecated Select native query type has been removed in 0.17.0.

If you have native queries that use Select, you need to modify them to use Scan instead. See the Scan query documentation (https://druid.apache.org/docs/0.17.0/querying/scan-query.html) for syntax and output format details.

For Druid SQL queries that use Select, no changes are needed; the SQL planner already uses the Scan query type under the covers for Select queries.

https://github.com/apache/incubator-druid/pull/8739

Old consoles have been removed

The legacy coordinator and overlord consoles have been removed, and they have been replaced with the new web console on the coordinator and overlord.

https://github.com/apache/incubator-druid/pull/8838

Calcite 1.21 upgrade, Druid SQL null handling

Druid 0.17.0 updates Calcite to version 1.21. This newer version of Calcite can make additional optimizations that assume SQL-compliant null handling behavior when planning queries.

If you use Druid SQL and rely on null handling behavior, please read the information at https://druid.apache.org/docs/0.17.0/configuration/index.html#sql-compatible-null-handling and ensure that your Druid cluster is running in the SQL-compliant null handling mode before upgrading.

https://github.com/apache/incubator-druid/pull/8566

Logging adjustments

Druid 0.17.0 has tidied up its lifecycle, querying, and ingestion logging.

Please see https://github.com/apache/incubator-druid/pull/8889 for a detailed list of changes. If you relied on specific log messages for external integrations, please review the new logging changes before upgrading.

The full set of log messages can still be seen when logging is set to DEBUG level. Template log4j2 configuration files that show how to enable per-package DEBUG logging are provided in the _common configuration folder in the example clusters under conf/druid.

Stateful auto-compaction changes

The auto-compaction scheduling logic in 0.17.0 tracks additional segment partitioning information in Druid's metadata store that is not present in older versions. This information is used to determine whether a set of segments has already been compacted under the cluster's current auto-compaction configurations.

When this new metadata is not present, a set of segments will always be scheduled for an initial compaction and this new metadata will be created after they are compacted, allowing the scheduler to skip them later if auto-compaction config is unchanged.

Since this additional segment partitioning metadata is not present before 0.17.0, the auto-compaction scheduling logic will re-compact all segments within a datasource once after the upgrade to 0.17.0.

This re-compaction on the entire set of segments for each datasource that has auto-compaction enabled means that:

  • There will be a transition period after the upgrade where more total compaction tasks will be queued than under normal conditions
  • The deep storage usage will increase as the entire segment set is re-compacted (the old set of segments is still kept in deep storage unless explicitly removed).

Users are advised to be aware of the temporary increase in scheduled compaction tasks and the impact on deep storage usage. Documentation on removing old segments is located at https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#deleting-data

targetCompactionSizeBytes property removed

The targetCompactionSizeBytes property has been removed from the compaction task and auto-compaction configuration. For auto-compaction, maxRowsPerSegment is now a mandatory configuration. For non-auto compaction tasks, any partitionsSpec can be used.

https://github.com/apache/incubator-druid/pull/8573

Compaction task tuningConfig

Due to the parallel auto-compaction changes introduced by #8570, any manually submitted compaction task specs need to be updated to use an index_parallel type for the tuningConfig section instead of index. These spec changes should be applied after the cluster is upgraded to 0.17.0.

Existing auto-compaction configs can remain unchanged after the update; the auto-compaction will create non-parallel compaction tasks until the auto-compaction configs are updated to use parallelism post-upgrade.

To control the level of parallelism, the auto-compactiontuningConfig has new parameters, maxNumConcurrentSubTasks and splitHintSpec.

Please see https://druid.apache.org/docs/0.17.0/configuration/index.html#compaction-dynamic-configuration for details.

Compaction task ioConfig

The compaction task now requires an ioConfig in the task spec.

Please see https://druid.apache.org/docs/0.17.0/ingestion/data-management.html#compaction-ioconfig for details.

ioConfig does not have to be added to existing auto-compaction configurations, the coordinator after the upgrade will automatically create task specs with ioConfig sections.

https://github.com/apache/incubator-druid/pull/8571

Renamed partition spec fields

The targetPartitionSize and maxSegmentSize fields in the partition specs have been deprecated. They have been renamed to targetNumRowsPerSegment and maxRowsPerSegment respectively.

https://github.com/apache/incubator-druid/pull/8507

Cache metrics are off by default

Cache metrics are now disabled by default. To enable cache metrics, add "org.apache.druid.client.cache.CacheMonitor" to the druid.monitoring.monitors property.

https://github.com/apache/incubator-druid/pull/8561

Supervisor API has changed to be consistent with task API

Supervisor task specs should now put the dataSchema, tuningConfig, and ioConfig sections as subfields of a spec field. Please see https://github.com/apache/incubator-druid/pull/8810 for examples.

The old format is still accepted in 0.17.0.

Segments API semantics change

The /datasources/{dataSourceName}/segments endpoint on the Coordinator now returns all used segments (including overshadowed) on the specified intervals, rather than only visible ones.

https://github.com/apache/incubator-druid/pull/8564

Password provider for basic authentication of HttpEmitterConfig

The druid.emitter.http.basicAuthentication property now accepts a password provider. We recommend updating your configurations to use a password provider if using the HTTP emitter.

https://github.com/apache/incubator-druid/pull/8618

Multivalue expression transformation change

Reusing multi-valued columns in expressions will no longer result in unnecessary cartesian explosions. Please see the following links for details.

https://github.com/apache/druid/issues/8947 https://github.com/apache/incubator-druid/pull/8957

Kafka/Kinesis ingestion during rolling upgrades

During a rolling upgrade, if there are tasks running 0.17.0 and overlords running older versions, and a task made progress reading data from its stream but rejected all the records it saw (e.g., all were unparseable), you will see NullPointerExceptions on overlords running older versions when the task updates the overlord with its current stream offsets.

Previously, there was a bug in this area (https://github.com/apache/incubator-druid/issues/8765) where such tasks would fail to communicate their current offsets to the overlord. The task/overlord publishing protocol has been updated to fix this, but older overlords do not recognize this protocol change.

This condition should be fairly rare.

Default Hadoop version change

Druid 0.17.0 now bundles Hadoop 2.8.5 libraries instead of 2.8.3.

If you were referencing the bundled 2.8.3 libraries in your configuration via the druid.indexer.task.defaultHadoopCoordinates property, or the hadoopDependencyCoordinates property in your Hadoop ingestion specs, you will need to update these references to point to the bundled 2.8.5 libraries instead.

ParseSpec.verify method removed

If you were maintaining a custom extension that provides an implementation for the ParseSpec interface, the verify method has been removed, and the @Override annotation on the method will need to be removed in any custom implementations.

https://github.com/apache/druid/pull/8744

Known issues

Filtering on long columns in SQL-compatible null handling mode

We are currently aware of a bug with applying certain filter types on null values from long columns when SQL-compatible null handling is enabled (https://github.com/apache/druid/issues/9255).

Please file an issue if you encounter any other null handling problems.

Ingestion spec preview in web console

The preview specs shown for native batch ingestion tasks created in the Data Loader of the web console are not correctly formatted and will fail if you copy them and submit them manually. Submitting these specs through the Data Loader submits a correctly formatted spec, however.

https://github.com/apache/druid/issues/9144

Other known issues

For a full list of open issues, please see https://github.com/apache/druid/labels/Bug
