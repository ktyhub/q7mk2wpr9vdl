Druide Druide-0.14.0-incubating

Apache Druid (in Inkubation) 0.14.0-incubating enthält über 200 neue Funktionen, Leistungs-/Stabilitäts-/Dokumentationsverbesserungen und Fehlerbehebungen von 54 Mitwirkenden. Zu den wichtigsten neuen Funktionen und Verbesserungen gehören:

  • Neue Webkonsole
  • Amazon Kinesis-Indexdienst
  • Stilllegungsmodus für historische Objekte – Veröffentlichter Segment-Cache im Broker
  • Bloom-Filter-Aggregator und -Ausdruck – Aktualisierte Apache Parquet-Erweiterung – Pushdown-Option für verschachtelte GroupBy-Abfragen erzwingen
  • Bessere Handhabung von Segmentübergaben und Drop-Regeln – MapReduce-Jobs automatisch beenden, wenn Apache Hadoop-Aufnahmeaufgaben beendet werden
  • DogStatsD-Tag-Unterstützung für statsd-Emitter
  • Neues API zum Abrufen aller Suchspezifikationen
  • Neue Verdichtungsoptionen
  • Effizienteres Caching, Kostensegmentausgleichsstrategie Die vollständige Liste der Änderungen finden Sie hier: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0 Die Dokumentation für diese Version finden Sie unter: http://druid.io/docs/0.14.0-incubating/

Highlights

Neue Webkonsole

Druid verfügt über eine neue Webkonsole, die Funktionen bietet, die zuvor zwischen der Koordinator- und der Overlord-Konsole aufgeteilt waren. Mit der neuen Konsole kann der Benutzer Datenquellen, Segmente, Aufgaben, Datenprozesse (Historische Daten und MiddleManager) sowie die dynamische Konfiguration des Koordinators verwalten. Der Benutzer kann in der Konsole auch SQL- und native Druid-Abfragen ausführen. Weitere Einzelheiten finden Sie unter http://druid.io/docs/0.14.0-incubating/operations/management-uis.html Hinzugefügt von @vogievetsky in #6923.

Kinesis-Indexierungsdienst

Druid unterstützt jetzt die Aufnahme von Kinesis-Streams, bereitgestellt durch die neue druid-kinesis-indexing-service-Kernerweiterung. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html. Hinzugefügt von @jsun98 in #6431.

Stilllegungsmodus für historische Daten

Historische Prozesse können jetzt in einen „Stilllegungsmodus“ versetzt werden, in dem der Koordinator den historischen Prozess nicht mehr als Ziel für die Segmentreplikation betrachtet. Der Koordinator wird auch Segmente aus der Stilllegungshistorie verschieben. Dies wird über die dynamische Konfiguration des Koordinators gesteuert. Weitere Einzelheiten finden Sie unter http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration. Hinzugefügt von @egor-ryashin in #6349.

Veröffentlichter Segment-Cache auf Broker

Der Druid Broker verfügt nun über die Möglichkeit, durch Abfragen des Koordinators einen Cache veröffentlichter Segmente zu verwalten, was die Antwortzeit für Metadatenabfragen in der sys.segments-Systemtabelle erheblich verbessern kann. Einzelheiten finden Sie unter http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata. Hinzugefügt von @surekhasaharan in #6901

Bloom-Filter-Aggregator und Ausdruck

Der druid-bloom-filter-Erweiterung wurde ein neuer Aggregator zum Erstellen von Bloom-Filtern zur Abfragezeit und Unterstützung für die Durchführung von Bloom-Filterprüfungen innerhalb von Druid-Ausdrücken hinzugefügt. Bitte sehen Sie sich http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html an Hinzugefügt von @clintropolis in #6904 und #6397

Aktualisierte Parquet-Erweiterung

druid-extensions-parquet wurde aus den Contrib-Erweiterungen in den Kernerweiterungssatz verschoben und unterstützt jetzt Flattening- und Int96-Werte. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html. Hinzugefügt von @clintropolis in #6360

Pushdown-Option für verschachtelte GroupBy-Abfragen erzwingen

Die äußere Abfrageausführung für verschachtelte GroupBy-Abfragen kann jetzt auf historische Prozesse verschoben werden. Bisher wurden die äußeren Abfragen immer auf dem Broker ausgeführt. Weitere Informationen finden Sie unter https://github.com/apache/incubator-druid/pull/5471. Hinzugefügt von @samarthjain in #5471.

Bessere Segmentübergabe und Handhabung von Aufbewahrungsregeln

Bei der Segmentübergabe werden nun Segmente ignoriert, die durch die Aufbewahrungsregeln einer Datenquelle verworfen würden, wodurch Aufnahmefehler aufgrund von Problem Nr. 5868 vermieden werden. Periodenladeregeln umfassen jetzt standardmäßig die Zukunft. Eine neue Regel „Periodenabfall vor“ wurde hinzugefügt. Einzelheiten finden Sie unter http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule. Hinzugefügt von @QiuMM in #6676, #6414 und #6415.

MapReduce-Jobs automatisch beenden, wenn Hadoop-Aufnahmeaufgaben beendet werden

Druid beendet nun automatisch MapReduce-Jobs, die von Hadoop-Batch-Aufnahmeaufgaben erstellt wurden, wenn die Aufnahmeaufgabe beendet wird. Hinzugefügt von @ankit0811 in #6828.

DogStatsD-Tag-Unterstützung für statsd-emitter

Die statsd-emitter-Erweiterung unterstützt jetzt Tags im DogStatsD-Stil. Bitte sehen Sie sich http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html an Hinzugefügt von @deiwin in #6605, mit Unterstützung für konstante Tags, hinzugefügt von @glasser in #6791.

Neues API zum Abrufen aller Suchspezifikationen

Ein neuer API zum Abrufen aller Suchspezifikationen für alle Ebenen wurde hinzugefügt. Einzelheiten finden Sie unter http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups. Hinzugefügt von @jihoonson in #7025.

Neue Komprimierungsoptionen

Die automatische Komprimierung unterstützt jetzt die Option maxRowsPerSegment. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments. Die Komprimierungsaufgabe unterstützt jetzt eine neue Option segmentGranularity, wodurch die ältere Option keepSegmentGranularity zur Steuerung der Segmentgranularität komprimierter Segmente veraltet ist. Weitere Informationen zu diesen Eigenschaften finden Sie in der Tabelle segmentGranularity in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html. Hinzugefügt von @jihoonson in #6758 und #6780.

Effizienteres CachingKostensegmentausgleichsstrategie

Die Segmentausgleichsstrategie des cachingCost-Koordinators berücksichtigt jetzt nur historische Prozesse für Ausgleichsentscheidungen. Bisher berücksichtigte die Strategie unnötigerweise auch aktive Worker-Aufgaben, die keine Ziele für die Segmentreplikation waren. Hinzugefügt von @QiuMM in #6879.

Neue Metriken:

– Neue Zuteilungsratenmetrik jvm/heapAlloc/bytes, hinzugefügt von @egor-ryashin in #6710.
– Neue Abfrageanzahl-Metrik query/count, hinzugefügt von @QiuMM in #6473. – SQL-Abfragemetriken sqlQuery/bytes und sqlQuery/time, hinzugefügt von @gaodayue in #6302. – Apache Kafka-Metriken zur Aufnahmeverzögerung ingest/kafka/maxLag und ingest/kafka/avgLag, hinzugefügt von @QiuMM in #6587 – Aufgabenanzahlmetriken task/success/count, task/failed/count, task/running/count, task/pending/count, task/waiting/count, hinzugefügt von @QiuMM in #6657

Neue Schnittstellen für Erweiterungsentwickler

RequestLogEvent

Es ist nun möglich, die von EmittingRequestLogger ausgegebenen Felder in RequestLogEvent zu steuern. Weitere Informationen finden Sie unter #6477. Hinzugefügt von @leventov.

Benutzerdefinierte TLS-Zertifikatprüfungen

Ein Erweiterungspunkt für benutzerdefinierte TLS-Zertifikatprüfungen wurde hinzugefügt. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checks. Hinzugefügt von @jon-wei in #6432.

Kafka Indexing Service nicht mehr experimentell

Die Erweiterung „Kafka Indexing Service“ wurde aus dem experimentellen Status entfernt.

SQL-Verbesserungen

Verbesserungen an dsql

Die dsql-Befehlszeile client unterstützt jetzt den CLI-Verlauf, grundlegende automatische Vervollständigung und die Angabe von Abfrage-Timeouts im Abfragekontext. Hinzugefügt in #6929 von @gianm.

SQL-ID, Anforderungsprotokolle und Metriken hinzufügen

SQL-Abfragen haben jetzt eine ID und native Abfragen, die als Teil einer SQL-Abfrage ausgeführt werden, verfügen über die zugehörige SQL-Abfrage-ID in den Anforderungsprotokollen der nativen Abfrage. SQL-Abfragen werden nun in den Anforderungsprotokollen protokolliert. Zwei neue Metriken, sqlQuery/time und sqlQuery/bytes, werden jetzt für SQL-Abfragen ausgegeben. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging und http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics. Hinzugefügt von @gaodayue in #6302

Mehr SQL-Aggregator-Unterstützung

Die folgenden Aggregatoren werden jetzt in SQL unterstützt:

  • DataSketches HLL-Skizze
  • DataSketches Theta-Skizze
  • DataSketches-Quantilskizze
  • Bin-Histogramm korrigiert
  • Bloom-Filter-Aggregator Hinzugefügt von @jon-wei in #6951 und @clintropolis in #6502

Weitere SQL-Erweiterungen

  • SQL: Unterstützung für Abfragen mit Project-After-Semijoin hinzugefügt. #6756
  • SQL: Unterstützung für die Auswahl mehrwertiger Dimensionen. #6462
  • SQL: Unterstützt AVG auf Systemtabellen. #601
  • SQL: Funktion „POSITION“ hinzufügen. #6596
  • SQL: Legen Sie den INFORMATION_SCHEMA-Katalognamen auf „Druid“ fest. #6595
  • SQL: Reihenfolge von sort, sortProject in DruidSemiJoin korrigiert. #6769 Hinzugefügt von @gianm.

Aktualisierung von 0.13.0-incubating und früher

Ausfallzeit der Kafka-Aufnahme beim Upgrade

Aufgrund des in #6958 beschriebenen Problems können bestehende Kafka-Indizierungsaufgaben während eines fortlaufenden Upgrades des Overlords unnötigerweise beendet werden. Die beendeten Aufgaben werden vom Overlord neu gestartet und funktionieren nach dem ersten Neustart ordnungsgemäß.

Änderungen an der Parquet-Erweiterung

Die Erweiterung druid-parquet-extensions wurde von contrib auf core verschoben. Stellen Sie bei der Bereitstellung von 0.14.0-incubating sicher, dass Ihr extensions-contrib-Verzeichnis keine älteren Versionen der Parquet-Erweiterung enthält. Darüber hinaus gibt es in der Erweiterung jetzt zwei Arten von Parquet-Parsern:

  • parquet-avro: Konvertiert Parquet in Avro und analysiert dann die Avro-Darstellung. Dies war der vorhandene Parser vor 0.14.0-incubating.
  • parquet: Ein neuer Parser, der das Parquet-Format direkt analysiert. Nur dieser neue Parser unterstützt int96-Werte. Vor 0.14.0-incubating musste eine Aufgabe, die einen Parser vom Typ parquet angab, den Avro-konvertierenden Parser verwenden. Um in 0.14.0-incubating weiterhin den Avro-konvertierenden Parser verwenden zu können, müssen Sie Ihre Aufnahmespezifikationen aktualisieren, um stattdessen parquet-avro zu verwenden. Das Feld inputFormat im inputSpec für Aufgaben, die die Parquet-Eingabe verwenden, muss auch mit der Wahl des Parsers übereinstimmen:
  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html.

Druid mit Nicht-2.8.3-Hadoop ausführen

Wenn Sie Druid 0.14.0-incubating mit anderen Hadoop-Versionen als 2.8.3 verwenden möchten, müssen Sie möglicherweise Folgendes tun: – Legen Sie die Hadoop-Abhängigkeitskoordinaten auf Ihre Zielversion fest, wie in http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html unter Tip #3: Use specific versions of Hadoop libraries beschrieben.

  • Erstellen Sie Druid mit Ihrer Zielversion von Hadoop neu, indem Sie hadoop.compile.version im Haupt-Druid pom.xml ändern und dann den Standard-Build-Anweisungen folgen.

Andere Verhaltensänderungen

Bereinigung alter Aufgaben

Alte Aufgabeneinträge im Metadatenspeicher werden nun automatisch zusammen mit ihren Aufgabenprotokollen bereinigt. Weitere Informationen finden Sie unter http://druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging und #6592.

Automatische Größe des Verarbeitungspuffers

Die Eigenschaft druid.processing.buffer.sizeBytes verfügt über ein neues Standardverhalten, wenn sie nicht festgelegt ist. Druid wählt nun automatisch einen Wert für die Verarbeitungspuffergröße anhand der folgenden Formel:

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

Wo:

  • totalDirectMemory: Das durch -XX:MaxDirectMemorySize angegebene direkte Speicherlimit für den JVM
  • numMergeBuffers: Der Wert von druid.processing.numMergeBuffers.
  • numProcessingThreads: Der Wert von druid.processing.numThreads. Druid verwendet höchstens 1 GB für die automatisch ausgewählte Verarbeitungspuffergröße. Die Größe des Verarbeitungspuffers kann weiterhin manuell angegeben werden. Weitere Informationen finden Sie unter #6588.

Aufbewahrungsregeln umfassen jetzt standardmäßig die Zukunft

Bitte beachten Sie, dass neue Aufbewahrungsregeln nun standardmäßig die Zukunft einschließen. Weitere Informationen finden Sie unter #6414.

Eigentumsänderungen

Segmentankündigung

Die Eigenschaft druid.announcer.type, die zur Auswahl zwischen Zookeeper oder HTTP-basierter Segmentverwaltung/-erkennung verwendet wird, wurde nach druid.serverview.type verschoben. Wenn Sie http vor 0.14.0-incubating verwendet haben, müssen Sie Ihre Konfigurationen aktualisieren, um das neue druid.serverview.type zu verwenden. Weitere Informationen finden Sie im Folgenden:

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

Fehlende Eigenschaft in JsonTypeInfo von SegmentWriteOutMediumFactory beheben

Die Eigenschaft druid.peon.defaultSegmentWriteOutMediumFactory.@type wurde behoben. Die Eigenschaft lautet jetzt druid.peon.defaultSegmentWriteOutMediumFactory.type ohne das „@“. Weitere Informationen finden Sie unter #6656.

Abwertungen

Ungefährer Histogramm-Aggregator

Der Aggregator [ApproximateHistogram](http://druid.io/docs/0.14.0-incubating/development/extensions-core/ approximate-histograms.html) ist veraltet. Es handelt sich um einen verteilungsabhängigen Algorithmus ohne formale Fehlergrenzen, der erhebliche Genauigkeitsprobleme aufweist. Für Quantil- und Histogramm-Anwendungsfälle sollte stattdessen der Aggregator DataSketches-Quantile verwendet werden. Weitere Informationen finden Sie unter Histogramm- und Quantilaggregatoren

Kardinalität/HyperUnique-Aggregator

Die Aggregatoren Cardinality und HyperUnique wurden zugunsten des Aggregators DataSketches HLL und des Aggregators Theta Sketch veraltet. Diese Aggregatoren weisen eine bessere Genauigkeit und Leistungsmerkmale auf. Weitere Informationen finden Sie unter [Count Distinct Aggregators] (http://druid.io/docs/0.14.0-incubating/querying/aggregations.html#count-distinct).

Abfrage-Chunk-Zeitraum

Die chunkPeriod-Abfragekontextkonfiguration ist jetzt veraltet, zusammen mit der zugehörigen query/intervalChunk/time-Metrik. Weitere Informationen finden Sie unter #6591.

keepSegmentGranularity für Verdichtung

Die Option keepSegmentGranularity für Komprimierungsaufgaben ist veraltet. Weitere Informationen zu diesen Eigenschaften finden Sie in #6758 und in der Tabelle segmentGranularity in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html.

Schnittstellenänderungen für Erweiterungsentwickler

SegmentId-Klasse

Druid verwendet jetzt eine SegmentId-Klasse anstelle von einfachen Strings, um Segment-IDs darzustellen. Weitere Informationen finden Sie unter #6370. Hinzugefügt von @leventov.

druid-api, druid-common, java-util wurden nach druid-core verschoben

Die Module druid-api, druid-common, java-util wurden in druid-core verschoben. Bitte aktualisieren Sie Ihre Abhängigkeiten entsprechend, wenn Ihr Projekt von diesen Bibliotheken abhängt. Weitere Informationen finden Sie unter #6443.

druid druid-0.14.0-incubating

Apache Druid (incubating) 0.14.0-incubating contains over 200 new features, performance/stability/documentation improvements, and bug fixes from 54 contributors. Major new features and improvements include:

  • New web console
  • Amazon Kinesis indexing service
  • Decommissioning mode for Historicals
  • Published segment cache in Broker
  • Bloom filter aggregator and expression
  • Updated Apache Parquet extension
  • Force push down option for nested GroupBy queries
  • Better segment handoff and drop rule handling
  • Automatically kill MapReduce jobs when Apache Hadoop ingestion tasks are killed
  • DogStatsD tag support for statsd emitter
  • New API for retrieving all lookup specs
  • New compaction options
  • More efficient cachingCost segment balancing strategy

The full list of changes is here: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Amerged+milestone%3A0.14.0

Documentation for this release is at: http://druid.io/docs/0.14.0-incubating/

Highlights

New web console

Druid has a new web console that provides functionality that was previously split between the coordinator and overlord consoles.

The new console allows the user to manage datasources, segments, tasks, data processes (Historicals and MiddleManagers), and coordinator dynamic configuration. The user can also run SQL and native Druid queries within the console.

For more details, please see http://druid.io/docs/0.14.0-incubating/operations/management-uis.html

Added by @vogievetsky in #6923.

Kinesis indexing service

Druid now supports ingestion from Kinesis streams, provided by the new druid-kinesis-indexing-service core extension.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/kinesis-ingestion.html for details.

Added by @jsun98 in #6431.

Decommissioning mode for Historicals

Historical processes can now be put into a "decommissioning" mode, where the coordinator will no longer consider the Historical process as a target for segment replication. The coordinator will also move segments off the decommissioning Historical.

This is controlled via Coordinator dynamic configuration. For more details, please see http://druid.io/docs/0.14.0-incubating/configuration/index.html#dynamic-configuration.

Added by @egor-ryashin in #6349.

Published segment cache on Broker

The Druid Broker now has the ability to maintain a cache of published segments via polling the Coordinator, which can significantly improve response time for metadata queries on the sys.segments system table.

Please see http://druid.io/docs/0.14.0-incubating/querying/sql.html#retrieving-metadata for details.

Added by @surekhasaharan in #6901

Bloom filter aggregator and expression

A new aggregator for constructing Bloom filters at query time and support for performing Bloom filter checks within Druid expressions have been added to the druid-bloom-filter extension.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/bloom-filter.html

Added by @clintropolis in #6904 and #6397

Updated Parquet extension

druid-extensions-parquet has been moved into the core extension set from the contrib extensions and now supports flattening and int96 values.

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html for details.

Added by @clintropolis in #6360

Force push down option for nested GroupBy queries

Outer query execution for nested GroupBy queries can now be pushed down to Historical processes; previously, the outer queries would always be executed on the Broker.

Please see https://github.com/apache/incubator-druid/pull/5471 for details.

Added by @samarthjain in #5471.

Better segment handoff and retention rule handling

Segment handoff will now ignore segments that would be dropped by a datasource's retention rules, avoiding ingestion failures caused by issue #5868.

Period load rules will now include the future by default.

A new "Period Drop Before" rule has been added. Please see http://druid.io/docs/0.14.0-incubating/operations/rule-configuration.html#period-drop-before-rule for details.

Added by @QiuMM in #6676, #6414, and #6415.

Automatically kill MapReduce jobs when Hadoop ingestion tasks are killed

Druid will now automatically terminate MapReduce jobs created by Hadoop batch ingestion tasks when the ingestion task is killed.

Added by @ankit0811 in #6828.

DogStatsD tag support for statsd-emitter

The statsd-emitter extension now supports DogStatsD-style tags. Please see http://druid.io/docs/0.14.0-incubating/development/extensions-contrib/statsd.html

Added by @deiwin in #6605, with support for constant tags added by @glasser in #6791.

New API for retrieving all lookup specs

A new API for retrieving all lookup specs for all tiers has been added. Please see http://druid.io/docs/0.14.0-incubating/querying/lookups.html#get-all-lookups for details.

Added by @jihoonson in #7025.

New compaction options

Auto-compaction now supports the maxRowsPerSegment option. Please see http://druid.io/docs/0.14.0-incubating/design/coordinator.html#compacting-segments for details.

The compaction task now supports a new segmentGranularity option, deprecating the older keepSegmentGranularity option for controlling the segment granularity of compacted segments. Please see the segmentGranularity table in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html for more information on these properties.

Added by @jihoonson in #6758 and #6780.

More efficient cachingCost segment balancing strategy

The cachingCost Coordinator segment balancing strategy will now only consider Historical processes for balancing decisions. Previously the strategy would unnecessarily consider active worker tasks as well, which are not targets for segment replication.

Added by @QiuMM in #6879.

New metrics:

  • New allocation rate metric jvm/heapAlloc/bytes, added by @egor-ryashin in #6710.
  • New query count metric query/count, added by @QiuMM in #6473.
  • SQL query metrics sqlQuery/bytes and sqlQuery/time, added by @gaodayue in #6302.
  • Apache Kafka ingestion lag metrics ingest/kafka/maxLag and ingest/kafka/avgLag, added by @QiuMM in #6587
  • Task count metrics task/success/count, task/failed/count, task/running/count, task/pending/count, task/waiting/count, added by @QiuMM in #6657

New interfaces for extension developers

RequestLogEvent

It is now possible to control the fields in RequestLogEvent, emitted by EmittingRequestLogger. Please see #6477 for details. Added by @leventov.

Custom TLS certificate checks

An extension point for custom TLS certificate checks has been added. Please see http://druid.io/docs/0.14.0-incubating/operations/tls-support.html#custom-tls-certificate-checks for details. Added by @jon-wei in #6432.

Kafka Indexing Service no longer experimental

The Kafka Indexing Service extension has been moved out of experimental status.

SQL Enhancements

Enhancements to dsql

The dsql command line client now supports CLI history, basic autocomplete, and specifying query timeouts in the query context.

Added in #6929 by @gianm.

Add SQL id, request logs, and metrics

SQL queries now have an ID, and native queries executed as part of a SQL query will have the associated SQL query ID in the native query's request logs. SQL queries will now be logged in the request logs.

Two new metrics, sqlQuery/time and sqlQuery/bytes, are now emitted for SQL queries.

Please see http://druid.io/docs/0.14.0-incubating/configuration/index.html#request-logging and http://druid.io/docs/0.14.0-incubating/querying/sql.html#sql-metrics for details.

Added by @gaodayue in #6302

Updating from 0.13.0-incubating and earlier

Kafka ingestion downtime when upgrading

Due to the issue described in #6958, existing Kafka indexing tasks can be terminated unnecessarily during a rolling upgrade of the Overlord. The terminated tasks will be restarted by the Overlord and will function correctly after the initial restart.

Parquet extension changes

The druid-parquet-extensions extension has been moved from contrib to core. When deploying 0.14.0-incubating, please ensure that your extensions-contrib directory does not have any older versions of the Parquet extension.

Additionally, there are now two styles of Parquet parsers in the extension:

  • parquet-avro: Converts Parquet to Avro, and then parses the Avro representation. This was the existing parser prior to 0.14.0-incubating.
  • parquet: A new parser that parses the Parquet format directly. Only this new parser supports int96 values.

Prior to 0.14.0-incubating, a specifying a parquet type parser would have a task use the Avro-converting parser. In 0.14.0-incubating, to continue using the Avro-converting parser, you will need to update your ingestion specs to use parquet-avro instead.

The inputFormat field in the inputSpec for tasks using Parquet input must also match the choice of parser:

  • parquet: org.apache.druid.data.input.parquet.DruidParquetInputFormat
  • parquet-avro: org.apache.druid.data.input.parquet.DruidParquetInputFormat

Please see http://druid.io/docs/0.14.0-incubating/development/extensions-core/parquet.html for details.

Running Druid with non-2.8.3 Hadoop

If you plan to use Druid 0.14.0-incubating with Hadoop versions other than 2.8.3, you may need to do the following:

  • Set the Hadoop dependency coordinates to your target version as described in http://druid.io/docs/0.14.0-incubating/operations/other-hadoop.html under Tip #3: Use specific versions of Hadoop libraries.
  • Rebuild Druid with your target version of Hadoop by changing hadoop.compile.version in the main Druid pom.xml and then following the standard build instructions.

Other Behavior changes

Old task cleanup

Old task entries in the metadata storage will now be cleaned up automatically together with their task logs. Please see http:/druid.io/docs/0.14.0-incubating/development/extensions-core/configuration/index.html#task-logging and #6592 for details.

Automatic processing buffer sizing

The druid.processing.buffer.sizeBytes property has new default behavior if it is not set. Druid will now automatically choose a value for the processing buffer size using the following formula:

processingBufferSize = totalDirectMemory / (numMergeBuffers + numProcessingThreads + 1)
processingBufferSize = min(processingBufferSize, 1GB)

Where:

  • totalDirectMemory: The direct memory limit for the JVM specified by -XX:MaxDirectMemorySize
  • numMergeBuffers: The value of druid.processing.numMergeBuffers.
  • numProcessingThreads: The value of druid.processing.numThreads.

At most, Druid will use 1GB for the automatically chosen processing buffer size. The processing buffer size can still be specified manually.

Please see #6588 for details.

Retention rules now include the future by default

Please be aware that new retention rules will now include the future by default. Please see #6414 for details.

Property changes

Segment announcing

The druid.announcer.type property used for choosing between Zookeeper or HTTP-based segment management/discovery has been moved to druid.serverview.type. If you were using http prior to 0.14.0-incubating, you will need to update your configs to use the new druid.serverview.type.

Please see the following for details:

  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-management
  • http://druid.io/docs/0.14.0-incubating/configuration/index.html#segment-discovery

fix missing property in JsonTypeInfo of SegmentWriteOutMediumFactory

The druid.peon.defaultSegmentWriteOutMediumFactory.@type property has been fixed. The property is now druid.peon.defaultSegmentWriteOutMediumFactory.type without the "@".

Please see #6656 for details.

Deprecations

Approximate Histogram aggregator

The ApproximateHistogram aggregator has been deprecated; it is a distribution-dependent algorithm without formal error bounds and has significant accuracy issues.

The DataSketches quantiles aggregator should be used instead for quantile and histogram use cases.

Please see Histogram and Quantiles Aggregators

Cardinality/HyperUnique aggregator

The Cardinality and HyperUnique aggregators have been deprecated in favor of the DataSketches HLL aggregator and Theta Sketch aggregator. These aggregators have better accuracy and performance characteristics.

Please see Count Distinct Aggregators for details.

Query Chunk Period

The chunkPeriod query context configuration is now deprecated, along with the associated query/intervalChunk/time metric. Please see #6591 for details.

keepSegmentGranularity for Compaction

The keepSegmentGranularity option for compaction tasks has been deprecated. Please see #6758 and the segmentGranularity table in http://druid.io/docs/0.14.0-incubating/ingestion/compaction.html for more information on these properties.

Interface changes for extension developers

SegmentId class

Druid now uses a SegmentId class instead of plain Strings to represent segment IDs. Please see #6370 for details.

Added by @leventov.

druid-api, druid-common, java-util moved to druid-core

The druid-api, druid-common, java-util modules have been moved into druid-core. Please update your dependencies accordingly if your project depended on these libraries.

Please see #6443 for details.
