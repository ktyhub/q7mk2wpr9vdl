DeepSpeed v0.20.0

Highlights

  • HybridEngine graph rollouts broaden, with a backend opt-in — Non-greedy temperature/top-k/top-p sampling now reaches graph decode and continuous batching (#8939), while Transformers 5.20 query offsets and a prebuilt 4-D SDPA mask remove capture blockers (#8852, #9004). Capture is capability-gated rather than CUDA-name-gated (#8933, #8980): CUDA/NPU opt in automatically, while custom accelerators must implement is_graph_capture_supported() and stream-capture detection or fall back to eager execution. Use hybrid_engine.enable_graph_capture; enable_cuda_graph remains a deprecated alias.

  • ZeRO-1/2 fixes multi-request gradient accumulation — An accumulation boundary is no longer treated as an optimizer step: gradients survive across request boundaries until step(), without carrying stale gradients into the next update (#8949, #9018). ZeRO-2 CPU offload now accumulates in compact partition storage (#9044), and stale offload scratch is cleared before low-precision gradients are restored (#8728). This matters for delayed updates, conditional parameter use, and CPU-offloaded training.

  • ZeRO-3 strengthens precision preservation and offload efficiency — Parameters explicitly kept in FP32 by the model remain FP32 under ZeRO-3 (#8843), FP32 masters are restored for ZeRO-3 and ZeRO-1 BF16 optimizers (#8892), and CPU optimizer states loaded from state_dict retain FP32 (#8974). Pinned master-weight copy-back avoids slow pageable CPU casts (#8840), partition reuse avoids duplicate master storage when dtypes already match (#8842), and NVMe prefetch no longer conflicts with existing swap-buffer assignments (#9014).

  • AutoEP/AutoTP and VocabTP support more composed workloads — ZeRO-3 can now combine AutoEP + AutoTP folding with CPU optimizer offload (#8829), with routed-expert gradient clipping corrected for that configuration (#8823). VocabTP adds a fused Hugging Face forward path for vocabulary-parallel LM-head projection plus loss (#8945) and Triton generalized-JSD kernels (#8958), giving large-vocabulary training and distillation workloads more efficient execution options.

  • Deterministic execution becomes an explicit policy — Enable deterministic_mode: true for strict PyTorch deterministic algorithms, disabled TF32/cuDNN autotuning, deterministic FPDT FlashAttention backward, and fixed Triton grouped-GEMM configurations (#8917). The mode rejects ROCm, CUDA-compatible non-NVIDIA accelerators, and legacy stochastic_mode: true; validate the cuBLAS workspace environment before CUDA initialization. Treat it as a reproducibility/debugging mode and benchmark before production use.

  • Breaking changes — None listed.
