daily_stock_analysis v3.12.0

Release-Highlights

  • 📊 Der Backtest-Seite wurde eine neue Ansicht „Verifizierung am nächsten Tag“ hinzugefügt – Sie können KI-Vorhersagen im Vergleich zum tatsächlichen Anstieg und Rückgang des nächsten Tages nach Aktie und Datumsbereich anzeigen, historische Analysen und 1-Tages-Backtest-Ergebnisse wiederverwenden und die Genauigkeit der Analyse schnell überprüfen.
  • 🔧 Vereinfachtes LLM-Zugriffserlebnis – Das benutzerseitige Copywriting wird als „Hauptmodell/Alternativmodell/Modellkanal“ vereinheitlicht, LiteLLM gilt nicht mehr als ein Muss-Lernkonzept für normale Benutzer und bestehende Konfigurationsschlüssel bleiben kompatibel.
  • 🐳 Docker / Steady-State-Verbesserung der WebUI-Laufzeit – Es wurden Probleme behoben, wie z. B. dass die Konfiguration nach dem Speichern der Systemeinstellungen nicht wirksam wurde, fehlende frühe Startprotokolle, Wiederverwendung vorgefertigter statischer Ressourcen usw., um die Betriebs- und Wartungsprobleme bei der Bereitstellung in Containern zu reduzieren.
  • 🔒 Sicherheit und Parallelitätsstabilität werden gleichzeitig verbessert – Der eingehende Discord-Webhook vervollständigt die Ed25519-Signaturüberprüfung und behebt Probleme wie z. B. dass der gemeinsame Status während der gleichzeitigen Ausführung nicht gesperrt wird, Benachrichtigung im Single-Share-Push-Modus bei gleichzeitiger Wiederverwendung usw.
  • 🖥️ Details zu Desktop und geplanten Aufgaben verbessert – Windows Installer unterstützt benutzerdefinierte Installationsverzeichnisse, der integrierte geplante Planer erkennt SCHEDULE_TIME-Änderungen während des Betriebs und setzt Downloads basierend auf der Marktzeitzone fort.

Neue Funktionen

  • 📊 Die neue Ansicht „Überprüfung am nächsten Tag / 1-Tages-Fenster“ wurde zur Backtest-Seite hinzugefügt – Sie können KI-Vorhersagen, den tatsächlichen Anstieg und Rückgang des nächsten Tages sowie die Genauigkeit des Screening-Bereichs nach Aktiencode und Analysedatumsbereich anzeigen und historische Analysen und 1-Tages-Backtest-Ergebnisse wiederverwenden.
  • 🏷️ Neue Versionsinformationskarte zur Web-Einstellungsseite hinzugefügt – apps/dsa-web fügt jetzt beim Erstellen die Front-End-Paketversion und die Build-Zeit ein, und ein neuer schreibgeschützter „Versionsinformations“-Block wird zur Systemeinstellungsseite hinzugefügt, um WebUI 版本 / 构建标识 / 构建时间 anzuzeigen; Wenn package.json noch eine Platzhalterversion 0.0.0 ist, wird automatisch auf die Build-Identifikation zurückgegriffen, wodurch Docker schnell bestätigen kann, ob die aktuellen statischen Ressourcen nach der Rekonstruktion wirksam geworden sind.
  • 🪟 Windows-Desktop-Installationsprogramm unterstützt selbstgewähltes Installationsverzeichnis – Das Installationsprogramm unterstützt jetzt das Anpassen des Installationsverzeichnisses im Installationsassistenten. Nach der Installation auf einem nicht standardmäßigen Laufwerksbuchstaben wird weiterhin die vorhandene Verpackungsverzeichnislogik zum Lesen und Schreiben von .env, data/stock_analysis.db und logs/desktop.log neben dem Installationsverzeichnis verwendet, während die installationsfreie Verteilungsmethode von win-unpacked beibehalten wird. Das Installationsprogramm unterstützt nur die Installation durch den aktuellen Benutzer, hat die Eskalation von Administratorrechten deaktiviert (allowElevation: false) und blockiert die Auswahl von Systemschutzverzeichnissen über NSIS .onVerifyInstDir.

Verbesserungen

  • 🔎 SerpAPI Konvergenz des Textabrufbereichs – Natürliche Suchergebnisse crawlen den Webseitentext nicht mehr synchron nacheinander; Jetzt werden nur noch eine sehr kleine Anzahl hochrangiger Ergebnisse mit offensichtlich unzureichenden Zusammenfassungen innerhalb eines kürzeren Timeout-Budgets verzögert, und die von SerpAPI zurückgegebenen strukturierten Zusammenfassungen werden priorisiert, um die Verzögerung am Ende des Suchlinks und das Risiko einer langsamen Site-Verstärkung zu reduzieren.
  • 🤖 Vereinfachtes LLM-Zugriffserlebnis – Die benutzerorientierte Zugriffskopie des KI-Modells wurde in „Hauptmodell / Agent-Hauptmodell / Alternativmodell / Modellkanal / Erweiterte Modellrouting-Konfiguration“ vereinheitlicht; Die Web-Einstellungsseite, Konfigurationsmetadaten, Überprüfungsaufforderungen sowie chinesische und englische Dokumente betrachten LiteLLM nicht mehr als Standardkonzept, das normale Benutzer erlernen müssen, und die vorhandenen Konfigurationsschlüssel LITELLM_* / LLM_CHANNELS bleiben kompatibel.

Beheben

  • 🚀 Entdecken Sie die tatsächliche Ursache, wenn der frühe Start fehlschlägt – python main.py legt jetzt die tatsächliche Ursache über stderr offen, die Bootstrap-Phase schreibt keine Dateiprotokolle mehr in das fest codierte logs/-Verzeichnis und das Dateiprotokoll wird verschoben, bis config.log_dir verfügbar ist, um verbleibende Protokolldateien in unerwarteten Pfaden während eines ordnungsgemäßen Starts zu vermeiden.
  • 🐳 Docker WebUI-Laufzeit verwendet vorzugsweise vorgefertigte statische Ressourcen wieder – prepare_webui_frontend_assets() prüft jetzt, ob das vorhandene static/index.html im Bild direkt wiederverwendet werden kann; Wenn der Container das Quellcodeverzeichnis apps/dsa-web nicht enthält und npm nicht installiert ist, wird nicht fälschlicherweise gemeldet: „Front-End-Projekt nicht gefunden, kann nicht automatisch erstellt werden“, wodurch Docker wiederhergestellt wird. Möglichkeit zum Öffnen der WebUI nach der Bereitstellung.
  • 🐳 Die Konfiguration wird wirksam, nachdem die Docker-WebUI-Systemeinstellungen gespeichert wurden – Nachdem die WebUI STOCK_LIST, SCHEDULE_ENABLED, SCHEDULE_TIME, SCHEDULE_RUN_IMMEDIATELY und RUN_IMMEDIATELY im Docker-Szenario speichert, gibt Config dem Einlesen der persistenten .env-Neuwerte Priorität, um ein Überschreiben durch alte Umgebungsvariablen zu vermeiden, die beim Erstellen des Containers eingefügt wurden.
  • 📈 Marktbewertung LLM max_tokens-Verbesserung – Der Link zur Marktbewertungsgenerierung aktualisiert LLM max_tokens von 2048 auf 8192, wodurch die Wahrscheinlichkeit verringert wird, dass die Ausgabe langer Bewertungen aufgrund von MAX_TOKENS im Voraus gekürzt wird, was zu unvollständigen Inhalten führt.
  • ⏰ Der integrierte geplante Scheduler erkennt SCHEDULE_TIME-Laufzeitänderungen – Der Scheduler erkennt jetzt die SCHEDULE_TIME-Änderung, nachdem WebUI zur Laufzeit gespeichert wurde, und bindet den täglichen Job in der nächsten Prüfrunde erneut.
  • 🪟 Windows-Release-Channel-Editor behält das MiniMax-Modellpräfix bei – Beim Ausfüllen von minimax/<模型名> im Channel-Modus behält die Modellliste den Wert bei, der bei der Ausführung auf den Backend-Normalisierungs- und Web-Einstellungsseiten vorhanden ist, und wird nicht mehr fälschlicherweise als openai/minimax/<模型名> umgeschrieben.
  • 🤖 Inbound-Webhook von Discord ergänzt Ed25519-Signaturüberprüfung – DiscordPlatform überprüft jetzt die Discord-Interaktionssignatur basierend auf X-Signature-Ed25519, X-Signature-Timestamp und dem ursprünglichen Anfragetext; Lehnen Sie die Anfrage direkt ab, wenn der Signatur-Header fehlt, das Format des öffentlichen Schlüssels illegal ist oder die Signatur nicht übereinstimmt, und der Zeitstempel wird in einem Alterungsfenster von ±5 Minuten überprüft, um sich gegen Replay-Angriffe zu schützen.
  • ⚙️ Klärung der Konfigurationsbeziehung STOCK_GROUP_N / EMAIL_GROUP_N – Klärung der Beziehung mit STOCK_LIST und Ausgabe einer Warnung für E-Mail-Gruppen, die STOCK_LIST während der Konfigurationsüberprüfung überschreiten.
  • 🗓️ Die Wiederaufnahme des Haltepunkts wurde so geändert, dass sie anhand der Marktzeitzone und des Handelskalenders beurteilt wird (Behebung von Nr. 880) – Die Bestandsdaten-Existenzprüfung verwendet nicht mehr direkt den natürlichen Tag des Servers, sondern analysiert den „letzten wiederverwendbaren Handelstag“ gemäß den jeweiligen Marktzeitzonen von A-Aktien/Hongkong-Aktien/US-Aktien.
  • 📨 Im Einzelaktien-Push-Modus werden gemeinsam genutzte Benachrichtigungsinstanzen nicht mehr gleichzeitig wiederverwendet – StockAnalysisPipeline.run() behält jetzt die Parallelität der Einzelaktienanalyse bei, verschiebt jedoch die Sofortbenachrichtigungen unter SINGLE_STOCK_NOTIFY=true auf die Ergebniserfassungsseite für den seriellen Versand.
  • 🔇 Die Echtzeit-Marktherabstufungsaufforderung ist auf einen einzelnen Alarm beschränkt – Wenn der Hauptanalyseprozess den Aktiennamen erhält, wird keine Echtzeit-Marktabfrage mehr im Voraus ausgelöst. Erst wenn nicht alle Datenquellen verfügbar sind, wird die Eingabeaufforderung auf den historischen Schlusskurs herabgestuft, um die Analyse fortzusetzen.
  • 🔍 A-Share-Suche nach chinesischen Informationen stellt chinesische Priorität wieder her – search_stock_news() testet nun weiterhin nachfolgende Suchmaschinen, wenn der erste Anbieter hauptsächlich englische Informationen zurückgibt, und ordnet chinesische Informationen im gleichen Ergebnisstapel ganz vorne ein.
  • 🔒 **Der gemeinsam genutzte Status vervollständigt die einheitliche Sperrung während der gleichzeitigen Ausführung. ** – Das Problem der fehlenden einheitlichen Sperrung des gemeinsam genutzten Status während der gleichzeitigen Ausführung wurde behoben, um Datenkonkurrenz in Multi-Thread-Szenarien zu vermeiden.

Test

  • 🧪 Regressionstest für Versionsinformationen der Seite „Ergänzende Einstellungen“ – Rendering-Assertion für Seitenversionsinformationen der Webeinstellungen hinzugefügt und die Platzhalterversion 0.0.0 überschrieben, um automatisch auf die Logik des Build-Logos zurückzugreifen.

daily_stock_analysis v3.12.0

发布亮点

  • 📊 回测页新增"次日验证"视图 — 可按股票与日期范围查看 AI 预测 vs 次日实际涨跌，复用历史分析与 1 日回测结果，快速验证分析准确率。
  • 🔧 LLM 接入体验简化 — 用户侧文案统一收口为"主模型 / 备选模型 / 模型渠道"，不再把 LiteLLM 当作普通用户必学概念，现有配置键保持兼容。
  • 🐳 Docker / WebUI 运行时稳态补强 — 修复系统设置保存后配置不生效、启动早期日志缺失、预构建静态资源复用等问题，降低容器化部署的运维摩擦。
  • 🔒 安全与并发稳定性同步增强 — Discord 入站 Webhook 补齐 Ed25519 验签，修复并发执行时共享状态未加锁、单股推送模式通知并发复用等问题。
  • 🖥️ 桌面端与定时任务细节打磨 — Windows 安装器支持自选安装目录，内置定时调度器感知运行中 SCHEDULE_TIME 变更，断点续传改按市场时区判断。

新功能

  • 📊 回测页新增"次日验证 / 1 日窗口"视图 — 可按股票代码与分析日期范围查看 AI 预测、次日实际涨跌及筛选区间准确率，复用历史分析与 1 日回测结果实现。
  • 🏷️ Web 设置页新增版本信息卡片 — apps/dsa-web 现在会在构建时注入前端包版本与构建时间，系统设置页新增只读"版本信息"区块，展示 WebUI 版本 / 构建标识 / 构建时间；当 package.json 仍为占位版本 0.0.0 时，会自动回退为构建标识，方便 Docker 重建后快速确认当前静态资源是否已经生效。
  • 🪟 Windows 桌面安装器支持自选安装目录 — 安装器改为支持在安装向导中自定义安装目录，安装到非默认盘符后仍沿用现有打包态目录逻辑在安装目录旁读写 .env、data/stock_analysis.db 和 logs/desktop.log，同时保留 win-unpacked 免安装分发方式。安装器仅支持当前用户安装、已禁用管理员提权（allowElevation: false），并通过 NSIS .onVerifyInstDir 阻止选择系统保护目录。

改进

  • 🔎 SerpAPI 正文补抓范围收敛 — 自然搜索结果不再逐条同步抓取网页正文；现在仅对极少数高位且摘要明显不足的结果，在更短超时预算内做延迟补抓，并优先复用 SerpAPI 已返回的结构化摘要，降低搜索链路尾延迟与慢站点放大风险。
  • 🤖 LLM 接入体验简化 — 面向用户的 AI 模型接入文案已统一收口为"主模型 / Agent 主模型 / 备选模型 / 模型渠道 / 高级模型路由配置"；Web 设置页、配置元数据、校验提示与中英文文档不再把 LiteLLM 当作普通用户默认必学概念，现有 LITELLM_* / LLM_CHANNELS 配置键仍保持兼容。

修复

  • 🚀 启动早期失败时暴露真实根因 — python main.py 现在通过 stderr 暴露真实根因，bootstrap 阶段不再向硬编码 logs/ 目录写入文件日志，文件日志推迟到 config.log_dir 可用后创建，避免健康启动在非预期路径残留日志文件。
  • 🐳 Docker WebUI 运行时优先复用预构建静态资源 — prepare_webui_frontend_assets() 现在会先检查镜像内已有的 static/index.html 是否可直接复用；当容器运行时不包含 apps/dsa-web 源码目录且未安装 npm 时，也不会误报"未找到前端项目，无法自动构建"，从而恢复 Docker 部署后的 WebUI 打开能力。
  • 🐳 Docker WebUI 系统设置保存后配置生效 — Docker 场景下 WebUI 保存 STOCK_LIST、SCHEDULE_ENABLED、SCHEDULE_TIME、SCHEDULE_RUN_IMMEDIATELY、RUN_IMMEDIATELY 后，Config 会优先读取持久化 .env 中的新值，避免被容器创建时注入的旧环境变量覆盖。
  • 📈 市场复盘 LLM max_tokens 提升 — 市场复盘生成链路将 LLM max_tokens 从 2048 提升到 8192，降低长复盘输出因 MAX_TOKENS 提前截断导致内容未完成的概率。
  • ⏰ 内置定时调度器感知 SCHEDULE_TIME 运行时变更 — 调度器现在会在运行中感知 WebUI 保存后的 SCHEDULE_TIME 变化，并在下一轮检查时重绑 daily job。
  • 🪟 Windows Release 渠道编辑器保留 MiniMax 模型前缀 — 渠道模式下填写 minimax/<模型名> 时，后端归一化与 Web 设置页运行时模型列表都会保留该值原样，不再误改写成 openai/minimax/<模型名>。
  • 🤖 Discord 入站 Webhook 补齐 Ed25519 验签 — DiscordPlatform 现在会基于 X-Signature-Ed25519、X-Signature-Timestamp 和原始请求体校验 Discord Interaction 签名；缺失签名头、公钥格式非法或签名不匹配时直接拒绝请求，同时对 timestamp 做 ±5 分钟时效窗口校验以防御重放攻击。
  • ⚙️ STOCK_GROUP_N / EMAIL_GROUP_N 配置关系明确化 — 明确与 STOCK_LIST 的关系，并在配置校验中对超出 STOCK_LIST 的邮件分组给出 warning。
  • 🗓️ 断点续传改按市场时区和交易日历判断（fixes #880）— 股票数据存在性检查不再直接使用服务器自然日，而是按 A 股 / 港股 / 美股各自市场时区解析"最新可复用交易日"。
  • 📨 单股推送模式不再并发复用共享通知实例 — StockAnalysisPipeline.run() 现在会保留个股分析并发，但把 SINGLE_STOCK_NOTIFY=true 下的即时通知挪到结果收集侧串行发送。
  • 🔇 实时行情降级提示收口为单次告警 — 分析主流程获取股票名称时不再提前触发一次实时行情查询，只有在全部数据源都不可用时才提示已降级为历史收盘价继续分析。
  • 🔍 A 股中文资讯搜索恢复中文优先 — search_stock_news() 现在会在首个 provider 主要返回英文资讯时继续尝试后续引擎，并将同批结果中的中文资讯排到前面。
  • 🔒 并发执行时共享状态补齐统一加锁 — 修复并发执行时共享状态缺少统一加锁的问题，避免多线程场景下的数据竞争。

测试

  • 🧪 补充设置页版本信息回归测试 — 新增 Web 设置页版本信息渲染断言，并覆盖占位版本 0.0.0 自动回退为构建标识的逻辑。
