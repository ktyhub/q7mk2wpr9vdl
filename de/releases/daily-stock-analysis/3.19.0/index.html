daily_stock_analysis v3.19.0

Neue Funktionen

– #1391 Phase 1 Mindestlink zum Ausführen der Diagnose implementiert: Task/SSE hängt Trace_ID an und zeichnet tägliche und Echtzeit-Markt-ProviderRun-Snapshots auf.

  • Die Alarmzentrale fügt P7-Regeln für die Ampelstrukturierung im großen Maßstab hinzu, unterstützt market_light_status und market_light_score_drop und verwendet vorhandene Worker, Auslöserhistorie, Benachrichtigungen und Kühllinks wieder.
  • #1391 Phase 2 Run Diagnostic Summary implementiert: Generieren Sie eine vom Benutzer lesbare RunDiagnosticSummary, die historische Berichtsdiagnose API und desensibilisierten Texttexts bereitstellt.
  • #1391 Phase 3 Sichtbarkeit der laufenden Diagnose implementiert: Berichtsdetails und Aufgabenfenster werden standardmäßig ausgeblendet, um den laufenden Status, die Ablaufverfolgung und reproduzierbare Informationen zur Fehlerbehebung anzuzeigen; Das Backend bietet historisches Link-Backfilling über api/v1/history/{record_id}/diagnostics und context_snapshot.diagnostics.
  • Interner Vertrag von AnalysisContextPack P1 und desensibilisierte Serialisierungstests hinzugefügt. – AnalysisContextPack P2-Builder hinzugefügt, um interne Kontextpakete aus vorhandenen Artefakten in allgemeinen Analysepipelines zusammenzustellen. – Wengu hat die Komprimierung des sichtbaren Konversationskontexts hinzugefügt, die standardmäßig deaktiviert ist, Web-Switch, erweiterte Agent-Voreinstellung, fortlaufende Zusammenfassung und Originaltextschutz der letzten Runde unterstützt und so den Token-Verbrauch bei langen Sitzungen reduziert. – Der Stock-Index zur automatischen Vervollständigung unterstützt standardmäßig die Remote-Aktualisierung und den Cache vom GitHub-Hauptindex zum lokalen Index. Wenn der Web/CLI-Analyseeintrag fehlschlägt, wird er automatisch auf den integrierten Index heruntergestuft, wodurch die Wahrscheinlichkeit verringert wird, dass die alte Abkürzung die Analyse nach der Enthauptung und Namensänderung verunreinigt. – Gewöhnliche Analyse und Agent-Laufzeitaufforderung sind mit der AnalysisContextPack-Zusammenfassung mit geringer Empfindlichkeit verbunden, um die Kompatibilität mit der Verlaufs-/API-/Webausgabe aufrechtzuerhalten.

Verbesserungen

– scripts/fetch_tushare_stock_list.py kann Namen mit dem Präfix XD/XR/DR/N/C in A-Shares für die Standardverwendung im automatischen Vervollständigungsaktualisierungsprozess auffüllen und korrigieren. – Die Web-Routing-Seite wurde so geändert, dass sie bei Bedarf geladen wird, die Größe des ersten Pakets wurde reduziert und eine Wiederherstellungsaufforderung für Routenladefehler wurde hinzugefügt.

  • Die Markdown-Schublade für die vollständige Webberichterstattung wurde so geändert, dass sie bei Bedarf geladen wird.
  • Basislinien für die Marktphaseninferenz hinzugefügt und die Semantik der Tage vor dem Markt, im Markt innerhalb des Marktes, in der Mittagspause, in der Nähe des Handelsschlusses, nach dem Markt und in Nichthandelstagen geklärt.
  • Es wurden Kontextkonstruktions- und Degradationstests für die laufende Marktphase hinzugefügt.
  • Die Konfiguration der Einstellungsseite hilft dabei, das zweisprachige Verfassen chinesischer und englischer Texte für die tatsächlichen Anzeige-/konfigurierbaren Felder der Web-Einstellungsseite schrittweise zu vervollständigen und deckt Agent, Backtesting, Berichterstellung, Benachrichtigungsweiterleitung, Systemlaufzeit, AI-Legacy, Datenquellen und erweiterte Benachrichtigungskonfiguration ab.
  • P2-min: LLM Prompt fügt Marktphasenkontext ein.

Beheben

– Die Generierung des automatischen Vervollständigungsindex für Aktien schlägt direkt fehl, wenn pypinyin fehlt, um das Schreiben herabgestufter Indizes mit fehlenden Pinyin-Feldern zu vermeiden.

  • Normalisieren Sie das Echtzeit-Markthandelsvolumen von Tencent als Aktienkaliber, um eine Verstärkung der Volumen-Energie-Änderungsmultiplikatoren und irreführende Analyseberichte zu vermeiden. – Die Standardbereitstellung von Docker entfernt die .env-Einzeldatei-Mount, um zu verhindern, dass Device or resource busy dadurch ausgelöst wird, dass os.replace den Mount-Punkt aktualisiert, wenn die WebUI die Konfiguration speichert.
  • Konvergenz #1391 Phase 0 A-Share-Code-Eigentumsgrenze: Vervollständigen Sie die Eigentumskonsistenz der Präfixszenarien SH/SZ und klären Sie den Umfang dieser Reparaturrunde für data_provider/baostock_fetcher.py, data_provider/pytdx_fetcher.py und data_provider/tushare_fetcher.py. – Die interne Formatkonvertierung des Datenquellen-Fallbacks wie Baostock wurde behoben, wenn STOCK_LIST bloße A-Share-Codes verwendet, wobei die Benutzerkonfiguration beibehalten wurde, um weiterhin 6-stellige Aktiennummern zu verwenden. – Die automatischen Updates des Windows-Desktops werden so geändert, dass das Installationsprogramm unbeaufsichtigt ausgeführt wird, nachdem der Benutzer den Neustart der Installation bestätigt hat, und Prozessverweise nach dem Stoppen des integrierten Backends bereinigt werden, wodurch die Wahrscheinlichkeit verringert wird, dass das Installationsprogramm die Meldung „Tägliche Bestandsanalyse kann nicht geschlossen werden“ ausgibt. – Der macOS-Desktop migriert die Laufzeitkonfiguration in das Benutzerdatenverzeichnis und migriert .env, Datenbank und Protokolle, während auf die Dateien im alten .app-Paket noch zugegriffen werden kann, um eine Neukonfiguration nach nachfolgenden Ersetzungen und Upgrades zu vermeiden. – Die Extraktion zugehöriger Abschnitte und Abschnittsverknüpfungsfelder in mit Agenten/historisch kompatiblen Snapshots wurde wiederhergestellt und das Regressionsproblem der fehlenden „Abschnittsverknüpfung“ im neuen Homepage-Bericht behoben. – Der Feldname des alten Alarms JSON und die semantische Beschreibung der Übermittlung des Stillezeitraums in der Hilfe zu den Webeinstellungen wurden korrigiert. – Das Problem wurde behoben, dass der Konfigurationstitel, die Beschreibung und die wichtigsten Dropdown-Optionen in den Datenquellen-, Benachrichtigungs-, System- und Agent-Bereichen der Web-Chinesisch-Einstellungsseite fehlten. – Es wurde ein Problem behoben, bei dem der Status der laufenden Agenten-/Analyseaufgabe möglicherweise bestehen bleibt, nachdem die Sitzung gewechselt und die Verbindung zur Startseitenaufgabe wiederhergestellt wurde. – Anbieterbewusster Trace-Subtrack zum Einzelagenten hinzugefügt und reasoning_content und Tool-Protokollmaterialien von DeepSeek V4 Thinking + Tool-Call über alle Räder hinweg beibehalten. – Der historischen Bottom-Up-Schnittstelle von Akshare Sina/Tencent A-Share wurde ein Timeout auf Anrufebene hinzugefügt und der Tushare 605xxx Shanghai Stock Code Routing-Regressionstest abgeschlossen, um zu verhindern, dass die geplante Analyse aufgrund der Nichtreaktion der Datenquelle hängen bleibt.
  • Erhöhen Sie die Untergrenze der exchange-calendars-Abhängigkeit auf 4.13.0, um Analysefehler aufgrund des Ausfalls der Timedelta-Einheit T beim Importieren des Handelskalenders in die Pandas-3-Umgebung zu vermeiden.
  • Durch interaktive Befehle (DingTalk-Konversationen, Feishu-Konversationen, Telegram) ausgelöste Analyseergebnisse werden nur an die Quellkonversation zurückgegeben und nicht mehr gleichzeitig an statische Benachrichtigungskanäle gesendet. – An die Longbridge OAuth 2.0-Authentifizierung und Token-Cache-Wiederherstellung angepasst, um zu verhindern, dass die Longbridge-Datenquelle fälschlicherweise als unkonfiguriert eingeschätzt wird, wenn das neue Backend kein Legacy-Zugriffstoken hat. – Der Longbridge-OAuth-Pfad protokolliert explizit Downgrades, wenn das aktuelle SDK OAuthBuilder/Config.from_oauth nicht unterstützt, um Buildfehler zu vermeiden, wenn Linux/Docker nur ältere SDK installieren kann.
  • Kompatibel mit dem Szenario, in dem die YFinance-Tageszeile einen unbenannten Datumsindex zurückgibt, um die Unterbrechung des täglichen Fallbacks der US-Aktien zu vermeiden, die durch das Fehlen der Spalte date nach der Standardisierung verursacht wird.

  • Füllen Sie die Alarm Center P8-Dokumentation und die Konfigurationsanweisungen aus, um die Grenzen zwischen älteren JSON-, erweiterten Regeln, Web-/API-, Docker-, GitHub-Aktionen und Desktop zu klären. – Beachten Sie, dass dieser Desktop-Fix nur den Installationslink für das Windows NSIS-Update und die Bereinigung des Back-End-Prozesslebenszyklus abdeckt. Die Semantik des Einstellungselements Speichern/Modelllaufzeitbereinigung wird nicht geändert. Entfernen Sie die docker/Dockerfile npm registry-Änderungen, die zuvor versehentlich eingeführt wurden, und stellen Sie die Trennung der Verantwortlichkeiten zwischen Bereitstellungs-Builds und Update-Reparaturen wieder her. – AnalysisContextPack P0-Kontextinventur hinzugefügt, um den Feldqualitätsstatus, die vorhandene Statuszuordnung und die Grenzen des ersten Versionspakets zu verdeutlichen. – Stellen Sie klar, dass der strukturierte Erkennungsalarm in #1391 Phase 2 ein Nicht-Konfigurationsmigrationssignal ist: Unzulässige Werte agent_max_steps/agent_orchestrator_timeout_s werden auf die Standardwerte zurückgesetzt und Protokollalarme generieren. Der neue Diagnoselink fügt nur Lese- und Schreibfelder context_snapshot/RunDiagnosticSummary hinzu und schreibt die Semantik von litellm_model, agent_litellm_model, openai_base_url, LLM-Kanalrouting oder Konfigurationsmigration nicht neu.
  • Ergänzende Kompatibilitätsbeschreibung Nr. 1391 Phase 3: Zeichnen Sie die Persistenz der Backend-Diagnose, historische Abfrage- und Benachrichtigungs-Writeback-Link-Änderungsgrenzen und Rollback-Strategien sowie vollständige Überprüfungsanforderungen für die Backend-Zugriffsebene auf.

daily_stock_analysis v3.19.0

新功能

  • 落地 #1391 Phase 1 运行诊断最小链路：任务/SSE 追加 trace_id，并记录日线与实时行情 ProviderRun 快照。
  • 告警中心新增 P7 大盘红绿灯结构化规则，支持 market_light_status 与 market_light_score_drop 并复用现有 worker、触发历史、通知和冷却链路。
  • 落地 #1391 Phase 2 运行诊断摘要：生成用户可读 RunDiagnosticSummary，提供历史报告诊断 API 与脱敏复制文本。
  • 落地 #1391 Phase 3 运行诊断可见性：报告详情和任务面板默认折叠展示运行状态、trace 与可复制排障信息；后端通过 api/v1/history/{record_id}/diagnostics 与 context_snapshot.diagnostics 提供历史链路回填。
  • 新增 AnalysisContextPack P1 内部契约与脱敏序列化测试。
  • 新增 AnalysisContextPack P2 builder，从普通分析 pipeline 已有 artifacts 组装内部上下文包。
  • 问股新增默认关闭的可见对话上下文压缩，支持 Web 开关、Agent 高级 preset、滚动摘要和最近轮次原文保护，降低长会话 token 消耗。
  • 股票自动补全索引默认支持从 GitHub main 远程刷新并缓存到本地，Web/CLI 分析入口失败时自动降级到内置索引，降低摘帽和更名后旧简称污染分析的概率。
  • 普通分析与 Agent 运行时 Prompt 接入 AnalysisContextPack 低敏摘要，保持 history/API/Web 输出兼容。

改进

  • scripts/fetch_tushare_stock_list.py 可对 A 股中带 XD/XR/DR/N/C 前缀的名称进行回填修正，供自动补全刷新流程默认使用。
  • Web 路由页面改为按需加载，降低首包体积并增加路由加载失败恢复提示。
  • Web 完整报告 Markdown 抽屉改为按需加载。
  • 新增市场阶段推断基线并明确盘前、盘中、午休、临近收盘、盘后和非交易日语义。
  • 新增运行态市场阶段上下文构造与降级测试。
  • 设置页配置帮助阶段性补齐 Web 设置页实际展示/可配置字段的中英双语文案，覆盖 Agent、回测、报告、通知路由、系统运行时、AI legacy、数据源和通知高级配置。
  • P2-min：LLM Prompt 注入市场阶段上下文。

修复

  • 股票自动补全索引生成缺少 pypinyin 时改为直接失败，避免写出缺失拼音字段的降级索引。
  • 归一腾讯实时行情成交量为股口径，避免量能变化倍数被放大并误导分析报告。
  • Docker 默认部署移除 .env 单文件挂载，避免 WebUI 保存配置时因 os.replace 更新挂载点触发 Device or resource busy。
  • 收敛 #1391 Phase 0 A 股代码归属边界：补齐 SH/SZ 前缀场景的归属一致性，明确 data_provider/baostock_fetcher.py、data_provider/pytdx_fetcher.py、data_provider/tushare_fetcher.py 的本轮修复范围。
  • 修复 STOCK_LIST 使用裸 A 股代码时 Baostock 等数据源 fallback 的内部格式转换，保持用户配置继续使用 6 位股票编号。
  • Windows 桌面端自动更新在用户确认重启安装后改为静默执行安装器，并在停止内置后端后清理进程引用，降低安装器提示“每日股票分析无法关闭”的概率。
  • macOS 桌面端将运行时配置迁移到用户数据目录，并在旧 .app 包内文件仍可访问时迁移 .env、数据库和日志，避免后续替换升级后重新配置。
  • 恢复 Agent/历史兼容快照中的关联板块与板块联动字段提取，修复新版首页报告缺少“板块联动”的回归问题。
  • 修正 Web 设置帮助中 legacy 告警 JSON 字段名与静默时段投递语义说明。
  • 修复 Web 中文设置页在数据源、通知、系统与 Agent 区域的配置标题、说明和关键下拉选项漏翻问题。
  • 修复问股会话切换和首页任务重连后可能残留 Agent/分析任务进行中状态的问题。
  • 问股 single-agent 新增 provider-aware trace 分轨，跨轮保留 DeepSeek V4 thinking + tool-call 的 reasoning_content 与工具协议材料。
  • 为 Akshare 新浪/腾讯 A 股历史兜底接口增加调用级超时，并补齐 Tushare 605xxx 沪市代码路由回归测试，避免定时分析因数据源无响应而挂起。
  • 将 exchange-calendars 依赖下限提升到 4.13.0，避免 pandas 3 环境导入交易日历时因 Timedelta 单位 T 失效导致分析失败。
  • 交互式命令（钉钉会话、飞书会话、Telegram）触发的分析结果只回到来源会话，不再同时广播到静态通知渠道。

  • 兼容 YFinance 日线返回未命名日期索引的场景，避免标准化后缺少 date 列导致美股日线 fallback 中断。
