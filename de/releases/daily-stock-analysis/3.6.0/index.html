daily_stock_analysis v3.6.0

Hinzugefügt

  • 🗑️ Batch-Löschung des Verlaufs – Die Web-Benutzeroberfläche unterstützt jetzt die Mehrfachauswahl und das Batch-Löschen des Analyseverlaufs; POST /api/v1/history/batch-delete-Endpunkt und ConfirmDialog-Komponente hinzugefügt.
  • 🔐 Authentifizierungseinstellungen API – neuer POST /api/v1/auth/settings-Endpunkt zum Aktivieren oder Deaktivieren der Webauthentifizierung zur Laufzeit und zum Festlegen des anfänglichen Administratorkennworts bei Bedarf
  • openclaw Skill-Version – 新增 docs/openclaw-skill-integration.md, 说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ LLM-Kanalprotokoll/Test-UX – .env und Webeinstellungen haben jetzt dieselbe Kanalform (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED); Die Einstellungsseite fügt Verbindungstests pro Kanal, Auswahl des Primär-/Fallback-/Vision-Modells und protokollbewusste Modellpräfixierung hinzu
  • 🤖 Agent-Architektur Phase 0+1 – gemeinsame Protokolle (AgentContext, AgentOpinion, StageResult), extrahierter run_agent_loop()-Runner, AGENT_ARCH-Switch (single/multi), Konfigurationsregistrierungseinträge
  • 🔍 Bot NL-Routing – zweischichtiges Routing in natürlicher Sprache: günstiger Regex-Vorfilter (Börsencodes + Finanzschlüsselwörter) → leichtes LLM-Intent-Parsing; gesteuert durch AGENT_NL_ROUTING=true; unterstützt die Extraktion mehrerer Aktien und Strategien
  • 💬 /ask-Multi-Stock-Analyse – durch Komma oder vs getrennte Codes (max. 5), parallele Thread-Ausführung mit 150-Sekunden-Timeout (behält Teilergebnisse bei), Markdown-Vergleichsübersichtstabelle oben
  • 📋 /history-Befehl – Sitzungsisolierung pro Benutzer über das {platform}_{user_id}:{scope}-Format (Doppelpunkttrennzeichen verhindert Präfixkollision); listet sowohl /chat- als auch /ask-Sitzungen auf; Details anzeigen oder löschen
  • 📊 /strategies-Befehl – listet die verfügbaren Strategie-YAML-Dateien gruppiert nach Kategorie (趋势/形态/反转/框架) mit dem Aktivierungsstatus ✅/⬜ auf
  • 🔧 Backtest-Zusammenfassungstools – get_strategy_backtest_summary und get_stock_backtest_summary als schreibgeschützte Agent-Tools registriert
  • ⚙️ Automatische Agentenerkennung – is_agent_available() erkennt automatisch von LITELLM_MODEL; explizites AGENT_MODE=true/false hat vollen Vorrang
  • 🏗️ Multi-Agent-Orchestrator (Phase 2) – AgentOrchestrator mit 4 Modi (quick/standard/full/strategy); Drop-in-Ersatz für AgentExecutor über AGENT_ARCH=multi; BaseAgent ABC mit Tool-Teilmengenfilterung, zwischengespeicherter Dateninjektion und strukturierter AgentOpinion-Ausgabe
  • 🧩 Spezialisierte Agenten (Phase 2-4) – TechnicalAgent (8 Tools, Trend-/MA-/MACD-/Volumen-/Musteranalyse), IntelAgent (Nachrichten und Stimmung, Verbreitung von Risikohinweisen), DecisionAgent (Synthese in das Entscheidungs-Dashboard JSON), RiskAgent (7 Risikokategorien, zweistufiger Schweregrad mit weicher/harter Überschreibung)
  • 📈 Strategiesystem (Phase 3) – StrategyAgent (Bewertung pro Strategie aus YAML-Fähigkeiten), StrategyRouter (regelbasierte Regimeerkennung → Strategieauswahl), StrategyAggregator (gewichteter Konsens mit Backtest-Leistungsfaktor)
  • 🔬 Deep Research Agent (Phase 5) – ResearchAgent mit 3-Phasen-Ansatz (zerlegen → Unterfragen recherchieren → Bericht synthetisieren); Verfolgung des Token-Budgets; neuer Bot-Befehl /research mit Aliasnamen (/深研, /deepsearch)
  • 🧠 Speicher und Kalibrierung (Phase 6) – AgentMemory mit Verfolgung der Vorhersagegenauigkeit, Vertrauenskalibrierung (aktiviert nach dem Mindeststichprobenschwellenwert), automatischer Strategiegewichtung basierend auf der historischen Gewinnrate
  • 📊 Portfolio Agent (Phase 7) – PortfolioAgent für die Analyse mehrerer Aktienportfolios (Positionsgröße, Sektorkonzentration, Korrelationsrisiko, marktübergreifende Verknüpfung, Vorschläge zur Neuausrichtung)
  • 🔔 Ereignisgesteuerte Warnungen (Phase 7) – EventMonitor mit den Regeln PriceAlert, VolumeAlert, SentimentAlert; Asynchrone Prüfung, Rückrufbenachrichtigungen, serialisierbare Persistenz
  • ⚙️ Neue Konfigurationseinträge – AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING – alle registriert in config.py + config_registry.py (WebUI-konfigurierbar)

Geändert

  • 🔐 Semantik des Authentifizierungspasswortstatus – Das Vorhandensein gespeicherter Passwörter wird jetzt unabhängig von der Authentifizierungsaktivierung verfolgt. Wenn die Authentifizierung deaktiviert ist, gibt /api/v1/auth/status passwordSet=false zurück, während das gespeicherte Passwort für eine spätere erneute Aktivierung erhalten bleibt
  • 🔐 Authentifizierungseinstellungen aktivieren die Härtung erneut – die erneute Aktivierung der Authentifizierung mit einem gespeicherten Passwort erfordert jetzt currentPassword, und eine fehlgeschlagene Sitzungserstellung setzt die Authentifizierungsumschaltung zurück, um eine Sperrung zu vermeiden
  • ♻️ AgentExecutor überarbeitet – _run_loop delegiert an gemeinsam genutztes runner.run_agent_loop(); Doppelter Serialisierungs-/Parsing-/Thinking-Label-Code entfernt
  • ♻️ Unified Agent Switch – Bot, API und Pipeline verwenden alle config.is_agent_available() anstelle der divergenten config.agent_mode-Prüfungen
  • 📖 README.md – erweiterter Bot-Befehlsabschnitt (ask/chat/strategies/history), NL-Routing-Hinweis hinzugefügt, Beschreibung des Agentenmodus aktualisiert
  • 📖 .env.example – Konfigurationsdokumentation für AGENT_ARCH und AGENT_NL_ROUTING hinzugefügt

Behoben

  • 🐛 Rotation von Sitzungsgeheimnissen unter Windows – verwenden Sie atomares Ersetzen, damit Authentifizierungsschalter bestehende Sitzungen ungültig machen, selbst wenn .session_secret bereits vorhanden ist
  • 🐛 Authentifizierung umschalten Atomizität – ADMIN_AUTH_ENABLED beibehalten, bevor das Sitzungsgeheimnis rotiert wird; Bei einem Rotationsfehler kehren Sie zum vorherigen Authentifizierungsstatus zurück
  • 🔧 Leitlinien für die LLM-Laufzeitauswahl – Der Kanaleditor im YAML-Modus deckt LITELLM_MODEL / Fallback / Vision nicht mehr ab; Die Überprüfung der Systemkonfiguration fügt die Laufzeitquellenprüfung hinzu, nachdem alle Kanäle deaktiviert wurden, und behebt das Problem, dass Protokoll-Alias-Modellen wie vertexai/... wiederholt vorangestellt werden
  • 🐛 Multi-Aktien-/ask-Folgeregressionen – Portfolio-Overlay hat jetzt das gleiche Timeout-Budget wie die Pro-Aktien-Phase und wird bei Timeout übersprungen, anstatt die Bot-Antwort zu blockieren; /history speichert jetzt die lesbare Zusammenfassung pro Aktie anstelle des Roh-Dashboards JSON; Die komprimierte Multi-Stock-Ausgabe rendert jetzt numerische sniper_points-Werte
  • 🐛 Entscheidungs-Dashboard-Enum-Kompatibilität – Multi-Agent DecisionAgent behält decision_type jetzt innerhalb des alten buy|hold|sell-Vertrags und normalisiert verirrte strong_*-Ausgaben vor Risikoüberschreibung, Pipeline-Konvertierung und Downstream-Anwendungen
  • 🛟 Multi-Agent-Teilergebnis-Fallback – IntelAgent speichert jetzt geparste Informationen für die spätere Wiederverwendung zwischen, die gemeinsame JSON-Analyse toleriert leicht fehlerhafte Modellausgaben und der Orchestrator behält/synthetisiert ein minimales Dashboard bei Zeitüberschreitungen oder Analysefehlern in der Mitte der Pipeline, anstatt immer auf 50/观望/未知 zu reduzieren
  • 🐛 Gemeinsames LiteLLM-Routing wiederhergestellt – Bot-NL-Intent-Parsing und ResearchAgent-Planung/Synthese verwenden jetzt denselben LiteLLM-Adapter/Router/Fallback/api_base-Injection-Pfad wie der Hauptagentenfluss wieder, sodass sich LLM_CHANNELS/LITELLM_CONFIG/OpenAI-kompatible Bereitstellungen konsistent verhalten
  • 🐛 Abwärtskompatibilität der Bot-Chat-Sitzung – /chat verwendet jetzt weiterhin die alte {platform}_{user_id}-Sitzungs-ID, wenn bereits ein alter Verlauf vorhanden ist, und /history kann diese Sitzungen vor der Migration weiterhin zusammen mit dem neuen {platform}_{user_id}:chat-Format auflisten/anzeigen/löschen
  • 🐛 EventMonitor nicht unterstützte Regelablehnung – Konfigurationsvalidierung/Laufzeitladen lehnt jetzt Alarmtypen ab oder überspringt sie, die der Monitor noch nicht auswerten kann, sodass der Zeitplanmodus keine permanenten No-Op-Regeln mehr stillschweigend akzeptiert
  • 🐛 P0 Fundamental Aggregation Stability Fix (#614) – Korrigieren Sie die semantische Regression des get_stock_info-Sektors (fügen Sie belong_boards hinzu und behalten Sie boards-kompatible Aliase bei), führen Sie grundlegende kontextoptimierte Rückgaben für Kontrolltokens ein, fügen Sie maximale Eintragseliminierung zum grundlegenden Cache hinzu und vervollständigen Sie die ETF-Gesamtstatusaggregation und NaN-Sektorfeldfilterung, um Fail-Open und minimales Eindringen sicherzustellen.
  • 🔧 Zusatz von GitHub Actions-Suchmaschinen-Umgebungsvariablen – Der Workflow fügt die Umgebungsvariablenzuordnung MINIMAX_API_KEYS, BRAVE_API_KEYS, SEARXNG_BASE_URLS hinzu, sodass GitHub Actions-Benutzer die Suchdienste MiniMax, Brave und SearXNG konfigurieren können (zuvor hatte v3.5.0 eine Anbieterimplementierung hinzugefügt, aber keine Workflow-Konfiguration)
  • 🤖 Multi-Agent-Laufzeitkonsistenz – AGENT_MAX_STEPS wird jetzt an jeden orchestrierten Subagenten weitergegeben; Hinzugefügtes kooperatives AGENT_ORCHESTRATOR_TIMEOUT_S-Budget, um überlange Pipelines zu stoppen, bevor sie weiter kaskadieren
  • 🔌 Multi-Agent-Funktionsverkabelung – AGENT_RISK_OVERRIDE stuft endgültige Dashboards jetzt aktiv bei harten Risikoergebnissen herab; AGENT_MEMORY_ENABLED fügt jetzt den Speicher für aktuelle Analysen und die Vertrauenskalibrierung in spezialisierte Agenten ein; Multi-Stock /ask führt jetzt PortfolioAgent aus, um Allokations- und Konzentrationsrichtlinien auf Portfolioebene hinzuzufügen
  • 🔔 EventMonitor-Laufzeitverkabelung – Der Zeitplanmodus kann jetzt Alarmregeln von AGENT_EVENT_ALERT_RULES_JSON laden, sie bei AGENT_EVENT_MONITOR_INTERVAL_MINUTES abfragen und ausgelöste Alarme über den vorhandenen Benachrichtigungsdienst senden
  • 🛠️ Folge Stabilitätskorrekturen – Multi-Stock /ask greift jetzt auf die verwendbare Textausgabe zurück, wenn die Analyse des Dashboards JSON fehlschlägt; EventMonitor überspringt semantisch ungültige Regeln, anstatt den Start des Zeitplans abzubrechen. Die Hintergrundwarnungsabfrage läuft jetzt unabhängig von der geplanten Hauptanalyseschleife
  • 🧪 Multi-Agent-Regressionsabdeckung – Orchestrator-Ausführungstests für run(), chat(), Fehler in kritischen Phasen, ordnungsgemäße Verschlechterung und Timeout-Behandlung hinzugefügt
  • 🧹 PortfolioAgent-Bereinigung – post_process() verwendet jetzt die gemeinsam genutzte JSON-Analyse wieder und entfernt veraltete, nicht verwendete Importe
  • 🚦 Asynchroner Bot-Versand – CommandDispatcher macht jetzt dispatch_async() verfügbar; NL-Intent-Parsing und Standardbefehlsausführung werden aus der Ereignisschleife ausgelagert, der DingTalk-Stream wartet direkt auf asynchrone Handler und die Feishu-Stream-Verarbeitung wird aus dem SDK-Callback-Thread verschoben
  • 🌐 Asynchroner Webhook-Handler – neue handle_webhook_async()-Funktion in bot/handler.py zur Verwendung aus asynchronen Kontexten (z. B. FastAPI); ruft dispatch_async() direkt ohne Thread-Bridging auf
  • 🧵 Feishu-Stream ThreadPoolExecutor – unbegrenztes Spawnen pro Nachricht Thread durch ein begrenztes ThreadPoolExecutor(max_workers=8) ersetzt, um eine Thread-Explosion bei Nachrichtenbursts zu verhindern
  • 🔒 EventMonitor-Sicherheit – _check_volume() verarbeitet jetzt sicher get_daily_data, das None zurückgibt (kein Absturz beim Tupel-Entpacken); on_trigger-Rückrufe unterstützen sowohl synchronisierte als auch asynchrone Callables über asyncio.to_thread/await
  • 🧹 ResearchAgent dedup – _filtered_registry() delegiert jetzt an BaseAgent._filtered_registry(), anstatt die Filterlogik zu duplizieren
  • 🧹 Bot-Trailing-Whitespace-Bereinigung – W291/W293-Whitespace-Probleme in bot/handler.py, bot/dispatcher.py, bot/commands/base.py, bot/platforms/feishu_stream.py, bot/platforms/dingtalk_stream.py entfernt
  • 🐛 Dispatcher _parse_intent_via_llm-Sicherheit – fragiles 'raw' in dir() durch 'raw' in locals() für undefinierte Variablenschutz im JSONDecodeError-Handler ersetzt
  • 🐛 Vervollständigen Sie die Chipstruktur LLM, wenn sie nicht ausgefüllt ist (#589) – Wenn DeepSeek und andere Modelle chip_structure nicht korrekt ausfüllen, wird es automatisch mit den aus der Datenquelle erhaltenen Chipdaten vervollständigt, um sicherzustellen, dass die Anzeige jedes Modells konsistent ist; Sowohl die normale Analyse als auch der Agentenmodus sind gültig
  • 🐛 History Report Sniper Point Display Originaltext (#452) – Die Seite mit den historischen Details gibt jetzt der Anzeige der Originalzeichenfolge in raw_result.dashboard.battle_plan.sniper_points Vorrang, um zu verhindern, dass die numerische Spalte analysis_history Intervalle, erklärenden Text oder komplexe Punkte in eine einzige Zahl komprimiert; Behalten Sie als Ersatz die ursprüngliche Zahlenspalte bei
  • 🐛 Sitzungspräfix-Kollision – Benutzer-ID 123 konnte Sitzungen des Benutzers 1234 über startswith sehen; Mit Doppelpunkt-Trennzeichen im Sitzungs-ID-Format behoben
  • 🐛 NL-Vorfilter falsch positiver Ergebnisse – re.IGNORECASE führte dazu, dass [A-Z]{2,5} mit gebräuchlichen englischen Wörtern wie „Hallo“ übereinstimmte; Globale Flagge entfernt, Inline-(?i:...) nur für englische Finanzschlüsselwörter verwenden
  • 🐛 Gepunkteter Ticker in Strategieargumenten – _get_strategy_args() hat BRK.B nicht als Aktiencode erkannt und beließ ihn im Strategietext; Akzeptiert jetzt das TICKER.CLASS-Format
  • ⏱️ Hang-Fix bei langen Efinance-Anrufen (#660) – Einführung des _ef_call_with_timeout()-Wrappers für alle Efinance-API-Aufrufe (Standard 30 Sekunden, konfigurierbar über EFINANCE_CALL_TIMEOUT); Verwenden Sie executor.shutdown(wait=False), um sicherzustellen, dass der Hauptthread nach einer Zeitüberschreitung nicht mehr blockiert wird, wodurch das 81-Minuten-Hängerproblem vollständig beseitigt wird
  • 🛡️ Typsichere Inhaltsintegritätsprüfung (#660) – check_content_integrity() behandelt jetzt die Nicht-String-Typen operation_advice / analysis_summary als fehlende Felder, um nachgelagerte get_emoji()-Abstürze aufgrund von dict.strip() zu vermeiden
  • 📄 Berichtspeicherung und Benachrichtigung entkoppeln (#660) – _save_local_report() verlässt sich nicht mehr auf den Flag-Trigger send_notification und lokale Berichte werden wie gewohnt im --no-notify-Modus gespeichert
  • 🔄 Operation_Advice-Dictionary-Normalisierung (#660) – Pipeline und BacktestEngine ordnen jetzt das von LLM zurückgegebene dict-Format operation_advice über decision_type einer Standardzeichenfolge zu (Groß- und Kleinschreibung wird nicht beachtet), um Abstürze zu verhindern, die durch Änderungen im Modellausgabeformat verursacht werden
  • 🛡️ runner.py-Nutzung Kein Schutz (#660) – AttributeError wird nicht mehr ausgelöst, wenn response.usage None ist, Fallback auf 0 Token-Anzahl
  • 📋 Der stille Fehler des Orchestrators wurde in eine Protokollwarnung geändert (#660) – Der Fehler der Stufe IntelAgent/RiskAgent protokolliert jetzt WARNING, anstatt ihn stillschweigend zu überspringen, um die Diagnose zu erleichtern

Notizen

  • ⚠️ Multi-Worker-Authentifizierung umschaltbar – Aktualisierungen der Laufzeitauthentifizierung erfolgen prozesslokal; Multi-Worker-Bereitstellungen müssen Worker neu starten/rollen, um den Authentifizierungsstatus konsistent zu halten

daily_stock_analysis v3.6.0

Added

  • 🗑️ History batch deletion — Web UI now supports multi-selection and batch deletion of analysis history; added POST /api/v1/history/batch-delete endpoint and ConfirmDialog component.
  • 🔐 Auth settings API — new POST /api/v1/auth/settings endpoint to enable or disable Web authentication at runtime and set the initial admin password when needed
  • openclaw Skill 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ LLM channel protocol/test UX — .env and Web settings now share the same channel shape (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED); settings page adds per-channel connection testing, primary/fallback/vision model selection, and protocol-aware model prefixing
  • 🤖 Agent architecture Phase 0+1 — shared protocols (AgentContext, AgentOpinion, StageResult), extracted run_agent_loop() runner, AGENT_ARCH switch (single/multi), config registry entries
  • 🔍 Bot NL routing — two-layer natural-language routing: cheap regex pre-filter (stock codes + finance keywords) → lightweight LLM intent parsing; controlled by AGENT_NL_ROUTING=true; supports multi-stock and strategy extraction
  • 💬 /ask multi-stock analysis — comma or vs separated codes (max 5), parallel thread execution with 150s timeout (preserves partial results), Markdown comparison summary table at top
  • 📋 /history command — per-user session isolation via {platform}_{user_id}:{scope} format (colon delimiter prevents prefix collision); lists both /chat and /ask sessions; view detail or clear
  • 📊 /strategies command — lists available strategy YAML files grouped by category (趋势/形态/反转/框架) with ✅/⬜ activation status
  • 🔧 Backtest summary tools — get_strategy_backtest_summary and get_stock_backtest_summary registered as read-only Agent tools
  • ⚙️ Agent auto-detection — is_agent_available() auto-detects from LITELLM_MODEL; explicit AGENT_MODE=true/false takes full precedence
  • 🏗️ Multi-Agent orchestrator (Phase 2) — AgentOrchestrator with 4 modes (quick/standard/full/strategy); drop-in replacement for AgentExecutor via AGENT_ARCH=multi; BaseAgent ABC with tool subset filtering, cached data injection, and structured AgentOpinion output
  • 🧩 Specialised agents (Phase 2-4) — TechnicalAgent (8 tools, trend/MA/MACD/volume/pattern analysis), IntelAgent (news & sentiment, risk flag propagation), DecisionAgent (synthesis into Decision Dashboard JSON), RiskAgent (7 risk categories, two-level severity with soft/hard override)
  • 📈 Strategy system (Phase 3) — StrategyAgent (per-strategy evaluation from YAML skills), StrategyRouter (rule-based regime detection → strategy selection), StrategyAggregator (weighted consensus with backtest performance factor)
  • 🔬 Deep Research agent (Phase 5) — ResearchAgent with 3-phase approach (decompose → research sub-questions → synthesise report); token budget tracking; new /research bot command with aliases (/深研, /deepsearch)
  • 🧠 Memory & calibration (Phase 6) — AgentMemory with prediction accuracy tracking, confidence calibration (activates after minimum sample threshold), strategy auto-weighting based on historical win rate
  • 📊 Portfolio Agent (Phase 7) — PortfolioAgent for multi-stock portfolio analysis (position sizing, sector concentration, correlation risk, cross-market linkage, rebalance suggestions)
  • 🔔 Event-driven alerts (Phase 7) — EventMonitor with PriceAlert, VolumeAlert, SentimentAlert rules; async checking, callback notifications, serializable persistence
  • ⚙️ New config entries — AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING — all registered in config.py + config_registry.py (WebUI-configurable)

Changed

  • 🔐 Auth password state semantics — stored password existence is now tracked independently from auth enablement; when auth is disabled, /api/v1/auth/status returns passwordSet=false while preserving the saved password for future re-enable
  • 🔐 Auth settings re-enable hardening — re-enabling auth with a stored password now requires currentPassword, and failed session creation rolls back the auth toggle to avoid lockout
  • ♻️ AgentExecutor refactored — _run_loop delegates to shared runner.run_agent_loop(); removed duplicated serialization/parsing/thinking-label code
  • ♻️ Unified agent switch — Bot, API, and Pipeline all use config.is_agent_available() instead of divergent config.agent_mode checks
  • 📖 README.md — expanded Bot commands section (ask/chat/strategies/history), added NL routing note, updated agent mode description
  • 📖 .env.example — added AGENT_ARCH and AGENT_NL_ROUTING configuration documentation

Fixed

  • 🐛 Session secret rotation on Windows — use atomic replace so auth toggles invalidate existing sessions even when .session_secret already exists
  • 🐛 Auth toggle atomicity — persist ADMIN_AUTH_ENABLED before rotating session secret; on rotation failure, roll back to the previous auth state
  • 🔧 LLM runtime selection guardrails — YAML 模式下渠道编辑器不再覆盖 LITELLM_MODEL / fallback / Vision；系统配置校验补上全部渠道禁用后的运行时来源检查，并修复 vertexai/... 这类协议别名模型被重复加前缀的问题
  • 🐛 Multi-stock /ask follow-up regressions — portfolio overlay now shares the same timeout budget as the per-stock phase and is skipped on timeout instead of blocking the bot reply; /history now stores the readable per-stock summary instead of raw dashboard JSON; condensed multi-stock output now renders numeric sniper_points values
  • 🐛 Decision dashboard enum compatibility — multi-agent DecisionAgent now keeps decision_type within the legacy buy|hold|sell contract and normalizes stray strong_* outputs before risk override, pipeline conversion, and downstream统计/通知汇总
  • 🛟 Multi-Agent partial-result fallback — IntelAgent now caches parsed intel for downstream reuse, shared JSON parsing tolerates lightly malformed model output, and the orchestrator preserves/synthesizes a minimal dashboard on timeout or mid-pipeline parse failure instead of always collapsing to 50/观望/未知
  • 🐛 Shared LiteLLM routing restored — bot NL intent parsing and ResearchAgent planning/synthesis now reuse the same LiteLLM adapter / Router / fallback / api_base injection path as the main Agent flow, so LLM_CHANNELS / LITELLM_CONFIG / OpenAI-compatible deployments behave consistently

  • 🌐 Async webhook handler — new handle_webhook_async() function in bot/handler.py for use from async contexts (e.g. FastAPI); calls dispatch_async() directly without thread bridging
