daily_stock_analysis v3.7.0

Neue Funktionen

  • 💼 Positionsverwaltung P0 voll funktionsfähig online (#677, entspricht Issue #627)
    • Kernbuch und Snapshot-Closed-Loop: Fügen Sie neue Konten, Transaktionen, Cashflow, Unternehmensverhalten, Positions-Cache, tägliche Snapshots und andere Kerndatenmodelle und API-Endpunkte hinzu; unterstützt die Wiedergabe mit der FIFO/AVG-Dual-Cost-Methode; die Reihenfolge der Ereignisse am selben Tag ist auf 现金 → 企业行为 → 交易 festgelegt; Beim Schreiben von Positions-Snapshots werden atomare Transaktionen verwendet.
    • Broker-CSV-Import: Unterstützt die erste Reihe von Anpassungen durch Huatai/CITIC/China Merchants, einschließlich Listing-Alias-Kompatibilität; zweistufige Schnittstelle (Analysevorschau + Bestätigungsübermittlung); trade_uid-Priorität, idempotente Deduplizierung mit Schlüsselfeld-Hash; Führende Null-Bestandscodes bleiben vollständig erhalten.
    • Portfolio-Risikobericht: Konzentrationsrisiko (Top-Positionen + A-Aktien-Sektorkaliber), historische Retracement-Überwachung (unterstützt das Auffüllen fehlender Snapshots), Stop-Loss-Annäherungswarnung; einheitliche Umrechnung mehrerer Währungen in CNY-Kaliber; Wenn die Extraktion fehlschlägt, greifen Sie auf den letzten erfolgreichen Wechselkurs zurück und markieren Sie ihn als veraltet.
    • Web-Positionsseite (/portfolio): Portfolioübersicht, Positionsdetails, Konzentrations-Kreisdiagramm, Risikoübersicht, Wechsel zwischen vollständigem Portfolio und Einzelkonto; manuelle Eingabe von Transaktionen/Kapitalfluss/Unternehmensverhalten; Eingang zur eingebetteten Kontoerstellung; CSV-Analyse + Übermittlungs-Closed-Loop und Brokerage-Selektor.
    • Agent Position Tool: get_portfolio_snapshot-Datentool, standardmäßige kompakte Zusammenfassung, optionale Positionsdetails und Risikodaten hinzugefügt.
    • Ereignisabfrage API: GET /portfolio/trades, GET /portfolio/cash-ledger, GET /portfolio/corporate-actions hinzugefügt, unterstützt Datumsfilterung und Paging.
    • Erweiterbare Parser-Registrierung: gemeinsame Registrierung auf Anwendungsebene, unterstützt die Laufzeitregistrierung neuer Broker; Neu hinzugefügte GET /portfolio/imports/csv/brokers-Erkennungsschnittstelle.
  • 🎨 Front-End-Designsystem und atomare Komponentenbibliothek (#662)
    • Einführung einer progressiven Dual-Theme-Architektur (HSL-Variablen-Design-Token) zur Bereinigung des historischen Legacy-CSS; Refactoring von mehr als 20 Kernkomponenten wie Button / Karte / Badge / Collapsible / Input / Select usw.; Hinzufügen von Tools zum Zusammenführen von Klassennamen clsx + tailwind-merge; Verbesserung der Lesbarkeit des Verlaufs, der LLM-Konfiguration und anderer Seiten.
  • ⚡ Analyse des asynchronen Vertrags API und Startup-Optimierung (#656)
    • Standardisierung des Rückgabevertrags für asynchrone POST /api/v1/analysis/analyze-Anfragen; Optimieren Sie die Hilfslogik für den Dienststart. Beheben Sie das Ausrichtungsproblem zwischen der gemeinsamen Definition des Front-End-Berichtstyps und der Back-End-Antwort.

Beheben

  • 🔔 Abwärtskompatibilität der Discord-Umgebungsvariablen (#659): Fallback-Lesung von DISCORD_CHANNEL_ID → DISCORD_MAIN_CHANNEL_ID während der Laufzeit hinzugefügt; Benutzer der historischen Konfiguration können Discord Bot-Benachrichtigungen ohne Änderung wiederherstellen; Alle zugehörigen Dokumente sind auf .env.example ausgerichtet.
  • 🔧 GitHub Actions Node 24-Upgrade (#665): Aktualisieren Sie alle offiziellen GitHub-Aktionen auf Node 24-kompatible Versionen, wodurch die Node.js 20-Veraltungswarnung im CI-Protokoll entfernt wird (betrifft das erzwungene Upgrade-Fenster 2026-06-02).
  • 📅 Lokalisierung des Standarddatums auf der Positionsseite: Das Standarddatum im manuellen Eingabeformular wird auf Ortszeit (getFullYear/Month/Date) geändert, um das Problem der Datumsverschiebung für Benutzer in der UTC-N-Zeitzone am Abend desselben Tages zu beheben.
  • 🔁 Verstärkung der CSV-Import-Deduplizierungslogik: Der Dedup-Hash berücksichtigt die Zeilenseriennummer als Unterscheidungsmerkmal, um sicherzustellen, dass rechtlich getrennte Transaktionen im selben Feld nicht falsch gefaltet werden; Gleichzeitig wird der Hash auch beibehalten, wenn trade_uid vorhanden ist, um wiederholtes Schreiben aus gemischten Quellen zu verhindern.

Ändern

– POST /api/v1/portfolio/trades gibt 409 zurück, wenn trade_uid innerhalb desselben Kontos in Konflikt steht.

  • Ein neues Feld sector_concentration wird zur Positionsrisikoreaktion hinzugefügt (inkrementelle Erweiterung), und das ursprüngliche Feld concentration bleibt unverändert.
  • Analyse der Vertragsdokumentation zum asynchronen Verhalten der Schnittstelle API analyze; Gemeinsame Aktualisierung des Front-End-Berichtstyps.

Test

  • Neue Positionskerndiensttests hinzugefügt (FIFO/AVG-Teilverkauf, Ereignissequenz am selben Tag, wiederholte trade_uid-Rückgabe 409, Snapshot API-Vertrag).
  • CSV-Import-Idempotenz, legale Split-Transaktionsdeduplizierung, Deduplizierungsgrenze, Risikoschwellengrenze und Verhaltenstests bei Wechselkursherabstufungen hinzugefügt.
  • Agent get_portfolio_snapshot-Tool-Aufruftest hinzugefügt. – Analyse des asynchronen Vertragsregressionstests API hinzugefügt.

daily_stock_analysis v3.7.0

新功能

  • 💼 持仓管理 P0 全功能上线（#677，对应 Issue #627）

    • 核心账本与快照闭环：新增账户、交易、现金流水、企业行为、持仓缓存、每日快照等核心数据模型与 API 端点；支持 FIFO / AVG 双成本法回放；同日事件顺序固定为 现金 → 企业行为 → 交易；持仓快照写入采用原子事务。
    • 券商 CSV 导入：支持华泰 / 中信 / 招商首批适配，含列名别名兼容；两阶段接口（解析预览 + 确认提交）；trade_uid 优先、key-field hash 兜底的幂等去重；前导零股票代码完整保留。
    • 组合风险报告：集中度风险（Top Positions + A 股板块口径）、历史回撤监控（支持回填缺失快照）、止损接近预警；多币种统一换算 CNY 口径；汲取失败时回退最近成功汇率并标记 stale。
    • Web 持仓页（/portfolio）：组合总览、持仓明细、集中度饼图、风险摘要、全组合 / 单账户切换；手工录入交易 / 资金流水 / 企业行为；内嵌账户创建入口；CSV 解析 + 提交闭环与券商选择器。
    • Agent 持仓工具：新增 get_portfolio_snapshot 数据工具，默认紧凑摘要，可选持仓明细与风险数据。
    • 事件查询 API：新增 GET /portfolio/trades、GET /portfolio/cash-ledger、GET /portfolio/corporate-actions，支持日期过滤与分页。
    • 可扩展 Parser Registry：应用级共享注册，支持运行时注册新券商；新增 GET /portfolio/imports/csv/brokers 发现接口。

  • 🎨 前端设计系统与原子组件库（#662）

    • 引入渐进式双主题架构（HSL 变量化设计令牌），清理历史 Legacy CSS；重构 Button / Card / Badge / Collapsible / Input / Select 等 20+ 核心组件；新增 clsx + tailwind-merge 类名合并工具；提升历史记录、LLM 配置等页面可读性。

  • ⚡ 分析 API 异步契约与启动优化（#656）

    • 规范 POST /api/v1/analysis/analyze 异步请求的返回契约；优化服务启动辅助逻辑；修复前端报告类型联合定义与后端响应对齐问题。

修复

  • 🔔 Discord 环境变量向后兼容（#659）：运行时新增 DISCORD_CHANNEL_ID → DISCORD_MAIN_CHANNEL_ID 的 fallback 读取；历史配置用户无需修改即可恢复 Discord Bot 通知；全部相关文档与 .env.example 对齐。
  • 🔧 GitHub Actions Node 24 升级（#665）：将所有 GitHub 官方 actions 升级至 Node 24 兼容版本，消除 CI 日志中的 Node.js 20 deprecation warning（影响 2026-06-02 强制升级窗口）。
  • 📅 持仓页默认日期本地化：手工录入表单默认日期改用本地时间（getFullYear/Month/Date），修复 UTC-N 时区用户在当天晚间出现日期偏移的问题。
  • 🔁 CSV 导入去重逻辑加固：dedup hash 纳入行序号作为区分因子，确保同字段合法分笔成交不被误折叠；同时在 trade_uid 存在时也持久化 hash，防止混合来源重复写入。

变更

  • POST /api/v1/portfolio/trades 在同账户内 trade_uid 冲突时返回 409。
  • 持仓风险响应新增 sector_concentration 字段（增量扩展），原有 concentration 字段保持不变。
  • 分析 API analyze 接口异步行为契约文档化；前端报告类型联合更新。

测试

  • 新增持仓核心服务测试（FIFO / AVG 部分卖出、同日事件顺序、重复 trade_uid 返回 409、快照 API 契约）。
  • 新增 CSV 导入幂等性、合法分笔成交不误去重、去重边界、风险阈值边界、汇率降级行为测试。
  • 新增 Agent get_portfolio_snapshot 工具调用测试。
  • 新增分析 API 异步契约回归测试。
