#FastGPT v4.17.1

📦 Upgrade-Anleitung

Upgrade-Skript

Dieses Upgrade umfasst die folgenden Automatisierungsskripte

  1. Füllen Sie den Snapshot der Anwendungsressourcenberechtigungen auf, bereinigen Sie die alten V1-Anwendungs- und Versionsdaten und überprüfen Sie die offizielle Version der Anwendung. Die Migrationsaufgabe blockiert den Dienststart nicht und die Fortschritts- und Fehleraufzeichnungen können in der Systemaktualisierungsaufgabe angezeigt werden.
  2. Argumentationszuordnung für kompatible Kanäle aktivieren: Aktivieren Sie die map_reasoning_to_reasoning_content: true-Antwortfeldkonvertierung für den vorhandenen AIProxy OpenAI-Protokollkanal, um das Problem der Kompatibilität von Denkinhaltsfeldern von Deep-Thinking-Modellen (wie DeepSeek-R1) zu lösen und die ursprüngliche Konfiguration des Kanals beizubehalten. Kanäle, die mit diesem Element konfiguriert wurden, werden nicht wiederholt aktualisiert und die Migrationsaufgabe blockiert den Dienststart nicht.
  3. Aktualisieren Sie die Tag-Daten der Wissensdatenbank: Migrieren Sie vorhandene Sammlungs-Tags in typisierte Tags und bereinigen Sie doppelte Tag-Definitionen. Die Migrationsaufgabe blockiert den Dienststart nicht.
  4. Einstellungsmarkierung für den Namen des Teammitglieds auffüllen: Die Markierung isSetMemberName für historische Teammitglieder auffüllen; Der Eigentümer wird immer als festgelegt markiert, und Namen von Nicht-Eigentümer-Mitgliedern, die mit dem Login-Benutzernamen identisch sind, werden als ergänzungsbedürftig markiert. Die Migrationsaufgabe blockiert den Dienststart nicht.

Anpassung des Administratorzugangs

Die kommerzielle Versionsverwaltungsschnittstelle wurde in die FastGPT-Hauptanwendung integriert. Nach der Anmeldung kann der Root-Benutzer über das „Administrator“-Portal auf die Systemkonfiguration, die Betriebsverwaltung sowie die Seiten zur Lizenzaktivierung und -verlängerung zugreifen. Die Systemkonfiguration befindet sich unter /admin/settings/*, Systemtools und Systemmodelle befinden sich unter /admin/resources/tool bzw. /admin/resources/model. Der alte Weg wird nicht mehr gepflegt.

Der FastGPT Pro-Dienst muss weiterhin beibehalten werden; Wenn für Pro eine benutzerdefinierte Gesundheitsprüfung konfiguriert ist, passen Sie bitte den Erkennungspfad auf /api/health an.

Highlights

  • Admin routes are a breaking change — Commercial administration is now part of the main app, and old management URLs are removed. Root users should update bookmarks and integrations to /admin/settings/*, /admin/resources/tool, and /admin/resources/model (#7777, #7792, #7805). Keep fastgpt-pro deployed, and point custom Pro health checks to /api/health.

  • Published apps gain permission snapshots — Static resources are authorized against their release-time snapshot, while dynamic resources are checked against the actual runtime user, eliminating permission drift in collaboratively developed apps (#7559). This may expose previously tolerated access mismatches; monitor the non-blocking migration, which also cleans legacy V1 apps and associated versions, chats, and external links.

  • Knowledge bases add opt-in file authorization and typed search — File/folder-level collaborators, inheritance, independent overrides, and ownership transfer arrive in #7750; authorization applies individually to lists, details, and retrieval. The feature defaults off, and disabling it clears all file-level permission configuration. Typed tags now filter workflow and Agent V2 searches (#7660), while Agent V2 citations show the actual retrieved reference content (#7737).

  • Workflow integrations and execution become more predictable — Workflows can now serve as entry points (#7724), and isolated tool runtime state plus restored interactive memory reduce cross-call contamination and lost resume context (#7727). The new hidden off input type preserves parameter definitions, defaults, and validation for third-party APIs without rendering a control or allowing Agent-generated values; singleton JSON objects sent to array variables are also wrapped automatically to prevent loop and parallel failures.

  • Model administration becomes safer and more observable — Admins can change a system model’s model through stable modelId, with associated channel mappings synchronized automatically (#7808). Optional scheduled probes provide 48-hour health graphs and state-change Webhooks, while new OpenAPI endpoints expose public and member-available model lists and batch model details through API-Key authentication; app dashboards also report token consumption (#7775).

  • SSO and security controls tighten — Third-party password changes now share one authorization, verification, and update flow (#7368), and administrators can prohibit platform-password login or password changes within an SSO namespace; review this policy carefully because it removes that local authentication path.
