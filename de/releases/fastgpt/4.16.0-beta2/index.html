#FastGPT v4.16.0-beta2

📦 Upgrade-Anleitung

1. Bereinigen Sie die Konfiguration des historischen Systemmodells

Ab dieser Version wird beim Initialisieren und Speichern von Systemmodellen ein striktes Schema verwendet. Numerische Zeichenfolgen, Preisverläufe in Zeichenfolgenform oder fehlende Felder, die in früheren Versionen gespeichert wurden, können dazu führen, dass die Erstüberprüfung fehlschlägt. Führen Sie nach dem Upgrade zunächst einen Probelauf durch, um die zu verarbeitende Modellkonfiguration anzuzeigen. Durch den Trockenlauf werden weder die Daten geändert noch der Cache aktualisiert:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Nachdem Sie sichergestellt haben, dass in invalidSamples keine Daten vorhanden sind, die eine manuelle Verarbeitung erfordern, führen Sie eine formelle Bereinigung durch:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Die Reinigung wandelt zulässige numerische Zeichenfolgen in Zahlen um, wandelt priceTiers als Zeichenfolge in ein Array um und entfernt illegale optionale Zahlen. Ungültige oder fehlende erforderliche Nummern verwenden die Systemstandardwerte: maxContext/maxResponse/quoteMaxToken für LLM ist 16000/16000/13000, defaultToken/maxToken für Einbettung ist 500/3000 und der Preis ist 0. functionCall bleibt optional und das fehlende weight in der Einbettung wird durch 0 ersetzt.

Bei der formalen Ausführung werden Daten einheitlich geschrieben und der Systemmodell-Cache sofort aktualisiert. Der Laufzeitcache wird auch dann neu erstellt, wenn keine Datensätze zum Aktualisieren vorhanden sind. Die Schnittstelle kann sicher erneut ausgeführt werden. Beim erneuten Trockenlauf sollte wouldUpdate 0 sein. Datensätze, die das aktuelle vollständige Modellschema nicht bestehen können, werden nicht geschrieben und alle Details werden in invalidSamples zurückgegeben.

🚀 Neue Inhalte

  1. Die Systemkonfiguration der Workflow-Anwendung wird in das unabhängige Konfigurationsfenster in der Symbolleiste auf der linken Seite der Leinwand verschoben, das beim Erstellen einer neuen Workflow-Anwendung automatisch geöffnet wird.
  2. Das Eröffnungsstatement unterstützt die unabhängige Konfiguration mehrerer voreingestellter Fragen und kann per Drag & Drop sortiert werden.

⚙️ Optimierung

  1. Rekonstruieren Sie die Release-Kanalseite, zeigen Sie sie in Gruppen nach nativen Kanälen und Drittanbieterkanälen an und zeigen Sie die konfigurierte Menge jedes Kanals an.
  2. Das Batch-Update des Tool-Marktes unterstützt die Anzeige einiger fehlgeschlagener Elemente, den erneuten Versuch oder die einzelne Deinstallation und verbessert die Anzeige der installierten Versionen und des Update-Status.
  3. Die Obergrenze der Anzahl der Schnellanwendungen auf der Portalseite wird auf 3 angepasst, und historische Konfigurationen, die die Obergrenze überschritten haben, sind kompatibel.
  4. Der PDF-Parser verwendet dynamisches Kantenbeschneiden anstelle des festen Kantenbeschneidens, um ein Ausschneiden des tatsächlichen Inhalts zu vermeiden.

🐛 Fix

  1. Das Problem wurde behoben, dass die dynamischen Parameter der alten Version des Workflow-HTTP-Tools die Standardeingabemethode nicht korrekt wiederherstellten.
  2. Das Problem wurde behoben, dass beim Erstellen einer neuen Workflow-Anwendung die internationalen Ressourcen nicht vorab geladen wurden, was dazu führte, dass die anfängliche Konfigurationskopie abnormal war.
  3. Das Problem wurde behoben, bei dem Workflow-Tool-Parameter möglicherweise wiederholt gerendert wurden.
  4. Das Problem wurde behoben, bei dem Dateivariablen nach der Veröffentlichung der Anwendung keine Dateien hochladen konnten.
  5. Das Problem, dass der Dateiparameter des freigegebenen Workflow-Tools keine Dateien hochladen kann, wurde behoben.
  6. Es wurde ein Problem behoben, bei dem S3-Objektschlüssel und Dateinamen, die Sonderzeichen wie Leerzeichen, %, #, ? und Schrägstriche enthalten, zu abnormalen Uploads, Analysen, Vorschauen oder Downloads führen können.
  7. Beheben Sie das Problem, dass das Standardmodell des Systems vertrauliche Informationen nicht filtert, um zu verhindern, dass die Antwort der Systeminitialisierungsschnittstelle den Schlüssel des Modells API, die Anforderungsadresse und die interne Konfiguration zurückgibt.

🛠️ Codeoptimierung

  1. Das Audit-Log-Archiv wird nicht mehr gelöscht, sondern in das S3-Cold-Archiv übertragen.
  2. Fügen Sie Datenüberprüfung und -bereinigung für die Administratorkonfiguration hinzu.
  3. Kündigen Sie die Konto-/*Seiten-SSR.

Englisches Original / English original

FastGPT v4.16.0-beta2

Highlights

  • Mandatory system-model data migration — Model initialization and saves now enforce a strict schema, so legacy numeric strings, serialized priceTiers, and missing required fields can block startup. Run POST /api/admin/dataClean/cleanSystemModelConfigs with {"dryRun":true}, resolve any invalidSamples, then run it with {"dryRun":false}; the operation is idempotent and rebuilds the system-model cache even when no records change. Missing required numbers fall back to documented defaults, including LLM maxContext/maxResponse/quoteMaxToken of 16000/16000/13000, Embedding defaultToken/maxToken of 500/3000, and price 0.

  • Security hardening removes credential exposure — Default models are now sanitized in system-initialization responses, preventing model API keys, request URLs, and internal configuration from leaking through that endpoint. Integrations that previously consumed those fields from initialization data must obtain credentials through an authorized configuration path instead (#7519). S3 key handling also now safely supports spaces and characters such as %, #, ?, and /, while preserving deletion of legacy keys rejected by current validation (#7468, #7509).

  • Workflow configuration and file handling are more reliable — Workflow system settings move to a dedicated left-toolbar panel that opens automatically for new apps (#7454). File uploads are fixed for published apps, shared workflow tools, and node debugging; external variables are consistently exposed as workflow inputs while explicit input modes are preserved (#7472, #7504, #7506, #7510). This removes several environment-specific upload failures and prevents inherited or duplicated tool-parameter rendering from disrupting workflow configuration.

  • Release operations change materially — Tool Marketplace batch updates can now show partial failures and retry or unload individual plugins instead of requiring an all-or-nothing recovery path (#7444). Audit logs are no longer deleted: they are archived to S3, so deployments need archive storage and permissions configured, and retention/recovery procedures should account for cold-stored records. Publish-channel UI now separates native and third-party channels and reports configured counts (#7456).

  • Model execution and deployment compatibility fixes — Responses ending with reasoning-only tool_calls are no longer misclassified as empty, avoiding dropped tool-call output in agent workflows (#7517). Zod contracts are aligned with runtime data, ESM imports and documentation builds receive compatibility fixes, and OpenSandbox adopts Cilium isolation plus filesystem-based stream handling (#7499, #7500, #7514). Operators should review sandbox networking prerequisites, and note that Helm charts and their release workflow have moved to fastgpt-pro (#7463).

Breaking changes: strict model validation requires the documented cleanup; audit logs now archive to S3 instead of being deleted; Helm distribution moves to fastgpt-pro.

📦 升级指南

1. 清洗历史系统模型配置

本版本开始在系统模型初始化及保存时使用严格 Schema。此前版本保存的数字字符串、字符串形式的价格梯度或缺失字段可能导致初始化校验失败。升级后请先执行 dry-run，查看需要处理的模型配置；dry-run 不会修改数据或刷新缓存：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认 invalidSamples 中没有需要人工处理的数据后，执行正式清洗：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

清洗会将合法数字字符串转换为 number、将字符串形式的 priceTiers 转换为数组，并删除非法的可选数字。非法或缺失的必填数字使用系统默认值：LLM 的 maxContext/maxResponse/quoteMaxToken 分别为 16000/16000/13000，Embedding 的 defaultToken/maxToken 分别为 500/3000，价格为 0。functionCall 保持可选，Embedding 缺失的 weight 补为 0。

正式执行会统一写入数据并立即刷新系统模型缓存；即使没有记录需要更新，也会重新构建运行时缓存。接口可安全重复执行；再次 dry-run 时，wouldUpdate 应为 0。无法通过当前完整模型 Schema 的记录不会写入，详情会全部返回在 invalidSamples 中。

🚀 新增内容

  1. 工作流应用的系统配置移至画布左侧工具栏中的独立配置面板，新建工作流应用时会自动打开。
  2. 开场白支持独立配置多个预设问题，并可拖拽排序。

⚙️ 优化

  1. 重构发布渠道页面，按原生渠道和第三方渠道分组展示，并显示各渠道已配置数量。
  2. 工具市场批量更新支持展示部分失败项、单独重试或卸载，并完善已安装版本和更新状态的展示。
  3. 门户页快捷应用数量上限调整为 3 个，并兼容已超出上限的历史配置。
  4. PDF 解析器动态边缘裁剪，而不是固定边缘裁剪，避免裁剪掉真实内容。

🐛 修复

  1. 修复旧版工作流 HTTP 工具的动态参数未正确恢复默认输入方式的问题。
  2. 修复新建工作流应用时，国际化资源未预加载导致初始配置文案异常的问题。
  3. 修复工作流工具参数可能被重复渲染的问题。
  4. 修复应用发布后，文件变量无法上传文件的问题。
  5. 修复共享工作流工具的文件参数无法上传文件的问题。
  6. 修复 S3 对象键和文件名包含空格、%、#、?、斜杠等特殊字符时，可能导致上传、解析、预览或下载异常的问题。
  7. 修复系统默认模型未进行敏感信息过滤的问题，避免系统初始化接口响应返回模型 API Key、请求地址及内部配置。

🛠️ 代码优化

  1. 审计日志归档，不再删除，改成转存到 S3 冷归档。
  2. 增加对 admin 配置的数据校验和清洗。
  3. 取消 account/* 页面 SSR。
