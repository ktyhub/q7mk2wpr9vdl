#FastGPT v4.16.0

📦 Upgrade-Anleitung

1. Aktualisieren Sie die Umgebungsvariable Agent-sandbox-proxy (optional)

4.16.0 muss sich für den Proxy-Zugriff auf statische Ressourcen auf einen Proxy verlassen. Wenn das Gateway ws und http auf demselben Port unterstützt, können Sie nur einen Port öffnen. Wenn dies nicht unterstützt wird, können Sie den HTTP-Zugriffsport festlegen, indem Sie PREVIEW_PORT festlegen.

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

Die Zugangsadresse beginnt mit http:// oder https://. Bei der Bereitstellung mit einem einzelnen Port kann es auf denselben Domänennamen und Port wie AGENT_SANDBOX_PROXY_URL verweisen, die Protokolle verwenden jedoch HTTP(S) bzw. WebSocket(S). Es wird dringend empfohlen, dass der konfigurierte Domänenname und die FastGPT-Hauptseite unterschiedliche Ursprünge verwenden. Durch die Same-Origin-Bereitstellung können diese Skripte die Same-Origin-Sicherheitsgrenze der Haupt-Site betreten und möglicherweise auf die Anmeldeinformationen oder Schnittstellen der Haupt-Site zugreifen. Das System erzwingt derzeit keine Überprüfung des Ursprungs auf Isolierung.

Sie können überprüfen, ob es zugänglich ist, indem Sie Folgendes besuchen: https://{{host}}/health.

2. Aktualisieren Sie die Umgebungsvariable fastgpt (muss aktualisiert werden, wenn die Sandbox aktiviert ist)

Variablen werden in fastgpt-app und fastgpt-pro gleichzeitig geändert.

# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. Veraltete Sandbox-Umgebungsvariablen

AGENT_SANDBOX_DISK_MB, E2B-bezogene Variablen.

  1. Neue optionale Sandbox-Konfigurationsvariablen

| Variable | Standardwert | Beschreibung | | ---------------------------------------- | ------ | ----------------------------------------------------------------------------------- | | AGENT_SANDBOX_CPU_COUNT | 1 | Agent Sandbox CPU-Kernlimit für eine einzelne Instanz. | | AGENT_SANDBOX_MEMORY_MIB | 2048 | Speicherlimit für eine einzelne Instanz der Agent-Sandbox, Einheit MiB. | | AGENT_SANDBOX_STORAGE_SIZE_GI | 1 | Speicherkapazität der Agent-Sandbox, in Gi; Wird für das Sealos Devbox-Speicherlimit und zum Erstellen neuer PVCs im OpenSandbox Kubernetes-Modus verwendet. | | AGENT_SANDBOX_SUSPEND_MINUTES | 60 | Gibt an, wie lange die laufende Sandbox nach Inaktivität automatisch angehalten wird (in Minuten). | | AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS | 7 | Die angehaltene Sandbox wird nach Ablauf der inaktiven Zeit (in Tagen) automatisch archiviert. |

Der E2B-Sandbox-Anbieter wurde entfernt. Die Umgebung, in der E2B zuvor konfiguriert wurde, muss auf opensandbox oder sealosdevbox umgestellt und AGENT_SANDBOX_E2B_API_KEY gelöscht werden.

Die Vorschauprotokolle von FastGPT, fastgpt-agent-sandbox-proxy und fastgpt-agent-sandbox wurden gleichzeitig geändert. Diese Version des unterstützenden Images muss verwendet werden, wenn Agent Sandbox aktiviert wird. Eine gemischte Bereitstellung alter und neuer Versionen wird nicht unterstützt.

4. Bereinigen Sie die Konfiguration des historischen Systemmodells

Ab dieser Version wird beim Initialisieren und Speichern von Systemmodellen ein striktes Schema verwendet. Numerische Zeichenfolgen, Preisverläufe in Zeichenfolgenform oder fehlende Felder, die in früheren Versionen gespeichert wurden, können dazu führen, dass die Erstüberprüfung fehlschlägt. Führen Sie nach dem Upgrade zunächst einen Probelauf durch, um die zu verarbeitende Modellkonfiguration anzuzeigen. Durch den Trockenlauf werden weder die Daten geändert noch der Cache aktualisiert:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Nachdem Sie sichergestellt haben, dass in invalidSamples keine Daten vorhanden sind, die eine manuelle Verarbeitung erfordern, führen Sie eine formelle Bereinigung durch:

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Die Reinigung wandelt zulässige numerische Zeichenfolgen in Zahlen um, wandelt die Zeichenfolgenform priceTiers in ein Array um und entfernt illegale optionale Zahlen. Ungültige oder fehlende erforderliche Nummern verwenden die Systemstandardwerte: maxContext/maxResponse/quoteMaxToken für LLM ist 16000/16000/13000, defaultToken/maxToken für Einbettung ist 500/3000 und der Preis ist 0. functionCall bleibt optional und das fehlende weight in der Einbettung wird durch 0 ersetzt.

Bei der formalen Ausführung werden Daten einheitlich geschrieben und der Systemmodell-Cache sofort aktualisiert. Der Laufzeitcache wird auch dann neu erstellt, wenn keine Datensätze zum Aktualisieren vorhanden sind. Die Schnittstelle kann sicher erneut ausgeführt werden. Beim erneuten Trockenlauf sollte wouldUpdate 0 sein. Datensätze, die das aktuelle vollständige Modellschema nicht bestehen können, werden nicht geschrieben und alle Details werden in invalidSamples zurückgegeben.

5. HTTP-Tool-Daten migrieren

Diese Version ändert die Array-Parameter des HTTP-Tools im manuellen Modus auf das Standardschema JSON. Umgebungen, die vor dem Upgrade manuelle HTTP-Tools erstellt haben, müssen diese Migration durchführen; HTTP-Tools im OpenAPI-Modus müssen nicht migriert werden und das Skript wird automatisch übersprungen.

Führen Sie zunächst einen Probelauf durch, um die ausstehenden Daten in der aktuellen Anwendung und in historischen Versionen anzuzeigen. Der Trockenlauf verändert die Daten nicht:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Führen Sie nach Bestätigung des Ergebnisses die offizielle Migration durch:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Das Skript filtert zunächst Anwendungen nach HTTP-Tooltyp und migriert dann die entsprechenden historischen Versionen basierend auf appId dieser Anwendungen. Es werden nur manuelle Modi verarbeitet, die für apiSchemaStr nicht vorhanden sind, andere Anwendungen und OpenAPI-Modi werden nicht geändert. Die Migration wird stapelweise ausgeführt und kann problemlos wiederholt werden. total.changedDocumentCount im zurückgegebenen Ergebnis gibt die Anzahl der zur Verarbeitung gefundenen Dokumente an. Nach der formellen Ausführung können Sie einen erneuten Probelauf durchführen, um zu bestätigen, dass der Wert 0 ist.

6. Agent-Sandbox-Daten migrieren (langsamer)

Diese Version passt die Agent-Sandbox von App Chat von „eine Instanz pro Konversation“ auf „eine Instanz, die von derselben App und demselben Benutzer geteilt wird“ an. Die Dateien verschiedener Konversationen werden weiterhin jeweils im Verzeichnis sessions/<chatId> gespeichert, und die veröffentlichten Skills werden im freigegebenen Verzeichnis projects gespeichert.

Wenn die Agent-Sandbox zuvor aktiviert war, muss die Migration des Legacy-Workspace in der folgenden Reihenfolge abgeschlossen werden. Umgebungen, in denen Agent Sandbox nicht aktiviert ist, können diesen Abschnitt überspringen.

Führen Sie zunächst einen Probelauf durch, um die ausstehende Anzahl der Feldnormalisierungen in der Beta6-Sandbox und die Bereinigung des alten Skill-Debug-Chats anzuzeigen. Der Trockenlauf erstellt keine Ressourcen, greift nicht auf den Objektspeicher zu und ändert keine Daten:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Führen Sie die offizielle Migration durch, nachdem Sie die Probelaufergebnisse angezeigt haben. Bei der offiziellen Migration wird zunächst die Beta6-Normalisierung durchgeführt und die Workspace-Archivierung in derselben Anfrage erst dann fortgesetzt, wenn die verbleibende ausstehende Anzahl Null erreicht:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Wenn failures nur Sandbox source is missing or deleted enthält und Sie bestätigt haben, dass die entsprechende App oder der entsprechende Skill nicht mehr vorhanden ist, können Sie diese verbleibenden Sandboxen explizit überspringen:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError Der Standardwert ist false, wobei die strikte Migration beibehalten wird, wenn es weggelassen wird. Dieser Schalter überspringt nur die gesamte Gruppe, deren Quelle fehlt oder vorläufig gelöscht wurde, und archiviert, löscht oder migriert die darin enthaltene Sandbox nicht. Sprungdetails werden über skippedCount und skipped zurückgegeben. Andere Fehler wie Archivierung, Objektspeicherung, Anbieter und Parallelitätskontrolle können weiterhin Migrationen blockieren.

Bei der Migration wird zunächst die vollständige Vorlogik von V4.15.0-beta6 ausgeführt: Vervollständigen Sie den sourceType/sourceId der alten Sandbox, bereinigen Sie die Legacy-Felder, löschen Sie die verwaisten Ressourcen, die nicht zugeordnet werden können, und bereinigen Sie die alten Skill Debug Chat-Dreitabellendaten ohne sourceType und die alten Präfixe der privaten und öffentlichen Buckets. Skills mit derselben ID wie die App überspringen die Chat-Bereinigung. Nach erneuter Angabe der beiden Datentypen beträgt die Summe normalization.pendingCount; Wenn die Menge nicht 0 ist, wird sie nicht in das Workspace-Archiv eingetragen. Archivieren Sie nach dem Nullsetzen direkt alle alten Arbeitsbereiche und bereinigen Sie alte Computerressourcen, migrieren Sie dann die Fähigkeiten und aggregieren Sie sie schließlich nach App und Benutzer in einer Sandbox auf Benutzerebene. Solange in der Archivierungsphase ein Fehler auftritt, wird die Installationsphase nicht gestartet. Die neue Sandbox wird nach Abschluss der Workspace-Installation angehalten und bei der ersten Verwendung wie gewohnt gestartet. Skripte können sicher wiederholt werden und abgeschlossene Archivierungen und Migrationen werden nicht erneut ausgeführt; Alte Archive und alte MongoDB-Datensätze bleiben nach Abschluss der Migration als Backups erhalten.

Bitte überprüfen Sie die zurückgegebenen Ergebnisse für normalization.pendingCount, normalizationBlocked, failedCount, failures, skippedCount und skipped. Nur wenn normalization.pendingCount und failedCount beide 0 sind und normalizationBlocked false ist, bedeutet dies, dass alle nicht übersprungenen Sandbox-Migrationen abgeschlossen sind; Ältere Datensätze in skipped bleiben erhalten und werden nicht migriert.

🚀 Neue Inhalte

  1. Die Agent-Sandbox wird in eine Instanz auf App-Benutzerebene geändert. Mehrere Konversationen derselben App und desselben Benutzers verwenden die Sandbox wieder und isolieren jede Konversationsdatei über ein unabhängiges Sitzungsverzeichnis.
  2. Sandbox-HTML und -Dateien unterstützen die direkte Vorschau über kurzfristige schreibgeschützte Links und müssen zur Vorschau nicht mehr wiederholt in den Objektspeicher hochgeladen werden.
  3. App Workflow archiviert und stellt den Arbeitsbereich automatisch wieder her, wenn sich der Sandbox-Anbieter oder das Laufzeit-Image ändert, und der Upgrade-Prozess wird während der aktuellen Ausführung stillschweigend abgeschlossen.
  4. Der Workflow-Tool-Knoten unterstützt die automatische Generierung spezifizierter Eingabeparameter durch den Agenten und behält vorhandene Konfigurationen wie feste Werte, Referenzen und Benutzereingaben bei.
  5. Wenn ChatAgent ein Tool auswählt, unterstützt es die manuelle Angabe, ob Parameter für KI generiert werden sollen.
  6. Wissensdatenbankdaten unterstützen die Anpassung von metadata, und JSON-Metadaten können über API-, CSV- oder Excel-Vorlagen importiert werden; Dieses Feld wird in Suchergebnissen und Backup-Exporten beibehalten. Sowohl der Vorlagenimport als auch der Backup-Import unterstützen .csv- und .xlsx-Dateien unter Verwendung der Header q, a, index und metadata. q, a und metadata haben jeweils eine Spalte, und index kann mehrere Spalten in beliebiger Reihenfolge haben. Excel-Dateien unterstützen nur ein einzelnes Arbeitsblatt und können keine verbundenen Zellen enthalten. CSV- oder Excel-Dateien, die nicht korrekt analysiert werden können, führen zu einer Dateiformatausnahme.
  7. Laden Sie große Dateien in Blöcken hoch.
  8. Wenn der Administrator den System-Tool-Schlüssel konfiguriert, wird er verschlüsselt (kompatibel mit dem konfigurierten Schlüssel).
  9. Leere Statusführung in der Fertigkeitsliste und Verknüpfung bei der Auswahl von Fertigkeiten.
  10. Die Systemkonfiguration der Workflow-Anwendung wird in das unabhängige Konfigurationsfenster in der Symbolleiste auf der linken Seite der Leinwand verschoben, das beim Erstellen einer neuen Workflow-Anwendung automatisch geöffnet wird.
  11. Das Eröffnungsstatement unterstützt die unabhängige Konfiguration mehrerer voreingestellter Fragen und kann per Drag & Drop sortiert werden.

⚙️ Optimierung

  1. Rekonstruieren Sie den Lebenszyklus und den Migrationsprozess der Agent-Sandbox. Erstellen, Anhalten, Archivieren, Wiederherstellen, Löschen und Anbieterwechsel unterstützen Parallelitätsschutz, Breakpoint-Wiederaufnahme und idempotente Wiederholung.
  2. Wenn Agent Sandbox nicht verfügbar ist oder vom aktuellen Teampaket nicht unterstützt wird, deaktiviert App Chat automatisch die Sandbox-Funktion und andere Modelle, Tools, Wissensdatenbanken und Workflow-Knoten können weiterhin ausgeführt werden.
  3. Persistente Volumes können nach dem Stoppen von OpenSandbox beibehalten und bei nachfolgenden Ausführungen wiederverwendet werden; Pausen- und Archivschwellenwerte unterstützen die Konfiguration über Umgebungsvariablen.
  4. Die App und der Skill haben einen einheitlichen Runtime-Image-Upgrade-Status und die Skill-Bearbeitungsseite kann kontinuierlich die Upgrade-Ergebnisse abfragen.
  5. Erstellen Sie automatisch übergeordnete Verzeichnisse, bevor Sie Sandbox-Dateien schreiben, um Fehler beim Schreiben verschachtelter Pfade zu vermeiden.
  6. Optimieren Sie Kompatibilitätsprobleme wie alte Workflow-Daten und Werkzeugparameter.
  7. Agent Ask-Benutzeroberfläche.
  8. Rekonstruieren Sie die Release-Kanalseite, zeigen Sie sie in Gruppen nach nativen Kanälen und Drittanbieterkanälen an und zeigen Sie die konfigurierte Menge jedes Kanals an.
  9. Das Batch-Update des Tool-Marktes unterstützt die Anzeige einiger fehlgeschlagener Elemente, den erneuten Versuch oder die einzelne Deinstallation und verbessert die Anzeige der installierten Versionen und des Update-Status.
  10. Die Obergrenze der Anzahl der Schnellanwendungen auf der Portalseite wird auf 3 angepasst, und historische Konfigurationen, die die Obergrenze überschritten haben, sind kompatibel.
  11. Der PDF-Parser verwendet dynamisches Kantenbeschneiden anstelle des festen Kantenbeschneidens, um ein Ausschneiden des tatsächlichen Inhalts zu vermeiden.

🐛 Fix

  1. Das Problem wurde behoben, bei dem OpenSandbox-Ressourcen nach dem Stoppen nicht korrekt freigegeben oder wiederverwendet wurden.
  2. Beheben Sie Probleme mit Statuskonflikten und doppelten Vorgängen während der Erstellung, Wiederherstellung oder Laufzeitaktualisierung der Agent-Sandbox.
  3. Das Problem wurde behoben, bei dem Sandbox keine Dateien in verschachtelte Verzeichnisse schreiben konnte, weil das übergeordnete Verzeichnis nicht existierte.
  4. Das Problem wurde behoben, bei dem die Zahleneingabe nach dem Wechsel zwischen Agentengenerierung und manueller Eingabe zu einem normalen Textfeld wurde.
  5. Das Problem wurde behoben, bei dem die Zeichenfolgentexteingabe fälschlicherweise als Dropdown-Auswahl gerendert wurde.
  6. Das Problem wurde behoben, bei dem der JSON-Editor fälschlicherweise zur Workflow-Tool-Konfiguration hinzugefügt wurde.
  7. Das Problem wurde behoben, bei dem Tool-Ausführungsfehler in der Agent-/Workflow-Tool-Schnittstelle falsch angezeigt wurden.
  8. Das Anzeigeproblem deinstallierter Tools in der System-Tool-Liste wurde behoben.
  9. Korrigieren Sie die Standardlogik zur Versionsauswahl von Agent/Agent V2, sodass standardmäßig die neueste Version ausgewählt wird.
  10. Wenn in der S3-Datei Leerzeichen vorhanden sind, tritt beim Parsen der Bilder in der Datei aufgrund einer Schlüsselausnahme ein 404-Fehler auf.
  11. MCP SSE-Modus, Header wird wiederholt.
  12. Der Schlüssel des Agent V2-Systemtools ist nicht verschlüsselt.
  13. Das Problem wurde behoben, dass die dynamischen Parameter der alten Version des Workflow-HTTP-Tools die Standardeingabemethode nicht korrekt wiederherstellten.
  14. Das Problem wurde behoben, bei dem internationalisierte Ressourcen beim Erstellen einer neuen Workflow-Anwendung nicht vorab geladen wurden, was dazu führte, dass die anfängliche Konfigurationskopie abnormal war.
  15. Es wurde ein Problem behoben, bei dem Workflow-Tool-Parameter möglicherweise wiederholt gerendert wurden.
  16. Das Problem wurde behoben, bei dem Dateivariablen nach der Veröffentlichung der Anwendung keine Dateien hochladen konnten.
  17. Das Problem, dass der Dateiparameter des freigegebenen Workflow-Tools keine Dateien hochladen kann, wurde behoben.
  18. Es wurde ein Problem behoben, bei dem S3-Objektschlüssel und Dateinamen, die Sonderzeichen wie Leerzeichen, %, #, ?, Schrägstriche usw. enthalten, zu abnormalen Uploads, Analysen, Vorschauen oder Downloads führen können.
  19. Das Problem wurde behoben, dass das Standardmodell des Systems vertrauliche Informationen nicht filtert und verhindert, dass die Antwort der Systeminitialisierungsschnittstelle den Schlüssel des Modells API, die Anforderungsadresse und die interne Konfiguration zurückgibt.

🛠️ Codeoptimierung

  1. Der Sandbox-Adapter wird nach Lebenszyklus, Dateisystem, Befehlsausführung und Provider-Vertrag neu aufgeteilt und der E2B-Adapter wird entfernt.
  2. Agent Sandbox Proxy und IDE Agent fügen Vorschau der direkten Workspace-Verbindung, Bereichsanforderung, Pfad-Escape-Schutz und Sitzungsauthentifizierung hinzu.
  3. Optimierung des Workflow-Schemas, einheitlicher Tool-Aufruf und Formular-Rendering.
  4. Erweitertes Tool JSON Schema zur Unterstützung weiterer Datentypen.
  5. Zeitüberschreitung beim Lesen einheitlicher Servicedateien.
  6. Optimieren Sie das Problem der Multiprozessberechtigungssicherheit von Systemtools.
  7. Anmelde- und Authentifizierungscode umgestalten.
  8. Rekonstruieren Sie das Strombegrenzungsmodul.
  9. Das Audit-Log-Archiv wird nicht mehr gelöscht, sondern in das S3-Cold-Archiv übertragen.
  10. Datenüberprüfung und -bereinigung für die Administratorkonfiguration hinzugefügt.
  11. Konto/Seite SSR kündigen.
  12. CICD-Bildverpackung.

Highlights

  • Agent Sandbox is now shared per App/user — Multiple chats in the same App now reuse one Sandbox for the same user instead of creating one per conversation. Files remain isolated under sessions/<chatId>, while published Skills share projects. Short-lived read-only preview links eliminate duplicate object-storage uploads, and provider/runtime-image changes automatically archive and restore Workspaces. Sandbox failures or unsupported plans now disable only Sandbox, leaving models, tools, knowledge bases, and Workflow nodes operational.

  • Breaking: Sandbox deployment and data migration — The E2B provider is removed: switch to opensandbox or sealosdevbox, delete AGENT_SANDBOX_E2B_API_KEY, and retire AGENT_SANDBOX_DISK_MB and other E2B variables. In both fastgpt-app and fastgpt-pro, configure AGENT_SANDBOX_PREVIEW_PROXY_URL for HTTP(S), while AGENT_SANDBOX_PROXY_URL uses WebSocket(S); OpenSandbox also requires VM_VOLUME_NAME_PREFIX. Configure proxy PREVIEW_PORT if HTTP and WebSocket cannot share a port, and preferably use a separate origin because isolation is not enforced. Use matching fastgpt-app/fastgpt-pro v4.16.0 and agent-sandbox-proxy/agent-sandbox-volumn v0.3.0 images—mixed preview-protocol versions are unsupported. Any environment that previously enabled Sandbox must run /api/admin/4160/initUserSandbox with dryRun:true, then dryRun:false, checking normalization.pendingCount, failedCount, and normalizationBlocked. Use skipError:true only after confirming failures are missing/deleted sources; skipped Legacy records remain unmigrated.

  • Breaking: strict system-model configuration validation — Legacy numeric strings, stringified priceTiers, and missing fields can now fail initialization or save validation. Run /api/admin/dataClean/cleanSystemModelConfigs with dryRun:true, review invalidSamples, then execute with dryRun:false. Cleaning converts valid numeric strings to numbers and priceTiers strings to arrays, removes invalid optional numerics, and applies defaults: LLM maxContext/maxResponse/quoteMaxToken become 16000/16000/13000, Embedding defaultToken/maxToken become 500/3000, and price becomes 0. The formal run rebuilds the model cache even when nothing changes; records that still fail the complete Schema are not written.

  • Breaking: manual HTTP tool schemas require migration — Manual-mode array parameters now use standard JSON Schema. Environments with manually created HTTP tools must run /api/admin/4160/initHttpToolSchema with dryRun:true, then dryRun:false. The retryable migration also processes matching historical app versions; a follow-up dry-run should show total.changedDocumentCount as 0. Only manual tools lacking apiSchemaStr are changed—OpenAPI-mode tools and other applications are skipped.

  • Upgrade value and who can skip — This is a substantive release, not a re-tag. Upgrade for shared Sandboxes, dataset metadata with .csv/.xlsx template and backup imports, chunked large-file uploads, AI-generated workflow/tool parameters, and fixes for S3/DOCX filenames containing spaces or special characters. Security-sensitive deployments should also upgrade because system-tool secrets are encrypted and system-model initialization no longer exposes API keys, request URLs, or internal configuration. Sandbox-free installations can skip initUserSandbox, and OpenAPI-only HTTP-tool users can skip initHttpToolSchema; after a clean model-config dry-run, users who need none of these features or fixes can defer upgrading.

4. 清洗历史系统模型配置

本版本开始在系统模型初始化及保存时使用严格 Schema。此前版本保存的数字字符串、字符串形式的价格梯度或缺失字段可能导致初始化校验失败。升级后请先执行 dry-run，查看需要处理的模型配置；dry-run 不会修改数据或刷新缓存：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认 invalidSamples 中没有需要人工处理的数据后，执行正式清洗：

curl -X POST 'https://你的域名/api/admin/dataClean/cleanSystemModelConfigs' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

清洗会将合法数字字符串转换为 number、将字符串形式的 priceTiers 转换为数组，并删除非法的可选数字。非法或缺失的必填数字使用系统默认值：LLM 的 maxContext/maxResponse/quoteMaxToken 分别为 16000/16000/13000，Embedding 的 defaultToken/maxToken 分别为 500/3000，价格为 0。functionCall 保持可选，Embedding 缺失的 weight 补为 0。

正式执行会统一写入数据并立即刷新系统模型缓存；即使没有记录需要更新，也会重新构建运行时缓存。接口可安全重复执行；再次 dry-run 时，wouldUpdate 应为 0。无法通过当前完整模型 Schema 的记录不会写入，详情会全部返回在 invalidSamples 中。

5. 迁移 HTTP 工具数据

本版本将手动模式 HTTP 工具的数组参数改为标准 JSON Schema。升级前创建过手动 HTTP 工具的环境需要执行此迁移；OpenAPI 模式的 HTTP 工具无需迁移，脚本会自动跳过。

先执行 dry-run，查看当前应用及历史版本中的待处理数据。dry-run 不会修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认结果后执行正式迁移：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

脚本会先按 HTTP 工具类型筛选应用，再根据这些应用的 appId 迁移对应的历史版本。仅 apiSchemaStr 不存在的手动模式会被处理，其他应用及 OpenAPI 模式不会修改。迁移按批次执行且可安全重试；返回结果中 total.changedDocumentCount 表示发现的待处理文档数，正式执行后可再次 dry-run，确认该值为 0。

6. 迁移 Agent Sandbox 数据(较慢)

本版本将 App Chat 的 Agent Sandbox 从“每个对话一个实例”调整为“同一 App、同一用户共享一个实例”。不同对话的文件仍分别保存在 sessions/<chatId> 目录中，已发布 Skill 则统一保存在共享的 projects 目录中。

如果此前启用过 Agent Sandbox，必须按以下顺序完成旧 Workspace 迁移。未启用过 Agent Sandbox 的环境可以跳过本节。

先执行 dry-run，查看 beta6 Sandbox 字段归一化和旧 Skill Debug Chat 清理的待处理数。dry-run 不会创建资源、访问对象存储或修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

查看 dry-run 结果后执行正式迁移。正式迁移会先执行 beta6 归一化，并且只在剩余待处理数归零时，才在同一请求中继续 Workspace 归档：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

如果 failures 中仅包含 Sandbox source is missing or deleted，并且已确认对应 App 或 Skill 确实不再存在，可以显式跳过这些残留 Sandbox：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError 默认为 false，省略时保持严格迁移。该开关只跳过 source 已缺失或已软删除的整个分组，不会归档、删除或迁移其中的 Sandbox；跳过明细通过 skippedCount 和 skipped 返回。归档、对象存储、Provider 和并发控制等其他错误仍会阻断迁移。

迁移会先执行 V4.15.0-beta6 的完整前置逻辑：补齐旧 Sandbox 的 sourceType/sourceId、清理遗留字段、删除无法归属的孤立资源，并清理缺失 sourceType 的旧 Skill Debug Chat 三表数据及私有、公开 Bucket 旧前缀。与 App 同 ID 的 Skill 会跳过 Chat 清理。两类数据重新统计后合计为 normalization.pendingCount；数量不为 0 时不会进入 Workspace 归档。归零后直接归档全部旧 Workspace 并清理旧计算资源，再迁移 Skill，最后按 App、用户聚合到用户级 Sandbox。只要归档阶段存在失败，安装阶段就不会开始。新的 Sandbox 会在 Workspace 安装完成后暂停，首次使用时再按正常流程启动。脚本可安全重试，已完成的归档和迁移不会重复执行；迁移完成后会保留旧归档和旧 MongoDB 记录作为备份。

请检查返回结果中的 normalization.pendingCount、normalizationBlocked、failedCount、failures、skippedCount 和 skipped。只有 normalization.pendingCount 和 failedCount 均为 0，且 normalizationBlocked 为 false 时，才表示所有未跳过的 Sandbox 迁移完成；skipped 中的 Legacy 记录会保留且不会迁移。

  1. Agent Sandbox 改为 App 用户级实例，同一 App、同一用户的多个对话复用 Sandbox，并通过独立 session 目录隔离各对话文件。

  3. App Workflow 在 Sandbox Provider 或运行时镜像变化时自动归档并恢复 Workspace，升级过程在当前运行中静默完成。
  4. 工作流工具节点支持将指定输入参数交由 Agent 自动生成，并保留固定值、引用和用户输入等既有配置。
  5. ChatAgent 选择工具时，支持手动指定是否为 AI 生成参数。
  6. 知识库数据支持自定义 metadata，可通过 API、CSV 或 Excel 模板导入 JSON 元数据；检索结果和备份导出会保留该字段。模板导入和备份导入均支持 .csv 和 .xlsx 文件，使用 q、a、index、metadata 表头；q、a、metadata 各一列，index 可多列且顺序任意。Excel 文件仅支持单个工作表且不能包含合并单元格，无法正确解析的 CSV 或 Excel 文件会提示文件格式异常。
  7. 大文件分块上传。
  8. 管理员配置系统工具密钥时，加密（兼容已配置的密钥）。
  9. 技能列表空状态引导，以及选择技能时联动。
  10. 工作流应用的系统配置移至画布左侧工具栏中的独立配置面板，新建工作流应用时会自动打开。
  11. 开场白支持独立配置多个预设问题，并可拖拽排序。

⚙️ 优化

  1. 重构 Agent Sandbox 生命周期和迁移流程，创建、暂停、归档、恢复、删除及 Provider 切换支持并发保护、断点续跑和幂等重试。
  2. Agent Sandbox 不可用或当前团队套餐不支持时，App Chat 自动禁用 Sandbox 能力，其他模型、工具、知识库和 Workflow 节点仍可继续运行。
  3. OpenSandbox 停止后可保留持久卷并在后续运行时复用；暂停和归档阈值支持通过环境变量配置。
  4. App 与 Skill 统一运行时镜像升级状态，Skill 编辑页可持续轮询升级结果。
  5. Sandbox 文件写入前自动创建父目录，避免写入嵌套路径失败。
  6. 优化工作流旧数据、工具参数等兼容问题。
  7. Agent Ask UI。
  8. 重构发布渠道页面，按原生渠道和第三方渠道分组展示，并显示各渠道已配置数量。
  9. 工具市场批量更新支持展示部分失败项、单独重试或卸载，并完善已安装版本和更新状态的展示。
  10. 门户页快捷应用数量上限调整为 3 个，并兼容已超出上限的历史配置。
  11. PDF 解析器动态边缘裁剪，而不是固定边缘裁剪，避免裁剪掉真实内容。
