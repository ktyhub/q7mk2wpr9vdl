LightRAG v1.5.8rc2

Highlights

  • Query failures are no longer empty answers — Failed queries now return an error instead of a misleading “no context” result (#4478), while aquery_data returns its failure shape when keyword extraction produces nothing (#4419). Reasoning-only completions are neither returned nor cached (#4483), preventing unusable responses from entering the cache. Update fallback logic and monitoring to distinguish retrieval failures from legitimately empty results.

  • Provider timeouts and retries are more predictable — LLM_TIMEOUT now reaches every provider client, including per-role configuration, and embedding/rerank clients receive their respective timeout settings (#4474, #4479). Non-positive timeout values mean “no timeout” (#4098), so use a positive value when a finite deadline is required. Permanent Jina and generic-rerank 4xx errors stop retrying (#4028, #4420), while malformed OpenAI completions and transient Bedrock, LMDeploy, and AGE failures are retried (#4279, #4447, #4458, #4212).

  • Client ownership and async behavior are safer — Caller-supplied OpenAI HTTP clients are no longer closed and retain their configured default headers (#4237, #4152), making connection reuse safe for applications that manage their own clients. Internally created Zhipu clients are closed after calls (#4427), and Qdrant’s vector-upsert flush runs off the event loop (#4446), reducing latency and blocking during concurrent ingestion.

  • Storage deletion now fails visibly — Nano, MongoDB, PostgreSQL, and OpenSearch propagate queue, KV, and document-status deletion failures instead of silently completing partial cleanup (#4424, #4167, #4432, #4169). Custom deletion and recovery workflows should catch and retry these exceptions. Workspace clearing now removes vectors for every embedding model (#4263), and cancelled uploads are cleaned up (#4223), reducing stale-data risks.

  • Document ingestion better preserves Unicode and OOXML structure — UTF-8 BOM contamination is fixed, UTF-16/UTF-32 BOM files are accepted, and HTML/chunk offsets remain Unicode-safe (#4132, #4434, #4438, #4116). DOCX handling now respects on/off values and leading-header repetition while preserving special text nodes, OMML function names, and literal Markdown examples (#4430, #4433, #4239, #4259, #4204); dot-prefixed bundle files and assets also work (#4219, #4440, #4291). These changes improve extraction and citation provenance, with DOCX body parsing also reported 7.7% faster (#4298).

  • Compatibility — No breaking changes are declared; nevertheless, audit bcrypt-limited passwords (#4489), invalid rerank/chunk settings (#4487, #4488), timeout semantics, and exception handling before upgrading.
