  • Komprimierung (Cache-aware): Fügen Sie einen Opt-in-, standardmäßig deaktivierten, nutzungsabhängigen Präfix-Freeze hinzu (H5). OmniRoute v3.8.43

Highlights

  • Compression gains an opt-in engine suite (all default-off) — v3.8.43 adds five gated compression features: an llm prose condenser whose default backend is a no-op pass-through until you wire one via setLlmCompressorBackend() (fails open on every error), a lossy read-lifecycle engine that collapses superseded file-Read tool results, a per-engine process-local circuit breaker (COMPRESSION_PIPELINE_BREAKER_ENABLED), a graded CCR retrieval ramp (retrievalRampFactor, default 2; set 1 for the old binary cliff), and usage-observed prefix freezing (COMPRESSION_PREFIX_FREEZE_ENABLED) that preserves recurring system prompts to keep prompt-cache hits. None join the default pipeline, so upgrading is byte-identical until enabled — watch that read-lifecycle is semantic/lossy and that breaker default-off still propagates a throwing engine (enable TV1 for per-request bail-out).

  • Usage output changes: percentages replace USD, flat-rate providers read $0 — @@om-usage and /api/usage now report personal-key quotas as remaining percentages (USD no longer appears in command output), provider quota is scaled by the configured cutoff so the protected reserve reads 0% left, and a management-auth-gated provider USD drilldown returns (/api/usage/provider-window-costs, ProviderUsdCostModal, #5863). Flat-rate/subscription providers (ChatGPT Web, grok-web, the Coding plans, etc.) show $0 in analytics instead of inflated per-token estimates (#5552) while budget/quota/routing still estimate; codex/cx, byteplus, minimax-cn are deliberately excluded. Watch for: anything parsing USD out of @@om-usage will break, and observed same-resetAt quota resets now override stale recorded weekly events.

  • Live dashboard WebSocket can sit behind a reverse proxy / Cloudflare Tunnel (#5877) — set NEXT_PUBLIC_LIVE_WS_PUBLIC_URL (e.g. wss://ws.my-ai.com/live-ws); it's inlined at build time and, for prebuilt Docker/npm images, read at runtime through the /api/v1/ws?handshake=1 handshake, which only accepts ws:///wss:// (other values resolve to null). useLiveDashboard resolves the URL from that handshake before connecting, falling back to the old ws(s)://hostname:20129 default. Migration is config-only (no rebuild for prebuilt images), but if the handshake isn't reachable at the public URL clients silently fall back to the direct host:port.

  • CLI profile auto-sync for Codex and Claude Code (opt-in) — model-catalog changes can regenerate tool profiles from the live catalog: Codex (~/.codex/*.config.toml) and now Claude Code (~/.claude/profiles/<name>/settings.json, new claudeProfileAutoSync.ts). Both are off by default, gated by OMNIROUTE_AUTO_SYNC_CODEX_PROFILES / OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES (DB/dashboard override > env > false) and the CLI_ALLOW_CONFIG_WRITES write-guard, and never touch the active/default config — so enabling them won't clobber your live CLI setup. The toggle moves to the CLI Code dashboard (migrated from the providers dashboard in #5778).

  • Typed memory decay (TV6, opt-in) — targets episodic-noise accumulation: migration 111_memory_typed_decay adds always-on, non-destructive access_count/last_accessed_at telemetry, while the sweep itself is off by default (MEMORY_TYPED_DECAY_ENABLED=false). Only episodic decays (30d TTL, env-tunable); factual/procedural/semantic are immune, any memory accessed ≥3 times earns immunity, and the clock re-bases on last access. Deletions reuse deleteMemory so SQLite/sqlite-vec/Qdrant stay in sync and fail open; periodic sweeps need a second flag (MEMORY_TYPED_DECAY_SWEEP_INTERVAL>0). With the flag off nothing is deleted — safe to adopt, but expect one schema migration on upgrade.

  • MCP RTK learn/discover tools + request correlation IDs — agents can grow the RTK filter catalog without leaving MCP via two new read-only tools, omniroute_rtk_discover (surfaces candidate noise patterns and a suggested filter) and omniroute_rtk_learn (lists captured command samples and resolves a command to its filter id), both scope read:compression and audit-logged. Separately, requests now carry a correlation ID threaded through logs for end-to-end tracing (#5834). Small additions, but useful for debugging the compression pipeline or running agents against it.

No breaking changes.

The boot-time call-log cleanup (cleanupExpiredLogs → rotateCallLogs) ran two unbounded SELECT … FROM call_logs … .all() queries — listReferencedArtifacts (every artifact path) and deleteCallLogsBefore (every id before the retention cutoff). node:sqlite's StatementSync.all() materializes the entire result set as JS objects at once, so on a large table the V8 heap blew up and the process crashed before binding (FATAL ERROR: … heap out of memory, native frame node::sqlite::StatementSync::All). Both queries now page through call_logs in bounded 5 000-row chunks (new src/lib/usage/callLogsBoundedQueries.ts), keeping peak memory flat regardless of table size — no more manual --max-old-space-size bump required. Regression guard: tests/unit/call-log-oom-unbounded-5618.test.ts. (#5618)
