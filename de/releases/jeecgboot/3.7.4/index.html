Veröffentlichungszeit: v3.7.4 | 07.04.2025

Upgrade-Protokoll

Die Hintergrundarchitektur wurde einer umfassenden Aktualisierung unterzogen; das Standard-JDK wurde auf 17 geändert; Das Online-Low-Code-Modul wurde speziell aktualisiert. Knife4j hat das SpringDoc von openapi3 aktualisiert ([Upgrade ist nicht kompatibel, überprüfen Sie die Anmerkungsänderungen](https://help.jeecg.com/java/upgrade/springboot3#knife4j%E5%8D%87%E7%BA%A7%E8%AF%B4%E6%98%8E „Dieses Upgrade ist nicht kompatibel, Anmerkungsänderungsmethode“));

JeecgBoot v3.7.4

Highlights

  • JDK 17 default + Undertow swap — The runtime baseline moves to JDK 17 (JDK 8 and 21 still supported), and the embedded servlet container changes from Tomcat to Undertow. Audit any Tomcat-specific filters, server.* config, or web.xml behavior before deploying, since these silently change at runtime.
  • Knife4j → SpringDoc OpenAPI 3 (breaking) — Explicitly flagged as incompatible: the Swagger annotations change and must be migrated by hand. Any controller or DTO still using the old Knife4j/Swagger 2 annotations will fail to generate docs until updated — this is the main migration cost in the release.
  • Dependency/security refresh — Spring Cloud 2021.0.8 and Alibaba 2021.0.6.2, JimuReport 1.9.5, Shiro 1.13.0 + shiro-redis 3.2.3, Druid 1.2.24, java-jwt 4.5.0, fastjson 2.0.43, and weixin4j 2.0.1. Logback is bumped to 1.2.13 for a vulnerability fix and CVE-2023-6378 is addressed (#7951) — worth prioritizing if you run internet-facing endpoints.
  • JUnit 4 removed — Issue #4939 drops JUnit 4 in favor of JUnit 5 as the default. Existing test suites using JUnit 4 runners/assertions need porting, and the 3.7.3 JDK/MongoDB startup regressions (#7787) plus the xxl-job SQL script mismatch (#7788) are also cleaned up here.
  • Caching, locking, and Redis behavior — @Cacheable gains inline TTL via cacheNames = "...ttl#60"; @JLock auto-renewal is fixed (#7836) and the RepeatSubmitAspect unlock path is hardened (#7722); the ERR unknown command "keys" failure against Redis is resolved, indicating a move away from KEYS — important if you run managed/cluster Redis where KEYS is disabled. Static resources now get a default Cache-Control.
  • Online low-code module hardening — Online form data now supports tenant isolation, non-admin users are blocked from importing DB tables (#7504), and a critical bug that deleted all child-table rows when editing an ERP-style main form (#7190) is fixed. Also resolves dynamic-report column ordering/width (#7880, #7609), JS enhancement event/value bugs, and #7059 button customization — the data-loss fix alone makes this upgrade worthwhile for anyone using online forms.
