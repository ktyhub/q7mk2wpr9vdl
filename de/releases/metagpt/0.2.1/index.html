MetaGPT v0.2.1

Highlights

  • Anthropic Claude as a first-class provider — Native Claude support lands in PR #65, and PR #194 handles the case where you supply ANTHROPIC_API_KEY instead of OPENAI_API_KEY. This is the biggest adoption win for anyone not tied to OpenAI: the same multi-agent workflow can be routed through Claude without rewriting config. Watch out that the two changes shipped separately, so verify which env var your pinned config actually reads before switching, and expect different cost/quality behavior on long-horizon generation.

  • Pluggable vector memory — Qdrant joins FAISS as an ANN backend (PR #207), and a new memory_storage uses ANN similarity to avoid re-executing near-duplicate ideas (PR #70). This matters because it makes long-running agent loops less wasteful and lets you externalize memory to a real vector DB instead of a local index. Note the faiss_store write fix (PR #84) — upgrade before trusting persisted memory if you were on the old store.

  • Web search and the Researcher role — Search expands from a single provider to pluggable duckduckgo_search / googleapi backends (PR #161) plus a Serper API wrapper with its own key field (PR #50), backed by targeted content retrieval and result parsing (PR #69). The new researcher role (PR #161) ties these together to search, summarize, and write reports, so you can build research-first pipelines without bolting search onto the engineer role. Expect a larger config surface: you'll need to choose a provider and set its key.

  • Network resilience and cost accounting — The OpenAI interface gains configurable timeouts and anomaly alerts (PR #112), update_cost/update_usage become fault-tolerant (PR #138), and proxy usage is fixed alongside a revised default-setting check (PR #121). Together these attack the "one flaky request kills the whole run" failure mode — important for unattended pipelines — but the new anomaly alerts mean logging you should wire into monitoring rather than ignore.

  • An executable-code quality loop — A new qa engineer role writes test cases, runs code, and debugs errors (PR #77), paired with a code-review pass and a generation retry mechanism (PR #73), plus a write docstring action supporting Sphinx/Google/NumPy styles (PR #124). The release shifts from "generate plausible code" toward "generate code that runs," but extra review and retry steps mean longer, more expensive runs — tune retry limits for latency-sensitive use.

  • Developer environment and hygiene — GitHub Codespaces support (PR #186) and a custom event-loop policy for Windows (PR #257) widen where MetaGPT runs, while local mmdc installs can skip the Chromium download (PR #83). Requirements/install instructions were corrected (PR #238) and a pre-commit config added (PR #67). One behavioral change to account for: parse_tasks and parse_workspace were fixed (PR #116), so tooling depending on the old (incorrect) parse output will see different results.

No breaking changes were flagged in this release.
