Neue Modelle in dieser Version (siehe Kochbuch für alle unterstützten Modelle): | Modell | Geben Sie | ein PRs | Kochbuch | |---|---|---|---| | Muse Glimmer | Autoregressiv (multimodal) | #34262 | Link | | Praktikant-S2-Mobius | Autoregressiv | #33691 | Link | | SANA-Video | Verbreitung | #32921 | Link | | LingBot-Video-MoE | Verbreitung | #32341 | Link | | LTX-2.5 | Verbreitung | #34471 | Link | | Cosmos3 Edge & Destilliert | Verbreitung | #31590 | Link | | LongCat-Bild | Verbreitung | #23274 | | Plus Kochbuchrezepte für die Qwen3.8-Familie, Ling-3.0, Nemotron 3.5 Lightning, Dots3-Note und DeepSeek-V4-Pro-0813 (#34809). Überlappendes Checkpoint-Staging beim Start: Checkpoint-Seiten werden jetzt aus dem Speicher bereitgestellt, während CUDA-Diagramme erfasst werden. Qwen3-32B auf H100 startet 8.6-11.7 % schneller als seriell mit Prefetch und 2,38x schneller (35,6 s vs. 84,8 s) als die einfache Standardeinstellung. Melden Sie sich mit --startup-weight-load-mode overlap (#32017) an. TP LMHead mit All-to-All: Das Allgather + Scatter des TP LMHead wird zu einem einzigen All-to-All für reine DP-Dp-Aufmerksamkeit. Bei der DeepSeek-V4-Pro B200-Dekodierung sinkt die LMHead-Zeit von 320us auf 169us und der TPOT verbessert sich von 36,97ms auf 35,67ms (#32313). FlashInfer MNNVL für reines Allreduce: Nicht fusionierte Allreduce-Sites verwenden jetzt den FlashInfer MNNVL-Arbeitsbereich wieder, anstatt auf NCCL zurückzugreifen. DeepSeek-V4-Flash TP4-Dekodierung auf Blackwell steigert bis zu +6.9 % bei kleinen Chargen. Automatisch aktiviert für DeepSeek-V3/V3.2/V4; anderswo --enable-flashinfer-pure-allreduce (#30700). NVFP4-Prüfpunkte laufen auf AMD: --quantization quark_mxfp4 dequantisiert ModelOpt- und Quark-NVFP4-Gewichte und requantisiert bei Last auf MXFP4, ohne dass eine Kopie mit voller Genauigkeit gespeichert wird. 97.5-100.2 % GSM8K-Wiederherstellung im Vergleich zur NVFP4-Referenz bei MiniMax-M2.7, GLM-5.1, Kimi-K2.6, Qwen3.5-397B und DeepSeek-R1 (#29328). Kimi K3 optimiert für MI355X: Ein MLA-Verifizierungskernel mit gruppiertem Kopf ersetzt den MHA-förmigen Split-KV-Pfad, der das gemeinsam genutzte Latent einmal pro Kopf erneut liest, für 1.37-1.77x-Durchsatz und 1.45-2.42x ITL bei Parallelität 2-32; Der AITER MLA-Prefill-Kernel akzeptiert jetzt die 12-Kopf-Form von K3 (TTFT bis zu -14.9 %). Eine auf gfx950 abgestimmte Decodierungsstufe 1-Geometrie fügt 46-73 % ITL bei 68k-Eingang hinzu, Opt-in über SGLANG_MLA_DECODE_TUNE=1. GSM8K hält bei 0.951-0.957 (#33981, #34261, #34837, #34580). Ein Cache-Verzeichnis für den kompilierten Kernel: Triton-, FlashInfer-, Inductor-, DeepGEMM- und CUDA-Treiber-Caches werden alle unter SGLANG_CACHE_DIR verschoben. Beim ersten Start nach dem Upgrade wird einmal neu kompiliert. siehe Breaking Changes (#32434). Abhängigkeiten: Torch 2.13.0 mit Triton 3.7.1 (#28836), Flashinfer 0.6.17 (#33997), CuTeDSL 4.6.2, Behebung einer FA4-Startregression auf Blackwell (#34372), DeepEP ist jetzt seit der Veröffentlichung installiert sgl-deep-ep-Räder (#33932) und SGL-Kernel 0.4.6.post1 (#33842). Vollständige release notes nach Kategorie unten; Breaking Changes und bekannte Probleme finden Sie am Ende.

Kimi K3 tuned for MI355X: a grouped-head MLA verify kernel replaces the MHA-shaped split-KV path that re-read the shared latent once per head, for 1.37-1.77x throughput and 1.45-2.42x ITL at concurrency 2-32; the AITER MLA prefill kernel now accepts K3's 12-head shape (TTFT up to -14.9%); a gfx950-tuned decode stage-1 geometry adds 46-73% ITL at 68k input, opt-in via SGLANG_MLA_DECODE_TUNE=1. GSM8K holds at 0.951-0.957 (#33981, #34261, #34837, #34580).

Copy or symlink the old directories if you pre-warm or volume-mount them (deep_gemm and flashinfer are the expensive ones): ~/.triton to {SGLANG_CACHE_DIR}/triton, ~/.cache/flashinfer to {SGLANG_CACHE_DIR}/.cache/flashinfer, ~/.cache/deep_gemm to {SGLANG_CACHE_DIR}/deep_gemm, /tmp/torchinductor_$USER to {SGLANG_CACHE_DIR}/inductor, ~/.nv/ComputeCache to {SGLANG_CACHE_DIR}/nv. Setting any of TRITON_CACHE_DIR, FLASHINFER_WORKSPACE_BASE, SGLANG_DG_CACHE_DIR, TORCHINDUCTOR_CACHE_DIR, or CUDA_CACHE_PATH keeps that one where it is: #32434
  • The torchao integration is removed (--torchao-config had raised ImportError for every accepted value since the torchao pin moved to 0.17.0): #34304
  • DeepEP now installs from released sgl-deep-ep wheels instead of building from source: #33932
  • MoE deferred finalize is on by default on the NVFP4 + flashinfer_trtllm path with an unfused, non-TP1 shared expert (the DeepSeek-V3 family); set SGLANG_ENABLE_MOE_DEFERRED_FINALIZE=False to fall back: #33618
  • Unified-cache out-of-window SWA slot freeing is on by default for the unified radix cache; set SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS=False to restore the old behavior: #34653
  • Remote media downloads are bounded to 64 MiB by default, with redirect validation and opt-in exact-hostname allowlisting for image, video, and audio URLs: #34892
  • The DSV4 fused MHC post+pre path is on by default, including on SM12x: #35214, #34019
  • torch.compile becomes opt-in for diffusion speed mode: #34173
  • 22 unmaintained benchmarks are removed: #34520

Known Issues

  • The Kimi K3 MLA gate-projection fusion into the QKV-A GEMM was landed and reverted this cycle (#33623, #34642). It is not in this release.
  • The AMD GLM-5.2 fused shared-expert append into aiter grouped-topk was landed and reverted (#31323, #35105). It is not in this release.
  • The parallel request lifecycle tracking that shipped with gRPC generation semantics in v0.5.17 (#32588) is reverted: #34160
  • Several failing NPU test cases are disabled pending fixes: #34377
