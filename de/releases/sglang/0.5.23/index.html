Was ist neu?

  • DeepSeek-V4.1 auf GB300 bietet bis zu 1,5-mal mehr Prefill-Durchsatz unter Last und etwa 28 % geringere Latenz beim ersten Token bei 32K- bis 64K-Eingabeaufforderungen (#44403, #45059, #45107).
  • SGLang-Modus mit niedriger Latenz: Die optionalen NVIDIA Megakernel- und AMD Monokernel-Plugins führen die DeepSeek-V4.1-Flash-Dekodierung als fusionierte persistente Kernel aus, für bis zu 44 % schnellere Einzelbenutzer-Dekodierung auf GB300 und 75 % auf MI350X (#44945, #45450, #44353, #44621).
  • MoE-Modelle wie DeepSeek-V4.1-Flash, GLM-5.3-Flash und gpt-oss erreichen den ersten Token 30 % bis 58 % früher bei 8K-Eingabeaufforderungen auf H200 (#43363).
  • Paged Experts (Opt-in) führt MoE-Modelle aus, die größer als der GPU-Speicher auf einer einzelnen Consumer-GPU sind, bis zu 30-mal schneller als CPU-Offload (#42557, #45787).
  • SGLang läuft jetzt auf Google TPU7x über SGLang-TorchTPU, ein PyTorch-natives Plugin für TPU.
  • Sie können jetzt LoRA-Adapter auf quantisierten MoE-Modellen (FP8 und NVFP4) mit einer neuen Opt-in-LoRA-Engine (#45892) bereitstellen.
  • MLA-Modelle im DeepSeek-Stil, die Kontextparallelität dekodieren, können ihren Präfix-Cache jetzt im dateibasierten HiCache-L3-Speicher behalten (#41187).

Wichtige Änderungen und Upgrade-Hinweise

  • Der DeepSeek-V4- und V4.1-Chat folgt jetzt dem Deepseek-Recipe. Eingabeaufforderungen, Ausgaben und die nativen /separate_reasoning- und /parse_function_call-Endpunkte durchlaufen den offiziellen Encoder von DeepSeek, und SGLangs eigene encoding_dsv4.py / encoding_dsv41.py sind weg. Clients bemerken möglicherweise: Gestreamte Tool-Call-Argumente kommen in Teilen an (der erste Block trägt arguments: ""), also verketten Sie sie, wie es der OpenAI SDK tut; Werkzeugaufruf-IDs verwenden das offizielle call_00_...-Format. V4-Argumentation folgt dem offiziellen Profil von DeepSeek und die dsv4_reasoning_effort_profile-Überschreibung wurde entfernt; ein numerischer Wert reasoning_effort auf V4 gibt 400 zurück; developer-Nachrichten werden als Systemnachrichten dargestellt. /parse_function_call gibt auch Aufrufe an Tools außerhalb von tools mit tool_index -1 zurück; Anfragen, die tools mit continue_final_message kombinieren, geben 400 zurück. Die Ausgabeanalyse erfolgt über deepseek-recipe, wenn der DeepSeek-Argumentation- oder Tool-Call-Parser festgelegt ist; sgl-router und sglang-server behalten vorerst ihre Rust-Parser: #45315, #45907, #46219
  • Die begrenzte SWA-Wiedergabe des DeepSeek-V4.1-Decoders ist standardmäßig aktiviert für unterstützte CUDA-Konfigurationen, einschließlich beider PD-Rollen. Es ist numerisch nicht identisch mit der vollständigen Vorfüllung. Übergeben Sie --no-enable-decoder-swa-bounded-replay, um die vollständige Vorabfüllung beizubehalten, zum Beispiel für RL-Rollouts, deren Logprobs mit dem Trainer übereinstimmen müssen: #44403, #45035
  • DeepSeek-V4.1 ist unter PD standardmäßig auf MegaAttention eingestellt. Auf SM100/SM103 lösen jetzt beide PD-Rollen flashmla_mega auf und der PD-Handshake prüft das KV-Layout, daher müssen Vorfüllung und Dekodierung dasselbe Aufmerksamkeits-Backend ausführen (#45075). Aktualisieren Sie Prefill und Decodierung gemeinsam, da eine ältere Decodierung das neue Handshake-Feld nicht lesen kann. Übergeben Sie --dsv4-attn-backend flashmla für beide Rollen, um FlashMLA beizubehalten. Aggregierte Server behalten FlashMLA bei, wenn die Aufmerksamkeit über die Ränge hinweg tensorparallel ist: #46263
  • Das Aufmerksamkeits-Backend tokenspeed_mla wurde entfernt. tokenspeed_mla startet weiterhin als veralteter Alias für cutedsl_mla mit einer Warnung. Um zu wechseln, übergeben Sie --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3 und --speculative-attention-mode decode mit spekulativer Dekodierung: #44803
  • --speculative-skip-dp-mlp-sync wurde entfernt. Startbefehle, die es übergeben, schlagen jetzt mit einem Fehler aufgrund eines nicht erkannten Arguments fehl; Lassen Sie die Flagge fallen: #45043
  • Der Diffusionsquantisierungsname kitchen_int8 wurde entfernt. Verwenden Sie convrot_int8, das seit v0.5.22 dafür veraltet ist: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE wird jetzt ohne Warnung ignoriert. Es hatte bereits keine Auswirkung, da der einheitliche Basisbaum die Standardeinstellung ist; Entfernen Sie es aus den Startskripten: #45090
  • Alte .pt-Kontrollpunkte im Tar-Format werden nicht mehr geladen. Der unsichere Pickle-Fallback weights_only=False wurde entfernt; Konvertieren Sie solche Prüfpunkte offline in Safetensoren oder im ZIP-Format .pt: #42760
  • Diffusion HTTP-Endpunkte validieren strenger. URL-Werte für upscaling_model_path und frame_interpolation_model_path geben 400 zurück, ein nicht unterstütztes response_format wird vor der Generierung abgelehnt und ein fehlgeschlagener Cloud-Upload gibt 502 statt 400 zurück: #43585
  • Der erste Start eines FlashInfer CUTLASS MoE-Servers dauert länger. Die Autotune-Startup-Funktion deckt jetzt auch Prefill-Größen ab, sodass ein Server ohne gespeicherte Tuning-Ergebnisse länger braucht, um bereit zu sein (bei DeepSeek-V4.1-Flash auf 8x H200 geht die Autotune von etwa 41 s auf 177 s). Spätere Startups verwenden die gespeicherten Ergebnisse wieder und --disable-flashinfer-autotune überspringt die Optimierung: #43363
  • Diffusions-PNG-Antworten sind größer. Die PNG-Ausgabe ist jetzt standardmäßig auf Zlib-Ebene 0 eingestellt: die gleichen Pixel, etwa dreimal so viele Bytes, um ein Vielfaches schneller zu kodieren. Setzen Sie output_compression auf einen anderen Wert als 75, um eine Ebene auszuwählen: #45987
  • sgl-router wurde in das Verzeichnis der obersten Ebene sgl-router/ verschoben. Builds und Skripts, die auf experimental/sgl-router/ verweisen, müssen den Pfad aktualisieren (#45414); --max-in-flight ist jetzt --max-inflight-requests und der alte Name funktioniert weiterhin als Alias: #44950

  • SGLang low-latency mode: the opt-in NVIDIA megakernel and AMD monokernel plugins run DeepSeek-V4.1-Flash decode as fused persistent kernels, for up to 44% faster single-user decode on GB300 and 75% on MI350X (#44945, #45450, #44353, #44621).

  • SGLang now runs on Google TPU7x through SGLang-TorchTPU, a PyTorch-native plugin for TPU.
  • You can now serve LoRA adapters on quantized MoE models (FP8 and NVFP4) with a new opt-in LoRA engine (#45892).
  • DeepSeek-style MLA models running decode context parallelism can now keep their prefix cache in HiCache file-based L3 storage (#41187).

Breaking Changes & Upgrade Notes

  • DeepSeek-V4 and V4.1 chat now follows deepseek-recipe. Prompts, outputs and the native /separate_reasoning and /parse_function_call endpoints go through DeepSeek's official encoder, and SGLang's own encoding_dsv4.py / encoding_dsv41.py are gone. Clients may notice: streamed tool-call arguments arrive in pieces (the first chunk carries arguments: ""), so concatenate them as the OpenAI SDK does; tool-call ids use the official call_00_... format; V4 reasoning effort follows DeepSeek's official profile and the dsv4_reasoning_effort_profile override is removed; a numeric reasoning_effort on V4 returns 400; developer messages render as system messages; /parse_function_call also returns calls to tools outside tools with tool_index -1; requests that combine tools with continue_final_message return 400. Output parsing goes through deepseek-recipe when the DeepSeek reasoning or tool-call parser is set; sgl-router and sglang-server keep their Rust parsers for now: #45315, #45907, #46219
  • DeepSeek-V4.1 decoder SWA bounded replay is on by default for supported CUDA configurations, including both PD roles. It is not numerically identical to full prefill. Pass --no-enable-decoder-swa-bounded-replay to keep full prefill, for example for RL rollouts whose logprobs must match the trainer: #44403, #45035
  • DeepSeek-V4.1 defaults to MegaAttention under PD. On SM100 / SM103 both PD roles now resolve flashmla_mega and the PD handshake checks the KV layout, so prefill and decode must run the same attention backend (#45075). Upgrade prefill and decode together, since an older decode cannot read the new handshake field; pass --dsv4-attn-backend flashmla on both roles to keep FlashMLA. Aggregated servers keep FlashMLA when attention is tensor-parallel across ranks: #46263
  • The tokenspeed_mla attention backend is removed. tokenspeed_mla still starts as a deprecated alias for cutedsl_mla with a warning. To switch, pass --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, plus --speculative-attention-mode decode with speculative decoding: #44803
  • --speculative-skip-dp-mlp-sync is removed. Launch commands that pass it now fail with an unrecognized-argument error; drop the flag: #45043
  • The kitchen_int8 diffusion quantization name is removed. Use convrot_int8, deprecated in favor of it since v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE is now ignored without a warning. It already had no effect because the unified radix tree is the default; drop it from launch scripts: #45090
  • Legacy tar-format .pt checkpoints no longer load. The unsafe weights_only=False pickle fallback is removed; convert such checkpoints to safetensors or zip-format .pt offline: #42760
  • Diffusion HTTP endpoints validate more strictly. URL values for upscaling_model_path and frame_interpolation_model_path return 400, an unsupported response_format is rejected before generation, and a failed cloud upload returns 502 instead of 400: #43585
  • The first startup of a FlashInfer CUTLASS MoE server takes longer. Startup autotune now also covers prefill sizes, so a server with no saved tuning results takes longer to become ready (on DeepSeek-V4.1-Flash on 8x H200, autotune goes from about 41 s to 177 s). Later startups reuse the saved results, and --disable-flashinfer-autotune skips tuning: #43363
  • Diffusion PNG responses are larger. PNG output now defaults to zlib level 0: the same pixels, about 3x the bytes, several times faster to encode. Set output_compression to a value other than 75 to pick a level: #45987
  • sgl-router moved to the top-level sgl-router/ directory. Builds and scripts that point at experimental/sgl-router/ must update the path (#45414); --max-in-flight is now --max-inflight-requests, and the old name still works as an alias: #44950
