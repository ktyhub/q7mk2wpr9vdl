Deer-Flow v2.1.0

DeerFlow 2.1.0

DeerFlow 2.1 baut auf dem Superagenten-Kabelbaum 2.0 auf und konzentriert sich auf trust, Skalierung und Bedienbarkeit: überprüfbare Agentenausführung, dauerhafte Batch-Delegierung, steckbare Speicher-Backends, vier neue Sandbox-Anbieter, eine Out-of-Tree-Erweiterung System sowie Authentifizierung und Autorisierung auf Unternehmensniveau – verpackt in einem Viel umfangreicherer Arbeitsbereich mit Projekten, Konversationsverzweigung und Referenzen Gespräche.

Diese Version schließt den 2.1.0-Meilenstein ab. mit 772 zusammengeführten PRs seit der 2.0.0-Veröffentlichung.

📖 Vollständige Notizen: CHANGELOG.md · 中文版

⚠️ Bahnbrechende Veränderungen

  • Trace-IDs sind bedingungslos – jede Gateway-HTTP-Antwort enthält eine X-Trace-Id-Header und logging.enhance.enabled steuern jetzt die Protokollausgabe nur. Client-gelieferte deerflow_trace_id-Werte in Laufmetadaten sind überschrieben, damit Header, Protokolle und der persistente Lauf nicht übereinstimmen können – senden den X-Trace-Id-Anforderungsheader zum Anheften einer Korrelations-ID. ([#5119]) – /mnt/skills ist reserviert für verwaltete, aktivierte Fertigkeitsprojektionen. DEER_FLOW_HOST_SKILLS_PATH / SKILLS_HOST_PATH werden nicht mehr verwendet und E2B-Operator-Mounts, die auf diesen Pfad abzielen, werden mit einer Warnung übersprungen. ([#4178])
  • sandbox.replicas wird für E2B als Kapazitätsgrenze erzwungen; die Standardeinstellung Die wait-Richtlinie kann jetzt den Agentenzug nicht bestehen lassen, anstatt über die Obergrenze hinaus zu wachsen. ([#4391])
  • Ein SKILL.md-Verzeichnis ist eine Laufzeitpaketgrenze – verschachteltes SKILL.md Bei den Dateien handelt es sich um unterstützende Daten, die nicht mehr als eigenständige Fähigkeiten registriert werden. ([#4098])
  • Speicher ist steckbar (memory.manager_class): DeerMem-private Einstellungen in memory.backend_config verschieben (automatische Migration mit einer Warnung), /memory/config hat seine Form geändert, storage_path ist jetzt ein Stammverzeichnis (Alte Werte im Dateistil werden mit einer Warnung verworfen), benutzerdefinierte Speicherklassen Wechseln Sie zu einem neuen Pfad und nehmen Sie config in __init__ und ein Backend ohne search() fällt im tool-Modus schnell aus. ([#4122], [#4023], [#4324])
  • database.checkpoint_delta_snapshot_frequency umgezogen database.checkpoint_delta.snapshot_frequency und seine Standardeinstellung wurde geändert von 1000 bis 10 – legen Sie es explizit fest, um die alte Kadenz beizubehalten. ([#4516])
  • Docker bindet standardmäßig Loopback – der veröffentlichte Eingangsport bindet 127.0.0.1 in beiden Compose-Dateien, passend zum dokumentierten local-trust Bereitstellungsmodell; Legen Sie BIND_HOST fest, um den Stapel auf anderen Schnittstellen verfügbar zu machen. ([#4618])

✨ Highlights

  • Überprüfbare Agentenausführung – jeder Tool-Aufruf enthält ein manipulationssicheres, Ein zur Laufzeit gestempelter Beleg und ein begrenztes Belegbuch erreichen das Modell Kontext; Subagentenberichte müssen Werkzeugbelege mit überprüfbaren Ergebnissen enthalten kümmert sich darum, dass der Hauptagent Gegenprüfungen durchführt; und acceptance_criteria auf Delegationen werden deterministisch auf übergeordneter Seite überprüft (Dateiexistenz, aufgezeichneter Exit-Status des Testbefehls), wobei alles Unentscheidbare gemeldet wird UNVERIFIZIERT. ([#4659], [#5076], [#5090], [#5109], [#4365])
  • Unteragenten im großen Maßstab – ein vom System verwaltetes Delegationsbuch verhindert redundante erneute Delegation und eine totale Auffächerung der Obergrenzen ([#3877], [#4115]); Ein prozessweiter Kapazitätscontroller regelt die Parallelität und das Opt-in Das batch_task-Tool führt große Sammlungen unabhängiger Artikel als langlebige, Wiederaufnehmbare SQL-gestützte Batches mit Leases, Wiederholungsversuchen, Anhalten/Fortsetzen/Abbrechen usw ein Chat-Fortschrittsfenster ([#4998], [#5289]); task(context_mode="snapshot") trägt eine Kopie der übergeordneten Konversation zum Versandzeitpunkt ([#5367]); und Der Verlauf der Subagentenschritte wird beibehalten und im Thread angezeigt. ([#3845])
  • Geplante Aufgaben werden größer – interval-Zeitpläne schließen sich once und cron an ([#5291]); Bevorstehende Cron-Vorkommen können vor dem Speichern in der Vorschau angezeigt werden ([#5381]); Der Laufverlauf filtert serverseitig nach Status und blättert rückwärts die Benutzeroberfläche ([#5384], [#5363]); Aufgaben können lead_agent oder einen benutzerdefinierten Agenten anheften ([#5286], [#5288]); Ausgelastete Vorkommnisse bleiben über Neustarts hinweg dauerhaft in der Warteschlange ([#4918]); und die Wiederherstellung mehrerer Instanzen unterbricht Live-Läufe nicht mehr. ([#4713])
  • Pluggable Memory – neue OpenViking-, mem0- und Honcho-Backends über HTTP ([#4509], [#4528], [#4730]); ein eingebauter FTS5/BM25-Retrieval-Adapter ([#4360]); LLM-unterstützte Konsolidierung und Staleness Pruning ([#3996], [#3860], [#4143]); inkrementelle Faktenspeicherung pro Agent ([#4279]); ein Hybrid Räumungsrichtlinie ([#4789]); garantierte Korrektur-Fakten-Injektion ([#3592]); und Opt-in-Fakten-Dedup auf der Schreibseite. ([#5254])
  • Mehr Sandboxen, strengere Kontrolle – neues E2B, BoxLite (Mikro-VM mit Warm pool), Tenki und OpenSandbox-Anbieter ([#3883], [#3940], [#3951], [#4382], [#4877]); Opt-in isolated / domain-allowlist Netzwerkausgang für lokal Docker-Sandboxes mit abgelehnten Domänen, die durch menschliche Eingaben genehmigt werden können Karte ([#5152]); und gehärtete lokale Container – Bridge-Gateway-Portbindungen, Standard-Seccomp, entfallene Funktionen. ([#4986])
  • Out-of-Tree-Erweiterungen – Python-Erweiterungen tragen zur Middleware bei, Lebenszyklus- und Systemmodellbeobachter, Gateway-Dienste und HTTP-Router, verwaltet mit deerflow extensions install/upgrade/enable/disable/remove ([#4636], [#4684], [#4780], [#5347]); Eine 0.2-Erweiterung API ermöglicht Erweiterungen Beobachten Sie, was der Agent getan hat ([#4863]); und ein neuer RunEvidenceReader-Vertrag sorgt für eine dauerhafte, Cursor-basierte Erkennung geänderter Ausführungen. ([#5405])
  • Enterprise-Authentifizierung und -Autorisierung – generisches OIDC/SSO mit Keycloak-Unterstützung ([#3506]); persönliche Zugriffstoken mit bereichsbezogenen Routenrichtlinien ([#5041]); a Integrierter RBAC-Anbieter mit erzwungener Tool-, Modell- und Sandbox-Autorisierung sowohl zur Assembly als auch zur Laufzeit ([#4260], [#4370], [#4540], [#4911], [#4439]); Die lokale Selbstregistrierung kann für die reine SSO-Bereitstellung geschlossen werden ([#4311]); und Kontoeinstellungen funktionieren auch nach einem gelöschten Browser. ([#5397])
  • MCP als Produktionsinfrastruktur – eine dauerhafte Task-Laufzeit bleibt bestehen Gateway wird neu gestartet und meldet den Fortschritt in der Chat-Benutzeroberfläche ([#4665], [#4690], [#4833]); Gemeinsam genutzte Server können Anmeldeinformationen oder Karten pro Benutzer einfügen Anfragebezogene Geheimnisse für Header ([#4868], [#5010]); Server verwaltet werden aus den Einstellungen ([#5022]); und ein hängender stdio-Server kann das nicht mehr blockieren Gateway- oder Agent-Assembly. ([#4657], [#5217])
  • Längere Laufzeit – Token-Budgets pro Lauf werden additiv über den gesamten Lead verteilt Agent und Subagenten ([#3412]); Torfortsetzungen mit verfolgter, gedeckelter count ([#3858]); Dual-Mode-Checkpoint-Speicher reduziert den Thread-Speicher für lange Laufzeiten von O(N²) bis nahezu linear ([#4292], [#4638]); dauerhafter Kontext überlebt Zusammenfassung ([#3556], [#3887], [#3906]); Opt-in-Aufgabennotizen und Rückruf des komprimierten Verlaufs ([#5382]); Ein Lauf kann zuvor referenziert lesen Gespräche, gewährt vom SDK und dem Komponisten ([#5399], [#5463], [#5465]); strukturierte Klärungsformularfelder ([#4406]); und konfigurierbar Rekursionsgrenzen für Gateway und geplante Ausführungen. ([#5390], [#4848])
  • Modelle und Wissen – Modell- und Generierungseinstellungen pro Agent ([#4347]); ein optionaler Request-Admission-Limiter steuert Anrufe pro Anbieter ([#5432]); Modellfavoriten pro Benutzer ([#5441]); ein Z.AI GLM-5.3-Flash-Profil und MiniMax Code ACP-Unterstützung ([#5074], [#4846]); Opt-in knowledge_search über RAGFlow oder LightRAG ([#4955], [#5209]); Von Dramatikern unterstützte Agenten-Browsersteuerung ([#4187]); und neue Suchanbieter – Serply, Tencent Cloud WSA, Sofya, GroundRoute, Crawl4AI, fastCRW und Parallel – mit nativen Aktualitätsfiltern. ([#5023], [#5057], [#5099], [#5239], [#3675], [#3821], [#3585], [#3881], [#3866], [#5028])
  • Arbeitsbereich – Projekte organisieren Chats mit Anweisungen pro Projekt, a Dokumentenablage und bidirektionale Dateiförderung ([#5265], [#5443]); Assistent Wandelt Verzweigungen in Nebengespräche mit eindeutigen Titeln um ([#3950], [#3934], [#4983]); Die neueste Antwort wird neu generiert und der Benutzer bearbeitet und An Ort und Stelle erneut ausführen ([#3637], [#4377]); Chats archivieren, wiederherstellen und anheften ([#5236], [#4442]); eine Konversationsübersicht navigiert durch lange Chats ([#5025]); Vorschau der CSV/TSV-Artefakte als Tabellen ([#5284]); Textartefakte strömen über Bytebereiche und Dateien eines Laufs werden als eine ZIP-Datei heruntergeladen ([#5056], [#5117]); MCP-Server, Integrationen und Fähigkeiten werden in eine dedizierte Funktion integriert Mitte ([#5468]); und benutzerdefinierte Agenten erhalten Anzeigenamen, eine Bereitstellungsebene Subagentenkatalog und zustandsloser memory_enabled: false-Modus. ([#5324], [#4887], [#5167])
  • Kanäle – ein neuer Buzz (Nostr)-Anschluss ([#4649], [#4727]); /agent list / /agent use IM-Befehle schalten eine Konversation auf die des Eigentümers um Benutzerdefinierte Agenten ([#5168]); Postgres-gestütztes Webhook-Deduplizieren ermöglicht mehrere Pods denselben Kanal bedienen ([#4210]); und DingTalk erhält Datei/Bild Anhänge. ([#4423])

🚀 Leistung

  • Dual-Mode-Checkpoint-Speicher mit LangGraph DeltaChannel schneidet Thread ab Speicherung von O(N²) bis nahezu linear für lange Forschungs-/Codierungsläufe. ([#4292])
  • Chat-Streams fordern messages-tuple + updates + custom statt voll an values-Snapshots – der erneut übertragene Verlauf betrug etwa 75 % der SSE-Nutzlast. ([#5159])
  • Indexieren Sie MemoryRunStore nach thread_id und MemoryRunEventStore-Ereignisse nach run_id zur Eliminierung von O(n)-Scans. ([#3562], [#3686])
  • read_file liest stattdessen nur den angeforderten Zeilenbereich aus der Sandbox Zuerst die gesamte Datei abrufen. ([#3824])
  • view_image fügt Inhalte über wrap_model_call ein, also bis zu 20 MB Base64 sitzt nicht mehr an zwei Kontrollpunkten pro angesehenem Bild. ([#5014])
  • Zwischenspeichern von Sandbox-Pfadumschreibungs- und Ausgabemaskierungs-Regexes pro Instanz. ([#3648], [#3713])
  • Frontend: Streaming-Renderings zu einem Frame-Budget zusammenführen, Neuableitung stoppen Nachrichteninhalt auf jedem Block, Cache-basierte Kopie-Daten-Ableitung und Erzwingen Sie Routen-JS/CSS-Budgets. ([#4425], [#4441], [#5095])
  • Browser-Live-Frames werden als JPEG kodiert, wodurch die Größe der Fortschrittsnutzlast verringert wird. ([#4836])
  • Gebundener Gateway-Speicher, nachdem das Terminal ausgeführt wurde. ([#5112])
  • Deduplizieren Sie gestreamte KI-Nachrichten über einen Seen-ID-Satz (O(n²) → O(n)). ([#3687])
  • Indexieren Sie die Ergebnisse von Werkzeugaufrufen pro Gruppe. ([#4411])

🔒 Sicherheit

  • Skill Review Gate – SkillScan empfängt jetzt jede Datei Byte für Byte (Binärdateien, verschachtelte Archive und NUL-Bytes entgehen dem Scan nicht mehr), Die Archivextraktion ist durch die Anzahl der Mitglieder sowie durch die Größe und das Installationsprogramm begrenzt. Export Guard und Scanner teilen sich eine Codedatei/ausführbare Magic-Definition. ([#5431], [#4241])
  • Prompt-Injection-Verteidigungsmaßnahmen – neue Middleware zur Eingabebereinigung mit beiden Bypässe geschlossen; untrusted-Inhalte in Modellaufforderungen (Speicherfakten, SOUL.md, Subagentenbeschreibungen, Skill-Metadaten) HTML-escaped; MindIE Tool-Response-Framing mit Escapezeichen; und web_capture und MCP-basiertes Tool Ergebnisse werden über dieselbe trust-Grenze wie die integrierten Web-Tools bereinigt. ([#3662], [#5375], [#4028], [#4253], [#4839])
  • Sandbox-Härtung – lokale Docker-Sandboxen binden veröffentlichte Ports an die Docker-Bridge-Gateway, führen Sie das Standard-Seccomp-Profil von Docker aus und löschen Sie alle Funktionen und erhalten Sie no-new-privileges; SSH_AUTH_SOCK wird gelöscht die Sandbox-Umgebung; und projizierte Fertigkeitsdateien sind Kopien, nicht Hardlinks, sodass ein Sandbox-Schreibvorgang die kanonische Quelle nicht verändern kann. ([#4986], [#5145], [#4825], [#4830])
  • Geheimnisse – geerbte geheime Umgebungsvariablen werden aus dem gelöscht Kompetenzumfeld; MCP stdio-Launcher-Argumente und Umgebungsvariablen sind eingeschränkt in der Konfiguration API; Anmeldeinformationen, die nicht als HTTP-Headerwerte übertragen werden können an der Konfigurationsgrenze abgelehnt; und Fertigkeitenumschaltungen bleiben nicht mehr bestehen $VAR-Geheimnisse in extensions_config.json aufgelöst. ([#4018], [#4617], [#5066], [#5357])
  • Artefakte – Der Schreibschutz nur für Ausgaben lässt sich nicht mehr täuschen Prozentcodierte Punktsegmente oder Symlinks und XML-Artefakte (alle +xml Typ enthalten) werden als Download-Anhänge bereitgestellt, sodass aktive Inhalte nicht verfügbar sind Rufen Sie den API mit der Viewer-Sitzung auf. ([#5321], [#5353])
  • Autorisierung – eine leere Tool-Zulassungsliste wird jetzt abgelehnt, anstatt fehlzuschlagen offen; run-create wird auf zustandslosen Stream/Wait-Endpunkten erzwungen; a widerrufen Die sandbox:execute-Zuteilung wird vor der Wiederverwendung der Sandbox erneut überprüft. benutzerdefinierter Agent Zulassungslisten für Fertigkeiten werden auf der Ebene des Sandbox-Dateisystems durchgesetzt; und Abbruch-/Rollback-Aktionen bei GET-Stream-Joins werden mit 405 abgelehnt. ([#4067], [#5030], [#5006], [#5077], [#5092])
  • Sonstiges – SSRF-Schutz für selbst gehostete web_fetch-Anbieter; Lerche CLI Anmeldeinformationsbäume erzwingen private ACLs unter Windows; und Streamdown Die Desinfektion wird in benutzerdefinierten Rehype-Ketten wiederhergestellt. ([#3942], [#5141], [#4987])

🐛 Bemerkenswerte Korrekturen

  • Ausführungen und Laufzeit – Brechen Sie eine Ausführung von jedem Live-Gateway-Worker ab, nicht nur vom Besitzer; Workerübergreifende idempotente Wiederverwendung blockiert die nicht mehr dauerhaft Faden; Schlüsselwiederholungen lösen die Anforderung des Benutzers konsistent auf; die Abschaltung Run Drain übersteht wiederholten Abbruch; und eine Reparaturmigration heilt Datenbanken, die das Run-Change-Clock-Schema stillschweigend übersprungen haben. ([#4500], [#5393], [#5401], [#5487], [#5517])
  • Middleware – Schleifenerkennungsschlüssel read_file anhand des genauen Zeilenbereichs, also Beim Durchblättern einer Datei wird der Festanschlag nicht mehr ausgelöst. max_turns gewährt jetzt Zuschüsse die Umdrehungen, die es benennt (es wurde als LangGraph-Superschritte übergeben, ~7–8 pro Umdrehung); Token-Budgets gelten für alle Zielfortsetzungen; Schutzvorrichtungen, die Werkzeugaufrufe entfernen bricht nicht mehr bei jeder späteren Claude-/Antwort-Runde ab; und wiederholte Modellaufrufe Warnungen in der Warteschlange erneut zustellen. ([#5486], [#5485], [#5410], [#5447], [#5433])
  • Subagenten – ein Subagent behält seine Anweisungen nach der Kontextkomprimierung; Der Fehler eines delegierten Subagenten führt nicht mehr dazu, dass die übergeordnete Ausführung fehlschlägt. wiederholt Abgebrochene Subagenten verlieren nicht mehr ihren Ausführungsslot; und Windows Akzeptanzprüfungen schlagen bei Befehlen außerhalb des Gültigkeitsbereichs fehl. ([#5454], [#5407], [#5477], [#5162])
  • Sandbox-Tools – Remote-Berichtsfehler list_dir / glob / grep anstatt „leeres Verzeichnis“ oder „keine Übereinstimmungen“ zu erfinden; read_file Die Kürzung wird in Zeilen mit dem genauen Fortsetzungspunkt gemeldet. Host-Pfad Maskierung behandelt Verknüpfungen im $PATH-Stil und Schrägstrich-Windows-Schreibweisen; gleichzeitige Subagenten arbeiten über die AIO-Shell-Sitzungsobergrenze hinaus; und CJK-Tool Die Ausgabe ist in PowerShell nicht mehr verstümmelt. ([#5264], [#5422], [#5380], [#5474], [#5418], [#5373], [#5178], [#5440])
  • Modelle – das Claude Code OAuth-Token wird einmal pro Prozess gelesen, also Titel, Zusammenfassung und Subagentenmodelle verlieren nicht mehr ihre Anmeldeinformationen; Modelle mit supports_reasoning_effort schlägt beim Erstellen nicht mehr fehl; Codex ungültiges Tool Anrufe werden mit ihren Ergebnissen gepaart; und api_base wird bei jedem geehrt BaseChatOpenAI-Unterklasse. ([#5411], [#5403], [#5509], [#4146])
  • Kanäle – WeCom clips und Aufteilung über die 20-KB-Protokollobergrenze statt die Antwort fallen lassen; Eine nicht entschlüsselbare WeChat-Nachricht verwirft sie nicht mehr Charge; Ein toter Discord client hängt ausgehende Sendungen nicht mehr auf und friert die ein Kanalpool; Telegram rich_messages rendert nur, wenn der Text tatsächlich ist enthält umfangreiche Konstrukte; und eingehende WeChat/WeCom-Medien werden gestreamt, größenbegrenzt und auf der Host-Zulassungsliste aufgeführt. ([#5148], [#4231], [#5227], [#5470], [#5225])
  • Fähigkeiten und Geheimnisse – Durch das Umschalten einer Fertigkeit werden keine gelösten Geheimnisse mehr geschrieben in extensions_config.json; Stellen Sie $VAR-Referenzen wieder her und drehen Sie alle Anmeldeinformationen werden auf diese Weise offengelegt. ([#5357])
  • Planer – das globale max_concurrent_runs-Budget wird durchgesetzt SQLite (nicht nur Postgres) und für manuelle Trigger; und ein Versandrennen das zwei Läufe für eine Aufgabe starten könnte, ist geschlossen. ([#5469], [#4769], [#4105])
  • MCP – parallele synchrone Aufrufe an einen STDIO-Server werden nicht mehr abgebrochen die Verbindung des anderen; Der Sitzungspool hält seine Kapazitätsgrenze unter gleichzeitige Initialisierung; und dauerhafte Aufgabenabfragen bleiben gepoolt Sitzungen über Protokoll-Timeouts hinweg. ([#5396], [#4962], [#5027])
  • Frontend – die Nachrichtenreihenfolge bleibt über lange Laufzeiten und erneute Verbindungen stabil; Von Menschen eingegebene Karten bleiben in der Runde, in der sie angefordert wurden. Die Eingabe des Benutzers ist nach einer inkrementellen Stream-Wiederverbindung wiederhergestellt; Seitenleiste-Chat-Löschung fragt zuerst zur Bestätigung; und der client sendet einmal einen gestreamten Werkzeugaufruf mit seine vollständigen Argumente. ([#5293], [#4892], [#5428], [#5406], [#5408])

📦 Bereitstellung und Betrieb

  • Docker – der veröffentlichte Eingangsport bindet standardmäßig Loopback (siehe bahnbrechende Änderungen); make up wartet vorher auf eine echte Gateway-Zustandsprüfung Erklären des Stapels für bereit; Startup toleriert einen fehlenden .env; und Windows Git-Bash-Preflight- und Socket-Handhabungsarbeiten. ([#4618], [#4658], [#4806], [#5371], [#5402])
  • Kubernetes – Dienste pro Sandbox sind standardmäßig auf ClusterIP eingestellt NodePort, daher sind Sandboxen nur innerhalb des Clusters erreichbar ([#4190]); ClusterIP-Dienste und bereichsbezogene PVC-Bereitstellungen pro Skill ([#4016], [#3928]); und Ein optionaler Lark-Credential-Broker-Sidecar hält App-Geheimnisse fern Sandbox-Dateisystem. ([#4501])
  • Gesundheit und Bereitschaft – der neue GET /health/ready führt eine begrenzte Datenbank aus prüft und gibt 503 zurück, während die Datenbank nicht erreichbar ist; /health bleibt pure Lebendigkeit. ([#5166])
  • Nginx – Thread-Routen, die auf einen Modellaufruf warten, erlauben 600 Sekunden (a langsam /compact gibt nicht mehr 504 für angewendete Arbeit zurück) und lang Chat-Eingabeaufforderungen bestehen /api/langgraph/ ohne rohe 500. ([#5505], [#4277])
  • Konfiguration – ein benutzerdefiniertes PostgreSQL-Schema wird über ausgewählt postgres_schema und automatisch erstellt ([#3442]); recursion_limit und scheduler.recursion_limit sind durch die Bereitstellung konfigurierbar ([#5390], [#4848]); und make dev behält das ollama-UV-Extra über Neustarts hinweg bei. ([#5318])
  • Upgrades – Der Start toleriert die Migration einer Datenbank auf die überprüfte neuere Version Revision, Rollback möglich halten ([#5219]); Legacy-Threads erhalten ein Run-Event Saatgut-Hinterfüllung ([#4590]); und Postgres-Verbindungen überstehen Leerlaufzeitüberschreitungen über pool_recycle. ([#4230])
  • CI & Verpackung – der Backend-Unit-Test-Workflow ist in vier Teile aufgeteilt parallele Shards mit isoliertem Postgres/Redis ([#5137]); und die Umbenennung Das tenki-Paket ersetzt das von PyPI entfernte tenki-sandbox. ([#5087])

deer-flow v2.1.0

DeerFlow 2.1.0

DeerFlow 2.1 builds on the 2.0 super-agent harness with a focus on trust, scale, and operability: verifiable agent execution, durable batch delegation, pluggable memory backends, four new sandbox providers, an out-of-tree extension system, and enterprise-grade authentication and authorization — wrapped in a much richer workspace with projects, conversation branching, and referenced conversations.

This release closes the 2.1.0 milestone with 772 merged PRs since the 2.0.0 release.

📖 Full notes: CHANGELOG.md · 中文版

⚠️ Breaking changes

  • Trace ids are unconditional — every Gateway HTTP response carries an X-Trace-Id header, and logging.enhance.enabled now controls log output only. Client-supplied deerflow_trace_id values in run metadata are overwritten so header, logs, and the persisted run cannot disagree — send the X-Trace-Id request header to pin a correlation id. ([#5119])
  • /mnt/skills is reserved for managed enabled-only skill projections. DEER_FLOW_HOST_SKILLS_PATH / SKILLS_HOST_PATH are no longer used, and E2B operator mounts targeting that path are skipped with a warning. ([#4178])
  • sandbox.replicas is enforced for E2B as a capacity limit; the default wait policy can now fail the agent turn instead of growing past the cap. ([#4391])
  • A SKILL.md directory is a runtime package boundary — nested SKILL.md files are supporting data, no longer registered as independent skills. ([#4098])
  • Memory is pluggable (memory.manager_class): DeerMem-private settings move into memory.backend_config (auto-migrated with a warning), /memory/config changed shape, storage_path is now a root directory (legacy file-style values are dropped with a warning), custom storage classes move to a new path and take config in __init__, and a backend without search() fails fast in tool mode. ([#4122], [#4023], [#4324])
  • database.checkpoint_delta_snapshot_frequency moved to database.checkpoint_delta.snapshot_frequency and its default changed from 1000 to 10 — set it explicitly to keep the old cadence. ([#4516])
  • Docker binds loopback by default — the published entry port binds 127.0.0.1 in both compose files, matching the documented local-trust deployment model; set BIND_HOST to expose the stack on other interfaces. ([#4618])

✨ Highlights

  • Verifiable agent execution — every tool call carries a tamper-evident, runtime-stamped receipt and a bounded receipt ledger reaches the model context; subagent reports must cite tool receipts with verifiable deliverable handles that the lead agent cross-checks; and acceptance_criteria on delegations are checked deterministically parent-side (file existence, recorded test-command exit status), with anything undecidable reported UNVERIFIED. ([#4659], [#5076], [#5090], [#5109], [#4365])
  • Subagents at scale — a system-maintained delegation ledger prevents redundant re-delegation and a total cap bounds fan-out ([#3877], [#4115]); one process-wide capacity controller governs concurrency, and the opt-in batch_task tool runs large collections of independent items as durable, resumable SQL-backed batches with leases, retries, pause/resume/cancel, and a chat progress panel ([#4998], [#5289]); task(context_mode="snapshot") carries a dispatch-time copy of the parent conversation ([#5367]); and subagent step history is persisted and displayed in the thread. ([#3845])
  • Scheduled tasks grow up — interval schedules join once and cron ([#5291]); upcoming cron occurrences can be previewed before saving ([#5381]); run history filters server-side by status and pages backwards in the UI ([#5384], [#5363]); tasks can pin lead_agent or a custom agent ([#5286], [#5288]); busy occurrences queue durably across restarts ([#4918]); and multi-instance recovery no longer interrupts live runs. ([#4713])
  • Pluggable memory — new OpenViking, mem0, and Honcho backends over HTTP ([#4509], [#4528], [#4730]); a built-in FTS5/BM25 retrieval adapter ([#4360]); LLM-assisted consolidation and staleness pruning ([#3996], [#3860], [#4143]); incremental per-agent fact storage ([#4279]); a hybrid eviction policy ([#4789]); guaranteed correction-fact injection ([#3592]); and opt-in write-side fact dedup. ([#5254])
  • More sandboxes, tighter control — new E2B, BoxLite (micro-VM with warm pool), Tenki, and OpenSandbox providers ([#3883], [#3940], [#3951], [#4382], [#4877]); opt-in isolated / domain-allowlist network egress for local Docker sandboxes, with denied domains approvable through the Human Input card ([#5152]); and hardened local containers — bridge-gateway port binds, default seccomp, dropped capabilities. ([#4986])
  • Out-of-tree extensions — Python extensions contribute middleware, lifecycle and system-model observers, Gateway services, and HTTP routers, managed with deerflow extensions install/upgrade/enable/disable/remove ([#4636], [#4684], [#4780], [#5347]); a 0.2 extension API lets extensions observe what the agent did ([#4863]); and a new RunEvidenceReader contract drives durable, cursor-based changed-run discovery. ([#5405])
  • Enterprise auth & authorization — generic OIDC/SSO with Keycloak support ([#3506]); personal access tokens with scoped route policies ([#5041]); a built-in RBAC provider with tool, model, and sandbox authorization enforced at both assembly and runtime ([#4260], [#4370], [#4540], [#4911], [#4439]); local self-registration can be closed to SSO-only provisioning ([#4311]); and account preferences survive a cleared browser. ([#5397])
  • MCP as production infrastructure — a durable task runtime survives Gateway restarts and reports progress in the chat UI ([#4665], [#4690], [#4833]); shared servers can inject per-user credentials or map request-scoped secrets to headers ([#4868], [#5010]); servers are managed from Settings ([#5022]); and a hung stdio server can no longer stall the Gateway or agent assembly. ([#4657], [#5217])
  • Richer runtime — per-run token budgets shared additively across the lead agent and subagents ([#3412]); goal continuations with a tracked, capped count ([#3858]); dual-mode checkpoint storage cuts long-run thread storage from O(N²) to near-linear ([#4292], [#4638]); durable context survives summarization ([#3556], [#3887], [#3906]); opt-in task notes and compacted-history recall ([#5382]); a run can read referenced earlier conversations, grantable from the SDK and the composer ([#5399], [#5463], [#5465]); structured clarification form fields ([#4406]); and configurable recursion limits for Gateway and scheduled runs. ([#5390], [#4848])
  • Models & knowledge — per-agent model and generation settings ([#4347]); an optional request-admission limiter paces calls per provider ([#5432]); per-user model favorites ([#5441]); a Z.AI GLM-5.3-Flash profile and MiniMax Code ACP support ([#5074], [#4846]); opt-in knowledge_search over RAGFlow or LightRAG ([#4955], [#5209]); Playwright-backed agentic browser control ([#4187]); and new search providers — Serply, Tencent Cloud WSA, Sofya, GroundRoute, Crawl4AI, fastCRW, and Parallel — with native recency filters. ([#5023], [#5057], [#5099], [#5239], [#3675], [#3821], [#3585], [#3881], [#3866], [#5028])
  • Workspace — Projects organize chats, with per-project instructions, a document shelf, and two-way file promotion ([#5265], [#5443]); assistant turns branch into side conversations with distinguishing titles ([#3950], [#3934], [#4983]); the latest answer regenerates and user turns edit and rerun in place ([#3637], [#4377]); chats archive, restore, and pin ([#5236], [#4442]); a conversation outline navigates long chats ([#5025]); CSV/TSV artifacts preview as tables ([#5284]); text artifacts stream over byte ranges and a run's files download as one zip ([#5056], [#5117]); MCP servers, integrations, and skills move into a dedicated Capability Center ([#5468]); and Custom Agents get display names, a deployment-level subagent catalog, and stateless memory_enabled: false mode. ([#5324], [#4887], [#5167])
  • Channels — a new Buzz (Nostr) connector ([#4649], [#4727]); /agent list / /agent use IM commands switch a conversation to the owner's Custom Agents ([#5168]); Postgres-backed webhook dedup lets several pods serve the same channel ([#4210]); and DingTalk gains file/image attachments. ([#4423])

🚀 Performance

  • Dual-mode checkpoint storage with LangGraph DeltaChannel cuts thread storage from O(N²) to near-linear for long research/coding runs. ([#4292])
  • Chat streams request messages-tuple + updates + custom instead of full values snapshots — retransmitted history was ~75% of SSE payload. ([#5159])
  • Index MemoryRunStore by thread_id and MemoryRunEventStore events by run_id to eliminate O(n) scans. ([#3562], [#3686])
  • read_file reads only the requested line range from the sandbox instead of fetching the whole file first. ([#3824])
  • view_image injects content via wrap_model_call, so up to 20 MB of base64 no longer sits in two checkpoints per viewed image. ([#5014])
  • Cache sandbox path-rewrite and output-masking regexes per instance. ([#3648], [#3713])
  • Frontend: coalesce streaming renders to a frame budget, stop re-deriving message content on every chunk, cache settled copy-data derivation, and enforce route JS/CSS budgets. ([#4425], [#4441], [#5095])
  • Browser Live frames encode as JPEG, cutting progress payload size. ([#4836])
  • Bound gateway memory after terminal runs. ([#5112])
  • Deduplicate streamed AI messages via a seen-id set (O(n²) → O(n)). ([#3687])
  • Index tool-call results per group. ([#4411])

🔒 Security

  • Skill review gate — SkillScan now receives every file byte for byte (binaries, nested archives, and NUL bytes no longer escape scanning), archive extraction is capped by member count as well as size, and installer, export guard, and scanner share one code-file/executable-magic definition. ([#5431], [#4241])
  • Prompt-injection defenses — new input-sanitization middleware with both bypasses closed; untrusted content in model prompts (memory facts, SOUL.md, subagent descriptions, skill metadata) HTML-escaped; MindIE tool-response framing escaped; and web_capture and MCP-sourced tool results sanitized through the same trust boundary as the built-in web tools. ([#3662], [#5375], [#4028], [#4253], [#4839])
  • Sandbox hardening — local Docker sandboxes bind published ports to the Docker bridge gateway, run Docker's default seccomp profile, drop all capabilities, and get no-new-privileges; SSH_AUTH_SOCK is scrubbed from the sandbox environment; and projected skill files are copies, not hardlinks, so a sandboxed write cannot mutate the canonical source. ([#4986], [#5145], [#4825], [#4830])
  • Secrets — inherited secret environment variables are scrubbed from the skill environment; MCP stdio launcher arguments and env vars are constrained at the config API; credentials that cannot travel as HTTP header values are rejected at the config boundary; and skill toggles no longer persist resolved $VAR secrets into extensions_config.json. ([#4018], [#4617], [#5066], [#5357])
  • Artifacts — the outputs-only write guard is no longer fooled by percent-encoded dot segments or symlinks, and XML artifacts (any +xml type included) are served as download attachments so active content cannot call the API with the viewer's session. ([#5321], [#5353])
  • Authorization — an empty tool allowlist now denies instead of failing open; run-create is enforced on stateless stream/wait endpoints; a revoked sandbox:execute grant is re-checked before sandbox reuse; custom-Agent skill allowlists are enforced at the sandbox filesystem level; and cancel/rollback actions on GET stream joins are rejected with 405. ([#4067], [#5030], [#5006], [#5077], [#5092])
  • Other — SSRF guard for self-hosted web_fetch providers; Lark CLI credential trees enforce private ACLs on Windows; and streamdown sanitization is restored in custom rehype chains. ([#3942], [#5141], [#4987])

🐛 Notable fixes

  • Runs & runtime — cancel a run from any live gateway worker, not only the owner; cross-worker idempotent reuse no longer permanently blocks the thread; keyed retries resolve the request user consistently; the shutdown run drain survives repeated cancellation; and a repair migration heals databases that silently skipped the run-change clock schema. ([#4500], [#5393], [#5401], [#5487], [#5517])
  • Middleware — loop detection keys read_file by exact line range, so paging through a file no longer trips the hard stop; max_turns now grants the turns it names (it was passed as LangGraph super-steps, ~7–8 per turn); token budgets hold across goal continuations; guards that remove tool calls no longer break every later Claude/Responses turn; and retried model calls re-deliver queued warnings. ([#5486], [#5485], [#5410], [#5447], [#5433])
  • Subagents — a subagent keeps its instructions after context compaction; a delegated subagent's error no longer fails the parent run; repeatedly cancelled subagents no longer leak their execution slot; and Windows acceptance checks fail closed on out-of-scope commands. ([#5454], [#5407], [#5477], [#5162])
  • Sandbox tools — remote list_dir / glob / grep report failures instead of inventing "empty directory" or "no matches"; read_file truncation is reported in lines with the exact resume point; host-path masking handles $PATH-style joins and forward-slash Windows spellings; concurrent subagents work past the AIO shell-session ceiling; and CJK tool output is no longer garbled in PowerShell. ([#5264], [#5422], [#5380], [#5474], [#5418], [#5373], [#5178], [#5440])
  • Models — the Claude Code OAuth token is read once per process, so title, summarization, and subagent models stop losing their credential; models with supports_reasoning_effort no longer fail to build; Codex invalid tool calls are paired with their results; and api_base is honored on every BaseChatOpenAI subclass. ([#5411], [#5403], [#5509], [#4146])
  • Channels — WeCom clips and splits over the 20 KB protocol cap instead of dropping the reply; one undecodable WeChat message no longer drops its batch; a dead Discord client no longer hangs outbound sends and freezes the channel pool; Telegram rich_messages renders only when the text actually contains rich constructs; and WeChat/WeCom inbound media is streamed, size-bounded, and host-allowlisted. ([#5148], [#4231], [#5227], [#5470], [#5225])
  • Skills & secrets — toggling a skill no longer writes resolved secrets into extensions_config.json; restore $VAR references and rotate any credential exposed this way. ([#5357])
  • Scheduler — the global max_concurrent_runs budget is enforced on SQLite (not just Postgres) and for manual triggers; and a dispatch race that could launch two runs for one task is closed. ([#5469], [#4769], [#4105])
  • MCP — parallel synchronous calls to one stdio server no longer cancel each other's connection; the session pool holds its capacity limit under concurrent initialization; and durable task polling preserves pooled sessions across protocol timeouts. ([#5396], [#4962], [#5027])
  • Frontend — message order stays stable across long runs and reconnects; human-input cards keep the turn that requested them; the user's input is restored after an incremental stream reconnect; sidebar chat deletion asks for confirmation first; and the client emits a streamed tool call once, with its complete arguments. ([#5293], [#4892], [#5428], [#5406], [#5408])

📦 Deploy & ops

  • Docker — the published entry port binds loopback by default (see breaking changes); make up waits for a real Gateway health probe before declaring the stack ready; startup tolerates a missing .env; and Windows Git Bash preflight and socket handling work. ([#4618], [#4658], [#4806], [#5371], [#5402])
  • Kubernetes — per-sandbox Services default to ClusterIP instead of NodePort, so sandboxes are reachable only inside the cluster ([#4190]); ClusterIP Services and scoped per-skill PVC mounts ([#4016], [#3928]); and an optional Lark credential broker sidecar keeps app secrets out of the sandbox filesystem. ([#4501])
  • Health & readiness — the new GET /health/ready runs a bounded database probe and returns 503 while the database is unreachable; /health stays pure liveness. ([#5166])
  • Nginx — thread routes that wait on a model call allow 600 seconds (a slow /compact no longer returns 504 for work that was applied), and long chat prompts pass /api/langgraph/ without a raw 500. ([#5505], [#4277])
  • Configuration — a custom PostgreSQL schema is selected via postgres_schema and created automatically ([#3442]); recursion_limit and scheduler.recursion_limit are deployment-configurable ([#5390], [#4848]); and make dev preserves the ollama uv extra across restarts. ([#5318])
  • Upgrades — startup tolerates a database migrated to the reviewed newer revision, keeping rollback possible ([#5219]); legacy threads get run-event seed backfill ([#4590]); and Postgres connections survive idle timeouts via pool_recycle. ([#4230])
  • CI & packaging — the backend unit-test workflow splits into four parallel shards with isolated Postgres/Redis ([#5137]); and the renamed tenki package replaces the PyPI-removed tenki-sandbox. ([#5087])
