Terraform v1.16.0

1.16.0 (26. August 2026)

NEUE FUNKTIONEN:

  • Terraform speichert jetzt geplante private Daten für Anbieter, sodass der anbieterspezifische Status über Plan und Anwendung hinweg beibehalten werden kann. (#37986)
  • terraform_data: Der neue store-Block kann flüchtige und sensible Werte über Plan und Anwendung hinweg speichern. (#38298)
  • Anbieter können jetzt verschachtelte Blöcke als berechnete Werte verwenden (#38305)
  • Import: import-Blöcke innerhalb von Modulen werden jetzt unterstützt. (#38352)
  • Terraform ist jetzt als vorgefertigte Binärdatei für Linux s390x (zLinux) verfügbar. (#38384)
  • Ressourcenaktionsauslöser können jetzt die on_failure-Modi halt, taint oder continue verwenden. (#38722) VERBESSERUNGEN:
  • Statusanzeige: Der Befehl state show kann jetzt eine maschinenlesbare Ausgabe erzeugen, wenn er mit dem Flag -json bereitgestellt wird (#23940)
  • Arbeitsbereich: Der Befehl workspace list kann jetzt eine maschinenlesbare Ausgabe erzeugen, wenn er mit dem Flag -json bereitgestellt wird (#38397)
  • Test: Terraform meldet jetzt, welche Ressourcen zurückgelassen wurden, wenn skip_cleanup gesetzt ist. (#38449)
  • Stapel: Aktionskonfigurationen haben jetzt Zugriff auf ein caller-Symbol, das den Objektwert der aufrufenden Ressource enthält. (#38668)
  • Aktionen können jetzt die Ereignisse before_destroy und after_destroy verwenden. (#38668)
  • cloud: Terraform zeigt jetzt eine Zusammenfassung der Richtlinienauswertungsergebnisse für plan- und apply-Läufe gegen HCP Terraform an. (#38715)
  • Richtlinie: Terraform löst jetzt während init, plan und apply Richtlinien-Plugin-Anmeldeinformationen aus der konfigurierten Cloud oder dem Remote-Backend auf, anstatt dass das Plugin die Anmeldeinformationen selbst lesen muss. (#38716)
  • Graph: Der Befehl terraform graph kann jetzt mithilfe des Flags -format=mermaid Diagramme im Mermaid-Format ausgeben. (#38719)
  • Untergeordnete Modulausgaben mit nicht referenzierten veralteten verschachtelten Attributen geben keine veralteten Warnungen mehr zurück. (#38778)
  • Ressourcen-lifecycle-Blöcke unterstützen jetzt destroy = false, um zu verhindern, dass eine Ressource zerstört wird. (#38784)
  • Die Funktion contains() kann jetzt auf null-Werte testen. (#38792)
  • Konsole: Der Befehl terraform console akzeptiert jetzt ein optionales -scope=<module address>-Flag, das zum Auswerten von Ausdrücken im Bereich eines Moduls oder einer bestimmten Modulinstanz verwendet werden kann. (#31861)
  • -invoke kann jetzt mit -target kombiniert werden, um die aufrufende Ressourceninstanz anzugeben, wenn mehrere Ressourcen dieselbe Aktion auslösen. (#38845)
  • Der Befehl terraform stacks leitet jetzt automatisch den Ziel-Hostnamen aus der lokalen Anmeldeinformationsdatei (credentials.tfrc.json) ab, wenn weder TF_STACKS_HOSTNAME noch TF_CLOUD_HOSTNAME festgelegt ist (#38896) FEHLERBEHEBUNGEN:
  • import-Blöcke berücksichtigen jetzt korrekt die lokalen Namen der Anbieter. (#38338)
  • terraform apply gerät nicht mehr in Panik, wenn der Plan eine No-Op-Änderung für eine abgelegte Ressource enthält, die über lifecycle.precondition- oder lifecycle.postcondition-Blöcke verfügt. (#38586)
  • Arbeitsbereich: Terraform löst jetzt einen Fehler aus, wenn aufgrund von Out-of-Band-Änderungen ein ungültiger Arbeitsbereichsname ausgewählt wird. (#38594)
  • Test: Terraform gibt jetzt eine Warnung aus, wenn eine Datei, auf die über das Flag -filter verwiesen wird, nicht existiert. (#38603)
  • init: Terraform entfernt keine Sperren mehr aus der Abhängigkeitssperrdatei für Anbieter, die als dev_override konfiguriert sind. (#38634)
  • init: Terraform warnt jetzt, wenn nicht verwaltete Anbieter verwendet werden, und kann sich auf die Anbieterinstallation auswirken. (#38656)
  • Aktionen werden jetzt in Bezug auf alle Ressourcenabhängigkeiten aufgerufen. (#38668)
  • Terraform gibt jetzt den korrekten Fehler zurück, wenn ein import-Ziel im Status vorhanden ist, aber keine entsprechende Konfiguration hat. (#38782)
  • Die Funktion merge() gerät nicht mehr in Panik, wenn null-Objekte übergeben werden. (#38792)
  • Erlauben Sie Unterstriche in den Namensräumen der Anbieter-Quelladressen, damit private Registrierungsanbieteradressen nicht mehr als ungültig abgelehnt werden (#38894)
  • Test: Optionale kurzlebige Werte müssen nicht zum Planungszeitpunkt festgelegt werden (#38974) HINWEISE:
  • init: Fehler aufgrund inkompatibler -upgrade- und -lockfile=readonly-Flags werden jetzt früher im Init-Prozess ausgelöst. (#38561) UPGRADE-HINWEISE:
  • bastion_host_key wird jetzt von Provisionern korrekt angewendet. Überprüfen Sie vor dem Upgrade Ihre Provisioner-Konfigurationen, um sicherzustellen, dass der konfigurierte Schlüssel korrekt ist. (#38318)

terraform v1.16.0

1.16.0 (August 26, 2026)

NEW FEATURES:

  • Terraform now stores planned private data for providers, allowing provider-specific state to be preserved across plan and apply. (#37986)

  • terraform_data: The new store block can hold ephemeral and sensitive values across plan and apply. (#38298)

  • Providers can now use nested blocks as computed values (#38305)

  • import: import blocks inside modules are now supported. (#38352)

  • Terraform is now available as a pre-built binary for Linux s390x (zLinux). (#38384)

  • Resource action triggers can now use on_failure modes of halt, taint, or continue. (#38722)

ENHANCEMENTS:

  • state show: The state show command can now produce machine-readable output when supplied with the -json flag (#23940)

  • workspace: The workspace list command can now produce machine-readable output when supplied with the -json flag (#38397)

  • test: Terraform now reports which resources were left behind when skip_cleanup is set. (#38449)

  • stacks: Action configurations now have access to a caller symbol containing the object value of the calling resource. (#38668)

  • Actions can now use before_destroy and after_destroy events. (#38668)

  • cloud: Terraform now displays a summary of policy evaluation outcomes for plan and apply runs against HCP Terraform. (#38715)

  • policy: Terraform now resolves policy plugin credentials from the configured cloud or remote backend during init, plan, and apply, rather than requiring the plugin to read credentials itself. (#38716)

  • graph: The terraform graph command can now output graphs in Mermaid format using the -format=mermaid flag. (#38719)

  • Child module outputs with unreferenced deprecated nested attributes no longer return deprecation warnings. (#38778)

  • Resource lifecycle blocks now support destroy = false to prevent a resource from being destroyed. (#38784)

  • The contains() function can now test for null values. (#38792)

  • console: The terraform console command now accepts an optional -scope=<module address> flag, which can be used to evaluate expressions within the scope of a module or a specific module instance. (#31861)

  • -invoke can now be combined with -target to specify the calling resource instance when multiple resources trigger the same action. (#38845)

  • The terraform stacks command now automatically infers the target hostname from the local credentials file (credentials.tfrc.json) when neither TF_STACKS_HOSTNAME nor TF_CLOUD_HOSTNAME is set (#38896)

BUG FIXES:

  • import blocks now correctly respect provider local names. (#38338)

  • terraform apply no longer panics when the plan contains a no-op change for a deposed resource that has lifecycle.precondition or lifecycle.postcondition blocks. (#38586)

  • workspace: Terraform now raises an error if an invalid workspace name becomes selected due to out-of-band changes. (#38594)

  • test: Terraform now raises a warning when a file referenced via the -filter flag does not exist. (#38603)

  • init: Terraform no longer removes locks from the dependency lock file for providers configured as dev_override. (#38634)

  • init: Terraform now warns when unmanaged providers are in use and may impact provider installation. (#38656)

  • Actions are now invoked with respect to all resource dependencies. (#38668)

  • Terraform now returns the correct error when an import target exists in state but has no corresponding configuration. (#38782)

  • The merge() function no longer panics when passed null objects. (#38792)

  • Allow underscores in provider source address namespaces, so private registry provider addresses are no longer rejected as invalid (#38894)

  • test: Optional ephemeral values do not have to be set at plan time (#38974)

NOTES:

  • init: Errors due to incompatible -upgrade and -lockfile=readonly flags are now raised earlier in the init process. (#38561)

UPGRADE NOTES:

  • bastion_host_key is now correctly applied by provisioners. Review your provisioner configurations to verify the configured key is correct before upgrading. (#38318)
