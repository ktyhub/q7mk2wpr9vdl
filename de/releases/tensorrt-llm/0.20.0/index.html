TensorRT-LLM v0.20.0

TensorRT-LLM-Version 0.20.0

Hauptfunktionen und Verbesserungen

  • Modellunterstützung
    • Qwen3-Unterstützung hinzugefügt. Weitere Informationen finden Sie im Abschnitt „Qwen3“ in examples/models/core/qwen/README.md.
    • HyperCLOVAX-SEED-Vision-Unterstützung im PyTorch-Flow hinzugefügt. Siehe examples/models/contrib/hyperclovax/README.md
    • Dynasor-CoT in Gerüstbeispielen hinzugefügt. Siehe examples/scaffolding/contrib/Dynasor/README.md
    • Mistral Small 3.1 24B VLM-Unterstützung im TRT-Workflow hinzugefügt – Gemma3-1b-it-Unterstützung im PyTorch-Workflow hinzugefügt
    • Unterstützung für das Nemotron-H-Modell hinzugefügt
    • Eagle-3-Unterstützung für LLAMA4 hinzugefügt
  • PyTorch-Workflow
    • Lora-Unterstützung hinzugefügt
    • Unterstützung für Rückgabeprotokolle hinzugefügt – Neue LogProb-Definition im PyTorch-Flow übernehmen – Aktivierte Statistiken pro Anfrage mit PyTorch-Backend
    • LogitsProcessor im PyTorch-Backend aktiviert
  • Benchmark:
    • Strahlbreite hinzufügen, um die Latenz zu verringern. – Behebung der trtllm-bench iter_stats- und cuda_graph_batch_sizes-Fehler. – Entfernen Sie den veralteten Laufzeit-Benchmark Python
    • Benchmark-Unterstützung für Gerüste hinzufügen
  • Multimodale Modelle
    • Unterstützung in trtllm-serve hinzugefügt – Unterstützung in trtllm-bench hinzugefügt, die Unterstützung ist vorerst nur auf Bilder beschränkt
  • Unterstützt DeepSeek-R1 W4A8 auf Hopper – Fügen Sie die RTX Pro 6000-Unterstützung auf einer einzelnen GPU hinzu
  • Integrierter Llama4-Eingabeprozessor
  • CGA-Reduktions-FHMA-Kernel auf Blackwell hinzugefügt – Chunked-Kontext für FlashInfer aktiviert – Unterstützte KV-Cache-Wiederverwendung für MLA
  • Unterstützung für stückweise CUDA-Graphen hinzugefügt
  • Unterstützt mehrere LoRA-Adapter und TP – KV-Cache-fähiger Router für disaggregierte Bereitstellung hinzugefügt
  • Uneingeschränkte Aufmerksamkeit für die native Unterstützung – Group_rms_norm-Kernel hinzugefügt, um mehrere Eingaben in einem einzigen Operator zu normalisieren
  • Smart Router für das MoE-Modul hinzugefügt
  • Unterstützung der Kopfgröße 72 für den QKV-Vorverarbeitungskernel hinzugefügt – MNNVL MoE A2A-Unterstützung hinzugefügt
  • Optimierte große Einbettungstabellen in multimodalen Modellen – Unterstützte Top-K-Logprobs und prompt_logprobs in LLMAPI – Überlappungsplaner im TRT-Workflow über Executor API aktiviert

Infrastrukturänderungen

  • TRT-LLM-Team veröffentlicht offiziell docker-Bild auf NGC. – Das vorgefertigte TensorRT-LLM-Rad auf PyPI ist jetzt mit PyTorch 2.7.0 verknüpft, das die CXX11-ABI verwendet – Die abhängige TensorRT-Version wird auf 10.10.0 aktualisiert – Die abhängige CUDA-Version wird auf 12.9.0 aktualisiert – Die abhängige öffentliche PyTorch-Version wurde auf 2.7.0 aktualisiert – Die abhängige NVIDIA ModelOpt-Version wird auf 0.29.0 aktualisiert
  • Die abhängige NCCL-Version wird unter 2.25.1 gepflegt
  • Open-Source-XQA-Kernel – Die abhängige Datensatzversion wurde auf 3.1.0 aktualisiert
  • Migrieren Sie das Triton-Backend zum TensorRT-LLM-Repo zum TensorRT-LLM-Submodul
  • Downgrade der gcc-Toolset-Version von 13 auf 11

API Änderungen

  • [Breaking Change]: Planüberschneidungen standardmäßig aktivieren – Entfernen Sie veraltete GptSession/V1 aus dem TRT-Workflow – Legen Sie _AutoDeployLlmArgs als primäres Konfigurationsobjekt fest – Überschreiben von CLI-Argumenten mit der YAML-Datei in trtllm-serve zulassen
  • Einführung eines multimodalen Einbettungsfelds in LlmRequest

Behobene Probleme

– Behebung eines Hang-Fehlers, wenn der Kontextserver nicht über genügend Kapazität für den KV-Cache verfügt (#3095)

  • C++-Decoder-Synchronisierung in PyTorch behoben (#3106) – Fehler beim Erstellen eines Cuda-Streams als Standardparameter behoben, der beim Importieren initialisiert wird (#3764) – Fehler im Zusammenhang mit der Erstellung eines CUDA-Streams als Standardparameter behoben, der beim Import initialisiert wird (#3764)
  • Aufmerksamkeits-DP-Fehler beim Qwen3 MoE-Modell behoben (#4141) – Behebung illegaler Speicherzugriffe beim Ausführen von LLaMA 4 mit aktiviertem CUDA Graph (#4101) – Geplante Zustände zurücksetzen, um Speicherverlust in TrtllmAttentionWrapper zu vermeiden (#4227)

Bekannte Probleme

  • Unterstützung mehrerer GPU-Modelle auf RTX Pro 6000

TensorRT-LLM v0.20.0

Highlights

  • Scheduling overlap now on by default (breaking) — The most consequential behavioral change: overlap scheduling ships enabled, which alters request scheduling and can shift latency/throughput profiles for existing deployments. The flag was also corrected to enable_overlap_scheduler (#4433), so launch scripts still using the old name will silently lose control of it — audit your configs. In the same vein, the legacy GptSession/V1 TRT path is removed (V1 batching tests dropped in #4703) and _AutoDeployLlmArgs becomes the primary config object, so code built on the old session API or config shape needs migration.
  • Toolchain and dependency jump — This release rebases on PyTorch 2.7.0 (now built with the CXX11 ABI), TensorRT 10.10.0, CUDA 12.9.0, ModelOpt 0.29.0 and datasets 3.1.0, with NCCL held at 2.25.1. The CXX11 ABI switch is the one to watch: out-of-tree C++ extensions and custom plugins must be rebuilt against the new ABI or you'll hit symbol/link mismatches. GCC is downgraded 13→11 and the Triton backend moves into a submodule — both relevant if you build from source. NVIDIA now publishes an official release image on NGC (#4400), the safest route to a consistent stack.
  • Broader model and hardware coverage — Qwen3 (including a fix for missing mrope args in summary tasks, #4432), Nemotron-H, Eagle-3 speculative decoding for Llama4, Mistral Small 3.1 24B VLM, Gemma3-1b-it and HyperCLOVAX-SEED-Vision land, plus DeepSeek-R1 W4A8 on Hopper. RTX Pro 6000 (SM120) gains single-GPU FP8/NVFP4 support for Nemotron Super 49B (#4363, #4548), but multi-GPU on that part remains a known issue — plan single-GPU deployments for now.
  • PyTorch flow approaches parity — The PyTorch backend adds LoRA, return-logits, per-request stats and LogitsProcessor support, and adopts the new logprob definition. That last item is behaviorally significant: logprob values and their contract change, so downstream scoring or cross-backend comparisons should be revalidated rather than assumed identical to the TRT path.
  • New serving and performance levers — Long-context and MoE serving get piecewise CUDA graphs, MLA KV-cache reuse, a KV-cache-aware router for disaggregated serving, chunked context for FlashInfer, a smart MoE router and the overlap scheduler via the TRT executor API. LLM API adds top-K logprobs and prompt_logprobs, and LlmRequest gains a multimodal embedding field — important if you build multimodal serving on trtllm-serve.
  • Stability fixes worth the bump — Several correctness bugs close here: a hang when the context server lacks KV-cache capacity (#3095), illegal memory access with Llama4 under CUDA graphs (#4101), C++ decoder synchronization in PyTorch (#3106) and an attention data-parallel bug on Qwen3 MoE (#4141). If you run disaggregated serving or CUDA-graph-enabled Llama4, these alone justify upgrading.
