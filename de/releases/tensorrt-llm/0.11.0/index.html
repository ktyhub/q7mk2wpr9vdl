TensorRT-LLM v0.11.0

Hallo, Wir freuen uns sehr, die Version 0.11.0 von TensorRT-LLM bekannt zu geben. Dieses Update beinhaltet:

Hauptfunktionen und Verbesserungen

  • Unterstützte sehr lange Kontexte für LLaMA (siehe Abschnitt „Auswertung langer Kontexte“ in examples/llama/README.md).
  • Optimierung mit geringer Latenz – Es wurde eine Funktion zum Reduzieren der Norm hinzugefügt, die darauf abzielt, die ResidualAdd- und LayerNorm-Kernel nach AllReduce zu einem einzigen Kernel zusammenzuführen. Es wird empfohlen, diese Funktion zu aktivieren, wenn die Batch-Größe klein ist und die Zeit der Generierungsphase dominant ist. – FP8-Unterstützung zum GEMM-Plugin hinzugefügt, was in Fällen von Vorteil ist, in denen die Stapelgröße kleiner als 4 ist. – Ein verschmolzenes GEMM-SwiGLU-Plugin für FP8 auf SM90 hinzugefügt.
  • LoRA-Verbesserungen – Unterstützt die Ausführung von FP8 LLaMA mit FP16 LoRA-Kontrollpunkten. – Unterstützung für quantisiertes Basismodell und FP16/BF16 LoRA hinzugefügt.
    • SQ OOTB (- INT8 A/W) + FP16/BF16/FP32 LoRA
    • INT8/ INT4 Nur Gewicht (INT8 /W) + FP16/BF16/FP32 LoRA​
    • Nur-Gewicht-Gruppenweise + FP16/BF16/FP32 LoRA
    • LoRA-Unterstützung zu Qwen2 hinzugefügt, siehe Abschnitt „Modelle mit LoRA ausführen“ in examples/qwen/README.md.
    • Unterstützung für Phi-3-mini/small FP8 Base + FP16/BF16 LoRA hinzugefügt, siehe Abschnitt „Phi-3 mit LoRA ausführen“ in examples/phi/README.md. – Unterstützung für Starcoder-v2 FP8 Base + FP16/BF16 LoRA hinzugefügt, siehe Abschnitt „StarCoder2 mit LoRA ausführen“ in examples/gpt/README.md. – Encoder-Decoder-Modelle C++-Laufzeitverbesserungen
    • Unterstützt ausgelagerten KV-Cache und Inflight-Batching. (#800)
    • Unterstützte Tensorparallelität.
  • Unterstützte INT8-Quantisierung ohne Einbettungsschicht. – Standardmodell für Whisper auf distil-whisper/distil-large-v3 aktualisiert, dank des Beitrags von @IbrahimAmin1 in #1337.
  • Unterstützter automatischer Download des HuggingFace-Modells für den Python High-Level-API. – Unterstützte explizite Draft-Tokens für die Stapelverarbeitung während des Flugs. – Unterstützte lokale benutzerdefinierte Kalibrierungsdatensätze, dank des Beitrags von @DreamGenX in #1762.
  • Batch-Logits-Postprozessor hinzugefügt. – Hopper-QGMMA-Kernel zum XQA-JIT-Codepfad hinzugefügt. – Unterstützte Tensor-Parallelität und Experten-Parallelität gemeinsam für MoE aktiviert.
  • Unterstützung für Pipeline-Parallelitätsfälle, bei denen die Anzahl der Schichten nicht durch die PP-Größe geteilt werden kann. – numQueuedRequests zum Iterationsstatistikprotokoll des Executors API hinzugefügt. – iterLatencyMilliSec zum Iterationsstatistikprotokoll des Executors API hinzugefügt.
  • Fügen Sie den HuggingFace-Modellzoo aus der Community hinzu, dank des Beitrags von @matichon-vultureprime in #1674.

API Änderungen

– [BREAKING CHANGE] trtllm-build-Befehl – Whisper wurde auf einen einheitlichen Workflow migriert (Befehl trtllm-build), siehe Dokumente: examples/whisper/README.md.

  • max_batch_size im Befehl trtllm-build ist standardmäßig auf 256 umgestellt. – max_num_tokens im Befehl trtllm-build ist standardmäßig auf 8192 umgestellt. – max_output_len veraltet und max_seq_len hinzugefügt. – Unnötiges --weight_only_precision-Argument aus dem trtllm-build-Befehl entfernt. – Das Argument attention_qk_half_accumulation aus dem Befehl trtllm-build entfernt. – Argument use_context_fmha_for_generation aus Befehl trtllm-build entfernt. – Argument strongly_typed aus Befehl trtllm-build entfernt. – Der Standardwert von max_seq_len wird jetzt aus der HuggingFace-Moduskonfiguration gelesen.
  • C++-Laufzeit
    • [BREAKING CHANGE] free_gpu_memory_fraction von ModelRunnerCpp in kv_cache_free_gpu_memory_fraction umbenannt.
    • [BREAKING CHANGE] GptManager API überarbeitet
      • maxBeamWidth nach TrtGptModelOptionalParams verschoben.
      • schedulerConfig nach TrtGptModelOptionalParams verschoben.
    • Einige weitere Optionen zu ModelRunnerCpp hinzugefügt, darunter max_tokens_in_paged_kv_cache, kv_cache_enable_block_reuse und enable_chunked_context.
  • [BREAKING CHANGE] Python High-Level API – Die Klasse ModelConfig wurde entfernt und alle Optionen wurden in die Klasse LLM verschoben.
    • Die Klasse LLM wurde überarbeitet, siehe examples/high-level-api/README.md – Die am häufigsten verwendeten Optionen wurden in die explizite Arg-Liste verschoben und die Expertenoptionen in den Kwargs ausgeblendet. – model zur Annahme entweder des HuggingFace-Modellnamens oder des lokalen HuggingFace-Modells/TensorRT-LLM-Prüfpunkts/TensorRT-LLM-Engine verfügbar gemacht.
      • Unterstützt das Herunterladen des Modells vom HuggingFace-Modell-Hub. Derzeit werden nur Llama-Varianten unterstützt. – Unterstützt den Build-Cache zur Wiederverwendung der erstellten TensorRT-LLM-Engines, indem die Umgebungsvariable TLLM_HLAPI_BUILD_CACHE=1 festgelegt oder enable_build_cache=True an die Klasse LLM übergeben wird.
      • In den Kwargs werden Low-Level-Optionen wie BuildConfig, SchedulerConfig usw. verfügbar gemacht. Idealerweise sollten Sie in der Lage sein, Details zur Build- und Laufzeitphase zu konfigurieren.
    • LLM.generate() und LLM.generate_async() API überarbeitet.
      • SamplingConfig entfernt.
      • SamplingParams mit umfangreicheren Parametern hinzugefügt, siehe tensorrt_llm/hlapi/utils.py. – Das neue SamplingParams enthält und verwaltet Felder aus Python-Bindungen von SamplingConfig, OutputConfig usw.
      • LLM.generate()-Ausgabe als RequestOutput umgestaltet, siehe tensorrt_llm/hlapi/llm.py.
    • Die apps-Beispiele wurden aktualisiert, insbesondere durch Umschreiben von chat.py und fastapi_server.py unter Verwendung der LLM APIs. Einzelheiten finden Sie im examples/apps/README.md. – Der chat.py wurde aktualisiert, um Multi-Turn-Konversationen zu unterstützen, sodass Benutzer mit einem Model im Terminal chatten können. – fastapi_server.py behoben und mpirun in Multi-GPU-Szenarien überflüssig gemacht.
  • [BREAKING CHANGE] Vereinheitlichung der spekulativen Dekodierungskonfigurationen
    • Einführung von SpeculativeDecodingMode.h zur Auswahl zwischen verschiedenen spekulativen Decodierungstechniken. – Einführung der Basisklasse SpeculativeDecodingModule.h für spekulative Decodierungstechniken.
    • decodingMode.h entfernt.
  • gptManagerBenchmark – [BREAKING CHANGE] api im gptManagerBenchmark-Befehl ist jetzt standardmäßig executor.
    • Laufzeit max_batch_size hinzugefügt.
    • Laufzeit max_num_tokens hinzugefügt. – [BREAKING CHANGE] Dem LayerNorm-Modul wurde ein bias-Argument hinzugefügt und unterstützt die Normalisierung der Nicht-Bias-Schicht.
  • [BREAKING CHANGE] GptSession Python-Bindungen entfernt.

TensorRT-LLM v0.11.0

Highlights

  • High-level Python API overhaul (breaking) — ModelConfig is removed and all options fold into LLM, which now accepts an HF model name or a local HF/TRT-LLM checkpoint/engine and can auto-download from the Hub (currently Llama variants only). SamplingConfig is replaced by SamplingParams (absorbing OutputConfig fields) and generate()/generate_async() return RequestOutput instead of legacy structures, so output-unpacking code will break. Migration upside: TLLM_HLAPI_BUILD_CACHE=1 or enable_build_cache=True reuses compiled engines across runs, and the rewritten chat.py/fastapi_server.py drop the mpirun requirement for multi-GPU serving (examples/high-level-api/README.md).

  • trtllm-build defaults and flags changed (breaking) — max_batch_size now defaults to 256 and max_num_tokens to 8192; max_output_len is deprecated in favor of max_seq_len, whose default is read from the HF config. --weight_only_precision, attention_qk_half_accumulation, use_context_fmha_for_generation, and strongly_typed were removed, so scripts passing them fail outright — and scripts relying on old defaults will silently build different engines, so pin prior values explicitly for parity. Whisper also moves onto the unified trtllm-build flow (examples/whisper/README.md).

  • C++ runtime API breaks — ModelRunnerCpp.free_gpu_memory_fraction is renamed to kv_cache_free_gpu_memory_fraction, GptManager's maxBeamWidth and schedulerConfig move into TrtGptModelOptionalParams, and the GptSession Python bindings are removed entirely. New ModelRunnerCpp options worth adopting: max_tokens_in_paged_kv_cache, kv_cache_enable_block_reuse, and enable_chunked_context.

  • Speculative decoding unification and misc breaks — decodingMode.h is deleted in favor of SpeculativeDecodingMode.h plus a new SpeculativeDecodingModule.h base class; gptManagerBenchmark now defaults api to executor (with runtime max_batch_size/max_num_tokens); and LayerNorm adds a bias argument for non-bias norms. Expect compile-time breakage for custom speculative-decoding implementations and benchmark scripts that assumed the old API default.

  • Throughput and capability wins — very-long-context LLaMA support; an FP8 GEMM plugin that helps batch sizes <4, a fused FP8 GEMM–SwiGLU kernel for SM90, and a reduce-norm fusion best when generation dominates at small batch. LoRA now runs on FP8/quantized bases (SmoothQuant, INT8/INT4 weight-only, group-wise) with FP16/BF16 adapters across LLaMA, Qwen2, Phi-3, and StarCoder2; MoE can combine tensor and expert parallelism, and pipeline parallelism tolerates layer counts not divisible by PP size. Encoder-decoder models gain paged KV cache and inflight batching (#800) plus tensor parallelism.

  • Correctness fixes and dependency jump — several silent-corruption bugs are fixed: bad outputs for batch>1 and with use_fp8_context_fmha (#1539), broken inflight batching for FP8 Llama/Mixtral (#1738), and occasional invalid tokens from Top-P sampling (#1590), all strong upgrade reasons. The stack moves to TensorRT 10.1.0, CUDA 12.4.1, PyTorch 2.3.1, ModelOpt v0.13.0, and 24.05 base images, so revalidate container alignment. Known issue: importing under Windows conda can fail with an access-violation OSError.

Hi,

We are very pleased to announce the 0.11.0 version of TensorRT-LLM. This update includes:

Key Features and Enhancements

  • Supported very long context for LLaMA (see “Long context evaluation” section in examples/llama/README.md).
  • Low latency optimization
    • Added a reduce-norm feature which aims to fuse the ResidualAdd and LayerNorm kernels after AllReduce into a single kernel, which is recommended to be enabled when the batch size is small and the generation phase time is dominant.
    • Added FP8 support to the GEMM plugin, which benefits the cases when batch size is smaller than 4.
    • Added a fused GEMM-SwiGLU plugin for FP8 on SM90.
  • LoRA enhancements
    • Supported running FP8 LLaMA with FP16 LoRA checkpoints.
    • Added support for quantized base model and FP16/BF16 LoRA.
      • SQ OOTB (- INT8 A/W) + FP16/BF16/FP32 LoRA​
      • INT8/ INT4 Weight-Only (INT8 /W) + FP16/BF16/FP32 LoRA​
      • Weight-Only Group-wise + FP16/BF16/FP32 LoRA
    • Added LoRA support to Qwen2, see “Run models with LoRA” section in examples/qwen/README.md.
    • Added support for Phi-3-mini/small FP8 base + FP16/BF16 LoRA, see “Run Phi-3 with LoRA” section in examples/phi/README.md.
    • Added support for starcoder-v2 FP8 base + FP16/BF16 LoRA, see “Run StarCoder2 with LoRA” section in examples/gpt/README.md.
  • Encoder-decoder models C++ runtime enhancements
    • Supported paged KV cache and inflight batching. (#800)
    • Supported tensor parallelism.
  • Supported INT8 quantization with embedding layer excluded.
  • Updated default model for Whisper to distil-whisper/distil-large-v3, thanks to the contribution from @IbrahimAmin1 in #1337.
  • Supported HuggingFace model automatically download for the Python high level API.
  • Supported explicit draft tokens for in-flight batching.
  • Supported local custom calibration datasets, thanks to the contribution from @DreamGenX in #1762.
  • Added batched logits post processor.
  • Added Hopper qgmma kernel to XQA JIT codepath.
  • Supported tensor parallelism and expert parallelism enabled together for MoE.
  • Supported the pipeline parallelism cases when the number of layers cannot be divided by PP size.
  • Added numQueuedRequests to the iteration stats log of the executor API.
  • Added iterLatencyMilliSec to the iteration stats log of the executor API.
  • Add HuggingFace model zoo from the community, thanks to the contribution from @matichon-vultureprime in #1674.

API Changes

  • [BREAKING CHANGE] trtllm-build command
    • Migrated Whisper to unified workflow (trtllm-build command), see documents: examples/whisper/README.md.
    • max_batch_size in trtllm-build command is switched to 256 by default.
    • max_num_tokens in trtllm-build command is switched to 8192 by default.
    • Deprecated max_output_len and added max_seq_len.
    • Removed unnecessary --weight_only_precision argument from trtllm-build command.
    • Removed attention_qk_half_accumulation argument from trtllm-build command.
    • Removed use_context_fmha_for_generation argument from trtllm-build command.
    • Removed strongly_typed argument from trtllm-build command.
    • The default value of max_seq_len reads from the HuggingFace mode config now.
  • C++ runtime
    • [BREAKING CHANGE] Renamed free_gpu_memory_fraction in ModelRunnerCpp to kv_cache_free_gpu_memory_fraction.
    • [BREAKING CHANGE] Refactored GptManager API
      • Moved maxBeamWidth into TrtGptModelOptionalParams.
      • Moved schedulerConfig into TrtGptModelOptionalParams.
    • Added some more options to ModelRunnerCpp, including max_tokens_in_paged_kv_cache, kv_cache_enable_block_reuse and enable_chunked_context.
  • [BREAKING CHANGE] Python high-level API
    • Removed the ModelConfig class, and all the options are moved to LLM class.
    • Refactored the LLM class, please refer to examples/high-level-api/README.md
      • Moved the most commonly used options in the explicit arg-list, and hidden the expert options in the kwargs.
      • Exposed model to accept either HuggingFace model name or local HuggingFace model/TensorRT-LLM checkpoint/TensorRT-LLM engine.
      • Support downloading model from HuggingFace model hub, currently only Llama variants are supported.
      • Support build cache to reuse the built TensorRT-LLM engines by setting environment variable TLLM_HLAPI_BUILD_CACHE=1 or passing enable_build_cache=True to LLM class.
      • Exposed low-level options including BuildConfig, SchedulerConfig and so on in the kwargs, ideally you should be able to configure details about the build and runtime phase.
    • Refactored LLM.generate() and LLM.generate_async() API.
      • Removed SamplingConfig.
      • Added SamplingParams with more extensive parameters, see tensorrt_llm/hlapi/utils.py.
        • The new SamplingParams contains and manages fields from Python bindings of SamplingConfig, OutputConfig, and so on.
      • Refactored LLM.generate() output as RequestOutput, see tensorrt_llm/hlapi/llm.py.
    • Updated the apps examples, specially by rewriting both chat.py and fastapi_server.py using the LLM APIs, please refer to the examples/apps/README.md for details.
      • Updated the chat.py to support multi-turn conversation, allowing users to chat with a model in the terminal.
      • Fixed the fastapi_server.py and eliminate the need for mpirun in multi-GPU scenarios.
  • [BREAKING CHANGE] Speculative decoding configurations unification
    • Introduction of SpeculativeDecodingMode.h to choose between different speculative decoding techniques.
    • Introduction of SpeculativeDecodingModule.h base class for speculative decoding techniques.
    • Removed decodingMode.h.
  • gptManagerBenchmark
    • [BREAKING CHANGE] api in gptManagerBenchmark command is executor by default now.
    • Added a runtime max_batch_size.
    • Added a runtime max_num_tokens.
  • [BREAKING CHANGE] Added a bias argument to the LayerNorm module, and supports non-bias layer normalization.
  • [BREAKING CHANGE] Removed GptSession Python bindings.

Infrastructure Changes

  • Base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.05-py3.
  • Base Docker image for TensorRT-LLM backend is updated to nvcr.io/nvidia/tritonserver:24.05-py3.
  • The dependent TensorRT version is updated to 10.1.0.
  • The dependent CUDA version is updated to 12.4.1.
  • The dependent PyTorch version is updated to 2.3.1.
  • The dependent ModelOpt version is updated to v0.13.0.

Known Issues

  • In a conda environment on Windows, installation of TensorRT-LLM may succeed. However, when importing the library in Python, you may receive an error message of OSError: exception: access violation reading 0x0000000000000000. This issue is under investigation.

Currently, there are two key branches in the project:

  • The rel branch is the stable branch for the release of TensorRT-LLM. It has been QA-ed and carefully tested.
  • The main branch is the dev branch. It is more experimental.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The rel branch will be updated less frequently, and the exact frequencies depend on your feedback.
