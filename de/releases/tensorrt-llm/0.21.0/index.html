TensorRT-LLM v0.21.0

TensorRT-LLM-Version 0.21.0

Hauptfunktionen und Verbesserungen

  • Modellunterstützung
    • Gemma3 VLM-Unterstützung hinzugefügt
  • Funktionen
    • Umfangreiche EP-Unterstützung hinzugefügt
    • Integration von NIXL in die Kommunikationsschicht des disaggregierten Dienstes – Fabric-Speicherunterstützung für KV-Cache-Übertragung hinzugefügt
    • MCP in ScaffoldingLLM hinzugefügt
    • Unterstützung für w4a8_mxfp4_fp8-Quantisierung hinzugefügt
    • Unterstützung für die zeilenweise Quantisierung von fp8 hinzugefügt
    • Unterstützung für Generierungsprotokolle im TRTLLM Sampler hinzugefügt
    • Unterstützung für Protokollprobleme im TRTLLM Sampler hinzugefügt
    • Optimierter TRTLLM-Sampler mit Einzelstrahl und Einzelschritt – Disaggregierte Bereitstellung für Qwen-3 aktiviert
    • EAGLE3-Unterstützung für Qwen-3 hinzugefügt
    • Fusionierte Finalisierung und Allreduzierung für das Qwen-MoE-Modell
    • Überarbeitetes Fused MoE-Modul – Unterstützung für gebündelte Aufmerksamkeit für Blackwell und Hopper hinzugefügt – Einführung von Sliding-Window-Aufmerksamkeitskernen für die Generierungsphase auf Blackwell – Aktualisierte DeepSeek FP8 TRT-LLM Gen-Cubins, um die Leistung in Szenarios mit großen Batches zu verbessern – FP8-Block-Scale-GEMM-Unterstützung für SM89 hinzugefügt
    • Überlappungsplaner zwischen Entwurfsweiterleitungen aktiviert
    • Unterstützung für stückweise Cuda-Graphen für MLA hinzugefügt
    • Modellunabhängiger einmotoriger Eagle3 hinzugefügt – Finalize + Allreduce + Add + RMSnorm-Fusion aktiviert
    • Integriertes TRT-LLM Gen FP8 Blockscale MoE mit Pytorch-Workflow-Kernel-Autotuner – Unterstützung für die disaggregierte Bereitstellung von Eagle3 + in einem spekulativen Dekodierungsfluss mit zwei Modellen hinzugefügt
    • Validierte Llama 3.1-Modelle auf H200 NVL
  • Benchmark:
    • Benchmark-Skript all_reduce.py zum Testen hinzugefügt – Strahlbreite zum Befehl „trtllm-bench latency“ hinzugefügt – Fehler bei trtllm-bench iter_stats und cuda_graph_batch_sizes behoben – Trtllm-bench wurde aktiviert, um LoRA auszuführen und grundlegende E2E-Leistungstestfunktionen für LoRA hinzuzufügen
    • Unterstützt post_proc für Bench – Option no_kv_cache_reuse und Streaming-Unterstützung für trtllm Serve Bench hinzugefügt

Infrastrukturänderungen

– Das Basisbild Docker für TensorRT-LLM wird auf nvcr.io/nvidia/pytorch:25.05-py3 aktualisiert. – Das Basisbild Docker für das TensorRT-LLM-Backend wird auf nvcr.io/nvidia/tritonserver:25.05-py3 aktualisiert. – Die abhängige öffentliche PyTorch-Version wurde auf 2.7.1 aktualisiert. – Die abhängige TensorRT-Version wird auf 10.11 aktualisiert. – Die abhängige NVIDIA ModelOpt-Version wurde auf 0.31 aktualisiert. – Die abhängige NCCL-Version wird auf 2.27.5 aktualisiert.

API Änderungen

– Legen Sie _AutoDeployLlmArgs als primäres Konfigurationsobjekt fest

  • Decoder-Anfrage von der Decoder-Schnittstelle entfernt
  • Torch_compile_config in llm args verbessert – Das redundante Feld „use_kv_cache“ wurde aus PytorchConfig entfernt – Allreduce_strategy von Committed api in die Referenz verschoben

Behobene Probleme

– Das Aufhängen des disaggregierten Dienstes wurde behoben, wenn MNNVL Two-Shot AllReduce aktiviert ist (#4678)

  • EP-Load-Balancer mit MTP-Layer und Routenversatz durch EP-Rang behoben (#4767)
  • Cuda-Graph-Padding für die Spezifikationsdekodierung behoben (#4853) – Problem mit dem langen Kontext von Lama 4 behoben (#4809)
  • Berechnung von max_num_sequences mit Überlappungsplanung korrigiert (#4532)
  • Chunked Prefill + Overlap-Planung behoben (#5761) – Problem mit dem Aufhängen von trtllm-bench aufgrund von LLM API IPC behoben (#4798) – Fehler „Index außerhalb der Grenzen“ bei der Spezifikationsdekodierung behoben (#5954)
  • Unzulässiger MTP-Speicherzugriff beim Cuda-Graph-Aufwärmen behoben (#5947) – Fehler „Keine freien Slots“ mit Spec Decode + Disagg behoben (#5975)
  • Einmalige Größe des Aufmerksamkeitsfensters für Gemma3 1B korrigiert (#5564)

Bekannte Probleme

  • precision/test_cli_flow::TestGpt2::test_beam_search_large ist defekt. – Die gleichzeitige Aktivierung der disaggregierten Bereitstellung, des MTP und des Überlappungsplaners kann zu Genauigkeitsproblemen führen. – In 0.21 wurde vollständige Chunked-Attention-Unterstützung hinzugefügt, um sicherzustellen, dass das LLaMA4-Modell funktional mit einer seq-Länge von > 8 KB ausgeführt werden kann, während es aufgrund dieser Funktionsverbesserung zu einem bekannten Leistungsrückgang (betrifft nur das LLaMA4-Modell) bei Hopper kommt. Die Grundursache der Regression wurde bereits identifiziert und der Fix wird Teil der zukünftigen Version sein.

TensorRT-LLM v0.21.0

Highlights

  • Breaking API reshuffle in the LLM stack — Config construction needs attention on upgrade: _AutoDeployLlmArgs becomes the primary config object, the decoder request is removed from the decoder interface, the redundant use_kv_cache field is dropped from PytorchConfig, allreduce_strategy moves from the committed API to reference, and the monolithic LLM class is split into TorchLLM/TrtLLM (#4900). TorchCompileConfig fields also lose their torch_compile prefix (#5261), so any code reading those attributes by name will break. Budget migration time for config and wrapper code, not just a version bump.

  • Disaggregated serving moves toward production transport — NIXL is now integrated into the disaggregated service's communication layer, joined by fabric-memory KV cache transfer and large-scale EP support. Stability work targets real deployment hazards: a hang when MNNVL two-shot AllReduce is enabled (#4678) and the "no free slots" failure under spec-decode + disagg (#5975) are fixed. Watch out for the documented accuracy problem when disaggregated serving, MTP, and the overlap scheduler are enabled together — that combination is not yet safe.

  • Speculative decoding gets a broader, sturdier footing — EAGLE3 lands for Qwen3 (#5206), alongside a model-agnostic one-engine EAGLE3 path and overlap scheduling between draft forwards; draft-target decoding also moves into the new framework (#4558). The long tail of correctness fixes matters more than the headline features here: CUDA-graph padding (#4853), an index-out-of-bounds in spec decoding (#5954), and an MTP illegal-memory-access during graph warmup (#5947) are all addressed, with piecewise CUDA graph support for MLA (#4467) improving graph coverage. If you were holding off on spec decode for stability reasons, this is the release to re-evaluate.

  • Model and quantization coverage expands, with a Hopper caveat — New entry points include Gemma3 VLM, Qwen3 disaggregated serving, w4a8_mxfp4_fp8 and fp8 rowwise quantization, FP8 block-scale GEMM on SM89 (Ada), and TRT-LLM Gen FP8 block-scale MoE wired into the PyTorch autotuner (#5207). LLaMA4 >8K sequences now run via full chunked attention, but that functional win carries a known performance regression on Hopper affecting LLaMA4 only, with the fix deferred to a future release — benchmark before committing to H100-class deployments. Two off-by-one/context bugs worth noting are fixed: Gemma3 1B attention window size (#5564) and Llama 4 long context (#4809).

  • Container and dependency baseline jumps to NGC 25.05 — Base images move to pytorch:25.05-py3 and tritonserver:25.05-py3, with PyTorch 2.7.1, TensorRT 10.11, ModelOpt 0.31, and NCCL 2.27.5. This is the most likely source of environment-level breakage: custom Dockerfiles and pinned host NCCL/driver combinations should be rebuilt and revalidated rather than assumed compatible.

  • Sampler and benchmark tooling get developer-facing upgrades — The TRTLLM Sampler gains generation logits, log probs, and a single-beam/single-step performance optimization, while LlmResponse is reimplemented in Python to cut pybind host overhead (#5224). Benchmarking closes several gaps that previously distorted measurements: trtllm-bench gains beam-width control, LoRA end-to-end testing, no_kv_cache_reuse, and streaming, plus fixes to iter_stats and cuda_graph_batch_sizes errors and an IPC hang (#4798). Expect cleaner perf data, but note that old benchmark scripts may need flag updates.
