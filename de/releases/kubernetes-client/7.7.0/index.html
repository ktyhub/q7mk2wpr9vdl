kubernetes-client v7.7.0

Fehler

  • Fix #7747: (mockwebserver) vermeidet RejectedExecutionException in MockWebServer#shutdown() – linearisiert die Schließsequenz, um das Rennen zwischen httpClose-Listener und Wait zu entfernen, und macht Shutdown() idempotent gegen wiederholte Aufrufe (z. B. JUnit @Nested afterAll-Kaskaden). – Fix #7734: (Mockwebserver) Vermeiden Sie das Senden von Content-Length zusammen mit Transfer-Encoding für Chunk-Antworten – Fix #7716: (Informer) SerialExecutor.execute() kehrt jetzt sofort nach dem Herunterfahren zurück – es wird kein Wrapper angeboten, ScheduleNext() wird nicht aufgerufen und der zugrunde liegende Executor wird nicht berührt, wodurch ein von SharedProcessor.distribute(...) nach stop() aufgedecktes NPE-Race nach dem Stopp behoben wird. – Fix Nr. 7702: ExecWebSocketListener.onError umschließt WebSocketHandshakeException jetzt über den verkettenden Konstruktor KubernetesClientException anstelle von Post-hoc initCause – Handshake-Fehler mit einer Upgrade-Antwort ungleich Null lösen IllegalStateException nicht mehr synchron aus, sodass onFailure/exitCode den analysierten Status und die ursprüngliche Handshake-Ausnahme als Ursache erhalten – Fix #7686: (httpclient-vertx-5) StackBasedRecursionGuard.enter() erhöht nicht mehr die Tiefe, wenn die Eingabe verweigert wird, und behebt eine endlose runOnContext-Schleife, die InputStreamReadStream-Uploads aufgrund von CPU-Konflikten blockierte – Fix Nr. 7700: ExecWebSocketListener.onError verschiebt jetzt die Fehlerbehandlung durch den SerialExecutor, sodass eine ausstehende Channel-3-Exit-Status-Aufgabe zuerst ausgeführt wird und der analysierte Exit-Code erhalten bleibt, anstatt durch eine Peer-Close-Ausnahme überschrieben zu werden – Fix #7698: (httpclient-vertx-5) InputStreamReadStream löst jetzt endHandler aus, wenn es registriert wird, nachdem das Endsignal bereits übermittelt wurde, wodurch ein Rennen um leere/schnelle Streams behoben wird – Fix Nr. 7696: (httpclient-vertx) Löschen Sie den Antwort-Ausnahmehandler vor dem Zurücksetzen in cancel(), um zu verhindern, dass StreamResetException mit zukünftigen Abbrüchen überläuft – Fix Nr. 7695: ExecWebSocketListener verzögert jetzt die ExitCode-Vervollständigung durch den SerialExecutor, sodass ausstehende asynchrone stdout/stderr-Schreibvorgänge vor den Exit-Signalen geleert werden – Fix #7632: Java-Generator setzt jetzt HTML-Escapezeichen für <, > und & in CRD-Beschreibungen, um gültiges Javadoc zu erstellen – Fix #7543: ProcessInlineDuplicateFields korrigiert, um verschachtelte Inline-Einbettungen rekursiv aufzulösen – Fix #7450: StandardHttpClient.shouldRetry() führt bei Vert.x HttpClosedException keinen erneuten Versuch durch – Fix #7350: Falsches Callback-Timing bei der Leaderelection führt zum Dual-Leader – Fix #7265: Behebung des vorübergehenden Entfernens von Indexeinträgen aus Informer-Caches

Verbesserungen

– Fix #7426: Fügen Sie HasMetadata#isSameResource hinzu, um zu testen, ob zwei HasMetadata-Instanzen auf dieselbe logische Clusterressource verweisen, mit einem optionalen strikten Modus, der auch eine Übereinstimmung von Art und Ressourcenversion erfordert – Fix #7662: (mockwebserver) neuer MockWebServer#setHttp2ClearTextEnabled(boolean)-Setter zum Deaktivieren des HTTP/2-Klartext-Upgrades (h2c). – Fix #7522: Abhängigkeitsverwaltung für kubernetes-httpclient-okhttp verbessern – Fix Nr. 7550: Fügen Sie eine ResourceEventHandler-onList-Methode hinzu und onNothing ist veraltet – Fix #6922: addOwnerReference-Variante hinzufügen, um Controller- und blockOwnerDeletion-Felder festzulegen – Fix #3396: (mockwebserver) Erweitern Sie die Generierung selbstsignierter Zertifikate um die Einbeziehung von Subject Alternative Names (SANs) für eine ordnungsgemäße TLS-Überprüfung durch moderne clients – Fix Nr. 6923: Sorgen Sie dafür, dass das crd-generator-maven-plugin Toolchain-fähig ist

kubernetes-client v7.7.0

Bugs

  • Fix #7747: (mockwebserver) avoid RejectedExecutionException in MockWebServer#shutdown() — linearize close sequence to remove the httpClose-listener vs await race, and make shutdown() idempotent against repeated calls (e.g. JUnit @Nested afterAll cascades)
  • Fix #7734: (mockwebserver) avoid sending Content-Length together with Transfer-Encoding for chunked responses
  • Fix #7716: (informer) SerialExecutor.execute() now returns immediately after shutdown — no wrapper is offered, scheduleNext() is not called, and the underlying executor is not touched, fixing a post-stop NPE race exposed by SharedProcessor.distribute(...) after stop()
  • Fix #7702: ExecWebSocketListener.onError now wraps WebSocketHandshakeException via the chaining KubernetesClientException constructor instead of post-hoc initCause — handshake failures with a non-null upgrade response no longer throw IllegalStateException synchronously, so onFailure/exitCode receive the parsed Status and the original handshake exception as the cause
  • Fix #7686: (httpclient-vertx-5) StackBasedRecursionGuard.enter() no longer increments depth when refusing entry, fixing an infinite runOnContext loop that stalled InputStreamReadStream uploads under CPU contention
  • Fix #7700: ExecWebSocketListener.onError now defers failure handling through the SerialExecutor so a pending channel-3 exit-status task runs first and the parsed exit code is preserved instead of being overwritten by a peer-close exception
  • Fix #7698: (httpclient-vertx-5) InputStreamReadStream now fires endHandler when registered after the end signal has already been delivered, fixing a race for empty/fast streams
  • Fix #7696: (httpclient-vertx) clear response exception handler before reset in cancel() to prevent StreamResetException from racing with future cancellation
  • Fix #7695: ExecWebSocketListener now defers exitCode completion through the SerialExecutor so pending stdout/stderr async writes are flushed before exit signals
  • Fix #7632: java-generator now HTML-escapes <, >, and & in CRD descriptions to produce valid Javadoc
  • Fix #7543: fix processInlineDuplicateFields to recursively resolve nested inline embeds
  • Fix #7450: StandardHttpClient.shouldRetry() does not retry on Vert.x HttpClosedException
  • Fix #7350: Improper callback timing in leaderelection leads to the dual-leader
  • Fix #7265: fix ephemeral removal of index entries from informer caches

Improvements

  • Fix #7426: add HasMetadata#isSameResource to test whether two HasMetadata instances point to the same logical cluster resource, with an optional strict mode that also requires matching kind and resourceVersion
  • Fix #7662: (mockwebserver) new MockWebServer#setHttp2ClearTextEnabled(boolean) setter to opt out of HTTP/2 cleartext (h2c) upgrade
  • Fix #7522: improve dependency management for kubernetes-httpclient-okhttp
  • Fix #7550: add a ResourceEventHandler onList method and deprecated onNothing
  • Fix #6922: add addOwnerReference variant to set controller and blockOwnerDeletion fields
  • Fix #3396: (mockwebserver) Enhance self-signed certificate generation to include Subject Alternative Names (SANs) for proper TLS verification by modern clients
  • Fix #6923: Make the crd-generator-maven-plugin be toolchain aware

  • Fix #7544: cluster-api model classes moved from package io.fabric8.kubernetes.api.model.clusterapi.v1beta1 to io.fabric8.kubernetes.api.model.clusterapi.core.v1beta1 (following upstream cluster-api v1.11+ API reorganization)
