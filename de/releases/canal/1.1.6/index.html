Kanalkanal-1.1.6

Neue Funktionen

  1. Unterstützen Sie das Abonnement und die Nutzung von PolarDB-X 2.0 binlog
    • PolarDB-X ist eine cloudnative verteilte Datenbank, die unabhängig von Alibaba entwickelt wurde. Das kürzlich eingeführte globale Binlog ist vollständig kompatibel mit dem Binlog-Protokoll mysql [Referenzdokument] (https://help.aliyun.com/document_detail/207719.html).
    • Der Kanal kann das PolarDB-X-Binlog-Docking nativ unterstützen und unterstützt mehrere Modi wie TCP/MQ/Adapter #3494 vollständig
  2. Puslar MQ-Unterstützung #3791 #4060 hinzugefügt
  3. Adapter zur Unterstützung von TableStore #3754 hinzugefügt
  4. Kompatibel mit der neuen Version von MySQL8.0 (8.0.29), z. B. versteckte Spalten, Typtypen usw., #3976

Wichtige Optimierung

  1. Wechseln Sie fastjson auf Version 2.0.2 und aktualisieren Sie Druid auf Version 1.2.10
  2. Beheben Sie zugehörige Probleme beim Parsen von DDL-Anweisungen in Tabelle Meta #3839 #3840 #3954 #3900
  3. Das Problem, dass Tabellenmeta beim Speichern historischer Versionen #3693 nicht korrekt mit den Filterbedingungen übereinstimmen konnte, wurde behoben
  4. Korrigieren Sie, dass der Kafka-Connector die Umgebungsvariablen Nr. 3829 liest
  5. Beheben Sie das Problem des Startfehlers des ES-Adapters in einigen Szenarien #3466 #3144 #3684
  6. Aktualisieren Sie jvm gc auf den G1-Algorithmus #4014
  7. Beheben Sie den Synchronisierungsfehler, der durch Schlüsselwörter unter RDB-Synchronisierung #2783 #3984 verursacht wurde
  8. Beheben Sie das Problem mit gleichzeitigen Threads unter Einzelmaschine und mehreren Instanzen des Adapters Nr. 3923

Kleine Anforderungen und Fehlerbehebung

  1. Beheben Sie das Nullzeigerproblem in CanalServer.get() #4027
  2. Beheben Sie das Parallelitätsproblem beim Instanzstart im Admin-Modus #4018
  3. Korrigieren Sie die 6-stellige sichere Passwortüberprüfung im Admin-Modus #3877
  4. Beheben Sie die Nullzeiger-Ausnahme beim Abrufen von Tabellenmeta in mysql 8.0 #3538
  5. Beheben Sie das negative Zeitproblem des mysql-Zeittyps #4178
  6. Korrigieren Sie die Überwachungskonfiguration Nr. 3576 des docker-Bildexporters des Canal-Servers
  7. Korrigieren Sie den Start im lokalen Modus, der mit Canal-Server unter Windows #3484 kompatibel ist
  8. Setzen Sie Guava Version 18.0 zurück, um mit dem Adaptermodus Nr. 3880 kompatibel zu sein
  9. Beheben Sie die Ausnahme beim Abrufen des Indexnamens unter ES-Synchronisierung #4122
  10. Beheben Sie das Problem zweier Join-Tabellen unter ES-Synchronisierung #4161
  11. Optimieren Sie die Protokolldruckkonfiguration #3329 von rocketmq

Englisches Original / English original

canal canal-1.1.6

Highlights

  • PolarDB-X 2.0 CDC — Canal can now consume PolarDB-X 2.0 global binlog through its MySQL-compatible protocol using TCP, MQ, or adapter paths (#3494). This brings a distributed SQL source into existing Canal pipelines; validate DDL and schema-history behavior before cutting over production workloads.
  • Pulsar and TableStore integrations — Adds Apache Pulsar MQ support (#3791, #4060) and a TableStore adapter (#3754), expanding options for event distribution and downstream writes. Verify connector configuration and TableStore schema mappings during rollout.
  • MySQL 8.0.29 and schema-metadata fixes — Supports hidden columns and newer type metadata (#3976), while fixing DDL parsing (#3839, #3840, #3954, #3900), historical-version filter matching (#3693), and negative TIME values (#4178). These changes reduce schema-history mismatches and ingestion failures when replaying or filtering changes.
  • RDB synchronization and operational hardening — Fixes keyword-related RDB failures (#2783, #3984), admin-instance startup races (#4018), CanalServer.get() null pointers (#4027), and adapter multi-instance threading (#3923). Review the admin-mode six-character password validation change (#3877) against existing credentials before upgrading.
  • Dependency and JVM migration — FastJSON moves to 2.0.2, Druid to 1.2.10, and Guava is rolled back to 18.0 for adapter compatibility (#3880); JVM GC switches to G1 (#4014). Custom adapters directly using FastJSON may require package/API updates, and existing JVM heap and GC settings should be revalidated in staging.
  • Breaking changes — None explicitly declared; custom integrations still require compatibility checks against the dependency and JVM changes.

功能新增

  1. 支持PolarDB-X 2.0 binlog的订阅和消费
    • PolarDB-X是阿里巴巴自主研发的云原生分布式数据库，近期推出全局Binlog可完全兼容mysql binlog协议 参考文档
    • canal可原生支持PolarDB-X binlog对接,全面支持tcp/MQ/adapter等多种模式 #3494
  2. 新增Puslar MQ支持 #3791 #4060
  3. 新增Adapter，支持TableStore #3754
  4. 兼容MySQL8.0新版本(8.0.29), 比如隐藏列、type类型等，#3976

重要优化

  1. 切换fastjson为2.0.2版本，以及升级druid为1.2.10版本
  2. 修复table meta中相关DDL语句解析问题 #3839 #3840 #3954 #3900
  3. 修复table meta在保存历史版本时无法正确匹配过滤条件 #3693
  4. 修复kafka connector读取env变量 #3829
  5. 修复ES Adapter部分场景启动失败问题 #3466 #3144 #3684
  6. 升级jvm gc为G1算法 #4014
  7. 修复RDB同步下的关键字引起的同步报错 #2783 #3984
  8. 修复adapter单机多实例下的并发线程问题 #3923

小需求&bugfix

  1. 修复CanalServer.get()出现空指针问题 #4027
  2. 修复admin模式下instance启动的并发问题 #4018
  3. 修复admin模式下的密码6位强校验 #3877
  4. 修复mysql 8.0获取table meta的空指针异常 #3538
  5. 修复mysql time类型的负值时间问题 #4178
  6. 修复canal-server的docker镜像exporter监控配置 #3576
  7. 修复windows下兼容canal-server的local模式启动 #3484
  8. 回滚guava版本18.0兼容adapter模式 #3880
  9. 修复es同步下通过索引名获取异常 #4122
  10. 修复es同步下两个join表的问题 #4161
  11. 优化rocketmq的日志打印配置 #3329
