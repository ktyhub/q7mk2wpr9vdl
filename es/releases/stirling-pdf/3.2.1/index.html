Stirling-PDF_0.33.1 Docker movimiento del centro a Stirlingtools v3.2.1

Versión más pequeña con algunas mejoras interesantes en el visor y el editor y correcciones de errores para anotaciones y compresión.

Las características clave son:

  • Soporte de teclas de flecha para el visor
  • Vista de página dual para admitir portadas
  • La lectura en voz alta ahora comienza en el texto seleccionado
  • Ahora puedes duplicar páginas en el editor de páginas (herramienta múltiple)
  • Optimizaciones de memoria
  • Etiquetar archivos PDF dañados y ofrecer reparación
  • Exportar comentarios PDF como CSV

Corrección de errores

  • Se corrigieron los casos en los que la compresión no se comprimía correctamente.
  • Se corrigieron varios problemas de anotación introducidos en 3.2.0.
  • Se solucionaron problemas con el modo de selección de herramientas predeterminado.

Stirling-PDF v3.2.1

Highlights

  • Viewer navigation and reading flow — Keyboard-driven review gets real support: left/right arrow paging (PR #7136), a cover-page option for dual-page view so a title page can stay solo before pages pair up (PR #8484), and read-aloud that now starts at the selected text instead of the document top (PR #8488). If your workflow is proofreading long documents, this release materially cuts the clicks between "find the passage" and "hear/see it."
  • Annotation regressions from 3.2.0 are repaired — Treat this as a correctness patch for anyone who adopted 3.2.0's annotation work: transparent shape fills and hollow defaults are fixed (PR #8574), the toolbar button now actually toggles annotation mode off (PR #8590), and PDF permission inspection plus annotation lifecycle regressions are corrected (PR #8566). On top of that, comments can be exported to CSV (PR #8487), giving you machine-readable review data for downstream QA or reporting pipelines rather than trapped-in-PDF notes.
  • Compression will no longer make files bigger — PR #8586 discards qpdf output when it grows the file and bumps the version to 3.2.1. This is a behavioral change worth scripting around: a "compress" call that previously returned a larger artifact now keeps the original, so automation that assumes compression always shrinks (or always produces a changed file) needs to handle the no-op case.
  • Page editor duplication and Markdown fidelity — The multi-tool page editor gains a per-page duplicate action with a Ctrl+D shortcut (PR #8559), which speeds up repetitive page construction. Separately, Markdown-to-PDF conversion now preserves line breaks inside code blocks (PR #8483) — important if you generate technical docs or release notes with code samples and were seeing them collapse into a single line.
  • Memory and damaged-file handling — Type3 font payloads are now lazy-loaded (PR #8584), reducing memory pressure for font-heavy documents, and damaged PDFs are explicitly labeled with a Repair offer (PR #8589) instead of failing opaquely — a better failure mode for untrusted or user-uploaded inputs.
  • Settings persistence and SaaS onboarding — Default tool picker mode and default view now persist across launches (PR #6827), so user preferences finally stick; on the SaaS side, first-time visitors are asked where to run Stirling (PR #8417) and team/authorities come from the Supabase user lookup (PR #8062), which matters if you integrate with or mirror the hosted deployment.

No breaking changes in this release.

Smaller release with some nice viewer and editor improvements and bug fixes for annotation and compression

Key features are:

  • Arrow key support for viewer
  • Dual page view to support cover pages
  • Read aloud now starts at the selected text
  • You can now duplicate pages in page editor (multi tool)
  • Memory optimisations
  • Label damaged PDFs and offer Repair
  • Export PDF comments as CSV

Bug fixes

  • Fixed cases were compression was not correctly compressing
  • Fixed various annotation issues introduced in 3.2.0
  • Fixed issues with default tool picker mode
