AutoGPT autogpt-platform-beta-v0.8.1

Highlights

  • Experts and reusable skills — This release adds 17 core/generalist experts, introduces Zara for go-to-market work, and folds the former senior-sales package into Max (#14636, #14713, #14794, #14798). Session skills now participate in capability search (#14779), installed and saved skills receive separate per-expert budgets (#14786), and the 150-skill limit is enforced atomically during publication (#14740, #14793)—important for concurrent catalog updates.

  • Feature flags, migration, and consent — A PostHog backend now sits behind the existing flag API, with Redis caching, Sentry flag context, and a script to recreate LaunchDarkly definitions and targeting (#14317, #14767, #14805, #14806). Self-hosted operators should provision PostHog/Redis and port existing flag configuration; FORCE_ALL_FLAGS enables all flags locally (#14742), while LaunchDarkly initialization now fails after 5 seconds instead of potentially stalling startup (#14694). PostHog analytics also now require Cookiebot consent (#14838).

  • Workspace files and AutoPilot — Nested folders, AutoPilot folder listing, and expert access to user-owned files enable more structured file workflows (#14773, #14774). Open folders persist in URLs (#14769), and Shift-click supports range selection (#14771); teams should review access to sensitive files now that experts can use them. The 20-attachment cap is enforced when files are added rather than at send time (#14770), so clients should surface that validation earlier.

  • Models, pricing, and MCP catalog — New options include Claude Opus 5.5, GPT-6 Sol/Luna (#14821), Qwen 3.8 Flash (#14757), Gemma 4 31B (#14743), Tencent Hy4 Preview (#14755), and Zapier in the official MCP catalog (#14753). Multiple OpenRouter display prices were corrected (#14746, #14776, #14796, #14820, #14825), and stale advanced-tier Opus defaults now target claude-opus-5 (#14819); verify pinned model IDs and cost expectations before adopting.

  • Sandboxing and execution reliability — Every E2B create/connect path now passes through an egress-pinned chokepoint (#14624), and exec_file paths are confined to the sandbox base (#14750), reducing escape and exfiltration risk. Identical retried tool requests now replay the previously accepted result instead of returning HTTP 409 (#14760), while structured 429 responses let BYOSUB clients reconnect correctly (#14602); integrations should handle these response semantics explicitly.

  • Breaking changes — None declared.
