#peft v0.19.0

Destacados

Esta versión de PEFT contiene nada menos que nueve nuevos métodos PEFT, que se describen a continuación. También contiene numerosas mejoras que deberían hacer que PEFT sea más útil para muchos usuarios.

Nuevos métodos

GraLoRA

@yeonjoon-jung01 agregó "GraLoRA: Adaptación granular de bajo rango para un ajuste fino de parámetros eficiente" a PEFT (#2851). Este método subdivide el peso base en bloques más pequeños y les aplica LoRA. Esta adaptación más granular promete aumentar la expresividad y mejorar el rendimiento, especialmente en los rangos más altos (64+), cerrando la brecha para un ajuste completo.

BD-LoRA

@Conzel contribuyó con BD-LoRA: "LoRA en diagonal de bloque para eliminar la sobrecarga de comunicación en el servicio Tensor Parallel LoRA" (#2895). Con BD-LoRA, los pesos LoRA se implementan en forma de bloque diagonal. Esto permite reducir la sobrecarga de comunicación cuando se utiliza el paralelismo tensorial (TP) y, por lo tanto, un servicio más rápido.

Hay una rama experimental para la compatibilidad con BD-LoRA en vLLM: vllm-project/vllm#28136.

Cartuchos

Gracias a @kashif, PEFT ahora también admite Cartuchos (#2953). El objetivo principal de este método es entrenar un prefijo para [comprimir un contexto largo a un tamaño corto] (https://hazyresearch.stanford.edu/blog/2025-06-08-cartridges) y así ahorrar tokens. En un nivel bajo, esto es similar a ajuste de prefijo. El RP también agregó una receta de ejemplo para comenzar rápidamente.

PVeRA

"PVeRA: Adaptación de matriz aleatoria basada en vectores probabilísticos" fue agregado a PEFT por @leofillioux en el n.º 2952. Es una extensión de VeRA, un método PEFT que utiliza el peso compartido entre capas para ser especialmente eficiente en los parámetros. PVeRA se basa en eso agregando un elemento probabilístico, tomando muestras de los parámetros compartidos y prometiendo un mejor rendimiento general.

PSOFT

@fei407 agregó PSOFT, "Ajuste fino ortogonal eficiente con adaptación del subespacio principal", a PEFT en el n.° 3037. Las técnicas de ajuste fino ortogonal como OFT y BOFT son buenas para preservar la estructura y, por tanto, las capacidades del modelo base subyacente. PSOFT mejora la eficiencia de esta técnica al limitar la adaptación al subespacio principal de bajo rango.

lirio

@yibozhong agregó Lily: "Adaptación interconectada de bajo rango entre capas" a PEFT en el n.° 2563. Lily es superficialmente similar a LoRA pero tiene un sofisticado esquema de intercambio de parámetros. Los parámetros A se comparten en bloques (por ejemplo, 4 capas q_proj consecutivas comparten la misma A). Hay un grupo de parámetros B que se comparte globalmente; los B reales se eligen de forma dependiente de los datos a través de un enrutador. Esto le permite a Lily usar rangos más altos que LoRA mientras mantiene un recuento bajo de parámetros entrenables.

MANÍ

En el n.° 3084, "PEANuT: Adaptación eficiente de parámetros con ajustes neuronales conscientes del peso" fue agregado a PEFT, nuevamente por @yibozhong. PEANuT agrega una pequeña red neuronal (los llamados ajustadores neuronales conscientes del peso) al modelo base. En comparación con LoRA, esto aumenta la expresividad para el mismo recuento de parámetros entrenables o permite reducir considerablemente el recuento de parámetros sin sacrificar la expresividad. Esto tiene el costo de un mayor requisito de memoria para el mismo recuento de parámetros y una menor velocidad.

PequeñaLoRA

Tenemos otro colaborador en serie en @kashif, que también contribuyó con TinyLoRA: "Aprender a razonar en 13 parámetros" en el n.º 3024. Este es un método PEFT que permite entrenar una cantidad extremadamente pequeña de parámetros, mucho menor de lo que se podría lograr incluso con LoRA rango 1. El documento muestra que, en particular con el aprendizaje por refuerzo, a menudo puede ser suficiente entrenar solo unos pocos parámetros para lograr buenos resultados.

AdamMSS

@LonglongaaaGo agregó "AdaMSS: Enfoque adaptable de múltiples subespacios para un ajuste fino de parámetros eficiente" a PEFT. Este método segmenta los pesos base del modelo en subespacios más pequeños destinados a realizar ajustes. Además, es posible asignar dinámicamente un presupuesto de parámetros más bajo a subespacios menos importantes durante el entrenamiento, similar a lo que hace AdaLoRA. Esto promete proporcionar una mayor expresividad y una mejor generalización que métodos PEFT similares.

Mejoras

Convertir adaptadores que no sean LoRA a LoRA

En el n.° 2939, agregamos funciones a PEFT para permitir [convertir puntos de control de muchos métodos que no son LoRA en puntos de control LoRA] (https://huggingface.co/docs/peft/main/en/package_reference/lora_conversion). Esto puede resultar útil porque muchos otros paquetes solo admiten LoRA pero no otros métodos PEFT, p. Difusores y vLLM. Con las nuevas herramientas de conversión, se pueden utilizar más métodos PEFT además de LoRA con esos paquetes. La conversión genera pérdidas, pero las pruebas empíricas demostraron que con un rango LoRA suficientemente alto, el error puede ser bastante bajo.

LoRA-GA

@sambhavnoobcoder agregó una nueva forma de inicializar los pesos de LoRA con "LoRA-GA: Adaptación de rango bajo con aproximación de gradiente" (#2926). Esto le permite inicializar los pesos de LoRA de una manera que alinee los gradientes con un ajuste completo y debería conducir a una convergencia de entrenamiento más rápida.

Reducir las dimensiones del intruso

En "LoRA vs ajuste fino completo: una ilusión de equivalencia", los autores demostraron que el ajuste fino de LoRA puede introducir las llamadas "dimensiones intrusas" que contribuyen al olvido. Ahora tenemos una función de utilidad para eliminar la dimensión del intruso en PEFT, reduce_intruder_dimension. Al invocar esto en un modelo LoRA ajustado, el olvido debería reducirse mientras que el rendimiento de la tarea ajustada debería permanecer casi igual.

Motor transformador

En el n.º 3048, @balvisio agregó compatibilidad con Transformer Engine, un método de cuantificación de NVIDIA, a PEFT.

Soporte paralelo de tensor

En una serie de relaciones públicas (#3079, #3091, #3096), @michaelbenayoun agregó soporte para [Paralelismo tensorial] (https://huggingface.co/docs/transformers/v5.4.0/en/perf_infer_gpu_multi#tensor-parallelism) a LoRA.

Mejoras en el control de peso

En muchos LLM, la incrustación y el cabezal LM tienen pesos vinculados para ahorrar en el recuento de parámetros. Sin embargo, esto puede dar lugar a situaciones complicadas al intentar ajustar esas capas. A través de una serie de PR (#2803, #2922, #2870, #2879, #3126), mejoramos la experiencia del usuario al hacerlo. En particular, los usuarios ahora pueden pasar ensure_weight_tying=True a su configuración PEFT para forzar que se mantenga la vinculación de peso. Consulte los [documentos PEFT sobre vinculación de peso] (https://huggingface.co/docs/peft/main/en/developer_guides/lora#weight-tying) para saber cómo se maneja ahora la vinculación de peso. Gracias a @romitjain, @sambhavnoobcoder y @Cursx por sus contribuciones.

Soporte de tipo flotante de baja precisión

#3055 hace que LoRA funcione con modelos base que usan flotadores de muy baja precisión como torch.float8_e4m3fn. Un ejemplo de eso sería MiniMax-M2.5.

Inicio cero para PrefixTuning

#3128 introduce el inicio cero en Prefix Tuning que, según nuestros puntos de referencia, redujo significativamente la variación del resultado y produjo una buena precisión de la tarea sin la necesidad de una ingeniería rápida.

Cuantización LoftQ + int8

Con el número 3088, la implementación de LoftQ ahora admite la corrección de errores para la cuantificación int8 sin utilizar umbrales de activación junto con la cuantificación nf4 ya existente.

Cambios

Eliminación de hueso

El método Bone PEFT se eliminó en el n.º 3115. Se indica a los usuarios que utilicen MiSS en su lugar, que es el reemplazo mejorado de Bone. Utilice este [script de conversión de Bone a MiSS] (https://github.com/huggingface/peft/blob/main/scripts/convert-bone-to-miss.py) si desea portar puntos de control de Bone antiguos.

AutoGPTQ y AutoAWQ

Estos dos métodos de cuantificación ahora usan GPTQModel como backend (#2932) gracias a @ZX-ModelCloud.

Manejo de requires_grad en modules_to_save

Anteriormente, PEFT habilitaba requires_grad en el módulo original si el modules_to_save correspondiente estaba deshabilitado. Esto casi nunca es deseable y así se solucionó. Aunque este cambio es técnicamente incompatible con versiones anteriores, es un caso de nicho extremo, por lo que no esperamos que ningún usuario se vea afectado negativamente.

peft v0.19.0

Highlights

This PEFT release contains no less than nine new PEFT methods, described below. It also contains numerous enhancements that should make PEFT more useful to many users.

New Methods

GraLoRA

@yeonjoon-jung01 added "GraLoRA: Granular Low-Rank Adaptation for Parameter-Efficient Fine-Tuning" to PEFT (#2851). This method subdivides the base weight into smaller blocks and applies LoRA to those. This more granular adaptation promises to increase expressiveness and improve performance, especially at higher ranks (64+), closing the gap to full fine-tuning.

BD-LoRA

@Conzel contributed BD-LoRA: "Block-Diagonal LoRA for Eliminating Communication Overhead in Tensor Parallel LoRA Serving" (#2895). With BD-LoRA, the LoRA weights are implemented in a block-diagonal way. This allows to reduce communication overhead when using tensor parallelism (TP) and thus faster serving.

There is an experiment branch for BD-LoRA support in vLLM: vllm-project/vllm#28136.

Cartridges

Thanks to @kashif, PEFT now also supports Cartridges (#2953). The main purpose of this method is to train a prefix to compress a long context to a short size and thus save on tokens. On a low level, this is similar to prefix tuning. The PR also added an example recipe to quickly get started.

PVeRA

"PVeRA: Probabilistic Vector-Based Random Matrix Adaptation" was added to PEFT by @leofillioux in #2952. It is an extension of VeRA, a PEFT method that uses weight sharing between layers to be especially parameter efficient. PVeRA builds on top of that by adding a probabilistic element, sampling from the shared parameters and promising better performance overall.

PSOFT

@fei407 added PSOFT, "Efficient Orthogonal Fine-Tuning with Principal Subspace Adaptation", to PEFT in #3037. Orthogonal fine-tuning techniques like OFT and BOFT are good at preserving the structure and thus capabilities of the underlying base model. PSOFT improves efficiency of this technique by constraining the adaptation to low-rank principal subspace.

Lily

@yibozhong added Lily: "Low-Rank Interconnected Adaptation across Layers" to PEFT in #2563. Lily is on the surface similar to LoRA but has a sophisticated parameter sharing scheme. The A parameters are shared blockwise (e.g. 4 consecutive q_proj layers share the same A). There is a pool of B parameters that is shared globally, the actual B's are chosen in a data-dependent way through a router. This allows Lily to use higher ranks than LoRA while maintaining a low trainable parameter count.

PEANuT

In #3084, "PEANuT: Parameter-Efficient Adaptation with Weight-aware Neural Tweakers" was added to PEFT, again by @yibozhong. PEANuT adds a small, neural net (so called weight-aware neural tweakers) to the base model. Compared to LoRA, this increases expressivity for the same trainable parameter count or allows to greatly lower the parameter count without sacrificing expressivity. This comes at the expensive of a higher memory requirement for the same parameter count and decreased speed.

TinyLoRA

We have another serial contributor in @kashif, who also contributed TinyLoRA: "Learning to Reason in 13 Parameters" in #3024. This is a PEFT method that allows to train an extremely small number of parameters, much lower than what could be achieved even with LoRA rank 1. The paper shows that in particular with reinforcement learning, it can often be enough to train just a few parameters to achieve good results.

AdaMSS

@LonglongaaaGo added "AdaMSS: Adaptive Multi-Subspace Approach for Parameter-Efficient Fine-Tuning" to PEFT. This method segments the base weights of the model into smaller subspaces that are targeted for fine-tuning. Moreover, it's possible to dynamically assign a lower parameter budget to less important subspaces during training, similar to what AdaLoRA does. This promises to provide higher expressiveness and better generalization than similar PEFT methods.

Enhancements

Convert non-LoRA adapters to LoRA

In #2939, we added functions to PEFT to allow converting checkpoints of many non-LoRA methods into LoRA checkpoints. This can be useful because many other packages support only LoRA but not other PEFT methods, e.g. Diffusers and vLLM. With the new conversions tools, more PEFT methods than just LoRA can thus be used with those packages. Conversion is lossy but empirical testing showed that with a sufficiently high LoRA rank, the error can be quite low.

LoRA-GA

@sambhavnoobcoder added a new way to initialize LoRA weights with "LoRA-GA: Low-Rank Adaptation with Gradient Approximation" (#2926). This allows you to initialize the LoRA weights in a way that aligns the gradients with full fine-tuning and should lead to faster training convergence.

Reducing intruder dimensions

In "LoRA vs Full Fine-tuning: An Illusion of Equivalence", the authors showed that LoRA fine-tuning can introduce so-called "intruder dimensions" which contribute to forgetting. We now have a utility function to remove intruder dimension in PEFT, reduce_intruder_dimension. When calling this on a fine-tuned LoRA model, forgetting should be reduced while the fine-tuned task performance should remain almost the same.

Transformer Engine

In #3048, @balvisio added support for Transformer Engine, a quantization method by NVIDIA, to PEFT.

Tensor Parallel Support

In a series of PRs (#3079, #3091, #3096), @michaelbenayoun added support for Tensor Parallelism to LoRA.

Weight tying improvements

In many LLMs, the embedding and the LM head have tied weights to save on parameter count. This can, however, lead to tricky situations when trying to fine-tune those layers. Through a series of PRs (#2803, #2922, #2870, #2879, #3126), we improved the user experience when doing so. Most notably, users can now pass ensure_weight_tying=True to their PEFT config to force weight tying to be upheld. Please check the PEFT weight tying docs for how weight tying is now being handled. Thanks to @romitjain, @sambhavnoobcoder, and @Cursx for their contributions.

Low precsion floating type support

#3055 makes LoRA work with base models that use very low precision floats like torch.float8_e4m3fn. An example of that would be MiniMax-M2.5.

Zero init for PrefixTuning

#3128 introduces zero init to Prefix Tuning which, according to our benchmarks, reduced the result variance significantly and yielded good task accuracy without the need for prompt engineering.

LoftQ + int8 quantization

With #3088 the LoftQ implementation now supports correcting errors for int8 quantization without utilizing activation thresholding alongside the already existing nf4 quantization.

Changes

Removal of Bone

The Bone PEFT method was removed in #3115. Users are directed to use MiSS instead, which is the improved replacement for Bone. Use this Bone-to-MiSS conversion script if you want to port old Bone checkpoints.

AutoGPTQ and AutoAWQ

These two quantization methods now use GPTQModel as their backend (#2932) thanks to @ZX-ModelCloud.

Handling of requires_grad in modules_to_save

Previously, PEFT would enable requires_grad on the original module if the corresponding modules_to_save was disabled. This is almost never desirable and was thus fixed. Although this change is technically backwards-incompatible, it's an extreme niche case, so we don't expect any user to be negatively affected by it.
