lighthouse v7.0.0

faro v7.0.0

#7.0.0 (2020-12-17) Changelog completo Lighthouse 7.0 incluye una serie de cambios programáticos importantes y nuevas auditorías en las categorías Accesibilidad y PWA. Hubo algunas mejoras en la precisión de los cálculos de las métricas, pero no se espera que las puntuaciones de rendimiento cambien significativamente en casi todos los sitios. Es posible que haya cambios mayores en las puntuaciones de Accesibilidad y PWA debido a las nuevas auditorías. Se espera que esta versión se envíe en DevTools de Chrome 89. Se publicó en PageSpeed Insights el 19 de febrero de 2021.

Cambios notables

  • Se toma una captura de pantalla de página completa y se utiliza para mejorar la experiencia de ver los detalles del elemento DOM. Ahora se mostrará una miniatura y clicking revela una caja de luz que muestra en qué parte de la página vivía el nodo DOM. Esta captura de pantalla aumenta el tamaño del Lighthouse JSON en ~33%. (#11769, #11768, #11829, #11846, #11852)
  • La Categoría PWA cambió de manera bastante significativa.
    • El grupo Instalable funciona enteramente con las comprobaciones de capacidad que habilitan los criterios instalables de Chrome. Estas son las mismas señales que se ven en el panel Manifiesto en Chrome DevTools. Como tal, la auditoría "Registra un trabajador de servicio..." se traslada al grupo PWA optimizado y la auditoría "Usa HTTPS" ahora se incluye como parte de la auditoría clave de "requisitos de instalación".
    • El grupo Rápido y fiable se ha evaporado en el aire. 🌬 Ahora que la auditoría renovada de "requisitos de instalación" incluye verificación de capacidad fuera de línea, hemos eliminado las auditorías dedicadas para verificar si la página actual y start_url responden con 200 cuando están fuera de línea. Por otra parte, se eliminó la auditoría "La carga de la página es lo suficientemente rápida en la red móvil". Si bien ya no forma parte de la sección PWA, recomendamos a las personas que crean una PWA que consulten la categoría Rendimiento para asegurarse de que su aplicación web sea rápida y agradable.
  • Una construcción nocturna de Lighthouse ahora está disponible como lighthouse@next en npm. Tenga en cuenta que, si bien las pruebas automatizadas pasan antes de su publicación, se espera que esta versión sea más inestable que las versiones regulares (#11792, #11805, #11810)
  • La biblioteca de pruebas de accesibilidad axe-core se actualizó a la última versión 4.1.1. Las auditorías de accesibilidad ahora son más rápidas, más sólidas e incluyen múltiples comprobaciones nuevas (#11661)
  • Lighthouse ejecuta una pequeña prueba comparativa al inicio y ahora incluirá una advertencia si la máquina de prueba parece tener poca potencia y puede estar afectando la precisión de las métricas de Lighthouse (#11350)
  • Se agregó la detección de Joomla y October CMS, por lo que las páginas de esas plataformas ahora recibirán asesoramiento personalizado sobre algunas auditorías de Lighthouse (#11788)

Nuevos contribuyentes

¡Gracias a Kohta Ito (@koh110) y Sam Stoelinga (@samos123) por sus primeras contribuciones!

🆕 Nuevas auditorías

  • La nueva auditoría de PWA installable-manifest, mencionada anteriormente, utiliza los propios criterios de instalación de Chrome para que siempre permanezca sincronizado con los requisitos de instalación (#11745)
  • third-party-facades busca incrustaciones de terceros en la página de prueba que puedan cargarse de forma diferida con una "fachada" estática. Si la inserción no es necesaria para la interacción inmediata de un usuario, considere usar una de las fachadas para acelerar la carga de la página (#11290)
  • Con la actualización de la versión ax vienen nuevas auditorías que garantizan nombres accesibles: aria-treeitem-name, aria-command-name, aria-tooltip-name, aria-meter-name y aria-progressbar-name (#11661)

♻️ Auditorías eliminadas

  • La actualización al último axe-core también elimina dos auditorías que no se verificaban mucho: layout-table y video-description (#11661)
  • Las auditorías works-offline y offline-start-url se eliminaron ya que sus comprobaciones ahora están cubiertas por la nueva implementación installable-manifest (#11806)
  • La auditoría load-fast-enough-for-pwa también se eliminó ya que las métricas de desempeño existentes de Lighthouse cubren con creces las necesidades allí (#11764)
  • without-javascript ha sido eliminado (#11711)

💥 Cambios importantes

  • Los ajustes de configuración de emulación de dispositivo y los indicadores CLI han cambiado para ser más claros y tener menos superposición. Si ha utilizado --emulated-form-factor u otra configuración relacionada con la emulación, deberá realizar cambios. La nueva configuración debería ser considerablemente más sencilla de usar con corredores Lighthouse personalizados que utilizan dispositivos reales, Puppeteer o aceleración a nivel de sistema. Consulte los documentos de emulación para obtener orientación sobre la migración. (#11779)
  • Mientras espera que la página se cargue por completo, Lighthouse ahora esperará si hay solicitudes de red activas de alta prioridad. En casos raros, como cuando la inicialización de la aplicación depende de un único XHR de retorno lento, algunas métricas de rendimiento pueden empeorar; sin embargo, las nuevas mediciones ahora son precisas. (#11738, #11851)
  • Se ha eliminado el soporte para el Nodo 10. La versión mínima requerida del Nodo ahora es 12 (#11656)

🤖💥 Cambios importantes para usuarios programáticos

Es poco probable que estos cambios afecten a los usuarios finales, pero pueden ser importantes si está escribiendo configuraciones personalizadas, complementos o procesando la salida de Lighthouse JSON.

  • ConsoleMessages es un [nuevo artefacto] (https://github.com/GoogleChrome/lighthouse/blob/a6738e0033e7e5ca308b97c1c36f298b7d399402/types/artifacts.d.ts#L753-L802) que es una combinación de los antiguos artefactos ConsoleMessages y RuntimeExceptions, con algunos datos ampliados sobre elementos registrados en la consola. RuntimeExceptions ha sido eliminado (#11663)
  • Los datos de "detalles del nodo" de DOM que anteriormente se encontraban distribuidos en los artefactos existentes ahora se recopilan en una propiedad NodeDetails en cada elemento (#11474, #11695, #11752)
  • El artefacto ImageElements ha sido simplificado para representar mejor los datos recopilados y cómo se utilizan (#11703, #11707, #11733)
  • Anteriormente, se permitía extends: true como alias para extends: 'lighthouse:default' para extender una configuración desde el archivo de configuración predeterminado de Lighthouse. La opción booleana se eliminó para preparar el camino para la extensión desde cualquier archivo de configuración válido (#11835)
  • Se eliminó una función nunca utilizada para pasar opciones de la configuración a los recopiladores para que sea compatible con cambios futuros (#11743)

lighthouse v7.0.0

7.0.0 (2020-12-17)

Full Changelog

Lighthouse 7.0 includes a number of programmatic breaking changes and new audits in the Accessibility and PWA categories. There were some improvements in the accuracy of metric calculations, but it is not expected that Performance scores will change significantly for almost all sites. There may be larger changes in Accessibility and PWA scores due to the new audits.

This release is expected to ship in the DevTools of Chrome 89. It went live on PageSpeed Insights on Feb 19, 2021.

Notable changes

  • A full-page screenshot is taken and used to improve the experience of viewing DOM element details. Now a thumbnail will be shown and clicking reveals a lightbox showing where in the page the DOM node lived. This screenshot increases the size of the Lighthouse JSON by ~33%. (#11769, #11768, #11829, #11846, #11852)
  • The PWA Category changed fairly significantly.
    • The Installable group is powered entirely by the capability checks that enable Chrome's installable criteria. These are the same signals seen in the Manifest pane in Chrome DevTools. As such, the "Registers a service worker…" audit moves to the PWA Optimized group, and the "Uses HTTPS" audit is now included as part of the key "installability requirements" audit.
    • The Fast and reliable group has evaporated into thin air. 🌬 Now that revamped "installability requirements" audit includes offline-capability checking, we've removed the dedicated audits for checking if the current page and start_url respond with 200 when offline. Separately, the "Page load is fast enough on mobile network" audit was removed—while it's no longer part of the PWA section, we encourage folks building a PWA to consult the Performance category to ensure their web app is speedy and delightful.
  • A nightly Lighthouse build is now available as lighthouse@next on npm. Note that while automated tests pass before publishing, it's expected that this version will be more unstable than the regular releases (#11792, #11805, #11810)
  • The accessibility-testing library axe-core has been updated to the latest 4.1.1 release. The accessibility audits are now faster, more robust, and include multiple new checks (#11661)
  • Lighthouse runs a small benchmark at startup, and will now include a warning if the test machine appears underpowered and may be affecting the accuracy of the Lighthouse metrics (#11350)
  • Joomla and October CMS detection has been added, so pages on those platforms will now get customized advice on some Lighthouse audits (#11788)

New contributors

Thanks to Kohta Ito (@koh110) and Sam Stoelinga (@samos123) for their first contributions!

🆕 New audits

  • The new installable-manifest PWA audit, mentioned above, uses Chrome's own installability criteria so it will always stay in sync with installability requirements (#11745)
  • third-party-facades looks for third-party embeds in the test page that can be lazy loaded with a static "facade". If the embed isn't necessary for immediate interaction by a user, consider using one of the facades to speed up page load (#11290)
  • With the axe version upgrade comes new audits ensuring accessible naming: aria-treeitem-name, aria-command-name, aria-tooltip-name, aria-meter-name, and aria-progressbar-name (#11661)

♻️ Removed audits

  • The update to latest axe-core also removes two audits that weren't checking much: layout-table and video-description (#11661)
  • works-offline and offline-start-url audits were removed as their checks are now covered by the new installable-manifest implementation (#11806)
  • The load-fast-enough-for-pwa audit has also been removed since Lighthouse's existing performance metrics more than cover the needs there (#11764)
  • without-javascript has been removed (#11711)

💥 Breaking changes

  • Device-emulation config settings and CLI flags have changed to be clearer and have less overlap. If you've used --emulated-form-factor or other emulation-related configuration, you'll need to make changes. The new settings should be considerably simpler to use with custom Lighthouse runners using real devices, Puppeteer, or system-level throttling. See the emulation docs for migration guidance. (#11779)
  • When waiting for the page to be fully loaded, Lighthouse will now wait if there are active high-priority network requests. In rare cases, like where the app initialization is dependent on a single, slow-returning XHR, some performance metrics may worsen; however, the new measurements are now accurate. (#11738, #11851)
  • Support for Node 10 has been dropped. The minimum required Node version is now 12 (#11656)

🤖💥 Breaking changes for programmatic users

These changes are unlikely to affect end users, but may be important if you are writing custom configs, plugins, or processing the Lighthouse JSON output.

  • ConsoleMessages is a new artifact that is a combination of the old ConsoleMessages and RuntimeExceptions artifacts, with some expanded data on items logged to the console. RuntimeExceptions has been removed (#11663)
  • DOM "node details" data formerly spread throughout existing artifacts are now gathered in a NodeDetails property on each element (#11474, #11695, #11752)
  • The ImageElements artifact has been streamlined to better represent the data collected and how it's used (#11703, #11707, #11733)
  • Previously, extends: true was allowed as an alias for extends: 'lighthouse:default' to extend a config from the default Lighthouse config file. The boolean option has been removed to prepare the way for extending from any valid config file (#11835)
  • A never-used feature to pass options from the config to gatherers has been removed to be compatible with future changes (#11743)

🧱 Core

Improvements, bug fixes, clarifications

  • lantern: allow non-XHRs to depend on CPU Nodes (#11767)
  • lantern: maximize throughput under HTTP/2 (#11666)
  • properly split node labels in the report around unicode surrogate pairs (#11698)
  • move the service-worker audit to the pwa-optimized group; its path in the JSON and metadata on scope URLs are unchanged (#11798)
  • support local plugins from a globally-installed Lighthouse (#11696)

Internal refactors and improvements

  • driver: create typed Runtime.evaluate from function code (#10816)
  • gather-runner: remove <M82 compat for InstallabilityErrors (#11782)
  • simulator: clearer intermediate timing types (#11744)
  • types: remove unneeded casts (#11753)
  • lightrider: skip uses-http2 audit (again) (#11777)
  • script-treemap-data: fix sourceRoot and missing coverage bugs (#11825)
  • fraggle-rock: add base snapshot runner (#11748)
  • fraggle-rock: add driver (#11742)

Tests

  • re-enable change-related tests in github actions (#11801)
  • smoke: use font-size for a non-composited animation in tests (#11808, #11836)
  • smoke: handle warn-not-offline-capable in test (#11799)
  • smoke: fix failureReasonsMask flake (#11791)
  • smoke: update flaky third-party-facades test (#11786)
  • make devtools webtests stable and reliable (#11717, #11731, #11751, #11789, #11790, #11804, #11809, 6ad47fa)

Misc

  • uses-http2: remove mention of h2 push in docs (#11834)
  • readme: add integration (#11775)
  • add log files to GCP run results (#11833)
  • temporarily allow css in redirectPass to work around crbug (#11813)
  • eslintignore *.d.ts files (#11793)
  • buildtracker: skip git --deepen if no token (#11785)
  • build: quiet the npm pack command (#11783)
  • build: fix bundling lighthouse-plugin-publisher-ads in Lightrider (#11648)
  • release: add print-contributors.js script (#11736)

Deps

  • update yargs to latest (#11794)
  • update old transitive deps (#11811)
