ruiseñor v9.1.1

¿Qué ha cambiado?

  • hazaña: las páginas de lista mantienen la página actual en la URL, por lo que una actualización o un viaje a una página de detalles te lleva de vuelta a donde estabas; la página se restablece a 1 solo al guardar o cuando cambia de grupo empresarial
  • hazaña: la lista de usuarios obtiene una columna de origen de cuenta, y la columna de última hora activa que faltaba en la configuración de la columna (ni representada ni seleccionable) se corrige
  • perf: el visor de registros muestra filas a través de una lista virtual, por lo que los grandes volúmenes de registros ya no tartamudean
  • solución: la creación simultánea de webhook/cola de devolución de llamada ya no se bloquea y descarta eventos
  • Solución: un lapso de tiempo efectivo HH:MM con formato incorrecto en una regla de alerta ahora se rechaza directamente en lugar de guardarse silenciosamente como una configuración inutilizable.
  • solución: los íconos de los componentes de integración ya no se rompen en Linux cuando una base de datos actualizada tiene un directorio entre mayúsculas y minúsculas o una falta de ortografía, y la ruta del ícono ahora rechaza el recorrido de ruta
  • solución: las fuentes woff2 y las plantillas de recopilación n9e-collect-templates/*.toml se trataron como rutas de interfaz y sirvieron a index.html, lo que interrumpió su descarga
  • solución: la tabla board_busigroup nunca obtuvo su clave primaria compuesta porque la etiqueta se escribió fuera de la etiqueta gorm
  • solución: corrige la normalización de las URL base del proveedor LLM que no terminan en /v1
  • solución: una regla de alerta Elasticsearch ya no mantiene un date_field obsoleto cuando el índice seleccionado no tiene campos de fecha
  • solución: el explorador de registros de Doris resuelve los nombres de pseudocampos aplanados en las columnas reales al filtrar
  • solución: los parámetros del encabezado del canal de eventos ahora se envían como un objeto
  • solución: los MCP API pasan por el prefijo N9E_PATHNAME en implementaciones de subrutas
  • solución: la búsqueda desplegable de fuente de datos ahora también coincide con el nombre del tipo de fuente de datos
  • solución: raw_message aparece cuando falla una llamada de API

aspectos destacados de v9

  • Presentamos Nightingale AI: un asistente de IA integrado, un mercado de habilidades, administración de configuración de LLM y recomendaciones rápidas basadas en páginas
  • Una base de datos de series temporales incorporada que funciona de inmediato, por lo que las configuraciones a pequeña escala ya no necesitan un Prometheus/VictoriaMetrics por separado.
  • Menú de navegación rediseñado, diseño global y interfaz de usuario de tabla
  • Formularios de regla de alerta / regla de silencio / regla de suscripción / regla de notificación completamente reconstruidos
  • Gestión del canal de notificación reelaborada.
  • Una nueva página de seguimiento de la ejecución del canal de eventos que muestra el procesamiento en detalle.
  • Una nueva generación de explorador de registros con soporte unificado para Elasticsearch, Loki y VictoriaLogs

Pasos de actualización

Reemplace el binario y el directorio integrations, luego reinicie.

Cambios en el esquema (omita esto si su cuenta de base de datos puede crear tablas)

Nightingale crea las tablas por ti. Si la cuenta de base de datos con la que se conecta Nightingale no puede crear tablas, debe crearlas a mano; el DDL está en https://github.com/ccfos/nightingale/blob/main/docker/migratesql/migrate.sql

Notas

  • El nuevo asistente de IA se basa en Redis Streams, por lo que se requiere Redis 5.0 o posterior (se recomienda Redis 7.0+ para usuarios de clústeres, para habilitar Pub/Sub fragmentado)
  • Reemplazar solo el binario no habilita el TSDB integrado: la sección [EmbeddedTSDB] existe solo en el nuevo etc/config.toml, por lo que transferir un archivo de configuración antiguo deja la función desactivada; copie la sección usted mismo. Lo maneja únicamente el proceso central (n9e-edge / n9e-alert / n9e-pushgw lo ignora y registra una advertencia), y los datos residen en el disco local de esa instancia central, por lo que se adapta únicamente a implementaciones de instancia única; con múltiples réplicas centrales, utilice una TSDB externa en su lugar
  • Los usuarios de Telegraf deben agregar ignore_host=false a la dirección de escritura de métricas; de lo contrario, los hosts que ejecutan Telegraf ya no se registrarán en la lista de hosts.
  • Si ejecuta n9e-edge o n9e-pushgw, actualícelos junto con n9e

nightingale v9.1.1

What's Changed

  • feat: list pages keep the current page in the URL, so a refresh or a trip into a detail page brings you back to where you were; the page resets to 1 only on save or when you switch business group
  • feat: the user list gains an account source column, and the last-active-time column that was missing from the column config — neither rendered nor selectable — is fixed
  • perf: the logs viewer renders rows through a virtual list, so large log volumes no longer stutter
  • fix: concurrent webhook / callback queue creation no longer blocks on itself and drops events
  • fix: a malformed HH:MM effective time span in an alert rule is now rejected outright instead of being saved silently as an unusable config
  • fix: integration component icons no longer break on Linux when an upgraded database has a directory case or spelling mismatch, and the icon route now rejects path traversal
  • fix: woff2 fonts and n9e-collect-templates/*.toml collect templates were treated as frontend routes and served index.html, which broke their download
  • fix: the board_busigroup table never got its composite primary key, because the tag was written outside the gorm tag
  • fix: correct the normalization of LLM provider base URLs that do not end in /v1
  • fix: an Elasticsearch alert rule no longer keeps a stale date_field when the selected index has no date fields
  • fix: the Doris log explorer resolves flattened pseudo field names back to the real columns when filtering
  • fix: event pipeline header parameters are now submitted as an object
  • fix: MCP APIs go through the N9E_PATHNAME prefix in sub-path deployments
  • fix: the datasource dropdown search now also matches the datasource type name
  • fix: raw_message is surfaced when an API call fails

v9 highlights

  • Introducing Nightingale AI: a built-in AI assistant, a Skills marketplace, LLM configuration management, and page-aware prompt recommendations
  • A built-in time series database that works out of the box, so small-scale setups no longer need a separate Prometheus / VictoriaMetrics
  • Redesigned navigation menu, global layout and table UI
  • Fully rebuilt alert rule / mute rule / subscribe rule / notification rule forms
  • Reworked notification channel management
  • A new event pipeline execution tracking page that shows the processing in detail
  • A new generation of log explorer with unified support for Elasticsearch, Loki and VictoriaLogs

Upgrade steps

Replace the binary and the integrations directory, then restart.

Schema changes (skip this if your database account can create tables)

Nightingale creates the tables for you. If the database account Nightingale connects with cannot create tables, you need to create them by hand — the DDL is at https://github.com/ccfos/nightingale/blob/main/docker/migratesql/migrate.sql

Notes

  • The new AI assistant relies on Redis Streams, so Redis 5.0 or later is required (Redis 7.0+ recommended for Cluster users, to enable sharded Pub/Sub)
  • Replacing only the binary does not enable the built-in TSDB: the [EmbeddedTSDB] section exists only in the new etc/config.toml, so carrying over an old config file leaves the feature off — copy the section across yourself. It is handled by the center process only (n9e-edge / n9e-alert / n9e-pushgw ignore it and log a warning), and the data lives on that center instance's local disk, so it suits single-instance deployments only; with multiple center replicas, use an external TSDB instead
  • telegraf users need to append ignore_host=false to the metrics write address, otherwise the hosts running telegraf will no longer register into the host list
  • If you run n9e-edge or n9e-pushgw, upgrade them together with n9e
