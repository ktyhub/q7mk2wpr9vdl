Notas

Esta nueva versión candidata de Maven 4 se lanza para obtener comentarios de los usuarios. Maven 4 ha restringido algunas cosas en comparación con Maven 3, así que asegúrese de ejecutar la herramienta mvnup antes de probar su proyecto con Maven 4.

Problemas solucionados desde RC-5

Se han solucionado todos los problemas conocidos informados en los RC-5 release note:

  • Error de configuración de Bean: el estado de accesibilidad del campo se almacenó en caché globalmente, lo que provocó fallas en la inyección de configuración del complemento. Corregido en #11433.
  • Problema de simultaneidad en la versión 4 API: se solucionó un ConcurrentModificationException en #11429.
  • Empaquetado de BOM: la conversión de POM del consumidor para proyectos de BOM ahora conserva correctamente las versiones de dependencia. Corregido en #11464.
  • macOS Gatekeeper: los archivos binarios nativos de JLine extraídos que activaron Gatekeeper se eliminaron de la distribución (#11997). La solución alternativa xattr de RC-5 ya no es necesaria.

Problemas de compatibilidad conocidos

Los siguientes son problemas de compatibilidad conocidos al usar Maven 4. mvnup antes de construir con Maven 4 solucionará automáticamente muchos problemas comunes de versión de complementos. los problemas A continuación se muestran aquellos que requieren intervención manual o correcciones ascendentes.

Validación POM más estricta

Maven 4 aplica una validación más estricta que Maven 3. Es posible que los proyectos necesiten arreglar sus POM:

  • Elementos XML duplicados: ahora se rechazan los duplicados <artifactId>, <properties>, etc. (error Duplicated tag). Repare el POM de origen.
  • Declaraciones de dependencia duplicadas: ahora se rechaza el mismo groupId:artifactId declarado dos veces (must be unique).
  • Expresiones no interpoladas: las expresiones ${...} en las URL del repositorio, ID de administración de distribución y otros campos que Maven 3 aceptó silenciosamente ahora se rechazan.
  • XML no válido en POM transitivos: instrucciones de procesamiento ilegales o prefijos de espacios de nombres no declarados en POM transitivos causan errores Non-parseable POM.
  • Propiedades en rutas <module>: Maven 4 ya no interpola propiedades como ${spark.version} en elementos <module> en el momento de lectura de POM.
  • Versiones compatibles con CI: los proyectos que utilizan ${revision} sin flatten-maven-plugin pueden sufrir errores de versión de dependencia faltante.
  • Solicitud de recopilación no válida: se rechazan las dependencias transitivas con expresiones de versión ${...} no interpoladas.

Cambios en la resolución de dependencia transitiva

TransitiveDependencyManager de Maven 4 aplica dependencyManagement en todas las profundidades transitivas (Maven 3 solo lo aplicó en el primer nivel). Esto es intencional pero puede cambiar las versiones resueltas:

  • Las dependencias anteriores en el classpath pueden desaparecer: agregue declaraciones explícitas. Consulte #12302.
  • Las reglas de la versión maven-enforcer-plugin pueden activarse debido a versiones transitivas degradadas.
  • license-maven-plugin puede informar nuevas dependencias transitivas que no están en la lista permitida.
  • La verificación de funciones de Karaf puede fallar debido a discrepancias en la versión del paquete OSGi.

Compatibilidad de complementos y extensiones

Algunos complementos y extensiones requieren versiones específicas para Maven 4:

  • Quarkus: las versiones anteriores a 3.20 usan patrones ServiceLocator/RepositorySystem incompatibles con la DI basada en Sisu de Maven 4. Actualice a Quarkus 3.20+.
  • Tycho: las versiones anteriores a 5.0 usan patrones de inyección de Guice/Sisu rotos por Maven 4. Actualice a Tycho 5.0.3+.
  • Extensión Development Maven: no se inicializa debido a cambios en la carga de clases de SLF4J (ClassNotFoundException: SimpleLogger).
  • pgpverify-maven-plugin: las versiones anteriores a 1.20 alcanzaron un ClassCastException con el solucionador de Maven 4. Consulte resolver#1957.
  • cyclonedx-maven-plugin: falla con Invalid Version Range Request cuando se utilizan versiones compatibles con CI ${revision}.
  • maven-site-plugin: la representación de la plantilla de Velocity puede fallar con versiones de complementos del sitio incompatibles.
  • maven-shade-plugin — dependency-reduced-pom.xml puede causar el error The parents form a cycle.
  • commons-release-plugin — clean-staging falla en Maven 4.

Cambios en la carga de clases

  • Los complementos que dependen del diseño de dominio de clase de Maven 3 pueden encontrar errores de "importaciones extranjeras" (por ejemplo, complementos Quarkus, JAXB).
  • El enrutamiento del repositorio basado en prefijos de Maven 4 puede bloquear artefactos que no coincidan con /.meta/prefixes.txt.

Formato posterior a mvnup

  • spotless-maven-plugin y sortpom-maven-plugin pueden informar violaciones de formato después de que mvnup modifique los archivos POM. Vuelva a ejecutar el formateador después de mvnup.

Otro

  • POM ascendentes rotos; por ejemplo, hadoop-project 3.1.0–3.3.0 tiene XML no válido (<Xlint:-unchecked/>) que provoca errores de análisis. Estos necesitan correcciones ascendentes rastreadas en HADOOP-19923.
  • Ordenamiento de elementos POM de Enforcer: el generador de modelos de Maven 4 reordena los elementos POM en un orden canónico, lo que puede romper las reglas de Enforcer que verifican el orden de los elementos.
  • Manejo de INSTANTÁNEAS: los artefactos de INSTANTÁNEAS pueden mostrarse como "presentes, pero no disponibles" en el manejo de metadatos de resolución diferente de Maven 4.

maven maven-4.0.0-rc-6

Notes

This new release candidate of Maven 4 is released to get feedback from users. Maven 4 has restricted a few things compared to Maven 3, so make sure to run the mvnup tool before trying your project with Maven 4.

Issues fixed since RC-5

All known issues reported in the RC-5 release notes have been fixed:

  • Bean configuration bug — field accessibility state was cached globally, causing plugin configuration injection failures. Fixed in #11433.
  • Concurrency issue in the v4 API — a ConcurrentModificationException was fixed in #11429.
  • BOM packaging — consumer POM conversion for BOM projects now correctly preserves dependency versions. Fixed in #11464.
  • macOS Gatekeeper — the extracted JLine native binaries that triggered Gatekeeper have been removed from the distribution (#11997). The xattr workaround from RC-5 is no longer needed.

Known compatibility issues

The following are known compatibility issues when using Maven 4. Running mvnup before building with Maven 4 will fix many common plugin version issues automatically. The issues below are those that require manual intervention or upstream fixes.

Stricter POM validation

Maven 4 enforces stricter validation than Maven 3. Projects may need to fix their POMs:

  • Duplicate XML elements — duplicate <artifactId>, <properties>, etc. are now rejected (Duplicated tag error). Fix the source POM.
  • Duplicate dependency declarations — same groupId:artifactId declared twice is now rejected (must be unique).
  • Uninterpolated expressions — ${...} expressions in repository URLs, distribution management IDs, and other fields that Maven 3 silently accepted are now rejected.
  • Invalid XML in transitive POMs — illegal processing instructions or undeclared namespace prefixes in transitive POMs cause Non-parseable POM errors.
  • Properties in <module> paths — Maven 4 no longer interpolates properties like ${spark.version} in <module> elements at POM reading time.
  • CI-friendly versions — projects using ${revision} without flatten-maven-plugin may hit missing dependency version errors.
  • Invalid Collect Request — transitive dependencies with uninterpolated ${...} version expressions are rejected.

Transitive dependency resolution changes

Maven 4's TransitiveDependencyManager applies dependencyManagement at all transitive depths (Maven 3 only applied it at the first level). This is intentional but can change resolved versions:

  • Dependencies previously on the classpath may disappear — add explicit declarations. See #12302.
  • maven-enforcer-plugin version rules may trigger due to downgraded transitive versions.
  • license-maven-plugin may report new transitive dependencies not in the allow-list.
  • Karaf feature verification may fail due to OSGi bundle version mismatches.

Plugin and extension compatibility

Some plugins and extensions require specific versions for Maven 4:

  • Quarkus — versions before 3.20 use ServiceLocator/RepositorySystem patterns incompatible with Maven 4's Sisu-based DI. Upgrade to Quarkus 3.20+.
  • Tycho — versions before 5.0 use Guice/Sisu injection patterns broken by Maven 4. Upgrade to Tycho 5.0.3+.
  • Develocity Maven extension — fails to initialize due to SLF4J classloading changes (ClassNotFoundException: SimpleLogger).
  • pgpverify-maven-plugin — versions before 1.20 hit a ClassCastException with Maven 4's resolver. See resolver#1957.
  • cyclonedx-maven-plugin — fails with Invalid Version Range Request when using ${revision} CI-friendly versions.
  • maven-site-plugin — Velocity template rendering may fail with incompatible site plugin versions.
  • maven-shade-plugin — dependency-reduced-pom.xml can cause The parents form a cycle error.
  • commons-release-plugin — clean-staging fails under Maven 4.

Classloading changes

  • Plugins relying on Maven 3's classrealm layout may encounter "foreign imports" errors (e.g., Quarkus, JAXB plugins).
  • Maven 4's prefix-based repository routing may block artifacts not matching /.meta/prefixes.txt.

Post-mvnup formatting

  • spotless-maven-plugin and sortpom-maven-plugin may report formatting violations after mvnup modifies POM files. Re-run the formatter after mvnup.

Other

  • Broken upstream POMs — e.g., hadoop-project 3.1.0–3.3.0 has invalid XML (<Xlint:-unchecked/>) causing parse errors. These need upstream fixes tracked in HADOOP-19923.
  • Enforcer POM element ordering — Maven 4's model builder reorders POM elements into a canonical order, which can break enforcer rules checking element ordering.
  • SNAPSHOT handling — SNAPSHOT artifacts may show as "present, but unavailable" under Maven 4's different resolver metadata handling.
