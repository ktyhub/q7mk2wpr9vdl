A continuación se muestran los release note completos para esta versión. # Regresiones rastreadas ### El inicio de NCCL produce un error de CUDA con un 'argumento no válido' en el controlador 12.2 Algunos usuarios con el controlador CUDA 12.2 (versión 535) informan haber visto un "error del controlador CUDA: argumento no válido" durante la inicialización de NCCL o memoria simétrica. Se eliminó la compatibilidad con CUDA 12.4, Anaconda en CI/CD. - Se eliminó la compatibilidad con CUDA 12.4 en CI/CD a favor de 12.8 (#148895, #142856, #144118, #145566, #145844, #148602, #143076, #148717). - Se eliminó el soporte de Anaconda en CI/CD (#144870, #145015, #147792) - Se eliminó el soporte para Triton < 2.2.0 (versiones sin ASTSource) (#143817) ### Extensiones de C++ `py_limited_api=True` ahora están construidas con `-DPy_LIMITED_API` (#145764) Comenzamos formalmente a respetar el kwarg `py_limited_api=True` en 2.6 y dejamos de vincular `libtorch_python.so` cuando se especificó la bandera, ya que libtorch_python.so no garantiza el uso de API del estable Python limitado API. En 2.7, vamos más allá al especificar el indicador `-DPy_LIMITED_API` que exigirá que la extensión se pueda construir con el API limitado. Como resultado de esta aplicación, **las extensiones personalizadas que configuran `py_limited_api=True` pero no cumplen con el API limitado pueden no compilarse**. Para ver un ejemplo, consulte el n.º 152243. Este es un comportamiento estrictamente mejor, ya que es incompleto afirmar el agnosticismo de CPython sin imponerlo con la bandera. Si se encuentra con este problema, asegúrese de que la extensión que está creando no utilice ningún API que esté fuera del API limitado de Python, por ejemplo, `pybind`. ### Cambie `torch.Tensor.new_tensor()` para que esté en el dispositivo Tensor dado de forma predeterminada (#144958) Esta función siempre creaba el nuevo Tensor en el dispositivo "cpu" y ahora usará el mismo dispositivo que el objeto Tensor actual. Este comportamiento ahora es coherente con otros métodos `.new_*`. ### Utilice Manylinux 2.28 y CXX11_ABI=1 para versiones futuras de Linux. Con la migración a manylinux_2_28 (basado en AlmaLinux 8), ya no podemos admitir distribuciones de sistema operativo con glibc2_26. Estos incluyen los populares Amazon Linux 2 y CentOS 7. (#143423, #146200, #148028, #148135, #148195, #148129) ### `torch.onnx.dynamo_export` ahora usa la ruta lógica del Programa Exportado (#137296) Los usuarios que utilicen el `torch.onnx.dynamo_export` API pueden ver que algunos `ExportOptions` se vuelven no es compatible debido a un interruptor interno para usar `torch.onnx.export(..., dynamo=True)`: `diagnostic_options`, `fake_context` y `onnx_registry` son eliminados/ignorados por `ExportOptions`. Sólo se conserva `dynamic_shapes`. Los usuarios deben pasar a utilizar la opción `dynamo=True` en `torch.onnx.export` como `torch.onnx.dynamo_export` ahora está en desuso. Aproveche el argumento [`dynamic_shapes`](https://pytorch.org/docs/stable/export.html#torch.export.export) en `torch.onnx.export` para especificar formas dinámicas en el modelo. (#147301) Ambos API han quedado obsoletos desde 2.2. Utilice `LRScheduler.get_last_lr()` para acceder a la tasa de aprendizaje. `print_lr` y `verbose` eran confusos, no estaban documentados adecuadamente y se usaban poco, como se describe en el n.° 99270, por lo que los desaprobamos en 2.2. Tracked Regressions

NCCL init hits CUDA failure 'invalid argument' on 12.2 driver

Some users with 12.2 CUDA driver (535 version) report seeing "CUDA driver error: invalid argument" during NCCL or Symmetric Memory initialization. This issue is currently under investigation, see #150852. If you use PyTorch from source, a known workaround is to rebuild PyTorch with CUDA 12.2 toolkit. Otherwise, you can try upgrading the CUDA driver on your system.

C++ Extensions py_limited_api=True is now built with -DPy_LIMITED_API (#145764)

We formally began respecting the py_limited_api=True kwarg in 2.6 and stopped linking libtorch_python.so when the flag was specified, as libtorch_python.so does not guarantee using APIs from from the stable Python limited API. In 2.7, we go further by specifying the -DPy_LIMITED_API flag which will enforce that the extension is buildable with the limited API. As a result of this enforcement, custom extensions that set py_limited_api=True but do not abide by the limited API may fail to build. For an example, see #152243.

This is strictly better behavior as it is sketchy to claim CPython agnosticism without enforcing with the flag. If you run into this issue, please ensure that the extension you are building does not use any APIs which are outside of the Python limited API, e.g., pybind.

Change torch.Tensor.new_tensor() to be on the given Tensor's device by default (#144958)

This function was always creating the new Tensor on the "cpu" device and will now use the same device as the current Tensor object. This behavior is now consistent with other .new_* methods.
