flujo de ciervos v2.1.0

#DeerFlow 2.1.0

DeerFlow 2.1 se basa en el arnés de superagente 2.0 centrándose en trust, escala y operatividad: ejecución de agente verificable, delegación de lotes duradera, backends de memoria conectables, cuatro nuevos proveedores de sandbox, una extensión fuera del árbol sistema y autenticación y autorización de nivel empresarial, envueltas en un espacio de trabajo mucho más rico con proyectos, ramificación de conversaciones y referencias conversaciones.

Este lanzamiento cierra el hito 2.1.0 con 772 PR fusionados desde el lanzamiento de 2.0.0.

📖 Notas completas: CHANGELOG.md · 中文版

⚠️ Cambios importantes

  • Los identificadores de seguimiento son incondicionales: cada respuesta HTTP de puerta de enlace lleva un encabezado X-Trace-Id y logging.enhance.enabled ahora controla la salida del registro solamente. Los valores Client proporcionados por deerflow_trace_id en los metadatos de ejecución son sobrescrito para que el encabezado, los registros y la ejecución persistente no puedan estar en desacuerdo: enviar el encabezado de solicitud X-Trace-Id para fijar una identificación de correlación. ([#5119])
  • /mnt/skills está reservado para proyecciones de habilidades administradas y habilitadas únicamente. DEER_FLOW_HOST_SKILLS_PATH / SKILLS_HOST_PATH ya no se utilizan y Los montajes del operador E2B que apuntan a esa ruta se omiten con una advertencia. ([#4178])
  • Se aplica sandbox.replicas para E2B como límite de capacidad; el valor predeterminado La política wait ahora puede fallar en el turno del agente en lugar de superar el límite. ([#4391])
  • Un directorio SKILL.md es un límite de paquete de tiempo de ejecución — SKILL.md anidado Los archivos son datos de respaldo, que ya no están registrados como habilidades independientes. ([#4098])
  • La memoria se puede conectar (memory.manager_class): configuración privada de DeerMem pasar a memory.backend_config (migrado automáticamente con una advertencia), /memory/config cambió de forma, storage_path ahora es un directorio raíz (los valores de estilo de archivo heredados se eliminan con una advertencia), clases de almacenamiento personalizadas muévase a una nueva ruta y tome config en __init__, y un backend sin search() falla rápidamente en el modo tool. ([#4122], [#4023], [#4324])
  • database.checkpoint_delta_snapshot_frequency movido a database.checkpoint_delta.snapshot_frequency y su valor predeterminado cambió de 1000 a 10: configúrelo explícitamente para mantener la cadencia anterior. ([#4516])
  • Docker enlaza loopback de forma predeterminada: el puerto de entrada publicado enlaza 127.0.0.1 en ambos archivos de redacción, que coinciden con el local-trust documentado modelo de implementación; configure BIND_HOST para exponer la pila en otras interfaces. ([#4618])

✨ Destacados

  • Ejecución de agente verificable: cada llamada a la herramienta lleva una prueba de manipulación, recibo sellado en tiempo de ejecución y un libro de recibos acotado llega al modelo contexto; Los informes de subagente deben citar recibos de herramientas con entregable verificable. se encarga de que el agente principal realice verificaciones cruzadas; y acceptance_criteria encendido las delegaciones se verifican de manera determinista en el lado principal (existencia de archivos, estado de salida del comando de prueba registrado), con cualquier cosa indecidible reportada NO VERIFICADO. ([#4659], [#5076], [#5090], [#5109], [#4365])
  • Subagentes a escala: un libro de delegación mantenido por el sistema evita redelegación redundante y ampliación total de los límites máximos ([#3877], [#4115]); un controlador de capacidad para todo el proceso gobierna la concurrencia, y la opción de participación La herramienta batch_task ejecuta grandes colecciones de artículos independientes como duraderos, lotes respaldados por SQL reanudables con concesiones, reintentos, pausa/reanudación/cancelación y un panel de progreso del chat ([#4998], [#5289]); task(context_mode="snapshot") lleva una copia de la conversación con los padres en el momento del envío ([#5367]); y El historial de pasos del subagente persiste y se muestra en el hilo. ([#3845])
  • Las tareas programadas crecen — Las programaciones interval se unen a once y cron ([#5291]); Las próximas apariciones de cron se pueden previsualizar antes de guardar. ([#5381]); El historial de ejecución filtra el lado del servidor por estado y las páginas hacia atrás en la interfaz de usuario ([#5384], [#5363]); las tareas pueden fijar lead_agent o un agente personalizado ([#5286], [#5288]); los sucesos ocupados se ponen en cola de forma duradera durante los reinicios ([#4918]); y la recuperación de múltiples instancias ya no interrumpe las ejecuciones en vivo. ([#4713])
  • Memoria conectable: nuevos backends OpenViking, mem0 y Honcho a través de HTTP ([#4509], [#4528], [#4730]); un adaptador de recuperación FTS5/BM25 incorporado ([#4360]); Consolidación asistida por LLM y poda de obsolescencia ([#3996], [#3860], [#4143]); almacenamiento incremental de datos por agente ([#4279]); un híbrido política de desalojo ([#4789]); inyección de hechos de corrección garantizada ([#3592]); y opción de deduplicación de hechos en el lado de escritura. ([#5254])
  • Más sandboxes, control más estricto — nuevo E2B, BoxLite (micro-VM con cálido pool), Tenki y proveedores OpenSandbox ([#3883], [#3940], [#3951], [#4382], [#4877]); opt-in isolated / dominio-allowlist salida de red para local Sandboxes Docker, con dominios denegados aprobables a través de la entrada humana tarjeta ([#5152]); y contenedores locales reforzados: enlaces portuarios puente-puerta de enlace, seccomp predeterminado, capacidades eliminadas.   • Extensiones fuera del árbol: las extensiones Python contribuyen con middleware, observadores de ciclo de vida y modelo de sistema, servicios de puerta de enlace y enrutadores HTTP, gestionado con deerflow extensions install/upgrade/enable/disable/remove ([#4636], [#4684], [#4780], [#5347]); una extensión 0.2 API permite extensiones observar lo que hizo el agente ([#4863]); y un nuevo contrato RunEvidenceReader impulsa el descubrimiento duradero de ejecuciones modificadas basado en cursor. ([#5405])
  • Autenticación y autorización empresarial: OIDC/SSO genérico con soporte Keycloak ([#3506]); tokens de acceso personal con políticas de ruta específicas ([#5041]); un Proveedor RBAC integrado con autorización de herramienta, modelo y entorno de pruebas aplicada tanto en tiempo de ensamblaje como en tiempo de ejecución ([#4260], [#4370], [#4540], [#4911], [#4439]); el autorregistro local se puede cerrar al aprovisionamiento solo de SSO ([#4311]); y las preferencias de la cuenta sobreviven a un navegador limpio. ([#5397])

([#4657], [#5217])
  • Tiempo de ejecución más rico: presupuestos de tokens por ejecución compartidos de forma aditiva en todo el cliente potencial agente y subagentes ([#3412]); continuación de objetivos con un seguimiento, limitado contar ([#3858]); El almacenamiento de punto de control de modo dual reduce el almacenamiento de subprocesos a largo plazo de O(N²) a casi lineal ([#4292], [#4638]); el contexto duradero sobrevive resumen ([#3556], [#3887], [#3906]); notas de tareas de inclusión voluntaria y recuperación del historial compactado ([#5382]); una ejecución puede leer la referencia anterior conversaciones, otorgables por el SDK y el compositor ([#5399], [#5463], [#5465]); campos de formulario de aclaración estructurados ([#4406]); y configurable Límites de recursividad para Gateway y ejecuciones programadas.   • Modelos y conocimientos: configuración de generación y modelo por agente ([#4347]); un limitador de solicitud de admisión opcional controla las llamadas por proveedor ([#5432]); favoritos de modelos por usuario ([#5441]); un perfil Z.AI GLM-5.3-Flash y MiniMax Soporte de código ACP ([#5074], [#4846]); optar por knowledge_search sobre RAGFlow o LightRAG ([#4955], [#5209]); Control de navegador agente respaldado por dramaturgos ([#4187]); y nuevos proveedores de búsqueda: Serply, Tencent Cloud WSA, Sofya, GroundRoute, Crawl4AI, fastCRW y Parallel, con filtros de actualidad nativos. ([#5023], [#5057], [#5099], [#5239], [#3675], [#3821], [#3585], [#3881], [#3866], [#5028])

🚀 Rendimiento

  • Almacenamiento de punto de control de modo dual con hilo de corte LangGraph DeltaChannel almacenamiento de O(N²) a casi lineal para ejecuciones largas de investigación/codificación. ([#4292])
  • Las transmisiones de chat solicitan messages-tuple + updates + custom en lugar de completo Instantáneas values: el historial retransmitido fue ~75 % de la carga útil de SSE. ([#5159])
  • Índice de eventos MemoryRunStore por thread_id y MemoryRunEventStore por run_id para eliminar escaneos O(n). ([#3562], [#3686])
  • read_file lee solo el rango de líneas solicitado del sandbox en lugar de buscando primero el archivo completo. ([#3824])
  • view_image inyecta contenido a través de wrap_model_call, por lo que hasta 20 MB de base64 ya no se ubica en dos puntos de control por imagen vista. ([#5014])
  • Caché de expresiones regulares de enmascaramiento de salida y reescritura de rutas de sandbox por instancia. ([#3648], [#3713])
  • Frontend: fusiona renderizaciones de streaming con un presupuesto de fotogramas, deja de volver a derivar contenido del mensaje en cada fragmento, derivación de datos de copia establecidos en caché y hacer cumplir los presupuestos de ruta JS/CSS. ([#4425], [#4441], [#5095])
  • Los fotogramas en vivo del navegador se codifican como JPEG, lo que reduce el tamaño de la carga útil del progreso. ([#4836])
  • Memoria de puerta de enlace vinculada después de que se ejecuta el terminal. ([#5112])
  • Deduplicar mensajes AI transmitidos a través de un conjunto de ID visto (O(n²) → O(n)). ([#3687])
  • Índice de resultados de llamadas de herramientas por grupo. ([#4411])

🔒 Seguridad

  • Puerta de revisión de habilidades: SkillScan ahora recibe cada archivo byte por byte (los archivos binarios, los archivos anidados y los bytes NUL ya no escapan al análisis), la extracción de archivos está limitada por el número de miembros, así como por el tamaño y el instalador, export guard y scanner comparten una definición de archivo de código/mágica ejecutable. ([#5431], [#4241])
  • Defensas de inyección rápida: nuevo middleware de desinfección de entradas con ambos circunvalaciones cerradas; contenido untrusted en las indicaciones del modelo (hechos de memoria, SOUL.md, descripciones de subagente, metadatos de habilidades) con formato de escape HTML; menteie se escapó el encuadre de respuesta a herramientas; y web_capture y herramienta de origen MCP resultados desinfectados a través del mismo límite trust que las herramientas web integradas. ([#3662], [#5375], [#4028], [#4253], [#4839])
  • Reforzamiento de la zona de pruebas: las zonas de pruebas locales Docker vinculan los puertos publicados al Puerta de enlace del puente Docker, ejecute el perfil seccomp predeterminado de Docker, elimine todo capacidades y obtenga no-new-privileges; SSH_AUTH_SOCK se borra de el entorno de caja de arena; y los archivos de habilidades proyectados son copias, no enlaces duros, por lo que una escritura en espacio aislado no puede mutar la fuente canónica. ([#4986], [#5145], [#4825], [#4830])
  • Secretos: las variables de entorno secretas heredadas se eliminan del entorno de habilidades; Los argumentos del lanzador stdio de MCP y las variables de entorno están restringidas en la configuración API; Las credenciales que no pueden viajar como valores de encabezado HTTP son rechazado en el límite de configuración; y los cambios de habilidad ya no persisten resolvió los secretos de $VAR en extensions_config.json. ([#4018], [#4617], [#5066], [#5357])
  • Artefactos: la protección contra escritura de solo salidas ya no se deja engañar segmentos de puntos o enlaces simbólicos codificados por porcentaje y artefactos XML (cualquier +xml tipo incluido) se sirven como archivos adjuntos de descarga, por lo que el contenido activo no puede Llame al API con la sesión del espectador. ([#5321], [#5353])
  • Autorización: una lista de herramientas vacías ahora se niega en lugar de fallar. abierto; run-create se aplica en puntos finales de flujo/espera sin estado; un revocado La concesión sandbox:execute se vuelve a verificar antes de reutilizar la zona de pruebas; agente personalizado las listas de habilidades permitidas se aplican en el nivel del sistema de archivos sandbox; y Las acciones de cancelación/reversión en uniones de secuencia GET se rechazan con 405. ([#4067], [#5030], [#5006], [#5077], [#5092])
  • Otro: protección SSRF para proveedores web_fetch autohospedados; Alondra CLI los árboles de credenciales imponen ACL privadas en Windows; y corriente abajo la sanitización se restablece en cadenas de rehype personalizadas. ([#3942], [#5141], [#4987])

🐛 Correcciones notables

  • Ejecuciones y tiempo de ejecución: cancele una ejecución de cualquier trabajador de puerta de enlace en vivo, no solo el propietario; La reutilización idempotente entre trabajadores ya no bloquea permanentemente el hilo; los reintentos con clave resuelven la solicitud del usuario de manera consistente; el cierre el drenaje sobrevive a cancelaciones repetidas; y una migración reparadora sana bases de datos que silenciosamente omitieron el esquema de reloj de cambio de ejecución. ([#4500], [#5393], [#5401], [#5487], [#5517])
  • Middleware — claves de detección de bucle read_file por rango de línea exacto, por lo que al hojear un archivo ya no se activa la parada brusca; max_turns ahora otorga los turnos que nombra (se pasó como superpasos de LangGraph, ~7–8 por turno); los presupuestos simbólicos se mantienen en todas las continuaciones de objetivos; guardias que eliminan llamadas de herramientas ya no se rompe cada turno posterior de Claude/Respuestas; y reintenté llamadas de modelo volver a enviar advertencias en cola. ([#5486], [#5485], [#5410], [#5447], [#5433])
  • Subagentes: un subagente mantiene sus instrucciones después de la compactación del contexto; el error de un subagente delegado ya no falla en la ejecución principal; repetidamente los subagentes cancelados ya no pierden su espacio de ejecución; y ventanas las comprobaciones de aceptación fallan al cerrarse con comandos fuera de alcance. ([#5454], [#5407], [#5477], [#5162])
  • Herramientas Sandbox: informes remotos de errores de list_dir / glob / grep en lugar de inventar "directorio vacío" o "no hay coincidencias"; read_file el truncamiento se informa en líneas con el punto de reanudación exacto; ruta-host el enmascaramiento maneja uniones de estilo $PATH y la ortografía de Windows con barra diagonal; los subagentes concurrentes trabajan más allá del límite máximo de sesiones shell de AIO; y herramienta CJK La salida ya no es confusa en PowerShell. ([#5264], [#5422], [#5380], [#5474], [#5418], [#5373], [#5178], [#5440])
  • Modelos: el token OAuth de Claude Code se lee una vez por proceso, por lo que el título, los modelos de resumen y subagente dejan de perder su credencial; modelos con supports_reasoning_effort ya no deja de construir; Herramienta no válida del códice las llamadas se emparejan con sus resultados; y api_base es honrado en cada Subclase BaseChatOpenAI. ([#5411], [#5403], [#5509], [#4146])
  • Canales: WeCom clips y se divide sobre el límite del protocolo de 20 KB en lugar de abandonar la respuesta; un mensaje de WeChat no descodificable ya no deja caer su lote; un Discord client muerto ya no bloquea los envíos salientes y congela el grupo de canales; Telegram rich_messages se procesa solo cuando el texto realmente contiene construcciones ricas; y se transmiten los medios entrantes WeChat/WeCom, de tamaño limitado y en la lista de hosts permitidos. ([#5148], [#4231], [#5227], [#5470], [#5225])
  • Habilidades y secretos: alternar una habilidad ya no escribe secretos resueltos en extensions_config.json; restaurar las referencias $VAR y rotar cualquier credencial expuesta de esta manera. ([#5357])
  • Programador: el presupuesto global de max_concurrent_runs se aplica en SQLite (no sólo Postgres) y para activadores manuales; y una carrera de despacho que podría iniciar dos ejecuciones para una tarea está cerrado. ([#5469], [#4769], [#4105])
  • MCP: las llamadas síncronas paralelas a un servidor stdio ya no se cancelan la conexión de cada uno; el grupo de sesiones mantiene su límite de capacidad bajo inicialización concurrente; y reservas de sondeo de tareas duraderas agrupadas sesiones a través de tiempos de espera de protocolo. ([#5396], [#4962], [#5027])
  • Frontend: el orden de los mensajes se mantiene estable durante ejecuciones largas y se vuelve a conectar; las cartas ingresadas por humanos mantienen el turno que las solicitó; la entrada del usuario es restaurado después de una reconexión de flujo incremental; Preguntas para eliminar el chat de la barra lateral para confirmación primero; y el client emite una llamada de herramienta transmitida una vez, con sus argumentos completos. ([#5293], [#4892], [#5428], [#5406], [#5408])

📦 Implementación y operaciones

  • Docker: el puerto de entrada publicado vincula el loopback de forma predeterminada (consulte cambios importantes); make up espera una prueba de estado real de la puerta de enlace antes declarar lista la pila; el inicio tolera la falta de un .env; y ventanas Trabajo de verificación previa y manejo de sockets de Git Bash. ([#4618], [#4658], [#4806], [#5371], [#5402])

([#4501])
  • Salud y preparación: el nuevo GET /health/ready ejecuta una base de datos limitada sonda y devuelve 503 mientras la base de datos es inaccesible; /health se queda pura vivacidad. ([#5166])
  • Nginx: las rutas de subprocesos que esperan una llamada de modelo permiten 600 segundos (un lento /compact ya no devuelve 504 para el trabajo que se aplicó), y largo los mensajes de chat pasan /api/langgraph/ sin 500 sin formato. ([#5505], [#4277])
  • Configuración: se selecciona un esquema PostgreSQL personalizado mediante postgres_schema y creado automáticamente ([#3442]); recursion_limit y scheduler.recursion_limit se pueden configurar mediante implementación ([#5390], [#4848]); y make dev conserva el ollama uv extra durante los reinicios. ([#4230])
  • CI y empaquetado: el flujo de trabajo de pruebas unitarias de backend se divide en cuatro fragmentos paralelos con Postgres/Redis aislado ([#5137]); y el renombrado El paquete tenki reemplaza al tenki-sandbox eliminado de PyPI. ([#5087])

deer-flow v2.1.0

DeerFlow 2.1.0

DeerFlow 2.1 builds on the 2.0 super-agent harness with a focus on trust, scale, and operability: verifiable agent execution, durable batch delegation, pluggable memory backends, four new sandbox providers, an out-of-tree extension system, and enterprise-grade authentication and authorization — wrapped in a much richer workspace with projects, conversation branching, and referenced conversations.

This release closes the 2.1.0 milestone with 772 merged PRs since the 2.0.0 release.

📖 Full notes: CHANGELOG.md · 中文版

⚠️ Breaking changes

  • Trace ids are unconditional — every Gateway HTTP response carries an X-Trace-Id header, and logging.enhance.enabled now controls log output only. Client-supplied deerflow_trace_id values in run metadata are overwritten so header, logs, and the persisted run cannot disagree — send the X-Trace-Id request header to pin a correlation id. ([#5119])
  • /mnt/skills is reserved for managed enabled-only skill projections. DEER_FLOW_HOST_SKILLS_PATH / SKILLS_HOST_PATH are no longer used, and E2B operator mounts targeting that path are skipped with a warning. ([#4178])
  • sandbox.replicas is enforced for E2B as a capacity limit; the default wait policy can now fail the agent turn instead of growing past the cap. ([#4391])
  • A SKILL.md directory is a runtime package boundary — nested SKILL.md files are supporting data, no longer registered as independent skills. ([#4098])
  • Memory is pluggable (memory.manager_class): DeerMem-private settings move into memory.backend_config (auto-migrated with a warning), /memory/config changed shape, storage_path is now a root directory (legacy file-style values are dropped with a warning), custom storage classes move to a new path and take config in __init__, and a backend without search() fails fast in tool mode. ([#4122], [#4023], [#4324])
  • database.checkpoint_delta_snapshot_frequency moved to database.checkpoint_delta.snapshot_frequency and its default changed from 1000 to 10 — set it explicitly to keep the old cadence. ([#4516])
  • Docker binds loopback by default — the published entry port binds 127.0.0.1 in both compose files, matching the documented local-trust deployment model; set BIND_HOST to expose the stack on other interfaces. ([#4618])

✨ Highlights

  • Verifiable agent execution — every tool call carries a tamper-evident, runtime-stamped receipt and a bounded receipt ledger reaches the model context; subagent reports must cite tool receipts with verifiable deliverable handles that the lead agent cross-checks; and acceptance_criteria on delegations are checked deterministically parent-side (file existence, recorded test-command exit status), with anything undecidable reported UNVERIFIED. ([#4659], [#5076], [#5090], [#5109], [#4365])
  • Subagents at scale — a system-maintained delegation ledger prevents redundant re-delegation and a total cap bounds fan-out ([#3877], [#4115]); one process-wide capacity controller governs concurrency, and the opt-in batch_task tool runs large collections of independent items as durable, resumable SQL-backed batches with leases, retries, pause/resume/cancel, and a chat progress panel ([#4998], [#5289]); task(context_mode="snapshot") carries a dispatch-time copy of the parent conversation ([#5367]); and subagent step history is persisted and displayed in the thread. ([#3845])
  • Scheduled tasks grow up — interval schedules join once and cron ([#5291]); upcoming cron occurrences can be previewed before saving ([#5381]); run history filters server-side by status and pages backwards in the UI ([#5384], [#5363]); tasks can pin lead_agent or a custom agent ([#5286], [#5288]); busy occurrences queue durably across restarts ([#4918]); and multi-instance recovery no longer interrupts live runs. ([#4713])
  • Pluggable memory — new OpenViking, mem0, and Honcho backends over HTTP ([#4509], [#4528], [#4730]); a built-in FTS5/BM25 retrieval adapter ([#4360]); LLM-assisted consolidation and staleness pruning ([#3996], [#3860], [#4143]); incremental per-agent fact storage ([#4279]); a hybrid eviction policy ([#4789]); guaranteed correction-fact injection ([#3592]); and opt-in write-side fact dedup. ([#5254])
  • More sandboxes, tighter control — new E2B, BoxLite (micro-VM with warm pool), Tenki, and OpenSandbox providers ([#3883], [#3940], [#3951], [#4382], [#4877]); opt-in isolated / domain-allowlist network egress for local Docker sandboxes, with denied domains approvable through the Human Input card ([#5152]); and hardened local containers — bridge-gateway port binds, default seccomp, dropped capabilities. ([#4986])
  • Out-of-tree extensions — Python extensions contribute middleware, lifecycle and system-model observers, Gateway services, and HTTP routers, managed with deerflow extensions install/upgrade/enable/disable/remove ([#4636], [#4684], [#4780], [#5347]); a 0.2 extension API lets extensions observe what the agent did ([#4863]); and a new RunEvidenceReader contract drives durable, cursor-based changed-run discovery. ([#5405])
  • Enterprise auth & authorization — generic OIDC/SSO with Keycloak support ([#3506]); personal access tokens with scoped route policies ([#5041]); a built-in RBAC provider with tool, model, and sandbox authorization enforced at both assembly and runtime ([#4260], [#4370], [#4540], [#4911], [#4439]); local self-registration can be closed to SSO-only provisioning ([#4311]); and account preferences survive a cleared browser. ([#5397])
  • MCP as production infrastructure — a durable task runtime survives Gateway restarts and reports progress in the chat UI ([#4665], [#4690], [#4833]); shared servers can inject per-user credentials or map request-scoped secrets to headers ([#4868], [#5010]); servers are managed from Settings ([#5022]); and a hung stdio server can no longer stall the Gateway or agent assembly. ([#4657], [#5217])
  • Richer runtime — per-run token budgets shared additively across the lead agent and subagents ([#3412]); goal continuations with a tracked, capped count ([#3858]); dual-mode checkpoint storage cuts long-run thread storage from O(N²) to near-linear ([#4292], [#4638]); durable context survives summarization ([#3556], [#3887], [#3906]); opt-in task notes and compacted-history recall ([#5382]); a run can read referenced earlier conversations, grantable from the SDK and the composer ([#5399], [#5463], [#5465]); structured clarification form fields ([#4406]); and configurable recursion limits for Gateway and scheduled runs. ([#5390], [#4848])
  • Models & knowledge — per-agent model and generation settings ([#4347]); an optional request-admission limiter paces calls per provider ([#5432]); per-user model favorites ([#5441]); a Z.AI GLM-5.3-Flash profile and MiniMax Code ACP support ([#5074], [#4846]); opt-in knowledge_search over RAGFlow or LightRAG ([#4955], [#5209]); Playwright-backed agentic browser control ([#4187]); and new search providers — Serply, Tencent Cloud WSA, Sofya, GroundRoute, Crawl4AI, fastCRW, and Parallel — with native recency filters. ([#5023], [#5057], [#5099], [#5239], [#3675], [#3821], [#3585], [#3881], [#3866], [#5028])
  • Workspace — Projects organize chats, with per-project instructions, a document shelf, and two-way file promotion ([#5265], [#5443]); assistant turns branch into side conversations with distinguishing titles ([#3950], [#3934], [#4983]); the latest answer regenerates and user turns edit and rerun in place ([#3637], [#4377]); chats archive, restore, and pin ([#5236], [#4442]); a conversation outline navigates long chats ([#5025]); CSV/TSV artifacts preview as tables ([#5284]); text artifacts stream over byte ranges and a run's files download as one zip ([#5056], [#5117]); MCP servers, integrations, and skills move into a dedicated Capability Center ([#5468]); and Custom Agents get display names, a deployment-level subagent catalog, and stateless memory_enabled: false mode. ([#5324], [#4887], [#5167])
  • Channels — a new Buzz (Nostr) connector ([#4649], [#4727]); /agent list / /agent use IM commands switch a conversation to the owner's Custom Agents ([#5168]); Postgres-backed webhook dedup lets several pods serve the same channel ([#4210]); and DingTalk gains file/image attachments. ([#4423])

🚀 Performance

  • Dual-mode checkpoint storage with LangGraph DeltaChannel cuts thread storage from O(N²) to near-linear for long research/coding runs. ([#4292])
  • Chat streams request messages-tuple + updates + custom instead of full values snapshots — retransmitted history was ~75% of SSE payload. ([#5159])
  • Index MemoryRunStore by thread_id and MemoryRunEventStore events by run_id to eliminate O(n) scans. ([#3562], [#3686])
  • read_file reads only the requested line range from the sandbox instead of fetching the whole file first. ([#3824])
  • view_image injects content via wrap_model_call, so up to 20 MB of base64 no longer sits in two checkpoints per viewed image. ([#5014])
  • Cache sandbox path-rewrite and output-masking regexes per instance. ([#3648], [#3713])
  • Frontend: coalesce streaming renders to a frame budget, stop re-deriving message content on every chunk, cache settled copy-data derivation, and enforce route JS/CSS budgets. ([#4425], [#4441], [#5095])
  • Browser Live frames encode as JPEG, cutting progress payload size. ([#4836])
  • Bound gateway memory after terminal runs. ([#5112])
  • Deduplicate streamed AI messages via a seen-id set (O(n²) → O(n)). ([#3687])
  • Index tool-call results per group. ([#4411])

🔒 Security

  • Skill review gate — SkillScan now receives every file byte for byte (binaries, nested archives, and NUL bytes no longer escape scanning), archive extraction is capped by member count as well as size, and installer, export guard, and scanner share one code-file/executable-magic definition. ([#5431], [#4241])
  • Prompt-injection defenses — new input-sanitization middleware with both bypasses closed; untrusted content in model prompts (memory facts, SOUL.md, subagent descriptions, skill metadata) HTML-escaped; MindIE tool-response framing escaped; and web_capture and MCP-sourced tool results sanitized through the same trust boundary as the built-in web tools. ([#3662], [#5375], [#4028], [#4253], [#4839])
  • Sandbox hardening — local Docker sandboxes bind published ports to the Docker bridge gateway, run Docker's default seccomp profile, drop all capabilities, and get no-new-privileges; SSH_AUTH_SOCK is scrubbed from the sandbox environment; and projected skill files are copies, not hardlinks, so a sandboxed write cannot mutate the canonical source. ([#4986], [#5145], [#4825], [#4830])
  • Secrets — inherited secret environment variables are scrubbed from the skill environment; MCP stdio launcher arguments and env vars are constrained at the config API; credentials that cannot travel as HTTP header values are rejected at the config boundary; and skill toggles no longer persist resolved $VAR secrets into extensions_config.json. ([#4018], [#4617], [#5066], [#5357])
  • Artifacts — the outputs-only write guard is no longer fooled by percent-encoded dot segments or symlinks, and XML artifacts (any +xml type included) are served as download attachments so active content cannot call the API with the viewer's session. ([#5321], [#5353])
  • Authorization — an empty tool allowlist now denies instead of failing open; run-create is enforced on stateless stream/wait endpoints; a revoked sandbox:execute grant is re-checked before sandbox reuse; custom-Agent skill allowlists are enforced at the sandbox filesystem level; and cancel/rollback actions on GET stream joins are rejected with 405. ([#4067], [#5030], [#5006], [#5077], [#5092])
  • Other — SSRF guard for self-hosted web_fetch providers; Lark CLI credential trees enforce private ACLs on Windows; and streamdown sanitization is restored in custom rehype chains. ([#3942], [#5141], [#4987])

🐛 Notable fixes

  • Runs & runtime — cancel a run from any live gateway worker, not only the owner; cross-worker idempotent reuse no longer permanently blocks the thread; keyed retries resolve the request user consistently; the shutdown run drain survives repeated cancellation; and a repair migration heals databases that silently skipped the run-change clock schema. ([#4500], [#5393], [#5401], [#5487], [#5517])
  • Middleware — loop detection keys read_file by exact line range, so paging through a file no longer trips the hard stop; max_turns now grants the turns it names (it was passed as LangGraph super-steps, ~7–8 per turn); token budgets hold across goal continuations; guards that remove tool calls no longer break every later Claude/Responses turn; and retried model calls re-deliver queued warnings. ([#5486], [#5485], [#5410], [#5447], [#5433])
  • Subagents — a subagent keeps its instructions after context compaction; a delegated subagent's error no longer fails the parent run; repeatedly cancelled subagents no longer leak their execution slot; and Windows acceptance checks fail closed on out-of-scope commands. ([#5454], [#5407], [#5477], [#5162])
  • Sandbox tools — remote list_dir / glob / grep report failures instead of inventing "empty directory" or "no matches"; read_file truncation is reported in lines with the exact resume point; host-path masking handles $PATH-style joins and forward-slash Windows spellings; concurrent subagents work past the AIO shell-session ceiling; and CJK tool output is no longer garbled in PowerShell. ([#5264], [#5422], [#5380], [#5474], [#5418], [#5373], [#5178], [#5440])
  • Models — the Claude Code OAuth token is read once per process, so title, summarization, and subagent models stop losing their credential; models with supports_reasoning_effort no longer fail to build; Codex invalid tool calls are paired with their results; and api_base is honored on every BaseChatOpenAI subclass. ([#5411], [#5403], [#5509], [#4146])
  • Channels — WeCom clips and splits over the 20 KB protocol cap instead of dropping the reply; one undecodable WeChat message no longer drops its batch; a dead Discord client no longer hangs outbound sends and freezes the channel pool; Telegram rich_messages renders only when the text actually contains rich constructs; and WeChat/WeCom inbound media is streamed, size-bounded, and host-allowlisted. ([#5148], [#4231], [#5227], [#5470], [#5225])
  • Skills & secrets — toggling a skill no longer writes resolved secrets into extensions_config.json; restore $VAR references and rotate any credential exposed this way. ([#5357])
  • Scheduler — the global max_concurrent_runs budget is enforced on SQLite (not just Postgres) and for manual triggers; and a dispatch race that could launch two runs for one task is closed. ([#5469], [#4769], [#4105])
  • MCP — parallel synchronous calls to one stdio server no longer cancel each other's connection; the session pool holds its capacity limit under concurrent initialization; and durable task polling preserves pooled sessions across protocol timeouts. ([#5396], [#4962], [#5027])
  • Frontend — message order stays stable across long runs and reconnects; human-input cards keep the turn that requested them; the user's input is restored after an incremental stream reconnect; sidebar chat deletion asks for confirmation first; and the client emits a streamed tool call once, with its complete arguments. ([#5293], [#4892], [#5428], [#5406], [#5408])

📦 Deploy & ops

  • Docker — the published entry port binds loopback by default (see breaking changes); make up waits for a real Gateway health probe before declaring the stack ready; startup tolerates a missing .env; and Windows Git Bash preflight and socket handling work. ([#4618], [#4658], [#4806], [#5371], [#5402])
  • Kubernetes — per-sandbox Services default to ClusterIP instead of NodePort, so sandboxes are reachable only inside the cluster ([#4190]); ClusterIP Services and scoped per-skill PVC mounts ([#4016], [#3928]); and an optional Lark credential broker sidecar keeps app secrets out of the sandbox filesystem. ([#4501])
  • Health & readiness — the new GET /health/ready runs a bounded database probe and returns 503 while the database is unreachable; /health stays pure liveness. ([#5166])
  • Nginx — thread routes that wait on a model call allow 600 seconds (a slow /compact no longer returns 504 for work that was applied), and long chat prompts pass /api/langgraph/ without a raw 500. ([#5505], [#4277])
  • Configuration — a custom PostgreSQL schema is selected via postgres_schema and created automatically ([#3442]); recursion_limit and scheduler.recursion_limit are deployment-configurable ([#5390], [#4848]); and make dev preserves the ollama uv extra across restarts. ([#5318])
  • Upgrades — startup tolerates a database migrated to the reviewed newer revision, keeping rollback possible ([#5219]); legacy threads get run-event seed backfill ([#4590]); and Postgres connections survive idle timeouts via pool_recycle. ([#4230])
  • CI & packaging — the backend unit-test workflow splits into four parallel shards with isolated Postgres/Redis ([#5137]); and the renamed tenki package replaces the PyPI-removed tenki-sandbox. ([#5087])
