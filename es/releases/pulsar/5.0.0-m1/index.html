pulsar v5.0.0-M1

2026-06-23

Apache Pulsar 5.0.0-M1 es el primer lanzamiento importante en el camino hacia Apache Pulsar 5.0.0, y se espera que esté disponible general más adelante en 2026. Es una vista previa: una versión inicial que pone en sus manos las principales funciones nuevas de 5.0 para que pueda probarlas con cargas de trabajo reales y enviar comentarios antes del lanzamiento de GA. No está destinado a la producción. Se destacan dos cambios: Temas escalables, un nuevo tipo de tema que crece y se reduce por sí solo, y la promoción de Oxia al almacén de metadatos recomendado por Pulsar, junto con una migración del sistema de compilación a Gradle, la división de los conectores IO en un repositorio separado y el registro estructurado.

Para obtener un tutorial completo, consulte el anuncio: [Apache Pulsar 5.0.0-M1: vista previa de la próxima versión importante] (https://pulsar.apache.org/blog/2026/06/23/announcing-apache-pulsar-5-0-m1).

Destacados

Temas escalables (Temas v5). Un nuevo tipo de tema que reemplaza las particiones fijas con segmentos basados en rangos, de modo que un tema puede ampliarse y reducirse dividiendo y fusionando segmentos de forma transparente y al mismo tiempo preservando el orden por clave. Esto evita la interrupción del pedido y la deriva operativa que se producen al cambiar el recuento de particiones de un tema particionado normal. El trabajo abarca el controlador del lado del corredor (PIP-468), transacciones basadas en metadatos (PIP-473), migración de temas regular a escalable (PIP-475) y división/fusión automática (PIP-483). Consulte PIP-460.

Nuevo V5 Java client API. Un client API limpio y diseñado específicamente para temas escalables, enviado como un nuevo módulo aditivo pulsar-client-v5; los módulos pulsar-client y pulsar-client-api existentes no se modifican, por lo que las aplicaciones actuales siguen funcionando. Reemplaza el clásico Consumer/Reader y los cuatro tipos de suscripción con tres consumidores especialmente diseñados: QueueConsumer (consumo de cola de trabajo paralelo, reconocido individualmente con soporte para mensajes no entregados), StreamConsumer (acks ordenados y acumulativos) y CheckpointConsumer (para procesadores de flujo como Flink y Spark que rastrean su propia posición). El V5 client también funciona con temas existentes particionados y no particionados, y un consumidor puede suscribirse a un espacio de nombres completo. En M1 se envía para Java; Los SDK en otros idiomas seguirán antes de GA. Consulte PIP-466.

Oxia es ahora el almacén de metadatos recomendado. Oxia se convierte en el almacén de metadatos recomendado para los nuevos clústeres de Pulsar en 5.0 y es el backend elegido para temas escalables, cuyas búsquedas se basan en sus sesiones de visualización de streaming. ZooKeeper sigue siendo totalmente compatible y PIP-454 agrega un marco de migración en vivo y sin tiempo de inactividad que mueve un clúster existente de ZooKeeper a Oxia mientras el plano de datos sigue publicando y consumiendo.

El sistema de compilación migró de Maven a Gradle. Las compilaciones ahora usan ./gradlew en lugar de mvn, con almacenamiento en caché y paralelismo a nivel de tareas que reducen sustancialmente los tiempos de compilación local y de CI, y un catálogo de versiones central (gradle/libs.versions.toml) para la gestión de dependencias. La migración es transparente para los usuarios que consumen los artefactos Maven publicados, las imágenes Docker y los JAR sombreados client. Consulte PIP-463.

Los conectores IO se dividen en un repositorio separado. Los conectores Pulsar IO integrados se han retirado del repositorio principal para que puedan seguir su propia cadencia de lanzamiento. Consulte PIP-465. Registro estructurado. Pulsar ahora emite registros estructurados a través de slog a través del broker, client, ​​libro mayor administrado, funciones y módulos de metadatos, con salida de registro plana JSON / OpenTelemetry y una variable de entorno PULSAR_LOG_FORMAT para cambiar formatos fácilmente. Consulte PIP-467.

API y modernización de la plataforma. Pulsar migró de javax.* a jakarta.* APIs (PIP-472), estableció Protobuf v4 como predeterminado, migró las anotaciones REST API de Swagger a OpenAPI 3 y ahora admite la compilación y ejecución en Java 25. Las políticas de temas obtuvieron un reconocimiento de legado, backend de enrutamiento respaldado por almacén de metadatos (PIP-469).

Actualizaciones de seguridad y dependencias. Esta versión incluye un gran conjunto de actualizaciones de dependencias que abordan numerosos CVE en Netty, Jetty, log4j, BouncyCastle, Thrift, vert.x y async-http-client, ​​y actualiza BookKeeper a 4.18.0. Consulte Actualizaciones de la biblioteca a continuación.

Aviso importante

5.0.0-M1 es una versión importante que elimina funciones obsoletas y cambia algunos API. Revise lo siguiente antes de actualizar:

  • Migración javax.* → jakarta.* (PIP-472). Los complementos de intermediario personalizado, interceptores, proveedores de autenticación/autorización u otras extensiones que hacen referencia a paquetes javax.* (por ejemplo, javax.ws.rs o javax.servlet) deben actualizarse a los paquetes jakarta.* correspondientes y volver a compilarse.
  • Se eliminó el backend del almacén de metadatos de Etcd (PIP-462). Las implementaciones que utilizan Etcd como almacén de metadatos deben migrar a ZooKeeper u Oxia antes de actualizar.
  • Los conectores IO se movieron a un repositorio separado (PIP-465). Los conectores ya no se publican desde el repositorio principal de Pulsar; consígalos en el proyecto de conectores dedicados.
  • El sistema de compilación ahora es Gradle (PIP-463). Si compila Pulsar desde el código fuente, use ./gradlew en lugar de mvn. Los artefactos publicados no cambian.
  • Se eliminó la dependencia de fastutil (#25413).

pulsar v5.0.0-M1

2026-06-23

Apache Pulsar 5.0.0-M1 is the first milestone release on the road to Apache Pulsar 5.0.0, with general availability expected later in 2026. It is a preview: an early build that puts the major new features of 5.0 in your hands so you can try them against real workloads and send feedback ahead of the GA release. It is not meant for production. Two changes stand out — Scalable Topics, a new topic type that grows and shrinks on its own, and the promotion of Oxia to Pulsar's recommended metadata store — alongside a migration of the build system to Gradle, the split of the IO connectors into a separate repository, and structured logging.

For a full walkthrough, see the announcement: Apache Pulsar 5.0.0-M1: A Preview of the Next Major Release.

Highlights

Scalable Topics (Topics v5). A new topic type that replaces fixed partitions with range-based segments, so a topic can scale up and down by transparently splitting and merging segments while preserving per-key ordering. This avoids the ordering breakage and operational drift that come from changing the partition count of a regular partitioned topic. The work spans the broker-side controller (PIP-468), metadata-driven transactions (PIP-473), regular-to-scalable topic migration (PIP-475), and automatic split/merge (PIP-483). See PIP-460.

New V5 Java client API. A clean-slate, purpose-built client API for scalable topics, shipped as a new, additive pulsar-client-v5 module — the existing pulsar-client and pulsar-client-api modules are unchanged, so current applications keep working. It replaces the classic Consumer/Reader and the four subscription types with three purpose-built consumers: QueueConsumer (parallel, individually-acknowledged work-queue consumption with dead-letter support), StreamConsumer (ordered, cumulative acks), and CheckpointConsumer (for stream processors such as Flink and Spark that track their own position). The V5 client also works against existing partitioned and non-partitioned topics, and a consumer can subscribe to an entire namespace. In M1 it ships for Java; other language SDKs will follow before GA. See PIP-466.

Oxia is now the recommended metadata store. Oxia becomes the recommended metadata store for new Pulsar clusters in 5.0 and is the backend of choice for scalable topics, whose lookups build on its streaming watch sessions. ZooKeeper remains fully supported, and PIP-454 adds a live, zero-downtime migration framework that moves an existing cluster from ZooKeeper to Oxia while the data plane keeps publishing and consuming.

Build system migrated from Maven to Gradle. Builds now use ./gradlew instead of mvn, with task-level caching and parallelism that substantially reduce local and CI build times, and a central version catalog (gradle/libs.versions.toml) for dependency management. The migration is transparent to users consuming the published Maven artifacts, Docker images, and shaded client JARs. See PIP-463.

IO connectors split into a separate repository. The built-in Pulsar IO connectors have been moved out of the core repository so they can follow their own release cadence. See PIP-465.

Structured logging. Pulsar now emits structured logs through slog across the broker, client, managed-ledger, functions, and metadata modules, with flat JSON / OpenTelemetry log output and a PULSAR_LOG_FORMAT environment variable to switch formats easily. See PIP-467.

API and platform modernization. Pulsar migrated from javax.* to jakarta.* APIs (PIP-472), made Protobuf v4 the default, migrated REST API annotations from Swagger to OpenAPI 3, and now supports building and running on Java 25. Topic policies gained a legacy-aware, metadata-store-backed routing backend (PIP-469).

Security and dependency updates. This release bundles a large set of dependency upgrades that address numerous CVEs across Netty, Jetty, log4j, BouncyCastle, Thrift, vert.x, and async-http-client, and upgrades BookKeeper to 4.18.0. See Library updates below.

Important notice

5.0.0-M1 is a major release that removes deprecated functionality and changes some APIs. Review the following before upgrading:

  • javax.* → jakarta.* migration (PIP-472). Custom broker plugins, interceptors, authentication/authorization providers, or other extensions that reference javax.* packages (for example javax.ws.rs or javax.servlet) must be updated to the corresponding jakarta.* packages and recompiled.
  • Etcd metadata store backend removed (PIP-462). Deployments using Etcd as the metadata store must migrate to ZooKeeper or Oxia before upgrading.
  • IO connectors moved to a separate repository (PIP-465). Connectors are no longer released from the core Pulsar repository; obtain them from the dedicated connectors project.
  • Build system is now Gradle (PIP-463). If you build Pulsar from source, use ./gradlew instead of mvn. Published artifacts are unchanged.
  • fastutil dependency removed (#25413).
