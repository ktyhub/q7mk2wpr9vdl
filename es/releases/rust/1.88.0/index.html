rust 1.88.0

<a id="1.88.0-Language"></a>

Idioma

  • Estabilizar #![feature(let_chains)] en la edición 2024. Esta función permite encadenar declaraciones let dentro de if y while, lo que permite la mezcla con expresiones booleanas. Los patrones dentro de las subexpresiones let pueden ser irrefutables o refutables.
  • Estabilizar #![feature(naked_functions)]. Las funciones desnudas permiten escribir funciones sin epílogo ni prólogo generados por el compilador, lo que permite un control total sobre el ensamblado generado para una función en particular.
  • Estabilizar #![feature(cfg_boolean_literals)]. Esto permite usar literales booleanos como predicados cfg, p.e. #[cfg(true)] y #[cfg(false)].
  • Desestabilizar completamente el atributo #[bench]. El uso de #[bench] sin #![feature(custom_test_frameworks)] ya desencadenó una pelusa de incompatibilidad futura denegada por defecto desde Rust 1.77, pero ahora se convertirá en un error grave.
  • Agregar pelusa de advertencia por defecto dangerous_implicit_autorefs contra autoref implícito de desreferencia del puntero sin formato. La pelusa se cambiará a denegar por defecto en la próxima versión de Rust.
  • Agregue pelusa invalid_null_arguments para evitar el uso no válido de punteros nulos. Esta pelusa se ha extraído de clippy::invalid_null_ptr_usage.
  • Cambiar la preferencia del candidato de impl de rasgo para impls incorporados y cláusulas donde triviales.
  • [Verifique los tipos de valores predeterminados de parámetros constantes genéricos] (https://github.com/rust-lang/rust/pull/139646) <a id="1.88.0-Compiler"></a>

Compilador

  • Estabilice -Cdwarf-version para seleccionar la versión de la información de depuración DWARF que se generará. <a id="1.88.0-Platform-Support"></a>

Soporte de plataforma

  • Degradar i686-pc-windows-gnu al nivel 2. Consulte la [página de soporte de plataforma] de Rust (https://doc.rust-lang.org/rustc/platform-support.html) para obtener más información sobre el soporte de plataforma por niveles de Rust. <a id="1.88.0-Libraries"></a>

Bibliotecas

  • Eliminar comillas invertidas del mensaje de error de prueba #[should_panic].
  • Garantiza que [T; N]::from_fn se genera en orden de índices crecientes., para aquellos que le pasan un cierre con estado.
  • El indicador libtest --nocapture está obsoleto en favor del indicador más consistente --no-capture.
  • Garantiza que {float}::NAN es un NaN silencioso. <a id="1.88.0-Stabilized-APIs"></a>

Carga

  • Estabilizar la recolección automática de basura.
  • use zlib-rs para compresión gzip en código rust <a id="1.88.0-Rustdoc"></a>

Rustdoc

  • Las pruebas de documentos se pueden ignorar según los nombres de los objetivos que utilizan los atributos ignore-*.
  • Estabilizar las opciones --test-runtool y --test-runtool-arg CLI para especificar un programa (como qemu) y sus argumentos para ejecutar una prueba de documentación. <a id="1.88.0-Compatibility-Notes"></a>

Notas de compatibilidad

  • Terminar de cambiar la representación interna de los tokens pegados. El compilador ahora rechaza correctamente ciertas macros declarativas no válidas que antes se aceptaban en circunstancias poco claras. El uso de un especificador de fragmentos tt a menudo puede solucionar estas macros.
  • Desestabilizar completamente el atributo #[bench]. El uso de #[bench] sin #![feature(custom_test_frameworks)] ya desencadenó una pelusa de incompatibilidad futura denegada por defecto desde Rust 1.77, pero ahora se convertirá en un error grave.
  • Se corrigió la verificación de préstamos en algunos patrones siempre verdaderos. El verificador de préstamos era demasiado permisivo en algunos casos, permitiendo programas que no deberían haberse compilado.
  • Actualice el LLVM externo mínimo a 19.
  • Haga que sea un error grave utilizar un tipo de vector con una ABI que no sea Rust sin habilitar la función de destino requerida.

rust 1.88.0

<a id="1.88.0-Language"></a>

Language

  • Stabilize #![feature(let_chains)] in the 2024 edition. This feature allows &&-chaining let statements inside if and while, allowing intermixture with boolean expressions. The patterns inside the let sub-expressions can be irrefutable or refutable.
  • Stabilize #![feature(naked_functions)]. Naked functions allow writing functions with no compiler-generated epilogue and prologue, allowing full control over the generated assembly for a particular function.
  • Stabilize #![feature(cfg_boolean_literals)]. This allows using boolean literals as cfg predicates, e.g. #[cfg(true)] and #[cfg(false)].
  • Fully de-stabilize the #[bench] attribute. Usage of #[bench] without #![feature(custom_test_frameworks)] already triggered a deny-by-default future-incompatibility lint since Rust 1.77, but will now become a hard error.
  • Add warn-by-default dangerous_implicit_autorefs lint against implicit autoref of raw pointer dereference. The lint will be bumped to deny-by-default in the next version of Rust.
  • Add invalid_null_arguments lint to prevent invalid usage of null pointers. This lint is uplifted from clippy::invalid_null_ptr_usage.
  • Change trait impl candidate preference for builtin impls and trivial where-clauses.
  • Check types of generic const parameter defaults

<a id="1.88.0-Compiler"></a>

Compiler

  • Stabilize -Cdwarf-version for selecting the version of DWARF debug information to generate.

<a id="1.88.0-Platform-Support"></a>

Platform Support

  • Demote i686-pc-windows-gnu to Tier 2.

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.88.0-Libraries"></a>

Libraries

  • Remove backticks from #[should_panic] test failure message.
  • Guarantee that [T; N]::from_fn is generated in order of increasing indices., for those passing it a stateful closure.
  • The libtest flag --nocapture is deprecated in favor of the more consistent --no-capture flag.
  • Guarantee that {float}::NAN is a quiet NaN.

<a id="1.88.0-Stabilized-APIs"></a>

Stabilized APIs

  • Cell::update
  • impl Default for *const T
  • impl Default for *mut T
  • HashMap::extract_if
  • HashSet::extract_if
  • hint::select_unpredictable
  • proc_macro::Span::line
  • proc_macro::Span::column
  • proc_macro::Span::start
  • proc_macro::Span::end
  • proc_macro::Span::file
  • proc_macro::Span::local_file
  • <[T]>::as_chunks
  • <[T]>::as_chunks_mut
  • <[T]>::as_chunks_unchecked
  • <[T]>::as_chunks_unchecked_mut
  • <[T]>::as_rchunks
  • <[T]>::as_rchunks_mut
  • mod ffi::c_str

These previously stable APIs are now stable in const contexts:

  • NonNull<T>::replace
  • <*mut T>::replace
  • std::ptr::swap_nonoverlapping
  • Cell::replace
  • Cell::get
  • Cell::get_mut
  • Cell::from_mut
  • Cell::as_slice_of_cells

<a id="1.88.0-Cargo"></a>

Cargo

  • Stabilize automatic garbage collection.
  • use zlib-rs for gzip compression in rust code

<a id="1.88.0-Rustdoc"></a>

Rustdoc

  • Doctests can be ignored based on target names using ignore-* attributes.
  • Stabilize the --test-runtool and --test-runtool-arg CLI options to specify a program (like qemu) and its arguments to run a doctest.

<a id="1.88.0-Compatibility-Notes"></a>

Compatibility Notes

  • Finish changing the internal representation of pasted tokens. Certain invalid declarative macros that were previously accepted in obscure circumstances are now correctly rejected by the compiler. Use of a tt fragment specifier can often fix these macros.
  • Fully de-stabilize the #[bench] attribute. Usage of #[bench] without #![feature(custom_test_frameworks)] already triggered a deny-by-default future-incompatibility lint since Rust 1.77, but will now become a hard error.
  • Fix borrow checking some always-true patterns. The borrow checker was overly permissive in some cases, allowing programs that shouldn't have compiled.
  • Update the minimum external LLVM to 19.
  • Make it a hard error to use a vector type with a non-Rust ABI without enabling the required target feature.
