rust 1.94.0

<a id="1.94.0-Language"></a>

Idioma

  • Impls y elementos impl heredan el nivel de pelusa dead_code de los rasgos y elementos de rasgos correspondientes
  • Estabilizar 29 funciones de destino RISC-V adicionales, incluidas grandes porciones de los perfiles RVA22U64 / RVA23U64
  • Agregue pelusa unused_visibilities de advertencia predeterminada para mayor visibilidad en las declaraciones const _
  • Actualización a Unicode 17
  • Evitar errores de vida útil incorrectos para cierres <a id="1.94.0-Platform-Support"></a>

Soporte de plataforma

  • Agregar riscv64im-unknown-none-elf como objetivo de nivel 3 Consulte la [página de soporte de plataforma] de Rust (https://doc.rust-lang.org/rustc/platform-support.html) para obtener más información sobre el soporte de plataforma por niveles de Rust. <a id="1.94.0-Libraries"></a>

Bibliotecas

  • Relájate T: Ord con destino a algunos métodos BinaryHeap<T>. <a id="1.94.0-Stabilized-APIs"></a>

API estabilizados

-<[T]>::array_windows -<[T]>::element_offset -LazyCell::get -LazyCell::get_mut -LazyCell::force_mut -LazyLock::get -LazyLock::get_mut -LazyLock::force_mut -impl TryFrom<char> for usize -std::iter::Peekable::next_if_map -std::iter::Peekable::next_if_map_mut

  • intrínsecos x86 avx512fp16 (excluyendo aquellos que dependen directamente del tipo inestable f16)
  • Intrínsecos de AArch64 NEON fp16 (excluyendo aquellos que dependen directamente del tipo inestable f16) -f32::consts::EULER_GAMMA -f64::consts::EULER_GAMMA -f32::consts::GOLDEN_RATIO -f64::consts::GOLDEN_RATIO Estos API anteriormente estables ahora lo son en contextos constantes: -f32::mul_add -f64::mul_add <a id="1.94.0-Cargo"></a>

Carga

  • Estabilizar la clave de inclusión de configuración. La clave de configuración de inclusión de nivel superior permite cargar archivos de configuración adicionales, lo que permite una mejor organización, uso compartido y gestión de las configuraciones de Cargo en todos los proyectos y entornos. docs #16284
  • Estabilizar el campo pubtime en el índice de registro. Esto registra cuándo se publicó una versión de caja y permite la resolución de dependencias basada en el tiempo en el futuro. Tenga en cuenta que crates.io reabastecerá gradualmente los paquetes existentes cuando se publique una nueva versión. No todas las cajas tienen hora de publicación todavía. #16369 #16372
  • Cargo ahora analiza TOML v1.1 en busca de manifiestos y archivos de configuración. Tenga en cuenta que el uso de estas funciones en Cargo.toml aumentará su MSRV de desarrollo, pero el manifiesto publicado sigue siendo compatible con analizadores más antiguos. #16415
  • Hacer que CARGO_BIN_EXE_<crate> esté disponible en tiempo de ejecución <a id="1.94.0-Compatibility-Notes"></a>

Notas de compatibilidad

  • Prohibido lanzar libremente límites de por vida de tipos dyn
  • [Hacer que la captura de cierre tenga un comportamiento consistente y correcto alrededor de los patrones] (https://github.com/rust-lang/rust/pull/138961) Se han cambiado algunos detalles más finos de cómo las capturas de cierre precisas se ven afectadas por la coincidencia de patrones. En algunos casos, esto puede provocar que un cierre sin movimiento que anteriormente capturaba una variable completa mediante movimiento, ahora capture solo una parte de esa variable mediante movimiento y otras partes mediante préstamo. Esto puede hacer que el verificador de préstamos se queje donde antes no lo hacía, o hacer que Drop se ejecute en un momento diferente.
  • Las macros de biblioteca estándar ahora se importan mediante preludio, no mediante #[macro_use] inyectado Esto generará un error si las macros con el mismo nombre se importan globalmente. Por ejemplo, si una caja define su propia macro matches y luego la importa globalmente, ahora es ambiguo si se refiere a la biblioteca personalizada o estándar matches y se requiere una importación explícita del nombre para resolver la ambigüedad. Una excepción son core::panic y std::panic, si su importación es ambigua se genera una nueva advertencia (ambiguous_panic_imports). Esto puede generar una nueva advertencia (ambiguous_panic_imports) en el código global #![no_std] al importar la caja estándar. Tanto core::panic! como std::panic! están entonces dentro del alcance y cuál se utiliza es ambiguo.
  • No elimine shebang en contexto de expresión include!(…) Esto puede provocar que las inclusiones que funcionaban anteriormente ya no se compilen si incluían archivos que comenzaban con un shebang.
  • [Las reexportaciones globales ambiguas ahora también son visibles entre cajas] (https://github.com/rust-lang/rust/pull/147984) Esto unifica el comportamiento entre los errores locales y entre cajas en estas exportaciones, lo que puede introducir nuevos errores de ambigüedad.
  • No normalice las cláusulas donde antes de comprobar que están bien formadas
  • Introducir una advertencia de compatibilidad futura sobre atributos codegen en métodos de rasgos sin cuerpo Estos atributos actualmente no tienen efecto en esta posición.
  • En Windows std::time::SystemTime::checked_sub_duration devolverá None para tiempos anteriores a la época de Windows (1/1/1601)
  • [Los identificadores de por vida como 'a ahora están normalizados mediante NFC] (https://github.com/rust-lang/rust/pull/149192).
  • [Revisión del manejo de nombres de archivos para lograr coherencia entre compiladores] (https://github.com/rust-lang/rust/pull/149709) Cualquier ruta emitida por el compilador ahora siempre respeta la relativa de las rutas y --remap-path-prefix proporcionadas originalmente. Un efecto secundario de este cambio es que las rutas emitidas para cajas locales en Cargo (dependencias de ruta y miembros del espacio de trabajo) ya no son absolutas sino relativas cuando se emiten como parte de un diagnóstico en una caja posterior. <a id="1.94.0-Internal-Changes"></a>

Cambios internos

Estos cambios no afectan ninguna interfaz pública de Rust, pero representan mejoras significativas en el rendimiento o los componentes internos de rustc y herramientas relacionadas.

  • Cambiar a annotate-snippets para emisión de errores Esto debería conservar prácticamente las mismas salidas en los mensajes de error de rustc.

rust 1.94.0

<a id="1.94.0-Language"></a>

Language

  • Impls and impl items inherit dead_code lint level of the corresponding traits and trait items
  • Stabilize additional 29 RISC-V target features including large portions of the RVA22U64 / RVA23U64 profiles
  • Add warn-by-default unused_visibilities lint for visibility on const _ declarations
  • Update to Unicode 17
  • Avoid incorrect lifetime errors for closures

<a id="1.94.0-Platform-Support"></a>

Platform Support

  • Add riscv64im-unknown-none-elf as a tier 3 target

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.94.0-Libraries"></a>

Libraries

  • Relax T: Ord bound for some BinaryHeap<T> methods.

<a id="1.94.0-Stabilized-APIs"></a>

Stabilized APIs

  • <[T]>::array_windows
  • <[T]>::element_offset
  • LazyCell::get
  • LazyCell::get_mut
  • LazyCell::force_mut
  • LazyLock::get
  • LazyLock::get_mut
  • LazyLock::force_mut
  • impl TryFrom<char> for usize
  • std::iter::Peekable::next_if_map
  • std::iter::Peekable::next_if_map_mut
  • x86 avx512fp16 intrinsics (excluding those that depend directly on the unstable f16 type)
  • AArch64 NEON fp16 intrinsics (excluding those that depend directly on the unstable f16 type)
  • f32::consts::EULER_GAMMA
  • f64::consts::EULER_GAMMA
  • f32::consts::GOLDEN_RATIO
  • f64::consts::GOLDEN_RATIO

These previously stable APIs are now stable in const contexts:

  • f32::mul_add
  • f64::mul_add

<a id="1.94.0-Cargo"></a>

Cargo

  • Stabilize the config include key. The top-level include config key allows loading additional config files, enabling better organization, sharing, and management of Cargo configurations across projects and environments. docs #16284
  • Stabilize the pubtime field in registry index. This records when a crate version was published and enables time-based dependency resolution in the future. Note that crates.io will gradually backfill existing packages when a new version is published. Not all crates have pubtime yet. #16369 #16372
  • Cargo now parses TOML v1.1 for manifests and configuration files. Note that using these features in Cargo.toml will raise your development MSRV, but the published manifest remains compatible with older parsers. #16415
  • Make CARGO_BIN_EXE_<crate> available at runtime

<a id="1.94.0-Compatibility-Notes"></a>

Compatibility Notes

  • Forbid freely casting lifetime bounds of dyn-types
  • Make closure capturing have consistent and correct behaviour around patterns Some finer details of how precise closure captures get affected by pattern matching have been changed. In some cases, this can cause a non-move closure that was previously capturing an entire variable by move, to now capture only part of that variable by move, and other parts by borrow. This can cause the borrow checker to complain where it previously didn't, or cause Drop to run at a different point in time.
  • Standard library macros are now imported via prelude, not via injected #[macro_use] This will raise an error if macros of the same name are glob imported. For example if a crate defines their own matches macro and then glob imports that, it's now ambiguous whether the custom or standard library matches is meant and an explicit import of the name is required to resolve the ambiguity. One exception is core::panic and std::panic, if their import is ambiguous a new warning (ambiguous_panic_imports) is raised. This may raise a new warning (ambiguous_panic_imports) on #![no_std] code glob importing the std crate. Both core::panic! and std::panic! are then in scope and which is used is ambiguous.
  • Don't strip shebang in expression-context include!(…)s This can cause previously working includes to no longer compile if they included files which started with a shebang.
  • Ambiguous glob reexports are now also visible cross-crate This unifies behavior between local and cross-crate errors on these exports, which may introduce new ambiguity errors.
  • Don't normalize where-clauses before checking well-formedness
  • Introduce a future compatibility warning on codegen attributes on body-free trait methods These attributes currently have no effect in this position.
  • On Windows std::time::SystemTime::checked_sub_duration will return None for times before the Windows epoch (1/1/1601)
  • Lifetime identifiers such as 'a are now NFC normalized.
  • Overhaul filename handling for cross-compiler consistency Any paths emitted by compiler now always respect the relative-ness of the paths and --remap-path-prefix given originally. One side-effect of this change is that paths emitted for local crates in Cargo (path dependencies and workspace members) are no longer absolute but relative when emitted as part of a diagnostic in a downstream crate.

<a id="1.94.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • Switch to annotate-snippets for error emission This should preserve mostly the same outputs in rustc error messages.
