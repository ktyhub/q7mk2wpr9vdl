rust 1.89.0

<a id="1.89.0-Language"></a>

Idioma

  • Estabilizar argumentos constantes inferidos explícitamente (feature(generic_arg_infer))
  • Agregar una pelusa mismatched_lifetime_syntaxes de advertencia por defecto. Esta pelusa detecta cuando diferentes categorías de sintaxis hacen referencia a la misma vida útil entre los argumentos de la función y los valores de retorno, lo que puede resultar confuso de leer, especialmente en código no seguro. Esta pelusa reemplaza la pelusa elided_named_lifetimes de advertencia predeterminada.
  • Ampliar unpredictable_function_pointer_comparisons para incluir también comparaciones de punteros de función en macros externas
  • Hacer que la pelusa dangerous_implicit_autorefs niegue de forma predeterminada
  • Estabilizar las características del objetivo avx512
  • Estabilizar las funciones de destino kl y widekl para x86
  • Estabilizar las funciones de destino sha512, sm3 y sm4 para x86
  • Estabilizar las características del objetivo LoongArch f, d, frecipe, lasx, lbt, lsx y lvz
  • Eliminar i128 y u128 de improper_ctypes_definitions
  • Estabilizar repr128 (#[repr(u128)], #[repr(i128)])
  • Permitir #![doc(test(attr(..)))] en todas partes
  • [Ampliar la extensión de vida temporal para pasar también por los constructores de estructuras de tupla y variantes de tupla] (https://github.com/rust-lang/rust/pull/140593)
  • Las funciones extern "C" en el objetivo wasm32-unknown-unknown ahora tienen una ABI compatible con los estándares <a id="1.89.0-Compiler"></a>

Compilador

  • Predeterminado para punteros de marco que no son hojas en aarch64-linux
  • Habilitar punteros de marco que no son hojas para Arm64EC Windows
  • Establecer punteros de marco de Apple por arquitectura <a id="1.89.0-Platform-Support"></a>

Soporte de plataforma

  • Agregar nuevos objetivos de nivel 3 loongarch32-unknown-none y loongarch32-unknown-none-softfloat
  • x86_64-apple-darwin está en proceso de ser degradado al Nivel 2 con herramientas de host Consulte la [página de soporte de plataforma] de Rust (https://doc.rust-lang.org/rustc/platform-support.html) para obtener más información sobre el soporte de plataforma por niveles de Rust. <a id="1.89.0-Libraries"></a>

Bibliotecas

  • Especifique la ruta base para file!
  • Permitir almacenar format_args!() en una variable
  • Agregar #[must_use] a [T; N]::map
  • Implementar DerefMut para Lazy{Cell,Lock}
  • Implementar Default para array::IntoIter
  • Implementar Clone para slice::ChunkBy
  • Implementar io::Seek para io::Take <a id="1.89.0-Stabilized-APIs"></a>

Carga

  • cargo fix y cargo clippy --fix ahora tienen de forma predeterminada la misma selección de destino de carga que otros comandos de compilación. Anteriormente, se aplicaba a todos los objetivos (como archivos binarios, ejemplos, pruebas, etc.). La bandera --edition todavía se aplica a todos los objetivos.
  • Estabilizar doctest-xcompile. Las pruebas de documentos ahora se prueban durante la compilación cruzada. Al igual que otras pruebas, utilizará la configuración runner para ejecutar las pruebas. Si necesita deshabilitar las pruebas para un objetivo, puede usar ignorar el atributo doctest para especificar los objetivos que se ignorarán. <a id="1.89.0-Rustdoc"></a>

Rustdoc

  • En dispositivos móviles, haga que la barra lateral sea de ancho completo y ajuste de línea. Esto hace que los nombres largos de secciones y elementos sean mucho más fáciles de manejar en dispositivos móviles. <a id="1.89.0-Compatibility-Notes"></a>

Notas de compatibilidad

  • Hacer de missing_fragment_specifier un error incondicional
  • [Habilitar la función de destino neon en aarch64-unknown-none-softfloat provoca una advertencia] (https://github.com/rust-lang/rust/pull/135160) porque LLVM no admite correctamente la combinación de código con y sin esa función de destino
  • Jerarquía de tamaños: Parte I
    • Introduce un pequeño cambio importante que afecta los límites de ?Sized en implicaciones en tipos recursivos que contienen proyecciones de tipos asociadas. No se espera que afecte a ninguna caja publicada existente. Se puede solucionar refactorizando los tipos involucrados u optando por la función inestable sized_hierarchy. Consulte el informe FCP para ver un ejemplo de código.
  • La pelusa de advertencia predeterminada elided_named_lifetimes es reemplazada por la pelusa de advertencia predeterminada mismatched_lifetime_syntaxes.
  • Error en tipos opacos recursivos anteriormente en el verificador de tipos
  • Los efectos secundarios de la inferencia de tipos al requerir tipos de elementos de expresiones repetidas de matriz son Copy ahora solo están disponibles al final de la verificación de tipos
  • [Los std::intrinsics::{copy,copy_nonoverlapping,write_bytes} obsoletos y accidentalmente estables ahora son intrínsecos adecuados] (https://github.com/rust-lang/rust/pull/139916). No hay afirmaciones de depuración que protejan contra UB y no se pueden obligar a que funcionen como punteros.
  • Eliminar std::intrinsics::drop_in_place, obsoleto desde hace mucho tiempo
  • Hacer que los predicados de buena formación ya no sean coinductivos
  • Eliminar el truco al comprobar la compatibilidad del método impl
  • Eliminar inferencia de tipos innecesaria debido a implicaciones de objetos de rasgos incorporados
  • Pelusa contra "stdcall", "fastcall" y "cdecl" en objetivos que no son x86-32
  • Las futuras advertencias de incompatibilidad relacionadas con el tipo nunca (!) ahora se informan en las dependencias
  • Asegúrese de que los intrínsecos del std::ptr::copy_* también realicen las comprobaciones estáticas de autoinicio
  • Las funciones extern "C" en el objetivo wasm32-unknown-unknown ahora tienen un ABI compatible con los estándares <a id="1.89.0-Internal-Changes"></a>

Cambios internos

Estos cambios no afectan ninguna interfaz pública de Rust, pero representan mejoras significativas en el rendimiento o los componentes internos de rustc y herramientas relacionadas.

  • Anular correctamente la reasignación de rutas de fuentes del compilador con el componente rustc-dev

original en inglés / English original

rust 1.89.0

<a id="1.89.0-Language"></a>

Language

  • Stabilize explicitly inferred const arguments (feature(generic_arg_infer))
  • Add a warn-by-default mismatched_lifetime_syntaxes lint. This lint detects when the same lifetime is referred to by different syntax categories between function arguments and return values, which can be confusing to read, especially in unsafe code. This lint supersedes the warn-by-default elided_named_lifetimes lint.
  • Expand unpredictable_function_pointer_comparisons to also lint on function pointer comparisons in external macros
  • Make the dangerous_implicit_autorefs lint deny-by-default
  • Stabilize the avx512 target features
  • Stabilize kl and widekl target features for x86
  • Stabilize sha512, sm3 and sm4 target features for x86
  • Stabilize LoongArch target features f, d, frecipe, lasx, lbt, lsx, and lvz
  • Remove i128 and u128 from improper_ctypes_definitions
  • Stabilize repr128 (#[repr(u128)], #[repr(i128)])
  • Allow #![doc(test(attr(..)))] everywhere
  • Extend temporary lifetime extension to also go through tuple struct and tuple variant constructors
  • extern "C" functions on the wasm32-unknown-unknown target now have a standards compliant ABI

<a id="1.89.0-Compiler"></a>

Compiler

  • Default to non-leaf frame pointers on aarch64-linux
  • Enable non-leaf frame pointers for Arm64EC Windows
  • Set Apple frame pointers by architecture

<a id="1.89.0-Platform-Support"></a>

Platform Support

  • Add new Tier-3 targets loongarch32-unknown-none and loongarch32-unknown-none-softfloat
  • x86_64-apple-darwin is in the process of being demoted to Tier 2 with host tools

Refer to Rust's platform support page for more information on Rust's tiered platform support.

<a id="1.89.0-Libraries"></a>

Libraries

  • Specify the base path for file!
  • Allow storing format_args!() in a variable
  • Add #[must_use] to [T; N]::map
  • Implement DerefMut for Lazy{Cell,Lock}
  • Implement Default for array::IntoIter
  • Implement Clone for slice::ChunkBy
  • Implement io::Seek for io::Take

<a id="1.89.0-Stabilized-APIs"></a>

Stabilized APIs

  • NonZero<char>
  • Many intrinsics for x86, not enumerated here
    • AVX512 intrinsics
    • SHA512, SM3 and SM4 intrinsics
  • File::lock
  • File::lock_shared
  • File::try_lock
  • File::try_lock_shared
  • File::unlock
  • NonNull::from_ref
  • NonNull::from_mut
  • NonNull::without_provenance
  • NonNull::with_exposed_provenance
  • NonNull::expose_provenance
  • OsString::leak
  • PathBuf::leak
  • Result::flatten
  • std::os::linux::net::TcpStreamExt::quickack
  • std::os::linux::net::TcpStreamExt::set_quickack

These previously stable APIs are now stable in const contexts:

  • <[T; N]>::as_mut_slice
  • <[u8]>::eq_ignore_ascii_case
  • str::eq_ignore_ascii_case

<a id="1.89.0-Cargo"></a>

Cargo

  • cargo fix and cargo clippy --fix now default to the same Cargo target selection as other build commands. Previously it would apply to all targets (like binaries, examples, tests, etc.). The --edition flag still applies to all targets.
  • Stabilize doctest-xcompile. Doctests are now tested when cross-compiling. Just like other tests, it will use the runner setting to run the tests. If you need to disable tests for a target, you can use the ignore doctest attribute to specify the targets to ignore.

<a id="1.89.0-Rustdoc"></a>

Rustdoc

  • On mobile, make the sidebar full width and linewrap. This makes long section and item names much easier to deal with on mobile.

<a id="1.89.0-Compatibility-Notes"></a>

Compatibility Notes

  • Make missing_fragment_specifier an unconditional error
  • Enabling the neon target feature on aarch64-unknown-none-softfloat causes a warning because mixing code with and without that target feature is not properly supported by LLVM
  • Sized Hierarchy: Part I
    • Introduces a small breaking change affecting ?Sized bounds on impls on recursive types which contain associated type projections. It is not expected to affect any existing published crates. Can be fixed by refactoring the involved types or opting into the sized_hierarchy unstable feature. See the FCP report for a code example.
  • The warn-by-default elided_named_lifetimes lint is superseded by the warn-by-default mismatched_lifetime_syntaxes lint.
  • Error on recursive opaque types earlier in the type checker
  • Type inference side effects from requiring element types of array repeat expressions are Copy are now only available at the end of type checking
  • The deprecated accidentally-stable std::intrinsics::{copy,copy_nonoverlapping,write_bytes} are now proper intrinsics. There are no debug assertions guarding against UB, and they cannot be coerced to function pointers.
  • Remove long-deprecated std::intrinsics::drop_in_place
  • Make well-formedness predicates no longer coinductive
  • Remove hack when checking impl method compatibility
  • Remove unnecessary type inference due to built-in trait object impls
  • Lint against "stdcall", "fastcall", and "cdecl" on non-x86-32 targets
  • Future incompatibility warnings relating to the never type (!) are now reported in dependencies
  • Ensure std::ptr::copy_* intrinsics also perform the static self-init checks
  • extern "C" functions on the wasm32-unknown-unknown target now have a standards compliant ABI

<a id="1.89.0-Internal-Changes"></a>

Internal Changes

These changes do not affect any public interfaces of Rust, but they represent significant improvements to the performance or internals of rustc and related tools.

  • Correctly un-remap compiler sources paths with the rustc-dev component
