hipit v0.2.6

Temporización de subtítulos, tolerancia mux e imágenes Wan 2.7

Esta versión corrige dos defectos que rechazaron o estropearon la salida correcta, agrega los modelos de imagen Wan 2.7 y hace que los ejemplos de perfil de tiempo de ejecución en los archivos README se puedan copiar y pegar.

Tiempo de los subtítulos

Un alineador informa que cada palabra termina donde comienza la siguiente, y tokenFrameSpan mantuvo el marco en el que cae ese instante, por lo que las ventanas de Word adyacentes se superponen por un marco. Los límites de las Cue heredaron esa superposición, y un renderizador que dibuja Cues en una sola posición dibujó dos de ellos en el mismo fotograma. Los subtítulos en chino se superponían en casi todas las transiciones.

exclusiveActivationFrames en @hypit/caption-fine ya estableció la regla para Atoms: tan pronto como se inicia la siguiente unidad creada, la anterior se detiene. Ahora se aplica una vez donde se construyen los tiempos de las unidades, por lo que los límites exclusivos de Cue siguen desde la envolvente Cue que termina en su última unidad. La línea de tiempo mantiene las medidas del token sin procesar. (#300, #297)

Afirmación final de mux

El WAV preparado se afirma con exactitud de muestra antes del mux, por lo que la afirmación final es sobre lo que sobrevive al AAC. AAC no puede transportar un recuento de muestras arbitrario: el codificador emite cuadros de 1024 muestras e informa un retraso de cebado que el muxer MP4 compensa con una lista de edición, por lo que el intervalo presentado aterriza a algunas muestras de la entrada. Medidas en tono sintético, 4.249.600 muestras presentaron 4.249.584 y 4.236.800 presentaron 4.236.768. Rellenar la línea de tiempo con un número entero de fotogramas AAC no lo elimina.

Por lo tanto, exigir igualdad exacta rechazó cada mux correcto cuya longitud no sea un punto fijo de ese viaje de ida y vuelta, fallando un segundo render 88.5 en su último paso con todo el material generado ya pagado. La afirmación ahora tolera el retraso del codificador. (#298, #296)

Modelos de imagen Wan 2.7

@hypit/wan@1 lleva dos modelos exactos, wan-2.7-image y wan-2.7-image-pro. Ambos aceptan un mensaje de hasta 5000 caracteres, hasta nueve imágenes de referencia y una banda 1K o 2K; la variante Pro agrega 4K. count renderiza hasta cuatro imágenes, o nombra el techo de un conjunto de imágenes de hasta doce, donde el modelo elige cuántas devuelve.

El modelo no tiene relación de aspecto: con referencias presentes, la salida sigue a la última, y ​​una solicitud de solo aviso se representa en el encuadre de la banda. Lee exclusiones del mensaje en lugar de un campo de mensaje negativo.

@hypit/provider-monid sirve a ambos a través de los puntos finales alibaba de Monid. Su ruta de resultados previamente asumía un video; las rutas ahora nombran su tipo de resultado y la colección descarga cada archivo devuelto, por lo que un conjunto de imágenes llega como un conjunto. Se informan dos límites de servicio antes de que se resuelva cualquier referencia: 4K se procesa solo a partir de un mensaje y una solicitud representa como máximo cuatro imágenes fuera de un conjunto de imágenes. (#301)

Almacenamiento de credenciales de Windows

HypiHub OAuth almacena JSON con tokens de actualización y acceso JWT, y el PasswordVault de Windows Credential Locker rechaza contraseñas de más de 512 caracteres con un error de escritura opaco una vez que se completa el flujo del navegador. La Tienda ahora rechaza dicha escritura antes de generar PowerShell y nombra el archivo Tienda en el mensaje. (#294, #291)

Documentación

  • Los ejemplos de perfil de tiempo de ejecución README del proveedor son perfiles completos. Copiados en hypit.runtime.json, anteriormente fallaron en auth status. (#289, #288)
  • El ejemplo del perfil de tiempo de ejecución README de HypiHub es un hypit.runtime.json válido: faltaban format, dataRoot y un almacén de credenciales declarado, y se llamaba almacén os mientras que runtime init ahora escribe platform. (#295, #292)

hypit v0.2.6

Caption timing, mux tolerance and Wan 2.7 images

This release fixes two defects that rejected or spoiled correct output, adds the Wan 2.7 image models, and makes the Runtime Profile examples in the READMEs copy-pasteable.

Caption timing

An aligner reports each word ending where the next one begins, and tokenFrameSpan kept the frame that instant falls in, so adjacent Word windows overlapped by one frame. Cue boundaries inherited that overlap, and a renderer that draws Cues at a single position drew two of them on the same frame. Chinese subtitles overlapped at almost every transition.

exclusiveActivationFrames in @hypit/caption-fine already stated the rule for Atoms: as soon as the next authored unit starts, the previous one stops. It is now applied once where unit timings are built, so exclusive Cue boundaries follow from the Cue envelope ending at its last unit. The Timeline keeps the raw Token measurements. (#300, #297)

Final mux assertion

The staged WAV is asserted sample-exact before the mux, so the final assertion is about what survives AAC. AAC cannot carry an arbitrary sample count: the encoder emits 1024-sample frames and reports a priming delay that the MP4 muxer compensates with an edit list, so the presented span lands a few samples away from the input. Measured on a synthetic tone, 4,249,600 samples in presented 4,249,584, and 4,236,800 presented 4,236,768. Padding the timeline to a whole number of AAC frames does not remove it.

Demanding exact equality therefore rejected every correct mux whose length is not a fixed point of that round trip, failing an 88.5 second render at its last step with all generated material already paid for. The assertion now tolerates the encoder's delay. (#298, #296)

Wan 2.7 image models

@hypit/wan@1 carries two exact models, wan-2.7-image and wan-2.7-image-pro. Both take a prompt of up to 5,000 characters, up to nine reference images, and a 1K or 2K band; the Pro variant adds 4K. count renders up to four pictures, or names the ceiling of an image set of up to twelve, where the model chooses how many it returns.

The model takes no aspect ratio: with references present the output follows the last one, and a prompt-only request renders at the band's own framing. It reads exclusions from the prompt rather than a negative-prompt field.

@hypit/provider-monid serves both through Monid's alibaba endpoints. Its result path previously assumed one video; routes now name their result type and collection downloads every returned file, so an image set arrives as a set. Two service limits are reported before any reference is resolved: 4K renders from a prompt alone, and a request renders at most four pictures outside an image set. (#301)

Windows credential storage

HypiHub OAuth stores JSON carrying JWT access and refresh tokens, and the Windows Credential Locker's PasswordVault rejects passwords over 512 characters with an opaque write failure after the browser flow completes. The Store now refuses such a write before spawning PowerShell and names the file Store in the message. (#294, #291)

Documentation

  • The Provider README Runtime Profile examples are complete Profiles. Copied into hypit.runtime.json they previously failed auth status. (#289, #288)
  • The HypiHub README Runtime Profile example is a valid hypit.runtime.json: it was missing format, dataRoot and a declared credential store, and named store os while runtime init now writes platform. (#295, #292)
