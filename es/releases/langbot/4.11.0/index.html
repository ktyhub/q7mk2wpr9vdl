#LangBot v4.11.0

LangBot es una plataforma de agente y chatbot de IA de código abierto que admite múltiples plataformas de mensajería instantánea, grandes modelos de lenguaje, bases de conocimiento y complementos para ayudarlo a crear, implementar y administrar asistentes de IA. LangBot es una plataforma de agentes y chatbot de IA de código abierto que conecta plataformas de mensajería, grandes modelos de lenguaje, bases de conocimiento y complementos para ayudarlo a crear, implementar y administrar asistentes de IA.

🚀 Funciones clave / Actualizaciones clave

LangBot 4.11 trae una importante actualización arquitectónica: el robot puede responder a eventos de la plataforma, el corredor del agente se cambia a un complemento y la interfaz de usuario web agrega un nuevo asistente de espacio de trabajo. LangBot 4.11 trae una importante actualización arquitectónica: los bots pueden reaccionar a los eventos de la plataforma, los agentes ejecutores ahora son complementos y la WebUI agrega un asistente de espacio de trabajo.

⚡ Agentes basados en eventos (EBA): escrito por @RockChinQ @huanghuoguoguo @wangcham @dadachann

Más allá de los mensajes, los eventos de la plataforma, como uniones, abandonos, retiradas, reacciones y tarjetas clicks, ahora pueden activar el procesamiento. Se han reconstruido 13 adaptadores en EBA y el Enrutamiento de eventos envía cada evento a un Pipeline, un Agente o un procesador de complementos.

LangBot v4.11.0

Highlights

  • Event-driven agents replace message-only triggers — The biggest architectural shift in 4.11: 13 platform adapters were rewritten on the new Event-Based Agents (EBA) core, so joins, leaves, recalls, reactions, and card clicks can now feed an Event Routing layer that dispatches to Pipelines, Agents, or plugin event processors. In practice your bot can react to chat lifecycle events, not just inbound text — but revisit any adapter-level assumptions, since routing is now declarative and the event debugger is the fastest way to inspect payloads and run logs. Platform-level wins ride along here: Slack Socket Mode, DingTalk card interactions, WeChat typing indicators, OneBot WebSocket (PR #2277).

  • Built-in runners removed — migration is mandatory — This is the release's breaking change: LocalAgent, Dify, Coze, and n8n were pulled out of core into Marketplace plugins (joined by new Codex, Claude Code, and ACP runners), so an upgraded instance has no runners until you run the migration on the Pipelines page. The one-click path auto-installs required plugins and backs up config, but migrated pipelines start fresh sessions, air-gapped installs must choose "Data only" and install runner plugins manually, and any custom Runner must be rewritten against AgentRunner Protocol v1. Also upgrade installed plugins to langbot-plugin 0.7.x and consult the config map in the migration docs.

  • Marketplace certification and signed plugins — Core now enforces certified archive admission and verifies plugin signatures (PR #2553, #2554), with certified packages routed to shared workers (#2578) and explicit handling for unsigned Cloud/dedicated plugins (#2609, #2610). For plugin developers this is a supply-chain change: packaging and distribution now pass through a certification gate, so test against the certified flow early — the long tail of fixes around OSS compatibility (#2577) and backfilled artifact digests (#2580) suggests the first rollout had rough edges.

  • Telemetry on by default; config keys changed — Execution telemetry is now enabled by default without message content; opt out with space.disable_telemetry: true if your deployment has strict data policies. Audit your config too: media_cache, api.host, and runner.admin_plugins were added, and force_box_session_id_template was removed, so anything still referencing the old key needs updating.

  • Operations and auth tooling — The WebUI gains a Workspace Assistant that inspects resources and builds Pipelines/knowledge bases through chat, with every write gated behind explicit confirmation (PR #2549), alongside operation traceability with integrity checks (#2579) and lbctl + API-key diagnostics (#2601). WebAuthn/passkey login (#2530) and TOTP 2FA (#2565) are now available — worth enabling for any instance exposed beyond a trusted network.

  • Storage and database fixes worth watching — Media is now stored content-addressed, curbing langbot.db bloat (#2544), while Runner execution on PostgreSQL was repaired and SQLite WAL enabled (#2560) — relevant if you run a non-default database backend. Also fixed: RAG ingestion state retention after interruption (#2556), WeCom AI Bot empty bubbles and premature stream close on blank chunks (#2561), and the fnOS package now runs entirely non-root.

LangBot 是一个开源的 AI 聊天机器人与智能体平台，支持多种即时通讯平台、大语言模型、知识库和插件，帮助你构建、部署和管理 AI 助手。 LangBot is an open-source AI chatbot and agent platform that connects messaging platforms, large language models, knowledge bases, and plugins to help you build, deploy, and manage AI assistants.

🚀 Key Features / 关键更新

LangBot 4.11 带来了一次较大的架构升级：机器人可以响应平台事件，Agent 运行器改为插件化，WebUI 新增工作区助手。 LangBot 4.11 brings a major architectural update: bots can react to platform events, Agent runners are now plugins, and the WebUI adds a Workspace Assistant.

⚡ 事件驱动智能体 / Event-Based Agents (EBA) - Authored by @RockChinQ @huanghuoguoguo @wangcham @dadachann

除消息外，入群、退群、撤回、表情回应、卡片点击等平台事件现在也可以触发处理。13 个平台适配器已基于 EBA 架构重写，可在「事件路由」中将事件分发给 Pipeline、Agent 或插件处理器。 Beyond messages, platform events such as joins, leaves, recalls, reactions and card clicks can now trigger processing. 13 adapters have been rebuilt on EBA, and Event Routing dispatches each event to a Pipeline, an Agent or a plugin processor.

<img width="1058" height="1002" alt="Event Routing" src="https://github.com/langbot-app/LangBot/releases/download/v4.11.0/eba-event-routing.png" /> <img width="1442" height="864" alt="Create event processor" src="https://github.com/langbot-app/LangBot/releases/download/v4.11.0/eba-create-processor.png" />
  • 场景化路由 / Scenario routes：按欢迎新成员、处理成员离开等常用场景创建路由 / Create routes from common scenarios such as welcoming new members
  • 三类处理器 / Three processor types：Pipeline、Agent、插件事件处理器可组合使用 / Pipelines, Agents and plugin Event Processors can be combined
  • 事件调试器 / Event debugger：表单编辑事件数据，查看运行日志与执行详情 / Edit event payloads in a form and inspect run logs and details
  • 平台增强 / Platform upgrades：Slack Socket Mode、钉钉卡片交互、微信“正在输入”、OneBot WebSocket 等 / Slack Socket Mode, DingTalk card interactions, WeChat typing indicator, OneBot WebSocket and more

🧩 AgentRunner 插件化 / Pluginized AgentRunner - Authored by @huanghuoguoguo @RockChinQ @fdc310

LocalAgent、Dify、Coze、n8n 等内置运行器已迁出主程序，改为扩展市场中的官方插件，并新增 Codex、Claude Code、ACP 等运行器。运行器可独立更新、按需安装，开发者也可基于 AgentRunner Protocol v1 编写自己的运行器。 Built-in runners such as LocalAgent, Dify, Coze and n8n have moved out of the core into official Marketplace plugins, alongside new runners such as Codex, Claude Code and ACP. Runners are updated independently and installed on demand, and developers can write their own on AgentRunner Protocol v1.

<img width="1418" height="1124" alt="AgentRunner plugins in Marketplace" src="https://github.com/langbot-app/LangBot/releases/download/v4.11.0/runner-plugins-marketplace.png" />

  • 权限可控 / Scoped authorization：运行器只能调用当前上下文授权的工具与平台 API / Runners only reach tools and platform APIs authorized for the current context
  • 插件认证 / Plugin certification：扩展市场展示认证徽章，主程序校验插件签名 / Certification badges in the Marketplace and signature verification in the core

🤖 工作区助手 / Workspace Assistant - Authored by @huanghuoguoguo @RockChinQ @dadachann

WebUI 新增工作区助手，可通过对话查询资源、创建并配置流水线与知识库，所有写操作需确认后才执行。 The WebUI adds a Workspace Assistant that inspects resources and sets up Pipelines and knowledge bases through chat; every write runs only after confirmation.
