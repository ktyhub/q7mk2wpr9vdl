códice v1.6.1

[1.6.1] - 2026-09-29

Destacados

  • Respuestas más nítidas de codegraph_explore. Devuelve las funciones y métodos que usted nombra, incluso desde un archivo muy grande o uno lleno de anulaciones con el mismo nombre, respeta los números de línea en una consulta y dice cuándo acortó una respuesta en lugar de llamarla completa.
  • La navegación y las solicitudes de su aplicación están en el gráfico. Las páginas Expo Router, Next.js, React Router, TanStack Router, Vue Router/Nuxt y SvelteKit y los enlaces entre ellas son rutas y bordes navigates, y el fetch de una página llega a la ruta que le sirve, por lo que "adónde va esto" y "cómo se llama este punto final" son una pregunta para codegraph_explore.
  • Explore dice cuándo ocurre una llamada. Cada salto en la sección Flujo de codegraph_explore lleva la condición bajo la cual se ejecuta, para JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go y C.
  • Menos enlaces incorrectos. Muchas correcciones en cómo se resuelven las llamadas, importaciones y herencias en TypeScript, JavaScript, Python, Java, Kotlin, Go, Rust, Scala, PHP y C/C++, por lo que una llamada deja de aterrizar en un símbolo no relacionado que comparte su nombre.
  • Sincronización en vivo en la que puede confiar. El servidor MCP sigue un índice reconstruido después de codegraph index, una sincronización interrumpida a mitad de camino recupera lo que tendría un índice limpio, las carpetas con enlaces simbólicos permanecen sincronizadas y un proyecto WSL en una unidad de Windows obtiene un índice propio.
  • Más liviano en repositorios grandes. Las exploraciones repetidas desde el servidor MCP ya no vuelven a escanear todo el gráfico, y los archivos de gran tamaño y los dispositivos de video .ts ya no se leen ni analizan durante la indexación.
  • Actualización: vuelva a indexar sus proyectos después de esta versión: varias correcciones y los nuevos enlaces de navegación se escriben durante la indexación.

Nuevas características

  • Codex y Astra leen la guía del proyecto de AGENTS.md. La guía del agente canónico ahora se encuentra en AGENTS.md (con un docs/AGENTS.md anidado para notas de validación largas); CLAUDE.md es un envoltorio delgado @AGENTS.md para Claude Code. Codex/Astra ya no pierde las antiguas instrucciones exclusivas de CLAUDE.
  • Las páginas Next.js y su navegación están en el gráfico. Las páginas de App Router (app/(group)/blog/[slug]/page.tsx → /blog/:slug) y las páginas de Pages Router son rutas vinculadas al componente que exportan, y <Link href>, un <a href> interno, router.push/router.replace (next/navigation y next/router), redirect()/permanentRedirect() y el middleware. NextResponse.redirect(…) son bordes navigates entre ellos. Las exportaciones app/api/**/route.ts (GET, POST,…) son puntos finales vinculados a sus funciones, y los controladores pages/api/* son ANY /api/…. Vuelva a indexar después de la actualización.
  • Las rutas y la navegación de TanStack Router están en el gráfico. Las rutas se leen en ambas formas en que la aplicación TanStack las declara: basada en archivos, donde createFileRoute('/posts/$postId') lleva toda la ruta, y basada en código, donde cada createRoute({ path, getParentRoute }) se compone a través de su padre, y navigate({ to }), un redirect({ to }) lanzado y <Link to>/<Navigate to> son bordes navigates de la ruta que nombran. Un diseño _auth sin ruta, una carpeta (group) y __root no son páginas, y un destino calculado se omite en lugar de adivinarse. Vuelva a indexar después de la actualización.
  • La navegación de Vue Router, Nuxt y SvelteKit está en el gráfico. Vue: las rutas se leen desde createRouter({ routes: [...] }), incluido un component: () => import('@/views/Login') lento, y router.push / router.replace / $router.push, navigateTo y <router-link> / <RouterLink> / <NuxtLink> de Nuxt son bordes de navigates, resueltos también por nombre de ruta. como por camino. SvelteKit: goto('/login'), redirect(303, …) de una carga o acción de formulario, y un <a href> simple son bordes navigates, y una página se une al archivo de página que la sirve y al +page.server.js al lado. Un destino calculado o una ruta que no se declara nada se omite en lugar de adivinarse. Vuelva a indexar después de la actualización.
  • La navegación de React Router está en el gráfico. history.push / history.replace, navigate(…) de useNavigate, redirect() en un cargador o una acción, y <Link to> / <NavLink to> / <Navigate to> / <LinkContainer to> de react-router-bootstrap ahora son bordes navigates de la ruta que abren, y una ruta con un parámetro opcional. (/cart/:id?) es alcanzado tanto por /cart como por /cart/5. Un destino calculado o una ruta sin ruta se omite en lugar de adivinarse, y un paths.push('/x') normal en una matriz nunca se confunde con la navegación. Vuelva a indexar después de la actualización.
  • codegraph_explore sigue una aplicación web en todos sus niveles. La llamada fetch('/api/users', { method: 'POST' }) de una página (o una llamada axios / ky / got / $fetch, incluida una a través de una instancia axios.create({ baseURL })) ahora llega a la ruta que la sirve en el mismo índice. Un trabajo colocado en una cola BullMQ/Bull llega al método @Process, al controlador Worker o queue.process que lo consume, un evento NestJS EventEmitter2 a sus oyentes @OnEvent, un mensaje de socket al controlador @SubscribeMessage de la puerta de enlace y viceversa, y una acción del servidor Next.js llamada desde un archivo client es un cruce al servidor. Cada uno es un salto sintetizado que la sección Flow nombra y dónde fue conectado. Sólo se empareja una ruta literal o un nombre de evento. Vuelva a indexar para recoger los nuevos bordes.
  • codegraph_explore dice cuándo ocurre cada llamada. Cada salto en la sección Flujo lleva la condición bajo la cual se encuentra su sitio de llamada - ↓ calls (when isCollected) - leído desde las ramas if / else, switch / when / match, ternario, try y && / and alrededor de la llamada y los retornos tempranos antes de ella (if (busy) return lee como !busy, if err != nil { return } de Go como err == nil). Funciona para JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go y C, se lee desde la fuente tal como está y un lenguaje sin reglas no dice nada más que adivinar.
  • Aplicaciones React Native: los módulos nativos de Swift y sus eventos se conectan de un extremo a otro. Una llamada JS como captureView.finalizeCaptureSession(), donde captureView está vinculado a NativeModules.CaptureView y el módulo es una clase Swift expuesta a través de una corrección RCT_EXTERN_MODULE, ahora se resuelve en el método Swift en sí en lugar de detenerse en la constante, por lo que codegraph_explore sigue el código en nativo. Los eventos nativos → JS ahora también llegan a los oyentes escritos en línea (addListener('onZipComplete', (data) => { … })), atribuidos al componente que los registra. Vuelva a indexar después de actualizar para seleccionar los nuevos bordes.
  • Aplicaciones Expo Router: las pantallas y la navegación están en el gráfico. Cada archivo de pantalla bajo app/ (o src/app/) es ahora un nodo de ruta nombrado por su ruta (/object-detail, /item/[id], con las carpetas (group) eliminadas) vinculado al componente que representa. Llamadas como router.push('/object-detail?…'), router.navigate({ pathname: '/item/[id]', params }), hrefs literales de plantilla, un href mantenido en un const local y router.push(await pickRoute()) donde el asistente devuelve rutas de pantalla (un borde por pantalla puede regresar) se resuelven en la pantalla que abren como un nuevo borde navigates que recuerda el href, por lo que "adónde va al tocar esto" y "quién abre esta pantalla" son un salto. codegraph_explore y callers en lugar de un callejón sin salida en una cadena. Vuelva a indexar después de actualizar para seleccionar los nuevos bordes.

Correcciones

  • El enlace de aviso de Claude Code ya no se ejecuta en los mensajes de notificación de tareas que Claude Code inyecta cuando finaliza un agente en segundo plano, lo que elimina una parada de varios segundos en cada turno. (#1832)
  • Las llamadas Rust en self ahora permanecen con el tipo adjunto en lugar de vincularse al método del mismo nombre de un tipo no relacionado. Gracias @L4XB. (#1861)
  • Desactivar la telemetría ahora restablece su identidad y evita que los procesos en ejecución registren, envíen o restablezcan datos no enviados. (#1869)
  • Las llamadas entre archivos JavaScript, JSX y TypeScript mantienen a sus llamantes y flujos de devolución de llamadas.
  • Las acciones de Zustand mantienen a quienes llaman cuando se leen a través de tiendas escritas, se desestructuran del estado de la tienda o se seleccionan mediante un enlace.
  • Las llamadas puente Direct React Native conservan sus implementaciones nativas y relaciones multiplataforma.
  • Los captadores de tipo extensión Dart siguen permitiéndose búsquedas cuando se utiliza el analizador WebAssembly.
  • Llamar a un método integrado en un valor esperado ya no registra una llamada a una clase no relacionada que declara un método del mismo nombre, y una variable vinculada a una llamada esperada ahora resuelve métodos en el tipo que devuelve la llamada. Gracias @maxmilian. (#1840)
  • Las asignaciones de Spring ahora incluyen todas las combinaciones de rutas declaradas y resuelven las constantes declaradas en el mismo archivo, mientras que las rutas no resueltas ya no aparecen como rutas raíz falsas. (#1461)
  • codegraph node ahora acepta una referencia de archivo que lleva un número de línea (src/app.ts:42, src/app.ts:42-80, src/app.ts#L42, src/app.ts#L42-L80) en lugar de informar el archivo como no indexado; el rango de líneas se convierte en la ventana que se lee, y un --offset/--limit que usted mismo pase aún gana. Un camino que realmente se llama así todavía se busca tal como está escrito. (#1831)
  • codegraph callers, codegraph callees y codegraph impact ahora resuelven nombres calificados, resultados de grupo y bordes JSON por definición, y aceptan --file para restringir nombres ambiguos; gracias @ferrine. (#1512, #1656)
  • codegraph callers, codegraph callees y codegraph impact (CLI y MCP) ahora informan nombres faltantes con sugerencias de lo que quiso decir en lugar de los resultados de otro símbolo, y las coincidencias exactas sin personas que llaman permanecen vacías; gracias @uvmplus. (#1473, #1481)
  • Cuando codegraph_explore recorta un archivo grande, los espacios en su fuente ahora nombran los símbolos que quedaron fuera, usando solo el espacio que le queda al archivo, por lo que los nombres nunca eliminan el código en sí. (#1711)
  • codegraph_explore ya no informa "despacho en tiempo de ejecución" a través de una clase base que no declara el método, por lo que un nombre común compartido por muchas subclases no relacionadas ya no abre una respuesta con una lista de miles de implementaciones.
  • Cuando nombras varias funciones en un archivo y hay código no relacionado entre ellas, codegraph_explore ahora devuelve las funciones que nombraste antes del código que las rodea, en lugar de gastar el espacio del archivo en ese código y dejar una de las funciones que solicitaste sin fuente alguna.
  • codegraph_explore ahora devuelve el cuerpo de un método que usted nombra junto con su clase, como SQLCompiler.as_sql, incluso en un archivo lleno de anulaciones del mismo nombre. Solía ​​reducir el método solicitado a su línea de firma, mientras que los métodos más pequeños a su alrededor volvían en su totalidad. Un método demasiado largo para la respuesta ahora regresa como sus líneas iniciales más los lugares donde llama a los otros símbolos que nombró, con la consulta de seguimiento exacta que devuelve el resto.
  • codegraph_explore ahora respeta los números de línea en una consulta: compiler.py:776 devuelve el método que contiene esa línea y compiler.py lines 900-1003 (o :900-1003, #L900-L1003, L900-L1003) devuelve exactamente esas líneas. Solía ​​fijar el archivo e ignorar los números.
  • Cuando un nombre de archivo en una consulta codegraph_explore coincide con archivos en más de una carpeta, solo se fijan aquellos que definen una función o clase que la consulta también nombra, y la línea de resumen enumera los archivos omitidos. Cada coincidencia solía estar fijada, por lo que el archivo al que te refieres tiene la mitad del espacio que obtiene cuando omites su nombre; un nombre compartido por muchos archivos, como models.py, ahora se resuelve de la misma manera en lugar de ser reportado como ambiguo.

MCP / indexación

  • En Windows, el demonio MCP compartido ahora espera más tiempo a que otro programa (un análisis antivirus, un indexador u otra sesión que lea su archivo de bloqueo) suelte ese archivo, por lo que se inicia en lugar de abandonar la sesión para recurrir a un servidor en proceso más lento. (#1773)
  • Un archivo que supera el límite de tamaño ya no se lee antes de omitirlo. Los grandes videos comprometidos y los elementos de blobs solían cargarse en la memoria por completo, una vez por paso de indexación, solo para descartarse; La indexación y la detección de cambios ahora se basan en el tamaño del archivo. Gracias @danusha2345. (#1910)
  • Un video de flujo de transporte MPEG que se llama .ts (dispositivos dorados bajo testdata/, e2e clips) ahora se reconoce desde sus primeros bytes y se omite en lugar de enviarse al analizador TypeScript, que pasó mucho tiempo en cada clip sin símbolos. Los archivos reales TypeScript todavía están indexados. Gracias @danusha2345. (#1910)
  • Las llamadas repetidas a codegraph_explore desde un servidor MCP en ejecución ya no vuelven a clasificar todo el gráfico cada vez para encontrar el archivo principal del proyecto; la respuesta se reutiliza hasta que cambia el índice. Gracias @danusha2345. (#1864)
  • La observación de archivos ya no elimina el nuevo escaneo completo que solicita un directorio eliminado cuando falla la sincronización, por lo que los archivos eliminados abandonan el índice en lugar de permanecer. (#1964)
  • La ejecución de codegraph index mientras el servidor MCP está en ejecución ya no deja la escritura de sincronización automática en vivo en el índice antiguo reemplazado: el servidor ahora cambia al índice reconstruido antes de su próxima actualización y se pone al día con todo lo que de otro modo se habría perdido. Gracias @danusha2345. (#1902)
  • El inicio y la limpieza del demonio ahora preservan los bloqueos PID heredados activos y al mismo tiempo recuperan registros inactivos o con identidad refutada, lo que evita que dos escritores sirvan en el mismo proyecto.
  • Un codegraph.db vacío o sin tablas dejado en un directorio principal (por un codegraph init interrumpido o un ~/.codegraph/ nunca poblado) ya no cuenta como un proyecto inicializado, por lo que ya no puede ocultar el índice real de cada proyecto debajo de él. Sólo una base de datos que realmente lleva el esquema de código se trata como inicializada, y codegraph init en el directorio con el archivo roto ahora lo repara en lugar de rechazarlo con "Ya inicializado". Gracias @danusha2345. (#1895)
  • La sincronización incremental ahora mantiene la vinculación de borde a salvo de fallas: reemplazar un borde resuelto con su referencia de recuperación se confirma atómicamente, por lo que una interrupción no puede eliminar permanentemente la relación.
  • El estado ahora detecta cambios confirmados pero no indexados y ediciones restauradas sin escanear cada archivo fuente; gracias @inth3shadows. (#1829)
  • El enlace de solicitud ya no inyecta proyectos no relacionados cuando se ejecuta desde su directorio de inicio o desde un directorio más amplio que contenga un manifiesto de espacio de trabajo perdido. (#1454)
  • codegraph_explore ahora dice que cuando una consulta nombra un archivo sin extensión, el índice no se mantiene. Una ruta como scripts/deploy no tiene extensión en su último segmento, por lo que no pasó la prueba de forma que decide que un tramo es una ruta fuera de toda duda: el nombre se dejó en la consulta, se dividió en scripts y deploy, y la respuesta regresó como un montón de fuentes no relacionadas sin ningún indicio de que el archivo que usted nombró nunca fue consultado. Dicho intervalo ahora se compara con el directorio del proyecto: si es un archivo real, la respuesta lleva la misma nota No indexed file uniquely matches ... que ya recibió un src/foo.ts mal escrito. La prosa cortada (and/or, input/output, gen_server:call/2) no tiene ningún archivo detrás y aún se deja intacta en la consulta. (#1830)
  • La indexación ahora tiene éxito cuando SQLite de Node.js carece de FTS5, y la búsqueda vuelve al nombre y la coincidencia aproximada; gracias @aniruddhaadak80. (#1532)
  • codegraph_explore ahora deja claro que los recuentos de llamadas sugeridos son orientativos, por lo que los agentes siguen explorando cuando una respuesta está incompleta; gracias @rongbc. (#1504, #1570)
  • Las funciones de C++ que siguen espacios de nombres anónimos que contienen plantillas de cadenas sin formato ahora se indexan correctamente, incluso cuando el texto de la plantilla se parece a una llamada de macro sin terminar. (#1505)
  • La indexación ahora advierte cuando los errores del analizador dejan un archivo sin símbolos, incluidas cadenas sin formato de C++ con delimitadores de 16 caracteres, por lo que el código faltante ya no permanece en silencio. (#1522)
  • codegraph index <path> ahora rechaza rutas no inicializadas y nombra el padre inicializado más cercano en lugar de reconstruirlo silenciosamente; gracias @danusha2345. (#1524, #1689)
  • La sincronización ahora recupera las mismas conexiones que un índice limpio después de una resolución de referencia interrumpida, incluidas las llamadas heredadas y las devoluciones de llamadas que anteriormente permanecían perdidas. (#1577)
  • codegraph_explore ahora reserva la fuente para nuevos subagentes y después de la compactación del contexto, con desduplicación de llamadas cruzadas disponible solo a través de una suscripción explícita a CODEGRAPH_EXPLORE_DEDUP=1; gracias @danusha2345. (#1620, #1624)
  • El alcance del observador ahora coincide con git ls-files --exclude-standard (#1728). buildDefaultIgnore / buildScopeIgnore leen .git/info/exclude y core.excludesFile (no solo la raíz .gitignore), y los directorios semilla git informan como ignorados y sin seguimiento, por lo que los efectos anidados de .gitignore eliminan al observador en vivo de la misma manera que el indexador los omite. La sincronización automática de un solo archivo ya era incremental (pendingFiles → sync({ paths }) con alcance); el espacio restante estaba observando los árboles que git había excluido.
  • La sincronización en vivo ya no permite que el registro de escritura anticipada crezca sin límites cuando un lector lo mantiene abierto (#1539). La sincronización incremental ahora usa la misma pausa del escritor que ya usaba la indexación completa, y si los puntos de control aún no pueden finalizar una vez que el registro supera su límite de tamaño documentado (normalmente porque el grupo de consultas se lee al mismo tiempo), la sincronización se detiene con un error claro en lugar de seguir escribiendo hasta que se llene el disco. El comportamiento anterior podría dejar un registro de varias decenas de gigabytes junto a un índice de unos pocos gigabytes en un proyecto grande. Cierre los lectores simultáneos y vuelva a intentarlo, o aumente CODEGRAPH_WAL_VALVE_MB si el límite es demasiado ajustado para el proyecto.

El modo directo (CODEGRAPH_NO_DAEMON=1 o proxy→retroceso en proceso) ahora requiere un bloqueo exclusivo de .codegraph/writer.pid; un segundo escritor sale inmediatamente con instrucciones para detener el otro servidor o desarmar CODEGRAPH_NO_DAEMON para que clients comparta el demonio. El demonio compartido ya multiplexa N clients en un observador; esto cierra la brecha directa dual del mismo sistema operativo sobre la que los documentos advirtieron para Windows/WSL pero que no protegieron.

Una importación relativa que apunta encima del directorio del proyecto (../../something) hizo que CodeGraph sondeara esa ubicación en el disco mientras la resolvía. Nunca se leyó nada fuera del proyecto, y ningún archivo de ese tipo se agregó al índice ni se vinculó a él, pero la verificación en sí no debería haber ocurrido; tal importación ahora simplemente no se resuelve en nada. Los enlaces simbólicos dentro de su proyecto que apuntan al código guardado en otro lugar no se ven afectados y siguen indexándose como antes. Gracias @ErQrYfkrju. (#1631)

  • codegraph install --refresh ya no deja un archivo .backup junto a la configuración de un agente para el que no está configurado. Verificar si un agente ya tiene CodeGraph significaba leer su configuración, y una configuración que no era válida JSON (un mcp_config.json vacío al lado de una instalación de Antigravity, por ejemplo) se copiaba a un lado con una advertencia de que CodeGraph estaba a punto de sobrescribirla, aunque el agente luego se omitió sin tocar. La verificación ahora es silenciosa; Aún se realiza una copia de seguridad de una configuración que no se puede leer, pero solo cuando CodeGraph realmente la está reemplazando. Gracias @ Gotman08.   • codegraph_explore ahora marca un import()/require() dinámico creado a partir de un literal de plantilla con una sustitución o una concatenación de cadenas, mientras que un \${…} con escape permanece como una cadena simple. Gracias @inth3shadows. (#1967)

  • Cuando codegraph_explore no encuentra nada, ahora dice que la coincidencia es léxica, enumera las palabras de consulta que el índice no contiene y sugiere nombres de símbolos reales para volver a intentarlo. Gracias @iacore. (#1904)

codegraph v1.6.1

[1.6.1] - 2026-09-29

Highlights

  • Sharper answers from codegraph_explore. It returns the functions and methods you name — even from a very large file, or one full of same-named overrides — honours line numbers in a query, and says when it shortened an answer instead of calling it complete.
  • Your app's navigation and requests are in the graph. Expo Router, Next.js, React Router, TanStack Router, Vue Router / Nuxt and SvelteKit pages and the links between them are routes and navigates edges, and a page's fetch reaches the route that serves it, so "where does this go" and "what calls this endpoint" are one question to codegraph_explore.
  • Explore says when a call happens. Each hop in codegraph_explore's Flow section carries the condition it runs under, for JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go and C.
  • Fewer wrong links. Many fixes to how calls, imports and inheritance resolve in TypeScript, JavaScript, Python, Java, Kotlin, Go, Rust, Scala, PHP and C/C++, so a call stops landing on an unrelated symbol that happens to share its name.
  • Live sync you can rely on. The MCP server follows a rebuilt index after codegraph index, a sync interrupted halfway recovers what a clean index would have, symlinked folders stay in sync, and a WSL project on a Windows drive gets an index of its own.
  • Lighter on big repositories. Repeated explores from the MCP server no longer rescan the whole graph, and oversize files and .ts video fixtures are no longer read or parsed while indexing.
  • Upgrading: re-index your projects after this release — several fixes and the new navigation links are written while indexing.

New Features

  • Codex and Astra read project guidance from AGENTS.md. The canonical agent guide now lives in AGENTS.md (with a nested docs/AGENTS.md for long validation notes); CLAUDE.md is a thin @AGENTS.md wrapper for Claude Code. Codex/Astra no longer miss the old CLAUDE-only instructions.

  • Next.js pages and their navigation are in the graph. App Router pages (app/(group)/blog/[slug]/page.tsx → /blog/:slug) and Pages Router pages are routes bound to the component they export, and <Link href>, an internal <a href>, router.push / router.replace (next/navigation and next/router), redirect() / permanentRedirect() and the middleware's NextResponse.redirect(…) are navigates edges between them. app/api/**/route.ts exports (GET, POST, …) are endpoints bound to their functions, and pages/api/* handlers are ANY /api/…. Re-index after upgrading.

  • TanStack Router routes and navigation are in the graph. Routes are read both ways a TanStack app declares them — file-based, where createFileRoute('/posts/$postId') carries the whole path, and code-based, where each createRoute({ path, getParentRoute }) is composed through its parent — and navigate({ to }), a thrown redirect({ to }) and <Link to> / <Navigate to> are navigates edges to the route they name. A pathless _auth layout, a (group) folder and __root are not pages, and a computed destination is left out rather than guessed. Re-index after upgrading.

  • Vue Router, Nuxt and SvelteKit navigation is in the graph. Vue: routes are read from createRouter({ routes: [...] }), including a lazy component: () => import('@/views/Login'), and router.push / router.replace / $router.push, Nuxt's navigateTo and <router-link> / <RouterLink> / <NuxtLink> are navigates edges, resolved by route name as well as by path. SvelteKit: goto('/login'), redirect(303, …) from a load or a form action, and a plain <a href> are navigates edges, and a page is joined to the page file that serves it and the +page.server.js beside it. A computed destination or a path nothing declares is left out rather than guessed. Re-index after upgrading.

  • React Router navigation is in the graph. history.push / history.replace, navigate(…) from useNavigate, redirect() in a loader or an action, and <Link to> / <NavLink to> / <Navigate to> / react-router-bootstrap's <LinkContainer to> are now navigates edges to the route they open, and a route with an optional parameter (/cart/:id?) is reached by both /cart and /cart/5. A computed destination or a path no route serves is left out rather than guessed, and an ordinary paths.push('/x') on an array is never mistaken for navigation. Re-index after upgrading.

  • codegraph_explore follows a web app across its tiers. A page's fetch('/api/users', { method: 'POST' }) — or an axios / ky / got / $fetch call, including one through an axios.create({ baseURL }) instance — now reaches the route that serves it in the same index. A job put on a BullMQ / Bull queue reaches the @Process method, Worker or queue.process handler that consumes it, a NestJS EventEmitter2 event its @OnEvent listeners, a socket message the gateway's @SubscribeMessage handler and back, and a Next.js server action called from a client file is a crossing to the server. Each is a synthesized hop that the Flow section names, with where it was wired up. Only a literal path or event name pairs. Re-index to pick the new edges up.

  • codegraph_explore says when each call happens. Every hop in the Flow section carries the condition its call site sits under — ↓ calls (when isCollected) — read from the if / else, switch / when / match, ternary, try and && / and branches around the call and the early returns before it (if (busy) return reads as !busy, Go's if err != nil { return } as err == nil). It works for JavaScript, TypeScript, Swift, Python, Java, Kotlin, C#, Go and C, is read from the source as it stands, and a language without rules says nothing rather than guess.

  • React Native apps: Swift native modules and their events connect end to end. A JS call like captureView.finalizeCaptureSession() — where captureView is bound to NativeModules.CaptureView and the module is a Swift class exposed through an RCT_EXTERN_MODULE shim — now resolves to the Swift method itself instead of stopping at the constant, so codegraph_explore follows the code into native. Native → JS events now also land on listeners written inline (addListener('onZipComplete', (data) => { … })), attributed to the component that registers them. Re-index after upgrading to pick the new edges up.

  • Expo Router apps: screens and navigation are in the graph. Every screen file under app/ (or src/app/) is now a route node named by its path — /object-detail, /item/[id], with (group) folders stripped — linked to the component it renders. Calls like router.push('/object-detail?…'), router.navigate({ pathname: '/item/[id]', params }), template-literal hrefs, an href held in a local const, and router.push(await pickRoute()) where the helper returns screen paths (one edge per screen it can return) resolve to the screen they open as a new navigates edge that remembers the href, so "where does tapping this go" and "who opens this screen" are one hop in codegraph_explore and callers instead of a dead end at a string. Re-index after upgrading to pick the new edges up.

Links and navigation

  • A <Card/> is the Card that file imports, not the first one in the repo. When two components share a name — Section, Picker, FrameCard, one per feature folder — the render link out of a component picked whichever happened to be indexed first, ignoring what the file actually declares or imports, so a component gained a link to something it never renders and callers and impact dead-ended at the one it does. It now follows the file's own declaration or import, and a JavaScript tag prefers a JavaScript component over a same-named class in a mobile app's native half. Re-index after upgrading.

  • A navigation that goes to one of several places now links to all of them. A destination written as a choice — a paginator's !isAdmin ? keyword ? \/search/${keyword}/page/${x}` : `/page/${x}` : `/admin/productlist/${x}`, redirect(307, user ? `/profile/@${user.username}` : '/login')in a loader,router.push(cond ? '/a' : '/b')— used to produce no edge at all, because one edge carried one destination and picking an arm would have been a guess. Every arm is now its ownnavigates` edge to the route it names; arms that name the same route still make one.

  • A conditional inside a conditional no longer reads the wrong arm. A paginator written !isAdmin ? keyword ? '/search/…' : '/page/…' : '/admin/…' was split at the first : rather than the matching one, so an admin's page links pointed at the storefront's pagination. The arms are paired properly now, and a three-way choice — which is more destinations than one link can name — is left alone.

  • In a repository with several apps, a link no longer points into a different one. Every app has a / and most have a /login, and the route table was built for the whole repository at once, so whichever app was indexed first claimed each address — a <Link to="/posts"> in one app resolved to another app's /posts. Measured on a monorepo of 477 apps: 82% of navigations pointed at a route belonging to a different app, and all of them now point within their own.

  • A client call with a type argument — useSWR<Team>('/api/team', fetcher), ky.get<User>('/api/users/1') — now reaches its route like the untyped form.

Routes and framework detection

  • A SvelteKit layout is no longer a second route at a page's address. +layout.svelte and +error.svelte sit at the same path as the +page.svelte beside them and were each indexed as a route, so one address appeared in the index two and three times over. Only a page is a route now.

  • A framework whose package lives in a subfolder is detected again. In a project that keeps its dependencies one level down — a frontend/ and a backend/, or an apps/web/ — the framework check ran once before any file had been indexed, found no folders to look in, and remembered that empty answer for the rest of the run. Every React, React Router and Next.js behaviour that depends on knowing the framework is there silently did nothing for those projects.

  • Express routes behind app.use('/api', router) are named by the path a request takes. A router mounted at a prefix — through as many router.use('/users', usersRouter) levels as the app nests, by import or require — now names its routes POST /api/users instead of POST /, and the chained form router.route('/:id').get(getProduct).put(protect, updateProduct) (split across lines or not) registers one route per method. A client's request is paired with its route by that real path too.

  • An Express handler written through a wrapper is the endpoint's handler. const authUser = asyncHandler(async (req, res) => { … }) — the express-async-handler idiom — is now the handler its route is bound to.

  • A framework declared in a workspace's package.json is detected. React, Next.js, Expo Router, Express and NestJS are found when their dependency lives in frontend/, backend/, apps/web/ or packages/api/ rather than at the repository root, so a monorepo's pages and endpoints exist in the index.

  • FastAPI routes are named by the path a request takes. APIRouter(prefix="/items") and a literal app.include_router(router, prefix="/api/v1") — nested through an aggregate router, through a module import or an alias — now compose onto the route names (GET /api/v1/items/{id} instead of GET /{id}); a prefix that is a setting rather than a string leaves that mount alone rather than guessing.

  • ASP.NET Minimal API endpoint groups are routes. The handler-first form — groupBuilder.MapPost(CreateTodoItem), MapPut(UpdateTodoItem, "{id}") inside an IEndpointGroup / EndpointGroupBase class (the Clean Architecture template and its descendants) — now registers POST /api/TodoItems and PUT /api/TodoItems/{id}, with the /api/ head read from the app's own MapGroup($"/api/{groupName}") and a class's RoutePrefix honoured, each bound to its handler.

  • A FastAPI service that lives in one directory of a monorepo is detected. backend/pyproject.toml and backend/app/main.py count, not only files at the repository root, so the official full-stack template's routes are indexed.

  • React Router routes are now read from each <Route> tag's own attributes and each route object's own fields, so an element no longer bleeds into a sibling or parent route. Thanks @inth3shadows. (#1348)

  • MyBatis mappers with whitespace inside a closing tag, and <include refid> references to another namespace, are now extracted correctly. Thanks @ESPINS for the report and @fengshao1227. (#1209)

  • render, include, section and assign written inside a {% liquid %} block are now extracted with their real line numbers, and commented or raw content is ignored. Thanks @Puma7. (#1906)

  • Rust functions annotated #[tauri::command] are no longer reported as dead code. Thanks @vdavid. (#1543)

  • TypeScript/JavaScript value aliases — export const alias = fn, export { fn as alias }, object-literal api = { run: fn }, and same-file const local = fn — now forward calls edges to the aliased function, so callers and impact on the implementation include consumers that call through the alias instead of stopping at the binding. Genuine wrappers (() => fn()) are unchanged. Re-index after upgrading. Thanks @valkyriweb. (#1482, #1485)

A TypeScript class implementing a service that is declared as both a value and an interface under one name, the pattern VS Code uses for every service, now links to the interface instead of the value. Thanks @ctype-lab. (#1536)

In a polyglot repository where Spring is detected (a sibling Java module is enough), a Scala or Kotlin extends/implements reference could be resolved by Spring's directory-convention heuristics to an unrelated same-named class — for example a test fixture — corrupting the inheritance graph that codegraph_impact and codegraph_explore walk. Inheritance now always resolves through imports and name matching, and the Spring DI patterns only apply to Java/Kotlin references. Re-index after upgrading. (#1825)

  • PHP static calls through imported class aliases now reach the correct class when services and repositories share method names, so callers and impact analysis show the right dependencies after re-indexing. (#1545)

  • TypeScript/JavaScript: a call through a field of the enclosing class — this.mailer.send() — now resolves on the field's declared type, so a delegating wrapper that shares the method's name no longer records itself as its own callee and callers, impact and trace stop lying on that shape. A field whose type is external or a builtin stays unresolved rather than guessed. Re-index after upgrading. (#1496)

  • TypeScript and JavaScript collection calls through local variables and their nested properties no longer link to unrelated project methods; re-index after upgrading. (#1566)

  • Objective-C headers now index in a project that has no .m file. A .h file is read as C from its name alone, and only later — once its contents are read — recognized as Objective-C; the grammar for that was never loaded up front, so the file failed with a parser error and nothing in it reached the index. Adding any .m file used to make the same header work, which is what made this look arbitrary. Thanks @Juddd. (#1628)

  • TypeScript interface methods and properties are now indexed, so node, callers and impact can find platform .d.ts APIs while declaration-only files keep their lower ranking on flow queries, and an interface's members don't pull unrelated files into answers to plain-English questions; re-index TypeScript projects after upgrading. (#1638)

  • Lua and Luau function expressions assigned to locals, table members, or keyed table fields are now indexed as callable nodes. Calls from local f = function() ... end, M.f = function() ... end, and callback tables such as M.handlers = { onClick = function() ... end } are attributed to the named function or method instead of collapsing onto the file node, so callers and impact no longer omit these handlers. Re-index after upgrading. (#1616, #1650)

  • Functions bound with const inside another function are symbols now. const handleClear = () => {…} inside a React component — every handler that skips useCallback — was invisible to callers, callees and impact, answering "Symbol not found" exactly the way a function with no callers would. It is indexed like its module-level twin, contained by the enclosing function, with its own calls. Re-index after upgrading. (#1669)

  • codegraph callers, callees, and query now clearly report when their result limit hides additional matches, including exact totals in callers/callees JSON output; the codegraph_callers and codegraph_callees MCP answers carry the same "showing N of M" note. (#1639, #1674)

  • CommonJS controllers written as exports.getItems = async (req, res) => {…} or module.exports.x = function () {…} are now indexed as exported functions, so node, callers and impact find every Express handler in that style and the calls inside them belong to the handler instead of the file. Re-index JavaScript projects after upgrading. (#1675)

  • Python parameters annotated with a quoted forward reference — def f(o: "Alpha"), or anything under from __future__ import annotations — now resolve the methods called on them, the same as the unquoted annotation. Re-index Python projects after upgrading. (#1684)

  • A C macro call written with designated initializers no longer swallows every function after it. Betaflight resets each config struct with RESET_CONFIG(type, dst, .field = value, …), a shape the C grammar cannot parse; past a hundred or so fields its error recovery ran the enclosing function to the end of the file, the next function vanished from the index and every later one was filed under the first, where name matching then treated it as an unreachable closure. The argument list of such a call is now blanked before parsing, offsets kept, so the file's functions come out with their real extents. On that tree 45 functions in pid.c alone moved back to top level and their 117 callers resolve at exact-match confidence. Re-index after upgrading. (#1729)

The receiver is kept so the inner call still resolves; the outer method stays unresolved rather than guessed. Re-index after upgrading. (#1683, #1681)

  • A Python call through an imported project module whose name collides with a builtin collection method — ledger.append(row) after from . import ledger — is no longer dropped as list.append. The builtin-method filter now lets the receiver through when it is an imported module that resolves to a file in the project, so resolveViaImport can attach the real edge; a stdlib/PyPI receiver (os.remove) still produces none. Re-index after upgrading. (#1681, via #1704)

  • Python method calls on module-scope builtin collections no longer create false calls or file dependencies to unrelated project methods with the same name; re-index after upgrading. (#1652)

  • A definition its language makes file-local no longer captures calls from other files. A C static in another source file (.c/.cc/… — not a header's static inline, which is textually included), a Kotlin/Java/C#/Swift/Scala/Dart/PHP private member, a Go unexported name in another package, and a Rust non-pub item outside its module subtree cannot be what a name in another file means, but name matching accepted them whenever the names agreed: an Android editor.apply() onto an unrelated class's private fun apply, a JavaScript fail(...) onto a Go func fail, a Rust .count() onto a private fn count in another crate, and C USB helpers onto a static in a .c they never link. Such a target is now declined after the whole name-matching pipeline settles — the reference stays unresolved rather than falling through to a fuzzy namesake. Same-file definitions, a child Rust module reaching its ancestors' private items, and Rust impl Trait for Type methods stay resolvable. Re-index after upgrading. (#1730, #1731)

  • A binding in a module that exports nothing is no longer a cross-file target. On vite, every import { defineConfig } from 'vite' across the playground resolved onto a const vite = await createServer(…) sitting at module scope in playground/ssr-html/test-stacktrace.js — a file with an import and no export, so that binding is reachable from nowhere but itself. Name matching commits as soon as one candidate survives, and nothing asked whether an import could reach the survivor; that one binding took 157 edges. A JS/TS file holding an import and no export of any kind now offers its locals to no other file. Classic scripts, CommonJS (including exports["x"] = …), a later export { … }, and names contributed through declare global are all unaffected. Across vite this removed 320 wrong edges and added 18, each addition a reference that was previously ambiguous rather than newly invented. Re-index after upgrading. (#1719)

  • A bare call inside a JavaScript or TypeScript method no longer resolves to the method itself. When a method and a module-scope function share a name, serialize(this.raw) written inside Record.serialize means the function, but the nearest same-named definition won the tie and the graph recorded the method calling itself. A call written without a receiver can never reach a method in JS/TS, so methods are no longer candidates for it; this.serialize() and other.serialize() resolve as before. (#1714)

  • Fuzzy matching no longer lands on a closure it cannot reach. A function nested inside another function is only callable from inside its container, and exact-name matching already declined such candidates; the fuzzy fallback did not, so a builtin method call (res.text(), items.push()) whose only same-named project symbol was some file's closure resolved onto that closure. The fallback now checks that the one candidate it would commit to is reachable, and declines otherwise — it does not filter the candidate list first, which would turn a crowd of same-named definitions into a single "unique" survivor and hand it every call of that name. On vite that removes the 12 edges onto nested functions and adds none. Re-index after upgrading. Thanks @bompus. (#1708, #1709)

Under moduleResolution: node16 | nodenext | bundler TypeScript requires import { x } from './util.js' for util.ts, and no file of that name exists, so the import resolver returned nothing and every name imported that way fell through to bare-name matching: a method wrapping the same-named helper it imports (renderDockStyles() { return renderDockStyles(); }) resolved to itself, and cross-module edges in such projects were name guesses. .js / .jsx / .mjs / .cjs specifiers now retry with the source extensions TypeScript compiles from when the emitted file is absent; a real .js beside the .ts still wins. On a 582-file repo whose .ts files import this way, import-backed calls/imports edges went from 4,002 to 7,312 and the eight wrapper-method self-edges disappeared. Re-index after upgrading. Thanks @bompus. (#1705, #1706)

A Kotlin or Java project whose package path runs through com/google/samples/… (Now in Android, for one) had nearly every file counted as a test fixture. Only the project layout above a src/ folder decides now; the package path below it never does.

The hook capped its injection at 16,000 characters, but Claude Code shows hook output inline only up to 10,000 and otherwise persists it to a file with a 2 KB preview, so on any repo where explore filled the cap the model saw a file path and the first 2 KB.
