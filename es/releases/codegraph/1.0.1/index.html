códice v1.0.1

[1.0.1] - 2026-06-13

Nuevas características

  • Nuevo comando codegraph daemon (alias daemons): un administrador interactivo para los demonios en segundo plano. Muestra lo que se está ejecutando (primero el demonio de su proyecto actual, preseleccionado), y presiona la tecla de flecha hacia uno y presiona Enter para detenerlo, o selecciona "Detener todo". Anteriormente, la única forma de cerrar un demonio era buscar su pid y kill manualmente. (#845)
  • Ahora es fácil comprobar la versión instalada, independientemente de cómo la adivines: codegraph version, codegraph -v y codegraph -version la imprimen, junto con el codegraph --version existente. (#864)
  • El servidor CodeGraph MCP ahora se repara automáticamente si su hilo principal alguna vez se bloquea. Un perro guardián ligero se da cuenta cuando el proceso ha dejado de responder y lo detiene para que se inicie uno nuevo en su próxima solicitud; ya no puede permanecer bloqueado al 100% de la CPU sin forma de recuperarse. Ajuste la ventana de detección con CODEGRAPH_WATCHDOG_TIMEOUT_MS o apáguela por completo con CODEGRAPH_NO_WATCHDOG=1. (#850)

Correcciones

  • Los árboles de trabajo de Git anidados dentro de tu proyecto, como el .claude/worktrees/ que crea Claude Code, ya no se indexan como copias duplicadas de todo tu código base. CodeGraph indexa deliberadamente repositorios incrustados genuinos (un segundo proyecto real verificado dentro del suyo), pero un árbol de trabajo es solo otra vista funcional de un repositorio que ya indexó, por lo que cada uno multiplicaba cada símbolo: un informe pasó de ~1,850 archivos a más de 24,000, con la búsqueda y explore inundados de duplicados obsoletos. CodeGraph ahora reconoce árboles de trabajo y los omite, mientras sigue indexando repositorios y submódulos reales incrustados. Gracias @tphakala. (#848)
  • Ejecutar codegraph serve --mcp a mano ya no se queda en silencio. Ese comando es el servidor MCP que su agente de IA inicia por sí mismo, no un paso que usted ejecuta directamente, y en una terminal solía permanecer allí esperando una entrada que nunca llega, luciendo rota. Ahora reconoce cuando una persona lo ejecuta y explica qué hacer en su lugar (codegraph status, codegraph daemon), y se eliminó de la lista de comandos, por lo que deja de parecer algo que necesita iniciar.
  • Las llamadas a métodos estáticos entre archivos como ClassName.staticMethod() ahora se resuelven correctamente. CodeGraph estaba vinculando la llamada a la clase en lugar del método (y registrándola como una construcción), por lo que callers y impact para un método estático volvieron vacíos: un verdadero punto ciego en las bases de código TypeScript y JavaScript que se basan en clases de utilidad estáticas (Python y otros lenguajes con la misma forma de llamada también se benefician). La llamada ahora enlaza con el método en sí. Gracias @contextFlow-lab. (#825)
  • codegraph affected ahora acepta rutas de archivo absolutas y con prefijo ./, no solo rutas relativas al proyecto. Pasar ./src/x.ts o una ruta absoluta (común cuando la lista de archivos proviene de otra herramienta) se utiliza para no hacer coincidir nada de forma silenciosa e informar que no hay pruebas afectadas. Gracias @contextFlow-lab. (#825)
  • El servidor CodeGraph MCP ya no corre el riesgo de quedarse atascado al 100% de la CPU después de un error interno inesperado. Anteriormente se registraba un error de este tipo, pero el proceso se dejaba ejecutándose en un estado roto, donde podía hacer girar un núcleo de CPU indefinidamente y tenía que cerrarse manualmente. El servidor ahora registra el error y sale limpiamente, por lo que se inicia uno nuevo en la siguiente solicitud. Gracias @songhlc. (#850)
  • CodeGraph ya no indexa todo su directorio personal por accidente. Ejecutar el instalador, o codegraph init / codegraph index, desde su carpeta de inicio o desde la raíz del sistema de archivos indexaría todo lo que hay debajo (cachés, Library, cualquier otro proyecto), produciendo un índice de varios gigabytes y una constante rotación de archivos. CodeGraph ahora rechaza estas raíces y en su lugar le señala un proyecto específico; pase --force si realmente lo desea. (Combinado con la corrección del descriptor de archivos de macOS que ya está en 1.0.0, esto cierra el informe de un observador descontrolado que agota el límite de archivos del sistema). Gracias @ligson. (#845)

codegraph v1.0.1

[1.0.1] - 2026-06-13

New Features

  • New codegraph daemon command (alias daemons) — an interactive manager for the background daemons. It shows what's running (your current project's daemon first, pre-selected), and you arrow-key to one and press enter to stop it, or pick "Stop all". Previously the only way to shut a daemon down was to hunt for its pid and kill it by hand. (#845)
  • Checking your installed version is now easy to reach however you guess at it: codegraph version, codegraph -v, and codegraph -version all print it, alongside the existing codegraph --version. (#864)
  • The CodeGraph MCP server now self-heals if its main thread ever locks up. A lightweight watchdog notices when the process has stopped responding and stops it so a fresh one starts on your next request — it can no longer sit pinned at 100% CPU with no way to recover. Tune the detection window with CODEGRAPH_WATCHDOG_TIMEOUT_MS, or turn it off entirely with CODEGRAPH_NO_WATCHDOG=1. (#850)

Fixes

  • Git worktrees nested inside your project — like the .claude/worktrees/ that Claude Code creates — are no longer indexed as duplicate copies of your whole codebase. CodeGraph deliberately indexes genuine embedded repos (a real second project checked out inside yours), but a worktree is just another working view of a repo it already indexed, so each one was multiplying every symbol — one report went from ~1,850 files to over 24,000, with search and explore flooded by stale duplicates. CodeGraph now recognizes worktrees and skips them, while still indexing real embedded repos and submodules. Thanks @tphakala. (#848)
  • Running codegraph serve --mcp by hand no longer just hangs in silence. That command is the MCP server your AI agent starts for itself — not a step you run directly — and in a terminal it used to sit there waiting for input that never comes, looking broken. It now recognizes when a person runs it and explains what to do instead (codegraph status, codegraph daemon), and it's been dropped from the command listing so it stops looking like something you need to launch.
  • Cross-file static method calls like ClassName.staticMethod() now resolve correctly. CodeGraph was linking the call to the class instead of the method (and recording it as a construction), so callers and impact for a static method came back empty — a real blind spot in TypeScript and JavaScript codebases that lean on static utility classes (Python and other languages with the same call shape benefit too). The call now links to the method itself. Thanks @contextFlow-lab. (#825)
  • codegraph affected now accepts ./-prefixed and absolute file paths, not just bare project-relative ones. Passing ./src/x.ts or an absolute path — common when the file list comes from another tool — used to silently match nothing and report no affected tests. Thanks @contextFlow-lab. (#825)
  • The CodeGraph MCP server no longer risks getting stuck at 100% CPU after an unexpected internal error. Previously such an error was logged but the process was left running in a broken state, where it could spin a CPU core indefinitely and had to be killed by hand. The server now logs the error and exits cleanly, so a fresh one starts on the next request. Thanks @songhlc. (#850)
  • CodeGraph no longer indexes your entire home directory by accident. Running the installer — or codegraph init / codegraph index — from your home folder or a filesystem root would index everything underneath it (caches, Library, every other project), producing a multi-gigabyte index and constant file-watching churn. CodeGraph now refuses these roots and points you at a specific project instead; pass --force if you genuinely mean to. (Combined with the macOS file-descriptor fix already in 1.0.0, this closes the report of a runaway watcher exhausting the system file limit.) Thanks @ligson. (#845)
