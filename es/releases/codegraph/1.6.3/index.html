códice v1.6.3

[1.6.3] - 2026-11-17

Destacados

  • Nueve agentes y editores más. codegraph install ahora configura IBM Bob, Factory Droid, Windsurf, Qwen Code, DeepSeek Harness, Grok Build, Kimi Code, Qoder CLI y Pi.
  • Correcciones de seguridad. Una carpeta confidencial como ~/.ssh ya no se puede abrir como proyecto a través de un enlace, un cruce u otra ortografía de su ruta, y el Node.js incluido se mueve a 24.22.1, que corrige CVE-2026-111497.
  • Enlaces más precisos en todos los idiomas. Cientos de correcciones ayudan a que las llamadas, las importaciones y los tipos lleguen al código que quieren decir, sobre todo en JavaScript y TypeScript, Go, C y C++, Rust, Python, C#, Java y Dart. Tauri, CodeIgniter 3, servicios y complementos de Drupal, middleware Next.js y controladores MediatR ahora también están cubiertos.
  • Mejores respuestas para su agente. codegraph_explore ya no se detiene en un proyecto grande, responde a un registro o archivo pegado en segundos, encuentra nombres de códigos en chino, japonés o coreano y su flujo llega a todos los símbolos de los nombres de su consulta.
  • Nuevos comandos. codegraph cycles encuentra archivos que se importan entre sí en un círculo, codegraph implementations enumera lo que implementa un tipo, codegraph files --format package divide un monorepo por paquete y codegraph init --local-only mantiene a .codegraph/ fuera de git.
  • Un servidor en segundo plano más estable. Una nueva sesión ya no espera minutos cuando el servidor en segundo plano está bloqueado, la actualización durante una sesión lo cambia a la nueva versión, y codegraph sync y el observador de archivos mantienen los enlaces correctos a medida que se agregan, eliminan y restauran archivos.
  • Más rápido y ligero. Los comandos que solo leen el índice se inician más rápido y la indexación requiere menos CPU y memoria, sobre todo en proyectos pequeños y en C y C++.
  • Actualización: vuelva a indexar sus proyectos después de esta versión con codegraph index. La mayoría de estas correcciones se escriben durante la indexación, y codegraph status y su agente le informan cuándo se creó un índice con una versión anterior.

Seguridad

  • Una carpeta confidencial como ~/.ssh, /etc o C:\Windows ya no se puede utilizar como proyecto a través de un enlace o unión, un nombre talizado de manera diferente, una ruta \\?\ o una ruta a una carpeta faltante dentro de una. Antes, cualquiera de estos permitía que la consulta de un agente leyera los archivos que contenía. Gracias @mixxer. (#2929)
  • El servidor MCP ya no utiliza una carpeta confidencial como ~/.ssh o /etc como proyecto predeterminado de una sesión, ya sea que provenga del espacio de trabajo del agente, la carpeta en la que comenzó o --path. Antes, una sesión comenzaba en una que contenía un índice respondido a partir de los archivos internos. (#3012)
  • El tiempo de ejecución Node.js incluido pasa a 24.22.1, la versión de seguridad de octubre de Node, que corrige CVE-2026-111497, una escritura fuera de límites de alta gravedad en su decodificador Brotli, y cada versión ahora verifica el Nodo que incluye con las sumas de verificación que publica nodejs.org. También corrige un bloqueo de Windows cuando un comando como codegraph sync sale una vez finalizado su trabajo. Gracias @Ancienttwo y @IdealBoy709. (#2617, #2780)

Correcciones

ventanas

  • En Windows, eliminar la carpeta a la que apunta un enlace en su proyecto, como una unión a una biblioteca externa, ya no hace que el servidor de CodeGraph use un núcleo de CPU completo o deje de editar sus ediciones. Gracias @L0garithmic.
  • En Windows, un proyecto en la raíz de una unidad, como una unidad de red asignada como Z:\, una unidad subst o la raíz de un recurso compartido de red, ahora indexa en lugar de rechazar cada archivo como "Recorrido de ruta bloqueado". Gracias @Kamilslaoui93.
  • En Windows, una carpeta temporal en una unidad que no está allí, como un disco desconectado o una unidad RAM desmontada, ya no bloquea todos los comandos codegraph al inicio.
  • En Windows, ahora se reconoce un árbol de trabajo git dentro de su caja principal, como uno bajo .claude/worktrees/, sin importar cómo esté escrita su ruta, como por ejemplo con la letra de unidad minúscula VS Code y el paso del cursor. Gracias @nk33-dev.
  • El instalador de Windows, irm …/install.ps1 | iex, ya no se detiene con "(403) Prohibido" una vez que se agota el límite de solicitudes anónimas de GitHub, y ahora se instala una versión configurada sin su v, como CODEGRAPH_VERSION=1.6.2. Gracias @hiyochi.
  • En los archivos JavaScript y TypeScript con finales de línea de Windows (CRLF), un almacén exportado en una línea posterior, como export default useStore;, ahora tiene sus acciones indexadas, como ocurre con los finales de línea de Unix.
  • En Windows, una llamada Swift escrita después de try!, como try! Settings.Defaults.load(), ahora se vincula a lo que llama, como ya lo hacía en macOS y Linux.

  • El servidor en segundo plano compartido ya no se cierra con "El hilo principal no responde" mientras actualiza el índice de otro proyecto, como uno de los nombres de una sesión con projectPath. Gracias @mradwankhalil. (#2404)

  • codegraph sync ya no falla con "Error en la restricción FOREIGN KEY" en un proyecto que carga de forma diferida un paquete de espacio de trabajo, como () => import('@vben/layouts').then((m) => m.IFrameView). Gracias @bompus y @inth3shadows. (#2565)

  • Un archivo ya no se guarda sin símbolos cuando su analizador de idioma no se puede cargar, como sucedió después de que una actualización eliminó la instalación de un servidor en ejecución; Los archivos vaciados de esta manera se vuelven a indexar en la siguiente sincronización. Gracias @lipchey. (#2335)
  • codegraph sync y el observador de archivos ahora vinculan los archivos importando un archivo que se omitió, por su tamaño o por un error de análisis, una vez que una edición permite indexarlo, como lo hace un índice completo. Gracias @inth3shadows. (#3016)

  • Un programa que utiliza CodeGraph como biblioteca ya no falla cuando se lanza una devolución de llamada watch(), onSyncError o onDegraded; el error se registra y aún así se intenta una sincronización fallida. Gracias @johnhldiver-beep. (#2643)

  • Ejecutar codegraph query, explore, node, callers y otros comandos de lectura, o el enlace de contexto de Claude Code, mientras se reconstruye codegraph index ya no hace que la reconstrucción falle con "la base de datos está bloqueada". Gracias @sealad886. (#2913)

Highlights

  • Nine more agents and editors. codegraph install now sets up IBM Bob, Factory Droid, Windsurf, Qwen Code, DeepSeek Harness, Grok Build, Kimi Code, the Qoder CLI and Pi.
  • Security fixes. A sensitive folder such as ~/.ssh can no longer be opened as a project through a link, a junction or another spelling of its path, and the bundled Node.js moves to 24.22.1, which fixes CVE-2026-111497.
  • More accurate links in every language. Hundreds of fixes help calls, imports and types reach the code they mean, most of all in JavaScript and TypeScript, Go, C and C++, Rust, Python, C#, Java and Dart. Tauri, CodeIgniter 3, Drupal services and plugins, Next.js middleware and MediatR handlers are now covered too.
  • Better answers for your agent. codegraph_explore no longer stalls on a large project, answers a pasted log or file in seconds, finds code named in Chinese, Japanese or Korean, and its Flow reaches every symbol your query names.
  • New commands. codegraph cycles finds files that import each other in a circle, codegraph implementations lists what implements a type, codegraph files --format package splits a monorepo by package, and codegraph init --local-only keeps .codegraph/ out of git.
  • A steadier background server. A new session no longer waits minutes when the background server is stuck, upgrading during a session switches it to the new version, and codegraph sync and the file watcher keep links right as files are added, deleted and restored.
  • Faster and lighter. Commands that only read the index start faster, and indexing takes less CPU and memory, most of all on small projects and on C and C++.
