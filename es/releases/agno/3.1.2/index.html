año v3.1.2

#Changelog

Nuevas características:

  • Compactación de conversaciones: Agent(compaction=True) mantiene sesiones largas dentro de la ventana de contexto al plegar los giros más antiguos en un resumen. Los mensajes almacenados nunca se reescriben: un CompactionRecord en la nueva tabla agno_compactions genera una carga útil del modelo derivado, por lo que al eliminar el registro se restaura la conversación completa. Sintonice con Compaction(model=..., compact_at_tokens=..., uncompacted_runs=...), pliegue según demanda con agent.compact() / acompact() e inspeccione run.compaction. Con searchable=True, el agente obtiene una herramienta search_compacted_history, una expresión regular grep sobre la transcripción archivada. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/02_agents/03_context_management/compaction/compaction.py). (#9873)
  • Agente externo Codex: se agregó CodexAgent, un adaptador para OpenAI Codex integrado en openai-codex SDK, junto con los adaptadores Claude Agent SDK, LangGraph, DSPy y Antigravity. Codex ejecuta su propio bucle de agente; el adaptador traduce sus notificaciones en eventos de ejecución de Agno y llamada de herramientas, asigna cada sesión de Agno a un hilo del Codex (persistente cuando se configura un db) y expone las configuraciones de sandbox, approval_mode, reasoning_effort, output_schema y MCP. Funciona de forma independiente y a través de AgentOS. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/frameworks/codex/codex_basic.py). (#10901)
  • Transformación de consulta HyDE: se agregó QueryTransformer como un nuevo gancho de recuperación y HyDE como su primera implementación: Knowledge(vector_db=..., query_transformer=HyDE()) busca con una respuesta hipotética en lugar de la pregunta sin formato, mientras que los reclasificadores aún puntúan según la consulta original. HyDE usa su propio model, luego el modelo del agente o equipo que llama y luego el marco predeterminado. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/07_knowledge/02_building_blocks/12_hyde_query_transformer.py). (#10527)
  • Política de origen del navegador: se agregó AgentOS(cors=CORSConfig(origins=..., origin_regex=..., merge_base_app=...)) y se optó por PublicSurface(enforce_browser_origins=True). Las comprobaciones previas de CORS, la ejecución pública y la admisión de cancelación, los encabezados de error de autenticación, los WebSockets de flujo de trabajo y los alias de MCP ahora comparten una política de origen, y CORS es el middleware más externo, por lo que las respuestas de error llevan encabezados consistentes. cors_allowed_origins mantiene su comportamiento actual. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/05_agent_os/27_public_pages/browser_origins.py). (#10869)
  • Seguimientos configurables: followups: bool | FollowupConfig en Agente y Equipo. FollowupConfig establece un rango de conteo (num_followups o min_followups / max_followups), un modelo separado e instrucciones personalizadas que van únicamente a la llamada de seguimiento. El mensaje predeterminado ahora permanece dentro de los límites de la respuesta y ya no vuelve a ofrecer una solicitud con la respuesta declined. Las personas que llaman a num_followups siguen recibiendo exactamente N sugerencias. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/02_agents/14_advanced/followup_instructions.py). (#10087)
  • Heabsy: Se agregó Heabsy como proveedor de modelo compatible con OpenAI, también resoluble como "heabsy:<model>". Consulte libro de cocina. (#10828)
  • FlexAI: se agregó FlexAI como proveedor de modelos compatible con OpenAI para modelos de peso abierto, también resoluble como "flexai:<model>". Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/90_models/flexai/basic.py). (#10871)
  • SixtyDBTools: Nuevo conjunto de herramientas para el discurso alojado de 60 dB API: descubra voces en el espacio de trabajo y genere discurso como artefactos de audio WAV. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/91_tools/sixtydb_tools.py). (#10786)

Mejoras:

  • Registros de sincronización de páginas: la sincronización de páginas ahora registra las esperas de bloqueo, el descubrimiento, el progreso cada 25 páginas y los recuentos finales, por lo que las sincronizaciones prolongadas muestran el progreso sin una devolución de llamada personalizada. Se agregó un libro de recetas de AgentOS que sincroniza la documentación con las páginas de conocimiento respaldadas por PostgreSQL y las expone a través del sistema de archivos del agente. Consulte [libro de cocina] (https://github.com/agno-agi/agno/blob/main/cookbook/05_agent_os/27_filesystem/knowledge_fs.py). (#10868)
  • OpenAIResponses y OpenRouterResponses: reconoce GPT-6 (OpenAI) y GPT-5/6 (OpenRouter) como modelos de razonamiento, de modo que se apliquen el encadenamiento de estados de razonamiento y la reproducción de razonamiento cifrada y los seguimientos de llamadas de herramientas ya no fallen con errores de elementos de razonamiento faltantes. (#10830)
  • PerplexitySearch: las solicitudes ahora envían un encabezado X-Pplx-Integration: agno para que Perplexity pueda atribuir el tráfico de la integración. (#10827)

Corrección de errores:

  • Aprobaciones: cada llamada a la herramienta @approval en una ejecución ahora obtiene su propio registro de aprobación, para agentes y equipos. Anteriormente, una segunda pausa en la misma ejecución no creaba ningún registro y la siguiente continuación ejecutó la nueva llamada contra la aprobación resuelta para la primera. (#10812)
  • Caché de respuesta del modelo: las clases Pydantic output_schema están codificadas por su esquema JSON en lugar de su nombre de clase, por lo que dos esquemas con el mismo nombre pero diferentes campos ya no comparten una respuesta almacenada en caché. (#10621)
  • Métricas de uso: MessageMetrics.cache_write_tokens ahora se completa a partir del uso de respuestas y finalizaciones de chat de OpenAI (#10313) y de prompt_tokens_details de LiteLLM (#10476). Antes siempre era cero.
  • JsonDb: las tablas se serializan en un archivo provisional y se publican con os.replace, por lo que una escritura fallida deja legible la última tabla guardada correctamente en lugar de un archivo truncado. (#10794)
  • MongoDb y MongoVectorDb: session_name, search_content y los filtros de búsqueda de palabras clave tienen escape de expresiones regulares, por lo que un valor como (draft ya no devuelve HTTP 500 de GET /sessions y GET /memories, y v1.2 ya no coincide con v1x2. (#10709)
  • Esquemas de herramientas: las sugerencias de Annotated[T, ...] se desenvuelven en T antes de la generación del esquema JSON en lugar de pasar a un esquema de objeto vacío. (#10858)
  • SQLTools: las URL de conexión se crean con URL.create, por lo que una contraseña como p@ssword ya no se divide en la contraseña p y el host ssword@.... (#10800)
  • FileTools: replace_file_chunk rechaza rangos de líneas negativas, invertidas y fuera de límites con un error y deja el archivo intacto; un reemplazo válido conserva la nueva línea final. (#10798)
  • GoogleCalendarTools: find_available_slots compara el final del espacio completo con la hora de cierre en su fecha de inicio, por lo que ya no se ofrece un espacio de 45 minutos a las 16:30 para un cierre a las 17:00 y los espacios no pueden cruzar la medianoche. (#10878)
  • BaiduSearchTools, Searxng y SpiderTools: un max_results=0 / fixed_max_results=0 explícito ahora significa que no hay resultados en lugar de volver al valor predeterminado. (#10877)
  • Lectores: TextReader, MarkdownReader (#10779) y JSONReader (#10634) aceptan transmisiones cuyo name es un número entero o None, como archivos temporales respaldados por descriptores, en lugar de no devolver nada o generar archivos.
  • Libros de cocina: se corrigió la ruta de importación de DynamoDb en el archivo README del almacenamiento de DynamoDB. (#10788)

agno v3.1.2

Highlights

  • Conversation compaction without losing history — Enable Agent(compaction=True) to fold older turns into a derived model payload while preserving stored messages; deleting the CompactionRecord from agno_compactions restores the full conversation. Thresholds and retained context are configurable, searchable=True adds regex-based archive search, and agent.compact() supports manual control (#9873).
  • Codex as an external agent — CodexAgent delegates execution to Codex’s own loop while translating notifications into Agno events, so tool execution and approvals remain governed by Codex. Each Agno session maps to a Codex thread, persisted when a database is configured; sandbox, approval, reasoning, schema, and MCP settings need explicit review before exposing it through AgentOS (#10901).
  • Unified browser-origin enforcement — AgentOS now shares one origin policy across CORS, run and cancel admission, authentication error headers, workflow WebSockets, and MCP aliases. Adopters should test browser clients and MCP aliases against enforce_browser_origins=True; the existing cors_allowed_origins behavior remains unchanged (#10869).
  • Retrieval and follow-up controls — Knowledge(query_transformer=HyDE()) searches using a generated hypothetical answer while rerankers still evaluate the original query, at the cost of an extra model call. followups: FollowupConfig supports bounded counts, separate models, and call-specific instructions; legacy num_followups=N still returns exactly N suggestions (#10527, #10087).
  • New model and tool integrations — Heabsy and FlexAI can be selected directly or through "heabsy:<model>" / "flexai:<model>", while SixtyDBTools adds hosted voice discovery and WAV generation (#10828, #10871, #10786).
  • Correctness and observability fixes worth adopting — Repeated @approval pauses now receive separate records (#10812), model caching includes the output schema to prevent cross-schema collisions (#10621), cache-write usage metrics are populated for OpenAI and LiteLLM (#10313, #10476), and JsonDb writes publish atomically to protect saved tables (#10709).
  • No breaking changes are listed.

Changelog

New Features:

  • Conversation Compaction: Agent(compaction=True) keeps long sessions inside the context window by folding older turns into a summary. Stored messages are never rewritten: a CompactionRecord in the new agno_compactions table drives a derived model payload, so removing the record restores the full conversation. Tune with Compaction(model=..., compact_at_tokens=..., uncompacted_runs=...), fold on demand with agent.compact() / acompact(), and inspect run.compaction. With searchable=True the agent gets a search_compacted_history tool, a regex grep over the archived transcript. See cookbook. (#9873)
  • Codex External Agent: Added CodexAgent, an adapter for OpenAI Codex built on the openai-codex SDK, alongside the Claude Agent SDK, LangGraph, DSPy and Antigravity adapters. Codex runs its own agent loop; the adapter translates its notifications into Agno run and tool-call events, maps each Agno session to one Codex thread (persisted when a db is set), and exposes sandbox, approval_mode, reasoning_effort, output_schema and MCP config. Works standalone and through AgentOS. See cookbook. (#10901)
  • HyDE Query Transform: Added QueryTransformer as a new retrieval hook and HyDE as its first implementation: Knowledge(vector_db=..., query_transformer=HyDE()) searches with a hypothetical answer instead of the raw question, while rerankers still score against the original query. HyDE uses its own model, then the calling agent or team's model, then the framework default. See cookbook. (#10527)
  • Browser Origin Policy: Added AgentOS(cors=CORSConfig(origins=..., origin_regex=..., merge_base_app=...)) and opt-in PublicSurface(enforce_browser_origins=True). One origin policy is now shared by CORS preflights, public run and cancel admission, auth error headers, workflow WebSockets and MCP aliases, and CORS is the outermost middleware so error responses carry consistent headers. cors_allowed_origins keeps its existing behaviour. See cookbook. (#10869)
  • Configurable Follow-ups: followups: bool | FollowupConfig on Agent and Team. FollowupConfig sets a count range (num_followups or min_followups / max_followups), a separate model and custom instructions that go only to the follow-up call. The default prompt now stays within the answer's boundaries and no longer re-offers a request the answer declined. Existing num_followups callers keep getting exactly N suggestions. See cookbook. (#10087)
  • Heabsy: Added Heabsy as an OpenAI-compatible model provider, also resolvable as "heabsy:<model>". See cookbook. (#10828)
  • FlexAI: Added FlexAI as an OpenAI-compatible model provider for open-weight models, also resolvable as "flexai:<model>". See cookbook. (#10871)
  • SixtyDBTools: New toolkit for the 60db hosted speech API: discover workspace voices and generate speech as WAV audio artifacts. See cookbook. (#10786)

Improvements:

  • Page Sync Logs: Page synchronization now logs lock waits, discovery, progress every 25 pages and final counts, so long syncs show progress without a custom callback. Added an AgentOS cookbook that syncs documentation into PostgreSQL-backed knowledge pages and exposes them through the agent's filesystem. See cookbook. (#10868)
  • OpenAIResponses & OpenRouterResponses: Recognise GPT-6 (OpenAI) and GPT-5/6 (OpenRouter) as reasoning models, so reasoning-state chaining and encrypted reasoning replay apply and tool-call follow-ups no longer fail with missing reasoning-item errors. (#10830)
  • PerplexitySearch: Requests now send an X-Pplx-Integration: agno header so Perplexity can attribute traffic from the integration. (#10827)

Bug Fixes:

  • Approvals: Each @approval tool call in a run now gets its own approval record, for agents and teams. Previously a second pause in the same run created no record and the next continue ran the new call against the approval resolved for the first one. (#10812)
  • Model Response Cache: Pydantic output_schema classes are keyed by their JSON schema instead of their class name, so two schemas with the same name but different fields no longer share a cached response. (#10621)
  • Usage Metrics: MessageMetrics.cache_write_tokens is now populated from OpenAI Chat Completions and Responses usage (#10313) and from LiteLLM's prompt_tokens_details (#10476). Previously it was always zero.
  • JsonDb: Tables are serialized to a staging file and published with os.replace, so a failed write leaves the last successfully saved table readable instead of a truncated file. (#10794)
  • MongoDb & MongoVectorDb: session_name, search_content and keyword-search filters are regex-escaped, so a value like (draft no longer returns HTTP 500 from GET /sessions and GET /memories, and v1.2 no longer matches v1x2. (#10709)
  • Tool Schemas: Annotated[T, ...] hints are unwrapped to T before JSON schema generation instead of falling through to an empty object schema. (#10858)
  • SQLTools: Connection URLs are built with URL.create, so a password like p@ssword is no longer split into password p and host ssword@.... (#10800)
  • FileTools: replace_file_chunk rejects negative, reversed and out-of-bounds line ranges with an error and leaves the file untouched; a valid replacement preserves the trailing newline. (#10798)
  • GoogleCalendarTools: find_available_slots compares the full slot end against closing time on its start date, so a 45 minute slot is no longer offered at 16:30 for a 17:00 close and slots cannot cross midnight. (#10878)
  • BaiduSearchTools, Searxng & SpiderTools: An explicit max_results=0 / fixed_max_results=0 now means no results instead of falling back to the default. (#10877)
  • Readers: TextReader, MarkdownReader (#10779) and JSONReader (#10634) accept streams whose name is an integer or None, such as descriptor-backed temporary files, instead of returning nothing or raising.
  • Cookbooks: Fixed the DynamoDb import path in the DynamoDB storage README. (#10788)
