año v3.1.12

#Changelog

Nuevas características:

  • Aprobaciones nativas para agentes de Harness: las solicitudes de permiso de Claude y Codex ahora llegan a la interfaz de usuario de aprobación de AgentOS. Cuando el agente tiene una base de datos, incluida una proporcionada por AgentOS, una solicitud nativa persiste en una ejecución EN PAUSA que aparece en las vistas de chat y Aprobaciones existentes, y Resolve más Continuar ejecución devuelve la decisión a la misma ejecución nativa sin reproducir el mensaje. La propia política del arnés decide cuándo preguntar: Claude mantiene su permission_mode y las devoluciones de llamadas de permisos explícitos, Codex admite approval_policy="on-request" | "untrusted" | "never" junto con sus modos existentes SDK auto_review y deny_all, por lo que no hay una configuración Agno separada para activar. Las decisiones se validan con respecto a la acción exacta solicitada, con sincronización y continuación asincrónica, cancelación, vencimiento y manejo de fallas de almacenamiento, y los agentes en espacio aislado mantienen esto en Docker y AgentCore: negociación de capacidad, un RPC de decisión, persistencia cercada, reconexión después de una pérdida de un trabajador API, presupuestos de ejecución y espera de aprobación separados, y no hay repetición después de la pérdida del proceso. Tenga en cuenta que un CodexAgent sin configuración de aprobación ahora se ejecuta bajo la política nativa on-request, por lo que una solicitud que anteriormente no llegó a ninguna parte detiene la ejecución; hitl_timeout (900 predeterminado) limita el tiempo de espera. Ver cookbook/frameworks/human_in_the_loop/.
  • Rutinas de empresa inicialmente deshabilitadas: Routine(enabled=False) permite que una plantilla envíe una rutina inactiva que un usuario activa más tarde desde la interfaz de usuario, con True sigue siendo el valor predeterminado. Las rutinas deshabilitadas se crean atómicamente, permanecen vinculadas a su Producto y visibles en los listados, el programador las omite y mantienen la elección guardada del usuario durante los reinicios. La bandera se respeta en el arranque Python y YAML, en los API de configuración y creación, en el Administrador de empresa de sincronización y asíncrono y en las herramientas de la empresa. Las solicitudes de creación duplicadas aún devuelven 409 y no pueden habilitar una rutina existente, y los puntos finales de pausa/reanudación existentes la habilitan sin volver a crearla. Ver cookbook/05_agent_os/30_company/11_disabled_routine.py.
  • Números de titulares en los gráficos: ChartTools.create_chart() toma un value preformateado opcional (un valor total o más reciente como "$22.3K" o "94%") emitido como "value" en el bloque del gráfico y representado por Agno OS junto al título del gráfico. La cadena de documentación le dice al modelo que lo omita cuando ningún número resuma el gráfico, por lo que los promedios y las tasas no se suman.

Mejoras:

  • Clasificación de rutinas de la empresa: GET /company/routines ahora también ordena por next_run_at, schedule_type y enabled, por lo que Agno OS puede ordenar su tabla de rutinas por Próxima ejecución en, Programada y Activa. Las rutinas en pausa y bajo demanda no tienen ejecución próxima, por lo que son las últimas en cualquier dirección y las rutinas con el mismo valor mantienen su orden de creación.
  • Libros de cocina: se agregó un ejemplo de búsqueda de empleo ApifyTools que limita el recuento de elementos del actor con un gancho de herramienta y recorta cada elemento del conjunto de datos por título, empresa, ubicación, fecha de publicación y enlace, para que una búsqueda amplia permanezca pequeña en contexto. Se agregó un ejemplo de Pixeltable RAG completamente local que escribe fragmentos a través de langchain-pixeltable y los busca con LangChainVectorDb, usando incrustaciones locales de sentence-transformers y Ollama; sin incrustar la clave API ni un servidor de base de datos vectorial separado.

Corrección de errores:

  • Seguimiento nativo FastAPI: FastAPI 0.142.0 habilita su propio seguimiento OpenTelemetry tan pronto como existe un proveedor de seguimiento global, que instala AgentOS(tracing=True), por lo que los intervalos de solicitudes de FastAPI se almacenaron junto con los de Agno. Cada ejecución se convirtió en un hijo del intervalo de solicitudes y los seguimientos se registraron como fastapi.dependencies con run_id, session_id y agent_id vacíos, rompiendo la vista de Ejecuciones, mientras que cada solicitud de UI almacenó un seguimiento propio. AgentOS ahora opta por la aplicación que construye a partir del rastreo de FastAPI, y setup_tracing() filtra intervalos externos para que un rastreo almacenado se arraigue en la ejecución de Agno. Las aplicaciones sin tracing=True mantienen los valores predeterminados de FastAPI y los intervalos creados por los propios usuarios dentro de las herramientas aún se conservan.
  • Cancelación de rutina de la empresa: POST /company/routines/{id}/cancel registró la ejecución como cancelled tan pronto como el ejecutor aceptó la solicitud, pero el agente solo se detiene en el siguiente punto de control. Para esa ventana, API informó cancelled mientras el agente todavía estaba funcionando, y el archivo, la eliminación y el cambio del ejecutor se realizaron a mitad de ejecución. La ruta ahora registra un estado solo a partir de evidencia duradera: una ejecución en vivo se deja sola para que ScheduleExecutor se establezca, una ejecución finalizada se escribe a través del propio mapeo del programador, una ejecución faltante se registra cancelled y una ejecución fallida que supera su tiempo de espera ya no bloquea el archivo, la eliminación o el cambio de ejecutor.
  • Juez AccuracyEval: AccuracyEval sin model ni evaluator_agent construyó su juez con OpenAIChat(id="o4-mini"), que OpenAI cerró el 23 de octubre de 2026, por lo que cada llamada de juez devolvió 404 model_not_found, no se puntuó ninguna iteración y la evaluación informó una ejecución vacía en lugar del error del proveedor detrás de ella. El valor predeterminado ahora es gpt-5.6-terra, las listas de OpenAI de reemplazo para o4-mini. Los ejemplos que fijaron modelos retirados también cambian, y los ejemplos de precisión cambian a OpenAIResponses porque OpenAIChat rechaza las herramientas funcionales para estos modelos.
  • Fragmentación del conocimiento por carga: POST /knowledge/content acepta chunker, chunk_size y chunk_overlap por carga, y process_content() los aplicó directamente a content.reader, el lector personalizado compartido o ya resuelto en la base de conocimientos. Cada carga posterior que utilizó ese lector mantuvo el fragmento de la carga anterior hasta que se reinició el proceso. La carga ahora obtiene su propia copia superficial del lector antes de aplicar la estrategia de fragmentación, por lo que la base de conocimientos mantiene su propia configuración.

agno v3.1.12

Highlights

  • Native approvals are the main behavioral change — Claude and Codex permission requests now reach AgentOS’s chat/Approvals UI, persist a PAUSED run when a database is available, and resume the same execution without replaying the prompt. Migration: a CodexAgent with no approval settings now defaults to approval_policy="on-request" and waits up to hitl_timeout (900s default), so previously ignored requests pause runs; set approval_policy="never" to opt out. Upgrade for harness-level human approvals.

  • Tracing and AccuracyEval reliability — AgentOS(tracing=True) now excludes FastAPI 0.142.0 request spans from stored Agno traces, fixing Runs entries with empty run_id, session_id, and agent_id while preserving users’ own tool spans. Separately, AccuracyEval replaces the retired OpenAIChat(id="o4-mini") default with gpt-5.6-terra; examples now use OpenAIResponses where function tools are required. Check explicitly pinned retired models, and prioritize this upgrade if you use the default evaluator.

  • Knowledge and Routine correctness — POST /knowledge/content applies per-upload chunker, chunk_size, and chunk_overlap to a reader copy, preventing one upload from silently changing later uploads until restart. Routine cancellation now records cancelled only from durable stopped evidence rather than executor acceptance, avoiding misleading status and allowing archive, delete, or executor changes after a crashed run times out. Upgrade if either workflow affects your workloads.

  • Additive Company and chart features — Routine(enabled=False) creates inactive templates that remain visible and can be enabled later; duplicate creation still returns 409, while existing pause/resume endpoints enable them without recreation. GET /company/routines adds sorting by next_run_at, schedule_type, and enabled. ChartTools.create_chart() accepts a preformatted value, such as "$22.3K" or "94%", for a headline beside the chart title. These are useful but not migration-critical.

  • Upgrade recommendation — This is a substantive release, not a re-tag or metadata-only update: prioritize it for AgentOS approvals/tracing, default AccuracyEval, mixed per-upload chunking, or Routine cancellation. Users outside those paths can defer unless they want initially disabled Routines or chart headline numbers; README and cookbook changes alone require no action.

Changelog

New Features:

  • Native Approvals for Harness Agents: Claude's and Codex's own permission requests now reach the AgentOS approval UI. When the agent has a database, including one AgentOS supplies, a native request persists a PAUSED run that shows up in the existing chat and Approvals views, and Resolve plus Continue Run delivers the decision back to the same native execution without replaying the prompt. The harness's own policy decides when to ask — Claude keeps its permission_mode and explicit permission callbacks, Codex supports approval_policy="on-request" | "untrusted" | "never" alongside its existing SDK auto_review and deny_all modes — so there is no separate Agno setting to turn on. Decisions are validated against the exact action requested, with sync and async continuation, cancellation, expiry and storage-failure handling, and sandboxed agents keep this across Docker and AgentCore: capability negotiation, a decision RPC, fenced persistence, reattachment after an API-worker loss, separate approval-wait and execution budgets, and no replay after process loss. Note that a CodexAgent with no approval settings now runs under the native on-request policy, so a request that previously went nowhere pauses the run instead; hitl_timeout (default 900s) bounds how long it waits. See cookbook/frameworks/human_in_the_loop/.
  • Initially Disabled Company Routines: Routine(enabled=False) lets a template ship an inactive Routine that a user turns on later from the UI, with True still the default. Disabled Routines are created atomically, stay linked to their Product and visible in listings, are skipped by the scheduler, and keep the user's saved choice across restarts. The flag is honored in Python and YAML bootstrap, the setup and creation APIs, the sync and async Company Manager, and the Company tools. Duplicate create requests still return 409 and cannot enable an existing Routine, and the existing pause/resume endpoints enable it without recreating it. See cookbook/05_agent_os/30_company/11_disabled_routine.py.
  • Headline Numbers on Charts: ChartTools.create_chart() takes an optional preformatted value — a total or latest value such as "$22.3K" or "94%" — emitted as "value" in the chart block and rendered by Agno OS beside the chart title. The docstring tells the model to leave it out when no single number summarizes the chart, so averages and rates are not summed.

Improvements:

  • Company Routine Sorting: GET /company/routines now also sorts by next_run_at, schedule_type and enabled, so Agno OS can sort its routines table by Next run at, Schedule and Active. Paused and on-demand Routines have no upcoming run, so they come last in either direction, and Routines with the same value keep their creation order.
  • Cookbooks: Added an ApifyTools job search example that caps the Actor's item count with a tool hook and trims each dataset item to title, company, location, posted date and link, so a broad search stays small in context. Added a fully local Pixeltable RAG example that writes chunks through langchain-pixeltable and searches them with LangChainVectorDb, using local sentence-transformers embeddings and Ollama — no embedding API key and no separate vector database server.

Bug Fixes:

  • FastAPI Native Tracing: FastAPI 0.142.0 enables its own OpenTelemetry tracing as soon as a global tracer provider exists, which AgentOS(tracing=True) installs, so FastAPI's request spans were stored alongside Agno's. Every run became a child of the request span and traces were recorded as fastapi.dependencies with empty run_id, session_id and agent_id, breaking the Runs view, while each UI request stored a trace of its own. AgentOS now opts the app it builds out of FastAPI's tracing, and setup_tracing() filters foreign spans so a stored trace is rooted at the Agno run. Apps without tracing=True keep FastAPI's defaults, and users' own spans created inside tools are still kept.
  • Company Routine Cancel: POST /company/routines/{id}/cancel recorded the run as cancelled as soon as the executor accepted the request, but the agent only stops at its next checkpoint. For that window the API reported cancelled while the agent was still working, and archive, delete and executor change went through mid-run. The route now records a status only from durable evidence: a live run is left alone for ScheduleExecutor to settle, a finished run is written through the scheduler's own mapping, a missing run is recorded cancelled, and a crashed run past its timeout no longer blocks archive, delete or executor change.
  • AccuracyEval Judge: AccuracyEval with no model and no evaluator_agent built its judge with OpenAIChat(id="o4-mini"), which OpenAI shut down on 2026-10-23, so every judge call returned 404 model_not_found, no iteration scored, and the eval reported an empty run instead of the provider error behind it. The default is now gpt-5.6-terra, the replacement OpenAI lists for o4-mini. The examples that pinned retired models move across too, and the accuracy examples switch to OpenAIResponses because OpenAIChat rejects function tools for these models.
  • Knowledge Per-Upload Chunking: POST /knowledge/content accepts per-upload chunker, chunk_size and chunk_overlap, and process_content() applied them straight to content.reader — the shared custom or already-resolved reader on the knowledge base. Every later upload using that reader kept the previous upload's chunker until the process restarted. The upload now gets its own shallow copy of the reader before the chunking strategy is applied, so the knowledge base keeps its own configuration.
