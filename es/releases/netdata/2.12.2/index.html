datos de red v2.12.2

Netdata v2.12.2 es una versión de parche para solucionar problemas descubiertos desde v2.12.1.

Esta versión refuerza la autenticación SNMPv3 en el receptor de capturas SNMP, evita que la evaluación de alertas mantenga vivos los gráficos obsoletos indefinidamente, hace que la nube vea de manera confiable a los niños desconectados como fuera de línea y reciba cada transición de alerta, restaura la interrupción prevista cuando el agente se vuelve a conectar a la nube, requiere que las solicitudes de configuración dinámica y de función lleven el estricto JSON, mantiene los complementos externos ejecutándose después de una única línea de salida con formato incorrecto, evita que los gráficos de estado de Kubernetes y sus alertas desaparezcan cuando un se elimina un objeto con nombre similar, hace que las consultas de largo alcance devuelvan datos de niveles más nuevos después de una brecha en los más antiguos y corrige compilaciones ARM estáticas de 64 bits que podrían fallar al inicio en placas Cortex-A53 como la Raspberry Pi 3.

Nube de streaming y Netdata

  • Se corrigió una carrera por la cual un niño que se desconectaba de su padre podía permanecer vivo en Netdata Cloud. La actualización del estado del nodo se programó antes de que el niño fuera marcado como fuera de línea, por lo que, bajo competencia de CPU, a veces el estado fuera de línea nunca se enviaba (#24285, @stelfrag)
  • Un padre ahora espera el 125% del tiempo de reinicio esperado de un niño desconectado, con un límite de 30 segundos, antes de informarlo fuera de línea a Netdata Cloud. La aritmética de enteros había reducido el margen al 100%. Un niño sin tiempo de reinicio registrado ya no programa un temporizador de retardo cero, lo que puede provocar un uso elevado de la CPU con versiones anteriores de libuv (#24343, @stelfrag)
  • Se corrigieron las transiciones de alerta que se perdían en el camino a Netdata Cloud. Un mensaje que la capa MQTT rechazó, por ejemplo mientras estaba fuera de línea o con el búfer lleno, se trataba como entregado y se eliminaba de la cola; ahora se vuelve a intentar. La instantánea de alerta también podría anunciar más fragmentos de los que envió y ahora se crea a partir de una única consulta coherente y se envía solo después de una reconstrucción exitosa (#24224, @stelfrag)
  • Se corrigió el retraso en la reconexión a Netdata Cloud. Una vez que el retroceso alcanzó su límite, la abrazadera se devolvió en segundos pero durmió en milisegundos, por lo que un agente desconectado volvió a intentarlo aproximadamente una vez por segundo en lugar de esperar hasta el máximo previsto (actualmente 20 minutos) (#24340, @stelfrag)
  • Se corrigió que la conexión a la nube entregara el ID 1 del paquete MQTT dos veces cuando el contador de ID del paquete giraba. Dos mensajes en tránsito con la misma identificación pierden su reconocimiento y seguimiento del tiempo de espera (#24341, @stelfrag)
  • Se corrigió la marca de tiempo t-rx en las respuestas HTTP del Agente a Netdata Cloud, que se había enviado como 0 desde v2.0.0 en lugar de la hora en que se recibió la solicitud (#24252, @stelfrag)

Salud

  • Se corrigió la evaluación de alertas que mantenía vivos los gráficos obsoletos. Cada paso de evaluación actualizaba la hora del último acceso al gráfico, por lo que un gráfico obsoleto con una alerta adjunta nunca tenía la edad suficiente para ser limpiado. En los nodos Kubernetes con rotación de pods, esto siguió aumentando el número de gráficos k8s.cgroup y los metadatos de Parents junto con ellos (#24273, @stelfrag)
  • Se corrigieron varios errores de persistencia de salud: se filtró una declaración preparada en cada transición de alerta en hosts sin una configuración ACLK, los identificadores de eventos de 64 bits se vincularon como valores de 32 bits y el siguiente identificador de evento de alarma volvió a 0 en lugar del identificador de alarma cuando no había filas de detalles (#24223, @stelfrag)

Base de datos

  • Se corrigieron los pasos de limpieza de metadatos que podían detenerse. Una pasada de limpieza de dimensión, gráfico o etiqueta nunca se completa si la primera fila de su instantánea se eliminó antes de ser leída, y una limpieza de contexto interrumpida eliminó el contexto de su cola, dejando el resto de sus dimensiones sin marcar. Ahora se vuelven a intentar los almacenes de etiquetas de gráficos fallidos y el tamaño de WAL se verifica con mucha menos frecuencia durante la limpieza (#24227, @stelfrag)
  • Se corrigió un punto muerto al liberar un diccionario cuya devolución de llamada de eliminación destruye un diccionario anidado que todavía tiene elementos referenciados. El reabastecimiento de nivel podría alcanzarlo cuando se liberaba un gráfico de un host eliminado mientras aún se hacía referencia a una de sus dimensiones (#24344, @stelfrag)
  • dbengine: las páginas corruptas comprimidas por Gorilla cuya longitud no es un múltiplo del tamaño del búfer ahora se rechazan en lugar de leerse más allá del final de su asignación (#24310, @ArjunD3456)
  • Se corrigieron los puntos completados de niveles superiores que permanecían invisibles para las consultas durante un período de nivel adicional completo. Se publicaban sólo cuando una colección se encontraba exactamente en un límite de nivel, algo que los coleccionistas lentos o desplazados pueden pasar por alto siempre; Los puntos vencidos ahora se publican en la siguiente muestra recopilada (#24405, @ktsaou)
  • dbengine: los espacios de un solo segundo ahora se almacenan en caché como los más largos, por lo que las consultas repetidas sobre ellos ya no vuelven a buscar en las revistas, y un espacio en caché ya no se superpone al primer punto de la página que le sigue (#24370, @ktsaou)

Consultas

  • Se corrigió el filtro dimensions= de /api/v1/context y /api/v1/contexts, que ignoraba todas las métricas cuyo nombre equivale a su ID (la mayoría de ellas) y, por lo tanto, devolvía todas las dimensiones, instancias y contextos (#24245, @stelfrag)
  • Se corrigieron patrones instance@node_id en los pesos API (correlaciones métricas, tasas de anomalías), que no coincidían con nada (#24245, @stelfrag)
  • Se corrigieron los filtros de etiquetas que combinan un nombre de etiqueta simple con un término name=value, por lo que los gráficos coincidentes se mantienen mientras que los términos name=value negativos aún tienen prioridad (#24202, @stelfrag)
  • Se corrigió que /api/v1/info leyera las cadenas de análisis (información de compilación, canal de lanzamiento, métodos de notificación, conectores de exportación) sin su bloqueo, por lo que una solicitud que se superpusiera a una actualización de análisis podría leer la memoria liberada (#24342, @stelfrag)
  • Se corrigieron las consultas que devolvían filas vacías durante el resto de su rango de tiempo cuando un nivel anterior se quedaba sin datos mucho antes del cambio planificado a un nivel más nuevo. La consulta ahora continúa en el nivel más nuevo y SES/DES ya no extiende los valores obsoletos hasta el final de una consulta cuyo cambio de nivel falló (#24406, @ktsaou)

Funciones

  • Las solicitudes de función y configuración dinámica ahora aceptan solo cuerpos de solicitud estrictos JSON (RFC 8259). Cualquier otro cuerpo, como YAML, datos de formulario o texto plano, se rechaza con HTTP 400. El tablero, Netdata Cloud y las propias personas que llaman del Agente ya envían JSON. Una configuración dinámica guardada que no es estricta JSON no se vuelve a aplicar y aparece una advertencia en el registro. Los cuerpos se verifican nuevamente donde se pasan a los complementos y a los niños de transmisión, por lo tanto, actualice los padres y sus hijos (#24409, @ktsaou)
  • go.d.plugin: el cuerpo de una solicitud de función ahora se trata como datos hasta su marcador final. Una línea en el cuerpo que parecía un comando de complemento podría reemplazar la llamada de función en ejecución, cancelar otra o evitar que el complemento lea más solicitudes. Las solicitudes con formato incorrecto o de gran tamaño ahora se omiten en su totalidad, sin que sus cuerpos se analicen como comandos (#24410, @ilyam8).

Coleccionistas

  • Complementos externos: un error de protocolo, como una sola línea corrupta de salida del complemento, deshabilitó permanentemente el complemento hasta que se reinició el Agente. Los errores de protocolo ahora siguen la misma política que las salidas de error: el complemento se reinicia después de 10 × update_every segundos y se deshabilita solo si nunca produjo resultados útiles o falla en más de 10 ejecuciones consecutivas (#24051, @ilyam8).
  • Trampas SNMP: los mensajes SNMPv3 ahora se rechazan y cuentan como usm_failures cuando omiten la autenticación de un usuario configurado para requerirla o declaran un modelo de seguridad que no es USM. Los mensajes rechazados no se reconocen y no registran los ID del motor (#24188, @ilyam8)
  • SNMP: las cadenas de comunidad y las frases de contraseña SNMPv3 ya no se incluyen en los detalles de conexión escritos en los registros de depuración (#24217, @ilyam8)
  • Estadísticas de disco: detección fija de los campos de descarte y vaciado en /proc/diskstats. Los núcleos anteriores a 4.18 tenían seis tablas de ceros disk_ext.*, y los núcleos 4.18 a 5.4 tenían las dimensiones de flushes atascadas en cero. Los campos ahora se detectan por disco y las dimensiones flushes se agregan cuando un disco comienza a informarlas (#24243, @stelfrag)
  • proc.plugin: sobrecarga reducida en kernels donde algunos archivos /proc no se pueden buscar, como Ubuntu 24.04 HWE (6.14). Rebobinar un archivo de este tipo ya no resuelve su nombre nuevamente en cada lectura, lo que reduce el tiempo de actividad de proc.plugin en aproximadamente un 9 % (#24212, @stelfrag)
  • Estado Kubernetes: eliminar un nodo, pod, implementación o cronjob ya no elimina los gráficos de objetos activos cuyos nombres comienzan con el mismo nombre, como los pods web-10 a web-19 cuando se elimina web-1. Esos gráficos no regresaron hasta que se recreó el objeto o se reinició el Agente, y sus alertas, como k8s_state_deployment_condition_available, se detuvieron silenciosamente. La programación de un pod tampoco reescribe la etiqueta del nodo en dichos gráficos (#24402, @stelfrag)
  • log2journal: la entrada JSON con matrices anidadas a mayor profundidad que la profundidad máxima del analizador ahora se rechaza con un error en lugar de sobrepasar su pila de claves (#24290, @ArjunD3456)

Instalación y embalaje

  • Las compilaciones estáticas para ARM de 64 bits ahora habilitan las soluciones del vinculador para las erratas Cortex-A53 835769 y 843419, incluso para los complementos Rust. Dependiendo del diseño del código, una compilación estática podría morir con SIGILL al inicio en placas Cortex-A53 como Raspberry Pi 3 y ODROID-C2. CI ahora escanea el archivo estático aarch64 en busca de secuencias de instrucciones no fijadas, y las funciones Rust están alineadas a 8 bytes para que los resguardos de erratas del vinculador no puedan volver a colocarlos en una secuencia afectada (#24207, @stelfrag, #24387, @vkalintiris)
  • Los paquetes de Windows ahora incluyen el msys-2.0.dll del propio paquete msys2-runtime 3.6.11 de MSYS2, fijado por URL y suma de comprobación, en lugar de crear un tiempo de ejecución 3.6.10 parcheado desde el código fuente. 3.6.11 incluye las correcciones originales para el bloqueo de inicio solucionado en v2.12.1, y la compilación fuente ya no se compila con la cadena de herramientas actual de MSYS2 (#24390, @stelfrag)
  • Se actualizaron las bibliotecas IBM MQ client suministradas a 9.4.5.1 (#24294, @Ferroin)

netdata v2.12.2

Netdata v2.12.2 is a patch release to address issues discovered since v2.12.1.

This release tightens SNMPv3 authentication in the SNMP traps receiver, stops alert evaluation from keeping obsolete charts alive indefinitely, makes Cloud reliably see disconnected children as offline and receive every alert transition, restores the intended backoff when the Agent reconnects to Cloud, requires Function and dynamic configuration requests to carry strict JSON, keeps external plugins running after a single malformed line of output, keeps Kubernetes state charts and their alerts from disappearing when a similarly named object is deleted, makes long-range queries return data from newer tiers after a gap in older ones, and fixes static 64-bit ARM builds that could crash at startup on Cortex-A53 boards such as the Raspberry Pi 3.

Streaming and Netdata Cloud

  • Fixed a race where a child that disconnected from its Parent could stay live in Netdata Cloud. The node state update was scheduled before the child was marked offline, so under CPU contention the offline state was sometimes never sent (#24285, @stelfrag)
  • A Parent now waits 125% of a disconnected child's expected reboot time, capped at 30 seconds, before reporting it offline to Netdata Cloud. Integer arithmetic had reduced the margin to 100%. A child with no recorded reboot time no longer schedules a zero-delay timer, which can cause high CPU usage with older libuv versions (#24343, @stelfrag)
  • Fixed alert transitions being lost on the way to Netdata Cloud. A message the MQTT layer refused, for example while offline or with a full buffer, was treated as delivered and removed from the queue; it is now retried. The alert snapshot also could announce more chunks than it sent, and is now built from a single consistent query and sent only after a successful rebuild (#24224, @stelfrag)
  • Fixed the reconnect backoff to Netdata Cloud. Once the backoff reached its cap, the clamp was returned in seconds but slept as milliseconds, so a disconnected Agent retried about once per second instead of waiting up to the intended maximum (currently 20 minutes) (#24340, @stelfrag)
  • Fixed the Cloud connection handing out MQTT packet id 1 twice when the packet id counter wrapped around. Two messages in flight with the same id lose their acknowledgement and timeout tracking (#24341, @stelfrag)
  • Fixed the t-rx timestamp in the Agent's HTTP replies to Netdata Cloud, which had been sent as 0 since v2.0.0 instead of the time the request was received (#24252, @stelfrag)

Health

  • Fixed alert evaluation keeping obsolete charts alive. Every evaluation pass refreshed the chart's last-access time, so an obsolete chart with an alert attached was never old enough to be cleaned up. On Kubernetes nodes with pod churn this kept growing the number of k8s.cgroup charts, and the metadata on Parents along with it (#24273, @stelfrag)
  • Fixed several health persistence bugs: a prepared statement leaked on every alert transition on hosts without an ACLK configuration, 64-bit event ids were bound as 32-bit values, and the next alarm event id fell back to 0 instead of the alarm id when there were no detail rows (#24223, @stelfrag)

Database

  • Fixed metadata cleanup passes that could stall. A dimension, chart or label cleanup pass never completed if the first row of its snapshot was deleted before being read, and an interrupted context cleanup dropped the context from its queue, leaving the rest of its dimensions unchecked. Failed chart label stores are now retried, and the WAL size is checked far less often during cleanup (#24227, @stelfrag)
  • Fixed a deadlock when freeing a dictionary whose delete callback destroys a nested dictionary that still has referenced items. Tier backfill could reach it when a chart of a removed host was freed while one of its dimensions was still referenced (#24344, @stelfrag)
  • dbengine: corrupted gorilla-compressed pages whose length is not a multiple of the buffer size are now rejected instead of being read past the end of their allocation (#24310, @ArjunD3456)
  • Fixed completed points of higher tiers staying invisible to queries for a full extra tier period. They were published only when a collection landed exactly on a tier boundary, which slow or offset collectors can miss every time; overdue points are now published on the next collected sample (#24405, @ktsaou)
  • dbengine: gaps of a single second are now cached like longer ones, so repeated queries over them no longer search the journals again, and a cached gap no longer overlaps the first point of the page that follows it (#24370, @ktsaou)

Queries

  • Fixed the dimensions= filter of /api/v1/context and /api/v1/contexts, which ignored every metric whose name equals its id (most of them) and so returned all dimensions, instances and contexts (#24245, @stelfrag)
  • Fixed instance@node_id patterns in the weights API (metric correlations, anomaly rates), which matched nothing (#24245, @stelfrag)
  • Fixed label filters that combine a bare label name with a name=value term, so matching charts are kept while negative name=value terms still take precedence (#24202, @stelfrag)
  • Fixed /api/v1/info reading the analytics strings (build info, release channel, notification methods, exporting connectors) without their lock, so a request that overlapped an analytics refresh could read freed memory (#24342, @stelfrag)
  • Fixed queries returning empty rows for the rest of their time range when an older tier ran out of data well before the planned switch to a newer tier. The query now continues into the newer tier, and SES/DES no longer extend stale values to the end of a query whose tier switch failed (#24406, @ktsaou)

Functions

  • Function and dynamic configuration requests now accept only strict JSON request bodies (RFC 8259). Any other body, such as YAML, form data or plain text, is rejected with HTTP 400. The dashboard, Netdata Cloud and the Agent's own callers already send JSON. A saved dynamic configuration that is not strict JSON fails to re-apply, with a warning in the log. Bodies are checked again where they are passed to plugins and streaming children, so update Parents as well as their children (#24409, @ktsaou)
  • go.d.plugin: the body of a Function request is now treated as data up to its end marker. A line in the body that looked like a plugin command could replace the running Function call, cancel another one, or stop the plugin from reading further requests. Malformed or oversized requests are now skipped as a whole, without their bodies being parsed as commands (#24410, @ilyam8)

Collectors

  • External plugins: a protocol error, such as a single corrupted line of plugin output, permanently disabled the plugin until the Agent restarted. Protocol errors now follow the same policy as error exits: the plugin is restarted after 10 × update_every seconds, and disabled only if it never produced useful output or fails more than 10 consecutive runs (#24051, @ilyam8)
  • SNMP traps: SNMPv3 messages are now rejected and counted as usm_failures when they skip authentication for a user configured to require it, or declare a non-USM security model. Rejected messages are not acknowledged and do not register engine IDs (#24188, @ilyam8)
  • SNMP: community strings and SNMPv3 passphrases are no longer included in the connection details written to debug logs (#24217, @ilyam8)
  • Disk statistics: fixed detection of the discard and flush fields in /proc/diskstats. Kernels before 4.18 got six disk_ext.* charts of zeros, and kernels 4.18 to 5.4 got flushes dimensions stuck at zero. The fields are now detected per disk, and flushes dimensions are added when a disk starts reporting them (#24243, @stelfrag)
  • proc.plugin: reduced overhead on kernels where some /proc files are not seekable, such as Ubuntu 24.04 HWE (6.14). Rewinding such a file no longer resolves its name again on every read, cutting proc.plugin busy time by about 9% (#24212, @stelfrag)
  • Kubernetes state: deleting a node, pod, deployment or cronjob no longer removes the charts of live objects whose names start with the same name, such as pods web-10 to web-19 when web-1 is deleted. Those charts did not come back until the object was recreated or the Agent restarted, and their alerts, such as k8s_state_deployment_condition_available, silently stopped. Scheduling a pod also no longer rewrites the node label on such charts (#24402, @stelfrag)
  • log2journal: JSON input with arrays nested deeper than the parser's maximum depth is now rejected with an error instead of overrunning its key stack (#24290, @ArjunD3456)

Installation and packaging

  • Static builds for 64-bit ARM now enable the linker workarounds for Cortex-A53 errata 835769 and 843419, including for the Rust plugins. Depending on code layout, a static build could die with SIGILL at startup on Cortex-A53 boards such as the Raspberry Pi 3 and ODROID-C2. CI now scans the aarch64 static archive for unfixed instruction sequences, and Rust functions are aligned to 8 bytes so the linker's erratum stubs cannot shift them back onto an affected sequence (#24207, @stelfrag, #24387, @vkalintiris)
  • Windows packages now bundle the msys-2.0.dll from MSYS2's own msys2-runtime 3.6.11 package, pinned by URL and checksum, instead of building a patched 3.6.10 runtime from source. 3.6.11 carries the upstream fixes for the startup crash addressed in v2.12.1, and the source build no longer compiled with MSYS2's current toolchain (#24390, @stelfrag)
  • Updated the vendored IBM MQ client libraries to 9.4.5.1 (#24294, @Ferroin)
