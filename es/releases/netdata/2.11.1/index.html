datos de red v2.11.1

Release note

Netdata v2.11.1 es una versión de parche para solucionar problemas descubiertos desde v2.11.0.

Se trata de una versión de parche más grande de lo habitual centrada en la corrección de las consultas, la estabilidad del motor de la base de datos, la solidez de la conectividad en la nube, la eficiencia del estado/alertas y la seguridad del apagado y la vida útil del proceso, junto con una serie de correcciones de recopiladores y plataformas, incluida una cobertura más amplia de SQL Server y mejoras en la CPU y el disco de Windows.

Motor de consultas

  • Se conservaron los valores SUM exactos cuando un punto almacenado abarca filas de resultados o un límite de nivel de almacenamiento automático, y se conservaron las líneas base de suma incremental para que los depósitos que contienen solo una muestra inicial ya no produzcan consultas vacías (#23512, #23505, @ktsaou)
  • Se mantuvieron las marcas de tiempo API independientes de la retención de cada Agente, por lo que la misma solicitud explícita o relativa devuelve las mismas marcas de tiempo de fila en todos los Agentes (#23507, @ktsaou)
  • Se atribuyó RESET de nivel 0 y evidencia de anomalías a la fila de resultados que realmente contiene la muestra de origen, y se corrigieron los recuentos de contribuyentes con tasa de anomalías en consultas agrupadas de dos pasadas (#23504, #23508, @ktsaou)
  • Se aplicó options=absolute a los puntos obtenidos del nivel entrante durante un cambio de plan, por lo que un valor negativo ya no puede cruzar una transición de nivel sin cambios (#23503, @ktsaou)
  • Se corrigió un operador lógico en el contenedor JSON para que las dimensiones no consultadas se excluyan como se esperaba a menos que se soliciten todas las dimensiones (#23639, @stelfrag)

Motor de base de datos

  • Se corrigió un problema de uso después de la liberación y un error fatal en las consultas de extensión combinada al adquirir referencias de caché de página antes de publicar los detalles de la página y sincronizar el desmontaje de la consulta de extensión combinada bajo el bloqueo de extensión (#23475, #23521, @stelfrag)
  • Se corrigió un doble libre de métricas MRG obsoletas durante la migración del diario v2 y una fuga en el contador de lotes vacíos que podía dejar el apagado o la rotación del archivo de datos en espera indefinida (#23560, #23699, @stelfrag)
  • Se evitaron informes de retención de niveles negativos y basados en épocas: sin truncamiento de 32 bits al formatear duraciones, tiempos de inicio desconocidos o cero tratados como no disponibles, diarios vacíos ignorados y retención extrapolada limitada (#23648, @stelfrag)
  • Se aceptaron cadencias de página válidas de más de un día en lugar de tratarlas como no válidas y emitir telemetría de reparación falsa (#23514, @ktsaou)
  • Se evitó la contención de creación/liberación de abandono de mapas UUID y bloqueo de escritura de particiones durante las búsquedas de métricas de MRG, y se incluyó caché completo e identidad de página en mensajes fatales de PGC para hacer que los problemas de caché sean diagnosticables (#23538, #23522, @stelfrag)
  • Se actualizó el SQLite incluido a 3.53.4 (#23511, @stelfrag)
  • Se repararon las cargas de trabajo de prueba de esfuerzo de -W createdataset y dbengine, que fallaban en un asignador de etiquetas NULL, marcaban cada muestra generada con el reloj de pared en lugar del rango de tiempo solicitado y liberaban dos veces el estado en el desmontaje del host (#23758, @stelfrag)

Conectividad en la nube (ACLK)

  • Se agregó verificación de IP y nombre de host TLS para solicitudes HTTPS de ACLK, al mismo tiempo que se preserva el comportamiento en modo inseguro (#23463, @stelfrag)
  • Se dejó de informar los certificados autofirmados exentos como fallas de verificación de certificados en modo inseguro, por lo que luego se informan los errores de E/S o HTTP tal como son (#23732, @stelfrag)
  • Se cambiaron los HTTPS y MQTT clients a tiempos de espera monótonos basados en microsegundos con un mecanismo de vigilancia del progreso de E/S y se limitó el sondeo previo a CONNACK a un segundo para que un interlocutor silencioso ya no pueda retrasar el apagado hasta 60 segundos (#23105, #23733, @stelfrag)
  • Se dejó de contar los PUBACK MQTT faltantes como reconocimientos exitosos, y se los rastrea con un contador de tiempo de espera dedicado que ahora se conserva en todas las desconexiones sin tocar un client liberado (#23486, #23734, @stelfrag)
  • Se conservaron los buffers de respuesta agrupados y sus metadatos para respuestas ACLK comprimidas, y se corrigió el enmascaramiento de WebSocket de las cargas útiles que abarcan los límites del ring-buffer (#23485, @stelfrag)

Salud y alertas

  • Se corrigió la alerta 10min_cpu_usage de Windows que se adjuntaba a los gráficos service.*_cpu_utilization y disparaba falsas alarmas CRÍTICAS (#23559, @thiagoftsm)
  • Alertas indexadas por nombre por host, reemplazando análisis de alertas de host completo durante la resolución de variables de estado (#23554, @stelfrag)
  • Se evitó reinicializar prototipos de alerta cuando los metadatos de los gráficos no han cambiado, por lo que los nuevos registros continuos de gráficos secundarios ya no desencadenan una reevaluación repetida del estado (#23515, @stelfrag)
  • Se crearon resúmenes de alerta solo cuando se envía una notificación, evitando el trabajo de iteración y un posible punto muerto en el orden de bloqueo con la eliminación del gráfico (#23544, @stelfrag)
  • Se corrigió una verificación de error incorrecta en la preparación de declaraciones SQL en el código de la base de datos de salud y se eliminaron dos índices health_log_detail no utilizados para reducir el almacenamiento de la base de datos principal y el mantenimiento del árbol B (#23545, #23722, @stelfrag)

Metadatos, etiquetas y elementos internos

  • Destrucción diferida del diccionario mientras los diccionarios API están en vuelo, lo que hace que establecer/obtener/eliminar y recorrer sea seguro contra la destrucción simultánea durante el apagado (#23634, @stelfrag)
  • Se corrigió un uso después de la liberación en la recolección de basura del diccionario cuando una devolución de llamada de eliminación reingresaba al recopilador y liberaba el sucesor en caché a mitad de camino, y dejaba de ver las colecciones dejando atrás los elementos eliminados por el maestro (#23819, @stelfrag)
  • Se impidió que el reaper de gráficos obsoletos liberara un gráfico al que todavía hace referencia otro subsistema, lo que dejó un gráfico sin indexar con su bloqueo de destrucción y podría causar la muerte a un recopilador que todavía escribiera en él (#23761, @stelfrag)
  • Desmontaje diferido de la cola de trabajadores de aprendizaje automático hasta que se hayan detenido todos los recopiladores, por lo que un recopilador que sobreviva la fecha límite de cierre ya no podrá cancelar en una exclusión mutua de cola destruida (#23757, @stelfrag)
  • Restableció y desbloqueó SIGPIPE en niños generados, por lo que un niño cuyas tuberías están cerradas sale en lugar de sobrevivir en EPIPE, que había bloqueado cientos de procesos powermetrics en macOS, informó una entrega de señal fallida en lugar de eliminarla silenciosamente, e hizo que las pruebas de regresión del servidor de generación fueran deterministas (#23751, #23815, @stelfrag)
  • Se investigó la compatibilidad con KSM antes de habilitar la deduplicación de páginas en lugar de asumirla, por lo que los núcleos no compatibles ya no informan errores de KSM y se limitó el marcado de KSM a los grupos de páginas de dbengine que realmente pueden fusionarse (#23822, @stelfrag)
  • Se omitió la desinfección y la reincorporación de metadatos de gráficos sin cambios en el registro repetido de gráficos, y se incrementó la versión de la etiqueta solo en mutaciones de etiquetas reales (#23603, #23513, @stelfrag)
  • Se corrigió un problema de limpieza del búfer de texto y una carrera de tamaño de árbol dyncfg durante las actualizaciones de configuración simultáneas (#23657, @stelfrag)
  • Se reemplazó sprintf() con snprintfz() delimitado en formato numérico inicfg y se reemplazaron las cadenas de formato de ruta dinámicas /proc/net/dev por cadenas literales (#23638, #23450, @stelfrag)
  • Se redujo la sobrecarga de pulso al ejecutar la recopilación mallinfo2() en un intervalo configurable y alineado con el pulso, sellándolo después de la finalización para que una llamada lenta no pueda monopolizar el ciclo de trabajo y se detuvieron los aumentos redundantes de la versión de metadatos del gráfico de pulso (#23579, #23736, #23650. @stelfrag)
  • Se eliminó una sonda de etiqueta por gráfico de los gráficos secundarios de pulso, confiando en su lugar en la comparación de la versión de la etiqueta del host; en un padre con 808 hijos, la sonda representó aproximadamente el 23 % del hilo de pulso principal y dejó espacios en los gráficos netdata.* que emite (#23760, @stelfrag)
  • Se silenció un hallazgo de Coverity y se corrigieron comentarios obsoletos y diagnósticos de pruebas unitarias, incluida la documentación del comportamiento del indicador de inicialización de salud mientras un niño está desconectado (#23553, #23737, #23541, @stelfrag)

Coleccionistas y exportadores

  • Se corrigió el análisis de /proc/interrupts cuando el primer contador está pegado al ID de interrupción, lo que podría empujar los valores cambiantes del contador a ID de dimensión y provocar un crecimiento ilimitado de la dimensión (#23651, @stelfrag)
  • Colección de sockets limitada a un intento verificado por espacio de nombres de red, por lo que las fallas del asistente ya no activan intentos repetidos de recolección para cada registro de socket (#23778, @ktsaou)
  • Se detuvo el recopilador de UPS go.d que incorporaba el comando completo en errores de conexión, lo que registraba la credencial PASSWORD en texto claro; solo los argumentos USERNAME y PASSWORD están redactados, por lo que otros comandos siguen siendo diagnosticables (#23782, @stelfrag)
  • SQL saturado COUNT genera resultados en el recopilador ibm.d AS/400 antes de limitarlos a int, por lo que un recuento fuera de rango ya no puede ajustar los límites negativos y cambiar silenciosamente los límites de cardinalidad (#23783, @stelfrag)
  • Se corrigió la transformación del indicador MikroTik en el recopilador SNMP de go.d y se eliminaron los átomos no alineados del motor de gráficos de go.d (#23525, #23540, @ilyam8).
  • Se preservó la puntuación válida en los nombres de host de telnet y prefijos métricos de OpenTSDB, al mismo tiempo que se reemplazan los espacios en blanco, los caracteres de control y los delimitadores que corromperían los registros de telnet (#23749, @stelfrag)
  • Se corrigió el mensaje del gráfico deshabilitado charts.d.plugin que apuntaba a charts.d.plugin.conf en lugar del charts.d.conf real (#23662, @ilyam8)
  • SQL Server: se agregó un respaldo de caché de plan (sys.dm_exec_query_stats) para top-queries cuando el almacén de consultas no está disponible o está deshabilitado, y se recurrió a la sesión integrada system_health para error-info cuando no se configura una sesión de eventos extendidos dedicada (#23748, @thiagoftsm)
  • SQL Server: fortaleció las consultas de funciones en todas las ediciones, probó la edición y la versión del motor una vez por instancia y enruta las consultas con ámbito de servidor versus consultas con ámbito de base de datos en consecuencia, de modo que top-queries, deadlock-info y error-info funcionen en Azure SQL Database e Instancia administrada, así como en SQL Server local (#23564, @ilyam8)
  • SQL Server: se corrigieron las consultas de información de error y punto muerto en SQL Server 2014 y versiones anteriores, detectando el Almacén de consultas por columna del catálogo en lugar de la versión del producto y leyendo la ruta del archivo event_file del catálogo de sesiones en lugar de asumir que coincide con el nombre de la sesión (#23460, @thiagoftsm)
  • SQL Server: excluyó de la colección los trabajos del Agente SQL deshabilitados de forma predeterminada (configure collect_disabled_jobs: true para conservarlos) y bloqueó las alertas de trabajo en el trabajo que se estaba habilitando, por lo que la última ejecución fallida de un trabajo deshabilitado ya no genera una alerta (#23645, @ilyam8)
  • Windows: recopiló métricas de CPU del objeto de rendimiento Processor Information, asignando sus instancias NumaNode,NumaIndex a CPU lógicas a través de la topología del procesador, de modo que los hosts con más de 64 procesadores lógicos se informen correctamente; el objeto Processor heredado todavía se usa donde Processor Information no está disponible (#23549, @thiagoftsm)
  • Windows: se agregó exclude space metrics on paths en [plugin:windows:PerflibStorage] para mantener los volúmenes lógicos no deseados (como montajes de respaldo temporales) fuera de la recopilación de espacio en disco, se agregó una etiqueta de volumen serial_number y se corrigió la etiqueta driver_type mal escrita a drive_type (#23660, @thiagoftsm)

Instalación y embalaje

  • Windows: se corrigió el reclamo cuando solo se proporciona un token y se marcó el token de reclamo y el proxy como propiedades MSI ocultas para que ya no aparezcan en los registros detallados del instalador (#23547, @thiagoftsm; #23735, @stelfrag)
  • Se restringió el complemento eBPF a zonas de usuario de 64 bits y se resolvió la cadena de herramientas Go desde el tipo de máquina de la zona de usuario en lugar de la arquitectura del kernel (#23446, @stelfrag)
  • macOS: resolvió los IOKit API dinámicamente en lugar de vincularlos directamente, restaurando compilaciones contra macOS SDK más antiguos (#23421, @stelfrag)

netdata v2.11.1

Release notes

Netdata v2.11.1 is a patch release to address issues discovered since v2.11.0.

This is a larger-than-usual patch release focused on query correctness, database engine stability, Cloud connectivity robustness, health/alert efficiency, and shutdown and process-lifetime safety, along with a number of collector and platform fixes, including broader SQL Server coverage and Windows CPU and disk improvements.

Query engine

  • Preserved exact SUM values when a stored point spans result rows or an automatic storage-tier boundary, and preserved incremental-sum baselines so buckets holding only an opening sample no longer produce empty queries (#23512, #23505, @ktsaou)
  • Kept API timestamps independent of each Agent's retention, so the same explicit or relative request returns the same row timestamps across Agents (#23507, @ktsaou)
  • Attributed tier-0 RESET and anomaly evidence to the result row that actually contains the source sample, and fixed anomaly-rate contributor counts in two-pass group-by queries (#23504, #23508, @ktsaou)
  • Applied options=absolute to points fetched from the incoming tier during a plan switch, so a negative value can no longer cross a tier transition unchanged (#23503, @ktsaou)
  • Fixed a logical operator in the JSON wrapper so unqueried dimensions are excluded as expected unless all dimensions are requested (#23639, @stelfrag)

Database engine

  • Fixed a use-after-free and a fatal in merged extent queries by acquiring page-cache references before publishing page details and synchronizing merged extent query teardown under the extent spinlock (#23475, #23521, @stelfrag)
  • Fixed a double free of stale MRG metrics during journal v2 migration, and an empty flush-batch counter leak that could leave shutdown or datafile rotation waiting indefinitely (#23560, #23699, @stelfrag)
  • Prevented negative and epoch-based tier retention reporting: no 32-bit truncation when formatting durations, unknown or zero start times treated as unavailable, empty journals ignored, and extrapolated retention capped (#23648, @stelfrag)
  • Accepted valid page cadences longer than one day instead of treating them as invalid and emitting false repair telemetry (#23514, @ktsaou)
  • Avoided UUID map create/free churn and partition write-lock contention during MRG metric lookups, and included full cache and page identity in PGC fatal messages to make cache issues diagnosable (#23538, #23522, @stelfrag)
  • Updated the bundled SQLite to 3.53.4 (#23511, @stelfrag)
  • Repaired the -W createdataset and dbengine stress-test workloads, which crashed on a NULL labels allocator, stamped every generated sample with the wall clock instead of the requested time range, and double-freed state at host teardown (#23758, @stelfrag)

Cloud connectivity (ACLK)

  • Added TLS hostname and IP verification for ACLK HTTPS requests, while preserving insecure-mode behavior (#23463, @stelfrag)
  • Stopped reporting waived self-signed certificates as certificate verification failures in insecure mode, so later I/O or HTTP errors are reported for what they are (#23732, @stelfrag)
  • Switched the HTTPS and MQTT clients to monotonic, microsecond-based timeouts with an I/O progress watchdog, and bounded pre-CONNACK polling to one second so a quiet peer can no longer delay shutdown by up to 60 seconds (#23105, #23733, @stelfrag)
  • Stopped counting missing MQTT PUBACKs as successful acknowledgements, tracking them with a dedicated timeout counter that is now preserved across disconnects without touching a freed client (#23486, #23734, @stelfrag)
  • Preserved pooled response buffers and their metadata for compressed ACLK responses, and fixed WebSocket masking of payloads spanning ring-buffer boundaries (#23485, @stelfrag)

Health and alerts

  • Fixed the Windows 10min_cpu_usage alert attaching to service.*_cpu_utilization charts and firing false CRITICAL alarms (#23559, @thiagoftsm)
  • Indexed alerts by name per host, replacing full-host alert scans during health-variable resolution (#23554, @stelfrag)
  • Avoided re-initializing alert prototypes when chart metadata has not changed, so continuous child-chart re-registrations no longer trigger repeated health re-evaluation (#23515, @stelfrag)
  • Built raised-alert summaries only when a notification is actually sent, avoiding per-iteration work and a potential lock-order deadlock with chart removal (#23544, @stelfrag)
  • Fixed an incorrect error check on SQL statement preparation in the health database code, and removed two unused health_log_detail indexes to reduce parent database storage and B-tree maintenance (#23545, #23722, @stelfrag)

Metadata, labels and internals

  • Deferred dictionary destruction while dictionary APIs are in flight, making set/get/delete and traversal safe against concurrent destruction during shutdown (#23634, @stelfrag)
  • Fixed a use-after-free in dictionary garbage collection when a delete callback re-entered the collector and freed the cached successor mid-walk, and stopped view collections leaving master-deleted items behind (#23819, @stelfrag)
  • Stopped the obsolete-chart reaper from freeing a chart another subsystem still references, which left an unindexed chart holding its destroy lock and could fatal a collector still writing to it (#23761, @stelfrag)
  • Deferred machine-learning worker queue teardown until after all collectors have stopped, so a collector that outlives the shutdown deadline can no longer abort on a destroyed queue mutex (#23757, @stelfrag)
  • Reset and unblocked SIGPIPE in spawned children, so a child whose pipes are closed exits instead of surviving on EPIPE — which had stranded hundreds of powermetrics processes on macOS — reported failed signal delivery instead of dropping it silently, and made the spawn-server regression tests deterministic (#23751, #23815, @stelfrag)
  • Probed for KSM support before enabling page deduplication instead of assuming it, so unsupported kernels no longer report KSM errors, and limited KSM marking to the dbengine page pools that can actually merge (#23822, @stelfrag)
  • Skipped sanitizing and re-interning unchanged chart metadata on repeated chart registration, and incremented the label version only on actual label mutations (#23603, #23513, @stelfrag)
  • Fixed a text-buffer cleanup issue and a dyncfg tree sizing race during concurrent configuration updates (#23657, @stelfrag)
  • Replaced sprintf() with bounded snprintfz() in inicfg numeric formatting, and replaced dynamic /proc/net/dev path format strings with literal ones (#23638, #23450, @stelfrag)
  • Reduced pulse overhead by running mallinfo2() collection on a configurable, pulse-aligned interval, stamping it after completion so a slow call cannot monopolize the duty cycle, and stopped redundant pulse chart metadata version bumps (#23579, #23736, #23650, @stelfrag)
  • Removed a per-chart label probe from the pulse child charts, relying on the host label-version compare instead; on a parent with 808 children the probe accounted for about 23% of the main pulse thread and left gaps in the netdata.* charts it emits (#23760, @stelfrag)
  • Silenced a Coverity finding and corrected stale comments and unit-test diagnostics, including documenting health-initialization flag behavior while a child is disconnected (#23553, #23737, #23541, @stelfrag)

Collectors and exporting

  • Fixed /proc/interrupts parsing when the first counter is glued to the interrupt ID, which could push changing counter values into dimension IDs and cause unbounded dimension growth (#23651, @stelfrag)
  • Bounded socket collection to one verified attempt per network namespace, so helper failures no longer trigger repeated collection attempts for every socket record (#23778, @ktsaou)
  • Stopped the go.d UPS collector embedding the full command in connection errors, which logged the PASSWORD credential in clear text; only USERNAME and PASSWORD arguments are redacted, so other commands stay diagnosable (#23782, @stelfrag)
  • Saturated SQL COUNT results in the ibm.d AS/400 collector before narrowing them to int, so an out-of-range count can no longer wrap negative and silently change the cardinality limits (#23783, @stelfrag)
  • Corrected the MikroTik gauge transform in the go.d SNMP collector, and removed unaligned atomics from the go.d chart engine (#23525, #23540, @ilyam8)
  • Preserved valid punctuation in OpenTSDB telnet hostnames and metric prefixes, while still replacing whitespace, control characters, and delimiters that would corrupt telnet records (#23749, @stelfrag)
  • Fixed the charts.d.plugin disabled-chart message pointing to charts.d.plugin.conf instead of the actual charts.d.conf (#23662, @ilyam8)
  • SQL Server: added a plan-cache fallback (sys.dm_exec_query_stats) for top-queries when Query Store is unavailable or disabled, and fell back to the built-in system_health session for error-info when no dedicated Extended Events session is configured (#23748, @thiagoftsm)
  • SQL Server: hardened the function queries across editions, probing engine edition and version once per instance and routing server-scoped versus database-scoped queries accordingly, so top-queries, deadlock-info and error-info work on Azure SQL Database and Managed Instance as well as on-premises SQL Server (#23564, @ilyam8)
  • SQL Server: fixed the deadlock and error-info queries on SQL Server 2014 and older, detecting Query Store by catalog column instead of product version, and reading the event_file path from the session catalog instead of assuming it matches the session name (#23460, @thiagoftsm)
  • SQL Server: excluded disabled SQL Agent jobs from collection by default (set collect_disabled_jobs: true to keep them) and gated the job alerts on the job being enabled, so a disabled job's last failed run no longer keeps an alert raised (#23645, @ilyam8)
  • Windows: collected CPU metrics from the Processor Information performance object, mapping its NumaNode,NumaIndex instances to logical CPUs via the processor topology, so hosts with more than 64 logical processors are reported correctly; the legacy Processor object is still used where Processor Information is unavailable (#23549, @thiagoftsm)
  • Windows: added exclude space metrics on paths under [plugin:windows:PerflibStorage] to keep unwanted logical volumes (such as temporary backup mounts) out of disk space collection, added a volume serial_number label, and corrected the misspelled driver_type label to drive_type (#23660, @thiagoftsm)

Installation and packaging

  • Windows: fixed claiming when only a token is provided, and marked the claim token and proxy as hidden MSI properties so they no longer appear in verbose installer logs (#23547, @thiagoftsm; #23735, @stelfrag)
  • Restricted the eBPF plugin to 64-bit userlands and resolved the Go toolchain from the userland machine type rather than the kernel architecture (#23446, @stelfrag)
  • macOS: resolved the IOKit APIs dynamically instead of linking them directly, restoring builds against older macOS SDKs (#23421, @stelfrag)
