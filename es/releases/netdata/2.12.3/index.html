datos de red v2.12.3

Release note

Netdata v2.12.3 es una versión de parche para solucionar problemas descubiertos desde v2.12.2.

Esta versión hace que el Agente detecte una conexión Netdata Cloud inactiva incluso mientras el tráfico continúa fluyendo, corrige fallas de uso después de la liberación cuando se elimina un nodo obsoleto mientras un niño o un complemento todavía lo está usando, evita que los niños configurados con parent using h2o fallen en cada conexión, hace que una IP negada en una lista de acceso tenga prioridad sobre la coincidencia de nombre de host, rechaza escapes porcentuales mal formados en las URL, limita las solicitudes por lotes de MCP, elimina bloqueos globales de SQLite, corrige fallas cuando los gráficos están obsoletos se limpian mientras aún se están leyendo, evita que el Agente se cuelgue al inicio cuando no se puede crear un nivel dbengine, evita que los padres que usan los modos de almacenamiento ram o alloc cambien el historial de sus hijos después de un intervalo y se bloqueen en correlaciones métricas de múltiples nodos, permite que SNMP y otros nodos virtuales se desconecten nuevamente cuando su recopilador deja de informarlos, hace que los gráficos de PowerStore muestren los valores que reporta la matriz en lugar de ceros, hace que los complementos eBPF ignoren el directorio se anula del entorno cuando se ejecutan con privilegios elevados y recarga las etiquetas del host desde el archivo de configuración que el Agente realmente cargó.

Nube de streaming y Netdata

  • Se corrigió el mantenimiento MQTT de la conexión a la nube. Sólo se comprobaba cuando la conexión estaba inactiva, por lo que un enlace con tráfico entrante constante nunca notaba un ping sin respuesta y podía permanecer bloqueado indefinidamente. Los plazos de ping y reconocimiento también seguían el reloj de pared, por lo que un paso del reloj causaba un tiempo de espera de ping falso o una detección retrasada, y en placas sin un RTC los reconocimientos nunca expiraban antes de la primera sincronización NTP. Las fechas límite ahora usan un reloj monótono y se detecta una conexión inactiva 60 segundos después de un ping sin respuesta (#24427, @stelfrag)
  • El HTTPS client del agente para Netdata Cloud ahora verifica estrictamente los tamaños de los fragmentos de las respuestas fragmentadas y limita dichas respuestas a 1 MiB. Un tamaño de fragmento mal formado o muy grande podría hacer que el Agente salga mientras le asigna memoria (#24483, @stelfrag)
  • Se corrigieron fallas de uso después de la liberación cuando netdatacli remove-stale-node o la limpieza de host huérfano y efímero eliminaban un host que todavía estaba en uso, ya sea porque un niño se reconectaba a él o por un complemento que lo tenía seleccionado como nodo virtual. A un niño que se vuelve a conectar durante una eliminación ahora se le pide que vuelva a intentarlo, y un nodo virtual seleccionado por un complemento se informa como en línea y se deja solo (#24353, @stelfrag)
  • Se eliminó la opción [stream] parent using h2o. El servidor web h2o se eliminó en v2.7.0 y, desde v2.8.0, un niño con esta opción habilitada fallaba en cada intento de conexión con su padre. Un stream.conf que aún lo configura se acepta y se ignora la opción (#24426, @stelfrag)

Servidor web y API

  • Listas de acceso: un client cuya IP coincida con una entrada negada, como !203.0.113.7 en allow connections from = !203.0.113.7 *, ahora se deniega sin que su nombre de host se compare con la lista. Esto se aplica a todas las listas de acceso en netdata.conf cuando las comprobaciones de DNS están habilitadas, incluido el modo predeterminado heuristic para listas con un comodín (#24404, @ArjunD3456)
  • Las URL con porcentajes de escape mal formados ahora se rechazan con HTTP 400. A % tenía que ir seguido de dos dígitos hexadecimales, pero no se verificó, y una URL que no se pudo decodificar se entregó usando la parte decodificada hasta el momento, por lo que /api/v1/info%zz se respondió como /api/v1/info. Una solicitud que contiene un literal % que no va seguido de dos dígitos hexadecimales, como ?x=100%, ahora obtiene 400 (#24248, @stelfrag)
  • La clave MCP API y la clave de administración API ahora se comparan en tiempo constante, por lo que el tiempo de respuesta ya no revela qué tan cerca está una clave adivinada (#24418, @ArjunD3456)
  • MCP: Los lotes JSON-RPC están limitados a 64 solicitudes y 16 MiB de respuestas, y los mensajes WebSocket a 1 MiB, lo mismo que las solicitudes HTTP. Las solicitudes cuyo id no sea una cadena, un número o un valor nulo se rechazan (#24425, @stelfrag)
  • X-Forwarded-For: el Agente ahora conserva solo la primera dirección del encabezado, y solo cuando es una dirección IPv4 o IPv6 válida. Esta es la dirección client reenviada que se muestra en el registro de acceso y en las entradas de auditoría de cambios de configuración dinámica. Otros valores, como unknown, se eliminan (#24452, @ArjunD3456)
  • Registro: la identidad netdata_registry_id ahora se lee solo desde el encabezado Cookie, no desde ningún otro lugar de la solicitud, como la cadena de consulta. Esto afecta sólo a los Agentes con el registro habilitado, que está desactivado de forma predeterminada (#24494, @ArjunD3456)
  • Reclamación: una solicitud a /api/v2/claim o /api/v3/claim con una clave incorrecta ya no regenera la impugnación de reclamación, por lo que no puede interrumpir una reclamación que esté realizando un administrador. El desafío aún se regenera al inicio y después de un reclamo con una clave válida (#24531, @stelfrag)

Base de datos

  • Se corrigieron bloqueos de SQLite en todo el Agente. Se mantuvo un bloqueo global alrededor de las llamadas SQLite, por lo que una declaración lenta bloqueó todos los subprocesos que usaban SQLite, no solo aquellos que usaban la misma conexión de base de datos (#24099, @stelfrag)

  • La corrupción de la base de datos de metadatos que aparece mientras el Agente se está ejecutando ahora está marcada para recuperación en la primera consulta fallida, en lugar de solo en un apagado limpio o nunca después de un bloqueo. Las estadísticas de consultas SQLite ya no cuentan un reintento ocupado que luego tuvo éxito como una consulta fallida (#24225, @stelfrag)

  • Los padres que utilizan los modos de almacenamiento ram o alloc ya no cambian el historial transmitido y replicado de sus hijos después de un intervalo. Cada brecha movió todos los valores anteriores un intervalo antes y exageró la retención en un intervalo (#24434, @stelfrag)

  • dbengine ahora carga sólo archivos de datos con el nombre exacto que escribe. Se cargó una copia como datafile-1-0000000001.ndf.bak por segunda vez junto con el archivo real, y un datafile-2-*.ndf perdido detuvo el Agente al inicio. Otros nombres ahora se reportan como archivos desconocidos y se omiten (#24436, @stelfrag)

  • Se corrigieron fallas cuando la limpieza de gráficos obsoletos liberaba un gráfico, o sus etiquetas, mientras las búsquedas de variables de salud, Prometheus exportación, alertas y solicitudes o consultas de contexto API todavía lo estaban leyendo. Estos incluyen el Agente que sale de una asignación de gran tamaño (#24466, #24474, @stelfrag)

  • dbengine: el Agente ya no se bloquea al inicio cuando no se puede crear el directorio de un nivel o no se puede iniciar su hilo de inicialización. Un nivel faltante por encima del nivel 0 ahora deja al Agente ejecutándose con los niveles inferiores, y un nivel faltante 0 detiene el inicio con un error (#24435, @stelfrag)

Consultas

  • Se corrigió una falla en las correlaciones métricas y otras consultas de ponderaciones en dos o más nodos en Agentes sin un nivel dbengine, como un Padre que usa los modos de almacenamiento ram o alloc. Dichos agentes ahora procesan los nodos uno a la vez (#24433, @stelfrag)
  • La sección summary.nodes[] de respuestas a consultas ahora incluye la hora de consulta del último nodo, que faltaba. Con options=percentage, la tasa de anomalías de la vista de dimensiones ya no está inflada. Las matrices chart_labels de /api/v1/data ahora tienen una entrada por dimensión, con null donde un gráfico carece de la etiqueta (#24460, #24474, @stelfrag).

Aprendizaje automático

  • [ml] dimension anomaly score threshold ahora está limitado de 0.01 a 1.00, con una advertencia en el registro cuando se cambia el valor configurado. Se aceptaron valores hasta 5.00, pero cualquier valor superior a 1.00 desactivó silenciosamente la detección de anomalías, porque la puntuación de anomalía de un modelo no puede exceder 100. Dichos valores ahora se ejecutan en 1.00, la configuración menos sensible (#24499, @stelfrag)

Coleccionistas

  • ebpf.plugin y ebpf-go.plugin están instalados con setuid root. Cuando se ejecutan con privilegios elevados, ahora ignoran las variables de entorno NETDATA_*_DIR y usan los directorios de complementos, configuración y registros con los que fueron creados. Las instalaciones estándar no se ven afectadas. Una anulación de [directories] en netdata.conf que apunta estos directorios a otra parte ya no llega a los complementos de eBPF, que registran una línea para cada variable ignorada (#24412, @stelfrag)
  • Redfish: ahora se recopilan los puertos de red del administrador expuestos como estándar. Los recursos del puerto, incluido el estado y la velocidad del enlace. Fueron rechazados, dejando la colección permanentemente parcial (#24270, @ilyam8)
  • PAN-OS: panos.ipsec.tunnels ahora cuenta los túneles IPsec establecidos en lugar de informar los configurados, y un túnel con SA superpuestas durante la recodificación cuenta una vez. La vida útil restante de SA ahora informa la vida útil más larga válida de un túnel en lugar de un valor variable o sumado (#24385, @macmandr197)
  • go.d.plugin: se corrigió que los recopiladores como Cato Networks fallaran en un ciclo de recopilación con un conflicto de alcance del host cuando los metadatos de un host cambiaban mientras su identidad permanecía igual (#24415, @ktsaou)
  • Cato Networks: la función de topología ahora conecta cada sitio a sus dispositivos, mantiene cada túnel WAN observado en lugar de fusionar los paralelos y marca los túneles como conectados, desconectados o desconocidos. Los sitios, dispositivos y túneles contienen más detalles para la resolución de problemas, como roles de HA, pérdida, fluctuación, mediciones de última milla y sesiones de BGP, y el gráfico señala cuando faltan inventario, métricas o datos de BGP. El recopilador ahora usa Cato SDK v1.1.0 (#24413, @ktsaou, #24362, @ilyam8)
  • ebpf.plugin: el número de PID rastreados en ebpf.monitoring_pid ya no sigue creciendo en hosts con procesos de corta duración. Un proceso que salió antes de que se leyera su entrada /proc fue liberado sin ser restado (#24423, @stelfrag)
  • statsd.plugin: con [statsd] set charts as obsolete after habilitado (desactivado de forma predeterminada), el Agente ya no falla la primera vez que se elimina una métrica inactiva. La eliminación tampoco filtra los valores de la métrica y se conservan las métricas utilizadas por los gráficos sintéticos. El recuento de gráficos privados ya no se ajusta y bloquea cada nuevo gráfico privado (#24440, @stelfrag)
  • Nodos virtuales: vuelve a funcionar el tiempo de inactividad establecido por un recopilador, como el que utilizan los dispositivos SNMP. Se descartó cuando se definió el nodo, por lo que un nodo virtual nunca se desconecta después de que su recopilador dejó de informarlo. Un nodo virtual tomado nuevamente por su recopilador local después de que se detuviera una copia transmitida ahora tiene sus comprobaciones de estado y su funcionamiento normal restaurados (#24495, @ilyam8)
  • SNMP: ahora falla una encuesta en la que el dispositivo no respondió ninguna solicitud. Las estadísticas de perfil creadas a partir de metadatos almacenados en caché aún se reportaban para el nodo virtual del dispositivo, manteniéndolo activo después de que se detuvieran sus mediciones (#24497, @ilyam8)
  • PowerStore: los gráficos de rendimiento, Ethernet y capacidad ahora muestran los valores que informa la matriz. El recopilador lee los nombres de los campos de las muestras sin procesar, mientras que los resúmenes diarios y de cinco minutos que solicita usan nombres diferentes, por lo que estos gráficos mostraban ceros o faltaban. La CPU ahora muestra la utilización máxima del intervalo como porcentaje y el recuento promedio de inicios de sesión mantiene sus fracciones (#24448, @ilyam8)
  • log2journal: Las líneas JSON que terminan dentro de una barra invertida ahora se rechazan en lugar de analizarse con bytes más allá del final de la línea (#24365, @ArjunD3456)
  • log2journal: un grupo con nombre de un patrón PCRE2 o regla de reescritura que no participa en una coincidencia, como un grupo opcional, ya no hace que el analizador lea un byte antes de su búfer. La salida no cambia (#24380, @ArjunD3456)
  • log2journal: se corrigieron varios problemas de análisis y salida de JSON. Los números muy largos con un exponente podrían desbordar el búfer numérico o bloquear el proceso, los escapes \u000a y \u0009 eliminaron el resto del valor, los sustitutos no emparejados produjeron UTF-8 no válido y una línea que no se pudo analizar dejó sus campos en la siguiente línea tanto en el modo JSON como en el modo logfmt. Un --inject ahora reemplaza un valor leído del registro en lugar de agregarlo, y una reescritura que hace referencia a su propia clave lee el valor original (#24443, @stelfrag)
  • go.d.plugin: se corrigieron dos carreras de apagado en el administrador de trabajos. Un apagado o reinicio fallido podría esperar hasta la fecha límite en lugar de finalizar, y una solicitud de función que ya había sido aceptada podría reportarse como rechazada porque el complemento se estaba deteniendo (#24491, @ilyam8)
  • Descubrimiento de servicios go.d.plugin: los nombres y direcciones descubiertos ahora se codifican como datos en los trabajos que generan las reglas de descubrimiento. Se insertaron en el YAML como texto, por lo que una dirección IPv6 podría hacer que un trabajo no se pudiera analizar y un nombre como on se convirtiera en booleano. Las reglas estándar utilizan una nueva plantilla auxiliar job, por ejemplo {{ job "name" .Name "url" .Address }}, que las reglas personalizadas también pueden usar. Las reglas existentes y las configuraciones dinámicas guardadas siguen funcionando (#24469, @ilyam8)
  • go.d.plugin: los registros y errores del recopilador, incluidos los devueltos por comprobaciones de configuración dinámica, ya no incluyen contenido sin procesar de los archivos que lee un recopilador, como muestras de registros, líneas de configuración o certificados. En su lugar, nombran el archivo, la línea, el campo y el motivo, por lo que algunos mensajes son menos detallados (#24496, @ilyam8)
  • go.d.plugin y ibm.d.plugin: las respuestas HTTP leídas por los recopiladores, incluidos los puntos finales Prometheus y OpenMetrics, ahora están limitadas a 64 MiB, medidos después de la descompresión de gzip. Una respuesta más grande falla en la colección en lugar de hacer crecer la memoria sin límites. HTTPCheck informa una respuesta como bad_content; utilice un punto final más pequeño para las comprobaciones de estado (#24490, @ilyam8)
  • Trampas SNMP y S3: los archivos de estado que guardan estos recopiladores ahora se leen y escriben de forma segura. Los enlaces simbólicos y los archivos especiales se rechazan, y un archivo temporal dejado por una falla ya no bloquea escrituras posteriores (#24462, @ilyam8)
  • Se corrigieron problemas de metadatos y alertas de stock: la alerta Portcheck portcheck_connection_fails ya no busca una dimensión que no existe, los metadatos Elasticsearch, OpenSearch y Unbound ahora coinciden con los gráficos que describen, y los gráficos de los módulos Unbound y ethtool se titulan "Módulo ..." nuevamente en lugar de "CollectorV1 ..." (#24308, @ilyam8)

Funciones

  • La función de progreso ahora muestra como errores las llamadas API que fallaron con un error del servidor. Tenían un estilo que el panel no reconoce y parecían llamadas exitosas (#24185, @ilyam8)

Agente

  • Las etiquetas de host ahora se leen desde el archivo de configuración que cargó el Agente, incluido uno proporcionado con -c, al inicio y en netdatacli reload-labels. Las etiquetas eliminadas de ese archivo también se eliminan al recargar (#24117, @stelfrag)
  • Los informes de fallos ahora incluyen un seguimiento de la pila para SIGABRT generado fuera del manejo de errores fatales del propio Agente (#24094, @stelfrag)
  • En compilaciones de macOS y Linux sin libbacktrace, el Agente guarda nuevamente su archivo de estado cuando falla, por lo que el próximo inicio informa el motivo y la señal de salida (#24345, @stelfrag)
  • Se corrigió un problema de uso después de la liberación al apagar en Padres con niños archivados, cuando la carga de sus contextos duró más que la espera de apagado (#24492, @stelfrag)
  • Se corrigió que los mensajes de registro con velocidad limitada se emitieran con más frecuencia que su límite cuando varios subprocesos se registraban a través del mismo limitador a la vez (#24249, @stelfrag)
  • Cuando [db] update every está por encima de 3600, la advertencia ahora informa el valor al que se fijó (3600) en lugar de 1. La fijación en sí ya era correcta (#24378, @stelfrag)
  • Cuando un recopilador intenta agregar una dimensión sin una identificación, el error fatal ahora lo dice, en lugar de culpar a la destrucción del índice de dimensiones del gráfico (#24528, @stelfrag)

Instalación y embalaje

  • El instalador y el actualizador ahora tratan el estado de salida de curl 56, que algunas versiones de curl devuelven en caso de errores de protocolo, como un error de descarga, como los estados de salida 22 y 78 (#24276, @Ferroin)
  • Los paquetes de Windows ahora incluyen paquetes MSYS2 actualizados además de la base MSYS2 incluida, incluidos OpenSSL 3.6.5, curl 8.23.0 y msys2-runtime 3.6.11. Cada actualización está fijada por URL y suma de verificación, y la base de datos del paquete incluido coincide con los archivos que se envían (#24473, @stelfrag)
  • Cuando la compilación desde el código fuente necesita una cadena de herramientas Go y no hay ninguna instalada, el instalador ahora descarga Go 1.27.3 en lugar de 1.27.0. Vaya a 1.27.0 y luego siga siendo compatible (#24411, @ilyam8)

netdata v2.12.3

Release notes

Netdata v2.12.3 is a patch release to address issues discovered since v2.12.2.

This release makes the Agent detect a dead Netdata Cloud connection even while traffic keeps flowing, fixes use-after-free crashes when a stale node is removed while a child or plugin is still using it, stops children configured with parent using h2o from crashing on every connection, makes a negated IP in an access list take precedence over hostname matching, rejects malformed percent escapes in URLs, bounds MCP batch requests, removes global SQLite stalls, fixes crashes when obsolete charts are cleaned up while they are still being read, keeps the Agent from hanging at startup when a dbengine tier cannot be created, keeps Parents using the ram or alloc storage modes from shifting their children's history after a gap and from crashing on multi-node metric correlations, lets SNMP and other virtual nodes go offline again when their collector stops reporting them, makes PowerStore charts show the values the array reports instead of zeros, makes the eBPF plugins ignore directory overrides from the environment when they run with elevated privileges, and reloads host labels from the configuration file the Agent actually loaded.

Streaming and Netdata Cloud

  • Fixed the MQTT keepalive of the Cloud connection. It was only checked when the connection was idle, so a link with steady inbound traffic never noticed an unanswered ping and could stay stalled indefinitely. The ping and acknowledgement deadlines also followed the wall clock, so a clock step caused a false ping timeout or delayed detection, and on boards without an RTC acknowledgements never timed out before the first NTP sync. Deadlines now use a monotonic clock, and a dead connection is detected 60 seconds after an unanswered ping (#24427, @stelfrag)
  • The Agent's HTTPS client for Netdata Cloud now checks the chunk sizes of chunked responses strictly and caps such responses at 1 MiB. A malformed or very large chunk size could make the Agent exit while allocating memory for it (#24483, @stelfrag)
  • Fixed use-after-free crashes when netdatacli remove-stale-node or the orphan and ephemeral host cleanup removed a host that was still in use, either by a child reconnecting to it or by a plugin that had it selected as a virtual node. A child that reconnects during a removal is now asked to retry, and a virtual node selected by a plugin is reported as online and left alone (#24353, @stelfrag)
  • Removed the [stream] parent using h2o option. The h2o web server was removed in v2.7.0, and since v2.8.0 a child with this option enabled crashed on every connection attempt to its Parent. A stream.conf that still sets it is accepted and the option is ignored (#24426, @stelfrag)

Web server and APIs

  • Access lists: a client whose IP matches a negated entry, such as !203.0.113.7 in allow connections from = !203.0.113.7 *, is now denied without its hostname being checked against the list. This applies to every access list in netdata.conf when DNS checks are enabled, including the default heuristic mode for lists with a wildcard (#24404, @ArjunD3456)
  • URLs with malformed percent escapes are now rejected with HTTP 400. A % had to be followed by two hex digits but was not checked, and a URL that failed to decode was served using the part decoded so far, so /api/v1/info%zz was answered as /api/v1/info. A request containing a literal % that is not followed by two hex digits, such as ?x=100%, now gets 400 (#24248, @stelfrag)
  • The MCP API key and the management API key are now compared in constant time, so response timing no longer reveals how close a guessed key is (#24418, @ArjunD3456)
  • MCP: JSON-RPC batches are limited to 64 requests and 16 MiB of responses, and WebSocket messages to 1 MiB, the same as HTTP requests. Requests whose id is not a string, number or null are rejected (#24425, @stelfrag)
  • X-Forwarded-For: the Agent now keeps only the first address of the header, and only when it is a valid IPv4 or IPv6 address. This is the forwarded client address shown in the access log and in the audit entries of dynamic configuration changes. Other values, such as unknown, are dropped (#24452, @ArjunD3456)
  • Registry: the netdata_registry_id identity is now read only from the Cookie header, not from anywhere else in the request, such as the query string. This affects only Agents with the registry enabled, which is off by default (#24494, @ArjunD3456)
  • Claiming: a request to /api/v2/claim or /api/v3/claim with a wrong key no longer regenerates the claim challenge, so it cannot interrupt a claim an administrator is making. The challenge is still regenerated at startup and after a claim with a valid key (#24531, @stelfrag)

Database

  • Fixed SQLite stalls across the Agent. A global lock was held around SQLite calls, so one slow statement blocked every thread using SQLite, not only those using the same database connection (#24099, @stelfrag)

  • Corruption of the metadata database that appears while the Agent is running is now marked for recovery on the first failing query, instead of only at a clean shutdown or never after a crash. The SQLite query statistics no longer count a busy retry that later succeeded as a failed query (#24225, @stelfrag)

  • Parents using the ram or alloc storage modes no longer shift their children's streamed and replicated history after a gap. Every gap moved all older values one interval earlier and overstated retention by one interval (#24434, @stelfrag)

  • dbengine now loads only datafiles with the exact name it writes. A copy such as datafile-1-0000000001.ndf.bak was loaded a second time alongside the real file, and a stray datafile-2-*.ndf stopped the Agent at startup. Other names are now reported as unknown files and skipped (#24436, @stelfrag)

  • Fixed crashes when the cleanup of obsolete charts freed a chart, or its labels, while health variable lookups, Prometheus export, alert and context API requests or queries were still reading it. These include the Agent exiting on an allocation of a huge size (#24466, #24474, @stelfrag)

  • dbengine: the Agent no longer hangs at startup when the directory of a tier cannot be created or its initialization thread cannot start. A missing tier above tier 0 now leaves the Agent running with the tiers below it, and a missing tier 0 stops startup with an error (#24435, @stelfrag)

Queries

  • Fixed a crash in metric correlations and other weights queries over two or more nodes on Agents without a dbengine tier, such as a Parent using the ram or alloc storage modes. Such Agents now process the nodes one at a time (#24433, @stelfrag)
  • The summary.nodes[] section of query responses now includes the query time of the last node, which was missing. With options=percentage, the anomaly rate of the dimensions view is no longer inflated. The chart_labels arrays of /api/v1/data now have one entry per dimension, with null where a chart lacks the label (#24460, #24474, @stelfrag)

Machine learning

  • [ml] dimension anomaly score threshold is now limited to 0.01 to 1.00, with a warning in the log when the configured value is changed. Values up to 5.00 were accepted, but anything above 1.00 silently turned off anomaly detection, because a model's anomaly score cannot exceed 100. Such values now run at 1.00, the least sensitive setting (#24499, @stelfrag)

Collectors

  • ebpf.plugin and ebpf-go.plugin are installed setuid root. When they run with elevated privileges, they now ignore the NETDATA_*_DIR environment variables and use the plugin, configuration and log directories they were built with. Standard installations are not affected. A [directories] override in netdata.conf that points these directories elsewhere no longer reaches the eBPF plugins, which log one line for each ignored variable (#24412, @stelfrag)
  • Redfish: manager network ports exposed as standard Port resources are now collected, including their link state and speed. They were rejected, leaving the collection permanently partial (#24270, @ilyam8)
  • PAN-OS: panos.ipsec.tunnels now counts the established IPsec tunnels instead of reporting the configured ones, and a tunnel with overlapping SAs during rekeying counts once. The remaining SA lifetime now reports the longest valid lifetime of a tunnel instead of a varying or summed value (#24385, @macmandr197)
  • go.d.plugin: fixed collectors such as Cato Networks failing a collection cycle with a host scope conflict when a host's metadata changed while its identity stayed the same (#24415, @ktsaou)
  • Cato Networks: the topology Function now connects each site to its devices, keeps every observed WAN tunnel instead of merging parallel ones, and marks tunnels as connected, disconnected or unknown. Sites, devices and tunnels carry more detail for troubleshooting, such as HA roles, loss, jitter, last-mile measurements and BGP sessions, and the graph notes when inventory, metrics or BGP data are missing. The collector now uses Cato SDK v1.1.0 (#24413, @ktsaou, #24362, @ilyam8)
  • ebpf.plugin: the number of tracked PIDs in ebpf.monitoring_pid no longer keeps growing on hosts with short-lived processes. A process that exited before its /proc entry was read was released without being subtracted (#24423, @stelfrag)
  • statsd.plugin: with [statsd] set charts as obsolete after enabled (off by default), the Agent no longer crashes the first time an idle metric is removed. Removal also no longer leaks the metric's values, and metrics used by synthetic charts are kept. The private chart count no longer wraps around and blocks every new private chart (#24440, @stelfrag)
  • Virtual nodes: the inactivity timeout set by a collector, such as the one SNMP devices use, works again. It was discarded when the node was defined, so a virtual node never went offline after its collector stopped reporting it. A virtual node taken over again by its local collector after a streamed copy of it stops now has its health checks and normal operation restored (#24495, @ilyam8)
  • SNMP: a poll in which the device answered no request now fails. Profile statistics built from cached metadata were still reported for the device's virtual node, keeping it active after its measurements had stopped (#24497, @ilyam8)
  • PowerStore: performance, Ethernet and capacity charts now show the values the array reports. The collector read the field names of raw samples, while the five-minute and daily rollups it requests use different names, so these charts showed zeros or were missing. CPU now shows the peak utilization of the interval as a percentage, and average login counts keep their fractions (#24448, @ilyam8)
  • log2journal: JSON lines that end inside a backslash escape are now rejected instead of being parsed with bytes from beyond the end of the line (#24365, @ArjunD3456)
  • log2journal: a named group of a PCRE2 pattern or rewrite rule that does not take part in a match, such as an optional group, no longer makes the parser read one byte before its buffer. Output does not change (#24380, @ArjunD3456)
  • log2journal: fixed several JSON parsing and output issues. Very long numbers with an exponent could overflow the number buffer or crash the process, \u000a and \u0009 escapes dropped the rest of the value, unpaired surrogates produced invalid UTF-8, and a line that failed to parse left its fields to the next line in both JSON and logfmt mode. An --inject now replaces a value read from the log instead of being appended to it, and a rewrite that refers to its own key reads the original value (#24443, @stelfrag)
  • go.d.plugin: fixed two shutdown races in the job manager. A shutdown or failed restart could wait until its deadline instead of finishing, and a Function request that had already been accepted could be reported as rejected because the plugin was stopping (#24491, @ilyam8)
  • go.d.plugin service discovery: discovered names and addresses are now encoded as data in the jobs that discovery rules generate. They were inserted into the YAML as text, so an IPv6 address could make a job fail to parse and a name such as on became a boolean. Stock rules use a new job template helper, for example {{ job "name" .Name "url" .Address }}, which custom rules can use too. Existing rules and saved dynamic configurations keep working (#24469, @ilyam8)
  • go.d.plugin: collector logs and errors, including those returned by dynamic configuration checks, no longer include raw content from the files a collector reads, such as log samples, configuration lines or certificates. They name the file, line, field and reason instead, so some messages are less detailed (#24496, @ilyam8)
  • go.d.plugin and ibm.d.plugin: HTTP responses read by collectors, including Prometheus and OpenMetrics endpoints, are now limited to 64 MiB, measured after gzip decompression. A larger response fails the collection instead of growing memory without bound. HTTPCheck reports such a response as bad_content; use a smaller endpoint for health checks (#24490, @ilyam8)
  • SNMP traps and S3: the state files these collectors keep are now read and written safely. Symlinks and special files are rejected, and a temporary file left by a crash no longer blocks later writes (#24462, @ilyam8)
  • Fixed stock alert and metadata issues: the Portcheck portcheck_connection_fails alert no longer looks up a dimension that does not exist, the Elasticsearch, OpenSearch and Unbound metadata now match the charts they describe, and the Unbound and ethtool module charts are titled "Module ..." again instead of "CollectorV1 ..." (#24308, @ilyam8)

Functions

  • The progress Function now shows API calls that failed with a server error as errors. They were styled with a severity the dashboard does not recognize and looked like successful calls (#24185, @ilyam8)

Agent

  • Host labels are now read from the configuration file the Agent loaded, including one given with -c, at startup and on netdatacli reload-labels. Labels removed from that file are also removed on reload (#24117, @stelfrag)
  • Crash reports now include a stack trace for SIGABRT raised outside the Agent's own fatal error handling (#24094, @stelfrag)
  • On macOS and Linux builds without libbacktrace, the Agent again saves its status file when it crashes, so the next start reports the exit reason and signal (#24345, @stelfrag)
  • Fixed a use-after-free at shutdown on Parents with archived children, when loading their contexts outlasted the shutdown wait (#24492, @stelfrag)
  • Fixed rate-limited log messages being emitted more often than their limit when several threads logged through the same limiter at once (#24249, @stelfrag)
  • When [db] update every is above 3600, the warning now reports the value it was clamped to (3600) instead of 1. The clamp itself was already correct (#24378, @stelfrag)
  • When a collector tries to add a dimension without an id, the fatal error now says so, instead of blaming the destruction of the chart's dimension index (#24528, @stelfrag)

Installation and packaging

  • The installer and updater now treat curl exit status 56, which some curl versions return on protocol errors, as a download failure, like exit statuses 22 and 78 (#24276, @Ferroin)
  • Windows packages now include updated MSYS2 packages on top of the bundled MSYS2 base, including OpenSSL 3.6.5, curl 8.23.0 and msys2-runtime 3.6.11. Each update is pinned by URL and checksum, and the bundled package database matches the files that ship (#24473, @stelfrag)
  • When building from source needs a Go toolchain and none is installed, the installer now downloads Go 1.27.3 instead of 1.27.0. Go 1.27.0 and later remain supported (#24411, @ilyam8)
