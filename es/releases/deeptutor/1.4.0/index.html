#DeepTutor v1.4.0

DeepTutor v1.4.0 Release Note

Fecha de lanzamiento: 2026.05.22 v1.4.0 es el corte GA de la línea v1.4. Lleva el visor completo v1.4.0-beta (Modo automático, banco de trabajo de memoria de tres capas, investigación profunda agente/resolución profunda/ Pregunta, refactorización de chat de LlamaIndex, infraestructura de capacidades unificadas + i18n, fusión Visualize/Animator, nuevas herramientas de chat, configuración dividida, multiusuario endurecimiento de aislamiento y el lanzador deeptutor start / deeptutor init) y agrega un conjunto enfocado de correcciones de refuerzo del motor de agente y del tiempo de ejecución en la parte superior. Para conocer el alcance completo de la versión beta, consulte v1.4.0-beta.

Novedades desde v1.4.0-beta

Esfuerzo de razonamiento + Indicadores de pensamiento del proveedor

El motor agente ahora normaliza el "esfuerzo de razonamiento" entre proveedores en un solo lugar, en lugar de que cada tubería vuelva a derivarlo.

  • build_provider_extra_kwargs en deeptutor/core/agentic/client.py resuelve reasoning_effort contra provider_registry, asigna minimal / minimum a la forma de cable correcta (DashScope usa minimum) y enruta la intención de activación/desactivación a través de alternancias de estilo de pensamiento del proveedor: thinking_type (DeepSeek), enable_thinking (estilo Qwen) o reasoning_split. Los modelos de razonamiento conocidos por defecto son high; el La forma deepseek-v4-flash deja el pensamiento deshabilitado de forma predeterminada.
  • LLMClientConfig.reasoning_effort está conectado de extremo a extremo. los cuatro canalizaciones: chat con agentes, preguntas, investigación, resolución: pasar el enlace + esfuerzo en build_completion_kwargs, por lo que una configuración única a nivel de usuario controla el comportamiento de razonamiento entre capacidades.

Respaldo del esquema de herramientas para proveedores estrictos

Algunos proveedores compatibles con OpenAI rechazan los esquemas de llamada de funciones nativas con un error no estándar. run_labeled_step ahora detecta ese caso, tira tools / tool_choice de la solicitud, reintenta una vez y emite una advertencia evento de progreso para que el usuario sepa que la llamada se ejecutó en modo de prosa sin herramientas. El comportamiento no cambia para los proveedores que aceptan esquemas de herramientas normalmente.

Reiniciar el tiempo de ejecución del turno seguro

Un reinicio del servidor o contenedor se utiliza para dejar la fila de la base de datos por un giro en vuelo atascado en running, bloqueando el siguiente mensaje en ese sesión y dejar la interfaz de usuario suspendida en un flujo de eventos que nunca completo.

  • Detección de huérfanos — TurnRuntimeManager ahora comprueba si esto El proceso todavía posee el corredor en memoria del turno. Si no, el persistió el turno está marcado failed con "Turno interrumpido por el reinicio del servidor. Por favor, vuelva a intentar enviar su mensaje."
  • start_turn barre los turnos activos obsoletos de la sesión anterior creando un nuevo turno, para que el usuario pueda volver a intentarlo inmediatamente después de reiniciar.
  • subscribe_turn sintetiza un evento terminal error + done para el giro huérfano para que la interfaz cierre limpiamente su estado de transmisión en lugar de esperar indefinidamente.

Base frontal API - Endurecimiento del marcador de posición Docker

web/lib/api.ts cambió de detección de coincidencia exacta a detección de token de subcadena de el marcador de posición NEXT_PUBLIC_API_BASE y expone isApiBasePlaceholder() para su reutilización. Esto sobrevive a pequeños cambios en la forma del marcador de posición Docker que previamente se deslizó y produjo una página de Configuración en blanco sin error visible. El web/.env.local generado automáticamente y sin usar se envía con el Se elimina la versión beta.

Sonda de configuración LLM: copia de estado más clara

La sonda /settings/llm ahora emite un mensaje explícito de finalización del LLM básico. tuvo éxito. El chat también valida la herramienta de transmisión y proveedor compatibilidad en tiempo de ejecución." línea después de completar el humo, para que los usuarios sepan la sonda no cubre deliberadamente las rutas de transmisión/llamada de herramientas que ejercicios de chat.

CLI Chat REPL: superficie de configuración alineada con documentos

La superficie deeptutor chat REPL fue ajustada para que coincida con el público. documentos en deeptutor.info.

  • Semillas deeptutor chat --config key=value y --config-json '<json>' la configuración inicial sin ingresar primero el REPL.
  • Se aceptan /config set key value y /config set key=value; Los valores JSON ([…], {…}) se analizan correctamente a través de shlex.
  • La continuación de barra invertida le permite enviar mensajes de varias líneas en un solo turno.
  • /refs imprime una instantánea del estado estructurado (sesión, capacidad, herramientas, KB, historial, cuadernos, idioma, configuración) en lugar de una sola línea oscura.
  • deeptutor plugin info <name> ahora también devuelve cli_aliases y el Capacidad del bloque availability.

Higiene de repositorios y documentos

  • Nueva plantilla de publicación para el sitio de documentos públicos (.github/ISSUE_TEMPLATE/docs.yml).
  • AGENTS.md modernizado para reflejar el modo automático, la activación de herramientas y el etapas de capacidad actuales.
  • .gitignore cubre .playwright-cli/; rancio .playwright-cli/ capturas, .env.example_CN y DeepTutor.code-workspace eliminados.

Pruebas

  • Nuevo tests/core/test_agentic_client_provider_kwargs.py que cubre el Matriz de razonamiento-esfuerzo + proveedor-estilo de pensamiento.
  • Nuevo tests/core/test_labeled_step_tool_fallback.py ejercitando el ruta de reintento del esquema de herramientas de un extremo a otro contra un client con script.
  • tests/services/session/test_turn_runtime_subscribe.py agrega cobertura para la recuperación de turnos en ejecución huérfana tanto en subscribe como en start_turn.
  • tests/cli/test_chat_cli.py agrega pruebas de configuración/barra invertida de REPL y una Verificación del contrato de información del complemento.
  • El nuevo tests/cli/test_docs_contract.py mantiene los documentos públicos del sitio en sincronizar con la superficie CLI (enlaces + ejemplos de deeptutor …).
  • tests/scripts/test_docker_compose.py + web/tests/api-resolve-base.test.ts cubrir la nueva detección de marcador de posición.

Notas de actualización

  • Desde v1.4.0-beta: sin cita previa. PyPI se instala con pip install -U deeptutor (PyPI normaliza 1.4.0 sobre 1.4.0b0). Los usuarios de Docker tiran ghcr.io/hkuds/deeptutor:latest.
  • El esfuerzo de razonamiento ahora se lee desde LLMConfig.reasoning_effort. si previamente configuró manualmente los indicadores de pensamiento del proveedor en extra_body, el agente aún los respetará, pero la ruta recomendada es establecer reasoning_effort y deje que el motor lo mapee.
  • Reiniciar la recuperación es automático. Después de la actualización, cualquier existente Las filas de la base de datos atascadas en running debido a fallos anteriores se eliminarán. finalizará la próxima vez que se abra su sesión.
  • Limpieza de artefactos beta: web/.env.local fue generado automáticamente por el lanzador heredado y ya no es necesario. Si reconstruiste la interfaz manualmente con ese archivo, elimínelo antes de la siguiente compilación. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.4.0-beta...v1.4.0

DeepTutor v1.4.0

Highlights

  • GA feature set and upgrade path — v1.4.0 promotes the beta’s Auto Mode, three-layer Memory workbench, agentic Deep Research/Deep Solve/Question, unified capability infrastructure, and merged Visualize/Animator to GA, with runtime hardening on top. Beta users can upgrade directly with pip install -U deeptutor or pull ghcr.io/hkuds/deeptutor:latest.

  • Provider-neutral reasoning controls — Reasoning effort is now centralized in build_provider_extra_kwargs and flows through all four agentic pipelines via LLMConfig.reasoning_effort. The engine maps the setting to provider-specific thinking flags for DeepSeek, Qwen-style models, and DashScope; known reasoning models default to high, while deepseek-v4-flash disables thinking by default. Move manual extra_body thinking flags to reasoning_effort for consistent cross-provider behavior, though existing flags remain respected.

  • Tool-schema fallback with visibility — When an OpenAI-compatible provider rejects native function-calling schemas, run_labeled_step retries once without tools/tool_choice and emits a warning progress event. This prevents hard failures, but the model then operates in tool-less prose mode—validate outputs or switch providers if your workflow depends on structured tool execution.

  • Restart-safe turn lifecycle — Orphaned running turns are now marked failed, swept before the next turn starts, and closed on the frontend with synthesized terminal error and done events. Existing rows stuck from earlier crashes recover automatically when their session is opened, eliminating indefinitely hanging streams; interrupted work still needs a retry.

  • Docker API-base hardening — Frontend placeholder detection now tolerates changes to the Docker-injected NEXT_PUBLIC_API_BASE token shape, preventing blank Settings pages caused by missed placeholders. Delete the beta-generated web/.env.local before manually rebuilding the frontend; the legacy launcher no longer needs it.

  • CLI configuration and diagnostics — deeptutor chat can seed configuration through --config/--config-json, while /config set accepts both argument forms and correctly parses JSON values. /refs and plugin info now expose structured runtime and capability state. The LLM probe explicitly states that a successful completion does not validate streaming or provider tool compatibility, so those paths still require runtime testing.

  • Breaking changes — None; the beta-to-GA upgrade is drop-in.

DeepTutor v1.4.0 Release Notes

Release Date: 2026.05.22

v1.4.0 is the GA cut of the v1.4 line. It carries the full v1.4.0-beta scope (Auto Mode, three-layer Memory workbench, agentic Deep Research / Deep Solve / Question, LlamaIndex chat refactor, unified capabilities infrastructure + i18n, Visualize/Animator merge, new chat tools, settings split, multi-user isolation hardening, and the deeptutor start / deeptutor init launcher) and adds a focused set of agent-engine and runtime hardening fixes on top. For the full beta scope see v1.4.0-beta.

What's New Since v1.4.0-beta

Reasoning Effort + Provider Thinking Flags

The agentic engine now normalizes "reasoning effort" across providers in one place, instead of each pipeline re-deriving it.

  • build_provider_extra_kwargs in deeptutor/core/agentic/client.py resolves reasoning_effort against provider_registry, maps minimal / minimum to the right wire shape (DashScope uses minimum), and routes the on/off intent through provider thinking-style toggles — thinking_type (DeepSeek), enable_thinking (Qwen-style), or reasoning_split. Known reasoning models default to high; the deepseek-v4-flash shape gets thinking disabled by default.
  • LLMClientConfig.reasoning_effort is plumbed end-to-end. All four pipelines — agentic chat, question, research, solve — pass the binding + effort into build_completion_kwargs, so a single user-level setting controls reasoning behavior across capabilities.

Tool-Schema Fallback For Strict Providers

Some OpenAI-compatible providers reject native function-calling schemas with a non-standard error. run_labeled_step now detects that case, strips tools / tool_choice from the request, retries once, and emits a warning progress event so the user knows the call ran in tool-less prose mode. Behavior is unchanged for providers that accept tool schemas normally.

Restart-Safe Turn Runtime

A server or container restart used to leave the database row for an in-flight turn stuck on running, blocking the next message in that session and leaving the UI hanging on an event stream that would never complete.

  • Orphan detection — TurnRuntimeManager now checks whether this process still owns the turn's in-memory runner. If not, the persisted turn is marked failed with "Turn interrupted by server restart. Please retry your message."
  • start_turn sweeps stale active turns for the session before creating a new turn, so the user can immediately retry after a restart.
  • subscribe_turn synthesizes a terminal error + done event for the orphaned turn so the frontend cleanly closes its streaming state instead of waiting indefinitely.

Frontend API Base — Docker Placeholder Hardening

web/lib/api.ts switched from exact-match to substring-token detection of the NEXT_PUBLIC_API_BASE placeholder, and exposes isApiBasePlaceholder() for reuse. This survives small changes to the Docker placeholder shape that previously slipped through and produced a blank Settings page with no visible error. The unused auto-generated web/.env.local shipped with the beta is removed.

LLM Config Probe — Clearer Status Copy

The /settings/llm probe now emits an explicit "Basic LLM completion succeeded. Chat additionally validates streaming and provider tool compatibility at runtime." line after the smoke completion, so users know the probe deliberately doesn't cover the streaming / tool-call paths that chat exercises.

CLI Chat REPL — Config Surface Aligned With Docs

The deeptutor chat REPL surface was tightened so it matches the public docs at deeptutor.info.

  • deeptutor chat --config key=value and --config-json '<json>' seed the initial config without entering the REPL first.
  • /config set key value and /config set key=value are both accepted; JSON values ([…], {…}) are parsed correctly via shlex.
  • Backslash-continuation lets you send multi-line prompts in one turn.
  • /refs prints a structured state snapshot (session, capability, tools, KB, history, notebooks, language, config) instead of a single dim line.
  • deeptutor plugin info <name> now also returns cli_aliases and the capability availability block.

Repo & Docs Hygiene

  • New issue template for the public docs site (.github/ISSUE_TEMPLATE/docs.yml).
  • AGENTS.md modernized to reflect Auto Mode, tool gating, and the current capability stages.
  • .gitignore covers .playwright-cli/; stale .playwright-cli/ captures, .env.example_CN, and DeepTutor.code-workspace removed.

Tests

  • New tests/core/test_agentic_client_provider_kwargs.py covering the reasoning-effort + provider thinking-style matrix.
  • New tests/core/test_labeled_step_tool_fallback.py exercising the tool-schema retry path end-to-end against a scripted client.
  • tests/services/session/test_turn_runtime_subscribe.py adds coverage for orphan-running-turn recovery on both subscribe and start_turn.
  • tests/cli/test_chat_cli.py adds REPL config/backslash tests and a plugin-info contract check.
  • New tests/cli/test_docs_contract.py keeps the public site docs in sync with the CLI surface (links + deeptutor … examples).
  • tests/scripts/test_docker_compose.py + web/tests/api-resolve-base.test.ts cover the new placeholder detection.

Upgrade Notes

  • From v1.4.0-beta: drop-in. PyPI installs with pip install -U deeptutor (PyPI normalizes 1.4.0 over 1.4.0b0). Docker users pull ghcr.io/hkuds/deeptutor:latest.
  • Reasoning effort is now read from LLMConfig.reasoning_effort. If you previously set provider thinking flags manually in extra_body, the agent will still respect them, but the recommended path is to set reasoning_effort and let the engine map it.
  • Restart recovery is automatic. After upgrading, any existing database rows stuck on running from previous crashes will be finalized the next time their session is opened.
  • Beta artifact cleanup: web/.env.local was auto-generated by the legacy launcher and is no longer needed. If you rebuilt the frontend manually with that file, delete it before the next build.
