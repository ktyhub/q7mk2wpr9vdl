#DeepTutor v1.1.1

DeepTutor v1.1.1 Release Note

Fecha de lanzamiento: 2026.04.17

Destacados

Trampilla de escape universal "Responder ahora": rutas rápidas por capacidad

Se promovió "Responder ahora" de una opción de solo chat a una interrupción universal que respeta la forma de salida de cada capacidad. Un nuevo asistente compartido deeptutor/capabilities/_answer_now.py proporciona la puerta (extract_answer_now_context) y el resumen de seguimiento fácil de usar, y cada capacidad integrada ahora posee su propia rama de ruta rápida en la parte superior de run():

  • chat: sintetiza la respuesta de reducción final a partir del seguimiento parcial (comportamiento existente).
  • deep_solve: salta la planificación + razonamiento, salta directamente al escritor.
  • deep_question: omita ideas/plantillas, emita el cuestionario completo JSON en una llamada estructurada (aún representada por QuizViewer).
  • deep_research: omita reformular/descomponer/investigar, escriba el informe directamente a partir de la evidencia acumulada.
  • math_animator: omite análisis + diseño + resumen pero mantiene la generación de código + renderizado, para que el usuario aún obtenga una animación real.
  • visualize: omite análisis + revisión, emite el código renderizable final en una llamada estructurada. Cada ruta rápida conserva el mismo sobre de resultados que la canalización normal (por lo que los visores Quiz/MathAnimator/Visualización se muestran sin cambios) y antepone un aviso > ⚡ Skipped X stage(s) para que los usuarios sepan que fue la salida anticipada con el mejor esfuerzo. El orquestador ya no redirige answer_now a chat; ahora mantiene active_capability y solo vuelve a chat si la capacidad seleccionada originalmente se ha eliminado del registro. La interfaz coincide: handleAnswerNow ya no anula la capacidad de la instantánea, y un componente AnswerNowRow protegido de un solo disparo representa la acción en línea debajo del panel de seguimiento de transmisión.

Coautor: Sincronización de desplazamiento anclado en línea y división redimensionable

La página Co-Writer eligió un divisor arrastrable entre el editor y los paneles de vista previa (con una proporción persistente en localStorage) y una verdadera sincronización de desplazamiento bidireccional que sobrevive a las líneas ajustadas. Cada bloque de vista previa ahora lleva un atributo data-source-line que apunta a su línea inicial en la fuente de rebajas (proporcionada por las posiciones AST de los comentarios); en el lado del editor, un elemento espejo oculto imita la geometría envolvente del área de texto para que podamos leer el píxel real-y de cada línea fuente. Con ambos lados expresados ​​como coordenadas de píxeles, la sincronización se convierte en una única interpolación lineal por partes en cualquier dirección, con un caché por línea de origen que se invalida solo cuando cambia el contenido o el ancho de ajuste.

Guardar en cuaderno: modo de selección de mensajes

SaveToNotebookModal ahora acepta un accesorio messages opcional que cambia el modal al "modo de selección": el usuario elige exactamente qué usuario/asistente desea incluir, y la transcripción + userQuery enviada al backend se reconstruye a partir del subconjunto seleccionado. Los ajustes preestablecidos rápidos ("Seleccionar todo", "Último turno", "Últimos 3 turnos") y un título derivado automáticamente que rastrea el primer mensaje del usuario seleccionado mantienen el flujo rápido para los casos comunes. El modal ahora también usa íconos Check / MessageSquare / User para distinguir roles de un vistazo e informa el estado de carga de la lista de cuadernos por separado del control giratorio de guardado.

Adopción real de sistemas portátiles en toda la pila

Se migró cada superficie restante de Notebook de la categoría de prueba heredada API a los puntos finales reales /api/v1/notebook/*. Un nuevo bloque web/lib/notebook-api.ts exporta ayudas escritas (listNotebooks, getNotebook, createNotebook, updateNotebook, deleteNotebook, deleteNotebookRecord) junto con las ayudas conservadas solo para cuestionarios. La pestaña Conocimiento → Cuadernos, el selector de referencia del cuaderno de la página Guía (useNotebookSelection) y el modo Guardar en cuaderno ahora resuelven los UUID de un extremo a otro, por lo que los registros guardados desde Co-Writer, Chat o Aprendizaje guiado se pueden descubrir inmediatamente como referencias en todas partes.

Panel de configuración plegable unificado

Se extrajo la sección plegable "Configuración" que anteriormente solo existía en ResearchConfigPanel en un componente compartido de CollapsibleConfigSection. Los paneles Quiz, Math Animator y Visualize ahora comparten exactamente el mismo chevron + encabezado de resumen, y cada formulario incluye un asistente summarizeXxxConfig para que el estado colapsado muestre una sola línea significativa (por ejemplo, Personalizado · 5q · Difícil · MCQ o Mimic · paper.pdf · max 10). La página de chat ahora mantiene un único estado panelCollapsed para cualquier capacidad que esté activa, se expande automáticamente al cambiar de capacidad y se contrae automáticamente después de enviar un mensaje para que el compositor permanezca compacto durante la conversación.

Botón de parada de transmisión y polaco del compositor

Se reemplazó la rueda giratoria dentro del botón Enviar con un botón dedicado Detener que aparece en lugar de Enviar mientras se transmite un turno. Un anillo tenue gira lentamente alrededor del borde para indicar "aún funciona: click para cancelar", con un cuadrado blanco al frente y al centro como el objetivo click. El encabezado encima de los mensajes (etiqueta de capacidad + botones Guardar/Nuevo chat) ahora siempre se representa, y el contenedor de mensajes adquiere un gradiente de máscara suave en la parte superior e inferior para que el contenido de la transmisión aparezca y desaparezca gradualmente en lugar de aparecer en el borde de desplazamiento. En el modo de investigación profunda, las fuentes se movían a un menú desplegable con una línea de resumen compacta de las selecciones activas, que coincidía con el patrón utilizado por el selector de herramientas.

Refactorización del administrador de configuración de TutorBot

Se reescribió la persistencia de configuración de TutorBotManager en un pequeño API público (load_bot_config, save_bot_config, merge_bot_config) con tres mejoras significativas: las escrituras ahora son atómicas (write-temp + Path.replace), por lo que un proceso finalizado nunca deja un config.yaml a medio escribir; las fusiones tienen semántica clara y explícita: None significa "dejar como está", una cadena vacía o un dictado vacío es un claro intencional, por lo que clients puede borrar deliberadamente una descripción o una lista de canales; y el punto final API reenvía solo model_dump(exclude_unset=True), por lo que los campos omitidos pasan al valor en el disco. Las nuevas pruebas de regresión cubren el contrato de escritura atómica, el respaldo corrupto-yaml y los cuatro casos de semántica de fusión.

Refinamientos del renderizador Markdown

La familia MarkdownRenderer obtuvo un accesorio trackSourceLines que propaga los atributos data-source-line a través de cada elemento del bloque (encabezados, listas, párrafos, etc.) y omite los pasos de normalización de desplazamiento de línea (processMarkdownContent, normalizeMarkdownForDisplay) para que las posiciones AST se mantengan fieles para los consumidores de sincronización del editor/vista previa. RichCodeBlock ahora omite react-syntax-highlighter por completo para vallas sin etiquetar / text / plaintext (eliminando las advertencias de "idioma desconocido" de Prism) y las presenta como un bloque monoespaciado simple y ordenado. La detección de sirenas también se amplió para reconocer el estilo editor.md ```flow, ```seq y las vallas ```sequence que el preprocesador reescribe en sirena.

Actualización de la interfaz de usuario del tema y la guía

Se ajustaron los temas predeterminados de luz y nieve con primeros planos más profundos, bordes más cálidos y un --primary (#B0501E) ligeramente más saturado para una mejor legibilidad frente a las nuevas superficies de la tarjeta. La página de aprendizaje guiado (/guide) se migró de las paletas codificadas slate-*/indigo-* a los tokens de diseño (var(--card), var(--primary), var(--muted-foreground), etc.), por lo que ahora respeta el selector de temas. HistorySessionPicker recibió el mismo tratamiento, además de una solución para las marcas de tiempo de las sesiones que se trataban como milisegundos en lugar de segundos (lo que producía fechas de 1970).

Solución de representación de mensajes del sistema

Los mensajes del sistema backend (por ejemplo, el contexto de seguimiento de la prueba escrito por el tiempo de ejecución del turno) ahora se filtran en el límite UnifiedChatContext.hydrateMessages y nuevamente de manera defensiva en ChatMessageList, por lo que nunca aparecen como burbujas de chat fantasma en la interfaz de usuario mientras aún fluyen hacia el contexto LLM como se esperaba.

Corrección de errores

  • La configuración del canal TutorBot se borra en cada reinicio del servidor (#332) — create_and_start_bot estaba construyendo un BotConfig nuevo con valores predeterminados vacíos en cada llamada, que luego _save_bot_config persistió en el config.yaml existente, borrando los canales configurados por el usuario (por ejemplo, Telegram). El punto final ahora carga primero la configuración existente y superpone solo los campos proporcionados por client.
  • El middleware selective_access_log falla en cada respuesta que no sea 200 (#334 / #335): el middleware pasó cuatro argumentos al AccessFormatter de uvicorn, que espera cinco (omitiendo http_version), generando ValueError: not enough values to unpack en cada respuesta de error. Ahora lee http_version desde el alcance ASGI con un respaldo 1.1.
  • Vulnerabilidades de seguridad de 15 npm (n.° 330): se eliminaron jspdf 4.0.0 → 4.2.0 (9 CVE que incluyen inyección crítica de PDF), next 16.1.1 → 16.2.3 (8 CVE que incluyen contrabando de HTTP, omisión de CSRF), mermaid 11.12.2 → 11.14.0 y el eslint-config-next correspondiente. npm audit fix barrió la cadena indirecta (flatted, lodash-es, minimatch, picomatch, dompurify, ajv, brace-expansion). Estado final: 0 vulnerabilidades, sin cambios importantes.
  • .env.example_CN: se eliminó un sufijo // README accidental en el comentario de la lista de proveedores.

Expansión del conjunto de pruebas

Se agregó un nuevo módulo tests/services/tutorbot/test_manager_config.py que cubre viajes de ida y vuelta de carga/guardado, el respaldo corrupto de yaml, escrituras de archivos temporales atómicos, recuperación de fallas después de un OSError en mitad de la escritura y las cuatro semánticas de merge_bot_config (sin configuración existente, transferencia de campos omitidos, None como no proporcionado y valor vacío como claro explícito). tests/api/test_tutorbot_router.py ampliado con la clase de prueba explícitamente clara. Se reescribieron las pruebas de enrutamiento de respuesta inmediata del orquestador para fijar el nuevo contrato: active_capability se conserva cuando se establece answer_now_context, el orquestador recurre a chat solo cuando falta la capacidad original y emite un error claro cuando ninguna de las dos está registrada. Se agregó un nuevo módulo tests/capabilities/test_answer_now.py con 28 casos que cubren los ayudantes compartidos (extract_answer_now_context, truncamiento format_trace_summary/i18n, make_skip_notice, labeled_block, join_chunks) y todas las rutas rápidas por capacidad: chat, deep_solve, deep_question (incluido el respaldo unparseable-JSON), deep_research, visualize (incluida la eliminación de barreras de código y la recuperación no válida de render_type) y math_animator (verificando que run_analysis/run_design/run_summary no se invoquen mientras que run_code_generation/run_render sí). Una prueba inversa confirma que las capacidades aún siguen su proceso normal cuando no hay ningún answer_now_context presente.

DeepTutor v1.1.1

DeepTutor v1.1.1 Release Notes

Release Date: 2026.04.17

Highlights

Universal "Answer Now" Escape Hatch — Per-Capability Fast Paths

Promoted "Answer now" from a chat-only affordance to a universal interrupt that respects each capability's output shape. A new shared helper deeptutor/capabilities/_answer_now.py provides the gate (extract_answer_now_context) and the prompt-friendly trace summary, and every built-in capability now owns its own fast-path branch at the top of run():

  • chat — synthesize the final markdown answer from the partial trace (existing behavior).
  • deep_solve — skip planning + reasoning, jump straight into the writer.
  • deep_question — skip ideation/templates, emit the full quiz JSON in one structured call (still rendered by QuizViewer).
  • deep_research — skip rephrase/decompose/research, write the report directly from accumulated evidence.
  • math_animator — skip analysis + design + summary but keep code generation + render, so the user still gets a real animation.
  • visualize — skip analysis + review, emit the final renderable code in one structured call.

Each fast-path preserves the same result envelope as the normal pipeline (so the Quiz / MathAnimator / Visualization viewers render unchanged) and prepends a > ⚡ Skipped X stage(s) notice so users know it was a best-effort early exit. The orchestrator no longer re-routes answer_now to chat; it now keeps active_capability and only falls back to chat if the originally selected capability has been removed from the registry. The frontend matches: handleAnswerNow no longer overrides the snapshot's capability, and a single-shot guarded AnswerNowRow component renders the action inline below the streaming trace panel.

Co-Writer — Resizable Split & Line-Anchored Scroll Sync

The Co-Writer page picked up a draggable splitter between the editor and preview panes (with a persisted ratio in localStorage) and a true bidirectional scroll-sync that survives soft-wrapped lines. Each preview block now carries a data-source-line attribute pointing back at its starting line in the markdown source (provided by remark's AST positions); on the editor side a hidden mirror element mimics the textarea's wrap geometry so we can read the real pixel-y of every source line. With both sides expressed as pixel coordinates the sync becomes a single piecewise-linear interpolation in either direction, with a per-source-line cache that invalidates only when the content or wrap width changes.

Save-to-Notebook — Message Selection Mode

SaveToNotebookModal now accepts an optional messages prop that flips the modal into "selection mode": the user picks exactly which user/assistant turns to include, and the transcript + userQuery shipped to the backend are rebuilt from the selected subset. Quick presets ("Select all", "Last turn", "Last 3 turns") and an auto-derived title that tracks the first selected user message keep the flow fast for the common cases. The modal also now uses Check / MessageSquare / User icons to distinguish roles at a glance, and reports loading state for the notebook list separately from the save spinner.

Real Notebook System Adoption Across the Stack

Migrated every remaining Notebook surface off the legacy quiz-category API onto the real /api/v1/notebook/* endpoints. A new web/lib/notebook-api.ts block exports typed helpers — listNotebooks, getNotebook, createNotebook, updateNotebook, deleteNotebook, deleteNotebookRecord — alongside the preserved quiz-only helpers. The Knowledge → Notebooks tab, the Guide page's notebook reference picker (useNotebookSelection), and the Save-to-Notebook modal all now resolve UUIDs end-to-end, so records saved from Co-Writer, Chat, or Guided Learning are immediately discoverable as references everywhere.

Unified Collapsible Settings Panel

Extracted the collapsible "Settings" section that previously only existed in ResearchConfigPanel into a shared CollapsibleConfigSection component. The Quiz, Math Animator, and Visualize panels now share the exact same chevron + summary header, and each form ships a summarizeXxxConfig helper so the collapsed state shows a meaningful one-liner (e.g. Custom · 5q · Hard · MCQ or Mimic · paper.pdf · max 10). The chat page now keeps a single panelCollapsed state for whichever capability is active, auto-expands on capability switch, and auto-collapses after sending a message so the composer stays compact during conversation.

Streaming Stop Button & Composer Polish

Replaced the spinner-inside-the-Send-button with a dedicated Stop button that appears in place of Send while a turn is streaming. A faint ring slowly rotates around the rim to signal "still working — click to cancel", with a white square front-and-center as the click target. The header above the messages (capability label + Save / New chat buttons) is now always rendered, and the messages container picks up a soft mask gradient at the top and bottom so streaming content fades in/out instead of clipping at the scroll edge. In Deep Research mode, sources moved into a dropdown with a compact summary line of the active picks, matching the pattern used by the tool selector.

TutorBot Config Manager Refactor

Rewrote TutorBotManager's config persistence into a small public API (load_bot_config, save_bot_config, merge_bot_config) with three meaningful improvements: writes are now atomic (write-temp + Path.replace) so a killed process never leaves a half-written config.yaml; merges have explicit-clear semantics — None means "leave as-is", an empty string or empty dict is an intentional clear — so clients can deliberately wipe a description or channels list; and the API endpoint forwards only model_dump(exclude_unset=True) so omitted fields fall through to the on-disk value. New regression tests cover the atomic-write contract, the corrupt-yaml fallback, and the four merge-semantics cases.

Markdown Renderer Refinements

The MarkdownRenderer family gained a trackSourceLines prop that propagates data-source-line attributes through every block element (headings, lists, paragraphs, etc.) and bypasses the line-shifting normalization passes (processMarkdownContent, normalizeMarkdownForDisplay) so AST positions stay faithful for editor/preview sync consumers. RichCodeBlock now skips react-syntax-highlighter entirely for unlabeled / text / plaintext fences (eliminating Prism "unknown language" warnings) and renders them as a tidy plain-monospace block. Mermaid detection was also extended to recognize editor.md style ```flow, ```seq, and ```sequence fences that get rewritten to mermaid by the preprocessor.

Theme & Guide UI Refresh

Tightened the default light and Snow themes with deeper foregrounds, warmer borders, and a slightly more saturated --primary (#B0501E) for better legibility against the new card surfaces. The Guided Learning page (/guide) was migrated off hardcoded slate-* / indigo-* palettes onto the design tokens (var(--card), var(--primary), var(--muted-foreground), etc.) so it now respects the theme switcher. HistorySessionPicker got the same treatment, plus a fix for session timestamps that were being treated as milliseconds instead of seconds (which produced 1970 dates).

System Message Rendering Fix

Backend system messages (e.g. quiz follow-up grounding context written by the turn runtime) are now filtered out at the UnifiedChatContext.hydrateMessages boundary and again defensively in ChatMessageList, so they never surface as ghost chat bubbles in the UI while still flowing into the LLM context as intended.

Bug Fixes

  • TutorBot channel config wiped on every server restart (#332) — create_and_start_bot was constructing a fresh BotConfig with empty defaults on every call, which _save_bot_config then persisted over the existing config.yaml, wiping user-configured channels (e.g. Telegram). The endpoint now loads the existing config first and overlays only client-supplied fields.
  • selective_access_log middleware crash on every non-200 response (#334 / #335) — the middleware passed four args to uvicorn's AccessFormatter which expects five (omitting http_version), raising ValueError: not enough values to unpack on every error response. Now reads http_version from the ASGI scope with a 1.1 fallback.
  • 15 npm security vulnerabilities (#330) — bumped jspdf 4.0.0 → 4.2.0 (9 CVEs incl. critical PDF injection), next 16.1.1 → 16.2.3 (8 CVEs incl. HTTP smuggling, CSRF bypass), mermaid 11.12.2 → 11.14.0, and the matching eslint-config-next. npm audit fix swept up the indirect chain (flatted, lodash-es, minimatch, picomatch, dompurify, ajv, brace-expansion). End state: 0 vulnerabilities, no breaking changes.
  • .env.example_CN — removed an accidental // README suffix on the provider-list comment.

Test Suite Expansion

Added a new tests/services/tutorbot/test_manager_config.py module covering load/save round-trips, the corrupt-yaml fallback, atomic temp-file writes, failure-recovery after a mid-write OSError, and all four merge_bot_config semantics (no existing config, omitted-field passthrough, None-as-not-provided, and empty-value-as-explicit-clear). Extended tests/api/test_tutorbot_router.py with the explicit-clear test class. Rewrote the orchestrator answer-now routing tests to pin the new contract — active_capability is preserved when answer_now_context is set, the orchestrator falls back to chat only when the original capability is missing, and emits a clear error when neither is registered. Added a new tests/capabilities/test_answer_now.py module with 28 cases covering the shared helpers (extract_answer_now_context, format_trace_summary truncation/i18n, make_skip_notice, labeled_block, join_chunks) and every per-capability fast-path: chat, deep_solve, deep_question (including the unparseable-JSON fallback), deep_research, visualize (including code-fence stripping and invalid render_type recovery), and math_animator (verifying that run_analysis/run_design/run_summary are not invoked while run_code_generation/run_render are). A reverse test confirms that capabilities still take their normal pipeline when no answer_now_context is present.

What's Changed

  • fix(api): add missing http_version arg in selective_access_log middleware by @kagura-agent in https://github.com/HKUDS/DeepTutor/pull/335
  • fix(web): resolve 15 npm security vulnerabilities by @srinivasrk in https://github.com/HKUDS/DeepTutor/pull/330
