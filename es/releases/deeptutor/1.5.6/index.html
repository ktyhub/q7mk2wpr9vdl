#DeepTutor v1.5.6

DeepTutor v1.5.6 Release Note

Fecha de lanzamiento: 2026.07.29 Una continuación de v1.5.5 que finaliza lo que comenzó: el inicio de sesión del Codex que envió ahora se completa en una implementación remota o en contenedores, y también para socios y no administradores. Además de eso, una base de conocimientos puede apuntar a una biblioteca que ya mantiene en Tencent IMA, los archivos producidos por una conversación dejan de ocultarse en la transcripción y un libro japonés ya no regresa con pruebas de chino. Sin cita previa, sin migraciones.

¿Qué hay de nuevo?

Conectar una biblioteca IMA de Tencent

Una base de conocimientos ahora puede ser un indicador de una biblioteca que seleccione en Tencent IMA en lugar de un índice que crea DeepTutor. Sigue exactamente la forma lightrag-server: nada se copia y nada se almacena localmente: los documentos se agregan en IMA, la recuperación llama a OpenAPI de IMA y el bucle de chat aún escribe la respuesta. Las credenciales (client_id + api_key) y la identificación de la biblioteca están activas por KB, por lo que en una implementación compartida cada usuario recupera a través de su propia cuenta IMA en lugar de una clave global, y la conexión es independiente sin una superficie de configuración que completar primero. La conexión sondea la biblioteca una vez, por lo que una identificación mal escrita falla en el momento de la conexión en lugar de hacerlo silenciosamente en cada consulta posterior.

Archivos generados, donde podrás encontrarlos nuevamente

Solo se podía acceder a los archivos que producía el tutor a través de la única burbuja del asistente que los creaba, por lo que volver a encontrar una plataforma o una hoja de cálculo significaba desplazarse por la transcripción. El panel Actividad ahora divide lo que una conversación produjo de lo que usted subió: los archivos generados obtienen su propia tarjeta encima de los archivos adjuntos, con un tamaño y un título flotante que muestra dónde se encuentra el archivo debajo de la raíz de datos. Las filas reutilizan la ruta existente abierta en el visor.

Inicio de sesión remoto en Codex que se completa

v1.5.5 envió OpenAI Codex OAuth con una advertencia: en una caja remota, inicie sesión desde el servidor. Esa advertencia desapareció. El localhost del navegador y el localhost del servidor son máquinas diferentes, por lo que un proxy inverso por sí solo nunca puede transportar la devolución de llamada; DeepTutor ahora reenvía solo la ruta de devolución de llamada exacta a través del origen web a un agente de validación de estado, y la tarjeta de configuración y CLI imprimen la dirección de devolución de llamada real, el comando de túnel SSH, una acción de autorización explícita y una cuenta regresiva que sobrevive a una recarga de página (#716). Dos seguimientos hacen que funcione para todos los demás en la implementación. La devolución de llamada la entrega OAuth state (un secreto que este proceso genera para un inicio de sesión, comparado en tiempo constante) en lugar de hacerlo el usuario de la solicitud, porque el navegador llega a través de su propio túnel y no lleva ninguna cookie de sesión; sin esto, el inicio de sesión remoto devolvió login_not_active para todos los que no eran administradores. Y el turno de un socio ahora resuelve las credenciales del Codex en la raíz del propietario en lugar del espacio de trabajo sintético del socio, por lo que chatear con un socio ya no falla con "Iniciar sesión en Codex antes de usar este modelo" (#713). El oyente permanece vinculado al loopback, los puertos 1455 y 1457 nunca se publican, las respuestas de devolución de llamada nunca reflejan el código o el estado, y PKCE y el intercambio de tokens no cambian.

Cada idioma sigue siendo su propio idioma

parse_language() terminó en un simple return "zh", por lo que ja/ko/fr/de/ru/ar se resolvió en chino, razón por la cual un libro japonés volvió con cuestionarios en chino (#712). Ahora delega al normalizador existente y pasa códigos desconocidos, y las dos cadenas alternativas que asumieron que la respuesta era zh o en siguen su ejemplo: solicita try [code, base locale, "en"], por lo que zh-tw reutiliza los archivos chinos y ja aterriza en inglés en lugar de chino.

Correcciones variadas

  • La creación de libros y la regeneración de bloques se ejecutan a través de WebSocket en lugar de una solicitud de tiempo de espera de un proxy, y la síntesis de columna y la etapa de análisis de Visualize utilizan llamadas sin transmisión para que deje de ocurrir un retroceso de un solo capítulo o un bloque de código truncado (#707). Los tres ahora se enrutan a través de la unión del agente, lo que restaura los archivos adjuntos de imágenes, los metadatos de seguimiento y el enrutamiento por agente que las llamadas directas a fábrica estaban cayendo.
  • deeptutor start en una compra de fuente nueva instala web/node_modules automáticamente en lugar de fallar con un error de módulo faltante (#710).
  • La administración de usuarios administradores, el cierre de sesión, los cuadros de diálogo de confirmación y los brindis están localizados, por lo que cambiar la interfaz de usuario al chino ya no deja la administración de cuentas en inglés (#718).
  • El servicio de carga diferida utiliza rutas de importación literales (#717): comportamiento neutral, pero hace que el gráfico del módulo sea analizable estáticamente.

Notas de actualización

Acceso directo desde v1.5.5: pip install -U deeptutor; Los usuarios de Docker extraen ghcr.io/hkuds/deeptutor:latest. Sin migraciones, sin cambios de esquema o configuración.

  • El inicio de sesión remoto del Codex ahora utiliza un túnel SSH, y el consejo v1.5.5 para ejecutar deeptutor provider login openai-codex en el servidor ya no es la única ruta. DeepTutor imprime el comando ssh -N -L … exacto; ejecute solo el que coincida con el puerto de devolución de llamada que informa y tenga en cuenta que 3782 en ese comando es un ejemplo; reemplácelo con el puerto web que realmente escucha en el loopback del host SSH.
  • Una base de conocimientos de Tencent IMA necesita una clave client_id y API de ima.qq.com/agent-interface más la identificación de la biblioteca. Los documentos se agregan en IMA, no a través de DeepTutor. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.5.5...v1.5.6

DeepTutor v1.5.6

Highlights

  • Remote Codex OAuth now works behind proxies and for non-admins — The exact callback path is forwarded through the Web origin to a broker that validates process-minted state in constant time, fixing login_not_active without relying on browser session cookies; partner chats now resolve credentials from the owner’s root (#716, #713). The listener remains loopback-only, ports 1455/1457 stay unpublished, and PKCE/token exchange are unchanged. Use the printed ssh -N -L … command, replacing example port 3782 with the actual Web port.
  • Tencent IMA libraries can back knowledge bases without local indexing — Each KB stores its own client_id, API key, and library ID, enabling per-user retrieval on shared deployments. Documents remain in IMA, retrieval uses its OpenAPI, and connection-time validation catches bad library IDs before queries fail repeatedly.
  • Generated files are discoverable outside their chat bubble — The Activity panel now separates tutor-generated decks, spreadsheets, and other outputs from uploads, showing file sizes and data-root locations on hover while reusing the existing viewer path. Recovering artifacts no longer requires scrolling through the transcript.
  • Non-Chinese locales now generate in the requested language — parse_language() delegates to the existing normalizer and passes unknown codes through; fallback chains now try [code, base locale, "en"], so ja falls back to English rather than Chinese while zh-tw still reuses Chinese resources (#712). This fixes Japanese books producing Chinese quizzes and affects other previously misrouted locales.
  • Long-running generation and fresh checkouts are more robust — Book creation and block regeneration use WebSockets to avoid proxy timeouts, while spine synthesis and Visualize analysis use non-streaming calls to prevent single-chapter fallbacks and truncated code blocks (#707). These paths now use the agent seam, restoring image attachments, trace metadata, and per-agent routing; deeptutor start also installs missing web/node_modules automatically (#710).
  • No breaking changes — Drop-in upgrade from v1.5.5; no migrations, schema changes, or configuration changes.

DeepTutor v1.5.6 Release Notes

Release Date: 2026.07.29

A follow-up to v1.5.5 that finishes what it started: the Codex sign-in it shipped now actually completes on a remote or containerized deployment, and for partners and non-administrators too. Alongside that, a knowledge base can point at a library you already keep in Tencent IMA, the files a conversation produced stop hiding in the transcript, and a Japanese book no longer comes back with Chinese quizzes. Drop-in — no migrations.

What's New

Connect a Tencent IMA library

A knowledge base can now be a pointer to a library you curate in Tencent IMA rather than an index DeepTutor builds. It follows the lightrag-server shape exactly: nothing is copied and nothing is stored locally — documents are added in IMA, retrieval calls IMA's OpenAPI, and the chat loop still writes the answer. Credentials (client_id + api_key) and the library id live per-KB, so on a shared deployment each user retrieves through their own IMA account instead of one global key, and connecting is self-contained with no settings surface to fill in first. Connecting probes the library once, so a mistyped id fails at connect time rather than silently at every later query.

Generated files, where you can find them again

Files the tutor produced were only reachable through the one assistant bubble that made them, so finding a deck or a spreadsheet again meant scrolling the transcript. The Activity panel now splits what a conversation produced from what you uploaded: generated files get their own card above attachments, with a size and a hover title showing where the file sits under the data root. Rows reuse the existing open-in-viewer path.

Remote Codex sign-in that completes

v1.5.5 shipped OpenAI Codex OAuth with a caveat — on a remote box, sign in from the server instead. That caveat is gone. The browser's localhost and the server's localhost are different machines, so a reverse proxy alone can never carry the callback; DeepTutor now forwards only the exact callback path through the Web origin to a state-validating broker, and the settings card and CLI print the real callback address, the SSH tunnel command, an explicit authorize action, and a countdown that survives a page reload (#716).

Two follow-ups make it work for everyone else on the deployment. The callback is delivered by OAuth state — a secret this process minted for one login, compared in constant time — rather than by the request's user, because the browser arrives through your own tunnel and carries no session cookie; without this, remote sign-in returned login_not_active for every non-administrator. And a partner turn now resolves Codex credentials to the owner's root instead of the partner's synthetic workspace, so chatting with a partner no longer fails with "Sign in to Codex before using this model" (#713).

The listener stays bound to loopback, ports 1455 and 1457 are never published, callback responses never echo the code or state, and PKCE and the token exchange are unchanged.

Every language stays its own language

parse_language() ended in a bare return "zh", so ja/ko/fr/de/ru/ar all resolved to Chinese — which is why a Japanese book came back with Chinese quizzes (#712). It now delegates to the existing normalizer and passes unknown codes through, and the two fallback chains that assumed the answer was zh or en follow suit: prompts try [code, base locale, "en"], so zh-tw reuses the Chinese files and ja lands on English rather than Chinese.

Assorted fixes

  • Book creation and block regeneration run over WebSocket instead of a request that a proxy could time out, and spine synthesis and Visualize's analysis stage use non-streaming calls so a single-chapter fallback or a truncated code block stops happening (#707). All three now route through the agent seam, which restores the image attachments, trace metadata, and per-agent routing the direct factory calls were dropping.
  • deeptutor start on a fresh source checkout installs web/node_modules for you instead of crashing with a missing-module error (#710).
  • Admin user management, sign-out, confirm dialogs, and toasts are localized, so switching the UI to Chinese no longer leaves account management in English (#718).
  • The service lazy-loader uses literal import paths (#717) — behaviour-neutral, but it makes the module graph statically analyzable.

Upgrade Notes

Drop-in from v1.5.5: pip install -U deeptutor; Docker users pull ghcr.io/hkuds/deeptutor:latest. No migrations, no schema or config changes.

  • Remote Codex sign-in now uses an SSH tunnel, and the v1.5.5 advice to run deeptutor provider login openai-codex on the server is no longer the only path. DeepTutor prints the exact ssh -N -L … command; run only the one matching the callback port it reports, and note that 3782 in that command is an example — replace it with the Web port actually listening on the SSH host's loopback.
  • A Tencent IMA knowledge base needs a client_id and API key from ima.qq.com/agent-interface plus the library id. Documents are added in IMA, not through DeepTutor.
