#DeepTutor v1.3.10

DeepTutor v1.3.10 Release Note

Fecha de lanzamiento: 2026.05.10 v1.3.10 es una versión de confiabilidad enfocada para los problemas reportados después de v1.3.9. Restaura un acceso remoto más fluido al Docker y hace que funcionen los puntos finales LLM autofirmados consistentemente en todos los proveedores respaldados por SDK, protege los fragmentos de código de las citas reescribe y divide Matrix E2EE en una dependencia de suscripción explícita.

Destacados

Recuperación remota de Docker y CORS

  • El Docker remoto para un solo usuario vuelve a funcionar de inmediato - cuando AUTH_ENABLED=false, DeepTutor ahora acepta orígenes de navegador a través de HTTP/HTTPS, por lo que Las interfaces LAN o de servidor remoto ya no llegan al CORS v1.3.8/v1.3.9 regresión informada en el n.° 463.
  • Las implementaciones autenticadas permanecen explícitas - cuando AUTH_ENABLED=true, CORS todavía requiere una lista de permitidos concreta a través de CORS_ORIGIN o CORS_ORIGINS, Preservar el límite de seguridad de la autenticación acreditada.
  • Se admiten múltiples orígenes de implementación - CORS_ORIGINS acepta comas o valores separados por nueva línea, y ambos archivos Docker Compose pasan la configuración hasta el contenedor backend.
  • La configuración ya no elimina los indicadores de red - CORS_ORIGIN, CORS_ORIGINS y DISABLE_SSL_VERIFY son parte del orden de escritura canónico .env.

TLS del proveedor y correcciones de renderizado

  • DISABLE_SSL_VERIFY ahora llega a las rutas OpenAI SDK - Compatible con OpenAI, Azure OpenAI, ejecutor, TutorBot y la incorporación heredada SDK clients reciben un httpx.AsyncClient(verify=False) compartido cuando la bandera está habilitada, arreglando puntos finales HTTPS LLM autofirmados informados en el n.° 464.
  • La producción aún bloquea las derivaciones TLS inseguras - ENVIRONMENT=prod o ENVIRONMENT=production rechaza DISABLE_SSL_VERIFY, con una única advertencia registrado en uso no productivo.
  • Los bloques de código mantienen intactos los índices de la matriz - Vinculación de citas de Markdown ahora enmascara el código vallado y en línea antes de reescribir las referencias, por lo que values[0] permanece código en lugar de convertirse en un enlace de cita #references (#468).

Compatibilidad de instalación de Matrix

  • Matrix ya no instala E2EE de forma predeterminada - el estándar matrix extra y requirements/matrix.txt ahora usa matrix-nio simple, evitando el Fallos de compilación de python-olm/libolm observados en macOS Python 3.14 y Apple Sonido metálico 21 (#462).
  • Las salas cifradas son un complemento explícito - instale deeptutor[matrix-e2e] o requirements/matrix-e2e.txt cuando se necesita soporte E2EE y libolm es disponible.
  • Los fallos en tiempo de ejecución son más claros - Matrix utiliza de forma predeterminada el modo no E2EE y habilitar E2EE sin dependencias criptográficas ahora genera una instalación procesable mensaje en lugar de fallar en el momento de la importación.

Compatibilidad de tiempo de ejecución multiusuario

  • Las rutas del espacio de trabajo predeterminadas permanecen estables fuera del alcance del usuario - cuando no hay corriente El contexto multiusuario está activo, la resolución de la ruta vuelve a los datos predeterminados. espacio de trabajo en lugar de forzar un ámbito de administrador.
  • Las pruebas heredadas y los ganchos de parche de mono siguen disponibles - sesión y configuración Los enrutadores mantienen las cuñas de compatibilidad utilizadas por las pruebas y las integraciones más antiguas.
  • Se ignoran los artefactos del agente local - .claude/ ahora está excluido de Git, por lo que Los árboles de trabajo locales y los metadatos de los agentes no ingresan accidentalmente en las versiones.

Pruebas

  • Se agregaron pruebas de configuración de CORS para orígenes remotos no autenticados y autenticados. listas permitidas explícitas.
  • Se agregaron pruebas compartidas de OpenAI SDK HTTP-client en el núcleo del proveedor, Azure, ejecutores, TutorBot y adaptadores de integración.
  • Se agregaron pruebas de visualización de Markdown para citas en prosa, código delimitado, código en línea, y citas explícitas con comillas inversas.
  • Se agregaron pruebas divididas de dependencia de Matrix para mantener las instalaciones predeterminadas libres de matrix-nio[e2e].
  • Se volvieron a ejecutar pruebas Python específicas, pruebas de nodos web, comprobaciones de Ruff y espacios en blanco de diferencias. Validación del parche de lanzamiento.

Notas de actualización

  • Si ejecuta Docker remoto con AUTH_ENABLED=false, no se requiere ninguna configuración CORS adicional. requerido para orígenes de navegador HTTP/HTTPS normales.
  • Si ejecuta una implementación compartida o autenticada con AUTH_ENABLED=true, configure CORS_ORIGIN o CORS_ORIGINS al origen exacto de la interfaz, por ejemplo https://learn.example.com.
  • Utilice DISABLE_SSL_VERIFY=true solo para pruebas locales, autofirmadas o con espacio de aire Puntos finales de LLM. Queda bloqueado en ENVIRONMENT=prod y ENVIRONMENT=production.
  • Las instalaciones de Matrix ahora no son E2EE de forma predeterminada. Para salas Matrix cifradas, instale .[matrix-e2e] o requirements/matrix-e2e.txt, asegúrese de que libolm esté presente y configure e2ee_enabled=true en la configuración del canal Matrix.
  • Si instaló previamente .[matrix] solo para obtener Matrix no cifrado mensajería, la reinstalación después de esta versión ya no debería requerir nativa herramientas de construcción libolm. Changelog completo: https://github.com/HKUDS/DeepTutor/compare/v1.3.9...v1.3.10

DeepTutor v1.3.10

DeepTutor v1.3.10 Release Notes

Release Date: 2026.05.10

v1.3.10 is a focused reliability release for the issues reported after v1.3.9. It restores smoother remote Docker access, makes self-signed LLM endpoints work consistently across SDK-backed providers, protects code snippets from citation rewrites, and splits Matrix E2EE into an explicit opt-in dependency.

Highlights

Remote Docker and CORS Recovery

  • Remote single-user Docker works out of the box again - when AUTH_ENABLED=false, DeepTutor now accepts browser origins over HTTP/HTTPS so LAN or remote-server frontends no longer hit the v1.3.8/v1.3.9 CORS regression reported in #463.
  • Authenticated deployments stay explicit - when AUTH_ENABLED=true, CORS still requires a concrete allowlist through CORS_ORIGIN or CORS_ORIGINS, preserving the credentialed-auth safety boundary.
  • Multiple deployment origins are supported - CORS_ORIGINS accepts comma or newline separated values, and both Docker Compose files pass the setting through to the backend container.
  • Settings no longer drop network flags - CORS_ORIGIN, CORS_ORIGINS, and DISABLE_SSL_VERIFY are part of the canonical .env write order.

Provider TLS and Rendering Fixes

  • DISABLE_SSL_VERIFY now reaches OpenAI SDK paths - OpenAI-compatible, Azure OpenAI, executor, TutorBot, and legacy embedding SDK clients all receive a shared httpx.AsyncClient(verify=False) when the flag is enabled, fixing self-signed HTTPS LLM endpoints reported in #464.
  • Production still blocks unsafe TLS bypasses - ENVIRONMENT=prod or ENVIRONMENT=production rejects DISABLE_SSL_VERIFY, with a single warning logged in non-production use.
  • Code blocks keep array indexes intact - Markdown citation linkification now masks fenced and inline code before rewriting references, so values[0] stays code instead of becoming a #references citation link (#468).

Matrix Install Compatibility

  • Matrix no longer installs E2EE by default - the standard matrix extra and requirements/matrix.txt now use plain matrix-nio, avoiding the python-olm / libolm build failures seen on macOS Python 3.14 and Apple Clang 21 (#462).
  • Encrypted rooms are an explicit add-on - install deeptutor[matrix-e2e] or requirements/matrix-e2e.txt when E2EE support is needed and libolm is available.
  • Runtime failures are clearer - Matrix defaults to non-E2EE mode, and enabling E2EE without crypto dependencies now raises an actionable install message instead of failing at import time.

Multi-User Runtime Compatibility

  • Default workspace paths stay stable outside user scope - when no current multi-user context is active, path resolution falls back to the default data workspace rather than forcing an admin scope.
  • Legacy test and monkeypatch hooks remain available - session and settings routers keep compatibility shims used by tests and older integrations.
  • Local agent artifacts are ignored - .claude/ is now excluded from Git so local worktrees and agent metadata do not accidentally enter releases.

Tests

  • Added CORS setting tests for unauthenticated remote origins and authenticated explicit allowlists.
  • Added shared OpenAI SDK HTTP-client tests across provider-core, Azure, executors, TutorBot, and embedding adapters.
  • Added Markdown display tests for prose citations, fenced code, inline code, and explicit backticked citations.
  • Added Matrix dependency split tests to keep default installs free of matrix-nio[e2e].
  • Re-ran targeted Python tests, web node tests, Ruff checks, and diff whitespace validation for the release patch.

Upgrade Notes

  • If you run remote Docker with AUTH_ENABLED=false, no extra CORS setting is required for normal HTTP/HTTPS browser origins.
  • If you run a shared or authenticated deployment with AUTH_ENABLED=true, set CORS_ORIGIN or CORS_ORIGINS to the exact frontend origin(s), for example https://learn.example.com.
  • Use DISABLE_SSL_VERIFY=true only for local, self-signed, or air-gapped test LLM endpoints. It remains blocked in ENVIRONMENT=prod and ENVIRONMENT=production.
  • Matrix installs are now non-E2EE by default. For encrypted Matrix rooms, install .[matrix-e2e] or requirements/matrix-e2e.txt, ensure libolm is present, and set e2ee_enabled=true in the Matrix channel config.
  • If you previously installed .[matrix] only to get non-encrypted Matrix messaging, reinstalling after this release should no longer require native libolm build tooling.
