#DeepTutor v1.3.4

DeepTutor v1.3.4 Release Note

Fecha de lanzamiento: 2026.05.01 v1.3.4 convierte Book Engine y el espacio de trabajo de chat en un circuito de aprendizaje más estrecho: Las páginas de libros ahora pueden tener sus propias sesiones de chat persistentes, los libros pueden ser reconstruido a partir de un lomo existente, y los turnos de chat regulares pueden citar el libro seleccionado páginas junto al contexto espacial. Esta versión también mejora la coherencia del lenguaje, Manejo de resultados de razonamiento estilo DeepSeek, extracción de documentos para RAG, registro infraestructura y la documentación pública sobre el artículo arXiv de DeepTutor.

Destacados

Motor de libros, chat de páginas y referencias de libros

La generación y lectura de libros ahora preservan más el contexto del usuario y lo hacen Es más fácil iterar en un libro generado sin tener que empezar de nuevo.

  • El chat de la página del libro utiliza el protocolo de transmisión unificado - el panel de chat de la página ahora utiliza el WebSocket compartido client y el renderizador de eventos de transmisión utilizado por el principal espacio de trabajo de chat, por lo que la salida de la herramienta, los eventos del asistente, los archivos adjuntos y la restauración El historial de sesiones se comporta de forma coherente.
  • Las sesiones de chat de página persisten por página del libro - cada página puede vincularse a un chat session_id a través de la nueva página-chat-session API, y reabriendo el El lector restaura la conversación de la página cuando está disponible.
  • Los libros se pueden reconstruir desde el lomo aprobado - el nuevo flujo de reconstrucción desaparece contenido de la página generada y el progreso manteniendo el esquema confirmado, luego reinicia la compilación desde esa estructura.
  • La regeneración de una sola página mantiene las notas del alumno - la recompilación forzada puede restablecer el contenido generado conservando los bloques de notas y las claves creados por el usuario metadatos de transición.
  • El chat normal puede citar páginas de libros - el compositor del chat puede adjuntar las páginas seleccionadas libros y páginas como contexto de solicitud, conservarlos en la instantánea de turno, restaurar muéstrelos cuando las sesiones se hidraten y muéstrelos como chips de contexto extraíbles.
  • El contexto del libro es más limpio para los modelos de razonamiento - las páginas del libro seleccionadas son convertidos en referencias de texto delimitadas con etiquetas de pensamiento eliminadas antes de que se inyectan en el chat o en las conversaciones del lado de la página.

Lenguaje de chat y comportamiento del modelo de razonamiento

Los turnos de chat ahora siguen la configuración de idioma actual del usuario de manera más confiable y son más tolerante con los proveedores que devuelven contenido de razonamiento de manera diferente.

  • El idioma es parte de cada turno de chat - Las solicitudes de WebSocket pueden llevar el idioma actual, y tanto el chat agente como el chat clásico añaden explícito instrucciones de idioma para que las respuestas coincidan con el idioma activo de la interfaz de usuario.
  • Regenerar y responder ahora usa el idioma actual de la aplicación - nuevos turnos y Los turnos regenerados leen el último idioma almacenado en lugar de depender únicamente de preferencias de sesiones anteriores.
  • Las respuestas de contenido vacío estilo DeepSeek se recuperan mejor - Compatible con OpenAI Los proveedores pueden recurrir a reasoning_content cuando un modelo devuelve un valor vacío. campo content visible.
  • La escritura en bloque de libros puede afinar el esfuerzo de razonamiento - Bloque de libros respaldado por LLM La generación ahora pasa reasoning_effort, y los reintentos estructurados JSON pueden menor esfuerzo cuando los modelos con mucho razonamiento no devuelven JSON analizable.

Recuperación de RAG, documentos y base de conocimientos

La ingesta de documentos ahora utiliza la misma ruta de extracción en más tipos de archivos y mantiene la reindexación disponible en más estados de recuperación.

  • Ruta de archivos de Office mediante extracción del analizador - Archivos .xlsx y .pptx Ahora una PDF y DOCX en la ruta de enrutamiento respaldada por el analizador, con hoja de cálculo y categorías de presentación disponibles para la lógica RAG descendente.
  • La carga de LlamaIndex utiliza extracción de documentos compartidos - archivos enrutados por el analizador se leen a través de extract_text_from_path(), use un tamaño específico del tipo de archivo límites y evitar truncamientos innecesarios de caracteres durante la indexación.
  • La extracción DOCX tiene una ruta alternativa más segura - cuando python-docx no puede leer un archivo, el extractor puede analizar el contenido OOXML a través de defusedxml en lugar de fallando inmediatamente.
  • Los controles de reindexación de la base de conocimientos son menos frágiles - la interfaz de usuario web puede exponer volver a indexar acciones para estados de error y discrepancia sin requerir una ya tiempo de ejecución de RAG inicializado, siempre que los documentos fuente estén disponibles.
  • Los documentos escaneados o vacíos fallan más claramente - extracción y validación ahora distinguimos límites de bytes, límites de caracteres, contenido analizado vacío y Los resultados del analizador no compatible son más consistentes.

Configuración, estado de ejecución y registro

Esta versión continúa la limpieza de infraestructura necesaria para locales de larga duración. e implementaciones de servidores.

  • La configuración muestra un estado de ejecución más claro - backend, LLM, incrustación y búsqueda El estado se muestra como tarjetas de servicio con estado en línea, marcas de tiempo y tiempo de ejecución. detalles del modelo e indicadores pendientes de aplicar.
  • LLM_REASONING_EFFORT es configurable - Se puede proporcionar esfuerzo de razonamiento a través de la configuración del entorno y se incluye en los resúmenes de tiempo de ejecución.
  • El registro utiliza la superficie de registro estándar: enrutadores, agentes, proveedores, RAG El código y las integraciones de TutorBot se alejan del antiguo módulo de registro personalizado. hacia el uso estándar de logging.getLogger(__name__) más un Loguru enfocado puente.
  • El reenvío de registros de depuración RAG sin formato es más silencioso - el servicio RAG ya no reenvía la salida del controlador de registro de bajo nivel a flujos de eventos orientados al usuario mediante predeterminado.
  • Se actualizó la cobertura de CI y pelusa: los cambios en el flujo de trabajo y las pruebas cubren el ruta de configuración de registro, transmisión de registros de proceso y coherencia de pelusa.

Documentación y localización

La documentación del proyecto ahora refleja la publicación en papel y se mantiene localizada. Archivos README alineados con la última cadencia de lanzamiento.

  • El documento arXiv está vinculado desde el archivo README: la insignia README principal y las noticias. La sección ahora apunta a 2604.26962.
  • Se actualizaron los archivos README localizados - Los archivos README traducidos incluyen el lista de lanzamientos más recientes, actualizaciones de arXiv/news y navegación de idiomas ampliada.
  • La copia del libro, el chat, la configuración y la reconstrucción están localizadas - Inglés y chino Las cadenas de aplicaciones ahora cubren el nuevo chat del libro, la reconstrucción, el idioma, los archivos adjuntos y superficies de estado de tiempo de ejecución.

  • Se agregó cobertura de Book Engine para extracción del contexto del libro, sesión de chat de página enlace, controles de reconstrucción, recompilación forzada de páginas y escritura LLM JSON.

DeepTutor v1.3.4

DeepTutor v1.3.4 Release Notes

Release Date: 2026.05.01

v1.3.4 turns the Book Engine and chat workspace into a tighter learning loop: book pages can now carry their own persistent chat sessions, books can be rebuilt from an existing spine, and regular chat turns can cite selected book pages alongside Space context. This release also improves language consistency, DeepSeek-style reasoning output handling, document extraction for RAG, logging infrastructure, and the public documentation around DeepTutor's arXiv paper.

Highlights

Book Engine, Page Chat, and Book References

Book generation and reading now preserve more of the user's context and make it easier to iterate on a generated book without starting over.

  • Book page chat uses the unified stream protocol - the page chat panel now uses the shared WebSocket client and stream-event renderer used by the main chat workspace, so tool output, assistant events, attachments, and restored session history behave consistently.
  • Page chat sessions are persisted per book page - each page can be bound to a chat session_id through the new page-chat-session API, and reopening the reader restores the page's conversation when available.
  • Books can be rebuilt from the approved spine - the new rebuild flow clears generated page content and progress while keeping the confirmed outline, then restarts compilation from that structure.
  • Single-page regeneration keeps learner notes - forced recompilation can reset generated content while preserving user-authored note blocks and key transition metadata.
  • Regular chat can cite book pages - the chat composer can attach selected books and pages as request context, persist them in the turn snapshot, restore them when sessions hydrate, and show them as removable context chips.
  • Book context is cleaner for reasoning models - selected book pages are converted into bounded text references with thinking tags stripped before they are injected into chat or page-side conversations.

Chat Language and Reasoning-Model Behavior

Chat turns now follow the user's current language setting more reliably and are more tolerant of providers that return reasoning content differently.

  • Language is part of each chat turn - WebSocket requests can carry the current language, and both agentic chat and classic chat append explicit language instructions so answers match the active UI language.
  • Regenerate and Answer Now use the current app language - new turns and regenerated turns read the latest stored language instead of relying only on older session preferences.
  • DeepSeek-style empty-content responses recover better - OpenAI-compatible providers can fall back to reasoning_content when a model returns an empty visible content field.
  • Book block writing can tune reasoning effort - LLM-backed book block generation now passes reasoning_effort, and structured JSON retries can lower effort when reasoning-heavy models fail to return parseable JSON.

RAG, Documents, and Knowledge Base Recovery

Document ingestion now uses the same extraction path across more file types and keeps re-indexing available in more recovery states.

  • Office files route through parser extraction - .xlsx and .pptx files now join PDF and DOCX in the parser-backed routing path, with spreadsheet and presentation categories available to downstream RAG logic.
  • LlamaIndex loading uses shared document extraction - parser-routed files are read through extract_text_from_path(), use file-type-specific size limits, and avoid unnecessary character truncation during indexing.
  • DOCX extraction has a safer fallback path - when python-docx cannot read a file, the extractor can parse OOXML content through defusedxml instead of failing immediately.
  • Knowledge Base re-index controls are less fragile - the web UI can expose re-index actions for error and mismatch states without requiring an already initialized RAG runtime, as long as source documents are available.
  • Scanned or empty documents fail more clearly - extraction and validation now distinguish byte limits, character limits, empty parsed content, and unsupported parser results more consistently.

Settings, Runtime State, and Logging

This release continues the infrastructure cleanup needed for long-running local and server deployments.

  • Settings shows clearer runtime state - backend, LLM, embedding, and search status are displayed as service cards with online state, timestamps, runtime model details, and pending-apply indicators.
  • LLM_REASONING_EFFORT is configurable - reasoning effort can be supplied through environment configuration and is included in runtime summaries.
  • Logging uses the standard logger surface - routers, agents, providers, RAG code, and TutorBot integrations move away from the old custom logger module toward standard logging.getLogger(__name__) usage plus a focused Loguru bridge.
  • Raw RAG debug log forwarding is quieter - the RAG service no longer forwards low-level logging handler output into user-facing event streams by default.
  • CI and lint coverage were refreshed - workflow and test changes cover the logging configuration path, process-log streaming, and lint consistency.

Documentation and Localization

The project documentation now reflects the paper release and keeps localized README files aligned with the latest release cadence.

  • The arXiv paper is linked from the README - the main README badge and News section now point to 2604.26962.
  • Localized READMEs were refreshed - translated README files include the latest release list, arXiv/news updates, and the expanded language navigation.
  • Book, chat, settings, and rebuild copy is localized - English and Chinese app strings now cover the new Book chat, rebuild, language, attachment, and runtime-state surfaces.

Tests

  • Added chat-language prompt coverage for per-turn language directives and language-aware agentic chat behavior.
  • Added Book Engine coverage for book context extraction, page-chat session binding, rebuild controls, forced page recompilation, and LLM JSON writing.
  • Added RAG and document-loader coverage for parser-routed files, Office extraction paths, file-size limits, and re-index eligibility helpers.
  • Added provider/runtime coverage for LLM_REASONING_EFFORT, OpenAI-compatible reasoning fallback behavior, and provider runtime summaries.
  • Added logging tests for configuration, context propagation, Loguru bridging, process-log extraction, and task log streaming.
  • Updated frontend tests for document attachment handling, version reporting, and Knowledge Base re-index helper behavior.

Upgrade Notes

  • CLI and server installs should refresh dependencies after upgrading. The CLI extra and requirements/cli.txt now include defusedxml>=0.7.1 for safer XML parsing during Office document extraction.
  • Custom WebSocket clients can pass book_references and language on turn start messages. Clients that persist request snapshots should store book references alongside notebooks, history, skills, memory, and attachments.
  • Deployments that use reasoning models can set LLM_REASONING_EFFORT to tune reasoning effort globally; per-profile and per-model values remain available as lower-priority fallbacks.
  • Integrations that consumed raw RAG debug log events should rely on structured status and tool events instead of low-level forwarded logger output.
  • Book clients should call the new page-chat-session and rebuild APIs when they need page-level conversation persistence or spine-preserving regeneration.
