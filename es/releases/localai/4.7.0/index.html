LocalAI v4.7.0

🎉 ¡Lanzamiento de LocalAI 4.7.0! 🚀

<h1 align="centro"> <br> <img altura="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

¡LocalAI 4.7.0 ya está disponible!

Esta versión amplía lo que LocalAI puede generar y cómo manejarlo: una biblioteca de clonación de voz administrada por la interfaz de usuario, generación de avatares basada en audio y video local, y razonamiento intercalado que viaja con llamadas de herramientas. También incluye nuevos motores de audio (transcripción diaria de una sola pasada, F5-TTS, TTS de transmisión real) y un lote de correcciones de confiabilidad en la autenticación, la transcripción y la galería de modelos.

Aspectos destacados:

  • 🎙️ Clonación de voz administrada: grabe o cargue una referencia consentida en la interfaz de usuario, guárdela como un perfil reutilizable y haga referencia a ella desde cualquier backend TTS con capacidad de clonación con un URI localai://voice-profiles/<id> estable. No más YAML editado a mano ni copia de audio en carpetas de modelos.
  • 🎬 Video local y avatares: un nuevo backend longcat-video ofrece generación de avatar parlante de texto a video, de imagen a video y de audio, conectado a la interfaz de usuario de Studio con controles de audio e imagen de referencia.
  • 🧠 Pensamiento intercalado con llamadas de herramientas: un turno de asistente ahora puede llevar reasoning y tool_calls juntos y mantener el razonamiento a lo largo del ciclo herramienta-resultado, con un alias entrante reasoning_content y soporte de bloque antrópico thinking.
  • 🗣️ Nuevos motores de audio: transcripción diaria de una sola pasada (moss-transcribe-cpp), clonación de voz F5-TTS en CrispASR y TTS de transmisión real en vibevoice-cpp (tiempo hasta el primer audio 2,38 s frente a 39,96 s en la CPU).
  • 🎚️ Contexto completo automático - context_size: -1 ejecuta un modelo en su ventana de contexto completamente entrenada, lee los metadatos de GGUF por modelo, con una advertencia de ajuste de VRAM.
  • 🖥️ Control más nítido: elija en qué GPU se descarga llama.cpp (devices:) y un nuevo tiempo de reutilización de carga del modelo evita que un modelo que falla de manera determinista reaparezca su backend en cada encuesta y filtre VRAM.

Además de los modelos de galería de decodificación especulativa de DFlash, una solución OIDC para tokens firmados por EC/PS/EdDSA, configuraciones de idioma de transcripción/traducción que llegan al backend y el conjunto habitual de actualizaciones de dependencia.

🚀 Nuevas funciones y mejoras importantes

🎙️ Perfiles de clonación de voz administrados (Biblioteca de voz)

<p align="centro"> <em><img width="2880" height="1800" alt="ui-voice-library" src="https://github.com/user-attachments/assets/ea99bb2d-42b5-42b8-8c33-761090290e3f" /></em> <br><em>Registra o carga una referencia consentida, guárdala como un perfil reutilizable y haz referencia a ella desde cualquier backend TTS con capacidad de clonación.</em> </p>

La clonación de voz se convierte en un flujo de trabajo impulsado por la interfaz de usuario de primera clase. Grabe o cargue audio de referencia consentido en la interfaz de usuario de React, normalícelo a WAV, obtenga una vista previa y guárdelo como un perfil con nombre. Haga referencia al perfil desde la interfaz de usuario de TTS o /v1/audio/speech con un URI localai://voice-profiles/<id> estable, sin edición de YAML ni copia de audio en directorios de modelos.

  • Nueva superficie REST: GET /api/voice-profiles, GET /api/voice-profiles/:id/audio, POST /api/voice-profiles (admin), DELETE /api/voice-profiles/:id (admin), aparecida en Swagger, /api/instructions y el registro de capacidad de autenticación. Herramientas de administración de MCP list_voice_profiles, create_voice_profile, delete_voice_profile.
  • La nueva configuración escrita tts.voice_cloning (bool) habilita o excluye los nombres de modelos personalizados de la compatibilidad con la biblioteca de voz; false también rechaza referencias de perfil guardadas con HTTP 400. La prioridad de la solicitud es voice -> tts.voice -> tts.audio_path; Las opciones existentes todavía funcionan sin cambios importantes.
  • La compatibilidad se descubre en el servidor a partir de las capacidades del backend (el frontend codifica sin nombres de backend) y ofrece modelos de galería para instalar cuando no hay ninguno presente. La clonación se declara en el registro de capacidad para vllm-omni, vibevoice-cpp, coqui, pocket-tts, qwen-tts, qwen3-tts-cpp, faster-qwen3-tts, fish-speech, neutts, chatterbox, voxcpm, omnivoice-cpp y crispasr que depende del modelo.
  • Contrato cross-backend: referencia WAV + transcripción exacta vía params.ref_text. E2E verificado en qwen3-tts-cpp (la referencia de 4,47 s produjo un WAV no silencioso de 3,44 s y 24 kHz).

🔗 PR: #10799

🎬 Generación de avatar y vídeo de LongCat

Un nuevo backend longcat-video Python trae la generación de video local a LocalAI: texto a video, imagen a video y LongCat-Video-Avatar 1.5 para avatares parlantes controlados por audio. Está conectado a la interfaz de usuario de React Studio con controles de audio e imagen de referencia.

  • Entradas de galería longcat-video (entrada de texto+imagen, salida de vídeo) y longcat-video-avatar-1.5 (entrada de texto+imagen+audio, salida de vídeo). Imágenes de backend: CUDA 12 y CUDA 13 x86_64, más CUDA 13 ARM64 (se incluye guía DGX Spark/NVIDIA ARM64).
  • Introduce metadatos de capacidad declarativa: nuevos campos de configuración known_input_modalities / known_output_modalities para que el código genérico descubra lo que acepta un punto de control en lugar de bifurcarse en el backend o los nombres de los puntos de control. El importador HF emite metadatos de recetas autodescriptivos coincidentes.
  • El terminal /video obtiene parámetros de generación de audio y vídeo por etapas, con puesta en escena de audio distribuida (entrada limitada a 128 MiB). El modo Avatar admite generación de múltiples segmentos, cuantificación BF16 o INT8 opcional y configuraciones de destilación, documentadas en una nueva página de features/longcat-video.md.

🔗 PR: #10792

🧠 Pensamiento entrelazado con llamadas a herramientas

Un giro asistente ahora puede llevar reasoning y tool_calls juntos, y el razonamiento sobrevive al bucle herramienta-resultado a lo largo de los giros. Este es un comportamiento uniforme, probado y documentado en lugar de un accidente por backend.

  • Los mensajes de chat de OpenAI aceptan reasoning_content como alias entrante para el campo canónico reasoning (vLLM/DeepSeek/cogito-style clients lo emiten); La emisión no cambia y el campo canónico gana cuando ambos están presentes.
  • La ruta local de Anthropic Messages recorre los bloques thinking de ida y vuelta: los bloques thinking entrantes se analizan en el razonamiento del mensaje y se emite un bloque thinking antes de tool_use en las respuestas de streaming y sin transmisión, activado en el parámetro de solicitud thinking: {type: "enabled"}. La ruta de paso del proxy en la nube no se modifica.
  • Verificado en vivo: lfm2.5-8b-a1b y gemma-4-e2b devuelven reasoning más tool_calls estructurado en un solo turno. Un nuevo documento features/interleaved-thinking.md tiene enlaces cruzados de las guías de configuración del modelo, generación de texto y funciones.

🔗 PR: #10744

🗣️ Nuevos motores de audio: transcripción diaria, F5-TTS y streaming TTS

Tres adiciones amplían la superficie de audio:

  • moss-transcribe-cpp (#10756): un nuevo backend de Go que abre el puerto MOSS-Transcribe-Diarize de C++/ggml para realizar transcripciones, diarizaciones y marcas de tiempo conjuntas de varios hablantes en un solo paso sin conexión. Modelo de galería moss-transcribe-cpp-0.9b (por defecto q5_k GGUF). El puerto ggml es exacto en bytes a la referencia PyTorch y 1.6-2.2x más rápido en la CPU, exacto en bits en CUDA (verificado en Blackwell/Jetson Thor). Se construye en toda la matriz de Linux más Darwin/Metal.
  • F5-TTS en CrispASR (#10753): vincula el tiempo de ejecución estático de F5-TTS con la compilación CrispASR (SWivid, MIT; un modelo de coincidencia de flujo DiT de 22 capas con un codificador de voz Vocos incorporado) y envía un modelo de galería f5-tts-crispasr. Produce audio mono de 24 kHz y lo detecta automáticamente como f5-tts (sin selector backend:). Clonación de voz a través de options: [voice:/path/ref.wav, voice_text:Transcript...]; nota F5-TTS ejecuta un solucionador ODE de 32 pasos, por lo que la síntesis de la CPU requiere mucha computación.
  • vibevoice-cpp true streaming (#10764): reemplaza la síntesis completa de clip y luego fragmentos con transmisión incremental real a través de la nueva ABI de devolución de llamada vv_capi_tts_stream. El tiempo hasta el primer audio cae de 39,96 segundos (por lotes) a 2,38 segundos (transmisión), aproximadamente 17 veces, en una caja de solo CPU para VibeVoice-Realtime-0.5B. El alcance es el modelo en tiempo real de 0,5 mil millones; la ruta sin transmisión no cambia.

🔗 PR: #10756, #10753, #10764

🎚️ Contexto completo automático con context_size: -1

Un centinela context_size: -1 (cualquier valor negativo) ahora hace que un modelo se ejecute en su contexto entrenado completo, resuelto por modelo a partir de los metadatos de GGUF n_ctx_train durante la carga. Esto le permite optar por un modelo en su ventana máxima real incluso cuando una galería YAML ya fija un valor, sin codificar un número. Los equivalentes globales LOCALAI_CONTEXT_SIZE=-1 / --context-size -1 hacen que cada modelo se resuelva a su propio máximo entrenado, mientras que un valor explícito por modelo aún gana. Tres capas de defensa lo mantienen seguro: la resolución GGUF se degrada al valor predeterminado con una advertencia si los metadatos carecen de un máximo utilizable; un asistente warnIfContextExceedsVRAM solo para GPU registra (nunca bloquea) cuando es probable que la ventana no encaje; y la capa de opciones del backend fija cualquier negativo residual al valor predeterminado para que ningún backend reciba un n_ctx negativo. La ruta exclusiva anteriormente (context_size no configurada) no se modifica.

🔗 PR: #10752

🖥️ Selección de dispositivo GPU y tiempo de reutilización de carga del modelo

  • selección de dispositivo llama.cpp (#10724): una nueva opción device / devices en la matriz llama.cpp options: se asigna al --device ascendente, por lo que puede restringir la descarga a GPU específicas (por ejemplo, excluyendo una GPU de visualización o depuración). Ejemplo: options: [devices:CUDA1,CUDA2,CUDA3]. Los nombres de los dispositivos provienen de llama-server --list-devices.
  • Reutilización de falla de carga del modelo (#10728): después de que falla una carga, se rechazan nuevos activadores de carga independientes durante una ventana de recuperación, lo que devuelve un error escrito asignado a 503 + Retry-After en lugar de reaparecer el backend en cada encuesta. Esto evita que un modelo que falla de manera determinista pierda el estado de GPU/CUDA (un periodista vio contextos filtrados climb a ~58 GB) y, bajo LOCALAI_SINGLE_ACTIVE_BACKEND, robe la ranura activa de modelos sanos. Configurable a través de --model-load-failure-cooldown / LOCALAI_MODEL_LOAD_FAILURE_COOLDOWN (deshabilita 10s, 0 por defecto); el tiempo de reutilización se duplica por falla consecutiva, se limita a 5 m y se reinicia con una carga exitosa. Los seguidores fusionados de una ráfaga concurrente genuina aún obtienen su único reintento.

🔗 PR: #10724, #10728

🧠 Modelos

  • Modelos de decodificación especulativa Qwen DFlash (#10791): cuatro entradas de galería para el backend llama-cpp, cada una de las cuales incluye un modelo de destino completo más su pequeño redactor de difusión de bloques (los redactores no son modelos de chat independientes): qwen3-4b-dflash, qwen3.5-9b-dflash, qwen3.6-27b-dflash, qwen3.6-35b-a3b-dflash. La configuración por entrada es flash_attention: on, draft_model:, use_jinja:true, spec_type:draft-dflash, spec_n_max:15. Requiere el llama.cpp anclado con soporte DFlash ascendente; cada redactor incluido está verificado como general.architecture = dflash (los GGUF dflash-draft de solo bifurcación se excluyen intencionalmente porque no se cargan). Se recomienda GPU.
  • Valores predeterminados de inferencia (#10741): agrega valores predeterminados de muestreo recomendados para deepseek-v4 (generados automáticamente a partir de unsloth), por lo que LocalAI aplica automáticamente los parámetros de generación correctos para la familia.
  • Además, se agregaron nuevos modelos de galería a través del agente de galería (#10743, #10755).

🐛 Corrección de errores (resumen)

  • fix(auth): acepta tokens de identificación OIDC firmados por EC/PS/EdDSA, no solo RS256 (el inicio de sesión de OIDC era 500 en la devolución de llamada con tokens firmados por EC, por ejemplo, Authentik) - #10736
  • fix(transcription): honor model-config parameters.language/parameters.translate y el campo de formulario OpenAI language, que fueron ignorados silenciosamente para cargas de varias partes - #10731

  • fix(gallery): la (re)instalación backend es ahora un reemplazo atómico limpio (actualización, validación, intercambio, reversión) en lugar de una superposición, por lo que los archivos obsoletos de una versión anterior ya no ocultan la nueva - #10726
  • fix(vram): reporta el cuanto GGUF más grande en lugar de sumar cada cuanto en un repositorio HF, por lo que un modelo 9B ya no se muestra como 71 GB / "Puede que no quepa" - #10707

  • fix(vllm): fije el backend L4T arm64 a vllm==0.24.0 para estabilidad GB10/DGX Spark (0.23 falla de manera determinista en cargas frías y fija la memoria de la GPU) - #10725

  • fix(react-ui): conserva el contenido del archivo cargado al regenerar una respuesta que no sea la última (los archivos adjuntos se eliminaron silenciosamente después de bifurcar y regenerar un turno de archivo) - #10819
  • fix(ui): evita que una tabla de datos grande rompa el diseño de Flexbox y fuerce una barra de desplazamiento horizontal en toda la página - #10754

LocalAI v4.7.0

Highlights

  • Managed voice cloning — Studio can create reusable admin-managed profiles exposed through /api/voice-profiles and stable localai://voice-profiles/<id> URIs. Custom backends must opt in with tts.voice_cloning: true; request precedence is now voice → tts.voice → tts.audio_path (PR #10799).
  • Local video and avatars — The longcat-video backend adds text-to-video, image-to-video, and audio-driven avatar generation through /video. Declarative modality metadata lets generic clients discover supported inputs and outputs; avatar jobs use staged audio capped at 128 MiB (PR #10792).
  • Interleaved reasoning and tools — Assistant turns can carry reasoning alongside tool_calls and preserve reasoning across tool-result loops. reasoning_content is accepted as an inbound alias, but canonical reasoning wins when both are present; Anthropic thinking blocks round-trip only on the local path when explicitly enabled (PR #10744).
  • Expanded and faster audio engines — moss-transcribe-cpp performs offline multi-speaker transcription, diarization, and timestamps in one pass. F5-TTS adds 24 kHz cloning to CrispASR via voice/voice_text, though its 32-step solver is CPU-heavy; VibeVoice Realtime now streams incrementally, reducing CPU time-to-first-audio from 39.96s to 2.38s (PRs #10756, #10753, #10764).
  • Context, GPU, and load controls — context_size: -1 resolves each model’s trained context from GGUF metadata and warns rather than blocks on likely VRAM overflow. llama.cpp’s devices: option restricts GPU offload, while failed model loads enter an exponential cooldown and return 503 with Retry-After instead of repeatedly respawning crashing backends (PRs #10752, #10724, #10728).
  • No breaking changes — Existing APIs and configuration paths remain backward-compatible.

🎉 LocalAI 4.7.0 Release! 🚀

<h1 align="center"> <br> <img height="300" src="https://raw.githubusercontent.com/mudler/LocalAI/refs/heads/master/core/http/static/logo.png"> <br> <br> </h1>

LocalAI 4.7.0 is out!

This release widens what LocalAI can generate and how you drive it: a UI-managed voice cloning library, local video and audio-driven avatar generation, and interleaved reasoning that travels with tool calls. It also lands new audio engines (one-pass diarized transcription, F5-TTS, true streaming TTS) and a batch of reliability fixes across auth, transcription, and the model gallery.

Highlights:

  • 🎙️ Managed voice cloning - record or upload a consented reference in the UI, save it as a reusable profile, and reference it from any cloning-capable TTS backend with a stable localai://voice-profiles/<id> URI. No more hand-edited YAML or copying audio into model folders.
  • 🎬 Local video & avatars - a new longcat-video backend brings text-to-video, image-to-video, and audio-driven talking-avatar generation, wired into the Studio UI with audio and reference-image controls.
  • 🧠 Interleaved thinking with tool calls - an assistant turn can now carry reasoning and tool_calls together and keep the reasoning across the tool-result loop, with a reasoning_content inbound alias and Anthropic thinking block support.
  • 🗣️ New audio engines - one-pass diarized transcription (moss-transcribe-cpp), F5-TTS voice cloning in CrispASR, and true streaming TTS in vibevoice-cpp (time-to-first-audio 2.38s vs 39.96s on CPU).
  • 🎚️ Auto full context - context_size: -1 runs a model at its full trained context window, read from GGUF metadata per-model, with a VRAM-fit warning.
  • 🖥️ Sharper control - pick which GPUs llama.cpp offloads to (devices:), and a new model-load cooldown stops a deterministically-failing model from respawning its backend on every poll and leaking VRAM.

Plus DFlash speculative-decoding gallery models, an OIDC fix for EC/PS/EdDSA-signed tokens, transcription language/translate settings that reach the backend, and the usual set of dependency updates.

🚀 New Features & Major Enhancements

🎙️ Managed voice cloning profiles (Voice Library)

<p align="center"> <em><img width="2880" height="1800" alt="ui-voice-library" src="https://github.com/user-attachments/assets/ea99bb2d-42b5-42b8-8c33-761090290e3f" /></em> <br><em>Record or upload a consented reference, save it as a reusable profile, and reference it from any cloning-capable TTS backend.</em> </p>

Voice cloning becomes a first-class, UI-driven workflow. Record or upload consented reference audio in the React UI, normalize it to WAV, preview it, and save it as a named profile. Reference the profile from the TTS UI or /v1/audio/speech with a stable localai://voice-profiles/<id> URI, no YAML editing and no copying audio into model directories.

  • New REST surface: GET /api/voice-profiles, GET /api/voice-profiles/:id/audio, POST /api/voice-profiles (admin), DELETE /api/voice-profiles/:id (admin), surfaced in Swagger, /api/instructions, and the auth capability registry. MCP admin tools list_voice_profiles, create_voice_profile, delete_voice_profile.
  • New typed config tts.voice_cloning (bool) opts custom model names in or out of Voice Library compatibility; false also rejects saved profile references with HTTP 400. Request precedence is voice -> tts.voice -> tts.audio_path; existing options still work with no breaking change.
  • Compatibility is server-discovered from backend capabilities (the frontend hardcodes no backend names) and offers gallery models to install when none are present. Cloning is declared in the capability registry for vllm-omni, vibevoice-cpp, coqui, pocket-tts, qwen-tts, qwen3-tts-cpp, faster-qwen3-tts, fish-speech, neutts, chatterbox, voxcpm, omnivoice-cpp, and model-dependent crispasr.
  • Cross-backend contract: reference WAV + exact transcript via params.ref_text. E2E verified on qwen3-tts-cpp (4.47s reference produced a non-silent 3.44s 24kHz WAV).

🔗 PRs: #10799

🎬 LongCat video and avatar generation

A new longcat-video Python backend brings local video generation to LocalAI: text-to-video, image-to-video, and LongCat-Video-Avatar 1.5 for audio-driven talking avatars. It is wired into the React Studio UI with audio and reference-image controls.

  • Gallery entries longcat-video (text+image input, video output) and longcat-video-avatar-1.5 (text+image+audio input, video output). Backend images: CUDA 12 and CUDA 13 x86_64, plus CUDA 13 ARM64 (DGX Spark / NVIDIA ARM64 guidance included).
  • Introduces declarative capability metadata: new known_input_modalities / known_output_modalities config fields so generic code discovers what a checkpoint accepts instead of branching on backend or checkpoint names. The HF importer emits matching self-describing recipe metadata.
  • The /video endpoint gains staged audio and video-generation parameters, with distributed audio staging (input bounded to 128 MiB). Avatar mode supports multi-segment generation, BF16 or optional INT8 quantization, and distillation settings, documented in a new features/longcat-video.md page.

🔗 PRs: #10792

🧠 Interleaved thinking with tool calls

An assistant turn can now carry reasoning and tool_calls together, and the reasoning survives the tool-result loop across turns. This is uniform, tested, and documented behavior rather than a per-backend accident.

  • OpenAI chat messages accept reasoning_content as an inbound alias for the canonical reasoning field (vLLM/DeepSeek/cogito-style clients emit it); emission is unchanged and the canonical field wins when both are present.
  • The Anthropic Messages local path round-trips thinking blocks: inbound thinking blocks parse into the message reasoning, and a thinking block is emitted before tool_use on both non-streaming and streaming responses, gated on the request param thinking: {type: "enabled"}. The cloud-proxy passthrough path is untouched.
  • Verified live: lfm2.5-8b-a1b and gemma-4-e2b return reasoning plus structured tool_calls in a single turn. A new features/interleaved-thinking.md doc is cross-linked from the model-configuration, text-generation, and functions guides.

🔗 PRs: #10744

🗣️ New audio engines: diarized transcription, F5-TTS, and streaming TTS

Three additions widen the audio surface:

  • moss-transcribe-cpp (#10756): a new Go backend that dlopens the C++/ggml MOSS-Transcribe-Diarize port to do joint multi-speaker transcription, diarization, and timestamps in a single offline pass. Gallery model moss-transcribe-cpp-0.9b (default q5_k GGUF). The ggml port is byte-exact to the reference PyTorch and 1.6-2.2x faster on CPU, bit-exact on CUDA (verified on Blackwell / Jetson Thor). Builds across the full Linux matrix plus Darwin/Metal.
  • F5-TTS in CrispASR (#10753): links the F5-TTS static runtime into the CrispASR build (SWivid, MIT; a 22-layer DiT flow-matching model with a built-in Vocos vocoder) and ships an f5-tts-crispasr gallery model. Produces 24kHz mono audio and auto-detects as f5-tts (no backend: selector). Voice cloning via options: [voice:/path/ref.wav, voice_text:Transcript...]; note F5-TTS runs a 32-step ODE solver, so CPU synthesis is compute-heavy.
  • vibevoice-cpp true streaming (#10764): replaces whole-clip-then-chunk synthesis with real incremental streaming through the new vv_capi_tts_stream callback ABI. Time-to-first-audio drops from 39.96s (batch) to 2.38s (streaming), about 17x, on a CPU-only box for VibeVoice-Realtime-0.5B. Scope is the realtime-0.5B model; the non-streaming path is unchanged.

🔗 PRs: #10756, #10753, #10764

🎚️ Auto full context with context_size: -1

A context_size: -1 sentinel (any negative value) now makes a model run at its full trained context, resolved per-model from the GGUF n_ctx_train metadata at load. This lets you opt a model into its true maximum window even when a gallery YAML already pins a value, without hardcoding a number. The global equivalents LOCALAI_CONTEXT_SIZE=-1 / --context-size -1 make every model resolve to its own trained max, while an explicit per-model value still wins.

Three defense layers keep it safe: GGUF resolution degrades to the default with a warning if metadata lacks a usable max; a GPU-only warnIfContextExceedsVRAM helper logs (never blocks) when the window likely will not fit; and the backend options layer clamps any residual negative to the default so no backend receives a negative n_ctx. The previously-only path (unset context_size) is unchanged.

🔗 PRs: #10752

🖥️ GPU device selection and model-load cooldown

  • llama.cpp device selection (#10724): a new device / devices option in the llama.cpp options: array maps to upstream --device, so you can restrict offload to specific GPUs (for example excluding a display or debug GPU). Example: options: [devices:CUDA1,CUDA2,CUDA3]. Device names come from llama-server --list-devices.
  • Model-load failure cooldown (#10728): after a load fails, new independent load triggers are refused during a cooldown window, returning a typed error mapped to 503 + Retry-After instead of respawning the backend on every poll. This stops a deterministically-failing model from leaking GPU/CUDA state (a reporter saw leaked contexts climb to ~58 GB) and, under LOCALAI_SINGLE_ACTIVE_BACKEND, from stealing the active slot from healthy models. Configurable via --model-load-failure-cooldown / LOCALAI_MODEL_LOAD_FAILURE_COOLDOWN (default 10s, 0 disables); the cooldown doubles per consecutive failure, caps at 5m, and resets on a successful load. Coalesced followers of a genuine concurrent burst still get their one retry.

🔗 PRs: #10724, #10728

🧠 Models

  • Qwen DFlash speculative-decoding models (#10791): four gallery entries for the llama-cpp backend, each bundling a full target model plus its small block-diffusion drafter (drafters are not standalone chat models): qwen3-4b-dflash, qwen3.5-9b-dflash, qwen3.6-27b-dflash, qwen3.6-35b-a3b-dflash. Per-entry config is flash_attention: on, draft_model:, use_jinja:true, spec_type:draft-dflash, spec_n_max:15. Requires the pinned llama.cpp with upstream DFlash support; every bundled drafter is verified general.architecture = dflash (fork-only dflash-draft GGUFs are intentionally excluded because they fail to load). GPU recommended.
  • Inference defaults (#10741): adds recommended sampling defaults for deepseek-v4 (auto-generated from unsloth), so LocalAI applies correct generation parameters for the family automatically.
  • Plus new gallery models added via the gallery agent (#10743, #10755).

🐛 Bug Fixes (recap)

  • fix(auth): accept EC/PS/EdDSA-signed OIDC ID tokens, not just RS256 (OIDC login was 500ing at callback with EC-signed tokens, e.g. Authentik) - #10736
  • fix(transcription): honor model-config parameters.language/parameters.translate and the OpenAI language form field, which were silently ignored for multipart uploads - #10731
  • fix(backends): opus and local-store now refuse foreign model loads, so an LLM with no explicit backend cannot silently bind to the audio codec or vector store during backend probing - #10769
  • fix(gallery): backend (re)install is now a clean atomic replace (stage, validate, swap, rollback) instead of an overlay, so stale files from a prior version no longer shadow the new one - #10726
  • fix(vram): report the largest single GGUF quant instead of summing every quant in an HF repo, so a 9B model no longer shows as 71 GB / "May not fit" - #10707
  • fix(logs): capture backend stdout/stderr into the log store by default in single mode, so the Backend Logs page is populated out of the box - #10742
  • fix(vllm): pin the L4T arm64 backend to vllm==0.24.0 for GB10 / DGX Spark stability (0.23 crashes deterministically on cold loads and pins GPU memory) - #10725
  • fix(ds4): bundle the full transitive runtime dependency closure so the from-scratch DS4 image no longer exits 127 on a missing gRPC library - #10783
  • fix(diffusers,vllm-omni,tinygrad): save generated images as PNG explicitly, fixing an unknown file extension: .tmp crash right after successful inference - #10729
  • fix(react-ui): preserve uploaded file content when regenerating a non-last answer (attachments were silently dropped after forking and regenerating a file turn) - #10819
  • fix(ui): prevent a large data table from breaking the flexbox layout and forcing a page-wide horizontal scrollbar - #10754
