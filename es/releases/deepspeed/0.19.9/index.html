DeepSpeed v0.19.9

Highlights

  • Vocab-parallel and AutoTP numerics mature — PR #8838 adds Triton kernels for vocab-parallel logprob, entropy, and KL computation; the significance is that these losses no longer need a full logits gather/materialization across the tensor-parallel group, so RL and training objectives that touch the vocabulary finally scale cleanly with TP. Combined with #8782's masked-softmax stability fix and #8855 tying a row-parallel output head to the embedding (plus #8857 keeping Yuan's o_proj bias whole and replicated on every rank), the practical effect is that AutoTP layouts which previously produced shape mismatches or NaNs become loadable — worth re-running configs that failed under earlier AutoTP, but note that replicated-bias semantics now differ from sharded ones in your checkpoints.

  • MoE placement goes live and dynamic — The AffineIR work (#8800, #8885) plans expert transfers from the actual runtime placement and builds affine storage maps over live ZeRO parameters and optimizer states instead of assuming a static layout — a real step toward elastic/offloaded expert parallelism. AutoEP gains a fused Triton kernel for clamped expert activations (#8652) and a fix for nondeterministic all-gather partition-group ordering under ZeRO-3 (#8876); that ordering bug was a silent reproducibility hazard, so re-baseline MoE loss curves. Two hardening fixes — #8943 (race between folded checkpoint load and metadata drop in AutoEP+AutoTP) and #8922 (validating where column-split pieces write in a shard) — matter if you've seen flaky checkpoint restores in mixed AutoEP/AutoTP runs.

  • ZeRO optimizer-state and resume correctness — #8891 preserves fp32 master weights on ZeRO-1/ZeRO-2 when a resume skips optimizer state, closing a subtle trap where a fresh optimizer rebuilds masters from bf16/fp16 and quietly loses precision. #8647 restores fp16 hysteresis handling in the stage-0 fp16 optimizers, aligning loss-scaling behavior across stages, and #8642 fixes scalar-parameter byte-view broadcasts that could corrupt 0-d tensors. If you depend on stage-0 fp16 loss scaling or resume-without-optimizer workflows, upgrading changes numerical behavior — revalidate convergence rather than assuming bit-identical checkpoints.

  • CPU Adam gets RISC-V vectorization — #8817 adds an RVV (RISC-V Vector) FP32 kernel to CPU Adam, giving genuine throughput gains for CPU-offload or CPU-only training on emerging RISC-V many-core hardware with no code changes; dispatch is automatic, so x86 users see no change. Alongside the new v1 multi-rank CPU suite (#8926, manual dispatch for now) and the fix skipping accelerator-only optimizer tests on CPU accelerators (#8836), this signals sustained investment in the CPU path — a good sign if CPU offload is part of your stack.

  • Profiling gets cheaper and more compatible — #8909 fixes a throughput regression introduced by the comms logger (plus a bug in comms_logger.enabled), and #8795 skips accelerator synchronization for unprofiled communication ops; both are direct step-time recoveries, so re-measure if you noticed slowdowns after enabling profiling. #8900 moves to NVTX's module-level API so domain ranges render on older NVTX releases, meaning existing traces gain correct domain labels without a toolchain upgrade. Net: profiling is lighter and broader, but captured timelines may look different than before.

  • RL rollout efficiency and CI/docs hygiene — #8839 makes OPSD HybridEngine rollout prefill request only last-position logits, trimming memory and compute on long generations — directly relevant for on-policy/RLHF-style generation. The remainder is maintenance with no runtime API impact: CI Python bumps to 3.12 (#8902, #8921), TORCHINDUCTOR_COMPILE_THREADS=1 to eliminate 300s timeouts (#8914), and ~35 dead-link fixes across EN/CN docs (#8688, #8894), reducing CI flakiness and broken onboarding links.

No breaking changes reported in this release.
