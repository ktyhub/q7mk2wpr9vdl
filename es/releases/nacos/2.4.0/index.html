#nacos 2.4.0

Utilice primero 2.4.0.1 Esta versión es una versión importante que admite muchas funciones nuevas. La característica más importante es que el mantenedor de soporte de Nacos inicializa la contraseña del usuario administrador nacos en lugar de usar la contraseña predeterminada para mejorar la seguridad predeterminada para implementar clústeres de Nacos. Una cosa más son las operaciones de derby API deshabilitadas de forma predeterminada para evitar falsas alarmas con respecto a los riesgos correspondientes para los usuarios sin autenticación habilitada cuando se implementa en modo independiente. Si los mantenedores quieren usar este API para mantener y consultar datos en derby, los mantenedores pueden usar nacos.config.derby.ops.enabled=true para abrir este API. Y otras características principales son la compatibilidad con la comunicación TLS Grpc entre los nodos del clúster de Nacos como una característica opcional para mejorar la seguridad de Nacos, lo que significa que los nacos no solo admiten la comunicación TLS entre client y el servidor; Es más, Nacos comienza a admitir que el usuario extienda Selector antes de la devolución de llamada Subscriber para el módulo de nombres, no solo puede seleccionar instancias de servicios por estado y clústeres. Y el servicio de devolución de llamada de soporte de Nacos client se diferencia por un nuevo evento para reducir el caché de Subscriber y comparar la lógica. Las terceras características principales son admitir algunos usos de configuración en la consola Nacos y admitir un mayor uso de mejoras para complementos, como admitir la adición de todos los metadatos al protocolo prometheus sd y admitir la firma aliyun ram v4. Además de importantes actualizaciones de funciones, esta versión también corrige algunos errores de versiones anteriores y actualiza ciertas dependencias con vulnerabilidades de seguridad. nacos 2.4.0

Please use 2.4.0.1 first

This version is an important version which support many new features.

The most mainly feature is Nacos support maintainer to initialize the admin user nacos password instead of using default password to improve the default security for deploy nacos clusters.

One more thing is default disabled derby ops API to prevent false alarms regarding corresponding risks for users without authentication enabled when deploying in standalone mode. If maintainers want use this API to maintain and query data in derby, maintainers can use nacos.config.derby.ops.enabled=true to open this API.

And other mainly features are support TLS Grpc communication between Nacos cluster nodes as an optional feature to improve Nacos security, which means nacos not only support TLS communication between client and server; What's more, Nacos start to support user extend Selector before callback Subscriber for naming module, not only can select instance of services by healthy and clusters. And Nacos client support callback service diffs by new event to reduce Subscriber cache and compare logics.

Third mainly features are support some configs usages in Nacos console and support more enhancement usage for plugins, such as support add all metadata to prometheus sd protocol and support aliyun ram v4 signature.

In addition to substantial feature updates, this version also fixes some bugs from previous versions and upgrades certain dependencies with security vulnerabilities.
