#Nacos 3.3.0

Nacos 3.3.0 es una versión de iteración de funciones para la serie Nacos 3.x. Aporta a la versión estable la gestión y el descubrimiento de agentes independientes del protocolo, la búsqueda compartida de recursos de IA y la gestión unificada del ciclo de vida de MCP.

Esta versión se centra en:

  • Capacidades de registro de IA en recursos de agente, especificación de agente, habilidad, aviso y MCP.
  • Descubrimiento de servicios DNS y bloqueos distribuidos.
  • Gestión dinámica de complementos y autenticación habilitadas de forma predeterminada.
  • Compatibilidad con Spring Boot 4 y Jackson 3, con client y confiabilidad del servidor mejoradas.

Las principales actualizaciones de funciones incluyen:

  • Registro de agentes, gestión de versiones, puntos finales de tiempo de ejecución, descubrimiento de RAD, negociación de transporte y visualización/impresión a través de flujos de trabajo de consola y SDK de Java.
  • Búsqueda de recursos de IA compartida con recuperación híbrida de palabras clave y vectores, acceso a artefactos y filtrado de relevancia opcional.
  • Redacción, revisión, publicación, en línea/fuera de línea y gestión de visibilidad de MCP, con soporte de migración para recursos históricos.
  • Descubrimiento de DNS opcional con registros A, AAAA y SRV a través de UDP y TCP.
  • Cerraduras distribuidas reentrantes y no reentrantes con renovación de vigilancia y consistencia Raft.

La versión estable también mejora la coherencia de los metadatos de Skill en las transiciones de versiones, amplía las capacidades del complemento de visibilidad y fortalece la usabilidad de Config SDK, la compatibilidad con la consola y la recuperación después de que Naming se reconecta y se reinicia el clúster.

Estas notas son acumulativas e incluyen los cambios entregados en 3.3.0-BETA y 3.3.0-RC.

Aviso de cambio importante

Nacos 3.3.0 cambia los valores predeterminados de autenticación, deshabilita los API obsoletos seleccionados e introduce requisitos de migración. Las aplicaciones que utilizan el nuevo Agente SDK de BETA o RC también deben revisar el contrato de suscripción finalizado.

Usuarios afectados:

  • Aplicaciones que dependen de Client API sin credenciales o en puntos finales de importación de Pipeline y MCP obsoletos.
  • Implementaciones con datos de configuración heredados, claves de almacenamiento de IA históricas, registros de Raft sin etiquetar o recursos A2A/MCP que requieren migración.
  • Aplicaciones que se basan en métricas Prometheus client integradas o valores predeterminados de visibilidad de recursos de IA implícitos.
  • Adoptantes BETA/RC que utilizan suscripciones RAD o acceden de forma remota al servidor DNS opcional.

Ruta de actualización recomendada:

  • Prepare las credenciales de Client API. Un nacos.core.auth.enabled ausente ahora significa true. Las configuraciones explícitas existentes de false siguen siendo efectivas. Si es necesario, mantenga la autenticación explícitamente deshabilitada durante el aprovisionamiento de credenciales y luego habilítela de manera consistente en todo el clúster después de verificar el acceso a client. Los valores predeterminados de autenticación de administrador y consola no cambian.
  • Migrar llamadas AI API obsoletas. Los puntos finales de importación de MCP de consola y canalización heredados seleccionados devuelven HTTP 410 con API_DEPRECATED de forma predeterminada. Utilice los puntos finales Pipeline /list y /detail y los puntos finales unificados /v3/console/ai/import/validate y /execute. nacos.core.api.compatibility.enabled=true vuelve a abrir temporalmente los puntos finales seleccionados; nacos.ai.resource.import.legacy-mcp-api-enabled ya no se reconoce.
  • Completar migraciones de configuración heredadas. Actualice las implementaciones anteriores a 3.0 a través de una versión anterior de Nacos 3.x. Migre los datos del espacio de nombres predeterminado del inquilino vacío a public y los datos beta/de etiquetas heredados a config_info_gray. Para el proveedor de almacenamiento de IA nacos_config, migre explícitamente las coordenadas históricas afectadas no ASCII o de configuración excesivas al mapeo determinista seguro para ASCII.
  • Verifique los registros persistentes de Raft. Nacos 3.3 ya no reproduce entradas sin etiquetar, incluidas las entradas escritas originalmente por Nacos 2.0.x y retenidas a través de actualizaciones intermedias. Recupere y migre esos registros o instantáneas con una versión compatible antes de actualizar; cambiar la versión en ejecución por sí solo no convierte los registros persistentes.
  • Planificar la migración histórica de A2A y MCP. El nacos.ai.a2a.compatibility.mode=CANONICAL predeterminado no escanea datos históricos de A2A. Siga el runbook de actualización de A2A para la migración de AUTO y la verificación previa temprana de 3.3. Después de la transición canónica permanente, los servidores exclusivos no deben volver a unirse. Preservar el estado de reconciliación de MCP y sus datos de servicio de configuración/nombramiento existentes durante la transición unidireccional del ciclo de vida.
  • Mantenga las identidades del servidor del clúster consistentes. La autenticación nativa de JRaft se aplica después de que todos los miembros anuncian su soporte y la aplicación persiste durante los reinicios. No se garantiza que las rebajas continuas para miembros sin soporte de credenciales JRaft sigan estando disponibles.
  • Actualización de consumidores del Agente BETA/RC SDK. Los nuevos métodos RAD subscribeAgent ahora devuelven void. Reciba tanto el estado inicial como las actualizaciones posteriores a través del Listener, prepare el estado del Listener antes de suscribirse y vuelva a compilar las aplicaciones dependientes. Las firmas A2A heredadas y los contratos de transferencia HTTP/gRPC permanecen sin cambios.
  • Configurar las métricas de client explícitamente. nacos-client ya no incluye una dependencia obligatoria de Prometheus client. Instalar una implementación de NacosClientMetricsProvider cuando se requieran métricas; sin uno, la grabación no funciona incluso cuando enableClientMetrics está habilitado.
  • Revisar la configuración de visibilidad e importación de MCP. Los destinos de importación de MCP privados o locales requieren nacos.console.ai.mcp.import.allowed-private-addresses y no se siguen las redirecciones. El complemento de visibilidad incorporado establece de forma predeterminada los recursos de Agente y MCP recién creados en PUBLIC; Elija explícitamente un ámbito privado cuando sea necesario. Los ámbitos almacenados existentes y los valores predeterminados de Prompt/Skill no se modifican.
  • Revisar la configuración del detector de DNS. DNS sigue siendo opcional y está deshabilitado de forma predeterminada. Cuando está habilitado, nacos.naming.dns.bind-address por defecto es 127.0.0.1; configure la dirección de escucha prevista para clients remotos. El reenvío externo requiere una configuración explícita separada.
  • Actualizar los metadatos de las habilidades afectadas. Los descriptores de habilidades históricas sin información preliminar analizada conservan sus metadatos existentes; Esta versión no lee automáticamente sus paquetes ni completa los metadatos faltantes. Actualice el contenido o vuelva a cargar las habilidades afectadas para regenerar el contenido inicial y corregir las descripciones multilínea previamente almacenadas.
  • Haga una copia de seguridad y ensaye la actualización. Haga una copia de seguridad de la base de datos y de los datos persistentes del servidor, luego verifique la autenticación, la migración de datos, el descubrimiento y el comportamiento de client en la etapa de preparación. Derby integrado se actualizó a 10.16.1.1, por lo que incluye lecturas de datos persistentes, escrituras posteriores y reinicio de recuperación en la validación de la actualización.

Las implementaciones sin los datos históricos afectados no requieren esas migraciones de datos. Los valores predeterminados de autenticación y cualquier cambio aplicable de API o SDK aún deben revisarse.

Nacos 3.3.0

Nacos 3.3.0 is a feature iteration release for the Nacos 3.x series. It brings protocol-neutral Agent management and discovery, shared AI resource search, and unified MCP lifecycle management to the stable release.

This release focuses on:

  • AI Registry capabilities across Agent, AgentSpec, Skill, Prompt, and MCP resources.
  • DNS service discovery and distributed locks.
  • Dynamic plugin management and authentication enabled by default.
  • Spring Boot 4 and Jackson 3 compatibility, with improved client and server reliability.

The main feature updates include:

  • Agent registration, version management, runtime endpoints, RAD discovery, transport negotiation, and Watch/Push through Java SDKs and Console workflows.
  • Shared AI resource search with hybrid keyword and vector retrieval, artifact access, and optional relevance filtering.
  • MCP draft, review, publish, online/offline, and visibility management, with migration support for historical resources.
  • Optional DNS discovery with A, AAAA, and SRV records over UDP and TCP.
  • Distributed reentrant and non-reentrant locks with watchdog renewal and Raft consistency.

The stable release also improves Skill metadata consistency across version transitions, extends visibility plugin capabilities, and strengthens Config SDK usability, Console compatibility, and recovery after Naming reconnects and cluster restarts.

These notes are cumulative and include the changes delivered in 3.3.0-BETA and 3.3.0-RC.

Breaking Change Notice

Nacos 3.3.0 changes authentication defaults, disables selected deprecated APIs, and introduces migration requirements. Applications using the new Agent SDK from BETA or RC also need to review the finalized subscription contract.

Affected users:

  • Applications relying on Client APIs without credentials or on deprecated Pipeline and MCP import endpoints.
  • Deployments with legacy Config data, historical AI storage keys, untagged Raft logs, or A2A/MCP resources requiring migration.
  • Applications relying on built-in Prometheus client metrics or implicit AI resource visibility defaults.
  • BETA/RC adopters using RAD subscriptions or remotely accessing the optional DNS server.

Recommended upgrade path:

  • Prepare Client API credentials. An absent nacos.core.auth.enabled now means true. Existing explicit false settings remain effective. If necessary, keep authentication explicitly disabled during credential provisioning, then enable it consistently across the cluster after verifying client access. Admin and Console authentication defaults are unchanged.
  • Migrate deprecated AI API calls. Selected legacy Pipeline and Console MCP import endpoints return HTTP 410 with API_DEPRECATED by default. Use the Pipeline /list and /detail endpoints and unified /v3/console/ai/import/validate and /execute endpoints. nacos.core.api.compatibility.enabled=true temporarily reopens the selected endpoints; nacos.ai.resource.import.legacy-mcp-api-enabled is no longer recognized.
  • Complete legacy Config migrations. Upgrade pre-3.0 deployments through an earlier Nacos 3.x version. Migrate default-namespace data from the empty tenant to public, and legacy beta/tag data to config_info_gray. For the nacos_config AI storage provider, explicitly migrate affected historical non-ASCII or overlength Config coordinates to the deterministic ASCII-safe mapping.
  • Check persisted Raft logs. Nacos 3.3 no longer replays untagged entries, including entries originally written by Nacos 2.0.x and retained through intermediate upgrades. Recover and migrate those logs or snapshots with a compatible version before upgrading; changing the running version alone does not convert persisted logs.
  • Plan historical A2A and MCP migration. The default nacos.ai.a2a.compatibility.mode=CANONICAL does not scan historical A2A data. Follow the A2A upgrade runbook for AUTO migration and early-3.3 preflight. After permanent canonical cutover, legacy-only servers must not rejoin. Preserve MCP reconciliation state and its existing Config/Naming serving data during the one-way lifecycle transition.
  • Keep cluster server identities consistent. Native JRaft authentication becomes enforced after all members advertise support, and enforcement persists across restarts. Rolling downgrades to members without JRaft credential support are not guaranteed to remain available.
  • Update BETA/RC Agent SDK consumers. The new RAD subscribeAgent methods now return void. Receive both initial state and subsequent updates through the Listener, prepare Listener state before subscribing, and recompile dependent applications. Legacy A2A signatures and HTTP/gRPC wire contracts remain unchanged.
  • Configure client metrics explicitly. nacos-client no longer includes a mandatory Prometheus client dependency. Install an implementation of NacosClientMetricsProvider when metrics are required; without one, recording is a no-op even when enableClientMetrics is enabled.
  • Review MCP import and visibility settings. Private or local MCP import targets require nacos.console.ai.mcp.import.allowed-private-addresses, and redirects are not followed. The built-in visibility plugin defaults newly created Agent and MCP resources to PUBLIC; explicitly choose a private scope where required. Existing stored scopes and Prompt/Skill defaults are unchanged.
  • Review DNS listener configuration. DNS remains optional and disabled by default. When enabled, nacos.naming.dns.bind-address defaults to 127.0.0.1; configure the intended listening address for remote clients. External forwarding requires separate explicit configuration.
  • Refresh affected Skill metadata. Historical Skill descriptors without parsed frontmatter retain their existing metadata; this release does not automatically read their packages or backfill missing metadata. Update the content or re-upload affected Skills to regenerate frontmatter and correct previously stored multiline descriptions.
  • Back up and rehearse the upgrade. Back up the database and persisted server data, then verify authentication, data migration, discovery, and client behavior in staging. Embedded Derby is upgraded to 10.16.1.1, so include persisted-data reads, subsequent writes, and restart recovery in upgrade validation.

Deployments without the affected historical data do not require those data migrations. The authentication defaults and any applicable API or SDK changes still need review.
