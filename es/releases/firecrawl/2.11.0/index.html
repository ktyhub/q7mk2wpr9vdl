Firecrawl v2.11.0

Mejoras

  • Índice de investigación de Firecrawl: se agregó un índice especializado para la investigación de inteligencia artificial y aprendizaje automático: busque en más de 3M artículos arXiv y el código GitHub detrás de ellos (problemas, relaciones públicas fusionadas y archivos README, actualizados diariamente), obtenga los detalles de un artículo o el trabajo relacionado, y verifique las afirmaciones con el texto completo. Tiene un recuerdo de última generación en arXivQA, superando al siguiente mejor proveedor en un 18% a un costo comparable. Disponible a través de API, SDK, MCP y CLI.
  • Acceso sin llave para terminales principales: use /scrape, /search, /interact y /parse sin una clave API de MCP oficial, CLI y SDK clients.
  • Redacción automática de PII: se agregó una opción redactPII que elimina datos personales y confidenciales como nombres, correos electrónicos, números de teléfono, direcciones y secretos del contenido extraído antes de que se devuelva.
  • Formato deterministicJson: se agregó un formato que devuelve JSON estructurado sin ejecutar un LLM en cada solicitud. Firecrawl genera un extractor reutilizable para su esquema y lo almacena en caché por sitio, por lo que los raspados repetidos son más baratos y arrojan resultados consistentes.
  • Descubrimiento de videos en cualquier página: se amplió el formato video para buscar videos en cualquier página, no solo en proveedores compatibles como YouTube, devolviendo la URL, el título, la miniatura, la duración y más de cada video.
  • Adjunte su propia automatización del navegador: se agregó una URL de CDP WebSocket (cdpUrl) a las respuestas de la sesión del navegador, para que pueda ejecutar una sesión de navegador Firecrawl en vivo directamente con Playwright, Puppeteer o cualquier otro CDP client.
  • Alertas de monitor más inteligentes: se agregó un goal a los monitores para que un LLM juzgue cada cambio detectado como significativo o ruido en comparación con lo que realmente le interesa, reduciendo el spam de alertas y mostrando los cambios que importan primero en correos electrónicos resumidos.
  • Diferencias de JSON a nivel de campo para monitores: los monitores que raspan en el modo JSON ahora comparan los valores de campo reales entre ejecuciones en lugar de la página renderizada, para que pueda ver exactamente qué campos cambiaron en lugar del ruido de los cambios de diseño.
  • Confirmación por correo electrónico del monitor: se agregó un flujo de confirmación de suscripción con cancelación de suscripción one-click para destinatarios del monitor externo; Los miembros del equipo se confirman automáticamente y las respuestas de Monitor ahora informan el estado de suscripción de cada destinatario.
  • Horarios de monitorización AM/PM: se agregó soporte para entradas de horarios de 12 horas como daily at 9am y daily at 5:30pm, convertidas a la expresión cron UTC correcta.
  • Monitorear el estado de entrega del webhook: se agregó el estado de entrega a cada verificación del monitor, para que pueda ver si su webhook se intentó, se entregó o falló, y por qué.
  • Comprobaciones de monitor más constantes: los monitores ahora esperan a que las páginas terminen de renderizarse antes de realizar diferencias, lo que elimina las alertas falsas causadas por páginas parcialmente cargadas.
  • Límite de tamaño de PDF: aumentó el límite de tamaño de descarga y raspado de PDF de 30 MB a 50 MB.
  • Python SDK crawl() kwargs de raspado: se agregaron kwargs de raspado directo (formats, headers, include_tags, exclude_tags, etc.) a crawl() y start_crawl(), eliminando la necesidad de envolverlos en ScrapeOptions(...).
  • Errores .data más claros: se mejoró el error que aparece al acceder a .data en un resultado de búsqueda para señalar .web, .news y .images con sus recuentos, en lugar de devolver un None silencioso.
  • Valores predeterminados del formato Python: se eliminó el argumento type= requerido en JsonFormat y ChangeTrackingFormat, de forma predeterminada como ScreenshotFormat.
  • carcasa ChangeTrackingFormat: se agregó aceptación de change_tracking y changeTracking para el formato type, de modo que las cargas útiles sean de ida y vuelta entre Snake_case y camelCase clients.

Correcciones

  • Se resolvieron avisos de seguridad en los API y SDK mediante la actualización de axios, esbuild, ws, openssl y otras dependencias.

  • Se corrigió que los trabajadores de scrape se detuvieran durante decenas de segundos en entradas de extractores LLM muy grandes, lo que anteriormente causaba abandonos de trabajos y reinicios de trabajadores.

  • Se corrigieron los fragmentos de Wikipedia que faltaban metadata.ogImage en aproximadamente la mitad de las URL de Wikimedia.

  • Se corrigió el rastreo y la cancelación de lotes que no agotaban el trabajo pendiente de simultaneidad por equipo ni informaban el estado obsoleto; Los trabajos en cola ahora se eliminan y status informa cancelled inmediatamente.

  • Se corrigió el cargo de cheques de monitor cuando se denegaba el bloqueo de crédito; Los bloqueos denegados ahora marcan la marca skipped_no_credits y detiene la ejecución.

  • Se corrigieron las diferencias del monitor en modo JSON que devolvían veredictos falsos de changed cuando los valores de los campos eran idénticos pero estaban reordenados; Las diferencias ahora usan igualdad insensible al orden.

  • Se corrigieron los monitores en modo JSON que trataban un raspado de cadena vacía como entrada faltante e informaban changed en cada ejecución.

  • Se corrigieron los webhooks del monitor que se enviaban dos veces para la misma verificación.

  • Se corrigió que los webhooks del monitor se eliminaran por estar mal formados al envolver las cargas útiles monitor.page y monitor.check.completed en una matriz para que coincida con la forma de rastreo/lote.

  • Se corrigió que el juez monitor inventara texto antes/después y perdiera contexto en páginas largas; ahora recibe la diferencia unificada completa como única evidencia.

  • Se corrigieron artefactos almacenados corruptos o inesperados que rompían GET /v2/monitor/:id/checks/:checkId; Los datos incorrectos ahora aparecen como sin diferencia.

  • Se corrigieron las tablas HTML que perdían su fila de encabezado cuando la primera fila usaba celdas td; el convertidor de rebajas ahora lo promociona a un encabezado para que las etiquetas de las columnas sobrevivan en document.markdown.

  • Se corrigió el límite de tamaño de PDF que se omitía en ciertas rutas de raspado, por lo que los PDF de gran tamaño ahora se rechazan de manera consistente.

  • Se corrigieron las opciones de ChangeTrackingFormat (modes, prompt y campos relacionados) que se eliminaban durante los viajes de ida y vuelta de serialización de Python SDK. ##API

  • Se reemplazó el formato experimental pii con redactPII (boolean o { mode?, entities?, replaceStyle? }) en POST /v2/scrape, /v2/batch/scrape, /v2/crawl, /v2/parse y /v2/extract; cuando está habilitado, document.markdown devuelve texto redactado (los valores predeterminados son mode: "accurate", replaceStyle: "tag"). Se eliminan el antiguo formato pii y el bloque document.pii, y ahora se rechazan las solicitudes que incluyen "pii" en formats.

  • Se agregó el formato deterministicJson ({ type: "deterministicJson", schema?, prompt? }) a POST /v2/scrape, /v2/batch/scrape, /v2/crawl, /v2/parse y /v2/extract, completando document.json. No se puede combinar con el formato json.

  • Se agregó document.videos: VideoItem[] (con url, sourceURL, source y title, thumbnail, duration opcionales, dimensiones y más) a POST /v2/scrape y los puntos finales que comparten sus opciones cuando se solicita el formato video. La cadena document.video heredada permanece para los proveedores compatibles.

  • Se agregaron createdAt, completedAt y duration (segundos) a GET /v2/crawl/{id} y GET /v2/batch/scrape/{id}; completedAt está presente sólo en estados terminales.

  • Se agregó el proxy /v2/search/research (GET /v2/search/research/papers, /papers/:id, /papers/:id/similar y /github) facturado contra SEARCH_CREDITS a 2 créditos por 10 resultados (10 por 10 para equipos ZDR). El montaje heredado /v2/research/* se mantiene como un alias obsoleto.

  • Se agregaron POST/GET /interact, POST /interact/:sessionId/execute y DELETE /interact/:sessionId como alias completos para los puntos finales de sesión /v2/browser; El comportamiento, los límites de tasas y el cargo de creación de sesión de 2 créditos son idénticos.

  • Se agregó cdpUrl (Python: cdp_url) a las respuestas de ejecución de POST /v2/scrape/:jobId/interact y /v2/browser, exponiendo la URL sin formato del CDP WebSocket junto con las URL de visualización en vivo existentes.

  • Se agregó POST /v2/feedback que cubre trabajos de búsqueda, extracción, análisis y mapeo con lógica de reembolso y grabación compartida; el POST /v2/search/:jobId/feedback heredado sigue funcionando y escribe en la misma tienda.

  • Se agregó acceso sin llave a POST /v2/parse, coincidencia de raspado y búsqueda, y contabilidad de crédito sin llave más estricta para que las solicitudes simultáneas se mantengan dentro del límite diario por IP.

  • Se agregó un encabezado WWW-Authenticate: Bearer realm="firecrawl" a todas las respuestas 401 en /v0, /v1 y /v2 para que el agente clients pueda descubrir el esquema de credenciales.

  • Se agregaron los valores searchZDR "forced-zdr" y "forced-anon" y se obsoleto "forced" (ahora un alias para "forced-zdr"); el modo resuelto impulsa tanto la facturación como el enrutamiento.

  • Se agregaron goal y judgeEnabled a POST /v2/monitor y PATCH /v2/monitor/:id; judgeEnabled tiene como valor predeterminado true cuando se configura goal y goal: null lo borra.

  • Se agregaron judgment, meaningfulChange (con un reason por cambio), meaningfulChanges[], un objeto estructurado diff (text y/o json) y un campo snapshot para monitorear las páginas de verificación; Las comprobaciones en modo JSON devuelven diferencias a nivel de campo más una instantánea del valor actual.

  • Se agregaron POST /v2/monitor/email/confirm y POST /v2/monitor/email/unsubscribe no autenticados (token aceptado solo en el cuerpo de la solicitud), además de una matriz emailRecipientSubscriptions en las respuestas Monitor que informan los email, status (pending/confirmed/unsubscribed), source y confirmationEmailSent de cada destinatario.

  • Se agregó origin para monitorear los cuerpos de creación/actualización, coincidiendo con los otros puntos finales v2.

  • Se agregó una validación más estricta en delay para POST /v2/crawl y POST /v1/crawl; Los valores no numéricos, negativos o superiores a 86400 ahora se rechazan con un error de esquema en lugar de aplicarse silenciosamente.

  • Se agregaron include_domains y exclude_domains a la sincronización Firecrawl.search() del Python SDK, coincidiendo con la carga útil asíncrona client y /v2/search.

  • Se agregaron alias de métodos compatibles con V1 (scrape_url/scrapeUrl, crawl_url/crawlUrl, batch_scrape_urls, map_url, etc.) en V2 Python y JS clients; Los alias emiten un DeprecationWarning.

  • Se cambió la carga útil del webhook del monitor para envolver data en una matriz; monitor.page ahora incluye isMeaningful, judgment y un objeto diff.

  • Monitor normalizado scrapeOptions.formats para que el modo changeTracking json se reescriba a json, y el formato mixto ["json", "git-diff"] ahora ejecuta ambas diferencias en lugar de volver a recurrir silenciosamente a una.

firecrawl v2.11.0

Firecrawl v2.11.0

Improvements

  • Firecrawl Research Index — Added a specialized index for agentic AI/ML research: search across 3M+ arXiv papers and the GitHub code behind them (issues, merged PRs, and READMEs, refreshed daily), fetch a paper's details or related work, and check claims against full text. It has state-of-the-art recall on arXivQA, outperforming the next best provider by 18% at comparable cost. Available via the API, SDKs, MCP, and CLI.
  • Keyless access for core endpoints — Use /scrape, /search, /interact, and /parse without an API key from official MCP, CLI, and SDK clients.
  • Automatic PII redaction — Added a redactPII option that strips personal and sensitive data like names, emails, phone numbers, addresses, and secrets out of scraped content before it's returned.
  • deterministicJson format — Added a format that returns structured JSON without running an LLM on every request. Firecrawl generates a reusable extractor for your schema and caches it per site, so repeat scrapes are cheaper and return consistent results.
  • Video discovery on any page — Expanded the video format to find videos on any page, not just supported providers like YouTube, returning each video's URL, title, thumbnail, duration, and more.
  • Attach your own browser automation — Added a CDP WebSocket URL (cdpUrl) to browser session responses, so you can drive a live Firecrawl browser session directly with Playwright, Puppeteer, or any other CDP client.
  • Smarter monitor alerts — Added a goal to monitors so an LLM judges each detected change as meaningful or noise against what you actually care about, cutting alert spam and surfacing the changes that matter first in summary emails.
  • Field-level JSON diffs for monitors — Monitors that scrape in JSON mode now compare the actual field values between runs instead of the rendered page, so you see exactly which fields changed rather than noise from layout shifts.
  • Monitor email confirmation — Added an opt-in confirmation flow with one-click unsubscribe for external monitor recipients; team members are auto-confirmed, and Monitor responses now report each recipient's subscription status.
  • AM/PM monitor schedules — Added support for 12-hour schedule inputs like daily at 9am and daily at 5:30pm, converted to the correct UTC cron expression.
  • Monitor webhook delivery status — Added delivery status to each monitor check, so you can see whether its webhook was attempted, delivered, or failed — and why.
  • Steadier monitor checks — Monitors now wait for pages to finish rendering before diffing, cutting false alerts caused by partially-loaded pages.
  • PDF size cap — Raised the PDF download and scrape size cap from 30 MB to 50 MB.
  • Python SDK crawl() scrape kwargs — Added direct scrape kwargs (formats, headers, include_tags, exclude_tags, etc.) to crawl() and start_crawl(), removing the need to wrap them in ScrapeOptions(...).
  • Clearer .data errors — Improved the error raised when accessing .data on a search result to point at .web, .news, and .images with their counts, instead of returning a silent None.
  • Python format defaults — Removed the required type= argument on JsonFormat and ChangeTrackingFormat, defaulting it like ScreenshotFormat.
  • ChangeTrackingFormat casing — Added acceptance of both change_tracking and changeTracking for the format type so payloads round-trip between snake_case and camelCase clients.

Fixes

  • Resolved security advisories across the API and SDKs by upgrading axios, esbuild, ws, openssl, and other dependencies.
  • Fixed scrape workers stalling for tens of seconds on very large LLM-extractor inputs, which previously caused dropped jobs and worker restarts.
  • Fixed Wikipedia scrapes missing metadata.ogImage on roughly half of Wikimedia URLs.
  • Fixed crawl and batch cancellation not draining the per-team concurrency backlog and reporting stale state; queued jobs are now removed and status reports cancelled immediately.
  • Fixed monitor checks being charged when the credit lock was denied; denied locks now mark the check skipped_no_credits and stop the run.
  • Fixed JSON-mode monitor diffs returning spurious changed verdicts when field values were identical but reordered; diffs now use order-insensitive equality.
  • Fixed JSON-mode monitors treating an empty-string scrape as missing input and reporting changed on every run.
  • Fixed monitor webhooks being dispatched twice for the same check.
  • Fixed monitor webhooks being dropped as malformed by wrapping monitor.page and monitor.check.completed payloads in an array to match the crawl/batch shape.
  • Fixed the monitor judge fabricating before/after text and losing context on long pages; it now receives the full unified diff as its only evidence.
  • Fixed corrupt or unexpected stored artifacts breaking GET /v2/monitor/:id/checks/:checkId; bad data now surfaces as no diff.
  • Fixed HTML tables losing their header row when the first row used td cells; the markdown converter now promotes it to a header so column labels survive into document.markdown.
  • Fixed the PDF size cap being bypassed on certain scrape paths so oversized PDFs are now rejected consistently.
  • Fixed ChangeTrackingFormat options (modes, prompt, and related fields) being dropped through Python SDK serialization round-trips.

API

  • Replaced the experimental pii format with redactPII (boolean or { mode?, entities?, replaceStyle? }) on POST /v2/scrape, /v2/batch/scrape, /v2/crawl, /v2/parse, and /v2/extract; when enabled, document.markdown returns redacted text (defaults mode: "accurate", replaceStyle: "tag"). The old pii format and document.pii block are removed, and requests including "pii" in formats are now rejected.
  • Added the deterministicJson format ({ type: "deterministicJson", schema?, prompt? }) to POST /v2/scrape, /v2/batch/scrape, /v2/crawl, /v2/parse, and /v2/extract, populating document.json. Cannot be combined with the json format.
  • Added document.videos: VideoItem[] (with url, sourceURL, source, and optional title, thumbnail, duration, dimensions, and more) to POST /v2/scrape and the endpoints sharing its options when the video format is requested. The legacy document.video string remains for supported providers.
  • Added createdAt, completedAt, and duration (seconds) to GET /v2/crawl/{id} and GET /v2/batch/scrape/{id}; completedAt is present only on terminal states.
  • Added the /v2/search/research proxy — GET /v2/search/research/papers, /papers/:id, /papers/:id/similar, and /github — billed against SEARCH_CREDITS at 2 credits per 10 results (10 per 10 for ZDR teams). The legacy /v2/research/* mount is kept as a deprecated alias.
  • Added POST/GET /interact, POST /interact/:sessionId/execute, and DELETE /interact/:sessionId as full aliases for the /v2/browser session endpoints; behavior, rate limits, and the 2-credit session-create charge are identical.
  • Added cdpUrl (Python: cdp_url) to the POST /v2/scrape/:jobId/interact and /v2/browser execute responses, exposing the raw CDP WebSocket URL alongside the existing live-view URLs.
  • Added POST /v2/feedback covering search, scrape, parse, and map jobs with shared recording and refund logic; the legacy POST /v2/search/:jobId/feedback keeps working and writes to the same store.
  • Added keyless access to POST /v2/parse, matching scrape and search, and tightened keyless credit accounting so concurrent requests stay within the per-IP daily cap.
  • Added a WWW-Authenticate: Bearer realm="firecrawl" header to all 401 responses across /v0, /v1, and /v2 so agent clients can discover the credential scheme.
  • Added searchZDR values "forced-zdr" and "forced-anon" and deprecated "forced" (now an alias for "forced-zdr"); the resolved mode drives both billing and routing.
  • Added goal and judgeEnabled to POST /v2/monitor and PATCH /v2/monitor/:id; judgeEnabled defaults to true when goal is set, and goal: null clears it.
  • Added judgment, meaningfulChange (with a per-change reason), meaningfulChanges[], a structured diff object (text and/or json), and a snapshot field to monitor check pages; JSON-mode checks return field-level diffs plus a current-value snapshot.
  • Added unauthenticated POST /v2/monitor/email/confirm and POST /v2/monitor/email/unsubscribe (token accepted in the request body only), plus an emailRecipientSubscriptions array on Monitor responses reporting each recipient's email, status (pending/confirmed/unsubscribed), source, and confirmationEmailSent.
  • Added origin to monitor create/update bodies, matching the other v2 endpoints.
  • Added stricter validation on delay for POST /v2/crawl and POST /v1/crawl; non-numeric, negative, or values over 86400 are now rejected with a schema error instead of being silently applied.
  • Added include_domains and exclude_domains to the Python SDK's sync Firecrawl.search(), matching the async client and the /v2/search payload.
  • Added V1-compatible method aliases (scrape_url/scrapeUrl, crawl_url/crawlUrl, batch_scrape_urls, map_url, etc.) on the V2 Python and JS clients; aliases emit a DeprecationWarning.
  • Changed the monitor webhook payload to wrap data in an array; monitor.page now includes isMeaningful, judgment, and a diff object.
  • Normalized monitor scrapeOptions.formats so changeTracking json mode is rewritten to json, and the mixed ["json", "git-diff"] form now runs both diffs instead of silently falling back to one.
