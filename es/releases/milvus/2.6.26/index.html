milvus v2.6.26

##v2.6.26

Fecha de lanzamiento: 26 de octubre de 2026

| Versión Milvus | Python SDK Versión | Node.js SDK Versión | Versión Java SDK | Ir a la versión SDK | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

¡Estamos emocionados de anunciar el lanzamiento de Milvus v2.6.26! Esta versión acelera la decodificación de mensajes RPC, reduce el uso de memoria Proxy para solicitudes de búsqueda y consulta de gran tamaño, y corrige fallas de QueryNode en el filtrado anulable y NGRAM, se bloquea durante la carga de la colección y los trabajos de importación, y las marcas de tiempo que podrían retroceder después del inicio del coordinador.

Mejoras

  • Decodificación acelerada de mensajes RPC de búsqueda, consulta, inserción y inserción con un decodificador protobuf más rápido, habilitado de forma predeterminada y conmutable a través de common.enableFastPB (#53994, #54002)
  • Se fijó el lematizador del analizador de texto independientemente de Tantivy para que las actualizaciones de Tantivy no cambien los resultados de lematización ni provoquen coincidencias perdidas en índices de texto existentes y datos de BM25 (#54029, #54098)
  • Se redujo el retraso entre la finalización de una operación asíncrona de segmento y el llamante que recibe el resultado bajo una carga pesada, por lo que los resultados completados ya no esperan detrás del trabajo en cola mientras mantienen la memoria (#54128)
  • Se redujo el uso de memoria de proxy para solicitudes de búsqueda y consulta de gran tamaño al compartir las cargas útiles de las solicitudes entre fragmentos en lugar de copiarlas en profundidad por fragmento; El montón en vivo cayó de 8.7 GB a 5.85 GB en una prueba con 50 búsquedas simultáneas nq=10000 (#54224)
  • Se fusionaron condiciones array_contains de la misma columna en cadenas OR/AND en array_contains_any/array_contains_all durante la compilación del plan, lo que reduce la sobrecarga de compilación para filtros con miles de condiciones (#54435)
  • Se mejoró el filtrado de verificación de nulos en los índices de ruta JSON en segmentos sellados al almacenar en caché el mapa de bits de validez en lugar de volver a escanear el índice para cada consulta (#54422)
  • Se agregaron las configuraciones queryNode.segcore.interimIndex.sparseIPIndexAlgo y sparseBM25IndexAlgo para elegir el algoritmo de índice provisional (TAAT_NAIVE, DAAT_WAND o DAAT_MAXSCORE) para búsquedas dispersas de IP y BM25 en segmentos sellados en crecimiento y no indexados (#54443)
  • Se redujeron las lecturas y el análisis repetidos del pie de página de Parquet al cargar segmentos de StorageV2 en varios lotes y se optó por una corrección de almacenamiento milvus para el formato de URL del punto final en las nubes soberanas de Azure (#54488)

Corrección de errores

  • Se solucionó un problema por el cual la búsqueda de agrupaciones con un tamaño de grupo estricto podía devolver grupos con menos resultados de group_size incluso cuando existían suficientes entidades coincidentes; Se agregó queryNode.groupBy.strictGroupStrategy y configuraciones relacionadas para ajustar este comportamiento (#53451)
  • Se solucionó un problema por el cual el filtrado en un campo que acepta valores NULL mientras se ejecutaban inserciones o upserts podía bloquear el QueryNode o leer mal los valores nulos en segmentos en crecimiento (#53870)
  • Se solucionó un problema por el cual los filtros que combinan Y/O con comparaciones de enteros fuera de rango en campos de enteros que aceptan valores NULL podían bloquear el QueryNode o devolver resultados incorrectos (#53897)
  • Se solucionó un problema por el cual las consultas LIKE en campos con un índice NGRAM podían bloquear el QueryNode o devolver filas no coincidentes cuando el patrón contenía caracteres NUL (#53710)
  • Se solucionó un problema por el cual una lectura fallida de la ventana TSO persistente durante el inicio del coordinador podía provocar que las marcas de tiempo y los ID recién asignados retrocedieran (#51795)
  • Se solucionó un problema por el cual las solicitudes de búsqueda y consulta canceladas o con tiempo de espera permanecían en la cola de proxy y aún se ejecutaban, lo que retrasaba otras solicitudes bajo carga (#52938)
  • Se redujo la memoria máxima de compactación de clusters, lo que podría eliminar OOM los DataNodes en particiones grandes (#54078)
  • Se solucionó un problema por el cual los trabajos de importación podían bloquearse indefinidamente cuando una sola solicitud necesitaba más memoria que el límite de memoria de importación de DataNode, y donde los trabajos de importación descartados seguían esperando memoria en lugar de salir (#54112)
  • Se solucionó un problema por el cual los filtros en los campos JSON que mezclaban literales enteros y de punto flotante (por ejemplo, p == 1 OR p == 2.0) devolvían resultados incompletos cuando se cargaban las estadísticas de JSON (#54157)
  • Se solucionó un problema por el cual la carga y el equilibrio de la colección podían detenerse indefinidamente cuando un QueryNode cargaba o observaba un RPC colgado; Ahora se aplican tiempos de espera de tareas de QueryCoord, con valores predeterminados aumentados a 2 minutos para tareas de canal y 5 minutos para tareas de segmento y líder (#54218)
  • Se solucionó un problema por el cual la carga de segmentos en QueryNode podía bloquearse indefinidamente porque los camareros simultáneos no recibían notificaciones de finalización o cancelación de la carga (#54455)
  • Se solucionó un problema por el cual las cargas de segmentos de baja prioridad, como las activadas por el equilibrio o las actualizaciones de índice, cargaban datos de campo sin procesar con alta prioridad y competían con cargas urgentes por los recursos (#54336)
  • Se solucionó un problema por el cual las consultas paginadas que devolvían una página vacía fallaban con "El tipo de datos de campo no coincide" en Go SDK cuando la salida incluía una matriz vectorial o campos vectoriales StructArray (#54360)
  • Se solucionó un problema por el cual al eliminar un trabajo de importación no se detenían las tareas de importación que ya se estaban ejecutando en DataNodes (#54433)
  • Se solucionó un problema por el cual las particiones creadas después de LoadCollection permanecían descargadas en los clústeres en espera de CDC, por lo que sus datos no se podían consultar hasta que la colección se liberaba y se recargaba (#54567)
  • Se solucionó un problema por el cual la métrica milvus_proxy_report_value contaba dos veces las inserciones exitosas, exagerando el valor informado (#54606)

milvus v2.6.26

v2.6.26

Release date: October 26, 2026

| Milvus Version | Python SDK Version | Node.js SDK Version | Java SDK Version | Go SDK Version | | -------------- | ------------------ | ------------------- | ---------------- | -------------- | | 2.6.26 | 2.6.17 | 2.6.17 | 2.6.27 | 2.6.5 |

We are excited to announce the release of Milvus v2.6.26! This release speeds up RPC message decoding, cuts Proxy memory usage for large search and query requests, and fixes QueryNode crashes in nullable and NGRAM filtering, hangs during collection loading and import jobs, and timestamps that could go backward after coordinator startup.

Improvements

  • Sped up decoding of search, query, insert, and upsert RPC messages with a faster protobuf decoder, enabled by default and switchable via common.enableFastPB (#53994, #54002)
  • Pinned the text analyzer stemmer independently of Tantivy so that Tantivy upgrades do not change stemming results or cause missed matches on existing text indexes and BM25 data (#54029, #54098)
  • Reduced the delay between an async segcore operation completing and its caller receiving the result under heavy load, so completed results no longer wait behind queued work while holding memory (#54128)
  • Reduced Proxy memory usage for large search and query requests by sharing request payloads across shards instead of deep-copying them per shard; live heap dropped from 8.7 GB to 5.85 GB in a test with 50 concurrent nq=10000 searches (#54224)
  • Merged same-column array_contains conditions in OR/AND chains into array_contains_any/array_contains_all during plan compilation, reducing compilation overhead for filters with thousands of conditions (#54435)
  • Improved null-check filtering on JSON path indexes in sealed segments by caching the validity bitmap instead of rescanning the index for every query (#54422)
  • Added the queryNode.segcore.interimIndex.sparseIPIndexAlgo and sparseBM25IndexAlgo settings to choose the interim index algorithm (TAAT_NAIVE, DAAT_WAND, or DAAT_MAXSCORE) for sparse IP and BM25 search on growing and unindexed sealed segments (#54443)
  • Reduced repeated Parquet footer reads and parsing when loading StorageV2 segments in multiple batches, and picked up a milvus-storage fix for the endpoint URL format on Azure sovereign clouds (#54488)

Bug fixes

  • Fixed an issue where grouping search with strict group size could return groups with fewer than group_size results even when enough matching entities existed; added queryNode.groupBy.strictGroupStrategy and related settings to tune this behavior (#53451)
  • Fixed an issue where filtering on a nullable field while inserts or upserts were running could crash the QueryNode or misread null values in growing segments (#53870)
  • Fixed an issue where filters that combine AND/OR with out-of-range integer comparisons on nullable integer fields could crash the QueryNode or return incorrect results (#53897)
  • Fixed an issue where LIKE queries on fields with an NGRAM index could crash the QueryNode or return non-matching rows when the pattern contained NUL characters (#53710)
  • Fixed an issue where a failed read of the persisted TSO window during coordinator startup could cause newly allocated timestamps and IDs to go backward (#51795)
  • Fixed an issue where canceled or timed-out search and query requests stayed in the Proxy queue and were still executed, delaying other requests under load (#52938)
  • Reduced peak memory of clustering compaction, which could OOM-kill DataNodes on large partitions (#54078)
  • Fixed an issue where import jobs could hang indefinitely when a single request needed more memory than the DataNode import memory limit, and where dropped import jobs kept waiting for memory instead of exiting (#54112)
  • Fixed an issue where filters on JSON fields that mix integer and floating-point literals (e.g. p == 1 OR p == 2.0) returned incomplete results when JSON stats were loaded (#54157)
  • Fixed an issue where collection loading and balancing could stall indefinitely when a QueryNode load or watch RPC hung; QueryCoord task timeouts are now enforced, with defaults raised to 2 minutes for channel tasks and 5 minutes for segment and leader tasks (#54218)
  • Fixed an issue where segment loading on QueryNode could hang indefinitely because concurrent waiters missed load-completion or cancellation notifications (#54455)
  • Fixed an issue where low-priority segment loads, such as those triggered by balancing or index updates, loaded raw field data at high priority and competed with urgent loads for resources (#54336)
  • Fixed an issue where paginated queries returning an empty page failed with "FieldData type not matched" in the Go SDK when the output included vector array or StructArray vector fields (#54360)
  • Fixed an issue where dropping an import job did not stop its import tasks already running on DataNodes (#54433)
  • Fixed an issue where partitions created after LoadCollection stayed unloaded on CDC standby clusters, so their data could not be queried until the collection was released and reloaded (#54567)
  • Fixed an issue where the milvus_proxy_report_value metric counted successful upserts twice, overstating the reported value (#54606)
