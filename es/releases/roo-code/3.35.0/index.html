Roo-Code v3.35.0

Highlights

  • Native tool calling, everywhere — This is the headline of 3.35.0: structured tool invocation landed across a large provider matrix — Bedrock (#9698), Cerebras (#9692), Chutes with API auto-detection (#9715), DeepInfra (#9691), DeepSeek/Doubao (#9671), Groq (#9673), LiteLLM (#9719), Ollama (#9696), OpenAI-compatible endpoints (#9676), Requesty (#9672), Unbound (#9699), Vercel AI Gateway (#9697), Vertex Gemini (#9678), and xAI with Grok 4 Fast / 4.1 Fast (#9690). Native tools mean fewer malformed/invented calls than XML-emulated prompting, especially on reasoning models. Watch one concrete behavior change: Grok Code Fast now defaults to native tools (#9717), so if you had tuned prompts or permissions around the old format, revalidate that provider before shipping.

  • Two new editing primitives — apply_patch (#9663) and search_and_replace (#9549) give the agent more efficient, token-friendly ways to edit files, including batch text replacement across multiple files. For developers this changes the mechanics of agent-driven edits: patch-style updates are more reliable than whole-file rewrites, but you should expect new tool-permission prompts and consider whether your existing edit-tool configuration or includedTools/excludedTools allowlists need updating to admit them.

  • Metadata-driven subtasks with safer orchestration — Subtasks are now metadata-driven with automatic resume of the parent task and single-open safety (#8081, PR #9090). This matters because it removes manual hand-holding between a child task finishing and the parent continuing, while the single-open guard prevents the race where two subtasks are open at once. If you build workflows around nested/new tasks, this is the change most likely to alter task-lifecycle behavior — test your parent-resume assumptions.

  • Per-model tool control — New excludedTools and includedTools configuration (#9641) lets you tailor the tool set a given model can see. This is an actionable config surface: use it to restrict tools for models that mishandle certain calls, to trim context/cost, or — as noted above — to explicitly enable the new apply_patch and search_and_replace tools.

  • Fewer dropped calls, better forensics — Summaries now preserve tool_use blocks for parallel tool calls (#9700, PR #9714), so context compaction no longer silently loses in-flight tool invocations — a real correctness fix for long, parallel-heavy runs. Tool format is now surfaced in environment details (#9661), and debugging gets API/UI history buttons (#9684) plus web-evals task-log viewing, failed-log export, and kill-run support (#9637, #9681). Net effect: more predictable long-running agents and much easier triage when an eval or run goes wrong.

  • Breaking changes — None; no migration steps are required, though the Grok Code Fast native-tools default and the new tool config are behavior/config changes worth verifying.

[3.35.0] - 2025-12-01

3.35.0 Release - Subtasks & Native Tools

  • Metadata-driven subtasks with automatic parent resume and single-open safety for improved task orchestration (#8081 by @hannesrudolph, PR #9090 by @hannesrudolph)
  • Native tool calling support expanded across many providers: Bedrock (PR #9698 by @mrubens), Cerebras (PR #9692 by @mrubens), Chutes with auto-detection from API (PR #9715 by @daniel-lxs), DeepInfra (PR #9691 by @mrubens), DeepSeek and Doubao (PR #9671 by @daniel-lxs), Groq (PR #9673 by @daniel-lxs), LiteLLM (PR #9719 by @daniel-lxs), Ollama (PR #9696 by @mrubens), OpenAI-compatible providers (PR #9676 by @daniel-lxs), Requesty (PR #9672 by @daniel-lxs), Unbound (PR #9699 by @mrubens), Vercel AI Gateway (PR #9697 by @mrubens), Vertex Gemini (PR #9678 by @daniel-lxs), and xAI with new Grok 4 Fast and Grok 4.1 Fast models (PR #9690 by @mrubens)
  • Fix: Preserve tool_use blocks in summary for parallel tool calls (#9700 by @SilentFlower, PR #9714 by @SilentFlower)
  • Default Grok Code Fast to native tools for better performance (PR #9717 by @mrubens)
  • UX improvements to the Roo Code Cloud provider-centric onboarding flow (PR #9709 by @brunobergher)
  • UX toolbar cleanup and settings consolidation for a cleaner interface (PR #9710 by @brunobergher)
  • Add model-specific tool customization via excludedTools and includedTools configuration (PR #9641 by @daniel-lxs)
  • Add new apply_patch native tool for more efficient file editing operations (PR #9663 by @hannesrudolph)
  • Add new search_and_replace tool for batch text replacements across files (PR #9549 by @hannesrudolph)
  • Add debug buttons to view API and UI history for troubleshooting (PR #9684 by @hannesrudolph)
  • Include tool format in environment details for better context awareness (PR #9661 by @mrubens)
  • Fix: Display install count in millions instead of thousands (PR #9677 by @app/roomote)
  • Web-evals improvements: add task log viewing, export failed logs, and new run options (PR #9637 by @hannesrudolph)
  • Web-evals updates: add kill run functionality (PR #9681 by @hannesrudolph)
  • Fix: Prevent navigation buttons from wrapping on smaller screens (PR #9721 by @app/roomote)
