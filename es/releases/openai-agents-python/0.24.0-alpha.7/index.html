agentes-openai-python v0.24.0-alpha.7

Agentes SDK v0.24.0-alpha.7

Destacados

  • Utilice flujos de trabajo clásicos junto con la ejecución nativa. Importe el tiempo de ejecución v0 retenido a través de agents.classic. Este alfa también cambia los valores predeterminados de escritura del ejecutor; revise las acciones de actualización antes de abrir entornos existentes.
  • Mantenga las conversaciones en su propio almacenamiento. Agregue sesiones raíz duraderas con CustomStorage y concilie los efectos inciertos de las herramientas antes de reanudar el trabajo.
  • Agregue herramientas alojadas y de voz a agentes nativos. Conecte flujos de trabajo de voz a una sesión o use FileSearch, CodeInterpreter y ImageGeneration a través de proveedores de respuestas compatibles.
  • Controle el contexto, la finalización y el uso. Transforme la entrada del modelo, conserve el contexto seleccionado durante la compactación, revise las respuestas propuestas y limite el uso de raíz observado.

Actualización desde 0.24.0-alpha.6

  • Revisar políticas de escritura del entorno. Los nuevos entornos tienen por defecto write_policy="strict", lo que requiere un ejecutor compatible con Linux o macOS. El directorio de trabajo sigue siendo escribible; utilice writable_roots para directorios adicionales. Para conservar la política remota anterior, incluso en los ejecutores de Windows, configure write_policy="legacy" y deje writable_roots=None. La ejecución local requiere modo estricto. Al restaurar perfiles o puntos de control remotos heredados, seleccione heredados explícitamente; la reapertura no mejora su política. Consulte la política del ejecutor y reglas de restauración.
  • Verifique la configuración de razonamiento implícito. El catálogo de modelos incluido cambia el esfuerzo de razonamiento predeterminado de low a medium para gpt-6-astra, gpt-6.1-sol y gpt-5.6-sol. Configure model_settings={"reasoning_effort": "low"} explícitamente si necesita el esfuerzo anterior. Esto describe los metadatos agrupados; una configuración explícita o metadatos del modelo de proveedor pueden seleccionar otro valor. (#5517)
  • Cambiar el nombre de los modos de aprobación de MCP. Reemplace approval_mode="auto" con "native" y "approve" con "preapproved". Se rechazan los viejos valores; los nuevos nombres conservan su comportamiento de aprobación respectivo.
  • Actualizar devoluciones de llamadas de pasos secundarios. NativeAgents.before_step ahora recibe un ChildStepContext, con context, child y step_index, en lugar de argumentos secundarios y de índice de pasos separados. Las devoluciones de llamada raíz before_step mantienen su firma existente.
  • Maneja formularios MCP y URL por separado. ElicitationRequest ahora es la unión FormRequest | UrlRequest. Utilice FormRequest.reply() o respond() para formularios; utilice UrlRequest.reply_url_accept() o accept_url() para el consentimiento de URL.

Agregado

  • Almacenamiento de conversaciones propiedad de la aplicación. SessionStore, SQLiteSessionStore y CustomStorage conservan el historial de raíz y los resultados automáticos de la herramienta Python. Este perfil inicial excluye herramientas nativas, entornos, elementos secundarios, herramientas de planificación, ejecución de código generado, herramientas manuales y puntos de control portátiles. SQLiteSessionStore requiere un host y un sistema de archivos POSIX local. Tanto los perfiles locales como las tiendas personalizadas pueden informar llamadas raíz inciertas para una conciliación explícita; ninguno reproduce automáticamente esos efectos. (#5514, #5502)
  • Herramientas y almacenamiento alojados por el proveedor. Agregue FileSearch, CodeInterpreter y ImageGeneration, políticas de llamadas de Code Interpreter y almacenamiento administrado por el proveedor. Las herramientas alojadas requieren un proveedor de claves API y un modelo de Respuestas estándar compatible; excluyen el inicio de sesión de Responses Lite y Codex. La búsqueda web alojada agrega controles de dominio y ubicación y retiene las citas. (#5576, guía de herramientas alojadas)
  • Enganches de contexto y finalización. Agent.transform_context cambia la entrada muestreada sin cambiar el historial almacenado. before_compact y compactación con control de retención de elementos seleccionados. before_complete puede aceptar, devolver ContinueTurn o detener una respuesta propuesta; Es posible que el texto rechazado ya se haya transmitido y permanezca en el historial. La edición avanzada de prepare_request admite un perfil HTTP restringido. Consulte [contratos y límites de gancho] (https://github.com/openai/openai-agents-python/blob/4c1190046163c09e4f67ab7254f22bea60b14894/docs/sdk/configuration.md#choose-a-model-context-hook).
  • Presupuestos de uso observados. RunBudget limita las admisiones de solicitudes de raíz, los tokens informados o el costo estimado antes de la siguiente solicitud. Una solicitud admitida puede exceder un límite. Los niños están excluidos; El uso faltante detiene la admisión adicional de forma predeterminada. Las operaciones presupuestadas activas no pueden utilizar puntos de control portátiles. (#5555)
  • Recursos, avisos y reconexión de MCP. Utilice Session.list_mcp_resources(), list_mcp_resource_templates(), read_mcp_resource(), list_mcp_prompts() y get_mcp_prompt() con un servidor HTTP o stdio seleccionado mientras la sesión está inactiva. Los datos recuperados no ingresan automáticamente al contexto del modelo. La selección de herramientas con alcance y la reconexión explícita preservan el control sobre las herramientas admitidas sin reproducir llamadas inciertas. (#5597, #5604, #5556)
  • Ejecución local y búsqueda de proyectos. Environment.local() ejecuta herramientas ejecutoras compatibles localmente. En Linux, LocalStorageMount(source=path) otorga acceso de solo lectura a un directorio canónico existente; El origen y el destino deben coincidir. project_glob y project_grep buscan debajo del directorio de trabajo fijo del entorno sin permitir la ejecución del comando. (#5501, #5575, #5574)
  • Integración y supervisión. Agregue adaptadores de servidor y A2A client nativos a través del a2a adicional, TraceContext explícito, controles de seguimiento del flujo de trabajo, instantáneas de límite de velocidad de teclas API, recibos de giro, dirección de giro exacto y esperas de atención. Las integraciones clásicas utilizan los extras classic y classic-*; Los objetos y puntos de control clásicos y nativos permanecen separados.
  • Voz con historial y políticas nativas. agents.voice.NativeSessionVoiceWorkflow utiliza una sesión de salida de texto propiedad de la persona que llama con el canal de voz. Habla del texto final aceptado después de la revisión completa y la validación del resultado. La aplicación maneja las interacciones y la duración de la sesión. Instale el extra voice; Los agentes en tiempo real permanecen bajo agents.classic.realtime. (#5596)

Cambiado

  • Elija el manejo del tiempo de espera de la herramienta de función. timeout_behavior="error_as_result" devuelve un error de tiempo de espera al modelo, con formato timeout_error_function opcional. Subir sigue siendo el valor predeterminado. (#5605)
  • Respuestas almacenadas en búfer opcionales. NativeProvider(response_mode="buffered") lee cada respuesta HTTP JSON completa antes de emitir la salida del modelo. Seleccione explícitamente un modelo de Respuestas estándar; el modelo predeterminado utiliza Responses Lite. El modo almacenado en búfer requiere autenticación con clave API y excluye WebSockets, hijos nativos y el inicio de sesión de Codex. La transmisión sigue siendo la opción predeterminada. (#5589)
  • Reutilización experimental de inicios de sesión guardados. NativeProvider(auth=CodexLogin()) puede usar un inicio de sesión guardado del Codex a través de HTTP. Omita api_key y base_url. Esta característica experimental puede cambiar o eliminarse; consulte las [guías y límites de autenticación] (https://github.com/openai/openai-agents-python/blob/4c1190046163c09e4f67ab7254f22bea60b14894/docs/sdk/configuration.md#reuse-a-codex-login-experimental).

Fijo

  • Mantenga privados los archivos de credenciales de montaje de Classic durante la creación y el reemplazo, y la extracción de archivos de Sandbox de Classic vinculados.
  • Detener el trabajo diferido y compactación automática tras la cancelación. Conserve los propietarios de la limpieza para que las personas que llaman puedan volver a intentar la liberación incompleta de recursos sin repetir la conciliación o los efectos de las herramientas.
  • Detener los reintentos de muestreo después de fallas de autenticación del proveedor de terminales. Informe los motivos de los errores de salida escritos y los límites de contexto capturados, y conserve los recuentos de tokens de escritura en caché.
  • Conservar las observaciones de respuesta del proveedor y los detalles de ejecución según sus políticas configuradas. Reduzca la sobrecarga de inicio nativo y lectura de eventos.

openai-agents-python v0.24.0-alpha.7

Agents SDK v0.24.0-alpha.7

Highlights

  • Use Classic workflows alongside native execution. Import the retained v0 runtime through agents.classic. This alpha also changes executor write defaults; review the upgrade actions before opening existing environments.
  • Keep conversations in your own storage. Add durable root Sessions with CustomStorage, and reconcile uncertain tool effects before resuming work.
  • Add voice and hosted tools to native agents. Connect speech workflows to a Session, or use FileSearch, CodeInterpreter, and ImageGeneration through compatible Responses providers.
  • Control context, completion, and usage. Transform model input, retain selected context during compaction, review proposed answers, and limit observed root usage.

Upgrading from 0.24.0-alpha.6

  • Review Environment write policies. New Environments default to write_policy="strict", which requires a compatible Linux or macOS executor. The working directory remains writable; use writable_roots for additional directories. To retain the previous remote policy, including on Windows executors, set write_policy="legacy" and leave writable_roots=None. Local execution requires strict mode. When restoring legacy remote checkpoints or profiles, select legacy explicitly; reopening does not upgrade their policy. See the executor policy and restore rules.
  • Check implicit reasoning settings. The bundled model catalog changes the default reasoning effort from low to medium for gpt-6-astra, gpt-6.1-sol, and gpt-5.6-sol. Set model_settings={"reasoning_effort": "low"} explicitly if you need the previous effort. This describes bundled metadata; an explicit setting or provider model metadata can select another value. (#5517)
  • Rename MCP approval modes. Replace approval_mode="auto" with "native", and "approve" with "preapproved". The old values are rejected; the new names preserve their respective approval behavior.
  • Update child step callbacks. NativeAgents.before_step now receives one ChildStepContext, with context, child, and step_index, instead of separate child and step-index arguments. Root before_step callbacks keep their existing signature.
  • Handle MCP forms and URLs separately. ElicitationRequest is now the union FormRequest | UrlRequest. Use FormRequest.reply() or respond() for forms; use UrlRequest.reply_url_accept() or accept_url() for URL consent.

Added

  • Application-owned conversation storage. SessionStore, SQLiteSessionStore, and CustomStorage persist root history and automatic Python tool results. This initial profile excludes native tools, Environments, children, planning tools, generated-code execution, manual tools, and portable checkpoints. SQLiteSessionStore requires one host and a local POSIX filesystem. Both local profiles and custom stores can report uncertain root calls for explicit reconciliation; neither automatically replays those effects. (#5514, #5502)
  • Provider-hosted tools and storage. Add FileSearch, CodeInterpreter, and ImageGeneration, Code Interpreter caller policies, and provider-managed storage. Hosted tools require an API-key provider and a compatible standard Responses model; they exclude Responses Lite and Codex login. Hosted web search adds domain and location controls and retains citations. (#5576, hosted-tool guide)
  • Context and completion hooks. Agent.transform_context changes sampled input without changing stored history. before_compact and selected-item retention control compaction. before_complete can accept, return ContinueTurn, or stop a proposed answer; rejected text may already have streamed and remains in history. Advanced prepare_request editing supports a restricted HTTP profile. See the hook contracts and limits.
  • Observed usage budgets. RunBudget limits root request admissions, reported tokens, or estimated cost before the next request. An admitted request can exceed a limit. Children are excluded; missing usage stops further admission by default. Active budgeted operations cannot use portable checkpoints. (#5555)
  • MCP resources, prompts, and reconnection. Use Session.list_mcp_resources(), list_mcp_resource_templates(), read_mcp_resource(), list_mcp_prompts(), and get_mcp_prompt() with a selected HTTP or stdio server while the Session is idle. Retrieved data does not enter model context automatically. Scoped tool selection and explicit reconnection preserve control over admitted tools without replaying uncertain calls. (#5597, #5604, #5556)
  • Local execution and project search. Environment.local() runs supported executor tools locally. On Linux, LocalStorageMount(source=path) grants read-only access to an existing canonical directory; source and destination must match. project_glob and project_grep search beneath the Environment's fixed working directory without granting command execution. (#5501, #5575, #5574)
  • Integration and supervision. Add native A2A client and server adapters through the a2a extra, explicit TraceContext, workflow tracing controls, API-key rate-limit snapshots, turn receipts, exact-turn steering, and attention waits. Classic integrations use the classic and classic-* extras; Classic and native objects and checkpoints remain separate.
  • Speech with native history and policies. agents.voice.NativeSessionVoiceWorkflow uses a caller-owned text-output Session with the speech pipeline. It speaks accepted final text after completion review and output validation. The application handles interactions and Session lifetime. Install the voice extra; Realtime agents remain under agents.classic.realtime. (#5596)

Changed

  • Choose function-tool timeout handling. timeout_behavior="error_as_result" returns a timeout error to the model, with optional timeout_error_function formatting. Raising remains the default. (#5605)
  • Optional buffered Responses. NativeProvider(response_mode="buffered") reads each complete HTTP JSON response before emitting model output. Select a standard Responses model explicitly; the default model uses Responses Lite. Buffered mode requires API-key authentication and excludes WebSockets, native children, and Codex login. Streaming remains the default. (#5589)
  • Experimental saved-login reuse. NativeProvider(auth=CodexLogin()) can use a saved Codex login over HTTP. Omit api_key and base_url. This experimental feature may change or be removed; see the authentication guidance and limits.

Fixed

  • Keep Classic mount credential files private during creation and replacement, and bound Classic sandbox archive extraction.
  • Stop deferred work and automatic compaction after cancellation. Retain cleanup owners so callers can retry unfinished release of resources without repeating reconciliation or tool effects.
  • Stop sampling retries after terminal provider authentication failures. Report typed output-failure reasons and captured context limits, and preserve cache-write token counts.
  • Retain provider response observations and execution details under their configured policies. Reduce native startup and event-reading overhead.
