Nemotrón 3.5 ASR

<img width="1632" height="735" alt="image" src="https://github.com/user-attachments/assets/597bbb9c-b046-4e47-b9fd-f242e0a5b04d" />

Nemotron 3.5 ASR es un modelo de reconocimiento de voz multilingüe de 600M de parámetros de NVIDIA, creado para transcripción de alta calidad tanto en transmisión de baja latencia como en configuraciones por lotes de alto rendimiento, con puntuación nativa y capitalización. Para la transmisión, ofrece tamaños de fragmentos configurables: 80 ms, 160 ms, 560 ms y 1120 ms, lo que permite a los usuarios compensar la latencia con la precisión para adaptarse a su aplicación. Su arquitectura FastConformer-RNNT con reconocimiento de caché es fundamental para esta capacidad: a diferencia de la transmisión en búfer tradicional, que reprocesa repetidamente ventanas de audio superpuestas, el modelo procesa solo cada nuevo fragmento entrante mientras reutiliza el contexto del codificador almacenado en caché de fragmentos anteriores. Esto elimina el cálculo redundante, mejora significativamente la eficiencia y minimiza el retraso de un extremo a otro sin sacrificar la precisión, lo que lo hace muy adecuado para cargas de trabajo de transcripción en tiempo real.

VídeoPrisma

El modelo VideoPrism fue propuesto en el artículo VideoPrism: A Foundational Visual Encoder for Video Understanding de Google DeepMind (publicación de blog).

VideoPrism es un codificador de vídeo de uso general que aborda diversas tareas de comprensión de vídeo con un único modelo congelado. El modelo está preentrenado en un corpus heterogéneo a gran escala que contiene 36 millones de pares de subtítulos de video de alta calidad y 582 millones de videos clips con texto paralelo ruidoso (por ejemplo, transcripciones ASR). El enfoque de preentrenamiento mejora la codificación automática enmascarada a través de la destilación global-local de incrustaciones de video semánticas y un esquema de mezcla aleatoria de tokens, lo que permite que el modelo se centre principalmente en la modalidad de video mientras aprovecha el texto asociado con los videos. VideoPrism logra un rendimiento de vanguardia en 31 de 33 puntos de referencia de comprensión de video en cuatro amplios grupos de tareas, desde respuesta a preguntas en video web hasta visión por computadora para ciencia.

MiniCPM3

MiniCPM3 es el modelo de lenguaje denso MiniCPM de tercera generación de OpenBMB. La variante 4B (openbmb/MiniCPM3-4B) supera a muchos 7B–9B abiertos modelos en puntos de referencia estándar sin dejar de ser lo suficientemente livianos para su uso en el dispositivo.

MiniCPM3 combina varias ideas arquitectónicas:

  • Atención latente de múltiples cabezales (MLA) de DeepSeek-V2, que comprime la caché de clave/valor en una representación latente de bajo rango mientras se siguen utilizando incrustaciones rotativas en una parte del cabezas de consulta/clave.
  • Un SwiGLU MLP estándar (sin MoE).
  • Tres factores de escalar que gobiernan el flujo de señal:
    • scale_emb: escala las incrustaciones de entrada.
    • scale_depth / sqrt(num_hidden_layers) — escala las conexiones residuales.
    • hidden_size / dim_model_base: escala los estados ocultos antes del encabezado del modelo de lenguaje.

HfExporters: Exportación nativa y unificada para PyTorch / ONNX / ExecuTorch

<img alt="miniatura" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

Un canal de exportación nativo en Transformers: una clase base (HfExporter), tres subclases para los tiempos de ejecución que nos interesan, un API unificado:

| Exportador | Salida | Tiempo de ejecución | |---|---|---| | DynamoExporter | ExportedProgram | Cualquier tiempo de ejecución de PyTorch, compilación AOT | | OnnxExporter | ONNXProgram | Cualquier tiempo de ejecución de ONNX (ORT, TensorRT, OpenVINO,…) | | ExecutorchExporter | ExecutorchProgramManager | Móvil y perimetral (ExecuTorch) | La misma forma de llamada en los tres. Formas dinámicas por defecto. Los modelos de estilo generacional se dividen automáticamente en precarga + decodificación (+ subcodificadores de visión/audio para VLM).

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

Cambie una línea por otro tiempo de ejecución: DynamoExporter() / DynamoConfig o ExecutorchExporter() / ExecutorchConfig(backend=...).

Para los modelos generativos, la división de prellenado/decodificación se captura automáticamente:

from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-LlamaForCausalLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")

artifacts = OnnxExporter().export_for_generation(model, inputs, config=OnnxConfig(dynamic=True))
# {"prefill": ONNXProgram, "decode": ONNXProgram}

Nemotron 3.5 ASR is a 600M-parameter multilingual speech recognition model from NVIDIA, built for high-quality transcription in both low-latency streaming and high-throughput batch settings, with native punctuation and capitalization. For streaming, it offers configurable chunk sizes—80ms, 160ms, 560ms, and 1120ms, letting users trade off latency against accuracy to suit their application. VideoPrism is a general-purpose video encoder that tackles diverse video understanding tasks with a single frozen model. MiniCPM3

MiniCPM3 is the third-generation MiniCPM dense language model from OpenBMB. The 4B variant (openbmb/MiniCPM3-4B) outperforms many 7B–9B open models on standard benchmarks while remaining lightweight enough for on-device usage.

MiniCPM3 combines several architectural ideas:

  • Multi-head Latent Attention (MLA) from DeepSeek-V2, which compresses the key/value cache into a low-rank latent representation while still using rotary embeddings on a portion of the query/key heads.
  • A standard SwiGLU MLP (no MoE).
  • Three scalar scaling factors that govern signal flow:
    • scale_emb — scales input embeddings.
    • scale_depth / sqrt(num_hidden_layers) — scales residual connections.
    • hidden_size / dim_model_base — scales hidden states before the language model head.

HfExporters: Native, Unified export for PyTorch / ONNX / ExecuTorch

<img alt="thumbnail" src="https://github.com/user-attachments/assets/3ba5751b-c99e-4945-b5a8-b2b29231f5df" />

A native, in-Transformers export pipeline — one base class (HfExporter), three subclasses for the runtimes we care about, one unified API:

| Exporter | Output | Runtime | |---|---|---| | DynamoExporter | ExportedProgram | Any PyTorch runtime, AOT compilation | | OnnxExporter | ONNXProgram | Any ONNX runtime (ORT, TensorRT, OpenVINO, …) | | ExecutorchExporter | ExecutorchProgramManager | Mobile and edge (ExecuTorch) |

Same call shape across all three. Dynamic shapes by default. Generation-style models split automatically into prefill + decode (+ vision/audio sub-encoders for VLMs).

from transformers import AutoModelForMaskedLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-BertForMaskedLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForMaskedLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")
onnx_program = OnnxExporter().export(model, inputs, config=OnnxConfig(dynamic=True))

new_input = tokenizer("Hello, my cat is so adorable!", return_tensors="pt")
torch.testing.assert_close(
    onnx_program.call_reference(**new_input)[0],   # numpy reference
    onnx_program(**new_input)[0],                  # onnxruntime
    rtol=1e-4, atol=1e-4,
)

Swap one line for another runtime — DynamoExporter() / DynamoConfig or ExecutorchExporter() / ExecutorchConfig(backend=...).

For generative models the prefill/decode split is captured automatically:

from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers.exporters import OnnxExporter, OnnxConfig

model_id = "hf-internal-testing/tiny-random-LlamaForCausalLM"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).eval()
inputs = tokenizer(["Hello, my dog is cute"] * 2, return_tensors="pt")

artifacts = OnnxExporter().export_for_generation(model, inputs, config=OnnxConfig(dynamic=True))
# {"prefill": ONNXProgram, "decode": ONNXProgram}
# For VLMs: also vision_encoder, audio_encoder, multi_modal_projector, language_model, lm_head
