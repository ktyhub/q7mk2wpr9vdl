Meta Muse Glimmer

Muse Glimmer, lanzado hoy, es el nuevo modelo multimodal de Meta, especialmente diseñado para casos de uso agentes. Destilado de Muse a los parámetros 30B y lanzado bajo la licencia Apache 2.0, se puede implementar en configuraciones locales para aplicaciones que tienen en cuenta la privacidad, como codificación, análisis de documentos, asistentes personales, configuraciones tipo Claw o Hermes.

Muse Glimmer es un modelo denso de parámetros 30B que consta de:

  • Codificador de visión estilo 2B ViT (Perception Encoder)
  • Decodificador de texto de parámetros 28B

Cambios importantes

Los kernels ahora son opcionales en lugar de obligatorios para los modelos de atención lineal (Mamba, GDN, Conv-only, etc.), por lo que los usuarios que confiaban en la selección automática de kernel deben habilitar explícitamente los kernels para mantener el comportamiento anterior.

  • 🚨 [Kernels] Refactorice todos los modelos de atención lineal y respaldo de kernels nativos (#47630) por @vasqu

El recorte de caché API ahora solo acepta valores negativos (compensaciones relativas) en lugar de tamaños absolutos, por lo que los usuarios que llaman directamente a los métodos de recorte deben actualizar su código para pasar valores negativos en consecuencia.

  • 🚨 [caché] El recorte solo se puede realizar con valores negativos (#47720) por @Cyrilvallez

T5 y su familia de modelos (MT5, LongT5, etc.) ahora admiten SDPA y otros backends de atención a través de ALL_ATTENTION_FUNCTIONS, lo que significa que la implementación de atención predeterminada puede cambiar y los usuarios que dependen de la ruta anterior de solo entusiasmo deben configurar explícitamente attn_implementation="eager" si es necesario.

  • 🚨 Habilite SDPA (y otros backends de atención) para T5 y propague a la familia T5 (#47014) por @jiqing-feng

Se han eliminado varias pequeñas funciones auxiliares privadas (por ejemplo, _is_url, _build_image_tokens) de los archivos del procesador multimodal, por lo que los usuarios o las bibliotecas posteriores que importaron estas funciones privadas directamente deben eliminar o reemplazar esas referencias.

  • :rotating_light: Los procesadores actualizan el resto (#46556) por @zucchini-nlp

Meta Muse Glimmer

Muse Glimmer, released today, is Meta’s new multimodal model, especially designed for agentic use cases. Distilled from Muse to 30B parameters, and released under the Apache 2.0 license, it can be deployed to local setups for privacy-aware applications such as coding, document analysis, personal assistants, Claw- or Hermes-like setups.

Muse Glimmer is a dense 30B parameter model consisting of:

  • 2B ViT-style encoder for vision (Perception Encoder)
  • 28B parameter text decoder

Breaking changes

Kernels are now opt-in rather than mandatory for linear attention models (Mamba, GDN, Conv-only, etc.), so users who relied on automatic kernel selection must explicitly enable kernels to maintain previous behavior.

  • 🚨 [Kernels] Refactor all linear attn models & native kernels fallback (#47630) by @vasqu

The cache cropping API now only accepts negative values (relative offsets) instead of absolute sizes, so users calling crop methods directly must update their code to pass negative values accordingly.

  • 🚨 [cache] Cropping can only be done with negative values (#47720) by @Cyrilvallez

T5 and its model family (MT5, LongT5, etc.) now support SDPA and other attention backends via ALL_ATTENTION_FUNCTIONS, meaning the default attention implementation may change and users relying on the previous eager-only path should explicitly set attn_implementation="eager" if needed.

  • 🚨 Enable SDPA (and other attention backends) for T5 and propagate to the T5 family (#47014) by @jiqing-feng

Several small private helper functions (e.g., _is_url, _build_image_tokens) have been removed from multimodal processor files, so users or downstream libraries that imported these private functions directly must remove or replace those references.

  • :rotating_light: Processors update the rest (#46556) by @zucchini-nlp
