jerga v0.5.14

Destacados

Compatibilidad con nuevos modelos: GLM-5.2, LiquidAI LFM2.5, Kimi-K2.7-Code, Poolside Laguna-M.1, DiffusionGemma, Zyphra ZAYA1, MiMo-V2-ASR DeepSeek-V4 en GB300 desde el día 0: rendimiento 5 veces mayor con la misma interactividad, con DeepSeek-V4 en NVIDIA GB300 con SGLang (blog). Equilibrio de carga Waterfill y LPLB MoE: dos métodos de equilibrio de carga en el tiempo de despacho para el paralelismo experto de DeepEP: Waterfill para despacho de expertos compartido y LPLB para réplicas expertas redundantes, lo que mejora el rendimiento de DeepSeek-V3/R1 y DeepSeek-V4 (blog). Núcleo precargado KDA CuteDSL en Blackwell (SM100): Nuevo kernel precargado CuteDSL para Kimi-Linear (KDA), 1.08-1.52x más rápido que la ruta Triton a través de un espacio de trabajo temporal reutilizable, además de una corrección de relleno de cuda-graph (#27488); consulte el [libro de cocina Kimi-Linear] (https://docs.sglang.io/cookbook/autoregressive/Moonshotai/Kimi-Linear). Ahorro de memoria de caché de prefijo de atención lineal: un grupo de puntos de control int8 almacena estados recurrentes de forma compacta en la caché de base de Mamba, lo que aumenta sustancialmente la capacidad de caché de prefijo para los modelos KDA/GDN (#28185); la caché intermedia de ventana de conversión especulativa se deduplica con un diseño de ventana deslizante, lo que reduce a la mitad su espacio sin cambios numéricos (#28302). LPLB: equilibrador de carga de programación lineal para paralelismo experto de MoE: equilibra el enrutamiento de tokens entre réplicas expertas redundantes resolviendo un LP por capa; suscribirse a través de --ep-dispatch-algorithm=lp, comportamiento predeterminado sin cambios (#24515). Integración de MSCCL++ y fusión MNNVL allreduce: MSCCL++ migra al paquete ascendente mscclpp Python (compilador Executor + DSL) con colectivos ajustados automáticamente para TP=8 de un solo nodo y TP=16 de dos nodos (#22734); FlashInfer fusionado allreduce + residual + RMSNorm vuelve a habilitar un backend MNNVL detrás de --flashinfer-allreduce-fusion-backend (auto / trtllm / mnnvl), arreglando la interacción del gráfico CUDA por partes (#23402). Atención Nemotron DP + MTP: Atención de datos paralelos para el híbrido Nemotron-H (Mamba2 + atención completa + MoE), además de compatibilidad con MTP (#24955); consulte el libro de recetas de Nemotron 3 Ultra. AMD: gráfico CUDA rompible en ROCm/HIP: la ruta de ejecución del gráfico CUDA rompible ahora se ejecuta en GPU AMD (#28173). NVFP4 MoE para DeepSeek-V4: Agrega una ruta de cuantificación NVFP4 MoE para DeepSeek-V4 en Blackwell para un mayor rendimiento de MoE; habilitar con --moe-runner-backend flashinfer_trtllm_routed (#25820); consulte el libro de recetas de DeepSeek-V4. Optimizaciones de decodificación y cuantificación de DeepSeek-V4: la cuantificación de grupo FP8 ahora emite escalas de potencia de dos (UE8M0) directamente desde el núcleo cuantitativo de grupo por token, eliminando un pase de redondeo separado (#26766); Los q-heads de decodificación MLA se rellenan a 64 bajo atención-TP, por lo que FlashMLA envía el kernel head64 ~2 veces más barato en lugar de head128 (#27954); el kernel prenorma MHC se precalienta al inicio para eliminar la desaceleración JIT de la primera ejecución en un servidor nuevo (#27986); y los estados de compresión de tipo mixto BF16 se admiten en las rutas C4/C128 (#27277); consulte el libro de recetas de DeepSeek-V4. release note completos por categoría a continuación.

sglang v0.5.14

Highlights

New Model Support: GLM-5.2, LiquidAI LFM2.5, Kimi-K2.7-Code, Poolside Laguna-M.1, DiffusionGemma, Zyphra ZAYA1, MiMo-V2-ASR

DeepSeek-V4 on GB300 since Day 0: 5x higher throughput at the same interactivity, serving DeepSeek-V4 on NVIDIA GB300 with SGLang (blog).

Waterfill & LPLB MoE load balancing: Two dispatch-time load-balancing methods for DeepEP expert parallelism: Waterfill for shared-expert dispatch and LPLB for redundant expert replicas, improving throughput for DeepSeek-V3/R1 and DeepSeek-V4 (blog).

KDA CuteDSL prefill kernel on Blackwell (SM100): New CuteDSL prefill kernel for Kimi-Linear (KDA), 1.08-1.52x faster than the Triton path via a reusable scratch workspace, plus a cuda-graph padding fix (#27488); see the Kimi-Linear cookbook.

Linear-attention prefix-cache memory savings: An int8 checkpoint pool stores recurrent states compactly in the Mamba radix cache, substantially increasing prefix-cache capacity for KDA / GDN models (#28185); the speculative conv-window intermediate cache is deduplicated with a sliding-window layout, halving its footprint with no numerical change (#28302).

LPLB: linear-programming load balancer for MoE expert parallelism: Balances token routing across redundant expert replicas by solving a per-layer LP; opt-in via --ep-dispatch-algorithm=lp, default behavior unchanged (#24515).

MSCCL++ integration & MNNVL allreduce fusion: MSCCL++ migrates to the upstream mscclpp Python package (Executor + DSL compiler) with auto-tuned collectives for TP=8 single-node and TP=16 two-node (#22734); FlashInfer fused allreduce + residual + RMSNorm re-enables an MNNVL backend behind --flashinfer-allreduce-fusion-backend (auto / trtllm / mnnvl), fixing the piecewise-CUDA-graph interaction (#23402).

Nemotron DP attention + MTP: Data-parallel attention for the hybrid Nemotron-H (Mamba2 + full attention + MoE), plus MTP support (#24955); see the Nemotron 3 Ultra cookbook.

AMD: breakable CUDA graph on ROCm/HIP: The breakable CUDA graph execution path now runs on AMD GPUs (#28173).

NVFP4 MoE for DeepSeek-V4: Adds an NVFP4 MoE quantization path for DeepSeek-V4 on Blackwell for higher MoE throughput; enable with --moe-runner-backend flashinfer_trtllm_routed (#25820); see the DeepSeek-V4 cookbook.

DeepSeek-V4 decode & quantization optimizations: FP8 group quantization now emits power-of-two (UE8M0) scales directly from the per-token group-quant kernel, dropping a separate rounding pass (#26766); MLA decode q-heads are padded to 64 under attention-TP so FlashMLA dispatches the ~2x cheaper head64 kernel instead of head128 (#27954); the MHC prenorm kernel is prewarmed at startup to remove the first-run JIT slowdown on a fresh server (#27986); and BF16 mixed-dtype compression states are supported on the C4 / C128 paths (#27277); see the DeepSeek-V4 cookbook.
