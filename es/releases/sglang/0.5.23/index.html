¿Qué hay de nuevo?

  • DeepSeek-V4.1 en GB300 obtiene hasta 1,5 veces más rendimiento de prellenado bajo carga y aproximadamente un 28 % menos de latencia del primer token en mensajes de 32 000 a 64 000 (#44403, #45059, #45107).
  • Modo de baja latencia SGLang: los complementos opcionales NVIDIA megakernel y AMD monokernel ejecutan la decodificación DeepSeek-V4.1-Flash como núcleos persistentes fusionados, para una decodificación de usuario único hasta un 44 % más rápida en GB300 y un 75 % en MI350X (#44945, #45450, #44353, #44621).
  • Los modelos MoE como DeepSeek-V4.1-Flash, GLM-5.3-Flash y gpt-oss alcanzan el primer token entre un 30% y un 58% antes en indicaciones de 8K en H200 (#43363).
  • Paged Experts (opt-in) ejecuta modelos MoE más grandes que la memoria de la GPU en una sola GPU de consumo, hasta 30 veces más rápido que la descarga de la CPU (#42557, #45787).
  • SGLang ahora se ejecuta en Google TPU7x a través de SGLang-TorchTPU, un complemento nativo de PyTorch para TPU.
  • Ahora puede ofrecer adaptadores LoRA en modelos MoE cuantificados (FP8 y NVFP4) con un nuevo motor LoRA opcional (#45892).
  • Los modelos MLA estilo DeepSeek que ejecutan paralelismo de contexto de decodificación ahora pueden mantener su caché de prefijo en el almacenamiento L3 basado en archivos HiCache (#41187).

Cambios importantes y notas de actualización

  • El chat de DeepSeek-V4 y V4.1 ahora sigue la receta de deepseek. Las indicaciones, las salidas y los puntos finales nativos /separate_reasoning y /parse_function_call pasan por el codificador oficial de DeepSeek, y los propios encoding_dsv4.py/encoding_dsv41.py de SGLang ya no están. Clients puede notar: los argumentos de llamada de herramienta transmitidos llegan en pedazos (el primer fragmento lleva arguments: ""), así que concatenelos como lo hace OpenAI SDK; los identificadores de llamadas de herramientas utilizan el formato oficial call_00_...; El esfuerzo de razonamiento V4 sigue el perfil oficial de DeepSeek y se elimina la anulación de dsv4_reasoning_effort_profile; un reasoning_effort numérico en V4 devuelve 400; Los mensajes developer se representan como mensajes del sistema; /parse_function_call también devuelve llamadas a herramientas fuera de tools con tool_index -1; las solicitudes que combinan tools con continue_final_message devuelven 400. El análisis de salida pasa por deepseek-recipe cuando se configura el razonamiento de DeepSeek o el analizador de llamada de herramienta; sgl-router y sglang-server mantienen sus analizadores Rust por ahora: #45315, #45907, #46219
  • La reproducción limitada SWA del decodificador DeepSeek-V4.1 está activada de forma predeterminada para configuraciones CUDA compatibles, incluidas ambas funciones de PD. No es numéricamente idéntico al prellenado completo. Pase --no-enable-decoder-swa-bounded-replay para mantener el prellenado completo, por ejemplo, para implementaciones de RL cuyos logprobs deben coincidir con el entrenador: #44403, #45035
  • DeepSeek-V4.1 tiene como valor predeterminado MegaAttention en PD. En SM100/SM103, ambas funciones de PD ahora resuelven flashmla_mega y el protocolo de enlace de PD verifica el diseño de KV, por lo que el prellenado y la decodificación deben ejecutar el mismo backend de atención (#45075). Actualice el prellenado y la decodificación juntos, ya que una decodificación anterior no puede leer el nuevo campo de protocolo de enlace; pase --dsv4-attn-backend flashmla en ambos roles para mantener FlashMLA. Los servidores agregados mantienen FlashMLA cuando la atención es tenso-paralela entre rangos: #46263
  • Se eliminó el backend de atención de tokenspeed_mla. tokenspeed_mla todavía comienza como un alias obsoleto para cutedsl_mla con una advertencia. Para cambiar, pase --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, más --speculative-attention-mode decode con decodificación especulativa: #44803
  • Se eliminó --speculative-skip-dp-mlp-sync. Los comandos de inicio que lo pasan ahora fallan con un error de argumento no reconocido; suelta la bandera: #45043
  • Se elimina el nombre de cuantificación de difusión kitchen_int8. Utilice convrot_int8, en desuso en su favor desde v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE ahora se ignora sin previo aviso. Ya no tuvo ningún efecto porque el árbol de base unificado es el predeterminado; suéltelo desde los scripts de inicio: #45090
  • Los puntos de control .pt en formato tar heredado ya no se cargan. Se eliminó el respaldo inseguro del pickle weights_only=False; convierta dichos puntos de control a tensores de seguridad o formato zip .pt sin conexión: #42760
  • Los puntos finales HTTP de difusión se validan de forma más estricta. Los valores de URL para upscaling_model_path y frame_interpolation_model_path devuelven 400, un response_format no compatible se rechaza antes de la generación y una carga fallida en la nube devuelve 502 en lugar de 400: #43585
  • El primer inicio de un servidor FlashInfer CUTLASS MoE tarda más. El autoajuste de inicio ahora también cubre los tamaños de precarga, por lo que un servidor sin resultados de ajuste guardados tarda más en estar listo (en DeepSeek-V4.1-Flash en 8x H200, el autoajuste va de aproximadamente 41 s a 177 s). Los inicios posteriores reutilizan los resultados guardados y --disable-flashinfer-autotune omite el ajuste: #43363
  • Las respuestas de difusión PNG son más grandes. La salida PNG ahora tiene como valor predeterminado el nivel 0 de zlib: los mismos píxeles, aproximadamente 3 veces los bytes, varias veces más rápido de codificar. Establezca output_compression en un valor distinto de 75 para elegir un nivel: #45987
  • sgl-router se movió al directorio sgl-router/ de nivel superior. Las compilaciones y scripts que apuntan a experimental/sgl-router/ deben actualizar la ruta (#45414); --max-in-flight ahora es --max-inflight-requests y el nombre anterior todavía funciona como alias: #44950

  • SGLang low-latency mode: the opt-in NVIDIA megakernel and AMD monokernel plugins run DeepSeek-V4.1-Flash decode as fused persistent kernels, for up to 44% faster single-user decode on GB300 and 75% on MI350X (#44945, #45450, #44353, #44621).

  • Paged Experts (opt-in) runs MoE models larger than GPU memory on a single consumer GPU, up to 30x faster than CPU offload (#42557, #45787).
  • SGLang now runs on Google TPU7x through SGLang-TorchTPU, a PyTorch-native plugin for TPU.
  • You can now serve LoRA adapters on quantized MoE models (FP8 and NVFP4) with a new opt-in LoRA engine (#45892).
  • DeepSeek-style MLA models running decode context parallelism can now keep their prefix cache in HiCache file-based L3 storage (#41187).

Breaking Changes & Upgrade Notes

  • DeepSeek-V4 and V4.1 chat now follows deepseek-recipe. Prompts, outputs and the native /separate_reasoning and /parse_function_call endpoints go through DeepSeek's official encoder, and SGLang's own encoding_dsv4.py / encoding_dsv41.py are gone. Clients may notice: streamed tool-call arguments arrive in pieces (the first chunk carries arguments: ""), so concatenate them as the OpenAI SDK does; tool-call ids use the official call_00_... format; V4 reasoning effort follows DeepSeek's official profile and the dsv4_reasoning_effort_profile override is removed; a numeric reasoning_effort on V4 returns 400; developer messages render as system messages; /parse_function_call also returns calls to tools outside tools with tool_index -1; requests that combine tools with continue_final_message return 400. Output parsing goes through deepseek-recipe when the DeepSeek reasoning or tool-call parser is set; sgl-router and sglang-server keep their Rust parsers for now: #45315, #45907, #46219
  • DeepSeek-V4.1 decoder SWA bounded replay is on by default for supported CUDA configurations, including both PD roles. It is not numerically identical to full prefill. Pass --no-enable-decoder-swa-bounded-replay to keep full prefill, for example for RL rollouts whose logprobs must match the trainer: #44403, #45035
  • DeepSeek-V4.1 defaults to MegaAttention under PD. On SM100 / SM103 both PD roles now resolve flashmla_mega and the PD handshake checks the KV layout, so prefill and decode must run the same attention backend (#45075). Upgrade prefill and decode together, since an older decode cannot read the new handshake field; pass --dsv4-attn-backend flashmla on both roles to keep FlashMLA. Aggregated servers keep FlashMLA when attention is tensor-parallel across ranks: #46263
  • The tokenspeed_mla attention backend is removed. tokenspeed_mla still starts as a deprecated alias for cutedsl_mla with a warning. To switch, pass --attention-backend cutedsl_mla --kv-cache-dtype fp8_e4m3, plus --speculative-attention-mode decode with speculative decoding: #44803
  • --speculative-skip-dp-mlp-sync is removed. Launch commands that pass it now fail with an unrecognized-argument error; drop the flag: #45043
  • The kitchen_int8 diffusion quantization name is removed. Use convrot_int8, deprecated in favor of it since v0.5.22: #45706
  • SGLANG_ENABLE_UNIFIED_RADIX_TREE is now ignored without a warning. It already had no effect because the unified radix tree is the default; drop it from launch scripts: #45090
  • Legacy tar-format .pt checkpoints no longer load. The unsafe weights_only=False pickle fallback is removed; convert such checkpoints to safetensors or zip-format .pt offline: #42760
  • Diffusion HTTP endpoints validate more strictly. URL values for upscaling_model_path and frame_interpolation_model_path return 400, an unsupported response_format is rejected before generation, and a failed cloud upload returns 502 instead of 400: #43585
  • The first startup of a FlashInfer CUTLASS MoE server takes longer. Startup autotune now also covers prefill sizes, so a server with no saved tuning results takes longer to become ready (on DeepSeek-V4.1-Flash on 8x H200, autotune goes from about 41 s to 177 s). Later startups reuse the saved results, and --disable-flashinfer-autotune skips tuning: #43363
  • Diffusion PNG responses are larger. PNG output now defaults to zlib level 0: the same pixels, about 3x the bytes, several times faster to encode. Set output_compression to a value other than 75 to pick a level: #45987
  • sgl-router moved to the top-level sgl-router/ directory. Builds and scripts that point at experimental/sgl-router/ must update the path (#45414); --max-in-flight is now --max-inflight-requests, and the old name still works as an alias: #44950
