análisis_de_stock_diario v3.6.0

Agregado

  • 🗑️ Eliminación del historial por lotes: la interfaz de usuario web ahora admite la selección múltiple y la eliminación por lotes del historial de análisis; Se agregó el punto final POST /api/v1/history/batch-delete y el componente ConfirmDialog.
  • 🔐 Configuración de autenticación API: nuevo punto final POST /api/v1/auth/settings para habilitar o deshabilitar la autenticación web en tiempo de ejecución y establecer la contraseña de administrador inicial cuando sea necesario
  • Habilidad openclaw 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 Habilidad openclaw 调用 DSA API
  • ⚙️ Protocolo de canal LLM/UX de prueba: .env y la configuración web ahora comparten la misma forma de canal (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED); La página de configuración agrega pruebas de conexión por canal, selección de modelo primario/alternativo/de visión y prefijo de modelo con reconocimiento de protocolo.
  • 🤖 Arquitectura del agente Fase 0+1: protocolos compartidos (AgentContext, AgentOpinion, StageResult), ejecutor run_agent_loop() extraído, conmutador AGENT_ARCH (single/multi), entradas de registro de configuración
  • 🔍 Enrutamiento de bot NL: enrutamiento de lenguaje natural de dos capas: prefiltro de expresiones regulares económico (códigos de acciones + palabras clave financieras) → análisis de intención de LLM liviano; controlado por AGENT_NL_ROUTING=true; admite la extracción de múltiples acciones y estrategias
  • 💬 Análisis de múltiples acciones /ask: códigos separados por comas o vs (máximo 5), ejecución de subprocesos paralelos con tiempo de espera de 150 segundos (conserva resultados parciales), tabla de resumen de comparación de Markdown en la parte superior
  • 📋 Comando /history: aislamiento de sesión por usuario mediante el formato {platform}_{user_id}:{scope} (el delimitador de dos puntos evita la colisión de prefijos); enumera las sesiones /chat y /ask; ver detalle o borrar
  • 📊 Comando /strategies: enumera los archivos de estrategia YAML disponibles agrupados por categoría (趋势/形态/反转/框架) con estado de activación ✅/⬜
  • 🔧 Herramientas de resumen de backtest: get_strategy_backtest_summary y get_stock_backtest_summary registrados como herramientas de agente de solo lectura
  • ⚙️ Detección automática del agente — is_agent_available() detecta automáticamente desde LITELLM_MODEL; explícito AGENT_MODE=true/false tiene prioridad total
  • 🏗️ Orquestador multiagente (Fase 2) — AgentOrchestrator con 4 modos (quick/standard/full/strategy); reemplazo directo para AgentExecutor a través de AGENT_ARCH=multi; BaseAgent ABC con filtrado de subconjuntos de herramientas, inyección de datos en caché y salida estructurada AgentOpinion
  • 🧩 Agentes especializados (Fase 2-4) — TechnicalAgent (8 herramientas, análisis de tendencias/MA/MACD/volumen/patrones), IntelAgent (noticias y sentimiento, propagación de indicadores de riesgo), DecisionAgent (síntesis en el panel de decisiones JSON), RiskAgent (7 categorías de riesgo, gravedad de dos niveles con anulación suave/dura)
  • 📈 Sistema de estrategia (Fase 3) — StrategyAgent (evaluación por estrategia a partir de habilidades YAML), StrategyRouter (detección de régimen basada en reglas → selección de estrategia), StrategyAggregator (consenso ponderado con factor de rendimiento de backtest)
  • 🔬 Agente de investigación profunda (Fase 5) — ResearchAgent con enfoque de 3 fases (descomponer → subpreguntas de investigación → sintetizar informe); seguimiento del presupuesto simbólico; Nuevo comando de bot /research con alias (/深研, /deepsearch)
  • 🧠 Memoria y calibración (Fase 6) — AgentMemory con seguimiento de precisión de predicción, calibración de confianza (se activa después del umbral mínimo de muestra), ponderación automática de estrategia basada en la tasa de ganancia histórica
  • 📊 Agente de cartera (Fase 7) — PortfolioAgent para análisis de carteras de múltiples acciones (tamaño de posición, concentración sectorial, riesgo de correlación, vínculos entre mercados, sugerencias de reequilibrio)
  • 🔔 Alertas basadas en eventos (Fase 7) — EventMonitor con reglas PriceAlert, VolumeAlert, SentimentAlert; comprobación asíncrona, notificaciones de devolución de llamada, persistencia serializable
  • ⚙️ Nuevas entradas de configuración — AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING — todos registrados en config.py + config_registry.py (configurable por WebUI)

Cambiado

  • 🔐 Semántica del estado de la contraseña de autenticación: la existencia de la contraseña almacenada ahora se rastrea independientemente de la habilitación de la autenticación; cuando la autenticación está deshabilitada, /api/v1/auth/status devuelve passwordSet=false conservando la contraseña guardada para volver a habilitarla en el futuro
  • 🔐 La configuración de autenticación vuelve a habilitar el refuerzo: volver a habilitar la autenticación con una contraseña almacenada ahora requiere currentPassword, y la creación fallida de la sesión revierte el interruptor de autenticación para evitar el bloqueo.
  • ♻️ AgentExecutor refactorizado — _run_loop delega en runner.run_agent_loop() compartido; Se eliminó el código duplicado de serialización/análisis/etiqueta de pensamiento.
  • ♻️ Cambio de agente unificado: Bot, API y Pipeline usan config.is_agent_available() en lugar de comprobaciones divergentes de config.agent_mode.
  • 📖 README.md: sección de comandos de bot ampliada (ask/chat/strategies/history), nota de enrutamiento NL agregada, descripción actualizada del modo agente
  • 📖 .env.example — se agregó documentación de configuración de AGENT_ARCH y AGENT_NL_ROUTING

Fijo

  • 🐛 Rotación de secretos de sesión en Windows: use reemplazo atómico para que los cambios de autenticación invaliden las sesiones existentes incluso cuando .session_secret ya exista
  • 🐛 Atomicidad de alternancia de autenticación: persiste ADMIN_AUTH_ENABLED antes de rotar el secreto de sesión; en caso de falla de rotación, retroceder al estado de autenticación anterior
  • 🔧 Barandillas de selección de tiempo de ejecución de LLM: el editor de canales en el modo YAML ya no cubre LITELLM_MODEL/fallback/Vision; la verificación de la configuración del sistema agrega la verificación de la fuente de tiempo de ejecución después de que todos los canales estén deshabilitados y soluciona el problema de que los modelos de alias de protocolo, como vertexai/..., tengan prefijos repetidos.
  • 🐛 Regresiones de seguimiento de /ask de múltiples acciones: la superposición de cartera ahora comparte el mismo presupuesto de tiempo de espera que la fase por acción y se omite durante el tiempo de espera en lugar de bloquear la respuesta del bot; /history ahora almacena el resumen legible por acción en lugar del panel sin formato JSON; La salida condensada de stock múltiple ahora genera valores numéricos sniper_points
  • 🐛 Compatibilidad de enumeración del panel de decisiones: DecisionAgent multiagente ahora mantiene decision_type dentro del contrato buy|hold|sell heredado y normaliza las salidas perdidas de strong_* antes de la anulación de riesgos, la conversión de canalización y el flujo descendente.
  • 🛟 Reserva de resultados parciales de múltiples agentes: IntelAgent ahora almacena en caché la información analizada para su reutilización posterior, el análisis compartido de JSON tolera la salida del modelo ligeramente mal formada y el orquestador conserva/sintetiza un panel mínimo en el tiempo de espera o falla de análisis a mitad de proceso en lugar de colapsar siempre a 50/观望/未知
  • 🐛 Enrutamiento LiteLLM compartido restaurado: el análisis de intención del bot NL y la planificación/síntesis de ResearchAgent ahora reutilizan la misma ruta de inyección LiteLLM adaptador/enrutador/refuerzo/api_base como el flujo principal del agente, por lo que las implementaciones compatibles con LLM_CHANNELS/LITELLM_CONFIG/OpenAI se comportan de manera consistente
  • 🐛 Compatibilidad con versiones anteriores de sesiones de chat de bot: /chat ahora sigue usando la identificación de sesión heredada de {platform}_{user_id} cuando ya existe un historial antiguo, y /history aún puede enumerar/ver/borrar esas sesiones previas a la migración junto con el nuevo formato {platform}_{user_id}:chat.
  • 🐛 Rechazo de reglas no admitidas por EventMonitor: la validación de configuración/carga del tiempo de ejecución ahora rechaza u omite tipos de alerta que el monitor aún no puede evaluar, por lo que el modo de programación ya no acepta silenciosamente reglas permanentes de no operación
  • 🐛 Corrección de estabilidad de agregación fundamental P0 (#614): corrige la regresión semántica del sector get_stock_info (agregue belong_boards y conserve los alias compatibles con boards), introduzca retornos simplificados del contexto fundamental para los tokens de control, agregue eliminación máxima de entrada al caché fundamental y complete la agregación de estado general de ETF y el filtrado de campos del sector NaN para garantizar una apertura fallida y una intrusión mínima.
  • 🔧 Adición de variable de entorno del motor de búsqueda de GitHub Actions: el flujo de trabajo agrega el mapeo de variables de entorno MINIMAX_API_KEYS, BRAVE_API_KEYS, SEARXNG_BASE_URLS, lo que permite a los usuarios de GitHub Actions configurar los servicios de búsqueda MiniMax, Brave y SearXNG (anteriormente, v3.5.0 había agregado implementación de proveedor pero carecía de configuración de flujo de trabajo).
  • 🤖 Coherencia en tiempo de ejecución de múltiples agentes: AGENT_MAX_STEPS ahora se propaga a cada subagente orquestado; Se agregó presupuesto cooperativo AGENT_ORCHESTRATOR_TIMEOUT_S para detener tuberías demasiado largas antes de que sigan cayendo en cascada.
  • 🔌 Cableado de funciones de múltiples agentes: AGENT_RISK_OVERRIDE ahora degrada activamente los paneles finales sobre hallazgos de riesgos concretos; AGENT_MEMORY_ENABLED ahora inyecta memoria de análisis reciente + calibración de confianza en agentes especializados; /ask de múltiples acciones ahora ejecuta PortfolioAgent para agregar orientación sobre asignación y concentración a nivel de cartera
  • 🔔 Cableado de tiempo de ejecución de EventMonitor: el modo de programación ahora puede cargar reglas de alerta desde AGENT_EVENT_ALERT_RULES_JSON, sondearlas en AGENT_EVENT_MONITOR_INTERVAL_MINUTES y enviar alertas activadas a través del servicio de notificación existente
  • 🛠️ Correcciones de estabilidad de seguimiento: /ask de múltiples acciones ahora recurre a la salida de texto utilizable cuando falla el análisis del panel JSON; EventMonitor omite reglas semánticamente inválidas en lugar de cancelar el inicio del programa; El sondeo de alerta en segundo plano ahora se ejecuta independientemente del ciclo principal de análisis programado.
  • 🧪 Cobertura de regresión multiagente: se agregaron pruebas de ejecución del orquestador para run(), chat(), falla en etapa crítica, degradación elegante y manejo de tiempo de espera.
  • 🧹 Limpieza de PortfolioAgent: post_process() ahora reutiliza el análisis compartido de JSON y eliminó las importaciones obsoletas no utilizadas
  • 🚦 Envío asíncrono de bot: CommandDispatcher ahora expone dispatch_async(); El análisis de intenciones de NL y la ejecución de comandos predeterminada se descargan del bucle de eventos, la transmisión de DingTalk espera a los controladores asíncronos directamente y el procesamiento de la transmisión de Feishu se retira del subproceso de devolución de llamada SDK
  • 🌐 Manejador de webhook asíncrono: nueva función handle_webhook_async() en bot/handler.py para usar desde contextos asíncronos (por ejemplo, FastAPI); llama a dispatch_async() directamente sin puentes de hilo
  • 🧵 Feishu stream ThreadPoolExecutor: se reemplazó el desove ilimitado por mensaje de Thread con un ThreadPoolExecutor(max_workers=8) limitado para evitar la explosión de subprocesos en ráfagas de mensajes.
  • 🔒 Seguridad de EventMonitor: _check_volume() ahora maneja de forma segura get_daily_data que devuelve None (sin fallas al descomprimir tuplas); Las devoluciones de llamada on_trigger admiten llamadas sincronizadas y asíncronas a través de asyncio.to_thread/await
  • 🧹 ResearchAgent dedup: _filtered_registry() ahora delega en BaseAgent._filtered_registry() en lugar de duplicar la lógica de filtrado
  • 🧹 Limpieza de espacios en blanco al final del robot: se eliminaron los problemas de espacios en blanco W291/W293 en bot/handler.py, bot/dispatcher.py, bot/commands/base.py, bot/platforms/feishu_stream.py, bot/platforms/dingtalk_stream.py
  • 🐛 Seguridad del despachador _parse_intent_via_llm: se reemplazó el frágil 'raw' in dir() por 'raw' in locals() para protección de variable indefinida en el controlador JSONDecodeError
  • 🐛 Complete la estructura del chip LLM cuando no esté completa (#589): cuando DeepSeek y otros modelos no completan chip_structure correctamente, lo completará automáticamente con los datos del chip obtenidos de la fuente de datos para garantizar que la visualización de cada modelo sea consistente; Tanto el análisis normal como el modo Agente son válidos.
  • 🐛 Texto original de visualización del punto de francotirador del informe histórico (#452): la página de detalles históricos ahora da prioridad a mostrar la cadena original en raw_result.dashboard.battle_plan.sniper_points para evitar que la columna numérica analysis_history comprima intervalos, texto explicativo o puntos complejos en un solo número; conservar la columna numérica original como alternativa
  • 🐛 Colisión de prefijos de sesión: el ID de usuario 123 podía ver las sesiones del usuario 1234 a través de startswith; arreglado con delimitador de dos puntos en formato session_id
  • 🐛 Falsos positivos del prefiltro de NL: re.IGNORECASE provocó que [A-Z]{2,5} coincidiera con palabras comunes en inglés como "hello"; Se eliminó la bandera global, use (?i:...) en línea solo para palabras clave de finanzas en inglés.
  • 🐛 Ticker punteado en argumentos de estrategia: _get_strategy_args() no reconoció BRK.B como un código de acciones y lo dejó en el texto de la estrategia; ahora acepta el formato TICKER.CLASS
  • ⏱️ Corrección de bloqueo de llamada larga de efinance (#660): introduce el contenedor _ef_call_with_timeout() para todas las llamadas de efinance API (30 segundos predeterminado, configurable a través de EFINANCE_CALL_TIMEOUT); use executor.shutdown(wait=False) para garantizar que el hilo principal ya no esté bloqueado después del tiempo de espera, eliminando por completo el problema de bloqueo de 81 minutos
  • 🛡️ Verificación de integridad de contenido con seguridad de tipos (#660): check_content_integrity() ahora trata los tipos que no son cadenas operation_advice / analysis_summary como campos faltantes para evitar fallas posteriores de get_emoji() debido a dict.strip()
  • 📄 Desacoplamiento del guardado y notificación de informes (#660): _save_local_report() ya no depende del activador de bandera send_notification y los informes locales se guardan como de costumbre en el modo --no-notify.
  • 🔄 normalización del diccionario de consejos de operación (#660): Pipeline y BacktestEngine ahora asignan el formato dict operation_advice devuelto por LLM a una cadena estándar a través de decision_type (no distingue entre mayúsculas y minúsculas) para evitar fallas causadas por cambios en el formato de salida del modelo.
  • 🛡️ uso de runner.py Ninguna protección (#660) — AttributeError ya no se genera cuando response.usage es None, se vuelve a 0 recuento de tokens
  • 📋 Fallo silencioso del orquestador cambiado a advertencia de registro (#660): el fallo de etapa IntelAgent / RiskAgent ahora registra WARNING en lugar de omitirlo silenciosamente, para facilitar el diagnóstico.

Notas

  • ⚠️ Alternancias de autenticación de múltiples trabajadores: las actualizaciones de autenticación en tiempo de ejecución son locales del proceso; las implementaciones de varios trabajadores deben reiniciar/rotar a los trabajadores para mantener el estado de autenticación consistente

daily_stock_analysis v3.6.0

Added

  • 🗑️ History batch deletion — Web UI now supports multi-selection and batch deletion of analysis history; added POST /api/v1/history/batch-delete endpoint and ConfirmDialog component.
  • 🔐 Auth settings API — new POST /api/v1/auth/settings endpoint to enable or disable Web authentication at runtime and set the initial admin password when needed
  • openclaw Skill 集成指南 — 新增 docs/openclaw-skill-integration.md，说明如何通过 openclaw Skill 调用 DSA API
  • ⚙️ LLM channel protocol/test UX — .env and Web settings now share the same channel shape (LLM_CHANNELS + LLM_<NAME>_PROTOCOL/BASE_URL/API_KEY/MODELS/ENABLED); settings page adds per-channel connection testing, primary/fallback/vision model selection, and protocol-aware model prefixing
  • 🤖 Agent architecture Phase 0+1 — shared protocols (AgentContext, AgentOpinion, StageResult), extracted run_agent_loop() runner, AGENT_ARCH switch (single/multi), config registry entries
  • 🔍 Bot NL routing — two-layer natural-language routing: cheap regex pre-filter (stock codes + finance keywords) → lightweight LLM intent parsing; controlled by AGENT_NL_ROUTING=true; supports multi-stock and strategy extraction
  • 💬 /ask multi-stock analysis — comma or vs separated codes (max 5), parallel thread execution with 150s timeout (preserves partial results), Markdown comparison summary table at top
  • 📋 /history command — per-user session isolation via {platform}_{user_id}:{scope} format (colon delimiter prevents prefix collision); lists both /chat and /ask sessions; view detail or clear
  • 📊 /strategies command — lists available strategy YAML files grouped by category (趋势/形态/反转/框架) with ✅/⬜ activation status
  • 🔧 Backtest summary tools — get_strategy_backtest_summary and get_stock_backtest_summary registered as read-only Agent tools
  • ⚙️ Agent auto-detection — is_agent_available() auto-detects from LITELLM_MODEL; explicit AGENT_MODE=true/false takes full precedence
  • 🏗️ Multi-Agent orchestrator (Phase 2) — AgentOrchestrator with 4 modes (quick/standard/full/strategy); drop-in replacement for AgentExecutor via AGENT_ARCH=multi; BaseAgent ABC with tool subset filtering, cached data injection, and structured AgentOpinion output
  • 🧩 Specialised agents (Phase 2-4) — TechnicalAgent (8 tools, trend/MA/MACD/volume/pattern analysis), IntelAgent (news & sentiment, risk flag propagation), DecisionAgent (synthesis into Decision Dashboard JSON), RiskAgent (7 risk categories, two-level severity with soft/hard override)
  • 📈 Strategy system (Phase 3) — StrategyAgent (per-strategy evaluation from YAML skills), StrategyRouter (rule-based regime detection → strategy selection), StrategyAggregator (weighted consensus with backtest performance factor)
  • 🔬 Deep Research agent (Phase 5) — ResearchAgent with 3-phase approach (decompose → research sub-questions → synthesise report); token budget tracking; new /research bot command with aliases (/深研, /deepsearch)
  • 🧠 Memory & calibration (Phase 6) — AgentMemory with prediction accuracy tracking, confidence calibration (activates after minimum sample threshold), strategy auto-weighting based on historical win rate
  • 📊 Portfolio Agent (Phase 7) — PortfolioAgent for multi-stock portfolio analysis (position sizing, sector concentration, correlation risk, cross-market linkage, rebalance suggestions)
  • 🔔 Event-driven alerts (Phase 7) — EventMonitor with PriceAlert, VolumeAlert, SentimentAlert rules; async checking, callback notifications, serializable persistence
  • ⚙️ New config entries — AGENT_ORCHESTRATOR_MODE, AGENT_RISK_OVERRIDE, AGENT_DEEP_RESEARCH_BUDGET, AGENT_MEMORY_ENABLED, AGENT_STRATEGY_AUTOWEIGHT, AGENT_STRATEGY_ROUTING — all registered in config.py + config_registry.py (WebUI-configurable)

Changed

  • 🔐 Auth password state semantics — stored password existence is now tracked independently from auth enablement; when auth is disabled, /api/v1/auth/status returns passwordSet=false while preserving the saved password for future re-enable
  • 🔐 Auth settings re-enable hardening — re-enabling auth with a stored password now requires currentPassword, and failed session creation rolls back the auth toggle to avoid lockout
  • ♻️ AgentExecutor refactored — _run_loop delegates to shared runner.run_agent_loop(); removed duplicated serialization/parsing/thinking-label code
  • ♻️ Unified agent switch — Bot, API, and Pipeline all use config.is_agent_available() instead of divergent config.agent_mode checks
  • 📖 README.md — expanded Bot commands section (ask/chat/strategies/history), added NL routing note, updated agent mode description
  • 📖 .env.example — added AGENT_ARCH and AGENT_NL_ROUTING configuration documentation

Fixed

  • 🐛 Session secret rotation on Windows — use atomic replace so auth toggles invalidate existing sessions even when .session_secret already exists
  • 🐛 Auth toggle atomicity — persist ADMIN_AUTH_ENABLED before rotating session secret; on rotation failure, roll back to the previous auth state
  • 🔧 LLM runtime selection guardrails — YAML 模式下渠道编辑器不再覆盖 LITELLM_MODEL / fallback / Vision；系统配置校验补上全部渠道禁用后的运行时来源检查，并修复 vertexai/... 这类协议别名模型被重复加前缀的问题
  • 🐛 Multi-stock /ask follow-up regressions — portfolio overlay now shares the same timeout budget as the per-stock phase and is skipped on timeout instead of blocking the bot reply; /history now stores the readable per-stock summary instead of raw dashboard JSON; condensed multi-stock output now renders numeric sniper_points values
  • 🐛 Decision dashboard enum compatibility — multi-agent DecisionAgent now keeps decision_type within the legacy buy|hold|sell contract and normalizes stray strong_* outputs before risk override, pipeline conversion, and downstream统计/通知汇总
  • 🛟 Multi-Agent partial-result fallback — IntelAgent now caches parsed intel for downstream reuse, shared JSON parsing tolerates lightly malformed model output, and the orchestrator preserves/synthesizes a minimal dashboard on timeout or mid-pipeline parse failure instead of always collapsing to 50/观望/未知
  • 🐛 Shared LiteLLM routing restored — bot NL intent parsing and ResearchAgent planning/synthesis now reuse the same LiteLLM adapter / Router / fallback / api_base injection path as the main Agent flow, so LLM_CHANNELS / LITELLM_CONFIG / OpenAI-compatible deployments behave consistently
  • 🐛 Bot chat session backward compatibility — /chat now keeps using the legacy {platform}_{user_id} session id when old history already exists, and /history can still list / view / clear those pre-migration sessions alongside the new {platform}_{user_id}:chat format
  • 🐛 EventMonitor unsupported rule rejection — config validation/runtime loading now reject or skip alert types the monitor cannot actually evaluate yet, so schedule mode no longer silently accepts permanent no-op rules
  • 🐛 P0 基本面聚合稳定性修复 (#614) — 修复 get_stock_info 板块语义回归（新增 belong_boards 并保留 boards 兼容别名）、引入基本面上下文精简返回以控制 token、为基本面缓存增加最大条目淘汰，并补齐 ETF 总体状态聚合与 NaN 板块字段过滤，保证 fail-open 与最小入侵。

  • 🤖 Multi-Agent runtime consistency — AGENT_MAX_STEPS now propagates to each orchestrated sub-agent; added cooperative AGENT_ORCHESTRATOR_TIMEOUT_S budget to stop overlong pipelines before they cascade further
  • 🔌 Multi-Agent feature wiring — AGENT_RISK_OVERRIDE now actively downgrades final dashboards on hard risk findings; AGENT_MEMORY_ENABLED now injects recent analysis memory + confidence calibration into specialised agents; multi-stock /ask now runs PortfolioAgent to add portfolio-level allocation and concentration guidance
  • 🔔 EventMonitor runtime wiring — schedule mode can now load alert rules from AGENT_EVENT_ALERT_RULES_JSON, poll them at AGENT_EVENT_MONITOR_INTERVAL_MINUTES, and send triggered alerts through the existing notification service
  • 🛠️ Follow-up stability fixes — multi-stock /ask now falls back to usable text output when dashboard JSON parsing fails; EventMonitor skips semantically invalid rules instead of aborting schedule startup; background alert polling now runs independently of the main scheduled analysis loop
  • 🧪 Multi-Agent regression coverage — added orchestrator execution tests for run(), chat(), critical-stage failure, graceful degradation, and timeout handling
  • 🧹 PortfolioAgent cleanup — post_process() now reuses shared JSON parsing and removed stale unused imports
  • 🚦 Bot async dispatch — CommandDispatcher now exposes dispatch_async(); NL intent parsing and default command execution are offloaded from the event loop, DingTalk stream awaits async handlers directly, and Feishu stream processing is moved off the SDK callback thread
  • 🌐 Async webhook handler — new handle_webhook_async() function in bot/handler.py for use from async contexts (e.g. FastAPI); calls dispatch_async() directly without thread bridging
  • 🧵 Feishu stream ThreadPoolExecutor — replaced unbounded per-message Thread spawning with a capped ThreadPoolExecutor(max_workers=8) to prevent thread explosion under message bursts
  • 🔒 EventMonitor safety — _check_volume() now safely handles get_daily_data returning None (no tuple-unpacking crash); on_trigger callbacks support both sync and async callables via asyncio.to_thread/await
  • 🧹 ResearchAgent dedup — _filtered_registry() now delegates to BaseAgent._filtered_registry() instead of duplicating the filtering logic
  • 🧹 Bot trailing whitespace cleanup — removed W291/W293 whitespace issues across bot/handler.py, bot/dispatcher.py, bot/commands/base.py, bot/platforms/feishu_stream.py, bot/platforms/dingtalk_stream.py
  • 🐛 Dispatcher _parse_intent_via_llm safety — replaced fragile 'raw' in dir() with 'raw' in locals() for undefined-variable guard in JSONDecodeError handler
  • 🐛 筹码结构 LLM 未填写时兜底补全 (#589) — DeepSeek 等模型未正确填写 chip_structure 时，自动用数据源已获取的筹码数据补全，保证各模型展示一致；普通分析与 Agent 模式均生效
  • 🐛 历史报告狙击点位显示原始文本 (#452) — 历史详情页现优先展示 raw_result.dashboard.battle_plan.sniper_points 中的原始字符串，避免 analysis_history 数值列把区间、说明文字或复杂点位压缩成单个数字；保留原有数值列作为回退
  • 🐛 Session prefix collision — user ID 123 could see sessions of user 1234 via startswith; fixed with colon delimiter in session_id format
  • 🐛 NL pre-filter false positives — re.IGNORECASE caused [A-Z]{2,5} to match common English words like "hello"; removed global flag, use inline (?i:...) only for English finance keywords
  • 🐛 Dotted ticker in strategy args — _get_strategy_args() didn't recognize BRK.B as a stock code, leaving it in strategy text; now accepts TICKER.CLASS format
  • ⏱️ efinance 长调用挂起修复 (#660) — 为所有 efinance API 调用引入 _ef_call_with_timeout() 包装（默认 30 秒，可通过 EFINANCE_CALL_TIMEOUT 配置）；使用 executor.shutdown(wait=False) 确保超时后不再阻塞主线程，彻底消除 81 分钟挂起问题
  • 🛡️ 类型安全内容完整性检查 (#660) — check_content_integrity() 现在将非字符串类型的 operation_advice / analysis_summary 视为缺失字段，避免下游 get_emoji() 因 dict.strip() 崩溃
  • 📄 报告保存与通知解耦 (#660) — _save_local_report() 不再依赖 send_notification 标志触发，--no-notify 模式下本地报告照常保存
  • 🔄 operation_advice 字典归一化 (#660) — Pipeline 和 BacktestEngine 现在将 LLM 返回的 dict 格式 operation_advice 通过 decision_type（不区分大小写）映射为标准字符串，防止因模型输出格式变化导致崩溃
  • 🛡️ runner.py usage None 防护 (#660) — response.usage 为 None 时不再抛出 AttributeError，回退为 0 token 计数
  • 📋 orchestrator 静默失败改为日志警告 (#660) — IntelAgent / RiskAgent 阶段失败现在记录 WARNING 而非静默跳过，便于诊断
