análisis_de_stock_diario v3.8.0

Aspectos destacados de la versión

  • 🎨 La interfaz web completa una ronda de actualización básica: la nueva App Shell, la navegación lateral, las capacidades de temas, los procesos de inicio de sesión y configuración del sistema se han unido en una experiencia unificada, y el fondo de carga del escritorio también se ha alineado.
  • 📈 Se sigue mejorando el contexto analítico: las acciones estadounidenses han agregado información sobre la opinión pública social, las acciones A han agregado un contexto estructural para los informes financieros y los dividendos, y Tushare ha accedido recientemente a datos de subidas y bajadas del sector industrial y de distribución de chips.
  • 🔒 Se mejoró la estabilidad de la operación y la compatibilidad de la configuración: cerrar la sesión invalidará inmediatamente las sesiones anteriores, el inicio programado es compatible con las configuraciones anteriores y los comentarios sobre la ejecución de los ajustes de MAX_WORKERS y las ventanas de puntualidad de las noticias serán más claros.
  • 💼 El enlace de corrección de errores de posición es más completo: la sobreventa se interceptará con anticipación y las transacciones/flujos de capital/acciones de la empresa erróneas se pueden eliminar y revertir directamente para facilitar la reparación de datos sucios.

Nuevas funciones

  • 📱 Inteligencia de opinión pública social de acciones de EE. UU. — Añadido Reddit /
  • 📊 Mejora de la estructura de dividendos y informes financieros de acciones A (Edición n.° 710) - fundamental_context.earnings.data agrega los campos financial_report y dividend; los dividendos se calculan uniformemente basándose en "dividendos en efectivo únicamente, calibre antes de impuestos", y se suman ttm_cash_dividend_per_share y ttm_dividend_yield_pct; análisis/historial API details se agregan campos opcionales financial_report, dividend_metrics, manteniendo la compatibilidad con versiones anteriores y de falla de apertura.
  • 🔍 Acceso a chips Tushare y a la interfaz del sector industrial - Distribución de chips agregada, capacidades de adquisición de datos de ascenso y descenso del sector industrial e inclusión unificada de prioridades de fuentes de datos configuradas; De forma predeterminada, los días de negociación intradía/fuera de horario se recuperan según la hora de Shanghai, se da prioridad al uso de la interfaz Tushare Flush y se degrada a Dongcai si es necesario.
  • 🧱 Actualización del esqueleto básico de la interfaz de usuario web: reconstruya tokens de diseño compartidos y componentes comunes, agregue App Shell, proveedor de temas, navegación lateral y, simultáneamente, ajuste el fondo de carga de Electron para sentar las bases de una experiencia web/de escritorio unificada.
  • 🔐 Proceso de inicio de sesión y configuración del sistema rehecho: reconstruya los procesos de inicio de sesión, configuración y administración de autenticación, agregue procesamiento de estado de configuración de autenticación explícito y alinee el lado web con el comportamiento de configuración de autenticación en tiempo de ejecución API.
  • 🧪 Regresión frontal y mejora de la cobertura de humo: agregue y amplíe las pruebas de componentes y la cobertura de humo de Playwright para rutas clave como inicio de sesión, página de inicio, chat, shell móvil, página de configuración, entrada de backtest, etc.

Cambiar

  • 🧭 Acceso a la página al nuevo contrato de diseño de Shell: Inicio, Chat, Configuración y Prueba retrospectiva se han unificado para acceder a nuevos contenedores de páginas, cajones y convenciones de desplazamiento para reducir la inconsistencia en el comportamiento de la página durante la migración de la interfaz de usuario.
  • 💾 Sincronización más estable del estado de la página de configuración: optimice la retención de borradores, la sincronización de guardado directo y el manejo de conflictos, lo que reduce el problema del estado de configuración inconsistente de front-end y back-end después de guardar a nivel de módulo.
  • 🎭 Regreso de la línea base visual de la página de inicio de sesión: la página de inicio de sesión regresa a la línea base visual de la rama 006 existente, al tiempo que conserva la nueva lógica de estado de autenticación y el modelo de interacción de formulario unificado.
  • 🏛️ Refuerzo de activos de gobernanza colaborativa con IA: converge y fortalece las restricciones de coherencia de AGENTS.md, CLAUDE.md, instrucciones Copilot y scripts de verificación, lo que reduce el riesgo de deriva a largo plazo de los activos de gobernanza.

Arreglar

  • ⏰ El inicio programado ejecuta inmediatamente la compatibilidad con configuraciones antiguas (Problema #726) - SCHEDULE_RUN_IMMEDIATELY volverá a leer RUN_IMMEDIATELY cuando no esté configurado, solucione el problema de compatibilidad del antiguo .env en modo programado después de la actualización; También aclare el ámbito de aplicación de los dos elementos de configuración en .env.example/README, e indique que Outlook/Exchange OAuth2 obligatorio no es compatible actualmente.
  • 🧵 La configuración de MAX_WORKERS entra en vigor y la interpretabilidad se mejora durante el tiempo de ejecución (#633) - Se solucionó el problema de que la cola de análisis asíncrono no está sincronizada según MAX_WORKERS; agrega un mecanismo de sincronización local concurrente para colas de tareas (efecto inmediato inactivo, retraso de ocupado) y genera claramente profile/max/effective en la configuración para guardar comentarios y ejecutar registros para reducir la mala comprensión de "parámetros que no tienen efecto".
  • 🔐 Cerrar sesión invalida inmediatamente la sesión existente — POST /api/v1/auth/logout ahora rotará los secretos de sesión para evitar que las cookies antiguas sigan accediendo a la interfaz protegida después de cerrar sesión; La misma pestaña del navegador y las páginas simultáneas se cerrarán simultáneamente. Cuando la autenticación está habilitada, la interfaz ya no pertenece a la lista blanca anónima y las solicitudes sin inicio de sesión devolverán 401 para evitar que las solicitudes anónimas activen la invalidación de la sesión global.
  • 🧮 Límite actual de llamadas de chip/sección Tushare y reparación de caché entre días - El trade_cal recién agregado, las clasificaciones del sector industrial y los enlaces de distribución de chips están unificados y conectados a _check_rate_limit(); el caché del calendario de transacciones se cambia para que se actualice en función de los días naturales para evitar seguir usando el día de transacción anterior para determinar la fecha de recuperación después de que el servicio se ejecute durante varios días.
  • 💼 Intercepción de posición de sobreventa y recuperación de flujo de errores (#718) - POST /api/v1/portfolio/trades ahora verificará la cantidad vendible antes de escribir y devolverá 409 portfolio_oversell por sobreventa; la página de posición ha agregado la capacidad de eliminar transacciones/flujos de capital/acciones de la empresa. Después de la eliminación, la caché de posición no válida y las instantáneas futuras se sincronizarán para facilitar la recuperación directa del flujo de errores.
  • 📧 Codificación del nombre del remitente de correo electrónico en chino (#708): las notificaciones por correo electrónico ahora realizarán automáticamente la codificación RFC 2047 para EMAIL_SENDER_NAME que contiene chino y agregarán limpieza de conexión SMTP en la ruta anormal para corregir la falla de envío causada por 'ascii' codec can't encode characters en Acciones GitHub / QQ SMTP.
  • 🐛 Deduplicación de cotizaciones de mercado en tiempo real y enrutamiento rápido del agente de acciones de Hong Kong - Unifique HK01810 / 1810.HK / 01810 y otras reglas de normalización de códigos de acciones de Hong Kong; la cotización del mercado de acciones de Hong Kong en tiempo real se modifica para seguir directamente la ruta única akshare_hk para evitar activar repetidamente la misma interfaz fallida de acuerdo con la prioridad de fuente de acciones A; el período de ejecución del agente responde a retriable=false explícito. Agregue caché de cortocircuito para fallas de la herramienta para reducir las llamadas fallidas repetidas en la misma ronda de análisis.
  • 📰 Filtrado estricto de puntualidad de noticias y ventanas estratégicas (#697) - Agregue NEWS_STRATEGY_PROFILE (ultra_short/short/medium/long) y calcule la ventana efectiva de manera uniforme con NEWS_MAX_AGE_DAYS; después de que se obtengan los resultados de la búsqueda, realice un filtrado estricto del tiempo de publicación (eliminación de tiempo desconocido, eliminación de súper ventana, solo tolera 1 día en el futuro) y agregue las mismas restricciones al enlace de respaldo histórico para evitar que las noticias antiguas ingresen nuevamente a las "últimas noticias/alerta de riesgo".

daily_stock_analysis v3.8.0

发布亮点

  • 🎨 Web 界面完成一轮骨架升级 — 新的 App Shell、侧边导航、主题能力、登录与系统设置流程已经串成统一体验，桌面端加载背景也完成对齐。
  • 📈 分析上下文继续补强 — 美股新增社交舆情情报，A 股补齐财报与分红结构化上下文，Tushare 新接入筹码分布和行业板块涨跌数据。
  • 🔒 运行稳定性与配置兼容性提升 — 退出登录会立即让旧会话失效，定时启动兼容旧配置，运行中的 MAX_WORKERS 调整和新闻时效窗口反馈更清晰。
  • 💼 持仓纠错链路更完整 — 超售会被前置拦截，错误交易/资金流水/公司行为可以直接删除回滚，便于修复脏数据。

新功能

  • 📱 美股社交舆情情报 — 新增 Reddit / X / Polymarket 社交媒体情绪数据源，为美股分析提供实时社交热度、情绪评分和提及量等补充指标；完全可选，仅在配置 SOCIAL_SENTIMENT_API_KEY 后对美股生效。
  • 📊 A 股财报与分红结构化增强（Issue #710）— fundamental_context.earnings.data 新增 financial_report 与 dividend 字段；分红统一按“仅现金分红、税前口径”计算，并补充 ttm_cash_dividend_per_share 与 ttm_dividend_yield_pct；分析/历史 API 的 details 追加 financial_report、dividend_metrics 可选字段，保持 fail-open 与向后兼容。
  • 🔍 接入 Tushare 筹码与行业板块接口 — 新增筹码分布、行业板块涨跌数据获取能力，并统一纳入配置化数据源优先级；默认按上海时间区分盘中/盘后交易日取数，优先使用 Tushare 同花顺接口，必要时降级到东财。
  • 🧱 Web UI 基础骨架升级 — 重建共享设计令牌与通用组件，新增 App Shell、Theme Provider、侧边导航，并同步调整 Electron 加载背景，为 Web / Desktop 的统一体验打底。
  • 🔐 登录与系统设置流程重做 — 重构 Login、Settings 与 Auth 管理流程，补上显式的认证 setup-state 处理，并让 Web 端与运行时认证配置 API 行为对齐。
  • 🧪 前端回归与冒烟覆盖补强 — 新增并扩展登录、首页、聊天、移动端 Shell、设置页、回测入口等关键路径的组件测试与 Playwright smoke coverage。

变更

  • 🧭 页面接入新 Shell 布局契约 — Home、Chat、Settings、Backtest 已统一接入新的页面容器、抽屉和滚动约定，降低 UI 迁移期间的页面行为不一致。
  • 💾 设置页状态同步更稳 — 优化草稿保留、直接保存同步与冲突处理，减少模块级保存后前后端配置状态不一致的问题。
  • 🎭 登录页视觉基线回归 — 登录页恢复到既有 006 分支的视觉基线，同时保留新的认证状态逻辑和统一表单交互模型。
  • 🏛️ AI 协作治理资产加固 — 收敛并加强 AGENTS.md、CLAUDE.md、Copilot 指令和校验脚本的一致性约束，降低治理资产长期漂移风险。

修复

  • ⏰ 定时启动立即执行兼容旧配置（Issue #726）— SCHEDULE_RUN_IMMEDIATELY 未设置时会回退读取 RUN_IMMEDIATELY，修复升级后旧 .env 在定时模式下的兼容性问题；同时澄清 .env.example / README 中两个配置项的适用范围，并注明 Outlook / Exchange 强制 OAuth2 暂不支持。
  • 🧵 运行期 MAX_WORKERS 配置生效与可解释性增强（#633）— 修复异步分析队列未按 MAX_WORKERS 同步的问题；新增任务队列并发 in-place 同步机制（空闲即时生效、繁忙延后），并在设置保存反馈与运行日志中明确输出 profile/max/effective，减少“参数未生效”误解。
  • 🔐 退出登录立即失效现有会话 — POST /api/v1/auth/logout 现在会轮换 session secret，避免旧 cookie 在退出后仍可继续访问受保护接口；同浏览器标签页和并发页面会被同步登出。认证开启时，该接口也不再属于匿名白名单，未登录请求会返回 401，避免匿名请求触发全局 session 失效。
  • 🧮 Tushare 板块/筹码调用限流与跨日缓存修复 — 新增的 trade_cal、行业板块排行、筹码分布链路统一接入 _check_rate_limit()；交易日历缓存改为按自然日刷新，避免服务跨天运行后继续沿用旧交易日判断取数日期。
  • 💼 持仓超售拦截与错误流水恢复（#718）— POST /api/v1/portfolio/trades 现在会在写入前校验可卖数量，超售返回 409 portfolio_oversell；持仓页新增交易 / 资金流水 / 公司行为删除能力，删除后会同步失效仓位缓存与未来快照，便于从错误流水中直接恢复。
  • 📧 邮件中文发件人名编码（#708）— 邮件通知现在会对包含中文的 EMAIL_SENDER_NAME 自动做 RFC 2047 编码，并在异常路径补充 SMTP 连接清理，修复 GitHub Actions / QQ SMTP 下 'ascii' codec can't encode characters 导致的发送失败。
  • 🐛 港股 Agent 实时行情去重与快速路由 — 统一 HK01810 / 1810.HK / 01810 等港股代码归一规则；港股实时行情改为直接走单次 akshare_hk 路径，避免按 A 股 source priority 重复触发同一失败接口；Agent 运行期对显式 retriable=false 的工具失败增加短路缓存，减少同轮分析中的重复失败调用。
  • 📰 新闻时效硬过滤与策略分窗（#697）— 新增 NEWS_STRATEGY_PROFILE（ultra_short/short/medium/long）并与 NEWS_MAX_AGE_DAYS 统一计算有效窗口；搜索结果在返回后执行发布时间硬过滤（时间未知剔除、超窗剔除、未来仅容忍 1 天），并在历史 fallback 链路追加相同约束，避免旧闻再次进入“最新动态/风险警报”。

文档

  • ☁️ 新增云服务器 Web 界面部署与访问教程（Fixes #686）— 补充从云端部署到外部访问的落地说明，降低远程自托管门槛。
  • 🌍 补齐英文文档索引与协作文档 — 新增英文文档索引、贡献指南、Bot 命令文档，并补充中英双语 issue / PR 模板，方便中英文协作与外部贡献者理解项目入口。
  • 🏷️ 本地化 README 补充 Trendshift badge — 在多语言 README 中同步补上新版能力入口标识，减少中英文说明面不一致。
