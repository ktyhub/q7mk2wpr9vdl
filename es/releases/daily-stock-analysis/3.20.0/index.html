análisis_de_stock_diario v3.20.0

Aspectos destacados de la versión

  • hazaña: Se agregó el portal de selección de acciones AlphaSift, instalación automática y capa de adaptación estable, que admite la ejecución de políticas web, visualización de reordenamiento de LLM y activación controlable del apagado predeterminado.
  • hazaña: Mejore la visibilidad del historial de acciones individuales, colas autoseleccionadas, etapas del mercado y AnalysisContextPack, y mejore las capacidades de contexto estructurado de los informes web y API.
  • hazaña: el modelo predeterminado MiniMax se actualiza a MiniMax-M3 y se completan los precios relacionados, los ajustes preestablecidos y la cobertura de prueba.
  • solución: soluciona problemas de estabilidad como verificación de estado, actualización del escritorio de Windows y codificación de primera ejecución, ETF daily secid, verificación de LLM base_url y juicio erróneo del contexto diario del agente.

Nuevas funciones

  • Se agregó la pestaña de selección de acciones de AlphaSift, que está cerrada de forma predeterminada. Después de abrirlo a través de ALPHASIFT_ENABLED, puede leer la estrategia y ejecutar la selección de acciones a través de la capa de adaptación estable.
  • La columna izquierda de la página de inicio web se cambia a la columna de acciones individuales, que muestra duplicados por acción, y la revisión del mercado está en la parte superior. Haga clic en acciones individuales para cargar el informe más reciente y admite la deduplicación normalizada y la fusión por variante de código (.SZ/.SH/.SS). Conservar todas las entradas de selección, eliminación por lotes y confirmación de eliminación; agregue eliminación de lote por código de stock API DELETE /api/v1/history/by-code/{stock_code}.
  • Se agrega una nueva entrada de operación autoseleccionada en la columna derecha de los detalles del informe, que permite verificar si el stock actual está en la cola de autoseleccionación, agregándolo o eliminándolo con un solo clic; el informe de revisión del mercado no muestra esta operación.
  • Se agrega un botón de operación autoseleccionado encima del área de entrada de la página de consulta de stock. Después de que el usuario envíe un mensaje que contenga el código de acciones, se mostrará automáticamente agregar/eliminar de la entrada autoseleccionada.
  • Se agrega una nueva entrada en el cajón para las tendencias históricas de la misma acción a la página del informe web. El resumen de la lista histórica complementa los campos del mercado de tiempo de tendencia, resumen, modelo y análisis. Admite ver el análisis histórico del stock actual y cargar más.
  • La descripción general de baja sensibilidad de AnalysisContextPack P4 accede a detalles históricos, respuestas de análisis sincrónicos, estado de tareas completadas y páginas de informes web, mostrando el estado del bloque de datos, la fuente, los motivos faltantes y el resumen de degradación.
  • #1386 P5 Agrega barreras de seguridad para decisiones intradía dashboard.phase_decision a los informes de análisis de acciones individuales y limita las conclusiones de compra y venta intradía de alta confianza basadas en la etapa del mercado y la calidad de los datos antes de guardar el historial.
  • #1386 P4a agrega parámetros analysis_phase=auto|premarket|intraday|postmarket API y transmite de forma transparente la etapa de solicitud en la tarea asincrónica aceptada, estado de la memoria, lista, SSE y canalización de análisis.
  • #1386 La página del informe web de P4b agrega una etiqueta de etapa final del mercado, el panel de tareas muestra la etapa de solicitud y reutiliza el resumen de calidad de datos de baja sensibilidad de AnalysisContextPack.
  • Actualización de la lista de modelos de canales MiniMax: MiniMax-M3 se agrega como valor predeterminado y admite contexto de entrada de 1 M de acuerdo con el documento oficial compatible con OpenAI (el proyecto está registrado de manera conservadora como rango de precios <=512K: context_window 512K, max_tokens 128K, correspondiente a $0.6/M de entrada, $2.4/M de salida, el rango de precios de entrada >512K no está modelado), se retuvo MiniMax-M2.7 y MiniMax-M2.7-highspeed y conservar la entrada de precio heredada de MiniMax-M2.5 para compatibilidad con estimaciones de costos para configuraciones de usuario existentes. Página de configuración web Los modelos y precios predeterminados de MiniMax se actualizan presionando M3.
  • Se agregó el contrato interno de AnalysisContextPack P1 y las pruebas de serialización insensibilizadas.
  • Resumen de baja sensibilidad de la etapa de mercado, acceso a detalles históricos, respuesta de análisis de sincronización e informes de metadatos del estado de la tarea completada.

Mejoras

  • Primero ejecute la verificación de configuración para complementar la clave AI faltante, STOCK_LIST vacía, campos emparejados de Telegram/Email y diagnóstico de prefijo de URL de Webhook.
  • El portal de selección de acciones de AlphaSift se ha movido a "Preguntar acciones" en la barra lateral web, más cerca del flujo de trabajo del Agente/Asistente de investigación.
  • Docker preestablece la capa de adaptación AlphaSift predeterminada durante la fase de construcción de la imagen, lo que evita la instalación adicional durante el tiempo de ejecución al igual que el paquete de lanzamiento de escritorio.
  • La selección de acciones de AlphaSift cambió para depender de la interfaz estable de alphasift.dsa_adapter. AlphaSift proporciona dinámicamente la lista de estrategias web y ya no está codificada en la interfaz.
  • La página de selección de acciones de AlphaSift agrega ID de ejecución, número de instantánea, cantidad filtrada, factores y detalles de riesgo, muestra los detalles reales al expandir los candidatos y abre temporalmente solo el mercado de acciones A actualmente admitido.
  • Se agrega una nueva tarjeta de cambio de selección de acciones AlphaSift a la página de configuración web, que puede activar o desactivar directamente la pestaña de selección de acciones.
  • Al activar la selección de acciones de AlphaSift, primero cambie a ALPHASIFT_ENABLED y verifique la disponibilidad de la capa de adaptación. Si falta, se llamará automáticamente a la interfaz de instalación controlada y ya no será necesario que el usuario haga clics adicionales para instalar.
  • Cuando AlphaSift está activado pero falta la capa de adaptación, la lista de estrategias y la interfaz de selección de acciones se serializarán y se instalarán automáticamente para bloquear la fuente y forzar la reinstalación para sobrescribir el antiguo paquete alphasift.
  • La página de selección de acciones de AlphaSift fusiona mensajes de reserva de fuentes de instantáneas duplicadas y conserva la lógica de fuente de instantáneas prioritaria de Tushare de AlphaSift.
  • La página de selección de acciones de AlphaSift muestra advertencia/error de fuente/error de análisis cuando LLM se reorganiza y degrada, y evita mostrar por error puntuaciones de factores locales como juicios de LLM.
  • La página de configuración web ya no muestra repetidamente ALPHASIFT_ENABLED como elemento de configuración de fuente de datos común. Este valor solo se utiliza como estado persistente detrás del botón "Habilitar selección de valores".
  • Cuando AlphaSift está cerrado, la entrada de navegación "Stock Picking" en el lado izquierdo de la Web queda oculta para evitar engañar a los usuarios que no la han abierto.
  • Se agregó lógica de visualización de estrategia personalizada de selección de acciones de AlphaSift para evitar mostrar por error "Multifactor equilibrado" cuando los elementos preestablecidos no coinciden.
  • Se agregó el punto final GET /api/v1/history/stocks para devolver una lista de acciones únicas agrupadas por código; Se agregaron GET /api/v1/stocks/watchlist, POST /api/v1/stocks/watchlist/add y POST /api/v1/stocks/watchlist/remove endpoints para admitir la verificación opcional de adición y eliminación de colas. STOCK_LIST lee y escribe tal cual, sin normalización automática; durante la adición/eliminación, se realiza una comparación de normalización para determinar variantes de código equivalentes.
  • Se agregó el gancho useWatchlist para administrar de manera uniforme el estado del front-end de la cola autoseleccionada y reutilizar el elemento de configuración STOCK_LIST de SystemConfigService para lograr persistencia.
  • AnalysisContextPack P5 agrega puntuación de calidad de datos, estado fetch_failed, bloque de límite de datos rápido y visualización de calidad web de baja sensibilidad.
  • #1386 P2-full Agrega restricciones cruzadas entre la etapa del mercado y los datos degradados en las restricciones de datos del indicador AnalysisContextPack y corrige la etiqueta del mercado en etapas del indicador de análisis chino.
  • La ruta de envío predeterminada de informes de notificación se restaura al canal existente para que sea compatible con la lógica de conversión y fragmentación, y la nueva capacidad de procesamiento solo se reserva como base para futuras expansiones.
  • Cuando la sección asociada carece de datos de tipo, el nombre de la sección se muestra en una sola línea para evitar generar una tabla de secciones con toda la columna N/A.
  • Optimice el nivel de información de la página de detalles del informe web, moviendo el bloque de datos de entrada y ejecutando el diagnóstico hasta la información auxiliar plegada después del contenido principal.
  • El análisis intradiario completa el tiempo de adquisición del mercado en tiempo real, el tiempo del proveedor, las etiquetas obsoletas, de reserva y parciales/estimadas para que AnalysisContextPack mapee las restricciones de datos de entrada.

Arreglar

  • La ruta de análisis del Agente reutiliza el contexto de análisis diario eliminado antes de generar la descripción general de AnalysisContextPack para evitar que se muestre daily_bars_missing después de que la línea diaria se haya capturado correctamente.
  • Registre la ruta /api/v1/health y agregue la exención de autenticación, solucione el problema de la ruta que devuelve 404 y la sonda de salud recibe 401 después de activar ADMIN_AUTH_ENABLED.
  • El entorno de primera ejecución local de Windows comprueba la compatibilidad con la salida de la consola que no es UTF-8 y cambia el comentario requirements.txt a ASCII para reducir la probabilidad de que se produzca un error en la instalación de dependencias en la página de códigos predeterminada.
  • La capa de adaptación AlphaSift DSA permite la reorganización de LLM de forma predeterminada, el backend solicita explícitamente use_llm=True y la página de selección de acciones muestra puntuaciones, juicios, cobertura e inquietudes de LLM.
  • AlphaSift reutiliza el modelo de LLM, el canal y la configuración de claves que DSA analizó al incorporar DSA, para evitar que la web haya configurado LLM pero la reorganización de LLM de selección de acciones aún esté degradada debido a la falta de clave de proveedor.
  • Cuando la selección de acciones de AlphaSift reutiliza el enrutamiento DSA LLM, filtra los modelos alternativos de proveedores de hosting no declarados y agrega modelos de canales declarados a la cadena de respaldo para evitar que el respaldo residual de Gemini cubra los canales DSA disponibles.
  • La fuente de instalación predeterminada de AlphaSift se cambia a la dirección confiable GitHub de la confirmación bloqueada; La instalación automática en modo de escritorio no requiere una sesión de administrador, la implementación sin escritorio requiere una sesión de autenticación de administrador y continúa restringiendo las fuentes de instalación.
  • Se solucionó el problema de que al abrir AlphaSift en la Web, primero lo instalaba y luego escribía la configuración, lo que provocaba que no se pudiera abrir el estado cerrado predeterminado.
  • La interfaz de estado e instalación de AlphaSift ya no devuelve texto sin formato install_spec, solo se devuelven campos de estado no confidenciales como install_spec_is_default.
  • La detección de estado de AlphaSift distingue entre dependencias opcionales faltantes y excepciones inesperadas. Los escenarios de excepción registran advertencias y devuelven información de diagnóstico no confidencial.
  • Ajustar la compatibilidad de llamadas de filtro AlphaSift: screen se basa principalmente en max_results y admite la palabra clave histórica max_output, al tiempo que permite una transmisión transparente de políticas para alinear los parámetros de políticas manuales de front-end.
  • Las solicitudes de selección de acciones de AlphaSift Web utilizan tiempos de espera prolongados independientes para evitar interrupciones prematuras por el tiempo de espera común de 30 segundos API después de habilitar el reordenamiento de LLM.
  • AlphaSift está preestablecido y la capa de adaptación se recopila durante la fase de empaquetado del escritorio para evitar que el administrador la instale automáticamente cuando se ejecuta el paquete de lanzamiento.
  • La instalación automática de AlphaSift solo se activa cuando status se diagnostica como missing_module (solo falta el módulo); la capa de adaptación se puede importar, pero las excepciones de tiempo de ejecución ya no son pip install automáticamente, sino que regresan a 424 y conservan el diagnóstico para evitar enmascarar el error real de tiempo de ejecución como una reinstalación.
  • Cerrar la redacción restante en inglés en la interfaz web china y la brecha de ayuda en la página de configuración, cambiar la página de prueba retrospectiva a visualización en chino y permitir que la página de configuración web muestre solo elementos de configuración registrados con descripciones.
  • El escritorio de Windows actualiza automáticamente el directorio de instalación actual de forma explícita durante la instalación silenciosa para evitar errores al desinstalar archivos de versiones antiguas en escenarios de directorio de instalación personalizados.
  • El instalador de Windows agrega comillas al parámetro del directorio de instalación _?= al volver a intentar el desinstalador anterior y soluciona el problema de devolver 2 cuando la versión anterior se instala en una ruta con espacios, lo que provoca que falle la actualización automática.
  • El lado del escritorio de Windows actualiza automáticamente los parámetros del directorio /D= pasados ​​a NSIS y agrega automáticamente comillas cuando contiene espacios para evitar el truncamiento del registro de ubicación de instalación.
  • Fortalecer la verificación base_url del canal LLM para evitar la omisión de SSRF causada por diferencias de análisis.
  • Se corrigió la ruta secundaria de Eastmoney de la línea diaria del ETF de efinance para evitar que el ETF de Shanghai sea consultado por la identificación de cotización de Shenzhen, lo que provocó que la línea diaria estuviera vacía.

Documentación

  • Aclarar el límite de compatibilidad entre AlphaSift y LiteLLM: solo el DSA puente ha declarado el proveedor/modelo/URL base que se inyectará durante el período de llamada, y no se realiza ninguna migración de ruta de proveedor/modelo para .env; el método alternativo es cerrar AlphaSift y restaurar la configuración original de LITELLM_*/LLM_*.
  • Aclarar que AlphaSift solo reutiliza la semántica de configuración LLM/LiteLLM existente de DSA y no migra la semántica de nuevos modelos como LITELLM_MODEL, OPENAI_MODEL, OPENAI_BASE_URL, LLM_TIMEOUT_SEC; Los avisos de falla y las rutas alternativas utilizan de manera uniforme los enlaces de configuración del sistema existentes, lo que solo afecta la capacidad de selección de acciones de AlphaSift.
  • Aclare el bloqueo automático de la fuente de instalación de AlphaSift, missing_module y los límites de comportamiento anormal en tiempo de ejecución, así como LLM/proveedor/URL base y ruta de respaldo del canal personalizado, para facilitar el seguimiento de problemas y la reversión a la configuración original de LLM.
  • Aclarar que el nuevo campo de modelo para la tendencia histórica de la misma acción es un metadato de visualización de instantánea histórica, que no afecta el enrutamiento de la URL base/modelo/proveedor de LLM en tiempo de ejecución ni la limpieza de la migración de configuración; el método de reversión consiste en revertir este cambio de acuerdo con la versión habitual.
  • Aclare el límite de compatibilidad del n.º 1311: la capa de representación solo consume el campo de visualización model_used del resultado del análisis, no cambia el enlace de envío del remitente wechat/slack/feishu/telegram y no activa la migración de compatibilidad proveedor/modelo/base_url.
  • Aclarar la base del contrato alphasift.dsa_adapter para el compromiso de bloqueo de AlphaSift y los límites de compatibilidad de la estructura actual de llamadas web/DSA API.
  • Aclarar que la página Configuración solo muestra la agrupación y combinación de campos de configuraciones de LLM, y no reescribe ni activa rutas de migración/reversión de LLM; es compatible con la semántica de guardar y revertir la configuración existente de LLM.
  • Se agregó el paquete de contexto AnalysisContextPack P0.
  • Complete la documentación y las instrucciones de configuración de Alarm Center P8 para aclarar los límites entre JSON heredado, reglas avanzadas, acciones Web/API, Docker, GitHub y escritorio.

daily_stock_analysis v3.20.0

发布亮点

  • feat: 新增 AlphaSift 选股入口、自动安装与稳定适配层，支持 Web 策略执行、LLM 重排展示和默认关闭的可控启用。
  • feat: 完善个股历史、自选队列、市场阶段与 AnalysisContextPack 可见性，增强 Web 报告和 API 的结构化上下文能力。
  • feat: MiniMax 默认模型升级到 MiniMax-M3，并补齐相关价格、预设和测试覆盖。
  • fix: 修复健康检查、Windows 桌面更新与首次运行编码、ETF 日线 secid、LLM base_url 校验和 Agent 日线上下文误判等稳定性问题。

新功能

  • 新增默认关闭的 AlphaSift 选股页签，通过 ALPHASIFT_ENABLED 开启后经由稳定适配层读取策略并执行选股。
  • Web 首页左侧栏改为个股栏，按股票去重展示，大盘复盘置顶，点击个股加载最新报告，支持按代码变体（.SZ/.SH/.SS）归一化去重合并。保留全选、批量删除和删除确认入口；新增按股票代码批量删除 API DELETE /api/v1/history/by-code/{stock_code}。
  • 报告详情右侧栏新增自选操作入口，支持查看当前股票是否在自选队列、一键加入或移除；大盘复盘报告不显示该操作。
  • 问股页面输入区上方新增自选操作按钮，用户发送包含股票代码的消息后自动显示加入自选/从自选删除入口。
  • Web 报告页新增同股历史趋势抽屉入口，历史列表摘要补充趋势、摘要、模型和分析时行情字段，支持按当前股票查看历史分析并加载更多。
  • AnalysisContextPack P4 低敏 overview 接入历史详情、同步分析响应、completed 任务状态和 Web 报告页，展示数据块状态、来源、缺失原因与降级摘要。
  • #1386 P5 为个股分析报告新增 dashboard.phase_decision 盘中决策护栏，并在保存历史前按市场阶段与数据质量限制高置信盘中买卖结论。
  • #1386 P4a 新增 analysis_phase=auto|premarket|intraday|postmarket API 参数，并在异步任务 accepted、内存 status、list、SSE 与分析 pipeline 中透传请求阶段。
  • #1386 P4b Web 报告页新增最终市场阶段标签，任务面板展示请求阶段，并复用 AnalysisContextPack 低敏数据质量摘要。
  • MiniMax 渠道模型列表升级：新增 MiniMax-M3 并作为默认，按官方 OpenAI-compatible 文档支持 1M 输入上下文（项目保守注册为 <=512K 价格档：context_window 512K、max_tokens 128K，对应 $0.6/M 输入、$2.4/M 输出，>512K 输入价格档未建模），保留 MiniMax-M2.7 与 MiniMax-M2.7-highspeed，并保留 MiniMax-M2.5 legacy 价格条目以兼容现有用户配置的成本估算。Web 设置页 MiniMax 预设模型与价格按 M3 刷新。
  • 新增 AnalysisContextPack P1 内部契约与脱敏序列化测试。
  • 市场阶段低敏摘要接入历史详情、同步分析响应和 completed 任务状态的 report metadata。

改进

  • 首次运行配置校验补充缺失 AI Key、空 STOCK_LIST、Telegram/邮件成对字段和 Webhook URL 前缀诊断。
  • AlphaSift 选股入口在 Web 侧边栏中移动到“问股”下方，贴近 Agent/研究辅助工作流。
  • Docker 镜像构建阶段预置默认 AlphaSift 适配层，与桌面发布包一样避免运行期额外安装。
  • AlphaSift 选股改为依赖 alphasift.dsa_adapter 的稳定接口，Web 策略列表由 AlphaSift 动态提供，不再在前端硬编码。
  • AlphaSift 选股页补充 Run ID、快照数、过滤后数量、因子和风险详情，展开候选时展示真实明细，并暂时仅开放当前支持的 A 股市场。
  • Web 设置页新增 AlphaSift 选股开关卡片，可直接开启或关闭选股页签。
  • 开启 AlphaSift 选股时先切换 ALPHASIFT_ENABLED 并检查适配层可用性，缺失时自动调用受控安装接口，不再要求用户额外点击安装。
  • AlphaSift 已开启但适配层缺失时，策略列表和选股接口会串行化自动安装锁定来源，并强制重装以覆盖旧版 alphasift 包。
  • AlphaSift 选股页合并重复的快照源 fallback 提示，并保留 AlphaSift 自身的 Tushare 优先快照源逻辑。
  • AlphaSift 选股页在 LLM 重排降级时展示 warning/source error/parse error，并避免把本地因子评分误显示为 LLM 判断。
  • Web 设置页不再把 ALPHASIFT_ENABLED 作为普通数据源配置项重复展示，该值仅作为“开启选股”按钮背后的持久化状态。
  • AlphaSift 关闭时隐藏 Web 左侧“选股”导航入口，避免误导未开启用户。
  • 补充 AlphaSift 选股自定义策略显示逻辑，避免未匹配预设项时误显示“均衡多因子”。
  • 新增 GET /api/v1/history/stocks 端点按 code 分组返回不重复个股列表；新增 GET /api/v1/stocks/watchlist、POST /api/v1/stocks/watchlist/add、POST /api/v1/stocks/watchlist/remove 端点支持自选队列增删查。STOCK_LIST 读写保持原样，不做自动归一化；add/remove 时归一化比较判断等价代码变体。
  • 新增 useWatchlist hook 统一管理自选队列前端状态，复用 SystemConfigService 的 STOCK_LIST 配置项实现持久化。
  • AnalysisContextPack P5 增加数据质量评分、fetch_failed 状态、Prompt 数据限制区块和 Web 低敏质量展示。
  • #1386 P2-full 在 AnalysisContextPack Prompt 数据限制中追加市场阶段与降级数据的交叉约束，并修正中文分析 Prompt 的阶段化行情标签。
  • 通知报告默认发送路径恢复既有渠道兼容转换与分片逻辑，新增 renderer 能力仅保留为未来扩展基础。
  • 关联板块缺少类型数据时改为单行展示板块名称，避免生成整列 N/A 的板块表格。
  • 优化 Web 报告详情页信息层级，将输入数据块和运行诊断下移为主体内容后的折叠辅助信息。
  • 盘中分析补齐实时行情获取时间、provider 时间、stale、fallback 与 partial/estimated 标记，供 AnalysisContextPack 映射输入数据限制。

修复

  • Agent 分析路径生成 AnalysisContextPack overview 前复用已落库日线分析上下文，避免日线已抓取成功仍显示 daily_bars_missing。
  • 注册 /api/v1/health 路由并加入认证豁免，修复该路径返回 404 以及开启 ADMIN_AUTH_ENABLED 后健康探针收到 401 的问题。
  • Windows 本地首次运行环境检查兼容非 UTF-8 控制台输出，并将 requirements.txt 注释改为 ASCII 以降低默认代码页下的依赖安装失败概率。
  • AlphaSift DSA 适配层默认开启 LLM 重排，后端显式请求 use_llm=True，选股页展示 LLM 分数、判断、覆盖率和关注项。
  • AlphaSift 嵌入 DSA 时复用 DSA 已解析的 LLM 模型、渠道和密钥配置，避免 Web 已配置 LLM 但选股 LLM 重排仍因缺少 provider key 降级。
  • AlphaSift 选股复用 DSA LLM 路由时过滤未声明的托管 provider 备选模型，并把已声明渠道模型补入回退链，避免残留 Gemini fallback 覆盖可用的 DSA 渠道。
  • AlphaSift 默认安装来源改为锁定 commit 的受信任 GitHub 地址；桌面模式自动安装不要求管理员会话，非桌面部署要求管理员认证会话，并继续限制安装来源。
  • 修复 Web 开启 AlphaSift 时先安装后写配置导致默认关闭状态无法开启的问题。
  • AlphaSift 状态与安装接口不再返回 install_spec 明文，仅返回 install_spec_is_default 等非敏感状态字段。
  • AlphaSift 状态探测区分可选依赖缺失与非预期异常，异常场景记录 warning 并返回非敏感诊断信息。
  • 调整 AlphaSift 筛选调用兼容：screen 以 max_results 为主并支持历史 max_output 关键词，同时允许策略透传以对齐前端手动策略参数。
  • AlphaSift Web 选股请求使用独立长超时，避免开启 LLM 重排后被通用 30 秒 API 超时提前中断。
  • 桌面端打包阶段预置 AlphaSift 并收集适配层，避免发布包运行时再要求管理员自动安装。
  • AlphaSift 自动安装仅在 status 诊断为 missing_module 时触发（仅模块缺失场景）；适配层可导入但运行时异常不再自动 pip install，而是返回 424 并保留诊断，避免把真实运行时故障掩盖为重装。
  • 收口 Web 中文界面残留英文文案与设置页 help 缺口，回测页改为中文展示，并让 Web 设置页仅展示已注册且带说明的配置项。
  • Windows 桌面端自动更新静默安装时显式复用当前安装目录，避免自定义安装目录场景下卸载旧版本文件失败。
  • Windows 安装器重试旧卸载器时对 _?= 安装目录参数加引号，修复旧版本安装在带空格路径时返回 2 导致自动更新失败。
  • Windows 桌面端自动更新传给 NSIS 的 /D= 目录参数在包含空格时自动加引号，避免安装位置注册表被截断。
  • 加固 LLM channel base_url 校验，避免解析差异导致 SSRF 绕过。
  • 修正 efinance ETF 日线 Eastmoney secid 路由，避免沪市 ETF 被按深市 quote id 查询导致日线为空。

文档

  • 明确 AlphaSift 与 LiteLLM 兼容边界：仅桥接 DSA 已声明 provider/model/base URL 为调用期注入，不对 .env 做 provider/model 路由迁移；回退方式为关闭 AlphaSift 并恢复原有 LITELLM_*/LLM_* 配置。
  • 明确 AlphaSift 仅复用 DSA 现有 LLM/LiteLLM 配置语义，不新增 LITELLM_MODEL、OPENAI_MODEL、OPENAI_BASE_URL、LLM_TIMEOUT_SEC 等模型语义迁移；失败提示与回退路径统一沿用既有系统配置链路，仅影响 AlphaSift 选股能力本身。
  • 明确 AlphaSift 自动安装来源锁定、missing_module 与运行时异常行为边界，以及 LLM/provider/base URL 与自定义通道回退路径，便于问题溯源与回滚到原有 LLM 配置。
  • 明确同股历史趋势新增模型字段为历史快照展示元数据，不影响运行时 LLM Provider/Model/Base URL 路由与配置迁移清理；回退方式为按常规发布回滚本变更。
  • 明确 #1311 的兼容性边界：渲染层仅消费分析结果 model_used 展示字段，未改动 wechat/slack/feishu/telegram sender 发送链路，不触发 provider/model/base_url 兼容迁移。
  • 明确 AlphaSift 锁定 commit 的 alphasift.dsa_adapter 契约依据，以及当前 DSA API/Web 调用结构的兼容边界。
  • 明确 Settings 页面对 LLM 配置仅做展示分组与字段归并，不改写或触发 LLM 迁移/回退路径；兼容现有 LLM 配置保存与回退语义。
  • 新增 AnalysisContextPack P0 上下文盘点。
  • 补齐告警中心 P8 文档与配置收口说明，明确 legacy JSON、高级规则、Web/API、Docker、GitHub Actions 与 Desktop 边界。

测试

chore

  • 预置企业微信、飞书、Telegram、钉钉、Slack 平台 renderer 元数据，暂不改变默认推送报告入口和可见版式。
