análisis_de_stock_diario v3.11.0

Aspectos destacados de la versión

  • 🎨 Web Workbench ha completado una ronda de unificación de la interfaz de usuario y actualizaciones de temas duales: las páginas de página de inicio, consulta de stock, pruebas retrospectivas, posición y configuración se han integrado aún más en tokens de diseño unificados, superficies de entrada y expresiones de estado; Se ha agregado un tema completo de colores claros y se admite el cambio de color claro/oscuro con un solo clic y el guardado persistente.
  • 🤖 Las capacidades de bot/agente se restauran en la rama principal: se restauran comandos como /history, /strategies y /research, y /ask continúa admitiendo perspectivas de combinación y comparación de múltiples hilos; Los enlaces de investigación profunda, monitoreo de eventos y sondeo programado se restablecen en la línea principal.
  • 🔒 Mejoras en la sincronización de seguridad y estabilidad de ejecución: soluciona el riesgo de omisión de límite actual de X-Forwarded-For, restaura la ruta de instalación oficial de PyPI de LiteLLM, la inicialización de Tushare ya no depende del SDK local y reduce la vulnerabilidad de Docker, el empaquetado de escritorio y la reconstrucción del entorno.
  • 🖥️ Se siguen puliendo los detalles de uso diario: se solucionaron problemas como la finalización y el envío automático de acciones de Hong Kong en la página de inicio, el parpadeo del tema de la pantalla de inicio de la página de inicio de sesión, la superposición de nombres históricos largos de acciones y la interrupción del envío completo de notificaciones cuando falla el análisis de Telegram Markdown.

Nuevas funciones

  • 🎨 El nuevo tema claro y el cambio de tema dual están en línea - Se agrega un tema claro completo al banco de trabajo web y admite el cambio con un solo clic entre los modos claro y oscuro en la barra lateral; la selección del tema persistirá y la preferencia actual se mantendrá después de actualizar la página. Esta actualización no es un ajuste de color parcial, sino un conjunto completo de rediseños de temas claros en la jerarquía de tarjetas, el contraste de los bordes, la superficie de entrada, las indicaciones de estado y el fondo de la página.
  • 🤖 Completar las capacidades de Agente/Bot que faltan en la rama principal — #648 / #649 se ha reabastecido main: restauración de bot /history, /strategies, /research, /ask conserva la perspectiva de combinación y comparación de múltiples hilos; la configuración de Deep Research y Event Monitor vuelve a ser visible y editable en la página de configuración web, programar El modo también se vuelve a conectar al sondeo de alarmas de eventos.

Mejoras

  • 🖥️ Las páginas principales están unificadas en el mismo lenguaje visual del banco de trabajo: Home / Chat / Backtest / Portfolio / Settings integra aún más tokens de diseño compartidos, sistema de entrada input-surface, expresiones de estado vacío/error y semántica de máscara de cajón para reducir la fragmentación visual y la deriva de estilo privado local entre páginas.
  • 💬 Mejora de la accesibilidad de la interacción y la retroalimentación para las consultas de acciones: la página de consultas de acciones ha mejorado la exportación de sesiones, el envío de notificaciones, la copia de mensajes, la eliminación del historial y las indicaciones contextuales de seguimiento; Las operaciones de respuesta de IA ya no dependen demasiado del desplazamiento y se puede acceder directamente a los botones clave en dispositivos de pantalla táctil y escenarios de pantalla pequeña.
  • 📊 Las superficies de las páginas de prueba y posición y las expresiones de estado continúan estandarizadas: los controles de filtro de la página de prueba, el estado booleano, las tablas de resultados y las tarjetas de resumen se unifican en primitivas de estado/entrada compartidas; Los comentarios de importación de la página de posición, las indicaciones de actualización del tipo de cambio, el estado vacío y la información de advertencia se consolidan aún más en componentes compartidos para reducir la duplicación a nivel de página.
  • 🧭 Optimización colaborativa de navegación y shell de página: el cambio de tema de la barra lateral, la marca de esquina de finalización del stock de preguntas, la máscara del cajón móvil y el contrato de desplazamiento del contenido principal están aún más unificados, y la experiencia de cambio de página de la página de inicio, el stock de preguntas y la prueba retrospectiva en terminales de escritorio y móviles es más estable.

Prueba

  • 🧪 Mejora de la gobernanza de la interfaz de usuario y la regresión de la ruta crítica: complemente las pruebas de componentes para SidebarNav, ChatPage, BacktestPage y otros componentes, y agregue protecciones de gobernanza de la interfaz de usuario para evitar continuamente que los elementos interactivos reintroduzcan atributos nativos de title o que los estilos antiguos de input-terminal vuelvan a fluir. Actualice sincrónicamente la verificación relacionada con el cajón de humo/rebajas para cubrir los enlaces principales clave después de la actualización del tema.

Arreglar

  • 🌗 El tema predeterminado predeterminado para la pantalla de inicio de la Web es oscuro — apps/dsa-web/index.html ahora leerá las preferencias del tema guardado localmente antes de montar React; si no hay ningún valor guardado, preestablecerá inmediatamente dark para <html> y sincronizará color-scheme para evitar que el tema luminoso parpadee primero en la página de inicio y en la página de inicio de sesión.
  • 🔐 Cierre de la capa de tema independiente de la página de inicio de sesión: el cuadro de entrada, la etiqueta, el botón de cambio y la copia del botón de la página de inicio de sesión ahora usan el token visual --login-* independiente y ya no heredan el color de texto del tema claro/oscuro global; Incluso si el navegador almacena en caché el tema claro, la página de inicio de sesión aún mantiene un rendimiento de entrada de contraseña visual oscuro y cian estable, evitando que los puntos de contraseña y la redacción publicitaria se vuelvan negros.
  • 🖥️ Corrección de entrada del código de acciones de Hong Kong en la página de inicio: el cuadro de entrada de análisis de la página de inicio web ahora puede aceptar correctamente códigos de acciones de Hong Kong y completar automáticamente los artículos de stock de Hong Kong seleccionados, completar el reconocimiento de formato 00700.HK / HK00700 y otros formatos, y evitar falsas alarmas de "Ingrese un código de stock válido o un nombre de stock" al realizar el envío.
  • 🔒 Corrección del valor X-Forwarded-For de limitación de corriente de autenticación (CWE-345) (#841 / #842): get_client_ip() cambió de tomar el valor más a la izquierda de X-Forwarded-For al valor más a la derecha para evitar que los atacantes eludan la protección de fuerza bruta al forjar el primer cubo de limitación de corriente giratorio; solo afecta el escenario de implementación de TRUST_X_FORWARDED_FOR=true y el proxy inverso confiable de una sola capa. El entorno de proxy multinivel debe evaluarse y configurarse de acuerdo con el documento de implementación.
  • 📦 Restaurar la instalación oficial de PyPI de LiteLLM y bloquear el límite superior de seguridad — requirements.txt Reutilizar la ruta de instalación oficial de PyPI de pip install litellm y aumentar el límite superior de seguridad de <1.82.7 manteniendo el requisito mínimo histórico de >=1.80.10, para evitar instalar accidentalmente la versión riesgosa de 1.82.7/1.82.8 que se ha eliminado; Windows El script de empaquetado del escritorio también recurre sincrónicamente al enlace estándar pip install -r requirements.txt, lo que reduce los costos de mantenimiento causados ​​por ramas de descarga especiales.
  • 📨 El análisis de Telegram Markdown falla y vuelve a texto sin formato (corrige #850) - src/notification_sender/telegram_sender.py ahora eliminará automáticamente parse_mode cuando Telegram devuelva HTTP 400 y contenga errores de análisis de can't parse entities/Markdown y luego volverá a intentar enviar texto sin formato para evitar *ST y otro contenido de texto que directamente causa que toda la notificación falle.
  • 🔢 Las cotizaciones de mercado en tiempo real de las acciones A conservan los mensajes de cambio (correcciones #852) - DataFetcherManager y TushareFetcher ahora conservarán mensajes explícitos de Shanghai-Shenzhen como SZ000001 / 000001.SZ. La versión anterior de la rama de degradación del mercado en tiempo real de Tushare ya no juzga erróneamente Shenzhen 000001 como sh000001 en el índice compuesto de Shanghai.
  • 🎯 Los puntos de compra subóptimos de múltiples agentes ya no copian ciegamente los puntos de compra ideales (correcciones #851) - Cuando el resultado de múltiples agentes carece de secondary_buy independiente, el panel ahora da prioridad a mostrar N/A en lugar de copiar el valor alternativo para que sea exactamente el mismo que ideal_buy, lo que reduce la visualización engañosa de puntos de compra dobles.
  • 🧩 La inicialización de Tushare ya no depende en gran medida del paquete local SDK — TushareFetcher ahora usa directamente el HTTP client incorporado para acceder a Tushare Pro y ya no necesita import tushare para inicializarse durante la fase de inicio; Se corrigió Docker, empaquetamiento de escritorio o reconstrucción del entorno después de Docker, empaquetamiento de escritorio o reconstrucción del entorno, informando No module named 'tushare' por adelantado debido a la falta de problemas del paquete tushare y agregando las pruebas de regresión correspondientes.
  • ⚙️ El flujo de trabajo daily_analysis completa el mapeo DEEPSEEK_API_KEY: el flujo de trabajo de análisis diario de acciones GitHub ahora transmitirá correctamente y de forma transparente DEEPSEEK_API_KEY para evitar tareas en la nube que están configuradas con claves pero que no pueden obtener las variables de entorno correspondientes en tiempo de ejecución.
  • 🖥️ Truncado y visualización de nombres de acciones que son demasiado largos en la lista del historial (correcciones #815) - Los nombres de acciones que son demasiado largos en la lista del historial ahora se truncarán automáticamente según el tipo de carácter (inglés 15/chino 8/mezcla de 10 caracteres), el resultado del truncamiento se mostrará de forma predeterminada y el nombre completo se mostrará al pasar el mouse; resuelva el problema de los nombres de acciones que se superponen al texto de la etiqueta de estado a la derecha en una resolución de 1920x1080. Se agregó la función de herramienta stockName.ts y se agregaron las pruebas correspondientes.

daily_stock_analysis v3.11.0

发布亮点

  • 🎨 Web 工作台完成一轮 UI 统一与双主题升级 — 首页、问股、回测、持仓和设置页进一步收口到统一设计 token、输入表面和状态表达；新增完整浅色主题，并支持浅色 / 深色一键切换与持久化保存。
  • 🤖 Bot / Agent 能力重新补回主分支 — 恢复 /history、/strategies、/research 等命令，/ask 继续支持多股对比与组合视角；Deep Research、事件监控与 schedule 轮询链路重新接回主线能力。
  • 🔒 安全性与运行稳态同步补强 — 修复 X-Forwarded-For 限流绕过风险，恢复 LiteLLM 官方 PyPI 安装路径，Tushare 初始化不再依赖本地 SDK，降低 Docker、桌面打包和环境重建时的脆弱点。
  • 🖥️ 日常使用细节继续打磨 — 修复首页港股自动补全提交、登录页首屏主题闪烁、历史长股票名重叠，以及 Telegram Markdown 解析失败时整条通知发送中断等问题。

新功能

  • 🎨 全新浅色主题与双主题切换上线 — Web 工作台新增完整浅色主题，并支持在侧边栏中一键切换浅色 / 深色模式；主题选择会持久化保存，刷新页面后仍保持当前偏好。此次升级不是局部配色微调，而是对卡片层级、边界对比、输入表面、状态提示和页面背景做了一整套 light theme 重绘。
  • 🤖 补回主分支缺失的 Agent / Bot 能力 — #648 / #649 已重新补回 main：Bot 恢复 /history、/strategies、/research，/ask 保留多股对比与组合视角；Deep Research 与 Event Monitor 的配置重新在 Web 设置页可见并可编辑，schedule 模式也重新接入事件告警轮询。

改进

  • 🖥️ 核心页面统一到同一套工作台视觉语言 — Home / Chat / Backtest / Portfolio / Settings 进一步收口到共享设计 token、input-surface 输入体系、空态/错误态表达和抽屉遮罩语义，减少页面之间的视觉割裂与局部私有样式漂移。
  • 💬 问股交互可达性与反馈增强 — 问股页补强了会话导出、通知发送、消息复制、历史删除与追问上下文提示；AI 回复操作不再过度依赖 hover，触屏设备和小屏场景下也能直接触达关键按钮。
  • 📊 回测与持仓页表面和状态表达继续标准化 — 回测页筛选控件、布尔状态、结果表格与汇总卡片统一到共享输入/状态原语；持仓页的导入反馈、汇率刷新提示、空态与警示信息进一步归口到共享组件，减少页面级重复实现。
  • 🧭 导航与页面壳层协同优化 — 侧边栏主题切换、问股完成角标、移动端抽屉遮罩和主内容滚动契约进一步统一，首页、问股和回测在桌面端与移动端的切页体验更稳定。

测试

  • 🧪 UI 治理与关键路径回归补强 — 补充 SidebarNav、ChatPage、BacktestPage 等组件测试，并新增 UI governance 守卫，持续防止交互元素重新引入原生 title 属性或旧 input-terminal 样式回流。同步更新 smoke / markdown drawer 相关验证，覆盖主题升级后的关键主链路。

修复

  • 🌗 Web 首屏默认主题预设为深色 — apps/dsa-web/index.html 现在会在 React 挂载前读取本地保存的主题偏好；若没有已保存值，则立即给 <html> 预设 dark 并同步 color-scheme，避免首页和登录页首屏先闪出浅色主题。
  • 🔐 登录页独立主题层收口 — 登录页输入框、标签、切换按钮和按钮文案现在使用独立的 --login-* 视觉 token，不再继承全局浅/深主题文字色；即使浏览器缓存了浅色主题，登录页仍保持稳定的深色视觉与青色密码输入表现，避免密码圆点和文案落成黑色。
  • 🖥️ 首页港股代码输入修复 — Web 首页分析输入框现在可正确接受港股代码与自动完成选中的港股项，补齐 00700.HK / HK00700 等格式识别，避免提交时误报“请输入有效的股票代码或股票名称”。
  • 🔒 认证限流 X-Forwarded-For 取值修复（CWE-345）（#841 / #842）— get_client_ip() 从取 X-Forwarded-For 最左值改为最右值，防止攻击者通过伪造首部旋转限流桶绕过暴力破解保护；仅影响 TRUST_X_FORWARDED_FOR=true 且单层可信反向代理的部署场景，多级代理环境需按部署文档评估配置。
  • 📦 恢复 LiteLLM 官方 PyPI 安装并锁定安全上限 — requirements.txt 重新使用 pip install litellm 的官方 PyPI 安装路径，并在保留历史最低要求 >=1.80.10 的同时增加 <1.82.7 的安全上限，避免误装已被移除的 1.82.7 / 1.82.8 风险版本；Windows 桌面打包脚本也同步回退到标准 pip install -r requirements.txt 链路，减少特殊下载分支带来的维护成本。
  • 📨 Telegram Markdown 解析失败回退纯文本（fixes #850）— src/notification_sender/telegram_sender.py 现在会在 Telegram 返回 HTTP 400 且包含 can't parse entities / Markdown 解析错误时，自动去掉 parse_mode 后重试纯文本发送，避免 *ST 等正文内容直接导致整条通知失败。
  • 🔢 A 股同码实时行情保留交易所提示（fixes #852）— DataFetcherManager 与 TushareFetcher 现在会保留 SZ000001 / 000001.SZ 这类显式沪深提示，旧版 Tushare 实时行情降级分支不再把深市 000001 误判成 sh000001 上证指数。
  • 🎯 多 Agent 次优买点不再盲目复制理想买点（fixes #851）— 当多智能体结果缺少独立 secondary_buy 时，仪表盘现在优先展示 N/A 而不是把 fallback 值硬拷贝成与 ideal_buy 完全相同，减少误导性的双买点展示。
  • 🧩 Tushare 初始化不再强依赖本地 SDK 包 — TushareFetcher 现在直接使用内置 HTTP client 访问 Tushare Pro，不再在启动阶段先 import tushare 才能初始化；修复了 Docker、桌面打包或环境重建后因缺少 tushare 包而提前报 No module named 'tushare' 的问题，并补充对应回归测试。
  • ⚙️ daily_analysis 工作流补齐 DEEPSEEK_API_KEY 映射 — GitHub Actions 每日分析工作流现在会正确透传 DEEPSEEK_API_KEY，避免云端任务配置了密钥却在运行时拿不到对应环境变量。
  • 🖥️ 历史列表过长股票名称截断与悬停展示（fixes #815）— 历史列表中过长的股票名称, 现在会按字符类型自动截断（英文15/中文8/混合10字符），默认显示截断结果，悬停时展示完整名称；解决 1920x1080 分辨率下股票名称与右侧状态标签文字重叠的问题。新增 stockName.ts 工具函数并补充对应测试。
