análisis_de_stock_diario v3.9.0

Aspectos destacados de la versión

  • 🤖 Los enlaces de modelos y los idiomas de los informes son más flexibles - El agente ahora puede seleccionar enlaces de modelos de forma independiente a través de AGENT_LITELLM_MODEL, y los análisis ordinarios y los informes del agente también se pueden generar en un idioma unificado a través de REPORT_LANGUAGE=zh|en, lo que reduce los problemas de combinación como "contenido en inglés + shells chinos" y permite a los equipos sopesar el costo, la velocidad y las capacidades del análisis principal y del Agente, respectivamente.
  • 🔎 La experiencia de análisis de la página de inicio ha completado una ronda de optimización de bucle cerrado - Se ha agregado el autocompletado A-share a la página de inicio, código de soporte, nombre chino, pinyin y recuperación de alias; al mismo tiempo, el estado del Panel de control está integrado en la tienda unificada, y la interacción entre el historial, los informes, las noticias y los cajones de Markdown es más estable, y las preguntas de "Preguntar a AI" también darán prioridad al contexto del informe actual.
  • 💬 Las capacidades de notificación y recuperación continúan expandiéndose - Se agregó el canal de notificación de primera clase de Slack; SearXNG puede descubrir automáticamente instancias públicas y degradarlas según un sondeo controlado cuando las instancias autoconstruidas no están configuradas; Después de que se repare el enlace de noticias urgentes de Tavily, el filtrado estricto de las noticias urgentes ya no perderá resultados válidos debido a errores.
  • 💼 El vínculo entre las posiciones y la revisión del mercado es más estable — La revisión del mercado de acciones A puede acceder opcionalmente a TickFlow para fortalecer el índice y las estadísticas de subidas y bajadas; la escritura del libro de posiciones se cambia a serialización para reducir la ventana de sobreventa concurrente; la entrada de actualización del tipo de cambio y las indicaciones de estado deshabilitado también son más claras, lo que reduce los errores de juicio del usuario.

Nuevas funciones

  • 🔎 MVP de autocompletado de stock web: el cuadro de entrada de análisis de la página de inicio agrega autocompletado basado en índice local, compatible con código de stock, nombre chino, pinyin y coincidencia de alias; después de seleccionar un candidato, se enviará el código canónico y stock_name, original_query, selection_source se transmitirán de forma transparente a la solicitud de análisis, el estado de la tarea y el evento SSE; cuando falla la carga del índice, volverá automáticamente al modo de entrada anterior, sin bloquear el proceso de envío original. La sincronización se complementa con un cargador de índices estáticos, scripts de generación de índices y pruebas de contratos de front-end y back-end. El desarrollo se lleva a cabo en fases, y la primera fase solo admite acciones A.
  • 💬 Canal de notificación de primera clase de Slack - Se agregó soporte para notificaciones nativas de Slack, compatible con los métodos de acceso Bot Token y Webhook entrante; al configurar al mismo tiempo, dé prioridad al uso del Bot API para garantizar que el texto y las imágenes se envíen al mismo canal; El modo Bot Token admite la carga de imágenes (POST de cuerpo sin formato, sin utilizar multiparte); Se agregó el elemento de configuración SLACK_BOT_TOKEN, SLACK_CHANNEL_ID, SLACK_WEBHOOK_URL, el flujo de trabajo de acciones GitHub sincroniza y completa la entrega de secretos correspondiente.
  • 🌍 El idioma de salida del informe es configurable (Problema #758) - Se agregó REPORT_LANGUAGE=zh|en, zh predeterminado; la configuración de idioma inyectará simultáneamente el análisis normal y el aviso del agente, y cubrirá las plantillas de Markdown/Jinja, la reserva de notificaciones, los metadatos del historial/API report_language y la copia fija de la página del informe web para evitar la salida mixta de "contenido en inglés + shell chino".
  • 🚀 El agente está desacoplado del modelo de análisis ordinario (Problema #692) - Se agregó AGENT_LITELLM_MODEL (deje en blanco para heredar LITELLM_MODEL, ningún prefijo está normalizado según openai/<model>); la marca is_primary/is_fallback del enlace de ejecución del Agente y /api/v1/agent/models se cambian para basarse en el enlace del modelo real del Agente; la configuración del sistema y la verificación del período de inicio se completan AGENT_LITELLM_MODEL Comprobado por unknown_model/missing_runtime_source; La página de configuración web agrega la selección del modelo principal del Agente y se sincroniza con la configuración del tiempo de ejecución del modo de canal.
  • 🔎 Descubrimiento automático de instancia pública SearXNG y sondeo controlado (#752) - Se agregó SEARXNG_PUBLIC_INSTANCES_ENABLED. Cuando SEARXNG_BASE_URLS no está configurado, extraerá la lista de instancias públicas de searx.space de forma predeterminada y seleccionará las instancias en orden de sondeo controlado; Si se encuentra un tiempo de espera, un error de conexión, un HTTP distinto de 200 o un JSON no válido dentro de la misma solicitud, cambiará automáticamente a la siguiente instancia. Los usuarios que han configurado instancias autoconstruidas mantienen sin cambios las prioridades y la semántica originales; daily_analysis GitHub El flujo de trabajo de acciones también admite la transmisión transparente explícita de este conmutador y muestra el estado actual en el registro de inicio.
  • 📈 Mejora de la revisión del mercado de TickFlow (#632) — Se agregó TICKFLOW_API_KEY opcional; después de la configuración, a TickFlow se le dará prioridad para las principales tendencias del índice en la revisión del mercado de acciones A; Si el paquete TickFlow actual admite consultas del grupo objetivo, las estadísticas de aumento y caída del mercado también darán prioridad a TickFlow. En caso de falla o permisos insuficientes, recurrirá inmediatamente al enlace AkShare / Tushare / efinance existente; el orden de reserva de la lista de precios del sector permanece sin cambios. La capa de acceso también está adaptada al contrato SDK real: la consulta de índice principal extrae lotes de acuerdo con el límite superior de una sola solicitud y convierte uniformemente el change_pct / amplitude proporcional devuelto por TickFlow en el calibre porcentual interno del proyecto.

Mejoras

  • Parte de estado del panel y cierre del espacio de trabajo: se movió el estado de Inicio/Panel a stockPoolStore, selección de historial consolidado, carga de informes, sincronización de tareas, actualización de sondeos y manejo del cajón de rebajas en un solo segmento de estado.
  • Estandarización del panel del tablero: mantuvo estable el contrato de diseño del tablero actual mientras unificaba el historial, el informe, las noticias y la presentación de rebajas con tokens compartidos, estados estandarizados y desplazamiento limitado en el panel para la lista del historial.
  • Puente de seguimiento del panel al chat: enruta los seguimientos de "Preguntar a la IA" a través de la hidratación del contexto del informe en lugar del acoplamiento directo del estado entre páginas, mientras se mantienen los envíos de chat utilizables cuando el contexto del historial enriquecido aún se está cargando.
  • 💼 Serialización de escritura simultánea del libro mayor de posiciones (#742) - La escritura/eliminación de eventos de origen de posición ahora obtendrá primero el bloqueo de escritura serializado en SQLite, lo que reduce la ventana para la venta simultánea de transacciones con overbooking que se escribirán en el libro mayor; la interfaz de escritura de posición directa devuelve 409 portfolio_busy durante la competencia de bloqueo, y la importación CSV mantiene el envío uno por uno y cuenta ocupado como failed_count.
  • 💱 Rellene la entrada de actualización manual para el tipo de cambio de la página de posición (#748) - La página web /portfolio ahora mostrará el botón "Actualizar tipo de cambio" en la tarjeta "Estado del tipo de cambio", llamando directamente a la interfaz POST /api/v1/portfolio/fx/refresh existente; después de la actualización, solo se recargarán la instantánea y los datos de riesgo, y el resultado de "Actualizado/Aún obsoleto/Falló la actualización" se retroalimentará con un resumen en línea, lo que reduce las preocupaciones de los usuarios sobre fxStale Concepto erróneo de estadía prolongada.

Arreglar

  • 🔎 Completado automático web Ingrese la corrección semántica de confirmación: el autocompletado de stock ya no resalta el primer elemento de forma predeterminada cuando se buscan candidatos seleccionados; cuando la lista de candidatos se expande pero el usuario no la ha seleccionado explícitamente con las teclas de flecha o el mouse, presionar Enter continuará enviando la entrada original, evitando que el primer candidato sobrescriba silenciosamente la entrada manual.
  • 🌍 Completar el límite de localización entre el análisis de inicio de REPORT_LANGUAGE y la visualización del historial - Config continuará siguiendo la semántica existente de "variables de entorno real primero, .env toma la parte inferior" al iniciarse y generará advertencias explícitas cuando las dos entren en conflicto, lo que reduce los errores de juicio causados ​​por fuentes poco claras de REPORT_LANGUAGE; al mismo tiempo, la respuesta de detalles en inglés de /api/v1/history/{id} se sincronizará con sentiment_label localizado, Markdown histórico. También identificará correctamente el emoji de nivel de riesgo del bias_status en inglés para evitar visualizaciones mixtas o falsas positivas de chino e inglés, como 乐观 o 🚨Safe.
  • 📰 Reparación de mapeo de tiempo de publicación de recuperación de noticias urgentes de Tavily (#782) - Tavily ahora usará explícitamente topic="news" en noticias de stock y dimensiones de inteligencia estrictamente urgentes, y es compatible con dos campos de tiempo de publicación published_date / publishedDate; Se corrigió que Tavily devolviera resultados claramente, pero todos se registraron como drop_unknown en la etapa de filtrado estricto posterior. Se descartaron preguntas, al tiempo que se restauraron dimensiones analíticas como el análisis institucional, las expectativas de desempeño y el análisis de la industria a la búsqueda de fuentes amplias, y ya no se comprimen uniformemente en el modo de noticias.
  • 💱 Corrección semántica para deshabilitar la actualización del tipo de cambio en la página de posición (#772) - Cuando PORTFOLIO_FX_UPDATE_ENABLED=false, POST /api/v1/portfolio/fx/refresh ahora devolverán refresh_enabled=false y disabled_reason explícitos, y la página web /portfolio indicará claramente "La actualización en línea del tipo de cambio ha sido deshabilitada" y ya no informará falsamente "No hay ningún par de tipos de cambio que pueda actualizarse en el rango actual".
  • 🤖 Tiempo de espera del agente y refuerzo de configuración: AGENT_ORCHESTRATOR_TIMEOUT_S ahora también protege el bucle ReAct de agente único heredado, los lotes de herramientas paralelas dejan de esperar una vez que se agota el presupuesto restante y los valores numéricos no válidos de .env vuelven a valores predeterminados seguros con advertencias en lugar de bloquear el inicio.
  • 🌐 Compatibilidad con comodines CORS + credenciales: CORS_ALLOW_ALL=true ya no combina allow_origins=["*"] con solicitudes de credenciales, lo que evita fallas de origen cruzado en el lado del navegador en configuraciones de demostración/desarrollo.
  • 🧭 Configuraciones del agente no disponibles ocultas en la interfaz de usuario web: los controles de Investigación profunda/Monitor de eventos ahora se tratan como metadatos solo de compatibilidad en la rama actual y se eliminan de la página Configuración para evitar exponer opciones no funcionales.

daily_stock_analysis v3.9.0

发布亮点

  • 🤖 模型链路与报告语言更灵活 — Agent 现在可以通过 AGENT_LITELLM_MODEL 独立选择模型链路，普通分析与 Agent 报告也可通过 REPORT_LANGUAGE=zh|en 输出统一语言，减少“英文内容 + 中文壳子”这类混排问题，并允许团队分别权衡主分析与 Agent 的成本、速度和能力。
  • 🔎 首页分析体验完成一轮闭环优化 — 首页新增 A 股自动补全，支持代码、中文名、拼音和别名检索；同时 Dashboard 状态收口到统一 store，历史、报告、新闻与 Markdown 抽屉的交互更稳定，“Ask AI” 追问也会优先携带当前报告上下文。
  • 💬 通知与检索能力继续外扩 — 新增 Slack 一等通知渠道；SearXNG 在未配置自建实例时可以自动发现公共实例并按受控轮询降级；Tavily 时效新闻链路修复后，严格时效过滤不再错误丢光有效结果。
  • 💼 持仓与市场复盘链路更稳 — A 股 market review 可选接入 TickFlow 强化指数与涨跌统计；持仓账本写入改为串行化以缩小并发超卖窗口；汇率刷新入口和禁用态提示也更加清晰，减少用户误判。

新功能

  • 🔎 Web 股票自动补全 MVP — 首页分析输入框新增本地索引驱动的自动补全，支持股票代码、中文名、拼音和别名匹配；选中候选后会提交 canonical code，并透传 stock_name、original_query、selection_source 到分析请求、任务状态和 SSE 事件；索引加载失败时自动退回旧输入模式，不阻断原有提交流程。同步补充了静态索引加载器、索引生成脚本和前后端契约测试。分阶段进行开发，第一阶段仅支持 A 股。
  • 💬 Slack 一等通知渠道 — 新增 Slack 原生通知支持，同时支持 Bot Token 和 Incoming Webhook 两种接入方式；同时配置时优先使用 Bot API，确保文本与图片发送到同一频道；Bot Token 模式支持图片上传（raw body POST，不使用 multipart）；新增 SLACK_BOT_TOKEN、SLACK_CHANNEL_ID、SLACK_WEBHOOK_URL 配置项，GitHub Actions 工作流同步补齐对应 Secrets 传递。
  • 🌍 报告输出语言可配置（Issue #758）— 新增 REPORT_LANGUAGE=zh|en，默认 zh；语言设置会同步注入普通分析与 Agent Prompt，并覆盖 Markdown/Jinja 模板、通知 fallback、历史/API report_language 元数据及 Web 报告页固定文案，避免“英文内容 + 中文壳子”的混合输出。
  • 🚀 Agent 与普通分析模型解耦（Issue #692）— 新增 AGENT_LITELLM_MODEL（留空继承 LITELLM_MODEL，无前缀按 openai/<model> 归一）；Agent 执行链路与 /api/v1/agent/models 的 is_primary/is_fallback 标记改为基于 Agent 实际模型链路；系统配置与启动期校验补齐 AGENT_LITELLM_MODEL 的 unknown_model/missing_runtime_source 检查；Web 设置页新增 Agent 主模型选择并与渠道模式运行时配置同步。
  • 🔎 SearXNG 公共实例自动发现与受控轮询（#752）— 新增 SEARXNG_PUBLIC_INSTANCES_ENABLED，在未配置 SEARXNG_BASE_URLS 时默认从 searx.space 拉取公共实例列表，并按受控轮询顺序选择实例；同次请求内遇到超时、连接错误、HTTP 非 200 或无效 JSON 会自动切换到下一个实例。已配置自建实例的用户保持原有优先级与语义不变；daily_analysis GitHub Actions 工作流也已支持显式透传该开关并在启动日志中展示当前状态。
  • 📈 TickFlow market review enhancement (#632) — 新增可选 TICKFLOW_API_KEY；配置后，A 股大盘复盘的主要指数行情优先尝试 TickFlow；若当前 TickFlow 套餐支持标的池查询，市场涨跌统计也会优先尝试 TickFlow。失败或权限不足时立即回退到现有 AkShare / Tushare / efinance 链路；板块涨跌榜回退顺序保持不变。接入层同时适配了真实 SDK 契约：主指数查询按单次请求上限分批拉取，并将 TickFlow 返回的比例型 change_pct / amplitude 统一转换为项目内部的百分比口径。

改进

  • Dashboard state slice and workspace closure — moved Home / Dashboard state into stockPoolStore, consolidated history selection, report loading, task syncing, polling refresh, and markdown drawer handling under a single state slice.
  • Dashboard panel standardization — kept the current dashboard layout contract stable while unifying history, report, news, and markdown presentation with shared tokens, standardized states, and bounded in-panel scrolling for the history list.
  • Dashboard-to-chat follow-up bridge — routed “Ask AI” follow-ups through report-context hydration instead of direct cross-page state coupling, while keeping chat sends usable when enriched history context is still loading.
  • 💼 持仓账本并发写入串行化（#742）— 持仓源事件写入/删除现在会在 SQLite 下先获取串行化写锁，减少并发卖出把超售流水写入账本的窗口；直接持仓写接口在锁竞争时返回 409 portfolio_busy，CSV 导入保持逐条提交并把 busy 计入 failed_count。
  • 💱 持仓页汇率手动刷新入口补齐（#748）— Web /portfolio 页面现在会在“汇率状态”卡片中展示“刷新汇率”按钮，直接调用现有 POST /api/v1/portfolio/fx/refresh 接口；刷新后会仅重载快照与风险数据，并以内联摘要反馈“已更新 / 仍 stale / 刷新失败”的结果，减少用户对 fxStale 长时间停留的误解。

修复

  • 🔎 Web 自动补全 Enter 提交语义修正 — 股票自动补全在搜索命中候选时不再默认高亮第一项；候选列表展开但用户尚未用方向键或鼠标明确选中时，按 Enter 会继续提交原始输入，避免手动输入被第一条候选静默覆盖。
  • 🌍 补齐 REPORT_LANGUAGE 启动解析与历史展示本地化边界 — Config 在启动时继续遵循“真实环境变量优先、.env 兜底”的既有语义，并在两者冲突时输出显式告警，减少 REPORT_LANGUAGE 来源不清带来的误判；同时 /api/v1/history/{id} 英文详情响应会同步本地化 sentiment_label，历史 Markdown 也会正确识别英文 bias_status 的风险等级 emoji，避免出现 乐观 或 🚨Safe 这类中英混排/误报展示。
  • 📰 Tavily 时效新闻检索发布时间映射修复（#782）— Tavily 在股票新闻和严格时效的情报维度中现在会显式使用 topic="news"，并兼容 published_date / publishedDate 两种发布时间字段；修复了 Tavily 明明返回结果却在后续硬过滤阶段被全部记为 drop_unknown 丢弃的问题，同时将机构分析、业绩预期、行业分析等分析型维度恢复为宽源搜索，不再被统一压缩成新闻模式。
  • 💱 持仓页汇率刷新禁用语义修正（#772）— 当 PORTFOLIO_FX_UPDATE_ENABLED=false 时，POST /api/v1/portfolio/fx/refresh 现在会返回显式 refresh_enabled=false 与 disabled_reason，Web /portfolio 页面会明确提示“汇率在线刷新已被禁用”，不再误报“当前范围无可刷新的汇率对”。
  • 🤖 Agent timeout and config hardening — AGENT_ORCHESTRATOR_TIMEOUT_S now also protects the legacy single-agent ReAct loop, parallel tool batches stop waiting once the remaining budget is exhausted, and invalid numeric .env values fall back to safe defaults with warnings instead of crashing startup.
  • 🌐 CORS wildcard + credentials compatibility — CORS_ALLOW_ALL=true no longer combines allow_origins=["*"] with credentialed requests, avoiding browser-side cross-origin failures in demo/development setups.
  • 🧭 Unavailable Agent settings hidden from Web UI — Deep Research / Event Monitor controls are now treated as compatibility-only metadata in the current branch and are removed from the Settings page to avoid exposing non-functional toggles.
