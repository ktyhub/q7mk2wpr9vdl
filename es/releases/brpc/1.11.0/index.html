brpc 1.11.0

Highlights

  • Bazel/bzlmod adoption — brpc 1.11.0 ships bzlmod support (#2670), so Bazel users can consume it as a proper module instead of legacy WORKSPACE wiring; note that the Boost dependency is now sourced from the Bazel Central Registry (#2789), which can change your dependency resolution and may require a lockfile refresh when migrating existing WORKSPACE builds.

  • Concurrency debugging and bthread sync primitives — pthread mutex deadlock detection (#2692, #2727) plus timedlock support for fast/hook pthread mutexes and bthread::Mutex (#2760) make deadlock and lock-contention diagnosis far more practical; the new bthread semaphore and rwlock (#2752, #2773) fill gaps in the synchronization toolkit, so code that previously rolled its own can now use native primitives.

  • Protobuf memory control for hot paths — the new RPC protobuf message factory interface (#2718) and arena-backed factory (#2751) let you route message allocation through arenas, which matters most for high-QPS services where per-request protobuf allocation dominates; adopting the arena factory is the single biggest lever here, but it changes message lifetime semantics, so audit any code that retains messages past the RPC callback.

  • Tail-latency and throughput controls — backup (hedged) request policy (#2734) targets tail latency by issuing duplicate requests to slow backends, while batch create/accept stream (#2754) raises streaming throughput; server operators also get a method option to disable the eovercrowded check (#2774), and a tag-scoped restriction on batched butex wakeups (#2778) — together these are the knobs to reach for when tuning latency-sensitive deployments.

  • Behavioral and forward-compatibility changes — failed authentication now returns an explicit unauthorized response to the client (#2744) rather than silently dropping the connection, which clients should be ready to handle; std::aligned_storage was replaced with ManualConstructor(AlignedMemory) (#2719) to clear C++23 deprecation warnings, easing future compiler upgrades.

  • Correctness fixes worth upgrading for — a malloc deadlock caused by the contention profiler (#2684), a memleak in butil::ObjectPoolAllocator (#2725), an MPSC queue race fixed by switching to atomic exchange (#2739), and RDMA compile errors (#2707, #2720, #2741) are all resolved; if you run RDMA or contention profiling in production, these alone justify the bump.

No breaking API changes are reported in this release.
