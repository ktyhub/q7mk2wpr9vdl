OpenHands v1.19.0

Highlights

  • MCP least privilege for agent profiles — Profiles can now allowlist user-configured MCP servers through tri-state mcp_server_refs (null = all, list = selected, [] = none), keeping write-capable servers away from read-only agents (#17289). The editor preserves existing scopes and flags dangling references; however, Cloud can still fall back to unscoped settings when a reference disappears, and platform-managed MCP servers remain outside this filter.

  • Codex ACP registry consistency — GPT-6 Astra support (#17164) is now backed by synchronized UI and agent-server registry pins rather than a local shim, with CI enforcing alignment (#17423). Unsupported gpt-5.4 and gpt-5.4-mini IDs disappear, and matching launch commands are no longer overridden by Canvas—review custom ACP command pins before upgrading.

  • Static-server hardening — Injected runtime configuration is HTML-escaped to prevent script-tag breakout/XSS, and responses carrying sessionApiKey now use Cache-Control: no-store (#17175). Self-hosters should prioritize this update and expect credential-bearing pages to stop being cached.

  • Automation catalog and diagnostics — Catalog bundles now accept plugins/ sources while retaining path-traversal checks, so plugin-backed reviewer templates reach direct setup instead of an empty assisted conversation (#17403). The UI also exposes disabled_reason, disabled_detail, and disabled_at (#17425), making automatic pauses actionable without a backend migration.

  • Repository and request reliability — Azure DevOps SSH remotes now normalize to the correct web host and path, restoring repository labels, branch links, and Pull/Push/PR actions (#17375). Automation SDK-version lookups no longer refetch on window focus or reconnect, reducing background traffic while keeping lookup failures non-fatal (#16991).

  • Breaking automation API behavior — openhands-automation 1.12.1 changes unauthenticated GET /api/automation/v1 from 200 to 401; readiness probes and scripts must authenticate or treat 401 as service-ready (#17479). The coordinated SDK, agent-server, and TypeScript-client bump to 1.48.0 also enables session progress frames (item_started, delta, item_aborted) for streaming clients.
