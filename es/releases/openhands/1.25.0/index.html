OpenHands v1.25.0

Highlights

  • Model Router moves from opt-in to auto-configured — Direct-prompt router settings (#16147), a "Run at conversation start" toggle (#17797), and auto-enabling "Run on first message" when the first router is created (#17840) mean routing can now take effect before you type anything. The first router also preselects a classifier model so it gets created when no profiles exist (#17835), and defaults were renamed to OpenHands Router Pro / Flash (#17782) with the Flash prompt repaired and its model table injected (#17860). Watch for references to the old default names in scripts or docs, and note that gpt-5.2-codex was dropped from the Agent Canvas router prompts (#17811) and router templates now keep the "Don't create profiles" option (#18020).
  • LLM profiles become bulk-managed, with onboarding that stops clobbering settings — You can add a provider's whole model catalog as profiles in one shot (#16426), now also per connection (#17723), instead of configuring models one at a time. Onboarding preserves canonical LLM settings (#17211) and the auto-filled profile name tracks the selected model (#18017). If you relied on onboarding resetting LLM config, re-check that flow; for teams with multiple providers this is the biggest day-to-day setup win in the release.
  • Agent profiles gain a first-class persona and a pinned SDK — Profiles can carry their own persona or extra instructions (#17843) and now select any tool from the server's catalog, with Agent SDK pinned to 1.53.0 (#17516). Named profiles finally receive runtime services (#17279), and task_tracker is saved alongside delegation tools as a workaround for SDK#5519 (#18001). The unreachable non-embedded agent-settings mode is gone (#17825), and a new cross-repository version compatibility doc (#16884) is worth reading before upgrading — the SDK pin and the temporary workaround are the two things most likely to shift behavior, and the workaround should be revisited on the next SDK bump.
  • Canvas streaming internals are rewritten and Apps get an update path — Streaming slots are keyed by event id and the text-matching reconciler is deleted (#17465), so extensions that relied on text heuristics for stream updates should be retested. Installed Canvas Apps gain an in-place Update action (#17736) and render their manifest-declared SVG icon (#17877), while runtime clients and workspace capabilities are now scoped correctly (#17387) and hidden Canvas settings pages are blocked when locked to a Cloud host (#17866). The rapid Extensions bumps (0.26.0 → 0.27.0 → 0.29.0, #17850/#17870/#17998) signal active API churn — pin and test extension versions deliberately.
  • Automations mature beyond self-hosted — Templates now appear on cloud backends with native git integrations offered (#17830), and the built-in integration is presented ahead of issue-to-PR templates (#17868), so workflows that assumed issue-to-PR was the default should be re-verified. The dashboard filters by creator (#17814), list pagination uses offsets so "Load more" works past 100 items (#17839), preset actions hide irrelevant agent profiles (#17971), and the delete confirmation is now a modal that closes on Escape (#18011). Automation ships at 1.19.0 (#17998).
  • Session isolation and rate-limit hygiene harden production use — Local session keys are kept off externally reachable listeners (#17007) and website PostHog handoff is consent-aware (#16976), which matters if you expose OpenHands beyond localhost. Refetch-on-focus bursts that tripped Cloud rate limits are backed off and stopped (#17984), WebSockets now reconnect on foreground and disconnect cleanly on mobile background (#17982), and the last Node 22 runtime pins were replaced (#17997) — re-check your Node/runtime assumptions and expect fewer dropped mobile sessions.

No breaking changes in this release.
