Vibe-Trading v0.1.10

🌍 v0.1.10 — Capa de datos globales + resumen desde 0.1.9

v0.1.10 es una versión acumulada. El titular es la capa de datos globales: el registro de datos de mercado crece de 10 a 18 fuentes y gana 18 herramientas de datos de solo lectura que van más allá de OHLCV hacia los fundamentos y el flujo, todo expuesto a través de MCP. A su alrededor se envía todo lo acumulado desde 0.1.9: 10 conectores SDK de intermediario, la pila completa Alpha Zoo alpha compare, una revisión de la confiabilidad del proveedor, fase 1 del piloto automático de investigación, un caché de datos local opcional y una ola de refuerzo de seguridad impulsada por la comunidad. Esta versión está disponible en las versiones PyPI, ClawHub y GitHub.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Destacados

🌍 Capa de datos global: 18 fuentes + 18 herramientas de datos de solo lectura

El registro de cargadores crece de 10 a 18 fuentes de datos de mercado:

  • Gratis, sin clave: tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, además de cuatro nuevas incorporaciones directas de API: Eastmoney, Sina, Stooq y un HTTP directo Yahoo. client.
  • Proveedores estadounidenses con llave opcional: Finnhub, Alpha Vantage, Tiingo, FMP; Las claves ausentes se omiten en la cadena de respaldo, nunca la bloquee. Las cadenas de respaldo se reordenan por riesgo de prohibición de IP (puntos finales públicos livianos y tolerantes a la aceleración; rutas REST controladas por clave) detrás de una puerta HTTP acelerada compartida (backtest/loaders/_http.py) con grupos de tasas por host, fluctuación y reutilización de sesiones. En la parte superior se encuentran 18 herramientas de datos de solo lectura: flujo de fondos, tablero dragón-tigre, flujo en dirección norte (Stock-Connect), operaciones de margen, operaciones en bloque, recuento de accionistas, vencimiento de bloqueo, membresía del sector, informes de investigación, noticias, presentaciones ante la SEC (EDGAR + XBRL), estados financieros, cadenas de opciones, participaciones institucionales, análisis de mercado completo, búsqueda de símbolos, macro FRED y búsqueda de acciones A en lenguaje natural iwencai, en A-share / US / HK, todos expuestos sobre MCP. Tres clients compartidos (eastmoney / yahoo / sec_edgar) respaldan los cargadores y las herramientas, y un índice data-routing consolidado más habilidades eastmoney / sec-edgar por fuente documentan la capa.

💱 10 conectores SDK de corredor: lectura + papel, en vivo controlado por mandato

El comercio es primero el conector: elija un perfil y el papel/en vivo es un atributo del conector. Este lanzamiento eleva la lista a 10 corredores: IBKR (TWS/Gateway local de solo lectura) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (India NSE/BSE + F&O). Los conectores Direct-SDK comparten un transporte broker_sdk y cada uno lee + realiza pedidos de cuentas en papel; La colocación en vivo pasa por una única puerta de autonomía limitada cerrada ante fallas (sdk_order_gate.py: mandato + interruptor de apagado + auditoría). Los corredores con sin discriminador en tiempo de ejecución en papel/en vivo (Longbridge, Dhan, Shoonya) están estructuralmente limitados a papel + solo lectura: sus place_order / cancel_order rechazan cualquier configuración que no sea en papel en la primera línea. Las herramientas para realizar pedidos permanecen fuera de MCP (solo agente + CLI).

📊 Comparación alfa entre CLI / REST / Web / herramienta de agente

vibe-trading alpha compare clasifica cualquier conjunto de factores de Alpha Zoo por IC/IR en su universo, compartiendo un núcleo compare_runner.compare_alphas detrás de CLI, una ruta REST POST /alpha/compare con progreso transmitido por SSE, la vista de comparación de la interfaz de usuario web de Alpha Zoo y una herramienta de agente alpha_compare de solo lectura. Un filtro de subconjunto run_bench(only=…) agrupa solo los factores comparados en lugar de todo el zoológico.

🔌 Revisión de la confiabilidad del proveedor

Una capa de capacidad de proveedor controla la captura/reproducción de razonamiento, las firmas de pensamiento de Gemini, el agente de usuario Kimi y los cuerpos de razonamiento de OpenRouter por proveedor. vibe-trading provider doctor imprime una instantánea de diagnóstico redactada. Las fallas de transmisión ahora generan un ProviderStreamError explícito y redactado (que lleva status_code + .retryable) con un reintento para transitorios y falla rápida en 4xx; un reasoning_delta SSE acelerado impulsa un indicador de vida "Razonamiento..." en la interfaz de usuario web. Además: un adaptador DeepSeek nativo opcional (VIBE_TRADING_DEEPSEEK_ADAPTER), tiempos de espera de herramienta de solo lectura (VIBE_TRADING_TOOL_TIMEOUT_SECONDS) y manejo de temperatura por proveedor (Kimi-k2 forzado a 1.0, MiniMax fijado > 0).

🔬 Piloto automático de investigación Fase 1

run_research_autopilot convierte un hypothesis_id en un objetivo de investigación (tesis como objetivo, criterios de aceptación relevantes para el backtest, sugerencias para el siguiente paso), y generate_backtest_config escribe automáticamente un backtest config.json a partir del universo de la hipótesis y las fuentes de datos, de modo que el agente pasa directamente de la idea → signal_engine.py → ejecuta.

🗃️ Optar por caché de datos local + cargador local

VIBE_TRADING_DATA_CACHE=1 almacena en caché las barras liquidadas en ~/.vibe-trading/cache (inicio del usuario, nunca el repositorio); un guardia de obsolescencia nunca almacena en caché un rango que finaliza hoy, y las tramas almacenadas en caché son en bytes idénticos a las recuperaciones en vivo. Un nuevo cargador local lee OHLCV directamente desde sus propios archivos CSV/Parquet/DuckDB a través de ~/.vibe-trading/data-bridge/config.yaml, con soporte normal de cadena de respaldo.

🛡️ Ola de seguridad y endurecimiento

Un paso de refuerzo impulsado por la comunidad: configuración de API: autenticación de escritura (n.° 245), opción de herramienta de shell del agente (n.° 243), rechazo de vinculación del host de loopback (n.° 242), autenticación de apagado local explícita (n.° 241) y contención de identificadores para ID de propuesta de mandato (n.° 256), tipos de memoria persistente (n.° 257) y ID de ejecución de enjambre de MCP (n.° 258). Además, detiene la respuesta a mitad de camino + reconexión SSE al regresar a una sesión en ejecución (n.° 229), respaldo de web_search multimotor (n.° 231) y ida y vuelta de Gemini thoughtSignature a través de llamadas a herramientas compatibles con OpenAI (n.° 176, n.° 184).

🪪 Los informes de versiones ahora son consistentes

--version, REST API (/docs + /api), el protocolo de enlace del servidor MCP y el pie de página de la interfaz de usuario web se derivan de una fuente: el REST API se había desviado a un 5.0.0 codificado incorrecto. Packaging ahora también incluye scripts de ejemplo de habilidades en la rueda, y la imagen Docker instala las bibliotecas nativas de weasyprint para que se generen informes en PDF.

Vibe-Trading v0.1.10

🌍 v0.1.10 — Global data layer + roll-up since 0.1.9

v0.1.10 is a roll-up release. The headline is the Global data layer: the market-data registry grows from 10 to 18 sources and gains 18 read-only data tools that reach past OHLCV into fundamentals and flow, all exposed over MCP. Around it ships everything accumulated since 0.1.9 — 10 broker SDK connectors, the Alpha Zoo alpha compare full stack, a provider-reliability overhaul, Research Autopilot Phase 1, an opt-in local data cache, and a community-driven security-hardening wave.

This release is available on PyPI, ClawHub, and GitHub Releases.

pip install -U vibe-trading-ai
# or
uv tool install --reinstall vibe-trading-ai

Highlights

🌍 Global data layer — 18 sources + 18 read-only data tools

The loader registry grows from 10 to 18 market-data sources:

  • Free, no key — tushare, okx, yfinance, akshare, baostock, tencent, mootdx, ccxt, futu, local, plus four new direct-API additions: Eastmoney, Sina, Stooq, and a direct-HTTP Yahoo client.
  • Optional key-gated US providers — Finnhub, Alpha Vantage, Tiingo, FMP; absent keys are skipped in the fallback chain, never crash it.

Fallback chains are re-ordered by IP-ban risk (lightweight, throttle-tolerant public endpoints lead; key-gated REST trails) behind a shared throttled HTTP gate (backtest/loaders/_http.py) with per-host rate buckets, jitter, and session reuse. On top sit 18 read-only data tools — fund flow, dragon-tiger board, northbound (Stock-Connect) flow, margin trading, block trades, shareholder count, lockup expiry, sector membership, research reports, news, SEC filings (EDGAR + XBRL), financial statements, options chains, institutional holdings, full-market screening, symbol search, FRED macro, and iwencai natural-language A-share search — across A-share / US / HK, all exposed over MCP. Three shared clients (eastmoney / yahoo / sec_edgar) back the loaders and tools, and a consolidated data-routing index plus per-source eastmoney / sec-edgar skills document the layer.

💱 10 broker SDK connectors — read + paper, mandate-gated live

Trading is connector-first: pick a profile, and paper/live is an attribute of the connector. This release brings the roster to 10 brokers — IBKR (local read-only TWS/Gateway) · Robinhood (Agentic MCP, OAuth) · Tiger · Longbridge · Alpaca · OKX · Binance · Futu · Dhan · Shoonya (India NSE/BSE + F&O). Direct-SDK connectors share a broker_sdk transport and each does read + paper-account order placement; live placement passes a single fail-closed bounded-autonomy gate (sdk_order_gate.py: mandate + kill switch + audit). Brokers with no runtime paper/live discriminator (Longbridge, Dhan, Shoonya) are structurally capped at paper + read-only — their place_order / cancel_order hard-refuse any non-paper config at the first line. Order-placing tools stay off MCP (agent + CLI only).

📊 Alpha compare across CLI / REST / Web / agent tool

vibe-trading alpha compare ranks any set of Alpha Zoo factors by IC / IR on your universe, sharing one compare_runner.compare_alphas core behind the CLI, a POST /alpha/compare REST route with SSE-streamed progress, the Alpha Zoo Web UI Compare view, and a read-only alpha_compare agent tool. A run_bench(only=…) subset filter benches only the compared factors instead of the whole zoo.

🔌 Provider-reliability overhaul

A provider capability layer gates reasoning capture/replay, Gemini thought signatures, Kimi user-agent, and OpenRouter reasoning bodies per provider. vibe-trading provider doctor prints a redacted diagnostic snapshot. Streaming failures now raise an explicit, redacted ProviderStreamError (carrying status_code + .retryable) with one retry for transients and fail-fast on 4xx; a throttled reasoning_delta SSE drives a "Reasoning…" liveness indicator in the Web UI. Also: an optional native DeepSeek adapter (VIBE_TRADING_DEEPSEEK_ADAPTER), read-only tool hard-timeouts (VIBE_TRADING_TOOL_TIMEOUT_SECONDS), and per-provider temperature handling (Kimi-k2 forced to 1.0, MiniMax clamped > 0).

🔬 Research Autopilot Phase 1

run_research_autopilot turns a hypothesis_id into a research goal (thesis as objective, backtest-relevant acceptance criteria, next-step hints), and generate_backtest_config auto-writes a backtest config.json from the hypothesis's universe and data sources — so the agent goes straight from idea → signal_engine.py → run.

🗃️ Opt-in local data cache + local loader

VIBE_TRADING_DATA_CACHE=1 caches settled bars to ~/.vibe-trading/cache (user home, never the repo); a staleness guard never caches a range ending today, and cached frames are byte-identical to live fetches. A new local loader reads OHLCV straight from your own CSV / Parquet / DuckDB files via ~/.vibe-trading/data-bridge/config.yaml, with normal fallback-chain support.

🛡️ Security & hardening wave

A community-driven hardening pass: API settings-write auth (#245), agent shell-tool opt-in (#243), loopback-host rebinding rejection (#242), explicit local-shutdown auth (#241), and identifier containment for mandate proposal-ids (#256), persistent-memory types (#257), and MCP swarm run-ids (#258). Plus responsive Stop mid-stream + SSE reconnect on returning to a running session (#229), multi-engine web_search fallback (#231), and Gemini thoughtSignature round-trip through OpenAI-compat tool calls (#176, #184).

🪪 Version reporting is now consistent

--version, the REST API (/docs + /api), the MCP server handshake, and the Web UI footer all derive from one source — the REST API had drifted to a wrong hardcoded 5.0.0. Packaging also now ships skill example scripts in the wheel, and the Docker image installs weasyprint's native libs so PDF reports render.
