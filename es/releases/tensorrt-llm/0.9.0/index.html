#TensorRT-LLM v0.9.0 Hola, Estamos muy contentos de anunciar la versión 0.9.0 de TensorRT-LLM. Ha sido un esfuerzo intenso y esperamos que le permita implementar fácilmente la inferencia basada en GPU para LLM de última generación. Queremos que TensorRT-LLM le ayude a ejecutar esos LLM muy rápido. Esta actualización incluye:

  • Soporte de modelo
    • Apoye a distil-whisper, gracias a la contribución de @Bhuvanesh09 en PR #1061
    • Soporte HuggingFace StarCoder2
    • Soporte VILA
    • Soporte Smaug-72B-v0.1
    • Migrar ejemplos de BLIP-2 a examples/multimodal
  • Características
    • [CAMBIO ÚLTIMO] La optimización de muestreo TopP con el algoritmo determinista AIR TopP está habilitada de forma predeterminada
    • [CAMBIO ÚLTIMO] Admite la integración de uso compartido para Gemma
    • Agregar soporte a la fragmentación de contexto para trabajar con la reutilización de caché KV
    • Habilita diferentes tokens de rebobinado por secuencia para Medusa
    • Soporte BART LoRA (limitado al tiempo de ejecución Python)
    • Habilitar multi-LoRA para BART LoRA
    • Soporte early_stopping=False en búsqueda de haz para C++ Runtime
    • Agregue el posprocesador logits al administrador de lotes (consulte docs/source/batch_manager.md#logits-post-processor-optional)
    • Admite la importación y conversión de puntos de control de HuggingFace Gemma, gracias por la contribución de @mfuntowicz en el n.° 1147
    • Soporte para cargar Gemma desde HuggingFace
    • Admite planificador de paralelismo automático para API de alto nivel y flujo de trabajo de constructor unificado
    • Soporte para ejecutar GptSession sin OpenMPI #1220
    • Soporte Medusa IFB
    • [Experimental] Compatible con FP8 FMHA, tenga en cuenta que el rendimiento no es óptimo y seguiremos optimizándolo
    • Más tamaños de cabeza compatibles con modelos tipo LLaMA
      • Ampere (sm80, sm86), Ada (sm89), Hopper (sm90), todos los tamaños de cabezales compatibles [32, 40, 64, 80, 96, 104, 128, 160, 256] ahora.
    • Soporte de funcionalidad OOTB
      • T5
      • Mixtral 8x7B
  • API
    • C++ executor API
      • Agregue enlaces Python, consulte documentación y ejemplos en examples/bindings
      • Agregue ejemplos avanzados y de múltiples GPU para el enlace Python de executor C++ API, consulte examples/bindings/README.md
      • Agregar documentos para C++ executor API, ver docs/source/executor.md
    • API de alto nivel (consulte examples/high-level-api/README.md para obtener orientación)
      • [CAMBIO ÚLTIMO] Reutilice el QuantConfig utilizado en la herramienta trtllm-build, admita funciones de cuantificación más amplias
      • Soporte en LLM() API para aceptar motores construidos por el comando trtllm-build
      • Agregue soporte para el punto de control TensorRT-LLM como entrada del modelo
      • Perfeccione el SamplingConfig utilizado en los LLM.generate o LLM.generate_async API, con el soporte de búsqueda de haz, una variedad de penalizaciones y más funciones.
      • Agregue soporte para la función StreamingLLM, habilítela configurando LLM(streaming_llm=...)
      • Migrar Mixtral a API de alto nivel y flujo de trabajo de creación unificado
    • [CAMBIO ÚLTIMO] Modelo Qwen refactorizado para el flujo de trabajo de compilación unificado; consulte examples/qwen/README.md para conocer los comandos más recientes
    • [CAMBIO ÚLTIMO] Mover el script de punto de control de conversión de LLaMA del directorio de ejemplos a la biblioteca principal
    • [CAMBIO ÚLTIMO] Refactorice GPT con un flujo de trabajo de construcción unificado; consulte examples/gpt/README.md para conocer los comandos más recientes
    • [CAMBIO ÚLTIMO] Se eliminaron todos los indicadores relacionados con lora del script convert_checkpoint.py y el contenido del punto de control del comando trtllm-build, para generalizar mejor la función a más modelos.
    • [CAMBIO ÚLTIMO] Se eliminó el indicador use_prompt_tuning y las opciones del script convert_checkpoint.py y el contenido del punto de control, para generalizar mejor la función a más modelos. Utilice el trtllm-build --max_prompt_embedding_table_size en su lugar.
  • [CAMBIO ÚLTIMO] Se cambió el indicador trtllm-build --world_size al indicador --auto_parallel; la opción se usa solo para el planificador paralelo automático.
    • [CAMBIO ÚLTIMO] Se elimina AsyncLLMEngine, la clase tensorrt_llm.GenerationExecutor se refactoriza para funcionar con el inicio explícito con mpirun en el nivel de aplicación y aceptar un comunicador MPI creado por mpi4py
    • [CAMBIO ÚLTIMO] examples/server se eliminan; consulte examples/app en su lugar.
    • [CAMBIO ÚLTIMO] Elimina los parámetros relacionados con LoRA de los scripts de punto de control de conversión
    • [CAMBIO ÚLTIMO] Simplifique el script de punto de control de conversión de Qwen
    • [CAMBIO ÚLTIMO] Elimina el parámetro model de gptManagerBenchmark y gptSessionBenchmark

    • Se corrigió el error head_size al importar el modelo Gemma desde HuggingFace Hub, gracias por la contribución de @mfuntowicz en el n.° 1148.
    • Se corrigió la falla de construcción de ChatGLM2-6B en INT8 #1239
    • Se corrigió la ruta relativa incorrecta en la documentación de Baichuan #1242
    • Se corrigieron tensores SamplingConfig incorrectos en ModelRunnerCpp #1183
    • Solucionado el error al convertir SmoothQuant LLaMA #1267
    • Se solucionó el problema por el cual examples/run.py solo cargaba una línea desde --input_file.
    • Se solucionó el problema por el cual ModelRunnerCpp no transfiere correctamente los campos tensoriales de SamplingConfig #1183
  • Punto de referencia
    • Agregar procesamiento por lotes estático emulado en gptManagerBenchmark
    • Admite conjuntos de datos arbitrarios de HuggingFace para evaluaciones comparativas de C++; consulte la sección "Preparar conjunto de datos" en benchmarks/cpp/README.md
    • Agregar informe de latencia percentil a gptManagerBenchmark
  • Rendimiento
    • Optimice gptDecoderBatch para admitir muestreo por lotes
    • Habilite FMHA para modelos de la familia BART, Whisper y NMT
    • Elimine el paralelismo del tensor del enrutador para mejorar el rendimiento de los modelos MoE, gracias a la contribución de @megha95 en el n.° 1091
    • Mejorar el kernel totalmente reducido personalizado
  • Infraestructura
    • La imagen base Docker para TensorRT-LLM se actualiza a nvcr.io/nvidia/pytorch:24.02-py3
    • La imagen base Docker para el backend de TensorRT-LLM se actualiza a nvcr.io/nvidia/tritonserver:24.02-py3
    • La versión dependiente de TensorRT se actualiza a 9.3
    • La versión dependiente de PyTorch se actualiza a 2.2
    • La versión CUDA dependiente se actualiza a 12.3.2 (también conocida como 12.3 Actualización 2) Actualmente, hay dos ramas clave en el proyecto:
  • La rama rel es la rama estable para el lanzamiento de TensorRT-LLM. Ha sido sometido a controles de calidad y probado cuidadosamente.
  • La rama principal es la rama de desarrollo. Es más experimental. Actualizamos la rama principal periódicamente con nuevas funciones, correcciones de errores y optimizaciones de rendimiento. La rama estable se actualizará con menos frecuencia y las frecuencias exactas dependen de sus comentarios. Gracias, El equipo de ingeniería de TensorRT-LLM

TensorRT-LLM v0.9.0

Highlights

  • Unified builds change existing workflows — GPT, Qwen and Mixtral move to the unified builder/high-level path, so use the refreshed example commands. LoRA configuration moves from convert_checkpoint.py and checkpoint metadata into trtllm-build; prompt tuning now uses --max_prompt_embedding_table_size, and --world_size becomes planner-only --auto_parallel. The LLaMA conversion script also moves into the core library.
  • The high-level API accepts build artifacts directly — LLM() can load engines produced by trtllm-build or TensorRT-LLM checkpoints, while reusing the builder’s QuantConfig for broader quantization support. SamplingConfig gains beam search and penalties, and LLM(streaming_llm=...) enables StreamingLLM, reducing duplicate build configuration.
  • Default TopP sampling behavior changes — Deterministic AIR TopP is now enabled by default. Re-run sampling-sensitive evaluations and inspect output distributions rather than assuming parity with earlier releases. C++ beam search also gains support for early_stopping=False.
  • Runtime and serving APIs require migration — AsyncLLMEngine is removed in favor of a refactored GenerationExecutor, supporting explicit mpirun launching or an mpi4py communicator. GptSession can run without OpenMPI (#1220), the C++ executor gains Python bindings and multi-GPU examples under examples/bindings, and examples/server is replaced by examples/app.
  • Model and adapter coverage broadens — New support includes distil-Whisper (#1061), StarCoder2, VILA, Smaug-72B-v0.1 and Hugging Face Gemma checkpoint import/conversion (#1147), with T5 and Mixtral 8x7B available out of the box. BART LoRA and multi-LoRA are limited to the Python runtime, so C++ deployments should not assume adapter parity.
  • Performance gains arrive with a newer platform baseline — LLaMA-like models support head sizes [32, 40, 64, 80, 96, 104, 128, 160, 256] across Ampere, Ada and Hopper; MoE router tensor parallelism is removed (#1091), and BART, Whisper and NMT models gain FMHA. FP8 FMHA remains experimental with suboptimal performance. The stack moves to TensorRT 9.3, PyTorch 2.2 and CUDA 12.3.2 with 24.02 base images, so refresh environments and rebenchmark.

Hi,

We are very pleased to announce the 0.9.0 version of TensorRT-LLM. It has been an intense effort, and we hope that it will enable you to easily deploy GPU-based inference for state-of-the-art LLMs. We want TensorRT-LLM to help you run those LLMs very fast.

This update includes:

  • Model Support
    • Support distil-whisper, thanks to the contribution from @Bhuvanesh09 in PR #1061
    • Support HuggingFace StarCoder2
    • Support VILA
    • Support Smaug-72B-v0.1
    • Migrate BLIP-2 examples to examples/multimodal
  • Features
    • [BREAKING CHANGE] TopP sampling optimization with deterministic AIR TopP algorithm is enabled by default
    • [BREAKING CHANGE] Support embedding sharing for Gemma
    • Add support to context chunking to work with KV cache reuse
    • Enable different rewind tokens per sequence for Medusa
    • BART LoRA support (limited to the Python runtime)
    • Enable multi-LoRA for BART LoRA
    • Support early_stopping=False in beam search for C++ Runtime
    • Add logits post processor to the batch manager (see docs/source/batch_manager.md#logits-post-processor-optional)
    • Support import and convert HuggingFace Gemma checkpoints, thanks for the contribution from @mfuntowicz in #1147
    • Support loading Gemma from HuggingFace
    • Support auto parallelism planner for high-level API and unified builder workflow
    • Support run GptSession without OpenMPI #1220
    • Medusa IFB support
    • [Experimental] Support FP8 FMHA, note that the performance is not optimal, and we will keep optimizing it
    • More head sizes support for LLaMA-like models
      • Ampere (sm80, sm86), Ada (sm89), Hopper(sm90) all support head sizes [32, 40, 64, 80, 96, 104, 128, 160, 256] now.
    • OOTB functionality support
      • T5
      • Mixtral 8x7B
  • API
    • C++ executor API
      • Add Python bindings, see documentation and examples in examples/bindings
      • Add advanced and multi-GPU examples for Python binding of executor C++ API, see examples/bindings/README.md
      • Add documents for C++ executor API, see docs/source/executor.md
    • High-level API (refer to examples/high-level-api/README.md for guidance)
      • [BREAKING CHANGE] Reuse the QuantConfig used in trtllm-build tool, support broader quantization features
      • Support in LLM() API to accept engines built by trtllm-build command
      • Add support for TensorRT-LLM checkpoint as model input
      • Refine SamplingConfig used in LLM.generate or LLM.generate_async APIs, with the support of beam search, a variety of penalties, and more features
      • Add support for the StreamingLLM feature, enable it by setting LLM(streaming_llm=...)
      • Migrate Mixtral to high level API and unified builder workflow
    • [BREAKING CHANGE] Refactored Qwen model to the unified build workflow, see examples/qwen/README.md for the latest commands
    • [BREAKING CHANGE] Move LLaMA convert checkpoint script from examples directory into the core library
    • [BREAKING CHANGE] Refactor GPT with unified building workflow, see examples/gpt/README.md for the latest commands
    • [BREAKING CHANGE] Removed all the lora related flags from convert_checkpoint.py script and the checkpoint content to trtllm-build command, to generalize the feature better to more models
    • [BREAKING CHANGE] Removed the use_prompt_tuning flag and options from convert_checkpoint.py script and the checkpoint content, to generalize the feature better to more models. Use the trtllm-build --max_prompt_embedding_table_size instead.
    • [BREAKING CHANGE] Changed the trtllm-build --world_size flag to --auto_parallel flag, the option is used for auto parallel planner only.
    • [BREAKING CHANGE] AsyncLLMEngine is removed, tensorrt_llm.GenerationExecutor class is refactored to work with both explicitly launching with mpirun in the application level, and accept an MPI communicator created by mpi4py
    • [BREAKING CHANGE] examples/server are removed, see examples/app instead.
    • [BREAKING CHANGE] Remove LoRA related parameters from convert checkpoint scripts
    • [BREAKING CHANGE] Simplify Qwen convert checkpoint script
    • [BREAKING CHANGE] Remove model parameter from gptManagerBenchmark and gptSessionBenchmark
  • Bug fixes
    • Fix a weight-only quant bug for Whisper to make sure that the encoder_input_len_range is not 0, thanks to the contribution from @Eddie-Wang1120 in #992
    • Fix the issue that log probabilities in Python runtime are not returned #983
    • Multi-GPU fixes for multimodal examples #1003
    • Fix wrong end_id issue for Qwen #987
    • Fix a non-stopping generation issue #1118 #1123
    • Fix wrong link in examples/mixtral/README.md #1181
    • Fix LLaMA2-7B bad results when int8 kv cache and per-channel int8 weight only are enabled #967
    • Fix wrong head_size when importing Gemma model from HuggingFace Hub, thanks for the contribution from @mfuntowicz in #1148
    • Fix ChatGLM2-6B building failure on INT8 #1239
    • Fix wrong relative path in Baichuan documentation #1242
    • Fix wrong SamplingConfig tensors in ModelRunnerCpp #1183
    • Fix error when converting SmoothQuant LLaMA #1267
    • Fix the issue that examples/run.py only load one line from --input_file
    • Fix the issue that ModelRunnerCpp does not transfer SamplingConfig tensor fields correctly #1183
  • Benchmark
    • Add emulated static batching in gptManagerBenchmark
    • Support arbitrary dataset from HuggingFace for C++ benchmarks, see “Prepare dataset” section in benchmarks/cpp/README.md
    • Add percentile latency report to gptManagerBenchmark
  • Performance
    • Optimize gptDecoderBatch to support batched sampling
    • Enable FMHA for models in BART, Whisper and NMT family
    • Remove router tensor parallelism to improve performance for MoE models, thanks to the contribution from @megha95 in #1091
    • Improve custom all-reduce kernel
  • Infra
    • Base Docker image for TensorRT-LLM is updated to nvcr.io/nvidia/pytorch:24.02-py3
    • Base Docker image for TensorRT-LLM backend is updated to nvcr.io/nvidia/tritonserver:24.02-py3
    • The dependent TensorRT version is updated to 9.3
    • The dependent PyTorch version is updated to 2.2
    • The dependent CUDA version is updated to 12.3.2 (a.k.a. 12.3 Update 2)

Currently, there are two key branches in the project:

  • The rel branch is the stable branch for the release of TensorRT-LLM. It has been QA-ed and carefully tested.
  • The main branch is the dev branch. It is more experimental.

We are updating the main branch regularly with new features, bug fixes and performance optimizations. The stable branch will be updated less frequently, and the exact frequencies depend on your feedback.

Thanks,

The TensorRT-LLM Engineering Team
