#TensorRT-LLM v0.21.0

Lanzamiento de TensorRT-LLM 0.21.0

Funciones clave y mejoras

  • Soporte de modelo
    • Se agregó compatibilidad con Gemma3 VLM
  • Características
    • Se agregó soporte para EP a gran escala.
    • NIXL integrado en la capa de comunicación del servicio desagregado.
    • Se agregó soporte de memoria de tejido para transferencia de caché KV
    • MCP agregado en ScaffoldingLLM
    • Se agregó soporte para la cuantificación w4a8_mxfp4_fp8.
    • Se agregó soporte para la cuantificación por filas de fp8
    • Se agregó soporte de generación de logits en TRTLLM Sampler.
    • Se agregó soporte para problemas de registro en TRTLLM Sampler.
    • TRTLLM Sampler optimizado con rendimiento de un solo haz y un solo paso
    • Servicio desagregado habilitado para Qwen-3
    • Se agregó soporte EAGLE3 para Qwen-3.
    • Finalización fusionada y reducción total para el modelo Qwen-MoE
    • Módulo MoE fusionado refactorizado
    • Se agregó soporte para atención fragmentada en Blackwell y Hopper.
    • Se introdujeron núcleos de atención de ventana deslizante para la fase de generación en Blackwell.
    • Cubins DeepSeek FP8 TRT-LLM Gen actualizados para mejorar el rendimiento en escenarios de lotes grandes
    • Se agregó compatibilidad con GEMM a escala de bloques del FP8 en SM89.
    • Programador de superposición habilitado entre borradores adelantados.
    • Se agregó soporte para gráficos cuda por partes para MLA
    • Se agregó eagle3 monomotor independiente del modelo
    • Habilitado Finalizar + Allreduce + agregar + fusión rmsnorm
    • MoE de escala de bloques TRT-LLM Gen FP8 integrado con sintonizador automático del kernel de flujo de trabajo Pytorch
    • Se agregó soporte para la publicación desagregada Eagle3 + en dos modelos de flujo de decodificación especulativa.
    • Modelos Llama 3.1 validados en H200 NVL
  • Punto de referencia:
    • Se agregó el script de referencia all_reduce.py para realizar pruebas.
    • Se agregó ancho de haz al comando de latencia trtllm-bench.
    • Se corrigieron los errores de trtllm-bench iter_stats y cuda_graph_batch_sizes
    • Se habilitó trtllm-bench para ejecutar LoRA y agregar capacidad básica de prueba de rendimiento e2e para LoRA.
    • Post_proc soportado para banco
    • Se agregó la opción no_kv_cache_reuse y soporte de transmisión para el banco de servicio trtllm

Cambios de infraestructura

  • La imagen base Docker para TensorRT-LLM se actualiza a nvcr.io/nvidia/pytorch:25.05-py3.
  • La imagen base Docker para el backend de TensorRT-LLM se actualiza a nvcr.io/nvidia/tritonserver:25.05-py3.
  • La versión pública dependiente de PyTorch se actualiza a 2.7.1.
  • La versión dependiente de TensorRT se actualiza a 10.11.
  • La versión dependiente de NVIDIA ModelOpt se actualiza a 0.31.
  • La versión NCCL dependiente se actualiza a 2.27.5.

API Cambios

  • Establecer _AutoDeployLlmArgs como objeto de configuración principal
  • Se eliminó la solicitud de decodificador de la interfaz del decodificador.
  • Se mejoró torch_compile_config en llm args.
  • Se eliminó el campo use_kv_cache redundante de PytorchConfig.
  • Se movió allreduce_strategy de api comprometido a referencia

Problemas solucionados

  • Se corrigió el bloqueo del servicio desagregado cuando MNNVL de dos disparos AllReduce está habilitado (#4678)
  • Se corrigió el balanceador de carga de EP con capa MTP y ruta compensada por el rango de EP (#4767)
  • Se corrigió el relleno del gráfico cuda para la decodificación de especificaciones (#4853)
  • Se solucionó el problema de contexto largo de llama 4 (#4809)
  • Se corrigió el cálculo de max_num_sequences con programación superpuesta (#4532)
  • Se corrigió el llenado previo fragmentado + programación superpuesta (#5761)
  • Se solucionó el problema de bloqueo de trtllm-bench debido a LLM API IPC (#4798)
  • Se corrigió el error de índice fuera de límites en la decodificación de especificaciones (#5954)
  • Se corrigió el acceso ilegal a la memoria MTP en el calentamiento del gráfico cuda (#5947)
  • Se corrigió el error de no tener espacios libres con decodificación de especificaciones + desagg (#5975)
  • Se corrigió el tamaño de la ventana de atención única para Gemma3 1B (#5564)

Problemas conocidos

  • exactitud/test_cli_flow::TestGpt2::test_beam_search_large está roto.
  • Habilitar la publicación desagregada, MTP y el programador superpuesto al mismo tiempo puede generar problemas de precisión.
  • En 0.21, se agregó soporte completo de atención fragmentada para garantizar que el modelo LLaMA4 pueda ejecutarse funcionalmente con una longitud de secuencia > 8K, mientras que existe una regresión de rendimiento conocida (solo afecta al modelo LLaMA4) en Hopper debido a esta mejora funcional. La causa raíz de la regresión ya se ha identificado y la solución será parte de la versión futura.

TensorRT-LLM v0.21.0

Highlights

  • Breaking API reshuffle in the LLM stack — Config construction needs attention on upgrade: _AutoDeployLlmArgs becomes the primary config object, the decoder request is removed from the decoder interface, the redundant use_kv_cache field is dropped from PytorchConfig, allreduce_strategy moves from the committed API to reference, and the monolithic LLM class is split into TorchLLM/TrtLLM (#4900). TorchCompileConfig fields also lose their torch_compile prefix (#5261), so any code reading those attributes by name will break. Budget migration time for config and wrapper code, not just a version bump.

  • Disaggregated serving moves toward production transport — NIXL is now integrated into the disaggregated service's communication layer, joined by fabric-memory KV cache transfer and large-scale EP support. Stability work targets real deployment hazards: a hang when MNNVL two-shot AllReduce is enabled (#4678) and the "no free slots" failure under spec-decode + disagg (#5975) are fixed. Watch out for the documented accuracy problem when disaggregated serving, MTP, and the overlap scheduler are enabled together — that combination is not yet safe.

  • Speculative decoding gets a broader, sturdier footing — EAGLE3 lands for Qwen3 (#5206), alongside a model-agnostic one-engine EAGLE3 path and overlap scheduling between draft forwards; draft-target decoding also moves into the new framework (#4558). The long tail of correctness fixes matters more than the headline features here: CUDA-graph padding (#4853), an index-out-of-bounds in spec decoding (#5954), and an MTP illegal-memory-access during graph warmup (#5947) are all addressed, with piecewise CUDA graph support for MLA (#4467) improving graph coverage. If you were holding off on spec decode for stability reasons, this is the release to re-evaluate.

  • Model and quantization coverage expands, with a Hopper caveat — New entry points include Gemma3 VLM, Qwen3 disaggregated serving, w4a8_mxfp4_fp8 and fp8 rowwise quantization, FP8 block-scale GEMM on SM89 (Ada), and TRT-LLM Gen FP8 block-scale MoE wired into the PyTorch autotuner (#5207). LLaMA4 >8K sequences now run via full chunked attention, but that functional win carries a known performance regression on Hopper affecting LLaMA4 only, with the fix deferred to a future release — benchmark before committing to H100-class deployments. Two off-by-one/context bugs worth noting are fixed: Gemma3 1B attention window size (#5564) and Llama 4 long context (#4809).

  • Container and dependency baseline jumps to NGC 25.05 — Base images move to pytorch:25.05-py3 and tritonserver:25.05-py3, with PyTorch 2.7.1, TensorRT 10.11, ModelOpt 0.31, and NCCL 2.27.5. This is the most likely source of environment-level breakage: custom Dockerfiles and pinned host NCCL/driver combinations should be rebuilt and revalidated rather than assumed compatible.

  • Sampler and benchmark tooling get developer-facing upgrades — The TRTLLM Sampler gains generation logits, log probs, and a single-beam/single-step performance optimization, while LlmResponse is reimplemented in Python to cut pybind host overhead (#5224). Benchmarking closes several gaps that previously distorted measurements: trtllm-bench gains beam-width control, LoRA end-to-end testing, no_kv_cache_reuse, and streaming, plus fixes to iter_stats and cuda_graph_batch_sizes errors and an IPC hang (#4798). Expect cleaner perf data, but note that old benchmark scripts may need flag updates.
