#TensorRT-LLM v0.20.0

Lanzamiento de TensorRT-LLM 0.20.0

Funciones clave y mejoras

  • Soporte de modelo
    • Se agregó compatibilidad con Qwen3. Consulte la sección "Qwen3" en examples/models/core/qwen/README.md.
    • Se agregó compatibilidad con HyperCLOVAX-SEED-Vision en el flujo de PyTorch. Consulte examples/models/contrib/hyperclovax/README.md
    • Se agregó Dynasor-CoT en ejemplos de andamios. Consulte examples/scaffolding/contrib/Dynasor/README.md
    • Se agregó compatibilidad con Mistral Small 3.1 24B VLM en el flujo de trabajo TRT
    • Se agregó compatibilidad con Gemma3-1b-it en el flujo de trabajo de PyTorch.
    • Se agregó soporte para el modelo Nemotron-H.
    • Se agregó soporte Eagle-3 para LLAMA4
  • Flujo de trabajo de PyTorch
    • Se agregó soporte para lora.
    • Se agregó soporte para logs de devolución.
    • Adoptar una nueva definición de logprob en el flujo de PyTorch.
    • Estadísticas habilitadas por solicitud con el backend de PyTorch
    • LogitsProcessor habilitado en el backend de PyTorch
  • Punto de referencia:
    • Agregue ancho de haz para baja latencia.
    • Corregir errores de trtllm-bench iter_stats y cuda_graph_batch_sizes.
    • Eliminar el punto de referencia de tiempo de ejecución Python en desuso
    • Agregar soporte de referencia para andamios
  • Modelos multimodales
    • Se agregó soporte en trtllm-serve.
    • Se agregó soporte en trtllm-bench, el soporte está limitado solo a imágenes por ahora
  • Compatible con DeepSeek-R1 W4A8 en Hopper
  • Agregue compatibilidad con RTX Pro 6000 en una sola GPU
  • Procesador de entrada Llama4 integrado
  • Se agregaron núcleos FHMA de reducción de CGA en Blackwell
  • Contexto fragmentado habilitado para FlashInfer
  • Reutilización de caché KV compatible para MLA
  • Se agregó soporte para gráficos CUDA por partes
  • Admitió múltiples adaptadores LoRA y TP
  • Se agregó un enrutador KV con reconocimiento de caché para servicio desagregado
  • Atención no fusionada para soporte nativo.
  • Se agregó el kernel group_rms_norm para normalizar múltiples entradas en un solo operador.
  • Se agregó un enrutador inteligente para el módulo MoE.
  • Se agregó compatibilidad con tamaño de cabeza 72 para el kernel de preprocesamiento QKV.
  • Se agregó soporte MNNVL MoE A2A
  • Tablas de incrustación grandes optimizadas en modelos multimodales
  • Compatible con logprobs Top-K y Prompt_logprobs en LLMAPI
  • Programador de superposición habilitado en el flujo de trabajo TRT a través del ejecutor API

Cambios de infraestructura

  • El equipo TRT-LLM publica formalmente la imagen docker en NGC.
  • La rueda TensorRT-LLM prediseñada en PyPI ahora está vinculada a PyTorch 2.7.0, que utiliza la ABI CXX11
  • La versión dependiente de TensorRT se actualiza a 10.10.0
  • La versión CUDA dependiente se actualiza a 12.9.0
  • La versión pública dependiente de PyTorch se actualiza a 2.7.0
  • La versión dependiente de NVIDIA ModelOpt se actualiza a 0.29.0
  • La versión NCCL dependiente se mantiene en 2.25.1
  • Núcleos XQA de código abierto
  • La versión de los conjuntos de datos dependientes se actualizó a 3.1.0
  • Migrar el backend de Triton al repositorio de TensorRT LLM al submódulo de TensorRT LLM
  • Bajar la versión del conjunto de herramientas gcc de 13 a 11

API Cambios

  • [Cambio importante]: habilita la superposición de programación de forma predeterminada
  • Eliminar GptSession/V1 obsoleto del flujo de trabajo TRT
  • Establecer _AutoDeployLlmArgs como objeto de configuración principal
  • Permitir anular argumentos CLI con el archivo YAML en trtllm-serve
  • Se introdujo el campo de incrustación multimodal en LlmRequest

Problemas solucionados

  • Se corrigió el error cuando el servidor de contexto no tiene suficiente capacidad para KV Cache (#3095)
  • Se corrigió la sincronización del decodificador C++ en PyTorch (#3106)
  • Se corrigió el error al crear flujo cuda como parámetro predeterminado que se inicializará durante la importación (#3764)
  • Se corrigió el error relacionado con la creación de flujo CUDA como parámetro predeterminado, que se inicializará durante la importación (#3764)
  • Se corrigió el error de atención DP en el modelo Qwen3 MoE (#4141)
  • Se corrigió el acceso ilegal a la memoria al ejecutar LLaMA 4 con CUDA Graph habilitado (#4101)
  • Restablecer los estados planificados para evitar pérdidas de memoria en TrtllmAttentionWrapper (#4227)

Problemas conocidos

  • compatibilidad con modelos multi-GPU en RTX Pro 6000

TensorRT-LLM v0.20.0

Highlights

  • Scheduling overlap now on by default (breaking) — The most consequential behavioral change: overlap scheduling ships enabled, which alters request scheduling and can shift latency/throughput profiles for existing deployments. The flag was also corrected to enable_overlap_scheduler (#4433), so launch scripts still using the old name will silently lose control of it — audit your configs. In the same vein, the legacy GptSession/V1 TRT path is removed (V1 batching tests dropped in #4703) and _AutoDeployLlmArgs becomes the primary config object, so code built on the old session API or config shape needs migration.
  • Toolchain and dependency jump — This release rebases on PyTorch 2.7.0 (now built with the CXX11 ABI), TensorRT 10.10.0, CUDA 12.9.0, ModelOpt 0.29.0 and datasets 3.1.0, with NCCL held at 2.25.1. The CXX11 ABI switch is the one to watch: out-of-tree C++ extensions and custom plugins must be rebuilt against the new ABI or you'll hit symbol/link mismatches. GCC is downgraded 13→11 and the Triton backend moves into a submodule — both relevant if you build from source. NVIDIA now publishes an official release image on NGC (#4400), the safest route to a consistent stack.
  • Broader model and hardware coverage — Qwen3 (including a fix for missing mrope args in summary tasks, #4432), Nemotron-H, Eagle-3 speculative decoding for Llama4, Mistral Small 3.1 24B VLM, Gemma3-1b-it and HyperCLOVAX-SEED-Vision land, plus DeepSeek-R1 W4A8 on Hopper. RTX Pro 6000 (SM120) gains single-GPU FP8/NVFP4 support for Nemotron Super 49B (#4363, #4548), but multi-GPU on that part remains a known issue — plan single-GPU deployments for now.
  • PyTorch flow approaches parity — The PyTorch backend adds LoRA, return-logits, per-request stats and LogitsProcessor support, and adopts the new logprob definition. That last item is behaviorally significant: logprob values and their contract change, so downstream scoring or cross-backend comparisons should be revalidated rather than assumed identical to the TRT path.
  • New serving and performance levers — Long-context and MoE serving get piecewise CUDA graphs, MLA KV-cache reuse, a KV-cache-aware router for disaggregated serving, chunked context for FlashInfer, a smart MoE router and the overlap scheduler via the TRT executor API. LLM API adds top-K logprobs and prompt_logprobs, and LlmRequest gains a multimodal embedding field — important if you build multimodal serving on trtllm-serve.
  • Stability fixes worth the bump — Several correctness bugs close here: a hang when the context server lacks KV-cache capacity (#3095), illegal memory access with Llama4 under CUDA graphs (#4101), C++ decoder synchronization in PyTorch (#3106) and an attention data-parallel bug on Qwen3 MoE (#4141). If you run disaggregated serving or CUDA-graph-enabled Llama4, these alone justify upgrading.
