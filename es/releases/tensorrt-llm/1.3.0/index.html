#TensorRT-LLM v1.3.0

Funciones clave y mejoras

  • Soporte de Rubin (vista previa)
    • Se agregó soporte de vista previa para NVIDIA Rubin (SM107), validado en Vera Rubin.
    • Se agregó compatibilidad con DeepSeek-V4 y Kimi K3 en Vera Rubin.
  • Soporte de modelo
    • Se agregó compatibilidad con DeepSeek-V4 en Blackwell y Rubin (vista previa).
    • Se agregó compatibilidad con Kimi K3 en Blackwell y Rubin (versión preliminar), incluido el servicio multimodal y de múltiples nodos. El paralelismo de datos de atención (DEP16) requiere memoria GPU de clase GB300.
    • Se agregó compatibilidad con Qwen3.5 en Hopper, Blackwell y Rubin (versión preliminar), incluidos MTP y NVFP4 en Blackwell, y compatibilidad con Qwen3.6 y Qwen3.8-Flash-Next en Blackwell.
    • Se agregó compatibilidad con MiniMax-M3 en Blackwell y Rubin (vista previa).
    • Se agregó compatibilidad con GLM-5, GLM-5.2, Kimi-K2.5 y Step-3.7-Flash en Blackwell.
    • Se agregó soporte para Nemotron Nano Omni en Hopper y Blackwell.
    • Se agregó compatibilidad con Gemma 4 en Blackwell, incluido multimodal.
    • Se agregó soporte para Laguna en Hopper y Blackwell.
    • Se agregó almacenamiento en caché de prefijos para modelos híbridos Mamba, como Qwen3.5 y Nemotron Super V3.
  • Características
    • Rendimiento:
      • DeepSeek-V4, DeepSeek-V3.2, Qwen3.5, Gemma 4, MiniMax-M3 y Kimi K3 optimizados con fusiones de kernel específicas del modelo.
      • Se agregó localización de dominio de localidad (uGPU) para NVFP4 MoE en Rubin, que mantiene el tráfico de memoria local para cada unidad de GPU. Está habilitado de forma predeterminada; configure DISABLE_LOCALITY_DOMAINS=1 para desactivarlo.
      • Reducción de la sobrecarga del host con preprocesamiento asíncrono y búsqueda de haz sin sincronización, y reducción del tiempo de inicio con lectura anticipada del punto de control.
      • Se agregó atención en cascada y despacho GEMM BF16 de baja M para SM10x.
    • Porción desagregada:
      • Se agregó programación de primera generación, enrutamiento de afinidad de conversación, búsqueda de haces y soporte de modelo híbrido.
      • Se agregó servicio desagregado para Qwen3.8-Flash-Next.
    • Decodificación especulativa:
      • Se agregaron redactores DSpark, DFlash, Suffix Automaton y PARD.
      • Se agregaron árboles dinámicos EAGLE3, modelos borrador Eagle 3.1 y decodificación especulativa con LoRA.
      • Se agregó muestreo de rechazo para rutas de un modelo y desactivación automática basada en la tasa de aceptación para especulación dinámica.
      • Se agregó carga de pesos MTP desde puntos de control independientes.
    • Paralelismo y MoE:
      • Se agregó DWDP (paralelismo de datos de peso distribuido), paralelismo de contexto Helix extendido y un enrutador DP de atención con reconocimiento de caché KV.
      • Se agregaron los backends MoE DENSEGEMM, MEGAMOE_DEEPGEMM, MEGAMOE_CUTEDSL, CUTEDSL_FC12 (solo Rubin) y MARLIN.
      • Se agregó un backend NCCL-EP y soporte para hasta 2048 expertos.
      • Se agregó Router Replay (return_routed_experts) para devolver el enrutamiento MoE por token para el entrenamiento de RL.
    • Caché KV:
      • KV Cache Manager V2 se selecciona por modelo y se habilita de forma predeterminada para la mayoría de las familias de modelos.
      • Se agregó compresión de caché KV (TriAttention y compresión de página fría NVFP4), caché NVFP4 KV y caché de disco.
      • Se agregó reutilización de bloques por conversación y hash de bloques KV multimodal exacto.
      • Se agregaron conectores FlexKV y LMCache.
    • Cuantización:
      • Se agregó soporte lineal y MoE para MXFP8 (W8A8), incluidos puntos de control MXFP8 como MiniMax-M3.
      • Se agregó cuantificación de solo peso NVFP4 W4A16 a través de Marlin, por lo que los puntos de control NVFP4 se ejecutan en Hopper y Ada Lovelace.
      • Se agregó cuantización NVFP4 sintonizable.
      • Se agregó soporte para formatos de configuración de cuantificación heredados y ModelOpt 1.x.
  • Atención dispersa: Se agregaron núcleos de decodificación DSA FP4/FP8, GVR Top-K, Skip Softmax Attention (con dispersión de activación 2:4 opcional en Rubin) y MiniMax-M3 MSA.
    • Servicios y API:
      • Se agregaron los Mensajes Antrópicos API (/v1/messages) y se ampliaron las Respuestas API.
      • Se agregó un servidor gRPC y interfaces HTTP multiproceso.
      • Se agregaron priority por solicitud y función con nombre tool_choice a los API compatibles con OpenAI.
      • Se agregó la herramienta auto y la selección del analizador de razonamiento, y los analizadores de herramientas GLM-4.7, GLM-5 y Laguna.
      • Se agregaron métricas Prometheus y puntos finales de creación de perfiles /start_profile y /stop_profile.
      • Se agregaron las opciones trtllm-serve --served_model_name, --kv_cache_dtype y --middleware.
      • Se agregaron completaciones de logprobs de API y aceptación de parallel_tool_calls.
    • Muestreo y LoRA:
      • Se agregaron min_p, bad_words, penalizaciones por repetición/frecuencia/presencia, opciones de búsqueda de haz completo y sondas de registro procesadas a TorchSampler.
      • Se agregó un thinking_token_budget experimental para modelos de razonamiento.
      • Se agregó servicio multi-LoRA con gráficos CUDA, MoE LoRA por experto y FP8 LoRA denso.
    • Otros:
      • Se agregó programación teniendo en cuenta los prefijos, habilitada de forma predeterminada, para evitar el llenado previo duplicado de prefijos compartidos.
      • Se agregó compatibilidad con CUDA Graph precargado y rompible, y máscaras de atención personalizadas en el backend de atención TRTLLM.
      • Se agregó un caché de codificador multimodal y gráficos CUDA para codificadores multimodales.
      • Se agregaron actualizaciones de peso en vuelo para flujos de trabajo de RL.
      • Se agregó /v1/embeddings y una ruta rápida llm.encode() para modelos solo con codificador.
      • Se agregó el prototipo de carga del punto de control ModelExpress.
  • Documentación
    • Guía de migración: Se agregó la [Guía de migración eliminada del backend de TensorRT] (legacy/tensorrt-backend-removal.md).
    • Guías de implementación: Se agregaron guías de implementación para GLM-5, Kimi K3, MiniMax-M3, Nemotron 3, Qwen3.8-Flash-Next y Qwen3.8/Qwen3.5.
    • Documentación de funciones: Se agregaron guías para compresión de caché KV, incrustaciones, ModelExpress, enrutamiento de subagente y modelos de codificador-decodificador, y se reestructuró la guía de instalación.
    • Guías para desarrolladores: Se agregaron guías para atención escasa, compresión de caché KV, telemetría y kernels personalizados.

VisualGen

VisualGen es una nueva solución vertical en TensorRT-LLM para modelos de generación de imágenes y videos. Se ofrece a través de trtllm-serve junto con la inferencia LLM. Consulte la [documentación de VisualGen] (modelos/visual-generación.md) para obtener más detalles.

  • Modelos
    • Se agregaron modelos de generación de imágenes: FLUX.1, FLUX.2, GLM-Image y Qwen-Image, incluidos Qwen-Image-Edit y Qwen-Image-Layered.
    • Modelos de generación de video agregados: Wan 2.2 (incluidos 5B TI2V y FastWan), LTX-2, HunyuanVideo 1.5, Cosmos3 y MiniMax-H3.
  • Características
    • Se agregaron puntos finales de generación de imágenes, edición de imágenes y generación de video en trtllm-serve.
    • Se agregó tensor, contexto y paralelismo CFG, cuantificación NVFP4 y FP8, gráficos CUDA y tiempo de ejecución LoRA.
    • Se agregó almacenamiento en caché TeaCache y Cache-DiT, atención escasa y backends de atención FlashAttention 4, FlashInfer y cuDNN.
    • Se agregó una canalización trtllm-eval para modelos VisualGen.
  • Documentación
    • Ejemplos de VisualGen
    • Blogs de tecnología publicados en:
      • "Ampliación de la generación de vídeo en rack NVL72 con TensorRT-LLM"
      • "Acelerar la generación de video con cuantización GEMM, cuantización de atención y omitir atención Softmax en TensorRT-LLM"
  • Problemas conocidos

API Cambios

  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminó el backend de TensorRT.</span> PyTorch es el único backend. Se eliminan trtllm-build, TrtLlmArgs, BuildConfig, MedusaDecodingConfig, LookaheadDecodingConfig, trtllm-bench build y trtllm-bench --engine_dir. Consulte la [guía de migración] (legacy/tensorrt-backend-removal.md).
  • <span style="color: red">[CAMBIO IMPORTANTE] Se eliminaron los API de tiempo de ejecución y ejecutor de C++ heredado.</span> Se eliminaron los API de C++ Executor, los API de tiempo de ejecución y administrador de lotes heredados y la opción de compilación cpp_only.
  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminaron los modelos backend Triton con motor TensorRT.</span> Solo queda el modelo llmapi Triton.
  • <span style="color: red">[CAMBIO ÚLTIMO] TRTLLMSampler eliminado.</span> TorchSampler, que requiere FlashInfer, es el único sampler. El argumento sampler_type se ignora con una advertencia y se elimina disable_flashinfer_sampling.
  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminó la decodificación especulativa de dos modelos.</span> Se eliminaron los campos eagle3_one_model y mtp_eagle_one_model; Utilice las implementaciones de un modelo.
  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminaron AutoDeploy, Star Attention y WIDEEP.</span> Se eliminaron AutoDeploy y Star Attention, y ya no se puede seleccionar el backend de WIDEEP MoE.
  • <span style="color: red">[CAMBIO ÚLTIMO] Los indicadores CLI anulan la configuración de YAML.</span> Los indicadores trtllm-serve, trtllm-eval y trtllm-bench explícitos ahora tienen prioridad sobre los valores de configuración de YAML.
  • <span style="color: red">[CAMBIO ÚLTIMO] El tiempo de espera de transferencia de caché de KV está predeterminado en 60 segundos.</span> Anteriormente no había tiempo de espera; configúrelo con cache_transceiver_config.kv_transfer_timeout_ms.
  • <span style="color: red">[CAMBIO ÚLTIMO] Las plantillas de chat por solicitud son opcionales.</span> Habilítelas con trtllm-serve --allow_request_chat_template.
  • <span style="color: red">[CAMBIO ÚLTIMO] Logprobs con un límite de 100.</span> Los valores logprobs o prompt_logprobs más grandes generan un ValueError.
  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminó el punto final /perf_metrics.</span> Utilice el encabezado de solicitud X-TRTLLM-return-metrics: 1 en su lugar.
  • <span style="color: red">[CAMBIO ÚLTIMO] Se cambió el nombre de los campos de especulación dinámica.</span> Utilice acceptance_rate_window_size y acceptance_rate_threshold; el umbral ahora es una tasa de aceptación en [0, 1].
  • <span style="color: red">[CAMBIO ÚLTIMO] Se eliminaron las opciones obsoletas.</span> Esto incluye Eagle choices y trtllm-serve --fail_fast_on_attention_window_too_large.
  • La compresión de páginas frías de NVFP4 permanece habilitada y deshabilitada de forma predeterminada. Cuando está habilitado para DeepSeek-V4, NoPE usa NVFP4 y RoPE ahora tiene como valor predeterminado 2FP4 (nvfp4_residual_dim=64). Configure skip_rope_quantization=True para mantener RoPE en su precisión original, como antes, o nvfp4_residual_dim=0 para usar NVFP4 único. El tipo de caché KV de GPU activo no ha cambiado. Consulte el [ejemplo de compresión de página fría NVFP4] (fuente:examples/kv_cache_compression/nvfp4_cold_page.md#deepseek-v4).
  • [DEPRECATION] El backend de TRITON MoE (TritonFusedMoE, moe_config.backend="TRITON") está obsoleto a partir de TensorRT-LLM 1.3 (2026-09) y se eliminará después del período de migración de 3 meses. Su única función restante es una modesta ventaja de rendimiento para GPT-OSS en Hopper con W4A16_MXFP4: la configuración única AUTO se resuelve en TRITON y el formato que adopta un punto de control MXFP4 GPT-OSS en SM90. A medida que el conjunto de modelos y las plataformas compatibles siguen creciendo, una ruta MoE de un solo escenario ya no justifica su costo de mantenimiento. moe_config.backend="CUTLASS" lo reemplaza funcionalmente en Hopper: sirve W4A16_MXFP4 en SM90 junto con las rutas por tensor BF16 y FP8 no cuantificadas, y la resolución backend MoE ya se degrada automáticamente cuando TRITON decli crea una capa. Durante el período de migración, TRITON sigue funcionando y registra una advertencia única. Consulte la política de desuso.
  • [DEPRECATION] Las opciones trtllm-serve --backend, --moe_cluster_parallel_size y --metrics-log-interval, y la opción trtllm-eval --backend, están en desuso.
  • [DEPRECATION] TorchCompileConfig.enable_piecewise_cuda_graph y capture_num_tokens, MTPDecodingConfig.num_nextn_predict_layers y perf_metrics_max_requests están en desuso.
  • [DEPRECATION] La publicación desagregada sin internal_request_auth_key está obsoleta. Establezca la misma clave en la configuración del servidor desagregada y en cada configuración de trabajador.
  • La telemetría de uso está activada de forma predeterminada. Para optar por no participar, configure TRTLLM_NO_USAGE_STATS=1 o DO_NOT_TRACK=1, pase --no-telemetry al CLI o configure telemetry_config=TelemetryConfig(disabled=True) en el LLM API. Consulte la [guía de telemetría] (developer-guide/telemetry.md).
  • GPT-OSS utiliza de forma predeterminada el backend TRTLLM MoE en Blackwell.
  • TorchCompileConfig.max_num_streams ahora tiene como valor predeterminado 3 en lugar de 1.

Problemas solucionados

  • Porción desagregada:
    • Se corrigió un problema con el paralelismo de canalización de contexto y el paralelismo del tensor de generación, un problema conocido en 1.2.
    • Se corrigieron bloqueos con la reutilización de bloques después del desalojo y la transferencia KV asíncrona solo de generación.
    • Se corrigió un error en un rango que bloqueaba todos los rangos de generación.
  • Atención:
    • Se corrigió un acceso ilegal a la memoria cuando max_seq_len excede max_position_embeddings.
    • Se corrigió una condición de carrera XQA, precisión del sumidero de atención y acceso ilegal a la memoria por ventana deslizante.
    • Se corrigió la precisión del FP8 con Skip Softmax Attention.
    • Se corrigió un acceso ilegal a la memoria de DeepSeek-V3.2 con gráficos CUDA y descarga de caché KV del host.
  • Decodificación especulativa: Se corrigieron fallas de EAGLE3 en Qwen3-235B-A22B NVFP4 y fallas de MTP en Nemotron Super en Hopper.
  • KV Cache: Se corrigió la pérdida de precisión con VSWA y la reutilización de bloques, y la corrupción del contador de bloques libres con la descarga del host.
  • Paralelismo de canalización: Se corrigieron bloqueos con MTP, decodificación guiada y apagado del ejecutor.
  • MoE: Se corrigió un bloqueo de DeepEP causado por la recolección de basura no determinista.
  • Núcleos: Se corrigió la precisión de precisión mixta Qwen2.5, la precisión AllReduce de dos disparos y las salidas NaN GEMM a escala de bloque FP8.
  • Muestreo: Se corrigió que ignore_eos suprimiera el token incorrecto en TorchSampler y los parámetros de muestreo NaN ahora se rechazan.
  • General: Se corrigió la corrupción de búsqueda del haz del codificador-decodificador y errores de falta de memoria con muchos adaptadores LoRA o durante la captación previa del punto de control.

Problemas conocidos

  • Es posible que Kimi-K3 NVFP4 no cargue su tokenizador con la versión de transformadores incluidos.
  • En el servicio desagregado con decodificación especulativa DSpark, el borrador de caché KV no se transfiere al trabajador de generación, lo que reduce la tasa de aceptación. La porción agregada no se ve afectada.
  • GLM-5.2 NVFP4 en GB200 (TP=8, atención DP deshabilitada) puede fallar durante el calentamiento cuando max_num_tokens es mayor que 4096. Mantenga max_num_tokens en 4096 o menos.
  • La entrega desagregada de Nemotron-3-Super-120B-A12B FP8 en B300 puede fallar cuando la simultaneidad excede el tamaño máximo de lote.
  • La publicación desagregada de Qwen3-32B-FP8 en B300 puede producir resultados incorrectos.
  • El terminal /v1/responses tiene lagunas de compatibilidad con algunos formatos de entrada, transmisión de eventos, continuación de conversaciones y llamadas de herramientas (Qwen3, GPT-OSS).
  • Los modelos de codificador-decodificador con caché KV FP8 pueden desbordar el grupo de caché KV de atención cruzada, lo que provoca un acceso ilegal a la memoria o una salida incorrecta.
  • Qwen3-32B con TP=4 en AWS p4d (A100) puede fallar durante el calentamiento del autotuner cuando el complemento aws-ofi-nccl está habilitado.

TensorRT-LLM v1.3.0

Highlights

  • Breaking — PyTorch-only backend and removed APIs (plan a migration, not a drop-in upgrade) — v1.3.0 deletes the TensorRT backend entirely: PyTorch is the only backend, and trtllm-build, TrtLlmArgs, BuildConfig, MedusaDecodingConfig, LookaheadDecodingConfig, trtllm-bench build and trtllm-bench --engine_dir are gone. Also removed: the legacy C++ Executor/runtime/batch-manager APIs and cpp_only build; TensorRT-engine Triton backend models (only the llmapi model remains); TRTLLMSampler in favor of TorchSampler (requires FlashInfer, sampler_type ignored with a warning, disable_flashinfer_sampling removed); two-model speculative decoding (eagle3_one_model, mtp_eagle_one_model); and AutoDeploy, Star Attention and the WIDEEP MoE backend. Anyone on the C++ executor, prebuilt TensorRT engines, or two-model speculation must port before upgrading — start with legacy/tensorrt-backend-removal.md.

  • Breaking — quiet default and behavior changes that can silently alter serving — Explicit CLI flags for trtllm-serve/trtllm-eval/trtllm-bench now override YAML config; KV cache transfers gain a 60s default timeout (cache_transceiver_config.kv_transfer_timeout_ms); per-request chat templates are opt-in via --allow_request_chat_template; logprobs/prompt_logprobs above 100 raise ValueError; /perf_metrics is replaced by the X-TRTLLM-return-metrics: 1 header; and dynamic speculation fields become acceptance_rate_window_size / acceptance_rate_threshold (threshold now a rate in [0,1]). NVFP4 cold-page compression stays off by default, but when enabled for DeepSeek-V4 it changes RoPE to 2FP4 (nvfp4_residual_dim=64) — use skip_rope_quantization=True or nvfp4_residual_dim=0 to restore prior precision. Audit these even if you skip the big backend migration.

  • New models and hardware — the main reason to upgrade — Adds preview Rubin (SM107) support validated on Vera Rubin, with DeepSeek-V4 and Kimi K3 there and on Blackwell (Kimi K3 multimodal/multi-node; DEP16 needs GB300-class memory), plus Qwen3.5 (Hopper/Blackwell/Rubin, MTP and NVFP4 on Blackwell), Qwen3.6, Qwen3.8-Flash-Next, MiniMax-M3, GLM-5/5.2, Gemma 4, Nemotron Nano Omni and Laguna, and prefix caching for Mamba hybrids like Qwen3.5 and Nemotron Super V3. Worth it if these models or Vera Rubin are your targets; skip if you're stable on current Hopper models.

  • Serving and performance — substantial throughput/feature gains for those who stay current — New Anthropic Messages API (/v1/messages), extended Responses API, gRPC server, multi-process HTTP frontends, Prometheus metrics, /start_profile//stop_profile, /v1/embeddings and llm.encode(), trtllm-serve flags --served_model_name/--kv_cache_dtype/--middleware, per-request priority and named-function tool_choice. Internally: KV Cache Manager V2 on by default for most families, prefix-aware scheduling on by default, async preprocessing/sync-free beam search, model-specific kernel fusions, new MoE backends (DENSEGEMM, MEGAMOE_DEEPGEMM, MEGAMOE_CUTEDSL, Rubin-only CUTEDSL_FC12, MARLIN, NCCL-EP) up to 2048 experts, return_routed_experts for RL, and Rubin NVFP4 locality domains on by default (DISABLE_LOCALITY_DOMAINS=1 to opt out).

  • VisualGen and infrastructure — big surface expansion with a heavy dependency shift (check your environment) — Introduces VisualGen for image/video generation via trtllm-serve (FLUX.1/2, GLM-Image, Qwen-Image, Wan 2.2, LTX-2, HunyuanVideo 1.5, Cosmos3, MiniMax-H3), with trtllm-eval support; caveat: statically quantized FLUX.1 checkpoints from NVIDIA Model Optimizer may fail to initialize (out_channels null). Platform changes are broad: base images nvcr.io/nvidia/pytorch:26.09-py3 and nvcr.io/nvidia/tritonserver:26.09-py3, CUDA 13.4.1, PyTorch 2.14.0, transformers 5.5.4, C++20, two wheel sets (PyPI upstream vs pypi.nvidia.com/trtllm_ngcpytorch/ for NGC), and TensorRT, ModelOpt and ONNX dropped as dependencies. The TRITON MoE backend (TritonFusedMoE, moe_config.backend="TRITON") is deprecated with removal after 3 months. If you depend on those removed deps or the old container flavor, budget environment work; otherwise this is a strong upgrade.

Key Features and Enhancements

  • Rubin Support (Preview)

    • Added preview support for NVIDIA Rubin (SM107), validated on Vera Rubin.
    • Added DeepSeek-V4 and Kimi K3 support on Vera Rubin.

  • Model Support

    • Added DeepSeek-V4 support on Blackwell and Rubin (preview).
    • Added Kimi K3 support on Blackwell and Rubin (preview), including multimodal and multi-node serving. Attention data parallelism (DEP16) requires GB300-class GPU memory.
    • Added Qwen3.5 support on Hopper, Blackwell and Rubin (preview), including MTP and NVFP4 on Blackwell, and Qwen3.6 and Qwen3.8-Flash-Next support on Blackwell.
    • Added MiniMax-M3 support on Blackwell and Rubin (preview).
    • Added GLM-5, GLM-5.2, Kimi-K2.5 and Step-3.7-Flash support on Blackwell.
    • Added Nemotron Nano Omni support on Hopper and Blackwell.
    • Added Gemma 4 support on Blackwell, including multimodal.
    • Added Laguna support on Hopper and Blackwell.
    • Added prefix caching for Mamba hybrid models, such as Qwen3.5 and Nemotron Super V3.

  • Features

    • Performance:
      • Optimized DeepSeek-V4, DeepSeek-V3.2, Qwen3.5, Gemma 4, MiniMax-M3 and Kimi K3 with model-specific kernel fusions.
      • Added locality domain (uGPU) localization for NVFP4 MoE on Rubin, which keeps memory traffic local to each GPU die. It is enabled by default; set DISABLE_LOCALITY_DOMAINS=1 to disable it.
      • Reduced host overhead with async preprocessing and sync-free beam search, and reduced startup time with checkpoint read-ahead.
      • Added cascade attention and low-M BF16 GEMM dispatch for SM10x.
    • Disaggregated Serving:
      • Added gen-first scheduling, conversation affinity routing, beam search and hybrid model support.
      • Added disaggregated serving for Qwen3.8-Flash-Next.
    • Speculative Decoding:
      • Added DSpark, DFlash, Suffix Automaton and PARD drafters.
      • Added EAGLE3 dynamic trees, Eagle 3.1 draft models and speculative decoding with LoRA.
      • Added rejection sampling for one-model paths and acceptance-rate-based auto-disable for dynamic speculation.
      • Added loading MTP weights from standalone checkpoints.
    • Parallelism and MoE:
      • Added DWDP (Distributed Weight Data Parallelism), extended Helix context parallelism, and a KV cache-aware attention-DP router.
      • Added the DENSEGEMM, MEGAMOE_DEEPGEMM, MEGAMOE_CUTEDSL, CUTEDSL_FC12 (Rubin only) and MARLIN MoE backends.
      • Added an NCCL-EP backend and support for up to 2048 experts.
      • Added Router Replay (return_routed_experts) to return per-token MoE routing for RL training.
    • KV Cache:
      • KV Cache Manager V2 is selected per model and enabled by default for most model families.
      • Added KV cache compression (TriAttention and NVFP4 cold-page compression), NVFP4 KV cache and disk cache.
      • Added per-conversation block reuse and exact multimodal KV block hashing.
      • Added FlexKV and LMCache connectors.
    • Quantization:
      • Added MXFP8 (W8A8) linear and MoE support, including MXFP8 checkpoints such as MiniMax-M3.
      • Added W4A16 NVFP4 weight-only quantization through Marlin, so NVFP4 checkpoints run on Hopper and Ada Lovelace.
      • Added tunable NVFP4 quantization.
      • Added support for both legacy and ModelOpt 1.x quantization config formats.
    • Sparse Attention: Added DSA FP4/FP8 decode kernels, GVR Top-K, Skip Softmax Attention (with optional 2:4 activation sparsity on Rubin) and MiniMax-M3 MSA.
    • Serving and APIs:
      • Added the Anthropic Messages API (/v1/messages) and extended the Responses API.
      • Added a gRPC server and multi-process HTTP frontends.
      • Added per-request priority and named-function tool_choice to the OpenAI-compatible APIs.
      • Added auto tool and reasoning parser selection, and GLM-4.7, GLM-5 and Laguna tool parsers.
      • Added Prometheus metrics and /start_profile and /stop_profile profiling endpoints.
      • Added trtllm-serve options --served_model_name, --kv_cache_dtype and --middleware.
      • Added Completions API logprobs and acceptance of parallel_tool_calls.
    • Sampling and LoRA:
      • Added min_p, bad_words, repetition/frequency/presence penalties, full beam search options and processed logprobs to TorchSampler.
      • Added an experimental thinking_token_budget for reasoning models.
      • Added multi-LoRA serving with CUDA graphs, per-expert MoE LoRA and dense FP8 LoRA.
    • Others:
      • Added prefix-aware scheduling, enabled by default, to avoid duplicate prefill of shared prefixes.
      • Added prefill and breakable CUDA Graph support, and custom attention masks in the TRTLLM attention backend.
      • Added a multimodal encoder cache and CUDA graphs for multimodal encoders.
      • Added inflight weight updates for RL workflows.
      • Added /v1/embeddings and an llm.encode() fast path for encoder-only models.
      • Added prototype ModelExpress checkpoint loading.

  • Documentation

    • Migration Guide: Added the TensorRT Backend Removed migration guide.
    • Deployment Guides: Added deployment guides for GLM-5, Kimi K3, MiniMax-M3, Nemotron 3, Qwen3.8-Flash-Next and Qwen3.8/Qwen3.5.
    • Feature Documentation: Added guides for KV cache compression, embeddings, ModelExpress, sub-agent routing and encoder-decoder models, and restructured the installation guide.
    • Developer Guides: Added guides for sparse attention, KV cache compression, telemetry and custom kernels.
    • Tech Blogs: Published blogs on:

VisualGen

VisualGen is a new vertical solution in TensorRT-LLM for image and video generation models. It is served through trtllm-serve alongside LLM inference. See the VisualGen documentation for details.

  • Models
    • Added image generation models: FLUX.1, FLUX.2, GLM-Image and Qwen-Image, including Qwen-Image-Edit and Qwen-Image-Layered.
    • Added video generation models: Wan 2.2 (including 5B TI2V and FastWan), LTX-2, HunyuanVideo 1.5, Cosmos3 and MiniMax-H3.
  • Features
    • Added image generation, image editing and video generation endpoints in trtllm-serve.
    • Added tensor, context and CFG parallelism, NVFP4 and FP8 quantization, CUDA graphs and runtime LoRA.
    • Added TeaCache and Cache-DiT caching, sparse attention, and FlashAttention 4, FlashInfer and cuDNN attention backends.
    • Added a trtllm-eval pipeline for VisualGen models.
  • Documentation
    • VisualGen examples
    • Published tech blogs on:
      • "Scaling Video Generation Across NVL72 rack with TensorRT-LLM"

API Changes

  • <span style="color: red">[BREAKING CHANGE] TensorRT backend removed.</span> PyTorch is the only backend. trtllm-build, TrtLlmArgs, BuildConfig, MedusaDecodingConfig, LookaheadDecodingConfig, trtllm-bench build and trtllm-bench --engine_dir are removed. See the migration guide.
  • <span style="color: red">[BREAKING CHANGE] Legacy C++ Executor and runtime APIs removed.</span> The C++ Executor API, the legacy runtime and batch-manager APIs, and the cpp_only build option are removed.
  • <span style="color: red">[BREAKING CHANGE] TensorRT-engine Triton backend models removed.</span> Only the llmapi Triton model remains.
  • <span style="color: red">[BREAKING CHANGE] TRTLLMSampler removed.</span> TorchSampler, which requires FlashInfer, is the only sampler. The sampler_type argument is ignored with a warning, and disable_flashinfer_sampling is removed.
  • <span style="color: red">[BREAKING CHANGE] Two-model speculative decoding removed.</span> The eagle3_one_model and mtp_eagle_one_model fields are removed; use the one-model implementations.
  • <span style="color: red">[BREAKING CHANGE] AutoDeploy, Star Attention and WIDEEP removed.</span> AutoDeploy and Star Attention are removed, and the WIDEEP MoE backend can no longer be selected.
  • <span style="color: red">[BREAKING CHANGE] CLI flags override YAML config.</span> Explicit trtllm-serve, trtllm-eval and trtllm-bench flags now take precedence over YAML config values.
  • <span style="color: red">[BREAKING CHANGE] KV cache transfer timeout defaults to 60 seconds.</span> Previously there was no timeout; set it with cache_transceiver_config.kv_transfer_timeout_ms.
  • <span style="color: red">[BREAKING CHANGE] Per-request chat templates are opt-in.</span> Enable them with trtllm-serve --allow_request_chat_template.
  • <span style="color: red">[BREAKING CHANGE] Logprobs capped at 100.</span> Larger logprobs or prompt_logprobs values raise a ValueError.
  • <span style="color: red">[BREAKING CHANGE] /perf_metrics endpoint removed.</span> Use the X-TRTLLM-return-metrics: 1 request header instead.
  • <span style="color: red">[BREAKING CHANGE] Dynamic speculation fields renamed.</span> Use acceptance_rate_window_size and acceptance_rate_threshold; the threshold is now an acceptance rate in [0, 1].
  • <span style="color: red">[BREAKING CHANGE] Obsolete options removed.</span> This includes Eagle choices and trtllm-serve --fail_fast_on_attention_window_too_large.
  • NVFP4 cold-page compression remains opt-in and disabled by default. When enabled for DeepSeek-V4, NoPE uses NVFP4 and RoPE now defaults to 2FP4 (nvfp4_residual_dim=64). Set skip_rope_quantization=True to keep RoPE at its original precision, as before, or nvfp4_residual_dim=0 to use single NVFP4. The active GPU KV-cache dtype is unchanged. See the NVFP4 cold-page compression example.
  • [DEPRECATION] The TRITON MoE backend (TritonFusedMoE, moe_config.backend="TRITON") is deprecated as of TensorRT-LLM 1.3 (2026-09) and will be removed after the 3-month migration period. Its only remaining role is a modest performance edge for GPT-OSS on Hopper with W4A16_MXFP4 — the single configuration AUTO resolves to TRITON, and the format an MXFP4 GPT-OSS checkpoint takes on SM90. As the model set and the supported platforms keep growing, a single-scenario MoE path is no longer worth its maintenance cost. moe_config.backend="CUTLASS" replaces it functionally on Hopper: it serves W4A16_MXFP4 on SM90 along with the unquantized BF16 and FP8 per-tensor paths, and MoE backend resolution already degrades to it automatically when TRITON declines a layer. During the migration period TRITON keeps working and logs a one-time warning. See the deprecation policy.
  • [DEPRECATION] The trtllm-serve options --backend, --moe_cluster_parallel_size and --metrics-log-interval, and the trtllm-eval option --backend, are deprecated.
  • [DEPRECATION] TorchCompileConfig.enable_piecewise_cuda_graph and capture_num_tokens, MTPDecodingConfig.num_nextn_predict_layers, and perf_metrics_max_requests are deprecated.
  • [DEPRECATION] Disaggregated serving without internal_request_auth_key is deprecated. Set the same key in the disaggregated server config and every worker config.
  • Usage telemetry is on by default. To opt out, set TRTLLM_NO_USAGE_STATS=1 or DO_NOT_TRACK=1, pass --no-telemetry to the CLI, or set telemetry_config=TelemetryConfig(disabled=True) in the LLM API. See the telemetry guide.
  • GPT-OSS defaults to the TRTLLM MoE backend on Blackwell.
  • TorchCompileConfig.max_num_streams now defaults to 3 instead of 1.

Fixed Issues

  • Disaggregated Serving:
    • Fixed a hang with context pipeline parallelism and generation tensor parallelism, a known issue in 1.2.
    • Fixed hangs with block reuse after eviction and gen-only asynchronous KV transfer.
    • Fixed an error on one rank crashing all generation ranks.
  • Attention:
    • Fixed an illegal memory access when max_seq_len exceeds max_position_embeddings.
    • Fixed an XQA race condition, attention sink accuracy and a sliding window illegal memory access.
    • Fixed FP8 accuracy with Skip Softmax Attention.
    • Fixed a DeepSeek-V3.2 illegal memory access with CUDA graphs and host KV cache offload.
  • Speculative Decoding: Fixed EAGLE3 crashes on Qwen3-235B-A22B NVFP4 and MTP crashes on Nemotron Super on Hopper.
  • KV Cache: Fixed accuracy loss with VSWA and block reuse, and free-block counter corruption with host offload.
  • Pipeline Parallelism: Fixed hangs with MTP, guided decoding and executor shutdown.
  • MoE: Fixed a DeepEP hang caused by non-deterministic garbage collection.
  • Kernels: Fixed Qwen2.5 mixed-precision accuracy, two-shot AllReduce accuracy and FP8 block-scale GEMM NaN outputs.
  • Sampling: Fixed ignore_eos suppressing the wrong token in TorchSampler, and NaN sampling parameters are now rejected.
  • General: Fixed encoder-decoder beam search corruption and out-of-memory errors with many LoRA adapters or during checkpoint prefetch.

Known Issues

  • Kimi-K3 NVFP4 may fail to load its tokenizer with the bundled transformers version.
  • In disaggregated serving with DSpark speculative decoding, the draft KV cache is not transferred to the generation worker, which lowers the acceptance rate. Aggregated serving is not affected.
  • GLM-5.2 NVFP4 on GB200 (TP=8, attention DP disabled) may segfault during warmup when max_num_tokens is greater than 4096. Keep max_num_tokens at 4096 or lower.
  • Disaggregated serving of Nemotron-3-Super-120B-A12B FP8 on B300 may fail when concurrency exceeds the maximum batch size.
  • Disaggregated serving of Qwen3-32B-FP8 on B300 may produce incorrect output.
  • The /v1/responses endpoint has compatibility gaps with some input formats, streaming events, conversation continuation and tool calls (Qwen3, GPT-OSS).
  • Encoder-decoder models with an FP8 KV cache can overrun the cross-attention KV cache pool, causing an illegal memory access or incorrect output.
  • Qwen3-32B with TP=4 on AWS p4d (A100) may segfault during autotuner warmup when the aws-ofi-nccl plugin is enabled.
