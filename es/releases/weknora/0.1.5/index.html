WeKnora v0.1.5

Descripción general

  • Esta fusión incluye varias mejoras funcionales, mejoras de UI/UX, correcciones de seguridad y corrección de errores, que cubren módulos como servicios back-end, interfaces front-end, creación de imágenes y scripts de implementación.
  • Objetivos principales: soporte de base de conocimientos múltiples, mejora de inquilinos/cuentas, optimización del proceso de inicialización, mejoras de experiencia y seguridad front-end, y mejoras de solidez de los scripts DevOps y las compilaciones de imágenes Docker. Reflejos
  • La base de conocimientos múltiples admite la optimización de la recuperación con múltiples fuentes de datos (mejora colaborativa de front-end y back-end).
  • Se han mejorado la página de información del inquilino y las funciones de administración de claves API (incluida la generación de claves API y la interacción de copia).
  • Se optimiza la estructura del asistente de inicialización y se agrega una verificación más completa y una verificación de configuración multimodal (VLM).
  • Mejoras de seguridad en el front-end: corrige XSS, oculta información confidencial como la clave API en la interfaz de usuario.
  • Docker/CI: script de creación de imágenes mejorado y detección multiplataforma, inyección de información de compilación mejorada (VERSIÓN/COMMIT/BUILD_TIME/GO_VERSION). Funciones y mejoras
  • Se agregó soporte y administración de operaciones de múltiples bases de conocimiento (UI y lógica de back-end).
  • Gestión de información de inquilinos mejorada, página de inquilinos agregada y visualización de uso y cuota de almacenamiento más amigable (consulte TenantInfo.vue).
  • Mejoras en el asistente de inicialización: validación de formularios más estricta, validación de URL compatible con VLM/OpenAI y vista previa y validación de carga de archivos multimodal (consulte InitializationContent.vue).
  • Backend: Lógica de actualización y generación automática de claves API (ver tipos.Tenant y tenantService.UpdateTenant). interfaz de usuario/experiencia de usuario
  • Reconstruya la página de configuración y el diseño de la página de inicialización, optimice el estado de los botones, la carga y la información solicitada, y mejore la experiencia de carga/vista previa.
  • Mejora del componente del menú: lógica de verificación y cambio de múltiples bases de conocimientos antes de cargar (ver menu.vue).
  • Ocultar/proteger información confidencial (como la clave API) y agregar mensajes de interacción de copia (consulte TenantInfo.vue). Correcciones de seguridad
  • Corrija posibles vulnerabilidades XSS en el front-end y mejore la validación de entradas y las políticas de seguridad del contenido.
  • La interfaz de usuario oculta la clave API y mejora las indicaciones de comportamiento de copia para mejorar la protección contra fugas de información. correcciones de errores
  • Se corrigieron problemas relacionados con la compatibilidad con OCR/AVX y errores de simultaneidad en el análisis de imágenes.
  • Se corrigieron problemas de enrutamiento/salto de inicio de sesión del front-end y errores de contenido de descarga de archivos.
  • Se solucionaron problemas con la verificación del estado del servicio Docker y la captación previa del modelo. DevOps/compilación
  • Mejore el script de creación de imágenes, mejore la detección de plataforma/arquitectura (amd64/arm64) e inyecte información de la versión durante la compilación (consulte get_version.sh y build_images.sh).
  • Se han mejorado el Makefile y el proceso de compilación para facilitar la inyección de CI de LDFLAGS (consulte Makefile).
  • Se mejoró el uso y la documentación de la herramienta de migración y script (migrate) (consulte migrar.sh). Documentación
  • README actualizado y documentación en varios idiomas (EN/CN/JA) y versión/CHANGELOG (consulte CHANGELOG.md y README.md para obtener más detalles).
  • Instrucciones de uso e instalación del servidor MCP complementadas (consulte mcp-server/INSTALL.md). Cambios internos/de desarrollador en API (referencia disponible)
  • Se agregó/cambió la estructura de respuesta de información del sistema backend: handler.GetSystemInfoResponse.
  • Estructura de datos del inquilino con campo de almacenamiento JSON: tipos.Inquilino.

WeKnora v0.1.5

Highlights

  • Multi-knowledgebase and multi-source search — v0.1.5 makes multi-knowledgebase operations first-class (#321) and adds configurable multi-data-source search (#319), with the menu component now handling KB switching and pre-upload validation. This is the headline capability shift: integrations that assumed a single KB should revisit their query and ingest paths. The MCP server also gains file-based knowledge creation (#361), which is useful for automated ingestion pipelines.
  • Tenant info and API key lifecycle — A new tenant info page surfaces storage quota and utilization (#312), and the backend now auto-generates and rotates tenant API keys via types.Tenant and tenantService.UpdateTenant. Keys are masked in the UI with a copy affordance. Watch out: any automation or internal docs that relied on reading a plaintext key from the settings screen need updating.
  • Stricter initialization and VLM validation — The setup wizard now enforces stricter form validation, validates VLM/OpenAI-compatible endpoint URLs, and previews/validates multimodal uploads (InitializationContent.vue); App LLM model checks were also revised (#322). Upgrade note: endpoint or model configurations previously tolerated on first run may now be rejected — verify your VLM URL before rolling out.
  • Frontend security hardening — Fixes an XSS in the "thinking" render path (#308) and a CSP error (#311), alongside broader input validation and masking of sensitive values. Editorially: if you fed custom HTML/Markdown into model output or reasoning views, expect it to be escaped or sanitized now — test any rich-content flows against this build.
  • API behavior changes to watch — A new URL-duplication error type introduces 409 Conflict handling (#339), and internal shapes changed in handler.GetSystemInfoResponse and types.Tenant JSON fields. Clients parsing system-info or tenant payloads should be revalidated, and callers should handle 409 on duplicate URL creation. The PostgreSQL image also moved to v0.18.9-pg17 (#365), so plan a DB compatibility and backup check on redeploy.
  • Build and deployment — Docker scripts now detect amd64/arm64 and inject VERSION / COMMIT / BUILD_TIME / GO_VERSION via get_version.sh and build_images.sh, with an LDFLAGS-friendly Makefile (#326, #330, #332, #335). This yields reproducible, traceable multi-arch images worth adopting in CI. Separately, a [WIP] knowledge-extraction and graph-database feature landed (#343) — treat it as experimental and do not depend on it in production.

No formally declared breaking changes in this release.

概述

  • 本次合并包含若干功能增强、UI/UX 改进、安全修复与错误修复，覆盖后端服务、前端界面、镜像构建和部署脚本等模块。
  • 主要目标：多知识库支持、租户/账户增强、初始化流程优化、前端安全与体验改进，以及 DevOps 脚本和 Docker 镜像构建的健壮性提升。

Highlights

  • Multi-knowledgebase 支持与多数据源检索优化（前端与后端协同改进）。
  • 租户信息页与 API Key 管理功能增强（包括 API Key 生成与复制交互）。
  • 初始化向导（Initialization）结构优化并加入更完善的验证与多模态（VLM）配置校验。
  • 前端安全改进：修复 XSS、隐藏 UI 中的 API Key 等敏感信息。
  • Docker / CI：改进镜像构建脚本与跨平台检测，增强构建信息注入（VERSION / COMMIT / BUILD_TIME / GO_VERSION）。

功能与增强

  • 新增多知识库（Multi-knowledgebases）操作支持与管理（UI 与后端逻辑）。
  • 增强租户信息管理，新增租户页面与更友好的存储配额、使用率展示（参见 TenantInfo.vue）。
  • 初始化向导改进：更严格的表单验证、VLM/OpenAI 兼容 URL 校验及多模态文件上传预览与校验（参见 InitializationContent.vue）。
  • 后端：API Key 自动生成与更新逻辑（见 types.Tenant 与 tenantService.UpdateTenant）。

UI / UX

  • 重构设置页与初始化页面布局，优化按钮状态、加载与提示信息，上传/预览体验改进。
  • 菜单组件增强：多知识库切换与上传前校验逻辑（参见 menu.vue）。
  • 隐藏/保护敏感信息（例如 API Key）并增加复制交互提示（参见 TenantInfo.vue）。

安全修复

  • 修复前端潜在 XSS 漏洞并增强输入校验与内容安全策略。
  • UI 隐藏 API Key 并改进复制行为提示，提升信息泄露防护。

错误修复

  • 修复 OCR/AVX 支持相关问题与图像解析并发错误。
  • 修复前端路由/登录跳转问题与文件下载内容错误。
  • 修复 docreader 服务健康检查与模型预取问题。

DevOps / 构建

  • 改进镜像构建脚本，增强平台/架构检测（amd64 / arm64），并在构建时注入版本信息（见 get_version.sh 与 build_images.sh）。
  • Makefile 与构建流程完善，便于 CI 注入 LDFLAGS（参见 Makefile）。
  • 脚本与迁移工具（migrate）使用和文档完善（参见 migrate.sh）。

文档

  • 更新 README 与多语言文档（EN/CN/JA）与 release/CHANGELOG（详见 CHANGELOG.md 与 README.md）。
  • 补充 MCP server 使用说明与安装（见 mcp-server/INSTALL.md）。

开发者/内部 API 变更（可参考）

  • 新增/变更后端系统信息响应结构：handler.GetSystemInfoResponse。
  • 租户数据结构与 JSON 存储字段：types.Tenant。
