WeKnora v0.6.1

Highlights

  • CLI wire contract is breaking — rewrite your automation — PR #1475 ships the feat(cli)! v0.7 agent-first wire contract and command-surface cleanup; the ! is real: shell scripts and CI jobs driving the old command syntax will fail after upgrade and need to be re-cut against the new contract. Follow-up PR #1510 adds --dry-run, MCP annotations, and session continue-stream, so validate pipelines in dry-run mode before cutting over. This is the one item in v0.6.1 that demands migration planning rather than a drop-in bump.
  • OpenSearch becomes a first-class vector backend — a deliberate four-PR rollout: prep (#1445), gated skeleton (#1481), read/write paths (#1482), and finally the activated k-NN driver (#1542). If you were waiting for a self-hostable alternative to Milvus/Qdrant/ES/Doris, this is it. Pair it with #1608 (Milvus database selection) and note #1611 now rejects cross-store reuse_vectors knowledge moves — plan to re-embed, not relocate, when switching stores.
  • Built-in models move to declarative config-as-code — #1453 introduces YAML-based model definitions with ${ENV} interpolation (keep API keys out of committed YAML), and #1483 adds lifecycle semantics: delete, resurrect, and a default-invariant guard. A new display_name column (#1547) and native Gemini embeddings (#1571) land alongside it, plus MiniMax-M3 (#1569) and per-model thinking-mode configuration (#1613). Run migrations before deploying, and treat the default invariant as a guardrail against accidentally deleting your fallback model.
  • Platform ops and multi-tenant security get serious — #1493 delivers a unified system administration console with a platform audit log, and #1504 adds multi-use share-link invitations for invite_only mode (no more per-user account provisioning for closed deployments). Security-relevant if you expose endpoint configuration to tenants: #1596 validates vector-store connection addresses against an SSRF policy, and #1581 adds panic recovery to async goroutines so a single bad event can't take down a worker.
  • Retrieval and ingestion are hardened against silent failures — #1484 falls back to raw retrieval results when the rerank API fails (no more empty answers on a flaky reranker), and #1555 stitches chunks by text overlap rather than position, which fixes quality regressions on reordered/out-of-sequence chunks. On the ingestion side: cancellable parsing with a finalizing state (#1522) and a stop-parse control in the trace timeline (#1549), reliable finalizing counters (#1552), and inline image payloads scrubbed before embedding (#1536, #1546). Expect fewer "stuck at 99%" documents and more observable parse state.
  • API and MCP surface changes worth a client audit — /knowledge/search now accepts a ?query= alias but rejects empty keywords (#1612), so clients that relied on empty-keyword "list all" behavior will break. MCP gains read-only wiki tools via the Python server (#1502) and multi-transport support with restored session configuration (#1490); Doris now inlines LIMIT/OFFSET literals with parameter interpolation (#1488), and Elasticsearch search excludes the embedding field to cut response payloads (#1433). Check any direct API consumers against #1612 specifically.
