WeKnora v0.6.0

Highlights

  • Multi-tenant RBAC is now enforced end-to-end — PR #1367 adds the schema, enforcement, member management, ownership transfer, and an audit log (tracking #1303); #1385 exposes tenant RBAC and a per-user tenant cap as env knobs, and #1406 mirrors cross-tenant superuser Admin into the UI gates. This is the release's biggest architectural shift: teams moving off a single shared workspace must seed roles/memberships and re-audit API calls, because enforcement is config-driven and previously-open cross-tenant operations can now be denied. A Chinese RBAC guide is linked in #1421.

  • Retrieval becomes KB-scoped and fans out across vector stores — #1310 introduces a factory for KB-scoped retrieve-engine resolution, #1386 fans queries out to every vector store bound to a KB, and #1372 validates those bindings on create/copy/delete. Practical impact: one KB can now span multiple backends, so result sets may include hits you never got before, and misbound stores fail at write time instead of silently at query time. Watch ranking/duplicate behavior when a KB binds more than one store.

  • Docreader gRPC is locked down — a breaking deployment change — #1308 stops publishing the docreader gRPC port to the host, while #1359/#1361 add auth with a hardened TLS/token rollout, and #1363 raises the grpcio floor to 1.78.0 to match regenerated protos. If you reached docreader via the host-published port, that path is gone — move to in-network discovery and configure TLS/token credentials. Python clients must upgrade to grpcio ≥1.78.0 or generation-mismatch errors will surface.

  • CLI jumps from v0.3 to v0.6 in one release — #1315, #1342, #1354, and #1368 add an extended management surface and session subtree, a hardened output contract with mainstream alignment, agent CRUD plus a chunk subtree with audit-driven cleanup, and doc-wait/status/multi-id delete. The output contract is deliberately hardened in v0.4 and again in v0.6, so any scripts parsing CLI stdout should be re-validated — field shapes and naming were intentionally normalized.

  • Credentials gain a first-class API and encryption; new backends arrive — #1364 moves credentials to a /credentials subresource with at-rest encryption and test-connection UX, while #990 redacts sensitive fields and prevents credential loss on edit. New integrations: a Zhipu AI embedder (#1365/#1366), Huawei Cloud OBS storage (#1377), and configurable Doris compatibility modes with guarded switches (#1395). Clients using the old inline credential fields will need to migrate to the subresource.

  • Upgrade hygiene: Go 1.26, migration fixes, and a cleaner API error contract — #1407 bumps go.mod to Go 1.26.0; #1334 creates pg_trgm before the trigram index in migration 000041 (fixing failed upgrades on fresh databases), and #1335 surfaces migration errors with troubleshooting links. #1336/#1339 map ErrSessionNotFound and ErrKnowledgeBaseNotFound to 404 across handlers, so consumers can finally rely on 404 semantics — update code that keyed off the old 200/500 behavior. #1384 unifies DISABLE_REGISTRATION with auth.registration_mode, so reconcile your config keys on upgrade.
