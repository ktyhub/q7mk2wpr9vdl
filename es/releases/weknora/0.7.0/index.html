WeKnora v0.7.0

Highlights

  • Security hardening is the upgrade priority — Fixes close an agent SQL-validator bypass (#1881), KB/wiki authorization and IDOR paths (#1882), and SSRF exposure in embedders, imports, web_fetch, connectors, and DingTalk downloads (#1828, #1883, #1982). Refresh tokens are rejected as bearer tokens, MCP uploads are sandboxed, and integration credentials are redacted from viewer/IM endpoints (#1890, #1884, #1897). Self-hosted integrations relying on permissive URL or credential access should be retested.

  • Scoped agents and resumable MCP OAuth — @Skill/@MCP mentions now run within a scoped agent runtime (#1841). MCP authentication follows AuthType, auto-detects OAuth during connection tests, supports authorization prompts and resumption mid-conversation, scopes OAuth by principal, and adds per-agent wait timeouts (#1844, #1845, #1847, #1863). This improves tool isolation and reduces setup friction; validate consent behavior and timeouts for long-running flows.

  • Workspace-scoped access and storage — Scoped tenant API keys now cover full KB lifecycle routes plus FAQ-import and KB-copy progress polling (#1922, #2022, #2068, #2070). Workspaces can configure multiple storage backend instances (#2072), while tenantless/self-service provisioning and OIDC onboarding converge on a shared default_tenant_mode policy (#2037, #2038). Review key scopes, storage mappings, and provisioning policy before rollout.

  • Runtime queues become easier to operate and scale — Claim-based wiki batching (#1979), per-pool asynq governance with shared elastic capacity (#2030), and per-model background LLM limits (#1986) address throughput and resource contention. Configuration files now set WEKNORA_MODEL_MAX_CONCURRENCY=32 (#1995). The runtime dashboard adds task inspection, manual retry, cursor pagination, and model concurrency statistics (#2001, #2049, #2056); tune the cap for your infrastructure rather than assuming 32 is universally safe.

  • Knowledge retrieval and ingestion behavior changes — Tag filters now apply to knowledge search, with hardened scope resolution (#1907, #1952), so previously unfiltered queries may return different results. Per-pipeline custom instructions (#2026) and corrected chunking-strategy propagation to parent/child splitters (#2048) make processing more configurable; regression-test tagged retrieval and existing pipelines. QQBot support (#1824) and DingTalk file/image ingestion (#1969) also broaden input channels.

  • CLI changes are breaking — #1741 and #1917 are explicitly marked breaking: chat and session ask gain agent-first output modes, alongside broader v0.10 command-surface hardening. Scripts that parse CLI output should migrate to the new modes and retest streaming/error handling, which was realigned in #1903.
