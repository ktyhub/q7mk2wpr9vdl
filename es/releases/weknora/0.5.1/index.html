WeKnora v0.5.1

Highlights

  • Agent and IM execution — Agent model calls now have a dedicated timeout, while the pipeline-level timeout that aborted multi-round reasoning is removed (#1059, #1070). IM sessions are isolated per agent and recover after deletion (#1069), and private-storage links in replies are rewritten as HTTP URLs for IM delivery (#1068). Long-running reasoning can now finish without leaving individual LLM calls unbounded.

  • Document ingestion and long-file handling — Wiki Lite ingestion gains locking, failed-operation requeue, and consistent sync retries (#1064), while standalone image uploads are no longer incorrectly filtered out (#1076). DOCX parsing no longer has the default 100-page ceiling (#1071), so long documents ingest fully—but may require more processing time and memory.

  • Retrieval and analytics correctness — Reranking priority is aligned between Execute and rerankResults (#1067), reducing path-dependent result ordering, and broad-query fallbacks now receive the knowledge-base document listing (#1072). Data-analysis SQL gains validation and type processing (#1053), helping malformed or type-sensitive queries surface earlier; recheck custom ranking assumptions after upgrading.

  • Security and encryption failures — Encrypted API-key values (enc:v1:...) are no longer exposed to the UI, and keys can be reset from the API Info page (#1087, #1089). Undecryptable encrypted database fields now fail explicitly rather than being handled silently (#1100); verify encryption keys and existing ciphertext before deployment.

  • Multi-tenant and integration operations — Tenant scanning accepts legacy and current payload formats (#1060), clients can switch tenants (#1085), and a tenant-wide IM channel overview is available under the user menu (#1102). The new WeChat mini-program plugin (#1055) adds another IM entry point; multi-tenant integrations should validate their payloads and channel routing.

  • Breaking changes — None declared.
