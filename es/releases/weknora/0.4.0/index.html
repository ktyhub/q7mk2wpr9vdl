WeKnora v0.4.0

Highlights

  • VectorStore becomes a first-class, API-managed resource — This release turns vector storage from implicit plumbing into a manageable entity: schema/migrations and repository layer (#922), a service layer with connection testing (#933), and CRUD API endpoints plus docs (#934). For adopters this means you can now provision and validate a vector backend through the API instead of editing config and restarting; expect new migrations on upgrade, and use the connection-test path to fail fast on bad credentials before ingesting.
  • Model provider surface expands materially, with timeout control — Azure OpenAI for remote models (#925), Ollama (#930) and Baidu (#944) web-search providers, and a WeKnoraCloud provider covering chat/embedding/rerank with a signed docreader (#927) and credential management/status checks (#961), later extended with VLM support (#974). Combined with customizable LLM call timeout for agent calls (#916), this is the release to adopt if you were blocked on provider lock-in or slow-model hangs — though running two cloud-provider integrations means you should verify which path owns embedding/rerank before cutover.
  • Storage and crypto internals carry the breaking changes — The OSS service was migrated off the AWS S3 SDK onto Alibaba Cloud OSS SDK v2 (#956), with new Alibaba Cloud storage configuration (#949); S3-compatible deployments will need to re-check endpoint, credential, and bucket settings rather than assuming drop-in behavior. Meanwhile CryptoService was replaced by plain AES utilities (#954), so any downstream code calling that service directly must be rewritten — this is a real API break, not just a refactor. On the plus side, MINIO_ENDPOINT is finally environment-configurable (#911), removing a deployment annoyance.
  • Video multimodal landed, then was immediately removed — Video support was added in #926 with a follow-up migration-version conflict fix (000032 → 000033, #937), but the video parser was then removed outright (#966). Net effect: don't build on video ingestion in v0.4.0; the shipping feature set does not include it. The migration renumbering is the part to watch — anyone who applied the original 000032 migration on a pre-release build should verify schema state before upgrading, since two versions claimed the same slot.
  • IM and connector channels get production-oriented hardening — WeChat integration with QR-code login and long-polling (#946) joins a Notion connector (#923) and attachment support (#935); private WeCom deployments can now point at custom endpoints (#955). Notably, <kb> and <web> citation tags are stripped before sending to IM (#947) — a behavioral change that cleans up messages but means downstream consumers relying on those tags for provenance will lose that signal.
  • Desktop/Lite edition and Windows build robustness improve, with a compiler workaround to know about — A Wails-based desktop app plus Lite auto-setup and UI work (#938, #941) gained explicit auto-setup failure handling (#976), and server startup now uses a retry mechanism with platform-specific shutdown signals (#939). For Go 1.24 on Windows, the neo4j driver was first downgraded v6 → v5 (#942) then reverted to v6 with a -p=1 build workaround (#943) — Windows builders should adopt that flag rather than pinning the older driver.
