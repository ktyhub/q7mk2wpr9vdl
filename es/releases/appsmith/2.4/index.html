appsmith v2.4

🗑️ Recordatorio de eliminación de funciones - 30 de septiembre de 2026 - EOL

Appsmith AI llega al final de su vida útil el 30 de septiembre de 2026, tres semanas después de este lanzamiento.

Como se anunció en v2.3, ya no puede agregar nuevas conexiones o consultas de fuentes de datos de Appsmith AI. Cualquiera que tenga actualmente seguirá funcionando hasta el 30 de septiembre de 2026. Después de esa fecha, todas las fuentes de datos de Appsmith AI dejarán de funcionar, ya sea que haya actualizado o no.

Migre cualquier consulta restante de Appsmith AI a una fuente de datos de proveedor directo (OpenAI, Anthropic o Google AI) antes de esa fecha. Esta versión actualiza las listas de modelos disponibles para los tres proveedores, de modo que los modelos actuales estén disponibles para migrar. (#42114)

⚠️ Notas importantes de actualización

  • Secretos de configuración de administrador: los valores confidenciales devueltos por GET /api/v1/admin/env ahora están enmascarados y los campos editables de URL de MongoDB y Redis se reemplazan por estados de conexión de solo lectura. Actualice cualquier script o automatización que lea esos valores desde el administrador API. El envío de un valor enmascarado se trata como "sin cambios", por lo que se conserva la configuración existente. (#42169)
  • Respuestas de fuentes de datos de IA: las fuentes de datos de IA de OpenAI, Anthropic y Google ahora enumeran los modelos actuales. Las consultas antrópicas guardadas que utilizan ID de modelos modernos ingresados ​​manualmente pueden requerir actualizaciones vinculantes si dicen completion. (#42114)

✨ Nuevas funciones y mejoras

  • Appsmith MCP Server (BETA): un servidor [Protocolo de contexto de modelo] (https://modelcontextprotocol.io/) integrado y opcional que permite a AI clients compatibles crear y editar aplicaciones Appsmith a través de una herramienta estructurada API. Los agentes nunca crean enlaces de widgets DSL, SQL, JS o {{ }} sin formato: llaman a herramientas que el servidor compila bajo los propios permisos de la persona que llama. Configurar el servidor MCP → (#42185, #42187, #42190, #42193, #42208, #42210, #42212)
    • Desactivado de forma predeterminada, tanto en instalaciones nuevas como en actualizaciones: la actualización a v2.4 no expone un punto final de agente. Autohospedado: Configuración de administrador → Instancias → Servidor MCP (BETA) → habilitar → Guardar y reiniciar. Las cuentas de Appsmith Cloud con un nombre de organización personalizado lo habilitan en Organizaciones.
    • Claves por usuario en Configuración de administrador → Perfil → Claves MCP. Una clave autentica el client como ese usuario y no otorga permisos adicionales. Las claves caducan en 30/60/90/180/365 días (el valor predeterminado es 30) y tienen un límite de 10 claves no revocadas por usuario; el secreto se muestra solo una vez, en la creación o en la rotación. Deshabilitar el servidor rechaza las claves existentes pero no las revoca.
    • Las operaciones destructivas requieren aprobación humana a través de un apretón de manos prepare_* → confirm_* con una confirmación única vinculada al objetivo y su revisión de contenido actual.
    • Las aplicaciones conectadas a Git están cerradas. Las mutaciones deben nombrar la rama actual de la aplicación y no se pueden cerrar si no se puede leer el estado de git. Los agentes se comprometen solo dentro del espacio de nombres de rama reservado mcp/, y cada compromiso de agente lleva un prefijo [mcp] no eliminable.
    • Nota del operador: crear una rama mcp/ o confirmar una confirmación inserciones a su control remoto git usando la clave de implementación de la instancia, por lo que el CI remoto y los webhooks que observen las inserciones de rama se activarán en las referencias mcp/*.
  • Conexiones de solo lectura MSSQL: modo de solo lectura agregado con ApplicationIntent=ReadOnly, incluido el enrutamiento secundario de lectura para implementaciones de SQL Server Always On. (#41668)
  • Ayudante de valor evaluado: se mejoró la ubicación de las ventanas emergentes y se agregó una vista contraída compacta persistente. (#42128)

🤖 Mejoras en la IA

  • Descubrimiento de modelos de fuentes de datos OpenAI, Anthropic y Google AI actualizado para los modelos actuales GPT, Claude y Gemini. (#42114)

🎨 Mejoras en la interfaz de usuario y los widgets

  • Se eliminaron los errores de pelusa obsoletos JavaScript después de borrar los eventos del widget. (#42130)
  • Se evitó que los valores null en las configuraciones de ECharts personalizados interrumpieran la evaluación de la página. (#42145)
  • Se evitó que grandes errores de sintaxis del widget personalizado JavaScript bloquearan el generador. (#42198)
  • Se restauraron los marcadores de campos obligatorios en los widgets Select, MultiSelect y Tree Select heredados. (#41927)
  • Mantuvo consistente la etiqueta de inicio de sesión del formulario "Permitir que todos los usuarios se registren" cuando se alternaba. (#42167)

🛠️ Confiabilidad

  • Se alejaron las operaciones de bloqueo de fuentes de datos de los subprocesos del servidor compartido y se agregaron tiempos de espera de SMTP y SSH limitados. (#42159)
  • Se eliminaron búsquedas de fuentes de datos duplicadas y actualizaciones de políticas durante la validación de acciones. (#42138)

🔐 Seguridad

  • Identificadores de biblioteca JavaScript personalizados compartidos derivados del lado del servidor y permiso de lectura de aplicación aplicado antes de devolver manifiestos de biblioteca. (#42108, #42131)
  • Se evitó que las solicitudes de actualización de aplicaciones permitieran la exportación con credenciales incluidas o el comportamiento de bifurcación. (#42113)
  • Permiso de lectura de aplicaciones aplicado antes de que las rutas Git resuelvan aplicaciones o utilicen credenciales Git almacenadas. (#42121)
  • Se evitó que los flujos de fuentes de datos de OAuth se redireccionaran a orígenes que no coinciden con el host de la solicitud. (#42146)
  • Se reforzaron las comprobaciones de host restringido para representaciones alternativas de IPv4, IPv6 e IPv4 en IPv6. (#42132)
  • Se actualizaron client, servidor, observabilidad, herramientas incluidas y dependencias de imágenes base para abordar las vulnerabilidades reportadas. (#42103, #42110, #42075, #42154, #42183, #42200)

🔧 Git, implementación y configuración

  • Sincronización de sucursales Git respaldada por Redis mejorada para repositorios sin sucursales locales. (#42176)
  • Se permitieron comprobaciones de inicio del conjunto de réplicas para aceptar opciones más nuevas de URI de MongoDB, como serverMonitoringMode=poll. (#42188)

appsmith v2.4

Highlights

  • Appsmith AI end-of-life (breaking, hard deadline) — Appsmith AI reaches EOL on 2026-09-30, three weeks after v2.4. New AI datasource connections/queries have been blocked since v2.3, but existing ones keep working only until that date, then stop working regardless of whether you upgrade. Migrate all remaining Appsmith AI queries to direct OpenAI, Anthropic, or Google AI datasources before then; v2.4 refreshes the model lists for all three specifically so current models are available to migrate onto. (#42114)
  • Admin env API secret masking (breaking for automation) — GET /api/v1/admin/env now masks sensitive values, and the editable MongoDB and Redis URL fields are replaced by read-only connection-status indicators. Any scripts or automation that scrape those values must be updated. Submitting a masked value back is treated as "unchanged", so existing configuration is preserved rather than overwritten. (#42169)
  • Embedded MCP Server (BETA, opt-in) — A new Model Context Protocol server lets compatible AI clients build/edit apps through a structured tool API; agents never author raw widget DSL, SQL, JS, or {{ }} bindings, and tools compile under the caller's own permissions (no elevation). It is off by default on both new installs and upgrades, so upgrading to v2.4 does not expose an agent endpoint — enable via Admin Settings → Instances → MCP Server (BETA) → Save & Restart (Cloud custom-org accounts use Organizations). Access uses per-user keys under Profile → MCP keys that expire in 30/60/90/180/365 days (default 30), are capped at 10 un-revoked keys, and show the secret only once; disabling the server rejects keys without revoking them. Destructive operations require a prepare_* → confirm_* approval handshake bound to the target and its current content revision; git-connected apps must name the current branch, fail closed if git state is unreadable, and constrain agent commits to the reserved mcp/ branch namespace with a non-strippable [mcp] prefix. Operator warning: creating an mcp/ branch or confirming a commit pushes to the git remote using the instance deploy key, so remote CI and webhooks will fire on mcp/* refs. (#42185, #42187, #42190, #42193, #42208, #42110, #42212)
  • AI model discovery refresh (possible silent breakage) — OpenAI, Anthropic, and Google AI datasources now list current GPT, Claude, and Gemini models. Saved Anthropic queries that use manually entered modern model IDs may need binding updates if they read completion, so verify those queries after upgrading even though they are unrelated to the Appsmith AI shutdown. (#42114)
  • Worth upgrading — security/reliability hardening; not a no-op — This is a substantive release, not a metadata-only re-tag. Upgrade if the instance is shared or internet-exposed: app read permission is now enforced before Custom JavaScript Library manifests and Git routes resolve apps or use stored credentials, app updates can no longer enable credential-inclusive export/fork, OAuth datasource redirects are rejected when the origin doesn't match the request host, restricted-host checks cover alternate IPv4/IPv6/IPv4-in-IPv6 forms, and client/server/observability/base-image dependencies were updated. Reliability gains include blocking datasource operations moved off shared server threads with bounded SMTP/SSH timeouts, improved Redis-backed Git branch sync for repos without local branches, and replica-set checks accepting newer MongoDB URI options like serverMonitoringMode=poll; plus MSSQL read-only connections via ApplicationIntent=ReadOnly with Always On readable-secondary routing. Who can skip: isolated single-user/local instances with no Appsmith AI usage, no automation against GET /api/v1/admin/env, and no need for the MCP server or security hardening can defer — but anyone with remaining Appsmith AI queries must act before 2026-09-30 regardless of upgrade timing. (#42159, #42138, #42108, #42131, #42113, #42121, #42146, #42132, #41668)

🗑️ Feature Removal Reminder - September 30, 2026 - EOL

Appsmith AI reaches end of life on September 30th, 2026 — three weeks after this release.

As announced in v2.3, you can no longer add new Appsmith AI data source connections or queries. Any that you currently have will continue to work until September 30th, 2026. After that date, all Appsmith AI datasources will stop working — whether or not you have upgraded.

Migrate any remaining Appsmith AI queries to a direct provider datasource (OpenAI, Anthropic, or Google AI) before that date. This release refreshes the available model lists for all three providers, so the current models are available to migrate onto. (#42114)

⚠️ Important Upgrade Notes

  • Admin Settings secrets — Sensitive values returned by GET /api/v1/admin/env are now masked, and the editable MongoDB and Redis URL fields are replaced by read-only connection status. Update any scripts or automation that read those values from the admin API. Submitting a masked value back is treated as "unchanged", so existing configuration is preserved. (#42169)
  • AI datasource responses — OpenAI, Anthropic, and Google AI datasources now list current models. Saved Anthropic queries using manually entered modern model IDs may require binding updates if they read completion. (#42114)

✨ New Features & Enhancements

  • Appsmith MCP Server (BETA) — An opt-in, embedded Model Context Protocol server that lets compatible AI clients build and edit Appsmith applications through a structured tool API. Agents never author raw widget DSL, SQL, JS, or {{ }} bindings — they call tools that the server compiles under the caller's own permissions. Set up the MCP server → (#42185, #42187, #42190, #42193, #42208, #42210, #42212)
    • Off by default, on new installs and upgrades alike — upgrading to v2.4 does not expose an agent endpoint. Self-hosted: Admin Settings → Instances → MCP Server (BETA) → enable → Save & Restart. Appsmith Cloud accounts with a custom organization name enable it under Organizations instead.
    • Per-user keys under Admin Settings → Profile → MCP keys. A key authenticates the client as that user and grants no additional permissions. Keys expire in 30/60/90/180/365 days (default 30) and are capped at 10 un-revoked keys per user; the secret is shown only once, at creation or rotation. Disabling the server rejects existing keys but does not revoke them.
    • Destructive operations require human approval through a prepare_* → confirm_* handshake with a one-time confirmation bound to the target and its current content revision.
    • Git-connected apps are gated. Mutations must name the app's current branch and fail closed if git state cannot be read. Agents commit only within the reserved mcp/ branch namespace, and every agent commit carries a non-strippable [mcp] prefix.
    • Operator note: creating an mcp/ branch or confirming a commit pushes to your git remote using the instance deploy key, so remote CI and webhooks watching branch pushes will fire on mcp/* refs.
  • MSSQL read-only connections — Added read-only mode with ApplicationIntent=ReadOnly, including readable-secondary routing for SQL Server Always On deployments. (#41668)
  • Evaluated value helper — Improved popup placement and added a persistent compact collapsed view. (#42128)

🤖 AI Improvements

  • Updated OpenAI, Anthropic, and Google AI datasource model discovery for current GPT, Claude, and Gemini models. (#42114)

🎨 UI & Widget Improvements

  • Removed stale JavaScript lint errors after clearing widget events. (#42130)
  • Prevented null values in Custom ECharts configurations from breaking page evaluation. (#42145)
  • Prevented large Custom Widget JavaScript syntax errors from crashing the builder. (#42198)
  • Restored required-field markers on legacy Select, MultiSelect, and Tree Select widgets. (#41927)
  • Kept the “Allow all users to signup” Form Login label consistent when toggled. (#42167)

🛠️ Reliability

  • Moved blocking datasource operations away from shared server threads and added bounded SMTP and SSH timeouts. (#42159)
  • Removed duplicate datasource lookups and policy updates during action validation. (#42138)

🔐 Security

  • Derived shared Custom JavaScript Library identifiers server-side and enforced application read permission before returning library manifests. (#42108, #42131)
  • Prevented application update requests from enabling credential-inclusive export or fork behavior. (#42113)
  • Enforced application read permission before Git routes resolve applications or use stored Git credentials. (#42121)
  • Prevented OAuth datasource flows from redirecting to origins that do not match the request host. (#42146)
  • Strengthened restricted-host checks for alternate IPv4, IPv6, and IPv4-in-IPv6 representations. (#42132)
  • Updated client, server, observability, bundled tooling, and base-image dependencies to address reported vulnerabilities. (#42103, #42110, #42075, #42154, #42183, #42200)

🔧 Git, Deployment & Configuration

  • Improved Redis-backed Git branch synchronization for repositories without local branches. (#42176)
  • Allowed replica-set startup checks to accept newer MongoDB URI options such as serverMonitoringMode=poll. (#42188)
