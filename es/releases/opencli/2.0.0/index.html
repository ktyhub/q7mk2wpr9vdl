AbiertoCLI v2.0.0

Un lanzamiento importante centrado en la experiencia del agente: una superficie CLI más pequeña, resultados JSON predecibles, API nativos de Chrome y desarrollo de adaptadores basado en evidencia. Incluye la extensión de Chrome 1.0.25.

Cambios importantes y migración

  • Las sesiones del navegador son opciones explícitas: use opencli browser <command> ... --session research en lugar de nombres de sesión posicionales.
  • Los resultados de CLI por defecto son { "ok": true, "data": ... }; las fallas usan { "ok": false, "error": { "code", "message", "hint", ... } } y un estado de salida distinto de cero. Actualizar a los consumidores para que lean data; Los modos de seguimiento emiten líneas JSON. Los formatos explícitos legibles por humanos y las exportaciones sin formato siguen estando disponibles.
  • Utilice opencli adapter init, adapter test y adapter check para la creación y validación de adaptadores. Estos reemplazan los antiguos puntos de entrada de validación del adaptador y de inicio/verificación del navegador.
  • Utilice opencli browser network --static para solicitudes capturadas más evidencia de punto final derivada de AST y opencli browser state --diagnostics para diagnósticos de página. Se elimina el flujo de trabajo de descubrimiento/análisis independiente.
  • Se eliminan la automatización del escritorio de Electron, el registro de aplicaciones y la exportación del iniciador público, el conocimiento del mapa del sitio y el paso a través del concentrador CLI externo. Las conexiones CDP directas a Chrome siguen siendo compatibles.
  • Los contratos de ejecución y registro de adaptadores JS existentes (cli({...}), func(args), func(page, args)) siguen siendo compatibles. El adaptador defaultFormat ya no anula el valor predeterminado JSON del CLI.

Características

  • Descubrimiento y llamadas nativas de Chrome API a través de opencli browser chrome describe y chrome call, incluida la administración de pestañas/ventanas y la creación y edición de grupos de pestañas sin adjuntar una sesión de página. Los recursos de sesión administrados están protegidos.
  • Descubrimiento de comandos paginado y compacto con opencli list [query] --site --limit --offset; Habilidades de agente integradas optimizadas y creación de adaptadores.
  • Descubrimiento de puntos finales estáticos basado en AST integrado con evidencia de red capturada, con capturas de red incompletas retenidas cuando se solicita.
  • Los grupos de ranuras por sitio brindan pestañas exclusivas para ejecuciones de adaptadores simultáneos y ritmo a nivel de ejecución; limpieza opcional de pestañas propias y tiempo de espera de inactividad del navegador configurable.
  • Bandeja de entrada de Proton API y autenticación de navegador verificada; Comandos de comentarios/eliminación de comentarios de Xiaohongshu y comentarios de YouTube; Metadatos más ricos de Twitter, YouTube y Bilibili.

Correcciones

  • Excluir los destinos de la barra de herramientas del navegador Chrome 155 de la selección directa de páginas CDP para que las pestañas en blanco sigan siendo utilizables.
  • Cargas de archivos/imágenes ChatGPT más confiables y orientación del compositor; Flujos actuales de compositores de Gemini, Grok y DeepSeek.
  • Manejo de captcha/búsqueda/comentarios de Xiaohongshu, confirmación del carrito de Taobao y detección de páginas bloqueadas, lecturas XML respaldadas por el navegador DBLP y resolución de manejo del canal de YouTube.
  • Contención de rutas de complementos y vinculación de paquetes de host, activación del selector de archivos de carga del navegador, sugerencias de recuperación de autenticación y manejo estructurado de códigos de error/salida.
  • Vitest actualizado para abordar GHSA-82fw-gwwq-j7x9. Completo changelog: https://github.com/jackwener/OpenCLI/compare/v1.8.8...v2.0.0

OpenCLI v2.0.0

Highlights

  • Breaking CLI output and session syntax — Browser sessions are now explicit options (opencli browser <command> ... --session research). Results default to { "ok": true, "data": ... }; consumers must read data, while failures provide structured error objects and nonzero exit codes. Follow modes emit JSON Lines, and adapter defaultFormat no longer overrides the CLI’s JSON default. Human-readable and raw-export formats remain available.
  • Adapter and discovery workflow migration — Replace former adapter authoring/validation entry points with opencli adapter init, opencli adapter test, and opencli adapter check. The discover/analyze workflow is removed in favor of opencli browser network --static for captured requests plus AST-derived endpoints and opencli browser state --diagnostics for page diagnostics. Existing cli({...}), func(args), and func(page, args) adapter contracts remain supported.
  • Removed integrations — Electron desktop automation, its app registry and public launcher export, site sitemap knowledge, and external CLI Hub passthrough are gone. Direct CDP connections remain supported, but workflows depending on the removed features require rework.
  • Stronger browser automation — New opencli browser chrome describe and chrome call expose native Chrome APIs, including tab/window and tab-group management without attaching a page session. Paginated command discovery, AST-backed endpoint evidence, per-site exclusive tab pools, pacing, optional tab cleanup, and configurable idle timeout make concurrent automation safer. The release also improves ChatGPT uploads, several site-specific flows, Chrome 155 tab selection, and updates Vitest for GHSA-82fw-gwwq-j7x9.
  • Upgrade recommendation — Upgrade if you run browser agents concurrently, need native Chrome controls or richer site commands, or want the reliability and security fixes. Budget time for the output/session and workflow migrations. You can defer if your setup relies solely on unchanged adapter contracts, does not use removed features or integrations, and you can postpone those fixes.

A major release focused on agent experience: a smaller CLI surface, predictable JSON results, native Chrome APIs, and evidence-driven adapter development. Includes Chrome extension 1.0.25.

Breaking changes and migration

  • Browser sessions are explicit options: use opencli browser <command> ... --session research instead of positional session names.
  • CLI results default to { "ok": true, "data": ... }; failures use { "ok": false, "error": { "code", "message", "hint", ... } } and a nonzero exit status. Update consumers to read data; follow modes emit JSON Lines. Explicit human-readable formats and raw exports remain available.
  • Use opencli adapter init, adapter test, and adapter check for adapter authoring and validation. These replace the former browser init/verify and adapter validation entry points.
  • Use opencli browser network --static for captured requests plus AST-derived endpoint evidence, and opencli browser state --diagnostics for page diagnostics. The separate discover/analyze workflow is removed.
  • Electron desktop automation, its app registry and public launcher export, site sitemap knowledge, and external CLI Hub passthrough are removed. Direct CDP connections to Chrome remain supported.
  • Existing JS adapter registration and execution contracts (cli({...}), func(args), func(page, args)) remain supported. Adapter defaultFormat no longer overrides the CLI's JSON default.

Features

  • Native Chrome API discovery and calls through opencli browser chrome describe and chrome call, including tab/window management and tab-group creation and editing without attaching a page session. Managed session resources are protected.
  • Compact, paginated command discovery with opencli list [query] --site --limit --offset; streamlined bundled agent skills and adapter authoring.
  • AST-based static endpoint discovery integrated with captured network evidence, with incomplete network captures retained when requested.
  • Per-site slot pools give concurrent adapter runs exclusive tabs and run-level pacing; optional owned-tab cleanup and configurable browser idle timeout.
  • Proton API inbox and verified browser authentication; Xiaohongshu comment/comment-delete and YouTube comment commands; richer Twitter, YouTube, and Bilibili metadata.

Fixes

  • Exclude Chrome 155 browser toolbar targets from direct CDP page selection so blank tabs remain usable.
  • More reliable ChatGPT file/image uploads and composer targeting; current Gemini, Grok, and DeepSeek composer flows.
  • Xiaohongshu captcha/search/comment handling, Taobao cart confirmation and blocked-page detection, DBLP browser-backed XML reads, and YouTube channel-handle resolution.
  • Plugin path containment and host-package linking, browser upload file chooser activation, auth recovery hints, and structured error/exit-code handling.
  • Updated Vitest to address GHSA-82fw-gwwq-j7x9.

Full changelog: https://github.com/jackwener/OpenCLI/compare/v1.8.8...v2.0.0
