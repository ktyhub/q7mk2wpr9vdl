OpenCLI v1.8.8

Highlights

  • Security baseline and Node floor — The headline fix is undici 7.29.0/8.9.0 closing CVE-2026-13697 (#2326, lockfile synced in #2361), and #2381 now formally declares the engines floor of Node >=20.18.1 that undici 7.x already required. This is the one compatibility break to plan for: anyone still on Node 18 is now officially unsupported and should expect engine warnings or failed installs before upgrading. Two smaller hardening items ride along — a child_process call sanitized in spotify.js (#2318) and a dev-dependency npm audit fix (#2378).

  • Runtime configuration for automation — Two environment knobs matter for anyone harnessing OpenCLI from CI or a server. OPENCLI_SITE_SESSION supplies a default session to every site adapter, so you no longer have to thread a session into each command (#2221); and #2148 makes web adapters actually honor OPENCLI_CDP_ENDPOINT, enabling a remote or containerized Chrome instead of a fixed local CDP port. If you run the CLI headless or in a sandbox, both are directly relevant.

  • New adapters and capabilities — The largest surface expansion in this release: a browser-backed Gmail adapter (#2396), browser commands for Dribbble (#2403), a MiniMax music-generation adapter with separate global and China endpoints (#2290), Bilibili creator analytics (#2268), Pixiv novel commands (#2112), and Jira custom-field support (#2289). The Gmail and Dribbble additions in particular signal a shift toward authenticated, session-backed adapters rather than public-page scraping.

  • Xiaohongshu resilience and search filters — XHS got the bulk of scraping work: rows are now harvested continuously during scroll instead of a first/last-screen union (#2349), collapsed masonry layouts recover by reopening in a fresh tab (#2355), risk-control soft blocks get one cooldown retry (#2207), and ask no longer breaks on webpack chunk renumbering or spends a note search per call (#2420). Search also gains real filter flags — --sort, --note-type, --publish-time, --scope, --location (#2276). Expect fewer silent empty results and noticeably less request overhead at scale.

  • Pagination and data fidelity — Several "get everything" commands were previously only returning the first page/screen: YouTube authenticated watch history now paginates (#2386) and search pagination is fixed (#2387); Twitter intercepts the full followers timeline (#2380) and reads current following/follower counts (#2382); Zhihu preserves comment reply threads (#2306) and exports answers with local images (#2304). If you relied on these exports for completeness, re-pull them — the new results are materially more complete.

  • Output, errors and data-source migrations — Markdown rows now stay intact across multi-line cells (#2375), toEnvelope duck-types CliError across package boundaries so errors from separately installed adapters serialize correctly (#2388), structured network captures are preserved (#2406), and invalid pipeline concurrency limits are rejected rather than silently misbehaving (#2407). Several adapters changed upstream: sinafinance moved to a rolling news API (#2365), jike to structured search/notification APIs (#2394), ctrip to structured flight results (#2393), and trip flight extraction was repaired after a dropped font-black class emptied every row (#2385). Watch for changed field shapes if you parse those outputs directly; the npm package is also leaner now (#2410, #2411).
