código ballena v0.8.60

CodeWhale es el proyecto canónico, el comando, el paquete npm y nombre del activo de liberación. El paquete npm heredado deepseek-tui es está en desuso y no recibe más versiones. Usuarios provenientes de Los nombres deepseek / deepseek-tui heredados de v0.8.x deben migrar con docs/REBRAND.md.

Instalar

Recomendado: npm (un comando, ambos binarios)

npm install -g codewhale

El contenedor descarga ambos archivos binarios de esta versión y los coloca en el mismo directorio.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.60

La imagen incluye el despachador codewhale y el tiempo de ejecución codewhale-tui. La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Se requieren ambas cajas: codewhale-cli produce el despachador codewhale y codewhale-tui produce el tiempo de ejecución interactivo en el que delega el despachador. La instalación de solo un binario fallará en tiempo de ejecución con un error MISSING_COMPANION_BINARY.

Descarga manual: archivos de plataforma (recomendado)

Cada archivo a continuación contiene tanto el despachador codewhale como el tiempo de ejecución codewhale-tui, además de un script de instalación: | Plataforma | Archivo | Instalar script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | MacOS x64 | codewhale-macos-x64.tar.gz | install.sh | | BRAZO macOS | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (instalador) | CodeWhaleSetup.exe | Configuración de NSIS | | Ventanas x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portátil) | codewhale-windows-x64-portable.zip | — | Unix (Linux/macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • Para la ruta del instalador, ejecute CodeWhaleSetup.exe; instala ambos binarios en %LOCALAPPDATA%\Programs\CodeWhale\bin y agrega ese directorio a la RUTA del usuario actual.
  • Extracto codewhale-windows-x64.zip
  • Ejecute install.bat (copias a %USERPROFILE%\bin)
  • Añade %USERPROFILE%\bin a tu RUTA El archivo portátil de Windows omite el script de instalación: extráigalo y ejecútelo desde cualquier directorio. El instalador de NSIS actualmente no está firmado y puede activar Windows SmartScreen hasta que se conecte un certificado de firma al proceso de lanzamiento. Los binarios individuales también se adjuntan a continuación para secuencias de comandos y el contenedor npm. El paquete npm heredado deepseek-tui está obsoleto y no se vuelve a publicar. Para la migración desde nombres binarios heredados v0.8.x, consulte docs/REBRAND.md.

¿Qué hay en v0.8.60?

Agregado

  • Corte de ejecución real de Agent Fleet (#3154/#3096). codewhale fleet run ahora lanza trabajadores duraderos a través del codewhale exec --output-format sin cabeza ruta stream-json en lugar del intérprete de simulación local, con terminal Eventos para trabajadores que liberan arrendamientos para que las tareas de la flota en cola sigan ejecutándose.
  • Paralelismo de shell de solo lectura (#2983). El motor ahora puede funcionar de manera conservadora llamadas de shell de solo lectura en paralelo, incluidas las estrictas bash/sh/zsh -c contenedores para comandos incluidos en la lista blanca, mientras escribe, stdin, trabajo TTY en segundo plano, Las redirecciones, canalizaciones, sustitución de comandos y colas en modo de seguimiento permanecen en serie.
  • Autoría declarativa JS/TS WhaleFlow (#3097). WhaleFlow ahora acepta un formulario de creación de solo compilación workflow({...}) JavaScript/TypeScript que desciende al validador WorkflowSpec existente sin ejecutar el usuario JavaScript.
  • Menú de barra diagonal Ctrl+P/Ctrl+N navegación (#3196). El menú de comando de barra diagonal ahora admite el movimiento Ctrl+P/Ctrl+N sin permitir que el selector de archivos global robe enfoque mientras el menú está abierto. Gracias @ 1Git2Clone por las relaciones públicas.
  • Nuevos modelos y rutas de proveedores propios. Esta versión agrega GLM-5.2 (seleccionable en el plan de codificación Z.ai y en OpenRouter como z-ai/glm-5.2, junto con el predeterminado GLM-5.1 existente), un producto propio Ruta del proveedor Z.ai, una ruta propia StepFun/StepFlash (step-3.7-flash) y una ruta propia MiniMax cuyo valor predeterminado es MiniMax-M3 con la familia M2.7/M2.5/M2.1 seleccionable (#3187/#3191).

Cambiado

  • README y créditos de contribuyente. El archivo README ahora tiene un formato público más corto. descripción general y mueve el libro mayor de contribuyentes completo a docs/CONTRIBUTORS.md, preservando el agradecimiento público por DeepSeek, Ballena de datos, OpenWarp, y Diseño abierto.
  • Dirección del subagente respaldado por la flota. Los documentos en tiempo de ejecución ahora indican la intención transición claramente: "subagente" es vocabulario de rol/UX, aunque duradero y separado el trabajo debe converger en el ciclo de vida de los trabajadores respaldado por la flota con reintentos, recibos e inspección del libro mayor.

Fijo

  • La evaluación del subagente ya no bloquea de forma predeterminada. agent_eval ahora devuelve el proyección actual inmediatamente y ofrece información de seguimiento sin esperas para que un niño en ejecución finalice su llamada al proveedor. Pase block:true para un espera terminal intencional.
  • Rastros de pensamiento Z.ai GLM. Las solicitudes directas de Z.ai ahora utilizan el documento thinking forma, conserva y reproduce reasoning_content, clasifica GLM el razonamiento fluye como resultado del pensamiento y acepta ultracode como un esfuerzo máximo alias.
  • Compatibilidad con el archivo de habilidades de Claude (#2743). /skill install mantiene Se admiten carpetas de habilidades portátiles estilo Claude y se rechazan las habilidades múltiples. El complemento Claude archiva claramente en lugar de instalar silenciosamente solo una habilidad y eliminar la semántica del complemento. Gracias @AiurArtanis por la solicitud del ecosistema. Los créditos de los contribuyentes para este lanzamiento se encuentran en la entrada changelog anterior: Gracias a todos cuyos informes, relaciones públicas, reseñas y reproducciones le dieron forma. Consulte CHANGELOG.md para obtener notas completas y docs/CHANGELOG_ARCHIVE.md para versiones anteriores.

Codewhale v0.8.60

Highlights

  • Package rename and two-binary install — codewhale is now the canonical command and npm package; deprecated deepseek-tui will receive no further releases. Follow docs/REBRAND.md, and install both binaries: Cargo requires codewhale-cli and codewhale-tui, while installing only one causes MISSING_COMPANION_BINARY. Existing Docker integrations can retain DEEPSEEK_API_KEY and the ~/.deepseek mount.

  • Fleet execution leaves simulation behind (#3154/#3096) — codewhale fleet run now launches durable workers through codewhale exec --output-format stream-json. Fleet throughput and reliability now depend on real worker execution; terminal events release leases so queued tasks do not stall behind completed workers.

  • Concurrency and evaluation semantics changed (#2983) — Conservatively whitelisted read-only commands, including strict bash/sh/zsh -c wrappers, can execute in parallel. Writes, stdin, TTY work, redirects, pipes, command substitution, and follow-mode tails remain serial, so scripts cannot assume universal ordering. Separately, agent_eval now returns immediately and accepts follow-up input without waiting for a provider call; callers that require terminal completion must explicitly pass block:true.

  • JS/TS workflows without runtime execution (#3097) — The compile-only workflow({...}) authoring form lowers JavaScript/TypeScript into the existing WorkflowSpec validator without executing user code. This enables typed, declarative workflow authoring while preserving the established validation boundary.

  • More provider routes and corrected GLM reasoning — GLM-5.2 joins the Z.ai Coding Plan and OpenRouter as z-ai/glm-5.2, while GLM-5.1 remains the default. First-party routes add StepFun (step-3.7-flash) and MiniMax (defaulting to MiniMax-M3, with M2.7/M2.5/M2.1 selectable) under #3187/#3191. Direct Z.ai requests now use the documented thinking shape, replay reasoning_content, classify reasoning streams correctly, and accept ultracode as a max-effort alias.

  • Claude skill archives have a clearer compatibility boundary (#2743) — /skill install continues to support portable Claude-style skill folders, but now explicitly rejects multi-skill plugin archives instead of silently installing one skill and discarding plugin semantics. Teams distributing plugin bundles must repackage them as individual portable skills.

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Install

Recommended — npm (one command, both binaries)

npm install -g codewhale

The wrapper downloads both binaries from this Release and places them in the same directory.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.60

The image ships the codewhale dispatcher and codewhale-tui runtime. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Both crates are required — codewhale-cli produces the codewhale dispatcher and codewhale-tui produces the interactive runtime that the dispatcher delegates to. Installing only one binary will fail at runtime with a MISSING_COMPANION_BINARY error.

Manual download — platform archives (recommended)

Each archive below contains both the codewhale dispatcher and codewhale-tui runtime, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs both binaries under %LOCALAPPDATA%\Programs\CodeWhale\bin and adds that directory to the current-user PATH.
  • Extract codewhale-windows-x64.zip
  • Run install.bat (copies to %USERPROFILE%\bin)
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Individual binaries are also attached below for scripting and the npm wrapper. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.

What's in v0.8.60

Added

  • Agent Fleet real-run cutover (#3154/#3096). codewhale fleet run now launches durable workers through the headless codewhale exec --output-format stream-json path instead of the local simulation interpreter, with terminal worker events freeing leases so queued fleet tasks continue running.
  • Read-only shell parallelism (#2983). The engine can now run conservative read-only shell calls in parallel, including strict bash/sh/zsh -c wrappers for whitelisted commands, while writes, stdin, background TTY work, redirects, pipes, command substitution, and follow-mode tails stay serial.
  • Declarative JS/TS WhaleFlow authoring (#3097). WhaleFlow now accepts a compile-only workflow({...}) JavaScript/TypeScript authoring form that lowers into the existing WorkflowSpec validator without executing user JavaScript.
  • Slash-menu Ctrl+P/Ctrl+N navigation (#3196). The slash command menu now supports Ctrl+P/Ctrl+N movement without letting the global file picker steal focus while the menu is open. Thanks @1Git2Clone for the PR.
  • New models and first-party provider routes. This release adds GLM-5.2 (selectable on the Z.ai Coding Plan and over OpenRouter as z-ai/glm-5.2, alongside the existing GLM-5.1 default), a first-party Z.ai provider route, a first-party StepFun / StepFlash route (step-3.7-flash), and a first-party MiniMax route defaulting to MiniMax-M3 with the M2.7/M2.5/M2.1 family selectable (#3187/#3191).

Changed

  • README and contributor credits. The README now has a shorter public overview and moves the full contributor ledger to docs/CONTRIBUTORS.md, preserving public thanks for DeepSeek, DataWhale, OpenWarp, and Open Design.
  • Fleet-backed sub-agent direction. Runtime docs now state the intended cutover clearly: "sub-agent" is role/UX vocabulary, while durable detached work should converge on the fleet-backed worker lifecycle with retries, receipts, and ledgered inspection.

Fixed

  • Sub-agent eval no longer blocks by default. agent_eval now returns the current projection immediately and delivers follow-up input without waiting for a running child to finish its provider call. Pass block:true for an intentional terminal wait.
  • Z.ai GLM thinking traces. Direct Z.ai requests now use the documented thinking shape, preserve and replay reasoning_content, classify GLM reasoning streams as thinking output, and accept ultracode as a max-effort alias.
  • Claude skill archive compatibility (#2743). /skill install keeps portable Claude-style skill folders supported while rejecting multi-skill Claude plugin archives clearly instead of silently installing only one skill and dropping plugin semantics. Thanks @AiurArtanis for the ecosystem request.

Contributor credits for this release live in the changelog entry above — thank you to everyone whose reports, PRs, reviews, and reproductions shaped it.
