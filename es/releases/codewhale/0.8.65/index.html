código ballena v0.8.65

CodeWhale es el proyecto canónico, el comando, el paquete npm y nombre del activo de liberación. El paquete npm heredado deepseek-tui es está en desuso y no recibe más versiones. Usuarios provenientes de Los nombres deepseek / deepseek-tui heredados de v0.8.x deben migrar con docs/REBRAND.md.

Instalar

Recomendado: npm (un comando, ambos binarios)

npm install -g codewhale

El contenedor descarga los archivos binarios de tiempo de ejecución coincidentes de esta versión y los coloca en el mismo directorio.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.65

La imagen incluye el despachador codewhale, la cuña codew y el tiempo de ejecución codewhale-tui. La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Se requieren ambas cajas: codewhale-cli produce el despachador codewhale y la cuña codew, mientras que codewhale-tui produce el tiempo de ejecución interactivo en el que delega el despachador. La instalación de solo una caja fallará en tiempo de ejecución con un error MISSING_COMPANION_BINARY.

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

  • Para la ruta del instalador, ejecute CodeWhaleSetup.exe; instala codewhale.exe, codew.exe y codewhale-tui.exe en %LOCALAPPDATA%\Programs\CodeWhale\bin y agrega ese directorio a la RUTA del usuario actual.
  • Extracto codewhale-windows-x64.zip
  • Ejecute install.bat (copias a %USERPROFILE%\bin)
  • Añade %USERPROFILE%\bin a tu RUTA El archivo portátil de Windows omite el script de instalación: extráigalo y ejecútelo desde cualquier directorio. El instalador de NSIS actualmente no está firmado y puede activar Windows SmartScreen hasta que se conecte un certificado de firma al proceso de lanzamiento. Cada plataforma también tiene binarios básicos y sin archivar adjuntos a continuación (codewhale-<platform>, codew-<platform> y codewhale-tui-<platform>): el contenedor npm y el codewhale update en la aplicación descargan los binarios de tiempo de ejecución coincidentes, mientras que los archivos .tar.gz / .zip anteriores son la descarga manual recomendada y, además, incluyen un script de instalación. El paquete npm heredado deepseek-tui está obsoleto y no se vuelve a publicar. Para la migración desde nombres binarios heredados v0.8.x, consulte docs/REBRAND.md.

¿Qué hay en v0.8.65?

Agregado

  • Proveedor/modelo/resolución de ruta (EPIC #2608). Proveedor canónico, modelo, oferta y tipos de ruta con un solo RouteResolver que produce un resuelto ReadyRouteCandidate (punto final, protocolo de conexión, identificación del modelo, contexto límite, precio) para cada interruptor (#3458, #3084, #3384). El client en ejecución es ahora construido a partir del candidato resuelto en lugar de volver a derivar de la configuración (#3384). Un catálogo comprometido y sin red en forma de Models.dev brinda modelos reales ventanas de contexto y precios, con un caché en vivo libre de secretos (#3497, #3498, #3385). El precio de oferta con procedencia se proyecta en los candidatos (#3501, #3085), y los límites de ruta alimentan un servicio de presupuesto contextual con reconocimiento de ruta (#3508, #3523, #3086).
  • Sustrato de ejecución de flota (EPIC #3154). Tipos y configuración de perfil de flota (#3469), currículum de administrador duradero, carga del perfil del agente del espacio de trabajo resuelta en el tiempo de ejecución del trabajador (#3367), la intención de carga incluida en las especificaciones de la tarea (#3512) y recibos que persisten la ruta resuelta para inspección (#3154, #3166). trabajador El estado se pliega en la superficie unificada /fleet y se expone a través de la Tiempo de ejecución API.
  • Superficies del proveedor. Un panel de preparación de /provider con razonamiento preparación, un marcador de madurez experimental/apoyado y "modelos abiertos para acción de este proveedor" (#3083, #2984, #3485); búsqueda entre proveedores /model con desplazamiento y escritura anticipada del proveedor (#3484, #3075); en línea <think> enrutamiento de flujo de razonamiento con anulaciones por proveedor (#3222); telemetría de uso normalizado en clases de tokens canónicos que incluyen Respuestas cache-miss y fichas de razonamiento (#2961, #3509); e inicio de sesión remoto de MCP OAuth con portador/encabezado precedencia de autenticación (#3527).
  • Más proveedores y rutas. Proveedores personalizados compatibles con OpenAI definidos por el usuario vía [providers.<name>] (#1519); una ruta compatible con DeepSeek Anthropic (#2963, #3449); una ruta Qianfan (#3425); Zhipu se unió a Z.ai con igualdad de trato normalización del modelo (#3539); DashScope/Together accesorios.
  • Selector de modo localizado e indicadores de compositor. El mensaje del selector /mode, nombres de modos y sugerencias, además del indicador de modo Vim del compositor, ahora se representan en las siete configuraciones regionales enviadas (las etiquetas del modo orientado al modelo permanecen en inglés). Cosechado del n.° 2239 de @gordonlu.
  • Sitio web y automatización. Una página de ejecución/integraciones, procedencia y copia mirror-trust, una puerta CI de deriva de hechos, un script de instalación publicado y un archivo de resumen semanal de la comunidad en codewhale.net (#3419, #3421, #3415, #3482, #3420); modo por automatización/shell/trust/configuración de aprobación (#3467).
  • Navegador de referencia de modelo. Un comando /modeldb de solo lectura (alias model-reference, modelref) abre un buscapersonas sobre el catálogo incluido: cada ventana de contexto fáctico del modelo, producción máxima, modalidad y precio, agrupados por proveedor/tipo. Solo etiquetas: nunca selecciona, enruta ni clasifica un modelo (#3205, #2300).
  • Preajustes de transcripción. Un mecanismo /config preset <name> [--save] con un primer ajuste preestablecido de calm: modo tranquilo, colapso tranquilo de la herramienta, espaciado cómodo y movimiento bajo: solo presentación y preservación de evidencia (#3478).
  • Perfiles de capacidad del modelo. Un módulo tipo model_profile separa hechos intrínsecos del modelo a partir de la capacidad de ruta del proveedor resuelta, por lo que es compacto Las rutas difieren las herramientas no esenciales más pesadas, mientras que las rutas estándar/completas mantienen el superficie de la herramienta ansiosa (#3451, #3365).
  • Actualización del catálogo de proveedores en vivo. Una capa de búsqueda en vivo /models sin secretos (401/403/404/429 asignado a resultados escritos) alimenta el caché del catálogo; el API La clave autoriza la solicitud pero nunca persiste en el delta o en la caché. (#3385).

Cambiado

  • Modularización de configuración (#3311). ProviderKind (#3505), postura del arnés (#3507) y las semillas predeterminadas del proveedor (#3503) se trasladaron a módulos dedicados, y el monolito config.rs dividido en módulos de hojas limpias (rutas, búsqueda, constantes de modelo/URL base, límites de subagente) detrás de una fachada pub use. Los ayudantes de AppMode estaban centralizados (#3510) y la política de modo versus permiso es ahora derivado a través de un único solucionador base_policy_for_mode en lugar de mutación dispersa (#3386, comportamiento de intención de revisión de asesoramiento conservado).
  • Superficie de herramienta más eficiente. Se eliminó task_shell_* del conjunto activo y se dobló. tool_search_* (#3463); eliminó el loop_guard a su vez y el razonamiento codificado disposiciones (#3462); añadió la disposición de Orquestación a la constitución.
  • Enrutamiento. Conmutadores de proveedor/modelo y la cadena de respaldo consciente de la capacidad resolver mediante RouteResolver; El esfuerzo de razonamiento está normalizado para el resuelto proveedor; la cadena alternativa ahora omite los proveedores que carecen de autenticación (#2574); y la ventana de contexto y la presión de la memoria provienen de la ruta resuelta (#3086).
  • UX. El modal de aprobación obtuvo un divisor de grupo y un cursor de fila seleccionada (#3515); desplazamiento del selector/escritura anticipada y contraste de selección reforzados (#3500); el LÉAME fue reescrito como un final de arquitectura (#3087); y la orientación del agente de repositorios fue descodificado para vivir la verdad.
  • Identidad y valores predeterminados de la flota. Los trabajadores de la flota ahora ingresan con un nombre explícito contrato operativo de "miembro de la flota convocado", las indicaciones de configuración/perfil mantienen el comportamiento predeterminado del modelo como herencia en la misma ruta y trabajador generado Las instrucciones evitan filtrar la topología recursiva que solo el orquestador necesidades.
  • Limpieza de enjambre heredado. Se eliminó el comando/menú principal obsoleto de /swarm. registro por lo que /fleet es la superficie del producto, mientras que /subagents sigue siendo un acceso directo de compatibilidad al estado de trabajador.
  • Animación del estado de ejecución. Las tarjetas de herramientas y las filas de tareas en segundo plano ahora comparten una Cadencia de giro braille más rápida, por lo que el trabajo Bash/en segundo plano se lee de manera consistente vivo a lo largo de la transcripción y la barra lateral.
  • Crédito de colaborador restaurado. Crédito legible por máquina enhebrado (docs/CONTRIBUTORS.md + .github/AUTHOR_MAP) para trabajos fusionados anteriores que enviado sin él, incluida la acción /jobs cancel-all y el npm sugerencia de tiempo de espera de reintento (#1538) de @jieshu666 y el adaptador ACP de la comunidad referencia de @ rockeverm3m.

Fijo

  • Liberar higiene. La estricta cargo clippy --workspace --all-targets --locked -- -D advertencias gate passes; npm run build ya no ensucia el generado hechos web; el sitio establece metadataBase; la página de resumen de la comunidad analiza cada uno graba de forma independiente y localiza su cromo; y cargo audit está limpio con los avisos no mantenidos transitivos de Starlark documentados.
  • Corrección de modo y enrutamiento. El texto de aviso ordinario ya no está interpretado como un cambio de modo (#3387, #3491); Los candidatos modelo tienen como alcance el proveedor activo; Se aceptan rutas DeepSeek de propiedad conjunta (#3426); inseguro Los puntos finales personalizados http:// generan una advertencia (#1519); y la flota La selección de rol/modelo del planificador de configuración ahora impulsa el perfil generado.
  • Estabilidad del tiempo de ejecución. Las caídas de la conexión MCP son explícitas (#3524), HTTP API las llamadas reutilizan un grupo de MCP compartido (#3532) y un buzón de correo de subagente por agente la telemetría se acelera para reducir el retraso de la interfaz de usuario (#3454).
  • Aprobaciones de shell en segundo plano de YOLO. Ya no aparece un comando de shell en segundo plano un modal de aprobación en modo YOLO. classify_risk marca todos los comandos de shell destructivo, por lo que el piso de seguridad de revisión automática mantuvo cada capa de fondo durante revisión, y el sitio ForcePrompt nunca revisó auto_approve, solo Los comandos en segundo plano aparecieron, ya que los shells en primer plano toman el origen Interactive y omitir esa rama.
  • Ajuste modal de aprobación de Bash. El modal de aprobación de shell ahora etiqueta a Bash comandos directamente, evita repetir comando/workdir en el resumen de impacto, envuelve comandos largos y cambia a controles compactos en terminales cortos para las claves de decisión permanecen visibles.
  • Filas de selección de proveedores personalizados. Entradas concretas [providers.<name>] ahora aparecen en el selector de proveedores (id, punto final, preparación de autenticación, protocolo de conexión, modelo actual) en lugar de sólo el marcador de posición genérico; honores de preparación de autenticación clave por entrada/env/metadatos/no-auth/loopback.
  • Descubrimiento de herramientas MCP pasivas. Los procesos MCP stdio propiedad de Runtime API no son ya no se genera a partir de solicitudes pasivas de /v1/apps/mcp/tools; descubrimiento en vivo permanece disponible a través de ?connect=true. doctor ahora advierte sobre ruta relativa Comandos stdio MCP sin cwd.

Codewhale v0.8.65

CodeWhale is the canonical project, command, npm package, and release-asset name. The legacy npm package deepseek-tui is deprecated and receives no further releases. Users coming from v0.8.x legacy deepseek / deepseek-tui names should migrate with docs/REBRAND.md.

Install

Recommended — npm (one command, both binaries)

npm install -g codewhale

The wrapper downloads the matched runtime binaries from this Release and places them in the same directory.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v ~/.deepseek:/home/codewhale/.deepseek \
  ghcr.io/hmbown/codewhale:v0.8.65

The image ships the codewhale dispatcher, codew shim, and codewhale-tui runtime. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli codewhale-tui --locked

Both crates are required — codewhale-cli produces the codewhale dispatcher and codew shim, while codewhale-tui produces the interactive runtime that the dispatcher delegates to. Installing only one crate will fail at runtime with a MISSING_COMPANION_BINARY error.

Manual download — platform archives (recommended)

Each archive below contains the codewhale dispatcher, codew shim, and codewhale-tui runtime, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Linux RISC-V | codewhale-linux-riscv64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs codewhale.exe, codew.exe, and codewhale-tui.exe under %LOCALAPPDATA%\Programs\CodeWhale\bin and adds that directory to the current-user PATH.
  • Extract codewhale-windows-x64.zip
  • Run install.bat (copies to %USERPROFILE%\bin)
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Each platform also has bare, unarchived binaries attached below (codewhale-<platform>, codew-<platform>, and codewhale-tui-<platform>) — the npm wrapper and the in-app codewhale update download the matched runtime binaries, whereas the .tar.gz / .zip archives above are the recommended manual download and additionally bundle an install script. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.

sha256sum -c codewhale-artifacts-sha256.txt

What's in v0.8.65

Added

  • Provider/model/route resolution (EPIC #2608). Canonical provider, model, offering, and route types with a single RouteResolver that produces a resolved ReadyRouteCandidate (endpoint, wire protocol, model id, context limit, price) for every switch (#3458, #3084, #3384). The executing client is now constructed from the resolved candidate rather than re-derived from config (#3384). A committed, network-free Models.dev-shaped catalog gives models real context windows and pricing, with a secret-free live cache (#3497, #3498, #3385). Offering pricing with provenance is projected onto candidates (#3501, #3085), and route limits feed a route-aware context-budget service (#3508, #3523, #3086).
  • Fleet execution substrate (EPIC #3154). Fleet profile types and config (#3469), durable manager resume, workspace agent-profile loading resolved into the worker runtime (#3367), loadout intent carried in task specs (#3512), and receipts that persist the resolved route for inspection (#3154, #3166). Worker status is folded into the unified /fleet surface and exposed through the Runtime API.
  • Provider surfaces. A /provider readiness dashboard with reasoning readiness, an experimental/supported maturity marker, and an "open models for this provider" action (#3083, #2984, #3485); cross-provider /model search with scroll and provider type-ahead (#3484, #3075); inline <think> reasoning-stream routing with per-provider overrides (#3222); usage telemetry normalized into canonical token classes including Responses cache-miss and reasoning tokens (#2961, #3509); and remote MCP OAuth login with bearer/header auth precedence (#3527).
  • More providers and routes. User-defined OpenAI-compatible custom providers via [providers.<name>] (#1519); a DeepSeek Anthropic-compatible route (#2963, #3449); a Qianfan route (#3425); Zhipu folded into Z.ai with equal-treatment model normalization (#3539); DashScope/Together fixtures.
  • Localized mode picker and composer indicators. The /mode picker prompt, mode names, and hints, plus the composer's Vim mode indicator, now render in all seven shipped locales (model-facing mode labels stay English). Harvested from #2239 by @gordonlu.
  • Website and automation. A runtime/integrations page, provenance and mirror-trust copy, a fact-drift CI gate, a published install script, and a weekly community digest archive on codewhale.net (#3419, #3421, #3415, #3482, #3420); per-automation mode/shell/trust/approval settings (#3467).
  • Model reference browser. A read-only /modeldb command (aliases model-reference, modelref) opens a pager over the bundled catalog — every model's factual context window, max output, modality, and price, grouped by provider/kind. Labels only: it never selects, routes, or tiers a model (#3205, #2300).
  • Transcript presets. A /config preset <name> [--save] mechanism with a first calm preset — calm mode, calm tool collapse, comfortable spacing, and low motion — presentation-only and evidence-preserving (#3478).
  • Model capability profiles. A typed model_profile module separates intrinsic model facts from resolved provider-route capability, so compact routes defer heavier nonessential tools while standard/full routes keep the eager tool surface (#3451, #3365).
  • Live provider catalog refresh. A secret-free /models live-fetch layer (401/403/404/429 mapped to typed outcomes) feeds the catalog cache; the API key authorizes the request but is never persisted into the delta or cache (#3385).

Changed

  • Config modularization (#3311). ProviderKind (#3505), harness posture (#3507), and provider default seeds (#3503) moved into dedicated modules, and the config.rs monolith split into clean leaf modules (paths, search, model/base-URL constants, sub-agent limits) behind a pub use facade. AppMode helpers were centralized (#3510), and mode-vs-permission policy is now derived through a single base_policy_for_mode resolver instead of scattered mutation (#3386, advisory review-intent behavior preserved).
  • Leaner tool surface. Dropped task_shell_* from the active set and folded tool_search_* (#3463); ablated the in-turn loop_guard and encoded reasoning dispositions (#3462); added the Orchestration disposition to the constitution.
  • Routing. Provider/model switches and the capability-aware fallback chain resolve through RouteResolver; reasoning effort is normalized for the resolved provider; the fallback chain now skips providers that lack auth (#2574); and context window and memory-pressure come from the resolved route (#3086).
  • UX. Approval modal gained a group divider and selected-row caret (#3515); picker scroll/type-ahead and selection contrast hardened (#3500); the README was rewritten as an architecture end-cap (#3087); and repo agent guidance was de-hardcoded to live truth.
  • Fleet identity and defaults. Fleet workers now enter with an explicit "summoned Fleet member" operating contract, setup/profile prompts keep the default model behavior as same-route inheritance, and generated worker instructions avoid leaking recursive topology that only the orchestrator needs.
  • Legacy swarm cleanup. Removed the obsolete /swarm core command/menu registration so /fleet is the product surface, while /subagents remains a compatibility shortcut to worker status.
  • Running-state animation. Tool cards and background-task rows now share one faster braille spinner cadence, so Bash/background work reads consistently alive across the transcript and sidebar.
  • Restored contributor credit. Threaded machine-readable credit (docs/CONTRIBUTORS.md + .github/AUTHOR_MAP) for earlier merged work that shipped without it, including the /jobs cancel-all action and the npm retry-timeout hint (#1538) by @jieshu666, and the community ACP adapter reference by @rockeverm3m.

Fixed

  • Release hygiene. The strict cargo clippy --workspace --all-targets --locked -- -D warnings gate passes; npm run build no longer dirties the generated web facts; the site sets metadataBase; the community digest page parses each record independently and localizes its chrome; and cargo audit is clean with the starlark-transitive unmaintained advisories documented.
  • Routing and mode correctness. Ordinary prompt text is no longer interpreted as a mode switch (#3387, #3491); model candidates are scoped to the active provider; Together-owned DeepSeek routes are accepted (#3426); insecure http:// custom endpoints raise an advisory warning (#1519); and the Fleet setup planner's role/model selection now drives the generated profile.
  • Runtime stability. MCP connection drops are explicit (#3524), HTTP API calls reuse a shared MCP pool (#3532), and per-agent sub-agent mailbox telemetry is throttled to cut UI lag (#3454).
  • YOLO background-shell approvals. A background shell command no longer pops an approval modal in YOLO mode. classify_risk marks all shell commands destructive, so the auto-review safety floor held every background shell for review, and the ForcePrompt site never checked auto_approve — only background commands surfaced it, since foreground shells take the Interactive origin and skip that branch.
  • Bash approval modal fit. The shell approval modal now labels Bash commands directly, avoids repeating command/workdir in the impact summary, wraps long commands, and switches to compact controls on short terminals so the decision keys stay visible.
  • Custom-provider picker rows. Concrete [providers.<name>] entries now appear in the provider picker (id, endpoint, auth readiness, wire protocol, current model) instead of only the generic placeholder; auth readiness honors per-entry key/env/metadata/no-auth/loopback.
  • Passive MCP tool discovery. Runtime API-owned stdio MCP processes are no longer spawned from passive /v1/apps/mcp/tools requests; live discovery remains available through ?connect=true. doctor now warns on relative-path stdio MCP commands without cwd.
