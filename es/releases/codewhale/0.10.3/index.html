¿Qué hay en v0.10.3?

Codewhale v0.10.3 ofrece una superficie de complementos unificada con modo Creador ([features] plugin_creator) y compatibilidad con complementos DeepSeek Harness (@deepseek-ai/dsh-*), un guardián de revisión automática actualizado con límites de espacio de trabajo, reglas suaves, revisión de devolución de subagente y aprobaciones de reintento de un solo uso, y un único dial de permiso Shift+Tab predeterminado para Aceptar ediciones (Ask → Accept Edits → Plan → Auto-Review → Full Access). Mueve el servidor ACP y las sesiones del agente externo (incluidos Qwen Code y GitHub Copilot CLI) al protocolo oficial del agente Client SDK, publica recursos de lanzamiento nativos firmados de HarmonyOS ARM64, agrega un canal de registro de proveedor y modelo firmado verificado junto con una resolución unificada de ID de modelo y precios administrados de /v1/models, actualiza los tokens de diseño a 5.4.0 con una conexión acoplada. franja de aprobación de una sola línea, actividad de giro plegada, barridos de luz de fila de trabajo en vivo y 13 formularios de ballena de puntos de celosía hexagonal, agrega autenticación de facturación claude-org, gráficos de transcripción show_data, codewhale sessions migrate, herramientas de voz y búsqueda web DeepSeek Chatbot, actualizaciones automáticas recibidas y codewhale uninstall, y correcciones de seguridad de confiabilidad, CJK/Unicode, Windows y sandbox.

Instalar

Recomendado: lanzamiento oficial de GitHub

Nueva instalación de macOS/Linux (archivos binarios con suma de comprobación de esta versión):

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.3" sh
"$HOME/.local/bin/codewhale" --version

Para Windows, utilice el instalador o archivo correspondiente a continuación. Para un existente instalación directa, ejecute codewhale update; imprime la ruta ejecutable y mantiene construcciones más nuevas. Si el directorio de instalación está ocupado por una compilación diferente, utilice la migración de directorio nuevo en la guía de instalación.

Embalaje secundario: npm y carga

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

El contenedor descarga los recursos de comando codewhale y codew coincidentes. de esta versión. Ambos contienen el mismo tiempo de ejecución compilado.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/codewhale-hq/codewhale:v0.10.3

La imagen muestra el mismo tiempo de ejecución que codewhale y codew. el La etiqueta latest también se actualiza en el momento del lanzamiento.

Carga (Linux / macOS)

cargo install codewhale-cli --locked

El paquete Cargo instala codewhale. Cargo no puede crear un segundo comando alias de un objetivo binario; los usuarios que quieran una ortografía más corta pueden agregar una Enlace simbólico codew a ese ejecutable instalado. El npm, Homebrew, archivo, El instalador de shell y los canales de contenedor instalan ambos nombres de comando directamente.

Windows:

  • Para la ruta del instalador, ejecute CodeWhaleSetup.exe; se instala codewhale.exe, codew.exe y codewhale.bat bajo %LOCALAPPDATA%\Programs\CodeWhale\bin, agrega ese directorio al RUTA del usuario actual y crea un acceso directo al menú Inicio que prefiere Terminal de Windows (wt.exe) cuando esté instalado.
  • Extraiga el archivo para su máquina: codewhale-windows-x64.zip o codewhale-windows-arm64.zip
  • Doble-click codewhale.bat (no el .exe sin formato) para iniciar
  • Ejecute install.bat para copiar los binarios y el iniciador a %USERPROFILE%\bin
  • Añade %USERPROFILE%\bin a tu RUTA El archivo portátil de Windows omite el script de instalación: extraiga y ejecute codewhale.bat desde cualquier directorio. El instalador de NSIS actualmente no está firmado y puede activar Windows SmartScreen hasta que se conecte un certificado de firma al proceso de lanzamiento. Cada plataforma también tiene codewhale-<platform> desnudo y sin archivar y Activos codew-<platform>. Los siete nombres de archivos codewhale-tui-<platform> adjuntas a v0.9.5 son copias de compatibilidad de bytes idénticos que se utilizan únicamente para permitir v0.9.4 clients ya instalado descubre y cruza este binario único transición; Los instaladores actuales no exponen un tercer tiempo de ejecución. El legado de la npm El paquete deepseek-tui está en desuso y no se vuelve a publicar. Para la migración de los nombres binarios heredados v0.8.x, consulte docs/REBRAND.md.

Codewhale v0.10.3

Highlights

  • Plugins become a first-class surface — A unified Plugins view plus opt-in Creator mode ([features] plugin_creator) turns extension authoring into an in-product workflow. The real win for adopters is unmodified compatibility with @deepseek-ai/dsh-* plugins: existing DeepSeek Harness plugins load as-is, so there's no porting tax. If you've been waiting for a stable extension story, this is it — expect plugin discovery to become the primary route for third-party capabilities.

  • Permission dial collapses to one key; Auto-Review hardens — Shift+Tab now cycles a single dial (Ask → Accept Edits → Plan → Auto-Review → Full Access) and, importantly, defaults to Accept Edits — re-check your mode before assuming the old prompt-on-every-write behavior. Auto-Review gains workspace boundaries, soft rules, sub-agent return review, and one-use retry approvals, making autonomous runs far more contained. The shell policy was also tightened across many PRs: safe classification for read-only deferred tools (#7431), bounded AWK/sed scanning for embedded shell (#7430), stdin/group-redirection and numactl --strict isolation (#7429), fail-closed dynamic flag/verb resolution (#7427), and new launchers (oc, vagrant, op, opam, helm, #7425/#7428). Watch-out: stricter matching can reject commands that previously sailed through.

  • External agents move onto the official ACP SDK — The ACP server and external-agent sessions (Qwen Code, GitHub Copilot CLI) now ride the maintained Agent Client Protocol SDK instead of bespoke glue. That's a durability and interoperability win for anyone wiring in a third-party agent. If you maintain such an integration, re-validate handshake and session semantics against the SDK rather than assuming byte-for-byte parity with the old bridge.

  • Signed registry, unified IDs, managed pricing — A verified signed model-and-provider channel, unified model-ID resolution, and managed /v1/models pricing target the drift between provider metadata and what you're actually billed. New routing options land too: LLMTR gateway (#7450), SearchApi web search (#7410), Opper (#7131), plus AICraft setup notes for CN/global users (#7421). Keep an eye on case-sensitive model-ID collisions in the picker (#7214) and the new bounded HTTP rate-limit recovery with quota receipts (#7220) — especially if you fan out across multiple gateways.

  • Distribution, lifecycle, and UX get a sweep — Native signed HarmonyOS ARM64 assets ship, self-updates are now receipted, and new entry points (codewhale sessions migrate, codewhale uninstall, claude-org billing auth, show_data transcript charts) close lifecycle and observability gaps. Design tokens move to 5.4.0 with a docked single-line approval strip and folded turn activity, while CJK/Unicode input gets real fixes (@-mentions after CJK text #7258/#7259, full-width spacing #7260). Caveat: the Windows NSIS installer is still unsigned and will likely trip SmartScreen — use the archive/install.bat route or pre-warn users. Verify checksums, and note the latest Docker tag moves with the release.

  • Breaking changes — None documented for v0.10.3; the above are additive or behavioral changes.

What's in v0.10.3

Codewhale v0.10.3 brings a unified Plugins surface with Creator mode ([features] plugin_creator) and unmodified DeepSeek Harness (@deepseek-ai/dsh-*) plugin compatibility, an upgraded Auto-Review guardian with workspace boundaries, soft rules, sub-agent return review, and one-use retry approvals, and a single Shift+Tab permission dial defaulting to Accept Edits (Ask → Accept Edits → Plan → Auto-Review → Full Access). It moves the ACP server and external-agent sessions (including Qwen Code and GitHub Copilot CLI) onto the official Agent Client Protocol SDK, publishes native signed HarmonyOS ARM64 release assets, adds a verified signed model-and-provider registry channel alongside unified model-ID resolution and managed /v1/models pricing, updates design tokens to 5.4.0 with a docked single-line approval strip, folded turn activity, live working-row light sweeps and 13 hex-lattice dot-whale forms, adds claude-org billing auth, show_data transcript charts, codewhale sessions migrate, DeepSeek Chatbot web search and speech tools, receipted self-updates and codewhale uninstall, and lands reliability, CJK/Unicode, Windows, and sandbox security fixes.

Install

Recommended — official GitHub release

New macOS/Linux install (checksummed binaries from this release):

curl -fsSL https://codewhale.net/install.sh | CODEWHALE_VERSION="v0.10.3" sh
"$HOME/.local/bin/codewhale" --version

For Windows, use the matching installer or archive below. For an existing direct install, run codewhale update; it prints the executable path and keeps newer builds. If the install directory is occupied by a different build, use the fresh-directory migration in the installation guide.

Secondary packaging — npm and Cargo

npm install -g codewhale
# or build from source
cargo install codewhale-cli --locked

The wrapper downloads the matched codewhale and codew command assets from this Release. Both contain the same compiled runtime.

Docker / GHCR

docker run --rm -it \
  -e DEEPSEEK_API_KEY="$DEEPSEEK_API_KEY" \
  -v codewhale-home:/home/codewhale/.codewhale \
  ghcr.io/codewhale-hq/codewhale:v0.10.3

The image exposes the same runtime as both codewhale and codew. The latest tag is also updated on release.

Cargo (Linux / macOS)

cargo install codewhale-cli --locked

The Cargo package installs codewhale. Cargo cannot create a second command alias from one binary target; users who want the shorter spelling can add a codew symlink to that installed executable. The npm, Homebrew, archive, shell-installer, and container channels install both command names directly.

Manual download — platform archives (recommended)

Each archive below contains the same runtime under the codewhale and codew command names, plus an install script:

| Platform | Archive | Install script | |---|---|---| | Linux x64 | codewhale-linux-x64.tar.gz | install.sh | | Linux ARM64 | codewhale-linux-arm64.tar.gz | install.sh | | Android ARM64 (Termux) | codewhale-android-arm64.tar.gz | install.sh | | HarmonyOS ARM64 (native) | codewhale-ohos-arm64.tar.gz | install.sh | | macOS x64 | codewhale-macos-x64.tar.gz | install.sh | | macOS ARM | codewhale-macos-arm64.tar.gz | install.sh | | Windows x64 (installer) | CodeWhaleSetup.exe | NSIS setup | | Windows x64 | codewhale-windows-x64.zip | install.bat | | Windows x64 (portable) | codewhale-windows-x64-portable.zip | — | | Windows ARM64 | codewhale-windows-arm64.zip | install.bat | | Windows ARM64 (portable) | codewhale-windows-arm64-portable.zip | — |

Unix (Linux / macOS):

tar xzf codewhale-<platform>.tar.gz
cd codewhale-<platform>
./install.sh

Windows:

  • For the installer path, run CodeWhaleSetup.exe; it installs codewhale.exe, codew.exe, and codewhale.bat under %LOCALAPPDATA%\Programs\CodeWhale\bin, adds that directory to the current-user PATH, and creates a Start Menu shortcut that prefers Windows Terminal (wt.exe) when it is installed.
  • Extract the archive for your machine: codewhale-windows-x64.zip or codewhale-windows-arm64.zip
  • Double-click codewhale.bat (not the raw .exe) to launch
  • Run install.bat to copy the binaries and launcher to %USERPROFILE%\bin
  • Add %USERPROFILE%\bin to your PATH

The portable Windows archive skips the install script — extract and run codewhale.bat from any directory. The NSIS installer is currently unsigned and may trigger Windows SmartScreen until a signing certificate is wired into the release pipeline.

Each platform also has bare, unarchived codewhale-<platform> and codew-<platform> assets. The seven codewhale-tui-<platform> filenames attached to v0.9.5 are byte-identical compatibility copies used only to let already-installed v0.9.4 clients discover and cross this single-binary transition; current installers do not expose a third runtime. The legacy npm package deepseek-tui is deprecated and is not republished. For migration from v0.8.x legacy binary names, see docs/REBRAND.md.

Verify (recommended)

Download the checksum manifests from this Release and verify:

# Linux — archive bundles
sha256sum -c codewhale-bundles-sha256.txt --ignore-missing

# Linux — individual binaries
sha256sum -c codewhale-artifacts-sha256.txt --ignore-missing

# macOS
shasum -a 256 -c codewhale-bundles-sha256.txt --ignore-missing
shasum -a 256 -c codewhale-artifacts-sha256.txt --ignore-missing
