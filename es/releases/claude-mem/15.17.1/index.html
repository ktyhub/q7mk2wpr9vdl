claude-mem v15.17.1

Las sesiones abiertas siguen capturándose después de una actualización

Desde 15.16.0, el trabajador borra las versiones antiguas de complementos del caché de complementos de Claude Code cinco minutos después de su inicio y luego cada hora. Una sesión de Claude Code que ya estaba abierta cuando llegó una actualización sigue ejecutándose desde la carpeta de la versión anterior. Una vez que el barrido eliminó esa carpeta, Claude Code se negó a ejecutar todos los ganchos claude-mem para esa sesión ("El directorio de complementos no existe"), por lo que la sesión silenciosamente dejó de guardar indicaciones, llamadas a herramientas, observaciones y resúmenes.

El barrido ahora lee los registros .in_use que Claude Code guarda para cada versión del complemento y mantiene una versión mientras cualquier sesión cargada aún se está ejecutando. Las carpetas que no se utilizan en la sesión en ejecución aún se eliminan en el siguiente barrido, por lo que la limpieza del disco de 15.16.0 permanece. El barrido del trabajador, npx claude-mem prune (y su --dry-run) y el instalador siguen la misma regla (#5971, gracias @rigel905, corrige #5970).

Correcciones

  • Contexto: una selección de proyecto explícitamente vacía no muestra nada en lugar de observaciones de cada proyecto (#5866, gracias @Afloat16).
  • Contexto: las estimaciones de costo de lectura y ahorro cuentan los hechos almacenados una vez, en lugar de contar caracteres de escape adicionales y un [] inventado para filas sin hechos (#5980, gracias @Afloat16).
  • Observador: una respuesta transmitida que llega como un rechazo cuenta como resultado generado, por lo que una transmisión interrumpida no se envía nuevamente y se cobra dos veces (#5843, gracias @Afloat16).
  • Mi trabajo: el agente API rechaza una respuesta que el proveedor cortó con content_filter, en lugar de guardar un informe incompleto (#5878, gracias @Afloat16).
  • Sincronización: una página extraída de registros sincronizados espera a otro escritor en lugar de fallar de inmediato con "la base de datos está bloqueada", por lo que una primera extracción grande ya no retrocede durante minutos (#5996).
  • Mi trabajo: el trabajador lee el historial compartido de Mi trabajo una vez por cambio en lugar de volver a leerlo todo en cada paso de sincronización (#5986).
  • Visor de la nube: un visor de la nube de inicio lento recarga su página de "inicio" hasta que el trabajador responde, y una pestaña oculta de Mi trabajo en la nube cierra su transmisión en vivo hasta que se muestra nuevamente (#5988, #5953).

Integraciones

Nuevos flujos de trabajo de memoria verificados para marcos de agentes, cada uno de ellos enfocado a un proyecto: Vercel AI SDK (#5951), LangGraph (#5954), Pydantic AI (#5955), Microsoft Agent Framework (#6017), Haystack (#6018), LlamaIndex (#6019), Google ADK (#6020), CrewAI (#6021), Strands Agents (#6023), OpenAI Agentes SDK (#6024), Agno (#6025), SmolAgents (#6026), AG2 (#6027) y AutoGen (#6028). Gracias @Afloat16 por todos ellos.

También en esta versión

  • Visor de la nube: base para enrutar cada cuenta iniciada a su propia aplicación; el comportamiento de producción no cambia (#5952).
  • eve template: el archivo de bloqueo de la plantilla incluye claude-mem 15.17.0, por lo que se instala su botón de implementación (#5968).

claude-mem v15.17.1

Open sessions keep capturing after an update

Since 15.16.0 the worker clears old plugin versions out of Claude Code's plugin cache five minutes after it starts and then hourly. A Claude Code session that was already open when an update arrived keeps running from the older version folder. Once the sweep deleted that folder, Claude Code refused to run every claude-mem hook for that session ("Plugin directory does not exist"), so the session silently stopped saving prompts, tool calls, observations and summaries.

The sweep now reads the .in_use records Claude Code keeps for each plugin version, and keeps a version while any session loaded from it is still running. Folders no running session uses are still removed on the next sweep, so the disk clean-up from 15.16.0 stays. The worker's sweep, npx claude-mem prune (and its --dry-run) and the installer all follow the same rule (#5971, thanks @rigel905, fixes #5970).

Fixes

  • Context: an explicitly empty project selection shows nothing instead of observations from every project (#5866, thanks @Afloat16).
  • Context: read-cost and savings estimates count stored facts once, instead of counting extra escape characters and an invented [] for rows without facts (#5980, thanks @Afloat16).
  • Observer: a streamed answer that arrives as a refusal counts as generated output, so an interrupted stream is not sent again and charged twice (#5843, thanks @Afloat16).
  • My Work: the API agent rejects an answer the provider cut with content_filter, instead of saving an incomplete report (#5878, thanks @Afloat16).
  • Sync: a pulled page of synced records waits for another writer instead of failing at once with "database is locked", so a large first pull no longer backs off for minutes (#5996).
  • My Work: the worker reads My Work's shared history once per change instead of re-reading all of it on every sync pass (#5986).
  • Cloud viewer: a slow-starting cloud viewer reloads its "starting" page until the worker answers, and a hidden cloud My Work tab closes its live feed until it is shown again (#5988, #5953).

Integrations

New verified memory workflows for agent frameworks, each scoped to one project: Vercel AI SDK (#5951), LangGraph (#5954), Pydantic AI (#5955), Microsoft Agent Framework (#6017), Haystack (#6018), LlamaIndex (#6019), Google ADK (#6020), CrewAI (#6021), Strands Agents (#6023), OpenAI Agents SDK (#6024), Agno (#6025), SmolAgents (#6026), AG2 (#6027) and AutoGen (#6028). Thanks @Afloat16 for all of them.

Also in this release

  • Cloud viewer: groundwork for routing each signed-in account to its own app; production behaviour is unchanged (#5952).
  • eve template: the template's lockfile includes claude-mem 15.17.0, so its deploy button installs (#5968).
