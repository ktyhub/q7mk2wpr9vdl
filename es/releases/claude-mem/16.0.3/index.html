claude-mem v16.0.3

Solución crítica

  • El enlace OMP funciona con el tiempo de ejecución del servidor (#6367, gracias @flipcyde101, cierra el #6366 informado por @walynde). Cuando CLAUDE_MEM_RUNTIME era server o server-beta, el enlace OMP aún enviaba todo al trabajador local, por lo que se descartaban las sesiones OMP. El gancho ahora lee CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY y CLAUDE_MEM_SERVER_PROJECT_ID (o los nombres CLAUDE_MEM_SERVER_BETA_*; las variables de entorno ganan a settings.json) y habla directamente con el /v1 API del servidor: inicio de sesión, eventos de herramienta y respuesta, contexto y fin de sesión. Aplica las mismas reglas que aplica el trabajador antes de guardar algo: los bloques <private> se eliminan, los proyectos excluidos y CLAUDE_MEM_SKIP_TOOLS se respetan, cada mensaje se registra y el nombre del proyecto proviene de git. Si la configuración del servidor está incompleta, vuelve al trabajador como antes.
  • Usuarios de OMP: ejecute npx claude-mem install --ide omp una vez para obtener esta solución. El enlace OMP es un archivo copiado, por lo que una actualización del complemento por sí sola no lo reemplaza.

Correcciones

  • Las consultas de conocimiento y las solicitudes de corpus ya no pueden bloquearse para siempre (n.° 6368, gracias @flipcyde101, cierra el n.° 6364 informado por @soarkit). Se utilizaba una transmisión detenida del Agente SDK para mantener viva la solicitud y su hijo Claude CLI sin fin. Una consulta de conocimiento o principal ahora se detiene después de 10 minutos y una solicitud de corpus después de 15, con un error 504. El corpus permanece bloqueado hasta que el trabajo agotado se detiene realmente, por lo que no puede escribir después de una eliminación o reconstrucción.
  • El aviso de "memorias guardadas en pausa" desaparece una vez que Codex está guardando (#6374, gracias @ryrenz, cierra el #6372 reportado por @raw34). Después de cambiar CLAUDE_MEM_PROVIDER a codex después de una pausa de cuota de Claude, cada nueva sesión todavía decía que la captura se pausaba hasta que se agotaba el antiguo tiempo de reutilización de Claude. El aviso ahora se vuelve a calcular cuando el Codex almacena una memoria.
  • server api-key create --scope sin valor se rechaza (#6375, gracias @ryrenz, cierra #6373 reportado por @soarkit). Solía ​​​​crear una clave con alcance en la cadena literal true, que luego rechazaba cada solicitud. Un --scope, --name, --team o --project desnudo ahora imprime --<flag> requires a value y sale de 1 sin escribir nada, tanto en create como en migrate-scopes.
  • El Informe de costos del agente ya no falla en observaciones sin modelo (n.° 6376, gracias @ZedingZhang, cierra el n.° 6371 informado por @Realauster). acr.py rollup planteó un TypeError cuando a una ventana le faltaba un modelo y otro con nombre y sin precio.
  • La imagen del servidor Docker se vuelve a generar (#6386, cierra #6379 informado por @InfoALR). Ahora usa node:20-trixie, porque el 0.26 necesita un glibc más nuevo que el node:20.
  • La actualización de Mi trabajo se ejecuta en OpenCode 2.x (#6361, referencias #6339 informadas por @Realauster). OpenCode 2.x rechaza los indicadores --pure y --dir, por lo que cada paso de actualización salió de 1. El paso ahora verifica opencode --version y usa el aislamiento propio de cada versión. 2.0.0 a 2.2.2 y 3.x se rechazan por una razón, porque no pueden mantener fuera los complementos. En todas las versiones, el agente de actualización ahora tiene todas las herramientas denegadas.
  • OMP y Hermes leen un puerto de trabajo guardado como un número (#6363, gracias @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} en settings.json solía ser ignorado, por lo que sus solicitudes iban al puerto predeterminado.
  • El instalador de OpenClaw ya no elimina una carpeta que no instaló (#6381, gracias @DeryFerd). Ejecutó rm -rf en cualquier ruta de instalación denominada ~/.openclaw/openclaw.json. Ahora reemplaza una carpeta solo cuando falta, está vacía o contiene el manifiesto OpenClaw de claude-mem. Todo lo demás se deja solo con una advertencia y se usa la carpeta de extensiones predeterminada; Si eso también lo toma otra cosa, el instalador se detiene.
  • El trabajador puede detener a cada hijo de Claude que inicie (#6385, gracias @DeryFerd). La compresión de campo y la conclusión de Telegram iniciaron su proceso Claude fuera de la lista de procesos del trabajador, por lo que un trabajador que salió bruscamente los dejó en ejecución. Ahora están en esa lista y no ocupan un espacio de concurrencia.
  • Una impresión atascada de CLI no puede hacer crecer la memoria del trabajador sin límite (#6384, gracias @DeryFerd). La producción recopilada de claude, codex, gemini y opencode tiene un límite de 128 Mi caracteres, aproximadamente 2.5 veces el giro real más grande medido. Más allá del límite, se mantienen el inicio y el final, se registra una advertencia y la respuesta se rechaza en lugar de leerse como una respuesta parcial. Las producciones más pequeñas se mantienen sin cambios.
  • Un registro de transcripción sin fin no puede hacer crecer la memoria del trabajador sin límite (#6383, gracias @DeryFerd). Un registro JSONL de más de 64 MiB (el registro real más grande medido fue de 44 MiB) se omite, con una advertencia que nombra el archivo, el desplazamiento del registro y su tamaño. Las líneas posteriores se leen normalmente.
  • El /v1/info no autenticado ya no muestra el texto de error Redis (#6380, gracias @DeryFerd). Se utiliza un carril de cola que no se pudo leer para publicar el error del controlador, como un host y un puerto. El motivo ahora permanece en el registro del servidor.

Nuevo

  • Límite de CPU opcional para chroma-mcp (#6369, gracias @flipcyde101, soluciona parcialmente el #6365 reportado por @FengJie2004). Configure CLAUDE_MEM_CHROMA_MAX_THREADS en 2 si chroma-mcp mantiene ocupados varios núcleos. Limita los subprocesos del incrustador y, en Linux con taskset, las CPU que croma-mcp puede usar. Está desactivado de forma predeterminada (0), porque un límite siempre activo ralentizó el primer reabastecimiento. #6365 permanece abierto.
  • AIGROW preestablecido para el proveedor compatible con OpenAI (#6370, gracias @guglielmo-io).

Servicio de sincronización alojado

  • Los servicios de sincronización comparan la credencial del proyector interno en tiempo constante (#6382, gracias @DeryFerd). Una comparación de cadenas simples podría filtrar el secreto compartido a través del tiempo de respuesta. Esto cambia services/sync-api y services/sync-hub, que no forman parte del paquete npm: llega a los usuarios solo una vez que se implementan esos servicios, no a través de esta versión.

Pruebas

  • Una prueba de transcripción inestable ahora cuenta los toques de la encuesta adjunta en lugar de acelerar la verificación de archivos (#6360). changelog completo: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3

claude-mem v16.0.3

Critical fix

  • The OMP hook works with the server runtime (#6367, thanks @flipcyde101, closes #6366 reported by @walynde). When CLAUDE_MEM_RUNTIME was server or server-beta, the OMP hook still sent everything to the local worker, so OMP sessions were dropped. The hook now reads CLAUDE_MEM_SERVER_URL, CLAUDE_MEM_SERVER_API_KEY and CLAUDE_MEM_SERVER_PROJECT_ID (or the CLAUDE_MEM_SERVER_BETA_* names; environment variables win over settings.json) and talks to the server's /v1 API directly: session start, tool and reply events, context, and session end. It applies the same rules the worker applies before it saves anything: <private> blocks are stripped, excluded projects and CLAUDE_MEM_SKIP_TOOLS are honored, every prompt is recorded, and the project name comes from git. If the server settings are incomplete, it falls back to the worker as before.
  • OMP users: run npx claude-mem install --ide omp once to get this fix. The OMP hook is a copied file, so a plugin update alone does not replace it.

Fixes

  • Knowledge queries and corpus requests can no longer hang forever (#6368, thanks @flipcyde101, closes #6364 reported by @soarkit). A stalled Agent SDK stream used to keep the request and its Claude CLI child alive with no end. A knowledge query or prime now stops after 10 minutes and a corpus request after 15, with a 504 error. The corpus stays locked until the timed-out work has really stopped, so it cannot write after a delete or rebuild.
  • The "paused saving memories" notice goes away once Codex is saving (#6374, thanks @ryrenz, closes #6372 reported by @raw34). After you switched CLAUDE_MEM_PROVIDER to codex following a Claude quota pause, every new session still said capture was paused until the old Claude cooldown ran out. The notice is now recomputed when Codex stores a memory.
  • server api-key create --scope with no value is refused (#6375, thanks @ryrenz, closes #6373 reported by @soarkit). It used to create a key scoped to the literal string true, which every request then rejected. A bare --scope, --name, --team or --project now prints --<flag> requires a value and exits 1 without writing anything, on both create and migrate-scopes.
  • The Agent Cost Report no longer crashes on observations with no model (#6376, thanks @ZedingZhang, closes #6371 reported by @Realauster). acr.py rollup raised a TypeError when one window had both a missing model and a named, unpriced one.
  • The Docker server image builds again (#6386, closes #6379 reported by @InfoALR). It now uses node:20-trixie, because tree-sitter 0.26 needs a newer glibc than node:20 ships.
  • My Work refresh runs on OpenCode 2.x (#6361, refs #6339 reported by @Realauster). OpenCode 2.x rejects the --pure and --dir flags, so every refresh step exited 1. The step now checks opencode --version and uses each version's own isolation. 2.0.0 to 2.2.2 and 3.x are refused with a reason, because they cannot keep plugins out. On every version the refresh agent now has all tools denied.
  • OMP and Hermes read a worker port saved as a number (#6363, thanks @chuenchen309). {"CLAUDE_MEM_WORKER_PORT": 45678} in settings.json used to be ignored, so their requests went to the default port.
  • The OpenClaw installer no longer deletes a folder it did not install (#6381, thanks @DeryFerd). It ran rm -rf on whatever install path ~/.openclaw/openclaw.json named. It now replaces a folder only when it is missing, empty, or holds claude-mem's own OpenClaw manifest. Anything else is left alone with a warning and the default extensions folder is used; if that is also taken by something else, the installer stops.
  • The worker can stop every Claude child it starts (#6385, thanks @DeryFerd). Field compression and the Telegram wrap-up started their Claude process outside the worker's process list, so a worker that exited hard left them running. They are now on that list, and they do not take a concurrency slot.
  • A CLI stuck printing can't grow the worker's memory without limit (#6384, thanks @DeryFerd). Output collected from claude, codex, gemini and opencode is capped at 128 Mi characters, about 2.5 times the largest real turn measured. Past the cap, the start and end are kept, a warning is logged, and the reply is refused instead of read as a partial answer. Smaller outputs are unchanged.
  • A transcript record with no end can't grow the worker's memory without limit (#6383, thanks @DeryFerd). A JSONL record over 64 MiB (the largest real record measured was 44 MiB) is skipped, with a warning that names the file, the record's offset and its size. The lines after it are read as normal.
  • The unauthenticated /v1/info no longer shows Redis error text (#6380, thanks @DeryFerd). A queue lane that could not be read used to publish the driver's error, such as a host and port. The reason now stays in the server log.

New

  • Opt-in CPU cap for chroma-mcp (#6369, thanks @flipcyde101, partly addresses #6365 reported by @FengJie2004). Set CLAUDE_MEM_CHROMA_MAX_THREADS to 2 if chroma-mcp keeps several cores busy. It caps the embedder's threads and, on Linux with taskset, the CPUs chroma-mcp can use. It is off by default (0), because an always-on cap slowed the first backfill. #6365 stays open.
  • AIGROW preset for the OpenAI-compatible provider (#6370, thanks @guglielmo-io).

Hosted sync service

  • The sync services compare their internal projector credential in constant time (#6382, thanks @DeryFerd). A plain string compare could leak the shared secret through response timing. This changes services/sync-api and services/sync-hub, which are not part of the npm package: it reaches users only once those services are deployed, not through this release.

Tests

  • A flaky transcript test now counts the append poll's pokes instead of racing its file check (#6360).

Full changelog: https://github.com/thedotmack/claude-mem/compare/v16.0.2...v16.0.3
