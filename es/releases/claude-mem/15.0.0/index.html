claude-mem v15.0.0

Búsqueda de memoria inteligente por defecto

La recuperación de memoria ahora tiene como valor predeterminado Inteligente: busque el índice compacto, inspeccione el contexto alrededor de los resultados relevantes y luego obtenga solo los detalles seleccionados. El agente razona sobre la relevancia entre estos tres pasos. Las instrucciones locales, en la nube/Pro y de servidor independiente describen las herramientas disponibles en ese tiempo de ejecución. La búsqueda opcional de una llamada ahora es dumb_search. Su descripción es explícita: "No razona sobre los resultados. Rápido, pero superficial. Utilice Smart para una recuperación confiable". Realiza coincidencias de títulos deterministas y no razona sobre la relevancia.

Migración

  • Utilice la habilidad mem-search para la recuperación inteligente predeterminada. Las herramientas locales son search → timeline → get_observations; Cloud/Pro comienza con memory_search y puede recuperar resúmenes seleccionados con get_summaries.
  • Reemplace las llamadas a los antiguos mem_search guiados/automáticos API y flash_search con el flujo de trabajo inteligente, o elija explícitamente dumb_search para una búsqueda superficial. Se eliminan los modos automático/guiado y los cursores de continuación.
  • Actualice las conexiones MCP existentes para que clients cargue el nuevo catálogo de herramientas y sus descripciones.

Corrección

  • La línea de tiempo en la nube admite el contexto anclado a un resultado de búsqueda seleccionado.
  • La recuperación del servidor independiente permanece limitada a su proyecto de servidor configurado en lugar de leer la memoria de un trabajador local.
  • La salida con detalles seleccionados informa sus límites de manera honesta y preserva las identidades de los registros seleccionados cuando se debe acortar el contenido extenso.
  • La búsqueda en memoria nativa utiliza índices de solo observación, y los índices locales mixtos retienen los prefijos de ID de sesión/solicitud, por lo que las lecturas de seguimiento no pueden seleccionar un tipo de registro diferente con el mismo número.
  • Las indicaciones del instalador, la documentación pública, las instrucciones de integración y la guía de memoria generada utilizan la misma política Smart-first.

Otros cambios desde v14.0.1

  • Se agregó soporte e instalación de memoria del Agente Hermes, incluido el manejo seguro de la configuración YAML existente.
  • Se agregó un respaldo entre una clave Anthropic API y la suscripción de Claude, con clasificación de cuota y recuperación al proveedor principal en un límite de mensaje.
  • Mantuvo las solicitudes HTTP de los trabajadores receptivas durante las lecturas del contexto local, limitó las búsquedas alternativas amplias de texto completo y eliminó los bloqueos de eliminación de etiquetas cuadráticas.
  • Corrección de la memoria mejorada: type="all" busca en todas las categorías, las observaciones eliminadas eliminan sus documentos Chroma, las salidas inesperadas de Chroma rechazan las solicitudes pendientes y los cambios de nombre fallidos de los puntos de control de Windows conservan el punto de control anterior.
  • Privacidad y manejo de solicitudes reforzados: las indicaciones totalmente privadas ya no se convierten en solicitudes de usuario almacenadas; la redacción de claves maneja los guiones finales; Los resúmenes de investigación internos de Grok no se convierten en trabajo del usuario; se reconocen las solicitudes de trabajo multilingües; y la condensación de campo de OpenRouter evita razonamientos innecesarios.
  • Instalación mejorada y confiabilidad del tiempo de ejecución en Windows, macOS, Conda, Qoder, Goose, OpenCode, Antigravity, Codex y TeamBrain. Las correcciones incluyen recursividad automática del iniciador y manejo de directorios de trabajo, limpieza de directorios temporales obsoletos, autenticación procesable y errores de tiempo de ejecución faltantes, y registro correcto del enlace del host.
  • Se agregó contexto opcional entre proyectos con CLAUDE_MEM_CONTEXT_PROJECTS=all, ordenamiento de contexto de carpetas corregido y coincidencia global, entradas de cola de resumen huérfanas caducadas y telemetría de autenticación en la nube y búsqueda de registros de directorios de datos efectivos mejorada. Las identidades de validación y entrega se registran por separado en el recibo de lanzamiento una vez completadas las compilaciones finales, la implementación y las verificaciones de paquetes.

claude-mem v15.0.0

Smart memory search by default

Memory recall now defaults to Smart: search the compact index, inspect context around relevant results, then fetch only the selected details. The agent reasons about relevance between these three steps. Local, cloud/Pro, and standalone-server instructions describe the tools available in that runtime.

The optional one-call lookup is now dumb_search. Its description is explicit: “Doesn’t reason about the results. Fast, but shallow. Use Smart for reliable recall.” It performs deterministic title matching and does not reason about relevance.

Migration

  • Use the mem-search skill for default Smart recall. Local tools are search → timeline → get_observations; Cloud/Pro starts with memory_search and can fetch selected summaries with get_summaries.
  • Replace calls to the old mem_search guided/auto API and flash_search with the Smart workflow, or explicitly choose dumb_search for a shallow lookup. Auto/guided modes and continuation cursors are removed.
  • Refresh existing MCP connections so clients load the new tool catalog and descriptions.

Correctness

  • Cloud timeline supports context anchored to a selected search result.
  • Standalone-server recall stays scoped to its configured server project rather than reading a local worker's memory.
  • Selected-detail output reports its bounds honestly and preserves selected record identities when long content must be shortened.
  • Native memory lookup uses observation-only indexes, and mixed local indexes retain session/prompt ID prefixes so follow-up reads cannot select a different record kind with the same number.
  • Installer prompts, public documentation, integration instructions, and generated memory guidance use the same Smart-first policy.

Other changes since v14.0.1

  • Added Hermes Agent memory support and installation, including safe handling of existing YAML configuration.
  • Added fallback between an Anthropic API key and the Claude subscription, with quota classification and recovery back to the primary provider at a message boundary.
  • Kept worker HTTP requests responsive during local context reads, bounded broad full-text fallback searches, and removed quadratic tag-stripping stalls.
  • Improved memory correctness: type="all" searches every category, deleted observations remove their Chroma documents, unexpected Chroma exits reject pending requests, and failed Windows checkpoint renames preserve the previous checkpoint.
  • Tightened privacy and request handling: fully private prompts no longer become stored user requests; key redaction handles trailing dashes; internal Grok research briefs do not become user work; multilingual work requests are recognized; and OpenRouter field condensation avoids unnecessary reasoning.
  • Improved installation and runtime reliability across Windows, macOS, Conda, Qoder, Goose, OpenCode, Antigravity, Codex, and TeamBrain. Fixes include launcher self-recursion and working-directory handling, stale temporary-directory cleanup, actionable authentication and missing-runtime errors, and correct host hook registration.
  • Added optional cross-project context with CLAUDE_MEM_CONTEXT_PROJECTS=all, corrected folder context ordering and glob matching, expired orphaned summary spool entries, and improved effective-data-directory log lookup and cloud authentication telemetry.

Validation and delivery identities are recorded separately in the release receipt after the final builds, deployment, and package checks complete.
