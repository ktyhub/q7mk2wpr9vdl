claude-mem v15.21.0

claude-mem ya no desactiva el modo de código de Claude Code

  • El modo de código comienza con claude-mem habilitado (#6278, gracias @naive000; informado en #6209 por @nasif-naseef). El modo de código (experimental, Claude Code 2.1.323 y posterior) se niega a iniciarse cuando el módulo de enganches de un complemento engancha tool.call. El mod de borrado automático de claude-mem lo hizo, por lo que el modo de código estaba desactivado para todos los que tenían claude-mem habilitado, incluso con el borrado automático desactivado. El mod ahora lee los resultados de la herramienta a través de session.append. El borrado automático todavía funciona en todas las versiones de Claude Code que ejecutan mods (2.1.287 y posteriores).

El borrado automático continúa donde lo dejó

El borrado automático sigue desactivado a menos que configure CLAUDE_MEM_AUTO_CLEAR_ENABLED en true. Cuando está encendido:

  • Se reanuda con un mensaje de continuación en lugar de la simple palabra "continuar" (#6294). Antes de borrar, Claude guarda su estado de trabajo por última vez, nombrando la lista desde la que está trabajando, la tarea que acaba de terminar y el objetivo general. Después de /clear, los envíos de borrado automático: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. Si al guardar se dejó alguno de los tres, envía "continuar" como antes y registra el motivo.
  • Comienza en el 40% de la ventana de contexto en lugar del 33% (#6294). Un CLAUDE_MEM_AUTO_CLEAR_PERCENT que configuraste en settings.json o el entorno aún gana.

Nuevas formas de conectarse

  • Hermes Desktop, busca y guarda en MCP (#6284, gracias @krishnadobhal; parte de #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> agrega claude-mem como servidor MCP para Hermes One y Hermes Desktop sin convertirlo en proveedor de memoria. Podrás buscar y guardar cuando los solicites; nada se captura ni se inyecta por sí solo. claude-mem hermes uninstall elimina solo lo que escribió y restaura config.yaml byte por byte.
  • GitHub Copiloto en VS Code (#6286, gracias @krishnadobhal; parte de #5895). npx claude-mem install --ide copilot-vscode escribe la entrada MCP que lee el agente Copilot de VS Code (~/.copilot/mcp-config.json, el mismo archivo que usa Copilot CLI). La entrada ahora incluye "tools": ["*"]. Sin él, VS Code se conectó a claude-mem pero nunca ofreció sus herramientas al modelo. Aún no hay captura automática.
  • Preajuste de ModelGo (#6277, gracias @lichloe1116-gif del equipo de ModelGo). El proveedor compatible con OpenAI tiene un ajuste preestablecido modelgo para https://api.modelgo.ai/v1. No establece ningún modelo predeterminado, así que elija uno que su clave pueda usar.

También nuevo

  • Cheques de escritura en estado de trabajo (#6217, gracias @vieGPT). Puede hacer que work_state_write ejecute un comando de verificación local antes de escribir en las listas que elija, configuradas en ~/.claude-mem/work-state-write-guard.json. Una escritura rechazada devuelve HTTP 409 y no se guarda nada. Sin archivo, nada cambia.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, gracias @Moep90; #6223). Un objeto JSON agregado a cada solicitud que envía el agente api (la actualización de Mi trabajo y el agente de corpus con api). Para un modelo Qwen en vLLM, {"chat_template_kwargs":{"enable_thinking":false}} desactiva el razonamiento. Los campos como model, messages y max_tokens se eliminan con una advertencia y nunca se envían a la puerta de enlace cmem.ai.

Actualización de mi trabajo

  • Las respuestas lentas de tu propio modelo ya no fallan en aproximadamente 5 minutos (#6224, gracias @Moep90; #6222). La búsqueda de Bun abandonó una conexión que había estado en silencio durante 5 minutos, antes de que se aplicara el límite de solicitud de 10 minutos del agente api. Ahora ese límite es el único.
  • Puntos finales que quieren que max_completion_tokens funcione (#6242). Cuando un punto final rechaza max_tokens, el agente api envía la solicitud una vez más con max_completion_tokens, en lugar de fallar en todas las llamadas con HTTP 400.
  • Una actualización ya no se detiene en una respuesta que se rechazó dos veces (#6212, gracias @Moep90). En un reintento de agrupación, enfoque o revisión, las partes que no pasan las comprobaciones se descartan y el resto se guarda. Antes, el mismo lote fallaba en cada ejecución.
  • La historia de construcción está escrita en partes (#6279, gracias @0xABCD01; reportado en #6226 por @Moep90). El paso de la historia envió cada revisión modificada en una pregunta. Esa pregunta pasó más allá de la ventana de contexto del modelo y cada actualización posterior falló. Ahora envía piezas que se ajustan al mismo presupuesto de preguntas que utilizan los otros pasos.
  • Las conversaciones largas se agrupan según sus últimas solicitudes, no según las diez primeras (#6243, gracias @Afloat16).
  • Se reconocen las confirmaciones realizadas con git commit --message o --message= (#6236, gracias @Afloat16).
  • Una confirmación obtiene un enlace GitHub solo cuando la evidencia nombra un repositorio (#6237, gracias @Afloat16).
  • Mientras Mis reglas espera a un agente, vincula las instrucciones para configurar una actualización de API (#6214, gracias @liuyinchu).

Configurar, importar y exportar

  • La configuración finaliza cuando el historial de mensajes es grande (#6280, gracias @0xABCD01; #6266; informado en #6227 por @deserteaglemj). La configuración se detuvo al 99% en "Encontrar su trabajo reciente" cuando las indicaciones recientes superaron el límite de carga alojada de 2 MiB y todos los reintentos fallaron de la misma manera. Ahora finaliza la configuración en su máquina y lo dice. El paso de consentimiento también muestra "Demasiado para una carga. Desmarque una herramienta u omita el análisis". y apaga el botón de carga hasta que la selección encaje.
  • Importación de grandes exportaciones (#6261, gracias @Afloat16). Un archivo que superaba el límite de solicitud de 5 MiB del trabajador fue rechazado (HTTP 413) antes de que se guardara algo. Los archivos grandes ahora se envían por partes, primero las sesiones, con su contenido completo.
  • Las observaciones importadas se encuentran mediante deduplicación de la misma manera que las reales, cuando CLAUDE_MEM_DEDUP_ENABLED está activado (#6263, gracias @Afloat16).
  • claude-mem import --dry-run ya no se detiene ante una configuración de trabajador incorrecta, ya que una vista previa nunca llama al trabajador (#6215, gracias @liuyinchu).
  • Las conversaciones de Codex Desktop importadas de otro agente ya no se cuentan como mensajes escritos en Codex (#6219, gracias @rigel905; #6218).
  • Exportando a /dev/stdout, /dev/stderr, un enlace simbólico a cualquiera de ellos, o un FIFO escribe JSON limpio allí, y las líneas de progreso y las advertencias van a la otra secuencia (#6288, de #6258 por @Afloat16).

Correcciones

  • Windows: Claude Code carga RULES-AND-TOOLS.md nuevamente (#6234, gracias @QuantScorpus). claude-mem escribió sus líneas de importación @ con barras invertidas. Claude Code omite aquellos que no contienen una palabra, y claude-mem también omitió su otra copia de las instrucciones, por lo que ninguna llegó al modelo. Las líneas ahora usan barras diagonales. Una importación @ que se muestra dentro de un ejemplo de código delimitado ya no cuenta como real (n.° 6293, del n.° 6241 de @Afloat16).
  • claude-mem start ejecuta el trabajador instalado (#6235, gracias @ZedingZhang; informado en #6228 por @ExactDoug), no la copia a la que apunta un antiguo alias de shell, a la que pueden faltar sus dependencias.
  • Las copias de seguridad mantienen la nueva instantánea después de que el reloj se retrasa (#6273, gracias @Afloat16). Antes, la limpieza podía eliminar la instantánea que acababa de informar como guardada.
  • teambrain join activa la nueva conexión de sincronización incluso cuando falla el paso opcional para compartir (#6275, gracias @Afloat16).
  • Los resúmenes sin progreso no se almacenan (#6202, gracias @ShitK). Un resumen con sólo un título o planes de futuro solía guardarse y anunciarse como un éxito.
  • Los mensajes automáticos de Claude Code ya no dividen una solicitud (#6251, gracias @Afloat16). Los escaneos del asesor y de los entregables los trataron como nuevas solicitudes y perdieron los consejos anteriores y las escrituras de archivos del mismo turno.
  • Corpus construye más de 250.000 trabajos de observaciones (#6271, gracias @Afloat16). Fallaron con too many SQL variables.
  • Codex: un complemento desactivado con una tecla TOML punteada permanece desactivado (#6239, gracias @Afloat16), por ejemplo plugins."claude-mem@claude-mem-local".enabled = false.
  • El frontmatter de la habilidad de búsqueda de memoria es válido YAML (n.° 6276, gracias @Afloat16; informado en el n.° 6267 por @orbiutyt).
  • Aider: el instalador edita el archivo de configuración que Aider realmente usa (primero el directorio de trabajo, luego git root, luego home) (#6289, de #6230 de @Afloat16), y mantiene intactas las rutas de los archivos citados en las listas read: (#6290, de #6231 de @Afloat16).
  • Los archivos de contexto de Cursor y Grok mantienen el contexto más nuevo cuando se superponen dos actualizaciones (#6291, de #6232 por @Afloat16).
  • Servidor autohospedado: un trabajo con una clave revocada o una infracción de alcance se ejecuta una vez en lugar de tres veces (#6252), y claude-mem server jobs retry se vuelve a publicar con los reintentos y retrocesos de la cola (#6253), gracias @HEOJUNFO. El proveedor de OpenRouter lee como máximo 64 KiB cuando verifica una respuesta para un error de campo de token (#6238, gracias @Afloat16). Un evento de agente ilegible ya no interrumpe cada lectura de esa tabla (#6199, gracias @DeryFerd).

Seguridad

  • shell-quote 1.11.0 (#6205, gracias @manippoudel; reportado en #6200 por @lucasbritolubro). La versión 1.9.0 está en el rango de CVE-2026-102422 (crítica). Ninguna ruta de código en claude-mem alcanzó el código afectado; esto lo saca de lo que se envía.
  • adm-zip 0.6.1 y zod 4.6.7 en el tiempo de ejecución del complemento, fuera de sus avisos altos (n.° 6220, gracias @LeviReisJs; informado en el n.° 6211 por @noumanbhatti).
  • La clave Gemini API va en un encabezado, no en la URL de solicitud (#6196, gracias @DeryFerd), por lo que los servidores proxy y los registros de acceso no la registran.
  • Los archivos temporales obtienen un nombre aleatorio y se crean exclusivamente en los sitios de escritura atómica restantes (#6198, #6193, gracias @DeryFerd), por lo que un enlace simbólico instalado no puede redirigir una escritura de configuraciones o archivos de estado.
  • El /v1/info no autenticado del servidor autohospedado muestra solo el estado (#6195, gracias @DeryFerd): sin modo de autenticación, versión de esquema, host Redis o texto de error del controlador.
  • CI: la verificación de la lista de permitidos posterior a la instalación inspecciona cada dependencia directa del complemento (#6197), y la verificación del entorno de generación lee los bloques env declarados encima de una generación y escanea el tiempo de ejecución del complemento (#6194), gracias @DeryFerd.

Para contribuyentes

  • TypeScript 7.0.2 (#6207, gracias @krishnadobhal; #6188). Los scripts y pruebas que utilizan el compilador API mantienen TypeScript 6 mediante un alias.
  • La prueba de humo de importación cierra sus lectores SQLite antes del escaneo final (#6216, gracias @liuyinchu).

claude-mem v15.21.0

claude-mem no longer turns off Claude Code's Code Mode

  • Code Mode starts with claude-mem enabled (#6278, thanks @naive000; reported in #6209 by @nasif-naseef). Code Mode (experimental, Claude Code 2.1.323 and later) refuses to start when a plugin's hooks module hooks tool.call. claude-mem's auto-clear mod did, so Code Mode was off for everyone with claude-mem enabled, even with auto-clear off. The mod now reads tool results through session.append instead. Auto-clear still works on every Claude Code version that runs mods (2.1.287 and later).

Auto-clear picks up where it left off

Auto-clear is still off unless you set CLAUDE_MEM_AUTO_CLEAR_ENABLED to true. When it is on:

  • It resumes with a continuation prompt instead of the bare word "continue" (#6294). Before clearing, Claude saves its work state one last time, naming the list it is working from, the task it just finished and the overall goal. After /clear, auto-clear sends: You are working on "<list>" and recently completed "<task>". Pick back up on our overarching goal "<goal>" from where you left off. If that save left any of the three out, it sends "continue" as before and logs why.
  • It starts at 40% of the context window instead of 33% (#6294). A CLAUDE_MEM_AUTO_CLEAR_PERCENT you set in settings.json or the environment still wins.

New ways to connect

  • Hermes Desktop, search and save over MCP (#6284, thanks @krishnadobhal; part of #5940). claude-mem hermes install --mcp-only --project-cwd <absolute-directory> adds claude-mem as an MCP server for Hermes One and Hermes Desktop without making it the memory provider. You get search and save when you ask for them; nothing is captured or injected on its own. claude-mem hermes uninstall removes only what it wrote and restores config.yaml byte for byte.
  • GitHub Copilot in VS Code (#6286, thanks @krishnadobhal; part of #5895). npx claude-mem install --ide copilot-vscode writes the MCP entry that VS Code's Copilot agent reads (~/.copilot/mcp-config.json, the same file Copilot CLI uses). The entry now includes "tools": ["*"]. Without it, VS Code connected to claude-mem but never offered its tools to the model. No automatic capture yet.
  • ModelGo preset (#6277, thanks @lichloe1116-gif of the ModelGo team). The OpenAI-compatible provider has a modelgo preset for https://api.modelgo.ai/v1. It sets no default model, so pick one your key can use.

Also new

  • Work-state write checks (#6217, thanks @vieGPT). You can make work_state_write run a local check command before it writes to lists you choose, set in ~/.claude-mem/work-state-write-guard.json. A refused write returns HTTP 409 and nothing is saved. With no file, nothing changes.
  • CLAUDE_MEM_API_AGENT_EXTRA_BODY (#6225, thanks @Moep90; #6223). A JSON object added to every request the api agent sends (the My Work refresh and the corpus agent with api). For a Qwen model on vLLM, {"chat_template_kwargs":{"enable_thinking":false}} turns reasoning off. Fields such as model, messages and max_tokens are dropped with a warning, and it is never sent to the cmem.ai gateway.

My Work refresh

  • Slow answers from your own model no longer fail at about 5 minutes (#6224, thanks @Moep90; #6222). Bun's fetch gave up on a connection that had been quiet for 5 minutes, before the api agent's 10-minute request limit applied. Now that limit is the only one.
  • Endpoints that want max_completion_tokens work (#6242). When an endpoint refuses max_tokens, the api agent sends the request once more with max_completion_tokens, instead of failing every call with HTTP 400.
  • A refresh no longer stalls on an answer that was refused twice (#6212, thanks @Moep90). On the one retry for grouping, focus or review, the parts that fail the checks are dropped and the rest is saved. Before, the same batch failed on every run.
  • The build story is written in parts (#6279, thanks @0xABCD01; reported in #6226 by @Moep90). The story step sent every changed review in one question. That question grew past the model's context window, and every refresh after that failed. It now sends parts that fit the same question budget the other steps use.
  • Long conversations are grouped by their latest requests, not their first ten (#6243, thanks @Afloat16).
  • Commits made with git commit --message or --message= are recognized (#6236, thanks @Afloat16).
  • A commit gets a GitHub link only when the evidence names one repository (#6237, thanks @Afloat16).
  • While My Rules waits for an agent, it links the instructions for setting up an API refresh (#6214, thanks @liuyinchu).

Setup, import and export

  • Setup finishes when your prompt history is large (#6280, thanks @0xABCD01; #6266; reported in #6227 by @deserteaglemj). Setup stopped at 99% on "Finding your recent work" when the recent prompts were over the 2 MiB hosted upload limit, and every retry failed the same way. It now finishes setup on your machine and says so. The consent step also shows "Too much for one upload. Untick a tool or skip the scan." and turns off the upload button until the selection fits.
  • Large exports import (#6261, thanks @Afloat16). A file over the worker's 5 MiB request limit was refused (HTTP 413) before anything was saved. Large files are now sent in parts, sessions first, with their full content.
  • Imported observations are found by deduplication the same way live ones are, when CLAUDE_MEM_DEDUP_ENABLED is on (#6263, thanks @Afloat16).
  • claude-mem import --dry-run no longer stops on a bad worker setting, since a preview never calls the worker (#6215, thanks @liuyinchu).
  • Conversations Codex Desktop imported from another agent are no longer counted as prompts typed in Codex (#6219, thanks @rigel905; #6218).
  • Exporting to /dev/stdout, /dev/stderr, a symlink to either, or a FIFO writes clean JSON there, and progress lines and warnings go to the other stream (#6288, from #6258 by @Afloat16).

Fixes

  • Windows: Claude Code loads RULES-AND-TOOLS.md again (#6234, thanks @QuantScorpus). claude-mem wrote its @ import lines with backslashes. Claude Code skips those without a word, and claude-mem then also left out its other copy of the instructions, so neither reached the model. The lines now use forward slashes. An @ import shown inside a fenced code example no longer counts as the real one (#6293, from #6241 by @Afloat16).
  • claude-mem start runs the installed worker (#6235, thanks @ZedingZhang; reported in #6228 by @ExactDoug), not the copy an old shell alias points at, which can be missing its dependencies.
  • Backups keep the new snapshot after the clock is set back (#6273, thanks @Afloat16). Before, cleanup could delete the snapshot it had just reported as saved.
  • teambrain join turns on the new sync connection even when the optional sharing step fails (#6275, thanks @Afloat16).
  • Summaries with no progress in them are not stored (#6202, thanks @ShitK). A summary with only a title or future plans used to be saved and announced as a success.
  • Claude Code's automatic messages no longer split a request (#6251, thanks @Afloat16). The advisor and deliverable scans treated them as new requests and lost earlier advice and file writes from the same turn.
  • Corpus builds over 250,000 observations work (#6271, thanks @Afloat16). They failed with too many SQL variables.
  • Codex: a plugin turned off with a dotted TOML key stays off (#6239, thanks @Afloat16), for example plugins."claude-mem@claude-mem-local".enabled = false.
  • The mem-search skill's frontmatter is valid YAML (#6276, thanks @Afloat16; reported in #6267 by @orbiutyt).
  • Aider: the installer edits the config file Aider actually uses (working directory first, then git root, then home) (#6289, from #6230 by @Afloat16), and keeps quoted file paths intact in read: lists (#6290, from #6231 by @Afloat16).
  • Cursor and Grok context files keep the newer context when two refreshes overlap (#6291, from #6232 by @Afloat16).
  • Self-hosted server: a job with a revoked key or a scope violation runs once instead of three times (#6252), and claude-mem server jobs retry republishes with the queue's retries and backoff (#6253), thanks @HEOJUNFO. The OpenRouter provider reads at most 64 KiB when it checks an answer for a token-field error (#6238, thanks @Afloat16). One unreadable agent event no longer breaks every read of that table (#6199, thanks @DeryFerd).

Security

  • shell-quote 1.11.0 (#6205, thanks @manippoudel; reported in #6200 by @lucasbritolubro). Version 1.9.0 is in the range of CVE-2026-102422 (critical). No code path in claude-mem reached the affected code; this takes it out of what ships.
  • adm-zip 0.6.1 and zod 4.6.7 in the plugin runtime, out of their High advisories (#6220, thanks @LeviReisJs; reported in #6211 by @noumanbhatti).
  • The Gemini API key goes in a header, not the request URL (#6196, thanks @DeryFerd), so proxies and access logs don't record it.
  • Temp files get a random name and are created exclusively at the remaining atomic-write sites (#6198, #6193, thanks @DeryFerd), so a planted symlink can't redirect a write of settings or state files.
  • The self-hosted server's unauthenticated /v1/info shows state only (#6195, thanks @DeryFerd): no auth mode, schema version, Redis host or driver error text.
  • CI: the postinstall allowlist check inspects every direct plugin dependency (#6197), and the spawn environment check reads env blocks declared above a spawn and scans the plugin runtime (#6194), thanks @DeryFerd.

For contributors

  • TypeScript 7.0.2 (#6207, thanks @krishnadobhal; #6188). The scripts and tests that use the compiler API keep TypeScript 6 through an alias.
  • The import smoke test closes its SQLite readers before the final scan (#6216, thanks @liuyinchu).
