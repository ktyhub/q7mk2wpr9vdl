¿Qué ha cambiado?

Nuevas funciones

Herramienta de entrada de selección múltiple

  • Los nodos de herramientas de flujo de trabajo ahora admiten entradas desplegables de selección múltiple, lo que permite a los usuarios elegir múltiples valores de una lista predefinida al configurar los parámetros de la herramienta. (#39346)

Localizador de nodos de flujo de trabajo

  • Ahora puede click un node_id en los registros de ejecución del flujo de trabajo o mensajes de error para localizar y resaltar el nodo correspondiente en el lienzo del editor de flujo de trabajo. (#38187)

Mejoras en el selector de bloques de flujo de trabajo

  • El panel de selección de bloques ahora presenta navegación con teclado mejorada, vistas previas de categorías y una experiencia de búsqueda más intuitiva al agregar nodos a los flujos de trabajo. (#39212)

Exportar Agente DSL desde la barra lateral

  • Las aplicaciones del agente ahora se pueden exportar como DSL YAML directamente desde el menú de la barra lateral de la aplicación, lo que facilita la realización de copias de seguridad o el control de versiones de las configuraciones del agente. (#39299)

Seguimiento de conocimientos

  • Se agregaron más rastros de observabilidad a las operaciones de procesamiento de documentos de conocimiento/RAG, mejorando la visibilidad de los canales de indexación. (#38959)

Mejoras de seguridad

  • La zona de pruebas local del Agente ahora se ejecuta detrás de un proxy de reenvío Squid dedicado con reglas ACL estrictas, lo que evita que la zona de pruebas llegue directamente a los servicios internos. Solo se permiten el punto final /files/ en API y /agent-stub/ en agent_backend, ambos protegidos con tokens de acceso de corta duración. Esto reduce significativamente el radio de ejecución de código arbitrario en el entorno limitado del agente. (#39544)
  • La comunicación entre Dify API y el backend del agente ahora utiliza autenticación basada en token a través de DIFY_AGENT_API_TOKEN / AGENT_BACKEND_API_TOKEN, lo que refuerza los límites del servicio interno. (#39622)
  • Se cambió la representación de la plantilla Jinja2 para usar SandboxedEnvironment, evitando ataques de inyección de plantilla en los nodos de código de flujo de trabajo (#39609)
  • Vulnerabilidad DoS de componentes de React Server parcheados (#39539)
  • Se utilizó re.fullmatch en el validador de correo electrónico para rechazar nuevas líneas finales, evitando ataques de omisión (#39320)
  • Estado de cuenta validado antes de aceptar invitaciones al espacio de trabajo (#39438)

Rendimiento

  • Punto final ligero de aplicaciones recientes: el nuevo punto final GET /console/api/apps/recent reduce la latencia de la sección "Continuar trabajo" de la página de inicio en ~69% (3.2× más rápido), reduciendo las consultas SQL de 19+ a 1 proyección SELECT y el tamaño de respuesta en ~50% (#39625).
  • Modales de creación de inicio de carga diferida: carga diferida del código modal de creación hasta la interacción, lo que reduce el paquete inicial JavaScript (#39634)

[!IMPORTANTE] DIFY_AGENT_API_TOKEN es una nueva variable requerida para la comunicación segura entre Dify API y el backend del agente. El valor predeterminado (dify-agent-run-token-for-dev-only) no es seguro y debe reemplazarse en producción. Genera uno con:

python -c 'import secrets; print(secrets.token_urlsafe(32))'

Establezca el mismo valor que AGENT_BACKEND_API_TOKEN en el lado del backend del agente.

Guía de actualización

Migración de tipo de modelo

[!IMPORTANTE]

Migración única del tipo de modelo heredado para actualizaciones autohospedadas

Si esta implementación se actualizó desde una versión de Dify anterior a 1.15.0 y esta migración aún no se ha aplicado, ejecútela después de la actualización.

Esta migración no está incluida en flask db upgrade. Sin él, los registros de modelos heredados pueden provocar que las solicitudes API relacionadas con el modelo fallen con errores, lo que impide que se carguen o utilicen los modelos afectados.

Haga una copia de seguridad de la base de datos antes de aplicar la migración. El comando se ejecuta en modo de prueba de forma predeterminada; revise el resultado antes de volver a ejecutarlo con --apply. La migración es idempotente y se puede volver a ejecutar de forma segura.

Docker Redactar

Ejecute desde el directorio docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implementación del código fuente

Ejecute desde la raíz del repositorio después de completar flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Después de aplicar la migración, ejecute nuevamente el comando de ejecución en seco. Si no informa actualizaciones o eliminaciones de filas adicionales, reinicie los servicios relevantes y verifique que los modelos existentes se puedan cargar e invocar correctamente.

Docker Redactar (recomendado)

cd docker
docker compose down
git pull origin main
docker compose pull
docker compose up -d

Las migraciones de la base de datos se ejecutarán automáticamente al inicio.

[!IMPORTANTE] Revisar la nueva variable DIFY_AGENT_API_TOKEN en .env. El valor predeterminado es inseguro: genere un token seguro para producción:

python -c 'import secrets; print(secrets.token_urlsafe(32))'

Código fuente

git pull origin main
cd api
flask db upgrade

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

Docker Compose (Recommended)

cd docker
docker compose down
git pull origin main
docker compose pull
docker compose up -d

The database migrations will run automatically on startup.

[!IMPORTANT] Review the new DIFY_AGENT_API_TOKEN variable in .env. The default value is insecure — generate a secure token for production:

python -c 'import secrets; print(secrets.token_urlsafe(32))'
