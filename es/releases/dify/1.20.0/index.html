dify 1.20.0

Dify 1.20.0 mantiene el flujo de sus rastros y sus bases de conocimiento más seguras. Exporte los rastros a cualquier recopilador OpenTelemetry, mantenga a Langfuse trabajando después de retirar su endpoint de ingestión heredado y analice los archivos de conocimiento cargados en busca de malware antes de indexarlos. Los flujos de chat pueden mostrar la actividad de la herramienta del agente a medida que ocurre, y los tokens de acceso personal permiten que los scripts y los agentes llamen al Dify OpenAPI en su nombre. El demonio del complemento incluido se actualizó a 0.6.15-local. Nuevas funciones · Cambios de configuración e integración · Migraciones de bases de datos · Guía de actualización

Nuevas funciones

Nuevo HITL: incorpora aprobaciones a las herramientas de mensajería de tu equipo

Integre la revisión humana en sus flujos de trabajo a través del correo electrónico y las herramientas de mensajería que su equipo ya usa. El nuevo HITL presenta canales compartidos, contactos centralizados, plantillas de notificación y formularios de aprobación verificados, lo que permite a su equipo configurar destinatarios una vez y reutilizarlos en nodos de entrada humana, y ahora está habilitado de forma predeterminada (NEXT_PUBLIC_ENABLE_HITL_IM=true). (#44864, #45945)

  • Llegue a los aprobadores donde trabajan. Configure el correo electrónico y una plataforma de mensajería instantánea (Slack, Feishu/Lark, Microsoft Teams, DingTalk o WeCom) para entregar solicitudes de revisión del flujo de trabajo a través de los canales existentes de su equipo.
  • Administre destinatarios en Contactos. Sincronice directorios de mensajería instantánea y seleccione aprobadores de una lista de contactos compartida. Los flujos de trabajo también pueden dirigirse al iniciador o utilizar destinatarios de correo electrónico dinámicos y únicos.
  • Aprobar en tarjetas o formularios. Los destinatarios pueden revisar las solicitudes directamente en tarjetas de mensajería instantánea compatibles o abrir formularios independientes, con inicio de sesión en Dify o verificación por correo electrónico para verificar su identidad.
  • Personalice las notificaciones con el contexto del flujo de trabajo. Utilice plantillas y variables del flujo de trabajo para incluir el contexto esencial en los asuntos y cuerpos de las notificaciones.
  • Pruebe y realice un seguimiento de la entrega. Envíe notificaciones de prueba para verificar su configuración e inspeccione los registros de entrega para solucionar problemas con las solicitudes que no llegaron como se esperaba.
  • Adopte el nuevo HITL en los flujos de trabajo existentes. Utilice la migración voluntaria para actualizar los nodos de entrada humana heredados cuando su flujo de trabajo esté listo. Los requisitos de implementación se enumeran en [Cambios de configuración e integración] (#cambios-de-configuración-e-integración-de-contenido-de-usuario).

Exportar trazas a cualquier recopilador OpenTelemetry

Incorpore los seguimientos de ejecución de Dify a su pila de observabilidad existente. El nuevo proveedor OpenTelemetry exporta seguimientos de aplicaciones y agentes a cualquier recopilador compatible, lo que le permite realizar un seguimiento de los pasos del flujo de trabajo, las llamadas de modelos y la actividad de las herramientas en conjunto en su plataforma preferida. Utilice estos seguimientos para inspeccionar la ejecución de solicitudes y diagnosticar fallas sin requerir una integración Dify específica del proveedor. (#45659) El rastreo de Langfuse ahora es compatible con Langfuse v4 y el servicio de ingesta actual de Langfuse Cloud. Las configuraciones existentes de Langfuse continúan funcionando. (#45606)

[!IMPORTANTE] Langfuse Cloud retiró su punto final de ingestión heredado el 16 de noviembre de 2026 y Langfuse v4 autohospedado rechaza los eventos que se le envían. Actualice a 1.20.0 para seguir entregando seguimientos a esas implementaciones.

Analizar cargas de conocimientos en busca de malware

Proteja sus bases de conocimientos escaneando los archivos cargados en busca de malware antes de extraerlos o indexarlos. Cuando está habilitado (FILE_SCAN_ENABLED=true), los propietarios y administradores del espacio de trabajo pueden configurar los escáneres una vez en Integraciones → Análisis de seguridad de archivos y luego definir cómo los utiliza cada base de conocimientos. Los escáneres compatibles incluyen Cloudmersive, Scanii, OPSWAT MetaDefender Cloud y un Custom Endpoint. (#46090, #46492)

  • Elija protección por base de conocimientos. Seleccione un escáner y configure el comportamiento de respaldo cuando el escaneo no esté disponible o un archivo no se pueda escanear.
  • Proteja las cargas de conocimientos en Dify. El escaneo cubre bases de conocimientos clásicas, fuentes de archivos locales de RAG Pipeline y cargas de bases de conocimientos de agentes.
  • Vea por qué se bloquearon los archivos. Los errores de escaneo aparecen en la lista de documentos para su revisión.

Ver las herramientas del agente funcionan en Chatflow

Cuando un Chatflow delega tareas a un nodo Agent v2 (requiere NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true), los usuarios ahora pueden ver qué herramientas invoca en tiempo real. La actividad de la herramienta aparece junto con la respuesta tanto en las vistas previas como en los chats publicados, lo que facilita el seguimiento del progreso del Agente. Expanda cualquier tarjeta de herramienta para inspeccionar lo que solicitó y devolvió. (#46220)

Automatiza las llamadas de OpenAPI con tokens de acceso personal

Otorgue acceso a scripts, trabajos de CI y agentes personales al Dify OpenAPI en su nombre sin compartir su sesión de consola. Cree un token de acceso personal desde su página Cuenta y afínelo a espacios de trabajo y recursos específicos. Puede establecer una fecha de vencimiento opcional, actualizar su alcance a medida que evoluciona su automatización o revocarla cuando ya no sea necesaria. (#45540, #46606)

Elija fuentes de conocimiento GitHub de un árbol

Explore y seleccione el contenido de GitHub que desea agregar a una base de conocimientos desde un árbol expandible de repositorios, directorios, incidencias y solicitudes de extracción. Explore la estructura de fuentes y elija las páginas exactas para importar, ya sea que esté creando una nueva base de conocimientos o agregando una fuente a una existente. (#45990)

Busca y navega en pantallas más pequeñas

Busque en todo el contenido y limite los resultados utilizando ámbitos seleccionables en Ir a cualquier cosa. En pantallas más pequeñas, la búsqueda y la navegación se abren en cajones para conservar espacio para la página actual. (#45675, #45650) Los enlaces directos ahora pueden abrir los flujos de creación de plantillas o aplicaciones en blanco de Studio. (#45717)

Descripciones de conocimientos y metadatos más flexibles

  • Descripciones de bases de conocimientos más largas. Los límites de longitud de descripción aumentados le permiten proporcionar más contexto para cada base de conocimientos. (#45075)
  • Metadatos de conocimiento externo. La recuperación de conocimiento externo ahora devuelve metadatos del documento junto con el contenido. (#22496)

Mejoras

Reducción de la base de datos y de la sobrecarga de inicio. Las actualizaciones de ejecución de nodos evitan recargar las filas almacenadas, las políticas de credenciales se evalúan una vez por configuración del proveedor, los valores predeterminados del modelo utilizan sesiones de corta duración y las llamadas de inserción ya no mantienen abierta una sesión de base de datos. Las dependencias de funciones web también se cargan de forma más lenta. (#46410, #46441, #45806, #45788, #46145) Errores de documentos más claros y diseños más estables. Los documentos de conocimiento ahora informan razones de error específicas y etapas de procesamiento. Los diálogos se adaptan a ventanas de visualización estrechas y mantienen ciclos de vida consistentes en cuentas, conocimientos, aplicaciones, habilidades y flujos de trabajo. Las páginas de autenticación se cargan más rápido, se adaptan a pantallas más pequeñas y mantienen accesible el foco del teclado. Los controles segmentados se animan suavemente mientras conservan diseños compactos y respetan las preferencias de movimiento reducido. (#45128, #46487, #45686, #45668, #45634, #45600, #45640, #45974)

Corrección de errores

  • Vistas previas de archivos y enlaces firmados más seguros. Vistas previas de SVG en línea en Sandbox y verifique la firma original antes de renovar enlaces de archivos caducados. (#46505)
  • Protección de acceso más sólida. Redacte los detalles de reintento de nodos de las transmisiones públicas, evite la reutilización de devoluciones de llamadas de OAuth, aplique permisos de funciones de miembros y alcance la eliminación de vectores en el conjunto de datos de destino. (#46517, #46001, #46053, #45586)
  • Actualizaciones de dependencias de seguridad. Actualice github.com/klauspost/compress en dify-agent-runtime para abordar CVE-2026-116591 y actualice Node.js en imágenes en tiempo de ejecución a la versión de seguridad 24.22.3. (#46544, #46206, #46064)
  • Flujos de trabajo de bloqueo confiables. Libere las conexiones de la base de datos antes de la ejecución y devuelva los errores de preparación inmediatamente, lo que evita el agotamiento del grupo de conexiones y las solicitudes suspendidas que esperan hasta que se agote el tiempo de espera. (#46254)
  • Trabajadores más estables. Resuelva el bucle ocupado Redis BRPOP y evite la superposición de comprobaciones de actualización de complementos, limitando la simultaneidad a 20 comprobaciones entre trabajadores. (#45940, #46500)
  • Completar transmisiones de Chatflow. Cierra las transmisiones correctamente después de las respuestas directas y restablece el presupuesto de reconexión cuando se reanude una transmisión. (#45552, #46110)
  • Ejecución correcta del Agente. Conserve llamadas paralelas a la misma herramienta de complemento, pase entradas de aplicaciones declaradas a las ejecuciones del Agente y entregue imágenes cargadas a modelos de visión. (#45207, #45425, #45745)
  • Recuperación precisa de conocimientos. Restaure los resultados de palabras clave/híbridos de Weaviate devolviendo puntuaciones de BM25 y mantenga los vectores integrados alineados cuando se elimina un elemento del lote. (#45642, #45569)
  • Herramientas API personalizadas confiables. Resuelve variables del servidor OpenAPI, parámetros de ruta de codificación porcentual y admite uniones anulables OpenAPI 3.1. (#46504, #45965, #45895)

Configuración de trabajador y proxy inverso

  • Nueva ruta API: En el modo WEBHOOK, reenvíe /callbacks/human-input/v2/im/ al servicio API (api:5001 en Docker Compose), conservando la ruta de la solicitud, el cuerpo sin formato y los encabezados de firma del proveedor. La plantilla nginx incluida ya incluye esta regla; agregue su equivalente a nginx personalizado, Ingress u otras configuraciones de proxy inverso. Configure el proveedor de mensajería instantánea con la URL de devolución de llamada generada por el canal. (#44864)
  • Nuevas colas de Apio: Incluye human_input_delivery para procesamiento de devolución de llamadas de mensajería instantánea asíncrona y actualizaciones de tarjetas posteriores al envío, y human_input_contact_sync para sincronización del directorio de contactos de mensajería instantánea. La lista de trabajadores predeterminada Docker incluye ambos. Las listas personalizadas CELERY_QUEUES, CELERY_WORKER_QUEUES o Celery --queues deben proporcionar un consumidor activo para cada cola junto con las suscripciones existentes. (#44864)

Archivos de entorno Docker

docker/envs/core-services/shared.env ya no está cargado. Mueva las configuraciones comunes de API, trabajador y Beat a api-worker.env antes de recrear contenedores. Conserve cualquier configuración específica del servicio en el archivo de anulación utilizado por ese servicio. (#46497) Las URL públicas son compartidas por Web, API y los trabajadores a través del nuevo envs/core-services/urls.defaults y el urls.env opcional:

  • CONSOLE_API_URL
  • CONSOLE_WEB_URL
  • SERVICE_API_URL
  • APP_API_URL
  • APP_WEB_URL Establezca URL base accesibles para el navegador sin los sufijos /console/api, /api o /v1. Los valores explícitos en urls.env anulan la configuración de URL específica del servicio; root docker/.env anula ambos. El SERVER_CONSOLE_API_URL interno de Web permanece en web.env. Esto también resuelve un problema por el cual los enlaces de íconos generados apuntaban a 127.0.0.1:5001 en instalaciones nuevas. (#46497)

Guía de actualización

[!IMPORTANTE] Saque la configuración del shared.env retirado antes de volver a crear contenedores. Revise las URL públicas, el enrutamiento de devolución de llamadas HITL personalizado y las suscripciones de los trabajadores. Las implementaciones de OpenShell requieren una actualización de puerta de enlace compatible y ya no restauran instantáneas de inicio. El demonio del complemento incluido se actualiza a 0.6.15-local.

Preparar el despliegue

  1. Haga una copia de seguridad de los datos y la configuración. Haga una copia de seguridad de su base de datos, datos del almacén de vectores, archivos cargados, almacenamiento del demonio de complementos, almacenamiento del espacio de trabajo del agente, secretos de implementación y archivos de entorno. Programe una ventana de mantenimiento para una actualización de una sola pila.
  2. Actualice los componentes de Dify juntos. Utilice imágenes coincidentes de 1.20.0 API, trabajador, web, backend del agente y sandbox local, junto con el demonio de complemento 0.6.15-local. Mantenga SECRET_KEY, cualquier PASSWORD_PEPPER configurado y el token de autenticación de la zona de pruebas local sin cambios. Los tokens de acceso personal dependen de SECRET_KEY; asegúrese de que se utilice el mismo valor en todas las réplicas de API. Si actualiza desde una versión anterior a 1.19.0, siga también la guía de actualización de 1.19.0.
  3. Migre shared.env. Si envs/core-services/api-worker.env no existe, cambie el nombre de envs/core-services/shared.env a esa ruta. Si ambos existen, combine solo las configuraciones que faltan y conserve los valores api-worker.env existentes, incluidas las asignaciones vacías intencionales. Conserve la configuración específica del servicio en el archivo de anulación del servicio apropiado. Las implementaciones sin shared.env no requieren migración.
  4. Consolidar URL públicas. Cree envs/core-services/urls.env a partir de urls.defaults solo si aún no existe. Mueva allí los valores de URL públicos previstos y luego elimine las asignaciones duplicadas de los archivos de servicio individuales. Los valores raíz .env existentes conservan prioridad. Mantenga el enrutamiento web interno API en web.env.
  5. Aplicar cambios de entorno, ruta y cola. Siga Cambios de configuración e integración, incluida la nueva configuración HITL, la ruta de devolución de llamada de mensajería instantánea y ambas colas de Apio.
  6. Deje que se ejecute la inicialización del almacenamiento del complemento. init_permissions ahora también prepara ./volumes/plugin_daemon para el UID 1001 del demonio, y el demonio espera a que se complete. Vuelva a crear la implementación con docker compose up -d para que se ejecute el servicio de inicio. (#45615)

Implementaciones de OpenShell

Actualice la puerta de enlace OpenShell y SDK juntos a 0.1.3 o posterior dentro de la línea 0.1.x compatible, y actualice Dify API y Agent Backend juntos. La puerta de enlace debe admitir la exposición del servicio nativo y el paso a través del portador, preservando el token de autorización por sandbox derivado de DIFY_AGENT_OPENSHELL_SHELLCTL_AUTH_TOKEN. Mantenga ese secreto maestro idéntico en todas las réplicas del agente backend. (#45862) Cree la imagen del tiempo de ejecución de OpenShell desde la versión de pago y configure DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE con la referencia de imagen exacta disponible para los nodos informáticos de la puerta de enlace. La imagen debe incluir tanto shellctl como iproute2; una imagen de tiempo de ejecución almacenada en caché más antigua puede carecer de las herramientas de red necesarias. Al actualizar desde el token shellctl compartido en toda la implementación anterior, genere un nuevo secreto maestro de alta entropía y actualice todas las réplicas del agente backend juntas. Drene el trabajo activo, luego detenga y reinicie los entornos sandbox existentes para que shellctl se reinicie con la credencial derivada. Volver a adquirir un sandbox que ya está en buen estado no actualiza su credencial. Se eliminan las instantáneas de inicio de volumen compartido y DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH. Los entornos sandbox existentes en ejecución conservan su estado durante los ciclos de parada/reinicio, mientras que los enlaces recién creados comienzan desde el inicio predeterminado de la imagen. DIFY_AGENT_OPENSHELL_DRIVER_CONFIG ahora es opcional. Revise la guía de implementación de OpenShell, incluidos sus requisitos de imagen en tiempo de ejecución, antes de realizar la actualización. Otros backends de sandbox no se ven afectados.

Docker Redactar

Una vez que se publiquen la etiqueta 1.20.0 y las imágenes, detenga la implementación correctamente, cambie a la versión, migre los archivos de configuración locales y luego extraiga e inicie los servicios actualizados:

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

Mantenga habilitadas las migraciones de inicio API (MIGRATION_ENABLED=true) o aplique la cadena de migración completa a través de su proceso de migración administrada antes de iniciar nuevos trabajadores. Utilice docker compose up -d después de cambiar los archivos de entorno; un simple reinicio no los recarga.

Implementaciones de origen

Utilice Python 3.13, Node.js 24.22.3 o posterior en la línea 24.x y pnpm 12.18.0. Después de detener los servicios y cambiar a la versión, ejecute los siguientes comandos desde la raíz del repositorio:

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Reconstruya la Web y reinicie los servicios API, trabajadores, programador y Agente desde la misma versión. Actualice las dependencias bloqueadas del agente backend independiente si lo implementa por separado. Conserve las suscripciones de trabajadores existentes y agregue las dos colas HITL cuando sea necesario. Changelog completo: 1.19.0 → 1.20.0

dify 1.20.0

Dify 1.20.0 keeps your traces flowing and your knowledge bases safer. Export traces to any OpenTelemetry collector, keep Langfuse working after its legacy ingestion endpoint retirement, and scan uploaded knowledge files for malware before they are indexed. Chatflows can show Agent tool activity as it happens, and personal access tokens let scripts and agents call the Dify OpenAPI on your behalf. The bundled plugin daemon is upgraded to 0.6.15-local.

New Features · Configuration and Integration Changes · Database Migrations · Upgrade Guide

New Features

New HITL: bring approvals into your team's messaging tools

Integrate human review into your workflows via email and the messaging tools your team already uses. New HITL introduces shared channels, centralized contacts, notification templates, and verified approval forms—allowing your team to configure recipients once and reuse them across Human Input nodes, and is now enabled by default (NEXT_PUBLIC_ENABLE_HITL_IM=true). (#44864, #45945)

  • Reach approvers where they work. Configure email and an IM platform—Slack, Feishu/Lark, Microsoft Teams, DingTalk, or WeCom—to deliver workflow review requests through your team's existing channels.
  • Manage recipients in Contacts. Sync IM directories and select approvers from a shared contact list. Workflows can also address the initiator or use one-time and dynamic email recipients.
  • Approve in cards or forms. Recipients can review requests directly in supported IM cards or open standalone forms, with Dify login or email verification to verify their identity.
  • Customize notifications with workflow context. Use templates and workflow variables to include essential context in notification subjects and bodies.
  • Test and track delivery. Send test notifications to verify your setup and inspect delivery records to troubleshoot requests that did not arrive as expected.
  • Adopt New HITL in existing workflows. Use opt-in migration to upgrade legacy Human Input nodes when your workflow is ready.

Deployment requirements are listed under Configuration and Integration Changes.

Export traces to any OpenTelemetry collector

Bring Dify execution traces into your existing observability stack. The new OpenTelemetry provider exports app and Agent traces to any compatible collector, allowing you to track workflow steps, model calls, and tool activity together in your preferred platform. Use these traces to inspect request execution and diagnose failures without requiring a vendor-specific Dify integration. (#45659)

Langfuse tracing now supports Langfuse v4 and the current Langfuse Cloud ingestion service. Existing Langfuse configurations continue to work. (#45606)

[!IMPORTANT] Langfuse Cloud retired its legacy ingestion endpoint on November 16, 2026, and self-hosted Langfuse v4 rejects events sent to it. Upgrade to 1.20.0 to keep delivering traces to those deployments.

Scan knowledge uploads for malware

Protect your knowledge bases by scanning uploaded files for malware before they are extracted or indexed. When enabled (FILE_SCAN_ENABLED=true), workspace owners and admins can configure scanners once under Integrations → File Security Scan, then define how each knowledge base uses them. Supported scanners include Cloudmersive, Scanii, OPSWAT MetaDefender Cloud, and a Custom Endpoint. (#46090, #46492)

  • Choose protection per knowledge base. Select a scanner and configure fallback behavior when scanning is unavailable or a file cannot be scanned.
  • Protect knowledge uploads across Dify. Scanning covers classic knowledge bases, RAG Pipeline local-file sources, and Agent Knowledge Base uploads.
  • See why files were blocked. Scan failures appear in the document list for review.

Watch Agent tools work in Chatflow

When a Chatflow delegates tasks to an Agent v2 node (requires NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true), users can now see which tools it invokes in real time. Tool activity appears alongside the response in both previews and published chats, making it easier to follow the Agent's progress. Expand any tool card to inspect what it requested and returned. (#46220)

Automate OpenAPI calls with personal access tokens

Grant scripts, CI jobs, and personal agents access to the Dify OpenAPI on your behalf without sharing your Console session. Create a personal access token from your Account page and scope it to specific workspaces and resources. You can set an optional expiration date, update its scope as your automation evolves, or revoke it when it is no longer needed. (#45540, #46606)

Choose GitHub knowledge sources from a tree

Browse and select the GitHub content you want to add to a knowledge base from an expandable tree of repositories, directories, issues, and pull requests. Explore the source structure and pick the exact pages to import, whether you are creating a new knowledge base or adding a source to an existing one. (#45990)

Search and navigate on smaller screens

Search across content and narrow results using selectable scopes in Goto Anything. On smaller screens, search and navigation open in drawers to preserve space for the current page. (#45675, #45650)

Direct links can now open Studio's blank-app or template creation flows. (#45717)

More flexible knowledge descriptions and metadata

  • Longer knowledge base descriptions. Increased description length limits allow you to provide more context for each knowledge base. (#45075)
  • External knowledge metadata. External knowledge retrieval now returns document metadata alongside content. (#22496)

Improvements

Lower database and startup overhead. Node execution updates avoid reloading stored rows, credential policies are evaluated once per provider configuration, model defaults use short-lived sessions, and embedding calls no longer hold open a database session. Web feature dependencies also load more lazily. (#46410, #46441, #45806, #45788, #46145)

Clearer document failures and steadier layouts. Knowledge documents now report specific failure reasons and processing stages. Dialogs adapt to narrow viewports and maintain consistent lifecycles across accounts, knowledge, apps, Skills, and workflows. Authentication pages load faster, fit smaller screens, and keep keyboard focus accessible. Segmented controls animate smoothly while preserving compact layouts and respecting reduced-motion preferences. (#45128, #46487, #45686, #45668, #45634, #45600, #45640, #45974)

Bug Fixes

  • Safer file previews and signed links. Sandbox inline SVG previews and verify the original signature before renewing expired file links. (#46505)
  • Stronger access protection. Redact node-retry details from public streams, prevent OAuth callback reuse, enforce member-role permissions, and scope vector deletion to the target dataset. (#46517, #46001, #46053, #45586)
  • Security dependency updates. Upgrade github.com/klauspost/compress in dify-agent-runtime to address CVE-2026-116591, and update Node.js in runtime images to security release 24.22.3. (#46544, #46206, #46064)
  • Reliable blocking workflows. Release database connections before execution and return preparation failures immediately, preventing connection-pool exhaustion and hanging requests that wait until timeout. (#46254)
  • More stable workers. Resolve the Redis BRPOP busy loop and prevent overlapping plugin upgrade checks, capping concurrency at 20 checks across workers. (#45940, #46500)
  • Complete Chatflow streams. Properly close streams after direct replies and reset the reconnect budget when a stream resumes. (#45552, #46110)
  • Correct Agent execution. Preserve parallel calls to the same plugin tool, pass declared app inputs to Agent runs, and deliver uploaded images to vision models. (#45207, #45425, #45745)
  • Accurate knowledge retrieval. Restore Weaviate keyword/hybrid results by returning BM25 scores, and keep embedding vectors aligned when a batch item is dropped. (#45642, #45569)
  • Reliable custom API tools. Resolve OpenAPI server variables, percent-encode path parameters, and support OpenAPI 3.1 nullable unions. (#46504, #45965, #45895)

For Docker Compose, configure shared backend overrides in envs/core-services/api-worker.env and Web overrides in envs/core-services/web.env. Root docker/.env takes precedence. Apply changes with docker compose up -d; a plain restart does not reload environment files.

The OpenTelemetry provider supports OTLP/HTTP with protobuf; gRPC is not supported. Live Agent tool activity requires streaming output, is unavailable for buffered-output paths, and is not replayed from chat history.

File scanning is disabled by default at the deployment level and must also be enabled per knowledge base. Policies for scanner unavailability and unscannable files both default to blocking the file.

Disabling NEXT_PUBLIC_ENABLE_HITL_IM does not roll back saved data or halt server-side work already in progress.

Reverse proxy and worker configuration

  • New API route: In WEBHOOK mode, forward /callbacks/human-input/v2/im/ to the API service (api:5001 in Docker Compose), preserving the request path, raw body, and provider signature headers. The bundled nginx template already includes this rule; add its equivalent to custom nginx, Ingress, or other reverse proxy configurations. Configure the IM provider with the channel's generated Callback URL. (#44864)
  • New Celery queues: Include human_input_delivery for asynchronous IM callback processing and post-submission card updates, and human_input_contact_sync for IM contact directory synchronization. The default Docker worker list includes both. Custom CELERY_QUEUES, CELERY_WORKER_QUEUES, or Celery --queues lists must provide an active consumer for each queue alongside existing subscriptions. (#44864)

Docker environment files

docker/envs/core-services/shared.env is no longer loaded. Move common API, worker, and Beat settings to api-worker.env before recreating containers. Preserve any service-specific settings in the override file used by that service. (#46497)

Public URLs are shared by Web, API, and workers through the new envs/core-services/urls.defaults and optional urls.env:

  • CONSOLE_API_URL
  • CONSOLE_WEB_URL
  • SERVICE_API_URL
  • APP_API_URL
  • APP_WEB_URL

Set browser-accessible base URLs without /console/api, /api, or /v1 suffixes. Explicit values in urls.env override service-specific URL settings; root docker/.env overrides both. Web's internal SERVER_CONSOLE_API_URL remains in web.env. This also resolves an issue where generated icon links pointed to 127.0.0.1:5001 on fresh installations. (#46497)

Database Migrations

Upgrading from 1.19.0 adds six migration revisions, moving the migration head from 53c10126d551 to f8b6e2c4a901. Apply the complete Alembic chain through the normal migration runner.

| Revision | Change | | --- | --- | | 6b7e2a9c4d10 | Add nullable started_by_sys_user_id to human_input_im_sync_runs and require exactly one initiating identity per row. | | b2e4c6d8a013 | Add personal access tokens and their resource/workspace scope tables. | | 8c2f5d7a1e30 | Add file scanner, scan policy, and scan-result tables. | | 91f4b2d7c8e0 | Add Evaluation configuration, run, and run-item tables. | | c7e4a1b2d9f0 | Add the Evaluation framework column with a default value. | | f8b6e2c4a901 | Merge the Evaluation and main migration branches. |

The Evaluation migrations apply to the Community Edition as well, even though CE does not expose the Evaluation feature. Include these revisions when applying the migration chain; none of the six revisions require a separate manual backfill command. (#45945, #45540, #46090, #46141)

New HITL introduces the necessary database schema and automatically backfills Contact identities for existing accounts with no extra commands required. These migrations are already included in 1.19.0—existing 1.19.0 deployments need no action, while older versions should run the full migration chain. Legacy Human Input nodes are not automatically migrated and remain opt-in.

Upgrade Guide

[!IMPORTANT] Move settings out of the retired shared.env before recreating containers. Review public URLs, custom HITL callback routing, and worker subscriptions. OpenShell deployments require a compatible gateway upgrade and no longer restore Home Snapshots. The bundled plugin daemon is updated to 0.6.15-local.

Prepare the deployment

  1. Back up data and configuration. Back up your database, vector-store data, uploaded files, plugin daemon storage, Agent workspace storage, deployment secrets, and environment files. Schedule a maintenance window for a single-stack upgrade.
  2. Upgrade the Dify components together. Use matching 1.20.0 API, worker, Web, Agent Backend, and Local sandbox images, alongside plugin daemon 0.6.15-local. Keep SECRET_KEY, any configured PASSWORD_PEPPER, and the Local sandbox authentication token unchanged. Personal access tokens depend on SECRET_KEY; ensure the same value is used across all API replicas. If upgrading from a version earlier than 1.19.0, also follow the 1.19.0 upgrade guide.
  3. Migrate shared.env. If envs/core-services/api-worker.env does not exist, rename envs/core-services/shared.env to that path. If both exist, merge only missing settings and preserve existing api-worker.env values, including intentional empty assignments. Retain service-specific settings in the appropriate service override file. Deployments without shared.env require no migration.
  4. Consolidate public URLs. Create envs/core-services/urls.env from urls.defaults only if it does not already exist. Move the intended public URL values there, then remove duplicate assignments from individual service files. Existing root .env values retain precedence. Keep internal Web API routing in web.env.
  5. Apply environment, route, and queue changes. Follow Configuration and Integration Changes, including the New HITL settings, IM callback route, and both Celery queues.
  6. Let plugin storage initialization run. init_permissions now also prepares ./volumes/plugin_daemon for the daemon's UID 1001, and the daemon waits for it to complete. Recreate the deployment with docker compose up -d so the init service runs. (#45615)

OpenShell deployments

Upgrade the OpenShell gateway and SDK together to 0.1.3 or later within the supported 0.1.x line, and upgrade the Dify API and Agent Backend together. The gateway must support native service exposure and bearer passthrough, preserving the per-sandbox authorization token derived from DIFY_AGENT_OPENSHELL_SHELLCTL_AUTH_TOKEN. Keep that master secret identical across Agent Backend replicas. (#45862)

Build the OpenShell runtime image from the release checkout and set DIFY_AGENT_OPENSHELL_SANDBOX_IMAGE to the exact image reference available to the gateway's compute nodes. The image must include both shellctl and iproute2; an older cached runtime image may lack the required networking tools.

When upgrading from the previous shared deployment-wide shellctl token, generate a fresh high-entropy master secret and update all Agent Backend replicas together. Drain active work, then stop and restart existing sandboxes so shellctl restarts with the derived credential. Reacquiring an already healthy sandbox does not refresh its credential.

Shared-volume Home Snapshots and DIFY_AGENT_OPENSHELL_SHARED_MOUNT_PATH are removed. Existing running sandboxes retain their state across stop/restart cycles, whereas newly created Bindings start from the image's default Home. DIFY_AGENT_OPENSHELL_DRIVER_CONFIG is now optional. Review the OpenShell deployment guide, including its runtime-image requirements, before upgrading. Other sandbox backends are unaffected.

Docker Compose

Once the 1.20.0 tag and images are published, stop the deployment gracefully, switch to the release, migrate local configuration files, and then pull and start the updated services:

cd dify/docker
docker compose stop -t -1
git fetch --tags
git checkout 1.20.0
# Migrate shared.env, public URLs, and any custom proxy/worker configuration.
docker compose pull
docker compose up -d

Keep API startup migrations enabled (MIGRATION_ENABLED=true), or apply the full migration chain through your managed migration process before starting new workers. Use docker compose up -d after changing environment files; a plain restart does not reload them.

Source deployments

Use Python 3.13, Node.js 24.22.3 or later in the 24.x line, and pnpm 12.18.0. After stopping the services and switching to the release, run the following commands from the repository root:

uv sync --project api --frozen
uv run --directory api flask db upgrade
pnpm install --frozen-lockfile

Rebuild Web and restart the API, workers, scheduler, and Agent services from the same release. Update the standalone Agent Backend's locked dependencies if deploying it separately. Preserve existing worker subscriptions and add the two HITL queues where needed.
