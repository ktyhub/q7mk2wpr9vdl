dify 1.13.1

🚀 Cambios funcionales importantes

Plataforma de datos y operaciones de conjuntos de datos

  • Se agregó Hologres como una opción de backend compatible tanto para la recuperación de vectores como para la búsqueda de texto completo.
  • Se agregaron puntos finales del servicio API para descargas de documentos de conjuntos de datos:
    • Descarga ZIP por lotes para documentos seleccionados.
    • Descarga de URL firmada para archivos originales de un solo documento.

Mejoras en el flujo de trabajo y la experiencia de chat

  • Cambio importante: El contenido de correo electrónico HITL ahora utiliza la representación de rebajas antes de la entrega. Las plantillas de correo electrónico existentes que se basaban en un comportamiento sin formato o simple pueden mostrarse de manera diferente después de la actualización.
  • Las variables de borrador ahora tienen alcance de usuario en lugar de alcance de aplicación. Las variables de borrador históricas no estarán disponibles después de la actualización.
  • Se agregó compatibilidad con el menú contextual de bordes en el lienzo del flujo de trabajo, incluida la eliminación directa de bordes.
  • Se conservaron las conexiones existentes al cambiar los tipos de nodos en la edición del flujo de trabajo.
  • Se agregó un comportamiento de envío de clave configurable (Enter vs Shift+Enter) para entrada de chat integrada.
  • Se agregaron cargas útiles de archivos en las respuestas de la secuencia de fin de mensaje.
  • Se eliminó el comportamiento codificado específico de GPT-4 de la lógica de selección de modelo predeterminada.
  • Se agregó un nuevo comando export-app-messages CLI para exportar mensajes de aplicaciones y comentarios relacionados a JSONL.GZ (almacenamiento local o en la nube).

🔐 Actualizaciones de seguridad

  • Se evitaron riesgos de inyección de SQL en rutas de consulta del almacén de vectores al cambiar a SQL parametrizado en las implementaciones afectadas.
  • Entrega de correo electrónico HITL reforzada:
    • Higienizar el contenido del sujeto y del cuerpo.
    • Elimina CR/LF de los sujetos para evitar vectores de inyección de encabezados SMTP.
  • Controles de propiedad obligatorios para la eliminación de conversaciones API.
  • Se borraron las credenciales de proveedor obsoletas durante la desinstalación del complemento para reducir el riesgo de credenciales residuales.
  • Se mejoró el manejo de errores empresariales API y el comportamiento de aplicación de licencias para estados con licencias no válidas o vencidas.

🏗️ Actualizaciones de configuración, arquitectura e implementación

Despliegue y operaciones

  • Se agregó una cola de apio dedicada: dataset_summary para tareas de generación de resúmenes con gran cantidad de LLM.
    • Asegúrese de que los trabajadores se suscriban a esta cola para evitar trabajos pendientes de resumen.
  • Se agregaron métricas de telemetría para tareas de limpieza de retención (mensajes/ejecuciones de flujo de trabajo), además de comportamiento de descarga para trabajos de comando de corta duración.

Cambios de configuración

  • Se agregó REDIS_MAX_CONNECTIONS.
  • Se desaprobó la configuración del bus de eventos PUBSUB_* en favor de la configuración EVENT_BUS_*.

🛠 Otros cambios destacables

  • Se corrigió que workflow_runs.started_at se sobrescribiera en el currículum.
  • Se corrigieron fallas silenciosas en la edición por lotes de metadatos causadas por casos extremos de transacciones divididas.
  • Se corrigieron problemas de extracción del filtro de metadatos en la recuperación de conocimientos (condiciones {{...}}).
  • Visibilidad de citas restaurada en aplicaciones de chat avanzadas.
  • Se corrigió el comportamiento de reinicio de la variable de conversación después de los nodos HITL.
  • Se corrigió una falla de página en el flujo de configuración del nodo de recuperación de conocimiento.
  • Se corrigió el asistente de chat que bloqueaba el comportamiento del modo de respuesta.
  • Se agregó manejo de doc_type en los atributos vectoriales de Weaviate para una mejor compatibilidad.
  • Dependencias de OpenTelemetry actualizadas para resolver errores de separación de contexto.

Guía de actualización

[!IMPORTANTE] Si utiliza CELERY_QUEUES personalizado, asegúrese de que esté incluido el workflow_based_app_execution.
Si es ENABLE_API_TOKEN_LAST_USED_UPDATE_TASK=true, incluya también api_token.

Para conocer antecedentes y detalles, consulte ⚠️ Nota importante de actualización y 🔧 Nota operativa arriba.

Docker Redactar implementaciones

  1. Haga una copia de seguridad de su archivo personalizado docker-compose YAML (opcional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Obtenga el código más reciente de la rama principal.

    git checkout main
git pull origin main

  3. Detenga el servicio. Ejecute en el directorio docker

    docker compose down

  4. Hacer una copia de seguridad de los datos

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Servicios de actualización

    docker compose up -d

  1. Detenga el servidor API, el trabajador y el servidor frontend web.

  2. Obtenga el código más reciente de la rama de lanzamiento:

    cd api

  4. Luego, ejecutemos el script de migración:

    uv run flask db upgrade

dify 1.13.1

🚀 Major Functional Changes

Data platform and dataset operations

  • Added Hologres as a supported backend option for both vector retrieval and full-text search.
  • Added Service API endpoints for dataset document downloads:
    • Batch ZIP download for selected documents.
    • Signed URL download for single-document original files.

Workflow and chat experience improvements

  • Breaking change: HITL email content now uses markdown rendering before delivery. Existing email templates that relied on raw/plain behavior may render differently after upgrade.
  • Draft variables are now user-scoped instead of app-scoped. Historical draft variables will not be available after upgrading.
  • Added edge context menu support in workflow canvas, including direct edge deletion.
  • Preserved existing connections when changing node types in workflow editing.
  • Added configurable send-key behavior (Enter vs Shift+Enter) for embedded chat input.
  • Added file payloads in message-end stream responses.
  • Removed GPT-4-specific hardcoded behavior from default model selection logic.
  • Added a new export-app-messages CLI command to export application messages and related feedback to JSONL.GZ (local or cloud storage).

🔐 Security Updates

  • Prevented SQL injection risks in vector-store query paths by switching to parameterized SQL in affected implementations.
  • Hardened HITL email delivery:
    • Sanitize subject and body content.
    • Strip CR/LF from subjects to prevent SMTP header-injection vectors.
  • Enforced ownership checks for conversation deletion APIs.
  • Cleared stale provider credentials during plugin uninstall to reduce residual credential risk.
  • Improved enterprise API error handling and license-enforcement behavior for invalid/expired license states.

🏗️ Configuration, Architecture, and Deployment Updates

Deployment and operations

  • Added a dedicated Celery queue: dataset_summary for LLM-heavy summary generation tasks.
    • Ensure workers subscribe to this queue to avoid summary-job backlog.
  • Added telemetry metrics for retention cleanup tasks (messages/workflow runs), plus flush behavior for short-lived command jobs.

Configuration changes

  • Added REDIS_MAX_CONNECTIONS.
  • Deprecated PUBSUB_* event-bus settings in favor of EVENT_BUS_* settings.

🛠 Other Noteworthy Changes

  • Fixed workflow_runs.started_at being overwritten on resume.
  • Fixed metadata batch-edit silent failures caused by split-transaction edge cases.
  • Fixed metadata filter extraction issues in knowledge retrieval ({{...}} conditions).
  • Restored citation visibility in advanced chat applications.
  • Fixed conversation variable reset behavior after HITL nodes.
  • Fixed a page crash in knowledge-retrieval node configuration flow.
  • Fixed chat assistant blocking response-mode behavior.
  • Added doc_type handling in Weaviate vector attributes for better compatibility.
  • Upgraded OpenTelemetry dependencies to resolve context-detach errors.

  1. Back up your customized docker-compose YAML file (optional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Get the latest code from the main branch

    git checkout main
git pull origin main

  3. Stop the service. Please execute in the docker directory

    docker compose down

  4. Back up data

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Upgrade services

    docker compose up -d
