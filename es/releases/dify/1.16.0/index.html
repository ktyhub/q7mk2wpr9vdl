dify 1.16.0

Presentamos Dify Agent (Beta): una nueva experiencia de agente en Dify

[!ADVERTENCIA] Debe proporcionar servicios de Dify Agent ⚠️solo a usuarios trusted y no maliciosos⚠️.

Como muchos de ustedes saben, el paradigma del agente LLM basado en shell ha supuesto un salto importante en las capacidades de los agentes y ha cambiado nuestra forma de pensar sobre los agentes. Mientras tanto, Skills proporciona una forma estandarizada de empaquetar y distribuir capacidades, lo que facilita la creación de agentes potentes.

Hoy lanzamos Dify Agent. Al igual que otros agentes líderes, se ejecuta en un entorno limitado de Linux. Esta versión incluye:

  • Un constructor para crear agentes Dify.

    • Puede crear agentes de Dify a través de la interfaz de usuario: establezca un mensaje base, cargue habilidades y archivos, y conecte herramientas y conocimientos del ecosistema de Dify.
    • También proporcionamos un agente que lo ayuda a crear agentes Dify. A través de la conversación, puede configurar el entorno sandbox de Linux, instalar los paquetes necesarios y crear nuevas habilidades y archivos que su agente Dify puede usar más adelante.

  • Integración de Dify Workflow para Dify Agent

    • Puede utilizar un Agente Dify existente en un flujo de trabajo Dify o crear temporalmente un Agente Dify en línea. Ejecutará la tarea definida por el nodo de flujo de trabajo, generará el resultado requerido y lo pasará al siguiente nodo.

  • Una nueva experiencia de aplicación web

    • El Agente Dify que cree se puede publicar y utilizar como una aplicación web. Si bien la experiencia del usuario sigue siendo familiar, ahora funciona con Dify Agent.

Documentos: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

⚠️ Acción requerida

Aviso de compatibilidad con OpenAI GPT-5.6

Anteriormente, el complemento OpenAI utilizaba de forma predeterminada Chat Completions API, que OpenAI dejó de utilizar a principios de este año y tiene un soporte cada vez más deficiente para las series de modelos más nuevas. La familia GPT-5.6 recientemente lanzada tiene muchas restricciones de combinación de parámetros únicas e inusuales cuando se usa con Finalizaciones de chat, porque OpenAI ahora proporciona solo un soporte de compatibilidad mínimo para Finalizaciones de chat con nuevos modelos. Esto no es un problema del sistema Dify.

El tipo API predeterminado para nuevas configuraciones se cambió de Finalizaciones de chat a Respuestas. Sin embargo, los usuarios que previamente guardaron una clave API personalizada con el antiguo valor predeterminado (Finalizaciones de chat) conservarán esa configuración, lo que puede provocar errores inesperados que parecen originarse en Dify.

Si configuró previamente una clave OpenAI API personalizada, verifique la configuración de tipo API y cambie a Respuestas si todavía está configurada en Finalizaciones de chat, especialmente cuando usa GPT-5.6 o modelos posteriores.

Nuevas características

Aplicación de agente (Beta abierta)

  • La aplicación Agent entra en versión beta abierta y ahora está habilitada de forma predeterminada para todos los usuarios. Presenta un entorno limitado integrado para la ejecución de código y comandos de shell, un sistema de habilidades que permite a los agentes llamar a herramientas y API, una lista de agentes para administrar y reutilizar agentes en un espacio de trabajo y soporte para hacer referencia a nuevos agentes desde nodos de agentes de flujo de trabajo.

Generación de flujo de trabajo de IA más inteligente

  • El generador de flujo de trabajo de IA ⌘K → /create y /refine se ha mejorado de extremo a extremo: se eliminó el campo de bajo valor "Salida ideal", se reemplazaron chips de ejemplo estáticos con sugerencias generadas por IA basadas en el contexto de su espacio de trabajo y la generación de configuración de nodos ahora está en paralelo para obtener resultados más rápidos. Un tiempo de espera configurable (WORKFLOW_GENERATION_TIMEOUT_MS, predeterminado 180 s) evita que se cuelguen las generaciones de larga duración. Actualización del protocolo MCP
  • El servidor de flujo de trabajo como MCP ahora admite el protocolo MCP 2025-06-18 con negociación de versión y salida de herramienta estructurada, sin dejar de ser compatible con versiones anteriores de clients. Las conexiones MCPClient ahora pueden inyectar encabezados de solicitud HTTP dinámicos en tiempo de ejecución utilizando marcadores de posición (por ejemplo, {{request.headers.X-Custom-Auth}}), lo que permite el paso de autenticación por solicitud.

Personalización de la aplicación web

  • Los propietarios de aplicaciones ahora pueden personalizar el texto del marcador de posición de entrada del chat (hasta 64 caracteres) para las aplicaciones web Chatbot, Agent y Chatflow. La interfaz de usuario de personalización se ha perfeccionado con nombres más claros ("Frontal personalizado"/"Marca") y un mejor manejo de etiquetas. Las descripciones de las aplicaciones ahora se muestran en las pantallas de chat y de generación de texto con una vista plegable para evitar sacar el formulario de entrada de la pantalla.

Confiabilidad y operaciones del flujo de trabajo

  • Los archivos de ejecución de flujo de trabajo ahora se pueden exportar y las ejecuciones activas se cancelan correctamente durante el apagado en caliente de Celery para evitar tareas huérfanas. Las conexiones Redis son más resistentes con soporte TCP keepalive y cobertura de reintento ampliada. Los proveedores de modelos ahora reciben app_id para la atribución de costos del lado del proveedor (por ejemplo, metadatos de solicitud de Bedrock, metadatos de OpenAI, etiquetas de Vertex AI). Los flujos de inicio de sesión de OAuth y SSO ahora conservan las URL de redireccionamiento de manera más confiable, con una vista de error dedicada para las finalizaciones fallidas de SSO.

Corrección de errores

Flujo de trabajo y agente

  • Se corrigieron múltiples problemas con la pérdida de referencias en las importaciones de borradores del flujo de trabajo, la liquidación de nodos después de fallas, la visibilidad de los detalles de los reintentos y la restauración del estado del currículum HITL.
  • Se corrigió la corrupción de la transmisión SSE con separadores Unicode, la respuesta final del agente se borraba después de completar la transmisión y el título de la conversación se sobrescribía con valores vacíos.
  • Se corrigió el refuerzo de reintentos de archivo de flujo de trabajo, soporte de colaboración entre múltiples trabajadores y nodos principales del árbol de chat fuera de servicio.
  • Se corrigieron fallas de recuperación de conocimientos que no se mostraban a los usuarios y finalizar colisiones de nombres de variables de salida en plantillas integradas.

Autenticación y control de acceso

  • Se corrigieron vulnerabilidades de redireccionamiento abierto en flujos de redireccionamiento de autenticación y posterior al inicio de sesión.
  • Se corrigieron los redireccionamientos de inicio de sesión que no permanecían en la implementación actual, la duplicación del prefijo de autenticación y el cambio de correo electrónico no funcionaban.
  • Se corrigieron problemas de permisos del editor: los editores ahora pueden ver registros, ya no consultar suscripciones de facturación y ya no pueden administrar miembros
  • Se corrigieron cambios en la configuración de seguimiento que no requieren acceso de edición y refuerzo de acceso a aplicaciones de prueba para aplicaciones recomendadas.

Modelos y complementos

  • Se corrigió que el caché del modelo personalizado no se borrara al eliminarlo, fallas en la depuración del complemento del modelo y manejo del contexto de credenciales de Xinference.
  • Se corrigieron los parámetros máximos de token que no se podían desactivar en los parámetros del modelo de seguimiento.
  • Se corrigieron las estampidas de caché del proveedor de complementos, las devoluciones de llamadas de instalación del mercado y la configuración de permisos de complementos.

Web y interfaz de usuario

  • Se corrigió la creación de aplicaciones desde Learn Dify, entrada del campo de búsqueda de nodos, coherencia del avatar del espacio de trabajo y visualización del perfil de navegación.
  • Se corrigieron las acciones de la tabla de pantalla completa de Streamdown, la fluctuación del encabezado de la página del mercado y la accesibilidad del cuadro de diálogo de instalación.
  • Se corrigieron los archivos adjuntos del chat que se desplazaban fuera de la vista, la visibilidad del botón de guardar de entrada HITL y el metadesbordamiento de la tarjeta de la aplicación.
  • Se corrigió la visualización del valor cero del gráfico de monitoreo, el manejo del estado de la invitación de los miembros, el fondo en modo oscuro y los caracteres Unicode en los nombres de los campos del formulario.
  • Se corrigieron las descargas de enlaces de vista previa de archivos con rebajas, el estado vacío de sincronización de Notion y la atribución UTM del blog bajo CSP.

Otro

  • Se corrigió el bucle infinito en la eliminación de documentos por lotes, cargas útiles de caché UTF-8 no válidas y errores de indexación de documentos tragados.
  • Se corrigió la compatibilidad nativa con uuidv7() de PostgreSQL 18 y la compatibilidad con ADB-PG 7.0.
  • Se corrigió el valor predeterminado de CAN_REPLACE_LOGO en errores de idioma verdadero y no compatible en el código de ejecución, y el indicador CLI --insecure no omitía la verificación TLS.

Mejoras

Rendimiento

  • Se eliminaron consultas N+1 en listas de ejecución de flujo de trabajo de chat avanzado y carga de archivos de mensajes TokenBufferMemory.
  • Inicio de interfaz más rápido mediante complementos de Vite cargados de forma diferida y fragmentos de contrato de consola
  • Carga de base de datos reducida al almacenar en caché el estado de configuración, comprimir objetos de modelo de complemento grandes en Redis con zstd y recuperar flujos de trabajo publicados a través de una clave externa directa.

Arquitectura y calidad del código

  • Se migraron todos los puntos finales de la consola API a contratos OpenAPI generados con BaseModel y contratos de consola frontend a rutas y tipos generados.
  • Propagué sesiones de bases de datos explícitas a través de rutas de backend para lograr coherencia y capacidad de prueba.
  • Se reemplazaron los proveedores de contexto de aplicaciones heredados con átomos de Jotai en toda la interfaz.
  • Se actualizó a TypeScript 7 y la cadena de herramientas Vite+, se aplicaron reglas estrictas de ESLint y no se permitió el nuevo SQLAlchemy directo en los controladores.

Mejoras de seguridad

Esta versión incluye varias correcciones de seguridad, algunas de las cuales se solucionaron después de la versión 1.16.0-rc1:

  • Inyección SQL: se cerró una vulnerabilidad de inyección SQL y se mejoró la seguridad de las consultas SQL con validación de claves de metadatos.
  • SSRF: Se corrigió una derivación de SSRF a través de httpx.get sin procesar en la búsqueda del esquema de la herramienta API
  • Redirecciones abiertas: se evitaron redirecciones abiertas en flujos de redirección de autenticación y posteriores al inicio de sesión
  • Aplicación de Sandbox: Chatflow API ahora verifica el flujo de trabajo_id y el plan de Sandbox; El plan Sandbox no ejecutará flujos de trabajo especiales.
  • Protección Landlock: directorio HOME del agente protegido con Landlock; degradado a v1 para una mayor compatibilidad del kernel
  • Actualizaciones de dependencia CVE: httplib2, setuptools, wandb; motor python, enchufe python; voluble, almohada, click

Guía de actualización

Migración de tipo de modelo

[!IMPORTANTE]

Migración única del tipo de modelo heredado para actualizaciones autohospedadas

Si esta implementación se actualizó desde una versión de Dify anterior a 1.15.0 y esta migración aún no se ha aplicado, ejecútela después de la actualización.

Esta migración no está incluida en flask db upgrade. Sin él, los registros de modelos heredados pueden provocar que las solicitudes API relacionadas con el modelo fallen con errores, lo que impide que se carguen o utilicen los modelos afectados.

Haga una copia de seguridad de la base de datos antes de aplicar la migración. El comando se ejecuta en modo de prueba de forma predeterminada; revise el resultado antes de volver a ejecutarlo con --apply. La migración es idempotente y se puede volver a ejecutar de forma segura.

Docker Redactar

Ejecute desde el directorio docker.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Implementación del código fuente

Ejecute desde la raíz del repositorio después de completar flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Después de aplicar la migración, ejecute nuevamente el comando de ejecución en seco. Si no informa actualizaciones o eliminaciones de filas adicionales, reinicie los servicios relevantes y verifique que los modelos existentes se puedan cargar e invocar correctamente.

  • Esta versión incluye 8 nuevas migraciones de bases de datos. Ejecute migraciones de bases de datos como parte de la actualización.

dify 1.16.0

Introducing Dify Agent (Beta): A New Agent Experience in Dify

[!WARNING] You should provide Dify Agent services ⚠️only to trusted, non-malicious users⚠️.

As many of you know, the shell-based LLM agent paradigm has brought a major leap in agent capabilities and changed how we think about agents. Meanwhile, Skills provide a standardized way to package and distribute capabilities, making it easier to build powerful agents.

Today, we are launching Dify Agent. Like other leading agents, it runs in a Linux sandbox. This release includes:

  • A builder for creating Dify Agents

    • You can build Dify Agents through the UI: set a base prompt, upload Skills and files, and connect tools and knowledge from the Dify ecosystem.
    • We also provide an agent that helps you build Dify Agents. Through conversation, it can configure the Linux sandbox environment, install required packages, and create new Skills and files that your Dify Agent can use later.

  • Dify Workflow integration for Dify Agent

    • You can use an existing Dify Agent in a Dify Workflow, or temporarily create an inline Dify Agent. It will execute the task defined by the workflow node, generate the required output, and pass it to the next node.

  • A new web app experience

    • The Dify Agent you build can be published and used as a web app. While the user experience remains familiar, it is now powered by Dify Agent.

Docs: https://docs.dify.ai/en/self-host/use-dify/build/new-agent/overview

OpenAI GPT-5.6 Compatibility Notice

The OpenAI plugin previously defaulted to using the Chat Completions API, which was deprecated by OpenAI earlier this year and has increasingly poor support for newer model series. The newly released GPT-5.6 family has many unusual and unique parameter combination restrictions when used with Chat Completions, because OpenAI now provides only minimal compatibility support for Chat Completions with new models. This is not a Dify system issue.

The default API type for new configurations has been changed from Chat Completions to Responses. However, users who previously saved a custom API key with the old default (Chat Completions) will retain that setting, which may cause unexpected errors that appear to originate from Dify.

If you have previously configured a custom OpenAI API key, please check your API type setting and switch to Responses if it is still set to Chat Completions, especially when using GPT-5.6 or later models.

New Features

Agent App (Open Beta)

  • Agent App enters open beta and is now enabled by default for all users. It introduces a built-in sandbox for code execution and shell commands, a skill system that lets agents call tools and APIs, an agent roster for managing and reusing agents across a workspace, and support for referencing new agents from workflow agent nodes.

Smarter AI Workflow Generation

  • The ⌘K → /create and /refine AI workflow generator has been enhanced end-to-end: the low-value "Ideal output" field was removed, static example chips replaced with AI-generated suggestions grounded in your workspace context, and node config generation is now parallelized for faster results. A configurable timeout (WORKFLOW_GENERATION_TIMEOUT_MS, default 180s) prevents long-running generations from hanging.

MCP Protocol Upgrade

  • The workflow-as-MCP server now supports MCP protocol 2025-06-18 with version negotiation and structured tool output, while remaining backward compatible with older clients. MCPClient connections can now inject dynamic HTTP request headers at runtime using placeholders (e.g. {{request.headers.X-Custom-Auth}}), enabling per-request authentication passthrough.

Web App Customization

  • App owners can now customize the chat input placeholder text (up to 64 chars) for Chatbot, Agent, and Chatflow web apps. The customization UI has been refined with clearer naming ("Custom Frontend" / "Branding") and better label handling. App descriptions are now displayed on chat and text-generation app screens with a collapsible view to avoid pushing the input form off screen.

Workflow Reliability & Operations

  • Workflow run archives can now be exported, and active runs are properly aborted during Celery warm shutdown to prevent orphaned tasks. Redis connections are more resilient with TCP keepalive support and expanded retry coverage. Model providers now receive app_id for provider-side cost attribution (e.g. Bedrock requestMetadata, OpenAI metadata, Vertex AI labels). OAuth and SSO login flows now preserve redirect URLs more reliably, with a dedicated error view for failed SSO completions.

Bug Fixes

Workflow & Agent

  • Fixed multiple issues with workflow draft imports losing references, node settlement after failures, retry detail visibility, and HITL resume state restoration
  • Fixed SSE stream corruption with Unicode separators, agent final answer clearing after stream completion, and conversation title being overwritten with empty values
  • Fixed workflow archive retry hardening, multi-worker collaboration support, and chat tree out-of-order parent nodes
  • Fixed knowledge retrieval failures not being surfaced to users, and End output variable name collisions in built-in templates

Authentication & Access Control

  • Fixed open redirect vulnerabilities in post-login and auth redirect flows
  • Fixed login redirects not staying on current deployment, auth prefix duplication, and change email not working
  • Fixed editor permission issues: editors can now view logs, no longer query billing subscriptions, and can no longer manage members
  • Fixed trace config changes not requiring edit access, and trial app access hardening for recommended apps

Models & Plugins

  • Fixed custom model cache not being cleared on deletion, model plugin debugging failures, and Xinference credential context handling
  • Fixed max token params not being disableable in follow-up model parameters
  • Fixed plugin provider cache stampedes, marketplace installation callbacks, and plugin permission settings

Web & UI

  • Fixed app creation from Learn Dify, node search field input, workspace avatar consistency, and navigation profile display

Upgrade Guide

Model Type Migration

[!IMPORTANT]

One-time legacy model type migration for self-hosted upgrades

If this deployment was upgraded from a Dify version earlier than 1.15.0 and this migration has not already been applied, run it after upgrading.

This migration is not included in flask db upgrade. Without it, legacy model records can cause model-related API requests to fail with errors, preventing affected models from being loaded or used.

Back up the database before applying the migration. The command runs in dry-run mode by default; review the output before rerunning it with --apply. The migration is idempotent and can be safely rerun.

Docker Compose

Run from the docker directory.

# Apply after reviewing the dry-run output
docker compose exec -T api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

Source Code Deployment

Run from the repository root after completing flask db upgrade.

# Apply after reviewing the dry-run output
uv run --project api flask data-migrate legacy-model-types --apply \
  > legacy-model-types-apply.jsonl

After applying the migration, run the dry-run command again. If it reports no additional row updates or deletions, restart the relevant services and verify that existing models can be loaded and invoked successfully.

[!IMPORTANT]

  • This release includes 8 new database migrations. Run database migrations as part of the upgrade.
  • 28 new environment variables, 1 removed, and 1 modified. Review the Environment Variable Changes section and update your .env accordingly.
  • Docker Compose configuration changed significantly: two new services (agent_backend, local_sandbox) were added. If you maintain a customized docker-compose.yaml, review the changes and re-apply local customizations carefully.
  • DIFY_AGENT_SERVER_SECRET_KEY ships with a development default. You must replace it in production with a securely generated key: python -c 'import secrets; print(secrets.token_urlsafe(32))'
  • ENABLE_AGENT_V2 has been renamed to NEXT_PUBLIC_ENABLE_AGENT_V2 and now defaults to true. Remove the old variable from your env files.
  • OpenAI GPT-5.6 users: If you have previously configured a custom OpenAI API key, verify your API type is set to Responses (not Chat Completions). See the Known Issues section above.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML and env files.

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak
cp .env .env.$(date +%s).bak 2>/dev/null || true

  2. Get the latest code from the release branch or tag.

    git fetch --tags
git checkout 1.16.0

  3. Stop the service. Please execute in the docker directory.

    docker compose down

  4. Back up data.

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Review the new environment variables (especially DIFY_AGENT_SERVER_SECRET_KEY) and update your .env file. Re-apply any local customizations.

  6. Upgrade services.

    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend Server.

  2. Get the latest code from the release tag.

    git fetch --tags
git checkout 1.16.0

  3. Update Python dependencies.

    cd api
uv sync

  4. Run the migration script.

    uv run flask db upgrade

  5. Configure the new Agent backend service. Refer to the dify-agent section in docker/envs/core-services/dify-agent.env.example for required environment variables.

  6. Restart the API server, Worker, and Web frontend Server.
