dify 1.13.3

🚀 ¿Qué hay de nuevo en v1.13.3?

Nuestra última versión del parche, v1.13.3, se centra en la estabilidad y la corrección en la ejecución del flujo de trabajo, la transmisión y la recuperación de conocimientos. A continuación se ofrece un vistazo rápido a las actualizaciones más importantes:

🎬 Nuevas funciones

  • Configuración del flujo de trabajo: Se agregó soporte de referencia variable para los parámetros del modelo en los nodos LLM, Clasificador de preguntas y Extractor de variables por @scdeng en #33082.

🛠️ Corrección de errores

  • Confiabilidad de transmisión: Se corrigieron problemas de repetición y concurrencia de StreamsBroadcastChannel para mantener estable la entrega de eventos frontend/backend por parte de @QuantumGhost en #34030 y #34061.
  • Comportamiento del editor de flujo de trabajo: Se corrigieron los nodos pegados que conservaban los metadatos de bucle/iteración y se evitó que @majiayu000 y @hjlarry pegaran los nodos HumanInput en contenedores no válidos en los números 29983 y 34077.
  • Ejecución en tiempo de ejecución: se restauró la lógica de transformación de mensajes de aviso y se corrigió el manejo de max_retries=0 para la ejecución de solicitudes HTTP impulsadas por el ejecutor por parte de @QuantumGhost, @fatelei y @kurokobo en #33666, #33619 y #33688.
  • Recuperación de conocimientos: metadatos de citas conservados en las respuestas web, fallos fijos cuando faltan metadatos de iconos del conjunto de datos, filtrado de consultas de recuento de visitas corregido y vistas previas restauradas de fragmentos de documentos indexados por @Theysua, @copilot-swe-agent y @fatelei en #33778, #33907, #33757 y #33942.

🔧 Debajo del capó

  • Estabilidad del parche: esta versión prioriza las correcciones específicas para el comportamiento del tiempo de ejecución del flujo de trabajo, la transmisión en tiempo real y la usabilidad de la base de conocimientos para los equipos que actualizan desde v1.13.2.

Guía de actualización

[!IMPORTANTE] La imagen Sandbox utilizada por Dify v1.13.3 espera las siguientes rutas Python y Node.js. Si actualizó desde una implementación anterior de Docker Compose y ya tiene docker/volumes/sandbox/conf/config.yaml, actualícela en la máquina host:

python_path: /opt/python/bin/python3
nodejs_path: /usr/local/bin/node

No edite el archivo dentro del contenedor sandbox. El directorio docker/volumes/sandbox/conf está montado en el contenedor como /conf, por lo que los cambios del host persisten después de que se reinicia el contenedor.

Docker Redactar implementaciones

  1. Haga una copia de seguridad de su archivo personalizado docker-compose YAML (opcional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Obtenga el código más reciente de la rama principal.

    git checkout main
git pull origin main

  3. Detenga el servicio. Ejecute en el directorio docker

    docker compose down

  4. Hacer una copia de seguridad de los datos

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Servicios de actualización

    docker compose up -d

Implementaciones de código fuente

  1. Detenga el servidor API, el trabajador y el servidor frontend web.

  2. Obtenga el código más reciente de la rama de lanzamiento:

    git checkout 1.13.3

  3. Actualice las dependencias de Python:

    cd api
uv sync

  4. Luego, ejecutemos el script de migración:

    uv run flask db upgrade

  5. Finalmente, ejecute nuevamente el servidor API, el trabajador y el servidor frontend web.

🚀 What's New in v1.13.3?

Our latest patch release, v1.13.3, focuses on stability and correctness across workflow execution, streaming, and knowledge retrieval. Here's a quick look at the most important updates:

🎬 New Features

  • Workflow Configuration: Added variable-reference support for model parameters in LLM, Question Classifier, and Variable Extractor nodes by @scdeng in #33082.

🛠️ Bug Fixes

  • Streaming Reliability: Fixed StreamsBroadcastChannel replay and concurrency issues to keep frontend/backend event delivery stable by @QuantumGhost in #34030 and #34061.
  • Workflow Editor Behavior: Fixed pasted nodes retaining Loop/Iteration metadata and prevented HumanInput nodes from being pasted into invalid containers by @majiayu000 and @hjlarry in #29983 and #34077.
  • Runtime Execution: Restored prompt message transformation logic and corrected max_retries=0 handling for executor-driven HTTP Request execution by @QuantumGhost, @fatelei, and @kurokobo in #33666, #33619, and #33688.
  • Knowledge Retrieval: Preserved citation metadata in web responses, fixed crashes when dataset icon metadata is missing, corrected hit-count query filtering, and restored indexed document chunk previews by @Theysua, @copilot-swe-agent, and @fatelei in #33778, #33907, #33757, and #33942.

🔧 Under the Hood

  • Patch Stability: This release prioritizes targeted fixes for workflow runtime behavior, real-time streaming, and knowledge base usability for teams upgrading from v1.13.2.

Upgrade Guide

[!IMPORTANT] The Sandbox image used by Dify v1.13.3 expects the following Python and Node.js paths. If you upgraded from an older Docker Compose deployment and already have docker/volumes/sandbox/conf/config.yaml, update it on the host machine:

python_path: /opt/python/bin/python3
nodejs_path: /usr/local/bin/node

Do not edit the file inside the sandbox container. The directory docker/volumes/sandbox/conf is mounted into the container as /conf, so host changes persist after container restarts.

Docker Compose Deployments

  1. Back up your customized docker-compose YAML file (optional)

    cd docker
cp docker-compose.yaml docker-compose.yaml.$(date +%s).bak

  2. Get the latest code from the main branch

    git checkout main
git pull origin main

  3. Stop the service. Please execute in the docker directory

    docker compose down

  4. Back up data

    tar -cvf volumes-$(date +%s).tgz volumes

  5. Upgrade services

    docker compose up -d

Source Code Deployments

  1. Stop the API server, Worker, and Web frontend Server.

  2. Get the latest code from the release branch:

    git checkout 1.13.3

  3. Update Python dependencies:

    cd api
uv sync

  4. Then, let's run the migration script:

    uv run flask db upgrade

  5. Finally, run the API server, Worker, and Web frontend Server again.
