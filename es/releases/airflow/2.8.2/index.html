flujo de aire 2.8.2

Cambios significativos

La bandera allowed_deserialization_classes ahora sigue un patrón global (#36147).

Por ejemplo, si uno quiere agregar la clase airflow.tests.custom_class al Lista allowed_deserialization_classes, se puede hacer escribiendo la clase completa nombre (airflow.tests.custom_class) o un patrón como los utilizados en glob búsqueda (por ejemplo, airflow.*, airflow.tests.*). Si actualmente utiliza una ruta de expresión regular personalizada, asegúrese de reescribirla como un patrón global. Alternativamente, si aún desea que coincida con un patrón de expresión regular, agréguelo bajo el nuevo enumere allowed_deserialization_classes_regexp en su lugar.

Los permisos audit_logs se han actualizado para mayor seguridad (#37501).

Esto se hizo bajo la política de que no queremos usuarios como Viewer, Ops, y otros usuarios además del administrador tengan acceso a audit_logs. La intención detrás este cambio es para restringir que los usuarios con menos permisos vean los detalles del usuario como nombre, correo electrónico, etc. de audit_logs cuando no están permitidos. El impacto de este cambio es que los usuarios existentes sin derechos de administrador no podrán para ver o acceder a los audit_logs, tanto desde la pestaña Examinar como desde la ejecución del DAG.

AirflowTimeoutError is no longer except by default through Exception (#35653).

El AirflowTimeoutError is now inheriting BaseException en lugar de AirflowException->Exception. Ver https://docs.python.org/3/library/exceptions.html#exception-hierarchy Esto evita que el código que capture Exception accidentalmente capturando AirflowTimeoutError y continuando corriendo. AirflowTimeoutError es una intención explícita de cancelar la tarea y no debe quedar atrapado en los intentos de manejar el error y devolver algún valor predeterminado. Captando AirflowTimeoutError is still possible by explicitly excepting AirflowTimeoutError or BaseException. Esto no se recomienda, ya que puede permitir que el código continúe ejecutándose incluso después de dichas solicitudes de cancelación. Código que anteriormente dependía de realizar una limpieza estricta en cada situación. después de capturar bloques Exception is advised to use finally o gestores de contexto. Para realizar solo la limpieza y luego automáticamente volver a plantear la excepción. Vea consideraciones similares sobre la captura de KeyboardInterrupt en https://docs.python.org/3/library/exceptions.html#KeyboardInterrupt

airflow 2.8.2

Highlights

  • Breaking — allowed_deserialization_classes is now glob-based (#36147) — Values are matched as glob patterns (airflow.*, airflow.tests.*) instead of regexps. If you used a custom regexp path you must rewrite it as a glob, or move it to the new allowed_deserialization_classes_regexp list to preserve regexp matching; a broken regex is fixed as part of this change. Anyone with custom deserialization entries needs to migrate config before upgrading or task deserialization will silently stop matching.

  • Breaking — audit_logs access restricted to admins (#37501, #37292, #37468) — Viewer, Ops, and other non-admin roles can no longer view audit_logs from the Browse tab or DAG runs, closing a leak of user details (First Name, Email). Related to this, IMPORT_ERROR moved from DAG-related to view-related permissions. Upgrade carefully if your workflows depend on non-admin users reading audit history — those users will lose access with no opt-out.

  • Breaking — timeout errors now inherit BaseException, not Exception (#35653) — Both AirflowTimeoutError and AirflowTaskTimeout were re-parented so that broad except Exception blocks no longer swallow a cancellation and keep running. Code that relied on catching Exception to do strict cleanup must be rewritten with finally blocks or context managers that clean up and re-raise; catching explicitly is still possible but discouraged. This is the highest-risk migration item for custom operator/task code.

  • Security and bug fixes worth upgrading for — Hardening includes masking passwords with special characters (#36692) and sanitizing conn_id to block script execution (#32867). Notable fixes: PythonVirtualenvOperator no longer crashes when a python_callable shares the DAG's source (#37165), SystemExit raised in a task is handled (#36986), namedtuple serialization works (#37168), and a previously applied fix for future DagRuns under max_active_runs saturation was reverted (#37596) — if you were relying on that behavior, expect it to change back.

  • Packaging changes and who should upgrade — Pydantic became an optional dependency (#37320), markdown was removed from core dependencies (#37396), Alembic minimum raised to 1.13.1 (#36928), and flask-session constrained to <0.6 (#36895); Python 3.12 exclusions were added to provider builds (#37404). As a patch release with no new features, this is worth upgrading for security hardening and the bug fixes if you're on 2.8.x — but teams using regexp deserialization patterns, non-admin audit-log access, or except Exception-based timeout cleanup must complete the migrations above first; otherwise you can safely defer.

Significant Changes

The allowed_deserialization_classes flag now follows a glob pattern (#36147).

For example if one wants to add the class airflow.tests.custom_class to the allowed_deserialization_classes list, it can be done by writing the full class name (airflow.tests.custom_class) or a pattern such as the ones used in glob search (e.g., airflow.*, airflow.tests.*).

If you currently use a custom regexp path make sure to rewrite it as a glob pattern.

Alternatively, if you still wish to match it as a regexp pattern, add it under the new list allowed_deserialization_classes_regexp instead.

The audit_logs permissions have been updated for heightened security (#37501).

This was done under the policy that we do not want users like Viewer, Ops, and other users apart from Admin to have access to audit_logs. The intention behind this change is to restrict users with less permissions from viewing user details like First Name, Email etc. from the audit_logs when they are not permitted to.

The impact of this change is that the existing users with non admin rights won't be able to view or access the audit_logs, both from the Browse tab or from the DAG run.

AirflowTimeoutError is no longer except by default through Exception (#35653).

The AirflowTimeoutError is now inheriting BaseException instead of AirflowException->Exception. See https://docs.python.org/3/library/exceptions.html#exception-hierarchy

This prevents code catching Exception from accidentally catching AirflowTimeoutError and continuing to run. AirflowTimeoutError is an explicit intent to cancel the task, and should not be caught in attempts to handle the error and return some default value.

Catching AirflowTimeoutError is still possible by explicitly excepting AirflowTimeoutError or BaseException. This is discouraged, as it may allow the code to continue running even after such cancellation requests. Code that previously depended on performing strict cleanup in every situation after catching Exception is advised to use finally blocks or context managers. To perform only the cleanup and then automatically re-raise the exception. See similar considerations about catching KeyboardInterrupt in https://docs.python.org/3/library/exceptions.html#KeyboardInterrupt
