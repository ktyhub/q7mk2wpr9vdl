Cambios significativos

  • El código HTML sin formato en los documentos DAG y las descripciones de los parámetros DAG está deshabilitado de forma predeterminada. Para garantizar que los autores de DAG no puedan inyectar descripciones de DAG ni activar formularios de interfaz de usuario a ningún javascript malicioso. un nuevo parámetro webserver.allow_raw_html_descriptions was added with default value of False. Si modifica el código de autor de su DAG y desea permitir el uso de HTML sin formato en las descripciones y parámetros de DAG, puede restaurar el código anterior. comportamiento estableciendo el valor de configuración en True. Para garantizar que Airflow sea seguro de forma predeterminada, la compatibilidad con HTML sin formato en la interfaz de usuario del activador ha sido superpuesta por compatibilidad con rebajas a través de el description_md attribute. If you have been using description_html please migrate to description_md. El custom_html_form ahora está en desuso. (#35460)

airflow 2.8.0

Highlights

  • Secure-by-default DAG descriptions — Raw HTML in DAG docs, parameter descriptions, and trigger forms is now disabled. Set webserver.allow_raw_html_descriptions=True only if you trust DAG authors; otherwise migrate description_html to description_md, as custom_html_form is deprecated (#35460).
  • Airflow Object Store and data-table serialization — AIP-58 introduces Airflow Object Store (AFS) for provider-neutral object-storage workflows. Lightweight Delta Lake and Iceberg table serialization reduces serialization overhead and improves compatibility with data-heavy pipelines (#35462, #35456).
  • Better task logging and Python ergonomics — Task context logging forwards emitted messages into task logs (#32646, #32693, #35857). New PySpark, external-Python, and venv branching decorators expand authoring options, while the literal wrapper lets you explicitly disable field templating (#35247, #35043, #35017).
  • More flexible scheduling — schedule=None DAGs no longer require start_date, simplifying manually triggered workflows (#35356). The new prev_end_date_success accessor improves scheduling logic (#34528), and the UTC-offset fix addresses incorrect next-run calculations (#35887).
  • Improved UI and operations visibility — Grid gains an XCom tab (#35719), downstream task clearing from the task-instance view (#34529), and multi-select run states (#35403). Dataset listener hooks enable event-driven responses to dataset updates (#34418, #36247).
  • Dependency and API changes to review — Airflow upgrades to Pydantic v2 (#35551), renames Connection.to_json_dict() to Connection.to_dict() (#35894), changes the default MySQL client to MariaDB (#36243), and upgrades Elasticsearch support to 8.x (#33135). Audit custom Pydantic models, connection serialization, database clients, and provider compatibility before deploying.

Significant Changes

  • Raw HTML code in DAG docs and DAG params descriptions is disabled by default

    To ensure that no malicious javascript can be injected with DAG descriptions or trigger UI forms by DAG authors a new parameter webserver.allow_raw_html_descriptions was added with default value of False. If you trust your DAG authors code and want to allow using raw HTML in DAG descriptions and params, you can restore the previous behavior by setting the configuration value to True.

    To ensure Airflow is secure by default, the raw HTML support in trigger UI has been super-seeded by markdown support via the description_md attribute. If you have been using description_html please migrate to description_md. The custom_html_form is now deprecated. (#35460)
