airflow 3.1.2

Highlights

  • Dependency compatibility unblocked — #57335 repairs the import failure triggered by structlog 25.5.0+, and #56762 moves retry logic off retryhttp onto tenacity, an already-core dependency, so you can drop a package. If you had pinned structlog below 25.5 to keep Airflow importable, lift that pin — but re-test custom retry behavior after the tenacity switch, since exception and backoff semantics differ.

  • Airflow 2→3 migration hardening — Migration-path crashes get addressed: #55884 fixes triggerer errors after a 2→3 upgrade, #57459 corrects connection retrieval in DagProcessorManager during bundle initialization, and #57330 stops the DAG processor from ingesting callbacks from other bundles. This matters most for multi-bundle or distributed setups, where a stray callback or missing connection could previously take down the processor — consolidating on 3.1.2 removes several upgrade-time footguns.

  • Scalability fixes for large deployments — A concentrated wave of query and memory work targets the pain of many DAGs and DAG versions: N+1 elimination in XCom (#57554), Event Logs (#57558), and DAG-list tag fetches (#57570), plus a limited-access DAG-list optimization (#57460), an "Out of sort memory" fix (#57042), dynamic DAG updates that no longer load large serialized DAGs (#57592), smaller serialized DAGs via smarter default_args callback serialization (#57397), and an API-client SSL-context memory-leak fix (#57374). Expect lower DB load and faster UI/API responses on big instances — worth benchmarking if you run thousands of DAGs.

  • Task execution and API correctness — Several behavioral fixes change what developers can rely on: tasks killed by external signals now retry correctly (#55767), triggering_user_name is restored in context (#56193), outlet event extra data populates in task-instance success listener callbacks (#57031), Human-in-the-Loop operators work with notifiers (#57551), and Task SDK requests now carry a Content-Type header (#57386). Watch #57616, which tightens Pydantic validation strictness during serialization — stricter checks can surface latent type errors in custom operators that previously slipped through.

  • Observability and UI workflow — Debugging gets easier: you can download all task logs at once (#56771), the XCom viewer gains a timestamp column (#57447), the execution API server URL is logged at task startup (#57409), and event-log responses expose a task_display_name alias (#57609). Note #57548 downgrades "Connection not found" from error to debug — if you alert on that error-level line, update your rules or you'll miss it.

  • Breaking changes — None; this is a maintenance release with no significant or breaking changes.

  • Fix iteration errors when using ObjectStoragePath (#57156)
  • Fix auto-refresh not working on Required Actions page (#57207)
  • Fix DAG processor crash by ignoring callbacks from other bundles (#57330)
  • Fix asset name text overflow in DAG list view (#57363)
  • Fix memory leak caused by repeated SSL context creation in API client (#57374)
  • Fix performance issues loading DAG list page with many DAGs (#57444)
  • Fix text selection jumping unexpectedly in log viewer (#57453)
  • Fix DAG documentation pane not scroll-able when content is too long (#57518)
  • Fix incorrect macro listings in template reference documentation (#57529)
  • Fix Human-In-The-Loop operators failing when using notifiers (#57551)
