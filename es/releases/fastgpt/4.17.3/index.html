#FastGPT v4.17.3

Guía de actualización

Cambios de configuración

  • La versión Node.js implementada desde el código fuente debe cumplir con ^22.23.4 || ^24.22.1 || ^26.12.1. Confirme que el entorno operativo cumpla con este rango antes de realizar la actualización.
  • DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED todavía tiene por defecto false; cuando está habilitado, al grupo predeterminado de todos los miembros de un nuevo equipo no solo se le otorgará el permiso para crear aplicaciones, habilidades y bases de conocimientos, sino también el permiso de creación de la clave API. A los equipos existentes no se les otorgarán automáticamente permisos adicionales.
  • El límite superior total de instancias activas de la zona de pruebas del Agente se cambia para configurarse a través de AGENT_SANDBOX_MAX, con un valor predeterminado de 100. La cuota se comparte entre las sesiones de la aplicación y la edición de habilidades; el AGENT_SANDBOX_MAX_EDIT_DEBUG original ya no se utiliza. Se agregó AGENT_SANDBOX_MAX_PER_TEAM para establecer el límite superior para un solo equipo. No hay límite por defecto. La configuración de cuotas en la consola de administración de la versión comercial tiene prioridad sobre las variables de entorno.
  • OpenSandbox agrega AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR y AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR, el valor predeterminado es 1 y el valor no debe ser menor que 1. Solo tiene efecto cuando se está ejecutando Kubernetes y el servidor OpenSandbox no es inferior a v0.2.1. La reserva de recursos se reduce pero el límite superior de recursos permanece sin cambios. Solo afecta a los entornos sandbox recién creados o reconstruidos.
  • La consola de administración de la versión comercial ha agregado "Número máximo concurrente de recuperaciones de vectores" (systemEnv.vectorRecallConcurrency), que permite una configuración de 0-1000. El valor predeterminado de 0 significa que no hay límite. Los números positivos limitan la simultaneidad de recuperación compartida de todas las instancias de servicio y todas las bibliotecas de vectores; la versión de código abierto no permite este límite y no tiene variables de entorno correspondientes.
  • Se agregó AUXILIARY_GENERATION_SHOW_RUN_DETAIL, predeterminado false, para controlar si se muestra la entrada de detalles de la operación generada por habilidades, agentes y asistencia de flujo de trabajo.
  • La dirección predeterminada de App Market (MARKETPLACE_URL) se actualiza a https://v3.marketplace.fastgpt.cn y la dirección personalizada configurada explícitamente continúa usando el valor original.

Script de actualización

El sistema primero completa las tareas de inicio necesarias y su cadena de dependencia de requisitos previos, y luego cada instancia de la aplicación recarga el modelo y luego inicia el negocio. Las siguientes 3 tareas nuevas se ejecutan automáticamente en segundo plano, con un máximo de 3 cuotas simultáneas en el clúster compartido. El fracaso no bloqueará las tareas no dependientes; Puede ver los resultados en la página de administración, reparar los datos fallidos y volver a intentarlo.

  • Rellenar la afiliación del equipo de la instancia sandbox (20261009_backfill_agent_sandbox_team_id): complete la afiliación del equipo de las instancias históricas según las aplicaciones de origen o las habilidades para las estadísticas de cuota del equipo; Los registros huérfanos con fuentes eliminadas se omiten y cuentan.
  • Rellenar rutas ancestrales del directorio (20261022_backfill_folder_ancestor_ids): reconstruya las rutas de los directorios de aplicaciones, herramientas y bases de conocimientos y limpie los campos residuales de los recursos que no son carpetas. Las carpetas que se encuentran directamente debajo de otros tipos de árboles de directorios se mueven al directorio raíz de este equipo y se borran los antiguos permisos de herencia de los padres; los caminos de ancestros entre árboles de nivel superior se truncan en los límites. Los registros de excepción, como padres faltantes, equipos cruzados o bucles, se conservan como elementos fallidos y se volverán a intentar después de la reparación.
  • Migrar el precio del modelo del sistema a millones de unidades (20261025_token_prices_per_million): convierta el precio del modelo del sistema histórico y escríbalo en pricing, conserve el valor original del campo anterior y omita el modelo que ya tiene pricing legal; el modelo de equipo no participa en la migración.

Instrucciones de compatibilidad

  • activación de root y contraseña: elimine DEFAULT_ROOT_PSW, el inicio ya no sobrescribirá la contraseña de root existente. La contraseña inicial para una nueva raíz es 123456. Debe establecer una nueva contraseña cuando inicie sesión por primera vez; cuando la raíz histórica status no se guarda, debe usar la contraseña original para iniciar sesión y completar la activación. Los cambios diarios de contraseña se realizan en la página de información de la cuenta. Cuando olvide su contraseña, utilice el script de restablecimiento de contraseña de root y proporcione la nueva contraseña explícitamente.
  • Unidad de precio del modelo: LLM usa pricing.tiers, otros modelos usan pricing.unitPrice. Precio unitario del token y escalera maxInputTokens El límite superior se cambia a un millón de tokens, el TTS se cambia a un millón de caracteres, el STT sigue siendo cada 60 segundos y el precio unitario se mantiene con dos decimales. Después de la actualización, confirme que la migración en segundo plano se realizó correctamente y verifique el precio del modelo del sistema; Los modelos de sistema que no se han migrado a pricing se tratan temporalmente como gratuitos y los modelos de equipo son gratuitos.
  • Verificación de la orquestación del flujo de trabajo: el lienzo, la depuración y la generación auxiliar siguen uniformemente [reglas de organización] (/guide/build/workflow/rules). Se prohíben los loopbacks en serie puros, las conexiones de procesos entre herramientas y múltiples nodos de llamada que comparten la misma entrada de herramienta, y se permite el reflujo controlado por salidas de condiciones válidas. Los subprocesos de herramientas pueden leer en sentido ascendente de la persona que llama, pero no pueden hacer referencia a resultados que la persona que llama no haya producido. El flujo de trabajo anterior conserva las conexiones existentes y puede guardar borradores. Las conexiones que no cumplan con las reglas deben corregirse antes de depurar y publicar.
  • Permisos de administración de la base de conocimientos: la modificación de la información básica de la base de conocimientos, la configuración del modelo y sus propios atributos, como nombres de archivos, etiquetas, estado deshabilitado, etc., requiere permisos administrables (manage); las operaciones de contenido continúan utilizando los permisos de edición originales. La modificación de atributos al mover un archivo también requiere permisos administrativos para el archivo.
  • Exportación de la base de conocimientos: /api/core/dataset/exportAll solo admite una única base de conocimientos y la exportación del directorio debe solicitarse por base; cuando los permisos a nivel de archivo están habilitados, solo se exportarán los archivos que puedan leer los miembros actuales.
  • Tipo de archivo de conversación: se agregaron document y unknown a la categoría de archivos adjuntos; Los antiguos parámetros de entrada y registros históricos del file siguen siendo compatibles y están clasificados por nombre de archivo, enlace e información de respuesta. El cliente personalizado debe ser compatible con la nueva clasificación y ya no utilizar únicamente file para juzgar documentos.
  • Paginación y respuesta de error: la paginación general tratará a pageSize que exceda 500 como 500, y algunas interfaces aún tienen restricciones menores; cuando se pasan offset y pageNum al mismo tiempo, se utilizará primero offset, incluido offset=0, y los desplazamientos ilegales no se revertirán a los números de página. La solicitud API identificada como un error de configuración del usuario devuelve HTTP 400 y la parte de acceso debe manejarla como una respuesta de error.

FastGPT v4.17.3

Highlights

  • Runtime and upgrade path — Source deployments now require Node.js ^22.23.4 || ^24.22.1 || ^26.12.1 (images use 24.22.1). DEFAULT_ROOT_PSW is removed: existing root passwords are no longer overwritten, new roots start with 123456 and must set a password on first login, and legacy roots without status must activate with their existing password. Three background migrations backfill sandbox team ownership, folder ancestors and pricing; retry failures before trusting quotas, ACL paths or billing. SeekDB data now survives container restart/recreation (#7942).
  • Billing units change — LLM pricing.tiers and other models’ pricing.unitPrice now express prices per million tokens; tier maxInputTokens is also in millions, TTS is per million characters, and STT remains per 60 seconds, rounded to two decimals. Migration preserves legacy fields and skips valid pricing; team models are excluded. Audit migrated system-model prices—unmigrated system models and team models are treated as free.
  • Workflow/Agent authoring — Pro adds resumable assisted workflow generation, but candidates still require manual application, inspection and debugging before save/publish; it needs edit rights plus assisted-generation and sandbox capabilities. Variables can now supply select options, passwords, tool secrets and HTTP/MCP auth headers. Canvas, debug and assistance share stricter validation: pure serial loops, cross-tool edges and multiple callers sharing one tool entry are rejected, while valid conditional backflow is allowed. Existing invalid drafts remain editable but must be corrected before debug/publish.
  • Permissions and tenant isolation — Team members can configure isolated models/channels with AI Proxy integration (#7895), and owners can bulk-replace invalid model references. Dataset metadata, model and file-attribute changes—including file moves—now require manage; content operations retain edit. App test/debug paths enforce edit rights before node execution and run system tools as the actual member (#7927). Cross-team PG/OpenGauss recall and cross-dataset image access are fixed; folder inheritance is opt-in at creation (#7966).
  • Sandbox capacity controls — Replace AGENT_SANDBOX_MAX_EDIT_DEBUG with AGENT_SANDBOX_MAX (default 100), shared by app sessions and skill editing; AGENT_SANDBOX_MAX_PER_TEAM adds a per-team cap and defaults to unlimited. Kubernetes with OpenSandbox Server ≥ v0.2.1 supports CPU/memory overcommit factors (default and minimum 1), lowering reservations without raising hard limits and affecting only new/rebuilt sandboxes.   • API and integration contracts — Pagination caps pageSize at 500 (some endpoints lower), prefers offset over pageNum even for offset=0, and no longer falls back on invalid offsets; recognized user-config errors return HTTP 400. /api/core/dataset/exportAll is single-dataset and respects readable-file ACLs. Chat attachments add document/unknown while retaining legacy file, so clients must stop using file alone to detect documents. Pro streamed/raw responses survive NextAPI (#7971); MCP and external channels now share team QPM limits, with dependency failures failing open.

兼容说明

  • root 激活与密码：移除 DEFAULT_ROOT_PSW，启动不再覆盖已有 root 密码。新建 root 初始密码为 123456，首次登录需设置新密码；历史 root 未保存 status 时需使用原密码登录并完成激活。日常改密在账号信息页操作，忘记密码时使用 root 密码重置脚本，并显式提供新密码。
  • 模型计价单位：LLM 使用 pricing.tiers，其他模型使用 pricing.unitPrice。Token 单价与阶梯 maxInputTokens 上限改为百万 Tokens，TTS 改为每百万字符，STT 仍按每 60 秒，单价最多保留两位小数。升级后确认后台迁移成功并核对系统模型价格；未迁入 pricing 的系统模型暂按免费处理，团队模型免费。
  • 工作流编排校验：画布、调试与辅助生成统一遵循编排规则，禁止纯串行回环、跨工具流程连线及多个调用节点共用同一工具入口，允许由有效条件出口控制的回流。工具子流程可读取调用者上游，但不可引用调用者自身尚未产生的输出。旧工作流保留已有连线并可保存草稿，调试和发布前需修正不符合规则的连线。
  • 知识库管理权限：修改知识库基本信息、模型配置，以及文件名称、标签、禁用状态等自身属性需要可管理（manage）权限；内容操作继续使用原有编辑权限。移动文件时同时修改属性，也需要该文件的管理权限。
  • 知识库导出：/api/core/dataset/exportAll 仅支持单个知识库，目录导出需逐库请求；开启文件级权限时，仅导出当前成员可读文件。
  • 对话文件类型：附件分类新增 document 与 unknown；旧 file 入参和历史记录继续兼容，并按文件名、链接及响应信息归类。自定义客户端应兼容新分类，不再仅用 file 判断文档。
  • 分页与错误响应：通用分页将超过 500 的 pageSize 按 500 处理，部分接口仍有更小限制；同时传入 offset 和 pageNum 时优先使用 offset，包括 offset=0，非法偏移量不回退为页码。被识别为用户配置错误的 API 请求返回 HTTP 400，接入方需按失败响应处理。
