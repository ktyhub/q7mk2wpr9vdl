Script de actualización

Esta actualización incluye los siguientes scripts de automatización

  1. Rellene la instantánea de permisos de recursos de la aplicación, limpie la aplicación V1 heredada y los datos de la versión, y verifique la versión oficial de la aplicación; la tarea de migración no bloquea el inicio del servicio y los registros de progreso y fallas se pueden ver en la tarea de actualización del sistema.
  2. Habilite el mapeo de razonamiento para canales compatibles: habilite la conversión del campo de respuesta map_reasoning_to_reasoning_content: true para el canal de protocolo AIProxy OpenAI existente para resolver el problema de compatibilidad del campo de contenido de pensamiento de los modelos de pensamiento profundo (como DeepSeek-R1) y conservar la configuración original del canal; Los canales que se hayan configurado con este elemento no se actualizarán repetidamente y la tarea de migración no bloqueará el inicio del servicio.
  3. Actualizar los datos de etiquetas de la base de conocimientos: migrar etiquetas de colección existentes a etiquetas escritas y limpiar definiciones de etiquetas duplicadas; la tarea de migración no bloquea el inicio del servicio.
  4. Rellenar la marca de configuración del nombre del miembro del equipo: rellene la marca isSetMemberName para los miembros históricos del equipo; el propietario siempre se marca como establecido, y los nombres de miembros que no son propietarios y que son iguales al nombre de usuario de inicio de sesión se marcan como que deben complementarse; la tarea de migración no bloquea el inicio del servicio.

Ajuste de entrada del administrador

La interfaz de gestión de versiones comerciales se ha integrado en la aplicación principal FastGPT. Después de iniciar sesión, el usuario root puede acceder a las páginas de configuración del sistema, administración de operaciones y activación y renovación de licencias desde el portal "Administrador". La configuración del sistema se encuentra en /admin/settings/*, las herramientas del sistema y los modelos del sistema se encuentran en /admin/resources/tool y /admin/resources/model respectivamente. El antiguo camino ya no se mantiene.

Aún es necesario conservar el servicio FastGPT Pro; Si se configura una verificación de estado personalizada para Pro, ajuste la ruta de detección a /api/health.

FastGPT v4.17.1

Highlights

  • Admin routes are a breaking change — Commercial administration is now part of the main app, and old management URLs are removed. Root users should update bookmarks and integrations to /admin/settings/*, /admin/resources/tool, and /admin/resources/model (#7777, #7792, #7805). Keep fastgpt-pro deployed, and point custom Pro health checks to /api/health.

  • Published apps gain permission snapshots — Static resources are authorized against their release-time snapshot, while dynamic resources are checked against the actual runtime user, eliminating permission drift in collaboratively developed apps (#7559). This may expose previously tolerated access mismatches; monitor the non-blocking migration, which also cleans legacy V1 apps and associated versions, chats, and external links.

  • Knowledge bases add opt-in file authorization and typed search — File/folder-level collaborators, inheritance, independent overrides, and ownership transfer arrive in #7750; authorization applies individually to lists, details, and retrieval. The feature defaults off, and disabling it clears all file-level permission configuration. Typed tags now filter workflow and Agent V2 searches (#7660), while Agent V2 citations show the actual retrieved reference content (#7737).

  • Workflow integrations and execution become more predictable — Workflows can now serve as entry points (#7724), and isolated tool runtime state plus restored interactive memory reduce cross-call contamination and lost resume context (#7727). The new hidden off input type preserves parameter definitions, defaults, and validation for third-party APIs without rendering a control or allowing Agent-generated values; singleton JSON objects sent to array variables are also wrapped automatically to prevent loop and parallel failures.

  • Model administration becomes safer and more observable — Admins can change a system model’s model through stable modelId, with associated channel mappings synchronized automatically (#7808). Optional scheduled probes provide 48-hour health graphs and state-change Webhooks, while new OpenAPI endpoints expose public and member-available model lists and batch model details through API-Key authentication; app dashboards also report token consumption (#7775).

  • SSO and security controls tighten — Third-party password changes now share one authorization, verification, and update flow (#7368), and administrators can prohibit platform-password login or password changes within an SSO namespace; review this policy carefully because it removes that local authentication path. Security fixes also close Markdown-link stored XSS, MCP DNS-rebinding SSRF, and unsafe S3 import authorization, while CHECK_INTERNAL_IP=true no longer incorrectly blocks supported internal integrations such as log delivery and DingTalk token retrieval.
