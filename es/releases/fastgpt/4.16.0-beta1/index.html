#FastGPT v4.16.0-beta1

📦 Guía de actualización

1. Actualice la variable de entorno Agent-sandbox-proxy (opcional)

4.16.0 necesita depender del proxy para el acceso al proxy de recursos estáticos. Si la puerta de enlace admite ws y http en el mismo puerto, solo puede abrir un puerto. Si no es compatible, puede configurar el puerto de acceso http configurando PREVIEW_PORT.

# ws和http服务的端口
PORT=1006
# http服务的端口，可以覆盖 PORT
PREVIEW_PORT=1007

La dirección de acceso comienza con http:// o https://. Cuando se implementa con un solo puerto, puede apuntar al mismo nombre de dominio y puerto que AGENT_SANDBOX_PROXY_URL, pero los protocolos usan HTTP(S) y WebSocket(S) respectivamente. Se recomienda encarecidamente que el nombre de dominio configurado y el sitio principal de FastGPT utilicen orígenes diferentes. La implementación del mismo origen permitirá que estos scripts ingresen al límite de seguridad del mismo origen del sitio principal y potencialmente accedan a las credenciales o interfaces del sitio principal. Actualmente, el sistema no exige la verificación del origen para el aislamiento.

Puedes comprobar si es accesible visitando: https://{{host}}/health.

2. Actualice la variable de entorno fastgpt-app (debe actualizarse si el entorno de pruebas está habilitado)

Las variables se modifican simultáneamente en fastgpt-app y fastgpt-pro.

  1. Agregar variables de entorno
# 浏览器访问 Sandbox 文件预览的 HTTP(S) 地址，这个地址从第一步取。
AGENT_SANDBOX_PREVIEW_PROXY_URL=https://sandbox-proxy.example.com
# opensandbox 需配置，存储全前缀名（之前是配置在 volumn 镜像环境变量里）
VM_VOLUME_NAME_PREFIX=fastgpt-session
  1. Variables de entorno de sandbox obsoletas

AGENT_SANDBOX_DISK_MB, variables relacionadas con E2B.

  1. Nuevas variables de configuración opcionales de sandbox

| variables | valor predeterminado | descripción | | ---------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------- | | AGENT_SANDBOX_CPU_COUNT | 1 | Límite de núcleos de CPU de instancia única de Agent Sandbox. | | AGENT_SANDBOX_MEMORY_MIB | 2048 | Límite de memoria de instancia única de Agent Sandbox, unidad MiB. | | AGENT_SANDBOX_STORAGE_SIZE_GI | 1 | Capacidad de almacenamiento del agente Sandbox, en Gi; se utiliza para el límite de almacenamiento de Sealos Devbox y para crear nuevos PVC en el modo OpenSandbox Kubernetes. | | AGENT_SANDBOX_SUSPEND_MINUTES | 60 | Cuánto tiempo se pausará automáticamente el Sandbox en ejecución después de estar inactivo, en minutos. | | AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS | 7 | El Sandbox en pausa se archiva automáticamente después del tiempo que estará inactivo, en días. |

Se eliminó el proveedor de entorno de pruebas E2B. Los entornos que hayan configurado previamente E2B deben cambiar a opensandbox o sealosdevbox y eliminar AGENT_SANDBOX_E2B_API_KEY.

Los protocolos de vista previa de FastGPT, fastgpt-agent-sandbox-proxy y fastgpt-agent-sandbox se cambiaron simultáneamente. Esta versión de la imagen de soporte se debe utilizar al habilitar Agent Sandbox y no se admite la implementación mixta de versiones antiguas y nuevas.

4. Migrar datos de la zona de pruebas del agente

Esta versión ajusta el Agent Sandbox de App Chat de "una instancia por conversación" a "una instancia compartida por la misma aplicación y el mismo usuario". Los archivos de diferentes conversaciones todavía se guardan en el directorio sessions/<chatId> respectivamente, y las habilidades publicadas se guardan en el directorio compartido projects.

Si Agent Sandbox estaba habilitado anteriormente, la migración del espacio de trabajo heredado debe completarse en el siguiente orden. Los entornos que no hayan habilitado Agent Sandbox pueden omitir esta sección.

Primero realice un ensayo para ver el recuento pendiente de la normalización del campo de Sandbox beta6 y la limpieza del antiguo chat de depuración de habilidades. La ejecución en seco no crea recursos, no accede al almacenamiento de objetos ni modifica datos:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Realice la migración oficial después de ver los resultados del ensayo. La migración oficial primero realizará la normalización beta6 y solo continuará con el archivado del espacio de trabajo en la misma solicitud cuando el recuento pendiente restante llegue a cero:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

Si failures solo contiene Sandbox source is missing or deleted y se ha confirmado que la aplicación o habilidad correspondiente ya no existe, puedes omitir explícitamente estos entornos limitados residuales:

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError El valor predeterminado es false, manteniendo una migración estricta cuando se omite. Este modificador solo omite todo el grupo cuyo origen falta o se elimina temporalmente, y no archiva, elimina ni migra el entorno limitado dentro de él; Los detalles de omisión se devuelven a través de skippedCount y skipped. Otros errores, como el archivado, el almacenamiento de objetos, los proveedores y el control de concurrencia, aún pueden bloquear las migraciones. La migración primero ejecutará la lógica previa completa de V4.15.0-beta6: completará el sourceType/sourceId del antiguo Sandbox, limpiará los campos heredados, eliminará los recursos huérfanos que no se pueden atribuir y limpiará los datos de tres tablas del antiguo Skill Debug Chat al que le faltan sourceType y los prefijos antiguos de los depósitos públicos y privados. Las habilidades con el mismo ID que la aplicación omitirán la limpieza del chat. Después de reformular los dos tipos de datos, el total es normalization.pendingCount; cuando la cantidad no sea 0, no se ingresará en el archivo del espacio de trabajo. Después de la puesta a cero, archive directamente todos los espacios de trabajo antiguos y limpie los recursos informáticos antiguos, luego migre las habilidades y, finalmente, agréguelas en entornos sandbox a nivel de usuario por aplicación y usuario. Mientras haya un error en la fase de archivo, la fase de instalación no comenzará. El nuevo Sandbox se pausará una vez completada la instalación de Workspace y se iniciará según el proceso normal cuando se utilice por primera vez. Es seguro reintentar los scripts y los archivos y migraciones completados no se vuelven a ejecutar; Los archivos antiguos y los registros antiguos de MongoDB se conservan como copias de seguridad una vez completada la migración.

Verifique los resultados devueltos para normalization.pendingCount, normalizationBlocked, failedCount, failures, skippedCount y skipped. Solo cuando normalization.pendingCount y failedCount son 0 y normalizationBlocked es false, significa que se completaron todas las migraciones de Sandbox no omitidas; Los registros heredados en skipped se conservarán y no se migrarán.

5. Migrar datos de la herramienta HTTP

Esta versión cambia los parámetros de matriz de la herramienta HTTP en modo manual al esquema estándar JSON. Los entornos que han creado herramientas HTTP manuales antes de la actualización deben realizar esta migración; No es necesario migrar las herramientas HTTP en modo OpenAPI y el script se omitirá automáticamente.

Primero ejecute un simulacro para ver los datos que se procesarán en la aplicación actual y en las versiones históricas. el ensayo no modifica los datos:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

Luego de confirmar el resultado, realice la migración oficial:

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

El script primero filtrará las aplicaciones por tipo de herramienta HTTP y luego migrará las versiones históricas correspondientes basadas en appId de estas aplicaciones. Sólo se procesarán los modos manuales que no existen para apiSchemaStr, no se modificarán otras aplicaciones ni los modos OpenAPI. La migración se ejecuta en lotes y se puede volver a intentar de forma segura; total.changedDocumentCount en el resultado devuelto indica la cantidad de documentos que se encontraron para procesar. Después de la ejecución formal, puede volver a realizar un ensayo para confirmar que el valor es 0.

🚀 Nuevo contenido

  1. El Agent Sandbox se cambia a una instancia de nivel de usuario de la aplicación. Varias conversaciones de la misma aplicación y el mismo usuario reutilizan el Sandbox y aíslan cada archivo de conversación a través de un directorio de sesión independiente.
  2. Los archivos y HTML de Sandbox admiten la vista previa directa a través de enlaces de solo lectura a corto plazo y ya no es necesario cargarlos repetidamente en el almacenamiento de objetos para obtener una vista previa.
  3. App Workflow archiva y restaura automáticamente el espacio de trabajo cuando cambia el proveedor de Sandbox o la imagen del tiempo de ejecución, y el proceso de actualización se completa de forma silenciosa durante la ejecución actual.
  4. El nodo de la herramienta de flujo de trabajo admite la generación automática de parámetros de entrada específicos por parte del Agente y conserva las configuraciones existentes, como valores fijos, referencias y entradas del usuario.
  5. Cuando ChatAgent selecciona una herramienta, permite especificar manualmente si se generan parámetros para la IA.
  6. Los datos de la base de conocimientos admiten la personalización de metadata y los metadatos de JSON se pueden importar a través de plantillas de API, CSV o Excel; Este campo se conservará en los resultados de búsqueda y en las exportaciones de copias de seguridad. Tanto la importación de plantillas como la importación de copias de seguridad admiten archivos .csv y .xlsx, utilizando encabezados q, a, index y metadata; q, a y metadata tienen una columna cada uno y index puede tener varias columnas en cualquier orden. Los archivos de Excel solo admiten una única hoja de trabajo y no pueden contener celdas combinadas. Los archivos CSV o Excel que no se puedan analizar correctamente generarán una excepción de formato de archivo.
  7. Cargue archivos grandes en trozos.
  8. Cuando el administrador configura la clave de la herramienta del sistema, está cifrada (compatible con la clave configurada).
  9. Guía de estado vacía en la lista de habilidades y vínculo al seleccionar habilidades.

⚙️ Optimización

  1. Reconstruir el ciclo de vida y el proceso de migración del Agent Sandbox. Crear, pausar, archivar, restaurar, eliminar y cambiar de proveedor admiten protección de concurrencia, reanudación de puntos de interrupción y reintentos idempotentes.
  2. Cuando Agent Sandbox no está disponible o no es compatible con el paquete de equipo actual, App Chat desactiva automáticamente la capacidad Sandbox y otros modelos, herramientas, bases de conocimiento y nodos de flujo de trabajo aún pueden continuar ejecutándose.

  5. Cree automáticamente directorios principales antes de escribir archivos Sandbox para evitar errores al escribir rutas anidadas.

FastGPT v4.16.0-beta1

Highlights

  • Sandbox instance model + mandatory migration — Agent Sandbox shifts from one instance per chat to a single shared instance per App per user; per-chat files stay isolated under sessions/<chatId>, while published Skills move to a shared projects directory. Anyone who has ever enabled Sandbox must run /api/admin/4160/initUserSandbox (dry-run first, then real) or old Workspaces will never be archived and migrated. The script replays the v4.15.0-beta6 normalization first and refuses to archive while normalization.pendingCount is nonzero; skipError:true (#7417) only skips groups whose source App/Skill is gone (soft-deleted), not other failures. Declare success only when normalization.pendingCount and failedCount are 0 and normalizationBlocked is false — skipped Legacy records remain in place and are not migrated. New Sandboxes are installed then paused until first use, and old archives plus MongoDB records are kept as backups. Mixed old/new image deployments are explicitly unsupported.

  • E2B removed; env-var surface changed — The E2B Sandbox Provider is gone: switch to opensandbox or sealosdevbox and delete AGENT_SANDBOX_E2B_API_KEY. Add AGENT_SANDBOX_PREVIEW_PROXY_URL and, for OpenSandbox, VM_VOLUME_NAME_PREFIX (moved out of the volume image); AGENT_SANDBOX_DISK_MB and E2B variables are deprecated, while new tunables cover CPU/memory/storage and suspend/archive thresholds plus AGENT_SANDBOX_OPENSANDBOX_DISABLE_NETWORK_POLICY (#7406). The proxy needs PORT/PREVIEW_PORT (http may override ws) and exposes /health; deploy it on a different origin from the main site — origin isolation is only "strongly recommended," not enforced, and same-origin preview scripts land inside the main site's security boundary with access to its credentials and APIs. Separately, PASSWORD_LOGIN_LOCK_SECONDS is replaced by PASSWORD_LOGIN_MINUTE_LIMIT_COUNT for per-minute login throttling.

  • Manual HTTP tool params → JSON Schema migration — Environments with pre-existing manual-mode HTTP tools must run /api/admin/4160/initHttpToolSchema (dry-run, then real); only tools lacking apiSchemaStr are touched, and OpenAPI-mode tools are auto-skipped. This matters because tool input runtime compilation was unified (#7419), legacy input defaults had to be restored (#7462), and the runtime now accepts JSON Schema 2019-09 and 2020-12 dialects (#7425) — so custom schemas that previously failed validation should now work, but re-run the dry-run until total.changedDocumentCount is 0 to confirm nothing is left behind (#7416).

  • Dataset custom metadata — dataset_data gains a metadata field (#7400) importable via API or CSV/Excel templates with headers q, a, index, metadata (#7449); it survives into retrieval results and backup exports (#7436). Practical constraints: q/a/metadata are single columns, index may span multiple columns in any order, and Excel must be a single worksheet with no merged cells — expect "file format abnormal" errors otherwise, so normalize existing templates before bulk imports.

  • Sandbox preview pipeline rewritten — Sandbox HTML and files now render through short-lived read-only links instead of re-uploading to object storage, and the proxy/IDE agent adds Workspace direct preview, Range requests, path-escape protection, and session auth. Because the preview protocol changed in lockstep across FastGPT, the proxy, and the sandbox, this is a matched-image set (proxy and volume at v0.3.0-beta4), not an in-place drop-in — plan a coordinated upgrade. During rollout there is a safety net: if the Sandbox is unavailable or the team plan doesn't support it, App Chat disables only Sandbox capabilities while models, tools, knowledge bases, and Workflow nodes keep running.

  • Workflow and agent tool-node behavior — Workflow tool nodes can now delegate selected inputs to the Agent for generation while preserving fixed values, references, and user input, and ChatAgent exposes a manual toggle for AI-generated parameters. Existing apps should retain their configured inputs thanks to explicit render-type preservation (#7437) and fixes for duplicate parameter rendering (#7465) and lost defaults (#7462), but verify apps that relied on implicit array/JSON rendering after the runtime refactor, since the underlying schema handling changed substantially.

4. 迁移 Agent Sandbox 数据

本版本将 App Chat 的 Agent Sandbox 从“每个对话一个实例”调整为“同一 App、同一用户共享一个实例”。不同对话的文件仍分别保存在 sessions/<chatId> 目录中，已发布 Skill 则统一保存在共享的 projects 目录中。

如果此前启用过 Agent Sandbox，必须按以下顺序完成旧 Workspace 迁移。未启用过 Agent Sandbox 的环境可以跳过本节。

先执行 dry-run，查看 beta6 Sandbox 字段归一化和旧 Skill Debug Chat 清理的待处理数。dry-run 不会创建资源、访问对象存储或修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

查看 dry-run 结果后执行正式迁移。正式迁移会先执行 beta6 归一化，并且只在剩余待处理数归零时，才在同一请求中继续 Workspace 归档：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

如果 failures 中仅包含 Sandbox source is missing or deleted，并且已确认对应 App 或 Skill 确实不再存在，可以显式跳过这些残留 Sandbox：

curl -X POST 'https://你的域名/api/admin/4160/initUserSandbox' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false,"skipError":true}'

skipError 默认为 false，省略时保持严格迁移。该开关只跳过 source 已缺失或已软删除的整个分组，不会归档、删除或迁移其中的 Sandbox；跳过明细通过 skippedCount 和 skipped 返回。归档、对象存储、Provider 和并发控制等其他错误仍会阻断迁移。

迁移会先执行 V4.15.0-beta6 的完整前置逻辑：补齐旧 Sandbox 的 sourceType/sourceId、清理遗留字段、删除无法归属的孤立资源，并清理缺失 sourceType 的旧 Skill Debug Chat 三表数据及私有、公开 Bucket 旧前缀。与 App 同 ID 的 Skill 会跳过 Chat 清理。两类数据重新统计后合计为 normalization.pendingCount；数量不为 0 时不会进入 Workspace 归档。归零后直接归档全部旧 Workspace 并清理旧计算资源，再迁移 Skill，最后按 App、用户聚合到用户级 Sandbox。只要归档阶段存在失败，安装阶段就不会开始。新的 Sandbox 会在 Workspace 安装完成后暂停，首次使用时再按正常流程启动。脚本可安全重试，已完成的归档和迁移不会重复执行；迁移完成后会保留旧归档和旧 MongoDB 记录作为备份。

请检查返回结果中的 normalization.pendingCount、normalizationBlocked、failedCount、failures、skippedCount 和 skipped。只有 normalization.pendingCount 和 failedCount 均为 0，且 normalizationBlocked 为 false 时，才表示所有未跳过的 Sandbox 迁移完成；skipped 中的 Legacy 记录会保留且不会迁移。

5. 迁移 HTTP 工具数据

本版本将手动模式 HTTP 工具的数组参数改为标准 JSON Schema。升级前创建过手动 HTTP 工具的环境需要执行此迁移；OpenAPI 模式的 HTTP 工具无需迁移，脚本会自动跳过。

先执行 dry-run，查看当前应用及历史版本中的待处理数据。dry-run 不会修改数据：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":true}'

确认结果后执行正式迁移：

curl -X POST 'https://你的域名/api/admin/4160/initHttpToolSchema' \
  -H 'Content-Type: application/json' \
  -H 'rootkey: 你的ROOT_KEY' \
  -d '{"dryRun":false}'

脚本会先按 HTTP 工具类型筛选应用，再根据这些应用的 appId 迁移对应的历史版本。仅 apiSchemaStr 不存在的手动模式会被处理，其他应用及 OpenAPI 模式不会修改。迁移按批次执行且可安全重试；返回结果中 total.changedDocumentCount 表示发现的待处理文档数，正式执行后可再次 dry-run，确认该值为 0。

🚀 新增内容

  1. Agent Sandbox 改为 App 用户级实例，同一 App、同一用户的多个对话复用 Sandbox，并通过独立 session 目录隔离各对话文件。
  2. Sandbox HTML 和文件支持通过短期只读链接直接预览，不再为预览重复上传到对象存储。
  3. App Workflow 在 Sandbox Provider 或运行时镜像变化时自动归档并恢复 Workspace，升级过程在当前运行中静默完成。
  4. 工作流工具节点支持将指定输入参数交由 Agent 自动生成，并保留固定值、引用和用户输入等既有配置。
  5. ChatAgent 选择工具时，支持手动指定是否为 AI 生成参数。
  6. 知识库数据支持自定义 metadata，可通过 API、CSV 或 Excel 模板导入 JSON 元数据；检索结果和备份导出会保留该字段。模板导入和备份导入均支持 .csv 和 .xlsx 文件，使用 q、a、index、metadata 表头；q、a、metadata 各一列，index 可多列且顺序任意。Excel 文件仅支持单个工作表且不能包含合并单元格，无法正确解析的 CSV 或 Excel 文件会提示文件格式异常。
  7. 大文件分块上传。
  8. 管理员配置系统工具密钥时，加密（兼容已配置的密钥）。
  9. 技能列表空状态引导，以及选择技能时联动。
