Papelclip v2026.1106.0

Publicado: 2026-11-06

Paperclip v2026.1106.0 incluye 515 confirmaciones, promovidas desde 2026.1023.0-beta.0. El titular es que Paperclip Runner es ahora el predeterminado para los nuevos agentes: los nuevos agentes Claude, Codex, OpenCode y Pi se inician en el Runner nativo en hosts macOS y Linux calificados, los agentes existentes obtienen una acción de "Actualizar ejecutor" de un click y GitHub Copilot se une como un arnés nativo. En torno a eso: repositorios de proyectos que se convierten automáticamente en fuentes de habilidades, prevención de inyección rápida respaldada por modelos, observabilidad del agente en Braintrust o cualquier punto final OTLP, una conexión unificada de Google Workspace, ediciones masivas en la lista de agentes, espacios de trabajo que se compactan y caducan con puntos de restauración cifrados, y Grok Bot y Muse como proveedores de Runner experimentales. Debajo, el servidor reinicia el informe y está listo antes, la imagen Docker arranca desde un paquete precompilado, las páginas de tareas se cargan más rápido y más servicios en segundo plano dejan de sondear la base de datos.

Cambios importantes

  • Se eliminó el experimento Pipelines. Los tableros de canalización, la configuración de escenario, la automatización de casos, las colas de revisión, los comandos pipelines CLI, el permiso pipelines:write, la configuración enablePipelines y el campo linkedCases en los detalles de la tarea desaparecieron; Los casos y las rutinas permanecen. Las tablas y registros de canalización existentes se conservan intactos y se ignora un valor enablePipelines almacenado. (#16834)
  • Los errores de ejecución ya no llegan a Sentry de forma predeterminada. Un DSN de backend por sí solo ya no informa errores de ejecución del agente. Configure PAPERCLIP_SENTRY_RUN_FAILURES=unexpected para mantener la política filtrada anterior o all para informar cada ejecución fallida o con tiempo de espera agotado; el valor predeterminado es off. (#16300)
  • La lista del historial de ejecución está limitada. GET /api/companies/{companyId}/heartbeat-runs devuelve 200 filas de forma predeterminada y como máximo 1000; clients que dependían de una matriz ilimitada deben pasar un limit explícito. (#16286)
  • paperclipai agent instructions-file:delete requiere --yes como los otros comandos destructivos CLI; los scripts que lo llaman deben agregar la bandera. (#11504)

Destacados

  • El Paperclip Runner es el predeterminado: nuevos agentes Claude en Apple Silicon, Intel macOS y Linux x64 (#15993, #15997), nuevos agentes Codex en Apple Silicon, Intel macOS, Linux x64 y Linux ARM64 (#15683) y nuevos agentes OpenCode y Pi en macOS y Linux x64 (#17120, #17142) ahora se inicia en el Runner nativo en lugar del adaptador heredado, a través de la incorporación, API y CLI, contrataciones, integraciones, complementos e importaciones; Linux necesita GNU libc 2.39 o posterior, una anulación de "ejecutor heredado" se encuentra en Avanzado y los agentes existentes mantienen su ejecutor actual. Los agentes Claude y Codex existentes en objetivos calificados muestran una acción Ejecutor de actualización que los convierte en un click, manteniendo el modelo, la cuenta y las instrucciones y enumerando cualquier configuración que no se pudo convertir (#17122). Los agentes de Claude Runner comienzan con sus herramientas de tareas principales precargadas, aproximadamente un 20% más rápido en tareas simples (#16885), llevan el nivel de esfuerzo elegido a través de currículums (#15994) y comienzan en Linux ARM64 (#16372).
  • GitHub Copilot como arnés nativo: conecte el GitHub Copilot a través de aplicaciones/conexiones AI con un token GitHub guardado; la lista de modelos del agente se descubre a partir de la cuenta autenticada y Copilot (CLI 1.0.88) se ejecuta a través de Paperclip Runner con las mismas instrucciones, permisos y límites de finalización que los otros proveedores nativos, incluido el manifiesto de proveedor de Linux necesario para los entornos sandbox de Daytona (#15705, #15701, #15706).
  • Los repositorios de proyectos se convierten en fuentes de habilidades: los repositorios GitHub adjuntos a un nuevo proyecto se importan automáticamente como fuentes de habilidades: Paperclip importa sus habilidades, vuelve a verificar la rama configurada cada cinco minutos con la conexión GitHub de la persona que realizó la configuración e instala nuevas habilidades a menos que se excluyan; los proyectos existentes obtienen una acción "adoptar repositorios" en Habilidades → Fuentes, las actualizaciones automáticas se pueden pausar, las habilidades derivadas del proyecto heredan el acceso al proyecto y cada ejecución fija las versiones de habilidades con las que comenzó (#16066). Las importaciones mantienen la instantánea completa del repositorio en la confirmación escaneada para que las habilidades que dependen de scripts compartidos o habilidades entre hermanos funcionen después de la entrega, enumeren cada habilidad con su carpeta y omitan archivos no compatibles o de gran tamaño con una advertencia en lugar de fallar (#15731, #16308). Las fuentes obtienen un selector de ramas que carga las ramas del repositorio, marca las predeterminadas y valida la referencia antes de guardar (#16288); una fuente cuya rama rastreada desapareció muestra una acción de reparación de rama (#16256); cada fuente guardada aparece una vez con errores de actualización agrupados (#16310); y desconectar una fuente realmente la elimina, con la opción de mantener o eliminar las habilidades importadas (#16150).
  • Prevención de inyección de avisos respaldada por modelo — Configuración → Conexiones permite que un administrador de conexiones elija una conexión y un modelo OpenRouter compartidos (predeterminado openai/gpt-oss-safeguard-20b) para clasificar los resultados de la herramienta antes de que lleguen a un agente, reemplazando el veredicto de expresiones regulares y permitiendo código benigno que simplemente parece un ataque; los costos aparecen en Costos y una acción "Verificaciones del modelo de prueba" verifica dos muestras fijas. Apagado hasta que se configure. (#16976)
  • Observabilidad del agente en su propio backend — Configuración de la empresa → General → La observabilidad del agente envía registros y rastreos nativos de Codex y Claude Code a Braintrust (EE. UU.) o un punto final HTTP OTLP personalizado, con credenciales guardadas en secretos de la empresa y una acción de prueba; desactivado de forma predeterminada (#16874). Braintrust también se une al catálogo de aplicaciones con inicio de sesión en EE. UU. y UE o métodos de clave API (#17141).
  • Una conexión unificada de Google Workspace: una entrada de Google Workspace reemplaza las configuraciones separadas del servicio de Google: elija Gmail, Drive (Documentos, Hojas de cálculo, Presentaciones) y Calendario, cada uno opcionalmente de solo lectura, y el consentimiento y el acceso a las herramientas están vinculados a esa selección; Las conexiones existentes de Google siguen funcionando (#15545). Gmail obtiene una capacidad de archivo opcional (#16331).
  • Espacios de trabajo que se limpian después de sí mismos: una hora después de que finaliza un árbol de tareas, el reaper del espacio de trabajo del terminal elimina directorios regenerables como node_modules, dist y target que el propio .gitignore del repositorio ignora, manteniendo la rama y todos los cambios de fuente; el tiempo de reutilización del archivo cae de 7 días a 1 (#16304). La caducidad de caché de Git opcional elimina los árboles de trabajo terminados propiedad de Paperclip y los clones de bases privadas 24 horas después de que se completa el árbol de tareas y los restaura en la confirmación exacta cuando se vuelve a abrir una tarea (#16457, #16691); con los puntos de restauración activados, los árboles de trabajo cerrados que aún contienen confirmaciones no enviadas o archivos no confirmados se guardan primero en un punto de restauración cifrado y se restauran exactamente cuando se reanuda el trabajo, los problemas abiertos inactivos se estacionan de la misma manera después de siete días, las comprobaciones de múltiples repositorios anidados obtienen sus propios puntos de restauración y una tarea cuyo punto de restauración ha expirado se vuelve a abrir en un espacio de trabajo nuevo con una nota en lugar de fallar (#17248, #17271, #17257, #17269). Las versiones de habilidades materializadas no utilizadas se eliminan cada hora y se reconstruyen según demanda (#16433), y las copias de seguridad de conmutación por error del lado del host de las sesiones remotas de espacio aislado vencen una semana después de que se cierran sus problemas (#16866).
  • Tareas con su propio espacio de trabajo: una tarea que necesita archivos pero no tiene una fuente configurada ahora obtiene un directorio estable de empresa/tarea en lugar de heredar la carpeta de inicio del agente, los agentes pueden inspeccionar, seleccionar y solicitar repositorios para su espacio de trabajo a través de nuevas herramientas de ejecución, y las conexiones de chat pueden establecer los valores predeterminados del proyecto y del espacio de trabajo (#15749); una nueva tarea obtiene su propio clon cuando el proceso de pago predeterminado del proyecto contiene un árbol de trabajo que el agente no puede leer (#16095), con un reintento one-click en un proceso de pago limpio cuando la configuración está bloqueada de esa manera (#16909).
  • Ediciones masivas en la lista de agentes: seleccione filas y filtre por arnés para cambiar la conexión de IA, el modelo predeterminado o ambos para muchos agentes a la vez, con una vista previa y un reintento para actualizaciones fallidas; Se elimina el selector de estado de la lista y los agentes en pausa muestran una insignia en lugar de atenuarse (#17215). La descripción general del agente muestra quién creó un agente en empresas con más de una persona (#16055).
  • Grok Bot y Muse, ambos experimentales: Grok Bot le permite invitar a un Grok Bot existente como agente que recibe asignaciones a través de una rutina de webhook y trabaja a través de una conexión dedicada agente-OAuth MCP, con configuración guiada, códigos de emparejamiento, progreso, preguntas, documentos y archivos que regresan a la tarea, y controles de parada y recuperación; No se informa el gasto del proveedor (#16219, #16338, #16274, #16305). Muse empareja un Meta Muse personal a través de un receptor de solo activación y OAuth respaldado por Vault con un ticket de un solo uso de diez minutos, con controles de preparación, caducidad de credenciales y desconexión en el cuadro de diálogo de invitación (#16444, #16447, #16448, #16450).
  • Hable con un agente con Speko: una entrada de Speko en el catálogo de aplicaciones conecta una persona de Speko con un agente existente para que pueda hablar con él mediante la voz del navegador o por teléfono desde una tarea, con transcripciones, controles de llamadas, configuraciones de líneas entrantes, devoluciones de llamadas telefónicas y entradas de llamadas en Actividad; se muestra mientras la configuración experimental Conectores de chat está activada (#15728).
  • Bots de Slack, refinado: la configuración de conexión de Slack se simplifica en torno a "Abrir configuración de Slack" y una fila "Enviar mensaje de prueba", con "Usar tu propia aplicación" en Avanzado (#15679); los mensajes directos simples siempre comienzan o continúan funcionando incluso cuando Requerir mención está activado para los hilos del canal (#16151); y la reacción de los ojos aparece tan pronto como se acepta una mención, incluso en mensajes directos (#16491, #16494).
  • Un bot de revisión GitHub más resistente: el bot mantiene actualizado un comentario principal de relaciones públicas en cada envío, ignora los mensajes dirigidos a otros bots y marca el trabajo detenido con precisión (#16901); los comentarios de resumen están encabezados con el nombre para mostrar del bot, de modo que se puedan distinguir varios bots en un PR (#16212); reintentos de publicación a través de GitHub 503/429 con retroceso limitado y sobrevive a los reinicios sin comentarios ni comprobaciones duplicadas (#16284, #16883); Las herramientas de bot GitHub obtienen el máximo de 60 segundos de la puerta de enlace, por lo que submit_review ya no caduca (#16275); y la configuración muestra un aviso "Reconectar GitHub" con reconectar la aplicación guardada como primera opción (#16856).
  • Más aplicaciones en el catálogo — Daytona, con credenciales de clave API personales o compartidas y 274 acciones generadas para sandboxes, instantáneas, volúmenes, archivos, Git y comandos (#16483); Unikraft Cloud, con acciones generadas a partir de sus especificaciones OpenAPI y un metro predeterminado por conexión (#17139); y lo mismo (#16472). Una tarjeta de proveedor con varias conexiones las colapsa detrás de una fila "N conexiones" (#16097).
  • Comentario del agente en Auditoría: las quejas y sugerencias que los agentes presentan sobre sus herramientas ahora tienen un hogar: Auditoría obtiene una pestaña de Comentarios con agentes y filtros de tipo, búsqueda de texto, paginación y enlaces para compartir (#16884), legible por cada rol humano a través de un nuevo permiso commentary:view (#16903).

Correcciones

  • Espacios de trabajo y entornos limitados: un entorno limitado cuya ejecución falló antes de la exportación, cuyo arrendamiento se limpió con trabajo no exportado o cuya tarea se canceló antes de la reconstrucción se mantiene con sus archivos detrás de una decisión de reparación explícita en lugar de eliminarse mediante limpieza (#16397, #16583, #16700); una tarea cuyo sandbox fue destruido antes de la exportación ofrece una acción "Continuar desde fuentes guardadas" solo en el tablero (#16690); los archivos que se dejan en el entorno limitado de una ejecución detenida se recuperan automáticamente y los seguimientos guardados se entregan una vez (#16906); una exportación de espacio de trabajo en tiempo de apagado mantiene su propiedad a través del drenaje del finalizador (#16843); una copia de seguridad larga ya no pierde el bloqueo del tiempo de espera de transacción inactiva de PostgreSQL (#16340, #16956); la reanudación de una zona de pruebas reutilizable detenida respeta el tiempo de espera de inicio del entorno en lugar de los 60 segundos fijos (#16802); una única verificación de estado con tiempo de espera ya no reemplaza a un Runner remoto (#16835); se ejecuta en repositorios con miles de espacios de trabajo históricos que ya no permanecen "preparándose" durante horas (#16372, #16334, #16342, #16963); un pago compartido ya no permanece bloqueado por un lector cuya identidad ha desaparecido (#16928) y un espacio de trabajo bloqueado por el árbol de trabajo restringido de otra tarea recibe un aviso de configuración claro en lugar de un 403 opaco (#16545, #16895); una tarea secundaria que hereda un espacio de trabajo compartido ocupado espera en lugar de fallar con un error de secretos engañoso (#16371); y la creación de una tarea con el selector de aislamiento oculto ya no falla en la configuración (#16220).
  • Ejecuciones, recuperación y reintentos: las tareas retenidas detrás de un espacio de trabajo retenido o de una ejecución fallida obtienen un reintento confiable a nivel de tarea que preserva los archivos, establece los resultados aceptados o inicia un espacio de trabajo independiente (#16965, #17053, #16894, #16104); Detener evita la continuación automática hasta que reanude (#17105, #14180); un reinicio del servidor ya no bloquea las ejecuciones nativas en retenciones permanentes, repite las finalizaciones guardadas ni sobrescribe las paradas del operador establecidas mientras tanto (#16349, #16962, #16403, #15824); las ejecuciones heredadas canceladas o perdidas antes del envío se reintentan en lugar de resolverse como fallidas (#16355, #16358), una finalización lenta ya no falla en un controlador activo (#16622) y las consultas lentas no relacionadas ya no cuestan las ejecuciones heredadas en su arrendamiento (#17032); un comentario normal sobre una tarea en progreso ya no cancela su reintento de ejecución (#16855), y detener una ejecución en cola antes de que comience mantiene su seguimiento guardado en lugar de ejecutarla de todos modos (#16357); los mensajes para agentes en pausa o para un agente que no sea el propietario de la tarea se entregan una vez en lugar de fallar o diferirse para siempre (#16679, #16673); un agente atascado marcado como "en ejecución" se repara después de un período de gracia de cinco minutos (#16791); una ejecución de Claude (ACP) con una llamada de herramienta detenida falla después de 30 minutos en lugar de ejecutarse hasta el tiempo de espera de cuatro horas, y las llamadas de MCP obtienen un tiempo de espera de 15 minutos (#16671, #16360); un agotamiento de giros máximos ya no se clasifica erróneamente como modelo faltante (#13885); y se vuelve a intentar una respuesta del Codex "modelo a capacidad" como transitoria (#16407).
  • Interfaz de usuario de chat y tareas: descartar una solicitud por encima del compositor borra la insignia, sobrevive a la recarga y ya no bloquea el reintento (#17218); un mensaje a un agente Runner ya no cambia brevemente su avatar por una fila genérica "En funcionamiento" (#16989); un seguimiento consumido sale de la cola pendiente (#16317); la respuesta final de una tarea del árbol de trabajo ya no se reemplaza por el aviso de "espacio de trabajo listo" (#16400); un archivo adjunto antes del primer mensaje de Chat del Agente sobrevive a la creación de la tarea (#16896); Los brindis de tareas en una empresa multiusuario aparecen solo para las personas involucradas en la tarea (#16153); cargar una lista de tareas ya no agrega tareas terminadas no relacionadas a su bandeja de entrada (#16063); responde de forma predeterminada al último agente que le asignó la tarea (#15594); las pestañas del panel lateral mantienen un ancho constante (#17068, #14949); Los editores de Markdown ya no muestran los cambios no guardados al cargar (#13915); y una tarea de Slack que da lugar a una continuación programada devuelve su resultado al hilo original (#17045).
  • Costos y presupuestos: un presupuesto en su umbral de advertencia se muestra como una advertencia en lugar de un banner falso "PARADA HARD DEL AGENTE" (#16201) y las comprobaciones de presupuesto ya no escalan con la cantidad de agentes inactivos no relacionados en la empresa (#17046).
  • Conexiones y MCP: una llamada MCP remota fallida ya no hace que todas las herramientas hermanas en esa conexión no estén disponibles (#16890); un proveedor 403 en una operación de chat ya no desactiva toda la conexión de Slack, GitHub o Discord (#16847, #16138); GitHub y las herramientas del canal Slack permanecen disponibles en ejecuciones posteriores de la misma tarea (#16806); varias respuestas del hilo de revisión GitHub obtienen cada una su propia ejecución de seguimiento (#17054) y se enumeran descriptores de herramientas idénticos una vez (#16281); una actualización de catálogo de MCP de gran tamaño ya no enumera una herramienta dos veces ni se bloquea con una devolución de llamada de OAuth (#16602); los resultados de la herramienta asignada de aproximadamente 500 KB devuelven una referencia limitada y una herramienta read_tool_result en lugar de colgarse (#16980); los comandos de shell heredados del Codex pueden ver secretos de servicio asignados explícitamente (#17216); el corredor nativo call_api sigue los propios permisos de la ruta sin una lista de denegación adicional (#16040); y los agentes de espacio aislado pueden leer el historial de ejecución, los archivos adjuntos, los archivos de habilidades y los registros de recuperación y enviar el token de puente como X-API-Key (#16575, #16892, #12785).
  • Adaptadores y CLI: una ejecución ilimitada de Claude ya no falla en su sonda CLI después de un segundo (#15329); Las ejecuciones remotas simultáneas de Claude de un agente ya no interrumpen la preparación de habilidades de cada uno (#17061); se inicia una tarea de Claude aislada con herramientas MCP asignadas (#17149); un sandbox cuyo Claude CLI preinstalado sea anterior a las necesidades del modelo seleccionado obtiene la versión requerida instalada de forma privada durante la instalación en lugar de fallar la verificación de la versión (#17259); la instalación del servidor Claude (ACP) ya no falla porque faltaba el puente ACP en el paquete del servidor (#15912); un turno de Runner OpenCode sobrevive a eventos SSE de gran tamaño (#16401) y utiliza las credenciales GitHub administradas de la ejecución en comandos de shell (#16488); Hermes vuelve a llamar a la URL API configurada del adaptador (#9425); Los registros de ejecución de pi_local son aproximadamente 150 veces más pequeños (#10249); paperclipai install y update funcionan con npm 12 y el nodo 26 (#14000); paperclipai service install ya no escribe un servicio que se bloquea en un shim administrado que falta (#13985); y el inicio de sesión del navegador CLI respeta los encabezados Retry-After con límite de velocidad (#16482).
  • Servidor y Docker: el inicio ya no falla en bases de datos heredadas SQL_ASCII (#16958) ni falla en un publicBaseUrl sin esquema (#13727); un servidor detrás de un proxy inverso con búsquedas PTR lentas ya no deja de responder durante minutos después de la actualización (#16333, #16335); una conexión agrupada interrumpida ya no falla en las comprobaciones de permisos, la preparación del espacio de trabajo o el reaper (#16857, #16859); Docker arranca con muchos archivos en el volumen de datos o un USER_UID/USER_GID no predeterminado ya no recorre todo el volumen (#15992, #16475); ambos archivos de redacción enviados reenvían PAPERCLIP_TOOL_ACTION_SIGNING_SECRET (#15202); una parada que dura más que la sincronización devuelve un 409 reintentable en lugar de un 500 (#16032); las ediciones simultáneas de títulos de tareas ya no son 500 (#13898); un ID de comentario con formato incorrecto ya no bloquea las activaciones en cola de una tarea (#13912); los despertares del perro guardián entregan las instrucciones del operador (#13771); el límite de tareas secundarias solo cuenta las secundarias abiertas (#11542); un agente sencillo puede volver a comentar las tareas (#12621); una transferencia humana de una ejecución heredada ya no se cancela mediante una restauración lenta (#16082); y las exportaciones de comentarios mantienen los identificadores públicos legibles y al mismo tiempo enmascaran tokens reales (#16168).

Mejoras

  • Los casos experimentales mantienen una tarea principal en todas las transferencias de agentes con un libro de contabilidad de transferencia duradero, herramientas nativas create_case, read_case, update_case y handoff_case, páginas de casos de solo lectura e indicaciones de flujo de trabajo con nombre reutilizables que un caso adopta al inicio o en la transferencia (#16959, #17114).
  • Una verificación fallida del ciclo de vida del agente nombra el paso fallido y una acción correctiva (#16418), y la incorporación crea el registro del agente tan pronto como usted envía su nombre, por lo que la configuración y los reintentos mantienen una identidad (#17005).
  • Los complementos pueden suscribirse a eventos comprometidos del ciclo de vida del agente y del proyecto con reproducción en lugar de sondeo (#16203); recibir cambios de configuración, instrucción, habilidad, conexión, herramienta y concesión del agente a través de enlaces de tiempo de ejecución duraderos (#16499, #16501, #16603, #16604, #16605); almacenar secretos de instancia propiedad del agente y del proyecto en el almacén de secretos cifrados (#16191, #17034); propios espacios de trabajo de tareas y almacenamiento de proyectos, actuar como proveedor de espacio de trabajo predeterminado y ejecutar tareas nativas de Runner en entornos propiedad de complementos verificados por la prueba de entorno del agente (#17001, #17247, #16978, #17029, #17252, #15406); y declarar rutas WebSocket autenticadas y vistas detalladas de agentes (#17111).
  • Más trabajo en segundo plano espera escrituras confirmadas y fechas límite conocidas en lugar de sondear la base de datos: mantenimiento de Telegram (#16094), limpieza del espacio de trabajo del terminal (#16282), limpieza de inicio de sesión (#17106), recuperación del control de ejecución (#17094), suscripciones a eventos de MCP (#17036) y sincronización de fuente de habilidades (#17008); Las rutinas y los monitores de tareas se activan en la fecha límite guardada en lugar de esperar el siguiente análisis (#16514).
  • Inicios más rápidos en todas partes: el servidor informa que está listo antes después de un reinicio porque el mantenimiento se ejecuta después de la preparación y se omiten las finalizaciones establecidas (#16329, #16485, #16328); la imagen Docker arranca desde un paquete de tiempo de ejecución precompilado, lo que reduce el tiempo de carga del código de hasta 24 segundos a menos de 4 (#16672); las páginas de tareas se cargan lentamente, difieren la representación oculta y actualizan la barra lateral de tareas recientes mediante una solicitud limitada (#16849, #16878, #16851, #16862); y los lanzamientos de agentes se superponen a GitHub, habilidades, herramientas y preparación de sandbox, reutilizan un caché de objetos Git por empresa y archivos de imagen de sandbox verificados, y realizan muchas menos llamadas a bases de datos y Daytona (#16620, #16608, #16585, #16487, #16687, #16493, #16683, #16536, #16521, #16527, #16561, #16468, #16480, #16552, #16484, #16473, #16425, #16424, #16461, #16498, #16576, #16569, #16414, #17026).
  • Tareas, listas de proyectos, descubrimiento de bandeja de entrada y Bloqueado ocultan las tareas creadas por el agente y el sistema de forma predeterminada detrás de un filtro "mostrar tareas creadas por el agente" guardado por empresa (#16157), y la Bandeja de entrada "Mina" excluye el canal, la rutina y las tareas creadas por el agente a menos que haya comentado, haya sido asignado o tenga una solicitud abierta (#16356); los avisos de falla muestran solo el error más reciente con su acción de reintento (#16982); y una tarjeta de solicitud de conexión vencida dice lo que aún no está conectado (#14067).

paperclip v2026.1106.0

Paperclip v2026.1106.0

Released: 2026-11-06

Paperclip v2026.1106.0 carries 515 commits, promoted from 2026.1023.0-beta.0. The headline is that the Paperclip Runner is now the default for new agents: new Claude, Codex, OpenCode, and Pi agents start on the native Runner on qualified macOS and Linux hosts, existing agents get a one-click "Upgrade runner" action, and GitHub Copilot joins as a native harness. Around that: project repositories that automatically become skill sources, model-backed prompt injection prevention, agent observability to Braintrust or any OTLP endpoint, a unified Google Workspace connection, bulk edits on the Agents roster, workspaces that compact and expire themselves with encrypted restore points, and Grok Bot and Muse as experimental Runner providers. Underneath, server restarts report ready sooner, the Docker image boots from a precompiled bundle, task pages load faster, and more background services stop polling the database.

Breaking Changes

  • The Pipelines experiment is removed. Pipeline boards, stage settings, case automation, review queues, the pipelines CLI commands, the pipelines:write permission, the enablePipelines setting, and the linkedCases field on task detail are gone; Cases and Routines remain. Existing pipeline tables and records are preserved untouched and a stored enablePipelines value is ignored. (#16834)
  • Run failures no longer reach Sentry by default. A backend DSN alone no longer reports agent run failures. Set PAPERCLIP_SENTRY_RUN_FAILURES=unexpected to keep the previous filtered policy or all to report every failed or timed-out run; the default is off. (#16300)
  • The run history list is bounded. GET /api/companies/{companyId}/heartbeat-runs returns 200 rows by default and at most 1,000; clients that relied on an unbounded array must pass an explicit limit. (#16286)
  • paperclipai agent instructions-file:delete requires --yes like the other destructive CLI commands; scripts that call it must add the flag. (#11504)

Highlights

  • The Paperclip Runner is the default — New Claude agents on Apple Silicon, Intel macOS, and Linux x64 (#15993, #15997), new Codex agents on Apple Silicon, Intel macOS, Linux x64, and Linux ARM64 (#15683), and new OpenCode and Pi agents on macOS and Linux x64 (#17120, #17142) now start on the native Runner instead of the legacy adapter, across onboarding, the API and CLI, hires, built-ins, plugins, and imports; Linux needs GNU libc 2.39 or later, a "Legacy runner" override lives under Advanced, and existing agents keep their current runner. Existing Claude and Codex agents on qualified targets show an Upgrade runner action that converts them in one click, keeping model, account, and instructions and listing any settings that could not be converted (#17122). Claude Runner agents start with their core task tools preloaded, measured about 20% faster on simple tasks (#16885), carry the chosen effort level through resumes (#15994), and start on Linux ARM64 (#16372).
  • GitHub Copilot as a native harness — Connect GitHub Copilot through Apps / AI Connections with a saved GitHub token; the agent's model list is discovered from the authenticated account, and Copilot (CLI 1.0.88) runs through the Paperclip Runner with the same instruction, permission, and completion boundaries as the other native providers, including the Linux provider manifest needed for Daytona sandboxes (#15705, #15701, #15706).
  • Project repositories become skill sources — GitHub repositories attached to a new project are imported as skill sources automatically: Paperclip imports their skills, re-checks the configured branch every five minutes with the setup person's GitHub connection, and installs new skills unless excluded; existing projects get an "adopt repositories" action in Skills → Sources, automatic updates can be paused, project-derived skills inherit project access, and each run pins the skill versions it started with (#16066). Imports keep the whole repository snapshot at the scanned commit so skills that depend on shared scripts or sibling skills work after delivery, list every skill with its folder, and skip unsupported or oversized files with a warning instead of failing (#15731, #16308). Sources gain a branch picker that loads the repository's branches, marks the default, and validates the ref before saving (#16288); a source whose tracked branch disappeared shows a branch repair action (#16256); each saved source is listed once with grouped refresh errors (#16310); and disconnecting a source really removes it, with a keep-or-delete choice for the imported skills (#16150).
  • Model-backed prompt injection prevention — Settings → Connections lets a connection manager pick a shared OpenRouter connection and model (default openai/gpt-oss-safeguard-20b) to classify tool results before they reach an agent, replacing the regex verdict and allowing benign code that merely looks like an attack; costs appear in Costs, and a "Test model checks" action verifies two fixed samples. Off until configured. (#16976)
  • Agent observability to your own backend — Company Settings → General → Agent observability sends native Codex and Claude Code logs and traces to Braintrust (US) or a custom OTLP HTTP endpoint, with credentials held in company secrets and a test action; off by default (#16874). Braintrust also joins the Apps catalog with US and EU sign-in or API-key methods (#17141).
  • A unified Google Workspace connection — One Google Workspace entry replaces the separate Google service setups: pick Gmail, Drive (Docs, Sheets, Slides), and Calendar, each optionally read-only, and consent and tool access are bound to that selection; existing Google connections keep working (#15545). Gmail gains an opt-in archive capability (#16331).
  • Workspaces that clean up after themselves — One hour after a task tree finishes, the terminal-workspace reaper removes regenerable directories such as node_modules, dist, and target that the repository's own .gitignore ignores, keeping the branch and all source changes; the archive cooldown drops from 7 days to 1 (#16304). Opt-in Git cache expiration removes finished Paperclip-owned worktrees and private base clones 24 hours after the task tree is done and restores them at the exact commit when a task reopens (#16457, #16691); with restore points on, closed worktrees that still hold unpushed commits or uncommitted files are saved to an encrypted restore point first and restored exactly when work resumes, idle open issues are parked the same way after seven days, nested multi-repository checkouts get their own restore points, and a task whose restore point has expired reopens on a fresh workspace with a note instead of failing (#17248, #17271, #17257, #17269). Unused materialized skill versions are removed hourly and rebuilt on demand (#16433), and host-side failover backups of remote-sandbox sessions expire a week after their issues close (#16866).
  • Tasks with their own workspace — A task that needs files but has no configured source now gets a stable company/task directory instead of inheriting the agent's home folder, agents can inspect, select, and request repositories for their workspace through new runner tools, and chat connections can set project and workspace defaults (#15749); a fresh task gets its own clone when the project's default checkout contains a worktree the agent cannot read (#16095), with a one-click Retry on a clean checkout when setup is blocked that way (#16909).
  • Bulk edits on the Agents roster — Select rows and filter by harness to change the AI connection, the default model, or both for many agents at once, with a preview and retry for failed updates; the roster's status selector is removed and paused agents show a badge instead of dimming (#17215). The agent Overview shows who created an agent in companies with more than one person (#16055).
  • Grok Bot and Muse, both experimental — Grok Bot lets you invite an existing Grok Bot as an agent that receives assignments through a webhook routine and works through a dedicated agent-OAuth MCP connection, with guided setup, pairing codes, progress, questions, documents, and files flowing back into the task, and Stop and recovery controls; provider spending is not reported (#16219, #16338, #16274, #16305). Muse pairs a personal Meta Muse through a wake-only receiver and Vault-backed OAuth with a ten-minute single-use ticket, with readiness, credential expiry, and disconnect controls in the invite dialog (#16444, #16447, #16448, #16450).
  • Talk to an agent with Speko — A Speko entry in the Apps catalog connects a Speko persona to an existing agent so you can talk to it by browser voice or phone from a task, with transcripts, call controls, inbound-line settings, phone callbacks, and call entries in Activity; shown while the Chat connectors experimental setting is on (#15728).
  • Slack bots, refined — Slack connection Settings are simplified around "Open Slack configuration" and a "Send test message" row, with "Use your own app" under Advanced (#15679); plain direct messages always start or continue work even when Require at-mention is on for channel threads (#16151); and the eyes reaction appears as soon as a mention is accepted, including in direct messages (#16491, #16494).
  • A sturdier GitHub review bot — The bot keeps one main PR comment updated across pushes, ignores messages addressed to other bots, and marks stopped work accurately (#16901); summary comments are headed with the bot's display name so several bots on one PR are distinguishable (#16212); publication retries through GitHub 503/429 with bounded backoff and survives restarts without duplicate comments or checks (#16284, #16883); GitHub bot tools get the gateway's 60-second maximum so submit_review no longer times out (#16275); and settings show a "Reconnect GitHub" notice with reconnect-the-saved-App as the first option (#16856).
  • More apps in the catalog — Daytona, with personal or shared API-key credentials and 274 generated actions for sandboxes, snapshots, volumes, files, Git, and commands (#16483); Unikraft Cloud, with actions generated from its OpenAPI specs and a per-connection default metro (#17139); and Ditto (#16472). A provider card with several connections collapses them behind an "N connections" row (#16097).
  • Agent commentary in Audit — The complaints and suggestions agents file about their tooling now have a home: Audit gains a Commentary tab with agent and type filters, text search, paging, and shareable links (#16884), readable by every human role through a new commentary:view permission (#16903).

Fixes

  • Runs, recovery, and Retry — Tasks held behind a retained-workspace or failed-run hold get one reliable task-level Retry that preserves files, settles accepted results, or starts an independent workspace (#16965, #17053, #16894, #16104); Stop prevents automatic continuation until you resume (#17105, #14180); a server restart no longer strands native runs on permanent holds, repeats saved completions, or overwrites operator stops set in the meantime (#16349, #16962, #16403, #15824); legacy runs killed or lease-lost before dispatch are retried instead of settled as failed (#16355, #16358), a slow completion no longer fails a live controller (#16622), and slow unrelated queries no longer cost legacy runs their lease (#17032); a normal comment on an in-progress task no longer cancels its running retry (#16855), and stopping a queued run before it starts keeps its saved follow-up instead of running it anyway (#16357); messages for paused agents or for an agent other than the task owner are delivered once instead of being failed or deferred forever (#16679, #16673); an agent stuck marked "running" is repaired after a five-minute grace period (#16791); a Claude (ACP) run with a stalled tool call fails after 30 minutes instead of running to the four-hour timeout, and MCP calls get a 15-minute timeout (#16671, #16360); a max-turns exhaustion is no longer misclassified as a missing model (#13885); and a Codex "model at capacity" reply is retried as transient (#16407).
  • Chat and task UI — Dismissing a request above the composer clears the badge, survives reload, and no longer blocks Retry (#17218); a message to a Runner agent no longer briefly swaps its avatar for a generic "Working" row (#16989); a consumed follow-up leaves the pending queue (#16317); the final reply of a worktree task is no longer replaced by the "workspace ready" notice (#16400); a file attached before the first Agent Chat message survives task creation (#16896); task toasts in a multi-user company appear only for people involved in the task (#16153); loading a task list no longer adds unrelated finished tasks to your inbox (#16063); replies default to the latest agent that assigned you the task (#15594); side panel tabs keep a steady width (#17068, #14949); Markdown editors no longer show unsaved changes on load (#13915); and a Slack task that yields to a scheduled continuation returns its result to the original thread (#17045).
  • Costs and budgets — A budget at its warning threshold renders as a warning instead of a false "AGENT HARD STOP" banner (#16201), and budget checks no longer scale with the number of unrelated idle agents in the company (#17046).
  • Connections and MCP — One failed remote MCP call no longer makes every sibling tool on that connection unavailable (#16890); a provider 403 on one chat operation no longer disables the whole Slack, GitHub, or Discord connection (#16847, #16138); GitHub and Slack channel tools stay available on later runs of the same task (#16806); several GitHub review-thread replies each get their own follow-up run (#17054) and identical tool descriptors are listed once (#16281); a large MCP catalog refresh no longer lists a tool twice or deadlocks with an OAuth callback (#16602); assigned tool results over about 500 KB return a bounded reference and a read_tool_result tool instead of hanging (#16980); legacy Codex shell commands can see explicitly assigned service secrets (#17216); native-runner call_api follows the route's own permissions without an extra denylist (#16040); and sandboxed agents can read run history, attachments, skill files, and recovery records and send the bridge token as X-API-Key (#16575, #16892, #12785).
  • Adapters and CLI — An unlimited Claude run no longer fails its CLI probe after one second (#15329); concurrent remote Claude runs of one agent no longer break each other's skill staging (#17061); an isolated Claude task with assigned MCP tools starts (#17149); a sandbox whose preinstalled Claude CLI is older than the selected model needs gets the required version installed privately during setup instead of failing the version check (#17259); a Claude (ACP) server install no longer fails because the ACP bridge was missing from the server package (#15912); a Runner OpenCode turn survives oversized SSE events (#16401) and uses the run's managed GitHub credentials in shell commands (#16488); Hermes calls back at the adapter's configured API URL (#9425); pi_local run logs are about 150× smaller (#10249); paperclipai install and update work with npm 12 and Node 26 (#14000); paperclipai service install no longer writes a service that crash-loops on a missing managed shim (#13985); and the CLI browser login honors rate-limit Retry-After headers (#16482).

  • Experimental Cases keep one primary task across agent handoffs with a durable handoff ledger, native create_case, read_case, update_case, and handoff_case tools, read-only case pages, and reusable named workflow prompts a case adopts at kickoff or on handoff (#16959, #17114).
  • A failed agent-lifecycle verification names the failed step and a corrective action (#16418), and onboarding creates the agent record as soon as you submit its name, so setup and retries keep one identity (#17005).
  • Plugins can subscribe to committed project and agent lifecycle events with replay instead of polling (#16203); receive agent configuration, instruction, skill, connection, tool, and grant changes through durable runtime hooks (#16499, #16501, #16603, #16604, #16605); store agent- and project-owned instance secrets in the encrypted secret store (#16191, #17034); own project storage and task workspaces, act as the default workspace provider, and run native Runner tasks in plugin-owned environments verified by the agent environment test (#17001, #17247, #16978, #17029, #17252, #15406); and declare authenticated WebSocket routes and agent detail views (#17111).
  • More background work waits for committed writes and known deadlines instead of polling the database: Telegram maintenance (#16094), terminal workspace cleanup (#16282), login cleanup (#17106), execution-control recovery (#17094), MCP event subscriptions (#17036), and skill-source sync (#17008); routines and task monitors fire at their saved deadline instead of waiting for the next scan (#16514).
  • Faster starts everywhere: the server reports ready sooner after a restart because housekeeping runs after readiness and settled finalizations are skipped (#16329, #16485, #16328); the Docker image boots from a precompiled runtime bundle, cutting code-load time from up to 24 seconds to under 4 (#16672); task pages load lazily, defer hidden rendering, and refresh the recent-tasks sidebar through one bounded request (#16849, #16878, #16851, #16862); and agent launches overlap GitHub, skill, tool, and sandbox preparation, reuse a per-company Git object cache and verified sandbox image files, and make far fewer database and Daytona calls (#16620, #16608, #16585, #16487, #16687, #16493, #16683, #16536, #16521, #16527, #16561, #16468, #16480, #16552, #16484, #16473, #16425, #16424, #16461, #16498, #16576, #16569, #16414, #17026).
  • Tasks, project lists, inbox discovery, and Blocked hide agent- and system-created tasks by default behind a "show agent-created tasks" filter saved per company (#16157), and Inbox "Mine" excludes channel, routine, and agent-created tasks unless you commented, were assigned, or have an open request (#16356); failure notices show only the latest error with its retry action (#16982); and an expired connection request card says what is still not connected (#14067).
  • An experimental Artifacts V1 presentation shows paper stacks and tiles on the Artifacts page, compact rows in the panel, and grouped rows in the thread (#17228); you can upload files directly in the Artifacts panel by icon or drag-and-drop without sending a message (#15964); the offline recovery page matches the app (#16904); the "Run with provider trace" header button is replaced by the agent's Debugging configuration (#17211); and an app's Access tab shows linked users' photos (#15577).
  • Adding a repository skill to an agent no longer stalls on a full library read (#16899), and invalid arguments to assigned tools, call_api, and set_task_monitor return schema locations and repair guidance (#16905, #16889, #16868, #16961).
  • paperclip_runner agents can set homeMode: "preconfigured" to run native Codex or ACPX Claude with the execution account's existing login, skills, and MCP configuration (#16486); the Runner reports refreshed OAuth credentials without token values crossing the protocol (#16463) and can register verified session-local stdio MCP servers on Unix (#16526); the task PATCH API accepts expectedStatusVersion for backlog-to-todo promotion (#16893); and an anonymous GET /api/liveness reports process liveness without touching the database (#16101).
  • Failure reports record why an OpenCode turn fails when its server stops (#16863); Sentry reports for run failures link to the task and run pages, skip classified provider quota limits, and report a native retry only when the retry ends (#16803, #16029, #16865); due task monitors held by recovery record why in the task activity (#16891); and, when an OTLP endpoint is configured, traces gain spans for controller preparation, execution configuration, workspace and connector preparation, and finalization (#16178, #16236, #16419, #16428, #16454, #16515).

Upgrade Guide

  • Migrations 0334–0374 run on upgrade. Additive schema: 0334, 0341, and 0342 repository skill snapshots, project_skill_sources, and import budgets; 0335 chat_slack_manager_grants and its link from Slack registrations; 0336–0338 execution workspace repository tables; 0339 and 0370 agent-, plugin-, and project-owned company_secrets; 0344 and 0346 Grok Bot tables; 0349–0353 Muse tables; 0357 company_observability; 0362 prompt injection prevention tables; 0363–0368 and 0371 case handoff and workflow tables; 0372–0374 execution_workspace_restore_points; 0373 interaction dismissal columns. Constraint rewrites: 0340 allows delete as a lifecycle-event action; 0361 allows github as an AI default provider. Triggers: 0347, 0348, and 0354–0356 install runtime-invalidation triggers on agents, skills, connections, grants, memberships, and secrets; 0358 bumps issues.status_version on assignee change; 0372 expires restore points when issues close. Row updates: 0343 backfills agents.created_by_user_id from the activity log; 0347 seeds one agent_runtime event per active agent; 0359 grants commentary:view to every active human membership; 0363 backfills case_access_sources. Indexes: 0360 adds a partial index for retained-workspace recovery; 0345 and 0369 are built CONCURRENTLY outside a transaction and are safe to rerun if interrupted. Expect 0343, 0345, and 0369 to take longer on instances with large run histories, and the check-constraint rewrites in 0339, 0362, and 0370 to scan company_secrets, budget_reservations, and cost_events.
  • New agents default to the Paperclip Runner (#15993, #15997, #15683, #17120, #17142): on qualified hosts (Apple Silicon, Intel macOS, Linux x64 with glibc 2.39+, and Linux ARM64 for Codex), new Claude, Codex, OpenCode, and Pi agents are created on the native Runner regardless of the enableNativeRunner setting. Existing agents are unchanged; choose "Legacy runner" under Advanced to opt a new agent out, or use Upgrade runner on an existing agent's configuration to convert it (#17122).
  • New environment variables, none required. Workspace cleanup: PAPERCLIP_WORKSPACE_COMPACTION_ENABLED (on unless exactly false) and PAPERCLIP_WORKSPACE_COMPACTION_DELAY_HOURS (default 1) control removal of regenerable files from finished task worktrees, and PAPERCLIP_WORKSPACE_REAPER_COOLDOWN_DAYS now defaults to 1 instead of 7 (#16304); PAPERCLIP_GIT_CACHE_EXPIRATION_ENABLED and PAPERCLIP_GIT_BASE_EXPIRATION_ENABLED (default false) with PAPERCLIP_GIT_CACHE_EXPIRATION_DRY_RUN (default true) opt into expiring finished worktrees and base clones (#16457); PAPERCLIP_GIT_RESTORE_POINTS_ENABLED (default false) with PAPERCLIP_GIT_RESTORE_POINT_TERMINAL_DELAY_DAYS (default 3), PAPERCLIP_GIT_RESTORE_POINT_IDLE_DAYS (default 7, 0 disables), and PAPERCLIP_GIT_RESTORE_POINT_RETENTION_DAYS (default 90) govern encrypted restore points (#17248, #17271, #17241); PAPERCLIP_SKILL_VERSION_RETENTION_ENABLED (default true) with _DRY_RUN (false), _KEEP (0), and _GRACE_MINUTES (60) prunes unused materialized skill versions (#16433); PAPERCLIP_NATIVE_HARNESS_BACKUP_EXPIRATION_ENABLED (default true) with _DAYS (7) and _DRY_RUN (false) expires remote-session failover backups, so reopening an issue closed longer than that window starts a fresh provider session (#16866). Reporting: PAPERCLIP_SENTRY_RUN_FAILURES (off, unexpected, or all; default off) (#16300). Claude agents also honor an existing ANTHROPIC_BASE_URL and ANTHROPIC_CUSTOM_HEADERS (#16850).
  • New experimental settings, all off by default: Grok Bot (enableGrokBot), which requires Assistant connections (MCP), the Paperclip Runner, authenticated sign-in, and an HTTPS PAPERCLIP_PUBLIC_URL (#16219); Muse — Personal agent (enableMuse), which requires the Runner and public HTTPS (#16450); Artifacts V1 (enableArtifactsV1) (#17228). Speko voice appears under the existing Chat connectors setting (#15728) and workflows under Cases (#17114). enablePipelines is removed (#16834). Settings → Connections is now always visible and no longer depends on Experimental fast responses (#16976).
  • commentary:view for every human role (#16903): migration 0359 and startup seeding grant the new permission to every active human membership, including viewers, so anyone in the company can open Audit → Commentary. Deleting that grant from a member is temporary: startup seeding re-adds every role-default grant for each active human member on the next server start, and this release has no durable way to withhold it. Source-task privacy still filters what each person sees in commentary.
  • Sentry operators (#16300): set PAPERCLIP_SENTRY_RUN_FAILURES=unexpected to keep receiving run-failure events; they are off by default even with SENTRY_DSN_BACKEND configured.
  • API clients: the run history list is capped at 1,000 rows (default 200) (#16286); the linkedCases field and all Pipeline routes are gone (#16834); a PATCH that replaces executionPolicy and sets done during a live review cycle returns 422 unexecuted_review_stage (#13178); and anything parsing GitHub review summary headings must accept bot names (#16212).
  • Custom Docker images (#16672): the shipped image now starts with node server/dist-runtime/index.mjs; images that invoked server/dist/index.js through tsx should switch to the runtime bundle.
  • Default views change: agent- and system-created tasks are hidden from task lists until you enable "show agent-created tasks" (#16157), and Inbox "Mine" no longer includes automation you did not take part in (#16356).
  • Google Workspace (#15545): new Google Workspace requests depend on the Paperclip-hosted OAuth broker update, and older brokers reject them; existing per-service Google connections keep working.
  • Harness pins are unchanged from v2026.1023.0: Codex 0.160.0, Claude Agent SDK 0.3.286 (Claude Code 2.1.286), and OpenCode 1.18.34. GitHub Copilot ships at CLI 1.0.88 (#15701).
  • No other configuration or API changes require action.
