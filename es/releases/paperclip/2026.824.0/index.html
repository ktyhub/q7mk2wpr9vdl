Papelclip v2026.824.0

Publicado: 2026-08-24

Paperclip v2026.824.0 es un seguimiento rápido de 2026.817.0 y el primer establo en recorrer el canario completo → todas las noches → beta → estable camino feliz de principio a fin, sumergiéndose como 2026.818.0-beta.1 antes de la promoción. Incluye 172 confirmaciones: las tareas de estilo chat pasan del experimento a la experiencia predeterminada, las vistas previas en tiempo de ejecución administradas se vuelven accesibles a través de Tailscale HTTPS, la ejecución de la zona de pruebas obtiene un contrato de capacidad de proveedor verificado, puede iniciar sesión en Claude y Codex desde dentro del producto, las importaciones de grandes empresas sobreviven a las conexiones caídas y un gran lote de correcciones comunitarias de larga data aterrizan.

Cambios importantes

Ninguno de estos requiere acción para una instalación típica, pero lea detenidamente antes de actualizar:

  • Las tareas de estilo de chat son las predeterminadas. La opción del experimento "Tareas de estilo de chat" ya no está; la página de detalles de la tarea ahora es la vista de conversación para todos. Una nueva preferencia de "Interfaz de tareas clásica" (enableClassicTaskInterface, que reemplaza a enableTaskChatRedesign en la configuración de la instancia) restaura la página previa al chat (encabezado a nivel de página, hilo de comentarios simple, barra lateral de Propiedades fija), pero las funciones de solo chat no están disponibles allí. (#11101)
  • La transmisión de salida de sesión de Sandbox ahora se basa en la capacidad y tres indicadores de operador desaparecieron. La configuración streamAgentSessionOutput del servidor y las claves useSessions y useLogStream del complemento Daytona ya no existen; la instantánea de la capacidad del proveedor verificado es la única decisión de transmisión, con un respaldo de encuesta automático. Las configuraciones guardadas que aún contienen las claves eliminadas se cargan bien: las claves son simplemente inertes. (#11463, #11557)
  • Los tiempos de ejecución de desarrollo administrados ahora utilizan de manera predeterminada las vistas previas HTTPS de Tailscale. Cuando el agente de host está disponible, los tiempos de ejecución del árbol de trabajo administrados por Paperclip elegibles se exponen como tailscale_https en lugar de HTTP de bucle invertido. Configure PAPERCLIP_MANAGED_RUNTIME_HTTPS=off para mantener el comportamiento anterior o force para que no se cierre cuando falte el intermediario. Las rutas de control de tiempo de ejecución administradas también obtuvieron dos nuevas respuestas 409 (workspace_runtime_control_in_progress, workspace_runtime_lease_conflict): las personas que llaman y asumen que un control siempre se inicia deben manejar un conflicto. (#11524, #11525)
  • La política de resolución de interacciones tiene como valor predeterminado anyone para nuevas interacciones. Cada tipo de interacción ahora pasa por un evaluador de políticas de resolución con procedencia registrada, en lugar de reglas por ruta que bloqueaban agentes válidos. La migración 0218 deliberadamente no amplía nada que ya esté pendiente: las filas existentes mantienen sus antiguas restricciones con nuevos nombres (board_or_agents → not_creator, board_only → human_only). (#11376)
  • Las superficies de entrenamiento de decisiones se eliminan del escritorio de Decisiones: la ruta de la biblioteca de entrenamiento, las acciones de fila y el cajón. El contrato de instantáneas de backend no se modifica y no se ejecuta ninguna migración de datos. (#11225)

Destacados

  • Tareas estilo chat, ahora la experiencia predeterminada: la vista de conversación experimental de la última versión ahora es cómo funciona cada tarea, y creció en el camino: espaciado de mensajes más limpio y burbujas de agentes, tareas con capacidad de búsqueda y el árbol de subtareas en el panel de propiedades, comentarios de documentos acoplados en un canal lateral y una barra lateral de chat que muestra cada documento de problema y artefacto de agente. Las tareas bloqueadas muestran sus bloqueadores como enlaces con el bloqueador ordenado en vivo que funciona directamente en el hilo, y un problema con una ejecución en vivo muestra un aviso tranquilo en vuelo en lugar de una falsa alarma. La incorporación también es el chat primero: finalizar el asistente lo lleva directamente a la conversación de su primera tarea, donde el agente lo saluda, le hace preguntas aclaratorias y le propone un plan que usted aprueba elemento por elemento. (#11101, #11263, #11226, #11456, #11487, #11423)
  • Vistas previas HTTPS para tiempos de ejecución administrados, a través de Tailscale: un servicio de tiempo de ejecución administrado solía escuchar en HTTP de bucle invertido simple, por lo que no se podía acceder a la vista previa de la rama de un agente desde un teléfono o una segunda computadora. Paperclip ahora puede exponerlo en una URL HTTPS real en su tailnet, construida en tres capas deliberadas: un agente de host separado con privilegios mínimos que autoriza cada mapeo (credenciales de pares, un rango de puertos fijo, denegaciones de puertos protegidos, auditoría de solo agregar), el ciclo de vida de exposición con concesiones duraderas de tiempo de ejecución propiedad del problema y recuperación de control limitada para que un control varado nunca pueda bloquear el carril para siempre, y un único mediador de par de puertos para que un inicio nunca pueda colisionar con o adoptar el servicio de otra edición: cada desajuste falla y nombra el conflicto. (#11524, #11525, #11526)
  • Inicie sesión en Claude y Codex desde Paperclip: la página de nuevo agente ahora ofrece inicio de sesión de suscripción de Claude antes de crear el agente, en ambos carriles de prueba, con diagnósticos guardados en registros de servidor redactados y URL de inicio de sesión normalizadas para hosts Anthropic incluidos en la lista de permitidos. Debajo del capó, un flujo de token de configuración protegido conduce a claude setup-token a través de un pseudoterminal de zona de pruebas con sesiones vinculadas al propietario y entrega de tokens única, y el adaptador Codex obtiene un inicio de sesión de dispositivo de zona de pruebas equivalente que promueve la credencial solo después de las comprobaciones de preparación y luego elimina la zona de pruebas temporal. Las implementaciones detrás de un borde de plataforma con terminación TLS (Railway, Render, Fly,…) pueden declarar CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true para que el guardia de transporte deje de advertir sobre una conexión que es HTTPS para el usuario, y una credencial de inicio de sesión de dispositivo promocionada ahora sobrevive a la reubicación en el hogar administrado. (#11347, #11286, #11237, #11579, #11578)
  • Un contrato de capacidad real para proveedores de entorno de pruebas: la última versión introdujo transmisión en vivo y sesiones persistentes para Daytona; esta versión hace que esos comportamientos sean demostrables en lugar de configurados. Los proveedores declaran capacidades en su manifiesto, el trabajador en vivo las verifica y el servidor resuelve el conjunto efectivo cerrado por falla como la intersección de declarado, verificado y configurado; una capacidad declarada nunca puede otorgar un método que el trabajador no probó. Las sesiones de streaming y persistentes ahora se activan donde lo permita la instantánea verificada, con un respaldo de encuesta automático, y los tres indicadores de operador que solían bloquearlas desaparecieron (consulte Cambios importantes). (#11463, #11557)
  • Importaciones de empresas fragmentadas y reanudables: la última versión aumentó el límite de importación a 1 GB; esta versión hace que la transferencia sea digna de ello. Una conexión interrumpida al 90 % solía iniciar de nuevo toda la carga: las importaciones ahora se mueven como partes verificadas de ~32 MB puestas en cola en el disco con un libro de ejecución duradero, por lo que se reanuda una transferencia interrumpida desde las partes ya cargadas (a través de conexiones interrumpidas, actualizaciones de páginas y reinicios del servidor) y la memoria de carga máxima cae a una parte. La página Importar y CLI obtuvieron la carga reanudable y una vista previa fragmentada, los paquetes ahora conservan las marcas de tiempo y la jerarquía de las tareas a través de la exportación/importación, los agentes importados mantienen su propio adaptador en lugar de ser obligados al adaptador CEO del destino, y las tareas recién importadas permanecen inactivas bajo el barrido de revisión de productividad. (#11223, #11224, #11193, #11192, #11191)

Mejoras

  • La incorporación te encuentra donde estés: una empresa sin agente es enviada a la incorporación automáticamente, abriéndose en el paso correcto: el paso de la misión se omite cuando la empresa ya tiene una, una misión existente se lleva al asistente y el paso se decide una vez en lugar de saltar bajo un cliente de flujo medio. Los pasos del agente del asistente y del modelo de conexión se modificaron para el flujo de chat primero, ya no mantienen seleccionado un adaptador invisible deshabilitado y el panel decorativo sigue su tema. (#11352, #11416, #11429, #11371, #11379)
  • Semilla de incorporación de Paperclip Cloud: una instancia ahora puede recibir la misión, el primer agente y la primera tarea recopilados durante el registro en Paperclip Cloud y aplicarlos en el momento de la activación, de modo que se abre una pila inicial lista para funcionar en lugar de volver a preguntar. (#11098)
  • Implementaciones de espacio aislado administrado: los inquilinos pueden editar variables de entorno en un entorno de espacio aislado administrado por plataforma (y solo eso), y un modo solo de espacio aislado administrado oculta la ejecución local por completo y la selección de ejecución falla al cerrarse. Las variables de entorno de credenciales documentadas de los proveedores incluidos (por ejemplo, DAYTONA_API_KEY) ahora llegan a sus trabajadores de complementos, y la opción sintética predeterminada "Local" respeta el modo. (#11200, #11244)
  • El trabajo archivado se reabre en el lugar: un espacio de trabajo de ejecución aislado archivado se puede reabrir donde estaba, incluidos los árboles de trabajo git archivados para proyectos de pago administrado. Las llegadas en frío a la URL de una empresa archivada se devuelven a una página clara con un desarchivado one-click. (#11322, #11395, #11302)
  • Gobernanza de revisión: los veredictos de la política de revisión son serializados y transaccionales, un veredicto ya no puede eludir una política al degradarla, el solicitante persiste atómicamente y la interfaz de usuario identifica la política de revisión cuando es lo que restringe la aprobación. (#11405, #10938)
  • Los agentes pueden buscar secretos por nombre: un punto final /secrets/catalog de solo lectura asigna nombres secretos a identificadores para agentes que conectan enlaces de entorno: sin valores, sin configuración de proveedor. Las anotaciones de los documentos emitidos también se incluyen en el contexto de revisión del agente, de modo que los comentarios que se dejan en un documento llegan al agente que actúa en consecuencia. (#9530, #11332)
  • Búsqueda que escala: el selector de problemas principales busca en el servidor en lugar de en la página cargada, y la lista de problemas API obtuvo un filtro updatedSince. (#11334, #9050)
  • Observabilidad: los pasos stage.sync del lado del host están instrumentados y la duración del proceso del agente se aloja correctamente, continuando con el trabajo de seguimiento del inicio del entorno aislado de la última versión. (#11301)
  • Vea su canal con paperclipai channels: el nuevo comando muestra cada línea de lanzamiento (estable, beta, nocturna, canaria), la versión a la que se resuelve actualmente cada una y cuál sigue su instalación. (#11210)

Correcciones

  • Las implementaciones detrás de un proxy de autenticación funcionan de extremo a extremo: el WebSocket de eventos en vivo ahora autentica los navegadores proxy en la nube (anteriormente nunca podía conectarse a través de un proxy de terminación de autenticación), el recurso de recuperación del trabajador del servicio siempre responde con un Response real en lugar de una página en blanco, el manifiesto de la aplicación web se recupera con credenciales y la interfaz de usuario sobrevive a la primera carga contra un backend frío. El ping-pong de selección de empresas archivadas que podría atrapar una sesión en un bucle de redireccionamiento ya no existe. (#11290, #11292, #11245, #11246, #11300)
  • Todo se limita a la cuenta en la que se inició sesión: las comprobaciones de membresía de las invitaciones, la selección de empresas y los cachés de consultas están vinculados a la cuenta que realmente inició sesión, los cachés se borran al cerrar sesión y la empresa almacenada sobrevive a una solicitud fallida de la empresa en lugar de ser eliminada. Los borradores de incorporación verifican la propiedad con una lista obtenida en esta sesión y nunca restauran el estado del asistente para una empresa que no pertenece al usuario. (#11417, #11430, #11380, #11477, #11382, #11370)
  • Reforzamiento de la seguridad: las rutas de acceso a herramientas ya no filtran oráculos de identificación entre inquilinos, los webhooks de rutina rechazan las repeticiones de HMAC, las respuestas detalladas de rutina excluyen la configuración del asignado, las credenciales del cargador de publicación de páginas se limitan al asistente de publicación, los resúmenes del espacio de trabajo de ejecución están aislados, solo se resaltan los enlaces de los archivos del espacio de trabajo accesibles, el comentario de reserva de latidos nunca puede publicar una transcripción sin procesar y la guía CLI que se muestra a los usuarios pasa por el npx seguro forma. (#9589, #9994, #9818, #10894, #10790, #11090, #10143, #11343, #11400)
  • Las ejecuciones mantienen su contexto: las sesiones del agente se reutilizan en las transferencias de ejecución y se mantienen en los comentarios de los problemas, las decisiones de activación de los comentarios leen el estado del problema posterior a la inserción, las reactivaciones de los comentarios de cierre obsoletos sobre las incidencias realizadas se detienen, la recuperación de la transferencia ejecutada exitosamente omite las ejecuciones impulsadas por acciones de recuperación y administradas por complementos, y las correcciones del ciclo de vida de las ejecuciones de ACP solucionan fallas, sincronizan los espacios de trabajo y limpian los arrendamientos adecuadamente. (#9917, #10111, #10068, #8656, #9010, #9047, #11454)
  • Resiliencia de plomería de Sandbox: la carrera de archivos stdin de sandbox se cierra con escrituras atómicas y un sondeador tolerante a fallas, las escrituras estándar se ordenan en el puente de sesión de proceso, el bucle de sondeo del puente de devolución de llamada tiene un tiempo de espera por iteración y un perro guardián, el tráfico del puente se reenvía al origen de escucha local, las rutas de la habilidad de contratación de agente pasan el puente de devolución de llamada, las ejecuciones que llegan a una ventana de reinicio del trabajador del proveedor se reintentan en lugar de fallar la configuración, las llamadas de actividad de Daytona son limitado por llamada y syncOut acepta listados tarball bsdtar. (#11235, #11406, #11341, #10017, #8978, #10212, #11408, #11289)
  • Confiabilidad del adaptador: Claude local canaliza el mensaje de impresión a través de la entrada estándar y ya no falla en los permisos de solo raíz; Codex local omite las advertencias stderr benignas al generar un error de respaldo; OpenCode vuelve a intentar la verificación previa de sus modelos bajo contención transitoria y trata la prueba de disponibilidad como no fatal; Grok informa el uso y el costo real de los tokens en lugar de ceros codificados; La nube del cursor arroja una devolución de llamada API inalcanzable; se rechaza la contratación de un adaptador que la instancia no puede ejecutar; y los adaptadores se cargan en Windows (pathToFileURL antes de la importación dinámica). (#9500, #9463, #10003, #9225, #10294, #10433, #8546, #10256, #4287)
  • Corrección del servidor: DELETE /api/issues/:id tiene éxito para problemas con dependientes (comentarios y cascada de estado de lectura; los registros de costos y finanzas se mantienen con la referencia del problema borrada), las referencias de la compañía que no son UUID devuelven 404 en lugar de 500, se reconocen errores Zod entre paquetes, los bloqueadores de cableado en un PATCH ya no vuelven a abrir implícitamente un problema bloqueado, las solicitudes de preguntar primero sin firmar permanecen fuera de la cola de revisión sin ser canceladas, el reaper del espacio de trabajo del terminal deja de morir de hambre en sus candidatos más antiguos, el TTL predeterminado de JWT ejecutado por el agente está alineado con las 48 h documentadas, por lo que las ejecuciones de computadoras portátiles suspendidas dejan de activarse con una credencial caducada, un PAPERCLIP_API_URL explícito anula la URL de tiempo de ejecución derivada en el entorno de ejecución, los puertos de URL base solo se reescriben para hosts de loopback y las salidas silenciosas distintas de cero en la superficie de flujo de Hermes son fallas. (#11331, #9959, #10168, #10269, #11338, #11238, #10176, #10339, #10258, #10107)
  • Los análisis de Git del espacio de trabajo están limitados: un programador limitado ahora fusiona y limita todos los análisis costosos de Git del espacio de trabajo (una tormenta de solicitudes produjo ~270 procesos git status simultáneos y comprobaciones de estado insuficientes), y el navegador solo inicia los análisis cuando el panel de archivos está abierto y visible. (#11572)
  • Cortes de papel en la interfaz de usuario: la acción de interrupción de mensajes en cola ha vuelto, el acceso secreto del agente se ha movido a una pestaña de secretos con capacidad de búsqueda, los desplazamientos de autocompletar dentro de los cuadros de diálogo se cortan, el archivo de la bandeja de entrada obtuvo un sistema de deshacer y se recuerdan las subtareas plegadas, el enrutamiento de la bandeja de entrada respeta la política guardada para objetivos explícitos, la prosa de aprobación de la junta se representa como rebaja, las insignias de creación de diálogo usan el prefijo de problema real, los enlaces profundos del documento de problema se enrutan correctamente, las descripciones de problemas truncadas se marcan, se generan enlaces de invitación prefiera la URL base pública, el ciclo de vida de ejecución seleccionado y los registros se mantienen actualizados, y el chat de tareas móviles obtuvo acciones de bloqueo, un compositor alineado con el hilo y un cuadro de diálogo de nueva tarea que permanece encima del teclado. (#11374, #11283, #11222, #11220, #11069, #11221, #9817, #8550, #11551, #4771, #7619, #10169, #11282, #11296, #11281)
  • Probabilidades y fines: la sincronización de habilidades actualiza las carpetas del proyecto en su lugar en lugar de reemplazarlas, las escrituras de problemas a través de las claves del tablero funcionan independientemente del asignado, los enlaces secretos del entorno resuelven el contexto de su empresa en el primer guardado y las instancias de desarrollo en modo árbol de trabajo advierten cuando el directorio de datos de Postgres integrado se encuentra en el directorio temporal del sistema operativo. (#11066, #9025, #11291, #8283)

Guía de actualización

  • Migraciones: esta versión agrega 11 migraciones de bases de datos (0212 a 0222), que cubren la primera tarea de incorporación de una por empresa (0212), ejecuciones de transferencias reanudables de la empresa (0213), sesiones de inicio de sesión del dispositivo adaptador (0214, 0215), semillas de incorporación a la nube (0216), políticas de clave externa de eliminación de problemas (0217), valores predeterminados de políticas de resolución de interacción. y procedencia (0218), estado de exposición del tiempo de ejecución (0219), arrendamientos de tiempo de ejecución del espacio de trabajo de ejecución (0220), sesiones de token de configuración de Claude (0221) y referencias de arrendamiento de entorno que sobreviven a la eliminación del entorno (0222). Las migraciones se ejecutan automáticamente al inicio, no se requiere ninguna acción manual. Nada elimina una tabla ni elimina datos; tenga en cuenta que 0218 reescribe los valores de la política de resolución en las interacciones pendientes existentes (de manera conservadora; consulte Cambios importantes) y 0217/0222 cambian lo que sucede con las filas dependientes al eliminarlas.
  • Nuevas variables de entorno opcionales (todas tienen valores predeterminados razonables; configúrelos solo si los necesita):
    • PAPERCLIP_MANAGED_RUNTIME_HTTPS — auto (predeterminado), off o force; controla el valor predeterminado de Tailscale HTTPS para las vistas previas del tiempo de ejecución administrado (consulte Cambios importantes). PAPERCLIP_TAILSCALE_BROKER_SOCKET y PAPERCLIP_TAILSCALE_DNS_NAME anulan la ruta del socket del intermediario y el nombre DNS de la red trasera; PAPERCLIP_VITE_HMR_PROTOCOL (ws/wss) fija el protocolo HMR de vista previa de desarrollo. (#11524, #11525)
    • CLAUDE_LOGIN_TRUSTED_PROXIES: pares proxy incluidos en la lista permitida para el protector de transporte de inicio de sesión de Claude; CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true: declara la terminación TLS de borde de plataforma en plataformas administradas donde las direcciones de proxy no se pueden conocer. (#11286, #11579)
    • PAPERCLIP_ONBOARDING_SEED_ADAPTER_TYPE: tipo de adaptador para el agente creado por una semilla de incorporación en la nube. (#11098)
    • SANDBOX_ORPHAN_CLEANUP_SPOOL_DIR: donde se ponen en cola los registros duraderos de limpieza del entorno sandbox; PAPERCLIP_PROCESS_SESSION_STDIN_MAX_RETRIES: reintento máximo para el sondeador estándar de sandbox. (#11347, #11235)
  • Claves de configuración eliminadas: streamAgentSessionOutput (servidor) y useSessions / useLogStream (complemento de Daytona) ya no hacen nada; elimínelos de las configuraciones guardadas cuando lo desee; Se cargan pero son inertes. (#11557)
  • Agente ejecuta JWT TTL: el valor predeterminado del servidor ahora coincide con las 48 h documentadas (PAPERCLIP_AGENT_JWT_TTL_SECONDS=172800). Si confió en el antiguo vencimiento implícito de 1 hora, establezca la variable explícitamente. (#10176)
  • Vistas previas HTTPS: para usarlas, instale Tailscale en el host y ejecute el nuevo broker (consulte el archivo README @paperclipai/tailscale-https-broker); para optar por no participar, configure PAPERCLIP_MANAGED_RUNTIME_HTTPS=off. Nada más cambia para los servicios personalizados o no administrados.

paperclip v2026.824.0

Paperclip v2026.824.0

Released: 2026-08-24

Paperclip v2026.824.0 is a fast follow to 2026.817.0 — and the first stable to walk the full canary → nightly → beta → stable happy path end to end, soaking as 2026.818.0-beta.1 before promotion. It carries 172 commits: chat-style tasks graduate from experiment to the default experience, managed runtime previews become reachable over Tailscale HTTPS, sandbox execution gains a verified provider capability contract, you can sign in to Claude and Codex from inside the product, large company imports survive dropped connections, and a large batch of long-standing community fixes lands.

Breaking Changes

None of these require action for a typical install, but read through before upgrading:

  • Chat-style tasks are the default. The "Chat-Style Tasks" experiment toggle is gone; the task detail page is now the conversation view for everyone. A new "Classic Task Interface" preference (enableClassicTaskInterface, replacing enableTaskChatRedesign in instance settings) restores the pre-chat page — page-level header, plain comment thread, fixed Properties sidebar — but chat-only features are unavailable there. (#11101)
  • Sandbox session-output streaming is now capability-driven, and three operator flags are gone. The server's streamAgentSessionOutput setting and the Daytona plugin's useSessions and useLogStream keys no longer exist; the verified provider capability snapshot is the only streaming decision, with an automatic poll fallback. Saved configurations that still carry the removed keys load fine — the keys are simply inert. (#11463, #11557)
  • Managed dev runtimes now default to Tailscale HTTPS previews. When the host broker is available, eligible Paperclip-managed worktree runtimes are exposed as tailscale_https instead of loopback HTTP. Set PAPERCLIP_MANAGED_RUNTIME_HTTPS=off to keep the old behavior, or force to fail closed when the broker is missing. Managed runtime control routes also gained two new 409 responses (workspace_runtime_control_in_progress, workspace_runtime_lease_conflict) — callers that assumed a control always starts must handle a conflict. (#11524, #11525)
  • Interaction resolver policy defaults to anyone for new interactions. Every interaction kind now goes through one resolver-policy evaluator with recorded provenance, instead of per-route rules that blocked valid agents. Migration 0218 deliberately does not widen anything already pending: existing rows keep their old restrictions under new names (board_or_agents → not_creator, board_only → human_only). (#11376)
  • The decision-training surfaces are removed from the Decisions desk — the training library route, row actions, and drawer. The backend snapshot contract is unchanged and no data migration runs. (#11225)

Highlights

  • Chat-style tasks, now the default experience — Last release's experimental conversation view is now how every task works, and it grew up on the way: cleaner message spacing and agent bubbles, searchable assignment and the sub-task tree in the properties pane, document comments docked in a side gutter, and a chat sidebar that surfaces every issue document and agent artifact. Blocked tasks show their blockers as links with live, ordered blocker work right in the thread, and an issue with a live run shows a calm in-flight notice instead of a false alarm. Onboarding is chat-first too: finishing the wizard drops you straight into your first task's conversation, where the agent greets you, asks clarifying questions, and proposes a plan you approve item by item. (#11101, #11263, #11226, #11456, #11487, #11423)
  • HTTPS previews for managed runtimes, over Tailscale — A managed runtime service used to listen on plain loopback HTTP, so an agent's branch preview was unreachable from a phone or a second computer. Paperclip can now expose it at a real HTTPS URL on your tailnet, built in three deliberate layers: a separate least-privilege host broker that authorizes every mapping (peer credentials, a fixed port range, protected-port denies, append-only audit), the exposure lifecycle with durable issue-owned runtime leases and bounded control recovery so a stranded control can never block the lane forever, and a single port-pair mediator so a start can never collide with or adopt another issue's service — every mismatch fails closed and names the conflict. (#11524, #11525, #11526)
  • Sign in to Claude and Codex from inside Paperclip — The new-agent page now offers Claude subscription login before you create the agent, on both Test lanes, with diagnostics kept in redacted server logs and login URLs normalized to allowlisted Anthropic hosts. Under the hood, a guarded setup-token flow drives claude setup-token through a sandbox pseudo-terminal with owner-bound sessions and one-time token delivery, and the Codex adapter gets an equivalent sandbox device-login that promotes the credential only after readiness checks and then deletes the temporary sandbox. Deployments behind a TLS-terminating platform edge (Railway, Render, Fly, …) can declare CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true so the transport guard stops warning about a connection that is HTTPS to the user, and a promoted device-login credential now survives managed-home re-seeding. (#11347, #11286, #11237, #11579, #11578)
  • A real capability contract for sandbox providers — Last release introduced live output streaming and persistent sessions for Daytona; this release makes those behaviors provable instead of configured. Providers declare capabilities in their manifest, the live worker verifies them, and the server resolves the effective set fail-closed as the intersection of declared, verified, and configured — a declared capability can never grant a method the worker didn't prove. Streaming and persistent sessions now turn on wherever the verified snapshot allows, with an automatic poll fallback, and the three operator flags that used to gate them are gone (see Breaking Changes). (#11463, #11557)
  • Chunked, resumable company imports — Last release raised the import cap to 1 GB; this release makes the transfer worthy of it. A dropped connection at 90% used to start the whole upload over — imports now move as verified ~32 MB parts spooled to disk with a durable run ledger, so an interrupted transfer resumes from the parts already uploaded (across dropped connections, page refreshes, and server restarts) and peak upload memory drops to one part. The Import page and CLI gained the resumable upload and a chunked preview, bundles now preserve task timestamps and hierarchy through export/import, imported agents keep their own adapter instead of being coerced to the destination's CEO adapter, and freshly imported tasks stay quiescent under the productivity review sweep. (#11223, #11224, #11193, #11192, #11191)

Improvements

  • Onboarding meets you where you are — A company with no agent is sent into onboarding automatically, opening at the right step: the mission step is skipped when the company already has one, an existing mission is carried into the wizard, and the step is decided once instead of jumping under a mid-flow customer. The wizard's agent and connect-model steps were reworked for the chat-first flow, no longer keep an invisible disabled adapter selected, and the decorative panel follows your theme. (#11352, #11416, #11429, #11371, #11379)
  • Paperclip Cloud onboarding seed — An instance can now receive the mission, first agent, and first task collected during Paperclip Cloud signup and apply them at activation, so a seeded stack opens ready to work instead of asking again. (#11098)
  • Managed sandbox deployments — Tenants can edit environment variables on a platform-managed sandbox environment (and only that), and a managed-sandbox-only mode hides local execution entirely with run selection failing closed. Bundled providers' documented credential env vars (e.g. DAYTONA_API_KEY) now reach their plugin workers, and the synthetic "Local" default option respects the mode. (#11200, #11244)
  • Archived work reopens in place — An archived isolated execution workspace can be reopened where it was, including archived git worktrees for managed-checkout projects. Cold arrivals on an archived company's URL are bounced to a clear page with a one-click Unarchive. (#11322, #11395, #11302)
  • Review governance — Review-policy verdicts are serialized and transactional, a verdict can no longer bypass a policy by downgrading, the requester is persisted atomically, and the UI badges the review policy when it is what constrains approval. (#11405, #10938)
  • Agents can look up secrets by name — A read-only /secrets/catalog endpoint maps secret names to ids for agents wiring env bindings — no values, no provider config. Issue-document annotations are also included in agent review context, so feedback left on a document reaches the agent that acts on it. (#9530, #11332)
  • Search that scales — The parent-issue picker searches on the server instead of the loaded page, and the issues list API gained an updatedSince filter. (#11334, #9050)
  • Observability — Host-side stage.sync steps are instrumented and the agent process span is homed correctly, continuing last release's sandbox-startup tracing work. (#11301)
  • See your channel with paperclipai channels — the new command shows every release lane (stable, beta, nightly, canary), the version each currently resolves to, and which one your install follows. (#11210)

Fixes

  • Deployments behind an authenticating proxy work end to end — The live-events WebSocket now authenticates cloud-proxied browsers (previously it could never connect through an auth-terminating proxy), the service worker's fetch fallback always answers with a real Response instead of a blank page, the web app manifest is fetched with credentials, and the UI survives first load against a cold backend. The archived-company selection ping-pong that could trap a session in a redirect loop is gone. (#11290, #11292, #11245, #11246, #11300)
  • Everything is scoped to the signed-in account — Invite membership checks, company selection, and query caches are all keyed to the account that is actually signed in, caches clear on sign-out, and the stored company survives a failed company request instead of being dropped. Onboarding drafts verify ownership against a list fetched this session and never restore wizard state for a company the user does not own. (#11417, #11430, #11380, #11477, #11382, #11370)
  • Security hardening — Tool-access routes no longer leak cross-tenant ID oracles, routine webhooks reject HMAC replays, routine detail responses exclude assignee configuration, page-publish uploader credentials are scoped to the publish helper, execution workspace summaries are isolated, only accessible workspace file links are highlighted, the heartbeat-fallback comment can never publish a raw transcript, and CLI guidance shown to users goes through the safe npx form. (#9589, #9994, #9818, #10894, #10790, #11090, #10143, #11343, #11400)
  • Runs keep their context — Agent sessions are reused across execution handoffs and kept across issue comments, comment-wake decisions read post-insert issue state, stale closure-comment wakeups on done issues stop, successful-run handoff recovery skips recovery-action-driven and plugin-managed runs, and ACP run lifecycle corrections settle failures, sync workspaces back, and clean up leases properly. (#9917, #10111, #10068, #8656, #9010, #9047, #11454)
  • Sandbox plumbing resilience — The sandbox stdin file race is closed with atomic writes and a fault-tolerant poller, stdin writes are ordered in the process-session bridge, the callback bridge poll loop has a per-iteration timeout and watchdog, bridge traffic forwards to the local listen origin, the agent-hire skill's routes pass the callback bridge, runs that hit a provider worker restart window retry instead of failing setup, Daytona liveness calls are bounded per call, and syncOut accepts bsdtar tarball listings. (#11235, #11406, #11341, #10017, #8978, #10212, #11408, #11289)
  • Adapter reliability — Claude local pipes the print prompt via stdin and no longer fails root-only permission skips; Codex local skips benign stderr warnings when deriving a fallback error; OpenCode retries its models preflight under transient contention and treats the availability probe as non-fatal; Grok reports real token usage and cost instead of hardcoded zeros; Cursor cloud drops an unreachable API callback; hiring onto an adapter the instance cannot run is refused; and adapters load on Windows (pathToFileURL before dynamic import). (#9500, #9463, #10003, #9225, #10294, #10433, #8546, #10256, #4287)
  • Server correctness — DELETE /api/issues/:id succeeds for issues with dependents (comments and read-state cascade; cost and finance records are kept with their issue reference cleared), non-UUID company refs return 404 instead of 500, cross-package Zod errors are recognized, wiring blockers in a PATCH no longer implicitly reopens a blocked issue, unsigned ask-first requests stay out of the review queue without being cancelled, the terminal workspace reaper stops starving on its oldest candidates, the agent run JWT default TTL is aligned to the documented 48h so suspended-laptop runs stop waking with an expired credential, an explicit PAPERCLIP_API_URL overrides the derived runtime URL in run env, base-URL ports are only rewritten for loopback hosts, and silent nonzero exits in the Hermes flow surface as failures. (#11331, #9959, #10168, #10269, #11338, #11238, #10176, #10339, #10258, #10107)
  • Workspace Git scans are bounded — One bounded scheduler now coalesces and caps every expensive workspace Git scan (a request storm once produced ~270 concurrent git status processes and starved health checks), and the browser only starts scans when the file panel is open and visible. (#11572)
  • UI paper cuts — The queued-message interrupt action is back, agent secret access moved to a searchable secrets tab, slash autocomplete scrolls inside dialogs, inbox archive gained an undo toast and folded subtasks are remembered, inbox routing honors the saved policy for explicit targets, board approval prose renders as markdown, create-dialog badges use the real issue prefix, issue-document deep links route correctly, truncated issue descriptions are flagged, generated invite links prefer the public base URL, selected run lifecycle and logs stay current, and the mobile task chat gained blocker actions, a composer aligned with the thread, and a new-task dialog that stays above the keyboard. (#11374, #11283, #11222, #11220, #11069, #11221, #9817, #8550, #11551, #4771, #7619, #10169, #11282, #11296, #11281)
  • Odds and ends — Skill sync refreshes project folders in place instead of replacing them, issue writes through board keys work regardless of assignee, environment-secret bindings resolve their company context on first save, and worktree-mode dev instances warn when the embedded-Postgres data directory sits in the OS temp dir. (#11066, #9025, #11291, #8283)

Upgrade Guide

  • Migrations: this release adds 11 database migrations (0212 through 0222), covering the one-per-company onboarding first task (0212), resumable company transfer runs (0213), adapter device-login sessions (0214, 0215), Cloud onboarding seeds (0216), issue-deletion foreign-key policies (0217), interaction resolver-policy defaults and provenance (0218), runtime exposure state (0219), execution-workspace runtime leases (0220), Claude setup-token sessions (0221), and environment-lease references that survive environment deletion (0222). Migrations run automatically on startup — no manual action required. Nothing drops a table or deletes data; note that 0218 rewrites resolver-policy values on existing pending interactions (conservatively — see Breaking Changes) and 0217/0222 change what happens to dependent rows on delete.
  • New optional environment variables (all have sensible defaults; set only if you need them):
    • PAPERCLIP_MANAGED_RUNTIME_HTTPS — auto (default), off, or force; controls the Tailscale HTTPS default for managed runtime previews (see Breaking Changes). PAPERCLIP_TAILSCALE_BROKER_SOCKET and PAPERCLIP_TAILSCALE_DNS_NAME override the broker socket path and the tailnet DNS name; PAPERCLIP_VITE_HMR_PROTOCOL (ws/wss) pins the dev-preview HMR protocol. (#11524, #11525)
    • CLAUDE_LOGIN_TRUSTED_PROXIES — allowlisted proxy peers for the Claude login transport guard; CLAUDE_LOGIN_EDGE_TLS_TERMINATED=true — declare platform-edge TLS termination on managed platforms where the proxy addresses aren't knowable. (#11286, #11579)
    • PAPERCLIP_ONBOARDING_SEED_ADAPTER_TYPE — adapter type for the agent created by a Cloud onboarding seed. (#11098)
    • SANDBOX_ORPHAN_CLEANUP_SPOOL_DIR — where durable sandbox cleanup records are spooled; PAPERCLIP_PROCESS_SESSION_STDIN_MAX_RETRIES — retry ceiling for the sandbox stdin poller. (#11347, #11235)
  • Removed configuration keys: streamAgentSessionOutput (server) and useSessions / useLogStream (Daytona plugin) no longer do anything — remove them from saved configs at your leisure; they load but are inert. (#11557)
  • Agent run JWT TTL: the server default now matches the documented 48h (PAPERCLIP_AGENT_JWT_TTL_SECONDS=172800). If you relied on the old implicit 1h expiry, set the variable explicitly. (#10176)
  • HTTPS previews: to use them, install Tailscale on the host and run the new broker (see the @paperclipai/tailscale-https-broker README); to opt out, set PAPERCLIP_MANAGED_RUNTIME_HTTPS=off. Nothing else changes for unmanaged or custom services.
