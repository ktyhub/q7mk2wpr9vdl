uso del navegador 1.0.0

<img src="https://github.com/browser-use/browser-use/releases/download/1.0.0/browser-use-1.0-vs-0.x-bench.png" alt="browser-use 1.0 vs 0.x: puntuación más alta, más barato, más rápido, 80% menos código" width="100%">

−136,866 líneas. Se eliminó el 80% de la biblioteca.

Empezamos de nuevo. El agente ahora escribe Python en un REPL persistente, directamente en el protocolo Chrome DevTools. Sin serializador DOM, sin esquema de acción, nada intermedio. La simplicidad gana: ahora es el agente web de última generación.

  ● task
  │
  ● model writes a cell          new_tab(url); bu.click(41); js(...)
  │
  ● REPL runs it on Chrome (CDP) → output back to the model
  │
  ✓ finish(result)

Mismos modelos: hasta 33 puntos más, 2.7: 5,2 veces más barato, 2 a 3 veces más rápido.

uv add 'browser-use==1.0.0'
export BROWSER_USE_API_KEY=bu_...    # cloud.browser-use.com/new-api-key

from browser_use import Agent

print(Agent('Find the number of stars of the browser-use repo').run_sync().final_result())

Qué cambia por defecto

| | 0.x | 1.0 | |---|---|---| | Modelo (llm=None) | requerido | bu-fast en el navegador Utilice la puerta de enlace | | Navegador (Browser()) | Cromo local | un navegador Utilice un navegador en la nube; Browser('chromium') para uno local | | Clave | uno por proveedor | una clave de uso del navegador (BROWSER_USE_API_KEY o browser-use login) | | Modo | | ultrafast (ID de árbol de accesibilidad) en bu-fast / bu-ultrafast; mode='default' se excluye | | Límites run() | max_steps=500 | max_steps=100, timeout=1700 |

Su propio modelo: ChatOpenAI, ChatAnthropic, ChatGoogle o cualquier cadena de modelo Pydantic AI (llm='groq:llama-3.3-70b-versatile').

Actualizando desde 0.x

Lea primero MIGRATING.md. Enumera todas las opciones 0.x y su respuesta 1.0.

  • Una opción que 1.0 no puede aceptar genera un nombre TypeError antes de que se inicie cualquier navegador o se facture algo. Sin operaciones silenciosas. Las perillas de sintonización 0.x 1.0 no sirven para (use_vision=True, flash_mode, max_failures, ...) advierten una vez y se ignoran.
  • Cada importación 0.x eliminada (todas las rutas de los módulos desde 0.1 a 0.13, y cada nombre público de un módulo 1.0 mantenido) genera un ImportError que nombra el reemplazo y vincula MIGRATING.md. Las alternativas de except ImportError todavía funcionan.
  • ActionResult(include_in_memory=...) advierte y se ignora: cada resultado de la herramienta permanece en la conversación.
  • Una vez que pasan las comprobaciones de configuración, run() no genera: una clave o modelo rechazado, un navegador que no se inicia (creación en la nube 402/5xx/tiempo de espera) y fallas dentro de la ejecución devuelven status='error' con result.error, y un navegador que se inició se detiene. Una clave que falta aún aparece antes de que se cree algo.

Cambios de comportamiento para comprobar

  • Browser() es un navegador en la nube. Las tareas en localhost o IP privadas necesitan Browser('chromium') (una advertencia lo dice).
  • Browser(local=True) ahora significa Browser('chromium'). Tu propio Chrome abierto es Browser('chrome').
  • Browser('chrome') se adjunta sólo a un navegador cuyo DevToolsActivePort activo se encuentra en los directorios de su propio perfil. Ya no se adjunta a las respuestas de 127.0.0.1:9222.
  • run(max_steps=...) tiene el valor predeterminado 100 (en lugar de 500). Un paso es una solicitud de modelo.
  • is_successful() es None cuando el agente no dio veredicto. Utilice r.is_done() and r.success is not False para el valor predeterminado 0.x.
  • errors() devuelve sólo el error que finalizó la ejecución. Los errores de celda recuperados están en result.messages.
  • result.partial está configurado únicamente por checkpoint(..., partial=True). Para obtener uno, nombre la bandera en la tarea: "después de cada página, guarde los títulos con checkpoint('titles.json', titles, parcial=True)".
  • result.cost_usd cubre los cargos de búsqueda web y de modelo, no el navegador en la nube ni su proxy.
  • El espacio de trabajo (predeterminado: un nuevo directorio temporal browser-use-*) se conserva después de la ejecución. Se utiliza una ruta workspace= tal como se indica (se hace absoluta, los enlaces simbólicos no se resuelven), por lo que result.downloads[0].relative_to(workspace) funciona.
  • prohibited_domains=['example.com'] también bloquea sus subdominios. Con cualquier regla de dominio establecida, todas las URL de file: están bloqueadas. BROWSER_USE_ALLOWED_DOMAINS no se lee: Browser() sube mientras está armado.
  • Se rechazan los modelos de pasarela 0.x (bu-2-0, bu-1-0, bu-latest,...). BROWSER_USE_LLM_URL no se lee: utilice ChatBrowserUse(base_url=...).
  • Los modelos de chat de LangChain plantean TypeError. Azure lee AZURE_OPENAI_API_KEY (no AZURE_OPENAI_KEY) y necesita OPENAI_API_VERSION.
  • browser-use --mcp imprime un aviso de obsolescencia y sirve las herramientas --cli-mcp (browser_exec, browser_screenshot, browser_login). browser-use init fue eliminado.
  • Los scripts de consola bu y browser desaparecieron (rompieron uv tool install junto con otras herramientas). Utilice browser-use o browseruse.
  • Los extras aws, oci, video, examples, eval, core, openai-tools, cli-oci ya no están (pip advierte e instala sin ellos). anthropic, google, mcp, cli, all aún se resuelven; Anthropic, Google y MCP son dependencias centrales.

También nuevo

  • Resultados escritos: Agent(task, output_model_schema=MyModel) y luego result.structured_output.
  • Cargas y descargas en navegadores locales y en la nube: entradas desde workspace=, descargas en workspace/downloads y result.downloads. El agente carga el archivo que usted nombró y nunca lo crea ni lo sobrescribe.
  • Secretos: sensitive_data= escrito con type_secret() y redactado a partir de la salida de la celda, los puntos de control, los resultados de la herramienta y el resultado. No es una caja de arena; consulte el modelo trust en MIGRATING.md.
  • Restricciones de dominio (allowed_domains, prohibited_domains, block_ip_addresses) con los patrones 0.x, en todos los modos de navegador.
  • Búsqueda web (web_search=True), facturada por búsqueda a la clave de uso del navegador y agregada a result.cost_usd.
  • CLI y MCP: browser-use canaliza Python al arnés del navegador; browser-use --cli-mcp ejecuta el servidor MCP; browser-use skill install registra la habilidad del agente.
  • Docker: browseruse/browseruse:1.0.0 y ghcr.io/browser-use/browser-use:1.0.0. Cada compilación de imágenes se prueba en amd64 y arm64 en CI, también en solicitudes de extracción.

Fiabilidad

  • Respuestas transmitidas. Cada solicitud de Respuestas de OpenAI (la puerta de enlace de uso del navegador y api.openai.com) se transmite. Un giro transmitido tarda 300 s en llegar a su primer evento y luego se ejecuta mientras los eventos fluyen, hasta 930 s. Los giros largos del bu-smart ya no terminan a los 300 s.
  • Un reintento transitorio. Una falla reportada dentro de HTTP 200 (server_error, overloaded, request_timeout, upstream_stream_failed) o una transmisión que finaliza antes de su evento final se reintenta una vez por ejecución, como 429 o 5xx.
  • Compactación. Una solicitud de Respuestas en la ventana contextual se compacta una vez y se envía nuevamente. Los modelos con ventanas más pequeñas (gpt-4o, 128k) se compactan antes de que se desborden. Un elemento de compactación transmitido se devuelve exactamente como lo haría una respuesta no transmitida, y un 400 en él reenvía la solicitud una vez sin el elemento.
  • Muchos agentes en un proceso. Un Agent aumenta un límite bajo de archivos abiertos a min(hard limit, 10240) (el valor predeterminado de macOS es 256). Un error de conexión ahora indica su causa, p. ModelConnectionError: Connection error. (OSError: [Errno 24] Too many open files).
  • Gpt-6-luna proxy. ChatOpenAI('gpt-6-luna', base_url=...) obtiene reasoning_effort='none' en cualquier host, por lo que las herramientas funcionan detrás de un proxy.
  • Páginas con trabajadores. wait_for_network_idle() ya no espera los scripts de Web Worker ni los iframes entre sitios, lo que lo ejecutó hasta su límite de 10 s.
  • Diálogos. Una navegación mantenida por un mensaje beforeunload, o una captura de pantalla con un cuadro de diálogo JS abierto, nombra el cuadro de diálogo en cuestión de segundos.
  • keep_alive. Una ejecución después de que un demonio del navegador esté inactivo continúa en la pestaña del agente, no en about:blank.

Problemas conocidos

  • Cada dependencia se fija exactamente (==) y el archivo de bloqueo se confirma. Esta es una política de la cadena de suministro: obtienes exactamente las versiones probadas por CI. El costo: un proyecto que necesita una versión diferente de pydantic, pydantic-ai-slim, mcp, google-genai, pillow u otro paquete anclado no puede instalar 1.0 junto a él. Cuéntanos qué pin te bloquea.
  • google-genai permanece por debajo de 3: 3.0.0 llama al Gemini API en v1, que rechaza herramientas. Esto desaparece una vez que Pydantic AI lo admite.
  • La emulación de Viewport aún no funciona en navegadores en la nube. Utilice Browser('chromium') para otra ventana gráfica.

browser-use 1.0.0

Highlights

  • Ground-up rewrite on CDP — 1.0 deletes ~137k lines (80% of the library): the DOM serializer and action schema are gone, and the agent now emits Python into a single persistent REPL that drives Chrome DevTools Protocol directly (new_tab, bu.click, js, finish). That is the architectural bet behind the claimed state-of-the-art numbers — same models score up to 33 points higher at 2.7–5.2x lower cost and 2–3x the speed. Read the benchmark footnote carefully, though: an OpenAI outage skewed the raw gap, and with provider errors excluded 1.0 is statistically tied with Browser Use Pi on quality; the defensible win is −$0.013/task and −114 s/task, not accuracy.

  • New defaults break 0.x configs loudly — llm=None now resolves to bu-fast on the Browser Use gateway and Browser() means a Browser Use Cloud browser, so a clean install needs BROWSER_USE_API_KEY (or browser-use login) before anything runs. MIGRATING.md is mandatory reading. Unsupported 0.x options raise a TypeError naming the option before a browser starts or anything is billed, and removed imports raise an ImportError pointing to the replacement — no silent no-ops. Pin ==1.0.0 to avoid drift; stay on 0.x with pip install 'browser-use<1'.

  • Local-browser and localhost semantics changed — Browser() is cloud-backed, so tasks against localhost or private IPs must opt into Browser('chromium') (one warning flags this), and Browser(local=True) is now an alias for it. Browser('chrome') no longer attaches to whatever answers on 127.0.0.1:9222 — it requires a live DevToolsActivePort in your own profile dirs, which will break generic debugging-port CI setups. Also: BROWSER_USE_ALLOWED_DOMAINS is not read (it actually raises), BROWSER_USE_LLM_URL is replaced by ChatBrowserUse(base_url=...), 0.x gateway models (bu-2-0, bu-latest, …) are rejected, and LangChain chat models raise TypeError.

  • Run and result semantics to rewrite assertions around — run() now defaults to max_steps=100 (was 500; one step = one model request) with a 1700 s timeout. After config checks pass, run-time failures no longer raise: rejected keys/models, cloud-browser create failures (402/5xx/timeout) and in-run errors return status='error' with result.error; only a missing key raises up front. is_successful() is None when the model gave no verdict (use r.is_done() and r.success is not False for 0.x behavior), errors() holds only the terminal error (recovered cells are in result.messages), and result.cost_usd covers model + web search but not the cloud browser or its proxy. Workspaces persist after the run, and domain rules now block subdomains and all file: URLs.

  • Reliability work aimed at long, parallel runs — Every OpenAI Responses request is streamed (300 s to first event, up to 930 s total), so long bu-smart turns no longer die at 300 s; one transient retry covers HTTP-200-embedded failures (server_error, overloaded, request_timeout, upstream_stream_failed) and streams that end early. Over-window requests compact once and resend, and Agent raises the soft open-file limit to min(hard, 10240) (macOS defaults to 256) so many agents can share a process — connection errors now name causes like Too many open files. Also fixed: wait_for_network_idle() no longer stalls on Web Workers/cross-site iframes, beforeunload dialogs are surfaced in seconds, and a dead browser daemon resumes in the agent's tab.

  • New capabilities, with packaging constraints to watch — Typed results via output_model_schema → result.structured_output; workspace-scoped uploads/downloads (result.downloads) where the agent never overwrites a named file; sensitive_data= secrets redacted from cells/checkpoints/results (explicitly not a sandbox); domain restrictions and per-search-billed web_search=True; CLI/MCP (browser-use --cli-mcp, skill install, with --mcp deprecated and browser-use init removed); and amd64/arm64 Docker images smoke-tested on PRs. Constraints: all dependencies are pinned == with a committed lockfile as a supply-chain policy, so projects needing different pydantic/mcp/google-genai versions cannot co-install 1.0; google-genai stays below 3; viewport emulation does not work on cloud browsers; and the bu/browser console scripts are gone — use browser-use or browseruse.

<details> <summary><b>Upgrading from 0.x, benchmarks, everything that changed</b></summary>

Need 0.x? pip install 'browser-use<1'

What changes by default

| | 0.x | 1.0 | |---|---|---| | Model (llm=None) | required | bu-fast on the Browser Use gateway | | Browser (Browser()) | local Chromium | a Browser Use Cloud browser; Browser('chromium') for a local one | | Key | one per provider | one Browser Use key (BROWSER_USE_API_KEY, or browser-use login) | | Mode | | ultrafast (accessibility-tree ids) on bu-fast / bu-ultrafast; mode='default' opts out | | run() limits | max_steps=500 | max_steps=100, timeout=1700 s |

Your own model: ChatOpenAI, ChatAnthropic, ChatGoogle, or any Pydantic AI model string (llm='groq:llama-3.3-70b-versatile').

Upgrading from 0.x

Read MIGRATING.md first. It lists every 0.x option and its 1.0 answer.

  • An option 1.0 cannot honor raises a TypeError naming it before any browser starts or anything is billed. No silent no-ops. 0.x tuning knobs 1.0 has no use for (use_vision=True, flash_mode, max_failures, ...) warn once and are ignored.
  • Every removed 0.x import (all module paths from 0.1 to 0.13, and every public name of a module 1.0 kept) raises an ImportError that names the replacement and links MIGRATING.md. except ImportError fallbacks still work.
  • ActionResult(include_in_memory=...) warns and is ignored: every tool result stays in the conversation.
  • Once configuration checks pass, run() does not raise: a rejected key or model, a browser that fails to start (cloud create 402/5xx/timeout) and failures inside the run all return status='error' with result.error, and a browser that did start is stopped. A missing key still raises before anything is created.

Behavior changes to check

  • Browser() is a cloud browser. Tasks on localhost or private IPs need Browser('chromium') (one warning says so).
  • Browser(local=True) now means Browser('chromium'). Your own open Chrome is Browser('chrome').
  • Browser('chrome') attaches only to a browser whose live DevToolsActivePort is in your own profile dirs. It no longer attaches to whatever answers on 127.0.0.1:9222.
  • run(max_steps=...) defaults to 100 (was 500). One step is one model request.
  • is_successful() is None when the agent gave no verdict. Use r.is_done() and r.success is not False for the 0.x default.
  • errors() returns only the error that ended the run. Recovered cell errors are in result.messages.
  • result.partial is set only by checkpoint(..., partial=True). To get one, name the flag in the task: "after each page, save the titles with checkpoint('titles.json', titles, partial=True)".
  • result.cost_usd covers model and web search charges, not the cloud browser or its proxy.
  • The workspace (default: a new temp dir browser-use-*) is kept after the run. A workspace= path is used as given (made absolute, symlinks not resolved), so result.downloads[0].relative_to(workspace) works.
  • prohibited_domains=['example.com'] also blocks its subdomains. With any domain rule set, every file: URL is blocked. BROWSER_USE_ALLOWED_DOMAINS is not read: Browser() raises while it is set.
  • The 0.x gateway models (bu-2-0, bu-1-0, bu-latest, ...) are rejected. BROWSER_USE_LLM_URL is not read: use ChatBrowserUse(base_url=...).
  • LangChain chat models raise TypeError. Azure reads AZURE_OPENAI_API_KEY (not AZURE_OPENAI_KEY) and needs OPENAI_API_VERSION.
  • browser-use --mcp prints a deprecation notice and serves the --cli-mcp tools (browser_exec, browser_screenshot, browser_login). browser-use init was removed.
  • The bu and browser console scripts are gone (they broke uv tool install next to other tools). Use browser-use or browseruse.
  • Extras aws, oci, video, examples, eval, core, openai-tools, cli-oci are gone (pip warns and installs without them). anthropic, google, mcp, cli, all still resolve; Anthropic, Google and MCP are core dependencies.

Also new

  • Typed results: Agent(task, output_model_schema=MyModel) then result.structured_output.
  • Uploads and downloads on local and cloud browsers: inputs from workspace=, downloads in workspace/downloads and result.downloads. The agent uploads the file you named and never creates or overwrites it.
  • Secrets: sensitive_data= typed with type_secret() and redacted from cell output, checkpoints, tool results and the result. Not a sandbox; see the trust model in MIGRATING.md.
  • Domain restrictions (allowed_domains, prohibited_domains, block_ip_addresses) with the 0.x patterns, in every browser mode.
  • Web search (web_search=True), billed per search to your Browser Use key and added to result.cost_usd.
  • CLI and MCP: browser-use pipes Python to browser-harness; browser-use --cli-mcp runs the MCP server; browser-use skill install registers the agent skill.
  • Docker: browseruse/browseruse:1.0.0 and ghcr.io/browser-use/browser-use:1.0.0. Every image build is smoke-tested on amd64 and arm64 in CI, on pull requests too.

Reliability

  • Streamed Responses. Every OpenAI Responses request (the Browser Use gateway and api.openai.com) is streamed. A streamed turn gets 300 s to its first event, then runs while events flow, up to 930 s. Long bu-smart turns no longer end at 300 s.
  • One transient retry. A failure reported inside HTTP 200 (server_error, overloaded, request_timeout, upstream_stream_failed) or a stream that ends before its final event is retried once per run, like a 429 or 5xx.
  • Compaction. A Responses request over the context window compacts once and is sent again. Models with smaller windows (gpt-4o, 128k) compact before they overflow. A streamed compaction item is sent back exactly as a non-streamed response would carry it, and a 400 on it resends the request once without the item.
  • Many agents in one process. An Agent raises a low soft open-file limit to min(hard limit, 10240) (macOS defaults to 256). A connection error now names its cause, e.g. ModelConnectionError: Connection error. (OSError: [Errno 24] Too many open files).
  • Proxied gpt-6-luna. ChatOpenAI('gpt-6-luna', base_url=...) gets reasoning_effort='none' on any host, so tools work behind a proxy.
  • Pages with workers. wait_for_network_idle() no longer waits for Web Worker scripts and cross-site iframes, which ran it to its 10 s cap.
  • Dialogs. A navigation held by a beforeunload prompt, or a screenshot with a JS dialog open, names the dialog within seconds.
  • keep_alive. A run after a dead browser daemon continues in the agent's tab, not on about:blank.

Benchmark

BU Bench v2, 60 tasks x 3 reps, cloud browsers, 2026-11-09.

| agent | score [95% CI] | $/task | s/task | |---|---|---|---| | browser-use 1.0 (mode='ultrafast', the mode bu-fast uses) | 62.5 [58.3, 66.5] | 0.070 | 650 | | Browser Use Pi (e7007f2), same window | 56.3 [50.2, 62.4] | 0.082 | 743 |

An OpenAI outage hit this window. Pi lost 18 of 180 runs to provider errors, 1.0 lost 1 (its one retry recovered 13 of 14). So the raw gap overstates quality. With provider errors excluded, paired 1.0 minus Pi: score +1.1 [-3.2, +5.7] (no significant difference), cost -$0.013/task [-0.024, -0.004], time -114 s/task [-202, -31]. Same quality, cheaper and faster.

Both arms ran gpt-6-luna on api.openai.com, judged by gpt-5.6-luna (xhigh). The default bu-fast model on the Browser Use gateway was not part of this run. 95% task-clustered bootstrap intervals.

Known issues

  • Every dependency is pinned exactly (==), and the lockfile is committed. This is a supply-chain policy: you get exactly the versions CI tested. The cost: a project that needs a different version of pydantic, pydantic-ai-slim, mcp, google-genai, pillow or another pinned package cannot install 1.0 next to it. Tell us which pin blocks you.
  • google-genai stays below 3: 3.0.0 calls the Gemini API on v1, which rejects tools. This goes away once Pydantic AI supports it.
  • Viewport emulation does not work on cloud browsers yet. Use Browser('chromium') for another viewport.

Report problems at https://github.com/browser-use/browser-use/issues
