caddy v2.10.1

Este es probablemente nuestro lanzamiento de parche más grande hasta la fecha; no es que muchas cosas estuvieran rotas, pero se están realizando muchas mejoras gracias a una adopción más amplia y las contribuciones de muchas más personas. ¡Solo mire a los nuevos colaboradores a continuación! De todos modos, esta versión contiene algunas correcciones de errores y actualizaciones de dependencias que esperamos sean de gran utilidad. ¡Háganos saber si hay algún problema! ¡Y gracias a todos los que contribuyeron, especialmente a nuestro confiable equipo de mantenimiento! Esta versión de Caddy requiere Go v1.25.0 o posterior.

caddy v2.10.1

Highlights

  • Go 1.25 is now the floor — Building from source requires Go 1.25.0+ (#7184), which is what lets this release lean on newer stdlib APIs throughout: http.KeepAliveConfig, http.Protocols, reflect.TypeFor, maps.Copy, slices.*/max/min. If you ship custom builds or vendor Caddy as a library, upgrade your toolchain first; prebuilt binaries are unaffected.
  • HTTP/3 and QUIC get a major refresh — quic-go was bumped three times, v0.51.0 → v0.53.0 → v0.54.0 (#6972, #7094, #7138), alongside a switch to http.Protocols for unified h1/h2/h2c handling (#6961) and a fix that frees the QUIC listener on shutdown (#7177). Net effect: better protocol negotiation and cleaner config reloads, but anyone pinning quic-go in their own module should re-check compatibility.
  • Keepalive semantics changed — verify your configs — Listeners and transport probes now use the new KeepAliveConfig API (#7151, #7157), and a negative KeepAliveInterval now disables keepalives outright (#7158). This is the one behavioral shift that could surprise operators: if you set a negative interval expecting the old default behavior, re-examine it. Listener cleanup on partial bind failures also landed (#7176).
  • Reverse proxy: dynamic SNI and stricter validation — With DialTLSContext, a server_name containing a placeholder now actually drives the TLS dial (#6955), which matters for per-request SNI/routing setups that previously silently ignored placeholders. HTTP transport versions are now validated (#7112), and the forwardproxy module's LoadModule field-name bug (#6978) is corrected — relevant if you build custom modules or use forward proxying.
  • TLS/ACME and provisioning are more robust — The client_auth leaf verifier is finally wired into Caddyfile (#6772), TLS DNS-challenge options are validated at adapt time (#7099), and an external certificate manager regression is fixed (#7179). For module authors, provisioning fixes are the headline: failed apps no longer surface as (val, nil) from Context.App (#7070), admin routers are provisioned correctly (#6997, #7004), and failed configs are cleaned up (#7068).
  • Smaller wins worth adopting — caddy adapt reads from stdin (#7163); hash-password gains a bcrypt cost flag (#7149, typo fixed in #7168); header replacement search patterns accept placeholders (#7117); the default logger honors {include}/{exclude} (#6995); error handlers no longer clobber sub-handler matchers (#6999); file server adds AVIF (#6988), returns 400 on invalid paths (#7017), and sets Range on precompressed files so Content-Length appears (#7042).

No breaking changes.

This is probably our biggest patch release ever -- not that lots of things were broken, but there's lots of refinement happening thanks to broader adoption and contributions from many more people. Just look at the New Contributors below!

Anyway, this release does contain some bug fixes and dependency upgrades which we hope will serve you well. Let us know if there's any issues! And thank you to all who contributed, especially our reliable maintainer team!

This version of Caddy requires Go v1.25.0 or newer.
