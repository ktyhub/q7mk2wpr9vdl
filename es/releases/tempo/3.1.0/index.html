#tempo v3.1.0 Grafana Tempo 3.1.0 agrega redacción de seguimiento basada en consultas, aritmética de métricas TraceQL y extrapolación con reconocimiento de muestreo, mejoras de conectividad de Kafka y herramientas experimentales para comparar y podar seguimientos. También convierte a vParquet5 en el formato predeterminado para bloques recién escritos.

Destacados

  • Redacción por consulta: envíe trabajos de redacción utilizando un selector TraceQL en lugar de enumerar ID de seguimiento, con ventanas de tiempo opcionales y mejoras en la confiabilidad de la redacción.
  • Métricas de TraceQL: Combine agregaciones con aritmética y opte por la extrapolación utilizando la probabilidad de muestreo registrada en intervalos. La ruta de recuperación más rápida de solo intervalo ahora está habilitada de forma predeterminada.
  • Generador de métricas y gráficos de servicio: Detecte la topología del servicio bajo muestreo intenso con un indicador de información de conexión opcional, reconozca db.system.name y reduzca la sobrecarga de procesamiento de gráficos de servicio y métricas de intervalo.
  • Poda de intervalo experimental: Reduzca el tamaño de respuesta de rastreo por ID v2, con opción de suscripción a nivel de solicitud y valores predeterminados configurables.
  • Conectividad Kafka: Configure mecanismos SASL adicionales, TLS y TLS mutuo, recuperación en rack y compresión de productor, incluido gzip para Azure Event Hubs.
  • Diferencias y resúmenes de trazas experimentales: Compare trazas a través de API, tempo-cli y MCP, con formatos de parche completo y resumen compacto.
  • vParquet5 de forma predeterminada: Escriba nuevos bloques en vParquet5 mientras continúa leyendo los bloques vParquet4 y vParquet3 existentes, sin una migración de datos. El changelog detallado a continuación incluye las notas RC1 revisadas y los backports posteriores. con referencias de relaciones públicas, créditos de contribuyentes, identificadores de seguridad y orientación sobre actualizaciones.

Cambios importantes

Antes de actualizar

Esta versión incluye importantes cambios de configuración y nuevos valores predeterminados. Revise las entradas detalladas a continuación, especialmente si utiliza el almacenamiento en caché Redis, escrituras vParquet3 o configuraciones personalizadas de interfaz de consulta.

  • vParquet3: Tempo se niega a iniciarse cuando se configura para escribir bloques de vParquet3. Cambie storage.trace.block.version a vParquet5 o vParquet4 antes de actualizar. Los bloques vParquet3 existentes siguen siendo legibles pero ya no están compactados.
  • Redis: El clúster Redis se convierte en el predeterminado, se elimina la compatibilidad con Sentinel y cambian las claves de configuración y los ajustes de TLS. Revise los detalles de la migración antes de actualizar una instalación utilizando el caché experimental Redis.
  • Redacción en ventana: No envíe trabajos de redacción en ventana mientras los programadores y los trabajadores ejecutan versiones diferentes. Un trabajador mayor puede ignorar la ventana de tiempo y redactar cada rastro coincidente en un bloque.
  • Actualización desde un 3.1 RC: Elimina la opción obsoleta query_frontend.trace_by_id.span_pruning_enabled. La poda sigue siendo voluntaria con span_pruning=true a menos que se configure un valor predeterminado; span_pruning_enabled_by_default y la anulación por inquilino span_pruning_enabled siguen estando disponibles.
  • Comparación de trazas: El comando CLI y la herramienta MCP ahora se denominan traces-diff.
  • Comportamiento de consulta: Revise los cambios de fragmentación de seguimiento por ID, la validación de consultas de métricas más estricta y el tamaño reducido del paquete de transmisión predeterminado gRPC.

tempo v3.1.0

Grafana Tempo 3.1.0 adds query-based trace redaction, TraceQL metrics arithmetic and sampling-aware extrapolation, Kafka connectivity improvements, and experimental tools for comparing and pruning traces. It also makes vParquet5 the default format for newly written blocks.

Highlights

  • Redaction by query: Submit redaction jobs using a TraceQL selector instead of enumerating trace IDs, with optional time windows and redaction reliability improvements.
  • TraceQL metrics: Combine aggregations with arithmetic and opt into extrapolation using the sampling probability recorded in spans. The faster span-only fetch path is now enabled by default.
  • Metrics-generator and service graphs: Detect service topology under heavy sampling with an opt-in connection-information gauge, recognize db.system.name, and reduce span-metrics and service-graph processing overhead.
  • Experimental span pruning: Reduce trace-by-ID v2 response size, with request-level opt-in and configurable defaults.
  • Kafka connectivity: Configure additional SASL mechanisms, TLS and mutual TLS, rack-aware fetching, and producer compression, including gzip for Azure Event Hubs.
  • Experimental trace diff and summaries: Compare traces through the API, tempo-cli, and MCP, with full-patch and compact-summary formats.
  • vParquet5 by default: Write new blocks in vParquet5 while continuing to read existing vParquet4 and vParquet3 blocks, without a data migration.

Breaking Changes

Before upgrading

This release includes breaking configuration changes and new defaults. Review the detailed entries below, especially if you use Redis caching, vParquet3 writes, or custom query-frontend settings.

  • vParquet3: Tempo refuses to start when configured to write vParquet3 blocks. Change storage.trace.block.version to vParquet5 or vParquet4 before upgrading. Existing vParquet3 blocks remain readable but are no longer compacted.

  • Redis: Redis Cluster becomes the default, Sentinel support is removed, and configuration keys and TLS settings change. Review the migration details before upgrading an installation using the experimental Redis cache.

  • Windowed redaction: Do not submit windowed redaction jobs while schedulers and workers run different versions. An older worker can ignore the time window and redact every matching trace in a block.

  • Upgrading from a 3.1 RC: Remove the obsolete query_frontend.trace_by_id.span_pruning_enabled option. Pruning remains opt-in with span_pruning=true unless a default is configured; span_pruning_enabled_by_default and the per-tenant span_pruning_enabled override remain available.

  • Trace comparison: The CLI command and MCP tool are now named traces-diff.

  • Query behavior: Review Trace-by-ID sharding changes, stricter metrics-query validation, and the reduced default gRPC streaming packet size.

  • cache: Experimental Redis cache has been completely rewritten with multiple breaking changes. Sentinel support has been dropped in favor of Redis Cluster (default, opt-out) (#7337) (@oleg-kozlyuk-grafana)

    • Upgrade Redis client to github.com/redis/go-redis/v9 and make routing explicit.
    • Redis Cluster is now the default; opt into the single-node client with single_node: true (or -redis.single-node).
    • Redis Cluster deployments require Redis 7+.
    • Redis Sentinel support is removed: the master_name, sentinel_username, sentinel_password YAML keys and their -redis.master-name, -redis.sentinel-username, -redis.sentinel-password flags are gone. YAML keys idle_timeout and max_connection_age are renamed to conn_max_idle_time and conn_max_lifetime.
    • The minimal tls_enabled/tls_insecure_skip_verify pair is replaced with the dskit-style TLS block (tls_cert_path, tls_key_path, tls_ca_path, tls_server_name, tls_insecure_skip_verify, tls_cipher_suites, tls_min_version); invalid TLS settings now fail closed instead of silently downgrading to cleartext.

Cross-slot MGet/Del fan out across shards in parallel; MSet uses Pipeline instead of TxPipeline so cross-slot writes no longer fail with CROSSSLOT.
