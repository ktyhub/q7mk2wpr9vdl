tempo v3.0.0

Mayor Publicado28 may 2026 Fuentegrafana/tempo original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

#tempo v3.0.0 Tempo 3.0 es una versión importante que completa la transición a la nueva arquitectura de ingesta/escritura, elimina componentes 2.x obsoletos, gradúa las métricas de TraceQL a disponibilidad general y agrega herramientas de migración para usuarios de Tempo 2.x. Esta versión contiene cambios importantes en la configuración y la implementación. Revise la guía de migración antes de actualizar, especialmente si utiliza ingestadores heredados, anulaciones heredadas, bloques v2, OpenCensus, bloques locales o configuraciones personalizadas de tienda en vivo/frontend de consulta.

Destacados

  • La nueva arquitectura de ingesta/escritura reemplaza a los ingestadores heredados.
  • Las métricas de TraceQL están generalmente disponibles; las alertas sobre las métricas de TraceQL y la ruta de lectura más rápida siguen siendo experimentales.
  • Mejoras en vParquet5 y rutas de consulta de métricas más rápidas.
  • Controles ampliados del generador de métricas para la gestión de cardinalidad.
  • Soporte de redacción de seguimiento.
  • Soporte de perfilado de tramos mediante otelpiroscopio.
  • Correcciones de corrección y observabilidad de Live Store y Block Builder. Enlaces útiles:
  • Release note: https://grafana.com/docs/tempo/latest/release-notes/v3-0/
  • Guía de migración: https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/migrate-to-3/
  • Guía de actualización: https://grafana.com/docs/tempo/latest/set-up-for-tracing/setup-tempo/upgrade/

Cambios importantes

Tempo 3.0 incluye varias eliminaciones y cambios predeterminados que afectan al operador. Revise la guía de migración antes de actualizar.

  • Se eliminó la ruta de escritura heredada basada en ingesta. Las implementaciones deben migrar a la arquitectura de ingesta/escritura 3.0.
    • Se eliminaron los ingestadores y el módulo de ingesta por @javiermolinar en #6504 / #6959
    • Se eliminó la configuración de ingesta de aplicaciones restante y ingest.enabled por @javiermolinar en #6667/#6873.
    • Se eliminó la configuración de livestore del anillo de partición por @javiermolinar en #6981
    • Se eliminaron alertas de ingeridor y compactador por @javiermolinar en #6369
  • Se eliminó la codificación de bloques v2 y el componente compactador v2 heredado por @joe-elliott en #6273.
    • Se eliminaron los comandos CLI específicos de v2: list block, list index, view index, gen index y gen bloom.
  • Bloque centralizado y configuración WAL: block_builder y live_store ahora siempre usan la configuración storage.trace.block; @stoewer elimina los campos de configuración de bloque por módulo en #6647
  • Las consultas de datos recientes ahora garantizan resultados completos al fallar cuando una instancia está retrasada. Valores predeterminados de query_frontend.query_end_cutoff a 30s y live_store.fail_on_high_lag a true por @mapno en #7210/#7232
  • Anulaciones heredadas (planas, sin ámbito) deshabilitadas de forma predeterminada. Tempo se niega a iniciarse si se detectan anulaciones heredadas. Configure enable_legacy_overrides: true o -config.enable-legacy-overrides=true para volver a participar temporalmente. @electron0zero eliminará las anulaciones heredadas en una versión futura en el n.° 6741
  • La configuración de anulaciones configurables por el usuario metrics_generator.processors ya no se fusiona con las anulaciones de tiempo de ejecución. metrics_generator.processors ahora tiene prioridad sobre las anulaciones del tiempo de ejecución y coincide con todas las demás configuraciones en las anulaciones configurables por el usuario. La configuración de processors: [] deshabilita todos los procesadores para el inquilino por @electron0zero en #7176/#7185
  • RetryInfo habilitado de forma predeterminada. distributor.retry_after_on_resource_exhausted ahora tiene como valor predeterminado 5s (era 0), por lo que OTLP clients recibe una sugerencia de reintento sobre errores de ResourceExhausted de @electron0zero en #7088.
    • Establezca en 0 para deshabilitar todo el clúster, o configure la anulación por inquilino ingestion.retry_info_enabled: false para deshabilitarla para un solo inquilino.

tempo v3.0.0

Tempo 3.0 is a major release that completes the transition to the new ingest/write architecture, removes deprecated 2.x components, graduates TraceQL metrics to general availability, and adds migration tooling for Tempo 2.x users.

This release contains breaking configuration and deployment changes. Review the migration guide before upgrading, especially if you use legacy ingesters, legacy overrides, v2 blocks, OpenCensus, localblocks, or custom live-store/query-frontend settings.

Highlights

  • New ingest/write architecture replaces legacy ingesters.
  • TraceQL metrics is generally available; alerting on TraceQL metrics and the faster read path remain experimental.
  • vParquet5 improvements and faster metrics query paths.
  • Expanded metrics-generator controls for cardinality management.
  • Trace redaction support.

Breaking Changes

Tempo 3.0 includes several operator-impacting removals and default changes. Review the migration guide before upgrading.

  • The legacy ingester-based write path has been removed. Deployments must migrate to the 3.0 ingest/write architecture.
    • Removed ingesters and the ingester module by @javiermolinar in #6504 / #6959
    • Removed remaining app ingester config and ingest.enabled by @javiermolinar in #6667 / #6873
    • Removed partition ring livestore config by @javiermolinar in #6981
    • Removed ingester and compactor alerts by @javiermolinar in #6369
  • Removed v2 block encoding and the legacy v2 compactor component by @joe-elliott in #6273
    • Removed v2-specific CLI commands: list block, list index, view index, gen index, and gen bloom.
  • Centralized block and WAL config: block_builder and live_store now always use storage.trace.block settings; per-module block config fields are removed by @stoewer in #6647
  • Recent data queries now guarantee complete results by failing when an instance is lagging. Defaults query_frontend.query_end_cutoff to 30s and live_store.fail_on_high_lag to true by @mapno in #7210 / #7232
  • Disabled legacy (flat, unscoped) overrides by default. Tempo refuses to start if legacy overrides are detected. Set enable_legacy_overrides: true or -config.enable-legacy-overrides=true to opt back in temporarily. Legacy overrides will be removed in a future release by @electron0zero in #6741
  • User-configurable overrides config metrics_generator.processors no longer merges with runtime overrides. metrics_generator.processors now takes precedence over runtime overrides, matching every other config in user-configurable overrides. Setting processors: [] disables all processors for the tenant by @electron0zero in #7176 / #7185
  • Enabled RetryInfo by default. distributor.retry_after_on_resource_exhausted now defaults to 5s (was 0) so OTLP clients receive a retry hint on ResourceExhausted errors by @electron0zero in #7088
    • Set to 0 to disable cluster-wide, or set the per-tenant override ingestion.retry_info_enabled: false to disable for a single tenant.
  • Removed duplicate compaction prefix from CompactorConfig CLI flags by @electron0zero in #6909
    • compaction.compaction.block-retention → compaction.block-retention
    • compaction.compaction.max-objects-per-block → compaction.max-objects-per-block
    • compaction.compaction.max-block-bytes → compaction.max-block-bytes
    • compaction.compaction.compaction-window → compaction.compaction-window
  • Removed OpenCensus receiver by @javiermolinar in #6523
  • Removed legacy mem-ballast-size-mbs CLI flag by @orkhan-huseyn in #6403
  • tempo-cli: Support relative time (now, now-1h) for start/end args and standardize on RFC3339 in all commands by @electron0zero in #6458
    • query search command no longer accepts timestamps without timezone, for example 2024-01-01T00:00:00; use RFC3339, for example 2024-01-01T00:00:00Z, or relative time instead.
  • Consolidated read configuration for recent data cutoff. query_frontend.search.query_ingesters_until is removed in favor of only query_frontend.search.query_backend_after by @mapno in #6507
  • Removed deprecated querier.query_live_store config. This field must be removed from configs on upgrade by @javiermolinar in #7048
  • Optimized TraceQL AST by rewriting conditions on the same attribute to their array equivalent by @stoewer in #6353
    • Slightly changes the array matching semantics of != and !~ operators and introduces stricter rules for regex literals.
  • Removed span-metrics leftovers and lazy-init generator clients by @javiermolinar in #6618
  • Decommissioned livestore MetricsGenerator query service by @javiermolinar in #6615
  • Removed metrics-generator localblocks processor and related local block storage plumbing by @javiermolinar in #6555
  • SpanMetricsSummary is removed and querier code simplified by @javiermolinar in #6496 and #6510
  • Set the all target to be 3.0-compatible and removed the scalable-single-binary target by @joe-elliott in #6283
  • Cleaned up enterprise jsonnet by @javiermolinar in #6505
