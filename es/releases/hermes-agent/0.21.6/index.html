Lanzamiento del parche. Esta etiqueta acumula los ~2100 PR fusionados desde v0.21.5 en una versión etiquetada estable para Docker y Hermes Cloud. Notas seleccionadas completas para este barco con ventana con v0.22.0.

Acerca de esta versión

Esta es la primera versión eliminada por el nuevo proceso de lanzamiento estable: una referencia de intento, una imagen Docker probada y una etiqueta de recibo en el momento de la publicación. Envía la etiqueta, esta versión de GitHub y la imagen de Docker. La aplicación de escritorio, los paquetes de Termux y Microsoft Store permanecen en su versión actual por ahora y avanzan con la próxima versión del paquete.

Medida en la confirmación 818c13be1dc4fd28987e1e881a9408224afd4535, la ventana desde v0.21.5 contiene 8,867 confirmaciones sin fusión en 8,342 archivos modificados (+772,490 / −225,600), 2,106 PR fusionados y 3,027 problemas cerrados.

También en la ventana, no documentada aquí a propósito: transcripción en vivo mientras hablas en CLI, TUI y Desktop (stt.streaming); la voz hablada se enruta a su propio modelo (auxiliary.voice_chat) con el razonamiento desactivado de forma predeterminada; complementos de terceros que se ejecutan en un host de complementos por perfil (plugins.isolation: host) y una configuración ▸ inicio de complementos para sus páginas de configuración; modelos favoritos y fijados en la parte superior del selector de escritorio, un chip de uso antes de que una suscripción llegue a su fin y proveedores de tarifa limitada que dicen por qué y hasta cuándo; modelos locales en hermes model más llama.cpp CUDA en Linux x64 y arm64; paquetes de idiomas en capas conectables en el núcleo, el escritorio y la TUI; un resumen primero hermes status (--short, --full); un selector de alcance diferencial en el panel de revisión (No comprometido/Rama/Último turno) y mantenerse despierto que sigue al turno; advertencias de cron, doctor y del canal de inicio cuando no se puede escribir en el almacén cron; indicadores de aprobación para cargas de credenciales y Unicode invisible en comandos de terminal; una configuración de Discord que verifica el token del bot e imprime el enlace de invitación; una definición de flujo de trabajo Kanban unificada; activate.fish; GPT-6.1 Sol y Claude Sonnet 5.5 / Haiku 5.5 en los catálogos; y docenas de nuevos complementos comunitarios.

Los release note completamente seleccionados para esta ventana se envían con v0.22.0, que documentarán todo desde v0.21.0 en adelante: aspectos destacados, áreas destacadas y créditos completos de los contribuyentes. No se omite nada en esta ventana.

Actualizando

  • CLI (instalaciones de git): hermes update, o vuelva a ejecutar el resumen del instalador.

Correcciones de seguridad

Reforzamiento de la autenticación del panel

  • Los encabezados X-Forwarded-For falsificados podrían restablecer el límite de tasa de inicio de sesión con contraseña y sortear el límite por IP en el inicio de sesión nativo (#133367)
  • Las solicitudes de inicio de sesión no autenticadas podrían escribir valores ilimitados en el registro de auditoría de autenticación (#133369)
  • Las rutas públicas /auth/ no tenían límite de tamaño del cuerpo de solicitud (#133370)
  • El inicio de sesión nativo podía enviar códigos de inicio de sesión a una redirección sin bucle invertido, lo que permitía tomar el control de la sesión (#130685)

Gracias a Tenable Research por informar los cuatro problemas (TRA-725, TRA-726, TRA-727, TRA-728). El problema de redireccionamiento de inicio de sesión nativo también fue informado de forma independiente y @Froraut lo solucionó. La solución X-Forwarded-For se basa en el trabajo comunitario de @hinotoi-agent y @BearHuddleston (#40285).

Reforzamiento del filtro git del repositorio

  • Las llamadas automáticas de git (instantánea del espacio de trabajo de la sesión, árboles de trabajo de subagente, kanban, limpieza del árbol de trabajo, hermes -w) podrían ejecutar programas de filtro clean/smudge/process definidos por la configuración propia del repositorio untrusted, antes del primer mensaje (#130661)

Gracias a 燕涛 por informar esto de forma privada. También fue reportado y arreglado públicamente por @jonpol01 (#126017, #126019) y @JoaoMarcos44 (#126075).

Refuerzo del remitente de la puerta de enlace de correo electrónico

  • Un nombre para mostrar entre comillas en el encabezado From (por ejemplo, "Victim <victim@example.com>" <attacker@evil.test>) podría hacer que el mensaje de un atacante pase la lista de correo electrónico permitido como remitente permitido (#125212).

Gracias a Daniel Steele (@keeltrace) por informar esto y escribir la solución (#124322).

hermes-agent v0.21.6

Hermes Agent v0.21.6

Release Date: October 8, 2026

Patch release. This tag rolls up the ~2,100 PRs merged since v0.21.5 into a stable tagged release for Docker and Hermes Cloud. Full curated notes for this window ship with v0.22.0.

<!-- HERMES_BUILDS_TABLE -->

About this release

This is the first release cut by the new stable release pipeline: one attempt ref, a tested Docker image, and a receipt tag at publish. It ships the tag, this GitHub release and the Docker image. The desktop app, Termux packages and the Microsoft Store stay on their current build for now and move with the next bundled release.

Measured at commit 818c13be1dc4fd28987e1e881a9408224afd4535, the window since v0.21.5 contains 8,867 non-merge commits across 8,342 changed files (+772,490 / −225,600), 2,106 merged PRs and 3,027 closed issues.

Also in the window, undocumented here on purpose: live transcription while you speak on CLI, TUI and Desktop (stt.streaming); spoken voice turns routed to their own model (auxiliary.voice_chat) with reasoning off by default; third-party plugins running in a per-profile plugin host (plugins.isolation: host) and one Settings ▸ Plugins home for their settings pages; favorite and pinned models at the top of the Desktop picker, a usage chip before a subscription hits its wall, and rate-limited providers that say why and until when; local models in hermes model plus llama.cpp CUDA on Linux x64 and arm64; pluggable, layered language packs across core, Desktop and TUI; a summary-first hermes status (--short, --full); a review-pane diff scope selector (Uncommitted / Branch / Last turn) and keep-awake that follows the turn; cron, doctor and home-channel warnings when the cron store goes unwritable; approval flags for credential uploads and invisible Unicode in terminal commands; a Discord setup that checks the bot token and prints the invite link; a unified Kanban workflow definition; activate.fish; GPT-6.1 Sol and Claude Sonnet 5.5 / Haiku 5.5 in the catalogs; and dozens of new community plugins.

Full curated release notes for this window ship with v0.22.0, which will document everything from v0.21.0 onward — highlights, feature areas, and complete contributor credits. Nothing in this window is skipped.

Updating

  • Docker / Hermes Cloud: nousresearch/hermes-agent:stable (or :latest).
  • CLI (git installs): hermes update, or re-run the installer one-liner.
  • Desktop app and Termux: no change in this release; they update with the next bundled release.

Security Fixes

Dashboard authentication hardening

  • Spoofed X-Forwarded-For headers could reset the password-login rate limit and get around the per-IP cap on native sign-in (#133367)
  • Unauthenticated login requests could write unbounded values to the auth audit log (#133369)
  • The public /auth/ routes had no request-body size limit (#133370)
  • Native sign-in could send login codes to a non-loopback redirect, which allowed session takeover (#130685)

Thanks to Tenable Research for reporting all four issues (TRA-725, TRA-726, TRA-727, TRA-728). The native sign-in redirect issue was also reported independently and fixed by @Froraut. The X-Forwarded-For fix builds on community work by @hinotoi-agent and @BearHuddleston (#40285).

Repository git filter hardening

  • Automatic git calls (session workspace snapshot, subagent worktrees, kanban, worktree cleanup, hermes -w) could run clean/smudge/process filter programs defined by an untrusted repository's own config, before the first prompt (#130661)

Thanks to 燕涛 for reporting this privately. It was also reported and fixed publicly by @jonpol01 (#126017, #126019) and @JoaoMarcos44 (#126075).

Email gateway sender hardening

  • A quoted display name in the From header (e.g. "Victim <victim@example.com>" <attacker@evil.test>) could make an attacker's message pass the email allowlist as an allowed sender (#125212)

Thanks to Daniel Steele (@keeltrace) for reporting this and writing the fix (#124322).
