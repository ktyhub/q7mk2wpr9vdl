Usuario final Changelog

❗ Problemas conocidos ❗

  • service: el punto final de métricas interno Prometheus del recopilador (:8888) ahora emite etiquetas de servicio OTel con guión bajo. nombres (service_name, service_instance_id, service_version) en lugar de nombres en notación de puntos (service.name, service.instance.id, service.version). Los usuarios que seleccionen este punto final con el receptor Prometheus verán estos cambios de nombre. etiquetas en atributos de recursos y puntos de datos. Como solución alternativa, agregue el siguiente metric_relabel_configs a su scrape configuración en el receptor prometheus: 
    metric_relabel_configs:  - source_labels: [service_name]    target_label: service.name  - source_labels: [service_instance_id]    target_label: service.instance.id  - source_labels: [service_version]    target_label: service.version  - regex: service_name|service_instance_id|service_version    action: labeldrop
    Consulte https://github.com/open-telemetry/opentelemetry-collector/issues/14814 para obtener detalles y actualizaciones.

🛑 Cambios importantes 🛑

  • all: cambie las unidades métricas para que sean singulares y coincidan con las especificaciones de OTel, p. {requests} -> {request} (#14753)

💡 Mejoras 💡

  • cmd/mdatagen: agregue el campo obsoleto_type para permitir especificar un alias para los tipos de componentes. (#14718)
  • cmd/mdatagen: Genera MetricsBuilder API con ámbito de entidad que aplica asociaciones de métricas de entidad en tiempo de compilación (#14659)
  • cmd/mdatagen: omitir la generación de opciones de configuración de reagregación para métricas que no tienen atributos agregables. (#14689)
  • pkg/service: El informe de estado interno ya no elimina los estados repetidos Ok y RecoverableError (#14282) Los eventos de estado ahora pueden transportar metadatos y es valioso permitir que se emitan a pesar del valor de estado en sí. no cambiando.

🧰 Corrección de errores 🧰

  • cmd/builder: agregue .exe para generar nombres binarios al compilar para objetivos de Windows. (#12591)
  • exporter/debug: agregue impresión de metadatos métricos con detalle. (#14667)
  • exporter/otlp_grpc: evita el pánico del puntero nulo cuando se llaman métodos de inserción antes de que el exportador OTLP inicialice sus gRPC clients. (#14663) Cuando la cola de envío y el reintento están deshabilitados, llamar a ConsumeTraces, ConsumeMetrics, ConsumeLogs o ConsumeProfiles antes del exportador OTLP inicializa su gRPC clients podría causar pánico por desreferencia del puntero nulo. Los métodos push ahora devuelven un error en lugar de entrar en pánico.
  • exporter/otlp_http: muestra la URL de destino real en mensajes de error cuando el middleware modifica la URL de solicitud. (#14673) Desenvuelve el *url.Error devuelto por http.Client.Do() para evitar registros de errores engañosos cuando una extensión de middleware actualiza dinámicamente el punto final.
  • pdata/pprofile: cambia el diccionario de entradas de tablas de diccionario solo una vez al fusionar perfiles (#14709) Para los datos de la tabla del diccionario, solíamos cambiar sus diccionarios al hacer el interruptor para los datos que los utilizan. Sin embargo, cuando una entrada está asociada con muchos otros datos (varios las muestras pueden usar la misma pila), habríamos estado cambiando el diccionarios de la entrada varias veces. Ahora cambiamos los diccionarios para los datos de la tabla del diccionario solo una vez, antes cambiar los perfiles de recursos.

API Changelog

🛑 Cambios importantes 🛑

  • cmd/mdatagen: Genera un tipo de configuración por métrica <MetricName>Config para cada métrica cuando reaggregation_enabled: true (#14689) Las métricas con atributos agregables obtienen AggregationStrategy y EnabledAttributes []<MetricName>AttributeKey campos; otros solo obtienen Enabled. Constantes clave de atributo escritas (por ejemplo, DefaultMetricAttributeKeyStringAttr) reemplace []string, eliminando las asignaciones de segmentos de atributos de tiempo de ejecución. Los errores de validación ahora enumeran atributos válidos y estrategias por nombre. Los componentes que utilicen reaggregation_enabled: true deberán actualizar las referencias a MetricConfig.
  • pdata/pprofile: Actualizar protoID para campos de muestra de mensajes (#14652)

💡 Mejoras 💡

  • cmd/mdatagen: amplíe la herramienta mdatagen para generar estructuras go config para los componentes del recopilador OpenTelemetry. (#14561) El código de configuración del componente se genera a partir de la sección config del archivo metadata.yaml.
  • cmd/mdatagen: amplíe la herramienta mdatagen para generar el esquema de configuración JSON para los componentes OpenTelemetry. (#14543) El esquema de configuración del componente JSON se genera a partir de la sección config del archivo metadata.yaml.
  • cmd/mdatagen: Generación de esquemas para partes de configuración controladas por mdatagen (#14562) El esquema se genera en un archivo yaml independiente y se utiliza para crear un esquema de componente completo.
  • pdata/pprofile: Implementar atributos basados en referencias en Perfiles (#14546)
  • pkg/pdata: actualice las definiciones de protobuf de OTLP a la versión 1.10.0 (#14766)
  • pkg/service: El informe de estado interno ya no elimina los estados repetidos Ok y RecoverableError (#14282) Los eventos de estado ahora pueden transportar metadatos y es valioso permitir que se emitan a pesar del valor de estado en sí. no cambiando.
  • pkg/xexporterhelper: agrega lógica para limpiar particiones de la memoria que no se utilizan durante un período de tiempo específico. (#14526)
  • pkg/xpdata: agregue el constructor NewEntity, Entity.CopyToResource y EntityAttributeMap.All a pdata/xpdata/entity (#14659)

🧰 Corrección de errores 🧰

  • cmd/mdatagen: conserva extensiones personalizadas (por ejemplo, x-customType, x-pointer) durante la resolución de referencia de esquema. (#14713, #14565) Soluciona un problema por el cual las propiedades personalizadas definidas localmente en un nodo eran sobrescrito y perdido al resolver un $ref en un esquema externo/interno.
  • pkg/xexporterhelper: Se corrigió la carrera cuando se elimina la partición de LRU y se agregan nuevos elementos al mismo tiempo. (#14526)

opentelemetry-collector v0.148.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.148.0

End User Changelog

❗ Known Issues ❗

  • service: The collector's internal Prometheus metrics endpoint (:8888) now emits OTel service labels with underscore names (service_name, service_instance_id, service_version) instead of dot-notation names (service.name, service.instance.id, service.version). Users scraping this endpoint with the Prometheus receiver will see these renamed labels in resource and datapoint attributes. As a workaround, add the following metric_relabel_configs to your scrape config in prometheus receiver: 
    metric_relabel_configs:  - source_labels: [service_name]    target_label: service.name  - source_labels: [service_instance_id]    target_label: service.instance.id  - source_labels: [service_version]    target_label: service.version  - regex: service_name|service_instance_id|service_version    action: labeldrop
    See https://github.com/open-telemetry/opentelemetry-collector/issues/14814 for details and updates.

🛑 Breaking changes 🛑

  • all: Change metric units to be singular to match OTel specification, e.g. {requests} -> {request} (#14753)

💡 Enhancements 💡

  • cmd/mdatagen: Add deprecated_type field to allow specifying an alias for component types. (#14718)
  • cmd/mdatagen: Generate entity-scoped MetricsBuilder API that enforces entity-metric associations at compile time (#14659)
  • cmd/mdatagen: Skip generating reaggregation config options for metrics that have no aggregatable attributes. (#14689)
  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

🧰 Bug fixes 🧰

  • cmd/builder: Add .exe to output binary names when building for Windows targets. (#12591)

  • exporter/debug: Add printing of metric metadata in detailed verbosity. (#14667)

  • exporter/otlp_grpc: Prevent nil pointer panic when push methods are called before the OTLP exporter initializes its gRPC clients. (#14663) When the sending queue and retry are disabled, calling ConsumeTraces, ConsumeMetrics, ConsumeLogs, or ConsumeProfiles before the OTLP exporter initializes its gRPC clients could cause a nil pointer dereference panic. The push methods now return an error instead of panicking.

  • exporter/otlp_http: Show the actual destination URL in error messages when request URL is modified by middleware. (#14673) Unwraps the *url.Error returned by http.Client.Do() to prevent misleading error logs when a middleware extension dynamically updates the endpoint.

  • pdata/pprofile: Switch the dictionary of dictionary tables entries only once when merging profiles (#14709) For dictionary table data, we used to switch their dictionaries when doing the switch for the data that uses them. However, when an entry is associated with multiple other data (several samples can use the same stack), we would have been switching the dictionaries of the entry multiple times.

    We now switch dictionaries for dictionary table data only once, before switching the resource profiles.

API Changelog

🛑 Breaking changes 🛑

  • cmd/mdatagen: Generate a per-metric config type <MetricName>Config for each metric when reaggregation_enabled: true (#14689) Metrics with aggregatable attributes get AggregationStrategy and EnabledAttributes []<MetricName>AttributeKey fields; others get Enabled only. Typed attribute key constants (e.g. DefaultMetricAttributeKeyStringAttr) replace []string, eliminating runtime attribute slice allocations. Validation errors now list valid attributes and strategies by name. Components using reaggregation_enabled: true will need to update references to MetricConfig.

  • pdata/pprofile: Update protoID for message Sample fields (#14652)

💡 Enhancements 💡

  • cmd/mdatagen: Extend mdatagen tool to generate go config structs for OpenTelemetry collector components. (#14561) The component config go code is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Extend mdatagen tool to generate config JSON schema for OpenTelemetry components. (#14543) The component config JSON schema is generated from config section of the metadata.yaml file.

  • cmd/mdatagen: Schema generation for mdatagen-controlled config parts (#14562) The schema is generated in separate yaml file and used to create full component schema.

  • pdata/pprofile: Implement reference based attributes in Profiles (#14546)

  • pkg/pdata: Upgrade the OTLP protobuf definitions to version 1.10.0 (#14766)

  • pkg/service: The internal status reporter no longer drops repeated Ok and RecoverableError statuses (#14282) Status events can now carry metadata and there's value in allowing them to be emitted despite the status value itself not changing.

  • pkg/xexporterhelper: Add logic to cleanup partitions from memory which are not being used for specific time period. (#14526)

  • pkg/xpdata: Add NewEntity constructor, Entity.CopyToResource, and EntityAttributeMap.All to pdata/xpdata/entity (#14659)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Preserve custom extensions (e.g., x-customType, x-pointer) during schema reference resolution. (#14713, #14565) Fixes an issue where custom properties defined locally on a node were overwritten and lost when resolving a $ref to an external/internal schema.

  • pkg/xexporterhelper: Fix race when partition is being removed from LRU and new items are being added at the same time. (#14526)
