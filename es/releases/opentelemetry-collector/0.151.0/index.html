opentelemetry-coleccionista v0.151.0

Imágenes y binarios aquí: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.151.0

Usuario final Changelog

🛑 Cambios importantes 🛑

  • cmd/builder: en la fuente del recopilador generada, las declaraciones replace en el módulo Go ahora usarán rutas relativas de forma predeterminada. (#15097) Esperamos que esto no interrumpa los casos de uso existentes en los que el recopilador generado solo se usa de manera provisional para compilaciones. Permite la posibilidad de rastrear el código de Collector generado como un artefacto de mayor duración, lo que permite ejecutarlo en cualquier máquina (mientras que las rutas absolutas serán diferentes dependiendo de la máquina en la que se genere la fuente de Collector). Hemos agregado dist::use_absolute_replace_paths para volver al comportamiento de ruta absoluta en el caso de que exista un caso de uso imprevisto que requiera rutas absolutas.
  • pkg/confighttp: Estabiliza la puerta de función Snappy enmarcada. (#15096)

💡 Mejoras 💡

  • all: agregue soporte de esquema declarativo para la configuración de recursos de telemetría del servicio. (#14411) La configuración service::telemetry::resource ahora acepta el esquema declarativo con pares de nombre/valor explícitos: 
    service:  telemetry:    resource:      schema_url: https://opentelemetry.io/schemas/1.38.0      attributes:        - name: service.name          value: my-collector        - name: host.name          value: collector-host
    El formato de mapa de atributos en línea heredado todavía se admite por compatibilidad con versiones anteriores: 
    service:  telemetry:    resource:      service.name: my-collector      host.name: collector-host
    Nota: resource.detectors se acepta para compatibilidad futura, pero el recopilador aún no lo aplica.
  • exporter/otlp_grpc: Se agregaron los atributos server.address y url.path a las métricas generadas por el exportador otlp. (#14998)
  • exporter/otlp_http: Se agregaron los atributos server.address y url.path a las métricas generadas por el exportador otlp_http. (#14998)
  • pkg/config/configgrpc: agregue el campo UserAgent a ClientConfig para permitir anular la cadena de usuario-agente predeterminada gRPC. (#14686) El exportador otlp gRPC estaba configurando incondicionalmente el User-Agent a través de grpc.WithUserAgent() en el momento de marcar, que tiene prioridad sobre la llamada metadatos, lo que hace que cualquier agente de usuario configurado por el usuario se descarte silenciosamente. Se ha añadido un campo dedicado UserAgent a ClientConfig que, cuando set, se usa en la opción de marcado directamente en lugar de la cadena derivada de BuildInfo predeterminada.
  • pkg/config/configgrpc: acepte los URI del esquema de resolución gRPC en el punto final client (por ejemplo, passthrough:///host:port) para permitir el control sobre la resolución de nombres (#14990) Después de la migración a grpc.NewClient, algunos componentes de gRPC client como el OTLP El exportador experimentó problemas de conexión en entornos DNS de doble pila. Esto ahora puede ser Se solucionó utilizando el esquema de resolución passthrough:/// gRPC en el campo del punto final.
  • pkg/config/confignet: se agregó soporte para el transporte de canalización con nombre de Windows (npipe) (#15085)
  • pkg/service: emite una advertencia al utilizar el antiguo formato de configuración declarativa v0.2.0 (#15088)

🧰 Corrección de errores 🧰

  • pkg/otelcol: imprime componentes exactamente una vez en el comando otelcol components (#14682) Esto resuelve un problema por el cual se omitían componentes con alias.
  • pkg/otelcol: sincroniza los ciclos de vida de ejecución y apagado del recopilador para que el apagado se bloquee hasta que la ejecución complete toda la limpieza. (#4947) El apagado ahora se bloquea hasta que Ejecutar finaliza la limpieza, coincidiendo con la semántica de http.Server. Si se llama a Apagar antes de Ejecutar, la siguiente llamada a Ejecutar devuelve cero después de la limpieza el proveedor de configuración.
  • pkg/pdata: utilice una representación de cadena compatible con las especificaciones para NaN, Infinity e -Infinity en Value.AsString(). (#14487)
  • pkg/pprofile: Se corrigió la corrupción de datos de los atributos de recursos y alcance después del viaje de ida y vuelta de mariscal-desmarshal-merge. (#15084)
  • pkg/service: Los atributos de recursos que no son cadenas en la configuración de telemetría ahora devuelven un error en lugar de entrar en pánico (#15171)
  • pkg/xscraperhelper: corrige la combinación de perfiles en los asistentes del raspador de perfiles (#14790)
  • receiver/otlp: Se corrigió que el receptor de perfiles informara sus muestras como intervalos (#15089)

La función anterior se mantiene como un contenedor obsoleto y se eliminará. en una versión futura.

  • cmd/mdatagen: agregue compatibilidad con override_value opcional para la configuración de atributos de recursos a través del indicador override_value_enabled (#15109) Los componentes pueden participar configurando override_value_enabled: true en sus metadatos.yaml. Cuando está habilitado, los tipos de configuración por atributo se generan con campos escritos override_value que permiten a los usuarios anular los valores de los atributos de recursos en la configuración del recopilador. Los componentes sin la bandera continúan usando el tipo ResourceAttributeConfig compartido.
  • cmd/mdatagen: Ampliar la generación de código de configuración de mdatagen para manejar correctamente los valores predeterminados para todas las referencias integradas (#14560)
  • cmd/mdatagen: Maneja validadores de cadenas en estructuras de configuración generadas (#14807) Los validadores compatibles incluyen minLength, maxLength y pattern.
  • pkg/config/configgrpc: agregue una constante DefaultBalancerName para el nombre del balanceador de carga predeterminado (#15139) Esto reemplaza la función BalancerName.
  • pkg/config/configgrpc: acepte los URI del esquema de resolución gRPC en el punto final client (por ejemplo, passthrough:///host:port) para permitir el control sobre la resolución de nombres (#14990) Después de la migración a grpc.NewClient, algunos componentes de gRPC client como OTLP El exportador experimentó problemas de conexión en entornos DNS de doble pila. Esto ahora puede ser Se solucionó utilizando el esquema de resolución passthrough:/// gRPC en el campo del punto final.
  • pkg/exporterhelper: se agregó la opción WithAttrs para permitir atributos personalizados en las métricas del exportador (#14998)

🧰 Corrección de errores 🧰

  • cmd/mdatagen: se corrigió un error en mdatagen donde el campo allOf no se manejaba adecuadamente, lo que resultaba en una generación incorrecta de modelos de datos. (#15153)
  • pkg/otelcol: sincroniza los ciclos de vida de ejecución y apagado del recopilador para que el apagado se bloquee hasta que la ejecución complete toda la limpieza. (#4947) El apagado ahora se bloquea hasta que Ejecutar finaliza la limpieza, coincidiendo con la semántica de http.Server. Si se llama a Apagar antes de Ejecutar, la siguiente llamada a Ejecutar devuelve cero después de la limpieza el proveedor de configuración.
  • pkg/pdata: use constructores que tengan en cuenta el grupo en los controladores de servicios gRPC para que las estructuras de solicitud de nivel superior participen en el ciclo de vida de sync.Pool. (#14763) Los manejadores de servicios gRPC para todos los tipos de señales asignaron el nivel superior ExportXxxServiceRequest con bare new(), omitiendo sync.Pool cuando pdata.useProtoPooling está habilitado. Esto provocó que los objetos regresaran a la piscina. a través de Eliminar para no recuperarse nunca. Los manejadores ahora usan el pool-aware Nuevos*() constructores.

opentelemetry-collector v0.151.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.151.0

End User Changelog

🛑 Breaking changes 🛑

  • cmd/builder: In the generated Collector source, the replace statements in the Go module will now use relative paths by default. (#15097) We expect that this will not break existing use-cases where the generated collector is only used in an interim manner for builds. It enables the possibility of tracking the generated Collector code as a longer living artifact, allowing it to be run on any machine (whereas absolute paths will be different depending on the machine the Collector source is generated on.) We have added dist::use_absolute_replace_paths to go back to the absolute path behaviour in the case where there is an unforeseen use-case that requires absolute paths.

  • pkg/confighttp: Stabilize framedSnappy feature gate. (#15096)

💡 Enhancements 💡

  • all: Add declarative schema support for service telemetry resource configuration. (#14411) The service::telemetry::resource configuration now accepts the declarative schema with explicit name/value pairs:

    service:
  telemetry:
    resource:
      schema_url: https://opentelemetry.io/schemas/1.38.0
      attributes:
        - name: service.name
          value: my-collector
        - name: host.name
          value: collector-host

    The legacy inline attribute map format is still supported for backward compatibility:

    service:
  telemetry:
    resource:
      service.name: my-collector
      host.name: collector-host

    Note: resource.detectors is accepted for forward compatibility but is not yet applied by the collector.

  • exporter/otlp_grpc: Added the server.address and url.path attributes to metrics generated by the otlp exporter. (#14998)

  • exporter/otlp_http: Added the server.address and url.path attributes to metrics generated by the otlp_http exporter. (#14998)

  • pkg/config/configgrpc: Add UserAgent field to ClientConfig to allow overriding the default gRPC user-agent string. (#14686) The otlp gRPC exporter was unconditionally setting the User-Agent via grpc.WithUserAgent() at dial time, which takes precedence over per-call metadata, causing any user-configured User-Agent to be silently discarded. A dedicated UserAgent field has been added to ClientConfig which, when set, is used in the dial option directly instead of the default BuildInfo-derived string.

  • pkg/config/configgrpc: Accept gRPC resolver scheme URIs in client endpoint (e.g. passthrough:///host:port) to allow control over name resolution (#14990) After the migration to grpc.NewClient, some gRPC client components such as the OTLP exporter experienced connection issues in dual-stack DNS environments. This can now be fixed by using the passthrough:/// gRPC resolver scheme in the endpoint field.

  • pkg/config/confignet: Add support for Windows Named Pipe (npipe) transport (#15085)

  • pkg/service: Emit a warning when using the old v0.2.0 declarative config format (#15088)

🧰 Bug fixes 🧰

  • pkg/otelcol: Print components exactly once in the otelcol components command (#14682) This resolves an issue where aliased components were skipped.

  • pkg/otelcol: Synchronize Collector Run and Shutdown lifecycles so that Shutdown blocks until Run completes all cleanup. (#4947) Shutdown now blocks until Run finishes cleanup, matching http.Server semantics. If Shutdown is called before Run, the next Run call returns nil after cleaning up the config provider.

  • pkg/pdata: Use spec-compliant string representation for NaN, Infinity, and -Infinity in Value.AsString(). (#14487)

  • pkg/pprofile: Fix data corruption of resource and scope attributes after marshal-unmarshal-merge round-trip. (#15084)

  • pkg/service: Non-string resource attributes in telemetry configuration now return an error instead of panicking (#15171)

  • pkg/xscraperhelper: fix the merge of profiles in the profiling scraper helpers (#14790)

  • receiver/otlp: Fix profiles receiver reporting its samples as spans (#15089)

API Changelog

🛑 Breaking changes 🛑

  • receiver/otlp: Config.Protocols is now a named field instead of an anonymous embedded field. (#15178) Access to cfg.GRPC and cfg.HTTP must be updated to cfg.Protocols.GRPC and cfg.Protocols.HTTP.

🚩 Deprecations 🚩

  • cmd/mdatagen: The DefaultMetricsBuilderConfig function is deprecated. Use NewDefaultMetricsBuilderConfig instead. (#15165) The generated DefaultMetricsBuilderConfig function has been renamed to NewDefaultMetricsBuilderConfig to follow Go naming conventions. The old function is kept as a deprecated wrapper and will be removed in a future release.

💡 Enhancements 💡

  • cmd/mdatagen: Handle default values for configuration fields in generated code in mdatagen. (#14560)

  • cmd/mdatagen: Add opt-in override_value support for resource_attributes config via override_value_enabled flag (#15109) Components can opt in by setting override_value_enabled: true in their metadata.yaml. When enabled, per-attribute config types are generated with typed override_value fields that let users override resource attribute values in the collector configuration. Components without the flag continue to use the shared ResourceAttributeConfig type.

  • cmd/mdatagen: Extend mdatagen config code generation to correctly handle default values for allOf embedded references (#14560)

  • cmd/mdatagen: Handle string validators in generated config structs (#14807) Supported validators include minLength, maxLength and pattern.

  • pkg/config/configgrpc: Add a DefaultBalancerName constant for the name of the default load balancer (#15139) This replaces the BalancerName function.

  • pkg/config/configgrpc: Accept gRPC resolver scheme URIs in client endpoint (e.g. passthrough:///host:port) to allow control over name resolution (#14990) After the migration to grpc.NewClient, some gRPC client components such as the OTLP exporter experienced connection issues in dual-stack DNS environments. This can now be fixed by using the passthrough:/// gRPC resolver scheme in the endpoint field.

  • pkg/exporterhelper: Added the WithAttrs option to allow custom attributes on exporter metrics (#14998)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix a bug in mdatagen where the allOf field was not being properly handled, resulting in incorrect generation of data models. (#15153)

  • pkg/otelcol: Synchronize Collector Run and Shutdown lifecycles so that Shutdown blocks until Run completes all cleanup. (#4947) Shutdown now blocks until Run finishes cleanup, matching http.Server semantics. If Shutdown is called before Run, the next Run call returns nil after cleaning up the config provider.

  • pkg/pdata: Use pool-aware constructors in gRPC service handlers so top-level request structs participate in the sync.Pool lifecycle. (#14763) The gRPC service handlers for all signal types allocated the top-level ExportXxxServiceRequest with bare new(), bypassing the sync.Pool when pdata.useProtoPooling is enabled. This caused objects returned to the pool via Delete to never be retrieved. The handlers now use the pool-aware New*() constructors.
