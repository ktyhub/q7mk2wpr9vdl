opentelemetry-coleccionista v0.165.0

Imágenes y binarios aquí: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

Usuario final Changelog

🛑 Cambios importantes 🛑

  • pkg/confighttp: Elimina los campos obsoletos IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives. (#15973)

🚀 Nuevos componentes 🚀

  • pkg/xreceiverhelper: agregue xreceiverhelper con un ObsReport que informa métricas de muestra de perfil por tipo de muestra. (#16251) ObsReport.EndProfilesOpBySampleType registra el Métricas otelcol_receiver_{accepted,refused,failed}_profile_samples con un adicional Atributo sample_type, formateado como "tipo: unidad", ya que una sola carga útil puede contener múltiples perfiles con diferentes tipos de muestra. Utilice ProfileSampleCountsByType para calcular los recuentos de muestras antes los perfiles se pasan al siguiente consumidor, ya que los datos pueden sufrir modificaciones posteriores. El receptor OTLP ahora usa EndProfilesOpBySampleType.

💡 Mejoras 💡

  • pkg/configmiddleware: permite anular el marcador utilizado por confighttp.ToClient y configgrpc.ToClient (#16019)
  • pkg/featuregate: permite guiones bajos en los ID de puertas de funciones. (#16243)
  • pkg/pdata: mejora el rendimiento de las funciones pcommon.Map Get, Range y All. (#16282, #16321)
  • pkg/pdata: Reduce el número de asignaciones al actualizar una de las primitivas (#16226)
  • pkg/service: el servicio ahora admite la configuración de detectores de recursos adicionales para telemetría interna según la actualización de otelconf v0.26.0. (#15869)
  • pkg/service: advierte al inicio cuando una canalización combina el procesador por lotes con el procesamiento por lotes de Exporterhelper. (#15965) La detección no cruza conectores ni inspecciona envoltorios de exportadores que ocultan la capacidad de procesamiento por lotes de exportadorhelper.
  • pkg/xprocessorhelper: Instrumento xprocessorhelper.NewProfiles con otelcol_processor_incoming_items, otelcol_processor_outgoing_items y otelcol_processor_internal_duration, consistente con los demás constructores de señales. (#15523)
  • processor/memory_limiter: agregue la sección de configuración garbage_collector para permitir deshabilitar la recolección de basura forzada a través del campo enabled. (#15081)
  • processor/queue_batch: promueve el procesador queue_batch a beta para seguimientos, métricas y registros, y a alfa para perfiles. (#12022)
  • processor/queue_batch: Informe de métricas de cola y lotes como métricas de procesador (#14038)

🧰 Corrección de errores 🧰

  • cmd/mdatagen: Se solucionó el pánico en Attribute.TestValue() y Attribute.TestValueTwo() al manejar atributos de enumeración vacíos o de un solo elemento. (#15644)
  • cmd/mdatagen: Se corrigieron las pruebas de métricas generadas que fallaban cuando las puertas de funciones through_gates de una migración de métricas se promocionaban más allá de alfa. (#16249) Las pruebas generadas ahora establecen explícitamente las puertas de la función de migración para cada caso de prueba y restauración. su estado anterior durante la limpieza, en lugar de asumir que las puertas están deshabilitadas de forma predeterminada. Cuando la etapa de una puerta prohíbe el estado que necesita un caso, como deshabilitar una puerta estable, el generador de métricas La prueba omite sólo el recuento dependiente de la puerta y las aserciones de advertencia, y la métrica versionada por combinación. Se omiten las subpruebas para esa combinación.
  • cmd/mdatagen: genera documentos de configuración LÉAME para las definiciones de exported_configs. (#16164) Las definiciones de objetos y los alias de tipos escalares en exported_configs ahora se representan en el archivo README después de la tabla config:. Los paquetes que solo declaran exported_configs ahora pueden generar documentos una vez que su archivo README contenga los marcadores de configuración. Los componentes que solo declaran exported_configs ya no obtienen una tabla de configuración vacía.
  • cmd/schemagen: Maneja errores de archivo no encontrado al cargar esquemas (#15925)
  • pkg/configgrpc: limita la ventana del decodificador zstd por el tamaño máximo de mensaje de recepción configurado en lugar del valor predeterminado de la biblioteca. (#16280) Un marco zstd declara su ventana en el encabezado y el decodificador la asignó antes de producir cualquier resultado, por lo que un pequeño mensaje elaborado podría generar una gran asignación independientemente de max_recv_msg_size_mib. El decodificador también es regresa a su grupo tan pronto como gRPC termina con un mensaje.
  • pkg/confighttp: enlaza la ventana del decodificador zstd con max_request_body_size en lugar del valor predeterminado de la biblioteca. (#16280) Un marco zstd declara su ventana en el encabezado y el decodificador la asignó antes de producir cualquier resultado, por lo que un cuerpo pequeño y elaborado podría impulsar una gran asignación independientemente del tamaño del cuerpo de la solicitud configurado.
  • pkg/confighttp: Aceptar codificación de contenido: identidad como equivalente a no codificar. (#15122)
  • pkg/exporterhelper: Se solucionó un pánico de Cannot unref freed data cuando una cola de envío persistente reenvía solicitudes a otra canalización (#15256)
  • pkg/exporterhelper: Con wait_for_result, cancelar una solicitud que la cola de envío ya aceptó ya no regresa antes de tiempo (#16255) Anteriormente, un contexto cancelado hacía que regresara context.Canceled mientras la solicitud aún estaba entregado, para que las personas que llaman pudieran informar una falla en los datos que se habían enviado. Cancelar todavía tarda efecto mientras no se haya hecho nada con la solicitud.
  • pkg/pdata: agregue un límite de profundidad de recursividad (100) para protodesordenar AnyValue, ArrayValue, KeyValueList y KeyValue para evitar el desbordamiento de la pila debido a cargas útiles profundamente anidadas diseñadas con fines malintencionados. (#15301)
  • pkg/service: omita los nodos del gráfico que no se hayan creado durante el apagado para evitar el pánico cuando una recarga parcial del receptor no logra construir un receptor. (#16261)

opentelemetry-collector v0.165.0

Images and binaries here: https://github.com/open-telemetry/opentelemetry-collector-releases/releases/tag/v0.165.0

End User Changelog

🛑 Breaking changes 🛑

  • pkg/confighttp: Remove deprecated fields IdleConnTimeout, MaxIdleConns, MaxIdleConnsPerHost, DisableKeepAlives. (#15973)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types. Use ProfileSampleCountsByType to compute the sample counts before the profiles are passed to the next consumer, as the data may be mutated downstream. The OTLP receiver now uses EndProfilesOpBySampleType.

💡 Enhancements 💡

  • pkg/configmiddleware: allow to override the dialer used by confighttp.ToClient and configgrpc.ToClient (#16019)
  • pkg/featuregate: Allow underscores in feature gate IDs. (#16243)
  • pkg/pdata: Improve performance of pcommon.Map Get, Range, and All functions. (#16282, #16321)
  • pkg/pdata: Reduce number of allocations when updating an oneof primitive (#16226)
  • pkg/service: Service now supports configuring additional resource detectors for internal telemetry as per the update to otelconf v0.26.0. (#15869)
  • pkg/service: Warn at startup when a pipeline combines the batch processor with exporterhelper batching. (#15965) Detection does not cross connectors or inspect exporter wrappers that hide exporterhelper's batching capability.
  • pkg/xprocessorhelper: Instrument xprocessorhelper.NewProfiles with otelcol_processor_incoming_items, otelcol_processor_outgoing_items, and otelcol_processor_internal_duration, consistent with the other signal constructors. (#15523)
  • processor/memory_limiter: Add garbage_collector config section to allow disabling forced garbage collection via enabled field. (#15081)
  • processor/queue_batch: Promote the queue_batch processor to beta for traces, metrics, and logs, and to alpha for profiles. (#12022)
  • processor/queue_batch: Report queue and batch metrics as processor metrics (#14038)

🧰 Bug fixes 🧰

  • cmd/mdatagen: Fix panic in Attribute.TestValue() and Attribute.TestValueTwo() when handling single-element or empty enum attributes. (#15644)

  • cmd/mdatagen: Fix generated metrics tests failing when a metric migration's through_gates feature gates are promoted past alpha. (#16249) The generated tests now explicitly set the migration feature gates for each test case and restore their previous state on cleanup, instead of assuming the gates are disabled by default. When a gate's stage forbids the state a case needs, such as disabling a stable gate, the metrics-builder test skips only its gate-dependent count and warning assertions, and the per-combination versioned-metric sub-tests for that combination are skipped.

  • cmd/mdatagen: Generate README configuration docs for exported_configs definitions. (#16164) Object definitions and scalar type aliases under exported_configs are now rendered in the README after the config: table. Packages that only declare exported_configs can now get generated docs once their README contains the config markers. Components that only declare exported_configs no longer get an empty configuration table.

  • cmd/schemagen: Handle file-not-found errors when loading schemas (#15925)

  • pkg/configgrpc: Bound the zstd decoder window by the configured maximum receive message size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted message could drive a large allocation regardless of max_recv_msg_size_mib. The decoder is also returned to its pool as soon as gRPC is done with a message.

  • pkg/confighttp: Bound the zstd decoder window by max_request_body_size instead of the library default. (#16280) A zstd frame declares its window in the header and the decoder allocated it before producing any output, so a small crafted body could drive a large allocation regardless of the configured request body size.

  • pkg/confighttp: Accept Content-Encoding: identity as equivalent to no encoding. (#15122)

  • pkg/exporterhelper: Fix a Cannot unref freed data panic when a persistent sending queue forwards requests into another pipeline (#15256)

  • pkg/exporterhelper: With wait_for_result, canceling a request that the sending queue already accepted no longer returns early (#16255) Previously a canceled context made it return context.Canceled while the request was still delivered, so callers could report a failure for data that had been sent. Canceling still takes effect while nothing has been done with the request.

  • pkg/pdata: Add recursion depth limit (100) to proto unmarshalling of AnyValue, ArrayValue, KeyValueList, and KeyValue to prevent stack overflow from maliciously crafted deeply nested payloads. (#15301)

  • pkg/service: Skip graph nodes that have not been built during shutdown to prevent a panic when a partial receiver reload fails to build a receiver. (#16261)

API Changelog

🚩 Deprecations 🚩

  • pkg/componentstatus: Deprecate componentstatus.Watcher in favour of extensioncapabilities.ComponentStatusWatcher (#16304)

🚀 New components 🚀

  • pkg/xreceiverhelper: Add xreceiverhelper with an ObsReport that reports profile sample metrics per sample type. (#16251) ObsReport.EndProfilesOpBySampleType records the otelcol_receiver_{accepted,refused,failed}_profile_samples metrics with an additional sample_type attribute, formatted as "type:unit", as a single payload can hold multiple profiles with different sample types. Use ProfileSampleCountsByType to compute the sample counts before the profiles are passed to the next consumer, as the data may be mutated downstream.
