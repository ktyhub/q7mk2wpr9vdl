MaxKB v1.10.2-lts

Highlights

  • API apps gain file and reasoning support — Applications invoked through the API Key can now accept uploaded file parameters (#2300) and surface the model's thinking/reasoning process, including in the OpenAI-compatible call format (#2392). If you integrate MaxKB apps externally, this closes two long-standing gaps: no more proxying files out-of-band, and reasoning models such as DeepSeek-R1 now expose their thought stream through the API instead of only in the web UI.

  • Workflow builder gets state and safer editing — A new variable assignment node (#2346) gives workflows mutable state across nodes, and blank applications can be scaffolded from scratch (#2377). User-input parameters gain password/switch widgets and custom titles (#2307, #2313), judgment conditions can parse variables (#2311), and the editor now warns before discarding unsaved work (#2312). Watch for the node-rename flow moving to "..." → Rename (#2432) and the raised 10,000 reference-segment ceiling (#2487), which materially changes recall-heavy RAG designs.

  • Provider fixes worth retesting against — Several model integrations had silent correctness bugs: Ollama's num_ctx triggered dialogue errors (#2444, with supplier-side model reordering now supported), vLLM replies could fail to terminate (#2375), Kimi token counts were inaccurate (#2326), and adding DeepSeek-R1 to Azure OpenAI (#2483) or full-modal Bailian models (#2302) errored out. If you pinned any of these providers, upgrade before trusting token metrics or long-running streams.

  • Function library becomes portable — Functions can now be imported and exported (#2294), so definitions move between environments instead of being rebuilt by hand. Lookups are also case-insensitive across functions, models, and team members (#2279) — a quiet change that eliminates "not found" failures in scripts with inconsistent casing.

  • Knowledge base and RAG pipeline upgrades — Failed question-generation segments can be retried (#2299), generated questions can interpolate the segment {title} variable (#2310), and document lists are sortable (#2284). Together with the 10,000-segment cap (#2487), this targets larger, more maintainable knowledge bases — but retrying question generation on previously failed segments is a manual follow-up for existing bases.

  • Q&A fixes with data-loss implications — The chat layout flips to AI-left/questions-right (#2258) and sessions can be renamed (#2348), but the consequential changes are fixes: refreshing after the first question in a new conversation no longer deletes it (#2428), Excel sources with merged cells no longer drop data (#2265), and non-mandatory child-node parameters no longer throw at runtime (#2278). X-Pack adopters also gain Slack as an access channel, OIDC scope configuration, and WeChat Work image uploads.

No breaking changes reported in this release.
