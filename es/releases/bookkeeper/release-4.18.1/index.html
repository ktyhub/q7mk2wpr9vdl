##4.18.1

La versión 4.18.1 incluye algunos client API nuevos, varias mejoras de rendimiento, correcciones de errores y actualizaciones de dependencias.

Se recomienda a los usuarios de Apache BookKeeper que actualicen a 4.18.1 si están utilizando 4.18.x. Los detalles técnicos de esta versión se resumen a continuación.

Características

  • Fijar las devoluciones de llamada de un libro mayor a un hilo de trabajo elegido por la persona que llama a través de withOrderingKey PR #4881
  • Agregue OpenBuilder.withKeepUpdateMetadata y DeleteBuilder.withLoggerContext al constructor API PR #4834

Mejoras

  • Agregue SingleThreadExecutor.executeOrRun y emita lecturas en línea desde el propio hilo del libro mayor PR #4883
  • Evite el boxeo por suma de comprobación en Java9IntHash utilizando MethodHandle.invokeExact PR #4876
  • Utilice colas de drenaje por lotes en SingleThreadExecutor PR #4836
  • Omitir el ciclo de seguimiento de descarga del diario cuando el registro de depuración está deshabilitado PR #4835
  • Escriba el prefijo de longitud de la entrada del diario y la carga útil en una única escritura de BufferedChannel PR #4833
  • Utilice ThreadLocalRandom para la selección de subprocesos en OrderedExecutor PR #4832
  • Agregar sugerencia de espera y giro a los bucles ocupados del lado del productor BlockingMpscQueue PR #4831

Errores

  • Revertir "Se corrigió el bloqueo de subprocesos de lectura en sendResponseAndWait que causaba un pico de latencia en READ_ENTRY_REQUEST p99 (#4730)" PR #4830
  • Evitar fugas de subprocesos cuando falla el constructor BookKeeper client PR #4798

Actualizaciones de dependencia

  • Cambie Jetty a 12.1.10 y corrija los metadatos de la licencia binaria PR #4871
  • Bump org.apache.thrift:libthrift de 0.23.0 a 0.24.0 PR #4874
  • Saltar en.yawk.lz4:lz4-java de 1.10.2 a 1.11.1 PR #4869
  • Pasar bytes de 1.5.0 a 1.11.1 en el módulo Rust nativo-io PR #4747

bookkeeper release-4.18.1

Highlights

  • New client controls — withOrderingKey now pins ledger callbacks to a caller-chosen worker thread, while OpenBuilder.withKeepUpdateMetadata and DeleteBuilder.withLoggerContext add opt-in builder controls. Existing callers need no changes; adopt these where callback placement, metadata handling, or logger context matters.

  • Lower scheduling and I/O overhead — SingleThreadExecutor.executeOrRun, inline reads from the ledger thread, and batch queue draining reduce executor hand-offs. Writing journal length prefixes and payloads in one BufferedChannel write also reduces journal overhead, benefiting latency- and throughput-sensitive deployments.

  • Reduced allocation and CPU work — Java9IntHash avoids per-checksum boxing with MethodHandle.invokeExact, disabled debug logging skips the journal flush-trace loop, OrderedExecutor uses ThreadLocalRandom, and BlockingMpscQueue busy loops add spin-wait hints. The checksum change is particularly relevant to checksum-heavy workloads.

  • Thread-leak fix and reverted latency fix — Failed BookKeeper client construction no longer leaks a thread, which matters for retry-heavy startup paths. However, PR #4830 reverts the #4730 fix for READ_ENTRY_REQUEST p99 latency, restoring earlier behavior; affected deployments should re-benchmark rather than assume read latency improves.

  • Dependencies and upgrade advice — Jetty moves to 12.1.10, org.apache.thrift:libthrift to 0.24.0, at.yawk.lz4:lz4-java to 1.11.1, and the native-io Rust module’s bytes to 1.11.1. No breaking API changes or mandatory migrations are listed. BookKeeper recommends this release for 4.18.x users; the leak fix and performance work justify upgrading, while stable deployments can defer if they do not need them and want to avoid revalidating dependency integrations.

4.18.1

Release 4.18.1 includes a few new client APIs, several performance improvements, bug fixes and dependency updates.

Apache BookKeeper users are encouraged to upgrade to 4.18.1 if you are using 4.18.x. The technical details of this release are summarized below.

Features

  • Pin a ledger's callbacks to a caller-chosen worker thread via withOrderingKey PR #4881
  • Add OpenBuilder.withKeepUpdateMetadata and DeleteBuilder.withLoggerContext to the builder API PR #4834

Improvements

  • Add SingleThreadExecutor.executeOrRun and issue reads inline from the ledger's own thread PR #4883
  • Avoid per-checksum boxing in Java9IntHash by using MethodHandle.invokeExact PR #4876
  • Use batch-draining queues in SingleThreadExecutor PR #4836
  • Skip journal flush-trace loop when debug logging is disabled PR #4835
  • Write journal entry length prefix and payload in a single BufferedChannel write PR #4833
  • Use ThreadLocalRandom for thread selection in OrderedExecutor PR #4832
  • Add spin-wait hint to BlockingMpscQueue producer-side busy loops PR #4831

Bugs

  • Revert "Fix read thread blocking in sendResponseAndWait causing READ_ENTRY_REQUEST p99 latency spike (#4730)" PR #4830
  • Prevent thread leak when BookKeeper client constructor fails PR #4798

Dependency updates

  • Bump Jetty to 12.1.10 and fix binary license metadata PR #4871
  • Bump org.apache.thrift:libthrift from 0.23.0 to 0.24.0 PR #4874
  • Bump at.yawk.lz4:lz4-java from 1.10.2 to 1.11.1 PR #4869
  • Bump bytes from 1.5.0 to 1.11.1 in native-io Rust module PR #4747
