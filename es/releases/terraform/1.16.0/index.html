terraforma v1.16.0

1.16.0 (26 de agosto de 2026)

NUEVAS CARACTERÍSTICAS:

  • Terraform ahora almacena datos privados planificados para los proveedores, lo que permite conservar el estado específico del proveedor en todo el plan y la solicitud. (#37986)
  • terraform_data: El nuevo bloque store puede contener valores efímeros y sensibles en todo el plan y la aplicación. (#38298)
  • Los proveedores ahora pueden usar bloques anidados como valores calculados (#38305)
  • importar: ahora se admiten bloques import dentro de los módulos. (#38352)
  • Terraform ahora está disponible como un binario prediseñado para Linux s390x (zLinux). (#38384)
  • Los activadores de acciones de recursos ahora pueden usar los modos on_failure de halt, taint o continue. (#38722) MEJORAS:
  • state show: el comando state show ahora puede producir una salida legible por máquina cuando se suministra con el indicador -json (#23940)
  • espacio de trabajo: el comando workspace list ahora puede producir resultados legibles por máquina cuando se suministra con el indicador -json (#38397)
  • prueba: Terraform ahora informa qué recursos quedaron atrás cuando se configura skip_cleanup. (#38449)
  • pilas: las configuraciones de acción ahora tienen acceso a un símbolo caller que contiene el valor del objeto del recurso que llama. (#38668)
  • Las acciones ahora pueden usar eventos before_destroy y after_destroy. (#38668)
  • nube: Terraform ahora muestra un resumen de los resultados de la evaluación de políticas para las ejecuciones plan y apply contra HCP Terraform. (#38715)
  • política: Terraform ahora resuelve las credenciales del complemento de política desde la nube configurada o el backend remoto durante init, plan y apply, en lugar de requerir que el complemento lea las credenciales por sí mismo. (#38716)
  • gráfico: el comando terraform graph ahora puede generar gráficos en formato Mermaid usando la bandera -format=mermaid. (#38719)
  • Las salidas del módulo secundario con atributos anidados obsoletos sin referencia ya no devuelven advertencias de obsolescencia. (#38778)
  • Los bloques de recursos lifecycle ahora admiten destroy = false para evitar que se destruya un recurso. (#38784)
  • La función contains() ahora puede probar los valores de null. (#38792)
  • consola: el comando terraform console ahora acepta un indicador -scope=<module address> opcional, que se puede usar para evaluar expresiones dentro del alcance de un módulo o una instancia de módulo específica. (#31861)
  • -invoke ahora se puede combinar con -target para especificar la instancia del recurso de llamada cuando varios recursos desencadenan la misma acción. (#38845)
  • El comando terraform stacks ahora infiere automáticamente el nombre del host de destino del archivo de credenciales local (credentials.tfrc.json) cuando no están configurados ni TF_STACKS_HOSTNAME ni TF_CLOUD_HOSTNAME (#38896) CORRECCIÓN DE ERRORES:
  • Los bloques import ahora respetan correctamente los nombres locales de los proveedores. (#38338)
  • terraform apply ya no entra en pánico cuando el plan contiene un cambio no operativo para un recurso depuesto que tiene bloques lifecycle.precondition o lifecycle.postcondition. (#38586)
  • espacio de trabajo: Terraform ahora genera un error si se selecciona un nombre de espacio de trabajo no válido debido a cambios fuera de banda. (#38594)
  • prueba: Terraform ahora genera una advertencia cuando un archivo al que se hace referencia mediante el indicador -filter no existe. (#38603)
  • init: Terraform ya no elimina bloqueos del archivo de bloqueo de dependencia para proveedores configurados como dev_override. (#38634)
  • init: Terraform ahora advierte cuando se están utilizando proveedores no administrados y puede afectar la instalación del proveedor. (#38656)
  • Las acciones ahora se invocan con respecto a todas las dependencias de recursos. (#38668)
  • Terraform ahora devuelve el error correcto cuando existe un objetivo import en estado pero no tiene la configuración correspondiente. (#38782)
  • La función merge() ya no entra en pánico cuando se pasan objetos null. (#38792)
  • Permitir guiones bajos en los espacios de nombres de direcciones de origen de proveedores, de modo que las direcciones de proveedores de registros privados ya no se rechacen como inválidas (#38894)
  • prueba: los valores efímeros opcionales no tienen que establecerse en el momento del plan (#38974) NOTAS:
  • init: Los errores debidos a indicadores -upgrade y -lockfile=readonly incompatibles ahora se generan en una etapa más temprana del proceso de inicio. (#38561) NOTAS DE ACTUALIZACIÓN:
  • Los aprovisionadores ahora aplican correctamente bastion_host_key. Revise las configuraciones de su aprovisionador para verificar que la clave configurada sea correcta antes de actualizar. (#38318)

terraform v1.16.0

1.16.0 (August 26, 2026)

NEW FEATURES:

  • Terraform now stores planned private data for providers, allowing provider-specific state to be preserved across plan and apply. (#37986)

  • terraform_data: The new store block can hold ephemeral and sensitive values across plan and apply. (#38298)

  • Providers can now use nested blocks as computed values (#38305)

  • import: import blocks inside modules are now supported. (#38352)

  • Terraform is now available as a pre-built binary for Linux s390x (zLinux). (#38384)

  • Resource action triggers can now use on_failure modes of halt, taint, or continue. (#38722)

ENHANCEMENTS:

  • state show: The state show command can now produce machine-readable output when supplied with the -json flag (#23940)

  • workspace: The workspace list command can now produce machine-readable output when supplied with the -json flag (#38397)

  • test: Terraform now reports which resources were left behind when skip_cleanup is set. (#38449)

  • stacks: Action configurations now have access to a caller symbol containing the object value of the calling resource. (#38668)

  • Actions can now use before_destroy and after_destroy events. (#38668)

  • cloud: Terraform now displays a summary of policy evaluation outcomes for plan and apply runs against HCP Terraform. (#38715)

  • policy: Terraform now resolves policy plugin credentials from the configured cloud or remote backend during init, plan, and apply, rather than requiring the plugin to read credentials itself. (#38716)

  • graph: The terraform graph command can now output graphs in Mermaid format using the -format=mermaid flag. (#38719)

  • Child module outputs with unreferenced deprecated nested attributes no longer return deprecation warnings. (#38778)

  • Resource lifecycle blocks now support destroy = false to prevent a resource from being destroyed. (#38784)

  • The contains() function can now test for null values. (#38792)

  • console: The terraform console command now accepts an optional -scope=<module address> flag, which can be used to evaluate expressions within the scope of a module or a specific module instance. (#31861)

  • -invoke can now be combined with -target to specify the calling resource instance when multiple resources trigger the same action. (#38845)

  • The terraform stacks command now automatically infers the target hostname from the local credentials file (credentials.tfrc.json) when neither TF_STACKS_HOSTNAME nor TF_CLOUD_HOSTNAME is set (#38896)

BUG FIXES:

  • import blocks now correctly respect provider local names. (#38338)

  • terraform apply no longer panics when the plan contains a no-op change for a deposed resource that has lifecycle.precondition or lifecycle.postcondition blocks. (#38586)

  • workspace: Terraform now raises an error if an invalid workspace name becomes selected due to out-of-band changes. (#38594)

  • test: Terraform now raises a warning when a file referenced via the -filter flag does not exist. (#38603)

  • init: Terraform no longer removes locks from the dependency lock file for providers configured as dev_override. (#38634)

  • init: Terraform now warns when unmanaged providers are in use and may impact provider installation. (#38656)

  • Actions are now invoked with respect to all resource dependencies. (#38668)

  • Terraform now returns the correct error when an import target exists in state but has no corresponding configuration. (#38782)

  • The merge() function no longer panics when passed null objects. (#38792)

  • Allow underscores in provider source address namespaces, so private registry provider addresses are no longer rejected as invalid (#38894)

  • test: Optional ephemeral values do not have to be set at plan time (#38974)

NOTES:

  • init: Errors due to incompatible -upgrade and -lockfile=readonly flags are now raised earlier in the init process. (#38561)

UPGRADE NOTES:

  • bastion_host_key is now correctly applied by provisioners. Review your provisioner configurations to verify the configured key is correct before upgrading. (#38318)
