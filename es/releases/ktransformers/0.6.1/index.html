ktransformadores v0.6.1

KTransformers v0.6.1 es una refactorización completa y una importante actualización de la ruta de ajuste fino de KT existente para LoRA SFT de gran MoE. Esta versión reconstruye el backend de KT SFT en torno a kt-kernel, empaqueta la pila SFT detrás de la entrada ktransformers[sft] y mantiene la entrada de capacitación de LLaMA-Factory y el flujo de trabajo de YAML familiares para los usuarios. En entornos de referencia medidos, KT SFT alcanza un rendimiento de entrenamiento 6-12x en comparación con la línea base de ZeRO-Offload. Por otra parte, el uso de la memoria de la CPU se reduce a aproximadamente 1/2 en comparación con la ruta KT SFT anterior, con una menor presión de memoria de la GPU en el mismo contexto de referencia. Estos resultados están vinculados a la configuración de referencia y deben leerse junto con el modelo, el hardware, la longitud del contexto, la configuración de LoRA y los detalles de referencia.

🚀 Aspectos destacados principales

  • Backend SFT de MoE grande refactorizado: reconstruyó la ruta KT SFT alrededor de los kernels AMX MoE con soporte LoRA, incluidos los kernels AMX específicos de SFT, pruebas de adición fusionadas LoRA, pruebas de reempaquetado, envoltorios SFT Python, integración de autograduación, definiciones de capas y ayudantes de peso (#1936).
  • Pila SFT instalable por Pip: ktransformers[sft] ahora instala la pila KT SFT a través de paquetes Python normales: ktransformers, kt-kernel, transformers-kt y accelerate-kt.
  • Integración del flujo de trabajo de LLaMA-Factory: KT SFT está diseñado para usarse después de instalar LLaMA-Factory, preservando al mismo tiempo el flujo de trabajo estándar accelerate launch / src/train.py / YAML. Relaciones públicas complementarias de LLaMA-Factory: hiyouga/LLaMA-Factory#10430.
  • Límite del paquete más limpio: el antiguo paquete kt-sft ha sido archivado; SFT ahora usa ktransformers[sft], mientras que la inferencia KT usa kt-kernel + sglang-kt (#1954, #1955).
  • Línea de base actual de la antorcha: los metadatos del paquete y la ruta de instalación pública validada están alineados en torch==2.9.1, con torchaudio==2.9.1 y torchvision==0.24.1 para la configuración actual de pila completa.

📌 Modelos, hardware y herramientas

SFT y embalaje

  • Prepare el paquete de ruedas v0.6.1 SFT en main, incluidas las actualizaciones de paquetes de ktransformers[sft], kt-kernel, actualizaciones de flujo de trabajo de lanzamiento y una cuña de paquete liviana de nivel superior (#1945).
  • Alinear kt-kernel y los metadatos del paquete relacionados con la línea base de dependencia de la versión actual (#1948).
  • Aplane la cuña del paquete ktransformers para obtener un embalaje de rueda más limpio (#1955).
  • Archive el paquete heredado kt-sft en archive/kt-sft/ para que sea más fácil razonar sobre el diseño del paquete activo (#1954).

Mejoras en el kernel y el hardware

  • Agregue soporte de respaldo AVX512F+BW para FP8 y BF16 en el backend de AMX, mejorando la cobertura de respaldo de CPU donde las rutas específicas de AMX no están disponibles (#1908).
  • Agregue soporte VNNI-256 para GPTQ INT4 MoE, incluida una nueva ruta gptq_int4_avxvnni y cobertura de prueba de precisión por confirmación (#1926).
  • Agregue kernels AMX MoE específicos de SFT, ayudantes SFT MoE paralelos a tensores, pruebas de kernel LoRA, pruebas de reempaquetado y envoltorios de módulos SFT Python (#1936).

Integración de inferencia y tiempo de ejecución

  • Actualice el flujo de trabajo de lanzamiento de SGLang-KT para utilizar un ejecutor alojado, evitando el bloqueo de lanzamiento en ejecutores autohospedados no disponibles.

Habilitación del modelo

📦 Instalación

KT SFT con LLaMA-Factory

Utilice una caja de LLaMA-Factory que contenga los ejemplos de KT y requirements/ktransformers.txt.

cd /path/to/LLaMA-Factory
pip install -e .
pip install -r requirements/ktransformers.txt

Para la instalación directa del paquete fuera de ese archivo de requisitos:

pip install "ktransformers[sft]"

Inferencia KT

La inferencia KT utiliza la ruta SGLang-KT:

pip install kt-kernel sglang-kt

Mantenga kt-kernel en la ruta de instalación de inferencia. LLaMA-Factory SFT sigue utilizando ktransformers[sft].

ktransformers v0.6.1

KTransformers v0.6.1 is a full refactor and major upgrade of the existing KT fine-tuning path for large-MoE LoRA SFT. This release rebuilds the KT SFT backend around kt-kernel, packages the SFT stack behind the ktransformers[sft] entry, and keeps the LLaMA-Factory training entry and YAML workflow familiar for users.

In measured benchmark settings, KT SFT reaches 6-12x training performance compared with the ZeRO-Offload baseline. Separately, CPU memory usage is reduced to about 1/2 compared with the previous KT SFT path, with lower GPU memory pressure in the same benchmark context. These results are tied to the benchmark setup and should be read together with the model, hardware, context length, LoRA config, and baseline details.

🚀 Core Highlights

  • Refactored large-MoE SFT backend: rebuilt the KT SFT path around AMX MoE kernels with LoRA support, including SFT-specific AMX kernels, LoRA fused add tests, repacking tests, Python SFT wrappers, autograd integration, layer definitions, and weight helpers (#1936).
  • Pip-installable SFT stack: ktransformers[sft] now installs the KT SFT stack through regular Python packages: ktransformers, kt-kernel, transformers-kt, and accelerate-kt.
  • LLaMA-Factory workflow integration: KT SFT is designed to be used after installing LLaMA-Factory, while preserving the standard accelerate launch / src/train.py / YAML workflow. Companion LLaMA-Factory PR: hiyouga/LLaMA-Factory#10430.
  • Cleaner package boundary: the old kt-sft package has been archived; SFT now uses ktransformers[sft], while KT inference uses kt-kernel + sglang-kt (#1954, #1955).
  • Current torch baseline: package metadata and the validated public install path are aligned on torch==2.9.1, with torchaudio==2.9.1 and torchvision==0.24.1 for the current full-stack setup.

📌 Models, Hardware & Tooling

SFT and Packaging

  • Prepare v0.6.1 SFT wheel packaging on main, including ktransformers[sft], kt-kernel packaging updates, release workflow updates, and a lightweight top-level package shim (#1945).
  • Align kt-kernel and related package metadata with the current release dependency baseline (#1948).
  • Flatten the ktransformers package shim for cleaner wheel packaging (#1955).
  • Archive the legacy kt-sft package under archive/kt-sft/ so the active package layout is easier to reason about (#1954).

Kernel and Hardware Improvements

  • Add AVX512F+BW fallback support for FP8 and BF16 under the AMX backend, improving CPU fallback coverage where AMX-specific paths are unavailable (#1908).
  • Add VNNI-256 support for GPTQ INT4 MoE, including a new gptq_int4_avxvnni path and per-commit accuracy test coverage (#1926).
  • Add SFT-specific AMX MoE kernels, tensor-parallel MoE SFT helpers, LoRA kernel tests, repacking tests, and Python SFT module wrappers (#1936).

Inference and Runtime Integration

  • Sync the bundled sglang submodule for KT layerwise prefill updates and later packaging fixes (#1920).
  • Update SGLang-KT release workflow to use a hosted runner, avoiding release blocking on unavailable self-hosted runners.

Model Enablement

  • Add GLM-5.1 tutorial and prerequisite notes for the kt-kernel path (#1916, #1932).
  • Refresh README and model documentation links for Kimi-K2.5, MiniMax-M2.5, Qwen3.5, DeepSeek-V3.2, and SFT docs.

📦 Installation

KT SFT with LLaMA-Factory

Use a LLaMA-Factory checkout that contains the KT examples and requirements/ktransformers.txt.

cd /path/to/LLaMA-Factory
pip install -e .
pip install -r requirements/ktransformers.txt

For direct package installation outside that requirements file:

pip install "ktransformers[sft]"

KT Inference

KT inference uses the SGLang-KT path:

pip install kt-kernel sglang-kt

Keep kt-kernel in the inference installation path. LLaMA-Factory SFT continues to use ktransformers[sft].
