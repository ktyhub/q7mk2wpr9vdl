ktransformadores v0.7.0.post4

KTransformadores 0.7.0.post4

Entrenamiento LoRA de texto Kimi K2.5, currículum de puntos de control y carga de adaptador SGLang con expertos nativos enrutados RAWINT4.

Instalación Python 3.11 / 3.12

Comience con la guía paso a paso y el kit de usuario r2. Verifique SHA256SUMS-r2.txt antes de extraerlo. Se realiza un seguimiento de la guía actualizada en PR #2207. El kit contiene tres YAML, herramientas de preparación de datos y conversión LoRA, y bloqueos de dependencia separados Python 3.11 / 3.12. Sólo es necesario cambiar el modelo y las rutas de salida. Los paquetes principales se instalan desde PyPI; La rueda de rama LF aprobada y las ruedas PEFT/TRL de solo metadatos se incluyen con el kit. No instale paquetes Transformers/Accelerate ascendentes superpuestos en estos entornos.

  • Linux x86_64, glibc 2.35+, Python 3.11 o 3.12, CUDA 12.8, Torch 2.9.1.
  • Hardware validado: AMD EPYC 9355 dual, aproximadamente 1.5 TiB RAM; 8 GPU RTX 5090 para entrenamiento y 4 para inferencia. Esta no es una afirmación de especificaciones mínimas.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4; transformadores-kt 5.6.0.post5; acelerar-kt 1.14.0.post3.
  • El embalaje está deshabilitado. Utilice el modelo original fijado y el paso explícito de preparación de datos. Los anfitriones sin acceso a Hugging Face deben obtener las instantáneas del modelo/datos anclados por separado. El suplemento del 14 de septiembre agrega una rueda CPython 3.11 real, incluidas fijaciones nativas a juego. Las versiones existentes, los archivos originales de cinco ruedas y el kit r1 no se modifican. Python 3.11 requiere r2; No reutilice los archivos de bloqueo r1 Python 3.12 ni cambie el nombre de una rueda cp312. Si un espejo no ha sincronizado el nuevo archivo, utilice el índice oficial de PyPI.

Validación y alcance

Los entornos candidatos limpios separados Python 3.11 y 3.12 pasaron el entrenamiento base de Kimi, un resumen de nuevos procesos con bits exactos en 20 comparaciones de estados, conversión LoRA ordinaria/experta y nueva generación de SGLang con las 60 capas LoRA expertas cargadas. También pasó la reconstrucción independiente del Python 3.12 principal congelado. La evidencia candidata y las referencias de fuentes congeladas se incluyen en r2. El ciclo de vida público-PyPI original de Python 3.12 pasó el 13 de septiembre; consulte PUBLIC_WHEEL_VERIFICATION.json. La instalación de r2 posterior a la publicación y la verificación del ciclo de vida ya se están ejecutando; la publicación por sí sola no se informa como finalización de esa verificación. El Neko checkpoint-100 entrenado por separado se recargó en ambas versiones Python y completó 32 respuestas reservadas por versión con texto coincidente. Muestra el estilo deseado, pero aun así no supera algunas comprobaciones estrictas de formato y calidad del contenido. El entrenamiento con humo en cuatro pasos no es un experimento completo de convergencia de estilos ni una garantía general de calidad/seguridad. La validación de versiones anteriores cubrió el entrenamiento/inferencia Qwen3-30B-A3B BF16, el entrenamiento FP8 nativo de DeepSeek-V3.1 y la inferencia de texto GLM next-0808 designada por el usuario; estos no se repitieron para este suplemento Python. K2.5 está validado por hardware. La ruta de arquitectura compartida de K2.6 no fue probada en hardware por separado. El entrenamiento visual, otras arquitecturas y longitudes de secuencia arbitrarias no están certificados aquí. La equivalencia de la fuente original permanece registrada en main-equivalence.json. Las ruedas de la misma versión reconstruidas de forma independiente no reemplazan los artefactos publicados.

ktransformers v0.7.0.post4

KTransformers 0.7.0.post4

Kimi K2.5 text LoRA training, checkpoint resume, and SGLang adapter loading with native RAWINT4 routed experts.

Python 3.11 / 3.12 installation

Start with the step-by-step guide and the r2 user kit. Check SHA256SUMS-r2.txt before extracting it. The updated guide is tracked in PR #2207.

The kit contains three YAMLs, data preparation and LoRA conversion tools, and separate Python 3.11 / 3.12 dependency locks. Only model and output paths need changing. Core packages install from PyPI; the approved LF branch wheel and metadata-only PEFT/TRL wheels are bundled with the kit. Do not install overlapping upstream Transformers/Accelerate packages into these environments.

  • Linux x86_64, glibc 2.35+, Python 3.11 or 3.12, CUDA 12.8, Torch 2.9.1.
  • Validated hardware: dual AMD EPYC 9355, approximately 1.5 TiB RAM; 8 RTX 5090 GPUs for training and 4 for inference. This is not a minimum-spec claim.
  • ktransformers / kt-kernel / sglang-kt 0.7.0.post4; transformers-kt 5.6.0.post5; accelerate-kt 1.14.0.post3.
  • Packing is disabled. Use the pinned original model and explicit data-preparation step. Hosts without Hugging Face access must obtain the pinned model/data snapshots separately.

The September 14 supplement adds one real CPython 3.11 wheel, including matching native bindings. Existing versions, the original five wheel files, and the r1 kit are unchanged. Python 3.11 requires r2; do not reuse the r1 Python 3.12 lock files or rename a cp312 wheel. If a mirror has not synchronized the new file, use the official PyPI index.

Validation and scope

Separate Python 3.11 and 3.12 clean candidate environments passed Kimi base training, bit-exact new-process resume across 20 state comparisons, ordinary/expert LoRA conversion, and fresh SGLang generation with all 60 expert-LoRA layers loaded. The independent frozen-main Python 3.12 rebuild also passed. Candidate evidence and frozen source references are included in r2.

The original Python 3.12 public-PyPI lifecycle passed on September 13; see PUBLIC_WHEEL_VERIFICATION.json. Post-publication r2 installation and lifecycle verification is now running; publication alone is not reported as completion of that check.

The separately trained Neko checkpoint-100 was reloaded in both Python versions and completed 32 held-out answers per version with matching text. It displays the intended style, but still fails some strict-format and content-quality checks. Four-step smoke training is not a full style-convergence experiment or a general-quality/safety guarantee.

Earlier release validation covered Qwen3-30B-A3B BF16 training/inference, DeepSeek-V3.1 native FP8 training, and user-designated GLM next-0808 text inference; these were not repeated for this Python supplement. K2.5 is hardware-validated. K2.6's shared architecture path was not separately hardware-tested. Vision training, other architectures, and arbitrary sequence lengths are not certified here.

Original source equivalence remains recorded in main-equivalence.json. Same-version independently rebuilt wheels do not replace published artifacts.
