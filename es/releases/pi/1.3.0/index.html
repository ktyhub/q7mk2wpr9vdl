#piv1.3.0

Nuevas características

  • Elija dónde se carga /share: sessionShareDestination selecciona auto, gist o radius. Consulte Sesiones y contexto y Exportar o compartir una sesión.
  • Cambios en el nivel de pensamiento que preservan el caché en OpenAI GPT-6: cambiar el nivel de pensamiento a mitad de sesión con una clave API mantiene el caché de mensajes.
  • Código Kimi sobre finalizaciones de chat: las herramientas agregadas durante la conversación ya no invalidan el caché de mensajes. Las anulaciones de URL base de models.json ahora deben incluir /v1. Consulte Proveedores.
  • Cambio de modelo limpio: el pensamiento de un modelo anterior se elimina en lugar de mostrarse al nuevo modelo como texto.
  • Las sesiones reanudadas mantienen sus herramientas activas: --tools +name/-name se aplica encima de ellas. Consulte Herramientas.

Agregado

  • Cambiar el nivel de pensamiento a mitad de sesión en los modelos OpenAI GPT-6 (tecla API) ahora mantiene el caché de mensajes (#10853)
  • Se agregó la configuración sessionShareDestination para elegir cargas automáticas, GitHub gist o Radius para /share (#10870 por @vegarsti)

Cambiado

  • Se cambió el proveedor kimi-coding para usar Finalizaciones de chat OpenAI en https://api.kimi.com/coding/v1, el protocolo utilizado por el Código Kimi oficial client. K3, K3-256K y Kimi For Coding ahora aceptan herramientas agregadas en medio de una conversación sin invalidar el caché de mensajes. Las anulaciones de models.json de la URL base de kimi-coding ahora deben incluir /v1 (#10720)
  • Se cambió el cambio de modelo para eliminar bloques de pensamiento de mensajes anteriores del asistente producidos por un modelo diferente, en lugar de enviarlos como texto sin formato. Anteriormente, el nuevo modelo veía el razonamiento del modelo anterior como parte de sus respuestas y podía comenzar a escribir su propio razonamiento en la respuesta visible (#10995)

Fijo

  • Se fijaron las dependencias internas de Pi a las versiones de lanzamiento exactas para evitar que las instalaciones nuevas mezclen paquetes incompatibles (#10865)
  • Se corrigieron las sesiones reanudadas que dejaban caer las herramientas activadas durante la sesión. Reanudar ahora restaura las herramientas activas de la sesión, con las entradas --tools +name/-name aplicadas a ellas, a menos que --tools con nombres de herramientas, --no-tools o --no-builtin-tools seleccione herramientas explícitamente (#10785)
  • Se corrigió la detención de un script en modo de código o el cumplimiento de su fecha límite esperando que regresara un elemento integrado no interrumpible en Bun (#10748)
  • Se corrigieron los tiempos de espera o abortos repetidos del modo de código que acumulaban trabajadores supervivientes; la admisión ahora limita los trabajadores activos a dos en todas las sesiones, contando los trabajadores cancelados hasta la salida real (#10748)
  • Se corrigió que --model eligiera un proveedor por orden de catálogo cuando varios proveedores ofrecen la combinación; Pi ahora prefiere al proveedor con credenciales y, en caso contrario, informa de la ambigüedad. --models y enabledModels agregan un modelo para cada proveedor que lo ofrece y advierten sobre la ambigüedad (#10160)
  • Se corrigieron las etiquetas de rango de líneas read para cadenas numéricas o argumentos nulos en la TUI, el árbol de sesión, las exportaciones HTML y los ejemplos (#9887)
  • Se corrigió el error de compilación de Nix flake cuando un proveedor cambiaba API: el pin del catálogo de modelos ahora se actualiza desde el catálogo publicado más reciente cuando sus grupos de modelos API difieren, y las versiones fijan el catálogo más nuevo y compilan con él antes de etiquetarlo (#10985)
  • Se corrigió el paquete Nix que colocaba su Node.js primero en PATH, lo que hacía que los shells de herramientas bash usaran el Nodo de Pi en lugar del node/npm del usuario. El nodo de Pi ahora es solo una alternativa (#10519)
  • Se corrigieron las plantillas de mensajes que dejaban caer argumentos entrecomillados vacíos ("" o ''), lo que cambiaba los argumentos posicionales posteriores e impedía que se aplicaran los valores predeterminados posicionales (#10867)
  • Se corrigió que la compilación del paquete Nix fallara en su verificación de instalación porque todavía esperaba chord y esbuild, de los cuales Pi ya no depende.
  • Se corrigió el argumento de llamada de herramienta que analizaba la eliminación de campos cuando una cadena contiene un escape \u no válido, como \usepackage (#10868)
  • Se corrigieron las solicitudes de Anthropic y Bedrock Claude que fallaban con un 400 cuando el resultado de una herramienta de error contiene imágenes; las imágenes ahora se envían después de los resultados de la herramienta del turno, por lo que el modelo aún las ve (#10794)
  • Se corrigió que los modelos OpenCode Go Gemini fallaran con un 404 al mover OpenCode Zen y OpenCode Go a los puntos finales opencode.ai/inference, y se agregó compatibilidad con Google Generative AI al proveedor OpenCode Go.
  • Se corrigió el error de OpenCode Go MiniMax M2.7 con "El modelo no admite este protocolo" mediante el uso de Anthropic Messages API.
  • Se corrigió el reintento automático que no se activaba para los errores de puerta de enlace Unable to forward upstream stream (#10920)
  • Se corrigió el reintento automático que no activaba los errores The service is temporarily unavailable, lo que también hacía que la compactación fallara en el primer intento (#10965)
  • Se corrigieron las respuestas compatibles con OpenAI que mostraban pensamientos después de la respuesta cuando un proxy como LiteLLM envía razonamiento y contenido en el mismo fragmento de transmisión (#10926)
  • Se corrigieron las solicitudes de Gemini 4 Argon en Google Vertex que fallaban con "El presupuesto de pensamiento no es compatible" y su nivel de pensamiento se ignoraba en el Gemini API (#10890)
  • Se corrigieron los modelos Xiaomi MiMo que fallaban con un 400 en el nivel de pensamiento minimal; ahora exponen solo los niveles off y high (#10818)
  • Se corrigió openai-codex/gpt-6.1-sol usando una ventana de contexto de 272K en lugar de la ventana de 500K que ahora proporciona el Codex (#10840)
  • Se corrigieron llamadas a herramientas cuyos argumentos finales tienen formato incorrecto JSON ejecutándose silenciosamente con solo los campos analizados antes del error; ahora fallan la validación y muestran al modelo los argumentos sin procesar que envió (#10897)
  • Se corrigió que Claude Haiku 5.5 y Claude Opus 5 no admitieran el nivel de pensamiento off (#10753)
  • Se corrigió done() de ctx.ui.custom({ overlay: true }) de una extensión que cerraba la superposición superior en lugar de la suya propia, lo que dejaba la superposición terminada en la pantalla y el diálogo de otra extensión sin resolver (#10648, #10999 por @masonc15)

original en inglés / English original

pi v1.3.0

New Features

  • Choose where /share uploads: sessionShareDestination selects auto, gist, or radius. See Sessions and context and Export or share a session.
  • Cache-preserving thinking level changes on OpenAI GPT-6: changing the thinking level mid-session with an API key keeps the prompt cache.
  • Kimi Code over Chat Completions: tools added mid-conversation no longer invalidate the prompt cache. models.json base URL overrides must now include /v1. See Providers.
  • Clean model switching: thinking from a previous model is dropped instead of being shown to the new model as text.
  • Resumed sessions keep their active tools: --tools +name/-name applies on top of them. See Tools.

Added

  • Changing the thinking level mid-session on OpenAI GPT-6 models (API key) now keeps the prompt cache (#10853)
  • Added the sessionShareDestination setting to choose automatic, GitHub gist, or Radius uploads for /share (#10870 by @vegarsti)

Changed

  • Changed the kimi-coding provider to use OpenAI Chat Completions at https://api.kimi.com/coding/v1, the protocol used by the official Kimi Code client. K3, K3-256K, and Kimi For Coding now accept tools added mid-conversation without invalidating the prompt cache. models.json overrides of the kimi-coding base URL must now include /v1 (#10720)
  • Changed model switching to drop thinking blocks from earlier assistant messages produced by a different model, instead of sending them as plain text. The new model previously saw the old model's reasoning as part of its replies and could start writing its own reasoning into the visible answer (#10995)

Fixed

  • Pinned internal Pi dependencies to exact release versions to prevent fresh installs from mixing incompatible packages (#10865)
  • Fixed resumed sessions dropping tools activated during the session. Resume now restores the session's active tools, with --tools +name/-name entries applied to them, unless --tools with tool names, --no-tools, or --no-builtin-tools selects tools explicitly (#10785)
  • Fixed stopping a codemode script or reaching its deadline waiting for a non-interruptible built-in to return on Bun (#10748)
  • Fixed repeated codemode timeouts or aborts accumulating surviving workers; admission now limits live workers to two across sessions, counting cancelled workers until actual exit (#10748)
  • Fixed --model choosing a provider by catalog order when several providers offer the match; Pi now prefers the provider with credentials and otherwise reports the ambiguity. --models and enabledModels add a model for each provider that offers it and warn about the ambiguity (#10160)
  • Fixed read line-range labels for numeric-string or null arguments in the TUI, session tree, HTML exports, and examples (#9887)
  • Fixed the Nix flake build failing when a provider switched APIs: the model catalog pin is now refreshed from the newest published catalog when its model API groups differ, and releases pin the newest catalog and build with it before tagging (#10985)
  • Fixed the Nix package putting its Node.js first on PATH, which made bash tool shells use Pi's Node instead of the user's node/npm. Pi's Node is now only a fallback (#10519)
  • Fixed prompt templates dropping empty quoted arguments ("" or ''), which shifted later positional arguments and prevented positional defaults from applying (#10867)
  • Fixed the Nix package build failing in its install check because it still expected chord and esbuild, which Pi no longer depends on
  • Fixed tool-call argument parsing dropping fields when a string contains an invalid \u escape such as \usepackage (#10868)
  • Fixed Anthropic and Bedrock Claude requests failing with a 400 when an error tool result contains images; the images are now sent after the tool results of the turn, so the model still sees them (#10794)
  • Fixed OpenCode Go Gemini models failing with a 404 by moving OpenCode Zen and OpenCode Go to the opencode.ai/inference endpoints, and added Google Generative AI support to the OpenCode Go provider
  • Fixed OpenCode Go MiniMax M2.7 failing with "Model does not support this protocol" by using the Anthropic Messages API
  • Fixed automatic retry not triggering for gateway Unable to forward upstream stream errors (#10920)
  • Fixed automatic retry not triggering for The service is temporarily unavailable errors, which also made compaction fail on the first attempt (#10965)
  • Fixed OpenAI-compatible responses showing thinking after the answer when a proxy such as LiteLLM sends reasoning and content in the same stream chunk (#10926)
  • Fixed Gemini 4 Argon requests on Google Vertex failing with "Thinking budget is not supported", and its thinking level being ignored on the Gemini API (#10890)
  • Fixed Xiaomi MiMo models failing with a 400 at the minimal thinking level; they now expose only the off and high levels (#10818)
  • Fixed openai-codex/gpt-6.1-sol using a 272K context window instead of the 500K window Codex now provides (#10840)
  • Fixed tool calls whose final arguments are malformed JSON silently running with only the fields parsed before the error; they now fail validation and show the model the raw arguments it sent (#10897)
  • Fixed Claude Haiku 5.5 and Claude Opus 5 not supporting the off thinking level (#10753)
  • Fixed done() of an extension's ctx.ui.custom({ overlay: true }) closing the topmost overlay instead of its own, which left the finished overlay on screen and another extension's dialog unresolved (#10648, #10999 by @masonc15)
