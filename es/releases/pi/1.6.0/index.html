#piv1.6.0

Nuevas características

  • GPT-6.2 Astra y GPT-6.2 Sol: ambos modelos están disponibles en los proveedores openai, azure y openai-codex, y GPT-6.2 Sol es ahora el modelo predeterminado para los tres. Consulte Proveedores.

Cambios importantes

  • Componentes de extensión: render() ahora devuelve readonly string[] y Container devuelve la misma matriz almacenada en caché mientras sus elementos secundarios no se modifican. Las extensiones que modifican la salida de renderizado en su lugar, incluido super.render() en una subclase Container o la salida de un componente incrustado, deben copiarlo primero (#9549)

Agregado

  • Se agregaron GPT-6.2 Astra y GPT-6.2 Sol a los proveedores openai, azure y openai-codex. Ambos rechazan el esfuerzo de razonamiento none y minimal, por lo que el nivel de pensamiento off no está disponible. Azure les ofrece una ventana de contexto de 1,05 millones; Codex sirve GPT-6.2 Sol con 500K y GPT-6.2 Astra con 272K
  • Se agregó qwen4-max-preview a los proveedores individuales del plan Qwen Token (#12259)
  • Se agregaron deepseek-v4.1-flash y deepseek-v4.1-flash-1017 a los proveedores individuales del plan Qwen Token y las variables clave por plan QWEN_TOKEN_PLAN_TEAM_API_KEY, QWEN_TOKEN_PLAN_TEAM_CN_API_KEY, QWEN_TOKEN_PLAN_INDIVIDUAL_API_KEY y QWEN_TOKEN_PLAN_INDIVIDUAL_CN_API_KEY; los QWEN_TOKEN_PLAN_API_KEY y QWEN_TOKEN_PLAN_CN_API_KEY compartidos todavía funcionan (#11773)
  • Se agregó un aviso de transcripción cuando OpenAI elimina elementos de razonamiento de una solicitud, como OpenAI dropped 2 reasoning items: prefix_mismatch (details in session) después de la compactación en GPT-6.2. Al igual que el aviso de pensamiento antrópico, se muestra cuando showCacheMissNotices está activado y solo cuando se eliminan más elementos que en la respuesta anterior. Ambos avisos mencionan ahora los motivos.

Cambiado

  • Los proveedores de Qwen Token Plan ahora utilizan las puertas de enlace actuales (token-plan.maas.qwencloudapi.com internacional, token-plan.maas.qianwenaiapi.com China), y qwen-token-plan y qwen-token-plan-cn se denominan "Qwen Token Plan Team" y "Qwen Token Plan Team CN". Los ID de proveedor no han cambiado y los antiguos hosts aliyuncs.com aún funcionan (#11773)
  • Se actualizó undici a 8.12.4 para los avisos de seguridad GHSA-mqg3-3v4r-cm32, GHSA-7xg3-fphp-28hg, GHSA-5rm8-gv32-r954, GHSA-9v6h-8rgp-m69f, GHSA-3g9m-rv3r-w5w2 y GHSA-r4pc-4jcp-7pqc (#12200)
  • El modelo predeterminado para los proveedores openai, azure y openai-codex ahora es GPT-6.2 Sol (gpt-6.2-sol) en lugar de GPT-6.1 Sol, al mismo precio.
  • Los patrones de ruta de la herramienta de búsqueda ahora son relativos al directorio de búsqueda, como glob de grep: src/*.ts encuentra src/a.ts pero ya no pkg/src/a.ts; use **/src/*.ts para igualar a cualquier profundidad. Los patrones sin / aún coinciden con los nombres de archivos en cualquier profundidad (#12066)
  • La extensión llama.cpp ahora se conecta a http://127.0.0.1:9931 de forma predeterminada, el puerto predeterminado actual del servidor llama, en lugar del puerto 8080 (#12001 por @julien-c)
  • Los hilos de mensajes antrópicos ahora están activados de forma predeterminada para cualquier proveedor cuya baseUrl esté en api.anthropic.com, no solo el proveedor anthropic (#11987)
  • El comando de reanudación impreso al salir ahora está en su propia línea después de To resume this session:, por lo que se puede seleccionar con un triple-click (#12237)

  • Se corrigió que read almacenara una nota de que el modelo actual no admite imágenes, que se reproducía en el modelo como texto obsoleto después de cambiar a un modelo de visión. La imagen aún se reemplaza con un marcador de posición por solicitud para los modelos sin entrada de imagen, y el resultado de la lectura ahora muestra la advertencia solo en la TUI, también cuando está contraído (#12131)
  • Se corrigió que las herramientas MCP cargadas por tool_search se eliminaran en el currículum y /reload cuando una extensión desactiva solo su propia herramienta en session_start, como lo hacen pi-web-access y pi-subagents en el modo toolActivation: "auto" (#11996)
  • Se corrigió que el binario independiente no pudiera resolver las dependencias de extensión npm cuyo punto de entrada se declara en package.json main o exports (por ejemplo, shiki, yaml, graceful-fs), incluidas las importaciones realizadas desde dentro de otras dependencias (#12012)
  • Se corrigió que la herramienta de búsqueda no arrojara resultados para patrones que comenzaban con ./, como ./src/*.ts (#12020)
  • Se corrigió la salida de pi con un AbortError no detectado cuando se cancela una llamada a la herramienta read mientras se abre el archivo (#11956)
  • Se corrigió que pi saliera con un AbortError no detectado cuando el selector de sesión cancela la carga después de omitir un archivo .jsonl que no es una sesión, y se corrigió que dichos archivos permanecieran abiertos (#11956)
  • Se corrigió el fallo del pi del /share cuando el GitHub CLI no se inicia
  • Se corrigió el error pi update en instalaciones administradas de Windows con "No se pudo verificar Pi administrado" cuando un sistema más antiguo Node.js aparece antes del Node.js independiente del instalador en PATH (#12048)
  • Se corrigió el HTML /export que mostraba códigos de escape de hipervínculos de terminal sin formato alrededor de los enlaces en la salida de la herramienta personalizada; los enlaces ahora son clickable (#12003)
  • Se corrigió que la herramienta bash no devolviera resultados, con un pie de página como [Showing lines 3-2 of 2], cuando el resultado termina en una línea de más de 100 KB, como una coincidencia de grep en un archivo minimizado; ahora muestra el final de esa línea (#12062)

  • Se corrigieron los modelos Groq Qwen que fallaban con 400 Unexpected message role; Los proveedores compatibles con OpenAI distintos de OpenAI ahora reciben mensajes del sistema (el mensaje del sistema y los mensajes del sistema a mitad de la conversación) con la función system (#10741)
  • Se corrigieron las advertencias de enabledModels/--models, como No models match pattern "github-copilot/nope", que se escribían sobre la TUI interactiva en cada /new, /resume y /fork, lo que dejaba líneas obsoletas en el modo de pantalla completa. Las advertencias ahora se muestran una vez al inicio, en el chat en modo interactivo y en stderr en otros modos; El modo RPC ya no los repite en stderr para cada new_session, switch_session o fork (#11264)
  • Se corrigió la herramienta de búsqueda que coincidía con patrones de ruta a través de carpetas encima de la ruta de búsqueda: con el proyecto en ~/src/app, src/**/*.ts devolvió todos los archivos .ts en el proyecto (#12066)

  • Se corrigió presionar Esc durante un lote de llamadas a herramientas dejando las llamadas que aún no habían comenzado sin resultado en la sesión; ahora obtienen el resultado "Operación cancelada" (#9986)

  • Se corrigieron problemas encontrados al reemplazar la sesión con /new, /resume, /fork o RPC new_session, switch_session y fork que nunca se muestran, por ejemplo, una extensión de proyecto que no se carga después de /resume en otro proyecto, o un patrón enabledModels que no coincide con nada después de un cambio de configuración. El modo interactivo ahora los muestra en el chat e imprime, los modos JSON y RPC los escriben en stderr; un problema ya reportado no se repite. Los hosts SDK pueden llamar al nuevo AgentSessionRuntime.takeUnreportedDiagnostics() al inicio y después de cada reemplazo para obtener cada diagnóstico una vez.
  • Se corrigió que RPC new_session, switch_session, fork y clone ejecutaran los controladores de extensión session_start y resources_discover dos veces para la nueva sesión. Los RPC clients ahora también reciben eventos emitidos por los controladores session_start, como entry_appended para las entradas que agregan (#10470)
  • Se corrigió una excepción generada por el controlador pi.events de una extensión que se imprimió con console.error en la TUI interactiva. Ahora se reporta como otros errores de extensión: en el chat en modo interactivo, como extension_error en modo RPC y como Extension error (...) en modo impresión. Los errores de un controlador que falla después de que se reemplazó su sesión se eliminan (#11264)
  • Se corrigió que AgentSession.reload() no emitiera session_start a las extensiones cuando el host SDK las vinculaba con bindExtensions({}), después de que ya había emitido session_shutdown. Las extensiones que comienzan a funcionar en session_start, como la extensión MCP que conecta sus servidores, permanecieron detenidas después de una recarga
  • Se corrigieron los eventos de eliminación de --mode json emitidos por los controladores de extensión session_start, como entry_appended para las entradas que agregan, al inicio y después de que una extensión reemplaza la sesión.
  • Se corrigió que Could not restore model <provider>/<model>. Using <fallback> se mostrara solo en el inicio interactivo. Al reanudar o bifurcar una sesión cuyo modelo ya no existe o no tiene inicio de sesión, se cambió a otro modelo sin previo aviso y los modos de impresión JSON y RPC nunca lo mostraron. Ahora se informa en todos los modos, al inicio y después de /resume, /fork y RPC switch_session o fork.
  • Se corrigió que la salida de git y npm, como Cloning into ... o added 12 packages, se dibujara sobre la TUI interactiva cuando pi instalaba o actualizaba paquetes durante /reload, /new, /resume y /fork, incluidos los paquetes temporales -e git: y -e npm:. En el modo interactivo, su resultado ahora se captura y una instalación fallida informa el final del mismo. Hasta que se inicie la TUI, cada instalación se anuncia como Installing <source>... en stderr en lugar de mostrar la salida de git y npm. git y ssh ya no pueden solicitar mensajes en modo interactivo: un paquete que necesita una contraseña o frase de contraseña escrita falla con una sugerencia para configurar un asistente de credenciales o un agente ssh, o para ejecutar pi install <source> una vez desde el shell. pi install y pi update mantienen la salida en vivo (#11264)

pi v1.6.0

New Features

  • GPT-6.2 Astra and GPT-6.2 Sol: both models are available on the openai, azure, and openai-codex providers, and GPT-6.2 Sol is now the default model for all three. See Providers.

Breaking Changes

  • Extension components: render() now returns readonly string[], and Container returns the same cached array while its children are unchanged. Extensions that modify render output in place, including super.render() in a Container subclass or an embedded component's output, must copy it first (#9549)

Added

  • Added GPT-6.2 Astra and GPT-6.2 Sol to the openai, azure, and openai-codex providers. Both reject reasoning effort none and minimal, so thinking level off is unavailable. Azure serves them with a 1.05M context window; Codex serves GPT-6.2 Sol with 500K and GPT-6.2 Astra with 272K
  • Added qwen4-max-preview to the Qwen Token Plan Individual providers (#12259)
  • Added deepseek-v4.1-flash and deepseek-v4.1-flash-1017 to the Qwen Token Plan Individual providers, and per-plan key variables QWEN_TOKEN_PLAN_TEAM_API_KEY, QWEN_TOKEN_PLAN_TEAM_CN_API_KEY, QWEN_TOKEN_PLAN_INDIVIDUAL_API_KEY, and QWEN_TOKEN_PLAN_INDIVIDUAL_CN_API_KEY; the shared QWEN_TOKEN_PLAN_API_KEY and QWEN_TOKEN_PLAN_CN_API_KEY still work (#11773)
  • Added a transcript notice when OpenAI drops reasoning items from a request, such as OpenAI dropped 2 reasoning items: prefix_mismatch (details in session) after compaction on GPT-6.2. Like the Anthropic thinking notice, it is shown when showCacheMissNotices is on and only when more items are dropped than in the previous response. Both notices now name the reasons

Changed

  • Qwen Token Plan providers now use the current gateways (token-plan.maas.qwencloudapi.com international, token-plan.maas.qianwenaiapi.com China), and qwen-token-plan and qwen-token-plan-cn are named "Qwen Token Plan Team" and "Qwen Token Plan Team CN". Provider IDs are unchanged, and the old aliyuncs.com hosts still work (#11773)
  • Updated undici to 8.12.4 for security advisories GHSA-mqg3-3v4r-cm32, GHSA-7xg3-fphp-28hg, GHSA-5rm8-gv32-r954, GHSA-9v6h-8rgp-m69f, GHSA-3g9m-rv3r-w5w2, and GHSA-r4pc-4jcp-7pqc (#12200)
  • The default model for the openai, azure, and openai-codex providers is now GPT-6.2 Sol (gpt-6.2-sol) instead of GPT-6.1 Sol, at the same price
  • The find tool's path patterns are now relative to the search directory, like grep's glob: src/*.ts finds src/a.ts but no longer pkg/src/a.ts; use **/src/*.ts to match at any depth. Patterns without / still match file names at any depth (#12066)
  • The llama.cpp extension now connects to http://127.0.0.1:9931 by default, the current llama-server default port, instead of port 8080 (#12001 by @julien-c)
  • Anthropic message threads are now on by default for any provider whose baseUrl is on api.anthropic.com, not only the anthropic provider (#11987)
  • The resume command printed on exit is now on its own line after To resume this session:, so it can be selected with a triple-click (#12237)

Fixed

  • Fixed read storing a note that the current model does not support images, which was replayed to the model as stale text after switching to a vision model. The image is still replaced with a placeholder per request for models without image input, and the read result now shows the warning in the TUI only, also when collapsed (#12131)
  • Fixed MCP tools loaded by tool_search being dropped on resume and /reload when an extension deactivates only its own tool at session_start, as pi-web-access and pi-subagents do in toolActivation: "auto" mode (#11996)
  • Fixed the standalone binary failing to resolve extension npm dependencies whose entry point is declared in package.json main or exports (for example shiki, yaml, graceful-fs), including imports made from inside other dependencies (#12012)
  • Fixed the find tool returning no results for patterns starting with ./, such as ./src/*.ts (#12020)
  • Fixed pi exiting with an uncaught AbortError when a read tool call is cancelled while the file is being opened (#11956)
  • Fixed pi exiting with an uncaught AbortError when the session picker cancels loading after skipping a .jsonl file that is not a session, and fixed such files staying open (#11956)
  • Fixed /share crashing pi when the GitHub CLI fails to start
  • Fixed pi update on Windows managed installs failing with "Could not verify managed Pi" when an older system Node.js comes before the installer's standalone Node.js on PATH (#12048)
  • Fixed /export HTML showing raw terminal hyperlink escape codes around links in custom tool output; links are now clickable (#12003)
  • Fixed the bash tool returning no output, with a footer like [Showing lines 3-2 of 2], when the output ends in one line longer than about 100KB, such as a grep match in a minified file; it now shows the end of that line (#12062)
  • Fixed provider errors reading "Connection closed." not triggering automatic retries (#12064)
  • Fixed /resume sometimes selecting an unrelated session while the list reloads after deleting or renaming a session (#12106)
  • Fixed Groq Qwen models failing with 400 Unexpected message role; OpenAI-compatible providers other than OpenAI now receive system messages (the system prompt and mid-conversation system messages) with the system role (#10741)
  • Fixed enabledModels/--models warnings such as No models match pattern "github-copilot/nope" being written over the interactive TUI on every /new, /resume and /fork, which left stale lines in fullscreen mode. The warnings are now shown once at startup, in the chat in interactive mode and on stderr in other modes; RPC mode no longer repeats them on stderr for each new_session, switch_session or fork (#11264)
  • Fixed the find tool matching path patterns through folders above the search path: with the project in ~/src/app, src/**/*.ts returned every .ts file in the project (#12066)
  • Fixed pi crashing with RangeError: Maximum call stack size exceeded when rendering a very large edit diff, for example after editing a file with a multi-megabyte line, and again on every resume of that session (#8036)
  • Fixed pressing Esc during a batch of tool calls leaving the calls that had not started yet without a result in the session; they now get an "Operation aborted" result (#9986)
  • Fixed an unreadable CHANGELOG.md (pi's own or an extension package's) printing Warning: Could not parse changelog over the interactive TUI; it now shows no changelog notes (#11264)
  • Fixed problems found when replacing the session with /new, /resume, /fork or RPC new_session, switch_session and fork never being shown, for example a project extension that fails to load after /resume into another project, or an enabledModels pattern that matches nothing after a settings change. Interactive mode now shows them in the chat and print, JSON and RPC modes write them to stderr; a problem already reported is not repeated. SDK hosts can call the new AgentSessionRuntime.takeUnreportedDiagnostics() at startup and after each replacement to get each diagnostic once
  • Fixed RPC new_session, switch_session, fork and clone running extension session_start and resources_discover handlers twice for the new session. RPC clients now also receive events emitted by session_start handlers, such as entry_appended for entries they append (#10470)
  • Fixed an exception thrown by an extension's pi.events handler being printed with console.error over the interactive TUI. It is now reported like other extension errors: in the chat in interactive mode, as extension_error in RPC mode and as Extension error (...) in print mode. Errors from a handler that fails after its session was replaced are dropped (#11264)
  • Fixed AgentSession.reload() not emitting session_start to extensions when the SDK host bound them with bindExtensions({}), after it had already emitted session_shutdown. Extensions that start work in session_start, such as the MCP extension connecting its servers, stayed stopped after a reload
  • Fixed --mode json dropping events emitted by extension session_start handlers, such as entry_appended for entries they append, at startup and after an extension replaces the session
  • Fixed Could not restore model <provider>/<model>. Using <fallback> being shown only at interactive startup. Resuming or forking into a session whose model no longer exists or has no login switched to another model without notice, and print, JSON and RPC modes never showed it. It is now reported in every mode, at startup and after /resume, /fork and RPC switch_session or fork
  • Fixed git and npm output, such as Cloning into ... or added 12 packages, being drawn over the interactive TUI when pi installed or refreshed packages during /reload, /new, /resume and /fork, including temporary -e git: and -e npm: packages. In interactive mode their output is now captured, and a failed install reports the end of it. Until the TUI starts, each install is announced as Installing <source>... on stderr instead of showing git and npm output. git and ssh can no longer prompt in interactive mode: a package that needs a typed password or passphrase fails with a hint to set up a credential helper or ssh agent, or to run pi install <source> once from the shell. pi install and pi update keep live output (#11264)
  • Fixed fullscreen scrolling in long sessions saturating a CPU core by re-rendering the whole transcript on every wheel event (#9549)
  • Fixed search in /login, /logout, /scoped-models and /resume keeping the highlight on the row scrolled to before typing, so Enter picked whichever entry landed there instead of the best match; a query now highlights the top match, as /model does (#12245, #12246 by @acmerfight)
  • Fixed exiting pi, pi config and the --resume and other startup pickers dropping terminal output still queued in stdout, such as the resets that turn off mouse tracking and Kitty keyboard reporting; the shell could then print mouse and key reports as text. pi now waits up to one second for queued output before exiting or continuing (#12133)
  • Fixed moving the cursor in a search field with Left, Right, Home or End moving the highlight back to the first entry in /login, /logout, /model, /scoped-models, /resume, /settings, the per-model settings model picker and pi config (#12245)
  • Fixed llama.cpp decision classifiers ignoring the image input that llama.cpp reports, such as Clef with its mmproj; models.classify() now sends their images to /v1/systemone (#12282)
  • Fixed kill -TSTP from outside pi stopping it without restoring the terminal, which left mouse tracking and the Kitty keyboard protocol on at the shell prompt and turned mouse movement into garbage input. pi now suspends as with Ctrl+Z and redraws on fg (#12283 by @haoqixu)
  • Fixed changing the thinking level on the openai-codex provider invalidating the prompt cache on GPT-6 models (#12269)
  • Fixed unscoped syntax-highlighted text inheriting the terminal foreground and becoming unreadable on contrasting tool cards (#11092)
  • Fixed /copy saying "No agent messages to copy yet." after Esc during a tool call or after a provider error; it now copies the previous answer. RPC get_last_assistant_text skips the same messages (#12119, #12121 by @acmerfight)
  • Fixed pi.exec reporting exit code 0 for commands ended by a signal, such as a timeout, an abort or a crash; it now reports 128 + the signal number, like a shell (143 for SIGTERM, 137 for SIGKILL) (#12088, #12089 by @acmerfight)
  • Fixed GitHub Copilot Gemini and Kimi models (gemini-4-argon, gemini-4-carbon, gemini-3.8-flash, kimi-k3) ignoring the thinking level, and Copilot usage always reporting 0 reasoning tokens (#12110 by @DenielC1)
  • Fixed provider errors that report only a Node socket error code, such as read ECONNRESET, write EPIPE, or connect ETIMEDOUT, not triggering automatic retries (#12128)
  • Fixed OpenAI rejecting requests with a 400 error when a tool's schema contains a node without a type (such as items: {} or Type.Unknown()); such tools are now sent in non-strict mode (#12049)
  • Fixed Mistral Large 4 tool calls stalling for minutes; Mistral models no longer receive strict tools unless compat.supportsStrictMode is set (#12148)
  • Fixed non-strict Anthropic tool schemas not telling the model that extra arguments are forbidden (#12067)
  • Fixed GitHub Copilot models on the Responses API (GPT, Grok, MAI-Code) filling omitted optional tool arguments with empty strings or invented values (#12286)
  • Fixed the OpenAI Codex WebSocket 60-minute connection limit failing the turn when it hit mid-stream, for example during long thinking; the request is now retried on a fresh connection (#12124)
  • Fixed the openai-codex provider getting almost no prompt cache hits for the system prompt on GPT-6.2 models (#12273)
  • Fixed the openai-codex provider ignoring a model's maxTokens
  • Fixed fullscreen Kitty images disappearing after a full redraw such as a window resize (#12010)
  • Fixed text after a multi-row inline image in Markdown drawing over the image (#12017)
  • Fixed Kitty and iTerm2 images covering overlays drawn over them (#11584)
  • Fixed Enter on a Tab path menu for an absolute path (look at /tmp/fi) or a slash command argument menu (/open /tm) submitting the prompt instead of accepting the completion (#12309, #12312 by @acmerfight)
