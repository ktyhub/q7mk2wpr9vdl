pi v0.99.0

Menor Publicado29 sept 2026 Fuenteearendil-works/pi original en inglés

Esta página está traducida automáticamente. El texto original en inglés es la referencia.

#piv0.99.0

Nuevas características

  • Codemode y MCP: conecte servidores MCP y permita que los modelos ejecuten JavaScript que llama a herramientas en paralelo. Consulte Servidores MCP y Habilitar modo de código.
  • Tema del sistema: los colores de Pi ahora provienen de la propia paleta de tu terminal de forma predeterminada. Consulte Utilice los colores de su terminal.
  • Inicie sesión con ChatGPT: utilice una suscripción ChatGPT con el proveedor OpenAI a través de /login openai. Consulte Autenticarse interactivamente.
  • Modelos virtuales: las extensiones pueden enrutar cada solicitud a un modelo físico diferente. Consulte Modelos virtuales.
  • Modelos de clasificador: ejecute clasificadores Jev desde scripts de modo de código o utilice cualquier modelo llama.cpp como clasificador. Consulte Cómo funciona el modo de código y Clasificación.

Agregado

  • Se agregó modo de código, búsqueda de herramientas y compatibilidad con MCP como extensiones integradas. La herramienta codemode ejecuta JavaScript escrito en modelo en una zona de pruebas QuickJS que llama a las herramientas de pi; habilítelo con defaultTools o --tools y configúrelo con codemode.mode y codemode.inlineBudget. tool_search busca herramientas que no están declaradas para el modelo y las declara. Los servidores MCP sobre HTTP stdio o streaming, con OAuth, provienen de mcp.json (global o por proyecto una vez trusted) o pi.registerMcpServer() y se administran con /mcp y pi mcp add|remove|list|login|logout. Consulte Servidores MCP y Habilitar modo de código (#10040).
  • Se agregó la herramienta de extensión API para herramientas de orquestación: exposure (direct, model-only, codemode, deferred o hidden), namespace, annotations, outputSchema con resultados de structuredContent, isError, prepareLoadout() y ctx.executeTool() para llamadas de herramientas anidadas, que emite eventos con parentToolCallId y se registran como nestedCalls limitado en el resultado de la herramienta de llamada. Consulte Exposición de la herramienta.
  • Se agregó una advertencia cuando una extensión que registra la misma herramienta, comando o bandera reemplaza una extensión integrada (#10174 por @cristinaponcela).
  • Se agregaron modelos virtuales experimentales: las extensiones los registran con pi.registerVirtualModel() y eligen un modelo físico y un nivel de pensamiento para cada solicitud. El pie de página muestra el modelo enrutado, /session enumera el costo por modelo físico y examples/extensions/jev-router.ts enruta con el clasificador Jev. Consulte Modelos virtuales.
  • Se agregó el inicio de sesión con ChatGPT al proveedor OpenAI en /login, que utiliza una suscripción ChatGPT con OpenAI API. Pi almacena un deviceId estable en la configuración global para este inicio de sesión y lo omite de los informes de errores.
  • Se agregó el tema system, ahora el predeterminado, que deriva los colores de pi del primer plano, el fondo y la paleta ANSI informados del terminal y los reconstruye cuando el terminal cambia entre claro y oscuro. Consulte Utilice los colores de su terminal.
  • Se agregaron colores #rgb, oklch() y okhsl() y un campo appearance opcional para archivos de temas, y theme.style(), theme.colors y theme.appearance para extensiones. Consulte Temas y TUI.
  • Se agregó un modelo clasificador para cada modelo de chat llama.cpp, respondido a partir de las probabilidades de la etiqueta del siguiente token. Consulte Clasificación.
  • Se agregaron modelos de clasificador Jev heredados en OpenRouter, Cloudflare Workers AI, Vercel AI Gateway y OpenCode Zen.
  • Se agregó la configuración fullscreenWheelScrollLines y la entrada /settings para el desplazamiento con la rueda del mouse en pantalla completa. El "auto" predeterminado acelera los giros rápidos de la rueda fuera de los terminales macOS locales (#9758).
  • Se agregó disposición por entrada a las respuestas RPC exitosas prompt, steer y follow_up, AgentSession.steer()/followUp() y RpcClient.prompt()/steer()/followUp(); RpcClient.prompt() también acepta streamingBehavior (#9098, #9803).
  • Se agregó generación de imágenes a ModelRuntime: generateImages() con autenticación resuelta en tiempo de ejecución (credenciales almacenadas, OAuth, claves API en tiempo de ejecución, encabezados models.json), además de getModelsOfType(), getModelOfType(), getAvailableOfType(), getAllModels() y getAllAvailable(). Los modelos de imágenes de OpenRouter se enumeran bajo el proveedor openrouter y comparten su credencial; una identificación ascendente puede tener entradas de chat e imágenes separadas. Los proveedores models.json y los registros de extensiones sin una lista de modelos mantienen la generación de imágenes incorporada. Las listas de modelos de extensión pueden incluir entradas discriminadas de chat, imágenes y clasificadores con implementaciones de operaciones; cuando se suministran, reemplazan el catálogo de proveedores en cada operación. Las lecturas orientadas al chat (getModels(), getAvailableSnapshot(), el selector de modelo) no cambian.
  • Se agregó soporte de clasificador a ModelRuntime, incluido classify(), descriptores de acceso al modelo de clasificador, autenticación resuelta en tiempo de ejecución y el modelo TypeSafe jev-latest integrado.
  • Se agregó types=chat,image,classifier a las solicitudes del catálogo de modelos pi.dev para que las actualizaciones remotas superpongan todos los tipos de modelos admitidos; las entradas de tipos de modelos desconocidos se ignoran.
  • Se agregó el evento de extensión provider_stream_event para observar eventos de proveedores analizados antes de la normalización, con un visor de ejemplo /debug-provider opcional (#9784, #9901 de @davidbrai).
  • Se agregó una opción para mostrar/ocultar (H) en las exportaciones HTML para mensajes personalizados marcados como display: false. Los mensajes permanecen ocultos de forma predeterminada y también se pueden revelar desde la barra lateral (#8896, #10020 por @rwachtler).
  • Se agregó soporte heredado de Claude Sonnet 5.5 para Anthropic con pensamiento adaptativo y una ventana de contexto de 1M.
  • Se agregó una sección integrada en pi config para deshabilitar las extensiones integradas mcp, llama.cpp, codemode y tool-search globalmente o por proyecto, almacenadas como -builtin:<name> en la configuración extensions. Las extensiones en línea SDK optan por builtin: true.
  • Se agregaron entradas +name y -name a la configuración defaultTools para agregar o eliminar herramientas sin repetir los valores predeterminados, por ejemplo "defaultTools": ["+codemode"]. Las entradas de proyecto de este formulario se aplican además de la configuración del usuario. Se documentó cómo habilitar codemode sin MCP y cómo usar modelos de clasificador como Jev desde scripts de modo de código.
  • Se agregó el uso del token y el costo de las llamadas en modo de código models.classify() al resultado de la herramienta de modo de código, por lo que cuentan para el costo de la sesión; el resultado del modo de código muestra el costo de cada llamada.

Cambiado

  • Se cambió la compilación de la vista previa nativa TypeScript a TypeScript 7.0 con un destino ES2024 y se reemplazó tsx con la eliminación de tipos incorporada de Node para ejecutar desde el código fuente (#9965).
  • Se eliminó la sección [Themes] del banner de inicio. Los temas personalizados siguen estando disponibles en /settings y todavía se informan conflictos de temas.
  • Se cambió el encabezado de inicio para mostrar el logotipo de pi con la versión en lugar del nombre de la aplicación.
  • Se cambiaron los temas integrados dark y light a los colores pi revisados, escritos en OKHSL.
  • Se cambió la detección de terminal claro/oscuro para usar primero el color de fondo informado, luego el informe claro/oscuro del terminal y luego COLORFGBG. La configuración inicial ya no muestra la apariencia detectada.
  • Se cambió el nombre del proveedor OpenAI Codex heredado a "OpenAI Codex (heredado)"; Inicie sesión con ChatGPT en el proveedor OpenAI que lo reemplaza.
  • Se modificó la detección de terminal heredada para tratar a TERM=*-direct como color verdadero.
  • Las extensiones y herramientas integradas se denominan builtin:<name> (por ejemplo, builtin:mcp y builtin:read) en errores, diagnósticos, información de origen RPC e informes de errores, en lugar de <inline:name> y <builtin:name>. Sus comandos de barra diagonal ya no llevan una etiqueta de autocompletar [t].
  • --no-extensions también desactiva las extensiones integradas, incluido el proveedor llama.cpp. Cargue uno explícitamente con -e builtin:<name>, por ejemplo pi -ne -e builtin:mcp.
  • Las llamadas a herramientas sin un procesador de llamadas personalizado, incluidas las llamadas directas a herramientas MCP, ahora muestran sus argumentos: como pares key=value en la línea de título cuando están contraídos y una línea key: value por argumento cuando están expandidos. Las llamadas de MCP se titulan server/tool y sus resultados se reducen a 5 líneas.
  • Los resultados estructurados de bash y powershell, que reciben los scripts de modo de código, ahora contienen hasta 1 MiB de salida en lugar de las 2000 líneas o 50 KB orientadas al modelo, y agregan truncated y full_output_path. La producción más larga mantiene sus primeros y últimos 512 KiB. La salida vacía es "" en lugar de (no output).

Fijo

  • Se corrigió que el texto del tablero clipboard X11 se identificara erróneamente como una imagen cuando el propietario del tablero cli acepta objetivos de imágenes no anunciadas (#9786).
  • Se evitó que los paquetes git administrados instalaran automáticamente dependencias de pares de Pi y se agregaron advertencias para los paquetes de extensión que enumeran los módulos proporcionados por el host en dependencies (#9863).
  • Se corrigieron extensiones de git fijadas cargadas con -e que continuaban usando la primera confirmación descargada después de los cambios de referencia (#9982).
  • Se corrigió que RpcClient omitiera el siguiente detector de eventos cuando un detector se daba de baja mientras manejaba un evento, lo que podía hacer que waitForIdle() expirara después de collectEvents() (#9990).
  • Se corrigieron las llamadas de archivo completo read que se representan como :1 cuando los modelos envían null para offset y limit omitidos (#9996).
  • Se corrigió la pérdida de nuevas sesiones cuando pi sale antes de la respuesta del primer asistente. El archivo de sesión ahora se crea cuando se envía el primer mensaje de usuario (#10000).
  • Se corrigieron los ajustes preestablecidos de carga automática de llama.cpp descargados que sobrescribían una ventana de contexto de tiempo de ejecución en caché con el contexto de entrenamiento GGUF (#10077, #10158 por @cristinaponcela).
  • Se corrigieron los temas personalizados que ignoraban terminal.trueColor y otras anulaciones de capacidad del terminal y se renderizaban con 256 colores (#9973, #10039 por @christianklotz).
  • Se corrigió el pegado de archivos copiados en Finder insertando la imagen del icono del archivo en lugar de las rutas del archivo; las rutas se citan en modo bash (#9999, #10136 por @christianklotz).
  • Se corrigió que el encabezado de inicio, los recursos cargados y los avisos de chat mantuvieran sus colores antiguos después de un cambio de tema.
  • Se corrigió el modelo predeterminado de Fireworks que apuntaba al modelo Kimi K2.6 eliminado; ahora el valor predeterminado es Kimi K3.
  • Se corrigió el modelo predeterminado de OpenCode Go que apuntaba al modelo Kimi K2.6 eliminado; ahora el valor predeterminado es Kimi K3.
  • Se corrigió el modelo predeterminado de Together que apuntaba al modelo eliminado Kimi K2.6; ahora el valor predeterminado es Kimi K3.
  • Uso reducido de CPU durante la transmisión en sesiones largas y al obtener una vista previa de temas: el pie de página almacena en caché los totales de uso de la sesión, los resultados de bash colapsados ​​almacenan en caché su vista previa y sanitizeBinaryOutput() ya no divide la salida en matrices por carácter.
  • Se corrigió el uso de herramientas llamadas a través de ctx.executeTool(), por ejemplo desde scripts en modo de código, que se eliminan del costo de la sesión; ahora se agrega al uso de resultados de la herramienta de llamada.
  • Se corrigió el autocompletado heredado de /skill que aparecía vacío cuando los nombres de habilidades cargados no contenían las letras en skill (#9944).
  • Se corrigió que la ruta heredada y el autocompletado @ no funcionaran después de abrir contenedores como (, [, {, < o un acento grave.
  • Se corrigió el estiramiento de imagen heredado en terminales que usan el protocolo de gráficos Kitty (#8938, #9957 por @rwachtler).
  • Se corrigió que el cursor de shell heredado permaneciera oculto después de salir cuando una extensión cerraba una superposición durante el apagado (#10026).
  • Se corrigió la pérdida de la entrada de teclado heredada después de que un mouse click en un submenú /settings la cerraba.
  • Se corrigió que las escrituras de caché Anthropic heredadas de 1 hora a través de Vercel AI Gateway tuvieran un precio de 5 minutos (#9210).
  • Se corrigió que el nivel de modelo heredado samplingParams se descartara mediante llamadas directas a stream()/complete() en API compatibles con OpenAI (#9506).
  • Se corrigieron las solicitudes heredadas de Mistral GLM que fallaban con "Se esperaba como máximo un ThinkChunk líder" después de deltas de contenido vacíos (#9674).
  • Se corrigió que las solicitudes heredadas del modo OpenAI Fast tuvieran un precio estándar (#10034).
  • Se corrigieron los modelos de razonamiento heredados de Mistral que ignoraban el nivel de pensamiento solicitado (#9678).
  • Se corrigió que OpenCode Zen y OpenCode Go qwen3.8-flash heredados se reprodujeran como texto sin formato en turnos posteriores (#10047).
  • Se corrigieron los flujos de respuestas OpenAI heredados de servidores que omiten output_index, como llama.cpp, ejecutando llamadas de herramientas confusas; dichas transmisiones ahora terminan con un error (#9974).
  • Se corrigió el inicio de sesión heredado del navegador Anthropic y OpenAI Codex que esperaba indefinidamente después de que el proveedor fue redirigido con un error de autorización, y el inicio de sesión de Anthropic fallaba cuando su puerto de devolución de llamada estaba en uso.
  • Se corrigió el copiloto GitHub heredado Claude Opus 5.5 que ofrecía niveles de pensamiento no admitidos cuando los metadatos del modelo ascendente estaban incompletos.

pi v0.99.0

New Features

  • Codemode and MCP — Connect MCP servers and let models run JavaScript that calls tools in parallel. See MCP Servers and Enable codemode.
  • System theme — Pi's colors now come from your terminal's own palette by default. See Use your terminal's colors.
  • Sign in with ChatGPT — Use a ChatGPT subscription with the OpenAI provider through /login openai. See Authenticate interactively.
  • Virtual models — Extensions can route each request to a different physical model. See Virtual Models.
  • Classifier models — Run Jev classifiers from codemode scripts, or use any llama.cpp model as a classifier. See How codemode works and Classification.

Added

  • Added codemode, tool search, and MCP support as built-in extensions. The codemode tool runs model-written JavaScript in a QuickJS sandbox that calls pi's tools; enable it with defaultTools or --tools and configure it with codemode.mode and codemode.inlineBudget. tool_search finds tools that are not declared to the model and declares them. MCP servers over stdio or streamable HTTP, with OAuth, come from mcp.json (global, or per project once trusted) or pi.registerMcpServer() and are managed with /mcp and pi mcp add|remove|list|login|logout. See MCP Servers and Enable codemode (#10040).
  • Added extension tool APIs for orchestrating tools: exposure (direct, model-only, codemode, deferred, or hidden), namespace, annotations, outputSchema with structuredContent, isError results, prepareLoadout(), and ctx.executeTool() for nested tool calls, which emit events with parentToolCallId and are recorded as bounded nestedCalls on the calling tool's result. See Tool exposure.
  • Added a warning when an extension that registers the same tool, command, or flag replaces a built-in extension (#10174 by @cristinaponcela).
  • Added experimental virtual models: extensions register them with pi.registerVirtualModel() and pick a physical model and thinking level for each request. The footer shows the routed model, /session lists cost per physical model, and examples/extensions/jev-router.ts routes with the Jev classifier. See Virtual Models.
  • Added Sign in with ChatGPT to the OpenAI provider in /login, which uses a ChatGPT subscription with the OpenAI API. Pi stores a stable deviceId in the global settings for this login and omits it from bug reports.
  • Added the system theme, now the default, which derives pi's colors from the terminal's reported foreground, background, and ANSI palette and rebuilds them when the terminal switches between light and dark. See Use your terminal's colors.
  • Added #rgb, oklch(), and okhsl() colors and an optional appearance field to theme files, and theme.style(), theme.colors, and theme.appearance for extensions. See Themes and TUI.
  • Added a classifier model for every llama.cpp chat model, answered from next-token label probabilities. See Classification.
  • Added inherited Jev classifier models on OpenRouter, Cloudflare Workers AI, Vercel AI Gateway, and OpenCode Zen.
  • Added the fullscreenWheelScrollLines setting and /settings entry for fullscreen mouse-wheel scrolling. The default "auto" accelerates fast wheel spins outside local macOS terminals (#9758).
  • Added per-input disposition to successful RPC prompt, steer, and follow_up responses, AgentSession.steer()/followUp(), and RpcClient.prompt()/steer()/followUp(); RpcClient.prompt() also accepts streamingBehavior (#9098, #9803).
  • Added image generation to ModelRuntime: generateImages() with runtime-resolved auth (stored credentials, OAuth, runtime API keys, models.json headers), plus getModelsOfType(), getModelOfType(), getAvailableOfType(), getAllModels(), and getAllAvailable(). OpenRouter image models are listed under the openrouter provider and share its credential; an upstream ID can have separate chat and image entries. models.json providers and extension registrations without a model list keep built-in image generation. Extension model lists can include discriminated chat, image, and classifier entries with operation implementations; when supplied, they replace the provider catalog across every operation. Chat-facing reads (getModels(), getAvailableSnapshot(), the model picker) are unchanged.
  • Added classifier support to ModelRuntime, including classify(), classifier model accessors, runtime-resolved authentication, and the built-in TypeSafe jev-latest model.
  • Added types=chat,image,classifier to pi.dev model catalog requests so remote refreshes overlay every supported model type; entries of unknown model types are ignored.
  • Added the provider_stream_event extension event for observing parsed provider events before normalization, with an opt-in /debug-provider example viewer (#9784, #9901 by @davidbrai).
  • Added a show/hide toggle (H) in HTML exports for custom messages marked display: false. Messages remain hidden by default and can also be revealed from the sidebar (#8896, #10020 by @rwachtler).
  • Added inherited Claude Sonnet 5.5 support for Anthropic with adaptive thinking and a 1M context window.
  • Added a Built-in section in pi config to disable the built-in mcp, llama.cpp, codemode, and tool-search extensions globally or per project, stored as -builtin:<name> in the extensions setting. SDK inline extensions opt in with builtin: true.
  • Added +name and -name entries to the defaultTools setting to add or remove tools without repeating the defaults, for example "defaultTools": ["+codemode"]. Project entries of this form apply on top of the user setting. Documented how to enable codemode without MCP and how to use classifier models such as Jev from codemode scripts.
  • Added the token usage and cost of codemode models.classify() calls to the codemode tool result, so they count toward the session cost; the codemode result shows each call's cost.

Changed

  • Switched the build from the TypeScript native preview to TypeScript 7.0 with an ES2024 target, and replaced tsx with Node's built-in type stripping for running from source (#9965).
  • Removed the [Themes] section from the startup banner. Custom themes remain available in /settings, and theme conflicts are still reported.
  • Changed the startup header to show the pi logo with the version instead of the app name.
  • Changed the built-in dark and light themes to the revised pi colors, written in OKHSL.
  • Changed light/dark terminal detection to use the reported background color first, then the terminal's light/dark report, then COLORFGBG. The first-time setup no longer shows the detected appearance.
  • Renamed the inherited OpenAI Codex provider to "OpenAI Codex (legacy)"; Sign in with ChatGPT on the OpenAI provider supersedes it.
  • Changed inherited terminal detection to treat TERM=*-direct as truecolor.
  • Built-in extensions and tools are named builtin:<name> (for example builtin:mcp and builtin:read) in errors, diagnostics, RPC source info, and bug reports, instead of <inline:name> and <builtin:name>. Their slash commands no longer carry a [t] autocomplete tag.
  • --no-extensions also disables the built-in extensions, including the llama.cpp provider. Load one explicitly with -e builtin:<name>, for example pi -ne -e builtin:mcp.
  • Tool calls without a custom call renderer, including direct MCP tool calls, now show their arguments: as key=value pairs on the title line when collapsed and one key: value line per argument when expanded. MCP calls are titled server/tool and their results collapse to 5 lines.
  • bash and powershell structured results, which codemode scripts receive, now hold up to 1 MiB of output instead of the model-facing 2000 lines or 50KB, and add truncated and full_output_path. Longer output keeps its first and last 512 KiB. Empty output is "" instead of (no output).

Fixed

  • Fixed X11 clipboard text being misidentified as an image when the clipboard owner accepts unadvertised image targets (#9786).
  • Prevented managed git packages from automatically installing Pi peer dependencies and added warnings for extension packages that list host-provided modules in dependencies (#9863).
  • Fixed pinned git extensions loaded with -e continuing to use the first downloaded commit after the ref changes (#9982).
  • Fixed RpcClient skipping the next event listener when a listener unsubscribes while handling an event, which could make waitForIdle() time out after collectEvents() (#9990).
  • Fixed full-file read calls rendering as :1 when models send null for omitted offset and limit (#9996).
  • Fixed new sessions being lost when pi exits before the first assistant response. The session file is now created when the first user message is sent (#10000).
  • Fixed unloaded llama.cpp autoload presets overwriting a cached runtime context window with the GGUF training context (#10077, #10158 by @cristinaponcela).
  • Fixed custom themes ignoring terminal.trueColor and other terminal capability overrides and rendering with 256 colors (#9973, #10039 by @christianklotz).
  • Fixed pasting files copied in Finder inserting the file icon image instead of the file paths; paths are quoted in bash mode (#9999, #10136 by @christianklotz).
  • Fixed the startup header, loaded resources, and chat notices keeping their old colors after a theme change.
  • Fixed the Fireworks default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Fixed the OpenCode Go default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Fixed the Together default model pointing at the removed Kimi K2.6 model; it now defaults to Kimi K3.
  • Reduced CPU use while streaming in long sessions and when previewing themes: the footer caches session usage totals, collapsed bash results cache their preview, and sanitizeBinaryOutput() no longer splits output into per-character arrays.
  • Fixed the usage of tools called through ctx.executeTool(), for example from codemode scripts, being dropped from the session cost; it is now added to the calling tool's result usage.
  • Fixed inherited /skill autocomplete appearing empty when loaded skill names did not contain the letters in skill (#9944).
  • Fixed inherited path and @ autocomplete not working after opening wrappers such as (, [, {, <, or a backtick.
  • Fixed inherited image stretching in terminals that use the Kitty graphics protocol (#8938, #9957 by @rwachtler).
  • Fixed inherited shell cursor staying hidden after exit when an extension closed an overlay during shutdown (#10026).
  • Fixed inherited keyboard input being lost after a mouse click in a /settings submenu closed it.
  • Fixed inherited 1-hour Anthropic cache writes through Vercel AI Gateway being priced at the 5-minute rate (#9210).
  • Fixed inherited model-level samplingParams being dropped by direct stream()/complete() calls on OpenAI-compatible APIs (#9506).
  • Fixed inherited Mistral GLM requests failing with "Expected at most one leading ThinkChunk" after empty content deltas (#9674).
  • Fixed inherited OpenAI Fast mode requests being priced at the standard rate (#10034).
  • Fixed inherited Mistral reasoning models ignoring the requested thinking level (#9678).
  • Fixed inherited OpenCode Zen and OpenCode Go qwen3.8-flash thinking being replayed as plain text on later turns (#10047).
  • Fixed inherited OpenAI Responses streams from servers that omit output_index, such as llama.cpp, running mixed-up tool calls; such streams now end with an error (#9974).
  • Fixed inherited Anthropic and OpenAI Codex browser sign-in waiting indefinitely after the provider redirected with an authorization error, and Anthropic sign-in failing when its callback port is in use.
  • Fixed inherited GitHub Copilot Claude Opus 5.5 offering unsupported thinking levels when upstream model metadata is incomplete.
