MinerU 4.2.3-released

#MinerU mineru-4.2.3-released

##4.2.3

  • Se agregó tiempo de espera de ejecución de un solo archivo y recuperación administrada. WebUI, enrutador y servidor API admiten --task-timeout, el valor predeterminado es 3600 segundos, a partir del momento en que se obtiene la cuota de análisis, que cubre el análisis y el empaquetado del producto del lado del servidor. La tarea de tiempo de espera devuelve task_timeout, el API independiente deja de recibir nuevas tareas y el implementador reconstruye el servicio. El enrutador supervisa el reciclaje de los trabajadores de tiempo de espera y modela los procesos secundarios a través del proceso principal y reinicia el servicio. La recuperación se puede activar incluso si se cancela el hilo de ejecución, el bucle de eventos o la suspensión de la limpieza.
  • Mejorar la experiencia de recuperación de WebUI y la limpieza de procesos. El enrutador aloja la WebUI local como el único trabajador, el estado se muestra durante la recuperación y las solicitudes en cola que aún no se han enviado continúan una vez que el servicio está listo. Otras solicitudes pendientes del antiguo trabajador devuelven worker_restarted y el archivo problemático se puede volver a intentar manualmente. Mejore el árbol de procesos de Windows, el directorio temporal y el reciclaje del canal de control, informe claramente los errores de precarga del modelo y detenga los reintentos automáticos después de tres errores consecutivos de recuperación de inicio.
  • Se corrigió que la búsqueda de texto completo de Doclib estuviera abarrotada por la carga de imágenes. Al construir el texto de búsqueda, extraiga el texto, las fórmulas y las descripciones de los gráficos, y luego aplique un presupuesto de caracteres para evitar que el contenido base64 de las imágenes incrustadas llene el índice y pierda el texto. Después de la actualización, el índice existente se reconstruirá a partir de la caché de análisis y se conservará el contenido de varias páginas. Los documentos con caché incompleta registrarán los motivos de la migración. Después de llenar el caché o volver a analizarlo, reinicie Doclib para continuar con la migración.
  • Compruebe la compatibilidad de vLLM y Transformers con antelación. Identifique la combinación incompatible de vllm<0.29.0 y transformers>=5.23.0 antes de arrancar el motor y brinde indicaciones claras para actualizar vLLM o ajustar el rango de versiones de Transformers, lo que reduce las fallas que son difíciles de localizar durante la etapa de carga del modelo.
  • Dependencias DocVortex actualizadas. La versión mínima se actualiza a 0.6.24, que mejora simultáneamente el análisis de documentos nativos y las capacidades de representación compartida.

Consejos de configuración. El valor predeterminado --worker-tier del enrutador es auto y cada trabajador determina el límite superior del equipo de acuerdo con su propio entorno de equipo. Cuando se requiere un límite superior fijo, se pueden especificar explícitamente flash, basic, standard o advanced. --task-timeout debe ser un número entero positivo. La carga, la puesta en cola, la descarga de clientes y la precarga del inicio del modelo utilizan configuraciones de ciclo de vida y espera independientes.

##4.2.3

  • Agregar tiempos de espera de ejecución por archivo y recuperación administrada. WebUI, enrutador y servidor API admiten --task-timeout, con un valor predeterminado de 3600 segundos desde la adquisición de una ranura de ejecución hasta el análisis y el empaquetado de artefactos del lado del servidor. Las tareas agotadas devuelven task_timeout. Un API independiente deja de aceptar nuevos trabajos y depende de su host de implementación para recrear el servicio. El enrutador supervisa los trabajadores locales del proceso principal, recupera los trabajadores con tiempo de espera agotado y los subprocesos del modelo, y reinicia el servicio incluso cuando los subprocesos de ejecución, el bucle de eventos o la limpieza de cancelación se detienen.
  • Mejorar la recuperación de WebUI y la limpieza de procesos. La WebUI local utiliza el enrutador para administrar un solo trabajador, muestra el estado de recuperación y reanuda las solicitudes en cola en espera de envío una vez que el servicio esté listo. Otras solicitudes incompletas en el trabajador reemplazado devuelven worker_restarted y los archivos afectados se pueden volver a intentar manualmente. Mejore la limpieza del árbol de procesos, directorios temporales y canales de control de Windows, elimine los errores de precarga del modelo y detenga la recuperación automática después de tres errores de inicio consecutivos.
  • Mantenga las cargas útiles de imágenes fuera de los índices de texto completo de Doclib. Cree texto de búsqueda a partir del contenido del cuerpo, fórmulas y descripciones de figuras o tablas antes de aplicar el presupuesto de caracteres, evitando que los datos base64 de imágenes incrustadas desplacen el texto de búsqueda. Reconstruya los índices existentes a partir de los resultados del análisis almacenados en caché durante la actualización y, al mismo tiempo, preserve las continuaciones entre páginas. Los documentos con cachés incompletos registran un motivo de migración y pueden reanudar la migración después de restaurar o volver a analizar el caché y reiniciar Doclib.
  • Verifique la compatibilidad de vLLM y Transformers antes del inicio. Detecte la combinación incompatible de vllm<0.29.0 y transformers>=5.23.0 antes de la inicialización del motor, con orientación práctica para actualizar vLLM o seleccionar una gama de Transformers compatible.
  • Actualizar DocVortex. Aumente la versión mínima a 0.6.24 para el análisis de documentos nativos y mejoras en la representación compartida.

Nota de configuración. El enrutador ahora establece de forma predeterminada --worker-tier en auto, lo que permite a cada trabajador seleccionar su nivel máximo desde el entorno de su dispositivo. Especifique flash, basic, standard o advanced para un techo fijo. --task-timeout requiere un número entero positivo. Las cargas, las colas, las descargas de client y la precarga de inicio del modelo utilizan sus propias configuraciones de espera y ciclo de vida.

MinerU mineru-4.2.3-released

Highlights

  • Execution timeouts and managed recovery — --task-timeout defaults to 3600 seconds and starts when a parsing slot is acquired, covering parsing and server-side artifact packaging—but not uploads, queueing, downloads, or model preloading. Timed-out tasks return task_timeout; standalone API services stop accepting work and require deployment-level recreation, while Router reclaims hung workers and model subprocesses and restarts managed workers.

  • WebUI restart semantics — Local WebUI now uses one Router-managed worker. Requests still awaiting submission resume after recovery, but unfinished requests on the replaced worker return worker_restarted and require manual file retries. Automatic recovery stops after three consecutive startup failures, so monitor surfaced model-preload errors rather than assuming the service will keep restarting.

  • Doclib index migration — Body text, formulas, and figure/table descriptions now enter the search text before the character budget is applied, preventing embedded base64 images from crowding out searchable content. Existing indexes rebuild from cached parse results with cross-page continuations preserved; incomplete caches pause migration with a recorded reason and require cache restoration or reparsing before restarting Doclib.

  • Fail-fast model dependency validation — Startup now detects vllm<0.29.0 combined with transformers>=5.23.0 before engine initialization and provides corrective guidance. Upgrade vLLM or constrain Transformers before deployment to avoid late-stage model-loading failures.

  • Dependency and capacity defaults — DocVortex now requires at least 0.6.24, so ensure deployment pins include its native parsing and rendering updates. Router’s --worker-tier default changes to auto, allowing per-device tier ceilings; explicitly set flash, basic, standard, or advanced when you need predictable capacity and resource behavior.

  • Breaking changes — None explicitly declared.

4.2.3

  • 新增单文件执行超时与托管恢复。WebUI、Router 和 API Server 支持 --task-timeout，默认 3600 秒，从取得解析名额开始计时，覆盖解析和服务端产物打包。超时任务返回 task_timeout，独立 API 停止接收新任务，由部署方重建服务。Router 通过父进程监督回收超时 worker 及模型子进程，并重新启动服务，即使执行线程、事件循环或取消清理挂起也能触发恢复。
  • 改善 WebUI 恢复体验与进程清理。本地 WebUI 由 Router 托管唯一 worker，恢复期间显示状态，尚未提交的排队请求在服务就绪后继续。旧 worker 上其他未完成请求返回 worker_restarted，问题文件可手动重试。完善 Windows 进程树、临时目录与控制通道回收，明确报告模型预加载失败，并在连续三次启动恢复失败后停止自动重试。
  • 修复 Doclib 全文检索被图片载荷挤占。构造检索文本时提取正文、公式和图表说明，再应用字符预算，避免内嵌图片的 base64 内容占满索引而遗漏正文。升级后从解析缓存重建已有索引，并保留跨页内容续接。缓存不完整的文档会记录迁移原因，补齐缓存或重新解析后重启 Doclib 可继续迁移。
  • 提前检查 vLLM 与 Transformers 兼容性。启动引擎前识别 vllm<0.29.0 与 transformers>=5.23.0 的不兼容组合，并给出升级 vLLM 或调整 Transformers 版本范围的明确提示，减少模型加载阶段难以定位的失败。
  • 更新 DocVortex 依赖。最低版本提升至 0.6.24，同步原生文档解析与共享渲染能力的改进。

配置提示。Router 的 --worker-tier 默认改为 auto，由各 worker 根据自己的设备环境确定档位上限。需要固定上限时可显式指定 flash、basic、standard 或 advanced。--task-timeout 必须为正整数，上传、排队、客户端下载及模型启动预加载各自使用独立的等待与生命周期设置。

4.2.3

  • Add per-file execution timeouts and managed recovery. WebUI, Router, and API Server support --task-timeout, defaulting to 3600 seconds from acquiring an execution slot through parsing and server-side artifact packaging. Timed-out tasks return task_timeout. A standalone API stops accepting new work and relies on its deployment host to recreate the service. Router supervises local workers from the parent process, reclaims timed-out workers and model subprocesses, and restarts the service even when execution threads, the event loop, or cancellation cleanup stall.
  • Improve WebUI recovery and process cleanup. Local WebUI uses Router to manage a single worker, displays recovery status, and resumes queued requests awaiting submission once the service is ready. Other unfinished requests on the replaced worker return worker_restarted, and affected files can be retried manually. Improve Windows process-tree, temporary-directory, and control-channel cleanup, surface model preload failures, and stop automatic recovery after three consecutive startup failures.
  • Keep image payloads out of Doclib full-text indexes. Build search text from body content, formulas, and figure or table descriptions before applying the character budget, preventing embedded image base64 data from crowding out searchable text. Rebuild existing indexes from cached parse results during upgrade while preserving cross-page continuations. Documents with incomplete caches record a migration reason and can resume migration after restoring or reparsing the cache and restarting Doclib.
  • Check vLLM and Transformers compatibility before startup. Detect the incompatible combination of vllm<0.29.0 and transformers>=5.23.0 before engine initialization, with actionable guidance to upgrade vLLM or select a compatible Transformers range.
  • Update DocVortex. Raise the minimum version to 0.6.24 for native document parsing and shared rendering improvements.

Configuration note. Router now defaults --worker-tier to auto, allowing each worker to select its tier ceiling from its device environment. Specify flash, basic, standard, or advanced for a fixed ceiling. --task-timeout requires a positive integer. Uploads, queueing, client downloads, and model startup preloading use their own waiting and lifecycle settings.
