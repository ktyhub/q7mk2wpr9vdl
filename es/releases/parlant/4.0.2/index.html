[4.0.2] - 2026-11-05

Agregado

  • El widget de chat permite que el agente de IA en el navegador de un visitante hable con su agente sobre WebMCP (document.modelContext; en Chrome detrás de una bandera hoy). encendido En cada página en la que se encuentra, el widget registra una herramienta ask_agent descrita con el nombre del agente. Una llamada inicia la conversación del widget si no hay ninguna. sin embargo, como uno que un agente tiene para el cliente (customer_represented_by_an_agent), envía la pregunta por el chat, así se muestra ahí con la respuesta, abre el chat, y responde al agente navegador una vez finalizado el turno. Seguimiento Las llamadas continúan la misma conversación. El mensaje lleva metadata.parlant_widget.asked_by = "customer_agent", así que el chat y tu Las herramientas pueden distinguir al agente del visitante del visitante. No pasa nada en un navegador sin WebMCP; webmcp={false} lo apaga. ParlantTransport's sendMessage toma un argumento de metadatos opcional y ensureSession un Opción para la bandera.
  • Server(session_store=..., customer_store=...) acepta un s3://bucket URL para mantener sesiones y clientes en Amazon S3. Dale a Parlant un cubo de el suyo. Las credenciales provienen de la cadena de credenciales de AWS; agregue ?region= o, para almacenamiento compatible con S3, ?endpoint=. El almacenamiento debe soportar Escrituras condicionales, que evitan que los servidores simultáneos sobrescriban cada uno. las actualizaciones de otros. Las colecciones vacías sobreviven a los reinicios y a una migración fallida write deja los datos originales en su lugar. Cualquier consulta que no sea una búsqueda por ID, como enumerar sesiones, lee todos los objetos de la colección, así que use MongoDB si necesita consultas indexadas a escala.
  • El widget de chat (parlant widget init) toma la fotografía del agente en una Accesorio avatar: { type: "logo", src }, { type: "photo", src, live? } o { type: "video", src?, poster?, live?, launcher? }. Un avatar de vídeo reproduce un bucle corto silenciado debajo del encabezado, se desplaza con la conversación una vez se inicia y mantiene su tamaño abierto cuando se expande el chat. en el cerrado lanzador, launcher lo recorta en la cara. Omita src para usar el Vídeo propio del widget de un agente. live agrega el punto verde en el video. esquina también, roja mientras no se puede alcanzar al servidor. Utilice un MP4 H.264 guardado con -movflags +faststart; iPhone Safari se bloquea en WebM.

Cambiado

  • Las sugerencias persistentes del widget de chat se destacan de las iniciales: delineado y escrito en el color principal del tema en el fondo del chat, en lugar del relleno gris.
  • En teléfonos y tabletas, el widget de chat cierra el teclado en pantalla una vez al día. se envía el mensaje, ya sea escrito o elegido entre las sugerencias, por lo que la respuesta no se esconde detrás de ello.
  • Con el proveedor LiteLLM, las rutas de revisión ahora están predeterminadas en gemini/gemini-3.8-flash en lugar de gemini/gemini-3.6-flash, lo mismo modelo que el proveedor Gemini ya utiliza para ellos.
  • El agente del andamio lead-gen ya no adivina cuando un visitante pregunta sobre el negocio, sus productos o su proyecto y su conocimiento del producto no tiene respuesta. Dice que es una gran pregunta pero difícil de responder adecuadamente en el chatea, ofrece conectarlos con el equipo, solicita un correo electrónico o un teléfono número y pasa la pregunta con request_team_follow_up. No relacionado preguntas, preguntas sobre pedidos de clientes existentes y precios se manejan como antes. Para que esto sea posible, record_lead ahora acepta una ventaja con solo un meta y un contacto: buying_for y role son opcionales, y uno desconocido no anota nada.
  • parlant dashboard project confirm finaliza un proyecto local o autohospedado incluso cuando su servidor ya mantiene sesiones, como por ejemplo al probar el agente. Primero los importa al panel, como lo hace la sincronización del panel, y luego completa la configuración, por lo que el proyecto ya no permanece en "Finalizar configuración". Una importación que tarda más de 90 segundos se detiene con SYNC_IN_PROGRESS; ejecute confirm nuevamente para seguir esperando la misma importación. Una importación fallida se detiene con SYNC_FAILED y su motivo.
  • parlant init --dashboard --json y parlant dashboard project create --json para un proyecto local o autohospedado ahora incluya nextSteps, que termine en project confirm. El AGENTS.md con andamios les dice a los agentes codificadores que confirmen el proyecto una vez que su servidor esté conectado.
  • Después de crear un proyecto administrado cuya configuración encontró cómo ejecutarlo, parlant dashboard project create ahora apunta a parlant dashboard --project ID deploy: el primer despliegue en vivo completa el configuración. La página de configuración del panel es opcional para revisar la configuración.

En desuso

  • Los accesorios avatarUrl, avatarStyle y liveIndicator del widget de chat, en favor de avatar. Todavía funcionan cuando avatar no está configurado.

Fijo

  • Gemini Argon puede reproducir llamadas de herramientas guardadas con su pensamiento original firmado bloques en lugar de recurrir innecesariamente al historial de solo resultados.
  • El filtrado de sesiones por etiquetas ahora devuelve páginas completas y en funcionamiento. cursores de continuación, con recuentos totales consistentes en cualquier orden de clasificación.
  • La paginación del cursor de MongoDB ahora conserva los filtros $or en páginas posteriores, por lo que Los listados filtrados ya no incluyen registros fuera del conjunto solicitado.
  • Las respuestas preparadas ahora conservan vectores de búsqueda separados para su texto y cada señal, por lo que las señales ya no chocan en el índice de relevancia. Se aplica cuando se crean o actualizan respuestas; Los índices existentes no son reconstruido automáticamente.
  • En iPhone, al enfocar el cuadro de mensaje del widget de chat ya no se amplía la página. in, lo que empujó el chat abierto fuera del borde derecho de la pantalla. la caja utiliza una fuente de 16px en las pantallas táctiles, el tamaño por debajo del cual iOS hace zoom.
  • Las herramientas locales y MCP ahora aceptan argumentos de lista separados por comas sin corchetes conservando las comas entre comillas y las listas vacías.
  • El último mensaje del widget de chat ya no aparece entre las sugerencias y cuadro de mensaje cuando algo ocupa el espacio de la transcripción, como el Banner "Conexión interrumpida" que aparece justo después de un envío. la transcripción permaneció fijado en la parte inferior sólo a medida que los mensajes crecían, no cuando su vista se reducía.
  • Los programas de actualización de variables de contexto no válidos se rechazan antes de guardar, por lo que una actualización de programación fallida deja intactos los datos existentes de la variable.
  • Un mensaje de cliente que llega mientras el agente todavía está trabajando en el El anterior ahora reemplaza ese giro, como estaba previsto, incluso cuando el motor estaba en medio de rechazar un paso: una llamada de herramienta o un mensaje rechazado por un gancho de revisión, por el revisor o por moderación. Antes, el rechazo se reiniciaba el paso y descartó la cancelación pendiente, por lo que el agente terminó de responder al primer mensaje y luego contestó el segundo en un turno aparte. Los clientes que envían dos mensajes en rápida sucesión ahora reciben una respuesta que tiene ambos en cuenta.

Seguridad

  • Eleve la versión mínima de python-multipart a 0.0.30 para ambos uv y pips, impidiendo la instalación de versiones afectadas por CVE-2026-53539.

Cambiado

Antes de su primera herramienta llamar al agente dice una línea corta, como "Déjame comprobar eso", por lo que el El visitante no se queda esperando en silencio. Sin él, los preámbulos no tenían sentido: lo que sea que escribió el modelo antes de que se realizara una llamada a la herramienta.

Parlant envió un temperature, que esos modelos rechazan con "temperature está obsoleto para este modelo."; ahora envía uno solo a Modelos Claude 3 y modelos Claude 4 hasta 4.6, que aún lo aceptan.
  • Un esfuerzo de razonamiento basado en un modelo de Claude Fable ahora utiliza el pensamiento adaptativo. de un presupuesto pensado, que Fable rechaza.
  • Un esfuerzo de razonamiento sobre Claude Opus 4.5 ya no falla. Parlant lo envió pensamiento adaptativo, que rechaza ("el pensamiento adaptativo no se apoya en este modelo"); ahora tiene un presupuesto pensado, como lo hacen Sonnet y Haiku 4.5.

parlant v4.0.2

[4.0.2] - 2026-11-05

Added

  • The chat widget lets the AI agent in a visitor's browser talk to your agent over WebMCP (document.modelContext; in Chrome behind a flag today). On every page it's on, the widget registers an ask_agent tool described with the agent's name. A call starts the widget's conversation if there is none yet, as one an agent holds for the customer (customer_represented_by_an_agent), sends the question through the chat, so it shows there with the reply, opens the chat, and answers the browser agent once the turn has ended. Follow-up calls continue the same conversation. The message carries metadata.parlant_widget.asked_by = "customer_agent", so the chat and your tools can tell the visitor's agent from the visitor. Nothing happens in a browser without WebMCP; webmcp={false} turns it off. ParlantTransport's sendMessage takes an optional metadata argument and ensureSession an option for the flag.
  • Server(session_store=..., customer_store=...) accepts an s3://bucket URL to keep sessions and customers in Amazon S3. Give Parlant a bucket of its own. Credentials come from the AWS credential chain; add ?region= or, for S3-compatible storage, ?endpoint=. The storage must support conditional writes, which keep concurrent servers from overwriting each other's updates. Empty collections survive restarts, and a failed migration write leaves the original data in place. Any query other than a lookup by ID, such as listing sessions, reads every object in the collection, so use MongoDB if you need indexed queries at scale.
  • The chat widget (parlant widget init) takes the agent's picture in one avatar prop: { type: "logo", src }, { type: "photo", src, live? } or { type: "video", src?, poster?, live?, launcher? }. A video avatar plays a short muted loop under the header, scrolls away with the conversation once it starts, and keeps its opened size when the chat is expanded. On the closed launcher, launcher crops it onto the face. Leave out src to use the widget's own video of an agent. live adds the green dot, on the video's corner too, red while the server can't be reached. Use an H.264 MP4 saved with -movflags +faststart; iPhone Safari stalls on WebM.

Changed

  • The chat widget's persistent suggestions stand out from its opening ones: outlined and lettered in the theme's primary color on the chat's background, instead of the grey fill.
  • On phones and tablets, the chat widget closes the on-screen keyboard once a message is sent, whether typed or picked from the suggestions, so the reply isn't hidden behind it.
  • With the LiteLLM provider, review routes now default to gemini/gemini-3.8-flash instead of gemini/gemini-3.6-flash, the same model the Gemini provider already uses for them.
  • The lead-gen scaffold's agent no longer guesses when a visitor asks about the business, its products or their project and its product knowledge has no answer. It says it's a great question but hard to answer properly in the chat, offers to connect them with the team, asks for an email or phone number, and passes the question on with request_team_follow_up. Unrelated questions, existing customers' order questions and prices are handled as before. To make that possible, record_lead now accepts a lead with just a goal and a contact: buying_for and role are optional, and an unknown one scores nothing.
  • parlant dashboard project confirm finishes a local or self-hosted project even when its server already holds sessions, such as from trying the agent. It imports them into the dashboard first, as the dashboard's Sync does, and then completes the setup, so the project no longer stays at "Finish setup". An import that takes longer than about 90 seconds stops with SYNC_IN_PROGRESS; run confirm again to keep waiting for the same import. A failed import stops with SYNC_FAILED and its reason.
  • parlant init --dashboard --json and parlant dashboard project create --json for a local or self-hosted project now list nextSteps, ending with project confirm. The scaffolded AGENTS.md tells coding agents to confirm the project once its server is connected.
  • After creating a managed project whose setup check found how to run it, parlant dashboard project create now points to parlant dashboard --project ID deploy: the first live deploy completes the setup. The dashboard's setup page is optional for reviewing the settings.

Deprecated

  • The chat widget's avatarUrl, avatarStyle and liveIndicator props, in favor of avatar. They still work when avatar isn't set.

Fixed

  • Gemini Argon can replay saved tool calls with their original signed thought blocks instead of unnecessarily falling back to result-only history.
  • Filtering sessions by labels now returns complete pages and working continuation cursors, with consistent total counts in either sort order.
  • MongoDB cursor pagination now preserves $or filters on later pages, so filtered listings no longer include records outside the requested set.
  • Canned responses now retain separate search vectors for their text and every signal, so signals no longer collide in the relevance index. Applies when responses are created or updated; existing indexes are not rebuilt automatically.
  • On iPhone, focusing the chat widget's message box no longer zooms the page in, which pushed the open chat off the right edge of the screen. The box uses a 16px font on touch screens, the size below which iOS zooms.
  • Local and MCP tools now accept comma-separated list arguments without brackets while preserving quoted commas and empty lists.
  • The chat widget's latest message no longer slips under the suggestions and message box when something takes the transcript's space, such as the "Connection interrupted" banner appearing just after a send. The transcript stayed pinned to the bottom only as messages grew, not as its view shrank.
  • Invalid context-variable freshness schedules are rejected before saving, so a failed schedule update leaves the variable's existing data intact.
  • A customer message that arrives while the agent is still working on the previous one now replaces that turn, as intended, even when the engine was in the middle of rejecting a step: a tool call or message turned down by a review hook, by the reviewer, or by moderation. Before, the rejection restarted the step and dropped the pending cancellation, so the agent finished replying to the first message and then answered the second one in a separate turn. Customers who send two messages in quick succession now get one reply that takes both into account.

Security

  • Raise the minimum python-multipart version to 0.0.30 for both uv and pip installations, preventing installation of versions affected by CVE-2026-53539.

[4.0.1] - 2026-11-02

Changed

  • parlant init --scaffold lead-gen now creates its agent with preamble_config=p.PreambleConfiguration.encourage(). Before its first tool call the agent says one short line, such as "Let me check that", so the visitor isn't left waiting in silence. Without it, preambles were unmanaged: whatever the model wrote before a tool call went straight through.
  • Every tool in the lead-gen and retail-store scaffolds now has a narration, such as "Checking which days are free" or "Tracking your shipment". The chat shows it while the tool runs, instead of the generic "Running tools".

Fixed

  • With the Anthropic provider, indexing no longer fails on Claude Opus 4.7 and later or any Claude 5 model, including the default routes (Sonnet 5.5 and Haiku 5.5). Parlant sent a temperature, which those models reject with "temperature is deprecated for this model."; it now sends one only to Claude 3 models and Claude 4 models up to 4.6, which still accept it.
  • A reasoning effort on a Claude Fable model now uses adaptive thinking instead of a thinking budget, which Fable rejects.
  • A reasoning effort on Claude Opus 4.5 no longer fails. Parlant sent it adaptive thinking, which it rejects ("adaptive thinking is not supported on this model"); it now gets a thinking budget, as Sonnet and Haiku 4.5 do.
