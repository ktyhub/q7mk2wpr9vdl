lechuga 6.9.0.RELEASE

¡El equipo de Lettuce se complace en anunciar el lanzamiento de Lettuce 6.9.0! Esta versión cambia la forma en que se rechazan los comandos mientras no hay una conexión disponible. Lea el cambio de comportamiento a continuación antes de actualizar.

Lettuce 6 admite Redis 2.6+ hasta Redis 8.2. En términos de tiempo de ejecución de Java, Lettuce requiere al menos Java 8 y funciona con Java 21.

Gracias a todos los contribuyentes que hicieron posible Lettuce 6.9.0.

  • GitHub Discusiones: https://github.com/lettuce-io/lettuce-core/discussions
  • Desbordamiento de pila (Preguntas): https://stackoverflow.com/questions/tagged/lettuce
  • Únase al chat en https://discord.gg/redis y busque el canal "Ayuda: Herramientas Lechuga"
  • Problemas con GitHub (informes de errores, solicitudes de funciones): https://github.com/lettuce-io/lettuce-core/issues *Documentación: https://lettuce.io/core/6.9.0.RELEASE/reference/
  • Javadoc: https://lettuce.io/core/6.9.0.RELEASE/api/

Cambio de comportamiento

Esto se aplica cuando los comandos son rechazados estando desconectado: con DisconnectedBehavior.REJECT_COMMANDS, o con DisconnectedBehavior.DEFAULT y reconexión automática deshabilitados.

  • Clúster Redis: un comando ahora falla inmediatamente cuando la conexión a su nodo de destino aún se está realizando. establecido, por ejemplo, los primeros comandos a un nodo después del inicio, o después de que aparece una nueva asignación de ranura. esto También se aplica a los comandos redirigidos con MOVED/ASK. Antes estos comandos esperaban la conexión intento, hasta el tiempo de espera de conexión.
  • Todos los tipos de conexión: cuando falla la escritura de un comando en el canal, el comando ahora se rechaza en lugar de siendo puesto nuevamente en cola.

Para evitar rechazos inmediatamente después del inicio, conéctese a los nodos del clúster desde el principio.

Este cambio también está en 7.7.0 y posteriores. Las líneas 7.0.x – 7.6.x no lo incluyen.

Correcciones

  • DisconnectedBehavior.REJECT_COMMANDS no falla rápidamente para los comandos del clúster Redis que esperan el establecimiento de conexión de nodo diferido en https://github.com/redis/lettuce/issues/3747 (puerto posterior de https://github.com/redis/lettuce/pull/3782 por @Vaibhav026)

lettuce 6.9.0.RELEASE

The Lettuce team is pleased to announce the Lettuce 6.9.0 release! This release changes how commands are rejected while a connection is not available. Read the behavior change below before you upgrade.

Lettuce 6 supports Redis 2.6+ up to Redis 8.2. In terms of Java runtime, Lettuce requires at least Java 8 and works with Java 21.

Thanks to all contributors who made Lettuce 6.9.0 possible.

  • GitHub Discussions: https://github.com/lettuce-io/lettuce-core/discussions
  • Stack Overflow (Questions): https://stackoverflow.com/questions/tagged/lettuce
  • Join the chat at https://discord.gg/redis and look for the "Help:Tools Lettuce" channel
  • GitHub Issues (Bug reports, feature requests): https://github.com/lettuce-io/lettuce-core/issues
  • Documentation: https://lettuce.io/core/6.9.0.RELEASE/reference/
  • Javadoc: https://lettuce.io/core/6.9.0.RELEASE/api/

Behavior change

This applies when commands are rejected while disconnected: with DisconnectedBehavior.REJECT_COMMANDS, or with DisconnectedBehavior.DEFAULT and auto-reconnect disabled.

  • Redis Cluster: a command now fails right away when the connection to its target node is still being established, for example the first commands to a node after startup, or after a new slot mapping appears. This also applies to commands redirected with MOVED/ASK. Before, these commands waited for the connection attempt, up to the connect timeout.
  • All connection types: when writing a command to the channel fails, the command is now rejected instead of being re-queued.

To avoid rejections right after startup, connect to the cluster nodes up front.

This change is also in 7.7.0 and later. The 7.0.x – 7.6.x lines do not include it.

Fixes

  • DisconnectedBehavior.REJECT_COMMANDS does not fail fast for Redis Cluster commands waiting on lazy node connection establishment in https://github.com/redis/lettuce/issues/3747 (backport of https://github.com/redis/lettuce/pull/3782 by @Vaibhav026)
