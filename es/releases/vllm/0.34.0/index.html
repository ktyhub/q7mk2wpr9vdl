vllm v0.34.0

#v0.34.0

1061 confirmaciones de 412 contribuyentes (120 nuevos). ¡Gracias!

TL;DR

  • 10 modelos nuevos (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe y más).
  • La caché KV extensible está activada de forma predeterminada: vLLM dimensiona la caché KV a partir de la memoria realmente libre después del calentamiento, por lo que la mayoría de los modelos obtienen una caché más grande y un mayor rendimiento.
  • Model Runner V1 ya no está. Model Runner V2 es ahora el único ejecutor de GPU.
  • Grandes aceleraciones en Blackwell y MI355X: decodificación de hasta 1.95× (Paso 5 en GB200), rendimiento de 1.6× (GLM-5.3-Flash), TTFT de aviso largo y rápido 1.24–1.40× (GLM-5.3).
  • Verificación de actualización: el tamaño de bloque predeterminado ahora es 64, las imágenes ROCm 7.2 desaparecieron y se requiere huggingface_hub >= 2.0.0. Consulte [Antes de actualizar](#antes de actualizar).

Destacados

Caché KV extensible, activado de forma predeterminada

  • En CUDA y ROCm, el tamaño de la caché KV se determina a partir de la memoria realmente libre después de la captura y el calentamiento del gráfico CUDA, no de una estimación (#56492).
  • Resultado: un caché más grande (por ejemplo, MiniMax-M3 en H200: 433k → 672k tokens), por lo que el rendimiento es mayor y el TTFT menor con alta concurrencia.
  • Compensación: la latencia de decodificación por token puede aumentar en algunos modelos (TPOT +6–18 % en algunos modelos H200 con simultaneidad 128). Opte por no participar con --gpu-memory-utilization 0.9 o --no-enable-extensible-kv-cache.
  • Reforzado con correcciones para la fragmentación del asignador, OOM de inicio y conectores KV (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Solo modelo Runner V2

  • Se eliminó el modelo Runner V1 (#63373).
  • La superposición de doble lote ahora se ejecuta en MRV2, incluso con decodificación especulativa y DCP (#61464).

Decodificación especulativa

  • Decodificación de sufijos se ejecuta en MRV2 con un especulador de GPU; La Inferencia Ártica ya no es necesaria (#60339).
  • Especuladores personalizados: configuraciones declarativas más un complemento register_speculative_method API (#63205).
  • Gráficos CUDA para especuladores del modelo borrador MRV2 (#60989).
  • Verificación adaptativa funciona con XPress (#65175).
  • El borrador de caché KV coincide con el tipo d del objetivo, por lo que un objetivo FP8 obtiene un borrador de caché FP8 (#65198).

AMD ROCm

  • Las imágenes de lanzamiento y las ruedas son ROCm 10.0 únicamente (#61939).
  • MoRI EPv2 vía --all2all-backend mori (#61361).
  • Decodificación especializada Kimi-K3 en MI355X, suscripción voluntaria (#61435).
  • TRITON_ATTN es el backend de atención predeterminado en RDNA3 y RDNA4 (#60418).

Servicio y operaciones

  • Punto de control/restauración (CRIU + cuda-checkpoint) hasta /checkpoint/prepare, /checkpoint/status y /checkpoint/restore, tanto en el frontend Python como en el Rust (#62570).
  • Reducción de escala de DP+EP tolerante a fallas: se eliminan las filas muertas y se atribuyen sus expertos redis sin reiniciar (#46370).
  • Enlace NUMA de mejor esfuerzo activado de forma predeterminada (#61258).
  • Optar por realizar pedidos de admisión con reconocimiento de caché (#54625).
  • Interfaz Rust: sin estado Respuestas API (#63902) y n > 1 (#65625).

TL;DR

  • 10 new models (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, and more!)
  • Extensible KV cache is on by default: vLLM sizes the KV cache from memory actually free after warmup, so most models get a bigger cache and more throughput.

Highlights

Extensible KV cache, on by default

  • On CUDA and ROCm, the KV cache is sized from memory actually free after CUDA graph capture and warmup, not from an estimate (#56492).
  • Result: a larger cache (e.g. MiniMax-M3 on H200: 433k → 672k tokens), so throughput is higher and TTFT lower at high concurrency.
  • Trade-off: per-token decode latency can rise on some models (TPOT +6–18% on some H200 models at concurrency 128). Opt out with --gpu-memory-utilization 0.9 or --no-enable-extensible-kv-cache.
  • Hardened with fixes for allocator fragmentation, startup OOMs and KV connectors (#67296, #67485, #66731, #66523, #66197, #65137, #66605, #66674).

Model Runner V2 only

  • Model Runner V1 is removed (#63373).
  • Dual-batch overlap now runs on MRV2, including with speculative decoding and DCP (#61464).

Speculative decoding

  • Suffix decoding runs on MRV2 with a GPU speculator; Arctic Inference is no longer needed (#60339).
  • Custom speculators: declarative configs plus a register_speculative_method plugin API (#63205).
  • CUDA graphs for MRV2 draft-model speculators (#60989).
  • Adaptive verification works with XPress (#65175).
  • Draft KV cache matches the target's dtype, so an FP8 target gets an FP8 draft cache (#65198).

  • Best-effort NUMA binding on by default (#61258).
  • Opt-in cache-aware admission ordering (#54625).
  • Rust frontend: stateless Responses API (#63902) and n > 1 (#65625).
