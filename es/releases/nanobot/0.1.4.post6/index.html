nanobot v0.1.4.post6

#nanobot v0.1.4.post6 🐈 nanobot v0.1.4.post6 está aquí: 57 RP fusionados, 27 nuevos contribuyentes y un lanzamiento que se trata menos de agregar área de superficie que de repensar lo que hay debajo. Algunos comunicados tratan sobre lo que puedes hacer. Este trata sobre qué tan limpiamente puedes hacerlo. El tiempo de ejecución del agente se descompuso formalmente, se eliminó una dependencia importante, la transmisión se realizó de un extremo a otro y se cerró una vulnerabilidad de seguridad. Debajo del trabajo característico, v0.1.4.post6 es un punto de inflexión estructural: el tipo de lanzamiento que hace posible el próximo lanzamiento.

Destacados

  • El tiempo de ejecución del agente se descompuso en partes componibles: se extrajo un AgentRunner compartido, los enlaces del ciclo de vida se unificaron en un HookContext formal y el progreso del subagente ahora se conserva incluso en caso de falla. El enrutamiento de comandos se refactorizó en una estructura compatible con complementos y process_direct se unificó para devolver OutboundMessage de manera consistente. Esto no es solo una limpieza: es la base para los comportamientos de los agentes conectables, las estrategias de ejecución personalizadas y las integraciones del ciclo de vida de terceros que vendrán a continuación. (#2524, #2541, #2388, #2338)
  • litellm fue reemplazado por OpenAI + Anthropic SDK nativos: toda la capa de proveedor se reescribió para comunicarse directamente con los SDK ascendentes en lugar de enrutarse a través de litellm. La optimización rápida de la caché para Anthropic, el manejo adecuado de max_completion_tokens para OpenAI o1 y la preservación de firmas de Gemini pensaron que todo esto vino de la mano. Si alguna vez depuró un rastreo de Litellm a las 2 a. m., comprenderá por qué esto es importante. (#2448, #1109, #2468, #2550, #2453)
  • La transmisión fue de un extremo a otro: del proveedor al canal y al CLI, la salida de transmisión ahora fluye como una ruta de primera clase. Feishu obtuvo soporte de transmisión CardKit, los deltas de transmisión en cola se fusionan para reducir las llamadas API y el administrador de canales maneja los límites de transmisión correctamente. Esta es la diferencia entre "el robot está escribiendo..." y verlo pensar. (#2365, #2545, #2497)
  • Se solucionó una vulnerabilidad de seguridad: se corrigió la inyección de correo electrónico y la suplantación de identidad mediante la falta de verificación de autenticación. Los correos electrónicos entrantes ahora verifican SPF/DKIM a través de encabezados Authentication-Results, con verify_dkim y verify_spf habilitados de forma predeterminada. El contenido del correo electrónico está etiquetado con [EMAIL-CONTEXT] para evitar la inyección de avisos de LLM desde los cuerpos de los correos electrónicos. Consulte el aviso para obtener más detalles. (GHSA-4gmr-2vc8-7qh3)
  • La compatibilidad con WeChat llegó como canal completo: WeChat (Weixin) se unió a la familia de canales con encuesta larga HTTP, inicio de sesión con código QR y compatibilidad con el complemento 1.0.3. Además, Telegram, QQ, WhatsApp y Feishu recibieron mejoras en todos los canales, incluidos mecanismos de reintento con retroceso exponencial. (#2412, #2428, #2386, #2478)
  • La cobertura de proveedores siguió expandiéndose: llegaron los proveedores de Mistral y OVMS, Step Fun (阶跃星辰) se unió al ecosistema y los informes de errores de proveedores personalizados se volvieron mucho más honestos: errores API sin procesar en lugar de JSONDecodeError opacos. nanobot continúa encontrando usuarios dondequiera que vivan sus modelos. (#2199, #2472, #2289, #2139)
  • El agente se volvió más inteligente con respecto a los recursos: se realizó el envío simultáneo por sesión, se agregaron capacidades sensoriales multimodales nativas, la estimación de tokens ahora cuenta todos los campos del mensaje y la consolidación de la memoria reserva adecuadamente el margen de finalización. El bucle de agente también maneja CancelledError con elegancia y registra los resultados de los subagentes con las funciones correctas. (#2393, #2304, #2344, #2378, #2239, #2104)
  • Feishu y Telegram subieron de nivel: Feishu obtuvo tarjetas de transmisión, análisis de bloques de código en mensajes de publicación y correcciones para la representación de rebajas y los tipos de medios. Telegram obtuvo soporte para medios URL HTTP(S), grupos de conexiones separados para evitar el agotamiento del grupo y un registro de errores de red más silencioso. Pequeños individualmente, sustanciales juntos. (#2545, #2246, #1814, #1755, #1793, #2247, #2272)
  • CLI y la incorporación se volvieron más capaces: llegó un asistente integrado con todas las funciones, --dir habilita múltiples instancias, /status muestra información de tiempo de ejecución, -h funciona en todas partes y la zona horaria ahora es configurable. El tipo de pulido que hace que la experiencia de la primera ejecución parezca intencionada. (#2101, #1763, #1985, #2123, #2477, #1136, #2266)
  • Infraestructura reforzada en todos los ámbitos: los procesos zombies se cosechan en el tiempo de espera del shell, los almacenes de trabajos cron se limitan a los espacios de trabajo, los esquemas de herramientas MCP manejan los parámetros anulables correctamente, las compilaciones Docker incluyen openssh-client y el conjunto de pruebas se reorganizó en una estructura más limpia. El tipo de trabajo que evita el informe de error que, de otro modo, presentarías el próximo mes. (#2362, #2204, #2230, #2287, #1911, #2427, #2367)

Comunidad

Una cálida bienvenida a nuestros 27 nuevos colaboradores en esta versión. v0.1.4.post6 está formado por la creencia de que el trabajo más importante en código abierto no siempre es el más visible. Reemplazar una dependencia central, descomponer un tiempo de ejecución, cerrar un agujero de seguridad: ninguno de estos hace demostraciones llamativas, pero todos hacen de nanobot un proyecto que puedes desarrollar con más confianza mañana que ayer. Gracias a todos los que contribuyeron con código, correcciones, documentos e ideas. La base se está fortaleciendo. Changelog completo: https://github.com/HKUDS/nanobot/compare/v0.1.4.post5...v0.1.4.post6

nanobot v0.1.4.post6

🐈 nanobot v0.1.4.post6 is here — 57 PRs merged, 27 new contributors, and a release that's less about adding surface area than about rethinking what's underneath.

Some releases are about what you can do. This one is about how cleanly you can do it. The agent runtime got formally decomposed, a major dependency was removed, streaming went end-to-end, and a security vulnerability was closed. Beneath the feature work, v0.1.4.post6 is a structural turning point — the kind of release that makes the next release possible.

Highlights

  • The agent runtime was decomposed into composable pieces — A shared AgentRunner was extracted, lifecycle hooks were unified into a formal HookContext, and subagent progress is now preserved even on failure. Command routing was refactored into a plugin-friendly structure, and process_direct was unified to return OutboundMessage consistently. This isn't just cleanup — it's the foundation for pluggable agent behaviors, custom execution strategies, and third-party lifecycle integrations that are coming next. (#2524, #2541, #2388, #2338)

  • litellm was replaced with native OpenAI + Anthropic SDKs — The entire provider layer was rewritten to talk directly to upstream SDKs instead of routing through litellm. Prompt cache optimization for Anthropic, proper max_completion_tokens handling for OpenAI o1, and Gemini thought signature preservation all came along for the ride. If you've ever debugged a litellm traceback at 2am, you understand why this matters. (#2448, #1109, #2468, #2550, #2453)

  • Streaming went end-to-end — From provider to channel to CLI, streaming output now flows as a first-class path. Feishu gained CardKit streaming support, queued stream deltas are coalesced to reduce API calls, and the channel manager handles stream boundaries correctly. This is the difference between "the bot is typing..." and actually watching it think. (#2365, #2545, #2497)

  • A security vulnerability was patched — Email injection and spoofing via missing authentication verification has been fixed. Inbound emails now verify SPF/DKIM through Authentication-Results headers, with verify_dkim and verify_spf enabled by default. Email content is tagged with [EMAIL-CONTEXT] to prevent LLM prompt injection from email bodies. See the advisory for details. (GHSA-4gmr-2vc8-7qh3)

  • WeChat support landed as a full channel — WeChat (Weixin) joined the channel family with HTTP long-poll, QR code login, and plugin 1.0.3 compatibility. Alongside it, Telegram, QQ, WhatsApp, and Feishu all received cross-channel enhancements including retry mechanisms with exponential backoff. (#2412, #2428, #2386, #2478)

  • Provider coverage kept expanding — Mistral and OVMS providers arrived, Step Fun (阶跃星辰) joined the ecosystem, and custom provider error reporting got much more honest — raw API errors instead of opaque JSONDecodeError. nanobot continues to meet users wherever their models live. (#2199, #2472, #2289, #2139)

  • The agent got smarter about resources — Per-session concurrent dispatch landed, native multimodal sensory capabilities were added, token estimation now counts all message fields, and memory consolidation properly reserves completion headroom. The agent loop also handles CancelledError gracefully and records subagent results with correct roles. (#2393, #2304, #2344, #2378, #2239, #2104)

  • Feishu and Telegram both leveled up — Feishu gained streaming cards, code block parsing in post messages, and fixes for markdown rendering and media types. Telegram got HTTP(S) URL media support, separated connection pools to prevent pool exhaustion, and quieter network error logging. Small individually, substantial together. (#2545, #2246, #1814, #1755, #1793, #2247, #2272)

  • CLI and onboarding became more capable — A full-featured onboard wizard arrived, --dir enables multiple instances, /status shows runtime info, -h works everywhere, and timezone is now configurable. The kind of polish that makes first-run experience feel intentional. (#2101, #1763, #1985, #2123, #2477, #1136, #2266)

  • Infrastructure hardened across the board — Zombie processes are reaped on shell timeout, cron job stores are scoped to workspaces, MCP tool schemas handle nullable params correctly, Docker builds include openssh-client, and the test suite was reorganized into a cleaner structure. The kind of work that prevents the bug report you'd otherwise file next month. (#2362, #2204, #2230, #2287, #1911, #2427, #2367)

Community

A warm welcome to our 27 new contributors in this release.

v0.1.4.post6 is shaped by a belief that the most important work in open source isn't always the most visible. Replacing a core dependency, decomposing a runtime, closing a security hole — none of these make for flashy demos, but all of them make nanobot a project you can build on with more confidence tomorrow than yesterday. Thank you to everyone who contributed code, fixes, docs, and ideas. The foundation is getting stronger.
