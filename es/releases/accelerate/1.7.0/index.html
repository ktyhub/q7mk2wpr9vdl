acelerar v1.7.0

Compilación regional

En lugar de compilar todo el modelo a la vez, la compilación regional apunta primero a bloques repetidos (como capas de decodificador). Esto permite al compilador almacenar en caché y reutilizar código optimizado para bloques posteriores, lo que reduce significativamente el tiempo de compilación de inicio en frío que normalmente se observa durante la primera inferencia. ¡Gracias @IlyasMoutawwakil por la función! Puede ver el punto de referencia completo aquí y consultar nuestra guía de compilación actualizada para obtener más detalles. Para habilitar esta función, configure use_regional_compilation=True en la configuración de TorchDynamoPlugin.

# Configure the compilation backend
dynamo_plugin = TorchDynamoPlugin(
    use_regional_compilation=True,
    ... # other parameters
)
# Initialize accelerator with the plugin
accelerator = Accelerator(dynamo_plugin=dynamo_plugin)
# This will apply compile_regions to your model
model = accelerator.prepare(model)

Gancho de lanzamiento en capas

Hemos introducido un nuevo gancho que permite la conversión ascendente y descendente por capa (por ejemplo, para capas lineales) durante la inferencia. Esto permite a los usuarios ejecutar modelos con tipos de computación y almacenamiento separados, lo que genera ahorros de memoria. El concepto se implementó por primera vez en [difusores] (https://huggingface.co/docs/diffusers/main/en/optimization/memory#layerwise-casting), donde la conversión de modelos a FP8 resultó efectiva sin una degradación importante de la calidad. Contribuido por @sayakpaul en https://github.com/huggingface/accelerate/pull/3427

model = ....
storage_dtype = torch.float8_e4m3fn
compute_dtype = torch.bfloat16
attach_layerwise_casting_hooks(
            model,
            storage_dtype=storage_dtype,
            compute_dtype=compute_dtype,
        )

Mejor soporte para FSDP2

Esta versión incluye numerosas funciones nuevas y correcciones de errores. En particular, hemos agregado soporte para FULL_STATE_DICT, una opción ampliamente utilizada en FSDP, lo que ahora permite que .save_pretrained() en transformadores funcione con modelos envueltos en FSDP2. Ahora también se admite la capacitación QLoRA, pero se necesitan más pruebas. También resolvimos un problema de backend relacionado con la descarga de parámetros a la CPU. Además, se ha solucionado un pico de memoria significativo que se producía cuando se habilitaba cpu_ram_efficient_loading=True. También se incluyen otras mejoras y correcciones menores; consulte la sección Qué ha cambiado para obtener detalles completos.

  • FULL_STATE_DICT ha sido habilitado por @S1ro1 en https://github.com/huggingface/accelerate/pull/3527
  • Soporte QLoRA por @winglian en https://github.com/huggingface/accelerate/pull/3546
  • configurar el backend correctamente para CUDA+FSDP2+cpu-offload en https://github.com/huggingface/accelerate/pull/3574
  • Se corrigió el pico de memoria al usar cpu_ram_efficient_loading=True por @S1ro1 en https://github.com/huggingface/accelerate/pull/3482

Torch.compile cambios importantes para el argumento dynamic

Hemos actualizado la lógica para configurar self.dynamic para preservar explícitamente Ninguno en lugar de establecer el valor predeterminado False cuando la variable de entorno USE_DYNAMIC no está configurada. Este cambio alinea el comportamiento con la documentación de PyTorch para torch.compile. Gracias a @yafshar por contribuir con esta mejora en #3567.

accelerate v1.7.0

Highlights

  • Regional torch.compile compilation — Repeated blocks such as decoder layers can now be compiled and cached independently, reducing cold-start compilation time for large models. Opt in with TorchDynamoPlugin(use_regional_compilation=True) before calling accelerator.prepare(); CLI and environment-variable support arrived in #3572.
  • Layerwise casting for lower-memory inference — The new attach_layerwise_casting_hooks() API (#3427) separates parameter storage from compute precision—for example, FP8 storage with BF16 compute—to reduce memory usage. Validate output quality for your model and workload before relying on FP8 storage.
  • FSDP2 checkpointing and memory improvements — FULL_STATE_DICT support (#3527) lets Transformers’ .save_pretrained() work with FSDP2-wrapped models. CPU-offload backend selection (#3574) and the cpu_ram_efficient_loading=True memory spike (#3482) are also fixed; QLoRA support (#3546) is available but still needs broader validation.
  • Breaking change to implicit torch.compile dynamic behavior — When USE_DYNAMIC is unset, the plugin now preserves dynamic=None instead of defaulting to False (#3567), allowing torch.compile to choose dynamic-shape behavior. If you depended on the previous implicit static default, set dynamic=False explicitly.
  • Distributed-training correctness fixes — set_epoch() now actually takes effect (#3556), which matters for sampler ordering and reproducibility across epochs. Duplicate GPU usage in distributed processing is also prevented (#3526), reducing resource contention in multi-GPU jobs.

Regional compilation

Instead of compiling the entire model at once, regional compilation targets repeated blocks (such as decoder layers) first. This allows the compiler to cache and reuse optimized code for subsequent blocks, significantly reducing the cold start compilation time typically seen during the first inference. Thanks @IlyasMoutawwakil for the feature ! You can view the full benchmark here, and check out our updated compilation guide for more details!

To enable this feature, set use_regional_compilation=True in the TorchDynamoPlugin configuration.

# Configure the compilation backend
dynamo_plugin = TorchDynamoPlugin(
    use_regional_compilation=True,
    ... # other parameters
)
# Initialize accelerator with the plugin
accelerator = Accelerator(dynamo_plugin=dynamo_plugin)
# This will apply compile_regions to your model
model = accelerator.prepare(model)

Layerwise casting hook

We've introduced a new hook that enables per-layer upcasting and downcasting (e.g., for Linear layers) during inference. This allows users to run models with separate storage and compute dtypes, resulting in memory savings. The concept was first implemented in diffusers, where downcasting models to FP8 proved effective without major quality degradation. Contributed by @sayakpaul in https://github.com/huggingface/accelerate/pull/3427

model = ....
storage_dtype = torch.float8_e4m3fn
compute_dtype = torch.bfloat16
attach_layerwise_casting_hooks(
            model,
            storage_dtype=storage_dtype,
            compute_dtype=compute_dtype,
        )

Better FSDP2 support

This release includes numerous new features and bug fixes. Notably, we’ve added support for FULL_STATE_DICT, a widely used option in FSDP, now enabling .save_pretrained() in transformers to work with FSDP2 wrapped models. QLoRA training is now supported as well but more testing is needed. We have also resolved a backend issue related to parameter offloading to CPU. Additionally, a significant memory spike that occurred when cpu_ram_efficient_loading=True was enabled has been fixed. Several other minor improvements and fixes are also included—see the What’s Changed section for full details.

  • FULL_STATE_DICT have been enabled by @S1ro1 in https://github.com/huggingface/accelerate/pull/3527
  • QLoRA support by @winglian in https://github.com/huggingface/accelerate/pull/3546
  • set backend correctly for CUDA+FSDP2+cpu-offload in https://github.com/huggingface/accelerate/pull/3574
  • memory spike fixed when using cpu_ram_efficient_loading=True by @S1ro1 in https://github.com/huggingface/accelerate/pull/3482

Better HPU support:

We have added a documentation for Intel Gaudi hardware ! The support is already available since v1.5.0 through this PR.

  • Add the HPU into accelerate config by @yuanwu2017 in https://github.com/huggingface/accelerate/pull/3495
  • Add Gaudi doc by @regisss in https://github.com/huggingface/accelerate/pull/3537

Torch.compile breaking change for dynamic argument

We've updated the logic for setting self.dynamic to explicitly preserve None rather than defaulting to False when the USE_DYNAMIC environment variable is unset. This change aligns the behavior with the PyTorch documentation for torch.compile. Thanks to @yafshar for contributing this improvement in #3567.
