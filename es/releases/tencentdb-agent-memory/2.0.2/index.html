TencentDB-Agente-Memoria v2.0.2

[2.0.2] - 2026-10-09

Posicionamiento del producto: permita que la experiencia, los documentos y el código del Agente se conviertan en activos reutilizables para el próximo Agente Leer archivos directamente. Consulte README_CN.md para obtener más detalles.

🗄️ Backend de almacenamiento escalable · Soporta MongoDB

La memoria del equipo ya no está ligada a una única base de datos y las capacidades de back-end de MongoDB se complementan aún más:

  • Se agregaron dos nuevos tipos de almacenamiento, aviso de memoria y referencia de generación, que cubren más estructuras de datos de memoria.
  • La entrada con un clic ./start-all-mongo.sh escribirá persistentemente STORE_MODE en .env para inicios posteriores. Mantenga el mismo backend, no más configuraciones cada vez
  • Se corrigió la capacidad de autocuración de los escenarios de conflicto de índice. Los registros predeterminados/extraídos repetidos ya no causan errores de inicio.

🔀 Más acceso de clientes

  • OpenCode Se agregó el paquete de configuración del adaptador de memoria oficial (incluido opencode.json y documentación de acceso). Puede acceder a él siguiendo las instrucciones y no es necesario escribir el código del complemento.
  • OpenCode admite la estructura de configuración del proveedor v2 de 2.0, y la nueva versión del cliente puede reutilizar directamente el opencode.v2.json oficial
  • Arnés DeepSeek Se agregó la adaptación del escritorio dsh; el método de configuración puede consultar la parte 1.6 de ./agents/dsh/README.md
  • Se agregó acceso al cliente Pi (similar al cliente AI Agent de Codex, usando el protocolo OpenAI Chat)

🧠 Importación de fuente externa (Wiki/Código/Tareas)

  • Se agregó la capacidad de importar tareas desde sistemas de gestión de tareas externos. Las tarjetas de tareas muestran directamente la fuente y admiten la copia y paginación de ID.
  • Se agregó registro de fuente de código externo (repositorio privado) y aislamiento de credenciales. Cada equipo tiene credenciales independientes y son invisibles entre sí.
  • Se agregó la importación de fuente externa Wiki para completar el enlace de importación de activos externos junto con la fuente del código y la fuente de la tarea.

🧰Optimización de la experiencia de habilidades

  • Se agrega un nuevo modo estricto a la extracción de habilidades por lotes de inicio en frío, lo que hace que la calidad de la extracción sea más controlable.
  • La extracción de habilidades sigue automáticamente el idioma del usuario y genera contenido más acorde con los hábitos de uso.
  • La lista de habilidades admite la clasificación por actividad de uso, lo que facilita la búsqueda de habilidades de alta frecuencia.

🎛️ Panel del concentrador de memoria

  • Las tarjetas de tareas admiten visualización de origen, copia de ID y optimización de paginación, lo que hace que las interacciones de importación por lotes sean más fluidas
  • El filtrado de tiempo se restablece automáticamente cuando se actualiza manualmente y los recuerdos recién generados se pueden ver inmediatamente

🔄 Experiencia de sesión y acceso

  • La guía de sesión es más estable con más clientes: el único Agente se selecciona automáticamente, la confirmación de activos es más precisa y el valor predeterminado falla Omitir automáticamente en lugar de quedarse atascado
  • Se solucionó el problema de las ventanas emergentes repetidas del subagente paralelo WorkBuddy y la normalización de la sesión es más sólida.
  • Se corrigieron problemas que afectaban la experiencia, como comandos de memoria, contaminación de resultados de herramientas y duplicación de mensajes históricos en varios clientes.

🐛 Arreglar

  • Se corrigieron anomalías de recuperación de BM25, contaminación de resultados de la herramienta L0 y problemas de visualización del texto original en escenarios sin incrustación.
  • Se solucionaron problemas como la recuperación de memoria vacía, mensajes históricos duplicados y truncamiento de listas de cambio de varios equipos.
  • Se corrigieron problemas como la falta de instrucciones AGENTS.md de Claude Code
  • Se corrigieron problemas de compatibilidad de scripts de implementación en algunos entornos.

TencentDB-Agent-Memory v2.0.2

Highlights

  • MongoDB graduates to a sticky, first-class backend — Two new stores (memory-prompt, generation-ref) fill out the Mongo schema, but the adoption-relevant change is behavioral: ./start-all-mongo.sh now persists STORE_MODE into .env, so your backend choice survives restarts instead of being re-declared every launch. Self-healing for index conflicts means duplicate default/extracted records no longer abort startup — expect fewer cold-start failures on shared collections.
  • Client integration goes config-only and broader — OpenCode ships an official Memory adapter (opencode.json + docs, no plugin code) and supports the 2.0 v2 provider schema (opencode.v2.json); DeepSeek Harness desktop (./agents/dsh/README.md §1.6) and Pi — a Codex-like agent on the OpenAI Chat protocol — are also onboarded. Watch the v1-vs-v2 provider split: load the config matching your client version or the adapter won't attach.
  • External asset import closes the loop, with credential isolation — Tasks import from external task systems with source badges, ID copy, and pagination; private repos register as code sources with per-team credentials that are mutually invisible; Wiki joins as the third source. The isolation is the security-relevant win — teams can share one deployment without cross-reading each other's private repos.
  • Skill extraction gets guardrails and ranking — Cold-start batch extraction adds a strict mode for quality control, generated content auto-follows the user's language, and the list can sort by usage activity so high-frequency skills surface. For adopters, strict mode is the knob to reach for when auto-extracted skills are noisy.
  • Recall and session reliability harden — BM25 recall without embeddings, L0 tool-result pollution, empty-recall cases, duplicate history messages, multi-team list truncation, and lost AGENTS.md instructions in Claude Code are all fixed. Note one behavior change in the hub: manual refresh now resets the time filter so newly generated memories appear immediately — relevant if you rely on filtered views.
  • Breaking changes — None reported in v2.0.2.

[2.0.2] - 2026-10-09

产品定位：让 Agent 的经验、文档、代码沉淀成可复用资产，让下一位 Agent 直接读档。详见 README_CN.md。

🗄️ 存储后端可扩展 · 支持 MongoDB

团队记忆不再绑定单一数据底座，MongoDB 后端能力进一步补全：

  • 新增 memory-prompt 与 generation-ref 两类存储，覆盖更多记忆数据结构
  • 一键入口 ./start-all-mongo.sh 会把 STORE_MODE 持久化写入 .env，后续启动 保持同一后端，不再每次重复配置
  • 修复索引冲突场景的自愈能力，重复的默认/抽取记录不再导致启动报错

🔀 更多客户端接入

  • OpenCode 新增官方 Memory adapter 配置包（含 opencode.json 与接入文档），按说明配置即可接入，无需编写插件代码
  • OpenCode 支持 2.0 的 v2 provider 配置结构，新版客户端可直接复用官方 opencode.v2.json
  • DeepSeek Harness 新增 dsh 桌面端适配，配置方式可参考 ./agents/dsh/README.md 中 1.6 的部分
  • 新增 Pi 客户端接入（类似 Codex 的 AI Agent 客户端，走 OpenAI Chat 协议）

🧠 外部源导入（Wiki / 代码 / 任务）

  • 新增从外部任务管理系统导入 Task 的能力，任务卡片直接展示来源、支持 ID 复制与分页
  • 新增外部代码源（私有仓）注册与凭据隔离，各团队持有独立凭据、互不可见
  • 新增 Wiki 外部来源导入，与代码源、任务源一起补齐外部资产导入链路

🧰 技能（Skill）体验优化

  • 冷启动批量技能抽取新增严格模式，抽取质量更可控
  • 技能抽取自动跟随用户语言，生成内容更贴合使用习惯
  • 技能列表支持按使用活跃度排序，高频技能更容易被找到

🎛️ Memory Hub 面板

  • 任务卡片支持来源展示、ID 复制与分页优化，批量导入交互更顺畅
  • 手动刷新时自动重置时间筛选，新产生的记忆能即时看到

🔄 会话与接入体验

  • 会话引导在更多客户端下更稳定：自动选中唯一 Agent、资产确认更精准、预设失败时 自动绕过而非卡住
  • 修复 WorkBuddy 并行子代理反复弹窗的问题，会话归一更稳健
  • 修复多种客户端下记忆命令、工具结果污染、历史消息重复等影响体验的问题

🐛 修复

  • 修复无 embedding 场景下 BM25 召回异常、L0 工具结果污染与原文展示问题
  • 修复记忆召回为空、历史消息重复、多团队切换列表截断等问题
  • 修复 Claude Code 的 AGENTS.md 指令丢失等问题
  • 修复部署脚本在部分环境下的兼容性问题
