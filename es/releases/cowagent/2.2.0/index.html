🧩 Centro de capacidades

El antiguo menú Habilidades ahora es Capacidad, un lugar único en la consola web y el escritorio client para administrar herramientas integradas, herramientas MCP y habilidades:

  • Instalación de habilidades: instale desde Cow Skill Hub, GitHub o ClawHub, o cargue un archivo, un SKILL.md o una carpeta. Cada habilidad se obtiene una vista previa primero y solo se instala después de que usted confirme.
  • Configuración de MCP: agregue, edite y elimine servidores MCP en la interfaz de usuario, cubriendo los transportes stdio, SSE y HTTP Streamable. Tanto la edición de formulario como la de JSON están disponibles, y puede pegar una o más entradas de mcpServers directamente. Guardar comprueba la conexión y enumera las herramientas del servidor; Los cambios entran en vigor en el siguiente mensaje sin necesidad de reiniciar. Gracias @tsumon (#3155)
  • Diagnóstico de recuperación de herramientas: vea cómo se clasificaron las herramientas de MCP y por qué la recuperación retrocedió durante una conversación, lo que facilita descubrir por qué no se seleccionó una herramienta. Gracias @zhongjunqi7657 (#3165)

🤝 Colaboración entre múltiples agentes

  • Transferencia de tareas como mensajes separados: cuando un Agente delega una tarea a un miembro del equipo, la respuesta del miembro se transmite como su propio mensaje con su propio nombre y avatar, tanto en la consola web como en el escritorio client.
  • Gestión de sesiones de equipo: al borrar el contexto ahora se borra para todos los participantes en una sesión de equipo; un chat grupal muestra a sus miembros en la lista de sesiones antes de que se envíe el primer mensaje; el selector @ puede seleccionar el Agente propietario de la sesión.
  • Aislamiento de datos: las habilidades, las vistas previas de archivos cargados y los directorios de sitios web ahora tienen un alcance por Agente.
  • Correcciones:
    • Se corrigió que un agente respondiera en nombre de un miembro del equipo y que las llamadas de herramientas del propio agente desaparecieran después de una actualización.
    • Se corrigieron los agentes eliminados que permanecían en las listas de miembros, lo que hacía que los chats directos no pudieran usar herramientas (Gracias @Frank-zhu0404 #3234).
    • Se corrigió que el Agente predeterminado no se resolviera al crear miembros del equipo y limpiar los equipos del canal (Gracias @c020627 #3205).
    • Se corrigieron algunos puntos finales que no podían ubicar al Agente cuando el parámetro se enviaba solo en el cuerpo de la solicitud (Gracias @c020627 #3177).

🖥 Actualizaciones de consola

  • Reconstrucción de frontend y backend: las páginas de frontend de la consola web y los controladores API de backend se dividen en módulos de funciones, reemplazando los archivos individuales de gran tamaño que se habían vuelto difíciles de mantener. Los activos de frontend se cargan por módulo y se almacenan en caché, por lo que una actualización ya no descarga todo nuevamente. Cada página tiene su propia URL (como /agents, /settings, /scheduler), el navegador avanza y retrocede, la actualización permanece en la página actual y la antigua dirección /chat se redirige automáticamente. Gracias @zkjqd (#3167, #3172)
  • Navegador de mensajes: salta rápidamente a preguntas anteriores de una sesión. La consola web abre una lista de preguntas desde un botón en el encabezado y el escritorio client agrega una barra de navegación a la derecha.
  • Actualización One-click: el menú de versión en la barra lateral busca y aplica actualizaciones de origen en un click. Se realiza una copia de seguridad de los datos del usuario antes de la actualización y una actualización fallida no afecta el servicio en ejecución. Gracias @tsumon (#3154)
  • Estado de respuesta: las respuestas detenidas, interrumpidas y en curso se etiquetan en consecuencia. Una respuesta interrumpida por un reinicio del servicio muestra un aviso claro y, después de una actualización, puede seguir siguiendo una respuesta que aún se está generando.

🧠 Base de conocimientos y memoria

  • Reclasificación: la recuperación de memoria admite un modelo de reclasificación opcional que vuelve a puntuar los resultados recuperados para una mayor precisión. Está desactivado de forma predeterminada y habilitado a través de rerank_provider. Gracias @SummerCaptain (#3230)
  • Puntuación de recuperación híbrida: la recuperación de vectores y palabras clave ahora se fusiona con puntuaciones normalizadas por rango, lo que corrige puntuaciones diluidas cuando un lado no tiene aciertos y escalas de puntuación que no coinciden entre los dos. Gracias @SummerCaptain (#3164)
  • Índice de la base de conocimientos: index.md se actualiza cuando se eliminan o mueven documentos (Gracias @alanyz106 #3237); un índice grande inyecta solo la lista de títulos para evitar ocupar demasiado contexto de conversación.
  • Base de conocimientos compartida: lectura fija y sincronización de una base de conocimientos compartida ubicada fuera del espacio de trabajo del Agente (Gracias @lorenzozanee #3182, @Jeremy-xuan #3183); Las ediciones realizadas a través de herramientas o la consola ahora marcan el índice para actualizar (Gracias @NBSW002 #3184, @c020627 #3206).
  • Memoria a largo plazo: cuando MEMORY.md excede su límite de longitud, las entradas más recientes se mantienen primero (Gracias @SEVEN-us #3244).
  • fragmentación de documentos: el contenido fijo antes del primer encabezado de un documento Markdown largo no se indexa y el contenido se indexa dos veces cuando se omiten los niveles de encabezado; /memory status le solicita que reconstruya el índice (Gracias @Bdysj #3309).
  • Carga de sesión: abrir una sesión ya no activa un escaneo de memoria y una reconstrucción del índice, por lo que el primer mensaje en una nueva sesión responde más rápido.

📐 Contexto y costo del token

  • Tasa de aciertos de caché de modelo más alta: el mensaje del sistema ahora muestra solo la fecha actual y la hora exacta proviene de una nueva herramienta time. El aviso del sistema permanece estable durante todo el día, lo que mejora en gran medida las tasas de aciertos de la caché del modelo y reduce el uso de tokens. Gracias @a1094174619 (#3250)
  • Recorte de contexto: el recorte de presupuesto por turnos y de tokens se fusiona en un único pase basado en el presupuesto. No se realiza llamada de resumen estando dentro del presupuesto, evitando solicitudes de modelos innecesarias, y siempre se mantiene el turno anterior. Gracias @liuns-yang (#3188), @Frank-zhu0404 (#3199), @lorenzozanee (#3185)
  • Mensajes de seguimiento: los mensajes que envías mientras el modelo aún está transmitiendo ahora se recogen rápidamente (Gracias @tsumon #3190).

🤖 Capacidades del modelo

  • Nuevos modelos: se agregaron gpt-6.1-sol, gpt-6-luna y gpt-6-sol, con gpt-6.1-sol como modelo OpenAI recomendado por defecto (la llamada de herramientas pasa por las Respuestas API); Se agregó claude-opus-5-5 como modelo Claude recomendado por defecto.
  • Ventana de contexto: la familia Claude 5 (claude-opus-5-5, claude-opus-5, claude-sonnet-5, claude-fable-5, etc.) ahora se cuenta en una ventana de contexto de 1M y una salida máxima de 128K, en lugar de los 200K planos anteriores. Claude 4 y anteriores no han cambiado.
  • Respuestas de OpenAI API: una nueva configuración de open_ai_api_type. Configúrelo en responses para llamar a las respuestas API, para puntos finales que ya no proporcionan /chat/completions. El auto predeterminado mantiene el comportamiento existente.
  • MiniMax: la comprensión de imágenes ahora utiliza la capacidad multimodal nativa de M3 (Gracias @octo-patch #3160).
  • Qwen: qwen3.8-max y qwen3.8-flash se manejan como modelos de pensamiento híbrido; Se corrigieron las sesiones de DashScope que ignoraban el mensaje del sistema establecido por el complemento de función (Gracias @Bdysj #3310).
  • Reconocimiento de voz: utiliza el modelo ASR configurado en lugar de utilizar siempre whisper-1.
  • AnySearch: región e idioma de búsqueda configurables, con validación más estricta de los resultados devueltos (Gracias @WangPan59 #3153, #3163).

🛡 Estabilidad y seguridad

Esta versión hace que la ejecución de tareas sea más confiable y refuerza sistemáticamente el acceso a recursos externos y la escritura de archivos locales:

  • Ejecución persistente: la respuesta del modelo, las llamadas a las herramientas y los resultados de cada paso se escriben en la base de datos de la sesión tan pronto como se completa el paso, en lugar de hacerlo todo a la vez al final del turno. Después de un reinicio del servicio o una salida inesperada del proceso, un turno interrumpido se restaura junto con sus pasos completados, y el siguiente mensaje puede continuar desde allí. Gracias @liuns-yang (#3191)
  • Límites de descarga: las descargas externas (medios de canal, imágenes de terminal, comprensión de imágenes, archivos de palabras clave y más) tienen un límite en el tamaño del archivo y el tiempo total, por lo que los archivos de gran tamaño o las conexiones lentas no pueden afectar el servicio. La comprensión de la imagen revalida la dirección en cada redireccionamiento. Gracias @rudycelekli (#3255, #3256, #3257, #3264, #3266, #3267, #3268, #3269, #3270, #3271, #3272), @c020627 (#3219, #3225, #3252, #3300, #3322)
  • Tiempos de espera de solicitudes: cada solicitud externa de modelos, voz, traducción y más ahora tiene un tiempo de espera, por lo que un canal ascendente que no responde ya no cuelga la conversación. Gracias @c020627 (#3217, #3220, #3240, #3254, #3275)
  • Escrituras de configuración segura: config.json, configuraciones de complementos, listas de modelos, tareas programadas, configuraciones de habilidades, archivos de credenciales, MEMORY.md y más se escriben de forma atómica, por lo que una escritura que falla a mitad de camino no puede dañar el archivo original; un archivo de tarea programada dañado se restaura automáticamente desde su copia de seguridad. Gracias @c020627 (#3223, #3239, #3241, #3242, #3259, #3273, #3274, #3276, #3279, #3280, #3281), @rudycelekli (#3260)
  • Archivos temporales: los nombres de archivos recibidos por los canales se limitan al directorio temporal y tienen una longitud limitada (Gracias @Lesereingrape #3247, #3248, @c020627 #3212, #3301); los medios descargados, los archivos adjuntos de respuesta y el discurso sintetizado se almacenan en el directorio temporal del Agente propietario (Gracias @c020627 #3198, #3207, #3208, #3213); el directorio temporal se limpia cuando no se puede extraer un archivo de habilidades (Gracias @Lesereingrape #3325).
  • Redacción de registros: las credenciales del canal están enmascaradas en los registros de depuración (Gracias @fuxicodex #3228).

CowAgent 2.2.0

Highlights

  • Capabilities Center replaces Skills, MCP goes self-service — The Skills menu is now Capabilities, unifying built-in tools, MCP tools, and skills in one place. You can add/edit/remove MCP servers in the UI across stdio, SSE, and Streamable HTTP, edit as form or JSON, paste mcpServers entries, and saving validates the connection and lists the discovered tools; changes apply on the next message with no restart (#3155). Tool retrieval diagnostics now show how MCP tools were ranked and why retrieval fell back (#3165), and installs are preview-then-confirm. Practically: far less hand-editing of config to wire up tools, plus a concrete way to debug why a tool wasn't selected.

  • New models and a context-window jump — Added gpt-6.1-sol (now the recommended OpenAI default, tool calls via the Responses API), gpt-6-luna, gpt-6-sol, and claude-opus-5-5 (recommended Claude default). The whole Claude 5 family is now budgeted at 1M context / 128K output instead of a flat 200K; Claude 4 and earlier are unchanged. A new open_ai_api_type setting lets you force responses for OpenAI-compatible endpoints that dropped /chat/completions, while default auto preserves current behavior. Watch this if you pin context budgets or still assume the old 200K Claude limit.

  • Context and token cost — The system prompt now carries only the current date, with exact time moved to a new time tool, keeping the prompt stable across the day for much higher cache hit rates (#3250). Context trimming merges turn- and token-based logic into one budget-driven pass that skips summarization while within budget and always keeps the previous turn (#3188, #3199, #3185); messages sent mid-stream are picked up promptly (#3190). Expect lower token spend and fewer needless model calls — but note that anything keying off the system-prompt hash (e.g., your own caching layer) changes.

  • Memory retrieval gets more precise — An optional rerank model re-scores recalled results via rerank_provider (off by default) (#3230), and hybrid vector+keyword search now fuses by rank-normalized scores, fixing diluted scores and mismatched scales when one side has no hits (#3164). Chunking fixes cover pre-heading content and skipped heading levels (#3309), an oversized index.md injects only titles, and opening a session no longer triggers a memory scan and index rebuild, so first messages respond faster. Enabling rerank adds an extra model call; hybrid scoring changes result ordering without any migration.

  • Multi-agent isolation and a QQ behavior change to plan for — Delegated tasks now stream as their own named messages, and skills, uploaded-file previews, and website directories are scoped per Agent (plus fixes for deleted Agents breaking direct-chat tool use, #3234, and default-Agent resolution, #3205). The migration-relevant bit: QQ group sessions now default to one session per member; set "group_shared_session": true to restore the previous group-wide shared session (#3209). Audit your QQ channel configs before upgrading if you relied on shared group context.

  • Production hardening and a restructured console — Steps are persisted to the session DB incrementally so interrupted turns resume after a restart (#3191); external downloads are size/time-capped with redirect revalidation, every upstream request has a timeout, config writes are atomic, temp files are confined to the owning Agent, and channel credentials are masked in logs. The console frontend/backend are split into feature modules with per-page URLs (/agents, /settings, /scheduler), /chat now redirects, and one-click source updates back up data first (#3167, #3172, #3154). Check any bookmarks or integrations still pointing at the old /chat route.

🧩 Capabilities Center

The former Skills menu is now Capabilities, a single place in the Web console and desktop client to manage built-in tools, MCP tools, and skills:

  • Skill installation: install from Cow Skill Hub, GitHub, or ClawHub, or upload an archive, a SKILL.md, or a folder. Every skill is previewed first and only installed after you confirm.
  • MCP configuration: add, edit, and remove MCP servers in the UI, covering the stdio, SSE, and Streamable HTTP transports. Both form and JSON editing are available, and you can paste one or more mcpServers entries directly. Saving checks the connection and lists the server's tools; changes take effect on the next message without a restart. Thanks @tsumon (#3155)
  • Tool retrieval diagnostics: see how MCP tools were ranked and why retrieval fell back during a conversation, making it easier to find out why a tool was not picked. Thanks @zhongjunqi7657 (#3165)

🤝 Multi-Agent Collaboration

  • Task handoff as separate messages: when an Agent delegates a task to a team member, the member's reply streams as its own message under its own name and avatar, on both the Web console and the desktop client.
  • Team session management: clearing context now clears it for every participant in a team session; a group chat shows its members in the session list before the first message is sent; the @ picker can select the Agent that owns the session.
  • Data isolation: skills, uploaded file previews, and website directories are now scoped per Agent.
  • Fixes:
    • Fixed an Agent answering on behalf of a team member, and an Agent's own tool calls disappearing after a refresh.
    • Fixed deleted Agents lingering in member lists, which left direct chats unable to use tools (Thanks @Frank-zhu0404 #3234).
    • Fixed the default Agent not being resolved when building team members and cleaning up channel teams (Thanks @c020627 #3205).
    • Fixed some endpoints failing to locate the Agent when the parameter was sent only in the request body (Thanks @c020627 #3177).

🖥 Console Upgrades

  • Frontend and backend rebuild: the Web console's frontend pages and backend API controllers are split into feature modules, replacing the oversized single files that had become hard to maintain. Frontend assets load per module and are cached, so a refresh no longer downloads everything again. Each page has its own URL (such as /agents, /settings, /scheduler), browser back and forward work, a refresh stays on the current page, and the old /chat address redirects automatically. Thanks @zkjqd (#3167, #3172)
  • Message navigator: jump quickly to earlier questions in a session. The Web console opens a question list from a button in the header, and the desktop client adds a navigation rail on the right.
  • One-click update: the version menu in the sidebar checks for and applies source updates in one click. User data is backed up before updating, and a failed update does not affect the running service. Thanks @tsumon (#3154)
  • Reply status: stopped, interrupted, and in-progress replies are labeled accordingly. A reply cut off by a service restart shows a clear notice, and after a refresh you can keep following a reply that is still being generated.

🧠 Memory & Knowledge Base

  • Reranking: memory retrieval supports an optional rerank model that re-scores recalled results for better precision. It is off by default and enabled via rerank_provider. Thanks @SummerCaptain (#3230)
  • Hybrid retrieval scoring: vector and keyword retrieval are now fused by rank-normalized scores, fixing diluted scores when one side has no hits and mismatched score scales between the two. Thanks @SummerCaptain (#3164)
  • Knowledge base index: index.md is updated when documents are deleted or moved (Thanks @alanyz106 #3237); a large index injects only the list of titles to avoid taking up too much conversation context.
  • Shared knowledge base: fixed reading and syncing a shared knowledge base located outside the Agent workspace (Thanks @lorenzozanee #3182, @Jeremy-xuan #3183); edits made through tools or the console now mark the index for refresh (Thanks @NBSW002 #3184, @c020627 #3206).
  • Long-term memory: when MEMORY.md exceeds its length limit, the newest entries are kept first (Thanks @SEVEN-us #3244).
  • Document chunking: fixed content before the first heading of a long Markdown document not being indexed, and content being indexed twice when heading levels are skipped; /memory status prompts you to rebuild the index (Thanks @Bdysj #3309).
  • Session loading: opening a session no longer triggers a memory scan and index rebuild, so the first message in a new session responds faster.

Related docs: Memory

📐 Context & Token Cost

  • Higher model cache hit rate: the system prompt now carries only the current date, and the exact time comes from a new time tool. The system prompt stays stable throughout the day, which greatly improves model cache hit rates and lowers token usage. Thanks @a1094174619 (#3250)
  • Context trimming: turn-based and token-budget trimming are merged into a single budget-driven pass. No summarization call is made while within budget, avoiding unnecessary model requests, and the previous turn is always kept. Thanks @liuns-yang (#3188), @Frank-zhu0404 (#3199), @lorenzozanee (#3185)
  • Follow-up messages: messages you send while the model is still streaming are now picked up promptly (Thanks @tsumon #3190).

🤖 Model Capabilities

  • New models: added gpt-6.1-sol, gpt-6-luna and gpt-6-sol, with gpt-6.1-sol as the default recommended OpenAI model (tool calling goes through the Responses API); added claude-opus-5-5 as the default recommended Claude model.
  • Context window: the Claude 5 family (claude-opus-5-5, claude-opus-5, claude-sonnet-5, claude-fable-5, etc.) is now counted at a 1M context window and 128K max output, instead of the previous flat 200K. Claude 4 and earlier are unchanged.
  • OpenAI Responses API: a new open_ai_api_type setting. Set it to responses to call the Responses API, for endpoints that no longer provide /chat/completions. The default auto keeps the existing behavior.
  • MiniMax: image understanding now uses M3's native multimodal capability (Thanks @octo-patch #3160).
  • Qwen: qwen3.8-max and qwen3.8-flash are handled as hybrid-thinking models; fixed DashScope sessions ignoring the system prompt set by the role plugin (Thanks @Bdysj #3310).
  • Speech recognition: uses the configured ASR model instead of always using whisper-1.
  • AnySearch: configurable search region and language, with stricter validation of returned results (Thanks @WangPan59 #3153, #3163).

  • DingTalk:
    • AI card streaming replies when dingtalk_card_enabled is on (Thanks @tsumon #3162); replies fall back to Markdown when cards are off or a card fails to send.
    • Receives file attachments (Thanks @tsumon #3161).
    • Fixed error and notice replies being dropped, group messages outside the allowlist raising errors, and rich-text messages without images getting no response (Thanks @Lesereingrape #3282, #3284, #3293).
  • QQ:

    • Group chat sessions now follow group_shared_session, consistent with other channels: each member gets their own session by default, whereas earlier versions shared one session across the whole group. Set "group_shared_session": true to keep the previous behavior (Thanks @c020627 #3209).
  • Feishu: group messages that only @-mention other members no longer trigger a reply, and rich-text group messages are checked against their @ list (Thanks @c020627 #3173); image and file replies upload directly from memory (Thanks @c020627 #3226); webhook callbacks now verify the token.
  • WeCom: the WeCom app supports file and video replies (Thanks @c020627 #3249) and replying with locally generated images (Thanks @Lesereingrape #3312), and its callback verifies the Corp ID (Thanks @c020627 #3159); WeCom Bot group messages are correctly recognized as @-mentions (Thanks @c020627 #3193).

  • WeChat: fixed managing multiple channel instances in multi-Agent setups; login state is kept when channel instances change.
  • Video replies: Discord, Slack, Telegram, Feishu, DingTalk, WeChat Customer Service, and WeChat Official Account upload locally generated videos directly, instead of dropping them or sending only the file path (Thanks @Lesereingrape #3289, #3299, #3321, @c020627 #3297).

🛡 Stability & Security

This release makes task execution more reliable and systematically hardens external resource access and local file writes:

  • Persistent execution: each step's model reply, tool calls, and results are written to the session database as soon as the step completes, instead of all at once at the end of the turn. After a service restart or an unexpected process exit, an interrupted turn is restored together with its completed steps, and the next message can continue from there. Thanks @liuns-yang (#3191)
  • Download limits: external downloads — channel media, terminal images, image understanding, keyword files, and more — are capped in file size and total time, so oversized files or slow connections cannot drag the service down. Image understanding re-validates the address on every redirect. Thanks @rudycelekli (#3255, #3256, #3257, #3264, #3266, #3267, #3268, #3269, #3270, #3271, #3272), @c020627 (#3219, #3225, #3252, #3300, #3322)
  • Request timeouts: every external request for models, voice, translation, and more now has a timeout, so an unresponsive upstream no longer hangs the conversation. Thanks @c020627 (#3217, #3220, #3240, #3254, #3275)
  • Safe config writes: config.json, plugin configs, model lists, scheduled tasks, skill configs, credential files, MEMORY.md, and more are written atomically, so a write that fails midway cannot corrupt the original file; a corrupted scheduled-task file is restored from its backup automatically. Thanks @c020627 (#3223, #3239, #3241, #3242, #3259, #3273, #3274, #3276, #3279, #3280, #3281), @rudycelekli (#3260)
  • Temporary files: file names received by channels are confined to the temporary directory and limited in length (Thanks @Lesereingrape #3247, #3248, @c020627 #3212, #3301); downloaded media, reply attachments, and synthesized speech are stored in the owning Agent's temporary directory (Thanks @c020627 #3198, #3207, #3208, #3213); the temporary directory is cleaned up when a skill archive fails to extract (Thanks @Lesereingrape #3325).
  • Log redaction: channel credentials are masked in debug logs (Thanks @fuxicodex #3228).
