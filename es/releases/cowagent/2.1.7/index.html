CowAgent 2.1.7

🌐 Inglés | 中文

🗂 Múltiples espacios de trabajo

El Agente ya no está vinculado a un único directorio: puede configurar varios espacios de trabajo de proyectos y asignar el suyo propio a cada sesión. Disponible tanto en la consola web como en el escritorio client:

  • Múltiples espacios de trabajo: cree o abra cualquier directorio como espacio de trabajo del proyecto; Los documentos, páginas web y el código que produce el Agente se crean y gestionan allí.
  • Espacio de trabajo por sesión: cada sesión está vinculada a su propio espacio de trabajo del proyecto, por lo que las tareas que se ejecutan en paralelo permanecen fuera del camino de las demás.
  • Modelo por sesión: cambia el modelo para una sola sesión; Las nuevas sesiones comienzan desde el valor predeterminado global.
  • Sesiones agrupadas: la lista de sesiones se agrupa por espacio de trabajo, con fijación, reordenación, cambio de nombre y eliminación.
  • Recursos compartidos del sistema: la memoria, las habilidades y la base de conocimientos aún se encuentran en el espacio de trabajo del sistema (~/cow de forma predeterminada).

🔐 Modos de permiso

Las sesiones ahora tienen su propio modo de permiso, que funciona junto con los espacios de trabajo para controlar hasta dónde puede llegar el Agente:

  • Tres niveles: solo lectura, escritura en el espacio de trabajo y acceso completo, configurados de forma independiente para cada sesión.
  • Modo predeterminado: elija un modo de permiso predeterminado y las nuevas sesiones comenzarán con él.
  • Denegaciones procesables: cuando se bloquea una llamada de herramienta, la sugerencia es clickable para que puedas ajustar el permiso en el momento.

🖥 Escritorio Client

  • Entrada de voz: un botón de voz en la entrada del chat transcribe lo que dices directamente en el cuadro; El reconocimiento y la síntesis de voz también funcionan con proveedores y modelos personalizados. Gracias @chimyves (#3052, #3050)
  • Borradores guardados: al salir de la página de chat y regresar ya no se pierden el texto y los archivos adjuntos no enviados. Gracias @chimyves (#3040)
  • Iniciar al iniciar sesión: una nueva opción en la configuración del sistema, desactivada de forma predeterminada.
  • Diagnóstico de inicio: cuando el backend no se inicia, client informa lo que realmente salió mal en lugar de un error genérico.
  • Descarga de registro: la página de registro de ejecución puede descargar el archivo de registro y las cargas locales obtuvieron reintentos y errores más claros.

🔔 Notificaciones de tareas

Tanto la consola web como el escritorio client generan una notificación (con un sonido) cuando finaliza o falla la ejecución de un Agente, para que pueda abandonar una tarea larga:

  • Ambos clients: notificaciones del sistema operativo en el escritorio, notificaciones del navegador en la Web, solo mientras la ventana no está enfocada. Cli Al seleccionar uno, vuelves a la sesión.
  • Insignia de no leídos: la pestaña Web muestra un recuento de no leídos mientras está oculta, que se borra una vez que vuelves a cambiar.
  • Alternancias separadas: las notificaciones y el sonido son dos interruptores independientes, ambos activados de forma predeterminada. Cancelar una tarea usted mismo ya no genera una notificación de error.

Gracias @chimyves (#3056, #3055)

🤖 Actualizaciones de modelos

  • Nuevos modelos: glm-5.3, qwen3.8-max, gemini-3.7-flash y gemini-3.6-flash, cada uno configurado como predeterminado de su proveedor.
  • Página de configuración fusionada: la consola web pliega la página de Modelos en Configuración, dividida en una pestaña Básica y Modelos, por lo que hay menos saltos.
  • Correcciones de llamadas: se corrigió el pensamiento forzado de GLM-5.3, además de enrutamiento y manejo de URL base para algunos modelos de DashScope; Los modelos personalizados ahora aparecen en el selector de modelos de sesión.

🛠 Mejoras y correcciones

  • Visualización de imágenes: se corrigieron las imágenes de ruta local y las imágenes de ruta relativa dentro de los documentos de conocimiento que no se procesan; en el escritorio, cli al copiar una imagen en un chat o en un documento se amplía su lugar. Gracias @chimyves (#3046)
  • Unidades de Windows: se corrigió que el selector de carpetas no enumerara las unidades en Windows. Gracias @CNXudiandian (#3048)
  • Guía de shell de Windows: mejor guía de recuperación cuando falla un comando de shell en Windows. Gracias @dajiaohuang (#3065)
  • Respuestas de mensajería instantánea más limpias: las respuestas de los agentes en los canales de mensajería instantánea ya no contienen contenido pensado. Gracias @LHMQ878 (#3044)
  • Tareas programadas: se corrigió una tarea que fallaba durante la medianoche y nunca regresaba a la programación (Gracias @chimyves #3054), y las tareas programadas se reconocían en lugar de ejecutarse.
  • Primer mensaje más rápido: inicialización optimizada del sistema de memoria para que ya no bloquee el primer mensaje de una sesión, lo que reduce notablemente la espera antes de la respuesta inicial.
  • Recorte de contexto: se corrigió que la respuesta de IA no se guardara cuando se recortaba el contexto.
  • Canal Feishu: la tarjeta de transmisión ahora acumula texto en cada turno.
  • Docker: config.json sobrevive a las actualizaciones de contenedores a través del soporte COW_DATA_DIR.

📦 Cómo actualizar

  • Implementación de origen: ejecute cow update para una actualización de un click, o extraiga el código más reciente y reinicie. Consulte la guía de actualización.
  • Escritorio client: busque actualizaciones y actualice con un click dentro del client, ​​u obtenga la última versión desde la página de descarga.

CowAgent 2.1.7

Highlights

  • Workspace-scoped sessions — Sessions can now bind to independent project directories, keeping files from concurrent tasks isolated. Memory, skills, and the knowledge base remain shared through the system workspace (~/cow by default), so those resources are not project-scoped.

  • Per-session permission modes — Choose read-only, workspace-write, or full-access for each session, with a configurable default for new sessions. For routine automation, workspace-write constrains filesystem changes to the selected workspace; blocked tool calls now offer actionable permission controls.

  • Provider model defaults changed — glm-5.3, qwen3.8-max, gemini-3.7-flash, and gemini-3.6-flash are now provider defaults, so unchanged configurations may produce different responses, latency, or cost. GLM forced-thinking behavior and DashScope routing/base-URL handling are fixed, and custom models appear in the session picker.

  • Desktop and background-run UX — Voice transcription supports custom providers/models (#3052, #3050), while drafts and attachments survive leaving the chat (#3040). Both clients can notify on completed or failed runs while unfocused; notification and sound toggles are independent and default on, and cancelled runs no longer trigger failure alerts.

  • Scheduling and container persistence — Scheduled tasks recover their cadence after midnight failures (#3054) and execute instead of merely being acknowledged—important for unattended automation. Docker deployments should keep config.json under the COW_DATA_DIR mount so configuration survives container upgrades.

  • Breaking changes — None announced.

🗂 Multiple Workspaces

The Agent is no longer tied to a single directory — you can set up several project workspaces and give each session its own. Available in both the Web console and the desktop client:

  • Multiple workspaces: create or open any directory as a project workspace; the documents, web pages, and code the Agent produces are created and managed there.
  • Per-session workspace: each session is bound to its own project workspace, so tasks running side by side stay out of each other's way.
  • Per-session model: switch the model for a single session; new sessions start from the global default.
  • Grouped sessions: the session list is grouped by workspace, with pinning, reordering, renaming, and deleting.
  • Shared system resources: memory, skills, and the knowledge base still live in the system workspace (~/cow by default).

Docs: Workspace

🔐 Permission Modes

Sessions now carry their own permission mode, which works together with workspaces to control how far the Agent can reach:

  • Three levels: read-only, workspace-write, and full-access, set independently for each session.
  • Default mode: pick a default permission mode, and new sessions start with it.
  • Actionable denials: when a tool call is blocked, the hint is clickable so you can adjust the permission on the spot.
<img src="https://cdn.jsdelivr.net/gh/zhayujie/cowagent-assets@main/screenshots/en/web-console-access-mode.png" width="600" />

🖥 Desktop Client

  • Voice input: a voice button in the chat input transcribes what you say straight into the box; speech recognition and synthesis also work with custom providers and models. Thanks @chimyves (#3052, #3050)
  • Drafts kept: leaving the chat page and coming back no longer loses unsent text and attachments. Thanks @chimyves (#3040)
  • Launch at login: a new toggle in system settings, off by default.
  • Startup diagnostics: when the backend fails to start, the client reports what actually went wrong instead of a generic error.
  • Log download: the run-log page can download the log file, and local uploads gained retries and clearer errors.

Download: CowAgent Desktop

Docs: Desktop Client

🔔 Task Notifications

The Web console and the desktop client both raise a notification (with a sound) when an Agent run finishes or fails, so you can walk away from a long task:

  • Both clients: OS notifications on the desktop, browser notifications on the Web — only while the window isn't focused. Clicking one takes you back to the session.
  • Unread badge: the Web tab shows an unread count while it's hidden, cleared once you switch back.
  • Separate toggles: notifications and the sound are two independent switches, both on by default. Cancelling a task yourself no longer triggers a failure notification.

Thanks @chimyves (#3056, #3055)

🤖 Model Updates

  • New models: glm-5.3, qwen3.8-max, gemini-3.7-flash, and gemini-3.6-flash, each set as its provider's default.
  • Merged config page: the Web console folds the Models page into Config, split into a Basic and a Models tab, so there's less jumping around.
  • Call fixes: fixed GLM-5.3's forced thinking, plus routing and base-URL handling for some DashScope models; custom models now show up in the session model picker.

🛠 Improvements & Fixes

  • Image display: fixed local-path images and relative-path images inside knowledge docs not rendering; on the desktop, clicking an image in a chat or a document zooms it in place. Thanks @chimyves (#3046)
  • Windows drives: fixed the folder picker not listing drives on Windows. Thanks @CNXudiandian (#3048)
  • Windows shell guidance: better recovery guidance when a shell command fails on Windows. Thanks @dajiaohuang (#3065)
  • Cleaner IM replies: Agent replies on IM channels no longer carry thinking content. Thanks @LHMQ878 (#3044)
  • Scheduled tasks: fixed a task that failed across midnight never getting back on schedule (Thanks @chimyves #3054), and scheduled tasks being acknowledged instead of run.
  • Faster first message: streamlined memory system initialization so it no longer blocks a session's first message, noticeably cutting the wait before the initial reply.
  • Context trimming: fixed the AI reply not being saved when the context was trimmed.
  • Feishu channel: the streaming card now accumulates text across turns.
  • Docker: config.json survives container upgrades through the COW_DATA_DIR mount.

📦 How to Upgrade

  • Source deployment: run cow update for a one-click upgrade, or pull the latest code and restart. See the upgrade guide.
  • Desktop client: check for updates and update with one click inside the client, or get the latest version from the download page.
