CowAgent 2.1.2

🌐 Inglés | 中文

💬 Mejoras en la consola web

Esta versión agrega varias capacidades de administración visual a la consola web, por lo que se pueden realizar más configuraciones en la interfaz de usuario sin editar archivos:

  • Gestión de tareas programadas: vea, edite, habilite/deshabilite y elimine cualquier tarea programada directamente en la consola. La lista de tareas se ordena primero por estado habilitado y luego por tiempo de ejecución siguiente. Gracias @HnBigVolibear (#2892)
  • Categorías de la base de conocimientos y gestión de documentos: la base de conocimientos ahora se puede organizar por categoría, con los documentos de cada categoría gestionados en la interfaz de usuario. Gracias @yangziyu-hhh (#2893)
  • Múltiples proveedores de modelos personalizados: configure múltiples proveedores compatibles con OpenAI y cambie el activo con un único click, totalmente compatible con la configuración existente. Gracias @kirs-hola (#2877)
  • Cambio de nombre de sesión: cambie el nombre de las sesiones manualmente para diferenciar las tareas paralelas (#2897)
  • Salida de transmisión de Bash: los comandos Bash de ejecución prolongada ahora transmiten su progreso en tiempo real. Gracias @yangziyu-hhh (#2879)

🧬 Mejoras de autoevolución

Basándose en la autoevolución introducida en la versión anterior, esta versión la perfecciona aún más:

  • Umbrales de activación más bajos: los umbrales de revisión predeterminados se reducen, por lo que la colaboración diaria se convierte en mejoras antes.
  • Sin revisiones simultáneas: cuando un solo turno se prolonga, la revisión inactiva ya no se activa por error, lo que evita la interferencia con la conversación activa.
  • Mejor resumen de revisión: se perfeccionó el mensaje de resumen para mantener los resúmenes concisos, aumentar su densidad de información y generarlos en el idioma de la conversación.

Documentación: Autoevolución

🤖 Nuevos Modelos

  • kimi-k2.7-code: agregado y configurado como modelo Kimi predeterminado, con kimi-k2.7-code-highspeed también disponible
  • glm-5.2: agregado y configurado como modelo GLM predeterminado

Documentación: Descripción general de modelos

🏢 Modo de devolución de llamada del WeCom Smart-Bot

El canal de robot inteligente de WeCom agrega un modo de devolución de llamada HTTP junto con la conexión larga existente, por lo que las implementaciones que no pueden mantener abierta una conexión larga aún pueden conectarse de manera confiable:

  • Cambio de modo: cambia entre websocket (conexión larga) y webhook (devolución de llamada) a través de wecom_bot_mode
  • Transporte cifrado: el modo de devolución de llamada es totalmente compatible con la verificación de URL, el descifrado de mensajes y el cifrado de respuesta pasiva
  • Correcciones de estabilidad: Se corrigió la interrupción de la respuesta, la terminación prematura de la transmisión y las fugas temporales de archivos de imágenes.

Gracias @6vision (#2896 #2869)

Documentación: WeCom Smart Bot

🔒 Refuerzo de la seguridad

  • Protección SSRF de la herramienta Vision: valida la dirección de destino antes de resolver la URL de una imagen, bloqueando las solicitudes a los puntos finales de metadatos internos, de bucle invertido y del servidor en la nube. Gracias @kirs-hola (#2886)
  • Protección SSRF de recuperación web: web_fetch valida la dirección de destino antes de recuperarla y revalida cada salto de redireccionamiento, evitando que los redireccionamientos pasen por alto la verificación para llegar a direcciones internas. Gracias @christop (#2900)
  • Protección transversal de ruta de instalación de habilidades: valida la ruta al instalar una habilidad, evitando que un nombre de habilidad malicioso escape del directorio skills/ a través de la ruta transversal y la escritura en una ubicación no autorizada. Gracias @kirs-hola (#2886)

🛠 Mejoras y correcciones

  • Reinicio automático CLI: se agregó el comando cow self-restart para que el agente pueda reiniciar su propio proceso.
  • Compatibilidad con Windows: persiste el directorio cow CLI en la RUTA del usuario; se corrigieron los comandos largos de python -c que excedían el límite de longitud de cmd.exe; Evite construir un greenlet desde la fuente durante la instalación.
  • Roles personalizados: el complemento de roles admite la personalización a través de archivos de aviso independientes en roles/*.json. Gracias @sufan721 (#2891)
  • Correcciones de estabilidad: se corrigió un KeyError en /cancel y un bucle infinito en la compresión de imágenes (Gracias @kirs-hi #2888)
  • Mejoras de instalación: se actualizó el script de inicio y la configuración predeterminada; Se corrigieron los valores predeterminados de ASR/TTS, el indicador de autoevolución y la instalación se bloquea.
  • Estabilidad de la herramienta de visión: Aumentó el tiempo de espera de la herramienta de visión y max_tokens
  • Destilación de memoria: se eliminó el límite de longitud de salida en la destilación de sueños profundos para evitar truncar un MEMORY.md grande

📦 Actualizar

Las implementaciones de código fuente pueden ejecutar cow update para una actualización de un click, o extraer el código más reciente y reiniciar manualmente. Consulte la Guía de actualización para obtener más detalles.

CowAgent 2.1.2

Highlights

  • Web Console absorbs more config surface — Scheduled tasks (#2892), categorized knowledge bases with in-UI document management (#2893), and multiple switchable OpenAI-compatible model providers (#2877) are now manageable without editing files. The provider change is explicitly backward-compatible with existing config, so you can migrate incrementally; session renaming (#2897) and real-time streaming of long-running Bash commands (#2879) remove two concrete daily friction points.
  • Self-Evolution becomes safer to leave on — Lowered default review thresholds mean the feature now triggers on ordinary collaboration rather than only major events, so expect far more improvement activity out of the box. The important behavioral fix: idle reviews no longer fire alongside a long-running turn, eliminating a race that previously interrupted active conversations. Summaries are denser and now emitted in the conversation language.
  • Default model IDs change — kimi-k2.7-code replaces the old Kimi default (with kimi-k2.7-code-highspeed also available) and glm-5.2 becomes the default GLM model. These are default swaps, so anyone relying on implicit defaults will see different outputs without touching config — pin your model IDs explicitly before upgrading.
  • WeCom smart-bot gains an HTTP callback mode — Set wecom_bot_mode to webhook instead of websocket for deployments that can't hold a long connection open; the callback path supports URL verification, message decryption, and passive-reply encryption (#2896, #2869). Combined with fixes for reply interruption, premature stream termination, and temp-image leaks, this moves callback mode from fallback to production-viable.
  • Three SSRF / path-traversal hardenings — The vision tool validates image URLs before resolution, blocking internal, loopback, and cloud-metadata endpoints (#2886); web_fetch re-validates every redirect hop so a redirect can't bypass the allowlist (#2900); and skill installs validate paths to stop a malicious skill name escaping skills/ via path traversal (#2886). Watch-out: fetches to internal or redirecting URLs that used to work will now be rejected — intentionally.
  • Ops and Windows quality-of-life — New cow self-restart lets the agent restart its own process; Windows installs now persist the CLI directory to PATH, avoid building greenlet from source, and sidestep cmd.exe length limits on long python -c commands. Custom roles load from standalone roles/*.json prompt files (#2891), deep-dream distillation drops its output cap so large MEMORY.md files aren't truncated, and #2888 fixes a /cancel KeyError plus an image-compression infinite loop.

No breaking changes.

💬 Web Console Improvements

This release adds several visual management capabilities to the Web Console, so more configuration can be done in the UI without editing files:

  • Scheduled task management: View, edit, enable/disable, and delete any scheduled task directly in the console. The task list is sorted by enabled status first, then by next run time. Thanks @HnBigVolibear (#2892)
  • Knowledge base categories and document management: The knowledge base can now be organized by category, with documents under each category managed in the UI. Thanks @yangziyu-hhh (#2893)
  • Multiple custom model providers: Configure multiple OpenAI-compatible providers and switch the active one with a single click, fully compatible with existing configuration. Thanks @kirs-hi (#2877)
  • Session renaming: Rename sessions manually to tell parallel tasks apart (#2897)
  • Bash streaming output: Long-running Bash commands now stream their progress in real time. Thanks @yangziyu-hhh (#2879)

🧬 Self-Evolution Improvements

Building on the Self-Evolution introduced in the previous release, this version refines it further:

  • Lower trigger thresholds: The default review thresholds are lowered, so everyday collaboration turns into improvements sooner
  • No concurrent reviews: When a single turn runs long, the idle review no longer fires by mistake, avoiding interference with the active conversation
  • Better review summary: Refined the summary prompt to keep summaries concise, raise their information density, and output them in the conversation language

Documentation: Self-Evolution

🤖 New Models

  • kimi-k2.7-code: Added and set as the default Kimi model, with kimi-k2.7-code-highspeed also available
  • glm-5.2: Added and set as the default GLM model

Documentation: Models Overview

🏢 WeCom Smart-Bot Callback Mode

The WeCom smart-bot channel adds an HTTP callback mode alongside the existing long connection, so deployments that cannot keep a long connection open can still connect reliably:

  • Mode switching: Switch between websocket (long connection) and webhook (callback) via wecom_bot_mode
  • Encrypted transport: Callback mode fully supports URL verification, message decryption, and passive-reply encryption
  • Stability fixes: Fixed reply interruption, premature stream termination, and temporary image file leaks

Thanks @6vision (#2896 #2869)

Documentation: WeCom Smart Bot

🔒 Security Hardening

  • Vision tool SSRF protection: Validates the target address before resolving an image URL, blocking requests to internal, loopback, and cloud server metadata endpoints. Thanks @kirs-hi (#2886)
  • Web fetch SSRF protection: web_fetch validates the target address before fetching and re-validates every redirect hop, preventing redirects from bypassing the check to reach internal addresses. Thanks @christop (#2900)
  • Skill install path traversal protection: Validates the path when installing a skill, preventing a malicious skill name from escaping the skills/ directory through path traversal and writing to an unauthorized location. Thanks @kirs-hi (#2886)

🛠 Improvements & Fixes

  • CLI self-restart: Added the cow self-restart command so the agent can restart its own process
  • Windows compatibility: Persist the cow CLI directory to the user PATH; fixed python -c long commands exceeding the cmd.exe length limit; avoid building greenlet from source during install
  • Custom roles: The role plugin supports customization via standalone prompt files under roles/*.json. Thanks @sufan721 (#2891)
  • Stability fixes: Fixed a KeyError on /cancel and an infinite loop in image compression (Thanks @kirs-hi #2888)
  • Install improvements: Updated the startup script and default config; fixed ASR/TTS defaults, the self-evolution flag, and install hangs
  • Vision tool stability: Increased the vision tool timeout and max_tokens
  • Memory distillation: Removed the output length cap in deep-dream distillation to avoid truncating a large MEMORY.md

📦 Upgrade

Source-code deployments can run cow update for a one-click upgrade, or pull the latest code and restart manually. See the Upgrade Guide for details.
