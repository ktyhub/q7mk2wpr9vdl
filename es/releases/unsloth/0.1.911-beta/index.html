perezoso v0.1.911-beta

Esta versión agrega tareas programadas, compatibilidad con la edición de FLUX-3, mejoras de rendimiento y más. También nuevo: MiniMax-M3.1-Flash, retoques faciales para imágenes y rendimiento más rápido + chats en Mac.

Destacados

  • Tareas programadas: ejecute un mensaje según una programación con un modelo local o un API
  • MiniMax-M3.1-Flash: 428B MoE de MiniMax (23B activo) Guía
  • Edición de FLUX 3: FLUX 3 ahora admite la edición de imágenes con indicaciones
  • Mejoras de rendimiento: grandes ganancias de rendimiento de Mac, menos retraso, tamaños binarios reducidos
  • Preajustes guardados: guarde la configuración de ejecución como ajustes preestablecidos con nombre para cada modelo

Tareas programadas

  • Abra Programado desde el menú Más de la barra lateral para ejecutar un mensaje una vez, diariamente, entre semana, semanalmente o mensualmente; cada respuesta se guarda como un nuevo chat.
  • Cada tarea se puede ejecutar en el modelo cargado, un modelo en su dispositivo o un modelo de un proveedor API conectado.
  • Cuando el modelo de una tarea no está cargado, Unsloth pregunta antes de cargarlo, a menos que actives Cambiar automáticamente cuando no estoy.
  • Cada tarea puede notificarte después de cada ejecución, solo cuando falla o nunca.
  • Las tareas se ejecutan solo mientras Unsloth está en ejecución, sin herramientas ni búsqueda web.

UI + experiencia de usuario

  • Guarde la configuración de ejecución en el selector de modelo como ajustes preestablecidos con nombre para cada modelo, luego cambie el nombre, elimínelos o cambie entre ellos.
  • El ajuste preestablecido que eligió por última vez es con el que se carga ese modelo la próxima vez, incluidas las cargas a través del API.
  • La configuración del chat puede recordar la configuración de muestreo de un modelo o restablecerla a los valores recomendados del modelo.
  • Los chats de GGUF ahora muestran el progreso y el tiempo restante mientras se procesa un mensaje largo, antes de que comience la respuesta.
  • La página API ahora muestra el uso del contexto, la velocidad y el recuento de solicitudes de cada modelo servido.
  • Cada tipo de botón e ícono ahora tiene el mismo aspecto en todas partes de la aplicación.
  • Las páginas Biblioteca y Sistema en Configuración muestran el almacenamiento como una barra de uso, dividida en modelos, cachés y espacio libre.

##Mac

  • Los chats MLX ahora responden hasta un 16% más rápido con modelos borrador.
  • Los modelos MLX que se envían con un modelo borrador incorporado ahora lo usan automáticamente, sin necesidad de descargarlo por separado.
  • Los renderizados de imágenes y videos necesitan mucha menos memoria al final, por lo que las Mac con poca memoria rara vez se ralentizan debido al intercambio.
  • En Apple Silicon, los GGUF Z-Image ahora crean imágenes a partir de texto con el motor MLX de forma predeterminada, 1.5-2x más rápido que antes.

Imágenes + vídeo

  • Cree videos a partir de texto o una imagen con Cosmos3-Edge de NVIDIA en la página de Video.
  • En la página Imágenes, active Detallador para volver a dibujar caras, manos u otras cosas que nombre en mayor resolución; necesita SAM 3 y un modelo que pueda pintar.
  • En GPU NVIDIA anteriores a la serie RTX 30, los clips de texto a video Wan2.1 1.3B se procesan aproximadamente 5 veces más rápido.
  • En las GPU NVIDIA, muchos modelos de imagen y video se cargan más rápido después de la primera vez, ya que Unsloth guarda la versión que crea en la primera carga.
  • FLUX.3 Klein ahora puede editar fotos en Imágenes > Editar, manteniendo las dimensiones de la foto.

Entrenamiento

  • Divida cada capa de un modelo entre GPU para el entrenamiento de LoRA y QLoRA, de modo que cada GPU tenga menos capacidad: establezca UNSLOTH_TP_SIZE en la cantidad de GPU y ejecútelo con torchrun.
  • El ajuste de los puntos de control gpt-oss de 4 bits de Unsloth ya no falla en el primer paso de entrenamiento.
  • GRPO que genera con vLLM se ejecuta hasta 1,9 veces más rápido por paso con LoRA de 16 bits en Linux con GPU NVIDIA.
  • GRPO que genera sin vLLM se ejecuta hasta 4,4 veces más rápido por paso para Llama y Qwen3 en GPU NVIDIA.

Agentes codificadores + API

  • Las aplicaciones que utilizan una clave Unsloth API ya no pueden aprobar su propio Python o llamadas de terminal para ejecutarse fuera del entorno de pruebas.
  • Unsloth ya no trust reenvía IP client de forma predeterminada; detrás de su propio proxy inverso, configure UNSLOTH_STUDIO_TRUST_FORWARDED=1 o todos los usuarios compartirán un límite de tasa de inicio de sesión.

Modelos + hardware

  • Ejecute MiniMax-M3.1-Flash, el modelo MoE de MiniMax para codificación, uso de herramientas y flujos de trabajo de agentes, con hasta 1 millón de tokens de contexto. GGUF
  • A 1 bit, MiniMax-M3.1-Flash necesita al menos 130 GB de RAM y VRAM combinados.
  • En algunas PC con Windows, los modelos GGUF se cargan nuevamente en lugar de fallar cada vez con "llama-server no pudo iniciarse".

unsloth v0.1.911-beta

This release adds scheduled tasks, FLUX-3 edit support, perf improvements and more. Also new: MiniMax-M3.1-Flash, face touch-ups for images and faster performance + chats on Mac.

Highlights

  • Scheduled tasks: Run a prompt on a schedule with a local model or an API
  • MiniMax-M3.1-Flash: MiniMax's 428B MoE (23B active) Guide
  • FLUX 3 Editing: FLUX 3 now supports editing of images with prompts
  • Perf improvements: Large Mac perf gains, less lag, reduced binary sizes
  • Saved presets: Save your Run settings as named presets for each model

Scheduled tasks

  • Open Scheduled from the sidebar's More menu to run a prompt once, daily, on weekdays, weekly or monthly; each answer is saved as a new chat.
  • Each task can run on the loaded model, a model on your device, or a model from a connected API provider.
  • When a task's model isn't loaded, Unsloth asks before loading it, unless you turn on Switch automatically when I'm away.
  • Each task can notify you after every run, only when it fails, or never.
  • Tasks run only while Unsloth is running, without tools or web search.

UI + UX

  • Save Run settings in the model picker as named presets for each model, then rename, delete or switch between them.
  • The preset you picked last is what that model loads with next time, including loads through the API.
  • Chat settings can remember your sampling settings for a model, or reset them to the model's recommended values.
  • GGUF chats now show progress and time left while processing a long prompt, before the reply starts.
  • The API page now shows each served model's context use, speed and request count.
  • Each kind of button and icon now looks the same everywhere in the app.
  • The Library and System pages in Settings show storage as a usage bar, split into models, caches and free space.

Mac

  • MLX chats now reply up to 16% faster with draft models.
  • MLX models that ship with a built-in draft model now use it automatically, with no separate download.
  • Image and video renders need far less memory at the end, so low-memory Macs rarely slow down from swapping.
  • On Apple Silicon, Z-Image GGUFs now make images from text with the MLX engine by default, 1.5-2x faster than before.

Images + video

  • Make videos from text or an image with NVIDIA's Cosmos3-Edge on the Video page.
  • On the Images page, turn on Detailer to redraw faces, hands or other things you name at higher resolution; it needs SAM 3 and a model that can inpaint.
  • On NVIDIA GPUs older than RTX 30-series, Wan2.1 1.3B text-to-video clips render about 5x faster.
  • On NVIDIA GPUs, many image and video models load faster after the first time, since Unsloth saves the version it builds on first load.
  • FLUX.3 Klein can now edit photos in Images > Edit, keeping the photo's dimensions.

Training

  • Split each layer of a model across GPUs for LoRA and QLoRA training, so each GPU holds less: set UNSLOTH_TP_SIZE to the number of GPUs and launch with torchrun.
  • Fine-tuning Unsloth's 4-bit gpt-oss checkpoints no longer crashes on the first training step.
  • GRPO that generates with vLLM runs up to 1.9x faster per step with 16-bit LoRA on Linux with NVIDIA GPUs.
  • GRPO that generates without vLLM runs up to 4.4x faster per step for Llama and Qwen3 on NVIDIA GPUs.

Coding agents + API

  • Apps using an Unsloth API key can no longer approve their own Python or terminal calls to run outside the sandbox.
  • Unsloth no longer trusts forwarded client IPs by default; behind your own reverse proxy, set UNSLOTH_STUDIO_TRUST_FORWARDED=1 or all users share one login rate limit.

Models + hardware

  • Run MiniMax-M3.1-Flash, MiniMax's MoE model for coding, tool use and agent workflows, with up to 1M tokens of context. GGUF
  • At 1-bit, MiniMax-M3.1-Flash needs at least 130 GB of RAM and VRAM combined.
  • On some Windows PCs, GGUF models load again instead of failing every time with "llama-server failed to start".
