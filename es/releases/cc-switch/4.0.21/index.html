Interruptor CC v4.0.21

Esta versión agrega el cambio entre múltiples cuentas de suscripción oficiales para Claude Code: agregue varias cuentas de Claude en el centro de autorización, elija una para cada tarjeta oficial y, cualquiera que sea la tarjeta a la que cambie, Claude Code usará ese número; si quieres utilizar varios números a la vez "abre el terminal" de la tarjeta, ese terminal siempre utilizará el número de la tarjeta. Inicie sesión y siga el proceso oficial de Claude Code. El token solo permanecerá en el Claude Code de la máquina local. CC Switch no cargará, actualizará ni cerrará sesión. Las tarjetas vinculadas a cuentas y el centro de autorización mostrarán el paquete y el saldo restante de cada cuenta. Además, "Abrir Terminal" se ha movido a la tarjeta y la lista de modelos del Codex se puede arrastrar y ordenar, que se mantendrá después de reiniciar en modo ligero. Se solucionó el problema de la caducidad incorrecta del inicio de sesión después de que se reinicia la cuenta ChatGPT administrada, la solicitud del Codex se envía a otra dirección durante el enrutamiento, hay timeout / autoApprove adicionales en la configuración MCP del Codex, OpenCode y Grok Build no están instalados correctamente en npm 12, el tiempo de uso del Código Kimi es incorrecto y hay &, *, ! en el models.yml de Oh My Pi. Problemas como no poder editar. Para obtener el contenido completo de la actualización de 4.0, consulte las Notas de la versión de v4.0. Inglés → | Versión japonesa →

Agregar

Cambiar entre varias cuentas de suscripción oficiales de Claude

Cuando tiene más de una suscripción a Claude (como Max personal y equipo de la empresa, o varias cuentas Pro), solo puede crear /logout y luego /login en Claude Code, o crear usted mismo un directorio de configuración para cada cuenta. Ahora es posible administrar varias cuentas en CC Switch (#1928). Para ver el uso de gráficos y una comparación de cumplimiento artículo por artículo, consulte Utilice CC Switch para cambiar varias suscripciones oficiales de Claude y problemas de cumplimiento. **Seguridad y cumplimiento. ** La cuenta de suscripción es administrada por la herramienta. Lo más importante es que el token sea seguro y no viole los términos de Anthropic. Esta función se implementa de acuerdo con la documentación oficial de Claude Code. El token siempre está solo en su Código Claude local:

  • **Inicia sesión y sigue el proceso oficial. ** Al agregar una cuenta, ejecuta claude auth login --claudeai que viene con Claude Code. La contraseña y la autorización se completan en la página oficial de claude.ai. CC Switch no tiene su propio inicio de sesión de Claude ni su propio cliente OAuth. La [Página Legal y de Cumplimiento] de Anthropic (https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use) requiere que el inicio de sesión en una cuenta de Claude se complete a través del propio proceso de Anthropic, y explícitamente no restringe a los usuarios el inicio de sesión en Claude Code no modificado con sus propias suscripciones.
  • **Varias cuentas utilizan el método recomendado oficialmente. ** Cada cuenta tiene un directorio de configuración independiente, distinguido por CLAUDE_CONFIG_DIR. El método es el mismo que el de la sección "Iniciar sesión con varias cuentas" en Claude Code [Documento de certificación] (https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts). CC Switch simplemente crea el directorio y abre la terminal por usted.
  • **El token no sale de la máquina. ** El token solo existe en la propia ubicación de Claude Code (llavero para macOS, .credentials.json para Linux y Windows) y no se carga, sincroniza con la nube ni se escribe en la base de datos de CC Switch. El propio CC Switch solo recuerda información de la cuenta, como correo electrónico, organización, paquete y tiempo de vencimiento del inicio de sesión, pero no recuerda los tokens.
  • **No envía solicitudes por ti. ** CC Switch no tiene servidor y no requiere un token de suscripción para llamar al modelo; Las solicitudes de diálogo se envían directamente a Anthropic desde el Claude Code local no modificado y el uso se factura a su propia cuenta. Al verificar el límite, verifique directamente la interfaz de límite oficial de Anthropic en esta máquina, que tiene los mismos datos que el /usage de Claude Code.
  • **Sin actualización, sin cierre de sesión, sin cambios de Claude Code. ** Los tokens siempre los actualiza el propio Claude Code. Eliminar una cuenta solo eliminará el directorio creado para ella por CC Switch (junto con la entrada de este directorio en el llavero en macOS) y no permitirá que la cuenta cierre sesión en ningún lugar. CC Switch no modifica los archivos de programa de Claude Code.
  • **Solo controla tu propia cuenta. ** No rota cuentas automáticamente según cuotas, ni brinda la función de compartir suscripciones con otros. La tarjeta y el número se moverán y registrarán entre las ubicaciones de almacenamiento del Claude Code local (solo en el formato propio de Claude Code). La documentación oficial no menciona específicamente este uso. Si solo desea utilizar el método especificado en el documento, conserve la tarjeta "Iniciar sesión con Claude Code", y otras cuentas sólo se pueden utilizar desde la tarjeta "Open Terminal". Cómo utilizar:
  • **Agregar cuenta. ** Haga clic en "Agregar cuenta" en el grupo Claude del Centro de autorización. El navegador abrirá la página de autorización oficial de claude.ai y la cuenta aparecerá automáticamente en la lista después de iniciar sesión. Si el navegador no puede regresar a la máquina después de la autorización, puede pegar la dirección en la barra de direcciones o el código en la página posterior. Los directorios de cada cuenta no interfieren entre sí y sincronizarán su configuración en ~/.claude, MCP y CLAUDE.md (excepto las credenciales de inicio de sesión y las configuraciones relacionadas con el enrutamiento).
  • **Elige una cuenta para la tarjeta oficial. ** El menú desplegable "Método de inicio de sesión" de la tarjeta oficial de Claude es el mismo que el de la tarjeta oficial de Codex: la parte superior es la cuenta que inició sesión y la parte inferior es "Agregar o administrar la cuenta de Claude" (saltar al centro de autorización) e "Iniciar sesión con Claude Code". Simplemente cree una tarjeta para una cuenta.
  • **Corta la tarjeta y se cortará el número. ** Al cambiar a la tarjeta oficial de la cuenta seleccionada, CC Switch coloca el inicio de sesión de esta cuenta en la posición donde Claude Code lo lee de forma predeterminada y la cuenta original se vuelve a colocar en su propio directorio. claude en la terminal, el complemento IDE y el script usarán este número, y el Código Claude que ya se está ejecutando también se cambiará inmediatamente sin reiniciar. Al cambiar a la tarjeta oficial de la cuenta seleccionada, el inicio de sesión actual se recopilará primero si aún no está en el centro de autorización. Claude Code mantiene su propio bloqueo al cambiar; Si CC Switch sale accidentalmente durante el cambio, se completará o retirará automáticamente la próxima vez que se cambie o inicie. Las tarjetas que elijan "Iniciar sesión con Claude Code" no iniciarán sesión y aquellas que no agreguen una cuenta no se verán afectadas.
  • **Se utilizan varios números al mismo tiempo. ** "Open Terminal" en la tarjeta con la cuenta seleccionada. Este terminal se fija con el número de la tarjeta. Cambiar de tarjeta más tarde no afectará.
  • **Paquete y cupo. ** El subtítulo de la tarjeta muestra el número de cuenta y el paquete (como Max 20x), y se muestra un mensaje cuando es necesario actualizar el inicio de sesión; el límite restante de esta cuenta se muestra de forma predeterminada en la parte inferior de la tarjeta, y cada cuenta en el centro de autorización también tiene la misma columna de límite. Cuando el token de una cuenta no utilizada caduque, CC Switch ejecutará el claude -p /usage de Claude Code en su directorio una vez (hasta una vez cada 10 minutos para cada cuenta). Claude Code actualizará el inicio de sesión y consultará la cuota por sí solo, y CC Switch solo leerá los resultados. /usage no llama al modelo y no consume el crédito del diálogo. Las tarjetas oficiales sin una cuenta seleccionada también mostrarán el paquete actualmente conectado. Algunos puntos a tener en cuenta:
  • El control remoto que está utilizando se desconectará después de cambiar el número; el primer mensaje después del cambio de número necesita reconstruir el caché de avisos, que será más lento y consumirá más crédito.
  • Cuando el directorio de configuración de Claude se sobrescribe en la configuración (incluido el apuntamiento a WSL), Cheka no cambiará los inicios de sesión y la interfaz le pedirá que use "Abrir Terminal" en su lugar.

La lista de modelos del Codex se puede ordenar arrastrando

La lista de modelos en el formulario de proveedores del Codex tiene un controlador de arrastre al principio de cada línea y el orden se puede ajustar con el mouse o el teclado (#8870). Este orden es el orden del menú /model en el Codex. Cuando la primera fila representa el modelo predeterminado, el modelo arrastrado a la primera fila se convierte en el nuevo modelo predeterminado. En el pasado, tenía que eliminarlo y volver a agregarlo para moverlo.

Mejoras

**"Abrir Terminal" y moverlo a la tarjeta. ** Anteriormente en el menú ⋯, ahora es un botón de icono a la izquierda de "Editar". El mensaje emergente es "Abra la terminal con este proveedor". Cuando el terminal utilice esta tarjeta de forma permanente (la tarjeta con su propia dirección y Clave, la tarjeta oficial con la cuenta Claude seleccionada), dirá "(Aislamiento Ambiental)". **El botón "Agregar cuenta" para cada grupo en el Centro de autorización está fijo a la derecha del título. ** En el pasado, cuando no había una cuenta, el botón se movía al mensaje en blanco y los botones de varios grupos de tarjetas tenían diferentes alturas. El método de inicio de sesión de ChatGPT se cambia a un pequeño menú desplegable al lado del botón. Se eliminó el menú "Eliminar todas las cuentas" en el título y las cuentas se eliminan en sus respectivas filas de menús. Las barras de límite de cada cuenta ahora están alineadas y tienen la misma longitud. **El modo liviano permanece después del reinicio. ** Si sale de CC Switch en modo ligero, seguirá en modo ligero la próxima vez que lo inicie y la interfaz principal ya no aparecerá. Cuando inicie en frío desde el enlace ccswitch://, abra la interfaz principal como de costumbre para que se pueda mostrar el cuadro de diálogo de importación. **La tarjeta Hermes muestra "Predeterminado" y "Establecer como predeterminado" se mueve al menú ⋯. ** Hermes escribe todos los proveedores agregados en config.yaml. El actual es solo el valor predeterminado, el mismo que OpenClaw, OpenCode y Kimi Code. El botón "Habilitar" del antiguo ícono de encendido parecía un interruptor. **Cuando la tarjeta pasa a estar "En uso", la columna de uso ya no se mueve hacia la izquierda y hacia la derecha. ** MCP pregunta qué aplicaciones no son compatibles cuando se selecciona SSE (#8882). Codex solo admite stdio y HTTP, y tratará la dirección SSE como una conexión HTTP. El servidor no puede conectarse cuando solo admite SSE; Pi y Antigravity informarán un error al guardar. Ahora habrá un mensaje de avance en "Escribir en". Cuando la dirección ascendente de Claude Desktop es githubcopilot.com, el formato ascendente se muestra como "Seleccionado automáticamente por ruta según el modelo" (#8838), que es el mismo que cuando se selecciona el proveedor de copiloto GitHub. Las tarjetas OMO y OMO Slim de OpenCode ya no muestran "Detectar conectividad" (#8842). Son simplemente la relación correspondiente entre el agente y el modelo. No hay dirección para probar. Si hizo clic en él antes, se informará un error. Traducción completa al turco (#8836). Predeterminado: DeepSeek siempre usa el modelo Flash; El ajuste preestablecido oficial de Kimi agrega K3.1 Pro y K3.1 Pro HighSpeed, puede elegir un nivel de pensamiento bajo/alto/máximo (#8867); El Flash MiniMax M3.1 de OpenClaw puede elegir máximo; nuevo ClinePass (#8885), TeamoRouter Claude (#8266); OpenCode Go de Claude Desktop utiliza la dirección del documento oficial y la cuota también se puede verificar (#8720, #8779).

Arreglar

  • Después de reiniciar la cuenta ChatGPT administrada, muestra "El inicio de sesión ha caducado" y no se puede cambiar. Se recupera después de un tiempo (#8901). En el pasado, cualquier HTTP 403 encontrado al actualizar el inicio de sesión se consideraba un error de inicio de sesión y los errores de red también se mostraban como vencidos. Ahora, al igual que el Codex CLI, solo los errores 401 o de invalidación de token claro se consideran caducados; Los problemas temporales de red se volverán a intentar como de costumbre y la cuota conservará el último resultado. Después de cambiar la bandeja, el saldo que no se pudo consultar en la interfaz principal también se consultará nuevamente.
  • Cuando Codex se enrutaba localmente, la solicitud se enviaba a otras direcciones (#8849, #8848). Cuando hay varias tablas de proveedores en config.toml, o hay una línea de direcciones antiguas comentadas anteriormente, el primer base_url en el texto se obtuvo previamente y la clave del proveedor seleccionado se enviará a otra parte. Ahora presione model_provider para obtener la dirección de la tabla seleccionada.
  • A veces se omite el uso de la compresión remota del Codex (#8879).
  • Hay timeout y autoApprove adicionales en la configuración MCP de Codex, la versión de escritorio de Codex informó configuraciones desconocidas y --strict-config se negó a cargar (#8843). Estos dos campos pertenecen a otros clientes. Fueron escritos en config.toml como estaban antes. Si se eliminan manualmente, se volverán a escribir la próxima vez que se sincronicen. Ahora se elimina al escribir en Codex; otras aplicaciones no se verán afectadas.
  • Cuando Codex está conectado a varios recursos de Azure mediante retransmisión, se informa un mensaje 400 "creado bajo un recurso diferente de Azure OpenAI" a mitad de la sesión y no se puede continuar (#8877). Ahora intente nuevamente después de recibir este error, eliminando el ID de entrada del historial. Las solicitudes normales no se ven afectadas.
  • ClinePass es un upstream que devuelve resultados de finalización de chat en data. Las solicitudes que no son de transmisión informan 422 "No hay opciones en respuesta" (#5658).
  • En npm 12, el OpenCode instalado en la página "Aplicación" informa "Incompatible con la versión de Windows que está ejecutando" en Windows, y Grok Build todavía ejecuta la versión anterior después de la actualización (#8863). npm 12 no ejecuta el script de instalación de forma predeterminada y estos dos paquetes dependen de él para colocar programas reales. Sus scripts de instalación ahora están permitidos durante la instalación y actualización.
  • Hermes en Windows se muestra como dos instalaciones en la página "Aplicaciones" (#8839). hermes.cmd dejado en el mismo directorio ya no se cuenta como una instalación.
  • Uso del Código Kimi, el tiempo de solicitud para una ronda completa de diálogo es el mismo y, cuando se calcula por hora, se reduce a la última hora (#8899). Ahora registre la hora en que se completa cada solicitud. Los registros importados se corregirán la próxima vez que cambie el archivo de sesión.
  • Cuando el models.yml de Oh My Pi contiene name: Search & Fetch, que contiene valores como &, * y !, el proveedor informa "Este YAML utiliza un formato o sintaxis que CC Switch no puede editar de forma segura" (#8897).
  • Cuando ~/.gemini/.env se escribe como export GEMINI_API_KEY=..., no hay clave después de la importación y se eliminará del archivo al volver al proveedor predeterminado (#8862, #8861).
  • **Al cambiar de un proyecto con palabras de aviso habilitadas a un proyecto sin palabras de aviso, las palabras de aviso originales no se desactivan. **
  • Cuando la barra lateral de la página de estadísticas de uso se expande o contrae, el borde derecho del gráfico de tendencias salta (#8548).

cc-switch v4.0.21

Highlights

  • Multiple official Claude accounts, switchable per card — CC Switch can now manage several Claude.ai subscriptions (personal Max vs. company Team, multiple Pro seats) and swap which one claude uses (#1928). Accounts are added through the official claude auth login --claudeai flow, each in its own CLAUDE_CONFIG_DIR — the same pattern Claude Code's own docs recommend — with settings, MCP config and CLAUDE.md seeded from ~/.claude but credentials and routing left alone. Switching a card moves that account's login into Claude Code's default credential store (macOS Keychain / .credentials.json) under Claude Code's own lock, with automatic completion or rollback on the next launch if the app dies mid-swap; running sessions follow immediately, no restart needed. Tokens never reach CC Switch's database or any server — it stores only email, org and plan metadata, never refreshes or logs out accounts, and deletion only removes the directories it created. For genuinely parallel use, launch a terminal from the card: that shell is pinned to the card's account and unaffected by later switches. Watch-outs: Remote Control sessions disconnect on account change, the first message after a switch rebuilds the prompt cache (slower, extra usage), and if you've overridden the Claude config directory — including pointing it at WSL — card switching deliberately won't move credentials; use "Open Terminal" instead.

  • Codex routing and auth correctness — With multiple provider tables in config.toml, or a commented-out old address above the active one, CC Switch previously grabbed the first base_url in the text and paired it with the selected provider's key — sending both to the wrong host. The address is now resolved from the table named by model_provider (#8849, #8848). Related fixes: Azure relay sessions hit by 400 "created under a different Azure OpenAI resource" now retry once with the prior entry IDs stripped (#8877), remote-compaction usage is no longer lost (#8879), and managed ChatGPT accounts no longer show a false "login expired" and lock out switching on any 403 — only 401 or an explicit token-invalid error counts, matching Codex CLI, with transient failures retried and the last quota result kept (#8901). If you somehow depended on that commented-out URL being used, that behavior is gone.

  • Generated config stays valid under strict validation — CC Switch stops writing timeout and autoApprove into Codex's MCP config (#8843): those fields belong to other clients and triggered "unknown setting" errors in Codex Desktop and outright load failures under --strict-config, with manual deletion undone on the next sync; other applications' configs are unaffected. SSE selection now warns up front (#8882) — Codex accepts only stdio and HTTP and will try to talk HTTP to an SSE-only server, while Pi and Antigravity reject it on save. Editing robustness also improved: ~/.gemini/.env entries written as export GEMINI_API_KEY=... import correctly and no longer get deleted when switching back to the default provider (#8862, #8861), and Oh My Pi models.yml values containing &, *, or ! (e.g. name: Search & Fetch) no longer block saving with "unsupported YAML format" (#8897).

  • Installs and usage metering — npm 12 stopped running install scripts by default, which made the OpenCode install on Windows report "incompatible with your Windows version" and left Grok Build running the old binary after an upgrade; install and upgrade now explicitly allow those packages' scripts (#8863). A leftover hermes.cmd no longer registers as a second Windows installation (#8839), and ClinePass-style upstreams that wrap Chat Completions payloads in data no longer produce 422 "No choices in response" on non-streaming calls (#5658). Kimi Code usage is now timestamped per request completion instead of stamping a whole conversation identically and bunching it into the last hour (#8899); already-imported records correct themselves on the next session-file change.

  • Model and card workflow polish — The Codex provider form's model list is drag-reorderable with mouse or keyboard, and that order is literally the /model menu order — drag a model to the top to make it the default, replacing the delete-and-re-add workaround (#8870). "Open Terminal" moved from the ⋯ menu to an icon next to "Edit," with an "(environment isolated)" tooltip on cards pinned to an account or custom endpoint; lightweight mode now survives restarts, though a cold ccswitch:// launch still opens the main window so import dialogs can render. Presets were refreshed too: DeepSeek standardized on Flash, Kimi gained K3.1 Pro / Pro HighSpeed with low/high/max reasoning (#8867), and ClinePass (#8885) and TeamoRouter Claude (#8266) were added.

  • Breaking changes — None.

CC Switch v4.0.21

本版本为 Claude Code 增加了多个官方订阅账号的切换：在授权中心添加几个 Claude 账号，每张官方卡选一个，切到哪张卡，Claude Code 就用哪个号；想几个号同时用，从卡片上「打开终端」，那个终端固定用卡片上的号。登录走 Claude Code 官方的流程，令牌只留在本机的 Claude Code 里，CC Switch 不上传、不刷新、不登出。绑了账号的卡片和授权中心都会显示每个号的套餐和剩余额度。另外，「打开终端」挪到了卡片上，Codex 的模型列表可以拖动排序，轻量模式重启后保持。修复了托管 ChatGPT 账号重启后误报登录过期、Codex 经路由时请求发到了别的地址、Codex 的 MCP 配置里多出 timeout / autoApprove、npm 12 下 OpenCode 和 Grok Build 装不好、Kimi Code 用量的时间不对、Oh My Pi 的 models.yml 里有 &、*、! 时无法编辑等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

在多个 Claude 官方订阅账号之间切换

手上有不止一个 Claude 订阅（比如个人 Max 和公司 Team，或者多个 Pro 账号）时，以前只能在 Claude Code 里 /logout 再 /login，或者自己给每个号建配置目录。现在可以在 CC Switch 里管理多个号（#1928）。

图文用法和逐条的合规对照见 使用 CC Switch 切换多个 Claude 官方订阅以及合规问题。

安全与合规。 订阅账号交给工具管理，最要紧的是令牌安全、不违反 Anthropic 的条款。这个功能按 Claude Code 官方文档的做法实现，令牌始终只在你本机的 Claude Code 里：

  • 登录走官方流程。 添加账号时运行的是 Claude Code 自带的 claude auth login --claudeai，密码和授权都在 claude.ai 的官方页面完成。CC Switch 没有自己的 Claude 登录，也没有自己的 OAuth 客户端。Anthropic 的法律与合规页要求 Claude 账号的登录必须通过 Anthropic 自己的流程完成，并且明确不限制用户用自己的订阅登录未经修改的 Claude Code。
  • 多账号用的是官方推荐的方法。 每个号一个独立的配置目录，用 CLAUDE_CONFIG_DIR 区分，和 Claude Code 认证文档里「Log in with multiple accounts」一节的方法一样，CC Switch 只是替你建好目录、打开终端。
  • 令牌不离开本机。 令牌只存在 Claude Code 自己的位置（macOS 的钥匙串，Linux、Windows 的 .credentials.json），不上传，不随云同步，也不写进 CC Switch 的数据库。CC Switch 自己只记邮箱、组织、套餐这类账号资料和登录过期时间，不记令牌。
  • 不替你发请求。 CC Switch 没有服务器，不用订阅令牌调用模型；对话请求都由本机未经修改的 Claude Code 直接发给 Anthropic，用量计在你自己的账号上。查额度时在本机直接查 Anthropic 官方的额度接口，和 Claude Code 自己的 /usage 查的是同一份数据。
  • 不刷新、不登出、不改 Claude Code。 令牌一律由 Claude Code 自己刷新。删除账号只删 CC Switch 为它建的目录（macOS 上连同这个目录在钥匙串里的条目），不会让这个号在任何地方退出登录。CC Switch 不修改 Claude Code 的程序文件。
  • 只管你自己的账号。 不按额度自动轮换账号，也不提供把订阅共享给别人的功能。

切卡即切号会在本机 Claude Code 的存储位置之间移动登录（只按 Claude Code 自己的格式），官方文档没有专门讲到这种用法。只想用文档写明的方式的话，卡片保持「跟随 Claude Code 登录」，其他号只从卡片「打开终端」使用。

怎么用：

  • 添加账号。 在授权中心的 Claude 组点「添加账号」。浏览器会打开 claude.ai 的官方授权页，登录后账号自动出现在列表里。浏览器授权后回不到本机时，可以把地址栏里的地址或页面上的代码粘贴回来。每个号的目录互不干扰，会同步你在 ~/.claude 里的设置、MCP 和 CLAUDE.md（登录凭据和路由相关的设置除外）。
  • 给官方卡选账号。 Claude 官方卡的「登录方式」下拉和 Codex 官方卡一样：上面是已登录的账号，下面是「添加或管理 Claude 账号」（跳到授权中心）和「跟随 Claude Code 登录」。一个号建一张卡就行。
  • 切卡即切号。 切到选了账号的官方卡时，CC Switch 把这个号的登录放进 Claude Code 默认读取的位置，原来那个号放回它自己的目录。终端、IDE 插件、脚本里的 claude 都改用这个号，已经在运行的 Claude Code 也会立即跟着换，不用重启。切到选了账号的官方卡时，现在的登录如果还不在授权中心会先收进来。切换时持有 Claude Code 自己的锁；切换中途 CC Switch 意外退出的话，下次切换或启动时会自动补完或撤回。选「跟随 Claude Code 登录」的卡不碰登录，不添加账号的人不受影响。
  • 几个号同时用。 在选了账号的卡上「打开终端」，这个终端固定用卡片上的号，之后切换卡片不影响它。
  • 套餐和额度。 卡片副标题显示账号和套餐（如 Max 20x），登录需要更新时带一个提示；卡片底部默认显示这个号的剩余额度，授权中心里每个号也有一样的额度列。不在用的号令牌过期时，CC Switch 在它的目录里运行一次 Claude Code 自带的 claude -p /usage（每个号最多 10 分钟一次），由 Claude Code 自己刷新登录、查询额度，CC Switch 只读结果。/usage 不调用模型，不消耗对话额度。没选账号的官方卡也会显示当前登录的套餐。

几点注意：

  • 切号后正在用的 Remote Control 会断开；换号后第一条消息要重建提示缓存，会慢一点、多用一点额度。
  • 在设置里覆盖了 Claude 配置目录（包括指向 WSL）时，切卡不会切换登录，界面会提示改用「打开终端」。

Codex 的模型列表可以拖动排序

Codex 供应商表单里的模型列表，每行开头有拖动手柄，可以用鼠标或键盘调整顺序（#8870）。这个顺序就是 Codex 里 /model 菜单的顺序。第一行代表默认模型时，拖到第一行的模型成为新的默认模型。以前要删掉再加回来才能挪位置。

改进

「打开终端」挪到卡片上。 以前在 ⋯ 菜单里，现在是「编辑」左边的一个图标按钮。悬停提示是「以此供应商打开终端」，终端固定用这张卡时（填了自己的地址和 Key 的卡、选了 Claude 账号的官方卡）会写「（环境隔离）」。

授权中心每组的「添加账号」按钮固定在标题右边。 以前没有账号时按钮会挪到空白提示里，几组卡片的按钮高低不一。ChatGPT 的登录方式改成按钮旁边的一个小下拉。标题里的「删除全部账号」菜单去掉了，账号在各自那一行的菜单里删除。各个账号的额度条现在对齐，长度一致。

轻量模式重启后保持。 在轻量模式下退出 CC Switch，下次启动仍是轻量模式，不再弹出主界面。从 ccswitch:// 链接冷启动时照常打开主界面，好显示导入对话框。

Hermes 卡片显示「默认」，「设为默认」移到 ⋯ 菜单里。 Hermes 把添加的供应商都写进 config.yaml，当前那家只是默认值，和 OpenClaw、OpenCode、Kimi Code 一样。以前的电源图标「启用」按钮看起来像开关。

卡片变成「使用中」时，用量一栏不再左右挪动。

MCP 选了 SSE 时提示哪些应用不支持（#8882）。Codex 只支持 stdio 和 HTTP，会把 SSE 地址当作 HTTP 连接，服务端只支持 SSE 时连不上；Pi 和 Antigravity 保存时会报错。现在「写入到」下面会提前提示。

Claude Desktop 的上游地址填 githubcopilot.com 时，上游格式显示为「由路由按模型自动选择」（#8838），和选 GitHub Copilot 供应商时一样。

OpenCode 的 OMO、OMO Slim 卡片不再显示「检测连通」（#8842）。它们只是代理和模型的对应关系，没有地址可测，以前点了会报错。

土耳其语翻译补全（#8836）。

预设： DeepSeek 一律改用 Flash 模型；Kimi 官方预设加入 K3.1 Pro 和 K3.1 Pro HighSpeed，可以选 low / high / max 思考程度（#8867）；OpenClaw 的 MiniMax M3.1 Flash 可以选 max；新增 ClinePass（#8885）、TeamoRouter Claude（#8266）；Claude Desktop 的 OpenCode Go 改用官方文档的地址，额度也能查了（#8720、#8779）。

修复

  • 托管 ChatGPT 账号重启后显示「登录已过期」、不能切换，过一会儿又自己好了（#8901）。以前刷新登录时遇到任何 HTTP 403 都当成登录失效，网络错误也显示成过期。现在和 Codex CLI 一样，只有 401 或明确的令牌失效错误才算过期；一时的网络问题照常重试，额度保留上一次的结果。托盘切换后，主界面里查询失败的额度也会重新查询。
  • Codex 经本地路由时，请求发到了别的地址（#8849、#8848）。config.toml 里有多个供应商表、或上面有一行注释掉的旧地址时，以前取的是文本里第一个 base_url，会带着选中供应商的 Key 发到别处。现在按 model_provider 选中的那张表取地址。
  • Codex 远程压缩的用量有时漏记（#8879）。
  • Codex 的 MCP 配置里多出 timeout、autoApprove，Codex 桌面版报未知设置，--strict-config 拒绝加载（#8843）。这两个字段是别的客户端的，以前原样写进了 config.toml，手动删掉下次同步又会写回来。现在写给 Codex 时去掉，其他应用不受影响。
  • Codex 经中转连到多个 Azure 资源时，会话中途报 400「created under a different Azure OpenAI resource」，无法继续（#8877）。现在收到这个错误后重试一次，去掉历史记录的条目 ID。正常的请求不受影响。
  • ClinePass 这类把 Chat Completions 结果包在 data 里返回的上游，非流式请求报 422「No choices in response」（#5658）。
  • npm 12 下，「应用」页装的 OpenCode 在 Windows 上报「与你运行的 Windows 版本不兼容」，Grok Build 升级后仍在跑旧版本（#8863）。npm 12 默认不运行安装脚本，这两个包要靠它放置真正的程序。现在安装和升级时允许它们的安装脚本。
  • Windows 上 Hermes 在「应用」页显示成两处安装（#8839）。同一目录里遗留的 hermes.cmd 不再算一处安装。
  • Kimi Code 的用量，一整轮对话的请求时间都一样，按小时统计时挤在最后一小时（#8899）。现在按每次请求完成的时间记。已导入的记录在会话文件下次变化时会更正。
  • Oh My Pi 的 models.yml 里有 name: Search & Fetch 这类含 &、*、! 的值时，保存供应商时报「此 YAML 使用了 CC Switch 无法安全编辑的格式或语法」（#8897）。
  • ~/.gemini/.env 里写成 export GEMINI_API_KEY=... 时，导入后没有 Key，切回默认供应商还会把它从文件里删掉（#8862、#8861）。
  • 从启用了提示词的项目切到没有提示词的项目，原来的提示词没有停用。
  • 用量统计页展开或收起侧栏时，趋势图右边缘跳动（#8548）。
