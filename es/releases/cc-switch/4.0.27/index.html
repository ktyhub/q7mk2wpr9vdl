interruptor cc v4.0.27

Interruptor CC v4.0.27

Esta versión permite que la gestión de sesiones busque en el cuerpo del mensaje, agrega densidad de interfaz y configuraciones de escala de interfaz, se pueden buscar tablas de precios de modelos y los proveedores que utiliza Grok Build también pueden abrir la terminal. La página instalada de Habilidades ha sido rediseñada y los íconos de proveedores seguirán el tema oscuro y claro. Además, el archivo de configuración se reemplazó con un archivo normal o no se pudo escribir cuando era un enlace suave, el proveedor se quedó atascado en la recuperación del disyuntor hasta que se reinició después de cancelar la solicitud, el modo de plan informó un error después de que el Codex estableció permisos personalizados, se informó falsamente que la habilidad de ejecución tenía una actualización, el almacén de habilidades mostró 0 habilidades, pi.exe de Python fue reconocido como Pi en Windows, se agotó el tiempo de sincronización del precio del modelo, la ventana no se pudo arrastrar cuando Al abrir el cuadro de diálogo, apareció el menú del navegador al hacer clic con el botón derecho y Linux Problemas como la visualización anormal del panel de acceso directo. Para obtener el contenido completo de la actualización de 4.0, consulte las Notas de la versión v4.0. Inglés → | Versión japonesa →

Agregar

Buscar en el cuerpo del mensaje de una conversación

En el pasado, la búsqueda en la página de administración de sesiones solo podía encontrar el título, el directorio y el ID de la sesión. No se pudo encontrar cuando recordé de qué había hablado pero no pude recordar qué sesión era (#7896, #7420). Ahora puede abrir "Buscar texto del mensaje": ábralo en el menú "⋯" en la esquina superior derecha de la página, o haga clic en el botón en el mensaje directamente cuando la búsqueda no tenga resultados. Después de abrir, los resultados de la búsqueda enumerarán los fragmentos del cuerpo de la búsqueda y cuántos mensajes fueron alcanzados.

  • Desactivado de forma predeterminada. Después de abrir, CC Switch indexará localmente el cuerpo del mensaje y el progreso se mostrará durante la creación. En este momento, es posible que los resultados del cuerpo no estén completos.
  • El índice es un archivo local independiente session-index.db, que no participa en la sincronización ni en la copia de seguridad en la nube; desactivar este interruptor lo eliminará.

Densidad de interfaz y escalado de interfaz

Se agregan dos elementos nuevos en "Configuración → General → Apariencia" (#9209):

  • Densidad de la interfaz: "Compacto" es el tamaño original y el valor predeterminado; "Cómodo" es un tamaño de fuente más grande y los botones y cuadros de entrada son más altos.
  • Zoom de interfaz: 90%, 100%, 110%, 125% cuatro niveles, también puedes presionar Ctrl (⌘ en macOS) más +, - para ajustar, presionar Ctrl/⌘ más 0 para restaurar. Ambas configuraciones sólo se guardan localmente, al igual que el tema. El panel de acceso a la bandeja sigue siendo de tamaño compacto.

Se puede buscar en la tabla de precios de modelos

Se agregó un cuadro de búsqueda encima de la tabla de precios de modelos para filtrar por ID o nombre del modelo (#9205). Al presionar Enter se editará el primer resultado; cuando no hay ningún modelo coincidente, al presionar Enter se agregará un nuevo precio para el modelo ingresado.

Grok Build Abrir terminal

La tarjeta de proveedor de Grok Build también tiene un botón "Abrir terminal" (#9234). Grok CLI no puede permitir que un solo terminal cambie de proveedor, por lo que este botón solo aparece en el proveedor que se está utilizando. El terminal abierto utiliza directamente la configuración de Grok administrada por CC Switch; Se agregará --always-approve al omitir la confirmación de permiso.

Cambiar

  • Reformateo de la página de Skills instaladas (#9210):
    • La columna de nombre está fija a la izquierda y las columnas de cada aplicación se desplazan horizontalmente debajo de ella cuando la ventana es estrecha.
    • El estado y el filtrado de fuentes se mueven a la misma barra de herramientas que la página "Descubrir", y las habilidades no se bloquearán después de ser seleccionadas; las operaciones por lotes retienen la actualización, desinstalación y "habilitar"/"deshabilitar" por aplicación.
    • Se eliminó el enlace "N actualizable" en el encabezado y en "Actualizar todo" en la barra de herramientas ya se escribió el número; haga clic en la marca "Actualizable" en cada fila para actualizar esta habilidad.
    • El menú "..." de cada fila conserva el documento abierto, el directorio abierto y la desinstalación; cuando falla la escritura, el mensaje de error se muestra en la posición descrita.
  • El ícono del proveedor sigue el tema (#8438): se eliminó el fondo blanco fijo detrás del ícono de la tarjeta. Los íconos oscuros de un solo color cambiarán con el color del texto y se podrán ver claramente en el modo oscuro; Los íconos multicolores con trazos oscuros, los íconos de imágenes y los íconos que cargue seguirán teniendo un fondo claro en el modo oscuro.
  • Al hacer clic con el botón derecho ya no aparece el menú del navegador (#8919, #8921): en el pasado, al hacer clic con el botón derecho en la ventana principal y en el panel de la bandeja aparecía el propio menú del navegador (en Windows, era "Atrás", "Recargar", "Guardar como", "Imprimir", etc.). Ya no; Los cuadros de entrada, los editores de código y el texto seleccionado aún se pueden hacer clic derecho y copiar y pegar.
  • El registro del disyuntor indica qué proveedor es (#9292): Todos los registros del disyuntor (CB-001 a CB-006) llevan "aplicación: identificación del proveedor"; Cuando el disyuntor rechaza a un proveedor, también registrará una línea de FWD-004, indicando el nombre del proveedor, y ya no la omitirá silenciosamente. Solo se cambiaron los registros, pero los comportamientos de enrutamiento y disyuntor permanecen sin cambios.
  • Preajustes: El modelo predeterminado de los ajustes preestablecidos de Mistral AI se ha cambiado a mistral-large-4 (Mistral Medium 3.5 ha sido anunciado como obsoleto por Mistral), y los ajustes preestablecidos de Mistral AI para Claude Code, Codex y Claude Desktop ya no están ocultos. El paquete Mistral Vibe y el API comparten la misma cuota. "Obtener clave API" se cambia para abrir la página de claves de Vibe CLI, que está disponible de forma gratuita, por suscripción y de pago por uso; También puede encontrarlo buscando "Vibe" al agregar un proveedor. Se agregó Génesis (#9269) y TokenPlus (#9296). Los proveedores que ya se han agregado no se ven afectados.

Arreglar

  • Cuando el archivo de configuración es un enlace suave, el cambio de proveedor lo reemplazará con un archivo normal y se informará un error directamente en Windows (#6764, #9283). Cuando utiliza la herramienta dotfiles o la carpeta de sincronización para administrar archivos ~/.claude/settings.json, ~/.codex/config.toml, opencode.json, etc., generalmente son enlaces suaves. En el pasado, el enlace en sí se reemplazaba al escribir. En macOS y Linux, el enlace se convirtió en un archivo normal y se desacopló del archivo original. En Windows, se informó un error "falló el reemplazo atómico" (error del sistema operativo 1464). Ahora se escribe el archivo real al que apunta el enlace y el enlace permanece sin cambios.
  • Después de que la solicitud se cancela a mitad de camino, el proveedor puede estar en recuperación del disyuntor hasta que se reinicie (#7206, #9292). Durante el período de recuperación del disyuntor, el disyuntor solo pasa una solicitud de detección; Si el cliente se desconecta antes de que se complete la solicitud, la cuota no se devolverá y todas las solicitudes posteriores a este proveedor serán rechazadas. Ahora, no importa cómo termine la solicitud, el lugar será devuelto.
  • Después de configurar permisos personalizados en Codex, use el modo de plan para informar errores (#7349, #7294). El Codex más nuevo requiere que model_catalog_json sea una ruta absoluta al leer permisos personalizados. En el pasado, CC Switch escribió el nombre del archivo y el Codex informó AbsolutePathBuf deserialized without a base path. Ahora escribe la ruta absoluta; Todavía escriba el nombre del archivo cuando el directorio de configuración esté en WSL.
  • Las habilidades que se han ejecutado una vez se muestran como "actualizables" y al hacer clic en actualizar se cubrirá todo el directorio (#7780, #7772). Los archivos __pycache__ y .pyc generados cuando se ejecuta Python se incluyen en el contenido de Skill. Estos archivos ahora se ignoran al buscar actualizaciones; Los registros antiguos tomados de versiones anteriores se convertirán automáticamente y no darán lugar a falsos positivos.
  • El almacén de habilidades muestra "0 habilidades reconocidas" (#9273). La sucursal del almacén agregada durante la importación se registra como HEAD, o cuando la sucursal predeterminada del almacén es maestra pero está asignada a principal, la cantidad siempre es 0. Ahora el recuento se basa en las sucursales realmente leídas; el almacén que no puede leer indicará "error de lectura" y el motivo. Después de importar Skill y agregar un nuevo almacén, se volverá a leer la próxima vez que se abra.
  • Windows trata pi.exe en el paquete Python como Pi (#9267). Hay un paquete pi no relacionado en PyPI que instalará Scripts\pi.exe y la página de la aplicación lo mostrará como "no se puede ejecutar". Pi solo se lanza a través de npm y ahora pi.exe en el directorio Python Scripts ya no se reconoce como Pi.
  • Error en la sincronización del precio del modelo, solo aparece error decoding response body (#9262). La descarga de la lista de precios de models.dev se agota a mitad de camino a través de una red lenta o un proxy. El tiempo de espera ahora se ha reducido de 15 segundos a 60 segundos y el motivo real se escribirá en el estado de sincronización cuando falle.
  • Al agregar el proveedor de DeepSeek Harness, solo aparece Invalid DeepSeek Harness profile YAML, no sé qué archivo es (#9297). Ahora el informe de errores escribirá la ruta del archivo de configuración del error y el error específico de YAML, lo que facilitará la búsqueda del archivo a reparar.
  • La prueba de conectividad determina que la estación de redireccionamiento es inalcanzable (#9253, #5747). Algunas puertas de enlace se redirigen entre sí entre /v1 y /v1/. Ahora estamos probando que puedan conectarse incluso si reciben la redirección.
  • La ventana no se puede arrastrar al abrir un cuadro de diálogo (#9140). Ahora se puede arrastrar Windows mientras hay un cuadro de diálogo abierto; Los botones minimizar, maximizar y cerrar todavía están disponibles cuando se usan los botones de ventana de la aplicación en Windows y Linux.
  • Excepción de visualización del panel de acceso directo de Linux: el panel y la ventana que se vuelven a abrir en el modo ligero se representan incorrectamente (#9233, #9216) y parte del panel se recorta cuando se configura el zoom de visualización (#9287, #8556). Los paneles en Linux cambiaron a un fondo opaco.
  • Cuando el nombre del proveedor comienza con caracteres como emoji o está precedido por un espacio, el primer carácter que se muestra en una tarjeta sin icono aparece confuso o en blanco (#8139).
  • La advertencia de riesgo del enlace de importación con un solo clic omite la dirección IPv6 con la dirección IPv4 integrada (#8127). Este tipo de dirección ahora se juzga según la dirección IPv4 a la que realmente apunta, ya sea la máquina local o la intranet.

cc-switch v4.0.27

Highlights

  • Full-text session search is opt-in — Search can now match message bodies, not just titles, directories, and IDs (#7896). CC Switch builds a separate local session-index.db; it is excluded from cloud sync and backups, deleted when the feature is disabled, and results may be incomplete during initial indexing—important if you rely on cross-device session history.
  • Configuration writes preserve symlinks — Provider switches now write through to the target of linked files such as ~/.claude/settings.json, ~/.codex/config.toml, and opencode.json instead of replacing the link (#9283). This keeps dotfiles and synced configurations connected and fixes Windows atomic-replacement error 1464; existing links need no migration.
  • Two reliability blockers are fixed — Codex custom-permission configurations now use an absolute model_catalog_json path, resolving plan-mode deserialization failures (#7349); WSL configuration directories intentionally still use a filename. Canceled requests now return circuit-breaker probe slots, preventing providers from remaining stuck in recovery until restart (#9292).
  • Skill updates no longer chase runtime artifacts — Update checks ignore __pycache__ and .pyc, preventing used Python Skills from being falsely marked stale and then overwritten during updates (#7780); old records are converted automatically. Repository discovery now counts the branch actually read and reports failures with reasons instead of showing “0 skills” (#9273).
  • Provider setup gains safer defaults and Grok terminal access — New Mistral AI presets default to mistral-large-4 because Medium 3.5 is deprecated; existing providers are unchanged. Grok Build’s terminal action appears only on the active provider because Grok CLI cannot switch providers per terminal; it uses CC Switch’s managed configuration and adds --always-approve when permission confirmation is skipped (#9234).
  • Breaking changes — None.

CC Switch v4.0.27

本版本让会话管理可以搜索消息正文，新增界面密度和界面缩放设置，模型定价表可以搜索，Grok Build 正在使用的供应商也能打开终端了。Skills 的已安装页重新排了版，供应商图标会跟随深浅色主题。另外修复了配置文件是软链接时被替换成普通文件或写入失败、取消请求后供应商卡在熔断恢复中直到重启、Codex 设置了自定义权限后 plan 模式报错、运行过的 Skill 被误报有更新、Skills 仓库显示 0 个 Skill、Windows 上把 Python 的 pi.exe 认成 Pi、模型价格同步超时、打开对话框时窗口拖不动、右键弹出浏览器菜单，以及 Linux 快捷面板显示异常等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

搜索会话的消息正文

以前会话管理页的搜索只能找标题、目录和会话 ID，记得聊过什么、却想不起是哪个会话时找不到（#7896、#7420）。

现在可以打开「搜索消息正文」：在页面右上角的「⋯」菜单里打开，或者搜索没有结果时直接点提示里的按钮。打开后，搜索结果会列出命中的正文片段和命中了几条消息。

  • 默认关闭。打开后 CC Switch 会在本地为消息正文建立索引，建立期间会显示进度，这时正文结果可能还不全。
  • 索引是单独的本地文件 session-index.db，不参与云同步，也不进备份；关闭这个开关会删除它。

界面密度和界面缩放

「设置 → 通用 → 外观」里新增两项（#9209）：

  • 界面密度：「紧凑」就是原来的尺寸，也是默认值；「舒适」的字号大一档，按钮和输入框更高一些。
  • 界面缩放：90%、100%、110%、125% 四档，也可以按 Ctrl（macOS 上是 ⌘）加 +、- 调整，按 Ctrl/⌘ 加 0 复原。

两项设置只保存在本机，和主题一样。托盘快捷面板始终保持紧凑尺寸。

模型定价表可以搜索

模型定价表上方加了搜索框，按模型 ID 或名称筛选（#9205）。按回车会编辑第一个结果；没有匹配的模型时，回车会为输入的模型新增定价。

Grok Build 打开终端

Grok Build 的供应商卡片也有「打开终端」按钮了（#9234）。Grok CLI 不能只让某一个终端换供应商，所以这个按钮只出现在正在使用的供应商上，打开的终端直接用 CC Switch 管理的这份 Grok 配置；选择跳过权限确认时会加上 --always-approve。

变更

  • Skills 已安装页重新排版（#9210）：
    • 名称列固定在左侧，窗口窄时各应用的列在它下面横向滚动。
    • 状态和来源筛选移到和「发现」页一样的工具栏里，选中 Skill 后也不会被挡住；批量操作保留更新、卸载和按应用「启用到」/「停用」。
    • 去掉了页头的「N 个可更新」链接，工具栏的「全部更新」已经写了数量；点每行的「可更新」标记就能更新这个 Skill。
    • 每行的「…」菜单保留打开文档、打开目录和卸载；写入失败时，错误信息显示在描述的位置。
  • 供应商图标跟随主题（#8438）：去掉了卡片图标后面固定的白底。单色的深色图标会跟着文字颜色变化，深色模式下也看得清；带深色笔画的多色图标、图片图标和你上传的图标在深色模式下仍然带浅色底。
  • 右键不再弹出浏览器菜单（#8919、#8921）：以前在主窗口和托盘面板里点右键，会弹出浏览器自带的菜单（Windows 上是「后退」「重新加载」「另存为」「打印」等）。现在不会了；输入框、代码编辑器和选中的文字仍然可以右键复制粘贴。
  • 熔断日志写明是哪家供应商（#9292）：熔断器的日志（CB-001 到 CB-006）都带上了「应用:供应商 id」；熔断器拒绝某家供应商时也会记一行 FWD-004，写明供应商名称，不再悄悄跳过。只改了日志，路由和熔断行为不变。
  • 预设： Mistral AI 预设的默认模型改为 mistral-large-4（Mistral Medium 3.5 已被 Mistral 宣布弃用），Claude Code、Codex 和 Claude Desktop 的 Mistral AI 预设不再隐藏。Mistral Vibe 套餐和 API 共用额度，「获取 API Key」改为打开 Vibe CLI 的密钥页，免费、订阅和按量付费都能用；添加供应商时搜「Vibe」也能找到它。新增 Genesis（#9269）、TokenPlus（#9296）。已添加的供应商不受影响。

修复

  • 配置文件是软链接时，切换供应商会把它替换成普通文件，Windows 上直接报错（#6764、#9283）。用 dotfiles 工具或同步文件夹管理 ~/.claude/settings.json、~/.codex/config.toml、opencode.json 等文件时，它们通常是软链接。以前写入时会把链接本身替换掉，macOS 和 Linux 上链接变成普通文件、和原文件脱钩，Windows 上报错「原子替换失败」（os error 1464）。现在会写到链接指向的真实文件，链接保持不变。
  • 请求中途被取消后，供应商可能一直处在熔断恢复中，直到重启（#7206、#9292）。熔断恢复期间，熔断器只放一个探测请求过去；如果这个请求还没结束客户端就断开了，名额不会还回去，之后发给这家供应商的请求全被拒绝。现在无论请求怎么结束，名额都会还回去。
  • Codex 设置了自定义权限后，用 plan 模式报错（#7349、#7294）。较新的 Codex 读取自定义权限时要求 model_catalog_json 是绝对路径，以前 CC Switch 写的是文件名，Codex 报 AbsolutePathBuf deserialized without a base path。现在写成绝对路径；配置目录在 WSL 里时仍写文件名。
  • 运行过一次的 Skill 被显示为「可更新」，点更新会覆盖整个目录（#7780、#7772）。Python 运行时生成的 __pycache__ 和 .pyc 文件被算进了 Skill 的内容。现在检查更新时忽略这些文件；以前版本记下的旧记录会自动换算，不会因此误报。
  • Skills 仓库显示「识别到 0 个技能」（#9273）。导入时添加的仓库分支记为 HEAD，或者仓库默认分支是 master 却配成了 main 时，数量总是 0。现在按实际读取的分支计数；读取失败的仓库会写明「读取失败」和原因，导入 Skill 新增了仓库后，下次打开会重新读取。
  • Windows 上把 Python 包里的 pi.exe 当成 Pi（#9267）。PyPI 上有一个无关的 pi 包会装出 Scripts\pi.exe，应用页会把它显示为「无法运行」。Pi 只通过 npm 发布，现在 Python Scripts 目录里的 pi.exe 不再被识别为 Pi。
  • 模型价格同步失败，只提示 error decoding response body（#9262）。网络较慢或经代理时，从 models.dev 下载价格表会在读到一半时超时。现在超时时间从 15 秒放宽到 60 秒，失败时同步状态里会写出真正的原因。
  • 添加 DeepSeek Harness 供应商时只提示 Invalid DeepSeek Harness profile YAML，不知道是哪个文件（#9297）。现在报错会写出出错的配置文件路径和 YAML 的具体错误，方便找到文件修复。
  • 连通性测试把会重定向的中转站判为不通（#9253、#5747）。有的网关在 /v1 和 /v1/ 之间互相重定向，现在测试收到重定向就算连得上。
  • 打开对话框时窗口拖不动（#9140）。现在对话框打开时仍然可以拖动窗口；Windows 和 Linux 上使用应用内窗口按钮时，最小化、最大化和关闭按钮也照常可用。
  • Linux 快捷面板显示异常：轻量模式下重新打开的面板和窗口渲染出错（#9233、#9216），设置了显示缩放时面板被裁掉一部分（#9287、#8556）。Linux 上的面板改为不透明背景。
  • 供应商名称以 emoji 等字符开头、或前面带空格时，没有图标的卡片显示的首字是乱码或空白（#8139）。
  • 一键导入链接的风险提示漏判了内嵌 IPv4 地址的 IPv6 地址（#8127）。这类地址现在按它实际指向的 IPv4 地址判断是否为本机或内网。
