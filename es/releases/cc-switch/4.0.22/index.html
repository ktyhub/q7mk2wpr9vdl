Interruptor CC v4.0.22

Esta versión agrega soporte para DeepSeek Harness, que es la decimocuarta aplicación administrada por CC Switch: el proveedor escribe su configuración web y de escritorio juntas, MCP, habilidades y palabras de aviso se sincronizan con ella, se puede explorar la sesión y la página "Aplicación" se puede instalar, actualizar y desinstalar; También puede iniciar sesión en la cuenta de DeepSeek en el centro de autorización, consultar el saldo y las estadísticas de uso. El uso de Oh My Pi ahora también se cuenta. "Abrir terminal" puede marcar para omitir la confirmación de permiso y agregar parámetros de inicio, y la tarjeta Codex también puede abrir el terminal; La configuración de WebDAV se puede borrar; Las habilidades pueden abrir el directorio y ver documentos en la página de descubrimiento; El modelo Claude de GitHub Copilot ha cambiado a la interfaz nativa, lo que indica que la tasa de aciertos de caché ha mejorado enormemente. Además, se ha solucionado el problema de que el cambio de cuenta de Claude falla cuando el MCP remoto de OAuth está conectado a macOS, se informa 403 al agregar una cuenta de Claude cuando el proxy global está habilitado, Fable se usa de forma predeterminada para las nuevas sesiones de Claude Desktop, la cuota semanal MiniMax no se muestra después de agotarse, los saldos de proveedores no utilizados no se actualizan automáticamente, las solicitudes se redirigen a la ruta misma, lo que hace que la memoria se dispare, la llamada a la herramienta Gemini se informa 400, xAI rechaza el Codex 0.163 Hay problemas como almacenar una página completa de informes de errores en el registro de solicitudes y expandir la base de datos. Para obtener el contenido completo de la actualización de 4.0, consulte las Notas de la versión v4.0. Inglés → | Versión japonesa →

Agregar

Arnés DeepSeek

DeepSeek Harness (comando dsh) es ahora una aplicación independiente con su propio proveedor, MCP, habilidades, indicaciones y sesiones (#8795, #8986). Está configurado en ~/.dsh. Cuando se establece DSH_HOME, prevalecerá.

  • **Web y Escritorio administrados juntos. ** La versión web y la versión de escritorio de DeepSeek Harness tienen cada una una configuración (perfil). CC Switch escribe el proveedor y el MCP en dos perfiles al mismo tiempo. El perfil que falta se creará automáticamente; el headless inicializado y el acp también se escriben juntos. Solo hay un arnés DeepSeek en la barra lateral y junto al título "Agregado" se indica que la Web y el escritorio comparten esta lista. Cuando una copia se modifica manualmente para que sea diferente de otra copia, el editor será rechazado y avisado, y sus cambios no se sobrescribirán.
  • **Se pueden agregar proveedores al mismo tiempo. ** Igual que OpenCode, "agregar" y "eliminar", varios proveedores pueden escribir al mismo tiempo y seleccionar el modelo en DeepSeek Harness. Admite tres interfaces: Finalizaciones de chat OpenAI, Respuestas OpenAI y Mensajes antrópicos, y está preestablecido desde el directorio Pi. La clave API se escribe en el archivo de credenciales .credentials.yaml del propio DeepSeek Harness y solo se coloca la referencia en la configuración; otras configuraciones de complementos en la configuración se conservan tal como están y se revertirán si falla la escritura.
  • **Edición de modelo. ** Los interruptores de entrada de pensamiento e imagen, la longitud del contexto y la salida máxima se completan por separado, al igual que las líneas modelo de Pi y Kimi Code; DeepSeek Harness también puede configurar engranajes de pensamiento opcionales y opciones de compatibilidad de interfaz para cada modelo. La edición de modelos de OpenCode y MiniMax Code también se ha cambiado para verse así.
  • **Inicio de sesión de cuenta DeepSeek. ** Utilice un navegador para iniciar sesión en su cuenta DeepSeek en el grupo DeepSeek Harness del centro de autorización y se mostrarán el saldo y la bonificación; La Web y el escritorio comparten este inicio de sesión, y el inicio o cierre de sesión en cualquiera de los dos lugares tendrá efecto en ambos lados. Al agregar un proveedor, al seleccionar "Inicio de sesión oficial de DeepSeek" se accederá al centro de autorización. Después de iniciar sesión, la cuenta se mostrará al frente de "Agregado" con una tarjeta oficial. El modelo de la cuenta lo proporciona el propio DeepSeek Harness. Esta tarjeta no se puede editar y desaparecerá automáticamente después de cerrar sesión.
  • **MCP, Habilidades, palabras clave. ** Admite stdio y HTTP MCP transmitible.
  • **Sesiones y uso. ** Puede explorar las sesiones de DeepSeek Harness (incluidos procesos de pensamiento y llamadas a herramientas); restaure y elimine sesiones en DeepSeek Harness. El uso se importa de los registros de sesión y las solicitudes que utilizan cuentas de DeepSeek se muestran por separado como "Cuenta de DeepSeek (OAuth)" en la página de uso.
  • **La página "Aplicación" administra DeepSeek Harness. ** Utilice npm para instalar, actualizar y desinstalar @deepseek-ai/dsh. La desinstalación no eliminará sus datos.
  • DeepSeek Harness no pasa por enrutamiento local.

Estadísticas de uso de Oh My Pi

La página de uso ahora cuenta el uso de Oh My Pi y tiene su propia categoría de aplicación (#9046, #8939). También se cuentan el uso de subagente, las llamadas de modelo fuera de las conversaciones y la primera importación incluirá sesiones anteriores de subagente. Cuando Oh My Pi y Pi usan el mismo directorio de sesión, cada uno solo importa su propia sesión. No es necesario volver a importar los datos ya importados por Pi.

"Abrir Terminal" puede omitir la confirmación de permiso y agregar parámetros de inicio.

Hay dos elementos más en el cuadro de diálogo "Abrir terminal" (#9008):

  • **Omitir confirmación de permiso. ** Después de la verificación, Claude Code y Antigravity se inician con --dangerously-skip-permissions y Codex se inicia con --dangerously-bypass-approvals-and-sandbox. No marcado por defecto.
  • **Parámetros adicionales (opcional). ** Complete parámetros como --debug y --append-system-prompt "Be concise", seguidos del comando de inicio. Separe con espacios y encierre los valores que contengan espacios entre comillas, hasta 16 valores. Los parámetros solo se pasan al programa como parámetros y no se ejecutarán como comandos. Ambos elementos sólo se utilizan para el terminal abierto esta vez y no escriben ninguna configuración; Después de que la terminal se abra exitosamente, CC Switch recordará su selección al aplicarla.

Las tarjetas Codex también pueden "abrir terminal"

Anteriormente, este botón no estaba disponible en las tarjetas Codex. Ahora el terminal abierto por la tarjeta de terceros solo usa esta tarjeta: comience con codex -c ..., no cambie config.toml, la clave se pasa a través de la variable de entorno y no aparece en la línea de comando. La configuración dejada por el proveedor actual en config.toml se cambiará a valores que no afecten en la medida de lo posible a esta tarjeta. Aquellos que no se pueden cambiar (como encabezados de solicitud y perfiles específicos) le solicitarán que primero cambie a esta tarjeta y luego la abra para evitar que la clave del proveedor actual se envíe a otro lugar. La tarjeta actualmente en uso inicia codex directamente.

Borrar la configuración de WebDAV

Después de configurar la sincronización WebDAV en el pasado, solo podía desactivar la sincronización automática y la dirección, la cuenta y la contraseña siempre se dejaban en la máquina local (#8977). Ahora hay un botón "Borrar configuración" en la configuración de sincronización WebDAV. Después de la confirmación, la información se eliminará de la máquina local y se detendrá la sincronización automática; los datos cargados en la nube no se eliminarán.

Habilidades: abrir directorio, copiar nombre, ver documento

  • Skill instalado (#8993): ⋯ Puede "Abrir directorio" en el menú y abrir la carpeta de este Skill en el administrador de archivos; haga clic en el nombre de la habilidad para copiar el nombre. Se ha eliminado el "Copiar nombre de directorio" original.
  • Página de descubrimiento (#9039): cada línea tiene un botón "Abrir documento". Puede leer las instrucciones antes de la instalación. Si no hay ningún documento, abra la página de inicio del almacén.

Mejoras

El modelo Claude de GitHub Copilot sugiere una gran mejora en la tasa de aciertos de caché (#8908). En el pasado, todos los modelos Claude de Copilot se convertían al formato de finalización de chat y se enviaban, lo que perdía la etiqueta de caché. Los mensajes del sistema insertados por Claude Code en medio de la conversación también interrumpirían el caché. Ahora Copilot admite el modelo de interfaz Anthropic nativo para utilizar la interfaz nativa directamente. La tasa de aciertos de caché de la sesión larga de Copilot Enterprise Edition se ha medido entre aproximadamente el 35% y aproximadamente el 95%. Al agregar, habilitar, desactivar o eliminar repositorios de habilidades, solo se volverá a leer este repositorio (#8907, #1426), y todos los repositorios ya no se descargarán nuevamente. Al hacer clic en el botón Actualizar se volverá a leer todo. **También puedes ver el límite de la tarjeta oficial de Claude vinculado a la cuenta en la bandeja y en la configuración de uso. ** En el pasado, solo se mostraba en la tarjeta, no en la bandeja, y la ventana emergente de configuración de uso todavía se mostraba como no habilitada. El servicio de enrutamiento de Claude Desktop también acepta el token x-api-key (#5123), y la verificación del token se cambia a una comparación fija que requiere mucho tiempo (#7488, #7482). Cuando el directorio de configuración de Claude está en WSL, el centro de autorización indica directamente que la cuenta de Claude no es compatible actualmente y "Agregar cuenta" y "Volver a iniciar sesión" no están disponibles. En el pasado, se le pedía que usara "Abrir terminal", pero ahora abre Claude Code en Windows, que tampoco se puede usar. Ya no aparecerán dos mensajes al mismo tiempo al pasar el cursor sobre la casilla de verificación en las listas de MCP y Habilidades; la tarjeta de ayuda con el signo de interrogación se mostrará a la derecha, sin bloquear el mouse, y el contenido largo se ajustará y se desplazará en la tarjeta (#8593). Al saltar de otros lugares a un determinado grupo en el centro de autorización, otras partes de la página ya no se moverán en consecuencia (#8964). Cuando los archivos de configuración de OpenCode, OpenClaw y Hermes no se pueden leer, se mostrará un error en la página del proveedor (#9044). En el pasado, la página estaba vacía como si nunca se hubiera configurado. Solo vi un error después de que falló al agregar un proveedor y quedó un registro redundante. **Cuando caduque el inicio de sesión administrado de la cuenta ChatGPT y xAI, el mensaje cambiará a "Inicie sesión en esta cuenta nuevamente en el centro de autorización". ** Anteriormente se me pidió que ejecutara un comando que no existía. Predeterminado: Se agregó el código Claude predeterminado (#9036) para OspreyAI y iFlytek Astron Coding Plan; TokenFlux utiliza el nuevo nombre de dominio tokenflux.com y tokenflux.dev como dirección de respaldo.

Arreglar

  • Al conectarse a un MCP remoto que requiere inicio de sesión OAuth en macOS, al cambiar la cuenta de Claude, aparece el mensaje "La información de inicio de sesión de Claude Code es demasiado grande y no se puede escribir en el llavero, y no hay ningún cambio" (#9002). La información de inicio de sesión y la cuenta de MCP existen en la misma entrada del llavero, lo que excede la longitud máxima de una escritura. Ahora el código superlargo está escrito de la misma manera que Claude Code.
  • Cuando el proxy global esté activado, agregue la cuenta de Claude en el centro de autorización y el navegador informará 403 (#9038) después de iniciar sesión correctamente. El intercambio de tokens lo realiza el propio Claude Code y antes no utilizaba el proxy global. Ahora, cuando CC Switch ejecute Claude Code para iniciar sesión y verificar el saldo, se le pasará el proxy global (el proxy SOCKS Claude Code no lo admite y no se pasará).
  • Las nuevas sesiones de Claude Desktop usan Fable de forma predeterminada y el orden de los modelos cambiará cada vez que se habilita la configuración (#7491, #7457, #8973). Claude Desktop trata el primer modelo de la lista como el modelo predeterminado, previamente escrito en orden alfabético. Ahora escriba en el orden de Soneto, Opus, Fábula y Haiku en la interfaz. La nueva sesión utiliza el archivo Sonnet de forma predeterminada.
  • Después de que se agote la cuota semanal MiniMax, la cuota semanal ya no se mostrará en la tarjeta ni en la bandeja. Cuando se restablece la cuota de 5 horas por primera vez, parecerá que está llena (#8124, #8123). Ahora muestra un "Usado" rojo y una cuenta regresiva para el reinicio de la cuota semanal.
  • El proveedor que no está en uso ha establecido un intervalo de consulta automática y el saldo no se actualiza (#8342, #8335).
  • Cuando la dirección ascendente se completa con la propia dirección de la ruta, la solicitud se redirige de nuevo a la ruta infinitamente y la memoria continúa creciendo (#8598). Ahora informe directamente el error de configuración.
  • Cuando Claude Code se conecta a Gemini a través de un enrutador, se informa un mensaje 400 después de llamar a la herramienta: la firma está fuera de lugar e informa "Nombre desconocido thinkSignature" (#6690); el CC Switch pierde la firma después de reiniciar o en una ronda anterior, y Gemini 3 o superior rechaza la solicitud (#6833); el resultado de la herramienta en Vertex va seguido del texto "Las solicitudes que terminan con un giro de modelo no son compatibles" (#8988).
  • Cuando Claude Code se reenvía a OpenAI Responses a través de enrutamiento, WebSearch con nombres de dominio bloqueados informará directamente 400 (#8979). Ahora las respuestas conectadas por la clave API se pasarán al flujo ascendente tal como están; la ruta de inicio de sesión oficial de ChatGPT no admite el bloqueo de nombres de dominio y aún así se informará claramente un error.
  • La ruta anterior del Codex 0.163 está conectada a xAI Times 400 (#8997, #8996).
  • Cuando hay una tabla de matriz como [[skills.config]] en config.toml del Codex, la dirección del proveedor externo se escribe en esta tabla (#9029, #9023).
  • El proveedor del nuevo formato OpenCode (V2) "Verificar conectividad" informa que falta options.baseURL (#8969).
  • Cuando se informa el error ascendente, el registro de solicitudes guarda la página completa de error HTML y la base de datos y la copia de seguridad son cada vez más grandes (#9010, #6706). Ahora sólo se guardan los primeros 4096 caracteres de cada registro; Los registros antiguos que se han guardado no se borrarán esta vez.
  • Cuando se utiliza una barra de tareas de terceros como MyDockFinder en Windows, no hay respuesta al hacer clic en el icono de la bandeja (#8729, #8565).
  • La versión anterior de Kimi Code 0.43.0 permanecerá sin cambios después de la actualización en la página "Aplicación" (#9032). Las versiones anteriores no tienen la opción de confirmar automáticamente las actualizaciones; ahora utilice el administrador de paquetes que las instaló o vuelva a ejecutar el script de instalación oficial.
  • **En la página "Aplicaciones", las aplicaciones que tienen archivos de programa pero que no pueden ejecutarse se muestran como "No instaladas" en el grupo "Instaladas". ** Ahora muestra "No se puede ejecutar" y proporciona el motivo.
  • Cuando CLI de Antigravity y el IDE están instalados, el uso de la sesión anterior que continúa en el IDE no se actualiza y la sesión no se puede abrir (#8941).

Instrucciones de actualización

Versión de la base de datos actualizada de 23 a 24, agregando conmutadores DeepSeek Harness para MCP y Skills. Se realizará una copia de seguridad de la base de datos automáticamente antes de la actualización; Si vuelve a la versión anterior después de la actualización, la versión anterior le indicará que la versión de la base de datos es demasiado nueva y no se puede abrir.

  • DeepSeek Harness se muestra en la barra lateral de forma predeterminada. Si no se utiliza, puede desactivar "Mostrar el arnés DeepSeek en la barra lateral" en la página "Aplicación".

cc-switch v4.0.22

Highlights

  • DeepSeek Harness becomes the 14th managed app — CC Switch now manages its providers, MCP, Skills, prompts, sessions, and npm lifecycle (#8795, #8986). Web and Desktop profiles are synchronized, conflicting manual edits are rejected instead of overwritten, and API keys stay in .credentials.yaml. Harness traffic bypasses CC Switch’s local router, so route-based policies will not apply.

  • Copilot’s Claude models now use native Anthropic requests — eliminating the Chat Completions conversion that discarded cache markers and was disrupted by mid-conversation system messages (#8908). Reported enterprise cache-hit rates rose from roughly 35% to 95%, potentially reducing latency and token costs substantially.

  • Codex provider cards can launch isolated terminals — these use codex -c ..., pass keys through environment variables, and leave config.toml untouched. However, existing headers or profile settings can still override the card; CC Switch warns when this happens. The new permission-bypass options for Claude Code, Antigravity, and Codex disable important safety boundaries and apply only to that terminal session (#9008).

  • Several cross-provider routing failures are resolved — self-referencing upstream URLs now fail fast instead of causing an infinite forwarding loop and memory growth (#8598); Gemini tool signatures survive restarts and later turns (#6690, #6833); and Codex array tables no longer receive provider URLs by mistake (#9029).

  • Logs and sync credentials are easier to control — upstream error bodies are capped at 4,096 characters to prevent database and backup bloat, but existing oversized records are not cleaned up (#9010). WebDAV settings can now be fully purged locally without deleting cloud data, while Oh My Pi gains usage accounting, including subagents and non-conversation model calls (#9046).

  • The database migration is one-way — schema version 23 upgrades to 24 for DeepSeek Harness MCP and Skills switches. CC Switch creates a backup automatically, but after upgrading, older releases reject the database as too new; do not downgrade without restoring that backup.

CC Switch v4.0.22

本版本新增对 DeepSeek Harness 的支持，它是 CC Switch 管理的第 14 个应用：供应商一起写进它的 Web 和 Desktop 配置，MCP、Skills、提示词同步给它，会话可以浏览，「应用」页可以安装、升级、卸载；还可以在授权中心登录 DeepSeek 账号、查看余额，用量也会统计。Oh My Pi 的用量现在也会统计。「打开终端」可以勾选跳过权限确认、追加启动参数，Codex 卡片也能打开终端；WebDAV 配置可以清除；Skills 可以打开目录、在发现页查看文档；GitHub Copilot 的 Claude 模型改走原生接口，提示缓存命中率大幅提高。另外修复了 macOS 上连了 OAuth 远程 MCP 时切换 Claude 账号失败、开了全局代理时添加 Claude 账号报 403、Claude Desktop 新会话默认用 Fable、MiniMax 周额度用完后不显示、没在用的供应商余额不自动刷新、请求被转回路由自己导致内存暴涨、Gemini 工具调用报 400、xAI 拒绝 Codex 0.163 的请求、请求日志里存下整页报错把数据库撑大等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

DeepSeek Harness

DeepSeek Harness（命令是 dsh）现在是一个独立的应用，有自己的供应商、MCP、Skills、提示词和会话（#8795、#8986）。配置在 ~/.dsh，设了 DSH_HOME 时以它为准。

  • Web 和 Desktop 一起管理。 DeepSeek Harness 的网页版和桌面版各有一份配置（profile），CC Switch 把供应商和 MCP 同时写进两份，缺的那份会自动建好；已经初始化的 headless、acp 也一起写。侧栏只有一个 DeepSeek Harness，「已添加」标题旁注明 Web 和 Desktop 共用这份列表。某一份被手动改得和另一份不一样时，编辑会被拒绝并提示，不会覆盖你的改动。
  • 供应商可以同时添加。 和 OpenCode 一样是「添加」「移除」，多个供应商同时写进去，在 DeepSeek Harness 里选模型。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种接口，预设来自 Pi 的目录。API Key 写进 DeepSeek Harness 自己的凭据文件 .credentials.yaml，配置里只放引用；配置里的其他插件设置原样保留，写入失败会回滚。
  • 模型编辑。 思考、图片输入用开关，上下文长度和最大输出单独填，和 Pi、Kimi Code 的模型行一样；DeepSeek Harness 还可以设置可选的思考档位和每个模型的接口兼容选项。OpenCode、MiniMax Code 的模型编辑也改成了这个样子。
  • DeepSeek 账号登录。 在授权中心的 DeepSeek Harness 组用浏览器登录 DeepSeek 账号，显示余额和赠金；Web 和 Desktop 共用这份登录，在任一处登录或退出，两边同时生效。添加供应商时选「DeepSeek 官方登录」会跳到授权中心。登录后，账号以一张官方卡显示在「已添加」最前面，账号下的模型由 DeepSeek Harness 自己提供，这张卡不能编辑，退出登录后自动消失。
  • MCP、Skills、提示词。 支持 stdio 和 Streamable HTTP 两种 MCP。
  • 会话和用量。 可以浏览 DeepSeek Harness 的会话（含思考过程和工具调用）；恢复和删除会话请在 DeepSeek Harness 里操作。用量从会话记录导入，走 DeepSeek 账号的请求在用量页单独显示为「DeepSeek 账号（OAuth）」。
  • 「应用」页管理 DeepSeek Harness。 用 npm 安装、升级、卸载 @deepseek-ai/dsh，卸载不删你的数据。
  • DeepSeek Harness 不经过本地路由。

Oh My Pi 的用量统计

用量页现在会统计 Oh My Pi 的用量，有自己的应用分类（#9046、#8939）。子代理的用量、对话之外的模型调用也会算进去，首次导入会包括以前的子代理会话。Oh My Pi 和 Pi 用同一个会话目录时，各自只导入自己的会话。Pi 已导入的数据不用重新导入。

「打开终端」可以跳过权限确认、追加启动参数

「打开终端」对话框多了两项（#9008）：

  • 跳过权限确认。 勾选后 Claude Code 和 Antigravity 以 --dangerously-skip-permissions 启动，Codex 以 --dangerously-bypass-approvals-and-sandbox 启动。默认不勾。
  • 附加参数（可选）。 填 --debug、--append-system-prompt "Be concise" 这类参数，接在启动命令后面。用空格分隔，含空格的值用引号括起来，最多 16 个。参数只作为参数传给程序，不会被当成命令执行。

两项都只用于这次打开的终端，不写进任何配置；终端打开成功后，CC Switch 会按应用记住你的选择。

Codex 卡片也能「打开终端」

以前 Codex 卡片上没有这个按钮。现在第三方卡片打开的终端只用这张卡：以 codex -c ... 启动，不改 config.toml，Key 通过环境变量传入，不出现在命令行里。当前供应商在 config.toml 里留下的设置会尽量改成不影响这张卡的值，改不了的（比如请求头、指定的 profile）会提示先切到这张卡再打开，避免当前供应商的 Key 被发到别处。当前使用中的卡直接启动 codex。

清除 WebDAV 配置

以前配好 WebDAV 同步后，只能关掉自动同步，地址、账号、密码一直留在本机（#8977）。现在 WebDAV 同步设置里有「清除配置」按钮，确认后从本机删除这些信息并停止自动同步；云端已上传的数据不会删除。

Skills：打开目录、复制名称、查看文档

  • 已安装的 Skill（#8993）：⋯ 菜单里可以「打开目录」，在文件管理器里打开这个 Skill 的文件夹；点击 Skill 名称就能复制名称。原来的「复制目录名」去掉了。
  • 发现页（#9039）：每一行多了「打开文档」按钮，安装前可以先看说明，没有文档时打开仓库主页。

改进

GitHub Copilot 的 Claude 模型提示缓存命中率大幅提高（#8908）。以前 Copilot 的 Claude 模型一律转成 Chat Completions 格式发送，会丢掉缓存标记，Claude Code 在对话中途插入的系统消息还会打断缓存。现在 Copilot 支持原生 Anthropic 接口的模型直接走原生接口，Copilot 企业版长会话的缓存命中率实测从约 35% 提高到约 95%。

添加、启用、停用、删除 Skill 仓库时，只重新读取这一个仓库（#8907、#1426），不再把所有仓库重新下载一遍。点刷新按钮仍会全部重新读取。

托盘和用量设置里也能看到绑了账号的 Claude 官方卡额度。 以前只有卡片上显示，托盘里没有，用量设置弹窗还显示成未启用。

Claude Desktop 的路由服务也接受 x-api-key 传令牌（#5123），令牌校验改成固定耗时的比较（#7488、#7482）。

Claude 配置目录在 WSL 里时，授权中心直接说明暂不支持 Claude 账号，「添加账号」「重新登录」不可用。以前会让你改用「打开终端」，但这时打开的是 Windows 里的 Claude Code，同样用不了。

MCP、Skills 列表悬停勾选框时不再同时弹出两个提示；问号帮助卡片改为显示在右边，不再挡住鼠标，长内容会换行、在卡片里滚动（#8593）。

从别处跳到授权中心的某一组时，页面其他部分不再跟着移动（#8964）。

OpenCode、OpenClaw、Hermes 的配置文件读不了时，供应商页会显示错误（#9044）。以前页面像从没配置过一样空着，添加供应商失败后才看到报错，还会留下一条多余的记录。

托管的 ChatGPT、xAI 账号登录过期时，提示改为「请在授权中心重新登录这个账号」。 以前提示运行一条并不存在的命令。

预设： 新增 OspreyAI、讯飞星火 Astron Coding Plan 的 Claude Code 预设（#9036）；TokenFlux 改用新域名 tokenflux.com，tokenflux.dev 作为备用地址。

修复

  • macOS 上连了需要 OAuth 登录的远程 MCP 时，切换 Claude 账号报「Claude Code 的登录信息太大，无法写入钥匙串，没有切换」（#9002）。MCP 的登录信息和账号存在同一个钥匙串条目里，超过了一次写入的长度上限。现在超长时改用和 Claude Code 一样的写法。
  • 开了全局代理时，在授权中心添加 Claude 账号，浏览器登录成功后报 403（#9038）。换取令牌是 Claude Code 自己完成的，以前它没有用到全局代理。现在 CC Switch 运行 Claude Code 登录、查额度时会把全局代理传给它（SOCKS 代理 Claude Code 不支持，不传）。
  • Claude Desktop 新会话默认用 Fable，而且模型顺序每次启用配置都会变（#7491、#7457、#8973）。Claude Desktop 把模型列表里的第一个当默认模型，以前按字母顺序写。现在按界面上 Sonnet、Opus、Fable、Haiku 的顺序写，新会话默认用 Sonnet 档。
  • MiniMax 周额度用完后，卡片和托盘里不再显示周额度，5 小时额度刚重置时看起来像额度全满（#8124、#8123）。现在显示为红色的「已用完」和周额度重置倒计时。
  • 没在用的供应商设了自动查询间隔，余额也不刷新（#8342、#8335）。
  • 上游地址填成了路由自己的地址时，请求被无限转回路由，内存不断增长（#8598）。现在直接报配置错误。
  • Claude Code 经路由连 Gemini 时，工具调用后报 400：签名放错位置报「Unknown name thoughtSignature」（#6690）；CC Switch 重启后或较早的轮次丢了签名，Gemini 3 以上拒绝请求（#6833）；Vertex 上工具结果后面跟着文字时报「Requests ending with a model turn are not supported」（#8988）。
  • Claude Code 经路由转 OpenAI Responses 时，WebSearch 带屏蔽域名就直接报 400（#8979）。现在 API Key 接入的 Responses 上游会原样传过去；ChatGPT 官方登录的路由不支持屏蔽域名，仍会明确报错。
  • Codex 0.163 以上经路由连 xAI 时报 400（#8997、#8996）。
  • Codex 的 config.toml 里有 [[skills.config]] 这类数组表时，第三方供应商的地址被写进了这张表里（#9029、#9023）。
  • OpenCode 新格式（V2）的供应商「检测连通」报缺少 options.baseURL（#8969）。
  • 上游报错时，请求日志存下整页 HTML 报错，数据库和备份越来越大（#9010、#6706）。现在每条只存前 4096 个字符；已经存下的旧记录这次不清理。
  • Windows 上用 MyDockFinder 这类第三方任务栏时，点托盘图标没反应（#8729、#8565）。
  • Kimi Code 0.43.0 以前的版本在「应用」页升级后版本不变（#9032）。旧版本没有自动确认升级的选项，现在改用安装它的包管理器，或重新运行官方安装脚本。
  • 「应用」页里，程序文件在但运行不起来的应用，分在「已安装」组里却显示「未安装」。 现在显示为「无法运行」，并给出原因。
  • Antigravity 的 CLI 和 IDE 都装了时，在 IDE 里继续的旧会话用量不更新、会话打不开（#8941）。

升级说明

数据库版本从 23 升到 24，为 MCP 和 Skills 增加 DeepSeek Harness 的开关。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。

  • DeepSeek Harness 默认显示在侧栏，不用的话可以在「应用」页关掉「在侧栏显示 DeepSeek Harness」。
