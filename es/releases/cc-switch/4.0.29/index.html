Interruptor CC v4.0.29

Esta versión agrega una nueva aplicación administrada GitHub Copilot CLI: Los proveedores con su propia clave escribirán su propio providers.json en Copilot. Utilice /model en copilot para seleccionarlo junto con el modelo oficial sin pasar por CC Switch. Se han agregado los idiomas coreano y ruso a la interfaz. Los siete idiomas se han mantenido simultáneamente y el inglés ya no se muestra en los lugares que faltan. Además, la versión de escritorio de Codex en Windows informó un error al ejecutar Codex en WSL cuando se utiliza un proveedor externo; Las nuevas conversaciones del Codex informaron 400 al conectarse al flujo ascendente de Respuestas nativas de terceros a través de enrutamiento; cuando Codex se conectaba al formato Anthropic en sentido ascendente mediante enrutamiento, las respuestas largas se truncaban por el límite superior de salida de 8192; El funcionario del Codex se quedó atascado en el modo de enrutamiento y no pudo obtener la lista de modelos de la cuenta. Agregar

GitHub Copiloto CLI

GitHub Copilot CLI (copilot) se convierte en una nueva aplicación administrada (#8753, consulte #5768 para conocer los requisitos). Existen dos tipos de tarjetas de proveedor:

  • Inicio de sesión oficial: inicie sesión con Copilot CLI, su propio GitHub sin escribir ningún archivo. "Open Terminal" inicia copilot con el modelo y la fuerza de inferencia en la tarjeta; cuando la tarjeta esté vinculada a la cuenta GitHub del centro de autorización, utilice esta cuenta para comenzar. El límite de Copilot de la cuenta se muestra en la tarjeta.
  • Proveedores con Clave propia: Haga clic en "Agregar" y escriba la propia providers.json ($COPILOT_HOME/providers.json) de Copilot. Luego, si inicia copilot en cualquier lugar de la máquina, puede seleccionar "Logotipo/modelo de tarjeta" en /model junto con el modelo oficial, y la solicitud se enviará directamente al proveedor sin pasar por CC Switch. GitHub se puede utilizar sin iniciar sesión.
    • CC Switch solo cambia sus propias entradas, dejando otras entradas en el archivo (Copilot también escribirá este archivo) y el orden sin cambios. providers.json Copilot no podrá iniciarse si está escrito incorrectamente, por lo que se verificará todo el archivo de acuerdo con las reglas de Copilot antes de escribir. Por ejemplo, la salida máxima del modelo no puede ocupar toda la ventana de contexto.
    • La casa donde se encuentra el modelo predeterminado actual de Copilot está marcada como predeterminada y no se puede eliminar ni eliminar. Para cambiar, primero use /model en copilot para reemplazarlo por otro modelo.
    • El botón terminal de la tarjeta sólo se puede utilizar después de añadirla. Al comenzar, seleccione directamente el primer modelo de esta tarjeta.
    • Los valores predeterminados heredan los valores predeterminados del proveedor de Pi. También soporta:
  • MCP, Habilidades, Palabras Rápidas: Sincronizado con el mcp-config.json de Copilot, el directorio de Habilidades y los archivos de comando.
  • Gestión de sesiones: Lista las sesiones de Copilot, que se pueden reanudar en el terminal.
  • Estadísticas de uso: Importa el uso desde el registro de sesión de Copilot; A los proveedores con Clave propia se les facturará según la tarjeta seleccionada en la sesión.
  • Enlace de importación con un clic: puede importar proveedores de Copilot, reconocer la escritura providers.json, admitir bearerToken y conservar todos los ID de modelo en el enlace.

Interfaces coreano y ruso, se mantienen siete idiomas simultáneamente

  • Coreano (#8794, consulte #2704 para conocer los requisitos) y ruso (#7788, consulte #6010 para conocer los requisitos): la selección automática por idioma del sistema en el primer inicio, el menú de la bandeja y el panel de acceso directo también se han traducido. La moneda para las estadísticas de uso se agregó al won coreano (KRW), que admite la adquisición automática de tipos de cambio.
  • El turco, el coreano y el ruso ya no son "traducciones comunitarias y se muestra inglés cuando falta": cada oración en la interfaz está disponible en siete idiomas: chino simplificado, chino tradicional, inglés, japonés, 한국어, Türkçe y Русский. Posteriormente también se cambiarán los textos publicitarios nuevos y modificados en los siete idiomas.
  • El resumen de actualización que aparece después de la actualización actualmente solo está disponible en chino simplificado, chino tradicional, inglés y japonés, y otros idiomas se muestran en inglés.

Cambiar

  • Copilot explica el motivo por el cual la lista de modelos obtenida está vacía (#5500): Las cuentas Copilot Free pueden obtener modelos, pero ninguno de ellos puede usarse en el selector de modelos. Anteriormente, solo indicaba que no se encontró ningún modelo. Ahora le indicará que es posible que esta cuenta no tenga activado Copilot Pro; Los formularios de Claude Code y Claude Desktop también indicarán que gpt-4.1 o gpt-4o se pueden completar manualmente. Cuando la cuenta tiene modelos, pero ninguno de ellos admite el formato upstream seleccionado actualmente, el formulario del Codex lo explicará por separado.

Arreglar

  • Cuando la versión de escritorio de Codex en Windows ejecuta Codex en WSL, un proveedor externo informa "No existe tal archivo o directorio (error 2 del sistema operativo)" al iniciar (#9375). A partir de v4.0.27, CC Switch escribe el archivo del directorio del modelo como una ruta absoluta de Windows en config.toml. El Codex en WSL no puede leer esta ruta y los tres modos de conexión directa, enrutamiento y agregación se ven afectados. Ahora en Windows, la versión de escritorio de Codex ha habilitado el cambio para volver a escribir solo el nombre del archivo cuando se ejecuta Codex en WSL, que se corregirá automáticamente la próxima vez que se escriba.
  • Nueva ruta de conversación del Codex para conectar respuestas nativas de terceros en sentido ascendente Times 400 (#9328, relacionado #7074, #9379). La nueva versión de escritorio del Codex traerá los resultados de la herramienta de contexto de página sin call_id en nuevas conversaciones, al igual que los recibos para la automatización y el envío de tareas cruzadas, y los flujos ascendentes con validación estricta rechazarán toda la solicitud. En el pasado, solo se reescribía para xAI, pero ahora todas las respuestas nativas no oficiales en sentido ascendente se reescriben en un mensaje de usuario y el contenido se conserva. Las suscripciones oficiales y los resultados de herramientas con call_id no se ven afectados.
  • Cuando el Codex está conectado al formato Anthropic ascendente a través del enrutador, la respuesta larga se trunca y se informa "Respuesta incompleta, motivo: max_output_tokens". Lo mismo ocurre con el reintento. Las solicitudes del Codex sin límite de salida se emitían anteriormente como 8192, y el pensamiento también cuenta: las llamadas a herramientas que escriben un archivo completo a la vez se agotaron. El valor predeterminado ahora es 32000. Cuando el límite de salida ascendente sea inferior, informará 400. Puede completar el valor que admite en los "tokens de salida máxima" del proveedor.
  • La tarjeta oficial del Codex no puede obtener la lista de modelos propios de la cuenta en el modo de enrutamiento: el Codex solo puede usar su propia lista, que carece de modelos específicos de la cuenta; Después de abrir Daybreak en la versión de escritorio del Codex, todos los modelos oficiales se vuelven grises. Ahora, cuando el enrutador esté usando la tarjeta oficial y "Suspender el uso del inicio de sesión oficial" no esté activado, el enrutador entregará la lista de modelos oficiales al Codex tal como está. Los proveedores externos no reenvían.
  • Cuando Claude Code se conecta al modelo DeepSeek en Mistral mediante enrutamiento, cada ronda después de que la herramienta se llama informa 422 (#9385, #9388).
  • La tarjeta Claude Code solo se puede utilizar mediante ruta. Después de hacer clic en "Abrir terminal", Claude Code indica "No he iniciado sesión" para cada frase y la solicitud no se envía en absoluto. Las credenciales para tarjetas como GitHub Copilot, Codex OAuth y xAI OAuth se proporcionan mediante enrutamiento. Las tarjetas en formatos no antrópicos deben convertirse al formato mediante enrutamiento, y el terminal se conecta directamente a la dirección de la tarjeta y no se puede utilizar. Ahora el botón "Abrir terminal" de este tipo de tarjeta está atenuado y dice que necesita activar el enrutamiento y ejecutar el cliente directamente en el terminal. Este tipo de tarjeta en la página del Codex también ha cambiado de un botón oculto a también atenuado.
  • El límite que se muestra en la tarjeta oficial de Claude puede ser el de otra cuenta: después de que el inicio de sesión predeterminado de esta máquina se cambie a otra cuenta, la tarjeta que se utiliza leerá el límite de la cuenta de inicio de sesión predeterminada. Ahora se confirmará que el inicio de sesión predeterminado pertenece a esta cuenta.
  • La cuota de Antigravity no coincide con agy /usage; Tanto Google AI Ultra 5x como 20x solo muestran "Google AI Ultra" (#9317, #9319).

cc-switch v4.0.29

Highlights

  • GitHub Copilot CLI becomes a managed app (#8753) — Two card types: official cards use Copilot CLI's own GitHub login and write no files; BYOK cards write into Copilot's own $COPILOT_HOME/providers.json (requested in #5768). The key architectural point: BYOK requests go straight from copilot to the provider via /model, bypassing CC Switch routing entirely, and work without a GitHub login. For adopters this is the first app whose config lives in the client rather than the switcher — expect to manage it from copilot itself.
  • BYOK safety rules and Copilot tooling — A malformed providers.json prevents Copilot from starting, so CC Switch validates the whole file before writing, touches only its own entry, and preserves other entries and ordering; the provider holding the current default model can't be removed until you switch away with /model. Presets are inherited from Pi. MCP servers, Skills, prompts, session resume and usage import are wired up, and one-click import links accept bearerToken while preserving model IDs — useful for migrating an existing Copilot setup.
  • Codex routing: 400s on new conversations and truncated long answers — Tool results without call_id (new-chat page context, automation receipts) are now rewritten as a user message for all non-official native Responses upstreams, not just xAI (#9328, #7074, #9379); official subscriptions and call_id-bearing results are untouched. Separately, routed requests to Anthropic-format upstreams now default to 32,000 output tokens instead of 8,192 (thinking counts toward the cap). Watch this: if an upstream's own limit is lower, set the provider's "max output tokens" or you'll trade truncation for a 400.
  • Codex WSL paths and account model lists — Since v4.0.27 CC Switch wrote Windows absolute paths for model directory files into config.toml; Codex under WSL couldn't read them and third-party providers failed with "No such file or directory" across direct, route and aggregate modes (#9375). The fix writes just the filename when WSL execution is enabled and self-corrects on the next write. Routing also now passes the official account's own model list through when the official card is active and "pause official login" is off — previously Daybreak greyed out every official model.
  • Claude Code routing and credential correctness — Fixes a 422 on every turn after a tool call when routing to DeepSeek models on Mistral (#9385, #9388), and stops the official card from showing another account's quota by verifying the default login belongs to that card. Route-only cards (Copilot, Codex OAuth, xAI OAuth, non-Anthropic formats) now grey out "Open terminal" instead of launching a session that reports "Not logged in" — if you used that button for these cards, run the client with routing enabled instead.
  • Seven languages at parity, clearer empty-model hints — Korean (#8794) and Russian (#7788) join the UI; Turkish, Korean and Russian are no longer partial translations with English fallbacks, all seven locales are maintained together, and KRW is added with automatic FX rates. Caveat: the post-upgrade summary still ships only in Simplified/Traditional Chinese, English and Japanese. An empty Copilot model list now explains a likely missing Copilot Pro subscription and suggests gpt-4.1/gpt-4o (#5500) rather than a generic "no models found".
  • No breaking changes.

CC Switch v4.0.29

本版本新增受管应用 GitHub Copilot CLI：自带 Key 的供应商会写进 Copilot 自己的 providers.json，在 copilot 里用 /model 就能和官方模型一起选，不用经过 CC Switch。界面新增韩语和俄语，七种语言从此同步维护，不再有缺的地方显示英文。

另外修复了 Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商启动就报错；Codex 新对话经路由连第三方原生 Responses 上游报 400；Codex 经路由连 Anthropic 格式上游时，长回答被 8192 的输出上限截断；Codex 官方卡在路由模式下拿不到账号自己的模型列表等问题。

新增

GitHub Copilot CLI

GitHub Copilot CLI（copilot）成为新的受管应用（#8753，需求见 #5768）。供应商卡片分两种：

  • 官方登录：用 Copilot CLI 自己的 GitHub 登录，不写任何文件。「打开终端」以卡片上的模型和推理强度启动 copilot；卡片绑定了授权中心的 GitHub 账号时，用这个账号启动。卡片上显示该账号的 Copilot 额度。
  • 自带 Key 的供应商：点「添加」后写进 Copilot 自己的 providers.json（$COPILOT_HOME/providers.json）。之后在本机任何地方启动 copilot，都能在 /model 里和官方模型并列选到「卡片标识/模型」，请求直接发给供应商，不经过 CC Switch 的路由。不登录 GitHub 也能用。
    • CC Switch 只改这一家自己的条目，文件里的其他条目（Copilot 自己也会写这个文件）和顺序原样保留。providers.json 写坏了 Copilot 会起不来，所以写入前会按 Copilot 的规则把整份文件校验一遍，例如模型的最大输出不能占满整个上下文窗口。
    • Copilot 当前默认模型所在的那一家标为默认，不能移除或删除。要换，先在 copilot 里用 /model 换成别家的模型。
    • 卡片上的终端按钮要添加之后才能用，启动时直接选中这张卡的第一个模型。
    • 预设沿用 Pi 的供应商预设。

此外还支持：

  • MCP、Skills、提示词：同步到 Copilot 的 mcp-config.json、Skills 目录和指令文件。
  • 会话管理：列出 Copilot 会话，可以在终端里恢复。
  • 用量统计：从 Copilot 的会话日志导入用量；自带 Key 的供应商按会话里选中的卡片记账。
  • 一键导入链接：可以导入 Copilot 供应商，认得 providers.json 写法，支持 bearerToken，链接里的模型 ID 全部保留。

韩语、俄语界面，七种语言同步维护

  • 韩语（#8794，需求见 #2704）和俄语（#7788，需求见 #6010）：首次启动按系统语言自动选择，托盘菜单和快捷面板也已翻译。用量统计的币种新增韩元（KRW），支持自动获取汇率。
  • 土耳其语、韩语、俄语不再是「社区翻译、缺的地方显示英文」：界面上的每一句话，中文简体、中文繁体、English、日本語、한국어、Türkçe、Русский 七种语言都有，之后新增和修改文案也会七种语言一起改。
  • 升级后弹出的更新摘要暂时只有中文简体、中文繁体、英文和日文，其他语言显示英文。

变更

  • Copilot 获取模型列表为空时说明原因（#5500）：Copilot Free 账号能拿到模型，但没有一个可以在模型选择器里用，以前只提示没有找到模型。现在会提示这个账号可能没有开通 Copilot Pro；Claude Code 和 Claude Desktop 的表单还会提示可以手动填写 gpt-4.1 或 gpt-4o。账号有模型、但都不支持当前选择的上游格式时，Codex 表单会单独说明。

修复

  • Windows 上 Codex 桌面版在 WSL 里运行 Codex 时，用第三方供应商一启动就报「No such file or directory (os error 2)」（#9375）。v4.0.27 起，CC Switch 在 config.toml 里把模型目录文件写成 Windows 绝对路径，WSL 里的 Codex 读不懂这个路径，直连、路由、聚合三种模式都受影响。现在在 Windows 上、Codex 桌面版开启了在 WSL 中运行 Codex 时，改回只写文件名，下次写入时自动改正。
  • Codex 新对话经路由连第三方原生 Responses 上游时报 400（#9328，相关 #7074、#9379）。新版 Codex 桌面版会在新对话里带上没有 call_id 的页面上下文工具结果，自动化和跨任务派发的回执也是这样，校验严格的上游会拒绝整个请求。以前只对 xAI 改写，现在对所有非官方的原生 Responses 上游都改写成一条用户消息，内容保留。官方订阅和带 call_id 的工具结果不受影响。
  • Codex 经路由连 Anthropic 格式上游时，长回答被截断，报「Incomplete response returned, reason: max_output_tokens」，重试也一样。Codex 请求不带输出上限，以前按 8192 发出，思考也算在内，一次写一整个文件的工具调用就会用完。现在默认改为 32000。上游的输出上限更低时会报 400，可以在供应商的「最大输出 tokens」里填它支持的值。
  • Codex 官方卡在路由模式下拿不到账号自己的模型列表：Codex 只能用它自带的列表，缺少账号专属的模型；Codex 桌面版打开 Daybreak 后，官方模型全部变灰。现在路由正在用官方卡、且没有打开「暂停使用官方登录」时，路由会把官方的模型列表原样交给 Codex。第三方供应商不转发。
  • Claude Code 经路由连 Mistral 上的 DeepSeek 模型时，工具调用之后的每一轮都报 422（#9385、#9388）。
  • 只能经路由使用的 Claude Code 卡片，点「打开终端」后 Claude Code 每句话都提示未登录（「Not logged in」），请求根本没发出去。GitHub Copilot、Codex OAuth、xAI OAuth 这类卡片的凭据由路由提供，非 Anthropic 格式的卡片要靠路由转换格式，终端直连卡片地址用不了。现在这类卡片的「打开终端」按钮变灰，并说明要开启路由后在终端里直接运行客户端。Codex 页面上这类卡片也从隐藏按钮改为同样变灰。
  • Claude 官方卡显示的额度可能是另一个账号的：本机默认登录换成别的账号后，正在用的那张卡会读到默认登录那个账号的额度。现在会先确认默认登录属于这个账号。
  • Antigravity 的额度和 agy /usage 对不上；Google AI Ultra 5x 和 20x 都只显示「Google AI Ultra」（#9317、#9319）。
