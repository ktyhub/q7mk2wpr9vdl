Interruptor CC v4.0.39

Esta versión es principalmente para reparaciones. Se agregó un botón de copia al cuadro de entrada de clave API; Copia de seguridad puede establecer el límite superior del tamaño total y, cuando exceda el límite, se eliminará del más antiguo; cuando Claude Code usa GPT-6.2 Sol / Astra a través de Codex OAuth, la tasa de aciertos de caché solicitada por el sistema mejora enormemente. Además, los proveedores nativos de Claude Code y Claude Desktop han sido reparados y tienen que esperar hasta 600 segundos antes de la conmutación por error; una respuesta de transmisión larga hace que la memoria ocupada por el uso y la recopilación de registros siga creciendo; todavía aparece un cuadro de confirmación después de que falla la configuración de combinación de enlaces de importación con un solo clic; cuando solo está instalada la versión de escritorio del Codex, la página del complemento muestra "Codex no está instalado"; la página del complemento crea una carpeta de configuración vacía para las aplicaciones desinstaladas; Falta el Flash DeepSeek V4.1 de OpenCode Go max Pensando en engranajes; Problemas como capas emergentes y menús desplegables que parpadean cuando se hace clic rápidamente. Agregar

API El cuadro de entrada clave se puede copiar con un solo clic

Hay un botón de copia (#9232) al lado del cuadro de entrada Clave API en el formulario del proveedor. Lo que se copia es la clave sin los espacios iniciales y finales. Se le indicará el éxito o el fracaso. No se muestra cuando el cuadro de entrada está vacío o no se puede editar.

Tamaño máximo total de copia de seguridad

Se agregó un nuevo "Tamaño total máximo de copia de seguridad" a la configuración de copia de seguridad (#9011, relacionado con #6706). El valor predeterminado es "Sin límite" y no se eliminará ninguna copia de seguridad después de la actualización.

  • Después de establecer el límite superior, cuando la carpeta de respaldo exceda este tamaño, se eliminará comenzando desde la copia de seguridad más antigua.
  • La copia de seguridad más reciente y la copia de seguridad que se utiliza para la recuperación siempre se conservan, por lo que cuando una sola copia de seguridad supera el límite superior, es posible que la carpeta aún supere el límite superior.
  • El límite superior entra en vigor en la siguiente copia de seguridad o mantenimiento diario. El mantenimiento diario también limpia los archivos temporales que quedan tras fallas en las copias de seguridad que tienen más de 24 horas.

Cambiar

  • Claude Code tiene una mayor tasa de aciertos de caché cuando se usa GPT-6.2 Sol / Astra a través de Codex OAuth (#9848, consulte #9847): el mensaje del sistema se cambia para colocarse en el primer mensaje del desarrollador, y el backend de ChatGPT lo almacenará en caché junto con la conversación. La tasa real de aciertos en la segunda ronda es aproximadamente del 98%. Otros modelos y enrutamiento con llave API permanecen sin cambios.
  • Filtro de privacidad más rápido (#9826): filtrado de resultados sin cambios.

Arreglar

  • Cuando el proveedor nativo de Claude Code y Claude Desktop está bloqueado y no puede imprimir palabras, la conmutación por error tardará hasta 600 segundos (#9754): este tipo de solicitud de transmisión utiliza el tiempo de espera de las solicitudes que no son de transmisión y ahora usa el tiempo de espera de la primera palabra (60 segundos predeterminado) como otras solicitudes de transmisión.
  • Las respuestas de transmisión largas o interminables hacen que el uso y el uso de memoria para la recopilación de registros continúen creciendo (#9846, consulte #9843): el búfer ahora tiene hasta 64 MiB y puede continuar analizando contenido posterior después de encontrar eventos extremadamente grandes.
  • Después de que falla la configuración de combinación del enlace de importación con un solo clic, el cuadro de confirmación aún aparece (#9844, consulte #9841): ahora solo se muestra un error y el cuadro de confirmación ya no aparece.
  • Cuando solo está instalada la versión de escritorio de Codex, la página del complemento muestra "Codex no está instalado" (consulte #9850): Por ejemplo, solo la versión de escritorio de Codex (MSIX) está instalada en Windows. Ahora, cuando no se pueda encontrar el codex instalado por separado, la página del complemento y otros lugares que usan la línea de comando del Codex usarán la que viene con la versión de escritorio. La instalación, actualización y desinstalación de la página "Aplicación" todavía solo se aplica al Codex CLI instalado por separado.
  • La página del complemento crea carpetas de configuración vacías para aplicaciones desinstaladas (consulte #9852): Al abrir la página del complemento, también se crearán carpetas vacías como ~/.codex y ~/.grok para aplicaciones que no están instaladas, como Codex, Grok Build, OpenClaw, Pi o MiniMax Code. Ahora puedes compilarlo después de encontrar la herramienta de línea de comando. Si no está instalado, seguirá mostrando "No instalado".
  • DeepSeek V4.1 Flash de OpenCode Go carece del equipo de pensamiento max (consulte #9853): de forma predeterminada, la lista de modelos de OpenCode Go ahora indica low, high y max. OpenCode ya no vuelve al universal low / medium / high.
  • La capa emergente y el menú desplegable parpadean cuando se hace clic rápidamente (#9176, consulte #9175): Al hacer clic nuevamente durante la animación de apertura o cierre no se cambiará dos veces seguidas.

cc-switch v4.0.39

Highlights

  • Claude Code 流式可靠性 — 原生供应商卡住时的故障转移从最长 600 秒降至默认 60 秒的首字超时；长流式响应的用量/日志缓冲限制为 64 MiB，降低内存持续增长的风险。依赖长请求或故障转移的用户值得升级。
  • Codex OAuth 缓存优化 — 仅针对 Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 的路径，系统提示改放入首条 developer 消息，官方实测第二轮起缓存命中率约 98%；其他模型和 API Key 路由不受影响。使用该组合的用户优先升级。
  • 备份大小上限 — 新增可选的「备份总大小上限」，超限时从最旧备份开始删除，但最新备份和正在用于恢复的备份始终保留。默认「不限制」，升级不会自动删除备份；需要控制磁盘占用的用户可配置此选项，但单份备份超过上限时仍可能超限。
  • 插件与模型预设修复 — 仅安装 Codex 桌面版（MSIX）时会回退使用其内置 CLI，打开插件页也不再为未安装应用创建空配置目录；OpenCode Go 的 DeepSeek V4.1 Flash 补齐 low / high / max 思考档位。相关用户值得升级。
  • 小修复与升级建议 — API Key 复制按钮会去除首尾空格并提示复制结果；导入失败不再误弹确认框，快速点击不再导致弹层和菜单闪烁；隐私过滤器提速但结果不变。未发现破坏性变更或必需迁移步骤；未使用相关功能的用户可跳过本次升级。

CC Switch v4.0.39

本版本以修复为主。API Key 输入框加了复制按钮；备份可以设置总大小上限，超过时从最旧的开始删；Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时，系统提示的缓存命中率大幅提高。

另外修复了 Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，要等最长 600 秒才故障转移；很长的流式响应让用量和日志收集占用的内存一直增长；一键导入链接合并配置失败后仍弹出确认框；只装了 Codex 桌面版时，插件页显示「未安装 Codex」；插件页给没装的应用建了空配置文件夹；OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位；快速点击时弹出层和下拉菜单闪烁等问题。

新增

API Key 输入框可以一键复制

供应商表单的 API Key 输入框旁边多了复制按钮（#9232），复制的是去掉首尾空格后的 Key，成功或失败都会提示。输入框为空或不可编辑时不显示。

备份总大小上限

备份设置里新增「备份总大小上限」（#9011，相关 #6706），默认「不限制」，升级后不会删任何备份。

  • 设置上限后，备份文件夹超过这个大小时，会从最旧的备份开始删除。
  • 最新的一份备份和恢复正在使用的备份始终保留，所以单份备份比上限还大时，文件夹仍可能超过上限。
  • 上限在下次备份或每日维护时生效。每日维护还会清理备份中途崩溃留下、超过 24 小时的临时文件。

变更

  • Claude Code 经 Codex OAuth 使用 GPT-6.2 Sol / Astra 时缓存命中率更高（#9848，见 #9847）：系统提示改放在第一条 developer 消息里，ChatGPT 后端会把它和对话一起缓存。实测从第二轮起命中率约 98%。其他模型和用 API Key 的路由不变。
  • 隐私过滤器更快（#9826）：过滤结果不变。

修复

  • Claude Code 和 Claude Desktop 的原生供应商卡住不出字时，最长要等 600 秒才故障转移（#9754）：这类流式请求用的是非流式请求的超时，现在和其他流式请求一样用首字超时（默认 60 秒）。
  • 很长或一直不结束的流式响应，让用量和日志收集占用的内存一直增长（#9846，见 #9843）：缓冲现在最多 64 MiB，遇到超大的事件后也能继续解析后面的内容。
  • 一键导入链接合并配置失败后，仍弹出确认框（#9844，见 #9841）：现在只提示错误，不再弹确认框。
  • 只装了 Codex 桌面版时，插件页显示「未安装 Codex」（见 #9850）：比如 Windows 上只装了 Codex 桌面版（MSIX）。现在找不到单独安装的 codex 时，插件页等用到 Codex 命令行的地方会改用桌面版自带的那份。「应用」页的安装、升级和卸载仍只管单独安装的 Codex CLI。
  • 插件页给没装的应用建了空配置文件夹（见 #9852）：打开插件页时，没装 Codex、Grok Build、OpenClaw、Pi 或 MiniMax Code 也会建出 ~/.codex、~/.grok 等空文件夹。现在找到命令行工具后才建，没装的照常显示「未安装」。
  • OpenCode Go 的 DeepSeek V4.1 Flash 缺少 max 思考档位（见 #9853）：预设现在按 OpenCode Go 的模型列表写明 low、high、max 三档，OpenCode 不再退回通用的 low / medium / high。
  • 快速点击时，弹出层和下拉菜单闪烁（#9176，见 #9175）：在打开或关闭的动画过程中再点一下，不会再连着切换两次。

致谢

感谢 @H15teve（GPT-6.2 缓存命中）、@minimote（复制 API Key）、@zayokami（备份总大小上限）、@vastStage（流式请求超时）、@HaiYangBG1（流式响应内存、一键导入失败提示、测试隔离）、@YUZHEthefool（隐私过滤器提速）、@Delta1035（弹出层闪烁）、@allenxu09（评审修改）、@SaladDay（代码整理）的贡献。

感谢 @IndexEeve、@Thanatos-Z、@beiqixingnang、@muchenkezhan 报告问题和提供复现信息。

完整的技术细节请见 CHANGELOG。
