Interruptor CC v4.0.38

Esta versión es principalmente para reparaciones. Los enlaces de importación con un solo clic ahora pueden importar proveedores de WorkBuddy; Las cuentas de Antigravity también se pueden cambiar en el Centro de autorización en Linux; La lista de sesiones de Antigravity ya no se mezcla con sesiones vacías y subsesiones internas, y el lector de la sesión puede ver pensamientos, llamadas de herramientas y resultados. Además, se ha solucionado que todos los proveedores externos desaparezcan después de que el archivo de configuración de DeepSeek Harness pase a través de ciertas herramientas YAML; al abrir CC Switch desde Finder, la página "Aplicación" marca la instalación normal de npm como "no se puede ejecutar"; cuando el almacén de habilidades no es GitHub / GitLab / Gitea, solo muestra "0 habilidades" sin informar ningún error; el nivel de pensamiento seleccionado por el Codex para el modelo a veces no surte efecto; Codex Hay varios errores de conversión de formato en el enrutamiento; el uso se contabiliza dos veces; "Ninguna sesión contiene esta palabra" se muestra cuando falla la búsqueda de texto de la sesión; la interfaz principal se convierte en una barra blanca o queda cubierta por la barra de menú de macOS; el enlace en Linux AppImage no responde, etc. Inglés → | Versión japonesa →

Agregar

WorkBuddy admite la importación de enlaces con un solo clic

ccswitch:// Los enlaces de proveedores ahora se pueden importar a los proveedores de WorkBuddy (#9768) y las tarjetas resultantes serán las mismas que las agregadas manualmente en la página de WorkBuddy.

  • El enlace debe tener un modelo; apiFormat sólo es compatible con openai_chat.
  • Cuando el ID del modelo ya esté ocupado por otra tarjeta, se rechazará la importación y no quedará media tarjeta.

Cambiar cuenta de Antigravity en Linux

En Linux, también puede administrar el inicio de sesión y el cambio de cuenta de agy en el centro de autorización. La tarjeta oficial muestra el límite de la cuenta vinculada (#9774, relacionada #9245).

  • Las credenciales de inicio de sesión se almacenan en el llavero del sistema (Servicio Secreto). Cuando el llavero está bloqueado, se omitirán las verificaciones de antecedentes para determinar el estado y el saldo de crédito, y se solicitará el desbloqueo al cambiar activamente de número.
  • Para tarjetas con cuenta vinculada en Linux, el cuadro de diálogo "Abrir terminal" ahora tiene "Usar agy para iniciar sesión esta vez": cuando no hay una cuenta vinculada a la máquina o el llavero no está disponible, primero puede abrir la terminal con el inicio de sesión actual y la vinculación de la tarjeta permanece sin cambios.

Cambiar

  • Lista de sesiones de Antigravity y lector de sesiones (#9266, consulte #9265): simplemente busque /usage en la terminal para salir de las sesiones vacías que quedaron (se muestran como Jan 1), los registros residuales que se han eliminado o sincronizado desde otros dispositivos, los subagentes de /boost y las preguntas de omisión de /btw ya no aparecen en la lista y su uso se cuenta como habitual. Las conversaciones sin título utilizan una vista previa o la primera pregunta como título. El lector de la sesión puede ver pensamientos, texto, llamadas a herramientas (incluido MCP, navegador, etc.) y resultados de herramientas (incluidos códigos de salida de comandos, estado de interrupción), y los cambios de archivos muestran la cantidad de líneas agregadas y eliminadas. Después de la actualización, el índice del cuerpo de la sesión se reconstruirá automáticamente.
  • Las estadísticas de uso y búsqueda de sesiones son más rápidas (#9823, #9825): el índice de búsqueda ya no se reconstruye para cada ID de sesión y ruta al cambiar de aplicación en la página de sesión, y el uso de memoria es mucho menor; la consulta de estadísticas de uso puede utilizar el índice de la base de datos, la primera palabra solo se lee una vez y el precio solo se carga una vez para cada consulta.
  • Elimine el "Google" redundante del nombre del paquete de la cuenta de Google en el Centro de autorización (#9834): "Google AI Pro" para las cuentas Antigravity y Gemini CLI ahora se muestra como "AI Pro".

Arreglar

  • Todos los proveedores externos en DeepSeek Harness desaparecieron repentinamente (consulte #9785): después de que ciertas herramientas YAML guarden cordis.patch.yml, el off en el equipo de pensamiento se convertirá en false. CC Switch solía guardarlo tal como está y volver a escribirlo cada vez que se sincronizaba. DeepSeek Harness invalidó toda la configuración del proveedor debido a esta clave ilegal. Ahora se corregirá al leer y escribir (false se vuelve a cambiar a off y se elimina el engranaje desconocido).
  • Al abrir CC Switch desde Finder, la página "Aplicación" marca la instalación de npm que funciona normalmente como "no se puede ejecutar" (Consulte #9810): No se puede encontrar el nodo en la RUTA utilizada para la instalación. Las herramientas de línea de comando instaladas con npm --prefix, volta, pnpm, bun, etc. se considerarán inoperables y la interfaz también recomendará reinstalarlas o desinstalarlas. La detección ahora incluye la RUTA del shell de inicio de sesión, igual que cuando CC Switch ejecuta otras herramientas de línea de comandos. Windows no se ve afectado.
  • Al agregar un almacén de habilidades en un sitio no compatible (como cnb.cool), solo se mostrará "0 habilidades" sin error (consulte #9812): este tipo de sitio devolverá una página web a cualquier dirección, y la página web descargada previamente se tratará como un paquete comprimido y no habrá ningún mensaje si falla. Ahora aparecerá el mensaje "El paquete descargado no es un paquete comprimido: es posible que este sitio no sea el almacén GitHub / GitLab / Gitea y aún no es compatible".
  • El nivel de pensamiento seleccionado manualmente (como max, ultra) para el modelo en el Codex a veces no tiene efecto (#9017, consulte #8952): cuando el nombre del modelo coincide con el modelo oficial del Codex, el directorio del modelo generado utiliza el nivel de pensamiento oficial. Ahora presione Escribir seleccionado en la tarjeta.
  • Cuando el Codex se convierte al formato Chat mediante enrutamiento, las herramientas con nombres similares colisionarán (#9554, consulte #9551): cuando el nombre de la herramienta o el espacio de nombres contiene __, es posible que la herramienta se haya perdido en el pasado o que la llamada se haya enviado a la herramienta incorrecta. Cada herramienta ahora tiene un nombre único y las llamadas se pueden asignar con precisión.
  • Las conversaciones que utilizan modelos de terceros a través del enrutamiento del Codex no pueden continuar después de cambiar al modelo oficial (#9756, consulte #9054): el ID del mensaje convertido comienza con resp_ y la interfaz oficial requiere que comience con msg_. En modo de conexión directa, se informará invalid_id_prefix. El ID recién generado cambia para comenzar con msg_; las antiguas conversaciones que se han guardado permanecen sin cambios.
  • Cuando Codex está conectado a Claude en AWS Bedrock a través del enrutador, cada solicitud informa 400 (#8659, consulte #6118): la definición de la herramienta contiene un campo strict adicional específico de OpenAI, que Bedrock no acepta. Este campo ya no se reenvía.
  • Doble cálculo de dosis:
    • Cuando el nombre del modelo tiene un prefijo de puerta de enlace (como antigravity/gemini-3.8-flash-high), la misma solicitud se cuenta una vez en el registro de enrutamiento y en el registro de sesión del Codex (#9249). Ahora elimine el prefijo y compare nuevamente.
    • Después de actualizar el antiguo archivo de sesión de Gemini, se importó nuevamente el uso archivado; la cantidad de tokens en la sesión cambió pero no se actualizó (#9527, consulte #9523).
  • Las escrituras de caché para Codex en las estadísticas de uso muestran N/A (#8191): ahora se muestran los valores reales, solo Gemini y Grok Build todavía muestran N/A (no informan escrituras de caché). El registro de solicitudes tampoco cuenta las escrituras en caché del Codex como nuevas entradas.
  • La velocidad de salida de Antigravity se muestra como una estimación, que es baja (#9788, consulte #9787): Antigravity registra el tiempo de la primera palabra y la duración de la salida de transmisión, que no se usaban antes. La velocidad se estima en función del tiempo total invertido (incluida la espera antes de la primera palabra). Ahora cuenta la duración real de la salida en cuanto a las solicitudes enrutadas.
  • Cuando se produce un error en la búsqueda de texto de la conversación, se muestra "Ninguna conversación contiene esta palabra" (#9512, consulte #9511): Ahora aparecerá el mensaje "Error en la búsqueda de texto y solo se puede buscar por título, directorio y primer y último mensaje". Puede hacer clic en "Reintentar" y la conversación se volverá a incluir en el índice cuando vuelva a intentarlo.
  • Dos problemas de límites con las sesiones de OpenCode (#7982): Las sesiones que se migraron al nuevo formato y luego continuaron en OpenCode 1.x solían mostrar el contenido antiguo; cuando la migración al nuevo formato se interrumpió a mitad de camino, las sesiones inacabadas ya no estaban ocultas.
  • El comando de restauración de sesión de Oh My Pi informará un error cuando se pegue en PowerShell en Windows (#9153, consulte #9152): el método de escritura de PowerShell ahora se genera en Windows, y macOS y Linux permanecen sin cambios.
  • No sucede nada al hacer clic en un enlace o abrir una carpeta en una AppImage de Linux (#9113, consulte #9112): La versión anterior de xdg-open que viene con AppImage no hace nada en KDE Plasma 6. Ahora use el xdg-open del sistema en su lugar. deb/rpm, macOS y Windows no se ven afectados.
  • En macOS, cierre la interfaz principal de pantalla completa en la bandeja y luego quedará cubierta por la barra de menú y el Dock cuando la abra nuevamente (#9770, consulte #9769): ahora saldrá de la pantalla completa antes de cerrar la bandeja y restaurará la pantalla completa cuando la abra nuevamente desde la bandeja, el Dock, etc.
  • La interfaz principal es solo una barra blanca después de abrirla (#9504, ver #9496): El tamaño de la ventana recordada es anormalmente pequeño y se restaura al tamaño predeterminado cuando se abre.
  • Al editar un proveedor, cierre el editor que aún se está guardando y vuelva a abrirlo, y el botón "Guardar" seguirá girando (#9593, consulte #9592).
  • La migración de inicio de sesión de la versión anterior de Copilot se cancelará cuando se agote el tiempo de espera de la red y se intentará nuevamente después de reiniciar (#9549, consulte #9544): ahora, después de restaurar la red, la migración continuará la próxima vez que se use Copilot sin reiniciar; solo se dará por vencido si el token caduca (401/403) o cierra la sesión.
  • La dirección de la estación de transferencia se confundió con la del fabricante oficial (#9648): cuando aparece un nombre de dominio oficial en la ruta o los parámetros de la dirección, o el nombre de dominio parece similar (como api.x.ai.example.com), anteriormente se consideraba como ese fabricante: xAI lo manejará específicamente, y el saldo y el límite del paquete también se verificarán de acuerdo con la plantilla oficial de esa compañía. Ahora sólo mire los nombres de dominio reales.
  • Durante operaciones como la importación de configuración y la descarga de sincronización en la nube, algunos proveedores en la aplicación acumulativa no se han escrito en el archivo de configuración, pero el mensaje es exitoso (#9747): ahora se enumerarán los proveedores que no se pudieron escribir.
  • Después de mover la ubicación de almacenamiento de habilidades, algunas aplicaciones no pudieron volver a vincularse, pero informaron que tuvieron éxito (#9748): ahora aparecerá en la lista del mensaje.

cc-switch v4.0.38

Highlights

  • WorkBuddy providers via shareable links — ccswitch:// links can now create WorkBuddy provider cards (#9768), extending the one-click import flow that previously excluded this provider. The constraints matter when distributing configs to a team: the link must include a model, apiFormat is limited to openai_chat, and a model ID already claimed by another card causes the whole import to be rejected rather than leaving a half-created card. Plan model IDs ahead of time if you're generating links programmatically.

  • Linux Antigravity account management — Authorization Center now handles agy login/account switching on Linux, with quota shown on the official card (#9774, #9245). Credentials live in the system Secret Service keyring, so headless or locked-keyring environments will silently skip background status/quota refresh and only prompt for unlock on an explicit switch — worth knowing before scripting this on CI boxes. The new "use current agy login for this session" option in the terminal dialog is a useful escape hatch that keeps the card's binding untouched.

  • Antigravity session cleanup and a one-time index rebuild — The session list now filters out empty /usage exits (Jan 1 entries), deleted or cross-device leftovers, /boost subagents, and /btw side questions, while their usage still counts; untitled sessions fall back to preview text or the first prompt (#9266). The reader surfaces thinking blocks, tool calls (including MCP/browser), tool results with exit codes and interruption state, and file diffs with add/delete line counts. Expect a one-time body-index rebuild after upgrading — searches may be incomplete until it finishes, and long-lived sessions will look noticeably different in the list.

  • Codex routing correctness — Four format fixes unblock previously broken routed workflows: manually selected thinking levels like max/ultra are no longer overwritten by official-model defaults (#9017); uniquely generated tool names prevent __-containing names from colliding or misrouting calls (#9554); converted message IDs now use the required msg_ prefix instead of resp_, fixing invalid_id_prefix when switching a routed conversation to an official model (#9756); and the OpenAI-only strict field is stripped from tool definitions for AWS Bedrock Claude, eliminating per-request 400s (#8659). Note that the ID fix is forward-only — already-stored conversations keep their old IDs.

  • Usage numbers you can trust — Gateway prefixes such as antigravity/ are stripped before deduplication so a single request isn't counted in both the route log and Codex session log (#9249); updated legacy Gemini session files no longer re-import archived usage and now refresh changed token counts (#9527); Codex cache-write reports real values instead of N/A and is no longer double-counted as new input (#8191). Session search and usage queries also got faster and lighter — no per-session index rebuild when switching apps, indexed queries, single-pass first-token reads, and pricing loaded once per query (#9823, #9825). Recomputed historical figures may shift once these fixes are applied.

  • Self-healing config and honest failure reporting — The DeepSeek Harness .yml fix is the subtle one: after certain YAML editors turn off into false, CC Switch used to write the invalid key back on every sync until Harness rejected the entire vendor block; it now normalizes false→off and drops unknown tiers on both read and write (#9785). npm/volta/pnpm/bun installs are no longer falsely flagged as "cannot run" when CC Switch is launched from Finder, because detection now uses the login-shell PATH (#9810); proxy URLs are matched by real hostname instead of substrings like api.x.ai.example.com (#9648); and partial failures during config import/cloud sync or skill relocation are now listed instead of reporting success (#9747, #9748). Search errors are surfaced as failures with a retry action rather than a misleading "no sessions contain this term" (#9512).

No breaking changes in this release.

新增

WorkBuddy 支持一键导入链接

ccswitch:// 供应商链接现在可以导入 WorkBuddy 供应商（#9768），生成的卡片和在 WorkBuddy 页手动添加的一样。

  • 链接必须带模型；apiFormat 只支持 openai_chat。
  • 模型 ID 已被别的卡片占用时，导入会被拒绝，不会留下半截卡片。

Linux 上切换 Antigravity 账号

Linux 上也能在授权中心管理 agy 的登录、切换账号，官方卡片上显示所绑定账号的额度（#9774，相关 #9245）。

  • 登录凭据存在系统的钥匙串（Secret Service）里。钥匙串锁着时，后台查状态和额度会跳过，主动切号时会请求解锁。
  • Linux 上绑了账号的卡片，「打开终端」对话框里多了「本次使用 agy 当前登录」：本机没有绑定的账号或钥匙串不可用时，可以先用当前登录打开终端，卡片的绑定保留不变。

变更

  • Antigravity 会话列表和会话阅读器（#9266，见 #9265）：在终端里只查一下 /usage 就退出留下的空会话（显示为 Jan 1）、已删除或从别的设备同步来的残留记录、/boost 子代理和 /btw 旁路提问不再出现在列表里，它们的用量照常统计。没有标题的会话用预览或第一句提问当标题。会话阅读器能看到思考、正文、工具调用（含 MCP、浏览器等）和工具结果（含命令退出码、中断状态），文件改动显示增删行数。升级后会话正文索引会自动重建一次。
  • 会话搜索和用量统计更快（#9823、#9825）：会话页切换应用时不再为每个会话 ID 和路径重建搜索索引，内存占用也小得多；用量统计的查询能用上数据库索引，首字时间只读一遍，价格每次查询只加载一次。
  • 授权中心里 Google 账号的套餐名去掉多余的「Google」（#9834）：Antigravity 和 Gemini CLI 账号的「Google AI Pro」现在显示为「AI Pro」。

修复

  • DeepSeek Harness 里所有第三方供应商突然消失（见 #9785）：cordis.patch.yml 经过某些 YAML 工具保存后，思考档位里的 off 会变成 false。CC Switch 以前会原样存下来、每次同步都写回去，DeepSeek Harness 因为这一个非法键把整段供应商配置都判为无效。现在读写时都会改正（false 改回 off，不认识的档位去掉）。
  • 从访达打开 CC Switch 时，「应用」页把能正常用的 npm 安装标成「无法运行」（见 #9810）：检测安装时用的 PATH 里找不到 node，用 npm --prefix、volta、pnpm、bun 等方式装的命令行工具就会被判成无法运行，界面还会建议重装或卸载。现在检测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。Windows 不受影响。
  • 添加不支持的站点（如 cnb.cool）上的技能仓库时，只提示「0 个技能」而不报错（见 #9812）：这类站点对任何地址都返回一个网页，以前下载到的网页被当成压缩包，失败了也没有提示。现在会提示「下载到的不是压缩包：这个站点可能不是 GitHub / GitLab / Gitea 仓库，暂不支持」。
  • Codex 给模型手动选的思考等级（如 max、ultra）有时没生效（#9017，见 #8952）：模型名和 Codex 官方模型对得上时，生成的模型目录用的是官方的思考等级。现在按卡片里选的写入。
  • Codex 经路由转成 Chat 格式时，名字相近的工具会撞名（#9554，见 #9551）：工具名或命名空间里自带 __ 时，以前可能丢掉工具，或者把调用发给错的工具。现在每个工具都有唯一的名字，调用能准确对回去。
  • Codex 经路由用过第三方模型的对话，切到官方模型后无法继续（#9756，见 #9054）：转换出来的消息 ID 以 resp_ 开头，官方接口要求以 msg_ 开头，直连模式下会报 invalid_id_prefix。新生成的 ID 改为 msg_ 开头；已经存下的旧对话不变。
  • Codex 经路由连 AWS Bedrock 上的 Claude 时，每个请求都报 400（#8659，见 #6118）：工具定义里多带了 OpenAI 专用的 strict 字段，Bedrock 不接受。现在不再转发这个字段。
  • 用量重复计算：
    • 模型名带网关前缀（如 antigravity/gemini-3.8-flash-high）时，同一个请求在路由记录和 Codex 会话日志里各算一次（#9249）。现在去掉前缀再比对。
    • Gemini 旧会话文件更新后，已经归档的用量又被导入一次；会话里的 token 数变了却没有更新（#9527，见 #9523）。
  • 用量统计里 Codex 的缓存写入显示 N/A（#8191）：现在显示实际数值，只有 Gemini 和 Grok Build 仍显示 N/A（它们不上报缓存写入）。请求日志也不再把 Codex 的缓存写入算进新输入。
  • Antigravity 的输出速度显示为估算值，偏低（#9788，见 #9787）：Antigravity 自己记录了首字时间和流式输出时长，以前没用上，速度按总耗时（含首字前的等待）估算。现在和经路由的请求一样按实际输出时长计算。
  • 会话正文搜索出错时，显示「没有会话包含这个词」（#9512，见 #9511）：现在会提示「正文搜索失败，暂时只能按标题、目录和首末消息查找」，可以点「重试」，重试时会把会话重新收录进索引。
  • OpenCode 会话的两个边界问题（#7982）：迁移到新格式后又在 OpenCode 1.x 里继续的会话，以前显示的是旧内容；新格式迁移中途中断时，没迁完的会话不再被隐藏。
  • Oh My Pi 的恢复会话命令在 Windows 上粘贴到 PowerShell 会报错（#9153，见 #9152）：Windows 上现在生成 PowerShell 写法，macOS 和 Linux 不变。
  • Linux AppImage 里点链接在浏览器中打开、或打开文件夹，没有任何反应（#9113，见 #9112）：AppImage 自带的旧版 xdg-open 在 KDE Plasma 6 下什么都不做。现在改用系统自己的 xdg-open。deb / rpm、macOS 和 Windows 不受影响。
  • macOS 上把全屏的主界面关到托盘，再打开时被菜单栏和 Dock 遮住（#9770，见 #9769）：现在关到托盘前先退出全屏，从托盘、Dock 等再打开时恢复全屏。
  • 主界面打开后只是一条白条（#9504，见 #9496）：记住的窗口尺寸异常小时，打开时恢复成默认大小。
  • 编辑供应商时，关掉还在保存的编辑器再打开，「保存」按钮一直转圈（#9593，见 #9592）。
  • Copilot 旧版登录迁移遇到网络超时就放弃，要重启才会再试（#9549，见 #9544）：现在网络恢复后，下次用到 Copilot 时会继续迁移，不用重启；只有令牌失效（401 / 403）或退出登录才放弃。
  • 中转站地址被误认成官方厂商（#9648）：地址的路径或参数里出现官方域名，或者域名长得像（如 api.x.ai.example.com）时，以前会被当成那家厂商：xAI 走专门的处理，余额和套餐额度也按那家的官方模板查。现在只看真正的域名。
  • 导入配置、云同步下载等操作中，累加式应用有供应商没写进配置文件，却提示成功（#9747）：现在会列出写入失败的供应商。
  • 移动技能存储位置后，有应用没能重新链接，却提示成功（#9748）：现在会在提示里列出来。
