Interruptor CC v4.0.25

Esta versión agrega una verificación de conectividad a la página MCP, que puede verificar con un clic si todos los servidores MCP habilitados se pueden conectar; cuando Codex utiliza la cuenta oficial a través del enrutamiento local, la solicitud oficial puede suspenderse automáticamente antes de que la cuota esté casi agotada y los modelos de terceros todavía estén disponibles. Además, el tipo de cambio en la página de uso se puede obtener automáticamente y el formulario de proveedor del Codex puede establecer el límite de concurrencia del subagente. Cuando Claude Code y Claude Desktop se enrutan o agregan, el menú del modelo indicará de qué proveedor proviene cada modelo y qué modelo es realmente. Las sesiones de Kimi Code también se pueden eliminar en la gestión de sesiones. También ha solucionado problemas como "terminal abierto" que mezcla configuraciones de enrutamiento y agregación, proveedores como OpenCode Go en modo de enrutamiento pidiendo a Claude Code que inicie sesión nuevamente, errores que se informan cada vez que se envía un archivo a un modelo de texto sin formato, contenido del formulario del proveedor en Windows parpadeando hacia adelante y hacia atrás, el panel de la bandeja no se abre al inicio y el uso se cuenta dos veces cuando Codex usa el mapeo de modelos. Para obtener el contenido completo de la actualización de 4.0, consulte las Notas de la versión de v4.0. Inglés → | Versión japonesa →

Agregar

Comprobación de conectividad MCP

En el pasado, después de configurar el servidor MCP, solo se sabía si se podía conectar cuando se usaba en la herramienta de programación (#4498). Ahora hay un botón "Verificar conectividad" en la parte superior de la página MCP, que verificará todos los servidores habilitados; También hay una "Probar conexión" en el menú de cada fila, y sólo se comprobará esta.

  • No se marcará automáticamente al abrir la página y se mostrará "desmarcado" si no se ha marcado; después de cambiar la configuración de conexión de un determinado servidor, sus resultados se restablecerán.
  • El método de verificación consiste en completar un protocolo de enlace MCP con el servidor, y se admiten los tres métodos de conexión, comando local (stdio), HTTP y versión anterior SSE. Espere hasta 30 segundos por servidor y toda la aplicación puede verificar hasta 3 segundos simultáneamente.
  • Después de verificar el servidor iniciado por el comando local, finalizará junto con el proceso hijo que inició y no quedará ningún proceso en segundo plano. Comandos como npx y uvx también se pueden encontrar en macOS y Linux cuando CC Switch no se inicia desde la terminal.

Protección de cuotas oficiales del Codex

Cuando Codex usa la cuenta oficial de ChatGPT, ingresará al modo Reserva cuando se agote la cuota semanal o de cinco horas. Ahora puede suspender las solicitudes oficiales cuando la cuota esté casi agotada, dejando la cuota y los modelos de terceros aún se pueden utilizar como de costumbre. Active la "Protección de cuota oficial" en "Configuración → Configuración de la aplicación → Mejora de la aplicación Codex", puede establecer umbrales de uso semanales y de cinco horas (95 % y 98 % predeterminados) y suspender nuevas solicitudes oficiales cuando se alcance cualquiera de ellos.

  • Solo tiene efecto para las solicitudes oficiales del Codex enviadas localmente a través de CC Switch y está desactivado de forma predeterminada.
  • La tasa de uso lee directamente la información de cuota incluida en la respuesta oficial. No se enviarán múltiples solicitudes durante el uso normal; se consultará por separado solo después de que recién haya comenzado a usarse o haya estado inactivo durante aproximadamente 5 minutos.
  • Si no se puede encontrar la cuota (problemas de red, vencimiento del inicio de sesión, etc.), el sistema se liberará como de costumbre y no habrá ningún error de bloqueo. Las solicitudes suspendidas devolverán errores directamente y no se transferirán a otros proveedores en la cola de conmutación por error.

Obtener automáticamente el tipo de cambio en la página de uso

El área "Pantalla" en "Configuración de uso" en la página de uso tiene una "Fuente de tipo de cambio". Puede elegir "Relleno manual" (predeterminado) u "Obtención automática". Sólo cuando se seleccione la recuperación automática se conectará la red. El tipo de cambio se actualizará automáticamente si supera las 12 horas. Si la recuperación falla, se seguirá utilizando el último tipo de cambio. El tipo de cambio obtenido automáticamente y el completado manualmente se guardan por separado. Cuando vuelva al llenado manual, el valor que ingresó seguirá ahí. Las tarifas aún se registran en dólares estadounidenses y solo se convierten cuando se muestran.

Límite de simultaneidad de subagente del Codex

Existe un "Límite de simultaneidad de subagentes" en el "Modelo de subagentes" en el formulario de proveedor del Codex, que establece el número máximo de subagentes que se pueden abrir simultáneamente en una sesión del Codex (#9055). Este es el escenario global del Codex. [agents] max_threads escrito en config.toml permanecerá sin cambios al cambiar de proveedor y también se puede cambiar en la tarjeta oficial; si se deja en blanco, se utilizará el valor predeterminado del Codex.

El menú de modelo indica el proveedor y el modelo real.

Claude Code En el modo de enrutamiento, cada archivo en el menú /model solía leer solo "modelo de Sonnet personalizado", y era imposible saber qué modelo correspondía a qué proveedor. Ahora se escribirá como "Proveedor · Modelo real · Ventana" (la ventana solo se muestra cuando el cursor está 1 M hacia arriba), y lo mismo ocurre con los modelos en modo de agregación. Si el proveedor ha escrito él mismo la descripción del modelo, prevalecerá la escrita por usted. Claude Desktop En los modos de enrutamiento y agregación, la descripción debajo del modelo solía aplicar la copia oficial según Opus y Sonnet en el nombre, y el modelo de agregación siempre mostraba la misma oración. Ahora cámbielo también a "Proveedor·Modelo actual·Ventana".

Eliminar sesión del Código Kimi

Las sesiones de Kimi Code se pueden eliminar directamente en la gestión de sesiones. En el pasado, solo se podían eliminar en Kimi Code. El método de eliminación es el mismo que el de Kimi Code y el historial del subagente se eliminará en conjunto. Precios: Se agregó GPT-6.1 Terra a la lista de precios integrada.

Cambiar

  • El enrutamiento local ya no acepta solicitudes de páginas web. La ruta local reemplazará la solicitud con sus credenciales de proveedor guardadas y luego la reenviará, por lo que si la página web puede enviar la solicitud a la ruta local, puede agotar su cuota. Las solicitudes con una etiqueta de origen del navegador ahora serán rechazadas y ya no se aceptará el acceso a esta máquina a través de un nombre de dominio común. Las solicitudes enviadas por herramientas de programación no se ven afectadas.
  • La barra de herramientas de la página "Descubrir" de Habilidades está alineada con la página "Instalado" (#9125): la posición y el ancho del cuadro de búsqueda son consistentes, el botón de actualización se cambia al botón de texto "Actualizar almacén", la fuente, el filtro de almacén y "Ver solo los desinstalados" se mueven al encabezado y "Instalar en" se coloca en el lado derecho del encabezado. Falta una línea, pero la funcionalidad sigue siendo la misma.
  • Cuando el terminal preferido en Windows es PowerShell, si PowerShell 7 está instalado, úselo para abrir (#8992, #3271). De lo contrario, utilice Windows PowerShell que viene con el sistema. Esto es válido para "abrir el terminal" de la tarjeta de proveedor e instalar y actualizar aplicaciones.
  • Predeterminado: El plan de pago por uso y el plan Token de Qianwen AI Platform y QwenCloud se cambian al nuevo nombre de dominio MaaS, y el plan de codificación permanece sin cambios.

Arreglar

  • En el modo de enrutamiento o agregación, el "Terminal Abierto" de la tarjeta Claude Code combina configuraciones de enrutamiento y agregación. El Claude Code en el terminal traerá las credenciales del marcador de posición de la ruta y la Clave de esta tarjeta al mismo tiempo. El archivo de modelo que no coincida con esta tarjeta utilizará el nombre del modelo en la agregación y no se utilizará la dirección enviada a esta tarjeta; Los modelos de otros proveedores también aparecerán en el menú /model. Ahora sólo se utilizan los ajustes propios de esta tarjeta en el terminal y el resto de ajustes globales se conservan como de costumbre.
  • En el modo de enrutamiento, los proveedores como OpenCode Go que usan ANTHROPIC_API_KEY para almacenar claves le pedirán a Claude Code que confirme la clave personalizada. Si selecciona "No" de forma predeterminada, no habrá iniciado sesión (#8111, #8104). Ahora, en el modo de enrutamiento, las credenciales del marcador de posición siempre se escriben en ANTHROPIC_AUTH_TOKEN y las solicitudes enviadas al canal ascendente permanecen sin cambios.
  • Después de enviar un archivo o audio al modelo de texto plano, se informarán 400 en cada ronda posterior (#6274, #6151). Ahora, al enviar a un modelo de texto sin formato mediante enrutamiento, los archivos y el audio de la conversación serán reemplazados por una descripción de texto; También se puede reconocer el informe de error chino de GLM. El procesamiento de imágenes permanece sin cambios.
  • Los nombres y otros contenidos en el formulario de proveedor en Windows parpadean de un lado a otro (#6420, #6349). Este es el autocompletar de WebView2 que superpone el contenido del formulario, ahora desactivado para la ventana principal.
  • El panel de la bandeja no se puede abrir ni salir de la bandeja durante un período de tiempo después del inicio (#9154). El uso de la sesión importada ocupará la base de datos al inicio y el panel de la bandeja tendrá que esperar a recibir datos. Ahora el panel aparecerá primero, "Abrir ventana principal" y "Salir" estarán disponibles inmediatamente, y luego se cargará la lista.
  • Cuando Codex utiliza el mapeo de modelos mediante enrutamiento, el uso de la misma solicitud se cuenta dos veces (#7643, #5526). Lo que se registra en el registro de sesión es el nombre del modelo utilizado por Codex y lo que se registra en la ruta es el nombre del modelo asignado, que no puede coincidir durante la deduplicación. Ahora las dos partes pueden enfrentarse.
  • La cuota utilizada por el subagente en el ejemplo oficial de Pi no está incluida en las estadísticas (#8386, #8340). Ahora se registrará por separado según el proveedor y modelo de cada subagente. Después de la actualización, la sesión Pi anterior se volverá a leer y se recuperará.
  • Al importar MCP desde Pi, los servidores no compatibles con Pi también se importaron y habilitaron, y todas las sincronizaciones posteriores fallaron (#7888). Los servidores con métodos de conexión SSE, nombres no compatibles y servidores cuyos nombres solo sean diferentes de - y _ ahora se omitirán y se les solicitará; El archivo de configuración MCP de Pi ya no se creará cuando Pi no esté instalado.
  • Cuando solo se configura el agente en la terminal o CC Switch y no se configura ningún agente del sistema, la sincronización de precios de models.dev sigue fallando (#8739, #6696). Ahora CC Switch lo descarga en segundo plano y se utilizará el agente que configuró; lo mismo ocurre con la importación de precios de modelos y el llenado automático de los parámetros del modelo en el formulario.
  • Cuando Claude Code se conecta a xAI a través de un enrutador, xAI rechaza la solicitud de búsqueda de red forzada e informa 422 (#8664).
  • MiniMax M3.1 Flash Thinking Gears en Pi (#8540): Los dos ajustes preestablecidos oficiales de MiniMax eliminan "Apagado" y "Mínimo" que no son aceptados por este modelo, y los engranajes restantes se envían como de costumbre.

cc-switch v4.0.25

Highlights

  • MCP connectivity checks — The MCP page gains a "check connectivity" button that handshakes every enabled server (stdio, HTTP, and legacy SSE), with a 30s per-server timeout and a cap of three concurrent checks; each row also gets a "test connection" for a single server. This matters because previously you only found out a server was dead when a coding tool actually tried to use it (#4498). Watch out: results are lazy, not live — nothing is checked on page open, and editing a server's connection config resets its status, so a green result is a point-in-time signal.

  • Codex official quota protection — Opt-in under Settings → App Config → Codex App Enhancements: once 5-hour or weekly usage on an official ChatGPT account crosses a threshold (95%/98% by default), new official requests are paused while third-party models keep working. It applies only to official requests through CC Switch's local router, reads quota data already in responses (no extra calls in steady state), and fails open if quota can't be read. Important behavioral caveat: paused requests return an error outright rather than falling through to your failover queue — plan for a hard stop, not a graceful handoff.

  • Breaking: local router rejects web-origin requests — Requests carrying a browser origin marker, and access to the local router via a normal domain pointing at localhost, are now refused; coding-tool traffic is unaffected. This closes a hole where any web page could spend your stored provider credentials (reported responsibly by @yukitakasama). If you had a custom web UI or dashboard calling the local router, that integration will break and needs to move to a non-browser client.

  • Model menus show provider and actual model — Claude Code's /model menu in route mode, and Claude Desktop in route/aggregate mode, now label entries as "provider · actual model · window" (window only when 1M is in play), replacing the generic "Custom Sonnet model" and name-based Opus/Sonnet guesses. Custom descriptions you set on a provider take precedence. This is a genuine debugging win for tracing which upstream a request hit — especially paired with the auth fix below.

  • Usage accounting fixes — Two long-standing billing bugs are resolved: Codex requests using model mapping were double-counted because session logs and router logs disagreed on the model name (#7643, #5526), and Pi official-example subagent usage was omitted entirely (#8386, #8340). On upgrade, past Pi sessions are re-read to backfill missing usage. Also in route mode, placeholder credentials now go into ANTHROPIC_AUTH_TOKEN instead of ANTHROPIC_API_KEY, fixing Claude Code prompting for a custom key and ending up logged out after choosing "no" (#8111, #8104) — upstream requests are unchanged.

  • Subagent concurrency and exchange rates — Codex provider forms gain a "subagent concurrency limit" that writes [agents] max_threads into config.toml; it's a global setting that survives provider switches (also editable on the official card), and blank means the Codex default (#9055). The usage page can now auto-fetch exchange rates (12h refresh, falls back to the last known rate, stored separately from manual entries), and Kimi Code sessions can finally be deleted from session management, including subagent history.

新增

MCP 连通性检查

以前 MCP 服务器配好以后，只有在编程工具里用到时才知道能不能连上（#4498）。

现在 MCP 页面顶部多了「检查连通性」按钮，会检查所有已启用的服务器；每一行的菜单里也有「测试连接」，只检查这一个。

  • 打开页面时不会自动检查，没检查过的显示「未检查」；改了某个服务器的连接配置后，它的结果会重置。
  • 检查方式是和服务器完成一次 MCP 握手，本地命令（stdio）、HTTP 和旧版 SSE 三种连接方式都支持。每个服务器最多等 30 秒，整个应用同时最多检查 3 个。
  • 本地命令启动的服务器检查完会连同它启动的子进程一起结束，不会留下后台进程。macOS 和 Linux 上不从终端启动 CC Switch 时，也能找到 npx、uvx 这类命令。

Codex 官方额度保护

Codex 用官方 ChatGPT 账号时，五小时或每周额度用完会进入 Reserve 模式。现在可以在额度快用完时先暂停官方请求，留着额度，第三方模型照常可用。

在「设置 → 应用配置 → Codex 应用增强」里打开「官方额度保护」，可以设置五小时和每周使用率的阈值（默认 95% 和 98%），任一达到就暂停新的官方请求。

  • 只对经过 CC Switch 本地路由的 Codex 官方请求生效，默认关闭。
  • 使用率直接读官方响应里自带的额度信息，正常使用时不会多发请求；刚开始用或空闲约 5 分钟后，才会先单独查询一次。
  • 查不到额度（网络问题、登录过期等）时照常放行，不会误挡。被暂停的请求会直接返回错误，不会转到故障转移队列里的其他供应商。

用量页汇率自动获取

用量页「用量设置」里的「显示」区多了「汇率来源」，可以选「手动填写」（默认）或「自动获取」。选了自动获取才会联网，汇率超过 12 小时会自动更新，获取失败时继续用上次的汇率。自动获取的汇率和手动填的分开保存，切回手动填写时你自己填的值还在。费用仍按美元记录，只在显示时换算。

Codex 子代理并发上限

Codex 供应商表单的「子代理模型」下面多了「子代理并发上限」，设置一个 Codex 会话里最多同时开多少个子代理（#9055）。这是 Codex 的全局设置，写进 config.toml 的 [agents] max_threads，切换供应商时保持不变，官方卡片上也能改；留空就用 Codex 的默认值。

模型菜单写明供应商和实际模型

Claude Code 在路由模式下，/model 菜单里每一档以前只写「Custom Sonnet model」，看不出对应哪家供应商的哪个模型。现在会写成「供应商 · 实际模型 · 窗口」（窗口只在上游标了 1M 时显示），聚合模式下的模型也一样。供应商里自己写过模型说明的，以你写的为准。

Claude Desktop 在路由和聚合模式下，模型下面的说明以前按名字里的 Opus、Sonnet 套用官方文案，聚合模型一律显示同一句。现在也改成「供应商 · 实际模型 · 窗口」。

删除 Kimi Code 会话

会话管理里可以直接删除 Kimi Code 会话了，以前只能去 Kimi Code 里删。删除方式和 Kimi Code 自己的一样，子代理的历史会一起删掉。

定价： 内置价格表新增 GPT-6.1 Terra。

变更

  • 本地路由不再接受网页发来的请求。本地路由会把请求换成你保存的供应商凭据再转发，所以网页如果能把请求发到本地路由，就能用掉你的额度。现在带浏览器来源标记的请求会被拒绝，通过普通域名指向本机的访问也不再接受。编程工具发的请求不受影响。
  • Skills「发现」页的工具栏和「已安装」页对齐（#9125）：搜索框位置和宽度一致，刷新按钮改为「刷新仓库」文字按钮，来源、仓库筛选和「只看未安装」挪进表头，「安装到」放在表头右侧。少了一行，功能不变。
  • Windows 上首选终端是 PowerShell 时，装了 PowerShell 7 就用它打开（#8992、#3271），没装才用系统自带的 Windows PowerShell。供应商卡片的「打开终端」和应用的安装、升级都是这样。
  • 预设： 千问 AI 平台和 QwenCloud 的按量付费、Token Plan 改用新的 MaaS 域名，Coding Plan 不变。

修复

  • 在路由或聚合模式下，Claude Code 卡片的「打开终端」混入了路由和聚合的设置。终端里的 Claude Code 会同时带上路由的占位凭据和这张卡片的 Key，这张卡片没配的模型档位会用上聚合里的模型名，发到这张卡片的地址上用不了；/model 菜单里也会出现其他供应商的模型。现在终端里只用这张卡片自己的设置，你的其他全局设置照常保留。
  • 路由模式下，OpenCode Go 等用 ANTHROPIC_API_KEY 存 Key 的供应商会让 Claude Code 要求确认自定义 Key，默认选「否」后就是未登录（#8111、#8104）。现在路由模式下占位凭据一律写进 ANTHROPIC_AUTH_TOKEN，发给上游的请求不变。
  • 给纯文本模型发过一个文件或音频后，之后每一轮都报 400（#6274、#6151）。现在经路由发给纯文本模型时，对话里的文件和音频会换成一段文字说明；智谱 GLM 的中文报错也能认出来。图片的处理不变。
  • Windows 上供应商表单里的名称等内容来回闪（#6420、#6349）。这是 WebView2 的自动填充在覆盖表单内容，现在已对主窗口关掉。
  • 启动后的一段时间里托盘面板打不开，也没法从托盘退出（#9154）。启动时导入会话用量会占着数据库，托盘面板要等数据。现在面板会先弹出，「打开主窗口」和「退出」马上能用，列表随后加载。
  • Codex 经路由用了模型映射时，同一个请求的用量被算两遍（#7643、#5526）。会话日志里记的是 Codex 用的模型名，路由记的是映射后的模型名，去重时对不上。现在两边能对上了。
  • Pi 官方示例的子代理用的额度没有统计进来（#8386、#8340）。现在会按每个子代理的供应商和模型分别记录，升级后会把以前的 Pi 会话重新读一遍补上。
  • 从 Pi 导入 MCP 时，Pi 不支持的服务器也被导入并启用，之后每次同步都失败（#7888）。SSE 连接方式、名字不合规、名字只差 - 和 _ 的服务器现在会跳过并提示；没装 Pi 时也不会再创建 Pi 的 MCP 配置文件。
  • 只在终端或 CC Switch 里设了代理、没设系统代理时，models.dev 价格同步一直失败（#8739、#6696）。现在改由 CC Switch 后台下载，会走你设的代理；导入模型价格和表单自动填模型参数也一样。
  • Claude Code 经路由连 xAI 时，强制联网搜索的请求被 xAI 拒绝，报 422（#8664）。
  • Pi 里的 MiniMax M3.1 Flash 思考档位（#8540）：两个 MiniMax 官方预设去掉了这个模型不接受的「关闭」和「最小」，其余档位照常发送。
