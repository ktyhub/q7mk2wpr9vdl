Interruptor CC v4.0.40

Esta versión permite que la tarjeta oficial de Grok Build esté vinculada a la cuenta xAI en el centro de autorización y se puede cambiar entre varias cuentas de Grok, como las tarjetas oficiales de Claude y Codex. Página de complemento compatible con Antigravity CLI; Estadísticas de uso ha agregado la tasa de aciertos de caché a la lista de proveedores y modelos; Xiaomi MiMo tiene consulta de límite de saldo y plan de tokens integrada; la tarjeta de cuenta en el centro de autorización sigue el orden y la configuración oculta de la aplicación de la barra lateral. Esta versión también fortalece los controles de seguridad de MCP de importación de enlaces profundos, scripts de uso, importación de SQL y direcciones de escucha no nativas, y mejora la velocidad de la base de datos, el enrutamiento local, la sincronización de uso, la búsqueda de sesiones y la página de la aplicación. Además, no se cuenta el uso del agente principal de Kimi Code Desktop; la velocidad de salida de Antigravity es falsamente alta a partir de 4.0.38; no se puede ver la sesión de Antigravity en Código T3 y el ACP ejecutándose solo; la respuesta oficial del Mistral API está vacía después de empezar a pensar; Las respuestas nativas de Kimi siempre informan 400 después de llamar a la herramienta de vista paralela; Los puntos de la cuenta empresarial WorkBuddy se muestran como agotados; no se puede ver en la bandeja. La cuota xAI y la cuenta oficial se muestran como nombres de dominio del sitio web; las habilidades duplicadas aparecen en el "Descubrimiento" de la página de Habilidades; la página "Aplicación" no muestra el estado de la instalación hasta que se verifica la versión. Agregar

La tarjeta oficial de Grok está vinculada a la cuenta xAI

La forma oficial de Grok de Grok Build ha agregado un "método de inicio de sesión" (#9321, cerrar #8599). Puede seleccionar la cuenta xAI en el centro de autorización, agregar o administrar la cuenta xAI o "iniciar sesión con Grok CLI". El uso es el mismo que el de las tarjetas oficiales de Claude y Codex.

  • Cada cuenta vinculada es una tarjeta independiente. Con el número de cuenta en el nombre, puedes agregar tantas tarjetas como quieras; aquellos que no estén vinculados a una cuenta seguirán teniendo la misma tarjeta fija.
  • Al cambiar a la tarjeta con una cuenta vinculada, CC Switch primero actualizará el inicio de sesión de esta cuenta y luego lo escribirá en ~/.grok/auth.json de Grok CLI, y el resto del contenido del archivo no cambiará. Grok CLI no se escribe cuando esta cuenta ya ha iniciado sesión; cuando la red falla temporalmente, solicita volver a intentarlo más tarde. Cuando la cuenta no es válida, se le solicita que vaya al centro de autorización para iniciar sesión nuevamente.
  • Antes de cambiar el número, el número actualmente registrado en Grok CLI se recopilará en el centro de autorización; al volver a la tarjeta "Iniciar sesión con Grok CLI", se restaurará al número anterior al primer cambio de número.
  • Al eliminar la cuenta en el centro de autorización, si Grok CLI está usando CC Switch para iniciar sesión en esta cuenta, se restaurará el inicio de sesión original. Si la cuenta original ya no existe, cierre sesión.
  • Para las tarjetas vinculadas a un número de cuenta, los límites de la tarjeta, el uso y el palet se verifican según este número. Cuando el inicio de sesión de Grok CLI caduque para una tarjeta sin cuenta, use la cuenta del mismo usuario en el centro de autorización para verificar el límite.

Complemento antigravedad CLI

La página "Complementos" admite Antigravity CLI (#9882, #9885). Al igual que otras aplicaciones, puedes llamar a la propia línea de comando de agy. Puede buscar complementos del mercado oficial y de socios en "Descubrir" para instalarlos, habilitarlos, deshabilitarlos, desinstalarlos y actualizarlos.

  • Antes de actualizar, compare el número de versión del mercado. Si es la última versión, no la reinstale.
  • Cuando el complemento está ocupado por una sesión de Antigravity en ejecución o un servicio en segundo plano, se le solicitará que lo cierre primero y vuelva a intentarlo.
  • Los complementos instalados por la antigua aplicación Antigravity se colocan en un directorio con nombre numérico. CC Switch no puede actualizarlos. Le pedirá que los desinstale y los reinstale en "Descubrir".

Estadísticas de uso: vea la tasa de aciertos de la caché por proveedor y modelo

Las listas de estadísticas de uso "Proveedor" y "Modelo" agregan una columna "Tasa de aciertos" después de los Tokens, para que pueda ver qué proveedor y qué modelo no utilizaron el caché. El algoritmo es el mismo que la tasa de aciertos en el registro de solicitudes (accesos de caché ÷ entradas almacenables en caché). Los aciertos de caché y las entradas almacenables en caché de cada fila suman el total en la parte superior; las filas sin entradas almacenables en caché muestran "—".

Saldo de Xiaomi MiMo y límite del plan de tokens

El proveedor de Xiaomi MiMo tiene dos consultas oficiales integradas (cerradas #9404), por lo que ya no necesita confiar en el script de uso de cookies de la consola:

  • Plan Token (Clave que comienza con tp-): Muestra la cuota utilizada y total, así como la hora de finalización de este período.
  • Saldo (Tecla que comienza con sk-): Muestra el saldo disponible (descontando la parte congelada). Un saldo de 0 no se considerará una clave no válida.

La tarjeta del centro de autorización sigue la aplicación de la barra lateral

Las tarjetas de cuenta en el centro de autorización están ordenadas en el orden de las aplicaciones arrastradas a la página "Aplicaciones". La tarjeta se ocultará sólo si todas las aplicaciones que utilizan esta cuenta están ocultas (las cuentas Copilot, ChatGPT, xAI también serán utilizadas por proveedores de aplicaciones como Claude Code); Siempre se mostrará la tarjeta omitida del formulario de proveedor.

Agregar nuevo ajuste preestablecido

Se agregó StringAI.

Cambiar

  • La base de datos y el enrutamiento local son más rápidos (#9820, #9821): la base de datos principal cambia al modo WAL, la configuración, el enrutamiento, los precios y las colas de conmutación por error que se leerán para cada solicitud de enrutamiento se cambian para leer desde el caché, las operaciones de la base de datos de enrutamiento se mueven a un subproceso separado, sin ocupar más el subproceso que procesa la solicitud; el contenido de la conversación se copia una vez menos al reenviar la solicitud y el filtrado de privacidad ya no se repite para las solicitudes que no se han reescrito.
  • La sincronización de uso es más rápida (#9817, #9818): los registros de sesión de cada aplicación se analizan en paralelo; Los scripts de uso se ejecutan en subprocesos separados y ya no ralentizan otras solicitudes.
  • La búsqueda de contenido de conversaciones es más rápida (#9827, #9896): la búsqueda de una o dos palabras ya no escaneará todo el texto; cuando continúe escribiendo, se cancelará la última búsqueda inconclusa. El formato del índice de búsqueda ha cambiado y el índice se reconstruirá para la primera búsqueda después de la actualización.
  • La página "Aplicación" se abre más rápido (#9418, #9886, cerrar #9884): Primero muestra el grupo "Instalado/No instalado" según la ruta de instalación de la máquina, sin esperar la verificación de la versión de cada herramienta; las versiones de cada herramienta se verifican al mismo tiempo y cada herramienta se muestra una después de la verificación.

Seguridad

  • Importación de enlace profundo MCP (#9831): el cuadro de confirmación muestra todos los campos del servidor MCP (incluido el directorio de trabajo, los encabezados de solicitud, etc.) y los campos de alto riesgo están marcados en rojo. Leerá las variables de entorno local, ejecutará comandos auxiliares, señalará el directorio de trabajo a la ruta compartida de la red o la dirección de configuración no es http / https y se negará directamente a importar.
  • Secuencia de comandos de uso (#9829): las solicitudes enviadas por la secuencia de comandos ya no siguen redireccionamientos y no se pueden enviar al propio puerto de enrutamiento del CC Switch. La respuesta puede leer hasta 2 MiB; La clave, la dirección y otras variables completadas en el script se escaparán correctamente. También se verificará la dirección de consulta de uso en el enlace profundo. Si es una intranet o una dirección local, aparecerá un cuadro de confirmación.
  • Importación de SQL (#9832): al importar una copia de seguridad de SQL o una instantánea de sincronización WebDAV/S3, no se permite la creación de activadores ni vistas, el tamaño máximo de archivo es 512 MiB y la ejecución se cancela después de más de 30 segundos.
  • Comprobación del host para direcciones de escucha no locales (#9833): cuando el servicio de enrutamiento escucha 0.0.0.0 / ::, las solicitudes de la máquina local también deben pasar la verificación del host para evitar la nueva vinculación de DNS.

Arreglar

  • El uso del agente principal de Kimi Code Desktop no se cuenta (#9505, consulte #9498): Kimi Code Desktop 1.3.5 ha cambiado el formato de registro de sesión, se omite el uso del agente principal y el modelo de subagente se muestra como unknown. Ambos formatos ahora se pueden leer sin doble cálculo; Después de la actualización, los registros antiguos se volverán a escanear para compensar el uso y los modelos perdidos anteriormente.
  • La velocidad de salida antigravedad es falsamente alta (#9858): a partir de 4.0.38, las solicitudes que se han considerado durante mucho tiempo pueden mostrar decenas de miles de tok/s. El token de salida de Antigravity contiene pensamiento oculto, y la primera palabra tiempo también incluye el tiempo de pensamiento. Ahora se calcula en base al tiempo completo.
  • Las sesiones de Antigravity en Código T3 y ACP independiente no son visibles (#9857, consulte #9838): Estas sesiones ahora aparecerán en la lista de sesiones y en las estadísticas de uso. No hay ningún comando de recuperación disponible para ellos y no se pueden eliminar en CC Switch; la descripción agregada por el Código T3 fuera de la pregunta se eliminará y el título mostrará la pregunta original.
  • La respuesta del API oficial de Mistral está vacía después de habilitar el pensamiento (Ver #9902): El API oficial de Mistral (incluido el modelo de terceros que proporciona) divide la respuesta en fragmentos de pensamiento y texto y los devuelve. La ruta local no se puede leer y la respuesta está vacía o no tiene proceso de pensamiento. Ambos fragmentos ahora se pueden leer secuencialmente; Las solicitudes a aguas arriba permanecen sin cambios.
  • Las respuestas nativas de Kimi siguen reportando 400 después de ver la imagen en paralelo (#8825, consulte #7504): Codex Desktop insertará mensajes entre los resultados de las llamadas a herramientas paralelas. Las respuestas nativas estrictas, como las de Kimi upstream, descartarán los resultados que no sigan la llamada, y se informarán 400 en cada ronda después de esta sesión. Ahora recopilemos todos los resultados y luego coloquemos el mensaje de inserción.
  • Los puntos de la cuenta empresarial de WorkBuddy se muestran como agotados (consulte #9694): la cuenta empresarial se cambia para verificar el uso empresarial, mostrando la cantidad total, el uso y el tiempo de vencimiento; La cantidad ilimitada se muestra como "ilimitada, N usada". Cuando no se encuentra la cantidad, la consulta falla y ya no se muestra "agotado (total 0)".
  • La cuota de xAI no es visible en la bandeja (consulte #9899): los proveedores de xAI OAuth en Codex y Claude Code (incluidos los miembros de la agregación del Codex) también muestran cuotas en la bandeja de acuerdo con la cuenta xAI vinculada. Cuando no está vinculado, se utiliza la cuenta predeterminada del centro de autorización, que es coherente con la tarjeta de interfaz principal.
  • La cuenta oficial en la bandeja se muestra como el nombre de dominio del sitio web (#9863): Se vincula la tarjeta Codex oficial con la cuenta administrada, así como las tarjetas Codex OAuth, GitHub Copilot y xAI OAuth. El subtítulo de la bandeja muestra la cuenta iniciada (las notas manuales tienen prioridad). La tarjeta xAI OAuth en la interfaz principal también muestra el número de cuenta; la bandeja se actualizará después de iniciar sesión en el centro de autorización, cambiar la cuenta predeterminada, eliminarla o cerrar sesión.
  • Las habilidades duplicadas aparecen en "Descubrir" en la página Habilidades: dos habilidades con el mismo nombre en el último directorio del mismo almacén se cargarán en el mismo directorio. "Descubrir" originalmente mostraba dos líneas, pero ahora solo se muestra la más cercana al directorio raíz del almacén.
  • **Se solicita a CLI que viene con OpenCode Desktop que use npm para actualizar (#9099): la fuente de instalación de este CLI se muestra como OpenCode Desktop y explica que se actualiza con la aplicación de escritorio y ya no se cuenta en "todas las actualizaciones"; OpenCode instalado por separado se actualiza como de costumbre.
  • Los eventos de transmisión que están cerca del límite superior de 64 MiB se omiten por error (#9867): el límite superior del búfer agregado por 4.0.39 se cambia para juzgarse en función de un solo evento. Los eventos normales que estén cerca del límite superior ya no se descartarán junto con el siguiente en el mismo bloque.

Instrucciones de actualización

  • Si el servicio de enrutamiento monitorea 0.0.0.0 / :: y utiliza un nombre de host personalizado (que no termina en .local, .internal, .localhost) para acceder a la ruta en esta máquina, recibirá un 403 después de la actualización. Debe completar este nombre de host en la "Dirección de conexión" de la "Ruta local" (esta dirección también se escribirá en la configuración de cada cliente). Otros dispositivos en LAN, WSL y Docker no se ven afectados.
  • El índice para la búsqueda de contenido de la sesión se reconstruirá durante la primera búsqueda después de la actualización. Si son muchas sesiones la primera búsqueda será más lenta.

cc-switch v4.0.40

Highlights

  • Grok Official now supports xAI account switching — #9321 adds account-bound Grok cards that refresh credentials and write only the selected identity to ~/.grok/auth.json, preserving its other contents. Quotas follow the bound account, while deleting an account or returning to “Follow Grok CLI login” restores the previous CLI identity.

  • Antigravity CLI joins the plugin manager — #9882 and #9885 support discovering and managing official and partner-market plugins through agy. Updates skip current versions and require stopping active sessions; plugins installed by older Antigravity versions into numbered directories must be uninstalled and reinstalled because CC Switch cannot update them.

  • Quota diagnostics are more actionable — Supplier and model tables now expose cache-hit rate, making cache-unfriendly workloads visible. Xiaomi MiMo also gains built-in queries for tp- Token Plan usage and sk- balance, including frozen-fund adjustments, removing the need for cookie-scraping usage scripts.

  • Import and routing surfaces are hardened — #9831, #9829, and #9832 reject risky deep-link MCP configurations, restrict usage-script redirects and response size, and block SQL triggers/views with new size and execution-time limits. Migration: if routing listens on 0.0.0.0 or :: and local requests use a custom hostname, expect HTTP 403 until that hostname is added under Local Routing → Connection Address (#9833).

  • Routing, usage collection, and search are faster — WAL, cached request-path configuration, and dedicated database threads reduce routing contention (#9820, #9821); session logs are scanned in parallel, and usage scripts run off the request path. Migration: the search-index format changed, so the first search after upgrading rebuilds the index and may take longer for large histories (#9827).

  • Provider compatibility fixes prevent empty or stuck sessions — Mistral responses now preserve reasoning/body fragment order, and Kimi native Responses groups parallel image-tool results before intervening prompts to prevent subsequent turns from repeatedly returning HTTP 400 (#8825). Antigravity throughput is recalculated against full elapsed time so hidden thinking no longer inflates tok/s, while the 64 MiB streaming fix avoids dropping valid near-limit events (#9867).

CC Switch v4.0.40

本版本让 Grok Build 的官方卡可以绑定授权中心里的 xAI 账号，像 Claude、Codex 官方卡一样在多个 Grok 账号之间切换。插件页支持 Antigravity CLI；用量统计的供应商和模型列表加了缓存命中率；小米 MiMo 内置余额和 Token Plan 额度查询；授权中心的账号卡片跟随侧栏应用的顺序和隐藏设置。

本版本还加固了深链接导入 MCP、用量脚本、SQL 导入和非本机监听地址的安全检查，并提升了数据库、本地路由、用量同步、会话搜索和「应用」页的速度。另外修复了 Kimi Code Desktop 主 agent 的用量没统计；Antigravity 输出速度从 4.0.38 起虚高；T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到；Mistral 官方 API 开思考后回复为空；Kimi 原生 Responses 在并行看图工具调用后一直报 400；WorkBuddy 企业账号积分显示为已用完；托盘里看不到 xAI 额度、官方账号显示成网站域名；Skills 页的「发现」里出现重复的技能；「应用」页要等版本检查完才显示安装状态等问题。

新增

Grok 官方卡绑定 xAI 账号

Grok Build 的 Grok Official 表单加了「登录方式」（#9321，关闭 #8599），可以选授权中心里的 xAI 账号、添加或管理 xAI 账号，或者「跟随 Grok CLI 登录」，用法和 Claude、Codex 官方卡一样。

  • 每个绑定的账号是一张单独的卡，名字带上账号，可以加任意多张；不绑账号的仍是原来那张固定的卡。
  • 切到绑了账号的卡时，CC Switch 会先刷新这个号的登录，再把它写进 Grok CLI 的 ~/.grok/auth.json，文件里的其他内容不动。Grok CLI 已经登录着这个号时不写；网络暂时失败时提示稍后重试，账号确实失效才提示去授权中心重新登录。
  • 换号前，Grok CLI 当前登录的号会先收进授权中心；切回「跟随 Grok CLI 登录」的卡时，还原成第一次换号前的号。
  • 在授权中心删掉账号时，如果 Grok CLI 正在用的是 CC Switch 替这个号写的登录，会还原原来的登录，原来的号也没了就退出登录。
  • 绑了账号的卡，卡片、用量和托盘的额度都按这个号查。没绑账号的卡在 Grok CLI 的登录过期时，改用授权中心里同一个用户的账号查额度。

Antigravity CLI 插件

「插件」页支持 Antigravity CLI（#9882、#9885），和其他应用一样调用 agy 自己的命令行，可以在「发现」里浏览官方和合作伙伴市场的插件，安装、启用、停用、卸载和更新。

  • 更新前先比对市场上的版本号，已是最新就不重装。
  • 插件被正在运行的 Antigravity 会话或后台服务占用时，提示先关掉再重试。
  • 旧版 Antigravity 应用装的插件放在数字命名的目录里，CC Switch 无法替它更新，会提示卸载后在「发现」里重新安装。

用量统计：按供应商和模型看缓存命中率

用量统计的「供应商」和「模型」列表在 Tokens 后面加了「命中率」一列，能看出是哪家供应商、哪个模型没吃到缓存。算法和请求日志里的命中率一样（缓存命中 ÷ 可缓存输入），各行的缓存命中和可缓存输入加起来与顶部的总数一致；没有可缓存输入的行显示「—」。

小米 MiMo 余额和 Token Plan 额度

小米 MiMo 的供应商内置了两种官方查询（关闭 #9404），不用再靠抓控制台 Cookie 的用量脚本：

  • Token Plan（tp- 开头的 Key）：显示已用和总额度，以及本期结束时间。
  • 余额（sk- 开头的 Key）：显示可用余额（扣除冻结部分），余额为 0 不会被当成 Key 无效。

授权中心卡片跟随侧栏应用

授权中心的账号卡片按「应用」页里拖动的应用顺序排列。只有用到这个账号的应用全都隐藏了，卡片才隐藏（Copilot、ChatGPT、xAI 账号还会被 Claude Code 等应用的供应商用到）；从供应商表单跳过来的那张卡总是显示。

新增预设

新增 StringAI。

变更

  • 数据库与本地路由更快（#9820、#9821）：主数据库改用 WAL 模式，路由每次请求要读的配置、路由、定价和故障转移队列改从缓存读，路由的数据库操作移到单独的线程，不再占住处理请求的线程；转发请求时少复制一次对话内容，没有改写过的请求不再重复跑隐私过滤。
  • 用量同步更快（#9817、#9818）：各应用的会话日志并行扫描；用量脚本在单独的线程里运行，不再拖慢其他请求。
  • 会话内容搜索更快（#9827、#9896）：一两个字的搜索不再扫描全部正文；继续输入时，上一次还没完成的搜索会被取消。搜索索引格式有变，升级后第一次搜索会重建索引。
  • 「应用」页打开更快（#9418、#9886，关闭 #9884）：先按本机的安装路径显示「已安装 / 未安装」分组，不用等每个工具的版本检查；各工具的版本同时检查，查完一个显示一个。

安全

  • 深链接导入 MCP（#9831）：确认框显示 MCP 服务器的全部字段（包括工作目录、请求头等），高危字段标红提示。会读取本机环境变量、执行辅助命令、把工作目录指向网络共享路径，或地址不是 http / https 的配置，直接拒绝导入。
  • 用量脚本（#9829）：脚本发出的请求不再跟随重定向，不能发给 CC Switch 自己的路由端口，响应最多读 2 MiB；填进脚本的 Key、地址等变量会正确转义。深链接里的用量查询地址也会检查，是内网或本机地址时确认框会提示。
  • SQL 导入（#9832）：导入 SQL 备份或 WebDAV / S3 同步快照时，不允许创建触发器和视图，文件最大 512 MiB，执行超过 30 秒即中止。
  • 非本机监听地址的 Host 检查（#9833）：路由服务监听 0.0.0.0 / :: 时，来自本机的请求也要通过防 DNS 重绑定的 Host 检查。

修复

  • Kimi Code Desktop 主 agent 的用量没统计（#9505，见 #9498）：Kimi Code Desktop 1.3.5 换了会话日志格式，主 agent 的用量被跳过，子 agent 的模型显示为 unknown。现在两种格式都能读，不会重复计算；升级后会重新扫描一次旧日志，补上以前漏掉的用量和模型。
  • Antigravity 输出速度虚高（#9858）：4.0.38 起，思考较久的请求能显示几万 tok/s。Antigravity 的输出 token 含隐藏的思考，首字时间也包含思考时长，现在改回按完整耗时计算。
  • T3 Code 和单独运行的 ACP 里的 Antigravity 会话看不到（#9857，见 #9838）：这些会话现在会出现在会话列表和用量统计里。它们没有可用的恢复命令，也不能在 CC Switch 里删除；T3 Code 加在提问外面的说明会去掉，标题显示原本的提问。
  • Mistral 官方 API 开思考后回复为空（见 #9902）：开了思考的 Mistral 官方 API（包括它提供的第三方模型）把回复拆成思考和正文两种片段返回，本地路由读不出来，回复为空或没有思考过程。现在两种片段都能按顺序读出；发给上游的请求不变。
  • Kimi 原生 Responses 在并行看图后一直报 400（#8825，见 #7504）：Codex Desktop 会在并行工具调用的结果之间插入提示，Kimi 这类严格的原生 Responses 上游会丢掉不紧跟调用的结果，这个会话之后每轮都报 400。现在先把这批结果收齐放在一起，再放插入的提示。
  • WorkBuddy 企业账号积分显示为已用完（见 #9694）：企业账号改查企业用量，显示总额度、已用和到期时间；不限量的显示「不限量，已用 N」，查不到额度时报查询失败，不再显示「已用完（共 0）」。
  • 托盘里看不到 xAI 额度（见 #9899）：Codex、Claude Code 里的 xAI OAuth 供应商（包括 Codex 聚合的成员）在托盘里也按绑定的 xAI 账号显示额度，没绑定时用授权中心的默认账号，和主界面卡片一致。
  • 托盘里官方账号显示成网站域名（#9863）：绑了托管账号的 Codex 官方卡，以及 Codex OAuth、GitHub Copilot、xAI OAuth 卡，托盘副标题显示登录的账号（手动备注优先）。主界面的 xAI OAuth 卡片也显示账号；在授权中心登录、切换默认账号、删除或退出登录后托盘会跟着更新。
  • Skills 页的「发现」里出现重复的技能：同一个仓库里末级目录同名的两个技能会装进同一个目录，「发现」里原来显示成两行，现在只显示离仓库根目录最近的那个。
  • OpenCode Desktop 自带的 CLI 被提示用 npm 升级（#9099）：这份 CLI 的安装来源显示为 OpenCode Desktop，并说明它随 Desktop 应用更新，不再计入「全部升级」；单独安装的 OpenCode 照常升级。
  • 快到 64 MiB 上限的流式事件被误跳过（#9867）：4.0.39 加的缓冲上限改成按单条事件判断，接近上限的正常事件不会再和同一块里的下一条一起被丢掉。

升级说明

  • 路由服务监听 0.0.0.0 / ::、又在本机用自定义主机名（不以 .local、.internal、.localhost 结尾）访问路由的，升级后会收到 403，需要在设置「本地路由」的「连接地址」里填上这个主机名（这个地址也会写进各客户端的配置）。局域网、WSL、Docker 里的其他设备不受影响。
  • 会话内容搜索的索引会在升级后第一次搜索时重建，会话多的话第一次会慢一些。
