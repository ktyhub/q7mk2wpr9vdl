Interruptor CC v4.0.34

Esta versión del repositorio de habilidades admite GitLab, Gitea y Forgejo (incluidas instancias autoconstruidas y Codeberg), y ya no puede agregar repositorios únicamente en GitHub. Ahora puedes eliminar directamente la sesión de Antigravity CLI en la gestión de sesiones; Después de activar la descarga automática de actualizaciones, la nueva versión comenzará a descargarse inmediatamente. Además, los modelos agregados manualmente de WorkBuddy pueden establecer la intensidad del pensamiento y la sincronización S3 también puede borrar configuraciones guardadas localmente como WebDAV. Además, el proveedor "Obtener lista de modelos" de Gemini CLI informó que la clave no es válida o obtiene una lista vacía; se considera que el modelo de copiloto GitHub en el Codex no admite imágenes; Alibaba Cloud OSS, Tencent Cloud COS y Huawei Cloud OBS no pueden utilizar la sincronización S3; toda la carga de sincronización en la nube falla cuando hay enlaces no válidos en el directorio de Habilidades; Fable 5.2 se muestra como Fable 5 en modo de enrutamiento; Copilot La tasa de aciertos de caché del modelo Gemini en Copilot es baja; Copilot tiene problemas como una solicitud fallida para el modelo 1M Fable. Agregar

El almacén de habilidades admite GitLab, Gitea y Forgejo

"Management Skills Warehouse" solía aceptar solo la dirección de github.com, pero ahora también puede agregar almacenes públicos en GitLab, Gitea y Forgejo (para conocer los requisitos, consulte #1324, #4227), incluidas instancias autoconstruidas y Codeberg:

  • Complete owner/name y proceselo como GitHub; Al completar la dirección completa de otros sitios, CC Switch primero preguntará si el sitio es Gitea/Forgejo o GitLab, y luego lo descargará de la forma correspondiente. Se pueden utilizar puertos personalizados, agrupación de varios niveles de GitLab y direcciones copiadas en la página de Gitea.
  • Las habilidades de exploración, la instalación, la búsqueda de actualizaciones y los enlaces "Abrir documento" irán al sitio donde se encuentra el repositorio.
  • Solo se admiten almacenes públicos y la dirección debe ser https. Gitee aún no lo admite (su interfaz de descarga requiere un token).
  • El mismo owner/name sólo se puede conservar en un sitio. Agregar un almacén con el mismo nombre a otro sitio reemplazará el original.

Eliminar sesión de Antigravity CLI en la gestión de sesiones

Anteriormente, las sesiones de Antigravity solo se podían eliminar en agy. Ahora puedes eliminar directamente la sesión de Antigravity CLI en la gestión de sesiones. Al eliminar, limpiará su índice de sesión y su resumen como si fuera el propio agy. No volverá a aparecer después de reiniciar nuevamente.

  • La sesión no se puede eliminar mientras esté abierta en agy. Ciérrelo primero.
  • Las sesiones IDE de Antigravity, así como las sesiones con solo índices y sin registros de sesión, aún deben eliminarse en Antigravity.

Comience a descargar automáticamente la nueva versión inmediatamente después de descubrirla

Después de activar "Descargar actualizaciones automáticamente", solía tener que esperar una verificación de antecedentes aproximadamente 1 minuto después del inicio para comenzar a descargar. La página "Acerca de" solo mostraba que había una nueva versión, lo que parecía como si el cambio no estuviera vigente. Ahora comenzará a descargarse tan pronto como se encuentre una nueva versión durante el inicio, y se mostrará "Descargando nueva versión en segundo plano..." o "Descarga completada" debajo del mensaje de nueva versión en la página "Acerca de". También se han realineado los iconos, texto y botones del cuadro de confirmación de instalación.

Los modelos agregados manualmente de WorkBuddy pueden establecer la intensidad del pensamiento

El modelo predeterminado de WorkBuddy ya ha podido seleccionar la intensidad del pensamiento en el menú del modelo WorkBuddy, pero los modelos agregados o seleccionados manualmente de la lista de modelos solo tienen el interruptor de pensamiento (consulte #9599). Ahora, después de activar el pensamiento, puede verificar la "intensidad del pensamiento" que se proporcionará en los detalles del modelo y establecer "puede desactivar el pensamiento"; Si no se marca ninguna, solo se seguirá mostrando el interruptor de pensamiento. Los modelos obtenidos de la lista de modelos también se completarán automáticamente con las fortalezas disponibles de acuerdo con las reglas del formulario Pi.

La sincronización S3 puede borrar la configuración local

La configuración de sincronización de S3 tiene una nueva "Configuración clara", que es la misma que WebDAV: elimina el área guardada, el depósito, la clave, el punto final y el directorio remoto de la máquina local y detiene la sincronización automática. Los datos cargados en el depósito no se eliminarán.

Arreglar

  • El proveedor de Gemini CLI "Obtener lista de modelos" informa que la clave no es válida o que se obtiene una lista vacía cuando se utiliza una puerta de enlace compatible (consulte #8546): en el pasado, cuando presionaba Authorization: Bearer para enviar una clave AI Studio, Google no la reconocía; ahora lo obtienes mediante el método nativo de Gemini. La última versión fue reparada por Claude Code / Claude Desktop, que eligió el proveedor de formato Gemini Native. Esta vez la reparación la realizó el propio proveedor de Gemini CLI.
  • Cuando se utiliza GitHub Copilot en Codex, los modelos que admiten imágenes se tratan como solo texto de soporte (#8027, consulte #7977): Al obtener la lista de modelos, se leerá la capacidad de entrada de imágenes declarada por Copilot. Para los proveedores de Copilot que se han agregado, vuelva a obtener la lista de modelos y guárdela, luego salga por completo y reinicie Codex.
  • Alibaba Cloud OSS, Tencent Cloud COS y Huawei Cloud OBS no pueden usar la sincronización S3 y se les solicita un error de clave de acceso (consulte #3996): los nuevos depósitos de estas tres empresas rechazan la antigua dirección basada en ruta y ahora usarán automáticamente la dirección que coloca el depósito en el nombre de dominio. Otros servicios como MinIO y R2 se mantienen sin cambios.
  • El proveedor de servicios seleccionado en la configuración de sincronización de S3 no se recuerda después de volver a abrir la página de configuración (#8644).
  • Cuando hay enlaces no válidos en el directorio de Skills, toda la carga de sincronización en la nube falla (consulte #9615): los enlaces simbólicos no válidos o las conexiones de directorio que no se pueden abrir en Windows provocaron anteriormente que se cancelara toda la carga (Windows informó os error 5), y la descarga tampoco pudo realizar una copia de seguridad de las Skills existentes. Estos enlaces ahora se omiten y se registra una advertencia.
  • Cuando el upstream es Fable 5.2 en modo de enrutamiento, /model de Claude Code todavía muestra Fable 5 (ver #9608): Fable 5.2 / 5.1 ahora está escrito como el ID de modelo de la versión correspondiente, y Claude Desktop también está corregido.
  • Cuando GitHub Copilot usa el modelo Gemini, la tasa de aciertos de caché para sesiones largas es solo alrededor del 27% (ver #9613): Claude Code agrega un mensaje del sistema en cada ronda, y Copilot parece moverlos al comienzo de la solicitud, lo que hace que el comienzo de cada ronda de solicitudes cambie. Ahora solo para el modelo Gemini en Copilot, los mensajes del sistema en medio de la sesión se envían como mensajes de usuario en sus posiciones originales y el comienzo no cambia. Otros proveedores y modelos no se ven afectados.
  • Cuando GitHub Copilot usa el modelo Fable y verifica 1M, la solicitud reporta 400: Copilot no tiene una versión 1M del modelo Claude, y ahora devolverá el modelo normal de la misma versión. Después de obtener la lista de modelos de Copilot, los modelos que no tienen una versión de 1M (y el contexto es inferior a 1M) no se pueden verificar para 1M; aquellos que ya han sido marcados aparecerán en el mensaje. Se recomienda cancelar porque Claude Code seguirá planificando el contexto de acuerdo con 1M.
  • Después de cambiar el directorio de configuración de Hermes en los ajustes, el proveedor no se escribió en el nuevo directorio (#9567).
  • Después de que se produzca un error interno en la detección de conectividad de MCP o en el inicio de sesión del arnés DeepSeek, se debe reiniciar CC Switch antes de poder usarlo nuevamente (#9572).
  • Si el nombre del proveedor, dirección o nombre del modelo contiene la palabra mistral, se tratará como Mistral. Intensidad de pensamiento (#9573): Ahora solo se reconoce la dirección oficial api.mistral.ai.
  • Se agregó el precio máximo de Qwen4 (#9612).

Instrucciones de actualización

La versión de la base de datos aumentó de 26 a 27, para que el almacén de habilidades registre el sitio en el que se encuentra. Se realizará una copia de seguridad de la base de datos automáticamente antes de la actualización; Si vuelve a la versión anterior después de la actualización, la versión anterior le indicará que la versión de la base de datos es demasiado nueva y no se puede abrir.

cc-switch v4.0.34

Highlights

  • One-way database migration (v26 → v27) — The only breaking change: the schema now records which host each skill repo lives on. Upgrade auto-backs-up the DB, but rollback is off the table — older builds refuse to open the newer database ("version too new"). If you need an escape hatch, keep that pre-upgrade backup yourself before deploying.
  • Skill repos escape GitHub (#4227) — "Manage skill repos" now accepts GitLab, Gitea and Forgejo, including self-hosted instances and Codeberg. owner/name still means GitHub; a full URL triggers a one-time Gitea/Forgejo-vs-GitLab prompt, and custom ports, GitLab nested groups and URLs copied from Gitea all work — browsing, install, update checks and "open docs" follow the repo's host. Watch the limits: public repos and HTTPS only (no Gitee, whose download API needs a token), and since an owner/name may exist on only one host, adding the same name elsewhere silently replaces the original entry.
  • Copilot fixes demand a manual refresh and restart — Image-capable Copilot models were misdetected as text-only (#8027); existing providers must re-fetch and save the model list, then fully quit and restart Codex. The 1M checkbox is also now honest: Copilot has no 1M Claude variants, so requests fall back to the standard model, models without 1M can no longer be flagged, and any still-checked ones are listed for you to uncheck — Claude Code otherwise keeps planning against a 1M context it won't get.
  • Copilot + Gemini cache-hit rate repaired — Long sessions through GitHub Copilot were hitting ~27% cache because Claude Code appends a system message every turn, which Copilot hoists to the front and thereby changes the prompt prefix each round (#9613). The fix re-sends mid-session system messages in place as user messages, scoped to Gemini models on Copilot only — expect better cache reuse there, no behavior change elsewhere.
  • S3 sync: virtual-hosted addressing and local config clearing — Alibaba OSS, Tencent COS and Huawei OBS buckets reject legacy path-style URLs, so sync now uses bucket-in-domain addressing (#3996); MinIO/R2 are untouched. A new "Clear config" action (like WebDAV) wipes locally stored region, bucket, keys, endpoint and remote dir and stops auto-sync — uploaded data in the bucket is safe, and the chosen provider now survives reopening settings (#8644).
  • Smaller operational fixes worth noting — Gemini CLI providers now fetch models the native way instead of sending an Authorization: Bearer AI Studio key that Google rejects or that yields empty lists via gateways (#8546). Cloud sync skips dead symlinks / broken Windows junctions with a warning instead of aborting the whole upload (#9615). Auto-download now starts the moment an update is detected at launch rather than waiting for the ~1-minute background check. And Mistral thinking-strength handling now keys off the official api.mistral.ai host, so any provider/name/model containing the string "mistral" is no longer misclassified (#9573).

CC Switch v4.0.34

本版本的技能仓库支持 GitLab、Gitea 和 Forgejo（包括自建实例和 Codeberg），不再只能添加 GitHub 上的仓库。会话管理里现在可以直接删除 Antigravity CLI 的会话；开启自动下载更新后，发现新版本会立刻开始下载。另外，WorkBuddy 手动添加的模型可以设置思考强度，S3 同步也可以像 WebDAV 一样清除本机保存的配置。

另外修复了 Gemini CLI 的供应商「获取模型列表」报 Key 无效或拿到空列表；Codex 里的 GitHub Copilot 模型被当成不支持图片；阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步；Skills 目录里有失效链接时整个云同步上传失败；路由模式下 Fable 5.2 被显示成 Fable 5；Copilot 上的 Gemini 模型缓存命中率低；Copilot 上勾了 1M 的 Fable 模型请求失败等问题。

新增

技能仓库支持 GitLab、Gitea 和 Forgejo

「管理技能仓库」以前只接受 github.com 的地址，现在也能添加 GitLab、Gitea、Forgejo 上的公开仓库（需求见 #1324、#4227），包括自建实例和 Codeberg：

  • 填 owner/name 仍按 GitHub 处理；填其他站点的完整地址时，CC Switch 会先问一次这个站点是 Gitea / Forgejo 还是 GitLab，再按对应的方式下载。自定义端口、GitLab 的多级分组、Gitea 页面上复制的地址都能用。
  • 浏览技能、安装、检查更新和「打开文档」链接都会去仓库所在的站点。
  • 只支持公开仓库，地址必须是 https。Gitee 暂不支持（它的下载接口需要令牌）。
  • 同一个 owner/name 只能保留在一个站点上，在另一个站点添加同名仓库会替换原来的。

在会话管理里删除 Antigravity CLI 会话

以前 Antigravity 的会话只能在 agy 里删。现在可以在会话管理里直接删除 Antigravity CLI 的会话，删除时会和 agy 自己一样，把它的会话索引和摘要一并清理，重启 agy 后不会再冒出来。

  • 会话正在 agy 里打开时不能删，先在 agy 里关掉它。
  • Antigravity IDE 的会话，以及只有索引、没有会话记录的会话，仍然要在 Antigravity 里删除。

发现新版本后立刻开始自动下载

开启「自动下载更新」后，以前要等启动约 1 分钟后的后台检查才开始下载，「关于」页只显示有新版本，看起来像开关没生效。现在启动时一发现新版本就开始下载，「关于」页的新版本提示下会显示「正在后台下载新版本…」或「已下载完毕」。安装确认框的图标、文字和按钮也重新对齐了。

WorkBuddy 手动添加的模型可以设置思考强度

预设里的 WorkBuddy 模型早就能在 WorkBuddy 的模型菜单里选思考强度，手动添加或从模型列表选的模型却只有思考开关（见 #9599）。现在打开思考后，模型详情里可以勾选要提供的「思考强度」，并设置「可以关闭思考」；都不勾时仍只显示思考开关。从模型列表获取的模型也会按 Pi 表单的规则自动填上可用的强度。

S3 同步可以清除本机配置

S3 同步设置新增「清除配置」，和 WebDAV 一样：从本机删除保存的区域、存储桶、密钥、端点和远程目录，并停止自动同步，存储桶里已经上传的数据不会删除。

修复

  • Gemini CLI 的供应商「获取模型列表」报 Key 无效，或者用兼容网关时拿到空列表（见 #8546）：以前按 Authorization: Bearer 发 AI Studio Key，Google 不认；现在按 Gemini 原生方式获取。上一版修好的是 Claude Code / Claude Desktop 选 Gemini Native 格式的供应商，这次修的是 Gemini CLI 自己的供应商。
  • Codex 里用 GitHub Copilot 时，支持图片的模型被当成只支持文字（#8027，见 #7977）：获取模型列表时会读取 Copilot 声明的图片输入能力。已经添加的 Copilot 供应商，请重新获取模型列表并保存，再完全退出并重启 Codex。
  • 阿里云 OSS、腾讯云 COS、华为云 OBS 用不了 S3 同步，被提示 Access Key 错误（见 #3996）：这三家的新存储桶拒绝旧的路径式地址，现在会自动改用把存储桶放在域名里的地址。MinIO、R2 等其他服务不变。
  • S3 同步设置里选的服务商，重新打开设置页后没记住（#8644）。
  • Skills 目录里有失效的链接时，云同步整个上传失败（见 #9615）：失效的符号链接，或 Windows 上打不开的目录联接，以前会让上传整体中止（Windows 上报 os error 5），下载时也会在备份现有 Skills 这一步失败。现在跳过这类链接并记录警告。
  • 路由模式下上游是 Fable 5.2 时，Claude Code 的 /model 仍显示 Fable 5（见 #9608）：Fable 5.2 / 5.1 现在写成对应版本的模型 ID，Claude Desktop 同样修正。
  • 经 GitHub Copilot 用 Gemini 模型时，长会话的缓存命中率只有约 27%（见 #9613）：Claude Code 每一轮都会追加一条系统消息，Copilot 看起来会把它们都挪到请求开头，导致每轮请求的开头都变了。现在只对 Copilot 上的 Gemini 模型，把会话中途的系统消息按原位置作为用户消息发送，开头不再变化。其他供应商和模型不受影响。
  • 经 GitHub Copilot 用 Fable 模型并勾选 1M 时，请求报 400：Copilot 没有 1M 版本的 Claude 模型，现在会退回同版本的普通模型。获取过 Copilot 模型列表后，没有 1M 版本（上下文也不到 1M）的模型不能再勾 1M；已经勾了的会列在提示里，建议取消，因为 Claude Code 仍会按 1M 规划上下文。
  • 在设置里改了 Hermes 的配置目录后，供应商没有写进新目录（#9567）。
  • MCP 连通性检测或 DeepSeek Harness 登录出过一次内部错误后，要重启 CC Switch 才能再用（#9572）。
  • 供应商名称、地址或模型名里带 mistral 字样，就会被当成 Mistral 处理思考强度（#9573）：现在只认官方地址 api.mistral.ai。
  • 新增 Qwen4 Max 的价格（#9612）。

升级说明

数据库版本从 26 升到 27，为技能仓库记录它所在的站点。升级前会自动备份数据库；升级后再退回旧版本，旧版本会提示数据库版本过新，打不开。
