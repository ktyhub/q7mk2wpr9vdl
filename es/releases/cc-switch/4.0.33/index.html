Interruptor CC v4.0.33

Esta versión soluciona el problema de que después de volver a Claude oficial desde un proveedor externo, la sesión de Claude Code ya abierta aún envía la solicitud al proveedor anterior y es necesario reiniciar la sesión para recuperarla. Ollama Cloud se ha agregado a la consulta de cuota de paquete; El cambio de cuenta de Antigravity en el centro de autorización ahora también es compatible con Windows. Además, el proveedor de Claude Code/Claude Desktop ha solucionado el informe "La clave API no es válida o no tiene permiso" al obtener la lista de modelos al seleccionar el formato Gemini Native; Cloudflare bloquea a algunos proveedores de servicios para obtener la lista de modelos; algunas solicitudes de Antigravity Orchestrator aún no tienen precio; La sincronización WebDAV no está disponible en absoluto en algunos NAS; El error de carga de WebDAV/S3 solo muestra "Error en la construcción de la solicitud"; consultar xAI Problemas como que se le solicite iniciar sesión nuevamente cuando se encuentre con nerviosismo en la red al solicitar cuotas; no actualizar una habilidad a mitad de camino y eliminar la habilidad original, etc. Inglés → | Versión japonesa →

Agregar

Cuota del paquete Ollama Cloud

El proveedor con la dirección ollama.com ahora puede consultar la cuota del Plan Token (para conocer los requisitos, consulte #9382): el paquete actual muestra la proporción restante de la cuota y el tiempo de reinicio en el paquete actual, y la versión anterior del paquete muestra la proporción restante de 5 horas y dos ventanas por semana. No se muestra la cuota comprada por separado; Las cuentas de pago por uso no tienen cuotas de paquete y se explicarán los motivos. Ollama (localhost:11434) que se ejecuta de forma nativa no tiene un plan y no será reconocido.

  • Para los proveedores de Ollama Cloud recién agregados o la importación con un solo clic, la consulta de cuota está habilitada de forma predeterminada; para proveedores existentes, haga clic en "Configurar consulta de uso" en la tarjeta y la plantilla del plan de token se seleccionará automáticamente. Abra "Habilitar consulta de uso" y guárdelo.

Cambiar cuenta de Antigravity en Windows

El cambio de cuenta Antigravity en el centro de autorización solía ser compatible solo con macOS, pero ahora también se puede usar en Windows: después del cambio, agy lee la nueva cuenta. La tarjeta oficial de Antigravity puede vincular la cuenta y verificar el límite de la cuenta vinculada. También le indicará a qué cuenta cambiará antes de abrir la terminal. Linux aún no es compatible.

Arreglar

  • Después de volver a cambiar a Claude oficial desde un proveedor externo, la sesión abierta de Claude Code aún envía la solicitud al proveedor anterior y debe reiniciarse para reanudarla (#9247, consulte #7808, #3057): El Claude Code en ejecución solo leerá las variables de entorno settings.json que se agreguen y cambien en la sesión, y las eliminadas permanecerán en el sesión. Ahora, al cambiar, primero escriba la dirección, las credenciales y la asignación del modelo que se eliminarán como valores nulos. La siguiente solicitud de la sesión abierta ya no utilizará la anterior y luego la eliminará del archivo después de unos 10 segundos. El modelo principal (ANTHROPIC_MODEL) configurado cuando se inicia la sesión no cambiará: si se configuró en el modelo anterior, seleccione Predeterminado en el menú del modelo después de volver a cambiar o abra una nueva sesión.
  • Cuando el proveedor de Claude Code / Claude Desktop selecciona el formato Gemini Native, "Obtener lista de modelos" siempre informa "La clave API no es válida o no tiene permiso": Ahora pase la clave en la forma requerida por Google. La solicitud real que se enruta ya es normal, solo se ve afectada la obtención de la lista de modelos. Además, para Pi, Oh My Pi y Kimi Code, si elige el proveedor de la interfaz de Google, puede obtener una lista de modelos que antes solo enumera hasta 50 modelos, pero ahora puede enumerarlos todos.
  • Al obtener la lista de modelos, algunos proveedores de servicios detrás de Cloudflare la rechazaron directamente y fueron informados erróneamente como "La clave API no es válida o no tiene permiso" (#7429, consulte #7427): la solicitud ahora lleva User-Agent de forma predeterminada; Si User-Agent está configurado en el encabezado del proveedor o de la solicitud, prevalecerá la configuración.
  • Cuando Antigravity selecciona Orchestrator, algunas solicitudes aún se muestran sin precio (#9542, consulte #9493): Los pasos que se muestran como "Gemini 4 Hydrogen (Orchestrator)" tienen un precio de acuerdo con el precio de Gemini 4 Hydrogen, y el historial de los últimos 30 días también compensará la tarifa. Los precios personalizados siguen teniendo prioridad.
  • La sincronización WebDAV no está disponible en absoluto en algunos NAS y las conexiones de prueba, cargas y descargas fallan (#5623, consulte #5621): Estos NAS aún devuelven 400 a "Crear directorio" cuando la carpeta compartida ya existe. En el pasado, abortaría directamente, pero ahora comprobará nuevamente si el directorio existe.
  • Cuando el servidor desconecta la carga de WebDAV/S3, solo se muestra "Error en la construcción de la solicitud" (consulte #9559): ahora está claro si la solicitud no se construye o falla cuando se envía, y se adjunta el motivo específico para facilitar la determinación de si se trata de un problema de red, TLS o servidor. Los parámetros de contraseña y firma en la dirección no aparecerán en el informe de errores.
  • La sincronización automática de S3 aún se puede cargar nuevamente después de desactivarla (#9528): las cargas automáticas en cola mientras hay otra sincronización en progreso ahora volverán a leer la configuración antes de comenzar y ya no se cargarán si la sincronización automática o la sincronización de S3 se desactivan durante el período. WebDAV es sólo eso.
  • Al consultar el saldo de la cuenta xAI, si encuentra fluctuaciones en la red o un error del servicio xAI, se le pedirá que inicie sesión nuevamente (#9526, consulte #9522): este mensaje solo aparecerá si el inicio de sesión no es realmente válido. Los errores temporales se informarán como de costumbre y se conservará el último saldo encontrado. Inténtalo de nuevo la próxima vez.
  • Después de que caducó una cuenta xAI no predeterminada, la cuenta predeterminada seleccionada en el centro de autorización fue reemplazada por otra cuenta (#9548, consulte #9543).
  • Si la copia falla a mitad de camino al actualizar una habilidad, la habilidad original se eliminará, pero aún se mostrará como instalada en la lista (ver #9521): ahora la nueva versión será reemplazada solo después de que se haya copiado por completo, y la versión original se conservará si falla.
  • Cuando el Codex se convierte al formato Chat mediante enrutamiento, required: null en la definición de la herramienta es rechazado por el flujo ascendente estricto (#7023, consulte #7019).
  • Cuando la ruta al archivo de configuración del shell en macOS/Linux contiene dos puntos, "se detectó un conflicto de variables de entorno del sistema" no podrá eliminar ni restaurar las variables (#7170, consulte #7169).
  • Los valores predeterminados de Pi de PIPELLM, AICodeWith y E-FlowCode se muestran como el nombre del modelo antiguo en la selección de modelo (#9514): por ejemplo, Claude Opus 5.5 se muestra como claude-opus-5 y la solicitud real es el nuevo modelo. Los ajustes preestablecidos de DeepSeek Harness, Copilot CLI, Oh My Pi, MiniMax Code y Kimi Code generados utilizando estos ajustes preestablecidos se modifican juntos; Los proveedores ya agregados conservan sus nombres originales guardados.
  • Los proveedores con direcciones en formato api.commandcode.ai/providers se utilizan como cuota de consulta del paquete de código de comando (#9518).

Gracias a @Lawgk, @eDramas, @xinluke, @JImmyHui2017, @liuxixiang11, @WindowsXP-PLUS por informar problemas y proporcionar información de reproducción. cc-switch v4.0.33

Highlights

  • Claude Code 切换供应商 — 修复从第三方供应商切回 Claude 官方后，已打开的会话仍请求上一家的问题（#9247）。切换时先将被删除的地址、凭据和模型映射写成空值，约 10 秒后再从文件中删除，使会话的下一条请求立即生效。但 ANTHROPIC_MODEL 在会话启动时已固定，不会自动改变；若上一家配置过它，切回后需在模型菜单选择一次 Default 或新开会话。经常切换供应商的用户应优先升级。

  • 模型列表与协议兼容性 — Claude Code / Claude Desktop 使用 Gemini Native 格式时，模型列表不再误报「API Key 无效或无权限」；实际路由请求此前正常，本次只修列表获取。Pi、Oh My Pi、Kimi Code 的 Google 接口列表不再限制为 50 个模型；Cloudflare 后的服务商默认携带 User-Agent，自定义值仍优先。同时修复 Codex 转 Chat 格式时工具定义中的 required: null 被严格上游拒绝的问题。

  • 同步与 Skill 更新可靠性 — WebDAV 现在能兼容部分在目录已存在时仍返回 400 的 NAS；WebDAV / S3 上传失败会区分请求构造错误与发送错误，给出具体原因，并避免暴露密码和签名参数。关闭自动同步后，已排队的 S3 上传不会再执行。Skill 更新改为完整复制成功后才替换，失败会保留原版本，避免更新失败导致 Skill 丢失。使用 NAS、S3 或频繁更新 Skill 的用户值得升级。

  • 额度、账号与计价 — 新增 Ollama Cloud Token Plan 额度查询；新添加或导入的供应商默认启用，已有供应商需在卡片「配置用量查询」中选择 Token Plan 模板并保存。Windows 现已支持 Antigravity 账号切换、绑定和额度查看，Linux 仍不支持。xAI 查询遇到临时网络或服务错误时不再要求重新登录，并保留上次额度；非默认账号过期也不会再顶替默认账号。Antigravity Orchestrator 的 Hydrogen 步骤按 Gemini 4 Hydrogen 计价，近 30 天历史费用会补算，自定义价格仍优先。

  • 升级判断 — 未声明破坏性变更，也没有强制迁移步骤；可选功能除外，现有配置无需调整。另外修复了 macOS / Linux 冒号路径下的环境变量冲突处理、部分 Pi 预设的旧模型名，以及 api.commandcode.ai/providers 被误判为 Command Code 套餐的问题。命中上述问题的用户建议升级；完全未使用相关功能、且当前没有这些故障的用户可以跳过。

CC Switch v4.0.33

本版本修复了从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家、要重开会话才恢复的问题。套餐额度查询新增 Ollama Cloud；授权中心的 Antigravity 账号切换现在也支持 Windows。

另外修复了 Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时获取模型列表总报「API Key 无效或无权限」；部分服务商获取模型列表被 Cloudflare 拦下；Antigravity Orchestrator 仍有部分请求显示未定价；WebDAV 同步在一些 NAS 上完全用不了；WebDAV / S3 上传失败只显示「请求构造失败」；查询 xAI 额度时遇到网络抖动就被要求重新登录；更新 Skill 中途失败把原来的 Skill 删掉等问题。

新增

Ollama Cloud 套餐额度

地址是 ollama.com 的供应商现在可以查询 Token Plan 额度（需求见 #9382）：现行套餐显示本期套餐内额度的剩余比例和重置时间，旧版套餐显示 5 小时和每周两个窗口的剩余比例。单独购买的额度不显示；按量付费的账号没有套餐额度，会说明原因。本机运行的 Ollama（localhost:11434）没有套餐，不会被识别。

  • 新添加或一键导入的 Ollama Cloud 供应商默认开启额度查询；已有的供应商在卡片上点「配置用量查询」，Token Plan 模板会自动选好，打开「启用用量查询」后保存即可。

Windows 上切换 Antigravity 账号

授权中心的 Antigravity 账号切换以前只支持 macOS，现在 Windows 也能用：切换后 agy 读到的是新账号，Antigravity 官方卡可以绑定账号、查看所绑账号的额度，打开终端前也会提示将切换到哪个账号。Linux 暂不支持。

修复

  • 从第三方供应商切回 Claude 官方后，已经开着的 Claude Code 会话仍把请求发给上一家，要重开会话才恢复（#9247，见 #7808、#3057）：运行中的 Claude Code 只会读入 settings.json 里新增和改动的环境变量，被删掉的仍留在会话里。现在切换时先把要删的地址、凭据和模型映射写成空值，开着的会话下一条请求就不再用上一家，约 10 秒后再从文件里删掉。会话启动时就定下的主模型（ANTHROPIC_MODEL）不会跟着变：如果上一家设了它，切回后在模型菜单里选一次 Default，或者新开会话。
  • Claude Code / Claude Desktop 的供应商选 Gemini Native 格式时，「获取模型列表」总是报「API Key 无效或无权限」：现在按 Google 要求的方式传 Key。经路由的实际请求本来就正常，只有获取模型列表受影响。另外，Pi、Oh My Pi、Kimi Code 选 Google 接口的供应商，获取模型列表以前最多只列出 50 个，现在能列全。
  • 获取模型列表时，部分放在 Cloudflare 后面的服务商直接拒绝，被误报为「API Key 无效或无权限」（#7429，见 #7427）：请求现在默认带上 User-Agent；供应商或请求头里设了 User-Agent 的，仍以设置的为准。
  • Antigravity 选 Orchestrator 时，仍有部分请求显示未定价（#9542，见 #9493）：显示为「Gemini 4 Hydrogen (Orchestrator)」的步骤按 Gemini 4 Hydrogen 的价格计价，近 30 天内的历史也会补上费用。自定义价格仍然优先。
  • WebDAV 同步在部分 NAS 上完全用不了，测试连接、上传、下载都失败（#5623，见 #5621）：这些 NAS 在共享文件夹已存在时仍对「建目录」回 400，以前会直接中止，现在会再查一次目录是否存在。
  • WebDAV / S3 上传被服务器中途断开时，只显示「请求构造失败」（见 #9559）：现在分清是请求没构造出来还是发送时失败，并附上具体原因，方便判断是网络、TLS 还是服务器的问题。地址里的密码和签名参数不会出现在报错里。
  • S3 自动同步在关掉之后仍可能再上传一次（#9528）：另一次同步进行中时排队的自动上传，现在开始前会重新读取设置，期间关掉了自动同步或 S3 同步就不再上传。WebDAV 本来就是这样。
  • 查询 xAI 账号额度时，遇到网络抖动或 xAI 服务出错就提示需要重新登录（#9526，见 #9522）：只有登录真的失效才这样提示，临时错误照常报错并保留上次查到的额度，下次查询再试。
  • 一个非默认的 xAI 账号过期后，授权中心里选好的默认账号被换成了别的账号（#9548，见 #9543）。
  • 更新 Skill 时如果复制到一半失败，原来的 Skill 被删掉，列表里却仍显示已安装（见 #9521）：现在新版本完整复制好之后才替换，失败时保留原来的版本。
  • Codex 经路由转成 Chat 格式时，工具定义里的 required: null 被要求严格的上游拒绝（#7023，见 #7019）。
  • macOS / Linux 上 shell 配置文件的路径里带冒号时，「检测到系统环境变量冲突」删除或恢复变量会失败（#7170，见 #7169）。
  • PIPELLM、AICodeWith、E-FlowCode 的 Pi 预设在模型选择里显示成旧模型名（#9514）：比如 Claude Opus 5.5 显示成 claude-opus-5，实际请求的是新模型。用这几个预设生成的 DeepSeek Harness、Copilot CLI、Oh My Pi、MiniMax Code、Kimi Code 预设一起修正；已经添加的供应商保留原来保存的名字。
  • 地址形如 api.commandcode.ai/providers 的供应商被当成 Command Code 套餐查询额度（#9518）。

致谢

感谢 @funkpopo（切回 Claude 官方后开着的会话跟着切换，以及语言列表集中管理）、@ziyangxiami（Hydrogen Orchestrator 计价）、@SailingLoong（获取模型列表的 User-Agent）、@stofancy（WebDAV 兼容 NAS）、@HaiYangBG1（xAI 账号的两处修复、Skill 更新失败时保留原版本）、@GalaxyKW（Codex 工具定义的 required）、@cuishuang（环境变量路径里的冒号）、@SaladDay（Pi 预设模型名、Command Code 地址识别、S3 自动同步，以及 WebDAV 与 S3 同步代码合并、语言列表集中管理、前后端常量比对等内部整理）的贡献。

感谢 @Lawgk、@eDramas、@xinluke、@JImmyHui2017、@liuxixiang11、@WindowsXP-PLUS 报告问题和提供复现信息。
