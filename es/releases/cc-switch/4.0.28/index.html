Interruptor CC v4.0.28

Esta versión trata principalmente de la actualización incompatible del Codex del 8 de noviembre.

⚠️ **Codex versión de escritorio 26.1103, CLI 0.167 en adelante, la suscripción oficial y las sesiones de proveedores externos están completamente separadas. ** Cambie entre los dos en modo de conexión directa. Hasta ahora sólo se mostraban por separado las sesiones de ambos lados. Ahora la sesión del otro lado pasa directamente a ser de solo lectura: se puede ver pero no se puede continuar. Al continuar, aparecerá el mensaje "El proveedor del modelo no coincide". Para alternar y continuar con la sesión anterior, hay dos formas:

  1. Cambiar al modo de enrutamiento o agregación: a partir de esta versión, cambiar a un tercero en modo de enrutamiento o agregación mantendrá la sesión y la suscripción oficial en el mismo grupo, y podrá continuar alternando.
  2. Abra el "Historial de sesiones del Codex unificado" ("Configuración → Configuración de la aplicación → Codex"): las sesiones oficiales y de terceros se agrupan en el mismo grupo y puede alternar entre ellas en el modo de conexión directa. Además, cuando el interruptor de conexión directa haga que la sesión sea de solo lectura, se solicitará el número; Después de activar el "Historial de sesiones del Codex unificado" y comprobar la importación de sesiones existentes, se seguirán importando las sesiones oficiales. Cuando se agota la cuota oficial y Codex bloquea el botón de enviar, puede activar "Suspender el uso del inicio de sesión oficial" en la configuración de enrutamiento o agregación y continuar usando modelos de terceros; la protección de cuota oficial está activada de forma predeterminada. La instalación y las actualizaciones en la página de la aplicación muestran el estado de la cola y el progreso en tiempo real. Además, se han solucionado problemas como que Codex todavía lleva el nombre del modelo de la compañía anterior cuando conmuta por error a otra compañía, falla de compresión en Kimi For Coding y la sesión que siempre informa 400 después de continuar con la llamada de la herramienta en Kimi o DeepSeek. Agregar

Agrupación de conversaciones adaptada a la nueva versión del Codex

Codex registra las sesiones por ID de proveedor: las suscripciones oficiales se registran en el openai integrado, los proveedores externos escritos por CC Switch se registran en el custom. La nueva versión de Codex solo puede continuar sesiones con el mismo grupo que el proveedor actual y el otro grupo es de solo lectura (#7974). Esta versión ha realizado los siguientes cambios en torno a este punto:

  • Al cambiar a un tercero en modo de enrutamiento o agregación, las sesiones ya no se dividen en dos grupos: cuando la máquina inicia sesión en ChatGPT y el "Historial de sesiones de Unified Codex" no está activado, la ruta al tercero también se escribe como el openai integrado, como el oficial. La solicitud se envía al tercero mediante enrutamiento local como de costumbre y todas las sesiones están en el grupo openai. La clave de terceros se reemplaza por enrutamiento local, el ID de cuenta de ChatGPT, la organización y otros encabezados de solicitud se eliminarán y el tercero no podrá recibir la información de su cuenta.
    • Las siguientes situaciones todavía están escritas como custom: la máquina no tiene inicio de sesión ChatGPT, el historial de sesión unificado está activado, "Pausar inicio de sesión oficial" está activado o la configuración del proveedor tiene configuraciones como reintento de solicitud, reintento de transmisión, tiempo de espera de inactividad de transmisión y compresión remota que no se pueden expresar mediante el openai integrado.
    • Si ya estás usando el modo de enrutamiento, no necesitas hacer nada. CC Switch lo reescribirá automáticamente la próxima vez que se conecte al enrutador. El modo de conexión directa permanece sin cambios.
  • Después del cambio de conexión directa, se le indicará cuántas sesiones solo se pueden ver: cuando el historial de sesiones unificado no está activado, al cambiar entre la suscripción oficial y la de terceros en el modo de conexión directa, habrá una línea adicional en el mensaje para un cambio exitoso, como "Las 12 sesiones que anteriormente estaban bajo suscripción oficial solo se pueden ver ahora". No aparece el mensaje para cambiar de bandeja.
  • Historial de sesiones de Unified Codex ("Configuración → Configuración de la aplicación → Codex"): Después de activarlo, la suscripción oficial también usará el logotipo custom. Las sesiones de ambas partes están en el mismo grupo y pueden continuar en la nueva versión del Codex. Se recomienda activarlo cuando se cambia con frecuencia entre oficial y de terceros.
    • "Importar también el historial de conversaciones oficiales existentes" se cambió para que esté marcado de forma predeterminada. Después de verificar, cada vez que inicie CC Switch, se incorporarán las sesiones que aparecen en el grupo oficial, como apagar y encender el Switch, o usar Codex sin CC Switch.
    • Haga una copia de seguridad de la base de datos de la sesión del Codex antes de la migración y la restauración. Solía ​​tomar alrededor de 90 segundos hacer una copia de seguridad de una base de datos de 42 MB, pero ahora toma menos de 1 segundo.
    • Una vez completada la migración en segundo plano, se le preguntará cuántas sesiones se han migrado. Puede continuar después de reiniciar Codex.

Suspensión del inicio de sesión oficial (Codex)

Una vez que se agote la cuota oficial de ChatGPT, Codex verificará la cuota por sí mismo, bloqueará la selección del modelo y las claves de envío, y no podrá enviar modelos de terceros incluso si están seleccionados (#7974, #7962). Este paso no se puede gestionar mediante enrutamiento local en el cliente Codex; en el pasado, el método de cambiar manualmente requires_openai_auth a false se sobrescribirá una vez que se realice el cambio. Ahora las "Configuraciones de enrutamiento" y las "Configuraciones de agregación" del Codex (cuando el modo de enrutamiento o agregación está activo, el botón de engranaje en el extremo derecho de la barra de pestañas del modo) tienen un interruptor de "Pausar el inicio de sesión oficial" en la parte superior:

  • Después de la apertura, Codex ya no utilizará el inicio de sesión oficial y la clave de envío no se bloqueará debido a la cuota oficial. Se pueden seguir utilizando modelos de terceros en agregación y enrutamiento. El inicio de sesión oficial todavía está guardado en esta máquina y no se cerrará.
  • Durante la apertura, no se puede enviar el modelo oficial y se le pedirá que utilice un modelo de terceros; el Codex no muestra información de cuenta ni de uso, y puede aparecer un cuestionario para principiantes por primera vez; la sesión original en "Proyectos" en la barra lateral es temporalmente invisible y volverá después de apagar el interruptor; la nueva sesión se registra en el grupo custom y solo se puede ver después de volver al modelo oficial.
  • Siempre habrá un mensaje en la parte superior de la página del Codex durante el período de apertura. Una vez restaurada la cuota oficial, simplemente haga clic en "Restaurar inicio de sesión oficial".
  • Salga y vuelva a abrir completamente el Codex después de abrir y cerrar. Sólo tiene efecto en los modos de enrutamiento y agregación, las conexiones directas no se ven afectadas.

La página de la aplicación muestra el progreso de la instalación.

La instalación, actualización y desinstalación de las páginas de la aplicación solo se ejecutan una a la vez. Cuando era lento en el pasado, cada línea giraba en círculos y no estaba claro si se estaba descargando, en cola o atascada (el paquete de instalación de MiniMax Code pesa aproximadamente 100 MB y tomó más de diez minutos cuando la red era lenta). Ahora la línea en cola dirá "en cola, esperando a que se complete la aplicación anterior" y la línea en ejecución muestra el tiempo transcurrido y la última línea de salida del comando. Sal de la página de la aplicación y regresa, el progreso sigue ahí.

Cambiar

  • La protección de cuota oficial cambió a habilitada de forma predeterminada: las solicitudes oficiales del Codex enrutadas localmente se suspenderán cuando el uso de cinco horas alcance el 95 % o el uso semanal alcance el 98 %. Los modelos de terceros seguirán estando disponibles, lo que evitará el paso de que Codex bloquee la clave de envío. Se abrirá automáticamente una vez después de la actualización; después de eso, se cerrará manualmente y no se volverá a abrir. El umbral se puede cambiar en "Configuración → Configuración de la aplicación → Codex → ​​​​Protección de cuota oficial".
  • disable_response_storage ya no está escrito (#7524): la nueva versión de Codex ha eliminado esta configuración y mostrará un elemento de configuración no reconocido cada vez que se inicie. Ya no se escribirán ajustes preestablecidos, plantillas, proveedores unificados y enlaces de importación con un solo clic. Esta línea en config.toml se borrará la próxima vez que cambie.
  • Antigravity muestra la cuota semanal de Argón (#8913): La cuota semanal de Argón para el plan Pro no se mostraba anteriormente. Ahora está fusionado en la fila Gemini de la tarjeta y el menú desplegable y el centro de autorización se enumeran por separado.
  • Primer inicio más rápido en Windows: al crear una nueva base de datos, la creación de tablas y la escritura de precios de modelos integrados se combinan en un envío cada uno, y el primer inicio es aproximadamente 6 segundos más rápido.

Arreglar

  • Cuando Codex conmuta por error a otro proveedor, todavía lleva el nombre del modelo del proveedor anterior y el proveedor de respaldo informa que el modelo no existe (#7547). Cuando la conmutación por error está activada ahora, antes de cambiar al proveedor de respaldo, primero verificará si reconoce el modelo en la solicitud (es su propio modelo o está en su lista de modelos). Si no, cambiará a su propio modelo; la cola de transferencia del mismo modelo se enviará tal cual. La generación de imágenes, la edición de imágenes y las solicitudes de búsqueda no cambian de modelo.
  • El contexto de compresión Codex siempre falla (HTTP 400) cuando se conecta a Kimi For Coding mediante enrutamiento. Kimi no acepta tool_choice: "none" en la solicitud de compresión; ahora, cuando el flujo ascendente de respuestas nativas de terceros rechace la solicitud de compresión, eliminará tool_choice y volverá a intentarlo.
  • Después de que Codex continúe con la llamada de la herramienta en las respuestas nativas de Kimi o DeepSeek, se informarán 400 en cada ronda después de esta sesión. Con un mensaje de ayuda intercalado entre la llamada a la herramienta y su resultado, tanto Kimi como DeepSeek rechazan todo el historial; Kimi también rechaza los mensajes de ayuda vacíos. Ahora sólo las direcciones de Kimi (Moonshot) y DeepSeek están clasificadas para este tipo de historial, y otras solicitudes se emiten tal como están.
  • Cuando el directorio Codex en Windows está en WSL (\\wsl.localhost), el uso de la sesión bifurcada nunca se importa.

cc-switch v4.0.28

Highlights

  • Codex session groups now split by provider — The upstream Nov 8 Codex update (desktop 26.1103 / CLI 0.167) is the whole reason for this release: official ChatGPT sessions are keyed under built-in openai, CC Switch's third-party providers under custom, and new Codex only resumes sessions in the current provider's group. Switch providers in direct mode and the other group's sessions become read-only with a "model provider mismatch" error — no longer just displayed separately (#7974). Assume any direct-mode workflow that bounced between official and third-party is effectively broken until you opt into one of the two workarounds below.

  • Two ways to keep sessions resumable — Either move to route/aggregate mode, where third-party providers are written as openai and the local route injects the third-party key while stripping ChatGPT account/org headers (providers never see your identity), or enable "Unify Codex Session History" (Settings → App Config → Codex), which writes official sessions as custom too. Route-mode users need no action — CC Switch rewrites once on next attach. Watch out: custom is still written in route mode if you have no local ChatGPT login, have unification on, paused official login, or use retry/stream-idle/remote-compact settings the openai marker can't express.

  • Session-history migration is now default-on and dramatically faster — "Also migrate existing official sessions" is checked by default, and on every launch CC Switch re-imports official-group sessions that reappear (e.g. after toggling the switch or using Codex outside CC Switch). Pre-migration backup for a 42 MB DB dropped from ~90s to under 1s, so there's little reason to skip it. Restart Codex after the background migration finishes to regain resumability.

  • "Pause official login" escapes the locked-send-button trap — When ChatGPT quota runs out, Codex checks usage and locks model selection and the send button, and the old requires_openai_auth = false hack gets overwritten on every switch (#7974, #7962). A new toggle atop route/aggregate settings detaches official login (kept locally, not logged out) so third-party models keep working. Caveats: route/aggregate modes only, requires a full Codex restart on both enable and disable, blocks official models while active, hides account/usage, and new sessions land in custom (read-only once you switch back).

  • Quota protection on by default; stale disable_response_storage removed — Official requests routed locally now pause at 95% five-hour / 98% weekly usage so you never hit Codex's hard lock; it auto-enables once on upgrade but respects a later manual disable, with thresholds in Settings → App Config → Codex. Separately, disable_response_storage is no longer written because Codex removed it and warns on every start, and the line is scrubbed from existing config.toml on next switch (#7524) — minor, but a migration worth knowing about.

  • Upstream-facing fixes and install UX — Failover now checks that a backup provider actually recognizes the requested model and substitutes its own model instead of erroring "model not found" (#7547, borrowing from @SailingLoong's PR); Kimi For Coding compaction 400s are fixed by stripping tool_choice, and Kimi/DeepSeek tool-call continuation 400s by sanitizing the interleaved assistant message only for those providers. Also: Windows usage import from WSL (\\wsl.localhost) paths, ~6s faster first launch, Antigravity Argon weekly quota (#8913), and per-app install progress with queue status.

CC Switch v4.0.28

本版本主要应对 Codex 11 月 8 日的不兼容更新。

⚠️ Codex 桌面版 26.1103、CLI 0.167 起，官方订阅和第三方供应商的会话彻底分开了。 直连模式下在两者之间切换，以前只是两边的会话分开显示，现在另一边的会话直接变成只读：能查看，不能继续，继续时提示「模型提供商不匹配」。要来回切换并继续旧会话，有两个办法：

  1. 改用路由或聚合模式：本版本起，路由或聚合模式下切到第三方，会话和官方订阅留在同一组，来回切换都能继续。
  2. 打开「统一 Codex 会话历史」（「设置 → 应用配置 → Codex」）：官方和第三方的会话归到同一组，直连模式下也能来回切换。

此外，直连切换让会话变成只读时会提示数量；开启「统一 Codex 会话历史」并勾选迁入现有会话后，会持续把官方会话迁进来。官方额度用完、Codex 锁住发送键时，可以在路由或聚合设置里打开「暂停使用官方登录」，继续用第三方模型；官方额度保护改为默认开启。应用页的安装和升级会显示排队状态和实时进度。另外修复了 Codex 故障转移到别家时仍带着上一家的模型名、Kimi For Coding 上压缩失败、在 Kimi 或 DeepSeek 上续接工具调用后会话一直报 400 等问题。

新增

适配新版 Codex 的会话分组

Codex 按供应商标识记录会话：官方订阅记在内置的 openai 下，CC Switch 写入的第三方供应商记在 custom 下。新版 Codex 只能继续与当前供应商同一组的会话，另一组只读（#7974）。本版本围绕这一点做了以下改动：

  • 路由或聚合模式下切到第三方，会话不再分成两组：本机登录了 ChatGPT、且没有开「统一 Codex 会话历史」时，路由到第三方也和官方一样写成内置的 openai，请求照常经本地路由发往第三方，所有会话都在 openai 这一组。第三方的 Key 由本地路由替换，ChatGPT 的账号 ID、组织等请求头会被去掉，第三方收不到你的账号信息。
    • 以下情况仍写成 custom：本机没有 ChatGPT 登录、开着统一会话历史、打开了「暂停使用官方登录」，或者供应商配置里写了请求重试、流重试、流空闲超时、远程压缩这些内置 openai 表达不了的设置。
    • 已经在用路由模式的不用操作，CC Switch 下次接上路由时会自动改写一次。直连模式不变。
  • 直连切换后提示有多少会话只能查看：没开统一会话历史时，直连模式下在官方订阅和第三方之间切换，切换成功的提示里会多一行，例如「之前在官方订阅下的 12 个会话现在只能查看」。从托盘切换不提示。
  • 统一 Codex 会话历史（「设置 → 应用配置 → Codex」）：开启后官方订阅也改用 custom 标识，两边的会话在同一组，新版 Codex 里都能继续。经常在官方和第三方之间切换时建议开启。
    • 「同时迁入现有官方会话历史」改为默认勾选。勾选后，之后每次启动 CC Switch 都会把又出现在官方组的会话迁进来，比如关掉再打开过这个开关，或者不经 CC Switch 用过 Codex。
    • 迁移和还原前都要备份 Codex 的会话数据库，以前 42 MB 的数据库要备份约 90 秒，现在不到 1 秒。
    • 后台迁移完成后会提示迁入了多少个会话，重启 Codex 后就能继续。

暂停使用官方登录（Codex）

官方 ChatGPT 额度用完后，Codex 会自己查额度，锁住模型选择和发送键，选了第三方模型也发不出去（#7974、#7962）。这一步在 Codex 客户端里，本地路由管不到；以前手动把 requires_openai_auth 改成 false 的办法，现在切换一次就会被覆盖。

现在 Codex 的「路由设置」和「聚合设置」（路由或聚合模式生效时，模式标签栏右端的齿轮按钮）最上面多了「暂停使用官方登录」开关：

  • 打开后 Codex 不再使用官方登录，不会因为官方额度锁住发送键，聚合和路由里的第三方模型可以继续用。官方登录仍保存在本机，不会退出。
  • 打开期间，官方模型发不出去，会提示改用第三方模型；Codex 里不显示账号和用量信息，第一次打开可能弹出新手问卷；侧栏「项目」里原来的会话暂时看不到，关掉开关后会回来；新会话记在 custom 组，切回官方后只能查看。
  • 打开期间 Codex 页面顶部会一直有提示，官方额度恢复后点「恢复官方登录」即可。
  • 打开和关闭后都要彻底退出并重新打开 Codex。只在路由和聚合模式下生效，直连不受影响。

应用页显示安装进度

应用页的安装、升级和卸载一次只跑一个，以前慢的时候每一行都在转圈，分不清是在下载、在排队还是卡住了（MiniMax Code 的安装包约 100 MB，网络慢时要十几分钟）。现在排队的那一行会写「排队中，等前一个应用完成」，正在跑的那一行显示已用时间和命令输出的最新一行。离开应用页再回来，进度还在。

变更

  • 官方额度保护改为默认开启：经本地路由的 Codex 官方请求，在五小时使用率达到 95% 或每周使用率达到 98% 时就会暂停，第三方模型照常可用，避免走到 Codex 锁住发送键那一步。升级后会自动打开一次；之后手动关掉，不会再被打开。阈值在「设置 → 应用配置 → Codex → 官方额度保护」里改。
  • 不再写入 disable_response_storage（#7524）：新版 Codex 删掉了这个设置，每次启动都会提示有一个无法识别的配置项。预设、模板、统一供应商和一键导入链接都不再写它，已有 config.toml 里的这一行在下次切换时清掉。
  • Antigravity 显示 Argon 每周额度（#8913）：Pro 套餐的 Argon 每周额度以前不显示。现在卡片上把它并进 Gemini 那一行，下拉菜单和授权中心单独列出。
  • Windows 上第一次启动更快：新建数据库时建表和写入内置模型价格各合成一次提交，第一次启动快了约 6 秒。

修复

  • Codex 故障转移到别家时，仍带着上一家的模型名，备用供应商报模型不存在（#7547）。现在开着故障转移时，换到备用供应商前会先看它认不认请求里的模型（是它自己的模型，或在它的模型列表里），不认就换成它自己的模型；同一个模型的中转队列照原样发。图片生成、图片编辑和搜索请求不换模型。
  • Codex 经路由连 Kimi For Coding 时，压缩上下文总是失败（HTTP 400）。Kimi 不接受压缩请求里的 tool_choice: "none"；现在第三方原生 Responses 上游拒绝压缩请求时，会去掉 tool_choice 再试一次。
  • Codex 在 Kimi 或 DeepSeek 的原生 Responses 上续接工具调用后，这个会话之后每一轮都报 400。工具调用和它的结果之间夹了一条助手消息，Kimi 和 DeepSeek 都会拒绝整段历史；Kimi 还会拒绝空的助手消息。现在只对 Kimi（Moonshot）和 DeepSeek 的地址整理这类历史，其他请求原样发出。
  • Windows 上 Codex 目录在 WSL 里（\\wsl.localhost）时，分叉出来的会话用量一直不导入。
