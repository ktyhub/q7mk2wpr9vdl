Interruptor CC v4.0.37

Esta versión es principalmente para reparaciones. Las entradas ilegibles de proveedores y MCP (como las escritas por versiones actualizadas y sincronizadas a través de WebDAV/S3) ya no se tratan como configuraciones vacías y se sobrescriben con los valores predeterminados la próxima vez que se guarden, sino que se enumeran por separado y se pueden eliminar; Pi ha agregado ajustes preestablecidos Mistral AI; La traducción de la interfaz coreana se ha mejorado en general. Además, se ha solucionado el problema de que la dirección de escucha del enrutamiento local no se puede iniciar cuando se completa IPv6; "Aplicar al complemento Claude Code" borrará todo el ~/.claude/config.json dañado; cuando la velocidad de la red es lenta, la descarga de un gran almacén de habilidades se interrumpe a la mitad; al abrir CC Switch desde Finder, la detección del directorio del modelo Codex no puede encontrar el Nodo; _ en los parámetros de llamada de la herramienta Los campos principales se eliminan antes de enviarse al flujo ascendente; los proveedores que se eliminan y se vuelven a agregar a la cola de conmutación por error aún se omiten; el botón "Reintentar" en la página del complemento parece no responder y hay otros problemas. Agregar

Pi agrega el ajuste preestablecido de Mistral AI

Pi ha agregado un nuevo ajuste preestablecido de Mistral AI, que utiliza el propio protocolo Mistral de Pi (mistral-conversations), y el contenido de pensamiento en streaming no se perderá (para conocer los requisitos, consulte #9343, #9344).

  • Viene con Mistral Large 4 y Mistral Small 4, el equipo de pensamiento es consistente con el directorio Mistral incorporado del Pi.
  • El nombre del proveedor es cc-switch-mistral, lo que no oculta el mistral integrado en el Pi.
  • mistral-conversations también se puede seleccionar en la lista de protocolos del formulario Pi. Oh My Pi y Kimi Code no admiten este protocolo y no muestran este valor predeterminado.

Cambiar

  • Las entradas de proveedor y MCP que no se pueden leer se conservan tal como están y se pueden eliminar individualmente (#9767): en el pasado, cuando los datos no se podían leer, se consideraban una configuración vacía. El valor predeterminado se volverá a escribir la próxima vez que se guarde y los datos originales se perderán. Ahora dichas entradas se enumeran por separado en la página del proveedor y en la página de MCP, lo que muestra el motivo por el cual no se pueden leer, editar ni habilitar. Se pueden eliminar (solo se eliminan los registros en CC Switch y no se tocan los archivos de configuración de cada aplicación); otras entradas se muestran y utilizan como de costumbre y la conmutación por error las omite; la operación para cambiar éste será rechazada. Cuando existen tales entradas, las aplicaciones acumulativas (como OpenCode) también informarán un error al sincronizar todos los proveedores con el archivo de configuración. Puede restaurarlo después de actualizar a una versión legible.
  • La marca 1M de Claude Code se reescribe a minúsculas [1m] (ver #9757): consistente con la escritura de documentos de Claude Code. Originalmente, Claude Code no distingue entre mayúsculas y minúsculas y el [1M] existente aún se puede usar.
  • Mejoras en la traducción de la interfaz coreana (#9395, #9349).
  • La fila de la cuenta en el centro de autorización es más legible (#9369): "N proveedores la están usando" en una fila separada y la columna del nombre de la cuota se establece según el nombre más largo. Cuando la ventana es estrecha, el paquete, el nombre de dominio y la fecha de inicio de sesión ya no están comprimidos en elipses; el porcentaje también se puede ver en traducciones más largas como las del alemán y el ruso.

Arreglar

  • No se puede iniciar cuando la dirección de escucha de la ruta local está llena con IPv6 (como ::1) (ver #9743): antes se informaba "sintaxis de dirección de socket no válida", pero ahora se puede monitorear normalmente.
  • Después de activar "Aplicar al complemento Claude Code", el ~/.claude/config.json dañado se borrará (consulte #9744): cuando el archivo no es un JSON legal, se sobrescribirá como un archivo vacío y se perderán otras configuraciones. Ahora se informará un error y se señalará la ruta del archivo, y el archivo permanecerá sin cambios; La escritura también se ha cambiado para escribir primero un archivo temporal y luego reemplazarlo, de modo que la mitad del archivo no quede cuando se interrumpa a mitad de camino.
  • Los repositorios de habilidades grandes se interrumpen durante la descarga en conexiones lentas: las habilidades de instalación, actualización, búsqueda de actualizaciones y descubrimiento anteriormente limitaban la descarga completa a 60 segundos. Ahora solo se detendrá si no se pueden recibir datos durante 60 segundos consecutivos y mostrará el mensaje "No se recibieron datos"; la descarga completa puede tardar hasta 10 minutos.
  • Al abrir CC Switch desde Finder, la detección del directorio del modelo Codex no puede encontrar el nodo (consulte #9764): Codex instalado con npm, por lo tanto, no se ejecuta y CC Switch recurre a CLI, que viene con la versión de escritorio de Codex y puede ser anterior. El modelo GPT en modo agregación carece de información oficial (como herramientas de búsqueda). Las sondas ahora incluyen la RUTA del shell de inicio de sesión, al igual que CC Switch cuando se ejecutan otras herramientas de línea de comandos.
  • Los campos que comienzan con _ en los parámetros de llamada de la herramienta se eliminan antes de enviarse al nivel superior (#9753): campos como _id, _meta y __typename se usan comúnmente en herramientas MCP, bases de datos y GraphQL. En el pasado, se eliminaban como campos privados. La llamada vista por el modelo es diferente de la ejecución real. Los proveedores estrictos podrán rechazar directamente la solicitud. Los parámetros de llamada de herramienta ahora se dejan intactos.
  • Para los proveedores que se eliminan de la cola de conmutación por error y luego se devuelven, la tarjeta se muestra normalmente, pero aún así se omitirá durante un período de tiempo (#9750): cuando se elimina de la cola o se sale de la ruta de una aplicación, el estado del disyuntor en ejecución ahora se borrará al mismo tiempo. Al abrir OMO/OMO Slim, el archivo de configuración de otra variante no se pudo eliminar y ahora también aparecerá por separado.
  • Parece que no responde al hacer clic en "Reintentar" después de que se agota el tiempo de carga de la página del complemento (consulte #9758): Las pestañas instaladas, descubiertas y comercializadas mostrarán la carga al volver a intentarlo.
  • Varios problemas con la página del complemento (#9742): al cambiar a otras aplicaciones y luego regresar, la operación en curso aún muestra un círculo; se habilita nuevamente durante el complemento de actualización del Codex y no se desactivará una vez completada la actualización; la búsqueda también puede buscar por nombre para mostrar (paquetes Pi instalados a través de git o el directorio local); después de desinstalar la versión fija del paquete Pi y luego instalarlo desde "Discover", ya no permanece en "Discover"; Windows está instalado en Complementos en WSL y ahora muestra la versión, el nombre y la descripción.
  • Uso de memoria y recursos (#9773): libera imágenes almacenadas en caché al salir del lector de sesión; liberar los paquetes de instalación descargados al desactivar las actualizaciones automáticas; algunas solicitudes de red reutilizan conexiones HTTP y ya no crean nuevas cada vez; el límite superior del cuerpo de la solicitud (incluida la descompresión) recibido por el enrutamiento local es 200 MiB, y se devolverán 413 si se excede.
  • Después de instalar o actualizar la herramienta de línea de comandos, la operación posterior ocasionalmente indica "en progreso" (#9775).

cc-switch v4.0.37

Highlights

  • Unreadable entries are quarantined instead of overwritten — Providers and MCP entries that cannot be parsed now appear separately with an error reason and remain non-editable and disabled; failover skips them. Deleting one removes only its CC Switch record, not the application’s configuration. While such entries exist, changes to them are rejected and incremental all-provider syncs—such as OpenCode’s—fail rather than silently replacing data. Upgrade to a compatible reader to restore them (#9767).
  • Claude Code plugin configuration writes are now fail-safe — Invalid ~/.claude/config.json produces an error identifying the path and leaves the file untouched, instead of treating it as empty and erasing unrelated settings. Writes use a temporary file followed by replacement, preventing interrupted writes from leaving truncated JSON. Repair any invalid configuration before applying plugin changes (#9744).
  • Tool arguments retain underscore-prefixed fields — Fields such as _id, _meta, and __typename are no longer stripped before requests reach upstream providers. This keeps the model’s requested call aligned with actual MCP, database, or GraphQL execution and avoids rejections from strict providers (#9753).
  • Pi gains a native Mistral AI preset — cc-switch-mistral uses Pi’s mistral-conversations protocol, includes Mistral Large 4 and Small 4, and preserves streamed reasoning without colliding with Pi’s built-in mistral provider. The preset is intentionally unavailable for Oh My Pi and Kimi Code, which do not support that protocol (#9344).
  • Transfer timeouts and request limits are more explicit — Skill downloads now time out after 60 seconds without incoming data rather than after 60 seconds total, with a 10-minute overall cap, reducing failures on slow connections. Local routing rejects request bodies—including decompressed bodies—above 200 MiB with HTTP 413, so integrations proxying unusually large payloads may need streaming or chunking (#9773).
  • Compatibility — No breaking changes in this release.

CC Switch v4.0.37

本版本以修复为主。读不出来的供应商和 MCP 条目（比如由更新版本写入、经 WebDAV / S3 同步过来的）不再被当成空配置、下次保存时被默认值覆盖，而是单独列出来，可以删除；Pi 新增 Mistral AI 预设；韩语界面翻译整体改进。

另外修复了本地路由监听地址填 IPv6 时启动不了；「应用到 Claude Code 插件」会把损坏的 ~/.claude/config.json 整个清空；网速慢时大的技能仓库下载到一半被中断；从访达打开 CC Switch 时 Codex 模型目录探测找不到 Node；工具调用参数里 _ 开头的字段被删掉后才发给上游；移出又加回故障转移队列的供应商仍被跳过；插件页点「重试」看起来没反应等问题。

新增

Pi 新增 Mistral AI 预设

Pi 新增 Mistral AI 预设，走 Pi 自己的 Mistral 协议（mistral-conversations），流式的思考内容不会丢（需求见 #9343，#9344）。

  • 自带 Mistral Large 4 和 Mistral Small 4，思考档位与 Pi 内置的 Mistral 目录一致。
  • 供应商名为 cc-switch-mistral，不会遮住 Pi 内置的 mistral。
  • Pi 表单的协议列表里也可以选 mistral-conversations。Oh My Pi 和 Kimi Code 不支持这个协议，不显示这个预设。

变更

  • 读不出来的供应商和 MCP 条目原样保留，可以单独删除（#9767）：以前数据读不出来时会被当成空配置，下次保存就把默认值写回去，原来的数据丢了。现在这样的条目在供应商页和 MCP 页单独列出，显示读不出来的原因，不能编辑或启用，可以删除（只删 CC Switch 里的记录，不动各应用的配置文件）；其他条目照常显示和使用，故障转移跳过它；改这一条的操作会被拒绝，有这样的条目时，累加式应用（如 OpenCode）把全部供应商同步到配置文件也会报错。升级到能读的版本后即可恢复。
  • Claude Code 的 1M 标记改写成小写 [1m]（见 #9757）：和 Claude Code 文档写法一致。Claude Code 本来不区分大小写，已有的 [1M] 照常可用。
  • 韩语界面翻译改进（#9395，#9349）。
  • 授权中心的账号行更好读（#9369）：「N 个供应商在用」单独一行，额度名称列按最长的名称定宽，窗口窄时套餐、域名和登录日期不再被挤成省略号；德语、俄语等较长的翻译也能看到百分比。

修复

  • 本地路由的监听地址填 IPv6（如 ::1）时启动不了（见 #9743）：以前会报「invalid socket address syntax」，现在可以正常监听。
  • 开了「应用到 Claude Code 插件」后，损坏的 ~/.claude/config.json 会被清空（见 #9744）：文件不是合法 JSON 时，以前当成空文件重写，里面的其他设置都丢了。现在会报错并指出文件路径，文件原样不动；写入也改成先写临时文件再替换，中途中断不会留下半截文件。
  • 网速慢时，大的技能仓库下载到一半被中断：安装、更新、检查更新和发现技能以前都限制整个下载 60 秒。现在只有连续 60 秒收不到数据才中止，并提示「没有收到数据」；整个下载最长 10 分钟。
  • 从访达打开 CC Switch 时，Codex 模型目录探测找不到 Node（见 #9764）：用 npm 装的 Codex 因此运行失败，CC Switch 退回用 Codex 桌面版自带、可能较旧的 CLI，聚合模式下的 GPT 模型少了官方信息（比如搜索工具）。现在探测时带上登录 shell 的 PATH，和 CC Switch 运行其他命令行工具时一样。
  • 工具调用参数里 _ 开头的字段被删掉后才发给上游（#9753）：MCP、数据库、GraphQL 类工具常用 _id、_meta、__typename 这类字段，以前会被当成私有字段删掉，模型看到的调用和实际执行的不一样，严格的供应商可能直接拒绝请求。现在工具调用参数原样保留。
  • 从故障转移队列移出再加回的供应商，卡片显示正常但仍会被跳过一段时间（#9750）：移出队列或退出某个应用的路由时，现在会同时清掉运行中的熔断状态。开启 OMO / OMO Slim 时没能删掉另一个变体的配置文件，现在也会单独提示。
  • 插件页加载超时后点「重试」看起来没反应（见 #9758）：已安装、发现和市场三个页签在重试时都会显示加载中。
  • 插件页的几处问题（#9742）：切到别的应用再切回来，进行中的操作仍显示转圈；Codex 更新插件期间又把它启用，更新结束后不会再被停用；搜索也能按显示名搜到（Pi 通过 git 或本地目录安装的包）；卸掉固定版本的 Pi 包、再从「发现」安装后，它不再留在「发现」里；Windows 上装在 WSL 里的插件现在能显示版本、名称和描述。
  • 内存和资源占用（#9773）：离开会话阅读器时释放缓存的图片；关闭自动更新时释放已下载的安装包；部分网络请求复用 HTTP 连接，不再每次新建；本地路由收到的请求体（含解压后）上限为 200 MiB，超过返回 413。
  • 安装或升级命令行工具后，紧接着的操作偶尔提示「正在进行中」（#9775）。

致谢

感谢 @SaladDay（读不出来的条目原样保留、熔断状态清理、工具锁释放顺序、清理无用代码）、@vastStage（工具调用参数保留 _ 字段）、@funkpopo（插件页修复、授权中心账号行）、@alterxyz（Pi 的 Mistral AI 预设）、@Owlbay（内存和资源占用）、@allenxu09（授权中心账号行）、@cuiyf5516（韩语翻译）的贡献。

感谢 @vastStage、@xxy9468615、@tanghululalala、@JohnZhong505 报告问题和提供复现信息。
