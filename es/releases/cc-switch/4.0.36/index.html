interruptor cc v4.0.36

Interruptor CC v4.0.36

Esta versión agrega una página de complementos, que le permite instalar, habilitar, actualizar y desinstalar complementos para Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw y Pi en CC Switch, y administrar el mercado de complementos para Claude Code, Codex y Grok Build. Los almacenes de habilidades ahora pueden leer almacenes privados con tokens de acceso; los proveedores encaminados localmente pueden establecer multiplicadores de tarifas; y los capítulos del escritorio de Claude Code se pueden ver en la gestión de sesiones. Además, hemos solucionado problemas como el bloqueo de la aprobación automática después de que el Codex abre la protección oficial de cuotas; los modelos oficiales recién lanzados en modo de agregación Codex tardan mucho en aparecer; el uso de sesiones 1.x ya no se cuenta después de que OpenCode se actualiza a 2.x; la fecha personalizada en la página de uso cambia a 1905 tan pronto como se ingresa el año; Varios modelos de Antigravity se muestran sin precio y otros problemas. Los niveles de inferencia con el mismo precio en las estadísticas de uso ahora se combinan en una fila. Inglés → | Versión japonesa →

Agregar

Página de complemento

Agregue "complementos" a la barra lateral y administre los complementos a través de la propia línea de comando de cada aplicación (para conocer los requisitos, consulte #791, #9220):

  • Admite Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, Pi y solo enumera aplicaciones no ocultas.
  • Puede habilitar, deshabilitar, actualizar (el código MiniMax no se puede actualizar) y desinstalar en "Instalado"; buscar e instalar en "Descubrir"; Claude Code, Codex y Grok Build también pueden agregar, actualizar y eliminar el mercado de complementos en el "Mercado". La dirección puede ser owner/repo de GitHub, dirección Git o carpeta local. Los complementos para Pi provienen del paquete Pi en npm.
  • Antes de la instalación, Grok Build, OpenClaw y Pi confirmarán que los complementos se ejecutan con sus permisos y solo instalarán aquellos de fuentes confiables. Para los complementos en Claude Code que requieren consentimiento en el terminal, CC Switch no lo aceptará y le solicitará que ejecute el comando de instalación correspondiente en el terminal; las aplicaciones que requieren iniciar sesión primero también solicitarán comandos de inicio de sesión.
  • Codex desactiva el complemento y solo cambia el enabled del complemento en config.toml, dejando el resto del contenido y comentarios sin cambios.
  • La descarga de un almacén de mercado grande puede tardar varios minutos. Puede cerrar el cuadro de diálogo primero y se le avisará cuando se complete.

El almacén de habilidades apoya a los almacenes privados

En el "Almacén de habilidades de gestión", puede configurar tokens de acceso por sitio. Los almacenes privados en GitHub, GitLab y Gitea/Forgejo pueden buscar, instalar y buscar actualizaciones (para conocer los requisitos, consulte #9666).

  • Los tokens se guardan por sitio (como github.com, gitlab.example.com), se almacenan en el almacenamiento de credenciales del sistema (llavero de macOS, Administrador de credenciales de Windows, otros sistemas son archivos que solo la máquina local puede leer) y no se sincronizan con la nube. Sólo se requiere permiso de solo lectura.
  • Cuando la descarga falla, se distinguirá si el token no está configurado o el token es rechazado (no válido, vencido o no autorizado para leer este almacén).

Ratio de gastos de proveedores

Cuando las transferencias se facturan en función de descuentos, los costos en las estadísticas de uso se pueden estimar en función de múltiplos (#9656). Se ha agregado un nuevo "multiplicador de costos de proveedor" a los formularios de proveedores no oficiales de Claude Code, Codex, Gemini CLI y Grok Build: los precios de referencia de todos los modelos de esta empresa se multiplican por él, 0.5 es la mitad de precio y dejar en blanco es 1 veces.

  • Sólo tiene efecto para solicitudes enrutadas localmente y configuradas después de la configuración; el uso importado de registros de sesión durante la conexión directa todavía se cuenta como 1x.

Mostrar los capítulos de la versión de escritorio de Claude Code en la gestión de sesiones

Los capítulos asignados a los diálogos por modelos en la versión de escritorio de Claude Code se mostraban anteriormente como llamadas a herramientas MCP ordinarias (consulte #9728, #9729 para conocer los requisitos). Ahora se muestra como una fila de capítulo, que se puede ver incluso cuando la línea de tiempo está cerrada; los capítulos se enumerarán en el directorio de conversaciones y saltarán cuando se haga clic en ellos; Los capítulos se pueden encontrar mediante búsqueda y los capítulos se convertirán en títulos al exportarlos a Markdown.

Cambiar

  • Las estadísticas de uso fusionan engranajes de inferencia con el mismo precio (#8845, consulte #9065): Diferentes fortalezas de inferencia del mismo modelo, si los cuatro precios de entrada, salida, lectura de caché y escritura de caché son los mismos que los del modelo básico, y el modelo básico tiene precios precisos, se fusionarán en la fila del modelo básico. El filtrado, el resumen diario y el tiempo de la primera palabra se calculan de acuerdo con la fusión, y el nombre del modelo original aún se muestra en el registro de solicitudes.

Arreglar

  • Después de que Codex activó la "Protección de cuota oficial", la aprobación automática se bloqueó cuando se alcanzó el umbral (#9733, consulte #9732): OpenAI ha hecho que el modelo de aprobación automática de Codex, codex-auto-review, sea gratuito y no esté incluido en la cuota del paquete. Ahora la protección de cuotas lo permite directamente, y otros modelos oficiales quedan suspendidos como viene siendo habitual.
  • En el modo de agregación de Codex, los modelos oficiales recién lanzados (como GPT-6.2) tardan mucho en aparecer: en el modo de agregación, Codex solo lee el directorio de modelos escrito por CC Switch. El caché de la lista oficial de modelos se ha reducido de 6 horas a 1 hora; la versión del Codex al obtener la lista también hará referencia al CLI que viene con la versión de escritorio y la versión registrada por el propio Codex. Una vez que la versión de escritorio se actualice automáticamente, ya no aparecerá una lista más corta basada en la versión anterior.
  • Después de actualizar OpenCode a 2.x, las sesiones creadas o continuadas en 1.x no se contarán en el uso (#8363, consulte #8361): cuando los conjuntos de datos antiguos y nuevos coexisten, ambos conjuntos ahora se leen y el mismo mensaje solo se cuenta una vez. Las bases de datos analizadas previamente continúan desde la última exploración y no reponen los registros anteriores.
  • Al ingresar manualmente el año en la fecha personalizada en la página de uso, se convierte en 1905 (consulte #9699): ahora la fecha completa entrará en vigencia y no se sobrescribirá durante el proceso de ingreso.
  • Varios modelos de Antigravity muestran "sin precio" en las estadísticas de uso: la versión escalonada de Gemini Flash (como gemini-3.8-flash-tiered para el subagente de navegador integrado) se factura al precio base de Flash (#9600); La versión escalonada de Hydrogen se factura al precio base (#9706, consulte #9705); el paso de ejecución cuando se utiliza Orchestrator se devuelve a Gemini 4 Hydrogen (#9686, consulte #9685), el paso de planificación se devuelve a Gemini 4 Neon y se agrega su precio (#8845); La versión Thinking de Claude (como Claude Opus 4.6 (Thinking)) se factura según el modelo base correspondiente. Los registros existentes sin precio se compensarán automáticamente.
  • La lista de modelos en el modo de enrutamiento de Claude Desktop se deja en blanco y se usa el nombre del modelo Claude predeterminado en lugar del modelo del proveedor (consulte #9735): el modo de enrutamiento es originalmente así, y el mensaje del formulario ahora está claramente escrito: si lo deja en blanco en conexión directa, se leerá automáticamente /v1/models. Para utilizar el modelo del proveedor en el modo de ruta, complete la lista de modelos.
  • El MCP en el nivel de inicio cordis.patch.yml de DeepSeek Harness no se puede ver en CC Switch y no hay explicación (consulte #9714): CC Switch solo lee y escribe archivos de cada perfil. El cuadro de diálogo de importación de MCP ahora indica que los archivos de nivel de inicio no se leen ni se escriben, y que el MCP que contienen se debe administrar allí.

cc-switch v4.0.36

Highlights

  • Plugins move into the sidebar — A new Plugins page manages Claude Code, Codex, Grok Build, MiniMax Code, OpenClaw, and Pi by driving each app's own CLI rather than reimplementing plugin logic (#791, #9220). For adopters: install/update/uninstall plus marketplace add/refresh/remove for the first three; Pi installs come from npm; MiniMax Code cannot be updated. It is deliberately not hands-off — Grok/OpenClaw/Pi prompt before install because plugins run with your privileges, Claude Code plugins needing terminal consent are handed back to you, and login-required apps surface the login command. Two details worth knowing: disabling a Codex plugin only flips its enabled flag in config.toml and leaves all other content and comments intact (safe for config management), and large marketplace clones can take minutes, with a notification on completion.

  • Private skill repos unblocked via per-site tokens — Skill repositories now accept access tokens to browse, install, and check updates on private GitHub, GitLab, and Gitea/Forgejo repos (#9666). Tokens are scoped per host (github.com, gitlab.example.com), need only read access, and live in the OS credential store (Keychain, Windows Credential Manager, or a local user-readable file elsewhere) — critically, they do not cloud-sync, so each machine must be configured separately. Download failures now distinguish "no token set" from "token rejected" (invalid/expired/no access), turning an opaque 404 into an actionable error.

  • Cost reporting: multiplier in, tier granularity out — Non-official provider forms for Claude Code, Codex, Gemini CLI, and Grok Build gain a "provider cost multiplier" (#9656): 0.5 halves reference prices, blank means 1×, useful when a reseller bills at a discount. Scope matters — it applies only to requests routed through the local proxy after you set it; imported/direct sessions still count at 1×, so historical spend is not retroactively discounted. Separately, reasoning tiers sharing all four prices (input/output/cache read/cache write) with an exactly-priced base model now collapse into that base row (#8845, #9065); filters, daily totals, and first-token timings use the merged data while request logs keep the original model name — fewer rows, not lost detail. Antigravity pricing gaps also close (Flash/Hydrogen tiered, Orchestrator execution→Hydrogen and planning→Neon with a new price, Claude Thinking→base) with existing unpriced records recalculated (#9600, #9706, #9685, #8845) — so past spend figures may rise.

  • Usage fixes for mixed or upgraded installs — OpenCode 2.x users with leftover 1.x sessions now count usage from both databases with per-message dedup (#8363, #8361); note that previously scanned DBs resume from the last scan and older messages are not backfilled. With Codex "official quota protection" on, the now-free codex-auto-review model bypasses the pause (#9733, #9732) while other official models still pause. In Codex aggregation mode the official-model cache drops from 6h to 1h and version detection now consults the bundled/desktop CLI, so newly released models (e.g. GPT-6.2) stop lagging behind auto-updates.

  • Claude Code Desktop chapters become first-class — Model-generated chapter markers, previously rendered as generic MCP tool calls, now appear as chapter rows (#9728, #9729): visible even with the timeline collapsed, listed in the session directory with click-to-jump, searchable, and exported as Markdown headings. A small but real quality-of-life win for navigating long Desktop sessions.

  • Breaking changes — None; no migration steps required.

CC Switch v4.0.36

本版本新增插件页面，可以在 CC Switch 里安装、启用、更新、卸载 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi 的插件，并管理 Claude Code、Codex、Grok Build 的插件市场。技能仓库现在可以用访问令牌读取私有仓库；经本地路由的供应商可以设置费用倍率；会话管理里能看到 Claude Code 桌面版的章节。

另外修复了 Codex 开了官方额度保护后自动审批也被拦下；Codex 聚合模式下新发布的官方模型要很久才出现；OpenCode 升级到 2.x 后 1.x 会话的用量不再统计；用量页自定义日期一输入年份就变成 1905；Antigravity 多个模型显示未定价等问题。用量统计里价格相同的推理档位现在合并成一行。

新增

插件页面

侧栏新增「插件」，通过各应用自己的命令行管理插件（需求见 #791，#9220）：

  • 支持 Claude Code、Codex、Grok Build、MiniMax Code、OpenClaw、Pi，只列出没有隐藏的应用。
  • 「已安装」里可以启用、停用、更新（MiniMax Code 不能更新）、卸载；「发现」里搜索并安装；Claude Code、Codex、Grok Build 还可以在「市场」里添加、刷新、移除插件市场，地址可以是 GitHub 的 owner/repo、Git 地址或本地文件夹。Pi 的插件来自 npm 上的 Pi 包。
  • Grok Build、OpenClaw、Pi 安装前会先确认：插件以你的权限运行，只装来源可信的。Claude Code 里要在终端同意的插件，CC Switch 不替你同意，会提示到终端运行对应的安装命令；需要先登录的应用也会提示登录命令。
  • Codex 停用插件只改 config.toml 里这个插件的 enabled，其余内容和注释不动。
  • 大的市场仓库下载可能要几分钟，可以先关掉对话框，完成后会提示。

技能仓库支持私有仓库

「管理技能仓库」里可以按站点设置访问令牌，GitHub、GitLab、Gitea / Forgejo 上的私有仓库都能浏览、安装和检查更新（需求见 #9666）。

  • 令牌按站点保存（如 github.com、gitlab.example.com），存在系统的凭据存储里（macOS 钥匙串、Windows 凭据管理器，其他系统是本机仅自己可读的文件），不随云同步。只需要只读权限。
  • 下载失败时会区分是没设令牌，还是令牌被拒（无效、过期或无权读取这个仓库）。

供应商费用倍率

中转按折扣计费时，用量统计里的花费可以按倍率估算（#9656）。Claude Code、Codex、Gemini CLI、Grok Build 的非官方供应商表单里新增「供应商费用倍率」：这家所有模型的参考价都乘以它，0.5 即半价，留空为 1 倍。

  • 只对经本地路由、并且设置之后的请求生效；直连时从会话记录导入的用量仍按 1 倍统计。

会话管理里显示 Claude Code 桌面版的章节

Claude Code 桌面版里模型给对话打的章节，以前显示成普通的 MCP 工具调用（需求见 #9728，#9729）。现在显示成章节行，收起时间线也能看到；对话目录里会列出章节，点击即跳转；查找能搜到章节，导出 Markdown 时章节变成标题。

变更

  • 用量统计合并价格相同的推理档位（#8845，见 #9065）：同一个模型的不同推理强度，如果输入、输出、缓存读、缓存写四种价格都和基础模型相同，并且基础模型有精确价格，就合并到基础模型那一行。筛选、每日汇总和首字时间都按合并后统计，请求日志里仍显示原始模型名。

修复

  • Codex 开了「官方额度保护」后，达到阈值时自动审批也被拦下（#9733，见 #9732）：OpenAI 已经让 Codex 的自动审批模型 codex-auto-review 免费、不计入套餐额度，现在额度保护对它直接放行，其他官方模型照常暂停。
  • Codex 聚合模式下，新发布的官方模型（如 GPT-6.2）要很久才出现：聚合模式下 Codex 只读 CC Switch 写的模型目录。官方模型列表的缓存从 6 小时缩短到 1 小时；获取列表时报的 Codex 版本也会参考桌面版自带的 CLI 和 Codex 自己记录的版本，桌面版自动更新后不会再按旧版本拿到少一截的列表。
  • OpenCode 升级到 2.x 后，之后在 1.x 里新建或继续的会话不计入用量（#8363，见 #8361）：新旧两套数据并存时现在两套都读，同一条消息只算一次。以前扫描过的数据库从上次扫描处继续，不回补更早的记录。
  • 用量页自定义日期手动输入年份时，一输入就变成 1905（见 #9699）：现在输入完整的日期才生效，输入过程中不会被改写。
  • Antigravity 多个模型在用量统计里显示「未定价」：Gemini Flash 的 tiered 版本（如内置浏览器子代理用的 gemini-3.8-flash-tiered）按 Flash 基础价计费（#9600）；Hydrogen 的 tiered 版本按基础价计费（#9706，见 #9705）；用 Orchestrator 时的执行步归到 Gemini 4 Hydrogen（#9686，见 #9685），规划步归到 Gemini 4 Neon 并新增它的价格（#8845）；Claude 的 Thinking 版本（如 Claude Opus 4.6 (Thinking)）按对应的基础模型计费。已有的未定价记录会自动补算。
  • Claude Desktop 路由模式下模型列表留空，用的是默认的 Claude 模型名而不是供应商的模型（见 #9735）：路由模式本来如此，表单提示现在写清楚了：直连时留空会自动读取 /v1/models，路由模式下要用供应商的模型请填写模型列表。
  • DeepSeek Harness 的 home 级 cordis.patch.yml 里的 MCP 在 CC Switch 里看不到，也没有说明（见 #9714）：CC Switch 只读写各 profile 的文件，MCP 导入对话框现在写明 home 级文件既不读也不写，其中的 MCP 请在那里管理。
