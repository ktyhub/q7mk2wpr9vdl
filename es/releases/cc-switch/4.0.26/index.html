interruptor cc v4.0.26

Interruptor CC v4.0.26

Esta versión permite que el centro de autorización y las tarjetas de proveedores oficiales muestren el plan de suscripción de cada cuenta. La cuenta Copilot GitHub enumerará todas las cuotas limitadas; el enlace de importación con un solo clic ahora también puede importar proveedores de Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness y Oh My Pi. La tarjeta Codex puede optar por conservar el archivo Fast oficial del modelo GPT; CC Switch le recordará cuando el agente del sistema se haga cargo de las solicitudes de Codex y Grok Build al enrutamiento local. DeepSeek Harness puede configurar un directorio de configuración y también administrarlo cuando se instala en WSL. Esta versión también realizó una ronda de optimización del rendimiento: la lista de proveedores, la carga de la ventana principal, el inicio, la lectura de sesiones y el reenvío de rutas son todos más rápidos, y la interfaz ya no se bloquea cuando la sincronización de sesiones ocupa la base de datos. Además, la solicitud de enrutamiento se bloquea durante más de dos minutos cuando IPv6 no está disponible, el servidor MCP que necesita iniciar sesión muestra que la conexión falla, la tarjeta de enrutamiento de Claude Desktop cambia el modelo y no tiene efecto, la tasa de aciertos de caché disminuye cuando el Codex se transfiere a Chat mediante enrutamiento, la solicitud Grok de GitHub Copilot informa 422 y la respuesta se muestra repetidamente, y la ventana emergente se ve borrosa en pantallas que no son Retina. Para obtener el contenido completo de la actualización de 4.0, consulte las Notas de la versión de v4.0. Inglés → | Versión japonesa →

Agregar

Plan de suscripción de cuenta

En el pasado, solo la cuenta de Claude en el centro de autorización escribía el plan de suscripción y otras cuentas solo mostraban la fecha de inicio de sesión. La cuenta Max y la cuenta gratuita del mismo servicio se verían exactamente iguales. Ahora las cuentas GitHub Copilot, ChatGPT, Kimi, Antigravity y xAI también tendrán planes de suscripción escritos al comienzo de la segunda línea. Las tarjetas oficiales de Codex, Kimi, Antigravity y Gemini CLI, así como las tarjetas de cuenta Copilot y xAI, también tendrán agregado "· Nombre del proyecto" después del subtítulo.

  • El nombre del plan en la tarjeta se basa directamente en el resultado de la consulta de cuota y no se enviarán múltiples solicitudes (Kimi, Antigravity y xAI tendrán una solicitud paralela más para obtener el nombre del plan al verificar la cuota); el nombre del plan solo aparecerá después de que se cargue la cuota y las tarjetas que no verifiquen la cuota no se mostrarán.
  • Si no se puede encontrar el nombre del plan, simplemente no se mostrará y el monto se mostrará como de costumbre; Si la actualización falla, se conservará el último plan encontrado.
  • La tarjeta Grok Build iniciada con Grok CLI y la tarjeta Antigravity sin cuenta aún no tienen un nombre de plan y esta información no se puede obtener a través de su método de verificación de saldo.

GitHub Copiloto Mostrar todos los saldos

Anteriormente, las cuentas de Copilot solo mostraban el porcentaje de solicitudes avanzadas. Ahora cada elemento con un límite superior tiene su propia línea. Puede pasar el cursor para ver "Restante/Total" y también puede ver el código completado y la cantidad de chats para la cuenta gratuita.

  • La solicitud avanzada pasa a llamarse Créditos, que es consistente con el nombre en el Codex, y es el mismo en la bandeja.
  • La cuenta gratuita no tiene Créditos. Solía ​​​​mostrarse como "100% restante", pero ahora está escrito como "El plan actual no incluye" y este artículo ya no se muestra en la tarjeta de proveedor.

La importación con un clic admite más aplicaciones

Anteriormente, los enlaces de proveedores para Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness y Oh My Pi habrían sido rechazados de plano. Ahora también se pueden importar enlaces a estas aplicaciones.

  • Claude Desktop: Cuando el enlace está en formato Anthropic y el nombre del modelo comienza con claude- (o no se escribe ningún modelo), se importará a una tarjeta de conexión directa; de lo contrario, se importará a una tarjeta de mapeo de modelo y las cuatro ranuras se completarán según el modelo en el enlace.
  • Código MiniMax, Código Kimi, Arnés DeepSeek, Oh My Pi: importado como un modelo único como Pi, el modelo debe estar incluido en el enlace.
  • Oh My Pi leerá la clave escrita de cierta manera como un nombre de variable de entorno o un comando. Después de la importación, es posible que envíe su clave local a la dirección que figura en el enlace. Por lo tanto, se rechazará la importación de este tipo de clave (que comienza con !, sin letras minúsculas, etc.).

Las tarjetas Codex conservan el archivo Fast oficial

A los modelos GPT en la lista de modelos de tarjetas de terceros del Codex se les eliminaba el archivo oficial de velocidad rápida y no se podía seleccionar Rápido (#5234). Las transferencias que reenvían cuentas oficiales de ChatGPT (como CPA) en realidad admiten Fast. Ahora, en las "Opciones avanzadas" del formulario del proveedor del Codex, aparece "Mantener archivo rápido oficial" en "Formato ascendente". Está desactivado de forma predeterminada y solo se muestra cuando el formato ascendente es Respuestas. Después de abrir el Codex y seleccionar Rápido, la solicitud contendrá service_tier=priority.

  • Sólo se reconocerán las transferencias que reenvíen cuentas oficiales de ChatGPT, lo que consumirá la cuota más rápido; otros proveedores pueden informar un error o facturarse a un precio más alto.
  • Si ha seleccionado Rápido en la tarjeta oficial anteriormente, entrará en vigor aquí inmediatamente después de abrirla. No tiene efecto en modo agregación. Es necesario reiniciar el Codex después de la modificación.

Alerta cuando el agente del sistema se hace cargo de la ruta local

Cuando las herramientas de proxy como Clash están habilitadas, las solicitudes enviadas por Codex y Grok Build a la ruta local (http://127.0.0.1:<port>) pueden ser recogidas por el proxy del sistema y transferidas al nodo remoto antes de devolver un 502 vacío (#9221). Codex solo muestra "502 Bad Gateway" y CC Switch no puede recibir solicitudes. No hay registros, por lo que es difícil comprobarlo. Ahora, después de que Codex o Grok Build ingresen al modo de enrutamiento, CC Switch enviará una solicitud a la ruta local en segundo plano de acuerdo con las mismas reglas de proxy que el cliente. Cuando la solicitud no pueda devolverse, se registrará una advertencia en el registro; Si ingresa al modo de enrutamiento manualmente, aparecerá un mensaje emergente en la interfaz que explica cómo conectar directamente la dirección local en la herramienta proxy (por ejemplo, agregue IP-CIDR,127.0.0.0/8,DIRECT,no-resolve al comienzo de la regla Clash).

Directorio de configuración del arnés DeepSeek

En el pasado, DeepSeek Harness solo reconocía DSH_HOME o ~/.dsh, y el DSH instalado en WSL no se podía administrar en la versión de Windows de CC Switch (#9239). Ahora hay una columna de DeepSeek Harness en "Configuración → Configuración de la aplicación", donde puede configurar el directorio de configuración. Los proveedores, las habilidades, los archivos de directivas, las sesiones y las importaciones de uso siguen este directorio. Al completar la ruta en WSL, la detección, instalación y actualización de la versión también se realizarán en esa distribución WSL.

Cambiar

  • Optimización del rendimiento:
    • La lista de proveedores se lee más rápido y cuantos más proveedores haya, más obvia será; Los proveedores sin cambios ya no se escribirán repetidamente en la base de datos y no se activará la sincronización en la nube (#9180).
    • Se cambia la página secundaria y el editor de proveedores para que se carguen cuando se usan, y los scripts que se cargarán cuando se inicia la ventana principal se reducen a la mitad (#9181).
    • La limpieza de registros al inicio se mueve a un segundo plano; la actualización programada se suspende cuando la ventana está oculta o minimizada y se actualiza como de costumbre cuando la ventana está visible pero no en primer plano (#9182).
    • Al leer registros de sesión, copie los datos una vez menos y el caché de la sesión se liberará después de ingresar al modo ligero (#9183).
    • El enrutamiento reenvía respuestas en tiempo real sin copiar mucha memoria, especialmente cuando la respuesta es larga; la conmutación por error lee la base de datos con menos frecuencia (#9161).
  • La interfaz ya no se bloquea durante la sincronización de la sesión (#9178): Los archivos de sesión grandes ocuparán la base de datos durante decenas de segundos durante la sincronización. Durante este período, abrir la página de Habilidades, cambiar a Pi u Oh My Pi, abrir la configuración de datos o de red, la selección de íconos, el panel de proveedores unificado, la prueba de velocidad y otras operaciones harán que toda la ventana y la bandeja se bloqueen hasta que se complete la sincronización. Ahora estas operaciones esperan en segundo plano y la interfaz responde como de costumbre.
  • Rediseño de la barra de herramientas en la página de lectura de la sesión (#9109): la primera línea contiene la ruta y las herramientas de lectura, y la segunda línea contiene el tiempo, las estadísticas de la sesión, los modelos y el uso; Se elimina el punto de separación que fácilmente cae al principio y al final de la línea. Si el nombre del modelo es demasiado largo, se mostrará en una nueva línea. Puedes pasar el cursor para ver el nombre completo.
  • Predeterminado: El modelo predeterminado de Grok Build se cambia a grok-4.7, el modelo predeterminado de Kimi preestablecido (excepto Codex) se cambia a kimi-k3.1-pro, el modelo predeterminado del Plan de codificación Qianwen de Hermes se cambia a qwen3.7-plus (#9193); TeamoRouter cambia el nombre de dominio teamorouter.com; el enlace de descarga de la tarjeta oficial de Claude Desktop se cambia a claude.com/download. Los proveedores que ya se han agregado no se ven afectados.

Arreglar

  • Cuando IPv6 no está disponible, las solicitudes de enrutamiento se retrasarán más de dos minutos antes de enviarse (#9212). Los nombres de dominio de servicios como Zhipu GLM y Alibaba Cloud Bailian resolverán primero las direcciones IPv6. En una red donde IPv6 está bloqueado, el enrutamiento local tendrá que esperar a que el sistema agote el tiempo de espera de cada dirección IPv6 antes de cambiar a IPv4. Esto tarda unos 150 segundos en macOS y unos 43 segundos en Windows. Ahora, si la dirección IPv6 no se puede conectar en 300 milisegundos, intentará IPv4 al mismo tiempo y el contenido de la solicitud permanecerá sin cambios.
  • El servidor MCP que requiere inicio de sesión, la verificación de conectividad muestra "Error de conexión" (#9190). Servidores como Notion y Sentry requieren inicio de sesión OAuth. Después de iniciar sesión en el cliente, se pueden utilizar normalmente. Sin embargo, cuando CC Switch verifica sin las credenciales de inicio de sesión del cliente, se considera que ha fallado. Esta situación ahora muestra un punto amarillo y al pasar el cursor se indicará que el servidor se puede conectar, pero solo requiere iniciar sesión. CC Switch todavía no lee las credenciales de inicio de sesión guardadas del cliente.
  • Después de cambiar el modelo de la tarjeta de enrutamiento de Claude Desktop, el modelo antiguo todavía está en Claude Desktop, así que elimínelo y reconstrúyalo (#9203). Al guardar, si el "Nombre para mostrar del menú" se deja en blanco, el nombre del modelo se completará automáticamente. Si solo cambia el modelo más tarde, el nombre para mostrar seguirá siendo el anterior. Ahora, cuando el nombre para mostrar sea el mismo que el nombre del modelo anterior, se cambiará junto con el nuevo modelo y el nombre que usted mismo se dio permanecerá sin cambios.
  • Cuando Codex se transfiere a Chat mediante enrutamiento, la tasa de aciertos de caché disminuye después de que se cambian las configuraciones durante la conversación. Por ejemplo, después de cambiar a sandbox_mode a mitad de camino, Codex insertará una descripción al comienzo de esta ronda. Anteriormente, se fusionaba al comienzo de la conversación, se reescribía todo el historial y todos los cachés ascendentes dejarían de ser válidos. Esta nota ahora permanece vigente y el historial anterior permanece sin cambios.
  • Cuando el Codex se dirige a través del Chat, el contenido de pensamiento de otra sesión puede mezclarse con la sesión actual. El ID de llamada de herramienta proporcionado por el upstream es fácil de repetir (como exec_command:0). Después de reiniciar la ruta local o eliminar el caché, se pueden encontrar llamadas con el mismo nombre en otras sesiones. Ahora se distingue por sesión del Codex, solo busque dentro de la misma sesión.
  • Cuando falla la solicitud de enrutamiento, el nombre del modelo del cliente se registra en el registro de solicitudes. Por ejemplo, la tarea en segundo plano de Claude Desktop usa claude-haiku-4-5-20251001. Después de asignar el modelo de esta tarjeta, el upstream informa 429, pero el registro muestra Haiku. Parece que se llama un modelo que no has configurado. Ahora las solicitudes fallidas se escribirán como "claude-haiku-4-5-20251001 → modelo real" al igual que las exitosas.
  • La tarjeta oficial de Claude que sigue al inicio de sesión local siempre mostrará "Token para actualizar" después de que caduque el inicio de sesión, y debes ejecutar Claude Code nuevamente para recuperarlo. Ahora, cuando el inicio de sesión caduque, CC Switch le pedirá a Claude Code que actualice el inicio de sesión y lea la cuota nuevamente. Omitir cuando se establezca el directorio de configuración de Claude.
  • Cuando el clasificador de seguridad de Claude Code y el modo automático de Claude Desktop no está disponible, el cliente seguirá reintentando y seguirá consumiendo la cuota (#9201, #9199). Ahora, cuando tres rondas consecutivas de resultados de la herramienta informan que el clasificador no está disponible, la ruta local devuelve directamente un error y ya no lo envía al flujo ascendente; enviar un nuevo mensaje para continuar.
  • Codex vía copiloto GitHub con modelo Grok multiplicado por 422 (#7989, #7988). Ahora las solicitudes Grok de Copilot se manejan de la misma manera que la xAI directa.
  • Cuando el Codex pasa el copiloto GitHub, la misma respuesta se muestra dos veces (#8025, #7977).
  • Al instalar o actualizar una aplicación, se encuentra un archivo existente con el mismo nombre y el mensaje solo contiene --force (#9196, #9173) recomendado por npm. Este archivo probablemente provenga de otro método de instalación y --force lo sobrescribirá directamente. Ahora el mensaje escribirá la ruta del archivo en conflicto. Se recomienda cambiar el nombre de la copia de seguridad y volver a intentarlo.
  • La sincronización automática de WebDAV falla cuando hay enlaces suaves de archivos en Skills (#9197). Por ejemplo, cuando CLAUDE.md y GEMINI.md están vinculados a AGENTS.md, aparecerán archivos con el mismo nombre en el paquete. Cada archivo ahora conserva su propio nombre.
  • Dos problemas con el límite superior simultáneo del subagente del Codex (#9148): cuando config.toml tiene comentarios detrás del encabezado de la tabla, cambiar el límite superior puede sobrescribir [features.multi_agent_v2]; cuando [agents] se escribe como un nombre clave entre comillas, se escribirá un campo duplicado adicional que el Codex no reconoce. La descripción también agrega que los cambios solo surten efecto para sesiones nuevas.
  • DeepSeek Harness no puede encontrar la clave guardada por CC Switch cuando se usa el perfil sin cabeza, informa MISSING_CREDENTIAL. La lectura de credenciales ahora se habilitará según el documento DSH al escribir en un perfil sin cabeza; Los perfiles que haya modificado en este elemento permanecerán sin cambios.
  • En monitores 1x, las ventanas emergentes como "Seleccionar modelo" aparecen borrosas (#9238). Cuando la ventana emergente está centrada, puede ocupar medio píxel y el texto y los bordes aparecerán borrosos en pantallas que no sean Retina.
  • En macOS, al escribir en cuadros de entrada como formularios MCP, editores de palabras, almacén de habilidades, búsqueda de sesiones, etc., la primera letra se cambia automáticamente a mayúscula y, como resultado, los nombres de variables de entorno, encabezados de solicitud, comandos y direcciones pueden almacenarse incorrectamente.
  • Linux AppImage empaqueta la versión anterior de libwayland-client (#9229, #8723), que no se puede abrir en un entorno con Intel Core Graphics y Wayland.

cc-switch v4.0.26

Highlights

  • Subscription visibility — Authorization and official-provider cards now show plan names and every metered GitHub Copilot quota, including Free-tier chat and completions. Free accounts report “not included” instead of a misleading 100% for Credits; plan names appear only after quota loading and silently disappear on lookup failure.

  • Broader one-click imports — Links now work for Claude Desktop, MiniMax Code, Kimi Code, DeepSeek Harness, and Oh My Pi. Claude Desktop links become direct connections only when using Anthropic-format claude-* models or no model; otherwise they become model-mapping cards. The other four require an explicit model, and dangerous Oh My Pi key syntax—such as !-prefixed values—is rejected to prevent accidental credential exposure.

  • Codex Fast tier and new behavior — Responses-format Codex providers can opt into Preserve official Fast tier, adding service_tier=priority when Fast is selected. This works only with gateways that forward official ChatGPT accounts, may consume quotas faster or fail elsewhere, does not apply in aggregate mode, and requires restarting Codex. Prior Fast selections activate once enabled.

  • Proxy and WSL diagnostics — Codex and Grok Build now probe local routes under the client’s proxy rules, warning when requests may escape to a proxy node and return an empty 502; add 127.0.0.0/8 to your proxy’s direct rules. DeepSeek Harness gains a configurable directory covering providers, Skills, instructions, sessions, and usage, with WSL paths also used for detection, installation, and upgrades.

  • Faster, more responsive routing — Lazy loading, reduced database writes and copies, background startup maintenance, and streamlined streaming reduce startup, session, and forwarding overhead (#9180, #9181, #9183, #9161). Session synchronization now queues UI actions instead of freezing the window and tray (#9178), while IPv6 connection failures fall back to IPv4 after 300 ms rather than waiting roughly 150 seconds on macOS (#9212).

  • Routing correctness fixes — Failed requests now log both the client-requested and actual upstream models, making mapping-related 429s diagnosable. Codex-to-Chat preserves history when settings change, preventing cache invalidation, and isolates tool-call lookup by session to stop cross-session reasoning leakage (#9203 covers a related Claude Desktop model-rename fix). Also notable: unavailable safety classifiers now stop after three rounds instead of retrying indefinitely (#9201); manually customized Claude configuration directories skip automatic login refresh.

CC Switch v4.0.26

本版本让授权中心和官方供应商卡片显示每个账号的订阅计划，GitHub Copilot 账号会列出所有有上限的额度；一键导入链接现在也能导入 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商。Codex 卡片可以选择保留 GPT 模型的官方 Fast 档；系统代理把 Codex、Grok Build 发往本地路由的请求接走时，CC Switch 会提醒你。DeepSeek Harness 可以设置配置目录，装在 WSL 里也能管理。这一版还做了一轮性能优化：供应商列表、主窗口加载、启动、会话读取和路由转发都更快，会话同步占着数据库时界面也不再卡住。另外修复了 IPv6 不通时经路由请求先卡两分多钟、需要登录的 MCP 服务器显示连接失败、Claude Desktop 路由卡片改了模型不生效、Codex 经路由转 Chat 时缓存命中率下降、GitHub Copilot 的 Grok 请求报 422 和回复重复显示、非 Retina 显示器上弹窗模糊等问题。4.0 完整的更新内容请见 v4.0 发布说明。

新增

账号订阅计划

以前授权中心里只有 Claude 账号会写订阅计划，其他账号只显示登录日期，同一个服务的 Max 账号和 Free 账号看起来一模一样。

现在 GitHub Copilot、ChatGPT、Kimi、Antigravity、xAI 账号的第二行开头也会写订阅计划。Codex、Kimi、Antigravity、Gemini CLI 的官方卡片，以及 Copilot、xAI 账号卡片，副标题后面也会加上「· 计划名」。

  • 卡片上的计划名直接用额度查询的结果，不会多发请求（Kimi、Antigravity、xAI 查额度时会多一个并行请求取计划名）；额度加载出来后计划名才出现，不查额度的卡片不显示。
  • 计划名查不到时只是不显示，额度照常显示；刷新失败时保留上次查到的计划。
  • 跟随 Grok CLI 登录的 Grok Build 卡片、没绑账号的 Antigravity 卡片暂时还没有计划名，它们查额度的方式拿不到这项信息。

GitHub Copilot 显示全部额度

Copilot 账号以前只显示高级请求的百分比。现在每一项有上限的额度各占一行，悬停可以看到「剩余 / 共」，Free 账号的代码补全和聊天次数也能看到了。

  • 高级请求改叫 Credits，和 Codex 的叫法一致，托盘里也一样。
  • Free 账号没有 Credits，以前会显示成「还剩 100%」，现在写「当前计划不含」，供应商卡片上不再显示这一项。

一键导入支持更多应用

以前 Claude Desktop、MiniMax Code、Kimi Code、DeepSeek Harness 和 Oh My Pi 的供应商链接会直接被拒绝。现在这些应用的链接也能导入了。

  • Claude Desktop：链接是 Anthropic 格式、模型名都以 claude- 开头（或没写模型）时，导入成直连卡片；其他情况导入成模型映射卡片，四个档位按链接里的模型填好。
  • MiniMax Code、Kimi Code、DeepSeek Harness、Oh My Pi：和 Pi 一样导入成单个模型，链接里必须带模型。
  • Oh My Pi 会把某些写法的 Key 当成环境变量名或命令来读，导入后可能把你本机的密钥发到链接里的地址。所以这类 Key（以 ! 开头、没有小写字母等）会被拒绝导入。

Codex 卡片保留官方 Fast 档

Codex 第三方卡片模型列表里的 GPT 模型以前一律去掉了官方的 Fast 速度档，选不了 Fast（#5234）。转发官方 ChatGPT 账号的中转（如 CPA）其实支持 Fast。

现在 Codex 供应商表单「高级选项」里，「上游格式」下面多了「保留官方 Fast 档」，默认关闭，只在上游格式为 Responses 时显示。打开后 Codex 选了 Fast 时请求会带 service_tier=priority。

  • 只有转发官方 ChatGPT 账号的中转才认，会更快消耗额度；其他上游可能报错或按更高价格计费。
  • 以前在官方卡片下选过 Fast 的，打开后会马上在这家生效。聚合模式下不生效，改完需要重启 Codex。

系统代理接走本地路由时提醒

开着 Clash 这类代理工具时，Codex 和 Grok Build 发往本地路由（http://127.0.0.1:<port>）的请求可能被系统代理接走，转到远程节点后返回一个空的 502（#9221）。Codex 只显示「502 Bad Gateway」，CC Switch 这边也收不到请求，没有任何日志，很难查。

现在 Codex 或 Grok Build 进入路由模式后，CC Switch 会在后台按客户端同样的代理规则给本地路由发一次请求。请求回不来时，日志里会记一条警告；如果是你手动进入路由模式，界面上也会弹出提示，说明怎么在代理工具里让本机地址直连（例如在 Clash 规则最前面加 IP-CIDR,127.0.0.0/8,DIRECT,no-resolve）。

DeepSeek Harness 配置目录

以前 DeepSeek Harness 只认 DSH_HOME 或 ~/.dsh，装在 WSL 里的 DSH 在 Windows 版 CC Switch 里管不了（#9239）。

现在「设置 → 应用配置」里多了 DeepSeek Harness 一栏，可以设置配置目录。供应商、Skills、指令文件、会话和用量导入都会跟着这个目录走。填 WSL 里的路径时，版本检测、安装和升级也会在那个 WSL 发行版里进行。

变更

  • 性能优化：
    • 供应商列表读取更快，供应商越多越明显；没改动的供应商不再重复写入数据库，也就不会因此触发云同步（#9180）。
    • 次要页面和供应商编辑器改为用到时才加载，主窗口启动要加载的脚本少了一半（#9181）。
    • 启动时的日志清理挪到后台进行；窗口隐藏或最小化时暂停定时刷新，窗口可见但不在前台时照常刷新（#9182）。
    • 读取会话记录时少复制一遍数据，进入轻量模式后会释放会话缓存（#9183）。
    • 路由转发流式响应时少了大量内存复制，响应很长时尤其明显；故障转移读数据库的次数也更少（#9161）。
  • 会话同步时界面不再卡住（#9178）：大会话文件同步时会占着数据库几十秒，这期间打开 Skills 页、切到 Pi 或 Oh My Pi、打开网络或数据设置、图标选择、统一供应商面板、测速等操作会让整个窗口和托盘卡住，直到同步结束。现在这些操作都在后台等待，界面照常响应。
  • 会话阅读页的工具栏重新排版（#9109）：第一行放路径和阅读工具，第二行放时间、会话统计、模型和用量；去掉了容易落在行首行尾的分隔点，模型名太长时换行显示，悬停可看完整名称。
  • 预设： Grok Build 默认模型改为 grok-4.7，Kimi 预设（Codex 的除外）默认模型改为 kimi-k3.1-pro，Hermes 的千问 Coding Plan 默认模型改为 qwen3.7-plus（#9193）；TeamoRouter 改用 teamorouter.com 域名；Claude Desktop 官方卡片的下载链接改为 claude.com/download。已添加的供应商不受影响。

修复

  • IPv6 不通时，经路由的请求要先卡两分多钟才发出（#9212）。智谱 GLM、阿里云百炼等服务的域名会先解析出 IPv6 地址，在 IPv6 不通的网络里，本地路由要等系统把每个 IPv6 地址都超时一遍才改用 IPv4，macOS 上约 150 秒、Windows 上约 43 秒。现在 IPv6 地址 300 毫秒内连不上就同时尝试 IPv4，发出的请求内容不变。
  • 需要登录的 MCP 服务器，连通性检查显示「连接失败」（#9190）。Notion、Sentry 这类服务器需要 OAuth 登录，客户端里登录后能正常用，但 CC Switch 检查时不带客户端的登录凭据，就被判成了失败。现在这种情况显示黄色圆点，悬停会说明服务器能连上、只是要求登录。CC Switch 仍然不读取客户端保存的登录凭据。
  • Claude Desktop 路由卡片改了模型后，Claude Desktop 里还是旧模型，删掉重建才行（#9203）。保存时「菜单显示名」留空会自动填成模型名，之后只改模型时显示名还是旧的。现在显示名和旧模型名一样时会跟着新模型一起改，你自己起的名字保持不变。
  • Codex 经路由转 Chat 时，对话中途改了设置后缓存命中率下降。比如中途切换 sandbox_mode 后，Codex 会在这一轮开头插入一条说明，以前它被合并到对话最开头，改写了整段历史，上游缓存就全部失效了。现在这条说明留在原位，之前的历史保持不变。
  • Codex 经路由转 Chat 时，可能把另一个会话的思考内容混进当前会话。上游给的工具调用 ID 容易重复（如 exec_command:0），本地路由重启或缓存被挤掉后，可能找到别的会话里同名的调用。现在按 Codex 会话区分，只在同一个会话里找。
  • 路由请求失败时，请求日志里记的是客户端的模型名。比如 Claude Desktop 的后台任务用的是 claude-haiku-4-5-20251001，映射到这张卡片的模型后上游报 429，日志里却显示 Haiku，看起来像调用了一个你没配过的模型。现在失败的请求和成功的一样，会写成「claude-haiku-4-5-20251001 → 实际模型」。
  • 跟随本机登录的 Claude 官方卡片，登录过期后一直显示「令牌待刷新」，要再跑一次 Claude Code 才恢复。现在登录过期时 CC Switch 会让 Claude Code 自己刷新登录，再读取额度。设置了 Claude 配置目录时跳过。
  • Claude Code 和 Claude Desktop 自动模式的安全分类器不可用时，客户端会一直重试、持续消耗额度（#9201、#9199）。现在连续 3 轮工具结果都报告分类器不可用时，本地路由直接返回错误，不再发给上游；发一条新消息即可继续。
  • Codex 通过 GitHub Copilot 用 Grok 模型时报 422（#7989、#7988）。现在 Copilot 的 Grok 请求和直连 xAI 一样做兼容处理。
  • Codex 通过 GitHub Copilot 时，同一条回复显示两遍（#8025、#7977）。
  • 安装或升级应用时撞上已有的同名文件，提示里只有 npm 建议的 --force（#9196、#9173）。这个文件多半来自另一种安装方式，用 --force 会直接覆盖它。现在提示会写出冲突的文件路径，建议先改名备份再重试。
  • Skills 里有文件软链接时，WebDAV 自动同步失败（#9197）。比如 CLAUDE.md 和 GEMINI.md 都链接到 AGENTS.md 时，打包会出现重名文件。现在每个文件保留自己的名字。
  • Codex 子代理并发上限的两个问题（#9148）：config.toml 里表头后面带注释时，改上限可能覆盖掉 [features.multi_agent_v2]；[agents] 写成带引号的键名时，会多写一个 Codex 不认的重复字段。说明文字也补充了改动只对新会话生效。
  • DeepSeek Harness 用 headless profile 时找不到 CC Switch 保存的 Key，报 MISSING_CREDENTIAL。现在写入 headless profile 时会按 DSH 文档开启凭据读取；你自己改过这一项的 profile 保持不变。
  • 在 1x 显示器上，「选择模型」等弹窗显示模糊（#9238）。弹窗居中时可能落在半个像素上，非 Retina 显示器上文字和边框会发虚。
  • macOS 上，在 MCP 表单、提示词编辑、Skills 仓库、会话搜索等输入框里打字时首字母被自动改成大写，环境变量名、请求头、命令、地址可能因此被存错。
  • Linux AppImage 打包了旧版 libwayland-client（#9229、#8723），在 Intel 核显加 Wayland 的环境下可能打不开。
