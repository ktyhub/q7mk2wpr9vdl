gstack v1.98.0.0

gstack v1.98.0.0

Las nuevas instalaciones ahora siguen a la versión estable probada, se retiran dos habilidades poco utilizadas y se bloquean varios servicios locales y el emparejamiento remoto del navegador.

¿Qué hay de nuevo?

  • Un nuevo git clone más ./setup ahora sigue el canal estable, por lo que los nuevos usuarios obtienen la versión probada en lugar de cada cambio en principal; Las instalaciones existentes y los pagos de los contribuyentes siguen a main, y el programa de instalación imprime el comando para cambiar. En Capy, gstack ahora se actualiza a la última versión principal al menos una vez al día, a menos que lo fijes con un motivo #4091.
  • /autoplan tiene una puerta de suscripción (./setup --autoplan-gate o gstack-config set autoplan_gate on) que evita que la sesión finalice hasta que cada fase de planificación haya publicado su informe y se escriba el paso de aprobación final #4100.
  • /plan-eng-review ya no está instalado, porque dos evaluaciones encontraron que no agregaba nada sobre Opus 5.5; /autoplan aún ejecuta su fase de revisión de ingeniería y el siguiente ./setup elimina la entrada anterior pero deja una habilidad que usted escribió con ese nombre sola #4108.
  • /investigate ya no está instalado, después de que una evaluación de 18 correcciones de errores reales no encontró ningún beneficio con él; el siguiente ./setup elimina la entrada anterior de la misma manera #4110.

Correcciones

  • En Capy, una verificación de instalación de gstack que se ejecuta en medio de una /ship abierta o revisión ya no actualiza gstack debajo de ella, y la ruta de actualización ahora funciona sin el binario flock #4095.
  • La puerta /plan-ceo-review ya no juzga una sesión antes de que Claude Code haya terminado de escribir su transcripción, por lo que ya no se realiza una revisión finalizada por error #4102.
  • La verificación que retiene la sesión de una habilidad hasta que se realizan los pasos requeridos ahora también espera a que Claude Code termine de escribir la transcripción, por lo que una ejecución finalizada ya no se bloquea por error #4104.
  • Las esperas de gstack en solicitudes de extracción ahora verifican GitHub como máximo una vez por minuto y esperan los límites de velocidad, por lo que dejan de usar la cuota compartida GitHub API #4109.
  • /ship ahora trata la interfaz de usuario escrita como plantillas Lit o htm dentro de un archivo .ts o .js como interfaz, por lo que esos cambios obtienen la verificación de diseño en lugar de omitirlos silenciosamente #4112.
  • /autoplan ahora reconoce la misma interfaz de usuario de plantilla Lit y ​​htm y palabras como fila, selector y menú, por lo que esos planes obtienen una fase de Diseño, y una ejecución rápida ya no dice que fusionó una fase de Diseño que omitió #4121.
  • /make-pdf lee imágenes locales sólo desde la propia carpeta del documento y sólo archivos de imágenes reales; cualquier otra cosa se muestra como un marcador de posición visible de "imagen bloqueada" #4113.
  • A través del túnel /pair-agent, un agente remoto ahora solo puede abrir páginas web: no puede leer archivos locales, elegir una ruta en su disco ni hacer que el navegador guarde capturas de pantalla allí #4116.
  • El tablero de diseño y los servicios en segundo plano de control de calidad de iOS ahora responden solo a las solicitudes locales realizadas directamente a ellos, y los enlaces del tablero de diseño ahora incluyen un secreto privado en la URL #4117.
  • /setup-gbrain ya no pasa la URL de su base de datos gbrain, que contiene su contraseña, en la línea de comando donde otros usuarios locales podrían verla, y la verificación de redacción de gstack ahora detecta más tipos de credenciales #4114.
  • El instalador de Capy ya no carga el bunfig.toml o .env de su proyecto mientras lee las versiones Bun y Node del proyecto #4115.

Cambios para mantenedores

  • La contabilidad de revisiones de /ship obtuvo varias correcciones: las revisiones de seguimiento y las rondas adicionales otorgadas por el propietario ahora cuentan correctamente, las ediciones de versiones y documentos después de una revisión ya no fuerzan otra ronda, un registro de revisión rechazado ahora dice de qué confirmación proviene y un hallazgo del revisor que se abre con "Encontrar 1" mantiene su propia gravedad #4089 #4093 #4096 #4099 #4101 #4106.
  • Una ejecución de /ship entregada a un nuevo hilo mantiene un presupuesto de gastos, y un resultado de CI borrado por la verificación remota ahora satisface el paso de prueba local de /ship para ese árbol exacto #4088 #4098.
  • Los dispositivos de prueba ya no hacen que /ship piense que un revisor los obtuvo de la red, y las pruebas del canal de actualización ya no pueden escribir la configuración real de gstack de un desarrollador #4105 #4094.
  • Las solicitudes de extracción de subprocesos del agente ahora muestran si tuvieron su paso de planificación y un repositorio puede requerirlo antes de la fusión #4118.
  • Se corrigieron tres errores de herramientas /ship: el envío de revisión del segundo modelo coincide con el plan de revisión y los resultados de la verificación previa a la fusión sobreviven a una repetición de solo prueba y a una rama base movida #4124.
  • Los puntos y los objetivos de arnés genéricos ya no registran el /plan-eng-review retirado, y cada uno de sus antiguos casos de prueba pagados tiene un destino registrado #4111. Comparar v1.97.0.0...v1.98.0.0 · changelog completo

gstack v1.98.0.0

gstack v1.98.0.0

New installs now follow the tested stable release, two little-used skills are retired, and several local services and the browser's remote pairing are locked down.

What's new

  • A fresh git clone plus ./setup now follows the stable channel, so new users get the tested release instead of every change on main; existing installs and contributor checkouts keep following main, and setup prints the command to switch. On Capy, gstack now updates itself to the latest main at least once a day unless you pin it with a reason #4091.
  • /autoplan has an opt-in gate (./setup --autoplan-gate, or gstack-config set autoplan_gate on) that keeps the session from ending until every planning phase has published its report and the final approval step is written #4100.
  • /plan-eng-review is no longer installed, because two evals found it added nothing over plain Opus 5.5; /autoplan still runs its engineering review phase, and the next ./setup removes the old entry but leaves a skill you wrote under that name alone #4108.
  • /investigate is no longer installed, after an eval on 18 real bug fixes found no gain from it; the next ./setup removes the old entry the same way #4110.

Fixes

  • On Capy, a gstack install check that runs in the middle of an open /ship or review no longer upgrades gstack underneath it, and the upgrade path now works without the flock binary #4095.
  • The /plan-ceo-review gate no longer judges a session before Claude Code has finished writing its transcript, so a finished review is no longer held by mistake #4102.
  • The check that holds a skill's session until its required steps are done now also waits for Claude Code to finish writing the transcript, so a finished run is no longer blocked by mistake #4104.
  • gstack's waits on pull requests now check GitHub at most once a minute and wait out rate limits, so they stop using up the shared GitHub API quota #4109.
  • /ship now treats UI written as Lit or htm templates inside a .ts or .js file as frontend, so those changes get the design check instead of skipping it silently #4112.
  • /autoplan now recognizes the same Lit and htm template UI and words like row, picker and menu, so those plans get a Design phase, and a quick run no longer says it merged a Design phase it skipped #4121.
  • /make-pdf reads local images only from the document's own folder and only real image files; anything else renders as a visible "image blocked" placeholder #4113.
  • Over the /pair-agent tunnel, a remote agent can now only open web pages: it can't read local files, pick a path on your disk, or make the browser save screenshots there #4116.
  • The design board and iOS QA background services now answer only local requests made directly to them, and design board links now include a private secret in the URL #4117.
  • /setup-gbrain no longer passes your gbrain database URL, which holds its password, on the command line where other local users could see it, and gstack's redaction check now catches more kinds of credentials #4114.
  • The Capy installer no longer loads your project's bunfig.toml or .env while it reads the project's Bun and Node versions #4115.

Changes for maintainers

  • /ship's review bookkeeping got several fixes: follow-up reviews and owner-granted extra rounds now count correctly, version and docs edits after a review no longer force another round, a refused review record now says which commit it came from, and a reviewer finding that opens with "Finding 1" keeps its own severity #4089 #4093 #4096 #4099 #4101 #4106.
  • A /ship run handed to a new thread keeps one spending budget, and a CI result cleared by the remote check now satisfies /ship's local test step for that exact tree #4088 #4098.
  • Test fixtures no longer make /ship think a reviewer fetched from the network, and the update-channel tests can no longer write a developer's real gstack config #4105 #4094.
  • Agent-thread pull requests now show whether they had their planning step, and a repo can require it before merge #4118.
  • Three /ship tooling bugs are fixed: the second-model review dispatch matches the review plan, and pre-merge check results survive a test-only rerun and a moved base branch #4124.
  • The dots and generic harness targets no longer register the retired /plan-eng-review, and its old paid test cases each have a recorded fate #4111.
