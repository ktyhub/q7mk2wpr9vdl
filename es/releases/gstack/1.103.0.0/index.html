gstack v1.103.0.0

gstack v1.103.0.0

Esta versión cierra las brechas en dos de las comprobaciones de seguridad de gstack y su herramienta de combinación, corrige las fallas de /ship que impedían que finalizaran las solicitudes de extracción y cambia el nombre de /verify a /build-check para que el propio /verify de Claude Code vuelva a funcionar. Actualice con /gstack-upgrade.

Acción necesaria: /verify ahora es /build-check

  • /verify ahora es /build-check, por lo que al escribir /verify se abre nuevamente el /verify integrado de Claude Code. Utilice /build-check para el bucle de compilación y verificación de gstack y /build-check quick para el pase de solo verificación. (#4714)
  • Si desactivaste la habilidad con disabled_skills: verify, cambia esa entrada a build-check. Hasta que lo hagas, gstack lee verify como build-check, por lo que la habilidad permanece desactivada después de actualizar. (#4719)
  • gstack ya no ejecuta la verificación antes de cada confirmación por sí solo, por lo que se retira la configuración verify_before_commit. Configurarlo imprime una nota y no cambia nada, y un archivo de configuración que todavía la tiene sigue funcionando. (#4714)
  • Las indicaciones sobre la verificación de un cambio ahora van a la propia habilidad de Claude Code: el enrutador de indicaciones de gstack y la descripción de /build-check ya no las reclaman. (#4719)
  • La actualización elimina la antigua entrada de habilidad verify de gstack (y gstack-verify en otros hosts o con --prefix), pero nunca una habilidad propia verify. (#4714)

Seguridad

  • La verificación de comando destructivo detrás de /careful y /guard ahora bloquea los empujes forzados al principal oculto detrás de un --no-dry-run abreviado, un -n que en realidad es un valor de opción de empuje, o un grupo de banderas con un dígito (-f4), y pregunta antes de una eliminación relativa después de cd en una carpeta del sistema o una eliminación de un dispositivo bajo /dev. (#4604)
  • La misma verificación ya no pregunta sobre una ruta entrecomillada que sea segura sin comillas, o sobre el título o cuerpo entrecomillado de un comando gh issue o gh pr. (#4604)
  • gstack-ship-queue land ahora ejecuta las comprobaciones del árbol fusionado de un repositorio en un clon desechable y se niega a continuar si una comprobación cambia la configuración, los enlaces o los archivos binarios de git o gh que usarían sus llamadas posteriores a git y gh. Cada llamada de git que realiza se ejecuta con los ganchos desactivados. (#4649)
  • La verificación de secretos ahora marca claves escritas como enlaces Rust let, const y static, y deja de marcar anotaciones de tipo Rust y brazos coincidentes. (#4675)
  • La verificación de secretos ahora lee archivos cuyos nombres contienen un espacio, un acento u otro carácter entre comillas; solía pasar una clave en src/clé.rs. (#4701)
  • La verificación de secretos de gstack y el enmascaramiento de cookies de navegación reconocen las claves Gemini que ahora emite Google AI Studio, que comienzan con AQ.. (#4684)
  • Las nuevas instalaciones de gstack ya no contienen 63 mensajes copiados de tareas reales de referencia de SWE-rebench: las pruebas del enrutador utilizan mensajes sintéticos y una prueba falla si aparece nuevamente una identificación de tarea de referencia. Las confirmaciones más antiguas aún contienen las indicaciones, por lo que una instalación con el historial completo de git aún puede acceder a ellas a través de git log. (#4642)
  • Un hallazgo de revisión sobre un código de seguridad que nombra solo un archivo nunca se cierra automáticamente, por lo que su ubicación no puede llegar al cuerpo de la solicitud de extracción pública. (#4700)

Correcciones para /ship y fusión

  • Una verificación de revisión adicional aprobada después del límite de dos rondas se puede utilizar una vez; se rechaza una segunda reclamación con GRANT_SPENT. (#4722)
  • El final de /ship ya no informa que la auditoría de documentos está obsoleta para un archivo que se leyó en una verificación de seguimiento limpia y no ha cambiado nada desde entonces. (#4722)
  • La aprobación de un propietario para una verificación más después de la segunda ronda de revisión de una solicitud de extracción ahora permite que /ship finalice, cualquiera que sea el comando que lo haya registrado. (#4717)
  • La verificación del valor de prueba obsoleto ya no marca las pruebas de un archivo diferente que comparte el nombre del archivo modificado; una prueba cuenta solo cuando una de sus importaciones se resuelve en ese archivo. (#4723)
  • /ship en una rama apilada en otra rama puede borrar su puerta de prueba remota de una ejecución de CI verde. (#4689)
  • La verificación final de CI de /ship acepta una ejecución verde que probó que su rama se fusionó con una principal más nueva cuando principal no cambió ninguna de sus líneas o las líneas al lado de ellas, por lo que los repositorios ocupados dejan de volver a ejecutar CI. (#4728)
  • Un gstack-ship-queue land --pin bloqueado ya no bloquea todas las fusiones posteriores: su bloqueo expira 90 minutos después de su último paso y un bloqueo cuyo proceso finalizó se recupera. (#4712)
  • Una ejecución de /ship que se detuvo o murió ya no bloquea la siguiente /ship, y el nuevo comando gstack-ship-run muestra el estado de una ejecución y finaliza una que dejó de funcionar. (#4654)
  • Una rama base cuya lista review_exclude_paths rompe el esquema de políticas ya no detiene cada /ship: la revisión cubre cada archivo e imprime una advertencia, por lo que la solicitud de extracción de reparación puede aterrizar. (#4637)
  • Una ejecución de CI omitida o neutral ya no bloquea la reutilización de una ejecución de paso en la misma confirmación. (#4695, #4713)
  • Un trabajo de CI que se ejecuta solo a través de un flujo de trabajo reutilizable ahora cuenta solo a partir de una ejecución de llamador que probó su confirmación exacta. (#4713)
  • La puerta de prueba local reutiliza cada CI verde ejecutado en su código exacto, no solo el primero que verifica. (#4671)
  • /ship ya no acepta un registro de puerta de prueba tomado contra una rama base diferente. (#4706)
  • gstack-ship-queue ready compara una solicitud de extracción con la rama a la que se dirige, no con la rama predeterminada del repositorio. (#4663)
  • gstack-ship-queue ready recupera los cabezales de solicitud de extracción faltantes de una sola vez, imprime el progreso y se detiene después de 60 segundos en lugar de permanecer en silencio durante minutos. (#4668)
  • /ship puede finalizar cuando su auditoría de documentos corrige un documento revisado después de la última ronda de revisión. (#4708)
  • /ship puede finalizar después de una auditoría de documentos que se detuvo antes de guardar su instantánea. (#4693)
  • /ship puede finalizar cuando se ejecutó la auditoría de documentos antes de una fusión desde la rama base. (#4648)
  • /ship mantiene la revisión finalizada de una solicitud de extracción después de una fusión base que solo vuelve a registrar un pin de arnés compartido, y /ship advierte cuando sus revisores se ejecutaron sin una revisión registrada. (#4669)
  • Una verificación de seguimiento que confirmó que sus bloqueadores fueron solucionados ahora cuenta una vez que se resuelvan los hallazgos restantes. (#4691)
  • Una verificación de seguimiento que lee una ronda de corrección aprobada y limpia ahora cierra los hallazgos de esa ronda de corrección. (#4664)
  • Una nueva verificación limpia de las correcciones aprobadas cuenta incluso cuando su resumen se redactó justo antes de que comenzara la revisión. (#4698)
  • El tráiler Review-Finding: de una confirmación de corrección cierra su hallazgo solo después de una revisión completa que finalizó con la corrección en su rango. (#4700)
  • La contabilidad de /ship se mantiene en tres casos más: un pasador de arnés convertido en un enlace simbólico necesita una nueva revisión, un reclamo que no se pudo guardar lo dice y las ejecuciones anteriores permanecen contadas después de una nueva descripción. (#4703)
  • El plan de revisión de /ship finaliza en repositorios con datos muy grandes o archivos de prueba, y GSTACK_REVIEW_CONSUMER_SCAN_CAP aumenta el límite de escaneo de archivos de datos. (#4651, #4643)
  • GSTACK_REVIEW_PLAN_TIMEOUT_MS ahora aumenta el límite de tiempo del plan de revisión en cada paso de /ship, para que los repositorios grandes puedan finalizar. (#4632)
  • La prueba propia de un repositorio para review_exclude_paths ya no vuelve a revisar los archivos excluidos. (#4699)
  • La revisión de código ahora lee la lista de verificación de diseño para cambios en la interfaz (antes apuntaba a un archivo faltante), y la revisión del segundo modelo ahora lee el código en la carpeta agents/ de su repositorio. (#4711)
  • La revisión de /ship ya no lee un nombre en clave como "la rama ALTA" como un hallazgo ALTO. (#4678)
  • Los resultados de la revisión del Codex escritos como encabezados numerados mantienen su gravedad. (#4681)
  • Siete pequeñas correcciones a las herramientas de ayuda de /ship, incluidos enlaces de problemas que ya no convierten los remolques Review-Finding: en líneas Refs. (#4672)

gstack v1.103.0.0

gstack v1.103.0.0

This release closes gaps in two of gstack's safety checks and its merge tool, fixes the /ship failures that were stopping pull requests from finishing, and renames /verify to /build-check so Claude Code's own /verify works again. Upgrade with /gstack-upgrade.

Action needed: /verify is now /build-check

  • /verify is now /build-check, so typing /verify opens Claude Code's built-in /verify again. Use /build-check for gstack's build-and-check loop and /build-check quick for the check-only pass. (#4714)
  • If you turned the skill off with disabled_skills: verify, change that entry to build-check. Until you do, gstack reads verify as build-check, so the skill stays off after you upgrade. (#4719)
  • gstack no longer runs the check pass before every commit on its own, so the verify_before_commit setting is retired. Setting it prints a note and changes nothing, and a config file that still has it keeps working. (#4714)
  • Prompts about verifying a change now go to Claude Code's own skill: gstack's prompt router and /build-check's description no longer claim them. (#4719)
  • Upgrading removes gstack's old verify skill entry (and gstack-verify on other hosts or with --prefix), but never a verify skill of your own. (#4714)

Security

  • The destructive-command check behind /careful and /guard now blocks force pushes to main hidden behind an abbreviated --no-dry-run, a -n that is really a push-option value, or a flag group with a digit (-f4), and asks before a relative delete after cd into a system folder or a delete of a device under /dev. (#4604)
  • The same check no longer asks about a quoted path that is safe unquoted, or about the quoted title or body of a gh issue or gh pr command. (#4604)
  • gstack-ship-queue land now runs a repository's merged-tree checks in a throwaway clone, and refuses to go on if a check changed the git or gh configuration, hooks or binaries its later git and gh calls would use. Every git call it makes runs with hooks turned off. (#4649)
  • The secrets check now flags keys written as Rust let, const and static bindings, and stops flagging Rust type annotations and match arms. (#4675)
  • The secrets check now reads files whose names hold a space, an accent or another character git quotes; a key in src/clé.rs used to pass. (#4701)
  • gstack's secrets check and browse's cookie masking recognize the Gemini keys Google AI Studio now issues, which start with AQ.. (#4684)
  • New gstack installs no longer contain 63 prompts copied from real SWE-rebench benchmark tasks: the router tests use synthetic prompts, and a test fails if a benchmark task id appears again. Older commits still hold the prompts, so an install with full git history can still reach them through git log. (#4642)
  • A review finding on security code that names only a file never closes automatically, so its location can't reach the public pull request body. (#4700)

Fixes for /ship and merging

  • An approved extra review check after the two-round limit can be used once; a second claim is refused with GRANT_SPENT. (#4722)
  • /ship's finish no longer reports the docs audit stale for a file that a clean follow-up check read and nothing changed since. (#4722)
  • An owner's approval for one more check after a pull request's second review round now lets /ship finish, whichever command recorded it. (#4717)
  • The stale-test-value check no longer flags tests of a different file that shares the changed file's name; a test counts only when one of its imports resolves to that file. (#4723)
  • /ship on a branch stacked on another branch can clear its remote test gate from a green CI run. (#4689)
  • /ship's final CI check accepts a green run that tested your branch merged onto a newer main when main changed none of your lines or the lines next to them, so busy repositories stop rerunning CI. (#4728)
  • A crashed gstack-ship-queue land --pin no longer blocks every later merge: its lock expires 90 minutes after its last step, and a lock whose process is gone is taken over. (#4712)
  • A /ship run that stopped or died no longer blocks the next /ship, and the new gstack-ship-run command shows a run's state and ends one that stopped working. (#4654)
  • A base branch whose review_exclude_paths list breaks the policy schema no longer stops every /ship: review covers every file and prints a warning, so the fixing pull request can land. (#4637)
  • A skipped or neutral CI run no longer blocks reuse of a passing run on the same commit. (#4695, #4713)
  • A CI job that runs only through a reusable workflow now counts only from a caller run that tested your exact commit. (#4713)
  • The local test gate reuses every green CI run at your exact code, not only the first one it checks. (#4671)
  • /ship no longer accepts a test-gate record taken against a different base branch. (#4706)
  • gstack-ship-queue ready checks a pull request against the branch it targets, not the repository's default branch. (#4663)
  • gstack-ship-queue ready fetches missing pull request heads in one go, prints progress and stops after 60 seconds instead of going silent for minutes. (#4668)
  • /ship can finish when its docs audit corrects a reviewed doc after the last review round. (#4708)
  • /ship can finish after a docs audit that stopped before saving its snapshot. (#4693)
  • /ship can finish when the docs audit ran before a merge from the base branch. (#4648)
  • /ship keeps a pull request's finished review after a base merge that only re-records a shared harness pin, and /ship warns when its reviewers ran without a logged review. (#4669)
  • A follow-up check that confirmed its blockers fixed now counts once the remaining findings are ruled. (#4691)
  • A follow-up check that reads an approved fix round clean now closes the findings that round fixed. (#4664)
  • A clean recheck of approved fixes counts even when its brief was written just before the review started. (#4698)
  • A fix commit's Review-Finding: trailer closes its finding only after a full review that finished with the fix in its range. (#4700)
  • /ship's bookkeeping holds up in three more cases: a harness pin turned into a symlink needs a fresh review, a claim that could not be saved says so, and earlier runs stay counted after a new description. (#4703)
  • /ship's review plan finishes on repositories with very large data or trial files, and GSTACK_REVIEW_CONSUMER_SCAN_CAP raises the data-file scan limit. (#4651, #4643)
  • GSTACK_REVIEW_PLAN_TIMEOUT_MS now raises the review-plan time limit at every step of /ship, so large repositories can finish. (#4632)
  • A repository's own test for review_exclude_paths no longer pulls excluded files back into review. (#4699)
  • Code review now reads the design checklist for frontend changes (it pointed at a missing file before), and the second-model review now reads code in your repository's own agents/ folder. (#4711)
  • /ship's review no longer reads a code name like "the HIGH branch" as a HIGH finding. (#4678)
  • Codex review findings written as numbered headings keep their severity. (#4681)
  • Seven small fixes to /ship's helper tools, including issue links that no longer turn Review-Finding: trailers into Refs lines. (#4672)

Other fixes

  • Defaults gstack picks for you now name current models in the design prototype script, Gemini cost labels and gstack-context-bill --exact. (#4678)
  • browse --session <name> <command> works with the flag before the command. (#4684)
  • The browse handoff window no longer opens with a stray blank tab. (#4684)
  • $D setup accepts Gemini keys that start with AQ.. (#4684)
  • /build-check trusts a repository's checks in every git worktree of it, so agent apps that start each session in a fresh worktree stop asking again. (#4684)
  • /context-restore finds Claude Code transcripts under CLAUDE_CONFIG_DIR and Codex sessions under CODEX_HOME. (#4684)
  • TypeScript hooks start on Windows when Git Bash leaves a path unconverted, such as a home folder with an apostrophe. (#4682)
  • ./setup --status passes on a --prefix install and names the command that clears each row it reports. (#4682)
  • ./setup no longer leaves owner-only files in Bun's shared package cache. (#4682)
  • Disabling /open-gstack-browser also removes its /connect-chrome alias. (#4682)
  • gstack-doctor no longer flags gstack's own CLAUDE.md as a pasted skill list. (#4682)
  • OpenClaw, Hermes and Dots registrations leave out skills turned off with disabled_skills. (#4682)
  • /autoplan's phase-report check works in sessions where Remote Control was on from the start. (#4681)
  • /ship sees every git worktree of a repository when it picks a version, so two worktrees can't take the same one. (#4681)
  • gstack-pr-shots --path compares against the real base branch when origin/HEAD points at the feature branch. (#4681)
  • When a reviewer's diff is too large, the suggested fix names only folders that review can actually leave out. (#4681)
  • The docs link check and prose check no longer read a line that starts with inline code as the start of a code block. (#4677)
  • /learn prune checks every learning, not just the first 100. (#4677)
  • /retro counts a test runner in tests/ with no test-style name and stops counting Godot and Unity sidecar files as tests. (#4677)
  • Deleting or renaming a test now checks the files that still list it, even when another test covers it. (#4702)
  • Playwright specs that take test from a local fixtures file run under playwright test. (#4702)
  • The changed-constant check no longer floods on one- and two-digit numbers. (#4683)
  • gstack-gbrain-mcp-verify no longer misreads a large or slow server-sent-events reply as broken. (#4710)
  • gbrain memory lookups find their pages: no more double imports, "Related from memory" hits work on a cloned brain host, and oversized logs keep their newest rows. (#4685)
  • Eight skill fixes reported by users, including the Aside check asking you to open Aside, /test-audit finding the eng-review test plan, and /design-shotgun passing the reason for each pick. (#4686)

What's new

  • The prompt-routing hook no longer names your bug-fix skill on bug reports: in a preregistered test on 183 real Python bugs it got the skill's steps followed but fixed no more bugs. It still routes /review and /qa, and never routes a message from another Claude Code session or a background agent's hand-back. (#4707, #4674, #4694)
  • Review can leave out copied open-source files that gstack-vendored-verify proves byte-for-byte equal to a pinned upstream commit; list the upstreams in review_vendored. (#4646, #4665, #4690)
  • gstack-ship-queue land can run full CI on the merged tree before it lands a pull request whose base moved (land.merged_ci), and main's push run reuses that result instead of testing again. (#4649, #4655)
  • gstack-ship-queue count prints how many finished pull requests are waiting to merge. (#4712)
  • On Capy, the second-model review in /ship and /review defaults to GPT-6.2 Sol. (#4636)
  • On Capy, /ship runs in the pull request's own thread and starts its reviewers as subagents, with no separate helper agent. (#4670)
  • /eval-plan refuses gpt-4o and older-generation models in every role a plan chooses, and plans frozen on or after 2026-11-22 check a model judge against 100 hand labels. (#4630)
  • /eval-plan's dry run follows the plan's own dates and declared vendor models, and new plans name how their grader treats the agent's repository. (#4673)
  • /plan-ceo-review explains its review-mode recommendation by what that mode does that the next-closest mode wouldn't. (#4730)
  • Skills that declare gbrain context queries load them at start; gstack-config set gbrain_context_load off turns it off. (#4687)
  • gstack-harness status reports unknown with the error when a harness's skill list fails, instead of listing every skill as missing. (#4687)
  • Test selection follows TypeScript NodeNext .js imports to their .ts source and maps Rails app/ and lib/ files to their specs. (#4679)
  • Published the results of two tests of /ship: running it in the pull request's own thread made no clear difference in cost or bugs caught (#4680), and its review panel beat two plain review reads, so it stays (#4676, #4732).

Changes for maintainers

  • Every gstack pull request gets a Test changes summary of deleted or skipped tests, loosened limits and edits to its own checks, as a two-week trial that never fails a pull request. (#4645)
  • A weekly Mutation report lists small wrong edits gstack's tests fail to catch. (#4652)
  • Flaky and slow test fixes: free test shards survive a browser that exits during cleanup (#4666), nightly Windows shards stay under their time limit (#4661), weekly test health passes again (#4633), and two git worktree races no longer fail each other (#4710).
  • Release-check fixes: the recommendation judge's calibration includes two real questions (#4705), the /autoplan guard test keeps its Claude Haiku 4.5 actor (#4639), and the docs-audit tests accept /ship's step for a stopped audit (#4731).
  • The bootstrap retention tests skip five cases that can't happen when the suite runs as root. (#4677)
  • Removed a sentence the revert drill added to its own docs. (#4716)
