gstack v1.101.0.0

gstack v1.101.0.0

¿Qué hay de nuevo?

  • Antes de que se te pida que pruebes la compilación de una aplicación, el nuevo comando gstack-first-use hace que un agente de otra familia de modelos juegue, construye en el mismo tipo de dispositivo y verifica las primeras cinco cosas que harás con él. (#4465)
  • Antes de que un agente le haga una pregunta a su propietario, gstack-owner-answers puede comparar el borrador con las respuestas anteriores del propietario y sugerir eliminar solo las líneas que ya cubre un sí existente. (#4467)
  • Los GitHub release note ahora enumeran cada cambio en palabras sencillas, con un enlace a su solicitud de extracción. (#4390)
  • Cuando otro agente conduce/envía paso a paso, cada fase ahora se ejecuta como un comando, las llamadas se cuentan y la ejecución se detiene sola después de 100 minutos. (#4451)
  • El paso de empuje de /ship ahora siempre termina con una línea PUSH: que dice si empujó; Si un script coincide con las antiguas líneas PUSH:, actualícelo. (#4474)
  • El plan de revisión de /ship ahora envía un código Swift que solicita permisos de privacidad o toca salud, calendario, contactos o archivos del dispositivo al panel de revisión completo. (#4472)
  • gstack-autoplan revise --plan con un archivo diferente ahora dice que la ejecución sigue a ese archivo. (#4470)
  • /office-hours explica por qué recomienda un modo, citando sus propias palabras. (#4450)
  • /office-hours mantiene sus 34 videos y ensayos del fundador fuera del archivo de habilidades, por lo que la habilidad es aproximadamente 8.6 KB más pequeña. (#4463)
  • Desatendido /autoplan ahora ejecuta la revisión del segundo modelo que activó y la espera en lugar de finalizar la sesión. (#4459)

Seguridad

  • El archivo, la línea y el motivo de un hallazgo de seguridad ya no aparecen en la descripción de una solicitud de extracción; muestra una identificación opaca y los detalles permanecen en el registro de aprobación privado. (#4486)
  • La verificación de secretos ahora detecta un secreto creado a partir de fragmentos cortos con + o escrito en un comentario, y deja de marcar tres tipos de código ordinario. (#4457)

Correcciones

  • /ship con un límite de token en Claude Code ya no se detiene en su primera transferencia: la nueva sesión ahora recibe su mensaje. Gracias @exGeni. (#4452)
  • En Claude Code, el mensaje de esa sesión de transferencia ahora comienza con el comando /ship escrito, por lo que la habilidad realmente se carga. (#4487)
  • /ship ya no se detiene para la aprobación del propietario cuando se fusiona la base, solo se cambia el texto del lado de la base. (#4458)
  • La prosa confirmatoria de un crítico ya no se convierte en un hallazgo crítico que sólo el propietario puede aclarar. (#4458)
  • Cuando /ship se detiene en su límite de rondas de revisión y el propietario permite una ronda más, esa ronda ahora paga por corregir los hallazgos en lugar de otra revisión de solo lectura. (#4479)
  • /ship en Codex ya no se detiene en la auditoría de cobertura de pruebas: las habilidades de Codex ahora inician sus subagentes de auditoría y revisor con las propias herramientas de Codex (active multi_agent = true en [features] en ~/.codex/config.toml). (#4489)
  • /ship ya no informa cero bloqueadores cuando la revisión del segundo modelo encontró uno, y no finalizará mientras ese bloqueador esté abierto. (#4485)
  • Cuando /ship publica una descripción de solicitud de extracción, el recuento de rondas de revisión anteriores ahora siempre proviene del historial real del RP; una descripción que contenga bloques históricos adicionales podría hacer que gstack cuente una ronda donde había tres. (#4440)
  • gstack-post ya no marca los ID de ejecución y los ID de confirmación de /ship como números de teléfono, por lo que publicar una descripción de solicitud de extracción de /ship ya no necesita confirmación. (#4488)
  • El plan de revisión de /ship ahora clasifica los archivos Swift y Xcode por riesgo en lugar de enviar cada solicitud de extracción de iOS al panel de revisión completo. (#4469)
  • La selección de prueba previa al envío de /ship ahora encuentra las pruebas de una aplicación monorepo que importa a través de su propio alias @/. Gracias @dtoelke. (#4464)
  • Una prueba o un repositorio temporal en el directorio temporal ya no puede escribir filas de aprobación en su Capy Drive real. (#4466)
  • El enrutador de gstack ya no da una regla especial a los informes de errores, por lo que el modelo corrige un error de la misma manera que lo haría sin gstack; En Claude Code, un informe de error tampoco carga el enrutador. (#4442)
  • Una ejecución desatendida/autoplan en Claude Code ya no informa que su protección de fase está apagada mientras está encendida, y un informe de fase escrito solo en razonamiento ahora recibe una denegación que indica la solución. (#4481)
  • gstack-autoplan revise ya no rechaza un plan que aceptó el primer next. (#4470)
  • Una revisión del plan del segundo modelo en /autoplan ya no se informa como no disponible cuando realmente se ejecutó. (#4471)
  • Desatendido /autoplan ahora registra la respuesta transmitida por el propietario a su pregunta final en lugar de rechazarla. (#4484)
  • Dos ejecuciones de /autoplan iniciadas en el mismo segundo ya no comparten una identificación de ejecución. (#4459)
  • Dos ejecuciones de gstack-owner-answers add para la misma respuesta ya no chocan. (#4490)
  • skill_prefix=true ahora sobrevive a las actualizaciones cuando se instala gbrain. Gracias @fliaron. (#4454)
  • Los documentos de OpenClaw ya no te envían a ClawHub, que actualmente no tiene habilidades de gstack; apuntan a ./setup --host openclaw. Gracias @exGeni. (#4454)
  • gstack-issue-links ya no lee los issues de otros repositorios como si fueran de gstack. (#4454)
  • /sync-gbrain ya no dice OK cuando las páginas no se pudieron importar o falló la inserción de artefactos, y una ruta en cola con formato incorrecto ya no detiene la sincronización de artefactos para cada proyecto. (#4455)
  • Empacar un pago para una ejecución de Ubicloud ya no falla cuando git reescribe una referencia al lado. (#4447)
  • Con un proveedor de Codex personalizado, la verificación de preparación del Codex y la revisión del segundo modelo ahora eligen el mismo modelo: el model del proveedor en ~/.codex/config.toml cuenta solo cuando es el modelo del nivel de revisión (gpt-6-astra para el nivel fronterizo), y ambos rechazan cualquier otro nombre por el mismo motivo. En el proveedor estándar de OpenAI, la revisión del segundo modelo en /autoplan y /spec ahora usa el modelo del nivel de revisión en lugar del config.toml. (#4491)
  • gstack-artifact validate y ack ahora rechazan un /autoplan run.json que gstack-autoplan no escribió, o cuyo diario, resultados de revisión o punto de control no están de acuerdo con él. (#4494)

Cambios para mantenedores

  • Una ejecución de CI que se aprobó solo después de que se volvieron a ejecutar sus trabajos fallidos ahora se marca como tal siempre que gstack la reutilice. (#4473)
  • /ship reutiliza la ejecución de prueba de CI cuando se fusiona la base sin cambios y se detiene en lugar de iniciar silenciosamente ejecuciones de prueba locales de una hora de duración o revisar una diferencia vacía. (#4461)
  • Un plan prerregistrado para pruebas/envío sin su subagente coordinador independiente. (#4456)
  • Ese plan ahora permite que los casos que revierten el conflicto con el código posterior se resuelvan manualmente. (#4460)
  • CI carga los resultados de las pruebas del paquete gratuito en Trunk con el cargador de análisis v2.1.8 y el análisis-cli 0.17.0. (#4453)
  • Una prueba de nivel de políticas ya no falla una vez que la propia versión de gstack alcanza la versión menor después de la clave de política más nueva. (#4495)
  • La evaluación /plan-ceo-review HOLD SCOPE ya no falla una revisión porque su pregunta de seguimiento no repitió el nombre del modo. (#4447) Comparar v1.100.0.0...v1.101.0.0 · Completo changelog

gstack v1.101.0.0

gstack v1.101.0.0

What's new

  • Before you're asked to try an app build, the new gstack-first-use command has an agent from another model family play that build on the same kind of device and check the first five things you'll do with it. (#4465)
  • Before an agent asks its owner a question, gstack-owner-answers can check the draft against the owner's earlier answers and suggest dropping only the lines an existing standing yes already covers. (#4467)
  • GitHub release notes now list every change in plain words, with a link to its pull request. (#4390)
  • When another agent drives /ship step by step, each phase now runs as one command, the calls are counted, and the run stops itself after 100 minutes. (#4451)
  • /ship's push step now always ends with one PUSH: line that says whether it pushed; if a script matched the old PUSH: lines, update it. (#4474)
  • /ship's review plan now sends Swift code that asks for privacy permissions or touches health, calendar, contacts or on-device files to the full review panel. (#4472)
  • gstack-autoplan revise --plan with a different file now says the run follows that file. (#4470)
  • /office-hours explains why it recommends a mode, quoting your own words. (#4450)
  • /office-hours keeps its 34 founder videos and essays out of the skill file, so the skill is about 8.6 KB smaller. (#4463)
  • Unattended /autoplan now runs the second-model review you turned on, and waits for it instead of ending the session. (#4459)

Security

  • A security finding's file, line and reason no longer appear in a pull request description; it shows an opaque id and the details stay in the private approval record. (#4486)
  • The secrets check now catches a secret built from short pieces with + or written in a comment, and stops flagging three kinds of ordinary code. (#4457)

Fixes

  • /ship with a token cap on Claude Code no longer stops at its first handoff: the new session now receives its prompt. Thanks @exGeni. (#4452)
  • On Claude Code, that handoff session's prompt now starts with the typed /ship command, so the skill actually loads. (#4487)
  • /ship no longer stops for an owner's sign-off when merging the base only changed base-side text. (#4458)
  • A reviewer's confirming prose no longer becomes a Critical finding that only an owner can clear. (#4458)
  • When /ship stops at its review-round limit and the owner allows one more round, that round now pays for fixing the findings instead of another read-only review. (#4479)
  • /ship on Codex no longer stops at the test coverage audit: Codex skills now start their audit and reviewer subagents with Codex's own tools (turn on multi_agent = true under [features] in ~/.codex/config.toml). (#4489)
  • /ship no longer reports zero blockers when the second-model review found one, and won't finish while that blocker is open. (#4485)
  • When /ship posts a pull request description, the count of earlier review rounds now always comes from the PR's real history; a description carrying extra history blocks could make gstack count one round where there were three. (#4440)
  • gstack-post no longer flags /ship's own run ids and commit ids as phone numbers, so posting a /ship pull request description no longer needs a confirm. (#4488)
  • /ship's review plan now sorts Swift and Xcode files by risk instead of sending every iOS pull request to the full review panel. (#4469)
  • /ship's pre-push test selection now finds the tests of a monorepo app that imports through its own @/ alias. Thanks @dtoelke. (#4464)
  • A test, or a scratch repository in the temp directory, can no longer write approval rows into your real Capy Drive. (#4466)
  • gstack's router no longer gives bug reports a special rule, so the model fixes a bug the way it would without gstack; on Claude Code, a bug report also no longer loads the router. (#4442)
  • An unattended /autoplan run on Claude Code no longer reports its phase guard as off while it is on, and a phase report written only in reasoning now gets a denial that names the fix. (#4481)
  • gstack-autoplan revise no longer refuses a plan that the first next accepted. (#4470)
  • A second-model plan review in /autoplan is no longer reported as unavailable when it actually ran. (#4471)
  • Unattended /autoplan now records the owner's relayed answer to its final question instead of refusing it. (#4484)
  • Two /autoplan runs started in the same second no longer share a run id. (#4459)
  • Two gstack-owner-answers add runs for the same answer no longer collide. (#4490)
  • skill_prefix=true now survives updates when gbrain is installed. Thanks @fliaron. (#4454)
  • The OpenClaw docs no longer send you to ClawHub, which has no current gstack skills; they point to ./setup --host openclaw. Thanks @exGeni. (#4454)
  • gstack-issue-links no longer reads other repositories' issues as gstack's. (#4454)
  • /sync-gbrain no longer says OK when pages failed to import or an artifacts push failed, and one malformed queued path no longer stops artifacts sync for every project. (#4455)
  • Packing a checkout for a Ubicloud run no longer fails when git is rewriting a ref beside it. (#4447)
  • With a custom Codex provider, the Codex readiness check and the second-model review now pick the same model: the provider's model in ~/.codex/config.toml counts only when it is the review tier's model (gpt-6-astra for the frontier tier), and both refuse any other name with the same reason. On the stock OpenAI provider, the second-model review in /autoplan and /spec now uses the review tier's model instead of config.toml's. (#4491)
  • gstack-artifact validate and ack now refuse an /autoplan run.json that gstack-autoplan didn't write, or whose journal, review outputs or checkpoint disagree with it. (#4494)

Changes for maintainers

  • A CI run that passed only after its failed jobs were re-run is now marked as such wherever gstack reuses it. (#4473)
  • /ship reuses CI's passing test run when merging the base changed no file, and stops instead of quietly starting hour-long local test runs or reviewing an empty diff. (#4461)
  • A preregistered plan for testing /ship without its separate coordinating subagent. (#4456)
  • That plan now lets case reverts that conflict with later code be resolved by hand. (#4460)
  • CI uploads free-suite test results to Trunk with analytics-uploader v2.1.8 and analytics-cli 0.17.0. (#4453)
  • A policy-floor test no longer fails once gstack's own version reaches the minor release after the newest policy key. (#4495)
  • The /plan-ceo-review HOLD SCOPE eval no longer fails a review because its follow-up question didn't repeat the mode name. (#4447)
