gstack v1.102.1.0

gstack 1.102.1.0 cierra una brecha donde un secreto escrito después de una barra diagonal podría imprimirse sin ocultarse, bloquea los informes de uso de gstack y lo hace más útil para las personas que optan por suscribirse, corrige una serie de errores en cómo gstack elige la habilidad correcta para un aviso y hace que el paso inicial de una habilidad de gstack se ejecute cuando Claude Code carga la habilidad, por lo que no se puede omitir. Informes de uso (telemetría, suscripción voluntaria)

  • El backend de informes de uso ahora acepta datos solo a través de su propio punto final verificado: la clave pública en el repositorio ya no puede leer ni escribir las tablas, y a un usuario de Supabase que haya iniciado sesión se le niega todo. Las propias ejecuciones de prueba de gstack nunca envían datos de uso, el tráfico de prueba queda fuera de gstack-community-dashboard y su recuento activo semanal ahora cuenta las instalaciones reales en lugar de las comprobaciones de actualizaciones. Las versiones de gstack anteriores a v0.11.16.0 (marzo de 2026) dejan de enviar datos de uso porque escribieron directamente en las tablas. (#4537)
  • Si opta por participar, cada ejecución de habilidad ahora también envía nueve campos nuevos, cada uno de los cuales es una selección de una lista fija: qué agente de codificación lo ejecutó, la familia de modelos, si usted, el modelo u otra habilidad lo inició, por qué terminó, si sus propias comprobaciones pasaron, si la sección de enrutamiento y los enlaces de gstack están configurados, una identificación de sesión aleatoria y, para las actualizaciones, la versión de la que vino y por qué falló una actualización. Las ejecuciones desde CI y las propias evaluaciones de gstack se etiquetan a sí mismas, y una duración que gstack no pudo medir se envía vacía en lugar de 0. La pregunta de participación voluntaria enumera los nuevos campos, y el modo anónimo ahora dice que envía "sin ID de dispositivo; una identificación aleatoria por sesión de agente que nunca se reutiliza". Ningún campo contiene código, rutas de archivo, mensajes o nombres de repositorio; Cada campo aparece en docs/privacy.md. (#4542) Habilidades y sugerencias de habilidades
  • En Claude Code, el paso de inicio de cada habilidad de gstack ahora se ejecuta mientras se carga la habilidad, por lo que el modelo ya no puede omitirlo (en las ejecuciones de prueba, los modelos habían seguido el paso de inicio de una habilidad cargada en solo entre el 45% y el 62% de las sesiones). Si la carga falla, la habilidad lo indica en una línea y el modelo ejecuta el paso inicial, como antes. Codex y otros agentes conservan las instrucciones antiguas. (#4509) La prueba paga de gstack que verifica este paso de inicio ahora cuenta uno que se ejecutó durante la carga. (#4543)
  • Cuando un mensaje se lee como un informe de error, el gancho de sugerencia de habilidades ahora nombra solo la habilidad de corrección de errores instalada y nunca sugiere/verificar antes de ella. En 60 mensajes reales de corrección de errores, ahora nombra la habilidad de corrección de errores en los 46 informes de errores. (#4539)
  • El gancho de sugerencia de habilidades ahora ignora las palabras dentro de las comillas invertidas y los bloques de código, por lo que un comando entre comillas como "Ejecutar gh pr review 123" ya no activa /revisa, y una bandera --fix en un registro pegado ya no hace que un mensaje parezca un informe de error. Gracias a @ vilano93, quien lo encontró y lo solucionó primero. (#4566)
  • gstack ahora le indica en una línea lo que está a punto de agregar antes de instalar un trabajo en segundo plano (gbrain autopilot) o la extensión del navegador gstack, incluido cómo eliminarlo. Una nueva prueba falla si un paso de instalación futuro deja esa línea fuera. (#4538) Seguridad y protección
  • La verificación de comando destructivo (/careful) cierra más formas de evitar sus bloques de borrado de disco y empuje forzado: wipefs -a está bloqueado en cada objetivo y, en más grafías, una escritura en un disco se bloquea cuando se cita su ruta o pasa por un enlace a /dev, y git push -fn --no-dry-run cuenta como un empuje forzado real. Ahora no se permite nada de lo que se bloqueó o preguntó antes. (#4534)
  • /cso ahora puede auditar repositorios que contienen enlaces simbólicos. Enumera cada enlace y su destino en el informe y nunca lo sigue, mientras que antes un solo enlace (incluso CLAUDE.md -> AGENTS.md) detenía la auditoría. Gracias a @nathanshox por el informe y la primera solución. (#4567)
  • El ocultador secreto de gstack ahora también oculta una contraseña, clave API o token escrito como name=value después de una barra (como cfg/api_key=… o https://host/cb/token=…), mientras que antes solo los detectaba al comienzo de una línea. El informe histórico de /cso había impreso dichos valores; Este y todos los demás lugares donde gstack oculta secretos (material de revisión, datos de uso, registros de envío) ahora los ocultan. (#4571) /revisión de envío y código
  • Una ejecución de CI verde todavía cuenta para /enviar y fusionar cuando GitHub se niega a almacenar los archivos de la ejecución porque el almacenamiento del repositorio está lleno: gstack ahora puede leer el mismo registro del registro del trabajo, bajo las mismas comprobaciones. (#4536)
  • /ship ahora se detiene y le indica qué hacer cuando la ejecución de prueba anterior de CI no se puede reutilizar, en lugar de iniciar todo el conjunto de pruebas en su máquina. (#4565)
  • Cuando el propietario dictamina que los hallazgos de una revisión detenida son aceptables como notas abiertas, esas resoluciones ahora permiten que /ship termine (n.° 4552), el registro de revisión indica qué hallazgos aún están esperando una resolución (n.° 4553) y las resoluciones también funcionan cuando los hallazgos de la revisión se guardaron en un archivo separado (n.° 4568).
  • Una solicitud de extracción que agrega solo el plan de una evaluación y sus archivos de datos simples (un registro previo) ahora obtiene la revisión más ligera de un revisor destinada a redacciones, y las filas de datos ya no cuentan como líneas de código cuando gstack dimensiona una revisión. (#4544)
  • Los identificadores de ejecución en los registros de aprobación de /ship, como 507-7192673, ya no se confunden con números de teléfono ni se bloquean, y un equipo cuyo nombre comienza con "GStack" puede registrar las decisiones. (#4549) Navegador y pruebas
  • El asistente del navegador ya no elige el puerto 10080, que Chrome se niega a abrir, por lo que aproximadamente un inicio entre 39.000 ya no falla al cargar sus propias páginas; También se solucionó una prueba inestable. (#4554)
  • La evaluación de sincronización de documentación de gstack ya no falla cuando /ship repara la línea de resultados de un revisor de la manera permitida. (#4555)
  • Para las personas que trabajan en gstack: cada prueba que falló y luego pasó en su reintento en las ejecuciones de prueba gratuitas de gstack ahora se registra, incluidas las ejecuciones iniciadas manualmente en una rama, por lo que las pruebas inestables se cuentan y reparan. (#4572)
  • Para las personas que trabajan en gstack: las ejecuciones de pruebas en solicitudes de extracción comienzan un paso antes, porque el trabajo que divide las pruebas ahora se ejecuta junto con las comprobaciones anteriores en lugar de después de ellas. (#4570)

gstack v1.102.1.0

gstack 1.102.1.0 closes a gap where a secret written after a slash could be printed unhidden, locks down gstack's usage reporting and makes it more useful for people who opt in, fixes a set of bugs in how gstack picks the right skill for a prompt, and makes a gstack skill's start step run as Claude Code loads the skill, so it can't be skipped.

Usage reporting (telemetry, opt-in)

  • The usage-reporting backend now accepts data only through its own checked endpoint: the public key in the repo can no longer read or write the tables, and a signed-in Supabase user is denied everything. gstack's own test runs never send usage data, test traffic is left out of gstack-community-dashboard, and its weekly active count now counts real installs instead of update checks. gstack versions older than v0.11.16.0 (March 2026) stop sending usage data, because they wrote straight to the tables. (#4537)
  • If you opt in, each skill run now also sends nine new fields, each a pick from a fixed list: which coding agent ran it, the model family, whether you, the model or another skill started it, why it ended, whether its own checks passed, whether gstack's routing section and hooks are set up, a random session id, and for upgrades the version you came from and why an upgrade failed. Runs from CI and gstack's own evals label themselves, and a duration gstack couldn't measure is sent empty instead of 0. The opt-in question lists the new fields, and anonymous mode now says it sends "no device ID; a random id per agent session that is never reused". No field carries code, file paths, prompts or repo names; every field is listed in docs/privacy.md. (#4542)

Skills and skill suggestions

  • In Claude Code, each gstack skill's start step now runs while the skill loads, so the model can no longer skip it (in test runs, models had followed a loaded skill's start step in only 45% to 62% of sessions). If loading fails, the skill says so in one line and the model runs the start step itself, as before. Codex and other agents keep the old instructions. (#4509) gstack's paid test that checks this start step now counts one that ran during loading. (#4543)
  • When a prompt reads like a bug report, the skill-suggestion hook now names your installed bug-fix skill alone and never suggests /verify ahead of it. On 60 real bug-fix prompts it now names the bug-fix skill on all 46 bug reports. (#4539)
  • The skill-suggestion hook now ignores words inside backticks and code blocks, so a quoted command such as "Run gh pr review 123" no longer triggers /review, and a --fix flag in a pasted log no longer makes a prompt look like a bug report. Thanks to @vilano93, who found and first fixed it. (#4566)
  • gstack now tells you in one line what it's about to add before it installs a background job (gbrain autopilot) or the gstack browser extension, including how to remove it. A new test fails if a future install step leaves that line out. (#4538)

Safety and security

  • The destructive-command check (/careful) closes more ways around its disk-wipe and force-push blocks: wipefs -a is blocked on every target and in more spellings, a write into a disk is blocked when its path is quoted or goes through a link to /dev, and git push -fn --no-dry-run counts as a real force-push. Nothing that was blocked or asked about before is allowed now. (#4534)
  • /cso can now audit repositories that contain symbolic links. It lists each link and its target in the report and never follows it, where before a single link (even CLAUDE.md -> AGENTS.md) stopped the audit. Thanks to @nathanshox for the report and first fix. (#4567)
  • gstack's secret hider now also hides a password, API key or token written as name=value after a slash (such as cfg/api_key=… or https://host/cb/token=…), where before it caught them only at the start of a line. /cso's history report had printed such values; it and every other place gstack hides secrets (review material, usage data, /ship logs) now hide them. (#4571)

/ship and code review

  • A green CI run still counts toward /ship and merging when GitHub refuses to store the run's files because the repository's storage is full: gstack can now read the same record from the job's log, under the same checks. (#4536)
  • /ship now stops and tells you what to do when CI's earlier test run can't be reused, instead of starting the whole test suite on your machine. (#4565)
  • When the owner rules a stopped review's findings acceptable as open notes, those rulings now let /ship finish (#4552), the review record says which findings are still waiting for a ruling (#4553), and rulings also work when the review's findings were saved in a separate file (#4568).
  • A pull request that adds only an eval's plan and its plain data files (a preregistration) now gets the lighter one-reviewer review meant for write-ups, and rows of data no longer count as lines of code when gstack sizes a review. (#4544)
  • Run ids in /ship's approval records, such as 507-7192673, are no longer mistaken for phone numbers and blocked, and a team whose name starts with "GStack" can record rulings. (#4549)

Browser and tests

  • The browser helper no longer picks port 10080, which Chrome refuses to open, so about one start in 39,000 no longer fails to load its own pages; one flaky test was fixed too. (#4554)
  • gstack's documentation-sync eval no longer fails when /ship repairs a reviewer's result line in the allowed way. (#4555)
  • For people working on gstack: every test that failed and then passed on its retry in gstack's free test runs is now recorded, including runs started by hand on a branch, so flaky tests get counted and fixed. (#4572)
  • For people working on gstack: test runs on pull requests start one step sooner, because the job that splits the tests now runs alongside the earlier checks instead of after them. (#4570)
