gstack v1.97.0.0

gstack v1.97.0.0

Principalmente /ship, el comando de gstack que revisa, prueba y abre una solicitud de extracción para usted: menos rondas de revisión adicionales innecesarias, auditorías que siguen su preferencia de modelo, dos puertas de participación voluntaria que mantienen a /investigate y /plan-ceo-review en su paso clave y una solución de seguridad para el navegador.

¿Qué hay de nuevo?

  • Una puerta de suscripción para /plan-ceo-review evita que la sesión finalice hasta que la revisión haya escrito sus hallazgos clasificados; enciéndalo con ./setup --ceo-review-gate #4047.
  • Una puerta de suscripción voluntaria para /investigate bloquea una solución hasta que se anota la causa raíz, incluidas las correcciones realizadas mediante comandos de shell; enciéndalo con ./setup --investigate-gate #4045.
  • Si sigue el canal de actualización estable, las correcciones importantes (seguridad, regresiones, pérdida de datos, bloqueadores) ahora se estabilizan en un día, y la estabilidad nunca está más de una semana por detrás de los cambios probados en la página principal #4083.

Correcciones

  • Seguridad: el navegador incluido de gstack ahora usa Playwright 1.65.0 con Chromium 158, que ya no es rust para las autoridades de certificación de eMudhra comprometidas #4087.
  • El registro de auditoría de exploración ya no guarda lo que escribe en las páginas, como las contraseñas enviadas con fill o type, las respuestas de los diálogos y los valores de las cookies o del encabezado. Reportado por @derHaken #4073, #4081.
  • El registro de auditoría de navegación y el registro de red ya no mantienen los valores de consulta de URL ni las credenciales, por lo que los campos de un formulario de inicio de sesión enviado permanecen fuera del disco #4082.
  • gstack-brain-sync ya no considera un envío rechazado como un error de autenticación solo porque la URL de su control remoto contiene una palabra como auth o 403, por lo que vuelve a intentar el envío como debería #4035.
  • El demonio de exploración ya no falla con "¿Está el puerto... en uso?" en una máquina ocupada; ahora elige su puerto justo antes de comenzar a escuchar #4035.
  • El escaneo secreto de gstack ya no marca código ordinario como config.prod o server.local(...) como un nombre de host interno filtrado, gracias @nazarli-shabnam #4043.
  • Los documentos de /ship, la cobertura de pruebas y las auditorías de planes ahora se ejecutan en el modelo que usted establece en sus preferencias en lugar de siempre en Sonnet 5.5 #4038, #4042.
  • /ship ya no solicita otra ronda de revisión cuando su propia auditoría de documentos edita archivos después de la revisión, incluso cuando la auditoría se ejecuta dos veces #4034, #4071.
  • Agregar patrones review_exclude_paths en su rama principal ya no obliga a abrir las solicitudes de extracción a través de revisión nuevamente cuando ninguno de sus archivos coincide con #4030, #4036, #4041.
  • Todos los revisores de /ship ahora ven la misma diferencia recortada, incluido un revisor cuyas instrucciones se reconstruyeron por su cuenta después de un inicio fallido #4048.
  • La planificación de la revisión de /ship finaliza en aproximadamente 35 segundos en repositorios de resultados muy grandes en lugar de expirar #4040.
  • Las solicitudes de extracción de resultados llenas de mensajes de modelo capturados ya no alcanzan el límite de tamaño de revisión del envío solo porque esos mensajes mencionan variables clave API #4044.
  • /ship y /review ya no cuentan la frase final de un revisor como "Ninguno de estos alcanza el nivel CRÍTICO". como hallazgo crítico #4075.
  • Una solicitud de extracción apilada cuyo padre fue fusionado ya no tiene los cambios propios de /ship flag main como ediciones no revisadas #4021.
  • /ship ya no se atasca cuando se agrega una línea de documentos con un reclamo de dinero, seguridad o numérico después de finalizar la revisión #4062.
  • /ship ya no se atasca después de una combinación de bases que cambia una línea revisada y mueve el código a su lado; ahora solicita una pequeña nueva verificación #4054.
  • /ship ya no solicita una nueva revisión cuando una combinación de bases solo supera una versión o número de reglas que su política de envío declara como mecánica #4053.
  • /ship ya no se detiene en un archivo Godot .uid agregado después de la revisión, y su política de envío ahora puede nombrar sus propios archivos de prueba #4063.
  • Una política de envío cuya versión mínima de gstack sea más reciente que la última versión estable ahora se rechaza por nombre, en lugar de enviar sesiones a una actualización que no puede satisfacerla #4080.
  • La verificación "probar nuevamente después de la última edición" de /investigate ahora detecta correcciones escritas mediante comandos de shell como sed -i o un documento heredoc #4078.
  • Las puertas /investigate y /plan-ceo-review ya no permiten que una sesión finalice sin marcar cuando su análisis se ejecuta lentamente #4072.
  • /runaway-stopper ya no marca a los agentes que se registran cada cuatro minutos mientras esperan en CI como fugitivos #4069.
  • El corredor de Ubicloud detrás de /ubicloud nunca trata un error API como un éxito y nunca destruye una VM que otra persona que llama creó con el mismo nombre #4039, #4046.

Cambios para mantenedores

  • Los pasos de finalización y aceptación del barco manejan mejor las rondas de reparación otorgadas por el propietario: todas las comprobaciones de reparación encadenadas cuentan, una ronda concedida actualiza el dinero y la seguridad se vuelve a leer por sí sola, las notas regidas por el propietario cierran sus hallazgos y el resultado nombra la concesión que utilizó #4050, #4064, #4070, #4077.
  • El registro de relectura de dinero y seguridad sobrevive a una fusión principal posterior y la aceptación toma su límite de espera de CI de la política de envío base (ci_record_timeout_s) #4058, #4065.
  • aceptar verifica una sucursal bajo su propia política de prueba cuando esa sucursal solo agrega ejecuciones de prueba y un propietario puede otorgar una excepción para una ejecución de prueba #4061.
  • Las nuevas claves de política de envío mechanical_retake y test_code requieren gstack 1.97.0.0 #4079.
  • En Capy, los comandos /ship helper ahora registran sus propias llamadas para que se conozca el recuento de llamadas de una ejecución #4059.
  • El propio repositorio de gstack ahora ejecuta una verificación de versión paga en main cada 8 horas, vuelve a probar una solicitud de extracción fusionada en la sugerencia de main antes de fusionarla cuando main se ha movido, y los archivos de prueba omitidos por CI se vuelven a ejecutar antes de la fusión #4031, #4029, #4028.
  • El paso de fusión oculta su propio entorno, incluido el token GitHub, de las comprobaciones que ejecuta en Linux #4032.
  • La verificación del archivo de lanzamiento acepta una salida de lanzamiento que la herramienta de lanzamiento del repositorio regenera #4033.
  • Una solicitud de extracción que edita setup ya no ejecuta todos los casos de evaluación paga en una pantalla estrecha #4056.
  • La advertencia de fragmentación lenta de CI gratuito ahora tiene en cuenta los fragmentos divididos en trabajos paralelos, gracias @indraoverflow #4085.
  • Reparaciones de prueba: dos archivos de prueba ahora pasan en un proceso y cuatro pruebas inestables informan por qué fallaron #4068, #4074.
  • El inventario de pruebas registra los últimos veredictos de evaluación de ruta e investigación #4076.
  • gstack ahora genera una edición de carga bajo demanda de tres habilidades (investigar, revisar y planificar revisión) para otro agente host #4049.
  • Documentos de agentes: los agentes en Capy comentan y solicitan revisiones solo a través de las herramientas de relaciones públicas de Capy, los agentes ejecutan /ship sleep hasta que finaliza y mantienen su contexto pequeño, y AGENTS.md enumera las habilidades solo por nombre #4027, #4055, #4060. gstack v1.97.0.0

gstack v1.97.0.0

Mostly /ship, gstack's command that reviews, tests and opens a pull request for you: fewer needless extra review rounds, audits that follow your model preference, two opt-in gates that hold /investigate and /plan-ceo-review to their key step, and a browser security fix.

What's new

  • An opt-in gate for /plan-ceo-review keeps the session from finishing until the review has written its ranked findings; turn it on with ./setup --ceo-review-gate #4047.
  • An opt-in gate for /investigate blocks a fix until a root cause is written down, including fixes made through shell commands; turn it on with ./setup --investigate-gate #4045.
  • If you follow the stable update channel, important fixes (security, regressions, data loss, blockers) now reach stable within a day, and stable is never more than a week behind tested changes on main #4083.

Fixes

  • Security: gstack's bundled browser now uses Playwright 1.65.0 with Chromium 158, which no longer trusts the compromised eMudhra certificate authorities #4087.
  • The browse audit log no longer saves what you type into pages, such as passwords sent with fill or type, dialog answers, and cookie or header values. Reported by @derHaken #4073, #4081.
  • The browse audit log and network log no longer keep URL query values or credentials, so a submitted login form's fields stay off disk #4082.
  • gstack-brain-sync no longer calls a rejected push an auth error just because your remote's URL contains a word like auth or 403, so it retries the push as it should #4035.
  • The browse daemon no longer fails with "Is port … in use?" on a busy machine; it now picks its port right before it starts listening #4035.
  • gstack's secret scan no longer flags ordinary code such as config.prod or server.local(...) as a leaked internal hostname, thanks @nazarli-shabnam #4043.
  • /ship's docs, test-coverage and plan audits now run on the model you set in your preferences instead of always on Sonnet 5.5 #4038, #4042.
  • /ship no longer asks for another review round when its own docs audit edits files after the review, even when the audit runs twice #4034, #4071.
  • Adding review_exclude_paths patterns on your main branch no longer forces open pull requests through review again when none of their files match #4030, #4036, #4041.
  • Every /ship reviewer now sees the same trimmed diff, including a reviewer whose instructions were rebuilt on their own after a failed start #4048.
  • /ship's review planning finishes in about 35 seconds on very large results repositories instead of timing out #4040.
  • Results pull requests full of captured model prompts no longer hit /ship's review size limit just because those prompts mention API key variables #4044.
  • /ship and /review no longer count a reviewer's closing sentence such as "None of these rises to CRITICAL." as a critical finding #4075.
  • A stacked pull request whose parent was squash-merged no longer has /ship flag main's own changes as unreviewed edits #4021.
  • /ship no longer gets stuck when a docs line with a money, security or numeric claim is added after the review finished #4062.
  • /ship no longer gets stuck after a base merge that both changes a reviewed line and moves code next to it; it now asks for one small re-check #4054.
  • /ship no longer asks for a new review when a base merge only bumps a version or rules number your ship policy declares as mechanical #4053.
  • /ship no longer stops on a Godot .uid file added after review, and your ship policy can now name your own test files #4063.
  • A ship policy whose minimum gstack version is newer than the latest stable release is now refused by name, instead of sending sessions to an upgrade that cannot satisfy it #4080.
  • /investigate's "test again after your last edit" check now notices fixes written through shell commands such as sed -i or a heredoc #4078.
  • The /investigate and /plan-ceo-review gates no longer let a session end unchecked when their scan runs slowly #4072.
  • /runaway-stopper no longer flags agents that check in every four minutes while waiting on CI as runaways #4069.
  • The Ubicloud runner behind /ubicloud never treats an API error as success and never destroys a VM that another caller created under the same name #4039, #4046.

Changes for maintainers

  • /ship's finish and accept steps handle owner-granted fix rounds better: chained fix-checks all count, a granted round refreshes the money and security re-read on its own, owner-ruled notes close their findings, and the result names the grant it used #4050, #4064, #4070, #4077.
  • The money and security re-read record survives a later main merge, and accept takes its CI wait limit from the base ship policy (ci_record_timeout_s) #4058, #4065.
  • accept checks a branch under its own test policy when that branch only adds test runs, and an owner can grant an exception for one test run #4061.
  • The new ship-policy keys mechanical_retake and test_code require gstack 1.97.0.0 #4079.
  • On Capy, /ship helper commands now log their own calls so a run's call count is known #4059.
  • gstack's own repository now runs one paid release check on main every 8 hours, re-tests a pull request merged onto main's tip before merging it when main has moved, and has CI-skipped test files rerun before merge #4031, #4029, #4028.
  • The merge step hides its own environment, including the GitHub token, from the checks it runs on Linux #4032.
  • The release-file check accepts a release output that the repository's release tool regenerates #4033.
  • A pull request that edits setup no longer runs every paid eval case on a narrow screen #4056.
  • The free-CI slow-shard warning now accounts for shards split across parallel jobs, thanks @indraoverflow #4085.
  • Test repairs: two test files now pass in one process, and four flaky tests report why they failed #4068, #4074.
  • The evidence inventory records the latest routing and /investigate eval verdicts #4076.
  • gstack now generates a load-on-demand edition of three skills (investigate, review and plan review) for another agent host #4049.
  • Agent docs: agents on Capy comment and request reviews only through Capy's PR tools, agents running /ship sleep until it finishes and keep their context small, and AGENTS.md lists skills by name only #4027, #4055, #4060.
