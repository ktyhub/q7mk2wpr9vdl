repomix v1.19.0

Esta versión traslada el servidor MCP a SDK v2 con progreso y cancelación en vivo, hace que la salida de --compress sea mucho más precisa y trae una gran ronda de correcciones de errores por parte de quienes contribuyen por primera vez.

Qué hay de nuevo 🚀

Servidor MCP en SDK v2 y el protocolo 2026-07-28 (#1952, #1954)

El servidor MCP ahora se ejecuta en MCP TypeScript SDK v2. Los Clients que admiten el protocolo 2026-07-28 lo negocian automáticamente y los clients existentes funcionan como antes.

  • El servidor sale limpiamente cuando client cierra la entrada estándar, por lo que ningún proceso repomix --mcp queda atrás.
  • La instalación incluye aproximadamente la mitad de paquetes (171 a 84), ya que la versión 1 SDK trajo dependencias de transporte HTTP como Express que el servidor estándar nunca usó.

Para los autores de client: los esquemas de herramientas ahora declaran el esquema JSON 2020-12 (cuerpos sin cambios) y los errores de validación ya no comienzan con MCP error -32602: .

MCP: Progreso y cancelación de paquetes de larga duración (#1955, #1958)

pack_codebase, pack_remote_repository y generate_skill ahora envían notifications/progress cuando client pasa un progressToken, por lo que los paquetes largos muestran el estado en vivo y los clients que restablecen su tiempo de espera en el progreso ya no los cortan. En el modo --sandbox, los mensajes solo llevan el nombre artístico, nunca una ruta de host.

Cancelar una llamada o desconectarse ahora detiene el paquete y limpia su salida parcial.

Mejoras ⚡

Salida --compress más precisa (n.º 2003)

Las pruebas doradas para cada idioma admitido expusieron una serie de errores, ahora corregidos:

  • El código de los cuerpos de las funciones ya no se filtra en la salida como si fuera una declaración.
  • Se eliminan las líneas duplicadas.
  • Se conservan las declaraciones que se eliminaron silenciosamente, como C/C++ typedef y #define, campos de C# y Java, campos de estructura Rust, llamadas Ruby attr_* y reglas at de CSS.

Cambios de salida para C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift y Vue. Si confía en --compress en una tubería, espere una diferencia con v1.18.

Generación de habilidades: mejor detección de pilas de tecnología (#1995)

--skill-generate ahora lee dependencias de Gradle Kotlin DSL (build.gradle.kts) y de PEP 621 y formas de poesía de pyproject.toml.

Advertencia cuando se ignora una ruta URL remota (#1980, #1984, #433)

Una URL como https://github.com/owner/repo/tree/main/src/shared llenó todo el repositorio y silenciosamente eliminó la ruta. Repomix ahora advierte y sugiere un patrón --include:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Corrección de errores 🐛

Ignorar patrones que terminan en un comodín Ahora excluir archivos (#1963, #1876, #320)

Patrones como **/npm-debug.log* y **/repomix-output.* solo excluían el contenido del directorio, por lo que archivos como npm-debug.log.1 y docs/repomix-output.xml se deslizaban en la salida. Ahora están excluidos. Nada de lo que antes estaba excluido pasa a estar incluido.

.git/info/exclude sigue las reglas de coincidencia de Git (#1871, #1870)

Un patrón sin barras como secret.txt ahora coincide en cualquier profundidad, como en Git, por lo que sub/secret.txt ya no está empaquetado.

¡Un agradecimiento especial a @ sxh313 por esta contribución! 🎉

Los patrones de ignorar personalizados negados ya no se invierten (#1975, #400)

!main.ts en ignore.customPatterns o --ignore excluyó a main.ts en lugar de volver a incluirlo. Los patrones negados ahora se omiten con una advertencia hasta que aterrice el soporte adecuado (#400).

Los archivos de salida divididos ya no se incluyen en la siguiente ejecución (#1921, #1920)

Con --split-output, archivos como repomix-output.1.xml de una ejecución anterior ya no se seleccionan como entrada.

¡Un agradecimiento especial a @lorenzozanee por su primera contribución! 🎉

--remove-comments Mantiene las URL en CSS, SCSS, Less, Vue y Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) se cortó a url(http: porque // se trató como un comentario. Cada idioma ahora usa sus propias reglas de comentarios, y los archivos Vue y Svelte se manejan según <script>, <style> y la sección de marcado.

¡Un agradecimiento especial a @plox-sumit por su primera contribución! 🎉

Nombres de archivos no ASCII en registros y diferencias de Git (#1940, #1979)

Nombres como 日本語.txt ya no aparecen como "\346\227\245..." en los registros y diferencias de git, y output.git.sortByChanges ahora ordena estos archivos correctamente.

¡Un agradecimiento especial a @feiiiii5 por su primera contribución! 🎉

--token-count-tree 0 muestra el árbol completo (#1941)

No imprimió nada antes; ahora muestra todos los archivos.

¡Un agradecimiento especial a @feiiiii5 por esta contribución! 🎉

Rutas de acceso --stdin anidadas en Windows (#1922)

La canalización de rutas como src/(routes)/page[1].ts a repomix --stdin en Windows incluye solo archivos de nivel raíz. Las rutas anidadas ahora coinciden.

¡Un agradecimiento especial a @lux-liang por su primera contribución! 🎉

Errores fatales visibles en --quiet y --stdout (#1875, #1874)

Un paquete fallido en --quiet o --stdout salió con el código 1 y no imprimió nada. El error ahora va a stderr.

¡Un agradecimiento especial a @ sxh313 por esta contribución! 🎉

Correcciones del servidor MCP (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose ya no escribe diagnósticos en la salida estándar, donde clients los lee como marcos de protocolo. (#1867)
  • El registro de errores ya no se silencia durante el resto de la sesión después de una llamada generate_skill o pack_remote_repository. (#1865)
  • grep_repomix_output ahora da formato al contexto como grep -C y maneja resultados muy grandes. (#1869)

¡Un agradecimiento especial a @sxh313 por su primera contribución! 🎉

Refuerzo de seguridad 🔒

MCP pack_codebase siempre ejecuta el escaneo secreto (#1960)

Un repomix.config.json en el directorio empaquetado podría desactivar el escaneo secreto de paquetes MCP con security.enableSecurityCheck: false. El escaneo ahora siempre se ejecuta para paquetes MCP; Las ejecuciones simples de CLI aún siguen el archivo de configuración.

Documentación 📚

Los documentos de MCP ahora indican que sin --sandbox, pack_codebase trust coloca el repomix.config.* en el directorio que contiene, al igual que ejecutar el CLI allí. Utilice --sandbox cuando su asistente pueda empaquetar directorios no rust, como repositorios clonados de terceros. (#1961)

Consulte [Servidor MCP: modo Sandbox] (https://repomix.com/guide/mcp-server#sandbox-mode) y [Por qué un archivo de configuración es código] (https://repomix.com/guide/security#why-a-config-file-is-code).

Cómo actualizar

npm update -g repomix

Como siempre, si tiene algún problema o sugerencia, háganoslo saber sobre los problemas de GitHub o nuestra [comunidad de Discord] (https://discord.gg/wNYzTwZFku).

repomix v1.19.0

This release moves the MCP server to SDK v2 with live progress and cancellation, makes --compress output far more accurate, and brings a big round of bug fixes from first-time contributors!

What's New 🚀

MCP Server on SDK v2 and the 2026-07-28 Protocol (#1952, #1954)

The MCP server now runs on the MCP TypeScript SDK v2. Clients that support the 2026-07-28 protocol negotiate it automatically, and existing clients work as before.

  • The server exits cleanly when the client closes stdin, so no repomix --mcp processes are left behind.
  • The install pulls in about half as many packages (171 to 84), since the v1 SDK brought HTTP transport dependencies such as Express that the stdio-only server never used.

For client authors: tool schemas now declare JSON Schema 2020-12 (bodies unchanged), and validation errors no longer start with MCP error -32602: .

MCP: Progress and Cancellation for Long-Running Packs (#1955, #1958)

pack_codebase, pack_remote_repository and generate_skill now send notifications/progress when the client passes a progressToken, so long packs show live status, and clients that reset their timeout on progress no longer cut them off. In --sandbox mode, messages carry only the stage name, never a host path.

Cancelling a call or disconnecting now stops the pack and cleans up its partial output.

Improvements ⚡

More Accurate --compress Output (#2003)

Golden tests for every supported language exposed a set of bugs, now fixed:

  • Code from function bodies no longer leaks into the output as if it were a declaration.
  • Duplicate lines are removed.
  • Declarations that were silently dropped are kept, such as C/C++ typedef and #define, C# and Java fields, Rust struct fields, Ruby attr_* calls and CSS at-rules.

Output changes for C, C++, C#, CSS, Dart, Go, Java, JavaScript/TypeScript, Ruby, Rust, Swift and Vue. If you rely on --compress in a pipeline, expect a diff from v1.18.

Skill Generation: Better Tech-Stack Detection (#1995)

--skill-generate now reads dependencies from Gradle Kotlin DSL (build.gradle.kts) and from the PEP 621 and Poetry forms of pyproject.toml.

Warning When a Remote URL Path Is Ignored (#1980, #1984, #433)

A URL like https://github.com/owner/repo/tree/main/src/shared packed the whole repository and silently dropped the path. Repomix now warns and suggests an --include pattern:

The path "src/shared" in the remote URL is ignored, and the whole repository will be packed.
To pack only that path, add: --include "src/shared/**"

Bug Fixes 🐛

Ignore Patterns Ending in a Wildcard Now Exclude Files (#1963, #1876, #320)

Patterns such as **/npm-debug.log* and **/repomix-output.* only excluded directory contents, so files like npm-debug.log.1 and docs/repomix-output.xml slipped into the output. They are now excluded. Nothing that was excluded before becomes included.

.git/info/exclude Follows Git's Matching Rules (#1871, #1870)

A slash-free pattern such as secret.txt now matches at any depth, as in Git, so sub/secret.txt is no longer packed.

Special thanks to @sxh313 for this contribution! 🎉

Negated Custom Ignore Patterns No Longer Invert (#1975, #400)

!main.ts in ignore.customPatterns or --ignore excluded main.ts instead of re-including it. Negated patterns are now skipped with a warning until proper support lands (#400).

Split Output Files No Longer Packed into the Next Run (#1921, #1920)

With --split-output, files like repomix-output.1.xml from a previous run are no longer picked up as input.

Special thanks to @lorenzozanee for their first contribution! 🎉

--remove-comments Keeps URLs in CSS, SCSS, Less, Vue and Svelte (#1912, #1965, #1911)

url(http://example.com/logo.png) was cut to url(http: because // was treated as a comment. Each language now uses its own comment rules, and Vue and Svelte files are handled per <script>, <style> and markup section.

Special thanks to @plox-sumit for their first contribution! 🎉

Non-ASCII File Names in Git Logs and Diffs (#1940, #1979)

Names like 日本語.txt no longer appear as "\346\227\245..." in git logs and diffs, and output.git.sortByChanges now sorts these files correctly.

Special thanks to @feiiiiii5 for their first contribution! 🎉

--token-count-tree 0 Shows the Full Tree (#1941)

It printed nothing before; it now shows every file.

Special thanks to @feiiiiii5 for this contribution! 🎉

Nested --stdin Paths on Windows (#1922)

Piping paths such as src/(routes)/page[1].ts into repomix --stdin on Windows packed only root-level files. Nested paths now match.

Special thanks to @lux-liang for their first contribution! 🎉

Fatal Errors Visible Under --quiet and --stdout (#1875, #1874)

A failed pack under --quiet or --stdout exited with code 1 and printed nothing. The error now goes to stderr.

Special thanks to @sxh313 for this contribution! 🎉

MCP Server Fixes (#1867, #1866, #1865, #1864, #1869, #1868)

  • --mcp --verbose no longer writes diagnostics to stdout, where clients read them as protocol frames. (#1867)
  • Error logging is no longer silenced for the rest of the session after a generate_skill or pack_remote_repository call. (#1865)
  • grep_repomix_output now formats context like grep -C and handles very large outputs. (#1869)

Special thanks to @sxh313 for their first contribution! 🎉

Security Hardening 🔒

MCP pack_codebase Always Runs the Secret Scan (#1960)

A repomix.config.json in the packed directory could turn off the secret scan for MCP packs with security.enableSecurityCheck: false. The scan now always runs for MCP packs; plain CLI runs still follow the config file.

Documentation 📚

The MCP docs now state that without --sandbox, pack_codebase trusts the repomix.config.* in the directory it packs, just like running the CLI there. Use --sandbox when your assistant may pack untrusted directories, such as cloned third-party repositories. (#1961)

See MCP Server: Sandbox Mode and Why a config file is code.

How to Update

npm update -g repomix

As always, if you have any issues or suggestions, please let us know on GitHub issues or our Discord community.
