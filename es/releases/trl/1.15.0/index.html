Características

⚡ Cabezal LM fusionado: hasta 6.9× secuencias más largas en la misma GPU

SFT, DPO, KTO, GRPO, RLOO y Distillation ahora puntúan tokens con una cabeza LM fusionada: un kernel Triton proyecta los estados ocultos a través de la cabeza LM en mosaicos y los reduce a problemas logarítmicos por token y entropía directamente, por lo que el tensor logits [batch, seq, vocab] nunca se construye. Está activado de forma predeterminada, no hay nada que activar. El valor predeterminado anterior de SFT (chunked_nll) ya evitaba los logits completos, por lo que no ha cambiado. La puntuación necesita Triton en una GPU (Linux con CUDA, ROCm o XPU). 💥 Qué cambia esto para ti. La ruta de puntuación de logs completos, la ruta fragmentada use_liger_kernel y _forward_redirection han desaparecido de GRPO, RLOO, DPO y KTO:

  • Ahora se levanta un adaptador PEFT en lm_head. Utilice modules_to_save=["lm_head"] en su lugar.
  • use_liger_kernel=True está obsoleto en estos cuatro entrenadores y se eliminará en v2.0.0. Los núcleos de capa de Liger aún se aplican, pero fused_linear_cross_entropy se ve obligado a False (reemplazaría la cabeza fusionada) y su configuración aumenta explícitamente. Utilice model_init_kwargs={"use_kernels": True}.
  • En DPO y KTO, compute_metrics y compute_loss(..., return_outputs=True) aún reciben los logits completos, a partir de un pase hacia adelante adicional que se realiza solo cuando se usan. Ambos advierten que esto está en desuso y se eliminará en v2.0.0. No se pierde nada más que registraron los entrenadores: el kernel obtuvo log_sum_sq_probs (ponderación WPO), mean_logits (logits/chosen, logits/rejected) y is_top1 (mean_token_accuracy de DPO) como salidas opcionales, cada una de ellas verificada con los logits completos en las pruebas. <detalles>

Features

⚡ Fused LM head: up to 6.9× longer sequences on the same GPU

SFT, DPO, KTO, GRPO, RLOO and Distillation now score tokens with a fused LM head: a Triton kernel projects the hidden states through the LM head in tiles and reduces to per-token log-probs and entropy directly, so the [batch, seq, vocab] logits tensor is never built. It is on by default, there is nothing to turn on.

Max trainable sequence length (gemma-3-1b, 262k vocabulary, 79 GiB of GPU memory, bf16, batch size 1, gradient checkpointing, sdpa):

| Trainer | v1.14.2 | v1.15.0 | | | --- | --- | --- | --- | | DPO | 10,240 | 59,392 | 5.80× | | KTO (batch size 2) | 9,216 | 63,488 | 6.89× | | GRPO (scoring only) | 28,672 | 114,688 | 4.00× | | RLOO (scoring only) | 23,552 | 100,352 | 4.26× | | SFT (loss_type="nll") | 20,480 | 107,520 | 5.25× | | SFT (default chunked_nll) | 107,520 | 107,520 | 1.00× |

At 8,192 tokens, peak memory drops 52% to 82% and steps are 2.3% to 10.9% faster:

| Trainer | Peak GiB v1.14.2 → v1.15.0 | Tokens/s | | --- | --- | --- | | DPO | 48.97 → 12.00 (-75.5%) | 1.035× | | KTO | 64.91 → 11.98 (-81.5%) | 1.045× | | GRPO | 24.15 → 10.30 (-57.4%) | 1.023× | | RLOO | 29.28 → 14.02 (-52.1%) | 1.029× | | SFT (nll) | 30.33 → 8.87 (-70.7%) | 1.029× |

The gain is largest for small models with large vocabularies. SFT's previous default (chunked_nll) already avoided full logits, so it is unchanged. Scoring needs Triton on a GPU (Linux with CUDA, ROCm or XPU).

💥 What this changes for you. The full-logits scoring path, the use_liger_kernel chunked path and _forward_redirection are gone from GRPO, RLOO, DPO and KTO:

  • A PEFT adapter on lm_head now raises. Use modules_to_save=["lm_head"] instead.
  • use_liger_kernel=True is deprecated in these four trainers and will be removed in v2.0.0. Liger's layer kernels still apply, but fused_linear_cross_entropy is forced to False (it would replace the fused head) and setting it explicitly raises. Use model_init_kwargs={"use_kernels": True}.
  • In DPO and KTO, compute_metrics and compute_loss(..., return_outputs=True) still receive the full logits, from an extra forward pass taken only when they are used. Both warn that this is deprecated and will be removed in v2.0.0.

Nothing else the trainers logged is lost: the kernel gained log_sum_sq_probs (WPO weighting), mean_logits (logits/chosen, logits/rejected) and is_top1 (DPO's mean_token_accuracy) as opt-in outputs, each checked against the full logits in tests.

<details> <summary>Benchmark details</summary>

1× B300 with the PyTorch allocator capped at 79 GiB (about an H100 80GB's usable memory), google/gemma-3-1b-pt built from its config with random bf16 weights, lr 1e-6, AdamW, synthetic token ids at exact length. Max length: one fresh process per attempt, 2 training steps, doubling from 8k then bisection to 1024 tokens, arms interleaved round-robin in the same job. Throughput: 12 steps, first 2 discarded, median of 3 A/B/A/B repeats in the same job. Noise floor (A vs A) is 0.1% to 0.8%, below every gap reported. GRPO/RLOO replace generation with fixed random completions, so only scoring is measured.

Not measured: H100 hardware itself, flash-attention (sdpa only), real generation, multi-GPU.

Selective activation checkpointing in SFT

With gradient checkpointing on, the attention output is now saved during the forward instead of being recomputed in the backward, recovering most of the checkpointing slowdown at long context for one extra hidden-state-sized tensor per layer. Same eager SAC approach torchtitan uses under FSDP2, no torch.compile needed.

SFTConfig(
    gradient_checkpointing=True,
    gradient_checkpointing_kwargs={"selective": True},
)

PEFT + DeepSpeed ZeRO-3 is rejected: that combination needs reentrant checkpointing, which SAC cannot use.

by @kashif in https://github.com/huggingface/trl/pull/7194

Assistant-only loss on vision datasets in SFT

assistant_only_loss=True now works on vision datasets. SFTTrainer used to refuse it because processors did not return usable assistant masks once image placeholders were expanded; transformers#48793 fixed that, and it ships in transformers 5.18.

SFTConfig(assistant_only_loss=True)  # now fine with an image dataset

The vision collator tokenizes conversational examples through the processor's apply_chat_template and requests the assistant masks to mask non-assistant tokens in the labels. Older transformers still raises, now with the required version in the message.
