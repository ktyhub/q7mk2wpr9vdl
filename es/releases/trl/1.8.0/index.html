#trlv1.8.0

Características

🎓 KTO ahora es un entrenador estable

Después de muchos ciclos de trabajo de alineación KTOTrainer ↔ DPOTrainer, KTO pasa de trl.experimental.kto al paquete de nivel superior trl. Mismo API que DPO/GRPO/SFT: las importaciones pasan del experimental, las pruebas pasan al árbol de pruebas principal y los documentos ya no lo marcan como experimental. La ruta experimental todavía funciona y emite un FutureWarning (eliminación en v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Según nuestra telemetría, KTO es el cuarto entrenador más utilizado en TRL; esta graduación estaba retrasada. por @albertvillanova en https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 y https://github.com/huggingface/trl/pull/6345

Recompensas de propiedad del medio ambiente y soporte multiambiente

Tres cambios interrelacionados hacen que el entrenamiento de RL agente con entornos sea sustancialmente más ergonómico. Recompensa propiedad del entorno. Si su entorno environment_factory define un método get_reward() reservado (sin argumentos → float), se llama una vez por implementación completa y se trata como una fuente de recompensa. reward_funcs se vuelve opcional: ya no se filtrará el estado del entorno a las funciones de recompensa propiedad del entrenador.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Soporte multientorno. environment_factory ahora acepta dict[str, factory] además de un único invocable. Cada fila del conjunto de datos selecciona su entorno a través de una columna environment, y solo las herramientas de ese entorno están expuestas en el mensaje de esa fila, por lo que una tarea de codificación y un juego pueden entrenarse juntos en una sola ejecución sin filtrar los esquemas de herramientas de cada uno. El uso de llamadas únicas no ha cambiado. El mismo cableado aterriza en GRPO, AsyncGRPO, DPPO y GRPO con búfer de reproducción. Recompensa de propiedad de sobre por @qgallouedec en https://github.com/huggingface/trl/pull/6238; multi-env en https://github.com/huggingface/trl/pull/6001 y https://github.com/huggingface/trl/pull/6002

Regularización de entropía para GRPO

GRPOConfig ahora admite regularización de entropía tanto estática como adaptativa (Skywork-OR1). El bono fomenta la exploración y ayuda a prevenir el colapso prematuro de las políticas.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

El modo adaptativo ajusta el coeficiente una vez por paso del optimizador a partir de la entropía agregada por ventana (consciente de la acumulación de gradiente) y mantiene entropy_coef en el punto de control para reanudarlo. No es compatible con el kernel Liger. por @albertvillanova en https://github.com/huggingface/trl/pull/6140

Argumento del entrenador quantization_config (QLoRA optimizado)

QLoRA ya no requiere acceder a model_init_kwargs o precargar el modelo manualmente.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Agregado a SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer y KTOTrainer. Se ubica junto a peft_config (el otro ingrediente QLoRA no serializable), fluye hacia from_pretrained y aumenta si también se configura en args.model_init_kwargs. También elimina la línea redundante get_kbit_device_map(): QLoRA se entrena de manera idéntica sin ella en todas las configuraciones probadas. por @qgallouedec en https://github.com/huggingface/trl/pull/6157 y https://github.com/huggingface/trl/pull/6276

La pérdida auxiliar de MoE se extiende a DPO y KTO

v1.7 agregó la pérdida auxiliar de equilibrio de carga del enrutador a GRPOTrainer / RLOOTrainer / AsyncGRPOTrainer. Ahora también está disponible en DPOTrainer y KTOTrainer, por lo que los modelos MoE posteriores al entrenamiento con datos de preferencia mantienen a los expertos equilibrados. por @qgallouedec en https://github.com/huggingface/trl/pull/6208 y https://github.com/huggingface/trl/pull/6275

chunked_nll compatible con neuronas mediante empaquetado de tokens de forma estática

La ruta NLL fragmentada tenía una indexación dependiente de los datos que interrumpía la compilación XLA/Neuron. Este PR lo reelabora para empaquetar tokens válidos al frente a través de un argsort estable en la máscara de validez, iterar sobre fragmentos completos de ceil(n_valid / chunk_size) * chunk_size (un tensor, sin sincronización Python-int) y usar ignore_index=-100 dentro de cada fragmento. El comportamiento de la GPU no cambia; Neuron ahora también funciona: la misma pequeña huella de memoria (~1.33 GiB frente a la ingenua alternativa 5.94 GiB) sin recompilación por máscara. por @michaelbenayoun en https://github.com/huggingface/trl/pull/6314

Procesamiento por lotes dinámico compatible con el embalaje en AsyncGRPO

El microprocesamiento por lotes AsyncGRPO se vuelve consciente del embalaje y está vinculado a tokens además de la ruta sin relleno de v1.7:

  • Equilibrio de filas Σ Lᵢ²: una primera asignación codiciosa y más larga le da a cada fila DP el mismo Σ Lᵢ² en lugar del mismo recuento de tokens (la atención es O(L²), FFN es O(L), por lo que los recuentos de tokens iguales no igualan el reloj de pared). Los rezagados de rangos cruzados desaparecen; +19% MFU a 4B en el índice de referencia.
  • Embalaje de presupuesto de token (optar por participar): limite cada fila en tokens token_budget con un recuento de muestra variable, desacoplando la memoria máxima de per_device_train_batch_size. Útil en regímenes vinculados a la memoria (sin puntos de control de gradiente, contexto largo, modelos muy grandes). Ambos aprovechan la acumulación de gradiente existente de HF Trainer: sin cirugía de bucle de entrenamiento, los colectivos FSDP/EP permanecen al unísono. por @AmineDiro en https://github.com/huggingface/trl/pull/6092

trl v1.8.0

Features

🎓 KTO is now a stable trainer

After many cycles of KTOTrainer ↔ DPOTrainer alignment work, KTO graduates from trl.experimental.kto to the top-level trl package. Same API as DPO/GRPO/SFT — imports move from experimental, tests move to the main test tree, docs no longer flag it as experimental. The experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.kto import KTOConfig, KTOTrainer

# Now
from trl import KTOConfig, KTOTrainer

Per our telemetry, KTO is the 4th most used trainer in TRL — this graduation was overdue.

by @albertvillanova in https://github.com/huggingface/trl/pull/6175, https://github.com/huggingface/trl/pull/6287 and https://github.com/huggingface/trl/pull/6345

Environment-owned rewards & multi-environment support

Three interrelated changes make agentic RL training with environments substantially more ergonomic.

Environment-owned reward. If your environment_factory env defines a reserved get_reward() method (no args → float), it's called once per completed rollout and treated as a reward source. reward_funcs becomes optional — no more leaking env state back out to trainer-owned reward funcs.

class WordleEnv:
    def reset(self, **kwargs):
        self._target = sample(words); self._solved = False

    def get_reward(self) -> float:       # optional, reserved (not a tool)
        return 1.0 if self._solved else 0.0

    def guess(self, word: str) -> str:   # exposed as a tool
        self._solved = word == self._target; ...

trainer = GRPOTrainer(
    model=model,
    train_dataset=dataset,
    environment_factory=WordleEnv,       # no reward_funcs needed
)

Multi-environment support. environment_factory now accepts dict[str, factory] in addition to a single callable. Each dataset row selects its environment via an environment column, and only that env's tools are exposed in that row's prompt — so a coding task and a game can train together in one run without leaking each other's tool schemas. Single-callable usage is unchanged.

Same wiring lands in GRPO, AsyncGRPO, DPPO, and GRPO-with-replay-buffer.

Env-owned reward by @qgallouedec in https://github.com/huggingface/trl/pull/6238; multi-env in https://github.com/huggingface/trl/pull/6001 and https://github.com/huggingface/trl/pull/6002

Entropy regularization for GRPO

GRPOConfig now supports both static and adaptive entropy regularization (Skywork-OR1). The bonus encourages exploration and helps prevent premature policy collapse.

GRPOConfig(
    entropy_coef=0.01,          # static
    # or:
    use_adaptive_entropy=True,  # adjust to target entropy
    entropy_target=1.5,
    entropy_coef_delta=0.01,
    entropy_coef_min=0.0,
    entropy_coef_max=0.1,
)

Adaptive mode adjusts the coefficient once per optimizer step from window-aggregated entropy (gradient accumulation-aware) and persists entropy_coef in the checkpoint for resume. Not compatible with the Liger kernel.

by @albertvillanova in https://github.com/huggingface/trl/pull/6140

quantization_config trainer argument (streamlined QLoRA)

QLoRA no longer requires reaching into model_init_kwargs or pre-loading the model manually.

SFTTrainer(
    model="meta-llama/Llama-2-7b-hf",
    quantization_config=BitsAndBytesConfig(load_in_4bit=True),
    peft_config=LoraConfig(),
    train_dataset=dataset,
)

Added to SFTTrainer, DPOTrainer, GRPOTrainer, RLOOTrainer, RewardTrainer, and KTOTrainer. Sits next to peft_config (the other non-serializable QLoRA ingredient), flows into from_pretrained, and raises if also set in args.model_init_kwargs. Also drops the redundant get_kbit_device_map() line — QLoRA trains identically without it across all tested configurations.

Neuron-friendly chunked_nll via static-shape token packing

The chunked NLL path had data-dependent indexing that broke XLA/Neuron compilation. This PR reworks it to pack valid tokens to the front via a stable argsort on the validity mask, iterate over ceil(n_valid / chunk_size) * chunk_size whole chunks (a tensor, no Python-int sync), and use ignore_index=-100 inside each chunk. GPU behavior is unchanged; Neuron now works too — same tiny memory footprint (~1.33 GiB vs the naive 5.94 GiB alternative) with no per-mask recompilation.

by @michaelbenayoun in https://github.com/huggingface/trl/pull/6314

Packing-aware dynamic batching in AsyncGRPO

AsyncGRPO micro-batching becomes packing-aware and token-bounded on top of the padding-free path from v1.7:

  • Σ Lᵢ² row balancing — a greedy longest-first assignment gives every DP row the same Σ Lᵢ² instead of the same token count (attention is O(L²), FFN is O(L), so equal token counts don't equalize wall-clock). Cross-rank stragglers vanish; +19% MFU at 4B in the benchmark.
  • Token-budget packing (opt-in) — cap each row at token_budget tokens with a variable sample count, decoupling peak memory from per_device_train_batch_size. Useful in memory-bound regimes (no gradient checkpointing, long context, very large models).

Both ride HF Trainer's existing gradient accumulation — no training-loop surgery, FSDP/EP collectives stay in lockstep.
