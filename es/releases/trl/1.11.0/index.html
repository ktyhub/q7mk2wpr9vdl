#trl v1.11.0

Características

Utilice el servidor propio de vLLM en lugar del de TRL

trl vllm-serve solía ejecutar una aplicación FastAPI personalizada alrededor de LLM de vLLM, con su propia distribución de datos en paralelo y una extensión de trabajo para sincronización de peso. El propio servidor de vLLM cubre todo eso. El servidor personalizado desapareció: trl/scripts/vllm_serve.py baja de 1218 a ~130 líneas y ahora traduce sus indicadores a vllm serve, imprime el comando equivalente, reenvía cualquier argumento adicional y establece las tres configuraciones que TRL necesita (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn y pydantic dejan extra el vllm. La sincronización de peso ahora utiliza el motor de transferencia de peso NCCL de vLLM: los tensores se anuncian una vez y se transmiten en una única transmisión empaquetada, en lugar de una solicitud HTTP + transmisión por tensor. Los logprobs del profesor de destilación provienen de prompt_logprobs. Parámetro (modo de servidor GRPO en H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, misma semilla, mismos datos): | Configuración | antes | después | aceleración | | --- | --- | --- | --- | | Texto, TP=1 | 1.08, 0.91 s/paso | 0.63, 0.62 s/paso | 1.59× | | Texto, TP=2 | 0.96, 0.96 s/paso | 0.62, 0.60 s/paso | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/paso | 1.48, 1.48 s/paso | 1.44× | Completaciones de bits idénticos frente al servidor anterior (16/16 en 4 mensajes × n=4, logprobs idénticos a 0.0 en 499 tokens). trl vllm-serve todavía acepta las mismas banderas; ahora simplemente reenvía a vllm serve. por @qgallouedec en https://github.com/huggingface/trl/pull/6765

Nuevo experimental AsyncDistillationTrainer (+ MOPD multiprofesor)

Destilación asíncrona de políticas, diseñada como AsyncGRPOTrainer: un trabajador de implementación en segundo plano genera las propias terminaciones del estudiante y las califica frente a un maestro a través de HTTP, por lo que la generación y la capacitación se superponen en lugar de alternarse. El profesor nunca se carga localmente, solo la URL del servidor vLLM. También admite MOPD (destilación de políticas de múltiples maestros): pase más de una entrada en teacher_server_urls y dirija cada muestra a un maestro a través de una columna teacher_id (por ejemplo, un maestro de matemáticas y un maestro de códigos, cada uno de ellos atendido de forma independiente).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

por @kashif en https://github.com/huggingface/trl/pull/6705

Ejemplos reorganizados en carpetas por ejemplo

examples/ se dividió por formato (scripts/ vs notebooks/), lo que dispersó archivos relacionados (por ejemplo, sft_nemotron_3 existía como un script y como un cuaderno, en diferentes carpetas; los cuadernos OpenEnv vivían separados de los scripts OpenEnv). Ahora todo es una carpeta por historia: el nombre dice el método y la tarea (grpo_wordle, sft_gpt_oss, ppo_tldr), y la carpeta contiene todos los archivos que el ejemplo necesita (scripts, cuadernos, indicaciones, plantillas de chat, código de evaluación). Se eliminan los scripts de demostración delgados para un solo entrenador (se encuentran en trl/scripts/ y cada página de documentación del entrenador tiene un fragmento ejecutable). Los enlaces antiguos examples/scripts/… y examples/notebooks/… GitHub / Colab serán 404: vale la pena marcarlos en publicaciones posteriores. por @qgallouedec en https://github.com/huggingface/trl/pull/6820

trl v1.11.0

Features

Use vLLM's own server instead of TRL's

trl vllm-serve used to run a custom FastAPI app around vLLM's LLM, with its own data-parallel fan-out and a worker extension for weight sync. vLLM's own server covers all of that. The custom server is gone: trl/scripts/vllm_serve.py drops from 1218 to ~130 lines and now translates its flags into vllm serve, prints the equivalent command, forwards any extra argument, and sets the three settings TRL needs (--weight-transfer-config, --logprobs-mode processed_logprobs, --max-logprobs -1). fastapi, uvicorn and pydantic leave the vllm extra.

Weight sync now uses vLLM's NCCL weight-transfer engine — tensors are announced once and streamed in a single packed broadcast, instead of one HTTP request + broadcast per tensor. Distillation teacher logprobs come from prompt_logprobs.

Benchmark (GRPO server-mode on H100, Qwen2.5-1.5B / Qwen2.5-VL-3B, same seed, same data):

| Setup | before | after | speedup | | --- | --- | --- | --- | | Text, TP=1 | 1.08, 0.91 s/step | 0.63, 0.62 s/step | 1.59× | | Text, TP=2 | 0.96, 0.96 s/step | 0.62, 0.60 s/step | 1.57× | | VLM, TP=1 | 2.14, 2.13 s/step | 1.48, 1.48 s/step | 1.44× |

Bit-identical completions vs the old server (16/16 over 4 prompts × n=4, logprobs identical to 0.0 over 499 tokens). trl vllm-serve still accepts the same flags — it just forwards to vllm serve now.

by @qgallouedec in https://github.com/huggingface/trl/pull/6765

New experimental AsyncDistillationTrainer (+ multi-teacher MOPD)

Async on-policy distillation, architected like AsyncGRPOTrainer: a background rollout worker generates the student's own completions and scores them against a teacher served over HTTP, so generation and training overlap instead of alternating. The teacher is never loaded locally — just a vLLM server URL.

Also supports MOPD (multi-teacher on-policy distillation): pass more than one entry in teacher_server_urls and route each sample to a teacher via a teacher_id column (e.g. a math teacher and a code teacher, each served independently).

from trl.experimental.async_distillation import AsyncDistillationConfig, AsyncDistillationTrainer

trainer = AsyncDistillationTrainer(
    model="Qwen/Qwen3-4B",
    args=AsyncDistillationConfig(
        teacher_server_urls=["http://teacher-math:8000", "http://teacher-code:8000"],
        teacher_top_k=16,
    ),
    train_dataset=dataset,  # rows carry a `teacher_id` column for MOPD
)
trainer.train()

by @kashif in https://github.com/huggingface/trl/pull/6705

Examples reorganized into per-example folders

examples/ was split by format (scripts/ vs notebooks/), which scattered related files (e.g. sft_nemotron_3 existed as both a script and a notebook, in different folders; OpenEnv notebooks lived apart from OpenEnv scripts). Everything is now one folder per story — the name says the method and the task (grpo_wordle, sft_gpt_oss, ppo_tldr), and the folder holds every file the example needs (scripts, notebooks, prompts, chat templates, eval code). Thin single-trainer demo scripts are removed (they live in trl/scripts/ and each trainer doc page has a runnable snippet). Old examples/scripts/… and examples/notebooks/… GitHub / Colab links will 404 — worth flagging in downstream posts.

by @qgallouedec in https://github.com/huggingface/trl/pull/6820
