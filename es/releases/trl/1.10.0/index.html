Características

🎓 DistillationTrainer ahora es un entrenador estable

Después de una refactorización de ~30 PR que reformó su contrato de datos, ruta de pérdida, pila de generación, superficie de configuración y pruebas, DistillationTrainer y DistillationConfig se gradúan de trl.experimental.distillation al paquete de nivel superior trl. Misma superficie de importación que SFT/DPO/GRPO/KTO. La antigua ruta experimental todavía funciona y emite un FutureWarning (eliminación en v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

También aterriza un trl distillation CLI y mueve las pruebas a tests/. El arco de refactor completo: cambió las columnas de firma a prompt (formato messages obsoleto), fijó la pila de generación a GRPO, conectó la pérdida JSD fragmentada y eliminó la ruta logit completa, limpió la ruta Liger para compartir la extracción con la ruta fragmentada, adoptó la sincronización log() / training_step / _save_checkpoint de GRPO, reconstruyó el conjunto de pruebas a la forma de GRPO y mucho más. por @qgallouedec en ~30 relaciones públicas (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: capacitación del agente propietario del bucle (arnés OpenEnv)

Nueva ruta experimental propietaria de bucle (caja negra) para AsyncGRPOTrainer: para entrenar agentes externos como opencode que ejecutan su propio bucle de herramientas, en lugar de TRL impulsando cada giro como en la ruta de caja blanca environment_factory. El agente se ejecuta en una sesión OpenEnv en modo transparent_proxy; un proxy en la zona de pruebas captura los identificadores de token y los problemas de registro de cada turno. Al finalizar, TRL lee el seguimiento, reconstruye las filas de entrenamiento por turno y califica el espacio de trabajo con el verify() de la sesión. Se entrega con tres ganchos de políticas proporcionados por la persona que llama (rollout_reward_fn, train_turn_fn, agent_turn_fn) para que pueda descartar llamadas auxiliares del marco (generador de títulos, resumen de contexto) y reforzar solo los turnos que desee. Incluye un examples/scripts/openenv/opencode.py autónomo (zona de pruebas de subproceso local + verificador stdin/stdout retenido de DeepCoder), validado de extremo a extremo en Qwen3-4B. por @AmineDiro en https://github.com/huggingface/trl/pull/6420, más variante HF-sandbox por @sergiopaniego en https://github.com/huggingface/trl/pull/6565

Ejemplo de SFT de difusión en bloque de DiffusionGemma

Un nuevo ejemplo de SFT para google/diffusiongemma-26B-A4B-it implementando la receta de referencia: un bloque de respuesta por paso, corrupción de token aleatoria uniforme con t ~ U(eps, 1), autocondicionamiento de dos pasadas, entropía cruzada plana en todo el lienzo más una copérdida autorregresiva en el codificador. LoRA apunta a la atención + lineales MLP densos. Requiere transformers >= 5.12.0. Se envía con plantillas de chat diffusion_gemma.jinja / diffusion_gemma_training.jinja (con marcadores {% generation %}) para que assistant_only_loss=True funcione de inmediato. por @kashif en https://github.com/huggingface/trl/pull/6003

trl v1.10.0

Features

🎓 DistillationTrainer is now a stable trainer

After a ~30-PR refactor that reshaped its data contract, loss path, generation stack, config surface, and tests, DistillationTrainer and DistillationConfig graduate from trl.experimental.distillation to the top-level trl package. Same import surface as SFT / DPO / GRPO / KTO. The old experimental path still works and emits a FutureWarning (removal in v2.0.0).

# Before
from trl.experimental.distillation import DistillationConfig, DistillationTrainer

# Now
from trl import DistillationConfig, DistillationTrainer

Also lands a trl distillation CLI and moves the tests to tests/. The full refactor arc: switched signature columns to prompt (deprecated messages-format), pinned the generation stack to GRPO's, wired the chunked JSD loss and deleted the full-logit path, cleaned the Liger path to share extraction with the chunked path, adopted GRPO's log() / training_step timing / _save_checkpoint, rebuilt the test suite to GRPO shape, and much more.

by @qgallouedec across ~30 PRs (#6479, #6480, #6481, #6482, #6484, #6487, #6497, #6508, #6509, #6510, #6511, #6512, #6513, #6521, #6522, #6523, #6524, #6525, #6526, #6530, #6537, #6604, #6605, #6606, #6607, #6609, #6610, #6611, #6612, #6613, #6614, #6629, #6630, #6632, #6633, #6634, #6639, #6640, #6641, #6642, #6643, #6644, #6645, #6647, #6653).

AsyncGRPO: loop-owning agent training (OpenEnv harness)

New experimental loop-owning (black-box) path for AsyncGRPOTrainer — for training external agents like opencode that run their own tool loop, rather than TRL driving each turn as in the environment_factory white-box path.

The agent runs in an OpenEnv session in transparent_proxy mode; an in-sandbox proxy captures each turn's token ids and logprobs. On completion, TRL reads the trace, rebuilds per-turn training rows, and scores the workspace with the session's verify(). Ships with three caller-supplied policy hooks (rollout_reward_fn, train_turn_fn, agent_turn_fn) so you can drop framework aux calls (title generator, context summarizer) and reinforce only the turns you want.

Includes a self-contained examples/scripts/openenv/opencode.py (local subprocess sandbox + DeepCoder held-out stdin/stdout verifier), validated end-to-end on Qwen3-4B.

by @AmineDiro in https://github.com/huggingface/trl/pull/6420, plus HF-sandbox variant by @sergiopaniego in https://github.com/huggingface/trl/pull/6565

DiffusionGemma block-diffusion SFT example

A new SFT example for google/diffusiongemma-26B-A4B-it implementing the reference recipe: one response block per step, uniform random token corruption with t ~ U(eps, 1), two-pass self-conditioning, flat cross-entropy over the whole canvas plus an autoregressive co-loss on the encoder. LoRA targets attention + dense MLP linears. Requires transformers >= 5.12.0.

Ships with diffusion_gemma.jinja / diffusion_gemma_training.jinja chat templates (with {% generation %} markers) so assistant_only_loss=True works out of the box.
