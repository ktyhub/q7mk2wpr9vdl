#ECC v2.1.0

ECC 2.1.0: Plan Canvas, Kimi Harness y computación autohospedada

ECC 2.1 convierte la revisión del plan en un bucle visual y abre el camino a los modelos autohospedados. Plan Canvas le permite revisar los planes de los agentes en el navegador. Señala la parte a la que te refieres en lugar de volver a escribirla en el chat. Un nuevo objetivo de instalación de Kimi Code y una ruta de GPU Itô verificada hacen de los modelos de código abierto ECC+ una configuración de primera clase, respaldada por nuestros patrocinadores públicos: Moonshot AI (Kimi), Itô y Atlas Cloud.

Plan Canvas: revise los planes señalando, no volviendo a escribir

Descargue la demostración MP4 /plan termina con una puerta de confirmación, y hasta ahora esa revisión era un muro de rebajas en la terminal. Ahora el agente abre el plan en un lienzo de navegador de solo bucle invertido:

  • Click elementos o seleccione texto para adjuntar anotaciones numeradas
  • Charla con el agente desde una barandilla lateral mientras trabaja en la terminal.
  • Los botones Aprobar plan / Solicitar cambios se asignan directamente a la puerta CONFIRMAR de /plan
  • Los diagramas, tablas y listas de tareas de Mermaid se representan de forma nativa; ediciones de archivos en vivo recargar la página
  • Independiente del modelo y del arnés: un protocolo simple CLI + JSON (ecc-plan-canvas), sin dependencia exclusiva de Claude

Arnés Kimi: asociación Moonshot AI

ECC ahora se instala directamente en Código Kimi (--target kimi). Kimi Code descubre las instrucciones .kimi/AGENTS.md instaladas y los flujos de trabajo .kimi/skills/ de forma nativa:

bash ./install.sh --target kimi --profile minimal
npx ecc doctor --target kimi
kimi

Autohospedaje en GPU Itô

Ejecute ECC en cualquier modelo de código abierto autohospedado. Si necesita capacidad de GPU, Itô es el patrocinador informático preferido de ECC. La integración se envió protegida de extremo a extremo:

  • ecc ito find: puente de suscripción al canónico Itô CLI que envía una solicitud de cotización en vivo y autenticada (no reserva capacidad)
  • Calificación de nodo activo protegido y transferencia de cálculo de solo lectura
  • Las cuñas CLI con credenciales se rechazan de plano. El enlace de patrocinio en sí es pasivo: no invoca una solicitud de cotización, no reserva capacidad, no aprovisiona computación ni configura el servicio. La inferencia gestionada a través de Itô aún no está disponible. Cualquier proveedor de GPU funciona y ECC se mantiene independiente del proveedor.

Socios

Moonshot AI (Kimi), Itô y Atlas Cloud ahora son patrocinadores públicos de ECC. El archivo README documenta una ruta de autohospedaje recomendada: Itô para la capacidad de GPU, un punto de control Kimi servido detrás de un punto final compatible, luego Kimi Code + ECC en la parte superior. Cada opción permanece separada e intercambiable.

También en 2.1

  • Objetivos de instalación de Hermes y OpenClaw: dos arneses más se unen a Claude Code, Codex, OpenCode, Cursor, Gemini, Zed, Copilot y Kimi.
  • Guía de navegación Codex ECC: encuentre la superficie de comando/habilidad adecuada desde el interior del Codex
  • Exenciones de ruta de GateGuard (GATEGUARD_EXEMPT_GLOBS) e inyección de instinto configurable (recuento + umbral de confianza)
  • PostToolUse enganches consolidados en despachadores sincronizados/asincrónicos, con menos procesos por llamada de herramienta
  • Reforzamiento de la cadena de suministro: el tiempo de ejecución del instalador pasa una investigación estricta y el análisis secreto previo a la confirmación ahora detecta claves Anthropic API (sk-ant-...).
  • Una larga lista de correcciones comunitarias en OpenCode, Windows, archivos de bloqueo de bun, el panel y detección de proyectos. El catálogo ahora cuenta con 67 agentes, 281 habilidades y 94 ajustes de comando (2.0.0 se envió el 64/261/84), además de ganchos, reglas, memoria, aprendizaje continuo y AgentShield.

ECC v2.1.0

Highlights

  • Plan Canvas replaces the terminal markdown wall at /plan's confirm gate — The agent now opens a loopback-only browser canvas: click elements or select text to attach numbered annotations, chat from a side rail while it works, and hit Approve / Request changes to drive the CONFIRM gate directly. Mermaid diagrams, tables, and task lists render natively and file edits live-reload, so review feedback is anchored to the actual plan instead of being retyped in chat. It's model- and harness-agnostic via a plain CLI + JSON protocol (ecc-plan-canvas) rather than a Claude-only dependency — expect to need a local browser, and treat that protocol as a new integration surface to validate.
  • Kimi Code becomes a first-class install target — bash ./install.sh --target kimi --profile minimal drops .kimi/AGENTS.md and .kimi/skills/, which Kimi Code discovers natively; verify with npx ecc doctor --target kimi. This is the first bundled non-Anthropic harness path, so adoption is a reinstall, not a config port. Hermes and OpenClaw join the target list, the catalog grows from 64/261/84 to 67 agents / 281 skills / 94 command shims, and the long tail of community fixes spans PRs #2100–#2543 — more surface area to audit on upgrade.
  • Self-hosted compute stays provider-agnostic, with guarded Itô sponsorship — ecc ito find is an explicitly opt-in bridge to the canonical Itô CLI that submits a live, authenticated RFQ; it does not reserve capacity, and the sponsorship link itself is passive. Node qualification is guarded, compute handoff is read-only, and credential-bearing CLI shims are rejected outright. Watch the semantics: managed inference through Itô is not live yet, so an RFQ is a quote request, not provisioned GPUs — any compatible serving endpoint works.
  • GateGuard and instinct injection gain configuration knobs — GATEGUARD_EXEMPT_GLOBS lets you carve paths out of gating, and instinct injection is now tunable by count and confidence threshold. If you depended on the old fixed gating behavior, re-check which paths are exempt and how many instincts actually get injected before trusting the gate.
  • PostToolUse hooks and supply-chain checks tighten up — Hooks are consolidated into sync/async dispatchers with fewer processes per tool call — a performance win, but verify any hook that assumed one process per call or strict ordering. The installer runtime now passes strict vetting and the pre-commit secret scan catches Anthropic sk-ant-... keys; good for hygiene, though previously accepted installer scripts may be rejected.
  • Breaking changes — None; existing installs upgrade in place with /plugin update ecc.

ECC 2.1.0: Plan Canvas, Kimi Harness, and Self-Hosted Compute

ECC 2.1 turns plan review into a visual loop and opens the harness to self-hosted models. Plan Canvas lets you review agent plans in the browser. Point at the part you mean instead of retyping it in chat. A new Kimi Code install target and a verified Itô GPU path make ECC + open-source models a first-class setup, backed by our public sponsors: Moonshot AI (Kimi), Itô, and Atlas Cloud.

Plan Canvas: review plans by pointing, not retyping

Download the MP4 demo

/plan ends with a confirm gate, and until now that review was a wall of markdown in the terminal. Now the agent opens the plan in a loopback-only browser canvas:

  • Click elements or select text to attach numbered annotations
  • Chat with the agent from a side rail while it works in the terminal
  • Approve plan / Request changes buttons map directly onto /plan's CONFIRM gate
  • Mermaid diagrams, tables, and task lists render natively; file edits live-reload the page
  • Model- and harness-agnostic: a plain CLI + JSON protocol (ecc-plan-canvas), no Claude-only dependency

Kimi harness: Moonshot AI partnership

ECC now installs directly into Kimi Code (--target kimi). Kimi Code discovers the installed .kimi/AGENTS.md instructions and .kimi/skills/ workflows natively:

bash ./install.sh --target kimi --profile minimal
npx ecc doctor --target kimi
kimi

Self-host on Itô GPUs

Run ECC against any self-hosted open-source model. If you need GPU capacity, Itô is ECC's preferred compute sponsor. The integration shipped guarded end to end:

  • ecc ito find: opt-in bridge to the canonical Itô CLI that submits a live, authenticated RFQ (it does not reserve capacity)
  • Guarded live node qualification and read-only compute handoff
  • Credential-bearing CLI shims are rejected outright

The sponsorship link itself is passive: it does not invoke an RFQ, reserve capacity, provision compute, or configure serving. Managed inference through Itô is not live yet. Any GPU provider works, and ECC stays provider-agnostic.

Partners

Moonshot AI (Kimi), Itô, and Atlas Cloud are now public sponsors of ECC. The README documents a recommended self-host path: Itô for GPU capacity, a Kimi checkpoint served behind a compatible endpoint, then Kimi Code + ECC on top. Each choice remains separate and swappable.

Also in 2.1

  • Hermes and OpenClaw install targets: two more harnesses join Claude Code, Codex, OpenCode, Cursor, Gemini, Zed, Copilot, and Kimi
  • Codex ECC navigation guide: find the right skill/command surface from inside Codex
  • GateGuard path exemptions (GATEGUARD_EXEMPT_GLOBS) and configurable instinct injection (count + confidence threshold)
  • PostToolUse hooks consolidated into sync/async dispatchers, with fewer processes per tool call
  • Supply-chain hardening: the installer runtime passes strict vetting, and the pre-commit secret scan now catches Anthropic API keys (sk-ant-...)
  • A long tail of community fixes across OpenCode, Windows, bun lockfiles, the dashboard, and project detection

The catalog now stands at 67 agents, 281 skills, and 94 command shims (2.0.0 shipped 64/261/84), plus hooks, rules, memory, continuous learning, and AgentShield.
