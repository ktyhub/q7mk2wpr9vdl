#ECC v2.2.1 #ECC 2.2.1 ECC 2.2.1 es un parche de seguridad y errores para ECC 2.2. Mantiene lo publicado Historia v2.2.0 inmutable. Estas notas describen el parche preparado; publicación y la firma de evidencia se rastrean por separado en la lista de verificación de liberación.

Seguridad y protección de datos

  • GateGuard y la captura de gobernanza reconocen comandos destructivos de PowerShell, incluida la ruta de la herramienta nativa de PowerShell. El manejo dinámico de comandos evita asignaciones de variables posteriores para ocultar invocaciones anteriores no resueltas (#2961).
  • Los globos de exención relativa de GateGuard permanecen dentro de la raíz del proyecto. Explícito se siguen apoyando las exenciones absolutas (#2921).
  • El instalador escribe rechazos de colisiones con archivos propiedad del usuario sin seguimiento. Fallido instala hashes de propiedad de actualización solo para los archivos que realmente escribieron, preservando el anterior hashes de propiedad de archivos administrados intactos (#2964).
  • La configuración guiada revalida su vista previa antes del filtrado de propiedad, por lo que los archivos que aparece entre la vista previa y la aplicación provoca un reintento claro en lugar de un falso éxito. Los archivos de usuario idénticos existentes permanecen fuera de la propiedad de ECC.
  • La desinstalación respeta ECC_DRY_RUN=1, incluidas las rutas heredadas del Codex, y rechaza valores de ejecución en seco no válidos en lugar de permitir la eliminación silenciosamente (#2952).
  • El análisis del observador conserva las observaciones fallidas o no confirmadas. procesamiento. El código de salida cero por sí solo ya no permite el archivo (#2971).
  • El archivo de bloqueo Yarn actualiza toml a 4.3.0, coincidiendo con el archivo de bloqueo npm y eliminando la resolución anterior afectada.

Ganchos e instalación

  • Las instalaciones manuales de Claude registran entradas de gancho propiedad de ECC en la configuración de Claude. Reparar, aceptar cambios y desinstalar conciliar esas entradas mientras preservando configuraciones no relacionadas. Actualizaciones de configuración atómica verificar directorio Identificar y reintentar ediciones simultáneas detectadas. (#2992).
  • Los puntos de entrada de gancho directo manejan cargas útiles más grandes de JSON con seguridad UTF-8 limitada lee en lugar de truncar silenciosamente las entradas válidas. Producción existente los límites de contenedor permanecen sin cambios (#2924).
  • El adaptador Pi selecciona un tiempo de ejecución de nodo real en lugar de recursivamente ejecutando un host OMP compilado como Nodo (#2909).
  • La lista de instaladores y el panel de control ayudan a evitar la dependencia de terceros cargando. Las funciones que requieren paquetes de tiempo de ejecución ausentes informan sobre la falta dependencia explícitamente (#2994).
  • La documentación de configuración del arnés autónomo reemplaza los nombres de paquetes inexistentes y banderas CLI no compatibles con interfaces documentadas, y distingue programación de sesiones desde un programador externo duradero (#2957).

Instalador y endurecimiento de la superficie de liberación

  • Los documentos de instalación públicos y empaquetados ahora apuntan consistentemente a la versión publicada. Comandos ecc-universal en lugar de nombres de paquetes obsoletos o no relacionados.
  • Los documentos del adaptador AdaL utilizan el npx ecc-universal doctor --target adal correcto comando.
  • La configuración de Claude realiza comprobaciones previas de git antes de que comience el trabajo específico del proveedor, por lo que falta Los requisitos previos fallan rápidamente con la acción correcta.
  • Los simulacros de configuración guiada utilizan aplicaciones HOME, config, XDG, temp y Windows aisladas raíces de datos para evitar que el estado ambiental del host afecte la revisión o las pruebas.
  • El artefacto empaquetado exacto ahora tiene una cobertura de ciclo de vida más sólida para Claude y Flujos de configuración, actualización, tratamiento, repetición de instalación, desinstalación y ejecución en seco de Kimi.
  • La cobertura de regresión del identificador bloquea ecc, ecc-install y otros obsoletos. los comandos de ruta de lanzamiento no coincidentes vuelvan a aparecer en los documentos de cara al usuario.

Documentación principal actual incluida en este parche

  • El flujo de trabajo canónico de Itô ahora documenta ecc ito accept <ticket-id> y el Herramienta MCP ito_accept.
  • La aceptación está explícitamente limitada a la ruta de la autoridad del comprador. Enruta el cotización de escritorio activo para revisión humana y no pretende realizar una operación.

Límite de procedencia

  • v2.2.1 pretende ser una etiqueta anotada y firmada en el main verde exacto.
  • v2.2.0 sigue siendo la excepción histórica inmutable sin firmar. no te muevas, recrear o reutilizar esa etiqueta.

Alcance y limitaciones

  • Falta el manejo de dependencias de complementos que no se agrupan ni se instalan automáticamente módulos. Las funciones de validación de esquemas y bases de datos requieren su declaración. dependencias de tiempo de ejecución.
  • La protección de propiedad cubre colisiones sin seguimiento e instalación fallida puntos de control. Las actualizaciones exitosas conservan el contrato existente para reemplazar archivos previamente administrados. Haga una copia de seguridad de las ediciones intencionales antes de actualizar.
  • Este parche no introduce nuevas plataformas de arnés ni afirma que cada El problema de la comunidad abierta está resuelto.

ECC v2.2.1

Highlights

  • PowerShell guard bypasses closed — GateGuard and governance capture now recognize destructive PowerShell commands through the native tool path and track unresolved invocations across later variable assignments (#2961), reducing the chance that dynamic commands evade review.
  • Safer installs and ownership recovery — The installer rejects collisions with untracked user-owned files and preserves ownership hashes for files a failed install did not modify (#2964). Guided setup revalidates its preview before applying changes, preventing false success when files appear mid-run. Successful upgrades can still replace previously ECC-managed files, so back up intentional edits.
  • Claude hook lifecycle is managed atomically — Manual installs register and reconcile ECC-owned hook entries while preserving unrelated settings, with directory-identity checks and retries for concurrent edits (#2992). Repairs, consent changes, and uninstall now update those entries automatically.
  • More reliable hooks and adapters — Direct hook entrypoints accept larger JSON payloads through bounded, UTF-8-safe reads instead of silently truncating valid input (#2924); production wrapper limits remain unchanged. The Pi adapter now launches an actual Node runtime rather than recursively invoking the compiled OMP host (#2909).
  • Data retention and dependency hardening — Observer analysis retains observations until processing is confirmed successful, rather than trusting exit code zero alone (#2971). Yarn now matches npm on toml 4.3.0, removing the affected older resolution; optional and database dependencies remain explicit and are not automatically installed.
  • Upgrade and compatibility — Once publication and registry integrity are verified, run npm install -g ecc-universal@2.2.1 followed by ecc doctor. Uninstall previews honor ECC_DRY_RUN=1, including legacy Codex paths, and invalid values are rejected rather than permitting deletion (#2952). No breaking changes are introduced.

ECC 2.2.1

ECC 2.2.1 is a bug and security patch for ECC 2.2. It keeps the published v2.2.0 history immutable. These notes describe the prepared patch; publication and signing evidence are tracked separately in the release checklist.

Security and data protection

  • GateGuard and governance capture recognize destructive PowerShell commands, including the native PowerShell tool path. Dynamic command handling prevents later variable assignments from concealing earlier unresolved invocations (#2961).
  • Relative GateGuard exemption globs stay within the project root. Explicit absolute exemptions remain supported (#2921).
  • Installer writes reject collisions with untracked user-owned files. Failed installs refresh ownership hashes only for files they actually wrote, preserving the previous ownership hashes of untouched managed files (#2964).
  • Guided setup revalidates its preview before ownership filtering, so files appearing between preview and apply cause a clear retry instead of a false success. Existing identical user files stay outside ECC ownership.
  • Uninstall respects ECC_DRY_RUN=1, including legacy Codex paths, and rejects invalid dry-run values instead of silently allowing deletion (#2952).
  • Observer analysis retains observations on unsuccessful or unconfirmed processing. Exit code zero alone no longer permits archival (#2971).
  • The Yarn lockfile updates toml to 4.3.0, matching the npm lockfile and removing the affected older resolution.

Hooks and installation

  • Manual Claude installs register ECC-owned hook entries in Claude settings. Repair, consent changes, and uninstall reconcile those entries while preserving unrelated settings. Atomic settings updates check directory identity and retry detected concurrent edits (#2992).
  • Direct hook entrypoints handle larger JSON payloads with bounded, UTF-8-safe reads instead of silently truncating valid inputs. Existing production wrapper limits remain unchanged (#2924).
  • The Pi adapter selects an actual Node runtime instead of recursively executing a compiled OMP host as Node (#2909).
  • Installer listing and control-pane help avoid eager third-party dependency loading. Features that require absent runtime packages report the missing dependency explicitly (#2994).
  • Autonomous harness setup documentation replaces nonexistent package names and unsupported CLI flags with documented interfaces, and distinguishes session scheduling from a durable external scheduler (#2957).

Installer and release-surface hardening

  • Public and packaged install docs now consistently point at the published ecc-universal commands instead of stale or unrelated package names.
  • The AdaL adapter docs use the correct npx ecc-universal doctor --target adal command.
  • Claude setup preflights git before provider-specific work starts, so missing prerequisites fail fast with the right action.
  • Guided setup dry runs use isolated HOME, config, XDG, temp, and Windows app data roots to avoid ambient host state affecting review or tests.
  • The exact packed artifact now has stronger lifecycle coverage for Claude and Kimi setup, update, doctor, repeat install, uninstall, and dry-run flows.
  • Identifier regression coverage blocks stale ecc, ecc-install, and other mismatched release-path commands from creeping back into user-facing docs.

Current-main documentation included in this patch

  • The canonical Itô workflow now documents ecc ito accept <ticket-id> and the ito_accept MCP tool.
  • Acceptance is explicitly bounded to buyer-authority routing. It routes the active desk quote to human review and does not claim to place a trade.

Provenance boundary

  • v2.2.1 is intended to be a signed annotated tag on exact green main.
  • v2.2.0 remains the immutable historical unsigned exception. Do not move, recreate, or reuse that tag.

Scope and limitations

  • Plugin dependency handling does not bundle or automatically install missing modules. Database and schema-validation features require their declared runtime dependencies.
  • Ownership protection covers untracked collisions and failed-install checkpoints. Successful upgrades retain the existing contract for replacing previously managed files. Back up intentional edits before upgrading.
  • This patch does not introduce new harness platforms or claim that every open community issue is resolved.

Upgrade

After the release workflow publishes 2.2.1 and verifies registry integrity, install or update the package, then run the same ECC command path you already use. Until publication completes, the exact-version command below returns E404.

npm install -g ecc-universal@2.2.1
ecc doctor

For first-time or guided terminal setup:

npx ecc-universal setup

The native Claude marketplace path remains supported:

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc
