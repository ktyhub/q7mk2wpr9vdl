#ECC v2.2.2 #ECC 2.2.2 ECC 2.2.2 agrega pi/core, un perfil seleccionado de habilidades nativas de Pi y solo indicaciones creado para empaquetadores posteriores que reflejan las versiones GitHub, además de un conjunto de paquetes, memoria, ganchos y correcciones de compatibilidad de Windows.

Perfil central de Pi

pi/core/ es un paquete autónomo (ecc-pi-core) que refleja posteriormente la versión tarball se puede copiar directamente: sin paso de compilación, sin extensiones, sin ganchos, sin tiempo de ejecución descargas y sin dependencias de red o SaaS.

  • 123 habilidades seleccionadas (patrones de lenguaje y marco, pruebas/TDD, revisión de código, revisión de seguridad, planificación, refactorización, documentos y flujos de trabajo de git/PR no ofensivos) y 24 comandos de aviso que son flujos de trabajo de aviso puro.
  • Generado de forma determinista a partir de las listas explícitas de inclusión/exclusión en manifests/pi-core.json por scripts/build-pi-core.js y comprometido, por lo que el el tarball de lanzamiento lo contiene palabra por palabra. pi/core/CURATION.md enumera todos los excluidos habilidad y dominio con su razón; la habilidad council se envía como ecc-council dentro de pi/core para evitar conflictos de nombres de catálogo.
  • La compilación falla debido a infracciones de seguridad: hosts de URL no permitidos, de canalización a shell. o buscar y ejecutar formularios de descarga, secretos o tokens, inicio absoluto por usuario rutas, enlaces simbólicos, texto frontal de SKILL.md no válido y nombres de habilidades duplicados.
  • CI reconstruye pi/core en cada PR y verifica que esté actualizado, luego lo instala el agente de codificación Pi CLI y demuestra que el perfil se carga completamente sin conexión (PI_OFFLINE=1), afirmando que cada comando seleccionado realmente se registra.
  • El flujo de trabajo de lanzamiento verifica además que VERSION coincida con la etiqueta y ese pi/core está actualizado antes de publicarse. Consumo aguas abajo: encuesta /releases, descargar archive/refs/tags/vX.Y.Z.tar.gz, fije su sha256, copie pi/core/ y cárguelo sin conexión con pi --offline --skill pi/core/skills --prompt-template pi/core/commands.

Embalaje

  • La carga útil compilada de OpenCode se incluye explícitamente en el paquete npm, y El embalaje se verifica desde un estado limpio con scripts de ciclo de vida habilitados.

Memoria y MCP

  • Las lecturas de memoria incompletas se distinguen de los registros y directorios faltantes. Las fallas transversales se clasifican.
  • El parámetro reservado _meta se acepta en las solicitudes de ping de la memoria MCP.

Ganchos y compatibilidad con Windows

  • hooks.json permanece dentro del esquema de Claude Code; metadatos de gancho estable movidos a un sidecar validado.
  • La protección sin verificación maneja los valores opcionales bloqueados y los prefijos de opciones largas.
  • Se admiten las rutas de Windows Linter y ESLint 9, y se toleran las actualizaciones de configuración. Faltan ID de dispositivos de Windows y al mismo tiempo se conservan comprobaciones de inodos de total precisión.

Guía de flujo de trabajo, catálogo y seguridad de dependencias

  • La sincronización épica filtra los problemas por etiqueta; Los aumentos de dependencia ya no se documentan fusión automática; la denominación y la guía booleana son neutrales en cuanto al idioma; el prp-pr se distingue el alias del comando; Descubrimiento de habilidades de Rails, cálculo de impuestos sobre facturas se corrigió el orden y la documentación marco; Catálogo Serply y Squish Se eliminaron las entradas.
  • lru actualizado a 0.18.2 (RUSTSEC-2026-0253) y js-yaml a 4.3.2 (GHSA-2883-xcg3-v3hh).

ECC v2.2.2

ECC 2.2.2

ECC 2.2.2 adds pi/core, a curated Pi-native skills+prompts-only profile built for downstream packagers that mirror GitHub Releases, plus a set of packaging, memory, hooks, and Windows compatibility fixes.

Pi core profile

pi/core/ is a self-contained package (ecc-pi-core) that downstream mirrors of the release tarball can copy directly: no build step, no extensions, no hooks, no runtime downloads, and no network or SaaS dependencies.

  • 123 curated skills (language and framework patterns, testing/TDD, code review, non-offensive security review, planning, refactoring, docs, and git/PR workflows) and 24 prompt commands that are pure prompt workflows.
  • Generated deterministically from the explicit include/exclude lists in manifests/pi-core.json by scripts/build-pi-core.js and committed, so the release tarball contains it verbatim. pi/core/CURATION.md lists every excluded skill and command with its reason; the council skill ships as ecc-council inside pi/core to avoid catalog name clashes.
  • The build fails on safety violations: non-allowlisted URL hosts, pipe-to-shell or fetch-and-run download forms, secrets or tokens, absolute per-user home paths, symlinks, invalid SKILL.md frontmatter, and duplicate skill names.
  • CI rebuilds pi/core on every PR and verifies it is up to date, then installs the Pi coding agent CLI and proves the profile loads fully offline (PI_OFFLINE=1), asserting that every curated command actually registers.
  • The release workflow additionally verifies that VERSION matches the tag and that pi/core is current before publishing.

Downstream consumption: poll /releases, download archive/refs/tags/vX.Y.Z.tar.gz, pin its sha256, copy pi/core/, and load it offline with pi --offline --skill pi/core/skills --prompt-template pi/core/commands.

Packaging

  • The compiled OpenCode payload is explicitly included in the npm package, and packing is verified from a clean state with lifecycle scripts enabled.

Memory and MCP

  • Incomplete memory reads are distinguished from missing records, and directory traversal failures are classified.
  • The reserved _meta parameter is accepted on memory MCP ping requests.

Hooks and Windows compatibility

  • hooks.json stays within Claude Code's schema; stable hook metadata moved into a validated sidecar.
  • The no-verify guard handles stuck optional values and long-option prefixes.
  • Windows linter paths and ESLint 9 are supported, and settings updates tolerate missing Windows device IDs while retaining full-precision inode checks.

Workflow guidance, catalog, and dependency security

  • Epic sync filters issues by label; dependency bumps no longer document auto-merge; naming and Boolean guidance is language-neutral; the prp-pr command alias is distinguished; Rails skill discovery, invoice tax calculation order, and framework documentation were corrected; Serply and Squish catalog entries were removed.
  • lru updated to 0.18.2 (RUSTSEC-2026-0253) and js-yaml to 4.3.2 (GHSA-2883-xcg3-v3hh).
