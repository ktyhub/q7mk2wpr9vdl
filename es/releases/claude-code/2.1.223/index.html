código-claude v2.1.223

¿Qué ha cambiado?

  • Se agregaron entradas comodín de propietario ("owner/*") a las configuraciones administradas de strictKnownMarketplaces y blockedMarketplaces para permitir o bloquear todos los repositorios del mercado bajo una organización GitHub.
  • Se agregó una advertencia cuando el modelo de subagente solicitado de agentes de flujo de trabajo, habilidades bifurcadas, comandos de barra diagonal o agentes en segundo plano reanudados está restringido y en su lugar se ejecuta el modelo principal.
  • Se agregó una pista de /teleport en sesiones en la nube que muestra cómo continuar localmente con claude --teleport <session id>.
  • Se corrigió una omisión de permisos de Bash donde un comando diseñado podía ocultar partes de sí mismo de las comprobaciones de permisos.
  • Se corrigieron las solicitudes de permiso para que los comandos rellenos con pestañas o Unicode invisible ya no puedan ocultar parte del comando del cuadro de diálogo de aprobación.
  • Se corrigieron los scripts de flujo de trabajo que podían usar import() dinámico para ejecutar código fuera del entorno limitado del flujo de trabajo.
  • Se corrigió una brecha de permisos donde el modo bypassPermissions de la definición de un agente ignoraba la política de desactivación de permisos de omisión de la organización.
  • Se corrigió la reanudación de una sesión después de que un /cd a mitad de sesión volviera vacío.
  • Se corrigió el descubrimiento del modelo de puerta de enlace que ocultaba los modelos de Claude registrados con ID con prefijo del proveedor, como vertex_ai/claude-* o bedrock/anthropic.claude-*.
  • Se corrigieron las claves modelOverrides que no son ID de modelo antrópico y se tratan como ID de modelo canónico de la sesión; Las claves desconocidas ahora se ignoran como está documentado.
  • Configuración administrada fija: la configuración proporcionada por el servidor ya no desactiva el bloque env de un perfil managed-settings.json o MDM local de la máquina; admin env ahora se fusiona por clave
  • Se corrigieron los comandos de espacio aislado que no se iniciaban en Linux cuando sandbox.filesystem.denyWrite cubre el directorio de trabajo.
  • Se corrigió que los agentes en segundo plano bifurcados se quedaran atascados "ya se estaban reanudando" durante el resto de la sesión cuando la reconstrucción del mensaje principal de la bifurcación fallaba durante la reanudación.
  • Se corrigió una sesión reanudada que fallaba en cada turno o dejaba la aplicación interactiva en una pantalla de error que no respondía, cuando su historial contenía un archivo adjunto de diagnóstico mal formado.
  • Se corrigió un problema poco común al analizar la salida inusual de git push.
  • Se cambió CLAUDE_CODE_DISABLE_1M_CONTEXT para mantener cada modelo de Claude con una ventana nativa de 1M a 200K mediante autocompactación, no solo una lista fija; Ahora aparece una advertencia de inicio cuando la compactación automática no mantiene la sesión en 200K.
  • Se modificó la compactación automática para mantener las sesiones con ID de modelo no reconocidos dentro de la ventana de contexto asumida en lugar de permitir que crezcan más allá de ella; configure CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 para restaurar el comportamiento anterior
  • Se cambió /review para que sea un alias de /code-review, que revisa la diferencia actual o un PR (/code-review <level> <pr#>); use /code-review ultra para una revisión profunda de la nube
  • Se modificó /code-review sin nivel de esfuerzo para reutilizar el último nivel que escribiste; escriba un nivel como /code-review high para cambiarlo

claude-code v2.1.223

What's changed

  • Added owner wildcard entries ("owner/*") to the strictKnownMarketplaces and blockedMarketplaces managed settings for allowing or blocking all marketplace repos under a GitHub org
  • Added a warning when workflow agents, forked skills, slash commands, or resumed background agents' requested subagent model is restricted and the parent model runs instead
  • Added a /teleport hint in cloud sessions showing how to continue locally with claude --teleport <session id>
  • Fixed a Bash permission bypass where a crafted command could hide parts of itself from permission checks
  • Fixed permission prompts so commands padded with tabs or invisible Unicode can no longer hide part of the command from the approval dialog
  • Fixed workflow scripts being able to use dynamic import() to run code outside the workflow sandbox
  • Fixed a permission gap where an agent definition's bypassPermissions mode ignored the org bypass-permissions disable policy
  • Fixed resuming a session after a mid-session /cd coming back empty
  • Fixed gateway model discovery hiding Claude models registered under provider-prefixed IDs such as vertex_ai/claude-* or bedrock/anthropic.claude-*
  • Fixed modelOverrides keys that aren't Anthropic model IDs being treated as the session's canonical model ID; unknown keys are now ignored as documented
  • Fixed managed settings: server-delivered settings no longer disable the env block of a machine-local managed-settings.json or MDM profile; admin env now merges per key
  • Fixed sandboxed commands failing to start on Linux when sandbox.filesystem.denyWrite covers the working directory
  • Fixed forked background agents getting stuck "already resuming" for the rest of the session when rebuilding the fork's parent prompt failed during resume
  • Fixed a resumed session failing every turn, or leaving the interactive app on an unresponsive error screen, when its history held a malformed diagnostics attachment
  • Fixed a rare hang when parsing unusual git push output
  • Changed CLAUDE_CODE_DISABLE_1M_CONTEXT to hold every Claude model with a native 1M window to 200K via auto-compaction, not just a fixed list; a startup warning now appears when auto-compaction isn't holding the session to 200K
  • Changed auto-compact to keep sessions on unrecognized model IDs within the assumed context window instead of letting them grow past it; set CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 to restore the previous behavior
  • Changed /review to be an alias of /code-review, which reviews the current diff or a PR (/code-review <level> <pr#>); use /code-review ultra for a deep cloud review
  • Changed /code-review with no effort level to reuse the level you typed last; type a level like /code-review high to change it
