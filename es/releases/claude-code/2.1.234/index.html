código-claude v2.1.234

¿Qué ha cambiado?

  • Se agregó la variable de entorno opcional CLAUDE_CODE_PROJECT_DIR_NAME: los hosts que le dan a cada sesión su propio directorio de configuración pueden elegir un nombre corto para el directorio de transcripción por proyecto.
  • Se agregó la acción de combinación de teclas selection:clear, por lo que se puede vincular una tecla para borrar una selección de texto en la aplicación; también funciona en la vista de agentes
  • Se agregó una insignia de solicitud de fusión GitLab al pie de página y a la línea de estado: los repositorios con un control remoto GitLab y un glab CLI autenticado muestran MR !N con estados borrador/pendiente/verde
  • Claude Code ahora continúa su sesión automáticamente cuando se restablece el límite de uso de claude.ai; apáguelo en /config ("Continuar automáticamente al límite de uso")
  • Ahora se le dice a Claude que use el correo electrónico de su cuenta solo para identificarlo y que no lo envíe a servicios no relacionados a menos que usted lo solicite.
  • Seguridad: las lecturas remotas de archivos, la restauración de sesiones, las inclusiones de CLAUDE.md, los scripts de flujo de trabajo y las cargas de archivos ahora rechazan las rutas del espacio de nombres de Windows NT (\??\), lo que protege los accesos restantes a los archivos de aprobación previa contra el vector de fuga de credenciales NTLM.
  • Se corrigió el modo automático en sesiones muy largas, volviendo a verificar y negando repetidamente el acceso a la red de los comandos de espacio aislado después de que la conversación había sido compactada.
  • Se corrigieron las respuestas de permisos de ámbito de sesión (incluidas las denegaciones) que se eliminaban al responder solicitudes de permisos de la herramienta subagente en segundo plano.
  • Se corrigió un bloqueo cuando una respuesta API en la ruta alternativa sin transmisión (generalmente a través de puertas de enlace de terceros) contenía un bloque de pensamiento al que le faltaba su campo de pensamiento o un bloque de texto al que le faltaba su campo de texto.
  • Se corrigió que la representación de rebajas se volviera extremadamente lenta para algunos mensajes que contenían secuencias Unicode inusuales.
  • Se corrigió que SendMessage rechazara un destinatario copiado de ListAgents cuando el nombre de la sesión tiene un límite de 200 caracteres o tiene muchos emojis.
  • Se corrigió la detección de repositorio que leía mal el host de controles remotos de git con información de usuario inusual, lo que generaba enlaces y comportamiento específico del repositorio para el host incorrecto.
  • Se corrigió el diagnóstico de MCP que imprimía secretos resueltos: las advertencias de conflicto de alcance ahora muestran el formulario ${VAR} configurado y los detalles de falla de conexión muestran solo el origen del servidor.
  • Se corrigieron las listas permitidas de strictKnownMarketplaces que aceptan fuentes de mercado de git estilo SCP cuyo host difiere del que git realmente se conectaría.
  • Se corrigió el texto modal, como la URL /login OAuth, que perdía caracteres cuando se copiaba en pantalla completa.
  • Se corrigió una regla horizontal --- en la rebaja renderizada que llegaba a la línea posterior.
  • Se corrigieron comandos de shell consecutivos que se dividían en múltiples filas de "comando de shell ejecutado 1" cuando las actualizaciones de tareas pendientes se intercalaban entre ellas.
  • Se corrigieron cuadros de diálogo como /permissions que se abrían mientras se ejecutaba un comando de shell ! y que se descartaban cuando finalizaba el comando.
  • Se corrigió un comando de shell ! en cola que se enviaba al modelo como texto sin formato después de presionar la flecha hacia arriba para editar la entrada en cola.
  • Se corrigió que los mensajes en cola reaparecieran en el historial de mensajes mientras aún estaban en cola, Esc al seleccionar un mensaje en cola ya no interrumpe el turno y el modo ! ya no se mantiene después de un envío a mitad de turno.
  • Se corrigió la aceptación del mensaje "¿Probar el nuevo renderizador de pantalla completa?" solicitar reiniciar la sesión sin su modo de permiso (por ejemplo, --dangerously-skip-permissions), herramientas para permitir/denegar reglas, modelo o indicadores de esfuerzo
  • Se corrigió que /tui dejara caer las reglas de inicio --allowed-tools/--disallowed-tools cuando se reinicia; Ahora es necesario cambiar, debido a que cuando la sesión tiene restricciones, el reinicio no se puede transferir.
  • Se corrigieron los mensajes trust que omitían la advertencia de alcance de todo el repositorio cuando el directorio se veía por primera vez antes de que el repositorio existiera allí.
  • Se corrigió un caso en el que el cierre de una pestaña de diferencias de IDE durante una nueva solicitud de permiso podía responder a la nueva solicitud con la entrada anterior.
  • Corregido: los archivos enviados al usuario durante las sesiones de Control remoto hospedadas por Claude Code Desktop o VS Code ahora se cargan, por lo que se abren en el teléfono y en la web en lugar de mostrar una tarjeta vacía.
  • Corregido: después de /login mientras CLAUDE_CODE_OAUTH_TOKEN está configurado, el recordatorio de ficha obsoleta ya no se filtra en el turno reanudado automáticamente de Claude; ahora solo te aparece a ti.
  • Corregido: las vistas previas de permisos ahora se transmiten solo a los servidores de canal admitidos por la puerta de entrada trust, y se respeta la opción de exclusión voluntaria de capacidad de permiso explícita de un servidor.
  • Corregido: el enmascaramiento de credenciales en las vistas previas de permisos retransmitidos ya no puede ocultar comandos, rutas o destinos al aprobador; bloques de clave privada de gran tamaño ahora redactados bajo redacción completa
  • Corregido: los tokens del proveedor API que se enmascaran en las vistas previas de permisos ahora se enmascaran incluso cuando van seguidos directamente de delimitadores de shell.
  • Se corrigió que la sesión del destinatario descartara silenciosamente los mensajes entre sesiones de Claude Desktop cuando los mensajes entre sesiones se leían como deshabilitados, lo que dejaba la consulta del remitente "pensando" durante muchos minutos.
  • Control remoto: al iniciar sesión en esta computadora en una cuenta u organización diferente de claude.ai ahora se detiene la sesión en ejecución en cuestión de segundos y se indica el motivo, en lugar de un HTTP engañoso 404 horas después.
  • Las sesiones de control remoto iniciadas desde Claude Code Desktop o VS Code ahora mantienen los teléfonos y claude.ai/code actualizados en el modo de permiso de la sesión (y claude.ai/code en el modelo) a medida que cambian.
  • Control remoto: las selecciones de esfuerzo realizadas en un teléfono o en claude.ai/code ahora se aplican a las sesiones alojadas en terminal y escritorio/VS Code, y la sesión publica su nivel de esfuerzo en los clients conectados.
  • SendMessage y ListAgents ahora indican cuándo la lista de sesiones de su cuenta era demasiado larga para verificarla por completo, en lugar de tratar las sesiones no vistas como ausentes.
  • La credencial de perfil Anthropic vencida ahora lo dirige a /login cuando un inicio de sesión en claude.ai tendría prioridad
  • Se mejoró la transcripción: sus propias indicaciones ahora muestran rebajas (bloques de código resaltados, código en línea, listas) de la misma manera que lo hacen las respuestas.
  • Se mejoró el error "API devolvió una respuesta vacía o con formato incorrecto" para indicar qué respondió (tipo de contenido, tipo de cuerpo, tamaño, ID de solicitud) y por qué falló la solicitud de transmisión original.
  • Títulos de sesión mejorados generados automáticamente para que se lean como nombres cortos y específicos (por ejemplo, "Error en el botón de inicio de sesión") en lugar de oraciones que repitan su solicitud (por ejemplo, "Reparar el botón de inicio de sesión en el móvil")
  • Se redujo el costo de contexto de cargar la habilidad claude-api incorporada de ~200 000 tokens a ~25 000 al cargar documentos de referencia bajo demanda.
  • Ahora se puede abrir /permissions mientras Claude está trabajando; los cambios en las reglas se aplican al resto del turno actual.
  • Ahora se puede utilizar /add-dir <path> mientras Claude está trabajando; Los cuadros de diálogo /add-dir, /autocompact, /theme, /help, /config y /advisor se abren a mitad de turno en la TUI de pantalla completa.
  • /goal ahora se borra solo con un aviso cuando un turno finaliza debido a un error irrecuperable (por ejemplo, autenticación revocada, saldo de crédito agotado o desbordamiento de contexto) en lugar de permanecer armado.
  • /goal: cuando las tareas en segundo plano hacen que un objetivo espere más de 30 minutos, Claude ahora las controla en lugar de esperar indefinidamente (configure CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 para optar por no participar).
  • claude setup-token ahora rechaza argumentos adicionales inesperados en lugar de ignorarlos silenciosamente.
  • Se cambió Esc en modo de pantalla completa para que ya no borre una selección de texto del mouse: interrumpe o descarta como de costumbre y la selección permanece resaltada.
  • Se eliminó la línea redundante "Permitido por el clasificador de modo automático" que el modo automático mostraba en cada llamada a la herramienta Agente.
  • Se eliminó la configuración "Modelo de compañero de equipo predeterminado" de /config; Los compañeros de equipo del agente ahora usan el modelo del líder a menos que el engendro nombre a uno.
  • Se atenuó el contador de tiempo transcurrido en el encabezado de la herramienta en ejecución para que ya no compita con los recuentos en negrita.
  • Las notificaciones de tareas en segundo plano entregadas entre turnos ahora se envían al modelo dentro de las etiquetas <system-reminder>, coincidiendo con la entrega a mitad de turno.
  • Manto: omita la prueba de disponibilidad del pin de administrador al inicio cuando ya se haya seleccionado un modelo de bucle principal
  • Windows: el inicio ya no se detiene al intentar cambiar el nombre repetidamente cuando ~/.claude.json es de solo lectura

claude-code v2.1.234

What's changed

  • Added the optional CLAUDE_CODE_PROJECT_DIR_NAME environment variable: hosts that give each session its own config directory can choose a short name for the per-project transcript directory
  • Added the selection:clear keybinding action, so a key can be bound to clear an in-app text selection; also works in the agents view
  • Added a GitLab merge request badge to the footer and statusline: repos with a GitLab remote and an authenticated glab CLI show MR !N with draft/pending/green states
  • Claude Code now continues your session automatically when a claude.ai usage limit resets; turn it off in /config ("Continue automatically at usage limit")
  • Claude is now told to use your account email only to identify you, and not to send it to unrelated services unless you ask
  • Security: remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads now reject Windows NT-namespace (\??\) paths, hardening the remaining pre-approval file accesses against the NTLM credential-leak vector
  • Fixed auto mode in very long sessions repeatedly re-checking and denying sandboxed commands' network access after the conversation had been compacted
  • Fixed session-scoped permission answers (including denies) being dropped when answering background subagent tool permission prompts
  • Fixed a crash when an API response on the non-streaming fallback path (typically via third-party gateways) contained a thinking block missing its thinking field or a text block missing its text field
  • Fixed markdown rendering becoming extremely slow for some messages containing unusual Unicode sequences
  • Fixed SendMessage rejecting a recipient copied from ListAgents when the session name is at the 200-character cap or emoji-heavy
  • Fixed repository detection mis-reading the host of git remotes with unusual userinfo, producing links and repo-specific behavior for the wrong host
  • Fixed MCP diagnostics printing resolved secrets: scope-conflict warnings now show the configured ${VAR} form, and connection-failure details show only the server origin
  • Fixed strictKnownMarketplaces allowlists accepting SCP-style git marketplace sources whose host differs from the one git would actually connect to
  • Fixed modal text such as the /login OAuth URL losing characters when copied in fullscreen
  • Fixed a --- horizontal rule in rendered markdown running into the line after it
  • Fixed consecutive shell commands splitting into multiple "Ran 1 shell command" rows when todo/task updates were interleaved between them
  • Fixed dialogs like /permissions opened while a ! shell command was running being dismissed when the command finished
  • Fixed a queued ! shell command being sent to the model as plain text after pressing up-arrow to edit the queued input
  • Fixed queued messages reappearing in the prompt history while still queued, Esc while selecting a queued message no longer interrupts the turn, and ! mode no longer sticks after a mid-turn submit
  • Fixed accepting the "Try the new fullscreen renderer?" prompt restarting the session without its permission mode (e.g. --dangerously-skip-permissions), tool allow/deny rules, model or effort flags
  • Fixed /tui dropping launch --allowed-tools/--disallowed-tools rules when it restarts; it now declines to switch, with the reason, when the session has restrictions a restart can't carry over
  • Fixed trust prompts omitting the repository-wide scope warning when the directory was first seen before the repository existed there
  • Fixed a case where an IDE diff tab closing during a permission re-prompt could answer the new prompt with the previous input
  • Fixed: files sent to the user during Remote Control sessions hosted by Claude Code Desktop or VS Code now upload, so they open on phone and web instead of showing an empty card
  • Fixed: after /login while CLAUDE_CODE_OAUTH_TOKEN is set, the stale-token reminder no longer leaks into Claude's automatically resumed turn — it now appears only to you
  • Fixed: permission previews now relay only to channel servers admitted by the inbound trust gate, and a server's explicit permission-capability opt-out is honored
  • Fixed: credential masking on relayed permission previews can no longer hide commands, paths, or destinations from the approver; oversized private-key blocks now redact under full-strength redaction
  • Fixed: provider API tokens that mask on permission previews now mask even when directly followed by shell delimiters
  • Fixed Claude Desktop inter-session messages being silently dropped by the recipient session when cross-session messaging read as disabled, which left the sender's query "thinking" for many minutes
  • Remote Control: signing this computer in to a different claude.ai account or organization now stops the running session within seconds and says why, instead of a misleading HTTP 404 hours later
  • Remote Control sessions started from Claude Code Desktop or VS Code now keep phones and claude.ai/code updated on the session's permission mode (and claude.ai/code on the model) as they change
  • Remote Control: effort picks made on a phone or on claude.ai/code now apply to terminal- and Desktop/VS Code-hosted sessions, and the session publishes its effort level to connected clients
  • SendMessage and ListAgents now say when your account's session list was too long to check completely, instead of treating unseen sessions as absent
  • Expired Anthropic profile credential now points you at /login when a claude.ai login would take precedence
  • Improved the transcript: your own prompts now render markdown (highlighted code blocks, inline code, lists) the same way replies do
  • Improved the "API returned an empty or malformed response" error to say what came back (content type, body kind, size, request ID) and why the original streaming request failed
  • Improved auto-generated session titles to read as short, specific names (e.g. "Login button bug") rather than sentences restating your request (e.g. "Fix the login button on mobile")
  • Reduced the context cost of loading the built-in claude-api skill from ~200k+ tokens to ~25k by loading reference docs on demand
  • /permissions can now be opened while Claude is working — rule changes apply to the rest of the current turn
  • /add-dir <path> can now be used while Claude is working; /add-dir, /autocompact, /theme, /help, /config and /advisor dialogs open mid-turn in the fullscreen TUI
  • /goal now clears itself with a notice when a turn dies on an unrecoverable error (e.g. revoked auth, an exhausted credit balance, or a context overflow) instead of staying armed
  • /goal: when background tasks keep a goal waiting for 30+ minutes, Claude now checks in on them instead of waiting indefinitely (set CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 to opt out)
  • claude setup-token now rejects unexpected extra arguments instead of silently ignoring them
  • Changed Esc in fullscreen mode to no longer clear a mouse text selection: it interrupts or dismisses as usual and the selection stays highlighted
  • Removed the redundant "Allowed by auto mode classifier" line that auto mode showed under every Agent tool call
  • Removed the "Default teammate model" setting from /config; agent-team teammates now use the leader's model unless the spawn names one
  • Dimmed the elapsed-time counter on the running tool header so it no longer competes with the bold counts
  • Background task notifications delivered between turns are now sent to the model inside <system-reminder> tags, matching mid-turn delivery
  • Mantle: skip the admin-pin availability probe at startup when a main-loop model is already picked
  • Windows: startup no longer stalls on repeated rename retries when ~/.claude.json is read-only
