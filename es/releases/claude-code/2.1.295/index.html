código-claude v2.1.295

¿Qué ha cambiado?

  • Se agregó onFailure: "block" para comandos y enlaces HTTP: un enlace que no puede iniciarse, se agota o sale con un código inesperado bloquea la acción en lugar de dejarla pasar.
  • Se agregó soporte para el Protocolo de estado del programa (OSC 7501): los terminales que lo implementan pueden mostrar si Claude Code está funcionando, esperándolo o listo.
  • Se agregó texto citado al selector /copy, por lo que un mensaje redactado se copia sin sus marcadores >.
  • Se agregó una advertencia a claude plugin install, enable, disable y marketplace add cuando el archivo de configuración en el que escriben no se carga.
  • Se agregó una línea en stderr, cuando es una terminal, que dice qué espera una ejecución claude -p cuando permanece abierta después de su último turno.
  • Se agregó soporte para timeouts.upstream_ttfb_ms en Bedrock, Vertex, Foundry y otras fuentes de nube de la puerta de enlace de aplicaciones de Claude: un valor que usted establece ahora limita cuánto tiempo puede tardar una transmisión en comenzar allí, después de lo cual falla o obtiene un 502.
  • Se agregó un mensaje de "Fondo cancelado" cuando detienes el giro mientras ← está esperando que finalice la herramienta actual.
  • Se agregó una lista models opcional a cada puerta de enlace de aplicaciones de Claude en sentido ascendente: solo los modelos enumerados se envían allí, también en caso de conmutación por error, y un * en una entrada es un comodín.
  • Se agregó soporte para forceLoginMethod: "gateway" y forceLoginGatewayUrl en su propia configuración de usuario en máquinas sin configuraciones administradas, por lo que /login se abre en esa puerta de enlace de aplicaciones de Claude.
  • Se agregó un consejo a claude plugin validate cuando el archivo README de un complemento no tiene una línea de instalación: imprime la línea para pegar y nunca cambia el código de salida, incluso con --strict
  • Se agregó upstream_request_id al evento de auditoría inference de la puerta de enlace de aplicaciones de Claude: el ID de solicitud de Amazon Bedrock, Anthropic API u otro upstream, para casos de soporte.
  • Se agregó $.ui.notify para mods: genera una notificación nativa a través de su propia configuración de notificación y dice qué canal la envió.
  • Se agregaron elementos secundarios al Button de un mod: cadenas y Text, por lo que una fila de una lista se puede presionar con un chip o un detalle tenue en el interior.
  • Se agregó CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS para limitar cuánto tiempo espera el modo de reintento desatendido (CLAUDE_CODE_RETRY_WATCHDOG) para los errores 429 y 529.
  • Se agregó un encabezado request-id a las respuestas de inferencia exitosas de la puerta de enlace de aplicaciones de Claude, de modo que request_id en la telemetría de Claude Code coincida con el registro de auditoría de la puerta de enlace.
  • Se corrigió cada solicitud que fallaba en un modelo [1m] cuando una puerta de enlace, Bedrock, Vertex o Foundry rechazaba el contexto-1m beta; Claude Code ahora se reenvía sin él
  • Se corrigió la salida de texto claude -p que dejaba caer las respuestas anteriores cuando el trabajo en segundo plano comenzaba otro turno; La respuesta de cada turno ahora se imprime cuando termina el turno.
  • Se corrigieron servidores MCP remotos en sesiones sin cabeza y SDK que permanecían desconectados después de una interrupción de más de 15 segundos, o se reconectaban en un bucle cerrado a un servidor que interrumpía cada conexión inmediatamente después de conectarse; Las caídas repetidas ahora retroceden, hasta 30 segundos.
  • Se corrigieron las conexiones MCP remotas que se interrumpían cuando la respuesta de error de un servidor contenía un nombre de error de red.
  • Se corrigieron los servidores MCP que repetían un cursor de paginación y se les solicitaba la misma página hasta 20 veces en cada conexión.

  • [Etiqueta de Claude] Se modificó el aviso de Claude de que un canal compartido en los espacios de trabajo de Enterprise Grid usa los valores predeterminados de la organización para publicar solo cuando alguien menciona a Claude, como máximo una vez al mes.
  • [Etiqueta de Claude] Se corrigieron los enlaces de canales y las menciones @ en la tarjeta "Continuación de" de un hilo bifurcado que se muestra como códigos de Slack sin procesar.

  • [Etiqueta de Claude] Se corrigió que @Claude de otra aplicación o bot quedara sin respuesta en un canal ocupado donde Claude había dejado de leer mensajes sin etiquetar.
  • [Claude Tag] Se agregó una confirmación en la configuración de administración de Claude Tag antes de agregar un administrador de canal y mover a ese miembro a roles personalizados, lo que puede eliminar su otro acceso.
  • [Revisión de código] Se corrigieron las re-revisiones de la revisión de código que decían que no se encontraron problemas mientras los hallazgos anteriores aún estaban abiertos; el comentario ahora dice cuantos quedan abiertos
  • [Revisión de código] Se corrigió que la revisión de código aún omitiera las reglas de CLAUDE.md de gran tamaño cuando la solicitud de extracción edita ese archivo
  • Se corrigieron las búsquedas web y las evaluaciones de ganchos agent que demoraban mucho más en el esfuerzo de xhigh y max.

What's changed

  • Added onFailure: "block" for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through
  • Added Program Status Protocol (OSC 7501) support: terminals that implement it can show whether Claude Code is working, waiting on you, or done
  • Added quoted text to the /copy picker, so a drafted message copies without its > markers
  • Added a warning to claude plugin install, enable, disable and marketplace add when the settings file they write to does not load
  • Added a line on stderr, when it is a terminal, that says what a claude -p run is waiting for when it stays open after its last turn
  • Added support for timeouts.upstream_ttfb_ms on the Claude apps gateway's Bedrock, Vertex, Foundry and other cloud upstreams: a value you set now limits how long a stream may take to start there, after which it fails over or gets a 502
  • Added a "Backgrounding cancelled" message when you stop the turn while ← is waiting for the current tool to finish
  • Added an optional models list to every Claude apps gateway upstream: only the listed models are sent there, on failover too, and one * in an entry is a wildcard
  • Added support for forceLoginMethod: "gateway" and forceLoginGatewayUrl in your own user settings on machines with no managed settings, so /login opens on that Claude apps gateway
  • Added advice to claude plugin validate when a plugin's README has no install line: it prints the line to paste and never changes the exit code, even with --strict
  • Added upstream_request_id to the Claude apps gateway's inference audit event: the request ID from Amazon Bedrock, the Anthropic API or another upstream, for support cases

  • Added children to a mod's Button: strings and Text, so a row of a list is one pressable with a chip or a dim detail inside
