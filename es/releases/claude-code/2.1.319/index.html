código-claude v2.1.319

¿Qué ha cambiado?

  • Se modificó el modo automático con telemetría o indicadores de funciones desactivados, incluso detrás de las puertas de enlace LLM: las llamadas que el servidor no puede verificar se solicitan o rechazan, sin respaldo al clasificador integrado; configure CLAUDE_CODE_AUTO_MODE_SERVER=0 para seguir usándolo (Bedrock, Vertex y Foundry no cambian)
  • Se modificó el modo automático detrás de una puerta de enlace LLM: CLAUDE_CODE_AUTO_MODE_SERVER=1 activa la verificación del lado del servidor incluso con CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS configurado; Si la configuración administrada establece lo último, también debe configurar 1.
  • Se agregó soporte para tareas MCP en la terminal: cuando un servidor MCP ejecuta una llamada de herramienta como tarea, Claude Code la mueve a un segundo plano de inmediato y le dice a Claude el resultado cuando finaliza.
  • Se agregó la variable de entorno CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND para hacer que Claude Code espere una tarea MCP dentro de su llamada de herramienta en lugar de moverla al fondo de inmediato.
  • Se agregó la configuración permissions.denyInsteadOfPrompting: se niega una llamada de herramienta que esperaría una solicitud de permiso y el turno continúa, en sesiones de terminal, subagentes y compañeros de equipo.
  • Se agregó /claude-api latency-optimize para encontrar dónde su código Claude API hace que la gente espere y pruebe configuraciones más rápidas en su evaluación.
  • Se agregó la variable de entorno CLAUDE_CODE_DISABLE_FEATURE_FLAGS, que detiene la búsqueda de indicadores de funciones sin desactivar la telemetría; cada bandera usa su valor predeterminado incorporado
  • Se agregó gasto para hoy, esta semana y este mes a /usage para los desarrolladores detrás de una puerta de enlace de aplicaciones Claude que no tienen límite de gasto, cuando la puerta de enlace ejecuta esta versión o posterior.
  • Se agregaron admin.pooled_conflict_rule y admin.pooled_priority_order al portal de aplicaciones de Claude, para establecer qué presupuesto de grupo conjunto paga primero por un desarrollador en varios grupos.
  • Se agregó una configuración opcional login_notice a la puerta de enlace de aplicaciones de Claude que muestra un mensaje definido por el operador en la página de verificación del navegador de la puerta de enlace y en la pantalla de inicio de sesión de Claude Code.
  • Se agregó CLAUDE_GATEWAY_LOG_FORMAT=json al portal de aplicaciones de Claude: las líneas de registro operativo se convierten en JSON con severity, time y message, para recopiladores de registros que leen el nivel de un campo.
  • Se agregó una advertencia de inicio de puerta de enlace de aplicaciones de Claude para un caso en el que availableModels de otra política también permite una identificación de modelo personalizada que una política enumera por nombre.
  • Se agregaron advertencias de inicio al portal de aplicaciones de Claude para políticas sin desktopHome que dependen de coworkTabEnabled: false o chatSessionRetentionDays, antes del cambio de Claude Desktop del 10 de noviembre.

claude-code v2.1.319

What's changed

  • Changed auto mode with telemetry or feature flags off, including behind LLM gateways: calls the server can't check are asked about or denied, with no fallback to the built-in classifier; set CLAUDE_CODE_AUTO_MODE_SERVER=0 to keep using it (Bedrock, Vertex and Foundry are unchanged)
  • Changed auto mode behind an LLM gateway: CLAUDE_CODE_AUTO_MODE_SERVER=1 turns on the server-side check even with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS set; if managed settings set the latter, they must set the 1 too
  • Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes
  • Added the CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND environment variable to make Claude Code wait for an MCP task inside its tool call instead of moving it to the background right away
  • Added permissions.denyInsteadOfPrompting setting: a tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates
  • Added /claude-api latency-optimize to find where your Claude API code makes people wait and try faster settings against your eval
  • Added the CLAUDE_CODE_DISABLE_FEATURE_FLAGS environment variable, which stops feature-flag fetching without turning off telemetry; every flag then uses its built-in default
  • Added spend for today, this week and this month to /usage for developers behind a Claude apps gateway who have no spend limit, when the gateway runs this version or later
  • Added admin.pooled_conflict_rule and admin.pooled_priority_order to the Claude apps gateway, to set which pooled group budget pays first for a developer in several groups
  • Added an optional login_notice setting to the Claude apps gateway that shows an operator-defined message on the gateway's browser verification page and on Claude Code's sign-in screen
  • Added CLAUDE_GATEWAY_LOG_FORMAT=json to the Claude apps gateway: operational log lines become JSON with severity, time and message, for log collectors that read the level from a field
  • Added a Claude apps gateway boot warning for a case where another policy's availableModels also allows a custom model id that one policy lists by name
  • Added start-up warnings to the Claude apps gateway for policies with no desktopHome that rely on coworkTabEnabled: false or chatSessionRetentionDays, ahead of Claude Desktop's November 10 change

  • Fixed a case where auto mode was wrongly refused when a client sent a model change and a request for auto mode back to back
  • Fixed /status showing "Auto mode server: Enabled" when the server-side review isn't reaching the session, for example behind an LLM gateway that drops it
  • Fixed Claude-drafted feedback, surveys and /feedback continuing to appear after the server refused feedback for your organization
