claude-code v2.1.260

código-claude v2.1.260

¿Qué ha cambiado?

  • Se agregó un panel de diferencias que se abre junto a la conversación en modo de pantalla completa y muestra los cambios no confirmados a medida que Claude edita; alternarlo con /diff
  • Se agregó una causa probable para errores en el caché de mensajes (por ejemplo, definiciones de herramientas o mensajes del sistema cambiados, inactivo después del TTL) a /cost y al campo prompt_cache de la línea de estado.
  • Se agregó /reload-plugins a las sesiones sin cabeza, para que aparezca en las listas de comandos de Claude Code Desktop y SDK.
  • Se agregó una forma de texto de /advisor (/advisor, /advisor <model>, /advisor off) para la aplicación de escritorio, Control remoto y otras sesiones sin cabeza (-p/Agent SDK).
  • Se agregó oidc.scope_on_refresh a la puerta de enlace de aplicaciones de Claude para IdP que devuelven un id_token al actualizar solo cuando se solicita openid nuevamente.
  • Se agregó compatibilidad con la puerta de enlace de aplicaciones de Claude para las nuevas claves de Claude Desktop en los bloques de políticas desktop, incluidos userPluginMarketplacesEnabled y userPluginUploadsEnabled.
  • Se corrigieron las reglas de permisos Edit/Write/Read cuya ruta contiene paréntesis que el sandbox de Bash descartaba como no válidas o las ignoraba, lo que dejaba carpetas de "solo lectura" en las que se podía escribir.
  • Se corrigió una regla de permiso de archivo con un patrón no compilable (por ejemplo, un [ no cerrado) que hacía que cada edición de archivo fallara con Invalid regular expression; tal regla de denegación ahora guarda el camino literal que deletrea
  • Se corrigió el permiso de Bash que verifica los comandos zsh de aprobación automática que ocultan una sustitución de comando en una asignación REPORTTIME, REPORTMEMORY o DIRSTACKSIZE; estos ahora solicitan aprobación
  • Se corrigió el error de descubrimiento del modelo Bedrock, recuento de tokens y llamadas de credenciales de AWS SSO/STS con "no se puede obtener el certificado del emisor local" cuando la CA raíz corporativa solo está en el almacén de certificados del sistema operativo.
  • Se corrigió permissions.blockReadsOutsideWorkingDirectories en macOS que ocultaba la configuración de git del usuario desde git sandbox y ocultaba el pago propio de un subagente aislado en el árbol de trabajo.
  • Se corrigió la configuración administrada que no se cargaba para los usuarios de claude.ai Enterprise/Team que también tenían una clave API sobrante de un /login anterior.
  • Se corrigió que /status enumerara una cuenta de claude.ai iniciada y una clave API configurada como si ambas estuvieran vigentes; la credencial no en uso ahora está marcada
  • Se corrigieron las entradas administradas skillOverrides ingresadas en el alias de una habilidad incluida (por ejemplo, checkup para /doctor) que no se aplicaban y Skill(name) denegaba reglas que no cubrían una habilidad anidada listada como <dir>:name.
  • Se corrigió que los agentes model: fable ignoraran la etiqueta [1m] en un pin ANTHROPIC_DEFAULT_FABLE_MODEL y se ejecutaran silenciosamente con una ventana de contexto de 200K.
  • Se corrigió que el selector /model no mostrara Fable 5.1 para las organizaciones que pueden usarlo, lo cual solo se aceptaba cuando se escribía como /model claude-fable-5-1.
  • Se corrigió el almacenamiento en caché de mensajes en Claude Fable 5.1 que no cubría el contexto adjunto después de los resultados de la herramienta, por lo que se reenviaba como entrada sin caché en cada turno de llamada de herramienta.
  • Se corrigió que el cambio de modelo permaneciera bloqueado por el resto de la sesión después de una falla en la carga del enlace del complemento; Cada interruptor ahora se vuelve a verificar y el rechazo nombra la causa.
  • Se corrigió el bloqueo del cambio de modelo para la sesión cuando no se podía cargar el mercado de un complemento administrado por la organización.
  • Se corrigieron los servidores MCP proporcionados por SDK (por ejemplo, conectores de escritorio) que a veces faltaban en el primer turno y solo aparecían en el siguiente.
  • Se corrigió que las herramientas de Claude en Chrome fallaran con "No conectado" a mitad de la tarea en sesiones de claude.ai alojadas en la nube cuando se agregaba o eliminaba un conector.
  • Se corrigieron banderas, emoji unidos y letras acentuadas que se dividían en líneas ajustadas, y texto obsoleto que permanecía en la pantalla cuando una bandera o un emoji unido caía en las dos últimas columnas del terminal (ahora se muestra como …).
  • Se corrigió el control remoto que aceptaba una selección de modelo que no era un nombre de modelo válido; ahora se rechaza con un error en lugar de fallar en el siguiente mensaje
  • Se corrigió el éxito de los informes de /rewind y --rewind-files cuando faltaban archivos de copia de seguridad del punto de control y no se restauraba nada.
  • Se corrigió que /rewind dejara el seguimiento de lectura de archivos obsoleto en los giros rebobinados, lo que provocaba resguardos de "Archivo sin cambios desde la última lectura" y reinyección de archivos completos después de ediciones externas.
  • Se corrigió que -p --resume/--continue (como lo usa la aplicación de escritorio) fallara en cada reintento una vez que el directorio del árbol de trabajo de una sesión perdía sus metadatos de git; ahora falla una vez y luego se reanuda sin el árbol de trabajo
  • Se corrigió un subagente que reanudó a otro agente a través de SendMessage y nunca fue despertado por la finalización de ese agente (en su lugar, la notificación fue a la conversación principal)
  • Equipos de agentes fijos: la transcripción de un compañero de equipo en proceso perdía mensajes o se quedaba en blanco durante largas esperas de reintento API (por ejemplo, bajo CLAUDE_CODE_RETRY_WATCHDOG), ya que los avisos de reintento expulsaban mensajes reales.
  • Se corrigió una sesión que se movía al fondo y aparecía dos veces en ListAgents (una vez como un gemelo "interactivo" fantasma con el mismo nombre) y recibía entregas de SendMessage en el visor.
  • Se corrigieron errores intermitentes de "intercambio de salida de tarea rechazado" cuando muchas sesiones comparten un directorio de proyecto
  • Se corrigió Ctrl+Z en pantalla completa dejando el shell en la pantalla alternativa, dibujado sobre la interfaz pausada.
  • Se corrigió que los subagentes de la herramienta de flujo de trabajo se reiniciaran porque estaban bloqueados mientras aún estaba en progreso una compactación de contexto larga.
  • Se corrigieron los complementos de un mercado de URL que no se instalaban con "la ruta de entrada al mercado no permanece dentro del directorio del mercado" cuando una aplicación anfitriona (por ejemplo, Claude Desktop) lo almacena como un directorio.
  • Se corrigió una pestaña adicional del navegador que se abre cuando se publica un artefacto en una sesión que estás conduciendo desde claude.ai, la aplicación de escritorio o móvil (Control remoto)
  • Se corrigió el error de validación de "Parámetros de herramienta no válidos" en la primera llamada de la herramienta Artefacto en algunas sesiones de Cowork.
  • Se corrigió que las selecciones de líneas IDE se eliminaran al ejecutar un comando de habilidad o barra (el contexto "N líneas seleccionadas" ahora llega a Claude)
  • Se corrigió la detección de repositorio para proyectos GitLab en subgrupos anidados (por ejemplo, gitlab.com/group/subgroup/project)
  • Se corrigieron las referencias de problemas de owner/repo#123 en la salida renderizada que vincula a github.com cuando se trabaja en un repositorio de GitLab; ahora enlazan al problema gitlab.com
  • Glob/Grep: se corrigió la ruta de búsqueda que se estaba investigando en el disco antes de la verificación de permisos; ahora se informa que falta una ruta después de que se decide el permiso, como lo hace Read
  • Se revirtió el cambio 2.1.259 aplicando reglas de denegación Read() a los argumentos de Bash; negó npm run build bajo una regla Read(./**/build/**) en todos los modos e hizo que cd … && grep avisara incluso en modo automático
  • Salida estructurada mejorada: el flujo de trabajo agent({schema}) rechaza un esquema JSON que nunca se puede satisfacer desde el principio, y los errores de reintento-cap ahora incluyen el último error de validación.
  • Se mejoró la eliminación de una sesión en segundo plano cuyo árbol de trabajo tiene confirmaciones no enviadas: el mensaje ahora nombra la rama y el recuento de confirmaciones, y al eliminar nuevamente se descarta el árbol de trabajo.
  • Se mejoró el registro de fallas de actualización de la puerta de enlace de aplicaciones de Claude para nombrar el paso que falló.
  • Uso de CPU inactivo mejorado en sesiones no interactivas (-p / SDK)
  • Se mejoró la puerta de enlace de aplicaciones de Claude en Amazon Bedrock: los tokens de entrada para una solicitud cancelada ahora se cuentan con los CountTokens API gratuitos de AWS (otorgar bedrock:CountTokens) en lugar de una solicitud de un solo token.
  • Se mejoró el error de configuración para reglas como Edit(C:\dir\(name)\**), donde \( se lee como un paréntesis de escape en lugar de un separador de ruta, para sugerir una ortografía inequívoca.
  • Autocompactación mejorada para modelos de contexto de 1 millón: las sesiones de Opus y Fable ahora se compactan poco antes del límite de token de 1 millón, y la compactación de recuperación en contextos muy grandes ya no caduca a los 10 minutos.
  • Se mejoraron /ultrareview y claude ultrareview para esperar hasta 45 minutos (antes 30) para revisiones en la nube de larga duración.
  • /effort mejorado en Claude Fable 5.1, por lo que cambiar el esfuerzo a mitad de sesión ya no invalida el caché de mensajes
  • Se actualizó la habilidad claude-api incluida para que sus ejemplos de Go, Java y C# utilicen ID de modelo de la generación actual y se aclaró que los modelos de trabajador o subagente más baratos también deberían ser de la generación actual.
  • Se modificó ctrl+l / cmd+k en modo de pantalla completa para borrar la vista de transcripción como una terminal clear; Desplázate hacia arriba para ver mensajes anteriores.
  • Se cambiaron las reglas de permiso con texto después del paréntesis de cierre (por ejemplo, Bash(ls) x), que nunca coincidieron con nada, para que se informen como configuraciones no válidas en lugar de ignorarse silenciosamente.
  • Se modificó la configuración administrada por el servidor para que un CLAUDE.md administrado (claudeMd) ya no active el cuadro de diálogo de aprobación de seguridad; Los ganchos, el comando de shell, la zona de pruebas y las configuraciones inseguras de env aún requieren aprobación
  • Se modificó Claude en Chrome para que siga la configuración de administrador de Claude en Chrome de su organización; cuando un administrador lo desactiva, --chrome, /chrome y las herramientas del navegador no están disponibles
  • Se modificó la puerta de enlace de aplicaciones de Claude para enviar orgPluginSettings en el formulario de lista leído por Claude Desktop 1.15200.0 y versiones posteriores; los escritorios más antiguos lo ignoran
  • Se modificó la puerta de enlace de aplicaciones de Claude para que también se niegue a iniciar, nombrando el campo, cuando una política desktop escribe mal un campo en un objeto anidado de una entrada managedMcpServers o orgPluginSettings.
  • Se cambiaron los comandos escritos en el indicador del modo bash ! para que se ejecuten fuera del entorno limitado incluso cuando el modo estricto (sandbox.allowUnsandboxedCommands: false) está activado, como escribir en su propia terminal.
  • Se modificó el ejecutor autohospedado --kill-session-after-min para liberar una sesión que solo espera a su usuario (pausada, reanudable en el siguiente mensaje) en lugar de finalizarla e informar una falla.
  • Se eliminó el límite de tiempo de una hora para los comandos en segundo plano iniciados por los subagentes; ahora se ejecutan hasta que salen o se detienen, coincidiendo con la sesión principal
  • [VSCode] Se agregó el nivel de esfuerzo seleccionado a la píldora del modelo de pie de página, se corrigió un nivel de esfuerzo obsoleto después de cambiar de modelo y se devolvieron las píldoras de pie de página a su tamaño compacto anterior.
  • [VSCode] Se agregó Abierto y Cerrado al menú de filtro de estado de la lista de sesiones
  • [VSCode] Se corrigió que la pantalla de bienvenida desapareciera en una nueva sesión cuando el control remoto se enciende automáticamente
  • [VSCode] Se corrigió que el selector del historial de sesiones cargara una sesión por segunda vez cuando ya estaba abierta en otra pestaña; ahora cambia a esa pestaña
  • [VSCode] Se corrigió el comando Cambiar nombre de la pestaña de la sesión sin hacer nada mientras se recargaba la vista de la pestaña; ahora siempre se aplica
  • [VSCode] Se corrigió un mensaje a medio terminar, una tarjeta de herramientas vacía o una línea adicional de "Pensamiento" que permanecía en la pantalla después de que Claude Code volviera a intentar una respuesta descartada.
  • [VSCode] Se corrigió que "Habilitar control remoto para todas las sesiones" no se aplicaba a una pestaña de sesión que aún se estaba iniciando cuando se activó el interruptor.

claude-code v2.1.260

What's changed

  • Added a diff panel that opens beside the conversation in fullscreen mode and shows your uncommitted changes as Claude edits; toggle it with /diff
  • Added a likely cause for prompt-cache misses (e.g. tool definitions or system prompt changed, idle past the TTL) to /cost and the status line's prompt_cache field
  • Added /reload-plugins to headless sessions, so it appears in the Claude Code Desktop and SDK command lists
  • Added a text form of /advisor (/advisor, /advisor <model>, /advisor off) for the desktop app, Remote Control, and other headless (-p/Agent SDK) sessions
  • Added oidc.scope_on_refresh to the Claude apps gateway for IdPs that return an id_token on refresh only when asked for openid again
  • Added Claude apps gateway support for newer Claude Desktop keys in desktop policy blocks, including userPluginMarketplacesEnabled and userPluginUploadsEnabled
  • Fixed Edit/Write/Read permission rules whose path contains parentheses being dropped as invalid or ignored by the Bash sandbox, which left "read-only" folders writable
  • Fixed one file permission rule with an uncompilable pattern (e.g. an unclosed [) making every file edit fail with Invalid regular expression; such a deny rule now guards the literal path it spells
  • Fixed Bash permission checks auto-approving zsh commands that hide a command substitution in a REPORTTIME, REPORTMEMORY or DIRSTACKSIZE assignment; these now prompt for approval
  • Fixed Bedrock model discovery, token counting and AWS SSO/STS credential calls failing with "unable to get local issuer certificate" when the corporate root CA is only in the OS certificate store
  • Fixed permissions.blockReadsOutsideWorkingDirectories on macOS hiding the user's git config from sandboxed git and hiding a worktree-isolated sub-agent's own checkout
  • Fixed managed settings not loading for claude.ai Enterprise/Team users who also had a leftover API key from an earlier /login
  • Fixed /status listing a signed-in claude.ai account and a configured API key as if both were in effect; the credential not in use is now marked
  • Fixed managed skillOverrides entries keyed on a bundled skill's alias (e.g. checkup for /doctor) not applying, and Skill(name) deny rules not covering a nested skill listed as <dir>:name
  • Fixed model: fable agents ignoring the [1m] tag on an ANTHROPIC_DEFAULT_FABLE_MODEL pin and silently running with a 200K context window
  • Fixed the /model picker not showing Fable 5.1 for organizations that can use it, which was only accepted when typed as /model claude-fable-5-1
  • Fixed prompt caching on Claude Fable 5.1 not covering the context attached after tool results, so it was re-sent as uncached input on every tool-call turn
  • Fixed model switching staying blocked for the rest of the session after a plugin hook load failure; each switch now re-checks and the refusal names the cause
  • Fixed model switching being blocked for the session when an organization-managed plugin's marketplace could not be loaded
  • Fixed SDK-provided MCP servers (e.g. Desktop connectors) sometimes missing from the first turn and only appearing on the next one
  • Fixed Claude in Chrome tools failing with "Not connected" mid-task in cloud-hosted claude.ai sessions when a connector was added or removed
  • Fixed flags, joined emoji and accented letters splitting across wrapped lines, and stale text staying on screen when a flag or joined emoji falls in the terminal's last two columns (now shown as …)
  • Fixed Remote Control accepting a model pick that is not a valid model name; it is now refused with an error instead of failing on the next message
  • Fixed /rewind and --rewind-files reporting success when checkpoint backup files were missing and nothing was actually restored
  • Fixed /rewind leaving stale file-read tracking from the rewound-away turns, which caused "File unchanged since last read" stubs and full-file re-injection after external edits
  • Fixed -p --resume/--continue (as used by the desktop app) failing on every retry once a session's worktree directory lost its git metadata; it now fails once, then resumes without the worktree
  • Fixed a subagent that resumed another agent via SendMessage never being woken by that agent's completion (the notification went to the main conversation instead)
  • Fixed agent teams: an in-process teammate's transcript losing messages, or going blank, during long API retry waits (e.g. under CLAUDE_CODE_RETRY_WATCHDOG) as retry notices evicted real messages
  • Fixed a session that moved to the background appearing twice in ListAgents (once as a phantom "interactive" twin with the same name) and receiving SendMessage deliveries in the viewer
  • Fixed intermittent "task output swap refused" errors when many sessions share a project directory
  • Fixed Ctrl+Z in fullscreen leaving the shell on the alternate screen, drawn over the paused interface
  • Fixed Workflow tool subagents being restarted as stalled while a long context compaction was still in progress
  • Fixed plugins from a URL marketplace failing to install with "marketplace entry path does not stay inside the marketplace directory" when a host app (e.g. Claude Desktop) stores it as a directory
  • Fixed an extra browser tab opening when an artifact is published in a session you're driving from claude.ai, the desktop app, or mobile (Remote Control)
  • Fixed the Artifact tool's first call failing with an "Invalid tool parameters" validation error in some Cowork sessions
  • Fixed IDE line selections being dropped when running a skill or slash command (the "N lines selected" context now reaches Claude)
  • Fixed repository detection for GitLab projects in nested subgroups (e.g. gitlab.com/group/subgroup/project)
  • Fixed owner/repo#123 issue references in rendered output linking to github.com when working in a GitLab repository; they now link to the gitlab.com issue
  • Glob/Grep: Fixed the search path being probed on disk before the permission check; a missing path is now reported after permission is decided, as Read does
  • Reverted the 2.1.259 change applying Read() deny rules to Bash arguments; it denied npm run build under a Read(./**/build/**) rule in every mode and made cd … && grep prompt even in auto mode
  • Improved structured output: Workflow agent({schema}) rejects a JSON Schema that can never be satisfied up front, and retry-cap errors now include the last validation failure
  • Improved deleting a background session whose worktree has unpushed commits: the message now names the branch and commit count, and deleting again discards the worktree
  • Improved the Claude apps gateway's refresh-failure log to name the step that failed
  • Improved idle CPU usage of non-interactive (-p / SDK) sessions
  • Improved the Claude apps gateway on Amazon Bedrock: input tokens for an aborted request are now counted with AWS's free CountTokens API (grant bedrock:CountTokens) instead of a one-token request
  • Improved the settings error for rules such as Edit(C:\dir\(name)\**), where \( is read as an escaped parenthesis rather than a path separator, to suggest an unambiguous spelling
  • Improved auto-compact for 1M-context models: Opus and Fable sessions now compact shortly before the 1M-token limit, and recovery compaction on very large contexts no longer times out at 10 minutes
  • Improved /ultrareview and claude ultrareview to wait up to 45 minutes (previously 30) for long-running cloud reviews
  • Improved /effort on Claude Fable 5.1 so changing effort mid-session no longer invalidates the prompt cache
  • Updated the bundled claude-api skill so its Go, Java, and C# samples use current-generation model IDs, and clarified that cheaper worker or sub-agent models should be current-generation too
  • Changed ctrl+l / cmd+k in fullscreen mode to clear the transcript view like a terminal clear; scroll up to see earlier messages
  • Changed permission rules with text after the closing parenthesis (e.g. Bash(ls) x), which never matched anything, to be reported as invalid settings instead of being silently ignored
  • Changed server-managed settings so a managed CLAUDE.md (claudeMd) no longer triggers the security approval dialog; hooks, shell-command, sandbox, and unsafe env settings still require approval
  • Changed Claude in Chrome to follow your organization's Claude in Chrome admin setting; when an admin turns it off, --chrome, /chrome and the browser tools are unavailable
  • Changed Claude apps gateway to send orgPluginSettings in the list form read by Claude Desktop 1.15200.0 and later; older desktops ignore it
  • Changed Claude apps gateway to also refuse to start, naming the field, when a desktop policy misspells a field in a nested object of a managedMcpServers or orgPluginSettings entry
  • Changed commands typed at the ! bash-mode prompt to run outside the sandbox even when strict sandbox mode (sandbox.allowUnsandboxedCommands: false) is on, like typing into your own terminal
  • Changed self-hosted runner --kill-session-after-min to release a session that is only waiting on its user (paused, resumable on the next message) instead of killing it and reporting a failure
  • Removed the one-hour time limit on background commands started by subagents; they now run until they exit or are stopped, matching the main session
  • [VSCode] Added the selected effort level to the footer model pill, fixed a stale effort level after switching models, and returned the footer pills to their earlier compact size
  • [VSCode] Added Open and Closed to the session list's status filter menu
  • [VSCode] Fixed the welcome screen disappearing in a new session when Remote Control turns on automatically
  • [VSCode] Fixed the session history picker loading a session a second time when it is already open in another tab; it now switches to that tab
  • [VSCode] Fixed the session tab's Rename command silently doing nothing while the tab's view was reloading; it now always applies
  • [VSCode] Fixed a half-finished message, an empty tool card or an extra "Thought for" line staying on screen after Claude Code retried a dropped response
  • [VSCode] Fixed "Enable Remote Control for all sessions" not applying to a session tab that was still starting when the toggle was flipped
