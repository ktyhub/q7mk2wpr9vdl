código-claude v2.1.229

¿Qué ha cambiado?

  • claude remote-control --continue documentado para reanudar la sesión de control remoto más reciente
  • Se agregó compatibilidad con el enlace Claude Code proporcionado por el servidor para sesiones de ejecución autohospedadas, que coincide con el comportamiento del entorno administrado.
  • Se agregaron pings de mantenimiento de actividad de SSE a las respuestas de transmisión de la puerta de enlace durante pausas prolongadas para pensar, lo que evita desconexiones por tiempo de inactividad en las aguas arriba de Vertex y Bedrock.
  • Se agregaron fuentes del mercado de complementos command: un comando local (por ejemplo, un IDE) imprime el directorio del complemento, que se vuelve a resolver en cada sesión y se aplica sin reiniciar; mode: "link" lo usa en su lugar
  • ListAgents ahora marca las sesiones de control remoto desconectadas como offline y etiqueta sus sesiones en la nube como cloud
  • Se corrigieron respuestas largas que desaparecían parcialmente durante la transmisión y se imprimían dos veces en la terminal.
  • Se corrigió un bloqueo en la pantalla de error (incluso en --resume de la sesión afectada) cuando una llamada de herramienta tenía un valor glob, file_path o command que no era una cadena.
  • Se corrigió un bloqueo de RangeError cuando una barra de progreso o una tabla de rebajas se representaba en una ventana de terminal muy estrecha (también podría bloquear claude --continue/--resume al inicio)
  • Se corrigió un bloqueo en Windows cuando una llamada de herramienta o un mensaje hacía referencia a un archivo mediante una ruta de longitud extendida (\\?\) o UNC.
  • Se corrigió el error del modo automático en cada llamada de herramienta para los usuarios que desactivan el encabezado de atribución a través de CLAUDE_CODE_ATTRIBUTION_HEADER (conexiones directas Anthropic API)
  • Se corrigió que /model rechazara Sonnet/Opus 1M para los suscriptores de claude.ai usando una puerta de enlace ANTHROPIC_BASE_URL personalizada.
  • Se corrigió MCP OAuth con servidores de autorización estricta usando 127.0.0.1 en lugar de localhost en el URI de redireccionamiento.
  • Se corrigió el control remoto clients que mostraba una rueda giratoria atascada después de escribir un comando de barra diagonal en la terminal de la computadora portátil.
  • Se corrigió el flujo de trabajo de revisión de código de Claude generado por /install-github-app al completarse sin publicar su revisión en la solicitud de extracción.
  • Se corrigieron bloqueos de la interfaz de usuario de varios segundos después de editar un archivo con miles de diagnósticos IDE mientras la extensión IDE está conectada
  • Se corrigieron los comandos únicos de claude plugin que dejaban un archivo de vida perdido que podría impedir la limpieza de versiones obsoletas de complementos.
  • Se corrigieron flujos de trabajo dinámicos dentro de contenedores con CPU limitada utilizando el recuento de núcleos de la máquina host en lugar del límite de CPU del contenedor.
  • Se corrigió una fuga en el identificador del observador de archivos después de reemplazos de archivos atómicos y un error no detectado en Windows cuando el observador de tareas programadas fallaba en una red o sistema de archivos virtual.
  • Se corrigieron las sesiones SDK y --input-format stream-json que obtenían un error 400 API cuando se enviaba un mensaje de solo espacios en blanco.
  • Se corrigieron las conversaciones cuyos mensajes por sí solos exceden el límite de solicitud de 32 MB del API al volver a intentar la compactación cuando no se pueden eliminar imágenes o documentos; ahora fallan una vez con un mensaje claro
  • Se corrigió que la puerta de enlace administrada por el escritorio rechazara la exportación OpenTelemetry de las sesiones de Claude Desktop cuando esa puerta de enlace también es el punto final de telemetría.
  • Se corrigió que el ejecutor autohospedado y otras sesiones remotas salieran al inicio cuando se implementa managed-mcp.json y el servidor entrega servidores MCP; esos servidores ahora se omiten con una advertencia
  • Se corrigió la preparación del repositorio de ejecución autohospedado que se bloqueaba en un mensaje de Git Credential Manager; git ahora falla rápidamente cuando faltan credenciales
  • Se mejoraron las distribuciones del flujo de trabajo para escalonar a los agentes hermanos con el mismo prefijo, de modo que los agentes posteriores lean el prefijo de aviso almacenado en caché en lugar de volver a pagarlo (CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0 está deshabilitado).
  • Se mejoraron los errores de "el mensaje es demasiado largo" para explicar por qué la compactación automática no se pudo recuperar en lugar de solo sugerir /compact
  • Sandbox mejorado: los literales IPv6 en las listas de dominios de red ahora están entre corchetes ([::1]:443), y las ortografías ambiguas se cierran en caso de error y se marcan con /doctor.
  • Se actualizó /login para repetir la advertencia de anulación de CLAUDE_CODE_OAUTH_TOKEN después de un inicio de sesión exitoso.
  • Se modificó /commit-push-pr para que los comandos git/gh con indicadores peligrosos (--force, --amend, --no-verify, etc.) ya no se aprueben automáticamente.
  • Se modificó el inicio de Windows del ejecutor autohospedado para que requiera un --base-dir explícito; no hay un directorio de pago predeterminado en Windows
  • [VSCode] "Informar un problema" y /bug ahora abren el cuadro de diálogo de comentarios integrado en lugar de un enlace de encuesta retirado
  • [VSCode] Se hizo redimensionable el panel de preguntas secundarias /btw arrastrando su límite, tanto en diseños acoplados como apilados.
  • [VSCode] Se agregaron grupos de sesiones en la barra lateral: derecha-click para crear, cambiar el nombre o eliminar; Cmd/Ctrl- o Shift-click para mover varias sesiones a la vez

claude-code v2.1.229

What's changed

  • Documented claude remote-control --continue for resuming the most recent Remote Control session
  • Added server-supplied Claude Code hook support for self-hosted runner sessions, matching managed-environment behavior
  • Added SSE keepalive pings to gateway streaming responses during long thinking pauses, preventing idle-timeout disconnects on Vertex and Bedrock upstreams
  • Added plugin marketplace command sources: a local command (e.g. an IDE) prints the plugin directory, which is re-resolved each session and applied without a restart; mode: "link" uses it in place
  • ListAgents now marks disconnected Remote Control sessions as offline and labels your cloud sessions as cloud
  • Fixed long responses partly disappearing while streaming and being printed twice in the terminal
  • Fixed a crash to the error screen (including on --resume of the affected session) when a tool call had a non-string glob, file_path, or command value
  • Fixed a RangeError crash when a progress bar or markdown table rendered in a very narrow terminal window (could also crash claude --continue/--resume at startup)
  • Fixed a crash on Windows when a tool call or message referenced a file by an extended-length (\\?\) or UNC path
  • Fixed auto mode failing on every tool call for users who disable the attribution header via CLAUDE_CODE_ATTRIBUTION_HEADER (direct Anthropic API connections)
  • Fixed /model rejecting Sonnet/Opus 1M for claude.ai subscribers using a custom ANTHROPIC_BASE_URL gateway
  • Fixed MCP OAuth with strict authorization servers by using 127.0.0.1 instead of localhost in the redirect URI
  • Fixed Remote Control clients showing a stuck working spinner after a slash command typed in the laptop terminal
  • Fixed the Claude Code Review workflow generated by /install-github-app completing without posting its review on the pull request
  • Fixed multi-second UI stalls after editing a file with thousands of IDE diagnostics while the IDE extension is connected
  • Fixed one-shot claude plugin commands leaving a stray liveness file that could prevent cleanup of outdated plugin versions
  • Fixed dynamic workflows inside CPU-limited containers using the host machine's core count instead of the container's CPU limit
  • Fixed a file-watcher handle leak after atomic file replacements, and an uncaught error on Windows when the scheduled-tasks watcher failed on a network or virtual filesystem
  • Fixed SDK and --input-format stream-json sessions getting a 400 API error when a whitespace-only message was submitted
  • Fixed conversations whose messages alone exceed the API's 32 MB request limit retrying compaction when no images or documents can be stripped; they now fail once with a clear message
  • Fixed OpenTelemetry export from Claude Desktop sessions being rejected by the Desktop-managed gateway when that gateway is also the telemetry endpoint
  • Fixed self-hosted runner and other remote sessions exiting at startup when managed-mcp.json is deployed and the server delivers MCP servers; those servers are now skipped with a warning
  • Fixed self-hosted runner repository preparation hanging on a Git Credential Manager prompt; git now fails fast when credentials are missing
  • Improved workflow fan-outs to stagger same-prefix sibling agents so subsequent agents read the cached prompt prefix instead of re-paying it (CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0 disables)
  • Improved "prompt is too long" errors to explain why automatic compaction could not recover instead of only suggesting /compact
  • Improved sandbox: IPv6 literals in network domain lists are now bracketed ([::1]:443), and ambiguous spellings are enforced fail-closed and flagged by /doctor
  • Updated /login to repeat the CLAUDE_CODE_OAUTH_TOKEN override warning after a successful login
  • Changed /commit-push-pr so git/gh commands with dangerous flags (--force, --amend, --no-verify, etc.) are no longer auto-approved
  • Changed self-hosted runner Windows startup to require an explicit --base-dir; there is no default checkout directory on Windows
  • [VSCode] "Report a problem" and /bug now open the built-in feedback dialog instead of a retired survey link
  • [VSCode] Made the /btw side-question panel resizable by dragging its boundary, in both side-docked and stacked layouts
  • [VSCode] Added session groups in the sidebar — right-click to create, rename, or delete; Cmd/Ctrl- or Shift-click to move several sessions at once
