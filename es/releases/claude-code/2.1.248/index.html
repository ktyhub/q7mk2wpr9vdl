código-claude v2.1.248

¿Qué ha cambiado?

  • Se agregó --restricted (o CLAUDE_CODE_RESTRICTED=1): elimina las herramientas integradas que ejecutan comandos o código y WebFetch (a menos que se nombren en --tools), mantiene las herramientas de archivos dentro del directorio de trabajo, rechaza bypassPermissions e ignora los archivos de configuración local, de proyecto y de usuario.
  • Se agregó experimental.cacheTtl ("5m" o "1h") al frontmatter del agente: un TTL de caché de solicitud por agente que se usa cuando no se configura ninguna configuración de TTL de subagente
  • Se agregó claude self-hosted-runner --client-label <label> (o SELF_HOSTED_RUNNER_CLIENT_LABEL) para anular la etiqueta con la que se registra el corredor (predeterminado: nombre de host)
  • Se agregaron diagnósticos de configuración administrados por el servidor: una advertencia de inicio cuando la configuración no se carga y una línea /doctor y /status que explica una falla de carga o por qué no se recuperaron (Bedrock/Vertex/proveedor externo, ANTHROPIC_BASE_URL personalizado)
  • Se agregó una advertencia en /web-setup cuando el token GitHub CLI carece del alcance workflow, ya que los envíos a repositorios muy grandes pueden rechazarse sin él.
  • Se agregó /usage-credits para organizaciones empresariales facturadas a través de AWS Marketplace, empresas de autoservicio y pruebas empresariales, para que los miembros puedan solicitar un límite de uso más alto a su administrador.
  • Se agregaron mensajes entre sesiones (SendMessage / ListAgents) entre sesiones en la misma máquina en Bedrock, Vertex y Foundry, y cuando la telemetría está deshabilitada.
  • Se corrigió un error en el mensaje de caché (y se perdió el contexto de pensamiento extendido) aproximadamente una vez por hora en sesiones largas, causado por definiciones de herramientas que se volvían a representar después de una actualización del token de OAuth.
  • Se corrigió la definición de la herramienta ScheduleWakeup que cambiaba entre una sesión y su --resume cuando la cuenta había ingresado en exceso de uso, causando una pérdida total de caché en el primer turno de la sesión reanudada.
  • Se corrigió que las sesiones de Claude Desktop y Cowork desaparecieran después de 30 días: la limpieza de transcripciones ahora mantiene las sesiones escritas en el escritorio mientras están en la aplicación (a menos que la política de la organización administre la retención); la nueva configuración desktopSessionCleanupPeriodDays limita la exención
  • Se corrigió el envío a la pantalla de inicio de sesión cuando otro proceso de Claude Code mantenía el bloqueo de actualización del token mientras el token de sesión había expirado; la solicitud ahora falla con un error reintentable
  • Windows: Se corrigió que la lista claude agents no respondiera al teclado después de desconectarse de una sesión, o cuando se iniciaba en una pestaña de terminal dejada en modo de entrada win32.
  • Se corrigió el error de inicio de sesión de consola recomendado en /login con un error de OAuth antes de mostrar una URL de inicio de sesión en máquinas donde no se puede usar (por ejemplo, cuando se configura ANTHROPIC_API_KEY o una clave auxiliar API); ahora vuelve al inicio de sesión con la clave API
  • Se corrigieron los nombres de los modelos en /model y los avisos de cambio de modo rápido para representar como código, por lo que los sufijos como [1m] se muestran literalmente en lugar de como un enlace.
  • Se corrigió que claude agents omitiera el indicador del espacio de trabajo trust cuando se configuraba la variable de entorno CI.
  • Se corrigió el fallo de claude agents al iniciarse cuando la caché de estado de PR contenía una entrada con formato incorrecto.
  • Se corrigió la vista del agente que resucitaba una sesión en segundo plano de una semana de antigüedad después de que la máquina estaba apagada: dicha sesión ahora se muestra como detenida en su final real y al abrirla se pregunta antes de reanudar la conversación guardada.
  • Se corrigió la vista del agente que a veces abría una conversación anterior y descartaba el mensaje escrito al iniciar una nueva sesión.
  • Corregido claude agents: abrir una sesión detenida que ya reanudaste en otro terminal ya no inicia un segundo proceso en esa conversación; la fila ahora dice que está abierta en una terminal
  • Se corrigió que claude agents y claude rm se negaran a eliminar una sesión ("tiene confirmaciones que no se envían a ninguna parte") cuando la rama de su árbol de trabajo ya estaba fusionada con su rama predeterminada desprotegida (por ejemplo, main local) pero aún no se había enviado.
  • Se corrigieron las sesiones en segundo plano que esperaban silenciosamente cuando un gancho PermissionRequest o PreToolUse imprime una respuesta no válida: la fila claude agents ahora nombra el gancho y el error de esquema.
  • Se corrigieron los ganchos que trataban silenciosamente un objeto estándar {…} que no es válido JSON como texto sin formato; ahora se informa como un error de enlace con el mensaje de análisis
  • Se corrigió /mcp que enumera una entrada de proyecto .mcp.json que declara el tipo de conector claude.ai bajo el encabezado trusted "claude.ai"; ahora aparece bajo su alcance real
  • Se corrigieron los servidores MCP cuyo headersHelper proporciona el encabezado Authorization y caían en el descubrimiento de OAuth en un 401 en lugar de volver a ejecutar el asistente y volver a intentar la llamada como se documenta.
  • Se corrigió /login en una puerta de enlace de aplicaciones de Claude que se bloqueaba cuando se requería el cuadro de diálogo de aprobación de seguridad de configuración administrada.
  • Se corrigió el descubrimiento del modelo de puerta de enlace (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) que nunca se ejecutaba cuando apiKeyHelper era la única credencial.
  • Se corrigió que claude logs dejara el seguimiento del mouse, el pegado entre corchetes y la pantalla alternativa encendida en la terminal desde la que se ejecutaba.
  • Se corrigió la lista de reglas de permisos de repositorio del cuadro de diálogo trust que mostraba un carácter confuso cuando una regla larga se cortaba en medio de un emoji.
  • Se corrigió el indicador de modo de permiso que permanecía oculto detrás de la sugerencia "Presione Ctrl-C nuevamente para salir" cuando presiona Mayús+Tab justo después de Ctrl+C.
  • Se corrigieron /ultrareview y sesiones en la nube con inicialización local que cargaban ediciones no confirmadas en archivos de estilo prod.env y *.tfvars, o en copias de intercambio, temporales y de respaldo del editor de archivos de credenciales (por ejemplo, key.pem.tmp, id_rsa.swo); ahora permanecen en su máquina
  • Se corrigieron sesiones de control remoto que ocasionalmente nunca mostraban una solicitud de permiso o los últimos mensajes en el dispositivo conectado después de que el CLI se reconectara silenciosamente.
  • Se corrigieron sesiones en la nube que ocasionalmente fallaban al inicio cuando las credenciales de sesión del contenedor aún no eran legibles.
  • Se corrigió que claude remote-control rechazara sus propios indicadores (por ejemplo, --spawn, --name) cuando un indicador global o una opción inyectada envoltorio precede al subcomando.
  • Se corrigieron las advertencias de inicio (por ejemplo, "N servidores MCP necesitan autenticación") que muestran una columna a la derecha del resto de la transcripción.
  • Se corrigió una sesión del árbol de trabajo en segundo plano que perdía su desprotección: la sesión en segundo plano ahora mantiene el bloqueo del árbol de trabajo mientras se ejecuta, por lo que la limpieza y git worktree remove lo dejan en paz.
  • Se corrigieron @-menciones de otras sesiones que no coincidían con nombres escritos con caracteres no latinos (por ejemplo, coreano ingresado a través de un IME)
  • Se corrigió un valor crossSessionInbound no válido que se ignoraba silenciosamente: ahora advierte y retiene mensajes entre sesiones (configuraciones de usuario) o los rechaza (configuraciones administradas) hasta que se solucione
  • Se corrigieron mensajes de límite de velocidad, uso y modo rápido que le indican que ejecute /usage-credits cuando ese comando no esté disponible para su organización (por ejemplo, oculto con DISABLE_EXTRA_USAGE_COMMAND).
  • [VSCode] Se corrigió una pestaña de chat que se atascaba en "No se encontró ninguna conversación" cuando su sesión nunca se guardaba; ahora comienza una nueva conversación
  • Se mejoró la huella de aviso de la herramienta Flujo de trabajo: su descripción ahora es de aproximadamente 1k tokens en lugar de 5.7k, con la referencia de escritura de guiones movida a una habilidad workflow-authoring incluida.
  • Se mejoró la insignia PR del pie de página para verificar GitHub con menos frecuencia mientras la solicitud de extracción no se modifica; una pulsación o un comando gh pr aún lo actualiza de inmediato
  • Configuración administrada mejorada: client-side timeout, MCP startup-mode y stream-watchdog env vars ya no activan el mensaje de aprobación de configuración
  • /ultrareview <PR#> mejorado para verificar antes del lanzamiento que la cuenta GitHub conectada a su cuenta Claude pueda acceder al repositorio y explicar cómo solucionarlo, en lugar de fallar después de que comience la sesión en la nube.
  • Mensajería entre sesiones mejorada: recurre a un directorio privado por usuario /tmp cuando no se puede usar el predeterminado, y el aviso y /status nombran el directorio para arreglar
  • Se cambió Mayús+entrar en la entrada de despacho de la vista del agente para insertar una nueva línea (que coincide con el mensaje); Ctrl+Intro ahora envía y adjunta
  • Se modificó /loop: el modo dinámico a su propio ritmo y el valor predeterminado autónomo sin aviso ahora siempre están disponibles, incluso en Bedrock/Vertex/Foundry
  • Se cambiaron las fallas de exportación de telemetría antrópica para que se registren en el nivel de depuración como [Anthropic telemetry] en lugar de [3P telemetry] OTEL diag error, para que no se confundan con fallas del recopilador de OTel.
  • Se modificó la mensajería entre sesiones en los espacios de nombres de usuario de Linux: trust equivalente a raíz para propietarios no asignados está limitado a directorios canónicos del sistema.
  • Se cambió SendMessage de un subagente a otra sesión: el resultado ahora indica que cualquier respuesta se entrega a la conversación de la sesión principal, no al subagente

claude-code v2.1.248

What's changed

  • Added --restricted (or CLAUDE_CODE_RESTRICTED=1): removes the built-in tools that run commands or code and WebFetch (unless named in --tools), keeps file tools inside the working directory, refuses bypassPermissions, and ignores user, project and local settings files
  • Added experimental.cacheTtl ("5m" or "1h") to agent frontmatter: a per-agent prompt cache TTL used when no subagent TTL setting is configured
  • Added claude self-hosted-runner --client-label <label> (or SELF_HOSTED_RUNNER_CLIENT_LABEL) to override the label the runner registers with (default: hostname)
  • Added server-managed settings diagnostics: a startup warning when the settings fail to load, and a /doctor and /status line explaining a load failure or why they weren't fetched (Bedrock/Vertex/third-party provider, custom ANTHROPIC_BASE_URL)
  • Added a warning in /web-setup when the GitHub CLI token lacks the workflow scope, since pushes to very large repositories can be rejected without it
  • Added /usage-credits for Enterprise organizations billed through AWS Marketplace, self-serve Enterprise, and Enterprise trials, so members can request a higher usage limit from their admin
  • Added cross-session messaging (SendMessage / ListAgents) between sessions on the same machine on Bedrock, Vertex, and Foundry, and when telemetry is disabled
  • Fixed a prompt-cache miss (and lost extended-thinking context) roughly once an hour in long sessions, caused by tool definitions being re-rendered after an OAuth token refresh
  • Fixed the ScheduleWakeup tool definition changing between a session and its --resume when the account had entered usage overage, causing a full prompt-cache miss on the resumed session's first turn
  • Fixed Claude Desktop and Cowork sessions disappearing after 30 days: the transcript cleanup now keeps desktop-written sessions while they are in the app (unless org policy manages retention); the new desktopSessionCleanupPeriodDays setting caps the exemption
  • Fixed being sent to the login screen when another Claude Code process held the token refresh lock while the session token had expired; the request now fails with a retryable error instead
  • Windows: Fixed the claude agents list not responding to the keyboard after detaching from a session, or when launched in a terminal tab left in win32-input-mode
  • Fixed the recommended Console sign-in in /login failing with an OAuth error before showing a sign-in URL on machines where it can't be used (for example when ANTHROPIC_API_KEY or an API key helper is set); it now falls back to the API-key sign-in
  • Fixed model names in /model and fast-mode switch notices to render as code, so suffixes like [1m] display literally instead of as a link
  • Fixed claude agents skipping the workspace trust prompt when the CI environment variable is set
  • Fixed claude agents crashing on launch when the PR-status cache held a malformed entry
  • Fixed agent view resurrecting a weeks-old background session after the machine was off: such a session now shows as stopped at its real end, and opening it asks before resuming its saved conversation
  • Fixed agent view sometimes opening an older conversation, and dropping the typed prompt, when starting a new session
  • Fixed claude agents: opening a stopped session that you already resumed in another terminal no longer starts a second process on that conversation; the row now says it is open in a terminal
  • Fixed claude agents and claude rm refusing to delete a session ("has commits that are not pushed anywhere") when its worktree branch was already merged into your checked-out default branch (e.g. local main) but not yet pushed
  • Fixed background sessions waiting silently when a PermissionRequest or PreToolUse hook prints an invalid answer: the claude agents row now names the hook and the schema error
  • Fixed hooks silently treating a stdout {…} object that isn't valid JSON as plain text; it's now reported as a hook error with the parse message
  • Fixed /mcp listing a project .mcp.json entry that declares the claude.ai connector type under the trusted "claude.ai" heading; it now appears under its real scope
  • Fixed MCP servers whose headersHelper supplies the Authorization header falling into OAuth discovery on a 401 instead of re-running the helper and retrying the call as documented
  • Fixed /login to a Claude apps gateway hanging when the managed-settings security approval dialog was required
  • Fixed gateway model discovery (CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY) never running when apiKeyHelper is the only credential
  • Fixed claude logs leaving mouse tracking, bracketed paste and the alternate screen switched on in the terminal it was run from
  • Fixed the trust dialog's list of repo permission rules showing a garbled character when a long rule was cut off in the middle of an emoji
  • Fixed the permission mode indicator staying hidden behind the "Press Ctrl-C again to exit" hint when you press shift+tab right after ctrl+c
  • Fixed /ultrareview and locally seeded cloud sessions uploading uncommitted edits to prod.env-style and *.tfvars files, or to editor swap, temp, and backup copies of credential files (e.g. key.pem.tmp, id_rsa.swo); they now stay on your machine
  • Fixed Remote Control sessions occasionally never showing a permission prompt or the latest messages on the connected device after the CLI silently reconnected
  • Fixed cloud sessions occasionally failing at startup when the container's session credentials were not yet readable
  • Fixed claude remote-control rejecting its own flags (e.g. --spawn, --name) when a global flag or a wrapper-injected option precedes the subcommand
  • Fixed startup warnings (e.g. "N MCP servers need authentication") rendering one column right of the rest of the transcript
  • Fixed a backgrounded worktree session losing its checkout: the background session now holds the worktree's lock while it runs, so cleanup and git worktree remove leave it alone
  • Fixed @-mentions of other sessions not matching names typed with non-Latin characters (for example Korean entered through an IME)
  • Fixed an invalid crossSessionInbound value being silently ignored: it now warns and holds cross-session messages (user settings) or refuses them (managed settings) until fixed
  • Fixed rate-limit, usage, and fast-mode messages telling you to run /usage-credits when that command isn't available for your organization (e.g. hidden with DISABLE_EXTRA_USAGE_COMMAND)
  • [VSCode] Fixed a chat tab getting stuck on "No conversation found" when its session was never saved; it now starts a new conversation instead
  • Improved the Workflow tool's prompt footprint: its description is now about 1k tokens instead of 5.7k, with the script-writing reference moved into a bundled workflow-authoring skill
  • Improved the prompt-footer PR badge to check GitHub less often while the pull request is unchanged; a push or a gh pr command still refreshes it right away
  • Improved managed settings: client-side timeout, MCP startup-mode, and stream-watchdog env vars no longer trigger the settings-approval prompt
  • Improved /ultrareview <PR#> to check before launch that the GitHub account connected to your Claude account can access the repository, and to explain how to fix it, instead of failing after the cloud session starts
  • Improved cross-session messaging: falls back to a private per-user /tmp directory when the default one can't be used, and the notice and /status name the directory to fix
  • Changed shift+enter in the agent view dispatch input to insert a newline (matching the prompt); ctrl+enter now dispatches and attaches
  • Changed /loop: self-paced dynamic mode and the no-prompt autonomous default are now always available, including on Bedrock/Vertex/Foundry
  • Changed Anthropic telemetry export failures to log at debug level as [Anthropic telemetry] instead of [3P telemetry] OTEL diag error, so they are not mistaken for your OTel collector failing
  • Changed cross-session messaging in Linux user namespaces: root-equivalent trust for unmapped owners is limited to canonical system directories
  • Changed SendMessage from a subagent to another session: the result now notes that any reply is delivered to the parent session's conversation, not to the subagent
