NocoDB en Claude Connectors

NocoDB ahora está disponible en Claude Connectors, por lo que se puede conectar una base a Claude desde el directorio de conectores en lugar de agregar la URL de MCP manualmente. Una vez conectado, Claude puede usar todas las herramientas MCP que permita la función del usuario conectado, que a partir de esta versión es un conjunto de 149 que cubren todo el espacio de trabajo. <img width="1280" height="1102" alt="claude-connectors" src="https://github.com/user-attachments/assets/9a241a7f-c90d-4bde-b3c4-665914eeb13d" />

1200% más herramientas MCP

El servidor MCP pasó de 11 herramientas a 149, cubriendo todo el espacio de trabajo, no solo los registros. Claude, ChatGPT, Cursor o cualquier MCP client ahora pueden crear en NocoDB: levantar una mesa, conectar un flujo de trabajo a un webhook, ensamblar una página de interfaz o bloquear permisos, todo en una sola conversación. Las herramientas abarcan tablas, campos, vistas, filtros, ordenaciones, flujos de trabajo, interfaces, paneles, widgets, scripts, documentos, webhooks, comentarios, permisos, seguridad a nivel de registro, coloración de filas, carpetas, miembros e importación y exportación de CSV. Cada uno incluye el mismo servicio que su REST API, por lo que la validación, los permisos y la auditoría son idénticos, y cada llamada respeta el rol de la persona que llama: los espectadores leen, los editores escriben, los creadores cambian el esquema. <img width="1008" height="868" alt="mcp-tools" src="https://github.com/user-attachments/assets/d61251cb-7e12-491e-9ca2-fb353087bc21" /> Más información sobre MCP → 149 es sólo el comienzo. Ya estamos construyendo el siguiente conjunto, y ese es el que cambiará el software empresarial para siempre.

Correos electrónicos de texto enriquecido en flujos de trabajo

Ahora se pueden formatear los correos electrónicos de flujo de trabajo. Los nodos Enviar correo electrónico, SMTP, Gmail y Outlook comparten un editor de texto enriquecido que admite encabezados, estilos de texto, listas, colores y enlaces con texto de anclaje personalizado. Las variables del flujo de trabajo se pueden insertar en cualquier parte del cuerpo. <img width="1137" height="781" alt="rich-text-email" src="https://github.com/user-attachments/assets/eb80d79a-974c-44c6-bb28-bffdfb1fcd71" /> Obtenga más información sobre el nodo Enviar correo electrónico →

Mejoras

  • Botones en las páginas de la interfaz: los botones ahora se pueden colocar en encabezados de páginas de tablas, barras de herramientas de revisión de registros, encabezados de grupos de paneles y grupos de campos dentro de una hoja de registro. Los botones a nivel de página ejecutan una automatización sin un registro, y Ir a la página de la interfaz puede abrir una página en cualquier interfaz de la base. Más información
  • Arrastrar y soltar en la Vista de lista - Los registros en la Vista de lista se pueden arrastrar a través de la jerarquía: suelte uno sobre otro para anidarlo o sobre un padre diferente para moverlo allí. Los subregistros viajan con sus padres y los enlaces subyacentes se actualizan para usted. Más información
  • Crear un campo de registro vinculado en línea - Cuando los niveles de Vista de lista o registros anidados necesitan un vínculo que aún no existe, click Crea un campo de registro vinculado para crearlo en el momento, tanto en la vista base como en el generador de interfaz. Más información
  • Ayudantes de fecha en expresiones de flujo de trabajo - $now() devuelve la hora actual y $dateAdd(date, amount, unit) la compensa, por ejemplo $dateAdd($now(), 3, 'days').
  • Kanban más rápido: el tablero Kanban optimizado, que anteriormente era una vista previa de funciones, ahora es el predeterminado en todas partes, incluida la Edición Comunitaria. Las pilas se cargan progresivamente a medida que te desplazas.
  • Descargas de Excel de tablas grandes - Las exportaciones de Excel se transmiten por secuencias, por lo que las tablas muy grandes se descargan de manera confiable y producen archivos más pequeños.
  • Progreso de la tarea en documentos largos - El recuento de tareas de un documento de lista de verificación lo sigue hasta el encabezado una vez que el título desaparece de la vista.

¿Qué está arreglado?

  • Búsquedas anidadas: la búsqueda de una búsqueda muestra cada valor en la cuadrícula y se resuelve correctamente en enlaces de varios a uno, en MySQL, SQL Server y Oracle.
  • Acumulaciones condicionales con usuario actual: los campos acumulativos, de búsqueda y de vínculo cuyas condiciones utilizan el usuario actual se calculan para cada usuario en lugar de servirse desde una caché compartida.
  • Confiabilidad de sincronización: una sincronización de tabla ahora siempre se completa en lugar de permanecer en el estado de sincronización, y la edición de una sincronización de aplicación se guarda sin errores.
  • Nodos de registro de flujo de trabajo: la prueba de un nodo Crear registro o Actualizar registro informa cualquier clave de campo que no coincida con la tabla de destino, en lugar de escribir un registro en blanco.
  • Hojas de registro de interfaz: las ediciones realizadas al recorrer los registros aparecen inmediatamente en la cuadrícula, las acciones de vinculación y desvinculación ofrecen Deshacer y un registro creado dentro de un grupo permanece en ese grupo.
  • Navegación con el teclado de la interfaz - Con una hoja de registro abierta, las teclas de flecha se mueven a través de la cuadrícula y la hoja sigue, y Alt+Izquierda y Alt+Derecha avanzan entre registros.
  • Creador de interfaces: agregar una clasificación mantiene abierto el menú desplegable, agrupar una vista vinculada incrustada deja la página en su lugar y una interfaz iniciada refleja los cambios publicados desde otra pestaña.
  • Listas de verificación de documentos: la marcación de una tarea se refleja para cada colaborador en tiempo real, y un nuevo subelemento no marcado debajo de una tarea completada se muestra sin tachado.
  • Permisos de integración: intentar editar una integración creada por otra persona muestra un mensaje claro en lugar de cerrar sesión.
  • MCP: la clasificación de registros funciona en la edición comunitaria, los tokens sin una función base reciben una respuesta clara de acceso denegado y la autorización de OAuth se completa desde clients como la plataforma OpenAI.
  • Fuentes externas: una página de resultados de gran tamaño explica cómo reducir los campos o el tamaño de la página en lugar de informar que la fuente es inaccesible.
  • Carpetas: el botón + en una fuente de datos externa ahora ofrece Carpeta junto a Tabla, y una carpeta creada a partir del menú Mover a de un elemento ocupa la posición del elemento en la barra lateral en lugar del final de la lista.

Notas de autohospedaje

  • El modo Comunidad mantiene visibles las funciones gratuitas - Con Mostrar solo funciones de edición comunitaria activado, los flujos de trabajo, las interfaces y las carpetas permanecen disponibles, y las subfunciones bloqueadas por el plan se ocultan en lugar de mostrarse como controles inactivos.
  • Reforzamiento de la seguridad: los tokens API deshabilitados o vencidos se rechazan en la edición comunitaria, los campos ocultos permanecen ocultos detrás de las reglas de color de fila en las vistas compartidas, los comentarios se limitan a su base y la visibilidad de la tabla se aplica en cada ruta.
  • Errores de permisos PostgreSQL más claros - Un intento de cambio de esquema sin propiedad de la tabla nombra la tabla afectada en su totalidad, incluidos los nombres entre comillas con espacios o mayúsculas y minúsculas.
  • Tipos de campos pagos en implementaciones sin licencia - Los tipos de campos no incluidos en la edición comunitaria (UUID, Autonumérico, color, restricciones únicas y límites de búsqueda) ahora son rechazados por el API y por la interfaz de usuario.

Cambio importante planificado al formato de fecha y hora API

<Callout type="info">Este cambio se anunció por primera vez en 2026.08.2 y todavía está previsto para un próximo lanzamiento. No forma parte de 2026.09.0. Mantenemos el aviso aquí para que se puedan preparar las integraciones.</Callout> En implementaciones de PostgreSQL y SQLite, los valores de fecha y hora devueltos por NocoDB pasarán de una precisión de segundos a milisegundos: | Hoy | Próximo lanzamiento | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Alcance: respuestas REST API, cargas útiles de webhook y exportaciones de archivos/CSV. Los valores se formatean durante la lectura, por lo que los registros existentes también se devuelven en el nuevo formato. No se requiere migración de datos ni reposición.
  • Qué comprobar: Es posible que los consumidores que analizan fechas y horas con un formato estricto o fijo deban aceptar el componente de milisegundos. Los analizadores tolerantes como Day.js y la mayoría de los analizadores ISO 8601 no se ven afectados.
  • Filtros: Los filtros de rango y la clasificación no se ven afectados. Los filtros de igualdad de fecha y hora exactos se comparan con una precisión de segundo, por lo que es posible que no coincidan con valores que contengan milisegundos distintos de cero. Como seguimiento se planea un filtrado con reconocimiento de milisegundos.
  • No afectado: las conexiones MySQL, SQL Server y Oracle mantienen la segunda precisión, las fechas y horas representadas por fórmulas permanecen en la segunda precisión y la visualización de la fecha y hora en la aplicación no cambia.

Para obtener más detalles sobre las funciones introducidas en 2026.08.2, consulte 2026.08.2 changelog.

NocoDB in Claude Connectors

NocoDB is now available in Claude Connectors, so a base can be connected to Claude from the connectors directory rather than adding the MCP URL manually. Once connected, Claude can use every MCP tool the connecting user's role allows, which as of this release is a set of 149 covering the whole workspace.

1200% More MCP Tools

The MCP server has gone from 11 tools to 149, covering the whole workspace, not just records. Claude, ChatGPT, Cursor, or any MCP client can now build in NocoDB: stand up a table, wire a workflow to a webhook, assemble an interface page, or lock down permissions, all in one conversation.

Tools span tables, fields, views, filters, sorts, workflows, interfaces, dashboards, widgets, scripts, documents, webhooks, comments, permissions, Record-Level Security, row coloring, folders, members, and CSV import and export. Each wraps the same service as its REST API, so validation, permissions, and audit are identical, and every call respects the caller's role: viewers read, editors write, creators change schema.

Improvements

  • Buttons across interface pages - Buttons can now be placed on table page headers, record review toolbars, dashboard group headers, and field groups inside a record sheet. Page-level buttons run an automation without a record, and Go to interface page can open a page in any interface in the base. Learn more
  • Drag and drop in List View - Records in List View can be dragged across the hierarchy: drop one onto another to nest it, or onto a different parent to move it there. Sub-records travel with their parent, and the underlying links are updated for you. Learn more
  • Create a linked record field inline - When List View levels or nested records need a link that does not exist yet, click Create a linked record field to create it on the spot, in both the base view and the interface builder. Learn more
  • Date helpers in workflow expressions - $now() returns the current time and $dateAdd(date, amount, unit) offsets it, for example $dateAdd($now(), 3, 'days').
  • Faster Kanban - The optimized Kanban board, previously a feature preview, is now the default everywhere, including the Community Edition. Stacks load progressively as you scroll.
  • Excel downloads of large tables - Excel exports are streamed, so very large tables download reliably and produce smaller files.
  • Task progress in long documents - The task count of a checklist document follows you into the header once the title scrolls out of view.

What's Fixed

  • Nested lookups - A lookup of a lookup shows every value in the grid and resolves correctly over many-to-one links, on MySQL, SQL Server, and Oracle.
  • Conditional rollups with Current User - Rollup, lookup, and link fields whose conditions use Current User are computed for each user rather than served from a shared cache.
  • Sync reliability - A table sync now always completes rather than staying in the syncing state, and editing an app sync saves without error.
  • Workflow record nodes - Testing a Create record or Update record node reports any field key that does not match the target table, instead of writing a blank record.
  • Interface record sheets - Edits made while stepping through records appear in the grid immediately, link and unlink actions offer Undo, and a record created inside a group stays in that group.
  • Interface keyboard navigation - With a record sheet open, arrow keys move through the grid and the sheet follows, and Alt+Left and Alt+Right step between records.
  • Interface builder - Adding a sort keeps the dropdown open, grouping an embedded linked view leaves the page behind it in place, and a launched interface reflects changes published from another tab.
  • Document checklists - Ticking a task is reflected for every collaborator in realtime, and a new unchecked sub-item under a completed task renders without strikethrough.
  • Integration permissions - Attempting to edit an integration created by someone else shows a clear message instead of signing you out.
  • MCP - Sorting records works in the Community Edition, tokens without a base role receive a clear access denied response, and OAuth authorization completes from clients such as OpenAI's platform.
  • External sources - An oversized page of results explains how to reduce fields or page size instead of reporting the source as unreachable.
  • Folders - The + button on an external data source now offers Folder alongside Table, and a folder created from an item's Move to menu takes the item's position in the sidebar instead of the end of the list.

Self-Hosting Notes

  • Community mode keeps Free features visible - With Show only community edition features on, Workflows, Interfaces, and folders stay available, and plan-locked sub-features are hidden rather than shown as dead controls.
  • Security hardening - Disabled or expired API tokens are rejected in the Community Edition, hidden fields stay hidden behind row color rules on shared views, comments are scoped to their base, and table visibility is enforced on every route.
  • Clearer PostgreSQL permission errors - A schema change attempted without table ownership names the affected table in full, including quoted names with spaces or mixed case.
  • Paid field types on unlicensed deployments - Field types not included in the Community Edition (UUID, AutoNumber, Color, unique constraints, and lookup limits) are now rejected by the API as well as the UI.

Planned Breaking Change to API Datetime Format

<Callout type="info">This change was first announced in 2026.08.2 and is still planned for an upcoming release. It is not part of 2026.09.0. We are keeping the notice here so integrations can be prepared.</Callout>

On PostgreSQL and SQLite deployments, datetime values returned by NocoDB will move from second to millisecond precision:

| Today | Upcoming release | | --- | --- | | 2026-07-25 12:34:56+00:00 | 2026-07-25 12:34:56.000+00:00 |

  • Scope: REST API responses, webhook payloads, and CSV/file exports. Values are formatted on read, so existing records are returned in the new format too. No data migration or backfill is required.
  • What to check: Consumers that parse datetimes with a strict or fixed format may need to accept the millisecond component. Tolerant parsers such as Day.js and most ISO 8601 parsers are unaffected.
  • Filters: Range filters and sorting are unaffected. Exact datetime equality filters compare at second precision, so they may not match values carrying non-zero milliseconds. Millisecond-aware filtering is planned as a follow-up.
  • Not affected: MySQL, SQL Server, and Oracle connections keep second precision, formula-rendered datetimes stay at second precision, and the datetime display in the app is unchanged.

For more details on the features introduced in 2026.08.2, see the 2026.08.2 changelog.
