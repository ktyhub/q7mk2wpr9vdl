Interfaces

Las interfaces te permiten crear aplicaciones personalizadas y fáciles de usar a partir de tus datos base. En lugar de brindarles a todos acceso a la base completa con todas sus tablas, vistas y opciones de configuración, usted diseña páginas enfocadas que muestran exactamente los datos y acciones que cada audiencia necesita: una cola de revisión para los aprobadores, un panel para el liderazgo, un formulario para los equipos de campo o una herramienta interna completa que los combina todos. Tu base sigue siendo la única fuente de verdad; lo que cambia es cómo lo vive cada grupo. Las interfaces (beta) están disponibles en NocoDB Cloud (plan Plus y superiores) e implementaciones autohospedadas con licencia (plan Business y superiores). <img width="1440" height="900" alt="interfaces" src="https://github.com/user-attachments/assets/b31ba6d3-6255-435f-bb30-add5b2684be8" /> Más información sobre interfaces →

Mejoras y correcciones

  • Condiciones dinámicas en seguridad a nivel de registro. Una política ahora puede hacer referencia a quien esté viendo los datos, como el usuario actual, su correo electrónico o sus equipos, por lo que una única política como "El asignado es el usuario actual" cubre todo el espacio de trabajo. Las políticas también pueden filtrar por campos del sistema, como Creado por y Última modificación por. Disponible en NocoDB Cloud (plan Scale y superior) y en planes Scale y Enterprise autohospedados. Más información →
  • Nueva función de fórmula WEEKNUM. WEEKNUM(date, [startDayOfWeek]) devuelve la semana del año en la que cae una fecha, coincidiendo con cómo la calculan las hojas de cálculo. Las semanas comienzan en domingo de forma predeterminada y un segundo argumento opcional elige un primer día de la semana diferente. Más información →
  • Seleccione un rango de filas con Shift+click. Mantenga presionada la tecla Shift mientras climarca la casilla de verificación de una fila en la cuadrícula para seleccionar cada fila entre ésta y la última fila que climarcó, de la misma manera que funcionan las hojas de cálculo.
  • Las actualizaciones de enlaces v3 se limitan a los registros solicitados. La actualización de un campo de enlace a través de los registros v3 API ya no elimina esos registros vinculados de otras filas.
  • Eliminar opciones de selección por título en API v3. El punto final de eliminación de opciones de campo ahora acepta títulos de opciones en lugar de identificadores e ignora los títulos que no existen. Actualice las integraciones v3 existentes en consecuencia.
  • Cambio de comportamiento en API v1: las actualizaciones de los usuarios ya no cambian el acceso al espacio de trabajo. PATCH /api/v1/users/{userId} ya no cambia el acceso al espacio de trabajo predeterminado. Para otorgar acceso a una base específica, use POST /api/v3/meta/bases/{baseId}/members con { email, base_role }. Para permitir la creación de bases y el acceso a todo el espacio de trabajo, utilice POST /api/v3/meta/workspaces/{workspaceId}/members con { email, workspace_role }.
  • Las vistas agrupadas permanecen fijas durante la edición. Las cuadrículas agrupadas por un enlace, usuario, JSON o campo adjunto ya no se borran y se recargan en cada edición de celda.
  • No más filas duplicadas mientras se desplaza. Cuando un registro se sale de una cuadrícula filtrada u ordenada, una recuperación en curso podría representarlo por segunda vez más abajo en la vista.
  • Duplicar un registro ya no mueve los registros vinculados. Copiar cada vínculo palabra por palabra podría separar silenciosamente los registros vinculados uno a uno y con muchos del original. Estos enlaces ahora se omiten en la copia, con un aviso que enumera los campos que no se transfirieron.
  • Vistas más rápidas con códigos QR. Las celdas de códigos QR ya no generan códigos de tamaño completo para cada fila, lo que podría congelar vistas con muchos registros.
  • Confiabilidad de las instantáneas. Las instantáneas ahora funcionan en bases con permisos restringidos y en espacios de trabajo que han alcanzado su límite base.
  • Correcciones de texto inteligente. Una carga inicial fallida ya no permite que el guardado automático borre el contenido de la celda, la tecla Retroceso funciona nuevamente en el editor expandido y las tablas muestran barras persistentes para agregar filas y columnas.
  • Los campos consolidados validan su objetivo. La creación de un resumen sobre un campo que no se puede agregar, como un campo de vínculo, búsqueda o botón, se rechaza con un error claro en lugar de dividir cada lectura de la tabla.
  • Los scripts del lado del servidor crean registros con datos. createRecordsAsync en los scripts ejecutados por flujos de trabajo y automatizaciones ya no crea registros en blanco.
  • El visor de imágenes funciona en formularios. Abrir una imagen adjunta desde un formulario ya no genera un error.
  • Las vistas de lista se cargan en fuentes de datos externas en NocoDB Cloud.
  • Las importaciones de Postgres mantienen el incremento automático sincronizado. Después de importar o migrar una base a Postgres, la creación del primer registro ya no falla con un error de clave duplicada.
  • El esquema SQLite cambia con los índices. Eliminar o modificar un campo indexado en una base de datos SQLite conectada ya no falla.
  • Comentarios de Sandbox. La creación de un Sandbox ahora se confirma con un mensaje en lugar de cambiarlo silenciosamente, y la creación de un documento, que un Sandbox no admite, se desactiva con una explicación en lugar de fallar en click.
  • Controles de visibilidad de campos más ordenados. El panel de campos en los detalles de la tabla ahora usa un interruptor ocular para mostrar u ocultar campos en la vista actual.
  • Varias correcciones de estabilidad. Right-cliAl marcar un espacio vacío en un tablero Kanban ya no se muestran las acciones de otra tarjeta, y se solucionaron varios bloqueos en celdas seleccionadas y en la cuadrícula del lienzo.

Seguridad

  • Manejo de entradas. Validación más sólida de expresiones de filtro, objetivos de redireccionamiento, configuraciones de conexión y parámetros de OAuth en toda la plataforma.
  • Controles de acceso a datos. Los enlaces públicos para compartir, las exportaciones y los datos anidados ahora respetan consistentemente los filtros de visualización y los campos ocultos, y las condiciones de seguridad a nivel de registro se aplican de manera uniforme en todos los datos, en tiempo real y en las rutas en caché.
  • Autenticación y sesiones. La rotación reforzada de tokens de sesión y los flujos de autorización de OAuth, y el inicio de sesión a través de proveedores de identidad ahora respetan el estado de verificación de correo electrónico del proveedor.
  • Protección de incrustación. Las páginas de NocoDB ahora envían encabezados con protección de marco, por lo que solo se pueden incrustar enlaces públicos para compartir en otros sitios.
  • Actualizaciones de dependencias. Las dependencias se actualizaron según los avisos publicados recientemente.

Autohospedaje

  • Cambie su plan de licencia usted mismo. Cada licencia en Cuenta → Licencias autohospedadas en nocodb.com obtiene una página de detalles con su plan, período de facturación, recuento de editores, fecha de renovación y facturas, además de un flujo de cambio de plan. Las actualizaciones se aplican inmediatamente con facturación prorrateada; las rebajas entran en vigor al final del período de facturación actual y pueden revertirse hasta entonces. Más información →
  • Ocultar funciones pagas en instancias sin licencia. Una nueva preferencia Mostrar solo funciones de edición comunitaria en Cuenta → Perfil oculta insignias de funciones pagas, mensajes de actualización y controles que solo conducen a una pantalla de actualización, por lo que una instancia que se ejecuta sin licencia muestra exactamente lo que realmente puede hacer. La opción aparece solo en instancias autohospedadas sin licencia.
  • Nuevas opciones de configuración. Tres variables NC_AI_* ajustan los presupuestos de tokens del asistente de IA: NC_AI_TURN_TOKEN_BUDGET, NC_AI_INRUN_MICROCOMPACT_MIN_TOKENS y NC_AI_TOOL_OUTPUT_SPILL_MAX_ENTRIES. Más información →

Interfaces

Interfaces let you build custom, easy-to-use apps on top of your base data. Instead of giving everyone access to the full base with all its tables, views, and configuration options, you design focused pages that surface exactly the data and actions each audience needs: a review queue for approvers, a dashboard for leadership, a form for field teams, or a full internal tool that combines all of them. Your base remains the single source of truth; what changes is how each group experiences it. Interfaces (beta) are available on NocoDB Cloud (Plus plan and above) and licensed self-hosted deployments (Business plan and above).

Improvements & Fixes

  • Dynamic conditions in Record-Level Security. A policy can now reference whoever is viewing the data, such as the current user, their email, or their teams, so a single policy like "Assignee is the current user" covers the whole workspace. Policies can also filter on system fields such as Created by and Last modified by. Available on NocoDB Cloud (Scale plan and above) and self-hosted Scale and Enterprise plans. Learn more →
  • New WEEKNUM formula function. WEEKNUM(date, [startDayOfWeek]) returns the week of the year a date falls in, matching how spreadsheets calculate it. Weeks start on Sunday by default, and an optional second argument picks a different first day of the week. Learn more →
  • Select a range of rows with Shift+click. Hold Shift while clicking a row's checkbox in the grid to select every row between it and the last row you clicked, the same way spreadsheets work.
  • v3 link updates stay scoped to the requested records. Updating a link field through the v3 records API no longer removes those linked records from other rows.
  • Delete select options by title in API v3. The field options delete endpoint now accepts option titles instead of ids and ignores titles that do not exist. Update existing v3 integrations accordingly.
  • Behaviour change in API v1: user updates no longer change workspace access. PATCH /api/v1/users/{userId} no longer changes default workspace access. To grant access to a specific base, use POST /api/v3/meta/bases/{baseId}/members with { email, base_role }. To allow base creation and workspace-wide access, use POST /api/v3/meta/workspaces/{workspaceId}/members with { email, workspace_role }.
  • Grouped views stay put while editing. Grids grouped by a link, user, JSON, or attachment field no longer blank out and reload on every cell edit.
  • No more duplicate rows while scrolling. When a record dropped out of a filtered or sorted grid, an in-flight fetch could render it a second time further down the view.
  • Duplicating a record no longer moves linked records. Copying every link verbatim could silently detach has-many and one-to-one linked records from the original. These links are now skipped on the copy, with a notice listing the fields that were not carried over.
  • Faster views with QR codes. QR code cells no longer generate full-size codes for every row, which could freeze views with many records.
  • Snapshot reliability. Snapshots now work on bases with restricted permissions and in workspaces that have reached their base limit.
  • Smart Text fixes. A failed initial load no longer lets autosave clear the cell's content, Backspace works again in the expanded editor, and tables show persistent bars for adding rows and columns.
  • Rollup fields validate their target. Creating a rollup over a field that cannot be aggregated, such as a Link, Lookup, or Button field, is rejected with a clear error instead of breaking every read of the table.
  • Server-side scripts create records with data. createRecordsAsync in scripts run by workflows and automations no longer creates blank records.
  • Image viewer works in forms. Opening an image attachment from a form no longer throws an error.
  • List views load on external data sources on NocoDB Cloud.
  • Postgres imports keep auto-increment in sync. After importing or migrating a base into Postgres, creating the first record no longer fails with a duplicate-key error.
  • SQLite schema changes with indexes. Deleting or modifying an indexed field on a connected SQLite database no longer fails.
  • Sandbox feedback. Creating a sandbox now confirms with a message instead of silently switching you over, and creating a document, which a sandbox does not support, is disabled with an explanation rather than failing on click.
  • Tidier field visibility controls. The fields panel in table details now uses an eye toggle to show or hide fields in the current view.
  • Assorted stability fixes. Right-clicking empty space on a Kanban board no longer shows another card's actions, and several crashes in select cells and the canvas grid were fixed.

Security

  • Input handling. Stronger validation of filter expressions, redirect targets, connection configurations, and OAuth parameters across the platform.
  • Data access controls. Public share links, exports, and nested data now consistently honour view filters and hidden fields, and record-level security conditions are applied uniformly across data, realtime, and cached paths.
  • Authentication and sessions. Hardened session token rotation and OAuth authorization flows, and sign-in via identity providers now honours the provider's email verification status.
  • Embedding protection. NocoDB pages now send frame-protection headers, so only public share links can be embedded in other sites.
  • Dependency updates. Dependencies were updated against recently published advisories.

Self-Hosting

  • Change your license plan yourself. Each license under Account → Self-hosted licenses on nocodb.com gets a detail page with its plan, billing period, editor count, renewal date, and invoices, plus a Change plan flow. Upgrades apply immediately with prorated billing; downgrades take effect at the end of the current billing period and can be reverted until then. Learn more →
  • Hide paid features on unlicensed instances. A new Show only community edition features preference under Account → Profile hides paid feature badges, upgrade prompts, and controls that only lead to an upgrade screen, so an instance running without a license shows just what it can actually do. The option appears only on unlicensed self-hosted instances.
  • New configuration options. Three NC_AI_* variables tune the AI assistant's token budgets: NC_AI_TURN_TOKEN_BUDGET, NC_AI_INRUN_MICROCOMPACT_MIN_TOKENS, and NC_AI_TOOL_OUTPUT_SPILL_MAX_ENTRIES. Learn more →
