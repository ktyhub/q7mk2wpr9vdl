servidores v2.5.0

Correcciones de seguridad

v2.5.0 corrige ocho vulnerabilidades en tres servidores. Actualice mcp-server-git a 2026.11.18, @modelcontextprotocol/server-filesystem a 2.4.0 y @modelcontextprotocol/server-everything a 2.3.1. | Paquete | Afectados | Fijado en | | --- | --- | --- | | mcp-server-git | a través de 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | todas las versiones anteriores a 2.4.0 y versiones de fecha 2025.1.14 a 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | a través de 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • Una fusión ya no inicia el mantenimiento automático de Git. Un git_merge exitoso, incluido un avance rápido, terminó en git maintenance run --auto, cuya recolección de basura ejecuta los comandos con los nombres propios de un repositorio gc.recentObjectsHook, con los privilegios del servidor. maintenance.auto ahora es false y gc.auto es 0 para cada comando Git que ejecuta el servidor (GHSA-h2g3-rwxm-xfm3)
  • Git nunca recupera un objeto faltante por sí solo. La configuración de un repositorio podría declarar un promisor remoto y nombrar el programa que Git ejecuta para recuperarlo (remote.<name>.uploadpack, core.sshCommand), que luego iniciaba una herramienta de solo lectura cuando necesitaba un objeto que no estaba en el disco. La recuperación diferida está desactivada (GIT_NO_LAZY_FETCH=1) y un Git demasiado antiguo para aceptarlo que rechaza un repositorio que declara un promitente remoto (GHSA-87qg-cmw8-jc5m)
  • Los controladores se leen nuevamente después de que una herramienta escribe el árbol de trabajo. La configuración de un repositorio puede incluir un archivo que crea una combinación o un proceso de extracción, por lo que un filtro o controlador de combinación podría aparecer después de que el servidor haya vaciado los que encontró y ejecutarse durante el git merge --abort que sigue a un conflicto. git_checkout, git_merge y esa cancelación ahora leen los controladores nuevamente antes de ejecutar cualquier otro comando de Git. La verificación de confinamiento --repository aún no se repite después de dicha escritura (#5599) (GHSA-9vjp-x34c-xg6v)
  • Un filtro o controlador de combinación con un nombre vacío también se vacía. Git acepta [filter ""], seleccionado por filter= en .gitattributes, y la lista del servidor de los controladores de un repositorio lo omitió, por lo que se ejecutó su comando (GHSA-pm7p-vphh-2cg7)
  • Las entradas de índice que apuntan fuera del árbol de trabajo se rechazan. Con --repository, un .git/index diseñado que nombra una ruta como ../outside/secret hizo que git_diff_unstaged y git_diff devolvieran el contenido de ese archivo, y git_status informara si existe. El índice ahora se verifica desde la parte superior antes de que cualquier herramienta lo lea, y el caché sin seguimiento, que puede nombrar un directorio fuera del árbol de trabajo, está desactivado (GHSA-r2q8-f657-4r56)
  • La configuración propia de un submódulo ya no ejecuta programas. Con diff.submodule=diff en la configuración del repositorio, git_diff ejecutó una diferenciación anidada dentro de cada submódulo modificado bajo los propios controladores diff.external y textconv del submódulo, y git_checkout y git_add también ejecutaron Git dentro de un submódulo bajo su propia configuración. diff.submodule ahora es short, los controladores que define un submódulo extraído se anulan y un Git anterior a 2.33, que no pasaría las anulaciones a un submódulo, se rechaza para un repositorio que tiene uno extraído (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Los listados de directorios permanecen en el directorio que se marcó (Linux y macOS). list_directory, list_directory_with_sizes, directory_tree y search_files ahora enumeran un directorio en su lugar después de verificarlo, por lo que un directorio intercambiado por un enlace simbólico entre la verificación y el listado ya no puede devolver los nombres de las entradas fuera de los directorios permitidos. En Windows, un listado aún no está anclado (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource trata una dirección NAT64 como la dirección IPv4 que lleva. El protector de direcciones privadas de la herramienta lee las direcciones en 64:ff9b::/96 como públicas, por lo que en una red con una puerta de enlace NAT64 una URL podría llegar a una dirección IPv4 privada a través de una. La dirección IPv4 integrada ahora está marcada (GHSA-38j4-j742-j7r3)

Actualización desde una versión de npm con fecha de versión

Los servidores TypeScript pasaron de versiones de fecha (2025.x, 2026.x) a versiones semánticas en 1.0.0. Los administradores de paquetes clasifican 2.4.0 por debajo de todas las versiones 2025.x y 2026.x, por lo que no lo ofrecerán como actualización. Si tiene una versión actualizada de @modelcontextprotocol/server-filesystem, instale 2.4.0 explícitamente: npm install @modelcontextprotocol/server-filesystem@2.4.0.

servers v2.5.0

Security fixes

v2.5.0 fixes eight vulnerabilities in three servers. Upgrade mcp-server-git to 2026.11.18, @modelcontextprotocol/server-filesystem to 2.4.0 and @modelcontextprotocol/server-everything to 2.3.1.

| Package | Affected | Fixed in | | --- | --- | --- | | mcp-server-git | through 2026.11.11 | 2026.11.18 | | @modelcontextprotocol/server-filesystem | all versions before 2.4.0, and date versions 2025.1.14 through 2026.8.31 | 2.4.0 | | @modelcontextprotocol/server-everything | through 2.3.0 | 2.3.1 |

mcp-server-git 2026.11.18

  • A merge no longer starts Git's automatic maintenance. A successful git_merge, a fast-forward included, ended in git maintenance run --auto, whose garbage collection runs the commands a repository's own gc.recentObjectsHook names, with the server's privileges. maintenance.auto is now false and gc.auto is 0 for every Git command the server runs (GHSA-h2g3-rwxm-xfm3)
  • Git never fetches a missing object by itself. A repository's configuration could declare a promisor remote and name the program Git runs to fetch from it (remote.<name>.uploadpack, core.sshCommand), which a read-only tool then started when it needed an object that was not on disk. Lazy fetching is turned off (GIT_NO_LAZY_FETCH=1), and a Git too old to honor that refuses a repository that declares a promisor remote (GHSA-87qg-cmw8-jc5m)
  • Drivers are read again after a tool writes the working tree. A repository's configuration can include a file that a merge or checkout creates, so a filter or merge driver could appear after the server had emptied the ones it found, and run during the git merge --abort that follows a conflict. git_checkout, git_merge and that abort now read the drivers again before any other Git command runs. The --repository confinement check is not yet repeated after such a write (#5599) (GHSA-9vjp-x34c-xg6v)
  • A filter or merge driver with an empty name is emptied too. Git accepts [filter ""], selected by filter= in .gitattributes, and the server's list of a repository's drivers missed it, so its command ran (GHSA-pm7p-vphh-2cg7)
  • Index entries that point outside the working tree are refused. With --repository, a crafted .git/index naming a path such as ../outside/secret made git_diff_unstaged and git_diff return that file's content, and git_status report whether it exists. The index is now checked from its top before any tool reads it, and the untracked cache, which can name a directory outside the working tree, is turned off (GHSA-r2q8-f657-4r56)
  • A submodule's own configuration no longer runs programs. With diff.submodule=diff in the repository's configuration, git_diff ran a nested diff inside each changed submodule under the submodule's own diff.external and textconv drivers, and git_checkout and git_add ran Git inside a submodule under its own configuration too. diff.submodule is now short, the drivers a checked-out submodule defines are overridden, and a Git older than 2.33, which would not pass the overrides into a submodule, is refused for a repository that has one checked out (GHSA-8wv7-r664-7594)

@modelcontextprotocol/server-filesystem 2.4.0

  • Directory listings stay with the directory that was checked (Linux and macOS). list_directory, list_directory_with_sizes, directory_tree and search_files now list a directory in place after checking it, so a directory swapped for a symlink between the check and the listing can no longer return the names of entries outside the allowed directories. On Windows a listing is not yet anchored (#5600) (GHSA-rq2p-q7c4-6g27)

@modelcontextprotocol/server-everything 2.3.1

  • gzip-file-as-resource treats a NAT64 address as the IPv4 address it carries. The tool's private-address guard read addresses in 64:ff9b::/96 as public, so on a network with a NAT64 gateway a URL could reach a private IPv4 address through one. The embedded IPv4 address is now checked (GHSA-38j4-j742-j7r3)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.4.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.4.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.4.0.
