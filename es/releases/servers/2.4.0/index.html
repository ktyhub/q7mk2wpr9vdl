servidores v2.4.0

Correcciones de seguridad

v2.4.0 corrige seis vulnerabilidades en tres servidores. Actualice @modelcontextprotocol/server-filesystem a 2.3.0, y mcp-server-git y mcp-server-fetch a 2026.11.11. | Paquete | Afectados | Fijado en | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | todas las versiones anteriores a 2.3.0 y versiones de fecha 2025.1.14 a 2026.8.31 | 2.3.0 | | mcp-server-git | a través de 2026.11.4 | 2026.11.11 | | mcp-server-fetch | a través de 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Las lecturas permanecen con el archivo que se verificó (Linux y macOS). Las herramientas de lectura y los recursos de archivos ahora abren un archivo relativo al directorio que se verificó, como ya lo hicieron las escrituras, por lo que un directorio intercambiado por un enlace simbólico entre la verificación de acceso y la lectura ya no puede devolver un archivo fuera de los directorios permitidos. Un FIFO, un socket o un dispositivo se rechaza en lugar de leerse. En Windows esto reduce la carrera sin cerrarla, como para escrituras (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file mueve solo la fuente que verificó. Un movimiento dentro de un dispositivo primero saca la fuente de su propio directorio verificado con un nombre nuevo, por lo que un directorio de origen intercambiado por un enlace simbólico ya no puede traer un archivo externo a los directorios permitidos, donde sería legible (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • La configuración Git propia de un repositorio ya no puede hacer que el servidor ejecute un programa. Una llamada de solo lectura como git_status en un repositorio untrusted se utiliza para ejecutar un comando nombrado en su .git/config (core.fsmonitor, diff.external, enlaces, filtros y controladores de combinación, firma) con los privilegios del servidor. Cada comando de Git ahora anula esas configuraciones, y un Git anterior a 2.31, que ignoraría las anulaciones, se rechaza (GHSA-6hqx-gqrx-c5r2)
  • El confinamiento --repository cubre almacenes de objetos alternativos, árboles de trabajo vinculados y enlaces en el directorio Git. Un repositorio dentro del permitido podría leer los objetos de otro repositorio a través de objects/info/alternates, o pasar el directorio Git de un árbol de trabajo vinculado como el del repositorio permitido. Ambos son rechazados, al igual que un enlace simbólico en un directorio de Git que conduce fuera del repositorio permitido. En Windows aún no se cubre una unión de directorios (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • Las direcciones locales del sitio IPv6 son privadas. El protector de direcciones privadas lee fec0::/10 como público. Ahora se rechaza, al igual que cualquier dirección IPv6 fuera de unidifusión global (2000::/3) que no lleve una dirección IPv4 (GHSA-3rxj-6jhw-qfv7)
  • robots.txt se compara con la ruta que el sitio resolverá, así como con la ruta tal como está escrita, por lo que //private o /x/../private ya no pueden pasar Disallow: /private (GHSA-f9hh-cmx9-2f23)

Actualización desde una versión de npm con fecha de versión

Los servidores TypeScript pasaron de versiones de fecha (2025.x, 2026.x) a versiones semánticas en 1.0.0. Los administradores de paquetes clasifican 2.3.0 por debajo de todas las versiones 2025.x y 2026.x, por lo que no lo ofrecerán como actualización. Si tiene una versión actualizada de @modelcontextprotocol/server-filesystem, instale 2.3.0 explícitamente: npm install @modelcontextprotocol/server-filesystem@2.3.0.

servers v2.4.0

Security fixes

v2.4.0 fixes six vulnerabilities in three servers. Upgrade @modelcontextprotocol/server-filesystem to 2.3.0, and mcp-server-git and mcp-server-fetch to 2026.11.11.

| Package | Affected | Fixed in | | --- | --- | --- | | @modelcontextprotocol/server-filesystem | all versions before 2.3.0, and date versions 2025.1.14 through 2026.8.31 | 2.3.0 | | mcp-server-git | through 2026.11.4 | 2026.11.11 | | mcp-server-fetch | through 2026.11.4 | 2026.11.11 |

@modelcontextprotocol/server-filesystem 2.3.0

  • Reads stay with the file that was checked (Linux and macOS). The read tools and file resources now open a file relative to the directory that was checked, as writes already did, so a directory swapped for a symlink between the access check and the read can no longer return a file from outside the allowed directories. A FIFO, socket or device is refused rather than read. On Windows this narrows the race without closing it, as for writes (#5260) (GHSA-p9cv-8g75-4xcg)
  • move_file moves only the source it checked. A move within one device first takes the source out of its own checked directory under a fresh name, so a source directory swapped for a symlink can no longer bring an outside file into the allowed directories, where it would become readable (GHSA-7m4x-rv66-mxhh)

mcp-server-git 2026.11.11

  • A repository's own Git configuration can no longer make the server run a program. A read-only call such as git_status on an untrusted repository used to run a command named in its .git/config (core.fsmonitor, diff.external, hooks, filter and merge drivers, signing) with the server's privileges. Every Git command now overrides those settings, and a Git older than 2.31, which would ignore the overrides, is refused (GHSA-6hqx-gqrx-c5r2)
  • --repository confinement covers alternate object stores, linked worktrees and links in the Git directory. A repository inside the allowed one could read another repository's objects through objects/info/alternates, or pass a linked worktree's Git directory off as the allowed repository's. Both are refused, as is a symlink in a Git directory that leads outside the allowed repository. On Windows a directory junction is not yet covered (#5520) (GHSA-q74p-4wrc-q7w6)

mcp-server-fetch 2026.11.11

  • IPv6 site-local addresses are private. The private-address guard read fec0::/10 as public. It is now refused, and so is any IPv6 address outside global unicast (2000::/3) that does not carry an IPv4 address (GHSA-3rxj-6jhw-qfv7)
  • robots.txt is matched against the path the site will resolve, as well as the path as written, so //private or /x/../private can no longer get past Disallow: /private (GHSA-f9hh-cmx9-2f23)

Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.3.0 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version of @modelcontextprotocol/server-filesystem, install 2.3.0 explicitly: npm install @modelcontextprotocol/server-filesystem@2.3.0.
