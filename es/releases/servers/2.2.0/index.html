servidores v2.2.0

Seguridad: actualizaciones del certificado CA y tiempo de ejecución de Node.js (octubre de 2026)

El 20 de octubre de 2026, eMudhra reveló que las claves privadas de ocho de sus certificados de CA intermedios podrían recuperarse de los certificados públicos. El 21 de octubre, Node.js envió [versiones de seguridad] (https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) que actualizan sus certificados de CA incluidos para el compromiso y corrigen varios CVE de tiempo de ejecución de alta gravedad no relacionados. El 23 de octubre, certifi 2026.10.23 de Python eliminó las raíces de eMudhra emSign Root CA - C1 y emSign ECC Root CA - C3. Cómo se encuentran estos servidores

  • Los servidores TypeScript dependen del tiempo de ejecución Node.js para las comprobaciones de certificados. No envían certificados de CA propios. Solo server-everything realiza solicitudes HTTPS salientes (gzip-file-as-resource) y el Node.js en el que se ejecuta las verifica. server-filesystem, server-memory y server-sequential-thinking no realizan conexiones de red.
  • mcp-server-fetch verifica HTTPS con el paquete certifi, a través de httpx. La instalación desde PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resuelve el certifi, 2026.10.23 actual o posterior. El archivo fetch Docker del repositorio se instala desde su archivo de bloqueo, que esta versión traslada a certifi 2026.10.23 (#5341).
  • mcp-server-git y mcp-server-time no realizan conexiones de red. Si ejecuta un servidor TypeScript desde npm (npx o una instalación global) Se ejecuta en su Node.js, que no podemos actualizar por usted. Ejecute Node.js 24.22.1 o 26.12.1, o posterior, y consulte con node --version. El campo engines de los paquetes acepta cualquier Node.js 24, por lo que npm no le advertirá sobre un tiempo de ejecución anterior y sin parches. Si ejecuta mcp-server-fetch desde un entorno existente Un entorno creado antes del 23 de octubre conserva su antiguo certifi. Actualícelo con uvx --refresh mcp-server-fetch o pip install -U certifi.

servers v2.2.0

Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped security releases that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's certifi 2026.10.23 removed the eMudhra roots emSign Root CA - C1 and emSign ECC Root CA - C3.

How these servers stand

  • The TypeScript servers rely on the Node.js runtime for certificate checks. They ship no CA certificates of their own. Only server-everything makes outbound HTTPS requests (gzip-file-as-resource), and the Node.js it runs on verifies them. server-filesystem, server-memory and server-sequential-thinking make no network connections.
  • mcp-server-fetch verifies HTTPS against the certifi bundle, through httpx. Installing from PyPI (uvx mcp-server-fetch, pip install mcp-server-fetch) resolves the current certifi, 2026.10.23 or later. The repository's fetch Dockerfile installs from its lockfile, which this release moves to certifi 2026.10.23 (#5341).
  • mcp-server-git and mcp-server-time make no network connections.

If you run a TypeScript server from npm (npx or a global install)

It runs on your Node.js, which we can't update for you. Please run Node.js 24.22.1 or 26.12.1, or later, and check with node --version. The packages' engines field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

If you run mcp-server-fetch from an existing environment

An environment created before October 23 keeps its older certifi. Refresh it with uvx --refresh mcp-server-fetch, or pip install -U certifi.
