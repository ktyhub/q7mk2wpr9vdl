bóveda v2.0.4

##2.0.4

04 de agosto de 2026

CAMBIOS ÚLTIMOS:

  • contenedores: los siguientes paquetes se han eliminado del contenedor basado en UBI Imágenes: gnupg, openssl, procps. SEGURIDAD:
  • acl: corrige una vulnerabilidad de escalada de privilegios donde se podía omitir una restricción denied_parameters en el campo de solicitud policies enviando un nombre de política que combina mayúsculas y minúsculas (por ejemplo, "Super-Admin" en lugar de "super-admin"). Vault ahora normaliza el parámetro policies a minúsculas antes de evaluar las restricciones allowed_parameters/denied_parameters.
  • identidad/scim (empresa): el punto final identity/entity/merge ahora rechaza solicitudes que involucran cualquier entidad administrada por SCIM, evitando que los operadores privilegiados eviten las barreras de propiedad de SCIM para transferir alias, membresías de grupos o políticas a través de los límites de SCIM.
  • identidad: evita que el punto final de eliminación por lotes de la entidad (identidad/entidad/eliminación por lotes) elimine el almacenamiento subyacente de entidades que pertenecen a otro espacio de nombres.
  • identidad: las actualizaciones de entidad/nombre ahora rechazan los selectores de ID no coincidentes o external_id para evitar reorientar las actualizaciones a una entidad diferente CAMBIOS:
  • auth/oci: Actualizar complemento a v0.21.3
  • núcleo: versión Bump Go para 1.26.5.
  • núcleo: elimina la compatibilidad con atributos duplicados en archivos de configuración de HCL y definiciones de políticas. Analizando HCL con los atributos duplicados ahora siempre fallan y el entorno VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES Se ha eliminado la variable que anteriormente restauraba el comportamiento heredado. CARACTERÍSTICAS:
  • secretos: Se agregó la capacidad de ver secretos en formato YAML MEJORAS:
  • auth/cert: admite inicio de sesión a través de encabezados de certificados reenviados por x incluso con tls deshabilitado en el detector de bóveda.
  • núcleo (empresa): agregue un punto final en sys/config/oauth-resource-server/id/:config_id para leer los perfiles del servidor de recursos oauth mediante config_id
  • núcleo (empresa): hacer que la validación JWT typ del servidor de recursos OAuth sea más permisiva para tokens de IdP como Okta al permitir que falte un encabezado typ, al tiempo que se restringen los valores actuales de typ a at+jwt, application/at+jwt y JWT.
  • núcleo (empresa): contención de bloqueo de envoltura de sello de Ameriolate para rutas centrales.
  • core/acl: agrega una opción de configuración global deny_slash_in_templated_path para rechazar la presencia de barras diagonales en las plantillas de identidad representadas en las políticas, de forma predeterminada es false.
  • núcleo/identidad: agrega una opción de configuración global deny_slash_in_templated_path para rechazar la presencia de barras diagonales en las plantillas de identidad representadas en las políticas, de forma predeterminada es false.
  • core/managed-keys/PKCS#11 (empresa): se rechaza proporcionar un valor que no esté vacío para un campo mientras el otro ya está guardado. Para cambiar los modos de direccionamiento, debe borrar explícitamente el campo antiguo enviándolo como una cadena vacía ("") en la misma solicitud junto con el nuevo valor.
  • core/managed-keys/PKCS#11 (empresa): slot y token_label ahora se aplican estrictamente como identificadores mutuamente excluyentes para un token HSM
  • eventos: agregue la variable de entorno VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE para configurar colas de eventos limitadas para los suscriptores de notificación de eventos. Establezca un número entero positivo (por ejemplo, 16) para habilitar canales almacenados en búfer de ese tamaño (máximo 1000). Esto evita el agotamiento de los recursos en implementaciones con un gran número de suscriptores, pero tiene el costo de la posibilidad de que los suscriptores se pierdan eventos. El valor predeterminado es 0 (sin búfer) para compatibilidad con versiones anteriores.
  • identidad/scim (empresa): se agregó soporte de filtrado a los puntos finales GET /scim/v2/Users y GET /scim/v2/Groups según RFC 7644. Filtros admitidos: userName eq, externalId eq, active eq y meta.lastModified gt/ge/lt/le para usuarios; displayName eq y meta.lastModified gt/ge/lt/le para Grupos. Las expresiones de filtro no admitidas devuelven HTTP 400. ServiceProviderConfig ahora anuncia filter.supported: true.
  • identidad/scim (empresa): mejore el rendimiento del punto final de listado de usuarios y grupos de SCIM mediante el uso de clasificación por prefijo en lugar de un pase de clasificación separado.
  • identidad: incluya el estado de la entidad y los detalles de la marca de tiempo de la entidad/alias en las respuestas key_info de la lista de entidades.
  • oauth-resource-server: agregue soporte para opciones de control de políticas detalladas (restricciones de parámetros) en solicitudes de autorización enriquecidas (RAR), incluidos allowed_parameters, denied_parameters y required_parameters dentro de authorization_details.
  • oauth-resource-server: agregue soporte para expresiones de plantilla de identidad (por ejemplo, {{identity.entity.id}}) en solicitudes de autorización enriquecidas (RAR).
  • scim: los recursos de usuario ahora incluyen un campo groups de solo lectura que enumera las membresías directas de grupos administradas por el SCIM client solicitante, según RFC 7643.
  • secrets/kv (empresa): admite la lectura y recuperación de secretos KVv2 a partir de una instantánea cargada, incluida la recuperación in situ y la copia desde la ruta dentro del mismo montaje y espacio de nombres.
  • ui: agregue una opción de vista YAML de solo lectura a la página de detalles secretos de KV v2, junto con la interfaz de usuario existente y las vistas JSON.
  • ui: Mejora la entrada de pnpm.overrides para tmp de 0.2.6 a 0.2.7.
  • ui: Mejora la entrada pnpm.overrides para ws de 8.20.1 a 8.21.0. CORRECCIÓN DE ERRORES:
  • Proxy/Agente: se corrigió un error por el cual los encabezados de los métodos de autenticación se acumulaban en el API client compartido a través de ciclos de reautenticación.
  • Proxy: se corrigió un error por el cual el encabezado del token de Vault acumulaba valores duplicados en las reconexiones de WebSocket en el actualizador de caché secreto estático.
  • Recuperación de secretos (empresarial): no redirigir al nodo activo para solicitudes de lista a sys/storage/raft/snapshot-load o solicitudes de lectura/eliminación a sys/storage/raft/snapshot-load/{id}. Si es posible, maneje estas solicitudes en el modo de espera de rendimiento; de lo contrario, reenvíe las solicitudes al nodo activo.
  • auditoría: se corrigió una regresión de CVE-2025-6000 que no permitía habilitar dispositivos de auditoría en Windows cuando se configuraba un directorio de complementos.
  • auditoría: haga que la serialización del receptor de auditoría de archivos y sockets tenga en cuenta el contexto, de modo que las solicitudes canceladas o caducadas dejen de esperar detrás de escrituras de auditoría bloqueadas, lo que reduce la acumulación de rutinas, memoria, conexiones y descriptores de archivos durante la contención del receptor de auditoría.
  • auth/cert: agregue soporte para encabezados de certificados reenviados x provenientes de ALB de AWS.
  • auth/spiffe (empresa): utilice la cadena de certificados de pares completa al verificar los certificados.
  • aws/auth: Redactar los valores de metadatos de la instancia EC2 de los mensajes de error de autenticación de AWS.
  • facturación de consumo: se solucionó el error por el cual las unidades de facturación de certificados PKI, SSH y SSH OTP de los nodos en espera de rendimiento no se reenviaban a los nodos activos para su almacenamiento, lo que provocaba que se perdieran los eventos de facturación en los nodos en espera.
  • facturación de consumo: se corrigió el error por el cual las unidades de facturación de tokens SPIFFE JWT de los nodos en espera de rendimiento no se reenviaban a los nodos activos para su almacenamiento, lo que provocaba que se perdieran los eventos de facturación en los nodos en espera.
  • facturación de consumo: se corrigió un error por el cual los recuentos de certificados ajustados por duración de SSH y los recuentos de OTP cuya representación decimal comenzaba con '4' no se podían leer desde el almacenamiento, lo que provocaba que sys/billing/overview devolviera un error 500 con "lz4: número mágico incorrecto". La codificación de almacenamiento ahora utiliza cadenas decimales simples consistentes con otras métricas de facturación, evitando la identificación errónea como datos comprimidos con lz4.
  • facturación de consumo: se corrigió el error por el cual los recuentos de duración del token OIDC de los nodos en espera de rendimiento no se reenviaban a los nodos activos para su almacenamiento, lo que provocaba que se perdieran los eventos de facturación en los nodos en espera.
  • facturación de consumo: se corrigieron interbloqueos en KMIP y rutas de facturación de escaneo de montaje al evitar la adquisición de bloqueos anidados durante la enumeración de complementos y montaje.
  • facturación de consumo: corrige el recuento de roles estáticos y dinámicos de LDAP y OpenLDAP en la facturación de casos de uso utilizar puntos finales de recuento dedicados (recuento de roles, recuento de roles estático) en lugar del recuento basado en LISTA, que estaba subestimando los roles.
  • núcleo (empresa): corrige un error que provoca que se vuelva a envolver el sello de forma innecesaria.
  • núcleo (empresa): preserva los metadatos de ajuste cuando el desencapsulado del grupo de control reproduce una solicitud aprobada que devuelve una respuesta ajustada.
  • núcleo (empresa): actualización de la comprobación del estado del token coherente del lado del servidor (SSCT) cuando se utiliza en clústeres secundarios de rendimiento. Se preferirán los códigos de respuesta 403 a los 412 para solicitudes de tokens entre clústeres no válidas a nodos activos secundarios.
  • núcleo/claves administradas (empresa): permite números de ranura superiores a 32 bits en claves administradas PKCS#11.
  • núcleo/sello: Se corrigió la fuga de rutina que ocurría cuando las funciones de cifrado y descifrado expiraban.
  • núcleo: conserva los parámetros de consulta de URL al redirigir solicitudes API que contienen barras diagonales duplicadas a su ruta canónica. Anteriormente, la redirección eliminaba parámetros como ?list=true, lo que podía cambiar el resultado de la solicitud.
  • eventos (empresa): corrige un error por el cual los eventos dejaban de reenviarse a los secundarios de rendimiento después de que el nodo activo se reiniciaba o tenía un evento de cambio (sellar/dessellar, etc.).
  • exportar API: normaliza el parámetro end_time en la actividad exportar API al final del mes para que coincida con el comportamiento indicado en la documentación.
  • oauth-resource-server (empresa): la autorización del servidor de recursos OAuth ahora trata una matriz authorization_details vacía como un reclamo ausente cuando los detalles de la autorización son opcionales. Anteriormente, los tokens que contenían una matriz vacía se rechazaban con RAR_NO_MATCH en lugar de continuar con la autorización normal de identidad y política.
  • secrets-sync (empresa): se corrigió la asignación de código de respuesta de error incorrecto para las validaciones de cifrado controlado por el cliente de GCP Secrets Sync, que se devolvieron como 500 Error interno del servidor en lugar de 400 Solicitud incorrecta.
  • secrets-sync: corrige que los destinos de GCP Secret Manager pierdan su clave KMS por región al reiniciar Vault.
  • secrets-sync: corrige el campo Etiquetas personalizadas en la vista Detalles para mostrar claves con valor vacío
  • secrets/pki-external-ca (empresa): incluya la clave privada dentro de los PEM del campo de respuesta del certificado API cuando el formato_certificado esté configurado en pem_bundle
  • secretos/tránsito (empresa): agregue compatibilidad con claves administradas para firmar CSR y establecer puntos finales de la cadena de certificados.
  • ui: maneja correctamente los valores de cadena ("verdadero"/"falso") para tls_disable al mostrar el estado de TLS en el widget de configuración del clúster.
  • ui: corrige que PKI genere raíz, por lo que no es válido después de controlar correctamente las entradas de caducidad de certificados.

vault v2.0.4

2.0.4

August 04, 2026

BREAKING CHANGES:

  • containers: The following packages have been removed from UBI based container images: gnupg, openssl, procps.

SECURITY:

  • acl: Fix privilege-escalation vulnerability where a denied_parameters constraint on the policies request field could be bypassed by submitting a mixed-case policy name (e.g. "Super-Admin" instead of "super-admin"). Vault now normalizes the policies parameter to lowercase before evaluating allowed_parameters/denied_parameters constraints.
  • identity/scim (enterprise): The identity/entity/merge endpoint now rejects requests that involve any SCIM-managed entity, preventing privileged operators from bypassing SCIM ownership guardrails to transfer aliases, group memberships, or policies across SCIM boundaries.
  • identity: Prevent the entity batch-delete endpoint (identity/entity/batch-delete) from deleting the underlying storage of entities that belong to another namespace.
  • identity: entity/name updates now reject mismatched id or external_id selectors to prevent retargeting updates to a different entity

CHANGES:

  • auth/oci: Update plugin to v0.21.3
  • core: Bump Go version to 1.26.5.
  • core: remove support for duplicate attributes in HCL configuration files and policy definitions. Parsing HCL with duplicate attributes now always fails, and the VAULT_ALLOW_PENDING_REMOVAL_DUPLICATE_HCL_ATTRIBUTES environment variable that previously restored the legacy behavior has been removed.

FEATURES:

  • secrets: Added ability to view secrets in YAML format

IMPROVEMENTS:

  • auth/cert: Support login via x-forwarded cert headers even with tls disabled on the vault listener.
  • core (enterprise): Add an endpoint at sys/config/oauth-resource-server/id/:config_id to read oauth resource server profiles by config_id
  • core (enterprise): Make OAuth resource server JWT typ validation more permissive for tokens from IdPs such as Okta by allowing a missing typ header, while restricting present typ values to at+jwt, application/at+jwt, and JWT.
  • core (entreprise): Ameriolate sealwrap lock contention for core paths.
  • core/acl: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/identity: Adds a global deny_slash_in_templated_path configuration option to reject the presence of slashes in rendered identity templates in policies, defaulting to false.
  • core/managed-keys/PKCS#11 (enterprise): Providing a non-empty value for one field while the other is already saved is rejected. To switch addressing modes, you must explicitly clear the old field by sending it as an empty string ("") in the same request alongside the new value.
  • core/managed-keys/PKCS#11 (enterprise): slot and token_label are now strictly enforced as mutually exclusive identifiers for an HSM token
  • events: Add VAULT_EVENT_NOTIFICATIONS_BOUNDED_QUEUE_SIZE environment variable to configure bounded event queues for event notification subscribers. Set to a positive integer (e.g., 16) to enable buffered channels of that size (maximum 1000). This prevents resource exhaustion in deployments with high subscriber counts, but comes at the cost of the potential for subscribers to miss events. Defaults to 0 (unbuffered) for backward compatibility.
  • identity/scim (enterprise): Added filtering support to the GET /scim/v2/Users and GET /scim/v2/Groups endpoints per RFC 7644. Supported filters: userName eq, externalId eq, active eq, and meta.lastModified gt/ge/lt/le for Users; displayName eq and meta.lastModified gt/ge/lt/le for Groups. Unsupported filter expressions return HTTP 400. ServiceProviderConfig now advertises filter.supported: true.
  • identity/scim (enterprise): Improve SCIM User and Group listing endpoint performance by using prefix sort instead of a separate sort pass.
  • identity: Include entity status and entity/alias timestamp details in entity list key_info responses.
  • oauth-resource-server: Add support for fine-grained policy control options (parameter constraints) in Rich Authorization Requests (RAR), including allowed_parameters, denied_parameters, and required_parameters inside authorization_details.
  • oauth-resource-server: Add support for identity template expressions (e.g. {{identity.entity.id}}) in Rich Authorization Requests (RAR).
  • scim: User resources now include a read-only groups field listing the direct group memberships managed by the requesting SCIM client, per RFC 7643.
  • secrets/kv (enterprise): Support reading and recovering KVv2 secrets from a loaded snapshot, including in-place recover and copy-from-path within the same mount and namespace.
  • ui: Add a read-only YAML view option to the KV v2 secret details page, alongside the existing UI and JSON views.
  • ui: Bump pnpm.overrides entry for tmp from 0.2.6 to 0.2.7.
  • ui: Bump pnpm.overrides entry for ws from 8.20.1 to 8.21.0.

BUG FIXES:

  • Proxy/Agent: Fixed a bug where auth method headers accumulated on the shared API client across re-auth cycles.
  • Proxy: Fixed a bug where the Vault token header accumulated duplicate values across WebSocket reconnects in the static secret cache updater.
  • Secrets Recovery (enterprise): Do not redirect to the active node for list requests to sys/storage/raft/snapshot-load or read/delete requests to sys/storage/raft/snapshot-load/{id}. If possible, handle these requests on the performance standby, otherwise forward the requests to the active node.
  • audit: Fix a regression from CVE-2025-6000 that broke enabling audit devices on Windows when a plugin directory was configured.
  • audit: make file and socket audit sink serialization context-aware so canceled or expired requests stop waiting behind blocked audit writes, reducing buildup of goroutines, memory, connections, and file descriptors during audit sink contention
  • auth/cert: Add support for x-forwarded cert headers coming from AWS ALBs.
  • auth/spiffe (enterprise): Use the full peer certificate chain when verifying certificates.
  • aws/auth: Redact EC2 instance metadata values from AWS auth error messages.
  • consumption-billing: Fix bug where PKI, SSH and SSH OTP certificate billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fix bug where SPIFFE JWT token billing units from performance standby nodes were not being forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed a bug where SSH duration-adjusted certificate counts and OTP counts whose decimal representation began with '4' could not be read back from storage, causing sys/billing/overview to return a 500 error with "lz4: bad magic number". The storage encoding now uses plain decimal strings consistent with other billing metrics, avoiding misidentification as lz4-compressed data.
  • consumption-billing: Fixed bug where OIDC token duration counts from performance standby nodes were not forwarded to active nodes for storage, causing billing events on standby nodes to be lost.
  • consumption-billing: Fixed deadlocks in KMIP and mount-scanning billing paths by avoiding nested lock acquisition during mount and plugin enumeration.
  • consumption-billing: Fixes LDAP and OpenLDAP dynamic and static role counting in use-case billing to use dedicated count endpoints (role-count, static-role-count) instead of LIST-based counting, which was undercounting roles.
  • core (enterprise): Fix a bug that causes unnecessary seal rewrapping.
  • core (enterprise): Preserve wrapping metadata when Control Group unwrap replays an approved request that returns a wrapped response.
  • core (enterprise): Update state checking of Sever-Side Consistent Token (SSCT) when used on performance secondary clusters. 403 response codes will be preferred over 412 for invalid, cross cluster token requests to secondary active nodes.
  • core/managed-keys (enterprise): Allow slot numbers above 32 bits in PKCS#11 managed keys.
  • core/seal: Fixed goroutine leak occurring when Encryption and Decryption functions time out.
  • core: Preserve URL query parameters when redirecting API requests containing duplicate slashes to their canonical path. Previously, the redirect dropped parameters such as ?list=true, potentially changing the result of the request.
  • events (enterprise): Fix a bug where events stopped being forwarded to performance secondaries after the active node restarted or had a change event (seal/unseal, etc).
  • export API: Normalize the end_time parameter in the activity export API to the end of the month to match the behavior stated in the documentation.
  • oauth-resource-server (enterprise): OAuth Resource Server authorization now treats an empty authorization_details array like an absent claim when authorization details are optional. Previously, tokens containing an empty array were rejected with RAR_NO_MATCH instead of continuing through normal identity and policy authorization.
  • secrets-sync (enterprise):fixed incorrect error response code mapping for GCP Secrets Sync Customer Controlled Encryption validations, which were returned as 500 Internal Server Error instead of 400 Bad Request.
  • secrets-sync: Fix GCP Secret Manager destinations losing their per-region KMS key on Vault restart.
  • secrets-sync: Fixes Custom Tags field in Details view to display keys with empty value
  • secrets/pki-external-ca (enterprise): Include the private key within the certificate API response field's PEMs when certificate_format is set to pem_bundle
  • secrets/transit (enterprise): Add managed key support to CSR sign and set certificate chain endpoints.
  • ui: Correctly handle string values ("true"/"false") for tls_disable when displaying TLS status in the Cluster Configuration widget.
  • ui: Fixes PKI generate root so Not valid after correctly controls cert expiration inputs.
