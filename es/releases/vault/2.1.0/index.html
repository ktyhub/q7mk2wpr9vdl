bóveda v2.1.0

##2.1.0

01 de septiembre de 2026

SEGURIDAD:

  • núcleo: actualice go.etcd.io/etcd/client/pkg/v3 a v3.7.1 para corregir la vulnerabilidad de seguridad GO-2026-6107.
  • núcleo: actualice software.sslmate.com/src/go-pkcs12 a v0.7.2 para corregir la vulnerabilidad de seguridad GO-2026-5052. CAMBIOS:
  • Licencia: agregue términos de Agentic IAM al modelo de licencia client y actualice los términos para el modelo de licencia Vault Platform.
  • núcleo: versión Bump Go para 1.26.7.
  • oauth-resource-server (empresa): evita que el id_emisor mute después de la creación del perfil del servidor de recursos OAuth. Los operadores deben eliminar y volver a crear perfiles para cambiar el id_emisor.
  • oauth-resource-server (empresa): evita que Unique_id_claim mute después de la creación del perfil del servidor de recursos OAuth. Los operadores deben eliminar y volver a crear perfiles para cambiar el Unique_id_claim.
  • oauth-resource-server (empresa): la función del servidor de recursos OAuth ya no requiere activación a través del punto final sys/activation-flags/oauth-resource-server/activate.
  • oauth-resource-server (empresa): actualice la configuración del servidor de recursos OAuth para incluir opciones de reclamo personalizadas para el identificador y actor únicos del token.
  • secrets/openldap (empresa): Actualización del complemento a v0.18.4+ent CARACTERÍSTICAS:
  • IU de Registro de Agentes (empresa): Agrega una nueva sección de Seguridad Agentic a la navegación principal con una página de Registro de Agentes donde los operadores pueden ver, buscar y administrar agentes de IA registrados, sus entidades y alias de Vault asociados, políticas asignadas y estado operativo.
  • Cumplimiento automático del desafío DNS-01 para CA externa PKI: Integre con los siguientes proveedores de DNS para el cumplimiento automático del desafío DNS-01: AWS Route53, Azure DNS, Google Cloud DNS y BIND y otros servidores compatibles con RFC2136.
  • Soporte PKI PKCS#12 y JKS: agrega soporte para paquetes de certificados PKCS#12 (PFX) y Java keytool (JKS) a los puntos finales PKI relevantes. Los paquetes se devuelven como archivos codificados en base64 y protegidos con contraseña.
  • Compatibilidad con SLH-DSA para firma/verificación híbrida en el motor Transit (empresa): agregue compatibilidad con SLH-DSA como componente PQC para operaciones de firma/verificación híbrida. Esto es compatible tanto con ECDSA (p-256, P-384, P-521) como con Ed25519.
  • secrets/pki-external-ca (empresa): agregue soporte para manejar desafíos dns-01 para Azure, AWS, GCP y rfc2136 DNS. MEJORAS:
  • registro-agente (empresa): se eliminó la restricción que no permitía el uso de 'denegar' en las políticas de límite máximo, lo que generaba errores en la solicitud.
  • agente/pkiexternalca: reemplace go.uber.org/atomic con sync/atomic (stdlib) para operaciones booleanas atómicas en el paquete pkiexternalca.
  • auth/token: agregue una lista de denegación global para revocar los JWT de OAuth para evitar la autorización de tokens específicos en todos los espacios de nombres.
  • core/seal (empresa): actualice la biblioteca de Oracle Cloud para permitir la integración del sello con regiones más nuevas.
  • ui: pasa dompurify de 3.4.6 a 3.4.13.
  • ui: Mejora la cita de shell de 1.8.4 a 1.9.0.
  • ui: exponer el campo de clave privada RSA en la interfaz de usuario al generar credenciales con el motor de secretos de la base de datos de Snowflake. Anteriormente, este campo sólo se mostraba en el cli.
  • UI: el modo de confirmación de eliminación del motor Secrets ahora requiere escribir delete-engine para confirmar, muestra el nombre del motor, el recuento de secretos (solo motores KV) y una lista de lo que se eliminará permanentemente. ConfirmModal ahora se ha actualizado para incluir un tipo de confirmación opcional. CORRECCIÓN DE ERRORES:
  • agente/pki-external-ca: Se corrigió la extracción de la cadena de CA de las respuestas API de Vault PKI donde el campo ca_chain siempre estaba vacío en las plantillas debido a un manejo incorrecto del tipo de respuestas de la matriz
  • api: cuenta para el encabezado HTTP Age al calcular la vida útil restante de un contrato de arrendamiento, de modo que los contratos de arrendamiento leídos o renovados a través de un proxy de almacenamiento en caché como Vault Agent se renueven antes de que caduquen.
  • núcleo (empresa): soluciona una carrera de datos y un posible pánico durante el sellado/desbloqueo
  • núcleo (empresa): solucionó el pánico en collectOperatorImportMetrics cuando router.Route devuelve una respuesta nula sin errores durante las lecturas de metadatos KVv2 en nodos secundarios de rendimiento. Esta condición ocurre durante la fase de sincronización parcial de la transmisión WAL de una unión inicial.
  • core/login: corrige el pánico en solicitudes de inicio de sesión con formato incorrecto. Vault ahora devuelve un error para cargas útiles de inicio de sesión con formato incorrecto en lugar de interrumpir la conexión client (sin pérdida de datos).
  • núcleo/métricas: se corrigió un error por el cual log_format = "json" no tenía ningún efecto en los errores de receptor de telemetría de los backends de statsd y statsite.
  • core/wrapping: sys/wrapping/wrap ahora aplica tokens de ajuste en formato uuid, ignorando cualquier formato de ajuste solicitado por la persona que llama.
  • núcleo: corrige el comando vault operator migrate -start al migrar al almacenamiento integrado en balsa.
  • núcleo: vault kv put/get ahora funciona con tokens OAuth externos.
  • cubbyhole: corrige las escrituras en cubbyhole para tokens JWT en espacios de nombres no raíz
  • autenticación predeterminada: soluciona el problema con las configuraciones de autenticación predeterminada heredadas que se romperían como parte de la actualización a una versión más nueva de Vault.
  • identidad: Se corrigió el error en la creación del alias de entidad con "el espacio de nombres del descriptor de acceso de montaje no coincide con el espacio de nombres de la solicitud" cuando se usa un descriptor de acceso de montaje sintético en un contexto de espacio de nombres
  • oauth-resource-server (empresa): solucionó el problema por el cual optional_authorization_details se ignoraba incorrectamente para los flujos de trabajo delegados (OBO) cuando el sujeto no tenía registro de agente, lo que provocaba que RAR no fuera obligatorio en esas solicitudes.
  • complementos: al leer un complemento solo versionado sin especificar -version ahora lo selecciona automáticamente cuando solo existe una versión, o devuelve un error que enumera las versiones disponibles, en lugar de un 404 silencioso.
  • proxy/caché (empresa): se corrigió un error en el caché secreto estático donde las solicitudes GET con ?list=true se almacenaban en caché incorrectamente y se entregaban obsoletas.
  • sdk/rotación: Las llamadas posteriores ya no permitirán que los campos rotation_period y rotation_schedule se configuren simultáneamente. El SDK ahora vacía explícitamente el campo opuesto para garantizar la exclusión mutua.
  • secreto/pki: Se corrigió la condición de carrera de finalización del pedido ACME donde solicitudes simultáneas podían emitir certificados dos veces y dejar uno huérfano del seguimiento con clave de pedido
  • secreto/pki: evita que el cambio de nombre de clave acepte un nombre que ya tiene una clave diferente.
  • secretos/base de datos: desinfecte el DisplayName controlado por la persona que llama antes de usarlo en los nombres de usuario generados para evitar la inyección de SQL a través de plantillas de nombre de usuario. Agrega una advertencia de configuración cuando una plantilla_usuario hace referencia a DisplayName sin una función de truncado.
  • secrets/ldap: rotar manualmente una contraseña de función estática reiniciará la rotación TTL una vez más, coincidiendo con el comportamiento anterior a v2.0.0
  • secretos/nómada: solucione el agotamiento de la conexión en condiciones de alta concurrencia introduciendo un HTTP client compartido y agrupado con un límite de conexión por host. Anteriormente, se abría una nueva conexión TCP para cada solicitud de credencial, lo que provocaba que Nomad devolviera errores HTTP 429 "demasiadas conexiones simultáneas" cuando se generaban más de 100 concesiones simultáneamente.
  • registro de servicio/cónsul: se solucionó un problema por el cual Vault se cancelaba permanentemente del catálogo de servicios de Consul cuando se enviaba una señal SIGHUP/recarga y la configuración usaba Consul como backend de almacenamiento sin una estrofa service_registration explícita.
  • ui/secrets/pki: Se corrigió que la página de lista de emisores no se cargara cuando el número de emisores excede 10
  • ui: Corrija el error 403 en el método de autenticación Configure la página para políticas que otorgan lectura en sys/auth* pero no en sys/auth/*.
  • ui: Se corrigió el método de autenticación Kubernetes que no guardaba token_reviewer_jwt: se usó la clave de esquema OpenAPI incorrecta (KubernetesConfigureRequest) en lugar de KubernetesConfigureAuthRequest, lo que provocó que el campo JWT se omitiera del formulario y la carga útil de API al guardar.
  • interfaz de usuario: corrige el borde clipping en las tablas de widgets del tablero aplicando un estilo oculto por desbordamiento.
  • ui: corrige el error de redireccionamiento abierto en la ruta del proveedor OIDC.
  • UI: Se corrigió el menú lateral del generador de políticas que rechazaba los guardados cuando no se seleccionaban capacidades para una regla.
  • ui: agregue la propiedad totalItems para corregir la paginación de la lista filtrada que muestra un recuento total de páginas incorrecto
  • interfaz de usuario: corrige el banner falso "Sin acceso" al navegar a la interfaz de usuario de Vault con ?namespace=root en la URL

vault v2.1.0

2.1.0

September 01, 2026

SECURITY:

  • core: Update go.etcd.io/etcd/client/pkg/v3 to v3.7.1 to fix security vulnerability GO-2026-6107.
  • core: Update software.sslmate.com/src/go-pkcs12 to v0.7.2 to fix security vulnerability GO-2026-5052.

CHANGES:

  • License: Add Agentic IAM terms to client licensing model and update terms for Vault Platform licensing model.
  • core: Bump Go version to 1.26.7.
  • oauth-resource-server (enterprise): Prevent issuer_id from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the issuer_id.
  • oauth-resource-server (enterprise): Prevent unique_id_claim from being mutated after OAuth Resource Server profile creation. Operators must delete and recreate profiles to change the unique_id_claim.
  • oauth-resource-server (enterprise): The OAuth Resource Server feature no longer requires activation via the sys/activation-flags/oauth-resource-server/activate endpoint.
  • oauth-resource-server (enterprise): Update OAuth Resource Server config to include custom claim options for the token's unique identifier and actor.
  • secrets/openldap (enterprise): Update plugin to v0.18.4+ent

FEATURES:

  • Agent Registry UI (enterprise): Adds a new Agentic Security section to the primary navigation with an Agent Registry page where operators can view, search, and manage registered AI agents, their associated Vault entities and aliases, assigned policies, and operational status.
  • Automatic DNS-01 Challenge Fulfillment for PKI External CA: Integrate with the following DNS providers for automatic DNS-01 challenge fulfillment: AWS Route53, Azure DNS, Google Cloud DNS, and BIND and other RFC2136-compliant servers.
  • PKI PKCS#12 and JKS Support: Adds support for PKCS#12 (PFX) and Java keytool (JKS) certificate bundles to relevant PKI endpoints. Bundles are returned as base64-encoded, password-protected files.
  • SLH-DSA support for Hybrid sign/verify in Transit engine (enterprise): Add support for SLH-DSA as the PQC component for Hybrid sign/verify operations. This is compatible with both ECDSA (p-256, P-384, P-521) and Ed25519.
  • secrets/pki-external-ca (enterprise): Add support for handling dns-01 challenges for Azure, AWS, GCP, and rfc2136 DNS.

IMPROVEMENTS:

  • agent-registry (enterprise): Removed the restriction that disallowed the use of 'deny' in ceiling policies, resulting in request errors.
  • agent/pkiexternalca: Replace go.uber.org/atomic with sync/atomic (stdlib) for atomic boolean operations in the pkiexternalca package.
  • auth/token: Add global denylist for revoking OAuth JWTs to prevent authorization of specific tokens across all namespaces.
  • core/seal (enterprise): Update Oracle Cloud library to enable seal integration with newer regions.
  • ui: Bump dompurify from 3.4.6 to 3.4.13.
  • ui: Bump shell-quote from 1.8.4 to 1.9.0.
  • ui: Exposing the RSA Private Key field in the UI when generating credentials with the snowflake database secrets engine. Previously, this field was only shown in the cli.
  • ui: Secrets engine delete confirmation modal now requires typing delete-engine to confirm, displays the engine name, secret count (KV engines only), and a list of what will be permanently deleted. ConfirmModal has now been updated to include a optional type-to-confirm.

BUG FIXES:

  • agent/pki-external-ca: Fix CA chain extraction from Vault PKI API responses where ca_chain field was always empty in templates due to incorrect type handling of array responses
  • api: Account for the HTTP Age header when calculating a lease's remaining lifetime, so that leases read or renewed through a caching proxy such as Vault Agent are renewed before they expire.
  • core (enterprise): Fix a data race and potential panic during seal/unseal
  • core (enterprise): Fix panic in collectOperatorImportMetrics when router.Route returns a nil response with no error during KVv2 metadata reads on performance secondary nodes. This condition occurs during the WAL-stream partial-sync phase of an initial join.
  • core/login: Fix panic on malformed login requests. Vault now returns an error for malformed login payloads instead of dropping the client connection (no data loss).
  • core/metrics: Fixed a bug where log_format = "json" had no effect on telemetry sink errors from statsd and statsite backends.
  • core/wrapping: sys/wrapping/wrap now enforces uuid-format wrapping tokens, ignoring any caller-requested wrap format.
  • core: Fix vault operator migrate -start command when migrating to raft integrated storage.
  • core: vault kv put/get now works with external OAuth tokens.
  • cubbyhole: Fix cubbyhole writes for JWT tokens in non-root namespaces
  • default-auth: Fix issue with legacy default-auth configs that would break as part of upgrading to a newer version of Vault.
  • identity: Fixed entity alias creation failing with "mount accessor namespace does not match request namespace" when using a synthetic mount accessor in a namespaced context
  • oauth-resource-server (enterprise): Fix issue where optional_authorization_details was incorrectly ignored for delegated (OBO) workflows when the subject has no agent registration, resulting in RAR not being mandatory in those requests.
  • plugins: Reading a versioned-only plugin without specifying -version now auto-selects it when only one version exists, or returns an error listing available versions, instead of a silent 404.
  • proxy/cache (enterprise): Fixed a bug in the static secret cache where GET requests with ?list=true were incorrectly cached and served stale.
  • sdk/rotation: Subsequent calls will no longer allow both the rotation_period and rotation_schedule fields to be set simultaneously. The SDK now explicitly empties the opposing field to guarantee mutual-exclusion.
  • secret/pki: Fix ACME order finalize race condition where concurrent requests could double-issue certificates and orphan one from order-keyed tracking
  • secret/pki: prevent key rename from accepting a name already held by a different key.
  • secrets/database: Sanitize the caller-controlled DisplayName before it is used in generated usernames to prevent SQL injection via username templates. Adds a configuration warning when a username_template references DisplayName without a truncate function.
  • secrets/ldap: manually rotating a static role password will restart the rotation TTL once again, matching the behavior prior to v2.0.0
  • secrets/nomad: Fix connection exhaustion under high concurrency by introducing a shared, pooled HTTP client with a per-host connection cap. Previously, a new TCP connection was opened for every credential request, causing Nomad to return HTTP 429 "too many concurrent connections" errors when more than 100 leases were generated simultaneously.
  • serviceregistration/consul: Fixed an issue where Vault would permanently deregister itself from the Consul service catalog when a SIGHUP/reload signal was sent and the configuration used Consul as the storage backend without an explicit service_registration stanza.
  • ui/secrets/pki: Fix issuers list page failing to load when issuer count exceeds 10
  • ui: Fix 403 error on auth method Configure page for policies that grant read on sys/auth* but not sys/auth/*.
  • ui: Fix Kubernetes auth method not saving token_reviewer_jwt — the wrong OpenAPI schema key (KubernetesConfigureRequest) was used instead of KubernetesConfigureAuthRequest, causing the JWT field to be omitted from the form and API payload on save.
  • ui: Fix border clipping on dashboard widget tables by applying overflow-hidden styling.
  • ui: Fix open redirect bug in OIDC provider route.
  • ui: Fix policy generator flyout rejecting saves when no capabilities are selected for a rule.
  • ui: add totalItems property to fix filtered list pagination showing incorrect total page count
  • ui: fix spurious "No access" banner when navigating to Vault UI with ?namespace=root in the URL
