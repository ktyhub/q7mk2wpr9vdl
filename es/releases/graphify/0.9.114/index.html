grafificar v0.9.114

Trabajo de rendimiento en el proceso de extracción/compilación/actualización, además de un lote de correcciones de extracción y compilación. Cada entrada marcada como Rendimiento conserva exactamente la salida del gráfico (byte idéntico); el extractor corrige el resultado del cambio y comparte un aumento en el esquema de caché AST (consulte la nota al final).

  • Rendimiento: ids normalize_id obtiene una ruta rápida ASCII, expresiones regulares precompiladas y un caché LRU, por lo que el caso del identificador común (ASCII, repetido) se salta el ciclo de normalización Unicode. ~1,26x en la ruta de cálculo y una gran ganancia en identificadores repetidos, lo que se repite mucho en un corpus.
  • Rendimiento: caché save_cached construye la copia en escritura de la carga útil portátil en disco en lugar de copy.deepcopy-ing cada resultado por archivo; ~20% más rápido en la transformación de escritura en caché, escalando con el tamaño del gráfico por archivo. La entrada nunca cambia y los bytes en el disco son idénticos.
  • Rendimiento: extraer cada archivo fuente se lee del disco una vez (el hash de clave y el análisis comparten un búfer) en lugar de dos veces en una compilación en frío, y el cuidador de árboles Parser se reutiliza por idioma dentro de un trabajador en lugar de reconstruirse por archivo (las lecturas de archivos se reducen aproximadamente a la mitad en la ruta del trabajador).
  • Rendimiento: extraer la resolución entre archivos finalizar construye sus índices de nodo/borde compartidos en unas pocas pasadas fusionadas en lugar de ~6 escaneos completos independientes del gráfico; ~15% más rápido en la etapa de finalización.
  • Rendimiento: observe la comparación de topología sin cambios utiliza un hash de contenido independiente del orden calculado en una sola pasada en lugar de ordenar y volver a serializar todo el gráfico; ~1,4 veces en esa comparación.
  • Rendimiento: clúster la partición de la comunidad se almacena en caché mediante un hash de topología y se reutiliza cuando el gráfico no cambia (~9x en un acierto de caché del clúster), y la clave determinista de clasificación de borde elimina un json.dumps por borde en favor de una clave de tupla barata (ordenamiento idéntico).
  • Rendimiento: analizar la centralidad de intermediación de suggest_questions ahora ejecuta una implementación Brandes de matriz plana en lugar de la basada en dict de networkx, con puntuaciones idénticas bit por bit; ~2,6 veces más rápido y crece con el tamaño del gráfico (#5303, gracias @Max17190).
  • Rendimiento: ver cada ruta de origen conservada se modifica una vez por actualización incremental en lugar de volver a calcularse por nodo y borde; el resultado de la actualización es de bytes idénticos (#5322, gracias @Max17190).
  • Solución: java un campo o clase anotado con Lombok @Getter obtiene el nodo getter getX()/isX() sintetizado que javac ve, por lo que obj.getX() lo resuelve; Los campos booleanos usan isX, se respeta @Getter(AccessLevel.NONE), no se duplica un captador escrito a mano y se ignora un @Getter que no sea de Lombok (#5148, gracias @Deepjyoti-Sarmah).
  • Solución: kotlin una llamada de miembro en un receptor con un tipo declarado (parámetro, propiedad, val x: T o val x = T()) se vincula al método de ese tipo en todos los archivos en lugar del último método con el mismo nombre en el archivo, y las llamadas de interfaz se envían a sus implementadores; un receptor ambiguo o desconocido falla al cerrarse (#5355, gracias @xiongjianxu).
  • Solución: sql un cuerpo de rutina PostgreSQL PL/pgSQL que la gramática solo analiza mediante recuperación de ERROR (RETURN QUERY SELECT ... FROM t) tiene sus lecturas de tabla recuperadas como bordes reads_from en lugar de eliminadas (#5349, gracias @Deepjyoti-Sarmah).
  • Solución: compilación cuando un borde extraído por AST y una copia semántica (LLM) del mismo borde se unen, el borde determinista EXTRAÍDO se mantiene, por lo que un documento posterior --update ya no elimina un borde de código que una copia semántica había sobrescrito (#5334, gracias @Ildar-gn).
  • Solución: sql un procedimiento T-SQL cuyo encabezado la gramática solo analiza parcialmente (tree-sitter-sql 0.3.12+ lee mal el nombre, absorbiendo parámetros sin paréntesis o un escape ""/]]) produce un único nodo de rutina en lugar de un duplicado bajo la identificación mal leída; Se mantiene una rutina real para compartir la línea del error leído (#5236, gracias @Deepjyoti-Sarmah).
  • Solución: vbnet un método declarado después de un literal de cadena de varias líneas ya no se elimina: el archivo se analiza nuevamente con cadenas de varias líneas aplanadas primero a un marcador de posición que conserva la línea, por lo que una cadena sin terminar en una línea ya no se traga al resto de la clase; los archivos de una sola línea se analizan sin cambios (#5320, gracias @Deepjyoti-Sarmah).
  • Solución: cpp un tipo calificado std:: (std::chrono::seconds, std::vector<T>) ya no se vuelve a cablear en un símbolo de proyecto con el mismo nombre; la referencia estándar obtiene su propio código auxiliar sin fuente que la reconexión del corpus omite, mientras que los argumentos de la plantilla del tipo estándar aún se resuelven en los propios tipos del proyecto (#5219, gracias @deba2k5).
  • Solución: python un import mod simple donde mod se encuentra en un directorio sys.path.insert(...) (un directorio de script que no es un paquete) ahora vincula mod.func() al nodo de función func, coincide con el archivo único en esa ruta y, al fallar, se cierra por ambigüedad o un nombre stdlib; un borde calls ya no tiene un alias en un nodo de archivo (#5253, gracias @madhusudanpatnaik).
  • Solución: servir una consulta que filtra la relación call ahora mantiene los bordes calls entre repositorios (escritos como relation=calls, context=cross_repo), que fueron eliminados silenciosamente por el filtro de solo contexto (#5257, gracias @LHopitalOne).
  • Solución: construir el borde estructural method/contains de un miembro con respecto a su propietario se mantiene sobre un borde de uso de miembro en dirección opuesta (un método que lee la propiedad estática o constante de su clase), por lo que el miembro ya no desaparece del recorrido del tipo; las relaciones de no uso (heredadas/implementadas) mantienen la regla existente (#2391, gracias @livingforelvis). El esquema de caché AST aumenta a 50; Los cachés calientes vuelven a ejecutar las extracciones de Kotlin, Java, SQL, VB.NET, C++ y Python (importación sys.path) afectadas.

graphify v0.9.114

Performance work on the extract/build/update pipeline, plus a batch of extractor and build fixes. Every entry marked Perf preserves graph output exactly (byte-identical); the extractor fixes change output and share one AST cache schema bump (see the note at the end).

  • Perf: ids normalize_id gets an ASCII fast-path, pre-compiled regexes and an LRU cache, so the common (ASCII, repeated) identifier case skips the Unicode normalization loop. ~1.26x on the compute path and a large win on repeated ids, which recurs heavily across a corpus.
  • Perf: cache save_cached builds the portable on-disk payload copy-on-write instead of copy.deepcopy-ing every per-file result; ~20% faster on the cache-write transform, scaling with per-file graph size. The input is never mutated and the on-disk bytes are identical.
  • Perf: extract each source file is read from disk once (the key hash and the parse share one buffer) instead of twice on a cold build, and the tree-sitter Parser is reused per language within a worker instead of rebuilt per file (file reads roughly halved on the worker path).
  • Perf: extract the cross-file resolution finalize builds its shared node/edge indexes in a few fused passes instead of ~6 independent full scans of the graph; ~15% faster on the finalize stage.
  • Perf: watch the no-change topology comparison uses an order-independent content hash computed in one pass instead of sorting and re-serializing the whole graph; ~1.4x on that compare.
  • Perf: cluster the community partition is cached by a topology hash and reused when the graph is unchanged (~9x on a cluster cache hit), and the deterministic edge-sort key drops a per-edge json.dumps in favour of a cheap tuple key (identical ordering).
  • Perf: analyze suggest_questions' betweenness centrality now runs a flat-array Brandes implementation instead of networkx's dict-based one, with bit-for-bit identical scores; ~2.6x faster, growing with graph size (#5303, thanks @Max17190).
  • Perf: watch each preserved source path is rebased once per incremental update instead of recomputed per node and edge; the update output is byte-identical (#5322, thanks @Max17190).
  • Fix: java a field or class annotated with Lombok @Getter gets the synthesized getX()/isX() getter node javac sees, so obj.getX() resolves to it; boolean fields use isX, @Getter(AccessLevel.NONE) is respected, a hand-written getter is not duplicated, and a non-Lombok @Getter is ignored (#5148, thanks @Deepjyoti-Sarmah).
  • Fix: kotlin a member call on a receiver with a declared type (parameter, property, val x: T, or val x = T()) binds to that type's method across files instead of the last same-named method in the file, and interface calls dispatch to their implementers; an ambiguous or unknown receiver fails closed (#5355, thanks @xiongjianxu).
  • Fix: sql a PostgreSQL PL/pgSQL routine body that the grammar only parses through ERROR recovery (RETURN QUERY SELECT ... FROM t) has its table reads recovered as reads_from edges instead of dropped (#5349, thanks @Deepjyoti-Sarmah).
  • Fix: build when an AST-extracted edge and a semantic (LLM) copy of the same edge tie, the deterministic EXTRACTED edge is kept, so a later docs --update no longer deletes a code edge that a semantic copy had overwritten (#5334, thanks @Ildar-gn).
  • Fix: sql a T-SQL procedure whose header the grammar only partly parses (tree-sitter-sql 0.3.12+ misreads the name, absorbing unparenthesised params or a ""/]] escape) yields a single routine node instead of a duplicate under the misread id; a real routine sharing the misread's line is kept (#5236, thanks @Deepjyoti-Sarmah).
  • Fix: vbnet a method declared after a multi-line string literal is no longer dropped: the file is reparsed with multi-line strings flattened to a line-preserving placeholder first, so an unterminated string on one line no longer swallows the rest of the class; single-line files are parsed unchanged (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp a std::-qualified type (std::chrono::seconds, std::vector<T>) is no longer rewired onto a same-named project symbol; the std reference gets its own sourceless stub the corpus rewire skips, while the std type's template arguments still resolve to the project's own types (#5219, thanks @deba2k5).
  • Fix: python a plain import mod where mod sits on a sys.path.insert(...) directory (a non-package script dir) now binds mod.func() to the func function node, matched to the unique file on that path and failing closed on ambiguity or a stdlib name; a calls edge is no longer aliased onto a file node (#5253, thanks @madhusudanpatnaik).
  • Fix: serve a query that filters on the call relation now keeps cross-repo calls edges (written as relation=calls, context=cross_repo), which were silently dropped by the context-only filter (#5257, thanks @LHopitalOne).
  • Fix: build a member's structural method/contains edge to its owner is kept over an opposite-direction member-usage edge (a method reading its class's own static property or constant), so the member no longer vanishes from the type's walk; non-usage relations (inherits/implements) keep the existing rule (#2391, thanks @livingforelvis).

The AST cache schema is bumped to 50; warm caches re-run the affected Kotlin, Java, SQL, VB.NET, C++ and Python (sys.path import) extractions.
