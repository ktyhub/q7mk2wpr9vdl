grafificar v0.9.118

Un lote de correcciones de extracción, resolución, servicio, exportación, agrupación y generación de informes en catorce solicitudes de extracción comunitarias. Los cambios de Objective-C, C y C# alteran la salida del nodo/borde, por lo que el esquema de caché de AST aumenta (51 a 53) y la primera compilación después de la actualización vuelve a extraer los idiomas afectados; las otras correcciones no necesitan reconstrucción.

  • Corrección: csharp un parámetro o campo local llamado partial, required, async, nint, nuint o with (palabras clave contextuales) que tree-sitter-c-sharp analiza mal donde comienza una declaración ya no descarrila el archivo; se reescribe textualmente en su formato @name antes del análisis (conservación de longitud de bytes), por lo que el tipo adjunto y los miembros posteriores se conservan en lugar de eliminarse silenciosamente (#5043, gracias @ThatAblaze).
  • Solución: c una llamada a través de un campo de puntero de función de estructura (ops->run(), ops.run()) ya no fabrica una ventaja calls para una función libre del mismo nombre; el nombre del campo no es evidencia del objetivo de tiempo de ejecución del puntero, por lo que se descarta la suposición. Una simple llamada directa aún se resuelve (#5410, gracias @sdivyanshu90).
  • Solución: objc un método Objective-C cuyo nombre se incluye en la identificación de un hermano dentro de un @interface/@implementation/@protocol (un _ inicial/final como en -setup/-_setup, o una diferencia de solo mayúsculas y minúsculas) obtiene su propia identificación de nodo salado en lugar de sobrescribirlo; la declaración y definición de un método aún comparten un solo nodo (#5390, gracias @ayushcodes10).
  • Solución: go el tipo de propietario de un campo de estructura tiene como ámbito su propio paquete, por lo que un campo de un tipo cuyo nombre se declara en dos paquetes se vincula al correcto y las llamadas de sus miembros se resuelven en lugar de descartarse como ambiguas (#5408, gracias @azizur100389).
  • Solución: extraer una importación Svelte que viene a través de un barril export * ahora se resuelve en el módulo de definición real, que coincide con el .ts simple. El solucionador de archivos cruzados enmascaraba .vue pero no .svelte, por lo que las importaciones de Svelte <script> se perdieron debido a un error de análisis de plantilla; los barriles encadenados se resuelven y las reexportaciones ambiguas fracasan cerradas. Ejecute graphify extract . --force una vez para reparar un gráfico que ya está almacenado en caché (#5403, gracias @Max17190).
  • Solución: extraer archivos de audio y video que se detectan pero no se extraen (el extracto sin cabeza no tiene paso de transcripción) ahora se informan en el resumen en lugar de desaparecer silenciosamente, coincidiendo con los otros avisos de omisión; no se fabrican nodos para ellos (#5076, gracias @ayushcodes10).
  • Solución: secciones El reintento de get_section ya no reutiliza el índice de búsqueda de trigramas del gráfico completo. El reintento se ejecutó contra una vista de subgrafo de networkx cuyo dictado .graph es el mismo objeto en el que se almacena en caché el índice, por lo que el reintento buscó identificadores obsoletos y fuera de sección y generó KeyError; la vista de reintento ahora obtiene sus propios metadatos de gráficos, lo que también elimina un peligro de corrupción del índice de gráficos compartidos para quienes llaman al servicio simultáneo (#5385, gracias @Deepjyoti-Sarmah).
  • Solución: servir el servidor MCP carga graph.json fuera del bucle de eventos, por lo que una recarga de gráfico grande ya no bloquea las solicitudes simultáneas; una solicitud durante una recarga recibe el gráfico actual y una recarga corrupta deja intacto el gráfico anterior (#5371, gracias @Deepjyoti-Sarmah).
  • Solución: actualizar un GRAPH_REPORT.md agrupado que se elimina mientras el gráfico permanece sin cambios se regenera en lugar de ser omitido por la puerta de no cambios; el gráfico en sí se deja con bytes idénticos (restaurado desde el caché de la partición), por lo que no hay una reconstrucción innecesaria (#5402, gracias @Max17190).
  • Solución: los nodos de imagen de consulta se degradan en la puntuación inicial junto con los documentos y artículos, por lo que una imagen rica en subtítulos ya no supera al código real para una consulta cuyos términos se repiten (#445, gracias @ayushcodes10).
  • Solución: exportar los nombres de archivo de exportación respetan el NAME_MAX del sistema de archivos de destino (probado mediante pathconf, no se supone que sea 255), por lo que graphify export obsidian/wiki/canvas ya no cancela con ENAMETOOLONG en sistemas de archivos que informan un límite inferior como eCryptfs (143); los nombres largos se truncan con un sufijo hash y los enlaces internos usan nombres abreviados (#2109, gracias @Synvoya).
  • Solución: las exportaciones de gráficos dirigidos de wiki ahora incluyen bordes entrantes, por lo que una auditoría de la comunidad ya no informa por debajo de la confianza (un borde AMBIGUO entrante podría ser invisible mientras la página dice "EXTRACTO 100%"). En las páginas de nodos divinos, los bordes entrantes están marcados como (incoming), por lo que una relación como calls no se lee al revés (#5369, gracias @sdivyanshu90).
  • Solución: config .graphifyrc ahora analiza demote_docs / query_demote_docs, por lo que un proyecto puede configurar la degradación del documento en el archivo rc en lugar de hacerlo únicamente a través del indicador CLI; un indicador explícito aún lo anula (#5290, gracias @debojyoti10CC).
  • Rendimiento: el recuento de superposición de comunidades de clúster durante una reconstrucción se calcula a partir de nodos compartidos en una sola pasada en lugar de intersectar cada par de comunidades, lo que convierte un paso O (comunidades al cuadrado) en uno lineal con resultados de bytes idénticos (#5382, gracias @Max17190).

graphify v0.9.118

A batch of extractor, resolution, serve, export, clustering and reporting fixes across fourteen community pull requests. The Objective-C, C and C# changes alter node/edge output, so the AST cache schema bumps (51 to 53) and the first build after upgrading re-extracts the affected languages; the other fixes need no rebuild.

  • Fix: csharp a local, parameter or field named partial, required, async, nint, nuint or with (contextual keywords) that tree-sitter-c-sharp mis-parses where a statement starts with it no longer derails the file; it is rewritten to its verbatim @name form before parsing (byte-length preserving), so the enclosing type and the members after it are kept instead of being silently dropped (#5043, thanks @ThatAblaze).
  • Fix: c a call through a struct function-pointer field (ops->run(), ops.run()) no longer fabricates a calls edge to a same-named free function; the field name is no evidence of the pointer's runtime target, so the guess is dropped. A plain direct call still resolves (#5410, thanks @sdivyanshu90).
  • Fix: objc an Objective-C method whose name folds onto a sibling's id within one @interface/@implementation/@protocol (a leading/trailing _ as in -setup/-_setup, or a case-only difference) gets its own salted node id instead of overwriting it; the declaration and definition of one method still share a single node (#5390, thanks @ayushcodes10).
  • Fix: go a struct field's owner type is scoped to its own package, so a field of a type whose name is declared in two packages binds to the right one and its member calls resolve instead of being dropped as ambiguous (#5408, thanks @azizur100389).
  • Fix: extract a Svelte import that comes through an export * barrel now resolves to the real defining module, matching plain .ts. The cross-file resolver was masking .vue but not .svelte, so the Svelte <script> imports were lost to a template parse error; chained barrels resolve and ambiguous re-exports fail closed. Run graphify extract . --force once to repair an already-cached graph (#5403, thanks @Max17190).
  • Fix: extract audio and video files that are detected but not extracted (headless extract has no transcription step) are now reported in the summary instead of silently vanishing, matching the other skip notices; no nodes are fabricated for them (#5076, thanks @ayushcodes10).
  • Fix: sections get_section's retry no longer reuses the full graph's trigram search index. The retry ran against a networkx subgraph view whose .graph dict is the same object serve caches the index on, so the retry searched stale, out-of-section ids and raised KeyError; the retry view now gets its own graph metadata, which also removes a shared-graph index-corruption hazard for concurrent serve callers (#5385, thanks @Deepjyoti-Sarmah).
  • Fix: serve the MCP server loads graph.json off the event loop, so a large graph reload no longer blocks concurrent requests; a request during a reload is served the current graph and a corrupt reload leaves the old graph intact (#5371, thanks @Deepjyoti-Sarmah).
  • Fix: update a clustered GRAPH_REPORT.md that is deleted while the graph is otherwise unchanged is regenerated instead of being skipped by the no-change gate; the graph itself is left byte-identical (restored from the partition cache) so there is no needless rebuild (#5402, thanks @Max17190).
  • Fix: query image nodes are demoted in seed scoring alongside documents and papers, so a caption-rich image no longer out-seeds real code for a query whose terms it happens to repeat (#445, thanks @ayushcodes10).
  • Fix: export export filenames honor the target filesystem's NAME_MAX (probed via pathconf, not assumed to be 255), so graphify export obsidian/wiki/canvas no longer aborts with ENAMETOOLONG on filesystems that report a lower limit such as eCryptfs (143); long names are truncated with a hash suffix and internal links use the shortened names (#2109, thanks @Synvoya).
  • Fix: wiki directed-graph exports now include incoming edges, so a community audit no longer under-reports confidence (an incoming AMBIGUOUS edge could be invisible while the page read "EXTRACTED 100%"). On god-node pages incoming edges are marked (incoming) so a relation like calls is not read backwards (#5369, thanks @sdivyanshu90).
  • Fix: config .graphifyrc now parses demote_docs / query_demote_docs, so a project can set doc demotion in the rcfile instead of only via the CLI flag; an explicit flag still overrides it (#5290, thanks @debojyoti10CC).
  • Perf: cluster community-overlap counting during a rebuild is computed from shared nodes in one pass instead of intersecting every pair of communities, turning an O(communities squared) step into a linear one with byte-identical results (#5382, thanks @Max17190).
