grafificar v0.9.113

  • Cambio: empaquetado el mínimo Python ahora es 3.11.5 (antes 3.11), y el tamiz de sopa está fijado a 4.1.1 para cada intérprete. Las versiones parcheadas de Soupsieve requieren 3.11.5, por lo que al elevar el piso se borran los avisos de Soupsieve abiertos (ReDoS y recursión/DoS polinomial en el analizador selector de CSS, alcanzado transitivamente a través de beautifulsoup4 en los extras opcionales svg/all/pdf). Las instalaciones en Python 3.11.0-3.11.4 siguen resolviendo en 0.9.112; todos los usuarios de 3.11.5 y superiores no se ven afectados (#5301, gracias @TPAteeq).
  • Solución: los métodos ruby de una clase o módulo cuyos nombres difieren solo por un _ inicial/final o por mayúsculas y minúsculas (_read_attribute/read_attribute, _where!/where!), incluidos aquellos en un class << self, obtienen identificadores de nodo distintos en lugar de que uno se trague al otro (#5292, gracias @rohit-jsfreaky).
  • Solución: lua las funciones de campo de tabla cuyos nombres difieren solo por un _ inicial/final (M._load/M.load, Runner:_start/Runner:start) obtienen identificadores de nodo distintos; M.f/M:f todavía nombra un campo (#5294, gracias @rohit-jsfreaky).
  • Solución: los miembros de scala cuyos nombres difieren solo por un _ inicial, un sufijo de establecimiento _= o un caso (_enter/enter, size/size_=, forEach/foreach), incluso en una clase y su objeto complementario, obtienen identificadores de nodo distintos (#5296, gracias @rohit-jsfreaky).
  • Solución: los defs de elixir cuyos nombres difieren solo por un _ inicial/final, un sufijo !/? o mayúsculas y minúsculas (_name/name, get/get!, __schema__/schema) obtienen identificadores de nodo distintos, por lo que una llamada get! ya no aterriza en get. (#5298, gracias @rohit-jsfreaky).
  • Solución: rust el argumento de tipo de rasgo de preludio (Celsius en impl From<Celsius> o un límite de T: Into<Celsius>) se lee como una referencia de argumento genérico en lugar de confundirse con el rasgo en sí, por lo que ya no emite un borde implements/inherits incorrecto (#5332, gracias @azeemshaik025).
  • Solución: go se mantiene una llamada de miembro cuando otro paquete en el corpus nombra un tipo de archivo hermano: el código auxiliar sin fuente en colisión se mueve a su propia identificación en lugar de salar la declaración real y dejar huérfanos los bordes de su método, lo que había descartado la llamada (#5304, gracias @Yi-111-a).
  • Solución: ruby un método escrito en línea después de un modificador de acceso (private def validate, private_class_method def self.audit) mantiene su membresía en la clase adjunta en lugar de emitirse como una función a nivel de archivo, por lo que las llamadas se resuelven en el método (#5310, gracias @Synvoya).
  • Solución: swift una llamada que es el último operando de una expresión de operador (base + bonus(), !isEmpty()), que la gramática analiza como el destinatario, se extrae en lugar de eliminarse (#5311, gracias @Synvoya).
  • Solución: kotlin una llamada bajo un operador de prefijo (!isReady(), -compute()) se extrae en lugar de descartarse, incluidos los prefijos apilados y !obj.ready() (#5312, gracias @Synvoya).
  • Solución: vbnet un parámetro con un valor predeterminado se cuenta como opcional independientemente del orden de los modificadores (ByVal Optional x As Integer = 0, ByRef Optional ...), por lo que la aridad del método y la resolución de sobrecarga son correctas (#5320, gracias @Deepjyoti-Sarmah).
  • Solución: cpp las identidades de inclusión se mantienen cuando el caché AST está en otra unidad distinta a la fuente (un caso de unidades cruzadas de Windows donde se generó os.path.relpath y cada archivo obtuvo una clave vacía), por lo que el plegado de declaración/definición aún funciona; la ruta normal de la misma unidad no ha cambiado (#5145, gracias @Ayushraj06-bit).
  • Solución: llm los reintentos de generación de etiquetas mantienen un mínimo de salida de 512 tokens, por lo que el pase de recuperación de una sola comunidad ya no se queda corto por debajo del lote del que se está recuperando; un GRAPHIFY_MAX_OUTPUT_TOKENS explícito aún anula (#2086, gracias @Synvoya).
  • Solución: ruby un include/prepend/extend de un módulo escrito dentro de un bloque class << self emite su borde mixes_in, en lugar de pasarse por alto porque solo se escanearon declaraciones directas del cuerpo de clase (#5317, gracias @Synvoya).
  • Solución: python una clase con una base parametrizada (class C(Base[T]), class D(Mapping[str, int])) emite el borde inherits al tipo base y se recorre para llamadas a métodos heredados, en lugar de descartarse y marcarse como opaca; un argumento genérico anidado, una base de llamadas y mod.Base[T] todavía no se tratan como padres (#5318, gracias @Synvoya).
  • Solución: tsconfig un tsconfig.json extends y el mapeo exacto de compilerOptions.paths se resuelven en la configuración/archivo escaneado real que nombran en lugar de un trozo colgante; se extiende un paquete que no es corpus, una ruta comodín y una extensión circular falla cerrada (#5223, gracias @Deepjyoti-Sarmah).
  • Solución: cpp una declaración directa de clase inalcanzable (una que no incluye la ruta de acceso) ya no bloquea el pliegue de la declaración de un miembro en su definición fuera de línea; Los casos genuinamente ambiguos (una plantilla o una segunda definición) aún permanecen separados (#5337, gracias @winesoft-namjin-yun).
  • Solución: extraer una importación que apunta a un encabezado involucrado en una colisión de ID ya no se redirecciona incondicionalmente a la variante de encabezado: el redireccionamiento está controlado por la familia de idiomas del archivo de importación, por lo que un Python import foo al lado de un foo.h/foo.py en colisión mantiene su ventaja en foo.py en lugar de eliminarse como entre idiomas (#5328, gracias @sdivyanshu90).
  • Solución: servir una consulta que es una identificación de nodo exacta se resuelve directamente en ese nodo en lugar de ser superada por un nodo diferente que comparte su ruta de origen tokenizada (#5343, gracias @Ayushraj06-bit). El esquema de caché AST aumenta a 49; Los cachés calientes vuelven a ejecutar las extracciones de Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python y TypeScript-config.

graphify v0.9.113

  • Change: packaging the minimum Python is now 3.11.5 (was 3.11), and soupsieve is pinned to 4.1.1 for every interpreter. soupsieve's patched releases require 3.11.5, so raising the floor clears the open soupsieve advisories (ReDoS and recursion/polynomial-DoS in the CSS selector parser, reached transitively through beautifulsoup4 in the optional svg/all/pdf extras). Installs on Python 3.11.0-3.11.4 keep resolving to 0.9.112; everyone on 3.11.5 and up is unaffected (#5301, thanks @TPAteeq).
  • Fix: ruby methods of one class or module whose names differ only by a leading/trailing _ or by case (_read_attribute/read_attribute, _where!/where!), including those in a class << self, get distinct node ids instead of one swallowing the other (#5292, thanks @rohit-jsfreaky).
  • Fix: lua table-field functions whose names differ only by a leading/trailing _ (M._load/M.load, Runner:_start/Runner:start) get distinct node ids; M.f/M:f still name one field (#5294, thanks @rohit-jsfreaky).
  • Fix: scala members whose names differ only by a leading _, a _= setter suffix, or case (_enter/enter, size/size_=, forEach/foreach), including across a class and its companion object, get distinct node ids (#5296, thanks @rohit-jsfreaky).
  • Fix: elixir defs whose names differ only by a leading/trailing _, a !/? suffix, or case (_name/name, get/get!, __schema__/schema) get distinct node ids, so a get! call no longer lands on get (#5298, thanks @rohit-jsfreaky).
  • Fix: rust a prelude trait's type argument (Celsius in impl From<Celsius> or a T: Into<Celsius> bound) is read as a generic-argument reference instead of being mistaken for the trait itself, so it no longer emits a wrong implements/inherits edge (#5332, thanks @azeemshaik025).
  • Fix: go a member call is kept when another package in the corpus names a sibling-file type: the colliding sourceless stub is moved to its own id instead of salting the real declaration and orphaning its method edges, which had dropped the call (#5304, thanks @Yi-111-a).
  • Fix: ruby a method written inline after an access modifier (private def validate, private_class_method def self.audit) keeps its membership of the enclosing class instead of being emitted as a file-level function, so calls to it resolve to the method (#5310, thanks @Synvoya).
  • Fix: swift a call that is the last operand of an operator expression (base + bonus(), !isEmpty()), which the grammar parses as the callee, is extracted instead of dropped (#5311, thanks @Synvoya).
  • Fix: kotlin a call under a prefix operator (!isReady(), -compute()) is extracted instead of dropped, including stacked prefixes and !obj.ready() (#5312, thanks @Synvoya).
  • Fix: vbnet a parameter with a default value is counted as Optional regardless of modifier order (ByVal Optional x As Integer = 0, ByRef Optional ...), so method arity and overload resolution are correct (#5320, thanks @Deepjyoti-Sarmah).
  • Fix: cpp include identities are kept when the AST cache is on another drive than the source (a Windows cross-drive case where os.path.relpath raised and every file got an empty key), so declaration/definition folding still works; the normal same-drive path is unchanged (#5145, thanks @Ayushraj06-bit).
  • Fix: llm label-generation retries keep a 512-token output floor, so the single-community recovery pass is no longer starved below the batch it is recovering from; an explicit GRAPHIFY_MAX_OUTPUT_TOKENS still overrides (#2086, thanks @Synvoya).
  • Fix: ruby an include/prepend/extend of a module written inside a class << self block emits its mixes_in edge, instead of being missed because only direct class-body statements were scanned (#5317, thanks @Synvoya).
  • Fix: python a class with a parameterized base (class C(Base[T]), class D(Mapping[str, int])) emits the inherits edge to the base type and is walked for inherited-method calls, instead of being dropped and marked opaque; a nested generic argument, a call base, and mod.Base[T] are still not treated as parents (#5318, thanks @Synvoya).
  • Fix: tsconfig a tsconfig.json extends and exact compilerOptions.paths mapping resolve to the real scanned config/file they name rather than a dangling stub; a non-corpus package extends, a wildcard path, and a circular extends fail closed (#5223, thanks @Deepjyoti-Sarmah).
  • Fix: cpp an unreachable class forward declaration (one no include path reaches) no longer blocks the fold of a member's declaration into its out-of-line definition; genuinely ambiguous cases (a template or a second definition) still stay separate (#5337, thanks @winesoft-namjin-yun).
  • Fix: extract an import that targets a header involved in an id collision is no longer unconditionally repointed to the header variant: the repoint is gated by the importing file's language family, so a Python import foo beside a colliding foo.h/foo.py keeps its edge to foo.py instead of being dropped as cross-language (#5328, thanks @sdivyanshu90).
  • Fix: serve a query that is an exact node id resolves straight to that node instead of being out-ranked by a different node that shares its tokenized source path (#5343, thanks @Ayushraj06-bit).

The AST cache schema is bumped to 49; warm caches re-run the affected Ruby, Lua, Scala, Elixir, Rust, Swift, Kotlin, VB.NET, Python and TypeScript-config extractions.
