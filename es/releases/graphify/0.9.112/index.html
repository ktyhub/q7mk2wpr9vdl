grafificar v0.9.112

  • Documentos: python el archivo README, sus traducciones, CONTRIBUCIÓN, LIBERACIÓN, la plantilla de informe de errores y los objetivos ruff/pyright ahora indican Python 3.11 como mínimo, coincidiendo con el piso que se envió en 0.9.111 (#5238, gracias @Deepanshu-Mehta; @Max17190 envió la misma solución en #5237).
  • Documentos: enlaza el enlace de configuración siempre activa en el archivo README y todas las traducciones apuntan directamente a docs.graphify.com/open-source/vibe-coding en lugar de realizar una redirección desde las guías antiguas/ruta siempre activa (#5261, gracias @SyedFahad7).
  • Solución: java cada método sobrecargado obtiene su propio nodo codificado por arity y firma borrada, en lugar de que todas las sobrecargas colapsen en un nodo que elimine miembros y desvíe llamadas; La coincidencia de anulación de affected ahora tiene en cuenta la aridad, por lo que un run(int) dividido no está vinculado a un supertipo run() por etiqueta, y las sobrecargas de métodos genéricos y de repositorios cruzados también se manejan (#5251, gracias @deba2k5). Las sobrecargas de la misma aridad y de tipo único todavía se vinculan a la primera declarada (reflejando el precedente de C# #4584); El envío de tipo argumento literal es un seguimiento. Los constructores sobrecargados todavía comparten un nodo.
  • Solución: ir un tipo de receptor simple (func (s Service) m()) se resuelve en su propio tipo de paquete en lugar de compararse con cada tipo con el mismo nombre en el corpus, por lo que dos paquetes que declaran cada uno un Service mantienen sus propios bordes de llamada de miembro en lugar de que ambos los pierdan debido a una fianza por ambigüedad (#5242, gracias @ayushcodes10).
  • Solución: rust una importación use crate::... se resuelve dentro de su propia caja en lugar de filtrarse a través de los límites de la caja al elemento del mismo nombre de otra caja en un espacio de trabajo de varias cajas; una importación de crate:: de una sola caja todavía se resuelve como antes (#5240, gracias @Max17190).
  • Solución: js un miembro this.x = function (params) {...} ya no fabrica un indirect_call falso cuando uno de sus parámetros oculta una función de corpus del mismo nombre utilizada en la posición del argumento; sus propios parámetros y nombres capturados desde el ámbito adjunto se tratan como enlaces locales, mientras que un nombre genuinamente independiente aún se resuelve (#5241, gracias @Max17190).
  • Solución: c una inclusión de ángulo calificada por directorio (#include <dir/header.h>) se resuelve en el archivo local coincidente, y los encabezados de biblioteca estándar (<stdio.h>, <functional>) se mantienen fuera del índice de alias para que un archivo de proyecto con el mismo nombre no se corrija en ellos; un encabezado local que comparte un nombre calificado de directorio aún se resuelve (#5218, gracias @Yi-111-a).
  • Corrección: sql una tabla nombrada con letras no ASCII cuya gramática se colapsa a un _ desnudo ya no crea un nodo con una identificación vacía o un borde para una identificación vacía; en su lugar, se elimina la ventaja falsa (#5250, gracias @grbr2010).
  • Solución: dedup una palabra derivada de prefijo se mantiene separada de su palabra base, por lo que los pares de antónimos y prefijos (synchronous/asynchronous, cyclic/acyclic, reload/load) ya no se unen a través de la fusión de etiquetas difusas, mientras que las inflexiones genuinas como handler/handlers aún se fusionan (#5239, gracias @Deepanshu-Mehta).
  • Solución: construir la tabla familiar del protector de borde entre idiomas ya no se deriva de la del extractor: 37 extensiones que no tenían entrada familiar (por lo que nunca se eliminó una colisión coincidente de nombres entre idiomas) se concilian y una prueba falla CI si las dos tablas divergen nuevamente (#5247, gracias @Yi-111-a).
  • Solución: instalar graphify claude install escribe su sección en el archivo que Claude Code realmente lee. Claude Code lee el AGENTS.md de un proyecto solo cuando no existe ningún CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) en el proyecto o en cualquier directorio encima de él, por lo que la creación de un CLAUDE.md al lado de un AGENTS.md ocultó silenciosamente ese AGENTS.md de Claude Code. La instalación ahora se dirige a un CLAUDE.md/.claude/CLAUDE.md existente, si está presente; de ​​lo contrario, a un AGENTS.md/.claude/AGENTS.md existente; de ​​lo contrario, a un CLAUDE.md nuevo como antes; la desinstalación es simétrica (#5277, gracias @andrebrait).
  • Solución: instalar graphify install se niega a sobrescribir una configuración de Kilo existente que no puede analizar, en lugar de reemplazarla silenciosamente con un archivo exclusivo de Graphify y perder la configuración del usuario; una configuración válida o faltante aún se fusiona como antes (#5265, gracias @divya0795).
  • Solución: analizar los ciclos de importación de dos archivos se enumeran antes de que se llene el límite de enumeración, por lo que en un gráfico con muchos ciclos más largos los ciclos más ajustados (dos archivos mutuos) ya no se eliminan; el listado ahora también es determinista entre ejecuciones (#5267, gracias @divya0795).
  • Solución: extraer la protección net-shrink no está activada para una fuente que no tiene nada que proteger (una que nunca produjo ningún nodo guardado, por ejemplo, un archivo cuya gramática adicional opcional no está instalada), por lo que dicha fuente ya no bloquea una extracción posterior que reduce legítimamente el gráfico; una fuente que sí tenía registros guardados todavía arma a la guardia (#5245, gracias @ayushcodes10).
  • Solución: construir doblar un documento gemelo Markdown preserva la estructura del superviviente: un nodo de encabezado real ya no se confunde con el gemelo semántico de la página y el nodo de la página (con su portada y bordes contains) se conserva, mientras que los gemelos semánticos genuinos aún se pliegan (#5272, gracias @sdivyanshu90).
  • Solución: construir alias de corpus con enlaces simbólicos se eliminan de forma independiente: excluir o eliminar un alias de enlace simbólico ya no elimina también su destino o un alias hermano que se resuelve en el mismo archivo, porque ahora se eliminan las claves coincidentes en la ruta del corpus en lugar del destino físico resuelto (#5273, gracias @sdivyanshu90).
  • Solución: pascal una unidad que la gramática cuidador de árboles no puede analizar de extremo a extremo (por ejemplo, una con un literal de cadena SQL escapado) se recupera mediante un reintento enmascarado que preserva la longitud de bytes, en lugar de no generar nodos; el reintento se ejecuta solo cuando el análisis normal falla y se acepta solo si es estrictamente más saludable, por lo que las unidades que ya se analizan no cambian (#5264, gracias @patrykseksymfonia).
  • Solución: pascal una clase base se resuelve en su declaración real en la unidad en la que está declarada, en lugar de un código auxiliar que coincida con la convención de nombre de archivo, por lo que el borde inherits y las llamadas heredadas a través de él se resuelven en todos los archivos (#5280, gracias @patrykseksymfonia).
  • Solución: pascal una llamada a través de una variable de objeto global (DM.Open, el modismo del módulo de datos de Delphi) se resuelve en el miembro de tipo de la variable: el extractor registra globales a nivel de unidad, campos por clase y sombras por rutina, y la resolución vincula la llamada calificada cerrada por falla a través de la cláusula de usos, dejándola sin resolver cuando un campo, local o global de tipo matriz oculta el nombre (#3101, gracias @patrykseksymfonia).
  • Hazaña: delphi un formulario (.dfm/.lfm) está vinculado a la unidad que lo implementa: la clase de formulario y cada trozo de OnClick = Handler obtienen una ventaja INFERIDA references para la clase y el método reales en el hermano .pas, emparejados por nombre base y una búsqueda única de clase/método (#5281, gracias @patrykseksymfonia). El esquema de caché AST aumenta a 48; Los cachés calientes vuelven a ejecutar las extracciones Go, Java, JS/TS, C/C++, SQL y Pascal afectadas.

original en inglés / English original

graphify v0.9.112

  • Docs: python the README, its translations, CONTRIBUTING, RELEASING, the bug-report template and the ruff/pyright targets now state Python 3.11 as the minimum, matching the floor that shipped in 0.9.111 (#5238, thanks @Deepanshu-Mehta; @Max17190 sent the same fix in #5237).
  • Docs: links the Always-on setup link in the README and all translations points straight at docs.graphify.com/open-source/vibe-coding instead of going through a redirect from the old guides/always-on path (#5261, thanks @SyedFahad7).
  • Fix: java each overloaded method gets its own node keyed by arity and erased signature, instead of all overloads collapsing into one node that dropped members and misrouted calls; affected override-matching is now arity-aware so a split run(int) is not tied to a supertype run() by label, and cross-repo and generic-method overloads are handled too (#5251, thanks @deba2k5). Same-arity, type-only-distinct overloads still bind to the first declared one (mirroring the C# precedent #4584); literal-argument-type dispatch is a follow-up. Overloaded constructors still share one node.
  • Fix: go a bare receiver type (func (s Service) m()) resolves to its own package's type instead of being matched against every same-named type in the corpus, so two packages each declaring a Service keep their own member-call edges rather than both losing them to an ambiguity bail (#5242, thanks @ayushcodes10).
  • Fix: rust a use crate::... import resolves inside its own crate instead of leaking across crate boundaries to another crate's same-named item in a multi-crate workspace; a single-crate crate:: import still resolves as before (#5240, thanks @Max17190).
  • Fix: js a this.x = function (params) {...} member no longer fabricates a false indirect_call when one of its parameters shadows a same-named corpus function used in argument position; its own params and names captured from the enclosing scope are treated as local bindings, while a genuinely unbound name still resolves (#5241, thanks @Max17190).
  • Fix: c a directory-qualified angle include (#include <dir/header.h>) resolves to the matching local file, and standard-library headers (<stdio.h>, <functional>) are kept off the alias index so a same-named project file is not healed onto them; a local header that shares a directory-qualified name still resolves (#5218, thanks @Yi-111-a).
  • Fix: sql a table named with non-ASCII letters that the grammar collapses to a bare _ no longer mints a node with an empty id or an edge to an empty id; the bogus edge is dropped instead (#5250, thanks @grbr2010).
  • Fix: dedup a prefix-derived word is kept apart from its base word, so antonym and prefixed pairs (synchronous/asynchronous, cyclic/acyclic, reload/load) no longer fold together through the fuzzy label merge, while genuine inflections like handler/handlers still merge (#5239, thanks @Deepanshu-Mehta).
  • Fix: build the cross-language edge guard's family table no longer drifts from the extractor's: 37 extensions that had no family entry (so a coincidental cross-language name collision was never dropped) are reconciled, and a test fails CI if the two tables diverge again (#5247, thanks @Yi-111-a).
  • Fix: install graphify claude install writes its section to the file Claude Code actually reads. Claude Code reads a project's AGENTS.md only when no CLAUDE.md (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md) exists in the project or any directory above it, so creating a CLAUDE.md beside an AGENTS.md silently hid that AGENTS.md from Claude Code. The install now targets an existing CLAUDE.md/.claude/CLAUDE.md if present, else an existing AGENTS.md/.claude/AGENTS.md, else a new CLAUDE.md as before; uninstall is symmetric (#5277, thanks @andrebrait).
  • Fix: install graphify install refuses to overwrite an existing Kilo config it cannot parse, instead of silently replacing it with a graphify-only file and losing the user's settings; a valid or missing config still merges as before (#5265, thanks @divya0795).
  • Fix: analyze two-file import cycles are listed before the enumeration cap fills, so on a graph with many longer cycles the tightest (mutual two-file) cycles are no longer dropped; the listing is also now deterministic across runs (#5267, thanks @divya0795).
  • Fix: extract the net-shrink guard is not armed for a source that has nothing to protect (one that never produced any saved nodes, e.g. a file whose optional grammar extra is not installed), so such a source no longer blocks a later extract that legitimately shrinks the graph; a source that did have saved records still arms the guard (#5245, thanks @ayushcodes10).
  • Fix: build folding a Markdown document twin preserves the survivor's structure: a real heading node is no longer mistaken for the page's semantic twin and the page node (with its frontmatter and contains edges) is kept, while genuine semantic twins still fold (#5272, thanks @sdivyanshu90).
  • Fix: build symlinked corpus aliases are pruned independently: excluding or deleting one symlink alias no longer also drops its target or a sibling alias that resolves to the same file, because prune matching now keys on the corpus path rather than the resolved physical target (#5273, thanks @sdivyanshu90).
  • Fix: pascal a unit the tree-sitter grammar cannot parse end to end (for example one with an escaped SQL string literal) is recovered through a byte-length-preserving masked retry, instead of yielding no nodes; the retry runs only when the normal parse errored and is accepted only if strictly healthier, so units that already parse are unchanged (#5264, thanks @patrykseksymfonia).
  • Fix: pascal a base class resolves to its real declaration in the unit it is declared in, instead of a stub matched by filename convention, so the inherits edge and the inherited calls through it resolve across files (#5280, thanks @patrykseksymfonia).
  • Fix: pascal a call through a global object variable (DM.Open, the Delphi data-module idiom) resolves to the variable's type member: the extractor records unit-level globals, per-class fields and per-routine shadows, and resolution binds the qualified call fail-closed through the uses-clause, leaving it unresolved when a field, local or array-typed global shadows the name (#3101, thanks @patrykseksymfonia).
  • Feat: delphi a form (.dfm/.lfm) is linked to the unit that implements it: the form class and each OnClick = Handler stub get an INFERRED references edge to the real class and method in the sibling .pas, paired by base name and a unique class/method lookup (#5281, thanks @patrykseksymfonia).

The AST cache schema is bumped to 48; warm caches re-run the affected Go, Java, JS/TS, C/C++, SQL and Pascal extractions.
