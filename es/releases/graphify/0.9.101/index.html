grafificar v0.9.101

grafificar 0.9.101

Liberación de precisión de resolución y corrección de caché en C++, Rust, Python, Go, la protección contra escritura de compilación y reconstrucciones incrementales. ###C++

  • Una llamada de miembro x.m() se vincula por el tipo de receptor, ahora escrito a partir de parámetros de función y campos de clase y no solo locales (void render(Base* b){ b->draw(); } se resuelve en Base::draw); un receptor ambiguo o sin tipo mantiene su enlace en el archivo (#3215, #4946).
  • Una definición fuera de línea o con encabezado dividido se adjunta al propietario único cuyo archivo de clase está en su conjunto de inclusión, en lugar de vincularse a una función no relacionada con el mismo nombre; Los propietarios ambiguos fallan cerrados (#4916, #4920).
  • Un valor invocable local (una lambda o std::function) se mantiene fuera de la resolución de llamadas globales mediante tiempos de vida de enlace de rango de bytes, por lo que ya no crea una llamada INFERRED espuria a una global del mismo nombre; sobrevive una llamada global legítima posterior (#4917, #4921).
  • Una referencia de alias de tipo (using Foo = Bar; y luego Foo x;) se vincula mediante ortografía exacta y un alias salado mantiene su propio borde contains (#4951).

Rust

  • Una llamada calificada por módulo (crate::b::helper(), super::m::f()) se resuelve a través de una resolución entre archivos verificada por calificador, permaneciendo dentro de la caja de la persona que llama (#2135, #4944).
  • Una llamada escrita dentro de los argumentos de una macro de expresión (println!("{}", f()), vec![g()]) está vinculada y conectada a una lista de permitidos, de modo que los cuerpos de macro_rules! y los DSL personalizados se dejan en paz (#4945).

Python / Ir

  • Una llamada simple dentro de un método ya no se vincula automáticamente a un método con el mismo nombre; se resuelve en la función importada o a nivel de módulo que nombra (#4933).
  • Las importaciones se resuelven en paquetes de espacio de nombres PEP 420 divididos en múltiples raíces src/ (#4929).
  • Un valor del método Go alcanzado a través de un campo receptor se vincula como indirect_call (#1566, #4931).
  • Un inicializador var a nivel de paquete Go hace referencia a los tipos que nombra (#2360, #4932).

Construir/caché/reconstruir/ver

  • La protección contra escritura ya no rechaza un gráfico saludable cuando la entidad desduplicada convierte un nodo guardado en un gemelo superviviente; aún se rechaza una pérdida genuina (#4940, #4952).
  • La evidencia de archivos semánticos de origen independiente sobrevive al pliegue en un nodo propio de archivo AST; Los fantasmas de mención ordinarios INFERRED aún se pliegan para que los gráficos no acumulen duplicados (n.° 4896, n.° 4927).
  • El índice de alias de raíz de archivo solo vuelve a vincular un borde cuando el archivo del borde y el destino del alias comparten una familia de idiomas (#4949).
  • Las claves de caché mantienen su caso escrito, por lo que README.md y readme.md ya no chocan, y los archivos hash/conteo de palabras se abren a través de os_long_path (#4925, #4937).
  • Un gráfico --code-only permanece como código únicamente en las reconstrucciones de gancho, update y reloj (#4923, #4939).
  • Una reconstrucción ya no espera eternamente cuando msvcrt.locking no es compatible (#4924, #4926).
  • Una conciliación completa desaloja los registros de origen de un árbol de trabajo git vinculado excluido (#4919).
  • Las actualizaciones exclusivas de AST conservan la evidencia semántica entre archivos cuyo ID de nodo choca con una definición de código (#4950).
  • Un archivo dividido se almacena en caché solo una vez que cada segmento se haya realizado correctamente y se haya ensamblado en orden de fragmentos (#4943, #4947). El esquema de caché AST aumenta a 36; Los cachés calientes vuelven a ejecutar las extracciones afectadas. graphify v0.9.101

graphify 0.9.101

Resolution-accuracy and cache-correctness release across C++, Rust, Python, Go, the build write guard, and incremental rebuilds.

C++

  • A member call x.m() binds by the receiver's type, now typed from function parameters and class fields and not only locals (void render(Base* b){ b->draw(); } resolves to Base::draw); an untyped or ambiguous receiver keeps its in-file binding (#3215, #4946).
  • An out-of-line or split-header definition attaches to the unique owner whose class file is in its include set, instead of cross-binding to an unrelated same-named function; ambiguous owners fail closed (#4916, #4920).
  • A local callable value (a lambda or std::function) is kept out of global call resolution by byte-range binding lifetimes, so it no longer mints a spurious INFERRED call to a same-named global; a later legitimate global call survives (#4917, #4921).
  • A type-alias reference (using Foo = Bar; then Foo x;) binds by exact spelling and a salted alias keeps its own contains edge (#4951).

Rust

  • A module-qualified call (crate::b::helper(), super::m::f()) resolves through qualifier-verified cross-file resolution, staying inside the caller's crate (#2135, #4944).
  • A call written inside an expression macro's arguments (println!("{}", f()), vec![g()]) is linked, gated to an allowlist so macro_rules! bodies and custom DSLs are left alone (#4945).

Python / Go

  • A bare call inside a method no longer self-binds to a same-named method; it resolves to the imported or module-level function it names (#4933).
  • Imports resolve across PEP 420 namespace packages split over multiple src/ roots (#4929).
  • A Go method value reached through a receiver field is linked as an indirect_call (#1566, #4931).
  • A Go package-level var initialiser references the types it names (#2360, #4932).

Build / cache / rebuild / watch

  • The write guard no longer refuses a healthy graph when entity dedup folds a saved node into a surviving twin; a genuine loss is still refused (#4940, #4952).
  • Independently sourced semantic file evidence survives a fold into an AST file-self node; ordinary INFERRED mention ghosts still fold so graphs do not accumulate duplicates (#4896, #4927).
  • The file-stem alias index only rebinds an edge when the edge's file and the alias target share a language family (#4949).
  • Cache keys keep their written case so README.md and readme.md no longer collide, and hashed/word-count files are opened through os_long_path (#4925, #4937).
  • A --code-only graph stays code-only across hook, update and watch rebuilds (#4923, #4939).
  • A rebuild no longer waits forever when msvcrt.locking is unsupported (#4924, #4926).
  • A full reconcile evicts source records for an excluded linked git worktree (#4919).
  • AST-only updates preserve cross-file semantic evidence whose node id collides with a code definition (#4950).
  • A sliced file is cached only once every slice has succeeded and is assembled in chunk order (#4943, #4947).

The AST cache schema is bumped to 36; warm caches re-run the affected extractions.

Thanks to @nothariharan, @Deepjyoti-Sarmah, @azizur100389, @andrebrait, @ayushcodes10, @madhusudanpatnaik, @Ethan-Ethan-Ethan and @AndresDiagoM.
