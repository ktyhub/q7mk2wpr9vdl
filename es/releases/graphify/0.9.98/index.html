grafificar v0.9.98

0.9.98 (2026-10-30)

  • Solución: compilación cuando los bordes duplicados de la misma relación colapsan, la procedencia de la copia perdedora (confianza más débil) se mantiene en una lista also_seen en el borde superviviente en lugar de descartarse, por lo que la evidencia más débil no se pierde silenciosamente; el campo está serializado en graph.json y es idempotente en todas las reconstrucciones (#4881, #4891, gracias @SyedFahad7).
  • Solución: csharp un nodo de método C# está etiquetado con su tipo propietario (MyClass.Method) en lugar de un Method simple, por lo que los métodos con el mismo nombre entre tipos se pueden distinguir; Los identificadores de nodo y los bordes no cambian (solo se muestra la etiqueta) (#4883, #4889, gracias @SyedFahad7).
  • Hazaña: ruta graphify path y la salida de la ruta más corta de MCP informan la confianza general de la ruta como el salto más débil (nivel de confianza más bajo, luego puntuación más baja), con una línea de resumen que nombra ese salto (#4885, #4892, gracias @SyedFahad7).
  • Solución: ruta un punto final escrito Type.Member se resuelve en el nodo miembro, no en el tipo contenedor, por lo que graphify path "Exporter.Run" "PdfReport.Build" encuentra la ruta de llamada real; los nombres exactos y los nombres de archivos siguen ganando primero, y un Type.Member cuyo miembro no existe falla y se cierra (#4884, #4893, gracias @SyedFahad7).
  • Solución: extraer los identificadores de archivos y los identificadores por declaración se mantienen distintos, por lo que una declaración de nivel superior cuyo nombre coincida con su archivo (por ejemplo, class Js en a.js) ya no se elimina silenciosamente en una colisión de identificadores; las referencias entre archivos se vinculan a la identificación declarada (#4854, #4857, gracias @Deepjyoti-Sarmah).
  • Solución: dedup cuando una mención de documento entre archivos y un nodo AST chocan en una identificación de definición, el nodo AST mantiene la identificación en lugar de descartarse, mientras que los casos de enriquecimiento del mismo archivo, gemelos de extensión y definidor único se dejan como están (#4859, #4872, gracias @TanmayShah29; enfoque duplicado en #4871 por @ayushcodes10).
  • Solución: compilar un ciclo de importación de dos archivos (a importa b, b importa a) se informa en la compilación no dirigida predeterminada, y el sello se borra correctamente en reconstrucciones incrementales/de observación, por lo que una importación eliminada ya no deja un ciclo obsoleto (#4839, #4841, gracias @Mpasha17; enfoque duplicado en #4852 por @legendteddy).
  • Solución: extraer una importación JS/TS relativa que lleva un sufijo ?query o #fragment (./mod.js?v=1) se resuelve en el módulo real en lugar de en un nodo fantasma; Las importaciones del nodo #subpath no se modifican (#4860, #4876, gracias @Jitendarmahara; enfoque duplicado en #4869 por @mirzasnowy).
  • Solución: go un receptor vinculado con var x = T{} o var x = &T{} (un literal compuesto) se escribe como T, que coincide con el formulario x := T{}, por lo que su miembro llama a resolver (#4843, gracias @ayushcodes10).
  • Solución: verilog un constructor de clase SystemVerilog (function new(...), que no tiene tipo de retorno) obtiene su propio nodo, borde method y referencias de tipo de parámetro (#4848, gracias @ayushcodes10).
  • Solución: powershell using module/using assembly elimina una extensión de archivo real (Helpers.psm1 a helpers) pero mantiene un nombre de módulo con puntos sin extensión intacta (Az.Accounts) (#4847, gracias @ayushcodes10).
  • Solución: solidez un conjunto using {a, b} for T de función libre emite bordes uses para cada función nombrada, no solo el formulario using Lib for T de biblioteca única (#4846, gracias @ayushcodes10).
  • Solución: commonlisp un defclass cuya superclase se define más adelante en el mismo archivo se vincula a ese nodo local en lugar de crear un código auxiliar sin fuente (#4845, gracias @ayushcodes10).
  • Solución: pascal Los bloques de componentes de formulario inherited y inline (.lfm/.dfm) se reconocen, por lo que un bloque object posterior mantiene su padre correcto en lugar de volver a asignarlo a una pila de anidamiento corrupta (#4844, gracias @ayushcodes10).
  • Solución: servir cuando dos nodos se vinculan en una búsqueda y difieren solo en mayúsculas y minúsculas, el que está escrito exactamente como se consulta gana (los demás permanecen accesibles en un nivel inferior) en lugar de que cada ortografía se rechace por ser ambigua (#4870, gracias @nothariharan).
  • Solución: exportar las claves de exportación de texto cifrado MERGE en la identificación del nodo estable y establece la etiqueta por separado, por lo que volver a importar después de un cambio de etiqueta actualiza el nodo en lugar de crear un duplicado (#4878, gracias @oleksii-tumanov).
  • Solución: pdf la caché de texto convertido está codificada en la ruta de origen resuelta, por lo que dos archivos PDF con el mismo nombre relativo en diferentes raíces no se envenenan entre sí dentro de un proceso (#4851, gracias @xunguangzlj-cloud).

graphify v0.9.98

0.9.98 (2026-10-30)

  • Fix: build when duplicate same-relation edges collapse, the losing (weaker-confidence) copy's provenance is kept in an also_seen list on the surviving edge instead of being discarded, so the weaker evidence is not silently lost; the field is serialized to graph.json and is idempotent across rebuilds (#4881, #4891, thanks @SyedFahad7).
  • Fix: csharp a C# method node is labelled with its owning type (MyClass.Method) instead of a bare Method, so same-named methods across types are distinguishable; node ids and edges are unchanged (display label only) (#4883, #4889, thanks @SyedFahad7).
  • Feat: path graphify path and the MCP shortest-path output report the overall path confidence as the weakest hop (lowest confidence tier, then lowest score), with a summary line naming that hop (#4885, #4892, thanks @SyedFahad7).
  • Fix: path an endpoint written Type.Member resolves to the member node, not the containing type, so graphify path "Exporter.Run" "PdfReport.Build" finds the real call route; exact names and file names still win first, and a Type.Member whose member does not exist fails closed (#4884, #4893, thanks @SyedFahad7).
  • Fix: extract file ids and per-declaration ids are kept distinct, so a top-level declaration whose name matches its file (for example class Js in a.js) is no longer silently dropped on an id collision; cross-file references bind to the declared id (#4854, #4857, thanks @Deepjyoti-Sarmah).
  • Fix: dedup when a cross-file document mention and an AST node collide on a defining id, the AST node keeps the id instead of being dropped, while same-file enrichment, extension twins and single-definer cases are left as-is (#4859, #4872, thanks @TanmayShah29; duplicate approach in #4871 by @ayushcodes10).
  • Fix: build a two-file import cycle (a imports b, b imports a) is reported in the default undirected build, and the stamp is cleared correctly on incremental/watch rebuilds so a dropped import no longer leaves a stale cycle (#4839, #4841, thanks @Mpasha17; duplicate approach in #4852 by @legendteddy).
  • Fix: extract a relative JS/TS import carrying a ?query or #fragment suffix (./mod.js?v=1) resolves to the real module instead of a phantom node; Node #subpath imports are left untouched (#4860, #4876, thanks @Jitendarmahara; duplicate approach in #4869 by @mirzasnowy).
  • Fix: go a receiver bound with var x = T{} or var x = &T{} (a composite literal) is typed as T, matching the x := T{} form, so its member calls resolve (#4843, thanks @ayushcodes10).
  • Fix: verilog a SystemVerilog class constructor (function new(...), which has no return type) gets its own node, method edge and parameter-type references (#4848, thanks @ayushcodes10).
  • Fix: powershell using module/using assembly drops a real file extension (Helpers.psm1 to helpers) but keeps a dotted module name with no extension intact (Az.Accounts) (#4847, thanks @ayushcodes10).
  • Fix: solidity a free-function using {a, b} for T set emits uses edges for each named function, not just the single-library using Lib for T form (#4846, thanks @ayushcodes10).
  • Fix: commonlisp a defclass whose superclass is defined later in the same file binds to that local node instead of minting a sourceless stub (#4845, thanks @ayushcodes10).
  • Fix: pascal inherited and inline form component blocks (.lfm/.dfm) are recognised, so a later object block keeps its correct parent instead of being re-parented by a corrupted nesting stack (#4844, thanks @ayushcodes10).
  • Fix: serve when two nodes tie in a lookup and differ only by case, the one spelled exactly as queried wins (the others stay reachable one tier down) instead of every spelling being refused as ambiguous (#4870, thanks @nothariharan).
  • Fix: export the Cypher text export keys MERGE on the stable node id and sets the label separately, so re-importing after a label change updates the node instead of creating a duplicate (#4878, thanks @oleksii-tumanov).
  • Fix: pdf the converted-text cache is keyed on the resolved source path, so two PDFs with the same relative name in different roots do not poison each other within one process (#4851, thanks @xunguangzlj-cloud).
