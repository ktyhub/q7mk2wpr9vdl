grafificar v0.9.97

0.9.97 (27/10/2026)

  • Seguridad: redacción racional la redacción de credenciales para etiquetas racionales se mueve a un único punto de bloqueo previo al caché (_redact_rationale_labels dentro de _safe_extract), por lo que ningún extractor puede omitirla, y ahora cubre más formas de fuga: información de usuario URL con un usuario vacío o con //@ en la contraseña, cuerpos de clave privada PEM, tokens pegados al texto circundante por _ (por ejemplo, ghp_...), Slack xoxe- tokens de actualización, JWT cortos y cadenas de documentos Common Lisp que anteriormente creaban etiquetas sin redactar. Las cadenas benignas (hashes, prosa sk-, URL sin información de usuario) se dejan en paz (#4647, gracias @0xkaushik-ai).
  • Seguridad: deps anyio está reducido a >=4.14.2 en el extra mcp, por encima de CVE-2026-63374 (una omisión de validación de nombre de host IDNA 2003 vs 2008 que permite que un MITM en un dominio no ASCII presente un certificado para un host ASCII diferente, CVSS 9.3). anyio es solo una dependencia transitiva y el archivo de bloqueo ya resuelve 4.15.1, por lo que este es un piso para evitar que una re-resolución futura retroceda.
  • Solución: markdown análisis de encabezados ATX por CommonMark: una ejecución final de # no es parte del texto del encabezado (## Setup ## es "Configuración"), se permiten hasta tres espacios de sangría (cuatro es un bloque de código con sangría) y una línea de solo hash como ## ## no genera ningún nodo (#4790, #4791, gracias @jaimemartinez).
  • Solución: rebajas los bloques de código cercados se rastrean según las reglas de CommonMark (comillas invertidas y tildes, cadenas de información, longitud cercana coincidente), por lo que una línea que parece un encabezado dentro de una cerca ya no se filtra como estructura, y un encabezado después de un bloque ~~~ que contiene una línea ``` ya no se pierde (#4787, #4788, gracias @jaimemartinez).
  • Solución: yaml la extracción estructural lee el árbol de nodos compuesto, por lo que las claves llevan su ortografía escrita y su propia línea de origen en lugar de aterrizar todas en la línea 1, y las claves simples YAML 1.1 como on/off/yes/no ya no están plegadas a booleanos (se extrae un bloque de flujo de trabajo on:, no se convierte en un nodo True) (#4784, #4785, gracias @jaimemartinez).
  • Solución: razor las interfaces @implements de un componente se extraen como bordes implements en lugar de eliminarse silenciosamente (#4820, gracias @ayushcodes10).
  • Solución: terraform un bloque de proveedor con alias obtiene su propio nodo calificado con alias (por lo que dos bloques provider "aws" ya no colapsan en uno y pierden atributos), y una referencia provider = aws.west se resuelve en él en lugar de colgar; un local literalmente llamado provider ya no se malinterpreta (#4819, gracias @ayushcodes10).
  • Solución: los párrafos cobol que siguen a un END PROGRAM anidado se vuelven a adjuntar al programa adjunto en lugar de apegarse al anidado, a través de una pila de programas (#4824, gracias @ayushcodes10).
  • Solución: blade una directiva wire:click vincula el nombre del método simple: los modificadores punteados (wire:click.prevent="submit") coinciden, los argumentos de llamada se eliminan del nombre (deleteItem(5) vincula deleteItem) y una acción mágica con el prefijo $ no genera ningún borde fabricado (#4823, gracias @ayushcodes10).
  • Solución: pascal un record se reconoce como un tipo con sus propios métodos en el respaldo de expresiones regulares (la ruta predeterminada sin el extra opcional pascal), que coincide con la ruta del cuidador del árbol; Los miembros de operator también se extraen (#4825, gracias @ayushcodes10).
  • Solución: vbnet se extrae una declaración Operator como miembro de su clase del tipo operator y su cuerpo se recorre para las llamadas, por lo que una llamada de ayuda dentro de un operador ya no desaparece (#4821, gracias @ayushcodes10).
  • Solución: fortran a call se resuelve en la subrutina que realmente nombra en lugar de un objetivo con el nombre del archivo de llamada (que nunca se resolvió), usando el propio modismo de código auxiliar entre archivos del extractor (#4795, gracias @ayushcodes10).
  • Solución: cli graphify query --help/-h (y ahora graphify explain --help/-h) sin nada más imprime el uso en lugar de ejecutar una consulta literal para el texto "--help"; una pregunta más larga que simplemente contiene "--help" como subcadena todavía se ejecuta como consulta (#4830, gracias @curl-man).
  • Solución: js una función anidada (interna) ya no se filtra en el mapa de nombres de todo el archivo, por lo que una llamada en otra parte del archivo se vincula a la función de nivel superior de ese nombre en lugar de a una interna que no puede ver; Los ámbitos de recursividad, sombreado y hermanos se resuelven correctamente (porta el esquema de alcance Python a JS/TS) (#4767, gracias @smngvlkz).
  • Solución: ocaml se extraen todos los enlaces en un module ... and ... o class ... and ... con cadena and, no solo el primero, por lo que los enlaces posteriores ya no se eliminan silenciosamente; cada uno lleva su propia línea fuente (#4822, gracias @ayushcodes10).
  • Solución: verilog un método task de clase SystemVerilog se modela como uno function (su propio nodo, borde method y referencias de tipo de parámetro), y una variable local de tarea ya no se filtra como una referencia de campo falsa en la clase (#4774, gracias @ayushcodes10).
  • Solución: compilar un borde sin relation se elimina en lugar de persistir, tanto en la ruta de escritura de compilación como en la de --no-cluster sin procesar, y el plegado de alias (relationship a relation) se ejecuta antes de la verificación (#4810, gracias @legendteddy; el reproductor también se presenta como #4826 por @sunhouy).
  • Solución: compilación la protección contra el encogimiento cuenta un nodo de mención de documento guardado que se pliega en su archivo AST gemelo al recargar como presente, no perdido, por lo que una escritura solo en clúster ya no se rechaza cuando en realidad no se perdió nada (#4778, #4779, gracias @AndresDiagoM).
  • Solución: detecta un árbol de trabajo de git vinculado cuyo pago principal se resuelve dentro de la raíz del escaneo se elimina, por lo que un árbol de trabajo hermano ya no se indexa como una segunda copia completa del repositorio (#4683, #4833, gracias @barlowa124; trabajo duplicado en #4685 por @AndresDiagoM).
  • Solución: resolución un comentario en línea en un globo pnpm-workspace se elimina según las reglas YAML, y un globo que Path.glob rechaza (un componente ** o un patrón absoluto) se omite con una advertencia en lugar de bloquear toda la ejecución de extract (#4681, #4687, gracias @Deepjyoti-Sarmah).
  • Solución: informar un centro comunitario [[wikilink]] pasa por el mismo export._obsidian_safe_stem que usa la exportación, por lo que el enlace coincide con el archivo que la exportación realmente escribe en lugar de colgar (#4696, gracias @ayushcodes10).
  • Solución: wiki una comunidad reetiquetada solo con letras mayúsculas conserva su artículo en lugar de que el barrido elimine el archivo que la ejecución acaba de escribir; en un sistema de archivos que distingue entre mayúsculas y minúsculas, el gemelo en minúscula obsoleto se desvincula en lugar de cambiarse el nombre sobre el archivo nuevo (lo que restauraría silenciosamente el cuerpo anterior) (#4508, #4798, gracias @dupeisen).
  • Solución: los verbos de relleno consulta get/gets/got/getting se eliminan de los términos de consulta (como los work/works existentes), por lo que un centro de marco denominado "Obtener" no se incorpora como semilla BFS mediante un bono de coincidencia exacta; Las búsquedas de nodos para un Get literal aún se resuelven (#4686, gracias @AndresDiagoM).

graphify v0.9.97

0.9.97 (2026-10-27)

  • Security: rationale redaction credential redaction for rationale labels moves to a single pre-cache choke point (_redact_rationale_labels inside _safe_extract), so no extractor can skip it, and it now covers more leak shapes: URL userinfo with an empty user or with //@ in the password, PEM private-key bodies, tokens glued to surrounding text by _ (for example ghp_...), Slack xoxe- refresh tokens, short JWTs, and Common Lisp docstrings that previously built labels without redacting. Benign strings (hashes, sk- prose, URLs without userinfo) are left alone (#4647, thanks @0xkaushik-ai).
  • Security: deps anyio is floored to >=4.14.2 in the mcp extra, above CVE-2026-63374 (an IDNA 2003 vs 2008 hostname-validation bypass that let a MITM on a non-ASCII domain present a cert for a different ASCII host, CVSS 9.3). anyio is only a transitive dependency and the lockfile already resolves 4.15.1, so this is a floor to stop a future re-resolution from regressing.
  • Fix: markdown ATX headings parse per CommonMark: a trailing run of # is not part of the heading text (## Setup ## is "Setup"), up to three spaces of indent are allowed (four is an indented code block), and a hash-only line like ## ## mints no node (#4790, #4791, thanks @jaimemartinez).
  • Fix: markdown fenced code blocks are tracked by CommonMark rules (backtick and tilde fences, info strings, matching close length), so a line that looks like a heading inside a fence no longer leaks as structure, and a heading after a ~~~ block that contains a ``` line is no longer lost (#4787, #4788, thanks @jaimemartinez).
  • Fix: yaml structural extraction reads the composed node tree, so keys carry their written spelling and their own source line instead of all landing on line 1, and YAML 1.1 bare keys like on/off/yes/no are no longer folded to booleans (a workflow on: block is extracted, not turned into a True node) (#4784, #4785, thanks @jaimemartinez).
  • Fix: razor a component's @implements interfaces are extracted as implements edges instead of being silently dropped (#4820, thanks @ayushcodes10).
  • Fix: terraform an aliased provider block gets its own alias-qualified node (so two provider "aws" blocks no longer collapse into one and lose attributes), and a provider = aws.west reference resolves to it instead of dangling; a local literally named provider is no longer misread (#4819, thanks @ayushcodes10).
  • Fix: cobol paragraphs that follow a nested END PROGRAM reattach to the enclosing program instead of sticking to the nested one, via a program stack (#4824, thanks @ayushcodes10).
  • Fix: blade a wire:click directive binds the bare method name: dotted modifiers (wire:click.prevent="submit") are matched, call arguments are trimmed from the name (deleteItem(5) binds deleteItem), and a $-prefixed magic action mints no fabricated edge (#4823, thanks @ayushcodes10).
  • Fix: pascal a record is recognised as a type with its own methods in the regex fallback (the default path without the optional pascal extra), matching the tree-sitter path; operator members are extracted too (#4825, thanks @ayushcodes10).
  • Fix: vbnet an Operator declaration is extracted as an operator-kind member of its class and its body is walked for calls, so a helper call inside an operator no longer vanishes (#4821, thanks @ayushcodes10).
  • Fix: fortran a call resolves to the subroutine it actually names instead of a target salted with the calling file's name (which never resolved), using the extractor's own cross-file stub idiom (#4795, thanks @ayushcodes10).
  • Fix: cli graphify query --help/-h (and now graphify explain --help/-h) with nothing else prints usage instead of running a literal query for the text "--help"; a longer question that merely contains "--help" as a substring still runs as a query (#4830, thanks @curl-man).
  • Fix: js a nested (inner) function no longer leaks into the file-wide name map, so a call elsewhere in the file binds to the top-level function of that name rather than an inner one it cannot see; recursion, shadowing and sibling scopes resolve correctly (ports the Python scope scheme to JS/TS) (#4767, thanks @smngvlkz).
  • Fix: ocaml every binding in an and-chained module ... and ... or class ... and ... is extracted, not just the first, so later bindings are no longer silently dropped; each carries its own source line (#4822, thanks @ayushcodes10).
  • Fix: verilog a SystemVerilog class task method is modeled like a function one (its own node, method edge and parameter-type references), and a task-local variable no longer leaks as a false field reference on the class (#4774, thanks @ayushcodes10).
  • Fix: build an edge with no relation is dropped instead of persisted, on both the build and the raw --no-cluster write paths, and alias folding (relationship to relation) runs before the check (#4810, thanks @legendteddy; reproducer also filed as #4826 by @sunhouy).
  • Fix: build the shrink guard counts a saved document-mention node that folds into its AST file twin on reload as present, not lost, so a cluster-only write is no longer refused when nothing was actually lost (#4778, #4779, thanks @AndresDiagoM).
  • Fix: detect a linked git worktree whose main checkout resolves inside the scan root is pruned, so a sibling worktree no longer gets indexed as a second full copy of the repo (#4683, #4833, thanks @barlowa124; duplicate work in #4685 by @AndresDiagoM).
  • Fix: resolution an inline comment in a pnpm-workspace glob is stripped per YAML rules, and a glob that Path.glob rejects (a ** component or an absolute pattern) is skipped with a warning instead of crashing the whole extract run (#4681, #4687, thanks @Deepjyoti-Sarmah).
  • Fix: report a community hub [[wikilink]] is slugged through the same export._obsidian_safe_stem the export uses, so the link matches the file the export actually writes instead of dangling (#4696, thanks @ayushcodes10).
  • Fix: wiki a community relabelled only by letter case keeps its article instead of having the sweep delete the file the run just wrote; on a case-sensitive filesystem the stale lower-case twin is unlinked rather than renamed over the fresh file (which would silently restore the old body) (#4508, #4798, thanks @dupeisen).
  • Fix: query filler verbs get/gets/got/getting are dropped from query terms (like the existing work/works), so a framework hub labelled "Get" is not pulled in as a BFS seed by an exact-match bonus; node lookups for a literal Get still resolve (#4686, thanks @AndresDiagoM).
