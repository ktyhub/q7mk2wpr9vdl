LightRAG v1.0.9

Highlights

  • Mixed search mode — PR #523 adds a new retrieval mode that fuses knowledge-graph traversal with LightRAG's other search techniques, with the prompts tuned in #524. This is the headline capability of the release: hybrid retrieval tends to win on multi-hop questions that pure vector or pure graph search miss. Adopters wiring it into existing clients should watch for changes to query-mode parameters/enums.

  • Resumable ingestion — PR #521 introduces document status tracking plus breakpoint resume for the indexing pipeline, and #529 fixes the resume filter so that only documents with a completed status are skipped. This matters for anyone running large, long-lived ingestion jobs — an interrupted run no longer restarts from zero. The #529 nuance is worth noting: failed and in-progress documents get reprocessed, so make sure your ingestion path is idempotent.

  • Temporal knowledge graphs — PR #525 extends KG relationships with temporal information, letting the graph encode when a relation held rather than just that it did. Teams working with time-sensitive corpora (news, event logs, versioned entities) gain time-aware reasoning without building a separate data model.

  • Windows async fix — PR #516 resolves an async runtime issue specific to Windows. If you develop or deploy on Windows, this removes a platform-specific hang/crash that previously made the async API unreliable there — a meaningful reliability win despite being a small patch.

  • Setup and error-handling cleanup — PR #514 streamlines API installation and documentation, lowering the barrier to a first successful run. Separately, #527 changes an exception type on a failure path; if your integration catches specific exception classes, re-check those handlers so a silently changed type doesn't break your error handling.

No breaking changes are indicated in this release.
