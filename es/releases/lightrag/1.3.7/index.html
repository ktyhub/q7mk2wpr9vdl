LightRAG v1.3.7

Highlights

  • Per-query prompts land in QueryParam — QueryParam now accepts a user prompt (PR #1546, #1552), so callers can steer RAG behavior request-by-request instead of being pinned to one global template. This is the headline API addition: if you were smuggling instructions into the query string to fake per-request control, there's now a first-class field. Not a breaking signature change, but worth validating in mix/naive paths where prompt flow differs.

  • Failed LLM calls now persist in the cache — "persistent LLM cache on error" (PR #1511) records failed generations so repeated identical requests don't re-hit a struggling provider. Great for cost and rate-limit pressure, but the trade-off is stickiness: a transient outage can remain cached for the TTL, so have a deliberate cache-clear/invalidation step when a provider recovers.

  • PostgreSQL/AGE storage gets a serious hardening pass — This is the real upgrade driver for AGE users: configurable max_connections (PR #1547), node names containing JSON no longer misread as JSON objects (PR #1512), corrected JSON handling (PR #1519), valid table-creation SQL (PR #1524), and timezone/created_at normalization (PR #1510). Plan to re-validate schema creation and historical timestamps after rollout — several of these touch persisted data, not just query logic.

  • Leaner, faster retrieval in naive/mix modes — Query context formatting was reworked (PR #1545) and redundant chunk re-fetching removed (PR #1537), while chat history is now excluded from vector search (PR #1538). Expect lower latency and less context bloat in conversational flows — but flag the behavioral change: prior turns no longer influence vector similarity, so multi-turn answers may shift in tone or relevance.

  • Streaming, client lifecycle, and a security fix — OpenAI streaming was repaired (PR #1553) and the OpenAI client moved under a context manager (PR #1548), improving cleanup under concurrent load. A security fix also landed (PR #1325); given LightRAG routinely ingests untrusted text, treat this as security-relevant and bump promptly rather than batching it with routine maintenance.

  • Provider and deployment coverage widens — bedrock_complete was generalized (PR #1508), the Ollama driver/sample refreshed (PR #1572), a Tongyi/Qwen demo added (PR #1518), and Docker/compose files updated (PR #1570). Easier adoption on non-OpenAI stacks, but these are integration-level changes — smoke-test them if you depend on Bedrock or Ollama.

No breaking changes were introduced in this release.
