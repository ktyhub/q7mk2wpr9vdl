LightRAG v1.5.5

🎉 Función de reconocimiento AddSmart Heading para documentos de Word

A partir de v1.5.5, el analizador DOCX integrado de LightRAG presenta la función Encabezado inteligente, que permite una mejor fragmentación basada en secciones incluso para documentos DOCX mal formateados.

Muchos documentos DOCX tienen estructuras de secciones visualmente claras, pero carecen de niveles de esquema de Word configurados correctamente o conservan estilos de encabezado incorrectos debido a los procesos de edición, copia y concatenación. En el pasado, estos problemas podían provocar que los títulos de las secciones se trataran como texto del cuerpo o que el texto normal se identificara erróneamente como encabezados, lo que generaba límites fragmentados que se desviaban de las verdaderas secciones semánticas del documento. Para las estrategias de fragmentación de P que se basan en estructuras de encabezados, esto crea un contexto fragmentado o contenido mixto de diferentes secciones, lo que afecta la indexación y recuperación posteriores.

Encabezado inteligente se dirige a documentos con formato deficiente pero semánticamente claros, restaurando sus verdaderas estructuras de encabezado tanto como sea posible:

  1. Recuperar títulos de secciones faltantes: identifique el contenido que aparece visualmente como títulos pero que carece de niveles de esquema configurados correctamente, lo que reduce la pérdida de estructuras de secciones.
  2. Reduzca los falsos positivos del cuerpo del texto como títulos: restaure el texto del cuerpo normal, cláusulas completas, leyendas, fechas y notas de versión que llevan incorrectamente estilos de encabezado al cuerpo del texto, evitando límites de fragmentación sin sentido.
  3. Mejorar las jerarquías de encabezados inconsistentes: reduzca problemas como niveles de encabezados entre hermanos inconsistentes, jerarquías entre padres e hijos invertidas y niveles omitidos, lo que hace que las estructuras de las secciones sean más coherentes.
  4. Distinga varios contenidos en documentos combinados: identifique los títulos principales y los límites de los documentos de cada contenido, evitando la interferencia a nivel de sección entre diferentes documentos.
  5. Reduzca el ruido de las tablas de contenido largas: comprima las tablas de contenido excesivamente largas, minimizando la interferencia de información duplicada en la indexación y recuperación.

Al proporcionar estructuras de sección más confiables para la fragmentación posterior, Smart Heading ayuda a mantener asociaciones semánticas entre los títulos y su cuerpo de texto correspondiente, lo que hace que los resultados de la fragmentación se alineen mejor con la organización del contenido original del documento.

Smart Heading es una capacidad opcional del analizador DOCX nativo y requiere activación para que surta efecto. Para obtener instrucciones de habilitación y configuración, consulte: docs/FileProcessingPipeline / 中文版.

LightRAG v1.5.5

Highlights

  • Opt-in Smart Heading for DOCX — The native DOCX parser gains a smart_heading engine parameter (#3364) that reconstructs heading structure in visually clear but poorly formatted documents: it recovers unstyled section titles, demotes false headings (captions, dates, version notes), repairs inverted/skipped/sibling hierarchies, separates merged sub-documents, and compresses bloated TOCs. This directly improves P-chunking boundaries and title↔body association for RAG indexing — but it is off by default, so existing corpora are unaffected until you enable it per the FileProcessingPipeline docs.
  • Large security-hardening pass — Multiple advisories landed: constant-time password comparison (GHSA-c759-cx9p-mrwq, #3423), /login rate limiting (GHSA-frch-4w6v-q5xx, #3424), chat-Markdown sanitization against stored XSS (GHSA-xpjq-3w4w-w5wr, #3437), /health config disclosure gated behind auth (#3329), warnings for unauthenticated network-exposed servers (GHSA-mmg5-8x8q-v934, #3328), removal of raw exception text in API errors (CWE-209, #3422), an IPv6-transition SSRF bypass patch (#3426), Postgres _dollar_quote hardening (#3427), task-ID path-injection prevention (#3324), and Docker CVE pins + non-root image (#3330). If you expose the API server, this is a priority upgrade; expect unauthenticated endpoints to return less information.
  • Pipeline reliability and resource governance — A cluster of refactors makes long-running ingestion more robust: dead-worker recovery for multiprocess keyed locks (#3408, #3409, #3413, #3415, #3431) and cancellation-safe lock release (#3407), workspace-scoped pipeline ingress (#3458–#3467), atomic shared-storage state updates (#3417), and bounded resident-set-size for pipeline processing (#3481–#3489, #3497). Document mutations are now recoverable via write-ahead anchors, journaled custom chunks, and scan rollback (#3416). Operators running memory-constrained or multi-worker deployments get the biggest win here.
  • Auth contract change — #3358 clarifies and enforces that X-API-Key and Authorization are mutually exclusive per request (fixing #2632). Clients that send both headers need auditing — one will be ignored or rejected. Combined with the /health gating above, treat any integration that relied on unauthenticated config reads as a required migration.
  • Correctness fixes that change indexing results — ainsert_custom_chunks no longer silently skips knowledge-graph construction (#3394) and now respects the pipeline-busy contract (#3401); reprocessing no longer accumulates stale descriptions or edge weights (#3395, #3399, #3398). A compute_args_hash cache-key collision closed via length-prefixed encoding (#3435) means some previously reused cache entries may have been wrong. Token-windowing now rejects chunk_overlap >= chunk_size (#3396), so configs at that boundary will start erroring. Truncated LLM responses are no longer cached (#3446, #3448).
  • Performance, telemetry, and cleanup — Descriptions are tokenized once in the entity/relation map-reduce (#3359), shared-storage manager RPCs are cut in update-flags/namespace/status paths (#3434, #3436, #3439), and JSON KV snapshots use DictProxy.copy() (#3433). Milvus/Qdrant (#3360), Redis (#3370), and AsyncOpenAI (#3371) clients are now properly closed in finalize(). The WebUI surfaces server-side query and first-token latency (#3387) plus live m_lock/a_lock counts (#3440) — useful for diagnosing the contention the lock refactors address. An Apple container orchestrator for the storage stack (#3347) is also available for local setups.

No breaking changes were formally declared; note the auth-header and chunk_overlap behavior changes above.

🎉 AddSmart Heading Recognition Feature For Word Document

Starting from v1.5.5, LightRAG's built-in DOCX parser introduces the Smart Heading feature -- enabling better section-based chunking even for poorly formatted DOCX documents.

Many DOCX documents have visually clear section structures but lack properly configured Word outline levels, or retain incorrect heading styles from editing, copying, and concatenation processes. In the past, these issues could cause section titles to be treated as body text, or regular text to be misidentified as headings, resulting in chunking boundaries that deviate from the document's true semantic sections. For P chunking strategies that rely on heading structures, this creates fragmented context or mixed content from different sections, affecting subsequent indexing and retrieval.

Smart Heading targets such poorly formatted but semantically clear documents, restoring their true heading structures as much as possible:

  1. Recover Missing Section Titles: Identify content that visually appears as titles but lacks properly configured outline levels, reducing loss of section structures.
  2. Reduce False Positives of Body Text as Headings: Restore regular body text, complete clauses, captions, dates, and version notes that incorrectly carry heading styles back to body text, avoiding meaningless chunking boundaries.
  3. Improve Inconsistent Heading Hierarchies: Reduce issues such as inconsistent sibling heading levels, inverted parent-child hierarchies, and skipped levels, making section structures more coherent.
  4. Distinguish Multiple Contents in Merged Documents: Identify main titles and document boundaries of each piece of content, preventing section level interference between different documents.
  5. Reduce Noise from Long Tables of Contents: Compress excessively long table of contents, minimizing the interference of duplicate information on indexing and retrieval.

By providing more reliable section structures for subsequent chunking, Smart Heading helps maintain semantic associations between titles and their corresponding body text, making chunking results align better with the document's original content organization.

Smart Heading is an optional capability of the Native DOCX parser and requires activation to take effect. For enabling and configuration instructions, please refer to: docs/FileProcessingPipeline / 中文版.
