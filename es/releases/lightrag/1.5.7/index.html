LightRAG v1.5.7

Notas importantes

Nueva característica: agregue un punto de entrada orientado al usuario final a WebUI

v1.5.7 agrega una segunda entrada orientada al usuario final, /workspace, junto con la marca y los controles rápidos que una implementación necesita antes de poder entregarse a usuarios reales.

  • Una entrada de solo consulta para usuarios finales: /workspace
  • Páginas de bienvenida, inicio de sesión y estado vacío personalizables
  • Un USER_PROMPT_PREFIX global

La interfaz de usuario de /workspace muestra la superficie de chat y nada más (sin gestión de documentos, sin gráficos de conocimiento, sin enlaces de documentos API) y está diseñada para uso móvil. Apunte UI_TEMPLATES_DIR a un pequeño directorio de archivos Markdown más un manifest.json, y LightRAG le mostrará su página de bienvenida, propaganda de la página de inicio de sesión, consulta de estado vacío, logotipo de marca y línea de derechos de autor, en varios idiomas, sin reconstruir la WebUI. Una configuración regional que declara tanto una propaganda de inicio de sesión como un documento de acuerdo también activa una casilla de verificación de consentimiento de inicio de sesión. Se envía un paquete listo para copiar en docs/ui_templates_example/.

USER_PROMPT_PREFIX (o USER_PROMPT_PREFIX_FILE para texto largo de varios párrafos) antepone instrucciones de implementación a cada solicitud user_prompt. Le brinda al operador un lugar para configurar la función, el tono y el formato de salida del LLM (diagramas de sirena, delimitadores de LaTeX, estilo de cita) tanto para las entradas de la interfaz de usuario como para el API. Las solicitudes nunca podrán leerlo ni reemplazarlo; sólo el campo API disable_user_prompt_prefix se excluye.

Para obtener más información, consulte:

  • docs/LightRAG-API-Server.md — § La entrada de consulta /workspace
  • docs/UserDefinedUI.md: la guía completa de personalización de la interfaz de usuario, además de docs/ui_templates_example/
  • README.md — USER_PROMPT_PREFIX / USER_PROMPT_PREFIX_FILE

LightRAG v1.5.7

Highlights

  • End-user-facing /workspace WebUI — v1.5.7 adds a second, query-only UI entry at /workspace that hides document management, the knowledge graph, and API-docs links and is built for mobile use. Together with UI_TEMPLATES_DIR (a directory of Markdown files plus manifest.json, with a ready-to-copy bundle in docs/ui_templates_example/), WEBUI_TITLE for the browser tab, custom logos/deployment titles, per-locale login blurbs and a consent checkbox, and a customer-defined copyright line on pre-login pages, this is the first release you can realistically hand to real end users without rebuilding the WebUI (#3729, #3755, #3763, #3765, #3768, #3773). If you are deploying LightRAG to non-technical users, this is the headline reason to upgrade.

  • Deployment-wide prompt control via USER_PROMPT_PREFIX — Set USER_PROMPT_PREFIX (or USER_PROMPT_PREFIX_FILE for long, multi-paragraph text) once to prepend instructions to every request's user_prompt, giving operators a single place to define the LLM's role, tone, and output format — Mermaid diagrams, LaTeX delimiters, citation style — across both UI entries and the API. Clients cannot read or replace it; the only opt-out is the API field disable_user_prompt_prefix. The feature includes cache partitioning (#3781), so changing the prefix does not poison shared query caches. Worth upgrading if you need consistent output formatting across all callers.

  • Breaking: deprecated document APIs removed — The deprecated GET /documents listing endpoint and get_docs_by_status have been removed (#3788). Any client, script, or integration calling these will break and must migrate before upgrading. Separately, the new ENABLE_API_DOCS switch (#3672) lets you hide API documentation exposure — relevant if you are locking down a public deployment such as the new /workspace entry. Review API consumers before rolling out.

  • Apache AGE users must act: AGE ≥ 1.8.0 refused, migration tool added — PGGraphStorage now refuses to run on Apache AGE ≥ 1.8.0 because it crashes the backend (#3621); if you are on that version you must downgrade AGE or move off it. An offline migration tool from Apache AGE to PostgreSQL tables ships in this release (#3620), along with a fix for a rebuild issue that corrupted quote-bearing entity_ids (#3587) and idempotent AGE graph initialization (#3677). AGE deployments should treat this upgrade as a planned migration, not a drop-in bump.

  • Security hardening and ingestion performance — upgrade recommended for most deployments — This release fixes multiple security issues, including GHSA-25c3-j78v-83qx (bounded native Markdown image downloads), GHSA-c922-pw4m-4wcv (attribute validation on manual entity/relation APIs plus graph-attribute contract enforcement across backends), bounded DOCX/OOXML decompression and member/image budgets, and bounded external result downloads for MinerU and Docling. It also adds graph-first ingestion with deferred vector indexing (#3473), deferred vector deletes for nano/faiss (#3680, #3693), and an explicit custom chunking selector (#3665). Anyone parsing untrusted documents or exposing write APIs should upgrade; teams with no AGE dependency and no need for the new UI/prompt features can skip if they have already patched these paths themselves.

Important Notes

New Feature: Add end-user-facing entry point to WebUI

v1.5.7 adds a second, end-user-facing entry — /workspace — together with the branding and prompt controls a deployment needs before it can be handed to real users.

  • A query-only entry for end users: /workspace
  • Customizable welcome, login and empty-state pages
  • A global USER_PROMPT_PREFIX

/workspace UI shows the chat surface and nothing else — no document management, no knowledge graph, no API-docs links — and is built for mobile use. Point UI_TEMPLATES_DIR at a small directory of Markdown files plus a manifest.json, and LightRAG serves your welcome page, login-page blurb, query empty state, brand logo and copyright line — in several languages, without rebuilding the WebUI. A locale that declares both a login blurb and an agreement document also switches on a login consent checkbox. A ready-to-copy bundle ships in docs/ui_templates_example/.

USER_PROMPT_PREFIX (or USER_PROMPT_PREFIX_FILE for long, multi-paragraph text) prepends deployment-wide instructions to every request's user_prompt. It gives the operator one place to set the LLM's role, tone and output format — Mermaid diagrams, LaTeX delimiters, citation style — for both UI entries and the API alike. Requests can never read or replace it; only the API field disable_user_prompt_prefix opts out.

For more information, please refer to:

  • docs/UserDefinedUI.md — the complete UI customization guide, plus docs/ui_templates_example/
  • README.md — USER_PROMPT_PREFIX / USER_PROMPT_PREFIX_FILE
