LightRAG v1.1.5

Highlights

  • New storage options — Adds MongoDB KnowledgeGraph support (PR #671, with implementation fixes in PR #708) and FAISS vector storage support (PR #686). These broaden backend choices; the changelog does not describe replacing existing backends or require migrating stored data.

  • Query controls and Ollama integration — The API server now accepts top_k and cosine_better_than_threshold (PR #674), while custom query prompts (PR #658) and revised prompts (PR #681) give users more control over retrieval and answer generation. Ollama gains conversation history, configurable model naming, and a /bypass query prefix (PR #650, PR #666, PR #698), improving provider flexibility.

  • Indexing and data reliability — Fixes concurrent document indexing/query problems (PR #693), CSV parsing (PR #659), document-status handling involving doc['status'] and doc_key (PR #695, PR #701, PR #711), and empty get_by_id results (PR #704). These are meaningful fixes for production ingestion and query workloads; Apache AGE performance also improves.

  • WebUI and graph tooling — Expands WebUI management, uploads, authentication, and graph rendering (PR #647, PR #649, PR #702). The optional GraphML visualizer was added, reverted, then reapplied (PR #703, PR #705, PR #709), and lightrag_visualizer was split into a separate module with an updated entry point (PR #710). Check that entry point if you import the visualizer directly.

  • Upgrade recommendation — This is a substantive feature-and-fix release, not a re-tag or metadata-only update. Upgrade if you need MongoDB/FAISS, finer query controls, improved Ollama support, or the concurrency/status fixes. No explicit breaking changes or migration steps are listed; users on stable, unaffected workflows who do not need these additions can reasonably skip it.
