LightRAG v1.4.0

Notas de importancia

  • Después de la actualización, borre los documentos y el caché, luego vuelva a indexarlos para que la función de eliminación de documentos funcione correctamente. Recuerde seleccionar la opción "borrar caché simultáneamente" al borrar documentos. Si la función de eliminación de documentos no se requiere de inmediato, no es necesario volver a indexar los documentos.
  • Esta actualización incluye cambios en los parámetros de QueryParam. Si anteriormente integró LightRAG usando QueryParam, actualice su paso de parámetros de acuerdo con la última versión API. Consulte los parámetros del punto final /query en la página API de la interfaz de usuario web.
  • La integración de Reranker en esta versión mejora significativamente el rendimiento de consultas mixtas. Recomendamos utilizar el modo de consulta mixto como predeterminado cuando Reranker está habilitado.

LightRAG v1.4.0

Highlights

  • Breaking: QueryParam API changed — Integrations that previously passed QueryParam must be updated to the latest signature; the canonical reference is the /query endpoint parameters on the WebUI's API page. Call sites written against v1.3.9 may fail to compile or silently drop options after upgrading, so audit every query invocation before rolling out rather than assuming a drop-in patch release.

  • Document deletion lands — but demands a re-index — The new WebUI deletion flow (#1698, #1697, #1732) only behaves correctly if you clear documents and cache (tick "clear cache simultaneously") and re-index, with WORKSPACE data isolation (#1743) added for all storage types. Indexes carried over from earlier versions retain stale cache entries that deletion won't reconcile; if you don't need deletion yet, you can safely defer the costly rebuild. Under the hood this rests on a flattened LLM cache structure (#1729) plus deletion-aware cache fixes for MongoKV and PGKV (#1718, #1717).

  • Reranking makes mixed queries the recommended default — Chunk reranking (#1753, #1782) materially improves mixed-query results, and the release explicitly advises making mix the default mode whenever a reranker is enabled. Teams with hardcoded query modes should revisit them to actually reap the gain; reranker config and lock state are now surfaced on the WebUI status card (#1773).

  • Parallel merge + multiprocess lock fix — The document-merge stage now processes in parallel to exploit LLM concurrency (#1549, #1772, #1771, #1770), cutting ingestion latency for large corpora. Pair that with the hotfix preventing premature lock cleanup in multiprocess mode (#1774) and Redis connection-pool repairs (#1775) — if you run multi-process ingestion, upgrading is what keeps parallel workers from tripping over each other's locks.

  • New backends and model compatibility — Memgraph joins as a graph database backend (#1703, #1766) and Cloudflare Workers AI as a serverless LLM/embedding option (#1765), widening deployment choices. COT/reasoning models are now supported by stripping <think> tags from entity/keyword extraction (#1752), so reasoning-model outputs stop polluting the knowledge graph. Watch the behavioral tweaks: default embedding batch size drops 32 → 10 (#1750) to ease memory pressure at some throughput cost, and the deprecated MAX_TOKEN_SUMMARY is removed (#1783) to prevent output truncation.

Importance Notes

  • After upgrading, please clear documents and cache, then re-index your documents for document deletion feature functions correctly. Remember to select the "clear cache simultaneously" option when clearing documents. If the document deletion functionality is not immediately required, there is no need to re-index documents.
  • This upgrade includes changes to QueryParam parameters. If you previously integrated LightRAG using QueryParam, please update your parameter passing according to the latest API. Refer to the /query endpoint parameters on the web UI's API page.
  • The integration of Reranker in this version significantly enhances the performance of mixed queries. We recommend using mixed query mode as the default when Reranker is enabled.
