🔧 Corrección de errores

  • solución(proxy): hacer que el tiempo de espera del protocolo de enlace SOCKS5 sea ajustable por el operador (SOCKS_HANDSHAKE_TIMEOUT_MS): en condiciones de alta concurrencia contra un solo host de puerta de enlace residencial, el protocolo de enlace de conexión SOCKS5 podría exceder los 10 codificados aunque el proxy fuera accesible, apareciendo como un [Proxy Fast-Fail] Proxy unreachable falso (el tamaño del grupo ya se puede ajustar a través de OMNIROUTE_PROXY_DISPATCHER_CONNECTIONS). El tiempo de espera del protocolo de enlace ahora dice SOCKS_HANDSHAKE_TIMEOUT_MS (el valor predeterminado sin cambios es 10000, con un límite de 120000), por lo que una implementación con mucha concurrencia puede aumentarlo sin un cambio de código. Mitigación para el número 5109 (el colapso total de la simultaneidad 100 aún necesita la confirmación de la prueba de carga en vivo del reportero). (#5109)
  • corrección(api): resuelve GET /v1/models/{id} sin distinguir entre mayúsculas y minúsculas: clients que normalizan la identificación del modelo (por ejemplo, OpenCode que solicita minimax/minimax-m3 para la entrada del catálogo canónico minimax/MiniMax-M3) omitieron la búsqueda de modelo único, que distingue entre mayúsculas y minúsculas, y recurrieron a la publicidad context_length: 0. findModelById ahora prefiere una coincidencia exacta entre mayúsculas y minúsculas y recurre a una coincidencia que no distingue entre mayúsculas y minúsculas, por lo que la entrada real (y su ventana de contexto) se devuelve independientemente de las mayúsculas y minúsculas. (#5082)
  • corrección(servicios): incrustar proxy WS respeta LIVE_WS_HOST; rechazar messages vacío temprano: dos correcciones de implementación sin cabeza/Docker (#5110). El proxy WebSocket integrado (:20131) solo leía EMBED_WS_PROXY_HOST, por lo que detrás de un túnel/proxy inverso permaneció vinculado a 127.0.0.1 incluso con LIVE_WS_HOST=0.0.0.0 configurado y el panel en vivo mostraba "WebSocket desconectado"; ahora vuelve a caer a LIVE_WS_HOST (el valor predeterminado sigue siendo loopback). Por otra parte, una solicitud con una matriz messages: [] explícitamente vacía se reenvió en sentido ascendente y se recuperó como un 400/502 sin formato confuso; handleChat ahora lo rechaza por adelantado con un messages: at least one message is required claro (las solicitudes de Responses-API input no se ven afectadas). (#5110)
  • solución(proxy): reparar una implementación de retransmisión click Deno y Cloudflare: el punto final /api/settings/proxy/test solo reconoció el tipo de retransmisión vercel, por lo que al probar una retransmisión implementada de Deno o Cloudflare se devolvió proxy.type must be http, https, or socks5 y nunca alcanzó la retransmisión; ahora enruta todos los tipos de relés a través de isRelayType(). En instalaciones con STORAGE_ENCRYPTION_KEY, el token de autenticación de retransmisión se lee a través de extractRelayAuth (formato relayAuthEnc cifrado), lo que corrige el 401 silencioso que dejó publicIp nulo. La carga de Cloudflare Worker ahora envía la parte del script como application/javascript (el API rechaza application/javascript+module; la semántica del módulo ES proviene de main_module) y el esquema de registro de proxy acepta los tipos deno/cloudflare + fuentes deno-relay/cloudflare-relay, por lo que editar un relé implementado ya no es 400. (#5128)

OmniRoute v3.8.38

Highlights

  • Local provider URLs are now allowed by default — OMNIROUTE_ALLOW_LOCAL_PROVIDER_URLS permits OpenAI-compatible loopback/LAN endpoints while still blocking cloud-metadata targets, making self-hosted inference work without workarounds. Shared or container deployments should review this SSRF-policy relaxation and disable the flag if public-only validation is required; webhook and remote-image protections are unchanged (#5066).

  • Routing gains Factory, Grok, ZenMux, and video support — Factory adds an OpenAI-compatible gateway with a Dashboard-managed Bearer key (#5065); grok-cli imports Grok authentication and rotates refresh tokens (#5020); cookie-backed zenmux-free translates Anthropic SSE to OpenAI and includes 12 free-tier models (#5105); Alibaba adds asynchronous wan2.7-t2v text-to-video routing.

  • Tool and reasoning streams better match native OpenAI traffic — When enabled, Kiro emits <thinking> content as delta.reasoning_content; Cursor Composer’s inline tool markers become structured tool_calls in both streaming and non-streaming responses. SSE hardening also preserves reasoning fields through JSON-as-SSE fallbacks and records disconnects as 499, preventing client cancellations from poisoning provider failure state (#5124).

  • Compression gains observable, guarded pipelines — The management-only Studio compares deterministic engine lanes and combined waterfalls using the real cl100k tokenizer, with USD-capped A/B verification (#5080). Opt-in fidelity gates reject lossy output, fuzzy dedup removes near-duplicates (#5143), and Ionizer samples JSON arrays while retaining CCR reconstruction data (#5148). Ionizer trades exactness for token savings, and fidelity gates fail open.

  • Restart and deployment failures are less likely — Persisted quota snapshots rehydrate exhausted-account state after restart, while auto-combo expansion now respects each target’s allowed connections (#5015). Deployments gain tunable SOCKS handshake timeouts—10 seconds by default, capped at 120 seconds—plus LIVE_WS_HOST fallback and repaired Deno/Cloudflare relay testing, authentication, and upload paths (#5110, #5128). The timeout change mitigates, but does not establish a fix for, the reported concurrency-100 collapse (#5109).

  • API and catalog behavior changes need attention — Explicit messages: [] now fails locally with 400 messages: at least one message is required rather than an opaque upstream error; Responses API input requests are unaffected (#5110). Kiro users must replace retired claude-sonnet-4.5 references with a supported model such as Sonnet 4.6 (#5140). Meanwhile, GET /v1/models/{id} now resolves case differences, preventing incorrect context_length: 0 fallbacks (#5082).

  • fix(api): sanitize error responses on seven management routes (Rule #12 hardening) — cli-tools/backups, cli-tools/guide-settings/[toolId], logs/export, models/catalog, providers/test-batch, settings/import-json and usage/proxy-logs no longer return raw error.message; they wrap caught errors in sanitizeErrorMessage(...), and the routes are removed from the check-error-helper allowlist. (thanks @JxnLexn)
  • fix(sse): keep output_text-only Responses bodies from being dropped/false-502'd — some upstreams return a shorthand Responses body whose answer is only in output_text with an empty output[]. sanitizeResponsesApiResponse discarded the text, so the response then tripped the malformed-200 guard. The sanitizer now synthesizes an output[] message item from a non-empty output_text (complements the Claude-native fix in #5108; both stem from #4942).
  • fix(executors): preserve a lone caller-supplied Anthropic-Version header casing — the case-variant dedupe (#4846) unconditionally rewrote Anthropic-Version/Anthropic-Beta to lowercase even when only one variant was present, clobbering the caller's header. Dedupe now runs only when both case variants coexist (the actual undici-merge collision it was meant to fix).
  • fix(responses): default text.format to { type: "text" } for openai-compatible responses providers — some Responses-compatible upstreams (e.g. LM Studio) reject a text object missing text.format with a 400 missing_required_parameter; the default executor now fills the Responses-API default before forwarding (guarded to openai-compatible-*responses*, never overwriting an existing format). (thanks @StevanusPangau)
  • fix(translator): stop stripping client-provided reasoning_content for reasoning-replay providers — the #4849 agentic-context strip (which drops reasoning_content from tool-call assistant turns to avoid O(n²) token growth) ran unconditionally, so replay providers (DeepSeek V4, Kimi K2, Qwen-Thinking, etc.) lost the client's reasoning and the reasoning-replay cache then overwrote it with a stale cached value (and such upstreams 400 without the original reasoning). The strip now skips reasoning-replay targets while non-reasoning providers keep the O(n²) protection. (#5122)
  • fix(providers): add MiniMax M3 & Nemotron 3 Ultra to the Cline catalog — the two models were missing from Cline's provider catalog and could not be selected; both are now registered. (#5136, closes #3321)
  • fix(dashboard): key model-visibility toggle on the canonical providerId — the per-model visibility toggle keyed off a display id, so toggling a model on one provider alias could mis-target another; it now keys on the canonical providerId. (#5091 — thanks @Theadd)
  • fix(diagnostics): recognize the Claude API format in detectMalformedNonStream — salvaged null-guard so a Claude-shaped non-streaming body is no longer misclassified. (#5141 — thanks @herjarsa / @diegosouzapw)
  • fix(logging): track the final connection IDs in failover logs — failover log lines now record the connection that actually served (or last failed) the request, instead of only the first attempt. (#5016 — thanks @JxnLexn)
  • fix(sse): ignore disconnect races during in-band stream error handling — a client disconnect that races with in-band upstream error handling no longer surfaces as a spurious provider failure. (#5007 — thanks @JxnLexn)
  • fix(dashboard): surface the server error on handleToggleCombo failure — a failed combo toggle now shows the backend error instead of silently no-op'ing. (#5138 — thanks @KooshaPari / @diegosouzapw)
  • fix(quota): track provider quota reset windows + enrich the Codex playground — observed quota reset windows are tracked and surfaced, and the Codex playground gains the enriched quota metadata. (#5141 — thanks @Witroch4 / @diegosouzapw)
  • fix(sidebar): drop the orphan settings accent color — removed a dangling accent-color entry that broke typecheck:core. (#5142)
  • fix(sse): preserve non-stream reasoning fields for compatible clients — non-streaming responses now keep the upstream reasoning fields (reasoning / reasoning_content and OpenRouter/Gemini reasoning_details) instead of stripping them in responseSanitizer, so clients that render reasoning on buffered responses no longer lose it. (#5155 — thanks @rdself)
  • fix(i18n): add missing English UI labels — fills in untranslated English strings that were surfacing as raw keys in the dashboard. (#5153 — thanks @rdself)

🔒 Security

  • fix(security): exact-host Anthropic baseUrl check — the Anthropic base-URL guard used a substring match that a crafted host could partially satisfy; it now requires an exact host match (resolves CodeQL js/incomplete-url-substring-sanitization alert #674). (#5130)

📝 Maintenance

  • refactor(store): remove dead legacy store modules — salvaged cleanup of unused legacy store code. (#5138 — thanks @JxnLexn / @diegosouzapw)
  • test(combo): deterministic routing-decision matrix for all 17 strategies — a deterministic E2E matrix pins the routing decision of every combo strategy. (#5146)
  • chore: baseline reconciliations (complexity / file-size / cognitive), golden-snapshot + apikey-count alignment for new providers, orphan-test relocation, release base-red repairs, CHANGELOG i18n mirror sync, and an actions/cache 5→6 bump. (#5145, #5144, #5125, #5126, #5120, #5117, #5112)
