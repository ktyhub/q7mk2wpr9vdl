agentscope v0.1.0

Highlights

  • Model & API coverage — Adds first-class wrappers for ZhipuAI (PR #181), Yi (PR #343), and LiteLLM (PR #204), plus streaming mode (PR #347) and model-name-driven input formatting (PR #381) so prompts are shaped per target model. Vision/multimodal support arrives for the OpenAI Chat API (gpt-4o, gpt-4-turbo, PR #221) and DashScope (PR #255), alongside an embedding post API (PR #186), a Gemini chat wrapper fix (PR #233), and a host URL option for Ollama wrappers (PR #365). Why it matters: broader provider choice, streaming, and multimodal support without leaving AgentScope.

  • Breaking changes / migration — Message typing is consolidated on Msg: Tht is removed (PR #313), MessageBase/dict-based messages and the agents' reply function typing are unified into Msg (PR #313, PR #386, PR #314), and message serialization changes with unused arguments dropped (PR #388). Deprecated modules are removed and duplicate files merged (PR #422), and Studio is rebuilt then switched to Gradio (PR #238, PR #295). Migration is required: replace Tht and MessageBase/dict usage with Msg, update custom reply signatures, drop imports of removed modules, and rework anything tied to the old Studio. These are not backward compatible.

  • New agent algorithms & prompt tooling — Adds MoA / Mixture-of-Agents (PR #327, tests PR #346), a prompt tuning/engineering module (PR #242), a reformatted and improved RAG module (PR #184), a CodeAct agent with notebook-executor service (PR #231), and a router agent example (PR #416). These are new capabilities, not just fixes — multi-agent aggregation, prompt optimization, RAG, and tool-using agents.

  • Services & infrastructure — New service functions: TripAdvisor search, DBLP search (PR #177), Wikipedia/Wiki retrieval (PR #324), Web Browser Control, and OpenAI/DashScope multimodal services (PR #255). Adds agent server management (PR #239, PR #211), unifies model/studio/file/monitor into one manager (PR #364), lets Studio allocate agent servers (PR #351), and adds security checks to execute_shell_command (PR #420) — relevant if you expose service functions.

  • Worth upgrading? — This is a substantial feature release (v0.1.0, after v0.0.5 and pre-releases 0.0.6a2 / 0.0.6a3), not a no-op, re-tag, or metadata-only update. Upgrade for the new providers, streaming, multimodal, MoA, prompt tuning, or RAG improvements. You can defer if your code is heavily built on Tht, MessageBase/dict messages, removed deprecated modules, or the pre-Gradio Studio — budget migration effort first.

  4. Support LiteLLM (https://github.com/modelscope/agentscope/pull/204)
  5. Format input messages according to the name of the model (https://github.com/modelscope/agentscope/pull/381)
