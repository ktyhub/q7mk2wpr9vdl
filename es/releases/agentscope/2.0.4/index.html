agentscope v2.0.4

Highlights

  • Agent interruption & agent service — #1995 adds agent interruption with graceful context and tool-state handling and wires it through the agent service backend and frontend; #1984 adds a session status endpoint, and AgentInvite lets you import an existing agent as a team member (p2p agent-to-agent communication). This is the headline for anyone running the agent service — upgrade if you need cancellable runs or agent-to-agent coordination.
  • Long-term memory — two new middleware paths land: ReMe-based long-term memory (#1972) and file-based "agentic" long-term memory (#1927). Relevant if you need memory that persists across sessions; custom-middleware authors should also note #1966, which preserves middleware kwargs across next handlers.
  • New TTS and RAG backends (additive) — OpenAI TTS API (#1878) and DashScope CosyVoice TTS (#1866) models, plus a Milvus Lite vector store (#1969) for RAG. Purely additive: switch providers/config only if you want them, otherwise no action required.
  • Reliability fixes worth having — structured output no longer hangs on streaming models (#2018), OpenAI response API fixed (#1950), truncated tool-call input no longer crashes the formatter (#2012), empty/interrupted streaming responses guarded (#1861), Gemini const schema sanitized (#2016) and empty thinking blocks dropped (#2013), plus duplicate credential registration (#1964) and negative grep pagination (#1954) fixes. Strongest upgrade case if you use Gemini tool calls/structured output or streaming structured output.
  • Upgrade call / migration — no explicit breaking changes or required migration steps are documented; this is a routine feature-and-fix release. The one thing to review is #1971, which re-organizes workspace implementation logic — inspect it if you subclass or depend on workspace internals. Safe to skip if you don't use the agent service, long-term memory, the new TTS/RAG backends, or the affected model paths; otherwise the fixes above make it a worthwhile upgrade.
