#iotdb v2.0.12

Funciones y mejoras

Prevención de inyección SQL: Se refactorizó la declaración preparada del modelo de tabla para evitar la inyección SQL. Administración de clústeres: Admite la implementación de clústeres IPv6 REST: REST API admite la configuración de la zona horaria client Sincronización de datos: Rendimiento de filtrado optimizado para columnas TAG que no son las primeras en el modelo de tabla Herramientas de importación/exportación de datos: Estrategia de degradación para archivos de carga Gestión de base de datos: SHOW CREATE DATABASE/TOPIC/PIPE Cálculo - Ejecución de consultas - Cláusulas SQL: Optimice el mensaje de error cuando una consulta select * tiene demasiadas columnas Funciones: Se agregó la función de análisis de tiempo-frecuencia (FFT) Funciones: Funciones de filtrado agregadas (HighPass, LowPass) Caché de puntos más reciente: El caché de puntos más reciente admite la activación/desactivación en la granularidad de la tabla/base de datos. Funciones: Funciones agregadas de tasa/aumento/irate/delta integradas para el modelo de tabla Funciones: Función de correlación de secuencia agregada (XCorr) Funciones: Función integrada M4 con valores de tabla Funciones: Función con valores de tabla de coincidencia de tendencias de series temporales Funciones: Se agregó la función incorporada con valores de tabla read_tsfile, que admite consultas directas desde un archivo ts específico usando SQL. Metadatos del modelo de árbol: Al crear una nueva serie temporal en un dispositivo existente, ignore los atributos alineados/no alineados especificados en la declaración de creación y use los atributos alineados/no alineados del dispositivo actual en lugar de informar un error. Medición: Se optimizó el resultado de validación de la medición durante las escrituras en caché. Eliminación por granularidad del dispositivo: Se solucionó un problema por el cual, después de eliminar una tabla con una gran cantidad de datos y luego volver a crear la tabla y escribir los datos, la consulta de esa tabla tenía una latencia alta. Optimización de la memoria: Optimización de la memoria al copiar la lista de TV memtable durante las consultas Pipe Data Sync: Optimizado el algoritmo de coincidencia para ** Metadatos del modelo de árbol: Se agregó un indicador booleano a los nodos del dispositivo que indica si hay otros dispositivos debajo y se ajustó la consulta select measurement from xxx.**. Cláusulas SQL: Optimización del rendimiento para order by time + limit de tabla completa en el modelo de tabla Cláusulas SQL: Optimización de la memoria para consultas de tabla completa en el modelo de tabla Pipe Data Sync: Se optimizó el algoritmo de expansión/contracción del bloque de memoria de Pipe

Errores

Fusión de archivos en línea: Se solucionó un problema por el cual show disk_usage causaba que la combinación se bloqueara Metadatos del modelo de árbol: Se solucionó el problema de "no hay base de datos coincidente" Sincronización de datos: Admite el almacenamiento del progreso del punto de control de análisis de TsFile, de modo que al volver a intentarlo después de una falla, no sea necesario volver a analizar todo el archivo. Escritura básica: Se solucionó un problema por el cual, para el mismo dispositivo alineado, escribir primero una solicitud con menos columnas y más filas y luego escribir una solicitud con más columnas y una fila generaba un WAL que, al reiniciar el DataNode, provocaba una expansión grave del valor nulo memtable y, en última instancia, provocaba que el reinicio del DataNode se bloqueara. TsFile Sync: Al cargar un archivo tsfile, modifique la lógica de comparación del conjunto de réplicas: al comparar conjuntos de réplicas, ya no se preocupe por el orden de la lista, solo compare si los elementos dentro de los conjuntos son exactamente idénticos; cambiar la comparación de la lista a una comparación establecida Sincronización de datos de Pipe: Se solucionó un problema por el cual Pipe arrojaba un NPE para puntos de medición nulos al convertir una escritura de inserción parcial en una tableta. Sincronización de datos de Pipe: Se solucionó un problema por el cual Pipe se detenía después de un tiempo de espera de análisis de tsfile Fusión de archivos en línea: Se solucionó un problema por el cual la combinación no recurría a la copia cuando fallaba la creación de enlaces físicos. Sincronización de datos de tubería: Se agregaron límites de cuota de memoria independiente por tubería o programación justa Sincronización de datos de tubería: Se implementó un retroceso exponencial y protección de disyuntor para escenarios en los que el disco está lleno o el receptor no está disponible Sincronización de datos de tubería: Se agregaron límites globales y por tubería en TsFiles en vuelo Sincronización de datos de tubería: Se solucionó un problema por el cual drop pipe no esperaba el regreso del fregadero. Herramientas de importación/exportación de datos: Se corrigió un error al ejecutar tsfile load mientras ya existe una base de datos nombrada con un prefijo root.. Metadatos del modelo de tabla: Se optimizó el manejo de caracteres especiales escapados con comillas invertidas en las vistas de tabla. Sincronización de datos de tubería: Al eliminar una tubería, hay procesos asincrónicos (por ejemplo, recuperación); el resultado de la ejecución asincrónica debe comunicarse al usuario Sincronización de datos de tubería: Drop pipe ya no espera el regreso del fregadero, lo que garantiza la eliminación completa de la tubería. Sincronización de datos de Pipe: Se corrigió el retraso en la parte del asignador al ejecutar los comandos de creación/inicio/detención/eliminación de Pipe. Sincronización de datos de Pipe: Se solucionó el problema de registro excesivo al reducir la cantidad de registros en el lado del receptor de Pipe. Sincronización de datos de tubería: Se solucionó un problema por el cual fallaba la división de un archivo ts en 1.3.x para sincronizar datos parciales con 2.x.

iotdb v2.0.12

Features & Improvements

SQL Injection Prevention: Refactored the table model's PreparedStatement to prevent SQL injection Cluster Management: Support IPv6 cluster deployment REST: REST API supports setting the client timezone Data Sync: Optimized filtering performance for non-first TAG columns in the table model Data Import/Export Tools: Degradation strategy for Load files Database Management: SHOW CREATE DATABASE/TOPIC/PIPE Computation - Query Execution - SQL Clauses: Optimize the error message when a select * query has too many columns Functions: Added time-frequency analysis function (FFT) Functions: Added filtering functions (HighPass, LowPass) Latest Point Cache: The latest point cache supports being enabled/disabled at table/database granularity Functions: Built-in rate/increase/irate/delta aggregate functions for the table model Functions: Added sequence correlation function (XCorr) Functions: Built-in M4 table-valued function Functions: Time-series trend matching table-valued function Functions: Added the built-in table-valued function read_tsfile, supporting direct querying from a specified tsfile using SQL Tree Model Metadata: When creating a new time series under an existing device, ignore the aligned/unaligned attributes specified in the create statement and use the current device's aligned/unaligned attributes instead of reporting an error Measurement: Optimized the validation result of Measurement during cache writes Device-Granularity Deletion: Fixed an issue where, after deleting a table with a large amount of data and then re-creating the table and writing data, querying that table had high latency Memory Optimization: Memory optimization when copying the memtable TVList during queries Pipe Data Sync: Optimized the matching algorithm for ** Tree Model Metadata: Added a boolean flag to device nodes indicating whether there are other devices below, and tuned the query select measurement from xxx.** SQL Clauses: Performance optimization for full-table order by time + limit in the table model SQL Clauses: Memory optimization for full-table queries in the table model Pipe Data Sync: Optimized the Pipe memory block expansion/contraction algorithm

Bugs

Online File Merge: Fixed an issue where show disk_usage caused the merge to hang Tree Model Metadata: Fixed the "no matched database" issue Data Sync: Support storing TsFile parsing checkpoint progress, so that on retry after failure there is no need to re-parse the entire file Basic Write: Fixed an issue where, for the same aligned device, first writing a request with fewer columns and more rows and then writing a request with more columns and one row generated a WAL that, upon restarting the DataNode, caused severe memtable null-value expansion and ultimately caused the DataNode restart to hang TsFile Sync: When loading a tsfile, modify the replica set comparison logic: when comparing replica sets, no longer care about list order, only compare whether the elements within the sets are exactly identical; change the list comparison to a set comparison Pipe Data Sync: Fixed an issue where Pipe threw an NPE for null measurement points when converting a partial insert write into a tablet Pipe Data Sync: Fixed an issue where Pipe stopped after a tsfile parsing timeout Online File Merge: Fixed an issue where the merge did not fall back to copying when creating hard links failed Pipe Data Sync: Added per-Pipe independent memory quota limits or fair scheduling Pipe Data Sync: Implemented exponential backoff and circuit breaker protection for scenarios where the disk is full or the receiver is unavailable Pipe Data Sync: Added global and per-Pipe limits on in-flight TsFiles Pipe Data Sync: Fixed an issue where drop pipe did not wait for the sink's return Data Import/Export Tools: Fixed an error when executing tsfile load while a database named with a root. prefix already exists Table Model Metadata: Optimized the handling of special characters escaped with backticks in table views Pipe Data Sync: When deleting a Pipe there are asynchronous processes (e.g., recover); the asynchronous execution result needs to be communicated to the user Pipe Data Sync: Drop pipe no longer waits for the sink's return, ensuring complete removal of the Pipe Pipe Data Sync: Fixed the lag in the assigner portion when executing Pipe create/start/stop/delete commands Pipe Data Sync: Fixed the excessive logging issue by reducing the amount of logs on the Pipe receiver side Pipe Data Sync: Fixed an issue where splitting a tsfile in 1.3.x to sync partial data to 2.x failed
