Lanzamiento de OpenSandbox-1.2.1

Lanzamiento de parche estable para usuarios que actualizan desde 1.2.0, incluidos los candidatos de lanzamiento de 1.2.1 y las correcciones posteriores. El servidor, CLI, SDK, gráficos e imágenes de plataforma se envían juntos en 1.2.1.

Destacados

  • Credenciales dinámicas: Credential Vault Exchange resuelve las credenciales por solicitud en el servidor, la salida y los cinco SDK, sin persistencia en el almacén de los secretos resueltos (#2457 #2535 #2534 #2560).
  • VMM Fast Sandbox de múltiples versiones: los paquetes Firecracker 1.16.1/1.17.0 administrados permiten que las nuevas compilaciones de plantillas seleccionen la versión más alta instalada mientras los artefactos existentes se restauran con su versión exacta de VMM registrada, fallando explícitamente si no está disponible (#2795 #2812 fast-sandbox#189).
  • Administración de capacidad y datos más segura: las cargas por etapas reducen la pérdida de datos por sobrescritura cuando el reemplazo atómico está disponible, los reinicios del controlador preservan los pods de sandbox en vivo y Docker aplica las cuotas de disco de capa de escritura solicitadas (#2433 #2478 #2398 #2716).

Servidor

  • Llevar plantillas de CPU/memoria a través de la creación y restauración de instantáneas en grupos ResourceAware; los grupos heredados conservan su comportamiento existente (#2602 #2619 #2623 #2628 #2633).
  • Aplicar Docker resourceLimits.disk en la capa contenedora de escritura, devolviendo 400 para controladores no admitidos o límites no válidos en lugar de ignorarlos silenciosamente (#2716).
  • Permitir instantáneas de Docker directamente desde entornos sandbox pausados ​​(#1941).
  • Mueva la ruta de datos del servidor proxy al modo de mantenimiento; El tráfico existente sigue siendo compatible, pero las implementaciones deben migrar a la puerta de enlace de ingreso (#2548).
  • Rechazar campos desconocidos en objetos de solicitud cerrados en lugar de aceptar silenciosamente opciones mal escritas (#2576).
  • Reducir el tráfico de Kubernetes API y los costos de lista mediante la invalidación del informador por objeto y selectores de metadatos del lado del servidor (#2599 #2559).
  • Requerir que los artefactos de la plantilla OCI estén fijados con SHA-256 en el repositorio esperado (#2491).
  • Error en el inicio cuando no se puede restaurar la aplicación de la caducidad de Docker, excepto para los contenedores eliminados simultáneamente (#2533).
  • Otras correcciones mejoran el diagnóstico de tiempo de espera de creación y los límites de la sonda de pausa inactiva (#2434 #2596); Montaje Docker, ruta de host y validación de recursos (#2421 #2505 #2474 #2701 #2751); cuerpos GET del proxy y errores de agotamiento (#2518 #2519); y filtros de metadatos vacíos, validación de nombres y códigos de error API (#2461 #2499 #2702 #2703).

SDK

  • Los cinco SDK admiten fuentes de credenciales de intercambio y autenticación vinculante solo de credenciales; Los consumidores de Kotlin/C# deben recompilar y revisar los tipos de credenciales ampliados (#2534 #2560).
  • Los API de descarga detallada opcionales exponen el estado, los encabezados, los rangos y la detección de respuesta parcial sin necesidad de realizar cambios en los adaptadores existentes; Python/JavaScript/C# informan totales desconocidos cuando las longitudes codificadas no pueden describir la salida decodificada (#1597 #2592).
  • La documentación amplía las opciones de red/ciclo de vida, intercambia credenciales, flujos de trabajo de plantillas y ejemplos de S3 (#2590 #2597 #2620 #2506).

Python

  • MCP agrega command_get_status y command_get_logs para sondeo de comandos en segundo plano y salida incremental (#2648).
  • El comando silencioso SSE transmite ahora tiempo de espera; las descargas abandonadas liberan conexiones y las fallas de transmisión utilizan constantemente excepciones SDK (#2527 #2487 #2531 #2570 #2515 #2525).
  • El cierre elegante de la piscina elimina las muertes por la limpieza de los desagües en lugar de abandonar los areneros; Las correcciones más pequeñas cubren la invalidación de puntos finales, redirecciones/enganches de adaptadores y errores de MCP procesables (#2507 #2409 #2553 #2524).

JavaScript

  • Evitar que los tiempos de espera de comandos positivos de menos de milisegundos se vuelvan ilimitados; corrige plazos de redireccionamiento ilimitados, errores estructurados de sesiones aisladas y cierre de descargas durante la iteración (#2440 #2488 #2466 #2514).

Kotlin

  • Redondear el tiempo de espera de sesión/comando fraccional en milisegundos hacia arriba, evitando que los valores inferiores a milisegundos se vuelvan ilimitados (#2537). ###C#
  • Utilice el modelo común CredentialSource para variantes en línea y de intercambio; actualice los supuestos solo en línea al volver a compilar (#2560).

Ir

  • Preservar los fragmentos de salida del intérprete de código en Execution.Text() sin insertar nuevas líneas (#2447).
  • Aplique presupuestos de activación, estado de ejecución y preparación del intérprete sin truncar transmisiones establecidas ni aceptar sondas de preparación sin terminar (#2572 #2611 #2528 #2668 #2480 #2504).
  • Preservar la propiedad de la limpieza durante las operaciones canceladas de la piscina y cercar la destrucción incompleta para un nuevo intento; las adquisiciones canceladas ya no consumen capacidad inactiva en buen estado (#2542 #2617 #2580 #2616).
  • Proteger las búsquedas de puntos finales obsoletas después de cambios en el ciclo de vida sin cancelar las recuperaciones que aún necesitan otras personas que llaman (#2503 #2564 #2579).
  • Otras correcciones limitan el desbordamiento de reintentos y los retrasos proporcionados por el servidor (#2452 #2508 #2509); mejorar el análisis SSE, los límites multiparte y la combinación de encabezados (#2439 #2618 #2468 #2529); y mantenimiento correcto del grupo, plazos de telemetría y pruebas de tiempo de espera (#2453 #2565 #2540 #2479).

Controlador

  • Agregue cachés con ámbito de espacio de nombres, tiempos de elección de líder configurables y controller.extraArgs para ajustar la implementación (#2571 #2651 #2566).
  • Recuperar asignaciones de grupos antes del desalojo, protegiendo los pods de sandbox en vivo después de que se reinicia el controlador (#2398).
  • Rechazar las instantáneas de rootfs a las que les faltan los resúmenes requeridos y conservar sus Pods en lugar de eliminar el único tiempo de ejecución reanudable (#2482).
  • Otras correcciones evitan el crecimiento de la memoria relacionada con el ciclo de vida, eliminan el exceso de Pods inactivos después de las reducciones de poolMax y colocan el ConfigMap de recuperación en el espacio de nombres correcto (#2646 #2470 #2694).

Execd

  • Descubra los tokens de tiempo de ejecución de Jupyter cuando JUPYTER_TOKEN no esté configurado (#2448).
  • Realizar cargas y reemplazos de archivos aislados antes de cambiar el nombre para proteger el contenido existente; La atomicidad requiere un directorio que contenga escritura, con un permiso alternativo descrito a continuación (#2433 #2478).
  • Preservar los contenidos y modos del espacio de trabajo aislado durante la copia/cambio de nombre, respetar las eliminaciones de superposiciones y rechazar el chmod de enlace simbólico en lugar de seguir los objetivos del host (#2638 #2469).
  • Actualice MITM trust después de la rotación de CA del sidecar de salida de Kubernetes, evitando fallas persistentes de TLS (#2582).
  • Las ejecuciones aisladas ya no consumen entrada de control de shell; la eliminación de sesiones de Bash finaliza todas las ejecuciones activas y el cierre de PTY bloquea los trabajos en segundo plano normales, al tiempo que conserva un comportamiento similar al de terminal para los trabajos que ignoran HUP (#2517 #2731 #2733).
  • Restaurar los reintentos de inicio de Jupyter y la limpieza de sesiones, fallar rápidamente en idiomas no compatibles y entregar resultados/errores antes de completar el informe (#2486 #2689 #2606).
  • Recuperar la ejecución de SQL después de fallas temporales de configuración sin reproducir consultas automáticamente (#2757).
  • Refuerzo de seguridad: bytes de control de codificación porcentual en encabezados de descarga y codificación correcta de nombres de archivos RFC 8187 (#2741 #2516).
  • Otras correcciones cubren la correlación y validación del registro de comandos (#2598 #2686); Salida PTY y escapes exportados (#2644 #2772); validación de descarga/búsqueda y marcas de tiempo de archivos (#2451 #2687 #2604); Métricas de cgroup-v1 y representación de bytes de SQL (#2641 #2685); y una solución alternativa de SSE heredada para implementaciones anteriores de Kotlin/JVM (#2472).

Redes

salida

  • Credential Vault Exchange: resuelve encabezados nuevos a través de UDS/HTTPS utilizando identidades de espacio aislado derivadas de salida y objetivos de solicitud; la resolución falla y los secretos resueltos no se conservan ni se almacenan en caché en la bóveda (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563).
  • Aplicar políticas de puerto TCP por sujeto y puerto IP/CIDR plus por sujeto de Fast Sandbox, incluidas comprobaciones de destino original a través de MITM (#2662).
  • El operador Fast Sandbox de recarga en caliente deniega/permite reglas y límites de puertos accesibles sin reiniciar la salida; Los cambios se aplican de forma atómica entre los sujetos activos, conservando la política anterior sobre fallas y rechazando las respuestas DNS obsoletas después de la revocación. La guía de seguridad de red documenta los límites de implementación, precedencia y aplicación, al tiempo que conserva las URL de la guía anterior (#2727 #2814).
  • Permitir que la política de sidecar dns+nft PATCH/DELETE opte por bloquear el tráfico establecido con dropEstablished=true; Fast Sandbox no es compatible (#2346).
  • [EXPERIMENTAL] Fortalezca la propiedad/persistencia estricta de Actions v2 y la preparación del sujeto con vallas duraderas, sesiones infantiles autenticadas e instantáneas reconocidas de políticas/Vault; los valores predeterminados permanecen sin cambios (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708).
  • [EXPERIMENTAL] — no para producción: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound selecciona un experimento de protocolo de enlace TLS presupuestado, que no funciona con la inyección de credenciales o el reenvío de solicitudes: todo el tráfico de origen HTTP/1.1 y HTTP/2 descifrado aún está denegado. all sigue siendo el valor predeterminado; el lanzamiento de OSEP-0023 describe el trabajo sin terminar (#2737 #2797 #2777).
  • Correcciones de seguridad: el PARCHE de política conserva las reglas de denegación intactas y los valores defaultAction no válidos se rechazan en lugar de producir una aplicación inconsistente y potencialmente fallida (#2664 #2662 #2693).
  • Renovar las concesiones de DNS de Fast Sandbox en el kernel y preservar las concesiones de otros sujetos durante la eliminación (#2652 #2653).
  • Otro refuerzo cubre la validación experimental del puerto de interceptación, ganchos de preparación idempotentes y comprobaciones de humo/lectura de nft (#2587 #2510 #2543 #2735).

ingreso

  • Utilice un presupuesto de cola más espera y valídelo con la vida útil del vuelo; El enrutamiento de reactivación mixto regular/Fast Sandbox ya no entra en pánico al inicio (#2511 #2513 #2600).
  • Otras correcciones validan los puertos de nombres de host heredados, corrigen la telemetría de estado final/client-IP y eliminan una carrera de prueba de activación (#2578 #2484 #2688 #2512).

Actualización y compatibilidad

  • Firecracker administrado: implementa gráficos coincidentes, tiempo de ejecución e imágenes de creación; runtimeEnvironments → firecracker.firecracker.vmmDir ahora es compatible y debe hacer referencia a un directorio binario administrado absoluto. Las nuevas compilaciones administradas eligen la versión más alta instalada (actualmente 1.17.0); Las restauraciones completas/RootfsOnly requieren la versión registrada en el manifiesto y fallan si no está disponible, en lugar de recurrir a la versión más reciente. Mantenga los archivos binarios 1.16.1 para los artefactos existentes sin volver a etiquetarlos; conservar los archivos binarios antiguos no garantiza la compatibilidad con la degradación para el estado persistente de Fast Sandbox (#2795 #2812 fast-sandbox#189).
  • Validación de solicitud: elimine las claves desconocidas de los objetos de solicitud cerrados y use solo un alias ortográfico; estos ahora devuelven 422. Reemplace los extras de ImageAuth.token/Docker-config con username/password compatibles, elimine las nuevas líneas finales de los nombres/direcciones y use solo allow/deny para la política defaultAction (#2576 #2499 #2693).
  • Modelos de credenciales SDK: Kotlin/C# no son compatibles con ABI con 1.2.0; Recompilar y revisar fuentes ampliadas y suposiciones de autenticación anulables/sin tipo. La autenticación de Exchange contiene solo credential; Las fuentes en línea Python rechazan claves adicionales y los usuarios de modelos generados deberían preferir modelos escritos a mano. Utilice literales Go con clave para modelos de fuente/metadatos modificados y Execution; El viaje de ida y vuelta del JSON pierde el modo de formato privado del Execution.Text() (#2560 #2534 #2447).
  • Proxy/ingreso: migrar opciones de servidor-proxy de solo mantenimiento a ingreso; los puertos de nombres de host heredados deben ser decimales canónicos en 1–65535 y --wake-park-budget deben estar por debajo de --wake-max-flight-lifetime (#2548 #2578 #2511).
  • Cuotas de Docker: los límites de disk/storage/ephemeral-storage proporcionados deben ser positivos y compatibles con el controlador de almacenamiento o la creación devuelve 400. Solo se cubre la capa grabable, no se vinculan montajes, volúmenes ni capas de imágenes; Windows conserva su comportamiento de tamaño de disco existente (#2716).
  • Comprobación previa/inicio de Docker: corregir destinos de montaje duplicados, raíz, que contengan dos puntos o reservados y cantidades por encima del int64 firmado; una lista permitida de ruta de host / explícita autoriza a todos los descendientes de POSIX. Los fallos de restauración por caducidad ahora impiden el inicio a menos que el contenedor se haya eliminado al mismo tiempo; investigar errores persistentes del demonio (#2421 #2505 #2751 #2474 #2533).
  • Descargas: Los API detallados siguen siendo opcionales para adaptadores personalizados; verifique 206/isPartial y los rangos antes de agregar y cierre los cuerpos de respuesta. Los totales desconocidos utilizan -1; Las longitudes/rangos HTTP codificados no son progreso decodificado ni compensaciones de reanudación. Las personas que llaman Python deben detectar excepciones SDK en lugar de errores httpx sin procesar (#1597 #2592 #2515 #2525).
  • Tiempos de espera y sondeo: el comando Python transmite el tiempo de espera después de max(request_timeout, 30s) sin bytes; Levante request_timeout por un silencio legítimo. Los encuestadores de MCP deben leer los registros una vez más una vez finalizados y conservar los cursores opacos; la salida vacía no se completa. Las tiendas de grupos Custom Go deben respetar la cancelación y la destrucción incompleta permanece protegida para volver a intentarlo (#2527 #2648 #2580).
  • Atomicidad de la carga: utilice directorios que contengan permisos de escritura para cargas por etapas/reemplazos aislados; Los archivos grabables existentes recurren al truncamiento no atómico en caso de errores de permisos de preparación. El /files/replace normal permanece en su lugar. El reemplazo por etapas conserva los modos, no las etiquetas xattrs/ACL/capabilities/SELinux; la propiedad es el mejor esfuerzo para escrituras ordinarias y UID/GID de sesión para escrituras aisladas (#2433 #2478).
  • Cargar almacenamiento: los enlaces físicos/lectores abiertos conservan el inodo antiguo, las sobrescrituras de varias partes pueden necesitar aproximadamente tres veces el tamaño del archivo y los escritores interrumpidos pueden dejar archivos provisionales. Evite los nombres reservados .osb-upload-/.osb-staging-, especialmente un prefijo más 16 dígitos hexadecimales; cambiar el nombre de las colisiones existentes directamente. Los destinos de archivos especiales se rechazan, mientras que los archivos abiertos/montados en enlace pueden impedir el cambio de nombre; la sincronización de directorios es el mejor esfuerzo (#2433 #2478).
  • Ciclo de vida de la sesión: la entrada estándar de primer plano aislada ahora es /dev/null; utilice archivos o documentos aquí. La eliminación de la sesión Bash finaliza todas las ejecuciones superpuestas; El cierre de PTY agrega SIGHUP y hasta 500 ms antes de la eliminación del grupo, mientras que los trabajos que ignoran nohup/HUP pueden sobrevivir (#2517 #2731 #2733).
  • Jupyter/JVM: las imágenes personalizadas necesitan un token explícito o archivos de token de tiempo de ejecución detectables y el kernel solicitado. Prefiera sandbox-api 1.0.18+ sombreado en lugar de EXECD_SSE_LEGACY_COMPAT, que está desactivado de forma predeterminada y elimina los valores estructurados de exit_code (#2448 #2689 #2472).
  • Configuración del controlador: el alcance de la caché debe incluir todos los espacios de nombres administrados, además de los espacios de nombres del entorno de ejecución/plantilla Fast Sandbox; no cambia el RBAC ni proporciona aislamiento a los inquilinos. Revise controller.podRecovery.*, que ahora entra en vigor, y elimine los ConfigMaps obsoletos que dejaron las actualizaciones de manifiesto simple. Los tiempos de elección personalizados requieren arrendamiento > renovar > 1.2×reintentar (#2571 #2581 fast-sandbox#161 #2694 #2651).
  • Implementación de Exchange: alinear el servidor/SDK/versiones de salida; el tiempo de ejecución de la revisión en vivo del sidecar no admite el intercambio. La autenticación de la persona que llama del solucionador no está implementada: Ed25519/JWKS sigue siendo solo de diseño. Utilice un UDS protegido o HTTPS de solo salida trust con CA trusted; Las reglas de permiso de sandbox no deben exponer los solucionadores, y la exclusión de MITM UID por sí sola no es aislamiento (#2501 #2549 #2631 #2547).
  • [EXPERIMENTAL] Acciones estrictas v2: habilita la coincidencia de valores de OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion de sandbox.fast.io/actions/v2 solo en implementaciones directas de Firecracker de base limpia con estado duradero, puertos de administración aislados y autorización de administrador. La pausa/reanudación, las instantáneas/restauración, la eliminación de enlaces activos, la migración del propietario y la reutilización del mismo UID siguen sin ser compatibles; utilice la eliminación de terminales/nuevos UID, conserve las barreras y nunca trate las barreras como autenticación ni degrade el estado existente a v1 (#2441 #2460 #2493 #2546 fast-sandbox#152).
  • [EXPERIMENTAL] Intercepción vinculada a credenciales: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound aún niega el reenvío de aplicaciones descifradas y no debe habilitarse en producción. Con el conmutador no configurado, ambas puertas heredadas habilitadas siguen siendo un alias obsoleto; El tiempo de ejecución de revisión por sí solo es solo de instalación. Conflictos explícitos de modo/puerta, valores vacíos/desconocidos y configuración de este interruptor en el inicio fallido del sidecar (#2737 #2797).
  • Requisitos de inicio experimental: el modo vinculado a credenciales requiere MITM transparente, dns+nft y solo puertos de interceptación predeterminados 80,443; elimine la verificación TLS insegura, los proxies encadenados y el ignore_hosts/allow_hosts efectivo. El usuario de tiempo de ejecución config.yaml y luego config.yml están marcados; Los errores de lectura/análisis fallan y se cierran. Para regresar a all, desactive ambas puertas heredadas; La revisión en vivo del sidecar también rechaza puertos de interceptación adicionales (#2587 #2797).
  • Políticas de puertos: Fast Sandbox solo admite TCP, como máximo 256 puertos por regla y no admite combinaciones de dominio y puerto; las actualizaciones normales preservan los flujos establecidos. dropEstablished solo se admite en dns+nft sidecar PATCH/DELETE, se ignora mediante POST y no se admite en los modos Fast Sandbox, solo dns, revisión en vivo o proxy encadenado más MITM transparente; instala caídas de paquetes, no restablecimientos de TCP. La eliminación de un permiso de solo puerto por sí solo no activa el bloqueo del flujo establecido (#2662 #2346).
  • Recarga de reglas del operador: Fast Sandbox recarga archivos de reglas mutables en tiempo de ejecución en un tic de un minuto; monte ConfigMaps como directorios, no subPath, y permita el retraso de proyección de kubelet. Las reglas basadas en imágenes aún requieren una nueva imagen y recreación. Las recargas exitosas borran las concesiones aprendidas de DNS, por lo que los dominios permitidos necesitan otra búsqueda; las recargas fallidas conservan la superposición anterior y las conexiones establecidas no se terminan por la fuerza (#2727 #2814).
  • Límites de seguridad de la red: el dominio niega el filtro DNS, no las conexiones directas a IP conocidas; utilice denegaciones IP/CIDR explícitas o políticas de denegación predeterminadas para esas rutas. El operador niega la anulación que el operador permite, por lo que los servicios internos permitidos requieren una exclusión del rango de denegación. La creación clásica de Docker/Kubernetes inyecta salida solo cuando se suministra networkPolicy; poolRef más networkPolicy no son compatibles, por lo tanto, configure controles agrupados en la plantilla (#2814).
  • Lanzamiento de ResourceAware: direct-Firecracker resource-admission.json pasa de v2 a v3; Los Fastlets antiguos/nuevos rechazan la otra versión de configuración, por lo tanto, coordine las actualizaciones del controlador/Fastlet por grupo. Los latidos del corazón permanecen v2. Los hosts requieren cgroup v2 grabable, clone3(CLONE_INTO_CGROUP) y cero intercambio de grupo efectivo; el límite de memoria compartida no es una protección por máquina virtual ni una garantía de supervivencia durante el reemplazo de contenedores (#2626 fast-sandbox#162).
  • Restaurar tamaño: Los grupos ResourceAware utilizan formas de plantilla de CPU/memoria; Las nuevas instantáneas reproducen los límites de origen, que deben coincidir con los límites de las personas que llaman en el tiempo de restauración. Los grupos heredados y las instantáneas sin límites registrados conservan su comportamiento anterior (#2623 #2628 #2633).
  • [EXPERIMENTAL] RootfsOnly: Completo sigue siendo el valor predeterminado; El modo RootfsOnly explícito está disponible a través de Fast Sandbox FastPath/CRD para instantáneas OCI reutilizables, no pausar/reanudar ni la selección del modo OpenSandbox REST/SDK. La nueva captura requiere plantillas Firecracker 1.17.0 parcheadas calificadas, un asistente invitado en vivo, backend kernel/OverlayBD calificado, propiedad exclusiva de ext4 y un perfil FAST_SANDBOX_ROOTFS_QUALIFICATION absoluto con resúmenes/certificación de almacenamiento coincidentes; Los resúmenes binarios personalizados no pasan por alto la puerta de versión. Actualice el tiempo de ejecución, Fastlet/Proxy, el generador y las herramientas juntos, reconstruya plantillas calificadas y conserve diarios/vallas. Restaura los arranques en frío y vuelve a ejecutar el punto de entrada; no se promete ninguna preservación de la memoria de la aplicación ni portabilidad validada entre CPU/arquitectura (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189).
  • Compilaciones de plantillas de OverlayBD: la inyección de control de invitados y la validación de congelación/descongelación ahora son obligatorias para el generador de OCI; FSB_GUEST_CONTROL_ENABLED ya no es una opción de exclusión voluntaria. Los ayudantes faltantes/incompatibles o las sondas fallidas detienen la compilación. Las plantillas nativas no cambian; Las plantillas OCI existentes necesitan reconstrucción en lugar de ediciones de metadatos para obtener capacidad de captura (#2812 fast-sandbox#183).
  • Registros de Fast Sandbox: los componentes Kubernetes cubiertos ahora escriben archivos rotativos en /var/log/fast-sandbox de forma predeterminada (100 MiB por archivo, 10 copias de seguridad, retención de copias de seguridad de 7 días, gzip); Los registros de aplicaciones ya no aparecen en kubectl logs a menos que se configure alsoStderr: true. Reemplace los indicadores de salida de klog heredados con el registro compartido YAML, conecte montajes de ConfigMap/volumen de registro para cargas de trabajo estáticas administradas por gráficos y configure cada espacio de nombres de inquilino por separado. La configuración es solo de inicio: utilice el drenaje/reemplazo controlado del pool para Fastlets, no la eliminación de Pods activos, y organice la recopilación antes de que se pierdan los registros efímeros. La configuración explícita faltante o no válida o la salida no grabable impiden el inicio; Los límites de rotación no son una cuota de disco duro y no cubren los registros de invitados/VM (#2812 fast-sandbox#197).
  • Caché de punto de control OCI: reserva espacio para el caché de blobs adicional (valor predeterminado: 16 GiB, 4096 archivos, 1 GiB de reserva de espacio libre), por separado del caché de bloques de OverlayBD. Mantenga el estado provisional/caché/dispositivo en un sistema de archivos para la reutilización de enlaces físicos; La colocación o la contención entre sistemas de archivos recae en el registro. Configure FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 para deshabilitar la inserción/búsqueda de caché de blobs; los pines de los dispositivos activos permanecen protegidos, incluso cuando los presupuestos se reducen (#2812 fast-sandbox#178).
  • recuperación ublkd: la reconstrucción automática de archivos instantáneos compartidos se aplica solo cuando ningún otro arrendamiento de Sandbox necesita el archivo adjunto; no es una recuperación transparente de las máquinas virtuales en ejecución. Elimine los Sandboxes afectados durante su ciclo de vida normal antes de volver a intentarlo cuando queden otros arrendamientos, en lugar de borrar manualmente los cachés compartidos (#2812 fast-sandbox#193).
  • Reconstrucción de plantillas: la opción runtime.execd_run_as_init necesita plantillas reconstruidas; execd sigue siendo un subreaper bajo el PID invitado 1. Los informes de página libre también necesitan plantillas de almacén de objetos reconstruidas y compatibilidad con VMM/kernel, no pueden alternar el estado restaurado del dispositivo y no habilitan los informes OCI ni justifican un mayor compromiso excesivo; la reversión utiliza una plantilla anterior (#2494 #2497 #2546 fast-sandbox#114).
  • Valores predeterminados del gráfico OCI: los dispositivos ublk inactivos ahora están reservados; configure runtime.oci.poolLow=0 para la asignación bajo demanda y haga coincidir poolSizeGB con la capacidad de rootfs redondeada. P2P permanece habilitado de forma predeterminada; El runtime.config personalizado necesita un ajuste separado para la entrega de origen directo (#2594 fast-sandbox#163 #2566).
  • Integridad de la instantánea: los resúmenes de confirmación que faltan ahora fallan en la pausa mientras se retienen los Pods; las instantáneas antiguas no se reparan. Las referencias de plantillas OCI deben llevar un resumen SHA-256 completo en el repositorio esperado; reconstruir referencias no válidas (#2482 #2491).
  • Scripts CLI: los tiempos de espera de solicitudes no positivas y los objetivos de reglas vacíos son errores de uso; El rechazo de sobrescritura de osb config init ahora sale 1 sin cambiar el archivo (#2742 #2692 #2743).
  • Colección de consolas de VM: opte por vm-console, alinee hostPaths.vmConsole con la raíz del estado de ejecución, cubra todos los nodos de ejecución y administre la retención del receptor de archivos (#2234 #2677).

OpenSandbox release-1.2.1

Stable patch release for users upgrading from 1.2.0, including both 1.2.1 release candidates and subsequent fixes. Server, CLI, SDKs, charts, and platform images ship together at 1.2.1.

Highlights

  • Dynamic credentials: Credential Vault Exchange resolves credentials per request across the server, egress, and all five SDKs, without vault persistence of resolved secrets (#2457 #2535 #2534 #2560).
  • Multi-version Fast Sandbox VMMs: managed Firecracker 1.16.1/1.17.0 bundles let new template builds select the highest installed version while existing artifacts restore with their exact recorded VMM version, failing explicitly if it is unavailable (#2795 #2812 fast-sandbox#189).
  • Safer data and capacity management: staged uploads reduce overwrite data loss where atomic replacement is available, controller restarts preserve live-sandbox Pods, and Docker enforces requested writable-layer disk quotas (#2433 #2478 #2398 #2716).

Server

  • Carry template CPU/memory shapes through creation and snapshot restore on ResourceAware pools; legacy pools retain their existing behavior (#2602 #2619 #2623 #2628 #2633).
  • Enforce Docker resourceLimits.disk on the writable container layer, returning 400 for unsupported drivers or invalid limits instead of silently ignoring them (#2716).
  • Allow Docker snapshots directly from paused sandboxes (#1941).
  • Move the server-proxied data path into maintenance mode; existing traffic remains supported, but deployments should migrate to the ingress gateway (#2548).
  • Reject unknown fields in closed request objects rather than silently accepting misspelled options (#2576).
  • Reduce Kubernetes API traffic and list costs through per-object informer invalidation and server-side metadata selectors (#2599 #2559).
  • Require OCI template artifacts to be SHA-256-pinned in the expected repository (#2491).
  • Fail startup when Docker expiration enforcement cannot be restored, except for concurrently removed containers (#2533).
  • Other fixes improve create-timeout diagnostics and idle-pause probe bounds (#2434 #2596); Docker mount, host-path, and resource validation (#2421 #2505 #2474 #2701 #2751); proxy GET bodies and exhaustion errors (#2518 #2519); and empty metadata filters, name validation, and API error codes (#2461 #2499 #2702 #2703).

SDKs

  • All five SDKs support exchange credential sources and credential-only binding auth; Kotlin/C# consumers must recompile and review widened credential types (#2534 #2560).
  • Optional detailed download APIs expose status, headers, ranges, and partial-response detection without requiring changes to existing adapters; Python/JavaScript/C# report unknown totals when encoded lengths cannot describe decoded output (#1597 #2592).
  • Documentation expands lifecycle/network options, exchange credentials, template workflows, and S3 examples (#2590 #2597 #2620 #2506).

Python

  • MCP adds command_get_status and command_get_logs for background-command polling and incremental output (#2648).
  • Silent command SSE streams now time out; abandoned downloads release connections, and streaming failures consistently use SDK exceptions (#2527 #2487 #2531 #2570 #2515 #2525).
  • Graceful pool shutdown drains cleanup kills rather than abandoning sandboxes; smaller fixes cover endpoint invalidation, adapter redirects/hooks, and actionable MCP errors (#2507 #2409 #2553 #2524).

JavaScript

  • Prevent positive sub-millisecond command timeouts from becoming unbounded; fix unlimited redirect deadlines, structured isolated-session errors, and closing downloads during iteration (#2440 #2488 #2466 #2514).

Kotlin

  • Round fractional command/session timeout milliseconds upward, preventing sub-millisecond values from becoming unbounded (#2537).

C#

  • Use the common CredentialSource model for inline and exchange variants; update inline-only assumptions when recompiling (#2560).

Go

  • Preserve code-interpreter output fragments in Execution.Text() without inserting newlines (#2447).
  • Enforce wake, Running-state, and interpreter-readiness budgets without truncating established streams or accepting unfinished readiness probes (#2572 #2611 #2528 #2668 #2480 #2504).
  • Preserve cleanup ownership during cancelled pool operations and fence incomplete destruction for retry; cancelled acquires no longer consume healthy idle capacity (#2542 #2617 #2580 #2616).
  • Fence stale endpoint lookups after lifecycle changes without cancelling fetches still needed by other callers (#2503 #2564 #2579).
  • Other fixes bound retry overflow and server-supplied delays (#2452 #2508 #2509); improve SSE parsing, multipart boundaries, and header merging (#2439 #2618 #2468 #2529); and correct pool maintenance, telemetry deadlines, and timeout tests (#2453 #2565 #2540 #2479).

Controller

  • Add namespace-scoped caches, configurable leader-election timings, and controller.extraArgs for deployment tuning (#2571 #2651 #2566).
  • Recover pool allocations before eviction, protecting live-sandbox Pods after controller restarts (#2398).
  • Reject rootfs snapshots missing required digests and retain their Pods instead of deleting the only resumable runtime (#2482).
  • Other fixes prevent lifecycle-related memory growth, remove excess idle Pods after poolMax reductions, and place the recovery ConfigMap in the correct namespace (#2646 #2470 #2694).

Execd

  • Discover Jupyter runtime tokens when JUPYTER_TOKEN is unset (#2448).
  • Stage uploads and isolated-file replacements before rename to protect existing content; atomicity requires a writable containing directory, with an in-place permission fallback described below (#2433 #2478).
  • Preserve isolated-workspace contents and modes during copy-up/rename, honor overlay deletions, and reject symlink chmod rather than following host targets (#2638 #2469).
  • Refresh MITM trust after Kubernetes egress-sidecar CA rotation, avoiding persistent TLS failures (#2582).
  • Isolated runs no longer consume shell control input; deleting Bash sessions terminates all active runs, and PTY close hangs up ordinary background jobs while retaining terminal-like behavior for HUP-ignoring jobs (#2517 #2731 #2733).
  • Restore Jupyter startup retries and session cleanup, fail unsupported languages promptly, and deliver output/errors before reporting completion (#2486 #2689 #2606).
  • Recover SQL execution after temporary setup failures without automatically replaying queries (#2757).
  • Security hardening: percent-encode control bytes in download headers and correct RFC 8187 filename encoding (#2741 #2516).
  • Other fixes cover command-log correlation and validation (#2598 #2686); PTY output and exported escapes (#2644 #2772); download/search validation and file timestamps (#2451 #2687 #2604); cgroup-v1 metrics and SQL byte rendering (#2641 #2685); and an opt-in legacy SSE workaround for older Kotlin/JVM deployments (#2472).

Networking

egress

  • Credential Vault Exchange: resolve fresh headers through UDS/HTTPS using egress-derived sandbox identity and request targets; resolution fails closed, and resolved secrets are neither persisted nor cached by the vault (#2457 #2495 #2500 #2501 #2535 #2538 #2539 #2547 #2549 #2563).
  • Enforce Fast Sandbox per-subject TCP port and IP/CIDR-plus-port policies, including original-destination checks through MITM (#2662).
  • Hot-reload Fast Sandbox operator deny/allow rules and reachable-port caps without restarting egress; changes apply atomically across active subjects, retaining the previous policy on failure and rejecting stale DNS answers after revocation. The network-security guide documents deployment, precedence, and enforcement boundaries while preserving old guide URLs (#2727 #2814).
  • Allow dns+nft sidecar policy PATCH/DELETE to opt into blocking established traffic with dropEstablished=true; Fast Sandbox is not supported (#2346).
  • [EXPERIMENTAL] Harden strict Actions v2 ownership/persistence and subject readiness with durable fences, authenticated child sessions, and acknowledged policy/Vault snapshots; defaults remain unchanged (#2441 #2460 #2493 #2586 #2589 #2609 #2634 #2649 #2666 #2708).
  • [EXPERIMENTAL] — not for production: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound selects a budgeted TLS handshake experiment, not working credential injection or request forwarding: all decrypted HTTP/1.1 and HTTP/2 origin traffic is still denied. all remains the default; the OSEP-0023 rollout describes unfinished work (#2737 #2797 #2777).
  • Security fixes: policy PATCH preserves untouched deny rules, and invalid defaultAction values are rejected rather than producing inconsistent, potentially fail-open enforcement (#2664 #2662 #2693).
  • Renew Fast Sandbox DNS leases in the kernel and preserve other subjects' leases during deletion (#2652 #2653).
  • Other hardening covers experimental interception-port validation, idempotent readiness hooks, and nft smoke/read-back checks (#2587 #2510 #2543 #2735).

ingress

  • Use one queue-plus-wait wake budget and validate it against flight lifetime; mixed regular/Fast Sandbox wake routing no longer panics at startup (#2511 #2513 #2600).
  • Other fixes validate legacy hostname ports, correct final-status/client-IP telemetry, and remove a wake-test race (#2578 #2484 #2688 #2512).

Fast Sandbox

  • Bundle managed Firecracker 1.16.1/1.17.0 binaries for runtime and template builds, selecting the exact artifact-recorded version for restore rather than silently using the latest installed VMM (#2795 #2812 fast-sandbox#189).
  • Isolate ResourceAware direct-Firecracker VMMs in a bounded cgroup subtree, protecting Fastlet from pool-local OOM while retaining failed-runtime identities for cleanup (#2626 fast-sandbox#162).
  • Enable free-page reporting in new object-store templates, returning guest-freed memory to the host without changing static resource commitments; OCI templates are not yet supported (#2546 fast-sandbox#114).
  • Improve OCI storage with reusable warm ublk devices and best-effort checkpoint/rootfs layer compaction (#2594 fast-sandbox#163 #2546 fast-sandbox#158).
  • Reuse locally published OCI checkpoint blobs for faster same-node resume, with bounded storage, protection for live-device references, and registry fallback (#2812 fast-sandbox#178).
  • [EXPERIMENTAL] RootfsOnly OCI snapshots now extend from runtime capture to Fast Sandbox's FastPath and SandboxSnapshot CRD, with capability checks, produced-mode validation, and journaled recovery. Restores cold-boot without preserving memory; OpenSandbox REST/SDK mode selection and RootfsOnly pause/resume remain unsupported (#2706 fast-sandbox#173 #2812 fast-sandbox#177).
  • OverlayBD template builds now inject guest-control and validate freeze/thaw by default; existing templates need rebuilding to gain RootfsOnly capture capability (#2812 fast-sandbox#183).
  • Add shared YAML-configured file logging and rotation for first-party Kubernetes components, with optional stderr mirroring; log collectors and custom launch flags need migration (#2812 fast-sandbox#197).
  • Expose timestamped template-build phases, elapsed times, and failures across image pull, rootfs preparation, guest readiness, snapshotting, and publication (#2815 fast-sandbox#201).
  • [EXPERIMENTAL] Fence delayed strict Actions v2 operations with durable owner identity and confirmed retirement; v1 remains the default (#2546 fast-sandbox#152).
  • Add namespace/API-client tuning, chart scheduling hooks, optional direct-origin delivery, and template-baked execd init mode (#2581 fast-sandbox#161 #2566 #2494 #2497).
  • Immediate create/pause/resume transitions now converge without settle delays, and active pools replace terminal Fastlet Pods instead of counting them as capacity (#2626 fast-sandbox#166 #2706 fast-sandbox#172).
  • Recover idle shared snapfiles attachments after ublkd device loss without manual cache wipes; attachments with other Sandbox leases remain protected rather than being rebuilt under live consumers (#2812 fast-sandbox#193).
  • Other fixes cover BusyBox-based template readiness, timestamp precision, and existing-secret rendering (#2626 fast-sandbox#164 #2706 fast-sandbox#170 #2695); restore cache-affinity matching for Firecracker image/template references (#2812 fast-sandbox#119).
  • Expand ResourceAware rollout coverage and correct fixture CPU budgets without changing saturation capacity (#2622 #2637 #2647 #2669 #2812); improve ublk recovery, exchange/console integration tests, KVM selection, and snapshot-staging documentation (#2454 #2561 #2676 #2665 #2714); gate PR KVM runs on maintainer-added ok-to-test, without unrelated labels cancelling an active run (#2813).

Misc

Upgrade & Compatibility

  • Managed Firecracker: deploy matching charts, runtime, and builder images; runtimeEnvironments → firecracker.firecracker.vmmDir is now supported and must reference an absolute managed-binary directory. New managed builds choose the highest installed version (currently 1.17.0); Full/RootfsOnly restores require the manifest-recorded version and fail if it is unavailable, rather than falling back to latest. Keep 1.16.1 binaries for existing artifacts without relabeling them; retaining old binaries does not guarantee downgrade compatibility for persisted Fast Sandbox state (#2795 #2812 fast-sandbox#189).
  • Request validation: remove unknown keys from closed request objects and use only one alias spelling; these now return 422. Replace ImageAuth.token/Docker-config extras with supported username/password, remove trailing newlines from names/addresses, and use only allow/deny for policy defaultAction (#2576 #2499 #2693).
  • SDK credential models: Kotlin/C# are not ABI-compatible with 1.2.0; recompile and review widened sources and nullable/typeless auth assumptions. Exchange auth contains only credential; Python inline sources reject extra keys, and generated-model users should prefer handwritten models. Use keyed Go literals for changed source/metadata models and Execution; JSON round-tripping loses Execution.Text()'s private formatting mode (#2560 #2534 #2447).
  • Proxy/ingress: migrate maintenance-only server-proxy options to ingress; legacy hostname ports must be canonical decimals in 1–65535, and --wake-park-budget must be below --wake-max-flight-lifetime (#2548 #2578 #2511).
  • Docker quotas: supplied disk/storage/ephemeral-storage limits must be positive and supported by the storage driver or creation returns 400. Only the writable layer is covered, not bind mounts, volumes, or image layers; Windows retains its existing disk-size behavior (#2716).
  • Docker preflight/startup: correct duplicate, root, colon-containing, or reserved mount destinations and quantities above signed int64; an explicit / host-path allowlist authorizes all POSIX descendants. Expiration-restore failures now prevent startup unless the container was concurrently removed; investigate persistent daemon errors (#2421 #2505 #2751 #2474 #2533).
  • Downloads: detailed APIs remain optional for custom adapters; check 206/isPartial and ranges before appending, and close response bodies. Unknown totals use -1; encoded HTTP lengths/ranges are not decoded progress or resume offsets. Python callers should catch SDK exceptions rather than raw httpx errors (#1597 #2592 #2515 #2525).
  • Timeouts and polling: Python command streams time out after max(request_timeout, 30s) without bytes; raise request_timeout for legitimate silence. MCP pollers must read logs once more after completion and retain opaque cursors; empty output is not completion. Custom Go pool stores must honor cancellation, and incomplete destruction stays fenced for retry (#2527 #2648 #2580).
  • Upload atomicity: use writable containing directories for staged uploads/isolated replacements; existing writable files fall back to non-atomic truncation on staging permission errors. Ordinary /files/replace remains in-place. Staged replacement preserves modes, not xattrs/ACLs/capabilities/SELinux labels; ownership is best effort for ordinary writes and session UID/GID for isolated writes (#2433 #2478).
  • Upload storage: hardlinks/open readers retain the old inode, multipart overwrites may need roughly three times the file size, and interrupted writers can leave staging files. Avoid reserved .osb-upload-/.osb-staging- names, especially a prefix plus 16 hex digits; rename existing collisions directly. Special-file targets are rejected, while bind-mounted/open files can prevent rename; directory sync is best effort (#2433 #2478).
  • Session lifecycle: isolated foreground stdin is now /dev/null; use files or here-documents. Bash-session deletion terminates all overlapping runs; PTY close adds SIGHUP and up to 500 ms before group kill, while nohup/HUP-ignoring jobs can survive (#2517 #2731 #2733).
  • Jupyter/JVM: custom images need an explicit token or discoverable runtime token files and the requested kernel. Prefer shaded sandbox-api 1.0.18+ over EXECD_SSE_LEGACY_COMPAT, which is off by default and removes structured exit_code values (#2448 #2689 #2472).
  • Controller configuration: cache scope must include all managed namespaces, plus Fast Sandbox template/runtime-environment namespaces; it does not change RBAC or provide tenant isolation. Review controller.podRecovery.*, which now takes effect, and remove obsolete ConfigMaps left by plain-manifest upgrades. Custom election timings require lease > renew > 1.2×retry (#2571 #2581 fast-sandbox#161 #2694 #2651).
  • Exchange deployment: align server/SDK/egress versions; the sidecar live revision runtime does not support exchange. Resolver caller authentication is not implemented—Ed25519/JWKS remains design-only. Use a protected UDS or trusted-egress-only HTTPS with trusted CAs; sandbox allow rules must not expose resolvers, and MITM UID exclusion alone is not isolation (#2501 #2549 #2631 #2547).
  • [EXPERIMENTAL] Strict Actions v2: enable matching OPENSANDBOX_EGRESS_ACTIONS_API_VERSION/Fastlet actionsApiVersion values of sandbox.fast.io/actions/v2 only on clean-base direct-Firecracker deployments with durable state, isolated management ports, and manager authorization. Pause/resume, snapshots/restore, live binding removal, owner migration, and same-UID reuse remain unsupported; use terminal deletion/new UIDs, preserve fences, and never treat fencing as authentication or downgrade existing state to v1 (#2441 #2460 #2493 #2546 fast-sandbox#152).
  • [EXPERIMENTAL] Credential-bound interception: OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound still denies decrypted application forwarding and must not be enabled in production. With the switch unset, both legacy gates enabled remain a deprecated alias; revision-runtime alone is installation-only. Explicit mode/gate conflicts, empty/unknown values, and setting this switch on sidecar fail startup (#2737 #2797).
  • Experimental startup requirements: credential-bound mode requires transparent MITM, dns+nft, and only default interception ports 80,443; remove insecure TLS verification, chained proxies, and effective ignore_hosts/allow_hosts. Runtime-user config.yaml then config.yml are checked; read/parse errors fail closed. To return to all, unset both legacy gates; sidecar live revision also rejects extra interception ports (#2587 #2797).
  • Port policies: Fast Sandbox supports TCP only, at most 256 ports per rule, and no domain-plus-port combinations; normal updates preserve established flows. dropEstablished is supported only on dns+nft sidecar PATCH/DELETE, ignored by POST, and unsupported in Fast Sandbox, dns-only, live-revision, or chained-proxy-plus-transparent-MITM modes; it installs packet drops, not TCP resets. Removing a port-only allow alone does not trigger established-flow blocking (#2662 #2346).
  • Operator-rule reload: Fast Sandbox reloads runtime-mutable rule files on a one-minute tick; mount ConfigMaps as directories, not subPath, and allow for kubelet projection delay. Image-baked rules still require a new image and recreation. Successful reloads clear DNS-learned leases, so allowed domains need another lookup; failed reloads retain the previous overlay, and established connections are not forcibly terminated (#2727 #2814).
  • Network-security boundaries: domain denies filter DNS, not direct connections to known IPs; use explicit IP/CIDR denies or default-deny policies for those paths. Operator denies override operator allows, so permitted internal services require a deny-range carve-out. Classic Docker/Kubernetes creation injects egress only when networkPolicy is supplied; poolRef plus networkPolicy is unsupported, so configure pooled controls in the template (#2814).
  • ResourceAware rollout: direct-Firecracker resource-admission.json moves from v2 to v3; old/new Fastlets reject the other configuration version, so coordinate controller/Fastlet upgrades per pool. Heartbeats remain v2. Hosts require writable cgroup v2, clone3(CLONE_INTO_CGROUP), and zero effective pool swap; the shared memory ceiling is not per-VM protection or a guarantee of survival across container replacement (#2626 fast-sandbox#162).
  • Restore sizing: ResourceAware pools use template CPU/memory shapes; new snapshots replay source limits, which restore-time caller limits must match. Legacy pools and snapshots without recorded limits retain their prior behavior (#2623 #2628 #2633).
  • [EXPERIMENTAL] RootfsOnly: Full remains the default; explicit RootfsOnly mode is available through Fast Sandbox FastPath/CRDs for reusable OCI snapshots, not pause/resume or OpenSandbox REST/SDK mode selection. New capture requires qualified patched Firecracker 1.17.0 templates, a live guest helper, qualified kernel/OverlayBD backend, exclusive ext4 ownership, and an absolute FAST_SANDBOX_ROOTFS_QUALIFICATION profile with matching digests/storage attestation; custom binary digests do not bypass the version gate. Upgrade runtime, Fastlet/Proxy, builder, and tools together, rebuild qualified templates, and preserve journals/fences. Restore cold-boots and reruns the entrypoint; no application-memory preservation or validated cross-CPU/architecture portability is promised (#2706 fast-sandbox#173 #2812 fast-sandbox#177 fast-sandbox#189).
  • OverlayBD template builds: guest-control injection and freeze/thaw validation are now mandatory for the OCI builder; FSB_GUEST_CONTROL_ENABLED is no longer an opt-out. Missing/incompatible helpers or failed probes stop the build. Native templates are unchanged; existing OCI templates need rebuilding rather than metadata edits to gain capture capability (#2812 fast-sandbox#183).
  • Fast Sandbox logs: covered Kubernetes components now write rotating files under /var/log/fast-sandbox by default (100 MiB per file, 10 backups, 7-day backup retention, gzip); application logs no longer appear in kubectl logs unless alsoStderr: true is configured. Replace legacy klog output flags with the shared logging YAML, wire ConfigMap/log-volume mounts for chart-managed static workloads, and configure each tenant namespace separately. Configuration is startup-only: use controlled Pool draining/replacement for Fastlets, not deletion of live Pods, and arrange collection before ephemeral logs are lost. Explicit missing/invalid configuration or unwritable output prevents startup; rotation limits are not a hard disk quota and do not cover guest/VM logs (#2812 fast-sandbox#197).
  • OCI checkpoint cache: reserve space for the additional blob cache (defaults: 16 GiB, 4096 files, 1 GiB free-space reserve), separately from OverlayBD's block cache. Keep staging/cache/device state on one filesystem for hard-link reuse; cross-filesystem placement or contention falls back to the registry. Set FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0 to disable blob-cache insertion/lookups; active-device pins remain protected, including when budgets shrink (#2812 fast-sandbox#178).
  • ublkd recovery: automatic shared-snapfiles rebuilding applies only when no other Sandbox lease needs the attachment; it is not transparent recovery of running VMs. Remove affected Sandboxes through their normal lifecycle before retrying when other leases remain, rather than manually wiping shared caches (#2812 fast-sandbox#193).
  • Template rebuilds: opt-in runtime.execd_run_as_init needs rebuilt templates; execd remains a subreaper beneath guest PID 1. Free-page reporting also needs rebuilt object-store templates and compatible VMM/kernel support, cannot toggle restored device state, and does not enable OCI reporting or justify higher overcommit; rollback uses an older template (#2494 #2497 #2546 fast-sandbox#114).
  • OCI chart defaults: idle ublk devices are now reserved; set runtime.oci.poolLow=0 for on-demand allocation and match poolSizeGB to rounded-up rootfs capacity. P2P remains enabled by default; custom runtime.config needs separate adjustment for direct-origin delivery (#2594 fast-sandbox#163 #2566).
  • Snapshot integrity: missing commit digests now fail pause while retaining Pods; old snapshots are not repaired. OCI template references must carry a full SHA-256 digest in the expected repository; rebuild invalid references (#2482 #2491).
  • CLI scripts: non-positive request timeouts and empty rule targets are usage errors; osb config init overwrite refusal now exits 1 without changing the file (#2742 #2692 #2743).
  • VM console collection: opt in to vm-console, align hostPaths.vmConsole with the runtime state root, cover every runtime node, and manage file-sink retention (#2234 #2677).
  • Artifact verification: umbrella workflows do not provide blanket signing/provenance coverage; BOM digest matching is not proof of origin, and signature requirements must not be bypassed (#2467).
  • Images: opensandbox/<component>:release-1.2.1 (all three registries; fsb images for fast-sandbox)

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.1            # Python
npm install @alibaba-group/opensandbox@1.2.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.1")
dotnet add package Alibaba.OpenSandbox --version 1.2.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.1

# Run the server locally
uvx opensandbox-server==1.2.1
