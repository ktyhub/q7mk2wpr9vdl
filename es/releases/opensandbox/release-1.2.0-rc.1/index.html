Lanzamiento de OpenSandbox-1.2.0-rc.1

Primer candidato de lanzamiento en la línea 1.2.0, que incluye todo lo fusionado desde release-1.1.1; el titular es OSEP-0024: pausa automática y activación al acceder para entornos sandbox rápidos, aterrizando de un extremo a otro. Las imágenes se publican ahora; Los paquetes SDK/CLI se envían en el tope estable 1.2.0. Pruebe e informe problemas.

Destacados

  • La pausa automática y la activación al acceder para entornos limitados rápidos (OSEP-0024) llegan de un extremo a otro: seguimiento de la actividad de ingreso y la ruta de activación, la barredora inactiva del lado del servidor, el campo de creación lifecycle.idlePolicy opcional y el contrato de reintento de activación en los cinco SDK: desactivados de forma predeterminada, solo aditivo (#2156 #2180 #2192 #2198 #2218)
  • Sidecar de salida (experimental, opcional): admisión a Vault vinculada a credenciales activas, compatibilidad con HTTP/2 con drenaje limitado, persistencia de archivos de políticas atómicas y contención de fallas en tiempo de ejecución (#2176 #2201 #2182 #2162 #2172)
  • Fiabilidad del SDK: las cargas y descargas de archivos ya no se cancelan tras un tiempo de espera de solicitud de 30 segundos en ninguno de los cinco SDK; execd ahora informa muertes de OOM y CPU en el ámbito de la zona de pruebas (#2165 #2186 #2196 #2206 #2191 #2200)

Servidor

  • Implementar el lado del servidor de la pausa automática OSEP-0024 para entornos sandbox rápidos: el campo de creación del ciclo de vida lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, activeProbe opcional) se valida con límites pydantic y persiste como la anotación CR reservada sandbox.opensandbox.io/idle-policy Sandbox (el error de escritura de la anotación permanece a prueba de fallas: el sandbox se crea sin políticas); un barredor inactivo enumera los entornos limitados de fsb habilitados desde el caché del informador, verifica la actividad en Redis (las escrituras monótonas máximas, las lápidas de claves faltantes solo pueden retrasar una pausa), toma un bloqueo de pausa por entorno de pruebas con nueva verificación bajo bloqueo y emite un FastPath idempotente PauseSandbox; un activeProbe declarado se ejecuta a través de la puerta de entrada y una respuesta de ocupado registra la actividad ordinaria; un centinela OpenSandbox-Skip-Activity: skip suprime la observación de una solicitud y se elimina tanto en los saltos de puerta de enlace como de servidor-proxy (#2192 #2181)
  • Configurar la pausa inactiva bajo el nuevo paraguas de automatización del ciclo de vida: [idle_pause] se convierte en [automation.idle_pause] y se elimina la puerta redundante redis.enabled; se requiere redis.dsn (validado en carga) cuando enabled = true, falla ruidosamente en lugar de no arrancar silenciosamente la barredora; configuration.md se reescribe para ser conciso y ahora documenta ingress.secure_access y las anulaciones de env-var que faltan (#2215)
  • Pods de BatchSandbox predeterminados en restartPolicy: Never: un reinicio del contenedor kubelet en el lugar recreó el contenedor principal a partir de su imagen (borrando la capa grabable y el estado en memoria) mientras el sandbox seguía informando Succeed; reiniciar nunca es una recuperación significativa para un sandbox, por lo que el valor predeterminado honesto es no reiniciar, lo que también hace que la ruta de falla del terminal del controlador sea accesible. Un restartPolicy explícito en la plantilla aún gana, el perfil de Windows sigue forzando Always (la instalación multifase depende de él) y el modo de grupo no cambia (#2128)
  • Trate a pasta/slirp4netns/none como modos de red en tiempo de ejecución de contenedor y páselos directamente, haciendo que la red a nivel de kernel de podman sea seleccionable: en Windows 11 + WSL2, donde netavark rompe el modo puente, pasta era la única red que funcionaba y anteriormente no se pudo crear con un 400 solicitando una red Docker definida por el usuario; networkPolicy ahora se rechaza para estos modos ya que no hay un puente al que conectar el sidecar de salida (anteriormente aceptado silenciosamente para none) (#2203)
  • Analizar marcas de tiempo de Docker cuya fracción de segundo no sea de 3 o 6 dígitos: Docker escribe RFC3339Nano (se eliminaron los ceros finales), Python 3.10 fromisoformat rechaza fracciones de 5 dígitos y el asistente volvió a datetime.now(), por lo que createdAt y status.lastTransitionAt informaron silenciosamente la situación actual. tiempo; la fracción ahora se rellena con ceros a 6 dígitos (#2220)

SDK

Los cambios de código a continuación se incluyen en la versión estable 1.2.0: rc no incluye paquetes SDK.

  • Agregue el contrato OSEP-0024 SDK a los cinco idiomas: un campo de creación lifecycle.idlePolicy escrito (modelos IdlePolicy/ActivityProbe con validación rápida a prueba de fallas del lado cli que refleja el servidor: tiempo de espera de 30 a 86400 s, emparejamiento de onIdle: "pause", ruta de sonda/límites de tiempo de espera; cableado a través de creación estándar y de plantilla) y el contrato de reintento de activación, activado un 503 que lleva el marcador OpenSandbox-Wake: expired propiedad de la puerta de enlace (su presencia prueba que la solicitud fue estacionada y nunca reenviada, lo que hace que cualquier método de reintento sea seguro), el SDK se reenvía después de Retry-After con un presupuesto limitado (5 intentos/60 s predeterminados, por perillas client), el agotamiento genera una excepción de tiempo de espera de activación escrita que lleva intentos y tiempo de espera, la reanudación del lado del servidor es nunca se cancela, el manejo de 503 básico no cambia y los transportes SSE/streaming omiten el reintento de activación (#2198 #2218)
  • Dejar de limitar las cargas y descargas de archivos en el tiempo de espera de la solicitud (30 s predeterminado) en los cuatro SDK restantes: el tiempo de espera de toda la llamada (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) cubría el envío del cuerpo de la solicitud y la lectura de la respuesta, por lo que cualquier transferencia grande o lenta fallaba en pleno vuelo incluso cuando estaba en buen estado; las transferencias ahora se ejecutan en un client dedicado sin una fecha límite para la llamada completa que aún limita la espera de los encabezados de respuesta, por lo que una transferencia estancada aún falla en lugar de colgarse (#2165 #2186 #2196 #2206)
  • Suprimir las métricas de sandbox.create client para las creaciones de calentamiento de client-pool en Go, Python y JavaScript, alineándose con Kotlin: tráfico de calentamiento (skipHealthCheck codificado, cientos de ms) previamente mezclado con métricas de latencia de creación orientadas al usuario y arrastrado p50/p99 hacia abajo; La creación directa desde la adquisición del grupo y las creaciones orientadas al usuario siguen generando informes (#2199)

Python

  • Limpieza del inicio del grupo asíncrono cancelado: la cancelación de SandboxPoolAsync.start() en mitad de la espera dejó la instancia atascada en STARTING, donde un start() posterior regresó silenciosamente y los recursos propiedad de la startup omitieron la limpieza; la cancelación ahora reutiliza la ruta de limpieza de conciliación, se mueve a STOPPED y vuelve a subir para que la persona que llama pueda volver a intentarlo (#2209)
  • Dejar de informar reemplazos de archivos fallidos como exitosos: los adaptadores de sistema de archivos ordinarios capturaron y descartaron el JSONDecodeError de client generado, por lo que un HTTP 400/500 vacío o no JSON de replace_contents() devolvió el éxito y un agente pudo seguir construyendo sobre una edición no aplicada; se elimina el bloqueo y se restablece el contrato de error SandboxException documentado (los adaptadores de sesión aislada mantienen su bloqueo de compatibilidad de cuerpo vacío) (#2222)

Ir

  • Elimina todos los encabezados OPEN-SANDBOX-*/OPENSANDBOX-* y todos los encabezados de autenticación configurados (incluidos X-EXECD-ACCESS-TOKEN, X-API-Key y nombres personalizados WithAuthHeader) en redireccionamientos entre orígenes, comparando cada destino con el esquema, el host y el puerto efectivo de la solicitud inicial para que las credenciales no puedan reaparecer en saltos posteriores de origen extranjero; se aplica en todo el ciclo de vida, execd, salida, transferencias de archivos, SSE y métricas de creación, preservando al mismo tiempo las políticas CheckRedirect personalizadas (#2178)

Controlador

  • Conservar un BatchSandbox hasta que se complete la limpieza: un sandbox eliminado podría desaparecer del ciclo de vida API (GET 404) mientras su pod propio aún se ejecuta, permitiendo que un sandbox de reemplazo escriba el mismo directorio persistente antes de que salga el escritor anterior; la eliminación ahora utiliza la eliminación en cascada en primer plano junto con los finalizadores de liberación de grupos y limpieza de tareas existentes, y la conciliación TTL se detiene una vez que se acepta la eliminación: DELETE aún devuelve 204 cuando se acepta, las consultas informan Stopping durante la limpieza administrada y 404 llega solo después de que finaliza el tiempo de ejecución; los documentos y registros de kill de los cinco SDK describen la semántica de eliminación aceptada (#2154)

Execd

  • Informar muertes de OOM a través del sondeo cgroupfs: la evidencia del lado del kernel estaba fuera del alcance desde el interior de una caja de arena (no CAP_SYSLOG, no /dev/kmsg), por lo que los eventos OOM no eran observables; execd ahora sondea el cgroup de sandbox cada 5 segundos y diferencia el contador de muertes OOM del kernel (memory.events en v2, mejor esfuerzo en v1); los contadores jerárquicos cubren cgroups anidados como sesiones aisladas de bwrap; exporta execd.system.oom.kills con un atributo de nivel local/descendant más registros de advertencia estructurados con atribución de víctima de mejor esfuerzo; el observador se ejecuta independientemente de la exportación OTLP y no necesita capacidades (#2191)
  • Informar métricas de CPU/memoria en el ámbito de la zona de pruebas: los medidores GET /metrics y execd.system.cpu.usage/execd.system.memory.usage_bytes leen /proc a través de gopsutil, que dentro de un contenedor describe el host; los paneles mostraban la memoria y la CPU de todo el host; cuando el cgroup de sandbox tiene límites configurados, el uso ahora proviene del propio cgroup de sandbox (cpu.stat/cpu.max, memory.current/memory.max, respaldo v1, los hosts híbridos prefieren v1), con la vista de host anterior mantenida para invitados ilimitados, como microVM de sandbox rápido; el formato del cable no ha cambiado (#2200)
  • Codificación porcentual de comillas y barras invertidas en Content-Disposition: un nombre de archivo que contiene " o \ produjo una cadena entre comillas que ningún analizador estándar acepta (mime.ParseMediaType la rechazó y clients no obtuvo ningún nombre de archivo); dichos nombres ahora se enrutan a través de la misma codificación filename*=UTF-8'' que los nombres que no son ASCII (#2161)
  • Analizar el encabezado Range antes de configurar los encabezados de descarga: un rango mal formado respondió 416 con los archivos Content-Disposition y Content-Length aún adjuntos, truncando el cuerpo del JSON o eliminándolo por completo, apareciendo en el Python SDK como un error de conexión en lugar de un 416 SandboxApiException; la respuesta de error ahora es un JSON 416 limpio y las respuestas 200/206 no han cambiado (#2216)

Redes

salida

Todos los elementos siguientes se refieren al tiempo de ejecución de revisión experimental OSEP-0023 predeterminado; Las implementaciones heredadas y de solo DNS no se modifican.

  • Agregar admisión experimental a Vault vinculada a credenciales en vivo: las mutaciones de Vault fluyen a través de la transacción de revisión e instalan la instantánea privada autenticada antes de publicar el resultado público; Las conexiones HTTPS vinculadas se admiten y las credenciales de encabezado se inyectan solo después de que la solicitud coincida exactamente con el acuerdo de autoridad SNI/HTTP/1 (la extensión ECH ClientHellos permanece opaca), con rotación de credenciales por solicitud, protección de enlaces eliminados en las conexiones existentes y retiro del transporte en la fecha límite de drenaje; el alcance es HTTPS de host exacto en 443 con HTTP/1.1 y credenciales de encabezado en línea (#2176)
  • Confirme las revisiones de la política en vivo antes de su publicación: la política API y las recargas automáticas deny.always/allow.always ahora se confirman en orden (persistencia de archivos opcional, aplicación nft, reconocimiento exacto del receptor o lectura reconciliada, luego publicación proxy y éxito de API) con recuperación cerrada ante fallas cuando el receptor falla después de que nft haya entrado en vigor y plazos de drenaje de 30 segundos en actualizaciones de solo políticas que nunca se extienden. en revisiones posteriores (#2182)
  • Agregue admisión HTTP/2 experimental y drenaje limitado: las instantáneas se vinculan atómicamente a los ID de flujo client reales en los encabezados de solicitud, las solicitudes posteriores a la valla obtienen REFUSED_STREAM antes de llegar al origen, GOAWAY espera las obligaciones de salida pendientes mientras el vencimiento usa un cierre anormal y un respaldo de salida de mitmdump de una sola vez cubre la propiedad de limpieza no verificable; el adaptador está fijado a CPython 3.10/3.11 y rechaza los proxies ascendentes encadenados configurados (#2201)
  • Contener fallas de recuperación de tiempo de ejecución en el espacio de nombres de la red sidecar: una salida MITM inesperada ahora activa una barrera IPv4/IPv6 independiente, verificada por relectura, anclada al espacio de nombres original durante la vida útil del proceso, bloqueando todo el tráfico de entrada/salida/reenvío, incluidas las conexiones existentes y el loopback, con QuarantineConfirmed reportado solo después de la lectura real de la regla; las mutaciones normales exitosas nunca introducen una barrera (#2172)
  • Persistir atómicamente los archivos de política de revisión experimental: las escrituras pasan por un inodo temporal del mismo directorio con fsync + renombrar + directorio fsync, las restauraciones devuelven exactamente los bytes anteriores (o ausencia sincronizada) y el almacenamiento no compatible (montajes de enlace de archivos, rutas de solo lectura o con enlaces simbólicos, enlaces duros, propiedad insegura, metadatos SELinux/IMA no compatibles) se rechaza antes de tocar el original; los operadores deben proporcionar un montaje de directorio escrito exclusivamente y de propiedad de salida existente (#2162)
  • Clasifique los efectos de aplicación de nft antes de la recuperación de la política: la construcción local, la cancelación previa al inicio y las fallas de inicio no se modifican (se conserva el estado, se permite el reintento después de la restauración), se confirma la ejecución exitosa y todos los errores posteriores al inicio o no clasificados se desconocen: cerrar la admisión del escritor y bloquear la recuperación antes de la restauración con el mejor esfuerzo; el respaldo de la tabla faltante conserva ambos errores y nunca degrada un resultado desconocido (#2167)

ingreso

  • Implementar seguimiento de actividad OSEP-0024 y reactivación al acceder: con --activity-enabled, cada solicitud enrutada registra una marca de tiempo de actividad monótona en Redis (disparar y olvidar, nunca en la ruta activa) con fusión de escritura por réplica, actualizaciones monotónicas máximas de Lua para que las escrituras fuera de orden nunca retrocedan a la observación más reciente y procesamiento por lotes de canalizaciones; con --wake-enabled, una solicitud enrutada a una zona de pruebas rápida pausada se estaciona en lugar de responderse 503: un ResumeSandbox por réplica por zona de pruebas bajo un solo vuelo cercado por un punto de control, un estacionamiento y un presupuesto delimitados (desbordamiento/tiempos de espera responden a 503 + Retry-After mientras continúa la restauración, nunca se cancela) y el reingreso a una ruta obsoleta se reproduce en una ruta nueva solo cuando se puede reproducir de forma segura; con ambos indicadores desactivados, el comportamiento es idéntico en bytes al actual (#2156)
  • Completar el endurecimiento de la activación OSEP-0024: la reproducción de ruta obsoleta posterior al envío está restringida a métodos idempotentes con cuerpos reproducibles (un POST reenviado nunca se vuelve a ejecutar silenciosamente); la respuesta de tiempo de espera previo al envío lleva el marcador definido por OSEP (503 + Retry-After: 1 + OpenSandbox-Wake: expired + un cuerpo sandbox_wake_timeout que nombra la zona de pruebas), eliminado de cada respuesta ascendente para que una zona de pruebas no pueda falsificar la procedencia; un permiso de restauración separado (--wake-restore-max, retenido en la terminal de vuelo) limita las restauraciones simultáneas independientemente del estacionamiento; y la activación ahora requiere que la suscripción lifecycle.idlePolicy por sandbox se lea estrictamente de la anotación CR de Sandbox; faltante o con formato incorrecto significa que no hay política y el 503 permanente de hoy, nunca una suscripción implícita; Los valores del gráfico gateway.wake.* conectan las banderas y agregan RBAC de solo lectura cuando está habilitado (#2180)

Zona de pruebas rápida

  • Hacer que la eliminación de la zona de pruebas sea confiable: la eliminación ahora envía una eliminación Fastlet delimitada antes de cualquier verificación de ausencia en tiempo de ejecución, por lo que una entrada de registro faltante, una falla de transporte o una respuesta de inspección vacía ya no se tratan como prueba de que la zona de pruebas ha desaparecido (lo que podría dejar huérfana la microVM mientras el CR desapareciera); el Fastlet registra un desecho por identidad, por lo que una creación retrasada no puede reactivar un sandbox eliminado, y el finalizador de limpieza persiste en la creación de CR (#2214)
  • Hacer que la ubicación de creación se recupere más rápido: después de rechazos comprobados, FastPath actualiza su lista de candidatos dentro de un presupuesto limitado (excluyendo los Fastlets ya probados) y espera hasta 2 s para que el estado de la asignación se ponga al día antes de cambiar, y un rastreador de creación de proceso local evita que un módulo de Fastlet eliminado o reemplazado bloquee la proyección de la nueva asignación o la recuperación de pérdida de módulo de carrera; la ruta feliz de la primera creación no se modifica (#2214)
  • Actualizaciones de NAT de invitado por lotes: las nuevas ranuras de VM invitado preparan cadenas DNAT/SNAT dedicadas y la restauración reemplaza solo esas cadenas en un lote iptables-restore --noflush, por lo que volver a aplicar la misma dirección de invitado ya no acumula reglas, con una nueva métrica fast_sandbox_network_guest_apply_stage_latency_seconds que separa las etapas de aplicación (#2214)

Varios

  • Consola: obtenga la primera porción de una nueva consola web opcional: una BFF FastAPI con sesiones httpOnly e inicio de sesión de inquilino/administrador que representa el ciclo de vida /sandboxes API (con un runtimeSummary en lista/obtener), además de un React SPA que cubre la descripción general del inquilino, lista/creación/detalle de sandbox, renovación/eliminación y el punto final; primero de cinco PR de consola planificados, seguido por la interfaz de usuario del administrador (#2129)
  • CLI: obliga a los valores del archivo de configuración a sus tipos declarados para que un api_key numérico ya no se resuelva silenciosamente en nulo (rompiendo cada comando con un ValidationError) y un defaults.timeout numérico ya no bloquee sandbox create (#2169); mantener la salida grabable en secuencias que no sean UTF-8: los usuarios de GBK/cp1252/C-locale no pudieron ejecutar ningún comando osb porque la representación de emoji generó UnicodeEncodeError, a menudo después de que el trabajo ya estaba hecho; las secuencias ahora escapan de caracteres no codificables y la salida YAML se vuelve a volcar en formato de escape para seguir siendo válida (#2187); escriba habilidades instaladas donde cada herramienta realmente las lea: el destino claude ahora escribe .claude/skills/<name>/SKILL.md (el archivo plano anterior nunca se cargó silenciosamente), y los destinos globales cline/copilot escriben ~/.cline/rules/opensandbox-<name>.md y ~/.copilot/copilot-instructions.md; Los archivos inertes instalados previamente no se migran (#2194 #2208)
  • Entorno de integración rápido de sandbox: impulse las etapas de verificación a través del osb CLI publicado en lugar del curl sin procesar (creación de plantilla, creación/eliminación de sandbox, recuperación de punto final, pausa/reanudación, creación/obtención/lista/eliminación/restauración de instantáneas, renovación), con server_api mantenido solo para llamadas que el CLI no expone (la política de red reemplaza PUT, RFC 7396). parche de fusión, valla de código de reingreso de instantáneas, sondas de puerta de enlace) (#2171); agregue un perfil IDLE_PAUSE=1 opcional que implemente el Redis efímero, habilite la barredora [automation.idle_pause] y los valores de actividad/activación de la puerta de enlace, y verifique el ciclo completo de pausa automática → activación al acceder en up, además de una suite SDK e2e y un trabajo de flujo de trabajo KVM nocturno (#2202)
  • Documentos: acepte y documente OSEP-0024: la propuesta en sí (#2152) más una página de arquitectura y una guía del usuario que cubre la habilitación, la referencia del campo idlePolicy, el contrato de sonda de actividad, el comportamiento de reintento de activación de SDK y un diagrama interactivo (#2217); unifique las métricas de telemetría de componentes de siete ubicaciones dispersas en una referencia en docs/guides/telemetry.md (#2205); actualizar las páginas de arquitectura de red con diagramas SVG rediseñados, una página de salida condensada y la reubicación de la guía de aislamiento de red (#2210); alinear CONTRIBUTING con el código (Go 1.25, Gin — no Beego) (#2175), deduplicar las reglas AGENTS.md e indicar la regla de ubicación de arquitectura versus guías una vez (#2211), y corregir el nombre incorrecto de "perfil de salida de Fastlet compartido" a "proceso de salida compartido por pod de Fastlet" con una nota que gRPC termina en FastPath (#2225)
  • Pruebas/CI: alinear la aserción e2e de recopilación de registros del agente de nodo con la nueva línea final preservada de execd (#2164); haga que el flujo de trabajo de lanzamiento general se envíe únicamente eliminando el ensayo semanal programado (#2223)
  • lanzamiento: versión de plataforma mejorada a 1.2.0-rc.1 en gráficos y referencias de imágenes

Actualización y compatibilidad

  • Cambio de comportamiento: los pods de BatchSandbox ahora tienen como valor predeterminado restartPolicy: Never (Always implícito → Never): las implementaciones que se basaron en el valor predeterminado implícito y desean reinicios deben configurar restartPolicy: Always explícitamente en su batchsandbox_template_file (una advertencia de inicio indicará la compensación) (#2128)
  • Cambio de comportamiento: los sandboxes eliminados permanecen consultables en Stopping hasta que se completa la limpieza en tiempo de ejecución, y solo entonces devuelven 404. Los clients que comparten un directorio persistente deben esperar el 404 antes de iniciar un reemplazo (#2154)
  • Cambio de comportamiento: las métricas de CPU/memoria execd informan valores con ámbito de sandbox cuando el cgroup de sandbox tiene límites configurados (anteriormente en todo el host); La semántica de los campos GET /metrics y los nombres de las métricas de OTel no cambian, pero los paneles cambiarán (#2200)
  • Cambio de comportamiento: networkPolicy se rechaza para los modos de red Docker none/pasta/slirp4netns; anteriormente se aceptaba silenciosamente para none (#2203)
  • Imágenes: opensandbox/<component>:release-1.2.0-rc.1 (los tres registros)
  • Paquetes: sin cambios: los artefactos SDK/CLI se publican en la versión estable 1.2.0
  • Gráficos: renderizado a partir de esta etiqueta (helm template ./manifests/charts/opensandbox)
  • Kubernetes: rango admitido v1.21 – v1.34 (los gráficos declaran kubeVersion: ">=1.21.1-0")
  • Inclinación: servidor ↔ CLI/SDK compatible con la misma línea; ±1 advertencia menor

OpenSandbox release-1.2.0-rc.1

First release candidate on the 1.2.0 line, carrying everything merged since release-1.1.1 — the headline is OSEP-0024: auto-pause and wake-on-access for fast sandboxes, landing end to end. Images publish now; SDK/CLI packages ship at the 1.2.0 stable bump. Please test and report issues.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: ingress activity tracking and the wake path, the server-side idle sweeper, the opt-in lifecycle.idlePolicy create field, and the wake-retry contract in all five SDKs — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Egress sidecar (experimental, opt-in): live credential-bound Vault admission, HTTP/2 support with bounded drain, atomic policy-file persistence, and runtime fault containment (#2176 #2201 #2182 #2162 #2172)
  • SDK reliability: file uploads and downloads are no longer aborted at the 30-second request timeout in any of the five SDKs; execd now reports sandbox-scoped CPU/memory and OOM kills (#2165 #2186 #2196 #2206 #2191 #2200)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle create field lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) validates with pydantic bounds and persists as the reserved sandbox.opensandbox.io/idle-policy Sandbox CR annotation (annotation-write failure stays fail-safe — the sandbox is created unpolicied); an idle sweeper enumerates opted-in fsb sandboxes from the informer cache, checks activity in Redis (monotonic-max writes, missing-key tombstones can only delay a pause), takes a per-sandbox pause lock with re-verify under lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe executes through the ingress gateway and a busy answer records ordinary activity; an OpenSandbox-Skip-Activity: skip sentinel suppresses the observation for one request and is stripped on both gateway and server-proxy hops (#2192 #2181)
  • Configure idle-pause under the new lifecycle-automation umbrella: [idle_pause] becomes [automation.idle_pause] and the redundant redis.enabled gate is removed — redis.dsn is required (validated at load) when enabled = true, failing loudly instead of silently not starting the sweeper; configuration.md is rewritten for conciseness and now documents ingress.secure_access and the missing env-var overrides (#2215)
  • Default BatchSandbox pods to restartPolicy: Never: a kubelet in-place container restart recreated the main container from its image — wiping the writable layer and in-memory state — while the sandbox kept reporting Succeed; restarting is never a meaningful recovery for a sandbox, so the honest default is no restart, which also makes the controller's terminal-failure path reachable. An explicit restartPolicy in the template still wins, the Windows profile keeps forcing Always (multi-phase installation relies on it), and pool mode is unchanged (#2128)
  • Treat pasta/slirp4netns/none as container-runtime network modes and pass them straight through, making podman's kernel-level networking selectable — on Windows 11 + WSL2 where netavark breaks bridge mode, pasta was the only working network and previously failed create with a 400 asking for a user-defined Docker network; networkPolicy is now rejected for these modes since there is no bridge for the egress sidecar to attach to (previously silently accepted for none) (#2203)
  • Parse Docker timestamps whose fractional second is not 3 or 6 digits: Docker writes RFC3339Nano (trailing zeros dropped), Python 3.10's fromisoformat rejects 5-digit fractions, and the helper fell back to datetime.now() — so createdAt and status.lastTransitionAt silently reported the current time; the fraction is now zero-padded to 6 digits (#2220)

SDKs

Code changes below ride the 1.2.0 stable release — rc ships no SDK packages.

  • Add the OSEP-0024 SDK contract to all five languages: a typed lifecycle.idlePolicy create field (IdlePolicy/ActivityProbe models with client-side fail-fast validation mirroring the server: timeout 30–86400 s, onIdle: "pause" pairing, probe path/timeout bounds; wired through both standard and template create) and the wake-retry contract — on a 503 carrying the gateway-owned OpenSandbox-Wake: expired marker (its presence proves the request was parked and never forwarded, making any-method retry safe), the SDK resends after Retry-After under a bounded budget (default 5 attempts / 60 s, per-client knobs), exhaustion raises a typed wake-timeout exception carrying attempts and waited time, the server-side resume is never canceled, bare 503 handling is unchanged, and SSE/streaming transports bypass wake retry (#2198 #2218)
  • Stop capping file uploads and downloads at the request timeout (30 s default) in all four remaining SDKs — the whole-call timeout (http.Client.Timeout, OkHttp callTimeout, AbortController, HttpClient.Timeout) covered sending the request body and reading the response, so any large or slow transfer failed mid-flight even while healthy; transfers now run on a dedicated client with no whole-call deadline that still bounds the wait for response headers, so a stalled transfer still fails instead of hanging (#2165 #2186 #2196 #2206)
  • Suppress sandbox.create client metrics for client-pool warmup creates in Go, Python, and JavaScript, aligning with Kotlin: warmup traffic (hardcoded skipHealthCheck, hundreds of ms) previously mixed into user-facing create-latency metrics and dragged p50/p99 down; direct-create from pool acquire and user-facing creates keep reporting (#2199)

Python

  • Clean up cancelled async pool startup: cancelling SandboxPoolAsync.start() mid-await left the instance stuck in STARTING, where a subsequent start() silently returned and startup-owned resources skipped cleanup; cancellation now reuses the reconciliation cleanup path, moves to STOPPED, and re-raises so the caller can retry (#2209)
  • Stop reporting failed file replacements as successful: the ordinary filesystem adapters caught and discarded the generated client's JSONDecodeError, so an empty or non-JSON HTTP 400/500 from replace_contents() returned success and an agent could keep building on an unapplied edit; the catch is removed and the documented SandboxException failure contract is restored (isolated-session adapters keep their empty-body compatibility catch) (#2222)

Go

  • Strip all OPEN-SANDBOX-*/OPENSANDBOX-* headers and every configured authentication header (including X-EXECD-ACCESS-TOKEN, X-API-Key, and custom WithAuthHeader names) on cross-origin redirects, comparing each destination against the initial request's scheme, host, and effective port so credentials cannot reappear on later foreign-origin hops; applied across lifecycle, execd, egress, file transfers, SSE, and creation metrics while preserving custom CheckRedirect policies (#2178)

Controller

  • Retain a BatchSandbox until cleanup completes: a deleted sandbox could disappear from the lifecycle API (GET 404) while its owned pod still ran, letting a replacement sandbox write the same persistent directory before the old writer exited; deletion now uses foreground cascading deletion alongside the existing task-cleanup and pool-release finalizers, and TTL reconciliation stops once deletion is accepted — DELETE still returns 204 when accepted, queries report Stopping during managed cleanup, and 404 arrives only after the runtime is gone; all five SDKs' kill docs and logs describe the accepted-deletion semantics (#2154)

Execd

  • Report OOM kills via cgroupfs polling: kernel-side evidence was out of reach from inside a sandbox (no CAP_SYSLOG, no /dev/kmsg), so OOM events were unobservable; execd now polls the sandbox cgroup every 5 s and diffs the kernel OOM kill counter (memory.events on v2, best-effort on v1) — the hierarchical counters cover nested cgroups like bwrap isolated sessions — exporting execd.system.oom.kills with a local/descendant level attribute plus structured warn logs with best-effort victim attribution; the watcher runs independently of OTLP export and needs no capabilities (#2191)
  • Report sandbox-scoped CPU/memory metrics: GET /metrics and the execd.system.cpu.usage/execd.system.memory.usage_bytes gauges read /proc through gopsutil, which inside a container describes the host — dashboards showed host-wide memory and CPU; when the sandbox cgroup carries configured limits, usage now comes from the sandbox's own cgroup (cpu.stat/cpu.max, memory.current/memory.max, v1 fallback, hybrid hosts prefer v1), with the previous host view kept for unlimitied guests such as fast-sandbox microVMs; the wire format is unchanged (#2200)
  • Percent-encode quotes and backslashes in Content-Disposition: a filename containing " or \ produced a quoted-string no standard parser accepts (mime.ParseMediaType rejected it and clients got no filename at all); such names now route through the same filename*=UTF-8'' encoding as non-ASCII names (#2161)
  • Parse the Range header before setting download headers: a malformed range answered 416 with the file's Content-Disposition and Content-Length still attached, truncating the JSON body or dropping it entirely — surfacing in the Python SDK as a connection error instead of a 416 SandboxApiException; the error response is now a clean JSON 416, and 200/206 responses are unchanged (#2216)

Networking

egress

All items below concern the default-off OSEP-0023 experimental revision runtime; legacy and DNS-only deployments are unchanged.

  • Add experimental live credential-bound Vault admission: Vault mutations flow through the revision transaction and install the private authenticated snapshot before publishing the public result; bound HTTPS connections are admitted and header credentials injected only after exact request matching with SNI/HTTP/1 authority agreement (ECH-extension ClientHellos stay opaque), with per-request credential rotation, fencing of removed bindings on existing connections, and transport retirement at the drain deadline; scope is exact-host HTTPS on 443 with HTTP/1.1 and inline header credentials (#2176)
  • Acknowledge live Policy revisions before publication: the Policy API and automatic deny.always/allow.always reloads now commit in order — optional file persistence, nft application, exact receiver acknowledgement or reconciled readback, then proxy publication and API success — with fail-closed recovery when the receiver fails after nft has taken effect, and 30-second drain deadlines on policy-only updates that never extend across later revisions (#2182)
  • Add experimental HTTP/2 admission and bounded drain: snapshots bind atomically to actual client stream IDs at requestheaders, post-fence requests get REFUSED_STREAM before reaching origin, GOAWAY waits for outstanding output obligations while expiry uses abnormal closure, and a once-only mitmdump exit fallback covers unverifiable cleanup ownership; the adapter is pinned to CPython 3.10/3.11 and rejects configured chained upstream proxies (#2201)
  • Contain runtime recovery faults in the sidecar network namespace: an unexpected MITM exit now triggers an independent, read-back-verified IPv4/IPv6 fence pinned to the original namespace for the process lifetime — blocking all input/output/forward traffic including existing connections and loopback — with QuarantineConfirmed reported only after real rule readback; normal successful mutations never introduce a fence (#2172)
  • Persist experimental revision policy files atomically: writes go through a same-directory temporary inode with fsync + rename + directory fsync, restores put back the exact previous bytes (or synchronized absence), and unsupported storage — file bind mounts, read-only or symlinked paths, hardlinks, unsafe ownership, unsupported SELinux/IMA metadata — is rejected before the original is touched; operators must provide an existing egress-owned, exclusively written directory mount (#2162)
  • Classify nft apply effects before policy recovery: local construction, pre-start cancellation, and start failures are Unchanged (state preserved, retry allowed after restore), successful execution is Committed, and every post-start or unclassified error is Unknown — closing writer admission and latching recovery before best-effort restoration; the missing-table fallback retains both errors and never downgrades an Unknown result (#2167)

ingress

  • Implement OSEP-0024 activity tracking and wake-on-access: with --activity-enabled, every routed request records a monotonic activity timestamp to Redis — fire-and-forget, never on the hot path — with per-replica write coalescing, Lua monotonic-max updates so out-of-order writes never regress the newest observation, and pipeline batching; with --wake-enabled, a request routed to a paused fast sandbox is parked instead of answered 503: one ResumeSandbox per replica per sandbox under a checkpoint-fenced singleflight, a bounded parking lot and budget (overflow/timeouts answer 503 + Retry-After while the restore continues, never canceled), and stale-route re-entry replayed on a fresh route only when safely replayable; with both flags unset, behavior is byte-identical to today (#2156)
  • Complete OSEP-0024 wake hardening: post-forward stale-route replay is restricted to idempotent methods with reproducible bodies (a forwarded POST is never silently re-executed); the pre-forward wake-timeout answer carries the OSEP-defined marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired + a sandbox_wake_timeout body naming the sandbox), stripped from every upstream response so a sandbox cannot forge provenance; a separate restore permit (--wake-restore-max, held to flight terminal) bounds concurrent restores independently of the parking lot; and wake now requires the per-sandbox lifecycle.idlePolicy opt-in read strictly from the Sandbox CR annotation — missing or malformed means no policy and today's permanent 503, never an implicit opt-in; gateway.wake.* chart values wire the flags and add read-only RBAC only when enabled (#2180)

Fast Sandbox

  • Make sandbox deletion reliable: deletion now sends a fenced Fastlet delete before any runtime-absence check, so a missing registry entry, transport failure, or empty inspect response is no longer treated as proof the sandbox is gone (which could orphan the microVM while the CR disappeared); the Fastlet records a per-identity tombstone so a delayed create cannot revive a deleted sandbox, and the cleanup finalizer is persisted at CR creation (#2214)
  • Make create placement recover faster: after proven rejections FastPath refreshes its candidate list within a bounded budget (excluding Fastlets already tried) and waits up to 2 s for assignment status to catch up before switching, and a process-local create tracker stops a deleted or replaced Fastlet pod from blocking the new assignment's projection or racing pod-loss recovery — the first-create happy path is unchanged (#2214)
  • Batch guest NAT updates: new guest-VM slots prepare dedicated DNAT/SNAT chains and restore replaces only those chains in one iptables-restore --noflush batch, so reapplying the same guest address no longer accumulates rules, with a new fast_sandbox_network_guest_apply_stage_latency_seconds metric separating the apply stages (#2214)

Misc

  • Console: land the first slice of a new optional web console — a FastAPI BFF with httpOnly sessions and tenant/admin login proxying the lifecycle /sandboxes API (with a runtimeSummary on list/get), plus a React SPA covering tenant overview, sandbox list/create/detail, renew/delete, and the endpoint; first of five planned console PRs, with the admin UI to follow (#2129)
  • CLI: coerce config-file values to their declared types so a numeric api_key no longer silently resolves to null (breaking every command with a ValidationError) and a numeric defaults.timeout no longer crashes sandbox create (#2169); keep output writable on non-UTF-8 streams — GBK/cp1252/C-locale users could not run any osb command because emoji rendering raised UnicodeEncodeError, often after the work was already done; streams now escape unencodable characters and YAML output is re-dumped escaped to stay valid (#2187); write installed skills where each tool actually reads them — the claude target now writes .claude/skills/<name>/SKILL.md (the previous flat file was silently never loaded), and global cline/copilot targets write ~/.cline/rules/opensandbox-<name>.md and ~/.copilot/copilot-instructions.md; previously installed inert files are not migrated (#2194 #2208)
  • Fast-sandbox integration environment: drive the verify stages through the published osb CLI instead of raw curl (template build, sandbox create/kill, endpoint fetch, pause/resume, snapshot create/get/list/delete/restore, renew), with server_api kept only for calls the CLI does not expose (networkpolicy replace PUT, RFC 7396 merge-patch, the snapshot re-entry code fence, gateway probes) (#2171); add an opt-in IDLE_PAUSE=1 profile that deploys ephemeral Redis, enables the [automation.idle_pause] sweeper and gateway activity/wake values, and verifies the full auto-pause → wake-on-access loop on up, plus an SDK e2e suite and a nightly KVM workflow job (#2202)
  • Docs: accept and document OSEP-0024 — the proposal itself (#2152) plus an architecture page and user guide covering enablement, the idlePolicy field reference, the activity-probe contract, SDK wake-retry behavior, and an interactive diagram (#2217); unify component telemetry metrics from seven scattered locations into one reference at docs/guides/telemetry.md (#2205); refresh the network architecture pages with restyled SVG diagrams, a condensed egress page, and the network-isolation guide relocation (#2210); align CONTRIBUTING with the code (Go 1.25, Gin — not Beego) (#2175), dedupe AGENTS.md rules and state the architecture-vs-guides placement rule once (#2211), and fix the "shared Fastlet egress profile" misnomer to "shared egress process per Fastlet pod" with a note that gRPC ends at FastPath (#2225)
  • Tests/CI: align the node-agent log-collection e2e assertion with execd's preserved trailing newline (#2164); make the umbrella release workflow dispatch-only by dropping the weekly scheduled dry-run (#2223)
  • release: bump platform version to 1.2.0-rc.1 across charts and image references

Upgrade & Compatibility

  • Behavior change: BatchSandbox pods now default to restartPolicy: Never (implicit Always → Never) — deployments that relied on the implicit default and want restarts must set restartPolicy: Always explicitly in their batchsandbox_template_file (a startup warning will note the trade-off) (#2128)
  • Behavior change: deleted sandboxes stay queryable in Stopping until runtime cleanup completes, and only then return 404 — clients sharing a persistent directory should wait for the 404 before starting a replacement (#2154)
  • Behavior change: execd CPU/memory metrics report sandbox-scoped values when the sandbox cgroup has limits configured (previously host-wide); GET /metrics field semantics and OTel metric names are unchanged, but dashboards will shift (#2200)
  • Behavior change: networkPolicy is rejected for Docker network modes none/pasta/slirp4netns — previously accepted silently for none (#2203)
  • Images: opensandbox/<component>:release-1.2.0-rc.1 (all three registries)
  • Packages: unchanged — SDK/CLI artifacts publish at the 1.2.0 stable release
  • Charts: render from this tag (helm template ./manifests/charts/opensandbox)
  • Kubernetes: supported range v1.21 – v1.34 (charts declare kubeVersion: ">=1.21.1-0")
  • Skew: server ↔ CLI/SDK same line supported; ±1 minor warns

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.0-rc.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# the default render needs required values (server env / api key) and the
# ingress gateway — see docs/deployment before applying
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

Verify what you installed against the BOM: see Release Verification.
