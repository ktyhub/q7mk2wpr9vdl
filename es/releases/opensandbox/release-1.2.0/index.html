Lanzamiento de OpenSandbox-1.2.0

Corte estable de la línea 1.2.0, que incluye todo lo fusionado desde release-1.1.1 a través de dos candidatos de lanzamiento más un delta de endurecimiento post-rc. Imágenes enviadas con los rcs; Los paquetes SDK/CLI/servidor se publican en 1.2.0. Todos los usuarios de 1.1.x deberían actualizar. Línea de base para cada sección a continuación: release-1.1.1.

Destacados

  • La pausa automática y la activación al acceder para entornos limitados rápidos (OSEP-0024) llegan de extremo a extremo: el ingreso registra la actividad y estaciona las solicitudes en los entornos limitados en pausa hasta que se completa la restauración, el servidor ejecuta una barredora inactiva detrás de un campo de creación lifecycle.idlePolicy opcional y los cinco SDK obtienen el contrato de reintento de activación; desactivado de forma predeterminada, solo aditivo (#2156 #2180 #2192 #2198 #2218)
  • Bóveda de credenciales (OSEP-0022) aterriza de extremo a extremo para entornos limitados rápidos: el sidecar de salida contiene el almacén con persistencia duradera por sujeto y transferencia de pausa/reanudación sellada, el servidor expone el almacén accesible para el usuario API con valores de credenciales que nunca aparecen en ninguna lectura pública, y la CA MITM está fijada por grupo para que un reinicio de salida ya no gire el ancla trust bajo entornos limitados activos — más reglas de salida con ámbito de puerto de extremo a extremo en el perfil clásico (#2249 #2252 #2255 #2263 #2251 #2212)
  • Las instantáneas rápidas de Sandbox y las compilaciones de plantillas se pueden publicar y arrancar desde registros OCI (ciclo de vida OverlayBD OCI), y una campaña de confiabilidad elimina los tiempos de espera de llamadas completas de las transferencias de archivos SDK en los cinco idiomas, genera informes execd de CPU/memoria y OOM con alcance de sandbox, y corrige una larga lista de problemas de corrección de backend de Docker y salida de PTY/sesión. (#2338 #2165 #2200 #2191)

Servidor

  • Implementar el lado del servidor de la pausa automática OSEP-0024 para entornos sandbox rápidos: el campo de creación lifecycle.idlePolicy (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, activeProbe opcional) persiste como una anotación CR reservada de Sandbox; una barredora inactiva enumera los entornos limitados de fsb habilitados, verifica la actividad en Redis, realiza un bloqueo de pausa por cada entorno de pruebas y emite un FastPath idempotente PauseSandbox; un activeProbe declarado corre a través de la puerta de enlace de entrada y un centinela OpenSandbox-Skip-Activity suprime una observación y se elimina tanto en los saltos de puerta de enlace como de proxy. La configuración se mueve bajo [automation.idle_pause] y redis.dsn se valida durante la carga cuando la barredora está habilitada (#2192 #2181 #2215)
  • Implementar Credential Vault API (OSEP-0022, perfil de zona de pruebas rápida): POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault envía revisiones completas de la bóveda a través del relé del controlador FastPath y trata la respuesta del relé como el reconocimiento de salida sincrónico validado: el CRD nunca transporta material de la bóveda y cada lectura pública se desinfecta en el lado del servidor; PATCH se compone en la memoria con expectedRevision como respaldo de réplica cruzada, los backends que no son fsb representan la superficie /credential-vault del sidecar y se elimina el rechazo del tiempo de creación del fsb credentialProxy (#2263)
  • Incorporar la CA MITM anclada en SandboxTemplates creadas por el servidor (OSEP-0022): la nueva configuración [kubernetes] template_mitm_ca_secret (desactivada por defecto) emite spec.egressMitmCertificate (solo la entrada del certificado, nunca la clave privada) en cada plantilla; el secreto debe existir en cada espacio de nombres de plantilla (distribución ops-runbook), y una copia perdida falla notablemente en la compilación (#2288)
  • Agregar lifecycle.renewalPolicy (OSEP-0009): la opción de renovación al acceder pasa de la clave opaca extensions["access.renew.extend.seconds"] a una renewalPolicy.extendSeconds estructurada (300–86400); la clave heredada está obsoleta (compatible con 1.x, eliminada en 2.0) y el entorno de pruebas rápido la rechaza con 400 en lugar de aceptar silenciosamente una no operación (#2296)
  • Implementar el punto final del contexto de diagnóstico (especificación en #2236): GET /v1/sandboxes/{sandboxId}/diagnostics/context devuelve el ID de la zona de pruebas, el estado del ciclo de vida, el tipo de backend y los identificadores definidos por el backend para Docker, Kubernetes y Fast Sandbox sin conectarse a execd; el contexto Kubernetes permanece disponible antes de que se asigne un Pod; Los backends de extensión que no lo implementan devuelven 501 (#2292)
  • Reenviar la ruta aún codificada a través del proxy de la zona de pruebas: Starlette vinculó la ruta {full_path:path} de la ruta con porcentaje decodificado, por lo que un ? decodificado inició una consulta, %2F se convirtió en un separador y los segmentos %2E%2E se resolvieron, cerrando un escape de prefijo en los puntos finales mapeados por el host Docker; el proxy ahora toma la cola aún codificada del client de la ruta sin formato (validando que se decodifique en la ruta enrutada) y lee la consulta de la cadena de consulta sin formato, de modo que los backends reciban los destinos de la solicitud byte por byte, coincidiendo con la puerta de enlace de entrada (#2228)
  • Seguir bloqueando las llamadas Docker fuera del bucle de eventos: las búsquedas de puntos finales de proxy, la validación de la existencia de red y la inspección/creación de volumen por PVC se ejecutaron sincrónicamente dentro de los controladores asíncronos, por lo que un demonio Docker lento (por ejemplo, durante una extracción grande) congeló todas las demás solicitudes, incluido el tráfico de proxy; ahora se ejecutan en subprocesos de trabajo con el contexto del inquilino conservado y los errores de validación de volúmenes aún limpian los volúmenes creados automáticamente (#2268 #2366)
  • Dejar de informar etiquetas heredadas de imágenes como estado de espacio aislado en Docker: las lecturas de metadatos recayeron en cada etiqueta de contenedor no reservada (incluidas las etiquetas fusionadas de la imagen) y los contenedores restaurados heredaron etiquetas reservadas como expires-at, puertos de host y el token de salida; en el peor de los casos, se eliminó una zona de pruebas TTL restaurada porque ya expiró después de reiniciar el servidor. Las creaciones ahora registran las claves de metadatos de la solicitud en una etiqueta reservada y vuelven a leer solo esas claves, y las etiquetas reservadas presentes en la imagen pero no configuradas por el entorno de pruebas se borran antes del inicio del contenedor (#2363 #2269)
  • Rechazar instantáneas de gVisor que eliminarían escrituras silenciosamente: docker commit bajo el valor predeterminado --overlay2=root:self de gVisor puede informar READY sin restaurar ninguna de las escrituras del sandbox; La verificación previa de instantáneas ahora rechaza gVisor a menos que los argumentos efectivos incluyan --overlay2=none, y la creación falla cuando la diferencia del sistema de archivos es solo de almacén de archivos (#2241)
  • Mantener una instantánea de fsb cuya respuesta de creación se perdió: un UNAVAILABLE/DEADLINE_EXCEEDED de FastPath después de que la solicitud fue aceptada de manera duradera devolvió 500 sin escribir una fila, dejando a SandboxSnapshot y sus artefactos publicados sin registro; la creación ahora busca la instantánea antes de fallar y la informa como enviada cuando FastPath la persistió (#2361)
  • Se corrigen las asperezas restantes del backend de Docker: la caducidad de BatchSandbox informa Terminated/SANDBOX_EXPIRED en lugar de Running después de spec.expireTime (#2238); los conflictos simultáneos del ciclo de vida se asignan a 404/409 en lugar de 500 (#2387); los parches de metadatos simultáneos ya no corren hacia 500 o claves eliminadas (#2267 #2281); createdAt permanece estable durante las lecturas y se registran las transiciones de pausa/reanudación (#2405); las acciones de política de red se validan y los campos desconocidos devuelven 422 (#2383 #2385); la imagen de la zona de pruebas se lee desde la configuración del contenedor, por lo que una imagen con docker rmi -f ya no es 500 GET /sandboxes (#2353); la plantilla lee trust la proyección de la base de datos en lugar de sincronizar el CR en cada comprobación de la puerta de creación (#2326); el tiempo de reutilización de renovación se aplica a cada fuente de renovación cuando el consumidor Redis está habilitado (#2276 #2279); Los pods de BatchSandbox están predeterminados en restartPolicy: Never, por lo que un reinicio de kubelet ya no puede borrar la capa de escritura mientras informa Succeed (#2128); los modos de red pasta/slirp4netns/none de podman pasan (con networkPolicy rechazado, ya que no hay ningún puente al que conectarse) (#2203); Las marcas de tiempo Docker con fracciones de segundo inusuales ya no informan silenciosamente la hora actual (#2220); y el contenedor de caché execd respeta los perfiles de seguridad [docker] y secure_runtime (#2254)

SDK

Los cambios de código a continuación se aplican a los paquetes 1.2.0.

  • Agregue el contrato OSEP-0024 SDK a los cinco idiomas: un campo de creación lifecycle.idlePolicy escrito con validación rápida de fallas en el lado cli, más el contrato de reintento de activación; en un 503 que lleva el marcador OpenSandbox-Wake: expired propiedad de la puerta de enlace (su presencia prueba que la solicitud fue estacionada y nunca reenviada, lo que hace que cualquier método de reintento sea seguro), el SDK se reenvía después Retry-After con un presupuesto limitado (5 intentos/60 s predeterminados, perillas por client) y el agotamiento genera una excepción de tiempo de espera de activación escrito; El manejo básico de 503 no ha cambiado (#2198 #2218). Inicialmente, el contrato pasó por alto los transportes de transmisión; la solicitud que inicia una transmisión ahora se reintenta en JavaScript, Python y Go (las transmisiones establecidas nunca se reproducen), mientras que el inicio de la transmisión en C#/Kotlin actualmente falla rápidamente (#2357 #2426)
  • Agregue el contrato Credential Vault client a los cinco SDK (OSEP-0022): los sandboxes respaldados por plantillas enrutan las llamadas a la bóveda a través del servidor en la misma señal de origen de plantilla que la política de red, mientras que los adaptadores directos al sidecar permanecen intactos (#2263)
  • Dejar de limitar las cargas y descargas de archivos en el tiempo de espera de la solicitud (30 s predeterminado) en los cinco SDK: el tiempo de espera de toda la llamada cubrió el envío del cuerpo y la lectura de la respuesta, por lo que cualquier transferencia grande o lenta fallaba en pleno vuelo incluso cuando estaba en buen estado; las transferencias ahora se ejecutan en un client dedicado sin fecha límite para la llamada completa que aún limita la espera de los encabezados de respuesta, por lo que una transferencia estancada aún falla en lugar de colgarse (#2165 #2186 #2196 #2206)
  • Implementar diagnósticos en toda la superficie SDK (con #2292): context se expone a través de las fachadas del administrador y de la zona de pruebas en los cinco idiomas, y JavaScript, Go y C# obtienen registros/eventos públicos API que coinciden con la superficie Python/JVM existente. (#2292)
  • Agregue lifecycle.renewalPolicy a los cinco SDK (OSEP-0009): un campo de creación escrito con validación rápida de fallos del lado cli (extendSeconds 300–86400), reemplazando la clave de extensiones opacas (#2296)
  • Admite reglas de salida con ámbito de puerto en los cinco SDK: NetworkRule.ports (TCP 1–65535, como máximo 256 por regla, target ahora opcional) con validación del lado de cli que refleja el servidor (rango, duplicados, límite, dominio+puertos rechazados); JavaScript codifica la invariante de destino o puertos como un tipo de unión (#2212)
  • Mostrar el autorizado execution_complete.exit_code en Go y Kotlin, prefiriéndolo a los anteriores evalue/inferred-0 y al mismo tiempo seguir siendo compatible con servidores más antiguos (#2330); honrar un encabezado OPEN-SANDBOX-API-KEY proporcionado explícitamente sobre la clave configurada independientemente de la mayúscula del nombre del encabezado en JavaScript, C# y Kotlin (#2348 #2372 #2375); suprimir las métricas sandbox.create para las creaciones de calentamiento de client-pool en Go, Python y JavaScript (#2199)
  • Elimina las credenciales protegidas en redireccionamientos entre orígenes en JavaScript, C# y Go: los encabezados con prefijo de sandbox, los tokens de punto final (X-EXECD-ACCESS-TOKEN, X-API-Key) y los encabezados de autenticación configurados se eliminan cada vez que un redireccionamiento cambia de esquema/host/puerto, mientras que se conservan los saltos del mismo origen y los encabezados no relacionados; las cargas de archivos nunca siguen redireccionamientos en JavaScript, y en los navegadores, un redireccionamiento opaco falla al cerrarse en lugar de correr el riesgo de reproducir las credenciales (#2178 #2173 #2183)
  • Enrute los encabezados del plano de datos del intérprete de código JavaScript y C# a través de la política compartida: las solicitudes /code en modo directo ya no llevan el inquilino OPEN-SANDBOX-API-KEY a la ejecución, una clave de conexión configurada explícitamente mantiene prioridad sobre el apiKey configurado sin entradas duplicadas de variantes de casos y las credenciales con alcance de punto final aún prevalecen (#2149)

Python

  • Reintentar el tiempo de espera de reactivación de la puerta de enlace al iniciar una transmisión: SSE clients eliminó por completo el contenedor de reintentos, por lo que commands.run, las ejecuciones de sesión y codes.run contra un entorno de pruebas con pausa automática fallaron con el marcado 503 cada vez que la restauración superó el presupuesto del parque de la puerta de enlace; Los transportes de transmisión ahora incluyen un reintento de solo activación (sin reintentos generales, sin fechas límite agregadas) y los documentos ya no afirman que las transmisiones omitan los reintentos (#2357)
  • Normalizar el dominio de conexión: una barra diagonal o /v1 en domain / OPEN_SANDBOX_DOMAIN produjo URL //v1/... que el servidor hizo 404; la misma variable funcionó en todos los demás SDK; Python ahora elimina ambos (#2347)
  • Reutilizar contextos SSL en transportes propios: los certificados de CA se recargaron en cada llamada, bloqueando el bucle de eventos bajo concurrencia asincio; la creación P50 medida mejora ~18–28 % bajo concurrencia (#2360)
  • Preservar el primer evento SSE después de una lista de materiales UTF-8 (incluido uno dividido en fragmentos de red) (#2226); cerrar los cuerpos de respuesta de tiempo de espera de activación en caso de cancelación (#2371); cerrar las respuestas de descarga de archivos asíncronas interrumpidas para que una lectura cancelada o fallida ya no ocupe la conexión (#2369); mantener el código de estado cuando una respuesta de error tenga un cuerpo que no sea JSON: el HTML/404/500 vacío de un proxy apareció anteriormente como InvalidArgumentException sin estado (#2402); genera el error estructurado compartido de las fallas del intérprete de código codes.run en lugar de una excepción creada manualmente que perdió retry_after (#2364); mantener juntos los fragmentos de salida del intérprete de código en Execution.text en lugar de insertar nuevas líneas adicionales (#2408); redondear los tiempos de espera de los comandos de submilisegundos hasta 1 ms en lugar de enviar 0 (lo que deshabilitó el tiempo de espera) (#2419); dejar de propagar una recuperación de punto final cancelada a camareros simultáneos (#2277); reenviar credential_proxy a través de grupos de sandbox, que silenciosamente lo eliminaron antes (#2283); dejar de informar reemplazos de archivos fallidos como exitosos (#2222); limpiar el inicio del grupo asíncrono cancelado en lugar de quedarse atascado en STARTING (#2209); regenerar el ciclo de vida client para eliminar los valores predeterminados codificados obsoletos (comportamiento del cable sin cambios) (#2280); MCP: cancelar una llamada de herramienta ya no cancela una conexión compartida fusionada para el mismo entorno de pruebas, que falló en todas las demás llamadas en espera (#2355)

JavaScript

  • Preservar eventos de ejecución con finales de línea CR: los analizadores SSE solo se dividen en LF, por lo que una secuencia válida delimitada por CR elimina silenciosamente el ID de ejecución, la salida y el evento de finalización (#2374)
  • Alcance la invalidación de caché de punto final en curso para cada entorno de pruebas, por lo que la invalidación del entorno de pruebas B ya no descarta el resultado de una recuperación pendiente para el entorno de pruebas A (#2349)
  • Preservar fragmentos de bytes reutilizados en la carga de archivos: un productor asíncrono que reutiliza una vista Uint8Array/Buffer cargó el contenido mutado dos veces en lugar de ambas instantáneas (#2428); mantenga activa la cancelación de llamadas después de que lleguen los encabezados de respuesta: cancelar a mitad de la transmisión SSE o a mitad de la descarga dejó el cuerpo en ejecución (#2350)
  • Eliminar encabezados protegidos en redirecciones de origen cruzado (consulte la entrada cross-SDK anterior) (#2173)

Kotlin

  • Mantenga un encabezado de clave API explícito delante de la clave configurada en cualquier caso y deje de adjuntar un encabezado de clave vacío cuando no esté configurado (#2375)
  • Preservar el cuerpo de la respuesta sin procesar en fallas de deserializacion y detectar LinkageError debido a una discrepancia entre el serializador y el tiempo de ejecución; anteriormente, un AbstractMethodError escapaba de todos los controladores, eliminando transmisiones SSE silenciosamente con la respuesta real del servidor irrecuperable (#2416) ###C#
  • Respetar un encabezado de clave API explícito independientemente de la mayúscula: la verificación que distingue entre mayúsculas y minúsculas agregó una segunda entrada predeterminada conflictiva y el reportero de métricas reemplazó la credencial de la persona que llama (#2372)
  • Elimina las credenciales protegidas en redirecciones entre orígenes y enruta las solicitudes de intérprete de código a través de la política de encabezado del plano de datos compartido (consulte las entradas cross-SDK anteriores) (#2183 #2149)

Ir

  • Dejar de reintentar escrituras no idempotentes de forma predeterminada: con el reintento habilitado, 27 sitios de llamadas POST/PATCH (sandbox/session/command/file/snapshot/vault mutaciones) podrían ejecutarse dos veces y aun así devolver éxito: POST/PATCH ya no reintenta códigos de estado de forma predeterminada, reintenta solo fallas de transporte que se haya demostrado que son previas al envío (marcar/CONNECT/TLS antes de los bytes de solicitud) y los arranques SSE omiten el reintento genérico bucle; Las personas que llaman y aceptan el riesgo de ejecución duplicada pueden optar por participar a través de RetryConfig.RetryableStatusCodesNonIdempotent (#2342).
  • Vuelva a intentar el tiempo de espera de activación de la puerta de enlace al iniciar una transmisión SSE: los seis sitios de llamadas de transmisión (comando/código/ejecuciones de sesión, vigilancia de métricas) anteriormente fallaron inmediatamente con el marcado 503; el bootstrap ahora se estaciona dentro del mismo presupuesto Retry-After y devuelve el error de tiempo de espera de activación escrito cuando se agota: las transmisiones establecidas nunca se reproducen, un 503 simple aún no se reintenta incluso con la opción de estado de escritura, y un 503 alcanzado a través de una cadena de redireccionamiento pierde la procedencia de activación, por lo que una solicitud ya ejecutada nunca se reenvía; las personas que llaman que dependen de falla rápida pueden pasar WakeRetryDisabled() (#2426)
  • Mantener terminadores de línea en Execution.Text(): execd ya incluye \n/\r en el texto del evento y requiere concatenación para reconstruir la salida estándar, pero el asistente insertó una nueva línea adicional entre los eventos terminados ("a\n" + "b\n" se convirtió en "a\n\nb\n"); ahora se agrega un separador solo cuando el evento anterior no termina en un terminador (#2381)
  • Elimine la clave del inquilino API de las solicitudes del plano de datos en modo directo: se entregó una clave de inquilino proporcionada a través de ConnectionConfig.Headers al execd y el sidecar de salida dentro del entorno limitado untrusted, completando las correcciones de exposición de credenciales en los cinco SDK (#2337)
  • Autenticar solicitudes de plano de datos proxy con el encabezado de clave API en lugar de pasar de contrabando la clave del inquilino al sandbox, arreglando 401 en modo proxy multiinquilino (#2274); superficie execution_complete.exit_code (#2330)

Controlador

  • Conservar un BatchSandbox hasta que se complete la limpieza: un sandbox eliminado podría desaparecer del ciclo de vida API (GET 404) mientras su pod propio aún se ejecuta, permitiendo que un sandbox de reemplazo escriba el mismo directorio persistente antes de que salga el escritor anterior; la eliminación ahora utiliza la eliminación en cascada en primer plano junto con los finalizadores existentes: las consultas informan Stopping durante la limpieza administrada y 404 llega solo después de que finaliza el tiempo de ejecución (#2154)
  • Se corrigió que el ejecutor de tareas tratara un archivo de salida vacío como código de salida 0, lo que reportaba una tarea fallida o interrumpida como Succeeded cuando la corrección se cancelaba en mitad de la escritura (#2270)

Execd

  • Informar métricas de CPU/memoria en el ámbito de la zona de pruebas y muertes de OOM: GET /metrics leyó el /proc del host dentro del contenedor, por lo que los paneles mostraron números de todo el host; el uso ahora proviene del propio cgroup del sandbox cuando se configuran los límites (la vista del host se mantiene para invitados ilimitados) y un sondeador cgroupfs diferencia el contador de muertes OOM del kernel cada 5 s para exportar execd.system.oom.kills con registros de advertencia estructurados; no se requieren capacidades (#2200 #2191)
  • Servir la sesión privada /tmp a través de los archivos API: el /tmp del perfil de aislamiento estricto era un tmpfs anónimo sin ruta del lado del host, por lo que las rutas de los archivos API bajo /tmp fallaron y las personas que llamaron tuvieron que trasladar artefactos a través de comandos de shell base64; /tmp ahora es un directorio por sesión respaldado por el host y enlazado en el espacio de nombres: la misma semántica privada, pero legible y grabable a través de los puntos finales de archivos existentes (#2424)
  • Admite autenticación PTY WebSocket del navegador: los navegadores no pueden configurar X-EXECD-ACCESS-TOKEN en un protocolo de enlace WebSocket nativo, por lo que las conexiones del terminal necesitaban un relé BFF; la actualización de PTY ahora acepta el token execd existente a través de la entrada de credencial del subprotocolo opensandbox-pty (estilo Kubernetes) sin un nuevo emisor de token y se conserva la prioridad del encabezado para SDK/CLI clients (#2334)
  • Mantener activas las sesiones aisladas cuando se cancela o desconecta una ejecución en primer plano: el contexto de la ejecución se deriva de la solicitud HTTP, por lo que una desconexión o una expiración de timeout_seconds SIGINTaba todo el grupo de procesos, incluido el shell de la sesión persistente: la sesión finalizaba y cada ejecución posterior era 404; Las ejecuciones ahora interrumpen solo el comando en ejecución (con una escalada SIGKILL limitada) mientras la sesión sobrevive, y las ejecuciones silenciosas en primer plano emiten pings SSE periódicos para que los tiempos de espera inactivos de la puerta de enlace ya no cierren la transmisión (#2351)
  • Preservar los finales de línea de salida de la sesión bash: los eventos de salida estándar run_in_session eliminaron bytes \n/\r, por lo que las líneas en blanco eran irrecuperables y la concatenación de eventos no reconstruía la salida; El texto del evento ahora lleva su final de línea original: los consumidores deben concatenar el texto del evento por ejecución (#2318)
  • Finalizar una ejecución de Jupyter cuando su núcleo muere o la conexión se interrumpe: ambos casos previamente dejaban la solicitud del intérprete de código abierta indefinidamente con pings SSE manteniéndola viva; ahora fallan la ejecución (KernelDied / KernelConnectionLost) exactamente una vez (#2401)
  • Mantener la salida de la sesión de lectura más allá de una línea de más de 16 MiB: el ciclo de lectura se detuvo en el límite: las sesiones de bash se colgaron hasta el tiempo de espera predeterminado de 24 h y las sesiones aisladas filtraron la salida a la siguiente ejecución; Las líneas demasiado largas ahora se transmiten en pedazos (nunca se dividen en UTF-8) (#2275)
  • Ejecutar código de fondo grande en sesiones aisladas: el contenedor pasó el código como un único argumento bash -c, y Linux limita un argumento ejecutivo a 128 KiB; el código de fondo anterior falló solo con Argument list too long; ahora se entrega a través de stdin como la ruta de primer plano (#2400); sondee la capacidad de la red privada, por lo que los tiempos de ejecución restringidos obtienen un error estructurado para las sesiones share_net=false en lugar de un EOF opaco (#2333)

Redes

salida

Los elementos de la bóveda OSEP-0022 se refieren a la superficie de la bóveda de credenciales del perfil fast-sandbox; los elementos OSEP-0023 permanecen dentro del alcance del tiempo de ejecución de revisión experimental predeterminado.

  • Agregue la bóveda de salida para entornos aislados rápidos (OSEP-0022), aterrizaje en etapas: la superficie de retransmisión interna /vault/{sandboxUid} con POST de solo creación (409 en duplicado, atómico en réplicas de servidores), PUT de revisión completa con expectedRevision y una condición previa expectedIncarnation para que un escritor obsoleto nunca pueda aterrizar en el sucesor de un reinicio, valor que incluye GET y DELETE que mantiene la política. (#2249); persistencia duradera por sujeto: un archivo por sujeto en un volumen con ámbito de pod (tmpfs opcional), el mismo protocolo de confirmación que los archivos de políticas, por lo que ack significa duradero y aplicado, recarga protegida por encarnación y purga al desvincular (#2252); y se eliminó la ruta de bóveda fastlet-proxy reemplazada (#2247)
  • Llevar la bóveda a través de pausa/reanudación (OSEP-0022 "Ciclo de vida de la bóveda"): VAULT_EXPORT copia el archivo de la bóveda en el paquete de instantáneas estrictamente antes del desmontaje en tiempo de ejecución y sella el asunto (todas las operaciones de la bóveda responden 409 mientras están en pausa; la aplicación continúa), y VAULT_IMPORT es la única transferencia de encarnación autorizada: una falla de exportación genuina no supera el punto de control de pausa, por lo que el desmontaje nunca se ejecuta sin un paquete y una capacidad vaultTransfer la señal permite que una salida sin persistencia de la bóveda omita la transferencia en lugar de fallar (#2255 #2290)
  • Fijar la CA MITM de la zona de pruebas rápida (OSEP-0022): la CA versionada y fijada por el grupo se inicializa desde un montaje secreto de solo lectura en el confdir de mitmdump, reemplazando la generación al inicio; un reinicio de salida ya no rota la CA e invalida silenciosamente el TLS trust de cada zona de pruebas activa; una CA faltante o no coincidente rechaza solo el complemento MITM con mitmCaFingerprint / mitmCaDown aparecido en /healthz (#2251)
  • Defina la toma de control de sujeto obsoleto en la reutilización de ranuras: la clave de despacho rápido de la zona de pruebas es la IP de la ranura y las ranuras se reutilizan, por lo que un SET_BINDING puede reclamar una clave que aún está en manos de un sujeto inactivo pero registrado; la salida ahora lo trata como autoritativo, eliminando las reglas nft del sujeto obsoleto, el recuento de DNS, la redirección de MITM y el segmento de bóveda antes de registrar el sucesor denegar primero (#2250)
  • Alinear la política de red de espacio aislado rápido con el patrón de la bóveda: la política registrada pasa a un estado de salida retenida: una superficie de retransmisión /policy/{sandboxUid} con condiciones previas de revisión, archivos duraderos por tema, transferencia de instantáneas POLICY_EXPORT/POLICY_IMPORT y, después de un reinicio de salida, el archivo confirmado reemplaza la entrada de enlace reproducida en el momento de creación (#2309)
  • Admite reglas de salida con ámbito de puerto de extremo a extremo (perfil clásico): NetworkRule.ports (TCP 1–65535, ≤256 por regla) hace que target sea opcional: reglas de solo puerto o puertos combinados con una IP/CIDR; dominio+ports se rechaza porque las reglas de dominio se evalúan en la capa de proxy DNS; una lista blanca de reachable.ports.cap enviada por el operador se aplica como una regla de siempre denegación antes de cada usuario, por lo que ni siquiera defaultAction: allow puede abrir un puerto que no está en la lista blanca, y la ruta rápida de la zona de pruebas rechaza ports con 400 hasta que la ruta fastlet nft pueda aplicarlos (cerrado ante fallos, documentado) (#2212)
  • Eximir el objetivo de redireccionamiento MITM de las reglas de ámbito de puerto: con el piso del puerto del operador y el MITM transparente ambos activos, cada flujo interceptado fue bloqueado silenciosamente: iptables REDIRECT reescribió el puerto 80/443 al oyente local antes de que se ejecutara la cadena de filtro, por lo que la caída del complemento del piso juzgó el puerto reescrito; la tupla de escucha ahora se acepta antes que cada regla de ámbito de puerto, sin agregar nueva accesibilidad, y un puerto interceptado no incluido en la lista blanca ahora falla visiblemente en el proxy en lugar de pasar silenciosamente (#2435)
  • Continuar con la base experimental OSEP-0023 [EXPERIMENTAL] en todos los aspectos: admisión a Vault vinculada a credenciales en vivo con rotación por solicitud (#2176), revisiones de políticas reconocidas antes de la publicación (#2182), admisión HTTP/2 con drenaje limitado (#2201), contención de fallas de tiempo de ejecución de forma inesperada Salida MITM (#2172), persistencia de archivos de políticas de revisión atómica (#2162), clasificación de efectos de aplicación nft (#2167), selectores de transferencia TLS estáticos con rechazo de inicio para listas nativas en conflicto (#2229), contadores de admisión TLS (#2265), la base de IPC de revisión de tema de solo instalación (#2284) y las transiciones de tema de Fast Sandbox convergentes antes de los consumidores del ciclo de vida v2 (#2294)
  • Y los elementos más pequeños: incluye egress-trace, un visor de admisión de solo lectura dentro de la imagen de salida (estado de política en vivo, conjuntos de nft, concesiones de DNS, veredictos por conexión y un subcomando probe; el contenido descifrado nunca se muestra) (#2230); reenviar consultas de DNS a través de TCP cuando el client usaba TCP, por lo que finalmente llegan respuestas grandes truncadas (SPF/DKIM TXT, respuestas de muchos registros) (#2358); preservar las reglas de DNS de la puerta de enlace compartida cuando se lanza el último tema en una puerta de enlace de zona de pruebas rápida, que anteriormente eliminó toda la tabla nft compartida (#2427); recorte fsyncs desde el arranque de la política de tiempo de creación y agregue instrumentación de creación de latencia por etapa: entrega en caliente real medida por debajo de 100 ms de extremo a extremo con la política aplicada (#2327)

OpenSandbox release-1.2.0

Stable cut of the 1.2.0 line, carrying everything merged since release-1.1.1 through two release candidates plus a post-rc hardening delta. Images shipped with the rcs; SDK/CLI/server packages publish at 1.2.0. Everyone on 1.1.x should upgrade. Baseline for every section below: release-1.1.1.

Highlights

  • Auto-pause and wake-on-access for fast sandboxes (OSEP-0024) lands end to end: the ingress records activity and parks requests to paused sandboxes until the restore completes, the server runs an idle sweeper behind an opt-in lifecycle.idlePolicy create field, and all five SDKs get the wake-retry contract — off by default, additive only (#2156 #2180 #2192 #2198 #2218)
  • Credential Vault (OSEP-0022) lands end to end for fast sandboxes: the egress sidecar holds the vault with durable per-subject persistence and sealed pause/resume transfer, the server exposes the user-reachable vault API with credential values never appearing on any public read, and the MITM CA is pinned per pool so an egress restart no longer rotates the trust anchor under live sandboxes — plus port-scoped egress rules end to end in the classic profile (#2249 #2252 #2255 #2263 #2251 #2212)
  • Fast Sandbox snapshots and template builds can publish to and boot from OCI registries (OverlayBD OCI lifecycle), and a reliability campaign removes whole-call timeouts from SDK file transfers in all five languages, makes execd report sandbox-scoped CPU/memory and OOM kills, and fixes a long list of Docker-backend correctness and PTY/session output issues (#2338 #2165 #2200 #2191)

Server

  • Implement the server side of OSEP-0024 auto-pause for fast sandboxes: the lifecycle.idlePolicy create field (idleTimeoutSeconds 30–86400, onIdle: pause, wakeOnAccess, optional activeProbe) persists as a reserved Sandbox CR annotation; an idle sweeper enumerates opted-in fsb sandboxes, checks activity in Redis, takes a per-sandbox pause lock, and issues an idempotent FastPath PauseSandbox; a declared activeProbe runs through the ingress gateway, and an OpenSandbox-Skip-Activity sentinel suppresses one observation and is stripped on both gateway and proxy hops. Config moves under [automation.idle_pause], and redis.dsn is validated at load when the sweeper is enabled (#2192 #2181 #2215)
  • Implement the Credential Vault API (OSEP-0022, fast-sandbox profile): POST|GET|PATCH|DELETE /v1/sandboxes/{id}/credential-vault pushes complete vault revisions over the FastPath handler relay and treats the relay response as the synchronous egress-validated ack — the CRD never carries vault material and every public read is sanitized server-side; PATCH composes in memory with expectedRevision as the cross-replica backstop, non-fsb backends proxy the sidecar's /credential-vault surface, and the fsb credentialProxy create-time rejection is lifted (#2263)
  • Bake the pinned MITM CA into server-created SandboxTemplates (OSEP-0022): new [kubernetes] template_mitm_ca_secret config (default off) emits spec.egressMitmCertificate — the certificate entry only, never the private key — on every template; the Secret must exist in each template namespace (ops-runbook distribution), and a missed copy fails the build observably (#2288)
  • Add lifecycle.renewalPolicy (OSEP-0009): the renew-on-access opt-in moves from the opaque extensions["access.renew.extend.seconds"] key to a structured renewalPolicy.extendSeconds (300–86400); the legacy key is deprecated (supported throughout 1.x, removed in 2.0), and fast sandbox rejects it with 400 rather than silently accepting a no-op (#2296)
  • Implement the diagnostics context endpoint (spec in #2236): GET /v1/sandboxes/{sandboxId}/diagnostics/context returns the sandbox ID, lifecycle state, backend type, and backend-defined identifiers for Docker, Kubernetes, and Fast Sandbox without connecting to execd — Kubernetes context stays available before a Pod is allocated; extension backends that don't implement it return 501 (#2292)
  • Forward the still-encoded path through the sandbox proxy: Starlette bound the {full_path:path} route from the percent-decoded path, so a decoded ? started a query, %2F became a separator, and %2E%2E segments were resolved — closing a prefix-escape on Docker host-mapped endpoints; the proxy now takes the client's still-encoded tail from the raw path (validating it decodes to the routed path) and reads the query from the raw query string, so backends receive request targets byte-for-byte, matching the ingress gateway (#2228)
  • Keep blocking Docker calls off the event loop: proxy endpoint lookups, network-existence validation, and per-PVC volume inspect/create ran synchronously inside async handlers, so a slow Docker daemon (e.g. during a large pull) froze every other request including proxy traffic; they now run on worker threads with tenant context preserved, and volume-validation failures still clean up auto-created volumes (#2268 #2366)
  • Stop reporting image-inherited labels as sandbox state on Docker: metadata reads fell back to every non-reserved container label — including labels merged in from the image — and restored containers inherited reserved labels such as expires-at, host ports, and the egress token; in the worst case a restored TTL sandbox was deleted as already expired after a server restart. Creates now record the request's metadata keys in a reserved label and read back only those keys, and reserved labels present on the image but not set by the sandbox are blanked before container start (#2363 #2269)
  • Reject gVisor snapshots that would silently drop writes: docker commit under gVisor's default --overlay2=root:self can report READY while restoring none of the sandbox's writes; snapshot preflight now refuses gVisor unless the effective args include --overlay2=none, and create fails closed when the filesystem diff is filestore-only (#2241)
  • Keep an fsb snapshot whose create reply was lost: a UNAVAILABLE/DEADLINE_EXCEEDED from FastPath after the request was durably accepted returned 500 without writing a row, stranding the SandboxSnapshot and its published artifacts with no record; the create now probes for the snapshot before failing and reports it as submitted when FastPath persisted it (#2361)
  • Fix the remaining Docker-backend rough edges: BatchSandbox expiry reports Terminated/SANDBOX_EXPIRED instead of Running past spec.expireTime (#2238); concurrent lifecycle conflicts map to 404/409 instead of 500 (#2387); concurrent metadata patches no longer race into 500s or dropped keys (#2267 #2281); createdAt stays stable across reads and pause/resume transitions are recorded (#2405); network policy actions are validated and unknown fields return 422 (#2383 #2385); the sandbox image is read from the container config so a docker rmi -f'd image no longer 500s GET /sandboxes (#2353); template reads trust the database projection instead of syncing the CR on every create-gate check (#2326); the renew cooldown applies to every renew source when the Redis consumer is enabled (#2276 #2279); BatchSandbox pods default to restartPolicy: Never so a kubelet restart can no longer wipe the writable layer while reporting Succeed (#2128); podman's pasta/slirp4netns/none network modes pass through (with networkPolicy rejected, since there is no bridge to attach to) (#2203); Docker timestamps with unusual fractional seconds no longer silently report the current time (#2220); and the execd cache container honors [docker] security profiles and secure_runtime (#2254)

SDKs

Code changes below ride the 1.2.0 packages.

  • Add the OSEP-0024 SDK contract to all five languages: a typed lifecycle.idlePolicy create field with client-side fail-fast validation, plus the wake-retry contract — on a 503 carrying the gateway-owned OpenSandbox-Wake: expired marker (its presence proves the request was parked and never forwarded, making any-method retry safe), the SDK resends after Retry-After under a bounded budget (default 5 attempts / 60 s, per-client knobs) and exhaustion raises a typed wake-timeout exception; bare 503 handling is unchanged (#2198 #2218). The contract initially bypassed streaming transports; the request that starts a stream now wake-retries in JavaScript, Python, and Go — established streams are never replayed — while C#/Kotlin stream starts currently fail fast (#2357 #2426)
  • Add the Credential Vault client contract to all five SDKs (OSEP-0022): template-backed sandboxes route vault calls through the server on the same template-origin signal as network policy, while sidecar-direct adapters stay untouched (#2263)
  • Stop capping file uploads and downloads at the request timeout (30 s default) in all five SDKs — the whole-call timeout covered sending the body and reading the response, so any large or slow transfer failed mid-flight even while healthy; transfers now run on a dedicated client with no whole-call deadline that still bounds the wait for response headers, so a stalled transfer still fails instead of hanging (#2165 #2186 #2196 #2206)
  • Implement diagnostics across the SDK surface (with #2292): context is exposed through both the manager and sandbox facades in all five languages, and JavaScript, Go, and C# gain public logs/events APIs matching the existing Python/JVM surface (#2292)
  • Add lifecycle.renewalPolicy to all five SDKs (OSEP-0009): a typed create field with client-side fail-fast validation (extendSeconds 300–86400), replacing the opaque extensions key (#2296)
  • Support port-scoped egress rules in all five SDKs: NetworkRule.ports (TCP 1–65535, at most 256 per rule, target now optional) with client-side validation mirroring the server (range, duplicates, cap, domain+ports rejected); JavaScript encodes the target-or-ports invariant as a union type (#2212)
  • Surface the authoritative execution_complete.exit_code in Go and Kotlin, preferring it over the previous evalue/inferred-0 fallbacks while staying compatible with older servers (#2330); honor an explicitly supplied OPEN-SANDBOX-API-KEY header over the configured key regardless of header-name casing in JavaScript, C#, and Kotlin (#2348 #2372 #2375); suppress sandbox.create metrics for client-pool warmup creates in Go, Python, and JavaScript (#2199)
  • Strip protected credentials on cross-origin redirects in JavaScript, C#, and Go: sandbox-prefixed headers, endpoint tokens (X-EXECD-ACCESS-TOKEN, X-API-Key), and configured authentication headers are removed whenever a redirect changes scheme/host/port, while same-origin hops and unrelated headers are preserved; file uploads never follow redirects in JavaScript, and in browsers an opaque redirect fails closed rather than risk replaying credentials (#2178 #2173 #2183)
  • Route the JavaScript and C# code-interpreter data-plane headers through the shared policy: direct-mode /code requests no longer carry the tenant OPEN-SANDBOX-API-KEY to execd, an explicitly configured connection key keeps precedence over the configured apiKey without duplicate case-variant entries, and endpoint-scoped credentials still win (#2149)

Python

  • Retry the gateway's wake timeout when starting a stream: the SSE clients stripped the retry wrapper entirely, so commands.run, session runs, and codes.run against an auto-paused sandbox failed with the marked 503 whenever the restore outlasted the gateway's park budget; streaming transports now carry a wake-only retry (no general retries, no added deadlines), and the docs no longer claim streams bypass retries (#2357)
  • Normalize the connection domain: a trailing slash or /v1 in domain / OPEN_SANDBOX_DOMAIN produced //v1/... URLs that the server 404'd — the same variable worked in every other SDK; Python now strips both (#2347)
  • Reuse SSL contexts across owned transports: CA certificates were reloaded on every call, blocking the event loop under asyncio concurrency — measured create P50 improves ~18–28% under concurrency (#2360)
  • Preserve the first SSE event after a UTF-8 BOM (including one split across network chunks) (#2226); close wake-timeout response bodies on cancellation (#2371); close interrupted async file-download responses so a cancelled or failed read no longer occupies the connection (#2369); keep the status code when an error response carries a non-JSON body — a proxy's HTML/empty 404/500 previously surfaced as InvalidArgumentException with no status (#2402); raise the shared structured error from Code Interpreter codes.run failures instead of a hand-built exception that lost retry_after (#2364); keep code-interpreter output fragments together in Execution.text instead of inserting extra newlines (#2408); round sub-millisecond command timeouts up to 1 ms instead of sending 0 (which disabled the timeout) (#2419); stop propagating a cancelled endpoint fetch to concurrent waiters (#2277); forward credential_proxy through sandbox pools, which silently dropped it before (#2283); stop reporting failed file replacements as successful (#2222); clean up cancelled async pool startup instead of getting stuck in STARTING (#2209); regenerate the lifecycle client to drop stale hardcoded defaults (wire behavior unchanged) (#2280); MCP: cancelling one tool call no longer cancels a coalesced shared connect for the same sandbox, which failed every other waiting call (#2355)

JavaScript

  • Preserve execution events with CR line endings: the SSE parsers only split on LF, so a valid CR-delimited stream silently dropped the execution ID, output, and completion event (#2374)
  • Scope in-flight endpoint-cache invalidation to each sandbox, so invalidating sandbox B no longer discards a pending fetch's result for sandbox A (#2349)
  • Preserve reused byte chunks in file uploads: an async producer that reuses a Uint8Array/Buffer view uploaded the mutated content twice instead of both snapshots (#2428); keep caller cancellation active after response headers arrive — aborting mid-SSE-stream or mid-download previously left the body running (#2350)
  • Strip protected headers on cross-origin redirects (see the cross-SDK entry above) (#2173)

Kotlin

  • Keep an explicit API key header ahead of the configured key in any casing, and stop attaching an empty key header when unconfigured (#2375)
  • Preserve the raw response body on deserialize failures and catch LinkageError from a serializer/runtime mismatch — previously an AbstractMethodError escaped every handler, killing SSE streams silently with the server's actual response unrecoverable (#2416)

C#

  • Honor an explicit API key header regardless of casing: the case-sensitive check added a second, conflicting default entry, and the metrics reporter replaced the caller's credential (#2372)
  • Strip protected credentials on cross-origin redirects and route code-interpreter requests through the shared data-plane header policy (see the cross-SDK entries above) (#2183 #2149)

Go

  • Stop retrying non-idempotent writes by default: with retry enabled, 27 POST/PATCH call sites (sandbox/session/command/file/snapshot/vault mutations) could execute twice and still return success — POST/PATCH no longer retry status codes by default, retry only transport failures proven to be pre-send (dial/CONNECT/TLS before request bytes), and SSE bootstraps bypass the generic retry loop; callers who accept duplicate-execution risk can opt in via RetryConfig.RetryableStatusCodesNonIdempotent (#2342)
  • Retry the gateway's wake timeout when starting an SSE stream: the six streaming call sites (command/code/session runs, metrics watch) previously failed immediately with the marked 503; the bootstrap now parks within the same Retry-After budget and returns the typed wake-timeout error on exhaustion — established streams are never replayed, a bare 503 is still not retried even with write-status opt-in, and a 503 reached through a redirect chain loses wake provenance so an already-executed request is never resent; callers relying on fail-fast can pass WakeRetryDisabled() (#2426)
  • Keep line terminators in Execution.Text(): execd already includes \n/\r in event text and requires concatenation to reconstruct stdout, but the helper inserted an extra newline between terminated events ("a\n" + "b\n" became "a\n\nb\n"); a separator is now added only when the preceding event does not already end in a terminator (#2381)
  • Strip the tenant API key from direct-mode data-plane requests: a tenant key supplied through ConnectionConfig.Headers was delivered to execd and the egress sidecar inside the untrusted sandbox — completing the credential-exposure fixes across all five SDKs (#2337)
  • Authenticate proxied data-plane requests with the API key header instead of smuggling the tenant key into the sandbox, fixing 401s in multi-tenant proxy mode (#2274); surface execution_complete.exit_code (#2330)

Controller

  • Retain a BatchSandbox until cleanup completes: a deleted sandbox could disappear from the lifecycle API (GET 404) while its owned pod still ran, letting a replacement sandbox write the same persistent directory before the old writer exited; deletion now uses foreground cascading deletion alongside the existing finalizers — queries report Stopping during managed cleanup, and 404 arrives only after the runtime is gone (#2154)
  • Fix task-executor treating an empty exit file as exit code 0, which reported a failed or interrupted task as Succeeded when the shim was killed mid-write (#2270)

Execd

  • Report sandbox-scoped CPU/memory metrics and OOM kills: GET /metrics read the host's /proc inside the container, so dashboards showed host-wide numbers; usage now comes from the sandbox's own cgroup when limits are configured (host view kept for unlimited guests), and a cgroupfs poller diffs the kernel OOM kill counter every 5 s to export execd.system.oom.kills with structured warn logs — no capabilities required (#2200 #2191)
  • Serve the session-private /tmp through the files API: the strict isolation profile's /tmp was an anonymous tmpfs with no host-side path, so files-API paths under /tmp failed and callers had to shuttle artifacts through base64 shell commands; /tmp is now a host-backed per-session directory bind-mounted into the namespace — same private semantics, but readable and writable through the existing files endpoints (#2424)
  • Support browser PTY WebSocket authentication: browsers cannot set X-EXECD-ACCESS-TOKEN on a native WebSocket handshake, so terminal connections needed a BFF relay; the PTY upgrade now accepts the existing execd token via the opensandbox-pty subprotocol's credential entry (Kubernetes-style) with no new token issuer and header precedence preserved for SDK/CLI clients (#2334)
  • Keep isolated sessions alive when a foreground run is cancelled or disconnected: the run's context derived from the HTTP request, so a disconnect or timeout_seconds expiry SIGINT'd the whole process group including the persistent session shell — the session died and every later run 404'd; runs now interrupt only the running command (with a bounded SIGKILL escalation) while the session survives, and silent foreground runs emit periodic SSE pings so gateway idle timeouts no longer close the stream (#2351)
  • Preserve bash session output line endings: run_in_session stdout events dropped \n/\r bytes, so blank lines were unrecoverable and concatenating events did not reconstruct the output; event text now carries its original line ending — consumers should concatenate event text per run (#2318)
  • End a Jupyter execution when its kernel dies or the connection drops: both cases previously left the code-interpreter request open indefinitely with SSE pings keeping it alive; they now fail the execution (KernelDied / KernelConnectionLost) exactly once (#2401)
  • Keep reading session output past a line longer than 16 MiB: the read loop stopped at the cap — bash sessions hung until the 24 h default timeout, and isolated sessions leaked output into the next run; over-long lines are now passed on in pieces (never splitting UTF-8) (#2275)
  • Run large background code in isolated sessions: the wrapper passed code as a single bash -c argument, and Linux caps one exec argument at 128 KiB — background code above that failed with only Argument list too long; it is now delivered through stdin like the foreground path (#2400); probe private-network capability so restricted runtimes get a structured error for share_net=false sessions instead of an opaque EOF (#2333)
  • And the smaller fixes: report exit_code explicitly on command completion and errors (#2303 #2316); send run errors after the stream started as framed SSE error events instead of a bare JSON body the Python SDK dropped (#2354); keep PTY output buffered until drained when the shell exits, so the last screen of output is no longer lost (#2362); always send the WSCloseTakenOver (4001) close frame on PTY takeover, even mid-write (#2376 #2378); write an isolated run's script while reading its output so a chatty run can no longer deadlock on the stdin/stdout pipes (#2399); reject out-of-scope absolute paths in the session files view instead of silently touching the wrong file (#2322); serve binds mount points through the isolated session files API (#2299); truncate command output files before unlink so daemons holding the fd can't cause invisible disk growth (#2295); omit invalid upper-usage metrics and fail quota admission closed on scan errors (#2257); deduplicate JDK MITM CA imports across shared trust stores (~6.2 s → ~0.6 s for four JDKs) (#2310); default PTY sessions to TERM=xterm-256color when unset (#2313); percent-encode quotes and backslashes in Content-Disposition filenames (#2161); and parse the Range header before setting download headers so a malformed range returns a clean JSON 416 (#2216)

Networking

egress

The OSEP-0022 vault items concern the fast-sandbox profile's credential-vault surface; the OSEP-0023 items remain scoped to the default-off experimental revision runtime.

  • Add the egress-held vault for fast sandboxes (OSEP-0022), landing in stages: the internal /vault/{sandboxUid} relay surface with create-only POST (409 on duplicate, atomic across server replicas), full-revision PUT with expectedRevision and an expectedIncarnation precondition so a stale writer can never land on a reset's successor, value-including GET, and DELETE that keeps the policy (#2249); durable per-subject persistence — one file per subject under a Pod-scoped volume (optional tmpfs), the same commit protocol as policy files so acked means durable and applied, incarnation-fenced reload, and purge on unbind (#2252); and the superseded fastlet-proxy vault route removed (#2247)
  • Carry the vault across pause/resume (OSEP-0022 "Vault Lifecycle"): VAULT_EXPORT copies the vault file into the snapshot bundle strictly before runtime teardown and seals the subject (all vault ops answer 409 while paused; enforcement continues), and VAULT_IMPORT is the only authorized incarnation transfer — a genuine export failure fails the pause checkpoint so teardown never runs without a bundle, and a vaultTransfer capability signal lets an egress without vault persistence skip the transfer instead of failing (#2255 #2290)
  • Pin the fast-sandbox MITM CA (OSEP-0022): the pool-pinned, versioned CA is seeded from a read-only secret mount into the mitmdump confdir, replacing generate-on-start — an egress restart no longer rotates the CA and silently invalidates every live sandbox's TLS trust; a missing or mismatched CA refuses only the MITM addon with mitmCaFingerprint / mitmCaDown surfaced on /healthz (#2251)
  • Define stale-subject takeover on slot reuse: the fast-sandbox dispatch key is the slot IP and slots are reused, so a SET_BINDING can claim a key still held by a dead-but-registered subject — egress now treats that as authoritative, tearing down the stale subject's nft rules, DNS refcount, MITM redirect, and vault slice before registering the successor deny-first (#2250)
  • Align the fast-sandbox network policy with the vault pattern: the recorded policy becomes egress-held state — a /policy/{sandboxUid} relay surface with revision preconditions, durable per-subject files, POLICY_EXPORT/POLICY_IMPORT snapshot transfer, and, after an egress restart, the committed file superseding the replayed create-time binding input (#2309)
  • Support port-scoped egress rules end to end (classic profile): NetworkRule.ports (TCP 1–65535, ≤256 per rule) makes target optional — port-only rules, or ports combined with an IP/CIDR; domain+ports is rejected since domain rules evaluate at the DNS proxy layer; an operator-shipped reachable.ports.cap whitelist is enforced as an always-deny ahead of every user rule so even defaultAction: allow cannot open a non-whitelisted port, and the fast-sandbox route rejects ports with 400 until the fastlet nft path can enforce them (fail-closed, documented) (#2212)
  • Exempt the MITM redirect target from port-scoped rules: with the operator port floor and transparent MITM both active, every intercepted flow was silently blackholed — the iptables REDIRECT rewrote dport 80/443 to the local listener before the filter chain ran, so the floor-complement drop judged the rewritten port; the listener tuple is now accepted ahead of every port-scoped rule, adding no new reachability, and a non-whitelisted intercepted port now fails visibly at the proxy instead of passing silently (#2435)
  • Continue the OSEP-0023 experimental foundation [EXPERIMENTAL] across the line: live credential-bound Vault admission with per-request rotation (#2176), acknowledged Policy revisions before publication (#2182), HTTP/2 admission with bounded drain (#2201), runtime-fault containment on an unexpected MITM exit (#2172), atomic revision policy-file persistence (#2162), nft apply-effect classification (#2167), static TLS passthrough selectors with startup rejection for conflicting native lists (#2229), TLS admission counters (#2265), the installation-only subject revision IPC foundation (#2284), and converged Fast Sandbox subject transitions ahead of the v2 lifecycle consumers (#2294)
  • And the smaller items: ship egress-trace, a read-only admission viewer inside the egress image (live policy state, nft sets, DNS leases, per-connection verdicts, and a probe subcommand; decrypted contents are never shown) (#2230); forward DNS queries over TCP when the client used TCP, so large truncated answers (SPF/DKIM TXT, many-record responses) finally arrive (#2358); preserve shared gateway DNS rules when the last subject on one fast-sandbox gateway releases, which previously removed the entire shared nft table (#2427); trim fsyncs from the create-time policy bootstrap and add per-stage create-latency instrumentation — real warm delivery measured sub-100 ms end to end with policy enforced (#2327)

ingress

  • Implement OSEP-0024 activity tracking and wake-on-access: with --activity-enabled, every routed request records a monotonic activity timestamp to Redis — fire-and-forget, never on the hot path; with --wake-enabled, a request routed to a paused fast sandbox is parked instead of answered 503: one ResumeSandbox per replica per sandbox under a checkpoint-fenced singleflight, a bounded parking lot, and stale-route replay restricted to idempotent methods with reproducible bodies; the wake-timeout answer carries the OSEP-defined marker (503 + Retry-After: 1 + OpenSandbox-Wake: expired), stripped from every upstream response so a sandbox cannot forge provenance; with both flags unset, behavior is byte-identical to before (#2156 #2180)
  • Stop rewriting unclean request paths: http.ServeMux answered paths with //, ., or .. segments with a 301 to the cleaned path — so requests never reached the sandbox and a followed POST became a GET; the gateway now dispatches status endpoints by exact escaped path and proxies everything else unchanged (#2403)

Fast Sandbox

  • Publish snapshots and template builds to OCI registries: each OverlayBD build can target an OCI registry (rootfs and snapfiles images, no name index — Sandboxes boot from status.manifestRef), Fastlets enable OCI by default with an explicit opt-out, OverlayBD templates require OCI storage, the controller consolidates snapshot artifact cleanup and refreshes Fastlet capacity after runtime deletion, and a bounded manifest cache survives Fastlet replacement; the SandboxSnapshot CRD gains oci:// manifest references and makes spec.templateName optional for OCI snapshots (#2338)
  • Place pool sandboxes by resources instead of fixed slots: spec.sandboxResources gains a mode (LegacySlot | ResourceAware) with a separate cpu/memory overcommitRatio (required in ResourceAware mode); cpu/memory limits become runtime limits/defaults that a ResourceAware pool may override per request, Sandbox status gains caller-owned immutable resources.limits (ResourceAware pools only), and pool status reports resource commitment plus fastlet/sandbox counters (#2442)
  • Make sandbox deletion reliable: deletion now sends a fenced Fastlet delete before any runtime-absence check, so a transport failure or empty inspect response is no longer treated as proof the sandbox is gone (which could orphan the microVM while the CR disappeared); the Fastlet records a per-identity tombstone so a delayed create cannot revive a deleted sandbox. Create placement also recovers faster: FastPath refreshes its candidate list within a bounded budget after proven rejections (#2214)
  • And the smaller items: read-only snapfiles are shared within each Fastlet (fsb-vm shares them by default), with recovery of shared snapfiles and orphan-cache cleanup (#2438); batch guest NAT updates into one iptables-restore --noflush so reapplying a guest address no longer accumulates rules (#2214); defer SET_BINDING while the network attachment has no IP, stop SandboxPool status-update loops, gate route removal on runtime deletion, and canonicalize Docker Hub credential hosts (#2338); and emit per-create phase timing from Fastlets, feeding the create-latency evidence pipeline (steady-state warm delivery measured at 16–17 ms past create) (#2327)

  • Examples: add an all-in-one Docker image for the DeerFlow example bundling the OpenSandbox server and the DeerFlow backend, for one-command workshop starts (#2262)

Upgrade & Compatibility

  • Breaking (Go SDK): POST/PATCH requests are no longer retried by default — status-code retries for writes require explicit opt-in via RetryConfig.RetryableStatusCodesNonIdempotent, and ambiguous transport failures (read/write timeouts, unexpected EOF) are no longer retried for writes; callers that relied on write retries must handle the returned error or opt in (#2342)
  • Behavior change (Python and Go SDKs): the request that starts a stream (commands.run, codes.run, session/isolated runs, metrics watch) now retries the gateway's marked wake-timeout 503 within the wake budget instead of failing fast — established streams are never replayed; keep the old fail-fast with WakeRetryDisabled() (Go) or disabled wake retry (Python) (#2357 #2426)
  • Behavior change: SDK display helpers no longer insert extra newlines between already-terminated stdout events (Go Execution.Text(), Python code-interpreter Execution.text), and the Go helper treats a trailing CR as a terminator for legacy pre-1.2 bash-session events (#2381 #2408)
  • Behavior change: bash-session stdout event text now includes its original line endings, and blank lines appear as events — consumers must concatenate event text per run to recover exact output instead of treating each event as a newline-free line (#2318)
  • Behavior change: a BatchSandbox past its spec.expireTime now reports Terminated / SANDBOX_EXPIRED instead of Running, even while the pod is still Ready — callers that treat Running as alive should check expiry (#2238)
  • Behavior change: BatchSandbox pods now default to restartPolicy: Never — deployments that relied on the implicit Always and want restarts must set it explicitly in their batchsandbox_template_file (#2128)
  • Behavior change: deleted sandboxes stay queryable in Stopping until runtime cleanup completes, and only then return 404 — clients sharing a persistent directory should wait for the 404 before starting a replacement (#2154)
  • Behavior change: Docker-backed snapshots of gVisor containers without --overlay2=none are rejected with SNAPSHOT::UNSUPPORTED_RUNTIME (409) instead of publishing a silently incomplete image (#2241)
  • Behavior change: execd CPU/memory metrics report sandbox-scoped values when the sandbox cgroup has limits configured (previously host-wide); metric names and wire format are unchanged, but dashboards will shift (#2200)
  • Behavior change: on Docker, labels inherited from the image no longer appear as sandbox metadata, restored sandboxes no longer inherit the source's reserved labels, and image.uri reports the reference the sandbox was created with (#2363 #2269 #2353)
  • Behavior change: unknown NetworkPolicy/NetworkRule fields now return 422 and unrecognized create-time actions return 400 (previously silently ignored); trailing newlines in labels and resource names are rejected; contract-valid inputs are unchanged (#2383 #2385)
  • Behavior change: networkPolicy is rejected for Docker network modes none/pasta/slirp4netns — previously accepted silently for none (#2203)
  • Behavior change (Go SDK, direct mode): the tenant API key supplied through ConnectionConfig.Headers is no longer sent to execd/egress inside the sandbox (#2337)
  • Behavior change: template reads (GET /templates, the create gate) report the database projection with freshness bounded by watch delivery (normally milliseconds) — a create racing a just-finished build can see a brief retryable 404 (#2326)
  • Behavior change: isolated-session files-API paths outside the session's mounts are rejected with an error instead of silently resolving into the workspace (#2322)
  • Behavior change (experimental egress live mode only): nonempty native ignore_hosts/allow_hosts now reject startup — migrate static TLS bypass entries to OPENSANDBOX_EGRESS_MITMPROXY_PASSTHROUGH_HOSTS (#2229)
  • Behavior change: execd upper-directory quota admission fails closed when upper_max_bytes > 0 and a usage scan fails (previously the quota check was silently bypassed) (#2257)
  • Deprecation: the extensions["access.renew.extend.seconds"] create key is deprecated in favor of lifecycle.renewalPolicy.extendSeconds — supported throughout 1.x, removed in 2.0; setting both is accepted only when values match (#2296)
  • Fast Sandbox: OverlayBD templates now require OCI storage, and snapshot spec.templateName is optional with status.manifestRef admitting oci:// — update consumers that assumed the name index or a required templateName (#2338)

Installation

# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.0
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
# Before first install, configure the server API key and enable the ingress
# gateway (required on Kubernetes; the bare render disables it, and the server
# refuses to start with an empty api_key) — see the deployment guide:
# https://open-sandbox.ai/deployment/
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.0            # Python
npm install @alibaba-group/opensandbox@1.2.0   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.0")
dotnet add package Alibaba.OpenSandbox --version 1.2.0
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.0

# Run the server locally
uvx opensandbox-server==1.2.0

Verify what you installed against the BOM: see Release Verification.
