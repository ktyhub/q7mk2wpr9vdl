Servidor OpenSandbox/v0.2.3

¿Qué hay de nuevo?

⚠️ Cambios importantes

  • OPENSANDBOX_EGRESS_SANDBOX_ID ahora es inyectado por el servidor y rechazado en el entorno de solicitud: el servidor establece incondicionalmente la variable de atribución sandbox-id del sidecar de salida en los tiempos de ejecución de Docker y Kubernetes, y la elimina de la lista de entornos permitidos. Las solicitudes que lo pasan en env ahora obtienen un valor 400 en lugar de un valor falsificado por el usuario. #1381

✨ Características

  • Enganches del ciclo de vida de Sandbox (preStart / periodic), OSEP-0020: CreateSandboxRequest.lifecycle se acepta, se valida (transportes reservados, nombres periódicos duplicados, combinaciones de asignación de grupos) y se transporta a cargas de trabajo Kubernetes a través del entorno reservado OPEN_SANDBOX_LIFECYCLE para que se ejecute execd. Docker rechaza explícitamente las solicitudes de ciclo de vida; PATCH y otros tipos de ganchos están fuera de alcance. Se envía con modelos Java/Kotlin, Python y TypeScript SDK alineados. #1588 #1589
  • El límite de preStart.timeoutSeconds aumentó de 300 a 3 horas: los límites del servidor y OpenAPI ahora permiten hasta 10800 para enlaces previos al inicio; el límite periódico se mantiene en 300s. Se elimina el límite de política de producto del lado execd, lo que mantiene los cambios de política solo en el servidor. #1637
  • Pausa/reanudación de QEMU VMState para entornos limitados basados en runc: captura voluntaria de la memoria del huésped/vCPU/estado del dispositivo a través de la migración QMP; rootfs y VMState comprimidos se almacenan como imágenes OCI separadas codificadas por resúmenes SHA-256 inmutables. Admite la pausa, la separación y la restauración independiente de BatchSandbox agrupadas, al tiempo que preserva la memoria del huésped, el disco grabable, la ID de inicio y la continuidad del contador. Las instantáneas exclusivas de Rootfs siguen siendo compatibles con versiones anteriores. #1584
  • El agotamiento de la capacidad del grupo ahora es identificable por la máquina: el controlador publica una condición PoolAllocationPending/PoolCapacityExhausted; el servidor espera una ventana de adquisición limitada (nuevo kubernetes.pool_acquisition_timeout_seconds, predeterminado 30 segundos) y luego devuelve HTTP 429 con KUBERNETES::POOL_CAPACITY_EXHAUSTED y Retry-After: 5 en lugar del tiempo de espera de preparación genérico 504. Los controladores más antiguos recurren con seguridad al comportamiento existente. #1581
  • Resumen de asignación de grupos en las respuestas del ciclo de vida: getSandbox ahora muestra un bloque Sandbox.allocation opcional (mode: pool, poolRef, state: allocated) para asignaciones confirmadas de grupos Kubernetes, emitido solo para referencias concretas de grupos sin comodines con evidencia de asignación coincidente. No se exponen datos de pod/espacio de nombres/IP. #1481
  • Métricas de solicitud HTTP genéricas a través de OTLP: un middleware ASGI delgado exporta server.http.request.duration (ms) con http_method, http_route coincidente (o unknown para solicitudes no enrutadas/con errores de autenticación) y atributos http_status_code, complementando el histograma de duración de creación existente. Las rutas, ID, claves y cuerpos sin procesar nunca son atributos; no operativo cuando [otel] está deshabilitado. #1561
  • Diagnóstico estable API con alcances: los diagnósticos ahora respetan el contrato de descriptor público en línea: logs: container|all y events: runtime|lifecycle|all, con 400 DIAGNOSTICS_SCOPE_UNSUPPORTED para alcances desconocidos y advertencias explícitas para alcances de mejor esfuerzo incompletos. Las respuestas de texto plano no-scope, obsoletas, todavía funcionan con un encabezado Deprecation. #1553
  • base de backend de flotas de fast-sandbox (OSEP-0007): FastPath v2 gRPC client envuelve todos los RPC de FastPathService con mapeo de errores escritos (FastPathNotFound → 404, etc.), y una capa de mapeo de creación/estado convierte el contrato público en semántica de fast-sandbox, rechazando campos no admitidos (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) con errores claros. Aún no está conectado como tiempo de ejecución activo. #1558 #1559
  • Las claves de firma de acceso seguro pueden provenir de un secreto Kubernetes: el servidor acepta anulaciones de entorno OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY (reflejando la anulación de clave API, se requiere modo de puerta de enlace) y el gráfico Helm agrega server.gateway.secureAccess.existingSecret (mutuamente excluyente con texto sin formato keys, aplicado en el momento del procesamiento) para que los flujos de GitOps nunca confirmen material clave. #1445
  • Docker tiempo de ejecución sandbox_env / sandbox_binds: los nuevos campos [docker] aplican variables de entorno de toda la flota y montajes de enlaces de host a cada contenedor sandbox (la solicitud env gana a sandbox_env; los enlaces de configuración preceden a los enlaces derivados de solicitudes), lo que le da al tiempo de ejecución Docker el gancho del lado del operador que tiene la plantilla de pod K8s. #1303
  • Tiempo de espera de preparación del sidecar de salida configurable: el nuevo [egress] timeout_seconds (30 s predeterminado, valores no positivos rechazados) permite que las implementaciones de Docker ajusten cuánto tiempo espera el servidor por el punto final de estado del sidecar. #1522
  • Espacios de nombres de inquilinos validados al inicio (OSEP-0014): el servidor verifica rápidamente que cada espacio de nombres de inquilinos existe y es accesible antes de atender el tráfico, agregando todos los espacios de nombres faltantes/inaccesibles en un único error fatal en lugar de fallar solo en el momento de la solicitud. OSEP-0004/0005/0014 marcado implementado. #1389

🔒 Seguridad

  • Problemas de dependencia de corrección de CVE: google.golang.org/grpc → v1.82.1 en kubernetes/ingress/execd/egress/internal (correcciones xDS RBAC y HTTP/2), postcss → 8.5.11 (archivo arbitrario leído a través de sourceMappingURL). #1385

🐛 Corrección de errores

  • Búsquedas de puntos finales Docker ~108 veces más rápidas: la búsqueda de contenedores ahora pasa por el nombre determinista sandbox-<id> con la validación de etiquetas opensandbox.io/id, recurriendo al escaneo de etiquetas solo cuando es necesario. Punto de referencia local: 6,07 s → 56 ms para resolución de punto final execd+egress. #1400
  • La caché del informador caduca cuando la vigilancia se detiene: has_synced ahora significa "la caché está actualmente activa", no "una lista inicial terminada una vez"; un reloj bloqueado o medio abierto (por ejemplo, después de una actualización del plano de control) se degrada a lecturas directas de API en lugar de servir al estado congelado para siempre, lo que anteriormente causaba que cada creación fuera 504 con POD_READY_TIMEOUT. Encuadernado derivado de perillas existentes (resync_period + watch_timeout); sin nueva configuración. #1534
  • Fuga de conexión de proxy en respuestas abortadas: cuando un client descendente se desconectó antes de que comenzara la transmisión del cuerpo de la respuesta, la respuesta httpx del backend nunca se publicó, agotando gradualmente el grupo compartido hasta httpcore.PoolTimeout. El proxy ahora posee la respuesta de backend para todo el ciclo de vida de ASGI, protege a aclose() de la cancelación y lo libera en caso de error de configuración. Prueba de estrés: 1000/1000 desconexiones limpiadas. #1488
  • ID de operación de proxy estables y únicos: las 20 operaciones HTTP proxy emitieron previamente 4 ID de operación duplicadas dependientes del proceso (16 advertencias de OpenAPI); Cada método ahora obtiene su propia ID determinista con envío de tiempo de ejecución, autenticación y comportamiento 405 idénticos. Los clients generados deben regenerarse. #1634
  • La creación automática de PVC ya no falla con un 500 mal formado: el parche de referencia del propietario de PVC pasó por una ruta _content_type no compatible que generó ApiTypeError (dejando los PVC sin referencias de propietario) y SandboxErrorCodes.INTERNAL_ERROR no estaba definido, enmascarando el error real. Ambos solucionados: el parche utiliza la ruta de fusión estratégica compatible call_api; código de error definido. #1538 #1447
  • El contenedor de plantilla securityContext ahora llega a los pods: la fusión profunda anteriormente reemplazó los contenedores de la plantilla al por mayor, eliminando silenciosamente el nivel de seguridadContexto de contenedor. Las claves de plantilla ahora complementan (nunca anulan) los valores de tiempo de ejecución, coincidiendo con la filosofía existente de volumeMounts. #1564
  • Las redirecciones de backend relativas a la raíz permanecen en la ruta del proxy: Location: /login de un backend de zona de pruebas se rebasó a /v1/sandboxes/{id}/proxy/{port}/login; Las referencias absolutas, de ruta de red y de solo consulta no se modifican. #1516
  • Los puntos finales del servidor proxy eliminan el encabezado de enrutamiento de entrada: OpenSandbox-Ingress-To (no distingue entre mayúsculas y minúsculas) se elimina de las respuestas use_server_proxy=true, mientras que el acceso seguro y otros encabezados de puntos finales se conservan. #1503
  • No hay encabezados Date/Server duplicados en las respuestas proxy: el proxy conserva un Date de origen mientras suprime el valor predeterminado de Uvicorn (y el encabezado Server del backend), emitiendo exactamente un Date. #1471
  • El error de reanudación no válida ya no filtra los componentes internos del controlador: el mensaje 409 para un sandbox en ejecución (internamente exitoso) ahora dice "estado en ejecución" en lugar de "fase exitosa"; Estado HTTP y código de error sin cambios. #1586
  • Límites de CPU no finitos rechazados: los valores nan, infinitos y desbordados se rechazan antes de la conversión de Docker NanoCpus en lugar de aceptarse silenciosamente. #1568
  • Se permiten montajes mixtos de subrutas de PVC de solo lectura: la fuente de PVC se establece en solo lectura cuando cada montaje del reclamo es de solo lectura; Se elimina el rechazo de nivel de servicio que bloqueaba la creación legítima de PVC de política mixta. #1440
  • Resolución de puntos finales de agente-sandbox servidor-proxy: la resolución interna de puntos finales ahora delega al proveedor de carga de trabajo y lee las direcciones del pod del agente-sandbox desde status.podIPs en lugar de la anotación exclusiva de BatchSandbox, y coloca entre corchetes los literales IPv6 antes de agregar el puerto. #1424
  • Informes de versiones corregidos en todas partes: /openapi.json, los metadatos del paquete instalado y el gráfico appVersion informaron 0.1.0 obsoleto; el servidor ahora lee su versión de los metadatos del paquete en tiempo de ejecución, las compilaciones inyectan SETUPTOOLS_SCM_PRETEND_VERSION y el script de lanzamiento supera Chart.yaml appVersion. #1439

📦 Varios

  • execd v1.0.22 incluye refuerzo de modo init OSEP-0018: se ejecuta como sandbox init (PID 1) con piso de endurecimiento preejecutivo (banda de entorno, conjunto de límites, no_new_privs, caída de identidad, límites ambientales, seccomp) y endurecimiento Kubernetes e2e + cobertura PTY/bwrap. #1474 #1555
  • Puerta del ciclo de vida de la carga de trabajo cerrada por error de sesión aislada: el servidor distribuye una puerta del ciclo de vida Bubblewrap nativa a /opt/opensandbox para ambos tiempos de ejecución; las cargas de trabajo permanecen bloqueadas hasta que execd las marca como listas. Solo la primera fase: la admisión de capacidades y la creación de redes de sesiones permanecen deshabilitadas. #1388
  • MITM de salida transparente puede interceptar puertos TCP adicionales: el OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS experimental agrega puertos al 80/443 siempre activo con validación de cierre fallido (límite multipuerto 15); La vinculación de credenciales todavía se aplica solo a los puertos canónicos. #1379
  • Bumps automáticos — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600); execd v1.0.22 (#1501).

OpenSandbox server/v0.2.3

Highlights

  • Egress sandbox attribution is now server-owned — remove OPENSANDBOX_EGRESS_SANDBOX_ID from request env; Docker and Kubernetes now inject it themselves, and client-supplied values receive HTTP 400 instead of being accepted as spoofable attribution. #1381
  • Lifecycle hooks are Kubernetes-only in this release — preStart and periodic hooks reach execd through OPEN_SANDBOX_LIFECYCLE, with aligned Java/Kotlin, Python, and TypeScript SDK models. Docker explicitly rejects lifecycle requests, PATCH is unsupported, preStart.timeoutSeconds now allows 10,800 seconds, and periodic hooks remain capped at 300 seconds. #1588 #1589 #1637
  • Pause/resume preserves live QEMU state, not just disk contents — opt-in runc support captures guest memory, vCPU, and device state through QMP, storing rootfs and compressed VMState as separate digest-addressed OCI images. Pooled BatchSandbox pause, detachment, and standalone restoration preserve guest memory, writable disks, boot IDs, and counters; rootfs-only snapshots remain compatible. #1584
  • Kubernetes pool exhaustion now has an actionable backpressure contract — new allocation conditions and kubernetes.pool_acquisition_timeout_seconds (default 30s) replace generic 504s with HTTP 429, KUBERNETES::POOL_CAPACITY_EXHAUSTED, and Retry-After: 5; clients should update capacity-related retry handling. getSandbox also exposes allocation state for concrete pool references without leaking pod, namespace, or IP data. #1581 #1481
  • Regenerate proxy clients and migrate diagnostics callers — the 20 proxied operations now have unique, deterministic OpenAPI operation IDs, so generated clients should be rebuilt despite unchanged runtime dispatch. Diagnostics require explicit logs/events scopes; unsupported scopes return 400, while deprecated unscoped plain-text responses remain available with a Deprecation header. #1634 #1553
  • Secure-access keys can stay out of Git, but startup validation becomes stricter — gateway deployments can source signing keys from a Kubernetes Secret through server.gateway.secureAccess.existingSecret, mutually exclusive with plaintext keys. Ensure configured tenant namespaces exist and are accessible before startup, since missing or inaccessible namespaces now cause a fatal error rather than request-time failures. #1445 #1389

What's New

⚠️ Breaking Changes

  • OPENSANDBOX_EGRESS_SANDBOX_ID is now server-injected and rejected in request env — the server unconditionally sets the egress sidecar's sandbox-id attribution variable in both Docker and Kubernetes runtimes, and removed it from the env allowlist. Requests that pass it in env now get a 400 instead of a user-spoofable value. #1381

✨ Features

  • Sandbox lifecycle hooks (preStart / periodic), OSEP-0020 — CreateSandboxRequest.lifecycle is accepted, validated (reserved transports, duplicate periodic names, pool-allocation combinations), and transported to Kubernetes workloads via the reserved OPEN_SANDBOX_LIFECYCLE env for execd to execute. Docker explicitly rejects lifecycle requests; PATCH and other hook types are out of scope. Ships with aligned Java/Kotlin, Python, and TypeScript SDK models. #1588 #1589

  • preStart.timeoutSeconds limit raised from 300s to 3 hours — server and OpenAPI limits now allow up to 10800s for pre-start hooks; the periodic limit stays at 300s. The execd-side product policy bound is removed, keeping policy changes server-only. #1637

  • QEMU VMState pause/resume for runc-based sandboxes — opt-in capture of guest memory/vCPU/device state via QMP migration; rootfs and compressed VMState are stored as separate OCI images keyed by immutable SHA-256 digests. Supports pooled BatchSandbox pause, detachment, and standalone restoration while preserving guest memory, writable disk, boot ID, and counter continuity. Rootfs-only snapshots remain backward compatible. #1584

  • Pool capacity exhaustion is now machine-identifiable — the controller publishes a PoolAllocationPending/PoolCapacityExhausted condition; the server waits a bounded acquisition window (new kubernetes.pool_acquisition_timeout_seconds, default 30s) and then returns HTTP 429 with KUBERNETES::POOL_CAPACITY_EXHAUSTED and Retry-After: 5 instead of the generic 504 readiness timeout. Older controllers safely fall back to the existing behavior. #1581

  • Pool allocation summary in lifecycle responses — getSandbox now surfaces an optional Sandbox.allocation block (mode: pool, poolRef, state: allocated) for confirmed Kubernetes pool allocations, emitted only for concrete non-wildcard pool references with matching allocation evidence. No pod/namespace/IP data is exposed. #1481

  • Generic HTTP request metrics via OTLP — a thin ASGI middleware exports server.http.request.duration (ms) with http_method, matched http_route (or unknown for unrouted/auth-failed requests), and http_status_code attributes, complementing the existing create-duration histogram. Raw paths, IDs, keys, and bodies are never attributes; no-op when [otel] is disabled. #1561

  • Stable diagnostics API with scopes — diagnostics now honor the public inline descriptor contract: logs: container|all and events: runtime|lifecycle|all, with 400 DIAGNOSTICS_SCOPE_UNSUPPORTED for unknown scopes and explicit warnings for incomplete best-effort scopes. Deprecated no-scope plain-text responses still work with a Deprecation header. #1553

  • fast-sandbox fleets backend groundwork (OSEP-0007) — a FastPath v2 gRPC client wraps all FastPathService RPCs with typed error mapping (FastPathNotFound → 404, etc.), and a create/status mapping layer converts the public contract to fast-sandbox semantics, rejecting unsupported fields (volumes, platform, resourceRequests, credentialProxy, snapshotId, etc.) with clear errors. Not yet wired as an active runtime. #1558 #1559

  • Secure-access signing keys can come from a Kubernetes Secret — the server accepts OPENSANDBOX_SECURE_ACCESS_KEYS / OPENSANDBOX_SECURE_ACCESS_ACTIVE_KEY env overrides (mirroring the API-key override, gateway mode required), and the Helm chart adds server.gateway.secureAccess.existingSecret (mutually exclusive with plaintext keys, enforced at render time) so GitOps flows never commit key material. #1445

  • Docker runtime sandbox_env / sandbox_binds — new [docker] fields apply fleet-wide environment variables and host bind mounts to every sandbox container (request env wins over sandbox_env; config binds precede request-derived binds), giving the Docker runtime the operator-side hook the K8s pod template has. #1303

  • Egress sidecar readiness timeout configurable — new [egress] timeout_seconds (default 30s, non-positive values rejected) lets Docker deployments tune how long the server waits for the sidecar health endpoint. #1522

  • Tenant namespaces validated at startup (OSEP-0014) — the server fail-fast verifies every tenant namespace exists and is accessible before serving traffic, aggregating all missing/inaccessible namespaces into a single fatal error instead of failing only at request time. OSEP-0004/0005/0014 marked implemented. #1389

🔒 Security

  • CVE-remediating dependency bumps — google.golang.org/grpc → v1.82.1 across kubernetes/ingress/execd/egress/internal (xDS RBAC and HTTP/2 fixes), postcss → 8.5.11 (arbitrary file read via sourceMappingURL). #1385

🐛 Bug Fixes

  • Docker endpoint lookups ~108x faster — container lookup now goes through the deterministic sandbox-<id> name with opensandbox.io/id label validation, falling back to the label scan only when needed. Local benchmark: 6.07s → 56ms for execd+egress endpoint resolution. #1400

  • Informer cache expires when the watch stalls — has_synced now means "cache is currently live", not "an initial list finished once"; a stalled or half-open watch (e.g. after a control-plane upgrade) degrades to direct API reads instead of serving frozen status forever, which previously caused every create to 504 with POD_READY_TIMEOUT. Bound derived from existing knobs (resync_period + watch_timeout); no new config. #1534

  • Proxy connection leak on aborted responses — when a downstream client disconnected before response-body streaming started, the backend httpx response was never released, gradually exhausting the shared pool until httpcore.PoolTimeout. The proxy now owns the backend response for the full ASGI lifecycle, shields aclose() from cancellation, and releases on setup failure. Stress test: 1000/1000 disconnects cleaned up. #1488

  • Unique, stable proxy operation IDs — the 20 proxied HTTP operations previously emitted 4 process-dependent duplicate operation IDs (16 OpenAPI warnings); each method now gets its own deterministic ID with identical runtime dispatch, auth, and 405 behavior. Generated clients should be regenerated. #1634

  • PVC auto-create no longer crashes with a malformed 500 — the PVC owner-reference patch went through an unsupported _content_type path that raised ApiTypeError (leaving PVCs without owner refs) and SandboxErrorCodes.INTERNAL_ERROR was undefined, masking the real error. Both fixed: patch uses the supported strategic-merge call_api path; error code defined. #1538 #1447

  • Template container securityContext now reaches pods — the deep-merge previously replaced the template's containers wholesale, silently dropping container-level securityContext. Template keys now supplement (never override) runtime values, matching the existing volumeMounts philosophy. #1564

  • Root-relative backend redirects stay under the proxy route — Location: /login from a sandbox backend is rebased to /v1/sandboxes/{id}/proxy/{port}/login; absolute, network-path, and query-only references are left untouched. #1516

  • Server-proxy endpoints drop the ingress routing header — OpenSandbox-Ingress-To (case-insensitive) is removed from use_server_proxy=true responses while secure-access and other endpoint headers are preserved. #1503

  • No duplicate Date/Server headers on proxied responses — the proxy preserves an origin Date while suppressing Uvicorn's default (and the backend Server header), emitting exactly one Date. #1471

  • Invalid-resume error no longer leaks controller internals — the 409 message for a Running (internally Succeed) sandbox now says "state Running" instead of "phase Succeed"; HTTP status and error code unchanged. #1586

  • Non-finite CPU limits rejected — nan, infinite, and overflowed values are rejected before Docker NanoCpus conversion instead of being silently accepted. #1568

  • Mixed read-only PVC subPath mounts allowed — the PVC source is set read-only only when every mount of the claim is read-only; the service-level rejection that blocked legitimate mixed-policy PVC creation is removed. #1440

  • Agent-sandbox server-proxy endpoints resolve — internal endpoint resolution now delegates to the workload provider and reads agent-sandbox pod addresses from status.podIPs instead of the BatchSandbox-only annotation, and brackets IPv6 literals before appending the port. #1424

  • Version reporting fixed everywhere — /openapi.json, installed package metadata, and the chart appVersion all reported stale 0.1.0; the server now reads its version from package metadata at runtime, builds inject SETUPTOOLS_SCM_PRETEND_VERSION, and the release script bumps Chart.yaml appVersion. #1439

📦 Misc

  • execd v1.0.22 ships OSEP-0018 init-mode hardening — execd as sandbox init (PID 1) with pre-exec hardening floor (env strip, bounding set, no_new_privs, identity drop, ambient caps, seccomp) and Kubernetes hardening e2e + PTY/bwrap coverage. #1474 #1555

  • Isolated-session fail-closed workload lifecycle gate — the server distributes a native Bubblewrap lifecycle gate to /opt/opensandbox for both runtimes; workloads stay blocked until execd marks them ready. First phase only — capability admission and session networking remain disabled. #1388

  • Egress transparent MITM can intercept extra TCP ports — experimental OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS appends ports to the always-on 80/443 with fail-closed validation (multiport cap 15); credential binding still applies to canonical ports only. #1379

  • Auto-bumps — egress v1.1.5 → v1.1.7 (#1391 #1498 #1600); execd v1.0.22 (#1501).
