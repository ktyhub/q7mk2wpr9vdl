druida druida-0.13.0-incubating

Druid 0.13.0-incubating contiene más de 400 funciones nuevas, mejoras de rendimiento/estabilidad/documentación y correcciones de errores de 81 contribuyentes. Es la primera versión de Druid en el programa Apache Incubator. Las principales nuevas características y mejoras incluyen:

  • indexación de lotes paralela nativa
  • compactación automática de segmentos
  • tablas de esquemas del sistema
  • estado de tareas de indexación mejorado, estadísticas e informes de errores
  • Manejo de nulos compatible con SQL
  • almacenamiento en caché del corredor a nivel de resultados
  • ingesta de RDBMS
  • Soporte de filtro Bloom
  • formatos de resultados SQL adicionales
  • agregadores adicionales (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch)
  • soporte para múltiples especificaciones de agrupación en consulta groupBy
  • soporte mutuo TLS
  • Gestión de trabajadores basada en HTTP
  • contrapresión del corredor
  • Configuración de ajuste de ingesta de maxBytesInMemory
  • vistas materializadas (extensión comunitaria)
  • analizador para el protocolo Influx Line (extensión comunitaria)
  • Emisor OpenTSDB (extensión comunitaria) La lista completa de cambios está aquí: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0 La documentación para esta versión está en: http://druid.io/docs/0.13.0-incubating/

Destacados

Indexación por lotes paralela nativa

Presenta el supervisor index_parallel que gestiona la ingesta por lotes paralela de fuentes divisibles sin necesidad de depender de Hadoop. Consulte http://druid.io/docs/latest/ingestion/native_tasks.html para obtener más información. Nota: Esta es la implementación inicial de una sola fase y tiene limitaciones sobre cómo espera que se particionen los datos de entrada. En particular, no tiene una implementación shuffle que se agregará en la próxima versión de esta función. Para obtener más detalles, consulte la propuesta en el n.º 5543. Agregado por @jihoonson en #5492.

Compactación automática de segmentos

Anteriormente, compactar segmentos pequeños en segmentos de tamaño óptimo para mejorar el rendimiento de las consultas requería enviar y ejecutar tareas de compactación o reindexación. A menudo, esto era un proceso manual o requería un programador externo para manejar el envío periódico de tareas. Este parche implementa la compactación automática de segmentos administrada por el servicio coordinador. Nota: Esta es la implementación inicial y tiene limitaciones de interoperabilidad con tareas de ingesta en tiempo real. Actualmente, las tareas de indexación requieren la adquisición de un bloqueo en la parte de la línea de tiempo que modificarán para evitar inconsistencias en operaciones simultáneas. Esta implementación utiliza bloqueos de baja prioridad para garantizar que nunca interrumpa la ingesta en tiempo real, pero esto también significa que la compactación puede no lograr ningún progreso si las tareas en tiempo real adquieren bloqueos continuamente en el intervalo de tiempo que se está compactando. Esto se mejorará en la próxima versión de esta característica con un bloqueo más detallado. Para obtener más detalles, consulte la propuesta en el n.° 4479. Documentación para esta función: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments Agregado por @jihoonson en el n.° 5102.

Tablas de esquemas del sistema

Agrega un esquema del sistema a la interfaz SQL que contiene tablas que exponen información sobre segmentos servidos y publicados, nodos del clúster e información sobre tareas de indexación en ejecución y completadas. Nota: Esta implementación contiene algunas ineficiencias generales conocidas que se abordarán en un parche futuro. Documentación para esta función: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema Agregado por @surekhasaharan en #6094.

Estado de tareas de indexación, estadísticas e informes de errores mejorados

Mejora el rendimiento y los detalles de los API relacionados con la ingesta que anteriormente eran bastante opacos, lo que dificultaba determinar la causa de las excepciones de análisis, las fallas de las tareas y el resultado real de una tarea completada. También agrega informes de métricas de ingesta mejorados que incluyen estadísticas de rendimiento promedio móvil. Agregado por @surekhasaharan y @jon-wei en #5801, #5418 y #5748.

Manejo de nulos compatible con SQL

Mejora el manejo de valores nulos por parte de Druid al tratarlos como valores faltantes en lugar de ser equivalentes a cadenas vacías o un valor cero. Esto hace que Druid sea más compatible con SQL y mejora la integración con herramientas de BI externas que admiten ODBC/JDBC. Consulte el n.° 4349 para conocer la propuesta. Para habilitar esta función, deberá configurar la propiedad de todo el sistema druid.generic.useDefaultValueForNull=false. Agregado por @nishantmonu51 en #5278 y #5958.

Almacenamiento en caché del intermediario a nivel de resultados

Implementa el almacenamiento en caché a nivel de resultados en intermediarios que pueden operar simultáneamente con el caché a nivel de segmento tradicional. Consulte el n.° 4843 para conocer la propuesta. Documentación para esta función: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching Agregado por @ a2l007 en #5028.

Ingestión desde RDBMS

Presenta una manguera contra incendios sql que admite la ingesta de datos directamente desde un RDBMS. Agregado por @ a2l007 en #5441.

Soporte de filtro Bloom

Agrega soporte para optimizar consultas de Druid aplicando un filtro Bloom generado por un sistema externo como Apache Hive. En el futuro, el número 6397 admitirá la generación de filtros Bloom como resultado de consultas Druid que luego se pueden utilizar para optimizar consultas futuras. Agregado por @nishantmonu51 en #6222.

Formatos de resultados SQL adicionales

Agrega formatos de resultados para JSON y CSV basados en líneas y, además, encabezados de respuesta X-Druid-Column-Names y X-Druid-Column-Types que contienen una lista de columnas contenidas en el resultado. Agregado por @gianm en #6191.

agregadores 'stringLast' y 'stringFirst'

Introduce dos agregadores complementarios, stringLast y stringFirst que operan en columnas de cadena y devuelven el valor con la marca de tiempo máxima y mínima respectivamente. Agregado por @andresgomezfrr en #5789.

ArrayOfDoublesSketch

Agrega soporte para bocetos de tupla numéricos, que amplían la funcionalidad del recuento de bocetos Theta distintos al agregar matrices de valores dobles asociados con claves únicas. Agregado por @AlexanderSaydakov en el n.° 5148.

HllSketch

Agrega una implementación configurable de un agregador de recuento distinto basado en HllSketch de https://github.com/DataSketches.. La comparación con el HyperLogLogCollector nativo de Druid muestra precisión, eficiencia y velocidad mejoradas: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html Agregado por @AlexanderSaydakov en el n.° 5712.

Soporte para múltiples especificaciones de agrupación en la consulta groupBy

Agrega soporte para el parámetro groupBy subtotalsSpec que permite a Druid ser eficiente al reutilizar resultados intermedios a nivel de intermediario cuando se ejecutan múltiples consultas que se agrupan por subconjuntos del mismo conjunto de columnas. Consulte la propuesta en el n.° 5179 para obtener más información. Agregado por @himanshug en #5280.

Soporte mutuo TLS

Agrega soporte para TLS mutuo (validación de certificado de servidor + validación de certificado client). Ver: https://en.wikipedia.org/wiki/Mutual_authentication Agregado por @ jon-wei en # 6076.

Gestión de trabajadores basada en HTTP

Agrega una implementación de gestión de tareas de indexación basada en HTTP para reemplazar la anterior basada en ZooKeeper. Parte de un conjunto de mejoras para reducir y eventualmente eliminar la dependencia de Druid de ZooKeeper. Consulte el n.° 4996 para conocer la propuesta. Agregado por @himanshug en el n.° 5104.

Contrapresión del corredor

Permite al corredor ejercer contrapresión sobre los nodos de servicio de datos para evitar que el corredor falle bajo presión de la memoria cuando los resultados llegan más rápido de lo que clients los lee. Agregado por @gianm en #6313.

Configuración de ajuste de ingesta 'maxBytesInMemory'

Anteriormente, un parámetro de ajuste importante para la gestión de memoria de tareas de indexación era la configuración maxRowsInMemory, que determinaba el umbral para derramar el contenido de la memoria en el disco. Esto fue difícil de configurar correctamente ya que el "tamaño" de una fila variaba según múltiples factores. maxBytesInMemory realiza esta configuración basada en bytes en lugar de filas. Agregado por @surekhasaharan en #5583.

Vistas materializadas

Admite la creación de vistas materializadas que pueden mejorar el rendimiento de las consultas en determinadas situaciones a costa de almacenamiento adicional. Consulte http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html para obtener más información. Nota: Esta es una extensión aportada por la comunidad y no se incluye automáticamente en la distribución de Druid. Agradecemos sus comentarios para decidir cuándo promover esto a una extensión principal. Para obtener más información, consulte Extensiones comunitarias. Agregado por @ zhangxinyu1 en # 5556.

Analizador del protocolo de línea de afluencia

Agrega soporte para la ingesta del formato de datos del protocolo de línea Influx. Para obtener más información, consulte: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/ Nota: Esta es una extensión aportada por la comunidad y no se incluye automáticamente en la distribución de Druid. Agradecemos sus comentarios para decidir cuándo promover esto a una extensión principal. Para obtener más información, consulte Extensiones comunitarias. Agregado por @njhartwell en #5440.

Emisor OpenTSDB

Agrega soporte para emitir métricas de Druid a OpenTSDB. Nota: Esta es una extensión aportada por la comunidad y no se incluye automáticamente en la distribución de Druid. Agradecemos sus comentarios para decidir cuándo promover esto a una extensión principal. Para obtener más información, consulte Extensiones comunitarias. Agregado por @QiuMM en #5380.

Actualización desde 0.12.3 y anteriores

Consulte a continuación los cambios entre 0.12.3 y 0.13.0 que debe tener en cuenta antes de actualizar. Si está actualizando desde una versión anterior a 0.12.3, consulte release note de las versiones intermedias relevantes para obtener notas adicionales.

La extensión de almacenamiento de metadatos MySQL ya no incluye el controlador JDBC

La extensión de almacenamiento de metadatos MySQL ahora está empaquetada junto con la distribución Druid pero sin el controlador JDBC MySQL requerido (debido a restricciones de licencia). Para utilizar esta extensión, será necesario descargar el controlador por separado y agregarlo al directorio de extensiones. Consulte http://druid.io/docs/latest/development/extensions-core/mysql.html para obtener más detalles.

Se requiere configuración de región de AWS para la extensión S3

Como resultado del cambio de jets3t a AWS SDK (#5382), los usuarios de la extensión S3 ahora deben configurar explícitamente la región de destino. Esto se puede hacer configurando la propiedad del sistema JVM aws.region o la variable de entorno AWS_REGION. Como ejemplo, para configurar la región en 'us-east-1' a través de las propiedades del sistema:

  • agregue -Daws.region=us-east-1 al archivo jvm.config para todos los servicios de Druid
  • agregue -Daws.region=us-east-1 a druid.indexer.runner.javaOpts en middleManager/runtime.properties para que la propiedad se pase a los procesos de peón (trabajador)

Cambios en las especificaciones de ingesta

Como resultado del cambio de nombre del paquete de io.druid a org.apache.druid, las especificaciones de ingesta que hacen referencia a las clases por su nombre de clase completo deberán modificarse en consecuencia. Como ejemplo, si está utilizando la extensión Parquet con indexación Hadoop, el campo inputFormat del inputSpec deberá cambiar de io.druid.data.input.parquet.DruidParquetInputFormat a org.apache.druid.data.input.parquet.DruidParquetInputFormat.

Cambios de métricas

Nuevas métricas

  • task/action/log/time: milisegundos necesarios para registrar una acción de tarea en el registro de auditoría (#5714)
  • task/action/run/time: milisegundos necesarios para ejecutar una acción de tarea (#5714)
  • query/node/backpressure: nanosegundos en los que el canal no se puede leer debido a la aplicación de contrapresión (#6335) (tenga en cuenta que esto no está habilitado de forma predeterminada y requiere una implementación personalizada de QueryMetrics para emitirse)

Nuevas dimensiones

  • taskId y taskType agregados a métricas relacionadas con tareas (#5664)

Otro

  • HttpPostEmitterMonitor ya no emite maxTime y minTime si no se registraron tiempos (#6418)

Restricciones de reversión

Agregadores dobles de 64 bits

Los agregadores dobles de 64 bits ahora se utilizan de forma predeterminada (consulte el n.º 5478). La compatibilidad con columnas de punto flotante de 64 bits se lanzó en Druid 0.11.0, por lo que si está habilitado, las versiones anteriores a 0.11.0 no podrán leer los segmentos de datos. Para deshabilitar y mantener el formato anterior, deberá configurar la propiedad de todo el sistema druid.indexing.doubleStorage=float.

Deshabilitar índices de mapas de bits

0.13.0 agrega soporte para deshabilitar índices de mapas de bits por columna, lo que puede ahorrar espacio en los casos en que los índices de mapas de bits no agregan valor. Esto se hace configurando el campo 'createBitmapIndex' en el esquema de dimensiones. Los segmentos escritos con esta opción no serán compatibles con versiones anteriores de Druid (#5402).

Cambios de comportamiento

Cambios en el nombre del paquete Java

Todos los nombres de los paquetes de Druid se han movido de io.druid a org.apache.druid. Esto afecta el nombre de la clase principal de Java que debe ejecutar al iniciar servicios, que ahora es org.apache.druid.cli.Main. También puede afectar la instalación y configuración de extensiones y monitores.

ParseSpec ahora es un campo obligatorio en las especificaciones de ingesta

Ya no existe una ParseSpec predeterminada (anteriormente DelimitedParseSpec). Las especificaciones de ingesta ahora requieren que se especifique parseSpec. Si anteriormente no proporcionó un parseSpec, debe usar uno con "format": "tsv" para mantener el comportamiento existente (#6310).

Cambiar al máximo predeterminado de filas para regresar en un marco JDBC

El valor predeterminado para druid.sql.avatica.maxRowsPerFrame se redujo de 100k a 5k para minimizar los errores de falta de memoria (#5409).

Cambio en el comportamiento del enrutador cuando se enruta a corredores dedicados a diferentes rangos de tiempo

Como resultado del número 5595, los enrutadores ahora pueden seleccionar un intermediario no deseado en configuraciones donde hay diferentes niveles de intermediarios que están destinados a consultas en diferentes rangos de tiempo. Consulte el n.° 1362 para obtener más información.

Ruby TimestampSpec ya no ignora los milisegundos

Las marcas de tiempo analizadas utilizando TimestampSpec con formato 'ruby' ya no truncan el componente de milisegundos. Si estaba utilizando este analizador y deseaba una granularidad de consulta de SEGUNDO, asegúrese de que esté configurado correctamente en sus especificaciones de indexación (#6217).

Pequeño aumento en el tamaño de los anuncios de tareas ZooKeeper

El nombre de la fuente de datos se agregó a TaskAnnouncement, lo que resultará en un pequeño aumento por tarea en la cantidad de datos almacenados en ZooKeeper (#5511).

Adición del campo 'nombre' a los agregadores filtrados

Los agregadores de tipo "filtrado" ahora admiten un campo "nombre". Anteriormente, el agregador filtrado heredaba el nombre del agregador que encapsulaba. Si ha proporcionado el campo 'nombre' tanto para el agregador filtrado como para el agregador empaquetado, preferirá el nombre del agregador filtrado. Utilizará el nombre del agregador empaquetado si el nombre del agregador filtrado falta o está vacío (#6219).

utf8mb4 es ahora el conjunto de caracteres de almacenamiento de metadatos recomendado

Para obtener instrucciones de actualización, utilice las instrucciones ALTER DATABASE y ALTER TABLE como se describe aquí: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html. Para motivación y referencia, consulte los números 5377 y 5411.

Propiedades de configuración eliminadas

  • druid.indexer.runner.tlsStartPort ha sido eliminado (#6194).
  • Se eliminó druid.indexer.runner.separateIngestionEndpoint (#6263).

Cambios en la interfaz para desarrolladores de extensiones

  • Se ha cambiado el nombre del embalaje de io.druid a org.apache.druid. Todas las extensiones de terceros deberán cambiar el nombre de su META-INF/io.druid.initialization.DruidModule a org.apache.druid.initialization.DruidModule y actualizar el paquete de su extensión adecuadamente (#6266).
  • Se eliminó la interfaz DataSegmentPuller (#5461).
  • Se han eliminado varias funciones de java-util (#5461).
  • El constructor de la clase Metadata ha cambiado (#5613).
  • Se eliminó el perfil de Maven 'spark2' (#5581).

API desaprobaciones

Señor supremo

  • El punto final /druid/indexer/v1/supervisor/{id}/shutdown ha quedado obsoleto en favor de /druid/indexer/v1/supervisor/{id}/terminate (#6272 y #6234).
  • El punto final /druid/indexer/v1/task/{taskId}/segments ha quedado obsoleto (#6368).
  • El campo status devuelto por /druid/indexer/v1/task/ID/status ha quedado obsoleto en favor de statusCode (#6334).
  • Los parámetros reportParseExceptions y ignoreInvalidRows para las configuraciones de ajuste de ingesta han quedado obsoletos en favor de logParseExceptions y maxParseExceptions (#5418).

Corredor

  • El punto final /druid/v2/datasources/{dataSourceName}/dimensions ha quedado obsoleto. En su lugar, se debe utilizar una consulta de metadatos de segmento o la tabla SQL INFORMACIÓN_SCHEMA (#6361).
  • El punto final /druid/v2/datasources/{dataSourceName}/metrics ha quedado obsoleto. En su lugar, se debe utilizar una consulta de metadatos de segmento o la tabla SQL INFORMACIÓN_SCHEMA (#6361).

druid druid-0.13.0-incubating

Druid 0.13.0-incubating contains over 400 new features, performance/stability/documentation improvements, and bug fixes from 81 contributors. It is the first release of Druid in the Apache Incubator program. Major new features and improvements include:

  • native parallel batch indexing
  • automatic segment compaction
  • system schema tables
  • improved indexing task status, statistics, and error reporting
  • SQL-compatible null handling
  • result-level broker caching
  • ingestion from RDBMS
  • Bloom filter support
  • additional SQL result formats
  • additional aggregators (stringFirst/stringLast, ArrayOfDoublesSketch, HllSketch)
  • support for multiple grouping specs in groupBy query
  • mutual TLS support
  • HTTP-based worker management
  • broker backpressure
  • maxBytesInMemory ingestion tuning configuration
  • materialized views (community extension)
  • parser for Influx Line Protocol (community extension)
  • OpenTSDB emitter (community extension)

The full list of changes is here: https://github.com/apache/incubator-druid/pulls?q=is%3Apr+is%3Aclosed+milestone%3A0.13.0

Documentation for this release is at: http://druid.io/docs/0.13.0-incubating/

Highlights

Native parallel batch indexing

Introduces the index_parallel supervisor which manages the parallel batch ingestion of splittable sources without requiring a dependency on Hadoop. See http://druid.io/docs/latest/ingestion/native_tasks.html for more information.

Note: This is the initial single-phase implementation and has limitations on how it expects the input data to be partitioned. Notably, it does not have a shuffle implementation which will be added in the next iteration of this feature. For more details, see the proposal at #5543.

Added by @jihoonson in #5492.

Automatic segment compaction

Previously, compacting small segments into optimally-sized ones to improve query performance required submitting and running compaction or re-indexing tasks. This was often a manual process or required an external scheduler to handle the periodic submission of tasks. This patch implements automatic segment compaction managed by the coordinator service.

Note: This is the initial implementation and has limitations on interoperability with realtime ingestion tasks. Indexing tasks currently require acquisition of a lock on the portion of the timeline they will be modifying to prevent inconsistencies from concurrent operations. This implementation uses low-priority locks to ensure that it never interrupts realtime ingestion, but this also means that compaction may fail to make any progress if the realtime tasks are continually acquiring locks on the time interval being compacted. This will be improved in the next iteration of this feature with finer-grained locking. For more details, see the proposal at #4479.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/design/coordinator.html#compacting-segments

Added by @jihoonson in #5102.

System schema tables

Adds a system schema to the SQL interface which contains tables exposing information on served and published segments, nodes of the cluster, and information on running and completed indexing tasks.

Note: This implementation contains some known overhead inefficiencies that will be addressed in a future patch.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/querying/sql.html#system-schema

Added by @surekhasaharan in #6094.

Improved indexing task status, statistics, and error reporting

Improves the performance and detail of the ingestion-related APIs which were previously quite opaque making it difficult to determine the cause of parse exceptions, task failures, and the actual output from a completed task. Also adds improved ingestion metric reporting including moving average throughput statistics.

Added by @surekhasaharan and @jon-wei in #5801, #5418, and #5748.

SQL-compatible null handling

Improves Druid's handling of null values by treating them as missing values instead of being equivalent to empty strings or a zero-value. This makes Druid more SQL compatible and improves integration with external BI tools supporting ODBC/JDBC. See #4349 for proposal.

To enable this feature, you will need to set the system-wide property druid.generic.useDefaultValueForNull=false.

Added by @nishantmonu51 in #5278 and #5958.

Results-level broker caching

Implements result-level caching on brokers which can operate concurrently with the traditional segment-level cache. See #4843 for proposal.

Documentation for this feature: http://druid.io/docs/0.13.0-incubating/configuration/index.html#broker-caching

Added by @a2l007 in #5028.

Ingestion from RDBMS

Introduces a sql firehose which supports data ingestion directly from an RDBMS.

Added by @a2l007 in #5441.

Bloom filter support

Adds support for optimizing Druid queries by applying a Bloom filter generated by an external system such as Apache Hive. In the future, #6397 will support generation of Bloom filters as the result of Druid queries which can then be used to optimize future queries.

Added by @nishantmonu51 in #6222.

Additional SQL result formats

Adds result formats for line-based JSON and CSV and additionally X-Druid-Column-Names and X-Druid-Column-Types response headers containing a list of columns contained in the result.

Added by @gianm in #6191.

'stringLast' and 'stringFirst' aggregators

Introduces two complementary aggregators, stringLast and stringFirst which operate on string columns and return the value with the maximum and minimum timestamp respectively.

Added by @andresgomezfrr in #5789.

ArrayOfDoublesSketch

Adds support for numeric Tuple sketches, which extend the functionality of the count distinct Theta sketches by adding arrays of double values associated with unique keys.

Added by @AlexanderSaydakov in #5148.

HllSketch

Adds a configurable implementation of a count distinct aggregator based on HllSketch from https://github.com/DataSketches. Comparison to Druid's native HyperLogLogCollector shows improved accuracy, efficiency, and speed: https://datasketches.github.io/docs/HLL/HllSketchVsDruidHyperLogLogCollector.html

Added by @AlexanderSaydakov in #5712.

Support for multiple grouping specs in groupBy query

Adds support for the subtotalsSpec groupBy parameter which allows Druid to be efficient by reusing intermediate results at the broker level when running multiple queries that group by subsets of the same set of columns. See proposal in #5179 for more information.

Added by @himanshug in #5280.

Mutual TLS support

Adds support for mutual TLS (server certificate validation + client certificate validation). See: https://en.wikipedia.org/wiki/Mutual_authentication

Added by @jon-wei in #6076.

HTTP based worker management

Adds an HTTP-based indexing task management implementation to replace the previous one based on ZooKeeper. Part of a set of improvements to reduce and eventually eliminate Druid's dependency on ZooKeeper. See #4996 for proposal.

Added by @himanshug in #5104.

Broker backpressure

Allows the broker to exert backpressure on data-serving nodes to prevent the broker from crashing under memory pressure when results are coming in faster than they are being read by clients.

Added by @gianm in #6313.

'maxBytesInMemory' ingestion tuning configuration

Previously, a major tuning parameter for indexing task memory management was the maxRowsInMemory configuration, which determined the threshold for spilling the contents of memory to disk. This was difficult to properly configure since the 'size' of a row varied based on multiple factors. maxBytesInMemory makes this configuration byte-based instead of row-based.

Added by @surekhasaharan in #5583.

Materialized views

Supports the creation of materialized views which can improve query performance in certain situations at the cost of additional storage. See http://druid.io/docs/latest/development/extensions-contrib/materialized-view.html for more information.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @zhangxinyu1 in #5556.

Parser for Influx Line Protocol

Adds support for ingesting the Influx Line Protocol data format. For more information, see: https://docs.influxdata.com/influxdb/v1.6/write_protocols/line_protocol_tutorial/

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @njhartwell in #5440.

OpenTSDB emitter

Adds support for emitting Druid metrics to OpenTSDB.

Note: This is a community-contributed extension and is not automatically included in the Druid distribution. We welcome feedback for deciding when to promote this to a core extension. For more information, see Community Extensions.

Added by @QiuMM in #5380.

Updating from 0.12.3 and earlier

Please see below for changes between 0.12.3 and 0.13.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.12.3, please see release notes of the relevant intermediate versions for additional notes.

MySQL metadata storage extension no longer includes JDBC driver

The MySQL metadata storage extension is now packaged together with the Druid distribution but without the required MySQL JDBC driver (due to licensing restrictions). To use this extension, the driver will need to be downloaded separately and added to the extension directory.

See http://druid.io/docs/latest/development/extensions-core/mysql.html for more details.

AWS region configuration required for S3 extension

As a result of switching from jets3t to the AWS SDK (#5382), users of the S3 extension are now required to explicitly set the target region. This can be done by setting the JVM system property aws.region or the environment variable AWS_REGION.

As an example, to set the region to 'us-east-1' through system properties:

  • add -Daws.region=us-east-1 to the jvm.config file for all Druid services
  • add -Daws.region=us-east-1 to druid.indexer.runner.javaOpts in middleManager/runtime.properties so that the property will be passed to peon (worker) processes

Ingestion spec changes

As a result of renaming packaging from io.druid to org.apache.druid, ingestion specs that reference classes by their fully-qualified class name will need to be modified accordingly.

As an example, if you are using the Parquet extension with Hadoop indexing, the inputFormat field of the inputSpec will need to change from io.druid.data.input.parquet.DruidParquetInputFormat to org.apache.druid.data.input.parquet.DruidParquetInputFormat.

Metrics changes

New metrics

  • task/action/log/time - Milliseconds taken to log a task action to the audit log (#5714)
  • task/action/run/time - Milliseconds taken to execute a task action (#5714)
  • query/node/backpressure - Nanoseconds the channel is unreadable due to backpressure being applied (#6335) (Note that this is not enabled by default and requires a custom implementation of QueryMetrics to emit)

New dimensions

  • taskId and taskType added to task-related metrics (#5664)

Other

  • HttpPostEmitterMonitor no longer emits maxTime and minTime if no times were recorded (#6418)

Rollback restrictions

64-bit doubles aggregators

64-bit doubles aggregators are now used by default (see #5478). Support for 64-bit floating point columns was release in Druid 0.11.0, so if this is enabled, versions older than 0.11.0 will not be able to read the data segments.

To disable and keep the old format, you will need to set the system-wide property druid.indexing.doubleStorage=float.

Disabling bitmap indexes

0.13.0 adds support for disabling bitmap indexes on a per-column basis, which can save space in cases where bitmap indexes add no value. This is done by setting the 'createBitmapIndex' field in the dimension schema. Segments written with this option will not be backwards compatible with older versions of Druid (#5402).

Behavior changes

Java package name changes

Druid's package names have all moved from io.druid to org.apache.druid. This affects the name of the Java main class that you should run when starting up services, which is now org.apache.druid.cli.Main. It may also affect installation and configuration of extensions and monitors.

ParseSpec is now a required field in ingestion specs

There is no longer a default ParseSpec (previously the DelimitedParseSpec). Ingestion specs now require parseSpec to be specified. If you previously did not provide a parseSpec, you should use one with "format": "tsv" to maintain the existing behavior (#6310).

Change to default maximum rows to return in one JDBC frame

The default value for druid.sql.avatica.maxRowsPerFrame was reduced from 100k to 5k to minimize out of memory errors (#5409).

Router behavior change when routing to brokers dedicated to different time ranges

As a result of #5595, routers may now select an undesired broker in configurations where there are different tiers of brokers that are intended to be dedicated to queries on different time ranges. See #1362 for discussion.

Ruby TimestampSpec no longer ignores milliseconds

Timestamps parsed using a TimestampSpec with format 'ruby' no longer truncates the millisecond component. If you were using this parser and wanted a query granularity of SECOND, ensure that it is configured appropriately in your indexing specs (#6217).

Small increase in size of ZooKeeper task announcements

The datasource name was added to TaskAnnouncement which will result in a small per task increase in the amount of data stored in ZooKeeper (#5511).

Addition of 'name' field to filtered aggregators

Aggregators of type 'filtered' now support a 'name' field. Previously, the filtered aggregator inherited the name of the aggregator it wrapped. If you have provided the 'name' field for both the filtered aggregator and the wrapped aggregator, it will prefer the name of the filtered aggregator. It will use the name of the wrapped aggregator if the name of the filtered aggregator is missing or empty (#6219).

utf8mb4 is now the recommended metadata storage charset

For upgrade instructions, use the ALTER DATABASE and ALTER TABLE instructions as described here: https://dev.mysql.com/doc/refman/5.7/en/charset-unicode-conversion.html.

For motivation and reference, see #5377 and #5411.

Removed configuration properties

  • druid.indexer.runner.tlsStartPort has been removed (#6194).
  • druid.indexer.runner.separateIngestionEndpoint has been removed (#6263).

Interface changes for extension developers

  • Packaging has been renamed from io.druid to org.apache.druid. All third-party extensions will need to rename their META-INF/io.druid.initialization.DruidModule to org.apache.druid.initialization.DruidModule and update their extension's packaging appropriately (#6266).

  • The DataSegmentPuller interface has been removed (#5461).

  • A number of functions under java-util have been removed (#5461).

  • The constructor of the Metadata class has changed (#5613).

  • The 'spark2' Maven profile has been removed (#5581).

API deprecations

Overlord

  • The /druid/indexer/v1/supervisor/{id}/shutdown endpoint has been deprecated in favor of /druid/indexer/v1/supervisor/{id}/terminate (#6272 and #6234).
  • The /druid/indexer/v1/task/{taskId}/segments endpoint has been deprecated (#6368).
  • The status field returned by /druid/indexer/v1/task/ID/status has been deprecated in favor of statusCode (#6334).
  • The reportParseExceptions and ignoreInvalidRows parameters for ingestion tuning configurations have been deprecated in favor of logParseExceptions and maxParseExceptions (#5418).

Broker

  • The /druid/v2/datasources/{dataSourceName}/dimensions endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
  • The /druid/v2/datasources/{dataSourceName}/metrics endpoint has been deprecated. A segment metadata query or the INFORMATION_SCHEMA SQL table should be used instead (#6361).
