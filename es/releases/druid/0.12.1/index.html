druida druida-0.12.1

Druid 0.12.1 contiene mejoras de estabilidad y correcciones de errores de 10 contribuyentes. Las principales mejoras incluyen:

  • Grandes mejoras de rendimiento para el estado de carga del coordinador API
  • Más limitación de memoria para HttpPostEmitter
  • Solucionar varios problemas de autenticación Kerberos
  • Se corrigió SQLMetadataSegmentManager para permitir inicios y paradas sucesivos.
  • Se corrigió el manejo de intervalos predeterminado en SegmentMetadataQuery
  • Admite solicitud de OPCIONES HTTP
  • Se corrigió un error de diferentes segmentos del mismo ID de segmento en la indexación de Kafka. La lista completa de cambios está aquí: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1 La documentación para esta versión está en: http://druid.io/docs/0.12.1

Destacados

Grandes mejoras de rendimiento para el estado de carga del coordinador API

El loadstatus API de Coordinadores devuelve el porcentaje de segmentos realmente cargados en el clúster frente a los segmentos que deberían cargarse en el clúster. Se ha mejorado mucho el rendimiento de este API. Agregado por @ jon-wei en # 5632.

Más limitación de memoria para HttpPostEmitter

Druid ahora puede limitar la cantidad de memoria utilizada por HttpPostEmitter al 10% del montón JVM disponible, evitando así errores OutOfMemory de eventos almacenados en el búfer. Agregado por @ jon-wei en # 5300.

Solucionar varios problemas de autenticación Kerberos

Hubo algunos errores en la autenticación Kerberos, como fallas de autenticación sin cookies o autenticación rota cuando se usa el enrutador. Consulte https://github.com/druid-io/druid/pull/5596, https://github.com/druid-io/druid/pull/5706, y https://github.com/druid-io/druid/pull/5766 para obtener más detalles. Agregado por @nishantmonu51 en #5596. Agregado por @b-slim en #5706. Agregado por @ jon-wei en # 5766.

Reparar SQLMetadataSegmentManager para permitir inicios y paradas sucesivos

Los coordinadores podrían quedarse estancados si pierden liderazgo al comenzar. Este error se ha solucionado ahora. Agregado por @jihoonson en #5554.

Corregir el manejo de intervalos predeterminado en SegmentMetadataQuery

Se supone que SegmentMetadataQuery usa el intervalo de druid.query.segmentMetadata.defaultHistory si no se especifica el intervalo, pero en su lugar consulta todos los segmentos, lo que genera un impacto inesperado en el rendimiento. SegmentMetadataQuery ahora vuelve a respetar la opción defaultHistory. Agregado por @gianm en #5489.

Admite solicitud de OPCIONES HTTP

Druid ahora admite la solicitud de OPCIONES HTTP arreglando su manejo de autenticación. Agregado por @ jon-wei en # 5615.

Corregir un error de diferentes segmentos de la misma identificación de segmento en la indexación de Kafka

El servicio de indexación de Kafka permitió reintentar tareas para sobrescribir los segmentos en el almacenamiento profundo escritos por las tareas fallidas anteriores. Sin embargo, esto provocó otro error: el mismo ID de segmento podía tener datos diferentes en el historial y en el almacenamiento profundo. Este error se ha solucionado ahora mediante el uso de rutas de segmento únicas para cada tarea de índice de Kafka. Agregado por @dclim en #5692.

¡Y mucho más!

La lista completa de cambios está aquí: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1

Actualización desde 0.12.0 y anteriores

0.12.1 es una versión menor y compatible con 0.12.0. Si está actualizando desde una versión anterior a 0.12.0, consulte release note de las versiones intermedias relevantes para obtener notas adicionales.

druid druid-0.12.1

Druid 0.12.1 contains stability improvements and bug fixes from 10 contributors. Major improvements include:

  • Large performance improvements for coordinator's loadstatus API
  • More memory limiting for HttpPostEmitter
  • Fix several issues of Kerberos Authentication
  • Fix SQLMetadataSegmentManager to allow successive start and stop
  • Fix default interval handling in SegmentMetadataQuery
  • Support HTTP OPTIONS request
  • Fix a bug of different segments of the same segment id in Kafka indexing

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1

Documentation for this release is at: http://druid.io/docs/0.12.1

Highlights

Large performance improvements for coordinator's loadstatus API

The loadstatus API of Coordinators returns the percentage of segments actually loaded in the cluster versus segments that should be loaded in the cluster. The performance of this API has greatly been improved.

Added by @jon-wei in #5632.

More memory limiting for HttpPostEmitter

Druid now can limit the amount of memory used by HttpPostEmitter to 10% of the available JVM heap, thereby avoiding OutOfMemory errors from buffered events.

Added by @jon-wei in #5300.

Fix several issues of Kerberos Authentication

There were some bugs in Kerberos authentication like authentication failure without cookies or broken authentication when router is used. See https://github.com/druid-io/druid/pull/5596, https://github.com/druid-io/druid/pull/5706, and https://github.com/druid-io/druid/pull/5766 for more details.

Added by @nishantmonu51 in #5596. Added by @b-slim in #5706. Added by @jon-wei in #5766.

Fix SQLMetadataSegmentManager to allow successive start and stop

Coordinators could be stuck if it loses leadership while starting. This bug has been fixed now.

Added by @jihoonson in #5554.

Fix default interval handling in SegmentMetadataQuery

SegmentMetadataQuery is supposed to use the interval of druid.query.segmentMetadata.defaultHistory if the interval is not specified, but it queried all segments instead which incurs an unexpected performance hit. SegmentMetadataQuery now respects the defaultHistory option again.

Added by @gianm in #5489.

Support HTTP OPTIONS request

Druid now supports the HTTP OPTIONS request by fixing its auth handling.

Added by @jon-wei in #5615.

Fix a bug of different segments of the same segment id in Kafka indexing

Kafka indexing service allowed retrying tasks to overwrite the segments in deep storage written by the previous failed tasks. However, this caused another bug that the same segment ID could have different data on historicals and in deep storage. This bug has been fixed now by using unique segment paths for each Kafka index tasks.

Added by @dclim in #5692.

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr+is%3Aclosed+milestone%3A0.12.1

Updating from 0.12.0 and earlier

0.12.1 is a minor release and compatible with 0.12.0. If you're updating from an earlier version than 0.12.0, please see release notes of the relevant intermediate versions for additional notes.

Credits

Thanks to everyone who contributed to this release!
