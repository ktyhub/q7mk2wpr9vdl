druida druida-29.0.0

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT y DESPIVOT (experimental)

Druid 29.0.0 agrega soporte experimental para los operadores SQL PIVOT y UNPIVOT.

El operador PIVOT realiza una agregación y transforma filas en columnas en la salida. La siguiente es la sintaxis general del operador PIVOT:

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

El operador UNPIVOT transforma los valores de las columnas existentes en filas. La siguiente es la sintaxis general del operador UNPIVOT:

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> Soporte de rango en funciones de ventana (experimental)

Las funciones de ventana (experimentales) ahora admiten rangos donde ambos puntos finales son ilimitados o son la fila actual. Los rangos funcionan en modo estricto, lo que significa que Druid fallará en las consultas que no sean compatibles. Puede desactivar el modo estricto para rangos configurando el parámetro de contexto windowingStrictValidation en false.

El siguiente ejemplo muestra una expresión de ventana con especificaciones de marco RANGE:

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

Druid ahora admite condiciones de unión arbitrarias para la unión INNER. Cualquier subcondición que no se pueda evaluar como parte de la unión se convierte en un filtro posterior a la unión. Las capacidades de unión mejoradas permiten a Druid admitir aplicaciones como Tableau de manera más efectiva.

Ya no es necesario determinar manualmente el tipo de bloqueo de tarea para agregar y reemplazar simultáneamente (experimentalmente) con el contexto de tarea taskLockType. Puede usar el parámetro de contexto "useConcurrentLocks": true para tareas y fuentes de datos individuales o habilitar la adición y reemplazo simultáneos a nivel de clúster usando druid.indexer.task.default.context.

Tareas de eliminación mejoradas de la siguiente manera:

  • Se resolvió un problema por el cual la función de eliminación automática no respetaba el período de búfer especificado. Esto ocurría cuando varios segmentos no utilizados dentro de un intervalo se marcaban como no utilizados en diferentes momentos.
  • Puedes enviar tareas de eliminación con un parámetro opcional maxUsedStatusLastUpdatedTime. Cuando se establece en una fecha y hora, la tarea de eliminación considera los segmentos en el intervalo especificado marcados como no utilizados a más tardar en esta hora. El comportamiento predeterminado es eliminar todos los segmentos no utilizados en el intervalo, independientemente del momento en que los segmentos se marcaron como no utilizados.

Apache Druid 29.0.0 contains over 350 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 67 contributors.

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-sql-pivot-and-unpivot-%28experimental%29">#</a> SQL PIVOT and UNPIVOT (experimental)

Druid 29.0.0 adds experimental support for the SQL PIVOT and UNPIVOT operators.

The PIVOT operator carries out an aggregation and transforms rows into columns in the output. The following is the general syntax for the PIVOT operator:

PIVOT (aggregation_function(column_to_aggregate)
  FOR column_with_values_to_pivot
  IN (pivoted_column1 [, pivoted_column2 ...])
)

The UNPIVOT operator transforms existing column values into rows. The following is the general syntax for the UNPIVOT operator:

UNPIVOT (values_column 
  FOR names_column
  IN (unpivoted_column1 [, unpivoted_column2 ... ])
)

<a name="29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29" href="#29.0.0-important-features%2C-changes%2C-and-deprecations-range-support-in-window-functions-%28experimental%29">#</a> Range support in window functions (experimental)

Window functions (experimental) now support ranges where both endpoints are unbounded or are the current row. Ranges work in strict mode, which means that Druid will fail queries that aren't supported. You can turn off strict mode for ranges by setting the context parameter windowingStrictValidation to false.

The following example shows a window expression with RANGE frame specifications:

(ORDER BY c)
(ORDER BY c RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
(ORDER BY c RANGE BETWEEN CURRENT ROW AND UNBOUNDED PRECEDING)

Now, excess requests will instead be queued with a timeout equal to MIN(Integer.MAX_VALUE, druid.server.http.maxQueryTimeout).

<a name="29.0.0-functional-area-and-related-changes-data-management-changed-%60numcorepartitions%60-to-0-for-tombstones" href="#29.0.0-functional-area-and-related-changes-data-management-changed-%60numcorepartitions%60-to-0-for-tombstones">#</a> Changed numCorePartitions to 0 for tombstones

Tombstone segments now have 0 core partitions. This means they can be dropped or removed independently without affecting availability of other appended segments in the same co-partition space. Prior to this change, removing tombstones with 1 core partition that contained appended segments in the partition space could make the appended segments unavailable.

Added MarkEternityTombstonesAsUnused to clean up non-overlapping eternity tombstones—tombstone segments that either start at -INF or end at INF and don't overlap with any overshadowed used segments in the datasource.

You can configure the pushgateway strategy to delete metrics from Prometheus push gateway on task shutdown using the following Prometheus emitter configurations:

  • druid.emitter.prometheus.deletePushGatewayMetricsOnShutdown: When set to true, peon tasks delete metrics from the Prometheus push gateway on task shutdown. Default value is false.

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes">#</a> Upgrade notes

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-%60equals%60-filter-for-native-queries" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-%60equals%60-filter-for-native-queries">#</a> Changed equals filter for native queries

The equality filter on mixed type auto columns that contain arrays must now be filtered as their presenting type. This means that if any rows are arrays (for example, the segment metadata and information_schema reports the type as some array type), then the native queries must also filter as if they are some array type.

This change impacts mixed type auto columns that contain both scalars and arrays. It doesn't impact SQL, which already has this limitation due to how the type presents itself.

#15503

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-console-automatically-sets-arrayingestmode-for-msq-queries" href="#29.0.0-upgrade-notes-and-incompatible-console-automatically-sets-arrayingestmode-for-msq-queries">#</a> Console automatically sets arrayIngestMode for MSQ queries

Druid console now configures the arrayIngestMode parameter in the data loading flow, and its value can persist across the SQL tab unless manually updated. Therefore, when loading multi-value dimensions or arrays in the Druid web console, note the value of the arrayIngestMode parameter, to prevent mixing MVDs and Arrays in the same column of a data source accidentally.

#15588

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-improved-concurrent-append-and-replace-%28experimental%29" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-improved-concurrent-append-and-replace-%28experimental%29">#</a> Improved concurrent append and replace (experimental)

You no longer have to manually determine the task lock type for concurrent append and replace (experimental) with the taskLockType task context. Instead, Druid can now determine it automatically for you. You can use the context parameter "useConcurrentLocks": true for individual tasks and datasources or enable concurrent append and replace at a cluster level using druid.indexer.task.default.context.

#15684

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-empty-ingest-queries" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-empty-ingest-queries">#</a> Enabled empty ingest queries

The MSQ task engine now allows empty ingest queries by default. For queries that don't generate any output rows, the MSQ task engine reports zero values for numTotalRows and totalSizeInBytes instead of null. Previously, ingest queries that produced no data would fail with the InsertCannotBeEmpty MSQ fault.

To revert to the original behavior, set the MSQ query parameter failOnEmptyInsert to true.

#15495 #15674

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-query-request-queuing-by-default-when-total-laning-is-turned-on" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-enabled-query-request-queuing-by-default-when-total-laning-is-turned-on">#</a> Enabled query request queuing by default when total laning is turned on

Columns ingested with the auto column indexer that contain only empty or null arrays are now stored as ARRAY<LONG\> instead of COMPLEX<json\>.

#15505

<a name="29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-druid-allocates-weekly-segments" href="#29.0.0-upgrade-notes-and-incompatible-changes-upgrade-notes-changed-how-druid-allocates-weekly-segments">#</a> Changed how Druid allocates weekly segments

When the requested granularity is a month or larger but a segment can't be allocated, Druid resorts to day partitioning. Unless explicitly specified, Druid skips week-granularity segments for data partitioning because these segments don't align with the end of the month or more coarse-grained intervals.

Removed the auto search strategy from the native search query. Setting searchStrategy to auto is now equivalent to useIndexes.
