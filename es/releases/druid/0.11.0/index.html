druida druida-0.11.0

Druid 0.11.0 contiene más de cien mejoras de rendimiento, mejoras de estabilidad y correcciones de errores de casi 40 colaboradores. Esta versión agrega dos características de seguridad importantes: compatibilidad con TLS y puntos de extensión para autenticación y autorización. Las principales características nuevas incluyen:

  • Soporte TLS (también conocido como SSL)
  • Puntos de extensión para autenticación y autorización.
  • Soporte de doble columna.
  • Estrategia de balanceador de costos de almacenamiento en caché
  • Soporte de expresión jq en el analizador JSON
  • Extensión de caché Redis
  • Mejoras de rendimiento de GroupBy
  • Varias mejoras a Druid SQL La lista completa de cambios está aquí: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0 La documentación para esta versión está en: http://druid.io/docs/0.11.0/

Destacados

Soporte TLS

Druid ahora admite TLS, lo que permite comunicaciones cifradas client y entre nodos. Consulte http://druid.io/docs/0.11.0/operations/tls-support.html para obtener detalles sobre la configuración y extensiones relacionadas. Añadido por @pjain1 en https://github.com/druid-io/druid/pull/4270.

Puntos de extensión de autenticación/autorización

Se han agregado a Druid puntos de extensión para autenticar y autorizar solicitudes. Consulte http://druid.io/docs/0.11.0/configuration/auth.html para obtener información sobre la configuración y la implementación de extensiones. La extensión de autenticación Kerberos existente se actualizó para implementar la nueva interfaz Authenticator; consulte la sección "Cambios en la configuración de Kerberos" en "Actualización desde 0.10.1 y versiones anteriores" para obtener más información si está utilizando la extensión Kerberos. Agregado por @jon-wei en https://github.com/druid-io/druid/pull/4271

Soporte de columnas dobles

Druid ahora admite columnas de agregación de tipo doble. Consulte http://druid.io/docs/0.11.0/querying/aggregations.html para obtener documentación sobre los nuevos agregadores dobles. Añadido por @b-slim en https://github.com/druid-io/druid/pull/4491.

estrategia de equilibrio de costos de almacenamiento en caché

Se anima a los usuarios que actualicen a 0.11.0 a probar la nueva estrategia de equilibrio de segmentos cachingCost en sus coordinadores. Esta estrategia ofrece grandes mejoras de rendimiento con respecto a la estrategia de balanceador de costos existente y está previsto que se convierta en la estrategia predeterminada en la versión posterior a 0.11.0. Esta estrategia se puede seleccionar estableciendo la siguiente propiedad en los coordinadores:

druid.coordinator.balancer.strategy=cachingCost

Agregado por @dgolitsyn en https://github.com/druid-io/druid/pull/4731

compatibilidad con expresiones jq en el analizador JSON

El analizador de entrada JSON de Druid ahora admite expresiones jq usando jackson-jq, lo que permite más transformaciones de entrada antes de la ingestión. Consulte http://druid.io/docs/0.11.0/ingestion/flatten-json.html para obtener más detalles. Agregado por @knoguchi en https://github.com/druid-io/druid/pull/4171.

Extensión de caché Redis

Se agregó una nueva implementación de caché usando Redis en una extensión, agregada por @QiuMM en https://github.com/druid-io/druid/pull/4615.. Consulte la solicitud de extracción anterior para obtener más detalles.

Mejoras de rendimiento de GroupBy

@jihoonson ha agregado varias optimizaciones de rendimiento nuevas a la consulta GroupBy en los siguientes RP: https://github.com/druid-io/druid/pull/4660 Clasificación paralela para ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Agregación basada en matrices para consulta groupBy https://github.com/druid-io/druid/pull/4668 Agregue IntGrouper para evitar el boxeo/unboxing innecesario en la agregación basada en matrices PR #4660 ofrece una mejora general al paralelizar la clasificación de resultados parciales, mientras que PR #4576 y #4668 ofrecen mejoras significativas al agrupar en una sola columna de cadena.

mejoras de SQL

@gianm ha agregado varias mejoras y características a Druid SQL en los siguientes RP: https://github.com/druid-io/druid/pull/4750 - Soporte TRIM https://github.com/druid-io/druid/pull/4720 - Redondeo para recuento distinto https://github.com/druid-io/druid/pull/4561 - Métricas para consultas SQL https://github.com/druid-io/druid/pull/4360 - Soporte de expresiones SQL

¡Y mucho más!

La lista completa de cambios está aquí: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Actualización desde 0.10.1 y versiones anteriores

Consulte a continuación los cambios entre 0.10.1 y 0.11.0 que debe tener en cuenta antes de actualizar. Si está actualizando desde una versión anterior a 0.10.1, consulte release note de las versiones intermedias relevantes para obtener notas adicionales.

Actualización de coordinadores y señores supremos

El siguiente parche cambia la forma en que se manejan las redirecciones de coordinador->overlord: https://github.com/druid-io/druid/pull/5037 El algoritmo de elección del líder supremo ha cambiado en 0.11.0: https://github.com/druid-io/druid/pull/4699. Como resultado de los dos parches anteriores, se necesita especial cuidado al actualizar Coordinator o Overlord a 0.11.0. Todos los coordinadores y señores supremos deben cerrarse y actualizarse juntos. Por ejemplo, para actualizar Coordinadores, debe apagar todos los coordinadores, actualizarlos a 0.11.0 y luego iniciarlos. Los Overlords deberían mejorarse de manera similar. Durante el proceso de actualización, no debe haber ningún período de tiempo en el que un coordinador o señor supremo que no sea 0.11.0 se esté ejecutando simultáneamente con un coordinador o señor supremo 0.11.0. Tenga en cuenta que al menos un señor supremo debe aparecer lo más rápido posible después de cerrarlos a todos para que los peones, la tranquilidad, etc. continúen funcionando después de algunos reintentos. Tenga en cuenta también que la propiedad druid.zk.paths.indexer.leaderLatchPath ya no se utiliza.

Cambios de nombre del servicio

En versiones anteriores de Druid, los caracteres / en los nombres de servicios definidos por druid.service se reemplazaban por caracteres : porque estos nombres de servicios se usaban en las rutas Zookeeper. Druida 0.11.0 ya no realiza estos reemplazos de personajes. Ejemplo: 1: si la configuración anterior tenía un intermediario con el nombre de servicio test/broker: druid.service=test/broker y se configuró un enrutador asumiendo que / se reemplazará con : en el nombre del servicio del corredor, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"} la configuración del enrutador debe actualizarse para eliminar esa suposición: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"} Ejemplo: 2: si la configuración anterior tenía el señor supremo con el nombre de servicio test/overlord, entonces el valor de druid.coordinator.asOverlord.overlordService o druid.selectors.indexing.serviceName debería ser test/overlord y no test:overlord. Ejemplo: 3: si la configuración anterior tenía el señor supremo con el nombre de servicio test:overlord, entonces el valor de druid.coordinator.asOverlord.overlordService o druid.selectors.indexing.serviceName debería ser test:overlord y no test/overlord. Las siguientes configuraciones relacionadas con el nombre del servicio también se ven afectadas y deben actualizarse para que coincidan exactamente con el valor de la propiedad druid.service en otro nodo que se descubra. druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap Consulte https://github.com/druid-io/druid/issues/4992 para obtener más detalles.

Cambios en la configuración de Kerberos

El formato de configuración de autenticación Kerberos ha cambiado como resultado de las nuevas interfaces introducidas por el número 4271. Consulte http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html para conocer las nuevas propiedades de configuración. Los usuarios pueden señalar el nombre de autorización del autenticador Kerberos a una instancia de un autorizador "allowAll" para replicar el comportamiento anterior a 0.11.0 de un clúster que utiliza la autenticación Kerberos sin autorización.

Búsquedas API cambios de ruta

Las rutas para la configuración de búsquedas API han cambiado debido al número 5058. Las rutas de configuración que tenían el formato /druid/coordinator/v1/lookups ahora tienen el formato /druid/coordinator/v1/lookups/config. Consulte http://druid.io/docs/0.11.0/querying/lookups.html para conocer el API actual.

Migrando a columnas dobles

Antes de 0.11.0, los agregadores Double* almacenaban valores de columna en el disco como flotantes mientras realizaban agregaciones utilizando representaciones Double. PR #4491 permite a los agregadores dobles almacenar valores de columna en el disco como dobles. Debido a preocupaciones relacionadas con actualizaciones continuas y degradaciones de versiones, este comportamiento está deshabilitado de forma predeterminada y Druid continuará almacenando agregadores dobles en el disco como flotantes. Para habilitar el almacenamiento de doble columna, establezca la siguiente propiedad en las propiedades comunes del tiempo de ejecución:

druid.indexing.doubleStorage=double

Los usuarios no deben configurar esta propiedad durante una actualización continua inicial a 0.11.0, ya que cualquier nodo que ejecute Druid anterior a 0.11.0 no podrá manejar columnas dobles creadas durante el período de actualización. Los usuarios también deberán volver a indexar cualquier segmento con columnas dobles si cambian de 0.11.0 a una versión anterior. Consulte los números 4944 y 4605 para obtener más información.

Escanear cambios en la consulta

La consulta de escaneo se ha movido de extensiones-contrib al núcleo Druid. Como parte de esta migración: https://github.com/druid-io/druid/pull/4751,, el manejo de la columna de tiempo de la consulta de escaneo ha cambiado. La columna de hora ahora se devuelve como "__hora" en lugar de "marca de tiempo", ya no se incluye si no la solicita específicamente en sus "columnas" y se devuelve como una cadena larga en lugar de una cadena. Los usuarios pueden revertir el manejo del tiempo de la consulta de escaneo al comportamiento de la extensión heredada configurando "legacy" : true en sus consultas o configurando la propiedad druid.query.scan.legacy = true. Esto tiene como objetivo proporcionar una ruta de migración para los usuarios que anteriormente usaban la extensión contrib.

Cambios en la interfaz de extensión

Soporte de doble columna agregador

La interfaz Aggregator ha obtenido un método getDouble(), que de forma predeterminada transmite el resultado de getFloat(). El método getDouble() debe volverse a implementar para cualquier agregador personalizado que admita dobles. Consulte https://github.com/druid-io/druid/pull/4595 para obtener más detalles.

Cambio de interfaz de QueryRunner

La interfaz de QueryRunner cambió y el antiguo método run() se eliminó y se reemplazó por un nuevo método que acepta un objeto QueryPlus. Las extensiones de consulta personalizadas deberán implementar la nueva interfaz. Consulte https://github.com/druid-io/druid/pull/4184 y https://github.com/druid-io/druid/pull/4482 para obtener más detalles.

Cambio de interfaz de filtro

El método Filter.getBitmapResult() ya no tiene una implementación predeterminada: https://github.com/druid-io/druid/pull/4481 Las extensiones de filtro personalizadas deberán proporcionar una implementación para getBitmapResult() ahora.

Otras notas

jvm/gc/métrica de tiempo

La métrica jvm/gc/time ya no se emite y se reemplaza por una nueva métrica denominada jvm/gc/cpu por los motivos que se describen aquí: https://github.com/druid-io/druid/pull/4480

Estrategia de selección de trabajador predeterminada

Tenga en cuenta que la estrategia de selección de trabajadores predeterminada ha cambiado de fillCapacity a equalDistribution. Este cambio se introdujo en 0.10.1, la versión anterior, pero no se mencionó en 0.10.1 release note, por lo que se menciona nuevamente aquí.

Se eliminó la creación del segmento V8

Druid ahora siempre creará segmentos V9, ya no se admite la creación de segmentos V8 y se eliminó la propiedad buildV9Directly para tareas de ingesta. Consulte https://github.com/druid-io/druid/pull/4420 para obtener más detalles.

LogLevelAdjuster eliminado

Tenga en cuenta que LogLevelAdjuster se ha eliminado: https://github.com/druid-io/druid/pull/4236 Cualquier usuario que utilice mbeans para configurar los niveles de registro debería configurar log4j2 utilizando jmx.

druid druid-0.11.0

Druid 0.11.0 contains over a hundred performance improvements, stability improvements, and bug fixes from almost 40 contributors. This release adds two major security features, TLS support and extension points for authentication and authorization.

Major new features include:

  • TLS (a.k.a. SSL) support
  • Extension points for authentication and authorization
  • Double columns support
  • cachingCost Balancer Strategy
  • jq expression support in JSON parser
  • Redis cache extension
  • GroupBy performance improvements
  • Various improvements to Druid SQL

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Documentation for this release is at: http://druid.io/docs/0.11.0/

Highlights

TLS support

Druid now supports TLS, enabling encrypted client and inter-node communications. Please see http://druid.io/docs/0.11.0/operations/tls-support.html for details on configuration and related extensions.

Added by @pjain1 in https://github.com/druid-io/druid/pull/4270.

Authentication/authorization extension points

Extension points for authenticating and authorizing requests have been added to Druid. Please see http://druid.io/docs/0.11.0/configuration/auth.html for information on configuration and extension implementation.

The existing Kerberos authentication extension has been updated to implement the new Authenticator interface, please see the "Kerberos configuration changes" section under "Updating from 0.10.1 and earlier" for more information if you are using the Kerberos extension.

Added by @jon-wei in https://github.com/druid-io/druid/pull/4271

Double columns support

Druid now supports Double type aggregator columns. Please see http://druid.io/docs/0.11.0/querying/aggregations.html for documentation on the new Double aggregators.

Added by @b-slim in https://github.com/druid-io/druid/pull/4491.

cachingCost Balancer Strategy

Users upgrading to 0.11.0 are encouraged to try the new cachingCost segment balancing strategy on their coordinators. This strategy offers large performance improvements over the existing cost balancer strategy, and it is planned to become the default strategy in the release following 0.11.0.

This strategy can be selected by setting the following property on coordinators:

druid.coordinator.balancer.strategy=cachingCost

Added by @dgolitsyn in https://github.com/druid-io/druid/pull/4731

jq expression support in JSON parser

Druid's JSON input parser now supports jq expressions using jackson-jq, enabling more input transforms before ingestion. Please see http://druid.io/docs/0.11.0/ingestion/flatten-json.html for more details.

Added by @knoguchi in https://github.com/druid-io/druid/pull/4171.

Redis cache extension

A new cache implementation using Redis has been added in an extension, added by @QiuMM in https://github.com/druid-io/druid/pull/4615. Please refer to the preceding pull request for more details.

GroupBy performance improvements

Several new performance optimizations have been added to the GroupBy query by @jihoonson in the following PRs:

https://github.com/druid-io/druid/pull/4660 Parallel sort for ConcurrentGrouper https://github.com/druid-io/druid/pull/4576 Array-based aggregation for groupBy query https://github.com/druid-io/druid/pull/4668 Add IntGrouper to avoid unnecessary boxing/unboxing in array-based aggregation

PR #4660 offers a general improvement by parallelizing partial result sorting, while PR #4576 and #4668 offer significant improvements when grouping on a single String column.

SQL improvements

Various improvements and features have been added to Druid SQL, by @gianm in the following PRs:

https://github.com/druid-io/druid/pull/4750 - TRIM support https://github.com/druid-io/druid/pull/4720 - Rounding for count distinct https://github.com/druid-io/druid/pull/4561 - Metrics for SQL queries https://github.com/druid-io/druid/pull/4360 - SQL expressions support

And much more!

The full list of changes is here: https://github.com/druid-io/druid/pulls?utf8=%E2%9C%93&q=is%3Apr%20is%3Aclosed%20milestone%3A0.11.0

Updating from 0.10.1 and earlier

Please see below for changes between 0.10.1 and 0.11.0 that you should be aware of before upgrading. If you're updating from an earlier version than 0.10.1, please see release notes of the relevant intermediate versions for additional notes.

Upgrading coordinators and overlords

The following patch changes the way coordinator->overlord redirects are handled: https://github.com/druid-io/druid/pull/5037

The overlord leader election algorithm has changed in 0.11.0: https://github.com/druid-io/druid/pull/4699.

As a result of the two patches above, special care is needed when upgrading Coordinator or Overlord to 0.11.0. All coordinators and overlords must be shut down and upgraded together.

For example, to upgrade Coordinators, you would shutdown all coordinators, upgrade them to 0.11.0 and then start them. Overlords should be upgraded in a similar way.

During the upgrade process, there must not be any time period where a non-0.11.0 coordinator or overlord is running simultaneously with an 0.11.0 coordinator or overlord.

Note that at least one overlord should be brought up as quickly as possible after shutting them all down so that peons, tranquility etc continue to work after some retries.

Also note that the druid.zk.paths.indexer.leaderLatchPath property is no longer used now.

Service name changes

In earlier versions of Druid, / characters in service names defined by druid.service would be replaced by : characters because these service names were used in Zookeeper paths. Druid 0.11.0 no longer performs these character replacements.

Example:1 - if the old configuration had a broker with service name test/broker: druid.service=test/broker

and a Router was configured assuming that / will be replaced with : in the broker service name, druid.router.tierToBrokerMap={"hot":"test:broker","_default_tier":"test:broker"}

the Router configuration should be updated to remove that assumption: druid.router.tierToBrokerMap={"hot":"test/broker","_default_tier":"test/broker"}

Example:2 - If the old configuration had overlord with service Name test/overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test/overlord and not test:overlord

Example:3 - If the old configuration had overlord with service Name test:overlord then value of druid.coordinator.asOverlord.overlordService or druid.selectors.indexing.serviceName should be test:overlord and not test/overlord

Following service name-related configurations are also affected and should be updated to exactly match the value of druid.service property on other node being discovered.

druid.coordinator.asOverlord.overlordService druid.selectors.coordinator.serviceName druid.selectors.indexing.serviceName druid.router.defaultBrokerServiceName druid.router.coordinatorServiceName druid.router.tierToBrokerMap

Please see https://github.com/druid-io/druid/issues/4992 for more details.

Kerberos configuration changes

The Kerberos authentication configuration format has changed as a result of the new interfaces introduced by #4271. Please refer to http://druid.io/docs/0.11.0/development/extensions-core/druid-kerberos.html for the new configuration properties.

Users can point the Kerberos authenticator's authorizerName to an instance of an "allowAll" authorizer to replicate the pre-0.11.0 behavior of a cluster using Kerberos authentication with no authorization.

Lookups API path changes

The paths for the lookups configuration API have changed due to #5058.

Configuration paths that had the form /druid/coordinator/v1/lookups now have the form /druid/coordinator/v1/lookups/config.

Please see http://druid.io/docs/0.11.0/querying/lookups.html for the current API.

Migrating to Double columns

Prior to 0.11.0, the Double* aggregators would store column values on disk as Float while performing aggregations using Double representations.

PR #4491 allows the Double aggregators to store column values on disk as Doubles. Due to concerns related to rolling updates and version downgrades, this behavior is disabled by default and Druid will continue to store Double aggregators on disk as floats.

To enable Double column storage, set the following property in the common runtime properties:

druid.indexing.doubleStorage=double

Users should not set this property during an initial rolling upgrade to 0.11.0, as any nodes running pre-0.11.0 Druid will not be able to handle Double columns created during the upgrade period. Users will also need to reindex any segments with Double columns if downgrading from 0.11.0 to an older version. Please see #4944 and #4605 for more information.

Scan query changes

The Scan query has been moved from extensions-contrib to core Druid. As part of this migration: https://github.com/druid-io/druid/pull/4751, the scan query's handling of the time column has changed.

The time column is now is returned as "__time" rather than "timestamp", it is no longer included if you do not specifically ask for it in your "columns", and it is returned as a long rather than a string.

Users can revert the Scan query's time handling to the legacy extension behavior by setting "legacy" : true in their queries, or setting the property druid.query.scan.legacy = true. This is meant to provide a migration path for users that were formerly using the contrib extension.

Extension Interface Changes

Aggregator double column support

The Aggregator interface has gained a getDouble() method, which defaults to casting the result of getFloat(). The getDouble() method should be re-implemented for any custom aggregators that can support doubles.

See https://github.com/druid-io/druid/pull/4595 for more details.

QueryRunner interface change

The QueryRunner interface has changed and the old run() method has been removed, replaced by a new method that accepts a QueryPlus object.

Custom query extensions will need to implement the new interface.

Please see https://github.com/druid-io/druid/pull/4184 and https://github.com/druid-io/druid/pull/4482 for more details.

Filter interface change

The Filter.getBitmapResult() method no longer has a default implementation: https://github.com/druid-io/druid/pull/4481

Custom filter extensions will need to provide an implementation for getBitmapResult() now.

Other Notes

jvm/gc/time metric

The jvm/gc/time metric is no longer emitted, replaced by a new metric named jvm/gc/cpu for the reasons described here: https://github.com/druid-io/druid/pull/4480

Default worker select strategy

Please note that the default worker select strategy has changed from fillCapacity to equalDistribution. This change was introduced in 0.10.1, the previous release, but was not mentioned in the 0.10.1 release notes, so it is called out again here.

V8 segment creation removed

Druid will now always build V9 segments, creating V8 segments is no longer supported and the buildV9Directly property for ingestion tasks has been removed.

Please see https://github.com/druid-io/druid/pull/4420 for more details.

LogLevelAdjuster removed

Please note that the LogLevelAdjuster has been removed: https://github.com/druid-io/druid/pull/4236

Any user using mbeans to configure log levels should configure log4j2 using jmx instead.
