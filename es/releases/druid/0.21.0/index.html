druida druida-0.21.0

Apache Druid 0.21.0 contiene alrededor de 120 funciones nuevas, correcciones de errores, mejoras de rendimiento, mejoras de documentación y cobertura de pruebas adicionales de 36 contribuyentes. Consulte la lista completa de cambios y todo lo relacionado con el hito para obtener más detalles.

<a name="21-new-features" href="#21-new-features">#</a> Nuevas funciones

<a name="21-operación" href="#21-operación">#</a> Operación

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Descubrimiento de servicios y elección de líder basado en Kubernetes

La nueva extensión Kubernetes admite el descubrimiento de servicios y la elección de líderes basados en Kubernetes. Esta extensión funciona junto con la vista del servidor basada en HTTP (druid.serverview.type=http) y la administración de tareas (druid.indexer.runner.type=httpRemote) para permitirle ejecutar un clúster Druid sin dependencias de ZooKeeper. Esta extensión aún es experimental. Consulte extensión Kubernetes para obtener más detalles. https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> Nueva configuración del coordinador dinámico para limitar el número de segmentos al encontrar un segmento candidato para el equilibrio de segmentos

Puede configurar percentOfSegmentsToConsiderPerMove para limitar la cantidad de segmentos considerados al seleccionar un segmento candidato para mover. Los candidatos se buscan hasta maxSegmentsToMove * 2 veces. Esta nueva configuración evita que Druid repita todos los segmentos disponibles para acelerar el proceso de equilibrio de segmentos, especialmente si tiene muchos segmentos disponibles en su clúster. Consulte Configuración dinámica del coordinador para obtener más detalles. https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> Puntos finales status y selfDiscovered para indexadores

El indexador ahora admite puntos finales status y selfDiscovered. Consulte Información del procesador APIs para obtener más detalles. https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Consultando

<a name="21-grouping-function" href="#21-grouping-function">#</a> Nueva función de agregador grouping

Puede utilizar la nueva función SQL del agregador grouping con GROUPING SETS o CUBE para indicar qué dimensiones de agrupación se incluyen en el conjunto de agrupación actual. Consulte Funciones de agregación para obtener más detalles. https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Manejo mejorado de argumentos faltantes en expresiones y funciones

El procesamiento de expresiones ahora se puede vectorizar cuando faltan entradas. Por ejemplo una columna inexistente. Cuando falta un argumento en una expresión, Druid ahora puede inferir el tipo adecuado de resultado basándose en argumentos no nulos. Por ejemplo, para longColumn + nonExistentColumn, nonExistentColumn se trata como (long) 0 en lugar de (double) 0.0. Finalmente, en el modo de manejo de nulos predeterminado, las funciones matemáticas pueden producir resultados correctamente al tratar los argumentos faltantes como ceros. https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> Permitir período cero para TIMESTAMPADD

La función TIMESTAMPADD ahora permite un período cero. Esta funcionalidad es necesaria para algunas herramientas de BI como Tableau. https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Ingestión

<a name="21-parallel-ingestion- without-intervals" href="#21-parallel-ingestion- without-intervals">#</a> La ingesta paralela nativa ya no requiere intervalos explícitos

La tarea paralela ya no requiere que establezcas intervalos explícitos en granularitySpec. Si faltan intervalos, la tarea paralela ejecuta un paso adicional para el muestreo de entrada que recopila los intervalos para indexar. https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Compatibilidad con la versión antigua de Kafka

Druid ahora admite Apache Kafka anteriores a 0.11. Para leer una versión antigua de Kafka, configure isolation.level en read_uncommitted en consumerProperties. Hasta esta versión, solo se han probado 0.10.2.1. Consulte Configuraciones del supervisor Kafka para obtener más detalles. https://github.com/apache/druid/pull/10551

Fusión de segmentos de varias fases para la ingesta de lotes nativos

Una nueva tuningConfig, maxColumnsToMerge, controla cuántos segmentos se pueden fusionar al mismo tiempo en la tarea. Esta configuración puede resultar útil para evitar una alta presión de memoria durante la fusión. Consulte tuningConfig para la ingesta de lotes nativos para obtener más detalles. https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> La reingestión nativa requiere menos memoria

Las tareas paralelas ahora clasifican los segmentos por ID antes de asignarlos a subtareas. Esta clasificación minimiza la cantidad de períodos de tiempo que debe manejar cada subtarea. Como resultado, se espera que cada subtarea utilice menos memoria, especialmente cuando se emite una única tarea paralela para volver a ingerir segmentos que cubren un período de tiempo prolongado. https://github.com/apache/druid/pull/10646

<a name="21-web-console" href="#21-web-console">#</a> Consola web

<a name="21-refresh-console-style" href="#21-refresh-console-style">#</a> Estilos de consola web actualizados y mejorados

Los nuevos estilos de la consola web hacen un mejor uso de los colores de la marca Druid y estandarizan los rellenos y márgenes en todas partes. Los colores del icono y del fondo ahora se derivan del logotipo de Druid. https://github.com/apache/druid/pull/10515

<a name="21-web-console-partitioning" href="#21-web-console-partitioning">#</a> La información de partición está disponible en la consola web

La consola web ahora muestra información de partición de fuentes de datos en las nuevas columnas Segment granularity y Partitioning.

columna Segment granularity en la pestaña Datasources

La tabla Schema ahora refleja el orden de dimensiones en dimensionsSpec. https://github.com/apache/druid/pull/10588

<a name="21-metrics" href="#21-metrics">#</a> Métricas

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Métricas de tiempo de ejecución de tareas del coordinador

El coordinador realiza varias tareas de "deber". Por ejemplo, equilibrar segmentos, cargar nuevos segmentos, etc. Ahora hay dos nuevas métricas para ayudarle a analizar qué tan rápido el Coordinador está ejecutando estas tareas.

  • coordinator/time: el tiempo para ejecutar un deber individual
  • coordinator/global/time: el tiempo para ejecutar todas las tareas ejecutables https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Métrica de tiempo de espera de consulta

Una nueva métrica proporciona la cantidad de consultas con tiempo de espera agotado. Las consultas previamente agotadas se trataron como interrumpidas y se incluyeron en query/interrupted/count (consulte Códigos de estado HTTP modificados para errores de consulta para obtener más detalles). query/timeout/count: el número de consultas agotadas durante el período de emisión https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Métricas aleatorias para la ingesta por lotes

Dos nuevas métricas proporcionan estadísticas aleatorias para los administradores intermedios y los indexadores. Estas métricas tienen el supervisorTaskId como dimensión.

  • ingest/shuffle/bytes: número de bytes barajados por período de emisión
  • ingest/shuffle/requests: número de solicitudes de reproducción aleatoria por período de emisión Para habilitar las métricas aleatorias, agregue org.apache.druid.indexing.worker.shuffle.ShuffleMonitor en druid.monitoring.monitors. Consulte Métricas aleatorias para obtener más detalles. https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> Nuevo programador de monitorización de métricas seguras contra la deriva del reloj

El programador de monitoreo de métricas predeterminado se implementa en base a ScheduledThreadPoolExecutor, que es propenso a una [desviación del reloj] ilimitada (https://en.wikipedia.org/wiki/Clock_drift). Un nuevo programador de monitores, ClockDriftSafeMonitorScheduler, supera esta limitación. Para utilizar el nuevo programador, configure druid.monitoring.schedulerClassName en org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler en el archivo runtime.properties. https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> Actualizando a 0.21.0

Considere los siguientes cambios y actualizaciones al actualizar de Druid 0.20.0 a 0.21.0. Si está actualizando desde una versión anterior a 0.20.0, consulte los release note de las versiones intermedias relevantes.

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Códigos de estado HTTP mejorados para errores de consulta

Antes de esta versión, Druid devolvía el "error interno (500)" para la mayoría de los errores de consulta. Ahora Druid devuelve diferentes códigos de error según su causa. La siguiente tabla enumera los errores y sus códigos correspondientes que han cambiado: Excepción | Descripción| Código antiguo | Nuevo código ------------ | ------------- | ------------- | ------------- SqlParseException y ValidationException de Calcita | Error en la planificación de consultas | 500 | 400 QueryTimeoutException | La ejecución de la consulta no finalizó en el tiempo de espera | 500 | 504 ResourceLimitExceededException | La consulta solicitó más recursos que el umbral configurado | 500 | 400 Excepción de recursos insuficientes | La consulta no se pudo programar debido a la falta de búferes de combinación disponibles en el momento en que se envió | 500 | 429, combinado con QueryCapacityExceededException QueryUnsupportedException | Funcionalidad no compatible | 400 | 501 También hay una nueva métrica de consulta para errores de tiempo de espera de consulta. Consulte Nueva métrica de tiempo de espera de consulta para obtener más detalles. https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Consulta métrica interrumpida

query/interrupted/count ya no cuenta las consultas que expiraron. Estas consultas se cuentan por query/timeout/count.

<a name="21-context-dimension" href="#21-context-dimension">#</a> Dimensión context en métricas de consulta

context ahora es una dimensión predeterminada emitida para todas las métricas de consulta. context es una cadena con formato JSON que contiene el contexto de consulta a la que hace referencia la métrica emitida. La adición de una dimensión que no existía anteriormente altera algunas métricas emitidas por Druid. Debe planificar el manejo de esta nueva dimensión context en su canal de métricas. Dado que la dimensión es una cadena con formato JSON, una solución común es analizar la dimensión y aplanarla o extraer los bits que desee y descartar el blob de cadena con formato JSON completo. https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Soporte obsoleto para Apache ZooKeeper 3.4

Como ZooKeeper 3.4 ha estado al final de su vida útil por un tiempo, la compatibilidad con ZooKeeper 3.4 está obsoleta en 0.21.0 y se eliminará en un futuro próximo. https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Formato de serialización coherente y convención de nomenclatura de columnas para la tabla sys.segments

Todas las columnas de la tabla sys.segments ahora están serializadas en el formato JSON para que sean coherentes con otras tablas del sistema. Los nombres de las columnas ahora usan la misma convención de "caso de serpiente". https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Problemas conocidos

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Vulnerabilidad de seguridad conocida en la biblioteca Thrift

La extensión Thrift puede ser útil para ingerir archivos del formato Thrift en Druid. Sin embargo, existe una vulnerabilidad de seguridad conocida en la versión de la biblioteca Thrift que utiliza Druid. La vulnerabilidad se puede explotar ingiriendo archivos Thrift creados con fines malintencionados cuando se utilizan indexadores. Recomendamos otorgar el permiso DATASOURCE WRITE solo a usuarios trusted.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Problemas de permisos al ejecutar el clúster Druid basado en docker

Si ejecuta el clúster Druid docker por primera vez en su máquina, utilizando la imagen 0.21.0 puede crear directorios internos con la cuenta raíz. Como resultado, los servicios de Druid pueden fallar debido a la falta de permisos. Este problema está archivado en https://github.com/apache/druid/issues/11166. Si está utilizando la redacción docker, puede utilizar los siguientes comandos para solucionar este problema. Estos comandos crearán directorios internos primero usando una imagen antigua y luego iniciarán servicios usando la imagen 0.21.0.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

Si no está utilizando docker compose, puede pasar directamente el parámetro de volumen para /opt/druid/var cuando inicie servicios usando la imagen 0.21.0. Por ejemplo, puede ejecutar el siguiente comando para iniciar el servicio de coordinador.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

Para obtener una lista completa de problemas abiertos, consulte https://github.com/apache/druid/labels/Bug.

druid druid-0.21.0

Apache Druid 0.21.0 contains around 120 new features, bug fixes, performance enhancements, documentation improvements, and additional test coverage from 36 contributors. Refer to the complete list of changes and everything tagged to the milestone for further details.

<a name="21-new-features" href="#21-new-features">#</a> New features

<a name="21-operation" href="#21-operation">#</a> Operation

<a name="21-k8s-extension" href="#21-k8s-extension">#</a> Service discovery and leader election based on Kubernetes

The new Kubernetes extension supports service discovery and leader election based on Kubernetes. This extension works in conjunction with the HTTP-based server view (druid.serverview.type=http) and task management (druid.indexer.runner.type=httpRemote) to allow you to run a Druid cluster with zero ZooKeeper dependencies. This extension is still experimental. See Kubernetes extension for more details.

https://github.com/apache/druid/pull/10544 https://github.com/apache/druid/pull/9507 https://github.com/apache/druid/pull/10537

<a name="21-segment-count-limit-for-balancing" href="#21-segment-count-limit-for-balancing">#</a> New dynamic coordinator configuration to limit the number of segments when finding a candidate segment for segment balancing

You can set the percentOfSegmentsToConsiderPerMove to limit the number of segments considered when picking a candidate segment to move. The candidates are searched up to maxSegmentsToMove * 2 times. This new configuration prevents Druid from iterating through all available segments to speed up the segment balancing process, especially if you have lots of available segments in your cluster. See Coordinator dynamic configuration for more details.

https://github.com/apache/druid/pull/10284

<a name="21-indexer-endpoints" href="#21-indexer-endpoints">#</a> status and selfDiscovered endpoints for Indexers

The Indexer now supports status and selfDiscovered endpoints. See Processor information APIs for details.

https://github.com/apache/druid/pull/10679

<a name="21-querying" href="#21-querying">#</a> Querying

<a name="21-grouping-function" href="#21-grouping-function">#</a> New grouping aggregator function

You can use the new grouping aggregator SQL function with GROUPING SETS or CUBE to indicate which grouping dimensions are included in the current grouping set. See Aggregation functions for more details.

https://github.com/apache/druid/pull/10518

<a name="21-expr-type-handling" href="#21-expr-type-handling">#</a> Improved missing argument handling in expressions and functions

Expression processing now can be vectorized when inputs are missing. For example a non-existent column. When an argument is missing in an expression, Druid can now infer the proper type of result based on non-null arguments. For instance, for longColumn + nonExistentColumn, nonExistentColumn is treated as (long) 0 instead of (double) 0.0. Finally, in default null handling mode, math functions can produce output properly by treating missing arguments as zeros.

https://github.com/apache/druid/pull/10499

<a name="21-timestampadd" href="#21-timestampadd">#</a> Allow zero period for TIMESTAMPADD

TIMESTAMPADD function now allows zero period. This functionality is required for some BI tools such as Tableau.

https://github.com/apache/druid/pull/10550

<a name="21-ingestion" href="#21-ingestion">#</a> Ingestion

<a name="21-parallel-ingestion-without-intervals" href="#21-parallel-ingestion-without-intervals">#</a> Native parallel ingestion no longer requires explicit intervals

Parallel task no longer requires you to set explicit intervals in granularitySpec. If intervals are missing, the parallel task executes an extra step for input sampling which collects the intervals to index.

https://github.com/apache/druid/pull/10592 https://github.com/apache/druid/pull/10647

<a name="21-old-kafka-support" href="#21-old-kafka-support">#</a> Old Kafka version support

Druid now supports Apache Kafka older than 0.11. To read from an old version of Kafka, set the isolation.level to read_uncommitted in consumerProperties. Only 0.10.2.1 have been tested up until this release. See Kafka supervisor configurations for details.

https://github.com/apache/druid/pull/10551

Multi-phase segment merge for native batch ingestion

A new tuningConfig, maxColumnsToMerge, controls how many segments can be merged at the same time in the task. This configuration can be useful to avoid high memory pressure during the merge. See tuningConfig for native batch ingestion for more details.

https://github.com/apache/druid/pull/10689

<a name="21-compaction" href="#21-compaction">#</a> Native re-ingestion is less memory intensive

Parallel tasks now sort segments by ID before assigning them to subtasks. This sorting minimizes the number of time chunks for each subtask to handle. As a result, each subtask is expected to use less memory, especially when a single Parallel task is issued to re-ingest segments covering a long time period.

https://github.com/apache/druid/pull/10646

<a name="21-metrics" href="#21-metrics">#</a> Metrics

<a name="21-coordinator-duty-metrics" href="#21-coordinator-duty-metrics">#</a> Coordinator duty runtime metrics

The coordinator performs several 'duty' tasks. For example segment balancing, loading new segments, etc. Now there are two new metrics to help you analyze how fast the Coordinator is executing these duties.

  • coordinator/time: the time for an individual duty to execute
  • coordinator/global/time: the time for the whole duties runnable to execute

https://github.com/apache/druid/pull/10603

<a name="21-query-timeout-metric" href="#21-query-timeout-metric">#</a> Query timeout metric

A new metric provides the number of timed out queries. Previously timed out queries were treated as interrupted and included in the query/interrupted/count (see Changed HTTP status codes for query errors for more details).

query/timeout/count: the number of timed out queries during the emission period

https://github.com/apache/druid/pull/10567

<a name="21-shuffle-metrics" href="#21-shuffle-metrics">#</a> Shuffle metrics for batch ingestion

Two new metrics provide shuffle statistics for MiddleManagers and Indexers. These metrics have the supervisorTaskId as their dimension.

  • ingest/shuffle/bytes: number of bytes shuffled per emission period
  • ingest/shuffle/requests: number of shuffle requests per emission period

To enable the shuffle metrics, add org.apache.druid.indexing.worker.shuffle.ShuffleMonitor in druid.monitoring.monitors. See Shuffle metrics for more details.

https://github.com/apache/druid/pull/10359

<a name="21-cron-scheduler" href="#21-cron-scheduler">#</a> New clock-drift safe metrics monitor scheduler

The default metrics monitor scheduler is implemented based on ScheduledThreadPoolExecutor which is prone to unbounded clock drift. A new monitor scheduler, ClockDriftSafeMonitorScheduler, overcomes this limitation. To use the new scheduler, set druid.monitoring.schedulerClassName to org.apache.druid.java.util.metrics.ClockDriftSafeMonitorScheduler in the runtime.properties file.

https://github.com/apache/druid/pull/10448 https://github.com/apache/druid/pull/10732

<a name="21-rds-password-provider" href="#21-rds-password-provider">#</a> New extension for a password provider based on AWS RDS token

A new PasswordProvider type allows access to AWS RDS DB instances using temporary AWS tokens. This extension can be useful when an RDS is used as Druid's metadata store. See AWS RDS extension for more details.

<a name="21-system-table-leader" href="#21-system-table-leader">#</a> The sys.servers table shows leaders

A new long-typed column is_leader in the sys.servers table indicates whether or not the server is the leader.

https://github.com/apache/druid/pull/10680

https://github.com/apache/druid/pull/9938

<a name="21-dynamic-config-provider" href="#21-dynamic-config-provider">#</a> Extensible Kafka consumer properties via a new DynamicConfigProvider

A new class DynamicConfigProvider enables fetching consumer properties at runtime. Currently, only a map-based config provider is supported by default. See DynamicConfigProvider for how to implement a custom config provider.

<a name="21-post-agg-subtotal" href="#21-post-agg-subtotal">#</a> Post-aggregator computation with subtotals

Before 0.21.0, the query fails with an error when you use post aggregators with sub-totals. Now this bug is fixed and you can use post aggregators with subtotals.

https://github.com/apache/druid/pull/10653

<a name="21-indexer-announce" href="#21-indexer-announce">#</a> Indexers announce themselves as segment servers

In 0.19.0 and 0.20.0, Indexers could not process queries against streaming data as they did not announce themselves as segment servers. They are fixed to announce themselves properly in 0.21.0.

<a name="21-upgrading-to-0.21.0" href="#21-upgrading-to-0.21.0">#</a> Upgrading to 0.21.0

Consider the following changes and updates when upgrading from Druid 0.20.0 to 0.21.0. If you're updating from an earlier version than 0.20.0, see the release notes of the relevant intermediate versions.

<a name="21-http-error-codes" href="#21-http-error-codes">#</a> Improved HTTP status codes for query errors

Before this release, Druid returned the "internal error (500)" for most of the query errors. Now Druid returns different error codes based on their cause. The following table lists the errors and their corresponding codes that has changed:

Exception | Description| Old code | New code ------------ | ------------- | ------------- | ------------- SqlParseException and ValidationException from Calcite | Query planning failed | 500 | 400 QueryTimeoutException | Query execution didn't finish in timeout | 500 | 504 ResourceLimitExceededException | Query asked more resources than configured threshold | 500 | 400 InsufficientResourceException | Query failed to schedule because of lack of merge buffers available at the time when it was submitted | 500 | 429, merged to QueryCapacityExceededException QueryUnsupportedException | Unsupported functionality | 400 | 501

There is also a new query metric for query timeout errors. See New query timeout metric for more details.

https://github.com/apache/druid/pull/10464 https://github.com/apache/druid/pull/10746

<a name="21-query-interrupted-metric" href="#21-query-interrupted-metric">#</a> Query interrupted metric

query/interrupted/count no longer counts the queries that timed out. These queries are counted by query/timeout/count.

<a name="21-context-dimension" href="#21-context-dimension">#</a> context dimension in query metrics

context is now a default dimension emitted for all query metrics. context is a JSON-formatted string containing the query context for the query that the emitted metric refers to. The addition of a dimension that was not previously alters some metrics emitted by Druid. You should plan to handle this new context dimension in your metrics pipeline. Since the dimension is a JSON-formatted string, a common solution is to parse the dimension and either flatten it or extract the bits you want and discard the full JSON-formatted string blob.

https://github.com/apache/druid/pull/10578

<a name="21-deprecate-zk-3.4" href="#21-deprecate-zk-3.4">#</a> Deprecated support for Apache ZooKeeper 3.4

As ZooKeeper 3.4 has been end-of-life for a while, support for ZooKeeper 3.4 is deprecated in 0.21.0 and will be removed in the near future.

https://github.com/apache/druid/issues/10780

<a name="21-consistent-segments-table" href="#21-consistent-segments-table">#</a> Consistent serialization format and column naming convention for the sys.segments table

All columns in the sys.segments table are now serialized in the JSON format to make them consistent with other system tables. Column names now use the same "snake case" convention.

https://github.com/apache/druid/pull/10481

<a name="21-known-issues" href="#21-known-issues">#</a> Known issues

<a name="21-cve-2020-13949" href="#21-cve-2020-13949">#</a> Known security vulnerability in the Thrift library

The Thrift extension can be useful for ingesting files of the Thrift format into Druid. However, there is a known security vulnerability in the version of the Thrift library that Druid uses. The vulerability can be exploitable by ingesting maliciously crafted Thrift files when you use Indexers. We recommend granting the DATASOURCE WRITE permission to only trusted users.

<a name="21-docker-volume-ownership" href="#21-docker-volume-ownership">#</a> Permission issues in running the docker-based Druid cluster

If you run the Druid docker cluster for the first time in your machine, using the 0.21.0 image can create internal directories with the root account. As a result, Druid services can fail due lack of permissions. This issue is filed in https://github.com/apache/druid/issues/11166.

If you are using docker compose, you can use the below commands to work around this issue. These commands will create internal directories first using an old image and then start services using the 0.21.0 image.

$ cd ${PREV_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml create
$ cd ${0.21.0_SRC_DIR}
$ docker-compose -f distribution/docker/docker-compose.yml up

If you are not using docker compose, you can directly pass the volume parameter for /opt/druid/var when you start services using the 0.21.0 image. For example, you can run the command below to start the coordinator service.

$ docker run -v /path/to/host/dir:/opt/druid/var apache/druid:0.21.0 coordinator

For a full list of open issues, please see https://github.com/apache/druid/labels/Bug.
