druida druida-0.6.171

Druid 0.6.171 es una solución estable de corrección de errores destinada principalmente a permitir una actualización menos dolorosa de Druid 0.7.0. En el futuro, respaldaremos las correcciones para 0.6.x según sea necesario para la comunidad y continuaremos desarrollando funciones importantes en 0.7.x.

Descargar

http://static.druid.io/artifacts/releases/druid-services-0.6.171-bin.tar.gz

Actualización, aspectos a tener en cuenta

Tanto esta versión como 0.7.0-RC1 brindan mucho mejor soporte listo para usar para PostgreSQL como almacén de metadatos. Para proporcionar esta funcionalidad, tuvimos que realizar algunos pequeños cambios en la forma en que se almacenan los datos en el almacenamiento de metadatos para las configuraciones de MySQL. Antes de actualizar a 0.6.171, asegúrese de que: Todas las tablas de metadatos de Druid MySQL utilizan codificación UTF-8 para todas las columnas de cadena/texto. El juego de caracteres predeterminado para la base de datos Druid MySQL se ha cambiado a UTF-8. Druid Coordinator y Overlord se negarán a iniciarse si el conjunto de caracteres predeterminado de la base de datos no es UTF-8. Para verificar la codificación de caracteres de la columna, use SHOW CREATE TABLE <table>;. Si la codificación predeterminada de la tabla no es UTF-8 o si alguna columna está codificada con otro formato que no sea UTF-8, deberá convertir esas tablas. Para verificar la codificación predeterminada de la base de datos, use SHOW VARIABLES LIKE 'character_set_database'; Si aún no está utilizando la codificación UTF-8 para sus columnas, puede convertir sus tablas y cambiar el valor predeterminado de la base de datos usando los siguientes comandos. Tenga en cuenta que la conversión de la tabla puede tardar un tiempo (del orden de minutos) y la carga/transferencia del segmento se interrumpirá mientras dure la actualización. ¡Haga una copia de seguridad de su base de datos antes de realizar la actualización!

ALTER TABLE druid_config    CONVERT TO CHARSET utf8;
ALTER TABLE druid_rules     CONVERT TO CHARSET utf8;
ALTER TABLE druid_segments  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasks     CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklogs  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklocks CONVERT TO CHARSET utf8;

-- replace druid with your Druid database name here 
ALTER DATABASE druid DEFAULT CHARACTER SET utf8;

Mejoras

Introdujimos varias optimizaciones de consultas, principalmente para topN y HLL. El señor supremo ahora puede elegir opcionalmente a qué trabajador enviarle tareas #904 Lógica de reintento mejorada para plomeros en tiempo real cuando fallan las transferencias durante el paso final de fusión

Corrección de errores

  • Se corrigió la búsqueda con el mismo valor en varias columnas.
  • Se corrigieron los valores predeterminados del embarcadero para aumentar el número de subprocesos y evitar bloqueos.
  • Se corrigieron las métricas de consulta/espera que se emitían dos veces.
  • Se corrigieron las exclusiones de dimensiones predeterminadas para marcas de tiempo y agregadores en el esquema de ingesta.
  • Se corrigió el origen faltante en la clave de caché para granularidades de período
  • Se corrigió FilteredServerView predeterminado para que realmente se filtre
  • Se corrigieron los archivos que no se limpiaban correctamente en el directorio de caché del segmento.
  • Se corrigieron los resultados que a veces aparecían desordenados.
  • Se corrigieron las consultas TopN de bySegment que no regresaban a nivel de corredor.
  • Se corrigieron algunos errores relacionados con agregadores filtrados.
  • Se corrigieron cantidades increíbles de registros cuando el coordinador pierde el liderazgo.
  • Bibliotecas jetty y spymemcached actualizadas para varias correcciones
  • Se corrigió el problema del esquema de almacenamiento en caché del agregador de cardinalidad.
  • Se corrigió que la página '/status' del Coordinador y del Señor Supremo no debería redirigirse a las instancias del líder.
  • Postgres hecho funcionar de inmediato en 0.6.x

druid druid-0.6.171

Druid 0.6.171 is a bug fix stable mainly meant to enable a less painful update to Druid 0.7.0. Going forward, we will be backporting fixes to 0.6.x as required for the community and continuing to develop major features on 0.7.x.

Download

http://static.druid.io/artifacts/releases/druid-services-0.6.171-bin.tar.gz

Updating, Things to be Aware

Both this version and 0.7.0-RC1 provide much better out of the box support for PostgreSQL as a metadata store. In order to provide this functionality, we had to make some small changes to the way data is stored in metadata storage for MySQL setups.

Before updating to 0.6.171, please make sure that: All Druid MySQL metadata tables are using UTF-8 encoding for all string/text columns, The default character set for the Druid MySQL database has been changed to UTF-8. Druid Coordinator and Overlord will refuse to start if the database default character set is not UTF-8.

To check column character encoding, use SHOW CREATE TABLE <table>;. If the default table encoding is not UTF-8 or if any columns are encoded using anything other than UTF-8 you will need to convert those tables.

To check the database default encoding, use SHOW VARIABLES LIKE 'character_set_database';

If you are not already using UTF-8 encoding for your columns, you can convert your tables and change the database default using the following commands. Please keep in mind that table conversion can take a while (order of minutes) and segment loading / handoff will be interrupted for the duration of the upgrade.

Make a backup of your database before performing the upgrade!

ALTER TABLE druid_config    CONVERT TO CHARSET utf8;
ALTER TABLE druid_rules     CONVERT TO CHARSET utf8;
ALTER TABLE druid_segments  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasks     CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklogs  CONVERT TO CHARSET utf8;
ALTER TABLE druid_tasklocks CONVERT TO CHARSET utf8;

-- replace druid with your Druid database name here 
ALTER DATABASE druid DEFAULT CHARACTER SET utf8;

Improvements

We introduced several query optimizations, mainly for topNs and HLLs The overlord can now optionally choose what worker to send tasks to #904 Improved retry logic for realtime plumbers when handoffs fail during the final merge step

Bug Fixes

  • Fixed searching with same value in multiple columns
  • Fixed jetty defaults to increase number of threads and prevent lockups
  • Fixed query/wait metrics being emitted twice
  • Fixed default dimension exclusions for timestamp and aggregators in ingestion schema
  • Fixed missing origin in cache key for period granularities
  • Fixed default FilteredServerView to actually be filtered
  • Fixed files not cleaning up correctly in segment cache directory
  • Fixed results sometimes coming in out of order
  • Fixed bySegment TopN queries not returning at the broker level
  • Fixed a few bugs related to filtered aggregators
  • Fixed crazy amounts of logging when coordinator loses leadership
  • Updated jetty and spymemcached libraries for various fixes
  • Fixed cardinality aggregator caching schema problem
  • Fixed Coordinator and overlord '/status' page should not be redirected to the leader instances
  • Made postgres actually work out of the box in 0.6.x
