LLM incorporado para Docker

<img width="3680" height="2212" alt="AnythingLLM Docker LLM integrado impulsado por Lemonade y llama.cpp" src="https://github.com/user-attachments/assets/410b5784-ca15-4027-a1c4-056d9d5c748e" />

AnythingLLM Docker ahora tiene una experiencia LLM local predeterminada lista para usar. El mismo tipo de motor integrado que se envía con AnythingLLM Desktop ahora se puede ejecutar dentro del contenedor: Lemonade, el servidor de inferencia local totalmente de código abierto de AMD, que ejecuta sus modelos con llama.cpp. Ya no necesitas ejecutar Ollama, LM Studio o cualquier otro servidor de inferencia junto a AnythingLLM.

Pase su GPU al contenedor y el motor se acelerará en cualquier hardware que tenga. Elige automáticamente el backend más rápido: CUDA para GPU NVIDIA, Vulkan para GPU AMD e Intel, o la CPU. Se ejecuta en hosts amd64 y arm64.

Cuando está activado, Integrado se convierte en el proveedor LLM predeterminado durante la incorporación, con tres modelos recomendados para su hardware. Puede descargar cualquier modelo de la tabla de modelos o extraer cualquier modelo GGUF de Hugging Face. Funciona en todos los lugares donde se puede utilizar un proveedor: el LLM del sistema, los LLM del espacio de trabajo y del agente, el selector de modelo de la ventana de chat y Model Router.

[!CONSEJO] El LLM integrado está desactivado de forma predeterminada. Actívelo iniciando el contenedor con -e ENABLE_BUILT_IN_LLM=true y agregue --gpus all (o pase sus dispositivos GPU AMD o Intel) para la aceleración de GPU. Consulte LLM integrado para Docker para conocer la configuración completa para cada tipo de hardware.

anything-llm v1.19.0

Highlights

  • Built-in LLM comes to Docker, opt-in — PR #6719 ports the Desktop "Built-in" engine into the container using AMD's Lemonade server on llama.cpp, so you can drop the sidecar Ollama/LM Studio process. It is off by default: start with -e ENABLE_BUILT_IN_LLM=true and add --gpus all (or pass AMD/Intel devices) for automatic CUDA/Vulkan/CPU selection on amd64 and arm64. When enabled it becomes the default onboarding provider and works anywhere a provider does — system, workspace and agent LLMs, the chat picker, and Model Router. Expect a larger image and new GPU device wiring in existing compose files.

  • Weaviate adopters have a client migration to plan — PR #6675 moves the integration to weaviate-client v3. This is the dependency bump in this release most likely to break an existing deployment, so verify connection settings and version compatibility against your Weaviate instance before rolling out.

  • open-computer removed from the bundle — PR #6727 pulls the open-computer agent tool out of the main repo and into its own project. Any agent or workflow referencing it must now install and configure it separately; treat this as a feature removal, not just a refactor.

  • Security hardening that matters for shared or public instances — PR #6729 caps request body size to close an unauthenticated embed-endpoint DoS, #6728 neutralizes spreadsheet formulas in CSV chat exports (formula injection when opened in Excel/Sheets), and #6763 strips API key fragments from web search error messages. Operators exposing a multi-user instance should prioritize this upgrade.

  • Provider behavior changes to re-test — Mistral gains reasoning-model support, a deduplicated model list and a thinking toggle (#6825); Gemini stops receiving deprecated sampling and thinking params (#6733); and OpenAI image generation now defaults to gpt-image-2.5-flare (#6780). If you pinned image models or relied on custom sampling/thinking params, validate outputs after upgrading.

  • Prompt compression and context fixes reduce silent answer degradation — #6738 fixes a compressor crash on history records skipped by convertToPromptHistory, #6742 preserves current-turn attachments when the string compressor runs, #6777 keeps conversation history on compressed OpenAI-compatible prompts, and #6745 counts attachment text in statsFrom. Combined with #6673 applying workspace model changes to agent sessions mid-thread, these matter most if you depend on compression or attachments — previously such turns could silently lose context.

Built-in LLM for Docker

<img width="3680" height="2212" alt="AnythingLLM Docker built-in LLM powered by Lemonade and llama.cpp" src="https://github.com/user-attachments/assets/410b5784-ca15-4027-a1c4-056d9d5c748e" />

AnythingLLM Docker now has a default local LLM experience right out of the box. The same kind of built-in engine that ships with AnythingLLM Desktop can now run inside the container: Lemonade, the fully open-source local inference server from AMD, running your models with llama.cpp. You no longer need to run Ollama, LM Studio or any other inference server next to AnythingLLM.

Pass your GPU into the container and the engine is accelerated on whatever hardware you have. It picks the fastest backend automatically: CUDA for NVIDIA GPUs, Vulkan for AMD and Intel GPUs, or the CPU. It runs on both amd64 and arm64 hosts.

When it's turned on, Built-in becomes the default LLM provider during onboarding, with three models recommended for your hardware. You can download any model from the model table or pull any GGUF model from Hugging Face. It works everywhere a provider can be used: the system LLM, workspace and agent LLMs, the chat window model picker, and Model Router.

[!TIP] The built-in LLM is off by default. Turn it on by starting the container with -e ENABLE_BUILT_IN_LLM=true, and add --gpus all (or pass in your AMD or Intel GPU devices) for GPU acceleration. See Built-in LLM for Docker for the full setup for each kind of hardware.
